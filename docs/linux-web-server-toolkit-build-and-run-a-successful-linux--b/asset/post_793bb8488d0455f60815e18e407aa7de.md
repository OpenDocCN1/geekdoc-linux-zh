Another large task of its directives is determining how information returned to browsers is marked for its type. Each response to a browser request includes several lines of header information, just as you see in an e-mail message. These headers come with the browser request and tell the server about the browser, the user, and the information requested. They are also sent from the browser to describe the information that is being sent in response. These often relate to the MIME types described earlier (and more later on in this section).

## DOCUMENTROOT

The DocumentRoot directive gives the location of the documents that will be served out from your Web server, as follows:

```
DocumentRoot /home/httpd/html
```

If one requests a file in the "root" of the Web server (that is, without a path), such as the following:

```
http://www.travelbuddies.com/
```

The file will be taken from the directory /home/httpd/html on the Web server.
A file in the DocumentRoot directory can be a symbolic link to a file located elsewhere on the Web server, and aliases can let documents in the DocumentRoot tree refer to other areas. But you should be careful about the security of your site if you use these to give a Web browser access to other areas. In particular, you can set a directive to disable symbolic links.

## USERDIR

The UserDir directive defines the name of a subdirectory within a user's home directory that can be used to create personal Web pages, as follows:

```
UserDir public_html
```

Any user on your OpenLinux system can have a subdirectory named public_html (or whatever you set this directive to) and can serve Web pages using his or your username. The URL to do this would be, for example, as follows:

```
http://www.bigcorp.com/~nwells/myvacation
```

This URL would return to the browser the file /home/nwells/myvacation.html. Having this UserDir option allows users who do not have control over the Web server or the DocumentRoot area to serve documents using the Web server that is already running.

## DIRECTORYINDEX

Whenever a browser requests a URL that ends in a path, the Web server will search for the filenames given in the DirectoryIndex directive (separate multiple filenames with spaces) as follows:

```
DirectoryIndex index.html
```

If none of the files listed as values of the DirectoryIndex directive is found, the Web server creates a directory listing of the subdirectory according to the other rules in the srm.conf file.

## FANCYINDEXING

The FancyIndexing directive indicates that you want the Web server to create a "fancy" listing of files if an index.html file is not present, as follows:

```
FancyIndexing on
```

- A fancy listing includes icons for different file types and descriptions of the file. The alternative, FancyIndexing off, returns a plain list of files.
- Many of the directives listed for this file apply to directory listings created when FancyIndexing is turned on (the default).

## ADDICON DIRECTIVES

The following is an abbreviated list of the Addicon directives in the srm.conf file:

```
AddiconByEncoding (CMP,/icons/compressed.gif) x-compress x-gzip
AddiconByType (TXT,/icons/text.gif) text*/
AddiconByTypeImage (IMG,/icons/image2.gif) image*/
Addicon/binary.gif .bin exe
Addicon/world2.gif .wrl .wr1 .vrm .iv
Addicon/compressed.gif .Z .tgz .gz .zip
Addicon/text.gif .txt
```

The Addicon directives define what to use when creating a fancy index list. Each AddiconByEncoding directive gives an encoding style as the last parameter (x-compress, for example) and the filename for an icon to be displayed with that filename. AddiconByType gives a MIME type as the last parameter, with the filename for an icon to be used to display files of that type. Finally, each Addicon defines file extensions that should use a particular icon for their display. Note that many file extensions can be included in each line for the named graphic.

Many Addicon lines are included in the default file. You shouldn't need to add more unless you become aware of a new format that you are storing on your system and want to identify using a particular icon.

Note that the filenames for the icons are relative to the DocumentRoot. The final line above, for example, would display the file /home/httpd/html/icons/text.gif for a text file ending with a .txt extension.

## DEFAULTICON

The Defaulticon directive gives a name for a graphic that is displayed if none of the Addicon directives apply, as follows:

```
Defaulticon /icons/unknown.gif
```

## ADDDESCRIPTION

You can use the AddDescription directive, which is not used in the default file, to place a one-line description after any file in the directory listings. For example, to have GIF graphics include a description, you could include the following line in srm.conf.

AddDescription Compuse GIF graphics format *.gif

```
AccessFileName .htaccess
```

## Content Negotiation

Many late-model browsers such as Netscape Navigator are able to exchange information with the Apache server to determine a best match between what the server can do and what the browser can handle. Several directives in srm.conf define what the server can do.

## ADDENCODING

The AddEncoding directive defines methods of preparing data to send to a browser. Multiple methods can be enabled on your Web server. In the following two examples of the AddEncoding directive, the Apache Web server is instructed to use either of two compression techniques for any browser that declares it can handle compression type:

```
AddEncoding x-compress Z
AddEncoding x-gzip gz
```
