## Processing Queries with Scripts

Once you've gone to the effort of creating a form, you need to have a tool on your Web server to use the data sent by the browser. These tools are normally scripts that you create to record the user's comments, to query the database, to log the order, or for whatever else you think of.

I'm going to use the Perl language for all the scripts in this section. You can use any language you prefer, including C, C++, shell scripts, various BASIC versions, or any other Linux-programming language that you prefer. The only requirement is that it conform to the cgi-bin standard so that it can communicate with the Web server to get data and provide a response back to the browser.

I choose Perl for several reasons, but not because it's easy to use. Perl is a good choice because it is:

- A popular language for Web server scripts
- Very fast
- Cross-platform
- Optimized for dealing with text

## Linux Web Server Toolkit

### Choosing a Method

Data from the browser can be sent to the Web server in two ways: GET or POST.

### USING GET

The GET method sends all data as part of the URL. Each name-value pair is separated by an ampersand (&). Spaces are converted to plus signs (+). Any non-alphanumeric characters are represented by a percentage sign (%).

A script named query.pl can be requested using the following:

```
http://www.server1.com/query.pl
```

In the following example, the script detects that no keywords are part of the URL, so it returns this line:

Please enter keywords to search for: <INDEX>

The user then enters keywords in the text field created by the <INDEX> tag and presses Enter. The resulting URL sent to the server would look like the following:

```
http://www.server1.com/query.pl?Houston=salsa
```

The query.pl script detects that keywords are included with the URL this time, instead of responding with the <INDEX> tag, the script responds with search results. A URL can't exceed 256 characters.

### USING GET FOR FORM-BASED SCRIPTS

Using the GET method is really like using a normal URL except that you "ask for" a script and it generates a response.

You can use the same type of request without using a form at all. Just use a regular <A> tag. Suppose you had a script that processed small database queries. Instead of providing a form, you could offer several links for your users to choose from, with each link including the necessary URL to query the database. It might look like the following HTML code:

```html
<P>
<B>Choose which type of restaurants you wish to see:</B>
<A href="http://www.city.com/cgi-bin/restaurants.pl?type=Italian">Italian</A>
<A href="http://www.city.com/cgi-bin/restaurants.pl?type=French">French</A>
<A href="http://www.city.com/cgi-bin/restaurants.pl?type=Chinese">Chinese</A>
<A href="http://www.city.com/cgi-bin/restaurants.pl?type=Others">Others</A>
<P>
```
