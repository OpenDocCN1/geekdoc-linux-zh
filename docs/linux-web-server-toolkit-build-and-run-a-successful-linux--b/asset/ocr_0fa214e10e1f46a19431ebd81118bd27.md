Once you have installed and tested the modem, you can use the /dev/modem device name in all the scripts that you prepare in the following sections.
The PPP programs are installed by default from your OpenLinux Lite CD-ROM. To start PPP, you create a script that dials your ISP, logs in, and starts the PPP daemon on your Web server.

# CREATING THE CHAT AND PPPD SCRIPTS

You can combine everything into a single command on a line, but using a couple of text files gives you more flexibility, I'll describe it that way.

First, create a script for the chat program to follow. The chat program uses your modem to have a conversation, a chat, with another computer. Each line in the script is a reply-response pair. The script waits for the reply from the modem (the remote system), then responds as directed. (The lines starting with ABORT indicate that if the words are found at any time, the whole operation should be cancelled.) The following script can be stored anywhere because you'll give the pathname to when you use it. For example, you could place it in /etc/ispconnect.chat.

```
abort NO CARRIER
abort BUSY
ATDT5558762
CONNECT
login: ppp
password:          password
```

The interpretation of this script is as follows (a carriage return is added after each response):

+   1. If the words NO CARRIER or BUSY appear at any time, exit the script and stop everything.
2. Don't wait for anything; just send the dial sequence to the modem (this number should be your dedicated phone number to call your ISP).
3. When the word CONNECT appears, do not do anything (just know that you're on the right track).
4. When the word Login: appears, respond with the special login account name that your ISP gave you to connect using PPP.
   Not knowing exactly how the login prompt will begin (capitalized or lower-cased), the script just uses the last part of the prompt. (You can test this by hand and adjust the script to fit.)n5. When the word Password: appears (wait for the end of it), the script responds with the password for your ISP account.
6. You would now logged in at a command prompt on the remote system, but you don't use the chat program alone.
