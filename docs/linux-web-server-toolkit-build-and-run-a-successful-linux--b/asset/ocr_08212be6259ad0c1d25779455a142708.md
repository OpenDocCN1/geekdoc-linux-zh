# An Example of Using a Gateway

Suppose you have an intranet site in your nonprofit organization. You use the site to provide all the marketing documents, human resources forms, and various other things such as the annual report and company newsletter. All of these documents are either prepared originally in HTML format or converted to HTML so they can be provided on the public Web site because they are more useful as HTML documents than they are in a word processor (more people browse the site than read the paper newsletter). The intranet site, it seems, is quite a success.

One day the CEO comes to your office and suggests that it would be helpful to be able to track in real time the number of operators on the call-in lines, the donations received so far each month, and the number of children sponsored by the organization. He'd like to be able to view these any time by going to the intranet site with his browser.

Now if this CEO is most, he doesn't use a computer very often, and if you're like most employees, when the CEO says “wouldn't it be great if ... spend the next week making it happen.

The problem with this data is that he wants to see the intranet site is located on a big UNIX server by a special-purpose package that has anything to do with the Web.

What you need a gateway.

Imagine the following arrangement. You create a Web page that has three graphs on it, one for each of the three things the CEO wants to see. Each graphic links to a small script on your Web server. These scripts don't work on the Web server or with HTML documents, however. When one of these scripts is invoked, it connects to the UNIX server that has all the needed information and, using special calls you've learned from the vendor of the special-purpose software, queries the various databases for the figures needed to answer the CEO's questions.

Once the script receives this data, it can easily prepare an HTML page that integrates the information into an attractive format, but the data retrieved in real time from a system that doesn' work with the Web. The script that you created acts as a gateway between the special software used by your organization and the formats of the Web that everyone these days can view in their browser.
