There are two dangers when using Web authoring tools. First, if the tool makes poorly formed HTML code, you cannot easily see it and haven't been practicing with real tags enough to know how to fix it. Second, Web authoring tools have a hard time keeping up with the latest tags from Netscape and Microsoft. If you're planning on using the latest and greatest Web page tricks, you'll need to use a text editor.

## Viewing Existing Pages

Have you ever used the Document Source menu option on your browser? If you haven't, you'll want to start. Open your browser and go to one of your favorite Web pages. Now choose the Document Source item from the File or Edit menu (it's called slightly different things in different browsers).

Don't be intimidated by the mess you probably see. Soon you'll be studying code to see how your favorite pages were created. HTML provides a great tool because it's always in plaintext, so you can see exactly how a developer created the effects you see on the screen.

There are two big dangers to watch out for as you study other people's Web pages. The first is copyright restrictions. If you're viewing a page from a large organization that has created a neat effect, they may consider that effect to be their "trade dress." If your organization uses the same look by using the same set of tags, they might consider it a copyright infringement. Although copyright protects only the expression of an idea (not the way it was created), there aren't a lot of different ways to create the same effect in HTML. The safest thing to do is to study other people's Web pages to learn about the things that are available. When you're going to start creating your own, start from a blank page, with only your HTML tag reference sheet beside you.

The second danger is the quality of other people's pages. HTML syntax checkers and spell checkers aside, many people post documents that are incorrectly formed, or use sloppy forms or poor tagging practices (running all the tags and text onto one line so you can't read anything unless viewing the page in a browser). You can learn a lot by reviewing other people's work, but you can also learn techniques and habits. Decide on some sound practices for your formatting and learn what the correct format is for your HTML tags.

You've read a lot about HTML tags and tools so far. Now it's time to start creating your Web pages. The next section takes you through the process of creating simple HTML pages, explaining how each of the tags is used.

## Creating Basic Pages

The simplest HTML page consists of just a headline and a few paragraphs of text. These pages still need the meta tags that define a well-formed HTML document, and they are very simple to create. Here's an example of a basic HTML page:

```
<HTML>
<HEAD>
<TITLE>My First HTML Page</TITLE>
</HEAD>
<body>
<h1>My First HTML Page</h1>
<P>
My first HTML Page has a first level heading and a paragraph of text.
</P>
<P>
No, make that two paragraphs of text.
</P>
</body>
</HTML>
```

## TABLE 9-2: The Most Basic HTML Tags

| Tag | Description |
| --- | --- |
| <HTML> | A meta tag indicating that the HTML tags and text follow. This tag is not often used. |
| <HEAD> | A meta tag that indicates the start of heading information for the document. Many meta tags can be placed in this area between <HEAD> and </HEAD>. Nothing appearing in this area is displayed in the browser window as part of the document, but items in this part of the HTML document can affect how the rest of the document is displayed. This tag may also add items to the browser menus or the title bar of the browser. |
| <TITLE> | A meta tag indicating the title of the document. The text between <TITLE> and </TITLE> is displayed in the title bar of the Browser window and is saved for the history list as the title of the document. The title is commonly the same as the first H1 heading in the document. |
| <body> | A meta tag indicating the beginning of the document itself (after the meta information). Nothing is displayed from this tag, but the browser expects displayable tags to begin after <body>. Everything appearing on the browser window is between <body> and </body>. |
| <h1> | A first level heading. The size and font used to display this tag are in the control of the browser. There should be only one H1 heading in each Web page. This heading is usually the same as the TITLE of the document. |
| <P> | A paragraph. The browser will not start a new line when it hits a carriage return in the HTML file; it will start a new line when it finds a P tag. (Many other tags also start a new line.) |

## Marking Text

In the middle of any text on your Web page, you might want to emphasize certain words. HTML provides simple character tags you can use to emphasize text. Several of these tags define a specific look, like bold or italic; other tags define a functional style like strong, or typeface, which is translated by the browser into a type style (usually bold and courier font for string and typeset).

Any text can be enclosed in character tags that define its appearance or purpose. These tags do not imply a new line. Table 9-3 lists the most commonly used character tags.

## Table 9-3: Common HTML Character Tags

| Tag | Description |
| --- | --- |
| <B> | Bold text |
| <I> | Italic text |
| <STRONG> | Usually rendered as bold text |
| <EM> | Emphasis; usually rendered as italic text |
| <CODE> | Code sample; usually rendered as courier font |
| <TT> | Teletype, usually rendered as courier font |
