# Using Telnet to Play with HTTP

The Web protocol is very straightforward. We can use a standard UNIX utility called Telnet to demonstrate how it works. Telnet is part of every Linux system. It allows you to connect to a remote computer as if you were using a locally connected terminal (where you have a username and password). Telnet uses a standard port to initiate a command-line style of interaction between your computer, acting as a remote terminal, and the remote computer.

You can also use Telnet to connect to port 80 (the standard Web port) and send HTTP requests as if they were coming from a Web browser. If you try this on a non-Linux system, the Telnet program you are using might not let you specify a nondefault port for the connection. Also, some Web servers may not allow you to connect from a Telnet program because they consider it a security risk, so you might need to try several sites.

To use Telnet to see HTTP working to send back a Web page, the following commands at a command-line prompt in Linux, once you get it up and running (the connection response from the Web server will fill in between your entries if the test is working:

```
telnet www.caldera.com 80
GET /index.html
```

After you send the GET command, the Web server should return the HTML file for the home page of the site, which will fill your screen. The connection is automatically closed by the Web server. Web server connections are based on the HTTP protocol, which is stateless, meaning that every new request opens a new connection, which is discarded as soon as the information is sent. Information about the browser or about a previous request is not maintained from one request to another. Everything starts from scratch with every new request from a client.
