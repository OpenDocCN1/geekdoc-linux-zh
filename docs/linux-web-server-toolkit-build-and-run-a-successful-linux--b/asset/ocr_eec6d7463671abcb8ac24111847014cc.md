Different purposes require different protocols on the Internet for optimal performance. When the Hypertext Transfer Protocol (HTTP) was developed by Tim Berners-Lee for the World Wide Web, it was designed to facilitate the following aspects of communications:

+   - Real-time transfers: pages are transferred at the instant requested, as with FTP or IRC chat.

+   - Smaller files: HTTP is designed for files a few kilobytes; using the Web for files of several megabytes is less efficient than using FTP.

+   - One to many: like FTP, one server is open to many visitors; none need an individual “invitation” as with e-mail or IRC chat.

+   - Pulled from the server by the recipient: as with FTP, the receiver of a Web page must request the page. Without the user requesting it, a Web server cannot “push” to a browser as is commonly done now with e-mail about how to make a million dollars.

HTTP was also intended to be used with files of a specific type: text files created with the HTML markup language.

The power of the Web – and the reason it became so wildly popular – was only half of the HTTP protocol and the HTML markup language, though having a graphically oriented document was a novelty on the Internet in general. The other half of its power came from the browsers that were created to read the HTML documents from the Web. The first widely used browser was Mosaic, written by a team at the National Center for Supercomputing Applications (NCSA) in Illinois. The team included Rob McCool and Andrew Andreessen (Marc later co-founded Netscape Communications Corp.) Mosaic was powerful because it allowed users to access documents in different formats using a single graphical utility. With Web documents in HTML as a starting point, links could be followed with the click of a mouse to view a document that was transferred using the FTP protocol, gopher protocol, e-mail, or others – all without leaving the browser.
As the UNIX system had been (each utility do one thing well), the convenience of Mosaic was a universal hit.
