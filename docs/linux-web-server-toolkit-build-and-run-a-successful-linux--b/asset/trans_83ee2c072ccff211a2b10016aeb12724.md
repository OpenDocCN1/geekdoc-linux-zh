## Netscape API 简介

OpenLinux 的 FastTrack 服务器拥有一个全面的编程接口，服务器的大部分功能都源于此接口。事实上，FastTrack 服务器使用此 API 来构建 `magnus.conf`（服务器配置文件）和 `obj.conf`（对象配置文件）中所用指令的常规函数。通过应用程序编程接口（API），你可以创建插件并插入服务器配置文件的指令中。

由于同一个 API 既用于你自己的应用程序也用于 FastTrack 服务器的核心，因此当你熟悉了 API 时，也就更深入地了解服务器是如何运行的。这意味着你可以覆盖服务器功能、添加功能或自定义自己的函数。例如，创建使用不同类型数据库进行访问控制的函数（包括在你的 OpenLinux 系统上处理 Oracle 或 NetWare NDS 数据库）。

FastTrack 服务器还可以使用 JavaScript 或 Java、JNI 以及 JavaScript。API 为 CGI、Java 和 JavaScript 提供了一个更底层的接口。该 API 是一组 ANSI C 函数和头文件，它们使用通用对象模型与你自己的代码进行交互。

# Linux Web 服务器工具包

由于它在较低层级提供了更多功能，因此它不受像 Java 和 JavaScript 那样的限制——保护措施。这意味着你使用 API 开发的插件可能会导致 Web 服务器崩溃。API 的典型用途包括：

- 自定义访问控制机制
- 自定义错误处理机制
- 自定义请求或错误日志
- 初始化共享资源
- 修改正常的 HTTP 请求-响应过程，包括维护有状态系统

尽管 FastTrack 提供了多种编程或将程序集成到 Web 服务器的方法，但 Netscape API 是可用执行最快、最强大的方法。Perl 甚至 C 语言的 CGI 脚本性能没有那么，Java 或 JavaScript 甚至无法比拟。为了获得最佳性能、最大的灵活性和力量，请使用插件 API。

就像 UNIX 模型本身一样，API 函数提供了许多小工具，这些工具经过仔细设计旨在很好地完成一项任务。这对服务器的行为提供了极大的控制。开发者可以实现自己的身份验证、客户端跟踪、访问控制、错误日志或其他功能的系统。

## 利用 API 取得优势

Netscape 和 Apache 的 API 都是用 C 语言编写的，因此你想写的任何模块也将将用 C 语言编写。以下章节简要提供了 Apache 和 Netscape API 功能和操作的大纲。你会从这些大纲以及 Apache 和 FastTrack 服务器自带的文档中注意到，Apache 可用函数相比 Netscape API 在 API 中提供了更大的灵活性、可能更强大的功能，以及更具体的示例。

另一方面，Netscape API 并不那么丰富，但可能更容易使用。它的进展没有那么快，对服务器功能的影响也没有那么深或那么广。遗憾的是，《Netscape 程序员指南》中帮助你走过这段道路的代码片段比 Apache 文档少。这部分很令人遗憾，但并不是由 Netscape 商业化性质决定的。

无论如何，当你为 Web 服务器添加功能时，两个 API 都能为你提供强大的能力和灵活性。使用以下信息对 API 有个初步感受，然后参考每个产品的文档以获取更完整的信息，包括函数列表以及我在这里无法提供的更多技术细节。

## 使用 Apache API 进行编程

正如我所说的，Apache Web 服务器是世界上使用最广泛的 Web 服务器。部分原因是因为它是免费的。但我认为更重要的因素是它的健壮性、速度和领先功能。

本节仅通过定义 API 所属的整体结构来开始探索 Apache API 的功能。你需要拿出你的编译器并开始编码，才能真正看到用它能做什么。

# APACHE 如何处理请求

Apache Web 服务器将来自浏览器的每个请求分解为一系列步骤。API 具有处理这些步骤每个阶段的函数。正如我之前提到的，你可以替换默认函数，或向标准功能中添加额外的函数。此过程中的步骤比 Netscape API 多。步骤如下：

1. URI 到文件名的翻译：通过应用重定向、别名等将请求的 URL/URI 转换为本地文件名。
2. 身份验证 ID 检查：确定请求的用户是否如其所称的身份。
3. 身份验证访问检查：确定请求的用户是否有权从请求的位置检索文档。
4. 访问检查：除上述步骤 2 和 3 描述之外之外的访问类型或身份验证类型。
5. 确定所请求对象的 MIME 类型（使用配置文件、文件扩展名等）。
6. 修复（Fixups）：该过程的阶段目前并未真正使用。Apache 文档将其包含在流程图中，但它是为了未来的扩展设计的。
7. 响应：向请求客户端发送某种响应文档。
8. 根据请求中的头信息和 Web 服务器采取的操作将请求记录到一个或多个日志文件中。

上述列表中的每个阶段都可以包含一个或多个模块。对于某些阶段，标准的 Apache 服务器连接到多个模块；对于其他阶段，标准服务器只包含一个模块。对于这些阶段的任何一个，你都可以向包含在该阶段的模块添加一个模块。

# 请求处理器

对于某些阶段，仅使用服务器存在的模块之一是有意义的。对于其他阶段（如日志模块），该阶段存在的所有模块都可以被连续调用。每个模块对于你希望其被调用的任何阶段都可以处理器。Web 服务器在每个阶段检查每个模块，查看它是否具有处理器以及是否应该在该阶段被调用。模块的处理器可以执行以下三件事之一：

- 对客户端请求执行操作（处理它或参与其处理）并在完成后返回 OK 代码。
- 通过返回 DECLINED 代码拒绝参与。（在这种情况下，服务器将完全跳过该请求的该模块并继续。）
- 返回错误代码（HTTP 错误之一），这将导致 Web 服务器停止对请求的正常处理，并进入错误处理和日志记录。

大多数时候，一个阶段使用它遇到的第一个模块。然而，日志、修复和非访问身份验证检查（上述列表中的步骤 4）会使用所有响应请求的处理器。响应阶段是独特的，因为单个模块对于该单一阶段可以有多个处理器（如函数）。正确的处理器是根据请求对象的 MIME 类型选择的（该类型在两个步骤之前已确定的）。响应阶段模块中的一个处理器甚至可以使用通配符作为 MIME 类型来处理任何请求，其响应类型为 /*，但只有在更具体的 MIME 类型处理器失败或未找到时，才会使用这些处理器。

## 使用 Netscape API 进行编程

《FastTrack 服务器程序员指南》包含了使用 Netscape API 的完整信息。它是你购买 FastTrack 时获取的在线文档的一部分。这里的信息将帮助你为使用 API 编写模块做好准备，但在深入研究之前，你需要熟悉 C 语言编程并学习完整的《程序员指南》。

在尝试使用 API 函数完成一个新模块之前，你应该也熟悉服务器配置文件和内置函数。很少直接访问配置文件（使用文本编辑器），因为通过浏览器和管理服务器使用图形化配置工具是如此方便。
