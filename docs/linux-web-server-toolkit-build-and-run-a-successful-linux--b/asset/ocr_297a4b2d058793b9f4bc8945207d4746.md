# Protocol Routing Firewall

One of the most common types of firewalls screens packets of network data based on the protocol of the packet, or more specifically, on the port it is addressed to. Because all UNIX services use a port to send and receive data, you can block services by blocking port numbers.

For example, the most secure protocol routing firewalls might only allow traffic on port 80, the standard Web port. Any other packets are discarded by the router (which might be the Same Linux system as the Web server). This means that even if a hacker has obtained information about your system, he could only try to break in via a standard service like the Web. All other services - telnet, FTP, ping, etc.— are blocked at the firewall level, reaching the other parts of the server.

Different services can be allowed to pass through different routers, allowing all Web traffic to pass through one part of the network, and all e-mail through another. Or, a single router might have only a few keys enabled.

This is called a "deny all" system. All services are denied, then one or two are allowed. The alternative is an "allow all" system, where every service is allowed to pass through the router (a request to any port number, really), except for a couple of specific ports that are disallowed. Obviously, it's safer to deny everything except for a few well-known ports than to leave 65,000 ports open for five known danger points. But that provides a lot less flexibility on your system, particularly if you're an Internet Service Provider with customers who want to provide different kinds of services through your site.
