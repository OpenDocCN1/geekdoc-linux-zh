
# Chapter 3: Choosing Your Software

We all know how trying it can be to install software as complicated as an operating system, so I'll fill you in in that aspect first.

## INSTALLATION

The most obvious difference between distributions is the installation process used to set up the new operating system on your computer. Some are command-line whereas others are menu- and graphical-based systems. Some work towards simplicity, others towards maximum flexibility.

For example, installation of the Slack distribution required that you answer numerous questions about how you wanted the system installed. This was tedious and difficult for novice Linux users, but maximum flexibility to those familiar with the available options. Conversely, Caldera and others are now using menu-based installations that don't make all options available, but makes installation simple for everyone. Online help and expert mode allow access to more advanced installation options.

## FILESYSTEM STANDARD

The Linux Filesystem Hierarchy Standard (FHS) specifies the arrangement and location of standard files and directories. Nevertheless, while every Linux strives towards this standard, past versions and other objectives sometimes dictate that library files, logs, and other application-oriented files are placed in different directories on different Linux systems. For example, one distribution might place the lib-c in /lib, whereas another place it in /usr/lib.

The FHS needn't affect your choice of Linux distributions, but it means that switching from one to another can cause a little pain as you rearrange files to suit your preferred environment. Some applications that are designed for a specific Linux distribution such as OpenLinux might also need to be adjusted to work with other distributions. For information about the Linux Filesystem Hierarchy Standard, visit http://www.pathname.com/fhs.

## INITIALIZATION SCRIPTS

Initialization scripts are set up automatically by the Linux kernel. Scripts control everything that occurs after the Linux started. For example, processes such as logging, FTP and Web servers, and directory services are activated by initialization scripts each time the system is restarted. Different scripts may have advantages in the type of security, the types of programs they start up, and their location in the filesystem. Of course the less you have to alter after installing your system, the more likely you are to prefer a certain distribution.

Some distributions, as Slack or Debian, are more likely to have minimal initialization scripts and allow you to tinker with the system to activate what you need. More commercially oriented distributions, such as Caldera OpenLinux, Red Hat, or Work Solutions will automatically start more services to save you from having to configure these yourself after installation. Of course, having services like FTP, e-mail, and others with automatic start-up requires memory that could be used for other things, so adjusting these automatic configurations is also wise.

## SOFTWARE PACKAGES INCLUDED

The Internet contains much software for Linux than a single distribution can include. Although all distributions will include standard items like the X Window System from the FreeX86 Project, Inc., the inclusion of many other pieces is at the discretion of the people who create the distribution. Even if you buy a distribution and all the software packages that you wanted on its CD-ROM, the default installation may not put everything wanted on your system. You then have to spend additional time locating and installing specific packages.

Software packages are installed using one of several common methods that may ease the installation process. These include the Debian package format, the RPM package format (widely used), or simple tar files (supported by all UNIX and Linux systems). Installing packages from a CD-ROM other than your original distribution usually causes inconsistencies in your system's database of installed software.

## PHILOSOPHY

Besides the technical issues just discussed, most creators of a distribution have a philosophy, or a particular mission for their product. They aim their products at a certain part of the market and have certain goals in doing so. Understanding the goals of the company whose you use is also important. It affects to some degree all of the technical factors mentioned in the previous sections.

For example, if you believe strongly in the free software model, you might select the Debian distribution even if you're a novice user who might otherwise prefer an easier installation program. However, the philosophy of Debian developers leads them to choose certain packages for default installation while avoiding entirely the commercial add-ons offered with other Linux distributions. This might affect your decision should you desire completely different default installation packages.

## Some Top Linux Providers and Their Products

The following sections describe some of the well-known Linux systems currently available. I have listed only a few of those systems that are considered stable and ongoing concerns, and only those that create a distribution, not those that press CD-ROMs of other companies' distributions and resell them.

### OpenLinux from Caldera, Inc.

OpenLinux is the basis for a complete line of Linux products from Caldera, Inc. Some of these products are inexpensive, some are very expensive. At their heart, however, they have in common the same Linux distribution: OpenLinux. This can make it easy should you want to migrate from an experimental system to one that includes all the commercial and value-added components that justify the higher cost. OpenLinux includes a full set of utilities and development tools, such as compilers and debuggers, scripting editors, graphical tools, games, Internet tools and servers, command-line utilities and online documentation. It also uses a packaging system called RPM that is popular among many Linux distributions these days. RPM facilitates easy installation and upgrades of software by placing files in correct directories. The RPM utility maintains a database of installed software. An example of the power of RPM is that you can install a large, complex program on your Linux with a single command that copies the files, places them in correct directories, and executes any initialization scripts that are required to set up the program without starting up your C compiler.
