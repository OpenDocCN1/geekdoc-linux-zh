# Using Anonymous Login

One reason that FTP became so popular (it's much older than the Web) is that you can use a standard username to log in to any public FTP server and get files from that server. To log in to another system, you need a valid username and password. To log in to an FTP server (or only to the FTP section on server), you generally use the username “anonymous,” and enter your e-mail address as the password.

Whenever a visitor to your FTP site uses the "ftp://" style for a URL to link a Web page to an FTP site, the Web browser automatically uses the “anonymous” user as the login name. In addition to using links that you provide in your Web pages, a visitor to your FTP site can simply enter an FTP URL to use a Web browser to access your FTP site. For example, Figure 14-1 shows a Web browser displaying this:

```
ftp://ftp.caldera
```

If you have your own user account on another server and want to download files from that server using your Web browser, you can use a different username by entering a URL like this one:

```
ftp://myfile@ftp.server1.com/
```

You will be prompted for your password, and then a directory on the server will appear in the browser (which directory depends on your permissions on this server).

# Setting Up FTP

Setting up FTP is very easy. In fact, if you installed OpenLinux Lite from the CD-ROM in this book, it's already done.

A line is included in the /etc/inetd.conf file to start the FTP daemon whenever someone makes an FTP request. There is also a line in the /etc/services file that defines how the FTP protocol operates.

FTP uses a directory structure similar to the Web, but instead of locating files in /home/http/ftp. Just like the Web site directory, the FTP directory has standard subdirectories. The only one you really need to worry about is the pub/directory, which stands for the "public directory."

When users log in as "anonymous" (using your Web browser or another FTP client), they are automatically placed in the /home/ftp directory. They cannot move to a different directory on the system. Only subdirectories of /home/ftp are visible to them.

All of the downloadable files are placed in the /pub directory. Several files may be in other directories, bin/ or lib/, but these are not used directly by visitors to the FTP site (that is, you won't be downloading files from these directories). Another directory, incoming/, can be used for anonymous users to upload files to your site, but you must set file permissions to allow this, and it can't be done from a Web browser.

# Placing Files for FTP Use

You can have any file available for FTP download, including an HTML file. If you use your Web browser to view an FTP site and it points to an HTML or cleartext file, the Web browser will usually display the contents instead of a download log box. You can create a download dialog box for any link (including any link on a Web page) by holding down the Shift key before you click on a link.

All you need to do is make a file for FTP download from your Web site is place it in the correct directory with correct permissions and make a link to it your Web pages. For example, suppose you have a file called demo in your home directory. Assuming you are logged in as root, you can use these commands:

- 1. Make a subdirectory for all related programs.
mkdir /home/ftp/pub/myprograms
- 2. Copy the program to the FTP area.
cp /home/tom/demo /home/ftp/pub/myprograms
- 3. Change the file permissions so that anyone can read (download) the program.
chmod a+r /home/ftp/pub/myprograms/demo

Now just include a link in one or more of your Web pages like this:

```
<A HREF=http://ftp.server1.com/pub/myprograms/demo >Try our new demo version</A>
```

# FTP Site Administration

Although FTP is set up and working automatically on your OpenLinux system, there are many other features you can offer additional services to users, to track how your FTP service is being used, and to make it more secure if it's used a lot.

When an anonymous user logs in to FTP site, a message is displayed for the user to see. This is the file welcome.msg, located in the directory /home/ftp/

Most of the FTP administration settings are saved in a set of files located in the /etc directory. These include the files ftusers, ftgroups, and ftaccess. The default contents of the ftaccess file, which is the only file you must have, are shown below:

```
class all real. guest. anonymous *
-email root@localhost
```

# Using Scripts

An alternative method for soliciting e-mail is to display a form where the user enters the username, e-mail address, and comments. Then when the form is submitted, it is e-mailed to a certain address by the script on your Web server (see Chapter 10). This has the advantage of not requiring any mail services at the client's location. It has the disadvantage of requiring that you write a form and script the mail features.

Of course, most users who have Web access will also have an e-mail account, so you rarely risk removing someone's ability to communicate with by having a form and script. Because the mailto URL is so simple, you might consider using it regularly and having a special comments page with form for those who don't use the.

If you have an e-mail server on your Linux system (see the "Accepting E-mail" below), you can use simple commands in your script to send a message to the e-mail system on the same computer. You can read these messages using a standard e-mail reader such as elm or the Netscape Navigator. Two methods of sending e-mail are:

- If you have a file to send, execute a command that includes the elm command with options that indicate the recipient and the file to mail. This method is easier but requires the information you want to mail is already in a single file. A sample command is shown here with the subject line, recipient and to send.

```
elm -s Subject line here john@server.com < filemail.txt
```

- If you are generating lines of text to send, you can open the SENDMAIL mail server and write lines to that output. This method is efficient for the server but takes more work in the script.
