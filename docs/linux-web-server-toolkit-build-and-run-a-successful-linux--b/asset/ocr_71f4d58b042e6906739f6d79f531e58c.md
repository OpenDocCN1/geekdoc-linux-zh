But using /etc/inetd.conf is not a foolproof method of protocol firewalling. In addition to this method, you can use the firewall features built into Linux to control which packets are passed on to the operating system for servicing.

# RE-COMPILING THE LINUX KERNEL

To recompile the Linux kernel, you'll need to re-compile (re-make) the Linux kernel, as described in Chapter 21. Select the firewalling options as you configure the kernel, and then follow the online documentation to create the firewall configuration files.

Re-making the Linux kernel is not hard, but creating complex firewall configuration files can be a challenge. That's why several commercial firewall products for Linux are now available. Linux can provide a great firewall, but it takes some expertise to use it. A good reference for commercial firewall products is the Linux Applications and Utilities Page. One mirror of the page is located at http://www.xnet.com/~blatura/linapp4.html#http.

# USING HOST-BASED FIREWALLING

One benefit of using kernel-level firewalling with the complex configuration files that you can create is that you have a variety of protection features at your disposal.

A frequently used protection feature is host-based firewalling, in which only certain hosts are allowed to access your network. This type of firewall functionality is very similar to what was described for Web server access control in Chapter 11. Here are a few examples of what you can easily set up for your Linux system using the Linux firewall features:

+   - Deny (ignore) all incoming packets; allow outgoing traffic from this router. (And check the actual origin to prevent IP spoofing).
- Deny all incoming packets from everyone, but then allow them from a short list of trusted hosts.
- Allow all incoming packets from everyone, but then allow them from a few known troublemakers.
- Deny all traffic to the telnet port.
- Deny all incoming traffic to all ports, but then allow all incoming traffic to the Web port (80), and to FTP ports (20 and 21), except certain hosts known to be unwelcome.
- Deny all outgoing packets except for the e-mail (SMTP) ports (internal people can do e-mail but not browse the Web).

The performance hit for all this firewalling in the Linux kernel is minimal. The kernel routing system must nevertheless examine every packet to see what to do with it (pass it or send it to a local servicing program). So adding a few simple rules that may mean discarding the packet altogether doesn't noticeably increase the router's work.
