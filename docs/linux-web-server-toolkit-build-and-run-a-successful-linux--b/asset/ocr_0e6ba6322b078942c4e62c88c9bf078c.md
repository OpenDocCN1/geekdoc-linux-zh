# Chapter 12: FastTrack Configuration and Administration

FastTrack can use a style setting to define the character set to use for documents within a directory. Because the name of the character set is sent to the browser with the document, the browser then knows how to correctly display the document in the language for which it was written.

# Document Footer

Styles that you define and assign to subdirectories within your document tree can include an automatic footer. The footer is added to the end of every document sent from a directory assigned that footer.

In the Document Footer page, you can select a style to which a footer will apply, then define how the footer will look.

A footer includes a date and optionally a text message. Footers are very short, with something like an e-mail address, date modified, and a copyright line.
You can specify how the date string is formatted if you don't like the default. Then just enter the text that should be included in the footer in the field shown (as shown in Figure 12-19). You may not want all files in a subdirectory to have the footer enabled. In fact, adding it to all files would include files like GIF graphics and CGI script filetypes, which would cause problems. The standard list of file types to add to the footer is HTML and text files.

# Parsed HTML

Chapter 10 describes at length the use of Server Includes. These are commands that are embedded within HTML tags that look like comments to the Web browser. The Web server executes these commands to customize a document just as it's being sent to the browser — a sort of real-time editing of the HTML file.

Because this feature poses a security threat (especially with the ability to execute commands on your Linux system), and causes an extra load on your Web server, you can define which directories have this feature enabled. Document directories that do not have this feature enabled via a style definition will not have their files scanned for SSI commands, saving the server's time and making the Web site a little more secure.

If you want to make a style that you assign to a directory so that the Web server automatically checks every HTML file for SSI commands as it's being sent, just select the Yes button on that page after selecting a style from the dropdown list. You can either select "Yes with Exec," which is an unqualified Yes, or select "Yes without Exec," which indicates that files will be scanned for SSI commands, but the Exec command (which causes the biggest security concern) will be ignored.

Finally, you can define which files in the directory that this style is assigned to will be scanned. It can save a lot of time to restrict this to only .html files, or only files with the execute bit set. Using only the execute bit can save your server a lot of extra processing in going through files that don't even use SSI commands.
