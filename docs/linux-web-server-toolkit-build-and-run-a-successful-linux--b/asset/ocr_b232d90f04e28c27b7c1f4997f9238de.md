In each case, you can link from anywhere in your Web pages to a service in one of these other protocols using a regular < HREF= ... link tag, but with the URL specifying the other protocol instead of "http" for another Web page. For example, if you want users to download a certain FTP file when they click on a link, you can use an anchor tag with a URL like this:

```
<<A HREF= ftp://ftp.sunsite.edu/pub/linux/filename >Download this file</a>
```

Of course, a URL allows you to link to a service on any server on the Internet, but it often makes sense to serve these services on the same computer that runs your Web server. # Providing FTP Access

FTP, the File Transfer Protocol, is almost as widely used on the Internet as the Web. But FTP's purpose is different. It transfers files of any size from an FTP server to a user's computer (the client). Files are not meant to be viewed immediately, and they can be in any format. The file transfer takes place in real time (unlike e-mail), and the protocol can work with very large files (many megabytes) as well as transfer small files of several thousand bytes.

FTP is most used on Web sites when your Web pages refer to something that users can get from for later use, to view or run on their computer, as opposed to another Web page they can read immediately. Examples include copies of demo software, large video clips or pictures, printed forms or catalogs, and so forth.

Moreover, these items are commonly in a format that is not read by most browsers. Hence, the user needs to download the file and use another program to read it. In addition, these files may be very large, especially in the case of demo software, which can take up many megabytes. These large files would bog down your Web server, which expects small files and quick connections with the Web browser.
