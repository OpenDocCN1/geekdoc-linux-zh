## Other Types of Gateways

There are many other types of information available on the Internet about gateways in addition to those I've mentioned in this book. A Good Web browser supports many formats, including FTP, gopher, multiple graphics formats, and others. But so many formats exist that you'll see many more Web gateways come use in the next couple of years.

The Web is becoming so strong and prevalent in the computer area that any type of information, especially on the Internet, will likely be available via a Web page before load. The other formats supported by a browser are great for reading those formats natively, but more, and more, data will be provided in HTML format to place the burden on the server instead of the client. I say this in spite of the number of client-side enhancements (plug-ins) that allow various multimedia additions to existing browsers.

Some of the data formats or protocols that can be made available now over the Web using gateways include the following (see Table 16-3 for example URLs):

- *WAIS*: Servers providing on the Wide Area Information Service, a server indexing program that you search across many servers for relevant information. (see Table 16-2.)

- *Finger*: The personal information service finger provides a username, full name, and a couple of facts about your user's account, as whether the user is currently logged in. This is a standard UNIX information service that is traditionally entered at a command line.

- *Newsgroups for newsgroup-capable browsers*: Newsgroups are very popular, but not all have the ability to process newsgroups and allow for reading and posting messages. Gateways for the NNTP news server protocol can allow newsgroups to be read and responses posted using standard HTML pages and forms.

- *Mailing list archives*: Described under the e-mail gateways section above, gateways for mailing list archives provides thousands of messages from active mailing lists in an easy-to-read format with searching, indexing, and color-coding of messages.

- *Other proprietary formats*: Other formats, both those on the Internet and those that are created or maintained by businesses for their special needs, are finding Web gateways an ideal way to promote easy access to their information.

## Summary

This chapter explained how gateways can make virtually anything accessible via a Web site, and you've seen how valuable that can be to organizations needing to share data that is regularly created or already exists in other formats.

In this chapter you've learned the following:

- Gateways are used to make non-Web data types available to those who browse your Web site.

- E-mail gateways are useful for processing data from forms that users submit, or for providing Web pages to users who have only e-mail access to the Internet.

- Database gateways are an important capability added to many Linux Web servers because much important data is stored in database formats. Web gateways make this data available via a Web browser.

- Many other types of gateways exist for Linux. These gateways allow most types of computer data to be prepared and then distributed using a Web server.

- In the next chapter, you'll see how using Web server APIs can let you add functionality to your server in a more profound and high-performance way than with scripts or the Java programming discussed in previous chapters. You also learn that you can even use APIs to create gateways that are tightly integrated into your Web server.

## What Are APIs?

You can probably do a lot with your Web server at this point. But I imagine you can also think of things you'd like to do with your Web server but can't see how to accomplish using the tools you've learned so far.

That's where web server Application Programming Interfaces, or APIs, come in. A set of APIs is like a set of programming functions that let you pass data back and forth between the Web server's core functionality and your added components.

APIs are developed to extend the capability of Web servers beyond what the designers of the server could immediately see. APIs allow you to add functionality that is more complex than standard Web server features, or just features that are more carefully suited to the needs of your site.

A server API allows you to interact at a much deeper level with the Web server. In fact, in both Apache and Netscape FastTrack, most of the functionality described in this book for these servers is implemented through the API. That means you have access to just about anything you need. API functions you add to the Web server function as rapidly as the Web server itself. While interpreted scripts and even C programs must be started as separate processes, loaded into memory, and initialized, a Web server module you create with one of the APIs is actually part of the Web server and therefore is loaded when the Web server starts and ready to work for you at any time.

## Introduction to the Apache API

The Apache server's API is a very generalized interface to the server. In fact, most of the functions described in Chapter 11 are implemented as modules to the core server. This includes all the URL management (aliases, user directories, and so forth), user authentication and password files, and access control functions that check whether a host is allowed to access the requested file. Other examples include all log management (which is totally configurable if you load in the optional log file module) and server side modules.

Some Apache modules are specifically written as "handlers" that deal with a particular type of data on the Web server. For example, one module might handle processing for all requests for JPEG graphics. Because of this design, you can easily add your own module to handle a new data type, or to replace a handler for an existing data type. For example, you can add a data type that utilizes a different method for automatically compressing files based on the headers sent by the client browser. Or, if one of your pages uses a part of the standard functionality of Apache, as the image map functions, you can recompile Apache without that module to save space in memory for each running copy of the server.
