# THE XF86CONFIG MONITOR SECTION

Things start getting more complicated in this section of XF86Config. The Monitor section contains definitions for one or more monitors, including an identifier, vendor name, model, and all the frequency values mentioned previously.

The most important part of the monitor section is the ModeLines. This series of lines defines how to create a certain resolution on the monitor by specifying the timing values for horizontal and vertical scanning. The problem is that you can't just make these up. If you can't get the configuration utility to create them for you, you should look for a sample file on the Internet that uses the same monitor model as yours. Copy the Monitor from that configuration file and insert it into yours.

Each ModeLine has a name, which is usually the resolution but can be anything (note it's in quotation marks). The dotclock specifies the timing base to be used on that line to generate the horizontal and vertical timing values to create that resolution. Each video card can generate certain dotclocks, as listed in the next section.

If you get the ModeLines correct, you won't damage your monitor because the X server won't try to send anything to the monitor that isn't listed here as a feasible option. The section is as follows:

The Monitor section can have several monitors defined. That's why each one has an identifier line. The Screen section ("The XF86Config Screen section" later in the chapter) can then refer to a specific monitor by name. This also gives you some flexibility in having multiple hardware options supported by your system.

# THE XF86CONFIG DEVICE SECTION

The Device section of XF86Config defines the video card you're using. As with the Monitor section, you can have multiple video cards defined, then specify one as the target to create a display section.

The Device section includes a lot of the same lines as the Monitor section, such as the vendor and model name. But the Device section also includes several key options, as follows, that can be a challenge to enter:

- Chipset: This is the type of video chip that is the brain of your video card. Common high-end video chips are ET4000, S3, and Cirrus Logic. You can see the chipset by looking at the actual board or reading the specification sheet.
- VideoRam: This line tells how much RAM in kilobytes is on the video board. If your video card has 2MB of RAM, this line would have the number 2048.
- Clocks: This line has a list of all the dotocks the video card can generate. This is the only really difficult line. You usually get these from a configuration utility or the specifications sheet for your video card. You can run X with the option -probe to try to get a list of the clocks for your video card.

The clock values must be listed very precisely with their fractional values, in the correct order— they are not arranged from lowest to highest!

- Options: This line contains options for a specific card or chipset. These options are interpreted by the X server for that particular card. As with mouse options in the Pointer section, don't add anything unless instructed by a document on your particular video card.

The section is as follows (note that this section differs from system to system):

# THE XF86CONFIG SCREEN SECTION

This is the section of XF86Config where you actually make something appear on screen. It combines the information in the other sections to define what to display on screen.

Within the Screen section, subsections for each resolution can be defined. The Screen section contains the following lines:

- Driver: The X server that is to be used for this screen; there may be a Screen section for each of several drivers, such as Accel, VGA16 and SVGA. This enables you to use different drivers without reconfiguring.
- Device: The identifier string for the video card definition that is to be used for this screen.
- Monitor: The identifier string for the monitor definition that is to be used for this screen.
- Subsection "Display": For multiple resolution settings–each "Display" contains the following lines:

- Depth: The number of bits to use for each pixel (a depth of 8 indicates 256 possible colors per pixel).
- Modes: The ModelLines from the Monitor definition referred earlier that apply to this display (usually, the entire list of supported resolutions of the monitor is listed). These are what you switch between when you use the Ctrl+Alt++ keys.
- View: The coordinates of the virtual desktop.
- Virtual: The size of the virtual desktop–you can define a virtual desktop so long as you have sufficient video memory.

# Using Your Network Connection

After you have your OpenLinux system installed and running, you can start thinking about networking to reach other computers and the Internet. If you're already connected to a local network with an Internet connection, it's a simple matter to start using your browser to view your favorite pages.

The networking information that you entered as part of the installation was used to create all the necessary configuration files to make your network connection function correctly. Of course, things don't always go as planned.

The network configuration of your system is made up of a few simple parts. If things don't go as you expect when you start trying to reach networked systems, you can start by checking the items listed in Table 5–4.

Files where Networking Configuration Information Is Stored

| Filename | Purpose |
|---|---|
| /etc/hosts | Lists the hostname and IP address for computers that you want to connect to. file usually lists localhost, your IP address, and may be few other important machines. The DNS name server is used to find other systems, but this file is used for those times when a name server cannot be reached. |
| /etc/networks | Lists network addresses and associated domain names that you want to have referenced for easy access. |
| /etc/resol.conf | Gives the name and IP address of the name server to use for looking up domain names. |
| /etc/hostname | Gives the hostname for this computer. |
