## Chapter 16

## Gateways: Providing Everything via the Web

IMPORTANT AS PEOPLE would say the Web has become (and I of course would agree with them), the world doesn’t revolve around the Web, nor has the Web been around long enough for its standardizing influence to have felt in many areas as it eventually may. For those reasons, numerous data formats that people would like to access or distribute via the Web as an easy-to-use and widely diffused mechanism are not actually compatible with the Web.

Gateways allow you to provide types of data other than those browsers normally support by enabling non-Web data to be delivered through the same system as HTML documents. Topics in this chapter include the following:

- Why use gateways
- E-mail gateways
- Database gateways
- Other types of gateways

## Why Use Gateways

The power of the Web and the reasons it became so popular so quickly were discussed in the first part of this book. Just to remind you, one of the biggest reasons it became popular was that almost every computer on the planet can get a free Web browser and access data in a common format.

Programs such as Lotus Notes sought to make a common database available to everyone in an organization but they still required that a piece of software be provided on every different platform. The Web had already taken care of that problem.

The idea behind gateways is to allow non-Web data to be delivered through the same system as HTML documents. That is, make data that wasn't developed to be delivered specifically through the Web available nevertheless through the browsers that everyone already has on their desk.

The next section provides an example that explains why gateways are so valuable and demonstrates how they are used.

## An Example of Using a Gateway

Suppose you have an intranet site in your nonprofit organization. You use the site to provide all the marketing documents, human resources forms, and various other things such as the annual report and company newsletter. All of these documents are either prepared originally in HTML format or converted to HTML so they can be provided on the public Web site because they are more useful as HTML documents than they are in a word processor (more people browse the site than read the paper newsletter). The intranet site, it seems, is quite a success.

One day the CEO comes to your office and suggests that it would be helpful to be able to track in real time the number of operators on the call-in lines, the donations received so far each month, and the number of children sponsored by the organization. He'd like to be able to view these any time by going to the intranet site with his browser.

Now if this CEO is most, he doesn't use a computer very often, and if you're like most employees, when the CEO says “wouldn't it be great if ... , spend the next week making it happen.

The problem with this data is that he wants to see the intranet site is located on a big UNIX server by a special-purpose package that has anything to do with the Web.

What you need a gateway.

Imagine the following arrangement. You create a Web page that has three graphs on it, one for each of the three things the CEO wants to see. Each graphic links to a small script on your Web server. These scripts don't work on the Web server or with HTML documents, however. When one of these scripts is invoked, it connects to the UNIX server that has all the needed information and, using special calls you've learned from the vendor of the special-purpose software, queries the various databases for the figures needed to answer the CEO's questions.

Once the script receives this data, it can easily prepare an HTML page that integrates the information into an attractive format, but the data retrieved in real time from a system that doesn't work with the Web. The script that you created acts as a gateway between the special software used by your organization and the formats of the Web that everyone these days can view in their browser.

## How Gateways Function

Of course, this example is very simple and doesn't really describe a generalized interface that can access any piece of information on the specialized software. Most gateways attempt to provide this type of generalized interface so that you can access anything you need from the other source.

Gateways are often separate programs that run in addition to your script. You find a gateway that you can use to access another data type, your script can query the gateway program that takes care of the interface to the other system, something like Figure 16-1. At other times, it's more efficient to use a script that directly interfaces with the target data system. Or a gateway can provide the entire interface, so that your Web pages can use the gateway directly as the script to process a request from a fill-in form, and you have nothing else to program.

## E-Mail Gateways

E-mail on the Internet is actually more popular than the Web. The Web just gets all the good press. That is, even more people have e-mail accounts than have Web browsing access, and anyone who can browse the Web has an e-mail account as well.

For these reasons, one of the most-used types of gateways on the Web is an e-mail gateway. There are two types of e-mail-to-Web interfaces, both of which can be called gateways. They are the following:

- Gateways to send Web pages to people with only e-mail access
- Gateways to forward Web page form data as e-mail

## Gateways to Return Web Pages by E-Mail

Many people who want to access the Web don't have the ability to browse Web pages because of country restrictions, router restrictions, delays over the Internet, or other problems. All these users can really do on the Internet is receive e-mail.

## Linux Web Server Toolkit

This type of e-mail gateway allows a user to send a URL by e-mail to a special e-mail address at the gateway system and have the Web page mailed back to him or her by the gateway. This doesn't preserve the graphics in the page and isn't done in real time browsing with Netscape. It allows anyone with an e-mail account to browse Web pages — slowly — retrieve the wealth of information that is available now on the Web.

## Gateways to Forward Form Data as E-Mail

This type of e-mail gateway is probably more what you had in mind. As you read about the use of forms on your Web page, you probably thought at point: all I want to do is to have the information from the form e-mailed to me so I can work on it.

There are many tools that allow you to create pages that do exactly that. There are toolkits let you program or arrange how things are. There are also very generalized interfaces that will accept the data from any Web form — and therefore require almost zero programming or intervention on your part — and e-mail it to a given e-mail address in a standard, structured format.
