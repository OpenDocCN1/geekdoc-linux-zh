
## Web Servers: How Much Power Do You Need?

It can be hard to guess how popular your Web site will be before you even get it up and running. Luckily, it's easy to upgrade today's hardware with only 20 minutes of downtime.

Many Web servers run on "slow" Pentium systems with 8 to 16MB of RAM. Of course, others run on Pentium Pro 200 systems with 128MB of RAM. While you'll need a less expensive system using Linux as your Web server than if you were using Windows NT, the following pointers may help you decide how powerful a system you really need.

## PROCESSOR

Get the fastest CPU you can. Changing a CPU is fraught with risks, and switching everything to a new system takes a lot longer than adding memory or hard disks. That said, a Web server is not generally a CPU-intensive system. The exceptions are if your Web server will be running a lot of CGI scripts or if you have database activity on your site. These use a lot of processing power and can bog down a CPU when the Web site is under heavy use.

A Pentium 90 can handle small Web sites (up to about 10,000 hits per day) without a problem if it has adequate memory. Considering the falling costs, it seems unwise in most cases to use less than a Pentium 133 for your Web server unless you need to use an existing machine.

## MEMORY

The largest single factor affecting Web server performance under identical load conditions is the amount of RAM on the system. As you'll see later, each hit on a Web server starts a separate process to respond to the client request for data. Having enough memory to handle many hits at once eliminates the need to stall requests or use the system swap space on hard disk to make up for the lack of memory. A Web server that runs a lot of CGI scripts or database queries requires more memory for the same performance because each request starts a separate program to handle the script or query. Starting a new script each time URL is requested takes longer than just sending a file, so a request for a CGI script uses a block of memory for a longer period.

Of course, it's easy to add memory to a system after it's up and running. A system with 32MB can handle a small Web site, but if your site needs to sustain more than 10,000 hits per day, and has large files (over 10MB) or many CGI scripts, make sure it has 64MB or more memory.

## HARD DISK

Hard disk space is becoming more plentiful all the time but it's not a big consideration for Web sites. Your site plan can help you easily determine what size of archive you'll need for your files. The size of the hard drive has no bearing on Web server performance. Just be certain you get a high-quality hard drive with good access times.

Most computers that you see advertised will come with an IDE hard drive. While this standard hard drive interface is for personal use, a SCSI hard drive is the preferred choice for Web servers. SCSI peripherals can achieve data transfer rates far higher than IDE devices, especially if the latest wide SCSI or ultrafasc SCSI cards are used. This higher data rate is critical in a busy Web server, where the hard drive can be a bottleneck for server performance.

## Using Modules for Hardware Support

Linux and the drivers that interact with hardware are great at using hardware to its maximum potential. Most of the drivers can be tuned to use specific software addresses or certain feature sets.

The 2.0 kernel includes a great feature: the capability to use modules for hardware support or other functionality. A module is a small piece of software that can be loaded into the kernel at any time. As you install OpenLinux, remember that each module supports a specific type of hardware. Some modules are more generic (like a floppy disk support, which is very standardized) and some are very specific, like a module for a certain model of SCSI CD-ROM drive that has specific features none of the generic SCSI or CD-ROM drivers work with it.

> Modules used for many things in Linux, including Java and many types of networking (such as PPP and IP/SPX). I discuss modules relative to how they are used during the installation of OpenLinux. You can learn more about modules from the insmod manual page or the Kernel Hacker's Guide (part of the Linux Documentation Project on the OpenLinux CD-ROM).

Modules make it easy to add just the hardware support you need without having everything with the kitchen sink in the Linux kernel and "making" the kernel (recompiling from the source code) to add support for new hardware. The modules enable hardware support to be added or removed without rebooting the Linux system, an important feature for a busy web site.

When you install the OpenLinux CD-ROM, default modules are loaded. Depending on your hardware, you can load other modules to provide support for your system.

After the installation is complete and you have started up your Linux system, you can use simple commands to list the modules that the kernel is using or to add or remove a module from the running system.
