Most of these packages are freely available because creating an e-mail gateway is an easy task, especially on Linux. Once a script has all the form data collected from a Web page, it can be e-mailed using a single command, or a standard data pipe can be opened to send the data directly to the e-mail server for processing.

You can try writing your own simple e-mail gateway using Perl or a shell script as bash. Use one of the best, the free downloadable packages listed in Table 16-1 as a code sample to guide you, if you prefer. I have tried to indicate in Table 16-1 whether the e-mail gateway is a generalized solution that requires very little effort on your part, or whether the package is a toolkit that you can use to customize a solution for your own forms or Web sites needs.

Remember that these gateways are between a Web server and e-mail client, and some work in both directions. These are not gateways between different types of e-mail systems. These packages all use standard e-mail systems on Linux and UNIX with the SMTP standard protocol for e-mail. They do not allow you to e-mail from Lotus CC: to the Internet or from Novell MHS to Lotus CC: That requires a different type of gateway from those we are talking about.

There are other types of software that might also be called e-mail gateways. One is a service that sends you an e-mail notification when a Web page you are interested in is updated.

Another is a package that automates providing a mailing list archive as a collection of HTML documents, maintaining discussion threads and chronology, and creating convenient links between articles. I think both of these are a stretch of the e-mail gateway, but both are useful, and you may need them for some point.

Another important type of gateway for many Web servers is a database gateway that allows data to be delivered easily in a Web page. These gateways are described in the next section.

# Database Gateways

Database gateways for the Web are probably the most important use of gateway technology. I say this for two reasons. First, using the Web as the delivery mechanism can eliminate the need to develop specialized database client software. In many cases, this removes a sizable burden from software developers.

You may remember some of the specialized database client development tools of a few years ago. Tools such as Borland Object Vision appeared, the main focus of which was on easily creating a specialized database client to access a large-base on a server somewhere in the organization. But even after you spent the time creating an Object Vision program to access the data and present it nicely on the user's screen, you still have been provided for only one platform. If someone in another department happened to have another type of system (Macintosh, Amiga, UNIX), the Object Vision program was of no help.

Having a database gateway to a Web server places all the programming and development on the Web server. This is not as easy as Object Vision (though there are many tools available; see Table 16-2), but it solves the larger problem very nicely: once you've written the program to make the database information available and upgradable, if need, by HTML documents or forms, everyone in the organization can access the information.

The reason that database gateways are so critical is that more business information is stored in database formats than any other format. Gateways allow all of information potential to be delivered to users via the Web.

Because of the amount of business information stored in databases around the world, database gateways are one type of gateway that has spawned the most commercial participation. Hence, you have many commercial solutions for both proprietary systems and for generalized solutions, in addition to the many strong offerings written in Perl or C that are free for you to download and try.

Some of these packages are toolkits that you can use to design your own scripts according to the requirements of your database. Others are complete and often complex systems that will interface with a specific type of database. Several database gateway products are described in Table 16-2. Remember that this is only a sampling of available products, both free and commercial.
