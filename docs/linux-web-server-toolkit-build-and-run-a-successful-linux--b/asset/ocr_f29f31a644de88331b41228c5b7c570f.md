The second reason that Linux has succeeded so well is because Linus Torvalds decided to distribute it under a different type of licensing agreement: the GNU General Public License. This license has some unusual provisions that encouraged the development of a collaborative project like Linux. Understanding the GNU General Public License is important to understanding the success of Linux as well as its continuing development.

# The Gnu General Public License

The GNU General Public License (GPL) is the creation of Richard Stallman. Mr. Stallman's work was based on the belief that software should be free. By free, however, it means freedom, rather than tied strictly to commercial control. It doesn't mean free of cost. Mr. Stallman is part of the Free Software Foundation, which espouses these ideals of software development. (See http://www.fsf.org). The GPL is different from other software licenses. A person who creates a piece of software always holds the copyright to that piece of intellectual property. The copyowner can distribute software under any license that he she chooses. By deciding to distribute the software under the GPL, the software or documentation can be freely distributed under a couple of unusual conditions (I'll simplify the long license here a bit):

+   The source code to the software must be available (usually included on the same media).

+   The software or other intellectual property can be copied and redistributed by anyone, as long as the terms of the GPL are followed.

+   Any user can make any changes or upgrades to the software, as long as such revisions are also distributed or available with the original software.

The underlying principle of the GPL is that software should be free, so sovereign-people may, however, pay for the media the software is delivered on, or the expertise (consulting, technical support, and so on) that makes it truly valuable for them. What does this mean? It means that anyone who contributed to the Linux effort was contributing to the entire community of Linux. There was no way to create a new component for the kernel-the core of the Linux operating system-and hold it proprietary, selling it as an upgrade or something similar.
