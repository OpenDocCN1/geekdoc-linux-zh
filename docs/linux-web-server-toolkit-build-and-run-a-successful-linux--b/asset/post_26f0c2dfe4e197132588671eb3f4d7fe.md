
Once you have installed and tested the modem, you can use the /dev/modem device name in all the scripts that you prepare in the following sections.
The PPP programs are installed by default from your OpenLinux Lite CD-ROM. To start PPP, you create a script that dials your ISP, logs in, and starts the PPP daemon on your Web server.

## CREATING THE CHAT AND PPPD SCRIPTS

You can combine everything into a single command on a line, but using a couple of text files gives you more flexibility, I'll describe it that way.

First, create a script for the chat program to follow. The chat program uses your modem to have a conversation, a chat, with another computer. Each line in the script is a reply-response pair. The script waits for the reply from the modem (the remote system), then responds as directed. (The lines starting with ABORT indicate that if the words are found at any time, the whole operation should be cancelled.) The following script can be stored anywhere because you'll give the pathname to when you use it. For example, you could place it in /etc/ispconnect.chat.

```
abort NO CARRIER
abort BUSY
ATDT5558762
CONNECT
login: ppp
password:          password
```

The interpretation of this script is as follows (a carriage return is added after each response):

1. If the words NO CARRIER or BUSY appear at any time, exit the script and stop everything.
2. Don't wait for anything; just send the dial sequence to the modem (this number should be your dedicated phone number to call your ISP).
3. When the word CONNECT appears, do not do anything (just know that you're on the right track).
4. When the word Login: appears, respond with the special login account name that your ISP gave you to connect using PPP. Not knowing exactly how the login prompt will begin (capitalized or lower-cased), the script just uses the last part of the prompt. (You can test this by hand and adjust the script to fit.)
5. When the word Password: appears (wait for the end of it), the script responds with the password for your ISP account.
6. You would now logged in at a command prompt on the remote system, but you don't use the chat program alone.

## Chapter 7: Connecting to the Internet

Next, set up an options file for the PPP program. This file must be stored as /etc/ppp/options. The following is a good sample to start with:

```
# PPP options file
mru 296
crtscts # use hardware handwriting
modem # use the modem control lines
defaultroute # make this the default route for all network traffic
```

Finally, you can execute the pppd command to make the connection to your ISP. Just use this command line, adjusting for the device used by your modem:

```
pppd /dev/ttyS0 115200 connect chat -f /etc/ispconnect.chat
```

This single command says to connect – don't wait for the remote computer to respond – using the given device at a speed of 115200 baud. The script is executed before the pppd command and prepares the connection that pppd uses.

![](img/e01f1106dd2902613fa07890c8baa7e6_222_0.png)

> Always use a higher speed than your modem when defining your connection. The speed in the previous pppd command indicates how fast data can be sent to the modem. If your 33.6k modem has a burst using compression of 90K, you don't want the data stream from your programs to hold up its progress.

pppd uses the options in the second file you created as it starts up. pppd has many options that you can view by entering man pppd.

Once you run this script, the connection with your ISP begins and you can immediately use network commands such as ping your Web server. You're live on the Internet through your ISP.

Problems usually occur with setting up correct domain name resolution and IP addresses, as your gateway. Adding the debug option to pppd options file /var/log/messages. You can also start to diagnose any problems with the ifconfig command, which will list the PPP connection, and the route command, which will list PPP as the default route. Other networking parameters, such as the Web server's IP address, are assigned automatically during the PPP process. You can, however, have ISP assign you a specific IP address each time to make your Web programming and security easier to manage.

## SECURITY

Letting someone log in your system using PPP is like letting someone onto your Network. It's a lot more dangerous than giving them a shell. That's why some ISPs do not use PPP. But PPP has at least two security methods to guarantee that you are the one authorized to connect to the ISP. One is called Password Authentication Protocol (PAP); the other is Challenge Handshake Protocol (CHAP). I'll describe the second, as you're more likely to see it in use.

CHAP uses a secret phrase that is stored on both computers. It is encrypted and compared during the PPP connection. If the phrases don't match, the connection is dropped.

When your ISP gives you a pass phrase, create a text file called /etc/ppp/chap-secrets. The file can contain the following line:

```
www.mydomain.com myisp.com_pass_phrase
```

## AUTOMATING YOUR CONNECTION

A modem connection is inherently not as stable as a digital connection, but it can remain up for days or weeks at a time without problems. When you want the system to come up as effortlessly as possible, assuming that your Web server is operating full-time and that you have a dedicated connection to your ISP, you would want your modem-based PPP connection to the Internet to come up whenever the connection is turned on. To do this, add the ppp command from the previous section to the end of the file /etc/rc.d/rc. The ppp command will be executed each time the system boots and make your ISP connection immediately, before anyone logs in. You can also try using the dial command, which automatically calls your ISP and makes a PPP connection whenever someone makes a request for an Internet connection. Follow the dial man page for more information (enter dial at any prompt).

## Other Types of Connections

Other connections are not nearly as easy to set up as a modem connection. That may sound discouraging after reading all the details of the previous section. There's so much to know, and so many options, that I can't explain all here. I provide some direction, however, to get you started.

If you're going to use a digital connection (described in the next section), this is about the best piece of advice I can give: develop a good relationship with your ISP technical staff and find a knowledgeable salesperson to guide you through the maze that is local telephone company. It wasn't long ago that you could call your telephone company's business service numbers and talk to ten people before you knew what ISDN is. The Internet has become too large a part of their business for that to happen now, but you'll find different levels of familiarity with your needs and the available technologies. When you find a salesperson or technician who is familiar with the type of system you plan on using or how to get problems resolved, stay in touch and treat that person well.

For a digital connection you'll be working with your ISP much more closely than for a modem connection. Your telephone company may actually call you whenever the connection between you and your ISP is not active for more than a minute.

The online documentation in your Linux system contains a list of consultants who are Linux experts. Consult the following file: /usr/doc/HOWTO/Consultants-HOWTO.gz. The following section has a little more information on digital connections.

## USING ISDN ON LINUX

ISDN connections use a special adapter card or, preferably, an external ISDN modem device that communicates over ISDN telephone lines. Because the ISDN standard has been active much longer in Europe, most of the available Linux support comes from Germany.

Several ISDN cards are fully supported in Linux, including the Teles cards and the Combine EverWISE 1000 series. Support for the Teles card is already standard in the Linux kernel, in fact.

Some special cards that rely on ISDN are also supported, as the ISTEC board for a PBX system. Several cards are also available that appear to the Linux system as regular Ethernet cards or serial mediums.

If ISDN sounded like a good option as you reviewed the tables in this chapter, begin by contacting your chosen ISP and your telephone company to see if they offer ISDN service. Once you've determined that they do, a good place to start learning about your options for Linux hardware is by reading the information at http://www.ix.de/ix/linux/linux-isdn.html.

Unfortunately for many of us, the information referred to on that ISDN "home page" is written in German. If you understand nicht, like me, you can also contact one of the growing number of U.S. ISDN card makers and inquire about Linux support. Search for ISDN at http://www.yahoo.com/

## FRAME RELAY AND LEASED LINES

As ISDN connections, the offerings of your ISP and telephone company will determine what options are available to you for very high-speed lines. Frame relay and leased lines are two technologies that can be used at many different speeds, from 56K to T3.

The configuration of a frame relay or leased line is beyond this book, if I know what hardware you were using. But once that information is known, the connection can be set up by a knowledgeable person in an hour or two.
