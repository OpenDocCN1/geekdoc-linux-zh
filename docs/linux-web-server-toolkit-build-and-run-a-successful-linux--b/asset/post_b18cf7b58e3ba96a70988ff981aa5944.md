In the On/Off page, you choose the On button to start a secure session, and the port that the secure port of the server should listen to for requests. You should use the standard port number of 443.

Finally, enter the filenames where the certificate is located, and where the key is located (generated by the Generate Key page). Once you have the encryption feature of FastTrack up and running, you can use it simply by making links to https:// instead of http:// at your same server address. A browser will use the 443 port number and access the secure connection, automatically using the keys from your server to transmit information. Because users aren't accustomed to entering https:// as a URL, you'll usually want to create links to the secure sections of your Web site. Here's one example. When you have a form that is submitted, the action of the form would have a secure URL:

```
<FORM ACTION= https://www.monkeys.org/cgi-bin/placeorder.pl
METHOD=POST >
```

Having a secure server in place opens a new set of possibilities for your Web site by removing (or decreasing greatly) the risks that people really assume are inherent in online commerce via the Web. Learning about the electronic payment options available, and the offerings of certificate authorities will help you understand how electronic commerce technologies can enhance the value of your Web site to your users.

## Configuring Programs

The Programs section allows you to set specific items so your server can prepare information to be sent to browsers.
The options available are quite simple:

- CGI Directory page: This page lets you define which directories are considered script directories. Whenever a browser requests a file from within one of these directories, the file will be executed, and the output of the program sent to the browser. The default directory for this is /cgi-bin (off of the ServerRoot directory). You can add as many other directories to this list as you need.
- CGI File Type page: A handy feature of the latest crop of Web servers is the ability to use a special MIME type to indicate scripts on the Web server that should be executed instead of returned regular files. This means that you can place a script anywhere without worrying whether it is in a directory that the Web server has marked as a "script directory."

Instead, you can select a section of the Web server, or the entire server, and define CGI files as a file type. When this is done, any script file requested will be executed instead of returned as a regular file.

- Java page: Java is the C++-like language developed by Sun that seems to be taking over the software development world. The FastTrack Server allows you to run Server Applets. These are small programs written in Java that run on the Web server in order to prepare information for a Web browser. They are very useful because they can be passed to the Web server and run no matter what platform the server is running on. Though they are not used a lot right now, they promise exciting new capabilities in the near future. More information about Java is provided in Chapter 15.

In order to allow Server Applets written in Java to function properly, you must enable the Java interpreter on the FastTrack Server by activating it within this page. The directory on the Linux system where related Java files are located must also be specified.

## Viewing Server Status

The Server Status pages allow you to monitor a wealth of information about how your Web is being used. It even provides a set of basic statistical information and reports like those described in Chapter 13.

Most of the information on the Server Status pages is based on log files. You've read a little about log files already, and you'll read a lot more in Chapter 13. FastTrack provides a lot of configuration options for log files that can be very useful in learning how your server is being used. Chapter 13 contains a list of how statistics generated by FastTrack or other programs can be used to benefit your Web site. The next sections outline how to use the pages in this section.

## View Access Log

The View Access Log page lets you view the transfers logged by your FastTrack Web server. You can choose the access log that you want to view. In most cases, this will just be the "access" log, with no others available. If you've used the Log Preferences to set up other log files for things like agents and referrers, you'll also see those listed, so you can view entries from those log files as well.

## Monitor Current Activity

The Monitor Current Activity page is one of the nicest features of FastTrack. It shows you (in real-time) how your server is being used. The page has a button that allows you to view the monitor page. Once you click that button, the information that is displayed is updated every seconds.

The items shown on the monitor page include the amount of processor time (as a percentage) for several activities that your server works on as requests are processed. Examples include writing rules (retrieving files and running scripts) and processing hostnames (resolving IP addresses and checking security settings).

You can use the server monitor to view the overall system load, or thread utilization, and the percentage of return codes that are successes and errors. The Monitor page is shown in Figure 12-13.

## Archive Log

The log files that record every error and every transfer grow continuously as your Web server is. In fact, on a busy server, they grow quite fast. As mentioned in Chapter 11 and Chapter 13, you have to archive log files so that they can be examined, stored, or whatever you choose, without threatening to use all your available disk space.

A simple script can be used to rotate log files without losing any log entries. FastTrack provides an even easier method with a click of the Archive button.

A second set of buttons allows you to select a standard time for archiving the log files each day at a certain time, or on any days of the week that you choose.

The statistics automatically generated by FastTrack include the Generate Report page, but you may also want to use some of the other statistical tools available for Linux, as described in Chapter 13. Archiving your log files makes them conveniently available for analysis with other programs later on.
