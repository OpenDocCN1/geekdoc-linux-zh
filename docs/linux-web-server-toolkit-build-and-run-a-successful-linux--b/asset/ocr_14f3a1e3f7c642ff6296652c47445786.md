# Chapter 15: Using Java and JavaScript

# Understanding JavaScript

Netscape originally had a scripting language that allowed browsers to interact directly with a user without interaction from a CGI script on a Web server. At the same time that this scripting language was being finalized, the Java language was gaining momentum. Through an arrangement between Sun and Netscape, the scripting language came to be called JavaScript and to resemble Java to some degree.

But the resemblance is not really strong, and the two differ widely. Whereas Java is a compiled language that uses a full development environment to create a binary executable program, JavaScript is an interpreted language in which generally small scripts are embedded in HTML pages using a text editor.

JavaScript programming centers around adding small pieces of functionality to Web pages — things that can be done within a browser environment. Java programs may run in this environment but can also be designed to run stand-alone applications; even something like a word processor can be written completely in Java.

# Understanding JavaScript’s Limitations

Because Java and JavaScript applications can be placed on a Web server and run on a Web browser, they could pose a security threat. Imagine if you were browsing the Web and downloaded a Java application that formatted your hard disk or secretly searched for certain files and e-mailed them to another company.

However, because everyone regularly browses sites where they can't be certain of the intentions or integrity of the information provider, Java and JavaScript have certain limitations that permit their use without the dangers that these scenarios pose.

Basically, Java and JavaScript applications can access files and other system resources, as only when run in a nonbrowser environment. When you download and run a Java application on your system, you can feel safe about files and data. This is a restriction placed on the application by the browser. Some browsers such as Netscape Communicator have configurable settings where you can set how much access a Java or JavaScript applet should have to your systems resources or to the network. For example, common settings for networking offer one of three choices: disallow any network connections, allow connections to the server from which the applet was downloaded, or allow connections to any host on the Internet. If you're running a Java application locally within a JVM rather than within a browser, the security concerns removed and the Java program can access your system resources.
