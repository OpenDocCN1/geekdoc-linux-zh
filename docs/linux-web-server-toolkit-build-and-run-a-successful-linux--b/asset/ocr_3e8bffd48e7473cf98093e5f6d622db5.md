Submit button on the fill-in form is linked to a URL. That URL refers to a script on the Web server. When you click on the Submit button, the name and address from the form are sent to the Web server. The Web server, noting that a script has been requested by this URL, saves the name and address internally and starts the script.

The script retrieves the name and address that were sent from the form (you'll learn later in this chapter how to retrieve data). With that information, it's a simple matter to perform any necessary actions. In this case, sending an e-mail containing the name and address to a preset e-mail address. The script also sends a short response back to the Web browser with a statement that the data was received and processed – something like: Thanks for your customers. They've been sent to our Sales Department.

The response from the script is the end of this process. The Web server doesn't send anything back to the browser. When a script is requested, the Web server starts the script and then goes to the next browser request.

# Understanding Server-Side Includes

Before explaining the details of how to use scripts and forms, I'm going to pause to explain a related feature called server-side includes (SSI). SSI provides a basic HTML preprocessing language using a set of predefined commands.

What does that mean? An example will help. Suppose you had a document that you wanted to always have the current date at the top. You could create a script that run every night on your Web server to alter that file and insert the date. That sounds like a lot of work, but it would do the job. Suppose instead that you wanted to have the time of day as part of the document. Now, what can you do? Actually, in either case, a server-side include provides the easiest solution. All you do is include the following line in the HTML document:

```
<! echo var= DATE_LOCAL >
```

Your document will include something like Tuesday, 19-Aug-97 08:30:44 MST. What's happening herenThe above above a comment to the HTML parser in your browser, because it starts with < and ends with >. If it didn't, the browser would try to interpret it as a tag or display its contents. But if you have enabled server-side includes for the directory where this file is located on the server, then the Web server will go through each HTML file before sending it, checking for lines like the one above and processing the command in them, substituting information in the file according to the command as it is sent to the browser.
