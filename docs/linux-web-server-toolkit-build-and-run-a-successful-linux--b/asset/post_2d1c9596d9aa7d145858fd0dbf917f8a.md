## Where Did Linux Come From?

The easy answer to the question of where Linux originates is from Lin Torvalds. Linux was a student in Helsinki in 1991 who started a project to develop a UNIX-like operating system for an Intel processor. He posted it to the Internet newsgroups to ask for suggestions and comments. Before long, a number of skilled people were adding their knowledge to that of Linux.

As the project grew, hundreds of developers around the world began to participate. Linux remained the focal point for the operating system kernel, while many other components in a typical Linux system (including the one on the CD-ROM that comes with this book) came from the GNU Free Software Foundation, the XFree86 Project, Inc., and similar software developed under nonrestrictive licenses.

## Linux Web Server Toolkit

Linux continues to maintain the Linux kernel, with contributions coming in from people over the world who have expertise and interest in contributing their time and effort to a project that gives them a little notoriety, a lot of goodwill, and good software. Lin Torvalds graduated and moved to Northern California in 1996, but the Linux project continues under his leadership.

In the time since Linux first asked for suggestions on his kernel experiments, Linux has developed into all-featured an operating system as anything available in the computer industry. Experts in networking, graphics, device drivers, virtual memory, and multiprocessing–just to make a few components of Linux–all have contributed to making Linux powerful and complete system.

Why did Linux succeed well in such a short time? For two reasons. The first is the Internet environment in which it was created. This worldwide infrastructure allowed people to work together across continents and time zones. It allowed people of diverse backgrounds to contribute their unique talents without constraints of time and place that a standard development team would face. In addition, the goal of the contributors always seemed to be create the best software. If you read the e-mail and newsgroup traffic of the development teams, you'll notice great professionalism and very little ego.

## Web Server Requirements

As everyone scrambles to get on the Web, organizations and individuals seem to be running Web servers on any system at hand. While any Web server may be better than no Web server, the following is a list of requirements for a Web server platform:

- **Multitasking**: This an operating system to handle multiple Web client requests at the same time and to process scripts at the same time as it prepares Web Pages. This requirement excludes Windows 3.1 from the running.
- **Support for popular Web scripting languages**: Thousands of standard scripts are available for languages as Perl and Tcl. Operating systems that don't really support these languages are at a real disadvantage.
- **High performance**: Busy Web servers place a heavy load on an operating system. Tasks such as running scripts, sending Web pages over the network, and accessing many files simultaneously tax all parts of a system. This requirement places Windows 95 and most Macintosh systems on the blacklist for Web servers.
- **Adequate software tools**: Web server platforms should have Java, secure servers, and HTML tools.

## The GNU General Public License

The GNU General Public License (GPL) is the creation of Richard Stallman. Mr. Stallman's work was based on the belief that software should be free. By free, however, it means freedom, rather than tied strictly to commercial control. It doesn't mean free of cost. Mr. Stallman is part of the Free Software Foundation, which espouses these ideals of software development. (See http://www.fsf.org). The GPL is different from other software licenses. A person who creates a piece of software always holds the copyright to that piece of intellectual property. The copyowner can distribute software under any license that the chooses. By deciding to distribute the software under the GPL, it ensures a couple of conditions:

- The source code must be available (usually included with the media).
- The software or documentation can be redistributed by anyone, as long as the terms of the GPL are followed.
- Any user can make any changes or upgrades to the software, as long as such revisions are also distributed.

The underlying principle of the GPL is that software should be free, so people may, however, pay for the media the software is delivered on, or the expertise (consulting, technical support, and so on) that makes it truly valuable. What does this mean? It means that anyone who contributed to the Linux effort was contributing to the entire community.
