## Brute Force Attacks

Any password can, with time, be discovered by a computer. Computers are ideal for this repetitive task. You can make this easy task for hackers if you choose passwords poorly. A program created to determine passwords can try every word in a dictionary to see which gains access. Even many passwords, such as those formed by substituting a 5 for an "s" or a zero for an "o" by inserting a period or other punctuation mark in the middle of a word, can be checked by a good "crack" program. Choosing a good password becomes a challenge. Combinations of family names, fictional names, product names, with punctuation and mixed case.

As you know now, your Linux system has a user root, but the root user is often not allowed to log in remotely because of the risk it poses to security. Therefore, a hacker may try to find out another account to break into. Once the attacker accesses your system using any username, he can obtain the password file containing the list of all usernames and the encrypted passwords and that file to prepare other attacks. Your Web server can actually act as an accomplice in a brute force attack by sending a copy of the password file (/etc/passwd) to an intruder who is able to exploit a design flaw in a CGI script. This danger was explained in detail in Chapter 10.

You sometimes detect attempts of a brute force attack by reviewing your log files for numerous bad login attempts by the same user or from the same remote location.

If you suspect someone is attempting this type of attack, you can alert the administrator at the company or the ISP serving that user's site. If your passwords are well chosen, you would be fairly safe from this attack, but refer to Chapter 20 to learn why it's very important to back up all of your data.

Shadow password systems (which are available on Linux systems) separate user account information from the encrypted passwords for those accounts. If a person is able to obtain account information, the encrypted password is not available to attempt decryption. With a shadow password system in place, passwords can also be monitored more effectively—regular password changes, numerous encryption options, and other similar security enhancements can be used.

## Keyboard Readers

A hacker attacking a keyboard reader will try to replace your keyboard driver with a new version that records your keystrokes. The keystrokes are e-mailed to the intruder or stored in a file. The hacker will review their keystrokes to uncover usernames and passwords. This type of attack is very effective, but very hard to do on Linux, it's not attempted very often. DOS and Windows systems, which are prone to viruses, can easily be subject to this type of attack.

Of course, in most cases a person who can access your keyboard driver in order to alter it is already already able to access your system without the keyboard attack. In many cases, this type of attack is added to other security breaches as a back-up plan. If other security holes are discovered, the keyboard reader will continue to send new information allowing the hacker to re-enter the system. You can detect this type of attack by reviewing e-mail or other logs that show unexpected traffic, the message that sends the data to a hacker is difficult to identify.

## Packet Sniffers

One of the most challenging attacks to counter is a packet sniffer. Packet sniffing is the process of gathering every packet that passes through a network and decoding it to look for useful data. Although billions of packets flow across the Internet day, only a small percentage passes through a given point, so everyone can't sniff the packets you're using. But simple computer programs can be used to decode and search for patterns in the packets.

Even your local organization is subject to packet sniffing. Strong security assumes that a computer within your organization is controlled by an outside hostile party and is being used to sniff packets. All sensitive information sent from your system should therefore be encrypted.

The Internet doesn't encode anything. Without additional software, everything is sent over the Internet in plaintext, which is easily read by anyone. That includes passwords, usernames, and credit card numbers that are sent without the use of any encryption techniques.

Packet sniffing is not illegal. It's done all the time to diagnose network problems at large ISPs. The difference is in how the information is used. Unfortunately, it's basically impossible to detect when a packet sniffer is reviewing your data. To counter attack sniffers, use any of several encryption techniques that make all of your sensitive traffic unreachable by a packet sniffer.

Most of your client connections (browsing the Web) can be done without fear of intruders because you're not placing any of your private information on the Internet. You are requesting files from another server. When you place an order for a product using your company's credit card, however, you want to be certain that you're connecting to a secure server (like FastTrack or Apache Stronghold) and that your browser supports secure connections. This ensures that your credit card is safe.

For other types of connections, like telnet or remote services, you can use security utilities that encrypt every packet using a very secure system. These utilities are not included in the Caldera OpenLinux Lite CD because they cannot be redistributed commercially, but you can obtain a copy of them from http://www.ssh.org. They include programs like ssh for secure shell logins and scp for secure remote operations.

## Human Error

The most difficult attacks to counter are a result of human error. People seem to regard network security as a minor concern and persist in choosing something obvious as the name of a spouse, child or pet, or a favorite hobby as a password. They write their password on a sticky note next to their neighbor or tell several coworkers what it is in case they need to access any files.

If an attacker is an acquaintance or an intended victim it's a simple matter to guess a password or find out by manipulating people without ever touching a keyboard. This is called "social engineering" in the hacker community. With a valid username and password in hand, an intruder can log in, set up all sorts of devious methods to ensure future access, and then begin attacks to gain root access to the system.

## Web Server Security Issues

Web servers do not provide interactive access to your Linux system, so they are not the ultimate goal of a hacker who wants to explore or destroy your data. Because Web servers are accessed by many people, they are an ideal entry point for a hacker seeking to learn enough about your system to force a larger attack using another method.

In addition, because Web server software interacts with many parts of your Linux system - including accessing files over the system, running scripts, and so forth—a clever user who can exploit a weakness in your Web server security can really cause a lot of damage and create a large hole, allowing him complete freedom to your system via other entry points as well.

The following list summarizes some of the most common ways that attackers may try to gain unauthorized access to other parts of your Linux system via your Web site. This list assumes you're familiar with the features described elsewhere in this book.

- The most obvious and most powerful method to attack a Web server is to submit a form to a poorly written script on the Web server and include a command line within the form data. Multiple commands can be used in Linux by separating each with a semicolon. If an attacker adds a semicolon and a command to data that is submitted by form, the script does not check the data carefully before acting on it, the added-on command might be executed by the script as an afterthought. Any system command could be executed in this way. Fortunately, if the Web server is running as "nobody" as described in Chapters 11 and 12, the danger from this type of attack is minimal.
