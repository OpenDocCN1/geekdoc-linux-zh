## DEFINING THE API

The Netscape API (which is called the "server plug-in API") is a set of functions and header files that help you create functions with the directives in server configuration files. The NetscapeTrack server uses this API to create the functions for the directives used in magnus.conf (the server configuration file) and obj.conf (the object configuration file). These built-in functions are described in Appendix B of the FastTrack Administrator's Guide.

To write a new plug-in function for the FastTrack server, follow these steps:

- 1. Learn about the process the server uses to handle browser requests (see Chapter 4 in the Programmer's Guide).
2. Write the code for your plug-in functions. Each function applies to a specific directive in the configuration files.
3. Compile your code into a shared object file (.so file).
4. Include your shared object filename in the Init directives of the obj.conf configuration file.
5. Specify the directives and values that apply to your functions somewhere in the server configuration file (obj.conf).

## WRITING FUNCTIONS

The easiest to start writing a new function is to use the sample code in the /nsapi subdirectory (under /opt/fasttrack after you've installed FastTrack on OpenLinux). Exploring the sample code, the header files, and a makefile will you understand how to start your own project.

The following subdirectories are included for you to review and use as you create your functions:

- nsapi/examples/ : contains example C files for each function class you create
- nsapi/include/ : contains all the header files you include when writing your functions
- nsapi/include/base : contains header files for low-level, platform-independent functions such as file, memory, and network access
- nsapi/include/frame : contains header files for functions like server and HTTP-specific things, accessing the configuration files, and defining interaction with HTTP actions

## COMPILING AND LINKING YOUR FUNCTIONS

Once you've written your function using the NSAPI calls, you can use the standard gnu c compiler in Linux (called gcc) to compile your code. A sample makefile is included in the /nsapi/examples directory.

Many options are available to link your new function as a shared object so the FastTrack server can use it. These are described in the Programmer's Guide. Once you've created the shared object, you add commands to the magnus.conf configuration file.

## LOADING YOUR SHARED OBJECT

Once you've compiled and linked your function as a shared object, you have to add an instruction to load that object as part of the FastTrack server. That way, all the functions you created as part of the shared object will be available for use as directives in the obj.conf or magnus.conf configuration files.

![](img/e01f1106dd2902613fa07890c8baa7e6_445_0.png)

When you start to use the functions, always use the directive in the configuration file that correctly corresponds to the class of the function.

Each time the FastTrack server starts up, it reads configuration information from the obj.conf file. You can add your new module by adding the following line to the obj.conf file (enter it on a single line):

```
Init fn= load-modules shlib=myobject.so
funcs=function_a.function_b....function_z
```

Using this command causes the FastTrack server to open the named shared object file as part of its initialization process. (Be sure to include the full path to the shared object file if it's not in the server root directory.) Each of the functions (function_a, function_b, and so forth) is then available to use with directives in the obj.conf file or in the magnus.conf file.

## USING PLUG-IN FUNCTIONS

Once the functions are loaded as part of the FastTrack server (which you took care of the command added to the obj.conf file above), then you have to specify how the functions will be used as your server running.

Each function is specified with a directive that matches the class of function you created. Following the directive name, you add a function name with values that are passed to it. The format is like this:

```
Directive fn=function_name [parameter1=value1]
<Body>...[name=valueN]
```

You can include any number of parameter-value pairs, according to what the function requires.

Here is one example of a new function created using the AddLog class. This function is named new_log_tool and has two parameters: the first indicates a filename where the custom log information is stored; the second provides a value indicating how much information should be logged.

```
AddLog fn=new_log_tool name=log_special type=maxinfo
```

If you created several plug-in functions that were stored in the same shared object, they can all be loaded with a single command line at the beginning of the obj.conf file, but each function must have a separate line with a corresponding directive in order to activate its use in the server.

In this chapter, you've learned how Web server APIs can be used to add fast and unique functionality to your Web server, giving you and your visitors additional reasons to use the Web.

In this chapter you learned:

- An API is a set of functions that lets you access the core functionality of your Web server. Both Apache and Netscape FastTrack servers have APIs you can use to extend Web server functionality.
- Key areas like authentication, logging, response style, data-type handling, and others can all be defined by a module you create using a Web server API.
- The Apache API includes many modules and sample code fragments to help you create your own server modules.

Modules for Apache or Netscape Fastrack are configured by adding information to the standard configuration files.
