# #BINDADDRESS

The BindAddress directive tells the Web server which IP address or domain name to listen to, and is used as follows:

```
#BindAddress *
```

The BindAddress directive is not used in the default configuration, hence the initial"#" to indicate a comment line.

![](bbox=[0.056, 0.226, 0.158, 0.293])

The BindAddress directive allows you to have one physical computer acting as a Web server for numerous domain names, such as abc.com, nbc.com, and cbs.com, all on one computer.

If you use multiple domain names on one system, the ServerRoot and DocumentRoot directives define where files are stored for each domain name. The value of the BindAddress directive determines which domain or which IP address a Web server requests for.

The BindAddress directive is commented out in the default httpd.conf because it's assumed that you'll be serving one IP address and one domain name with your computer.

![](bbox=[0.056, 0.573, 0.158, 0.64])

One computer can service multiple domain names or IP addresses simply by the way the routing and the Domain Name Server are set up. Several IP addresses can refer to the same physical computer, and several domain names can all refer to the same IP address. This provides you with a lot of flexibility when setting up your Web server.

# ERRORLOG

The ErrorLog directive defines the location where the error log file is stored, as follows:

```
ErrorLog /var/log/httpd/apache/error.log
```

The error log is assumed to be stored in a sub True of the directory given as the ServerRoot. To change that, start the value of this directive with a slash (/) in the default example just shown. If you check the inode (use ls -li) in both the /etc/httpd/apache/logs and /var/log/httpd/apache/, you'll see that the files are linked to the same inode — they are aliases to the same file. This maintains compatibility
