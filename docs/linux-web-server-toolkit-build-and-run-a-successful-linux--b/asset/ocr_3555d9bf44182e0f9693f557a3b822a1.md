You should remember, however, that while increases in bandwidth should be much cheaper for a server colocated at your ISP, physical access to the server is usually less flexible, and you have to rely to some extent on the ISP for the security parameters that your server uses. Table 7-2 compares the benefits and drawbacks of colocated and onsite Web servers.

# TABLE 7-2 Colocated Versus On-Site Web Servers

| Attribute | Colocated Web Server | A Web Server at Your Office |
| --- | --- | --- |
| Control | About the same amount of control; you can configure and update your hardware as you choose. Physical access to the server may be limited. Some security issues will require a strong relationship with your ISP; the ISP usually determines security procedures. | About the same amount of control; you can configure and update your hardware as you choose. |
| Flexibility | Same amount of flexibility. You can do anything you choose with scripts and server add-ons. | Same amount of flexibility. You can do anything you choose with scripts and server add-ons. |
| Maintenance | Same amount of maintenance; you must maintain Web pages and all system information. Some unfamiliar tasks may be harder to complete remotely, but you may also be able to draw on ISP technical support. | Same amount of maintenance; you maintain Web pages and all system information. |
| Scalability | Easier to scale because you have complete control of your hardware and complete access to the ISP bandwidth. | Small increases are very inexpensive (just the cost of memory/hard disk) and don't add to administrative overhead. Greater increases demand expensive bandwidth increases. |
