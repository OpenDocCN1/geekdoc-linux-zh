## Using the Order Directive

The order directive gives you a lot of flexibility in determining site security, especially because you can use it in local access control files (.htaccess is the default, as described previously). This means you can set specific access for a particular subdirectory within your document tree.

The allow and deny directives (allow is only used in the default setting) let you determine exactly who can access your document tree or a subdirectory of it. Both allow and deny can use the word "all" or an IP address or a domain name. For example, if you wanted to restrict access to only your own domain name, you could use the following lines:

```
order deny, allow
deny from all
allow from *.fishing.com
```

Or, if you've had a problem with students from a local university trying to hack into your system, you can use the following lines to let everyone but them access your documents:

```
order allow,deny
allow from all
deny from *.michigan.
```

If you prefer, you can use IP addresses instead of domain names.
You can even set a special order option called mutual-failure. For example, if you had the following directives directives:

```
order mutual-failure
allow from *.fishing.com
deny from gateway.fishing.com
```

then a browser wishing to gain access would have to be part of *.fishing.com and also not be gateway.fishing.com. If either test fails, the user is denied access.
Using the order directive provides a good complement to the user-based authentication for areas of your site that you are testing or to pass relatively private information between small groups via the Web.

## Using the Limit Container

Another use of the order directive (with allow and deny) is within a <Limit> container. A <Limit> container is similar to a directory container, but instead of defining access limits for a directory, it defines access limits for functionality.

All Web transfers fall into two types: GET and POST. Each is a command within the HTTP protocol. GET is used to retrieve documents from a Web server. POST is used to send data back to a Web server. Other commands in HTTP, so as DELETE and PUT, are not really used. The <Limit> container lets you limit who can GET or POST to certain areas within your site.

The <Limit> container is placed within a <Directory> container, so it applies to the directory named in that container heading. It uses the order, allow, and deny directives to set what can retrieve documents or post form data. For example, if you had a special area that used forms for business partners, you could set a restriction so that only users from your partners could use the form to send data back to your Web server. The directory where the HTML form was contained would also contain an .htaccess file with a section like the following:

```
<Limit POST>
order deny, allow
deny from all
allow from *.partner1.com, *.partner2.com, *.partner3.com
<Limit>
```

Within the <Limit> container, you can also include a require directive that indicates which users or groups can use the GET or POST commands.
