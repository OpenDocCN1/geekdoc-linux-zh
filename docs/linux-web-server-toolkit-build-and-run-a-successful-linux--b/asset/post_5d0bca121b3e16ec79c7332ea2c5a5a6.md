Once you have a tar file on your hard disk or a backup deivvice, you can examine the tar file in many ways. The easiest way is to look at a list of what the tar file contains, including the directory that each file goes in. This can help you see which files are part of each archive file and how the filesystem is organized. The following example demos the list of files to another file (a large archive will have a large file list); the list of files, list.txt, can be loaded into a text editor for review:

```bash
tar tvf website.tar >list.txt
```

Other options let you list the size of each file within the archive as part of the listing of files, restore one from the tar file, or restore the entire tar file. This is called extracting the files from the tar file. Many other options are also available.

# COMMERCIAL BACKUP UTILITIES

Several powerful and commercial backup utilities are available for Linux. You can learn more about these from places such as the Caldera online Linux Products catalog (see http://www.caldera.com/ivpo.html) and the Linux Commercial HOWTO (see http://www.caldera.com/LDP/HOWTO/Commercial-HOWTO.html). One of the best-known of these commercial utilities is BRU (Backup and Restore Utility).

These commercial utilities usually add ease-of-use features to the standard backup techniques of the tar command. For example, you could write your own scripts to define when the tar command archives your system, with separate script lines for each subdirectory to archive and complex cron commands to set the time when the script executes.

If you use a commercial package, you can generally select directories to backup, method of backup, and time to perform backups from easy to use graphical menus or using comprehensive command line utilities that remove the complexities of the UNIX commands.

# Chapter 20: Backups and Disaster Recovery

Restoring files from after a system failure is where a commercial solution can be even more useful. By helping you label backup media in an organized fashion, keeping separate records of what each archive contains, and adding tracking information into the archive files, a commercial backup product can take the guesswork out of restoring one file or a complete system from your archives.

# REMOTE BACKUPS

Both the tar and most commercial backup utilities allow you to back up your Linux system either to a local backup device such as a tape drive connected to your server, or to devices attached to a remote system. Backups to devices on a remote system can have several advantages and are as easy to use as local backups because the remote access capabilities of Linux are so powerful. Remote backups eliminate the need for an additional tape drive or other archive device. Remote backups also provide additional security by storing data at a location separate from your server.

For example, you can remotely access a tape drive or writable CD-ROM drive at another location to save your Web archives. If fire damaged your Web server, the archives at the remote site would remain safe. To learn more about remote access, review the manual page for the mount command or the manual for your commercial backup software.

# Tracking Updates of the Linux Kernel

The simple truth is, you probably don't need to track updates made to the Linux unless you're very interested in software development with Linux. The kernel changes daily or weekly, and it can be a full-time hobby just to keep up with it.
The other reasons for tracking the kernel revolve around any needs you may have for hardware support or, in some cases, software features that are not yet included in Linux but are planned for release season. For example, if you have a network card or Ethernet card that isn't supported in Linux but you've heard on the newsgroup grapevine that is coming soon, you might follow the Linux kernel updates to see when hardware support is added so you can upgrade your system.

Other than that, most users won't need to update their Linux kernel more than once or twice per year at most, although you might reconfigure the kernel to meet some new needs that aren't enabled in your current running system. See the next section for information on doing this.

If you want to be heavily involved in the Linux kernel development, you can subscribe to the kernel mailing list and receive numerous e-mails each week hundreds during some weeks – regarding the development of new features, reports, release information. This is the mailing list for Linus Torvalds uses for the core Linux kernel development, but it isn't intended for anyone but Linux developers. You can get more information by sending e-mail to majordomo@vger.rutgers.edu.

If you subscribe to the e-mail list at majordomo@vger.rutgers.edu, you will receive notification of each new update. You can also check the newsgroup comp.linux.announce, where newly released kernels are often announced and which includes the FTP site where you can download. In fact the newsgroup is a great place to hang out and keep up on all the latest in Linux. This newsgroup is only for announcements of new projects, user group meetings, or completed (shipping or downloadable) software that you can immediately get.

# Remaking the Linux Kernel

The process of installing a new kernel is really not too hard. There are two instances when you would want to update the kernel on your system. Either you've just downloaded the latest version from the Internet and create a new kernel from what you downloaded, or you've discovered some feature in your current kernel that requires remaking the kernel to alter it that the feature is enabled. You'll quickly see in the documentation for a feature if a kernel change is required; for example, the README file that comes with a new kernel module may describe certain kernel options that must be enabled for the module to work correctly.

# Using the make Utility

When you compile a program (create binary code from source code), you are usually working with many different components. These include source code that you or someone else has written, libraries of standard functions, pieces of code with existing parts of the program, and other files.

A special file contains all the instructions for putting these components together to make the finished binary program. The file has instructions to “make” the program from the components. The file is used by a utility called a make utility.

There are several reasons why the make utility is used. One is that different components of your program are created at different times. The make utility checks the dates on each component. If a component depends on something that needs to be recompiled, the make utility will organize that action. If the dependent component hasn't changed, you save a lot of time by not recompiling it, and the make utility identifies unchanged components. The make utility also allows the components of a program to be placed in the correct location in your Linux filesystem.
