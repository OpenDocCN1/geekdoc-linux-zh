Between these two lines you can use most of the directives that we've described already. But they apply to Web traffic for only the new hostname defined in the VirtualHost container. For example, you include a DocumentRoot directive that defines a directory where all the documents for the new hostname are stored. You can also have ErrorLog and TransferLog directives to store records about this host in a different set of files from the main logs. The following sample is taken from the httpd.conf file:

```
<VirtualHost host.foo.com>
ServerAdmin webmaster@host.foo.com
DocumentRoot /www/docs/host.foo.com
ServerName host.foo.com
ErrorLog logs/host.foo.com-error_log
TransferLog logs/host.foo.com-access_log
</VirtualHost>
```

Each domain for which you make documents available should have a separa-rate collection of server information recorded, as logs and documents. In order to facilitate this, you should include at least the directives in the previous example for each virtual host for which you serve documents.

You can have any number of VirtualHost containers and therefore serve Web pages for any number of sites using a single Apache server. The only limitation is how large a hard disk you have for the pages and how large a Web server you can handle.

Though most directives can be included in VirtualHost containers, some directives are related to the overall operation of the Web server and should not be included in a VirtualHost container. These include MinSpareServer and related directives, UserId, PidFile, and ServerRoot.
