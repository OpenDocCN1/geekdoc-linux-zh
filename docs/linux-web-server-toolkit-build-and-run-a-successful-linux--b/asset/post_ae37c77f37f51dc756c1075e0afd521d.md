
# Java on Linux

Java tools are available on Linux. In fact, the complete Java Development Kit from Sun, the creator of Java, is included in the /contrib directory of this book's CD-ROM.

There aren't yet many products on Linux that can run Java applications. When it comes to Netscape products, FastTrack Server (see Chapter 12) can run Java applications on the Web server (these are called server applets). The Netscape Navigator browser can run Java applications on a client (these are called client applets), or run JavaScript included in HTML pages that it downloads.

Other Java development tools for Linux and systems for running Java applications on Linux platforms are in the works and may be available by the time you read this.

# Objects and Properties

JavaScript uses many of the ideas of object-oriented programming. If these ideas are not familiar to you, they may seem strange, but after a little practice, they'll be very useful as you program in JavaScript.

JavaScript uses objects to hold data that your script uses. A single object can contain many properties, each containing a piece of data relative to the object. For example, if your Web site contains information about medical procedures, you might create an object for each procedure. The properties of the object could be items such as the name of the procedure, the insurance code, the cost, and the doctor associated with the procedure.

You have to separate the idea of a type of object (for example, "medical procedure") from an actual object (for example, "appendectomy"). An actual object is called an instance of the object definition. In JavaScript, you use the new command to create a new instance of an object. This is the actual object that can contain data for you to use. A sample line of JavaScript code to create a new variable and assign it initial values might look like the following:

```
todays_procedure = new CreateProcedure( appendectomy , 563779 ,
4290 , Devries );
```

When you refer to properties of an object in your JavaScript code, you use a period after the object name. As with objects, you have to separate the idea of the property from the value contained in that property. For example, the following line of JavaScript code prints one of the medical procedure procedures:

```
document.write( Procedure: + todays_procedure.procedure_name + <BR> );
```

A property of an object can also be another object. For example, the doctor in the medical procedure example could be a Doctor instead of just a doctor's name. The Doctor object that you define might include properties as name, hospital, and phone number. You could refer to one of these properties like the following:

```
document.write( Doctor: + todays_procedure.doctor.name + <BR> );
```

# Functions and Methods

One of the best ideas of object-oriented programming is that objects hold everything that pertains to a set of information, including the code that operates on that data. In this end, JavaScript lets you create a function that defines how properties of an unnamed object are acted upon, meaning added together, printed, stored, or whatever the action may be. You can then call the function as part of a specific object. When you do this, the action is called a method, because it applies to specific data. Here's a simple example. You can create a small function that prints any line of text it's handed. It might look like the following:

```
function PrintLine(string) {
document.write(string + <P> );
}
```

Now you can incorporate that function into an existing object type. When you've done that, whenever you refer to the PrintLine method of that object, the text that you pass from that object will be printed by the function. You don't have to rewrite the function for each object that needs this functionality. Note that the document object in the previous example is a predefined object that lets you send information to the browser window. One of the predefined methods of the document object is write, which sends a string to the browser. Other properties and commands of the document object let you interact with others with the browser window.

# Using Java

As described above, Java is the language that inspired JavaScript, and it's still about the biggest technology item around. Because the Java Development Kit (JDK) is included on this book's CD-ROM, you can immediately begin to develop Java applications.

Of course, you'll want to get a browser or server that can execute the Java application before you get too far along. The JDK compiles the source code you write into a special sort of byte-code that the Java-capable browser or server can understand.

All of the Netscape Navigator browsers for OpenLinux, as well as the Netscape FastTrack server for OpenLinux, understand Java applets. Client applets run on a user's browser as part of a Web page that he has downloaded. Server applets run on your Web server when invoked by a script on the server (usually as part of a response to form).

# Applications and Applets

An important distinction when using Java is between a Java application and a Java applet. If you write a Java application, it can run as a stand-alone application, just like your word processor. But it must have a Java Virtual Machine (JVM) to run it. For example, if you have a Sun Solaris system with a Java Virtual Machine installed, any Java application written on any platform will run on the Solaris system. This is the power of the cross-platform design on Java. (If you're familiar with programming terms, a Java application has a main() function and must initialize its entire environment).

Applets, on the other hand, are not complete applications. They are written to run within an executing application. Once they are loaded, they actually become part of that other application and are subject to certain limitations imposed by it. Hence, server applets and client applets become part of the browser after they are downloaded as part of a Web page.

Server applets are used primarily to distribute server-side functionality Webmasters want to use, as Perl scripts are distributed with various features that they have created for their Web sites. But because Java is compiled into byte-code, commercial applications can be developed in Java without having source code available. Because these commercial applications can run on any Java-capable Web server, the market for them is large and they only have to be developed once, rather than ported to each platform.

# Object-Oriented Languages

Java is an object-oriented language like Smalltalk or C++, but it isn't purely object oriented, because some of its data types are implemented outside of objects. Still, the more you are familiar with object-oriented programming, the easier you'll have starting to work with Java.

Java used the same object-oriented constructs described above for JavaScript: classes, objects, methods, inheritance, subclassing, and so forth.

# Installing the JDK

Installing the JDK from the book's CD-ROM is easy. Just use the rpm utility as follows:

- 1. Mount your CD-ROM using a command like this one:
   mount /mnt/cdrom
2. Change to the contrib directory where the JDK is located:
   cd /mnt/cdrom/contrib
3. Use the rpm command to install the JDK:
   rpm -i JDK_static-1.0.2.pl2-1386.rpm

# Summary

In this chapter you've learned about the popular technologies of Java and JavaScript, and how you can use them on your Web server to add functionality to visitors to your site. You've learned the difference between the two and when to use each one.

In this chapter you've learned the following:

- Java is a compiled language. Binaries created from Java require a special environment to run. That is cross-platform, which means that the same Java application can run on any system with Java support.
- JavaScript is an interpreted language that is similar to Java but simpler. JavaScript programs are included as part of an HTML page and are executed by a Netscape browser when an HTML page containing JavaScript is downloaded.
- Both Java and JavaScript are object-oriented languages. Java can be used to create stand-alone applications or applets that run within another environment such as a browser or Web server.
