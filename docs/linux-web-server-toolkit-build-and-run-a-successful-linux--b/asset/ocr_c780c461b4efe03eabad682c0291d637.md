# SEND BACK APPROPRIATE HEADERS

To enable your server to return a Web page back to the browser that sent in data to the script, the script can simply write to Standard Output as if writing to the screen.

The first thing that any script must send back to the browser is the headers that tell the browser what type of information the script will be sending. A single line indicating HTML content is enough. The Web server adds some other lines before sending data back to the browser.

After the header lines, a blank line indicates that the real data stream is about to start. The header section often contains the first part of the HTML text as well, or in a subroutine that leaves the body of the HTML text to be sent by the body of the script. The following sample script fragment sends a standard header and the first part of an HTML document:

```
print <<EOF;
Content-type: text/html

<html>
<head>
<title>Caldera, Inc. Product Order Form</title>
</head>
<body>
<h1>Caldera, Inc. Product Order Form</h1>
<form method=post action=https://www.caldera.com/cgi-bin/order_pl >

EOF
```

Note the use of the <<ALL_DONE command in Perl. It causes everything on the following lines to be printed until a line starts with ALL_DONE (you can choose your ending marker; I've used EOF in this example). This lets you easily place a large block of HTML text in a script without using the print command and quotation marks around each line. Note that you can use Perl variables in the text well.

After your script processes the data sent by the browser, it must return an HTML document as a response for the browser to display. This is discussed in the next section.
