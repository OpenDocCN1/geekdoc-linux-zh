## The Administration Server

FastTrack uses Netscape Navigator (or another browser) to administer the server. To do administration tasks, you enter the URL of your Web server but with a different port number. You can choose any port number you want as the administration port. The administration server will communicate with the browser through that port.

![](img/e01f1106dd2902613fa07890c8baa7e6_183_0.png)

Standard Web servers operate on port 80.

Using a separate administration server provides several benefits to you as you work with a FastTrack Web server. First, you can administer the Web server from anywhere in the world, as as long as you know the administration port and password.

Second, having a separate administration server provides some added security. A hacker must know the administration port, username, and password before he can cause problems with your Web server. In contrast, everyone knows how to contact your Web server itself: they just use the address you publish.

Third, a separate administration server helps to separate the load on the Web server. The Web server can interact with the administration server separately from standard browser requests.

Fourth, you can administer multiple FastTrack Servers on multiple machines via a single interface on your administration server machine. The administration server communicates with all the FastTrack programs in the background for you.

Of course, the nicest thing how FastTrack is administered is that it's easy. You never have to edit a text file containing different sections and options. You just go to a different page of the browser interface and click buttons.

### Configuring the Administration Server

Once you have installed FastTrack, you need to configure it before using it. Because the configuration utility installs right into the browser as its final step, it's helpful to start the config utility from within a graphical window. If you don't know how to do this, instructions are provided at the end of this section.

When you're ready to complete the configuration, you can start the configuration by changing to the FastTrack directory as follows:

```
cd /opt/fasttrack
```

Then run the configuration utility with the following command:

```
./config
```

![](img/e01f1106dd2902613fa07890c8baa7e6_184_0.png)

The following screen appears:

Netscape Communications Corporation Netscape FastTrack Server QuickStart Installation

This program allows you to configure and install a new server. Configuration for the server will be done through a forms-capable network navigator.

To start configuration, you must enter your machine's full name. A full name is of type <hostname>.<domainname> such as foobar.widgets.com

To accept the default shown in brackets, press return: Full name [www.tommy.com]:

If you configured your networking correctly as described in Chapter 5, correct, fully qualified hostname is shown in brackets, and you can just press Enter to accept the default hostname and continue with the configuration of the administration server. Your hostname may not start with www as in the previous example. You can easily configure the server name to point to any machine name you choose when www is used. For example, if you had a machine named pisa.tommy.com, you can make the name actually go to pisa.tommy.com by configuring the DNS name server. (This is described in further detail in Chapter 7.)

## THE ADMINISTRATION PORT

After you press Enter, another screen appears where you select the port that will be used by the administration server to administer your FastTrack server, as follows.

Administration port [45676]:

This port can be any port over 1024. The configuration utility chooses a port automatically, which you can keep if you prefer by pressing Enter. But you have to remember the port, whatever it is. If you have several administration servers in your organization (this isn't technically necessary, but may be preferred politically), then you could have all administration servers use the same port to aid in overall system administration.

Press Enter to accept the default port chosen for you, or enter a different port that you've selected and press Enter.

You'll collect the administration server (and therefore do all the administration for your FastTrack Server) by entering a URL that includes the port you select. For example, if you choose the port 7070, and your standard Web server is reached by the:

```
http://www.tommy.com
```

Then your administration server would be reached by entering the following URL:

```
http://www.tommy.com:7070
```

Keep in mind that you can administer several FastTrack Servers running on several different computers all from the same administration server.

## NAMES AND PASSWORDS

Next, you select the user that the administration server will run as. That is, the administration server program will run with the permissions to access files and directories as if it run by the user you enter in the:

Run administration server as [root]:

Press Enter to accept the default in brackets, or enter another Linux username on your system.

Your FastTrack Web servers (called Public Services in the configuration utility) will usually run as nobody for security reasons, so that scripts on the Web server cannot inadvertently access areas that Web browsers shouldn't.

The administration server has many safeguards. You can have the administration server run as root if you like, so that you can completely control the FastTrack Server from the Web browser administration screens. All the configuration files created with this utility will be written to this user as their owner.

### WHO CAN ACCESS THE ADMINISTRATION SERVER?

Even if someone knows the username and password to reach the administration server, if the host that the person is working from is not on the "approved" list, the administration server will refuse the connection.

The final information you will be requested to enter is the hostnames and IP addresses for all machines that should be allowed to access the administration server, as follows:

Hosts [NONE]:

Note the default, NONE. You'll want to change that – otherwise no one can use the administration server. Separate multiple entries with commas, as follows:

Hosts [NONE]: *.abc.org, *.cs.mit.edu, special.partner

Wildcard patterns are very useful, here as *.abc.org in the previous example. Although you might think it's very useful to be able to access the administration server from anywhere (such as you're on vacation and log in your AOL account), I strongly discourage from adding anything like *.aol.com. Doing so would mean anyone who discovered your administration password could completely control your Web server from an AOL account.

Next, enter matching IP addresses for the host machines that can use the administration server, as follows:

IP addresses [list]:

This list is similar to the Hosts (the domain names you just entered), but if a browser tries to access the administration server, and the hostname matches the list of acceptable hostnames but the IP address doesn't match this list of acceptable IP addresses, access will still be refused.

Having this list of IP addresses prevents someone from assuming that you allow access from *.abc.org. They won't alter their packet secures to look as though they are from that domain, when actually they are from *.hacker.org. The administration server will look up both the domain name and the IP address of the incoming browser to see if it is allowed access. A hacker can still spoof an IP address, but this can be filtered out by your firewall.
