## Backing Up Your Web Server

If your computer is used only as a Web server, performing backups is a lot easier than backing up a regular Linux server. This is because most of the data that changes on your Web server is contained in a single subdirectory: /home/httpd/html.

Of course, that oversimplifies the layout of many more diverse Web servers, but you can still see that backing up your Web server doesn't need to be complicated.

# DECIDING WHAT TO BACK UP

If you have a relatively static Web server, you might feel comfortable backing up the system every week or two. If your Web server adds new information every day, you would be better served by a backup every night. Otherwise you risk losing a great deal of time and effort in reconstructing everything that has been done on your site between the time you made the last backup and when the crash occurred.

Similarly, you can decide which areas of your system need to be backed up. If your system is used only as a Web server, this can guide your decision.

You should always have a complete backup of your system so that you have a copy of all the configuration files that you prepared when you installed the system. If you back up only the data on the Web site, you could still save yourself a lot of work if you have to reconfigure all the system information for the X Windows System, the network server, and so forth.

# BACKING UP PART OF YOUR SERVER

You may not need to back up the entire system very often, because the configuration information usually doesn't change very often. You probably want to focus more attention on the data portions of your Web site. Determining where these areas depends on how you've set up your Web server.

For example, the most basic Web servers will have documents in the /home/httpd/html directory only. But if you have any scripts that are used to process forms on your Web site, you would probably be located in /home/httpd/cgi-bin. If you have other services on your Web site such as a database gateway or users' Web pages, you might need to back up other areas. Don't forget any directories that you've linked to your Web area with aliases or symbolic links.

# FULL OR INCREMENTAL BACKUPS

In addition to the various areas of your server that you can decide to back up, you should also decide which backup method to use. The two easiest to use are a full backup and an incremental backup. Both of these are available using any of the utilities described in the next section.

A full backup stores all the files on your system or from the subdirectories that you indicate. This takes the most time and the most media space of any backup method, but provides the most secure backup because it contains all of the files from your system. If you have a full backup, you can completely restore your system.

An incremental backup stores all of the files that have changed since you last backed your system. For example, if you keep a regular backup schedule of every Sunday morning, which is usually a slow time on the Web, your script or configuration file can indicate that every file with a "last modified" date after the previous Sunday will be backed up. Thus only those files that are newly created or modified are stored during this Sunday's backup session. This takes less time and uses less space on the storage media.

# Utilities to Back Up Your Server

There is a variety of utilities that you can use to perform a back up of your Web server. Some of these are standard UNIX utilities that are included with your OpenLinux system. Others are freely available or commercial tools that you can learn more about the Internet.

# USING THE TAR COMMAND

Once you've decided on which parts of your Web server you want to back up, how often to back them up, and which backup method you want to use, you can immediately begin to perform backups using the tar command.

The tar command is a standard UNIX utility that has been around for decades. In fact, it was designed to be a tool for archiving filesystems onto tape backup devices. The tar command packs an entire directory, with all files, subdirectories, their files, and so forth, into a single file. That file can then be easily moved, copied, or compressed. You can examine any tar file (a file created with the extension .tar) using the tar command to see what files it contains or to extract one or many files from the tar file into their original condition.

The tar command has many options that let you determine how you want your system archived. You can learn about the tar command by using either the help option as:

```
tar help
```

or the UNIX manual page as follows:

```
man tar
```

The simplest way to use the tar command is to include it as parameters of a tar file to create and the directory to archive, as in the following example:

```
tar cWf website.tar /home/httpd/html
```

The example just creates a tar file called website.tar, with verification, from the directory /home/httpd/html and all of its subdirectories.

A file created with tar will not be smaller than the directory tree that it created from. Be certain you have enough space on your hard drive to create the tar file unless you are placing it on the backup device.
