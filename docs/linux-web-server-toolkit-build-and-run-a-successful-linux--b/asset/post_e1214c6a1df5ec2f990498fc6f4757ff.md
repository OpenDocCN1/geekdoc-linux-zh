## Choosing Web Server Features

Once you have your Linux distribution selected and installed (Appendix A explains how to install the included OpenLinux Lite CD-ROM), you can choose your Web server software. To review a little, the Web server is the program that runs on your Linux operating system to accept requests from Web clients (browsers such as Netscape Navigator), process these requests, and return the information over the Internet or an organizational intranet. A Web server is also called an HTTP server or HTTP daemon–a UNIX name for a background program or process. The protocols and terms are defined at length in the next chapter.

As you select a Web server, you should consider the factors mentioned in the paragraphs that follow. Consider which factors are most important to you based on your organizational goals and concerns. You can use Table 3-2 to decide if a Web server other than the included Apache server would best serve your needs, either immediately or as your Site grows and develops.

## Web Server Features

The features outlined in the following paragraphs are those that you should consider as you choose Web server software. Everyone would like to have the best of everything, but compromises are always in order. You give speed for a more stable product, you give up security to get a free Web server, and so forth.

## SPEED

Speed refers to both how quickly the Web server program can respond to a request from a Web client (latency), and the number of requests that can be handled at one time (throughput capacity). Responding quickly to numerous client requests involves many facets, the least of which is how efficient the Web server interacts with other running processes on the Linux machine. A busy Web server may be serving several dozen client requests during the same one-second period. The efficiency of the Web server's algorithms for loading files, checking permissions, running CGI scripts, passing data, and other factors affect how quickly the Web server responds to a request and, consequently, the number of client requests the Web server can handle simultaneously on a given computer before becoming bogged.

Different Web servers have different technical strengths. Though I've said how good free software is, you'll still find that one Web server is not necessarily as fast as another. Some are ported from other platforms with a great deal of optimization for Linux. Others were created as experiments or to focus on features, such as extending the capabilities of HTTP. These servers may not be your best choice if you are concerned about the speed of your server because you have a slower computer or anticipate a heavily loaded Web server.

## STABILITY

You aren't be trying any Web servers that aren't completely stable unless you are experimenting with new versions that implement improvements or new features that you would like to add. The Linux Web servers listed in Table 3-2 are suitable for running your Web server, but the latest, unstable version or the experimental Web servers you may hear of not being suitable for your site. The authors are generally very good about assessing the stability of the software versions they are releasing.

However, I think it's safe to say that if stability of a large site is a concern for you, read the section called "Reputation" later in this chapter before deciding on a Web server.

## FEATURES AND ADMINISTRATION

Features and administration are grouped together because the features that you are most likely to look for are administration features! Web servers are actually very simple programs at their core. They watch for a request and send a file or block of text to a script, which responds to the request. HTTP, the Web transport protocol, is a very stable, simple protocol that has changed little in actual use in the past four years.

Servers tout many additional features relative to HTTP, such as support for additional HTTP verbs like PUT and DELETE, or an API, which is discussed at length in Chapter 17. The most important day-to-day feature for most users is how the server is administered and which items can be administered.

Web administration starts very simply. In many cases, the configuration created by the default installation will suffice. But the number of things that can be altered, checked, or set expands rapidly with new Web servers. And for those new to the Web, the method of access to all configuration options is an important part of the Web server's feature set.

Web servers are basically administered by one of two ways: editing text files that are formatted with specific options and flags, or by special administration Web pages that present the options in an easy-to-use way and edit the files for you in the background.

## CROSS-PLATFORM

If you are working in a diverse computing environment, it may be important to you to have a Web server that is available on several different hardware or operating system platforms. This may reduce the headaches and administrative overhead of administering your multiser server.

Several of the Web servers mentioned in Table 3-2 are available for multiple versions of UNIX. Some are also available for Windows NT or other non-UNIX operating systems.

## REPUTATION

You may want to choose a Web server from a company that you have heard of and with which you feel comfortable, but most Linux servers are not created by companies that you have heard of; most are created as a project by a small group of Web experts, which then makes the server available freely for others to use. The issues of support, upgrades, and so forth are not considered by software authors, except to request bug reports and promote a new beta release when time permits.

If you feel more comfortable with a product from a well-known company, you really have only two choices. If your company is technically savvy about Linux, you can go with Red Linux or Caldera OpenLinux. Both advertise and have names that are well known in the Linux community. If your organization is not involved in the Linux community and doesn't understand much about the development of software, your best is Caldera. Backed by strong advertising and partnerships with software industry heavyweights like Novell, Netscape, and Sun, Caldera can provide the marketing material and official presence to make larger companies comfortable using Linux technology for a Web server.

## SECURITY

The Web being used more every month for commercial transactions. Despite all the bad press about security on the Internet and the lack of commercial standards, people who are familiar with the Web know that there are several ways to make purchases over the Internet.

Though passing a cleartext card number over the Internet may not be a terrible risk, most of us are averse to doing it. Secure Web servers, also called commercial servers, solve that problem by providing a mechanism for security-enabled browsers (and most of the popular ones are) used to send encrypted information back to the Web server. These issues are discussed in detail in later chapters, but if security in processing sales from your Web site is part of your plans, you should use a secure Web server. Unfortunately, all Web servers are commercial; you must pay for a copy of them. This is due to the licensing fees that are part of the secure/private key encryption that these products use.
