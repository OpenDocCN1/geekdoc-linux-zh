# Understanding Web Hits, or Why Statistics Are Useless

Web server statistics have received a lot of bad press over the years because they can be deceptive. In order to use statistics effectively (and fairly), you need to understand what the bad press is about. Remember what Mark Twain said: "There are lies, lies, and statistics."

Every time someone requests an item from your Web server

The trouble is that when you look at your home page and your Web site. Or several people browsing through your site generate 30 hits to generate no record in the access log. How are these things possible?

For the first case, realize that your Web pages almost always include several graphics. In cases, a single page may contain 15 graphics. Each of these graphics will be loaded with a separate request from the browser to your Web server. Admittedly, these are probably quick to load, but each is recorded in the access log as a separate transfer. The user loading your home page counts counts as 16 hits (15 graphics plus the main html file that included the images).

Maybe you looks at two other pages that contain 5 graphics (6 hits per page), then returns to your main page. But when he uses a link on the bottom of your other pages, he has no caching of documents. The first page and all 15 graphics are reloaded. This brief is now recorded as 16+16+6+6+6: 44 hits. Of course, if you would like this to be counted as one low-quality visit.

Let's look at the case 1. Mentioned in the previous paragraph that a user can have a browser that doesn't (cache or save) any files. The opposite is also true. A user can be part of a network with a caching proxy server that caches all documents for several days.

So imagine that someone finds your site, explores it a little, and finds it very interesting. The different pages she visits 240 hits (including all little graphics). She tells some statistics at her office who have similar interests. Sixteen of them also visit your site and explore it at length. But you don't know any of them because the proxy server at their office delivered all the same locally cached documents to all 17 people without making another request of your Web server.

You begin to see the problem.
