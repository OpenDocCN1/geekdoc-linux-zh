Because source to everything is included with the core Linux components and utilities, developers really put their best foot forward. And they are likely to be kind to others' efforts, so that they receive the same treatment!

The logistics of the Linux development community can be a little strange to understand—hard to believe, some might say. The system relies on a community of benevolent maintainers who collect pieces of code (patches, bug fixes, new features) from people on the Internet. Maintain write code, review submissions from others, correct errors in existing programs, and generally collect input from the entire Internet community. At regular intervals, they post a new version with the fixes, revisions, and so on. It works well.

If the maintainer becomes too busy to do this side work (or changes to a job without Internet access), another person among the contributing developers volunteers for the job and starts doing the same thing.

If someone doesn't the direction of the development, he or she can start a new branch of the development with a simple, nonmalicious announcement, rename the project slightly, and gather the developers who are best served by the altered plans to continue its development.

To the troublesome frequent question from press representatives: What if Linux gets hit by a truck? the answer is easy. After a suitable mourning period for the patriarch of Linux, one of the other key developers would be to collect every-one's work, just as Linux does now, and continue posting the latest kernel versions on the Internet. Linux goes forward.

# Linux Distributions

The first popular distribution of Linux was Slackware, which is no longer under development. But there are a dozen or more distributions available that you may have heard of, including OpenLinux, Debian, Red Hat, Craftworks, WorkGroup Solutions, Yggdrasil, and others.
