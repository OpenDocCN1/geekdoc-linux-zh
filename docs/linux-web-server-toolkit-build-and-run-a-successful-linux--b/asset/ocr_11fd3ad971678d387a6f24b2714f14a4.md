# Using the Limit Container

Another use of the order directive (with allow and deny) is within a <Limit> con-
tainer. A <Limit> container is similar to a directory container, but instead of
defining access limits for a directory, it defines access limits for functionality.

All Web transfers fall into two types: GET and POST. Each is a command
within the HTTP protocol. GET is used to retrieve documents from a Web server.
POST is used to send data back to a Web server. Other commands in HTTP,
so as DELETE and PUT, are not really used. The <Limit> container lets you limit
who can GET or POST to certain areas within your site.

The <Limit> container is placed within a <Directory> container, so it applies
to the directory named in that container heading. It uses the order, allow, and deny
directives to set what can retrieve documents or post form data. For example, if you
had a special area that used forms for business partners, you could set a restriction
so that only users from your partners could use the form to send data back to your
Web server. The directory where the HTML form was contained would also contain
an .htacces file with a section like the following:

```
<Limit POST>
order deny, allow
deny from all
allow from *.partner1.com, *.partner2.com, *.partner3.com
<Limit>
```

Within the <Limit> container, you can also include a require directive that indi-
cates which users or groups can use the GET or POST commands.
