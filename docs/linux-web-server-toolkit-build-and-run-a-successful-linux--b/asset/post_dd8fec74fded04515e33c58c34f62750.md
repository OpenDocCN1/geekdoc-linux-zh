But using /etc/inetd.conf is not a foolproof method of protocol firewalling. In addition to this method, you can use the firewall features built into Linux to control which packets are passed on to the operating system for servicing.

# RE-COMPILING THE LINUX KERNEL

To recompile the Linux kernel, you'll need to re-compile (re-make) the Linux kernel, as described in Chapter 21. Select the firewalling options as you configure the kernel, and then follow the online documentation to create the firewall configuration files.

Re-making the Linux kernel is not hard, but creating complex firewall configuration files can be a challenge. That's why several commercial firewall products for Linux are now available. Linux can provide a great firewall, but it takes some expertise to use it. A good reference for commercial firewall products is the Linux Applications and Utilities Page. # USING HOST-BASED FIREWALLING

One benefit of using kernel-level firewalling with the complex configuration files that you can create is that you have a variety of protection features at your disposal.

A frequently used protection feature is host-based firewalling, in which only certain hosts are allowed to access your network. This type of firewall functionality is very similar to what was described for Web server access control in Chapter 11. Here are a few examples of what you can easily set up for your Linux system using the Linux firewall features:

- Deny (ignore) all incoming packets; allow outgoing traffic from this router. (And check the actual origin to prevent IP spoofing).
- Deny all incoming packets from everyone, but then allow them from a short list of trusted hosts.
- Allow all incoming packets from everyone, but then allow them from a few known troublemakers.
- Deny all traffic to the telnet port.
- Deny all incoming traffic to all ports, but then allow all incoming traffic to the Web port (80), and to FTP ports (20 and 21), except certain hosts known to be unwelcome.
- Deny all outgoing packets except for the e-mail (SMTP) ports (internal people can do e-mail but not browse the Web).

The performance hit for all this firewalling in the Linux kernel is minimal. The kernel routing system must nevertheless examine every packet to see what to do with it (pass it or send it to a local servicing program). So adding a few simple rules that may mean discarding the packet altogether doesn't noticeably increase the router's work.

# Using Application-Level Firewalls

Application-level firewalls provide another method of protecting your systems. These firewalls are not part of the Linux kernel, but must be added separately. They may be considered applications themselves.

It could be said that application-level firewalls have more intelligence than protocol firewalls, which actually just have a narrower range of specialized capabilities.

An example of an application-level firewall is a proxy server. The proxy server receives a request for a service, either from an outside client or an internal client. The proxy then determines an action based on the firewall rules that you've set up for the proxy. For example, it might be set up that all internal people on Web browsers who request the CNN Sports page receive the monthly newsletter instead. Or it might allow everyone to use the GET command, but not the POST command, so no one can submit forms from Web pages.

The type of firewall just described examines specifics about the application being used and can decide which features or actions are allowed or refused, either from an internal user or an external user.

Other examples might be firewalls that limit external users of databases to a specific set of commands or firewalls that discarded e-mail messages that totaled more than 2 megabytes.

# Using Firewalls

The best way to use firewalls depends on your individual circumstances, the two types mentioned—packets filtering and application processes—are usually best together. As you watch for security problems and refine your configurations, or even add other firewall tools as needed, your understanding of the types of firewalls and security your system needs will increase.

Using both packet-based and application-based firewalls gives you the fine-grained control of packets and protocols for overall system protection, plus the fine-grained control of applications that might be better at controlling the use of Internet resources within your own organization.

As mentioned earlier, many "black box" firewall products are available that can provide protection for your network. Most of these operate only on the packet and protocol levels, leaving the application-level firewall to a special application running on your system. Many of these black-boxes are actually running Linux, though they don't say so. With adequate configuration, your Linux system (or a separate computer Linux if you have a busy network) can provide all the firewall protection you should ever need.
