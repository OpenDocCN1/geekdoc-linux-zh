## Terminal Emulation and Network Peers

There are many ways to connect to another computer. There's a big distinction in the Internet world between a terminal connection and a peer connection. While terminal connections are fast and easy, peer connections provide the full-featured, graphical remote access that people are usually looking for. This section discusses both types of connections and how each is used.

You've seen how UNIX allows for several login sessions at the same time for multiple users. In fact, if you are sitting at a Linux machine, you can connect multiple times with different user names if you like. To try this, just open several terminal windows in the X Window System (graphics mode) or use the Alt+F6 key combinations to switch to different virtual terminals. You can log in from each virtual terminal using any username on the system, then run programs independently of what you're doing on the other virtual terminals.

For each of these terminal windows or virtual terminals, you are creating an internal session for Linux. Your keystrokes are fed into this session, and from the session output goes to the window where you started the terminal session. All the computation takes place on the same computer.

A remote connection can be the same as a virtual terminal. Using a dumb terminal or a modem at a location far from your Linux computer, you can log in to your Linux machine as you were seated at the computer keyboard of the Linux machine. All your keystrokes are sent to the Linux computer, and all the output is returned over the modem connection to the place where you initiated the connection.

But here's the catch. The Linux computer can't really access the computer that the modem is on; it knows only the keystrokes that it's receiving. So you use FTP or a Web browser to transfer files to the remote computer. The remote computer with the modem has the capacity to act independently, but in case, it is "emulating" or acting like a dumb terminal to the Linux computer, just sending keystrokes and receiving characters to display, without any interaction of the other parts of the remote computer such as the hard disk. What I've just described is called terminal emulation.

Terminal emulation access like the modem just described is often called a shell account, because as it's if you have a command-line shell to the Linux system.

The alternative to this shell account is a peer-to-peer connection. In a peer-to-peer connection, the Linux computer sees another computer as another computer. The remote computer can execute commands that request data from the Linux computer, and they communicate using Internet protocols as if they were on a single network in an office.

This type of connection is needed to use graphical programs on the Internet, to run multiple networked programs at the same time, or to transfer files from the Linux computer to another computer. (Actually, the communications program that provides a terminal connection can use special protocols such as SSH to transfer files, but that doesn't help you reach Internet sites.)

To establish a peer-to-peer connection with the Internet, the Point-to-Point Protocol (PPP) is often used. It allows the IP packets to pass over a regular telephone line as if they were on a Linux. Serial line IP (SLIP) is another protocol that provides a peer-to-peer connection.

## Linux Filesystems, Users, and Programs

In order to use Linux effectively, you should understand a little about how Linux arranges things on the hard disk, how users and groups are created and managed, and how to interact with the command line to control programs that you've started. Because a standard Linux distribution is over 100MB when installed (and the OpenLinux Lite installation includes even more than that), where to find things can be a big help as you start configuring your system.

Linux uses a filesystem standard that is similar to most UNIX systems. However, as described in Chapter 3, each distribution may have a slightly different incarnation of the filesystem arrangement. What I describe here applies to OpenLinux Lite and for the most part, to all other Linux distributions.

To begin, you must know that everything in UNIX is part of the filesystem, or the directory tree. All floppy disk drives, hard disks, and other devices are accessed through a single filesystem. Everything starts at the root of the filesystem, which is indicated by a forward slash (/). (Note that this is the opposite direction to the slash used in DOS and Windows directory paths, and that no drive letter belongs the directory path.) Even hard disks on remote computers can be "mounted" so that they appear as part of your local filesystem via a simple directory path.

From the root of the filesystem, subdirectories store local files, allow access to devices, and provide transparent access to filesystems on networked computers. Table 4-4 lists the major subdirectories from the Linux root.

### TABLE 4–4 Main Linux Directories

| Subdirectory | Contents |
| --- | --- |
| /bin | Executable programs used by the root user. |
| /dev | Access to hardware devices such as printers, hard disks, and so on. Not accessed directly, but referred to when indicating system components. |
| /etc | Configuration files for many system programs, including password and group files. |
| /sbin | Essential system binaries used primarily by the root user. |
| /tmp | Temporary files created by programs. |
| /lib | Library files and shared objects needed by the binaries in /bin and /sbin. |
| /root | Home directory for the root user. |
| /home | Home directories for regular users. |
| /proc | A virtual filesystem providing kernel information and process data. |
| /var | Storage area for files that grow in size, such as logs and mail. |
| /usr | User-specific programs, libraries, and documentation. |

As a multiuser operating system, Linux is set up from the beginning to provide security, networking, and logging for many users. The next section describes user accounts.

## User Accounts and Login

Every user on a Linux system is listed in the file /etc/passwd. This file contains several fields of information about each user, including the user's home directory, encrypted password, and login shell. If you've installed a more secure system than the standard UNIX (such as the shadow password system), /etc/passwd is not used in the same way, but the following commands still apply.

Whenever you log in to Linux, either from a remote computer or from the Linux console, you enter your username and password. The login program compares the entries against /etc/passwd to see if you are granted access. If accepted, your login shell is started (the command-line prompt appears), with the current directory being your home directory.

There are many user accounts on the Linux system that are not used by regular users to log in and work on the system. These user accounts are used by regular programs to complete various tasks. Having separate user accounts provides more security for the things we need to do.

For example, a Web server often runs as nobody, which is a standard user account on Linux. Nobody has very few rights; if someone accessing the Web server were to gain control of the Web server to execute programs, access to the system would be very limited.

There are many security issues surrounding the /etc/passwd file. People can try to decrypt passwords if they have access to this file. They may try to disable accounts or capture users' keystrokes from the log files as they enter their passwords. All these security issues are discussed in later chapters.

If you want to add new users or see what users are on your system, you can do one of the following things:

- Type this command to see the names of home directories for users that actually log in to the Linux system:
  `ls -1 /home`
- Type this command with a new username, then respond when prompted for more information:
  `adduser nickw`
- Start the LISA administration utility:
  `lisa`
- Select System Administration -> System Configuration -> User Administration.
- From the User Administration, you can view all users and groups (see the next section), and complete other user-related system administration tasks.
