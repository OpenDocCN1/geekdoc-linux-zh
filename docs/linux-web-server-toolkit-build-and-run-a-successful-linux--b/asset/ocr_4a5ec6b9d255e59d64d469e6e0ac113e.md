# Linux Web Server Toolkit

Development kernels have odd minor version numbers: 1.3 before the release of 2.0, 2.1 after the release of 2.0. New development kernels are released at a rate of several month. But they can be unstable and may crash. They are intended for developers who are working on the next set of features for Linux.

When several new features are added, debugged, and stable, a new, evennumbered stable kernel appears. This occurs once or twice each year. After a stable kernel is released, updates are only for bug fixes or minor changes. Each of these updates increments the third number of the kernel version. This, OpenLinux 1.1 CD-ROM in this book uses the Linux 2.0.29 kernel. The development kernel moves at a much more rapid pace than the stable kernel. If you use a Linux distribution advertising the "latest" kernel, check whether you're getting the latest stable kernel (which you can run a business on) or the latest development kernel (which may not run at all this week).

# Frequency of Kernel Updates

If the hardware you use is supported by the Linux kernel you get, you may never feel a need to update your Linux system. Many people who create stable, running Linux systems are not interested in endangering what they have created by adding new kernels or system library revisions unless there is a serious problem that needs fixing.

Some Linux distributions (Red Hat, for example) are updated very frequently. Others, such asa OpenLinux, are updated less frequently and focus on building a base for a large number of third-party applications. If you prefer a distribution that has frequent updates, check the company's policy on updates. Do you pay for each one? How frequent are they? Is documentation included? Almost every company selling commercial Linux systems will provide updates when security fixes, major bugs, or package updates are prepared. These are distributed via FTP rather than on CD-ROM.

# Technical Support

If you are not a technical expert on Linux, does the distribution vendor provide any technical support for free? Support incidents or contracts available after the free support? One benefit of all the Linux companies I've seen is that they grew out of groups of technical experts, so when they say they offer support, you can generally count on them to take care of you. Each company has at least a couple of people who can describe for you the source code for the problem you're having, describe how they will alter it, and send you a patch that's what it takes.

# Documentation

As with technical support, if you are not really familiar with Linux, you will do a lot better with a distribution that includes how to set up your hardware, install the Linux system, and do some beginning system administration.
