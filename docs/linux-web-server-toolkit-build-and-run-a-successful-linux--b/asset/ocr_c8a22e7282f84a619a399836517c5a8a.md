Let's walk through a typical request and see how these protocols are used. We'll use a request from a Web browser as an example. Suppose you wanted to access the Web site of a large car manufacturer called ABC Autos. You'd type in the URL http://www.abcautos.com and press Return. The following steps are a simplified version of what happens in order to get the ABC Autos page onto your screen from a LINUX-based system:

+   1. The Web browser uses HTTP as the protocol to be used and requests a connection to www.abcautos.com on the standard HTTP port, 80.
2. Linux receives the request to make a connection to www.abcautos.com, but can't do so without an IP address.
3. Linux looks first in the hosts file to see if www.abcautos.com is defined. It probably isn't, so Linux uses DNS to send a request to the name server (which may be located at the ISP or locally). The request says: What is the IP number of www.abcautos.com?
4. The name server returns the IP address of www.abcautos.com.
5. With the IP number of www.abcautos.com in hand, Linux prepares to make a connection to that computer by using the TCP protocol to initiate a connection.
6. The Linux kernel prepares the TCP packet to send over IP on the Internet.
7. Routers on the Internet use protocols that aren't part of your Linux Web server to get the IP packet to the right destination. (Routing is discussed in Chapter 7.)
