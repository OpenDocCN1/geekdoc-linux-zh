# USING TAR

If you can't find an rpm-formatted file of the software package you want to install, the chances are you've found the package in tar format. As mentioned in earlier chapters, tar is a tape backup and archive format that has been around for years. It places an entire subdirectory into a single file. From that file, you can recreate the subdirectory. But tar doesn't include options such as running script automatically, tracking a description of the software contained in the file, or making a program ready to run in a single step.

Instead, you usually use the tar file to create the subdirectory for the new program, using a command like the following:

```
tar xvf newprogram.tar
```

and then look in the directory it creates for a README file that describes what to do.

If you want to see a list of what the tar file will create when you execute the previous command, you can use a t (test) instead of an x (extract), like the following:

```
tar tvf newprogram.tar
```

Often the tar file will be compressed to save time downloading it. Co compressed tar files have a file extension of .tgz or .tar.Z. You add the z option to the tar command for a compressed tar file, like the following example that extracts a compressed tar file:

```
tar xzvf newprogram.tgz
```

# Upgrading Existing Packages

The rpm system just described also has a wonderful method for updating existing packages. It will even determine the dates on the version that you have and warn you if the version you are trying to upgrade is not a newer version.

If you have an rpm of a program already installed on your Linux system, you can use a single command to upgrade to the newer system, as follows:

```
rpm -U newversion.rpm
```

If you have installed a program using a tar file, you'll have to search through your filesystem to remove old files, or install the newest version of the tar file and hope for the best.
