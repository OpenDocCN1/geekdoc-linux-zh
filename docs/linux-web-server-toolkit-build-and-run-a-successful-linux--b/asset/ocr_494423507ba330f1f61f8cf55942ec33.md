With the httpd.conf file set, you can begin to set up the options for resources on your Web server. These are controlled by the directives in the srm.conf file, which is described in the next section.

# Setting Up Server Resources

The directives in the srm.conf file are used to control the information sent to the user's browser from the Web server, including details such as how directories of files are listed and which language is used for documents. This section reviews each of the default settings and describes the options you can use in this configuration.

The srm.conf file is located in the /etc/httpd/conf directory. You can edit it with any text editor, including vi or the graphical CRISLite editor described in Chapter 6. The most commonly used directives are described in the sections that follow. Information about advanced directives is available in the Apache online help documents.

I'll start by reviewing the meaning of the lines in the default srm.conf file that you review after installing the OpenLinux CD-ROM. Many lines in that file are commented (start with a #), with other values changed the defaults of the Apache installation. I'll explain the commented-out lines as well as the changes to default values that I'd recommend for your Web server.

# Basic Resource Directives

The basic resource directives control how the Web server responds to browser requests, determining how to present data to users and what data can be presented. (Security settings are located in access.conf, however).

A large number of the directives in the srm.conf file are used in the following circumstance: if a browser makes a request to the Web server with a URL that ends in a directory name rather than a filename, what should be sent back to the browser?

A security option allows you to set that to "No file of that name found." But you'll often want to have a nice directory listing of available documents returned. Many of these directives determine what is included in that listing.
