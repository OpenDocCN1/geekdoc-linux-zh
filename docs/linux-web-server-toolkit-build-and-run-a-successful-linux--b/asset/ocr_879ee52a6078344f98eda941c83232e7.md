# Chapter 17: Using Server APIs

You can include any number of parameter-value pairs, according to what the function requires.

Here is one example of a new function created using the AddLog class. This function is named new_log_tool and has two parameters: the first indicates a filename where the custom log information is stored; the second provides a value indicating how much information should be logged.

```
AddLog fn=new_log_tool name=log_special type=maxinfo
```

If you created several plug-in functions that were stored in the same shared object, they can all be loaded with a single command line at the beginning of the obj.conf file, but each function must have a separate line with a corresponding directive in order to activate its use in the server.

# Summary

In this chapter, you've learned how Web server APIs can be used to add fast and unique functionality to your Web server, giving you and your visitors additional reasons to use the Web.

In this chapter you learned:

+   * An API is a set of functions that lets you access the core functionality of your Web server. Both Apache and Netscape FastTrack servers have APIs you can use to extend Web server functionality.

+   * Key areas like authentication, logging, response style, data-type handling, and others can all be defined by a module you create using a Web server API.

+   * The Apache API includes many modules and sample code fragments to help you create your own server modules.

Modules for Apache or Netscape Fastrack are configured by adding information to the standard configuration files. In the next chapter, you'll learn more about the security issues associated with using your Web server, and how to include security checks and firewall capabilities in your Linux Web server.
