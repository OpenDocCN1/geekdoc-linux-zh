## SELECTION MENUS

Selection menus, or drop-down selection lists, allow you to provide a user with a list of options to select from. Selection menus differ from other form tags such as radio buttons in two ways. First, the label for a selection menu – the text after each `<OPTION>` tag – is onscreen within the frame. For all other form tags, nothing within the tag is displayed on screen.

Second, selection menus allow users to select more than one item from the list. Selection menus provide several display options that let you control which item is displayed by default and how many items are displayed at once. For example, a selection menu with a height of one item (SIZE= 1 as in Figure 10-7) will appear as a drop-down list. If you define a selection menu with a height of three items (SIZE= 3 as in Figure 10-8), it will appear as a larger box in the browser window with a scroll bar on its right edge. It's important that you test the interface that you create to make certain it's usable. For example, a multiple-selection scrolling list that is only one or two items is difficult to use.

Selection menus begins with a `<SELECT ...>` tag that includes the NAME of the form element, the SIZE (height in items) for the list, and the MULTIPLE option if multiple selections are to be allowed.

Between the opening `<SELECT ...>` tag and the closing `</SELECT>` tag, the `<OPTION>` tag is used. The `<OPTION>` tag is used like the `<li>` tag for HTML lists, simply separating items in the selection list. The only parameter that can be added to the `<OPTION>` is SELECTED, which can be included on one or many items to make them preset. The first option in the next list using the SELECTED parameter, as shown in Figure 10-7.

A sample selection list appears in the following; this example uses a single selection in a drop-down menu format that could replace a set of radio buttons in your:

```
<SELECT NAME= SIZE= 1>
<OPTION SELECTED>UPS Ground
<OPTION>UPS Second Day
<OPTION>Federal Express
</SELECT>
```

## TEXT AREAS

Although you use the <INPUT> tag with a TYPE=TEXT to let a user enter a line of text, this tag always displays a single-input field. In many instances, you will want the user to enter a longer block of text, such as a comment or description. The <textarea> tag allows you to do this, specifying the size of the text box that will appear in the browser.

The <textarea> tag is also different from other form tags because it has a closing tag. The options for the interface element are in the <textarea> opening tag, but all the text between the opening tag and the </textarea> closing tag is displayed as the default text in the text box. This can be used to include a line like "Enter your comment here". It can also be left blank but then filled in automatically by a script that generates a form, so that it contains some longer passage of text for the user to review or edit.

The parameters allowed with the <textarea> tag are NAME (required), ROWS (how high the box should be, measured in lines), and COLS (how wide the box should be, measured in characters). The default values used if you don't include ROWS and COLS depend on the user's browser. But even if you don't specify a size, the <textarea> is intended for larger blocks of text and will include scroll bars as needed.

The following example of a <textarea> tag is displayed in a browser Figure 10-9.

```
<textarea NAME=COMMENTS ROWS=10 COLS=40>
Enter your comments here
</textarea>
```

## BUTTONS

The buttons on a form cause the browser to take action. While other elements wait patiently while a user enters data, as soon as a button is pressed, the browser does something. Basically, the browser can do one of two things: clear the form using a Reset button or submit data to the server using a Submit button.

If you include a Reset button on the form, the browser will clear all the fields on the page and redisplay it. This provides a convenience for users in many cases but is not strictly necessary. In a browser, it's not too hard to Reload or an equivalent button. A Reset button is created with the <INPUT> tag using TYPE=RESET. No name option is used, because there is no user data passed as part of the button being pressed. You can provide a VALUE, which will be the text displayed on the button. If you don't provide a VALUE option, the word "Reset" is displayed on the button.

The second action a browser can take is to submit the form data to the web using a Submit button. The Submit button is identical to the Reset button, except that instead of clearing the form, it packages up the data, and sends it to the URL listed in the ACTION option of the <FORM...> tag.

The following shows both a Reset and a Submit button; their appearance in Figure 10-10.

```
<P>
<INPUT TYPE=SUB Submit Order
<INPUT TYPE=RESET VALUE=Clear Form>
</P>
```
