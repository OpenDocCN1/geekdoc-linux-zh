Let's walk through a typical request and see how these protocols are used. We'll use a request from a Web browser as an example. Suppose you wanted to access the Web site of a large car manufacturer called ABC Autos. You'd type in the URL `http://www.abcautos.com` and press Return. The following steps are a simplified version of what happens in order to get the ABC Autos page onto your screen from a LINUX-based system:

- 1. The Web browser uses HTTP as the protocol to be used and requests a connection to www.abcautos.com on the standard HTTP port, 80.
- 2. Linux receives the request to make a connection to www.abcautos.com, but can't do so without an IP address.
- 3. Linux looks first in the hosts file to see if www.abcautos.com is defined. It probably isn't, so Linux uses DNS to send a request to the name server (which may be located at the ISP or locally). The request says: What is the IP number of www.abcautos.com?
- 4. The name server returns the IP address of www.abcautos.com.
- 5. With the IP number of www.abcautos.com in hand, Linux prepares to make a connection to that computer by using the TCP protocol to initiate a connection.
- 6. The Linux kernel prepares the TCP packet to send over IP on the Internet.
- 7. Routers on the Internet use protocols that aren't part of your Linux Web server to get the IP packet to the right destination. (Routing is discussed in Chapter 7.)

## The inetd Superserver

Remember that Linux is a multitasking operating system. Linux always has several programs running in the background taking care of system-related tasks such as logging user actions, and watching for network traffic. These programs use very little of the system's time but allow it to manage the system very effectively.

Programs run in the background without showing anything on the screen are sometimes called daemons. A program that writes an entry to a log file time someone logs in is one example of a daemon. It serves an important purpose and may always be running, but you never see any evidence of it as you work on the system unless you ask specifically what programs are running.

One of the programs that is always running in the background is a superserver called inetd (usually prototyped net-daemon), which stands for the Internet Daemon. inetd constantly watches the networking ports (connections) to see if a request is coming in. The configuration file of inetd provides it with instructions for which program to start for each possible request that comes in. In most cases, inetd will route the incoming request to a running program such as a Web server or else start a program to deal with the incoming request.

Following is part of a sample configuration file for inetd, with instructions that are provided for when network traffic is detected in each of several services. Another file, /etc/services, contains additional information on the ports that are being serviced by inetd.

## Ports

A port is like a socket. Port numbers can range from 1 to 65535. Most of the protocols we've talked about, such as HTTP, use a standard port. For example, web servers use port 80. If you try this on a non-Linux system, the Telnet program you are using might not let you specify a nondefault port. Also, some Web servers may not allow you to connect from a Telnet program because they consider it a security risk. If you rent space on an ISP, you can start a Web server on a nonstandard port. Because ports play an important role in a Linux Web server, the next section provides an exercise to help you learn more about networking.

## Using Telnet to Play with HTTP

The Web protocol is very straightforward. We can use a standard UNIX utility called Telnet to demonstrate how it works. Telnet is part of every Linux system. It allows you to connect to a remote computer as if you were using a locally terminal. You can also use Telnet to connect to port 80 (the standard Web port) and send HTTP requests as if they were coming from a Web browser. To use Telnet to see HTTP working to send back a Web page, the following commands at a command-line prompt in Linux, once you get it up and running (the connection response from the Web server will fill in between your entries if the test is working:

```
telnet www.caldera.com 80
GET /index.html
```

After you send the GET command, the Web server should return the HTML file for the home page of the site, which will fill your screen. The connection is automatically closed by the Web server. Web server connections are based on the HTTP protocol, which is stateless, meaning that every new request opens a new connection, which is discarded as soon as the information is sent. Information about the browser or about a previous request is not maintained from one request to another. Everything starts from scratch with every new request from a client.
