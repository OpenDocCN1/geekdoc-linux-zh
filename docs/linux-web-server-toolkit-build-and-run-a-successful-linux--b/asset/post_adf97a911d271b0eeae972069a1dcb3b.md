## Understanding HTML

HTML, or Hypertext Markup Language, was developed in the early 1990s as part of the original plan for the Web. It was created to meet the need for a simple language that could express graphical elements and hypertext links in documents passed back and forth on the Web. As started out as a very straightforward and simple tool you could learn in an hour or two. For better or worse, it's got a lot more complicated than that, more complicated than the information provided in this book. This chapter starts out by providing an overview of HTML. After that, I explain how HTML is organized and how browsers use to display documents from the Web. I'll also describe some of the tools you can use to create HTML pages.

## The Origins of HTML

It's interesting to note that the design of HTML came from another document language called SGML, the Standard Generalized Markup Language. SGML is a language specification for designing markup systems for documents. It's used by major publishers all over the world to define how their documents are created. The intention of SGML — and HTML in the beginning — was to mark up documents by content instead of by appearance. For example, instead of marking something "Bold" you would mark it as a "Title." This was a perfect system for a world, diverse Internet protocol.

But it didn't stick. The desire of Webmasters and users became ever stronger to have more control over the appearance of what browsers displayed. Thus, the original, pure HTML became polluted (yes, I am a purist at heart) with dozens of tags used to directly affect the appearance of the document the user sees. A tag is an instruction code within an HTML page, instead enclosed within angle brackets and looks something like this one, which defines the start of a table.

```
<TITLE>
```

You'll read a lot more about tags throughout this chapter. You'll probably come to really appreciate those tags, however, because they can make your Web pages look great.

> The Web page is used all the time, but it isn't really an accurate term. An entire HTML file will be loaded in the browser, instead of its contents may be too long to display on a single screen. So, the user will scroll to the bottom of what is actually equivalent to 20 pages of text, but it's still considered one Web page because it is a single HTML file.

## Writing in HTML

HTML is a plaintext format. That means you can use any regular text editor on any computer to write an HTML page. If you use a word processor to write HTML pages, you need to save your file as ASCII Text or plaintext or similar thing. Web browsers don't understand WordPerfect or FrameMaker files, only plaintext.

Of course, more and more word processors have HTML modes that enable you to write a document and save it as HTML.
