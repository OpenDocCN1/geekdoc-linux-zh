# # Virtual Hosts

Apache allows you to have a single physical computer serving Web pages for
several domains. This is called virtual hosting. For example, if you host sites
for several associated businesses, with a separate domain name, all the Web
pages for each domain name can be served to the Web using just one computer
running Apache.

The first step in enabling virtual hosting is to adjust your domain name server
IP routing so that the different domain names, and the different IP addresses if
applicable, all point to the same computer.
Once the network traffic is reaching your single Web server, you can easily
configure Apache to serve all the documents. Just use the BindAddress directive
described previously in this section and the directives described below.

Because no one can assume you'll be virtual hosting or know your
additional hostnames, the directives necessary to use virtual hosting are commented
out in the default httpd.conf file onLinux.
The Listen directive allows you to give another IP address and port, or just
another port, the Apache server should listen to for Web requests it should
service, as follows:

```
Listen 205.23.56.1:80
```

The most important part of virtual hosting, however, is the VirtualHost con-
tainer. This part of your httpd.conf or srm.conf configuration file isn't exactly a
direct. It's like an HTML tag. You give another domain or hostname as a value
and enclose it in angle brackets as follows:

```
<VirtualHost newweb.corp.com>
```
