# Linux Server Toolkit

# READMENAME AND HEADERNAME DIRECTIVES

The ReadName and HeaderName directives give the filename for a README file and a header file as follows:

ReadmeName README
HeaderName HEADER

In the case of ReadmeName as is set by default, if a file called readme.html is found, that file will be used as a README for that directory. If that file doesn't exist, a file name README exists, it will be assumed to be plaintext and will be used.

The contents of the file named in ReadmeName are sent at the end of each directory listing generated by the Web server.

The Header directive works in the same way. The contents of the file named by HeaderName are sent at the beginning of each directory listing generated by the Web server fancy indexing process.

# INDEXIGNOREORE

The Indexignore directive lists files that should not be included when creating a directory listing, whether fancy or not, as follows:

```
IndexIgnore /*.??* ~* */HEADER* */README* */RCS
```

The files defined by this directive are those that you don't want people to see in the directory. The default entry shown above includes hidden files, the HEADER file, and any RCS (Revision Control System) files that may be in the directory, among others.

# FILENAME

The AccessFileName directive is a security feature that keeps people from seeing files that commonly occur (especially hidden files) but are useful only for learning about the Web server setup. It is also a convenient way to keep directory listings clean for end users.

The AccessFileName directive defines the name of a hidden file starting with a period that can appear in any directory that the Web server accesses, including symbolic links or aliases, as follows:

```
AccessFileName .htaccess
```
