Remember that these gateways are between a Web server and a e-mail client, and some work in both directions. These are not gateways between different types of e-mail systems. These packages all use standard e-mail systems on Linux and UNIX with the SMTP standard protocol for e-mail. They do not allow you to e-mail from Lotus CC: to the Internet or from Novell MHS to Lotus CC: That requires a different type of gateway from those we are talking about.

There are other types of software that might also be called e-mail gateways. One is a service that sends you an e-mail notification when a Web page you are interested in is updated.

Another is a package that automates providing a mailing list archive as a collection of HTML documents, maintaining discussion threads and chronology, and creating convenient links between articles. I think both of these are a stretch of the e-mail gateway, but both are useful, and you may need them for some point.

Another important type of gateway for many Web servers is a database gateway that allows data to be delivered easily in a Web page. These gateways are described in the next section.

# Database Gateways

Database gateways for the Web are probably the most important use of gateway technology. I say this for two reasons. First, using the Web as the delivery mechanism can eliminate the need to develop specialized database client software. In many cases, this removes a sizable burden from software developers.

You may remember some of the specialized database client development tools of a few years ago. Tools such as Borland Object appeared, the main focus of which was on easily creating a specialized database client to access a large-base on a server somewhere in the organization.
