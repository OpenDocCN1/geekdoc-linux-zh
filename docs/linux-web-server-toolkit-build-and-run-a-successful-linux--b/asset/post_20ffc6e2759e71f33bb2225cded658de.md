# The Proxy Server

You can enable the ProxyRequests directive to use the proxy server feature of Apache as follows:

```
#ProxyRequests On
```

> NOTE: ProxyRequests directive is not used in default configuration.

The Apache server is a proxy server when it acts as a gateway sending a browser's request on to another server.
In association with the proxy server feature, you can enable caching of documents, so that frequently requested documents are stored on this server and returned to a browser without going to the place where the documents were originally stored. This is illustrated in Figure 11-1.

The following caching directives are provided (all are commented out in the default httpd.conf file):

- CacheRoot: gives the directory where cached documents are stored.
- CacheSize: gives the number of megabytes that can be used to store cached documents. When this limit is reached, the least accessed documents are deleted from the cache.
- NoCache: gives a list of documents from which documents should not be cached. For example, if you want all documents from your stock quotes site to be updated every time instead of being cached to avoid getting the same for five straight days, then you would list stocks.com after the NoCache directive.

## Virtual Hosts

Apache allows you to have a single physical computer serving Web pages for several domains. This is called virtual hosting. For example, if you host sites for several associated businesses, with a separate domain name, all the Web pages for each domain name can be served to the Web using just one computer running Apache.

The first step in enabling virtual hosting is to adjust your domain name server IP routing so that the different domain names, and the different IP addresses if applicable, all point to the same computer.
Once the network traffic is reaching your single Web server, you can easily configure Apache to serve all the documents. Just use the BindAddress directive described previously in this section and the directives described below.

Because no one can assume you'll be virtual hosting or know your additional hostnames, the directives necessary to use virtual hosting are commented out in the default httpd.conf file on Linux.
The Listen directive allows you to give another IP address and port, or just another port, the Apache server should listen to for Web requests it should service, as follows:

```
Listen 205.23.56.1:80
```

The most important part of virtual hosting, however, is the VirtualHost container. This part of your httpd.conf or srm.conf configuration file isn't exactly a direct. It's like an HTML tag. You give another domain or hostname as a value and enclose it in angle brackets as follows:

```
<VirtualHost newweb.corp.com>
```

Then you end this special container as you would end an HTML tag, as follows:

```
</VirtualHost>
```

Between these two lines you can use most of the directives that we've described already. But they apply to Web traffic for only the new hostname defined in the VirtualHost container. For example, you include a DocumentRoot directive that defines a directory where all the documents for the new hostname are stored. You can also have ErrorLog and TransferLog directives to store records about this host in a different set of files from the main logs. The following sample is taken from the httpd.conf file:

```
<VirtualHost host.foo.com>
ServerAdmin webmaster@host.foo.com
DocumentRoot /www/docs/host.foo.com
ServerName host.foo.com
ErrorLog logs/host.foo.com-error_log
TransferLog logs/host.foo.com-access_log
</VirtualHost>
```

Each domain for which you make documents available should have a separate collection of server information recorded, as logs and documents. In order to facilitate this, you should include at least the directives in the previous example for each virtual host for which you serve documents.

![](img/e01f1106dd2902613fa07890c8baa7e6_319_0.png)

You can have any number of VirtualHost containers and therefore serve Web pages for any number of sites using a single Apache server. The only limitation is how large a hard disk you have for the pages and how large a Web server you can handle.
