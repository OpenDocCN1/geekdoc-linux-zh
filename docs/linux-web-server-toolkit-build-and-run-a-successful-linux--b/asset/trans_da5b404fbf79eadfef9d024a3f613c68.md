

## 第 16 章：网关：通过 Web 提供一切内容

## 其他类型的网关

除了我在书中提到的之外，互联网上还有许多其他类型关于网关的信息可以可用。一个良好的 Web 浏览器支持许多格式，包括 FTP、gopher、多种图形格式等。但由于格式非常多，你将在未来几年内看到更多种类的 Web 网关被投入使用。

Web 在计算机领域已变得如此强大且流行，因此任何类型的信息（尤其是互联网上的信息）很可能在加载之前就通过 Web 页面可用。浏览器支持的其他格式对于原生读取这些格式非常有用，但会有越来越多、越来越多的数据将以 HTML 格式提供，从而将负担放在服务器端而不是客户端上。尽管有许多客户端增强（插件）允许向现有浏览器中添加各种多媒体扩展，我仍然认为（这种趋势是必然的）。

目前可以通过网关在 Web 上提供的某些数据格式或协议包括以下内容（示例 URL 参见表 16-3）：

- *WAIS*：提供广域信息服务（Wide Area Information Service）的服务器，这是一种服务器索引程序，你可以在跨越多个服务器时搜索相关信息。（参见表 16-2。）

- *Finger*：个人信息服务 finger 提供用户名、全名以及关于你用户账户的几个事实，例如用户当前是否已登录。这是一个标准的 UNIX 信息服务，传统上在命令行中输入。

- *支持新闻组的浏览器的新闻组*：新闻组（Newsgroups）非常流行，但并非所有组都具备处理新闻组并允许读取和发布消息的能力。NNTP 新闻服务器协议的网关可以使用标准的 HTML 页面和表单来读取新闻组并发布响应。

- *邮件列表存档*：在上文的电子邮件网关部分进行了描述，邮件列表存档网关提供了来自活动邮件列表的数千条消息，以易于阅读的格式提供，并对消息进行搜索、索引和颜色编码。

- *其他专有格式*：其他格式（包括互联网上的格式以及企业为了特殊需求而创建或维护的格式）正发现 Web 网关是推广其信息易访问的理想方式。

## 总结

本章解释了网关如何使几乎任何内容都能通过 Web 站点访问，你已经看到这对于需要共享定期创建或已以其他格式存在的数据的组织来说是多有价值的。

在本章中，你学习了以下内容：

- 网关用于向浏览你 Web 网站的用户提供非 Web 数据类型。

- 电子邮件网关对于处理用户提交的表单数据，或为仅通过电子邮件访问互联网的用户提供 Web 页面非常有用。

- 数据库网关是许多 Linux Web 服务器添加的一项重要功能，因为许多重要数据存储在数据库格式中。Web 网关通过 Web 浏览器使这些数据可用。

- Linux 存在许多其他类型的网关。这些网关允许使用 Web 服务器对大多数类型的计算机数据进行准备并进行分发。

- 在下一章中，你将看到使用 Web 服务器 API 如何让你以比之前章节中讨论的脚本或 Java 编程更深层次、更高性能的方式为服务器添加功能。你还将学到，甚至可以使用 API 创建紧密集成到你的 Web 服务器中的网关。

## 使用服务器 API

根据你在第 10 章和第 16 章中读到的内容，你可以看到在 Web 服务器上使用脚本可以做很多事情，它们与你在 Web 页面内创建的表单交互。但当你为 Web 服务器使用应用程序编程接口（APIs）时，你可以更进一步。本章的主题包括：

- 使用 API 的优势
- API 如何被使用的示例
- Netscape 和 Apache API 的概览

## 什么是 API？

到目前为止，你可能可以使用你的 Web 服务器做很多事情。但我想象你可能还在想一些你想用 Web 服务器做、但不知道如何使用你目前所学的工具来实现的事情。

这就是 Web 服务器应用程序编程接口（或 API）大显身手的地方。一组 API 就像一组编程函数，允许你在 Web 服务器的核心功能与你添加的组件之间往传数据。

API 的开发是为了扩展 Web 服务器的能力，超出其设计者的原始范围。API 允许你以更深层次的水平与服务器交互。在事实上，在 Apache 和 Netscape Fast 中，书中描述的大部分功能都是通过 API 实现。API 允许你添加比标准 Web 服务器功能更复杂的功能，适用于你网站的需求。

服务器 API 是一个非常通用的服务器接口。事实上，第 11 章描述的大部分功能都是作为模块内核的。这包括所有的 URL 管理（别名、用户目录等）、用户验证和密码文件，以及检查主机是否允许访问文件的访问控制功能。其他示例包括日志管理（如果你加载了可选日志模块）以及服务器端模块。

## Apache 简介

某些 Apache 模块专门编写为“处理器”（handlers），处理服务器上的特定类型数据。例如，某个模块可能处理所有 JPEG 图请求。由于这种设计，你可以轻松地添加自己的模块来处理新的数据类型，或替换现有数据类型的处理器。例如，你可以添加一种根据客户端浏览器发送的头部使用不同压缩方法的数据类型。或者，如果你的页面使用了 Apache 的标准功能（例如图像映射功能），你可以重新编译 Apache 而去掉该模块，以为每个运行的副本节省内存。

17-1 列出了几个模块及其功能。

| 模块 | 用途 |
| --- | --- |
| mod_log_config | 提供完全日志日志，基于客户端浏览器提交的任何头部信息。（此功能在第 11 章中有简单描述。） |
| mod_cookie | 允许 Cookie 维护。（Cookie 是 HTTP 中的会话，用于在浏览器会话之间维护状态信息。）在 Apache 的后续版本中，该模块被 mod_session 替换，提供了额外功能。 |
| mod_auth_msql | MSQL 数据库身份验证。此数据库工具的代码可以作为 Apache Web 服务器上许多不同数据库应用程序原型。 |
| mod_auth_anon | 此模块提供匿名用户身份验证，类似于 FTP 服务器，使用户可以登录但不需要特定的用户名和密码。 |
| mod_cern_meta | 提供 HTTP 头部元文件支持，基于 CERN 的标准。 |
