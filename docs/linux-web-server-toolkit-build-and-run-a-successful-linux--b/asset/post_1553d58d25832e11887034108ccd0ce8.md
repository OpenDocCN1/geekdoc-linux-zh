# Testing Your Network Connection

Before you dive in and try using a Web browser, you can also try some simpler tests to see if your network configuration is accurate. More information about setting up your network, including setting up high-speed connections, is provided in Chapter 6.

To try these tests, go to a command prompt either at the character mode screen or within the graphical system. The ping command simply sends a packet to a computer and receives an acknowledgment packet return, without exchanging data. If you can reach another computer, you know that basic networking is functioning. First, try the ping command to your own machine as follows:

```
$ ping localhost
PING sah.venture.com (127.0.0.1): 56 data bytes
64 bytes from 127.0.0.1: icmp_seq=0 ttl=64 time=2.0 ms
64 bytes from 127.0.0.1: icmp_seq=1 ttl=64 time=1.2 ms
64 bytes from 127.0.0.1: icmp_seq=2 ttl=64 time=1.1 ms
64 bytes from 127.0.0.1: icmp_seq=3 ttl=64 time=1.5 ms
```

+   - venture ping statistics
4 packets transmitted, 4 packets received, 0% packet loss
round-trip min/avg/max = 1.1/1.4/2.0 ms

Stop the ping command by pressing Ctrl+C.
Localhost is a special hostname that every UNIX system has; it refers to itself. With this command, you are pinging yourself. This works on UNIX you can connect from one process to another in a multitasking operating system. If pinging localhost works, it means that one portion of your network configuration is working correctly.

Next, try to ping a machine on your network using that machine's IP address, as follows:

```
$ ping 208.142.216.118

# Troubleshooting Your Network

If the tests in the last section don't work, the problem is usually in the configuration files mentioned in Table 5-4. Checking these files for correct IP addresses using a text editor—or better, using the configuration utility described in the next section—will usually solve the problem.

Networking can be exceedingly complex. Serious problems can arise from variety of sources to mention here. On that beat, I'll list a few problems to show what sorts of things you can look for. Complete troubleshooting is beyond the scope of this book, though more is covered relative to Web servers in later chapters. The experts at your ISP are usually worth the price to get a troublesome networking error fixed with the least downtime possible. Some possible causes of networking errors include the following:

-   You are using several subnets and you have your network and netmask addresses set incorrectly.
-   You are using several different protocols on your network and they are interfering with one another.
-   You have not informed the person managing your master name server to add the hostname you chose.
-   You didn't use the IP address that was given to you and that was entered in router tables for you at the main gateway.
-   The name server IP address is wrong, so only pings with IP addresses work.

# Changing Your Network Configuration

If you prefer not to edit text files to update your network configuration with new configuration, there are a couple of commands that are used to update some networking: the ifconfig utility, and the route utility. These commands use the information in the configuration files, either during startup or when LISA updates your system. Learning about these commands will be very helpful as you become more involved in setting up your Web site and managing the networking on your system.

Both of the utilities mentioned here should be used only by the root user. If any other user can use them, they pose a security risk. You can learn all the options and use of these utilities from the online documentation, including the man page (enter man ifconfig, for example).

# THE IFCONFIG UTILITY

The ifconfig utility (for Interface Configuration) is used to view or configure the networking interface used by the Linux kernel. Using ifconfig tells the Linux kernel how to process network packets, where to send information, and so forth.

Each network interface on your system has a separate configuration, with associated IP addresses and network traffic. For example, if you have a system with two Ethernet cards installed, it can act as a gateway between two networks. Each of the Ethernet cards is a separate networking interface. Each one has a different IP address and different characteristics that determine how network traffic is treated, including the process of routing packets between the two networks.

You can see the network interfaces that are configured on your system by entering the ifconfig command without any options, as follows:

```
$ ifconfig
