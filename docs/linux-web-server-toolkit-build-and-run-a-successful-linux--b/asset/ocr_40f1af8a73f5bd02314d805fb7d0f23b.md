# A Security Checklist

Of course, you can do more than just watch for security breaches that have already occurred. The information in this section can be used to regularly review your site for potential security weaknesses and correct them before they are ever exploited by someone trying to break into your system.

+   - Keep regular backups of your system, both the entire system and the Web data that you provide to visitors. Depending on the type of data you provide, you might want to keep several copies, including one off-site. (See Chapter 20 for more information about backing up your system.)

+   - Enable logging on your system (it's by default in OpenLinux) and scan the system logs regularly for questionable actions. You can often spot a hacker's attempts long before he succeeds and either short his circuit methods or contact your provider to stop his attempts.

+   - Formalize security plans in the event an intruder is detected. Different types of invasions might call for different actions. Will you shut your network access immediately if someone has downloaded your password file or if you feel the root password has been compromised?

+   - Spend time to break into your own system. This is time consuming and requires a change in mentality, so it's often a priority. But thinking about your system from the perspective of a hacker can help you eliminate weaknesses before someone else discovers them and exploits them.

+   - Search for files that have the setuid bit. If someone has broken into your system, they may set up these files (for example, a copy of the bash shell) to permit root access at a later time. You can use the command to search for these files. This command finds setuid files throughout your filesystem:

```
find /user root -perm -4000 -print
```

+   - Check your /etc/passwd file for any users that might have been created as back doors for an intruder, or for users with no password entry, which can be used by intruders.

+   - Inspect the /etc/inetd.conf file for any unauthorized additions that run unexplained programs (like a shell). Also make the correct version of a program is run by inetd when a service is invoked.

+   - Review the programs that are run by cron and at commands. Intruders may leave entries in these files to redo entry points that you discover and delete.
