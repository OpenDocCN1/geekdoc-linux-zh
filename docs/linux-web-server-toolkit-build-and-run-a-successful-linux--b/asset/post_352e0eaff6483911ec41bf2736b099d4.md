The version of X that is included with most Linux systems is the XFree86 software, created by the XFree86 Free Project, Inc., and distributed under a license that allows Linux to include it for free. Some Linux products also include one of the commercial X products as Metro X or Accelerated X.

X uses the concept of a client and a server, but in a different way what you're probably used to. A server is a graphical window that gets and sends information to a client, which is a program that displays the graphical window. It operates any graphical system when you start a program on your Linux system. The amazing things starting when you are working on the network.

Say you are working on a friend's system in your company. You want to work on a project, but your friend doesn't have the software you need. So while you are logged to your friend's system, sitting at her desk, you follow these steps:

- 1. Enter a command on your friend's computer lets your computer connect an X program to it.
- 2. Telnet (remote emulator) to your computer on your desk.
- 3. Enter a command to “display all graphical programs on my friend's computer.
- 4. Enter a command to start the application that you need.
- 5. The application runs on your computer (remote), but is displayed on your friend's computer (the computer you're using). Thus, your remote computer is the X client, and your friend's computer acts as an X server. The application running on the X client makes requests to the X server.

The application that appears in Step 5 on your friend's system is mixed in all with the other windows that your friend had running from her system as normal applications. But the new window is actually a program running on your system – just the display and keyboard input are from a different machine.

This ability to run a graphical application on one computer and display it on another, while allowing local applications to run at the same time, is something that no operating system can do. Windows is starting to add features similar to this, but they are not commonly available. Windows 3.1, Windows 95, and Macintosh do not have anything like this capability.

Another feature that X provides is complete configuration – a general UNIX feature. You can set your display to be the exact resolution and color depth that you want, within the capabilities of your video hardware. You can use multiple monitors as a single screen, have virtual desktops – anything the hardware is capable of. Compare this to Windows, where the selection of colors, resolutions, and other features that you can use is limited to what the standard Windows driver for your video card allows. The manufacturer creates a driver with certain options, and Windows doesn't allow you to alter that configuration. In X, the driver for your video card still allows for complete configuration to your liking when you install the system or any time thereafter.

The screen that you see is controlled by the window manager, which is a low-level program that provides the graphical services to programs, allowing them to interface with the lower-level X Windows System interface. The window used by OpenLinux (and many other Linux systems) is called fwm. Other window managers for Linux include Motif (a commercial product) and twwm.

When you have a window open in X, you can resize it, move it, and minimize or maximize it, just as in other windowing systems such as Macintosh or Windows. The fwwm window manager can be completely configured using text files. explore the text files in the directory usr/X11R6/lib/X11/fvwm.

# File Typing and Icons

Each of the icons in the window is assigned automatically by the Desktop according to a set of rules. The rules say things like "if a file has the following string in the first 50 characters, it is a WordPerfect document. Display it with this icon and give it this default and secondary actions" – pretty complex rules.

You can click the right mouse button on an icon to see the default and secondary actions, or Edit File Actions to add or change the actions. The rules for assigning types to files on the Desktop are contained in two configuration files:

```
/usr/visix/lg/default/lg_ftc/data.ftc
/usr/visix/lg/default/lg_ftc/prog.ftc
```

If you change these files, you have to remake them and restart the Desktop before they become effective. To remake the files, stay in the directory with the .FTC files and enter the following commands:

```
make
make install
```

The Desktop includes about 2,000 icons that you can specify for particular types of files. You can also add your own or modify an existing icon using the Icon Editor. To start it, choose Icon Editor from the Run menu of the Desktop. Choose the System Galley from the menu and double-click on the icon you want to edit. An edit dialog window like the one shown in Figure 4-4 appears.
