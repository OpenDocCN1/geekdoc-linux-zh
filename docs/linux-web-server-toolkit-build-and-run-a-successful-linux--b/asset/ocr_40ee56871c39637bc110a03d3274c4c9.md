# Setting Up Security Options

The directives in the access.conf file are used to control who can access your Web server and how they can access it. The number of options available in this file is small compared to the other two configuration files discussed so far, but each directory on your Web site can have a set of separate set of options listed in this file.

Every directive in the access.conf file must be inside a pair of container tags that define a directory on your Web server. Most of these directories be within the DocumentRoot area, but you also have a container for your script area and for any other areas that are accessed through links or aliases.

The default access.conf file on Linux includes containers for the DocumentRoot area (/home/httpd/html) and the script area (/home/httpd/cgi-bin). The access granted to these areas is described next, and then other possible options are presented.

# Understanding Document Tree Security

The first container in access.conf starts out with the following tag:

```
<Directory /home/httpd/html>
```

The directives discussed in this section are all included in that container before it ends with a </Directory> tag.

The most restrictive set of options you can select is None, as follows:

Options None

The AllowOverride directive specifies which things can be overridden by an .htacces file (or whatever filename you selected in srm.conf) in a subdirectory, as follows:

AllowOverride None

This example of the AllowOverride directive shows the most restrictive set of override options you can select: None. That means that nothing appearing in a configuration file in a subdirectory of the main document root can change anything appearing in the main configuration files.

The order directive specifies whether to process the allow directive first or the deny directive first, as follows:

```
order allow,deny
allow from all
```

The order in which you use these directives is important. You can deny all hosts and then allow some hosts. If you reversed the order (allow some hosts, then deny all other hosts), the hosts listed as denied wouldn't have access.
