# HIDDEN FIELDS

Hidden fields don't do anything – well, that's a little strong. They don't appear at all in the browser window, so you won't see a figure below showing the results of an <INPUT> tag using HIDDEN. What HIDDEN allows is to store information that the script on the Web server will need but that doesn't require interaction from the user, as, for example, with the following:

+   - A form is sent to the user after he or she selects a certain option. That option is stored in a hidden field so the script processing the form knows which option the user selected to reach the form.
- A user is in the middle of reviewing several database records. A hidden field records the current record number so that when the user presses a Submit button labeled Next Record, the script knows which number to send back.

Hidden fields can be created on the fly using server-side includes to insert specific values, but they are more likely to be a static part of several identical documents with forms that vary in appearance but in their hidden field values, or they include scripts that create the form HTML document on the fly, storing information relationative to the form as they go.
A sample hidden field tag looks something like this:

```
<INPUT TYPE= HIDDEN NAME=RECORD_NUM VALUE=323 >
```

This <INPUT> tag causes the browser to send back a name-value pair of RECORD_NUM=323, which can be processed by the Web server script to determine what action the server should take in responding to the user.
