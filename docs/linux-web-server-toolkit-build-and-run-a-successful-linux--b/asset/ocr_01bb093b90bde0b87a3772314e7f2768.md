# One Step Higher: TCP and UDP

The IP system is not used directly to deliver data from your applications but to establish communication between two systems so they can use another specialized protocol to exchange information. The two main protocols that are used with IP and which are discussed in this section are the Transmission Control Protocol (TCP) and the User Datagram Protocol (UDP).

TCP is used for almost everything on the Internet, including the Web. It provides for stable communication between two computers by packets of information can be exchanged, with checking to see if the connection is intact and guaranteed delivery of each packet of information. TCP delivers an ordered stream of data packets to a requesting application. If a packet is out of order or missing, TCP notifies the sending system to have the packet resent, and all the packets correctly. By using TCP, an application doesn't have to keep track of the low-level networking. TCP delivers assembled, corrected data from a remote connection.

Because of these features, the networking protocol you generally hear about in relation to the Internet is TCP/IP, makes the TCP protocol running on top of the IP protocol.

UDP is used for less common things on the Internet, but it's not used for aspects like the Web that rely on guaranteed delivery of each packet of data in correct order to as an application. UDP is used when establishing a 'long-term' (multipacket) connection between sender and receiver is not required, which saves a lot of time. UDP uses a checksum to verify that each 'one-shot' packet is received intact or not at all.

For example, the network management protocol Simple Network Management Protocol (SNMP) sends packets of status data to the network using UDP. Rather taking the time to use for a management console program and establish a connection with it, the SNMP protocol assumes that a console program is in a monitoring state, the packets will be received. In addition, because the management data is statistical in nature, it is less important if one packet is lost; another will be along shortly and the overall picture will still be accurate.

Note that TCP and UDP use different port numbers. When you explore the inetd configuration file later in this chapter, remember that a port served by the TCP protocol can be used by a different program served by UDP, though in practice this is rarely seen.
