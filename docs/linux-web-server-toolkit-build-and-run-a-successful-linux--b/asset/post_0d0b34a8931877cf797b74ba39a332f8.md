From the List User page, you can see a list of all the users that are a part of any user database. You can also filter the list to show only certain users. This is very useful if you have a large database of users and only want to review certain ones.

## Edit User

The Edit User page is very similar to the Create User page, except that you start the process by pulling information from a user that is already in the database.

First, you enter a login name that you want to edit and press the Get Data button (Make sure the correct database for the user you want to edit is selected from the drop-down list.). The data for the login name you entered is shown in the fields, where you can edit them and then choose OK to save your changes to the user information.

## Create Group and Remove Group

Creating a group involves only a group name, just like in Linux. A group is like a container. You can assign users to one of the groups you create, and then grant access to any of your Web pages based on which group a user is part of. This makes it much easier to grant access to a large number of individual users. Access is granted to the group, and doesn't need to be altered by adding users regularly. Each new user is simply a member of the group when that user account is created. All access granted to the group will be available to the user immediately.

To create a group, select the database that the group should be part of, then enter a name for the group. Remember that group membership cannot cross databases.

Removing a group is just as easy. Select the database that the group is part of and enter the name of the group in the field provided on the Remove Group page.

If you remove a group, all access control selections based on that group name are invalid. None of the users will have access as is granted only to a group that doesn't exist any longer. If you remove a group, you can't restore it without creating a new group and editing the profile of each user to be sure the user is listed as being in the correct group.

## List Groups and Edit Group

Listing and editing groups works just like listing and editing usernames. First, you can use the List Groups page to see all the groups that are part of any of the user/group databases on your system. You can use a filter to reduce the number of groups listed if needed, as m* to list all the groups that start with the letter m.

After you've found the group you want to edit, you can choose the Edit Group page, where you can enter the group name and choose the Get Group Data button.

With the group membership listed, as shown in Figure 12-9, you can make any edits that are needed before choosing OK to save your changes to the database. If you remove users from the group membership list, they may not be part of any group until you edit that user and add them to a specific group.

## Restrict Access

The Restrict Access page allows you to implement the security that you've created for these users and groups.

Access control is based on several factors, including the type of access (read or write, though write is seldom implemented on Web servers), allowing or denying access to hostname or IP address, and which part of the server to set access for.

You will often see the section shown in Figure 12-10 in the Administration pages. This section allows you to select part of the server to which configuration applies. You can select the Browse button to help you find a directory on your Web server. The Access Control options that you select in this page then apply to the directory you selected. The Wildcard button lets you select files that end with .html or .cgi.

If you don't make a selection from the buttons shown in Figure 12-10, but leave them as they appear by default, then the changes that you make, including the access control settings, will apply to every document on your Web server. Once you have selected part of your server for which you want to control access using the buttons shown in Figure 12-10, you will select Read as the Access type, then either Deny or Allow, and then use the Permissions button to enter a list of hostnames or IP addresses that are either denied or allowed. Additional information about allow and deny is provided in Chapter 11.

## Manage User Database

The Manage User Database page is only used if you want to have more than one user database. If the default database doesn't meet your needs, you can enter a new database in the New Database field and choose OK to add that database to your Web server.

Adding a new database doesn't add any users to your system or alter the security in any way. It just provides a new container that you can place user information into. Then you can grant access to those users you add to the database.

If you want to remove a database that you've created, select that database from the drop-down list, then choose the Remove Database button. All the users in that database are discarded. This action cannot be undone, so be very careful about using this feature!

## Import Users

If you used another Web server, or if you want to use your users as a basis for controlling access to your site, you can use this page to import a file and have each username automatically part of the Web server database.

Almost all username files follow the same format, so all you need to know is the filename containing the list of users to import. From the drop-down list of user databases on your Web server, select which database the imported users should become part of. Enter the name of the file containing the user data. Check the boxes for the features that you want to implement during the import operation. Then simply choose OK to complete the import operation.

## Configuring Encryption

Encryption refers to the type of public/private key security that I previously said was access control. More specifically, encryption is about the "Secure Server" features of FastTrack that allow it to be a commercial Web server, with online store capabilities that allow users to transmit credit card information over the Internet without fear of it being stolen.

When you install FastTrack it's not automatically a secure server because an additional piece of information called a certificate is required.

A certificate is a special code issued by a recognized authority such as Verisign Corporation. This authority uses real people's names and real documents (like your business license or incorporation documents) to verify that you are a legitimate entity on the Internet. The idea of a certificate is simply to have some level of verification about people who are collecting credit cards and other sensitive information. There are different levels of certificates available, depending on how much information you provide to the certifying authority.

Before you turn on the security features of FastTrack, you must get a certificate issued for your organization. The Request Certificate page allows you to fill in the information needed to request the certificate over the Internet. Additional communication over a telephone, fax, or postal service is also required to complete the process of getting a certificate.

![](img/e01f1106dd2902613fa07890c8baa7e6_359_0.png)

If you were to somehow get the security part of your FastTrack server running without obtaining a certificate from a recognized authority, every user's browser would display a message stating that your server was operating with an invalid or low-quality certificate. This isn't done to give an authority company a monopoly business—there are many certificate authorities—it just provides users with some assurance about who is running the Web server they're sending personal information to. For example, a server named policemen.com could be soliciting donations without any association with any law enforcement agency. But they could not do that and have a valid certificate.

Once you have acquired a certificate, you can install it through the Install Certificate page, then use the Generate Key page to create a key that is used to show browsers that you have a certificate (like the public part of a public/private key pair). Then use the On/Off page, shown in Figure 12-11, to define the pieces and start your secure FastTrack Web server.
