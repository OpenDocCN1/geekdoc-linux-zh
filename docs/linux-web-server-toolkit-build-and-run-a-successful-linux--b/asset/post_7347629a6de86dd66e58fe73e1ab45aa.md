
## Chapter 11: Configuring the Apache Web Server

### Adding Advanced Features

We, we've covered the basic features of Apache configuration. There are many more features that you can experiment with to add power and flexiblity to your Web server. All are described more fully in the documentation that accompanies the Apache server. I'm just going to summarize some key features to give you an idea of what you can do.

Some of the features described in this section require that you add modules to your standard Apache configuration. These modules are simple server add-ons that extend the Web server you can do. You can also read about adding modules in the Apache documentation. You can also find additional modules on the Apache Web site (http://www.apache.org) and from other locations on the Web. But be careful about using modules from spurious sources – they invite security problems. Table 11-3 describes some features or directives that can be used with Apache.

Table 11-3 Advanced Features Available in the Apache Web Server

| Feature | Module Required | Description |
| --- | --- | --- |
| Alias | No | Any directory on your Web server can be accessed using a standard directory within the DocumentRoot area by specifying an Alias directive in the httpd.conf file. A fake directory indicated by a browser is mapped (aliased) to a real directory on your system |
| Redirect | No | Any requested file can be redirected to another file on your Web server or on another server, using a complete URL. The browser will see the Redirect code and often retrieve the document from the redirected location. This is used when files have been moved or deleted but are still being requested. |
| AddType...cgi | No | A special use of the AddType command lets you define a type for scripts. This provides a more secure execution system. |
| Server-side includes | No | HTML documents can include special codes that cause the Web server to insert text into the document each time it is sent to a browser. Though they add a burden and possible security holes, this feature provides great flexibility for up-to-date documents. |

Table 11-3 Advanced Features Available in the Apache Web Server (Continued)

| Feature | Module Required | Description |
| --- | --- | --- |
| Cookies | Yes | Cookies allow a script running on the Web server to keep track of browsers making requests based on previous actions, such as getting the next record of a database. Though this can be implemented in other ways, cookies provide a simpler solution to making HTTP a more stateful protocol. |
| Configurable logging | Yes | The contents of the access log file can be configured to include a variety of data points. |
| Error messages | No | The error messages sent to a browser when a file cannot be found, when no more clients can connect, or when other errors occur, each can include a specific message. |
| As-Is files | No | A special file type called as-is can be used to send files without the headers normally generated by the Web server. This requires a knowledge of the standard headers so a browser can read the file, but it allows things such as GIF animations to be sent as a single file, saving overhead time. |

### Summary

In this chapter, we've seen how to configure the Apache Web server, the standard Web server that comes with the OpenLinux Lite CD-ROM in this book. We've seen how the standard configuration is set up and some changes that you should make before using it as a full-time Web server.

In this chapter you've learned the following:

- All Apache configuration files use directives — simple commands — to define how the Web server operates.
- The httpd.conf file contains information about the general operation of the Web server program.
- The httpd.conf file contains information about the resources used by the Web server, such as how documents are processed before sending them to a browser.
- The access.conf file contains information about security settings for your Web server. It defines which hosts can access files and what configuration information can be overridden.

It provides secure connections for Internet commerce and graphical administration that will seem very simple and straightforward, especially after the information you learned in this chapter about the features that a strong Web server can offer.

### FastTrack Server Basics

In Chapter 7 you learned how to use the -ps command to make sure the FastTrack server is installed and running. As you begin to configure and administer the FastTrack Server, it's important to remember that there are really two programs running.

- The FastTrack Web server, which services requests from browsers and is probably started automatically when you start your OpenLinux system.
- The Administration server, which you configured in Chapter 7, and which is started only when you begin to use it. This program changes the FastTrack Web server configuration for you according to instructions you provide.

Before you read any further, make sure that your FastTrack Server is running, and that you followed the instructions in Chapter 7 to prepare the Administration server for use (by running the config script in /opt/fasttrack).

### Linux Web Server Toolkit

Next, start the Administration server by opening your browser and entering the URL to reach it. Remember that instead of the standard HTTP port of 80, you selected a different port for the Administration server. If you can't remember what it was, check the configuration files in /opt/fasttrack. The URL that you use will look something like this (in this example 5050 is the administration port selected):

```
http://localhost:5050
```

Once you've entered this URL in your browser, the HTML page shown in Figure 12-1 appears. This is where you enter a valid username and password before you can start your FastTrack server. The username and password are those you entered during the configuration. The username is normally admin.

After you enter a username and password, you see the first configuration page, the Server Selector page shown in Figure 12-2. This page lists all the FastTrack servers that you can administer from this browser.

![](img/e01f1106dd2902613fa07890c8baa7e6_341_0.png)

You can only administer a FastTrack server if your browser is running on a system that is listed as a valid location (with both IP address and domain name) in the Administration Server configuration file. This prevents someone from learning your username and password and changing your FastTrack server from across the Internet.

Note in Figure 12-2 the FastTrack server listed includes an On/Off switch on the left side. This switch provides a simple way for you to shut down or start your FastTrack servers.

Additional servers can be added from the Administration Page within the browser, once you have it running for a single server. If you have several FastTrack servers running on your network, you can easily administer and configure any of them using the same interface, by simply selecting one of the servers listed on the page.

In addition to being able to select a server to administer from the page shown in Figure 12-2, you can also complete a couple of other tasks using the buttons at the bottom of this first Server Selector page.

The first button, which installs a New Netscape FastTrack Server, lets you enter the basic information like a hostname and port number that allows you to run another FastTrack Server on the same computer. A servername entered here will be listed on the Server Selector page as an administerable server.
