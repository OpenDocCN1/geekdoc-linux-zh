# TABLE 5-1 Commands to Manage Linux Kernel Modules

| Command | Description |
| --- | --- |
| insmod | Inserts a module into the kernel; use with no parameters to see a list of options |
| modprobe | Similar to insmod; automatically loads a set of modules according to information set up by the depmod command — see the manual pages for more details |
| ismod | Lists the modules currently in the kernel |
| rmmod | Removes a module from the kernel |

For example, to see the kernel modules installed on your system, you can use the insmod command, as follows:

| Module | #pages | Used by: |
| --- | --- | --- |
| nkfs | 3 | 2 |
| ipx | 3 | 2 |
| misc | 1 | 0 |
| ppp | 5 | 0 |
| slip | 2 | 0 |
| slhc | 2 | [ppp slip] 0 |
| lp | 2 | 0 |
| isofs | 5 | 0 |
| nfs | 12 | 5 |

You may need to provide specific hardware details, called *parameters*, if your hardware is not using standard system addresses, or if multiple hardware components on system conflict with one another. The next section describes how to use these hardware parameters for kernel modules.

# Using Hardware Parameters

Every piece of hardware makes several assumptions about your system and your requirements. For example, a CD-ROM drive controller assumes it can use a particular software interrupt number, a particular data port, a particular interface, and so forth.

Linux kernel modules allow you to specify the settings and features to use with that module or even probe to discover the required settings without your intervening.
