## UNDERSTANDING TAGS

In order to use tags, you must understand some basic rules. As I just mentioned, every HTML tag is enclosed in angle brackets. Based on this rule, a tag to begin an ordered list looks like this:

```
<OL>
```

Ending tags have the same command as beginning tags, but are preceded by a forward slash. For example, the tag to end an ordered list looks like this:

```
</OL>
```

![](img/e01f1106dd2902613fa07890c8baa7e6_248_0.png)

Most tags are in pairs; one tag starts something, another tag ends it. Don't forget the ending tags.

With a tag, parameters can be added to provide the browser with more information about that specific element. For example, a tag to create a link to another Web page has to indicate where the page is located. Or a tag that indicates where a graphic should appear on the page must include the name of the graphics to use. These parameters are included within the brackets, with their value (if they have one) in quotation marks. For example, the basic image placement tag looks like this, with SRC being the source file for the graphics:

```
<IMG SRC="/graphics/logo.gif">
```

This tag is composed of three parts. IMG is the type of tag and indicates that an image (a graphics file) is inserted where this tag appears in the document. SRC is a parameter that indicates the source file for the graphics image. When the browser detects an IMG tag, it expects an SRC parameter to be included as part of that tag. The third part, `/graphics/logo.gif`, is the value of the parameter, and gives the path and filename for the graphics file that will be displayed. HTML commands are not case sensitive, so the IMG and the SRC could be lower case. But the data provided with the parameter is case sensitive. It is a file path in this case, which is case sensitive in Linux.

If you're used to programming in C (which traditionally uses all lower case), it might be a stretch, but I recommend using all upper case for HTML tags so that they stand out from the text of your document. This makes it easier to spot HTML tags among the text when you're editing Web pages.

## Linux Web Server Toolkit

Another important thing to keep in mind when you're developing Web pages is that all extra carriage returns, tabs, and spaces are ignored when a browser displays an HTML page. If you write a section of HTML page like this:

Send it to:
P.O. Box 4345
Maryvale, Utah 84567

it will be displayed as

Send it to: P.O. Box 4345 Maryvale, Utah 84567

because all the carriage returns and extra spaces at the beginning of the indented lines in the top example are ignored.

This is actually a good thing. You can use white space (blank lines, tabs, and indents) to organize your HTML page so that the tags and sections of the page are easy to read. They will not affect how the page is displayed. This is the same way programmers make C or Java code easy to read: by using white space.

Don't break between lines. That is, keeping the opening bracket and the closing bracket on the same line. While white space is ignored, some browsers might lose track of tags if you have a line break in the middle of some tags.

To review, when you write HTML pages, you should remember a few basics:

- Most tags are in pairs. When you start something, you have to finish it.
- HTML tags are not case sensitive. But the data inside them must be!
- Keep each tag on the same line; don't split a tag with a carriage return.
- All white space characters (line breaks, tabs, multiple spaces) are ignored. Use it to make your HTML code readable, but use tags to determine how the page will look in the browser.

## UNDERSTANDING HOW AN HTML DOCUMENT IS ORGANIZED

Good HTML documents always follow a pattern that lets the browser know what's coming later in the document and communicate effectively with the Web server and with the user who's viewing the document.

Well-organized documents also make it easier for you to understand and update complicated documents over time, as information changes. Just like writing programming code, good design and well-documented code reward the extra work in the long run.

HTML includes many tags that are not for the display of information, but are instead used to record or embed information about the document itself. Information about the document is called meta information, which is stored in meta tags. For example, an `<h1>` tag indicates that the following text is a first level head. A `<HEAD>` tag doesn't tell you anything about how to display the document. It is a meta tag, which indicates only that the text that follows until the `</HEAD>` tag is the heading for the document, without providing the browser with any more information. Other meta tags provide information about the tool used to create the HTML document, the author, or other similar information.

## THE BROWSER WARS

The original graphical browser, Mosaic, understood a complete set of HTML tags. But as new browsers came on the commercial scene, particularly Netscape and Microsoft, they began to add their own list of tags to what their browsers understood. This allowed browser-specific features to emerge, but it also fragmented web standards.
