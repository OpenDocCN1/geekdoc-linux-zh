You can also use su to run a single command as root by using the -c option, as in su -c command to run command as root. If you use a dash (-) within the command, as in su -luke, the program opens a login session that runs the target user's login scripts. This is important because these scripts set environment variables that can be important for that user, such as $PATH.

The sudo command is similar to su, but it works for just one command at a time, which you type after sudo, similar to using -c. For instance, typing sudo cat /etc/shadow enables you to see the contents of the /etc/shadow file, which is not readable by ordinary users. You must either type your own password or the root password, depending on the sudo configuration, when you use this program. (When using su -c, you must always type the root password account privileges.) Some distributions, such as Ubuntu, rely heavily on sudo and don't permit direct root logins by default.

# ## The LEGALITIES OF ACQUIRING root PRIVILEGES

If your Linux system is in the workplace, it is important to determine your company's policies concerning acquiring root privileges. Logging directly into the root account or using the su command to obtain root privileges up what is called a repudiation environment. In this environment, a person can deny actions, as in this case, the person can deny whether he or she logged in as root. This environment could allow a root account user to perform troubling activity and then legally deny responsible for that activity. This is a potentially dangerous situation.

Many companies have (or should have) a policy that insists the sudo command is for anyone needing to acquire root privileges. The sudo command tracks and logs a user's activity and sets up what is called a nonrepudiation environment in which actions cannot be legally denied.

If you acquire root privileges by logging directly into root or by using sudo, your shell will change:

```
[luke@wembleth ~]$ su
Password:
[root@wembleth luke]# #
```
