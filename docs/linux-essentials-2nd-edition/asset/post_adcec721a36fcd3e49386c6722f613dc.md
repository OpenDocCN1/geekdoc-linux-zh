The cp command provides many options that modify its behavior. Some of the useful options enable you to modify the command's operation in helpful ways:

- Force Overwrite: The -f or --force option forces the system to overwrite any existing files without prompting.

- Interactive Mode: The -i or --interactive option causes cp to ask you before overwriting any existing files.

- Preserve Ownership and Permissions: Normally, the user who issues the cp command owns the copied files and that account's default permissions. The -p or --preserve preserves ownership and permissions, if.

- Perform a Recursive Copy: If you use the -R or --recursive option and specify a directory as the source, the entire directory, including subdirectories, is copied. Although -r also performs a recursive copy, its behavior with files other than ordinary files and directories is unspecified. Most cp implementations use -r as a synonym for -R, but this behavior isn't guaranteed.

- Perform an Archive Copy: The -a or --archive option is similar to -R, but it preserves ownership and copies links as is. The -R copies the files to which symbolic links point, rather than to the symbolic links themselves. (Links are described in more detail later in this chapter, in "Using Links")

- Perform an Update Copy: The -u or --update option tells cp to copy the file only if the original is newer than the target or if the target doesn't exist.

This list of cp options is incomplete but covers the most useful options. Consult cp's man page for information on additional cp options.

## Moving and Renaming Files

In a text-shell, the same command, mv, is used to move and rename files and directories. Its use is similar to that of cp; for instance, if you wanted to move outline.pdf to ~/publication, you would type the following:

```
$ mv outline.pdf ~/publication
```

If you specify a filename, with the destination, the file will be renamed as it's moved. If you specify a filename, and the destination directory is the same as the source directory, the file will be renamed but not moved. In other words, mv's effects are just like cp, except that the new file replaces, rather than supplements, the original.

Behind the scenes, mv does the following:

- When the source and target are on the same filesystem, mv rewrites entries without actually moving the file's data.
- When you move a file from one filesystem to another, mv copies the file and deletes the original file.

The mv command takes many of the same options as cp. From the earlier list, --recursive, and --archive do not apply to mv, but the others do.

## Using Links

Sometimes it is handy to refer to a single file by multiple names. Rather than create several copies of the file, you can create multiple links to one file. Linux supports two types of links, both of which are created with the ln command:

- Hard Link: A hard link is a duplicate directory entry. Both entries point to the same file. Because they work by tying together low-level filesystem data structures, hard links can only exist on a single filesystem. In a hard scenario, neither file holds any sort of priority over the other; both tie directly to the file's data structures. Type ln origname linkname where origname is the original name and linkname is the new file's name, to create a hard link.

- Symbolic Link (aka a soft link): is a file that refers to another file by name. That is, the symbolic link is a file that holds another file's name, and when you tell a program to read or write from a symbolic link, Linux redirects the access to the original file. Because symbolic links work by filename references, they can cross filesystem boundaries. Type ln -s origname-link to create a symbolic link.

You can identify links in long directory listings (using the -l option to ls) in a couple of ways. The following example illustrates this:

```
$ ln report.odt hardlink.odt
$ ln -s report.odt softlink.odt
$ ls -l
total 192
-rw-r-r-- 2 root users 94720 Jan 10 11:53 hardlink.odt
-rw-r-r-- 2 root users 94720 Jan 10 11:53 report.odt
lrwxrxr-x 1 user group 12 Jan 10 11:54 softlink.odt -> report.odt
```

This example begins with a single file, report.odt. The first two commands create two links, a hard link (hardlink.odt) and a symbolic link (softlink.odt). Typing ls -l shows all three files. The original file and the hard link can be identified as links by the presence of the value 2 in the second column of the ls -l output; this identifies the number of filename entries that point to the file, so a value higher than 1 indicates that a hard link exists. The symbolic link is denoted by l (a lowercase L) as the first character of the softlink.odt file's permissions (lrwxrwxrwx). Furthermore, the symbolic link's filename specification includes an explicit pointer to the linked-to file.

Both types of links are useful for referring to files by multiple names or in multiple directories. For instance, if you write a letter that you sent to multiple recipients, you might want to store copies in directories devoted work fine, but each type of link has implications. Most important, if you use symbolic links, deleting the original file makes the file completely inaccessible; the symbolic links remain but point to a non-existent file. If you use hard links, by contrast, you must delete all copies of the file to delete it itself. This is because hard links duplicate directory entries that point to the same file, symbolic links are separate files that refer to the original file by name.

If you modify a file by accessing its soft link, or by any hard-linked name, you should be aware that the program you use will modify the original file. Some programs create a backup of the original file that you can use to recover the original in case you find that your changes were in error. Most editors do this in a way that the backup is a new file, and they write changes to the original file, thus affecting it as well as the link. Some programs, rename the original file and then write a new file with the changes. If a program does this and you've accessed the file via a link, the linked-to file will be unaffected by your changes. If in doubt, test your program to be sure of what you expect.

If you want to create a link to a directory, be aware that you can normally do this only via symbolic links. Hard links between directories are potentially dangerous in terms of cycles, so you can't create them. Linux installations use links (mostly symbolic links) in various places. Runlevel management is beyond the scope of this book.

## Deleting Files

The rm command deletes files in text-mode. As you might expect, you pass the names of one or more files to this command:

```
$ rm outline.pdf outline.txt
```

This example deletes two files, outline.pdf and outline.txt. If you want to delete an entire directory, you can pass rm -r, -R, or --recursive with a directory name:

```
$ rm -r oldstuff/
```

The -i causes rm to prompt before deleting each file. This is a useful safety measure. If you use the -f (--force) to override this setting, if -i is configured as the default. Other options to rm exist; consult its man page to learn about them.

It's important to realize that rm does not implement any functionality like a file manager's "trash can." Once you delete a file with rm, it's gone, and you can't recover it except using low-level filesystem tools. You should be careful when using rm—and even more using it with its -r option or as root!

## Using Wildcards

A wildcard is a symbol or set of symbols that stands for other characters. You can use wildcards to refer to files. (Using wildcards is sometimes called globbing). Three classes of wildcards are common in Linux:

- ? A question mark stands for a single character. For instance, b?? matches book, bald, buck, or any other four-character filename that begins with b and ends with k.

- * An asterisk matches any character or set of characters, including none. For instance, b*k matches book, bald, and buck (just as b?? does). b*k also matches bbk, bbb, and backtrack.

**Bracketed Values** enclosed in square brackets ([]) normally match any character in the set. For instance, b[ao][l0] matches bald and book but not. It's also possible to specify a range of values; for instance, b[a-z]ck matches back, buck, and other four-letter filenames of this form whose second character is a lowercase letter. This differs from b?ck—because Linux treats filenames in a case-sensitive way and because ? matches any character (not just letter), b[a-z] doesn't match b3ck, although b?ck matches both of these filenames.
