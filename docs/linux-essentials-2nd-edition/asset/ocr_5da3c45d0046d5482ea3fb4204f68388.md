Some servers and other system programs run this way, which is often called SUID root. SUID programs are indicated by an s in the owner's execute bit in the permission string, as in rwsr-xr-x.

**Set Group ID (SGID)** The set group ID (SGID) option is similar to the SUID option, but it sets the group of the running program correctly to the group of the file. It is indicated by an s in the group execute bit position in the permission string, as in rwxr-sr-x.

You can set these bits by using chmod:

**Using an Octal Code** In the leading digit of a four-digit octal code, the value 4 to set the SUID bit, to 2 or 6 to set both bits. For instance, 4755 sets the SUID bit, but not the SGID bit, or on an executable file.

**Using a Symbolic Code** Use the s symbolic code, in conjunction with u to specify the SUID bit, g to specify the SGID bit, or to set both bits. For instance, typing chmod u+s myprog sets the SUID bit on myprog, whereas chmod ug-s myprog removes both the SUID and the SGID bit.

dinarily, you don't need to set or remove these bits; when necessary, the package manager sets these bits correctly when you install or upgrade a program. You might need to alter these bits if they've been mistakenly set or removed from files. In some cases, you might want to use source code or adjust these values on program files that you compile from source or if you need to modify the way a program works. Be cautious when doing so, though. If you set the SUID bit on a garden-variety program, it will run with increased privileges. If the program contains bugs, those bugs will be able to do more damage. If you accidentally remove these permissions, the results can be just as bad—programs like passwd, sudo, and all rely on their SUID bits being set, so removing this feature can cause them to stop working.

# Hiding Files from View

If you're looking for something analogous in Linux, you won't find it—at least not in the form of a dedicated feature.
