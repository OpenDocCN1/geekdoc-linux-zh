# Code Types

Programmers write programs in a form known as source code. Although source code can be arcane to the uninitiated, it's crystal clear compared to the program must take for a computer to run it—that is, binary code. A program known as a compiler translates source code to binary code. (Alternatively, some programming languages rely on an interpreter, which converts source code to binary code (on the fly), eliminating the need to compile source code.)

The open source code refers to the availability of source code. This is generally withheld from the public in the case of commercial software programs and OSs. Conversely, a programmer with access to a program's source code through open source software can fix bugs, and otherwise alter how the program operates.

OS X ships with some Unix server programs, so you can configure it to work much like Linux or other Unix-like OS as a network server computer.

OS X differs from Linux in its user interface, The OS X user interface is known as Cocoa from a programming perspective, or Aqua from a user's point of view. It includes elements that are roughly equivalent to both OS X and a desktop environment in Linux. Because Cocoa isn't compatible with X from a programming perspective, applications developed for OS X can't run directly on Linux (or on other Unix-like OSs), and porting them (which is modifying the source code and recompiling them) is a nontrivial undertaking. Thus native X applications seldom make the transition to Linux.

OS X includes an implementation of X that runs under Aqua. This makes the transfer of GUI Linux and Unix programs to OS X relatively straightforward. The resulting programs don't entirely conform to the Aqua user interface, though. They may have buttons, menus, and other features that look out of place compared to the usual appearance of OS equivalents.
