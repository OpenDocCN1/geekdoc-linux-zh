
The details of the shell prompt vary from one installation to another, but you can type text-mode commands at the shell prompt. For instance, you could type ls (short for list) to see a list of files in the current directory. Removing vowels, and sometimes consonants, shortens the most basic commands, in order to minimize the amount of typing required to execute a command. This has the unfortunate effect of making many commands rather obscure.

Some commands display no information, but most produce some output. For instance, the ls command produces a list of files:

```
$ ls 106792c01.doc f0101.tif
```

This example shows two files in the current directory: 106792c01.doc and f0101.tif. You can use additional commands to manipulate these files, as cp to copy them or rm to remove (delete) them. Chapter 6 and Chapter 7 (“Managing Files”) describe some common file-manipulation commands.

Some text-mode programs take over the display to provide constant updates or to enable you to interact with data in a flexible manner. ## Comparing Linux to Unix

If you attempt to draw a "family tree" of OSs, you would end scratching your head at. This is because OS designers often mimic each other's features, and sometimes incorporate each other's ideas into their OS's workings. The result can be a tangled mess of similarities between OSs, with cases ranging from coincidence to code "borrowing." Attempting to map these influences can be difficult. In case of Linux and Unix, though a broad statement is possible: Linux is modeled after Unix.

Unix was created in 1969 at AT&T's Bell Labs. Unix's history is complex and involves multiple forks (that is, splitting of the code into two or more independent projects) and entirely separate code rewrites. Modern Linux systems are, by large, the type of open source projects that clone Unix, or of original open source projects for Unix generally. These projects include the following:

- **The Linux Kernel**: Linus Torvalds created the Linux kernel as a hobby project in 1991, but it soon grew to be much more than that. The Linux kernel was designed to be compatible with other kernels, in the sense that it used the same software interfaces in source code. This made using open source programs for Unix versions them easy.
- **The GNU Project**: GNU's Not Unix (GNU) project is an effort by the Free Software Foundation (FSF) to develop open source replacements for all the core elements of an OS. In 1991, the FSF had already released the most important of such tools, with the notable exception of the kernel. The GNU HURD kernel is now available, but is not as popular as the Linux kernel.

## Where Does Linux Fit in the OS World?

Alternatives to the GNU tools include proprietary commercial tools and open source tools developed for the Berkeley Software Distribution (BSD) Unix variants. The tools used on a Unix-like OS can influence its overall “flavor,” but all of these tool sets are enough to give any Unix variety a similar feel when compared to a non-Unix OS.

**Xorg-X11**: The Window System is the GUI environment for most Unix OSs. Most Linux distributions today use the Xorg-X11 variety of X. As with the basic text-mode tools provided by the GNU, choice of an server can affect some features of a Unix-like OS, such as the types of fonts it supports.

**Desktop Environments**: GNOME, KDE, Xfce, and other popular source desktop environments have largely displaced commercial desktop environments. Thus you won't find differences between Linux and Unix in this area.

**Server Programs**: Historically, Unix and Linux have been popular as servers—organizations use them to run web servers, email servers, file servers, and so on. Linux runs the same server programs as do commercial Unix versions and the open source BSDs.
