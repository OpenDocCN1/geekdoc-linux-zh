
# Setting Ownership in a File Manager

As described in Chapter 4, “Using Common Linux Programs,” a file manager enables you to manipulate files. You're probably familiar with file managers in Windows or Mac OS X. Linux's ownership and permissions are different from those of Windows, though, you may want to know how to check on, and perhaps change, ownership features by using a Linux file manager. As noted in Chapter 4, you have a choice of several file managers in Linux. Most are similar in broad strokes but differ in some details. In this section, we use Nautilus, the default file manager used in the GNOME desktop, as example.

If you want to change the file's owner, you must run Nautilus, but you can change the file's group to any group to which you belong as an ordinary user. The procedure to perform this task as root is as follows:

1. Launch a terminal window.
2. In the terminal window, type `su` to acquire root privileges.
3. In the terminal window, type `nautilus` to launch Nautilus. You can optionally include the path to the directory in which you want Nautilus to start. If you don't include a path, Nautilus will begin by displaying the contents of the /root directory.
4. Locate the file ownership you want to adjust and right-click it.
5. In the resulting menu, select Properties. The result is a Properties dialog box.
6. Click the Permissions tab in the Properties dialog box. The result represents Figure 14-1.
7. To change the file's owner, select a new owner in the Owner field. This action is possible only if you run Nautilus as root.
8. To change the file's group, select a new group in the Group field. If you run Nautilus as an ordinary user, you will be able to select any group to which you belong, but if you run Nautilus as root, you will be able to select any group.
9. When you've adjusted the features that you want to change, click Close.

You should be extremely cautious about running Nautilus as root. If you forget that you're running this program as root, you can easily create new files as root, which will require additional root-privilege actions to correct by changing file ownership. It's also easy to delete critical system files accidentally as root, which you could not delete as an ordinary user. For these reasons, we recommend that you use a text-model shell to adjust file ownership. The change in the prompt makes it easier to notice that you're running as root, and if you're used to use a GUI, you're less likely to launch additional programs as root from a text-mode shell than from Nautilus.

# Setting Ownership in a Shell

The command to change the ownership of a file in the preferred text-mode manner is `chown`. In its most basic form, you pass the name of a file followed by a username:

The chown command stands for change owner.

```
# chown bob targetfile.edf
```

# Setting Permissions

This example gives ownership of targetfile.edf to bob. You can change the file's principal owner and its group with a single command by separating the owner and group with a colon (:):

```
$ chown bob:users targetfile.edf
```

This example gives ownership of targetfile.edf to bob and associates the file with the users group. To change the group without changing the owner, you can omit the owner, leaving the colon and group name:

```
$ chown :users targetfile.edf
```

Alternatively, you can use the `chgrp` command, which works in the same way but changes only the group and does not require the colon before the group name:

```
$ chgrp targetfile.edf
```

Note that the commands used to change the group as an ordinary user—but only if you own the file and belong to the target group.
The chown and chgrp commands both support a number of options that modify what they do. The most useful of these is -R (or --recursive), which causes a change in ownership of all the files in an existing directory. For instance, suppose that the user has left a company, and an existing employee, bob, must access her files. If mary's home directory is /home/mary, you might type this:

```
$ chown -R bob /home/mary
```

This command gives bob ownership of the /home/mary directory, all the files in the /home/mary directory, including all its subdirectories, the files in the directories, and so on. To make the transition a bit easier.

# Understanding Permissions

Understanding Linux permissions, you may begin with the `ls -l` command. This command provides detailed information:

```
-rw-r--r-- 1 bob users 512 Oct 25 10:00 test
```

This line consists of several sections:

- **Permissions**: The first ten characters (-rw-r--r--) show the permissions. The first character indicates the file type (-), and the next three sets of three characters represent permissions for the owner, group, and others, respectively.
- **Number of Links**: The next column (1) shows the number of hard links to the file.
- **Username**: The next column (bob) identifies the owner of the file.
- **Group Name**: The next column (users) identifies the group associated with the file.
- **File Size**: The next column (512) shows the size of the file in bytes.
- **Time Stamp**: The next column (Oct 25 10:00) identifies the time the file was last modified.
- **Filename**: Finally, the last column (test) shows the name of the file.

**File Type Code**: The first character indicates the file type, as summarized in Table 14.1. This type character is sometimes omitted from descriptions when the file type is not relevant or when it's identified in some other way.

# TABLE 14.1 Linux file type codes

| Code | Name | Meaning |
| :--- | :--- | :--- |
| - | Normal data file | May be text, an executable program, graphics, compressed data, or just any other type of data. |
| d | Directory | Disk devices are files, but they contain filenames and pointers to named files' data structures. |
| l | Symbolic link | The file contains the name of another file or directory. When Linux accesses the symbolic link, it tries to read the linked-to file. |
| p | Named pipe | A pipe enables running two Linux programs to communicate with each other in a one-way fashion. |
| s | Socket | A socket is similar to a named pipe, but it permits network and bidirectional links. |
| b | Block device | A file that corresponds to a hardware device and from which data is transferred in blocks of more than 1 byte. Disk devices (hard disks, USB flash drives, CD-ROMs, and so on) are common block devices. |
| c | Character device | A file that corresponds to a hardware device and from which data is transferred in units of 1 byte. Examples include parallel and RS-232 serial port devices. |
