
# Understanding Disk Issues

The most common partitioning scheme for .x86 and .x86-64 computers has gone by various names over the years, including master boot record (MBR), MS-DOS, and BIOS partitioning. It supports three types of partitions:

- **Primary** This is the simplest type of partition. A disk can have zero to four primary partitions, one of which may be an extended partition.

- **Extended** This is a special type of primary partition that serves as a holder for logical partitions. A disk may have at most one extended partition.

- **Logical** These partitions are contained within an extended partition. In the theory, a disk can have billions of logical partitions, thus overcoming the limit of four primary partitions, but in practice you're unlikely to see more than a dozen of them.

MBR's use of three partition types is awkward and limiting, but inertia has kept it in place for decades. MBR partitions have a hard limit, though they can't support disks larger than 2 terabytes (TiB), assuming 512-byte sectors, which are nearly universal today.

The Globally Unique Identifier (GUID) Partition Table (GPT) is the successor to MBR. GPT supports disks up to 8 zebibytes (ZiB), which is about 4 billion times large as MBR's. GPT also supports up to 128 partitions by default, with no distinction between primary, extended, and logical partitions. GPT is a superior partitioning system to MBR; however, its support varies between OSs. Linux supports both systems well. Windows can boot only from MBR when the computer uses the Basic Input/Output System (BIOS), and it can boot only from GPT when the computer is based on the Unified Extensible Firmware Interface (UEFI). Thus, if you dual-boot with Windows, you may need to select your partitioning scheme with care.

# MULTIBYTE UNITS

It is common to use prefixes from the International System of Units (SI units)—kilo (k), mega (M), giga (G), tera (T), and so on—in conjunction with byte (B) to refer to large quantities of storage space, as in KB, MB, GB, TB, and so on. Technically, these units are defined as base-10—kilo means 1000; mega means 1,000,000; and so on. In computers, though, base-2 values, such as $2^{10}$ (1,024) and $2^{20}$ (1,048,576), are even more natural, so the SI units often have (but not always) been used to mean these base-2 values. This practice has led to confusion, since it's not always clear whether base-10 or base-2 units are used.

# MULTIBYTE UNITS (Continued)

To resolve this conflict, the Institute of Electrical and Electronics Engineers (IEEE) defined a new set of prefixes as IEEE-1541. Under this system, new units and prefixes describe base-2 values. The first few of these are as follows:

- A kibibyte (KiB) is $2^{10}$ (1,024) bytes.
- A mebibyte (MiB) is $2^{20}$ (1,048,576) bytes.
- A gibibyte (GiB) is $2^{30}$ (1,073,741,824) bytes.
- A tebibyte (TiB) is $2^{40}$ (1,099,511,627,776) bytes.

In this book, we use IEEE-1541 units which have features that are expressed in this system, such as partition size limits. Most Linux utilities use SI and IEEE-1541 correctly, but which is depends on the whim of the program's authors. Be alert to this difference, particularly when dealing with large numbers—note that a tebibyte is almost 10 percent larger than a terabyte!

Other partitioning systems exist, but you're unlikely to encounter most of them. One possible exception is the Apple Partition Map (APM), which Apple used on its Macintosh computers prior to its switch to Intel CPUs.

When it comes to partitioning a disk, Linux supports three families of tools:

- **disk Family**: The fdisk, cgdisk, and sfdisk tools are simple, text-based partitioning utilities for MBR disks and some work and provide the means to recover from some disk errors, but their text-based nature can be intimidating to those who are unfamiliar with disk partitioning.

- **libparted-Based Tools**: Tools based on the libparted library can handle MBR, GPT, and other partition table types. Some of these tools, such as GNU Parted, are text based, but others, such as GParted, are GUI based and so are likely to be easier for new users to use. Figure 5.2 shows GParted in action. Note how its display mirrors the structure. Many Linux installers include libparted-based partitioning tools that run during system installation.

- **gpt Family**: The gdisk, cgdisk, and sgdisk tools are modeled after the fdisk family but work with GPT disks. They provide more options for handling GPT than do libparted-based tools, but at the cost of friendliness for new users.

If you're working with a preinstalled Linux system, you may not need to partition your disk. However, if you replace or install a new hard disk, you'll have to partition it before you can use it. You may also need to partition disks, although they generally come prepartitioned from the factory with one big partition.

To partition a disk, you must know the disk's device filename. In Linux, these filenames are normally /dev/sda, /dev/sdb, and so on, with each disk taking on a new letter. Partitions are numbered starting with 1, so you might refer to /dev/sda2, /dev/sdb6, and so on. When using MBR, partitions 1 through 4 are reserved for primary or extended partitions, whereas logical partitions number 5 and up.

- **ext2fs**: The Second Extended Filesystem (ext2fs) was used in the early 1990s, it it was quickly eclipsed by ext2fs. is is no longer supported.
- **ext3fs**: The Third Extended Filesystem (ext3fs) is essentially ext2fs with a journal. Until around 2010, it was a popular filesystem, but ext4fs has taken its place.
- **ext4fs**: The Fourth Extended Filesystem (ext4fs) is a further development of the filesystem line. It adds speed improvements and the ability to handle larger files and disks—files may be up to 16 TiB in size.
- **ReiserFS**: This filesystem, referred to as reiserfs by Linux tools, is similar to ext3fs in features, with an 8 TiB file-size limit and 16 TiB filesystem limit.it best feature is to make efficient use of disk space with small files—those sizes measured in the low kibyte range.
- **JFS**: IBM developed its Journaled Filesystem (JFS) for its AI OS, and its code ever worked its way into Linux. JFS supports maximum file and filesystem of 4 PiB and 32 PiB, (1 TiB is 1,024 TiB). JFS is not as popular as many other Linux filesystems.
- **XFS**: Silicon Graphics developed the Extended Filesystem (XFS) for its IRIX os and donated its code to Linux. XFS supports files up to 8 EiB and filesystems up to 16 EiB, making it the choice for very big disk arrays. XFS works with large multimedia and backup files.
- **Btrfs**: This filesystem (pronounced "butter-eff-eff" or "better-eff-eff") is ended as the next-generation Linux filesystem. It supports files up to 16 EiB and filesystems of the same size. It also provides a host of advanced features, such as the ability to combine multiple physical disks into a single filesystem. Linux distributions recently made Btrfs the default filesystem in installations, and its popularity is growing.
- **extfs**: The Original Extended Filesystem (extfs) was used in the early 1990s, it it was quickly eclipsed by ext2fs. is is no longer supported.
