# Finding Breaks in Connectivity

A step after ping is the traceroute command, which sends a series of test packets to each computer between your system and a specified target system. Listing 15.3 shows a sample of traceroute output

Listing 15.3: A sample traceroute output

```
$ traceroute -n 10.1.0.43
tracoute to 10.1.0.43 (10.1.0.43), 30 hops max, 52 byte packets
1 192.168.1.2 1.021 ms 36.519 ms 0.971 ms
2 10.10.88.1 17.250 ms 9.959 ms 9.637 ms
3 10.9.8.173 8.799 ms 19.501 ms 10.884 ms
4 10.9.8.133 21.059 ms 9.231 ms 103.068 ms
5 10.9.14.9 8.554 ms 12.982 ms 10.029 ms
6 10.1.0.44 10.273 ms 9.987 ms 11.215 ms
7 10.1.0.43 16.360 ms * 8.102 ms
```

The -n option to this command tells it to display target computers' IP addresses rather than their hostnames. This can speed up the process bit, particularly if you're having DNS problems, and it can sometimes make the output easier to read—but you may want to know the hostnames of problem systems because they can help you pinpoint who's responsible for a problem.
The output of traceroute be diagnostic in several ways:

- * Typically, times increase with increasing hop numbers. This is normal, and from some variability in the example output, you can see this pattern in Listing 15.3.

- * Variable times on a single hop can indicate that a router is overloaded or that some intermittent issue is causing variability in the times. You can see this factor in several hops in Listing 15.3, and particularly in hops 1 and 4. Such issues may result in variable performance but should not cause network sessions to time out or fail completely.

- * Some response to a packet is never received. This condition is indicated by an asterisk (*) in a time field, in the second packet for hop 7 in Listing 15.3.

- * A dramatic jump in times can indicate a great physical distance between routers. Ignoring the middle time of 36.519 ms in the first hop of Listing 15.3, you can see a jump in the change from hop 1 to 2. In the case of Listing 15.3, this indicates the link from the local network to the Internet service provider's network. Even bigger jumps in time are common on intercontinental links. Such jumps are not necessarily signs of misconfiguration that needs to be fixed, but they can influence network performance, particularly for highly interactive protocols such as remote login tools or network-enabled gaming.

Among other things, traceroute is helpful in determining whether a problem in network connectivity exists in a network for you're responsible. For instance, the variability in the first hop of Listing 15.3 could indicate a problem on the local network, but the last packet associated with the final destination most likely is not a local problem. If the trouble link is within your jurisdiction, you can check the status of the problem system, nearby systems, and the network segment in general.

> Some routers block traceroute data. If your tracer output contains nothing but asterisks past a certain point, you may have run into such a system.

# Testing DNS

DNS problems can cause networking to fail almost as badly as can a physically cut cable. Because both people and many network tools rely on hostnames, if DNS resolution doesn't work, the network becomes nearly useless.

You can test your DNS server using a number of tools, such as host, dig, and nslookup. These tools are similar in many ways, and they all enable you to look up a hostname by typing the command followed by a hostname:

```
$ host www.sybex.com
www.sybex.com address 208.215.179.228
```

This example shows normal resolution. In this case, the hostname links directly to one IP address. In some cases, you may find notices about aliases or multiple IP addresses. This is also normal, for some sites. If the command takes a long time to respond or complains about a time-out or an inability to reach servers, it means that your DNS configuration is wrong.

You can add the IP address of a specific DNS server, as in http://www.whitehouse.gov/192.168.39.7 to test the 192.168.39.7 server. If your computer is configured in this way you can test each individually. Perhaps one is unreliable or incorrect, in which case you might want to remove it from your configuration. Be aware, though, that you remove a DNS server from /etc/resolv.conf on a computer configured via DHCP, the change will eventually be undone by DHCP. This is a recurring problem, you should probably consult your network administrator.

Although host, dig (or the deprecated nslookup) can perform more complex queries and return more information about a hostname, domain, or IP address. This makes dig a useful tool for advanced network diagnostics, but at the cost of ease of use; that, it's harder for a novice to interpret dig's output.

# Checking Your Network Status

Another useful diagnostic tool is netstat. This is something of a Swiss army of network tools because it can be used in place of several others, depending on the parameters passed to it. It can also return information that's not easily obtained in other ways. Some examples include the following:

- Interface Information Pass netstat --interface or -i parameter to obtain information about your network interfaces similar to what ifconfig returns. (Some versions of netstat return information in the same format, but others lay out information differently.)

- Routing Information You can use the--route or -r parameter to obtain a routing table listing similar to what the route command displays.

- Masquerade Information Pass netstat --masquerade or -M parameter to obtain information about connections mediated by Linux's Network Address Translation (NAT) features, which often go by the name IP masquerading. NAT enables a Linux router to "hide" behind a single IP address. This can be a good way to stretch limited IPv4 addresses.

- Program Use Some versions of netstat support theprogram (-p) parameter, which attempts to provide information about the programs that are using network connections. This isn't always successful, but often it is, so you can see what programs are making outside connections.

- Open Ports When used with various parameters, or without any parameters at all, netstat returns information about open ports and the systems to they connect.

- All Connections The--all or -a option is used in conjunction with others. It causes netstat to display information about the ports that server programs open to listen for network connections, in addition to already-open connections.

Keep in mind that netstat is a powerful tool, and its options and output aren't entirely consistent from one distribution to another. You may want to peruse its man page and experiment with netstat to learn what it can do.

# Protecting Your System from the Bad Guys

Networks provide many useful features for their users. Unfortunately, they also provide risks. Network security is a complex topic, and we can provide only a few basic tips to help prevent your system from being compromised. Here are some of the most important things you can do:

- Shut Down Unused Servers Linux's major security vulnerabilities aren't in worms and viruses, as they are with Windows; in Linux, the risks center on outsiders breaking into your computer by abusing server programs that you run.
