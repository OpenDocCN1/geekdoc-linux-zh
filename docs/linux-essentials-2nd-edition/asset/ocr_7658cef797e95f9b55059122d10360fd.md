Given the number of ps options, users can have different ways to use the program, typing ps usually produces the desired information, including PID values and command names (including command-line options) for all processes on the computer. Adding u (as ps ax) adds usernames, CPU loads, and a few other tidbits. The sheer scope of the information produced, can be overwhelming. One way to narrow this scope is to pipe the results through grep, which eliminates lines that do not include the search criterion you specify. For instance, if you want to find the PID number for the get process, you can do this by:

```
$ ps ax | grep
27946 pts/8      Sl      0:00 edit
27950 pts/8      S+      0:00 grep-colour=auto grep
```

This command reveals that grep it has a PID value of 27946. This is usually the most important information when you use ps, since you'll use the PID value to change a process's priority or terminate it.

# Using to Identify Processes

Although ps can return process priority and CPU use information, the program's output is usually sorted by PID number, and it provides information at only a single moment in time. If you want to locate CPU- memory-hogging processes quickly, or if you want to study resource use over time, top is a more appropriate tool. This program ver 9.4 shows top running in a GNOME Terminal window.

By default, top sorts entries by CPU use, and it updates every few seconds. You'll need to be familiar with the purposes and normal habits of programs running on your system in order to determine if a CPU-hungry application is misbehaving; the legitimate needs of different programs vary so much that it's impossible to give a simple rule for judging when a process is consuming too much CPU.
