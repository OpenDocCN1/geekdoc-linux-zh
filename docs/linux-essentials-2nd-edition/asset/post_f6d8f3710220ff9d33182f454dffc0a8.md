## Saving Your Changes from nano

Once you've made changes to a text file, of course, you probably want to save them. One way to do this is with the Ctrl+O option. (That's the letter O, not the number 0.) When you press this key, nano asks you following:

Write Selection to File:

Ordinarily, the prompt will include the file's original name, so you can press the Enter key to save the file using nano. If you want to use a different name, you can delete the old one and type a new name. If you launched nano without specifying a filename, you can type nano at this prompt.

Another way to save the file is to press Ctrl+X. This command exits from nano, but if you've modified the file, it produces the following:

Save modified buffer (ANSWERING "NO" WILL DESTROY CHANGES) ?

Type y at this prompt to save the file. The program shows you the filename that you've seen if you've pressed Ctrl+O, so you can change the filename. Once nano saves the file, it terminates.

If you were following along your system, creating and editing the pets.txt file earlier in this chapter, here are the steps you need to follow to save your changes and exit the nano text editor:

- 1. Assuming you are still in the nano text editor with the pets.txt file displayed, press Ctrl+O to start the process of saving the file.
- 2. The status bar shows the words File Name to Write: pets.txt. Press Enter to save the file. You should see similar writing 6 lines on the status bar.
- 3. Press Ctrl+X to exit the nano text editor and return to the command-line prompt.

## Editing Files with vi

vi was the first full-screen text editor written for Unix. It was designed to be small enough to fit on the old-fashioned, tiny, floppy-based emergency boot sys-. When the GNU Project developed an open source replacement for the vi editor, they added several improvements to it and called it “vi improved,” or vim. Though many Linux distributions ship with vim, it is still referred to as vi editor, vim is upward compatible with the vi editor, and the command launch vim is typically vi—though some distributions have a vi command instead. The information presented in this chapter applies to both vi and vim.

Although the vi editor is useful for editing configuration files, it really shines in editing program files, such as shell scripts. Thus you will benefit from learning the vi editor, though it is considered by many to be the most complicated text editor to.

## Understanding vi Modes

To use vi, you should first understand the modes in which it operates. Then you begin to learn the text-editing procedures that vi implements. With any moment, vi is running in one of three modes:

**Command Mode** This mode accepts commands, which are usually entered as single letters. For instance, i and a enter insert mode, although in somewhat different ways, as described shortly, and o opens a line below the current one.

**Ex Mode** To manipulate files (including saving your current file and run- outside programs), you use ex mode. You enter ex mode by typing colon (:) followed by the command. After you run the ex command, vi returns to command mode.

**Insert Mode** You enter text in insert mode. Most keystrokes result in text appearing on the screen. One important exception is the Esc key, which exits insert mode and returns to command mode. Unfortunately, terminology surrounding vi modes is inconsistent as that. For instance, command mode is sometimes referred to as normal mode, and insert mode is sometimes called edit mode. Ex mode isn't described as a mode at all, but is referred to as colon commands.

## CHECKING vi/vim PACKAGE

Your Linux system may not have the full vi editor installed by default. For example, your distribution may only come with vim.tiny or vim.minimal installed. With these packages, you can still access a form of the vi editor, though you may not have full access to features described in this chapter. If you wish to learn and properly use the vi editor, it is recommended that you have the full vim installed.

To check your system, enter type vi at the command line. You should receive the pro-name (vi or vim), including its directory location, similar to what is shown here:

```
$ type vi
vi is hashed (/usr/bin/vi)
```

Once you have the program name and its location, type readlink -f /location/program to determine whether the program is linked to another program. (Linked files are covered in Chapter 7, "Managing Files.") You may receive something similar to the following:

```
$ readlink -f /usr/bin/vi
/usr/bin/vim.tiny
```

Next, you will need to check the software package that provided the program. (In some cases, the program name does not indicate which software package provided it.) Use the appropriate software package tool to determine this required information. The example here is on an Ubuntu distribution, so the dpkg -S command is used along with super privileges (obtaining superuser privileges is covered in more detail in Chapter 12.)

```
$ sudo dpkg -S /usr/bin/vim.tiny
[sudo] password for christine:
vim.tiny: /usr/bin/vim.tiny
```

You can see that in case the vim.tiny package is installed. If you find that the vim or vim.basic package is installed, you should have no problems using the vi editor commands in this chapter. However, if you do not either of these packages installed, as in the preceding example, you'll want to install the package in order to follow along with the rest of this chapter. For the preceding example on the Ubuntu distribution, you would enter apt-get install vim to install the full vim package. (Installing packages is covered in Chapter 9.)
