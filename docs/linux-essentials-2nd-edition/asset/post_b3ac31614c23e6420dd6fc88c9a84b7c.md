
## Using cut

When extracting data, grep is helpful in pulling out entire file lines (sometimes called a *record*). Sometimes, though, you only need parts of a file record. The cut command can help in this case. It extracts text from fields in a file record. It's frequently used to extract variable information from a file whose contents are highly patterned.

To use cut, you pass to one or more options that specify what you want, followed by one or more filenames. For instance, users' home directories appear in the sixth colon-delimited field of the /etc/passwd file. Therefore, to extract only the directory name, use this command:

```bash
$ cut -f 6 -d ":" /etc/passwd
```

Table 8.4 shows the options that you're most likely to need with the cut command. Consult its man page for additional options and a complete description of the cut command.

## TABLE 8.4 Common cut options

| --- | --- | --- |

| --delimiter | -d | Uses designated delimiter as field instead of the default (Tab). |
| --fields | -f | Selects only designated fields. |
| --only-delimited | -s | Lines without a delimiter are not printed (default is to print them when the -f option is used). |

You can capture the cut command's results into a file by using redirection. Redirection is covered later in this chapter, in the “Redirecting Input and Output” section.

## Using sort

When dealing with a large amount of data, being able to sort it is often useful. The sort command does just that. However, you need to be aware of its features in order to achieve the desired results.

$ cat pets.txt

Like the cut command, when using sort, no changes are made to the file's data. Only the output is sorted.

## Redirecting Input and Output

If you want to save a program’s output for future reference, you can redirect it to a file. You can also redirect the input to a program from a file. Although input redirection may sound strange, some programs rely on this feature to enable them to process data, such as raw text files fed through a program that searches the text for patterns. In addition to redirecting output to files or from files, you can pass one program’s output to another as its input. A related technique involves the xargs command, which enables you to generate command options from files or other programs’ output.

## Using Basic Redirection Operators

Redirection is achieved with the help of redirection operators, which are short strings that appear after the command and its arguments. Table 8.6 shows the most common operators. Be aware that output comes in two types:

Standard Output This is for normal program messages.

Standard Error This contains error messages.

| Redirection operator | Effect |
| --- | --- |
| > | Creates a new file containing standard output. If the specified file exists, it’s overwritten. |
| >> | Appends standard output to the existing file. If the specified file does not exist, it’s created. |
| 2> | Creates a new file containing standard error. If the specified file exists, it’s overwritten. |

As an example of redirecting output, a grep command to search for information on a particular user in all of the files in /etc. Without redirection, a command might look like this:

```bash
# grep /etc/*
```

Assuming that superuser privileges are used, this command will return a series of output lines like:

```
Binary file /etc/aliases.db
/etc/group:wheel:x:root,david
/etc/group:audio:x:david,pulse
/etc/group:cdrom:x:daemon,david
```

Such output can be quite lengthy, and you might want to peruse it later. To do so, you could redirect the output to a file, like this:

```bash
# grep /etc/* > david-in-etc.txt
```

Using the > redirection operator takes the output from the grep command and puts it into a file called david-in-etc.txt. If you wanted to see the output, you could use less:

```bash
less david-in-etc.txt
Binary file /etc/aliases.db
/etc/group:wheel:x:root,david
```

Be careful when using the > redirection operator: if the file already exists, this operator will overwrite the file's contents.

## Redirecting Input and Output

In this example, you haven't gained anything compared to typing grep /etc/*, but you might have in other cases. For instance, suppose a command is producing several error messages. You might redirect standard error to a file and search for strings that might be relevant, and so on, even as you attempt to run the command, or a modified version of it, once more.

This next example illustrates how standard error and output are separate. If you type grep /etc/* as a normal user (perhaps substituting your own username for david), you're likely to see output as shown earlier, specifying the files in which your username appears; however, you are likely to see error messages, since you lack permission to read some of the files in /etc.

```bash
grep: /etc/security: Permission denied
grep: /etc/shadow: Permission denied
```

The information on the files in which david appears is shown via standard output, the errors are shown via standard error. If you're not interested in the errors, you can redirect them to /dev/null—a device file that serves as a trash for data you want to discard:

```bash
$ grep /etc/* 2> /dev/null
```

Likewise, if you redirect output to a file but not redirect standard error, you'll see the error messages on your screen. However, the file you create (such as david-in-etc.txt from the earlier command) will not contain the error messages. You might want to try all of the different types of output redirecting by using grep /etc/* (substituting your own username for david) to get a feel for how they work.

Most programs have options, on the command line or in configuration files, that affect the wording of their output. Check the program's page to learn about such options.

The only difference between redirecting standard output using the > operator and redirecting standard error is the number 2. This is because the number 2 represents standard error at the command line.

## Using Pipes

Another type of redirected output is a command-line pipe or pipeline. In a pipe, the standard output from one program is redirected as the standard input to a second program. You create a pipe using a vertical bar (|) between the two commands; this key is usually above the Enter key and accessed with Shift. Pipelines can be useful when applied in various ways. For instance, you might pipe the lengthy output of a program through the less pager, which enables you to page up and down through the output. In this Chapter 6 describes the Less pager.
