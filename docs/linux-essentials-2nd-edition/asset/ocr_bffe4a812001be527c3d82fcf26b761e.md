# Chapter 13 - Creating Users and Groups

# TABLE 13.3: Options for groupadd

| Option name | Option abbreviation | Effect |
|---|---|---|
| --gid *GID* | -g | You can provide a specific GID with this parameter. If you omit it, groupadd uses the next available GID. |
| --non-unique | -o | Normally, the GID that you specify be unused by other groups, but the -o parameter overrides this behavior, enabling you to create multiple groups that share one GID. |
| --system | -r | This parameter instructs groupadd to create a system group, which is one with a GID of less than 500 or 1,000, depending on the distribution. Nonsystem groups are normally used as user private groups. |
| --force | -f | Normally, if you try to create a group that already exists, groupadd returns an error message. This parameter suppresses that error message. |

Using the groupadd command, including setting an option, looks like this:
# groupadd -g 1001 consultants

This example creates a group with a GID of 1001 and a group name of consultants. Notice in the preceding example that the # prompt, indicating that the root account was used to obtain the superuser privileges required.

Once the group is added, new members can be added to the group. The use of the usermod command, as follows:

```
# usermod -ag consultants rich
# groups rich
```

rich: users consultants
The -ag options were used together to add the account, to the new consultants group. If the -a option was not used, the account would be removed from its current group memberships and belong only to the consultants group. A good habit is to check if the modification was successful by using the groups command. The groups command shows all of the group memberships for the specified user account.

To modify the group, you can use the groupmod command. The --gid(-g) and --non-unique (-o) options from Table 13.3 can be used with this command, as well as --new-name(-n name), which changes the group's name.
