Linux filesystems exist, each with its own unique features:

ext2fs The Second Extended Filesystem (ext2fs) was popular in the 1990s, but
it is rarely used today because it lacks a journal, which is a filesystem feature
 speeds up filesystem checks after power outages or system crashes. A journal
consum disk space, though so ext2fs is still useful on small disks. You might
want to use it for a separate /boot partition, for instance, such partitions
are smaller. Its Linux filesystem type code is ext2.

ext3fs The Third Extended Filesystem (ext3fs) is essentially ext2fs with a jour-
al. Until around 2010, it was a popular filesystem, but ext4fs has taken its place.
it It supports files up to 2 TiB and filesystems up to 16 TiB (ext2fs imposes
the same limits). Its Linux type code is ext3.

the filesystem line. It adds speed improvements and the ability to handle

JFS IBM developed its Journaled Filesystem (JFS) for its AI OS, and its code

as many other Linux filesystems. Linux tools use jfs as its type code.

XFS Silicon Graphics developed the Extended Filesystem (XFS) for its IRIX
os and donated its code to Linux. XFS supports files of up to 8 EiB and
filesystems up to 16 EiB, making it the choice for very big disk arrays.
XFS works with large multimedia and backup files. Its Linux type code
is xfs.

Btrfs This filesystem (pronounced "butter-eff-eff" or "better-eff-eff") is
ended as the next-generation Linux filesystem. It supports files up to 16
EiB and filesystems of the same size. It also provides a host of advanced features,
such as the ability to combine multiple physical disks into a single filesystem.
