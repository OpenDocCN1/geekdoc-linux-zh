Unix's history, in turn, stretched back two more decades, to its origin at AT&T

software development to start. Most Unix programs were distributed as source
code, because Unix ran on a wide variety of hardware platforms—binary pro-
grades for one machine would seldom run on a different machine.

Early on, Linux began to tap into this reservoir of available software. As noted
in Chapter 1, Linux developers were particularly keen on the GNU project's
software, so Linux accumulated a collection of GNU utilities. Much of
this software had been written with workstations and more-powerful computers
in mind, but because computer hardware kept improving, run fine on the x86
PCs of the early 1990s.

# The MICROKERNEL DEBATE

Linux is an example of a monolithic kernel, which is a kernel that does everything
a kernel is supposed to do in one process. In 1991, a competing kernel design,
known as a microkernel, was all the rage. Microkernels are much smaller than
monolithic kernels; they move as many tasks as they can into nonkernel processes
and manage the communications between processes.

Soon after Linux's release, Linux Torvalds engaged in a public debate with Andrew
Tanenbaum, the creator of the Minix OS that Torvalds used as an early development
platform for Linux. Unix uses a microkernel design, and Tanenbaum considered
Linux's monolithic design to be backward.

As a practical matter for an end user, either design works. Linux and the BSD-
derived kernels use monolithic designs, whereas modern versions of Windows,
t GNU HURD, and Minix are examples of microkernels. Some people still get
worked up over this distinction, though.
