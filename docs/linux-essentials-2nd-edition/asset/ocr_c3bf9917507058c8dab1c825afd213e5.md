# Chapter 9 - Exploring Processes and Process Data.

Every process has associated with it process ID (PID) number. These numbers begin with 1, so it's PID is normal 1. Each process also has a parent process (PPID) number, which points to its parent. Many of the tools for managing processes rely on these numbers, and particularly on the PID number.

Internally, the kernel maintains process information in the process table. Tools such as ps and top (described shortly) enable you to view and manipulate this table.

# Identifying Processes

Before you can manage processes, you must be able to identify them. In either case, the ps and top utilities help you identify processes. In search for processes in various ways, such as by name or by resource use. You may also identify how much memory your processes are consuming, which you can do with the free command.

# Using ps to Identify Processes

The simplest tool for identifying processes is ps, which produces a process listing. 9.1 shows an example of ps in action. In this example, the -u option restricts output to processes owned by the specified user (rich), while-forest creates a display that shows parent/child relationships.

9.2 shows another example of ps. In this example, the u option adds information columns, while u restricts output to processes owned by rich. The ps command supports a huge number of options (consult its man page for details).

# LISTING 9.2: Output of ps -u u rich

```
$ ps u u rich
USER PID %CPU %MEM VSZ RSS TTY START TIME
COMMAND
```

The version of ps used in most distributions combines features from several earlier implementations. The result is a huge selection of (sometimes redundant) options.
