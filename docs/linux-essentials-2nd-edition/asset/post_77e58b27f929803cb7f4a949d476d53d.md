## Managing Red Hat Systems

RPM-based distributions include Red Hat, Fedora, CentOS, SUSE Enterprise, openSUSE, and Mandriva. The basic tool for installing software on these distributions is the text-mode rpm command. This program works on local files, though; to use a network repository, you must use another tool, which varies by distribution:

- Red Hat, Fedora, and CentOS use the text-mode yum or various GUI frontends to it, such as Yumex.
- SUSE Enterprise and openSUSE use zypper or a GUI front-end such as YaST2.
- Mandriva uses the text-mode rpm or the GUI Rpmdrake.

```
# yum yumex
```

You might use this command to install the GUI Yumex on a Red Hat, Fedora, or CentOS system. Similarly, you can remove a specific package by using the remove subcommand or upgrade all of computer's packages by using upgrade:

```
# yum remove zsh
# yum upgrade
```

This example removes the zsh package and then upgrades the remaining packages on the system. Both of these commands will produce a number of lines of output, and you may be asked to verify their actions. Consult the man page for yum (or whatever management software your distribution uses) to learn more about this tool.

If you need to deal with RPM package files directly, you should be aware that they have extensions of .rpm. These files also include codes for architecture type (such as x86_64), and often codes for which they are intended (such as Fedora). For instance, samba-4.1.17-1.x86_64.rpm is a package file for the Samba package, version 4.1.17, release 1, for the x86_64 platform. To install it using the rpm command, you'd use this:

```
# rpm -i samba-4.1.17-1.x86_64.rpm
```

That takes a bit more work than using the yum command, as you need to know the complete filename of the package.

## Managing Debian Systems

The Debian/Linux distribution created its own package system, and distributions based on Debian, such as Ubuntu and Mint, use the same system. Atop the Debian package system lies the Advanced Package Tool (APT), which provides access to network repositories. The dpkg command is the lowest-level interface to the Debian package system; it is roughly equivalent to the rpm utility on RPM-based systems. Just like the rpm utility, to use the dpkg command to know the exact name of the package to install:

```
# dpkg -i samba_3.6.1-3_amd64.deb
```

## Understanding the Process Hierarchy

The Linux kernel is the core of a Linux installation. The kernel manages memory, provides software with a way to access the hard disk, holds CPU time, and performs other critical low-level tasks. The kernel is loaded early in the boot process, and it's the kernel's responsibility for managing every other piece of software on a running Linux computer.

You can change program runs as the first process by adding init= to your boot loader kernel option line, as init=/bin/bash to run bash.

One of the ways that the kernel operates on the potentially chaotic set of running software is to create a sort of hierarchy—normally /sbin/init. When it boots, the kernel runs one program—init. The init process is then responsible for starting all the other basic programs that Linux must run; such programs, if launched directly by login, are called children. The children of init can in turn launch their children. This happens when you log into Linux. The process that launches a given process is called its parent.

Every process has associated with it process ID (PID) number. These numbers begin with 1, so it's normal. Each process also has a parent process (PPID) number, which points to its parent. Many of the tools for managing processes rely on these numbers, and particularly on the PID number. Internally, the kernel maintains process information in the process table. Tools such as ps and top (described shortly) enable you to view and manipulate this table.

## Identifying Processes

Before you can manage processes, you must be able to identify them. In either case, the ps and top utilities help you identify processes. In search for processes in various ways, such as by name or by resource use. You may also identify how much memory your processes are consuming, which you can do with the free command.
