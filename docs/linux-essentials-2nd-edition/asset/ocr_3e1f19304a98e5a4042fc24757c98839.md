# Learning about Your CPU

# CPU Bit DEPTH

CPUs process data in binary (base 2), meaning that numbers are represented using only two digits—0 and 1. CPUs have limits to the sizes of the numbers they can process, and those limits are described in terms of the number of binary digits, or bits, that the CPU can handle. A 32-bit CPU, for instance, can process numbers that contain up to 32 digits. Expressed as positive integers, this means that numbers can range in size from 0 to $2^{32}$—1 (4,294,967,295 in the base 10 that people generally use). When dealing with larger numbers, the CPU must combine two or more numbers, which requires extra code.

With larger bit depths have an advantage when dealing with lots of memory, since a 32-bit CPU has a 4 gibyte (GiB) limit on memory—although architectures, including x86, provide tricks to work around this. Greater bit depth does not improve speed per se, except when dealing with very large numbers. However, the 64-bit x86-64 CPU architecture is faster than the 32-bit predecessor for for unrelated reasons.

In addition to x86 and x86-64 CPUs, several other models are available. With the popularity of mobile devices, the ARM processor has become an overnight success. Technically, ARM chips are all full-featured as the x86-64 or even the x86 CPUs. They implement a type of processor model called Reduced Instruction Set Computing (RISC) architecture, which strips down the process to a bare-bones minimum. However, the ARM chips require less electrical power to operate (making them ideal for mobile devices), and can provide enough computing to handle most of today's consumer needs.

Linux can run not only on the newer processors, but also on older families, such as MIPS and SPARC. However, your choice of distribution is likely to be limited. Because software has to be recompiled and tested on new architectures, preparing a distribution for each architecture takes effort, and many distribution maintainers are unwilling or unable to spend this effort for more than x86 and x86-64.

Many CPUs are multicore. These CPUs package the circuitry for two or more CPUs into one unit. When plugged into a motherboard, such a CPU looks like multiple CPUs programs to the OS. The advantage is that Linux can run as many CPU-intensive programs as you have, and they won't slow down significantly by competing for CPU resources.

Debian is available on many architectures, so if you need to support Linux on a wide range of CPUs, Debian can make sense.

Some high-end motherboards support multiple CPUs, so you can use, two 4-core CPUs to get the performance of an 8-CPU system.
