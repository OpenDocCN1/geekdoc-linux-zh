Nonetheless, sometimes a program consumes too much memory, either because of inefficient coding or because of a memory leak—a type of program bug in which the program requests memory from the kernel and fails to return it when it's done with the memory. A program with a memory leak consumes increasing amounts of memory, sometimes to the point where it interferes with other programs. As a short-term solution, you can usually terminate the program and launch it again, which resets the program's memory consumption, something like draining a sink that's filled with water from a leaky faucet. The problem will recur, but if the memory leak is small enough, you'll at least able to get useful work done in the meantime.

If you want to study the computer's overall memory use, the free command is useful. This program generates a report on the computer's total status:

```
$ free
```

| Mem | used | free | shared | buffers | cached |
|---|---|---|---|---|---|
| | 791488 | 7734456 | 180432 | | 190656 | 3244720 |
|/+ buffers/cache: | 4299080 | 3615808 | | | |
| Swap: | 6291452 | 1030736 | 5266716 | | |

The Mem line reveals total access memory (RAM) statistics, including the total memory in the computer (minus whatever is by the motherboard and kernel), the amount of memory used, and the amount of free memory. This example shows that most of the computer's memory is in use. Such a state is normal, since Linux uses otherwise unused memory as buffers and caches, which helps speed up disk access. The Mem: line isn't the most useful; instead you should examine the +/- buffers/cache: line, which shows the total memory used by the computer's programs. In this example, 2,299,080 KiB of 7,914,888 KiB is in use. In other words, a bit half of the computer's memory is in use by programs, so there should be no memory-related problems.

The Swap line reveals how swap space is used. Swap space is disk space that's set aside as an adjunct to memory. Linux uses swap space when it runs out of RAM, or when it determines that RAM is better used for caches than to hold currently inactive programs. In this example, 1,030,736 KiB of swap is in use, with 6,291,452 KiB total, 5,260,716 free. Swap space use is generally quite low, and if it rises very much, you can suffer performance problems. In the long run, increasing the computer's RAM is generally the best solution to such problems.
