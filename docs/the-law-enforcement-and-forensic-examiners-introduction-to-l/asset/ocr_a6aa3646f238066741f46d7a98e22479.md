On to wiping... We can use a special device, /dev/zero as a source of zeros. This can be used to create empty files and wipe partitions of disks. You can write zeros to an entire disk (or at least to areas accessible to the kernel and user space) using the following command (assuming /dev/sdc is the disk you want to wipe):

```
root@forens1:~# dd if=/dev/zero of=/dev/sdc bs=32k
dd: error writing '/dev/sdj': No space left on device
64945 records in
64944 records out
2128084992 bytes (2.1 GiB, 2.0 GiB) copied, 294.083s, 7.2 MB/s
```

This starts at the beginning of the drive and writes zeros (the input file) to every sector on /dev/sdc (the output file) in 32 kilobyte chunks (bs =block size>). Specifying larger block sizes can speed the writing process (default is 512 bytes). Experiment with different block sizes and see what effect it has on the writing speed (i.e. 32k, 64k, etc.). Be careful of missing blocks at the end of the output if your block size is not a multiple of the device size. The error No space left on device indicates that the device has been filled with zeros. And, course, be sure that the target disk is in fact the disk you intend to wipe. Check and double check.

dc33 makes the wiping process even easier and provides options to wipe with specific patterns. In its simplest form, dc33 can wipe a disk with a simple:

```
root@forens1:~# dc3dd wipe=/dev/sdc
```

How do we verify that our command to write zeros to a whole disk was a success? You could check random sectors with a hex editor, but that's not realistic for a large drive. One of the best methods would be to use the xxd command (command hexdump) with the *autoskip* option. The output of this command on a zero-ed drive would give just three lines. The first line, starting at offset zero in the data area, followed by an asterisk (*) to identify lines, and the last line, with the final offset followed by the remaining zeros in the data area. Here's an example of the command on a zero-ed drive and its output.

```
root@forens1:~# xxd -a /dev/sdj
00000000: 0000 0000 0000 0000 0000 0000 0000 0000
*7ed7fff0: 0000 0000 0000 0000 0000 0000 0000 0000
```
