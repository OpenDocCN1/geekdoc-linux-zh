Back in the earlier section on disks and device nodes, we talked about device detection and naming. In addition to the /dev/sdx naming, there are other names assigned to the disk by UUID, and kernel path. When I see the Win10Image label appear on the desk top, a terminal can quickly be opened to see exactly what partition that disk label belongs to by accessing the /dev/disk/ sub-folders, specifically /dev/disk/by-label:

Using ls -l we see that the file /dev/disk/by-label/Win10Image is a link (much like a shortcut or pointer to another file) to /dev/sdb1.

```
root@forensic1:~# ls -l /dev/disk
total 0
drwxr-xr-x 2 root 146 Apr 16 18:28 by-id/
drwxr-xr-x 2 root 66 Apr 16 18:28 by-label/
drwxr-xr-x 2 root 80 Apr 16 18:28 by-partlabel/
drwxr-xr-x 2 root 80 Apr 16 18:28 by-partuuid/
drwxr-xr-x 2 root 80 Apr 16 18:28 by-path/
drwxr-xr-x 2 root 80 Apr 16 18:28 by-uuid/
```

```
root@forensic1:~# ls -l /dev/disk/by-label/
total 0
lrwxrwxwx 1 root 10 Apr 16 18:28 Win10Image -> ../sdb1
```

If we right click on the icon and select Mount Volume from the menu, the volume is mounted on /run/media/$user/$label. In this case the user is barr and the label is Win10Image. See illustration 3.
