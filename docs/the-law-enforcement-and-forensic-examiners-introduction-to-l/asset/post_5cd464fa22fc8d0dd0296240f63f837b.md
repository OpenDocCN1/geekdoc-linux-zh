three streams we can talk about: stdin is the standard input (usually the keyboard); stdout is the standard output (usually the display); and stderr is standard error (usually the display).

We use specific symbols to redirect these streams:

- stdin: <n
  - cmd < infile
  - cmd is taking its input from infile rather than the keyboard.

- stdout: >
  - cmd > outfile
  - cmd is sending its output to outfile rather than the display.

- stderr: 2>
  - cmd 2> errlog
  - cmd is sending any error messages to the file errlog.

Manipulating streams can be useful for tasks like creating an output file that contains a list of files on a mounted volume, or in a directory. For example:

```
barry@forensic1:-$ ls -al filelist.txt
```

The above command would output a long list of all the files in the current directory. Instead of outputting the list to the console, a new file filelist.txt will be created that contain the list. If the filelist.txt already existed, then it will be overwritten. Use the following command to append the output of the command to the existing file, instead of over-writing it:

```
barry@forensic1:-$ ls -al >> filelist.txt
```

Another useful tool is the command pipe, which uses the | symbol. The command pipe takes the output of one command and "pipes" it straight to the input of another command.

In this case, we are redirecting the output to another command rather than a file. You can see the difference below. I can echo a character string to a file with >, or I can echo to a command with |. The wc command shown below gives a count of lines, words, and bytes. In the first redirect, I'm creating a file named wc with the output of echo. In the second, I'm using a pipe, so the output of echo goes to the command wc. In the third, I am piping the output of echo to wc and redirecting the wc output to a file: Follow below, and experiment. Don't do.

```
bar@forensic1:~$ ps ax | grep bash

1714 pts/1 S 0:00 -bash
1729 pts/1 S+ 0:00 grep bash
```

# File Attributes

Linux file systems (like ext2, ext3, ext4) support what are called file attributes. There are a few of them, and we will not cover all of them. There are two that can be very useful for protecting forensic data from haphazard deletion and tampering. These are append only (a) and immutable (i).

Attributes are flags that control what file operations are allowed to occur on a file directory. Some of them can be changed, and some cannot. We can list the attributes of files and directories in our current directory with lsattr

```
root@forensic1:/MyDirectory# lsattr
------e /data
------e /textfile.txt
------e /file1.txt
------e /log.txt
```

I have a directory, in my /home/$USER directory (specified by ~/$DIRNAME in the prompt). This output shows that all of the available attributes, the files and single directory (data is a directory) all have only the extents attribution (e). We will not cover

> "Extents are a method of mapping physical blocks of data in a contiguous fashion."

We add attributes with the chattr command, simply using a + to add the attribute we want the file name. For example, if I want to make the directory data/ immutable, I can add the i attribute like this:

```
root@forensic1:/~/Directory# chattr +i data/
root@forensic1:/~/Directory# lsattr
------ /data
------ /textfile.txt
------ /file1.txt
------ /log.txt
root@forensic1:/~/Directory# rm -rf data
rm: cannot remove 'data': Operation not permitted
```

We added the immutable (i) attribute to the data directory, and you can see in the subsequent chattr attribute is displayed for ./data. When we try and delete the directory with rm-rf, we find that the operation is not permitted even though we are root. This is very powerful. We cannot delete the directory, nor can we add, or change files in the directory.

We will now add the append only (a) attribute to log.txt. This attribute means that the file can only be opened in append mode. We cannot change or delete current content, nor add to it. We will find this when redirect-ing output to a log file for documenting our work.

```
root@forensic1:/~/Directory# chattr +a log.txt
root@forensic1:/~/Directory# lsattr
------ /data
------ /textfile.txt
------ /file1.txt
------ /log.txt
root@forensic1:/~/Directory# echo "text" > log.txt
-su: log.txt: Operation not permitted
root@forensic1:/~/Directory# echo "text" >> log.txt
```

We change the attribute with chattr, see the change in log.txt with lsattr, and then try and redirect output to overwrite the file (using the single redirect >), which fails. Adding the same output is successful, however (appending is done with a redirect >>, meaning we are adding to the end of the file). # Metacters

The Linux command line (actually the bash shell in our case) also supports wild cards (meta-characters):

- * for multiple characters (including "")
- ? for single characters.
- ] for groups of characters or a range of characters or numbers.

This is a complicated and very powerful subject, and will require further reading... Refer to "regular expressions" in your favorite Linux text, along with "globbing" or "shell expansion". There are important differences that can confuse a beginner, so don't get discouraged by confusion over "*" means in different situations.

# Command Hints

- 1. Linux has a history of previously used commands (stored in the file named .bash_history in your home directory). Use the keyboard arrows to scroll through commands you've already typed.
- 2. Linux supports command line editing. You can use the cursor to navigate a previous command and correct errors.
- 3. Linux commands and filenames are CASE SENSITIVE.
- 4. Learn output redirect to stdout and stderr ("1" and "2"). More on this later.
- 5. Linux uses / for directories, MS Windows uses $.
- 6. Linux uses - for command options, DOS uses /.
- 7. Use q to quit from less or man sessions.
- 8. To execute commands in the current directory (if the current directory is not in your PATH), use the syntax ./command. This tells Linux to look in the present directory for the command. Unless it is explicitly specified, the current directory is NOT part of the normal user path.
