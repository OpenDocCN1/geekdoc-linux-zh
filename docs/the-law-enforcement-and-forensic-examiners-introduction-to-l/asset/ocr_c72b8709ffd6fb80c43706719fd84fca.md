# Writing Blocking

A quick word is made about the issue of write protecting disks and other storage media. In the past, much was made about the ability to mount volumes as “read only” in Linux. This should never be trusted other than to provide the very minimum of accidental changes to a working copy, or when no options exist (always document instances). This guide is about using acquisition policies is somewhat the scope of this document, it bears mentioning that write protection is something that should be kept in mind. Modern computing environments are extremely complex, and there's no way to be completely certain that some underlying kernel mechanism isn't making unknown or unexpected writes to poorly protected evidence drives from previously untested interface or other mechanism.

Where possible, be sure to use physical write blocking. This can be as simple as the physical switch on removable media, or exotic (and expensive) as purpose forensic write blockers. There are methods available for “software” writing blocking (various kernel patches and other scripts), but these should be relied upon only to the capability to physically block writes at the hardware level. We won't be covering kernel patching in this document. We'll briefly cover commands like hdpar are other options that will let you set devices as read only, as with **blockdev**, but again, your mileage may vary on those techniques. Many kernel level hardware settings take place after the kernel has already ready access to target media. Specific changes to udev to prevent prevent such access are outside the scope of this document.
