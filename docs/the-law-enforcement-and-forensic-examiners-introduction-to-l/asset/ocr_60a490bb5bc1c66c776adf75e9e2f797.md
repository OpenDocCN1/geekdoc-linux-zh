You can see from the output that disks and partitions are listed, and if any of the partitions are mounted, lsblk will also give you the current mount point. In this case we /dev/sda1 is mounted on /boot, /dev/sda2 is our swap partition, /dev/sda3 is our root partition, and we /dev/sddi is mounted as /run/media/berry/Evid and /dev/sdjj mounted as /run/media/berry/Kingston. The last two are from external devices, plugged in via the desktop.

Another useful command that we use is lscsi. I prefer it because although it does not show partitions, it gives a better idea of what the values are

root@forensic1:~# lscsi
[1:0:0] disk ATA ST1000DM003-1ER16 CC45 /dev/sda
[2:0:0] cd/vda HD-LT-BD-RE WH16NS40 1.00 /dev/sr0
[11:0:0] disk ATA SAMSUNG MHPV25 500 /dev/sdb
[23:0:0] disk EX5 CF Kingston Reader 055 /dev/vdd
[23:0:1] disk EX5 SD Kingston Reader 055 /dev/sde
[23:0:2] disk EX5 MS Kingston Reader 055 /dev/sdf
[23:0:3] disk EX5 MSD Kingston Reader 055 /dev/sdg
[23:0:4] disk EX5 XD Kingston Reader 055 /dev/sdh

[28:0:1] disk ST1000DM003-1ER16 6207 /dev/sddi
[32:0:0] disk Kingston DataTravel 3.0 PMAP /dev/sdj

You can see in the output above that this system has a number of USB devices and external media attached. This is a useful way of finding out what storage media are attached to a system. You will also notice that there are "disks" identified by lscsi that are not listed by lsblk. This is because lscsi is actually looking what is attached to the interface, not the actual media. lscsi is identifying media readers that have no media inserted. lscsi does not show on most platforms by default (although it does on Slackware).
