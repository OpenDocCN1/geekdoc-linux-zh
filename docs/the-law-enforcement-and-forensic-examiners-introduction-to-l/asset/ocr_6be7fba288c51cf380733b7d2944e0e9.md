# X. Integrating Linux with Your Work

This guide covers a myriad of subjects that really just touch the surface of the command line capabilities of Linux as a forensic platform. And while it is a lengthy guide, it still implies a basic set of commands and utilities to allow you to learn and grow as a forensic examiner or digital investigator. The real power of Linux (as an heir of UNIX itself) is in thinking UNIX. The more you use commands and get used to the output they produce, the more you will learn to string them together, solving increasingly complex issues quickly and efficiently. Getting a solid grasp of command line pipes and redirection is a liberating process.

Some of the repeated exercises we've done here were designed to kick start the repetition to anchor the command line into memory. It is not, however, realistic to expect that everyone will suddenly convert to Linux and forget other operating systems for forensic analysis. Linux is, at the end of the day, just another platform and tool set. I maintain that there is some value in every examiner to last familiar with and the tools it provides. We've talked about how the command line tools we've encountered (and there are *many*) are unique compared to common Windows tools. Much of this difference arises from the fact that they are generally designed with the UNIX approach of "do one thing and do it well". We see this in tools like grep, head, tail, tr, sed and utilities like icat, blkls and catdoc. They provide discrete output when they run on their output, but as you start piping them, you end accomplishing multiple steps in the same command line. This becomes very powerful not only when you learn what each tool is capable of, but when you also start to think in terms of a modular command line. Learning and remembering all this, means less of a burden on examiner resources. And so, one of the strengths of Linux is also, in fact, one of its weaknesses when it comes to mass appeal in the forensic community.

So do we continue to use Linux, maintain what we've learned and continue learning, while remaining efficient? Let's discuss how you can integrate a Linux platform into your lab or examination processes and continue to use it, if not on a daily basis, at least to maintain (and continue growing) the skills we've introduced.

We've seen tools in this guide that can be used to access file data, file system, volume information, and block information, etc. It can be done quickly and without the need for licenses, multiple programs, or extra resources to lead and target wanted information. Being able to accomplish this on full disk image or blocks of separated data (like the unallocated output of blkls, for example) and even individual files, makes Linux an excellent platform for both tool validation and the cross-verification of findings.
