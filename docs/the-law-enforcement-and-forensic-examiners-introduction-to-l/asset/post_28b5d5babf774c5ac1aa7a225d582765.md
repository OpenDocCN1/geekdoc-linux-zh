Looking at the fsstat output on our NTFS file system, we see it differs greatly from the output we saw running on a Linux EXT file. The tool is designed to provide pertinent information based on the file system being targeted. Notice that when run on an NTFS file system, fsstat provides us with information specific to NTFS, including data about the Master File Table (MFT) and specific attribute values.

We will now have a look at how Sleuth Kit interacts with active and deleted files on an NTFS file system. Our first run fls on the root level directory of our image:

Note that fls displays more information for us than normal directory directory listings for NTFS. Included with our regular files and directories are the NTFS file systems (starting with the $), including the $MFT and $MFTMIRROR (record numbers 0 and 1). If you look at the MFT numbers, you'll see that for some reason record number 5 is missing. MFT record is the root directory, which is what we are displaying here. Just as the default display for EXT file systems with fls is inode 2, the default for NTFS MFT record 5.

You can delve deeper into the file system by providing fls with a directory and it will display the contents of directory. For illustration, re-run the command (use the up arrow and edit the previous command) with the MFT record 64 (the Users directory);

You can delve deep into each directory you wish. This is one way to "browse" the file system with fls.

We can also specify that fls only show us only "deleted" content on the command line with the option -d (only file entries) and -r (recursive) as well:

```bash
barry@forensic1:~/NTFS_Path_2017$ fls -o 2048 NTFS_Path_2017.E01 64
/d 65-144-2:
    AlbertE
/d 66-144-2:
    ElsaE
```
