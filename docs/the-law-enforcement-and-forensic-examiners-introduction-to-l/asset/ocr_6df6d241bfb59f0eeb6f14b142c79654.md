Now it's time to find the end of the file.

Since we already know where the JPEG starts, we will start our search for the end of
t file from that point. Using again xxd and grep we search for the footer value ffd9
somewhere after the header:

```
barry@forensic1:$ xxd -s 223942 image_carve_2017.raw | grep ffd9
0005d3c6: af 29ae7 06e1 2e48 38a3 ffd9 8303 a138 .j)....H.......8
```

The -s 223942 option specifies where to search (since we know this
front of the JPEG, there's no need to search it and we will eliminate false hits from
region). The output shows the first ffd9 on the line at offset 0005d3c6. Let's convert that
to decimal, noting the uppercase value in our hex:

```
barry@forensic1:$ echo "base=16;5D3C6" | bc
381894
```

Because that is for the start of the file, we need to add 12 to the value to
include the ffd9 (giving us 381906). We do this because the ffd9 needs to be included in our
carve, so we skip past it. Now that we know the start and the end of the file, we can calculate
the size:

```
barry@forensic1:$ echo "381906-223942" | bc
157964
```

We now know the file is 157964 bytes in size, and it starts at byte offset 223942. The
carving is the easy part! We will use dd with three options:

+   skip= how far into the data chunk we begin "cutting"
bs= (block size) the number of bytes we include as a "block"
count= the number of blocks we will be "cutting".

The input file for the dd command is image_carve_2017.raw. Obviously, the value of
skip will be the offset to the start of the JPEG. The easiest way to handle the block size is
specify it as bs=1 (meaning one byte) and setting count to the size of the file. The name
of the output file is arbitrary.
