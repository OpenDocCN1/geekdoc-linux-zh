Let's check the hash of the image parts and compare to the:

```
root@forensic1:~/# cat able_3.00* | shasum
2ddbfe3d00cc736172ec320df88f61afda3502
```

Remember that the cat command streams the files one after the other and sends them through stdout. The shasum command takes the data from the pipe and hashes it. As we mentioned earlier, the - hash output indicates standard input was hashed, not a file. The hashes match and our image is good.

Now suppose we want to mount the images to see the file systems or browse for specific files. One solution would be to use the cat command we did and redirect the output to a new file all of the segments.

```
root@forensic1:~/# cat able_3.0* > able_3.raw
```

```
root@forensic1:~/# ls -lh able_3.raw
-rw-r--r-- 1 bary users 4G May 27 11:28 able_3.raw
```

The problem with this approach is that it takes twice the space as we are essentially duplicating the acquired disk in a single image rather than split. Not efficient for resource management. We need a way to take the split images and create a "whole disk" that we can mount using techniques we already learned. We'll use affuse and the file system provides. All we need to do is call affuse with the name of the first segment of our image and provide a mount point where we can access the virtual disk:

```
root@forensic1:~/# mkdir /mnt/aff
root@forensic1:~/# shasum able_3.000 /mnt/aff
root@forensic1:~/# ls -lh /mnt/aff
total 0
```

In the above session, we create a mount point for our fuse (the name here is arbitrary) with the mkdir command. We use affix with the first segment of our part and mount it to /mnt/aff. This creates our single image for us in /mnt/aff with the name and .raw extension. Finally, we check the hash of this new virtual image and it's the same as the hash for the total disk in our log file. Now we can use gdisk or fdisk on the image to identify the partition layout; we can use parted to manage the partitions for further investigation as we have learned in preceding sessions when working on complete images:

```
root@forensic1:/able# fdisk -l /mnt/aff/able_3.000.raw
```

So without having to reassemble the split images to a single image, we were able to map the partitions and identify the file systems ready for mounting.

```
root@forensic1:/able3# mount -o ro -t ext4 /dev/mapper/loop0p /mnt/analysis/
```

When we have finished with the affuse mount point, we remove it with the fusermount -u command. This removes our virtual disk image from the mount point. REMEMBER we must unmount any mounted file systems from kpartx -d prior to our fuse unmount.

```
root@forensic1:/able3# umount /mnt/analysis/
```

```
root@forensic1:/able3# kpartx -d /mnt/aff/able_3.000.raw
loop deleted: /dev/loop0
```

```
root@forensic1:/able3# ewmount -u /mnt/aff
```
