The first consideration when using any recovery strategy, is that the disk must be\accessible by the Linux kernel. If the drive does not show up in the /dev structure, then
there's no way to get tools like ddrescue to work.

Next, we have to a plan to recover as much data as we can from a bad drive. The
prevailing philosophy of ddrescue is that we should attempt to get all the data first. This
differs from normal dd tools, which simply attempt to get all the data at one time in
linear fashion. ddrescue uses the concept of "splitting the errors". In other words, when an
area of bad sectors is encountered, the errors are split until the "good" areas are properly
imaged and the unreadable areas marked as bad. Finally, ddrescue attempts to retry the bad
areas by re-reading them until we get data or fail after a certain number of specified
attempts.

There are a number of ingenious options to ddrescue that allow the user to try and
obtain the most important part of the disk first, then move on until much of the disk is
obtained possible. Areas that are imaged successfully need not be read more once. As
mentioned previously, this is made possible by a robust map file. The map file is written
periodically during the imaging process, so that in the event of any interruption, the
session can be restarted, keeping duplicate imaging efforts, and therefore disk access, to
minimum.

Given that we are addressing forensic acquisition here, if it means multiple runs. The following examples
will be used to illustrate the most important options to ddrescue work for the forensic
examiner. We will concentrate on detailing the map file used by ddrescue so that the user can
see what is going on with the tool, and how it operates.

Let's look at a simple example of running ddrescue on a small drive without errors, to
the simplest is by providing the input file, output file and a name
of our map file. Note that there is no if= or -f-. In order to get a good look at how the map
file works, we'll interrupt our imaging process halfway through, check the map file to illustrate
an an interruption is handled, and then resume the imaging.

```
root@forensic1:~# ddrescue /dev/sdd ddres.img.raw ddrescu.map
GNU ddrescue 1.21
Press Ctrl-C to interrupt
```
