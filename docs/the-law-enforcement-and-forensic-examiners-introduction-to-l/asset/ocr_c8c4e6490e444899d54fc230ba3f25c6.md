Actually you can mount file systems (not just on /mnt or /media), but it's better for organization. Since we will be dealing with temporary mounting of potential evidence we will use the /mnt directory for most of our work. Here is a brief overview.

Any time you specify a mount point you first make sure that the directory exists. For example to mount a USB disk /mnt/evidence you must be sure that /mnt/evidence exists. After all, suppose we want to have a CDROM and a USB drive mounted at the same time? They can't be mounted under /mnt (if you would be trying to access two file systems through one directory!). So we create directories for each device's file system under the primary /mnt. Keep in mind that until you learn to manipulate the file /etc/fstab (covered later), only root can mount and unmount file systems (explicitly).

# The Mount Command

The mount command uses the following syntax:

```
mount -t <filesystem> -o <options> <device> <mountpoint>
```

One of the options we pass to the mount command, using -t, it is the file system type'. But if you don't know what file system is on a device you've been? First, we need to know the partition layout of the device. Is there one partition? Two? Once've selected the partition we want to view, we need to know what file system might be on. We can accomplish this with a series of commands we've already covered in the earlier chapter on disks and disk naming conventions. We use the lsblk command to view our devices that have been detected. We use fdisk to determine the partition layout, and finally we use the file command with the -s option to determine the file system type we will be mounting. For example, if I insert a thumb drive into my system and I manually mount it, I use the following commands to gather the information you need:

```
root@forensic:~# lsblk
[0:0:0] disk ATA INTEL SSDSC2CT12 300i /dev/sda
```

> Actually, modern Linux systems do a pretty job of auto detecting file system types, but being explicit is not a bad.
