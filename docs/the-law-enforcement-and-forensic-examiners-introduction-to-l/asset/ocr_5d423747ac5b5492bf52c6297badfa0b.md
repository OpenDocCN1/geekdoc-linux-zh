The time for the UserAssist "directory" is Apr 5 21:36. A more precise time can be shown with the stat command run on the directory:

```
$ barry@forensic1:~/nuserm/Software/Microsoft/Windows/CurrentVersion/Explorer
File: UserAssist/
Size: 0 Blocks: 0 IO Block: 4096 directory
Device: 25h/3d Inode: 0 Links: 2
Access: (0555/dr-xr-xr-x) Uid: ( 1000/ barry) Gid: ( 100/ users)
Access: 2017-04-05 21:36:50.0000000000 -0400
Modify: 2017-04-05 21:36:50.0000000000 -0400
Change: 2017-04-05 21:36:50.0000000000 -0400
Birth:-
```

Here we get the more precise time of 2017-04-05 21:36:50.0000000000 -0400. Make particular note of the fact that the time zone is -0400. Because this is running within a fuse point, the times are shown in the host system time, NOT the time zone of the registry file. The rest of the information is also largely useless, as it is not really associated with the original source data. What we have shown here is the last write time of the UserAssist key is 2017-04-05 21:36:50.0000000000 -0400. If we add four hours to the output, we get 2017-04-06 01:36:50.0000000000 UTC.

# Registry Parsing #2 – SAM and Accounts

Let's look at another registry file, the SAM. The SAM hive can have a great deal of information available if there are local accounts present on the system. Again, we're not going to go through a comprehensive analysis, we're just going to have a look at a few values of the most important keys.

We can get the SAM hive using the NTUSER.DAT, first searching for the MFT entry using fls and then using icat to extract the file:

```
ry@forensic1:$ fls -Fr - 2048 NTFS_Pract_2017/NTFS_Pract_2017.E1 | grep SAM
r/r 178-128-2: Windows/System32/config/SAM
```
