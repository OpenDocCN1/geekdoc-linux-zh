```
root@forensic1:~# mount /mnt/cdrom
```

The above mount commands look incomplete. When not enough information is given, the mount command will look to /etc/fstab to fill in the blanks. If it finds the required information, it will go ahead the mount. To find out more available options for /etc/fstab, enter info fstab at the mount prompt. After installing a new Linux system, have a look at /etc/fstab to see what is available for you. If you need it's not there, add it. In my case I uncommented the entry for the CDROM. Out of habit, I prefer using fstab to mount my CD/DVD media.

# Desktop Mounting

Mounting can also take place via automated or partially automated processes through your desktop environment. Linux has a huge list of choices in desktop systems and management (XFCE, KDE, Gnome, Mate, etc.). They have the capability to handle and mount removable devices for the user. This is normally done through the dynamic addition of context desktop icons that appear when removable media is plugged in. Volumes can then be mounted via a right-click menu.

There are a number of changes for the general Linux user that makes this sort of desktop capable mounting make sense. First, for general daily use as a desktop workstation, who wants to have to log in as root to mount external devices? What if you are working on a system that you don't elevated privileges on? In addition to the personal logistics, there's also the fact that the more modern mounting systems will place removable device mount points to a user's personal space rather than a system mount point. This offers better security and accessibility for the user.
