```
root@forensic:~# cat /etc/rc.d/rc.inet2

# Start the OpenSSH SSH daemon:
if [ -x /etc/rc.d/rc.sshd ]; then
techo "Starting OpenSSH SSH daemon: /usr/sbin/sshd"
/etc/rc.d/rc.sshd start
fi
...
```

Again, this position of rc.inet2 checks to see if rc.sshd is executable. If it is, then it
runs the command /etc/rc.d/rc.sshd start. Note that the rc services can have either
start, stop or restart passed as arguments in most cases. So, in for this particular
example:

+   - /inittab calls /etc/rc.d/rc.M
- /etc/rc.d/rc.M calls /etc/rc.d/rc.inet2 (if rc.inet2 is executable)
- /etc/rc.d/rc.inet2 passes the command /etc/rc.d/rc.sshd start (if rc.sshd is
executable).

Earlier we discussed file permissions. Now let us look at a practical example of
changing permissions for the purpose of stopping select services from starting at boot time. A
look at the permissions of /etc/rc.d/rc.sshd shows that it is executable, and so will start
when rc.inet2 runs:

```
root@forensic:~# ls -l /etc/rc.d/rc.sshd
-rw-xr-x- 1 root 1726 Mar 10 2016 /etc/rc.d/rc.sshd*
```

To change the permissions to prevent the SSH service from starting at boot time, I
execute the following:

```
root@forensic:~# chmod 644 /etc/rc.d/rc.sshd
root@forensic:~# ls -l /etc/rc.d/rc.sshd
-rw-r--r-- 1 root 1726 Mar 10 2016 /etc/rc.d/rc.sshd
```

The directory listing shows that I have changed the executable status of the script, and
therefore prevented the service from starting when the system boots. Depending on your
color terminal settings, you may also see the color of the file change.
