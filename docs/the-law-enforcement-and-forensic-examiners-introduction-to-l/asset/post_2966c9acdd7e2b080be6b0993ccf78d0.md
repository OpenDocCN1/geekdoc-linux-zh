# Using Distribution Packages

As we've already mentioned, just about every Linux distribution has some sort of "package manager" for installing and adding official Slacksoftware (included in the distribution). For updating and adding, we've introduced slackpkg. slackpkg is actually a front to pkgtool, which handles the work of adding and removing software packages from your system. For an excellent overview of pkgtool and its various commands, have a look at http://www.slack.com/config/packages.php

Slack packages are just compressed archives that, when installed, place the package files in the proper place. To install a Slack package, when we are not using the slackpkg front, we use the pkgtool command installpkg.

Our example here will be a pretend Slack package called software. Slack packages are generally named with the extension tgz or txz (since they are really just compressed archives). Once you've downloaded or prepared your package (our example is called software.tgz), you install it with the following command:

```
root@forensic1:~# installpkg software.tgz
Verifying package software.tgz.
Installing package software.tgz:
PACKAGE DESCRIPTION:
# software
#
# This is where you will find a description
```

Packages can be similarly removed or upgraded with removepkg or upgradepkg, respectively.

You can find pre-made packages for all sorts of software for many distributions over the Internet. The problem with many of them is that they do not come from trusted sources and you have no idea what configuration options were used to build them.

As a general rule of thumb, I always like to build my own packages for software that is not part of the Slack installation. This allows me to build the software I need (or without ones I dont!), optimized for my particular system, and it further allows me to control how the software is eventually installed. Luckily Slack provides a relatively easy way to create packages from source code. Slackbuild.

# Building Packages – SlackBuilds

In Short, SlackBuild is a script that (normally) takes source code and compiles it into (or .tx) a Slack .tgz file that we can install using pkgtools.

The SlackBuild script handles the configure options and optimizations that the script author decides (but are visible and editable by you), and then installs the software and related files into a package that follows Slack conventions for executable and libraries, where assuming the author follows the template. The scripts are easily editable if you want to change some of the options or the target version, and provide for an easy, human readable way to control the build process. SlackBuilds for a large selection of software are available at http://www.Slackbuilds.org.

The SlackBuild comes as a .tar.gz file that you extract with the tar command. The resulting directory contains the build script. The script is named software.SlackBuild, with software being the name of the program we are creating a package for. There are normal four files included in the Slack package:

- info gives information about where to obtain the source code, the version of the software script is written for, the hash of the source code, required dependencies, and more.
- README contains useful information about the package, potential pitfalls, and optional dependencies.

- software.SlackBuild is the actual build script.
- slack-desc a brief description of the file displayed during install.

To build a Slack compatible package, you simply drop the source code for the software into the same directory and execute the SlackBuild script. The package is created and (normally) placed in the /tmp directory for installation via pkgtools.

Of course, there are automated tools for handling Slackware packages for you. You can check out sppkg, sbootools, slpkg and a few others.

A WORD OF CAUTION: Be careful about relying on automated tools for package management. Regardless of the platform you choose to run on, I would urge you to learn how to build packages yourself, or at the very least learn how to change package options or at minimum determine what build options were used before running software. This is not to say automated tools are bad...but one of the strengths of Linux that we often talk about is the control it gives over our system. Controlling your system is one aspect of that. You can use automated tools and still maintain control...you just need to be careful. We will use that approach here.

So what we've done up to this point is just download and extract the SlackBuild package. Now we need to get the sbotools source package in the same directory.

The sbotools.info file will help with this. We will verify the information contained therein to download the source code and check the MD5 hash. The MD5 hash is a value that lets us which file downloaded. Using wget and the URL provided in the DOWNLOAD file, the source code for sbotools will end up in the same directory.

```
root@forensic:-~/sbotools# cat sbotools.info
PRGN="sbotools"
VERSION="2.3"
HOMEPAGE="http://pink-mist.github.io/sbotools/
DOWNLOAD="http://pink-mist.github.io/sbotools/downloads/sbotools-2.3.tar.gz"
MDSUM="b975255e9f93717e3f7ff5a2e02da8"
MD5SUM_x86_64"
MD5SUM_x86_64"
REQUIRES"
```
