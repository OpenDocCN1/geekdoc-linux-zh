# Direct Blocks:

```
barry@forensic1:~/able_3$  icat -o 104448 able_3.000 21 | xxd | head -n 5
<no output>
```

Here we have a different outcome. Inode 21 points to an unallocated file. In an ext4 file system, when the Direct Blocks are cleared, there is no longer a pointer to the data, so commands like icat will not work. Remember that icat works at the inode (file meta-data) layer. The icat command uses the information found in the inode to recover the file. In this case there is none.

This does not mean we cannot recover the data that was there. On the contrary, there are a number of techniques we can use to attempt to recover the deleted files. But in this case it becomes more difficult to recover the data and associate it with a particular file name and inode information. While this sort of forensic analysis is outside the scope of our exercise, it does highlight the difference between using these tools on different file systems. And that is point: Know your tools, their capabilities, and their limits.

When we test tools for forensic use, it is not enough to say "X tool does not work on Y file system". You should understand why. In this case it would be accurate to say that "icat works as expected on an ext4 file system, but is limited of use on deleted entries". Be sure to understand the difference, and test your tools!
