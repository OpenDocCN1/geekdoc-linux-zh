If you look at the jpg images, you will see the pattern that we searched for our dd carving exercise. \xff\xd8 for the header and \xff\xd9 for the footer. When we run scalpel the unallocated blocks will be used to search for patterns. When you are finished editing the file (double check), save and quit with: :wq

For this exercise, we will use the able_3 image as our carving target. In our Sleuth Kit exercise #1B (deleted file identification and recovery - ext4), we across a number of files (olitaz+) in the /home/ directory that could not be recovered. This is an obvious case for file carving.

Since we are able to carve the allocated files from the /home partition on able_3, we might want to limit our carving to unallocated blocks. This is a common way to carve systems - separate the unallocated and the carved blocks. We already learned how to extract all unallocated blocks from a file system using the TSK blks. we'll start by extracting the unallocated first.

Remember that the TSK tools can work directly on split images, there is no need to fuse mount the image or loop mount any file systems. running mmls gives us the system offsets (if you remember, the /home directory was mounted on the second Linux system at offset 184448). We use that with our blks command. You can run a recursive flcmd using with the -r option to refresh your memory on the files we are looking for. The asterisk (*) next to the next node are deleted:

```
barry@forensics1:-carve mmls ~/able_3/able_3.000
GUID Partition Table (EFI)
Offset Sector: 0
Units are in 52-byte sectors
```
