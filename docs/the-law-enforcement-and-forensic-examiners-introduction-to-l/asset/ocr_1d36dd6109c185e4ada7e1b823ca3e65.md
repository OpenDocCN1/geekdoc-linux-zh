This list output provides some additional information, including which modules are loaded when the device is detected. This can be an important piece of information if I'm trying to troubleshoot a misbehaving device. One online help might suggest using a different driver altogether. If that is the case, you may need to "blacklist" (the currently loaded module in order to prevent it from loading and hindering the correct drive) (that you may need specify). Blacklisting is normally done in /etc/modules.d/ by creating a blacklist-[modename].conf file or making an entry in blacklist.conf, depending on your distribution. In Slackware you can read the README file in /etc/modules.d and the man page for modules.d for more information. Since the steps for this are far wildly depending on the driver, it won't cover this in any more depth. Specific help for individual driver cases can be found online. This simply introduces you to sources of information.

Note that if you are using a laptop or desktop with a wireless adapter, it likely won't show up in lspci. For that you will have to use lsusb (list USB – there's a pattern here, see?). In the following output, lsusb reveals info about a wireless network adapter. Use the -v option for more verbose output (bold for emphasis):

```
root@forensic1:~$ lsusb
```
