# A Comprehensive Beginner's Guide to Linux as a Digital Forensic Platform

Testing has shown that standard dd tools are simply inadequate for acquiring disks that have actual errors. This is NOT to say that dd, dc3dd and dcflddd are useless...far from it. They are not optimal for error recovery. You may be forced to use dd or dc3dd because of limits of external access or considerations of time. We teach in dd because there are instances where it may be the only tool available to you. In those cases, understanding the use of command line options to optimize the recovery regardless of errors is important for evidence preservation. However, if there are options, then perhaps a different tool would make sense.

This section is not meant to provide an education on disks, media failure, or types of failure. It is not meant to imply that any tool is better or worse than any other. I will simply describe the basic functionality and leave it to reader pursue the details.

First, let's start with some of the issues that arise with the use of common dd tools. For the most part, these tools take a “linear” approach to imaging, meaning that at the beginning of the input file and read by block until the end of the file is reached. When an error is encountered, the tool will either fail with an “input/output” error or if a parameter such as conv=noerror is passed, it will ignore the errors and attempt to read through (skip) them, continuing to read by block until it comes across readable data again. Here is a simple dd command on a disk. The disk is 41943040 sectors:

```
root@forensic1:~# blockdev --dev/sdf
41943040
```

```
root@forensic1:-# dd if=/dev/sdf of=dd.raw
dd: error reading '/dev/sdf': Input/output error
12840+0 records in
12840+0 records out
6574080 bytes (6.6 MiB, 6.3 MiB) copied, 0.157453 s, 41.8 MB/s
```

The dd command above was only able to read 12840 sectors (which the dd output shows). The same command, this time using conv=noerror,sync will ignore the error, pad the error with null bytes, and continue on:

```
root@forensic1:-# dd if=/dev/sdf of=error.raw bs=512 conv=noerror,sync
dd: error reading '/dev/sdf': Input/output error
12840+0 records in
12840+0 records out
6574080 bytes (6.6 MiB, 6.3 MiB) copied, 0.163426 s, 40.2 MB/s
dd: error reading '/dev/sdf': Input/output error
12841+0 records out
6574592 bytes (6.6 MiB, 6.3 MiB) copied, 0.163724 s, 40.2 MB/s
dd: error reading '/dev/sdf': Input/output error
```
