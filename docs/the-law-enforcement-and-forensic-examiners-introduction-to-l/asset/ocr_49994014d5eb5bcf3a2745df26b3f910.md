In this case we are concerned only with the ? and the +. Essentially, when the copying process is interrupted, the log is used to tell drescue where the copying left off, and what has already been copied (or otherwise marked). The first section (status) alone may be sufficient in this case, since drescue only picks where it left off, but in the case of a disk with errors, the block section is so drescue can keep track of what areas still need to be retried as good data is sought among the bad.

Translated, our log would tell us the following:

```
current_pos current_status
0x40B10000
?
```

+   - The status shows that the current imaging process is copying data at byte offset 1085341696 (0x40B10000). In our first pass, this identifies the "non-tried" blocks.

+   - pos size status
0x00000000 0x40B10000 +
0x40B10000 0x3F4EF000 ?

+   - The data blocks from offset 0 (0x00000000) of size 1085341696 bytes (0x40B10000) are finished.
- The data block from offset 1085341696 (0x40B10000) of size 1062137856 bytes (0x3F4EF000) are not tried.

Note also that the size of our partial image file matches the size of the block of data marked "finished" with the + symbol in our log file (size bold for emphasis):

```
root@forensic1:-# ls -l ddres.img.raw
-rw-r--r-- 1 root 1085341696 May 3 13:12 ddres.img.raw
```

We can continue and complete the copy operation by simply invoking the same command. By specifying the same input and output files, and by providing the map file, we will use drescue to continue where it left off:

```
root@forensic1:-sde drescue /dev/sde ddres.img.raw ddres ddres.map
GNU debug 1.21
Press Ctrl-C to interrupt
Initial status (read from mapfile)
rescued:
```
