Now it's time to find the end of the file.

Since we already know where the JPEG starts, we will start our search for the end of the file from that point. Using again xxd and grep we search for the footer value ffd9 somewhere after the header:

```bash
barry@forensic1:$ xxd -s 223942 image_carve_2017.raw | grep ffd9
0005d3c6: af 29ae7 06e1 2e48 38a3 ffd9 8303 a138 .j)....H.......8
```

The -s 223942 option specifies where to search (since we know this is in front of the JPEG, there's no need to search it and we will eliminate false hits from region). The output shows the first ffd9 on the line at offset 0005d3c6. Let's convert that to decimal, noting the uppercase value in our hex:

```bash
barry@forensic1:$ echo "base=16;5D3C6" | bc
381894
```

Because that is for the start of the file, we need to add 12 to the value to include the ffd9 (giving us 381906). We do this because the ffd9 needs to be included in our carve, so we skip past it. Now that we know the start and the end of the file, we can calculate the size:

```bash
barry@forensic1:$ echo "381906-223942" | bc
157964
```

We now know the file is 157964 bytes in size, and it starts at byte offset 223942. The carving is the easy part! We will use dd with three options:

- skip= how far into the data chunk we begin "cutting"
- bs=(block size) the number of bytes we include as a "block"
- count= the number of blocks we will be "cutting".

The input file for the dd command is image_carve_2017.raw. Obviously, the value of skip will be the offset to the start of the JPEG. The easiest way to handle the block size is specify it as bs=1 (meaning one byte) and setting count to the size of the file. The name of the output file is arbitrary.

```bash
barry@forensicl:-$ dd if=image_carve_2017.raw of=carved.jpg bs=1 skip=223942 count=157964
157964+0 records
157964+0 records out
157964 bytes (158 KB, 154 KiB) copied, 0.279145 s, 566 kb/s
```

You should now have a file in your current directory called carved.jpg. If you are in X, simply use the xv command to view the file (or any other image viewer, like display) and see what you've got.

```bash
barry@forensicl:-$ xv carved.jpg
```

## Carving Partitions with DD

Now we can try another useful exercise in carving with dd. Often, you will obtain or be given a dd image of a full disk. At times you might find desirable to have each separate partition within the disk available to search or mount. Remember, you cannot simply mount the entire image, only the partitions. We've already learned that we can find the structure of an image and mount the partitions using tools like kpartx and the loop device with the mount command.

In this case, we will assume we are on a system where we may not have access to extremely available tools like kpartx. We introduce this technique not to teach it for practical use (though you may have limited practical use), but to provide another practical exercise using a number of important command line tools. In any event, for the beginning Linux forensics student, I still consider this an important skill. It's just good practice for a number of common and useful commands.

The method we will use in this exercise entails identifying the partitions in a raw image with fdisk or gdisk. We will then use dd to carve the partitions of the image. We will use the same disk image we used previously (able_3.00). If you have not downloaded it already, do so now. Then check the hash of the downloaded file. It shall match here:

```bash
barry@forensicl:-$ wget http://www.linux.com/Files/able_3.gz
barry@forensicl:-$ sha1sum able_3.tar.gz
```

Check the contents of the tar archive (tar.gz), untar the files (tar xzvf) into the able_3 directory by cd. You can skip all of this if you already have the able_3 directory from your previous exercise.
