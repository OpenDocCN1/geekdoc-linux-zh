Here we saw the download of main.cvd, daily.cvd and bytecode.cvd. There are a couple of warnings issued, and this is because the files do not exist and freshclam attempts to read the headers before updating. Subsequent updates will not show these warnings. We also got a warning that Clam was NOT notified. This is because we are not running a scanning daemon (for mail servers). You can run freshclam with --no-warnings if you wish to suppress those.

We are now ready to run clamcan on our target. ClamAV supports direct scanning of files, can recurse through many file types and including zip files, PDF mounts mounts and forensic images (gpt and mbr partition types). The reliable way of running clamcan is to run it on a mounted file system.

There are options within clamcan to copy or move infected files to alternative directories. Normally we do not do this with infected files or malware during a forensic examination, preferring to examine the files in place, or extract them with forensic tools. Check clamscan for additional details if you are interested. The output of clamcan can be logged with the --logfile option, useful for keeping complete examination notes.

We will try out clamscan on our NTFS EWF files we downloaded. Change into the directory the files are located, use ewmount to mount the images, and loop mount the NTFS partition. If you do not already have the destination mount points in /mnt created use mkdir to create them. We will scan the NTFS partition.

```
root@forensic1:~# cd NTFS_Pract_2017
root@forensic1:~/NTFS_Pract_2017# ewmount NTFS_Pract_2017.E01 /mnt/ewf
ewfwmont 20140608
root@forensic1:~/NTFS_Pract_2017# mount -o ro,loop,offset=$((2048*512))
/mnt/ewf/ewfi /mnt/analysis/
root@forensic1:~/NTFS_Pract_2017# clamscan -r -i /mnt/analysis/ --log=NTFS_AV.txt

```
