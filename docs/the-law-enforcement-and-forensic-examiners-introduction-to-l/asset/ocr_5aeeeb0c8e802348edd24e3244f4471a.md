Here used /dev/side as our input file, wrote the image to ddres.img.raw, and
wrote the file to ddres.map. The output shows the progress of the imaging by
default, using a running count of the data copied or "rescued", along with
count of the number of errors encountered (in this zero), and an imaging speed. In this,
case the process was interrupted at about 50% completion, with the ctrl-c key command.

Now we have a look at our map file:

```
root@forensic1:~# cat ddres.map
# Mapfile. Created by GNU ddrescue version 1.21
# Command line: ddrescue /dev/side ddres.img.raw ddres.map
# Start time: 2017-05-03 13:12:15
# Current time: 2017-05-03 13:12:28
# Copying non-tried blocks... Pass 1 (forwards)
# current_pos current_status
0x40B10000 ?
# pos size status
0x00000000 0x40B10000 +
0x40B10000 0x3F4EFE00 ?
```

The map file shows us the current status of acquisition¹⁴ Lines starting with a #
comments. There are two sections of the note. The first comment line shows the current
status of the imaging while the second section (two lines, in this case) shows the status
of blocks of data. The values are in hexadecimal, and are used by ddrescue to keep track
of areas of the target device that have marked errors, areas that have already been
successfully read and written, and that remain to be read. The status symbols we will
disc here (taken from the info page) are as follows:

| Character Meaning |
| ? non-tried |
| * bad area non-trimmed |
| / bad area non-scraped |
| - bad hardware block(s) |
| + finished |

> ¹⁴ The ddres info page has a very detailed explanation of the map file structure.
