
# Scalpel

We'll start by installing scalpel. Use sboinstall to install it, being sure to read the README file. If you are not using Slackware, go ahead and use your distribution's package management tool. You will see that for Slack, scalpel has a single dependency that must be installed first TRE, which is handled automatically by sboinstall:

```
root@forensic1:~ sboinstall scalpel
Scalpel is a fast file carver that reads a database of header and footer
definitions and extracts matching files or data fragments from a set of
image files or raw device files. Scalpel is filesystem-independent and will
carve files from FATX, NTFS, ext2/3, HFS+, or raw partitions. It is useful
for digital forensics investigation and file recovery.
```

To use it, you MUST have a conf file that defines the file types you want
recover. Use the example scalpel.conf file from /usr/doc/scalpel

If you read the README file (which you did, RIGHT?), you will see that we need to copy and edit the scalpel.conf file before we can run the program. We can either edit and use it
in place, or copy it to our working directory which scalpel uses default.

For now, we'll copy the scalpel.conf file that was installed with our package to a new
carve subdirectory in our /home directory, which we'll create now, and edit it there.

```
barry@forensic1:~$ mkdir ~/carve
barry@forensic1:~$ cd ~/carve

barry@forensic1:~/carve cp /usr/share/doc/scalpel-2.0/scalpel.conf .
```

# This configuration file controls the types and sizes of files that
# are carved by Scalpel. NOTE THAT THE FORMAT OF THIS FILE WAS
# EXTENDED in Scalpel 1.90->

# For each file, the configuration file describes the file's
# extension, whether the header and footer are case sensitive, the

# footer are required. Any line that begins with a '#' is considered
# a comment and ignored. Thus, to skip a file type just put a '#'
# the beginning of the line containing the route for the file.

Scroll down to where the # GRAPHICS FILES section starts (for the purpose of our
exercise) and just uncomment every line that describes a file in that. Be careful not to
uncomment lines that should remain comments. To uncomment a line, simply remove the
hash (#) at the start of the line. The # GRAPHICS FILES section should look like this
when you are done (extra hash symbols don't matter, as long as the correct lines are
uncommented, and the sections are still commented):

```
----------------------------------------------------------------------
# GRAPHICS FILES
----------------------------------------------------------------------
#
#
```

> To obtain the allocated blocks using blks:

```
barry@forensic1:~/carve$ blks -o 104448 ~/able_3/able_3.000 > home.blks
barry@forensic1:~/carve$ ls
home.blks scalpel.conf*
```

The blks command is run with the offset (-o) pointing to the second Linux file system that starts at sector 104448. The output is redirected to home.blks. The name "home" is used to signify that this is partition mounted as /home. Now we can see (with the ls command above) that we have two files in the ~/home directory.
