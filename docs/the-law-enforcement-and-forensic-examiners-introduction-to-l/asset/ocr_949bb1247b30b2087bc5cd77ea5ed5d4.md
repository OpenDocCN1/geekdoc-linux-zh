Here's our command to create an output directory for analysis results. We are executing the
command in the directory where we placed our image file. Note the . / in front of the
directory name we are creating “in the current directory":

```
barry@forensic1:~$ mkdir ./analysis

barry@forensic1:~$ ls
analysis/ fat_fs.raw*
```

Directing all our output to this directory will keep our output files separated
from else and maintain case organization. You may wish to have a separate drive
mount /mnt/analysis to hold your analysis output. How you organize it is up to you.

An additional step you might want to take is to create a special mount point for all
subject file system analysis. This is another way of separating common use with
evidence processing. To create a mount point in the /mnt directory you will need to be
temporarily logged in as root. In this case we'll log in as root, create a mount point, and then
mount the fat_fs.raw image for further examination. Recall our discussion on the “super
 (root). We use the command su to become root:

```
barry@forensic1:~$ su -
Password:

root@forensic1:~$ mkdir /mnt/evid
```

Using our root login, we'll go ahead and mount the fat_fs.raw image on
/mnt/evid:

```
root@forensic1:~$ mount -t vfat -o ro,loop -barry/fat_fs.raw /mnt/evid/

root@forensic1:~$ losetup
NAME SELIMIT OFFSET AUTOCLEAR RO BACK-FILE
/dev/loop0 0 0 1 0 /home/barry/fat_fs.raw
```

(-t vfat) and the options (-o) read only (ro) and using the loop device (loop). The file system
we are mounting, fat_fs.raw, is located in /home/barry-(barry) and we are mounting it on
