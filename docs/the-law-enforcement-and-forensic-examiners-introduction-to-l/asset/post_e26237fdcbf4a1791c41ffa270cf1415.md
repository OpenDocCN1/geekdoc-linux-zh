## Viewing Files

For texts, you might want to use **cat**, more or **less** to view the contents.

```
cat filename
more filename
less filename
```

Be aware if the output is not standard text, then you might corrupt the terminal
output (type **reset** or **stty sane** at the prompt and it should clear up). Using the **file** command will give you a good idea of which files will be viewable and what program might
be used to view the contents of a file. For example, Microsoft Office documents can be
opened under Linux using OpenOffice, **catdoc** and **catox**.

Perhaps a better alternative for viewing unknown files would be to use the **strings** command. This can be used to parse regular ASCII out of any file. It's good for
formatted documents, data files (Excel, etc.) and even binaries (unidentified executable files,
example), which might have interesting text strings hidden in them. It might be to pipe
the output through **less**.

One neat trick you can do if you have a handful of picture files in a directory you want to view without having to use a separate command for each is to use a bash loop. Scripting and bash programming are outside the scope of this document (for now), but this is a very simple loop that illustrates some command line usage. This can be done all on one line, separating individual commands with ; makes it a bit more readable.

First, let's cd into the Pics/ directory under /mnt/evid, do a quick ls and see that we have a small directory with few picture files (you can check this with file). We then type our loop:

```
barry@forensic1:/mnt/evid$ cd Pics
barry@forensic1:/mnt/evid/Pics$ ls
C800x600.jpg bike2.jpg matrix3.jpg Stoppie.gif bike3.jpg mule.gif
barry@forensic1:/mnt/evid/Pics$ for pic in /*;
> do
> xv pic
> done
```

The first line of bash loop above means "for file in the current directory (/*), assign each file the name pic as we move through the loop". The second line is simply the keyword do. The third line executes xv the value of the pic ($pic) at each iteration of the loop, followed by the keyword done to close the loop. As you run the loop, each image will display, and the loop will pause until you close xv. When you close xv, the loop continues until all the values of $pic are exhausted (all the files in the directory) and the loop exits. Learn to do this and I promise you will find it useful.

If you are currently running the X window system, you can use any of the tools that come standard with Linux distribution you are using. th is one tool for the XFCE desktop that will display files in a directory. Other tools, such as Konquer from the KDE desktop have a feature that will create a very nice gallery for images in a directory.

Once you are finished exploring, be sure to unmount the mounted disk image. Again, make sure you are not anywhere in the mount point (another terminal session) when you try to unmount, or you will get the "busy" error. The following commands will take you back to your home directory (cd without arguments takes you to home directory automatically). su to root, and unmount the file system.

```
barry@forensic1:/mnt/evid/Pics$ cd
barry@forensic1:~ su

root@forensic1:~ umount /mnt/evid
root@forensic1:~# exit
barry@forensic1:~$
```

## Searching All Areas of the Forensic Image for Text

Now let's go back to the original image. The mounted disk image allowed you to check all the files and directories using logical view of the file system. What about unallocated and slack space (physical view?) We will now analyze the image itself, since it was bit for bit copy and includes data in the unallocated areas of the disk. We will do this using rudimentary Linux tools.

Let's assume that we have seized this image from media used by a former employee of a large corporation. The sent a letter to the corporation threatening to unleash virus in their network. The suspect denies sending the letter. This is a simple matter of finding the text from a deleted file (unallocated space).

First, change back to the directory where you saved the image file fat_fs.raw. In this case, the file is in my home directory (which you can see is my present working directory by both the in the prompt, and the output of the pwd command).

```
barry@forensic1:~$ pwd
/home/barry
```

```
barry@forensic1:~$ ls
Desktop/ Downloads/ analysis/ fat_fs.raw
```

Now we will use the grep command to search the image for any instance of expression or pattern. We will use a number of options to make the output of grep useful. The syntax of grep is normally:

```
grep -options <pattern> <file-to-search>
```

The first thing we do is create a list of keywords to search for. It's rare we ever want to search for a single keyword, after all. For our examples, let us use "ransom,$50000 (the ransom amount), and unleash a virus". These are some keywords and phrase that we decided to use from the original letter received by the corporation. Make the list of keywords (using vi) and save it as ~/analysis/searchlist.txt. Ensure each string you want to search for is on a different line.

```
$50,000
random
unleash a virus
```

Make sure there are NO BLANK LINES IN THE LIST OR AT THE END OF THE LIST!! Now run the grep command on our image:

```
barry@forensic1:~$ grep -abif analysis/searchlist.txt fat_fs.raw > analysis/hits.txt
```

We are asking grep to use the list we created in ./analysis/searchlist.txt for the patterns we are looking for. This is specified with the -f<file> option. We are telling grep to search fat_fs.raw for the patterns, and redirect the output to a file hits.txt in the .analysis directory, where we record the output. The -a option tells grep to ignore upper and lower case. And the -b option tells grep to give us the byte offset of each hit so we can find the line in xxd (our command line viewer). Earlier mentioned the grep man page and the section it has regular expressions. Please take the time to read it and understand it.

Once you run the command above, you should have a new file in your analysis directory called hits.txt. View this file with less or any text viewer. Keep in mind that strings might best for the job.
