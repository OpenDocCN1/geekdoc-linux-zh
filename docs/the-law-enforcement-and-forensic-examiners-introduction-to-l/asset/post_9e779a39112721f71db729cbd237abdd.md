
Slack Linux is stable, consistent, and simple. As always, Linux is Linux. Any distribution can be changed to function like any other (in theory). However, my philosophy has always been to start with an optimal system, rather than attempt to "roll back" to a heavily modified and optimized for the desktop rather than a forensic workstation.

If you are comfortable with another distribution, then by all means, continue to use and learn it. Just be aware that there may be customization made to the standard kernel and file system setups that might not be ideal for use. These can always be remedied, but I prefer to start as close to optimal as possible.

## Installation Methods

Download the needed bootable media files, burn them to a DVD or removable drive and boot the media. This is the most common method of installing Linux. Most distros can be downloaded for free via http, ftp, or torrent. Slack is available at... for information on downloading and installing other distributions.

During a standard installation, much of the work is done for you, and relatively safe defaults are provided. As mentioned earlier, hardware detection has gone through some improvements in recent years. I believe that many (if not all) Linux distros are far easier and faster to install. Typical Linux installation is well documented (check your specific distribution's website for more information). There are numerous books available on the subject, and you should familiarize yourself with Linux disk and partition naming conventions (covered in Chapter II of this document).

## Installation Notes

If you decide to give Linux a shot, here are some simple guidelines. The documentation provided on Slack's site is complete and easy to follow. Read first... decide on standalone Linux or dual boot. Determine how you want the Linux system to be partitioned. A single root partition and a single swap partition are fine. You might find it easier when starting out to install Linux in a virtual machine (VM), either through VirtualBox or VMware. This will allow you to snapshot and recover from any errors. It also provides you with access to community support while installing your system. Using Linux in a virtual machine is a perfectly acceptable way to follow this guide, and probably the easiest if you are an absolute beginner.

# v4.33 A Comprehensive Beginner's Guide to Linux as a Digital Forensic Platform

READ through the installation documentation before you start. Not be in a hurry. If you want to learn Linux, you will have to be willing to read. For a basic understanding of how Linux works and how to use it, the Slack Book located at http://www.slackbook.org/ has detailed instructions if you need step-by-step help, including partitioning, etc. Some of it may be a bit outdated, but the majority of it still applies. Here is some installation advice. As a very general overview:

- 1) Boot the Linux media
    - Read each screen carefully.
    - Accepting most works.
    - Your hardware will be detected and configured under most circumstances. Online support is extensive if you have problems.
    - Keep in mind that if a piece of hardware causes problems during install, or is not detected during installation, this does not mean it will not work. Install the operating system and spend some time troubleshooting. When learning Linux, Google is your best friend.
    - The Linux installation for the current version will boot by default using a kernel called. It includes support for most hardware. Hit the "F2" key at the initial "boot" prompt for more info.
    - Once the system is booted, you are presented with the keyboard map prompt followed by the login prompt. READ THE ENTIRE SCREEN as instructed. Login as root, and continue with your install routine.

- 2) Partition and format for Linux
    - You will partition your Linux system using **fdisk or gdisk** (if you prefer a GPT layout).
    - This step is normal part of the installation process, created in the distribution's documentation. You can partition however you like. I like to have at least two partitions:
        - Root (/) as type "Linux"
        - Swap as type "swap" (use 2x system memory as a starting point). The size of a swap partition is largely optional for machines with large amounts of RAM (>3GB). I still opt to use it.
    - You will hear a lot about using multiple partitions for different directories. Don't let that confuse you. There are arguments for and against using multiple partitions for a Linux file system. If you are just starting, use one large root (/) and one swap partition as described above.

- 3) Package installation (system)
    - The main install routine starts with the command **setup**. You will need to ensure that you have your disk properly partitioned **before** you enter the setup program.
    - Take the time to read each screen completely as it comes up.
    - When asked to format the root partition, I would suggest selecting the ext4 file system.
    - When asked packages to select for installation, it is usually safe for a beginner to select "everything" or "full". This allows you to try all the packages, along with multiple X Window desktop environments. This can take as much as 8GB to 12GB of some of the newer distributions (7GB on Slackware, depending on options), however it includes all the software you likely need for a long time (including many "office" type applications, Internet, E-mail, etc.). For a learning box it will give you the most exposure to available software for experimentation and additionally ensures that you are not limited.

- Installation Configuration
    - Boot Method (The boot loader selects the OS to boot)
        - Be mindful of EFI vs. legacy BIOS. Where possible, set the BIOS to legacy mode.
    - LILO or GRUB
        - LILO is the default for Slackware. GRUB is more flexible and secure. GRUB can be installed, if you like. Personally, I prefer LILO.
        - Generally select the option to install LILO to the master boot record (MBR). The presence of other loaders (provided by other operating systems) determines where to install LILO or GRUB.
        - If you use EFI, skip this and install LILO or GRUB manually. You should read README_UEFI on the install media's root directory beginning the installation process.
        - The boot loader contains the code that points to the kernel to be booted.
    - Create a user name for yourself – avoid root exclusively.
    - For more information, check the file CHANGES_AND_HINTS on the install media. This file is loaded with useful hints and changes of interest from one release to another.
