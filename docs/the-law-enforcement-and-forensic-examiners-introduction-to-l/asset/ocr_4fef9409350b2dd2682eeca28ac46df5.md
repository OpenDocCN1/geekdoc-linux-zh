Again, the SHA hashes in the file will be compared with SHA sums taken from the mount point. If anything has changed, the program will give a FAILED message. If there are failed hashes, you will get a message summarizing the number of failures at the bottom of the output. This is the fastest way to verify hashes. Note that the filenames start with /. This indicates a relative path. Meaning that we must be in the same relative directory when we check the hashes, since's that the command will look for the files.

# File Listing

Get creative. Take the ls command we used earlier and redirect the output to your ~/directory. With that you will have a list of all the files and their owners and permissions on the subject file system. Check the man page for various uses and options. For example, you could use the -i option to include the inode in the file (for Linux file systems), the -t option can be used so that the output will include and sort by modification.

```
barry@forensic1:/mnt/evid$ ls -lRt ~/analysis/ModTime.filelist.txt
```

You could also get a list of the files, one per line, using the find command (-type f) and redirecting the output to another list file:

```
barry@forensic1:/mnt/evid$ find -type f > ~/analysis/find.filelist.txt
```

Or a list of directories (-type d)

```
barry@forensic1:/mnt/evid$ find -type d > ~/analysis/find.dirlist.txt
```

There is also the tree command, which prints a recursive listing that is more visual...It indents the entries by directory depth and colorizes the filenames (if the terminal is correctly set).
