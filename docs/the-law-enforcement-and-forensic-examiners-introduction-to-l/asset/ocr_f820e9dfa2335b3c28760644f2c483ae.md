```
root@forensic1:~# hdparm -I /dev/sdc > case1/case1.disk1.hdparam.txt
```

```
root@forensic1:~# ls case1/
case1.disk1.hdparam.txt
```

In the second command above, we've redirected (>) the output of hdparm -I /dev/sdc
to a file in the case1 directory. The file is called case1.disk1.hdparam.txt. The last
command lists the contents of the case1 directory. If we have multiple disks, then we
ave output for disk2, disk3, etc. The file naming is arbitrary. This is an example.

Note that you can keep a running of things that you do by using a double redirect
[>>] symbol to add all case info to a single log. I would suggest not taking this approach as
y learn, though. If you mistakenly use a single redirect [], you clobing an entire log
file (recall that we can use our previously discussed chatter +a command to prevent this,
setting the file to append only).

We can also use the hdparm tool to help disk configuration overlays or host
protected areas (DCO or HPA, respectively). Manufacturers use these to change the number
sectors available to the user, sometimes to make driving drives size for marketing
(DCO) and specifics of hiding things like "restore" or "recovery" partitions (HPA).
The history and specifics of these areas are well documented on the Internet. If you have not heard
them, do some research. As forensic examiners, we are always interested in acquiring the
entire disk (or at least these areas we can nominally access through kernel tools). There are
deeper areas on disks that we will not address here.

In previous versions of this document we used Sleuth Kit to accomplish this. But
now hdparm can tell us there is a DCO (and the changes actually implemented by the DCO).
These can be manipulated using hdparm as well, but I will leave these advanced topics to your
own research (hint: read man hdparm).

In this case we have no HPA:

```
root@forensic1:~# hdparm -N /dev/sdc

dev/sdc:
max sectors = 78125000/78125000, HPA is disabled
```
