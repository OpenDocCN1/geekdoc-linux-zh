
# III. The Linux Boot Sequence (Simplified)

**Booting the kernel**

The first step in the (simplified) boot sequence for Linux is loading the kernel. The kernel
image is usually contained in the /boot directory. It can go by several different names... (this can vary greatly by)

- bImage
- vmlinuz

Sometimes the kernel image will specify the kernel version contained in the image, i.e.
vmlinuz-huge-4.4.19 Very often there is a soft link (like a shortcut) to the most current
kernel image in the /boot directory. It is normally this link is referenced by the boot
loader, LILO (or GRUB). In a Slackware system, the kernel image is /boot/vmlinuz.

Note that Slack uses LILO by default. LILO is an older and simpler system for booting,
but is much less flexible.

The boot loader specifies the "root device" (boot drive), along with the kernel version
to be booted. This is all controlled by the file /etc/lilo.conf. Each "image=" section
represents a choice in the boot sequence.

This is an example of a lilo.conf file:

```
root@conf1:~# cat /etc/lilo.conf
append+=vt.default_utf8=0
boot = /dev/sda
bitmap = /boot/slack.bmp
bmp-colors = 255,0,255,0,255,0
bmp-table = 60,6,1,16
bmp-timer = 65,27,1,6
prompt
timeout = 1200
change-rules
reset
vga = normal
image = /boot/vmlinuz
root = /dev/sda1
label = Linux
read-only
```

Once the system has finished booting, you can replay the kernel messages that "fly" past
the screen during the booting process with the command dmesg. We discussed this command when
we talked about device recognition earlier. As previously mentioned,

> The actual /etc/lilo.conf file on your system will be much more cluttered with comments
> (lines starting with a "#"). Comments have been removed for readability above.

this command can be used to find hardware problems, or to see how a removable (or suspect)
drive was detected, including its geometry, etc. The output can be piped to a paging
viewer to make it easier to see (in this case, dmesg is piped through less on my Slackware
system).

# System Initialization

After the boot loader initializes the kernel, the next step in the boot sequence starts with
the program /sbin/init. This program really has two functions:

- initialize the runlevel and startup scripts
- terminal process control (respawn terminals)

In short, the init program is controlled by the file /etc/inittab. It is this file that
controls your runlevel and the global startup scripts for the system. This is, again, for a
Slackware system. Some systems, like Ubuntu, use a systemd scheme for system control and
configuration. If you are interested in the system startup routine for your particular distro
(and you should be interested), research it online.

# Runlevel

The runlevel is a simple description of the system state. For our purposes, it is easiest
to say that (for Slackware, at least - other systems, such as those using systemd, will differ:

- runlevel 0 = shutdown
- runlevel 1 = single user mode
- runlevel 3 = full multiuser mode / text login (DEFAULT)
- runlevel 4 = multiuser /X11 / graphical login⁴
- runlevel 6 = reboot

In the file /etc/inittab you will see a line similar to:

> ⁴ This is largely distribution dependent. In some distributions, run level 5 provides a GUI
login. In Slack (and others), it's run level 4.

```
id:3:initdefault:
nbarry@forensic1:-$ cat /etc/inittab
```
