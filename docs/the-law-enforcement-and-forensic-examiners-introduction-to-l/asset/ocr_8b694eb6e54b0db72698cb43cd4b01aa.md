As part of our organization, we'll make a new directory images in case1 directory. This is where we keep working copies of images. Normally, you would create images directly to either a larger drive that has been sanitized, or to a network storage volume that is used to maintain original copies. That will depend on your specific policies.

In this case, for illustration, we will image directly to our case1/images directory. I prefer keeping images separate as it allows protecting the directory of attributes that prevents changes or deletions to your working copy image files, once we've completed the imaging process.

To keep your dd command shorter, we'll change into our case1/images directory (case1/images) and write our output file here. Without needing to specify the directory (where we are writing to the current), we keep the command shorter and easier to read.

```
root@forensic1:~# cd case1/images
root@forensic1:~/case1/images# dd if=/dev/sdc out=case1.disk1.raw bs=512
71825000+0 records in
71825000+0 records out
400000000000 (40 GB, 37 GB) copied, 939.88 s, 42.6 MB
```

This takes your device /dev/sdc as the input file and writes the output file of called case1.disk.raw in the current directory /root/case1. The bs option specifies the block size. This is really not needed for most devices (hard drives, etc.) as the Linux kernel handles actual block size. It's added here for illustration, as it can be a useful option in many situations (discussed later).

Using dd creates an exact duplicate of the physical device file. This includes all file slack and unallocated space. We are not simply copying the logical file structure. Unlike forensic imaging tools, dd does not fill the image with any proprietary data or information. It is a simple stream copy from start to end. This has a number of advantages, as we will see later.

You can see from our output that the number of records (512 byte, in this case) as the number of sectors for this disk previously reported by hdparm -I, /dev/sdc matches. To verify your image, we can do the following. We want to recall the hash from the original device (/dev/sdc), which we stored in the file case1/disk1.sha.txt and compare that to the hash of the image we just made

```
root@forensic1:~/case1/images# cat ../case1.disk1.sha.txt
b3b506ea4c53b83495ac4b1956e0a250104f /dev/sdc
root@forensic1:~/case1/images# shasum case1.disk1.raw
b3b506ea4c53b83495ac4b1956e0a250104f  case1.disk1.raw
```
