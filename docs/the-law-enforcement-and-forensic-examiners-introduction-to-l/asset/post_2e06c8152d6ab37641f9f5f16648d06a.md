One important step in any analysis is verifying the integrity of your data after the analysis is complete. We've already covered integrity checks on disks and images. The same command works on individual files. You can get a hash (CRC, MD5, or SHA) of each file in a number of different ways. In this example, we will use the SHA1 hash. We get an SHA1 sum of an individual file by changing our evidence directory (/mnt/evid) and running the following command on one of the files. These commands can be replaced with md5sum if you prefer to use the md5 algorithm.

```
barry@forensics1:/mnt/evid shasum ARP.EXE
49f0485267a653bac165795ee2f8d934fb16509a9 ARP.EXE
```

```
barry@forensics1:/mnt/evid$ shasum ARP.EXE ~/analysis/ARP.sha.txt
```

```
barry@forensics1:/mnt/evid$ cat ~/analysis/ARP.sha.txt
49f0485267a653bac165795ee2f8d934fb16509a9 ARP.EXE
```

The redirection in the second command, using the > allows us to store the signature in the file ~/analysis/ARP.sha.txt and use it later on. Having hashes of individual files can serve a number of purposes, including matching the hashes against lists of bad files (contraband files or malware, for example), or for eliminating known good files from an examination. Doing this for each file on a disk would be tedious at not.

We can get a hash of every file on the disk using the **find** command and an option that allows us to execute a command on each file found. We can get a very useful list of SHA hashes for every file on our mount point by find to identify all *regular* files on the file system and run a hash on all those files:

```
barry@forensic:/mnt/evid5 find -type f -exec shasum {} \; \
~/analysis/sha.filelist.txt
```

```
barry@forensic:/mnt/evid5 cat ~/analysis/sha.filelist.txt
8608e288fe4a05f5c3dc7c40b3e7947afec11 /Docs/Benchmarks.xml
816e2f9f7633e85b891e250ed190228188 /Docs/Computer_Build.xml
```

We can then look at the hashes by using the **cat** command to stream the file to standard output (in this case, our terminal screen), as in the second command above.

You can also use Linux to verify your (or hash matching). To verify hashes using a hash list created with one of our hashing programs (**shasum, md5sum**, etc.), you can use the **-c** option. If the files match in the hash list, the command will return OK. Making sure you are in a directory where the relative paths in the list will target the correct files, using the following command:

```
barry@forensic:/mnt/evid5 shasum -c ~/analysis/sha.filelist.txt
/Docs/Benchmarks.xml: OK
```

Again, the SHA hashes in the file will be compared with SHA sums taken from the mount point. If anything has changed, the program will give a FAILED message. If there are failed hashes, you will get a message summarizing the number of failures at the bottom of the output. This is the fastest way to verify hashes. Note that the filenames start with /. This indicates a relative path. Meaning that we must be in the same relative directory when we check the hashes, since the command will look for the files.

# File Listing

Get creative. Take the ls command we used earlier and redirect the output to your ~/directory. With that you will have a list of all the files and their owners and permissions on the subject file. Check the man page for various options. For example, you could use the -i to include the inode, or -t to sort by modification time, or use:

```
barry@forensic1:/mnt/evid ls -l ~/analysis/filelist.txt
```

You can also get a list of directories using the find command and redirecting the output to another list:

```
barry@forensics1:/mnt/evid find -type d > ~/analysis/dirlist.txt
```

There is also the tree command, which prints a recursive listing that indents the entries by depth:

```
barry@forensics1:/mnt/evid tree
```

# Making a List of File Types

```
barry@forensics1:/mnt/evid find -type f -exec file {} \; ~/analysis/filetype.txt
```
