# Conventions Used in this Document

When illustrating a command and it's output, you will see something like the following:

```
root@forensic1:-# command
output
```

This is essentially a command line (terminal) session where...

```
root@forensic1:-#
```

...is the command prompt, followed by the command typed by the user and then the command's output. The command will be shown in bold text to further differentiate it from the resulting output (as may span multiple lines).

In Linux, the command prompt can take different forms, depending on the environment settings (the default differs among distributions). In the example above, format is

```
user@hostname:[present working directory] #
```

meaning that we are the user "root" working on the computer "forensic1" currently working in the directory root (the user's home directory – in this case, "home directory" is symbolized by the shorthand representation of the tilde (~). Note that for a root login command prompt's trailing character is #. If we log as a regular user, the default prompt character changes to a $, as in the following example:

> 'I know...not a pretty URL

barry@forensic1:-~$

This is an important difference. The root user is the system "superuser" or administrator. We will cover the differences between user logins later in this document.

Where you see ellipses ("..."), it indicates removed output for the sake of brevity or clarity:

```
root@forensic1:~# command
...\<--- removed output for brevity
output
...\<--- removed output for brevity
```

# I. Installation

Much has changed in the past few years with respect to the robustness and feature set of the current Linux kernels. Hardware detection and configuration used to present some unique challenges for Linux novices. While issues can still arise, the fact is that setting up a Linux machine as a simple workstation is no longer the nailing exercise that it once was. Kernel detection of hardware has become the norm, and most distributions of Linux can be installed with a minimum of fuss on all but the cutting edge hardware (and usually even then).

For the vast majority of computers out there, the default kernel drivers and settings will work “out of the box” for both old and new systems. The range of online help available for any given distribution is far wider than it was ten years ago, and most problems can be solved with a targeted internet search. For the most part, solutions that are effective on one distribution across the board. This may not always be the case, but if you are familiar with your system, you can interpret solutions and apply them to your particular platform.

If your Linux machine is to be a dual boot system with Windows, you can use the Windows Device Manager to record all your hardware and the settings used by Windows. Hardware compatibility and detection have been greatly improved over the past couple of years. Most of the recent versions of Linux distributions have extraordinary hardware detection. But it still helps to have a good idea of the hardware you are using so if problems arise do your support queries be targeted.

At a minimum, you are going to know and plan for:

- Hard drive partitioning scheme
  - Size and partition layout
- Network configuration
  - DHCP or static?
  - Gateway
  - DNS, etc.

Most distributions have a plethora of documentation, including online help and documents in downloadable form. Do a Web search and you are likely to find a number of answers to any question you might have about hardware compatibility issues in Linux. A list of useful Linux educational resources is provided at the end of this guide. Use them. And remember to research first before jumping into a forum and asking questions.

# Distributions

Linux comes in a number of different “flavors”. These are most often referred to as “Linux distribution” or “distro”. Default kernel configuration, tools that are included (system management architecture and configuration, etc.) and the package format (the software install and upgrade path) most commonly differentiate the various Linux distros.

It is common to hear users complain that X works under one distribution, but not on another, etc. That device Y did not work under one version of a distribution, but a change to "fixed it". Most often, the difference is in the version of the Linux kernel being used and therefore the updated drivers, or the patches applied by the distribution vendor, not the version of the distribution (or the distribution itself).

Previous versions of this guide provide a short list of distros and a summary description of each. That has been removed for a more descriptive explanation of why we have so many distributions, and how you can choose from them. Everyone has an opinion on these, and they all have their strengths and apparent weaknesses.

One thing we've seen more and more lately is somewhat specialized distros, or in some cases, that are perceived as specialized. There are still "general workstation" flavors of Linux – CentOS, Debian, Ubuntu, Slackware, Gentoo, etc., but we also have specialization now – full distributions designed and distributed specifically for a target audience like pentesters, enterprise admins, etc.

Some examples of specialized distributions that may be of interest to readers of this document:

- The Parrot Project – A Security distribution that "includes a full portable laboratory" for security and digital forensic experts.
- The SANS SIFT Workstation – An advanced incident response and digital forensics distribution that is widely supported, frequently updated, and stocked with all the tools you need to conduct digital triage, incident response, and digital forensic examinations.
- BlackArch Linux – A newer project, based on Arch Linux, that provides another alternative "out of the box" security focused distribution.
- Kali Linux – An advanced pen-testing and security distribution based on Debian. This is one of my favorite bootable Linux distributions, and can also be installed on a computer for use as a workstation.

There are many others, along with selections for secured bootable distros, "lightweight" distros, and many others. Don't let the options confuse you. Find a mainstream distribution, install it and learn it.

Our previously mentioned "general workstation" Linux distros are all perfectly suitable for use as a forensic platform. A majority of people new to Linux are gravitating toward Ubuntu as their platform of choice. The support community is huge, and a majority of widely available software for Linux forensics is specifically built for and supported Ubuntu (though not exclusively in most cases). On a personal note, I find Ubuntu less than ideal for learning Linux. It is NOT to say that Ubuntu or its variations do not make excellent platforms. But this guide is focused on learning, and part of that journey starts with a clean slate and understanding how the operating system works and is made to suit your environment. That for we focus on a more Unix-like distribution.

If you are unsure where to start, will be using this guide as your primary reference, and are interested in forensic applications of Linux, then I would suggest Slackware. The original commercial distribution, Slackware has been around for years and provides a good Standard Linux that remains true to the Unix philosophy. Not-encumbered by GUI tools, Slackware aims to produce the "Unix-like" distribution available. One of my personal favorites, and in my humble opinion, one of the best for a forensic platform. (http://www.slackware.com/). This guide is tailored for you a Slackware installation.

# Slack and Using this Guide

Because of differences in architecture, the Linux distribution of your choice can cause different results in commands' output and different behavior. Additionally, some sections of this document describing configuration files, startup scripts or software installation, for example, might appear vastly different depending on the distro you select.

If you are selecting a Linux distribution for the sole purpose of learning along with this document, then I would suggest Slackware. Slackware is stable and does not attempt to enrich the user's experience with cutting edge file system hacks or automatic configurations that might hamper forensic work. Detailed sections of this guide on the inner workings of Linux will be written towards a basic Slackware 14.2 64 bit installation (current of this writing).
