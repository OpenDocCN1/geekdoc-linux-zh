
## V. Editing with Vi

There are a number of terminal mode (non-GUI) editors available in Linux, including emacs and vi. You could always use one of the available GUI text editors in Xwindow, but if you are unsure to start X, or a windowing system is not available? The benefit of learning vi or emacs is your ability to use them from a terminal, a character terminal, or a telnet or ssh session, etc. We will discuss vi here. (I don't know emacs :-)). vi in particular is useful, you will find it in on all versions of Unix. Learn vi and you should be able to edit a file on any Unix system.

## The Joy of Vi

You can start vi by simply typing vi at the command prompt, or you can specify the file you want to edit with vi filename. If the file does not already exist, it will be created for you.

vi consists of two operating modes, command mode and insert mode. When you enter vi you will be in command mode. Command mode allows you to search for text, move around the file, and issue commands for saving, save-as, and exiting the editor (as well as a whole host of other functions). Insert mode is where you actually input and change text.

In order to switch to insert mode, type a (append), i (for insert), or one of the other insert options listed on the next page. When you will see this "INSERT-" appear at the bottom of your screen (in most versions). You can now use input text. When you want to exit the insert mode and return to command mode, hit the escape key.

You can use the arrow keys to move around the file in command mode. The vi editor was designed, to be exceedingly efficient, if not intuitive. The traditional way of moving around the file is to use the qwerty keys under your fingers. More on this below. In addition, there are a number of other navigation keys that make moving around in vi easier, like using $ to move to the end of the current line or w to move to the next text, etc.

If you lose track of which mode you are in, hit the escape key twice. You will know that you are in command mode.

In current Linux distributions, vi is usually a link to some newer implementation of vi, such as vim (vi improved), or in the case of Slackware, elvis. If your distribution includes vim, it should come with a nice tutorial. It is worth your time. Try vimutor at a command prompt. Work through the entire file. This is the single best way to start vi. The navigation keys mentioned above will become clear if you use vimutor.

## Vi command summary

Entering Edit Mode from Command Mode:

- a : append text (after the cursor)
- i : insert text (directly under the cursor)
- o (lowercase "o"): open a new line under the current line
- O (capital "O"): open a new line above the current line

Command (Normal) Mode:

- 0 : move cursor to beginning of current line
- $ : move cursor to end of current line
- x : delete (cut) the character under the cursor
- X : delete (cut) the character before the cursor
- dd : delete the entire line
- dw : delete (cut) to the end of the word
- d$ : delete (cut) to the end of the line
- v : enter visual mode (select text)
- y : yank (copy) text
- yw : yank (copy) to the end of the word
- y$ : yank (copy) to the end of the line
- p : paste after the cursor
- P : paste before the cursor
- :w : save and continue
- :wq : save and quit
- :q : quit and discard changes
- :w filename : save a copy to filename (save as)

The best way to save yourself from messed up edit is to hit ESC followed by :q That will quit without saving changes.

Another feature in command mode is the search. To search for a particular string in a file, make sure you are in command mode and type:

```
/string
```

Where is your search target. vi is an extremely powerful editor. There are a huge number of commands and capabilities that are outside the scope of this guide. Keep in mind there are chapters devoted to vi alone. The importance of vi is that you never know when you will find yourself responding to a Unix machine, at a terminal, and needing to change a file... vi will almost certainly be there for you.

## Configuring “rc” (startup) Services

We'll start our security configuration with the most basic steps... disabling services (and/or daemons) that start when the computer boots. It is common that running programs and network services that you are not using and do not need serves to introduce potential vulnerabilities. There are all sorts of services running on any given workstation, regardless of distribution or operating system. Some of these services are required, some are downright undesirable for a forensic environment. As previously discussed, this is where you will find quite a difference between the various distributions. Ubuntu, for example, uses a new system for managing the starting and stopping of services called upstart. Consult your distribution's documentation for more info, and don't neglect this part of your Linux engine!

Previously, we discussed the initialization process. Part of that process is the execution of “rc” scripts that handle system services. Recall that the file /etc/init invokes the appropriate run level scripts in the /etc/rc.d/ directory. In turn, these scripts test various services also in the /etc/rc.d/ directory for executable permissions. If the script is executable, it is invoked and the service is started. This can be chained, where rc.M checks if an rc script is executable, and so the execution of that checks for more scripts are executable. For example, the test inside the rc.M (multuser init script) for the network services script (rc.inet2) looks like this (abbreviated):

```
root@forensic1:~# cat /etc/rc.d/rc.M
***
# Start networking daemons
if [ -x /etc/rc.d/rc.inet2 ]; then
  /etc/rc.d/rc.inet2
fi
***
```

The code shown above is an if / then statement where the brackets signify the test and the -x checks for executable permissions. So it would read:

```
if the file /etc/rc.d/rc.inet2 is executable, then execute the script
/etc/rc.d/rc.inet2
```

Once rc.inet2 is running, it checks the executable permissions on the network service am, among others. This allows us to control the execution of scripts many
