The output above shows a couple of things (highlights for emphasis). We have the completed run with the -N option, and the output shows that we have a trimmed area. The map file shows the position of unclipped area of the disk (0x00640000) and a size of 0x00010000 (65536 bytes). The status of this area is indicated with an asterisk. Note that the 65536 bytes are exactly 128 sectors, and this is the default "cluster" size used by ddresce. This does not mean that there are 128 sectors that cannot be read. It means the entire cluster could not be read, and the -N option prevented "trimming", or pairing the sectors down to smaller chunks. The cluster size can be controlled with the --cluster-size=X option, where X is the number of sectors in a cluster. We now have a partial image.

Now we can continue the imaging with the same input and output file, and the same map file, but this time we use the -N option, allowing areas to be trimmed, and we add the -r option to specify the number of retries when a bad sector is encountered, which is three in this case.

While we were not able to obtain the entire disk, hopefully you recognize the benefits of the approach: using ddrescue to get the good data first before causing additional damage to bad areas.

## Imaging Over the Wire

There may be occasions where you want to acquire an image of a computer using a boot disk and connectivity. Most often, this approach is used with a boot disk (the machine you are going to). Another computer, the imaging platform, is connected either via a network hub or crossover cable. There are almost infinite sorts of acquisitions take place across the world. The reasons for this approach range from level of physical access to the interface to local resources. As an example, you might come across a machine that has a drive (USB example), then you might need to resort to the network to transfer data. The drive is left in place, and your collection platform is attached through a hub, switch, or crossover cable. Where possible, I would use either crossover cable or own hub. Consider the most secure path between subject and collection is and integrity of your data if you attempt to transfer it across external network. We will concentrate here, and the very basic commands. As always, I urge you to follow.

First lets clarify some terminology for the purpose of our discussion. In this instance, the computer we want to image will be referred to as the *subject*. The computer to which we are writing will be referred as the *collection box*. In order to accomplish imaging across the network, we will need to setup our collection box to “listen” for data from our subject box. Do this using **netcat**, the **nc** command. Once you have the subject computer booted with a Linux Boot CD (preferably one that is set up with forensics in), you’ll need to ensure that the two computers are configured on the same network and can communicate. Checking and configuring network interfaces is accomplished with the ifconfig command. If you run ifconfig -a, you will get a list of interfaces and their current (if any) settings.
