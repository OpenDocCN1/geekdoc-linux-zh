fls can also be useful for uncovering deleted files. By default, fls will show both allocated and unallocated files. We can change this behavior by using other options. In the above command, we run the fls command against the partition able2.dd starting at offset 10260 (-o), showing only file (-F), descending into directories (-r), and displaying deleted entries (-d). Notice that all of the files listed have an asterisk (*) before the inode. This indicates the file is deleted, which we expect in the above output since we specified the -d option to fls.

Have a look at the output for inode number 2138 (root/pics.tar.gz). The inode is followed by realloc. Keep in mind that fls describes the file name. The realloc means that the file name is listed as unallocated, even though the metadata entry (2138) is marked as allocated. In other words, the deleted file may have been "reallocated" to a new file. This comes because there is a file name and a metadata layer. Every file has an entry in both layers and its own allocation status. If a file is marked as "deleted" then this means the file name and metadata are marked as unallocated. If a file is marked "realloc" then this means the file name and metadata is allocated. This occurs if:

- The file was renamed and a new file entry was created for the file.
- The old copies of the name will be "unallocated" even though the file still exists.

In the first two cases, the metadata correctly corresponds to the deleted file. In the last case, the metadata may not correspond to the new file. In case of 2138, it looks as though the file was being moved to the directory .001 (the fls listing of .001 on the previous page). The inode and the data blocks that it points to remain unchanged and in "allocated", but it has been "reallocated" to the new name.

If you look at the output of our last fls command, you will see a deleted file called lrkn.tgz located in the /root directory (the last file in the output of our fls command, before the list of files - the asterisk indicates it is deleted):

```
r * 2139: root/lrkn.tgz
```

The inode displayed by fls for this file is 2139. This same inode also points to another deleted file in /dev earlier in the output (same file, different location). We can find all the file names associated with a particular data entry by the find command:

```
barry@forensic1:abled$ find -o 10260 -a able2.dd 2139
* /dev/tty20/lrkn.tgz
* /root/lrkn.tgz
```

Here we see that there are two file names associated with inode 2139, and both are deleted, as noted again by the asterisk (the -a ensures we get all inode associations). Continuing on, we are going to use istat. Remember that fsstat took a file system as an argument and reported statistics about that file system. istat does the same thing; only it works on a specified inode or metadata entry. In NTFS, this would be an MFT entry, for example. We use istat -o to gather information about inode 2139:

```
barry@forensic1:abled$ istat -o 10260 able2.dd 2139 | less
```

Direct Blocks:

This reads the inode statistics (istat), on the file system located in able2.dd in the partition at offset 10260, from inode 2139 found in the fls command. There is a large amount of output here, showing all the inode information and the file system blocks ("Direct Blocks") that contain all the file's data. We can either pipe the output of istat to a file for logging, or we can send it to less for viewing.
