# dd and Splitting Images

It has become common practice for digital forensics to split the output of our imaging. This is done for a number of reasons, either for archiving or for use in another program. We will first discuss split on its own, then in conjunction with dd (on the fly) splitting.

For example, we have our 40GB image and now want to split it into 2GB parts so they can be written to DVD media, for example!, or if you wish to split the files on a system with limited file sizes and a particular size, you might want to split the image into 2GB pieces. For this we use the split command.

split normally works on lines of input (i. from a text file). But if we use the -b option, we split to treat the file as binary input and lines are ignored. We can specify the size of the files we want along with the prefix we use for the prefix files. split -d option gives us numerical numbering (*.01, *.02, *.03, etc.) for the output files as opposed to alphabetical (*.aa, *.ab, *.ac, etc.). The -a option specifies the suffix length. The command looks like:

```
split -d -a N <file to split> <prefix of output files>
```

where N is the length of the extension (or suffix) we will use and X is the size of the resulting files with a unit modifier (M, G, KM, KG, etc). For example, with our image of /dev/sdc, we can split it into 2GB parts using the following:

```
root@forensic:/case1/images# split -d -a 3 -b 2G case1.disk1.raw
case1.disk1.split
```

This will result in 20 files (2GB in size) each named with the prefix case1.split1 as specified in the command, followed by 000, 001, 002, and so on. The -a option with 3 specifies what we want the extension to be at least 3 digits long. Without -a 3, our files will be named *.01, .02, .03, etc. Using 3 digits maintains consistency with other tools. Note the trailing
