# Host Based Firewall with iptables

It is common practice for many forensic practitioners using other operating systems to utilize some sort of host based firewall program to monitor their network connections and provide some form of baseline protection from unsolicited access. You may want to do the same thing on your Linux workstation, or in some cases, be required to run a host based firewall by agency or corporate policy. In any event, the most commonly used Linux equivalent for this sort of thing is the iptables network packet filter.

All of the subjects covered in this guide, this is one of the most complex, with direct relationship to actual forensic practice. It is however, too important not to cover if we are going to discuss workstation security. A host firewall may not be a requirement for a good forensic workstation, especially that many agencies and companies are already working in a well protected (or air gapped) network environment. However in my opinion, it's a very good idea. It's all too common to see Linux users rely on the notion that Linux is "just more secure" than other operating systems. And I know from personal experience that there are digital forensic practitioners out that have fully connected workstations and don't take these precautions.

Unlike most of the other subjects in this configuration setup, iptables requires a bit more explanation to effectively set it up from scratch than I'm willing to put in a simple practitioner's guide. As a result, rather than giving a detailed description and step by step instructions, we are going to briefly discuss how to use the iptables configuration and provide a baseline script to get the reader started. Our "baseline" script has been provided by Bobby Workman (http://www.rworkman.com).

First, we need to make sure we understand the differences between the protections provided by TCP wrappers vs. iptables. As we mentioned earlier, TCP wrappers blocks access at the application level, whereas iptables blocks traffic at the specified interface. This is an important distinction. iptables essentially sits between the network and TCP wrappers and accepts or rejects network packets at the kernel level.
