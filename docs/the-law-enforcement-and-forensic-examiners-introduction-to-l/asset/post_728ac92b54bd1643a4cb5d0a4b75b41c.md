So we see that the feature was found in a Microsoft Word document .docx format, which is compressed XML. This file can be viewed with the catdoc script (remember catdoc is similar, for the XML zipped .docx format). We will do this at the end of the exercise. 

After the feature files, we move on to the histogram file. A histogram is a simple file that will list the features along with the number of times that feature was found. This frequency reporting is one of the most useful aspects of bulk_extractor. This is the histograms that provide a great deal of context to the contents of a disk image. Particularly where investigations involving fraud or PII are concerned, the frequency of a credit card number or email address context at a glance, what accounts were used and the most frequently used accounts, or where the closest accounts might be, In our case the histogram shows only one instance (n=1) of our search term.

```
berry@forensic1:~$ find_histogram.txt
# BANNER FILE NOT PROVIDED (-b option)
# BULK_EXTRACTOR-Version: 1.5.5 ($Rev: 10844 $)
# Feature-Recorder: find
# Filename: NTFS_Pract_2017/NTFS_Pract_2017.E01
# Histogram-File-Version: 1.1
n=1 uranium-235
```

Let's run bulk_extractor again, but then we'll leave the default scanners running and use list of search terms instead (just two). Change back to your home directory, and using a text editor (vi), create a file with these twos:

```
[Uu] ran-235
262698143
```

...we turned our first term into regular expression that looks for either an upper or lowercase letter to start the word. The second is a "known victim" social security number². Save the file as myterms.txt.

We'll also create a banner file so that all of our files have a heading that identifies the case and the examiner/analyst. Again, using a text editor enter information you might want at the top of each file:

```

```

> ². The second term is a social security number. Numbers for this exercise were generated with http://www.thegenerator.com/ssngenerator
