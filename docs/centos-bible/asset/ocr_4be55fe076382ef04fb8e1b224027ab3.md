Networking

**NOTE** If you want to off-load the processing of mail for a particular domain that is currently being directed to your Sendmail server, you can use the `/etc/mail/mailertable` file. After setting up a DNS MX record to point to your Sendmail server for this domain and listing that domain name in the mailertable file, you can identify another computer that Sendmail will forward all the traffic for that domain. For example:

```
example2.com
		smtp:mxl.example.com
```

This example shows that all messages destined for `example2.com` that are processed by your Sendmail server are forwarded to the server named `mxl.example.com`. The `smtp` indicates that the server supports Simple Mail Transfer Protocol.

# ## Configuring Virtual Users

Incoming mail to your Sendmail server will be directed to your machine with a request to deliver the message to a particular person at a particular domain name. For each domain that the Sendmail server supports, you can identify how e-mail to the mail recipients of that domain is treated.

With Sendmail, you set up virtual user definitions in the `/etc/mail/virtualuser table` file. Essentially, you are telling Sendmail to re-direct messages addressed to particular usernames or domain names based on definitions you set up.

Configuring the virtualuser table is particularly important if your server is handling mail for multiple domains. That's because, by default, mail for the same username (regardless of the domain name) will be stored in the same mailbox. For example, if your server handles mail for `example2.com` and `example.com` domains, mail for `timothy@example2.com` and `timothy@example1.com`, would all be directed to the `/var/spool/mail/timothy` mailbox. With the virtualuser file, you can change that behavior in a lot of ways.

The virtualuser table is empty by default. The following are some examples that illustrate how incoming messages can be directed in different ways based on virtualuser definitions.

```
timothy@example.com		timothy
btoronczyk@example.com		timothy
fgordon@example.com		fgordon@spidermaker.com
info@example.com		info-list
bogus@example.com		error:nouser No such user here
@example3.net		example-catchall
@example2.com		%1@example3.com
```

In the first two lines, incoming mail destined for `timothy` or `btoronczyk` at `example.com` is directed to the mailbox for the local domain user named chris. In the next line, any e-mail directed to `fgordon` in the same domain goes to `fgordon@spidermaker.com`. After that, e-mail sent to the `info` username is saved to the local `info-list` mail account.

The line beginning with `bogus@example.com` illustrates an `error` condition. Here, e-mail destined for the user named bogus will be rejected with the error message No such user here
