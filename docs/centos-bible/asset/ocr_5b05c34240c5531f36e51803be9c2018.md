# Setting Up an LDAP Address Book Server

description: Example Address Book Administrator

```
# members, example.com
dn: ou=members,dc=example,dc=com
objectClass: top
objectClass: organizationalUnit
ou: members

# John Wilson, example.com
dn: cn=John Wilson,ou=members,dc=example,dc=com
objectClass: organizationalPerson
objectClass: inetOrgPerson
cn: John Wilson
mail: jbwilson@example.com
givenName: John
sn: Wilson
uid: jbwilson
o: Example Organization
```

In this example, I asked to use simple authentication (clear-text passwords with the `-x` option), start at the base (`-b`) of the example.com directory to begin the search, and list all object classes (`objectClass=*`). If you like, you can pipe the output to `less` so you can page through it.

# 10. Debug Your Directory — Don't expect your LDIF file to load the first time without any errors. While you debug your address book directory, I recommend that you use a non-production machine and just clear out the database files after each failed attempt to load your directory. Assuming that you kept your LDAP directory files in `/var/lib/ldap` and that it's OK to erase the whole database while you debug your entries, you can do the following:

> **WARNING**  You're about to erase the LDAP directory files you created. Don't do this step if you have information in your LDAP directory files that is not in your LDIF file. Don't erase your LDIF file, because you need it to re-create your directory files.

```
# /etc/init.d/ldap stop
# rm /var/lib/ldap/*
# /etc/init.d/ldap restart
# slapadd -x -D "cn=Manager,dc=example,dc=com" -W -f people.ldif
```

Repeat this process until you feel that your LDIF file and all the information that it contains have been properly loaded into your LDAP directory files.

At this point, you can decide if you need to further tune your LDAP directory (as described in the section, “More Ways to Configure LDAP”). After that, I recommend that you check that your LDAP address book directory is working properly by trying to access it from Thunderbird, using its Contacts feature (as described later in this chapter).
