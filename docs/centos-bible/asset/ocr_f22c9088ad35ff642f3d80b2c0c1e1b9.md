Instead of using the simple hostname to get the computer's IP address, you can enter an IP address (instead of the name) or a fully qualified hostname. In the following example, the `dig` command is used with a domain name to get information about the addresses for a domain:

```
```
# dig example.com
:<>> Dig 9.3.4-P1 <<<>> example.com
; global options: printcmd
; Got answer:
; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 38166
; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 2, ADDITIONAL: 1

; QUESTION SECTION:
;example.com. IN A

; ANSWER SECTION:
example.com. 604800 IN A 208.77.188.166

; AUTHORITY SECTION:
example.com. 604800 IN NS ns1.example.com.
example.com. 604800 IN NS ns2.example.com.

; Query time: 24 msec
; SERVER: 10.0.0.1#53(10.0.0.1)
; WHEN: Tue Mar 17 02:12:32 2009
; MSG SIZE rcvd: 129
```
```

Sections in the output from `dig` include a question section and an authority section. The results show name server assignments and addresses associated with the domain you're querying about. The `nslookup` command is another tool you can use to look up domain information. In the following example, `nslookup` looks up the server that is resolving ftp.example.com:

```
```
# nslookup ftp.example.com
Server: 123.45.67.1
Address: 123.45.67.1#53

Name: ftp.example.com
Address: 123.45.67.4
```
```

The output from the `nslookup` command includes the name of the computer fulfilling the request and its IP address, along with the name and address of the computer you're asking for. Try `nslookup` with an IP address (such as 10.0.0.1) to make sure that reverse lookup works. You can also consider using `dig` instead of `nslookup`.

To check the status of the named server that is running on your local system, use the same script that starts `named`. Type the following to check the status of your DNS server daemon:

```
```
# /etc/init.d/named status
number of zones: 5
debug level: 0
