# 02 Get Archon runtime

Since 2014, several versions of Archon runtime have been released, from 1.0 to 2.1. Viad Filippov, the main developer, has been in a constant race for the latest and greatest Chrome code, whilst fixing Archon bugs at the same time. As a result, different combinations of Chrome and Archon versions may or may not work for you. The default choice, however, is to try the latest Archon runtime build from the project’s brand new site [archon-runtime.github.io](archon-runtime.github.io), with the current stable Chrome version from Google. At the time of writing, the latter software is up to version 41.0.x.

# 03 Prepare your browser

Archon is distributed in a form of unpacked Chrome extension. When you download it, you get a ZIP file with an extension folder inside. To be able to install unpacked extensions, go to [chrome/extensions](chrome/extensions) and tick the Developer mode checkbox. You will immediately see the new button, one of them will be the ‘Load unpacked extension...’ option. Click it and navigate to the folder where you unzipped the downloaded Archon package earlier. Once you click OK, it will appear in the installed extensions list. Before you proceed to the next step it is useful to check for WebGL support in Chrome, which can make use of hardware acceleration for graphics and help browser perform better. Go to [chrome://gpu](chrome://gpu) and see if there are any ‘software only’ strings. If so, switch to [chrome://flags](chrome://flags) and enable the ‘Override software rendering list’ parameter.

# Troubleshooting

Archon not working as it’s supposed to? Here’s how to find out what the trouble is and fix it

From a user’s perspective, Archon isn’t stable, so you may encounter errors and lockups. If things went wrong from the start, ensure that you’re using the Archon of the right architecture. After that, ensure Google Native Client is enabled (scroll your brow chrome://flags/#enable-nacl-flag).

Some apps may not launch and complain of a missing ‘message’ element for extName. To fix it, edit the file, _localize_en-mesages.json_,inside the extension folder and add the missing _text_ there. It should now look like this:

```
```
{
  "appNotSupported": {...},
  "extName": {
    "description": "Extension name",
    "message": "Whatever you like"
  }
}
