## 为什么选择 Bash？

> “用 Bash 还是不用 Bash，这是一个问题！”

Bash 脚本语言是‘老派’语言之一，可以追溯到 20 世纪 80 年代中期。它最初是作为 Unix 项目的一部分联合开发的。这就是为什么它的某些 (Unix/Linux) 函数/工具与 C 是相同的。例如，打印命令 `printf`。Bash 是任何基于 Unix/Linux 操作系统 (OS) 面向的核心。这就是为什么今天它对资深系统管理员专家和熟练用户来说仍然重要。它的长寿充分说明了它的实力、易用性和多功能性。

正因为与操作系统的紧密集成，事实上，所有的 Unix/Linux 命令加上你可能安装或实现的任何内容，在 Bash 中都是直接可用且极易调用的。

# 第一步

任何人当然可以在脚本文件中列出诸如 `cd ..; ls -al` 这样的命令并运行它。事实上，这样做是入门 `Bash` 编程的极佳方式。

创建一个名为 `myscript` 的文件，在其中放入一些命令，并使用 `chmod +x myscript` 使其具有执行权限。然后只需输入 `./myscript`，`Bash` 就会执行其中包含的所有命令。

除了 `Bash` 之外，还有其他几种 Shell 脚本变体。规定脚本的第一行应该始终以所谓的“shriekbang” `#!` 开头，这指示了需要哪种解释器（shell）以及它具体的所在位置。通常情况下，它是：`#!/bin/bash`

然而，在 Android 手机上，`Bash` 会安装在一个非标准的、路径较长的位置。因此，规范应该始终指向它所在的确切位置，否则它可能无法运行。随后的任何普通命令都将像你在提示符中输入它们时一样执行。`#` 将行的剩余部分变为注释。`Bash` 非常简洁。仅仅的一行代码就可能发生很多事情，因此慷慨地编写解释性注释是一个明智的主意。

注意：有时直接通过读取-评估-打印循环（REPL）尝试操作是很好的，这就是交互式终端的本质。在输入正确答案后，可能会出现“已找到命令（command found）”。例如，尝试这段简单的算术运算：`$((1+1))`。这其实没有问题，输出信息也是 `2`。你可以使用 `echo` 或 `printf` 命令来阻止这种情况发生，这些命令会丢弃它们的值（在此情况下不将其传回 REPL），如下所示：`echo $((1+1))`

# 引号、引号、引号

如今，`Bash` 被粗心的程序员认为容易产生编程错误，但它实际上并不糟糕，只要我们注意一些陷阱和“坑（gotchas）”。

主要的潜在问题是空格位置错误。这是我们为 `Bash` 将程序和数据视为同一物而付出的代价。你可能还能读懂这些。然而，计算机是“语法纳西主义”。它们“讨厌”任何输入错误或歧义。空格对任何文本的结构都至关重要，这意味着它们对 `Bash` 编程语言的结构同样重要。

`Bash` 中的一切都只是文本字符串（EIJ 原则）。这意味着 `Bash` 只知道并理解文本块。稍后我们将看到这种简单性如何带来一些惊人的机会和优势。

第一个首要的优势是简单：用户和 `Bash` 都不需要担心各种不同的类型并对它们进行检查。真的只有文本以及有时被显式注释为数字的文本。

然而，能力越大责任越大。我们必须准备好更多的错误，因此一次测试一小单元程序是明智的。如果遇到大麻烦（即难以找到 bug），强烈建议在程序代码中引入额外的 `printf` 语句，打印出你怀疑可能有错误的变量值。这种方法比任何语言中盲目的通用调试更有针对性，因此更成功。之后，可以很容易注释掉或删除这些额外的语句。

为了在不同情况下有效处理文本，有几种不同的标记或引用方式。每种方式都有其特定的效果，并决定了引用文本如何被解释或执行。理解所有它们以及它们之间的差异非常重要。

## 字符

首先，是对某些特殊和不可见的单个字符进行“转义”。一个有趣的例子：

```
printf "My book sales reached 200%%\n"
```

某些特定规则仅适用于 printf 格式化字符串。在这里，不可打印的字符“换行符”被编码为 `\n`。可打印字符 `%` 通过双倍处理来转义，否则它在 printf 格式化字符串中具有不同的含义。换句话说，在这一语境下，它是一个“保留字符”。

在任何地方（不仅仅是 `printf` 之后）双引号字符串的通用规则规定，以下 Bash 保留字符必须在它们前面加上反斜杠 `\` 来进行转义：美元符号、反引号、双引号、反斜杠、换行符。这里的转义“换行”指的是实际的换行，例如代码行末尾，我们希望它不中断地延续到下一行。

让我们来看字符串（字符序列）。

## 字面量字符串 (Literal string)

单引号 `'...'` 包围着一个简单的字面文本单元。单引号内的任何内容都不会被求值。示例：

```
1 'the cat sat on the mat'
```

要让单引号成为字符串的一部分而不提前终止它，有必要使用外部双引号，如下：

```
1  "the cat's mat was eaten by a rat"
```

## 解释性字符串 (Interpreted string)

双引号具有额外功能，可以评估（扩展）其中找到任何变量或表达式。`expansion` 通过在变量/表达式前面紧跟一个美元符号 `$` 来指示。事实上，除了上述字面字符串外，美元符号在任何其他地方也会引起 `expansion`。示例：

```
1 "The cat's name is $NAME"
```

变量大写只是一种实用的约定。

注意：在所有的评估上下文中，通常建议对单个变量使用双引号引用，例如 `"$FILENAME"`，以防止包含空格的文件名（一种极其糟糕的 Windows “发明”）被误解释为几个不同的文件，而不是我们预期的单个文件。同样，在测试中，对变量进行双引号引用可以确保它始终至少返回一个“空字符串”值。否则，未设置的变量在扩展后就会消失，这有时会导致程序语法错误。

## 赋值 (Assignment)

在给变量赋值时，赋值的左侧是不进行求值的，因此它不需要美元符号：

```
1 NAME='Bob'; ANOTHERBOB=$NAME
```

此外，要非常小心不要在赋值运算符 `=` 周围使用任何空格。

## 变量扩展 (Variable expansion)

`${VAR}`（在 `$` 之外使用大括号）是另一种引用变量的方法，称为变量扩展。在对变量进行常规的求值后，它还可以对该值应用某些特殊函数。这些函数可能涉及（例如）搜索和选择路径/文件名的特定部分，如下：

`EX="${FILESPEC##*.}"`

这会将最后一个文件扩展赋值给 `EX`，方法是删除 `$FILESPEC` 值中从最后一个点之前及包含的所有内容。通配符字符 `*` 用于匹配该点之前的所有内容。

`${V#*"$C"}` 删除 `$V` 值中从开始到包括 `$C` 中指定字符第一次出现处之前的所有内容。

`${V##*"$C"}` 删除从开始到包括 `$C` 最后一次出现处之前的所有内容。

`${V%"$C"*}` 删除从末尾到包括（从末尾开始）第一次出现 `$C` 的的所有内容。

`${V%%"$C"*}` 删除从末尾到包括（从末尾开始）最后一次出现 `$C` 的的所有内容。

`${V:=value}` 如果 V 未设置，则将其初始化为（默认）值。

`${V:?error message}` 如果 V 未设置，则打印错误消息并退出。该消息可以是一个双引号的解释性字符串。

`${VAR@Q}` 通过在需要时应用单个字符的反斜杠转义规则，自动转换 `$VAR` 的值。如果不确定哪些字符需要转义，请请教专家（Bash 本身）。当某些文本（可能包含特殊字符）被读入 `$VAR` 然后需要由 Bash 以某种方式进行解释时，这非常有用。

## 逻辑求值 (Logical eval)

`[...]` 对表达式进行逻辑求值（测试）。它预期返回一个布尔真/假值。在比较数字时，可以使用比较运算符 `-lt` `-le` `-eq` `-ne` `-gt` `-ge`，在比较字符串时使用 `=` 和 `!=`。它可以作为更大表达式的一部分，通过逻辑运算符连接几组方括号测试：`!`、`||`、`&&`（分别意味着“逻辑非”、“逻辑或”和“逻辑与”）。

事实上，Bash 中的一切（In fact, everything in Bash is an expression）都是一个表达式。即使是执行的命令也会返回一个“退出状态”值：成功返回 0（真），用户定义的失败返回 1-255。0 被解释为真，因为它表示成功退出，因此程序调用可以包含在测试中。

使用 `=~` 运算符的正则表达式（regexp）比较测试应该包含在双括号 `[[...]]` 中。

可以直接对程序、函数和工具的简单调用进行成功结果测试，而不需要方括号，例如：

```
1 mkdir somedir || echo failed to create somedir
```

请参下一章节了解这些条件语句的简单形式。

测试变量是否设置或未设置是常见的：

- `[ -n "$VAR" ]` 如果 `$VAR` 被设置为非零长度的内容，则为真

- `[ -z "$VAR" ]` 如果它未设置，则为真

- `[ -f "$VAR" ]` 如果 `$VAR` 的值是一个存在的文件，则为真

- `[ -d "$VAR" ]` 如果 `$VAR` 的值是一个存在的目录，则为真

- `[ -r "$VAR" ]` 是一个可读的文件

- `[ -h "$VAR" ]` 是一个符号链接

- `[ -w "$VAR" ]` 是一个可写的文件

- `[ -s "$VAR" ]` 是一个非零大小的文件

- `[ -x "$VAR" ]` 是一个可执行文件

- `[ "$F1" -ef "$F2" ]` F1 等于 F2

- `[ "$F1" -nt "$F2" ]` F1 比 F2 新

- `[ "$F1" -ot "$F2" ]` F1 比 F2 旧

- `[ "$F1" -eq "$F2" ]` F1 等于 F2

## 算术求值 (Arithmetic eval)

`$(( NUM1+NUM2 ))` 或“算术求值”会导致包含的表达式进行求值。Bash 没有浮点类型或对其进行计算（但请参见稍后的章节）。

有常用的（整数）算术运算符：`+`、`-`、`*`、`/`、`%` 以及它们的赋值版本 `+=`、`-=`、`*=` `/=`、`%=`，它们将右侧（RHS）的值加到左侧的现有值上。如果 `$COUNTER` 未初始化，将被赋予初始值 0（仅在这些赋值中）。

`let` 形式触发算术求值，类似于双括号，但它随后会丢弃产生的值。

当不确定运算符的优先级时，使用额外的括号。

## Eval (Eval)

`eval command1 ... argn` 是普通的求值。它在当前 shell 中执行 `command1 ... argn`。它可以用于构造并执行任何函数调用或外部工具调用。

对比：`printf "$P: "` 返回变量 `$P` 的格式化值，而 `eval $P` 此外还将其作为命令执行。



```bash
1 P=pwd; printf "$P: "; eval $P
```

## 花括号（Braces）

```bash
1 { P=pwd; printf "$P: ";  $P; }
2 
3 {
     P=pwd
     printf "$P: "
     $P
7 }
```

花括号用于将多个命令绑定为一个“块”，在当前 shell 中执行。注意最后一个括号之前的分号，如果没有它，`$P` 的值就不会执行。

在多行语法（最后一个版本）中，换行取代了分号的作用。

思考问题：这会打印什么？试一试！只有少数语言拥有这种强大（某些人说非常危险）的“程序即数据”机制。Lisp 就是其中之一。

事实上，这三个版本产生相同的结果，区别仅在于它们的语法。

## 子 shell 求值（Subshell eval）

`$( command1; command2; )&` 与上述花括号的效果相同，不同之处在于为求值（命令替换）启动一个新的子 shell。这会带来一些微小的开销。然而，它对于通过在右括号后可选添加 `&` 来“分出”后台进程非常有用。此类进程将在独立的线程中并行运行。

注意它们的输入和输出不要错乱。此外，在启动另一个依赖后台作业结果的进程之前，务必小心地使用 `wait` 命令！利用并行性通常比传统的单线程顺序进程需要更细致的思考。作为一个粗略的法则，可以“从顶部开始”，即首先并行运行大型独立任务。这样，这些任务中的所有计算都将在单独的核心上运行，而不会被细粒度的细节所缠绕。

这种 `&` 机制对于更好地利用现代多核处理器非常有用。操作系统负责将用于执行的线程分配到可用的物理核心。

对于简单命令，使用更简洁的反引号语法 `` `command` `` 有时会更方便，但不推荐用于嵌套求值，因为转义多个反引号可能会变得混乱，并且容易出现输入错误和疏忽错误。

## 文本并置（Text juxtaposition）

我们可以通过变量、字符和其他字符串的简单并置来构建任意字符串。不需要像大多数其他编程语言那样显式地调用 `concatenate`、`append` 等函数：

```bash
1 H=Hello
2 W=World
3 # 构建一个句子: 
4 # 在两个单词之间插入一个转义空格 
5 # 并在末尾添加 !
6 echo $H\ $W!
```

并置的另一个常见用途：

`$PATH/$FILE.$EXT`

## Bash 分支（Bash Branching）

`if` 语句具有以下结构。`else` 块是可选的，而 `fi` 是始终强制的。

```bash
1 if logical-expression; then
2     statement1
3     ...
4     statementn
5 else
6     neg-statement1
7     ...
8     neg-statementn
9 fi
```

制表符缩进（Tabbing）在某种程度上提高了代码的可读性。该表达式通常涉及方括号中的逻辑测试和逻辑运算符。

Bash 很容易爱，但有时是一种爱恨交织的关系。以这个 `if` 语句为例，忘记在 `then` 之前加上分号，你就会陷入深渊。如果这种奇特的语法让人们对 Shell 编程产生反，那就太可惜了。

幸运的是，有更好的分支方法，至少在简单情况下是。复杂的 `if` 语句最好还是避免，因为它们是影响程序基础逻辑的最大错误来源，并且很难被发现。

当某些必要条件不满足时，使用简单的验证测试，从循环内部提前 `continue` 或 `break`，从函数中 `return` 以及从程序中 `exit`。这在实际上将下面的代码转换为了 `else` 分支，而没有让复杂的条件结构一直拖下去。除了是一种良好的编码习惯外，它倾向于提高程序效率。我们将其称为*提前中断原则*（early break principle, EBP）。

## 短路逻辑评估（Short circuit logic evaluation）

在任何上下求值逻辑（布尔）表达式时，在表达式的所有各个部分被求值之前，结果的值通常是已知的。这怎么可能呢？

在合取（`&&`）中，只要第一个合取项返回 `false`，整个结果就为 `false`。

相反，在析取（`||`）中，只要第一个析取项返回 `true`，结果就为 `true`。

这些逻辑运算符具有相同的优先级，并且通常从左到右处理。

逻辑的*短路求值*属性用于人工智能（AI），以便对游戏播放和搜索应用中的所谓的 AND-OR 树进行高效评估。然而，我们也可以在谦陋的 Bash 程序中使用它。

为了利用这一属性，我们引入了两种条件判断：

### 正向条件（Positive conditional）

```bash
1 [ test1 ] && [ test2 ] && [ testn ] && { posblock }
```

在这里，只有当每个测试都返回 `true` 时，才会执行结尾的 `posblock`。一旦第一个测试求值为 `false`，整个操作就会失败并立即停止。因此该表达式“短路求值”。

### 负向条件（Negative conditional）

```bash
1 [ test1 ] || [ test2 ] || [ testn ] || { negblock }
```

在这里，只有当每个测试都返回 `false` 时，才会执行结尾的 `negblock`。一旦第一个测试求值为 `true`，整个操作就会成功并退出。

### `if` 语句的逻辑形式

比较这两种形式，理解逻辑在表达多样化条件时更优的便利性：

```bash
1 if [ condition ]; then posblock; else negblock; fi
2 [ condition ] && posblock || negblock
```

### 优点（Benefits）

这种语法（结构）比 `bash` 以及大多数其他语言提供的 `if` 语句更清晰、更紧凑、更通用且不易出错。

语义（含义）更具表现力，一份的价格提供了多种类型不同的 `if` 语句。

通过排列各个测试来鼓励*提前中断*，可以提高程序效率。参见上面介绍的 EBP 原则。在正向条件中，最可能失败的测试应该放在前面。在负向条件中，最可能成功的测试应该放在前面。

当不确定结果的概率时，在两种情况下，按照从快到慢顺序排列测试都是最好的。

可以使用此框架构建任意复杂的命题逻辑表达式，使用 `&&`、`||`、`! (not)`。在需要时应添加方括号以消除歧义（就像算术中使用括号一样）。例如，`! test1` 可用于将正向的 `test1` 混入到负向条件中。或者，使用 `! test2` 将一个负向的 `test2` 添加到正向条件中。通过将负向条件（析取）改为正向条件（合取），通常可以完全避免否定甚至原始的负向测试。

## 语句链（Chaining statements）

因为在 Bash 中，语句和表达式之间没有真实区别，上面的短路机制可以同样用于链式命令。此外，因为它们返回成功（真）或失败（假）作为值，将在效率上获得类似的 EBP 收益。

这与后来发明的被称为“逻辑编程”的编程类型有明确的关系。例如查看 Prolog 编程语言，它是围绕求值（正向）合取项和在失败时回溯的思想构建的。

### 正向（与）命令链（Positive (and) commands chaining）

```bash
1 command1 && ... commandn
```

这通常用于需要所有命令都成功的情况。

注意，这里使用逻辑“与”运算符来连接命令，代替了之前使用的分号。这种的效果是，一旦任何单个命令以失败状态退出，就会返回假值并*提前中断*。推测这种结果应该通过某种错误消息来报告，在末尾加上 `|| printf "error message\n"` 或部署某些补救措施。

其余的命令将被忽略，而如果使用分号分隔符，它们无论返回状态如何都会继续执行。

### 负向（或）命令链（Negative (or) commands chaining）

```bash
1 command1 || ... commandn
```

注意，现在使用逻辑“或”运算符代替了分号。这种的效果是，一旦任何命令以成功状态退出，就会从该块中*提前中断*。其余的命令将被忽略。这里的的逻辑意图是，任何一个命令的成功就是我们需要的。

或者，这种形式也可用于预期（或希望？）它们都应该失败的情况，例如在检查安全违规的发生时。那么整个块应该返回失败。如果它在某点成功了，可以通过在末尾加上 `&& printf "Security breached!\n"` 或任何其他补救措施来报告。

Bash 也拥有 `functions`（函数），它们的工作方式与任何外部脚本都一样，不同之处它们以文本形式插入到被使用的脚本中。在定义它们的文件中调用它们的好处是，它们不会在子壳（subshell）中运行。

尽管有这些便利性，但也存在意外的全局变量冲突的危险，这通常会导致严重的错误。因此，强烈建议对函数自身的工作变量使用 `local` 声明。这可以将它们隔离开来，就像该函数实际上位于自己一个独立的脚本文件中并在子壳中运行一样。请注意，函数还会继承全局声明并属于其脚本（shell）的任何文件流标识符。关于输入/输出的更多内容稍后介绍。

在函数中，就像在任何程序脚本中一样，形式参数通过特殊变量 `$1`、`$2`……等来标识。它们一一对应，并赋值为在函数/程序调用时提供的实际参数值。

为了从 Bash 函数中返回 0-255 以外的值，通常应该使用全局 `stdout` 流 1。也就是说，在最简单的情况下，在函数内部使用 `echo` 或 `printf` 命令将其返回值写入标准输出。这将作为函数调用的结果返回。

这里有一个带形式参数 `$1` 的递归函数示例。

在编写递归函数时，终止条件应该始终放在第一。注意这里使用了大量但在此遗憾是必要的算术评估双括号：`$((...))`。为了减少括号的数量，递归调用本身在这里通过反引号子壳评估（有时称为命令扩展）进行评估，它的工作方式与 `$(...)` 相似：

```bash
1 function factorial {
2   [ $1 -lt 3 ] && echo $1 || \
3      echo $(( $1*`factorial $(( $1-1 ))` ))
4 }
5 time factorial 20
6 2432902008176640000
7 real    0m0.027s
8 user    0m0.026s
9 sys     0m0.005s
```

请注意，对于较小的参数，答案将在没有警告的情况下溢出，因为 21 的阶乘已经大于 64 位整数的最大值。

使用迭代实现将比上述堆叠多个子壳调用更有效。在这里我们使用了“类 C”形式的迭代 `for` 循环，它递减到 2，并将所有（降序）整数累积乘到局部变量 `F` 中。如果提供的参数小于三，循环将什么都不做，参数值将立即作为答案回显到 stdout。

```bash
 1 function itfactorial {
2   local F=$1
3   for (( i=$1-1; i>1; i-- )); do F=$(( $F*i )); done
4   echo $F
5 }
6 time itfactorial 20
7 2432902008176640000
8 real    0m0.000s
9 user    0m0.000s
10 sys     0m0.000s
```

这次由于是在当前 shell 中进行评估的且没有使用栈，速度快到计时器都无法记录。

然而，应该指出的是，Bash 作为一种解释型语言，并不算快。因此，最大速度很少是主要关注的问题。速度是相对的。如今，得益于更快的处理器，即使是 Bash 的运行速度也比几年前的 C 等快速语言要快。复兴的另一个良好理由？尽管如此，Bash 更强大的点无疑是便利性、多功能性和紧凑性。

## 循环和控制语句

Bash 还配备了常用的 `while`、`until` 和 `for` 迭代循环，外加 `case` 语句。这不是一个困难或有趣的话题，所以我们不会对其进行过多探讨。通过简单阅读一些现有的实用代码可以更轻松地吸收。我们已经遇到过 `for` 循环的一种形式。`case` 语句将在接下来的章节中的某些示例中使用。

无限循环（依赖在数据耗尽或类似情况下调用 `break` 退出）可以是一种非常有用的机制。它也被用于人机交互，其实一个很好的例子是 REPL（读取-评估-打印循环）。用户通常通过 `Ctrl-D` 关闭输入或通过 `exit` 关闭终端来手动终止此类交互式会话。如果你在终端中尝试以下示例，请准备好快速输入 `Ctrl-C` 来终止它们。请注意它们都设置了无限循环。

```bash
1 while true; do
2   echo 'I am a lumberjack and I am OK'
3 done
```

```bash
1 until false; do
2   echo 'I sleep all night and work all day'
3 done
```

当然，`while` 语句更常用的形式是读取某些普通文本文件 `$F`。在这里，`read` 语句将在末尾返回 `false`：

```bash
1 cat "$F".txt | while read LINE; do
2   processline $LINE
3 done
```

我们已经遇到过类 C 版本的 `for` 命令，但它还有两种更有用的形式。这种形式对当前目录下的所有 `txt`（文本）文件应用 `processfile`：

```bash
1 for F in ./*.txt; do
2   processfile "$F"
3 done
```

这个版本的 `for` 以步长 3 遍历 0..100 的取值范围（并将它们全部打印在同一行）：

```bash
1 echo 'Multiples of three: '
2 for MULT3 in {0..100..3}; do
3   printf "$MULT3 "
4 done
```

## 处理参数

将参数传递给程序和函数是使其更通用、更有用的主要方法。它是抽象过程的一个重要部分。因此，大多数 Bash 脚本都期望某些参数，并且需要处理（读取）这些参数。

```bash
#!/bin/bash
# 此程序期望一些选项，
## 随后是三个强制性的的目录路径。

## 程序的路径/名称始终位于 $0 中。 
## 在这里我们使用 `##*/` 删掉程序名称之前的路径
PROGN=${0##*/}

## 将频繁使用的消息封装到函数中；
## 它们的输出被重定向到 stderr (>&2)
function usage {
   printf "Usage: $PROGN \
   [-h][-b][-c][-x][-q][-r][-u][-v][-z] \
   indir keydir outdir\n" >&2
}

function helpmsg {
   usage
   printf "\t%s\n" \
     '-b | --b64 : 测试 base64 编码文件' \
     '-c | --clean : 归档' \
     '-h | --help : 打印此文本' \
     '-q | --quiet : 关闭最终总结' \
     '-r | --recurse : 同时处理子目录' \
     '-u | --update : 归档' \
     '-v | --verbose : 详细报告' \
     '-x | --hex : 测试十六进制文件' \
     '-z | --zstd : 使用 zstd 压缩' >&2
   exit 1
}

## 使用实用工具 `getops` 进行选项解析： 
### 将列出的选项（即跟在 - 后面的单词）
### 放入 $OPT 中
while getopts hbcxqruvz-: OPT; do
  # 长选项以 -- 开头，
  # 这通过列表中的最后一个选项检测：`-`
  # 然后手动将长选项名称赋值给 $OPT：
  if [ "$OPT" = "-" ]; then
    # 找到 --：重置 OPT 和 OPTARG
    OPT="${OPTARG%%=*}"  # 提取长选项名称
    # 提取长选项参数（此处为空）
    OPTARG="${OPTARG#$OPT}" 
    # 移除长选项中的任何赋值 `=`
    OPTARG="${OPTARG#=}" 
  fi
  # 现在按任意顺序处理并记录所有选项
  # 在这里我们设置它们的变量，
  # 稍后检测它们被设置，例如：[ -n "$VAR" ]
  case "$OPT" in
    h | help ) helpmsg;;
    b | b64 ) B64TEST=0;;
    c | clean ) CLEAN=0;; 
    x | hex ) HEXTEST=0;;
    q | quiet ) QUIET=0;;
    v | verbose ) VERBOSE=0;; 
    r | recurse ) RECURSE=0;;
    u | update ) UPDATE=0;;
    z | zstd ) COMPRESSOR=zstd;; 
    ??* ) printf \
    "$PROGN quitting, bad long option: $OPT\n" >&2
       usage; exit 2;; 
    # 错误的短选项（将通过 getopts 报告） 
    *) exit 2;; 
  esac
done
### 从列表 $@ 中移除所有解析过的选项和参数
### 这样我们就可以解析剩余的参数。
### 下一个将位于 $1，
### 就像没有提供选项一样：
shift $((OPTIND-1)) 

### 验证输入目录
[ -d "$1" ] || { 
   printf "$PROGN: input directory $1 not found\n" >&2
   exit 2
}
...
### 可选的最终报告
[ $QUIET ] || { printf ... } 
```



现在，用户可以使用列出的选项的任意组合调用此程序，这些选项前加`-`，后跟三个目录路径。这些选项正如其名称所示，为程序提供了可选的功能和运行模式。例如：

```
ncrpt -rbxuc dir1 dir2 dir3
```

### 输入-输出

在所有的编程语言中，`Bash`一定拥有最简单方便的输入/输出（I/O）处理。

## 基本术语

* **文件**
  * 通常存储在文件系统中，通过路径、文件名和文件扩展名进行识别
  * 当存储在互联网上时，它们的通用资源定位符（`URL`）充当路径的角色。这些文件需要通过某些实用程序（如`scp`（ssh安全拷贝）或`wget`）通过网络复制（下载）。一旦安全地存储在本地文件系统中，就可以更快、更安全地进行读取和操作。

* **流（streams）**是字节序列，即实际数据，并关联一个内部存储的当前位置。读取和写入会自动推进该位置。
  * 输入流用于读取
  * 输出流用于写入
  * 输入流用于读取，输出流用于写入

当我们不再需要流`3`时，可以使用`exec 3>&-`将其关闭。横线表示“关闭此流”。

流也可以从一个流重定向到另一个流。例如，`1>&2`将`stdout`重定向到`stderr`。如果省略`1`，默认会认为它是`1`。因此`>&2`具有相同的效果（见上文）。

有时，我们可能需要一个流直接代表一个文件。

假设我们希望将100个随机十六进制字符管道到外部程序`prog`，但由于某种原因，该程序没有从`stdin`读取的能力。相反，`prog`期望一个显式的输入文件名参数。对于这种情况，有一些标准的系统文件名与标准流是永久关联的：

```
1 tr -dc '0-9a-f' < /dev/urandom | \
2 head -c 100 | prog /dev/stdin
```

在这里，我们从`/dev/urandom`向工具程序`tr`发送了一个随机字节（0-255）的“懒加载”流，它删除了除了指定的十六进制字符范围以外的所有内容，并将幸存的内容传给`head`。然后`head`只取其中的一百个并将它们传给`prog`。`prog`像通常一样无法读取流`0`（`stdin`）上的管道，而是打开文件`/dev/stdin`并找到那里的字节。

同样地，为了丢弃某些不需要的消息、数据或垃圾邮件，可以将它们重定向到`>/dev/null`。

## 管道与函数式组合

函数调用、子壳求值、`Bash`命令、其他程序的调用，基本上`Bash`中的几乎所有内容都是默认将其产生的值写入流`1`的函数。然后，结果将从流`0`接收并作为调用的返回值，或者通过管道传递。

这种机制与*函数式编程*中发生的情况有些相似：它促进了方便的组合。事实上，只要自律地不滥用全局变量，老牌`Bash`就可以用于函数式编程。无论如何，滥用全局变量都是一种坏习惯，当你开始使用`&`（子进程的后台并行执行）时，它注定会带来痛苦的代价。

现在我们将通过`case`命令的示例来演示向任何`Bash`语句进行管道输入和输出。以下文本片段摘自TokenCrypt项目[(4)](https://github.com/liborty/TokenCrypt)。

它展示了我们如何*切换管道*。也就是说，将所有公共计算提取出来并放在前面。然后将它们的结果管道到`case`语句中，在语句内部，每个分支将以其特定的方式继续管道操作。然后，在`case`语句完成后，我们再次继续通过一个公共路径。也就是说，在这个示例中，将解密解压后的结果写入`$OUTFILE`。

代码从流`3`读取已知`$FSIZE`的密钥，用它解密`$INFILE`，然后根据`$CH`的值选择相关的解压方法。最终写入`$OUTFILE`的取决于选择了`case`语句的哪个分支。

```
 1 head -c $FSIZE <&3 | symcrypt $INFILE | case "$CH" in
 2    h ) hexify;;
 3    b ) base64 -w 0;;
 4    i ) lzma -d;;
 5    j ) lzma -d | hexify;; 
 6    k ) lzma -d | base64 -w 0;; 
 7    l ) zstd -d -c;; 
 8    m ) zstd -d -c | hexify;; 
 9    n ) zstd -d -c | base64 -w 0;;
10    * ) printf "$PROGN importfile: unrecognised ch\n";
11        exit 2;;
12 esac > $OUTFILE
```

为任何`Bash`语句都可以设置类似的管道。将它们都看作某些数据流的过滤器。

## 惊叹的算术

公平地说，`Bash`的“万物皆字符串”（EIJAS）哲学确实有一个实际的缺点。即：缺乏浮点数算术。

假设我们想要进行简单的浮点数除法`C=$A/$B`。也就是说，我们不满足于`Bash`默认整数除法给出的截断答案，例如“5/2 = 2”，我们希望获得更高的精度（在这种情况下为2.5）。

我们可以寻求外部Linux工具，如`awk`、`dc`、`bc`等，大多数人也是这样做。然而，在`Bash`中嵌入它们的代码有些混乱。这些外部程序提供的大多数功能对于一个简单的单行计算来说是大材小用。此外，我们每次都要为它们启动一个子进程，即使是像这里这样微不足道的例子：

```
1 C=$( awk "BEGIN { print $A / $B }" )
```

幸运的是，这里有一种更简单、更高效的替代方案：*定点算术*。作为一个练习，我们现在将在`Bash`中实现它。完整源代码可在[(3)](https://github.com/liborty/fdiv)中找到。

定点算术用于处理的数字数量级相似的情况，这样它们就不需要维护浮点数的指数。

两个很好的例子是计算百分比和货币。在这两个常见用例中，小数点具有固定的意义（和位置）。这在许多应用程序中实际上是更优的，因为截断误差更具预测性且可控。

那么，“尾数”实际上可以扩展到整个64位字。请注意，通用的“双精度IEEE 754浮点数标准”只有5位有效。

## 定点算术中的比例

比例的计算比百分比更容易。我们通过将临时左移五位小数然后进行普通的除法来获得这种精度。当然，这应该通过某种方式右移这五个小数，以产生最终结果。

通常情况下，很容易检查我们总是除以两个数字中较大的一个而不是除以零。这足以确保比例始终是正常的且处于[0,1]区间。

回到我们的比例应用。以下行调用`du`（磁盘使用）来填充一个名为`SIZES`的数组，包含两个目录的大小和名称：

```
 # 创建数组 SIZES[size1, dir1, size2, dir2]
2 SIZES=$( du -hbs $INDIR $OUTDIR )
```

接下来我们使用`printf`格式将普通整数`%d`转换为定点数`0.%5d`。

在`printf`格式字符串中，`%s`（字符串）、`%d`（小数）等按顺序由求值参数的实际值（如果有）填充。在这里是两个目录的大小和名称，最后是计算出的比例（`\`允许代码延续到下一行）：

```
1 printf "Output size:\t%s (%s)\n\
2    Original size:\t%s (%s)\n\
3    Compressed to:\t0.%05d\n" \
4    ${SIZES[0]} ${SIZES[1]} ${SIZES[2]} ${SIZES[3]} \
5      $(( 100000*${SIZES[2]}/${SIZES[0]} ))
```

最后一行是实际的定点（整数）计算。我们在这里选择计算五位小数`比例.%0d`，因此我们，乘以10000。这五个零对应于我们通过格式字符串输出的五个小数。分子是较小的压缩`$OUTDIR`的大小，因此真实的比例将小于一。

好计划，但如何右移（除以100000）呢，而且在没有能够容纳结果后五位小数的数值类型的情况下？我们不是在绕圈子吗？

这里有一个技巧。我们可以通过简单的`文本操作`跳出这个循环。忘记再除回`100000`吧。我们只需要在整数结果前面加上字面量字符串`0.`，通过文本方式构造一个定点数。每当我们知道结果小于1时，就可以这样做。我敢打赌你错过了上面`printf`格式化字符串中的那个技巧？请注意，这为我们提供了一个“新的定点类型”，且没有违反`EIJ`原则。

通过一种会让任何现代编译器都会在抽搐中死掉的、糟糕且违反类型的魔法，我们将放大后的整数除法结果（例如`1234`）转换成了`0.01234`。在`Bash`中，这并不像看起来那么奇怪，因为反正一切返回的都是字符串。

当然，小数点后的任何前导零是有意义的，所以我们必须在左侧填充这些零。格式化字符串`"%05d"`中`%`之后的前导零正是为此。

数字`5`（有效位数）必须与我们乘法左移因子中的零的数量一致，在本例中为`100000`。它应该被赋值给变量，例如`SIGDIGITS=5`，并在格式化字符串中使用`"%0$SIGDIGITSd"`，在缩放因子中使用`10**$SIGDIGITS`，从而避免任何潜在的视觉不匹配问题。

## 百分比（整数运算中）

同样，以下代码将压缩率（CR）打印为原始大小的百分比，并四舍五入到最近的百分分之一。全部通过整数运算完成：

```bash
 1 # 百分比压缩率：xx.xx%
 2 # 乘以 10**5，然后取比例，
 3 # 加上 5 并除以 10，
 4 # 四舍五入到百分之分之一。
 5 # SIZES 是一个存储：size1,dir1,size2,dir2 的数组
 6 SIZES=$( du -bs $INDIR $OUTDIR ) 
 7 printf "$PROGN: ${SIZES[1]} ${SIZES[0]} "
 8 printf "=> ${SIZES[3]} ${SIZES[2]} "
 9 if [ ${SIZES[0]} = ${SIZES[2]} ]; then 
10    printf "(100 %%)\n"
11 else
12    # 计算保留两位小数的百分比
13    CR=$(( (5+100000*${SIZES[2]}/${SIZES[0]})/10 ))
14    # 压缩率以 xx.xx% 格式打印
15    printf "(${CR: 0:2}.${CR: 2:4} %%)\n" 
16 fi
```

在这里，我们没有使用`printf`格式化字符串替换，而是通过选择`$CR`的前两个数字、拼接小数点字符、最后加上接两个数字来直接构造百分比数字：`${CR: 0:2}.${CR: 2:4}`。单个字符及其范围的选择是变量扩展`${CR}`可用功能之一。

`Bash`非常适合这种文本黑客技巧，正因为“一切都只是字符串”。

## 通用除法

有人可能会反对认为这些只是特殊的打印技巧，除非我们能对数字进行通用计算，否则数字并没有太大用。我们是否可以写一个`Bash`函数，在没有预设硬编码小数位数的情况下进行除法？理想情况下，始终提供可能的精度？

让我们该函数命名为`fdiv`。以下是对它更详细的要求：

* `fdiv` `bash`脚本接受两个整数参数：`numerator`（分子）和`denominator`（除数）。它检查参数，如果缺失、不是整数或除数（`denominator`）为零，则返回错误。它能正确处理负参数。

* 它返回一个定点数除法结果，精度达到两个64位整数允许的最佳精度，四舍五入到最近的一位，例如：

```
1    fdiv -2 -3
2    0.666666666666666667  
3    fdiv 355 113
4    3.14159222035398230
```

* 当`numerator`为0时，立即返回`0.0`。

* 自动以最高精度计算。截断误差将小于`5E-19`。

* 当`numerator > denominator`时，答案由整数（`numerator/denominator`整数除法）组成，后面跟着小数点，然后是放大后的余数除以`denominator`。最后部分小于1，因此提供了小数点后的数字，类似于上面的“定点比率”部分。总体而言，即使对于某些非常大的数字，这也保持了`5E-19`的保证精度。例如：

```
1    fdiv $(( 2**63-1 )) 3
2    3074457345618258602.333333333333333333
```

* 当`denominator`可以被10或其倍数整除时，小数精度也可以增加，这次是在小数点后插入相应数量的零。在如下：

```bash
#!/bin/bash
# 添加定点

# 检查参数
if [[ -z "$1" || -z "$2" ]]; then
    printf "error: needs two arguments\n"
    exit 1
fi

if ! [[ "$1" =~ ^-?[0-9]+$ ]] || ! [[ "$2" =~ ^-?[0-9]+$ ]]; then
    printf "error: must be integers\n"
    exit 1
fi

if [[ "$2" -eq 0 ]]; then
    printf "error: divisor cannot be zero\n"
    exit 1
fi

## 将两者解析为整数部分和小数部分
ARR1=(${1//./})
ARR2=(${2//./})
F1=${ARR1[1]}
F2=${ARR2[1]}

## 交换小数部分使 $F1 更长
[[ ${#F1} -lt ${#F2} ]] && { 
    FT=$F1; F1=$F2; F2=$FT
}
LF2=${#F2} # 保存较短的长度

## 从较长的 F1 中删除末尾零，直到不再较长
while [[ ${#F1} -gt $LF2 ]]; do
    [[ ${F1: -1:1} == 0 ]] && F1=${F1:0:-1} || break
done
LF1=${#F1} # 现在完成对 F1 的裁剪

## 在较短的 F2 右侧补零，直到长度相同
while [[ $LF1 -gt ${#F2} ]]; do F2=${F2}0; done

## 执行加法
WHOLE=$(( ${ARR1[0]}+${ARR2[0]} ))
FRACT=$(( $F1+$F2 ))

## 检查小数溢出，即 >= 1
[[ ${#FRACT} -gt $LF1 ]] && {
    let WHOLE+=${FRACT:0:1}
    FRACT=${FRACT:1}
}
echo $WHOLE.$FRACT 
```

给读者的作业：实现一个类似的脚本`fsub`，执行这些定点数的减法。提示：先复制这段代码`https://github.com/liborty/fdiv/blob/master/fadd`，然后对其进行适当修改。

如前所述，使用`&`将进程在后台运行（可能在不同的处理器核心上运行），同时我们继续处理手头的工作，是`Bash`的重要部分。这过去一直如此，但最近随着多核处理器成为常态，这变得更具话题性。当你的处理器中坐着三十二或更多核心时，通俗地说，其中大多数核心都在“闲着摸鱼”，那么一个负责任的程序员应该想办法如何分配这些任务。

## 自动多线程

许多`Bash`应用只是处理大量文件。例如，开源GitHub项目`TokenCrypt`[(4)](https://github.com/liborty/TokenCrypt)也是如此。许多任务仅依赖于文件，因此它们可以并行运行。磁盘瓶颈可能会限制预期的加速效果，但我们在这里不会考虑这些问题。

在这里，我们将看到如何在`Bash`脚本中自动生成后台作业。这种技术具有通用性，并且可以加速许多天然并行的任务，例如多个文件的处理。

当然，进行复杂的多线程和异步编程（以及许多其他事情）的更好方法是Rust。然而，对于简单任务来说，`Bash`仍然是最简单的。

## 关于安全和隐私的吐槽

该项目的诞生是因为对互联网加密状态的沮丧。许多产品似乎只实现了混淆和不安全的目标。其中甚至包括一些初衷良好的产品。

然而，有一个非常简单且有效的替代方案：异或（XOR）对称加密。对称意味着加密解密使用相同的密钥，这极大地简化了密钥管理。它还允许多重授权的密钥合并等有用操作。

此外，由于密钥与消息等长，这种加密在理论上是不可破解的，即是最强的加密方式。它在`TokenCrypt`中以易于使用的形式实现。

有一个合理的反对意见，即生成如此长的密钥实际上使所需的存储空间增加了一倍。这通过先压缩文件来缓解，并采取了措施以有效地进行压缩。例如，如果实现了50%的压缩率，就没有任何存储开销。无论如何，磁盘是廉价的，即使有一定的开销，安全性也是值得的。优点是，加密和解密非常快，因为非常简单。

## 更快地加密多个文件

对给定目录下的文件进行压缩、加密、解压缩和解密任务显然是I/O密集型的。它们一次只依赖一个文件，因此可以并行执行，它们之间不需要通信。

对每个文件单独选择并应用最合适的压缩方法，并在加密时生成正确长度的密钥或在解密时查找。代码足够通用可以处理这些。我们在这里不详述细节，细节可以在[(4)](https://github.com/liborty/TokenCrypt)、[(5)](https://github.com/liborty/TokenCrypt/ncrpt)、[(6)](https://github.com/liborty/TokenCrypt/expcrypt)、[(7)](https://github.com/liborty/TokenCrypt/impcrypt)中找到。

我们的目标首先为长文件启动后台作业，将短文件留到最后在当前shell中处理，以避免子壳开销。这将最小脚本的整体执行时间。我们还希望代码简单，没有过多的测试和复杂的`if`语句。

首先处理脚本参数和标志，并用它们设置正确的输入输出目录。然后按长度对输入文件排序：



```bash
# 子壳中加密的文件大小
BACKSZ=10000
# INDIR 中按大小（字节）排序的文件列表
ITEMS=$(ls -SL $INDIR)
# 准备启动子壳
BJ=\&
```

上面的最后一行是一个奇妙的黑科技，将默认文本命令结束符`$BJ`设置为`&`。

这将导致大文件的作业（后面跟着`$BJ`）将首先在后台子壳中运行。

现在剩下的就是按大小从大到小的顺序处理所有文件，当达到阈值`BACKSZ`时，通过`BJ=''`永久关闭子壳模式：

```bash
for FILEND in $ITEMS; do
   # 重建一个完整的路径/文件名
   INFILE=$INDIR/$FILEND
   # 仅处理真实文件
   [ -f "$INFILE" ] || continue
   # 当文件大小小于
   # 阈值 BACKSZ 时关闭子壳
   # 一旦 $BJ 被为空字符串，
   # 不再检查文件大小
   [ -z "$BJ" ] || \
   [ $(stat -c%s $INFILE) -ge $BACKSZ ] || BJ=''
   # 处理单个文件的函数
   # 要么在后台，要么在此 shell 中
   # 取决于 $BJ 的值
   processfile $INFILE $BJ
done
wait # 等待所有 processfiles 完成
```

记住，当 Bash 函数的调用以`&`结束时，它们是在子 shell 中执行的。当变量`$BJ`被程序化地取消时，它的值将直接从程序文本中消失，此后的`processfile`执行将在当前 shell 中进行。

自修改程序，哈！（Bash 中 EIJAS 的福分啊）。

我们使用逻辑或`||`代替`if`。只有当`$BJ`仍设置为`&`但当前`$INFILE`的大小已低于阈值时，它才会执行最后一个命令设置`BJ=''`。之后执行的唯一检查是第一部分：`[ -z "$BJ" ]`计算为真并立即退出。如果有大量短文件，它节省了对其余文件昂贵的`stat`系统调用。

当然，在这个简单的示例中，我们可以通过在`if`语句中测试`$BJ`并显式调用两次`processfile`来实现相同效果，如下：

```bash
if [ -n "$BJ" ]; then
   processfile $INFILE &
else
   processfile $INFILE
fi
```
