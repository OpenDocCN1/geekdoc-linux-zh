## 协议

![](img/0937bf4b1739a36662bbe2484b163f1b_12_0.png)

在计算机网络和信息通信领域，人们经常提到“协议”一词。互联网上常用的代表性协议有 `IP`、`TCP`、`HTTP` 等。局域网（`Lan`）中常用的协议有 `IPX` / `SPX`（由 `Novell` 开发的 `NetWare` 系统协议）等。

### 为什么需要协议？

通常，我们发送电子邮件、访问主页获取信息时，并不知道背景中运行的协议，只有当我们重新配置计算机的网络连接并修改网络设置时，这些操作才成为可能。因此，只要网络设置好并连接成功，人们往往会忘记协议这些事情。只要应用程序知道如何利用协议，就足够让人们使用他们构建的网络连接了。一个人因为不理解某些协议而无法访问互联网的情况并不罕见。然而，在通过网络通信的过程中，协议起着至关重要的作用，既然你对了解协议感兴趣，这可以让你对该主题有一个整体的了解。

简而言之，协议是客户端计算机和服务器计算机通过网络实现通信的一种“约定”。这种“约定”允许由不同厂商的设备设备、不同 `CPU` 和不同操作系统组成的计算机，只要遵循相同的协议，就可以相互通信。另一方面，如果使用不同的协议，就无法实现通信。这就像两个说不同语言的人，无法理解对方。协议有很多类型，每种协议都明确定义了其行为规范。两台计算机必须能够支持相同的协议，并遵循相同的协议进行处理，以实现相互通信。

在进一步探讨协议主题之前，让我们讨论两个你为了更好地理解而需要知道的基础基础知识。它们是中央处理器和操作系统。

### CPU

`CPU`（`Central Processing Unit`）。它就像计算机的“心脏”，每个程序实际上都是由它进行调度和执行的。`CPU` 的性能很大程度上决定了计算机的处理性能。因此，人们常说计算机的历史实际上就是 `CPU` 的历史。目前，人们经常使用 `CPU` `Intel Core`、`Intel Atom`、`ARM CORTEX` 等产品。

### 操作系统

`Os`（`Operating System`）是一种基础软件。它集成了 `CPU` 管理、内存管理、计算机外设管理和程序管理等重要功能。这里描述的 `TCP` 或 `IP` 协议的处理在很多情况下已经嵌入到特定的操作系统中了。今天个人电脑常用的操作系统有 `UNIX`、`Windows`、`Mac OS x`、`Linux` 等。

计算机中可以运行的指令随 `CPU` 不同，也随操作系统而异。因此，如果将为某些 `CPU` 或操作系统设计的程序直接复制到具有其他类型 `CPU` 或操作系统的计算机上，可能无法直接运行。计算机中存储的数据也随 `CPU` 和操作系统而异。因此，如果不同计算机之间的 `CPU` 和操作系统要实现通信，就需要一方支持该协议，并遵循该协议进行数据读取。这就是为什么你不能在 `iPhone` 上运行安卓应用的原因。

此外，`CPU` 通常一次只能运行一个程序。为了让多个程序同时运行，操作系统采用了 `CPU` 时间片轮询机制在多个程序之间进行切换和合理调度。这种方法被称为多任务。

### 那么协议中的“约定”是什么？

约定就像人与之间的对话。这里有一个简单的例子。有三个人：`Sam`、`Tom` 和 `Jerry`。`Sam` 只会说中文，`Tom` 只会说英语，`Jerry` 会说中文和英语。现在 `Sam` 和 `Tom` 需要聊天。他们应该如何相互通信？如果 `Tom` 和 `Jerry` 需要聊天呢？

如果我们：将中文和英语视为“约定”。使用“聊天通信”并将你说的话视为“数据”。

我恐怕 `Sam` 和 `Tom` 只要说同一种语言就无法相互通信。因为对话中使用的约定（语言）存在差异，双方都无法将数据（说的话）传输给对方。（两人之间的同声传译员可以促进通信，就像网关在网络环境中做的那样。）

接下来，我们分析 `Sam` 和 `Jerry` 之间的对话。通过使用这种中文“约定”，两个人可以理解对方想说什么。也就是说，`Sam` 和 `Jerry` 使用相同的协议来顺畅地通信，以便他们可以传输所需的数据（他们想互相说的内容）。

从这个意义上说，约定就像普通口语。虽然语言是人类的属性，但当计算机在互联网上相互通信时，也可以认为通信是基于某种类似于人类“语言”的东西（同样，我们在日常生活中认为是理所当然的某些行为，在很多情况下与“约定”的概念一致）。

### 计算机通信的诞生与标准化

在计算机通信初期，系统化和标准化并没有得到足够的关注。每个计算机制造商都生产自己的网络产品来实现计算机通信。没有强烈的系统化、分层等概念。1974 年，`IBM` 发布了 `SNA`，将公司的计算机通信技术作为一种系统的网络架构发布。从那时起，计算机制造商也发布了自己的网络架构，引发了许多协议的系统化。然而，各种制造商的各种网络架构和协议是不兼容的。即使两台异构计算机在物理层上连接，由于不同的网络架构和协议，也无法实现正常通信。

这对用户来说极其不方便。因为这意味着最初使用的计算机网络产品一直只能使用同一厂商的。如果相关厂商破产或产品超过寿命，必须更换整个网络设备。此外，由于使用的网络产品不同，不同部门之间即使物理连接也无法通信的情况并不罕见。灵活性扩展性的缺乏使得使用户难以自由使用计算机通信。

随着计算机重要性的增加，许多公司开始意识到兼容性的重要性。人们开始研究让不同制造商的异构模型相互通信的技术。这促进了 `Web` 的开放性和多功能性。

为了解决这些问题，`ISO`（国际标准组织）制定了国际标准 `OSI`（开放系统连接参考模型），并对通信系统进行了标准化。目前 `OSI` 协议并不常用，但作为 `OSI` 协议设计指南的 `OSI` 参考模型经常用于网络协议的开发。

协议的标准化使得所有遵循标准协议的设备不再由于计算机硬件或操作系统的差异而无法通信。

协议的标准化也促进了计算机网络的普及。



在现实世界中，有很多的技术没有被广泛应用，因为开发公司没有发布相应的开发规范。如果公司能够将其开发规范公开，让更多同行及时使用它们并成为行业标准，那么会有更多更好的产品能够生存并被我们使用。

### OSI 参考模型

该模型将通信协议的必要功能分为 7 层。通过这些层，复杂的网络协议被简化。在这个模型中，每一层都接收其下层提供的特定服务，并负责向其上层提供特定服务。规范上下层之间交互的约定被称为“接口”。规范层之间交互的约定被称为协议。

协议分层类似于计算机软件中的模块化开发。`OSI`参考模型的建议是理想的。它希望实现从第一层到第七层的所有模块并将它们组合来实现网络通信。分层允许每一层独立使用，因此即使系统中某些分层发生了变化，也不会影响整个系统。因此，构建一个既可扩展又灵活的系统是可能的。此外，通过分层通信功能可以细分，更容易为每一层实现独立的协议，并定义每一层具体的职责和义务。这些都是分层的优点。分层的缺点可能是过度模块化，导致处理更加负担，并且必须为每个模块实现相似的处理逻辑。

### 通过简单示例理解分层

首先，以电话聊天为例。`Adam`和`Eve`两个人正在用电话（通信设备）用英语（语言协议）交谈。从表面上看，`Adam`和`Eve`正在用英语直接对话，但实际上，`Adam`和`Eve`都在听电话听筒里的声音，并对着麦克风说话。想象一个从未见过电话的人看到这一幕会怎么？我恐怕他一定从网络角度认为`Adam`和`Eve`正在打电话。

他们在音频输入麦克风时使用的语言协议在通信设备层面被翻译成无线信号发送到对方的手机，然后由通信设备层转换为音频输出传递给对方。因此，`Adam`和`Eve`实际上是使用电话与音频转换之间的接口进行对话。

人们通常认为当你拿起电话与某人通话时，就像是直接和他们说话一样，但如果你仔细观察，实际上是电话在调解整个过程，这一点不可否认。如果来自`Adam`手机的电子信号没有转换成与`Eve`的信号相同频率的声音会怎样？这类似于`Adam`的手机和`Eve`的手机之间的协议差异。`Eve`可能会听到声音，但觉得她不是在和`Adam`说话，而是在和别人说话。如果频率差很大，`Eve`更有可能认为她听到的不是英语。

那么，如果我们假设语言层相同而改变通信设备层呢？例如，将电话改为无线电台。如果通信设备层使用无线电台，他们必须学习使用无线电的方法。由于语言层仍使用英语协议，用户在通话时可以像以前一样正常说话。

那么，如果通信设备层使用电话而语言层改为英语呢？显然，电话本身不会受到用户语言的限制。因此，这种情况和使用英语的效果完全相同，仍然可以通话。

之前的示例简单地将协议划分为层。然而，实际的数据包通信协议可能非常复杂。`OSI`参考模型将这种复杂的协议组织成七个易理解的层。

### OSI 参考模型

`OSI`参考模型在总结通信必要功能方面做得很好。网络工程师在讨论协议相关问题时，也经常对`OSI`参考模型的层进行原型设计。对于计算机网络的初学者，学习`OSI`参考模型可以是成功的第一步。

`OSI`参考模型归到底是一个“模型”，是对每层功能的一组粗略定义，而没有对协议和接口的详细定义。它只作为学习和设计协议的指南。因此，如果你想知道更多关于协议的细节，有必要参考协议本身的特定规范。

许多通信协议对应于`OSI`参考模型的七层之一。通过此，我们可以对协议在整个通信功能中的位置和功能有一个大致的概念。虽然需要仔细阅读规范才能理解协议，但其通用目的可以在对应的`OSI`层找到。这就是为什么在学习每个协议之前首先研究的是`OSI`模型。

`OSI`（参考模型）将通信功能划分为七层，被称为`OSI`参考模型。`OSI`协议基于`OSI`参考模型定义了每一层的协议和接口相关标准。遵循`OSI`协议的产品被称为`OSI`产品，它们遵循的通信被称为`OSI`通信。不要因为含义不同而混淆“`OSI`参考模型”和“`OSI`协议”。

## 缓解网络威胁

对你的网络保持偏执并没有；事实上，偏执实际上可能会救你。即使是最强大的网络也面临安全威胁的风险。从安全角度维护你的网络完整性的秘密在于缓解风险。

### 识别威胁

你的网络危险是疯狂的。外面有很多风险，如果你忽视它们，或者假设你拥有最保护的网络，你就是愚蠢的。任何试图未经授权访问你的网络的人通常是为了侦察，或者出于破坏性原因。某些安全违露经过精心设计可以完成。安全泄露很重要，因为从你的网络获取的信息可以造成损害。

许多人现在为使用不安全的网络付出代价。他们的隐私和个人数据被盗了，一些人被冒充了。你可能会发现自己与某个完全不知道的袭击有关，因为有人盗取了你的身份并将其用于。

大多数人在安全方面只认为恶意软件和病毒是最大的风险。然而，外面还有许多风险可能会。你将学习许多安全威胁。有些已经存在多年，有些在未来出现。

- **拒绝服务**：拒绝服务攻击（`DoS`）阻止你访问网络或资源。`DoS`攻击今天很常见，通常针对大型公司。攻击者可以向组织网站发送大量流量，导致服务器无法处理，使得合法用户无法访问网站。

- **死亡 ping**：死亡之`ping`是`DoS`攻击的一种常见形式。那么，在死亡`ping`攻击中发生了什么？为了通信，你的设备向远程主机发送`ICMP`数据包以建立其可用性。然而，在死亡`ping`攻击中，入侵者会向远程主机泛洪`ICMP`数据包。

变得不堪应付，在此过程中它可能会挂起或不断重启。

幸运的是，今天许多操作系统都设计了补丁和安全更新，以保护它们免受此类攻击。

### 蓝精灵 (`Smurfs`)

忘掉你在电视上看到的那些矮小可爱的蓝色家伙吧。蓝精灵攻击一点也不可爱。蓝精灵攻击的做法是不断用伪造的`ping`广播包淹没你的网络。伪造是指使用他人的`IP`地址。

蓝精灵攻击是如何执行的？攻击者会伪造你的`IP`地址，然后将大量的`ping`包发送到与你的`IP`地址相关的广播地址。接收请求的路由器将继续在网络上广播这些`ping`包，假设这是一个正常的广播请求。从这里开始，所有其他主机都会接收到该广播。由于它们都在对`IP`请求进行回声响应，因此它们创建了回声。在短时间内，你的网络将将变成一场噩梦，因为该网络上的每台主机都在尝试响应该请求。

蓝精灵攻击在针对大型网络时更为有效。它们受益于规模经济。蓝精灵攻击可能已成为过去，但你永远无法排除其发生的可能性。总会有一个随机的黑客决定采用一种无人会怀疑的老办法。今天大多数路由器的程序设置使得它们无法随意地广播数据包。

### 部落泛洪网络攻击 (`Tribe flood network`)

部落泛洪网络攻击非常复杂，通常被称为分布式拒绝服务攻击，`DDoS`。当攻击者从多个源发起一系列`DoS`攻击，且所有攻击都针对一组设备时，就策划了这种攻击。

### 攻击是如何发生的

根据最终目标的不同，每个攻击者通常会有一个行动计划来获得他们想要的东西。某些攻击者会在一段时间内诱导你，在此过程中尽可能多地关于你和你的网络的信息，甚至在他们出手执行攻击之前，你还完全不知情。

攻击者可以以非常微妙的形式与你互动，你很少意识到自己正成为目标。仅仅是电脑游戏这样简单的东西就足以让他们访问你的网络。由于知道一直有人在试图获取你网络的特权访问权限，你必须保持警惕。

定向攻击（`Directed attack`）是由攻击者策划的攻击。这指的是那些寻找特定目标的人，或者黑入你的网络有非常特定的理由。定向攻击与病毒之类有所不同。例如，病毒可能由无意的用户从一个设备传输到另一个设备。病毒通常利用系统的弱点并嵌入设备中。某些病毒会克隆并看起来像你经常看到或访问的文件，因此你完全无法怀疑它们。以下是在管理网络时可能会遇到的一些最常见的网络攻击：

### ActiveX 攻击 (`Active X attack`)

这些攻击被嵌入在小型应用程序中，你必须在计算机上安装这些程序以允许你访问特定内容。某些网站要求你安装`Java`或`Adobe`插件来播放某些媒体。这些都是攻击者访问你设备的简单方法。一旦你安装了该程序，程序就会在你不知情的情况下在后台运行，收集并传输到黑客服务器的信息。

使用这种技术的黑客可以在你不知情的情况下远程访问你设备中的一切。这是一种危险的攻击，因为能看到你硬盘中所有内容的人可以在你的设备中存储致命信息或植入伪造的证据。

### 自动根程序 (`Auto rooter`)

自动根是一种自动化攻击。执行这种攻击的黑客依赖于根程序（`rootkits`）。这种攻击对于想要监控你网络的黑客来说很常见。一旦受到影响，他们就可以访问你做的一切，并根据需要一直监控你的设备。

### IP 伪造 (`IP spoofing`)

`IP`伪造是一种攻击者发送数据包，但不是使用真实源地址，而是使用虚假地址的情况。你的网络通常会因此受到影响，因为`IP`地址被伪装成像是来自网络内部的设备，而实际上这些数据包源于一个外地`IP`地址。

`IP`伪造的问题在于路由器会识别这些数据包并将其视为网络内的正常请求，因为它们可以识别出`IP`地址。处理此类攻击的最佳方法是部署防火墙。

今天互联网上有大量的特权信息。考虑一下在线购物的人数、在云端存储用户凭据和信息的公司等等。数据是新的黄金，每个人都试图黑入某些系统以获取有用的数据。例如，商业间谍活动是最大的黑帽业务之一。为了黑入系统并获取特定数据，人们支付了极高的报酬。在网络上实施防火墙是避免这一问题的最佳方法之一。

### 后门访问 (`Backdoor access`)



### 后门

后门是开发者创建的一种路径，允许他们在不通过正常流程的情况下访问程序或应用程序。大多数开发者创建后门是为了能够出于不同的原因访问这些程序。某些人将其用作正常流程失败且他们无法访问时对程序进行故障排除。

对于黑客来说，后门允许他们入侵网络。建议你尽可能经常监控和检查网络以检测后门。你还应该经常进行系统审计，以确保你的网络安全符合目前的网络安全标准。

### 应用层攻击 (Application layer attack)

应用层攻击利用某些应用程序中的漏洞。这些攻击大多数针对需要权限的程序，并从中收集信息。通过这种方式，他们获得了所需的信息。

### 数据包嗅探 (Packet sniffing)

数据包嗅探器是网络管理员用于排除网络故障的工具。然而，这些工具也可以被黑客用于窃取数据。

### 暴力破解 (Brute force)

在暴力破解攻击中，例如黑客会在你的网络上运行一个程序。他们获得了账户权限，随后他们就可以访问了。

### 网络侦察 (Network reconnaissance)

网络侦察简单来说是对网络进行监控。黑客在出手之前会花时间获取关于你网络的尽可能多的信息。他们可以扫描网络端口，或采用技术手段获取。

### 密码攻击 (Password attack)

密码攻击是黑客伪装成网络上的合法用户的攻击，允许他们访问你的资源。密码攻击可以通过许多方式发起。它们也可以与其他攻击结合使用。

### 中间人 (Man in the middle)

中间人攻击发生在黑客拦截你的通信时。他们在数据交付给接收者之前读取这些数据。互联网服务提供商、信用卡和借记卡刷卡机以及非法 ATM 机操作员通常被用于此类攻击。

### 信任利用 (Trust exploits)

人们经常说，任何安全设备中最薄弱的环节是人。我们倾向于高度信任，而这导致了整个系统的崩溃。你认为某人不会坏事，因为你认识他们，而且他们不是那种人。在你不知道的情况下，他们可能有动机，或者其他人在不知情的情况下使用了他们。信任利用发生在黑客成功利用你在网络中的信任关系时。

### 端口重定向 (Port redirection)

在这种攻击中，黑客使用一个已经被攻破的主机。被攻破主机是对你网络友好的。由于该机器已经拥有权限，黑客利用它产生网络流量，即通常会被你的防火墙阻止进入网络的数据包。

### 网络钓鱼 (Phishing)

网络钓鱼是你今天能遇到的最复杂的攻击尝试之一。它之所以被称为社会工程是有充分理由的。随着网络的演进，黑客获取特权信息的策略也随之演进。钓鱼攻击要求你向黑客提供你在清醒时不会提供的信息，但你却在不知情的情况下提供了。

大多数网络管理员已经采取了措施保护他们的网络免受攻击。黑入此类网络并不容易。与其费事，黑客简单地创建一个看起来合法的东西并传递给用户。通过这种方式，他们获得了他们所需的信息。

一个很好的例子是黑客想要收集身份信息、出生日期和地点等信息。

这样的黑客可以创建一个贷款应用，使其看起来合法合规，并将其放到应用商店。从那里开始，他们会适当地营销该贷款应用，并确保获得正确的关注。

一旦你下载了这个应用（因为你可能正在寻找针对信用分低者的廉价贷款），你就会输入提供给银行或任何贷款人的所有重要详细信息，并等待他们的反馈。你永远不会从这些钓鱼黑客那里得到任何反馈。他们已经拥有了你的全名、住址、电话号码、电子邮件地址等信息，有些甚至会提示你创建一个密码，而大多数人在所有账户都会使用相同的密码。

某些钓鱼黑客甚至会克隆电子邮件，使其看起来像是来自合法的来源，例如知名的政府实体或银行。为了避免这些情况，请务必确保从访问的网站使用官方链接。当你有疑问时，在向黑客提供信息之前，拨打官方联系电话以核实真相。

某些钓鱼攻击使用键盘记录器。键盘记录器可以在你的系统中不被检测的情况下运行。今天，大多数键盘记录器的设计方式使得它们不仅可以发送按键，甚至还可以截屏并在你不知情的情况下上传到黑客的服务器。由于你可能在键盘上输入大量内容，键盘记录器可以被程序设置为只捕捉特定信息，如电子邮件、密码、电话号码等。

### 如何将十进制转换为十六进制？

十六进制意味着该数字系统的基数为 16。记住，十进制 0 到 15 可以通过上述图表直接转换为十六进制。如果你有一个 16 或更大的十进制数字，则需要使用以下步骤将其转换为十六进制：

1. 将数字除以 16，记录余数。
2. 继续除以商，直到没有余数。
3. 将所有的单独余数转换为十六进制值，以得到你的十进制数字对应的十六进制值。

示例：将十进制 27 转换为十六进制。`27 ÷ 16 = 1`，余数为 11。

1. 十进制 1 的十六进制值为 `1`
2. 十进制 11 的十六进制值为 `B`
3. 因此，十进制 27 可以写为十六进制的 `1B`。

让我们来看另一个示例。将十进制 966 转换为十六进制。

| 十进制余数 | 余数的十六进制等值 | 数字除以 16 |
| :--- | :--- | :--- |
| `966 ÷ 16 = 60` | `6` | |
| `60 ÷ 16 = 3` | `12 (C)` | |
| `3 ÷ 16 = 0` | `3` | |

因此，十进制 966 的十六进制值为 `0x3C6`。

### 如何将十六进制转换为十进制？

使用以下简单步骤将任何十六进制值转换为对应的十进制值。

1. 将十六进制的每个位数值与数字对应的数字相乘。
2. 将所有结果相加。

示例：将十六进制 `0x179` 转换为十进制值。数字前的“0x”用于提醒这是一个十六进制数，而不是十进制数。

| 十六进制数 | 位 | 十进制值 | 乘以位值 |
| :--- | :--- | :--- | :--- |
| `1` | `16² = 256` | | `1 x 256 = 256` |
| `7` | `16¹ = 16` | | `7 x 16 = 112` |
| `9` | `16⁰ = 1` | | `9 x 1 = 9` |
| | | **`256+112+9=377`** | |

因此，十六进制 `0x179` 等于十进制的 377。

### `IPv6` 结构

`IPv6` 地址由八个四位十六进制数表示。每个四个数字之间用冒号 (`:`) 隔开。`IPv6` 的示例是 `1041:0000:130B:0000:0000:09C1:586D:1305`。由于单个十六进制位长 4 位，这八组四位十六进制数字相当于 `4x4x8=128` 位长。

### 记住以下规则

1. `IPv6` 中所有的前导 0 都可以省略。
2. 连续的零块可以压缩为 `::`。
3. 如果 `IPv6` 以零开头，你可以省略它。
4. 例如，如下所示：`1041:0000:130B:0000:0000:09C1:586D:1305`。
5. 全局路由前缀用于使 `IPv6` 可路由。
6. 子网也称为站点级 (`SLA`)。
7. 全局单播地址可以使用 `EUI-64` 格式唯一地标识网络中的接口。它通过在 24 位长的供应商 ID 和 24 位之间插入 16 位值 `0xFFFE` 来创建 `EUI-64`。

`0:0:0:0:0:16:1610.10`

或

`::16:1610.10`

在十六进制格式下，上述地址看起来如下：

`::A:A:10:10`

### 多组播地址

`IPv6` 中没有广播地址，因为它不支持广播流量。相反，你必须使用多组播地址将数据包发送到特定的主机组。识别 `IPv6` 多组播地址最简单的方法是每个组播 IP 的第一个字节始终以 `FF` 开头。

`IPv6` 多组播地址使用的前缀是 `FF00::/8`。

`0xFF` 之后的第一个字节表示寿命，第二个字节表示多组播的范围。组播的寿命可以是永久的也可以是瞬时的。范围可以是以下任何一种：

- `1.` 节点 `Node (0001)`
- `2.` 链路 `Link (0010)`
- `3.` 子网 `Subnet (0011)`
- `4.` 管理 `Admin (0100)`
- `5.` 站点 `Site (0101)`
- `6.` 组织 `Organization (1000)`
- `7.` 全局 `Global (1110)`

其余 112 位用于表示多组组 ID。某些多组播地址被保留用于特定用途。这些预留的多组播地址是：

- `FF01::1` —向所有节点/所有主机进行组播



- `FF02::1`—组播到所有主机（链路本地范围）

- `FF01::2`—组播到所有路由器（接口本地范围内）

- `FF02::2`—组播到链路中的所有路由器

- `FF05::2`—组播到站点内的所有路由器（站点本地范围）

- `FF02::5`—组播到所有 `OSPFv3` 路由器

- `FF02::6`—组播到所有 `OSPFv3` 指定路由器

- `FF02::A`—组播到 `EIGRP` 路由器

- `FF02::D`—组播到 `PIM` 路由器

- `FF02::1:FFXX:XXXX`—请求节点多组播地址（此处 `XX:XXXX` 代表 `IPv6` 接口地址的低 24 位）

一旦你开始，它就会变成一个游戏，并很快到位。开始前的良好组织可以解决过程中的大量问题。这里有一个按时间顺序排列的任务清单，会有很大帮助。

6. 安装所有连接器和模块。

### 电话柜

它不仅为你提供了一个中心化的、不干扰的地方来布线和设置网络设备，它还可以作为那些在办公环境中暴露会很碍眼的物品的藏身之处。你的电话柜应该提供这些基本功能：

- 如果可能，它应该位于中心位置，这样你就可以从每个设备位置布线并保持距离最短。有时建筑的后墙就能起到这个作用。利用你现有的资源即可！

- 房间应该有某种入口，以便线缆从不同位置接入。不要选择侧壁、天花板和地板都是混凝土的房间。必须进入吊顶或阁楼。

- 你应该有足够的空间在柜子里工作而不碰撞东西，也不需要倒立着够到线缆和连接。你会在这里花费大量时间。当你需要排除故障时，你在检查布线时需要一个舒适站立的地方。

- 确保选择一个有空调或不会太热的房间。大多数电子设备需要凉爽的环境，因为过热几乎总是会导致损坏。

- 最后，柜子应该有一面墙，从胸部到眼睛的高度有空间，在上面安装一块大板，用于安装设备和线缆。

安装板可以使用架子或胶合板制成，并且足够大容纳你所有的设备。你还应该能够如下图所示，将线缆绕过设备路由到它们的连接处。

### 吊顶（Drop Ceilings）

如果你还不知道什么是吊顶，它们就是那种瓷板天花板，大约每三块吊板中就有一个荧光灯具，每块吊板都由金属框架网格支撑。网格通过连接到上方天花板的钢丝固定。这种天花板是从真实的天花板向下“吊”到整个房间或整个建筑的标准高度。在吊顶和真实天花板之间有大量的空间、电线管和布线、灯具（当然了）、空调风道以及其他一些惊喜。

通过吊顶区域为建筑布线并不困难，但你必须做好准备。首先，千万不要爬进天花板内部并指望能在上面走动！你无疑会直接掉下去。它的设计是为了支撑吊板和灯具的，而不是人。那么，你该怎么做呢？首先，在电话柜内你安装板正上方尽可能近的地方打开一块吊板。然后，拿上手电筒，爬梯子进入大约胸部高度的天花板内部，观察它的布局是怎样的。

在大多数新建筑中，通往办公区域的墙只比吊顶高出几英寸。它们通常是标准高度——也许是 8 英尺——距离天花板仅几英寸。唯一延伸到真实天花板的墙是建筑主要区域之间的防火墙。这些墙也是由石膏板做的，通常可以无碍地穿透以布设细线。如果你发现的是这种情况，那么布线工作将会相对轻松。

确定方向后，你需要在第一个要布线的终点上方打开一块吊板。检查两个区域之间的路径是否有障碍物、需要绕过的风道或其他可能的问题。决定先走哪个最佳方向并朝那个方向移动。你问怎么过去？嗯，你无法在上面走或爬，所以你必须想办法把电线从 `A` 点传到 `B` 点。

有几种方法可以实现。我最喜欢的几种方法几乎让过程变得有趣。它们都涉及到绳子。通过沿着同一路径通过绳子，你可以将电线系在绳子上并拉过去。（你知道，他们管这叫拉拉线是有道理的。）不要用细弱或细小的绳子，比如风筝线，因为用力拉可能会割伤你的手，或者在电线卡住时断裂。使用几根纤维织在一起像小绳子一样的尼龙绳。例如，扎包裹用的绳效果应该很好。

去第一个打开的吊板 20 到 30 英尺远，在两个已经打开的吊板之间打开第三块。将绳子从第一个打开的吊板拉到沿线中的下一块，每隔 20 到 30 英尺重复一次，直到到达目的地。要将绳子从第一个孔传到第二个孔，你可以使用这些有趣方法之一：

- 获取一把小型弩箭，将绳子系在箭上。如果可能，务必取下箭头，或者确保避免撞击任何可能损坏的物体。直接横过下一个开口处发射，这样你到达那里时就能找到绳子。你也可以像使用弩箭一样使用玩具飞镖枪。

- 在绳子上系一个重物，并向目标投掷或扔过去。这稍微麻烦一点，但因为我们这类网络人员身边很少有弩箭，你更有可能使用这种方法。一些适合系在上面的较好物品是大鱼码、一卷胶带（电工胶带可以；防水胶带卷很重，可能会导致问题）、一把钳或其他工具（如活动扳手）。尽量避免使用在飞行中会晃动，或在落地时可能会刺破吊板的物体。

- 如果吊板上方的空间非常小——我讨厌这种方法——你可能必须一个接一个地拆掉它们，只需将绳子从一块拉到下一块，直到到达尽头。

在任何情况下，在射出或扔绳子末端之前，务必拉出足够的绳子到达下一个位置。否则，你扔出的重量在到达绳子末端时会直接弹回你身上。另外——抱歉，我必须说这个——在扔或射之前，确保你已经固定了绳子的一端。把整卷绳子射到天花板对面却不得不重来是非常沮丧的。一旦到达下一个孔，只需重复该过程，直到有一根长绳从一端延伸到另一端。

绳子法也适用于其他类型的布线情况，但不要尝试在狭窄空间或需要电线转很多弯的区域使用它。

当你拉好绳线后，就可以拉电线了。最好的方法是让一个人在另一端供线，而你在另一端拉。偶尔电线会卡在某些地方，你可能需要打开电线卡住处的吊板以让它继续通过。支撑吊顶网格的钢线在这方面很有名，因为它们在网格中形成一个圈然后自我缠绕，留下松端伸出来。

### 绳线合在一起拉

从这里开始，每个线路基本上相同。你可以按照上述针对每个位置的操作从一个位置移动到另一个位置。到达每个位置后，你必须决定是沿墙向下布线、在墙内布线到现有线盒，还是在墙内布线到你添加的新线盒。

### 其他类型的建筑

当然，并非所有建筑都是新的，布线还有其他方法。你可能需要向他人咨询你的特定设置。有些建筑预装了电线管，留有拉过更多电线的空间。有些建筑有地下室或爬行空间，你可以在其中布线。在某些情况下，你可能实际上需要绕过建筑外部从一个房间到另一个房间。只需确保你查看了所有选项，并根据安装简易性、美观性、扩展性、电线保护（等）以及到达电话柜的能力选择了最佳方案。

### 墙内布线

一旦你从电话柜到达第一个位置正上方，你可能沿着墙的内部向下布线。如果这是石膏板或安装标准墙柱上的墙板，你应该能够轻松地做到，特别是墙内没有隔棉的情况下。（除非有隔音需求，否则内墙很少有隔棉。）

### 在墙柱之间的墙上向下布线



在开孔之前，确保你位于两根墙柱之间。检查电源插座以确定正确的高度，使开口匹配。此外，确保对面墙上没有电源插座。你可能会切到某些线路，因为布线有时会在同一高度横跨墙面。为了避免这种情况，勾勒出要切割的区域。使用小刀或美工刀切割墙板。注意不要让刀尖伸进墙内太深。一旦开好孔并确定安全，你可以使用小锯或更大的刀清理切割边缘。

## 网络布线

为了将设备连接到网络，我们需要在设备之间使用某种介质，以便数据包从一个设备传输到另一个设备。这就是网络布线的用武之地。你可以使用不同类型的电缆来连接网络，但在今天现代硬件条件下，我们倾向于使用的只有两种类型。

直通以太网线有两种标准的布线方案。它们分别是 `T568A` 或 `T568B`，其中 `T568B` 是美国更常用的布线方案。两者唯一的区别是绿色对和橙色对的引脚位置对换了。任何一种方案在你的网络上都能正常工作，但除非你想遇到通信问题，否则不要混合使用。是否使用所有四对线取决于电缆的类别。例如，旧的 `10/100Mbps` 电缆仅使用两对，而 `1Gbps` 电缆将使用所有四对线，以便同时传输和接收。

有些人喜欢自己动手制作电缆，以便确定精确的长度。这是一个相当繁琐的过程，除非你非常精通，而且你还需要用电缆测试仪测试每一根制作的电缆，以确保其工作正常。

### 交叉线

交叉线用于连接类似的设备，例如交换机到交换机、路由器到路由器，或路由器直接连接到主机。这些电缆的外观和手感相同，但布线方案是它们不同之处。它们被称为交叉线，是因为八根线中的四根线在一端的布线方式与另一端相反。

如果你留了心，可能会发现交叉线基本上就是一端使用 `T568A` 布线方案、另一端使用 `T568B` 布线方案的电缆。

为了方便记忆，这里有一张表，列出了你在什么情况下使用直通线对比交叉线。

### 回环线（Rollover Cables）

我要提到的最后一种电缆被称为回环线，也称为空调制解调线（`null modem cable`）。这些电缆用于将 PC 连接到交换机或路由器的控制端口，以便在无法通过通常的网络端口连接时执行管理功能。

回环线一端的引脚定义在另一端是反转的。一端是 `RJ45` 连接，另一端是 `DB9` 连接。`RJ45` 连接插入交换机或路由器的管理端口，而 `DB9` 将连接到计算机的串口。大多数新电脑已不再有串口了，因此你除了回环线外还需要一个 USB 转串口适配器。一些高端交换机现在带有用于管理的微 USB 端口，因此你实际上可以使用 USB 线连接，甚至可以使用智能手机！

现在你已经知道什么是以太网线以及它是如何布线的，我想花一点时间讨论一下以太网线的类别。在 `Cat5e` 之前有一些变体，之后也有一些，这里是以太网线标准及其最大速率能力的快速摘要。

- 第3类（`Category 3`） – `10Mbps` 和 `16Mhz` 频率
- 第4类（`Category 4`） – `16Mbps` 和 `20Mhz` 频率
- 第5类（`Category 5`） – `100Mbps` 和 `100Mhz` 频率
- 第5e 类（`Category 5e`） – `1Gbps` 和 `100Mhz` 频率
- 第6 类（`Category 6`） – `1Gbps` 和 `250Mhz` 频率
- 第6a 类（`Category 6a`） – `10Gbps` 和 `500Mhz` 频率
- 第7 类（`Category 7`） – `100Gbps` 和 `600Mhz` 频率

这些高速（如 `1Gbps` 及以上）是通过使用四对线而非仅用两对，以及增加线芯每厘米的扭转次数来实现的。`Cat6` 及以上的电缆还有尼龙骨（`nylon spline`），这有助于消除串扰，串扰是来自一个电路对另一个电路的干扰。另一种类型的以太网线称为屏蔽双绞（`STP`），它在电线周围包裹了保护屏蔽层以进一步防止干扰问题。`STP` 电缆更贵且更难处理，因为由于屏蔽层的存在它们不够灵活。当电缆没有屏蔽层时，它被称为非屏蔽双绞线或 `UTP` 电缆。

### 802.11i

`802.11` 无线连接标准的设计旨在取代早期的有线等效协议。`802.11i` 也称为强壮安全网络（`Robust Security Network`）。`802.11i` 通过 `RADIUS` 等多种协议提供认证。`802.11i` 还支持 `CCMP` 加密。值得，`802.11i` 允许在不更换硬件的情况下升级有线等效协议。

### 认证

Wi-Fi 安全联盟（`WPA2`）认证其符合 `802.11i`。通过由中央机构管理开发，一致性和质量可能得到保证。此外，拥有一个协调的中心点对于增强安全性是必要的，可以确保只有意良好的实体参与开发。

### 临时密钥完整性协议

`TKIP` 指的是对于 WLAN `802.11i` 标准不可或缺的加密协议，它的设计旨在提供比有线等效协议更安全的加密。在应用中，`TKIP` 由一组算法组成，这些算法作为有线等效协议的封装，允许旧局域网设备在无需更换硬件的情况下升级。`TKIP` 通过利用早期的有线等效协议工作。`TKIP` 通过增加四个额外算法增强稳健性：

- 密文消息完整性检查：它是一种向量序列机制，使用哈希算法而不是有线等效协议的明文传输。哈希意味着数据已加密并赋予一个唯一值，可以通过检查该值来确认传输期间是否有修改。
- 逐包密钥混合函数：通过混合加密密钥，恶意用户破坏数据完整性变得越来越困难，因为破解加密所需的计算能力变得几乎不可不可及。
- 重新密钥技术：通过为每固定数量的传输数据包创建新密钥，攻击者很难在截获的数据中建立共同模式，这增强了无线连接的安全性。

相比之下，`TKIP` 对于升级最初配备有线等效协议的设备的安全性至关重要，但它无法解决有线局域网连接面临的所有安全问题，并且对于敏感的政府和企业数据传输来说可能不够高效或可靠。高级加密标准（`AES`）在 `802.11i` 标准中与 `TKIP` 一起被规定。`AES` 提供了更高程度的安全性并被推荐。

政府使用，但需要升级硬件才能实施。由于大多数组织正在更换旧的无线接入器和支持无线功能的设备，高级加密标准（`AES`）有望成为无线连接安全的标准加密方法。

带计数模式密码分组链消息认证码协议（`CCMP`）。

作为一种加密标准，带计数模式的密码分组链消息认证码协议是 `802.11i` 无线连接标准不可或缺的一部分，特别是实现 `WiMax` 技术的连接。

`CCMP` 算法基于美国联邦政府的高级加密标准。可以认为该标准旨在为无线连接提供最高程度的数据加密。

与 `TKIP` 等类似技术相比，`CCMP` 协议提供了更高的安全性。特别是，带计数模式的密码分组链消息认证码协议部署了 `128` 位密钥以及 `48` 位初始化向量，这降低了对重放攻击的脆弱性。具体而言，计数模式组件提供了数据隐私性。另一方面，密码分组链消息认证码元素提供了数据完整性和验证。与 `CCMP` 协议的临时密钥完整性协议（`TKIP`）相比，增加的隐私性和安全性在大多数情况下需要额外的处理能力来处理，这需要升级硬件。

### 无冲突服务

为了理想地利用需要近乎实时服务的应用程序，网络管理员应该使用 `802.11` 标准。该标准包括一种协调功能，提供了访问无线网络的不同方式。`PCF` 被定义为协调点功能（point of coordination function）。`PCF` 使 `802.11` 网络能够强制访问介质。在某些情况下，在 `PCF` 下访问介质类似于使用令牌（`token`）访问介质。

`PCF` 未被广泛使用，是因为在过去，一个媒体服务器曾实现 `PCF` 但并未成功。某些企业级产品使用 `PCF`，因为它提供了接入点对无线连接接入的额外控制。此外，`PCF` 帮助无线网络从单个网络站手中夺回控制权。如果需要无冲突交付，可以实施 `PCF` 以获得最佳结果。注意，`PCF` 是 `802.11` 标准中的可选内容。产品并不强制要求使用 `PCF`。然而，`PCF` 是 `IEEE` 专门为使用分布式协调函数的站设计的。

### 详细的 PCF 帧

无冲突期间（`CP`）使用几种互斥的帧。它们以不同的状态结合在一起：

- 轮询（`Polling`）
- 确认（`Acknowledgment`）
- 数据传输

本章解释了不同类型的帧如何整合，以及各种功能在帧传输期间组合的方式。

无冲突帧通常将多个功能合并到一个帧中。

`Data+CF-ACK`

它是为了传输期间的效率而将两个功能结合的帧。信息位于帧的有效负载中，并且帧确认了信息的接收。通常，信息和确认需要两个独立的网络站。冲突确认侧重于中继到前一个帧接入点的信息。

`CF-ACK`

如果只需要确认，则中继一个头部仅包含 `CF-ACK` 功能的帧。`CF-Poll` 可以单独传输信息。

通常情况下，只有接入点（`access points`）可以将信息从一个无线网络继到另一个网络。当接入点没有针对接收者的缓冲信息，且不需要确认其他帧的接收时，就会传输“裸”的 `CF-Poll`。在接入点每次交换 `CF-Poll` 时，不需要确认，这是一种常见的情况。此外，有时被询问的网络站没有信息且不响应。每当接入点没有下一个网络站的信息时，它们就会发送 `CF-Poll`。

`CSMA` 是无线连接用于共享介质访问的基础技术。`IEEE 802.11` 标准协议旨在克服因干扰导致帧丢失而引起的功率损失。干扰可能源于任何运行不正常的网络站。

## 网络实用

### ARP 工具

此工具用于显示某个 IP 地址是否正在被解析以获取 MAC 地址。

### NETSTAT 工具

此工具用于生成 TCP/IP 实用程序，`nbtstat` 将生成 TCP/IP 之上的 NetBIOS 统计数据。该命令通常显示本地地址如何映射到远程地址。

### TRACERT 工具

此工具用于查找网络上从一台计算机到另一台计算机的现有路径。

### Ping 工具

此工具用于检查特定主机是否有响应。要解析本地主机（`localhost`），应使用 IP 地址 `127.0.0.1`。执行命令后会发送 4 个响应数据包。

### FTP 工具

此工具允许通过互联网向 FTP 服务器上传和下载文件。

### `ipconfig` 和 `ifconfig`

`Ipconfig` 用于显示 Windows NT 以及其他较后版本各种操作系统的 TCP/IP 配置信息。`Ifconfig` 用于在 UNIX 环境中执行相同任务，并用于对某些用户界面任务进行配置。

### `winipcfg` 工具

此工具用于显示 Windows 95/98 中的 TCP/IP 配置。

### `dig` 工具和 `nslookup`

这些工具用于显示有关 DNS 解析的信息。

## 为什么要实现网络自动化？

“旧事物的遗迹必须被体面地安放，新事物的道路必须做好准备。这就是革命与进步之间的区别。” - 亨利·福特

变革的时刻已经到来。企业网络已经超越了使用传统工具进行有效管理和维护自身的能力。从历史上看，网络管理意味着从单个设备手动收集时间点信息，或对设备进行配置更改。网络通常使用配置命令驱动的方法，而不是数据驱动的方法。员工在 `CLI` 处手动执行命令以收集信息或执行更改。在做出更改后，通常需要重新收集信息以确认网络状态。网络文档的持续创建和维护也是手动进行的。做出更改需要数小时的工作，而且经常在不同的设备上重复相同的命令。由于使用手动方法会导致错误，不可避免地需要故障排除。网络自动化解决了所有这些问题。

### 规模

现代网络的规模呈指数级增长，以满足组织的需求。最初几个交换机和一个路由网络现在变成了大型企业网络。虽然逻辑网络在演变增长，但管理物理设备的工具仍然停滞不前。在校园网上，我们现在看到 `VoIP` 电话、无线访问点、`IoT`、安全摄像头、打印队列、桌面集群和会议室设备。在数据中心，大型物理和虚拟足迹并不罕见。在每个远程办公室都有交换和路由的全球 `WAN` 现在已成为常态。设备热潮并未放缓，越来越多的设备被加入网络，而没有相应的集中化、自动化管理解决方案。

网络管理始于控制线和本地 `CLI`。管理员必须通过管理 IP 地址启用对 `CLI` 的远程访问。现在想象一下网络技术人员仍然需要前往每个设备的物理控制台来管理它。这听起来不合理，但只有对 `CLI` 的远程访问是集中的。它遵循与登录 `CLI` 管理设备的相同方法，就好像操作员实际上位于控制台前一样。事实上，这些远程连接被称为虚拟电打字机或 `VTY` 线路。在当今网络的规模下，连接到每台设备的 `CLI` 来管理企业是完全无法实现的。即使有一支功能强大的网络运营团队，每个人也会按照自己的方式来操作、配置和管理每个设备。这导致了规模化下的配置漂移和缺乏一致性。

由于设备配置是模板化的，自动化解决方案随网络规模而扩展。小型的、针对特定功能的、模块化的模板确保了每个设备都经过标准化。当出现新功能需求时，配置命令被模板化并在规模范围内发布，从而统一更新网络标准。独特的、特定于设备的、有意义的信息被建模在数据字典中。该字典包含了用于为每个设备编译唯一配置的所有变量。代码可以模块化地编写，以匹配网络拓扑。通过创建针对特定环境（如校园、数据中心、`WAN` 或云）的剧本，`Ansible` 剧本确保了代码的简单性、可读性和开发灵活性。

### 复杂度

网络的复杂性大幅增加。虚拟路由转发器 (`VRF`)、`QoS`、无线连接、云连接、虚拟专用网络 (`VPN`)、第一跳冗余协议 (`FHRP`) 如热备路由器协议 (`HSRP`)、虚拟交换系统 (`VSS`) 以及作为 `802.1x` 的安全和身份服务，增加了设计工程师和运行网络操作员的能力。从网络中抽象重要数据允许操作员将设备视为一组人类可读的变量。设备配置的可读性减少了理解设备如何配置的技术要求。

### 文档

网络文档极其重要，特别是在危机期间，但在日常操作中经常被忽视。更改可能未反映在文档中。文件可能分散在各种源中，例如本地驱动器、`SharePoint` 站点或网络共享。过时的文档对组织价值很小。存在的文档通常表示为复杂的 `Visio` 图、大型 `Excel` 表格或与网络动态交互的文本文件。

`TFS` 仓库主分支的一部分应该是一个文件夹结构，包含动态文档 `Ansible` 剧本，以及生成的输出产物的文件夹。自动化文档可以直接构建到 `CI/CD` 流水线，创建逗号分隔值 (`.csv`)、`Markdown` (`.md`) 或文本文件。这些文件随后被纳入 `Git` 提交和拉请求，成为代码库和仓库的一部分。`TFS` 和 `VS Code` 可以原生查看这些文件，提供代码形式呈现的网络视图。这些产物包括预期的、自动生成的配置文件，以及用于以不同格式表达数据的模型变量。

例如，是否可以根据数据模型变量为每个设备自动生成以下文档：

- `VLAN`
- `VRF`
- 路由协议配置信息
- 静态路由
- 接口信息：
    - 开启/关闭
    - 模式 – 访问或中干
    - `VLAN` (s)
- 端口组信息：
    - 成员端口
    - IP 地址
    - 访问控制列表 (`ACL`)

事实上，任何表示在数据模型中的信息都可以转换为动态文档文件。这允许获取关于网络上的任何设备在构建时自动生成的所需信息，并可以通过 `TFS` 获取。这些文档文件的历史作为源码和版本控制包含在内。当添加或删除代码时，生成的文档会自动进行更新以反映这些更改。

### 标准

随着网络的演变和转型，企业标准的维护随时间推移变得非常困难。通常，项目压力和日常工作的交付物会导致标准被忽视、推迟或忽略。随着网络设备和 IP 地址的来来去去，随着时间的推移可能会发生自然的配置漂移。如果网络设备继续运行，错误的配置或糟糕的标准可能不会被察觉。一旦被识别出来，这些表面的更正可能被视为低优先级。

`Ansible` 的动态模板化保证了每个设备都有标准的配置。可以实现完全的配置覆盖，并且运行配置中的每一行代码都可以从模板派生。通过在“真理源”与设备配置之间实现完全的幂等性，可以确保基于意图的标准得到统一应用。使用这种方法，规模不是问题，人为错误的因素也是如此。当出现新标准或需要对现有标准进行更改时，只需更新集中的模板和数据模型。这些更改将通过自动化引擎推送，并将新标准交付到网络。

### 黄金配置（Golden Configuration）

黄金配置在 Windows 操作系统管理中被称为“预期状态配置”，它有很多名称。通过使用 `Jinja2` 模板和 `YAML` 数据模型，可以使用软件开发方法论实现网络中每个设备的黄金配置。模板内部的逻辑用于智能地生成设备配置命令。这些配置将大规模应用于包含在 `Ansible` 的 `hosts.ini` 清单文件中的所有设备。

主分支（`master branch`）代表网络的黄金配置。自动化构建会将主分支的各种构制品打包，并为该迭代版本的网络提供一个版本号。然而，当需要更改时（无论多微小），会创建工作分支进行代码开发和测试。开发期间频繁的 `Git` 提交用于将更改检入工作分支。通过拉取请求（`pull request`）将这些累积的更改合并到主分支，然后将其部署到生产环境中，大规模地更新标准的黄金配置。

## 安全

一些重大的安全泄露发生是因为 `telnet` 在具有公网 IP 地址的端口上开启。安全标准和最佳实践现在可以硬编码到模板中，以确保策略的执行。通常，访问层的接口上需要复杂的配置来解决安全风险。考虑访问层以及应该实现的所有以下安全标准：

- 生成树工具包命令。
- 桥接协议数据单元 (`BPDU`) 控制。
- `Portfast`。
- `802.1x` 或端口安全命令。
- 数据和语音 `VLAN`。
- `QoS` 设置。
- `CDP` 设置。
- 以太网供电 (`PoE`) 设置。
- 建立 `Native VLAN`。
- 在汇干口上应用 `Native VLAN`。
- `NTP` 源。
- 登录时显示安全横幅（Security banner）。
- `AAA`。
- `RADIUS` / `TACACS+`。
- 管理端口上的 `ACL`。
- 禁用 `VLAN 1`。



安全需求如果缺失或应用不当，将导致网络内部漏洞和威胁。这些漏洞可能会被利用，在某些情况下导致中断或数据丢失。拥有有保证的模板配置确保了重要的安全组件被硬编码到每个模板中，并应用于设备的全局配置以及每个接口配置。现在整个校园的每个访问端口都可以以相同的方式进行配置，并自动包含安全态势标准。

### 敏捷性

在按需的世界里，网络仍然是许多项目的瓶颈。转向自动化的推动因素之一是它提供的敏捷性。网络大多数常见的更改都变成了对现有数据模型的更新。当出现新功能需求（如对组播的需求）时，将开发新的模板以及新的数据模型变量。然后发布该功能并将其作为新任务整合到剧本（`playbooks`）的编排中。演变出一种非常可重复、模块化的流程，提供了更高效交付项目的敏捷性。

### 设计

传统的网络设计通常围绕设备配置命令展开。虽然这些命令在实施阶段至关重要，但驱动网络设计的应该是数据。网络工程师的新职责包括编写人类可读的数据模型以及驱动动态模板的逻辑。现有或新的动态文档应随着模板的添加或更新反映新功能。通过先考虑数据，后考虑配置，网络设计随之演进。

### 部署

网络自动化发现的最大优势通常位于网络管理的运营侧。大规模的更改通常很难推送到企业中。例如，在网络中引入 `QoS` 意味着触及网络所有层的所有设备，且每个平台通常有不同的代码。使用多层交换（`MLS`）或模块化质量服务命令行（`MQC`）的设备会导致不同平台产生不同的需求和配置命令。运营部门从网络工程师处接收批准的、最终的网络设计以及部署步骤。这通常需要几周或几个月才能从开始到结束完成到校园的交付。网络自动化（即使操作人员手动运行 `Ansible` 剧本的混合模型）解决了向网络部署配置相关的运营难题。使用 `Ansible` 剧本可以大幅减少部署时间，同时提高质量和准确性。

### 运营

`NetDevOps` 将极大改变网络运营在组织中的角色。一个预制的自动化 `Ansible` 剧本库随着时间的推移而建立。每当批准的更改合并到仓库时，就会触发自动化构建和部署。运营部门通常负责网络的日常运行，合并并部署来自项目或网络工程师的更改。运营部门现在将学习开发和使用代码。如果可以将运营的部署、网络侦查和文档方面实现自动化，将允许运营团队专注于网络的日常方面，以及用于收集信息的自动化工具。尽管如此，网络可能仍然需要网络管理系统（`NMS`）进行平台健康监控。网络可能存在不适合自动化的网络设备或控制器，或者存在值得注意的非 `SSH` 系统。

### 基于意图（Intent-Based）

这种方法论的人类可读性允许实现真正的意图驱动网络模型。配置被抽象到模板中，因此重点可以放在数据模型上。每个设备或设备组的意图可以用可读的形式表示。幂等的 `Ansible` 剧本结合检查模式（`check mode`）可以准确判断设备的运行配置是否匹配意图，以及 `Ansible` 剧本是否会添加代码。利用差异选项（`--diff`），操作人员可以看到两个配置之间的差异，还可以显示设备上存在但意图中缺失的命令。现在有基于设备的解决方案提供了一种 `GUI` 驱动的意图系统。在 `GUI` 中拖放意图会被转换为配置并自动推送到设备。这些新的基于意图的设备是 `Ansible` 网络自动化的最大对手。要么购买并配置设备，希望它能实现所有宣传的功能，要么构建内部的 `Ansible` 自动化框架。

使用新的 `NDLC`，`TFS` 中存在一个活跃的“单一事实来源”（`source of truth`）。这是一个包含数据模型、模板和 `Ansible playbook` 的丰富仓库，它还存储了每个设备编译的、基于意图的动态生成的配置文件。`TFS` 是网络单一、集中且受 `RBAC`（基于角色的访问控制）控制的事实来源。`TFS` 仓库可以作为未来所有网络设计和故障排除的参考。事实来源意味着可以通过浏览创建配置的数据模型或模板，或查看显示精确设备配置的编译输出，而无需连接到设备 `CLI`。其他制品（如路由表或防火墙规则列表）也可以作为动态 `playbook` 的输出存储在事实来源中。这并不是每个网络都能具备的，但在设计新功能、规划未来更改、处理网络故障或排除问题时，它是不可或缺的

### 变更管理

网络自动化有助于简化变更管理过程，因为它是拉取请求（`pull request`）的自然部分。可以锁定主分支，仅允许通过通过的更改合并。审批者拥有所有必要的制品来批准、拒绝或有条件地拒绝要求开发者提供更多信息的拉取请求。文档会自动生成，且设备数据模型或动态模板的更改在 `TFS` 中清晰可见并高亮显示，便于审批者查看。

### 示例流程：

- 新需求 / 更改 / 功能 / 修正 / 重构。

- 添加到 `TFS` 中的工作板。

- 分配工作。

- 创建新的工作分支。

- 工程师执行 `git pull` 下载中央仓库的更新。

- 工程师在本地 `VS Code` 中切换到新分支（`git checkout`）。

**开发工作：**

- 添加 / 更改 / 删除代码。

- 测试 – `check mode`。

- 生成文档。

- 工程师经常执行提交，理想情况下针对较小的相关更改。

- 工程师执行 `git push` 将更改上传到中央仓库。

- 工程师在 `TFS` 中提交拉取请求。

- 拉取请求触发审批工作流。

- 通知审批者/评审人员。

- 拉取请求被批准或拒绝。

- 已批准的请求合并到主分支。

- 触发自动构建。

- 更新文档。

- 触发自动测试。

- 调度自动发布。

- 通过 `Ansible` 将更改交付到环境。

或者，如果尚未建立完全的 `CI/CD` 自动化，操作人员将手动执行已批准的 `Ansible playbook`。

### 恶意软件：黑客的帮凶

`malware`，包含了黑客用于渗透他人网络或计算机系统的工具，目的是获取可能是个人或属于组织的信息。`malware` 是黑客用于瘫痪或破坏计算机或网络运行的软件，从而获得访问信息的机会。这种软件旨在对他们攻击的网络或系统造成故意破坏。通常，`malware` 违背用户的利益。`malware` 有两种类型：造成无意危害的软件和专门设计用于危害的软件。`badware` 一词被用来定义两者。

`malware` 的设计目的是隐蔽工作，因为其目的是从目标系统中收集敏感信息。它们可以运行长时间，用户可能不知道它们隐藏在自己的系统中。它们在用户不知情或不同意的情况下隐藏。它们被专门设计用于造成危害、获取信息、勒索或破坏系统。`malware` 和侵入性软件都属于 `malware`。这些包括各种程序和软件，如木马、病毒、广告软件、间谍软件、蠕虫和其他 `malware` 程序。所有这些软件都伪装成非恶意程序。根据最近的研究，使用的多数 `malware` 是蠕虫和木马。以前病毒曾是最广泛使用的 `malware`，但它们的数量已经下降。

### 恶意软件类型

-   `adware`：这些被认为是所有 `malware` 中危害最小且最获利的。它们被专门设计在你的计算机上显示广告。
-   `spyware`：黑客选择 `spyware` 来持续监控用户。这些程序设计用于随时跟踪用户。它们监视用户的互联网活动并相应显示广告。它们帮助 `adware` 利用收集的信息，以便用户在线时可以使用。
-   `virus`：`virus` 是具有传染性的程序或代码。它们附着在其他运行的软件上并可以自我复制。它们所附带的文件、文件夹或程序在使用或通过直接文件共享或网络传输到其他系统时传播 `virus`。
-   `worm`：这些是设计用于破坏操作系统文件的小型程序。它们像 `virus` 一样，可以自我复制并隐藏在文件夹中。它们消耗处理器和硬盘资源，减慢进程并减少硬盘上的可用空间。某些 `worm` 是无害的，而其他则不断复制直到驱动器变满。
-   `trojan`：`trojan` 专门设计用于窃取用户信息。这包括财务和个人信息。在所有 `malware` 中，这些被认为是最危险的。对于拒绝服务攻击，黑客使用 `trojan` 作为主要工具。它们帮助黑客跟踪用户的活动。它们维护用户活动的日志。
-   `Rootkit`：这些是允许其他 `malware` 进入系统的软件程序。像 `trojan` 一样，它们在用户未察觉的情况下隐蔽工作。对于用户来说，看起来没有任何问题，但在后台，它打开了多种类型 `malware` 的门户。
-   `Keyloggers`：键盘记录器专门设计用于记录所有键盘信息。它们只能存储给键盘的信息，无法记录数据。

### 主要漏洞

任何 `malware` 都可以利用的主要漏洞。

这既适用于小型和大型软件程序，从仅有几行代码的软件到像操作系统这样极其庞大的软件程序。只要安全上存在薄弱环节，这些程序都是易受的。过时的插件和旧版本的软件（如浏览器）是最常见的易受软件类型。你不能因为安装了更新的插件就认为它是安全的。某些插件会保留已的旧版本，这可能会损害该软件的安全性。

设计不安全或用户错误：诱骗用户运行受 `malware` 感染的特定文件是传播 `malware` 的另一种常用方法。此类类别可能包括复制到硬件（如 `USB` 设备或闪存盘）中的 `malware`。当使用这些硬件时，`malware` 会自动执行并附着到用户的系统中。如果该系统连接到网络，`malware` 就有可能跨越网络传播到每个连接到该网络的系统上。这是黑客用于传播 `malware` 的一种非常有效的方法。

使用过时的防毒软件：使用过时或免费的防毒软件的效果不如使用最新的更新版本。更新后的防毒软件会在其数据库中包含所有新的病毒和 `trojan` 的定义。旧版本的防毒软件可能保护你免受旧威胁，但它们无法检测并防止你受到新的 `malware` 和威胁。

特权用户和特权代码：在计算中，权限意味着修改系统的访问权限。在某些软件中，用户被赋予了比他们应有的更多的访问权限或权利。这通常发生在设计不当的软件上。`malware` 可以利用这种漏洞。`malware` 可以利用此漏洞的方法有两种，如下：

1.  特权用户：在某些系统中，用户被赋予更改和修改程序代码的权限。这样的用户被称为特权用户。
2.  特权代码：在其他某些系统中，用户执行的代码将被赋予更多权限。这些权限包括访问和修改系统资源的权限。此类代码被称为特权代码。少数操作系统和一些脚本语言会将这些权限赋予代码，使其成为特权代码。

在这些情况下，当用户执行代码时，系统将作为运行代码的用户为代码提供所有权限。这将导致系统受到来自互联网的 `malware` 的攻击。

### 同质性

当一组系统都连接到同一个网络并在相同的操作系统上运行时，它们就是同质的。这种现象被称为同质性。当存在同质性时，`malware` 更容易在连接到该网络的所有系统之间传播。例如，如果其中一个系统中存在 `virus`，它可以自行传播到该网络中的所有系统。同质性存在于各种组织中，如学校、大学和大多数软件机构。大多数系统运行在 `Windows` 或 `Mac` 操作系统上。专注于其中任何一个操作系统都会为黑客提供极佳的机会，来利用大量运行在这些系统上的系统。解决同质性的一种方法是在每个系统上使用不同的操作系统。这将使 `malware` 的传播变得困难。但在初始阶段存在一些缺点，例如培训和维护成本较高。

### 掩盖足迹

一个优秀的伦理黑客永远不会留下他们入侵的痕迹。黑客无法承担留有其已入侵网络或系统证据的风险。在这种情况下，黑客可以使用 `malware` 清理所有记录（例如事件日志），并实现干净的退出。有许多类型的 `malware` 可以隐藏网络流量并清理目录。

-   `proxy server`：对于意图穿过网络敏感区域的黑客来说，利用 `proxy server` 是一个非常好的主意。`proxy server` 不会被入侵检测软件检测到，因为它们不会留下任何痕迹。

为了成为一个优秀的黑客，你应该能够根据你当前的有效载荷（`payload`）选择正确的 `malware`。`trojan` 通常是黑客可以利用的最好的 `malware`。这是因为它们的隐蔽性以及长时间监控用户的能力。

### 网络犯罪软件

黑客用于黑客的软件工具有时被称为网络犯罪软件（`crimeware`）。`crimeware` 可以定义为：

-   通常不是理想的硬件或软件应用程序。
-   主要用于在线犯罪活动。
-   非自愿地导致犯罪。

`crimeware` 的一种类型是机器人（`bot`）。下面简要描述了机器人。

### 机器人 (`Bots`)

什么是机器人？

`Bot` 是 `robot` 的缩写，但它们与科幻电影中的机器人不同。它们甚至不是公司生产线制造的机器人。它们可以被认为是今天互联网面临的最复杂的 `crimeware` 之一。这些机器人与 `trojan` 和 `worm` 非常相似。它们与其他类型的 `malware` 不同之处在于，它们会代表放置它们的攻击者执行的各种自动化任务。这些攻击者通常位于互联网上的安全位置。机器人可以执行诸如发送垃圾邮件等任务，这属于拒绝服务攻击。被机器人感染的计算机将受到攻击者的控制；这些机器被称为僵尸主机（`zombies`）。

机器人可以通过许多不同的方式溜入计算机。它们在互联网上寻找未受保护的计算机。当发现易受的计算机时，它们会迅速感染它并向攻击者报告。它们被专门设计为保持隐藏，直到主命令它们。机器人并非设计为独立工作。它们与其他被感染的机器共同工作。这组机器被称为僵尸网络（`botnet`）。僵尸机器将由命令和控制中心（这是一个主计算机）控制。攻击者使用命令和控制服务器指示僵尸执行活动。通常，`botnet` 由大量被机器人感染的机器组成。这些分布在全球范围内。较小的 `botnet` 可能包含数百或数千台计算机。较大的 `botnet` 拥有十万台僵尸。

## IPv4 汇总

### 目的与配置

好了，你终于通过了子网划分和 `VLSM`。现在是时候汇总（Summarize）了，或者用 `Spock` 的话来说，“路由聚合队长”（你可能注意到我是原版《星际迷航》的超级忠实粉丝）。这实际上意味着，我们必须将许多小网络聚合成一个或可能两个网络，然后将它们发布给我们的核心路由器，从而减小它们的路由表。您的核心路由器不需要了解所有不同的局域网（`LAN`）来做出路由决策。“路由聚合”的另一个用途是发布汇总地址。这是为了让目的层的设备能够根据其意愿分配 `IP`。

汇总允许路由器在分析其自身的路由表以查看到达目的地需要哪条路径时，处理时间更短。

`Cisco` 有一个名为“`Cisco` 三层模型”的标准。该模型就像 `OSI` 模型一样，是一个理论模型。该模型仅根据路由器在拓扑中的位置告诉您某些路由器可能执行的角色；让我们来看下：

**`Cisco` 三层模型**

| 层 | 描述 |
| :--- | :--- |
| 核心层 (`Core`) | 核心层的唯一目的是可靠、快速地交换信息。 |
| 分布层 (`Distribution`) | 该层的主要目的是提供路由、过滤、`WAN` 访问，并决定有多少数据可以访问核心。此层也可以“工作组层”。 |
| 接入层 (`Access`) | 这一层也称为“桌面层”，是分布层的扩展。这是我们谈论的地方。 |

有 15 条条目需要确定将数据包发送到哪里。然而，我们将通过总结每个局域网网络并将它们的汇总地址通告给总部路由器来帮助解决这种情况。这将条目数量减少到三条学习到的路由，反之，减少它的三个连接路由。这样做将减少开销，路由器只需要查看 3 条学习到的路由，而不是 12 条。那么，我们该如何做到呢？让我们来看看吧？

请记住起始掩码是 `/24`。随后，我们从左到右计数；你将从第三字节的开始开始，这就是感兴趣字节（interesting octet）。

汇总地址 `192.168.8.0/22`

现在我们已经通过在公共位和非公共位之间画线找到了汇总地址，现在是时候通过面向总部路由器的接口向总部路由器通告了。以下是你将使用的命令：
