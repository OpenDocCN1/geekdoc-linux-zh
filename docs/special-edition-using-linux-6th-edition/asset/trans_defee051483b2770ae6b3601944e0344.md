

但对于那些仍然留在网络上或记住先前信息的客户端，前面解释的针对新客户端的流程会被绕过。在这种情况下，客户端跳过发现过程，直接从DHCPREQUEST消息开始。如果客户端已移动到另一个子网，它会从服务器收到DHCPNAK，然后重新开始发现过程。否则，服务器使用在DHCPREQUEST消息中收到的uid信息，以及客户端请求的IP地址，来验证该客户端是否是最后一个使用所请求地址的客户端。如果是这样，就可能通过DHCPACK将该租约释放给该客户端。

## 故障排除

*我配置了DHCP服务器（/etc/dhcpd.conf），并告诉系统启动它，但它没有启动。现在该怎么办？*

最可能的问题是/etc/dhcpd.conf文件中存在错误（拼写错误或其他错误）。在启动期间，错误消息会被抑制，因此您不会看到它们。您需要做的是从命令行启动dhcpd。错误消息会告诉您DHCP服务器软件（dhcpd）认为问题出在哪里。但请记住，如果您忘记末尾的分号，错误会出现在下一行。此外，您必须为每个接口的子网提供一个subnet语句（即使主体完全是空的）。

*我已经运行了DHCPD，我的大多数系统都能从服务器获取IP地址，但少数系统不能（防火墙另一侧的那些）。*

如果您正在运行DHCP服务器，请记住，除非您在网关上运行dhcrelay，并且正确配置了DHCP服务器以配置该子网，否则它只能为本地子网提供地址。这些细节超出了本章的范围，但文档充分解释了这种设置。

*我正在运行微软的DHCP服务器，却无法从中获取地址。*

不幸的是，微软的DHCP服务器实现不符合RFC标准，而dhcpd对此很敏感。尝试获取并使用dhclient或dhcpxd，它们中的任何一个都会忽略微软的缺陷。

*我们的网络已扩展到超过250台主机，所以我们增加了另一个网络。我希望DHCP服务器也为该网络提供地址。我能这样做吗？*

可以。您需要查找shared-network参数，dhcpd.conf(5)手册页中有相关信息。请尝试以下命令获取更多信息：

```
man 5 dhcpd.conf
```

*我有一些较老型号的SUN SparcStation，它们不支持DHCP，只支持BOOTP。但是，我不想为它们分配静态地址。*

您需要查找在range语句中使用的dynamic-bootp选项。请查看上面提到的手册页，以了解其用法的更多信息。

*我正在运行一个由Windows 95系统和一台使用代理ARP的路由器组成的网络。Win95系统找不到路由器：*

在这种情况下，您需要使用use-lease-addr-for-default-route选项，这会强制Win95对所有IP地址进行ARP请求。这应该可以解决问题。

### 使用PPP进行拨号连接

到目前为止，连接到互联网的最常见方法是通过使用点对点协议（Point-to-Point Protocol，PPP）的拨号调制解调器连接。这在任何操作系统上都是如此；PPP是拨号连接的事实标准。在Linux上设置PPP比在其他一些操作系统上稍微复杂一些，但当你了解基础知识后，配置起来其实非常简单。此外，在配置文件级别理解PPP设置，能让你更深入地了解它的工作原理。连接建立后，实际上你就已经接入互联网了。所有依赖互联网连接的其他应用程序，如Web浏览器，随后即可运行。

> **警告：** 请注意，在建立互联网连接后，你不仅可以访问互联网上的任何内容，而且其他人也可以看到你的机器。请采取必要的预防措施来保护你的系统。

#### PPP入门

PPP（点对点协议）只是一种建立允许正常IP（网际协议）流量传输的网络连接的手段。它实际上支持许多不同的协议，但就本书而言，你只需在通过IP控制协议（IPCP）建立互联网连接的上下文中了解它。Linux中的PPP连接是使用点对点协议守护进程pppd建立的。它由以下三个组件组成：

- **数据链路层**——提供一种在串行链路上封装数据报（数据包）的方法。
- **LCP（链路控制协议）**——提供通过串行链路传输链路控制信息的方法。
- **NCP（网络控制协议）**——提供建立和配置不同网络层协议的方法。
