

然后强制使用该IRQ在支持该卡片的模块上。如果该卡片是一块NE2000网卡，使用`pcnet_cs.o`（在配置文件中查找与该卡片关联的模块名），在`config.opts`的底部添加一行，如下所示：

```
module "pcnet_cs" opts "irq_list=5"
```

当加载pcnet_cs模块时，这将强制使用空闲的IRQ。

（如果PCMCIA芯片组有问题，你也可以强制一个IRQ给它。不是在config.opts中传递IRQ列表，而是在/etc/sysconfig/pcmcia的PCIC_OPTS=行中传递它：

```
PCIC_OPTS="irq_list=11"
```

不需要在config.opts中“保留”一个IRQ，因为这一行会在config.opts被读取之前处理。）

*我一直在尝试使用modprobe插入一个模块，但出现了未解析的符号错误。我该如何纠正？*

一个模块依赖于另一个已加载的模块时，就会导致这个特定错误。

首先，确保你有一个当前的文件/lib/modules/`uname -r`/modules.dep。这个文件列出了文件依赖关系。你可以用以下命令创建它：

```
depmod -a
```

在确认你有一个依赖文件之后，使用modprobe来插入驱动程序。modprobe实用程序会加载任何先决条件的模块。这应该能消除你遇到的未解析符号错误。

### 入门

设置一个安全的广域网（WAN）就像设置任何其他广域网一样，但它为机密数据提供了更好的安全性。使用FreeS/WAN设置安全广域网与使用路由表设置广域网之间的唯一区别在于，你需要构建一个修改过的内核，然后配置软件。额外的工作会以更高的安全性得到回报。

FreeS/WAN（自由安全/广域网）软件包允许你在任意两个或多个局域网（LAN）之间（或任意两个系统之间，或一个系统与一个LAN之间）构建加密隧道，以创建安全的广域网。

> **注意**
>
> FreeS/WAN软件包正在快速发展。本文基于1.3版本，它包含了超出1.1版本的额外功能。如果你使用更高的修订版本（你可能需要针对你的内核），下面的说明可能与该版本不完全一致。请将它们作为指南，并查看提供的示例文件和文档。

要使用FreeS/WAN构建虚拟专用网络（VPN），你首先需要构建一个自定义内核并安装它。然后你需要学习如何配置FreeS/WAN以将VPN投入使用。本章后面将提到一些“陷阱”（gotchas）。

开始之前，你需要配置内核，然后运行make dep和make clean步骤。这些步骤将配置信息传播到整个内核树中，并且是FreeS/WAN软件包所必需的。

下载FreeS/WAN软件包（获取最新版本）并将其移动到/usr/src。打开以下软件包：

```
tar xzvf freeswan-1.1.3.tar.gz
```

然后cd进入此步骤中创建的freeswan目录。

### 构建FreeS/WAN内核

构建内核实际上相当简单。如果你已经配置过内核，那么当内核配置界面再次出现时，你不需要做任何更改。

你需要选择一个make命令来构建FreeS/WAN软件包。以下选项可用：

- `make menugo`
- `make xgo`
- `make ogo`
- `make oldgo`

每个选项分别调用`make menuconfig`、`make xconfig`、`make config`或`make oldconfig`。当运行其中一个命令时，FreeS/WAN软件包首先修补内核，然后在内核源代码目录中运行相应的make命令。

当内核编译开始时，它从你之前选择的make config开始。你需要选择“网络选项”并查看列表底部。在内核修补过程中会添加几个选项（大约10个）。这些选项将出现在QOS和/或公平排队选择的下面。在更改FreeS/WAN安装的默认配置之前要仔细考虑。当你对选择满意后，必须保存这个新的内核配置，否则它将不会编译FreeS/WAN补丁。

FreeS/WAN make会为你完成内核编译，从make dep开始，一直到make modules。但FreeS/WAN不会安装模块或内核。这些由你按照第18章“构建自定义内核”中的讨论来完成。

内核编译完成后，cd到../linux，回到第18章，并完成从make modules_install开始的所有步骤。当你重启进入新内核后，就可以开始配置你的VPN了。

### VPN规划

要正确配置FreeS/WAN，你必须稍微了解它的工作原理。FreeS/WAN通过将虚拟设备ipsec0-ipsec999绑定到真实设备（如eth0、tr0、ppp0或连接到系统的任何其他真实通信设备）来创建虚拟网络。系统路由表中会添加条目。从一个加密系统到另一个加密系统的路由将比一般的默认路由更具体，因此会选择ipsec设备来发送消息。通过ipsec设备发送的消息在传输时会被加密。

这个解释略过了一些东西。它略过的最重要的一点是哪些数据包（来自哪些源）将被加密。稍后在配置中，你将具体选择要发送到另一个系统时被加密的数据包的源。你将设置为向另一个接受加密消息的系统发送加密消息的系统，要么是一个网关，它将为其后面的LAN加密流量，要么是一个单独的系统，它将为自己传输加密消息。

网关和单独系统之间的区别很重要。网关与另一个网关或单独系统通信时，不会加密自己的流量，只加密来自其后面LAN的流量。网关使用*隧道模式*。单独系统将加密自己的流量，但如果该单独系统同时也充当网关，则不会加密来自其后面LAN的流量。单独系统处于*传输模式*。

一个充当网关的系统如果自身需要发送加密流量，则必须同时设置为一个加密网关和一个发送加密流量的独立站点。换句话说，你将从一个系统设置两条隧道。

在开始之前，你必须决定哪些系统或网络需要安全通信。如果你有两个互联网网关，分别称为California和New York，后面有各种主机，如表20.1所示，你需要决定哪些主机需要与哪些其他主机安全通信。

**表20.1 两个示例LAN上的主机**

| LAN站点1 | LAN站点2 |
| --- | --- |
| California: (192.168.1.1)<br>(互联网连接：123.123.123.1) | New York: (192.168.2.1)<br>(互联网连接：200.200.200.1) |
| Encino (192.168.1.2) | Albany (192.168.2.2) |
| SantaB (192.168.1.3) | Erie (192.168.2.3) |
| SanF (192.168.1.4) | NYC (192.168.2.4) |
| LAX (192.168.1.5) | Buffalo (192.168.2.5) |
| Bakersfield (192.168.1.6) | Rochester (192.168.2.6) |

如果你将California和New York设置为加密网关，那么从California到New York通信时，网关后面的所有流量都将被加密。因此，从SantaB到NYC的所有流量在离开California之前都会被加密，在离开New York之后才会解密。但是，例如Encino和LAX之间的流量不会被加密。同样，源自California并前往任何其他主机（包括New York或其后面的任何主机）的流量也不会被加密。

因此，California后面的任何主机都能读取与California后面任何其他主机发起或终止（或两者）的任何流量。New York后面的主机也是如此。而且，源自任一网关的流量都是不加密发送的。

如果SanF和Albany属于公司的总裁和副总裁，他们需要建立其他主机无法读取的私人通信，包括在他们自己的子网内，那么他们将需要单独的主机设置，也在SanF和Albany之间直接建立一条加密隧道。如果网关隧道处于活动状态，SanF和Albany之间的加密隧道将穿过它。在另一条加密隧道中再有一条加密隧道是没有问题的，只是两端可能会注意到由于双重加密而带来的轻微延迟（取决于加密/解密系统的速度）。同样的概念也适用于NYC需要与Albany安全通信的情况。这两者需要在彼此之间建立单独的隧道。

### VPN配置

ipsec配置文件由两个独立的文件组成。第一个是`/etc/ipsec.secrets`。在`ipsec.secrets`文件中，要么是预共享密钥（PSK），要么是RSA密钥（RSA）。本文只讨论预共享密钥。这个共享密钥在两个系统之间是相同的，并允许这两个系统通过这个共享密钥相互认证。只要共享密钥保持机密，这种方法就是安全的。

> **警告**
>
> `ipsec.secrets`中的共享密钥绝不能以明文形式传输。通过确保只有root可以读取该文件（chmod 600）来维护机密性，并且仅通过安全方式将密钥传输到其他系统（将`ipsec.secrets`文件放在软盘上并使用“运动鞋网络”——手动携带——或通过openssh或安全shell传输）。
