
## 使用FTP提供文件服务

与Linux中可用的许多服务一样，FTP服务器默认配置为可供使用。这意味着文件可以提供给任何有权访问系统的人。系统访问仅提供给预先设置好帐户的用户。有关用户帐户设置的更多详细信息，请参阅第11章“用户、组和权限”。

### FTP服务器概述

FTP服务器的主要用途是向远程用户提供文件。这些用户可能是组织内部的本地用户，也可能是互联网上某处的匿名用户。对FTP存档或通过FTP访问任何文件的访问都由用户帐户控制。对于预先配置了帐户的用户，默认允许通过FTP访问文件。您只需提供用户帐户和密码。用户以这种方式通过FTP服务器身份验证后，就可以访问他有权访问的系统上的任何文件。默认目录是用户的主目录，如/etc/passwd文件中指定的那样。随OpenLinux安装的标准软件包集中包括一个名为anonftp的软件包。该软件包包含设置匿名FTP服务器的所有组件。Red Hat也提供此软件包作为附加安装包。在Debian下，安装FTP服务器时会询问您是否要设置匿名FTP；没有为此目的单独存在的软件包。

### 匿名FTP

匿名FTP可以说是FTP服务最常见的用途。全球各地存在无数的FTP存档。每个站点都允许未知用户连接到服务器并下载他们选择的文件。大多数软件公司通过FTP提供演示程序。一些FTP站点甚至提供将文件放置到FTP服务器系统上的功能。例如，Caldera FTP站点有一个incoming目录，许多程序员在那里贡献软件包供他人使用和受益。

如果在您的FTP服务器上设置了incoming目录，好的做法是将其配置为保护系统免受恶意行为的影响。例如，强烈建议incoming目录驻留在自己独立的分区上。这样，如果incoming目录满了——无论是因为意外还是恶意——都不会影响系统的其余部分。此外，将incoming目录设置为只写（对world无读权限）使您能够监视放置在那里的内容。在确定文件没有问题，即没有冒犯或不适当的文件后，可以将它们移动到所有匿名用户都可以访问的位置。大多数FTP站点将其称为FTP站点的contrib区域。

匿名FTP RPM包含以下文件：

- /home/ftp
- /home/ftp/bin
- /home/ftp/bin/gzip
- /home/ftp/bin/ls
- /home/ftp/bin/tar
- /home/ftp/bin/zcat
- /home/ftp/etc
- /home/ftp/etc/group
- /home/ftp/etc/passwd
- /home/ftp/pub
- /usr/doc/anonftp-3.1
- /usr/doc/anonftp-3.1/README

安装此软件包会设置提供匿名FTP服务所需的一切。正如本章前面提到的，要连接到FTP服务器，您必须拥有一个用户帐户。即使使用匿名FTP服务，也需要一个用户帐户。然而，并非为此目的创建新用户帐户，而是在/etc/passwd文件中已经创建了一个。当然，它被恰当地命名为ftp。它实际上是一种特殊类型的用户帐户，与/etc/passwd文件中的典型用户帐户不同。/etc/passwd文件中ftp帐户的条目如下：

```text
ftp:x:14:50:FTP User:/home/ftp:
```

正是/etc/passwd文件中的用户帐户条目允许匿名用户连接到FTP服务器。尽管用户帐户条目是ftp，但连接到FTP服务器时接受用户ID anonymous。事实上，许多人错误地认为anonymous是唯一可用的用户ID。

### 控制访问

可以通过以下四种方式之一控制对FTP服务器的访问：

- 删除或注释掉/etc/passwd文件中的FTP用户
- 将要排除的用户添加到/etc/ftpusers文件中
- 从/etc/ftpaccess文件中删除用户类别
- 通过ftpshut关闭FTP服务器

/etc/ftpaccess文件用于配置对FTP服务器的访问。初始安装时，该文件的内容如下：

```text
class       all    real,guest,anonymous  *

email root@localhost

loginfails 5

readme  README*  login
readme  README*  cwd=*

message /welcome.msg          login
message .message              cwd=*

compress       yes             all
tar             yes             all
chmod           no              guest,anonymous
delete          no              guest,anonymous
overwrite       no              guest,anonymous
rename          no              guest,anonymous

log transfers anonymous,real inbound,outbound
shutdown /etc/shutmsg
passwd-check rfc822 warn
```

此文件中定义的每个条目都在ftpaccess的手册页中详细描述。/etc/ftpaccess文件中的条目不仅控制谁能访问FTP服务器，还控制他们在建立连接后能做什么。

> **提示**  
> 要禁止系统上所有真实帐户访问FTP服务器，请删除/etc/ftpaccess文件class行中的real条目。

/etc/ftpusers文件用于控制哪些用户无权访问FTP服务器。默认情况下，/etc/ftpusers文件中放置了以下条目：

- root
- bin
- daemon
- adm
- lp
- sync
- shutdown
- halt
- mail
- news
- uucp
- operator
- games
- nobody

如果用户名包含在/etc/ftpusers文件中，则该用户无法访问FTP服务器。如果尝试使用此文件中包含的某个用户名连接到FTP服务器，将返回以下消息：

```text
# ftp ftp.kcpartners.com
Connected to ftp.kcpartners.com.
220 router.kcpartners.com FTP server (Version wu-2.4.2-academ[BETA-17](1)
Wed Aug 19 02:55:52 MST 1998) ready.
Name (kcpartners.com:col): ftp
530 User ftp access denied.
Login failed.
Remote system type is UNIX.
Using binary mode to transfer files.
ftp>
```

### 关闭FTP服务器

ftpshut命令可用于在指定时间中止FTP服务。它提供了一种通知用户FTP服务器暂时关闭、可以稍后重试的方法。ftpshut命令在/etc目录中创建一个名为shutmsg的文件。当尝试连接到FTP服务器时，FTP服务器会检查该文件是否存在。如果找到该文件，将显示以下消息：

```text
# ftp router
Connected to router.kcpartners.com.
500 router.kcpartners.com FTP server shut down -- please try again later.
ftp>
```

> **注意：** 发出`ftpshut`命令后，必须删除`/etc/shutmsg`文件才能重新建立FTP服务。

### 文件放置

由于FTP服务器默认启用匿名用户访问，因此放置文件以供FTP访问是一个简单的步骤。匿名FTP访问的默认目录结构经过配置，只需将文件放在/home/ftp/pub目录中即可。请注意，/home/ftp目录中的另外两个目录/home/ftp/bin和/home/ftp/etc在通过FTP连接时不可访问。将所有可公开访问的文件放在/home/ftp/pub目录下，或放在/home/ftp/pub内的子目录树结构中。

> **注意：** 请记得将FTP服务器上的所有文件权限设置为只读。`/home/ftp/pub`的目录权限默认就是这样设置的。

### 故障排除

*我尝试以root身份连接到ftp，但一直收到530 Login incorrect。Login Failed。我知道我使用了正确的密码。*

默认情况下，root被拒绝ftp访问。这是在PAM中配置的。大多数Linux发行版安装的`/etc/pam.d/ftp`文件包含一个auth行，列出`pam_listfile.so`并指向`/etc/ftpusers`。sense=deny意味着文件中列出的任何用户都会被拒绝ftp访问。root用户以及所有系统帐户都列在`/etc/ftpusers`文件中。您有两个选择：注释掉`/etc/pam.d/ftp`中的auth行，或注释掉`/etc/ftpusers`中的用户root（只需在该行开头放一个#）。然而，从安全角度来看，启用root对FTP的访问是一个非常糟糕的主意。如果这样做，您将严重削弱系统的安全性。即使在今天，对于仅偶尔使用调制解调器连接的系统，这也是一个值得关注的问题。

*我想关闭FTP服务器，但只是暂时关闭，而不是永久关闭。我该怎么做？*

使用`ftpshut`命令。此命令将写入一个默认路径为`/etc/shutmsg`的文件。（您可以在`/etc/ftpaccess`中更改此路径，shutdown变量指定了该文件。）当您准备再次允许访问时，只需删除`/etc/shutmsg`文件。在FTP关闭期间，任何尝试连接的用户都会在屏幕上看到shutmsg的内容。
