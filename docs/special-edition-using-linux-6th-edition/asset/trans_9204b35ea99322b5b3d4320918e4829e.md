
您还可以使用mknod创建无缓冲字符设备和管道。前面列出的devices.txt文件会告诉您在使用mknod时，何时需要用u代替c。用p创建的命名管道通常由程序创建（并且不占用主设备号和次设备号），但您可以创建一个并在脚本中使用。然而，这超出了本文的讨论范围。

## /devfs 目录

现在，您已经了解了/dev中的所有历史设备，当您查看该目录时，可能会看到完全不同的内容（也可能不是）。假设Caldera OpenLinux使用/devfs，它可能使用旧名称来实现。它也可能选择使用内核名称，甚至更新的（并且不断变化的）devfs名称。

当您开始理解/dev命名方案时，您会发现设备叫什么名字并不重要，因为内核是通过主设备号和次设备号来识别它们的。当您得知某个特定设备的名称后，可以让程序引用并使用它。如果您在自己的主目录中创建了一个名为foo1的块设备，主设备号为3，次设备号为1，然后查看它（您可以使用命令：less -f foo1来查看它），您将看到您的IDE 0（C:驱动器）硬盘的第一个分区。这就是为什么普通用户不能创建设备文件的原因——否则会使您可能拥有的任何权限失效。

每个带编号的目录都对应一个实际的进程ID。查看进程表，您可以将进程与关联的进程ID匹配。例如，对于Web服务器，进程表可能显示以下内容：

```text
# ps ax | grep httpd
460     ?   S     0:00 httpd -f /etc/httpd/apache/conf/httpd.conf
```

/proc目录中的文件与进程ID子目录文件的行为非常相似。例如，检查/proc/interrupts文件的内容会显示类似以下内容：

```text
# cat interrupts
 0:   27222899   timer
 1:       3152   keyboard
 2:          0   cascade
 9:     450448   eth0
12:       4477   PS/2 Mouse
13:          1   math error
14:      15198 + ide0
15:          0 + ide1
```

左侧的每个数字代表一个正在使用的中断。检查文件内容会动态收集相关数据并显示到屏幕上。/proc文件系统大部分是只读的；但是，有些文件允许更改内核变量。这提供了一种无需重新编译和重新启动即可实际调整内核的机制。
