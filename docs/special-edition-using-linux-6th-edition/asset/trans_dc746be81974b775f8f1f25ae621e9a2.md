

运行级别5意味着在几乎所有发行版中，XFree86都会自动启动。这是因为你的`/etc/inittab`中有类似如下的条目：

```
x:5:respawn:/etc/X11/prefdm --nodaemon
```

respawn标志告诉init，如果该程序终止，就重新启动它。因此当XFree86启动时，它会读取其配置文件，如果因错误而终止，init会立即重新启动它。因为XFree86在启动时会切换显示器的视频模式，所以在此过程中你将无法在控制台输入任何命令。

你可以通过重新启动进入单用户模式来重新获得对机器的控制。按Ctrl+Alt+Delete重新启动机器。在`boot:`提示符下，输入`linux -s`并回车。系统将进入单用户模式，并以root身份登录。输入以下命令切换到运行级别3：

```
# telinit 3
```

这将使系统在不启动XFree86的情况下进入多用户模式，这样你就可以处理配置文件了。为了测试配置文件，运行`startx`。这会显示错误所在之处，以便你进行修复。

> **提示**
>
> 如果你的问题机器位于网络上，可以避免重新启动。只需转到另一台机器，以普通用户身份telnet登录（不能用root登录）。然后su到root（输入su，回车，再输入root密码）。最后输入`telinit 3`，你的机器就会恢复正常。

### XFree86显示的分辨率错误。

XF86Config中可能列出了你并不想要的视频模式。

你需要编辑XF86Config文件。在此之前，你需要切换到运行级别3。如果你不这样做，并且在此文件中犯了任何错误，将很难重新获得对机器的控制。要切换到运行级别3，请成为root用户，并在命令提示符下输入`telinit 3`。

现在编辑`/etc/X11/XF86Config`（或`/etc/XF86Config`），查找Screen节。它们看起来像这样：

```
Section "Screen"
    Identifier  "Screen0"
    Device      "Card0"
    Monitor     "Generic Monitor"
    DefaultDepth 8
    SubSection "Display"
        Depth       24
        Modes       "320x200" "800x600"
        Virtual 0 0
    EndSubSection
EndSection
```

可能有好几个Screen节。请确保你使用的是对应你设备的那一个。

注意Modes行中的320x200。XFree86将从Modes行中找到的第一个分辨率开始启动。除非你确实需要测试它（它通常比看起来更没有用），否则这里只列一种模式即可。运行startx，确保它正常工作。然后在命令提示符下用`telinit 5`切换回运行级别5。

### Linux启动时XFree86没有启动。

你处于运行级别3而不是运行级别5。编辑你的/etc/inittab，将id行改为：

```
id:5:initdefault:
```

重新启动机器后，XFree86将自动启动。

这个桌面之所以值得注意，是因为它实际上非常复杂。X Window System隐藏了如此多的复杂性，以至于你很容易认为这是理所当然的。以下是一些值得考虑的事实：

- Mutt（邮件程序）正在通过ISDN线路在远程Solaris机器上运行。所有文本数据在两台机器之间传输时都经过加密和压缩（这是通过一个名为ssh的程序完成的）。但xterm的图形部分实际上运行在本地的Linux机器上，所以ISDN线路只需要处理文本。
- Emacs（编辑器）也在本地Linux机器上运行。但正在编辑的文件实际上位于运行Mutt的同一台远程机器上。
- Meeting Maker（日历程序）完全在远程Solaris机器上运行，将其所有图形信息发送回我的Linux机器（同样经过压缩和加密）。这使我即使Meeting Maker没有移植到Linux，也能运行它。
- 底部的按钮会自动启动这些远程应用程序。设置完成之后，我通常可以忽略哪台机器在运行哪个应用程序。它们都显示在同一台机器上，我可以把它们一视同仁。
- 从屏幕截图中看不出来的是，我实际上坐在一台运行Reflection X的Windows 98机器前。Linux机器和Windows 98机器通过快速本地网络连接。Linux机器将我的桌面显示在Windows机器上。我仍然享有Linux的所有优势，但无需离开座位即可运行Windows应用程序。除此之外，另一个用户（我妻子）可以登录Linux控制台，在那里使用Netscape，而我则在阅读邮件、运行我自己的Netscape副本等等。这一切都是透明的。

我使用过许多不同的操作系统和图形用户界面，但至今还没有找到一个能提供X Window System这样令人难以置信的灵活性和强大功能的系统。

### 浏览X Window System

X Window System向用户呈现多个窗口，每个窗口显示一个称为*客户端*的X应用程序的输出。客户端可以运行在用户的PC上（在Linux下很可能是这样），也可以运行在网络上的另一台工作站上。

你在X Window System中的操作方式很大程度上取决于你的窗口管理器。大多数窗口管理器使用一个称为*光标*的屏幕指针来指示你正在工作的位置。根据你正在做什么以及运行的是哪个窗口管理器，光标可以呈多种形状。

与大多数图形用户界面（GUI）一样，X Window System允许来自键盘和指向设备（通常是鼠标）的输入。通常，要让一个窗口接受输入，它必须是活动窗口。活动窗口通常具有与非活动窗口不同的外观（例如，高亮的边框）。当一个窗口被选中时，它就被称为获得了*焦点*。

本章的大部分内容将重点介绍fvwm2、Blackbox和Enlightenment等窗口管理器。GNOME、KDE和XFCE等桌面环境的做法往往大不相同。KDE和GNOME将在第3章“KDE”和第4章“GNOME”中详细介绍。

#### 获得焦点

使窗口变为活动窗口取决于你如何配置窗口管理器。某些配置允许你只需将光标移入窗口即可使其成为活动窗口；其他配置则要求你用鼠标单击窗口，就像在Microsoft Windows中那样。表6.1列出了最常见的焦点方案（特定的窗口管理器可能对这些方案有不同的名称）。

**表6.1 常见的焦点方案**

| 名称 | 描述 |
|---|---|
| 点击 | 你必须点击一个窗口，它才能获得焦点。Microsoft Windows使用这种焦点方案。 |
| 鼠标 | 指针当前所在的任何窗口都具有焦点。如果指针不在任何窗口中，则没有窗口具有焦点。 |
| 松弛 | 这种方案与鼠标非常相似，区别在于窗口不会放弃焦点，直到指针移动到新窗口中。使用这种方案通常比使用鼠标焦点方便得多。 |

如果你只熟悉只允许点击焦点的GUI，那么鼠标和松弛焦点可能需要一些时间适应。然而，一旦你习惯了它们，这些焦点类型可以让你完成一些点击焦点无法做到的事情。例如，如果你正在阅读一个窗口，同时在另一个窗口中输入，你可以让正在阅读的窗口显示在最前面，即使它部分遮住了活动窗口，而你正在输入的窗口仍然保持焦点。
