
## Chapter 3: System Configuration and Management

### Understanding Debian's Configuration Files

Debian, like other Linux distributions, relies heavily on configuration files to control various aspects of the system. These files are typically stored in plain text format, making them easy to read and edit. Understanding the purpose and location of these files is crucial for effective system administration.

### Important Configuration Directories

- `/etc`: This is the primary directory for system-wide configuration files.
- `/etc/default`: Contains default values for various services and applications.
- `/etc/skel`: Holds template files for new user accounts.
- `/etc/apt`: Stores configuration files for the APT package management system.
- `/etc/network`: Contains network configuration files.

### Key Configuration Files

- `/etc/fstab`: File System Table, defines how disk partitions and other block devices are mounted into the file system.
- `/etc/passwd`: Stores essential information for each user account.
- `/etc/shadow`: Contains encrypted passwords for user accounts.
- `/etc/group`: Defines user groups and their members.
- `/etc/hostname`: Specifies the system's hostname.
- `/etc/hosts`: Maps hostnames to IP addresses.
- `/etc/resolv.conf`: DNS resolver configuration file.
- `/etc/sudoers`: Configures sudo access and permissions.

### Configuration File Syntax

Most configuration files in Debian follow a simple syntax:

- Lines beginning with # are comments and are ignored by the system.
- Configuration options are typically specified in key=value or key value format.
- Some files use more complex formats, such as XML or INI-style configurations.

### Best Practices for Editing Configuration Files

- Always make a backup of the original file before making changes.
- Use appropriate text editors (e.g., nano, vim) that respect file permissions and formatting.
- Check file syntax and permissions after making changes.
- Restart relevant services or the entire system when required after configuration changes.

### Configuration Management Tools

For more complex systems or when managing multiple machines, consider using configuration management tools such as:

- Ansible
- Puppet
- Chef
- Salt

These tools can help automate the process of configuring and maintaining multiple systems consistently.

## User and Group Management

Effective user and group management is crucial for maintaining system security and organizing access to resources. Debian provides several tools and mechanisms for managing users and groups.

### User Accounts

A user account in Debian consists of:

- Username: A unique identifier for the user.
- User ID (UID): A numeric identifier assigned to each user.
- Primary Group ID (GID): The main group to which the user belongs.
- Home Directory: The user's personal directory, typically /home/username.
- Login Shell: The command interpreter assigned to the user.

### Group Accounts

Groups are used to organize users and manage permissions collectively. Each group has:

- Group Name: A unique identifier for the group.
- Group ID (GID): A numeric identifier assigned to each group.
- Member List: Users who belong to the group.

### Important User and Group Files

- `/etc/passwd`: Contains user account information.
- `/etc/shadow`: Stores encrypted user passwords.
- `/etc/group`: Defines groups and their members.
- `/etc/gshadow`: Contains encrypted group passwords (rarely used).

### Adding, Removing, and Modifying Users

#### Adding Users

To add a new user, use the `adduser` command:

```bash
sudo adduser username
```

This command will:

- Create a new user account
- Set up a home directory
- Copy default configuration files from `/etc/skel`
- Prompt for a password and additional user information

For more control, you can use the `useradd` command:

```bash
sudo useradd -m -s /bin/bash username
```

This creates a user with a home directory (-m) and sets the login shell to bash (-s).

#### Removing Users

To remove a user account, use the `deluser` command:

```bash
sudo deluser username
```

To remove the user's home directory and mail spool as well, add the `--remove-home` option:

```bash
sudo deluser --remove-home username
```

#### Modifying Users

To modify existing user accounts, use the `usermod` command. Some common operations include:

- Changing the user's home directory:

```bash
sudo usermod -d /new/home/dir username
```

- Changing the user's login shell:

```bash
sudo usermod -s /bin/new_shell username
```

- Adding a user to a group:

```bash
sudo usermod -aG groupname username
```

- Changing the user's UID:

```bash
sudo usermod -u new_uid username
```

#### Managing User Passwords

To change a user's password, use the `passwd` command:

```bash
sudo passwd username
```

To lock or unlock a user account:

```bash
# Lock
sudo passwd -l username

# Unlock
sudo passwd -u username
```

### User Permissions and Groups

Debian, like other Unix-like systems, uses a permission system based on users and groups to control access to files and directories.

#### File Permissions

Each file and directory has three sets of permissions:

- Owner permissions
- Group permissions
- Others permissions

Each set can have read (r), write (w), and execute (x) permissions.

To view permissions, use the `ls -l` command:

```bash
-rw-r--r-- 1 user group 1234 Jan 1 12:00 file.txt
```

In this example:

- The owner (user) has read and write permissions
- The group has read permission
- Others have read permission

#### Changing Permissions

Use the `chmod` command to change permissions:

```bash
chmod permissions file
```

Permissions can be specified using either symbolic or numeric notation:

- Symbolic notation:

```bash
chmod u+x file    # Add execute permission for the owner
chmod g-w file    # Remove write permission for the group
chmod o=r file    # Set read-only permission for others
```

- Numeric notation:

```bash
chmod 644 file    # Set rw-r--r-- permissions
chmod 755 file    # Set rwxr-xr-x permissions
```

#### Changing Ownership

Use the `chown` command to change file ownership:

```bash
chown user:group file
```

To change ownership recursively for directories:

```bash
chown -R user:group directory
```

#### Special Permissions

- SetUID (SUID): When set on an executable file, it runs with the permissions of the file owner.
- SetGID (SGID): When set on an executable file, it runs with the permissions of the file group. When set on a directory, new files created within it inherit the directory's group.
- Sticky Bit: When set on a directory, only the owner of a file can delete or rename it within that directory.

To set these special permissions:

```bash
chmod u+s file  # Set SUID
chmod g+s file  # Set SGID
chmod +t directory  # Set Sticky Bit
```

#### Access Control Lists (ACLs)

For more fine-grained control over permissions, Debian supports Access Control Lists. To use ACLs, ensure the `acl` package is installed:

```bash
sudo apt install acl
```

To set an ACL:

```bash
setfacl -m u:username:rwX file
```

To view ACLs:

```bash
getfacl file
```

## Managing Disk Partitions and File Systems

Effective disk management is crucial for optimal system performance and data organization. Debian provides various tools for managing disk partitions and file systems.

### Disk Partitioning

Partitioning involves dividing a physical disk into logical sections. Common reasons for partitioning include:

- Separating system and user data
- Using different file systems for different purposes
- Creating swap space
- Dual-booting multiple operating systems

#### Partitioning Tools

- `fdisk`: A text-based partitioning tool for MBR (Master Boot Record) partitions.
- `gdisk`: Similar to `fdisk`, but for GPT (GUID Partition Table) partitions.
- `parted`: A more advanced command-line tool that supports both MBR and GPT.
- `gparted`: A graphical partitioning tool (requires X11 or Wayland).

### Example: Creating a New Partition with fdisk

```bash
sudo fdisk /dev/sdb

# Commands:
# n - create new partition
# p - print partition table
# w - write changes and exit
```
