
- **解析器**。客户端程序生成 DNS 信息请求并将其发送至名称服务器以便满足这些请求。解析器可以直接访问至少一个名称服务器，并且还可以处理引荐，以便在必要时将其查询引导至其他名称服务器。

在其最基本的形式中，DNS 名称解析过程包括解析器向指定的 DNS 服务器提交名称解析请求。如果该服务器没有持有有关所请求名称的权威信息，则如果已这样配置，它可以将该请求转发到网络上的另一台 DNS 服务器。网络管理员可以选择其 DNS 服务器是否参与转发请求。第二台服务器生成包含所请求名称的 IP 地址的响应，并将其返回给第一台服务器。第一台服务器将信息中继给解析器。然而在实践中，DNS 名称解析过程可能会复杂得多。

为了使 DNS 能够正常工作，必须通过将其在多台服务器之间分布的方式来划分命名空间。此外，服务器必须能够找到特定名称的权威来源。为了实现这些目标，DNS 的开发者创建了*DNS 域*的概念。域是一个管理实体，由一组主机组成，通常是计算机、路由器、打印机和其他支持 TCP/IP 的设备的组合。DNS 命名空间由域层次结构组成，每个域都有负责提供该域内主机信息的 DNS 名称服务器，如图 12-1 所示。特定域的指定名称服务器是该域信息的权威来源。当 DNS 服务器是某个域的权威来源时，它拥有该域内主机的信息，并以资源记录的形式存储这些信息。

**警告** 在 DNS 上下文中，术语*域*的含义与它在 Active Directory 中的含义不同。在 Active Directory 中，Windows Server 2008 域是作为单一单元进行管理的 Windows 计算机和设备的分组。在 DNS 中，域是一组主机（可能还包括子域），代表 DNS 命名空间的一部分。

要完全理解 DNS，您应该了解以下配置项：

- **资源记录**。资源记录是所有 DNS 服务器中的基本数据存储单元。当 DNS 客户端和服务器交换名称和地址信息时，它们以资源记录的形式进行交换。最基本且通用的资源记录是主机 (A) 资源记录，它由主机名及其 IP 地址组成。然而，DNS 服务器还可以存储其他类型的资源记录，其中一些将在以下章节中描述。该记录是代表网络上支持 TCP/IP 的物理设备的逻辑条目。

- **授权起点 (SOA)**。SOA 资源记录标识哪台名称服务器是该域内数据的权威信息源。此记录表明特定服务器负责域内其他条目的相关 A 记录；它还负责对这些条目的任何更改或更新。区域数据库文件中的第一条记录必须是 SOA 记录。在 Windows Server 2008 DNS 服务器中，创建新区域时会自动使用默认值创建 SOA 记录。稍后，您可以根据需要修改各个字段值。与大多数资源记录不同，SOA 记录包含各种字段，其中大多数用于名称服务器维护操作。表 12-1 使用在 Windows Server 2008 DNS 控制台界面中指定的名称以及 DNS 标准中指定的字段名称（在括号中）列出了这些字段。

- **名称服务器 (NS)**。NS 资源记录标识特定区域或域的权威名称服务器；即能够为区域或域提供权威的从名称到 IP 地址映射的服务器。此资源记录由包含 DNS 名称服务器名称的单个字段组成。Microsoft DNS 服务器默认在每个新区域中创建 NS 资源记录。当您创建子域并将它们委托给不同的区域时，NS 记录使名称服务器能够将查询引荐给子域的权威名称服务器。

- **主机 (A)**。A 资源记录是 DNS 的基本数据单元。此资源记录具有单个 Address（地址）字段，其中包含与 Name（名称）字段中标识的系统关联的 IP 地址。主机资源记录提供 DNS 名称服务器用于执行名称解析的从名称到 IP 地址的映射。

- **主机 (AAAA)**。AAAA 记录是互联网协议版本 6 (IPv6) 主机的资源记录；AAAA 记录是 IPv4 中 A 记录的 IPv6 等效项。

> 您在第 2 课中已了解 A 记录。

- **规范名称 (CNAME)**。CNAME 资源记录，有时也称为别名记录，用于为 Name 字段中指定的系统指定*别名*或替代名称。资源记录包含单个 CName 字段，其中持有标准 DNS 命名格式下的另一个名称。您创建 CNAME 资源记录是为了使用多个名称指向单个 IP 地址。例如，您可以通过在 adatum.com 域中为主机名 www 创建 A 记录，并创建将主机名 ftp 等同于 www 的 A 记录的 CNAME 记录，在同一台计算机上托管文件传输协议 (FTP) 服务器（如 ftp.adatum.com）和 Web 服务器（如 www.adatum.com）。

- **主机信息 (HINFO)**。HINFO 资源记录包含两个字段，CPU 和 OS，其中包含标识所列主机使用的处理器类型和操作系统的值。您可以将此记录类型用作低成本的资源跟踪工具。

- **邮件交换器 (MX)**。DNS 的另一项关键功能是将电子邮件消息定向到适当的邮件服务器。尽管 DNS 标准定义了各种过时的和实验性的专用于电子邮件功能的资源记录，但用于电子邮件传输的通用资源记录是 MX 记录。此资源记录包含两个字段：*Preference*（优先级）和*Exchange*（交换器）。Preference 字段包含一个整数值，指示与此域中同类型和同类的其他资源记录相比，此资源记录的相对优先级。值越低，优先级越高。Exchange 字段包含能够充当 Name 字段中指定的域的电子邮件服务器的计算机名称。

- **指针 (PTR)**。PTR 资源记录是 A 记录的功能相反，使用 in-addr.arpa 域名提供 Name 字段中标识的系统的 IP 地址到名称映射。PTR 资源记录包含单个字段，其中包含 Name 字段中 IP 地址标识的系统的 FQDN。当您在 DNS 服务器上创建适当的反向查找区域时，您可以自动使用 A 记录创建 PTR 资源记录。

- **服务记录 (SRV)**。服务资源 (SRV) 记录使客户端能够找到提供特定服务的服务器。Windows Server 2008 Active Directory 客户端依赖 SRV 记录来找到验证登录请求所需的域控制器。

## 理解域层次级别

> DNS 域命名空间的层次结构性质使得互联网上的任何 DNS 服务器都能使用最少数量的查询找到任何域名的权威来源。这种效率是可能的，因为每个层级的域负责维护下一级域的信息。

DNS 域层次结构的每个层级都有负责该层级中各个域的名称服务器。在域层次结构的顶端是*根名称服务器*，它们是整个命名空间中最高层级的 DNS 服务器。它们维护有关顶级域的信息。单一实体并不负责所有根服务器；与互联网的其他部分一样，根名称服务器的管理分散在一百多个地点。所有 DNS 名称服务器实现都预配置了根名称服务器的 IP 地址，因为这些服务器是所有 DNS 信息的最终来源。当计算机尝试解析 DNS 名称时，它从命名空间层次结构的顶端开始，即根名称服务器，并逐层向下直到到达名称所在域的权威服务器。
