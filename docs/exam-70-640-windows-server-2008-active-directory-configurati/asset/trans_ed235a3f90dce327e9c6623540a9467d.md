# 执行安装后任务

> 在 Active Directory 安装完成后，您应在认为其完成之前验证若干项目。以下部分讨论了创建性能良好且具有一定容错能力的 Active Directory 基础设施所需的基本项目。

第一个安装后任务涉及 DNS 服务器服务。虽然您在 Active Directory 安装过程中安装了 DNS，但在认为安装完成并可运行之前，您应验证若干项目：

- 创建应用程序目录分区
- 区域的寿命管理和清理（Scavenging）
- 正向查找区域和 SRV 记录
- 反向查找区域

## 创建目录分区

首先，验证 DNS 应用程序目录分区是否已成功创建。应用程序目录分区用于将林范围的 DNS 信息与域范围的 DNS 信息分开，以控制不同类型 DNS 数据的复制范围。虽然 DNS 会自动为每组 DNS 数据设置范围，但可以根据需要使用随 Windows Server 2008 安装的 DNS 管理工具独立配置和添加范围。存储在应用程序分区中的信息可配置为复制到林中的任何域控制器，即使所选的域控制器不在同一个域中也是如此。就 DNS 而言，应用程序目录分区允许您控制哪些 DNS 数据是在单个域内还是在整个林中复制。

Active Directory 安装向导的一部分会安装两个位于 DNS 应用程序目录分区内的区域。以 lucernepublishing.com 为参考，表 2-1 描述您刚刚安装的区域类型和默认区域名称。

**表 2-1**
lucernepublishing.com 的默认 Active Directory 应用程序分区

| 区域类型 | 区域名称 | 目的 |
| :--- | :--- | :--- |
| DomainDnsZones | DomainDnsZone.lucernepublishing.com | 单个分区，允许 DNS 信息复制到域内所有运行 DNS 的域控制器。 |
| ForestDnsZones | ForestDnsZones.lucernepublishing.com | 包含林中所有 DNS 服务器的单个分区。存储在此处的区域会复制到整个林中所有运行在域控制器上的 DNS 服务器。 |

理解应用程序目录分区的关键点如下：

- 安装 Active Directory 集成 DNS 时会自动创建应用程序目录分区。
- 您必须是企业管理员组的成员才能创建或修改应用程序目录分区。
- 如果在 Active Directory 安装向导期间未能创建应用程序目录分区，您稍后可以手动创建；如果该分区已存在，则不会提供创建应用程序目录分区的选项。

# 配置寿命管理和清理

与 DNS 相关的下一个任务是在您的 DNS 服务器上设置 DNS 记录的寿命管理和清理。虽然默认情况下未启用，但寿命管理和清理是 Windows Server 2008 DNS 可用于在 DNS 记录变得“陈旧”或过时时清理 DNS 数据库的过程。如果没有此过程，DNS 数据库将需要手动维护，以防止服务器性能下降和潜在的磁盘空间问题。

### 验证正向查找区域的创建

接下来，您将验证在 Active Directory 安装向导过程中是否创建了适当的 DNS 记录。**正向查找区域**对于计算机主机名到 IP 地址的映射是必需的，这些映射被各种服务用于名称解析。例如，当用户请求基于其主机名访问服务器时，请求会传递给 DNS 服务器以将主机名解析为 IP 地址。大多数查询基于正向查找。

## 验证正向查找区域的创建

**准备就绪。** 在 Active Directory 安装后，请在您的域控制器指向用于名称解析的 DNS 服务器上执行以下步骤。

- 1. 从**管理工具**文件夹中打开**DNS**。
- 2. 在**DNS**下，展开您的服务器。
- 3. 展开**正向查找区域**标题。您应该能看到当前配置的正向查找区域。
  - .msdcs.lucernepublishing.com
  - lucernepublishing.com

**暂停。** 正向查找区域已创建。

Windows 2000、Windows Server 2003 和 Windows Server 2008 中的 Active Directory 需要支持**SRV 记录**。SRV 记录由 DNS 使用，用于提供服务到提供这些服务的计算机的映射。例如，当在服务器上安装 Active Directory 时，该服务器也成为域控制器和 Netlogon 服务器。尝试向 Active Directory 网络进行身份验证的客户端需要定位 Netlogon 服务器。如果名为 **Server2** 的服务器在 lucernepublishing.com 域中配置为域控制器，它会在启动时动态将自己注册到 DNS。此注册包括服务器名称的**A 记录**以及服务器上运行的服务的任何适当 SRV 记录。**A 记录**是将单个 IP 地址映射到 DNS 主机名的 DNS 构建块。例如，A 记录可能将 IP 地址 192.168.1.142 映射到主机名 **server1.lucernepublishing.com**。为服务器配置提供的每项服务注册一个 SRV 记录。尝试向网络进行身份验证的客户端将使用 DNS 帮助他们根据请求的服务找到适当的域控制器。SRV 记录默认可以在 DNS 的正向查找区域中找到。
