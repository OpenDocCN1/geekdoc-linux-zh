
# 进程终止

- 进程通过特殊信号通知其祖先进程和后代进程已经结束。
- 在 `fork()` 调用期间分配的资源会被释放。
- 调度器会被通知可以切换上下文了。

在应用程序中，你可以使用 `_exit()` 系统调用或其库函数 `exit()` 来完成进程。该函数关闭所有进程线程，正确释放所有资源，并调用 `_exit()` 以实际完成操作：

```c
#include <unistd.h>
void _exit(int status); // status 指定返回码

#include <stdlib.h>
void exit(int status); // status 指定返回码

exit(128);
```

请注意，当一个进程能够与其他进程联合使用资源时（例如，它是一个拥有祖先进程的后代进程，并且后代从祖先继承了资源描述符），最好不要调用 `exit()`。原因是，在这种情况下，尝试在子进程中释放资源也会导致祖先进程中的资源被释放。你必须使用 `_exit()` 来完成这些进程。

## 等待进程完成

当进程完成时，其控制块不会立即从进程列表和哈希表中移除，而是保留在那里，直到另一个进程（祖先）将其移除。如果进程实际上已不在系统中（已经结束），但仅保留其控制单元，则该进程被称为僵尸进程。

## waitpid() 系统调用

你可以使用 `wait()` 系统调用来从 Linux 中移除进程信息，但更常使用的是其功能更通用的版本——`waitpid()`。此调用检查相应进程的控制单元是否在系统中。如果在，且进程不处于僵尸状态（即仍在运行），则 `waitpid()` 处的进程将进入待机状态。当下进进程完成时，祖先进程退出待机状态并移除该后代进程的控制单元。如果祖先进程不为后代调用 `waitpid()`，后者可能会长时间停留在僵尸状态。

### 应用程序中进程的同步实现

让我们基于 `waitpid()` 来考虑进程的同步执行。根据 POSIX，该系统调用定义为：

```c
#include <sys/wait.h>

pid_t waitpid(pid_t pid,        // 预期进程的 pid
               int *status,      // 后代完成状态信息
               int options);     // 通常为 0
```

`pid` 参数可以设置为 `0`，这意味着进程正在等待与其所属组相同的组，或者设置为 `-1`，这意味着等待任意后代。以下是使用预期机制实现同步执行的示例：

```c
pid_t pid;
if ((pid = fork()) == -1)
    exit(-1);
if (pid == 0)
{
    // 后代 - 调用 exec()
}
else
{
    // 祖先 - 等待后代
    int status;
    waitpid(pid, &status, 0);
    // 继续执行
}
```

`status` 值为你提供了更多关于已完成后代进程的信息。`<sys/wait.h>` 中有许多宏：

- `WIFEXITED(status)` - 当后代正常完成时为非零值；
- `WEXITSTATUS(status)` - 后代的返回码（仅当 `WIFEXITED(status)` 非零时有效）。

后代的返回码获取方式如下：

```c
waitpid(pid, &status, 0);
if (WIFEXITED(status))
   printf("Descendant ended with code %d\n",
   WEXITSTATUS(status));
```

## 5.3.7 警报

在多任务环境中，需要报告系统中发生的事件或其他进程中的事件。POSIX 定义的最简单的此类警报机制是 *信号*。进程在接收到信号后，会立即响应其调用特殊函数——信号的 *处理程序*（信号处理函数），或对该信号采取默认操作。每个信号都对应一个在系统中唯一的数字。除了信号本身，无法传输其他信息。

信号是 UNIX 系统上最简单的进程间通信机制，但由于它们允许传输的数据有限，因此主要用于事件报告。

### 信号类型

根据具体情况，信号分为同步信号和异步信号。同步信号发生在活动进程流的执行过程中（通常通过错误产生——访问错误的内存区域、错误的浮点运算、执行处理器设计中不存在的指令）。这些信号由操作系统内核生成，并立即发送给导致错误的进程线程。

异步信号可以在进程执行的任何时刻被接收：

- 程序员可以使用系统调用向另一个进程发送异步信号，在 POSIX 系统上，该调用称为 `kill()`，其参数是信号编号和进程标识符
- 信号也可能由某些外部事件（按键、终止等）引起

在处理此类信号期间，系统必须中断当前代码的执行，执行处理器代码，并返回到接收信号时执行的那条指令。

### 信号布局

在接收到信号时，进程可以通过三种方式之一进行响应（响应方式称为信号处置）：

- 调用信号处理程序
- 忽略该信号，此时信号“消失”且不采取任何操作
- 使用默认操作（这是每个信号的默认设置，通常会导致进程终止）

进程可以为每个信号设置单独的处置方式。

## 信号阻塞

进程不仅可以设置信号的处置方式，还可以确定其在那一刻是否愿意接收某种类型的信号。如果进程尚未准备好，它可以阻塞这些信号。如果要把一个被阻塞的信号发送给进程，系统会将其排队，直到进程解除阻塞。进程通过更改 *进程信号掩码*（一个存储关于哪些信号可以立即传递给进程的特殊数据结构，通常存储在其控制块中）来阻塞和解除阻塞信号。后代进程继承祖先的信号掩码。

## 信号示例

考虑 POSIX 定义且 Linux 支持的信号（名称旁边括号内给出信号编号）。例如，同步信号包括在访问受保护的内存区域时由系统生成的 `SIGSEGV` (11) 信号。

异步信号包括：

- `SIGHUP` (1) - 挂断通信线路（例如，用户注销系统）
- `SIGINT` 和 `SIGQUIT` (2, 3) - 来自键盘的程序中断信号（分别由用户按下 Ctrl+C 和 Ctrl+\ 生成）
- `SIGKILL` (9) - 立即终止程序（此信号无法被捕获、阻塞或忽略）
- `SIGUSR1`、`SIGUSR2` (10, 12) - 可由应用程序使用的用户信号
- `SIGTERM` (15) - 请求程序关闭（与 `SIGKILL` 不同，此信号可能被忽略）

除了 `SIGSEGV` 之外，所有这些信号的默认操作都是终止程序（对于 `SIGSEGV` 还会生成额外的内存转储（core dump）——一个存储进程地址空间映像以供后续分析的文件）。

## 设置信号处置

使用 `sigaction()` 系统调用来设置信号处置。

```c
#include <signal.h>

int sigaction(int signum,              // 信号编号
              const struct sigaction *act, // 新处置
              struct sigaction *old_act); // 返回之前的处置
```

使用具有以下字段的 `sigaction` 结构体来描述处置：

- `sa_handler` - 指向信号处理函数的指针
- `sa_mask` - 指定在处理程序内部将阻塞哪些信号的信号掩码
- `sa_flags` - 附加标志

将 `sa_mask` 和 `sa_flags` 零化的限制（不阻塞任何信号）：

```c
struct sigaction action = {0};
```

`sa_handler` 字段应设置为指向先前声明的函数的指针，该函数看起来像这样：

```c
void user_handler(int signum)
{
    // 信号处理
}
```
