

不同的调度算法可以应用于不同的队列，并且可以为每个队列分配一定数量的 CPU 时间。共享优先级是一项困难的任务，如果无法解决这些问题，可能会导致低优先级进程的流等待很长时间。例如，1973 年，麻省理工学院的一台机器停机，原因是一个低优先级进程——它于 1967 年排队等待执行，但此后一直无法运行。这种情况被称为*饥饿*。

解决饥饿问题有多种方法。例如，调度程序可以逐渐降低其所执行流（stream/thread，此处指进程上下文）的优先级（此过程称为老化），当该优先级低于下一个优先级流时，将上下文切换到该流。相反，你也有可以逐渐增加等待在用户终端（UT）中流优先级的做法。

## 基于性能特征的规划

优先级调度算法的一个重要类别是那些基于对其后续执行特征的知识或评估来做出执行流选择决策的算法。

首先，需要注意的是，在“*最短完成时间优先*”算法（Shortest Time to Completion First, STCF）中，当每个流关联一个预计的 CPU 使用时长区间时，系统会选择那个具有最短该区间的流来执行。结果是，占用 CPU 时间较短的流在调度中占据优势，并能更快地离开系统。

STCF 算法在平均响应时间指标上是理论最优的，也就是说，可以证明对于选定的流组，应用此算法时的平均响应时间将比任何其他算法都小。不幸的是，在短期规划中无法实现它，因为其实现需要对预期特征的预测。在长期规划中，它经常被使用（在这种情况下，操作员在设置任务时必须指示预期的完成时间，系统在做出选择时会考虑这一点）。此外，请注意，此类算法的最优性与其对较长 CPU 使用区间流的“不公平性”是不可分割的。

对于短期调度，可以根据对下一个处理器使用区间长度的估计来实现对该算法的近似，该估计会考虑同一流之前的区间。你可以使用递归公式来计算此估计值：

$t_{n+1} = a \cdot t_n + (1 - a) \cdot T_n, \quad 0 \le a \le 1, \quad t_0 = T_0$

- $t_{n+1}$ - 区间长度的估计值；
- $t_n$ 是前一个区间长度的估计值；
- $T_n$ 是前一个区间的真实长度。

最常用的值是 $a = 0.5$，在这种情况下，只需计算前一个估计值和实际区间值之间的平均值即可。

**最短剩余完成时间优先，SRTCF。**
它与 STCF 的区别在于，当一个新的线程进入就绪线程队列时，如果下一个 CPU 使用时限短于当前线程完成前剩余的时间，则当前线程会被中断，新线程取而代之。

## 多级反馈队列

*多突发带反馈*算法（多级反馈队列）是调度算法（通过配置，它可以退化为其他任何算法），但其中一种变体被广泛用于实现中。在组织数据结构方面，此算法与传统的多级队列算法相似：存在几个具有不同优先级的就绪线程队列，低优先级队列中的线程仅在所有上级队列为空时运行。

这两种算法之间的区别是：

- 允许流（进程）在层级之间移动。
- 队列中的流（进程）不是根据优先级和使用区间长度划分的；具有较短区间的流（进程）位于更高优先级的队列中。

除了最低级别的队列外，所有队列内部都使用循环调度（最低级别使用 FIFO 算法运行）。不同的队列对应不同的时间片长度——优先级越高，时间片越短（通常相邻队列的时间片长度减半）。如果流（进程）耗尽了其时间片，它会移动到较低优先级（且时间片较长）队列的尾部。结果是，具有较短区间的流（例如 I/O 密集型流）保持高优先级，而具有较长区间的流则被延长执行时间。还可以自动将非受管流（即非交互式或无需用户关注的流）从低级层移动到其他层或移出队列。

## 彩票调度

彩票调度（lottery scheduling）- 一种易于理解和实现的算法，具有巨大潜力。彩票调度的理念是：

- 流（进程）接收一个疯狂的数量的彩票券，每张券授权其使用处理器时间为 T。
- 调度程序在时间段 T 内随机选择一张彩票券。
- 获胜的流（进程）获得控制权进入下一次抽奖。

彩票调度允许你：

- 模拟循环调度，通过给每个流（进程）相同数量的彩票券。
- 模拟优先级调度，通过根据流（进程）的优先级分配彩票券。
- 模拟 SRTCF - 给短流（进程）比长流（进程）更多的彩票券（如果流（进程）至少收到一张彩票券，它就不会饥饿）。
- 确保处理时间在线程之间分割 - 给每个线程分配与其所需处理器时间份额成比例的彩票券数量（例如，如果有三个线程，并且需要线程 A 占用 50% 的处理器，线程 B 和 C 各占 25%，则可以给流 A 两张彩票券，流 B 和 C 各一张）。
- 通过动态选择和添加彩票券来改变优先级。

虽然彩票调度只能以某种概率近似解决这些任务中的大多数，但在实践中，它们令人相当满意。系统运行时间越长，结果就越接近理论值（根据大数定律）。事实上，彩票调度利用了这样一个事实：所有的调度理念在很大程度上都是启发式的，因为无法准确预测系统中流的行为本质。

## Linux 中调度的实现

考虑 Linux 调度的两种实现方式——传统方式（包括 2.4 及更早的内核）和包含在 2.6 内核中的新方式。
Linux 内核在调度时不区分进程和流（threads），因此为了确定性，我们将继续讨论进程调度。系统中的所有进程可以分为三组：具有 FIFO 调度的实时进程、具有循环调度的实时进程、普通进程。

## 内核进程的实时调度

关于实时进程，只需说明以下几点：

- 在调度时，它们始终优先于普通进程。
- FIFO 调度进程一直执行，直到它自己放弃处理器（例如，由于暂停或终止），或者被更高优先级的实时进程取代。
- 循环调度进程也是如此，只不过当时间片耗尽后，它会进一步被移走。

### 传统调度算法

考虑普通进程的调度算法。该算法的核心是向*纪元*（epochs）分配 CPU 时间。在纪元期间，每个进程都有一个时间片，其长度在纪元开始时计算。在大多数情况下，不同进程的时间片长度不同。当进程耗尽其时间片时，它会被移开，并在当前纪元内不再执行。控制权移交给另一个进程。然而，如果进程因 I/O 或同步而暂停，其时间片不被视为已耗尽，并且调度器可以在当前纪元内再次使其耗尽。当所有就绪进程都耗尽其时间片时，纪元结束。在这种情况下，调度算法重新计算所有进程的时间片，并开始一个新的纪元。在纪元开始时设置的时间片被称为*基本处理时间片*。其值可以通过 *nice*() 和 *setpriority*() 系统调用动态修改。子进程始终继承其祖先的基本时间片。

有两种类型的进程优先级：固定优先级，仅适用于在进程创建期间设置的实时进程；以及动态优先级，适用于普通进程，取决于基本优先级和直到时间片耗尽的剩余时间。
