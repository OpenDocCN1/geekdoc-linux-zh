# 管理和流块

系统中有关进程和流的信息存储在特殊的数据结构中，这些结构被称为进程控制块（PCB）和流控制块（TCB）。这些结构对操作系统非常重要，因为系统基于这些信息来管理进程。

管理流向活跃流（即处于就绪、等待或执行状态的流）的电力流（线程控制块或 TCB）。此块可能包含以下信息：

-   流标识符（通常是其唯一标识符）
-   流处理器状态：自定义处理器寄存器、指令计数器、栈指针
-   流的计划信息

流表是流控制单元的列表或数组。它位于操作系统内存的受保护区域中。管理单元进程（进程控制块或 PCB）对应于系统中存在的进程。此类块可能包含：

-   进程标识符（唯一标识符，有关与该进程相关的其他进程的信息）
-   有关在进程地址空间中运行的线程的信息（例如，指向其控制块的指针）
-   允许确定进程使用不同资源的权限的信息（例如，创建该进程的用户 ID）
-   进程地址分配信息
-   有关进程使用的 I/O 资源和文件的信息

# 进程和流的映像

显示在内存中的进程信息的全集称为进程映像，所有流信息称为线程映像。进程映像包括：

-   进程控制单元
-   用户代码
-   用户数据（对所有线程通用的全局程序数据）
-   进程流模式信息

用户程序代码、用户数据和流信息被加载到进程地址空间中。进程映像通常不是内存的连续段；其部分会被卸载到磁盘上。流映像包括：

-   流控制单元
-   内核栈（执行内核流代码时使用的流栈）
-   用户栈（用户模式下可用的流栈）

# 创建和完成进程与线程

进程创建和终止工具允许动态更改在操作系统上运行的应用程序集合。线程创建和完成工具是多线程应用程序创建的基础。

# 创建进程

## 进程创建的基本原则

在系统初始化期间，系统的内核可以创建进程。例如，在 UNIX 兼容系统中，这样的进程可以是 init 系统的初始化进程，在 Windows XP 中则是子系统（Win32 或 POSIX）的进程。然而，这种创建过程是例外而非规则（fork 和 exec）。

大多数情况下，进程是在执行其他进程时创建的。在这种情况下，创建另一个进程的进程被称为祖先进程，而被它创建的进程被称为后代进程。根据应用程序的逻辑，可以在应用程序运行时创建新进程（编译器可以为每个编译步骤创建进程，Web 服务器可以处理传入请求），也可以直接根据用户请求创建（例如，从命令解释器、图形外壳或文件管理器）。

## 交互式进程和后台进程

根据与用户的交互方式，有两种类型的后台进程。

-   **交互式进程**直接与用户交互，接收来自键盘、鼠标等的输入。交互式进程的例子是文本编辑器或集成开发环境的进程。
-   **后台进程**不直接与用户交互。它们通常在系统启动时启动，并等待来自其他应用程序的请求。其中一些（系统进程）支持系统的运行（实现后台打印、网络工具等），另一些则执行专门的任务（实现 Web 服务器、数据库服务器等）。后台进程也称为服务（在 Windows XP 系统中）或守护进程（在 UNIX 上）。

## 创建进程时管理地址空间

由于进程的核心元素是安全的地址空间，因此在创建新进程时解决其分配问题非常重要。考虑两种不同的方法。

### 系统调用 Fork() Exec()

在第一种方法中，后代的地址空间创建为祖先地址空间的精确副本。此操作由系统调用实现，在 POSIX 系统中称为 `fork()`。在这种情况下，不仅复制了地址空间，还复制了主进程命令的计数器，因此在调用 `fork()` 后，祖先和后代会遵循相同的指令。开发人员必须确定应该管理这两个进程中的哪一个。这可以基于 `fork()` 返回码在祖先和后代之间的差异来完成。

当通过复制祖先地址空间来创建新进程时，需要特殊手段将代码加载到进程的地址空间中。这样的工具由系统调用实现，在 POSIX 系统中称为 `exec()`。作为一个选项，要调用 `exec()`，必须指定要加载到内存中的可执行程序的完整路径。在基于 `fork()` 的系统中，为了运行程序，必须在调用 `fork()` 后立即调用 `exec()`（这被称为 fork + exec 技术）。

### 通过一个系统调用运行应用程序

第二种方法不分离地址空间复制和代码加载——在这里，这些步骤合并为一个。在这种情况下，系统调用触发了指定应用程序的执行（通常需要指定该应用程序可执行文件的完整路径）。它应该分为系统调用实现的两个阶段：

-   为新进程的地址空间分配内存（不复制来自祖先地址空间的信息）
-   从指定文件中下载可执行代码到划分的地址空间

使用 `fork()` 和 `exec()` 的方法更加灵活，因为它允许在必要时仅通过启动应用程序的一个步骤来完成。现代操作系统主要实现第一种和第二种方法的组合。

## 进程完成的特点

考虑完成进程的三种选择。进程在完成任务后**正确地自行完成**（对于交互式进程，这通常由用户发起，例如，使用相应的菜单项）。为此，进程代码必须执行一个用于完成进程的系统调用。在 POSIX 系统中，此调用称为 `exit()`。它可以触发导致该调用的进程。

由于错误，进程**崩溃**。这种输出可以由程序员提供（处理程序无法继续的决定时的错误），也可能由中断生成（除以零、访问内存的安全区域等）引起。

进程由**另一个进程**或系统内核**完成**。例如，在操作系统关机之前，内核会停止执行所有进程。进程可以通过系统调用终止进程，在 POSIX 中称为 `kill()`。

一旦进程完成其工作，为其地址空间保留的内存就会被释放，并可用于其他用途。该进程的所有流也停止存在。如果该进程有后代，则最好在祖先工作结束后不终止它们的工作。在线进程通常在用户注销时终止。

### 进程的同步和异步执行

当系统为旧进程创建新进程时，有两个基本选项：

-   与新进程并行继续执行——这种操作模式称为**异步执行**
-   挂起执行直到新进程完成——这被称为**同步执行**。（在这种情况下，使用一个特殊的系统调用，在 POSIX 系统中称为 `wait()`）

特定模型的选择取决于具体任务。例如，Web 服务器可以创建后代进程来处理请求（如果后代集合不足以处理该请求）。在这种情况下，处理必须是异步的，一旦创建后代，祖先就必须准备好接收下一个请求。另一方面，编译器在继续下一阶段之前必须等待每个步骤完成，在这种情况下，使用同步处理。
