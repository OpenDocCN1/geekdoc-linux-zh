

传统进程的优先级在首次调度时总是低于任何实时进程的优先级。

我们描述进程数据结构中与调度规划相关的最重要字段：

-   **策略** – 决定进程属于哪个组（普通进程、实时 FIFO 算法等）。
-   **Nice** – 指定基于处理时间基础配额的基础值（为了简单起见，将来我们会认为 nice 值等于基础配额；但事实上并非完全如此）。
-   **Counter** – 包含在进程配额耗尽前剩余的定时器中断次数。在时间片开始时，定时器中断处理程序会将基础配额值逐步减少（每次减一）。

## 调度过程调用条件

考虑发生调度调用（称为 `schedule()`）的情况。

-   当进程需要阻塞，因为它所需的资源当前不可用。在这种情况下，其控制单元首先被添加到相应的等待队列中，然后发生重新调度。
-   延迟启动（惰性调用）。延迟启动是指在某一时刻，进程结构的特殊字段 `need_resched` 被赋值为 1。这在以下情况中会被触发：
    -   当当前进程已耗尽其时间配额时；
    -   当具有比当前进程更高优先级的进程进入待机状态时；
    -   当进程通过适当的系统调用明确表示其执行权利低于其他进程时。

这种重新调度立即发生，但随后，当进程在中断后必须重新获取控制权时，它会检查 `need_ressched` 单元是否被设置。如果等于 1，则启动调度过程。

## 调度过程

该过程首先检查当前进程是否处于待机状态，如果是，则将其从进程队列中移除。然后选择一个进程执行。为此，查看完成（就绪）进程队列，对每个进程评估动态优先级，并选择具有最大值的进程。对于一个时间配额已用完的进程，其值将为零。如果没有选择到进程，则当前进程继续运行。当做出选择时，上下文切换到新进程。

## 新时代的开始

当所有就绪进程队列中的进程动态优先级值均为零时，会出现一种特殊情况，这意味着它们都已耗尽配额，是时候开始一个新的纪元了。然而，这并不意味着系统中没有配额未耗尽的进程——它们可能被排队（最常见的情况是，这些是受 I/O 限制的进程）。

当新纪元开始时，系统中所有进程（不仅仅是待机进程）的配额都会重新计算。在这种情况下，每个进程的配额长度设置为其基础优先级与其剩余配额一半之和：

```c
for each_task (p)
    p.counter = (p.counter / 2) + p.nice;
```

由于新纪元的开始，只有在非就绪状态的进程中配额才保持非零，该算法为具有 I/O 限制的进程提供了优势。在这种情况下，进程的配额值永远不会大于其基础优先级值的两倍。

## 动态优先级计算

让我们回到动态优先级的计算。为此，使用 `goodness()` 函数。考虑它可能返回的值。

-   **0** – 当进程的时间用完时。该进程将不会被选择执行。除非它是完成（就绪）进程队列中的第一个，且队列中其他所有进程也已耗尽配额。
-   **0 到 1000** – 如果进程未耗尽其时间配额。该值基于进程的基础配额值和当前配额中剩余部分进行计算。这可以总结如下：

```c
c = p.counter + p.nice; // 其中 p 是指向进程控制块的指针。
```

这意味着进程完成任务所需的时间越长且其基础配额越长，其优先级越高。此外，对于与祖先进程使用相同内存的进程，每单位值会进一步增加（例如，如果进程显示使用 `clone()` 创建的流程）。

## 创建新进程时的配额重算

考虑创建新进程时发生的情况。最简单的解决方案（将计数器值复制到子进程数据结构中）可能会导致进程通过创建执行相同代码的新子进程来人为地延长其配额。为了防止这种情况，在 `fork()` 函数之后，计数器的值被一分为二：一半分配给子进程，另一半保留给父进程。

列出该算法的缺点。

-   执行进程的选择取决于对就绪进程队列中所有进程动态优先级的计算。随着系统中就绪进程数量的增加，在每次调度过程调用期间从头到尾遍历队列是不划算的。
-   如果进程数量非常多，在新时代开始时列出所有动态优先级将花费很长时间。另一方面，系统中进程越多，纪元变更的频率越低。
-   该算法旨在减少 I/O 受限进程（即使是非交互式进程，例如后台搜索引擎索引）的响应时间，即使它们不需要短的响应时间。
-   随着处理器数量的增加，维护不考虑不同处理器存在的公共队列变得不划算。

## 现代调度实现方法

在系统运行在负载条件下时，这些缺点开始显著影响系统的运行。在正常条件下，传统的 Linux 调度工作得相当有效。针对缺点的修复工作一直在进行。结果，一种新的调度算法实现被集成到 2.6 版本的内核中。简要考虑它如何帮助解决之前提到的问题。

首先，该算法支持每个处理器独立的就绪进程队列，确保在多处理条件下的高效运行。另一个问题涉及到需要在每次规划过程调用时依赖旧算法对所有就绪进程动态优先级的计算。解决方案如下：每个消化（就绪）进程队列都是就绪进程队列的数组，其中元素按动态优先级排序。结果，在选择要执行的进程时，只需查看最高优先级队列中第一个可以启动的进程即可。此过程不依赖于就绪进程的数量。

有两个就绪进程队列数组——一个活动进程队列数组和一个配额耗尽进程队列数组。当进程耗尽其配额后，它从第一个数组转移到第二个数组。当活动队列中没有进程时，两个数组互换，步骤序列从头重复。结果，配额耗尽增加了运行那些尚未耗尽配额的进程的可能性。

## 调度的编程接口

让我们看看那些可以处理底层进程优先级（`nice` 值）从而影响其调度的 Linux 系统调用。

要更改进程的基础优先级，请使用调用 `setpriority()`：

```c
#include <sys/resource.h>
int setpriority (int which, int who, int priority);
```

特别是，参数 `which` 可以设置为 `PRIO_PROCESS` 或 `PRIO_USER`，分别表示该参数将被解释为进程标识符或用户 ID。在第一种情况下，它们为特定进程（或如果 `who` 等于零，则为当前进程）设置优先级；在第二种情况下——为该用户的所有进程设置优先级。

优先级参数设置新的优先级。优先级可以在 -20 到 20 之间变化；较小的值表示较高的优先级。默认值为 0。只有具有管理员特权的用户才能设置负的优先级值。

使用 `getpriority()` 调用以获取当前基础优先级的信息：

```c
int getpriority (int which, int who);
```

此调用返回优先级值；对于它，`which` 和 `who` 参数的含义与 `setpriority()` 函数相同。
