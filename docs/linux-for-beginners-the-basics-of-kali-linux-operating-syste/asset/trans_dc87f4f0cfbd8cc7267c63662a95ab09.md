
介于两者之间。在这种情况下，可以说该操作不是一个原子而是分子。

因此，解决竞争问题的方法是将导致问题的代码片段转换为原子操作，即保证在不受到其他线程干扰的情况下完全执行。这段代码称为*临界区*：

```python
// start critical section
total_amount = total_amount + new_amount;
// end of critical section
```

现在，当两个线程同时试图执行临界区代码时，先启动的那一个将在第二个开始执行之前完全执行完其所有代码（第二个线程将等待第一个线程完成临界区的代码）。因此，我们保证程序中会出现选项 2 的事件序列，从而永远不会发生竞争。

考虑临界区应具备的特性。

- 互斥：在特定时刻，临界区只能执行一个线程
- 如果多个线程存在于临界区入口处，则必须有一个线程被要求进入其中（它们不能完全阻塞彼此），即前进性
- 有界等待，试图进入临界区的进程，迟早必然会被要求进入其中

一个简单的问题仍然保留着：“我们如何让系统将多个操作感知为一个原子操作？”解决此类任务的最简单方案是在临界区期间禁止中断。这种方法虽然在原则上解决了问题，但在实践中不能应用，因为整个系统的临界区循环程序可能会保持中断锁定状态，从而产生不利条件。

## 加锁

更整洁的解决方案是使用*锁*。锁是一种防止多个线程执行临界区代码的机制。使用锁分为两步：提交（加锁，`acquire_lock()`）和解锁（开锁，`release_lock()`）。在锁的情况下，会检查它是否已经被其他线程加锁，如果是，该线程进入待机状态，否则，强制加锁并进入临界区。离开临界区后，流程移除阻塞。

```
acquire_lock(lock);
// critical section
release_lock(lock);
```

这样就实现了互斥特性，因此阻塞的另一个名称是互斥锁，即 mutual exclusion 的缩写。

## 阻塞实现中的问题

考虑使用*锁变量*对临界区进行简单实现。
每个临界区关联一个整数变量，该变量在冻结时假设为单位值，在锻造后为零。以下是该实现的代码：

```
int lock = 0;
void acquire_lock(int lock)
{
// if lock does not have ( lock == 0), roll it (set lock = 1)
// and exit - we are in the critical section
// otherwise wait until the lock is removed
while(lock != 0); // (1)
lock = 1; // (2)
}
void release_lock(int lock)
{
// remove the lock
lock = 0;
}
```

该实现的主要问题是，检查锁变量的值和修改它不是单个原子操作的一部分。

## 流同步的基本机制

现代操作系统提供了一系列现成的同步机制。*同步机制*是帮助解决同步主要任务（确保处理共享数据的线程之间的协调）的操作系统工具。如果这些工具是构建多线程程序的最小模块，它们被称为*同步原语*。

同步原语分为以下主要类别：

- 通用的、低级的，可以以不同方式使用（*信号量*）
- 简单的、低级的，每一个都适应于解决方案
- 通过简单原语表达的高级通用原语；这一组包括可以通过互斥锁和条件变量表达的*监视器*概念
- 高级的，适应于解决特定同步问题（阻塞读/写和屏障）

让我们看看不同的机制，评估它们各自的优点，以及可能的缺点。为了进一步说明材料，让我们采用一个展示同步需求的经典示例——生产者-消费者问题或有限缓冲区问题。

问题陈述很简单。假设有生产线程和消费者线程。制造者创建对象，消费者接收它们。任务是同步它们的工作，以便消费者不能尝试获取尚未创建的对象，并且制造者不能创建超过消费者能力的对象。

为了同步线程，在制造者和消费者之间放置一个固定长度 $n$ 的缓冲区。制造者可以将对象放入缓冲区，消费者-从中取出。如果消费者取走对象，它就从缓冲区中移除。需要满足几个要求：

1. 当制造者或消费者正在操作缓冲区时，其余线程应等待其完成
2. 当制造者试图将对象放入缓冲区且缓冲区已满时，它必须等待直到出现空位
3. 当消费者试图从缓冲区取走对象且缓冲区为空时，它必须等待直到对象出现

## 信号量

信号量概念由 E. Dijkstra 于 1965 年提出——著名的荷兰计算机科学家。信号量是实践中使用的最古老的同步原语。信号量是一个共享的非负整数计数器，具有初始值，并确定以下原子操作：

- Down 信号量（down）：如果信号量的值大于零，则减一；如果值为零，则该线程进入待机状态，直到其大于零（所有在信号量处“等待”或“阻塞”的线程）。此操作也称为期望 - 等待。以下是其伪代码：

```
void down (semaphore_t sem)
{
    if (sem > 0)
        sem--;
    else sleep ();
}
```

- Increase 信号量（up）：将信号量的值增加一；当有线程在信号量处等待时，其中一个线程退出等待并执行其自身操作。如果一个信号量上有多个线程在等待，其 up 值由于 up 操作仍保持为零，但其中一个线程继续执行（在大多数实现中，该线程的选择将是随机的）。此操作也称为 post-信号。以下是其代码：

```
void up (semaphore_t sem)
{
    sem ++;
    if (waiting_threads ())
        wakeup (some_thread);
}
```

实际上，信号量的值决定了可以通过该信号量而不会阻塞它的线程数量。当信号量设置为初始值零时，它将阻塞所有线程，直到某个线程通过执行 up 操作“打开”它。任何对信号量有访问权限的线程都可以执行 up 和 down 操作。

## 信号量的使用特点

信号量可用于解决同步两个不同任务的债务问题。

1. 借助它们，可以组织互斥（保护临界区代码免受多个线程执行）。使用**二进制信号量**最为方便，它可以取两个值：0 和 1。以下是使用二进制信号量实现临界区的示例：

```c
semaphore_t sem = 1; // at the beginning the semaphore is open
down (sem);
// critical section
up (sem);
```

2. 借助它们，可以组织对某个条件满足的期望。假设需要组织一个线程等待另一个线程完成（类似于 join 操作）。在这种情况下，可以使用初始值为 0（关闭）的信号量。等待的线程必须对该信号量执行 down 操作，并且为了信号流的完成，其完成函数需要对该相同信号量执行 up 操作。以下是伪代码（this_thread 代表当前线程）：
