✈ To release the mutex ( mutex_unlock ): mutex becomes free; if several streams are expected on it, one of them is selected, it starts executing, occupies the mutex and enters the critical section. In most implementations, the flow selection will be random. Only the owner can release the mutex. Here is the pseudocode of this operation:

```
mutex_unlock (mutex_t mutex)
{
if (mutex.owner! = this_thread)
return error;
mutex.state = free;
if (waiting_threads ())
wakeup (some_thread);
}
```

Some implementations provide a third operation try to take the mutex ( mutex_trylock): if the mutex is free, to act similarly to mutex_lock, if busy - to immediately return the error and continue execution. Here is the simplest implementation of the critical section using a mutex.

```
mutex_t mutex;
mutex_lock (mutex);
```
