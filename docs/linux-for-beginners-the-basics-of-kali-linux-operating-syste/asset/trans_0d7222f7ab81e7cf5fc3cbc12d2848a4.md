

// 为当前进程设置优先级
setpriority (PRIO_PROCESS, 0, 10);
// 获取当前优先级值
printf ("当前优先级: %d\n", getpriority (PRIO_PROCESS, 0));

你还可以使用 nice() 系统调用相对地更改当前进程的基础优先级：

```c
#include <unistd.h>
int nice(int inc); // 将当前进程的优先级改变 inc。
```

## 结论

- 调度线程的任务是组织多个线程在单个处理器上的执行，使用户产生它们同时运行的错觉。规划目标是：最小化响应时间、最大化吞吐量以及公平性。主要的规划策略包括抢占式和非抢占式多任务。在现代操作系统中，当关于切换流程上下文的决策是在系统内核代码中而不是在流程代码中做出时，就会使用多任务处理。
- 区分长期、中期和短期规划。其中最重要的是短期调度器，它用于决定在给定时间运行哪个流程。基本的短期调度算法包括轮转和优先级规划。

# 第 5 章：流程交互

让我们考虑单个进程中流程交互的基本原理。重点将放在同步访问这些流共享数据上。

## 流程交互的基本原则

在并行过程中执行的线程可以是独立的，也可以相互交互。如果一个流不影响其他进程线程的执行，不检测来自它们的影响，并且没有与它们共有的数据，那么该流是独立的。其实现显然取决于输入数据，被称为确定性的。

所有其他线程都是交互式的。这些线程与其他线程共享数据（它们位于其进程的地址空间中）。它们的实现不仅取决于输入数据，还取决于其他线程的执行，即它们是 *非确定性的*（让我们进一步考虑这种非确定性的示例）。

独立线程执行结果总是可以重复的，而交互线程则不然。数据虫子是几个流共有的，称为共享数据。这是多线程编程最重要的概念。任何流都可以随时更改此数据。确保对共享数据正确访问的机制称为流同步机制。

处理独立流比处理交互线程更容易。程序员可以忽略其他线程与这些线程并发运行的事实，并忽略线程正在处理的共享数据的状态。

然而，有几种原因说明为什么不能实现线程交互。

- 在处理流时需要组织信息共享。例如，数据库或 Web 服务器用户可能希望同时请求相同的信息，系统必须确保服务这些用户的线程能够并发地接收信息。
- 正确实现这种交互并使用适当的算法可以显著加快多处理器系统上的计算过程。此任务被分为在不同处理器上同时执行的子任务，结果被收集在一起用于最终解决方案。这种技术称为 *并行计算技术*。
- 在需要并发执行 I/O 计算的任务中，I/O 线程应该能够向其他线程发出其操作完成的信号。
- 这种组织方式使得将任务划分为单独的模块成为可能，这些模块设计为独立的线程，同时，一个模块的输出可以作为另一个模块的输入，并且由于单个模块可以在不影响其他模块的情况下更改，因此增加了系统的灵活性。

并发执行交互流的需求需要机制来在它们之间交换数据并确保它们同步。

## 流程交互的主要问题

### 竞争问题

让我们看一个更简单的例子，当交互流在没有额外同步步骤的情况下共享公共数据时可能发生什么。假设在银行组织系统中，为每个用户分配一个单独的流（试图在大量同时请求的情况下提高系统性能）。假设将数据放入用户存款是通过增加全局变量 total_amount 来实现的。此时，每次更改存款时，每个流执行以下简单运算符：

`total_amount = total_amount + new_amount;`

问题是：由于存款，是否可能保证对应于每个用户的流能够按所需值增加 total_amount 的值？

实际上，这个乍看之下最简单的运算符分解为一系列操作：

- 获取全局内存中 total_amount 的当前值
- 将其增加 new_amount 并将结果存储在全局内存中

考虑两个用户 A 和 B 共享同一账户的情况。账户中有 100 个货币单位。用户 A 打算存入 1000。用户 B 同时存入 100。对应于用户 A 的流 $T_A$，流 $T_B$ 对应用户 B。

考虑以下事件序列（选项 1）。

1. 流 $T_A$ 读取 total_amount，其值为 100。
2. 流 $T_B$ 读取 total_amount 的值，其值也为 100。
3. 流 $T_A$ 将步骤 1 中读取的 total_amount 值增加 1000，得到 1100 并将其存储在内存中。
4. 流 $T_B$ 将步骤 2 中的 total_amount 值增加 100，得到 200，并同样存储在全局内存中，覆盖了流 $T_A$ 保存的内容。

用户 A 的存款完全丢失了。

现在考虑另一个事件序列（选项 2）。

1. 流 $T_A$ 读取 total_amount，将其增加到 1100（假设原始 100 + 1000）并将值记录在全局内存中。
2. 流 $T_B$ 读取 total_amount，其值为 1100，将其增加 100 至 1200，并将值写入全局内存。

结果，两笔存款都成功注册了。

正如你所见，上述最简单代码片段的执行结果取决于系统中线程的执行顺序。这导致：在一种情况下代码可能工作，在另一种情况下则不工作，并且通常无法预测错误的出现。这种情况被称为竞争（或竞争条件），这是程序员面临的最困难的 bug 之一。实际上它是不可检测的（因为覆盖所有可能的流执行序列组合是不现实的，特别是当存在许多序列时）。

解决这些问题需要流同步。立即指出，同步和并行计算组织的问题是实际编程中最困难的问题之一。因此，多线程程序的开发和调试通常被视为一种并非所有程序员都了解的“艺术”。

事实上，这种开发和调试不是艺术，而是一种严格的纪律，遵循一个基本原则：由于对于多线程程序，传统调试不适用，程序员必须编写代码，以便在开发阶段留有错误余地。让我们熟悉为了生成的代码符合此原则必须遵循的规则。考虑解决竞争问题的主要方法。

有时（但很少）你可以直接忽略这些错误。当我们不关心准确记录特定数据，而是收集关于它们的统计数据时，这可能有意义，因此个别错误不会影响总体结果。例如，全局计数器是一个用于计算每天系统平均请求数的值，你可以忽略每几小时发生一次的注册此类请求的错误。不幸的是，在大多数情况下，这种方法不被接受。

有时，全局数据的使用并非由任务的特定性所决定。在这种情况下，直接的解决方案是为每个流创建数据的本地副本，并仅操作它们。在实践中，这效果非常好，并应尽可能使用。例如，如果问题的特定性允许为每个线程创建单独的计数器（或全局计数器数组，其中每个元素仅由特定流更改），那么实现这样的数据结构解决了问题。再次说明，这种解决方案不能应用于所有情况（例如，在银行账户的情况下，不同的流最终必须以某种方式修改所有账户的总额）。

在所有其他情况下，必须保护更改免受其他流的影响。这是同步的主要任务。考虑解决它的不同方法。
