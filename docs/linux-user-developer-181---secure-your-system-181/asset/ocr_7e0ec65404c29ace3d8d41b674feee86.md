# File storage

Amazon S3 (Simple Storage Service) was an original AWS product offering, but now forms part of a suite of file storage products

+   ## QUICK TIP

When AWS first launched, the S3 storage service was the headline offering. Before then, if you needed online storage you'd provision it in chunks – maybe get a server with a few terabytes of storage and when you ran out of space, get another one. S3 changed that by employing the now familiar model of only charging for what you use – and being very competitive when doing so. Amazon S3 is a simple object store. It is secure, 99.99999999% durable and scales past tens of trillions of objects. S3 is ideal for backup and recovery, tiered archive or user-driven content (like photos, videos, music and files). Objects are uploaded and retrieved using the AWS APIs, or exposed directly to the internet via Amazon's CDN (content delivery network) service, CloudFront. S3 objects can be automatically distributed between availability zones and regions, and versioning can be employed to add extra resilience to the platform. Although S3 pricing is extremely competitive, you may find yourself uploading objects that you don't need to access very often – for example, if you are using the service for backup. In order to save costs in this kind of

scenario, Amazon offers an "infrequent access" tier of S3. This costs approximately half the price of regular S3 for the storage itself, but each request to the object will be considerably more expensive. For objects that are required even less frequently, Amazon offers a special version of S3 called 'Glacier'. Although it is very cheap, retrieving data from Glacier is much slower. Data retrieval is divided into three tiers, which can take from a few minutes to several hours. Alongside EBS for attached instance storage and S3 for resilient object storage, Amazon offers Amazon EFS (Elastic File System) which provides simple, scalable file storage for use with Amazon EC2 instances in the AWS Cloud (or, via VPC peering, Lightsail instances). EFS delivers a file system that grows and shrinks capacity automatically, and provides high throughput with consistently low latencies. EFS is designed for high availability and durability, and provides performance for a broad spectrum of workloads and applications, including big data and analytics, media processing workflows, content management, web

### AWS Elastic Beanstalk

![](bbox=[0.08, 0.65, 0.3, 0.74])

+   ### 01
+   #### Deploy Beanstalk
+   With Elastic Beanstalk, you can deploy, monitor and scale an application quickly and easily. To deploy an existing web app, you will need to create an application source bundle and create a new Beanstalk application. If you want to create a Beanstalk deployment using an existing Git repository, then you can do so using the CLI tools. A number of sample applications are also included so you can try out the process.

![](bbox=[0.33, 0.65, 0.6, 0.74])

+   ### 02
+   #### Source bundle
+   An application source bundle consists of a single ZIP or WAR file, less than 512MB, containing your application's source code. This will be automatically deployed by Elastic Beanstalk. Your source should be in the root directory and you can also include an `extensions` directory containing one or more Elastic Beanstalk `.config` YAML configuration files, for configuring environment options.

![](bbox=[0.64, 0.65, 0.9, 0.74])

+   ### 03
+   #### Name and platform
+   In the first step of the Elastic Beanstalk process, you're prompted to provide an app name of up to 100 characters. Next, you select the platform your code runs on – sample platforms include Python, Ruby, Tomcat, Go, Java, Node, PHP, Packer and .NET as well as several Docker options and generic Docker containers. After selecting a sample app or uploading your code, you can create your app here or configure options.
