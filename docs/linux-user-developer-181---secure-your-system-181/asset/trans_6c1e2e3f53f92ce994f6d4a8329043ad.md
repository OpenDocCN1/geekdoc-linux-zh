## 关于 Web 应用程序

如果你不熟悉 Web 应用程序，你可能会问什么是 Web 应用程序。Web 应用程序（或简称 web app）是一种客户端-服务器软件应用程序，其中客户端部分运行在 Web 浏览器上。网络邮件、即时消息服务、在线商店以及其他许多类型的应用程序都是 Web 应用程序。因此，本教程的其余部分将教你如何创建此类应用程序，其中服务器部分使用 Erlang 开发，客户端部分显示在你喜欢的 Web 浏览器上。

Erlang 允许你快速编写一个简单的 Web 服务器，可用于测试你的 Web 应用程序并发现你的机器与托管 Web 应用程序的机器之间的任何连接问题。因此，本节将介绍一个简单的 Erlang 模块，该模块实现了一个朴素的 Web 服务器，它始终打印‘Hello World!’消息。然而，在生产系统上使用如此简单的 Erlang Web 服务器可能不是最佳选择。

## 创建用于测试的 Web 服务器

该 Erlang 模块的名称为 *naiveWS*，将保存为 *naiveWS.erl*。你可以在 **图 1** 中看到它的 Erlang 代码，这主要是一个简单的并发 TCP 服务器。

```erlang
-module(naiveWS).

open_connection(Port) ->
    spawn(fun() -> {ok, Socket} = gen_tcp:listen(Port, [{active, false}]),
        loop(Socket) end).

loop(Sock) ->
    {ok, Conn} = gen_tcp:accept(Sock),
    Handler = spawn(fun() -> handle(Conn) end),
    gen_tcp:controlling_process(Conn, Handler),
    loop(Sock).

handle(Conn) ->
    gen_tcp:send(Conn, reply("Hello World!\r\n")),
    gen_tcp:close(Conn).

reply(Str) ->
    B = list_to_binary(Str),
    ["Status: 200 OK\r\n" | "Content-Type: text/html;\r\n" | "Content-Length: " ++ Str ++ "\r\n"],
    [Size(B), B]].
```

**上方** 是 *naiveWS.erl* 的 Erlang 代码，使用 *gen_tcp:listen()* 和 *spawn()* 实现了一个非常简单但并发的 Web 服务器

*naiveWS:open_connection()* 函数只需要一个参数，即 Web 服务器将使用的端口。因此，在编译 *naiveWS.erl* 后，你可以通过在 Erlang 外壳中执行以下命令来启动 Web 服务器：

```bash
2> naiveWS:open_connection(1200).
<0.64.0>
```

使用 *wget* 实用程序测试 Web 服务器就像执行下一个命令一样简单：

```bash
$ wget 127.0.0.1:1200/
--2017-05-29 10:12:08--
http://127.0.0.1:1200/
Connecting to 127.0.0.1:1200... connected.
HTTP request sent, awaiting response... 200 OK
Length: 12 [text/html]
Saving to: ‘index.html’

index.html              100%[===========================>]       12  --.-KB/s    in 0s

2017-05-29 10:12:08 (2.86 MB/s) - ‘index.html’ saved [12/12]
```

生成的输出将验证 Web 服务器按预期工作。

*index.html* 文件的内容如下，这意味着 Web 服务器正在工作并且期望的消息已成功传送：

```html

```

如果 Web 服务器没有工作，*wget* 命令的输出将与以下内容类似：

```bash
--2017-05-29 10:20:10-- http://127.0.0.1:1200/

Connection refused.
```

然而，稍后你会看到，还有另外三个 Erlang 项目——MochiWeb、Yaws 和 Cowboy——更适合开发 HTTP 服务器。由于 MochiWeb 的简洁性，本教程稍后将会使用 MochiWeb，并且因为 Cowboy 具有许多功能并受到其开发人员的极佳支持，所以也会使用 Cowboy。尽管如此，Cowboy 和 Yaws 都比 MochiWeb 拥有更多的功能。

## 使用 Cowboy，一个 HTTP 服务器

Cowboy 是用 Erlang 编写的，它是 Erlang、OTP 和 Elixir 项目的小型高效 HTTP 服务器。Cowboy 支持多种类型的手处理器，包括 REST、WebSockets 和 HTTP。虽然本教程不是关于 Cowboy 的，但下一节将讨论其安装过程，因为如果你不习惯安装外部 Erlang 模块，你可能会发现这有点令人困惑。你可以在 https://github.com/ninenines/cowboy 以及 Nine Nines 的网站 https://ninenines.eu 上找到有关 Cowboy 的更多信息。

### Hello World! 程序

理论到此为止——现在是时候学习如何安装 Cowboy 并观察其实际运行效果了！

本节将展示一个简单的 Web 应用程序，以便更好地理解 Erlang 和 Cowboy 的整体工作方式。由于整个过程会相当复杂，你需要一个构建系统来让你的生活更轻松——在这种情况下，构建系统将是 Erlang.mk 工具，它将是你在开发使用 Cowboy 的项目时需要下载的第一个东西。你可以在 https://github.com/ninenines/erlang.mk 上找到有关 Erlang 构建系统的更多信息。

但首先，你需要创建一个目录来保存项目的所有文件——在这种情况下，项目名称为 `hw`，所以目录名称也将是 `hw`，你可以通过执行 `mkdir hw` 命令来创建它。然后，你需要执行 `cd hw` 以实际进入该目录。

现在请按照以下步骤创建一个将使用 Cowboy 的新 Erlang 项目：

```bash
$ wget https://raw.githubusercontent.com/ninenines/erlang/master/erlang.mk
$ make -f erlang.mk bootstrap-rel
$ make
```

现在是时候通过修改 Makefile 来实际安装 Cowboy 了。Makefile 的最终版本如下：

```makefile
PROJECT = hw
PROJECT_DESCRIPTION = A Hello World program
PROJECT_VERSION = 0.1.0

DEPS = cowboy
include erlang.mk
```

所有的工作都由 `DEPS = cowboy` 这一行完成，这将指示构建系统下载并安装 Cowboy。然后你需要在 `src` 目录中创建一个名为 `hw.app.src` 的新文件（如果它尚不存在——你可以通过查看随本教程提供的源代码来看见 `hw.app.src`）。现在，如果你执行 make 实用程序，构建系统将负责其余的工作！如果输出的最后一行是 `release-1.tar.gz successfully created`，那你目前做得很好。

接下来，你需要编辑一些现有的文件以定义你的 Web 应用程序将支持的 URL，并添加实现 Web 应用程序所需功能的 Erlang 代码。首先，你将编辑 `src/hw.app.erl`。图 3 展示了 `src/hw.app.erl` 文件的最终版本——这是你了解支持的 URL 列表以及 Cowboy 服务器将监听的端口号的第一个地方。然而，我们还没有完成，因为我们必须为该 URL 创建一个纯 HTTP 处理程序：

```bash
$ make new t=cowboy_http m=hw_handler
```
