## Resources

Most of the tools we will be using in this tutorial are standard on any Linux distribution. But you might need to install the wget command.

### First steps: Using pipelines, grep and cat in the terminal

Getting to grips with the Linux terminal can be daunting, but once it's mastered you'll find yourself much more productive.

If you're a Linux user, you've probably used the terminal before, even if only once or twice, and you might have dived into the world of shell scripting; the terminal is at the heart of Linux. While we should celebrate the fact that it's now possible to do so much in a Linux system without touching the terminal, it remains the case that if you master the terminal and shell scripting, you will have unlocked a powerful tool that can make you more productive and give you greater control over your computer. There's a bigger learning curve when it comes to using the terminal than with a graphical user interface, but it is no harder than learning a programming language, and you will find that the effort is well worth it.

In this tutorial series, we will be exploring ways in which you can use shell scripting and the terminal to improve your workflow and to automate routine tasks. We shall start with the most basic material and build up quickly to more advanced topics.

The first step towards becoming a terminal master is to open the terminal on your system. You do this in different ways on different distributions, and we can't give comprehensive instructions here. Look for an application called 'Terminal' or 'Console' or something similar and open it. If you see a window with a prompt and a blinking cursor as in Figure 1, then you've done it right.

To use the terminal, we type commands at the blinking prompt and press Enter. Try typing `pwd` and pressing Enter. This command will show you the file path for the working directory that your terminal is currently living in. Now type `ls` and press Enter. You should see a list of all the files in that directory. Last, we'll use the `echo` command to send a greeting. `echo` is a command that will print your chosen line of text back to the terminal:

```bash
$ echo 'Hello, world!'
Hello, world!
```

If all seems to be working correctly, let's get started!

## Navigating in the terminal

To get started in the terminal, we'll create a new directory (folder) to experiment in. The Linux command for creating new directories is `mkdir`. Type `mkdir sandbox` and press Enter; this will create a new directory called `sandbox`.

![](img/fb76008333fb7aef815b136f9f1afe5f_35_1.png)

Once this directory is created, we will want to move into it. Use the `cd` command to change directory. If we want to move into our new `sandbox` directory, we type:

```bash
$ cd sandbox
```

If you type `pwd` and press Enter again, you will see that you are now inside the `sandbox` directory.

We refer to `mkdir` as a "command", but it is actually a program in its own right. Indeed, the basic mode of operation for the terminal is: when the user types the name of a program, run that program. Programs can take in arguments on the command line (for example, the `sandbox` in `mkdir sandbox`), which affect their behaviour.

As we will see later, these programs can be combined together to make a powerful language in which the programs take on the role of commands. We can use this language to write scripts to automate repetitive tasks.

Our new directory is currently empty. Indeed, if we now type `ls` at the command line and press Enter, we get no output. In order to illustrate various commands, let's create some files in the directory. We'll use the `touch` command to create some empty files:

```bash
$ touch email01.txt email02.txt email03.txt
$ touch work01.txt work02.txt work03.txt
$ ls
email01.txt email02.txt email03.txt
work01.txt work02.txt work03.txt
```

If we want to, we can delete files with the `rm` command: type `rm work03.txt` to delete that file.

The files created by `touch` are empty. If we want files with some content to them, we'll need to use different tools. If you like, you can use a text editor to create your own files to experiment with, but in this tutorial we shall get a text file from the internet using the `wget` command.

There is a chance that `wget` is not installed on your system. Try typing `wget` at the command line: if you get a 'command not found' error, then you will need to install it using your distro's package manager.

## Combining commands

Once you have `wget` installed, type `wget https://www.gutenberg.org/files/2701/old/moby10b.txt` and press Enter. This will download the text of the novel Moby Dick from an online public-domain repository. You can use the same command to download any file on the world wide web. You might like to type `ls` again, to make sure that this text file is now in your working directory alongside the other files we just created using `touch`.

If we want to delete a directory, we can use the `rm` command. Note, however, that this only works for directories that are empty:

```bash
$ mkdir new
$ touch new/file.txt
$ rmdir new

Above The terminal emulators available for Linux come in all sorts of sizes and colours. You might have more than one installed on your system

$ rmdir: failed to remove 'new': Directory not empty
```

In order to delete a directory that contains files, we can use `rm -rf`. For example:

```bash
$ rm -rf new
$ ls
email01.txt email02.txt email03.txt
moby10b.txt work01.txt work02.txt
```

This is a new way to use the `rm` program. The `-rf` part is called a "switch" or a "command-line option" and it causes `rm` to act in a different but related way. Whenever you see one or two dashes followed by one or more letters in a Linux command, you are looking at a command-line switch. `-rf` contains two letters, which are actually two separate command-line switches: `r` tells the program to remove a directory and all the files in it recursively, while `f` is short for "force". If you miss out the `f` and write `rm -r new`, then `rm` will sometimes prompt you to ask if you really want to delete those files. If you trust yourself not to delete the wrong thing accidentally, you can save yourself a bit of time by using `rm -rf`.

Most Linux commands have switches that can change their behaviour. For example, `echo -n` print the phrase without starting a new line at the end. So far, we have seen examples of individual commands, but the true power of the command line becomes apparent when we combine two or more commands together.

## UNIX is an IDE

One school of thought holds that "UNIX is an IDE". The idea is that, by running commands in one or more terminals, you can replicate the same functionality that you might see in a more advanced IDE such as Eclipse. You can run editors such as `nano` and `vi` in the terminal, as well as programming tools such as `gdb` and debuggers. If you throw in a few shell scripts to tie things together, you can program efficiently without leaving the terminal.
