TLBs store virtual address (VA) to physical address (PA) translations within microprocessor cores after the core has performed a ‘page walk’ off the page tables representing the virtual memory areas (VMAs) in use by the running process (known as a ‘task’ within the kernel). When a process switch occurs, it is necessary to ensure that stale translations aren’t seen by the new one, so a TLB ‘invalidate’ is performed. This was traditionally expensive on x86 (as opposed to modern alternatives, such as 64-bit ARM), but is less so with the enablement for PCID (process context ID) tag support in the TLBs, which allows for translations of two different address spaces to exist independently at the same time without conflicting.
One of the most interesting questions is whether Linus will decide to merge the initial patches for the RISC-V architecture. We covered RISC-V in the last issue. Version 4 of the enablement patch for the new architecture was posted by Palmer Dabbelt, incorporating all the existing feedback comments that had been given so far. While the support isn’t complete (it doesn’t provide actual drivers for specific real ‘machines’), it does form the basis for what can be used to enable actual platforms later. As of this writing, it has not been merged into Linus’s tree for Linux 4.13.

# ## Memory and scheduler work

Jérôme Glisse has posted another iteration of his work on cache coherent device memory (CDM), which layers upon his existing work on HMM (heterogeneous memory management). The idea of CDM is to provide a generic means for Linux to handle ‘coherent’ memory – that is to say, memory which behaves as normal RAM and whose contents can be shared between different devices and cores without getting out of sync – present on plug-in adaptors, such as certain future graphics cards and workload accelerator modules in servers.
The AMD team have posted updates to its Secure Memory Encryption and Secure Encrypted Virtualization patches. SME can be used to ‘mark individual pages of memory as encrypted through the page tables. A page of memory that is marked encrypted will be automatically decrypted when read from DRAM.’

The technology allows users (especially, data centre operators) to ensure that data is not only encrypted at rest (on disks), but also even whenever it leaves the microprocessor. Thus, a chain of trust can be established between an end user running a virtual machine supporting Secure Encrypted Virtualization (SEV) and AMD (though various additional capabilities built into the chip) in such a way that the data centre hosting company running the VM is unable to introspect the content of the running VM’s memory. I look forward to having such a feature for my cloud VMs.
Nicolas Pitre is working on a ‘scheduler tification’ patch series that aims to ‘[make] it possible to configure out some parts of the scheduler such as the deadline and real-time scheduler classes’. The Linux scheduler code is what determines when it is time for the system to switch from running one process (known as a task within the kernel), to another.
On a modern multi-core system, there may be many processes actually running at a time, but there are rarely enough CPU cores even now to actually execute every task simultaneously. Instead, the illusion of multitasking is provided by means of the scheduler rapidly switching from one process to another. Nico aims to make it possible to shrink the scheduler code for use in very small embedded systems, where some of the normal features aren’t required. This could be true, for example, in some of the larger IoT devices on the market.
