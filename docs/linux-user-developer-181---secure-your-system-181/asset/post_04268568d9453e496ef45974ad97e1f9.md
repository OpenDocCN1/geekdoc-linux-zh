
# AWS for Linux

## Getting started as a host

AWS provides a number of ways to host web servers within its system, from high-end EC2 instances to the bargain-basement Lightsail product.

![](img/fb76008333fb7aef815b136f9f1afe5f_57_0.png)

## EC2 / Lightsail

Originally announced in November for the main US region, but now available more widely (including in the London region), Lightsail is Amazon’s defence against providers such as Linode or DigitalOcean (see p. 63) who offer ultra-cheap hosting. Lightsail starts at $5 a month, with the first month free. Costs scale up as storage, memory, bandwidth allowance, and CPU power increase, but tiers are typically in line with rivals.

Creating a Lightsail instance is easy. The control panel is separated from the main AWS administrative interface, and setup is as simple as choosing an instance size, selecting a region and availability zone, defining a SSH key pair and an optional launch script, before finally choosing either a bare OS (Ubuntu or Amazon Linux) or a prepared stack such as WordPress, LAMP, and Magento, and so on. Press the ‘Create’ button and your instance will start. After which you can configure the firewall, take snapshots, and view various metrics. A web-based SSH console is also provided. You can assign a static IP to your instance, which is floating – if you spin up a new instance, you can change where the IP points on the fly. Static IPs are free as long as they’re attached to an instance.

### Understanding the EC2 process helps comprehend how Lightsail is working behind the scenes

EC2 (Elastic Compute Cloud): EC2 servers are created using Amazon Machine Images (AMIs), which can be created and managed manually or selected from the AWS Marketplace. When creating an instance in EC2, a huge number of different instance types are available, each with different numbers of vCPUs (virtual CPUs), memory, storage types, network speeds, and optimizations. Of course, the higher the spec you choose, the more you will pay. Some instance types have local storage (e.g., the i3.large instance is a powerful type with a 475GB SSD attached), while others use EBS (Elastic Block Storage). EBS provides persistent block storage for your instance, automatically replicated within your availability zone to protect against hardware failure. Magnetic, SSD, and high-performance versions are available – again, of course, with varying costs. After selecting your machine type, you'll be prompted to configure an IAM role (that is, who has access) and also which VPC you wish the machine to be in. A VPC is a virtual private cloud dedicated to your AWS account. One is created by default, but you can create multiple VPCs. After your EC2 instance is created, it will be assigned an IP for external access (subject to your security group config), or you can assign it an 'Elastic IP' which, as the name suggests, is an IP that can be assigned to any instance. Understanding the EC2 process helps to comprehend how Lightsail is working behind the scenes. Each size of Lightsail instance is equivalent to an EC2 instance, storage in Lightsail is a specific size of EBS volume, the static IP is an Elastic IP, and the preconfigured OS or application stacks are AMI images. The benefit of Lightsail is a fixed cost, a barrier to entry to AWS for many users. What if you have resources in both Lightsail and other AWS services – can they communicate? Yes: in your Lightsail configuration you'll see an option for 'VPC peering' which enables intercommunication between Lightsail (which has set up another 'hidden VPC' behind the scenes) and your configured VPC.

> The Lightsail product is designed to be accessible and, as such, has a stripped-down console – a good starting point with AWS!

## Microsoft Azure

There are only a handful of players approaching AWS's scale in the market – one of those is Microsoft, with its Azure platform. Microsoft Azure was announced in October 2008 and, like Amazon's service, has grown hugely thanks in part to Linux. Azure offers over 600 services, including virtual machines, serverless applications, file storage, database services, and messaging systems. Azure is available in 38 regions around the world, two of which are based in the UK.

## Choose your database

Once you've got a web server up and running, the next thing you'll want to think about is a database. As is often the case with AWS, there are a lot of different offerings to ponder. If you're looking for a traditional relational database on a managed service, you'll want to use Amazon RDS (Relational Database Service) which offers many of the most popular relational database engines. If you're building a data warehouse, Amazon Redshift might be what you need. Amazon DynamoDB provides a high-performance NoSQL database, and Amazon Elasticache provides in-memory caching via Memcached or Redis. You can host on your own EC2 instances too, but you won't then enjoy the managed nature of the Amazon services. One final option is third-party companies that host databases within the AWS cloud, such as the IBM-backed compose.io. Amazon RDS is incredibly useful because it takes away most of the difficult or tedious management tasks of a relational database. First and foremost, RDS manages backups, patching, automatic failure detection, and recovery. RDS can automatically provision high availability with multiple instances in multiple availability zones, providing peace of mind with minimal effort. If you roll your own server, you are forced to scale instance sizes to increase the server power, but RDS allows you to increase CPU, memory, and storage independently. Best of all, RDS is very cost-competitive with setting things up yourself – so why wouldn't you? The only thing RDS doesn't provide is shell access to the server, although you probably shouldn't need it. You can use the tools you're familiar with to manage the RDS database, as well as benefiting from being within AWS with CloudWatch monitoring, VPC-based security, and multiple region availability.

### Database engines supported

- **01 MySQL**
  - MySQL is one of the most widely used databases worldwide and forms a key component of the LAMP stack.
- **02 Aurora**
  - Aurora is AWS's high-performance, customized version of MySQL, and is fully compatible with no code changes required.
- **03 MariaDB**
  - Like Aurora, MariaDB is an enhanced, drop-in replacement for MySQL. It is maintained by the original developers of MySQL.
- **04 PostgreSQL**
  - Postgres is a complex, extensible, object-relational database management system, with excellent support for advanced data types and functions.
- **05 Oracle**
  - The Oracle database, which is closed source, is a business heavyweight, and its care is required for many companies migrating their data into RDS.
- **06 Microsoft SQL Server**
  - Microsoft SQL Server is the platform of choice for many Windows-based developers – all versions are offered by AWS, from 'Web' upwards.

## Quick Tip

**Snapshot backups**
If you are running Lightsail instances, you can manually Snapshot as required for backup. AWS also supply an 'auto snapshot' template, for simple daily snapshots and a custom retention period.

## File storage

Amazon S3 (Simple Storage Service) was an original AWS product offering, but now forms part of a suite of file storage products.

### Quick Tip: Command-line tools

As well as providing connectivity via APIs and management via the web console, AWS provides powerful yet accessible command-line tools in the form of aws-cli and aws-shell.

When AWS first launched, the S3 storage service was the headline offering. Before then, if you needed online storage you'd provision it in chunks – maybe get a server with a few terabytes of storage and when you ran out of space, get another one. S3 changed that by employing the now familiar model of only charging for what you use – and being very competitive when doing so. Amazon S3 is a simple object store. It is secure, 99.99999999% durable, and scales past tens of trillions of objects. S3 is ideal for backup and recovery, tiered archive, or user-driven content (like photos, videos, music, and files). Objects are uploaded and retrieved using the AWS APIs, or exposed directly to the internet via Amazon's CDN (content delivery network) service, CloudFront. S3 objects can be automatically distributed between availability zones and regions, and versioning can be employed to add extra resilience to the platform. Although S3 pricing is extremely competitive, you may find yourself uploading objects that you don't need to access very often – for example, if you are using the service for backup. In order to save costs in this kind of scenario, Amazon offers an "infrequent access" tier of S3. This costs approximately half the price of regular S3 for the storage itself, but each request to the object will be considerably more expensive. For objects that are required even less frequently, Amazon offers a special version of S3 called 'Glacier'. Although it is very cheap, retrieving data from Glacier is much slower. Data retrieval is divided into three tiers, which can take from a few minutes to several hours.

Alongside EBS for attached instance storage and S3 for resilient object storage, Amazon offers Amazon EFS (Elastic File System) which provides simple, scalable file storage for use with Amazon EC2 instances in the AWS Cloud (or, via VPC peering, Lightsail instances). EFS delivers a file system that grows and shrinks capacity automatically, and provides high throughput with consistently low latencies. EFS is designed for high availability and durability, and provides performance for a broad spectrum of workloads and applications, including big data and analytics, media processing workflows, content management, web development, and more.

## How To: AWS Elastic Beanstalk

![](img/fb76008333fb7aef815b136f9f1afe5f_59_0.png)

- **01 Deploy Beanstalk**
  - With Elastic Beanstalk, you can deploy, monitor, and scale an application quickly and easily. To deploy an existing web app, you will need to create an application source bundle and create a new Beanstalk application. If you want to create a Beanstalk deployment using an existing Git repository, then you can do so using the CLI tools. A number of sample applications are also included so you can try out the process.

![](img/fb76008333fb7aef815b136f9f1afe5f_59_1.png)

- **02 Source bundle**
  - An application source bundle consists of a single ZIP or WAR file, less than 512MB, containing your application's source code. This will be automatically deployed by Elastic Beanstalk. Your source should be in the root directory, and you can also include an `extensions` directory containing one or more Elastic Beanstalk `.config` YAML configuration files, for configuring environment options.

![](img/fb76008333fb7aef815b136f9f1afe5f_59_2.png)

- **03 Name and platform**
  - In the first step of the Elastic Beanstalk process, you're prompted to provide an app name of up to 100 characters. Next, you select the platform your code runs on – sample platforms include Python, Ruby, Tomcat, Go, Java, Node, PHP, Packer, and .NET as well as several Docker options and generic Docker containers. After selecting a sample app or uploading your code, you can create your app here or configure options.
