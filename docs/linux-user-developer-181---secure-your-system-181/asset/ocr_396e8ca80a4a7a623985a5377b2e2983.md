# Google Cloud Platform

![](bbox=[0.1, 0.2, 0.16, 0.23])

You would expect Google to have a presence in the cloud hosting space – and it does with Google Cloud Platform. As with AWS and Amazon, Google Cloud Platform is based on the same infrastructure used to power core Google services such as Search and YouTube. Key products include Compute Engine (equivalent to EC2), Cloud Functions (equivalent to Lambda), Cloud Datastore (equivalent to DynamoDB) and Storage (equivalent to S3).

# Free tier

Amazon’s free tier is a great way to try out services and each of the storage options above is included in the offer. Amazon will provide 30GB of Amazon Elastic Block Storage in any combination of General Purpose (SSD) or Magnetic; 1GB of snapshot storage; 5GB of Amazon S3 standard storage with 20,000 Get Requests and 2,000 Put Requests; plus 5GB per month of Amazon EFS capacity, free of charge for the first year.

As well as providing the first month free on Lightsail (understandably, there’s no longer-term free tier on the Lightsail servers per se), Amazon includes EC2 in the free tier. For the first year, you can use 750 hours per month (enough to run continuously) of Amazon EC2 Linux or Windows t2.micro instance usage (1GiB of memory and 32-bit and 64-bit platform support), together with a load balancer to sit in front of the instance if desired, with 15GB of transfer bandwidth. The database offerings are similarly generous – 750 hours per month of Amazon RDS Single-AZ db.t2.micro instances for running MySQL, PostgreSQL, MariaDB, Oracle BYOL or SQL Server (running SQL Server Express Edition) with 20GB of storage and 20GB of backup space and 750 hours of Amazon ElasticCache cache.

# 04  Additional options

In the additional options screen, you are able to select a basic low-cost configuration (which is eligible for the free tier) or manually configured more advanced setups such as high availability or fully custom. The basic free tier will deploy 64-bit Amazon Linux (and in our example PHP-7); if you require a different version, you can select ‘change platform configuration’ and choose from the list.

![](bbox=[0.355, 0.61, 0.59, 0.745])

# 05  Instances and capacity

Sensible defaults are selected for the various categories of options. If you need a more powerful server, you can select this in ‘Instances’. The ‘Capacity’ section allows you to specify a preferred number of instances and whether you wish to deploy across multiple availability zones. A load balancer will be automatically provisioned and your application updates can be deployed either immediately or on a rolling basis.

![](bbox=[0.635, 0.61, 0.87, 0.745])

# 06  Network and database

By default, the ‘Network’ section of the configuration will launch your instance into the default VPC. If you want to use a specific VPC, you can configure it here. Elastic Beanstalk can also deploy RDS database servers via the ‘Database’ section, with engine, size, credentials, retention and availability policies also configurable here. After deployment, the RDS console can be used to change these settings too.
