## About web applications

If you are not familiar with web applications, you might be wondering what one is. A web application (or web app for short) is a client-server software application where the client part runs on a web browser. Webmail, instant messaging services, online stores and many other kinds of applications are web applications. So, the rest of this tutorial will teach you how to create such applications where the server part is developed in Erlang and the client part is displayed on your favourite web browser.

Erlang allows you to quickly write a simple web server that can be used for testing your web apps and discovering any connectivity issues between your machine and the one that will host the web app. Therefore, this section will present a simple Erlang module that will implement a naive web server that just prints the ‘Hello World!’ message all the time. However, using such a simplistic Erlang web server on production systems might not be the best choice.

## Create a web server for testing

The name of the Erlang module will be *naiveWS* and will be saved as *naiveWS.erl*. You can see its Erlang code in **Figure 1**, which is mainly a simplistic concurrent TCP server.

```erlang
-module(naiveWS).

open_connection(Port) ->
    spawn(fun() -> {ok, Socket} = gen_tcp:listen(Port, [{active, false}]),
        loop(Socket) end).

loop(Sock) ->
    {ok, Conn} = gen_tcp:accept(Sock),
    Handler = spawn(fun() -> handle(Conn) end),
    gen_tcp:controlling_process(Conn, Handler),
    loop(Sock).

handle(Conn) ->
    gen_tcp:send(Conn, reply("Hello World!\r\n")),
    gen_tcp:close(Conn).

reply(Str) ->
    B = list_to_binary(Str),
    ["Status: 200 OK\r\n" | "Content-Type: text/html;\r\n" | "Content-Length: " ++ Str ++ "\r\n"],
    [Size(B), B]].
```

**Above** The Erlang code of *naiveWS.erl* that implements a very simple yet concurrent web server using *gen_tcp:listen()* and *spawn()*

The *naiveWS:open_connection()* function requires just one parameter, which is the port that the web server will use. Therefore, you can start the web server by executing the following command in the Erlang shell after compiling *naiveWS.erl*:

```bash
2> naiveWS:open_connection(1200).
<0.64.0>
```

Using the *wget* utility to test the web server is as simple as executing the next command:

```bash
$ wget 127.0.0.1:1200/
--2017-05-29 10:12:08--
http://127.0.0.1:1200/
Connecting to 127.0.0.1:1200... connected.
HTTP request sent, awaiting response... 200 OK
Length: 12 [text/html]
Saving to: ‘index.html’

index.html              100%[===========================>]       12  --.-KB/s    in 0s

2017-05-29 10:12:08 (2.86 MB/s) - ‘index.html’ saved [12/12]
```

The generated output will verify that the web server works as expected.

The contents of the *index.html* file are the following, which means that both the web server is working and the desired message was delivered successfully:

```html

```


## Use Cowboy, an HTTP server

Written in Erlang, Cowboy is a small and efficient HTTP server for Erlang, OTP and Elixir projects. Cowboy supports many kinds of handlers, including REST, WebSockets and HTTP ones. Although this tutorial is not about Cowboy, it will deal with its installation process in the next section because you might find it a little perplexing if you are not used to installing external Erlang modules. You can find more information about Cowboy at https://github.com/ninenines/cowboy and at the website of Nine Nines: https://ninenines.eu.

> As the whole process will be pretty complex, you will need a build system to make your life easier: in this case, the Erlang.mk tool

### The Hello World! program

Enough with the theory – it is now time to learn how to install Cowboy and watch it in action!

This section will present a simple web app in order to better understand how the whole Erlang with Cowboy thing works. As the whole process will be pretty complex, you will need a build system to make your life easier – in this case the build system will be the Erlang.mk tool and will be the first thing that you will need to download when developing a project that uses Cowboy. You can find more information about the Erlang build system at https://github.com/ninenines/erlang.mk.

But first you will need to create a directory that will keep all the files of the project – in this case the name of the project is `hw`, so the directory name will also be `hw`, which you can create by executing the `mkdir hw` command. Then you will need to execute `cd hw` to actually go into that directory.

Now follow the next steps in order to create a new Erlang project that will use Cowboy:

```bash
$ wget https://raw.githubusercontent.com/ninenines/erlang/master/erlang.mk
$ make -f erlang.mk bootstrap-rel
$ make
```

![](img/fb76008333fb7aef815b136f9f1afe5f_51_0.png)

**Above** A part of the `hw` project initialisation process that illustrates how you can use Cowboy in order to develop a web application in Erlang

Figure 2 shows some of the results you will get on your screen after executing the previous commands. So far, you have created the skeleton of a new Erlang project and a dump shell script that you can run as `.rel/hw/_rel/release/console` to make sure that everything is fine.

Now it’s time to actually install Cowboy by making changes to the Makefile. The final version of the Makefile will be as follows:

```makefile
PROJECT = hw
PROJECT_DESCRIPTION = A Hello World program
PROJECT_VERSION = 0.1.0

DEPS = cowboy
include erlang.mk
```

All the work is done by the `DEPS = cowboy` line, which will order the build system to download and install Cowboy. Then you will need to create a new file named `hw.app.src` inside the `src` directory (if it is not already there – you can see `hw.app.src` by looking at the source code that accompanies this tutorial). Now, if you execute the make utility, the build system will take care of the rest! If the last line of the output is `release-1.tar.gz successfully created` you are good so far.

Next, you will need to edit some of the existing files in order to define the URLs that your web app will support, as well as adding the required Erlang code that implements the desired functionality of the web app. First, you will edit `src/hw.app.erl`. Figure 3 shows the final version of the `src/hw.app.erl` file – this is the first place you should visit for finding out more about the list of supported URLs as well as the port number the Cowboy server will listen to. However, we are not done yet, as we will have to create a plain HTTP handler for the URL:

```bash
$ make new t=cowboy_http m=hw_handler
```

![](img/fb76008333fb7aef815b136f9f1afe5f_51_1.png)

**Above** The Erlang code of the `src/hw.app.erl` file, which is the most important file of the app, because this is where you define the supported URLs of the web app

Please make sure that the name of the handler is in sync with the name you defined in the `hw.app.erl` file.

Last, you will have to open the `src/hw_handler.erl` Erlang file, which was created by the previous command, in order to change the implementation of the `handle()` function. After editing, the implementation of the `handle()` function of the `hw_handler.erl` module should be as follows:

```erlang
handle(Req, State=#{state()}) ->
    {ok, Req2} = cowboy_req:reply(200,
```
