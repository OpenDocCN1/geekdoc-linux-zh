
## About WebSockets

WebSockets are part of the HTML5 standard and have nothing to do with Erlang. However, WebSockets offer bidirectional asynchronous sockets that allow browsers to communicate with the external world, which also includes programs written in Erlang! Being asynchronous means that WebSockets send data out without necessarily waiting for a response. As Erlang is also asynchronous by design, WebSockets are a perfect way to communicate with Erlang programs.

When developing an Erlang application that uses WebSockets, you need three components for things to work: a web browser that will run some of the code, an Erlang application (A) that executes some Erlang code and another Erlang application (B) that can communicate with the WebSockets protocol. Erlang application A contains the logic of the web app, whilst will do and the necessary Erlang code for communicating with a database and so on. Erlang application B is what transfers messages from Erlang application A to WebSockets and vice versa.

You can find the RFC document for the WebSockets protocol at https://tools.ietf.org/html/rfc6455.

## AMAZON WEB SERVICES FOR LINUX

**Peter O'Brien** investigates the powerful infrastructure that powers Amazon's services and is available to you via Amazon Web Services (AWS) on Linux for all your individual and company hosting needs.

**T**here's a huge number of options available if you're looking to host services in the cloud, whether it's a website, a database, files or anything you access over the internet. When deciding which service to use, you'll factor in a number of things, such as price, performance, reliability and reputation. When it comes to the latter, few services are more respected than Amazon Web Services, and with good reason. When was the last time Amazon's website went down? If it can host at scale for the amount of traffic it receives, then it can probably meet your requirements too. Traditionally, cost has been a barrier to entry for AWS for many people, but recent changes mean it's easier than ever to try out the service.

Amazon Web Services has been around for many years, although it has undergone — and continues to undergo — ongoing changes and improvements. The company was initially launched in 2002 with a vision of exposing Amazon's technology and product data to allow third parties to build their own applications. This concept was refined in 2003 with a proposal to build out the infrastructure used for retail operations, to be offered as an 'infrastructure as a Service' product that could potentially provide an additional source of revenue for the firm. The idea panned out and with massive growth since its full launch in March 2006, AWS is set to net Amazon around $13 billion in 2017.

As well as the vast range of interoperating services that AWS offers, one of its key strengths is that it is available in many different locations. The service offers six regions in North America, one in South America, three in Europe (including London) and six in Asia Pacific. For a company looking to offer services to users across the globe this is invaluable, as well as providing resilience, courtesy of the ability to host services and data in geographically remote locations. In addition, each region has multiple 'availability zones', which consist of one or more discrete data centres, each with their own power and connectivity. The availability zones are intentionally isolated from each other to prevent outages spreading between zones. AWS also offers 54 'Edge' points of presence worldwide, which can be used to host content closer to customers.

AWS services are typically on-demand and charged based on usage (although discounts can be achieved by pre-reserving resources). A free tier option is available for new users, which offers a basic level of service for many of AWS's services free of charge. More than 70 services are currently offered by the company across a range of technologies and are accessed via powerful RESTful APIs, with access controlled by IAM (identity and access management), which sits at the heart of AWS and allows extremely granular control of access.

One of the key advantages of AWS's vast infrastructure, and the pay-per-use model, is that it provides the ability to rapidly scale your provisioned resources. If you are managing server workloads that vary in terms of required resource, or you want to be able to handle a sudden influx of traffic, AWS is a good fit. The best way to understand how AWS works is to visualise the services as a set of building blocks. Each service works independently, so you can pick and choose which of the huge number of available products you need to serve your needs. As well as being completely independent however, services are designed to interoperate well with each other, sharing attributes such as common APIs, naming conventions, the aforementioned IAM authentication system and connectivity concepts. Although Amazon does provide extensive web services that will allow you to control any aspect of your infrastructure, you're not compelled to use them unless you choose to – the firm also provides tools and libraries for a number of languages, as well as a full-featured administrative console where, again, services are presented individually but share many common interface concepts.

### Controlling costs

One of the great fears of using a cloud service such as AWS is cost. If you exceed the free tier, or if your infrastructure suddenly scales up, how much are you going to pay? How can you know in advance how much the system you are building will cost? AWS provides a simple cost calculator to help you predict pricing, but there are a few key concepts to understand first. Prices (which can vary slightly from region to region), use metrics such as time (for example, the number of hours a server is online), volume (such as data transferred), count (when using a service such as message queuing) or time-space (such as amount of data stored for a period of time). Although costs can be a worry, AWS provides excellent tools for managing spend. As well as the billing features, the AWS‘Cost Explorer’ enables you to drill down on where your spend is going, and powerful billing alerts (driven by the ‘CloudWatch’ system that is used for monitoring across the AWS system) can allow you to know when costs are exceeding a predefined limit. Security is always a major concern and it is another reason why companies turn to AWS. Access to the service, both in regard to physical data centres and the network itself, is strictly controlled, monitored and audited by the company. You can be confident that it has its house in order and it provides the tools to ensure that you can do the same. As well as using identity and access management (IAM) to create very fine-grained permissions to AWS resources, you can also apply ACL-type permissions to your data (and ensure it is encrypted at rest) to configure a VPC (virtual private cloud) to isolate your resources from other virtual networks or the internet. In addition, you can configure security groups to provide a virtual firewall controlling in and outbound traffic to your servers and specify a key pair when launching virtual servers, which is used to encrypt your login information, ensuring only those with access to your private key can access your instances.

### TIMELINE

- **LATE 2003**: AWS as we know it now proposed. Although the firm couldn’t have known how quickly AWS would grow, Amazon realised that offering its own resilient infrastructure to others would be valuable.
- **MARCH 2006**: AWS relaunched with S3, SQS and EC2. The three original services launched as ‘Amazon Web Services’ still underpin the core system functionality today with file storage, messaging queues and server instances.
- **NOVEMBER 2010**: All Amazon sites hosted on AWS. Surprisingly, it took nearly four years for Amazon to migrate its own services to the AWS platform, but that move did show huge confidence in the project.
- **APRIL 2013**: Amazon offers certification. Engineers working with AWS services can complete Amazon certification in a range of areas, providing professional validation of their AWS skills.
- **APRIL 2015**: AWS turns first $265 million profit. Amazon is never shy of investing huge sums of money before eventually turning a profit; AWS took nearly ten years to break even.
- **DECEMBER 2016**: AWS London region launched. AWS now offers many of its services out of London, with the city joining Frankfurt and Ireland as a European location.
