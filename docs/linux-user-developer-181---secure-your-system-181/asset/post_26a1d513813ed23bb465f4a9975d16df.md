We are all quite acquainted with the concept of the three As regarding access to information (or ATAWAD): any time, anywhere and from any device. Virtual Desktop Infrastructure (VDI) is just a manifestation of such a promise: nowadays it would seem pointless to have a whole computer classroom with separate images deployed on every single box. We are all living in the era of the cloud, after all. Enter VDI. But, of course, this is not the only use we can find for VDI technology. Pen-testing, malware analysis and forensics are also well-known scenarios where a VDI broker can save the day! RAVADA VDI is one such VDI framework, ready to install and use. Its back-end has been designed and implemented in order to allow future hypervisors to be added to the framework, thanks to its REST API. This is great because you don't need to worry too much about KVM falling off a cliff some day: RAVADA VDI will certainly support the trendy hypervisor of the future. Deploying this framework will help you design and manage pen-testing training scenarios where you will be able to test any crazy, out-of-the-ordinary proof of concepts (PoCs) without damaging a single system.

As of this writing, RAVADA VDI only supports the KVM hypervisor, which means you need to load the proper module for your kernel. So, if you have an Intel-based processor, run (as root): `modprobe kvm-intel`. For AMD-based processors, run: `modprobe kvm-amd`.

From an end-user's point of view, the only requisites are a web browser and a remote viewer supporting the SPICE protocol (for example, `apt-get install virt-viewer`).

## Nested KVM

You can set up the framework on a computer with nested KVM capabilities. This way you can try RAVADA VDI before deploying it. You can create a new VM using libvirt and its `vir-manager` tool and then install RAVADA VDI on that VM. Make sure your processor does support nested KVM first: `cat /sys/module/kvm_intel/parameters/nested`. An output of 'Y' or '1' means you are good to go. If you don't have nested KVM capabilities, don't panic: there's still a chance you can have them: unload the kvm module and then reload it with the `nested=1` parameter:

```
modprobe kvm-intel nested=1
```

## Install and use RAVADA VDI on Debian

If you want to use this VDI broker on Debian Jessie, you need to make some changes first (see Resources). Note that RAVADA VDI is yet to be tested on Debian Stretch, which was released on 17 June.

Clone the repository and start looking at its nuts and bolts. The code is written in Perl 5 and AngularJS. The development team behind RAVADA VDI has implemented a bunch of tests to make sure everything is in order before releasing a new version. The first thing you need to do is clone it:

```
git clone https://github.com/UPC/ravada.git
```

Now install its prerequisites according to the documentation. Within the *ravada* directory, run: `perl Makefile.PL` and then execute all the tests as root: `make test`. RAVADA VDI can be installed either from its sources or by using a DEB package. To generate the package, there’s a Perl script within the **deb** directory; try it out: `deb/debianize.pl`.

## Capture the flag

When it comes to pen-testing, training is mandatory. There are a bunch of virtual machines and online systems out there already prepared, to test your skills without breaking the law. That’s fine, of course, but why not think bigger? By using a VDI broker, you can set up an environment where every single pen-tester trainee is using their own separate VDI to perform different tests and attacks against a shared virtual machine. The idea is to create a new VM within RAVADA VDI that the trainees will use with all the necessary tools and then make it public. This way, every authenticated user will be able to connect to it by means of the SPICE protocol (see Resources).

Thanks to the QCOW2 format, once you have created a new VM and made it as a base image, additional instances per user will occupy much less disk space than the original VM. As of writing, RAVADA VDI has not yet implemented an option within the GUI to add new VDI XML definitions nor ISO images, but it is not that bad! Next, you will prepare your VDI framework to accommodate Kali Linux (this will be your trainees’ virtual desktop).

## Create the pen-testing machine

Download Kali Linux 64-bit (see Resources) and save it to `/var/lib/libvirt/images` on your RAVADA VDI server. Compute its SHA256 and make sure it matches the one on the project’s website. Then, you will need to execute an INSERT SQL statement in order to update the table `iso_images` in the MySQL database server. The INSERT statement is pretty straightforward: every field in the table is fairly self-explanatory. Set the value for the field `file_re` as the name of the ISO, fill the fields `md5_*` with NULLS and don’t forget to set `sha256` with the corresponding hash. Finally, `sha256_url` should point to `https://codimage.kali.org/current/SHA256SUMS`.

The second step is to prepare two XML files for the new VM. The first will hold all the machine’s definitions – number of processors, network interfaces, USB channels and so on. The second is the volume definition. Copy these two files from any other VM and rename them: `cd /var/lib/ravada/xml/; cp jessie-amd64.xml kali-amd64.xml; cp jessie-volume.xml kali-volume.xml`. Using your favourite ASCII editor, edit `kali-amd64.xml` and make sure to change both disk and CD-ROM virtual disks definitions accordingly:

```
<source file='/var/lib/libvirt/images/kali64.img'/>
<source file='/var/lib/libvirt/images/kali-2017.1-amd64.iso'/>
```

Next, open your RAVADA VDI web interface and navigate to Admin Tools > Machines and click New Machine. Make sure you select the ‘Kali Linux’ ISO image in the dropdown list. Once you are happy with the VM settings, click Create. Now wait a while until the machine is created. You can start the machine using the ‘Start’ button, and connect to it by clicking ‘View’. Proceed with the normal installation of Kali and add any additional packages or tools you think your trainees will need. Once you think the machine is ready for deployment, check the Base and Public checkboxes: from now on, any registered RAVADA VDI user will be able to use their own separate Kali Linux VDI instance, running independently from the others.

## Open source VDI solutions

Apart from RAVADA VDI, there is a bunch of free (some of them open source) VDI projects out there. Most of them are based on KVM (http://bit.ly/VDI-KVM). RAVADA VDI works at not being attached to any particular hypervisor; as of this writing, it only supports KVM, but additional hypervisors are on the roadmap (such as LXDI). So if you feel like giving those guys a hand, don’t be shy.
