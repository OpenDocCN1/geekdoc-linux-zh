The Connection class connects to the platform where your relational database resides. To obtain a connection object, use the DriverManager's getConnection method:

```
Connection con =
DriverManager.getConnection(
    "jdbc:as:400://your400domainOrIP", "user", "password");
```

The first parameter of getConnection has three sections: protocol, subprotocol, and data source name. The protocol is always jdbc, but the subprotocol varies with each JDBC driver. (By the way, you have already used protocols, in URLs. The URL http://www.mcpressureline.com has a protocol of http, no subprotocol, and a domain name of www.mcpressureline.com.) For the 100% JDBC driver available from the AS/400 Toolkit for Java, the native JDBC driver from the AS/400 Developer Kit, it's db2. The data source is simply the domain name or IP address of your AS/400. The second and third parameters of getConnection are the user's name and password.

The JDBC Statement class executes the SQL statement mentioned earlier. A Statement is obtained from the Connection object:

```
Statement stmt = con.createStatement();
```

The Statement object has two powerful methods for the execution of SQL statements: executeQuery and executeUpdate. The executeQuery method accepts an SQL SELECT statement as a string, allows the RDS to execute that query, and then returns the set of records from the query. That of records is returned in the JDBC ResultSet object. For example, the following Java statement returns all the records from the invdt1 file, since no WHERE clause is specified:

```
ResultSet rs =
stmt.executeQuery(
    "SELECT * FROM invdt1");
```

# Set Processing

To iterate through the set of records contained in the ResultSet object, use the ResultSet's next method. You can think of next as manipulating a file cursor (except it is actually a cursor). When the next method positions the cursor to the subsequent element of the set, you can use the ResultSet's getter methods to retrieve the values of the fields of a particular record. The getter methods convert the data from the internal format of RDB to Java objects. There is a getter for every data type from DB2/400—too many to cover in detail. For the most part, you will use getString for character fields, and getBigDecimal for packed and zoned values. Each getter method is overloaded to accept two options for parameters. The first option accepts a field name, and the second option accepts a number that represents the ordinal position of the field as it occurs in the SQL SELECT statement.
