Since the primary key of any table is the primary access mechanism, it stands to reason that you should create an index by each file's primary key. The SQL syntax to create an index is as follows:

```
CREATE [UNIQUE] INDEX index name ON table name (column name[,])
```

Here are the SQL statements to create indexes over the three accounts-receivable tables:

```
CREATE UNIQUE INDEX invoice01 on invoice (InvoiceNo)
CREATE UNIQUE INDEX invoiceDetail01 on invoiceDetail (InvoiceNo, LineNo)
CREATE UNIQUE INDEX customer01 on customer (CustNo)
```

The UNIQUE keyword tells the RDB to disallowed duplicate key values. If you create an index over another column (or columns) of a table where the key of that index is not unique, you would omit UNIQUE.

# # Populating the Database

Adding rows to a table is done with the SQL INSERT command:

```
INSERT INTO table name VALUES (value1[,])
```

To add the rows displayed in the database Table 8.1, you would use the following commands:


The SQL keyword NULL means the value has explicitly not set.

# # Querying the Database

Companies consider the information in their databases to be a corporate asset. Much of the value of a database comes from the ability of individuals and automated processes to query it so that a business process can act on the results of query. For example, an automated process might print labels from information stored in a product catalog so a company's marketing department can send mailers to all customers who ordered more than $100 worth of merchandise in the past year. A salesperson, on the other hand, might want to interactively view information about a specific customer along with all orders for that customer.

RDB queries are requested via the SQL SELECT statement, in this format:

```
SELECT *|column name[,]) FROM table name;
```
