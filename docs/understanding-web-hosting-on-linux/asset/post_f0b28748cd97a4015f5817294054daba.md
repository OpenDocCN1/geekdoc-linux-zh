For right now, the most important function of the request variable is the getParameter function. This retrieves input values from the HTML form. Before discussing HTML forms, we need to decide the first two statements in PanelServlet's doGet function:

```
response.setContentType("text/html");
PrintWriter out = new PrintWriter(response.getOutputStream());
```

These are pretty much template code; any doGet function that you create should start with these two statements. Both of them use response, which you can think of as a handle to the HTML file containing to the user's request. The first statement, response.setContentType("text/html") says that the HTTP response to the client will contain text-based HTML. The next statement receives a handle to the output stream. It's sort of like setting a format in an RPG screen. PanelServlet uses the output to output an HTML response.

After setting the content and retrieving a handle to the HTML output stream, the doGet function then retrieves the user's HTML form input. By invoking the HttpServletRequest object the getParameter function. The code is fairly self-explanatory, that all of the input fields from the HTML form are retrieved. What you might find odd is if a user did not select one of the checkboxes, the parameter is not available to the servlet. Whenever the getParameter function cannot find a parameter with the name qualified, getParameter returns null for nothing. If you misspell the variable name or use incorrect capitalization, getParameter will also return a null.

Once all are retrieved, the doGet function increments the globalCount variable. The value of globalCount is used to the dynamically constructed HTML response. The response outputs the obligatory tags, such as <HTML>, <HEAD>, and <body>, before it starts to echo the user's values. Note that the println function is passed the variable name and the HTML line. The value for globalCount is then listed with the following statement:

```
out.println("This servlet accessed "+count+"<BR>");
```

The closing tags are added, and the output stream is closed. Figure 7.5 shows a screen of entries to PanelServlet. Note that I entered my name, selected Java as programming languages (personally I'd rather not do RPG and COBOL anymore, said I had more than 15 years experience, and Web. When I clicked Submit, the following URL was passed to my server:

```
http://127.0.0.1:8080/servlet/PanelServlet?name=Don&java=Java&x=15&prof=web&submit=Submit&hiddenField=secret
```

Let's break down that URL and look at the parameters it contains. The question mark of PanelServlet identifies the beginning of what is called the query string. The query string is made of name/value pairs separated by ampersands. The first name/value pair is `name=Don`. The input field will have a value of Don (the & sign is used as a placeholder for space). There are no name/value pairs for RPG, COBOL, or Visual Basic because those boxes were not selected on the form. The query string contains a value for java and then x. The value for x looks a bit: `%20` represents the hexadecimal value of space, since & in a query string normally identifies space. When PanelServlet reads the parameter, the value will be Java. The exp parameter also has a hexadecimal value to represent the greater-than symbol. The values for prof, submit, and hidden field follow.

If Panel.html's `<FORM>` tag used POST rather the query string would not have been in the URL. Instead, it would have been embedded in the HTTP packet. We use the GET method while testing we can clearly see the query string, but change to POST when the code is moved to production. Servlets dont always have to be invoked from a form. When PanelServlet is invoked by the server, it returns the HTML page shown in Figure 7.6. Notice the line "This servlet accessed 101 times." If the Panel.html form was submitted, the response would say "This servlet accessed 102 times." Numerical values come from PanelServlet's globalCount. The value for globalCount is available to all clients, and the doGet method increments it by one. If several clients are invoking PanelServlet, they will use the same value for globalCount and as mentioned earlier, fields are typically used for things like JDBC connections—variables to be shared among Web-browser requests.

## A Servlet Development Environment

The PanelServlet classes are installed and tested with WebSphere server, but because the WebSphere product can be difficult to install, we recommend that you install Tomcat (a simple servlet environment) on your system. Tomcat is an all-Java application server, so it will run on any platform that has a JVM. You can get it from Apache's Jakarta Web site, http://jakarta.apache.com. Click the link to the latest release (currently 4.0.2), and the /bin link, and you will be taken to a directory listing. At first, you may find the long list of files a little confusing. The only file

![](img/069cd06404ac5e90171e6d857bf3ad28_119_0.png)

required to get things rolling is the one that ends *.tar.gz. Once you've downloaded it, log on as root and installation. You'll need to decide where to place Tomcat. As mentioned in an earlier chapter, we recommend you place "optional" software in the /opt directory. Change your current directory to /opt with the **cd** command, and the Linux extraction command, which will look similar to this:

```
tar -xzf <download directory>/jakarta-tomcat-4.0.2.tar.gz
```

This **tar** command extracts the file into the directory /opt/jakarta-tomcat-4.0.2. Since the Tomcat documentation refers to the installation directory as simply jakarta-tomcat, the following little command renames the directory so that the installation matches the docs:

```
mv jakarta-tomcat-4.0.2 jakarta-tomcat_ug
```

The documentation is in the file tomcat.html in the directory /opt/jakarta-tomcat/doc/ugguide (assuming you are using the directory tree described here). Since it is in HTML format, you can open it in your browser.

The last step is to add an environment variable to /etc/profile, so that Tomcat can find itself:

```
export TOMCAT_HOME=/opt/jakarta-tomcat
```

To start Tomcat, simply change your terminal session's current directory to /opt/jakarta-tomcat/bin, and execute its startup script:

```
cd /opt/jakarta-tomcat/bin
sh startup.sh
```
