When open-source developers speak of “free” software, they are referring to the users’ freedom to run, copy, distribute, study, change, and improve the software. To ensure these rights, the FSF created the GNU General Public License (GNU GPL). The GNU GPL is essentially a copyright, but its proponents prefer to call it “copyleft” because it does the opposite of copyrighted software—it increase the rights of users. There are several other open-source software licenses, such as the Open Source Initiative (OSI) and the Apache Software License.

Regardless of the organization, the licenses at the top of every open-source file are relatively similar. As an example, the following is a summary, in everyday language, of the Apache Software License, Version 1.1:

+   1. Don't rip the tag off—Like those warnings against ripping labels off of soap, you're not supposed to delete the copyright off the top of a source file. While you probably won't be willing to sell your sofa soon time, you might well be selling your code. And sooner sooner or later, perhaps a competitor, will recognize code as open-source.
2. If you create code, it gets the label—New code that enhances open-source code gets the same copy copyright. This prevents a vendor from making mild enhancements to an open-source OS or server and calling the whole thing its product.
3. Tell the users where the code came from—All documentation must credit the organization that controls the open-source code.
4. If it breaks, it's not their fault—So don't expect to sue the Apache Software Foundation.

The first two are the big ones because effectively ensure that any software with open-source copyrights will always be open source. The organization that originated the code might die, but the code lives forever.

The last thing to keep in mind about open-source licenses is that they contain no warranty that prohibits anyone from making money off distributing or supporting open-source products. That's how Red Hat, Calder, Debian, and Suisse make their money. One well-known Website, Cheapbytes (www.cheapbytes.com), legally sells a copy of the Red Hat distribution CD, among other open-source software, for a couple of dollars (plus shipping), rather than the $100 or so CD would come from Red Hat itself. Of course, you don't get the Internet and phone support if you purchased directly from Red Hat.

# Linux Today

In late October 1998, two highly confidential Microsoft emails concerning its strategy against Linux leaked to the open-source community. The Open Source Initiative, a nonprofit organization, called them the “Halloween documents” because of the date on which they were received. These documents are accessible today at www.opensource.org/halloween. They clearly show that Microsoft was highly concerned about the threat of Linux specifically, and open in general, to its market dominance. Microsoft noted that IBM was taking a lead role in optimizing the open-source Apache server for NT. The document further stated that the “worst-case scenario” would be if IBM adopted Linux.
