This product enables you to make your desktop "skinnable," allowing you to customize its content. The bloat inherent in the Windows GUI is still there, however: Object Desktop adds to it. Another advantage of X is its virtual desktop. Both Gnome and KDE can also have virtual desktops, or separate desktops (pages) within the virtual desktops. For instance, let's say, that you are sitting at work or in class, you want to play games. On one desktop you can have Freecell running, while on another, you can have your work, switching between them with keystrokes or clicks. On a more particular, you can place your Web browser in one window to view your latest creation, while having the source open in an editor. The best Windows does is stack one window on top of another. Any competent user will have windows open, and X provides an easy way to organize them. Granted, the Object product allows you to have multiple desktops, but it is a Windows add-on instead of an inherent trait. And, you have to pay for Object Desktop; X is available for free.

One of the features touted in Windows XP is the "fast-switch". This feature permits a user to interrupt his or her work for something else and do so again. When the new user logs in, the state of the original user's desktop is restored where he or she left off. In instance, Microsoft is fairly attempting to create the multitasker operating system that it has claimed as a function of Windows for a long time. X is built on an operating system that is truly multitasker; it has been able to do this since its inception. To demonstrate, press Ctrl-Alt-F2, and you'll find yourself at another console. Log on as someone else, and then enter the following to start another X server on console 1:

```
startx :-1
```

You can alternate between your two users' sessions simply by pressing Ctrl-Alt-F7 for the original session, and Ctrl-Alt-F8 for the second session. And there you have it—the X Windows fast-switch feature! You can't do that with Windows version XP.

Of course, you could argue that this isn't a big deal, so let's go one step further. Although it is not apparent to a user on a single computer, the X client/server architecture applies to two separate computers. The programs communicate with each other over TCP/IP sockets, which are within the same machine or on different machines. This makes it possible to run a program on one computer while controlling it from another, which is something you just can't do from a Windows desktop. That's not completely true, since you can run a program like Virtual Network Computing (www.uk.research.at.com/vnc/). With VNC you get remote access to a Windows computer, and not remote access to the Windows computer. This difference becomes apparent if you happen to seize control of a Windows computer without its user being aware of the capability. In other words, you can remotely control the computer, but only to the extent that you would if you were sitting directly in front of it. A single Linux computer could easily be running programs on behalf of any number of users who are located anywhere on any network capable of reaching it. In fact, it is possible that the machine you use could be doing that right now! The good news: you will have an opportunity to experiment with all of this during the exercises at the end of this chapter.
