```
alias -p
alias ls='ls -color=tty'
alias ll='ls -l -color=tty'
alias l='ls -d [a-zA-Z]* -color=tty'
alias rm='rm -i'
alias mv='mv -i'
alias cp='cp -i'
alias which='alias /usr/bin/which -tty-only-read-alias-show-dot-show-tilde'
```

When you are using the ls command on a default alias of Red Hat, you are actually using an alias called ls. The alias invokes the actual ls command, but before it sets the default options of -color-tty. Red Hat also creates an alias ll that calls the ls command with the "long listing" option set.

Red Hat creates aliases for the shell commands rm, mv, and cp to set their default option to -i, which makes those commands interactively prompt for verification that the user really, wanted, to remove, move, or copy that file. If you, ever make mistakes, you might want to remove those aliases from /root/.bash_profile (or simply use the -f option to force them to run without prompting—but only when you are sure the command will work as expected).

We use aliases to save typing the fully qualified names when we are changing directories. Sure, word completion helps you type out a directory name quickly, but it's nowhere near as quick as a simple alias. Earlier in this chapter, we talked about word completion to avoid typing the long directory /opt/tomcat/webapps/WEB-INF/classes/com/manta. Instead, you could create an alias cpmanta that would make changing to that directory a breeze:

```
alias cpmanta='cd /opt/tomcat/webapps/manta/WEB-INF/classes/com/manta'
```

After this alias, you could put it in your .bash_profile so it would be available every time you logged on.
