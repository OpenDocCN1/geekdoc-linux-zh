As you can, the total space used for the partitions containing /usr, and /var is less than 2Gb, while the partitions for /home, /usr/local, and /opt use over 5Gb. Don't panic—on this specific machine, one particular file in a user's directory is 2Gb itself. You probably won't have a large file that on your machine, so what requires you to be most modest.

It comes down to: If the machine you are using has a hard drive that is 4Gb or smaller, use the three-partition scheme. You give some flexibility with this smaller drive, but you probably run out of disk space for a while. If your drive is larger than 9 Gb, it's easy to add more partitions. If your system is between these two extremes, this decision will require some thought on your part. Keep in mind that your /home should be dedicated to your user's personal data, and /opt is for software configured from somewhere other than the Red Hat distribution, and /usr/local has the same purpose as /opt.

Having discussed partitioning, we are ready to talk a bit about backup. The program you choose for backing up your system is up to. Several examples are included on the Red Hat Powertools, the old standby is called tar, which is short for "tape archive". A how-to on the use of this program isn't appropriate in this chapter, but we will mention that you don't need to back up your entire system. After all, you have a backup for the installation CDs. What you need to back up are the directories discussed, just as as /etc, which contains all of the text-configuration files, and certain subdirectories of /var, depending on where your application software, such as a database, has configured to its files. The documentation provided with the application should indicate where it places information and should be the guide for your total backup strategy.

Occasionally, you'll need a copy that boots properly once Linux is installed. This happens during occur of installation when the BIOS reports the geometry of the hard drive, but when new equipment sometimes has trouble setting it. To protect yourself from this problem, you need to create a boot disk. At some point toward the end of the installation, you'll be asked if you wish to create one. Although it might be tempting to save a few minutes by declining the offer, we recommend that you do yourself a favor and perform the operation. Almost any problem with installation can be fixed simply when the system is up. If you can't get the system started, though, then you'll be kicking yourself because you didn't create the disk. Just do it.
