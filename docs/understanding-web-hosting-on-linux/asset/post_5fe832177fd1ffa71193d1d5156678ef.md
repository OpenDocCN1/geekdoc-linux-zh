The X Window system is based on a client/server architecture, with the various parts available as individual software components. At the heart is the X server, which runs on the computer to which is attached the hardware providing the basic requirements of X: a graphics card and monitor, and a mouse. Working in conjunction with the X server are two additional components: the desktop environment and the window manager (sorry—we just couldn't resist) that permit you to give your a personalized look. The server, desktop environment, and window manager communicate with one another to provide you with the X Window experience.

The server is the one item within X that is not negotiable. You need to run one that is compiled for your particular CPU and operating system. There is an X server available for virtually every computer equipped with the basics, and your Linux distribution undoubtedly includes it. If your usual operating system is Linux, MacOS, OS/2, or even Windows, you can get an X server—if not an open-source (free) one, then a commercial one.

For the window manager and desktop environment, you have many choices. With your Linux distribution are various window managers, such as sawfish, windowmaker, and enlightenment, as well as desktop environments, such as KDE and Gnome. If you choose to install X and either or both KDE and Gnome, you already have some or all of these options at your disposal. Depending on which desktop you choose for your default, you'll find yourself in KDE or Gnome. If you are one of their itinerant GUI-trollers, you'll have lots of new toys to play with.

Before going any further, it would be helpful if you were currently at a computer that is in X. If you configured your computer to start in level 5 (the graphical runlevel), you will have a graphical signon screen. If you are looking at the console login prompt, you need to log on and, at the command prompt, enter the command startx, which brings up a graphical desktop. This, of course, assumes that you installed the X server and a desktop. If not, you can either go back and install them now, or simply skip this section if you don't plan to use X.

To start, click the KDE Control Center (on the toolbar at the bottom of the screen) or the Gnome Control Center (Foot->Settings->Gnome Control Center), and take a look at the vast array of options you can change. It's enough to make a geek drool. You can see what these control centers look like in Figures 10.1 and 10.2.

The closest equivalent to this in the Windows world comes from Stark, in a package titled "Object Desktop," which started as an OS/2 Workplace Shell extension. This product enables you to make your desktop "skinnable," allowing you to customize its content. The bloat inherent in the Windows GUI is still there, however: Object Desktop adds to it. So, while X allows you to balance functionality with form, the Windows GUI only allows you to add a facade at the cost of more bloat.

Another advantage of X is its virtual desktop. Both Gnome and KDE can have multiple virtual desktops, or separate desktops (pages) within X. For instance, let's say that you are sitting at work or in class, you want to play games. On one desktop you can have your browser running, while on another you can have your work open, switching between them with keystrokes or clicks. Any competent user will have windows open, and X provides an easy way to organize them. Granted, Windows allows you to have multiple desktops, but as an inherent trait you have to pay for Object Desktop; X is available for free.

One of the features touted in Windows is the "user switch". This feature permits a user to interrupt his work for something else and do so again. When the new user logs in, the state of the original user's desktop is restored where he left off. In instance, Microsoft has been attempting to create a multitasking operating system for a long time. X is built on a truly multitasking operating system; it has been able to do this since its inception. To demonstrate, press Ctrl-Alt-F2, and you'll find yourself at another console. Log on as someone else, and then enter the following to start another X server:

```
startx
```

You can alternate between your users simply by pressing Ctrl-Alt-F7 for the original session, and Ctrl-Alt-F8 for the second session. And there you have it—X user switch! You can't do that with Windows XP.

Of course you could argue that this isn't a big deal, so let's go one step further. Although it is not apparent to a user on a single computer, the X client/server architecture applies to separate computers. Programs communicate with each other over TCP/IP sockets, within the same machine or on different machines. This makes it possible to run a program on one computer while controlling it from another, which is something you just can't do from Windows. That's not completely true, since you can run a program like Virtual Network Computing (www.ultravnc.com/). With VNC you get remote access to the Linux computer, and not just the local desktop. This difference becomes apparent if you happen to seize control of a computer without its user being aware. In other words, you can remotely control the computer to the same extent that you would if you were sitting directly in front of it. A single computer could easily be running programs on behalf of any number of users who are located anywhere on any network capable of reaching it. In fact, it is possible that the machine you use could be doing that right now! The good news: you will have an opportunity to experiment with all of this during the exercises at the end of this chapter.

## Configuration and Administration

There are many different aspects to configuring and administering a Linux box that quite a number of books have been written on the subject. This section boils Linux configuration down to one simple fact: almost without fail you can find the configurations for the operating system and programs in the main /etc directory, or one of the other "etc" directories, such as /opt/etc or /usr/local/etc.

Our initial plan for this section was to show some examples from within the /etc directory, point out how to edit them, and then go on to talk about the various KDE, Gnome, or Linux utilities that you could use to accomplish the same task. The problem is, like so many things in Linux, there are many ways to accomplish this, and there are some risks to advocating a particular method. For example, the linuxconf utility is mentioned in many books as the primary way of configuring your system. However, it is officially deprecated by Red Hat, a polite way of saying it's broken, it's not supported, and it's unlikely to ever be fixed. As a matter of fact, it is so broken that, if you see references to it anywhere on your system, you should go out of your way to avoid it. As we can both attest, its use is likely to destroy your working configuration.

There have been other attempts at configuring your system less of an arcane art and more of science, but they all have been made obsolete by what has the best configuration tool ever: Webmin. It not only allows you to easily configure your system, it slices and dices to maintain it as well! Webmin is all you need to configure and maintain your Linux server (If you are a system administrator, however, you will still want to purchase some Linux administration books to explore the guts of the system.)

Webmin is a browser-based application that allows you to configure and manage your computer locally (from the same machine), or from another across a network. So complete is the implementation that you can replace all other configuration tools with this one. As a bonus, it is extensible, so that any software author can write a Webmin module to support his or her application. Webmin, will upon installation, determine the distribution of Linux (and some other operating systems) on which it is running and automatically configure itself to provide only the relevant options. But we digress. You first need to get and install Webmin.

Point your browser to http://www.webmin.com/webmin/ to get the Webmin RPM. To ensure you don't have conflicts with the browser distinguishing between a RealPlayer file and an RPM file, hold the Shift key while clicking the link to save the downloaded file a place to reside, which is probably your home directory, and a name, which is probably webmin-90-1.noarch.rpm (although the .90-1 could be different as the program is updated).

Once the file is downloaded, open a terminal window to get a command line, and then issue the su command to switch to the root user (You aren't logged on as the root user already, are you? You shouldn't be!) At the prompt, enter the following command to install the package:

```
rpm -Uvh webmin-90-1.noarch.rpm
```

> Tip: Everything through webmin in the line above, and press Tab. The file name will be completed for you through the magic of the bash shell.

After waiting and gnashing of disk, you'll be rewarded with a prompt that says you can log on to http://localhost:10000.
