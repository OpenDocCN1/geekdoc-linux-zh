```
http://127.0.0.1:8080/servlet/PanelServlet?name=Don+Denconcour&java=Java&cpp=%C2%2B&e&x=%3E15&prof=webMaster&submit=Submit&hiddenField=secret
```

Let's break down that URL and look at the form parameters it contains. The question marks the qualification of PanelServlet identifies the beginning of what is called the query string. The query string is made of name/value pairs separated by ampersands. The first name/value pair is `name=Don+Denconcour`. Panel name text-input field will have a value of Don Denconcour. (The plus sign is used as a placeholder for a space.)

There are no name/value pairs for RPG, COBOL, or Visual Basic because those boxes were not selected on the form. The query string contains a value for java and then cpp. The value for cpp looks a bit: `%C2%2B` represents the hexadecimal value of the plus sign, since a plus sign in a query string normally identifies a space. The browser casting C++ to `%C2%2B`. When PanelServlet reads the cpp parameter, the value will be C++.

The exp parameter also has a hexadecimal value to represent the greater-than symbol. The values for prof, submit, and the hidden field follow.

If Panel.html's `<FORM>` tag used POST rather the query string would not have been in the URL. Instead, it would have been embedded in the HTTP packet. We use the GET method while testing we can clearly see the query string, but change to POST when the code is moved to production. Another helpful hint for testing is to hardcode a hyperlink to the Java servlet on the HTML page—servlets dont always have to be invoked from a form.

When PanelServlet is invoked by the servlet server, it returns the HTML page shown in Figure 7.6 Notice the line "This servlet accessed 101 times." If the Panel.html form was submitted, the response would say "This servlet accessed 102 times." Numerical values come from PanelServlet's instance field, globalCount. The value for globalCount is available to all clients, and the doGet method increments it by one. If several clients are invoking PanelServlet, they will use the same value for globalCount and as mentioned earlier, instance fields are typically used for things like JDBC connections—variables that are to be shared among Web-browser requests.
