# Command Parameters

The next block of code is nested if that handles the command-line parameters to tomcat.sh. If you look at
else clause to the nested, you'll see that tomcat.sh accepts start, env, run, stop, ant and We'll
only cover start and stop in detail. But as you know, ant is a facility for compiling the entire
Tomcat product, and jsp is a utility that precompiles Java Pages.

The top of the if block checks to see the first parameter is start. If it, Tomcat does a shift. The shift utility
takes the parameter list and shifts the first one out. If your parameter list is 1, 2, 3, 4, 5, shift would
reset your parameter list to 2, 3, 4, 5. After shifting, Tomcat checks to see if the second parameter (which is
actually the first) is security. If so, Tomcat shifts parameters and starts the Tomcat Java
application, with the JAVACM environment variable with security options set. If the security parameter is
not set, the Tomcat application is started without the security options.

The next clause in the nested if, the else-if, checks to see tomcat.sh was invoked with a parameter value of
stop. If so, tomcat.sh starts the Tomcat Java application with options to end Tomcat. If the Tomcat Web
application server is not running in some other process, the Tomcat Java application ends with an error;
or, the Tomcat Web application server is shut down.

The very last clause of tomcat.sh resets CLSPATH to its original value, which tomcat.sh had earlier
saved in an environment variable called oldCP.
