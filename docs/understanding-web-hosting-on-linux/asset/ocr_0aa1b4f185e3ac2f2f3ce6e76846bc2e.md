Another term of interest is gateway. As mentioned earlier, two computers communicate with one another only if they are on the same network. If they are on different networks (say, your local network and the (Internet), your communications will be brokered by a device that has at least two interfaces: one on the network to which you are connected and another on another network. The gateway address given to you by your network administrator is the address to which it will send packets for a computer that is not on your local network.

The next term to know is Domain Name System, or DNS. The simplest way to explain DNS is the analogy of IP addresses and phone numbers. If you know someone's phone number, you can easily call that person. If you don't know the phone number, but you know the person's name, you can call directory assistance to get the number.

DNS is the directory assistance of the Internet. When you enter a URL like "http://yourdomain.com" into your Web browser, it will first look in its own book (the file /etc/hosts) to see if it knows that. If not, it will connect to a DNS server to retrieve the number. If the DNS system knows it, it will return the number to your computer, which will use to make the connection. If the name is unknown, the DNS server will return an error message to that effect, which you will see as a "Host Unknown" message from your browser.

The list of servers you'll call for your request is in the file /etc/resolv.conf. If you look there, you'll see up to three "nameserver xxx.xxx.xxx.xxx" entries which will be searched in the order they appear. Typically, you will be given two server addresses—primary and secondary. If the primary one fails, the secondary will provide DNS services until the primary comes back online.

The final term is Dynamic Host Configuration Protocol, or DHCP. In nutshell, it refers to a protocol by which a computer that has been turned on is automatically configured with the correct IP/netmask, and gateway addresses. It does this by broadcasting a DHCP request to the network (using a different type of address because you don't know anything about the network at this point) and waiting for a response from a DHCP server in which all of the network parameters are provided. The DHCP server has a pool of available addresses from which it will choose one to send to the client. Once it does, the address is to be leased, which means the server will not assign it to another client. The lease has a fixed, so the client will occasionally be polled to see if the lease should be renewed. If the client responds, the lease is renewed. If not, the lease is cancelled and the address is placed back in the pool.

Most networks use DHCP for all machines (and some you use it for, too!) because it requires much less effort on the part of the network administrator. If your net admin tells you to use DHCP when you initially connect your computer to the network, be sure to let him her know that you are going to be running a Web server. You cannot be assured of receiving the same IP address every time your computer comes online unless the admin makes special adjustments to the DHCP server configuration or gives you a static IP address.

Figure 11.1 shows how all of these pieces fit together. Note that your communication frequently go through a number of gateways until it gets to its destination. In fact, a file that is too large to make it in one TCP/IP packet will be split into many smaller ones. It is fascinating that they may travel different routes, arriving at the destination at different times and out of order. TCP/IP was designed to put them back together correctly. The beauty of TCP/IP is the whole process ultimately appears like magic. You have to do nothing more than correctly configure your computer's IP address, netmask, gateway, and DNS entries, and the rest happens.
