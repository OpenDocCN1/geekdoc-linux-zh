# **DB_FILE_MULTIBLOCK_READ_COUNT** *init.ora* Parameter

The DB_FILE_MULTIBLOCK_READ_COUNT *init.ora* parameter determines the maximum number of database blocks that are read in one I/O operation by a user’s Server Process whenever a full table scan read operation is performed. The default value for this parameter is 8. The maximum value for this parameter varies by OS. Setting this parameter to a value greater than 8 benefits performance most when the database blocks are being accessed via full table scans. By increasing this parameter, more blocks are accessed with each I/O, thereby cutting down on the total I/Os required to scan an entire table.

Before setting this parameter, you can use the following query on V$SYSSTAT to determine how often your application is performing full table scans:

```
```sql
SQL> SELECT name, value
  2  FROM v$sysstat
  3  WHERE name = 'table scans (long tables)';
```
```

| NAME | VALUE |
| :--- | :--- |
| table scans (long tables) | 948 |


High values for this statistic indicate that your application is performing frequent full table scans and may benefit from an increase in the DB_FILE_MULTIBLOCK_READ_COUNT parameter.

![](bbox=[0.18, 0.73, 0.27, 0.8])

The behavior of the Cost-based Optimizer is also affected by this parameter. If fewer I/Os are required to access all the rows of a table via a full table scan, then the CBO may now choose to access that table using a full table scan instead a previously used index.
