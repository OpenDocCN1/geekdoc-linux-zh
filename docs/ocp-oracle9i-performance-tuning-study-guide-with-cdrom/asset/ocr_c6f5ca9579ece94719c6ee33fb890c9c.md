When examining the above structure, one rule related to list partitioning should be considered: Values that do not meet any of the conditions of the partition key will raise an ORA-14400 error. Unlike Range partitioning, Oracle9i Release 1 currently does not support use of the MAXVALUE option to eliminate this problem.

> Specific physical segment attributes, such as STORAGE parameters, can be assigned at the partition level. These attributes will override the table’s default attributes.

# HASH PARTITIONING

Hash partitions use a hashing algorithm to assign inserted records into partitions. This has the effect of maintaining a relatively even number of records in each partition, thus improving the performance of parallel operations like Parallel Query and Parallel DML. Suppose you’ve decided to use hash partitioning on the STUDENT_ID column instead of Range partitioning to partition the STUDENT_HISTORY table. This means that STUDENT_ID is the partition key:

SQL> CREATE TABLE student_history
  2 (student_id     NUMBER(10),
  3 degree         VARCHAR2(3),
  4 graduation_date DATE,
  5 final_gpa      NUMBER)
  6 PARTITION BY HASH (student_id)
  7 PARTITIONS 6
  8 STORE IN (hist_tab01, hist_tab02, hist_tab03,
  9            hist_tab04, hist_tab05, hist_tab06);
