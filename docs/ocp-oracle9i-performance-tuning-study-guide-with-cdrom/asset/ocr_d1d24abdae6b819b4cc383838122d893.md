The V$DB_OBJECT_CACHE and V$SQLAREA dynamic performance views discussed in the previous section can be used to arrive at an estimated size for the Library Cache. Figure 4.11 shows an anonymous PL/SQL block that you can use to determine how much shareable memory the instance’s cached SQL statements are currently utilizing:

# FIGURE 4.11 Using V$Views to estimate proper Shared Pool size

```
set echo off
set feedback off
set serveroutput on

DECLARE

v_total_plsql_mem NUMBER := 0;
v_total_sql_mem NUMBER := 0;
v_total_shareable_mem NUMBER := 0;

BEGIN
-- Find the total shareable memory used by non-SQL objects like
-- packages, views, etc.
SELECT sum(shareable_mem)
INTO v_total_plsql_mem
FROM v$db_object_cache;

-- Find the total shareable memory used by SQL statements
SELECT sum(shareable_mem)
INTO v_total_sql_mem
FROM v$sqlarea
WHERE executions > 10;

-- Now add these two value to get the total shareable memory
-- (i.e. Library Cache) requirements
v_total_shareable_mem := v_total_plsql_mem + v_total_sql_mem;

DBMS_OUTPUT.PUT_LINE
('Estimated required Shared Pool size is: '||TO_CHAR(v_total_shareable_mem, '999,999,999,999')||' bytes');

END;
```

The above query totals all the shareable memory used by non-SQL objects and the shareable memory used by any SQL statement that has been executed more than ten times. This helps eliminate from consideration any extraneous, infrequently executed SQL statements that may not be part of the core application code.
