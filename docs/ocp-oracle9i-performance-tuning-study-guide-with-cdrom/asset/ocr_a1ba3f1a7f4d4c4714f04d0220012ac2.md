# Make It Bigger

The easiest way to improve the performance of the Database Buffer Cache is to increase its size. The larger the Database Buffer Cache, the less likely cached buffers are to be moved out of the cache by the LRU List. The longer buffers are stored in the Database Buffer Cache, the higher the hit ratio will be. Increasing the size of the Buffer Cache will also lower the number of waits reported by the `free buffer inspected`, `buffer busy waits`, and `free buffer waits` system statistics.

In Oracle9i, the size of the Database Buffer Cache is determined by the several `init.ora` parameters. A description of each of these parameters is shown in Table 5.4.

| **Parameter Name** | **Description** | |---|---| | DB_BLOCK_SIZE | Defines the primary block size for the data- base. Oracle9i supports multiple block sizes, allowing the block size for a specific tablespace to vary from this size. | | DB_CACHE_SIZE | Determines the size of the Default Buffer Pool for buffers with the primary block size as established by DB_BLOCK_SIZE. The default size is 48M. | | DB_KEEP_CACHE_SIZE | Determines the size of the Keep Buffer Cache. The default size is 0KB. Also uses the primary block size as its buffer size. The Keep Cache is discussed in the next section, “Use Multiple Buffer Pools.” | | DB_RECYCLE_CACHE_SIZE | Determines the size of the Recycle Buffer Cache. The default size is 0KB. Also uses the primary block size as its buffer size. The Recycle Cache is discussed in the next section, “Use Multiple Buffer Pools.” | | DB_2K_CACHE_SIZE | If 2KB is not the primary block size, specifies the size of the Buffer Cache for segments with a 2KB block size. |
