When a request is made for data, the user's Server Process copies the blocks (A, B, C) from disk into buffers at the beginning (Most Recently Used) of the LRU List. These buffers stay on the LRU List but move toward the least recently used end as additional data blocks are read into memory. If a buffer (A) is accessed again during the time it is on the LRU List, the buffer is moved back to the beginning of the LRU List (i.e., back to the MRU end). If buffers are not accessed again before they reach the end of the LRU List, the buffers (B and C) are marked as free and will subsequently be overwritten by another block being read from disk.

**NOTE** The behavior of the LRU List is slightly different when a table is accessed during a full table scan (FTS). During an FTS, the table buffers are placed immediately at the least recently used end of the LRU List. While this has the effect of immediately causing these blocks to be flushed from the cache, it also prevents an FTS on a large table from pushing all other buffers out of the cache.
