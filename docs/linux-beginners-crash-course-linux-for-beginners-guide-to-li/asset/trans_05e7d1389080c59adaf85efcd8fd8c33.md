

## 内核源代码

大多数 Linux 发行版都包含内核源代码。您安装到系统上的 Linux 内核正是基于这些源代码开发而成的。您可以在 ftp://ftp.cs.helsinki.fi 找到它们，其他网站也提供镜像服务。如果您没有互联网访问权限，可以以合理的价格从提供知名网站快照的供应商处获取 CD-ROM 光盘。一些供应商还提供定期更新的订阅服务。您当地的 Linux 用户组也是另一个绝佳的选择。

在源码树的顶层目录 /usr/src/Linux 下可以找到几个目录：

- **Arch：** 与特定体系结构相关的内核代码位于此子目录中。它进一步划分为子目录，每个子目录对应一种体系结构。Alpha 和 i386 就是子目录的例子。
- **Include：** 构建内核代码所需的头文件位于此子目录中。它同样为每种体系结构划分为一个子目录。编辑内核的 makefile 并重新运行内核配置程序可以更改体系结构。
- **Init：** 内核的初始化代码位于此目录中。若要理解内核的工作原理，这是一个很好的切入点。
- **MM：** 与内存管理相关的文件位于此目录中。与每种体系结构的内存管理相关的代码位于 arch/*/mm/ 中。
- **Drivers：** 这里包含系统的设备驱动程序，它们被分类到不同的类别中。
- **IPC：** 进程间通信的代码位于此目录中。
- **Modules：** 模块由此目录创建并存放于此。
- **FS：** 文件系统的代码位于此目录中。此目录有几个子划分，每个文件系统对应一个。
- **Kernel：** 这里由内核代码组成。与特定体系结构相关的内核代码可以在 arch/*/kernel 中找到。
- **Net：** 这是内核的网络代码。
- **Lib：** 内核的库代码位于此目录中。与特定体系结构相关的库代码位于 arch/*/lib/ 中。
- **Scripts：** 在内核配置期间使用的脚本位于此目录中。

# 第 4 章：Linux 进程

## task_struct

为了高效地处理系统中的进程，Linux 使用一种名为 task_struct 的数据结构来表示每个进程。（在 Linux 中，进程和任务这两个术语可以互换使用。）数据结构 task_struct 包含一个被称为任务向量的指针数组。

任务向量限制系统中进程的数量。默认情况下，最大条目数为 512。创建新进程会导致从内存中分配一个新的 task_struct。将其添加到任务向量即完成创建。current 指针指向当前正在运行的进程，以便更容易找到它们。

除了普通进程外，Linux 还支持实时进程。这些实时进程之所以被称为实时，是因为预计它们对外部请求的响应非常迅速。调度器对它们的处理方式与对普通进程略有不同。复杂的 task_struct 数据结构通过划分为以下功能区域来简化：

### 状态

进程在执行结束后，根据具体情况，其状态会发生变化。每个 Linux 进程具有以下状态之一：

Running（运行中）

在此状态下，进程已准备好运行或正在系统中运行。“准备好运行”意味着该进程已准备好被系统处理器之一接管以进行执行。

Waiting（等待中）

等待状态意味着进程正在等待资源或事件的触发。等待进程分为两种类型：可中断和不可中断。信号可以中断某些等待进程，这些被称为可中断进程；信号无法中断的等待进程被称为不可中断进程。

Stopped（停止）

当然，停止的进程已被停止，通常是由于接收到了信号。若要调试进程，必须将其置于停止状态。

Zombie（僵尸）

这是一个已终止的进程，它以数据结构 `task_struct` 的形式存在于任务向量中。因此，它被称为僵尸进程。

### 调度信息

这是调度器用来决定进程运行顺序的信息。

### 标识符

一个数值型进程标识符（PID）用于标识系统中的每个进程。

## 进程间通信（IPC）

Linux 支持的重要 IPC 机制包括信号、管道、消息队列、共享内存、信号量等；您将在后续章节中详细了解它们。

## 链接

## 时间与计时器

内核的另一项重要职责是跟踪创建进程所花费的时间。它还跟踪进程在其生命周期中消耗的 CPU 时间。随着时钟滴答，内核不断更新当前进程在系统中花费的时间。

## 文件系统

Linux 在支持多种类型的文件系统方面非常灵活。这有助于它与其他流行的操作系统共存。Linux 总共支持 15 种文件系统。它们是：

- ext2
- vfat
- affs
- minix
- sysv
- hpdfs
- ncp
- umsdos
- iso9660
- ufs
- xia
- msdos
- smb
- proc

未来还将添加更多文件系统。进程可以自由地打开或关闭其所需的任何文件。

## 虚拟内存

大多数进程使用虚拟内存。跟踪虚拟内存到物理内存的映射是 Linux 内核的职责。某些进程，如守护进程和内核线程，不使用虚拟内存。

## 处理器相关上下文

可以将进程视为系统当前状态的一种聚合。当进程运行时，它使用处理器的寄存器、堆栈等，这就是进程的上下文。在进程挂起后，必须将进程的上下文保存在 task_struct 数据结构中，以便在进程重启时能够恢复。

# Linux 如何组织数据

有效的操作系统应很好地组织其数据，Linux 正是如此做的。在本章中，我们将学习它是如何做到的。如果您使用过其他操作系统，如 Microsoft Windows，您可能会发现理解起来很容易，因为大多数操作系统以相似的方式组织其数据。

## 设备

Linux 从设备接收、存储并向设备发送数据。每个设备对应一个硬件单元，如串行端口或键盘，但设备并不一定需要有硬件对应物。内核可以创建许多伪设备，它们表现得像设备但不物理存在。给定的硬件单元可以连接多个设备；例如，Linux 操作系统会将磁盘驱动器的分区显示为单独的设备。

下表列出了某些典型的 Linux 设备：

| 设备 | 描述 |
| :--- | :--- |
| atibm | 总线鼠标 |
| audio | 声卡 |
| cdrom | CD-ROM 驱动器 |
| console | 当前虚拟控制台 |
| fd n | 软盘驱动器（n 指定驱动器；例如，fd0 是第一个软盘驱动器） |
| ftape | 不支持倒带的流式磁带驱动器 |
| hd xn | 非 SCSI 硬盘（x 指定驱动器，n 指定分区；例如，hda1 是第一个非 SCSI 硬盘的第一个分区） |
