# Looking at System Log Files

Linux keeps track of all kinds of system information in log files. These files are stored in different places and are maintained by the syslogd daemon. The syslogd daemon is started when the system boots and knows what type of information to store based on the contents of the /etc/syslog.conf file (shown in Figure 17.2). After the syslogd daemon knows where it should log system information, it goes merrily about its business once a minute, collecting messages from everywhere and entering them in log files.

You can also look in the /var/log directory to find the logs maintained by the syslogd daemon. Here are a few of the system logs that you'll find:

+   - The /var/log/messages file is the main system log and contains the information gathered by the kernel when the system was last booted.
+   - The /var/log/wtmp file contains the login time and duration for each user.
+   - The /var/log/utmp file is where information about currently logged-in users is kept.
+   - The /var/log/lastlog file is where user login times are stored.

As you can see, with all these system log files and new information added every minute, log files can get out of hand quickly. To keep from being buried under the information overload, you'll need to monitor the status of system log files and periodically clean them out. Because the logs are a valuable source of information about your system, and some are used by commands that the system runs, you shouldn't just delete them.
