# What Are Loadable Modules?

The kernel upgrade process is managed through the use of loadable modules. *Loadable modules* are separate pieces of kernel code that are not included (linked) directly into the kernel. They can be compiled separately and inserted into, or removed from, a running kernel as needed or requested. Loadable modules are the preferred way to code drivers for many of the new devices that are appearing daily. Also, because the size of the Linux kernel has grown a lot recently and the complexity and size of the device drivers have also increased the module size, compression utilities are a must for reasonable download file size.

> The GNU Hurd aims at being able to modularize everything, including things that are presently built into the Linux kernel, so that any user can pick and choose and use the modules to build a kernel any way he wants or needs.

# Obtaining the Modules Package

To get the source code for the new kernel, you will need to download it from the Internet. The source files that you'll need to get will be in an archived and compressed single file that can be retrieved via anonymous FTP from `ftp.kernel.org/pub/linux/kernel/vx.x.x` (where x.x.x is the version number). It is probably best if you use your country code to get source from the mirror for your country. So, for the United Kingdom, the path would be `ftp.uk.kernel.org/pub/linux/kernel/vx.x.x`, and for France it would be `ftp.fr.kernel.org/pub/linux/kernel/vx.x.x`.

![](bbox=[0.1, 0.9, 0.18, 0.97])

> It is important to be aware that the system used for numbering kernels has meaning. There are two methods for numbering kernels. The kernels that are assigned even minor numbers (such as 2.2.x) are production or stable kernels with the bugs removed. Those numbered with odd minor numbers (such as 2.3.x) are development kernels made available—often without the bugs removed—for people to test drive and contribute what they can. These kernels are not for the inexperienced user.
