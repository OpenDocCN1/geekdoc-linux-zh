## Understanding Dependencies

You might have noticed that the file size for many of the installed packages is quite small. (You’ll find quite a number of packages that are less than one megabyte.) How can these programs be so small, yet so powerful? The secret lies in the shared libraries that are installed on the system already. These libraries are used by most every application, utility, and command installed on the system. Instead of each program containing all the necessary functions needed to run the program, the common functions are stored in libraries, where every program can read them and use the needed functions. You can see how this would save space on your hard drive, and make it somewhat easier for programmers to develop new programs.

The downside to using a set of libraries to run another program is that the libraries must first be installed before the other program will run. And, considering this concept in reverse, if you uninstall a library that other programs need in order to run, you’ll cause quite a few problems and your favorite programs might not work if they are dependent on the library you uninstalled.

When you use rpm to install and uninstall programs, the rpm command checks for dependencies. If you uninstall a package upon which other packages depend, you'll see a message such as the following:

```
[root@localhost /root]# rpm -e libc-5.3.12
error: removing these packages would break dependencies:
libc.so.5 is needed by mswordview-0.5.14b6w-2mdk
```

The system will return only the error message: it will not uninstall the package. The error message does tell you which application or applications (in this case, mswordview) depend on the package that you just tried to remove.

![](img/782ecfdc0b083a767896cc983e10427f_257_0.png)

> A good rule of thumb about removing packages is that if other programs are dependent on a package, don't remove it!

You might also find that when you are installing packages, another package (or library) is needed before you can install the desired program. If you try to install a package that needs a certain library so that it can operate, and that library is not located on the system, you'll receive a failed dependencies warning along with the name of the missing library. You'll need to find the library and install it first. After the needed library is installed, you can install the package, this time with success.

## Task: Installing Packages from the Linux-Mandrake CD-ROM

Once more, it's time to work without a net while you install a package from the distribution CD-ROM from the command line. Unless you installed the entire distribution, you might be able to find on the CD-ROM a few packages that aren't on your system. Before you can install any packages, you must be logged in to the superuser account, and you need to place the distribution CD-ROM in the CD-ROM drive and mount the drive. Here's how to use the command line to add more software applications to your system:

- 1. Locate the directory in which the RPM files are stored on the CD-ROM. There should be a subdirectory called RPMS somewhere on the CD-ROM. Use the ls command to list the contents of the CD-ROM.

## Summary

During the past hour, you learned how to use the rpm command, along with the RpmDrake front end, to manage applications. With these tools, you can find out what programs are installed on the system, delete any of these programs that you don't use or need, and add any new applications that you find useful. The majority of the software that you'll find on the different Linux distributions, and packages that you can download from the Internet, is in the RPM format. This means that no matter where you get the software, you can install it on your system.
