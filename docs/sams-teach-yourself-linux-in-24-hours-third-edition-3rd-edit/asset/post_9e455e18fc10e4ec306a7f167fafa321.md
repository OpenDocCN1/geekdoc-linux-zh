
> The key to maintaining a secure root account is good password management. You'll also want to create an unprivileged user account in which to work. To learn more about these in detail, look in Hour 12, "Sharing Files with Other Users on the System."

## Performing Administrative Tasks as Superuser

One of the joys of Linux is the great opportunity you have to learn to be your own system administrator. In fact, if it is your Linux system, you will have to be your own system administrator. This is perhaps more technical involvement with your operating system than you might have experienced in the past. This might be especially true for those of you with previous experience only with the Apple Macintosh and Microsoft Windows operating systems. However, Linux is a multitasking, multi-user operating system capable of serving the needs of multiple jobs and multiple users simultaneously. Because of this broad world of flexibility and power, there exists a profound need for control and security of operations. The person who has the root or superuser account password may change anything in the system. The key is to be able to change things that need to be changed without compromising the integrity of the operating system or the autonomy of the users in their own accounts.

Linux is completely configurable. That means you can modify the operating system to accommodate different hardware or special tasks, and that you may tune it to perform better with particular applications. You can also change the operating system to suit a particular user's needs or to serve the needs of a group or special project. As the superuser, you have the job of maintaining the system and keeping up on everything that must be done to maintain and upgrade equipment and software. You are also the one who installs the software, adds new users, backs up the system, and manages the workload. You will perform many different jobs while working with Linux and you will wear several hats. Last but not least (and on top of all the things we just hinted at), you are the person who provides what the users want or need.

> Linux has built-in tools to help you manage the system. Hour 9, "Hooking Up Hardware Devices," shows you what is involved when you want to add a new hard drive. To make sure that the system is operating properly and that there is enough storage space, turn to Hour 14, "System Maintenance." When you want to try a new software program, look in Hour 15, "Installing Software."

## Working Day to Day as a Regular User

So far, you've seen the many jobs of the systems administrator and the needs of a system with multiple users. Your Linux system might well be just yours and have no other users. You might want to tailor the machine completely to your needs and desires. Even if you are the only user, you should set up a user account just for yourself. Log in as the superuser only to perform system administration tasks. The security and welfare of the system will be best served if the superuser's extraordinary power and accesses are simply reserved until they are called for by need.

## Restricting Access to the System

There are many reasons for restricting access to your system. Unauthorized users can wreck a lot of hard work and destroy valuable data even if they have no evil intent. Then, of course, there are the ones who do have bad intent that must be defended against. The method for restricting user access to the computer in Linux is a system of user-assigned passwords. These passwords allow user access to the home directory of the individual user. This password security is coupled with a system of file access permissions describing who may access the file, how they may access it, and what they may do with it. These passwords and file permissions form the foundation for security management in Linux.

## Using Shadow Password Files

Nearly all UNIX systems support what are called shadow password files. These files are not accessible by anyone except the superuser and they contain the passwords of all the users on the system in encrypted form. Linux uses the freely available Shadow package to provide this service. The Shadow package also accommodates password aging and some user account utilities.

## Task: Creating a Strategy for Choosing Passwords

If they are properly selected and frequently changed, passwords can be a major deterrent to someone trying to obtain unauthorized access to your account. Here are the guidelines that you should follow when choosing passwords for the superuser and unprivileged user account:

- 1. Use a mix of uppercase and lowercase letters, numbers, and symbols.
- 2. Do not use dictionary words and, in particular, do not use English words. If you can find the word in a dictionary, don't use it as a password.

![](img/782ecfdc0b083a767896cc983e10427f_70_0.png)

> Passwords should not be someone's name, either. Don't use the names of favorite pets, old lovers (or new ones), friends, enemies, birthdays, or phone numbers. It has been mentioned that it is really a simple matter to determine your great-grandmother's maiden name on either your father or mother's side of the family.

- 3. Passwords must be easy to remember and quick to type. They must also be hard to figure out.
- 4. Passwords should be at least eight characters in length.
- 5. Passwords can be made to appear to be words, if that makes them easier to remember—the password 2hfArEe (tooth fairy) is a good example, but it isn't a very good password anymore, now that it's been put in this book.
- 6. Test your passwords before you use them. Type the following on the command line:
  echo password | ispell -l
  Replace the word password with the password you chose. Figure 3.1 shows a few attempts at selecting good passwords.
- 7. Educate those people who will be using the system on how to select a sound and secure password.

## Designing Workgroups for File Sharing

Users working on a Linux system retain privacy, autonomy, and separate accounts for their files without other users having access to them. A special consideration must be made to allow users to share files with other users. The method for doing this is to place the users who need access to the files in a special group, and then place the files that you want to share in a directory to which only the group members are permitted access. Setting the file read, write, and execute permissions will control access to the files by the group members when they access the directory. The file permissions can be set to allow the group members full read, write, and execute privileges, or perhaps to allow some lesser access to the files, such as read only.

## Assigning Users to Appropriate Groups

The assignment of users to groups and the subsequent assignment of file access permissions form an important part of the way security operates in Linux. The assignment of members to groups needs to be carefully thought out. Workgroup computing projects are a function of a group process. The members of that group have special communication and computing needs that might endure through the life of the project. That's pretty straightforward, but what complicates matters is that any one individual might be working on several projects at once.

All the employees in a small business might be organized into a single workgroup. Even if there are only a few employees, there might be more than one project going on with different project members. This can make assignment confusing. One way to deal with this is to organize all your workgroups around projects. If done this way, you can facilitate the sharing of files, reports, and messages. All this needs to be done in a way that addresses the needs and enhances the productivity of project members.

## Using File Permissions to Limit File Access

Each file in the system can be configured to discriminately permit or refuse access or actions. You might have a list of things that you want only members of a certain group to see and read, but you don't want them to be able to change the things on the list or to add new things. You can accomplish this by controlling the user's file access privileges that are configured for the file.

## Controlling Access to User Accounts

Controlling access to user accounts is done through password authentication. Because this permits entry to the system and the user's private files, it is very important to maintain the integrity of the user's passwords for system security. Selecting good passwords (as described earlier) and changing them on a regular basis is always a good idea.

In your system administrator capacity, you might have to replace lost or forgotten passwords (or compromised ones). There might be times when you want to restrict access to a user's account. Maybe the user will be on a leave of absence and you want to temporarily deny access to the computer and user account, but retain the user's account and files. These and other actions can be easily managed through the password system.

## Limiting Access to System Devices

Linux treats everything as a file and that includes the hardware. To make this a little easier to understand, think of gaining access to a printer as gaining access to the printer's driver file. Now the way that you can apply the same access and privilege controls to system devices as you can to data files becomes much more apparent.
