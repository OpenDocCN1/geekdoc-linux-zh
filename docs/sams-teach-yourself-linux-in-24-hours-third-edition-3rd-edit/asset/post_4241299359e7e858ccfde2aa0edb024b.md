
## The Syntax for the who Command

When you want to know which users are logged into the system and how long their accounts have been active, use the who command. The following code shows the syntax for the who command:

```
who [options]
```

The who command can be used without any additional parameters, or you can add one or more of the following command options to display additional information about the logged-in users:

- When you need a quick reminder of the options available for the who command, use the shell's `-help` command option.
- When you're not sure which user account you are logged into, use the who am i command to display the username, the hostname, the terminal logged into, and the amount of time you have been logged in.
- To add column headings to the output of the who command, use the `-H` command option.
- A list of logged-in users and the total number of users logged in can be displayed with the `-q` command option.
- Sometimes a user may be logged in but not actively working in his or her account. To see how long accounts have been in use or idle, use the `-i` command option.
- To see whether a user is accepting messages (which you'll learn about later in this chapter), use the `-w` command option.

## Sending Messages to Other Users

One way to send a quickie message to another user on the system is with the write command. The write command allows you to leave a message for another user who is logged into the system. When the other user is ready to respond to your message, he or she will also use the write command to send the reply.

![](img/782ecfdc0b083a767896cc983e10427f_316_1.png)

> If you are not able to use the write command, the superuser will need to enable messages. From the root shell prompt, type mesg y and press Enter.

## The Syntax for the write Command

One way to send messages across a network without having to set up an email system is to use the write command. The following code shows the syntax for the write command:

```
write username [ttyname]
Your message here
Ctrl+D
```

Here, username is the name of the user to whom you want to send a message and the ttyname parameter indicates the terminal at which the user logged in. Use the ttyname parameter when a user is logged into more than one terminal to specify which terminal to send the message.

## Sending Messages

The write command allows two users to communicate across the network without using email or voice mail. Before you use the write command to send a message to another user, you'll need to make sure that the other user is logged into the system. For example, users rusty and mona are working together on a project and rusty needs to ask mona a question. To see if mona is logged in, rusty would use the who command (by typing who and pressing Enter at the shell prompt) to check and see whether mona is working at the computer.

![](img/782ecfdc0b083a767896cc983e10427f_316_2.png)

Once rusty has determined that mona is logged in, rusty would send the message by typing write mona and pressing Enter. The cursor appears on the next line and rusty can type the message. When rusty has finished composing the message, pressing Ctrl+D sends the message to mona. Here's what displays on the terminal at which rusty is working:

```
[rusty@localhost rusty]$ write mona
Do you have the schedule for the next two weeks?
[rusty@localhost rusty]$
```

Now rusty just sits back and relaxes until mona sends a reply.

## Replying to Messages

When a message arrives from another user, you'll again use the write command to respond to the user. In the previous message that rusty sent to mona, the message appears as follows on the terminal at which mona is working:

```
Message from rusty@localhost.localdomain on pts/1 at 02:16
Do you have the schedule for the next two weeks?
EOF
```

Before mona can respond, the Enter key must be pressed in order to display the shell prompt. Then, mona can reply by executing a command similar to the following:

```
[mona@localhost mona]$ write rusty
You'll need to ask Dezi for the updated schedule.
```

After mona has finished composing the message, pressing Ctrl+D (the Linux end-of-file character) sends the message back to rusty.

![](img/782ecfdc0b083a767896cc983e10427f_317_0.png)

> You may want to use communication commands (such as write and talk, discussed later) sparingly when communicating with other users. Some people do not like to be interrupted while they are working. You may also want to keep your messages short; a line or two is usually enough to give short instructions, leave requested information, or request a meeting.

## Sending a Message to All Users

There may be times when you need to send an important message to each and every user who is logged into the system. A system administrator may want to let everyone know when the system will be going down for repair, or the boss may want to let everyone know about an emergency staff meeting. The wall (write all) command sends a message to every user on the system. To send a message to every user, use the following command :

```
[rusty@localhost rusty]$ wall
Staff meeting at 3pm today.
Ctrl+D
```

As you might have noticed, the wall command works the same way as the write command. You execute the command, type a message, and press Ctrl+D to send the message. The message that is sent displays on each user's terminal, as follows:

```
Broadcast message from rusty (tty2) Mon Jun 12 02:38:37 2000...

Staff meeting at 3pm today.
```

If a user wants to reply to the broadcast message, he or she can use the write command to send a message to the sender.

## Turning Off Messages

There may be times when you don't want to receive messages from other users. You may be talking on the telephone and don't want any distractions, or you may be processing a large file and you don't want to add a heavier load to the system resources.

When you don't want to receive messages from other users, type mesg n and press Enter. Whenever someone tries to contact you using the write or talk command, a message similar to the following appears on their screen:

```
write: rusty has messages disabled
```

When you are ready to accept messages again, type mesg y and press Enter.

## Having a Two-way Conversation with Another User

Sometimes it may be more efficient to have a direct conversation with another user on the network. By using the talk command, you can call up another user and have a one-on-one conversation. If you visit the Internet chat rooms, you'll find the talk command works in somewhat the same way.

### FIGURE 20.3

You will have to wait until your invited guest joins the conversation.

![](img/782ecfdc0b083a767896cc983e10427f_319_0.png)

When rusty receives the request from mona for a little talk, a message like the following will appear on the screen:

```
Message from Talk_Daemon@localhost at 17:37 ...
talk: connection requested by mona@localhost.
talk: respond with: talk mona@localhost
```

The last line of the message tells rusty what command to use to connect with mona. In order for rusty to chat with mona, rusty would type talk mona@localhost at the shell prompt. When rusty has responded, both terminals display a message saying that the connection was established. Now that the two users are connected, they can begin their conversation. The user who is sending the message will type the message in the top half of the screen (don't worry about placing the cursor; the talk command does that for you). Responses from the recipient user appear in the bottom half of the screen. An example of a talk conversation is shown in Figure 20.4.

The talk command sends everything you type to the recipient as you type it. There are no special characters to type to display the message on the recipient's terminal. When the talk conversation is concluded, press Ctrl+D to end the session.
