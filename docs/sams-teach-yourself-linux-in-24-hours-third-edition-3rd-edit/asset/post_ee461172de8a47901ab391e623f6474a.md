Like the /etc/passwd file, each group has a separate entry in the /etc/group file. Each entry contains four fields, with each field separated by the colon (:) character. In order of appearance, these fields are

- The name given to the group.
- The password field, which is optional. This field usually contains the x character. You can give a group a password so that users who are not part of that group can access the group's files. The outsider would need to use the newgrp command to access the group.
- The group identification number.
- The list of additional users who have been assigned to the group. These are users who do not have this particular group listed in the group identification field of the /etc/passwd file.

## Task: Creating a Group Account

When you create a user account in Linux, each user is assigned to a primary group that has the same name as her username. The easiest way to add a new group is to edit the /etc/group file. Before you begin, you must be logged in to the superuser account to create group accounts. Here's how to create a group account:

- 1. Open the /etc/group file in your favorite text editor.
- 2. Scroll to the bottom of the file and create a new line. This is where you will type the information for the new group. Remember, the group information uses the following format:
  
  `group_name:x:groupID:group_members`
  
- 3. Type the name that you want to assign to the group, followed by a colon. For example, if you want to create a group in which the sales staff can store promotional literature and order forms, you might want to call the group sales.
  
- 4. Leave the password field blank. Type x.
  
- 5. Assign a group identification number. Look at the group identification number of the last entry and use the next number. For example, if the last group in the list has a group identification number of 508, assign the new group a group identification number of 509. Follow this number with a colon.
  
- 6. Assign members to the group. If users named rusty and mona will be assigned to the group, separate each name with a comma (but no space between the names). Using this example, the entry for the sales group would look like this:
  
  `sales:x:509:rusty,mona`
  
- 7. Save the file and close it.
  
- 8. Create a directory in which the group can store files. A good place to create directories for groups is in /usr/local. For example, create a /usr/local/sales directory in which the sales group can store files and create subdirectories.

When an individual wants to know the groups to which he belongs, all that's necessary is to use the groups command. For example, user rusty would see the following:

```
[rusty@localhost rusty]$ groups
rusty sales
[rusty@localhost rusty]$
```

This shows that rusty has a group all to himself and that he belongs to the sales group.

A user can also display the identification number for his user account and assigned groups with the id command, as shown here:

```
[rusty@localhost rusty]$ id
uid=501(rusty) gid=501(rusty) groups=501(rusty),509(sales)
[rusty@localhost rusty]$
```

If the user is working in his account, the new group account for the user might not be listed. The user will need to log out of his account and then log back in.

![](img/782ecfdc0b083a767896cc983e10427f_216_0.png)

If you want to delete a group account, delete the entry for the group in the /etc/group file.

## Granting Access to Files

After you have created accounts for each user and group that will be using the system, users and groups can then start storing files on the system. When a file (or directory, for that matter) is created by a group member, that member is the owner of the file. It is this user who can grant ownership and permissions to other group members and to other system users. This system of file ownership and permissions forms the basis for restricting and allowing access to files. There are three types of file ownership:

- The owner is the user who created the file.
- The group is the default group to which the owner belongs. By default, this is the primary group specified in the /etc/passwd file for the file owner.
- Other ownership can be assigned to system users that are not members of the group.

New Term File permissions determine which users on the system have access to a file and the type of access they are allowed. File permissions help maintain security for files by restricting access to files.

The file owner can also determine the type of access (or permissions) that other users may have to the file. There are three different levels of file permissions that can be assigned to a file or directory, and these permissions can be set differently for the different types of owners:

- Read access on a file allows the user, and groups that have permission, to view the contents of a file. Read access on a directory means that the user and groups can list the contents of the directory.
- Write access on a file gives selected users and groups the ability to make changes to the file or to delete the file. Write access for a directory allows the user and groups to create files in the directory and to delete those files.
- Execute access for a file means that the file can be run as a command or program. Execute access for a directory allows the user and groups to access the directory and list information about the files contained in the directory.

As you learned in Chapter 7, “Moving Around the Filesystem,” the ls -l command lists the user and group ownership of a file and the permissions assigned to each. Figure 12.3 shows an example. In this example, the owner has full access to the file (read, write, and execute). The group, owner, and other users have read and execute permissions on the file.

## Changing File Ownership

To change the ownership of a file (that is, the user owner and the group owner), use the chown and chgrp commands. Let's look at two files that user rusty has created and placed in the sales group directory:

```
-rw-r--r-- 1 rusty rusty 747293 Jul 4 04:04 packages
-rw-r--r-- 1 rusty rusty 155 Jul 7 01:01 tealist
```

For both files, the group ownership needs to be changed to the sales group. To do this, rusty would cd to the sales directory and use the chgrp command as follows:

```
[rusty@localhost sales]$ chgrp sales packages
[rusty@localhost sales]$ chgrp sales tealist
```

If rusty wants to transfer the tealist file into the hands of user mona, rusty would change the owner with the following command:

```
[rusty@localhost sales]$ chown mona tealist
```

The listing would then appear as follows:

```
-rw-r--r-- 1 rusty sales 747293 Jul 4 04:04 packages
-rw-r--r-- 1 mona sales 155 Jul 7 01:01 tealist
```

## Protecting Files

Now that the owners of the file have been set, you can change the type of access that each type of owner is permitted. The process for changing file permissions is a bit more complex. The chmod command changes the file permissions. The syntax of chmod is

```
chmod access_string filename
```

The syntax of the access_string is

```
owner+operator+file permission
```

Where owner is one or more of the following file owners:

- The u character sets permissions for the user owner
- The g character sets permissions for the group owner
- The o character sets permissions for all others
- The a character sets the permissions for all three types of owners

Where operator is one of the following:

- To add a file permission for the specified owner, use the + character
- To remove a file permission, use the - character
- To use the exact file permission, use the = character

Where file permission is one or more of the following:

- Read access is applied with the r character
- Write access is applied with the w character
- Execute access is applied with the x character

Use the following file as an example:

```
-rw-r--r-- 1 rusty sales 747293 Jul 4 04:04 packages
```

If user rusty wants to allow write access to the sales group, rusty would use the chmod command as follows:

```
[rusty@localhost sales]$ chmod g+w packages
```

To see the changes, use the ls -l command to display the new file permissions:

```
-rw-rw-r-- 1 rusty sales 747293 Jul 4 04:04 packages
```

You'll notice the w (for write access) in the group permissions.
