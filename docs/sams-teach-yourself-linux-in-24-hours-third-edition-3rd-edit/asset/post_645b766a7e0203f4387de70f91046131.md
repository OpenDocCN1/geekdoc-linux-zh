Other files, located in the /proc filesystem, contain information about the system architecture; that is, all the busses, boards, controllers, and peripherals attached to the system. This is important information to have before you make any configuration changes to the system. Here's how to view these files as read-only files in the vi text editor:

- 1. Log in as superuser. Type su and press Enter. You will be prompted for the root password. Type the password and press Enter.
- 2. Open the kernel boot message file as read-only. Type vi -R /var/log/messages and press Enter. The kernel boot messages are different, from system to system, depending on the drivers that are compiled as modules or loaded into the kernel. As you browse through the file, you'll notice messages for each device as it is initialized during the boot process.
- 3. Look for system configuration information. You'll need to know the screen font and color when the screen is used as a text terminal, PCI bus and PCI cards, CPU type and processor speed, system memory usage, type of mouse, serial and USB ports, mounted filesystems, and the version number of the Linux kernel.
- 4. Move around the file. Press Ctrl+F to move forward in the file one screen. Press Ctrl+B to move backward one screen.
- 5. When you are finished reading the file, exit (or quit) the text editor. Type :q and press Enter. The vi text editor will close and you will be returned to the shell prompt.
- 6. Return to your user account. Type su username and press Enter.
- 7. View information about the CPU type and speed. Type vi -R /proc/cpuinfo and press Enter. The -R command option tells vi to open the file as read-only. An example of the /proc/cpuinfo file is shown in Listing 9.3. When you are finished reading the file, type :q and press Enter to close the file and exit vi.

## Adding New Hardware

During the installation, you created different filesystems and corresponding mount points for the partitions on the hard drive. If you think you're running out of storage room, you might want to consider adding a second hard drive to the system. Here are the steps required to add a disk to the system:

- Make sure that the piece of hardware is compatible with the operating system. You'll find this information in the Linux Hardware Compatibility HOWTO. There are some other HOWTOs that you might want to read: The Hard Disk Upgrade mini-HOWTO, the Filesystems HOWTO, the CD-ROM HOWTO, the Zip Drive mini-HOWTO, the Jaz Drive HOWTO, the Plug-and-Play HOWTO, and the CD Writing HOWTO.
- Turn off the system and install the hard drive according to the manufacturer's directions. The manufacturer usually does a low-level format, but if not, you will need to take care of this. Remember to keep notes in your Linux diary so that you can refer to them on that slight chance that something goes wrong.
- When you turn on the computer and the system reboots, watch the boot message. You'll see the new device file for the hard drive listed.
- Your next big job is to create one or more partitions on the hard drive. Use the Linux fdisk utility to make the Linux partitions. After the partitions are created, use the fsck command to check the filesystem for errors.
- Configure the device in the /etc/fstab file. You can change parameters in the file so that filesystems are mounted automatically at boot time and to tell the kernel where in the filesystem the device stores files.
- When the /etc/fstab configuration file is set up, filesystems can be mounted automatically at boot time or mounted with the mount command.

Throughout this hour, you've listed filesystem information by viewing the /proc/mounts file, executing the mount command, and reading the kernel boot messages. All this information is stored in the /etc/fstab file. A sample /etc/fstab is shown in Listing 9.4. You can easily view this file with the cat command (type cat /etc/fstab and press Enter). The /etc/fstab configuration file contains the information required to mount filesystems when the system is booted.

Your listing might not show the contents of the file in neat and orderly rows. Listing 9.4 has been modified to illustrate the six fields required for each device that is attached to the filesystem and listed in the /etc/fstab file. The entries in the file use the following format:

- The first column is the device file. This file is the go-between for the user and the kernel. Various applications and commands use this file to access the piece of hardware, such as a hard drive or Zip drive.
- The mount point is the directory where the filesystem for the device is located. If you are adding a hard drive so that you have more storage space for user files, you could create a mount point as a subdirectory of the /home or /usr/local directories.
- GNU/Linux supports a variety of filesystem types. As you've seen earlier in the hour, you can use DOS floppies and CD-ROM drives. The Linux native filesystem type is ext2.
- Options are used to set the parameters under which the device operates. The device can be set to be read-write or read-only; it can be mounted automatically at boot time or not; and user storage space on the filesystem can be limited.
- The filesystem can be backed up (using the dump utility) on a regular frequency. This might not be used by all systems.
- The fsck utility checks each filesystem at boot time. The order in which the filesystem is checked is indicated in the last column.

## Task: Backing Up Configuration Files

Here's how to make a duplicate of the /etc/fstab file so that you can always retain the original configuration for reference or to recover from a failed configuration attempt:

![](img/782ecfdc0b083a767896cc983e10427f_183_1.png)

> The solemn and unbreakable rule of thumb here is NEVER tinker with any configuration file without backing it up first.

- 1. Log into the root account.
- 2. Change to the /etc directory. Type cd /etc and press Enter.
- 3. Copy the fstab file. Type cp fstab fstab.orig and press Enter. This identifies the file as being the original configuration. If you use the -p command option, you can change the modification date and time to the time that the copy was made.
