# Dealing with Program Crashes

It's not an everyday occurrence in Linux, but every now and then, a program crashes. You know the routine... everything is working fine, then all of a sudden, the program hoses and either locks up on you or disappears into thin air. When this happens, the system creates a core dump file that contains all kinds of information. As you can tell from the core dump in Figure 17.1, much of this information looks like gibberish. But, to the trained eye, it contains important debugging information.

**New Term** A core dump is a file that is written to your home directory whenever there is a failure (also known as a crash) somewhere in the system. A core dump contains the process information that is stored in memory at the time of the failure.

Looking at Figure 17.1, you'll notice that the core dump file can be quite large. In this example, the core dump file is 8,738 lines long (and almost 2MB in size). That's a lot of used space on your hard drive and a ton of reading material. If a core dump appears in your home directory, you can read the contents in the less pager. To do this from the command line, change to the directory in which the core dump file is stored and type less core.

One way to find the cause of a core dump is to use a debugging program such as gdb (as shown in Listing 17.1). Toward the end of the listing, you'll see that the program that caused the error was kshow, and it failed because of a segmentation fault.
