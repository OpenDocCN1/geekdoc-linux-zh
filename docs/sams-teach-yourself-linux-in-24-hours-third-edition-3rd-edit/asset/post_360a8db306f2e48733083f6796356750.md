New kernel iterations appear in response to Linux users' desires to have drivers for a new gadget or to have bugs fixed. There are certainly other reasons, but the big focus for most Linux users is on new drivers and bug fixes.

## Working with Kernel Modules

New additions to the kernel for new drivers and bug fixes are managed through the use of kernel modules. Some of these are dynamic modules that can be loaded when needed and removed to free up space when they are not being used. This helps to keep the size of the kernel manageable. New drivers don't have to be built into the kernel itself; they can be made into modules.

## What Are Loadable Modules?

The kernel upgrade process is managed through the use of loadable modules. *Loadable modules* are separate pieces of kernel code that are not included (linked) directly into the kernel. They can be compiled separately and inserted into, or removed from, a running kernel as needed or requested. Loadable modules are the preferred way to code drivers for many of the new devices that are appearing daily. Also, because the size of the Linux kernel has grown a lot recently and the complexity and size of the device drivers have also increased the module size, compression utilities are a must for reasonable download file size.

![](img/782ecfdc0b083a767896cc983e10427f_266_0.png)

> The GNU Hurd aims at being able to modularize everything, including things that are presently built into the Linux kernel, so that any user can pick and choose and use the modules to build a kernel any way he wants or needs.

## Obtaining the Modules Package

To get the source code for the new kernel, you will need to download it from the Internet. The source files that you'll need to get will be in an archived and compressed single file that can be retrieved via anonymous FTP from `ftp.kernel.org/pub/linux/kernel/vx.x.x` (where x.x.x is the version number). It is probably best if you use your country code to get source from the mirror for your country. So, for the United Kingdom, the path would be `ftp.uk.kernel.org/pub/linux/kernel/vx.x.x`, and for France it would be `ftp.fr.kernel.org/pub/linux/kernel/vx.x.x`.

![](img/782ecfdc0b083a767896cc983e10427f_266_1.png)

> It is important to be aware that the system used for numbering kernels has meaning. There are two methods for numbering kernels. The kernels that are assigned even minor numbers (such as 2.2.x) are production or stable kernels with the bugs removed. Those numbered with odd minor numbers (such as 2.3.x) are development kernels made available—often without the bugs removed—for people to test drive and contribute what they can. These kernels are not for the inexperienced user.

After the downloading is complete (hopefully it didn't take too long), you can dig right into the rest of the preparation you need to have a sane, secure, and positive kernel upgrading experience.

Because you probably loaded source files with your current Linux installation, you should have a directory in which the original source tree is still installed. It would be a good idea, if your drive has the space, to save your original source tree just in case you want to go back. To do this, change to the /usr/src directory and list the contents. One of the things you'll find is a subdirectory called /usr/src/linux, which contains the Linux source tree for your present installation. Rename this directory, by using the mv command, to something other than /linux. A common renaming scheme is to add the old kernel version number to the directory's name, as in linux-2.x.x. But just make sure that there is no directory named /linux in /usr/src.

> The installation program for the Linux-Mandrake and TurboLinux distributions renames the directory to linux-2.2.x automatically. Other distributions might also do the same, but inside this directory is an /include directory that contains the directory called /linux. However, there is no need to change the name of this directory to keep the files intact. Instead, there is a symbolic link called linux in the /usr/src directory. That link points to the linux-2.x.x directory that you must rename to something other than linux.

You're now finished with the preparation phase, and it is time to get on to the action phase. To begin, you need to unpack the source code that you downloaded. To do this make sure you are in /usr/src and type

```
tar xpvf linux-2.x.x.tar.gz
```

where 2.x.x is the kernel version you downloaded. After you have untarred the source code, read the README file! The README file found with the unpacked archive files will be the most up-to-date advice that you are going to get from the people at your favorite Linux distribution. Because they were the ones who introduced their own little variations into the soup, they are the ones who know what you should most exactly do next! After you finish reading the README, the only thing left is taking the plunge.

> In Hour 2, "Installing Linux-Mandrake," it was suggested that you create a boot disk. Make sure that you have this disk before you begin. You can also create the boot disk with the mkbootdisk command.

## Rebuilding the Kernel

Now you are really going to do it. First, of course, you will have to clean up some things and decide what you are going to use to do it with. To put things in order, first type

```
cd /usr/src/linux
```

and then type

```
make mrproper
```

This will clean up any leftover mess that might be lying around. Then type

```
make menuconfig
```

If you are running the X Window System, you have an alternative choice. You can type `make xconfig`, which will give you a graphical interface to use. Both will put the configuration options in menu hierarchies to make it easier for you to follow.

Now what you must do (with the Kernel HOWTO in hand) is go slowly and carefully through the list of kernel options. You will answer y for yes and n for no, wherever appropriate. You'll see m whenever you are offered the choice to make modules of things. You should try to modularize as much as you can. By modularizing, you can reduce some kernel memory requirements because the modules can be loaded on-the-fly. However, some things are needed for boot and cannot be made into modules. Read carefully! When you have finished, type

```
make dep
```

This will set up dependencies and make the source ready for compiling.

## Compile the Source Code

You are getting closer all the time. Now we will make some things that you need. Type

```
make bzImage
```

This will create a compressed kernel image. Now type

```
make modules
```

This will compile the modules that you just configured. Now type

```
make modules_install
```

Now, to install the new kernel, type

```
make install
```

This will copy your new kernel and system.map to the boot directory, /boot, with the version and all the correct names, and it will change the respective links. It will also back up your old files with a .old extension and run lilo to fix it for your new kernel. If you want to, you can use linuxconf later to set up lilo to boot either the new or the old kernel when you choose, if that is desired.

That's it! You're finished! Well, almost... Pour yourself a stiff drink, assume a praying-like posture in front of your computer, and reboot. You will be enjoying the fruits of your labors, with the new kernel working just as you envisioned and everything running perfectly, in minutes. Anyway, if it doesn't work, you still have the old kernel that you can boot back into and try it again.

## Summary

During the past hour, you followed the long and involved process of upgrading the Linux kernel. Remember that it isn't always necessary to upgrade every piece of software, utility, command, kernel, library, and programming language every time a new version comes out. Think before you upgrade. Will the upgrade be beneficial to you and your system? If you don't see the added value, don't do it. But, if you need the new kernel to support the fancy new piece of hardware that you just purchased, carefully read this chapter again and read the other sources of information listed in this hour so that you are well prepared.

## Q&A

Q Is there an easier way to upgrade my system? This kernel stuff is more than I can deal with and I'm afraid of wrecking my system.
A You might want to wait until the next version of your favorite Linux distribution comes out. When you install the new version, you can select the Upgrade option when the installation starts. Not only will the kernel be updated, but all your favorite applications will be upgraded as well.

Q How do I find out which version of the Linux kernel is installed on my system?
A That's an easy one! Just type `uname -a` and press Enter at the command line. Not only will you see the kernel version, but you'll also see the hostname of the computer, the number of times the kernel has been compiled, the date on which the kernel was compiled, and the model of the computer's processor.
