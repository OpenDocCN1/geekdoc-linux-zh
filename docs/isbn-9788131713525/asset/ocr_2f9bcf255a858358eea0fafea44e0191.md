# 14.5 When It Doesn't Boot

We can easily determine the linked location of this buffer from the Linux kernel map file System.map.

```
`% grep __log_buf System.map
   c022e548 b _log_buf`
```

Now if the system happens to hang upon booting, right after displaying the “Uncompressing Kernel Image... OK” message, reboot and use the bootloader to examine the buffer. Because the relationship between kernel virtual memory and physical memory is fixed and constant on a given architecture, we can do a simple conversion. The address of `__log_buf` shown earlier is a kernel virtual address; we must convert it to a physical address. For this particular PowerPC architecture, that conversion is a simple subtraction of the constant KERNELBASE address, 0xc0000000. This is where we probe in memory to read the contents, if any, of the `printk` log buffer.
