
*All*：拒绝所有客户端访问内容。

*host*：拒绝由*host*指定的客户端访问内容。*host*可以有多种形式：*host*可以是FQDN、部分域名（例如`example.com`）、IP地址、部分IP地址，或者网络/掩码对。

*var*：当名为*var*的环境变量被设置时，拒绝访问内容。你可以使用SetEnvIf指令设置变量。

-   上下文：`directory`、`.htaccess`
-   默认值：无
-   Fedora/RHEL：无

*Order* 指定默认访问权限以及Allow和Deny指令的评估顺序。

```
Order Deny,Allow | Allow,Deny
```

**Deny,Allow**：默认允许访问；仅拒绝在Deny指令中指定的客户端访问。（先评估Deny指令，然后评估Allow指令。）

**Allow,Deny**：默认拒绝访问；仅允许在Allow指令中指定的客户端访问。（先评估Allow指令，然后评估Deny指令。）

通过此指令授予或拒绝的访问权限适用于该指令所在的容器或`.htaccess`文件中指定的目录层次结构。

逗号两侧不得有空格。尽管Fedora/RHEL的默认值为Allow,Deny，即拒绝所有未由Allow指令指定的客户端访问，但`httpd.conf`中的下一个指令`Allow from all`允许所有客户端访问：

```
Order allow,deny
Allow from all
```

通过指定Deny,Allow来拒绝所有访问，然后仅在Allow指令中指定你想要授予访问权限的客户端，从而限制访问。以下指令仅授予`example.net`域中客户端的访问权限，通常出现在`<Directory>`容器中（第855页）：

```
Order deny,allow
Deny from all
Allow from .example.net
```

-   上下文：`directory`、`.htaccess`
-   默认值：Deny,Allow
-   Fedora/RHEL：Allow,Deny

### 重定向

Apache可以通过要求客户端请求不同的URL来响应URL请求。这种响应称为*重定向*。重定向之所以起作用，是因为重定向是HTTP实现的一部分：Apache发送适当的响应码和新URL，而合规的浏览器则请求新位置。

`Redirect`指令可以建立显式重定向，当Web站点移动时将客户端发送到不同的页面。或者，当用户在浏览器中输入目录的URI但省略尾部斜杠时，Apache可以自动将客户端重定向到以斜杠结尾的相同URI。

**UseCanonicalName**
`ServerName`指令（第852页）定义了服务器名称，`UseCanonicalName`指令（第861页）在服务器拥有多个名称且需要执行自动重定向时都非常重要。例如，假设名为`zach.example.com`且别名为`www.example.com`的服务器将`ServerName`设置为`www.example.com`。当客户端指定目录的URI但省略尾部斜杠（`zach.example.com/dir/`）时，Apache必须执行重定向以确定所请求目录的URI。当`UseCanonicalName`设置为`On`时，Apache使用`ServerName`的值并返回`www.example.com/dir/`。当`UseCanonicalName`设置为`Off`时，Apache使用传入请求中的名称并返回`zach.example.com/dir/`。
