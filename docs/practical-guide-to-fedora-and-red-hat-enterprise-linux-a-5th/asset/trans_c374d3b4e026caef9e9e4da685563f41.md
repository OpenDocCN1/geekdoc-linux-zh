
# 功能齐全的域名服务器

当带有 status 参数时，named 初始化脚本会显示有用的信息：

```
# /sbin/service named status
version: 9.6.1-P1-RedHat-9.6.1-11.P1.fc12
CPUs found: 1
worker threads: 1
number of zones: 15
debug level: 0
xfers running: 0
xfers deferred: 0
soa queries in progress: 0
query logging is OFF
recursive clients: 0/0/1000
tcp clients: 0/100
server is up and running
named (pid 31903) is running...
```

创建或更新 DNS 信息时，可以使用 **dig** 或 **host** 来测试服务器是否按预期工作。**dig** 最有用的部分通常是应答部分（answer section），它显示了域名服务器对您查询的回复：

```
$ dig example.com
...
;; ANSWER SECTION:
example.com.            172800 IN A 192.0.32.10
...
```

上述输出显示 **example.com** 域名有一条单独的 A 记录，该记录指向 192.0.32.10。此记录的 TTL（生存时间）指示该记录在缓存中可保留的时长，为 172,800 秒（即两天）。您还可以使用 **dig** 配合 **-t** 选项后加上要查询的记录类型来查询其他类型的记录（**-t** 也适用于 **host**）：

```
$ dig -t MX redhat.com
...
;; ANSWER SECTION:
redhat.com.         600 IN MX 5 mx1.redhat.com.
redhat.com.         600 IN MX 10 mx2.redhat.com.
...
```

如果您查询一个不存在的域名，**dig** 会返回查询中最高层级且实际存在的权威部分的 SOA 记录：

```
$ dig domaindoesnotexist.info
...
;; AUTHORITY SECTION:
info.                 900 IN SOA a0.info.afiliaos-nst.info. ...
...
```

由于它告诉您最后被正确查询的区域，因此这些信息在故障排查时可能很有用。

> **TSIG** 如果两个使用 TSIG（见第 803 页）的服务器无法通信，请检查两台服务器的时间是否相同。TSIG 认证机制依赖于当前时间。如果两台服务器的时钟不同步，TSIG 将失败。建议在这些服务器上配置 *NTP*（见第 1097 页）以防止此问题。

因为此示例中使用的 IP 地址属于*私有地址空间*（见第 1100 页），您可以复制该示例并运行服务器而不会影响全局 DNS。此外，为了防止污染全局 DNS，每个区域都设置了 *notify* 选项为 NO。当您构建与互联网集成的域名服务器时，希望使用您安装环境中独有的 IP 地址。您可能需要更改 *notify* 语句的设置。

此示例中的 *named.conf* 文件限制了 *named* 应答查询的 IP 地址，并设置了日志记录：

```text
$ cat /etc/named.conf
options {
    directory "/var/named";
    allow-query {127.0.0.1; 192.168.0.0/24;};

zone "." IN {
    type    hint;
    file    "named.ca";};

zone "0.168.192.in-addr.arpa" IN {
    type    master;
    file    "named.local";
    notify  NO;
};

zone "sam.net" IN {
    type    master;
    file    "sam.net";
    notify  NO;
};

logging{
    channel "misc" {
        file "/var/log/bind/misc.log" versions 4 size 4m;
        print-time YES;
        print-severity YES;
        print-category YES;
    };
    channel "query" {
        file "/var/log/bind/query.log" versions 4 size 4m;
        print-time YES;
        print-severity NO;
        print-category NO;
    };
    category default {
        "misc";
    };
    category queries {
        "query";
    };
}
```

Options 部分中的 **allow-query** 语句指定了服务器将应答来自哪些系统 IP 地址的查询。如果本地系统也要查询该服务器，必须将其包含为 127.0.0.1。该服务器拥有权威的区域是 **sam.net**；sam.net 的区域文件是 /var/named/sam.net。

**日志记录** 日志记录由 Logging 部分开启。此部分打开了两个日志通道：一个将信息记录到 /var/log/bind/misc.log，另一个将信息记录到 /var/log/bind/query.log。当其中一个日志增长到 4 兆字节（文件语句中的 **size 4m**）时，它会通过在其文件名后追加 **.1** 进行重命名，并启动一个新的日志。其他类似命名的日志末尾的数字会递增。任何编号大于 **versions** 子句指定值的日志（示例中为 **4**）都会被删除。有关维护日志文件的另一种方法，请参阅 *logrotate*（第 579 页）。**print** 语句确定信息的时间、严重性和类别是否发送到日志；每个选项指定为 YES 或 NO。类别确定什么信息会被记录到该通道。在示例中，默认信息被发送到 **misc** 通道，查询被发送到 **query** 通道。更多选项请参阅 named.conf 手册页。

**named.local** 反向区域文件（named.local）的起始（origin）是 0.168.192.in-addr.arpa（如 named.conf 中引用此文件的 Zone 部分所指定）。在 SOA 和 NS 资源记录之后，前三个 PTR 资源记录分别将子网 0.168.192.in-addr.arpa（即 192.168.0.1）中的地址 1 与名称 **gw.sam.net.**、**www.sam.net.** 和 **ftp.sam.net.** 对应起来。接下来的三个 PTR 资源记录将 192.168.0.3 对应为 **mark.sam.net.**，192.168.0.4 对应为 **mail.sam.net.**，192.168.0.6 对应为 **ns.sam.net.**。

```
$ cat named.local
;	zone "0.168.192.in-addr.arpa"
;
$TTL		3D
	@		IN	SOA	ns.sam.net.	mgs@sobel11.com. {
						;	serial
						2005110501
						;	refresh
						8h
						;	retry
						2h
						;	expire
						4w
						;	minimum
						1D)

		IN		NS	ns.sam.net.
1		IN		PTR	gw.sam.net.
1		IN		PTR	www.sam.net.
1		IN		PTR	ftp.sam.net.
3		IN		PTR	mark.sam.net.
4		IN		PTR	mail.sam.net.
6		IN		PTR	ns.sam.net.
```

**sam.net** sam.net 的区域文件利用了 BIND 的许多功能，并包含 TXT（第 782 页）、CNAME（第 780 页）和 MX（第 780 页）资源记录。当您查询资源记录时，named 会返回 TXT 资源记录以及您请求的记录。两条 NS 记录中的第一条指定了一个非限定名称（ns），BIND 会为其追加区域名称（**sam.net**），生成完整限定域名（FQDN）为 ns.sam.net。第二个域名服务器是通过 BIND 不修改的 FQDN 名称指定的。MX 记录以类似的方式指定邮件服务器，并在数据字段的开头包含一个优先级数字；较小的数字表示优先服务器。

```
$ cat sam.net
; zone "sam.net"
;
$TTL 3D
@       IN      SOA     ns.sam.net. mgs@sobell.com. (
                200511051 ; serial
                8H        ; refresh
                2H        ; retry
                4W        ; expire
                1D )    ; minimum

        TXT     "Sobel1 Associates Inc.";
        NS      ns        ; Nameserver address (unqualified)
        NS      ns.max.net.; Nameserver address (qualified)
        MX      10 mail   ; Mail exchange (primary/unqualified)
        MX      20 mail.max.net.; Mail exchange (2nd/qualified)

localhost IN    A       127.0.0.1

www       IN      CNAME   ns
ftp       IN      CNAME   ns

gw        IN      A       192.168.0.1
        TXT     "Router"

ns        IN      A       192.168.0.6
        MX      10 mail
        MX      20 mail.max.net.

mark      IN      A       192.168.0.3
        MX      10 mail
        MX      20 mail.max.net.
        TXT     "MGS"

mail      IN      A       192.168.0.4
        MX      10 mail
        MX      20 mail.max.net.
```

某些资源记录在名称（Name）字段中有一个值；那些没有名称的资源记录会从上一个资源记录继承名称。类似地，上一个资源记录可能也有继承的名称值，以此类推。SOA 资源记录之后的五个资源记录从 SOA 资源记录继承 @，即区域名称。这些资源记录与整个区域相关。在上面的示例中，第一个 TXT 资源记录从其名称从 SOA 资源记录继承；它是 sam.net 区域的 TXT 资源记录（执行命令 host -t TXT sam.net 可以显示该 TXT 资源记录）。

在这五个资源记录之后，是属于区域内某个域名的资源记录。例如，在 Name 字段设置为 mark 的 A 资源记录之后的 MX 资源记录，是 mark.sam.net. 域名的资源记录。
