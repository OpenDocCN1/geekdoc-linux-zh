
## yum：保持系统更新

Red Hat Linux 的早期版本未包含用于管理更新的工具。尽管 `rpm` 实用程序可以安装或升级单个软件包，但查找软件包及其依赖的软件包仍然需要用户手动完成。当 Terra Soft 公司为其 PowerPC 架构的 Red Hat 基础 Linux 发行版提供支持时，该公司创建了 Yellow Dog Updater 来填补这一空白。随后，该程序被移植到其他架构和发行版中。其结果被称为 Yellow Dog Updater, Modified（yum，wiki.linux.duke.edu/Yum），并包含在 Fedora/RHEL 中。

`yum` 实用程序与 `rpm` 软件包配合使用。当 `yum` 安装或升级软件包时，它还会安装或升级该软件包所依赖的其他软件包。有关 `rpm` 的更多信息，请参阅第 510 页。

`yum` 实用程序从被称为软件仓库（repositories）的服务器下载软件包头和软件包。虽然 Fedora 提供了软件仓库，但 `yum` 默认配置为使用镜像站点上维护的这些仓库副本。RHEL 使用 Red Hat Network（第 516 页）。下一节将介绍软件仓库的选择。

### 配置 yum

你无需配置 `yum`：安装后即可直接使用。本节为希望修改配置文件的用户描述了 `yum` 配置文件。主要配置文件 `/etc/yum.conf` 包含全局设置。在 Fedora 发行版中，`/etc/yum.repos.d` 目录中的次要文件定义了软件仓库。第一个示例展示了一个 `yum.conf` 文件：

```
$ cat /etc/yum.conf
[main]
cachedir=/var/cache/yum/$basearch/$releasever
keepcache=0
debuglevel=2
logfile=/var/log/yum.log
exactarch=1
obsoletes=1
gpgcheck=1
plugins=1
installonly_limit=3
...
# PUT YOUR REPOS HERE OR IN separate files named file.repo
# in /etc/yum.repos.d
```

标记为 `[main]` 的部分定义了全局配置选项。`cachedir` 指定 `yum` 存储已下载软件包的目录，尽管当 `keepcache` 设置为 0 时，`yum` 在安装后不会存储包头和软件包。`debuglevel` 指定记录的信息量，值为 10 时产生最多的信息。`logfile` 指定 `yum` 保存日志的位置。

你还可以配置 `yum` 从特定服务器安装，并在失败时回退到其他服务器。

将 **exactarch** 设置为 **1** 可使 `yum` 仅使用相同架构的软件包进行更新，从而防止例如 i686 软件包替换 i386 软件包。你可以使用 **retries** 来指定 `yum` 在返回错误之前尝试获取文件的次数（默认为 6）。将此参数设置为 0 将使 `yum` 无限重试。

将 **obsoletes** 设置为 **1** 可使 `yum` 在执行更新时替换已过时的软件包；它在安装过程中不起作用。当 **gpgcheck** 设置为 **1** 时，`yum` 会检查其安装软件包上的 GPG（第 1048 页）签名。此检查验证软件包的真实性。将 **plugins** 设置为 **1** 可启用 `yum` 插件，从而扩展 `yum` 的功能。（有关 `yum` 插件的更多信息，请参阅 wiki.linux.duke.edu/YumPlugins 以及 man 页面中第 8 部分的 `yum`。）**metadata_expire** 参数指定 `yum` 使用从软件仓库下载的有关软件包的元数据的时长（以秒为单位，如果数值后跟 m 则为分钟），之后才会再次下载该信息。此参数默认为 90 分钟。

虽然有关 `yum` 仓库的其余配置信息可以出现在 **yum.conf** 文件中，但 Fedora/RHEL 将每个仓库的信息放在 **/etc/yum.repos.d** 目录中的单独文件中。在仓库部分中设置的参数会覆盖 **[main]** 部分中设置的同名参数。

```
$ ls /etc/yum.repos.d
fedora-rawhide.repo       fedora-updates.repo
fedora-updates-testing.repo fedora.repo
```

这些文件中的每一个都包含一个标题，例如 **[fedora]**，它为仓库提供了一个唯一名称。文件名通常与仓库名称相似，并带有 **fedora-** 前缀和 **.repo** 文件扩展名。常用的仓库包括 **installed**（保存在 **fedora.repo** 文件中），其中包含安装 DVD 上存在的软件包；**updates**（保存在 **fedora-updates.repo** 文件中），其中包含稳定软件包的更新版本；以及 **updates-testing**（保存在 **fedora-updates-testing.repo** 文件中），其中包含尚未准备好发布的更新。最后一个仓库默认未启用；除非你正在测试不稳定的软件包，否则不要启用它。切勿在生产系统上启用 **updates-testing** 仓库。

> **可选** 每个 *.repo* 文件包含多个相关仓库的规范，这些仓库通常处于禁用状态。例如，**fedora.repo** 文件除了包含 **[fedora]** 外，还包含 **[fedora-debuginfo]** 和 **[fedora-source]**。你不能使用 `yum` 下载源文件。相反，请为此任务使用 **yumdownloader**（第 505 页）。

下一个示例展示了 **fedora.repo** 文件的一部分，该部分指定了 **fedora** 仓库的参数：

```
$ cat /etc/yum.repos.d/fedora.repo
[fedora]
name=Fedora $releasever - Basearch
failovermethod=priority
#baseurl=http://download.fedoraproject.org/pub/fedora/linux/releases/$releasever/Everything/$basearch/os/
mirrorlist=https://mirrors.fedoraproject.org/metalink?repo=fedora-$releasever&arch=$basearch
enabled=1
metadata_expire=7d
gpgcheck=1
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-fedora-$basearch
...
```

每个仓库规范都包含用括号 ([ ]) 包围的仓库名称、一个 **name**、一个 **failovermethod**、一个 **baseurl** 和一个 **mirrorlist**。**name** 为仓库提供了一个非正式名称，由 `yum` 显示。**failovermethod** 确定 `yum` 联系初始镜像站点和（如果第一个站点失败时）额外镜像站点的顺序；**priority** 按出现的顺序选择站点，而 **roundrobin** 随机选择站点。**baseurl** 指示主仓库的位置；默认情况下它是被注释掉的。**mirrorlist** 指定了一个文件的 URL，该文件保存了主仓库的 **baseurls**（或镜像）列表。在同一时间只能启用 **baseurl** 或 **mirrorlist** 中的一个。这些定义使用两个变量：`yum` 将 **$basearch** 设置为系统架构，将 **$releasever** 设置为发行版本（例如 Fedora 12 中的 12）。

如果 **enabled** 设置为 1，则该文件描述的仓库将被启用（`yum` 将使用它）；如果 **enabled** 设置为 0，则被禁用。**metadata_expire** 指定 `yum` 认为元数据有效的时长。在此时间之后，`yum` 将下载新的元数据。如前所述，**gpgcheck** 确定 `yum` 是否检查其下载文件上的 GPG 签名。**gpgkey** 指定 GPG 密钥的位置。有关更多选项，请参阅 **yum.conf** 的 man 页面。

## 使用 yum 更新、安装和删除软件包

以 **root** 身份操作时，你可以从命令行运行 `yum`。`yum` 的行为取决于你指定的选项。**update** 选项在没有附加参数的情况下，会更新所有已安装的软件包。它会下载已安装软件包的包头，确定哪些软件包需要更新，提示你继续，然后下载并安装更新的软件包。

在以下示例中，`yum` 确定四个软件包需要更新并检查依赖关系。一旦确定了需要执行的操作，`yum` 会告知你将要采取的行动，提示你 **Is this ok [y/N]**（是否继续 [y/N]），然后下载并更新软件包。

```
# yum update
Loaded plugins: presto, refresh-packagekit
Setting up Update Process
Resolving Dependencies
--> Running transaction check
---> Package selinux-policy-targeted.noarch 0:3.6.32-46.fc12 set to be updated
---> Package xor-g-11-driv-evedev.1686 0:2.3.0-4.fc12 set to be updated
---> Package xor-g-11-driv-keyboard.1686 0:1.4.0-2.fc12 set to be updated
---> Package xor-g-11-driv-synaptics.1686 0:1.2.0-2.fc12 set to be updated
--> Finished Dependency Resolution
```
