
将**yes**设为**是**，将TCP服务设为**否**。如果你将*telnet*等服务的**wait**设为是，则在任何给定时间只有一人能够使用该服务。

**用户**指定服务器以哪个用户身份运行。如果此用户属于多个组，你还可以使用关键字**group**在单独的一行中指定组。

如果**xinetd**未以**root**权限运行，则会忽略**user**指令。服务器提供**xinetd**为此服务运行的服务器程序的路径名。

唯一的**from**指定允许**xinetd**使用该服务的系统。建议使用仅IP地址——如果使用主机名，则在DNS故障时可能导致服务不可用。IP地址右侧的零被视为通配符。例如，**192.168.0.0**允许来自**192.168**子网中任何系统的访问。

**disable**行禁用服务而不删除配置文件。如Fedora/RHEL发行版所示，许多服务包含一个**xinetd**配置文件，其中**disable**设置为**yes**。要运行这些服务之一，请在**xinetd.d**中相应的文件中将**disable**更改为**no**，然后重启**xinetd**：

```
# /sbin/service xinetd restart
Stopping xinetd: [ OK ]
Starting xinetd: [ OK ]
```

## 加固服务器

你可以通过使用TCP包装器或设置chroot jail来加固服务器。

### TCP包装器：客户端/服务器安全（HOSTS.ALLOW 和 HOSTS.DENY）

当你将本地系统打开以供远程系统访问时，必须确保满足以下条件：

- 仅将你希望允许其访问的系统打开到本地系统。
- 允许每个远程系统仅访问你希望其访问的数据。
- 允许每个远程系统仅以适当的方式（只读、读/写、仅写）访问数据。

作为客户端/服务器模型的一部分，可用于任何链接到**libwrap.so**的守护进程的TCP包装器，依赖于*/etc/hosts.allow*和*/etc/hosts.deny*文件作为简单访问控制语言的基础。此访问控制语言定义了规则，基于客户端的地址和客户端尝试访问的守护进程，有选择地允许客户端访问本地系统上的服务器守护进程。

**hosts.allow**和**hosts.deny**文件中的每一行具有以下格式：

```
*daemon_list* : *client_list* [ : *command* ]
```

其中*daemon_list*是一个或多个服务器守护进程（例如**rbind**、**vsftpd**或**sshd**）的逗号分隔列表，*client_list*是一个或多个客户端的逗号分隔列表（参见第442页的表11-3“指定客户端”），可选的*command*是当来自`client_list`的客户端尝试访问来自`daemon_list`的服务器守护进程时执行的命令。

当客户端请求与本地服务器连接时，按照以下方式查询`hosts.allow`和`hosts.deny`文件，直到找到匹配项：

1. 如果守护进程/客户端对匹配`hosts.allow`中的一行，则允许访问。
2. 如果守护进程/客户端对匹配`hosts.deny`中的一行，则拒绝访问。
3. 如果在`hosts.allow`或`hosts.deny`文件中都没有匹配项，则允许访问。

第一个匹配项确定客户端是否被允许访问服务器。如果`hosts.allow`或`hosts.deny`不存在，则就好像该文件为空一样。虽然不推荐，但你可以通过删除这两个文件来允许所有客户端访问所有守护进程。

**示例** 为了获得更安全的系统，请在`hosts.deny`中放入以下行以阻止所有访问：

```
$ cat /etc/hosts.deny
ALL : ALL : echo '%c tried to connect to %d and was blocked' >> /var/log/tcpwrappers.log
```

此行阻止任何客户端连接任何服务，除非在`hosts.allow`中特别允许。当匹配此规则时，它会向名为`/var/log/tcpwrappers.log`的文件中添加一行。`%c`扩展为客户端信息，`%d`扩展为客户端尝试连接的守护进程名称。

在放置上述`hosts.deny`文件的情况下，你可以在`hosts.allow`中包含明确允许访问某些服务和系统的行。例如，以下`hosts.allow`文件允许任何人连接到OpenSSH守护进程（`ssh`、`scp`、`sftp`），但仅允许来自与本地系统相同网络的用户以及192.168子网中的用户进行telnet连接：

```
$ cat /etc/hosts.allow
sshd : ALL
in.telnetd : LOCAL
in.telnetd : 192.168.* 127.0.0.1
```

第一行允许任何系统（ALL）连接到sshd。第二行允许与服务器在同一域中的任何系统（LOCAL）连接。第三行匹配IP地址以192.168.开头的任何系统以及本地系统。

### 设置CHROOT JAIL

在早期的UNIX系统中，根目录是文件系统中的固定点。在现代UNIX变体中，包括Linux，你可以按进程定义根目录。chroot实用程序允许你运行根目录不是/的进程。

根目录位于目录层级的顶部，没有父级：进程无法访问根目录上方的任何文件（因为它们在根目录上下文中不存在）。例如，如果你运行一个程序（进程）并指定其根目录为/home/sam/jail/，那么该程序将不会概念化/home/sam或更高处的任何文件：jail是程序的根目录，并标记为/（而不是jail）。

通过创建一个人工根目录，通常称为（chroot）jail，你可以防止程序访问或修改——可能带有恶意意图——其根开始的目录层级之外的文件。你必须正确设置chroot jail以提高安全性：如果你没有正确设置chroot jail，实际上可能会使恶意用户更容易获得系统访问权限，甚至比没有chroot jail时更容易。

#### 使用chroot

创建chroot jail很简单：作为root工作，输入命令/usr/sbin/chroot directory。目录成为根目录，进程尝试运行默认shell。从/home/sam目录以root权限工作，输入以下命令在（现有的）/home/sam/jail目录中设置chroot jail：

```
# /usr/sbin/chroot /home/sam/jail
/usr/sbin/chroot: cannot run command '/bin/bash': No such file or directory
```

此示例设置了一个chroot jail，但当它尝试运行bash shell时，操作失败。一旦设置好jail，名为jail的目录就被视为根目录/，因此chroot无法找到由路径名/bin/bash标识的文件。在这种情况下，chroot jail正在工作，但没有用。

让chroot jail按你想要的方式工作要复杂一些。为了让前面的示例在chroot jail中运行bash，你需要在jail（/home/sam/jail/bin）中创建一个bin目录，并将/bin/bash复制到该目录。由于bash二进制文件动态链接到共享库，你还需要将这些库复制到jail中。库放在lib中。

下一个示例创建必要的目录，复制bash，使用ldd显示bash的共享库依赖项，并将必要的库复制到lib中。linux-gate.so.1文件是一个由内核提供的动态共享对象（DSO），用于加速系统调用；你不需要将它复制到lib目录中。

```
$ pwd
/home/sam/jail
$ mkdir bin lib
$ cp /bin/bash bin
$ ldd bin/bash
    linux-gate.so.1 =>  (0x0089c000)
    libtinfo.so.5 => /lib/libtinfo.so.5 (0x00cdd000)
    libdl.so.2 => /lib/libdl.so.2 (0x00bb0000)
    libc.so.6 => /lib/libc.so.6 (0x009c9000)
    /lib/ld-linux.so.2 (0x0099a000)
$ cp /lib/{libtinfo.so.5,libdl.so.2,libc.so.6,ld-linux.so.2} lib
```

现在一切都设置好了，你可以再次启动chroot jail。虽然所有设置可以由普通用户完成，但你必须以超级用户身份运行chroot：

```
$ su
Password:
# /usr/sbin/chroot .
bash-3.2# pwd
/
bash-3.2# ls
bash: ls: command not found
bash-3.2#
```

这次chroot找到并启动了**bash**，它显示其默认提示符（*bash-3.2#*）。**pwd**命令有效，因为它是一个shell内建命令（第247页）。然而，**bash**找不到**ls**实用程序（它不在chroot jail中）。如果你希望jail中的用户能够使用ls，你可以将/bin/ls及其库复制到jail中。

要设置一个有用的chroot jail，首先确定chroot jail的用户需要哪些实用程序。然后将适当的二进制文件及其库复制到jail中。或者，你可以构建二进制文件的静态副本并将它们放入jail中，而无需安装单独的库。（静态链接的二进制文件比其动态版本大得多。包含**bash**和核心实用程序的基础系统超过50兆字节。）你可以在**bash**和coreutils SRPMS（source rpm）软件包中找到大多数常见实用程序的源代码。

无论你选择哪种技术，你都必须在jail中放入**su**的副本。**su**命令是作为非**root**用户运行程序所必需的。由于**root**可以打破chroot jail，因此作为非**root**用户在chroot jail中运行程序至关重要。

Fedora/RHSEL分发的动态版本**su**需要PAM，无法在jail中工作。你需要从源代码构建一个**su**副本以在jail中使用。默认情况下，你构建的任何**su**副本都不需要PAM。请参考第513页的“GNU Configure and Build System”以了解如何构建coreutils（包含**su**）等软件包的说明。

要使用**su**，你必须将/etc/passwd和/etc/shadow文件中的相关行复制到jail内部**etc**目录中同名文件中。

### 在CHROOT JAIL中运行服务

在jail内部运行shell实用性有限。实际上，你更可能需要的是在jail内部运行特定服务。要在jail内部运行服务，你必须确保该服务所需的所有文件都在jail内部。在chroot jail中启动服务的命令格式为

```
# /usr/sbin/chroot jailpath /bin/su user daemnoname &
```
