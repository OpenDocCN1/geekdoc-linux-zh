

## 执行命令

### 派生与休眠
当你向 shell 发送一条命令时，它通常会*派生*（*创建*）一个子进程来执行该命令。在子*进程*执行命令期间，父*进程*会*休眠*。当一个*进程*处于*休眠*状态时，它*不会*使用任何计算机时间，而是保持非活跃状态，等待唤醒。当子*进程*完成命令执行后，它会通过其*退出*状态向父进程报告成功或失败，然后*终止*。父*进程*（正在运行*shell* 的那个）会醒来，并提示输入下一条*命令*。

### 后台进程
当你在命令末尾加上*和号*（**&**）从而在后台运行一个*进程*时，*shell* 会*派生*一个子*进程*，而不会进入*休眠*状态，也不*等待*该子*进程*运行至*完成*。正在执行*shell* 的父*进程*会报告该子*作业*编号和*PID* 编号，并提示输入下一条*命令*。子*进程*在*后台*运行，与其*父进程*是*独立*的。

### 内置命令
尽管*shell* 会*派生*一个*进程*来执行你提供的*大多数***命令*，但有些*命令*是*内置*于*shell* 中的。*shell* 无需*派生*一个*进程*即可运行*内置命令*。更多信息请参阅第 247 页的“*内置命令*”。

### 变量
在一个*给定*的*进程*中，例如*你的***登录***shell* 或*一个***子 shell*，你可以*声明*、*初始化*、*读取* *以及* *修改变量*。但*默认***情况下*，*一个***变量* 是*局部于* *该***进程*的。当*一个***进程***派生** 一个*子***进程**时，*父进程***不会***传递***该***变量***的值***给***子进程**。你*可以* 通过*使用* *export* *内置命令*（第 926 页）使*一个***变量***的值***对***子进程***可用***（全局）**。

## 历史记录

*历史* *机制*，*一种* *从* C *Shell* *移植* *的功能*，*维护* *一个* *最近* *执行* *的* *命令* *行***列表***，***也***称为***事件*****，***提供了***一种***快速***重新***执行*****列表中***任何***事件***的方式***。*该***机制*****还***允许*****你***执行*****以前*****命令*****的*****变体*****，*****并*****重用*****它们*****中的*****参数*****。*你*可以*复制*你*在*此*登录*会话*或*之前*的*会话*中*使用*过的*复杂*命令*和*参数*，*并*输入*一系列*彼此*略有*不同*的*命令*。*历史*列表*也*充当*你*所*做*事情*的*记录*。当*你*犯*了*错误*但*不确定*自己*做了*什么*，*或者*你想*保留*涉及*一系列*命令*的*过程*记录*时*，*它*可能*会*很有*帮助*。

*history* *内置命令* 会*显示* 历史*列表*。如果*它***没有***显示***，***请***继***续***阅***读*****你***需***要***设***置***一***些***变***量****。

## 控制历史记录的变量

*HISTSIZE* *变量***的***值*****决*****定*****在*****一*****个*****会*****话*****期*****间*****在*****历*****史*****列*****表*****中*****保*****留*****的*****事*****件*****数*****量*****。* 值*在* 100 *到* 1,000 *之*****间*****是*****正*****常*****的*****。*

当*你***从* *shell* ***退***出***时*****，*****最***近***执***行***的***命***令*****会*****被*****保***存*****在*****由***** ***HISTFILE***** 变***量***指***定***的***文***件***中***（***默***认***为*** ~/.bash_history*****）*****。*****下*****一***次*****你***启***动*** shell*** 时*****，*****该***文***件*****会***初***始***化***历***史***列***表*****。***** ***HISTFILESIZE***** 变***量***的***值*****决*****定*****保***存***在*** `HISTFILE` *****（***不***一***定***与*** `HISTSIZE` *****相***同*****）*****中***的***历***史***行***数*****。* `HISTSIZE` 保存会话期间记住的事件数，`HISTFILESIZE` 保存会话之间记住的事件数，而由 `HISTFILE` 指定的文件保存历史列表。参见表 9-7。

### history 有助于查找错误
> 当你犯了命令行错误（不是脚本或程序内部的错误）且不确定哪里出错时，查看历史列表以回顾最近的命令。有时这个列表可以帮助你查明问题所在以及如何修复。

| 变量 | 默认值 | 功能 |
| :--- | :--- | :--- |
| `HISTSIZE` | 500 个事件 | 会话期间保存的最大事件数 |
| `HISTFILE` | `~/.bash_history` | 历史文件的位置 |
| `HISTFILESIZE` | 500 个事件 | 会话之间保存的最大事件数 |

Bourne Again Shell 为每个命令行分配一个顺序事件号。你可以通过在 PS1 中包含 `!`（第 307 页）来显示 bash 提示符中的此事件号。本节的示例在有助于说明命令行为时，会显示带有编号的提示符。

手动输入以下命令或将其放入 `~/.bash_profile`（以影响未来会话），以建立一个包含最近 100 个事件的历史列表：

```bash
$ HISTSIZE=100
```

以下命令使 bash 在登录会话之间保存最近 100 个事件：

```bash
$ HISTFILESIZE=100
```

设置 `HISTFILESIZE` 后，你可以注销并再次登录，上一个登录会话中最近 100 个事件将出现在你的历史列表中。

输入命令 `history` 以显示历史列表中的事件。事件列表按顺序排列，最早的事件位于列表顶部。以下历史列表包含一条用于修改 bash 提示符以显示历史事件编号的命令。历史列表中的最后一个事件是显示该列表的 `history` 命令。

```text
32 $ history | tail
23  PS1="!\n bash$ "
24  ls -l
25  cat temp
26  rm temp
27  vim memo
28  1pr memo
29  vim memo
30  1pr memo
31  rm memo
32  history | tail
```

随着你运行命令且历史列表变长，当你使用 `history` 内置命令时，它可能会超出屏幕顶部。将 `history` 的输出通过管道传递给 `less` 进行浏览，或者输入命令 `history 10` 查看最近 10 个命令。

## 重新执行和编辑命令

你可以重新执行历史列表中的任何事件。此功能可以为你节省时间、精力和烦恼。无需重新输入长命令行，你可以更容易、更快速、更准确地重新执行事件，而不是像必须重新键入整个命令行那样。你可以通过三种方式回忆、修改并重新执行以前执行的事件：你可以使用 `fc` 内置命令（下面介绍）；感叹号命令（第 320 页）；或者使用 Readline 库，它使用类似 vi 或 emacs 的单行编辑器来编辑和执行事件（第 326 页）。

### 使用哪种方法？
> 如果你更熟悉 `vi` 或 `emacs`，而对 `C` 或 `TC` Shell 不太熟悉，请使用 `fc` 或 Readline 库。如果你更熟悉 `C` 或 `TC` Shell，而对 `vi` 和 `emacs` 不太熟悉，请使用感叹号命令。如果难以抉择，请尝试 Readline 库；与其他方面学习 Linux 相比，掌握 Readline 库会比学习感叹号命令给你带来更大的好处。

## `fc`: 显示、编辑和重新执行命令

`fc`（fix command）内置命令允许你显示历史列表，并编辑和重新执行以前的命令。它提供了与命令行编辑器相同的大部分功能。

### 查看历史列表

当你使用 `-l` 选项调用 `fc` 时，它会显示历史列表中的命令。如果不带任何参数，`fc -l` 会以编号列表形式列出最近 16 条命令，最早的出现首位：

```bash
$ fc -l
1024    cd
1025    view calendar
1026    vim letter.adams01
1027    aspell -c letter.adams01
1028    vim letter.adams01
1029    lpr letter.adams01
1030    cd ../memos
1031    ls
1032    rm *0405
1033    fc -l
1034    cd
1035    whereis aspell
1036    man aspell
1037    cd /usr/share/doc/aspell*
1038    pwd
1039    ls
1040    ls man-html
```

使用 `-l` 选项时，fc 内置命令可以接受零个、一个或两个参数。参数指定要显示的历史列表部分：

```text
fc [-l [first [last]]]
```

fc 内置命令列出从与 first 匹配的最新事件开始的命令。参数可以是事件号、命令行开头的几个字符，或者一个负数（表示倒数第 n 个命令）。如果你提供了 last，fc 将显示从与 first 匹配的最新事件到与 last 匹配的最新事件的命令。下一条命令显示从事件 1030 到事件 1035 的历史列表：

```bash
$ fc -l 1030 1035
1030  cd ../memos
1031  ls
1032  rm *0405
1033  fc -l
1034  cd
1035  whereis aspell
```

以下命令列出从以 view 开头的最新事件到以 whereis 开头的最新命令行的历史列表：

```bash
$ fc -l view whereis
1025  view calendar
1026  vim letter.adams01
1027  aspell -c letter.adams01
1028  vim letter.adams01
1029  lpr letter.adams01
1030  cd ../memos
1031  ls
1032  rm *0405
1033  fc -l
1034  cd
1035  whereis aspell
```

要从历史列表中列出单个命令，请使用相同的标识符作为第一个和第二个参数。以下命令列出事件 1027：

```bash
$ fc -l 1027 1027
1027  aspell -c letter.adams01
```

## 编辑和重新运行以前的命令

你可以使用 fc 编辑并重新执行以前的命令。

```text
fc [-e editor] [first [last]]
```

当你调用 fc 并使用 `-e` 选项后跟编辑器名称时，fc 会以 Work 缓冲区中的事件调用该编辑器。如果没有提供 first 和 last，fc 默认为最近一条命令。下一个示例调用 vi(m) 编辑器来编辑最近的命令：

```bash
$ fc -e vi
```
