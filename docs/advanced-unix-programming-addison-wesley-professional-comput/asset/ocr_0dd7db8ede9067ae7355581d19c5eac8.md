If statusp is non-NULL, the integer it points to is set to the status of the child. This is a combination of the child’s argument to _exit or exit (if that’s how it terminated) and a code that indicates how it terminated or stopped. Macros are supplied for interpreting the integer:

+   - WIFEXITED(status) true if the child terminated normally (with _exit or exit$^{8}$)
+   - WEXITSTATUS(status) if WIFEXITED, the low-order 8 bits of the argument to _exit or exit
+   - WIFSIGNALED(status) true if the child terminated abnormally (because of a signal)
+   - WTERMSIG(status) if WIFSIGNALED, the number of the signal that caused termination
+   - WIFSTOPPED(status) true if the child stopped; possible only if the WUNTRACED option is set (see below)
+   - WSTOPSIG(status) if WIFSTOPPED, the number of the signal that caused the child to stop
+   - WIFCONTINUED(status) true if the process was continued; possible only if the WCONTINUED option is set [X/Open]
+   - WCOREDUMP(status) true if a memory-dump file (called a “core dump” in UNIX) was produced; useful sometimes for post-mortem analysis (macro is nonstandard, but commonly implemented)

The last argument, options, is one or more of the flags ORed together:

+   - WCONTINUED Report on continued children, in addition to those that terminated. [X/Open]
+   - WNOHANG Do not wait for a child if status is not immediately available; return 0 instead of a process ID.
+   - WUNTRACED Report on stopped children, in addition to those that terminated.$^{9}$
