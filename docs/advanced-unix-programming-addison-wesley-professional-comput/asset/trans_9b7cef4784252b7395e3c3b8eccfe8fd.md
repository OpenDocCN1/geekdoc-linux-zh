### 1.1.2 程序、进程和线程

程序是一组保存在磁盘普通文件中的指令和数据。其 i-node 中该文件被标记为可执行，且文件内容按照内核确立的规则进行排列。（这是内核关心文件内容的另一个例子。）

程序员可以任意创建可执行文件。只要内容符合规则且文件被标记为可执行，程序就可以运行。在实践中，流程通常如下：首先，源程序（使用某种编程语言，例如 C 或 C++）被输入到一个普通文件中，这种文件常被称为文本文件，因为其内容排列成文本行。接下来，创建另一个称为目标文件的普通文件，其中包含源程序的机器语言翻译。这项工作由编译器或汇编器（它们本身也是程序）完成。如果该目标文件是完整的（没有缺失的子程序），则被标记为可执行，可以直接运行。如果不完整，则使用链接器（在 UNIX 术语中有时称为“加载器”）将该目标文件与之前创建的其他文件（可能来自称为库的目标文件集合）绑定在一起。除非链接器未找到其正在查找的内容，否则其输出是完整且可执行的。³

为了运行一个程序，首先要请求内核创建一个新进程，该进程是程序执行的环境。进程由三个段组成：指令段、⁴ 用户数据段和系统数据段。程序用于初始化指令和用户数据。初始化完成后，进程开始偏离其运行的程序。尽管现代程序员通常不修改指令，但数据确实会被修改。此外，进程可能会获取（更多的内存、打开的文件等）程序中不存在的资源。

当进程运行时，内核跟踪其线程，每个线程都是通过指令的独立控制流，它们都可能读写进程的相同部分数据。（然而，每个线程都有自己的栈。）在编程时，你从一个线程开始，除非你执行特殊的系统调用来创建另一个线程，否则你只有一个线程。因此，初学者可以将进程视为单线程的。⁵

多个并发运行的进程可以从同一个程序初始化。然而，这些进程之间没有功能关系。内核可能通过安排这些进程共享指令段来节省内存，但涉及的进程无法检测到这种共享。相比之下，同一进程中的线程之间存在强烈的功能关系。

进程的系统数据包括当前目录、打开的文件描述符、累计 CPU 时间等属性。进程无法直接访问或修改其系统数据，因为它位于其地址空间之外。相反，有各种系统调用用于访问或修改属性。

进程由内核代表当前执行的进程创建，该进程成为新子进程的父亲。子进程继承父亲的大部分系统数据属性。例如，如果父亲打开了某些文件，子进程也会打开这些文件。这种遗传对于 UNIX 的操作是绝对基础的，我们将在本书中看到。这与线程创建新线程不同。同一进程中的线程在大多数方面是平等的，没有继承关系。所有线程对所有数据和资源具有平等的访问权限，而不是它们的副本。

### 1.1.3 信号

内核可以向进程发送信号。信号可以由内核本身发起、由进程发送给自己、由另一个进程发送，或代表用户发送。

> 5. 并非每个版本的 UNIX 都支持多线程。它们是称为 POSIX 线程或“pthreads”的可选功能的一部分，于 1990 年代中期引入。关于 POSIX 的更多信息见第 1.5 节，关于线程的更多信息见第 5 章。

内核发起的信号的一个例子是段违反信号，当进程尝试访问其地址空间之外的内存时发送。进程发送给自身的信号的一个例子是中止信号，由 *abort* 函数发送以通过核心转储终止进程。从一个进程发送到另一个进程的信号的一个例子是终止信号，当相关进程之一决定终止整个进程族时发送。最后，用户发起的信号的一个例子是中断信号，当用户输入 Ctrl-c 时发送给该用户创建的所有进程。

大约有 28 种类型的信号（某些版本的 UNIX 稍多或稍少）。除了 2 个信号（终止信号和停止信号）外，进程可以控制收到信号时发生什么。它可以接受默认动作（通常导致进程终止）、忽略该信号，或者捕获该信号并在信号到达时执行一个称为信号处理器的函数。信号类型（例如 SIGALRM）作为参数传递给处理器。然而，没有直接的方式让处理器确定是谁发送了信号。⁵ 当信号处理器返回时，进程从中断点恢复执行。有两个信号未被内核使用。应用程序可以使用它们用于自己的目的。

### 1.1.4 进程 ID、进程组和会话

每个进程都有一个 *进程 ID*，这是一个正整数。在任何时刻，这些 ID 保证是唯一的。除一个进程外，每个进程都有一个父进程。

进程的系统数据还记录其 *父进程 ID*，即其父进程的进程 ID。如果进程因为父进程先于它终止而被孤立，其父进程 ID 会被更改为 1（或其他固定数字）。这是初始化进程（init）的进程 ID，该进程在启动时创建，是所有其他进程的祖先。换句话说，初始化进程会收养所有孤立的进程。

有时，程序员选择将子系统实现为一组相关的进程，而不是单个进程。UNIX 内核允许将这些相关进程组织成 *进程组*。进程组进一步组织成 *会话*。

5. 这适用于基本的 28 个信号。实时信号选项添加了一些信号，对于这些信号，可以获得此信息以及更多信息。更多细节见第 9 章。

其中一个会话成员是 *会话领导者*，每个进程组中有一个成员是 *进程组领导者*。对于每个进程，UNIX 跟踪其进程组领导者和会话领导者的进程 ID，以便进程可以在层次结构中找到自己的位置。

内核提供一个系统调用，用于向进程组的每个成员发送信号。通常，这将用于终止整个组，但任何信号都可以通过这种方式广播。

UNIX shell 通常为每个登录创建一个会话。它们通常为管道中的进程形成一个单独的进程组；在这种上下文中，进程组也被称为 *作业*。但这只是 shell 喜欢的方式；内核允许更大的灵活性，因此可以在单个登录内形成任意数量的会话，并且每个会话可以按照其喜欢的方式形成其进程组，只要保持层次结构即可。

它是这样工作的：任何进程都可以退出其会话，然后成为自己的会话（包含一个仅有一个进程的进程组）的领导者。然后，它可以创建子进程以完善新的进程组。会话中可以形成额外的进程组，并将进程分配给各个组。（分配也可以更改。）因此，单个用户可以运行，例如，由 10 个进程组成的会话，这些进程被组织成，例如，三个进程组。

一个会话，因此其中的进程，可以有一个 *控制终端*，这是由会话领导者打开的第一个终端设备；会话领导者随后成为 *控制进程*。通常，用户进程的控制终端是用户登录的终端。当形成新会话时，新会话中的进程不再具有控制终端，直到打开一个为止。没有控制终端是所谓的 *守护进程*⁷（Web 服务器、`cron` 设施等）的典型特征，它们一旦启动，就与用于启动它们的终端分离运行。
