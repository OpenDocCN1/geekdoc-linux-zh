
```
mdir a:\

I can use mcopy to copy the file "autoexec.bat" from the root directory to the floppy to my current directory on Linux:

```
mcopy a:\autoexec.bat
```

You have to be root to be able to write to a floppy.

will show how to display a content of a text file on a DOS partition.

pico /etc/mtools.conf
```

which instructs the mtools that the partition "dev/hda1" will be called "c:" The setup of /etc/mtools.conf requires uncommenting (removing the "#" at the beginning of the line) and adjusting the appropriate entry.

## 4.2 Mounting works when I am root. Can a normal user mount?

You have to edit the file /etc/fstab as root to give the normal users the permission to mount a drive. For example I can use the pico editor to do this:

```
pico -w /etc/fstab
```

The option "-w" turns off the long line wrap.

Here is the content of my /etc/fstab:

```
/dev/hda2 /ext2 defaults 1 1
/dev/hdc3 /home ext2 defaults 1 2
/dev/hdc2 /usr ext2 defaults 1 2
/dev/hdc4 swap defaults 0 0
/dev/fd0 /mnt/floppy auto noauto,users,rw 0 0
/dev/cdrom /mnt/cdrom auto noauto,user,ro 0 0
/dev/sda4 /mnt/zipdrive vfat noauto,user,rw,exec 0 0
/dev/hdl /mnt/dosdrive vfat noauto,user,rw 0 0
one /proc proc defaults 0 0
hacker:/mnt/cdrom /mnt/hacker_cdrom nfs noauto,user,ro 0 0
hacker:/mnt/floppy /mnt/hacker_floppy nfs noauto,user,rw 0 0
hacker:/home /mnt/hacker_home nfs noauto,user,rw 0 0
hacker:/usr /mnt/hacker_usr nfs noauto,user,rw 0 0
```

Each line contains space-delimited fields (this means that each line has six entries separated by white space). The first field is the name of the device. The second field is the mountpoint (an existing directory on your Linux system to which the resource will be mounted). The third is a filesystem type. For removable media that contain filesystems of several types, use the option "auto" to let Linux probe which filesystem is currently present. The order in which they are probed by the content of the file /etc/filesystems . You may want to make sure that it specifies "fat" before mounting /msdos or the DOS filename may be cut.) The fourth field contains options: "auto" = "user" has permission to mount this filesystem ("rw" = read and write; "ro" = read only, "user" has permission to mount this filesystem (one can also use "users") to allow a user to mount and another user to unmount—otherwise only the user who mounted the filesystem can execute "exec" programs from this filesystem. The number in field 5 specifies if the filesystem is backed up in a system backup, the number in the field 6 determines if to check the filesystem integrity during boot. The entries in /etc/fstab are filesystems on another computer (called "hacker") on my home network and it serves as an example of how to mount network resources. Check man fstab for more.

For example, regular (non-root) users have the permission to mount the cdrom (the "user" option is specified), they can mount it using a command like this:

```
mount /mnt/cdrom
```

The command which uses root options for mounting (see here [63]) will not work for a regular user because the user is restricted by the options in /etc/fstab and therefore cannot specifically mount both the device and the mountpoint.

For a regular user to be able to write to a disk or execute a program on it, he must also be given the appropriate permission to the "mountpoint" directory. For example, this will give all the users all permissions (read, write, execute) on the directory /mnt/floppy:

```
chmod +rwx /mnt/floppy
```

Now (also the "rw" option is specified for the floppy in the /etc/fstab) the user will be able to write to a floppy. If the "exec" option was also enabled in the /etc/fstab, the user would also be able to execute programs from the floppy.

Please note that the DOS vfat filesystem doesn't know about the file permissions the Linux. Linux handles this mounting by giving the default file permissions on the mounted filesystem: the user who mounted the filesystem will be the owner of all files and will be given the right to write to the filesystem (if "rw" was specified in fstab) but other users can only read. If you wanted to change this behaviour, you could use the "umask=" option so that the appropriate line in your /etc/fstab may look like example:

```
/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0
```

This gives absolutely every the permissions on your zipdrive (mounting, unmounting, read, write, execute).

To summarize, the file /etc/fstab is the place to keep your defaults on how to mount filesystems and what kind of access is allowed for users. You really want to customize it to simplify mounting on your system. Linux default mounting scheme is restrictive so to be secure, you may want to remove some restrictions when setting up Linux at home.

For example, regular (non-root) users have the permission to mount the cdrom (the "user" option is specified), they can mount it using a command like this:

```
mount /mnt/cdrom
```

The command which uses root options for mounting (see here [63]) will not work for a regular user because the user is restricted by the options in /etc/fstab and therefore cannot specifically mount both the device and the mountpoint.

For a regular user to be able to write to a disk or execute a program on it, he must also be given the appropriate permission to the "mountpoint" directory. For example, this will give all the users all permissions (read, write, execute) on the directory /mnt/floppy:

```
chmod +rwx /mnt/floppy
```

Now (also the "rw" option is specified for the floppy in the /etc/fstab) the user will be able to write to a floppy. If the "exec" option was also enabled in the /etc/fstab, the user would also be able to execute programs from the floppy.

Please note that the DOS vfat filesystem doesn't know about the file permissions the Linux. Linux handles this mounting by giving the default file permissions on the mounted filesystem: the user who mounted the filesystem will be the owner of all files and will be given the right to write to the filesystem (if "rw" was specified in fstab) but other users can only read. If you wanted to change this behaviour, you could use the "umask=" option so that the appropriate line in your /etc/fstab may look like example:

```
/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0
```

This gives absolutely every the permissions on your zipdrive (mounting, unmounting, read, write, execute).

To summarize, the file /etc/fstab is the place to keep your defaults on how to mount filesystems and what kind of access is allowed for users. You really want to customize it to simplify mounting on your system. Linux default mounting scheme is restrictive so to be secure, you may want to remove some restrictions when setting up Linux at home.
