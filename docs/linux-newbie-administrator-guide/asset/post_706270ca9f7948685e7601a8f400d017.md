
As an example of problems that you might face when using non-recommended characters in a filename, try creating a file with a name starting with a dash and then remove it--there seems to be no way to do it (a dash normally introduces command options). E.g., the command
dir > -junk

will create a funny file (the symbol ">").

The dot at dashing means "the current directory" and here just serve the purpose of hiding the leading so it is not interpreted as introducing an option to the rm command. The point is that I rather stick to traditional naming conventions face the occasional complications.

## 3.1.2 What are the different directories?

This is explained very nicely in the Linux System Administrator Guide (SAG), which should be available on your system.

```
cd /usr/doc/ldp/lynx sag.html
```

This will start a text-browser "lynx" to view this html book. You can also use any other browser, e.g. Netscape for Windows, to view this book. This book and other LDP books are actually quite to read.

Briefly, Linux contains five filesystems. These filesystems can reside on a single or different physical hard drives and/or hard partitions, depending on the size and need of your system. (A single filesystem can also be distributed between different physical devices, if needed.)

The root "/" filesystem--contains basic operating system and maintenance tools. The content of this filesystem should be sufficient to start up the system and perform emery maintenance and repairs if they are necessary.
/usr filesystem--contains all commands, libraries, documentation, and other files that do not change during normal operation. This will also contain many applications, the perhaps that ones come with your distribution, for example Netscape.
/var filesystem--contains files that change: spool directories, log files, lock files, temporary files,
/home filesystem--contains user files (users') own settings, customization files, documents, data, mail, caches, etc).

/proc filesystem--contains entirely illusory files. They don't really exist on the disk and don't take any space there (although ls -1 will show their size). When viewing them, you really access information stored in memory. It is used to access information about the system.

The parts of the root filesystem are:

- /bin-commands needed during booting that may be used by normal users.
- /sbin-commands not intended for general users (users may use them).
- /etc-system-wide configuration files for your operating system.
- /root-the home directory of the system administrator (called super-user) or root.
- /dev-devices Devices appear on Linux so it is easy to write to.
- /mnt-mount points for removable media (floppy, cdrom, zipdrive), partitions of other operating systems (like disk), network shares, and anything that is mounted on the file system temporarily. It normally contains subdirectories for the mounting shares.
- /lib-shared libraries for programs that reside on the root filesystem.
- /boot-files used by LILO a bootstrap loader, the thing loads first when the computer is booted and gives you an option on which operating system to boot, if you have more than one OS on your computer. It typically contains the Linux kernel, but if there could be stored somewhere else, only LILO is configured to know where it is.
- /opt-optional large applications, for example kde under RedHat 5.2 (under kde is distributed as any other X-windows distribution, main executables are in the /usr/bin directory).
- /tmp-temporary files recovered during the filesystem repair.

- The most important parts of the /usr filesystem are:
- /usr/X11R-X-windows system.
- /usr/X11R-the same as /usr/X11R (it is a symbolic link to /usr/X11R).
- /usr/X11R/bin -lots of small X-windows applications, and perhaps symbolic links to the executables of larger X-windows applications that reside in other subdirectories.
- /usr/doc--Linux documentation.
- /usr/bin and /usr/sbin-similar to the equivalents on the root filesystem (/bin and /sbin), but not needed for basic booting (e.g. during emergency maintenance).
- /usr/local--the installed "local user" applications, for example Netscape (each application in a separate subdirectory).
- /usr/local/bin-perhaps smaller "user" apps, and symbolic links to the larger executables contained in separate subdirectories under /usr.

It is important to understand that all directories appear in a single tree, even if the directories are on different partitions, physical drives (including floppies, etc.), or even if they distributed over the network. Therefore, there are no DOS-type "drive letters" under Linux.

## 3.1.3 How do I run a program?

Typing the name of the executable on the command line doesn't? There are three possibilities.

The first possibility: you dont the name of the executable correctly. Check the case--Linux case sensitive! For example, typing "Pico" or "PICO" will not start the pico editor.

The second possibility: maybe the program is not on your PATH. Under Linux (or UNIX), an executable must be on your PATH to run it, and the current directory is NOT on your PATH. Type the full path to the executable with name, execute:

```bash
cd the_program_dir
./program_name
```

You must put the dot and slash in front of the program name or the program will NOT execute. (This is a security feature not to put one's current directory on the path. It makes "trojan horses" more difficult. "trojan horse" is a malicious program that pretends to be something different than it really is.) This dot means "the current directory", and the slash "/" is a separator between the directory name and filename (exactly as "\" in DOS).

You may check your path using:

```bash
echo $PATH
```

To learn how to change your PATH, or add your current directory to it, see the next answer [p 33].

If your executable is lost somewhere in your directory tree, you may want to find it (for example):

```bash
find -name "netscape"
```

to find a file called "netscape". You may be able to achieve the same result faster:

```bash
locate netscape
```

Locate runs faster because it relies on a pre-built database of files on your system. This database is updated by a background cron process that runs at night, so don't count on locate to find a file if you regularly switch off your computer for the night, or search for a file that you just installed.

Please note that the PATH is normal for root than regular users (root's) PATH includes /sbin and /usr/bin whereas users (don't). Therefore users cannot execute command located in the "sbin" unless they specify the full path to the command. Also, if you become a superuser by executing the su command, you inherit your user's PATH, and to execute the command in sbin, you need specify the full path.

Conversely, if you need to learn where an executable is on your PATH (i., the executable runs by typing it anywhere in the system, but you would like to know where it is), you may use something like this:

```bash
which netscape
```

which will show a full PATH to the executable program "netscape".

The third possibility: maybe the file is not executable. If it should, change the permissions to make it executable. E.g. (as root or the user who owns the file):

```bash
chmod a+x my_file
```

will make the file "my_file" executable for all users. Check if it worked using:

```bash
ls -l my_file
```

## 3.1.4 How can I change the PATH?

The PATH is the list of directories which are searched for the program execution of which you request. You can check your PATH using this command:

```bash
echo $PATH
```

which, on my system, shows the PATH for the user "yogin" to be:

```
/opt/kde:/usr/local/bin:/bin:/usr/bin/X11R6:/home/yogin
```

The ":" is a separator, the above PATH represents a list of directories as follows:

```
/opt/kde/bin
/usr/local/bin
/bin
/usr/bin
/usr/X11R6/bin
/home/yogin
```

Here is the output from the command "echo $PATH" run on my system on the account "root":

```
/opt/kde/bin:/sbin:/bin:/usr/sbin:/bin:/usr/X11R6/bin:/root/bin
```

You can change the PATH for all users on the system by editing the file /etc/profile and adjusting (as root) the line starting with PATH=" I do it using the pico editor (as root):

```bash
pico -w /etc/profile
```

(The option -w turns off the wrap of lines)

Re-login for the change to effect. To set up the PATH for an individual user, edit the file /home/user_login_name/.bash_profile (please note the dot in front of the filename-files with a dot are normally invisible, you to use -a to see them).

If you really want to have the current directory on your PATH, add ". (dot) to your PATH. When used in the place when directory name is expected, a dot means the "current directory". The specification for the path in /etc/.bash_profile may then look like this:

```bash
PATH="$PATH:$HOME/bin:"."
export PATH
```
