
## 1.9 我应该如何划分硬盘？

如果你计划进行双引导（在同一台电脑上安装 Linux 和 MS Windows），请先使用你的 DOS/Win 工具 FDISK 创建 MS Windows 分区。留出硬盘的一部分不分区以供 Linux 使用。你将在 RedHat 安装期间创建并格式化 Linux 分区。将 MS Windows 分区设为“主分区”且“可启动”的。在安装 Linux 之前，请先安装、配置并测试你的 MS Windows。如果你只想运行 Linux，刚开始只需要一个干净的硬盘（无分区）即可。

可以只设置一个 Linux 分区（如果是双引导，则再加一个 MS Windows 分区）。但分多个分区更好，这样你可以将用户数据与操作系统的其他部分分开。这样，一旦出现问题，你想格式化并重新安装操作系统时，你就不会丢失用户数据。（不过，如果你在安装时跳过提供的“重新格式化”选项，你也可以可以在不丢失包含所有用户数据的 `/home` 目录内容的情况下重新安装 Linux。）

在 Linux 安装过程中，系统会要求你对硬盘上的可用空间进行分区。有很多可能的划分方法，取决于你的硬盘空间、需求和喜好。我喜欢这样的 Linux 硬盘分区（针对我为 Linux 分配的 2 GB 小容量）：

| 挂载点 | 类型 | 大小 |
| :--- | :--- | :--- |
| / | ext2 | 300 MB |
| /usr | ext2 | 1200 MB |
| /home | ext2 | 380 MB |
| swap | swap | 120 MB |

在上面的示例中，我分配了 300 MB 给存放 Linux 基础的挂载点。我分配了 1200 MB 给在文件系统中显示为 `/usr` 目录的挂载点，它将包含用户的程序（不是基础操作系统自带的、我之后安装的程序，例如 WordPerfect）。我分配了 380 MB 给显示为 `/home` 的分区，它将包含机器上所有用户的设置和数据。我分配了 120 MB 的“原始”分区供操作系统作为虚拟内存使用（硬盘上物理硅内存的扩展，即所谓的 swap）。如果你的内核版本低于 2.2（RHEL 2.2 及更早版本的情况如此），你的 swap 分区将大于约 127 MB。经验法是，你的 swap 大小应该是物理内存（RAM）的两倍左右。120 MB 的 swap 稍微有点，你可能不需要更多。如果你认为你需要更多（例如，你预计要运行具有大型数据结构的自定义程序），你可能需要在安装期间创建一个较大的 swap 分区（或较小的 swap 分区），或者添加 swap 文件。

2 GB 是一个很大的磁盘空间，即使对于喜欢拥有很多应用程序的用户来说也足够了。（因为 Linux 应用程序通常比相应的 MS Windows 程序精简）。
然而，如果你尝试安装互联网上所有提供的 Linux 程序，你肯定会耗尽硬盘空间的 :-)。我的经验是，无论硬盘有多大，它都会被填满，我会后悔没有更多空间了 :-)。

如果我的硬盘空间非常受限，我可能会考虑像这样的双分区设置（针对 Linux 分配的共计 600 MB 精简方案）：

| 挂载点 | 类型 | 大小 |
| :--- | :--- | :--- |
| / | ext2 | 600 MB |
| swap | swap | 50 MB |

在这个示例中，我分配了 600 MB 来包含操作系统基础、应用程序和文档/数据，并给了 50 MB 作为 swap 分区（供操作系统作为虚拟内存使用）。50 MB 的 swap 对于中等负载的操作已经足够了。操作系统、应用程序和用户数据限制在 600 MB 意味着你必须选择安装哪些应用程序，否则将面临耗尽硬盘空间的风险。在安装 Red Hat CD 上的可选软件时，尝试按 <F1>——它将为你提供关于该软件功能的简短描述，以便你决定是否真的需要它。如果你做出合理的选择，可以轻松地在 Linux 分区留有 200 MB 空闲空间（在本示例中使用了 600 MB）的情况下完成 RedHat 安装。请注意，不建议将根分区和 home 分区“捆在一起”。
