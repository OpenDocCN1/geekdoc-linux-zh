```
/usr hacker(ro) mars(ro)
/home hacker(rw) mars(rw)
/mnt hacker(rw) mars(rw)
```

This gives the machines called hacker and mars the permission to mount the directories /usr/
(read-only access), /home and /mnt (read-write).

If you set up NFS properly, you should be able to mount a network directory using a
command like this:

```
mount -t nfs :home /mnt/mars_home
```

This mounts the contents of the directory /home on a machine called "mars" into the directory
/mnt/mars_home/ (which must exist and be empty).

Many operating systems know NFS, but MS Windows doesn't. Therefore MS Windows remote
hares have to be dealt with. See the next answer for details.

# 4.2.4 How to mount a remote MS Windows filesystem through Samba

A remote MS Windows filesystem must be mounted onto a Linux filesystem through the Samba
protocol (Samba must be installed, go here [86] if it isn't). Type a command like this (as root):

```
smbmount //mars/windows /mnt/mars_windows -c marie
```

This mounts the MS Windows resource called from the MS Windows machine called mars.
The mountpoint on the client computer is /mnt/mars_windows/. The option "-c" specifies that
t samba server is a samba machine called mars (this should not be necessary, but it is on your system).

For the above to work, the permission must be given on the MS Windows machine for sharing the
directory or drive as a resource. To do this, on the MS Windows network, enable the filesharing
using "control panel-network", then launch the "Windows Explorer", click the right mouse button
on the drive or to share, click on properties, switch to the page "sharing", give yourself a
permission and give the resource a name.

To mount an MS Windows directory:

```
smbmount /mnt/mars_windows
```

If you have problems, see:

```
man smbmount
```
