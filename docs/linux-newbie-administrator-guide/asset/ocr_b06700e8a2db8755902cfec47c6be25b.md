and be able to browse the "apache" manual.

To put my own content on my web server, I move the "apache" sample files somewhere else, and
copy or link my html files (the ones I want to display to the public) to the directory
/home/httpd/html/ (don't forget to include the file index.html , this is the one that
appears first when someone connects to your server).

The apache configuration files and logs are in the directory /etc/html/ if you wanted to
view/customize them. The log file is viewed in "real time" using this simple command (as root):

```
tail -f /etc/httpd/logs/access_log
```

[The "tail" command normally displays the "tail" of a text file. With the option "-f", "tail"
keeping displaying the end of the log file as it grows--really handy monitor the log file and see who
logs onto your server.]

# 4.5.8 Simple ftp server

With my RedHat Linux distribution, setting up an ftp server could not be simpler--it works
out-of-box. This is because the ftp service is enabled on default as one of the standard services (as
netget and gopher), here is the relevant part of my /etc/inetd.conf:

```
ftp      stream tcp      nowait root      /usr/sbin/tcpd  in.ftpd -l
-a
telnet   stream tcp      nowait root      /usr/sbin/tcpd  in.telnet
gopher   stream tcp      nowait root      /usr/sbin/tcpd  gn
```

The second part of my ftp server setup is in the file /etc/passwd which defines the ftp account:

```
ftp*:*:14:50:User:/home/ftp:
```

The ": is a field separator. The first field is the username "ftp", the "*" indicates
that password is disabled (no login for this user), the user id is 14, group id is 50, "FTP
User" is comment, the home directory is /home/ftp, there is no shell specified for this user
(equivalent of the shell /bin/false, meaning no shell).

login as a user (who will be prompted for password and directed to his/her home directory), or login
"anonymous" and give his/her e-mail address as a password. Any user can also enter something like
