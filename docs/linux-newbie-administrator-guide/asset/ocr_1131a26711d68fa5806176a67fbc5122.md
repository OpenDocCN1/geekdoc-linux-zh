# 3.3 Job scheduling with "at", "batch", and cron

# 3.3.1 How do I execute a command at specified time (using "at" or "batch")?

The at command will execute the command(s) you specify at the date and time of your choice. For example, I could start playing music from my CDROM at 7 o'clock in the morning:

```
at 7:00
cdplay<Ctrl+d>
```

In the example above, I entered the first line "at 7" on the command line and pressed ENTER. This, the command displayed a prompt "at". At this point, I entered my command "cdplay" and then pressed the control key "d" simultaneously to finish the input. Instead of pressing <Ctrl+d>, the next "at" would appear, which I would be able to enter the next command to be executed right after "cdplay", also at 7. And so on, I could have made many commands scheduled for execution one by starting at 7. After typing the last command, I would finish the input with <Ctrl+d>. Think of the as sending "end-of-file" to the current input. Don't press <Ctrl+d> twice because this will log you out-that's what <Ctrl+d> does when entered straight into the Linux command.

You can list the job you scheduled for execution:

```
at -1
```

which will give you the numbered list of the jobs waiting.

If you changed your mind, you can remove a job from this list. For example:

```
atrm 8
```

will remove the job with the number eight on the list.

I could also schedule a job for execution much later, for example:

```
at 23:55 12/31/00
startx
```

would start my X-windowing system right on for the new millennium (5 minutes before midnight on 31 of December 2000).

If you cannot execute the command, check if the daemon ("atd") is loaded (as root, use setup-system services"). If you cannot execute the command as a regular user although it works for root, check if the empty file /etc/at.deny exists and there is no file /etc/at.allow. This would be the default setup and it permits all users to execute at at. If you want only certain users to use at, create a file /etc/at.allow and list these users.
