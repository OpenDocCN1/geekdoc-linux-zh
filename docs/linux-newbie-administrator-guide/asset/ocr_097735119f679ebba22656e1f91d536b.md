# 3.2.3a I forgot my password.

If a regular (non-root) uses his/her password, this is not a problem since root can change any password. For example (as root):

```
passwd barbara
```

will prompt for a new password for the user "barbara" (no knowledge of old password required). If a user (non-root) waits to change his/her password, s/he will be asked for the old password. (This is a security feature so nobody changes your password if you left your terminal unattended.)

If you need to temporarily disable any user account, there is no need to change his/her password. Just put an asterisk "*" at the beginning of the password field (before the encrypted password) in the file /etc/passwd or /etc/shadow. The "*" means that no login is permitted for this account. When you want to restore the account, you erase the star and the user account is back in operation, with its old password.

# 3.2.4 I have file permission problems. How do file ownership and permissions work?

Linux (the same as UNIX) is a multi-user operating system, and this creates a level of complexity with "file permissions". Trouble with file permissions can lead to an unexpected and nasty problems. Understanding file permissions is of utmost importance to administer any multipuser operating system (be it UNIX, WinNr, or Linux). My advice would be: learn the system of Linux (or any UNIX) file permissions, you will not regret it.

The permission conventions are the same for normal files and directories, so what is said about files below, also applies to directories. It is also important to remember that lower level directories (and the files they contain) inherit the permissions of their parents.
