In one instance, I had a problem with the reliability of establishing a connection (the error would pop up saying like: timeout for ppp startup), and the connection would establish only every few trials). The problem was solved by changing the "flow control" option (in setup under "device") from "CRTSCTS" to XON/XOFF (Still CRTSCTS is the recommended flow control method in most cases). The performance (speed) and the reliability of the connection with ppp was improved after I upgraded from RH5.2 to RH6.0. If you have problems with these, maybe it is time to upgrade.

If you keep having trouble setting up ppp, you may want to try minicom present on your system if you choose to install during RedHat initial setup. Here is a post from newsgroup.linux.help how to start ppp manually using minicom (edited for space):

> From mark balthazar@one.net.
> Subject: Re: ppp problem with 
> ZuWo: Also, for an experiment, using minicom to connect to your ISP, start ppp manually...this can prove buggy scripts. >how would you do that?

Easy!! If your ISP doesn't allow manual log then you might be in trouble. Every ISP I've ever used allows, so:
1. Start minicom.
2. Dial your ISP.
3. Log in.
4. After your ISP starts ppp, quit minicom with ALT-Q (or whatever the sequence is to quit without reset').
5. Start ppp, eg:
```bash
pppd -d -detach /dev/modem 115200 &```

OK, PPP will be running. Try pinging your ISP or another IP address. That will test everything is OK. If you can get PPP running this way, then you have no configuration problem. If you would like to start ppp from the command line, run netconf to configure your (ppp). The information you must enter is similar to what you enter when setting up ppp (like above!); the proper device for the modem, initialization and dialup settings, the number of your Service Provider (ISP), the proper authentication protocol (by entering the login name and password into the right slot). I edited the /etc/ppp/secrets and added the DNS addresses at the end of the setup line which created it like this:
```
my_login_name ppp0 password dns_server
```

Done with the settings, I could start the ppp interface using the command (as root, unless normal users can start the interface):
```bash
ifup ppp
```
and shut it down with:
```bash
ifdown ppp
```

Setting up the command line ppp was not more difficult on my machine. There are lots of command line scripts to start/stop ppp, but they are apparently not easy to set up and many newbies have problems with them. If this minimal setup of ppp does not work for you, here are some useful links:

## 4.5.4 How to browse the net from my networked computer without a modem

Another computer on your network must have a modem (or another Internet connection). Set up IP masquerading. This way, all requests from your network to your Service Provider (ISP) appear to have originated from a single computer, and your IP lets them through. Simple masquerading using RH5.2 requires just one command (on the computer with the modem):
```bash
/sbin/ipfwadm -F -p allow
```

Setting up masquerading as forwarding default of your IP firewall is therefore insecure for a home user. (The danger is that somebody from your network may need to route "tunnel" back to your network connecting his identity.) For more info, please check the file /doc/HOWTO/mini/IP-Masquerade. A more secure setup is shown here:
```bash
ipfwadm -F -p deny
ipfwadm -a allow -S 192.168.1.1/32 -D 0.0.0.0
ipfwadm -a allow -S 192.168.1.3/32 -D 0.0.0.0
ipfwadm -a allow -S 192.168.2.0/24 -D 0.0.0.0
```

This sets up the default policy to "deny" and explicitly masquerades two machines with IPs 192.168.1.1 and 192.168.1.3. It also masquerades any machine from the network 192.168.2.0. The number /32 stands for point-to-point networking (this means "machine-to-machine"), the option /24 identifies a class C network. The -D 0.0.0.0 identifies the default route that the machines are masqueraded to go out to the Internet.

ON RED HAT 6.0 THE NAME OF THE COMMAND is ipfwadm-wrapper (instead of ipfwadm) and I had to use the second, more secure method (setting up masquerading as the default policy does not work on any system at).

If you would like to have this command(s) always executed on your system startup, add it as the last line(s) to the file /etc/rc.local. This file is like AUTOEXEC.BAT in DOS.

If you would like to start ppp from the command line, run netconf to configure your ppp interface (ppp). The information you must enter is similar to what you enter when setting up ppp (like above!); the proper device for the modem, initialization and dialup settings, the number of your Service Provider (ISP), the proper authentication protocol (by entering the login name and password into the right slot). I edited the /etc/ppp/secrets and added the DNS addresses at the end of the setup line which created it like this:
```
my_login_name ppp0 password dns_server
```

Done with the settings, I could start the ppp interface using the command (as root, unless normal users can start the interface):
```bash
ifup ppp
```
and shut it down with:
```bash
ifdown ppp
```
