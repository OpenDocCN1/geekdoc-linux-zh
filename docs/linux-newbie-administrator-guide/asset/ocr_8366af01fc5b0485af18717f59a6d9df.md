Using numbers to set default permissions with umask is more tricky. The number shows the permissions that you take away for users (opposite to chmod). Thus:

mask 000

will give full permissions to everybody on newly created files. The next example gives full permissions to the owner, none for everybody else (perhaps that's what one may want):

umask 077

# 3.2.5 My mp3 player chokes. The sound is kind of interrupted (how to set suid).

The MP3 player might not be given enough priority (it requires a lot of it). It could be that your system is lossy. Or you might be running too many cpu-intensive programs at the same time. Or, most likely, you may need to run the player with a higher priority (The priority of a program can be set with the command nice -- see man niceinfo nice). Try to run the player as root--programs run by root are given higher priority than those run by normal users. If this solves the problem, set the "suid" on the executable so all users are given "effective user id" of root when running it, for:

```
chmod +s xllamp
```

will do the trick for the amplifier program. The output from

```
ls -l xllamp
```

on my computer is:

```
-rws-sr-x  1 root      root      319172 Mar 13 1998 xllamp
```

The first "s" indicates that the user-id (suid) is set. The second "s" indicates that the group-id (gid) is also set. Anybody who executes xllamp is the effective user id of the root program and effective group id of the owner, in the example above is the user "root" and the group "root".

Setting the suid for a program could possibly be a security hole in your system. This is unlikely on a closed home network and setting suid for a program of origin which is well traceable. However, at home, I wouldn't suit a piece of code of origin which is uncertain, even if the setup instructions urged me to do so.

Some programs do require suid for proper functioning, for example kppp (the popular modem "ppp" connection utility under the KDE graphical-user-interface desktop).
