In one instance, I had a problem with the reliability of establishing a connection(the error would pop up saying something like: timeout for the pppd startup), and the connection would establish only once every few trials). The problem was solved by changing the "flow control" option (in the kppp "setup under "device") from "CRTSCTS" to XON/XOFF. (Still CRTSCTS is the recommended flow control method in most cases).

The performance (speed) and the reliability of the connection with my kpppy was improved after I upgraded from RH5.2 to RH6.0. If you have problems with these, maybe it is time to upgrade.

If you keep having setting up ppp, you may want to try minicom to see if you can get your modem working from there. minicom is like PROCOMM for Linux. It should be present on your system if you choose to install it during RedHat initial setup. Here is a post from a newsgroup comp.linux.help how to start ppp manually using minicom (edited for space):

> From mark <balthazar@one.net.au> Subject: Re: ppp problem with kpppp
BuZuWo:
>>Also, for an experiment, using minicom to connect to your ISP, start ppp manually...this can prove buggy scripts. >how would you do that?

Easy!! If your ISP doesn't allow a manual log then you might be in trouble. Every ISP I've ever used does allow, so.. 1. Start minicom. 2. dial your ISP. 3. Log in. 4.After your ISP starts ppp, quit minicom with ALT-Q (or whatever the sequence is to 'quit without reset?'). 5. start ppp, eg:

```
pppd -d -detach /dev/modem 115200 &
```

OK, PPP will be running. Try pinging your ISP or another known IP address. That will test everything is OK. BTW, this is all in the PPP-HOWTO. If you can get PPP running this way, then you have a scripting problem. If PPP doesn't work, you have a PPP configuration problem. Cheers.

Command line. If you would like to start ppp from the command line, run netconf to configure your ppp interface (ppp). The information you must enter is similar to what you enter when setting up kppp (like have above!); the proper device for the modem port, modem initialization and dialup settings, the phone number of your Internet Service Provider (ISP), the proper authentication protocol (by entering the login name and password into the right slot). The netconf utility lacked a place to enter the IP addresses of my DNS server, so I edited the /etc/ppp/pap-secrets (I use PAP authentication protocol) and added the two DNS addresses at the end of the setup line which created by netconf so it looked like this:

```
# added by linuxconf
my_login_name ppp0 my_password 111.111.111.111 222.222.222.222
```
