This command:

```
chmod 411 junk
```

would give the owner the permission to read only, and the group and others to execute only. This
one does not seem useful, but might be funny, at least for North American Linux users who do
411 (telephone number) for directory assistance. Mail me if you can think of any other funny
permissions (maybe 0077).

The numerical way of representing file permissions is called "octal" because the numbers have base 8
(the decimal system base is 10). The highest digit in the system is 7 (octal system has eight
digits: 0 to 7, analog to decimal system having ten digits: 0 to 9). The octal representation
is a convenient notation for the binary representation of file permissions, where each permission is
flagged as "set" or "denied" with a one or zero and the total is represented as a string of zeros and\ones, in this diagram:

```
user class: owner group others
example permissions: rwx rw-- r---
absent permissions: --x -wx
binary representation of the binary: 111 110 100
octal representation: 7 6 4
```

Default file permissions with umask. When a new file is created, it is given default permissions.
On my system, these are:

```
-rw-r--r--
```

This means that files created by a user can be read and written to the user, but only read by his/her
group and others. Still, on my RH5.2 system, users cannot read the files in the other users'
home directories because the permissions on the home directories is:

```
drwx------
```

I can check the default file permissions given to my newly created files using:

```
umask -S
```

(The option "-S" stands for "symbolic" and tells umask to display the permissions in an easy-to-read
form.)

I can change the default file permissions for newly created files using a command like:

```
umask u=rwx, g=, o=
```

which will give the owner all the permissions on newly created files, and no permission to the group
and others.
