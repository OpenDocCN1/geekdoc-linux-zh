## 3.2 Users, passwords, file permissions, and security

### 3.2.1 Home directories, root, adding users

The (almost) only place on the hard drive that normal users (non-root) can write to their home directory, which is /home/user_login_name

This "home" directory is for all users: settings, program configuration files, data, network cache, mail, etc. As a user, you can create subdirectories under your home directory to keep yourself organized. Other users cannot read your files or write to your home directory unless they give them permission to do so.

The "root" (also called super user) is a special administrative account that has the power to modify any file on the system. It is not a good idea to habitually log on your system as root—mistakes can cost you dearly. Set up and use a normal user account for everyday work for yourself, another user account for your son, and yet another for your wife. The root account is the only account that exists on Linux after the initial installation.

A user account can be created by root using, for example:

```
adduser joe
passwd joe
[Type the password for the user joe]
```

Root can change any user's password, although she cannot read it. [Passwords are encrypted using a one-way encryption algorithm and only this encrypted version is stored in the system in the file /etc/passwd, the "open" version is never stored. When you login, the password you type is encrypted using the same one-way algorithm and compared with the already encrypted password stored in the file /etc/passwd (older systems) or /etc/shadow (newer systems).]

The separation of the administrator and user makes Linux systems secure and robust—it makes viruses under Linux difficult (the programs that a user can run only to his/her own directories, and therefore cannot affect the vital parts of the operating system).

It is customary that the user changes his/her password immediately after the first login, for example:

```
passwd
(current) UNIX password: pass_OLD
New UNIX password: pass_NEW
Retype New UNIX password: pass_NEW
```

In reality, the password will not appear on the screen as you type it (for security reasons).

### 3.2.2 About password security

Weak passwords are probably the most common source of security problems. Even at home, you may expose yourself to trouble if somebody is able to hack your computer when you browse the Internet and read your files. Here are some examples of hazardous passwords:

- no password (possible!)
- the word "password" (wow, this one is really weak!)
- your first or last name or your user name
- name of wife (husband), daughter, girlfriend, dog, etc;
- name of company, department, actually, etc.
- date of your birth;
- password written in the calendar or on your computer;
- any word which is in the dictionary (the dictionary does not contain so many words as it might seem, a skilful hacker can set up a program to try them all);
- a password which you also use in an insecure public place, for example an Internet store or a mailing list.

A good password is relatively long (minimum 6 letters), contains a mixture of letters (upper and lower case, if possible) and numbers, and is changed regularly (8 weeks?).

The system administrator can set the password policy through the utility included in this configuration program (run as root):

```
linuxconf
```

under the menu "user account"- "policies":"password" & account policies."

Also make sure that any file that contains a password (e.g., /root/.kde/share/config/kpprc) has proper secure permissions so that it cannot be read by anybody. Most likely you want:

```
chmod 600 kpprc
```

### 3.2.3 I forgot the root password

Never forget any passwords, I would study this issue in detail because it can give me a hint on how my mother might be reading my ICQ chats history:

First method. The easiest way to solve your "forgot root password" problem is to boot your Linux in the single-user mode, namely at the "lilo-prompt (during bootup)" type:

```
linux single
```

This will make you "root" without asking for password. Now, being root, you may change the root password using this command (no knowledge of the old password required):

```
passwd
```

If it strikes you as insecure, that's because no computer is secure if other people have physical access to your hardware. Nevertheless, I did not like the "linux single" hole on my computer and fixed it by adding the following lines to my /etc/lilo.conf (at the end of the "image=" section):

```
password="my_password"
```

This "lilo" password is required when, at LILO prompt during bootup, somebody enters the word "linux" with any parameter (normal bootup being possible). For the changes to /etc/lilo.conf to take effect, I must rerun the command:

```
chmod 600 /etc/lilo.conf
```

Second Method. Another way to solve the "lost root password" problem is to boot your computer from a Linux disk, find your root partition on the hard drive, mount it, and edit the file /etc/passwd to erase the password for root. For example, the /etc/passwd entry for root may look like this:

```
root:abcdefghijkl:0:root::/bin/bash
```

The "abcdefghijkl" is the encrypted password (actually, it is empty here). I would change this line to:

```
root::0:root::/bin/bash
```

Now, the root account has no password, so I can reboot the computer, and at the login prompt, type "root" and press ENTER (no password). After a successful login, I set the root password using the command:

```
passwd
```

The above applies to traditional UNIX files. In newer systems (e.g., RH2 and RH6), a more secure setup utilizes a shadow password file. In this case, /etc/passwd contains an "x" in the field where encrypted password used to be. The encrypted password is stored in the file /etc/shadow [This increases the security because of the different permissions: the file /etc/passwd can be read by anybody but /etc/shadow cannot. Additionally, the shadow system allows longer passwords and adds extras like password expiry policy, etc.] As root, you can manipulate the file /etc/shadow as you would /etc/passwd.

### 3.2.3a I forgot my password.

If a regular (non-root) uses his/her password, this is not a problem since root can change any password. For example (as root):

```
passwd barbara
```

will prompt for a new password for the user "barbara" (no knowledge of old password required). If a user (non-root) wants to change his/her password, s/he will be asked for the old password (This is a security feature so nobody changes your password if you left your terminal unattended).

If you need to temporarily disable any user account, there is no need to change his/her password. Just put an asterisk "*" at the beginning of the password field (before the encrypted password) in the file /etc/passwd or /etc/shadow. The "*" means that no login is permitted for this account. When you want to restore the account, you erase the star and the user account is back in operation, with its old password.

### 3.2.4 I have file permission problems. How do file ownership and permissions work?

Linux (the same as UNIX) is a multi-user operating system, and this creates a level of complexity with "file permissions". Trouble with file permissions can lead to unexpected and nasty problems. Understanding file permissions is of utmost importance to administer any multipuser operating system (be it UNIX, Windows, or Linux). My advice would be: learn the system of Linux (or any UNIX) file permissions, you will not regret it.
