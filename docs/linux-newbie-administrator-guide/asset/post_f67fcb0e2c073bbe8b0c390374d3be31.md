
- Freedom from viruses, software manufactures "features", invasion of privacy, forced upgrades, licensing and marketing schemes, high software prices, and piracy. How is this? Linux has no viruses because it is too secure an operating system for the viruses to spread with any degree of efficiency. The rest rests from the open-source and non-commercial nature of Linux.

- The operating platform that is guaranteed "here-to-stay". Since Linux is not owned, it cannot possibly be out of business. The Linux General Public License (GPL) ensures that development and support will be provided as long as there are Linux users.

- A platform which will technically develop at a rapid pace. This is insured by the modern, open-source development model which Linux implements: "build-on-the-back-of-the-previous-developer" and "peer-review-your-code" (as opposed to the anachronistic closed-software model: "always-start-from-scratch" and "nobody-will-see-my-code"). Even if the current "Linux-hype" died out, Linux will develop as it did before the media hype started.

If you wanted to learn first-hand about the General Public License, check these famous GNU documents:
http://www.gnu.org/copyleft/gpl.html
http://www.gnu.org/linux-and-gnu.html
http://www.gnu.org/philosophy/categories.html#TheGNUSystem

The licence under which Linux is distributed is probably the most important part of it.

# 0.4 I don't believe in free software, etc.

And do you believe in the Internet? The Internet and Linux share underlying ideas and have common roots. Do you remember the disbelief about the Internet few years ago, the endless, seemingly unbeatable arguments that the free Internet cannot exist? "Who pays for that, anyway?"

The reality is simple. Cooperation and good will benefit many at the same time: your gain is not my loss. Internet works fine and is expanding at a rapid pace. So Linux.

# 0.5 "There ain't so thing as a free lunch"

Brett Bazant <bbazant@shaw.wave.ca> wrote in LinuxToday
(http://linuxtoday.com/cgi-bin/showbt.pl?tbsn=12450&sn=5418):

The economic paradigm which makes this true depends upon scarcity of resources. Software resources are only scarce because we keep software proprietary and secret. But not Linux! When I give you my software, it may create opportunity cost for me, but I get to keep it even after I've given it to you. It is a free lunch only rivaled in history by the leaves and the fishes.

# 0.6 I need high security. With commercial software, I can sue them if things go wrong.

Don't count on suing. Things go wrong on many MS Windows NT machines every day, and there are no damages awarded by courts. Read your MS Windows agreement to find out that there is no guarantee whatsoever that ANYTHING will work. Trying to use it would be a waste of money.

Linux provides no guarantees, although it is far more secure than any version of MS Windows. If you are really security-sensitive, you can use high-security tools built by companies that rely on the availability of the source code to design and test their security features (e.g., Kryptokom in Germany provides high security firewalls). The "security in obscurity" implemented in MS Windows has repeatedly demonstrated to be a naive approach.

Here is a quote from David Kastrup, Research Engineer, Bochum, Germany (after the "Internet Week", http://www.techweb.com/se/directlink.cqi?INW19990329S0050);

> Risk aversion is what when using Linux and other open products, rather than NT. The risks with NT are entirely out of your control, and there is nobody who could use if anything goes wrong. Why people still believe the myth that Windows in any form offers any bit of accountability more than Linux remains a complete riddle to me.

# 0.7 I need standards. Big software corporations (Microsoft) provide standards.

Perhaps that is what people would expect from large corporations, but the reality is different. Once, big companies loved inventing nuts that could undo only by their own service shops. Did these nuts become standard? Hardly. They didn't—there was no public benefit involved, and they couldn't have—they were patented. Luckily, now we have open and free standards for nuts.

An example from the computer field. The "standard" MS Word format has changed numerous over the recent years. This keeps happening properly for a good reason: as soon as other companies "reverse-engineer" the current Word format, Microsoft changes it. There are even sub-formats (a MS "fast-save" anybody). It is also completely closed--Microsoft not publish the specifications. How can the user benefit from this in a longer term?

Xavier Basora (http://www.osopinion.com/Opinions/XavierBasora/XavierBasora47.html) writes:

> " Microsoft's standards are both proprietary and arbitrary—the stealth incompatibility of Office 97 file with older versions of Office or the subversion of Open standards like XML with proprietary extensions that Internet Explorer 5, MS Active server and so, are sober reminders of what the company does to market"

To add to the confusion, companies typically do not "standardize" on file formats but on applications that are supposed to produce them. It is like standardizing on a manufacturer of nuts instead of nuts. How is this supposed to work if the file format keeps changing?

There are a few text/document oriented file formats that are quite more standard than MS Word: ASCII, SGML, HTML, LaTeX, PostScript, pdf, dvi ... and all of them have excellent support under Linux. The Word format can also be read/written very well by Word Perfect, Star Office, Applizware, etc. to cover today's needs.

The story is similar with other proprietary computing "standards". Linux, by its nature, is based on true, published, and free standards because "open source" makes the full specifications available to everybody (competitors or not).

## 1. Before Installation

## 1.1 Which Linux distribution should I use?

The differences between the distributions ("distros") are minor: the installation program, choice of the bundled tools/applications, arrangement of few things on the hard drive (most of Linux is still at the same standard drive location in all distributions). Whichever distribution you decide to install, you will end up essentially the same Linux.

We mostly use "Red Hat" (also called RedHat or RH) for these reasons:

1. RedHat is very popular (both advantage for a newbie and a testimony to RedHat quality).
2. RedHat is a general-purpose distribution.
3. RedHat comes with a relatively easy setup program.
4. RedHat contributions to Linux are "open software" (this means that all the software written by RedHat and included on the RH CD is licensed under the General Public License, GPL, so that it can be legally copied, given away, reused, etc.).
5. RedHat can be obtained nearly free if you don't care for commercial support. This is a consequence of (4).

In short, as a newbie, you can safely bet on "Red Hat" unless you like something else or have specialized needs. The most recent RedHat release (October 1999) is version 6.1 (RH6.1) which is only a relatively minor upgrade over the previous version of Red 6.0 (RH6.0) which hit the street in May 1999. This previous version was Debian 5.2 and was very popular for quite a while. Be sure to check the most recent version if ordering your software from a dealer—many likes to clear their inventory by sending you old version (this applies not only to Linux). The authors have no connection to RedHat (or any other Linux distributor) whatsoever.

Our recommending RedHat for newbies does not mean that other distributions don't offer benefits or unique features which make RedHat in specific areas. We believe that we would benefit from an exposure to a different distribution because it help us understand Linux better.

We tried Debian and we liked it very much. It was as easy as RedHat, but it seems common (hence, being newbies, we picked up RedHat). The great benefit of Debian is that it is 100% non-commercial (put together by volunteer hackers, the true Linux) and it probably strictly adheres to Linux standards (it probably sets the standards too). Another benefit is that Debian on their numerous distribution CDs of tools and applications—easily more than any other distribution. All tools/apps are nearly "packaged" (for ease of installation) and tested for compatibility. This makes Debian distro look monumental, safe, conservative, and always slightly outdated. So yes, we would have no problem recommending Debian for a great general-purpose Linux.

Core is currently beta-testing their own Linux distribution geared towards a newbie and easy path to run the Core suite of applications: WordPerfect wordpress, QuattroPro spreadsheet, Core Presentations, Paradox database, CoreDraw artist package.... The Corel Linux is based on Debian. If you think about using Corel in the future, picking Debian may be your smart choice now.
