
This command takes the contents of the environmental variable PATH (as set for all users in /etc/profile), and appends to the name of your home directory as set by the variable HOME with an attached "bin" and then a dot. Finally, the command assigns the resulting string back to the variable PATH. It is necessary to use the command "export" after modifying PATH or any other user-environment variable, so that the path is visible outside the script that sets it.

## 3.1.5 How can I shutdown my computer?

In a text terminal

If you prefer your computer to halt after you press <Ctrl><Alt><Del> (instead of the default reboot), you can set this up by editing the file /etc/instab. This file specifies something like this:

```
# Trap CTRL-ALT-DELETE
ca::ctrlaltdel:/sbin/shutdown -t3 -r now
```

Change (as root) the option "-r" to "-h" so that it reads:

```
# Trap CTRL-ALT-DELETE
ca::ctrlaltdel:/sbin/shutdown -t3 -h now
```

The line starting with "#" is just a comment (it is for the humans, it does not have any effect on the computer).

Root can also use the shutdown command. This command can be used for a local or remote shutdown of the system. The last one is very useful if a program hangs so that the keyboard is no longer functional. For example:

```
telnet name_of_machine_with_no_operable_keyboard
[login as user]
su
[give password]
```

Now either execute ps aux |more, find the process id of the offending command in the ps output and do

```
kill pid_of_offending_process, or reboot your machine with:
/sbin/shutdown -rn now
```

If this command will shutdown really fast, bypassing standard (longer) shutdown procedure--useful when the system becomes really buggy (the option -n will make "shutdown" kill all the processes before rebooting).

Please note that for security reasons, you cannot login to a remote machine as root (e.g., over the telnet). You have to login as a user and execute su and give a password to become a super user (root).

The shutdown command may also be used to execute a shutdown later. E.g. (as root):

```
/sbin/shutdown -r 23:59
```

If the shutdown command is too long for you, you may want to try these two commands, which do exactly what their names suggest (as root):

```
reboot
halt
```

A fancy way to shut down your computer is to switch your system to the runlevel 0 (for halt) or runlevel 6 (for reboot). Try using it (as root):

```
init 0
```

The meaning of different runlevels is explained in the file /etc/instab.

## 3.1.6 How do I deal with a hung program?

Buggy programs hang under Linux. A crash of an application should not affect the operating system itself so should not happen too often that you have to reboot your computer. In our experience, behaving operating system may be a sign of hardware or configuration problems: repeatedly encountered problems with processor overheating (the fan did not turn as fast or stopped altogether, the heat sink on the Pentium was plugged with dirt), memory, different timing (you may try rearranging the order, it might help), wrong BIOS setup (you should probably turn off the "advanced" options, Linux takes care of things itself).

**Not really hung.** Some programs might give impression of hanging if a program is hung, although in reality they just wait for input. This happens if a program expects a filename as command line argument and no input is given by user, so the program defaults to standard input (which is console). For example, this command

```
cat
```
may look like it's hung but waits for keyboard. Try pressing <Ctrl>d (which means "end-of-file") to see that this will satisfy the "cat" command. Another example: I have seen many questions on newsgroups about the "buggy" command that hangs when trying to uncompress a file, for example:

```
tar -xzv my_file
```
waits for user input, since no option "-f" was specified the my_file was not recognized. The correct command is:

```
tar -xvmf my_file
```
Please note that the filename must follow immediately after the option "f" (which stands for filename). This WILL work (very common mistake):

```
tar -zxvf my_file
```

**Any program (hung or not) can be killed.** Text-mode program in the foreground can be killed by pressing <Ctrl>C. This will not work for larger applications which block <Ctrl>C, so it is not used accidentally. Still you can get back in control by sending the program to the background by pressing <Ctrl>z (no guarantee this will work) or switching to a different terminal, for example using <Ctrl><Alt><F2> and login as the same user that hung the program (this should always work). Once are back in control, find the program you want to terminate, for example:

```
ps
```
This command stands for "print status" and shows the list of programs that are currently running. In the ps output, find the process id (PID) of the program that hung, and now I can kill it. As user, I can only kill the processes I own (this is one I started). The root can kill any process. To see the complete list of all processes running on the system issue:

```
ps axu | more
```
This lists all the processes running (option "a"), even without the controlling terminal (option "x"), and together with the login name of the user that owns each process ("u"). The display is likely to be longer than one screen, use the "more" pipe so that the display stops after each screen.

The kill command has a shortcut killall to kill programs by name, for example:

```
killall netscape
```
will kill any program with "netscape" in its name.

X-windows-based programs have no control terminals and may be the easiest to kill (typed in an X-terminal):

```
xkill
```
to which the cursor changes into something looking like a death sentence; you point the window of the program to press the left mouse button; the window disappears for good, and the associated program is terminated.

If your X-windows system crashes so that it cannot recover, it may be the easiest to kill the X-server by pressing <Ctrl><Alt><Space>. After that, it may be a good idea to run ps axu, find any X-programs that might still be running, and kill them. If you don't, the misbehaving program that caused your X-windows to crash might cause trouble again.

If you have programs in the background, the operating system will object your logging out, and issue a message like "There are stopped jobs". To override and logout, just repeat the logout (or exit) command immediately --the background program(s) will be automatically terminated and you will be logged out.

**Core files.** When a program crashes, it dumps a "core" into your home directory. This is accompanied by an appropriate message. A core is a memory image (plus debugging info) and is meant to be a debugging tool. If you are a user who does not intend to debug the program, you may simply delete the core:

```
rm core
```
or do nothing (the core will be overwritten if another core is dumped). You can also disable dumping the core using the command:

```
ulimit -c 0
```
Checked if it worked using:

```
ulimit -a
```
(this shows "user limits", the option "-a" stands for "all"). To make option of disabling core dumps permanent for all users, edit the file /etc/profile (as root), where ulimit is set, and adjust the setting. Re-login for the changes to /etc/profile to take effect.

If you would like to see how a core file can be used, try (in the directory where you have a core file):

```
gdb -c core
```
