Try /dev/sda1, /dev/sda2, etc. ["hda" is the primary IDE master drive, "hdb" is the primary IDE slave drive, "hdc" is the secondary IDE master if you have two interfaces on your computer, hdd is the secondary IDE slave, "sda" is the first SCSI interface and the number is.]

```

```

## 4.2.2 How I access my CDROM?

Mount it. The mounting adds all the drives and files from your CD to your Linux directory so you can easily access them without the drive letter.

As root, you can mount the CDROM with a command like this:

```
mount -t auto /dev/cdrom /mnt/cdrom
```

If this works, the content of your CD appears in the directory /mnt/cdrom rightaway—you may have to customize it. Here is how it works.

The command tells the operating system to mount a filesystem autodetecting the filesystem type ("-t auto"). The device is /dev/cdrom. The mountpoint (the directory where which "mounting" takes place) is /mnt/cdrom. This directory must exist and be empty. If it does not exist, create it with:

```
mkdir /mnt/cdrom
```

If the mounting command fails, make sure that check the device /dev/cdrom exists. If it doesn't, where is your CDROM? Chances are it something like /dev/hdb if you have an IDE CDROM. Try /dev/hdb instead of /dev/cdrom in the mount example above. If this fails, you can try /dev/hdc or /dev/hld, if your cd is an IDE CDROM. If none of them is your CDROM, you might not have a drive but a SCSI CDROM? Try /dev/sda1, /dev/sda2, etc. ["hda" is the primary IDE master drive, "hdb" is the primary IDE slave drive, "hdc" is the secondary IDE master if you have two interfaces on your computer, hdd is the secondary IDE slave, "sda" is the first SCSI interface and the number is.]

It is a good idea to have a device /dev/cdrom anyway because some programs assume that it exists. If it does not exist on your system, you may create it as a symbolic link, for example:

```
ln -s /dev/hdb /dev/cdrom even```
if your cd is the /dev/hdb drive.

If you cannot mount because "the device is already mounted or directory busy", perhaps the mountpoint /mnt/cdrom is your current directory. You have to change the directory to somewhere else in order to be able to mount to; for example change the current directory to the root directory by issuing this command:

```bash
cd /
```

To unmount a mounted CD, edit the directory /mnt/cdrom and type as a root:

```
umount /mnt/cdrom
```

Your CDROM may refuse to eject the media if it is not mounted. Also, you may have problems mounting the next CD if the previous one was unmounted. If you cannot unmount because "the device is busy", perhaps /mnt/cdrom (or any subdirectory) is your current directory? You need to change your current directory to somewhere else out of the mount point in order to unmount the device.

## 4.2.3 How to mount a floppy, zip drive, DOS/Windows partition, or a network drive?

Very much the same as the CDROM--see the previous answer if you did not read it.

Floppy. I can mount my floppy (as root) with:

```
mount -t auto /dev/fd0 /mnt/floppy
```

Again, make sure that the directory /mnt/floppy exists and is empty. Also, /mnt/floppy/ cannot be your current directory.

After a successful mount, the files from the floppy appear in the directory /mnt/floppy/. All the users will be able to read the files, but only root will be able to modify/delete the files. Please read further if you wanted the users to be able to write to the floppy.

To unmount a floppy (you "must" do this before ejecting the disk!) use:

```
umount /mnt/floppy
```

If you cannot mount because "the device is busy", perhaps the /mnt/floppy/ directory is your current directory. Exit it by typing (for example):

```
cd
```

which will change your current directory to your home directory.

Zipdrive. I mount the parallel port external zipdrive (scsi emulation) with:

```
mount -t vfat /dev/sda4 /mnt/zipdrive
```

The -t vfat is used because zip disks come preformatted in the vfat filesystem, which is the filesystem of MS Windows with the long filename support. You won't be able to eject the disk without unmounting it.

All ziprives (internal SCSI and IDE, external SCSI and parallel port) but the USB is supported under Linux (April 1999).

## DOS/Windows partition. I use a dual boot system with both Linux and MS Windows on the same computer. I can access all of DOS/Windows partition after mounting it with the following command:

```
mount -t vfat /dev/hdal /mnt/dodsrive
```
