
## 1.9 How do I partition my hard drive?

If you plan a dual boot (Linux and MS Windows on the same computer), first use your DOS/Win utility FDISK to make the MS Windows partition(s). Leave a part of the hard drive(s) unpartitioned for Linux. You will make and format the Linux partitions during RedHat installation. Make the MS Windows partition "primary" and "bootable". Install, configure, and test your MS Windows before Linux installation. If you want to run Linux only, you need just clean hard drive (no partitions) to start with.

It is possible to have only one Linux partition (plus one for MS Windows if you dual-boot). But it is better to have more partitions so you can keep users' data from the rest of the operating system. This, if something goes wrong and you want to format and reinstall the operating system, you don't lose your users' data. (You can however do a Linux re-install without losing the contents of the /home directory that contains all user data if you skip the "re-format" option given to you installation.)

During the Linux setup, you will be asked to partition the available space on your hard drive. There are many possible ways to partition, depending on your drive space, requirements, and taste. I like Linux hard partitions like this (for a modest size of 2 GB that I dedicated for Linux):

| mount point | type | size |
| :--- | :--- | :--- |
| / | ext2 | 300 MB |
| /usr | ext2 | 1200 MB |
| /home | ext2 | 380 MB |
| swap | swap | 120 MB |

In the above example, I dedicate 300 MB for the mount point that holds the base of the Linux operating system. I give 1200 MB for the mount point that will be visible on my filesystem as the /usr directory and will contain users' programs (the programs that don't come with the base operating system and I later, for example WordPerfect). I dedicate 380 MB for the partition that will be visible as the /home and will contain the setting and data of all users on the machine. I give 120 MB for a "raw" partition for the operating system to use as the virtual memory (extension of the physical, silicon memory on the hard drive, so-called swap). If your kernel is lower than 2.2 (which is the case with RHEL 2.2 and earlier), your swap partition will be larger than approximately 127 MB. The rule of thumb is that your swap should be about twice the amount of the physical memory (RAM). 120 MB is a bit of swap and it is unlikely you will need more. If you think you need more (e.g. you expect to run custom programs with large data structures) you want to create a large swap partition during the installation (or smaller swap partitions) or add swap file(s).

2 GB is a lot of disk space and should be sufficient even for users who like having many applications. (This is because Linux applications tend to be slimmer than their MS Windows equivalents).
However, if you try to install everything that's available for Linux on the Internet, you will surely run out of disk space :-). My experience is that however large the hard drive, it will get filled and I regret I have no more :-).

If my space on the hard drive is really restricted, I may consider a two-partition setup like this (for a lean 600 MB total dedicated for Linux):

| mount point | type | size |
| :--- | :--- | :--- |
| / | ext2 | 600 MB |
| swap | swap | 50 MB |

In this example, I dedicate 600 MB to contain the base of the operating system, applications, and documents/data, and give 50 MB for the swap partition (for the operating system to use as the virtual memory). The 50-MB swap would be quite sufficient for medium duty operations. The limitation of 600 MB for the operating system, applications and user data means that you will have to select to which applications you install or else risk running out of hard drive space. Try pressing <F1> when installing the optional software that comes on Red Hat CD—will give you a short description of what the software does so you could decide if you really need it. You can easily finish the RedHat installation with 200 MB free on your Linux partition (of 600 MB used in this example) if you make reasonable choices. Please note that "bundling together" the root partition and the home partition is not recommended.
