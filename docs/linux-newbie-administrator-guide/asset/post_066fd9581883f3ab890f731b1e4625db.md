## 4.5.6 Sendmail

Sendmail is the standard mail-transport system and the default mail-transport on RedHat5.2 and RedHat6.0 Linux. As a user, you don't use sendmail directly—sendmail is the underlying engine that manages your mail in the background. To read/send mail in the text mode, you would probably want to use pine or elm (which stay with-it can be inconvenient to manage separate boxes). In KDE, you may choose to use the "mail" available from the K-menu. To communicate with the outside world through your p dial-out, you would probably like to use the Mozilla mail that is built into your Netscape and communicates directly with your remote Internet-Service-Provider-based mailbox.

Sendmail is very flexible and robust, but also difficult to manage if you needed to customize it to your specific needs. Luckily, RedHat (5.2 or 6.0) comes with the sendmail that runs out-of-box (with some limitations though).

On my home system (Red Hat setup), I can send mail to another user on the same machine with no problem (except using pine). I can send mail to anywhere in the world from after I am connected to my Internet Service Provider through the method. If I am not connected, the mail sits in the queues and waits for it (a minor annoyance). It gets sent once connected (It happens because sendmail is trying to do a DNS lookup that is not available on my system—RedHat default is cache-only). If you really want to avoid this on RH6.0, you may use netconf (as root) and specify that sendmail is not to use DNS at all (Linuxoconf with RH5.2 does not give you the choice). I do use DNS.

Under Linux 6.0, you may also want to configure other sendmail options (as root) netconf.conf. I entered the name of my Internet Service Provider and the names of other machines on my home network under "mail delivery system--relay to hosts". I also added the names of my home network machines under "relay for by".

You should also be aware of the limitation of your setup if you send e-mail from your home network (for example using pine), to the world beyond your network. If you invented the IP address and your domain name is unregistered, there is no chance you will receive a reply. Your outgoing mail is given a "reply" address in the format: "user_login_name@machine.domain". This is

NOT since your domain name does not exist, according to any DNS in the outside world, hence no way for any reply to get to you. To overcome this, you may use the Netscape mailer to communicate to the outside of your home network. Netscape uses the settings you enter in "edit-preferences" to communicate directly to your ISP-based mailbox (which resides on a registered server of your ISP) and bypasses your unregistered-homenetwork-based email system. Another possibility is to specify the correct address in the "reply-to" field. If you do in Netscape, you can set your NetscapeMail to your local Linux computer as the server, and this will be able to send e-mail from your NetscapeMail to the computers on your home network (not only in the "outside world). The option "reply-to" can also be set in the KDE "mail client" setting. Also in "pipe" you can specify the reply-to address under "setup-configure", "customized-hdrs" with something like:

Reply-to: joe@joe_net.net.

where "joe@joe_net.net" is your good reply-to e-mail address.

## 4.5 Simple web server (Apache)

```bash
cd /mnt/cdrom/RedHat/RPMS
rpm -ivh apache.*
```

Then, I run "setup" (as root) and make sure that the http daemon (under "system services") is enabled. [A daemon is a program that sits in the background and wakes up when it is needed. In the case of httpd it is awakened when somebody calls on your http server.]

Now, the httpd will automatically start every time I boot the computer. I can also start it manually (using as root):

```bash
/etc/rc.init.d/httpd start
```

and shut it down:

```bash
/etc/rc.init.d/httpd stop
```

I should already have the directory: /home/httpd (check if it exists), and under it, the subdirectory html—is the "root directory" for people accessing my computer from the web (their root directory means that they will be able to access any directories above the directory /home/httpd/html/ on your system). By default, this directory contains some files and a manual that the instalation program put there. So I should now be able to connect to my web server from another machine on my home network. For example I would type on my home network:

http://my_name

To be able to access my web server from the outside world, one has to know your IP address. To find out my current IP address, I use this "interface configuration" command which, when run without any parameters, just displays info on all network interfaces present on your machine:

```bash
/sbin/ifconfig
```

On this machine displays displays of information on: eth0 (the first ethernet interface that leads to other computers on my home network), lo (the loopback-only interface, the one with IP 127.0.0.1, which is present on every machine), and ppp0 (the first point-to-point protocol interface). My current IP address, assigned to me by my ISP, is displayed under the ppp0 heading. (Your Linux machine can have multiple IP addresses at the same time, so if you have a "static" IP that you use on your home network, it is still visible only on your network.)
