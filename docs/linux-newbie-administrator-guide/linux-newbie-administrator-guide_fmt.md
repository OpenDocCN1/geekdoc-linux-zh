## 0. 给未决定的者（Linux 的益处）

### 0.1 根本上，为什么选择 Linux？

如果你真心喜欢与计算机工作，`Linux` 就是你梦想中的操作系统。它比世界上任何其他计算机操作系统都要有趣。然而，`Linux` 真正具有革命性的原因在于它是开源软件。我们的科学技术之所以运作，是因为信息的自由可用和同行评审。你会驾驶一架基于专有科学和未经评审设计的飞机吗？一架除了制造商没人能查看内部的飞机？你何时、又会信任一个封闭的、未经评审的、专有的操作系统？`Linux` 特别适用于任务关键型应用。

制作马蹄曾是一个守口如的秘密。科学技术在 500 年前爆发，通过印刷手段共享了知识。在印刷术早期，许多敢于分享知识的人因泄露“贸易秘密”而被暗杀。`Linux` 是为古登堡发明术之后的计算机时代准备的（正如古登堡是为他的时代准备的一样）。希望这次不会有“暗杀”了 :-

### 0.2 Linux 适合我吗？

只有你才能回答这个问题。`Linux` 是一个成熟、强大且极多功能的类 `Unix` 操作系统。这种力量和多功能是有代价的——你可能需要具备计算机知识来设置和维护 `Linux`。当操作系统和应用程序设置妥当时，`Linux` 使用起来相对容易。所以，你的母亲也能使用 `Linux`，只要你为她设置一个简单的图形化账户并在图形桌面上放置图标/菜单。`Linux` 是安全的，所以无论你母亲如何尝试，都不会破坏系统——除非她用锤 :-

`Linux` 与 `Windows` 完全不同，所以不要指望会了 `Windows` 就能用 `Linux`，你可能需要学习。相反，如果你来自 `Unix` 世界，`Linux` 对你来说就很简单。如果你对计算机并不了解，或者不喜欢它们，那么 `Linux` 管理可能不适合你。如果你不了解硬件，`Linux` 安装对你来说可能是挑战。

### 0.2a Linux 对新手来说很难。

这可能是事实。但问题是：你想学吗？这对某些人是真的。Klimas 一家（我们使用并热爱它）。

### 0.3 Linux 的益处是什么？

`Linux` 可以带给你：

- 一个现代且强大的环境
- 一个极好的平台
- 一个真正的学习平台
- 卓越的网络能力
- 与 `微软`、`苹果` 和专有网络的连接性
- 数千个免费应用、工具和小型程序
- 许多顶尖的商业软件
- 免受病毒、软件商的“功能”、侵犯隐私、强制升级、许可和营销计划、高软件价格以及盗版的影响。这是怎么的？`Linux` 没有病毒，因为它是一个极其安全的操作系统，病毒无法以任何效率进行传播。其余的都源于 `Linux` 的开源和非商业性质。
- 一个保证“长久存在”的运营平台。由于 `Linux` 不归任何公司所有，它就不可能倒闭。`Linux` 通用公共许可证 (`GPL`) 确保了只要有 `Linux` 用户，就会提供开发和支持。
- 一个在技术上将以快速速度发展的平台。这由 `Linux` 实施的现代开源开发模型提供了保障：“在以前任开发者的肩膀上构建”和“同行评审你的代码”（与过时的闭源软件模型相比：“始终从零开始”和“没有人会看到我的代码”）。即使当前的“`Linux` 热潮”消灭了，`Linux` 也会像它在媒体炒作开始之前那样继续发展。

如果你想第一手了解通用公共许可证（`GPL`），请查看这些著名的 `GNU` 文档：

`http://www.gnu.org/copyleft/gpl.html`

`http://www.gnu.org/linux-and-gnu.html`

`http://www.gnu.org/philosophy/categories.html#TheGNUSystem`

`Linux` 分发时使用的许可证可能是它最重要的部分。

### 0.4 我不相信自由软件，等等。

你相信互联网吗？互联网和 `Linux` 共享底层理念并有共同的根源。你还记得几年前对互联网的不信任吗？那些无休止的、似乎不可战胜的争论，认为自由互联网是不可能存在的？“到底是谁在买单？”

现实很简单。合作和善意会同时造及许多人：你的收益并不是我的损失。互联网运行良好并正在以快速速度扩张。`Linux` 也是如此。

### 0.5 “世界上没有免费的午餐”

Brett Bazant `<bbazant@shaw.wave.ca>` 在 `LinuxToday` 写道：

`<http://linuxtoday.com/cgi-bin/showbt.pl?tbsn=12450&sn=5418>`:

使这成为真实的经济范式取决于资源的稀缺性。软件资源之所以稀缺，是因为我们一直保持软件的专有和保密。但 `Linux` 不是！当我把软件给你时，它可能会为我创造机会成本，但即使在我给你之后，我仍然保留了它。这种免费的午餐，在历史上只有叶子和鱼类能与之并肩。

### 0.6 我需要高安全性。使用商业软件，如果出问题，我可以起诉他们。

别指望起诉。每天有很多 `MS` `Windows` `NT` 机器都会出问题，但法院并没有裁定赔偿。阅读你的 `MS` `Windows` 协议就会发现，没有任何保证能`任何东西`都能正常工作。尝试使用它将浪费钱。



Linux 不提供保证，尽管它比任何版本的 MS Windows 都安全得多。如果你对安全非常敏感，可以使用由公司构建的高安全工具，这些公司依赖源代码的可用性来设计和测试它们的安全功能（例如，德国的 Kryptokom 提供高安全防火墙）。MS Windows 中实施的“隐蔽安全”已被反复证明是一种幼稚的方法。

以下是来自德国波鸿姆研究工程师 David Kastrup 的引言（在“互联网周”之后，`http://www.techweb.com/se/directlink.cqi?INW19990329S0050`）：

> 使用 Linux 和其他开源产品而非 NT，是规避风险的体现。NT 的风险完全不受你控制，而且一旦发生任何故障，没有人可以寻求帮助。为什么人们仍然相信“任何形式的 Windows 提供的问责性比 Linux 多一点点”这种神话，对我来说是一个完全的谜。

### 0.7 我需要标准。大型软件公司（微软）提供标准。

也许这是人们对大公司的期望，但现实并非如此。曾几何时，大公司喜欢发明只有通过他们自己的维修店才能拆卸的螺丝。这些螺丝变成标准了吗？几乎没有。它们没有变成——因为不涉及公共利益，而且它们无法做到——它们被专利了。幸运的是，现在我们有了螺丝的开源且免费标准。

计算机领域的一个例子。“标准”的 MS Word 格式在最近几年发生了多次变化。这种现象的发生是有正当理由的：一旦其他公司“反向工程”了当前的 Word 格式，微软就会更改它。甚至还有子格式（一个 MS“快速保存”，任何人都能用）。它也是完全封闭的——微软不发布规范。用户长远来看如何从中受益呢？

Xavier Basora (`http://www.osopinion.com/Opinions/XavierBasora/XavierBasora47.html`) 写道：

> “微软的标准既是专有的又是任意的——Office 97 文件与旧版本 Office 的隐性不兼容性，或者通过 Internet Explorer 5、MS Active server 等使用专有扩展对 XML 等开放标准的颠覆，都是对该公司对市场所为行为的清醒提醒”

为了增加混乱，公司通常不是对文件格式进行“标准化”，而是对旨在产生格式的应用程序进行标准化。这就像是标准化螺丝的制造商，而不是螺丝本身。如果文件格式不断变化，这应该如何运作呢？

有几种文本/文档导向的文件格式比 MS Word 标准得多：`ASCII`, `SGML`, `HTML`, `LaTeX`, `PostScript`, `pdf`, `dvi` ... 它们在 Linux 下都有极佳的支持。Word 格式也可以被 Word Perfect、Star Office、Applizware 等很好地读取/写入，以满足今天的需求。

其他专有计算“标准”的情况也类似。Linux 从本质上是基于真实的、发布的且免费的标准，因为“开源”让每个人（无论是否是竞争对手）都能获得完整的规范。

### 1.13 我完成了安装。如何登录？[20]

发行版之间的区别微乎其微：安装程序、捆绑的应用以及硬盘布局。无论你决定安装哪种发行版，都可以安全地选择“红帽”（称为 `RedHat` 或 `RH`），基于以下原因：

1. `RedHat` 非常受欢迎（对新手的证明）。
2. `RedHat` 是一个通用型发行版。
3. `RedHat` 带有相对容易的安装程序。
4. `RedHat` 对 Linux 的贡献遵循通用公共许可证 (`GPL`)，这意味着所有在 `RedHat` 中提供的软件都是合法复制、赠送、重复使用的（因此）。
5. 如果不需要商业支持，`RedHat` 可以几乎免费获得。这是基于第 4 点。

简而言之，作为新手，除非你有特殊需求，否则你可以放心地选择“红帽”。最近的 `RedHat` 版本（1999 年 10 月）是 `6.1 (RH6.1)`，相对于之前的版本 `6.0 (RH6.0)` 只有小幅升级，后者于 5 月发布。之前的之前的版本是 `Debian 5.2`，它曾有一段时间非常流行。

我们向新手推荐 `RedHat` 并不意味着其他发行版在特定领域没有优势或独特功能。我们相信，接触不同的发行版有助于我们更好地理解 Linux。

我们尝试了 `Debian` 并且非常喜欢它。它和 `RedHat` 一样简单（因此，作为新手，我们选择了 `RedHat`）。`Debian` 的巨大优势在于它是 100% 非商业的（由志愿者黑客编写，真正的 Linux），而且它可能严格遵守 Linux 标准（它可能还定义了标准）。另一个优势是，`Debian` 提供的工具和应用 `CD` 比任何其他发行版都多。所有工具/应用几乎都经过了打包（便于安装）并经过了测试。这让 `Debian` 发行版看起来庞大、安全、保守，且总是有些过时。因此，我们完全没有问题向新手推荐 `Debian`。

`Core` 目前正在测试他们自己的 Linux 发行版，面向新手并旨在运行 `Core` 套件：`WordPerfect` 文字、`QuattroPro` 表格、`Core Presentations`、`Paradox` 数据库、`CoreDraw` 绘画软件……`Corel Linux` 基于 `Debian`。如果你以后考虑使用 `Core`，现在选择 `Debian` 可能是明智之举。

`Slackware` 似乎是“尖端黑客”的一员，他们喜欢紧贴操作系统，并且每隔几天就更新一次内核——我们没有用过它，所以这只是道道。`S.uSE` 发行版在欧洲非常流行。它看起来可能是一个“德国式稳固”的通用发行版，安装简单且声誉极佳。另一个知名且受尊敬的发行版是 `Caldera`，据说其目标是企业用户——这有许多缺陷；`Mandrake` 发行版是 `RedHat` 的克隆版本，更新频率比正统的 `RedHat` 更高（`RedHat` 倾向于减少更新频率，以免产生过多的版本）。`Mandrake` 似乎非常流行。它们是针对特定国家或语言的“本地化”Linux 版本（如韩语、日语等）……默认可能包含了这些国家的用户想要看到的所有黑客技术（优化）。

此外还有“特殊用途”发行版，例如 Linux 的“实时”版本（如果你从事自动化、机器人等领域可能会很有用）、非常小的发行版（可能适用于下一代 `CD/MP3` 播放器，或者如果你喜欢从小型软盘运行 Linux 的想法）、并行计算和集群系统（如果你计划做自己的任何事情，这可能非常棒 :-)；这里的差异会更大，但这些发行版并非为了“通用”设计。作为一个新手，你不想从其中任何一个开始，尽管你可能会被其吸引。它们无疑展示了 Linux 的强大和可行性——它可以在计算机集群上运行，构建出世界上最快的系统。

你需要的发行版取决于你拥有的硬件。对于你的包含 `Intel 386` 处理器、`486`、`Pentium`、`Cyrix`、`K6` 或类似处理器的 `PC` 硬件，你需要二进制发行版“`Intel`”或“`386`”。[除非你准备好从自己编译 Linux 源码开始，这对于新手来说并不典型 :-] 这种情况发生是因为由于还有其他平台的二进制发行版（`PowerPC`、`Alpha` 以及可能还有十种更多）——它们并不不适用于你的 `PC` 兼容机，肯定无法工作。

简而言之，新手会对多个 Linux 发行版感到困惑，但拥有不同的发行版是有原因的。这应该被视为 Linux 的优势而非弱点。

本指南侧重于（`Intel`）平台上的 `RedHat 5.2`、`6.0` 和 `6.1`。许多答案适用于其他发行版或平台，但我们并未尝试。

## 1.2 Linux 的硬件要求是什么？

开箱即用的 Linux 运行在带有 `8 MB` 内存的 `386 PC` 上，但低端电脑对于纯文本应用程序（无 `X-Windows`）是实用的。配备 `16 MB` 内存和 `600 MB` 空闲（未分区）硬盘的 `486` 足够运行 `X-Windows`。我的那台带有 `64 MB` 内存的 `586-900 MHz` 运行如飞。我的带有 `64 MB` 内存的 `Pentium 2 237 MHz` 体验非常完美，即使在并发运行多个大型应用程序时也能几乎瞬时响应。我的带有 `8 MB` 内存和 `1 GB` 硬盘的 `486-32 MHz` 内存太小，无法在 `GUI` 下独立运行，但在我的家庭网络环境中很有用（一台 `486` 类机器如果至少有 `16 MB` 内存，独立运行也恰好足够）。我那台旧的带有 `9 MB` 内存和 `120 MB` 硬盘的 `Toshiba 386-SX-20 MHz` 便携式电脑在 `MS Windows 3.11` 下运行“旧应用程序”，并连接到我们的家庭网络，因此仍然有用。我们也在这台 `Toshiba` 上尝试了 `Debian`，它在文本模式下运行良好。

如果你愿意多克服一些困难，你应该能够在只有 `4 MB` 内存的环境下运行 Linux，但对于通用的家庭 Linux 机器来说，这可能不值得费力。我会说：至少获取 `16 MB` 内存，如果可能的话，`32` 或 `64 MB` —— 在并发运行多个 `GUI` 应用时，内存会产生差异。现在的内存很便宜。

## 双系统安装注意事项

如果你计划进行双启动（在同一台电脑上安装 Linux 和 MS Windows），请先使用你的 DOS/Windows 工具 `FDISK` 创建 MS Windows 分区。留出硬盘的一部分不分区以供 Linux 使用。你将在 RedHat 安装期间创建并格式化 Linux 分区。将 MS Windows 分区设为“主分区”且“可启动”的。在安装 Linux 之前，请先安装、配置并测试你的 MS Windows。如果你只想运行 Linux，刚开始只需要一个干净的硬盘（无分区）即可。



可以只设置一个 Linux 分区（如果是双引导，则再加一个 MS Windows 分区）。但分多个分区更好，这样你可以将用户数据与操作系统的其他部分分开。这样，一旦出现问题，你想格式化并重新安装操作系统时，你就不会丢失用户数据。（不过，如果你在安装时跳过提供的“重新格式化”选项，你也可以可以在不丢失包含所有用户数据的 `/home` 目录内容的情况下重新安装 Linux。）

| `/home` | `ext2` | 380 MB |
| `swap` | `swap` | 120 MB |

在上面的示例中，我分配了 300 MB 给存放 Linux 基础的挂载点。我分配了 1200 MB 给在文件系统中显示为 `/usr` 目录的挂载点，它将包含用户的程序（不是基础操作系统自带的、我之后安装的程序，例如 `WordPerfect`）。我分配了 380 MB 给显示为 `/home` 的分区，它将包含机器上所有用户的设置和数据。我分配了 120 MB 的“原始”分区供操作系统作为虚拟内存使用（硬盘上物理硅内存的扩展，即所谓的 `swap`）。如果你的内核版本低于 2.2（`RHEL` 2.2 及更早版本的情况如此），你的 `swap` 分区将大于约 127 MB。经验法是，你的 `swap` 大小应该是物理内存（`RAM`）的两倍左右。120 MB 的 `swap` 稍微有点，你可能不需要更多。如果你认为你需要更多（例如，你预计要运行具有大型数据结构的自定义程序），你可能需要在安装期间创建一个较大的 `swap` 分区（或较小的 `swap` 分区），或者添加 `swap` 文件。

2 GB 是一个很大的磁盘空间，即使对于喜欢拥有很多应用程序的用户来说也足够了。（因为 Linux 应用程序通常比相应的 MS Windows 程序精简）。

然而，如果你尝试安装互联网上所有提供的 Linux 程序，你肯定会耗尽硬盘空间的 :-)。我的经验是，无论硬盘有多大，它都会被填满，我会后悔没有更多空间了 :-)。

如果我的硬盘空间非常受限，我可能会考虑像这样的双分区设置（针对 Linux 分配的共计 600 MB 精简方案）：

| 挂载点 | 类型 | 大小 |
| :--- | :--- | :--- |
| `/` | `ext2` | 600 MB |
| `swap` | `swap` | 50 MB |

在这个示例中，我分配了 600 MB 来包含操作系统基础、应用程序和文档/数据，并给了 50 MB 作为 `swap` 分区（供操作系统作为虚拟内存使用）。50 MB 的 `swap` 对于中等负载的操作已经足够了。操作系统、应用程序和用户数据限制在 600 MB 意味着你必须选择安装哪些应用程序，否则将面临耗尽硬盘空间的风险。在安装 `Red Hat` CD 上的可选软件时，尝试按 `<F1>`——它将为你提供关于该软件功能的简短描述，以便你决定是否真的需要它。如果你做出合理的选择，可以轻松地在 Linux 分区留有 200 MB 空闲空间（在本示例中使用了 600 MB）的情况下完成 `RedHat` 安装。请注意，不建议将根分区和 home 分区“捆在一起”。

## 1.13 我完成了安装。我如何第一次登录？

作为 `root` 用户，"root" 是在初始安装后唯一存在的账户（较新的安装程序会在安装期间提示你创建一个普通用户账户）。登录示例如下：

```

Password: my_password
```

在上面的示例中，我在登录提示符处输入了 "root" 单词。之后，我输入了在初始 Linux 安装期间选择的密码。输入密码时屏幕上不会显示（出于安全考虑）。

"root" 是一个对系统拥有绝对权限的特殊账户，用于系统管理。你肯定想以后至少创建一个“user”（用户）账户来执行常规（而非系统管理）工作。请继续阅读了解如何操作。

## 2.2 有 help 命令吗？

大多数 Linux 命令可以使用 `--help` 选项运行。例如：

```
cp --help | less
```

通过命令行使用所谓的 `man` 页面访问更广泛的信息。例如：

```
man cp
```

将显示 "cp" 命令的手册页。手册页是 Linux 下标准的 "help" 系统，包含了丰富的详细信息，但通常需要花费精力理解。`man` 命令使用一个名为 `less` 的简单工具让你滚动文本。使用方向键滚动，按 "q" 退出。实际上，`info` 比这个更强大。按 "h" 查看运行 `less` 时的信息，或者学习使用 `man`。

还有 `info` 命令。例如：

```
info cp
```

如果你不确记得需要使用的命令名称，请尝试 `apropos`。例如，获取与 "copy" 相关的命令列表：

```
apropos copy
```

在菜单驱动的程序中，特别包括一个基于 GUI 的 "help" 浏览器，可以通过点击面板上的“书本”图标启动。该浏览器可以访问特定服务的帮助以及系统手册页。如果你想了解安装在 CD 上的许多 `rpm` 格式的软件包，你可能需要使用基于 `kde` 的 `info`（在 `RH6.0` 下，`info` 程序被 `man` 取代，后者快得多，但也不太方便）。

## 3.1 基础

### 3.1.1 文件名

`Linux` 是区分大小写的。文件名长度可达 256 个字符，通常包含字母、数字、下划线、点等。以下是一些元字符的含义：

- `*` = 匹配零个或多个字符（文件名开头的点除外）。
- `?` = 匹配任意单个字符。



- `[abc1]` = 匹配枚举集合中的单个字符。在此例中，集合是 `'a'`、`'b'`、`'C'` 或 `'1'`。

- `[a-z]` = 匹配任何小写字母。

- `[-F]` = 匹配拉丁表中 `A` 到 `F` 的任意大写字母。

- `[0-9]` = 匹配任何数字。

- `[a-zA-Z0-9]` = 匹配任何字母（大写或小写）或任何数字。

示例：此命令将显示当前目录下的每个文件名，排除以 `.`（点）开头的文件：

```
ls *
```

此命令的等效操作是输入 `ls` 或 `dir`。以 `.` 开头的文件不会显示，因为 `.` 作为文件名的第一个字符不会被 `*` 匹配。使用 `ls -a`（带有 `all` 选项的列表）或 `ls .*` 来查看“点”文件。点文件位于用户主目录中，通常用于存储用户级配置。

为了处理包含元字符的文件名，我使用一对单引号（`' '`），这样 shell 就不会解释它们的含义。例如，要删除一个 `file*` 文件，我会使用：

```
rm 'file*'
```

请注意，使用双引号（`" "`）包裹的效果比使用单引号（`' '`）的要弱。

此命令将显示任何包含点的文件名：

```
ls *.*
```

此命令将显示任何包含两个点的文件名：

```
ls *.*.*
```

作为一个在文件名中使用非推荐字符时可能遇到的问题示例，请尝试创建一个以破折号（dash）开头的文件，然后将其删除——似乎没有办法可以做到（破折号通常用于引入命令选项）。例如，执行命令

```
dir > -junk
```

将会创建一个奇怪的文件（符号为 `">"`）。

破折号前面的点（`.`）表示“当前目录”，在这里仅的作用是隐藏前导字符，使其不被解释为向 `rm` 命令引入的选项。要点是，我宁愿遵循传统的命名规范，以面对偶尔出现的复杂性问题。

### 3.1.2 不同的目录是什么？

在《Linux 系统管理员指南》（`SAG`）中对这一点解释得非常清楚，该指南在你的系统中应该是可用的。

```
cd /usr/doc/ldp/lynx sag.html
```

这将会启动一个文本浏览器 `lynx` 来查看这本 HTML 书。你也可以使用任何其他浏览器，例如 Windows 上的 `Netscape` 来查看这本书。这本书以及其他 `LDP` 书籍其实很好读。

简而言之，Linux 包含五个文件系统。这些文件系统可以位于单个或不同的物理硬盘和/或硬盘分区上，取决于你的系统的规模和需求。（如果需要，单个文件系统也可以分布在不同的物理设备之间。）

根目录 `/` 文件系统——包含基础操作系统和维护工具。该文件系统的内容应足以启动系统并在必要时执行紧急维护和修复。

`/usr` 文件系统——包含所有命令、库、文档以及在正常运行期间不更改的文件。这还包含许多应用程序，也许是随你的 Linux 发行版自带的那些，例如 `Netscape`。

`/var` 文件系统——包含会变化的文件：打印槽目录、日志文件、锁文件、临时文件。

`/home` 文件系统——包含用户文件（用户自己的设置、自定义文件、文档、数据、邮件、缓存等）。

`/proc` 文件系统——包含完全虚幻的文件。它们在磁盘上并不真实存在，也不占据那上的任何空间（尽管 `ls -1` 会显示它们的大小）。当你在查看这些文件时，你实际上是在访问存储在内存中的信息。它被用于访问有关系统的信息。

根文件系统的部分包括：

- `/bin` - 启动期间需要的命令，可能被普通用户使用。
- `/sbin` - 不供普通用户使用的命令（用户可能会使用它们）。
- `/etc` - 你的操作系统的系统级配置文件。
- `/root` - 系统管理员（称为超级用户）或 `root` 的家目录。
- `/dev` - 设备。设备出现在 Linux 中，因此很容易写入。
- `/mnt` - 可移动介质的挂载点（软盘、`CD-ROM`、`zip` 驱动器）、其他系统的分区（如磁盘）、网络共享，以及任何临时挂载在文件系统上的东西。它通常包含用于挂载共享的子目录。
- `/lib` - 位于根文件系统上的程序所需的共享库。
- `/boot` - 被 `LILO`（一种引导加载器）使用的文件，该程序是计算机启动时首先加载的内容，并为你提供一个启动哪个操作系统的选项，如果你的电脑上有多个一个 OS 的话。它通常包含 Linux 内核，但如果它可以存储在其他地方，则只有 `LILO` 配置为知道它在哪里。
- `/opt` - 可选的大型应用程序，例如 `RedHat` `5.2` 下的 `kde`（`kde` 像任何其他 `X-windows` 发行版一样分发，主可执行文件在 `/usr/bin` 目录）。
- `/tmp` - 文件系统修复期间恢复的临时文件。

`/usr` 文件系统最重要的部分是：

- `/usr/X11R` - `X-windows` 系统。
- `/usr/X11R` - 与 `/usr/X11R` 相同（它是指向 `/usr/X11R` 的符号链接）。
- `/usr/X11R/bin` - 许多小型的 `X-windows` 应用程序，以及可能指向位于其他子目录的较大的 `X-windows` 应用程序的可执行文件的符号链接。
- `/usr/doc` - 文档。
- `/usr/bin` - 许多可执行程序。
- `/usr/sbin` - 仅供系统用户使用的命令（普通用户可能可以使用它们）。
- `/usr/lib` - 位于根文件系统上的程序所需的库。
- `/usr/share` - 架构无关的数据数据。
- `/usr/local` - 本地安装的软件。
- `/usr/tmp` - 临时文件。

此命令获取环境变量 `PATH` 的内容（在 `/etc/profile` 中为所有用户设置），并将其附加到由变量 `HOME` 设置的主目录名称后面，后面带上 `bin` 和一个点。最后，该命令将生成的字符串赋值回变量 `PATH`。在修改 `PATH` 或任何其他用户环境变量后，必须使用 `export` 命令，以便该路径在设置它的脚本外部才可见。

### 3.1.5 我该如何关闭电脑？

#### 在文本终端中

如果你希望电脑在按下 `<Ctrl><Alt><Del>` 后停止（而不是默认的重启），你可以通过编辑 `/etc/instab` 文件来设置此项。该文件的内容类似于如下所示：

```
# Trap CTRL-ALT-DELETE
ca::ctrlaltdel:/sbin/shutdown -t3 -r now
```

以 `root` 身份将选项 `-r` 修改为 `-h`，使其内容变为：

```
# Trap CTRL-ALT-DELETE
ca::ctrlaltdel:/sbin/shutdown -t3 -h now
```

以 `#` 开头的行只是注释（是给人类看的，对电脑没有影响）。

`Root` 也可以使用 `shutdown` 命令。该命令可用于系统的本地或远程关闭。如果程序挂起导致键盘不再可用，那么远程关闭功能非常有用。例如：

```
telnet name_of_machine_with_no_operable_keyboard
[login as user]
su
[give password]
```

现在执行 `ps aux |more`，在 `ps` 输出中找到违规命令的进程 ID，然后执行：

```
kill pid_of_offending_process, 或者使用以下命令重启机器：
/sbin/shutdown -rn now
```

如果此命令将非常快地关闭，跳过标准的（更长的）关闭程序——这在系统变得非常不稳定时非常有用（`-n` 选项会让 `shutdown` 在重启之前杀死所有进程）。

请注意，出于安全考虑，你不能以 `root` 身份登录远程机器（例如通过 `telnet`）。你必须先以用户身份登录，执行 `su` 并输入密码以成为超级用户（`root`）。

`shutdown` 命令也可以用于稍后执行关闭。例如（以 `root` 身份）：

```
/sbin/shutdown -r 23:59
```

如果你觉得 `shutdown` 命令太长了，你可能想尝试这两个命令，它们的作用正如其名称所示（以 `root` 身份）：

```
reboot
halt
```

一种关闭电脑的别致方法是将系统切换到运行级别 `0`（停止运行）或运行级别 `6`（重启）。尝试使用它（以 `root` 身份）：

```
init 0
```

不同运行级别的含义在 `/etc/instab` 文件中均有解释。

### 3.1.6 我该如何处理挂起的程序？

有 Bug 的程序在 Linux 下会挂起。应用程序的崩溃不应该影响操作系统本身，因此发生的频率不应达到让你必须重启电脑的。根据我们的经验，操作系统异常可能是硬件或配置问题的迹象：反复遇到处理器过热问题（风扇转速变慢或完全停止，`Pent` 的散热器被脏垢堵塞）、内存问题、不同的定时设置（你可以尝试重新排列顺序，可能会有帮助）、错误的 `BIOS` 设置（你应该关闭“高级”选项，Linux 会自己处理这些事情）。

**并没有真正挂起。** 如果程序挂起，尽管某些程序可能会给人挂起的假象，但实际上它们只是在等待输入。这发生在程序期望从命令行参数接收文件名，但用户没有提供输入的情况下，因此程序默认指向标准输入（即控制台）。例如，此命令

```
cat
```



可能看起来像挂起了，但它是在等待键盘。尝试按下`<Ctrl>d`（表示“文件结束”），你会发现这满足了`"cat"`命令。另一个例子：我曾在新闻组中看到很多关于某个“有 Bug”的命令在尝试解压文件时挂起的提问，例如：

```
tar -xzv my_file
```

它在等待用户输入，因为没有指定`"-f"`选项，导致`my_file`未被识别。正确的命令是：

```
tar -xvmf my_file
```

请注意，文件名必须紧跟在选项`f`（代表文件名）之后。这种写法将不起作用（这是一个非常常见的错误）：

```
tar -zxvf my_file
```

**任何程序（无论是否挂起）都可以被杀死。** 前台的文本模式程序可以通过按下`<Ctrl>C`来杀死。这对于会阻塞`<Ctrl>C`的大型应用程序无效，因此它不会被误触。尽管如此，你仍然可以通过按下`<Ctrl>z`将程序发送到后台来重新获得控制权（不保证有效），或者切换到不同的终端，例如使用`<Ctrl><Alt><F2>`并以挂起程序的同一用户登录（这应该总是有效）。一旦重新获得控制权，找到你想要终止的程序，例如：

```
ps
```

此命令代表“打印状态（`print status`）”，并显示当前正在运行的程序列表。在`ps`输出中，找到挂起进程的进程 ID (`PID`)，现在我可以杀死它了。作为用户，我只能杀死我拥有的进程（这是我启动的）。`Root`可以杀死任何进程。要查看系统上运行的所有进程的完整列表，执行：

```
ps axu | more
```

这列出了所有运行中的进程（选项`a`），即使没有控制终端（选项`x`），并且列出了拥有每个进程的用户的登录名（选项`u`）。显示内容可能超过一屏幕，使用`more`管道可以使显示在每页屏幕后停止。

`kill`命令有一个快捷方式`killall`，用于通过名称杀死程序，例如：

```
killall netscape
```

将杀死任何名称中包含`netscape`的程序。

基于`X-windows`的程序没有控制终端，可能是最容易杀死的（在`X-terminal`中输入）：

```
xkill
```

此时光标会变成某种类似于死刑判决的符号；你指向该程序的窗口并按下左鼠标键；窗口将永久消失，相关的程序也会被终止。

如果你的`X-windows`系统崩溃到无法恢复，最简单的办法可能是按下`<Ctrl><Alt><Space>`来杀死`X-server`。之后，运行`ps axu`可能是个好主意，找到任何可能仍在运行的`X`程序并杀死它们。如果你不这样做，导致你`X-windows`崩溃的故障程序可能会再次引发麻烦。

如果你在后台有程序运行，操作系统会阻止你注销，并发出类似`There are stopped jobs`（有已停止的任务）的消息。要覆盖并注销，只需立即重复注销（或退出）命令——后台程序将被自动终止并将你注销。

**核心文件（Core files）。** 当程序崩溃时，它会在你的主目录中生成一个`core`文件。这会伴随相应的提示。`core`文件是内存映像（加上调试信息），旨在作为调试工具。如果你是一个不打算调试程序的用户，你可以直接删除`core`：

```
rm core
```

或者什么都不做（如果生成了另一个`core`，它会被覆盖）。你也可以使用命令禁用`core`转储：

```
ulimit -c 0
```

使用以下命令检查是否生效：

```
ulimit -a
```

（显示“用户限制”，选项`-a`代表“所有”）。要为所有用户永久禁用`core`转储设置，请以`root`身份编辑`/etc/profile`文件（即`ulimit`设置的地方），并调整设置。重新登录使`/etc/profile`的更改生效。

如果你想查看如何使用`core`文件，请在存放`core`文件的目录下尝试：

```
gdb -c core
```

这将在名为`core`的核心文件中启动`GNU`调试器(`gdb`)，并显示创建该核心文件的程序名称、程序终止时产生的信号等。输入`quit`退出调试器。要学习不同信号的含义，请尝试：

```
/usr/include/bits/signum.h
```

### 3.2 用户、密码、文件权限与安全

#### 3.2.1 主目录、root、添加用户

硬盘上（几乎）唯一允许普通用户（非`root`）可以写入其家目录的地方，该目录为`/home/user_login_name`。

这个“家”目录适用于所有用户：设置、程序配置文件、数据、网络缓存、邮件等。作为用户，你可以在自己的主目录下创建子目录以保持条理有条。除非其他用户授予了权限，否则他们无法读取您的文件或向您的主目录写入内容。

`root`（也称为超级用户）是一个特殊的管理账户，拥有修改系统中任何文件的权限。习惯性以`root`身份登录系统并不是好主意——错误可能会让你付出惨代价。为自己设置并使用普通用户账户进行日常工作，为儿子创建一个另一个账户，再为妻子创建一个。`root`账户是`Linux`在初始安装后唯一存在的账户。

`root`可以使用以下命令创建用户账户，例如：

```
adduser joe
passwd joe
[输入用户 joe 的密码]
```

`root`可以更改任何用户的密码，尽管她无法读取它。`[密码使用单向加密算法进行加密，且只有这个加密版本存储在系统的文件 /etc/passwd 中，而“明文”版本永远不会被存储。当你登录时，你输入的密码将使用相同的单向算法进行加密，并与存储在 /etc/passwd（旧系统）或 /etc/shadow（新系统）中的已加密密码进行比较。]`

管理员与用户的分离使得`Linux`系统既安全又健壮——这使得`Linux`下的病毒变得困难（用户可以运行的程序仅限于自己的目录，因此无法影响操作系统的关键部分）。

按照惯例，用户会在首次登录后立即更改密码，例如：

```
passwd
(current) UNIX password: pass_OLD
New UNIX password: pass_NEW
Retype New UNIX password: pass_NEW
```

在现实中，密码在输入时不会显示在屏幕上（出于安全考虑）。

#### 3.2.2 关于密码安全

弱密码可能是安全问题最常见的来源。即使在家里，如果有人在你浏览互联网和阅读文件时黑入你的电脑，你也可能面临麻烦。以下是一些危险密码的例子：

- 无密码（可能的！）
- 单词`password`（哇，这一个真的太弱了！）
- 你的名字或姓名或你的用户名
- 妻子（丈夫）、女儿、女朋友、狗等的名字；
- 公司名称、部门名称、实际上等。
- 你的出生日期；
- 写在日历上或电脑里的密码；
- 字典中的任何单词（字典包含的单词并没有看起来那么多，熟练的黑客可以设置程序尝试所有单词）；
- 你在在其他不安全的公共场所也使用的密码，例如网上商店或邮件列表。

一个良好的密码应该是较长的（至少 6 个字母），包含字母（尽可能包含大小写）和数字的混合，并定期更改（每 8 周？）。

系统管理员可以通过此配置程序包含的实用（以`root`身份运行）设置密码策略：

```
linuxconf
```

在菜单`user account`-`policies`:`password` & `account policies`下。

此外，确保任何包含密码的文件（例如`/root/.kde/share/config/kpprc`）都具有适当的安全权限，使其无法被任何人读取。你可能希望的是：

```
chmod 600 kpprc
```

#### 3.2.3 我忘记了 root 密码

永远不要忘记密码，我会详细研究这个问题，因为这可以给我提供关于我母亲如何阅读我的`ICQ`聊天记录的提示：

第一种。解决“忘记`root`密码”问题最简单的方法是以单用户模式启动你的`Linux`，即在`lilo-prompt (during bootup)`提示处输入：

```
linux single
```

这将让你在不询问密码的情况下成为`root`。现在，作为`root`，你可以使用此命令更改`root`密码（不需要旧密码的知识）：

```
passwd
```

如果你觉得这不安全，那是因为如果其他人对你的硬件有物理访问权限，那么没有一台电脑是不安全的。尽管如此，我不喜欢电脑上的`linux single`漏洞，并通过在我的`/etc/lilo.conf`中添加以下行（在`image=`部分的末尾）修复了它：

```
password="my_password"
```

这个`lilo`密码用于在启动时的`LILO`提示处，有人输入带有任何参数的`linux`时（可以正常启动）。为了让`/etc/lilo.conf`的更改生效，我必须重新运行命令：

```
chmod 600 /etc/lilo.conf
```



### 3.2.3 丢失 Root 密码的解决方法

解决“丢失 `root` 密码”问题的另一种方法是从 Linux 磁盘启动电脑，找到硬盘上的 `root` 分区并将其挂载，然后编辑 `/etc/passwd` 文件以删除 `root` 的密码。例如，`/etc/passwd` 中 `root` 的条目可能如下：

```
root:abcdefghijkl:0:root::/bin/bash
```

`abcdefghijkl` 是加密后的密码（实际上，这里是空的）。我将此行改为：

```
root::0:root::/bin/bash
```

现在 `root` 账户没有密码了，因此我可以重启电脑，并在登录提示处输入 `root` 并按回车（不需要密码）。成功登录后，我使用命令设置 `root` 密码：

```
passwd
```

上述内容适用于传统的 UNIX 文件。在较新的系统（例如 `RH2` 和 `RH6`）中，更安全的设置使用了影子密码文件。在这种情况下，`/etc/passwd` 在原本加密密码的字段包含一个 `x`。加密密码存储在 `/etc/shadow` 文件中。由于权限不同这增加了安全性：`/etc/passwd` 文件可以任何人读取，但 `/etc/shadow` 不能。此外，影子系统允许更长的密码，并添加了密码过期策略等额外功能。作为 `root`，你可以像操作 `/etc/passwd` 一样操作 `/etc/shadow` 文件。

### 3.2.3a 我忘记了密码

永远不要忘记任何密码。如果普通用户（非 `root`）使用其密码，这不是问题，因为 `root` 可以更改任何密码。例如（作为 `root`）：

```
passwd barbara
```

将提示为 `barbara` 设置新密码（不需要旧密码知识）。如果用户（非 `root`）想更改其密码，将被要求提供旧密码（这是一项安全功能，防止在你离开终端时他人更改你的密码）。

如果你需要临时禁用任何用户账户，无需更改密码。只需在 `/etc/passwd` 或 `/etc/shadow` 文件的密码字段（加密密码之前）放置一个星号 `*`。`*` 表示该账户不允许登录。当你想要恢复账户时，删除星号，账户即可使用旧密码恢复运行。

### 3.2.4 我遇到了文件权限问题。所有权和权限是如何工作的？

Linux（与 UNIX 相同）是一个多用户操作系统，这导致了“文件权限”的复杂性。权限问题会导致意外和糟糕的问题。理解权限对于管理任何多用户操作系统（无论是 UNIX、Windows 还是 Linux）都至关重要。我的建议是：学习 Linux（或任何 UNIX）权限系统，你不会后悔的。

权限规则对于普通文件和目录相同，因此对文件所说的也适用于目录。重要的是，低级目录（及其包含的文件）会继承父目录的权限。因此，如果你对父目录没有权限，你就不会对任何子目录（或其中的文件）拥有权限。

**文件所有者**

每个文件属于一个所有者（通常是登录名）和一个组。所有者通常是创建（或复制）文件的人。组通常包含一个人——所有者，且名称通常与所有者相同，但不必如此。文件可以仅移除（擦除）文件的所有者、该文件所属组的成员或 `root` 用户。

然而，如果赋予了相应的读取权限，其他用户可能也可以修改或删除文件的内容——以此类推。`ls -l` 命令（“长格式列出”）的输出中将显示文件的所有者和其所属的组。例如，执行命令：

```
ls -l junk
```

在我的屏幕上输出了以下输出：

```
-rwx------ 1 yogin inca 27 Apr 24 14:12 junk
```

这显示文件 `junk` 属于所有者 `yogin` 和组 `inca`。

文件的所有权可以使用 `chown`（更改所有者）和 `chgrp`（更改组）命令进行更改，这些命令通常由 `root` 用户执行：

```
chown peter junk
chgrp peter junk
ls -l junk
```

执行上述 3 行命令后，命令 `ls -l junk` 在我的屏幕上输出了输出：

```
-rwx------ 1 peter 27 Apr 25 20:27 junk
```

当你以 `root` 身份移动/复制文件以供其他用户使用时，文件的所有权会发生变化。

（注：原文后续内容存在大量重复与无意义的断句，已根据你提供的原文逻辑进行对应行翻译。）

对于其他选项，请查看：

```
man at
```

如果你想在系统负载较低时在后台执行处理器密集型任务，你可以选择使用 `batch` 命令。例如，我可以使用以下命令运行 `setiathome`（一个通过处理数据来帮助寻找外星生命的 SETI 的程序）：

```
batch
at>setiathome<Ctrl>d
```

在这个示例中，我输入了 `batch` 命令，然后在 `at> ` 提示符下，输入了我想要在后台执行的命令。该任务尝试立即启动，但只有当系统负载低于 0.8 时才会运行。你可以通过检查（虚拟）文件 `/proc/loadavg` 的内容来查看系统负载。

```
cat /proc/loadavg
```

## 3.3.2 我如何设置 cron？

Cron（一种在后台执行工作的 Linux 进程，通常在晚上运行）在你的 RedHat 系统上是默认配置的。除非你想在系统上定期执行某些任务，或者更改 cron 执行任务的时间，否则你不需要对它做任何处理。

请注意，某些 cron 工作可能对于你系统的长期运行至关重要。其中，cron 会：

- 重建在使用 `locate` 命令搜索文件时使用的文件数据库；
- 清理 `/tmp` 目录；
- 重建手册页（manual pages）；
- “滚动”日志文件，即丢弃旧日志文件、重命名中间日志并创建新日志；
- 执行其他检查，例如添加你最近复制到系统的字体。

因此，每天晚上都关闭 Linux 可能不是一个好主意——在这种情况下，cron 将永远没有机会执行工作。如果你喜欢在晚上关闭电脑，你可能需要调整 cron，让它在其他时间执行任务。

要查看 cron 在什么时候醒来执行任务，请查看 `/etc/crontab` 文件，例如：

```
cat /etc/crontab
```

它可能包含如下内容：

```
# run-parts root run-parts /etc/cron.hourly
01 * * * root run-parts /etc/cron.daily
02 4 * * root run-parts /etc/cron.weekly
22 4 1 * root run-parts /etc/cron.monthly
```

你可以看到 cron 作业分为四类：每小时、每日、每周和每月。

你可以修改这些分类或添加自己的分类。以下是其工作原理。

下面条目的列显示：分钟 (0-59)

因此，在引用的示例中，每小时作业在时钟显示“0 点一分”时执行，即每小时发生一次，在每小时的 1 分。每日作业在时钟显示凌晨 4 点 2 分时执行，每天发生一次。每周作业在周日 4 点 22 分执行。每月作业在每月第一日的 4 点 42 分执行。包含要执行命令的脚本文件目录将作为每行的最后一个条目。

如果你想让任务在正午执行而不是早晨 4 点，请将 `4` 改为 `12`。Cron 每分钟都会醒来并检查 `/etc/crontab` 是否发生变化，因此在你做出更改后无需重新启动。

如果你想向 cron 添加任务，请将运行你任务任务的脚本（或该脚本的链接）放置在 `/etc/cron.hourly`、`/etc/cron.daily`、`/etc/cron.weekly` 或 `/etc/cron.monthly` 目录下。

## 3.4 Swap space (交换空间)

Swap 是计算机物理内存的扩展。你可能在初始 RedHat 安装期间创建了一个交换分区。你可以验证系统上可用的交换空间大小：

```
cat /proc/meminfo
```

通常建议是：对于仅运行命令行的系统，至少需要 4 MB 交换空间和至少 32 MB 总内存（物理+交换）；对于运行 X-windows 的系统，至少需要 64 MB 总内存（物理+交换），且交换空间至少是系统上物理内存大小的 1.5 倍。

如果这太复杂了，你可能希望交换空间是你物理（硅基）内存的两倍，但不少于 64 MB。

如果你需要更改交换空间，这里有一些基础知识。

### 3.4.1 交换分区

你可以拥有多个交换分区，每个最大约为 124 MB。以下是创建和启用交换分区的步骤：

- 使用 `fdisk` 创建合适大小的分区（分区类型 82，“Linux swap"）。
- 格式化分区并检查坏块，例如：

```
mkswap -c /dev/hda4
```

你必须将 `/dev/hda4` 替换为你的分区名称。由于我没有指定分区大小，它将被自动检测。

- 启用交换，例如：

```
swapon /dev/hda4
```

为了在启动时自动启用交换，你必须将相应的条目包含在 `/etc/fstab` 文件中，例如：

```
/dev/hda4 swap swap defaults 0 0
```

如果你需要禁用交换，可以使用以下命令：

```
swapoff /dev/hda4
```



### 3.4.2 交换文件

交换到文件通常比交换到原始分区慢，因此这不是推荐的持久技术。然而，如果临时需要更多交换空间，创建交换文件是一个快速修复方法。你可以拥有多达 8 个交换文件，每个大小可达 16 MB。以下是制作交换文件的步骤：

- 创建一个指定大小的交换文件：

```
dd if=/dev/zero of=/swapfile bs=1024 count=8192
```

`dd` 命令物理上创建了 `swapfile`，块大小（`bs`）为 1024，块数（`count`）为 8192，总大小约为 8 MB。（在上面的示例中，输入文件 (`if`) 是 `/dev/zero`，输出文件 (`of`) 是 `/swapfile`。）

- 使用命令格式化文件：

```
mkswap /swapfile
```

- 使用命令启用交换：

```
swapon /swapfile
```

如果你需要禁用交换，可以使用：

```
swapoff /swapfile
```

## 3.5 Shell

### 3.5.1 什么是 Shell？

Shell 是用户和操作系统内核之间的接口程序。它接收用户的命令并将其传递给内核。Linux 中有很多类型的 Shell。最常见的有 `bash` (Bourne Again Shell)、`csh` (C shell)、`tcsh` (enhanced C shell) 和 `ksh`。

### 3.5.2 我如何编写 Shell 脚本？

Shell 脚本是由 Shell 执行的包含一系列命令的文本文件。脚本通常具有 `.sh` 扩展名，但这不是要求的。创建脚本，你可以使用任何文本编辑器如 `vi` 或 `nano`。

例如，创建一个名为 "untar" 的脚本来提取压缩包：

```bash
#!/bin/bash
echo this is the script $0
echo untarring the file $1
# this calls tar with options -xvzf (extract, verbose, filter through gzip, input filename)
tar -xvzf $1
```

脚本的第一行以 `#!`（称为 shebang）开头，这是特殊的——它告诉 shell 该用什么程序来解释脚本。在示例中，脚本由 `bash` shell `/bin/bash` 解释。第一行必须以 `#!` 开头，否则脚本将无法运行（文件将被视为纯文本文件）。

脚本中的 `$0`, `$1`, `$2` ... 是传递给脚本的参数。例如，如果我运行带有七个参数的脚本 "myscript："

```
myscript a b c d e f g
```

那么 `$0` 在 "myscript" 内部的值为 "myscript"，`$1` 将拥有值 "a"，`$2` 为 "b"，`$3` 将是 "c"，以此类推。

在我示例脚本的第二行和第三行中，`echo` 命令在屏幕上打印该行之后的所有内容，将 `$0` 和 `$1` 扩展为传递给脚本参数的值。第四行是我写给自己的注释，用来提醒我想要实现的目标，以防我以后需要修改脚本。第五行执行实际工作。

一旦脚本编写完成，我为文件所有者添加执行权限：

```
chmod u+x untar
```

这样我的脚本就可以使用了：

```
./untar my_tar.tar.gz
```

Linux 脚本功能非常丰富、灵活、强大，且可能很复杂。然而，为常见任务编写简单的自动化脚本并不需要特殊知识。你只需要将一组常用的命令一个一个地组合到一个文件中即可。我使用脚本是因为我太懒了，不想又一遍地输入相同的组命令。

## 4.1 LILO 问题

### 4.1.1 Linux 无法检测我所有的内存

如果你有超过 64 MB 的物理内存，Linux 内核 2.0.36 或更低版本默认只使用前 64 MB。要查看 Linux 在你的系统中使用了多少内存，请输入：

```



`cat /proc/meminfo`

你可以通过以下检查 Linux 内核版本：

`uname -a`

最后一个带有“内存问题”的流行内核 2.0.36 随 `RedHat 5.2` 发布。我的 `RedHat 6.0` 带有 `2.2.5-15` 内核，因此它不再有“内存问题”了。

为了让 `RH5.2` 识别超过 64 MB 的内存，你必须以 root 身份编辑 `/etc/lilo.conf` 文件，在 `image=` 语句之前添加如下行：

`append=mem=80M`

如果你的内存量不是 80 MB，请调整上述行。为了使 `/etc/lilo.conf` 中的任何更改生效，必须重新运行 `lilo` 程序。重启后，你可以使用任一命令检查调整是否生效：

`cat /proc/meminfo`
`free`

出于测试目的，或者如果你遇到问题，LILO 提示中指定内存量的选项是："mem=16M"。如果你在启用内存时遇到问题或机器死机，这将跳过。例如只启用 80 MB。对于某些 SCSI 控制器显然是这样。有时某些系统 Linux 只识别 16 MB 内存，这通常与 BIOS 设置中的“memory hole”（内存洞）有关（解决方案是禁用该 BIOS 设置）。在 BIOS 中禁用“高级”功能通常可能是好的（例如病毒检测会导致系统崩溃）。

### 4.1.2 LILO 只显示 LI（或 LIL）并卡死

引用自 Kamran Hussain、Timothy Parker 等人编写的书籍《Red Hat Unleashed》，由 Sams 发布：

当 LILO 加载时，它会显示 LILO 字样。每个字母在执行操作之前打印。如果 LILO 在某处失败，可以使用已打印的字母来识别问题。这是由几何结构不匹配或未运行 `/etc/lilo.conf` 引起的。几何结构意味着硬盘 BIOS 配置中使用的扇区/磁头/柱面数。希望这有帮助！拥有的关于 Linux 的优秀书籍是非常好的，Windows 的没用！如果遇到上述 LILO 错误，你可以使用 Linux 或 DOS 软盘启动。修复此类错误有几种通用方法：

1. 如果 LILO 损坏，可以删除并重新安装。可以在 Linux 下运行：
   `lilo -u /dev/hda`
   或者在 DOS 下运行：
   `DISK/MBR`
   这将重写 LILO 所在的硬盘主引导记录 (MBR)，将其替换为 DOS 内容。你会失去对 Linux 的访问，但可以从软盘启动并在 DOS MBR 之上重新安装 LILO。要重新安装 LILO，只需以 root 身份运行 `lilo` 命令。

2. 在你的 `/etc/lilo.conf` 文件中指定 `linear` 选项。这对于大硬盘 (>8 GB) 特别有用。详情见 `man lilo.conf`。“linear”选项是安全的——它不会影响正常运行的系统，因此你可以在任何情况下指定。

3. 查看你的 BIOS 设置，找出硬盘几何结构不匹配的原因。在 Linux 下，可以使用显示硬盘几何结构（例如第一个 IDE 硬盘）：
   `hdparm -g /dev/hda`

4. 将 LILO 放在另一个分区（不同的硬盘）并通过 `fdisk` 将该分区设置为启动（如果你的系统支持从另一个硬盘启动）。

5. 可能你喜欢使用 "loadlin" 而不是 "lilo"。在 DOS 下，找到你的 CDROM 并查看程序 `/dosutils/loadlin.exe`。它可以从 DOS 启动 Linux。

`lilo`

### 4.1.4 启动过程中 LILO 提示在屏幕上停留时间太短（或太长）

### 4.2.1 我的驱动器在哪里？

Linux 将所有目录显示在一个目录树中，无论它们位于哪个驱动器/硬件上。通常，这比传统的 DOS/Windows 模型要好得多——它将文件系统从底层硬件完全抽象。如果你需要重新排列或扩展硬件或添加网络资源，你会体会到这一点。对于习惯了 DOS 处理驱动器方式的用户来说，这增加了一些额外的复杂性。

简而言之，不要寻找驱动器号。Linux 下没有驱动器号；磁盘的内容显示为单一 Linux 文件系统（目录树）上的子目录。默认情况下，内容的可移动介质不会自动出现在这些子目录中——你必须“挂载”你的驱动器。详情请参见后面的答案。在弹出介质之前，你应该先卸载驱动器。

你可以在 Linux 下访问（读写）各种驱动器和系统。这包括原生 Linux 分区、DOS 和 MS Windows 分区（在硬盘或软盘上）、ZIP 和 Jazz 驱动器以及 CDROM 驱动器。还支持许多常见的文件系统。这意味着你可以使用 Windows 版 Netscape 下载 Linux 软件，将下载的文件保存到你的 Windows 硬盘分区，然后启动 Linux 并将下载的软件从 Windows 分区拷贝到你硬盘的 Linux 分区，最后在 Linux 上安装该软件。

### 4.2.2 我如何访问我的 CDROM？

挂载它。挂载会将你 CD 中的所有驱动器和文件添加到你的 Linux 目录，这样你就可以无需驱动器号轻松访问它们。

作为 root 用户，你可以可以使用这样的命令挂载 CDROM：

`mount -t auto /dev/cdrom /mnt/cdrom`

如果此操作有效，你的 CD 内容将立即出现在 `/mnt/cdrom` 目录中——你可能需要对其进行自定义。以下是工作原理。

该命令告诉操作系统挂载一个自动检测文件系统类型的文件系统（" `-t auto` "）。设备是 `/dev/cdrom`。挂载点（进行“挂载”操作的目录）是 `/mnt/cdrom`。此目录必须存在且为空。如果它不存在，使用以下命令创建它：

`mkdir /mnt/cdrom`

如果挂载命令失败，请确保检查设备 `/dev/cdrom` 是否存在。如果不存在，你的 CDROM 在哪里？如果你有一个 IDE CDROM，它很可能是类似 `/dev/hdb` 之类的设备。尝试在上面的挂载示例中使用 `/dev/hdb` 代替 `/dev/cdrom`。如果此操作仍然失败，且你的 CD 是 IDE CDROM，你可以尝试 `/dev/hdc` 或 `/dev/hld`。如果这些都不是你的 CDROM，那么你拥有的可能不是驱动器，而是 SCSI CDROM？尝试 `/dev/sda1`、`/dev/sda2` 等。["`hda`"是主 IDE 主驱动器，"`hdb`"是主 IDE 从驱动器，如果你的电脑上有两个接口，"`hdc`"是次级 IDE 主驱动器，"`hdd`"是次级 IDE 从驱动器，"`sda`"是第一个 SCSI 接口后面加上数字。]

总之，拥有一个 `/dev/cdrom` 设备是一个好主意，因为某些程序假设它存在。如果它在你的系统中不存在，你可以创建一个符号链接，例如：

`ln -s /dev/hdb /dev/cdrom`

如果你的 cd 是 `/dev/hdb` 驱动器。

如果你因为“设备已挂载或目录忙”而无法挂载，可能是挂载点 `/mnt/cdrom` 是你当前的目录。你必须切换到其他目录才能挂载；例如，通过此命令将当前目录更改到根目录：

`cd /`

要卸载已挂载的 CD，编辑 `/mnt/cdrom` 目录并以 root 身份输入：

`umount /mnt/cdrom`

如果没有挂载，CDROM 可能拒绝弹出介质。此外，如果上一个 CD 未卸载，挂载下一个 CD 时可能会遇到问题。如果你因为“设备忙”而无法卸载，可能是 `/mnt/cdrom`（或任何子目录）就是你所在的目录？你需要将当前目录切换到挂载点之外的地方才能卸载设备。

## 4.2 我是 root 时可以挂载。普通用户可以挂载吗？

你必须以`root`身份编辑`/etc/fstab`文件，以赋予普通用户挂载驱动器的权限。例如，我可以使用`pico`编辑器来实现：

`pico -w /etc/fstab`

`"-w"`选项关闭长行换行。

以下是我的`/etc/fstab`内容：

`/dev/hda2 /ext2 defaults 1 1

/dev/hdc3 /home ext2 defaults 1 2

/dev/hdc2 /usr ext2 defaults 1 2

/dev/hdc4 swap defaults 0 0

/dev/fd0 /mnt/floppy auto noauto,users,rw 0 0

/dev/cdrom /mnt/cdrom auto noauto,user,ro 0 0

/dev/sda4 /mnt/zipdrive vfat noauto,user,rw,exec 0 0

/dev/hdl /mnt/dosdrive vfat noauto,user,rw 0 0

one /proc proc defaults 0 0

hacker:/mnt/cdrom /mnt/hacker_cdrom nfs noauto,user,ro 0 0

hacker:/mnt/floppy /mnt/hacker_floppy nfs noauto,user,rw 0 0

hacker:/home /mnt/hacker_home nfs noauto,user,rw 0 0

hacker:/usr /mnt/hacker_usr nfs noauto,user,rw 0 0`

每行包含空格分隔的字段（这意味着每行有六个由空白分隔的目）。第一个字段是设备名称。第二个字段是挂载点（`Linux`系统上存在的目录，资源将挂载此处）。第三个是文件系统类型。对于包含多种类型文件系统的可移动介质，使用`"auto"`选项让`Linux`探测当前存在哪个文件系统。探测顺序由`/etc/filesystems`文件的内容决定。（你可能想在挂载`/msdos`之前确保指定了`"fat"`，否则`DOS`文件名可能会被截断。）第四个字段包含选项：`"auto"` = `"user"`有权限挂载此文件系统（`"rw"` = 可读可写；`"ro"` = 只读，`"user"`有权限挂载此文件系统（也可以使用`"users"`），允许一个用户挂载而另一个用户卸载——否则只有挂载该文件系统的用户可以从该文件系统执行`"exec"`程序。第 5 字段中的数字指定文件系统是否在系统备份中，第 6 字段中的数字决定在启动期间是否检查文件系统的完整性。`/etc/fstab`中的条目是我家庭网络中另一台计算机（称为`"hacker"`）上的文件系统，它是如何挂载网络资源的示例。更多请查看`man fstab`。

例如，普通（非`root`）用户有权限挂载光驱（指定了`"user"`选项），他们可以使用如下命令进行挂载：

`mount /mnt/cdrom`

使用`root`选项进行挂载的命令（参见此处 `[63]`）对普通用户不起作用，因为用户受到`/etc/fstab`中选项的限制，因此无法特定挂载设备和挂载点。

为了普通用户能够向磁盘写入或在其上执行程序，必须赋予其“挂载点”目录的适当权限。例如，这将赋予所有用户对`/mnt/floppy`目录的所有权限（读、写、执行）：

`chmod +rwx /mnt/floppy`

现在（在`/etc/fstab`中为软盘也指定了`"rw"`选项）用户将能够向软盘写入。如果`/etc/fstab`中也启用了`"exec"`选项，用户还能从软盘执行程序。

请注意，`DOS vfat`文件系统并不知道`Linux`文件权限。`Linux`通过在挂载的文件系统上赋予默认文件权限来处理此挂载：挂载文件系统的用户将成为所有文件的所有者，并获得写入文件系统的权限（如果在`fstab`中指定了`"rw"`），但其他用户只能读取。如果你想更改此行为，可以使用`"umask="`选项，这样你的`/etc/fstab`中的相应行可能像示例所示：



`/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0`

```
/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0
```

这赋予了你的 zip 盘绝对权限（挂载、卸载、读、写、执行）。

总结来说，`/etc/fstab` 文件是存储如何挂载文件系统的默认以及允许用户什么类型访问的地方。你确实希望自定义它以简化系统的挂载。Linux 默认的挂载方案是限制性的，为了安全，在家庭中设置 Linux 时可能想要移除一些限制。

将 `ppa` 模块插入内核中。（我猜 "ppa" 代表“并行口优先接口”（`parallel port first interface`））

完成所有操作后，检查 `/proc/modules` 查看 `ppa` 模块是否已加载（或以 `root` 身份运行 `lsmod` 列出模块）。来自 `kernelcfg` 的信息会写入 `/etc/conf.modules` 文件，因此在删除模块（我误插入的 1）时会遇到困难——就像我刚刚那样——我手动编辑并调整了该文件。

```

使用 Linux 内核 `v2.2.0.36` 及以下版本，你将无法使用通过并行口 zip 驱动器连接的打印机（这在内核 `2.2.x` 上有效）。使用命令

## 裸 X 服务器与 X 会话管理

裸 X 服务器是一个简化的 X 窗口系统，没有“窗口管理器”。你可以通过在 X 终端中输入程序名称（带前缀 `./` 或完整路径）来在此处执行 X 窗口程序，但你无法移动或调整窗口大小、添加图标等。

输入 `exit` 或按 `<Ctrl><Alt><Backspace>` 即可退出 X 服务器。如果 X 服务器无法正常工作，你可能需要重新调整配置文件。

挂载 `/etc/conf.modules`：

```
mount /etc/conf.modules
```

### 远程 X 会话设置

在远程服务器上启动一个 X 程序，并将显示重定向到你的本地屏幕，例如，你可以启动一个窗口管理器：

```
startkde -display local_machine_name:0.0 &
```

符号 `&` 将命令置于后台运行，这样你的 `telnet` 窗口仍然可用。
`:0.0` 表示“显示器 0，屏幕 0”，这是你第一台显示器上的第一个屏幕，这很合理，因为在你运行 Linux 的电脑上正运行着多个并发的 X 会话。

如果你的环境变量 `DISPLAY` 已经指定了当前终端的正确位置，你就不需要指定 `-display` 选项。在我的系统中默认就是这样，但对我其他人来说并不一定。你可以使用以下命令检查 `DISPLAY` 设置：

```
echo $DISPLAY
```

完成 X 会话后，使用以下命令恢复对 X 运行器的访问控制：

```
xhost -name_of_the_remote_server
```

或者

```
xhost
```

示例：这系列命令将在名为 `marie` 的远程机器上运行 `Netscape`，并将显示重定向到运行在本地机器 `hacker` 上的带有 X 窗口管理器的 X 服务器上：

```
startx
xhost marie
telnet marie
[login]
netscape -display hacker:0.0 &
[do my stuff]
[logout]
xhost -marie
```

原则上，你可以在网络上的任何计算机上运行程序，并将输出显示在任何一台（不一定是你正坐的这台）机器上。

我经常使用远程 X 窗口功能在轻量机器（486-33，8 MB 内存）上运行重量型程序（`kde`、`Word Perfect 8` 和 `Netscape`），而这些机器本身无法运行这些程序。对于没有设置 `nfs` 挂载的远程系统，这也是处理文件的一种既方便又快速的方法。

## 4.5 设置网络

### 4.5.1 建立家庭网络值得吗？

这是一个非常棒的主意。它能让你利用上现在放在衣柜里的那些机器，因为它们的性能不足以独立运行。益处包括：共享硬盘、`zip` 盘、`CD-ROM`、调制解调器、打印机甚至是扫描仪；远程运行程序（文本或图形模式）；以及通过一个连接在所有电脑上同时上网。如果你失去了对机器的控制，你可能还可以远程关闭它以避免可能的问题——详情请参见“关机”部分的回答。

### 4.5.2 如何设置我的家庭网络？

**硬件。** 你的硬件必须正确设置。你的网卡应该在初始 `RedHat` 安装期间已经设置好了。如果没有，你可能需要从 `X-windows` 中设置网卡。如果你的电脑上有多个网卡，你必须手动设置第二块网卡，因为 `Linux` 只会自动检测 1 个网卡。

启动一个 `X` 终端（`X-terminal`），执行 `su` 获取 `root` 权限，然后运行：

```bash
/usr/bin/kernelcfg
```

在 `Linux` 下，大多数网卡驱动程序都是作为模块实现的。因此，设置网卡只需插入带有参数的模块。你不需要重新编译内核，也不需要重启电脑（除非你使用的是非常罕见的网卡）。要确定你需要哪些模块和参数，请参阅《Linux 网络管理员指南》（`Linux Network Administrator Guide`，系统中的文件为 `/usr/LDP/nag`，或检查 `http://metalab.abc.org/mdw/index.html#`）。该指南被称为 `nag`。

参数（`IRQ` 和地址）在我在一台电脑上设置两块网卡时遇到了问题——你必须确保没有任何硬件冲突。问题的常见源是网卡想要配置 `IRQ 5`（被 `SoundBlast` 占用），或 `IRQ 3`（与串口 `COM2`, `cual`, `tty1` 冲突）。检查 `/proc/interrupts`、`/proc/ioport` 文件以及重启时的启动消息可能会有所帮助。

例如，你的 `WD8013` 卡（与 `SMC Elite` 和 `SMC Elite plus` 相同）位于 `IRQ 10`（通过卡上的跳线设置，我在内核模块设置中指定了 `IRQ`），地址为 `0300`，使用了 "WD" 模块。我的 "SMC EtherZ" 卡（卡上无跳线设置）运行在 `IRQ 9`，地址 `0240`，使用 "SMC EtherZ" 模块。请务必不要省略地址开头的 "0x"—它表示“十六进制”，否则数字将被解释为十进制。

从 `kernelcfg` 添加模块并重新运行内核后（`kernelcfg` 提供了此功能，见菜单），检查 `/proc/modules` 文件以查看模块是否已加载（或以 `root` 运行 `lsmod`）。来自 `kernelcfg` 的信息会写入 `/etc/conf.modules`，如果你遇到困难（例如，我曾难以移除误插入的模块），只需编辑并调整该手动文件，例如使用 `pico`。

**网络。** 在设置网卡并连接电缆后，以 `root` 身份运行以下命令设置网络：

```bash
netconf
```

该程序带有帮助信息！`netconf` 可以在 `GUI` 下运行，但我并没有真正尝试过。如果你需要更多关于网络工作原理的理解，可能想阅读之前提到的 `nag`。

在你的网络 `netconf` 中需要填写哪些内容？你肯定需要填写“基本主机信息”（启用以太网接口 `eth0`，本地电脑的名称、别名和 `IP`）以及“其他主机信息”（局域网内其他电脑的名称、别名和 `IP`）。这些信息对应文件：`/etc/hosts` 和 `/etc/sysconfig/network`，因此你可能需要检查并调整这些文件。

设置网络时，不要动用 `IP` 为 `127.0.0.1` 的“回环驱动程序”（`loopback driver`）。它一直存在——它是机器与自身通信的 `IP`。

如果你没有 `IP` 地址（对于没有与外部世界永久连接的家庭网络而言），你可能需要插入一个。当你通过调制解调器连接外部世界时，具体是什么 `IP` 并不太重要，你会动态分配到一个 `IP` 地址（机器名称可以同时拥有多个 `IP` 地址）。你插入的 `IP` 必须正确，子掩码必须匹配网络类别（`A` 类、`B` 类或 `C` 类）。参见前面提到的《网络管理员指南》中关于 `IP` 地址的章节（系统中的 `/usr/doc/LPD/nag`，如果没有，现在从 `http://metalab.unc/mdw/index.html#` 下载）。

通常，网络上的第一台机器是预期连接到外部世界的机器（因为它是第一个连接的，但这并没有标准）。因此，我在所有机器上将 `GATEWAY` 设置为 `xxx.xxx.xxx.1`（我的第一台机器），但在 `xxx.xxx.xxx.1` 这台机器上留了空。实际上，尽管我留了空，`netconf` 在 `/etc/sysconfig` 文件中插入了网关 `0.0.0.0`。这在启动加载网卡时产生了一个恼人的错误信息。为了消除它，我编辑了 `/etc/sysconfig/network` 并将其设置为如下：

```bash
# GATEWAYDEV=
GATEWAY=
```

[如果这台机器的以太网接口不通往外部世界，你就不希望在该接口上设置网关。一旦你通过调制解调器连接（例如使用 `kpppp`），第一台机器上的 `ppp` 接口将被设置为默认网关。]

电脑的名称完全是随机的——主用户通常选择一个他喜欢的短单词。家庭网络的域名也完全是随机的，除非你有一个永久连接并向你注册了密集的域名。尝试发明一个不存在的名字——如果你有永久连接，这会让你的生活更轻松。

至于 `DNS` 服务器（也称为 "named"），`RedHat 5.2` 和 `6.0` 预装了 `DNS` 且为“仅缓存”——选择非常容易。你也可以选择完全不使用 `DNS`——如果 `DNS` 有一台服务器且你能找到它。

找到一个适用于你的 `ISP`（互联网服务提供商）的。

在其中一个实例，我遇到了连接建立稳定性问题（会弹出错误提示，如：`ppp` 启动超时），并且每隔几次尝试才能建立连接）。通过将“设置”（`setup`）下“设备”部分中的“流量控制”选项从“CRTSCTS”更改为 `XON/XOFF` 解决了这个问题（在大多数情况下，`CRTSCTS` 仍然是推荐的流量控制方法）。从 `RH5.2` 升级到 `RH6.0` 后，与 `ppp` 连接的性能（速度）和可靠性得到了提高。如果你在这些方面遇到问题，也许是时候升级了。

如果你在设置 `ppp` 时持续遇到困难，如果你在 `RedHat` 初始设置时选择了安装，你可能想尝试系统自带的 `minicom`。以下是来自 `newsgroup.linux.help` 的一个关于如何使用 `minicom` 手动启动 `ppp` 的帖子（为了节省空间已编辑）：

2. 拨打你的 `ISP`。

```

## 4.5.4 如何从没有调制解调器的联网计算机上上网

网络上的另一台计算机必须有一个调制解调器（或另一个互联网连接）。设置`IP`伪装（`masquerading`）。这样，从你的网络到服务提供商（`ISP`）的所有请求看起来都源于一台计算机，而你的`IP`允许它们通过。使用`RH5.2`进行简单的伪装只需要命令（在带有调制解调器的电脑上）：

```bash
/sbin/ipfwadm -F -p allow
```

因此，将伪装作为`IP`防火墙的默认转发对于家庭用户来说是不安全的。（危险在于，网络中的某人可能需要“隧道”路由回你的网络以连接他的身份。）更多信息，请检查文件`/doc/HOWTO/mini/IP-Masquerade`。更安全的设置在此处所示：

```bash
ipfwadm -F -p deny
ipfwadm -a allow -S 192.168.1.1/32 -D 0.0.0.0
ipfwadm -a allow -S 192.168.1.3/32 -D 0.0.0.0
ipfwadm -a allow -S 192.168.2.0/24 -D 0.0.0.0
```

这会将默认策略设置为“拒绝”，并显式地伪装`IP`为`192.168.1.1`和`192.168.1.3`的两台机器。它还伪装了网络`192.168.2.0`中的任何机器。`/32`代表点对点网络（这意味着“机器到机器”），`/24`选项识别`C`类网络。`-D 0.0.0.0`标识了机器伪装后去往的的默认路由。

在`RED HAT 6.0`中，命令的名称是`ipfwadm-wrapper`（而不是`ipfwadm`），我必须使用第二种更安全的方法（将伪装作为默认策略在任何系统上有效）。

如果你想让这个命令在启动时始终执行，请将其添加到`/etc/rc.local`的最后。这个文件就像`DOS`中的`AUTOEXEC.BAT`。

如果你想从命令行启动`ppp`，请运行`netconf`来配置你的(`ppp`)。你必须输入的信息与设置`ppp`时输入的内容类似（如上面所示！）：调制解调器的正确设备、初始化和拨号设置、你的服务提供商（`ISP`）数量、正确的验证协议（通过在正确的槽中输入用户名和密码）。我编辑了`/etc/ppp/secrets`并在设置行末尾添加了`DNS`地址，创建的结果如下：

```
my_login_name ppp0 password dns_server
```

`OK`，`PPP`将开始运行。尝试`ping`你的`ISP`或另一个`IP`地址。这将测试一切是否正常。如果你能通过这种方式让`PPP`运行，说明你没有配置上的问题。

你可以将`Windows`目录挂载到`Linux`文件系统上。请查看[第 65 页]了解如何操作。

上述描述只是一个最小的`Samba`设置。你可以从以下地方获取更多信息：

## 4.5.6 Sendmail

`Sendmail`是标准的邮件传输系统，也是`RedHat 5.2`和`RedHat 6.0 Linux`默认邮件传输系统。作为用户，你并不直接使用`sendmail`——`sendmail`是后台管理你邮件的底层引擎。若要在文本模式下读写/发送邮件，你可能想使用`pine`或`elm`（保持它们运行对于管理独立的邮箱箱可能会不方便）。在`KDE`中，你可以选择使用`K`菜单中提供的“mail”。要通过你的`p`拨号与外部世界通信，你可能想使用内置在`Netscape`中的`Mozilla`邮件，它会直接与基于远程互联网服务商的邮箱进行通信。

`Sendmail`非常灵活且健壮，但如果你需要根据特定需求对其定制，它也很难以管理。幸运的是，`RedHat`（`5.2`或`6.0`）带了开箱即用的`sendmail`（尽管有一些局限性）。

在我的家庭系统（`Red Hat`设置）上，我可以顺利地向同一台机器上的另一个用户发送邮件（使用`pine`除外）。通过这种方法连接到互联网服务商后，我可以向世界任何地方发送邮件。如果我没有连接，邮件就会留在队列中等待（这是一个小困扰）。一旦连接，邮件就会发送（这是因为`sendmail`尝试进行一项在我系统中不可用的`DNS`查询——`RedHat`默认为仅限缓存）。如果你真的想在`RH6.0`上避免这种情况，可以使用`netconf`（以`root`身份）并指定`sendmail`完全不使用`DNS`（`RH5.2`的`Linuxoconf`并没有提供此选项）。我确实在使用`DNS`。

在`Linux 6.0`下，你可能还需要配置其他`sendmail`选项（以`root`身份）`netconf.conf`。我在“mail delivery system--relay to hosts”下输入了互联网服务商名称以及家庭网络上其他机器的名称。我还在“relay for by”下添加了我家庭网络机器的名称。

如果你从家庭网络（例如使用`pine`）向网络之外的世界发送电子邮件，你也应该意识到你的设置的局限性。如果你发明了`IP`地址且你的域名未注册，那么你没有机会收到回复。你的发出的邮件被赋予了一个格式为“user_login_name@machine.domain”的“回复”地址。这并不是

因为根据外部世界的任何`DNS`，你的域名并不存在，因此没有任何回复能到达这里。为了克服这个问题，你可以使用`Netscape`邮件程序与家庭网络外部进行通信。`Netscape`使用你在“edit-preferences”中输入的设置直接与你基于`ISP`的邮箱（该邮箱位于你`ISP`的注册服务器上）通信，并绕过你未注册的、基于家庭网络的电子邮件系统。另一种可能性是在“reply-to”字段中指定正确的地址。如果你在`Netscape`中这样做，你可以将`NetscapeMail`设置为本地`Linux`计算机为服务器，这样就可以从你的`NetscapeMail`发送电子邮件到家庭网络上的计算机（而不仅仅是“外部世界”。“reply-to”选项也可以在`KDE`的“mail client”设置中设置。此外，在“pipe”中，你可以在“setup-configure”，“customized-hdrs”下指定`reply-to`地址，内容如下：

```
Reply-to: joe@joe_net.net.
```

其中“joe@joe_net.net”是你可靠的回复邮件地址。

## 4.5 人如何从外部世界访问我的计算机

唯一的困难在于，IP 地址是由你的互联网服务商 (ISP) 动态分配给你的，因此在连接时 IP 是并不相同的（除非你与你的 ISP 妥善了特定安排）。一旦我知道了 IP 地址，我可以通过 ICQ 或电子邮件将其发送给朋友，然后他可以例如 `telnet` 计算机（他/她必须在我的机器上有一个账户）并在我的 Linux 机器上运行程序，或者在浏览器的“位置”行输入 `http://my_ip_address` 来浏览我的家庭网页等。我还可以写一个短脚本，在在我连接到互联网时自动通知我，并在“kppp-setup-account-dial-execute program upon connect”程序下指定脚本名称。这是我的脚本，当我家里有人上网时，它会在工作时通知我（我将文本输入到一个文本文件中并制作了

```bash
file executable using chmod o+x file_name:

#!/bin/bash
sleep 15
/sbin/ifconfig | mail -s notification my_email_address
```

此脚本的第一行告诉你的计算机将此文本文件解释为 `bash` 脚本。第二行让脚本等待 15 秒（这只是为了确保在 `ppp` 连接完全建立之前发送电子邮件）。第三行执行 `ifconfig` 命令并将输出通过给 `mail` 工具，该工具将以“notification”为主题将其发送到我的邮箱地址 `my_email_address`。

访问家中的电脑的一种灵活方法是将其配置为拨号 `ppp` 服务器（这与你连接到 ISP 时使用的拨号客户端相反）。如果有人知道如何操作的简单配方，请告诉我们。

## 4.5.10 我的家中的电脑会被黑客攻击吗？

遗憾的是，这是完全可能的，而且尝试这样做的情况非常常见。每当你连接到互联网服务提供商（ISP）时，你就面临着风险。如果你想知道这是如何可能的，请阅读之前的答案。

真正的危险是入侵者，如果他/她能够登录你的机器任何账户，找到另一个安全漏洞并获得 `root` 权限。如果你是一个真正的新手管理员，或者你的机器不是以安全为导向的，这种情况尤为可能（因为你在家里，不是吗——谁会在乎安全呢，谢谢！）。

为了保护自己，请为计算机上的所有账户设置同时包含数字和字母的长密码。在所有计算机上强制执行密码策略的最佳方法是运行（以 `root` 身份，`RH6.0` 中可用）`linuxconf`，并在“password and account policies”下，将最小长度设置为 6 或更多字符，将非字母数字字符（即符号）的最小数量设置为 1 或 2，将密码后必须更改的天数设置为 90 天或更短，并将密码过期相关的设置设置为过期前约 7 天左右。有关弱密码的更多信息，请在此处查阅。

偶尔扫描包含你电脑所有登录记录的文件也是个主意：`/var/log/secure`（最新日志）、`/var/log/secure.1`（旧日志）、`/var/log/secure.2`（更旧的日志）等。`/var/log` 目录下还有你可能想查看的其他日志文件，请定期检查它们。

如果你删除了到家里 Linux 的连接，你可能希望限制 `telnet`、`ftp` 等的使用权限（所有网络服务都列在 `/etc/inetd.conf` 文件中），仅限家庭网内的机器。访问由两个文件控制：`/etc/hosts.allow` 和 `/etc/hosts.deny`。访问控制的工作原理如下：当请求外部连接时，会扫描 `/etc/host.allow` 文件，如果请求连接的机器名称匹配，则授予访问（无论 `/etc/host.deny` 中是否有任何条目）。否则，扫描 `/etc/hosts.deny` 文件，如果请求连接的机器名称匹配，则关闭连接。如果两个文件中都未找到匹配项，则授予权限。例如，你可以通过在 `/etc/hosts.deny` 文件中插入以下条目，拒绝家庭网络之外的任何机器对你家服务器的 `telnet` 和 `ftp` 访问：

```
in.telnetd, in.ftpd: ALL EXCEPT LOCAL, .your_home_domain.name
```

欲了解更多信息，请查看优秀的《Linux 网络管理员指南》，这肯定包含在你的 RedHat（或其他）发行版光盘中。我打印了这本书并制作了硬壳装订。

## 5. 如何升级你的内核？

### 5.1 引言

编写本文是为了帮助 Linux 新手升级他们的内核。

我使用了多种来源来编写本文。包括从官方的 `HOW-TOs`（`http://metalab.unc.edu/LDP/HOWTO/`）到 Linux 知识库和其他来源。

### 5.2 什么是内核？

内核充当你的程序和硬件之间的调解者。首先，它对所有运行中的程序（进程）进行（或安排）内存管理，并确保它们获得公平（如果你愿意，也可以是不公平的）处理器周期份额。此外，它为程序提供了一个良好的、可移植的接口来与你的硬件通信。

内核的操作显然不仅于此，但了解基本功能是重要的。

### 5.3 为什么要升级？

升级内核有几个原因。大多数原因是你需要更快的设备，或者内核存在漏洞。

### 5.7.2 使用完整源码

如果你下载了源代码，你需要阅读这一节。

我们现在假设你位于 `/usr/src/kernel`。我们已经解压了新内核（第 5.6.2 节）。现在我们将移动到内核目录（假设名为 `linux`）。输入 `cd linux`。

现在我们位于内核目录中。现在让我们开始全新的编译。

1. 输入 `makeconfig`
2. 输入 `make dep`
3. 输入 `make clean`
4. 输入 `makeImage`（如果失败，请使用 `beImage`，它代表 `bigImage`）
5. 输入 `make modules`（如果你启用了它们）
6. 输入 `make modules_install`（如果你执行了第 5 步）

我们需要配置你的内核。我们在这里不会进行细节或解释，因为配置在不同机器之间是不同的。请明智地进行配置，如果你不知道某个选项的含义，请将其保留在配置之外。

如果一切顺利，我们就获得了一个新内核，可以安装到系统上使用。

### 5.8 安装新内核

安装新内核需要编辑位于 `/etc/` 目录下的 `lilo.conf` 文件。它会因机器而异，在你的机器上看起来可能与其他机器上不同。

首先，我们假设你仍在 `/usr/src/linux/` 目录。我们需要将新内核和 `System.map` 拷贝到位置，这在某些发行版中是不同的。

让我们切换到新内核目录。

如果在第 `5.7.x` 节使用了`make zImage`，则你应该拷贝`zImage`文件，否则拷贝`bzImage`文件。我们假设使用`zImage`。

你现在面临的选项是将内核拷贝到什么位置。在 Red Hat 发行版中，内核位于`/boot/`，在 Slackware 中位于`/`。我不熟悉其他发行版（Debian, SuSe 等）。请根据你的发行版选择你拷贝新内核的位置。

我们将为 Red Hat 制作示例。

输入`cp /boot/vmlinux-2.2.12`

现在切回目录`/usr/src/linux/`。

输入`cd /usr/src/linux/`

现在让我们拷贝新的`System.map`。请注意`System.map`始终位于`/boot/`。

输入`cp System.map /boot/System.map-2.2.12`

现在我们必须创建一个指向新`System.map`的新符号链接。

首先通过输入`cd /boot`进入`/boot`目录。现在删除旧的符号链接（注意符号链接只会删除链接本身，不会删除其指向的文件或目录）。输入`rm System.map`。现在让我们创建一个指向`System.map-2.2.12`的新符号链接。输入`ln -s System.map-2.2.12 System.map`

我们所做的就是编辑`lilo.conf`文件，在其中添加我们的新内核并运行`lilo`。

通过输入`cd /etc`切换到`/etc`目录，使用你喜欢的编辑器（`vi`, `joe`, `pico`）编辑`lilo.conf`文件。对于我们的示例，我们将使用`joe`。

你会在文件中看到类似的内容：

```
boot=/dev/hda
map=/boot/map
initrd=/boot/boot
prompt
timeout=5
image=/boot/vmlinux-2.0.36-0.7
label=lilo.old
root=/dev/hda1
read-only
```

请注意，这在你的系统上可能有所不同。

现在我们将新内核添加到我们的`lilo.conf`文件中。拷贝从`image`到结尾的部分，并将其在当前`image`之前粘贴。你应该得到类似的内容：

```
boot=/dev/hda
mapper=boot/map
install=boot/boot.b
prompt
timeout=50
image=boot/vmlinux-2.0.36-0
label=linux.old
root=/dev/hda
read-only
image=boot/vmlinux-2.0.36-0
label=linux.old
root=/dev/hda
read-only
```

现在将粘贴的部分更改为你新内核的设置和版本。对于我们的示例（我们使用 2.2.4 内核），它看起来如下：

### UNIX 提示的注意事项

例如：`Netscape`、`NETSCAPE` 和 `nEtscape` 是三个不同的命令。同样，`my_fiE`、`my_file` 和 `my_fILE` 是三个不同的文件。你的用户登录和密码也是区分大小写的。（这符合 UNIX 和 "C" 编程语言区分大小写的传统。）

1. 文件长度最多可达 256 个字符，可以包含字母、数字、`.`（点）、`_`（下划线）、`-`（连字符）以及其他不推荐的字符。
2. 以 `.*` 开头的文件通常被`ls`（列出）或`dir`命令显示。将这些文件视为“隐藏”文件。使用`ls -a`查看这些文件。
3. `/` 等同于 DOS 的 `\`（根目录，意味着所有其他目录的父目录）。
4. 在 Linux 下，所有目录都出现在单一目录树下（没有 DOS 风格的驱动器号）。
5. 在配置文件中以 `#` 开头的行是注释。

## 6.4 进程控制

`ps status` 显示当前运行的进程列表及其进程 ID (`PID`)。使用 `ps axu` 查看系统上的所有进程。

`fg` 将后台进程带到前台。

`bg` 将进程发送到后台。`fg` 的相反。

`any_command&` 在后台运行任何命令。符号 `"&"` 表示后台运行。

`kill PID` 强制停止进程。确定要杀死的进程 `PID`。

`killall` 按名称杀死程序。`programname`（在 `xwindow` 中）杀死 `GUI` 程序。用鼠标指向你想杀死的窗口。

`lpc`（作为 `root`）检查并控制进程。使用 `"top"` 查看可用命令列表。

`job_number` 从队列中移除打印作业。

`nice` 运行程序并调整其优先级。由于示例中未指定优先级，它将被调整 `10`（默认值为 `0`）。`nice` 值越低，优先级越高。优先级值范围为 `-20` 到 `19`。只有 `root` 可以设置负值。使用 `"top"` 显示运行进程的优先级。

`renice -1 PID`（作为 `root`）将进程优先级改为 `-1`。普通用户只能调整其拥有的进程的当前值。

## 7.10 刻录 CD-Rs (``` cdrecord ``` 和 ``` cdparanoia ```)

**免责声明**：复制受版权保护的是非法的。请勿将下面的说明用于任何非法活动。

### 简介

设置 CD 刻录机可能很复杂。欲了解良好信息请参阅 http://www.guug.de/~wenni/linux/cdr/html/CD-Writing-3.html。

我使用上述文档在运行 ``` RH6.0 ``` 的 PC 上设置了一个廉价的无品牌 ``` IDE-ATAPI ``` CD 刻录机。它可以正常工作，而且在最近升级到 ``` RH6.1 ``` 后，我的设置无需进行任何更改。

以下是我遵循的步骤（几乎所有操作都要以 ``` root ``` 执行）：

### 设置

1. 在文件 ``` /etc/lilo.conf ``` 的 Linux ``` "image" ``` 部分末尾添加一行：
   ```
   append="hdb=ide-scsi",
   ```

   如果你的 CD 刻录机不是 ``` "hdb" ```（第一个 ``` IDE ``` 接口上的第二个驱动器），请调整上面的行。这会让你的 ``` IDE-ATAPI ``` ``` CD-W(R) ``` 在 Linux 系统中被识别为 ``` SCSI ``` 设备。（它实际上不是 ``` SCSI ``` 设备，而是一个 ``` IDE ``` 设备，它伪装成 ``` SCSI ```。）在对 ``` /etc/lilo.conf ``` 进行任何更改后，运行 ``` lilo ```。如果你使用 Linux 内核 ``` 2.2.x ```，则上述更改对于启用 ``` IDE-ATAPI ``` ``` CD-R(W) ``` 上的 ``` SCSI ``` 是必须的。

2. 将循环设备添加到 ``` /dev/ ``` 目录中。这并非强制性的，但它是你创建自己的 CD 时可以享受的一项实用功能。循环设备允许你挂载 CD 镜像（如果它已经是文件系统）以检查其内容。在安装 Linux ``` RedHat ``` 后，我的硬盘上并不存在循环设备，所以我创建了它们：
   ```bash
   cd /dev/
   mknod loop
   ```

3. 在文件 ``` /etc/rc.d/rc.local ``` 的末尾添加两行，以便在系统设置时自动加载内核模块：
   ```bash
   /sbin/insmod ide-scsi
   /sbin/insmod loop
   ```

   这两个内核模块分别用于 ``` IDE ``` 驱动器的 ``` SCSI ``` 仿真以及支持循环设备。

4. 创建或修改设备 ``` /dev/cdrom ```，使其指向正确的设备，最可能是：
   ```bash
   ln -s /dev/sr0 /dev/cdrom
   ```

   你需要这样做是因为你的 ``` "dev/cdrom" ``` 之前指向的是一个 ``` IDE ``` 设备（很可能是 ``` /dev/hdb ```），但现在这些更改将使你的 ``` CD-R ``` 进入 ``` SCSI ``` 仿真模式。

5. 重启系统使 ``` /etc/lilo.conf ``` 生效。检查你的 ``` CD-R(W) ``` 是否仍能正常读取。

6. 从你喜爱的 Linux 软件仓库下载 ``` "cdrecord" ```（例如，``` http://fdirect.linux.org/ ```）。然后安装源码、编译它、安装程序，并创建易于运行的符号链接（如果你能找到二进制 ``` *.rpm ``` 文件，安装将变得简单得多）：
   ```bash
   cd /usr/local
   tar -xvzf /the_path_to_which_you_downloaded/cdrecord-1.6.1.tar.gz
   ls
   cd cdrecord-1.6.1
   make

   make install
   ls /opt/schily/bin/
   ln -s /opt/schily/bin/* /usr/local/
   ```

   程序 ``` cdrecord ``` 是一个刻录 CD 的简易命令行工具。它有几个 ``` GUI ``` 前端，但如果底层的 ``` cdrecord ``` 不支持，这些前端将毫无用处。

7. 检查你的 ``` CD-R ``` 是否处于 ``` SCSI ``` 仿真模式。

### 工具说明

程序 ``` cdrecord ``` 是一个刻录 CD 的简易命令行工具。它有几个 ``` GUI ``` 前端，但如果底层的 ``` cdrecord ``` 不支持，这些前端将毫无用处。

```bash
cdparanoia -B -p "1-2"
```



Parametr`-B`určuje použití"balového"režimu(batch), díkyžž každá stopa vložena do samostatného souboru (to je pravděpodobně to, co chcete, jinak by byly všechny stopy v jednom výsledním souboru). Parametr`-p`určuje výstup v surovém formátu(raw). Soubory mají názvy`track1.cdda.raw`a`track2.cdda.raw`.

Pro stakopování všech stop z audio CD, každou stopu do samostatného souboru`*.wav`, při vynucení rychlosti čtení 4x, mohu použít:

```
cdparanoia -S 4 -B "1-"
```

Ujijte se, že máte na tvrdém disku dostatek volného míst. Můžete využít místo na partition DOS (pokud máte dual boot systém).

- Pro napsání audio souborů na CD-R(W) mohu použít:

```
cdrecord -v speed=2 dev=1,0,0 -audio*
```

- Staré stereo si nepřečete mnoho CD-R (to souvisí s velikostí drážek na CD). Moje domové stereo však vůbec neumí číst přepsapsitelné CD (CD-RW), ale přečte jednorázové disky (CD-R), tyto přepsapsitelné mohou být dobré pro uklování dat, ale pro audio (pokud je neplánuji segment výhradně na svém počítači).

## OSTATNÍ PROBLÉMY

Přepsapsitelná CD (CD-RW) se používají stejně jako běžná jednorázová zapisovací CD (CD-R), ale přepsapsitelné disky musíte před vymazat, než je budete znovu použít, například:

```
cdrecord -v speed=2 dev=1,0,0 blank-fast
```

Pro zobrazení dalších (důkladnějších a pomalejších) možností vymazání použijte:

```
cdrecord blank=help
```

Pro zjednodušení dlouých příkazů požadovaných`cdrecord`mohu definovat globální alias pomocí umístění následujícího řádku do souboru`/etc/bashrc`:

```
alias cdrecord="cdrecord -v speed=2 dev=1,0,0"
```

Přihlásit se znovu, aby se změny v`/etc/bashrc`projeví. Po vytvoření tohoto alias mohu nýt CD pomocí zkráceného příkazu (nemím stále specifikovat rychlost zápisu CD a název zařízení):

```
cdrecord -audio track*
```

Většina CD lze zkopírovat kopírováním všech dat (pro data CD) nebo všech stop (pro audio CD) na tvrdý disk, jak je popsáno, ale u některých CD to nejde. U problematmatických CD můžete zkusit něco jako toto:

```
dd conv=noerror,sync if=/dev/cdrom of=cd_image
cdrecord -t audio cd_image
```

Příkaz`dd`kopíruje vstupní soubor(`if`), který je v tomto případě zařízení`/dev/cdrom`, na výstupní soubor(`of`), který je v příkladu soubor`cd_image` (na tvrdém disku v aktuální adresá). Parametr`"conv=noerror,sync"`určuje, že potenciální chyby při čtení budou ignorovány a soubory nejsou odstiženy. Návrat na domovou stránku: Linux Newbie Guide
