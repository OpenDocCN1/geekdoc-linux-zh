# ## Use Numba dynamically and statically

Numba includes a decorator that you can use to selectively compile up sections of your code from a regular Python program. This essentially enables you to compile specific sections of code on the fly. A very example would look like this:

```
from numba import jit

@jit
def my_func(x, y):
    return x + y
```

In the output, you would get

56
34

As the last been not actually printed. You can check to see if greenlet is by checking the death of actual execution: it is true if the greenlet has lived and exited. You can combine greenlets and Python threads. A single thread can have as many greenlets as required, and they will be behaved as expected within a thread. The more complex your application, the more greenlets from another need to communicate.

When code runs, Numba looks at the function and compiles an optimized binary version of this code. Then, however, this function will call the rest of the program, the compiled version is actually running. You can use the jit decorator to compile functions that have side effects, for example, nogit to tell the compiler that it should not access any Python objects and the GIL can be not handed back to the main Python thread. This works well only with primitive data types such as integers or floats.

Using PyPy requires no code changes; the changes needed for Numba are also pretty minimal.
