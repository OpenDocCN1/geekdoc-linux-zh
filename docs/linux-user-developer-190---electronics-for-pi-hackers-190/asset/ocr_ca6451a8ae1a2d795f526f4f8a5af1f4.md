This works for a small website, but before long
we have a large project with multiple files in
directories, of all time might be taken to copy
the server. It would be enough to write a script to
copy, but if we make a change to one
file we don't have to copy the whole thing;
we only want to copy the files that we have changed.

The answer to this problem is to build a sync
utility that tells which files have changed since
tlast the push, and copies only those files to
the server. The entire operation of Make is made
around modification times of files, it makes sense to use
it a tool to build a sync utility.

We use one (only) auxiliary file.push, the last
function of which is the record of the last time we
pushed to our local repository. In the time, before we
push the changes to the server, we run the command
touch last_push.

We copy the files to the server when of
them have changed since the last time we did a push.
This suggests that the files we want to push to the
server all be prerequisites for the last_push.

```
FILES = *.html *.css *.js
last_push = $(FILES)
```

The recipe for last_push should contain the
command touch last_push, in order to update

```
FILES = *.html *.css *.js
LAST_PUSH = .last_push
SCP = ./server_copy.sh
PHONY: push
push: $(LAST_PUSH)
	$(SCP $(FILES)
	touch $(LAST_PUSH)
```
