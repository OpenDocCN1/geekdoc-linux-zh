# ## Rhopts and RSA Authentication Configuration

This authentication scheme is conceptually described in *Rhopts and RSA Authentication* on page 286. To configure authentication using this method, you will need to set the rhopts-RSAAuthentication keyword appropriately. For the server, make sure that the entry

```
RhoptsRSAAuthentication yes
```

appears in `/etc/ssh/sshd_config`. For the client, you may use the same record as a command line option in the user’s `$HOME/.ssh/config` file or in the `/etc/ssh/ssh_config` file. You will also need to make sure that the client hostname appears in at least one of the trusted host files on the server.

Let’s consider an example. Suppose that we want to allow two trusted hosts access to the server pluto using this authentication scheme. We configure `/etc/ssh/ssh_config` as shown in Example 11-12. The entries associated with this authentication scheme (those that will be discussed) are in bold. Note that the last entry, **AllowHosts** tpcat underdog, limits the use of this scheme (and Rhopts Authentication, if it were turned on) to users from the two hosts, tpcat and underdog. We must also put the hostnames, tpcat and underdog, in an appropriate trusted host file on the server pluto. Example 11-13 shows the .rhopts file on pluto in the home directory of the user mary.

# **Example 11-12 Limiting Rhopts Authentication Access with AllowHosts**

```
# sshd config file for host pluto
Port 22
ListenAddress 0.0.0.0
HostKey /etc/ssh/ssh_host_key
RandomSeed /etc/ssh/ssh_random_seed
ServerKeyBits 768
LoginGraceTime 600
KeyRegenerationInterval 3600
PermitRootLogin yes
IgnoreRhopts no
IgnoreRootRhopts yes
StrictModes yes
QuietMode no
X11Forwarding yes
X11DisplayOffset 10
FascistLogging yes
PrintMotd yes
KeepAlive yes
SyslogFacility LOCAL5
RhoptsAuthentication no
RhoptsRSAAuthentication yes
RSAAuthentication yes
PasswordAuthentication yes
PermitEmptyPasswords no
AllowHosts tpcat underdog
```

# **Example 11-13 /home/mary/.rhopts file**

```
# .rhopts for ssh
underdog
tpcat
```
