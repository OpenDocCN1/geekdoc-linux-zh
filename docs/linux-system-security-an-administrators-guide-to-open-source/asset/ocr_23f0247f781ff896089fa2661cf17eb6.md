# Oh, By the Way...

> If you are setting up `tiger` on a secure server, the `TIGERHOME` directory can be set read only after the install has been performed. The `TIGERROOT` and `TIGERLOGS` directories will need to be writable when `tiger` executes, but should be protected from tampering at other times. It is recommended the directories chosen be something private to `tiger` only. Do not use the `/tmp` directory.

Now execute `make` as illustrated in Example 13-11.

Depending on your processor, number of users, and amount of memory, some checks will take longer than others. You will want to run some scripts more frequently than others. For example, you probably will not want to run `crack` every day (but then again, you're root---you can if you want to).

Now that you have installed `tiger`, you can set up a `cron` schedule to regularly run various parts of `tiger` on your own customized schedule. This involves adding a `cron` job to run `tiger/cron`, say every hour. `tiger/cron` will check the `crontab` file and run only those tasks that you have scheduled, and keep root's `crontab` a little cleaner.

The first time `tiger` runs via `tiger/cron`, you (or the user configured via the `Tiger_Mail_RCPT` variable in the `tiger.conf` file) will receive the full report via e-mail. On subsequent runs, only the changes since the previous run will be reported.

A sample `crontab` file is shown in Example 13-12.

# **Example 13-12** Sample crontab file

```
# Sample 'tiger/cron' crontab file...
# By running 'tiger/cron' from `cron` say, once an hour:
# 0 * * * * .../tiger/cron >/dev/null 2>&1
# You can run the different checks in stages, without having to
# clutter up the crontab for root.
#-------------------------------------------------------------
```
