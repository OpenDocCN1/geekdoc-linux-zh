Many of the scripts have configurable options. They are all listed in Table 13.6 on page 352. In Example 13-2 on page 357, we make several customizations. First, we configure *tiger* to not report messages of level INFO (with *Tiger_Show_INFO_Msgs=N*) and to set the width of reports run both on the command line (79 characters wide) and through *tigercron* (0, which means unlimited line length).

Next, for the *check_embedded* script, we specify to check three levels of recursive depth; to check only executables (in other words, not all regular files), but to check anything that is a SUID file; and, when generating the report, report only the embedded files found that are executable. (There’s a difference between checking and reporting; you will probably want to try both settings and see the difference or leave them both set to 1.) Also with *check_embedded*, we have said that we will allow *root*, *bin*, and *ucp* to own embedded system files (*Tiger_Embedded_OK_Owners*), but they can be writeable by only the root group (*Tiger_Embedded_OK_Group_Write*).

For the *check_path* script we configure to not check user *PATH* variables. Similarly, to *check_embedded*, we specify *root*, *bin*, *ucp*, or *news* can own executables in *root*’s path and that only root can write to them (*Tiger_ROOT_PATH_OK_Owners* and *Tiger_ROOT_PATH_OK_Group_Write*). There are similar variables that can be used if you check *PATHs* belonging to the users (*Tiger_PATH_OK_Owners* and *Tiger_PATH_OK_Group_Write*).

We configure *tiger* to wait for the output from Crack before producing the *tiger* report (*Tiger_Collect_CRACK*) and to crack local (*Tiger_Crack_Local*) passwords, rather than those from NIS. We’ve configured it to send the *tiger-cron* output to root (*Tiger_Mail_RCPT*).

The *Tiger_Files_of_Note* (other than being cryptic looking!) is a list of files of a specific pattern to report that we are using (the line that came with the sample *tigercc* in Example 13-2 on page 357). It will look for files with spaces, three or more dots, .log, and .fSP, which at one time or another were fairly good signs of intrusion.

Near the end of the file, there are several configuration options for the *find_files* script that allow us to enable or disable certain types of checks or to scan read-only file systems. We’ve enabled them all (*Tiger_FSScan_*) except we don’t want to check read-only file systems (*Tiger_FSScan_ReadOnly=N*).

We haven’t added anything to our USERDOTFILES variable—we are using what came in the sample file. These dot files will be checked for correct permissions and characteristics with the USERDOTFILES variable. And, finally, the RHOST_STRES variable defines what hostnames to ignore (if any) in .rhosts files. We’re allowing the users to have *topcat* or *mydomain.com* in their .rhosts files.
