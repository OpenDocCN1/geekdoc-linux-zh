Since I am only interested in text contents, I'll focus on `content.xml`.

In Figure 4, you can see how the “Hello World” text occurs in the XML file: it is enclosed in opening and closing `<text:p>` tags. For quickly finding text inside such tags you could search for the `<text:p ... >` to `</text:p>` pattern. On the command line, `grep` (or its sibling `egrep`) will do the job, but the XML file contains no line breaks, so we will first add a line break after each “>`” symbol. The streaming editor `sed` can do that:

```
$ sed -e '$s/>/\n/g' \ncontent.xml | egrep "</text:p"
```

![](bbox=[0.4, 0.59, 0.6, 0.63])

If you inspect other documents (with more complex formatting), you will notice that `<text:p>` is not the only XML tag that will hold text; Writer also stores text in `<text:span>` tags. The proper `egrep` pattern for these two tags is

```
“</text:(p|span)”,
```

Actually, this pattern is a regular expression. Regular expressions are used in many areas of computing, both theoretical and practical: They let you describe search terms in a simple language that allows for very complex patterns. For example,

```
(([a-z]|[a-z0-9]){b}()*$</\1)
```

is a regular expression that matches all text blocks that consist of an opening HTML tag (such as `<h1>`), some element content (such as the headline), and the corresponding closing tag (`</h1>`). Thus, `<h1>Hello</h1>` will match, but `<h1>None</h2>` will not because h1 and h2 are not the same.

# FINDING STUFF

If you only want to search a collection of Writer, Calc, or Impress files for some keywords, you already have all you need. To make this more usable, create the shell script `logrep.sh` shown in Listing 1.

The script works out-of-the-box on macOS and Linux machines; Windows users need to install a Unix/Linux subsystem with a Bash shell, for example Cygwin [4] will do. Alternatively, you could install openSUSE or Ubuntu via the new “Windows subsystem for Linux” feature that requires a recent Windows 10 release [5], though that option will require some configuration.

The script uses the `mktemp` command which generates a temporary file with a random name. That file is immediately deleted and in its place a new directory with the same name is created where the zip file can be unpacked.

If you have no Bash shell installed, use the Python script in Listing 2 instead. It does the same thing but uses Python's `zipfile` module to access the `content.xml` file inside the zip file, and it does not create temporary folders or files like the Bash script does. Figure 5 shows how the Bash script and the Python script deliver identical results.

In order to launch the `logrep.py` script from the Linux or macOS command line, simply enter `./logrep.py` (with leading dot and slash) in the directory that holds the script file, and provide the search pattern and a list of file names as arguments. Windows users running the `cmd.exe` shell enter `python logrep.py` followed by the same arguments.

If you get strange error messages from running the Python script, make sure that you are using a Python 2.x version — the script is not compatible with Python 3.x.
