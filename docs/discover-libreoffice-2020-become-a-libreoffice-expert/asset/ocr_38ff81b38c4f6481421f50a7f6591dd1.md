# DATA ENTRY FORM

Entering data directly into the table works pretty well with a table like *Category*, which only has one field other than the automatically numbered *ID*. In the *Place* table, all rooms, cupboards, and racks also can be filled in directly. The *Article* and rel_Article_Place tables, on the other hand, are more difficult to fill because both tables have fields for which the primary key is set as a foreign key in a different table. Therefore, both of these tables are good candidates for an input form.
To create a form, click on *Forms* in the sidebar and choose *Use Wizard to Create Form*. A window with a sidebar shows eight steps for creating a form.
1. **Field selection.** The wizard opens with the Article table already chosen in a drop-down in the main wizard window. All fields should show in the main form, so use the double-arrows to transfer them from the left box (list of available fields) to the right box (list of fields to appear in the form).
2. **Set up a subform.** Unfortunately, this step does not yet work automatically with the newly built in Firebird database, so you have to chose tables and link fields in the next steps yourself. Choose *Subform based on manual selection of fields*.
3. **Add subform fields.** Choose the rel_Article_Place table in the drop-down and move all fields to the rightmost box.
4. **Get joined fields.** Link the *ArticleID* field of the subform (rel_Article_Place table) with the *ID* field of the main form (Article table).
5. **Arrange controls.** The wizard now helps you lay out the interface in one of four formats. You can leave the entry form as a table, present the data entry cells in columnar form with labels to the left or on top, or arrange the form in *Blocks – Labels Above*. In this example, I display the main form in columns with labels on top, and I leave the subform as a *Data Sheet*. Now all places mentioned by an *Article* can appear in a form view.
6. **Set data entry.** Leave this step as is.
7. **Apply styles.** This step is a matter of taste. As shown in Figure 4, the background for the form is set to *Light Gray* and the border to *Flat*.
8. **Set name.** The form is now usable, but has a number of weaknesses; therefore, after entering a name, choose *Modify the form* and click *Finish*.
The following weaknesses can now be resolved:
*   The *Image* field shows only the path to the image, not the image itself.
*   The *ID* field is editable (although not visible here). A write protection should prevent modification of the primary key.
*   The *CategoryID* field shows the foreign key value (the Category table ID), not the *Category* value itself.
*   In the table foreign field (the sub-form) the foreign key value of *PlaceID* is shown instead of the contents of the *Place* table *ID*.
*   The display of *ArticleID* is not necessary because the value is already shown in the *ID* field of the main form.
If the form is not editable, close then re-open the form by right-clicking the form name and choosing *Edit* in the context menu. The fields will now be edited in the same order as arranged in the table.
Choose the *Image* input box by *Ctrl-Clicking*; then, *right-click* and select *Replace with \ Image Control from the context menu. Right-click again and choose *Control to get the Properties dialog*. In the *General* tab, click *Scale \ Keep Ratio in the drop-down so the image will not appear distorted.
