Since I am only interested in text contents, I'll focus on `content.xml`.

In Figure 4, you can see how the “Hello World” text occurs in the XML file: it is enclosed in opening and closing `<text:p>` tags. For quickly finding text inside such tags you could search for the `<text:p ... >` to `</text:p>` pattern. On the command line, `grep` (or its sibling `egrep`) will do the job, but the XML file contains no line breaks, so we will first add a line break after each “>” symbol. The streaming editor `sed` can do that:

```
$ sed -e 's/>/\n/g' content.xml | egrep "</text:p"
```

![](img/e39350c3a7c0d527d71b0e4097a0ba66_75_2.png)

If you inspect other documents (with more complex formatting), you will notice that `<text:p>` is not the only XML tag that will hold text; Writer also stores text in `<text:span>` tags. The proper `egrep` pattern for these two tags is

```
"</text:(p|span)"
```

Actually, this pattern is a regular expression. Regular expressions are used in many areas of computing, both theoretical and practical: They let you describe search terms in a simple language that allows for very complex patterns. For example,

```
(([a-z]|[a-z0-9]){b}()*$</\1)
```

is a regular expression that matches all text blocks that consist of an opening HTML tag (such as `<h1>`), some element content (such as the headline), and the corresponding closing tag (`</h1>`). Thus, `<h1>Hello</h1>` will match, but `<h1>None</h2>` will not because h1 and h2 are not the same.

## FINDING STUFF

If you only want to search a collection of Writer, Calc, or Impress files for some keywords, you already have all you need. To make this more usable, create the shell script `logrep.sh` shown in Listing 1.

The script works out-of-the-box on macOS and Linux machines; Windows users need to install a Unix/Linux subsystem with a Bash shell, for example Cygwin [4] will do. Alternatively, you could install openSUSE or Ubuntu via the new “Windows subsystem for Linux” feature that requires a recent Windows 10 release [5], though that option will require some configuration.

The script uses the `mktemp` command which generates a temporary file with a random name. That file is immediately deleted and in its place a new directory with the same name is created where the zip file can be unpacked.

If you have no Bash shell installed, use the Python script in Listing 2 instead. It does the same thing but uses Python's `zipfile` module to access the `content.xml` file inside the zip file, and it does not create temporary folders or files like the Bash script does. Figure 5 shows how the Bash script and the Python script deliver identical results.

In order to launch the `logrep.py` script from the Linux or macOS command line, simply enter `./logrep.py` (with leading dot and slash) in the directory that holds the script file, and provide the search pattern and a list of file names as arguments. Windows users running the `cmd.exe` shell enter `python logrep.py` followed by the same arguments.

If you get strange error messages from running the Python script, make sure that you are using a Python 2.x version — the script is not compatible with Python 3.x.

Python is not part of a Windows installation, but if you feel that installing the Bash shell and other Unix tools on Windows is a strange approach, you might feel more at home with a Python installation. After all, Python is a general-purpose scripting language with excellent support for all modern operating systems. Read the "Get Python for Windows" box for installation instructions. Again, Linux and macOS users find Python preinstalled on their systems.

### LISTING 1: logrep.sh

```bash
#!/bin/bash

pattern="$1"; shift
for doc in "$@"; do
  echo "$doc"
  newtmp=$(mktemp)
  rm -r "${newtmp}"; mkdir -p "${newtmp}"
  unzip -q -d "${newtmp}" "${doc}"
  pushd "${newtmp}" > /dev/null
  escaped_doc="${doc}/\\\\
  sed -e 's/>/\n/g' content.xml \
    | egrep "</text:(p|span)" \
    | grep "${pattern}" \
    | sed -e "s/$/${escaped_doc}" \
    | grep -color "${pattern}"
  popd > /dev/null
  rm -r "${newtmp}"
done
```

### LISTING 2: logrep.py

```python
#!/usr/bin/env python

from zipfile import ZipFile
from sys import argv
from re import search, split

def highlight(s, pat):
  normal = ('\033[0m', high = '\033[21m'  # 31-red
  parts = split(pat, s)
  return (high+pat+normal).join(parts)

pattern = argv[1]
for doc in argv[2:]:
  zipf = ZipFile(doc, 'r')
  content = zipf.open("content.xml").read()
  zipf.close()
  lines = content.replace(">", ">\n").split("\n")
  for line in lines:
    if search('</text:(p|span)>', line):
      if pattern in line:
        line = highlight(line, pattern)
        print("%s: %s" % (doc, line))
```

What's the Python code in Listing 2 doing? Line 1 makes the program find the right Python interpreter on Unix-like systems, and in lines 3-5 the script imports some default modules. The modules provide functions for opening zip files, evaluating command-line arguments, and matching regular expressions against strings.

Lines 7-10 implement a highlight() function, which adds escape sequences to parts of a string so that this part of the string is shown in a different color. Note that highlighting only works on Linux and macOS (and when run from Bash on Windows). If you start the script from cmd.exe, you should remove the call to highlight() by putting a comment sign (#) before the second-last line.

The main code is in lines 12-22. The script expects the pattern to search for as first argument (argv[1], argument vector, entry 1). All further arguments can be accessed as argv[2], argv[3], etc., and the for command in line 13 starts a loop over all those file names. For each of the names, all of the following steps will be executed.

Lines 14-16 use the ZipFile function to open the current LibreOffice file and extract the contents of content.xml from the archive's root directory.

Line 17 mimics the behavior of the shell version of this program: The replace method adds a newline after each ">" character, and the split method turns the string into an array of strings.

![](img/e39350c3a7c0d527d71b0e4097a0ba66_76_0.png)

Now every opening or closing tag sits in its private array entry.

Lines 18-22 perform a loop over all the short lines that were generated in the previous step. If a line matches the `</?text:(p|span)>` pattern, and if, furthermore, the search term occurs in that line, it gets run through the highlight() and then displayed in the filename: line format.

### TURN A HACK INTO SOFTWARE

Everything so far must be called a hack. There is nothing wrong with quickly hacking together a Shell or Python script that “does the job,” but attaching XML data structures with simple regular expressions does ask for trouble. For example, imagine what might happen if a search term was identical with an XML element name: Searching and replacing with some random word would introduce syntax errors to the file.

Is there a better way to process XML files? Python developers can use the `xml.etree.ElementTree` module [6] and have an XML document properly parsed.
It works like this:

1. Use the `fromstring` function to convert a string into an XML tree structure. The function call returns the root of that tree.
2. Use the `findall` method to search the tree (starting at the root) for interesting elements, such as `<text:p>` or `<text:span>`.
3. For each match, access the contents via its `text` property. Then you could print it, modify it, collect statistics data, etc.

Thus, a basic code block for achieving the goal mentioned in the introduction (replacing the word “Linux” with “Windows”) would be this:

```python
from xml.etree import ElementTree as et
# ... content is a string w/ XML inside
root = et.fromstring(content)
for x in root.findall('.//text:p') \
        + root.findall('.//text:span'):
    x.text = x.text.replace("Linux","Windows")
new_content = et.tostring(root)
```

(The `findall` method requires the leading `./` part in the element names.) But it turns out that this is too simple: LibreOffice relies heavily on the use of XML namespaces, and the XML parser must be made aware of all the namespaces that are used in the document.

### XML NAMESPACE CRAZINESS

What’s a namespace? Each specific XML language (such as the one used in LibreOffice documents, the XML used in the RDF format [7], or XHTML [8], which is the XML version of HTML, uses its own set of tag and attribute names.

For example, XHTML documents can contain `<head>`, `<body>`, `<title>` (document title), `<p>` (paragraph), `<h1>` (level 1 heading), and many more tags.

As a second example, the Dublin Core (DC) [9] metadata can be used to describe various documents, and they use tags such as `<description>`, `<publisher>`, and several others.
