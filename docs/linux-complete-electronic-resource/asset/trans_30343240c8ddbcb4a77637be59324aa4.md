
## 安全资源

关于 Unix 安全以及 Linux 安全，目前有许多优秀的网站。订阅一个（或多个）安全邮件列表并随时关注安全补丁的更新至关重要。大多数此类邮件列表的发送频率很低，但信息量非常充实。

### FTP 站点

CERT 是计算机应急响应团队。他们经常发布关于当前攻击和安全修复的警报。详情请参见 ftp://ftp.cert.org。

Replay（http://www.replay.com）存档了许多安全程序。由于该机构位于美国境外，因此无需遵守美国的加密限制。

Matt Blaze 是 CFS 的作者，也是一位卓越的安全倡导者。Matt 的存档可以在 ftp://ftp.research.att.com/pub/mab 获取。

tue.nl 是荷兰一个很棒的安全 FTP 站点（ftp.win.tue.nl）。

### 网站

- [黑客常见问题解答（Hacker FAQ）](http://www.solon.com/~sebs/faqs/hacker.html) 是一份关于黑客的常见问题解答。
- [COAST 存档](http://www.cs.purdue.edu/coast/) 包含大量 Unix 安全程序和信息。
- SuSE 安全页面：http://www.suse.de/security/。
- [Rootshell.com](http://www.rootshell.com/) 是一个很好的网站，可以看到破坏者目前正在利用哪些漏洞。
- [BUGTRAQ](http://www.netscape.org/~sv-archive/bugtraq.html) 会发布关于安全问题的公告。
- CERT（计算机应急响应团队）会发布关于 Unix 平台常见攻击的公告：CERT 主页（http://www.cert.org/）。
- Dan Farmer 是 SATAN 以及许多其他安全工具的作者。他的主页拥有一些有趣的安全调查信息，以及安全工具：http://www.trouble.org。
- Linux 安全 WWW 网站是获取 Linux 安全信息的好地方：`http://www.aoy.org/Linux/Security`。
- Infisee 拥有漏洞引擎，可以告诉你哪些漏洞影响特定平台：`http://www.infisee.com/vulnerabilities`。
- CIAC 会定期发布关于常见漏洞的安全通告：`http://ciac.l1nl.gov/cig-bin/index/bulletins`。
- 可以在 `http://www.kernel.org/pub/linux/libs/pam/` 找到关于 Linux 可插拔认证模块（PAM）的良好入门资料。
- Debian 项目有一个关于其安全修复和信息的网页。地址为：`http://www.debian.com/security/`。
- [Web 安全常见问题解答（WWW Security FAQ）](http://www.w3.org/Security/Faq/www-security-faq.html)，由 Lincoln Stein 编写，是优秀的 Web 安全参考资料。

### 邮件列表

以下是一些 Linux 邮件列表的示例。

- **Bugtraq**：若要订阅 *bugtraq*，请发送电子邮件至 `listserv@netspace.org`，并在消息的正文中（而非主题中）包含 *subscribe bugtraq*。（存档 URL 见上文）。
- **CIAC**：向 `majordomo@tholia.l1nl.gov` 发送电子邮件。在消息的*正文*（而非主题）中放置（以下任一项或两者）：*subscribe ciac-bulletin*。
- **Red Hat**：Red Hat 拥有多个邮件列表，其中最重要的是 *redhat-announce* 列表。你可以第一时间了解安全（及其他）修复的内容。向 `majordomo@redhat.com` 发送电子邮件并输入 *subscribe redhat-announce*。
- **Debian**：Debian 项目拥有一个涵盖其安全修复的安全邮件列表。更多信息请参见 `http://www.debian.com/security/`。

## 术语表

**身份验证** 指知晓接收到的数据与发送的数据相同，且声称的发送者实际上是真实的发送者这一特性。

**堡垒主机** 一种必须高度安全的计算机系统，因为它易受攻击，通常是因为它暴露在互联网上，并且是内部网络用户的主要联系点。其名称源自中世纪城堡外墙上的高度设防的工事。堡垒主机俯瞰关键防御区域，通常拥有坚固的城墙、额外的部队空间，以及偶尔用于威慑攻击者的沸腾热油桶。

**缓冲区溢出** 常见的编码风格往往是不分配足够大的缓冲区，并且不检查溢出。当这类缓冲区溢出时，正在运行的程序（守护进程或 set-uid 程序）可能会被迫执行其他操作。通常，这是通过覆盖堆栈上的函数返回地址，使其指向其他位置来实现的。

**拒绝服务** 拒绝服务攻击是指攻击者消耗你计算机上的资源，用于执行其本不打算执行的任务，从而阻止你出于合法目的正常使用网络资源。

![](img/a3584dae761d2e3abed8bf40d7637389_530_0.png)

**双宿主主机** 一种通用计算机系统，拥有至少两个网络接口。

**防火墙** 一种组件或组件集合，用于限制受保护网络与互联网之间，或其他网络集合之间的访问。

**主机** 连接到网络的计算机系统。

**IP 欺骗** IP 欺骗是一种复杂的技术攻击，由多个组成部分构成。这是一种安全漏洞利用手段，它通过欺骗处于信任关系中的计算机，使它们误认为你是某个你实际上并非的人。daemon9、route 和 infinity 撰写了一篇关于此主题的详尽论文，发表在 *Phrack* 杂志第 7 卷第 48 期中。

**不可否认性** 指接收者能够证明发送者确实发送了某些数据，即使发送者后来否认曾发送过该数据这一特性。

**数据包** 互联网上通信的基本单位。

**数据包过滤** 设备执行的选择性控制数据流入流出网络的操作。数据包过滤器允许或阻止数据包，通常是在将数据包从一个网络路由到另一个网络时（最常见的是从互联网到内部网络，反之亦然）。为了实现数据包过滤，你需要设置规则，指定允许哪些类型的数据包（针对特定 IP 地址或端口的数据包）以及阻止哪些类型的数据包。

**边界网络** 添加在受保护网络和外部网络之间的网络，旨在提供额外的安全层。边界网络有时也称为 DMZ（非军事区）。

**代理服务器** 代表内部客户端处理外部服务器事务的程序。代理客户端与代理服务器通信，代理服务器将经过批准的客户端请求转发给真实服务器，并将响应传回给客户端。

**超级用户** root 的非正式名称。

## 常见问题解答

以下是针对常见问题的一些解答。

1. **将驱动支持直接编译进内核，而不是使其成为模块，是否更安全？**

   回答：有些人认为禁用通过模块加载设备驱动程序的能力更好，因为入侵者可能会加载木马模块或影响系统安全的模块。然而，为了加载模块，你必须是 root。模块目标文件也只有 root 可写。这意味着入侵者需要 root 访问权限才能插入模块。如果入侵者获得了 root 访问权限，那么比起他是否会加载模块，有更严重的事情需要担心。

   模块用于动态加载对特定设备的支持，而这些设备可能不经常使用。例如在服务器机器或防火墙上，这种情况发生的可能性很小。因此，对于充当服务器的机器，将支持直接编译进内核更有意义。此外，模块比直接编译进内核的支持速度要慢。

2. **为什么从远程机器以 root 身份登录总是失败？**

   回答：这是有意为之，旨在防止远程用户尝试通过 telnet 以 root 身份连接到你的机器，这是一个严重的安全漏洞。别忘了：潜在的入侵者有时间优势，他们可以运行自动化程序来查找你的密码。（参见“Root 安全”章节。）

3. **如何在我的 Red Hat 4.2 或 5.x Linux 系统上启用影子密码？**

   回答：影子密码是一种将你的密码存储在普通 /etc/passwd 文件之外的文件中的机制。这有几个优势。首先，影子文件 /etc/shadow 仅由 root 可读，而 /etc/passwd 必须保持对所有人都可读。另一个优势是，作为管理员，你可以启用或禁用账户，而无需让其他人知晓其他用户账户的状态。
