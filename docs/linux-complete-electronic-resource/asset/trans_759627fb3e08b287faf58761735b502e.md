**User**
指定要登录的用户名。如果您在不同机器上拥有不同的用户名，这将非常有用。这省去了在命令行中记忆并输入用户名的麻烦。

**UserKnownHostsFile**
指定要使用的文件，以替代 SSH_HOME/.ssh/known_hosts。

**UseRsh**

## 环境变量

ssh 通常会设置以下环境变量：

- **DISPLAY** DISPLAY 变量指示 X11 服务器的位置。ssh 会自动将其设置为 "hostname:n" 格式的值，其中 hostname 指示运行 shell 的主机，n 是一个 >= 1 的整数。Ssh 使用此特殊值通过安全通道转发 X11 连接。用户通常不应显式设置 DISPLAY，因为这会使 X11 连接不安全（并且要求用户手动复制所需的授权 cookie）。

- **HOME** 设置为用户的家庭目录路径。

- **LOGNAME** USER 的同义词；为了与使用此变量的系统保持兼容而设置。

- **MAIL** 设置为指向用户的邮箱。

- **PATH** 设置为默认 PATH，如编译 ssh 时指定，或者在某些系统中为 /etc/environment 或 /etc/default/login。

- **SSH_AUTHENTICATION_FD** 如果您使用身份验证代理且与其建立的连接已被转发，则此值会被设置为一个整数值。该值指示用于与代理通信的文件描述符编号。在某些系统上，可能会改用 SSH_AUTHENTICATION_SOCKET 来指示用于与代理通信的 unix 域套接字路径。（这种方法安全性较低，仅在不支持第一种方法的系统上使用。）

- **SSH_CLIENT** 标识连接的客户端端。该变量包含三个以空格分隔的值：客户端 IP 地址、客户端端口号和服务器端口号。

- **SSH_TTY** 设置为与当前 shell 或命令关联的 tty 的名称（设备路径）。如果当前会话没有 tty，则不设置此变量。

- **TZ** 如果守护进程启动时设置了时区变量，则它会被设置以指示当前时区（即，守护进程会将该值传递给新连接）。

- **USER** 设置为正在登录的用户的名称。

此外，ssh 会读取 /etc/environment 和 $HOME/.ssh/environment，并将格式为 VARNAME=value 的行添加到环境中。某些系统可能仍有其他设置环境的机制，例如 Solaris 上的 /etc/default/login。

## 文件

- `$HOME/.ssh/known_hosts` 记录用户登录过的所有主机的主机密钥（不在 /etc/ssh/ssh_known_hosts 中的主机）。请参阅 sshd 手册页。

- `$HOME/.ssh/random_seed` 用于初始化随机数生成器。此文件包含敏感数据，应仅对用户可读/可写，其他用户不可访问。此文件在程序首次运行时创建并自动更新。用户无需读取或修改此文件。

- `$HOME/.ssh/identity` 包含用户的 RSA 身份验证标识。此文件包含敏感数据，应仅用户可读，其他用户不可访问。生成密钥时指定口令是可能的；该口令将用于在 **IDEA** 下加密此文件的敏感部分。

- `$HOME/.ssh/identity.pub` 包含用于身份验证的公钥（以人类可读形式呈现标识文件的公钥部分）。此文件的内容应添加到希望使用 RSA 身份验证登录的所有机器上的 `$HOME/.ssh/authorized_keys` 中。此文件不敏感，可以（但不需要）由任何人读取。此文件从不自动使用，也不是必需的；它仅提供给用户以方便使用。

- `$HOME/.ssh/config` 这是每用户的配置文件。此文件的格式如上所述。此文件由 `ssh` 客户端使用。此文件通常不包含任何敏感信息，但推荐的权限是用户可读/可写，其他用户不可访问。

- `$HOME/.ssh/authorized_keys` 列出可用于作为此用户登录的 RSA 密钥。此文件的格式在 `sshd` 手册页中描述。在最简单的形式中，格式与 .pub 标识文件相同（即，每行包含 n 模数的位数、公共指数、模数和注释字段，以空格分隔）。此文件不高度敏感，但推荐的权限是用户可读/可写，其他用户不可访问。

- `/etc/ssh_known_hosts` 系统范围的已知主机密钥列表。此文件应由系统管理员准备，包含组织中所有机器的公共主机密钥。此文件应允许所有用户读取。此文件包含公钥，每行一个，格式如下（字段以空格分隔）：系统名称、n 模数的位数、公共指数、模数和可选的注释字段。如果对同一台机器使用了不同的名称，应列出所有这些名称，以逗号分隔。该格式在 `sshd` 手册页中描述。

`sshd` 使用规范系统名称（由名称服务器返回）在登录时验证客户端主机；需要其他名称是因为 `ssh` 在检查密钥之前不会将用户提供的名称转换为规范名称，否则能够访问名称服务器的人就可以欺骗主机身份验证。

- `/etc/ssh/ssh_config` 系统范围的配置文件。此文件为未在用户配置文件中指定的值提供默认值，以及为没有配置文件的用户提供默认值。此文件必须允许所有用户读取。

- `$HOME/.rhosts` 此文件用于在 .rhosts 身份验证中列出允许登录的主机/用户配对。（请注意，此文件也被 rlogin 和 rsh 使用，这使得使用此文件是不安全的。）文件的每一行包含一个主机名（以名称服务器返回的规范形式），然后是该主机上的用户名，以空格分隔。此文件必须归用户所有，且不能具有其他任何人的写入权限。推荐的权限是用户可读/可写，其他用户不可访问。

请注意，默认情况下 sshd 将安装为要求在允许 .rhosts 身份验证之前成功完成 RSA 主机身份验证。如果您的服务器机器在 /etc/ssh/known_hosts 中没有客户端的主机密钥，您可以将其存储在 $HOME/.ssh/known_hosts 中。执行此操作的最简单方法是从服务器机器使用 ssh 连接回客户端；这将自动将主机密钥添加到 $HOME/.ssh/known_hosts。

- `$HOME/.shosts` 此文件的使用方式与 .rhosts 完全相同。拥有此文件的目的，是为了能够在 ssh 中使用 rhosts 身份验证，同时不许可使用 rlogin 或 rsh 登录。

- `/etc/hosts.equiv` 此文件在 .rhosts 身份验证期间使用。它包含规范的主机名称，每行一个（完整格式在 sseq 手册页中描述）。如果在此文件中找到客户端主机，只要客户端和服务器用户名相同，登录就会自动获得许可。此外，通常要求成功完成 RSA 主机身份验证。此文件应仅允许 root 写入。

- `/etc/.shosts.equiv` 此文件的处理方式与 /etc/hosts.equiv 完全相同。此文件可能有用，允许使用 ssh 登录，但不允许使用 rsh/rlogin。
