In both cases, when winbindd is not running, only locally resolvable groups can be recognized. Please refer to Figure 11.1 and Figure 11.2. The **net groupmap** is used to establish UNIX group to NT SID mappings as shown in Figure 11.3.

Administrators should be aware that where *smb.conf* group interface scripts make direct calls to the UNIX/ Linux system tools (the *shadow* utilities, *groupadd*, *groupdel*, *groupmod*, and *groupmod*), the resulting UNIX/Linux group names will be subject to any limits imposed by these tools. If the tool does not allow uppercase characters or space characters, then the creation of an MS Windows NT4/200x-style group of *Engineering Managers* will attempt to create an identically named UNIX/Linux group, an attempt that will of course fail.

There are several possible workarounds for the operating system tools limitation. One method is to use a script that generates a name for the UNIX/Linux system group that fits the operating system limits and that then just passes the UNIX/Linux group ID (GID) back to the calling Samba interface. This will provide a dynamic workaround solution.

Another workaround is to manually create a UNIX/Linux group, then manually create the MS Windows NT4/200x group on the Samba server, and then use the **net groupmap** tool to connect the two to each other.
