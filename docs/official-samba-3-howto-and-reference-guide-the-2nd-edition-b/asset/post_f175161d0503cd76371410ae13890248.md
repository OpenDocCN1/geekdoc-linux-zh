## 8.2.2 Joining a Domain: Windows 2000/XP Professional

Microsoft Windows NT/2000/XP Professional platforms can participate in domain security. This section steps through the process for making a Windows 2000/XP Professional machine a member of a domain security environment. It should be noted that this process is identical when joining a domain that is controlled by Windows NT4/2000x as well as a Samba PDC.

- 1. Click Start.
- 2. Right-click My Computer, then select Properties.
- 3. The opening panel is the same one that can be reached by clicking System on the Control Panel. See Figure 8.15.
- 4. Click the Computer Name tab. This panel shows the Computer Description, the Full computer name, and the Workgroup or Domain name. Clicking the Network ID button will launch the configuration wizard. Do not use this with Samba-3. If you wish to change the computer name or join or leave the domain, click the Change button. See Figure 8.16.
- 5. Click on Change. This panel shows that our example machine (TEMPTATION) is in a workgroup called WORKGROUP. We will join the domain called MID-EARTH. See Figure 8.17.
- 6. Enter the name MID-EARTH in the field below the domain radio button. This panel shows that our example machine (TEMPTATION) is set to join the domain called MID-EARTH. See Figure 8.18.

![](img/86d74c6cc862465e3a42e6dc3c90935a_159_0.png)

### Figure 8.7 Internet Protocol (TCP/IP) Properties

- 7. Now click the **OK** button. A dialog box should appear to allow you to provide the credentials (username and password) of a domain administrative account that has the rights to add machines to the domain. Enter the name “root” and the root password from your Samba-3 server. See Figure 8.19.
- 8. Click on **OK**. The “Welcome to the MIDEARTH domain.” dialog box should appear. At this point the machine must be rebooted. Joining the domain is now complete.

## 8.3 Common Errors

The most common errors that can afflict Windows networking systems include:

- Incorrect IP address.
- Incorrect or inconsistent netmasks.
- Incorrect router address.
- Incorrect DNS server address.
- Incorrect WINS server address.
- Use of a Network Scope setting — watch out for this one!

The most common reasons for which a Windows NT/2000/XP Professional client cannot join the Samba controlled domain are:

- *smb.conf* does not have correct *add machine script* settings.
- “root” account is not in password backend database.
- Attempt to use a user account instead of the “root” account to join a machine to the domain.
- Open connections from the workstation to the server.
- Firewall or filter configurations in place on either the client or the Samba server.
