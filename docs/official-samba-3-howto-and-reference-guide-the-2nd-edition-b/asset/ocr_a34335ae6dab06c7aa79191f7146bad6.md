+   * An existing printers.def file (the one specified in the now removed parameter printer driver file) will no longer work with Samba-3. In 3.0, smbd attempts to locate Windows 9x/Me driver files for the printer in [print$s$] and additional settings in the TDB and only there; if it fails, it will not (as 2.2.x$) drop down to using a printers.def (and all associated parameters). The make_printerdef tool is removed and there is no backward compatibility for this.

+   * You need to install a Windows 9x/Me driver into the [print$s$] share for a printer on your Samba host. The driver files will be stored in the \*WIN40/0* subdirectory of [print$s$], and some other settings and information go into the printing-related TDBs.

+   * If you want to migrate an existing printers.def file into the new setup, the only current solution is to use the Windows NT APW to install the NT drivers and the 9x/Me drivers. This can be scripted using smbclient and rpclient. See the Imprints installation client on the Imprints\u00ae web site for example. See also the discussion of rpclient usage in Chapter 21, \*CUPS Printing Support*.

# 20.14.1  I Give My Root Password but I Do Not Get Access

Do not confuse the root password, which is valid for the UNIX system (and in most cases stored in the form of a one-way hash in a file named /etc/shadow), with the password used to authenticate against Samba. Samba does not know the UNIX password. Root access to Samba resources requires that a Samba account for root must first be created. This is done with the smbpasswd command as follows:
