# Laboratory #1

## Lab #1: Install a Core Linux Operating System on a Server

### Learning Objectives and Outcomes

Upon completing this lab, students will be able to complete the following tasks:

- Design a plan for the Linux operating system based upon necessary software
- Design secured partitions within the core Linux server for desired security hardening, performance, and application support
- Understand how to use a network time server during installation to maintain a synchronized time setting throughout the system
- Create a non-privileged user account for system administration access as a secure alternative to logging in as root user

### Required Setup and Tools

This lab does not require the use of the Fedora VM, Fedora ISO, or Mock IT Infrastructure - Cisco core backbone network. In addition, the Instructor VM workstation and Student VM workstations should be physically disconnected from the internal network and be isolated on the classroom dedicated layer 2 switch. This will allow for a shared DHCP server to be used to allocate the IP addresses for the instructor and student workstations. This lab is optional equipment-based or paper-based. The following is required for equipment-based lab:

- A) A classroom workstation (with at least 2 Gig RAM) capable of supporting the removable hard drive with the VM server farm connected to the classroom layer 2 switch.
- B) An instructor workstation (with at least 4 Gig RAM recommended) that will act as the Instructor’s demo lab workstation. The instructor will display the Instructor workstation on the LCD projector to demonstrate the loading and configuring of the Instructor VM workstation using VMware Player.
- C) Students will perform a paper-based lab.

![](img/73be0eef2ceb12f43f3eb92c420134f5_6_0.png)

The following summarizes the setup, configuration, and equipment needed to perform Lab #1:

1. A Virtualized Server Farm with the following components:
   - a. Microsoft DHCP server for allocating student IP host addresses
   - b. In this lab we will be building a new Fedora 14 Linux Target VM using the supplied Linux OS Software
2. Standard onsite student workstation must have Internet access and the following software applications loaded to perform this lab:
   - a. VMware Player 3.x
   - b. Microsoft Office 2007 or higher for Lab Assessment Questions & Answers

### Recommended Procedures

#### Paper-Based Lab #1 – Student Steps:

Students should use the install step figures as a reference when writing a summary report for “Securing a Linux server – starting with the install”.

### Deliverables

Upon completion of Lab #1: Install a Core Linux Operating System on a Server, students are required to provide the following deliverables:

1. Lab #1 - Submit a summary report and an audit checklist for securing a Linux server – starting with the install. Make the assumption the server will be used as a retailer’s Web Server for an e-commerce web application.
   - a. Provide an explanation why it is especially important to physically secure Linux computers.
   - b. Summarize reasons for partitioning as it relates to security and availability.
   - c. Briefly explain why it may be acceptable to install X window and a graphical user interface with the server and how risks can be mitigated.
   - d. Provide a recommendation how to maintain synchronization with a Network Time Server
   - e. Suggest a method for administrators to login to the server and perform administrative tasks. (remote or physical access, accounts to use for login, etc.)
   - f. Provide an audit checklist Linux administrators could use during the install process.
2. Lab #1 – Lab Assessment Questions & Answers

### Evaluation Criteria and Rubrics

The following are the evaluation criteria and rubrics for Lab #1 that the students must perform:

1. Was the student able to recognize the importance to physically securing Linux computers?– **[20%]**
2. Was the student able to articulate why secured partitions within the core Linux server establish the basis for security hardening, performance, and application support?– **[20%]**
3. Did the student provide a recommendation to maintain a synchronized time setting throughout the system?– **[20%]**
4. Did the student suggest a server install with no GUI or provide a valid explanation why a GUI should be installed to a server and how to mitigate risks?– **[20%]**
5. Was the student able to understand why it is important to create a non-privileged user account for system administration access as a secure alternative to logging in as root user?– **[20%]**
