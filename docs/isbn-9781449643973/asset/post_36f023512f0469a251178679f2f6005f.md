### Overview

In this lab the students review the install of a Fedora Linux Server that will act as a web server for a fictitious financial institution. The installation process, applying passwords, creating partitions, and system administrator access controls will be part of the operating system configuration requirements.

### Lab Assessment Questions & Answers

- 1. During the install, the option to sync with a NTP (Network Time Protocol) server was checked. From a security perspective, why is it important for a system to keep accurate time?
- 2. During the install, a password has been set for the "root" user. What is the "root" user, and when is it appropriate to use this account?
- 3. During the install, X-Window and a Desktop Manager were installed. However, in a production environment it is recommended NOT to run the X-Window environment. Explain the purpose of this recommendation.
- 4. During the installation process it asks what the options given to create the partition are? Name them.
- 5. Why is it important to partition a Linux system correctly?
- 6. What is the significance of the SWAP partition in a Linux system? What different ways can the swap space be configured, and why would you recommend one over the other?

- 9. What is the fstab file used for and what fields make up its content? Explain.

## Laboratory #2

### Lab #2: Configure Basic Security Controls on a Fedora Linux Server

### Learning Objectives and Outcomes

Upon completing this lab, students will be able to:

- Configure the bootloader with set timeout to 0 and password credential to mitigate tampering with the GRUB loader and the boot sequence of the server
- Enable SELinux on a Fedora Linux Server and set it to “permissive” mode
- Create a student user account and add it to a user group for managing permissions and applying access controls across the system
- Configure user groups with limited sudo access (with password credentials) to log and properly monitor access across the system
- Create iptables set to “on” for runlevels 3 & 5 to enable an internal, host-based IP stateful firewall
- Set restrictions and permissions for user access to files and system log files

### Required Setup and Tools

This lab does not require the use of the Mock IT Infrastructure - Cisco core backbone network. In addition, the Instructor VM workstation and Student VM workstations should be physically disconnected from the internal network and be isolated on the classroom dedicated layer 2 switch.
