
`HASH`选项参数告诉Oracle使用`DEPTID`列而不是内部哈希函数。`HASHKEYS`参数指定要创建多少个哈希桶来存放哈希簇键索引（`DEPTID`）的输出值。此参数应等于不同簇键值的数量，并向上进位到下一个质数。在这种情况下，假设你有25个部门（`DEPTID`）。你向上进位到29，即下一个质数。关于如何调整和管理哈希簇和索引的更多信息，请参考《Oracle服务器管理员指南》。

### 监控 (MONITORING)

你已经看到了通过指南和聚类来缓解热表空间的竞争，但如何判断哪些表空间是热的呢？你在第3章中学习过，如果有良好的估算，可以利用这些数据来指导初始布局。

如果，例如有3个表平均每秒产生150次事务（`tps`），而剩余表少于30 `tps`，你就可以说这3个表是热的，因此应该分开。部署后，进入生产使用阶段，你需要能够提供底层I/O的监控技术，例如物理读和写，而不是高层估算。

如果不是并发访问，可以将“相似”的表/索引放在相同的表空间/索引中。

这是前一条指南的详尽扩展：如果必要，由于磁盘限制，可以*交错*热、温、冷表的放置。换句话说，要了解你所有表的访问模式、使用类型和并发级别。掌握了这些知识后，如果磁盘空间紧张，例如，你可以将两个不并发访问的表放在相同的表空间/磁盘上，将一个热索引和一个冷表放在不同表空间但同一块磁盘上，或者在适当的条件下将所有三种类型的*表*和索引放在同一块磁盘的六个不同表空间中！建议：*除非绝对必要，否则不要这样做*。这是针对磁盘空间极紧张的数据库系统的最后手段。

这显示该磁盘的每秒I/O访问低于40次，这是理想的，因为这被广泛认为是大多数现代磁盘的饱和点。然而，如果所有其他磁盘（例如）的每秒I/O次数远低于40次，你仍然需要卸载这块磁盘以帮助平衡I/O。你不希望孤立地减少每块磁盘，而是要尽可能地平衡I/O —— 实际上，是将其分散到所有磁盘上。

准则：如果任何给定磁盘接近或超过每秒40次I/O，你可能需要卸载其部分其他磁盘。在理想情况下，这意味着移动表，或者更糟糕的是，可能移动表及其对应的数据文件。之后，你将需要考虑交错（`interleaving`）、聚类（`clustering`）、条带（`striping`），或者在必要时购买更多磁盘。你的目标是根据应用程序峰值负载需求，均衡所有磁盘的I/O，使每个磁盘的每秒I/O都在40次或以下，从而尽可能地均衡所有磁盘的每秒I/O，使所有磁盘负载均衡。

## 调优块与区 (TUNING BLOCKS AND EXTENTS)

Oracle块由区（`extents`）组成，而区包含了表空间（`tablespaces`）。它们是表空间存储的物理基础。因此，你访问数据和管理其增长越高效，你的性能就越好。

### 使用预分配 (USING PREALLOC)

从第16节“性能调优基础”中，你了解到动态分配会产生过多的开销并损害I/O性能。在几乎所有情况下都倾向于静态预分配。你可以静态地预分配一个段（表或索引）或一个表空间。通常，选择其中一种方法即可。如果你预分配了表空间，你已经对表以及它们如何映射到区有了很好的了解。如果你设置了表空间默认值，然后预分配你的表，那么在同一个表空间中混合具有不同区要求的表时，你会有更大的灵活性。但请记住，你不希望混合具有许多不同区要求的表（作为通用准则，不超过三个），因为这实际上导致了碎片化，这是我们不希望的。

与其回顾第5节“Oracle数据库架构”和第21节“管理数据库存储”中给出的所有存储术语和参数，不如简要观察在同一表空间存储两个表的两种不同方法。假设你有两个表，每个最多需要100MB。创建一个允许额外增长的表空间，并带单个数据文件。第一种方法（预分配表空间）如下：

```sql
CREATE TABLESPACE TS1
DATAFILE '/data/file1.dat' SIZE 256M
DEFAULT STORAGE (INITIAL 100M NEXT 100M)
MINEXTENTS 1);
```

```sql
CREATE TABLE T1 (a number(9), ..., z number(9))
TABLESPACE TS1;
```

```sql
CREATE TABLE T2 (a number(9), ..., z number(9))
TABLESPACE TS1;
```

### 调优块与区 (TUNING BLOCKS AND EXTENTS)

第二种方法（预分配表）如下：

```sql
SQL> CREATE TABLESPACE TS1
DATAFILE '/data/file1.dat' SIZE 256M;
SQL> CREATE TABLE T1 (a number(9), ..., z number(9))
TABLESPACE TS1
STORAGE (INITIAL 100M NEXT 100M)
MINEXTENTS 1);
SQL> CREATE TABLE T2 (a number(9), ..., z number(9))
TABLESPACE TS1
STORAGE (INITIAL 100M NEXT 100M)
MINEXTENTS 1;
```

单独预分配表可以让你对增长甚至也对与该表空间相关的性能进行更细粒度的控制。如果其中一个表恰好需要扩展，而你只需要10M时，分配了100M吗？通常情况下，由于第10节中讨论的许多原因，预分配的存储单位越细，性能就越好。
