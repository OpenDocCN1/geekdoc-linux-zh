
`set path=(dirname dirname ...)`

你可能想在 `.shrc` 而不是 `.login` 中定义搜索路径。通过在 `.shrc` 中定义路径，你确保了所有 shell 调用都具有相同的搜索路径。然而，你也防止了继承环境。大多数人发现，登录脚本中定义搜索路径足够了。

你可能想将初始化的部分放在单独的文件中并让 `.shrc` 源自单独的文件。例如，将所有的别名放在单独的文件 `~/.cshrc.alias` 中，并将路径设置在 `~/.cshrc.path` 中。别名和路径文件需要你使用 `-f` 选项运行你的大部分脚本，脚本可以引用其所需的初始化部分（参见本章较前的“选项”，关于 `-f` 的描述）。

关于变量以及如何设置它们的更多信息，请参阅本章前面的“变量”部分。

## 在你的 .login 初始化文件中放入什么

`.login` 脚本是执行以下操作的绝佳场所：

- 识别你正在使用的终端类型——也许可以通过提示用户输入代码来实现。

- 设置 `TERM` 环境变量以匹配终端类型。`TERM` 被 `vi` 命令用于发送正确的终端控制代码，以进行全屏操作；如果 `TERM` 不正确，它将无法正常工作。

- 你可以使用 `stty erase '^H' kill '^U' intr '^C'` 来设置你偏好的控制键：

```
stty erase '^H' kill '^U' intr '^C'
```

- 你可以设置全局环境变量：

```
setenv TERM vt100
setenv EDITOR /usr/bin/vi
setenv PAGER /usr/bin/bin
```

- 你可以设置局部变量：

```
set path=(/usr/bin /usr/ucb /usr/X/bin $home/ )
set cdpath=(.. $home)
set mail=(60 /usr/spool/mail/$loginname)
```

- 而且，你可以执行任何你觉得有趣的系统命令：

```
news
df
```

关于变量以及如何设置它们的更多信息，请参阅本章前面的“变量”部分。

## 在你的 .logout 文件放入什么

`.logout` 文件没有标准用途。如果你不需要 `.logout` 文件，可以省略它，而不会产生任何错误信息。

## 作业控制

当你在命令行上输入命令并按下回车键时，该命令在前台执行，这意味着它占据了你 shell 的全部注意力，并一直占用该 shell 直到作业执行完毕。这意味着你必须等待命令执行完成后，才能在该 shell 中进行任何其他工作。对于运行结束的程序，这通常不是问题。但对于那些需要几分钟或几小时才能完成的命令或程序，这就是问题。大多数图形化应用程序（如 `xterm`）都是作为后台作业的。通过在后台执行命令或程序，你可以立即释放 shell 来执行其他任务。

C 为你提供了用于执行和管理后台作业的作业控制机制。

你使用 `&` 在后台执行命令。后台进程没有关联的终端：


## 列出活跃的后台作业：jobs

`jobs` 命令简单列出后台执行的进程组头。进程组头是指拥有自身以及零或多个子进程的进程。附加 `&` 的简单命令会启动一个进程和一个进程组头（一个带进程的作业）。在后台执行的三个命令的管道（例如 `ls | sed | xargs &`）会启动三个进程，但仍然是一个作业。

## 将前台作业移至后台：bg

你可以使用 `bg` 将作业切换到前台执行并重启任何已停止的作业。

```
bg [ job ... ]
```

如果后台运行的作业尝试读取终端，它将自动停止。例如，

```
stop [ %job ]
```

此命令向命名的作业发送一个停止信号（SIGSTOP），就像按了 SUSP 键（通常是 Ctrl-Z）。该作业已停止。

你可以使用 `bg` 命令恢复执行已停止的作业，或使用 `fg` 命令将作业带到前台并恢复其执行。

要终止后台作业的执行，请使用 `kill` 命令。详情请参见本章前面的“向进程发送信号：kill”。

## 停止当前 Shell：suspend

`suspend` 命令发送执行请求或停止当前的 shell 执行。其效果与按下 SUSP 键（通常是 Ctrl-Z）相同。例如：

```
suspend
```

## 等待后台作业完成：wait

你可以使用 `wait` 命令等待所有后台作业完成。例如：

```
wait
```

在接收到所有后台作业终止的通知之前，shell 将简单地停止提示输入命令。

要停止等待，只需按下 Return 键（或 Enter ）。shell 会打印所有后台作业的摘要，并恢复以正常方式提示命令输入。

## 请求后台作业状态变更通知：notify

你可以使用 `notify` 命令请求 shell 立即报告后台作业状态的任何变化。例如：

```
notify [ %job ]
```

默认情况下，shell 会在命令提示符之前向终端写入消息，报告作业的完成、终止、停止或其他状态变更。

你可以使用不带参数的 `notify` 来请求立即获取后台作业状态变更通知。但请注意，通知消息可能会在不方便的时间写入你的终端；例如，当屏幕处于全屏格式化状态时；消息可能会导致破碎的屏幕显示混乱。

你可以使用 `notify %job` 仅请求指定作业的状态通知。当你运行一个后台命令并在稍后决定在继续之前需要其结果时，这种方法非常方便。你不需要反复执行作业来查找后台作业何时完成，只需发布 `notify %job` 让 shell 在作业完成时通知你。

对于 `%job`，请指定如 `bg` 命令中描述的任何作业引用格式。

## 控制后台进程调度优先级：nice

你可以使用 `nice` 来更改分配给批作业的默认调度优先级。例如：

```
nice [ +number ] [ command ]
```

`nice` 功能的原理是：后台作业对系统要求的关注度应该比交互式进程少（交互式图形用户界面作业除外）。后台作业在没有附加终端的情况下执行，并且由于这些原因通常在后台运行：

- 预计该作业需要较长时间才能完成。

- 作业的结果不需要立即获得。

然而，当执行速度至关重要时，交互式进程通常使用 shell，因为这直接影响系统的响应时间。如果让其他人（以及你自己）让交互式进程的优先级高于后台工作会更好。

UNIX 提供了一个 `nice` 命令，你可以用它启动后台作业的同时分配较低的执行优先级。内置命令 `nice` 替换了 UNIX 的 `nice` 并增加了自动化。虽然 UNIX 的 `nice` 命令必须显式使用来启动低优先级后台作业，但 shell 总是为后台作业分配较低的执行优先级。你使用 `nice` 命令来更改 shell 的优先级。

当在不带参数的情况下调用时，内置的 `nice` 将 nice 值（执行优先级）设置为 4 或正数或零值。零值始终假设 nice 值为 0（与交互式进程相同）。你必须执行 `nice` 或 `nice+value` 来更改 nice 值（在此之前，你并没有“nice”；所有后台作业都以相同的优先级与交互式进程竞争）。

使用 `nice +number` 将后台作业的默认执行优先级更改为正数或零。正数对应于较低的优先级，因此 `nice +5` 的优先级低于 `nice +4`，`nice +6` 的优先级低于 `nice +5`，依此类推。

如果你指定了 `command`，`nice` 将使用默认或指定的执行优先级启动命令，但不会更改默认执行优先级。例如，`nice myprog.c` 使用默认优先级启动编译，而 `nice +7 myprog.c` 则以 7 的明确优先级启动编译。

注意，你不需要在 `nice` 命令后附加 `&` 即可作为后台作业运行命令；当你指定 `command` 时，会自动假设后台操作符。

## 向进程发送信号：kill

你可以使用内置的 `kill` 命令向一个或多个作业或进程发送信号。例如：

```
kill [ -signal ] [%job ... ] [pid]
kill -1
```

内置命令 **隐藏了 (HIDES)** UNIX 命令。要调用 UNIX 的 `kill` 命令，请使用其完整路径（可能是 `/bin/kill` 或 `/usr/bin/kill`）。内置命令提供了 `/bin/kill` 不支持的额外功能，并可以用相同的方式使用。

对于信号，请指定数字或符号名称。所有 UNIX 实现都支持 1 到 15；某些实现可能支持更多。按照惯例，表 12.15 中列出的信号始终是定义的。

## 表 12.15. 信号。

| 信号 | 名称 | 含义 | 效果 |
|---|---|---|---|
| 1 | HUP | 挂断 | 当注销断开终端时发送给进程组中的所有进程；对于远程终端，当终端连接掉时发送。 |
