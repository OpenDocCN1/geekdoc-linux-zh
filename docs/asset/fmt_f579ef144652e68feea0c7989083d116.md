
我们可以看到，每次迭代都有两次乘法运算，是很耗费时间的操作。不能优化一下呢？答案是肯定的。如果仔细看程序代码，就会发现这个程序的矩阵参数是跳跃的，我们可以比较容易地不用乘法就把它计算出来。

### 39.1 三个迭代器

指令序列39.1 采用`MSVC 2013 x64`优化的代码

```assembly
f               PROC
    ; RDX=al
    ; RCX=a2
    ; R8=cnt

    test    r8, r8      ; cnt==0? 如果则退出
je SHORT $LN1@f
pad 11

$LL3@f:
mov eax, DWORD PTR [rdx]
lea rcx, QWORD PTR [rcx+12]
lea rdx, QWORD PTR [rdx+28]
mov DWORD PTR [rcx-12], eax
dec r8
jne SHORT $LL3@f

$LN1@f:
ret 0
ENDP
```

这里有三个迭代变量，它们是`cnt`变量和两个序列参数（索引下标）。序列参数每次迭代都增加12或者28（其实就是采用加法替换源程序中的乘法）。因此我们可以采用`C/C++`语言写代码如下：

```c
#include <stdio.h>

void f(int *al, int *a2, size_t cnt)
{
    size_t i;
    size_t idx1=0; idx2=0;

    // 以某种特殊的方案从一个数组拷贝到另一个数组
    for (i=0; i<cnt; i++)
    {
        al[idx1]=a2[idx2];
        idx1+=3;
        idx2+=7;
    }
}
```

这个程序在每次迭代更新3个迭代参数，而不是1个。另外，编译器实现了两个乘法操作。

### 39.2 两个迭代器

`GCC 4.9`做得更好，只有两个参数。指令清单39.2采用`GCC 4.9`优化

```assembly
; RDI=al
; RSI=a2
; RDX=cnt
f:
    test rdx, rdx ; cnt==0? 如果则退出
    je .L1
    ; 计算"a2"最后一个元素的地址并留在RDX中
    lea rax, [rdx*4]
    ; RAX=cnt*4
    shl rdx, 5
    ; RDX<<5=cnt*32
    sub rdx, rax
    ; RDX-RAX=cnt*32-cnt*4=cnt*28
    add rsi, rdx
    ; RSI=a2+cnt*28
.L3:
    mov eax, DWORD PTR [rsi]
    add rsi, 28
    add rdi, 12
    mov DWORD PTR [rdi-12], eax
    cmp rsi, rdx
    jne .L3

.L1:
ret
```

这里没有计数器变量，是因为编译器认为没有必要。`a2`的最后一个参数在循环开始就已经计算好了（就是`cnt`乘以7）。而且循环在达到预先计算出的边界值时就会终止。

其中涉及特殊的加/减/位移代替乘法的算法，感兴趣的读者可以参考第16节。上述汇编代码对应的`CC++`程序：

```c
#include <stdio.h>

void f(int *al, int *a2, size_t cnt)
{
    size_t i;
    size_t idx1=0; idx2=0;
    size_t last_idx2=cnt*7;

    // 以某种特殊的方案从一个数组拷贝到另一个数组
    for (i=0; i<cnt; i++)
    {
        al[idx1]=a2[idx2];
        idx1+=3;
        idx2+=7;
        if (idx2==last_idx2)
            break;
    }
}
```

`ARM64`下的`GCC(Linaro) 4.9`采用了不同的编译方法。它是计算`a1`的最后一个索引值，而不是像上面的程序将`a2`作为边界条件。当然，程序的功能是一样的。

## 指令清单39.3 ARM64下的GCC(Linaro) 4.9

```assembly
X0=al
X1=a2
X2=cnt
f:
   cbz x2, .L1      ; cnt==0? 如果则退出
   ; 计算"a1"的最后一个元素
   add x3, x0, x2, LSL #2  ; x3=a1+cnt*4
   lsl x4, x2, #5         ; x4=cnt*32
   sub x4, x4, x3         ; x4=cnt*32-cnt*4=cnt*28
   add x1, x1, x4         ; x1=a2+cnt*28
.L3:
   ldr w0, [x1], #4      ; 从a2加载32位字（后增4）
   str w0, [x0], #12     ; 在a1+12处存储32位字
   add x0, x0, #12       ; a1=a1+12
   bne .L3
.L1:
   ret
```

## 40章 达夫装置

达夫装置(`Duff's Device`)是一种综合了多种语句的循环展开技术，可大幅度地减少代码的分支总数。这种循环展开巧妙地利用了`switch`语句的滑梯(`fallthrough`)效果。

```c
void bzero(uint8_t* dst, size_t count)
{
    int i;

    if (count&~7)) {
        // 计算8字节对的数据块
        for (i=0; i<count>>3; i++) {
            *(uint64_t*)dst=0;
            dst=dst+8;
        }
    }

    // 处理尾部字节
    switch (count & 7) {
        case 7: *dst++ = 0;
        case 6: *dst++ = 0;
        case 5: *dst++ = 0;
        case 4: *dst++ = 0;
        case 3: *dst++ = 0;
        case 2: *dst++ = 0;
        case 1: *dst++ = 0;
        case 0: // 什么都不做
            break;
    }
}
```

我们来看看这个计算是如何完成的。处理内部内存区域的大小是64位数据，它分为两个部分。

| 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |

|---|---|---|---|---|---|---|---|

| ... | B | B | B | B | B | S | S |

备注：`B`代表大小8字节的内存，`S`代表大小不足8字节的尾部内存。
