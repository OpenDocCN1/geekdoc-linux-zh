fd = open("foo.txt", O_WRONLY | O_CREAT | O_TRUNC, S_IRUSR | S_IWGRP | S_IROTH);

| 权限 | 用户 | 组 | 其他 |
|---|---|---|---|
| 读取 | `S_IRUSR` | `S_IRGRP` | `S_IROTH` |
| 写入 | `S_IWUSR` | `S_IWGRP` | `S_IWOTH` |
| 执行 | `S_IXUSR` | `S_IXGRP` | `S_IXOTH` |

```c
fd = open("foo.txt", O_WRONLY | O_CREAT | O_TRUNC, S_IRUSR | S_IWGRP | S_IROTH);
```

### close

`close` 在成功时返回 `0`，否则返回 `-1`。它实际上会释放进程的文件描述符，并使其供下一次 `open` 调用（如果有的话）使用。

多个进程可能会打开同一个文件，因此关于 `open` 和 `close` 你有几点需要了解的：

- 当一个文件被两个进程 A 和 B 打开（或在同一个程序中通过两次 `open` 调用打开）时，内核简单地为它们分配两个独立的文件描述符。每个描述符都可以独立地访问该文件。
- 在进程 A 中关闭文件会释放进程 A 的描述符；进程 B 仍然会发现该文件处于打开状态。只有当所有描述符都已释放时，文件才能被删除。
- 你可以在程序中显式地关闭任何一个标准流。你可以使用 `close(1)` 关闭输出文件，然后打开一个文件以返回 `1` 作为描述符值。（将磁盘文件设为标准输出！）

所有这些内容将在第 18 章中详细讨论，并涉及到内核在内存中为每个打开的文件维护的两个表。我们还将学习关闭标准输入和输出文件以实现重定向。

## 17.5 读取文件

两个系统调用——`read` 和 `write`——处理对普通文件（以及管道和套接字）的所有读写操作。这两个调用共享相似的语法，并使用用户定义的缓冲区。`read` 通过之前 `open` 返回的文件描述符来访问文件：

```c
ssize_t read(int fd, void *buf, size_t nbyte);
```

`read` 尝试从文件描述符读取 `nbyte` 个字符到缓冲区中。该缓冲区表示指向通用缓冲区的指针（其大小大致等同于基本数据类型，通常为 `char`）。`nbyte` 通常是缓冲区本身的大小。这就是你如何通过每次 `read` 调用获取 4096 字节的：

```c
#define BUFSIZE 4096

int n;
char buf[BUFSIZE];

while ((n = read(fd, buf, BUFSIZE)) > 0)
```

`read` 返回读取到 EOF（文件结束）为止读取的字符数，在到达 EOF 时返回 `0`。在循环中使用它读取整个文件时，除了最后一次外，返回的数量通常等于每次迭代中请求的数量；在最后一次，`read` 返回剩余待读字符数（因为文件大小可能不是缓冲区大小的倍数）。出错时，`read` 返回 `-1`。

如果你必须处理读取的每个字符，可以将 `buf` 声明为 `char` 变量，然后将其地址传递给 `read`：

```c
int fd, n;
char buf;

while ((n = read(fd, &buf, 1)) > 0)
```

使用单字符缓冲区读取 100 个字符（如上所示）需要 100 次系统调用，这是相当昂贵的。在这里，像 `fgetc` 这样的库函数是更好的选择。

`fread` 函数的行为类似，但它使用的参数不是文件描述符，而是一个指向 `FILE` 类型结构体的指针 (`FILE *`)。我们使用 `man 3` 来查找其四个参数的意义。

## 17.6 写入文件

`write` 调用使用从 `open` 获取的文件描述符。`write` 的原型与 `read` 几乎完全相同：

```c
ssize_t write(int fildes, const void *buf, size_t nbyte);
```

每次调用 `write` 都会从 `buf` 向文件描述符写入 `nbyte` 个字节，并返回写入的字符数，这必须等于请求的数量。然而，如果在写入过程中磁盘已满，或者文件大小超过了系统限制，`write` 将返回 `-1`。

为了以例如 8192 字节的块写入数据，但将其声明为字符数组以保存那么多字符，且 `write` 的第三个参数应代表该数组的大小：

```c
#define BUFSIZE 8192

int n;
char buf[BUFSIZE];

n = write(fd, buf, BUFSIZE);
```

像 `read` 一样，你可以一次写入一个字符，在这种情况下，你应该将 `buf` 声明为 `char` 变量：

```c
char buf;
write(fd, &buf, 1);
```

`read` 和 `write` 的缓冲区大小由写入设备（终端、硬盘等）以及在内存中维护的内核缓冲区的大小决定。这是一个重要问题，有时使用频繁的写入会更好。

在读取和写入标准流时，我们应该使用符号常量 `STDIN_FILENO`、`STDOUT_FILENO` 和 `STDERR_FILENO` 作为文件描述符，而不是它们代表的整数 `0`、`1` 和 `2`。这些符号常量定义在 `unistd.h` 中。

## 17.7 ccp：复制文件

此程序 `ccp.c`（图 17.2）将 `/etc/passwd` 复制到 `password.bak`。源文件以只读模式打开。目标文件以只写模式打开，如果不存在则创建，如果存在则将其截断。

### 图 17.2 ccp.c

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/stat.h>

#define BUFSIZE 1024

/* 程序：ccp.c */
int main(void) {
    int fd1, fd2;
    int n;
    char buf[BUFSIZE];

    /* 打开源文件 */
    if ((fd1 = open("/etc/passwd", O_RDONLY)) == -1) {
        perror("open");
        exit(1);
    }

    /* 打开目标文件 */
    if ((fd2 = open("password.bak", O_WRONLY | O_CREAT | O_TRUNC, 644)) == -1) {
        perror("open");
        close(fd1);
        exit(1);
    }

    /* 复制内容 */
    while ((n = read(fd1, buf, BUFSIZE)) > 0) {
        if (write(fd2, buf, n) != n) {
            perror("write");
            exit(1);
        }
    }

    close(fd1);
    close(fd2);
    return 0;
}
```

对于复制操作，`read` 和 `write` 使用同一个缓冲区。`read` 的返回值 `0` 表示 EOF。

## 描述符与指针

由于库函数和系统调用的处理方式不同，不建议在进行 I/O 时混合使用描述符和指针。但在某些情况下，你并没有选择。如果在父进程中打开了文件，子进程只能访问文件描述符。子进程继承所有的描述符但不继承 `FILE` 指针。

有时，你需要利用两者的优点。你通过 `open` 生成了文件描述符，但现在你想使用 `fgets` 逐行读取。要这样做，只需用 `fdopen` 将文件描述符转换为文件指针。反之，如果你用 `fopen` 打开了文件，现在想运行 `stat` 来获取文件大小，请使用 `fileno` 将文件指针转换为描述符：

| 转换方向 | 函数 |
|---|---|
| 文件描述符 → 文件指针 | `fdopen` |
| 文件指针 → 文件描述符 | `fileno` |

带有限制，偏移量（offset）可以是正整数或负，因此它由符号数据类型表示。例如，

```c
lseek(fd, 10, SEEK_CUR) // fd 从之前的偏移量获取
```

将指针从当前位置向前移动 10 个字符，并且

```c
lseek(fd, -10, SEEK_END) // 负偏移量
```

将指针设置为文件末尾（EOF）之前的 10 个字符处。当 `whence` 设置为 `SEEK_SET` 时不能使用负偏移量，但奇怪的是当 `whence` 为 `SEEK_END` 时可以使用正偏移量。在这种情况下，指针会移动到 EOF 之外，创建一个稀疏文件——称为带有“洞”的文件。稀疏文件用于数据库应用程序，但我们的下一个程序也会将指针移动到 EOF 之外。

`lseek` 返回指针距离文件开始计算的字节位置。此值可以用于确定文件的大小：

```c
size = lseek(fd, 0, SEEK_END); // 这返回文件大小
```

与 `read` 和 `write` 不同（它们实际上适用于所有文件类型），`lseek` 仅适用于能够“寻道”的文件。它不适用于终端文件、套接字（socket）或管道（pipe），主要用于磁盘文件。

向文件追加数据有两种方法。你可以使用 `open` 并配合 `O_APPEND` 状态标志，这会将文件的偏移指针置于 EOF。或者，你可以使用 `open`（不带该标志）后跟 `lseek(fd, 0, SEEK_END)`。前者技术代表一种原子操作（见插图），并推荐使用它，而不是后者。

### 注意：原子操作

当你处于像 UNIX 这样的多程序环境中时，有一点你必须时刻牢记在心：多个进程可能会竞争同一个资源——例如文件。这些资源在共享时不能引起冲突。在任何可能的情况下，你需要确保某些关键操作是以原子化的方式执行的。

一个原子操作由多个动作组成，这些动作要么全部执行，要么完全不执行。连续使用两次调用不是原子的，因为这允许第二个进程运行。UNIX 系统在尽可能的情况下使用原子性。目录条目的删除和相应的索引节点条目修改必须以原子方式执行。

你必须在程序中处理原子性。例如，使用 `O_EXCL` 检查文件是否存在以及使用 `O_CREAT` 创建文件必须作为单次操作执行。否则，另一个进程可能会创建文件并向其写入数据。我们不再使用系统调用来创建文件，因为我们仍然需要通过 `open` 先检查其是否存在，而这会使该操作变为非原子的。

## 17.8.1 reverse_read.c：反向读取文件

你无法使用标准的 UNIX 工具（perl 除外）从末尾到开头读取文件，但在 C 程序中使用 `lseek`，即 `reverse_read.c`（图 17.3），就可以做到。你必须将文件指针移动到 EOF 之前的一个字符。然后使用循环在每次读取一个字符时将指针移动两个位置。

与 `ccc.c` 不同（在其中我们分块获取数据），此应用程序要求我们每次读取一个字符。因此，我们配合 `read` 和 `write` 使用了单字符缓冲区。虽然 `read` 将指针向前移动一个字节，但下一次 `lseek` 则将其移动两个字节。

### 图 17.3 reverse_read.c

```c
/* 程序：reverse_read.c -- 反向读取文件 -- 使用错误处理 */
#include <fcntl.h>
#include <unistd.h>                               /* 用于 STDOUT_FILENO */
#include <stdio.h>
#include "quit.h"

int main(int argc, char **argv) {
    int size, fd;
    char buf;
    char *mesg = "Not enough arguments\n";     /* 单字符缓冲区 */

    arg_check(2, argc, mesg, 1);

    if ((fd = open(argv[1], O_RDONLY)) == -1)
        quit("open", 2);

    lseek(fd, 1, SEEK_END);                               /* 指针首先移动到 EOF + 1 */

    while (lseek(fd, -2, SEEK_CUR) >= 0) { /* 然后向后移动两个字节 */
        if (read(fd, &buf, 1) != 1)
            quit("read", 1);

        if (write(STDOUT_FILENO, &buf, 1) != 1)
            quit("write", 1);
    }

    close(fd);                               /* 这里也可能发生错误 */
    exit(0);                                 /* exit 不返回，因此没有错误 */
}
```

程序接受输入文件名作为参数并写入标准输出。我们使用了两个函数：`quit` 和 `arg_check`（在第 16.1.1 节中定义），并且 `out` 的前两次调用实际上调用了它们：

```bash
$ ./out
Not enough arguments

$ ./out /etc/host.equiv
open: no such file or directory

$ ./out /etc/hosts.equiv
... A blank line...
```
