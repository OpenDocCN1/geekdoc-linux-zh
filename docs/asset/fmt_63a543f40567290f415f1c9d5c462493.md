
/* 一个快速且简单的程序，将 `argv[1]` 放入 `hpterm` 的标题栏中

   Tom Arons 1992年3月

*/

```c
#include <string.h>

main(argc,argv)

 int argc; char **argv[];

{

   printf("\033&f0k%dD%s", strlen(argv[1]), argv[1]);

   printf("\033&f-1k%dD%s", strlen(argv[1]), argv[1]);

}
```

另一种方法是：

```bash
#!/bin/sh

LENGTH='strlen $1'

echo -e "&f0k${LENGTH}D$1\c"
```

第一个引号和 `f0k` 之间是 ESC 键。

如果你没有 `strlen`，它可以来自：

```c
#include <stdio.h>

main(argc, argv)

 int argc;

 int *argv[];

{

  if (argc != 2)

   exit(0);

  printf("%d\n", strlen(argv[1]));
}
```

要在图标中设置标题：

```bash
#!/bin/sh

LENGTH='strlen $1'

echo -e "&f-1k${LENGTH}D$1\c"
```

其中 `&` 是 ESC 键。

或者，你也可以简单处理，使用 `nohup` 启动一个新窗口，在后台运行，并使用带有 `-title` 选项 `hpterm` 退出原始窗口。例如：

```bash
nohup hpterm -title (window title) &
```

然后你就可以退出原始窗口了。

### 我的 `hpterms` 有时会自动消失。为什么？

如果你正在使用 C Shell，请检查是否设置了 `autologout`。默认值是 60 分钟。

要解决这个问题，只需编辑你的 `.cshrc` 文件并添加行 `unset autologout` 即可。

如果你使用的是 Korn shell，壳变量 `TMOUT` 可能有一个设置的值。要消除超时时间，请将此变量设置为 `0`。

### 我正在使用运行 HP X/Motif 客户端 Sun 工作站。为什么显示需要这么长时间？

这是一个 Sun 工作站特有的问题。Sun 提供了一个补丁；OW3 补丁 100444-35 或当前的替代补丁。

这本应该在 OW 3.0.1 中修复。如果你无法获得补丁或只需要一个临时的解决方案，可以在 Sun 工作站端设置 X 资源 `*useColorObj: False` 来解决这个问题。

### 当我使用 HP-VUE 时，如何让我的默认登录生效？

- HP-VUE 用户指南建议人们将 `/usr/vue/config/sys.vueprofile` 复制到 `~/.vueprofile`。该文件包含了关于设置的详细注释，说明如何配置它以便 `.login` 或 `.profile` 能被正确加载（包括关于确保只有在**不在** HP-VUE 时才运行类似 `tset(1)` 程序的详情）。

- 当你通过 VUE 登录时，VUE 会加载 `~/.vueprofile`，而**而不是**你的 `.login` (`csh`)、`.profile` (`sh/ksh`) 以及其他启动文件。在 `~/.vueprofile` 中采取的所有操作对于 VUE 启动的任何子进程都是持久。这意味着如果你将 `~/.vueprofile` 符号链接到 `~/.profile`，VUE 在启动窗口系统之前会加载你的 `~/.profile`，所有子进程 (`hpterms`、`xterms` 以及它们的交互式 shell) 将继承此环境（包括提示符变量）。

文档表明你的 `~/.vueprofile` 应该包含 `csh` 或 `sh`/ksh` 语法，取决于你的登录 shell。当 `csh` 是我的登录 shell 时，我设置 `~/.vueprofile` 只包含两行：
```bash
if ( -f /etc/csh.login ) source /etc/csh.login

if ( -f ~/.cshrc ) source ~/.cshrc
```
当 `sh`/ksh` 是我的登录 shell 时，我设置 `~/.vueprofile` 只包含两行：
```bash
test -f /etc/profile && . /etc/profile

test -f ${HOME}/.profile && . ${HOME}/.profile
```

所以，在启动窗口管理器和任何客户端之前，VUE 确保我所有的 shell 启动文件都已加载，并且我在 shell 环境中需要的所有变量都在那里等候我。

### 如何让我的控制台消息发送到工作站上的 `hpterm` 窗口？

首先，你需要指定一个 `hpterm` 会话作为接收控制台消息的窗口。这部分很容易。困难的部分是获取某种你可以实际读取的整洁输出。

你需要将此行存入你的 `~/.vue/sessions/home/vue.session` 中（注意第二行为了可读性进行了折行）：
```bash
# 以图标形式启动终端，如果有输出则将其置顶

vuesm -cmd "hpterm -C -iconic -ls -sl 256 -name Console -T Console -xrm *map"
```

### 如何让 vuepad 中覆盖系统默认打印机？

首先，你将全局 `vuepad` 复制到你的家目录：
```bash
cp /usr/vue/types/vuepad.vf $HOME/.vue/types
```

接下来，你必须编辑 `vuepad.vf` 文件并对 `ACTION PRINT_PR_VPAD` 行修改如下：

```text
# The PRINT_PR_VPAD
```

此动作使用 `pr(1)` 对其参数进行分页并打印。它使用 `arg 2` 作为标题。然后，它会删除 `temp #` 文件。

此动作被客户端 `vuepad` 使用。

```text
`ACTION PRINT_PR_VPAD`

` TYPE COMMAND`

` WINDOW-TYPE NO-STDIO`

` EXEC-HOST %LocalHost%`

` EXEC-STRING /bin/sh -c "pr -h %Arg_2% %(File)Arg_1% | \` 
` lp -d%"Printer:"%; rm %(File)Arg_1%"`
`END`
```

如果你实施了此操作，对话框将提示你输入打印机名称。

请注意不要在你的 `.vueprofile` 中设置 `LPDEST`，因为 `lp` 将使用该设置而不是系统默认值。
