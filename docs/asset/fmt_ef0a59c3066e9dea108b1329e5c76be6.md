### 核心目录

- `bin`：存放所有用户都使用的基本程序的目录。
- `dev`：存放特殊文件的目录，被称为设备节点，用于访问连接到你系统上的硬件设备。
- `etc`：存放系统配置信息的目录，包含系统上运行的某些应用程序的文件。
- `home`：存放不同用户存储个人文件的子目录的目录。
- `lib`：存放供其他应用程序调用的函数库的目录。
- `proc`：Linux 内核跟踪活动进程和一般状态的目录。
- `sbin`：包含通常由超级用户执行程序的目录。
- `opt`：通常用于安装第三方软件的目录。
- `usr`：包含普通用户在使用 Linux 系统时旨在使用的文件的层次结构。
- `sys`：Linux 内核跟踪系统硬件和相关接口状态的目录。
- `tmp`：存放系统中各种应用程序创建的临时文件的目录。
- `var`：存放具有变化内容的目录的目录。例如，`var/log`目录包含系统应用程序和事件的日志文件。

## Linux 文件系统简介

上一节讨论的目录为 Linux 系统的启动、运行标准应用程序等提供组织文件和目录的标准方法。你会注意到，目录路径以 `/` 符号开头。这并不意味着它们都位于硬盘或其他存储设备上。与 Windows 系统（使用唯一的驱动器符如 `C:`、`D:` 等来指代不同的磁盘分区）或 Mac OS X 系统（将磁盘驱动器或磁盘分区表示为桌面上的不同卷）不同，Linux 系统为它可以访问的所有存储设备和分区提供了一个“单一命名空间”。

本章将讨论 Linux 系统如何管理和访问磁盘、什么是磁盘分区，以及磁盘分区是如何集成到你在 Linux 系统上可以访问的目录层级结构中的。Linux 机器上的目录层级结构通常被称为 Linux 文件系统，尽管正如我在接下来的几节中解释的那样，“文件系统”一词也用于指代数据在磁盘分区上的组织方式。

## 分区与挂载点

任何计算机系统的主要功能都是存储、检索、处理和保存信息。作为一名计算机系统管理员，当那些对计算机完全不通的朋友告诉我“你的笔记本电脑太慢了，为什么不升级呢？”时，我总是感到惊讶。坦率地说，如果我的打字速度能比我笔记本电脑 1.4 GHz 的奔腾处理器处理得还要快，我就会去马戏团为“真假奇闻”的广告做模特，而不是写书了。另一方面，如果保存我正在做的内容需要五分钟，或者我永远无法在不删除其他内容的情况下找到保存修改后文件的空间，我会毫不犹豫地把现在的笔记本扔进河里，买一个当今最新、最亮眼的支持 Linux 的笔记本电脑。对于我的工作来说，能够可靠且快速地读写比极速的 CPU 速度重要得多。

计算机系统包括某些存储设备，如硬盘、DVD 和 CD 驱动器、闪卡等，它们存储了操作系统和你的应用程序，并提供了你可以用于存储所创建的文件和目录的空间。我写过的最好的文字之一是引用自 20 世纪 80 年代中期随惠普 HP-UX 工作站附带的手册中的话：

*“没有磁盘，你将永远在寻觅。”*

嗯，这意味着，如果不对用于存储数据的设备进行某种组织，文件系统将不知道去哪里寻找特定的文件、目录或任何内容。为了在磁盘上存储数据并在之后访问这些数据，必须对磁盘进行准备，以便你的操作系统和相关应用程序能够进行读取、写入和交互。这种准备通常包括：

- 将磁盘划分为一个或多个可以被操作系统唯一定位的部分。磁盘的每个部分被称为分区。
- 对分区进行格式化（称为“创建文件系统”），使操作系统能够访问每个分区并在其中创建文件和目录。

![](img/e88880e40d650bfe19d5b6927bd86568_118_0.png)

磁盘分区有几个原因：

- 减少在驱动器上定位特定数据所需的时间。在较小的信息池中寻找特定数据所需的时间更短（所需的定位信息也更少）。
- 限制磁盘或分区损坏时可能丢失或损坏的数据量。
- 在需要时加快碎片整理、一致性检查和修复等管理操作。
- 简化管理操作，例如备份。备份能够放入单条磁带或其他备份介质的分区要简单得多，因为不需要操作干预（例如更换磁带）。多个分区还允许你将系统文件和应用程序安装在与用户数据存储不同的分区上。这样你就可以相对频繁地备份包含用户数据的分区，而不会意外地备份大量相对不变的可执行文件、系统文件等。

正如上一节所讨论的，“文件系统”一词通常在口语中指代组成 Linux 系统的整个文件和目录集合。在本节中，我使用的是其技术意义上的“文件系统”，即它指的是磁盘分区格式化的方式，以便你可以存储甚至检索数据。

要对分区进行格式化并在其上创建文件系统，你必须让该磁盘分区对你的系统可用。这被称为该文件系统的*挂载*（mounting），它仅仅是将该文件系统连接到 Linux 目录结构上，以便你可以使用它提供的存储空间。Linux 系统将文件系统挂载到目录上，使其成为标准 Linux 文件系统命名空间的一部分，我将在稍后的“挂载文件系统”章节中详细讨论。任何 Linux 目录都可以作为文件系统的挂载点，而上一节讨论的许多标准目录实际上是存储这些内容的独立分区的挂载点。

标准的 Linux `/mnt` 目录通常包含用于挂载其他文件系统的特殊子目录。

## 网络文件系统

网络文件系统是存储在远程系统（通常称为文件服务器）上的文件系统，并像本地文件系统一样挂载到你的本地机器。网络文件系统允许用户从任何可以登录且拥有这些网络资源的系统访问信息。

与本地文件系统相比，网络文件系统具有若干优势：

- 它们减少了因单机故障导致你无法访问数据的概率。大多数网络文件系统允许你登录多台机器，并以完全相同的方式访问数据。
- 它们为所有用户必须或应该共享的数据提供了中心化位置。
- 它们简化了从更快系统访问现有数据的过程。假设你编写了一个测试 CPU 和内存性能的应用程序，或者你的工作或研究依赖于 CPU 和内存的密集型计算。在更快、更强大的机器上运行你的程序，只需登录到该机器并从网络文件系统运行程序即可。
- 它们提供了备份等管理操作中心化的机会。
- 它们促进了互操作性和灵活性。你通常可以在运行 Linux、Microsoft Windows、Mac OS X 等系统上访问网络文件系统。这使得你能够使用最适合你桌面需求的软件和硬件，同时仍访问网络文件系统上的相同数据。

Linux 支持网络文件系统。其中最流行的是 NFS，即网络文件系统（Network File System），最初由太阳微系统（Sun Microsystems）编写，自工作站诞生以来已得到几乎所有其他系统的支持。Apple 的 Mac OS X 积极支持 NFS，并且为 Microsoft Windows 系统也提供了相应的（客户端和服务器）。另一个常用的文件系统，讽刺的是，是微软的 SMB（服务器消息块）文件系统，它被重命名为 CIFS（通用互联网文件系统），试图掩盖其专有根源以及通过反向工程使其可供 Linux 和其他 Unix 类系统访问的事实。Linux 系统通过一组名为 Samba（www.samba.org）的客户端和服务器软件包支持 SMB/CIFS。Samba 允许 Linux 系统挂载并访问由微软导出的 SMB/CIFS 文件系统。Samba 服务器允许 Linux 系统导出其文件系统，以便从运行不同版本 Microsoft Windows 的机器访问。Linux 系统通过 Linux NCP —— Novell Core Protocol ——（www.novell.com/coolsolutions/feature/15350.html）以及 Linux netatalk 和 afpfs 工具（http://netatalk.sourceforge.net/ 或 www.anders.com/projects/netatalk/）连接到 Novell Netware 文件系统。
