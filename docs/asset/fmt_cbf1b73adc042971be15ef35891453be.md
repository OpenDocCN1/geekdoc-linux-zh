
## 只读变量

shell 识别一些约定命名的变量具有特殊含义。某些变量在 shell 启动时自动初始化；你通过 `set` 命令或在调用 shell 程序 `csh` 时使用命令行选项来设置它们。你可以为大多数这些变量赋值，但某些变量由 shell 在相应事件发生时自动设置。

除了你通过 `set` 和 `setenv` 定义的普通变量外，一些变量由 shell 定义并具有预设值。你可以使用这些变量获取其他方式无法获取的信息。特殊变量可以通过以下符号引用：

| 变量 | 含义 |
|---|---|
| `$0` | 替换为 shell 名称（如果已知）。如果未知，引用它会导致错误。`$0` 是 `argv[0]` 的缩写。 |
| `$1`, `$2` .. `$9` | 替换为 shell（第一个、第二个，等）。如果在脚本内部使用，这些符号引用命令的参数。最多九个参数可以通过任何符号引用。使用 `argv[n]` 或内置命令 `shift`。 |
| `$*` | 等于 `argv[*]`。替换为传递给 shell 的所有参数。 |
| `$$` | 替换为当前 shell 的进程号。当调用子 shell 时，`$$` 返回父级 shell 的 ID。 |
| `<` | 替换为来自标准输入文件的行。 |

## 12.10. 定义 shell 变量。

| 变量 | 描述 |
| --- | --- |
| `argv` | 一个包含当前 shell 参数的数组。`argv[1]` 的引用等于 `$1`，`argv[2]` 等于 `$2`，依此类推，直到 `$9`。`argv` 的值由 shell 在启动时以及执行每个命令之前设置。 |
| `cdpath` | 一个数组，指定 `cd` 命令要搜索的目录列表。shell 不为 `cdpath` 提供初始值。如果你不提供值，`cd` 命令将仅在当前目录搜索以 `/` 开头的或被视为锚定的路径。 |
| `cwd` | 包含当前目录的完整路径。在启动时，shell 将 `cwd` 初始化为你的家目录。你执行的每个 `cd` 命令都会更改 `cwd` 的值。注意，如果使用链接进入当前目录，`$cwd` 返回的值可能与 UNIX 命令 `pwd` 不同。 |
| `echo` | 如果设置，shell 在执行前打印每条命令。如果 `osh` 行上存在 `-x` 或 `-o` 选项，则 `echo` 初始化为空字符串；否则，该变量未设置。你可以通过执行命令 `set echo` 来激活任何跟踪，使用 `unset echo` 来关闭。`echo` 跟踪仅对当前的 shell 调用有效；它不会传播到调用的脚本中。对于内置命令，`echo` 在执行所有扩展、命令和文件名替换后发生。不是在执行前立即执行的命令。 |
| `history` | 指定在历史列表中维护的命令数量。如果内存足够，列表将保留此数量的命令。`history` 变量不会自动初始化，也不需要赋值。如果未设置，shell 将根据可用内存的大小维护最佳数量的历史。你可以随时设置 `history` 的值。 |
| `home` | 在 shell 启动时初始化为 `HOME` 环境变量的值。`home` 的值用作 `cd` 的默认目录以及 `~` 的替代符。更改 `home` 的值几乎总是正确的，除非被阻止这样做。 |
| `ignoreeof` | 如果设置，shell 将忽略在行首输入的文件结束符（EOF）字符。如果未设置，你的登录日志也将记录。你。与 EOF 字符对应的特殊键指示退出，可以使用 UNIX `stty` 命令显示和更改它。如果接收到大量连续的 EOF 字符，许多 shell 会注销。 |
| `mail` | 一个列出要监控更改的文件数组。如果第一个值是数字，它指定了 shell 检查新邮件的频率（以秒为单位）。默认频率在五到十或十五分钟之间变化。如果观察到任何文件的最后日期发生变化，则该文件会发布名为 `mail name` 的消息，其中 `name` 是发生变化的文件名。（如果 `mail` 仅列出一个监控的文件，通知消息为“你有新邮件”。）以下命令监控两个邮件文件，并指定了 10 秒的邮件检查间隔：`set mail=(10 /usr/mail/taytort /usr/spool/mail/taytort)`。 |
| `noclobber` | 如果 shell 不为 I/O 重定向激活替换文件。对于 `>>`，它要求目标文件已存在。你可以使用命令 `set noclobber` 激活该选项，并使用 `unset noclobber` 将关闭。当设置 `noclobber` 时，你可以使用 `! >>` 执行重定向。`noclobber` 变量未设置。 |
| `noglob` | 如果设置，将禁用使用模式字符 `*`、`?` 和 `[ . ]` 进行文件名扩展。`noglob` 变量未设置。 |
| `nonomatch` | 如果设置，未匹配任何文件的文件名将原封地传递给命令。默认情况下，如果找不到文件名模式的匹配项，shell 将发出错误并忽略命令。（注意使用 `nonomatch` 以接受不匹配的参数，使用 `unset nonomatch` 强制触发 shell 错误。`nonomatch` 变量未设置。 |
| `notify` | 如果设置，一旦后台作业状态发生变化，shell 将向你发送消息。默认情况下，shell 在发布下一个命令行提示之前不会通知你状态变化。注意，设置 `notify` 可能会导致屏幕上出现消息，例如使用全屏编辑器。`notify` 的值未设置。 |
| `path` | 一个要搜索的目录数组列表。如果 `path` 变量未设置，你必须使用显式路径名在当前目录中执行非内置命令（例如，`./mycmd`）。`path` 的值是 `PATH` 环境变量。 |

## 编写脚本：概述

编写 shell 脚本就像在键盘上输入命令，但有一些重要的不同：

- 你可能想给你的命令传递参数。shell 会自动将命令行中跟随脚本名称的任何单词放入 shell 变量 `argv` 的一组参数中。你不需要任何特殊操作来从命令行获取参数；它们已经存在于

当脚本开始执行时，`argv` 是参数数组。关于 `argv` 的信息，请参阅本章前面的“使用预定义变量”部分。

- 你可能希望让你的新命令支持一个或多个选项。shell 将选项作为其他的命令行参数传递给脚本。然而，选项可能具有复杂的结构，特别是当你打算支持标准的 UNIX 选项约定时。请参考 UNIX `getopt` 的描述以获取处理命令行选项的帮助。

- 键盘命令通常在输入时对所有信息都根据命令进行了具体的定制（例如使用 `ls -l foo html.gif`），而 shell 脚本内部的命令是参数化的（如 `ls $opt $file` 且可以根据条件执行）。你可以通过提供变量引用和文件名替换作为命令的参数而非字面文本，对命令进行参数化。为了编写备选命令集来处理不同的情况，你需要使用 shell 的 `if`、`switch`、`while` 和 `foreach` 命令。这些命令在键盘上很少使用，但在 shell 脚本中频繁出现。

无论 shell 脚本的用途如何，你编写 shell 脚本都遵循相同的通用步骤：

- 使用所需的命令创建一个文件。

- 使用 `chmod` 命令将该文件标记为可执行：

```
chmod +x filename
```

- 测试脚本。

- 将脚本安装到它的永久位置。

- 使用你的脚本。

你已经知道如何使用文本编辑器来准备文件了。如果不知道，请参阅第二卷第 3 章“使用 vi 和 emacs 进行文本编辑”。你可以使用任何喜欢的文本编辑器，因为 shell 关的是文件的内容，而不是你是如何创建它的。文本文件不能包含某些文字处理器生成的格式字符；然而， shell 脚本包含的行格式和内容必须与你在键盘上输入的完全相同。为此，你可能会使用如 `vi` 等通用文本编辑器来准备 shell 脚本。

文本文件必须被标记为可执行，才能通过输入其名称作为命令调用。如果一个文件没有被标记为可执行，你可以将其命名为 `csh` 命令的第一个参数来作为命令调用。例如，`csh payroll` 将使用标准路径（由 `path` 变量定义）搜索名为 `payroll` 的文件，打开该文件读取并执行文件中的命令。如果你将 `payroll` 文件标记为可执行，你可以输入 `csh first: payroll` 变成一个新的命令。

shell 定位脚本文件使用的路径与它定位 UNIX 命令使用的路径相同。要调用 shell 脚本，你必须将其存储在搜索路径中的某个目录下。或者，你可以将脚本所在的目录添加到你的搜索路径中。搜索路径中的许多目录可能会减慢 shell 的速度，因此 shell 脚本通常被收集在几个常用的目录中。

你会发现，如果你进行任何脚本编写，在主目录下创建一个 `bin` 目录是非常方便的。将你编写的所有个人使用的脚本放在 `~/bin` 中，或者将 `~/bin` 目录包含在搜索路径中。要向你的个人环境添加新命令，只需编写一个 shell 脚本，将其标记为可执行并存储在 `~/bin` 中；它即可使用。通常认为将 `~/` 放在标准的 `bin` 目录（`/bin` 和 `/usr/bin`）之前不是好主意，使用别名（`alias`）引用自定义的 UNIX 命令，这样你就不需要在自定义命令前加上 `~/bin/` 了。例如，如果你创建一个替换/增强 UNIX `rm` 命令的脚本，你应该设置以下内容：

```
alias rm ~/bin/rm
```

现在你可以使用你的 `rm` 而无需输入 `~/bin/rm`，且不会影响你的搜索效率。

供用户社区使用的 shell 脚本通常安装在不属于任何特定用户的通用目录中，例如 `/usr/bin` 或 `/usr/local/bin`。大多数系统管理员倾向于将本地脚本存储在与 UNIX 路径分开的目录中；这使得系统维护更加容易。如果你的安装实践遵循了这一点，你可能已经将本地命令的路径包含在搜索路径。你需要系统管理员的帮助来将 shell 脚本文件存储在公共目录，因为你可能没有该目录的写权限（除非你是管理员）。

测试脚本并没有什么神奇之处。按照惯，你会在专门留出的目录中开发新的 shell 脚本。脚本可能包含许多你用于测试它的数据文件，可能还会有多个版本的脚本。在完成测试之前，你可能不想让其他人访问脚本文件。

如果你发现脚本的行为令你困惑或无法解释，查看 shell 在运行脚本时实际执行的命令可能会对你有所帮助。只需使用 `-x` 选项调用脚本（例如 `csh -x payroll`），或者在脚本文件中嵌入 `echo` 命令，或者将 `#!` 修改为 `#!/bin/csh -x` 并带有 `echo` 变量。每个脚本命令在执行之前都会连接。你将看到添加的替换、文件名和其他替换内容，这样你就能确切知道 shell 在运行脚本时在做什么。有了这个追踪可以依靠，你发现脚本中发现错误可能并不困难。

如果 `-x` 的输出量过多，你可以通过括起想要跟踪的命令来缩小显示的命令范围。将命令集放在要跟踪的范围之前，并在末尾加上 `unset echo` 命令。shell 在运行你的脚本时，只会打印 `set` 和 `unset` 之间的命令。在完成测试并于将 shell 脚本投入生产环境之前，不要忘记移除 `set` 和 `unset` 命令。

# 一个简单的 shell 脚本

shell 脚本编写起来非常容易。以下内容如果输入到名为 `lld` 的文件中，将实现一个新命令：

```bash

if [ $1 == "x-v" ] then

set wordary; shift

endif

set DATE=``date`'

foreach F (*.html)

vprint Processing file $F

sed "s/$DATE/$DATE/" $F > $F.$

mmv -f $F.\$$ $F

end
```
