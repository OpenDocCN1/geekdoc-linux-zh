
## 支持的架构

- Intel IA-32 (x86)
- PowerPC
- PowerQUICC
- ARM/ARM7/ARM9/StrongARM
- Super-H
- MIPS R3000/R4000

支持以下主机操作系统：

- Red Hat 6.1 和 6.2
- TurboLinux Workstation，版本 6.0
- Windows 98/NT/2000

## 使用 BlueCat Linux

1. 获取你机器的 `root` 权限。

2. 以 `root` 身份，输入以下命令在 `/tmp/` 中创建 `bluecat` 目录：

```bash
mkdir -p /tmp/bluecat
```

BlueCat 压缩包在根目录下包含多个文件和目录（很乱）。通过将所有这些文件放入空目录 `/tmp`，你可以在安装后轻松地删除它们。

3. 现在使用以下命令从 BlueCat 网站下载 `x86-linux.tar.gz` 文件：

```bash
cd /tmp/bluecat; lynx http://www.LinuxWorks.com/...
```

文件大小为 70MB，需要一些时间。

4. 解压 `x86-linux.tar.gz`

```bash
tar xvzf x86-linux.tar.gz
```

当此过程完成后，你将拥有一个安装脚本和一个 `BlueCat_i386` 目录。

5. 创建 `bluecat` 用户：

```bash
adduser bluecat
```

如果你愿意，也可以将软件放在其他地方。

6. 切换到 `bluecat` 用户：

```bash
cd -bluecat
```

7. 在 `bluecat` 用户的家目录下创建一个 `bluecat` 目录并进入：

```bash
mkdir bluecat ; cd bluecat
```

我曾尝试直接将 BlueCat 软件安装到 `bluecat` 用户的家目录中，但安装脚本只会安装到没有其他文件的目录中。用户的家目录下有很多垃圾文件，这会阻止安装，因此使用子目录是强制要求的。

8. 使用此命令安装 BlueCat 软件：

```bash
/tmp/bluecat/install
```

当安装完成后，你将拥有九个新目录和一个设置脚本。

在实际项目中，你会修改项目的 `Makefile`，以便直接生成 `minicom`，而不是在当前目录下“手动”构建可执行文件。

- 26. 好的，回到我们项目的根目录：

```bash
cd ../../..
```

- 27. 准备好进行另一个 `Makefile` 更改了吗？

```bash
vi Makefile
```

找到第三行：

`KDI_NAME = shell`

将其修改为：

`KDI_NAME = minicom`

- 28. 另一个 `ncurses` 的临时补丁。这个操作是相当无害的，因为该文件与架构无关。`Minicom` 需要用于 Linux 控制台“终端”类型的 `terminfo` 文件：

```bash
cp / /usr/share/terminfo/1/linux local
```

- 29. 现在我们需要对 `minicom` 文件进行一些更改：

```bash
vi minicom.spec
```

这里是第一行：

`# shell.spec`

将其修改为：

`# minicom.spec`

这是一个注释，但你完全可以把它修复了。现在找到以下行：

`ln -s /dev/console /dev/tty1`

在其之后添加以下行：

```bash
mknod /dev/tty0 c 4 64
mknod /dev/tty1 c 4 65
mknod /dev/tty2 c 4 66
mknod /dev/tty3 c 4 67
```

这些行在目标系统的 `/dev` 目录下为四个串口端口创建设备节点。

现在找到以下行：

`mkdir -p /var/run`

在其后添加以下行（注意最后一个字符是小写字母 L）：

`mkdir -p /usr/share/termininfo/l`

这创建了存放 `terminfo` 文件的目录。

快要完成了。找到这一行：

`cp ./local/rc.sysinit /etc/rc.d`

在其后添加以下行：

```bash
cp ./local/linux /usr/share/termininfo/l
cp ./minicom/minicom/src/minicom /bin
```

这些行将 `minicom` 可执行文件和 `terminfo` 文件放置到目标的根文件系统中。

- 30. 现在我们需要编辑该文件。运行命令：`vi local/inittab`

最后一行看起来应该是这样的：

`1:12345:respawn:/sbin/getty tty1`

将该行修改为：

`1:12345:respawn:/bin/minicom`

确保删掉 `sbin` 中的 `s`。这会强制 `init` 程序在初始化机器时运行 `minicom` 命令。

- 31. 运行 `make` 命令来构建 BlueCat 项目：

```bash
make
```

第一次它必须重建内核，所以需要一些时间。

- 32. 创建启动软盘：

```bash
mkboot -b k minicom.disk -f minicom.fs -r /dev/fd0 /dev/fd0
```

`mkboot` 命令是 BlueCat 发行版的一部分。它根据 `make` 命令创建的部分在指定的设备（`/dev/fd0`）上创建一个可启动的镜像。`minicom.disk` 文件是内核中 `-bluecat/bluecat/usr/src/linux` 下 `zimage` 的拷贝。`minicom.fs` 文件是由 BlueCat 的 `mkrootfs` 在 `make` 过程中构建的。`mkboot` 命令的一个问题是如果你使用 `-b` 选项，它可能会输出到真实设备。如果你使用 VMware 这样的硬件模拟软件且从未真正创建过物理软盘，这就是问题。例如，在测试 BlueCat 时，我必须用 `mkboot` 命令构建一个真实的软盘，并使用 `dd` 命令将镜像从软盘提取并发送到文件中。

- 33. 在你的目标设备上启动软盘。如果运气好，可靠的 Minicom 就会出现，满足你的串口终端需求。
