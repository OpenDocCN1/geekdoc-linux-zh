## GUI 构建器

在上一个示例中，你通过调用每个组件的函数并将其放置在你想要的地方，创建了应用程序的用户界面。然而，对于更复杂的应用程序，这可能会非常麻烦。许多编程环境（包括 GNOME）都有称为 GUI 构建器的程序，它们可以自动为你创建 GUI。你只需要为信号处理程序和初始化你的程序编写代码即可。GNOME 应用程序的主要 GUI 构建器称为 `GLADE`。`GLADE` 在多数 Linux 发行版中都带了它。

大多数编程环境都有 GUI 构建器。Borland 有一系列工具，可以在 Linux 和 Win32 系统上快速方便地构建 GUI。KDE 环境有一个名为 `QT Designer` 的工具，可以帮助你自动开发该系统的 GUI。

开发图形化应用程序有广泛的选择，但希望这个附录让你体验到了 GUI 编程是什么样子的。

## 附录 B. 常用 x86 指令

### 读取表格

本附录中提供的指令表包括：

- 指令代码
- 使用的操作数
- 使用的标志位
- 指令作用的简要描述

在操作数部分，它将列出它接受的操作数类型。如果它接受多个操作数，每个操作数将用逗号隔开。每个操作数将有一个代码列表，告诉该操作数可以是立即数模式 (`I`)、寄存器 (`R`) 或内存地址 (`M`)。例如，`movl` 指令列为 `I/R/M, R/M`。这意味着第一个操作数可以是任何值，而第二个操作数必须是寄存器或内存位置。注意，在 x86 汇编语言中，你不能有多个操作数为内存地址。

在标志位部分，它列出了受指令影响的 `%efl` 寄存器的标志位。提到的标志位有：

**O**: 溢出标志位。如果目标操作数不足以容纳指令的结果，则将其置为真。

**S**: 符号标志位。它设置为上一次结果的符号。

**Z**: 零标志位。如果指令的结果为零，则将此标志置为真。

**辅助进位标志 (Auxiliary carry flag)**: 该标志用于第三位和第四位之间的进位和借位。它不经常被使用。

**奇偶性标志 (Parity flag)**: 如果上一次结果的低字节有偶数个1 位，则将此标志置为真。

**进位标志 (Carry flag)**: 用于算术运算，表示结果是否应该进一个额外的字节。如果进位标志被设置，通常意味着目标寄存器无法容纳结果。由程序员决定采取什么操作（例如 - 将结果传播到另一个地方）。

其他标志也存在，但它们没有那么重要。

## 附录 B. 常用 x86 指令

- 在 Intel 语法中，寄存器不以百分号 (`%`) 为前缀。
- 在 Intel 语法中，进行立即数模式寻址（immediate-mode addressing）时不需要美元符号 (`$`)。相反，通过将地址括在括号 (`[]`) 中来实现非立即数寻址。
- 在 Intel 语法中，指令名称不包含所移动移动数据的大小。如果存在歧义，则会在指令名称后显式地通过 `BYTE`、`WORD` 或 `DWORD` 指明。
- Intel 汇编语言中内存地址的表示方式大不相同（如下）。
- 由于 x86 处理器最初是一个 16 位处理器，大多数关于 x86 处理器的文献将字（words）视为 16 位的值，而将 32 位的值称为双字节字（double words）。然而，我们使用“word”一词来指代处理器的标准寄存器大小，这在 x86 处理器上是 32 位。该语法也保留了这一命名习惯——在 Intel 语法中，`DWORD` 代表“double word”，用于标准大小的寄存器，而我们通常将其简称为“word”。
- Intel 汇编语言具有作为段/偏移对对内存进行寻址的能力。我们没有提到这一点，因为 Linux 不支持分段内存，因此与普通的 Linux 编程无关。
