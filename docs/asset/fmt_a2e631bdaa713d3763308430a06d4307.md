- 4. 在 `README` 提示输入 `OK`。
- 5. 选择创建/升级数据库 (`Create/Upgrade Database`)。
- 6. 选择创建数据库对象 (`Database Objects`)。

- 9. 验证您的 `ORACLE_SID` 是否正确。

# 第四章 Linux 上安装 Informix

## 总结

`Informix` 是像 `Oracle` 一样强大的商业数据库。`Informix` 以及 `IBM` 的 `DB2`、`Sybase` 等企业级数据库在多种平台上进行竞争，但它们主要关注需要大量数据库流量和存储的企业级数据库管理，这通常出现在中大型企业环境中。

偏好通常取决于接触顺序。如果一个开发者首先接触的是 `Informix`，该开发者很可能会出于个人偏好继续支持 `Informix`。一旦你发现与市场其他产品相比，`Informix` 管理多么容易，这一点尤为真实。原因在于简单：一个典型的 `Oracle` 实例大约需要 `600MB` 的磁盘空间存储软件，更不用数据库所需的额外空间。典型的 `Oracle` 安装不仅在软件布局上，而且在配置上也比 `Informix` 复杂得多。只需查看 `Oracle` 软件目录，你就能看到接下来安装 `Informix` 的差异。安装和配置 `Oracle` 可能比 `Informix` 长得多，更不用说 `Oracle` 相比 `Informix` 的性能限制。如果 `Oracle` 是你的第一个引擎，而这个是第二个，你可能会惊讶于它的简单。如果 `Informix` 是你的第一个引擎，请在 `Informix` 之后安装 `Oracle` 软件，以感受我所说的内容。

`Informix` 占据的空间比 `Oracle` 小得多——引擎和核心开发者 `SDK` 工具通常占用小于 `150MB`。然而，这取决于你向 `Informix` 软件目录（在 `UNIX` 中通常称为 `$INFORMIXDIR`）添加了哪些组件。本章重点介绍如何在 `Linux` 环境中安装和启动 `Informix`。关注点不仅是企业级数据库，还包括一个从 `Linux` 向上扩展到市场上更大服务器（主要是 `UNIX` 操作系统）的引擎。你在这里学到的很多内容可以应用于 `UNIX` 中其他版本的 `Informix Dynamic Server`，以及在某种程度上应用于 `NT` 世界；但目前，你会发现没有与 `NT` 的对比，工作起来并不容易。市场上的大多数企业级引擎运行在 `UNIX` 和 `NT` 上，在某些情况下运行在 `MVS`（大型机）上。在 `UNIX` 上没有找到微软的数据库产品，他们选择 `NT` 作为其主打平台。微软现在才开始认真对待他们的数据库市场，构建用于数据仓库和数据转换的产品来补充其 `SQL Server` 系列。一旦 `Intel x86` 架构的平台足够大，让 `NT` 能够以类似于 `UNIX` 或其他平台的速度运行，那么 `Informix` 在这个领域可能就有机会了。
