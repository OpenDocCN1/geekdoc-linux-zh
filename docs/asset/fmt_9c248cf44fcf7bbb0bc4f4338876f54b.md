
接下来，我们直接通过 `pte_alloc()`（如果需要）分配一个 PTE，如果成功，则将其分配给 `struct vm_fault->pmd` 中引用的 PMD 条目。如果分配失败，我们通过 `VM_FAULT_OOM` 报告内存溢出。

### 6.3.1 零页

分页异常机制中一个非常实用的概念是“零页”的概念。这是一个预分配并清零的内存页，在发生读异常时被映射为写操作时的写时复制（CoW）。

通过这种方式，匿名读取不需要实际的内存，实际的分配可以推迟到写入时。

这是由由于没有发生写异常（即没有设置 `FAULT_FLAG_WRITE`）决定的，请注意由于我们已经检查了这一点，我们知道这并非共享。它还受到 `mm_forbids_zero()` 的调控，但这仅在 s390 架构上被禁止，与我们关注的 x86-64 架构不相关。

### 6.3.4 设置 PTE

我们接着进入设置 PTE 条目的阶段，通过 `mk_pte()` 开始设置从 `struct vm_area_struct` (VMA) 的 `vm_flags` 继承并存储在其 `vm_page_prot` 字段中的标志，注意当映射为共享时，这些映射总是映射写时复制（Copy on Write，即默认如此）。

我们调用 `pte_sw_mkyoung()`，它为那些不在硬件中设置此标志的架构设置可访问页表标志。然而，现代架构包括重点的 x86-64 支持这一点，因此在这种情况下它无任何操作。

接下来，如果这是一个写异常，我们会调整 PTE 标志，因为在这种情况下我们实际上并不希望该页是写时复制，因为我们刚刚为它分配了一个页（只读异常应该通过 `pte_mkwrite()` 和 `pte_mkdirty()` 将页表同时标记为可写、脏和软脏状态（即该页已被写异常“触碰”过））。

随后，一个指向 PTE 条目本身的指针被放置在 `struct vm_fault->pte` 字段中，并获取其锁将其放在 `pte` 字段中，使用该字段获取我们之前可能分配的 PTE 页地址。

由于我们只获取了该 PTE 的锁，因此必须检查竞态条件，现在通过 `pte_none()` 检查我们是否被抢占。如果是，我们简单地释放物理页并返回。

否则，我们检查我们是否处于一个“稳定”地址空间中（即未被 OOM 杀手程序针对），正如我们在零页路径 `check_stable_address_space()` 中做的那样。如果不是，则释放页并终止操作。

然后，我们通过 `inc_mm_counter_fast()` 增加匿名页统计。

### 6.3.5 添加到反向映射和 LRU 并设置 PTE

当我们使用内存时，有几项额外的任务需要执行 - 首先，我们必须将 folio 添加到代表此页的 `struct vma_object` 中，即 `page_add_anon_rmap()`（参见列表 7-20）。详细检查此内容请参见第 70.12 节。

其次，我们必须通过 `lru_cache_add_inactive_or_unevictable()` 将 folio 添加到“最久未使用”（LRU）缓存机制中——这是内核在决定交换出或从页缓存中驱逐哪些 folio 时，跟踪 folio 访问频率的一种手段。详细分析此内容请参见第 11.2 节。

随后，我们解锁 PTE 锁并返回 - 页已触发异常，所有页表都已正确设置，内存已根据需要被添加到反向映射和 LRU 机制中。

### 6.4 非匿名页异常处理程序

非匿名页异常由 `do_fault()` 处理，该函数在列表 6-25 中决定我们进入并调用的哪个处理程序。

```c
/*
 * 我们带有非排占的 mmap_lock 进入（以排除 vma 变化，
 * 但允许并发异常）。
 * mmap_lock 可能根据标志和我们的返回值被释放。
 * 查看 filename_fault() 和 _folio_lock_or_retry()。
 * 如果 mmap_lock 被释放，vma 可能会失效（例如
 * 其他线程调用 mmap()）。
 */
static vm_fault_t do_fault(struct vm_fault *vmf)
{
    struct vm_area_struct *vma = vmf->vma;
    struct mm_struct *vma_mm = vma->vm_mm;
    vm_fault_t ret;

    /*
     * VMA 未被 mmap() 完全填充或未合并 VM_DONTEXPAND
     */
    if (!vma->vm_ops->fault) {
        /*
         * 如果我们发现迁移 pmd 条目或空 pmd 条目，
         * 则不应返回，触发 SIGBUS
         */
        if (unlikely(!pmd_present(vmf->pmd))) {
            ret = VM_FAULT_SIGBUS;
        } else {
            vmf->pte = pte_offset_map_lock(vmf->vma->vm_mm,
                        vmf->pmd,
                        vmf->address,
                        &vmf->ptl);
            /*
             * 确保这不是 pte 的临时清除
             * 通过持有 pte 并再次检查。pte 的读/改/写更新
             * 涉及：获取 pte，
             */
            if (unlikely(pte_none(*vmf->pte)))
                ret = VM_FAULT_SIGBUS;
            else
                ret = VM_FAULT_NOPAGE;

            pte_unmap_unlock(vmf->pte, vmf->ptl);
        }
    } else if (vmf->flags & FAULT_FLAG_WRITE) {
        ret = do_cow_fault(vmf);
    } else if ((vma->vm_flags & VM_SHARED)) {
        ret = do_shared_fault(vmf);
    } else {
        ret = do_read_fault(vmf);
    }

    /* 任何预分配页 */
    if (vmf->prealloc_pte) {
        free_page(vmf->prealloc_pte);
        vmf->prealloc_pte = NULL;
    }

    return ret;
}
```

## 6.4.1 Folio 锁

在执行这些操作时，我们进入 folio 可能被锁定的状态，直到释放锁——为了确保 folio 在整个过程中是稳定的，不会与正在进行的移除映射或类似更改发生竞态。

在下面的所有操作中，共享的 `_do_fault()` 处理程序都会获取 folio 锁，并且 `finish_fault()` 中完成异常的共享逻辑假设该锁一直持有。

这些锁通过 `folio_lock()` 或 struct page 等效的 `lock_page()` 获取，并通过 `folio_unlock()` 或 `unlock_page()` 解锁。

页异常处理程序可以通过 `VM_FAULT_LOCKED` 表明它们已获取此锁，并且在异常或 page_mwrite 中预期这样做，对于并非如此的情况有特殊处理。

注意的是，这些函数并不是简单地设置或清除 folio `PG_locked` 标志，而是等待该标志被清除。

这部分简单地调用 `__do_fault()` 来填充 `vm_fault` 对象，并调用 `finish_fault()` 应用缺页异常的内存，同时处理好错误状态。

然而，关键区别在于缺页周围（fault-around）逻辑——从文件读取时，如果我们根据后续页面很可能被读取的合理假设（即仅执行次要异常），那么轻松地映射获取的页面是有用的。

一个典型的例子是：文件的多个 folio 存在于页缓存中，但尚未映射到缺页异常的 VMA 中。在这种情况下，映射这些页面相对简单，但如果它们必须从磁盘检索，情况就不同了。

这与预读（read-ahead）不同，预读是将 folio 从磁盘加载到页缓存中以预备后续读取，这是一项昂贵的操作。缺页周围由文件系统通过 `struct vm_area_struct` 的 `vm_ops->map_pages` 处理器指定，该处理器也被委托给了通用的 `filemap_map_pages()`。

缺页周围是否通过 `should_fault_around()` 并由静态变量 `fault_around_bytes` 介导，该变量默认值为 64 KiB，但可以通过 debugfs `/sys/kernel/debug/fault_around_bytes` 进行配置。

此值必须是 2 的幂；一个页或指定的值将向下取整到最接近的值（这在 `fault_around_bytes_set()` 中完成）。它还不能大于 PTE 能够映射的区域（最多为 `PTRS_PER_PTE` 个页），因为它不会跨越页边界。

重要：这意味着缺页的“周围”是指围绕该地址。例如，如果缺页了 16 个页面（4 KiB 大小的默认值），加载的将是包含缺页地址的 16 个页面，而不是紧随其后的页面。

例如，如果缺页地址为 `0xe000`，`0xe000` 到 `0xffff` 会被加载，而不是 `0xe000` 或其之后的 16 个页面（预读是预读要做的事，且是独立的，将在页缓存章节的第 9.7 节讨论）。
