## 选项

+ `-C` 保留段落内前两行的缩进，并将后续每行的左边距与第二行对齐。这种宽度模式对于带有标记的段落很有用。

+ `-S` 不将行合并成更长的行。此仅拆分行的选项可以防止代码示例行和其他此类格式化文本被过度合并。

+ `-w width` | `-width` 填充行直到达到宽度列。请注意，`-width` 选项为了兼容 BSD 是允许的，但可能会在未来的版本中移除。

### 操作数

+ `inputfile` 输入文件。

## fmtmsg — 在标准错误或系统控制台显示消息

### 概要

```
/usr/bin/fmtmsg [-c class] [-u subclass] [-1 label] [-s severity]

[-t tag] [-a action] text
```

## 描述

根据消息分类组件，`fmtmsg` 要向标准错误写入格式化消息，或向控制台写入格式化消息。
格式化消息由最多五个标准组件组成（参见环境变量 `MSGVERB.`）。分类和子类组件不作为标准消息的一部分显示，但它们定义了消息来源并引导格式化消息的显示。

## 选项

`-c hard | soft | firm`
描述消息来源为硬件、软件或固件。

`-u subclass`
关键字列表（用逗号分隔），进一步定义消息并引导消息的显示。有效关键字有：

+ `appl` 情况源于应用程序。不要将此关键字与 `util` 或 `opsys` 结合使用。
+ `util` 情况源于命令。不要将此关键字与 `appl` 或 `opsys` 结合使用。
+ `opsys` 消息源于内核。不要将此关键字与 `appl` 或 `util` 结合使用。

`fmtmsg` 377

`recov` 应用程序从该状态中恢复。不要将此关键字与 `nrecov` 结合使用。

`nrecov` 应用程序未从状态中恢复。不要将此关键字与 `nrecov` 结合使用。

`print` 将消息发送到标准错误。

`console` 将消息发送到控制台。

`halt` 程序遇到严重故障。

`error` 程序检测到故障。

`warn` 程序检测到状态。

`info` 程序正在提供相关信息。

`label` 标识消息来源。

`severity` 指示消息的严重程度。

`text` 指定描述该状态的字符串。

`action` 指定流程中的步骤。

`tag` 指定消息的标识符。

```
1   HALT.
```

在 Bourne 和 Korn shell 中如下所示设置 `SEV_LEVEL`：
```
$ SEV_LEVEL=[description:description:::]]; export SEV_LEVEL
```
在 C shell 中则如下所示设置。

```
castle% setenv SEV_LEVEL [description:description:::]]
```

`description` 是包含三个字段的逗号分隔列表。
`description=severity-keyword, level, printstring`

- `severity-keyword`
一个字符字符串，用作 `fmtmsg` 命令中 `-s` 严重程度选项的关键字。

- `level` 一个评估结果为正整数的字符字符串（0, 1, 2, 3 或 4 除外，这些值预留给标准的严重程度级别）。如果你使用了 `severity-keyword`，则 `level` 是传递给 `fmtmsg(3C)` 的严重程度值。

- `printstring` 当使用严重程度值列表时，`fmtmsg` 在标准消息格式使用的字符字符串。

如果未定义 `SEV_LEVEL` 或其值为空，则除默认值外没有其他严重程度级别。如果冒号分隔列表中的描述不是包含三个字段的逗号分隔列表，或者逗号分隔列表的第二个字段评估不是正整数，则忽略冒号分隔列表中的该描述。

## 退出状态

- `0` 所有请求的函数均执行成功。
- `1` 命令执行了语法错误、无效选项或无效的参数。
- `2` 函数部分执行成功；但消息未显示在标准错误上。
- `4` 函数部分执行成功；但消息未显示在系统控制台上。
- `32` 没有请求的函数被执行成功。
