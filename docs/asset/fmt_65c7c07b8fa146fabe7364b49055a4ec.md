
```
ls -al
```

你将看到更多的条目，`.`（单个点）和 `..`（两个连续的点），它们是目录和父目录条目。

在之前的示例中，权限之前的第一个字符（例如 `drwxr-xr--` 中的 `d`）提供了有关文件类型的信息。文件类型值如下：

- `d`：条目是一个目录。
- `b`：条目是一个块文件。
- `c`：条目是一个字符文件。
- `l`：条目是一个符号链接。
- `p`：条目是一个先进先出 (FIFO) 特殊文件。
- `s`：条目是一个套接字。
- `-`：条目是一个普通文件。

# 创建和删除目录：`mkdir` 和 `rmdir`

当你在 UNIX 操作系统中设置用户时，通常会将 `/home/username` 设置为你的目录。你需要组织你的目录。通过绝对路径，你可以创建一个目录。如果你的当前目录是 `/u/guhas`，执行

```

```

将在绝对路径为 `/u/guhas/temp` 的目录下创建一个名为 `temp` 的子目录。

```
mkdir /u/guhas/temp
```

也可以用于达到与上一个相同的效果。使用 `..`（两个连续的点）作为相对路径的一部分，表示将在上一级创建目录，即 `/u`。

- `kbytes`: 以千字节（KB）为的文件系统大小
- `used`: 已用量
- `avail`: 剩余可用存储空间
- `iused`: i-nodes 数量
- `capacity`: 总容量的百分比
- `%used`: 已用 i-nodes 的百分比
- `mounted`: 挂载顶层目录名称

如果你在主目录下并执行以下命令

它将返回以下内容

| 文件系统 | 总 KB | 空闲 已用 | iused | %used | 挂载点 |

| /dev/hdl | 151552 | 41828 72% | 5534 14% | /u |

这意味着你的目录位于 `/dev/hdl` 文件系统上，且该文件系统的顶层目录名为 /u。对于这个示例，无论你当前的目录在哪里，只要你所在的目录绝对路径是以 `/u` 开头的，就会得到相同的结果。

你可以不带任何参数执行 `df` 命令，以获取系统中所有文件系统及其属性列表。你可以为目录提供绝对路径或相对路径，以查找其所属文件的文件系统属性。

`du` 命令显示由文件和目录参数指定的文件和目录的块数，并递归地显示指定参数内所有目录的统计。

你可以从当前目录执行以下命令：

```
du or du
```

并获得以下结果

```
8
```

意味着当前目录所在的文件系统中仅包含当前目录，并且占用了 8 个块。如果该文件系统中还有其他目录，所有它们及其大小都将显示出来。

## 使用 `file` 命令确定文件的本质

`file` 命令可以用于确定文件的类型。`file` 命令实际上会读取文件并执行一系列测试来确定文件类型。该命令将输出显示在标准输出中。

如果一个文件看起来是 ASCII 格式，`file` 命令会检查前 512 字节并尝试确定语言。如果文件看起来不是 ASCII 格式，`file` 命令将进一步区分二进制数据文件和包含扩展字符的文本文件。

如果参数指定可执行文件或对象模块文件，且版本号大于 0，`file` 命令将显示版本标记。

`file` 命令使用 `/etc/magic` 文件来识别具有某种魔数（magic number）的文件——即任何包含指示类型的数字或字符串的文件。

例如，如果你在当前目录下有一个名为 `letter` 的文件，且其中包含一封写给朋友的信，执行命令

```
file letter
```

将显示以下结果：

```
letter: commands text
```

如果你有一个名为 `prog` 的文件且它是一个可执行程序（并且你正在使用 IBM RISC 6000 AIX 3.1 版本），执行命令

```
file prog
```

显示以下结果：

```
prog:      executable (RISC System/6000 V3.1)
```

如果你在 `/dev` 目录（其中包含所有特殊文件），执行命令

```

```

对于名为 `hdl` 的文件（已定义文件系统的磁盘），将显示以下结果：

```
hdl:      block special
```

## 文件和目录权限

在本章前面的部分，你看到带有 `-al` 选项的 `ls` 命令显示了与文件或目录相关的权限。与文件或目录相关的权限告诉你谁可以访问该文件或目录，以及该用户可以执行什么。

在 UNIX 中，每个用户通过唯一的登录 ID 进行标识。此外，多个用户可以分组并关联到一个组。一个用户可以属于一个或多个组。然而，用户只属于一个主组。用户所属的所有其他组都是辅助组。用户登录 ID 定义在 `/etc/passwd` 文件中，用户组定义在 `/usr/group` 文件中。UNIX 中的文件和目录权限基于用户和组。

与文件或目录相关的所有权限有三种类型：

- 所有者权限（owner）：标识了文件或目录所有者可以对该文件或目录执行的操作。
- 组权限（group）：标识了任何与文件或目录所有者属于同一组的用户可以执行的操作。
- 世界权限（world）：标识了其他人（所有者和所有者所属组的成员之外的人）可以执行的操作。

使用文件或目录的权限属性，用户可以选择性地为属于特定组的用户和不属于特定组的用户提供访问。UNIX 按照所有者、组和其他（世界）的顺序检查权限——并使用第一个适用于当前用户的权限。

这里是当前目录下名为 `testfile` 的文件示例，该文件由属于 `staff` 组的用户 `gahas` 创建。该文件设置为其他用户 `gahas` 可以读取、修改或删除文件；组用户可以读取，但组外用户可以访问。从当前目录执行以下命令

```
ls -al testfile
```

显示文件 `testfile` 的权限：

```
-rw-r--r-- 1 guhas staff 2031 Nov 04 06:14 testfile
```

# drxws--- 3 guhas staff 1536 Nov 4 06:00 testdir

在 testdir 目录中还有一个名为 testfile 的文件，其权限如下：

```
-rwxr---- 1 guhas staff 2000 Nov 4 06:10 testfile
```

这意味着 `guhas`组可以读取、修改和重命名目录内的文件和目录。`staff` 组的任何成员都对该目录拥有所有权限。testfile 文件仅对 `staff` 组的所有成员设置读取权限。然而，由于 `staff` 组的所有成员对 `testdir` 具有读、写、执行权限，任何属于 `staff` 组的成员都可以修改、删除和重命名 testfile 文件。

> 如果用户对包含文件的目录具有写权限，则该目录内文件的权限将被目录的权限所覆盖。

权限（针对所有者、组和其他人）在 UNIX 系统中以八进制数存储。八进制数在 UNIX 系统中使用三个位进行存储，因此每个数字的范围从 0 到 7。以下是八进制数的存储方式：

- 第 1 位，0 或 1（定义读取权限）
- 第 2 位，0 或 1（定义写入权限）
- 第 3 位，0 或 1（定义执行权限）

第一位（读）的权重为 4，第二位（写）的权重为 2，第三位（执行）的权重为 1。例如，值 101 将是 5。（101 的值为 (4 * 1) + (0 * 1) + (1 * 1) = 5。）

让我们看看如何使用八进制数来定义权限。例如，你可能想为当前目录下的 testfile 文件定义以下权限：

- 所有者读、写、执行
- 组读取和执行
- 其他人——完全没有访问

这可以这样定义（使用二进制算术）：

- 所有者 111 = 7
- 组 101 = 5
- 其他人 000 = 0

因此，testfile 的权限为 750。

某些版本的 UNIX 提供了一个名为“粘滞位”（sticky bit）的额外位作为目录权限的一部分。粘滞位的作用是仅允许目录的所有者、文件的所有者或 root 用户删除和重命名文件。

以下是设置目录和文件权限的惯例。对于隐私信息，权限应设置为 700。你将对目录或文件拥有读、写和执行权限。

如果你想让信息公开，但希望自己是唯一可以发布该信息的人，请将权限设置为 755。其他人将没有写入权限，也没有人能够更新文件或目录。

如果你不希望你或你的组以外的任何人访问信息，请将“其他人”的权限设置为 0。权限可以是 770 或 750。

以下是一个设置权限以拒绝特定组的访问权限的示例。假设当前目录下有一个名为 testdir 的目录，它由一个名为 outsider 的组所有。如果你在当前目录下执行以下命令，outsider 组将无法对 testdir 任何任何功能操作：

```
chmod 705 testdir
```

## 默认权限：`umask`

当用户登录到 UNIX 系统时，她将获得一个默认权限。创建的所有文件和目录都具有由 `umask` 定义的权限。

你可以通过执行以下命令来查看你拥有的默认权限：

```
umask
```

它可能会显示以下结果：

```
022
```

`umask` 以数字存储并显示，从 777 中减去。022 意味着默认权限为：

```
777 - 022 = 755
```

也就是说，所有者可以读、写、执行；组可以读取和执行；其他人也可以读取和执行。

默认的 `umask` 通常由系统管理员为所有人设置，但可以根据你的需要进行修改。你可以通过执行带参数的 `umask`（该参数即你想要的掩码）来实现这一点。例如，如果你希望默认权限具有读、写、执行（7）；组具有读、写（5）；以及其他人仅具有执行（1），则 `umask` 必须设置为 777 - 751 = 026。你将如下所示执行命令：

```
umask 026
```

## 修改权限：`chmod`

你刚刚看到了如何为文件和目录设置默认权限。有时，你可能需要修改文件或目录的现有权限以适应你的需求。更改权限的原因可能是你想授予或拒绝一个或多个个体的访问权限。这可以使用 `chmod` 命令完成。

通过 `chmod`，你指定了在文件或目录上想要的新权限。新权限可以使用以下两种方式之一指定：

- 三位数字八进制代码
- 符号模式

你已经熟悉八进制模式了。如果你想让 testfile 文件允许所有者读、写、执行；允许组读取；允许其他人执行，则你需要执行以下命令：

```
chmod 741 testfile
```

使用符号模式时，请指定以下内容：

- 谁的（所有者、组或其他人）
- 什么（+ 添加，- 减去）
- 操作（r, w, x）

例如，如果你想让 testfile 允许所有者读、写、执行；组读取；其他人执行，你可能需要执行以下命令：

```
chmod 741 testfile
```

在使用符号模式时，请指定以下内容：

- 谁的（所有者、组或其他人）
- 什么（+ 添加，- 减去，= 等于）
- 操作（r, w, x）

例如，如果你想让 testfile 允许所有者读、写、执行；组读取；其他人执行，你可能需要执行以下命令：

```
chmod 741 testfile
```

## 修改所有者和组：`chown` 和 `chgrp`

你刚刚看到了如何为文件和目录设置默认权限。有时，你可能需要修改文件或目录的现有权限以适应你的需求。更改权限的原因可能是你想授予或拒绝一个或多个个体的访问权限。这可以使用 `chmod` 命令完成。

如果你想更改文件或目录的所有者，可以使用 `chown` 命令。注意：在具有磁盘配额的 Unix 系统上，只有 root 用户可以更改所有者。

如果 testfile 属于 guhas，要将其所有改为 friend，你需要执行以下命令：

```
chown friend testfile
```

如果你想更改文件所属的组，可以使用 `chgrp` 命令。该组必须是所有者的主组或附加组。假设 guhas 拥有 testfile，文件组为 staff。此外has 属于 staff 和 dev 组。要将 testfile 的组改为 dev，执行以下命令：

```
chgrp dev testfile
```

## Setuid 和 Setgid

当你执行程序时，需要假设不同的用户或组身份。在 UNIX 中，可以对执行文件设置设置用户 ID（setuid），使得当你执行它时，将假设所有该文件的用户的身份。如果你正在执行一个名为 testpg 的文件，它由 specialuser 所有，在程序执行期间你将假设 specialuser 的身份。同样，如果对执行文件设置了组 ID（setgid），该文件将导致你在程序执行期间假设该文件所属组的身份。

这里是 SET USER ID 使用的一个示例。假设你想让夜间操作员对系统所有文件进行备份。这通常是由 root 用户完成的。创建一个设置了 SET USER ID 位的备份程序。然后，夜间操作员就可以执行该程序并假设 root 的身份。

## 总结

本章讨论了什么是文件、各种类型的文件以及如何在不同目录中组织文件。你学习了如何定义文件和目录的权限。你还查看了一些用于文件的命令，例如 `ls` 列出文件及其详情、`chmod` 修改文件和目录的权限、`chown` 更改文件或目录的所有者、`chgrp` 更改文件的组所有、`umask` 显示和更改用户的默认权限设置，以及 `du` 或 `df` 查看磁盘空间利用率。你将在第 5 章中学习更多各种 UNIX 命令。

## 通用命令

作者：Sanjiv Guha

UNIX 既有原生的命令，也有由你（或你安装处的人员）编写的命令。取决于你运行的 UNIX 版本以及你所处的 shell，命令会有所不同。在本章中，将讨论在大多数 UNIX 版本中都存在的命令。每个命令都可以关联有多个标志（flags）。命令的通用格式为：

```
command [flags] [argument1] ...
```

标志以连字符开头。多个标志可以只用一个连字符一起指定。例如，以下两个命令是等价的：

```bash
ls -a -l
ls -al
```

根据命令的不同，参数可以是可选的或强制的。所有命令都接受来自标准输入（stdin）的输入，在标准输出（stdout）显示输出，并在标准错误（stderr）显示错误信息。你可以使用重定向来重定向其中或多个。标准输入是 UNIX 获取命令输入的地方，标准输出是 UNIX 显示命令输出的地方，标准错误是 UNIX 显示执行命令时产生的任何错误的地方。

所有命令在执行成功时都会返回零返回码。然而，如果命令执行失败或部分成功，它们会返回非零返回码。返回码可以作为 shell 脚本中控制逻辑的一部分。

> 注意：这里讨论的命令在大多数 UNIX 系统上通通用，但与每个命令关联的标志的行为可能有所不同。你应该使用系统上的 `man` 命令来了解命令及其标志的细节。

## 用户相关命令

接下来的章节将讨论与登录和退出系统相关的命令。用户相关命令是指用于登录和退出你的 UNIX 系统的命令。它们在不同系统之间可能略有不同，但这里讨论的命令在大多数系统中是通用的。

```bash
login
```

如果远程主机没有设置密码，只要满足上述定义的条件，`login` 将允许你使用任何密码登录。然而，不建议设置没有密码的用户。当你退出远程主机时，你将回到本地主机。

**示例** 这是一个 `login` 命令的示例，其中未指定用户 ID。执行以下命令将提示你输入密码（如果需要的话），输入正确的密码将允许你进入远程主机：

```bash
login box2
```

在这种情况下，假设远程主机的用户 ID 与本地主机登录用户的用户 ID 相同。例如，如果 tester 当前登录在 box1 上，UNIX 将假设你正尝试在 box2 上登录 tester。

然而，如果你的用户 ID 在 box2 上与 box1 上不同，你可以使用 `login` 命令的另一个选项：

```bash
login box2 -l testusernew
```

在此选项中，你告诉 `login` 用于远程主机的用户 ID 为 `testusernew`。

## `telnet`

如果你正处于一个与多个联网的 UNIX 计算机工作的环境中，你可能经常需要在不同的机器之间工作。`telnet` 命令为你提供了一种机制，让你可以在不退出当前环境的情况下，从当前系统登录到其他计算机。`telnet` 命令与之前介绍的 `login` 命令类似。

`telnet` 的主机名是可选的。如果你不使用主机名作为命令，你将进入 `telnet>` 提示符，通常是 `telnet`。当你处于 `telnet>` 提示符时，有许多子命令可用。其中一些子命令如下：

- `exit`：如果之前使用 `open` 子命令连接到远程主机，则关闭当前连接并返回 telnet 提示符。然而，如果执行 `telnet` 时带了主机名参数，连接将关闭并将你返回到调用 `telnet` 命令的地方。
- `display`：显示操作参数。
- `open`：打开与主机的连接。参数可以是主机名或地址。如果你提供了错误的名称或地址，`telnet` 将返回错误消息。
- `quit`：退出 telnet。
- `set`：设置操作参数。
- `status`：打印状态信息。
- `toggle`：切换操作参数（输入 `?` 查看更多信息）。
- `?`：打印帮助信息。

**示例** 假设你正在两台联网的计算机 box1 和 box2 上工作。如果你当前登录在 box1 上，你可以执行以下命令登录 box2：

```bash
telnet box2
```

作为对该命令的响应，box2 将返回登录界面，你可以在其中输入 box2 的用户 ID 和密码进行登录。在 box2 上完成工作后，你可以返回 box1。

## `passwd`

正如你所见到的，每当你尝试登录计算机系统时，系统都会要求你输入用户 ID 和密码。虽然可以设置没有密码的用户，但大多数用户都会有一个密码，并在登录计算机系统时使用它。
