## 9.7 同步重读

源自 `filemap_get_pages()` 执行的读取（源自缓冲区读取范围，因此涉及多个 folio）与源自 `filemap_fault()` 的读取（包含对单个 folio 发生缺页异常的调入）之间存在显著差异。

我们首先检查两者中概念上更简单的——由 `filemap_fault()` 处理的文件支持页缺页异常。如果在这里发生了主缺页，我们将通过 `do_sync_mmap_readahead()` 执行同步重读，我们在代码列表 9-63 中检查该函数（不包括超出范围的透明巨页处理）。

```c
/*
 * 同步重读发生在我们完全没有在页缓存中找到页时。
 * 我们不想在映射 mapping 锁下执行 I/O，因此如果我们
 * 必须释放 mm 锁，我们会返回为了执行该操作而固定的
 * 文件。如果我们没有固定文件，则返回 NULL。返回的
 * 文件在使用完毕后需要调用 fput()。
 */
static struct file *do_sync_mmap_readahead(struct vm_fault *vmf)
{
    struct file *file = vmf->vma->vm_file;
    struct file_ra_state *ra = &file->f_ra;
    struct address_space *mapping = file->mapping;
    DEFINE_READAHEAD(ract, file, ra, mapping, vmf->goff);
    struct file *fpin = NULL;
    unsigned long vm_flags = vmf->vma->vm_flags;
    unsigned int mmap_miss;

    /* 如果我们不需要任何预读，就别麻烦了 */
    if (vm_flags & VM_RAND_READ)
        return fpin;

    if (!ra->ra_pages)
        return fpin;

    if (vm_flags & VM_SEQ_READ) {
        fpin = maybe_unlock_mmap_for_io(vmf, fpin);
        page_cache_sync_ra(&ract, ra->ra_pages);
        return fpin;
    }

    /* 如果不需要，则缓存缓存行 */
    mmap_miss = READ_ONCE(ra->mmap_miss);
    if (mmap_miss < MMAP_LOTSAMISS)
        WRITE_ONCE(ra->mmap_miss, ++mmap_miss);

    /*
     * 我们在这个文件中缺失次数多于命中吗？如果是，
     * 停止预读。这只会适得其反。
     */
    if (mmap_miss > MMAP_LOTSAMISS)
        return fpin;

    /* mmap-around */
    if (vm_flags & VM_SEQ_READ) {
        fpin = maybe_unlock_mmap_for_io(vmf, fpin);
        page_cache_sync_ra(&ract, ra->ra_pages);
        return fpin;
    }

    // ... 剩余逻辑
}
```

每当缓存命中时（即文件内部发生次要缺页），此计数器就会减 1。这发生在 `do_async_mmap_readahead()` 中。

否则，我们在最大读头大小范围内指定读头，并以文件中页缺页异常的偏移量为中心，必要时对齐到文件开头。与顺序情况一样，我们在按照如列表 9-77 所示通过 `page_cache_ra_order()` 继续执行读头之前，与 `mmap_for_io()` 不同，我们会尝试释放掉 `struct mm->mmap_lock` 结构体。

## 9.7.1.5 强制读头 (Forced Readhead)

当禁用预读时，我们通过 `force_page_cache_ra()` 执行简单的强制读头，如列表 9-66 所示。

```c
/*
 * 将读头划分为兆字节单元，以便不会锁定过多内存。
 */
void force_page_cache_ra(struct readahead_control *ractl,
    unsigned long nr_to_read)
{
    struct address_space *mapping = ractl->mapping;
    struct file_ra_state *ra = ractl->ra;
    struct backing_dev_info *bdi = inode_to_bdi(mapping);
    unsigned long max_pages, index;

    if (unlikely(mapping->a_ops->readahead && !mapping->a_ops->folio)) {
        return;
    }

    /*
     * 如果请求超过预读窗口，则允许预读达到
     * 最佳 IO 大小
     */
    index = readahead_index(ractl);
    max_pages = min_t(unsigned long, bdi->io_pages, ra->ra_pages);
    nr_to_read = min_t(unsigned long, nr_to_read, max_pages);

    while (nr_to_read) {
        unsigned long this_chunk = (2 * 1024 * 1024) / PAGE_SIZE;
        if (this_chunk > nr_to_read)
            this_chunk = nr_to_read;
        ractl->index = index;
        do_page_cache_ra(ractl, this_chunk, 0);
        index += this_chunk;
        nr_to_read -= this_chunk;
    }
}
```

列表 9-66: `mm/readahead.c`: `force_page_cache_ra()`

这抽象了 `struct address_space->a_ops` 地址空间操作，如果 `struct address_space_operations` 缓存对象没有指定 `readahead()` 或 `folio` 回调（当执行预读时若未指定前者则使用后者作为备选），则在该情况下简单无法继续。

否则，简单的读头将继续执行直到所有请求的页面都被预读。

## 9.7.2 异步预读 (Asynchronous Readahead)

当发生次缺页（minor fault）时，会执行异步预读，即在页异常或 `read()` 强制读取时发现了页缓存条目，且最新的 folio 设置了 `PG_readahead` 标志。

该标志由同步或异步预读逻辑在 folio 上设置，用以触发后续缺页之前的预读（从而使预读操作交错进行）。请注意，在预读发生时，该标志在已经存在于页缓存中的任何 folio 上都不会存在。

当 `filemap_get_pages()` 中发生由 `read()` 强制触发的次缺页操作（见上文列表 9-44）时，会调用 `filemap_readahead()` 来处理异步预读，我们在列表 9-67 中分析该函数。该函数仅在 folio 上设置了 `PG_readahead` 标志时才会被调用。

```c
static int filemap_readahead(struct ioc *ioc, struct file *file,
    struct address_space *mapping, struct folio *folio,
    pgoff_t last_index)
{
    DEFINE_READAHEAD(ract, file, &file->f_ra, mapping, folio->index);
    if (ioc->flags & IOC_NOAGAIN)
        return -EAGAIN;
    page_cache_async_ra(ract, folio, last_index - folio->index);
    return 0;
}
```
