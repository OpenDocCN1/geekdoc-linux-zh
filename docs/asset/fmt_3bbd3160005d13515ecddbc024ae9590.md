CVS 允许多个开发者协作进行源代码项目，并以一种相当合理的方式维护大型代码库。CVS 的内部安全机制本身相当简单（有些人甚至认为很薄弱），我对此赞同这一观点。CVS 的身份验证通常通过 `pserver` 在网络上实现，用户名以明文发送，而密码经过了简单的哈希处理（没有任何安全性可言）。为了绕过这个问题，你有几个很好的选择。在 Unix 环境中，可能最简单的方法是使用 `SSH` 在客户端和服务器之间建立隧道连接，“Time Wemaster” (Tim Hemel) 编写了一篇涵盖该内容的优秀文章，我没打算重新整理它，你可以在此处找到：http://cubic.xa4.nl/~cvs/。另一种稍微复杂一点（但从长远来看对于大型安装更好）是将 CVS 服务器和客户端 Kerberos 化，类型大型网络（特别是大学环境）已经建立了 Kerberos 基础设施。关于对 CVS 进行 Kerberos 化，可以在此处找到信息：http://www.cyclic.com/cyclic-pages/security.html。除外，我强烈建议对 CVS 使用防火墙，除非你将其用于某些公共目的（例如跨越互联网的开源项目）。

另一个新出的保护 CVS 的工具是 "cvsd"，它是 `pserver chroot` 和/或将 `suid` 指向一个无害用户的封装器，cvsd 可以在此处获取：http://chblack.mokey.com/cvsd/，提供 rpm 格式和源码 tar 包。

还有其他你应该注意的明显问题，在处理源代码时，你应该确保没有木马程序或后门被替换。在开源项目中，这相对简单：审查人们提交的代码，特别是如果这是一项公开访问的工作，并确保你有备份。CVS 使用端口 2401`tcp`。

```
ipfwadm -I a accept -P tcp -S 10.0.0.0/8 -D 0.0.0.0/0 2401
ipfwadm -I a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 2401
ipfwadm -I a deny -P tcp -S 0.0.0.0/0 -D 0.0.0.0/0 2401
```

`rsync` 是一种极其高效的文件镜像方法，无论是是 CVS 树的源代码文件、网站，甚至是本文，`rsync` 都能保留文件权限、链接、文件时间，此外，它还支持匿名模式（顺便提一下我用它来镜像本文），这让所有相关人的生活变得非常容易。`rsync` 程序本身可以作为客户端（通过命令行或脚本）也可以作为服务器（通常运行在 `inetd` 中）。该程序相当安全，作为客户端或服务器都不需要 `root` 权限（除非你真的想要，并且可以选择任何被镜像内容的根目录，但这需要 `root` 权限并且可能比其价值更危险）。你也可以映射访问访问系统的用户 ID 和组 ID（对于预编译的 rsync 包，默认是 `nobody`，这可能是最好的选择）。在非匿名模式下，`rsync` 支持用户名和密码，这些密码使用 128 位 MD4 进行加密。“rsync.conf” 页面清楚地将 `rsync` 设置为服务器并使其运行较快。默认配置文件是 `/etc/rsync.conf`，包含一个全局部分和模块部分（每个共享输出目录都是一个模块）。

rsync 示例：

```
motd file = /etc/rsync.modt # 指定要显示的文件，法律
免责声明，等
max connections = 5      # 最大连接数，防止你被流量淹没
[pub-ftp]
    comment = public ftp area # 简单注释
    path = /home/ftp/pub     # 目录路径
    read only = yes          # 设置为只读，非常适合导出
    chroot = yes             # chroot 到 /home/ftp/pub
    uid = nobody             # 显式设置 UID
    gid = nobody             # 显式设置 GID
[secret]
    comment = my stuff # 我的东西的路径
    path = /home/user/secret
    list = no               # 在请求时隐藏此模块
    secrets file = /etc/rsync.users # 密码文件
    auth = bob   # 查看我内容的的用户列表
    hosts = 1.1.1.1, 2.2.2  # 允许的主机列表
```

如你所见，`rsync` 是可配置的且通常是，异常是实际传输没有以任何方式加密。如果你需要免费方案，建议使用 `SSH` 建立隧道连接，或者某些 VPN 解决方案如 WAN。还要确保你运行的是 `rsync 2.3.x`，或者在 2.2.x 中发现了潜在漏洞。`Rsync` 可以在此处获取：http://rsync.org/。`Rsync` 运行在端口 873`tcp`。
