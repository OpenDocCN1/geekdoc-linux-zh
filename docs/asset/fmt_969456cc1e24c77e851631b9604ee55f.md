```
userid@userid ON gateway
```

### GEnie
GEnie 是通用电气（General Electric）的商业信息服务。

来自 Internet（From）：使用标准的 Internet 地址格式：

```
userid@genie.com
```

示例：`jjones@genie.com`

发往 Internet（To）：使用带有后缀的标准 Internet 地址格式：

```
userid@domain@INET#
```

示例：`bsmith@wubba.edu@INET#`

### Gold 400
Gold 400 是英国电信（British Telecom）的商业 X.400 服务。

来自 Internet（From）：使用以下地址格式：

```
userid@org_unit.org.prmd.gold-400.gb
```

你需要获取收件人的 `userid`、`org_unit`（组织单元）、`org`（组织）和 `prmd`（私邮件域）。

示例：`jjones@foo.bar.baz.gold-400.gb`

发往 Internet（To）：同样请参“X.400 编码”章节查看如何处理地址中的非标准字符，其格式如下：

```
/DD.RFC-822=userid(a)domain%/O=uknet/PRMD=uk.ac/ADMD=gold 400/C=GB
```

示例：`/DD.RFC-822=bsmith(a)wubba.edu/O=uknet/PRMD=uk.ac/ADMD=gold 400/C=GB`

### KeyLink
KeyLink 是澳大利亚电信（Telecom Australia）的商业 X.400 服务。

来自 Internet（From）：使用以下地址格式：

```
userid@org_unit.org.telemememo.au
```

你需要收件人告知他们的 `userid`、`org_unit`（组织单元）和 `org`（组织）。在这种情况下可能不使用 `org_unit`，请删除它以及其随后的点。

示例：`jjjones@frobez.grue.telemememo.au`

要获取地址，请参阅“X.400 编码”章节查看如何处理地址中的非标准字符，但这是通用格式：

```
(C:au,A:telememo,P:oz.au,"RFC-822":"name <userid(a)domain>")
```

`name` 实际上并不用于投递，仅作为注释。

示例：`(C:au,A:telememo,P:oz.au,"RFC-822":"Bubba Smith <bsmith(a)wubba.edu>")`

# MCI Mail
MCI Mail 是 MCI 的商业电子邮件服务。

来自 Internet（From）：有几种选择。每个 MCI 用户都有一个名字（Jim Jones）和一个。

来自 Internet（From）：使用标准的 Internet 地址格式：

```
userid@prodigy.com
```

示例：`jjones@prodigy.com`

发往 Internet（To）：使用带有后缀的标准 Internet 地址格式：

```
userid@domain@INET#
```

示例：`bsmith@wubba.edu@INET#`

发送邮件涉及三个主要组件。首先是链路层传输层。紧接传输层之上的是邮件传输代理（MTA）。该层负责邮件消息的移动和递送。MTA 包含多个组件，包括路由机制、本地递送代理和远程递送代理。UNIX 系统的 MTA 是 `sendmail` 程序。那些擅自修改消息内容的 MTA 被称为敌性 MTA（hostile MTA）。最后，用户代理（MUA）提供界面。它允许你读取、发送和转发邮件消息。这通常就是人们在谈论“邮件程序”时所指的内容。

有很多邮件程序可以选择。下一节将介绍它们共同拥有的元素。

## 你的邮件文件

通常情况下，你在处理邮件的任何计算机上都有一个邮件账户。你甚至可以对该账户进行邮件以外的其他操作，但目前这并不重要。对于你的新邮件（称为入站邮件），它们被保存在我们所谓的“邮件暂池文件”（mail spool file）中。你通常会查看暂池文件，并在有新邮件时收到通知。这是你运行邮件程序的线索。
