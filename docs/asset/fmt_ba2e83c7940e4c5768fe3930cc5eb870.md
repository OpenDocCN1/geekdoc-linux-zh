
`memmove(dst, src, count)`

从 `src` 拷贝字节到 `dst`。`src` 和 `dst` 或是表示内存地址的整数，或是可以转换为指针的 ctypes 类型实例。与 C 库函数 `memmove()` 相同。

`memset(dst, src, count)`

将从 `dst` 开始的 `count` 个内存单元设置为字节值 `c`。`dst` 或是整数或 ctypes 实例。`c` 是一个表示 0–255 范围内字节的整数。

`resize(cobj, size)`

调整用于表示 ctypes 对象 `cobj` 的内部内存的大小。`size` 是以字节为单位的新大小。

`set_conversion_mode(encoding, errors)`

设置将 Unicode 字符串转换为 8 位字符串时使用的 Unicode。`encoding` 是编码名称（如 'utf-8'），`errors` 是错误处理策略（如 'strict' 或 'ignore'）。返回包含之前设置的元组 `(encoding, errors)`。

## 示例

下面的示例通过构建 C 函数的接口，说明了 `ctypes` 模块的使用，在本章的第一部分部分介绍了手动创建 Python 扩展模块的细节。

```python
# example.py
import ctypes
_example = ctypes.CDLL("./libexample.so")

# int gcd(int, int)
gcd = _example.gcd
gcd.argtypes = (ctypes.c_int, ctypes.c_int)
gcd.restype = ctypes.c_int

# int replace(char *s, char oldch, char newch)
replace = _example.replace
replace.argtypes = (ctypes.c_char_p, ctypes.c_char, ctypes.c_char)
replace.restype = ctypes.c_int

# double distance(Point *a, Point *b)
class Point(ctypes.Structure):
    _fields_ = [("x", ctypes.c_double),
                ("y", ctypes.c_double)]

distance = _example.distance
distance.argtypes = (ctypes.POINTER(Point), ctypes.POINTER(Point))
distance.restype = ctypes.c_double

if __name__ == "__main__":
    p1 = Point(0.0, 0.0)
    p2 = Point(3.0, 4.0)
    print(distance(ctypes.byref(p1), ctypes.byref(p2)))
```

作为输出，它会生成一组 .c 和 .py 文件。然而，你通常不需要担心这个问题。如果你在使用 `distutils` 并在设置规范中包含一个 .i 文件，那么在构建扩展模块时，它会自动运行 SWIG。例如，这个 `setup.py` 文件会自动对列出的 `example.i` 文件运行 SWIG。

```python
# setup.py
from distutils.core import setup, Extension
setup(name="example",
    version="1.0",
    py_modules=['example.py'],
    ext_modules={
        Extension("example",
            ["example.i","example.c"])
    }
})
```

事实证明，该文件和 `setup.py` 文件就是示例中一个可工作扩展模块所需的全部内容。如果你输入 `setup.py build_ext --inplace`，你会在目录中发现一个完全可以工作的扩展模块。

## Jython 和 IronPython

扩展并不限于 C 程序。如果你正在使用 Java，可以考虑使用 Jython (http://www.jython.org)，它是在 Java 中对 Python 解释器的完全重新实现。通过 Jython，你可以简单地使用 `import` 语句导入 Java 库。例如：

```bash
bash-3.2 jython
Jython 2.2.1 on java_1.5.0_16
Type "copyright", "credits" or "license" for more information.
>>> from java.lang.System
>>> System.out.println("Hello World")
Hello World
>>>
```

在 Windows 上使用 .NET 框架，可以考虑使用 IronPython (http://codeplex.com/Wiki/View.aspx?ProjectName=IronPython)，它是用 C# 对 .NET 框架的完全重新实现。通过 IronPython，你可以以类似的方式从 Python 访问所有的 .NET 库。例如：

```python
# ip
IronPython 1.1.2 (1.1.2) on .NET 2.0.5072.42
Copyright (c) Microsoft Corporation. All rights reserved.
>>> import System.Math
>>> dir(System.Math)
['Abs', 'Acos', 'Asin', 'Atan', 'Atan2', 'BigMul', 'Ceiling', 'Cos', 'Cosh', ...]
>>> System.Math.Cos(3)
-0.9899924966
>>>
```

更详细地介绍 Jython 和 IronPython 超出了本书的范畴。然而，只需记住，它们都是 Python——主要的区别在于它们的库。

## Python 3

2008 年 12 月，Python 3.0 发布了——这是 Python 语言的一次重大更新，它在许多关键领域上破坏了与 Python 2 的向后兼容性。关于对 Python 3 所做更改的相当完整的调查，可以在 http://docs.python.org/3.0/whatsnew/3.html 上的“Python 3.0 新特性”文档中找到。从某种意义上说，本书的前 26 章可以看作是“新特性”的对立面。也就是说，到目前为止的所有材料都集中在 Python 2 和 Python 3 有的特性上。这包括所有的标准库模块、主要的语言特性，而且除了少数微小的差异以及 `print()` 是一个函数事实外，没有描述任何 Python 3 的特有特性。

本附录的主要重点是描述仅在版本 3 中提供的 Python 语言新特性，以及在迁移现有代码时需要注意的重要区别。在附录末尾，描述了一些策略以及 `2to3` 转换工具的使用。

### 谁应该使用 Python 3？

在继续下去之前，解决谁应该使用 Python 3.0 版本的问题是非常重要的。在 Python 社区中，人们一直认为向 Python 3 的过渡将在一夜之间发生，并且 Python 2 分支将在未来相当长的时间（几年）继续维护。因此，截至写此书时，没有迫切需要放弃 Python 2。我怀疑，当多年后这本书的第 5 版编写时，仍会有大量的 Python 2 继续在开发中。
