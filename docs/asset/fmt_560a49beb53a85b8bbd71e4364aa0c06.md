
```
*p = (target - baseaddr); /* 将偏移量存放在 *p 中 */
```

在解引用这些指针时，我们反上述步骤：

```
target = baseaddr + *p; /* 解释偏移量 */
```

在这里，我们假设在每个进程中，`baseaddr`指向共享内存段的起始位置（即它是`shmat()`返回的值）。基于此假设，无论共享内存段挂载在进程虚拟地址空间的何处，偏移量都能被正确地解释。

或者，如果我们正在链接一组固定大小的结构，可以将共享内存段（或其部分）强制转换为数组，然后使用数字作为从一个结构引用到另一个结构的“指针”。

## 48.7 共享内存控制

`shmctl`系统调用对由`shmid`标识的共享内存段执行一系列控制操作。

```
#include <sys/types.h>
#include <sys/shm.h>

int shmctl(int shmid, int cmd, struct shmid_ds *buf);
```

成功返回`0`，错误时返回`-1`。`cmd`参数指定要执行的操作。除`IPC_STAT`外，`buf`参数是必须的。

### 通用控制操作

`shmctl()`可用以下操作：

- `IPC_LOCK`：将共享内存段锁定内存中。
- `IPC_UNLOCK`：解锁共享内存段，允许其被交换出。

这些操作未由SUS指定，且并非所有UNIX实现中都提供。在Linux 2.6.10之前的版本，只有特权进程（`CAP_IPC_LOCK`）可以锁定共享内存段。从2.6.10开始，如果有效用户ID所有者或创建者且具有足够的`RLIMIT_MEMLOCK`限制，普通进程也可以锁定和解锁共享内存段。

锁定共享内存并不保证所有页面都在内存中。相反，非内存页只有在被连接的段加载内存时才会单独锁定。加载内存是指当进程引用该页面时会发生页异常。此时，如果页面在交换区域，则会将其重新加载到内存中；如果是第一次被引用，则交换文件中没有相应的页面。因此，内核会分配新的物理内存并调整进程页表以及共享内存段的记录数据结构。一旦锁定，页面将一直留在内存中，直到随后被解锁，即使所有进程都断开了该段。

- `IPC_STAT`：将`shmid_ds`数据结构的副本放入`buf`指向的缓冲区。
- `IPC_SET`：更新`buf`指向的缓冲区中`shmid_ds`结构的选定字段。

另一种锁定内存的方法语义略有不同是`mlock()`，我们在第50.2节中进行了描述。

### 共享内存关联数据结构

每个共享内存段都有一个关联的`shmid_ds`数据结构：

```
struct shmid_ds {
    struct ipc_perm shm_perm;   /* 所有权和权限 */
    size_t shm_segs;             /* 段的大小（字节） */
    time_t shm_atime;            /* 上次 shmat() 的时间 */
    time_t shm_dtime;            /* 上次 shmdt() 的时间 */
    time_t shm_ctime;            /* 最后更改的时间 */
    pid_t shm_cpid;              /* 创建者的 PID */
    pid_t shm_lpid;              /* 上次 shmat() / shmdt() 的 PID */
    shatt_t shm_natch;           /* 当前连接的进程数 */
};
```

SUSv3要求此处显示的所有字段。其他某些UNIX实现在`shmid_ds`中还包含额外的非标准字段。

`shmid_ds`的字段由各种共享内存系统调用隐式更新，`shm_perm`字段的某些子字段可以通过`shctl()`的`IPC_SET`操作显式更新。详细信息如下：

#### shm_perm

当按照第45.3节描述创建共享内存段时，`uid`、`gid`以及`mode`字段的其他9位可以通过`IPC_SET`更新。除了通常的权限位外，`shm_perm_mode`字段还包含两个只读掩码标记。其中第一个`SHM_DEST`（删除）表示当所有进程都从其地址空间分离时（通过`shctl()` `IPC_RMID`操作），该段是否被标记为删除。另一个标记`SHM_LOCKED`表示该段是否被锁定在物理内存中（通过`shm()` `SHM_LOCK`操作）。这两个标记在SUSv3中均未标准化，等效项仅出现在少数其他UNIX实现中，在某些情况下名称不同。

#### shm_segs

在创建共享内存段时，此字段被设置为请求的段大小（字节），即在`shmget()`中指定的`size`参数的值。如第48.2节所述，共享内存按页为单位分配的，因此该段的实际大小可能大于此值。

#### shm_atime

当共享内存段创建时，该字段设置为`0`，并且每当进程附加该段（`shmat()`）时，设置为当前时间。该字段以及`shmid_ds`结构中的其他时间戳字段的类型为`time_t`，存储自Unix时间（Epoch）以来的秒数。

#### shm_dtime

当共享内存段创建时，该字段设置为`0`，每当进程分离该段（`shmdt()`）时，设置为当前时间。

#### shm_ctime

当段创建时以及每次成功执行`IPC_SET`操作时，该字段被设置为当前时间。

#### shm_cpid

此字段设置为使用`shmget()`创建该段的进程ID（PID）。

#### shm_lpid

当共享内存段创建时，该字段设置为`0`，并在每次成功执行`shmat()`或`shmdt()`时，设置为调用进程的进程ID。

此字段计算当前已附加该段的进程数。它在段创建时初始化为`0`，然后每次成功的`shmat()`都会加增。用于定义此内容的`shmatt_t`数据类型是一种无符号类型，SV3要求其大小至少与`unsigned short`一大。（在Linux上，它被定义为`unsigned long`。）

## 48.9 共享内存限制

大多数UNIX实现对System V共享内存实施了各种限制。以下是Linux共享内存限制列表。括号中是受限制影响的系统调用以及达到限制时产生的错误。

`SHMMI`

这是可以创建的共享内存标识符（换句话说，共享内存段）数量的系统级限制。(`shmget()`, `ENOSPC`)

`SHMMIN`

这是共享内存段的最小大小（字节）。该限制定义为`1`（无法更改）。然而，有效限制是系统页大小。(`shmget()`, `EINVAL`)

`SHMMAX`

这是共享内存段的最大大小（字节）。`SHMMAX`的实际限制取决于可用的RAM和交换空间。(`shmget()`, `EINVAL`)

`SHMALL`

这是共享内存总页数的系统级限制。大多数其他UNIX实现不提供此限制。`SHMALL`的实际限制取决于可用的RAM和交换空间。(`shmget()`, `ENOSPC`)

其他UNIX实现还实施了以下限制（该限制在Linux上未实现）：

`SHMSEG`

这是每个进程允许附加内存段数量的限制。

在启动时，共享内存限制被设置为默认值。（这些默认值可能随内核版本而异，且某些发行版的内核与原生内核提供的内核有所不同。）在Linux上，可以通过`/proc`文件系统中的文件查看或更改某些限制。表48-2列出了与每个限制对应的`/proc`文件。例如，以下是x86-32系统上Linux 2.6.31的默认值：

```
$ cd /proc/sys/kernel
$ cat shmni
```

```
$ cat shmmax
33554432
$ cat shmall
```

Linux特有的`shmctl()` `IPC_INFO`操作检索类型为`shminfo`的结构，其中包含各种共享内存限制的值：

```
shmctl(0, IPC_INFO, (struct shmid_ds *) &buf);
```

一个相关的Unix特有操作`SHM_INFO`检索类型为`shm_info`的结构，其中包含用于共享内存对象的实际资源的信息。此类SHM_INFO的示例可以在本书源码发行中的`svhm/svhm-info.c`文件找到。

关于`IPC_INFO`、`SHM_INFO`以及`shmino`和`shm_info`结构的细节可以在`shmctl(2)`手页中找到。

表48-2：System V共享内存限制

| 限制 | 边界值 (x86-32) | /proc/sys/kernel 中对应的文件 |
| :--- | :--- | :--- |
| SHMMI | 32768 (IPCM) | shmni |
| SHMMAX | 取决于可用内存 | shmax |
| SHMALL | 取决于可用内存 | shmall |
