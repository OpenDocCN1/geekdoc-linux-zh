
要检查文件系统的空闲 `inode` 数量，请使用 `df -i`。

如果 `inode` 耗尽，必须删除一些文件，即使还有可用磁盘空间。

类似于 `chmod`，对于 `chmod` 符号链接也存在类似的担忧：`chmod` 会解析（dereference）命令行中指定的符号链接（可能是由于通配符展开的结果），但不会解析在递归遍历目录时遇到的符号链接。这是另一个可能让系统管理员困扰的细微且令人难以无从的之处。

使用 `find` 命令时，你需要添加 `-f` 选项来跟踪符号链接——或者只需在命令行中列出的符号链接/目录末尾加上斜杠 `/`（强制 shell 在对“零长度”的结尾文件名进行 glob 展开时失败）。

正如人们所说，“魔鬼在细节中。”

## 损坏的数据

`fsck` 具有极佳的文件系统恢复能力，实际上，在对卸载的文件系统上运行多次时，它可以获得额外的成功。恢复的 `inode` 块将被放在恢复的目录 `/found+` 下，该目录存在于每个 `ext2` 类型的物理分区上。通过一个良好的十六进制或二进制查看器，即使原始文件无法恢复，你可能能够恢复有价值的数据。

如果你愿意投入精力进行此类恢复，可以考虑使用 `dd` 命令将整个磁盘分区的扇区级拷贝到另一个设备、磁带驱动器，或通过网络管道传输到 `ssh` 进程，并将其输出重定向到远程设备、分区或文件（如果你的远程文件系统支持足够容纳整个分区的大文件；记住 32 位 Linux 版本上有 2GB 的文件大小限制！）。

## 网络问题

本节涵盖了网络配置错误、误用或损坏时出现的问题。

## NIS 访问无法工作

修改 `/etc/nsswitch.conf` 读取：

```
passwd: compat
```

以使 `/etc/passwd` 中的 `+/-` 条目生效。

注意，`libc5` 使用的是 `/etc/hosts.conf` 而不是 `/etc/nsswitch.conf`，并且必须安装编译了 NIS 支持的 `libc5`。

另请参见第 21 章“管理 NIS”。

## 无法通过网络访问系统

检查 TCP wrapper 设置，该设置由 `/etc/hosts.allow` 和 `/etc/hosts.deny` 控制。应检查适用于该机器的其他防火墙方面，然后检查以太网或其他网络线以及其连接到网络的节点。

## 附录 A 紧急情况

也有可能是附近的系统正在泛洪网络连接。如果是这种情况，该网段上的几个邻居将受到随机影响，无论它们正尝试访问什么种的服务都没有影响。

## TCP 流量缓慢且/或不稳定

在末端或途中可能存在 ICMP 数据包的过滤问题。要阻止 ICMP ping，你可以执行类似以下的操作：

```
/sbin/ipfwadm -Ia accept -P icmp -S 0/0 0 3 11 12
/sbin/ipfwadm -Ia deny -P icmp
```

注意，类型 3 是用于路径 MTU 发现的！

这将接受这些 ICMP 类型：

- 0. echo reply，以便传出的 ping 正常

- 3. destination unreachable（目标不可达，用于路径 MTU 发现并消除对不存在的主机和域名的超时等待）

- 11. TTL exceeded（TTL 超，用于 traceroute）

- 12. IP parameter error（非常常见）

## 输入问题

许多应用程序都有为特殊功能选择自己的有效按键的功能。如果只有像 `emacs` 这样复杂的程序遇到困难，可以使用它自己的命令来提供更舒适的按键绑定。

查找此详细信息的地方是：`http://www.bbnet.nl/~anne/keyboard.html`

## 物理键盘上的按键失效

在大多数情况下，修复此问题的最佳方法是更换键盘。然而，如果你在这里，说明是紧急情况；在这种情况下，可以使用 `loadkeys` 在文本控制台上绕过问题，并在 X 会话中使用 `xmodmap` 将所需的按键重新映射到其他按键上。

## 退格键（Backspace）不起作用；而是生成控制字符

检查你正在使用的控制台的 `TERM` 变量是否设置正确。确保导出该变量，以便 shell 和子程序在环境环境中包含它。

如果设置正确，执行 `stty -erase` 命令并按下退格键，生成其控制代码作为第二个参数。现在退格键将被分配删除功能，将其从之前拥有该功能的任何按键（通常是 `DELETE` 或现在已罕见的 `RUB OUT`）上移除。如果你只使用一个终端，可以将更改提交到你的 shell 登录脚本中。

## 文字全部显示为二进制字符

最常见的原因是使用 `more` 或 `cat` 等简单实用工具读取二进制文件。终端接受了一个或多个二进制代码作为更改符号字体的命令；你现在可以轻松地读取它试图表达的内容。即使你看不见它，输入命令 `reset`，你的终端特性将恢复到默认值。在某些情况下，你可能需要运行两次命令。

## 系统似乎对我的按键没有响应

如果系统仍然可以通过网络访问，通过运行 `loadkeys -d` 恢复系统默认键位。此外，检查键盘是否连接正确，对于 PS/2 键盘，检查是否不小心交换了鼠标端口。

## 特定按键在 X 中不起作用

`xmodmap` 工具在重新映射键盘按键方面提供了很大的灵活性。它的主页包含实用的示例，例如交换 `CTRL` 和 `CAPS LOCK` 键等。然而，它只影响 X Window 会话。你需要使用 `loadkeys` 来影响控制台会话。

## X 似乎对我的按键没有响应

`xmodmap` 工具在重新映射键盘按键方面提供了很大的灵活性。它的主页包含实用的示例，例如交换 `CTRL` 和 `CAPS LOCK` 键等。然而，它只影响 X Window 会话。你需要使用 `loadkeys` 来影响控制台会话。

当 X 不响应按键时，会出现一些问题：

- 窗口管理器可能会混乱，导致所有输入被忽略
- 你可能无法通过 `CTRL-ALT-FX` 跳到另一个控制台
- 在极端的情况下，杀死 X 服务器将强制关闭打开的文件
- 使用 `ssh` 或 `telnet` 即可

## 杂项

当然，某些紧急情况无法很好归类。我们在这里列出了一些。

## 并行设备无法工作

在现代时代，可能有很多设备：ZIP 驱动器、打印机、扫描仪、CD 等。随着 `PAR` 团队对驱动的工作，有时可以让多个设备在端口上工作。但在旧系统中，或者为了安全起见，你将设备作为模块加载。使用 `lsmod` 检查加载的模块对于该设备是否正确。强烈建议不要在依赖这些设备的文件系统挂载时尝试卸载模块。

## 内存超过 64MB 时系统似乎变慢

这是由于某些芯片组设计无法缓存超过 64MB 的内存地址导致的。这个问题在 Linux 下被加剧，因为 Linux 从高地址向下分配内存。一些建议：更换主板或使用 `mem` 内核设置来限制内存使用。

## 内存增加后系统不稳定

某些系统（芯片组/BIOS）在内存“顶部”使用一小块地址空间。尝试使用 `mem=xxx` 内核设置，其中 `xxx` 比实际内存量少 1 兆。
