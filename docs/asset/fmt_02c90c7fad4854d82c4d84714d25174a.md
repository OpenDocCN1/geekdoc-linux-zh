    unsigned short length;

        char *mbs;

typedef unsigned long XIMFeedback;

`feedback` 成员预留以后使用。`string` 和 `length` 成员用于转换。长度以字符为单位。

## 重置状态

`XNResetState` 参数指定了调用 `XmbResetIC` 或 `XwcResetIC` 后输入上下文返回的状态。该值可以设置为 `XCreateIC` 时指定的初始状态，也可以设置为保留当前状态。

`XIMResetState` 的有效掩码如下：

```
typedef unsigned long XIMResetState;
#define XIMInitialState (1L)
#define XIMResetState (1L<<1)
```

如果设置了 `XIMInitialState`，`XmbResetIC` 和 `XwcResetIC` 将返回 IC 的初始 `XNResetState`。

如果设置了 `XIMResetState`，`XmbResetIC` 和 `XwcResetIC` 将保留当前状态。

如果未指定 `XNResetState`，默认值为 `XIMInitialState`。除上述指定的 `XIMResetState` 值外，其他默认为 `XIMInitialState`。

由于此 IC 值是可选的，客户端在使用在使用参数前应通过 `XGetValues` 设置。

# 热键

`XHotKey` 参数为 IC 指定了热键列表。热键列表是一个类型为 `XIMHotKeyTrigger` 的结构指针，指定了必须在不中断输入方法的情况下接收的按键。要使用热键列表参数，客户端必须将 `XHotKeyState` 设置为 `XIMHotKeyStateON`。

由于此 IC 值是可选的，客户端在使用此功能前应通过 `XGetValues` 设置。

参数的值指向 `XIMHotKeyTrigger` 结构。

如果发现了热键列表中的按键事件，进程将接收该事件并在客户端内部进行处理。

```
typedef struct {
    KeySym keysym;
    unsigned int modifier;
    unsigned int modifier_mask;
} XIMHotKeyTrigger;
```

```c
int num_hot_key;
XIMHotKeyTrigger *key;
} XIMHotKeyTriggers;
```

修饰符（`modifier`）与修饰符掩码（`modifier mask`）的组合用于表示修饰符的三种状态之一：修饰符必须关闭、修饰符必须开启、或者修饰符 `don't care`（忽略）——即它可以开启或关闭。当修饰符位设置为 0 时，在评估键是否为热键时，将忽略相关修饰符的状态。

| 修饰符位 | 掩码位 | 含义 |
|---|---|---|
| 0 | 1 | 修饰符必须关闭。 |
| 1 | 1 | 修饰符必须开启。 |
| n/a | 0 | 不管修饰符是开启还是关闭。 |

## 热键状态

`XNHotKeyArgument` 指定了输入法的热键状态。这通常用于在热键操作和普通输入处理之间切换输入法。

该参数的值指向一个类型为 `XIMHotKeyState` 的结构体。

```c
typedef unsigned long XIMHotKeyState;
#define XIMHotKeyON (0x0001L)
#define XIMHotKeyStateOFF (0x0002L)
```

如果未指定，默认值为 `XIMHotKeyStateOFF`。

## 预编辑和状态属性

`XNPreditAttributes` 和 `XNStatusAttributes` 指定了预编辑区域和状态区域的参数（如果有的话）。这些属性作为嵌套的可变列表传递给 `XSetICValues` 或 `XGetICValues`。这些列表中使用的名称在接后的章节中描述。

## 区域 (Area)

`XNArea` 参数的值必须指向一个类型为 `Rectangle` 的结构体。`XNArea` 的解释取决于已设置的输入法样式。

如果输入法为 `XIMPrePosition`，`XNArea` 指定了进行预编辑的裁剪区域。如果设置了焦点窗口（focus window），则坐标假设为相对于客户端窗口（client window）。否则，如果两者都未设置，结果将未定义。

如果未指定 `XNArea`，则将其设置为 NULL；如果无效，输入法将将裁剪区域设置为 `XFocusWindow`。如果指定的区域为 NULL 或无效，结果将未定义。

如果输入样式为 `XIMPreprintArea` 或 `XIMStatusArea`，`XNArea` 指定了客户端提供给输入法的几何结构。输入法可以使用此区域来显示其数据，取决于指定的区域是预编辑还是状态状态。输入法可以创建一个作为客户端窗口子节点的窗口，其尺寸适应 `XNArea`。坐标相对于客户端窗口。如果未设置客户端窗口，输入法应保存这些值并在设置客户端窗口时应用它们。如果未指定 `XNArea`，则将其设置为 NULL；或者结果将未定义。

## 所需的区域 (Area Needed)

当设置时，`XNAreaNeeded` 参数指定了客户端为此区域建议的几何结构，类型为 `Xrectangle` 结构体。注意，`x`、`y` 值不被使用，宽度或高度的非零值是客户端希望输入法遵守的约束条件。

当读取时，`XNAreaNeeded` 参数指定了输入法对该区域所需的理想几何结构。

这仅在输入样式为 `XMIPreditArea` 或 `XMIStatusArea` 时才有效。它用于客户端和输入法之间的几何结构协商，对输入法没有影响（参见第 13.5.1.5 节）。

## 光标位置 (Spot Location)

`XNSpotLocation` 参数向输入法指定了光标坐标，当输入法在 `XNAnimationStyle` 设置为 `XMIPreditPosition` 时执行时有效。当指定给除 `XMIPreditPosition` 以外的任何输入法时，此 `XIC` 值将被忽略。

`x` 坐标指定了下一个字符插入的位置。`y` 坐标是焦点窗口中当前文本行的基线位置。如果已设置焦点窗口，则 `x` 和 `y` 坐标相对于焦点窗口；否则，它们相对于客户端窗口。如果焦点窗口和客户端窗口均未设置，结果将未定义。

该参数的值指向一个类型为 `Xpoint` 的结构体。

## 调色板 (Colormap)

可以使用两个参数来指示输入法应该使用什么调色板分配颜色：调色板 ID 或标准调色板名称。

`XNColormap` 用于指定调色板 ID。参数的值类型为 `Colormap`。当输入法使用无效参数时，可能会产生 `BadColor` 错误。

`XStdColormap` 用于指示输入法应该在其中分配颜色的标准调色板名称。参数的值是一个 `Atom`，且该 `Atom` 是 `XGetRGBColormaps` 的有效 `Atom`。当输入法使用无效参数时，可能会产生 `BadColor` 错误。

如果未指定调色板，则客户端窗口调色板成为默认值。

## 前景和背景 (Foreground and Background)

`XNForeground` 和 `XNBackground` 分别指定前景和背景像素。参数的值类型为 `unsigned long`。它必须是输入法调色板中的有效像素。

如果未指定这些值，默认值由输入法决定。

## 背景位图 (Background Pixmap)

`XNBackgroundPixmap` 参数指定了作为窗口背景的背景位图。该值的类型必须为 `Pixmap`。当输入法使用无效参数时，可能会产生 `BadPixmap` 错误。

如果未指定此值，默认值由输入法决定。

## 字体集 (Font Set)

`XNFontSet` 参数向输入法指定了要使用的字体集。参数的值类型为 `XFontSet`。

如果未指定，默认值由输入法决定。

## 行间距 (Line Spacing)

`XNLineSpace` 参数向输入法指定了在多行预编辑时使用的行间距。该参数类型为 `int`。

如果未指定，默认值由输入法决定。

## 光标 (Cursor)

`XNCursor` 参数向输入法指定了在该窗口使用的光标。该参数类型为 `Cursor`。

当输入法使用无效参数时，可能会产生 `BadCursor` 错误。如果未指定，默认值由输入法决定。

## 预编辑状态 (Preedit State)

`XNPreeditState` 参数指定输入法的预编辑状态。预编辑可以开启或关闭。

`XNPreeditState` 的有效掩码名称如下：

```c
typedef unsigned long XNPreeditState;
#define XNPreeditUnknown 0L
```
