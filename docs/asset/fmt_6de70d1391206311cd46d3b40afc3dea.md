
输入 `make` 以构建软件。此步骤将编译所有子目录中的源文件。

输入 `make install` 以安装软件。此步骤将库和可执行二进制文件复制到系统中的适当目录。

虽然这些步骤特定于 XMMS，但大多数其他软件包都遵循此流程：`configure`、`make`，然后 `install`。

通常，您只需要输入命令来构建软件；但是，您必须在系统上安装软件开发工具。这意味着您在安装 Red Hat Linux 时必须安装 Development 软件包。要构建和运行 XMMS，您还必须安装 X Window System 软件包，因为它是一个 X 应用程序。

## 构建软件

要开始构建 XMMS，请在 `xms-1.2.5` 目录中输入以下命令以运行 `configure` 脚本：

```bash
./configure
```

`configure` 脚本开始运行，并在检查系统的各种特性时打印大量消息，从 C 编译器的存在到构建 XMMS 所需的各个库。最后，`configure` 脚本会创建一个 `Makefile`，您可以使用它来构建软件。

如果 `configure` 脚本显示错误消息并失败，请再次阅读 `INSTALL` 和 `README` 文件，以寻找解决问题的线索。您可能可以通过向 `configure` 脚本提供命令行参数来绕过此问题。

`configure` 脚本完成后，输入以下命令以构建软件：

```bash
make
```

此命令运行 GNU make 实用程序，根据系统速度的不同，完成该操作可能需要 10 到 15 分钟。`make` 实用程序读取 `Makefile`，其中包含编译器根据您下载的源代码创建 XMS 程序所需的信息。`make` 命令遍历源目录，编译源文件，并创建运行 XMS 所需的可执行文件和库。随着每个文件的编译，您会看到大量消息滚动而过。这些消息显示了用于编译和链接文件的命令。

## 安装软件

`make` 命令完成后，您可以使用以下命令安装 XMS 软件：

```bash
make install
```

此命令也运行 GNU make，但 `install` 参数指示 GNU make 执行 `Makefile` 中特定的一组命令。这些说明基本上搜索子目录并将各种文件复制到其最终位置。例如，二进制可执行文件 `xmms`、`gnome-xmms`、`wm-xmms` 和 `xmms-config` 会被复制到 `/usr/bin` 目录。

## 运行软件

既然您已安装 XMS，请尝试在 GNOME 或 KDE 桌面的终端窗口中输入 `xmms` 来运行它。从 XMS 窗口，您可以打开一个 MP3 文件并尝试播放它。请注意，您的 PC 必须有声卡，并且必须正确配置。（Session 18 讨论了声卡配置。）图 27-1 显示了 XMS 播放 MP3 音乐片段的典型视图。

## 回顾基本构建步骤

现在您知道了如何下载、解压、构建和安装典型的软件包。以下是完成这些任务所遵循步骤的概述：

1. 从匿名 FTP 站点或网站下载源代码，通常以 `_tar.gz` 文件的形式。使用 Web 浏览器或手动从匿名 FTP 服务器下载源代码。
2. 使用 `tar zxvf filename` 命令解压文件。
3. 使用类似以下命令更改到软件解压后的新子目录：

```bash
cd software_dir
```

4. 阅读任何 `README` 或 `INSTALL` 文件，以识别软件的要求并了解构建和安装软件时必须遵循的任何特定说明。
5. 软件构建的细节可能因软件包而异，但通常，您输入以下命令来构建和安装软件：

```bash
./configure
make
make install
```

6. 阅读随软件提供的其他文档，以了解如何配置和使用它。

## 故障排除

如果您使用匿名 FTP 下载诸如压缩 `tar` 归档之类的文件，并且它似乎已损坏，请确保在下载文件之前已切换到二进制模式。在文本模式（也称为 `ASCII` 模式）下下载二进制文件会破坏下载的文件。以下两条消息是这种情况的症状：

```bash
$ tar zxvf mytarball.tar.gz

gzip: stdin: not in gzip format
tar: Child returned status 1
tar: Error exit delayed from previous errors
$ gunzip mytarball.tar.gz

gunzip: mytarball.tar.gz: not in gzip format
```

您在构建软件时可能会遇到问题，例如收到投诉缺少程序的错误消息，或者特别是消息 `Installation or configuration problem: compiler cannot create executables`。最可能的解释是您没有安装完整的开发环境。为了解决这个问题，请按照 Session 23 中的说明，从 Red Hat Linux 安装 CDs 中安装以下列表中至少包含的 `RPMs`：

- bzip2
- fileutils
- gcc
- gcc-c++
- glibc-devel
- gzip
- kernel-headers
- kernel-source
- make
- ncompress
- tar

您正在构建的特定软件包可能有额外的要求，但在许多情况下，此列表中的 RPMs 就足够了。

## 使用 top 实用程序

要查看 `top`，即最常使用的 CPU 进程，您可以使用 `top` 程序。要启动该程序，请在终端窗口或文本控制台中输入 `top`。然后，`top` 程序显示一个文本屏幕，按 CPU 使用率的降序列出当前进程。该程序还显示其他信息，如内存和交换空间使用情况。图 28-1 显示了 `top` 程序的典型输出。

### 图 28-1 查看 CPU 占用率最高的进程

![](img/5fe8f856723cde0b366f73584b9e64b8_305_0.png)

`top` 实用程序每五秒更新一次显示内容。您可以让 `top` 在一个窗口中持续运行，从而持续监控 Red Hat Linux 系统的状态。按 `q` 键或关闭终端窗口即可退出 `top`。

输出屏幕的前五行提供了关于系统的概要信息。这五行显示的内容如下：

- 第一行显示当前时间、系统已运行时长、登录的用户数量以及三个负载平均值（即过去 1、5 和 15 分钟内处于就绪状态等待运行的进程的平均数量）。
- 第二行列出进程的总数以及这些进程的状态。
- 第三行显示 CPU 使用情况——用户进程占用的 CPU 时间百分比、系统（内核）进程使用的百分比，以及 CPU 空闲时间的百分比。
- 第四行显示物理内存的使用情况。这包括内存总量、已用内存量、空闲内存量、共享内存量，以及分配给缓冲区（例如用于从磁盘读取数据）的内存量。
- 第五行显示虚拟内存或交换空间的使用情况。这包括交换空间的总量、已用量、空闲量以及缓存量。

在 `top` 的输出屏幕中（参见图 28-1），概要信息下方的表格列出了当前进程的信息，并按 CPU 时间使用量从高到低排序。在终端窗口中输入 `man top` 以了解 `top` 显示表格中各列标题的含义。
