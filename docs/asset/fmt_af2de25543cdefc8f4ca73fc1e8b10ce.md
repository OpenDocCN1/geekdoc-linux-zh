
用户使用许多不同的 shell 程序，但除非 `Makefile` 另有指定，否则 `Makefile` 中的配方始终由 `/bin/sh` 解释。请参见第 5.3 节 [配方执行](Recipe Execution)，第 44 页。

### 5.1 配方语法

`Makefile` 有一个特殊的属性，即一个文件中实际上存在截然不同的语法。`Makefile` 使用 make 语法（参见第 3 章 [编写 Makefile](Writing Makefiles)，第 11 页）。然而，配方旨在由 shell 解释，因此它们是用 shell 语法编写的。`make` 程序并不会尝试理解 shell 语法：它仅对配方内容执行少数特定的翻译，然后将其交给 shell。

配方中的每一行都必须以制表符（tab）开头（或 `_RECIPEPREFIX` 变量值的第一个字符；参见第 6.14 节 [特殊变量](Special Variables)，第 73 页），但配方行也可以通过中间的分号（;）与目标和先决行相连。`Makefile` 中任何以制表符开头并出现在“规则上下文中”（即从规则开始到另一个规则或变量定义之前）的行，都将被视为配方的一部分。配方行之间可能会出现空行和注释行；它们会被忽略。

这些规则的一些后果包括：

- 以制表符开头的空行不是空行；它是一个空配方（参见第 5.9 节 [空配方](Empty Recipes)，第 57 页）。
- 配方中的注释不是 make 注释；它将原样传递给 shell。shell 是否将其视为注释取决于你的 shell。
- 在“规则上下文中”的变量定义以制表符作为行的第一个字符缩进，将被视为配方的一部分而非变量定义，并传递给 shell。
- 在“规则上下文中”的、以制表符作为行的第一个字符缩进的条件表达式（`ifdef`, `ifeq`。参见第 7.2 节 [条件语法](Syntax of Conditionals)，第 78 页），将被视为配方的一部分并传递给 shell。

### 5.1.1 拆分配方行

`make` 解释配方的方法之一是在换行符之前检查反斜杠（\）。在标准的 `Makefile` 语法中，单行配方可以通过在每行之前放置反斜杠，在 `Makefile` 中拆分成多个物理行。这样的行序列被视为单行配方，并将调用一次 shell 来运行它。

然而，与它们在 `Makefile` 其他地方的处理方式不同（参见第 3.1.1 节 [拆分长行](Splitting Long Lines)，第 12 页），反斜杠/换行符并不会从配方中移除。反斜杠和换行符都会保留并传递给 shell。反斜杠/换行的解释取决于你的 shell。如果反斜杠/换行下一行的第一个字符是 make 配方前缀字符（默认为制表符；参见第 6.14 节 [特殊变量](Special Variables)，第 73 页），则该字符（仅该字符）会被删除。配方中永远不会添加空格。

例如，此 `Makefile` 中 `all` 目标的配方：

```
all :
    @echo no\
    space
    @echo no\
    space
    @echo one \\
    space
    @echo one\
    space
```

它由四个独立的 shell 命令组成，其输出为：

- nospace

nospace

- one space

one space

作为一个更复杂的例子，这个 `Makefile`：

```
all : ; @echo 'hello \\
    world'; echo "hello \\
    world"
```

将调用一个 shell，命令为：

```
echo 'hello \
    world'; echo "hello \\
    world"
```

根据 shell 引用规则，它将产生以下输出：

```
hello \
    world
hello    world
```

注意反斜杠/换行符对在双引号（"..."）引号字符串内部被删除了，但在单引号（'...'）引号字符串内没有。这是默认 shell `/bin/sh` 处理反斜杠/换行符的方式。如果你在 `Makefile` 中指定了不同的 shell，它将以不同的方式处理它们。

有时你想使用单引号来拆分长行，但你不希望反斜杠/换行符出现在引号内容中。这在将脚本传递给 `Perl` 等语言时经常发生，其中多余的反斜杠可能会改变脚本的含义或导致语法错误。处理此问题的一种简单方法是将引号字符串（甚至整个命令）放在单行中。例如，此 `Makefile` 中 `all` 目标的配方：

```
all :
    @echo 'hello \
    world';
    echo "hello \
    world"
```

注意反斜杠/换行符对在双引号（"..."）引号字符串内部被删除了，但在单引号（'...'）引号字符串内没有。这是默认 shell `/bin/sh` 处理反斜杠/换行符的方式。如果你在 `Makefile` 中指定了不同的 shell，它将以不同的方式处理它们。有时你想使用单引号来拆分长行，但你不希望反斜杠/换行符出现在引号内容中。这在将脚本传递给 `Perl` 等语言时经常发生，其中多余的反斜杠可能会改变脚本的含义或导致语法错误。处理此问题的一种简单方法是将引号字符串（甚至整个命令）放在单行中。例如，此 `Makefile` 中 `all` 目标的配方：

### 5.3.1 使用单个 Shell

有时你可能希望配方中的所有行都放在一次 shell 调用中。通常有两种情况下这很有用：首先，提高配方包含许多命令的 `Makefile` 的性能；其次，你可能希望包含你的配方命令中（例如，可能你正在使用非常不同的解释器作为 `SHELL`）。如果 `Makefile` 中任何地方出现 `.ONESHELL` 特殊目标，则每个目标将提供给单次 shell 调用。配方行之间的换行符将被保留。

```
.ONESHELL:
foo : bar/lose
  cd ($D)
  gobble ($F) > ../
```

如果使用了 `.ONESHELL`，则只对配方的第一行检查特殊字符（''、'-' 和 '+'）。后续行在 `SHELL` 被调用时将包含这些特殊字符。如果你想以这些特殊字符之一开头，你需要确保它们不是第一行的第一个字符，例如通过添加注释或其他方式。例如，除非 `make` 删除了第一个 '@'，否则这在 `Perl` 中会导致语法错误：¹在 MS-DOS 上，当前工作目录的值是全局的，因此更改它将影响这些系统上的后续配方行。

```makefile

.SHELLFLAGS = -e
```

然而，上述两种替代方案中的一种都可以正常工作：

```makefile
.ONESHELL:
SHELL = /usr/bin/perl
.SHELLFLAGS = -e
show :
  # 确保 "@" 不是第一行的第一个字符
  @f = qw(a b c);

```

或者

```makefile
.ONESHELL:
SHELL = /usr/bin/perl
.SHELLFLAGS = -e
show :
  my f = qw(a b c);
  print "@f\n";
```

作为一项特殊功能，如果 `SHELL` 被确定为 POSIX 风格的 shell，则“内部”配方行中的特殊前缀字符会在处理配方之前被移除。此功能允许 `Makefile` 在添加 `.ONESHELL` 特殊目标后，无需进行大量修改即可正常运行。由于特殊前缀字符在 POSIX shell 脚本的开头是非合法的，因此不会导致功能缺失。例如，以下操作符合预期：

```makefile
.ONESHELL:
foo : bar/lose
  @cd ($@)
  @gobble ($@) ../$
```

即使有此特殊功能，`makefile` 的行为仍可能产生可察觉的差异。例如，通常配方中的任何行失败都会导致规则失败，且不再处理后续的配方行。在 `.ONESHELL` 模式，任何最终配方行的失败都不会被 `make` 察觉。你可以修改 `.SHELLFLAGS` 为 shell 添加 `-e` 选项，这将导致命令行中的任何失败都导致退出，但这可能会导致你的配方行为发生变化。最终，你可能需要加固你的配方，使其能够与 `.ONESHELL` 配合。

### 5.4.1 并行期间的输出

在并行运行配方时，每个配方的输出会在生成时立即出现，导致来自不同配方的消息交织在一起，有时甚至出现在同一行。这可能使得输出变得难以阅读。

为了避免这种情况，你使用 `--output-sync` ('-0') 选项。该选项指示 `make` 保存其调用的命令的输出，并在所有命令完成后进行打印。

此外，如果并行存在多个递归 `make` 调用，它们将相互通信，确保一次只有一个它们在生成输出。

如果启用了目录打印（参见第 5.7.4 节 ['--print-directory' 选项，第 55 页]），则会在每个输出分组周围打印“进入/离开”消息。如果你不想看到这些消息，请在 `MAKEFLAGS` 中添加 `--no-print-directory` 选项。

同步输出有四种粒度级别，通过向选项传递参数来指定（例如，`--line` 或 `--output-sync=recursive`）。

- **none**：默认值：所有输出在生成时直接发送，且不进行任何同步。
- **line**：每个配方（recipe）中每一行的输出都将被分组，并在该行完成后打印。如果一个配方包含多行，它们可能会与其他配方的行交错在一起。
- **target**：每个目标的整个配方输出都将被分组，并在目标完成后打印一次。如果在不带参数的情况下给出 `--output-sync` 或 `-0` 选项，则为默认值。
- **recursive**：`make` 每次递归调用的输出都将被分组，并在递归调用完成后打印。

无论选择哪种模式，总时间都是相同的。区别仅在于输出的呈现方式。

'target' 和 'recursive' 模式都控制目标整个配方的输出，并在配方完成后不间断地显示它。它们之间的区别在于包含递归调用 `make` 的配方是如何创建的（参见第 5.7 节 [make 的递归使用]，第 50 页]）。对于所有没有递归行的配方，'target' 和 'recursive' 模式的行为完全相同。

如果使用 'recursive' 模式，包含递归 `make` 用的配方将被视为其他目标：配方的输出（包括来自 `make` 的输出）将被保存并在整个配方完成后进行打印。这确保了由递归 `make` 构建的所有目标的输出都组合在一起，这可能使构建更容易理解。然而，它也会导致在长时间内看不到任何输出，随后出现爆发式的输出。如果你不是在实时监控构建，而是事后查看构建日志，那么这可能是对你的最佳选择。

如果你正在实时监控构建，构建过程中长时间的静默可能会让你感到沮丧。'target' 输出同步模式会使用标准方法检测 `make` 何将被递归调用，并且它不会同步这些输出。recursive 模式将对其目标执行同步，每个调用的输出将在完成后后立即显示。请注意，配方中递归行的输出是不同步的（例如，如果配方在运行 `make` 之前打印了消息，则该消息将不会被同步）。

'line' 模式对于通过观察 `make` 输出来跟踪配方启动和完成的前端可能有用。

由 `make` 调用的某些程序如果确定自己是向终端写入输出，相对于（通常描述为“交互式”的）“非交互式”模式，其行为可能会不同。

## 5.4.2 并行执行期间输入

两个进程不能同时从同一设备获取输入。为了确保同时只有一个配方尝试从终端获取输入，`make` 将使除运行中的配方外的所有标准输入流失效。如果另一个配方尝试从标准输入读取，通常会产生致命错误（“Broken pipe signal”）。

无法预测哪个配方将具有有效的标准输入流（该流将来自终端，无论你如何重定向 `make` 的标准输入）。第一个配方总是第一个获得它，在第一个结束后之后启动的第一个配方将下一个获得它，依此类推。

如果我们发现了更好的替代方案，我们将更改 `make` 的工作方式。在此，如果你正在使用并行执行功能，你不应该依赖任何配方使用标准输入；但如果你没有使用此功能，标准输入在所有配方中正常工作。

## 5.5 配方中的错误

在每个 shell 调用返回后，`make` 会查看其退出状态。如果 shell 成功完成（退出状态为 0），则配方中的下一行将在新的 shell 中执行；在最后一行完成后，配方结束。

如果发生错误（退出状态非 0），`make` 将放弃当前规则，可能放弃所有规则。

有时，配方行的失败并不意味着存在问题。例如，你可能使用 `mkdir` 命令来确保目录存在。如果目录已经存在，`mkdir` 将报告错误，但你可能希望 `make` 无论如何继续。

要忽略配方中的错误，请在行开头（初始制表符之后）写一个 '-'。'-' 在该行传递给 shell 执行之前会被丢弃。

例如，

```
rm -f *.
```

这使得即使 `rm` 无法删除文件，`make` 也会继续。

当你使用 '-' 或 '--ignore-errors' 标志运行 `make` 时，所有规则中所有配方的错误都将被忽略。`makefile` 中针对特殊目标 `IGNORE` 的规则具有相同效果，前提是没有任何先决条件。这些忽略错误的方法已经过时了——'-' 更具灵活性。

当需要忽略错误时（无论是通过 '-' 还是 '-i' 标志），`make` 将错误等同于成功，但它会打印一条消息告知 shell 退出时的状态码，并表示错误已被忽略。
