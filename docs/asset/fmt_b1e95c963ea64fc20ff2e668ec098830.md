
在 `Libvirt` 中，虚拟机——有点令人困惑地被称为“域”——由另一个用户运行，因此如果本地用户的桌面在他们玩虚拟机时崩溃了，它会在后台继续运行并且可以重新连接。这样它的工作方式非常类似于连接到远程机器。事实上，这是 `Libvirt` 做的另一件事：允许从远程机器运行虚拟机。简单的 `Boxes` 工具在幕后使用 `Libvirt` 来完全抽象掉这种差异，因此通过相同的界面，你可以连接到远程机器、虚拟机，或者确实，远程虚拟机。

## 安装 `Libvirt`

我们可以通过从终端安装虚拟机管理器（又名 `virt-manager`）前端来在 `Ubuntu` 中安装所有必需的组件：

```
$ sudo apt install virt-manager
```

如果你跳过了前面的页面（真丢人），这将同时安装 `QEMU` 并启用所需的服务。它还会将你的用户添加到 `libvirt` 组，但在连接到所述服务之前，你需要注销并重新登录。

从应用程序菜单启动 `Virtual Machine Manager`，它应该会自动连接到 `Libvirt`。如果你没有遵守上一句，你会得到一个权限错误。点击左上角的“创建新虚拟机”按钮以启动向导。选择“本地安装介质”、“使用 ISO 镜像”、“浏览”、“浏览本地”（是的，这有点啰嗦），然后选择一个 ISO 文件。这次我们选择了 `Ubuntu 20.04` 桌面版每日构建。

`Virt-manager` 会根据名称尝试猜测介质将安装的操作系统。这通常不起作用，因此清除“自动检测操作系统”复选框，并选择 `Linux` 和 `Ubuntu 18.04`；它不必与客户机操作系统完全匹配，这是好事，因为并非所有操作系统都列出了。接下来，为你的虚拟机分配一些内存和 `CPU`：对于现代桌面发行版，少于两个核心和 2GB 内存可能是一次痛苦的经历。

点击“前进”并选择“创建磁盘镜像”选项，请记住虚拟机的磁盘填充速度与实际磁盘一样快。默认情况下，镜像存储于 `/var/lib/libvirt/images`。如果你希望将镜像创建在其他位置——例如在空间更大的另一个分区上——那么请在此处选择自定义存储选项。继续下一步并为你新的虚拟机命名——如果你想使用虚拟 `UEFI` 固件，请不要忽略那个小小的“在安装前自定义配置”复选框。这是你唯一一次设置此选项的机会，需要在“概述”部分使用固件选项：一旦虚拟机以传统 `BIOS` 模式安装完成，它就永远锁定在该模式下。

默认的 `NAT` 网络将与 `QEMU` 的默认设置方式相同工作，但如果你想要桥接网络，请选择 `vtap` 设备并将源模式设置为 `Bridge`。通过使用 `virtio` 视频（又名 `Virgl3d`）驱动程序，可以改进图形性能，该驱动程序使来宾系统能够使用主机的 `3D` 加速。为了让它在 `virt-manager` 中正常工作，你需要在 `Display Spice` 部分将“Listen”类型设置为“None”。由于在启用 `Virgl3d/virtio` 时我们几乎直接使用了显卡，所以此功能的远程部分无法工作。

你可以通过运行 `dnsmgr|grep drm` 来检查是否运行正常。你也可以轻松选择 `virtio` 网络和存储设备。现在你终于准备好启动基于 `libvirt` 的虚拟机了。点击左上角的“开始安装”按钮，– 祝你好运 – 一切应该都能正常工作。如果不行，请尝试使用 `QXL` 视频驱动程序（见下文）。

如果你觉得安装新的 `Linux` 虚拟机太费事，那么有个好消息 – 你可以从 https://osboxes.org 下载开箱即用的 `VirtualBox` 和 `VMware` 镜像。将 `VirtualBox VDI` 镜像转换为 `QEMU` 可用的格式非常容易。假设我们下载了 `Arch Linux CLI` 镜像（并将其解压缩到当前目录），那么 `QEMU` 提供了转换工具：

```bash
$ qemu-img convert -f vdi -O qcow2 201905-cli-64bit.vdi archlinux.xcow2
```

### 虚拟化 `Windows`

我们在此并未介绍 `Windows` 虚拟化，但这是完全可行的。你可以从 `Microsoft` 的网站 http://bit.ly/lxf261windows 完全合法地下载 `Windows 10` 的 ISO 镜像。请注意，如果你希望在你按照喜好完成设置后正式激活安装，你仍然需要购买有效的 `Windows` 密钥。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_74_0.png)

`Libvirt` 使用 `XML` 来定义虚拟化机器，如果你需要细粒度的控制，可以直接在 `virt-manager` 中编辑它。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_74_1.png)

确保虚拟 `Windows` 快速运行的最简单直接的方法是确保虚拟驱动器存储在 `SSD` 上，最好是快速的 `SSD`。其次，如果你正在使用 `KVM`，你需要从 http://bit.ly/lxf261virtio 安装 `virtio` 驱动程序。向下滚动到直接下载部分，下载稳定版（来自 `RHEL`）或最新版（来自 `Fedora`）ISO 文件。

在主机机器上这样做最容易，然后使用虚拟机的虚拟光驱来访问它。如果你想要使用 `virtio SCSI` 驱动程序（强烈推荐），你需要在安装时添加此 –

> 在 `Windows` 中插入 ISO 文件并右键点击相关的 `.INF` 文件来安装 `virtio` 驱动程序。

### 懒得折腾？

> “如果你觉得安装新的 `Linux` 虚拟机太费事，那么有个好消息 – 你可以下载开箱即用的 `VirtualBox` 和 `VMware` 镜像。”

其余部分可以稍后添加。你会希望给你的虚拟机分配大量内存：在少于 4GB 内存下运行 `Windows 10` 体验并不好。虽然没有 `Virgl3D` `Windows` 驱动程序，但有替代方案。`QXL` 显卡是一种部分半虚拟化视频设备，应该比标准 `VGA` 驱动程序提供更好的性能（和更高的分辨率）。你可以在 `QEMU` 中使用 `-vga qxl` 使用它。或者你可以在 `virt-manager` 的“视频”部分找到它。你可以在 `Red Hat` 的 ISO 中的 `qxlwlod/` 目录中找到它的 `Windows` 驱动程序。

不过，为了获得绝对最佳的视频性能，你需要研究 `PCIe` 直通。在这种设置中，我们为 `Windows` 虚拟机安装一块专用 `GPU`，并让内核在启动时将其隔离以供使用。我们在 `LXF244` 的上一期虚拟化特辑中已经介绍过这一点。关于此主题的一个绝佳资源是 `Arch Wiki` 页面，地址为 http://bit.ly/lxf261passthrough。如果你成功运行了此功能，我们很乐意听到你的消息和基准测试结果。虚拟化旧版本的 `Windows` 也是可能的，使用正确的 ISO 即可，这是一种保留旧应用程序的合理方式 – 也许来自你现已退役的 `Windows 7` 安装 – 直到你找到合适的 `Linux` 替代品。**完**
