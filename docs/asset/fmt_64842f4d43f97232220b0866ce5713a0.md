
我们首先将值 `yes` 赋值给变量 `foo`，然后用 `echo` 显示它的值。接下来，我们显示拼写错误的变量名 `foo` 的值，得到了空白结果。这是因为当 shell 遇到变量 `foo` 时，给了它默认值“无”或空。从这里我们学到，必须密切关注我们的拼写！理解在这个例子中到底发生了什么也很重要。根据我们之前对 shell 如何执行扩展的观察，我们知道以下命令：

```bash
$linuxbox ~$ echo foo
```

经过参数扩展后结果如下：

```bash
$linuxbox ~$ echo yes
```

相比之下，以下命令：

```bash
$linuxbox ~$ echo foo
```

展开为：

```bash
$linuxbox ~$ echo
```

空变量展开后都没有产生！这可能会对需要参数的命令造成破坏。这里有一个例子：

```bash
$linuxbox ~$ foo=foo.txt
$linuxbox ~$ foo1=foo1.txt
$linuxbox ~$ cp $foo $foo
cp: missing destination file oper after `foo.txt'
Try `--help for more information.
```

我们为两个变量 `foo` 和 `foo1` 赋予了值。我们执行了 `cp` 操作，但漏掉了第二个参数的名字。扩展后，`cp` 命令只被发送了一个参数，尽管它需要两个。关于变量名有一些规则：

- 变量名可以由字母数字字符（字母和下划线）组成。
- 变量名的第一个字符必须是字母或下划线。
- 不允许使用空格和标点符号。

“变量”一词意味着一个变化的值，在许多应用程序中，变量就是这样使用的。然而，我们应用程序中的变量 `title` 被用作常量。常量就像变量，它有一个名称并包含一个值。区别在于常量的值不会改变。在一个执行几何计算的应用程序中，我们可能会将 `PI` 定义为常量并赋值 `3.1415`，在整个程序中字面使用该数字。shell 不区分变量和常量；它们主要是为了程序员。一种常见的约定是使用大写字母表示常量，使用小写字母表示变量。

```bash
#!/bin/bash

# 输出系统信息页的程序
TITLE=System Information Report For $HOSTNAME

echo "<html>
<head>
<title>Page Title</title>
</head>
<body>
  Page body.
</body>
</html>"
```

我们还借此机会向报告中添加了一些数据：创建报告的时间以及创建者的用户名。

```bash
#!/bin/bash
TITLE=System Information Report For $HOSTNAME
CURRENT_TIME=$(date +"x %X %Z")
TIMESTAMP="Generated $CURRENT_TIME, by $USER"
```

> 良好的习惯是将变量和命令替换包含在双引号中，以限制 shell 单词拆分的影响。当变量名包含文件名时，引号尤为重要。

# Here Documents (在此文档)

我们已经查看了两种输出文本的方法，它们都使用了 `echo` 命令。第三种方法被称为*在此文档*（here document）或*在此脚本*（here script）。在此文档是 I/O 重定向的一种额外形式，我们将一段文本嵌入到脚本中，并将其馈给命令的标准输入。它的工作原理如下：

```
command << token
text
token
```

其中 `command` 是接受标准输入的命令名称，而 `token` 是用于指示嵌入文本结束的字符串。在这里我们将修改脚本来使用在此文档：

```bash
#!/bin/bash

# 输出系统信息页的程序
TITLE="System Information Report For $HOSTNAME"
CURRENT_TIME=$(date +"%x %xr %Z")
TIMESTAMP="Generated $CURRENT_TIME, by $USER"
```

```bash
cat << _EOF_
<html>
<head>
<title>$TITLE</title>
</head>
<body>
<h1>$TITLE</h1>
<p>$TIMESTAMP</p>
</body>
</html>
_EOF_
```

我们的脚本现在不再使用 `echo`，而是使用 `cat` 和在此文档。字符串 `_EOF_`（意味着 *end of file*，一种惯例）被选择为 `token`，并标记嵌入文本的结束。注意，`token` 必须单独出现，行尾不能有空格。

那么，使用在此文档的优势是什么？它大部分与 `echo` 相同，不同之处在于默认情况下文档内的单引号和双引号会失去对 shell 的特殊含义。这里有一个命令行示例：

```bash
@linuxbox ~$ foo="some text"
@linuxbox ~$ cat << _EOF_
> $foo
> "$foo"
> '$foo'
> \$foo
> _EOF_
some text
'some text'
'some text'
foo
```

我们可以看到，shell 并不注意引号。它将其视为普通字符。这允许我们在在此文档中自由地嵌入引号。这对我们的报告程序可能非常有用。

在此文档可以与任何接受标准插入命令一起。在这个示例中，我们使用在此文档向 `ftp` 程序传递一系列命令，从远程服务器检索文件：

```bash
#!/bin/bash

# 通过 FTP 获取文件的脚本

FTP_SERVER=ftp.nl.debian.org FTP_PATH=/debian/dists/stretch/main/installer-amd64/current/cdrom REMOTE_FILE=debian-cd-info.tar.gz

tftp -n << EOF
open $FTP_SERVER
user anonymous me@linuxbox
cd $FTP_PATH
hash
get $REMOTE_FILE
bye
EOF
ls -l "$REMOTE_FILE"
```

如果我们将重定向运算符从 `<<` 改为 `<<-`，shell 将忽略在此文档开头的制表符（但不忽略空格）。这允许在此文档进行缩进，从而提高可读性。

```bash
#!/bin/bash

# 通过 FTP 获取文件的脚本

FTP_SERVER=ftp.nl.debian.org
FTP_PATH=/debian/dists/stretch/main/installer-amd64/current/cdrom
REMOTE_FILE=debian-cd-info.tar.gz

ftp -n << EOF
	open $FTP_SERVER
	user anonymous me@linuxbox
	cd $FTP_PATH
	hash
	get $REMOTE_FILE
	bye
EOF
ls -1 "$REMOTE_FILE"
```

这个特性可能会有些问题，因为许多文本编辑器（以及程序员本身）更倾向于使用空格而不是制表符来实现脚本中的缩进。
