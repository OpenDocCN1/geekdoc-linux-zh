## 10.12. 验证正确性？

在优化显著减少过滤器运行时间后，有必要验证生成的图像是否相同。通过加载原始图像并与生成的图像进行对比，使用 GIMP 计算两者的差异。如果原始图像和优化后的图像相同，则所有像素都应为 0（黑色）。然而，视觉上看起来是黑色的，但在仔细检查（使用颜色选择器）后，某些像素是非零的。这意味着原始和优化后的图像是不相同的。这通常令人担心，因为这可能表明优化改变了过滤器的行为。然而，对过滤器源码的仔细检查显示，在运行过滤器之前使用了随机噪声对图像进行了抖动处理。由于两个图像之间的差异非常微小，我们可以假设优化没有引入任何问题。

## 10.13. 下一步工作

我们已经超过了 `lic` 过滤器性能提升 10% 的目标，从这个意义上说，我们已经完成了优化过程。然而，如果我们想继续提高性能，就必须在使用新的优化方案时对过滤器重新进行性能分析（`reprofile`）。在每次应用性能优化后，对应用程序进行重新性能分析是非常重要的，在继续优化应用程序时不要依赖旧的分析数据。应用程序的运行时行为在每次优化后都可能发生巨大变化。如果你在每次优化后都不进行性能分析，就可能会面临追踪一个不再存在的性能问题的风险。

## 10.14. 本章总结

在本章中，我们确定了为什么一个应用程序（GIMP 过滤器 `lic`）是 CPU 密集型的。我们确定了应用程序的基准运行时，设定了优化目标，并保存了一张参考镜像以验证我们的优化没有改变应用程序的行为。我们使用了 Linux CPU 性能工具（`oprofile` 和 `ltrace`）来调查应用程序为什么是 CPU 密集型的。然后，我们使用 `gdb` 来理解应用程序的工作原理，并想出不同的优化方法。我们尝试了几种不同的优化，但最终，我们选择了经典的“增加内存使用以减少 CPU 使用”的性能权衡方案。

我们超越了优化目标，并验证了我们的优化没有改变应用程序的输出。

虽然本章侧重于优化单个应用程序的运行时，但下一章将介绍一次性能搜寻，重点在于减少与 X Windows 交互时的延迟。减少延迟可能是困难的，因为单个事件往往会触发一系列不显见的其他事件。困难之处在于确定哪些事件被调用了以及每个事件花费了多长时间。

# 第 11 章 性能搜寻 2：延迟敏感型应用程序 (nautilus)

本章包含一个如何使用 Linux 性能工具在延迟敏感型应用程序中发现并修复性能问题的示例。

读完本章后，你应该能够：

- 使用 `ltrace` 和 `profile` 确定延迟敏感型应用程序中产生延迟的位置。
- 使用 `gdb` 为每次对“热点”函数的调用生成堆栈跟踪（`stack trace`）。
- 使用性能工具确定使用许多不同共享库的应用程序时间耗费在哪里。
- 将本章作为模板，寻找延迟敏感型应用程序中高延迟的产生。

## 11.1. 延迟敏感型应用程序

在本章中，我们调查了一个对慢延迟敏感的应用程序。延迟可以被认为应用程序响应不同外部或内部事件所需的时间。一个应用程序只有少量的 CPU 时间来响应不同的事件。然而，它对特定事件的响应不够快。在修复延迟性能问题时，我们需要减少对各种事件响应的延迟，并找出应用程序的哪些部分降低了响应。正如你所看到的，追踪延迟问题的策略与追踪 CPU 密集型问题的策略略有不同。

这次性能调查与 GIMP 调查的显著区别在于，我们试图减少的时间级是毫秒级的，而不是秒级的。当时间如此短时，要确保你捕获的分析数据确实是你试图测量的事件的结果，而不是仅仅是启动和停止性能分析工具时产生的噪声，是非常困难的。然而，这段短时间范围也使得在有趣的时间段内对应用程序的所有方面进行追踪变得可行。

## 11.3. 基准/设定目标

正如前面提到的，第一步是确定问题的当前状态。为了让我们的工作更轻松一点，并避免上一节提到的某些问题，我们将创建一个小窗口和弹出菜单问题使其看起来更像我们之前测量的长时间运行 CPU 密集型任务。单个弹出菜单出现的时间在毫秒范围内，这使得很难用我们的性能工具进行准确测量。正如之前提到的，在感兴趣的时间内（即打开实际菜单花费的时间）启动和停止这些工具将很困难。在这里，我们看到了我们感兴趣的内容（即我们点击的菜单）。我们不会只打开一次菜单，而是将连续快速打开 100 次菜单。这样，打开菜单花费的总时间将增加 100 倍。这使我们能够使用分析工具来捕获有关菜单如何执行的信息。

因为右键点击 100 次会很乏味，而且人类（除非经过良好训练）无法以可重复的方式可靠地打开 100 次弹出菜单，我们必须对其进行自动化。为了可靠地打开 100 次弹出菜单，我们依赖于自动化包。`xautation` 软件包可以在 http://httpajoo.net/projects/xautation.html 获取。它可以向 X 服务器发送任何窗口事件，模拟鼠标点击。下载 `xautation` 文件、解压并编译它后，我们就可以使用它来自动化鼠标点击。

与 GIMP 不同，我们不能简单地测量 `nautilus` 使用的 CPU 数量，我们需要让弹出菜单问题看起来更像我们之前测量的长时间运行 CPU 密集型任务。
