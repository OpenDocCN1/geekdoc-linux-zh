{
public:
    RangeError(unsigned long number);
    ~RangeError() {}
    virtual void PrintError();
    virtual unsigned long GetNumber() { return badNumber; }
    virtual void SetNumber(unsigned long number) { badNumber = number; }

private:
    unsigned long badNumber;
};

void RangeError::PrintError()
{
    cout << "Number out of range. You used " << GetNumber() << "!\n";
}

## 5. BUG 查找：以下代码哪里出了问题？

```cpp
#include "string.h" // 我们的字符串类

class xOutOfMemory
{
public:
    xOutOfMemory(const String& where) : location(where) {}
    ~xOutOfMemory() {}
    virtual String where() { return location; }

private:
    String location;
};

int main()
{
    try
    {
        char *var = new char;
        if (var == nullptr)
            throw xOutOfMemory("location info"); // 构造函数需要参数
    }
    catch(xOutOfMemory &theException)
    {
        cout << "Out of memory at " << theException.where() << "\n";
    }
    return 0;
}
```

**问题分析**：
在处理“内存不足”条件的过程中，由 `xOutOfMemory` 的构造函数会创建一个字符串对象。只有当程序内存不足时才能抛出此异常，这种分配必须失败。尝试创建此字符串可能会抛出相同的异常，导致无限循环，直到真正需要该字符串为止。你可以在程序开始之前在静态缓冲区中分配空间，然后在异常发生时根据需要使用它。

11. **编写一个不使用加法运算符 (`+`)、减法运算符 (`-`)、增运算符 (`++`) 或自减运算符 (`--`) 来相加两个数字的程序。提示：使用位运算符！**

**原理分析**：
如果你观察两个位的相加，你会发现结果包含两个位：结果位和进位。因此，在二进制中加 1 和 1 的结果是 1 带有进位 1。

- 进位的逻辑：只有当两个位都是 1 时，进位才为 1。这与与运算符 (`&`) 完全相同。
- 结果位的逻辑：如果其中一个位为 1（但不同时为 1），答案为 1；否则答案为 0。这与异或运算符 (`^`) 完全相同。
- 当你得到进位时，它会被加到下一个高位位（左侧），即左移一位 (`<< 1`)。

**真值表**：

| lhs | rhs | carry (lhs & rhs) | result (lhs ^ rhs) |
| :--- | :--- | :--- | :--- |
| 0 | 0 | 0 | 0 |
| 0 | 1 | 0 | 1 |
| 1 | 0 | 0 | 1 |
| 1 | 1 | 1 | 0 |

**实现代码**：

```cpp
int Add(int a, int b)
{
    while (b != 0)
    {
        int carry = a & b;      // 计算进位
        a = a ^ b;              // 计算不带进位的和
        b = carry << 1;         // 进位左移一位，准备下一轮相加
    }
    return a;
}
```

# 第 24 天

## 测验

1. **列出并定义进程的状态。**
   - `TASK_RUNNING` — 进程正在运行或等待运行。
   - `TASK_INTERRUPTIBLE` — 任务正在睡眠（等待），可被信号中断。
   - `TASK_UNINTERRUPTIBLE` — 任务正在睡眠，不可被信号中断（通常用于硬件 I/O 等待）。
   - `TASK_ZOMBIE` — 任务已终止，但父进程尚未读取其退出码（僵尸进程）。
   - `TASK_STOPPED` — 进程已停止，通常是因为接收到了 `SIGSTOP` 等信号。
   - `TASK_SWAPPING` — 任务正在进行交换（历史遗留状态，现代内核中较少见）。

2. **描述 FIFO（先进先出）和 Round Robin（轮询）调度策略的区别。**  
   - **FIFO 调度** 按照进程在运行队列中的顺序对每个进程进行调度，且该顺序永远不会改变。FIFO 进程将一直运行，直到在 I/O 上阻塞或被高优先级进程抢占。
   - **Round Robin 调度** 轮流运行实时进程。轮询进程将运行指定的时间（时间片），然后被换出并置于优先级列表的末尾。

3. **二进制信号量和计数信号量有什么区别？**  
   从概念上讲，信号量有两种基本类型：二进制信号量和计数信号量。二进制信号量的值只为 0 或 1，在逻辑上它等同于一个互斥锁（`mutex`）。计数信号量可以取任意的非负值。

4. **列出并定义死锁的四个条件。**  
   必须同时存在四个条件才能构成死锁状态：
   1. **互斥** — 至少有一个资源是不可共享的。
   2. **持有等待** — 一个线程持有一个资源，并正在等待另一个线程持有的资源。
   3. **非抢占** — 已分配的资源只能由拥有它的线程主动释放。
   4. **循环等待** — 必须存在一组等待的线程 `{t0, t1, t2, ... tn}`，其中 `t0` 等待 `t1` 持有的资源，`t1` 等待 `t2` 的资源，... `tn` 等待 `t0` 持有的资源。

## 练习

1. **使用计数信号量，如何解决启动线程时的竞态条件？**
   - 创建一个信号量并将其值初始化为 0（或减到正在启动的线程数量的负值，视实现而定；通常做法是初始化为 0，主线程等待 N 次，子线程各自 `post` 一次）。
   - 标准模式：信号量初始化为 0。主线程创建 N 个线程后，循环 N 次 `wait`（阻塞）。每个子线程启动完成初始化后，执行 `post`（`signal`/`release`）通知主线程。主线程收到 N 次通知后继续执行，确保所有线程就绪。

2. **使用条件变量对象 `CondVar` 实现列表 24.8 中的重入示例。**

```cpp
#include <iostream>
#include "tcreate.h"
#include "mutex.h"

int data = 0;
Mutex mutex;
CondVar condVar;
bool dataReady = false;

void write_thread(void* param)
{
    for (int i = 0; i < 10; ++i)
    {
        mutex.Lock();
        data = i;
        dataReady = true;
        condVar.Signal(); // 通知读线程
        mutex.Unlock();
        // 模拟延时
    }
}

void read_thread(void* param)
{
    while (1)
    {
        mutex.Lock();
        while (!dataReady)
        {
            condVar.Wait(mutex); // 等待条件，自动释放锁并阻塞，被唤醒后重新获取锁
        }
        cout << "read: " << data << endl;
        dataReady = false;
        mutex.Unlock();
    }
}
```

第一个列表是 `ex25-05.cpp`——主程序；第二个列表是 `ex25-06.mak`——Makefile 文件；最后一个列表是 `ex25-07.cpp`——管道实现（与当天的 `lst25-02.cpp` 相同）。你需要重命名文件，以便 `make` 命令和 `#include` 指令正常工作。

**ex25-05.cpp (主程序)**

```cpp
#include <iostream>
#include "lst25-02.h" // 假设管道类定义在此头文件中

using namespace std;

int main(int argc, char** argv) {
    Pipe* rp = new Pipe;
    Pipe* wp = new Pipe;

    char msg[] = "hello world\n";
    char buf[128];

    rp->Create();
    wp->Create();

    if (fork() > 0) { // 父进程
        rp->SetToRead();
        rp->ReadFromPipe(buf);

        wp->SetToWrite();
        wp->WriteToPipe(msg);

        cout << buf << endl;
    } else { // 子进程
        rp->SetToWrite();
        rp->WriteToPipe(msg);

        wp->SetToRead();
        wp->ReadFromPipe(buf);
    }

    delete rp;
    delete wp;
    exit(0);
}
```
