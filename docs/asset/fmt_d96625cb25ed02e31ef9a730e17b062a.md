
产生结果 `'$src/foo src/bar'`。

# `($join list1,list2)`

按单词连接两个参数：第一个单词（来自第一个参数）连接后形成结果的第一个单词，第二个单词形成结果的第二个单词，以此此类推。结果的第 `$n$` 个单词来自每个参数的第 `$n$` 个单词。如果一个参数的单词比另一个多，则多余的单词将原封不动地复制到结果中。

例如，'`$(join a b, c .o)`' 产生 `'a.c b.o'`。

列表单词之间的空格不会保留；它会被替换为单个空格。

此函数可以合并 `dir` 和 `notdir` 函数的结果，从而生成传递这些函数的原始文件列表。

# 第8章：文本转换函数

`$($wildcard pattern)`

参数 *pattern* 是一个文件模式，通常包含通配符字符（在 shell 文件模式中）。*wildcard* 的结果是一个由空格分隔的列表，包含匹配模式的现有文件的名称。（参见第 4.3 节 [在文件名中使用通配符]，第 23 页。）

`$($realpath names ...)`

返回 `names` 中的每个文件名的规范绝对名称（canonical absolute name）。规范名称不包含任何 `.` 或 `..` 组件，也不包含任何重复的分符（/）或符号链接。如果发生失败，则返回空字符串。请咨询 `realpath(3)` 文档以获取可能的失败原因列表。

`$($abspath names ...)`

为 `names` 中的每个文件名返回一个不包含任何 `.` 或 `..` 组件，也不包含重复分隔符（/）的绝对名称。注意，与 `realpath` 函数不同，`abspath` 不解析符号链接，也不要求文件名指向存在的文件或目录。使用 `wildcard` 函数来测试存在性。

# 8.4 条件函数

存在一些提供条件展开的函数。这些函数的一个关键方面是并非所有参数最初都会被展开。只有那些需要展开的参数会被展开。

`$($if condition,then-part [,else-part])`

该函数在函数上下文中支持条件展开（不同于 GNU make 条件判断，如 `ifeq`，参见第 7.2 节 [条件的语法]，第 78 页）。

第一个参数在剥离所有前置内容和空白后，会被展开。如果它展开为任何非空字符串，则条件被视为真。如果它展开为空字符串，则条件被视为假。

如果条件为真，则评估第二个参数 `then-part`，并将其作为整个函数评估的结果。

如果条件为假，则评估第三个参数 `else-part`，该结果为函数的结果。如果没有第三个参数，函数求值结果为空（空字符串）。

注意，只有 `then-part` 或 `else-part` 之一会被评估，绝不会两者都。因此，它们中的任何一个都可能包含副作用（如 shell 函数等）。

`$($or condition1,condition2,condition3...])`

`or` 提供了一种“短路”操作。每个参数按顺序展开。如果某个参数展开为非空字符串，处理停止，展开的结果为该字符串。如果在所有参数展开后，它们都为假（空），则展开的结果为空字符串。

`$(and condition1[condition2[condition3...]])`

`and` 提供了一种“短路”的 AND 操作。每个参数按顺序展开。如果某个参数展开为空字符串，处理停止，展开的结果为空字符串。如果所有参数都展开为非空字符串，则展开的结果为最后一个参数的展开。

# 8.5 foreach 函数

`foreach` 函数与其他函数非常不同。它导致某段文本被重复，每次重复都对其进行不同的替换。它类似于 sh 中的 `for` 命令和 C-shell csh 中的 `foreach` 命令。

`foreach` 函数的语法为：

```
$(foreach var,list)
```

该参数被视为一组由空格分隔的名称；`prefix` 被作为一个单元。`prefix` 的值会被附加到每个单独名称的前面，生成的较长名称通过单空格连接。例如，

```
$(foreach var,foo bar,src/)
```

产生结果 `'src/foo src/bar'`。

`($addsuffix .c,foo bar)` 产生 `foo.c bar`。
`($addprefix src/,foo bar)` 产生 `src/foo src/bar`。

# `($suffix names...)`

提取 `names` 中每个文件名的后缀。如果文件名包含句号，则后缀为从最后一个句号开始的所有内容。否则，后缀为空字符串。

例如，

```
($suffix src/foo.c src-1.0/bar.c hacks)
```

产生结果 `'.c.c'`。

# `($basename names...)`

提取 `names` 中每个文件名的所有后缀。如果文件名包含句号，则基名（basename）为从开始到最后一个句号（不包括句号）的内容。目录部分的句号会被忽略。如果没有句号，则基名为整个文件名。例如，

```
($basename src/foo.c src-1.0/bar hacks)
```

产生结果 `'$src/foo src-1.0/bar hacks'`。

# `($addsuffix suffix, names...)`

该参数被视为一组由空格分隔的名称；`suffix` 被作为一个单元使用。`suffix` 的值会被附加到每个单独名称的末尾，生成的较长名称通过单空格连接。例如，

```
($addsuffix .c,foo bar)
```

产生结果 `'foo.c bar.'`。

# `($addprefix prefix, names...)`

该参数被视为一组由空格分隔的名称；`prefix` 被附加到每个单独名称的前面，生成的较长名称通过单空格连接。例如，

```
($addprefix src/,foo bar)
```

产生结果 `'$src/foo src/bar'`。

# 8.7 call 函数

`call` 函数的独特之处在于，它可以被用于创建新的参数化函数。

`call` 函数的语法如下：

```
$($call variable,param,param,...)
```

当 `make` 展开此函数时，它会将 `param` 赋值给临时变量 `$(1)`、`$(2)` 等。变量 `$()` 将包含变量。参数个数没有最大限制，也没有最小值，而且在没有参数的情况下使用 `call` 没有意义。

然后，`variable` 在这些临时赋值的上下文中作为 make 变量被展开。因此，`variable` 值中对 `$(1)` 的任何引用将解析为 `call` 调用中的第一个 `param`。

注意，`variable` 是变量名，而不是该变量的引用。

如果 `variable` 是内置函数的名称，则始终会调用该内置函数。

`call` 函数在将 `param` 参数赋值给临时变量之前会先展开这些参数。

## 8.8 value 函数

`value` 函数提供了一种方法，让你使用变量的值而不对其进行展开。

`value` 函数的语法如下：

```
$(value variable)
```

注意，`variable` 是变量名，而不是该变量的引用。

该函数的返回值是一个包含变量 `variable` 值的字符串，且不会发生任何展开。例如：

```
FOO = $PATH
all:
  @echo $(FOO)
  @echo $(value FOO)
```
