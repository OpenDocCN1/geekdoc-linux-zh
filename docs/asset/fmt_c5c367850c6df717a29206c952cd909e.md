
发行版可能会为软件开发生命周期的不同阶段维护几个不同的仓库。例如，将有一个“测试”仓库，其中包含刚构建的软件包，供那些希望为通用发布的软件包寻找 bug 的勇士使用。一个发行版通常有一个“开发”仓库，其中正在进行中的软件包旨在包含在发行版的下一次大发布中。

发行版可能还有第三方仓库。这些仓库通常需要提供某些软件，由于法律原因（如专利或 DRM 反绕过问题）无法包含在发行版中。也许最广为人知的案例是加密 DVD 支持，这在美国是不合法的。第三方仓库在软件专利和反绕过法律不适用的国家运行。这些仓库通常独立于发行版。

## 依赖关系

虽然某些软件项目选择自己进行打包和分发，但如今的软件包是由发行版供应商和相关的第三方创建的。发行版用户可以在中央仓库中获取软件包，这些仓库可能包含数千个软件包，每个软件包都是为该发行版专门构建和维护的。

过去几年中，发行版推出了一些通用软件包格式，它们不限于特定的发行版。这些包括 Snaps（由 Canonical 开发）、Flatpaks（由 Flatpak 推广）以及 AppImages。尽管它们的工作方式略有不同，但目标是让应用程序自带依赖。这并不是一个全新的想法。在 Linux 早期（想想 90 年代），有一种名为静态链接的技术，它将应用程序及其依赖项组合进单个二进制文件中。

这种方法也有一些益处。首先，它们减少了分发应用程序的努力。由于它们自带了所有内容，因此可以在任何发行版上运行。但它们也有一些严重的缺点。这种方式打包的应用程序很大，有时非常大。这产生了两个影响：首先，它们需要大量的磁盘空间来存储。在现代硬件上，这可能不是大问题，但在旧机器上这是一个真实的问题。下一个技术问题与发行版的集成有关。由于这些应用程序自带了所有东西，它们无法利用发行版提供的功能。有时，容器化的应用程序无法访问优化性能所需的系统资源。

此外还有哲学问题。这种打包方式的最大受益者是专有软件供应商。他们可以构建一个 Linux 版本，每个发行版都可以使用。无需为不同的发行版定制应用程序。用户并不渴望这些全能软件包格式，而且它们对增强开源社区并没有什么帮助。

## 总结

在接下来的章节中，我们将探索许多不同领域的程序。虽然我们提到的许多程序是默认安装的，但我们可能需要安装额外的软件包。有了对软件包管理的这些知识，我们在安装和管理所需程序时应该没有问题。

- **设备过于奇特。** 并不是所有的发行版都包含所有可能的设备驱动程序。每个发行版都构建自己的内核，由于内核是高度可配置的，它们可能会忽略某个特定的设备。通过定位并下载该驱动程序的源代码，你可以自己编译并安装该驱动程序。这个过程并不困难，但相当繁琐。我们将在稍后的章节中讨论如何编译软件。
- **硬件厂商隐藏了某些信息。** 它既没有发布 Linux 驱动程序的源代码，也没有为任何人发布过该设备的技术文档。这意味着硬件厂商正试图对设备的编程接口保密。由于我们不希望在计算机中出现秘密设备，因此最好的办法是避免此类产品。

# 15 存储介质

在之前的章节中，我们查看了如何在文件层级操作数据。在本章中，我们将考虑设备层级的数据。Linux 在处理存储设备方面具有强大的能力，无论是硬盘等物理存储、网络存储，还是像冗余磁盘阵列（RAID）和逻辑卷管理器（LVM）之类的虚拟存储设备。

然而，由于这并不是一本关于系统管理的书，我们不会尝试深入涵盖整个主题。我们将尝试介绍一些用于管理存储设备的一些概念和关键命令。

为了完成本章中的练习，我们将使用 USB 闪盘、USB 硬盘驱动器 DVD/CD-RW 光盘（针对配备了 CD-ROM 刻字机的系统）。

我们将查看以下命令：

- `mount` 挂载文件系统。
- `umount` 卸载文件系统。
- `parted` 分区操作程序。
- `mkfs` 创建文件系统。
- `fsck` 检查并修复文件系统。
- `dd` 转换并复制文件。
- `genisimage` 创建 ISO 9660 镜像文件。
- `wodm` 将数据写入光存储介质。
- `sha256sum` 计算并检查 SHA256 校验和。

# 挂载和卸载存储设备

Linux 桌面系统的最新进展使得存储设备管理对桌面用户来说变得极其简单。在大多数情况下，我们只需将设备连接到我们的系统上，它就能“即插即用”。在过去（例如 2004 年），这必须手动完成。在非桌面系统（即服务器）上，这在很大程度上仍然手动操作，因为服务器通常有极端的需求和复杂的配置。管理存储设备的第一步是将设备挂载到文件系统中。这一过程被称为“挂载”（mounting），它允许设备与操作系统交互。正如我们在第 2 章中所回顾的，Linux 等类 Unix 系统维护一个单一的文件系统，并在各个点挂载设备。这与 MS-DOS 和 Windows 等其他操作系统不同，后者为每个设备维护独立的文件系统。

名为 `/etc/fstab` 的文件列出了启动时要挂载的设备（通常是硬盘分区）。这是一个早期 Fedora 系统的 `/etc/fstab` 文件示例：

```
LABEL=/               /ext4 defaults       1 1
LABEL=/home          /ext4 defaults       1 2
LABEL=/boot          /ext4 defaults       1 2
tmpfs            /dev/shm       tmpfs   defaults       0 0
devpts           /dev/pts       devpts  gid=5,mode=620 0
sysfs            /sys            sysfs   defaults       0 0
proc             /proc           proc        defaults       0 0
LABEL=SWAP       /swap           swap        defaults       0 0
```

此示例中列出的大多数文件系统都是虚拟的，不适用于我们的讨论。对于我们的目的来说，有趣的是前三个：

```
LABEL=/               /ext4 defaults       1 1
LABEL=/home          /ext4 defaults       1 2
LABEL=/boot          /ext4 defaults       1 2
```

文件的每行由六个字段组成，如表 15-1 所示。

### 表 15-1：/etc/fstab 字段

| 字段 | 内容 | 说明 |
| :--- | :--- | :--- |
| Device (设备) | 传统上，此字段包含设备的实际名称，例如 `/dev/sda`。 | 今天的计算机、现代 Linux 发行版有许多可插拔设备，将设备与文本标签或随机生成的 UUID 关联。 |
| Mount point (挂载点) | 设备挂载到文件系统树的目录。 |
| Filesystem type (文件系统类型) | Linux 允许挂载多种类型的文件系统。大多数 Linux 系统使用名为 `ext4` 的原生文件系统，但也支持许多其他类型，包括 `FAT16`、`FAT32` (`vfat`)、`NTFS` (`ntfs`)、`CD-ROM` (`iso9660`) 等。 |
| Options (选项) | 可以带各种选项挂载文件系统。例如，可以将文件系统挂载为只读。 |
| Frequency (频率) | 单个数字，指定使用 `dump` 命令备份文件系统的顺序。 |
| Order (顺序) | 单个数字，指定使用 `fsck` 命令检查文件系统的顺序。本章稍后部分将有更多相关介绍。 |

### 查看已挂载的文件系统列表

`mount` 命令用于挂载文件系统。不带参数输入该命令会显示当前挂载的文件系统列表：
