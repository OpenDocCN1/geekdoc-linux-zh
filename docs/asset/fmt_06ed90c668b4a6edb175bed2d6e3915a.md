
使用 `.netrc` 配置可以自动登录远程服务器并初始化你的连接。它通过读取你主目录下的 `.netrc` 文件来实现。你可以配置登录名、密码和账户（如果 ftp 服务器允许或在验证时要求账户）。在下面的 `.netrc` 文件示例中，几个常用服务器的登录名为匿名：

```
machine dg-rtp.dg.com login anonymous password@pencom.com
ftp.uu login anonymous password@pencom.com
rtfm.mit.edu login anonymous password@pencom.com
machine ftp.x.org login anonymous password@pencom.com
machine prep.ai.mit.edu login anonymous password@pencom.com
machine ftp.ncsa.lluc.edu login anonymous password@pencom.com
machine emx.cc.uttexas.edu login anonymous password@pencom.com
machine boombox.micro.umn.edu login anonymous password@pencom.com
machine rs.internic.net login anonymous guest
```

> 提示：只有当你只有文件时，大多数 ftp 版本才会使用 `.netrc` 中的密码信息。为了密码安全，此文件不应被其他人访问，或者更好的是，不要包含敏感密码。

### 匿名 ftp

有一种特殊的 ftp 登录方式允许你匿名访问远程机器上的文件。匿名访问并非完全匿名，因为某些机器会记录连接、使用的密码和检索的所有文件。要使用匿名登录，请使用登录 `anonymous`（在某些机器上登录 `ftp` 可以工作）以及任何非空字符串作为密码。

> 提示：某些机器会对匿名登录进行密码验证。大多数要求你提供有效的电子邮件地址。

一旦成功匿名登录，你将获得对远程机器 ftp 子树的有限访问权限。可以使用本节描述的所有命令。有些站点有一个名为 `incoming` 的目录（ftp 树中某处的一个目录），你可以在那里放置文件。许多站点在 `/pub` 下有公开的文件。

## Uucp, uuto 和 upnick

文件复制工具 `uucp`、`uito`、`upnick` 是基础网络工具（Basic Networking Utilities）发布的一部分。你的系统中可能没有这些工具。如果存在，则优先使用较新的网络服务（例如 `ftp` 和 `rcp`）。如果你对 uu 工具感兴趣，请检查系统文档查看它们是否受支持。

为了完整起见，以下是这些工具的简要总结。详细信息请查阅每个命令的系统手册。UU 服务将一个或多个文件从一个 UNIX 机器复制到另一个 UNIX 机器。使用 `uname` 命令查看你可以到达哪些远程机器。uu 使用旧的主机命名方案，格式为 `hostname:filepath`。要将本地文件 `myfile` 复制到远程机器 `rem-host` 的 `/tmp/`，输入命令 `uucp myfile rem-host!/tmp/`。

`uito` 和 `upnick`，`uito` 将文件发送到远程 UNIX 主机的特定用户。文件存放在远程主机上的特殊位置。远程用户要接收此文件，必须使用 `upnick` 工具。远程主机和用户由语法 `rem-host!user` 指定。要将本地文件发送到机器 `sturgeon` 上的用户 `arnie`，输入命令 `uito myfile sturgeon:arnie`。

然后用户 `arter` 使用 `upnick` 工具接收文件。

当你准备好接收通过 `uito` 发送的文件时，只需不带任何参数输入 `uito` 命令。发送给你的每个文件将逐一显示。在显示时，你可以选择跳过、移动、删除或打印它。

## 其他网络服务

本节简要介绍了目前 Internet 上可用的其他服务。包括源代码、当前天气信息、财务数据、各种主题的计算机功能，以及一些更多趣味性的程序，如计算机化的塔罗牌。

注意：这些程序只有在你连接到互联网并有一个允许你建立出站连接的网关时才有用。请检查你的本地网络配置以确认。

注意：这些程序可能会让人上瘾。请确保在每次上网冲浪的间隙有足够的睡眠和社交活动。

### archie

`archie` 程序可以访问通过匿名 ftp 提供的大量文件列表。当你运行 `archie` 搜索时，服务器会在其存档列表中搜索与目标名称字符串精确匹配的名称，并将匹配项返回给用户。你可以通过指定以下选项之一来修改搜索行为：

- `-` 区分大小写的子字符串搜索。
- `-r` 正则表达式搜索。
- `-s` 不区分大小写的通写匹配搜索。例如，如果你正在寻找 `xmosaic` 的源码，你可以输入 `archie -s xmosaic`。输出列出了大量通过匿名 ftp 提供 `xmosaic` 的站点。以下是 `archie -s xmosaic` 的响应部分内容：

```
Host ftp.engr.ucf.edu
Location:/pub/linux-mirrors/tsx11/binaries/usr.bin.X11.nomirror
FILE -rw-r-- 497473 Dec 26 18:06 xmosaic-1.2.term.tar
```

对于每个具有字符串匹配的主机，都会列出包含匹配项的位置列表。使用 `archie` 输出的最佳方法是寻找一个“附近”的主机（例如，你的搜索提供者、与你的服务供应商位于同一城市/州的人、同一国家的人），并使用 `ftp` 获取所需文件。

### gopher

明尼苏达大学开发了一个名为 `gopher` 的程序，你可以用它在互联网上检索信息。他们（在通过 `boombox.umn.edu` 的匿名 ftp 提供的 `/pub/gopher/0README` 中的 README 文件中）报告道：

Internet Gopher 使用客户端/服务器协议，可以在分布式的主机网络上发布和搜索信息。`Gopher` 客户端对 gopher 世界的信息具有无缝视图，尽管这些信息分布在许多不同的主机上。客户端可以在层级化的目录和文档中进行导航——或者使用索引服务器进行搜索。`Gopher` 对目录中的每份文档进行全文搜索。

如果你想在不建立自己的 gopher 服务器的情况下测试 gopher 客户端，应该配置客户端连接到端口为 70 的 `"gopher.micro.umn.edu"`。这允许你探索明尼苏达大学的 gopher 服务器分布式网络。你可以通过 `telnet` 到 `consultant.micro.umn.edu` 并以 `"gopher"` 登录尝试 Unix 客户端。

### WorldWide Web

1991 年，欧洲粒子物理实验室启动了一个项目，该项目变成了万维网，也称为 WWW 或 W3。WWW 是探索它的最佳方式。WWW 是一套软件、约定、服务器和协议（HTTP），用于在超文本结构中组织信息。

它允许将各种类型的图片（静态和动态）、声音和文本链接到 youtube 的网络中。你可以从任何地方开始（一个特别好的起点是位于 NCSA 的默认主页或使用 `xmosaic`），并选择你感兴趣的链接。信息使用统一资源定位符 (URL) 定位，它通常看起来如下：`/hostname/path`。该协议允许你访问数据（它是 `http`，表示超文本传输协议）。`hostname` 是要访问的主机名称。`path` 给出了资源的特定位置；其他部分指向信息，不像 UNIX 文件名。URL 路径与文件名之间的区别在于，路径指向动态生成的信息（例如，当前天气预报），而返回的实际数据取决于你的 WWW 客户端支持什么。通过探索 Web，你将能够找到个人节律到关于 PowerPC 的常见问题到 SCUBA 潜水报告存档的各种信息。

伊利诺伊大学国家超级计算机应用中心开发了名为 `Mosaic` 的 Wide Web 接口。UNIX 版本在 X11 小部件上运行，被称为 `xmosaic`。

### 使用 nslookup 检查地址映射

尝试建立网络连接时常见的失败之一是主机名错误或遇到名称错误或延迟。检查主机名有效性的一种方法是使用 `nslookup` 命令。最简单的方法是运行 `nslookup hostname`：

```
$ nslookup ftp.uu.net
Name Server: lazerus.pencom.com
Address:  198.3.201.57

Name:  ftp.uu.net
Address: 192.48.96.9

$ nslookup no.such.name.org
Name Server: lazerus.pencom.com
Address: 198.3.201.57
```

> *** lazerus.pencom.com 无法找到 no.such.name.org: 不存在的域名

$ $

此查询向 DNS 请求主机名的名称（第一个例子中的 `ftp.uu.net`，第二个例子中的 `no.such.name.org`）。

提示：当添加新主机名时，DNS 可能需要一些时间才能生效，在此期间你可能会遇到错误。

## 与他人通信

作者：Ron Dippold 和 Fred Tremble

从诞生之初，互联网的目的就是促进人与人之间的通信。它最初由军事部门开发，旨在提供一个巨大的分布式通信网络，以便在遭受核攻击时能够持续运行。其设计者希望通过分布式网络来消除存在“脆弱的中心节点”的可能性。尽管具有军事背景，但它被普通大众称为“信息高速公路（Infobahn）”、“信息超级公路”和“网络空间”。二十年后的今天，互联网的优势已让许多群体实现，包括中学、家庭和私营工业。互联网基础设施最初的设计是为了支持如电子邮件和文件传输等应用程序。虽然电子邮件仍然是互联网上最流行的应用程序，但其他网络硬件和协议不断演进，以支持其他类型的通信，包括实时音频和视频。

在整个互联网发展过程中，UNIX 发挥了重要作用。大多数 UNIX 系统都内置了许多互联网协议的支持：TCP/IP（传输控制协议）。因此，本章涵盖了以下主题，并在适当的情况下强调了 UNIX 功能：

| 电子邮件 | 电子邮件允许你与世界各地的人交换消息。许多电子邮件程序都具有扩展功能，例如附加二进制文件的能力。 |
| USENET | USenet 是全球最大的电子讨论论坛。作为互联网最受欢迎的功能之一，它允许世界各地的人就各种主题进行讨论和交换交换。 |
| Talk | `talk` 命令允许两个人实时交换文本消息。 |
| IRC | 互联网中继聊天（Internet Relay Chat）扩展了“talk” 命令的功能。它提供了一个实时人员讨论论坛，类似于 CB（民用无线电）频道。 |
| 多媒体 | 互联网允许实时音频和视频的传输。 |
| 未来 | 本节提供了对互联网未来的一个展望。 |

### 电子邮件 (E-Mail)

电子邮件是互联网上使用最广泛的应用程序。它被认为是一种异步通信系统，在邮件消息发送后，它会一直留存在接收者的计算机上，直到接收者登录并检索消息。本节重点关注电子邮件的许多方面，包括邮件消息的结构、随邮件发送二进制数据（如图形文件）、电子邮件地址、消息如何在互联网上传输以及常用的终端用户邮件程序。

### 邮件消息的组件

邮件消息由两部分组成：消息头部（header）和消息正文（body）。头部包含如谁发送了消息以及何时发送等信息。正文包含实际的消息文本。有些人会在消息结束处添加一个可选的第三部分，称为“签名（signature）”。这些邮件部分的每个将在后面的章节中详细描述。

消息头部 消息头部在顶部包含几行，格式为“关键词”：值对。对于使用 `mail` 或 `mailx` 程序发送给同一本地 UNIX 主机用户的消息，其结构非常简单。例如：

```
From smithj Thu Apr 24 00:42 EDT 1997
To: jonest
Subject: Code Review Meeting
Status: R
```

（注：此处为正文内容：请计划参加明天上午 10:00 的代码审查会议。）

然而，最终通过互联网传输的邮件头部消息要复杂得多。例如：

```
From nihil@eniac.seas.void Thu Apr 24 08:15:01 1997
Flags: 000000000000
Received: from phones.com [229.46.62.22]] by
happy.phones.com (8.6.5/QC-BSD-2.1) via SMTP;
id IAA19973 Thu Apr 1997 08:14:59 -0800 for
<rdippold@happy.phones.com>
Received: from linc.cis.void (root@LINC.CIS.VOID.EDU)
(230.91.8) by phones.com (8.6.5/VOID-2.3) via SMTP;
id IAA19373 Thu, 24 Apr 1997 08:14:56 -0800 for
<rdippold@phones.com>
Received: from eniac.seas.void (nihil@ENIAC.SEAS.VOID.EDU)
(230.941.1) by linc.cis.void (8.6.5/VOID 1.4) with
ESMTP id IAA17163 45 -0500
Thu, 24 Apr 1997 11:14:45
Received: from localhost by eniac.seas.void
id IAA24236; Thu 24 Apr 1997 11:14:44 -0500
From: nihil@eniac.seas.void [B Johnson]
Sender: nihil@seas.void
Reply-To:nih@seas.void, nihil@freetenet.com
Cc: group-stuff@uunet.net
Cc: james@foobar.com
Message-ID: <19930201164.E2436@eniac.seas.void>
Subject: Reply to
```

消息头部是由被称为“邮件代理（MUA）”和“邮件传输代理（MTA）”的程序自动构建的。事实上，头部中某些项目（如抄抄和回执通知）的存在取决于邮件本身的复杂性，这些电子邮件的组件将在稍后的章节中讨论。某些头部需要一些解释。这是第一行：

```
From nihil@eniac.seas.void Thu Apr 24 08:15:01 1997
```

这一行是由本地系统上的 MTA (`sendmail`) 添加的。它被用作快速摘要，注明谁发送了消息以及时间。当许多系统将用户的所有消息存储在单个文件中时，这种摘要也用于区分一条消息的结束和下一条的开始。对于大多数程序来说，这意味着如果你尝试将其放在其之前，它就不会错误地指示新消息的开始。

```
Flags: 000000000015
```

`Flags` 字段是 Berkeley mail 特有的，也由本地程序添加。
