
`auth name` {

  `hosts`: `hostlist`

  `auth`: `auth-program`

  `res`: `res-program`

  `default`: `defuser`

    `default-domain`: `defdomain`

}

`name`值用作唯一标识身份验证定义的标签。身份验证定义使用参数和值来标识其操作。`hosts`参数使用`hostlist`值来识别身份验证定义覆盖的单个远程主机。这些可以使用主机名或数字IP 地址列出，并带有匹配的通配符。

你可以使用`res`参数指定一个根据其网络信息验证连接的身份验证程序。或者，你可以使用`auth`参数指定一个可以使用用户ID/密码对来验证连接的身份验证程序。如果你对验证远程服务器感兴趣，应该考虑INN文档，因为这是一个相当复杂的过程。

访问定义规定了针对新闻读者组的访问限制和权限类别。访问定义的语法如下：

```
access name {

  users: identity-wildcat

  newsgroups: group-wildcat

  access: permissions

}
```

`name`值必须匹配对应的身份验证定义。访问定义中定义的参数仅适用于对应身份验证定义中定义的主机。`users`参数将访问规则限制在值列出的特定用户集中。如果不存在`users`参数，则访问规则适用于所有用户。`newsgroups`参数定义了该组可以访问哪些新闻组，`access`参数定义了该组拥有的访问权限。权限定义如下：

- `R`-Read-only：允许只读访问。
- `P`-Posting：允许发布文章。
- `A`-Posting：允许发布已批准的文章（使用审核员）。
- `N`：允许执行`NEWNEWS`命令。
- `L`：允许组发布到设置为不允许本地发布的新闻组。

有一个示例`readers.conf`文件，允许所有本地新闻读者在所有新闻组中读取和发布文章：

```
# readers.conf

auth "localhost"

  hosts: "localhost, 127.0.0.1, 192.168.1.100, stdin"

  default: "<localhost>"
```

```
access "localhost" {

  users: "<localhost>"

  newsgroups: ***

  access: RPA

}
```

```
auth "localnet" {

  hosts: "192.168.*"

  default: "<user>"

  default-domain: "isp.net"

}
```

```
access "localnet" {

  users: "*@isp.net"

  newsgroups: ***

  access: "RP"

}
```

此处显示的示例`readers.conf`文件定义了两个独立的用户组。第一组称为`localhost`，启用了本地主机、地址`127.0.0.1`、地址`192.168.1.100`（本地机的网络地址）以及任何使用标准输入连接到新闻服务器的连接。Fedora Core提供的未修改的`readers.conf`允许从本地主机访问。

第二组定义了位于`192.168.`网络上的任何客户端；它允许网络上的任何客户端读取和发布所有新闻组。你可以根据网络需要调整这些地址。

## active 和 newsgroups 文件

`active`和`newsgroups`文件虽然没有被明确标识为配置文件，但对新闻服务器的运行至关重要。这些文件控制你的新闻服务器可以处理哪些新闻组。新闻服务器处理的每个新闻组必须在`active`和`newsgroups`文件都有条目。当通过Fedora Core RPM包安装时，这两个文件都位于`/var/lib/news`目录。

`active`文件的语法如下：

```
newsgroup      first      last      post
```

新闻服务器处理的每个新闻组在`active`文件中单独定义。默认的Linux INN提供了一个骨架`active`文件，定义了特殊的新闻组：

```
control      n

cancel      n

checkgroups  n
```

配置本地新闻服务器

```
newgroup     n

rmgroup      n

junk         n
```

如果你运行的是独立的新闻服务器，这个默认文件就可以用。该文件的第一个字段定义新闻组名称。第二个和第三个字段定义第一个和最后一个文章序列号。最后一个字段定义了是否允许在该新闻组发布文章。默认新闻组被设置为`n`以防止发布。

`control`和`cancel`新闻组用于接收NNTP控制文章以对新闻服务器进行维护。远程站点创建新组并删除旧组，控制文章被发送到新闻服务器执行这些任务。`control`系列新闻组处理这些文章。此外，创建`junk`新闻组是为了处理未正确发布且无处可去的文章。

`newsgroups`文件与`active`文件并行；它必须包含与`active`文件相同的新闻组定义。

## history 文件

在`/var/lib/news`目录下有INN的历史文件。这些文件用于维护发布到每个新闻组的文章的运行索引。如果这些文件与实际的新闻文章不同步，这是至关重要的，否则新闻服务器在检索文章时会出现问题。

历史文件由两部分：文本历史文件和使用Berkeley db包中的数据库程序创建的二进制索引文件。在启动`innd`守护进程之前，你必须创建这两组文件。

你使用`/var/lib/news/bin/makehistory`命令根据服务器上的新闻组文章（应为空）创建文本历史文件。Fedora提供了一个空的历史文件。

创建文本历史文件后，你创建二进制索引文件。你使用`/usr/lib/news/bin/makedbz`程序将文本历史文件转换为二进制索引文件。`makedbz -i`命令创建三个独立的二进制文件：

- `history.n.dir`
- `history.n.index`
- `history.n.hash`

你应该将这些文件重命名为标准的历史文件名（`history.dir`、`history.index`和`history.pag`），以便`innd`程序能够识别它们。历史文件创建完成后，你终于准备好启动新闻服务器了。

# 运行 innd

使用`/var/lib/news/bin/inndstart`是启动`innd`守护进程的最佳方式，它随后会启动INN软件包程序。`instart`程序必须以`news`用户ID运行。它会在后台模式下启动`innd`程序和`controlchan`程序。

`innd`程序在NNTP端口监听新闻馈送（`newsfeeds`）和新闻阅读器请求。如果远程新闻阅读器建立了连接，`innd`就会派生一个活动程序来验证远程连接并处理新闻阅读器请求。如果传入的文章是控制文章（`control articles`），它们将传递给`controlchan`程序进行处理。

Fedora Core已经彻底配置了启动新闻服务器所需的SystemV文件；你可以（以适当的方式）使用`chkconfig`、`nytsysys`、`service`或`system-config-services`来启动服务器。（请参阅第7章“管理服务”以获取示例：）

```
# /sbin/service inn start
```

当`innd`程序运行时，你可以使用`clientnd`程序来控制它，其语法如下：

```
clientnd [-h] [ -s ] [-t timeout ] command { argument... }
```

`-s`选项抑制`clientnd`命令的任何输出。该选项通常用于批处理程序。`-t`选项指定等待服务器响应的时间（秒）。如果你正在通过慢速连接到服务器或连接到一个慢服务器，可以增加`timeout`的值。

命令参数定义了`clientnd`程序对`innd`新闻服务器应该采取的操作。`-h`选项提供了供`clientnd`使用所有可用命令参数的摘要。目前，你可以使用`newsgroup`命令创建一个本地新闻组，新闻阅读器可以读取和管理该组：

```
$ clientnd newsgroup local.linux.group hoyt@maximumhoy.com
```
