
可能需要删除数据包选项中源路由（Source Routing）、路由记录（Record Route）和互联网时间戳（Internet Timestamp）的最后条目。`ip_options_undo()`函数负责这项任务。调用`ip_options_echo()`后可以跟随此函数。例如，带有路由记录选项的回显请求被设置为本地计算机，`ip_options_echo()`函数复制入站包中的设置。这些数据包选项随后被用于返回。

```
ip_options_get()
```

此函数检查IP选项是否可以通过`setsockopt()`访问。如果是，返回0；否则返回一个负错误代码。

```
ip_options_forward()
```

如果数据包需要转发，此函数会将所有关于IP选项的信息添加到数据包中。这里传递的唯一参数是socket缓冲区。

```
ip_options_rcv_srr()
```

此函数检查数据包选项中的松散路由（Loose Routing）或严格源路由（Strict Source Routing）。如果是，意味着必须调用`ip_options_rcv_srr()`。

## 14.3 层中的选项

入站数据包IP数据包有多种方式跨越IP层。它可以从底层或从高层（即IP模块）进入。图14-10显示了这种关系以及在数据包处理过程的位置。

如果IP数据包从底层进入IP层，则首先调用`iprcv()`。数据包作为socket缓冲区传递，并首先通过过滤器（netfilters）。过滤器具有防火墙功能并可以进行地址转换。为了翻译地址，调用带有`iprcv_finish()`的`NK_HOOK()`。第19节描述了如何处理过滤器。在此过程之后，执行`iprcv_finish()`。该函数的唯一参数是socket缓冲区。

本地数据包交付 如果IP数据包需要交付到本地计算机，则调用`ip_local_deliver()`。该数据包可能是较大的数据报的分片，这意味着需要检查许多内容——例如所有分片都已到达，这通过`ipdefrag()`函数检查。一旦所有分片到达，必须从第一个分片中删除所有选项，以重组成原始数据报。第一个分片始终包含数据报分片时复制的所有选项。接下来，数据包再次遍历过滤器。`ip_local_deliver_finish()`完成IP层中的本地数据包交付。

## 转发数据包

当IP数据包需要转发时，会调用`ip_forward()`函数（见图14-10的中间部分）。数据包将再次通过检查，包括对严格路由（Strict Routing）选项的测试。如果存在此选项且本地地址不在选项字段中，则会向发送者返回相应的ICMP消息。在这种情况下，选项字段中既不能指定严格路由也不能指定松散源路由（Loose Source Routing），以确保能够向发送者返回ICMP重定向消息。

会创建一个IP数据包的备份副本（包括所有数据包选项），因为数据包在后续过程中可能会发生变化。TTL变量的值减1。如果数据包过大且IP包头中设置了不可分片（Don't-Fragment）位，则数据包被丢弃。此时再次调用netfilter，但这次使用的是`ip_forward_finish()`参数。

`ip_forward_finish()`函数会检查每个IP数据包的长度。如果长度不为空，则由`ip_forward_options()`函数处理记录路由源路由选项，并在两种情况下都会调用`ip_send()`。如果数据包过大且已被分片，则`ip_send()`会调用`ip_fragment()`函数。根据`Copy`标志是否设置，只有数据包选项的一部分或仅第一个选项被复制到所有分片中。该函数非常节省空间和时间。这也意味着只要socket缓冲区的内容是第一个或唯一的分片，则会调用`ip_options_fragment()`。

下一个函数是`ip_finish_output()`，它完成了数据包的转发过程。

## 处理本地创建的数据包

本地创建的数据包在IP层上可以通过两条路径之一传输：

调用`ip_build_and_send_pkt()`函数。虽然传递的socket包含一个数据报，但它还没有协议报头。在这种情况下，数据包选项将作为参数传递，与有效负载分离传递，并设置报头结构中的所有指针。根据是否存在选项，对之前设置为“5”字节的报头长度进行更正，并使用socket缓冲区、数据包选项、目的地址和路由表调用`ip_build()`函数。接下来，`ip_send_check()`和`maybe_reroute()`调用netfilters。当数据包通过IP层时，IP选项在剩余路径上没有进一步的规则。最后，数据包传递给下层或ARP（地址解析协议——第15章）。

高层将IP作为函数`ip_queue_xmt()`的参数传递给IP层。注意，数据包选项并没有直接作为参数传递给它们；`ip_queue_xmt()`可以使用指向socket的指针进行访问。第一步是决定数据包必须发送到哪里。如果设置了源路由（Source Routing）选项，则数据包的目的地址将由下一个指定的地址确定。这需要检查`is_stricroute`选项是否存在，以及目的地址是否等于本地路由表中注册的路由器。在这种情况下，IP数据包无法传输。如果可以顺利地确定路由，下一步将像第一种方法一样清除剩余的协议头。

### 1.4 互联网控制协议 (ICMP)

互联网控制消息协议（ICMP）用于错误报告和诊断信息。虽然IP负责交付数据包，但它没有报告错误的机制。ICMP提供了这种机制。ICMP消息被封装在IP数据包内部。

以下是各种标准中定义的ICMP消息类型：

- RFC 792：通知发送者数据包无法交付。
- RFC 792：通知发送者数据包因TTL过期而被丢弃。
- RFC 792：报告IP报头选项中的错误。
- RFC 792：通知发送者数据包因拥塞而被丢弃。
- RFC 792：指示发送者使用更好的路径进行路由。
- RFC 792：用于连通性测试（回显/响应）。
- RFC 792：用于同步时钟（时间戳/响应）。
- RFC 79：用于确定主机的网络地址。

ICMP最流行的应用是`ping`命令，用于检查主机的可达性。另一个工具是`traceroute`，它使用ICMP映射到目的地的路径。

#### 1.4.1 ICMP 的功能原理

ICMP发送和接收特殊消息。当IP数据包未到达目的地时，就会发生错误消息。ICMP提供有关网络状态的信息。

## 目标不可达 (Destination Unreachable)

“目标不可达”消息的数据包包含以下字段：

| 类型-0x03 | 代码 | 校验和 |
|---|---|---|
| 未用 | | |
| IP 头部 + 64 位原始数据 | | |

```
Code = 0x00 (网络不可达)：可以发送的 IP 数据包所处的网络不可访问。这可能会发生，例如，如果路由器路由表中到接收者网络的距离被设置为无穷大。
Code = 0x01 (主机不可达)：指定网络中的所需的目标计算机无法访问。
Code = 0x02 (协议不可达)：如果另一个协议在 TCP 数据包头部中列出了目标端口，则可以生成此消息。该消息可以由路由器或端系统发送。
Code = 0x03 (端口不可达)：TCP 数据包头部中指定的接收者端口地址不可访问。在这种情况下，端系统本身是“可达”的，因此路由器和端系统都可以生成此消息。
Code = 0x04 (需要分片)：如果 IP 数据包在路由器中必须进行分片，但数据包头部设置了“不分片”（Don't-Fragment）标志，则该数据包可能无法分片。在这种情况下，路由器必须丢弃该 IP 数据包。
Code = 0x05 (源路由失败)：如果设置了 IP 选项源路由并发生错误，则向发送者返回此 ICMP 消息。
```

导致ICMP消息的数据包的IP头部加上前64位数据位，指定在ICMP“目标不可达”消息的有效负载部分。
