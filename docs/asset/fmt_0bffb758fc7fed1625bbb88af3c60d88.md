## 前台进程与后台进程

UNIX 是一个多任务操作系统，能够同时处理许多不同的任务。即使你在终端窗口中工作或在前台访问浏览器，系统也在后台运行许多进程（程序和守护进程），以确保系统的正常运行。

### 前台处理

通常，用户与 shell（解释器）之间的通信是交互式完成的，一次处理一个任务。例如，当你在终端窗口中输入一个命令时，shell 会处理该命令并显示输出。你必须等待 shell 完成任务后才能请求另一个任务。这被认为是前台处理。

### 后台进程

尽管 UNIX 是一个多任务操作系统，但在前台运行进程会将命令和程序的执行限制为串行过程，即它们一个接一个运行，并不必要地占用终端窗口。如果要让程序同时运行，它们要么在不同的终端窗口运行，要么在后台运行。

你可以通过在命令行末尾添加安培符（`&`）来在后台运行进程。后台进程与其他系统进程和 shell 程序并发运行。你可能想在后台运行进程是因为它们非常耗时（例如，对大文件进行排序或在文件系统中搜索文件），或者你可能想启动一个程序并继续与 shell 交互。例如，如果你在终端窗口中通过在命令提示符处输入 `netscape` 来启动 Netscape，Netscape 将启动，但终端窗口会显得“锁定”。这是因为终端 shell 是运行在前台的 Netscape 程序的父进程。当 Netscape 退出时，shell 提示符会返回。如果你输入 `netscape&`，Netscape 将作为后台任务启动，提示符将返回到终端窗口，允许你继续工作。

## 控制前台和后台作业

作业控制让你能够将当前在前台运行的作业（进程）放入后台，因为其运行时间超过了预期，而你需要 shell 提示符来处理其他事情。

作业控制还允许你通过将作业移动到前台、挂起或终止它们来管理后台作业。例如，假设你使用 Windows Telnet 程序登录学校的计算机，并使用 `ftp` 命令开始下载（见第 16 章“网络基础”），当你意识到自己只是坐在那里等待时，为什么不挂起（暂停）作业然后将其放入后台，以便你从 shell 提示符处继续工作呢？

过一段时间后，你可能决定将下载作业带回前台以检查进度。

## 进程调度

UNIX 的多任务能力不仅限于在当前运行进程。UNIX 包含了某些程序，允许你使用 `at` 命令调度程序在指定的时刻运行一次，并使用 `crontab` 命令调度操作（本书未涵盖该内容）。

`at` 命令允许你在未来的某个特定日期和时间运行程序、命令或 shell 脚本。例如，假设你想在 1 月 1 日 12:01 给朋友发送一个文件的内容的电子邮件。

要使用 `at` 命令调度一次性作业，请执行以下步骤：

1. 输入 `at` 命令并跟上时间规范，规范可以是：
   - `$ at 10:30am today`
   - `$ at midnight`
   - `$ at 12:01 Jan 2002`
   （更多示例请参见帮助页。）
2. 在 `at` 提示符（`at<`）下，输入要在指定时间运行的命令，然后按回车。
3. 输入下一个要运行的命令，按回车（如果完成则按 `Ctrl-D`）。

会分配一个作业号来跟踪 `at` 作业。使用 `atq` 命令查看作业队列。使用 `atm job#` 命令删除调度作业。

> **提示** 要在指定时间运行脚本文件，使用命令 `at [时间] [文件名]`。例如，`at midnight whoson` 将运行 `whoson` 脚本，该脚本运行 `who` 命令查看访问系统的用户并将输出重定向到早上的文件。

## 内存管理：物理内存与交换空间

为了同时处理多个任务，计算机必须高效管理内存。这通过使用物理内存管理和虚拟内存来实现。

### 物理内存

所有计算机都有物理或系统内存芯片。这通常被称为随机存取存储器（RAM）。这种物理内存由处理器配合内存管理单元（MMU）直接控制。RAM 是计算机的工作区域，在程序运行时在此存储程序（指令序列）和相关数据。

系统启动时 RAM 是空的。UNIX 操作系统内核首先加载到 RAM 中。其他关键系统程序如 `init` 和 `ipsched` 也会被加载。如前所述，OS 内核通过分配 CPU 时间和 RAM 来管理所有其他进程。

### 虚拟内存

许多进程同时位于 RAM 中，因此可能会耗尽内存。如果需要将新进程放入 RAM，页面置换进程会选择某个进程当前未被使用的页面，并将它们临时移到磁盘上的交换空间。页面的选择是基于“最近未使用”算法进行的。交换空间是在系统安装期间为该目的预留的原始磁盘分区或磁盘文件。进程在活动时保留在 RAM 中。交换过程使用磁盘上的交换空间，而该空间是有限的。

RAM 加上交换空间构成了虚拟内存，这是进程可以使用的最大空间。虚拟内存的访问时间远短于访问磁盘格式化区域的时间。内核管理交换过程，且内核本身不会被交换。在图 13-13 中，内核正在硬盘的交换空间上进行程序的换入换出。

### 分页

Sun 工作站上的程序可以访问多达 4 GB 的内存。系统通常配备若干兆字节的 RAM。在执行期间，进程被放置在 RAM 中（划分为页），并以页为单位在 RAM 中进出交换。这种在 RAM 中进出页的过程也称为分页。在 RAM 容量非常大的系统中，很少发生交换或分页。

## 总结

现在你已经完成了本章，你应该对以下内容有所理解：

- UNIX 使用系统进程启动、管理和终止程序。当程序如 `sort` 命令或 `vi` 编辑器启动时，操作系统会为其分配一个唯一的进程标识符（PID）。内核为进程运行分配 CPU 时间和 RAM 空间。UNIX 进程是层次结构的，类似于 UNIX 文件系统。除了进程 1 `init` 进程外，每个进程都有一个父进程。
- UNIX 系统上存在五种系统进程：
  - **守护进程**——由 UNIX 内核启动的进程
  - **父进程**——产生另一个进程的进程
  - **子进程**——父进程产生的进程
  - **孤儿进程**——父进程在返回之前终止的结果
  - **僵尸进程**——未返回父进程且有多种处理选项的子进程
- `ps` 命令用于显示进程，`ps -ef` 命令显示每个进程的完整信息。
  - `-e`——所有进程
  - `-f`——完整信息列表
  - `-u`——用户进程
- `ps` 命令的输出可以管道到 `more` 命令以一次查看一次，或者管道到 `grep` 命令以搜索特定字符串（如程序名）。
- UNIX 是一个多任务操作系统，能够在前台和后台运行作业。
- 将作业置于后台可以使用 `&`（安培符）完成。可以使用多个命令来管理后台作业，包括 `jobs`、`stop`、`fg`、`bg` 和 `kill`。
- 作业不需要在当前运行；可以使用 `at` 命令在稍后的日期和时间调度。
- 长运行或无响应的进程可以使用 `kill` 命令指定进程 PID 来终止。大多数进程可以使用基本的 `kill PID` 命令终止，也称为软杀。杀死 shell 进程需要 `kill -9 PID` 命令，也称为强杀。

计算机具有物理内存，即随机存取存储器（RAM）。在安装期间，UNIX 操作系统在硬盘上预留了一个交换空间。当程序执行时，它们从硬盘复制到系统 RAM 中并被分为页。为了充分利用 RAM，最近未使用的程序部分会被分页输出到硬盘的交换区域。这允许更多程序装入 RAM。如果需要硬盘上的页，它们可以被分页回 RAM。物理 RAM 和跨硬盘的交换空间的组合被称为虚拟内存。

- `&` 在后台运行作业

# 系统进程与内存管理（术语表）

**父进程** 产生另一个进程的进程。系统启动后，会调用一个名为 `init` 守护进程的进程。除了 `init` 之外，每个进程都有父进程。

**物理内存** 所有计算机都有物理内存（或系统内存）微芯片。通常被称为随机存取存储器（RAM）。这种内存由处理器配合内存管理单元（MMU）进行控制。

**PID** 在 UNIX 系统上运行的每个程序都会创建一个进程，并被分配一个唯一的进程标识符（PID）。系统使用 PID 来识别和跟踪进程，直到其完成。

**进程** UNIX 系统上由内核管理的一项工作或任务单元。每个进程都会被分配 CPU 时间、RAM 和进程 ID（PID），直到其完成。

**进程调度** 在预定时间运行进程的能力。可以使用 `at` 命令和 `crontab` 命令来调度 UNIX 任务或进程。

**信号** 根据实现方式的不同，UNIX 中目前定义了 30 到 40 个信号。每个信号都关联一个数字和一个名称。信号用于终止、挂起和继续进程。`kill -9` 命令使用信号 9 来终止 shell。

**产生** 进程可以启动或产生子进程，从而创建一个类似于文件系统结构、具有父子关系的进程层次结构或树。

**虚拟内存** 交换过程使用磁盘上的交换空间，该空间是有限的。RAM 加上交换空间构成了虚拟内存，这是进程可以使用的最大空间。

**僵尸进程** 有时，子进程不会向父进程返回其输出。该进程在系统中变得“丢失”了。

## Korn 和 C Shell 的基本特性

### 简介

shell 是 UNIX 系统的主要用户界面。shell 的概念在第 1 章“UNIX 计算环境”中，与其他关键的 UNIX 操作系统组件（内核和文件系统）一起引入。UNIX 环境为许多内置（Bourne、C、Korn）和第三方 shell 提供支持。本章简要回顾了 shell 的功能，并重点介绍今天最广泛使用的两个 shell：Korn shell 和 C shell。它将更详细地介绍每个 shell 的独特特性，并提供如何通过使用自定义提示符、别名、历史记录和重新执行命令来提高效率的信息。最后，还讨论了用于自定义工作环境的本地和全局变量。

### shell 回顾

shell 是用户和内核之间的接口。它充当了解释器或翻译器的角色。换句话说，shell 接受你发出的命令，解释这些命令并执行相应的程序。

shell 可以是命令行驱动的，也可以是图形化的。此外，shell 是可互换的，这使得可以在任何时候启动它们或在它们之间切换，以使用其他 shell 中不可提供的某些功能。

当你登录系统时，shell 是第一个启动的程序。除了作为命令解释器的主要作用外，shell 程序还具有许多特性和内置命令，使得与系统的交互和完成任务变得简单。许多 shell 特性在书中已经介绍过。

- **通配符匹配**——（参见第 5 章“访问文件和目录”。）预留的特殊字符，用于指定选择模式，以选择一个或多个文件作为处理组。例如，`*slip chap*`。
- **输入/输出重定向**——预留的特殊字符用于重定向输入和输出（`>`、`>>` 和 `<`）。例如，`who > userlog`。（请参见第 7 章“高级目录和文件管理”。）
- **管道**——（参见第 7 章。）用于连接一个或多个简单命令以形成复杂的操作。例如，`who | sort ip`。
- **后台处理**——（参见第 13 章“系统进程与内存管理”。）允许程序和命令在后台运行，同时用户继续与 shell 交互以完成其他任务。例如，`sort large&`。
- **编程语言（高级主题）**——用于创建执行复杂操作的 shell 脚本的编程特性。例如，将编写一个脚本来设置所有用户账户、创建家目录，并将实验课文件复制到每个用户的家目录中，供 UNIX 基础课程使用。

本章重点关注 Korn (ksh) 和 C (csh) shell，这是终端用户最常用的 shell。你可以使用 `ps`（进程状态）命令查看你正在使用哪种 shell。

### Korn shell 简述

Korn shell 是由 Bell Labs 的 Stephen Korn 开发的，它是 Bourne shell 的超集。Bourne shell 是 UNIX 环境的原始 shell，也是 Solaris 计算环境的默认 shell。Bourne shell 是由 Stephen Bourne 为 AT&T System V2 UNIX 环境开发的，该 shell 不具备别名、历史记录或命令行编辑功能，主要供系统管理员使用。Bourne shell 的提示符是美元符号（`$`），类似于 DOS 的 `C:>` 提示符。

Korn shell 具有 Bourne shell 的许多功能，并增加了别名、历史记录和命令行编辑等功能。Korn shell 是最广泛使用的 shell，也是用户的行业标准。Korn shell 的提示符也是美元符号（`$`）。

### C shell 简述

C shell 基于 C 编程语言。与 Korn shell 类似，它由 Sun Systems 的 Bill Joy 开发，具有比 Bourne shell 更多的额外特性，并且今天仍被广泛使用。C shell 的提示符是百分号（`%`）。

### 其他特性

除了之前列出和早些介绍的特性外，Korn shell 还具有其他让交互更简单更快速的特性：

- **命令别名**——通过允许你为命令指定一个标记，为输入命令提供快捷方式——例如创建一个执行 `ls -l` 的别名
- **命令历史和命令行编辑**——允许你构建并引用命令历史，而无需重新输入——例如，重复以 `vi` 开头的最后一个命令。命令行编辑允许你回溯命令并进行修改
- **shell 变量**——作为 shell 脚本和自定义工作环境的预定义和自定义变量——例如，修改预定义 shell 变量将提示符从 `$` 改为 `UNIX`

## Korn Shell 别名

在 shell 中赋予不同名称的方法。别名是使用 shell 命令时提高效率和生产力的极佳方法。当你设置命令行时，别名仅在创建它们的 shell 中激活。将别名添加到 `.kshrc` 文件中（见第 15 章“自定义你的登录环境”）可以在登录时或每次打开新窗口或 shell 时激活它们。以下显示了创建别名的 `alias` 命令的基本语法：

```
alias name='command'
```
