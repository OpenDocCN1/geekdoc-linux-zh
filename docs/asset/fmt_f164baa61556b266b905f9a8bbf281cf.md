## 4.2 配置日志记录

应当配置日志服务以防止信息泄露并将日志聚合到远程服务器上，以便在系统遭受妥协时进行审查。集中日志服务器为进一步的分析、监控和过滤提供了单一入口点。

日志记录的安全准则

- 确保在客户端和日志服务器之间实现了传输层安全。
- 确保根据环境要求进行日志轮转。
- 确保所有本地生成的日志具有适当的权限。
- 确保所有安全日志发送到远程日志服务器。
- 确保记录了所需的事件。

涵盖范围

本节将涵盖使用 `syslog` 或 `journald` 的最小最佳实践。这些建议的编写方式使得每条建议彼此完全独立，且仅实现其中一种。

- 如果您的组织使用了完全超出 `syslog` 或 `journald` 的企业级日志系统，则以下建议不直接适用。但是，无论实现何种解决方案，都应遵循这些原则。如果企业解决方案包含了这些工具中的一种，则应仔细考虑以下建议以确定其适用性。
- 如果您的组织同时使用 `syslog` 和 `journald`，请注意建议是否适用。

未涵盖范围

- 未使用 `syslog` 或 `journald` 的日志系统。取决于情况，未涵盖。

## 4.2.1 配置 journald

`systemd` 软件包包含一个名为 `systemd-journal` 的服务。

`systemd-journald` 创建并维护索引日志。它从本地环境等各种源收集消息：

- `StandardOutput=journal` RFC364 syslog
- `StandardError=journal`
- 通过 `/dev/kmsg` 的内核消息
- 通过 `systemd-journal` 获取的结构化消息

## 4.2.1.1 确保 journal 配置为发送到远程主机

### 4.2.1.1.1 确保 systemd-journal-remote 已安装（自动化）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

描述：

`Journald`（通过 `systemd-journal-remote`）支持将收集的日志事件发送到远程主机或接收来自远程主机的消息，从而实现日志管理。

原理：

将日志存储在远程主机上可以保护日志完整性免受本地攻击。如果攻击者获取了本地系统的 `root` 权限，他们可能会篡改或删除存储在本地系统的日志数据。

```bash
# dpkg-query -W -f='$(binary:Package)\t$(Status:Status)\n'
systemd-journal-remote
```

修复：

运行以下命令安装 `systemd-journal-remote`：

```bash
# apt install systemd-journal-remote
```
