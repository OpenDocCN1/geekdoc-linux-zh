
[[graph:]]) echo "$REPLY" is a visible character.";

[[punct:]]) echo "$REPLY" is a punctuation symbol.";

[[space:]]) echo "$REPLY" is a whitespace character.";

[[xdigit:]]) echo "$REPLY" is a hexadecimal digit.";

esac

```

运行此脚本会产生：

```

[me@linuxbox ~]$ case4-1

Type a character > a

'a' is lower case.

```

该脚本大部分情况下可以工作，但如果一个字符匹配多个 POSIX 字符类，它就会失败。例如，字符 `a` 既是小写字母又是字母，还是十六进制数字。在 4.0 之前的 bash 版本中，`case` 无法同时匹配多个项。现代版本的 bash 添加了 `;;&` 符号来终止每个操作，这样我们可以这样做：

```bash
#!/bin/bash

# case4-2: test a character

read -r n 1 -p "Type a character > "

echo

case "$REPLY" in

  [[upper]])    echo "$REPLY' is upper case." ;;&

  [[lower]])    echo "$REPLY' is lower case." ;;&

  [[alpha]])    echo "$REPLY' is alphabetical." ;;&

  [[digit]])    echo "$REPLY' is a digit." ;;&

  [[graph]])    echo "$REPLY' is a visible symbol." ;;&

  [[punct]])    echo "$REPLY' is a punctuation symbol." ;;&

  [[space]])    echo "$REPLY' is a whitespace character." ;;&

  [[xdigit]])  echo "$REPLY' is a hexadecimal digit." ;;&

esac
```

当我们运行这个脚本时，会得到：

```

+ me@linuxbox~$ case4-2

Type a character > a

'a' is lower case.

'a' is alphabetical.

'a' is a visible character.

'a' is a hexadecimal digit.

```

添加 `;;&` 语法允许 `case` 继续下一个测试，而不是简单地终止。

## 总结

`case` 命令是我们编程技巧箱中一个实用的补充。正如我们将在下一章看到的，它是处理某些类型问题的完美工具。

## shift——获取大量参数

但当我们给程序大量的参数（例如下面的 `*`）时会发生什么？

```

+ me@linuxbox~$ posit-param *

Number of arguments: 8

```

shell 提供了一种方法（尽管很笨拙）来这样做。`shift` 命令每次执行时会导致所有参数“向下移动”。实际上，通过使用 `shift`，我们只需要一个参数（除了变化的 `$0`）即可工作。

```bash
#!/bin/bash

# posit-param2: script to display all arguments

count=1

while [[ $# -gt 0 ]]; do

  echo "Argument $count = $1"

  count=$((count + 1))

  shift

done
```

每次执行 `shift`，`$2` 的值就会移动到 `$1`，`$3` 的值移动到 `$2`，依此类推。`#` 的值也会减一。在 `posit-param2` 程序中，我们创建了一个循环，评估剩余参数的数量，只要至少有一个就继续执行。我们显示当前参数，并在每次循环迭代时增加计数变量，以提供处理参数的运行计数，最后执行 `shift` 将下一个参数加载到 `$1`。这是该程序的运行情况：

```

[linux]$ posit-param2 a b c d

Argument 1 = a

Argument 2 = b

Argument 3 = c

Argument 4 = d

```

有时，将所有位置参数作为一个组进行管理是有用的。例如，我们可能想为另一个程序编写一个“包装器”（wrapper）。这意味着我们创建一个脚本或 shell 函数来简化对另一个程序的调用。在这种情况下，包装器提供了一系列复杂的命令行选项，然后将参数列表传递给底层程序。

| 参数 | 说明 |

| `$*` | 展开为位置参数列表，从 1 开始。当被双引号包围时，它会展开为一个包含所有位置参数的双引号字符串，每个参数之间由 `IFS` shell 变量的第一个字符（默认为空格）分隔。 |

### 更完整的应用

在长时间停顿之后，我们将恢复对 `sys_info_page` 程序的工作，它上次出现在第 27 章。我们的下一个新增内容将为程序添加以下几个命令行选项：

**输出文件** 我们将添加一个选项来指定一个包含程序输出内容的文件名。它将被指定为 `-f file` 或 `--file file`。

**交互模式** 该选项将提示用户输入输出文件名，并判断指定的文件是否已存在。如果存在，将在覆盖现有文件之前提示用户。此选项将通过 `-i` 或 `-interactive` 指定。

**帮助** -可以指定 `-h` 或 `--help` 导致程序输出一条信息量丰富的用法消息。

以下是实现命令行处理所需的代码：

```
usage() {

  echo "PROGNAME: usage: $PROGNAME [-f file | -i]"

  return

}

# process command line options

interactive=

filename=

while [[ -n "$1" ]]; do

  case "$1" in

    -f | --file)

      filename="$2"

    -i | --interactive)

      interactive=1

    -h | --help)

      usage

      exit

    *)

      usage >&2

      exit 1

  esac

  shift

done
```

首先，我们添加了一个名为 `usage` 的 shell 函数，在调用帮助选项或尝试使用未知选项时显示消息。

接下来，我们开始处理循环。只要位置参数 `$1` 不为空，循环就会继续。在循环结束时，我们有一个 `shift` 命令来移动位置参数，确保循环最终终止。

在循环内部，我们有一个 `case` 语句来检查当前的位置参数以其是否匹配任何支持的选项。如果找到支持的参数，就会执行操作。如果找到未知选项，将显示用法消息并脚本带错误退出。

`-f` 参数的处理方式很有。当检测到它时，它会触发额外的 `shift`，将位置参数 `$1` 移动到为 `-f` 选项提供的文件名。

## getopts 选项

之前显示的位置解析代码是处理当前任务的良好解决方案，但并不是我们唯一可以采取的方法。shell 内置了 `getopts`（不要与同名的外部命令 `getopt` 混淆），它可以为我们完成一些工作。每当调用 `getopts`（通常在循环中），它都会返回当前参数名称并增加计数器 `OPTIND` 以指向下一个位置参数。如果选项需要参数，则该参数将在变量 `OPTARG` 中返回。

`getopts` syntax var [ arg ]

```
getopts optstring [arg ...]
```

`optstring` 是由单字符选项名称组成的字符串。`getopts` 不（容易地）支持长格式选项。此外，如果选项名称后面跟着冒号，则意味着该选项需要参数。

虽然 `getopts` 只支持单字符选项名称，但它允许将多个选项组合在一起。如果 `optstring` 以冒号开头，`getopts` 在出现无效选项或缺少参数时将忽略自己的错误消息。每当发生这两种错误之一时，`getopts` 将该选项放在 `OPTARG` 中。

通常 `getopts` 处理位置参数，但当看到它的运行时会变得更清晰。

```bash
#!/bin/bash

PROGNAME=$(basename "$0")

interactive=

filename=

usage() {

  echo "PROGNAME: usage: $PROGNAME [-f file | -i]"

  return

}

while getopts :f opt; do

  case $opt in

    f) filename="$OPTARG";

    i) interactive=1;

    h) usage;

    \?) echo "option '$OPTARG' invalid";

    :) echo "option '$OPTARG' missing argument";

  esac

done

echo "$interactive" filename = "$filename"
```

让我们详细查看这段代码。我们从变量定义和用法函数的定义开始。接下来，通过将 `getopts` 命令放在 `while` 循环中进入有趣的部分。我们的字符串以冒号开头，这将抑制错误消息。冒号后面跟着我们的选项字母。最后，我们指定一个变量（opt）来存储结果。循环一直持续到 `getopts` 用完参数。

在循环内部，我们有一个 `case` 语句来处理 `opt` 返回的结果。除了 `case` 语句中的最后模式外，这一切看起来都符合预期。当检测到无效选项时，`getopts` 返回 `?`。注意在 case 语句中，转转义问号，因为 shell 将其解释为通配符。接下来，我们有 `:`，当选项缺少必要参数时 `getopts` 返回它。

让我们观察它的运行：

```

[me@linuxbox ~]$ ./getopts-test

interactive = '' = ''

[me@linuxbox ~]$ ./getopts-test -I

interactive = '' filename = ''

[me@linuxbox ~]$ ./getopts-test -f foo.html

interactive = '' filename = 'foo.html'

[me@linuxbox ~]$ ./getopts-test -if foo.html

interactive = '1' filename = 'foo.html'

[me@linuxbox ~]$ ./getopts-test -i foo.html

interactive = '1' filename = 'foo.html'

[me@linuxbox ~]$ ./getopts-test -a

option 'a' invalid

interactive = '' filename = ''

```

```bash
[me@linuxbox]$getopts-test -f

option 'f' missing argument

interactive = '' filename = ''
```

那么，我们应该使用 `while/shift` 还是 `getopts` 呢？这取决于我们的需求。`while/shift` 方法提供了最大的控制权（包括轻松实现长参数），而 `getopts` 需要的代码更少，并支持单连字符多选项语法。
