
## 设置现有服务并准备迁移

- 设置你现有的服务（如 Apache 服务器、Samba 或 Netatalk 文件与打印服务），并使用测试数据运行至少几天，以确保一切运行正常。详情请参阅第 7.4 节和第 7.5 节。不要忘记确保你在 `/etc/` 目录下所做的任何更改或自定义脚本（包括 `/etc/rc.d/` 中的任何内容）也已根据需要在新服务器上完成。特别重要的一点是记得复制 `/etc/passwd`、`/etc/group` 以及（如果你使用 shadow 密码的话）`/etc/shadow` 中的用户账户信息！

- 关闭旧服务器上的服务，这样你的文件系统将看到最少的文件更新活动。显然，你不希望在向新服务器恢复数据时，用户还在旧服务器上上传网页和接收电子邮件！作为 root 用户，你可以使用以下命令关闭大部分服务：

```
killall httpd atalkd smbd nmbd sendmail ftpd
```

上述命令将关闭 Web 服务器、文件与打印服务以及电子邮件服务器。（你运行的服务可能比我上面列出的少或多。请检查你的进程列表并终止任何你认为适当的服务；详情请参阅第 9.2 节。）

你可能还想编辑旧服务器上的 `/etc/inet.conf` 文件，并使用 `#` 字符注释掉任何可能导致文件系统更新的服务（如 FTP、IMAP 和 POP3 服务）。然后，再次以 root 身份：

```
killall HUP inetd
```

上述命令将重新加载针对 Internet 服务的 TCP 封装器（安全封装），使得未来对你在 `/etc/inet.conf` 文件中禁用的任何服务的连接将不会被加载。

# 第 11 章 使用 Linux 进行企业级计算

现在你应该能够将数据从一个系统移动到另一个系统了。你可能已经为新服务器准备好了运行所需的所有内容，包括你想要安装但未随 Red Hat 发行版附带的任何额外软件。因此，你可能需要备份存储在 `/home/`、`/var/spool/` 以及可选文件系统（如可能的 `/archive/`）中的任何数据。这是一个使用 `tar` 工具制作数据压缩文件的示例命令：

```
cd /
tar zcvcp /tmp/backup_data.tar.gz -exclude=var/spool/ squid \
    home archive var/spool
```

上述命令将把你的 `/archive/`、`/home/` 和 `/var/spool/` 文件系统（或子目录，取决于你如何设置系统）备份以压缩格式写入名为 `/tmp/backup_data.tar.gz` 的文件中。确保你有足够的空间创建备份，或者将其写入其他地方！

> 提示：你可以使用 `du` 工具来帮助确定所需的空间。例如，要确定 `/archive/` 和 `/home/` 目录树的需求，

```
du -h -s /archive /home
```

请记住，上述命令将报告数据的实际大小，但如果你使用 `tar` 的 `z` 选项（如上所示）来压缩镜像文件，你的空间需求可能会少得多。请考虑 `du` 命令输出结果作为所需空间的最坏情况估计。

现在，你可以从 tar 文件将备份数据恢复到新服务器上。你可以直接通过 NFS 恢复（配置 NFS 的详情请参阅第 7.6 节），或简单地使用 FTP 传输并在本地解压。以下是一个恢复已备份文件的示例：

```
cd /
tar zxvpf /tmp/backup_data.tar.gz
```

- 接下来，如果有必要，交换你的 IP 地址，以便新服务器可以通过旧地址被访问。

- 最后，你可能希望关闭并重启服务器，以确保没有出现意外的错误信息。详情请参阅第 6.7 节。

完成后，请确保一切运行符合预期！如果不是，你始终可以重新启用在旧服务器上禁用的任何服务并重启它们，以便用户在你解决新服务器上的问题之前继续使用它（但请记住，如果你选择这样做，将需要重复上述步骤）。

# 第 12 章 保持服务器安全的策略

Linux 无疑可以被认为比其他供应商的操作系统更安全——或更安全。诚然，随着 Linux 越来越流行，它正成为黑客集中精力破入的一个非常有吸引力的目标。然而，尽管不时会发现漏洞，但 Linux 的开放性质通常意味着此类漏洞会被很快修补，并且安全公告会广泛发布，包含临时变措施或指向更新软件的指针。

## 保持服务器安全的核心措施

虽然对安全问题的详细讨论超出了本文的范围，但以下清单提供了一些你应该做的最重要的事情：

- 升级系统工具、应用程序和内核：入侵最常见的原因之一是没有保持系统更新。定期升级系统内核、工具和用程序可以确保你的系统不会充满存在已知漏洞的旧项目。关于保持系统更新的详情，请参阅第 4.9 节以及第 10.3 节。

- Shadow 密码：你应该使用 Shadow 密码；切换到这种格式非常简单！详情请参阅第 6.6 节。

- 明智密码管理：确保密码（特别是提供 shell 权限的用户密码）足够强大且经常更换。此外，如果你有多台服务器，不要对所有服务器使用相同的密码（否则，如果黑客通过发现的密码破解了一台服务器，他们就能破解所有服务器）。

- 使用安全 shell `ssh`：用 `ssh` 代替 `telnet`。`Telnet` 是安全的，原因有两个：第一，会话未加密，这意味着包括用户名和密码在内的一切都以明文传输。第二，开放的 `telnet` 端口是黑客尝试连接的首选位置之一。

> 注意：上述列出的 SSH RPM 文件是国际版本。如果您在美国在美国或加拿大，可以选择下载美国版本的软件包（其可能具有更强的加密算法）；这些软件包在版本号后面所使用的后缀是 `us` 而不是 `i`。根据美国法律，向美国或加拿大以外地区出口强加密产品是非法的。希望有一天，美国司法部的那些蠢货们最终能开开眼来，取消这一愚蠢的限制（红帽发行版 Red Hat 正因为这个原因没有在他们的发行版中包含 SSH，而我们都深陷其苦）。

> 注意：如果您决定切换到使用 `ssh`，请确保在所有的服务器上都安装并使用它。拥有五个安全的服务器和一个不安全的服务器是浪费时间，尤其是如果您愚蠢地对多个服务器使用同一个密码，情况更是如此。

- 限制对外部服务的访问：接下来，您应该编辑 `/etc/hosts.allow` 以及 `/etc/hosts.deny` 文件，以限制外部主机对服务的访问。这里是限制 `telnet` 和 `ftp` 访问的示例。首先是 `/etc/hosts.allow` 文件：

```
# hosts.allow

telnetd: 123.12.41, 126.27.18, .mydomain.name, .another.name
in.ftpd: 123.12.41, 126.27.18, .mydomain.name, .another.name
```

上述配置允许 IP C 类中所有 `123.12.41*` 和 `126.27.18*` 的主机，以及任何 `mydomain.name` 和 `another.name` 域内的主机建立 `telnet` 和 `ftp` 连接。

接下来，是 `/etc/hosts.deny` 文件：

```
# hosts.deny
telnetd: ALL
in.ftpd: ALL
```

- 关闭并卸载未使用的服务：编辑您的 `/etc/inetd.conf` 文件，并禁用（即使用 `#` 字符注释掉）任何不需要的服务（如果您按照上述建议使用 `ssh`，那么您可能希望禁用 `telnet` 服务）。完成后，以 root 身份输入 `/etc/rc.d/init.d/inet restart` 以带上更改重启 `inetd` 守护进程。

- 安装安全检测系统：考虑安装此类安全程序，例如 `Tripwire`（参见 http://www.tripwiresecurity.com/），它可以检测入侵行为；以及 `Abacus Sentry`（参见 http://www.psionic.com/abacus/），它可以帮助防止入侵。
