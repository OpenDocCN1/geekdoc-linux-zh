
尽管我之前说过芬兰在科技领域如此领先，但 Sinclair QL 并没有在欧洲第七大国家（按此语境推测或指特定市场）取得重大突破。由于市场如此狭小，每当你想为这台标志性、前沿的机器购买升级配件时，你都不得不通过邮寄订单从英国购买。这意味着你不得不翻遍目录，直到找到卖你想要东西的商家。然后你还得准备汇票，并等待数周的交货时间（毕竟这是在亚马逊网站和信用卡出现之前的日子）。当我想把 RAM 从 128 KB 扩展到 640 KB 时，我就得这么做。当我购买新的汇编器（用于将汇编语言转换为机器代码，即 0 和 1）和编辑器（基本上是一个用于编程的字处理程序）时，流程也是如此。

新的汇编器和编辑器都工作正常，但它们是放在微型驱动器上的，无法放入 EEPROM。所以我写了自己的编辑器和汇编器，并在我所有的编程工作中使用它们。两者都是用汇编语言编写的，用今天的标准来看，这简直愚蠢透顶。这很复杂且耗时——我估计，用汇编语言解决一个问题所需的时间是 C 语言（当时已可用）的一百倍。

我给机器自带的基本解释器添加了几条命令，这样当我想要编辑某些东西时，基本上只需自动运行我的编辑器，它就能立刻出现。我的编辑器比机器自带的编辑器快。我特别自豪于我能多快地将字符写入屏幕。通常，对于这样的机器，在屏幕上填满字符所需的时间太长，以至于你能看到文字滚动。而我很高兴的是，使用我的编辑器，你输入文字的速度如此之快，以至于当你快速向下滚动时，会产生一种模糊效果。这对我来说很重要。这一改进让机器感觉流畅了许多，我知道我为使其运行得如此快速付出了大量工作。

在这个时期，我身边没有太多像我这样热衷于计算机的人。学校里有一个计算机俱乐部，但我花在那里的时间不多。那基本上是为那些想了解计算机的孩子设立的。我的整个高中只有大约 250 名学生，我不认为有其他人从十岁起就开始使用计算机了。

我在 Sinclair QL 上喜欢做的很多事情之一就是制作游戏克隆版。我编写了 VIC-20 上那些我曾享受过的游戏的克隆版，有时还会增加一些增强功能。但大多数情况下它们并没有更好：是更好的机器，而不是更好的概念。

我最喜欢的游戏可能是《小行星》（Asteroids），但我始终无法制作出很好的克隆版。原因在于，当时所有的街机《小行星》游戏都是使用真正的矢量图形制作的。不同于基于小点——像素——的图形，它们的图形实际上是按照阴极射线管（CRT）的工作原理制作的，即电子从 CRT 后方的电子枪射出，并由磁铁偏转。通过这种方式，它们获得了更高分辨率的图形，这很难在其他设备上轻易复制。你可以制作克隆版，但如果你在没有特殊图形处理能力的计算机上编写，它看起来不会像原始的《小行星》游戏。

我记得我用汇编语言制作过一个《吃豆人》（Pac-Man）的克隆版。第一步是大概回忆一下《吃豆人》角色的样子。然后，你试图在 16x16 的方格纸上用颜色画出它们。如果你擅长艺术，你可以做得很好。但如果你像我一样是个“艺术盲”，结果看起来就像《吃豆人》的病态表亲。

好吧，所以它不是一个非常棒的克隆版。但我对它感到非常自豪。游戏实际上是可玩的，我把它寄给了一家发表计算机代码的杂志。我之前曾向杂志出售过其他程序，所以我认为这是顺理成章的。

并不然。

问题之一是程序是用汇编语言编写的。这意味着如果你从杂志上复制时犯哪怕最轻微的错误，它就无法运行。

我也写了一些自己的游戏。但是创造游戏需要特定的心态。因为游戏需要大量的性能，你必须深入计算机的硬件底层。我确实能做到，但我不具备游戏性思维。让一款游戏伟大的通常不是它的速度有多快或图形有多好。必须有什么东西能吸引你去玩它——什么能留住你。这就像电影一样。特效是一回事，但你还需要情节。而我的游戏从来没有情节。游戏必须有一种递进感，一个想法。通常，递进感仅仅意味着游戏变得越来越快。《吃豆人》就是这样做的。有时迷宫会变化，或者怪物追踪你的能力会增强。

我对《吃豆人》感兴趣的一点是解决图形闪烁的问题。这在早期的计算机游戏中是一个相当普遍的问题，因为没有特殊硬件，你的角色就会闪烁。移动角色的方式是先移除旧副本，再写入新副本。如果时机不好，人们实际上能看到没有副本的时刻，因此会看到闪烁。你可以用多种方式绕过这个问题。你可以先绘制新角色，然后移除旧角色，但必须小心不要移除旧角色被新角色遮挡的那部分。这样，你看到的不是恼人的闪烁，而是一个不错的效果——你有时会在屏幕上看到旧角色的影子。大脑会以良好的方式解释这种情况。它不会闪烁，但会产生一种运动模糊。这种解决方案的麻烦在于它相当昂贵且耗时。

游戏始终处于技术前沿是有原因的，而且它们通常是程序员创建的第一类程序。部分原因是，有些最聪明的程序员是十五岁在房间里玩耍的孩子。（这是我十六年前的想法，我仍然怀疑这是真的。）但游戏具有开创性的另一个原因是：游戏往往会推动硬件发展。

如果你看看今天的计算机，它们通常已经足够快了

## 二

大学第一年，一台 Sinclair QL 坐在我位于 Petersgatan 一楼卧室窗户下的桌子上，但我并没有在编程方面做太多事。部分原因是我想专注于学业。但另一方面，我也只是发现自己缺乏一个要在电脑上做的项目。缺乏项目，你就缺乏热情。你正在试图想出一些能激励你的东西。

那似乎是我加入军队的完美时机，而我原本也知道无论如何我最终都会这么做。我当时十九岁，对我电脑的各种缺点感到恼火，也没有依附于任何有趣的电脑项目。我登上一列开往拉普兰的火车。

我已经表明，我对自己在服役期间，包括对体力要求在内的许多方面，有多么无知。因此，在经历了十一个月的“带枪械的体育教育”后，我觉得自己完全有理由在剩下的几十年里沉浸在幸福的不作为中，唯一的运动就是往键盘上敲代码，或者用手指握着一杯皮尔森啤酒。（事实上，退伍后第一次接近运动的活动，直到退伍将近十年后才发生，当时大卫强迫我陪他去半月湾的杀手级海浪里玩冲浪板。我差点淹死，腿疼了好几天。）

军队服役期于 1990 年 5 月 7 日结束。虽然托芙（Tove）会告诉你我记不清我们的结婚纪念日，但我绝对忘不了我退伍的日期。

我最想做的第一件事是养一只猫。

我有个朋友，他的猫几周前刚生了一窝小猫，所以我买了剩下的那只唯一的小猫。它是一只白色的雄性猫，非常漂亮——因为它头几周都在户外度过，所以很容易适应在我母亲公寓里里外外生活。我给它取名叫兰德（Randi），这是米瑞德希尔（Mithrandir，即《魔戒》中的白袍巫师）的简称。现在它已经十一岁了，和它的主人一样，已经完全适应了加州的生活方式。

不，我认为那个整个夏天我都没有做什么有建设性的事。大学第二年的课程要到秋天才开始。我的电脑还不太好用。所以我要么穿着我破烂的浴袍闲逛，要么逗兰德玩，或者偶尔和朋友们聚在一起，让他们嘲笑我打保龄球或斯诺克的努力。好吧，我确实对下一台电脑进行了一些幻想。

我面临着一个极客的两难困境。像任何受 68008 芯片熏陶长大的正经电脑纯粹主义者一样，我鄙视 PC。但当 386 芯片在 1986 年推出时，PC 开始变得，嗯，有吸引力。它们能够做 68020 能做的一切，而且到 1990 年，大众市场生产以及廉价仿制机的出现使它们便宜得多。我非常在意金钱，因为我身无分文。所以，就像这样，这是我想要得到的机器。而且由于 PC 蓬勃发展，升级和附加设备很容易获得。尤其是在硬件方面，我想要一些标准化的东西。

我决定跨越鸿沟，跨越那道分界线。买一个新 CPU 应该会很有趣。就在那时，我开始出售我的 Sinclair QL 部件。

每个人心中都有一本改变过他或她生活的书。《圣经》。《资本论》。《和莫里先生的一 year》（Tuesdays With Morry）。《我所需的一切都源自幼儿园》。等等。（我真诚地希望，在阅读了序言以及我关于生命意义的理论后，你会决定这本书也对你奏效。）那本让我达到新高度的书是安德鲁·S·塔能鲍姆（Andrew S. Tanenbaum）所著的《操作系统：设计与实现》。

我已经注册了秋季的课程，其中我最期待的是 C 编程语言和 Unix 操作系统课程。为了预习这门课，我在夏天买了上述教科书，希望能抢个先机。书中，安德鲁·塔能鲍姆，一位阿姆斯特丹大学教授，讨论了 Minix，这是他编写的一个用于 Unix 的教学辅助工具。Minix 也是一个小型的 Unix 克隆。在读完介绍后，了解了 Unix 背后的哲学以及这个强大、简洁、美观的操作系统能够做什么之后，我决定买一台运行 Unix 的机器。我将运行 Minix，这是我找到的唯一比较有用的版本。

当我阅读并开始理解 Unix 时，我受到了巨大的热情冲击。老实说，这种激情从未消退过。（我希望你也能对某件事这么说。）

对于任何事情都是如此。但测试硬件极限的地方在于动作游戏，比如现在流行的一些 3D 游戏。从根本上说，游戏是计算机上为数不多的能让你分辨出事情是否正在实时发生的东西。在文字处理中，你不在乎这里或那里有一秒钟的延迟。但在游戏中，当延迟低于十分之一秒时，这种延迟就开始变得明显了。过去游戏比较简单。如今，编程实际上只是游戏中很小的一部分。有音乐，有情节。如果把它和制作电影做比较，编程部分仅仅是摄影工作而已。
