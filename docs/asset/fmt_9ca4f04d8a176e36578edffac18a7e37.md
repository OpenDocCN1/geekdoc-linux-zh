
# 回收与内存压力

## 直接压缩与回收路径

对于开销较大的分配，首先进行直接压缩（`direct compaction`），因为可能我们有足够的空页面且不需要回收。对于非可移动阶（`non-mobile-order`）的分配，也是这样做，因为编译器将尝试通过迁移具有相同元类型（`mettype`）的块来防止永久性碎片。不要对这些允许忽略水位线的分配进行尝试，因为 `ALLOC_NO_WATERMARKS` 尝试尚未发生。

```c
if (can_direct_reclaim &&
    (costly_ ||
     (order > 0 && _miggetype != MIGRATE_MOVABLE))
    && gfp_pmemalloc_allowed(gfp_map)) {
    page = __alloc_pages_direct_compact(gfp_map, order,
            alloc_flags, ac,
            __INIT_FLAGS_PRIORITY,
            &compact_result);
    if (page) {
        goto got_pg;
    }
}
retry:
/* 确保只要我们使用它，kswapaps 就不会意外睡眠 */
if (alloc_flags & ALLOC_KSWAPD)
    wake_all_kswapaps(order, gfp_map, ac);
```
