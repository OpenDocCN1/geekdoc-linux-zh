
只有文件或目录的所有者（超级用户）才能更改其模式。只有超级用户可以在非目录文件设置粘滞位。如果你不是超级用户，`chmod`会屏蔽粘滞位但不会返回错误。要开启文件的 set-group-ID 位，你的组 ID 必须与文件匹配，且必须设置组执行。

## 注意事项

绝对更改对于目录的 set-group-ID 位无效。你必须使用 `g+s` 或 `g-s`。`chmod`允许你产生无用的模式，只要它们不是非法的（例如，使文件变为可执行）。`chmod`不检查文件类型以查看强制锁定是否有意义。

如果系统挂载了 `nosuid` 选项，则不允许执行 setuid 程序。

## 选项

- `-f` 如果 `chmod`无法更改文件的模式，则不报错。
- `-R` 递归遍历目录参数，如上述所示为每个文件设置模式。遇到符号链接时，更改目标文件的模式，但不进行递归。

### 操作数

- `mode` 对由一个文件操作数命名的每个文件的模式位要进行的更改。
- `file` 要修改文件模式位的文件名。

## 使用方法

请参见 `largefile(5)` 获取关于 `chmod`遇到大于或等于 2 GB (`2**31` 字节) 文件时的行为描述。

## 示例

以下示例拒绝所有人的执行权限。

```bash
castle% chmod a-x file
```

以下示例仅赋予所有人读取权限。
```bash

```

以下示例使文件对其他人可读可写。
```bash

```

以下示例锁定一个文件。
```bash

```

以下示例允许所有人读取、写入和执行一个给定文件。
```bash

```

以下示例开启组 ID。
```bash

```

以下示例设置组 ID。
```bash

```

以下示例更改组 ID。
```bash

```

## chown — 修改文件所有权

## 摘要

```
/usr/bin/chown [-fR] owner[:group] file...
```

## 描述

使用 `chown`（更改所有者）命令更改你拥有的文件的用户 ID。你可以可选地通过此更改组 ID。如果由超级用户以外的人使用 `chown`，则清除 setuser-ID 位。只有文件的所有者（或超级用户）才能更改文件的所有者。操作系统有一个配置选项 `POSIX_CHOWN_RESTRICTED`，用于限制所有权的更改。当该选项生效时，即使是文件的所有者也无法更改所有 ID。无论该选项是否生效，超级用户都可以任意更改所有者。要设置 `POSIX_CHOWN_RESTRICTED` 选项，请在 `/etc/system` 中包含以下行：
`set rschown = 1`

要禁用 `POSIX_CHOWN_RESTRICTED` 选项，请在 `/etc/system` 中包含以下行：
`set rschown = 0`

`{POSIX_CHOWN_RESTRICTED}` 默认启用。请参见 `system(4)` 和 `fpathconf(2)`。

## 选项

- `-f` 报错。
- `-h` 如果文件是符号链接，更改符号链接的所有者。如果没有此选项，则更改符号链接引的文件的所有者。
- `-R` 递归遍历目录和任何子目录，设置所有权。遇到符号链接时，更改目标文件的所有者（除非指定了 `-h` 选项），但不递归。

### 操作数

```
owner[:group]
```

分配给文件的用户 ID 和可选的组 ID。操作的所有者部分必须是用户数据库中的用户名或数字用户 ID。指定赋予每个文件的用户 ID。如果数字所有者在用户数据库中作为用户名存在，`chown` 将使用与该用户名关联的用户 ID。同样，如果你使用操作数的组部分，它必须是组数据库中的组名或数字组 ID。指定赋予文件的组 ID。如果数字组在组数据库中作为组名存在，`chown` 将使用与该组名关联的组 ID 作为组 ID。

`file` 要修改用户 ID 的文件路径。

## 使用方法

参见 `largefile(5)` 获取关于 `chown`遇到大于或等于 2 GB (`2**31` 字节) 文件时的行为描述。

## 示例

(Examples)

在以下示例中，尽管用户 `winsor` 拥有名为 `kookaburra` 的文件，但启用了 `_POSIX_CHOWN_RESTRICTED`（默认），因此显示了 Not 错误信息。

```
castle$ ls -1 kookaburra
-rw-rw-rw- 1 winsor staff     242 Oct 1 16:12 kookaburra
castle$ chown ray kookaburra
chown: kookaburra: Not owner
cast$
```

在以下示例中，超级用户将名为 `kookaburra` 的文件的所有权更改为 `ray`，组更改为 `other`。

```
castle$ su
Password:
castle$ chown ray kookaburra
castle$ ls -1 kookaburra
-rw-rw-rw- 1 ray staff     242 Oct 1 16:12 kookaburra
castle$ chown ray:other kookaburra
castle$ ls -1 kookaburra
-rw-rw-rw- 1 ray other      242 Oct 1 16:12 kookaburra
cast$
```

# cksum — 写入文件校验和和大小 (Write File Checksums and Sizes)

用法概要 (Synopsis)
`/usr/bin/cksum [file...]`

描述 (Description)
`cksum` 命令为每个输入文件计算并向标准输出写入循环冗余校验 (CRC)，同时向标准输出写入每个文件的字节（octets）数。
对于每个成功处理的文件，`cksum` 按照以下格式写入：
`"%u %d%s"` `cksum`, 字节数, 文件路径
如果你未指定文件操作数，则省略文件名及其前面的空格。
CRC 是基于所引以太网标准中用于 CRC 错误检查的生成项式计算。
CRC 校验和的编码由生成多项式定义：
`G(x) = x32 + x26 + x23 + x22 + x16 + x12 + x11 + x10 + x8 + x7 + x5 + x4 + x2 + x + 1`
从数学上讲，给定文件的 CRC 值由以下过程定义：
1. 待评估的 n 位位被视为次数为 n-1 的模 2 多项式 `M(x)` 的系数。这些位是来自文件中的位；最高位是文件第一个字节的最高位，最后一位是文件最后一个字节的最低位，必要时用零位填充以达到整数字节数。最后一位之后紧跟一个或多个字节，以二进制值表示文件长度，最低位字节在前。使用能够表示该整数的最少字节数。
2. 将 `M(x)` 乘以 `x 32`（即左移 32 位）并使用模 2 除法除以 `G(x)`，产生一个次数 < 31 的余数 `R(x)`。
3. `R(x)` 的系数被视为一个 32 位序列。
4. 对该位序列进行取反，结果即为 CRC。

### 示例 (Examples)

你可以显示单个文件或目录的校验和、文件列表的校验和，或目录下所有文件的校验和。以下示例显示了当前工作目录下所有目录和文件的校验和。

```
castle$ cksum *
1583778740 1024 Art
2849654401 512 DeadLetters
4249967295 0 Design.book
364878811 512 Mail
1815174335 737 bibliography
2131326963 526 commands
```
