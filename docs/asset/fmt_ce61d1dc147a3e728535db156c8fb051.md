## 网络基础

系统管理可以被认为是电脑之间电子街道序列。这些街道可以是物理的，最常见的是 5 类或 6 类铜缆（CAT 5 或 CAT 6）链路或光纤链路。远程系统管理利用独特的无线发射器和接收器来引导物理系统之间相同的底层任务。

无论介质如何，物理或远程系统管理都有相似的基础部分。首先，至少有两个设备将通信，例如，Adam 的电脑将与 Bill 的电脑通信。为了实现这一点，他们需要在正确的介质上使用正确的交换设备。在这个模型中，Adam 将与 Bill 连接的相同的物理 CAT5 系统接口。如果设置正确，只要双方的约定和设置正确，Bill 就可以使用远程网卡而 Adam 就可以使用有线网卡。为了让此正常工作，Adam 和 Bill 都应该通过类似远程交换机的设备接入相同的系统部分，将有线和远程不同的物理介质类型关联。

有许多部分构成了一个现代网络，而完全解释系统管理远超本书的范围。将介绍的小型系统部分足以描述如何配置网卡。这个小系统只是 Adam 和 Bill 使用的两台电脑、一个连接调制解调器的有线交换机以及连接一切的链路（本模型中全是 CAT5）。交换机的内部互联网协议 (IP) 地址为 192.168.1.1，这对于小型家庭办公室 (SOHO) 和家庭系统的默认设置非常常见。这个小交换机通过其外部连接接入互联网，使用互联网提供商分配的 IP 地址，这将使 Adam 和 Bill 在有效配置其网卡后能够上网。在这个模型中，交换机还提供了动态主机配置协议 (DHCP)、基本的防火墙功能和域名系统 (DNS)，这些每项都将在以后详细讨论。该系统如图 4.3 所示，并将作为后续章节使用的基础系统。

## 私有地址

交换机的内部接口（或网卡）的 IP 地址为 192.168.1.1；这就是所谓的私有位置，因为它不能在互联网上使用。内部系统接口与图中的黑盒的地址类似于 DHCP 分配的地址（分配给 Adam 和 Bill 电脑的 IP 地址）。一个表格记录了可以用于内部或私有系统的正常私有 IP，但无法在互联网上使用。

为了访问互联网，交换机执行一种称为网络地址转换 (NAT) 的魔法，它将 Adam 和 Bill 使用的 IP 转换为可以在互联网上使用的地址。这通常是数字互联网供应商提供给交换机的地址，并将分配到外部接口（另一个网卡）。如果客户端在互联网上使用这些地址而没有 NAT 交换机，通信将失败，因为互联网路由器和其他设备会拒绝这些私有 IP 地址。

## 默认网关

交换机的内部接口 IP 地址是退出 Adam 和 Bill 的系统。此位置被称为默认网关，稍后在为客户的两个 PC 设计系统网卡时将派用到。描述默认网关的一种形象方法是将其看作离开社区的唯一一条街道。任何需要离开城镇的人都需要知道这条街道在哪里。在系统 PC 上（通过系统网卡），PC 需要知道离开局域的出口在哪里；这就是默认入口。

## 域名服务器 (Name Server)

PC 之间通过数字进行对话，而个人之间在通过单词和表达进行交流方面则有了极大的提高。为了让通信能够有效进行，PC 定期使用域名服务器或区域域名管理（DNS）。本书将在稍后的部分以更详尽的细节介绍 DNS，因此本节仅将对 DNS 进行简单概述。从根本上说，域名服务器将人类可读的名称（如 www.synergy.com）解释为 IP 地址，PC 和具有名称管理分段的设备更擅长处理这种地址。DNS 与域名服务器同义，在人类友好的名称与 PC 良好的位置之间进行解释。例如，当一台 PC 需要与另一台 PC（例如一个 Web 服务器）通信时，它最初应该将易懂的位置解释为可以发送消息的 PC 邻居地址。个人将在其首选程序中输入 www.synergy.com，PC 将将此位置发送到 DNS 机器。DNS 将通过提供该网站页面的 IP 地址（163.172.x.x）进行回答。客户的 PC 然后将使用此 IP 地址与 Sygress Web 服务器通信，客户即可与 Syngress 网站进行协作。如果没有这种管理，人们将被记住每个网站的特殊 IP 地址。这意味着个人需要记住 69.163.177.2，而不是 syngress.com。手动设计系统网卡需要 DNS 或域名服务器的区分标识证明。

## DHCP

对于纯粹的系统魔法，没有什么能比得上 DHCP 了。对于一台设置了 DHCP 自动配置的 PC，客户端只需连接到正在运行的系统链接并开始工作即可。这是在 PC 启动并在系统中建立通信时，通过发送一个搜索 DHCP 服务器的通信请求来实现。服务器响应客户端并为所提到的 PC 分配组织配置。这包括 PC 的 IP 地址（仅限系统网卡，但在本解释中略显复杂）、默认网关、域名服务器——或域名服务器以及默认子网掩码。

通常，这是配置你系统网卡的极佳方法。如果你正在进行渗透测试，使用 DHCP 配置你的系统网卡会向所有人报告你正在进入系统，这通常不是值得感谢的。

## 基础子网划分 (Essential Subnetting)

子网划分是一个可能会困扰许多人的主题，因此在书中，子网划分被描述为以理想方式设计组织以节省 IP 地址的最佳方法。这是通过应用一个掩码来过滤 PC IP 地址的一部分，从而允许不同的系统被隔离。回到 Syngress 模型，IP 地址是 69.163.177.2，如果我们处于一个少于 255 个客户端的小型系统中，我们可以使用 C 类子网掩码 255.255.255.0。在应用掩码时，位置的部分被抵消，而其他部分保留，使得系统上的 PC 知道自己所在的哪个系统。再次，子网掩码的一个基本示例仅使用 255 和 0 这两个数字字节位；因此，为了区分系统，协调位置的任何部分都不会发生变化，所以 IP 地址的前三个字节（69, 163, 177）将与 255 协调，允许前面的数字通过。由于 0 被完全抵消，位置的最后一个字节（即 2）将被偏移，导致变为 0。因此，通过将子网掩码 255.255.255.0 应用于位置 69.163.177.2，我们发现系统地址是 69.163.177.0。在大多数小型系统中，255.255.255.0 的子网掩码将运行良好，而较大的系统将需要另一个不同的子网掩码，该掩码可能被确定为向特定数量的主机提供服务。

## Kali Linux 默认设置

如前所述，大多数渗透测试工程师和白帽程序员不需要他们的 PC 在连接系统时让系统网卡报告其在系统上的身份。这正是 Kali Linux 在配置并与系统连接时将要做的。在指导渗透测试时必须注意，在连接到系统之前禁用系统网卡以避免这种不必要的额外通信。通过包含硬盘、优 盘或 SD 卡的自定义引导，可以更改这种自动系统配置。这种更改的另一种方法是构建一个用于手动系统设置的自定义活动系统盘。这些技术将在第 5 章调整 Kali Linux 时进行讨论。

### 使用图形用户界面配置网络接口

在 Linux 中配置系统网卡（也称为系统连接器）以前是一个必须通过命令行完成的程序。这最近发生了变化，Kali Linux 也是如此。Kali Linux 拥有强大的图形界面 (GUI)，允许使用简单的对话框配置许多基本设置。

通过选择 UI 右上角的“应用程序”，然后选择“系统工具”、“偏好”和“网络连接”，可以有效打开系统设置。点击“系统设置”，将显示系统设置框，并选择“有线”选项卡。另一方面，在屏幕右上角点击右键并选择“更改设置”将打开类似的对话框。通常，PC 只有一个需要配置的网卡，但在引入多个 NIC 的情况下，确保你正在配置正确的网卡。这将打开编辑框。此选项卡显示设备的媒体访问控制 (MAC) 地址（更多信息请参阅 MAC 地址章节）。设备标识符也显示在 MAC 地址之后。在这种情况下，设备标识符是 `eth0`，其中 `eth` 是以太网的缩写，0 是 PC 中的网卡。网络网卡的编号分组从 0 开始而不是 1，因此 PC 中的第二个网卡将是 `eth1`。

选择“802.1x 安全”选项卡、“IPv4 设置”和“IPv6 设置”可以创建有线以太网设置。本书将重点介绍带有 IP 第 4 (IPv4) 设置。在选择后，配置 PC 的 IP 地址 (192.168.1.66)、子网掩码或掩码 (255.255.255.0)、网关 (192.168.1.1) 以及 DNS 服务器 (192.168.1.1)。可以使用逗号分隔的多个 DNS 服务器。点击“保存”按钮可以保存并使设置生效。

### 使用命令行配置网络接口

了解如何从命令行配置或重新配置网络接口至关重要。这在不使用 Linux 图形界面或通过终端窗口远程连接到系统时非常有用。在渗透测试的许多情况下，命令行是更改设置的主要选择。

这些操作应作为具有权限的客户端使用 root 账户进行。在活动系统盘上实施这些改进并使用 SDO 指令实施它们是 Kali Linux 的另一种方法。

检查 PC 网卡的状态以及每个网卡的状态通过以下命令完成：

```
ifconfig - a
```

这将显示 PC 上所有系统网卡的当前布局。在图 4.7 中，显示了两个系统地址：`eth0`（主以太网卡）和 `lo`（回环接口或内部接口）。此连接器的设置是通过图形化界面设置的，而使用命令行更改这些设置非常基础。

#### 启动和停止接口

可以使用 `ifconfig` 命令的 `up` 选项启动接口，或使用 `down` 选项停止接口，同时需要指定要停止或启动的接口。随附的命令将停止主以太网连接器。

以下顺序将启动主以太网连接器：
```
ifconfig eth0 up
```

利用以下命令可以将此连接器的 IP 地址从其当前布局 192.168.1.66 更改为 192.168.1.22。
```
ifconfig eth0 192.168.1.22
```

也可以通过随附命令利用命令行更改系统配置。这将把 IP 地址设置为 192.168.1.22 并将子网掩码设置为 255.255.255.0。
```
ifconfig eth0 192.168.1.22 netmask 255.255.255.0
```

在命令行完整配置系统网卡比使用图形化 UI 需要更多工作，因为设置选项并没有全部存储在同一个区域。通过随附命令包含或更改默认网关，在此情况下设置为 192.168.1.2。
```
route add default 192.168.1.2
```

通过修改 `/etc/` 索引下的 `resolv.conf` 记录来更改名称服务器（或 DNS）设置。可以使用您喜好的文本编辑器修改该记录，或者基本上在命令行使用随附的命令。
```
nameserver 4.4.4.4 > /etc/resolv.conf
```

上述命令将清空当前的名称服务器并替换为 4.4.4.4。若要包含额外的名称服务器，随附命令会将新的名称服务器地址附加到 `resolv.conf` 中已记录的地址之后。

当 PC 执行名称查询时，它将按照记录的顺序检查前三个名称服务器。
```
nameserver 8.8.8.8 >> /etc/resolv.conf
```

#### 从命令行提示符使用 DHCP

设计系统网卡简单的方法可能是利用 DHCP 管理来配置网卡。方面，DHCP 服务器将提供网卡所需的所有设置选项。这对于大多数终端非常有帮助，但在进行渗透测试时并不理想，因为正在配置的框架已记录在 DHCP 服务器的数据库中。请按照以下说明在进行渗透测试时禁用已程序的 DHCP 设置。此模型使用 `nano` 文本编辑器；但可以使用其他内容工具。

```
nano /etc/network/interfaces
```
