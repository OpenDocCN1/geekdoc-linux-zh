# kill — 终止或信号化进程

## Synopsis

```
/usr/bin/kill -s signal pid...
/usr/bin/kill -1 [exit-status]
/usr/bin/kill [-signal] pid...
```

sh, ash, and ksh

```
kill [-sig] [pid] [%job-id]...
kill -1
```

## Description

有时，你可能需要完全消除一个进程，因为你想在一个大型作业完成之前停止它，或者你检测到一个挂起或运行不正常的进程。`kill` 命令向每个 `pid` 操作数指定的进程发送信号。使用 `ps(1)` 命令找到你想要杀掉的进程的进程 ID。

当你调用 `kill` 时，你实际上是在告诉系统发送信号。有 36 个数字编号信号和 44 个无编号信号。请参考 `signal(5)` 手册页获取完整列表。

你可以通过数字或 `signal(5)` 手册页列出的逻辑信号名称（去掉 SIG 部分）来指定信号。以下示例展示了通过编号和通过名称发送信号 15 的：

`castle kill -15 456`

`castle kill -TERM 457`

当你不提供任何信号时，`kill` 命令默认发送信号 15 (`SIGTERM`)。信号 15 在能够的情况下会终止进程，它是杀死进程的首选方法。有时当你使用 `kill` 命令时进程并不会死亡。最常见的三类是：

- 进程正在等待设备（如磁带驱动器）完成操作后再退出。
- 进程正在等待 NFS 问题导致不可用的资源。对于此类进程，使用信号 3 (`SQUIT`)。
- 进程是一个僵尸进程，如 ps 报告中显示的 defunct 消息。僵尸进程已释放了所有资源，但还没有收到父进程的确认（收到通常会将其从进程表中移除）。下次系统启动时，僵尸进程会被清除。僵尸进程不影响系统性能，你不需要删除它们。

当进程不通过信号 15 死亡时，使用信号 9 (`SIGKILL`) 强制进程死亡。

## Built-in Shell kill Commands

Bourne 作业控制 shell `jsh`、Korn shell 和 c shell 都有内置的 `kill` 版本，提供了 `kill` 命令的功能。

内置的 `kill` 提供了 `kill` 命令针对 job-id 的。

内置的 `kill` 默认向指定的进程发送信号 (`TERM`)，对于指定的进程 ID，使用数字或名称。

内置的 `kill` 提供了 `kill` 命令针对 job-id 的。

内置的 `kill` 提供了 `jsh`、`ksh` 和 `csh` 支持的所有信号值。如果你指定了 exit-status，结果是不确定的。

## Options

- `-1` (任意.) 输出 `jsh`、`ksh` 和 `csh` 支持的所有信号值。如果你不指定 exit-status。
- `-s signal` 向指定的进程或作业发送信号，使用数字或名称。此外，识别符号名称 0，表示信号值 0。与 `kill` 命令使用的典型值为 -15 (`TERM`)—默认值——以及 9 (`KILL`)。

## Usage

你可以通过 `ps*(1)` 找到 PID 数字。

当 `kill` 在其自身的命令执行环境中运行时，作业控制 ID 表示法可能无法按预期工作。例如，以下两个示例，`kill` 在不同的环境中运行，不共享 shell 对作业数的理解。

```
nohup kill & 
system("kill %1");
```

## Output

如果不指定 `-l` 选项，不使用标准输出。当指定 `-l` 选项时，每个信号的符号名称按以下格式写入：

`%s%c`, signal, separator

其中信号为大写，没有 SIG 前缀，分隔符为换行或空格。对于写的最后一个信号，分隔符为换行。

当你对 `/bin/kill` 同时指定 `-l` 选项和 `exit-status` 操作数时，相应信号的符号名称将按以下格式写入。

`%s\n`, signal

## 示例

以下示例使用 `-1` 选项来列出 `/usr/bin/kill` 可用的信号。

```
castle% /usr/bin/kill -1
EXIT HUP INT QUIT TRAP ERMT FPE KILL BUS SYS PIPE ALRM TERM
USR USR2 PWR WINCH URG POLL STOP TSTP TTCP TTIN TTOU VAL TERM
XCPU XFS2 WAITING LWP FREEZE THANC LOST RTMIN RTMIN+1 RTMIN+2
RTMIN+3 RTMAX-3 RTMAX-2 RTMAX-1 RTMAX
castle%
```

如果发送者具有发送信号的权限，则以下任何一个命令都将 `SIGKILL` 信号发送给 ID 为 100 的现有进程，并给所有进程组 ID 为 165 的进程。

```bash
# kill -9 -165
# kill -s kill 100 -165
# kill -s KILL 100 -165
```

> 为了避免初始负数参数在指定指定信号号或进程组时产生歧义，始终会指定信号号。因此，要向进程组（例如 123）发送默认信号，应用程序应使用类似于以下任意一个命令：

```bash
# kill -TERM -123
# kill --123
```

以下示例使用 `ps` 命令找到游戏 `spider` 的进程 ID，然后使用 `kill` 命令通过进程 ID 将其杀死。

```
castle% ps -ef | grep spider
winsor 544 419 0 15:45:42 pts/3 0:00 grep spider
winsor 542 419 1 15:45:35 pts/3 0:00 spider.exe
castle% kill 542
[1] Exit 1 spider
castle%
```

以下示例使用 `jobs` 命令找到游戏 `spider` 的作业号，然后使用 `kill` 命令通过作业 ID 将其杀死。

```
castle% jobs
[2] + Running spider
castle% kill %2
castle%
[2] Exit 1 spider
castle%
```

# kinit — Kerberos 登录命令

### 概要

```
/usr/bin/kinit [-ilrv] [username]
```

## 描述

`kinit` 命令用于登录 Kerberos 身份验证和授权系统。注意，只有注册的 Kerberos 用户才能使用 Kerberos 系统。有关注册为 Kerberos 用户的信息，请参阅 `kerberos(1)` 手册页。

当不带选项使用 `kinit` 时，命令会提示输入你的名称和 Kerberos 密码，并尝试通过本地 Kerberos 服务器验证你的登录身份。如果你愿意，可以在命令行上指定名称。
