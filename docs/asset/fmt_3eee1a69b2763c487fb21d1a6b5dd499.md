
### 交换机
交换机连接多个配置在同一网络上的计算机系统。它充当分配中心。当一个计算机系统想要向位于同一网络上的另一台计算机系统发送数据时，交换机会分配数据包中携带的目标地址，然后将数据包转发到目标系统。交换机是在线教学/学习系统中广泛使用的网络设备。它们用于为部门和办公室形成子网，也用于为计算机实验室小组活动构建子网。

### 三层交换机
与路由器类似，三层交换机可以将包转发到另一个网络上的目标计算机系统。三层交换机和路由器的区别在于，三层交换机是实现路由器内置软件逻辑的硬件。通过这样做，它可能会丢失一些灵活性，但获得更好的性能。因此，对于网络路由，三层交换机是一种高性能设备。

网络设备使用各种源协议，可以将网络流量携带到目的地，控制数据包的发送方式，检测并修复传输中的问题，并管理网络资源。接下来讨论协议。

## 网络协议
协议通常设计用于完成以下任务。它们通常通过软件或硬件来实现以下工作：
- 在网络上传输时，消息被分成称为“数据包”的小块，用于将消息携带到目的地。
- 协议确定数据包的开始和结束，以便在目的地建立连接。
- 协议检查传输到目的地的消息。
- 如果传输过程中发生错误，协议可以修正错误或丢弃数据包。
- 协议重组数据包以获取原始消息。
- 协议还可以管理连接。

## 网络开发与管理
除了上述任务，许多开源协议被创建用于完成特定任务。下面，让我们来看一些常用的开源协议：

### 网际协议 (IP)
IP 是一种众名的开源协议。局域网和互联网上的通信在很大程度上取决于 IP，它将消息从一种类型的网络发送到另一种类型。每个为数据传输形成的数据包都包含与发送和接收者 IP 地址相关的源地址和地址。IP 的工作是将消息携带到目的地。因此，IP 不具备错误检查功能。它需要与其他协议配合。

### 传输控制协议 (TCP)
TCP 是另一个开源协议。它经常与 IP 配合，实现互联网上的数据传输。TCP 和 IP 是 20 世纪 70 年代创建的前两个数据传输网络协议。当 IP 将消息传递给目标计算机或网络设备时，TCP 会跟踪每个数据包并确保它们被高效、正确地发送和接收。TCP 是在发送时实际格式化包并在重组包以获取原始消息的协议。重组任务可能是一个复杂的过程。当数据包传输时，它们可能会采取不同的路线到达同一个目的地。当这些数据包到达时，数据包的顺序已经改变。在目的地，TCP 等待所有数据包到达并将它们重新排序为原始序列。当传输过程中丢失某些数据包时，TCP 会等待足够的时间，然后丢弃整个消息并等待发送者重发消息。TCP 完成的另一个主要任务是维护发送者和接收者之间的连接。在接收端应用程序接收到所有消息之前，TCP 一直保持它们之间的连接。

TCP 的下一个主要任务是检查传输过程中发生的错误。它会验证传输过程中是否有数据包丢失。因此，TCP 被认为是完全可靠的协议。它确保发送者发送的任何内容都能送达接收者，并且没有重复的数据包。TCP 的另一个强大特性是拥塞控制。在传输过程中，繁忙的流量或硬件问题会导致数据包到达目的地的延迟。UDP 反而会导致更多消息的重发，这将使拥塞更加严重。TCP 使用测试信号来决定应该发送多少数据以避免拥塞。

作为开源协议，TCP/IP 组合不仅安装在 Linux 和 BSD 等开源操作系统上，还是大多数商业操作系统（如 Windows、Mac OS 以及各种版本的商业 UNIX 系统）的默认网络传输协议。

### 超文本传输协议 (HTTP)
在第 1 章中，提到了蒂姆·伯恩-李（Tim Bern-Lee）发明了开源世界维网。作为万维网的一部分，由蒂姆·伯恩-李编写的 HTTP 是一种嵌入在 TCP 中的应用协议，用于在万维网上传输文本文件、图像、音频、视频和其他文件。由于嵌入了 TCP 中，新版本的 HTTP 可以保持连接并能够传输所有的页面组件。通过这种方式，HTTP 无需为网页上的每个组件建立新连接；这可以显著加速传输。网页浏览器充当 HTTP 客户端。当点击链接或刷新 URL 时，HTTP 客户端向 Web 服务器发送请求，Web 服务器通过 HTTP 守护进程程序分析请求并处理请求。随后，来自 Web 服务器的响应将返回给 HTTP 客户端。

### 用户数据报协议 (UDP)
与 TCP 类似，UDP 用于在网络上发送或接收消息。UDP 通过这些程序使用的端口号来识别应用程序。UDP 还与 IP 协同工作，在互联网或局域网上传输消息。TCP 和 UDP 的区别在于，UDP 不提供错误检查，也不为数据传输形成数据包。这些特性使得 UDP 不再是完全可靠的协议。消息可能会丢失、重复、乱序或损坏。另一方面，UDP 比 TCP 更高效，开销也小得多。尽管 UDP 不适用于某些高质量传输，但它非常适合传输音频和视频数据，这些数据对小的传输错误的忍度较高。

### 文件传输协议 (FTP)
FTP 是另一种标准协议。几乎每个操作系统都支持 FTP；这意味着任何服务器操作系统都可以托管 FTP 服务器，任何个人电脑都可以安装 FTP 客户端。软件供应商和个人程序员可以在他们的产品中自由使用 FTP。FTP 设计用于通过互联网从一个计算机系统传输文件到另一个。文件存储在 FTP 服务器中，允许 FTP 客户端远程访问这些文件。例如，FTP 客户端向 FTP 服务器请求连接。连接建立后，FTP 可以从 FTP 客户端上传文件到 FTP 服务器，或从 FTP 服务器下载文件到 FTP 客户端。如果获得许可，FTP 客户端还可以对 FTP 服务器上的文件进行重命名或删除。在在线教学/学习系统中，学生经常使用 FTP 下载课程材料。

### 动态主机配置协议 (DHCP)
DHCP 是一种网络协议，可用于自动为物理上连接到 DHCP 服务器的客户端系统分配 IP 地址。要从 DHCP 服务器获取 IP 地址，客户端系统需要配置为获取动态 IP 地址。DHCP 服务器可以配置为分发一个范围内的 IP 地址。它还可以决定租用时间以及客户端是否续租。DHCP 的使用大大减少了网络管理员的工作量。当一个新计算机系统连接到网络时，它将自动获得 IP 地址，以便与其他计算机系统和网络设备开始通信。大多数情况下，学生的家用电脑将从其互联网服务提供商处获得动态 IP 地址。在计算机实验室进行实操练习的计算机系统将从 VPN 服务器或用于为实验室计算机分发 IP 地址的设置获取其 IP 地址。出于安全考虑，实操实验室中的计算机不会直接从大学网络上的 DHCP 服务器获取动态 IP 地址。对于在线计算机实验室的计算机系统，DHCP 服务器应配置为每次计算机服务器续租 DHCP 租约时都提供相同的 IP 地址。这样，学生就可以登录到同一台计算机上继续他们的实操任务。

### 简单邮件传输协议 (SMTP)
SMTP 用于通过互联网向各个电子邮件客户端发送电子邮件。在 SMTP 服务器接收到电子邮件客户端的邮件后，SMTP 将该邮件从此邮件服务器通过互联网发送到目标邮件服务器。然而，目标电子邮件客户端并不使用 SMTP 从目标邮件服务器检索邮件。其他协议被用于完成此任务。我们将在下一段中讨论这些协议。在在线教学/学习系统中，支持 SMTP 的邮件服务器通常安装在校园内。当学生在家里配置电子邮件客户端软件时，必须提供发出的邮件服务器的名称或 IP 地址。发出的邮件服务器可以是某个流行邮件服务商提供的服务器，也可以是大学的邮件服务器。由于 SMTP 是一种简单协议，它有时包含在 Web 服务器或其他服务中。它还需要联系 DNS 服务器来识别电子邮件地址。在这种情况下，请确保 Web 服务器和 DNS 服务器运行正常。

### 邮局协议 3 (POP3) 和 互联网消息访问协议 (IMAP)
如前段所述，SMTP 是一种简单协议；因此，它不具备在接收端缓存消息的能力。使用 SMTP SMTP，POP3 和 IMAP 协议用于检索数据。这两种协议允许客户端将消息保存到邮件服务器。POP3 是一种流行的检索电子邮件的服务器，它允许你从电子邮件客户端下载文件。IMAP 也可以用于检索电子邮件。IMAP 和 POP3 的区别在于，IMAP 在管理邮件服务器方面的能力更多。如上述，为在线教学/学习系统设置邮件服务时，应配合 POP3 或 IMAP 使用 SMTP。

### 安全壳 (SSH)
SSH 是一种用于在网络上安全交换信息的协议。当 SSH 客户端的连接请求到达 SSH 服务器时，SSH 守护进程通过创建安全连接来响应请求。通过加密数据并验证计算机和用户，SSH 在发送者和接收者之间创建了一个安全通道。它提供了安全的远程登录、安全的远程命令执行和安全的文件传输。SSH 开发了多种实现；其中一些是专有的，另一些是开源的。在这些 SSH 实现中，最流行的是开源 SSH 协议 OpenSSH。OpenSSH 已包含在 Linux、Windows 和不同版本的 UNIX 等操作系统中。
