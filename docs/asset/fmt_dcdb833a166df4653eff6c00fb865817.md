## 工作程序

这些是当队列中没有待处理事件时，事件处理循环调用的函数。该函数预期返回一个布尔值，指示它在被调用后是否需要从循环中移除。如果是 `TRUE`，则将其移除；如果是 `FALSE`，则将再次调用。例如，你可以设置一个在“后台”运行的磁盘文件传输，它在完成之前将一直返回 `FALSE`，完成后返回 `TRUE`。

*工作程序*定义为：

`XtWorkProc yourFunction(XtPointer clientdata);`

注册工作程序的方法是调用：

`XtWorkProcId XtAppAddWorkProc (XtAppContext app, XtWorkProc functionPointer, XtPointer clientData);`

此调用的返回 ID 是该工作程序的句柄。它用于通过调用以下函数移除工作程序：

`XtRemoveWorkProc(XtWorkProcId id);`

## 使用超时

*超时*用于按（几乎）固定的间隔执行某些任务。应用程序设置一个定时器回调函数，该函数在请求的时间间隔通过后被调用。该函数的定义如下：

`XtTimerCallbackProc thyTimerCallback(XtPointer clientdata, XtInterval *tid);`

在这里，`clientdata` 是指向客户端特定数据的指针。

超时的设置函数返回定时器 ID，定义如下：

`XtIntervalId XtAppAddTimeOut (XtAppContext app, int milliseconds, XtTimerCallback TimerProcedure, XtPointer clientdata);`

此调用设置了一个定时器，在请求的毫秒数通过后调用 `TimerProcedure` 函数。它只会执行一次。如果你需要循环超时（例如，在时钟应用程序中），你必须在定时器处理程序函数本身中显式地设置下一次函数调用。因此，通常定时器处理程序的最后一行是为该函数下次想要被调用时设置超时。

UNIX 设计之初并非为了*实时*应用程序设计，你无法期望连续定时器调用之间有*确定性*的时间间隔。一些密集的图形更新可能会导致定时器循环延迟。对于用户界面应用程序，这些延迟可能不是一个很大的缺点。但在尝试编写对时间敏感的控制应用程序之前，请咨询你的供应商。具体情况可能取决于你的应用程序。

CD-ROM上的文件 `2_15c` 是一个设置循环定时器的程序。

## 其他来源

`XtAddInput` 函数用于处理来自事件队列以外来源的输入。定义：

`XtInputId XtAddInput(XtAppContext app, int fileDescriptor, XtPointer condition, XtInputCallback inputHandler);`

此调用的返回值是 `inputHandler` 函数的句柄。与定时器不同，`inputHandler` 句柄与...

- `GCForeground` 和 `GCBackground`：这些是分别用于前景颜色和背景颜色的像素值。以下是操作这些值的函数调用：

`XSetForeground(Display *dp, GC gc, Pixel pixel)`

`XSetBackground(Display *dp, GC gc, Pixel pixel)`

- `GCLineWidth`：这是所有通过 `GC` 绘制的线条宽度的像素数。它的默认值为 0，这是向服务器发送的绘制尽可能细线的信号。

- `GCLineStyle`、`GCDashOffset` 和 `GCDashList`：这决定了在屏幕上绘制的线条样式。`LineSolid` 使用前景颜色绘制实线，`LineOnOffDash` 使用前景颜色绘制间断线，`LineDoubleDash` 绘制一条由前景色和背景色交替线段组成的线。`GCDashOffset` 和 `GCDashList` 的值决定了这些虚线的位置和长度。

- `GCCapStyle`：这决定了服务器如何绘制线条的末端。`CapNotLast` 绘制到但不包含线条终点像素。`CapButt` 绘制到线条终点（包含终点）。`CapRound` 尝试将粗线（3 像素或宽）的边缘圆化。`CapProjecting` 将终点向外投影一点。

- `GCJoinStyle`：用于绘制线条的连接点。它可以设置为 `JointMiter` 以实现 90 度连接、`JoinBevel` 以实现斜角连接，或 `JoinRound` 以实现圆角连接。

- `GCFillStyle`、`GCTile` 和 `GCStipple`：填充样式可以设置为 `FillSolid`，它指定前景颜色为填充颜色。`FillTiled` 指定 `tile` 属性中定义的模式。`FillStipple` 指定 `stipple` 属性中的模式。当位置被设置为 1 时使用前景颜色，当位置被设置为 0 时不使用任何颜色，而 `FillOpaqueStippled` 在位置为 1 时使用前景色，在位置为 0 时使用背景色。

- `GCFont`：这指定要使用的字体列表。请参见本章后面的“使用字体和字体列表”部分。

- `GCArcMode`：这定义了在屏幕上绘制弧的方式。参见下一节“绘制线条、点、弧和多边形”。

## 绘制线条、点、弧和多边形

Motif 应用可以访问 `Xlib` 提供的所有图形原语。所有 `Xlib` 函数必须在窗口（window）或像素映射（pixmap）上操作；它们统称为可绘制区域（drawable）。小部件在实现（realized）后会有一个窗口，你可以通过调用 `XtWindow()` 获取该窗口。如果对未实现的窗口进行 `Xlib` 调用，应用程序可能会崩溃。检查方法是通过在小部件上调用 `XtIsRealized()`，如果已实现则返回 `TRUE`，否则返回 `FALSE`。

**请使用 `XmDrawingArea` 小部件的回调函数来渲染你的图形，因为它是专门为此目的设计的。可以使用以下回调函数：**

- `XmNresizeCallback`：在小部件调整大小时调用。
- `XmNexposeCallback`：在小部件接收到 `Expose` 事件时调用。
- `XmNinputCallback`：在小部件上按下按钮或按键时调用。

这三个函数都会传递一个指向 `XmDrawingAreaCallbackStruct` 的指针。

### 绘制线条

要在屏幕上绘制一条线，请使用 `XDrawLine` 或 `XDrawLines` 函数调用。请参考 CD-ROM 文件 `2_16c` 中所示的示例。

以下代码是在小部件上绘制一条线所需的原语示例。注意为了实现这一目的需要设置多少 `GCValues`。`XDrawLine` 函数的定义如下：

```c
XDrawLine( Display *dpy,
 Drawable d,
 GC gc,
 int x1,
 int y1,
 int x2,
 int y2);
```

在一次调用中绘制多条线更高效。使用 `XDrawLines` 函数并传入指向点数组的指针及其大小。

`mode` 参数可以设置为：

- `CoorModeOrigin`：使用相对于可绘制区域原点的值。
- `CoorModePrevious`：使用相对于上一个点的增量值。第一个点始终相对于可绘制区域的原点。

要绘制矩形，请使用 `XDrawRectangle` 函数：

```c
XDrawRectangle( Display *display,
Drawable dwindow,
 GC gc,
 int x,
 int y,
 unsigned int width,
 unsigned int height);
```

这将在 (x, y) 处绘制一个几何为 (width, height) 的矩形。要一次绘制多个矩形，请使用 `XDrawRectangles()` 函数。它的声明如下：

```c
XDrawRectangles( Display *display,
 Window dwindow,
 GC gc,
 XRectangle *xp,
 int number);
```

在这里，`xp` 是指向包含 `number` 个结构数组的指针。对于填充矩形，请使用 `XFillRectangle` 和 `XFillRectangles`。

### 绘制点

要在屏幕上绘制一个点，请使用 `XDrawPoint` 或 `XDrawPoints` 函数调用。这些函数类似于线条绘制。

### 绘制弧

要绘制圆弧，请使用 `XDrawArc` 函数：

```c
XDrawArc( Display *display,
 Window dwindow,
 GC gc,
 int x,
 int y,
 unsigned int width,
 unsigned int height,
 int a1,
 int a2);
```
