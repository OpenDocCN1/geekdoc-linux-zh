## 创建目录

你应该为每个项目创建一个目录，以便将构成每个项目的文件保存在定义明确的地方。最好是将组件的源代码与项目本身放在一起。例如，在接下来的步骤中，你将下载 Linux 内核、`Minicom` 和 `Syslinux`。但如果你今天对你的副本进行了一些更改，然后需要升级到新版本该怎么办？你需要原始源代码来为新版本创建补丁（`patches`）。因为这对整个 Linux 社区至关重要，即使在多年以后，你也能下载到你所使用的内核源码。这实际上取决于每个包的维护者是否保留所有旧版本。对于此步骤，首先创建一个名为 `minicom` 的目录来存储 `Minicom` 软件。然后进入该目录以准备下载：

```bash
mkdir minicom
cd minicom
```

## 下载 Minicom

`Minicom` 是一个由 Michael van Steenenberg 编写的串口通信程序。它类似于以前在互联网出现之前，人们用来通过调制解调器连接到公告板系统（BS）的 MS-DOS 程序 `ProComm` 和 `Telex`。它也可以用于连接 PC 到路由器和交换机进行初始配置。

`Minicom` 是一个强大的程序，具有许多配置选项。可以使用 `Alt` 序列获取帮助。在你构建的系统上阅读 `Minicom` 的帮助页（`man page`）将有助于你熟悉其功能。例如，可以添加一种 `Minicom` 配置，使其能够将拨号列表保存到软盘，这样重启后拨号列表就会保留。

从 `www.net-linux.net/walker/minicom.html` 下载 `Minicom`。如果那里没有，请使用 `freshmeat.net` 查找。如果你下载遇到困难，请使用 `http://ftpsearch.lycos.com` 查找文件名，并选择你附近的站点下载。在写作期间，最新版本为 `1.8.3`。

注意：使用 `Netscape` 下载以 `.gz` 结尾的文件时要小心。尝试下载本节中的文件时，你应该 `Shift+点击` 或右键点击并“另存为”。更多信息请参见 `Netscape` 文档。

如果你想为其他简单的单二进制应用程序构建启动软盘，你可以下载那个。

## 下载 Syslinux

`Syslinux` 的文档描述如下：

### Syslinux 是什么

`Syslinux` 是一种运行在 MS-DOS/Windows FAT 文件系统上的 Linux 引导加载程序。它旨在简化 `Syslinux` 的首次安装，并创建救援和特殊用途启动磁盘。在正确配置的情况下，`Syslinux` 可以完全消除分发启动软盘原始镜像的需求。在创建 `Syslinux` 软盘之前，可以使用标准的 MS-DOS（或任何可以访问 MS-DOS 文件系统的操作系统）工具对其操作。

### Syslinux 不是什么

`Syslinux` 可能不适用于通用引导加载程序。它只能从 FAT 文件系统启动 Linux，而不是例如 `ext2`。原生的 Linux 实现通常使用 `ext2`；另一个引导加载程序（例如 `LILO`）可能更合适。在实际包含 DOS 或 Windows 的系统中，使用它可能会更简单。然而，`Syslinux` 已证明其在许多特殊用途应用中非常有用。

# 步骤 131

查找以 `minicom:` 开头的行，并在下一行的某处添加 `-static`。这个单项开关将使运行应用程序所需的所有代码都包含在单个可执行文件中。例如，如果该行内容如下：

```
$(CC) $(LFLAGS) -o minicom $(MOBJS) $(LIBS)$
```

将其修改为：

```
$(CC) -static $(LFLAGS) -o minicom $(MOBJS) $(LIBS)$
```

接下来，你需要移除一个在内核嵌入式应用中没有必要的 `Minicom` 安全功能。在 `minicom.c` 中，删除包含字符串 `'You don't exist. Go away.'` 的整个 `if` 子句。如果不删除此逻辑，当执行运行到这一点时，`Minicom` 将直接退出。由于在你的嵌入式环境中不需要担心权限和正确的用户，因此删除此逻辑是安全的。

现在制作 `Minicom` 可执行文件：

```
make
```

如果一切顺利，你将得到一个名为 `minicom` 的静态可执行文件。你可以使用 `ldd` 命令检查它是否为静态文件：

```
$ ldd src/minicom
libc.so.6 => /lib/ld.so.6 (0x4001e000)
/lib/ld-linux.so.2 => /lib/ld-linux.so.2 (0x40000000)
```

回到项目根目录（`minicom`）并使用 `dd` 命令创建一个空的 `initrd` 镜像：

```
cd ../
dd if=/dev/zero of=fs bs=1k count=600
```

此命令创建了一个包含 600 KB 块的文件。每个块都填充了零。每次从头创建此文件很重要，因为尽可能地。如果你反复使用同一个文件，那些真正没有数据的块将无法很好压缩，因为它们不再仅充满零。（当文件被删除时，这些文件的内容仍然留在 `initrd` 中。）

# 修改并挂载文件系统

现在你准备好在 `fs` 文件中创建文件系统了。我们将使用 `e2fs` 文件系统，因为它是 Linux 中测试最充分的文件系统：

```
mkfs.ext2 .fs
```

提示：你的根文件系统有多种文件系统供选择。选择通常取决于 `ext2` 或 `minix`。我通常使用 `ext2` 文件系统，尽管 `minix` 文件系统要小得多。

现在挂载文件系统。Linux 的 `mount` 命令非常擅长从文件系统本身判断类型。如果出现问题，你可能需要使用 `-t` 选项告诉它正在处理的文件系统类型。

```
mount -o loop fs /mnt
```

# 创建设备

你准备好为你的嵌入式环境创建所需的文件了。你必须使用 `cp` 命令的 `-a` 选项以便复制目录条目而不是合并文件。

```
mkdir -p /mnt/dev
(cd /dev && cp -a console full kmm loop0 loop1 mem null port ram0 ram1 tty0 tty1 tty2 tty9 tty2 tty3 urandom zero /mnt/dev)
(cd /mnt/dev && ln -s /proc/core core)
(cd /mnt/dev && ln -s ram1 ram)
```

现在，为控制台创建 `terminfo`。该文件包含了控制台转义序列的定义，用于清除屏幕和绘制线条等操作：

```
cp -p /usr/share/terminfo/1/linux /mnt
```

# 拷贝 Minicom 可执行文件

将 `Minicom` 可执行文件拷贝到 `initrd` 文件系统并命名为 `/linuxrc`：

```
cp minicom-1.83.0/src/minicom /mnt/linuxrc
```

你将其命名为 `/linuxrc` 是因为这是 Linux 内核在完成引导后将运行的脚本（在这种情况下是程序）的名字。你可能会预期命名为 `init`。但由于你正在使用 Linux 内核的 `initrd` 功能将应用程序加载到内存中，你必须将其命名为 `linuxrc`，因为这是 Linux 在启动 `initrd` 时时预期的名称。

# 设置根目录

通过使用 `/mnt` 作为根目录运行 `linuxrc` 程序来测试设置。这样，你就知道 `/linuxrc` 运行的环境与它在设备上运行的环境相同：

```
chroot /mnt /linuxrc
```

`chroot` 运行第三个参数指定的命令，并使用第二个参数指定的目录。该命令无法访问指定根目录以外的计算机上的任何文件。你运行 `/linuxrc` 而不是 `/mnt/linuxrc` 是因为 `chroot` 发生在执行之前，而一旦 `chroot` 发生，`linuxrc` 文件就在新目录结构的根部了。

如果一切正常，`Minicom` 程序应该会启动。如果你很有冒险精神，可以连接一个调制调器并让 `Minicom` 充分测试。退出 `Minicom` 按 `Ctrl+A` 然后按 `X`。

# 压缩文件系统

现在，卸载 `initrd` 文件系统并尽可能压缩（`-9` 选项牺牲速度以换取更好的压缩率）：

```
mount /mnt
gzip -9 fs
```
