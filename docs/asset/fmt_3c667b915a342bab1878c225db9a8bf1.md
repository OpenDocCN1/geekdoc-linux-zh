
为了有效实施安全，系统管理员需要对黑客的漏洞以及这些漏洞的后果有一定了解。这样就可以制定出有效的策略来执行组织的安全策略。研究计算机安全漏洞的历史有助于从全局角度来看问题。

## 用户漏洞

任何获得用户级访问权限的人都可以窃取该用户可读取的任何数据。该用户 ID 可写的所有文件都应被视为损坏。大多数经验丰富的入侵者不会对用户级账户做什么，因为他们无法隐藏自己的踪迹。相反，他将利用用户级访问尝试获取 root 权限。

> 3 参考 `http://www.rootshell.com` 和 `http://www.insecure.org` 获取当前漏洞的示例。

## root 漏洞

一旦入侵者获得了系统的 root 权限，他将有能力删除或更改入侵证据。入侵者还会有能力向系统中安装后门，以便他在日后后可以在不被察觉的情况下进出系统。

通过监控系统以及与系统相关的正常活动，可能可以将异常活动与实际入侵联系起来。这就是为什么审查日志文件是安全执行中至关重要的组成部分。通过 `syslog` 进行远程日志记录有助于确保攻击期间日志信息的完整性。

## 陷阱与特洛伊马

许多公开的软件包被编写，是为了提高用户对在系统中安装后门的意识。最广为人的是 `rootkit`，它有许多变体。在互联网上搜索最新版本，并在自己的系统上对其进行实验，以了解可能实现的操作，以及如何阻止和检测它们。

假设私有软件包具有比互联网上找到的软件包更先进的功能是明智的。不要假设检测公共版本的措施就能检测到所有版本。

## 拒绝服务

拒绝服务攻击试图关闭或使计算服务失效。某些拒绝服务攻击会导致系统崩溃，而另一些则使系统过载，使其无法为合法用户提供服务。某些攻击只影响一个服务；另一些则影响整个系统或网络。

大多数拒绝服务攻击分为两类：利用网络栈漏洞的利用协议漏洞的 `fork` 炸弹以及针对特定网络应用程序（如 `X Windows` 系统）的攻击。

针对利用网络栈漏洞的拒绝服务攻击，唯一防御方法是关注完全披露的安全邮件列表，例如 `BugTraq`。不应完全依赖 `CERT`，因为他们不会公开许多报告给他们的漏洞。一旦漏洞被报告并发布了补丁，就应该应用该补丁，从作为防火墙的暴露系统开始。

利用协议漏洞的典型攻击涉及发送伪造目标地址和返回地址的数据包。其中之一是广播地址。因此，攻击者发送的少量数据包会导致大量数据包在两个伪造网络之间来回反射。

> 4. `BugTraq` 的地址是 `http://www.SecurityFocus.com/`

防御措施是在外部网关过滤所有指向网络广播地址或任何子网广播地址的数据包。使用 `iptchains`，命令

```
iptchains -A input -d xxx.xxx.xxx.xxx -j DENY
```

将丢弃目标字段为 `xxx.xxx.xxx.xxx` 的任何包。

由于绝没有理由发送指向另一个网络广播地址的数据包，因此在网关接收到的任何包都应被认为是恶意的。使用 `DENY` 而不是 `REJECT`，以避免向这些恶意数据包的所谓来源发送 ICMP 主不可达消息。

## 处置程序

当检测到入侵时，在决定是否收集证据之前要谨慎行动。如果需要收集，请将受影响的系统下线，并准备干净的备用机投入生产。

接下来，评估漏洞的性质和造成的损害。在用户级漏洞的情况下，发现并封堵漏洞、更改密码并恢复任何丢失或损坏的数据可能足够了。在 root 级漏洞的情况下，完全重新安装是确保系统没有后门的唯一方法。当然，在重新安装后，原始的安全漏洞仍然存在。必须找到并封堵它。

除非是家庭系统，否则永远不要排除违入可能是由内部人员实施或协助的。调查看似未受影响的机器上的日志，因为它们可能包含线索，也可能包含后门。

在恢复服务后，启动对安全策略的审查。如果内部缺乏知识，可以考虑聘请顾问。问问不同的策略或更严格的执行是否可以防止此类入侵的发生。如有必要，更新安全策略。

## 启动

所有现代计算机在启动操作系统时都使用相同的通用组件和相同的启动序列。CPU 在内部进行自初始化，然后开始从物理内存的一个固定地址开始获取指令¹。硬件工程师安排将程序化在 `EPROM` 或闪存 `EPROM` 中的固件映射到这些地址。这些指令通常会初始化硬件，然后加载要执行的下一层软件（通常从硬盘加载，但有时也从软磁盘、`CD-ROM` 或网络加载），最后将控制权移交给称为“引导装载程序”（`bootstrap loader`）的软件。如果计算机架构对引导加载程序的大小有严苛限制，有时会使用次级引导程序。随后，该引导程序会加载操作系统。

`LINUX` 操作系统也不例外这一模型。`LINUX` 与操作系统的不同之处在于，其初始化过程会根据所使用的硬件架构而异。这使得 `Linux` 能够与其他操作系统共存。它允许 `LINUX` 的引导加载程序中使用相同的设备驱动程序。其他 PC 操作系统的用户会对系统管理员可提供的海量启动配置选项感到惊讶。

在运行 `Linux` 的 Intel 架构 PC 上，固件加载的软件是一个名为 `LILO` 的包，即 `LINUX` 加载器。对于 Alpha 架构，使用两种机制之一——`MILO` 或 `boot`。对于 SPARC 架构，使用 `LILO`。在 Macintosh 硬件上，使用 `BootX`。

## PC 固件与加载器

遗憾的是，截至本文编写时，大多数基于 Intel 的 PC 固件都充满了漏洞，且不适用于 `Linux`。由于源代码没有广泛公开，这些漏洞并未得到修复。好消息是，`OpenBIOS` 正在进行中。在未来几年内，PC 主板可能会带有开源的 `BIOS` 出货，而那些有充分理由配置和编译自己固件的系统管理员可能比那时更早实现这一点。

系统管理员在 `OpenBIOS` 稳定后将专有 `BIOS` 替换为 `OpenBIOS` 的一个理由是：前者不支持网络启动，而后者支持。这将方便大量 PC 的安装和升级。

`LILO` 是一个很小的软件，用于控制加载和启动哪个内核。系统管理员决定在启动期间由哪一个 `LILO` 在控制台上呈现给用户。选择可能包括一个或多个 `Linux` 内核以及一个或多个其他操作系统。`LILO` 还为系统管理员提了通过 `/etc/lilo.conf` 文件向内核传递参数的机会。也可以通过在控制台运行 `lilo` 交互地设置选项。

`LILO` 通过运行 `/sbin/lilo` 实例化，它读取 `/etc/lilo.conf` 以确定系统管理员的意图。这创建了映射文件 `/boot/map`，记录了内核以及引导加载程序可能需要引的所有其他文件的位置。这非常关键，因为引导加载程序不支持文件系统；它必须通过文件在磁盘上的位置来引用它们。因此，每当内核发生变化时，重启之前必须运行 `/sbin/lilo`。不这样做可能会导致系统不稳定。

`lilo` 可以在多用户模式下运行并带有 `-t`（测试）或 `q`（查询）选项，以显示 `LILO` 在实际启动期间将做什么。更多细节请参阅 `lilo(8)` 页面。

在 `/etc/lilo.conf` 中可以配置的一些有趣选项包括：在解压缩和加载内核之前是否显示控制台提示符、最多 16 个可能加载的内核列表以及传递给每个内核的参数，以及如果存在提示符的超时时间。还有许多其他配置选项。它们记录在随 `LILO` 源代码分发的《`LILO` 用户指南》中。

`LILO` 有时被配置将 `ramdisk` 镜像压缩并加载到内存中，以及内核。`Linux` 内核使用内核加载启动介质所需的内核模块。最常见的情况是 `SCSI` 支持，将 `SCSI` 适配器驱动程序指定为内核模块。当驱动程序加载到内核中时，文件系统会被释放。

通常情况下，`/etc/lilo.conf` 的配置使得 `/sbin/lilo` 将 `LILO` 引导加载程序的第一部分（连同分区表）安装到要启动系统的硬盘的主引导记录（`MBR`）中。`LILO` 引导加载程序的第一部分加载第二部分，通常是 `/boot/boot.b`。然而，`/etc/lilo.conf` 也可以配置为将 `LILO` 安装在其他地方，例如软磁盘或启动分区的第一个扇。后者允许将 `MBR` 的管理留给系统上安装的任何其他操作系统的软件。

除了向内核传递参数外，`LILO` 还能向 `init` 传递参数。这些参数的作用是定义环境变量。有关在 `Boot:` 提示符处传递参数的更多信息，请参阅 `BootPrompt` `HOWTO`。

在 PC 上启动 `LINUX` 的另一种机制是 `Loadlin`，它从 Microsoft `Windows` 内部启动 `LINUX`。
