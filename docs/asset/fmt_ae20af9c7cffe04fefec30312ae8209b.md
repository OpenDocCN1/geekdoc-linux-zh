> 注意 — 某些命令返回的状态不恰；使用 `-i` 或横杠 (`-`) 命令前缀来克服这一困难。

包含字符 `=`、`:` 和 `@` 的文件名无法工作。由 shell 直接执行的命令（特别是 `cd(1)`）在 `make` 的换行符之间无效。语法 `lib(file1.o file2.o file3.o)` 是非。你不能从 `file.o` 构建 `lib(file.o)`。

## 选项

- `-e` 环境变量覆盖 `makefile` 内部赋值。
- `-f makefile` 指定描述文件的名称。
- `-i` 忽略调用的命令返回的错误码。
- `-k` 如果当前条目失败，则放弃该工作，但继续处理不依赖于该条目的其他分支。
- `-n` 打印命令但不执行它们。即使命令行以 `@` 开头也打印。
- `-p` 打印完整的宏定义集和目标描述。
- `-q` 询问目标文件是否已更新。`make` 返回 `0` 或非零状态码。
- `-r` 不使用内置规则。
- `-s` 在执行前不打印命令行。
- `-t` 触摸目标文件（更新它们）而不是发布常规命令。

# 创建 makefile

使用 `-f` 选项调用的 `Makefile` 是一个结构严谨的文件。它包含了更新和重新生成程序的显式指令。一组指定依赖关系的条目。一个条目的第一行是一个由空格分隔的非空目标列表，接着是一个冒号 `:` 然后是（可能为空的）先决文件或依赖项列表。在 `;` 之后所有以 Tab 键开头的行都是为了更新目标而执行的 shell 命令。第一个不以 Tab 或 `#` 开头的非空行开始一个新的依赖关系或宏定义。你可以使用反斜杠-换行 (`\newline`) 序列跨行继续书写 shell 命令。`make` 打印的所有内容（初始 Tab 除外）都将原样传递给 shell。因此，以下序列

```
echo a\
b
```

产生

`ab`

这与 shell 的行为完全一致。换行符 (`#`) 和换行符包裹着包含 `\newline` 序列的命令。

以下 `Makefile` `pgm` 依赖于两个文件 `a.o` 和 `b.o`，而这两个文件又依赖于相应的源文件（`a.c` 和 `b.c`）以及一个公共文件 `incl.h`。

```
pgm: a.o b.o
cc a.o b.o -o pgm
a: incl.h a.c
cc -c a.c
b: incl.h b.c
cc -c b.c
```

命令行逐行执行，每个由其自己的 shell 执行。你可以使用环境变量 `SHELL` 来指定 `make` 执行命令使用的 shell。默认是 `/usr/bin/sh`。命令行的两个字符可以是 `@`、`-` 或 `-`。如果存在 `@`，则抑制命令打印。如果存在横杠 (`-`)，`make` 将忽略错误。除非你指定了 `-s` 选项、`Makefile` 中包含 `SILENT:` 或初始字符包含 `@`，否则执行时会打印行。`-n` 选项指定打印但不执行；然而 `-t` 选项更新目标文件。`-i` 选项忽略错误。`-k` 选项放弃当前条目的工作。`-e` 选项覆盖赋值。`-f` 选项指定描述文件。`-p` 选项打印宏定义。`-r` 选项不使用内置规则。`-s` 选项不打印命令行。

`$`

当来自 `Makefile` 的显式规则被求值时执行。它是相对于目标已过时的先决条件列表，本质上是那些必须重新构建的模块。

除了 `$7` 之外，所有宏都可以有替代形式。当在四个宏后附加大写的 `D` 或 `F` 时，其含义分别变为“目录”（directory）或“文件部分”（file part）。因此，`$(D)` 指向字符串 `$` 的目录部分。如果没有目录部分，则生成 `/`。

# 后缀 (Suffixes)

某些名称（例如以 `.o` 结尾）具有可推断的先决条件，如 `.c`、`.s` 等。如果 `Makefile` 中没有此类文件的更新命令，且存在可推断的先决条件，则该先决条件将被编译以生成目标。在这种情况下，`make` 拥有相应的规则，通过检查后缀并确定使用的合适的推断规则来从其他文件构建文件。

```
.c  c~  .f  f~  .s  s~  .sh  sh~  C~
.c  a  .c~a  .c~c  .o~o  .f~f  .a~a  .f.f  .y.y
.h  h~  1.c  1~c  1.o  1~o  1.-l -1~l  1.-o -1~o  a.s  a~s  s.-a -s~a
.s  s~  y.c  y~c  y.o  y~o  Y.-C -Y~C  L.-o -L~o  C.-c -C~c
C.-C  L.o  L~o  L.-L -L~L  Y.o  Y~o  Y.-C
```

`make` 的内部规则包含在程序的 `make.rules` 源文件中。这些规则可以进行本地修改。要以适用于重新编译的格式打印出任何机器上编译到 `make` 中的规则，请使用以下命令：

```
make -pf 2>/dev/null
```

上述规则中的波浪号 `~` 指向 `SCCS`（参见 `sccs-file(4)`）。因此，规则 `.c~o` 会将 `SCCS` C 源文件转换为对象文件（`.o`）。由于 `SCCS` 文件的 `s` 是前缀，它与后缀视角不兼容。在这里，波浪号是引用任何文件到 `SCCS` 文件引用的一种。

仅有一个后缀的规则（例如 `.c:`）定义了如何从 `x.c` 构建 `x`。实际上，另一个后缀为空。此功能对于从单个源文件构建目标有用，例如 shell 程序和简单的 C 程序。

额外的后缀作为 `.SUFFIXES` 的依赖列表给出。顺序至关重要：文件和规则的第一个可能名称将推断为先决条件存在。默认列表为：

`.SUFFIXES: ~o ~c ~y ~l ~s ~s ~sh ~h ~h~ ~f ~f~ ~C C~ .Y ~Y ~L~`

再次，打印内部规则的命令显示了当前机器实现的后缀列表。多个后缀列表会累积；没有依赖的 `SUFFIXES:` 清空列表。

# 推断规则 (Inference Rules)

第一个示例可以用更简洁的方式完成。

```
pgm: a.o b.o
cc a.o b.o -o pgm
a.o b.o: incl.h
```

这种省略可行，是因为 `make` 有一套用于构建文件的内部规则。你可以通过简单将它们放入 `Makefile` 来此列表中添加规则。默认推断规则使用某些宏，允许在任何生成的命令中包含可选内容。例如，`CFLAGS`、`LFLAGS` 和 `VFLAGS` 用于编译器 `cc(1B)`。同样，建议使用前述方法检查当前规则。

对先决条件的推断是可以受控制的。从后缀为 `.c` 的文件创建后缀为 `.o` 文件的规则被指定为 `.c.o:` 作为目标且无依赖。与目标相关的 shell 命令定义了从 `.c` 文件制作 `.o` 的规则。任何不包含斜杠且以点开头的目标都被识别为规则而非真实目标。

# 库 (Libraries)

如果目标或依赖项名称包含括号，则被假设为存档库。括号内的字符串指向库中的一个成员。因此，`lib(file.o)` 和 `$LIB(file.o)` 都指向一个包含 `file.o` 的存档库（此示例假设 `LIB` 宏已预定义）。表达式 `$LIB(file1.o file2.o)` 是非法的。与存档库相关的规则格式为 `.XX`，其中 `XX` 是用于制作存档成员的后缀。当前实现的一个遗憾副作用是 `XX` 必须与存档成员的后缀不同。因此，你不能让 `lib(file.o)` 依赖于 `file.o`。存档接口的最常用用法如下。这里假设源文件是 C 类型。

```
lib(file1.o) lib(file2.o) lib(file3.o)
@echo lib is now up-to-date
```
