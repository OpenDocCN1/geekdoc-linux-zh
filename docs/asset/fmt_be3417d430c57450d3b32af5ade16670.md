
| more | 一次一屏地显示文本文件 |
| paste | 将单列文本转换为多列 |
| roff | 综合文本格式化器和排版器 |
| sed | 非交互式文本行编辑器 |
| sort | 对文本列进行排序 |
| tail | 显示文件的最后 $n$ 行 |
| test | 比较两个字符串是否相等 |
| tr | 替换文件中的选定字符 |
| wc | 统计文件的行数、单词数或字符数 |

这些工具中的许多具有上述列表之外的其他功能。例如，`awk`可以交替使用字母和数字文本。`test`可以检查文件模式，以了解用户是否可写文件。`Lex`通过匹配输入流中的字符串表达式提供 C 语言语言的接口。`Sed`强大足以取代`grep`和`tail`等命令。

这些命令的混合模式能力倾向于模糊文本与传统意义上数据之间的界限。在这里，更容易表示以前存储在二进制文件中的文本格式。Unix 程序员通常将数值数据存储在文本文件中，因为 Unix 环境提供了丰富的工具来操作它们。

将数据存储为文本，然后用一组小型、面向文本的工具进行处理，使得 Unix 系统成为强大的数据处理器。由于在所有的 Unix 和 Linux 系统上都可以使用`awk`、`sed`和`grep`等工具，选择、修改和移动数据的能力对所有人来说都变得更加可及。即使不是程序员的人也能轻松阅读和解释存储在平坦文本中的数据。

惠普 OpenVMS 操作系统的开发人员可能正确地认为大多数人害怕计算机。然而，Unix 并没有保护用户免受系统，而是将他们带入系统内部。它引导他们穿过迷宫般的逻辑轨迹，而他们手中握着最后的熟悉感——即可以阅读和理解的格式的数据。

# 第 4 章

对于对“不友 Unix 界面”的所有批评，Unix 可能是所有系统中最友好的。用户可以随时查看自己的数据，而无需成为精通解释复杂二进制文件格式的系统大师。

## 4.2.4 增强的可移植性克服了速度的缺乏

在整个讨论过程中，你可能一直在想：“是的，可移植性很好，但性能如何？使用平坦文本文件确实会慢一点。表示一个二进制文件的内容需要二三个字符。”所以你可能在谈论性能下降了三倍。这听起来很大，但实际上并不如此，除非是高分辨率实时应用。

如果需要额外的时间将数据从不可移植的格式转换以便移动，那么当数据到达时价值就没那么高了。世界运行得太快，没时间等待你的数据。

## 4.2.5 速度的缺乏被下一年的机器克服

在整个讨论中，你可能已经意识到文本文件对性能造成了拖累。你可能可能会面临高达三倍的性能下降。这听起来很大，但实际上完全不是，除非是在实时应用或罕见的 TB 级数据仓库应用中。然而，即使在巨大的数据仓库应用中，用户吸收和分析的也只是微小的（至少按人类标准而言）数据抽象。因此在某个点，数据量将减少到按 CPU 周期标准来说微不足道的程度。

最终，每个应用程序都会被移植到新系统，或者它们灭亡。计算机制造商的持续压力使今天可能昂贵的设备在明天变得廉价。在一个维护成本日益增加的慢系统中运行应用程序是不划算的。

今天足够的速度，明天将绰绰有余。几年后，你甚至可能开始考虑如何减慢速度，以便人们能用得上它！

# 案例研究：一位 Unix 哲学者的百宝箱

我们已经看到，在高效性和可移植性之间做出选择时，Unix 程序员更倾向于后者。因此，当新平台出现时，他们的应用程序往往首批运行在新平台上的程序。这使得他们的软件在市场中具有绝对的优势。在一个机会之窗一夜之间开启又瞬间关闭的世界里，这决定了你是行业领导者，还是那些望而未的追随者之一。

Unix 程序员是如何接受这些信念的？大多数早期的软件工程师在学校里并没有学过可移植性的重要性，至少不是带着任何坚定的信念。更有可能，他们通过第一手经验学习了可移植代码的价值以及最佳实践。

大多数所谓的 Unix“大师”们都拥有一系列程序和 shell 脚本，它们构成了他们的个人工具箱。这些工具随着他们从一台机器、一份工作到一家公司一直跟随他们。为了说明这个问题，让我们来看看一位 Unix 哲学者的百宝箱。

# 第 4 章

我将一些脚本转换成了别名（aliases），供 C shell 使用，这是一种最初存在于 Berkeley Unix 系统上的活动命令解释器。别名允许你指定频繁使用命令的替代形式，而无需将所有内容都放入 shell 脚本中。如果是 shell 脚本，它们也是可移植的。

我最初是在一家从事报纸排版系统制造的小型公司、在 Digital PDP-11/70 上构建了这些工具。随着公司增加了新的软件开发系统，我将它们迁移到了同样运行 Unix 的 PDP-11/34、PDP-11/44 和 LSI-11/23 系统。考虑到 PDP-11 系列闻名的兼容性，这听起来似乎不是什么伟举，但请等。好戏在后。

最终，我为了追求其他机会离开了公司，带着我的工具在九条轨道上跳槽。这些 C 程序和 shell 脚本很快在 Digital VAX-11/750 上找到了家园。VAX-11/750 的性能比我那些较小的 PDP-11 大得多；因此，它们在新的公司运行得快了一些。当公司用 VAX-11/750 替换为 VAX-180 时，工具的速度再次提升。这一切在未对工具进行任何修改的情况下完成的。

大约那时，工作站——那些神奇的、“让我独享整台该死的计算机”的盒子——登场了。每个人都抢着从 Sun Microsystems 购买热门新机器，我的雇主也不例外。因此，那些从 PDP-11 迁移到 VAX 的工具突然发现自己可以在无需修改的情况下运行在 Sun 工作站上。

由于我的软件工程生涯的大部分时间是在英国度过的，我发现原始数字公司的最新设备在波士顿周边百英范围内相当常见。再次，我将我老而可靠的 C 程序和 shell 脚本迁移到了 Digital 系列，一直到了 VAX 8600 系列，随后又到了 VAX 8800 系列。再次，这些工具在无需修改的情况下运行。

需要是午夜发明的母亲。我当时工作的一位软件工程师注意到仓库里堆积了大量落灰的 Digital Professional 350。一个有进心的人得出结论，这些 350 可以成为我们家里的极佳个人电脑，特别是如果它们运行的是 Unix 的话。于是他着着将一个 Unix 版本移植到 350 上。我的工具很快紧随其后。

接着，VAXstations 队列和早期版本的 X Window System 相继到来。可移植的窗口系统是实用用户界面演进的一大步。尽管窗口系统有所有华丽的效果，我仍然发现我最喜欢的工具在 xterm（终端模拟器）窗口中非常有帮助。

但计算机业务是一项高风险的业务。你必须保持灵活性才能处于顶尖。对于软件工程师来说，灵活性转化为了可移植性。如果你的软件不能移植到最新的机器上，它就完蛋了。所以，当基于 RISC 的 DECstation 3100 和 5000 出现时，这是一个“不移植就死亡”的局面。我的工具再次展示了它们对可移植性的偏爱。

今天，我的小百宝箱运行在各种 Linux 发行版、各种大小的机器上——且无需任何修改。

每件价值在 100 到 150 美元之间。最终她意识到，虽然她是一个塑料推销员，但每周可以推销的时间是有限的。于是她找到了另外二十个人，并向他们推销销售乐扣（Tupperware）的想法。他们每人每周都会举办一次聚会，他们加起来每周总共举办百场。她向这二十个人卖碗，每件只赚取小额利润。没过多久，这二十个人就理解了这种“金字塔式”扩张的价值。每个人都有二十个人在为他们卖碗。

剩下的就是多级营销的历史了。

然后，我姨妈分享了一句非常有用的智慧：无论你多么聪明、精力充沛或多么具侵略性，你的精力都是有限的。如果你想取得惊人的成功，就必须倍增你对世界的影响。仅仅拥有高智商或在夏威夷卖滑雪场的能力是不够的。你需要启动企业，来分发并增强你的才华和能力的影响。对于你的每小时劳动，要预期获得你付出五倍、百倍甚至千倍的回报。
