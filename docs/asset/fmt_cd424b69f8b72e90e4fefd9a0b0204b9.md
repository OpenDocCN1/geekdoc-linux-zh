## 总结

正如你在本章看到的，创建、维护和修复文件系统并不是一项简单的任务。然而，这是一项必须充分理解的任务，否则系统将毫无用处。让我们快速概述一下涵盖的主题：

- 磁盘被分为分区（有时称为 slices）
- 每个分区都有文件系统
- 文件系统是 UNIX 存储的主要手段
- 文件系统由 inode 和 superblock 组成
- 某些分区用于原始数据，如交换（swap）
- `/proc` 文件系统不是文件系统，而是对内核数据的抽象
- inode 维护着关键信息
- superblock 跟踪磁盘信息以及 inode 列表
- 为了使用文件系统，必须将其挂载
- 为了卸载文件系统，没有人
- 文件系统可以挂载在目录树的任何地方
- `/etc/fstab`（在 Solaris 中）用于系统启动时自动挂载
- 根文件系统应该与用户隔离
- 根文件系统永远不应该填充
- `fsck` 是修复文件系统的工具

简而言之，文件系统管理不是一项简单的任务，不能轻视。良好的维护技术有助于你的系统运行时间，同时也如此。

## 什么是内核？

让我们先为内核术语提供定义。UNIX 内核是管理用户程序访问硬件软件资源的软件。这些资源范围从 CPU 时间、访问内存、写入磁盘驱动器、连接网络以及与终端或 GUI 交互。内核通过控制和提供对内存、处理器、输入输出设备、磁盘文件以及用户程序的特殊服务来实现这一切。

## 内核服务

基础 UNIX 内核分为四个子系统：

- 进程管理
- 内存管理
- I/O 管理
- 文件管理

这些子系统应该被视为独立的实体，它们协作工作为程序提供有意义的服务。这使得用户能够通过界面访问数据库、打印报告或执行复杂的应急管理任务。在系统的任何时刻，许多程序都会向这些子系统请求服务。内核的责任是调度工作，并在授权的情况下授予对子系统的访问。简而言之，程序通过软件库和调用接口与子系统交互。请参考你的 UNIX 手册获取系统支持的调用和库的描述。由于每个子系统都是进程执行有用功能的关键，我们将涵盖每个子系统的基础知识。我们将从观察 UNIX 内核如何通过系统初始化过程产生。

# 系统初始化

系统初始化（启动）是使你的系统进入运行状态的第一步。在你的系统开始提供服务之前，有许多依赖于机器和不依赖于机器的步骤被执行了。在启动时，中央处理器 (CPU) 上没有运行任何内容。内核是一个复杂的程序，它必须从某种类型的存储设备（通常是磁盘驱动器）在特定地址加载其镜像。启动过程包含一个称为引导区的限制区域，其中包含一个加载并初始化内核的程序。你会发现这是一个特定厂商的程序，反映了不同 UNIX 平台之间的架构差异。当此步骤完成后，CPU 必须跳转到一个内存地址并开始执行该位置的代码。一旦内核加载，它将通过其硬件和软件初始化。

## 内核模式

操作系统（或内核）以称为内核模式的特权方式运行。这种操作模式允许内核运行，而不受系统中其他程序的干扰。微处理器强制执行用户级和内核级之间的界限。由于内核在受保护的地址空间中运行，可以保证其数据结构和其他进程的完整性。（并不是说特权进程可能会无意中导致内核损坏。）

# 进程管理

进程管理子系统控制进程的创建、终止、统计和调度。它还负责进程状态以及特权和非特权执行模式之间的切换。进程管理子系统还协助和管理创建子进程的复杂任务。

进程的简单定义是它是正在执行的程序。它是一个需要系统资源且具有有限寿命实体。它具有通过系统调用接口创建其他进程的能力。简而言之，它是一个电子
用户或程序员完成某些有用工作的意图表示。对于用户来说，一个进程看起来就像是机器上运行的唯一任务。这种“障眼法”只是一种幻觉。在任何时刻，处理器只在执行单个进程。

## 进程结构

进程具有确定的结构（见图 19.1）。内核将这一串位视为进程映像。该二进制映像由用户地址空间、系统地址空间以及在进程执行期间存储进程数据的寄存器组成。用户地址空间也被称为用户映像（user image）。这是程序员编写并编译成 ".o" 文件的代码。对象文件是包含机器语言代码数据的文件，其格式供链接器程序使用以创建可执行程序。

进程区域图。

用户地址空间由五个独立的区域组成：文本（Text）、数据（Data）、Bss、栈（stack）和用户区（user area）。

**文本段 (Text Segment)** 进程的第一个区域是其文本段。该区域包含进程的可执行程序代码。它是固定且不可更改的，当内存紧张时会被系统交换出。

**数据区 (Data Area)** 数据区包含程序使用的全局变量和静态变量。例如，程序员可能预先知道某个数据变量需要设置为某个值。在 C 语言中，它看起来如下：

```c
int x = 15;
```

如果你在程序加载时查看数据段，你会发现变量 `x` 是一个初始值为 15 的整数。

**Bss 区 (Bss Area)** bss 区域像数据区一样，持有程序变量的信息。区别在于，bss 区域维护了在执行期间被分配了数据值的变量。例如，程序员可能知道这些变量将持有用户在程序执行期间输入的某些数据。

```c
int a,b,c;           // a,b 和 c 是持有整数值的变量。
char *ptr;          // ptr 是一个未初始化的字符指针。
```

程序还可以调用 `malloc` 等库函数来分配一块内存，并将其分配给上面声明的一个变量。

**栈区 (Stack Area)** 栈区维护局部变量、函数中使用的参数以及函数返回的值。例如，程序可能包含调用另一个代码块（可能由他人编写）的代码。调用代码块通过栈将数据传递给接收代码块。被调用的代码块将数据返回给调用者。栈在允许进程处理临时数据方面起着重要作用。

**用户区 (User Area)** 用户区维护进程运行时内核内核使用的数据。用户区包含真实和有效用户标识符、真实和有效组标识符、当前目录以及打开文件列表。系统还维护了文本、数据和栈区域的集合，以及指向进程结构的指针。其他被视为进程地址空间部分的区域还包括堆、私有共享库数据、共享库和共享内存。在程序的初始启动和执行期间，内核会分配内存并创建必要的结构来维护这些区域。

内核使用用户区来管理进程。该区域维护了进程的大部分计账信息。它是地址空间的一部分，仅在进程执行时由内核使用（见图 19.2）。当进程未执行时，用户区可能会被磁盘内存交换出。在大多数 UNIX 版本中，用户区被映射到一个固定的虚拟内存地址。在 HP-UX 10.X 下，虚拟地址为 `0x7FFE6000`。当内核执行上下文切换（启动不同的进程）到新进程时，它将始终固定在内存中的此位置；这只是引用当前的 u 来开始管理新换入进程的简单问题。文件 `/usr/include/sys/user.h` 包含你对应版本 UNIX 的用户区结构定义。

## 进程表 (Process Table)
进程表是内核用于管理系统中进程另一个重要结构。进程表是一个进程结构数组，内核利用它来管理进程的执行。每个表项都定义了一个内核创建的进程。进程表始终驻留在计算机内存中。这是因为内核在将进程换入出 CPU 时会反复查询和更新该表。对于当前没有在执行的进程，内核会出于调度目的更新其进程表结构。你系统的进程结构定义在 `/usr/include/sys/proc.h` 中。

# Fork 进程 (Fork Process)
内核为每个进程提供了工具，用于复制自身以创建新进程。这个新实体被称为子进程。`fork()` 系统调用由现有进程（父进程）调用并创建父进程的副本。虽然一个进程只有一个父进程，但它可以产生许多子进程。新进程从其父进程继承某些属性。HP-UX 10.0 的 `fork()` 系统调用文档（HP 9000 Computers HP-UX Reference Release 10.0 Volume 3 of 4 中的 `fork(2)`）列出了以下由子进程的内容：

- 真实、有效和保存的用户 ID
- 真实、有效和保存的组 ID
- 辅助组 ID
- 进程组 ID
- 环境
- 文件描述符
- 执行时关闭标志 (Close-on-exec flags)
- 信号处理设置
- 信号掩码
- 性能分析开启/关闭状态
- 计账中的命令名
- Nice 值
- 附加的共享内存
- 当前工作目录
- 根目录
- 文件模式创建
- 文件大小限制
- 实时优先级

当注意的是当内核创建子进程时，子进程与父进程的区别。由于父进程仍在执行，简单的代码检查状态是否为 0 并继续该分支。以下简短伪代码有助于澄清这一点：

```
start
print " 我是一个进程 "
print " 我现在将复制我自己 "
if fork() > 0
    print " 我是父进程"
    exit () or wait ()
else if fork() == 0
    print " 我是新的子进程"
    print " 我现在准备好启动一个新程序"
    exec("new_program")
else fork 失败
```

子进程还可以调用一个调用，用新程序的映像替换子进程的映像。系统将使用 `exec()` 完全覆盖文本、数据和 Bss 区域。这就是系统能够执行多个程序的原因。通过结合使用 `fork()` 和 `exec()` 系统，系统可以为程序员需要处理的任何任务执行大量程序。除了启动时的系统级进程外，这就是内核运行系统所需众多任务的方式。
