
在下一个 `makefile` 中，一个对象文件列表被赋值给名为 `OBJECTS` 的变量。在之前的 `makefile` 示例中，`bookrec` 依赖行你输入了对象文件列表，同时出现在依赖文件列表和链接这些文件的 `cc` 命令中。在这个 `makefile` 中，你只需要在两个地方通过 `$(OBJECTS)` 输入 `OBJECTS` 变量的求值。同样在 `makefile` 中，还定义了变量 `CFILES` 并为其赋值了所有 C 源代码文件的列表。该变量随后用于 `print` 依赖行，为 `lp` 命令提供所有 C 源代码文件的列表。注意，`make` 变量的操作方式有点类似于 `shell` 变量。你使用赋值运算符将字符串分配给变量。然后使用美元符号来求值变量。然而，与 `shell` 变量不同，在求值变量时你必须将变量名放在括号内。

`make` 变量的值是字符串。该字符串可以是任何字符集。例如，在下一个 `make` 示例中，字符串 `"Printing out the source-code files"` 被赋值给变量 `PRINTNOTICE`。该变量随后在 `print` 依赖行中求值，作为 `echo` 命令的参数。该字符串显示在屏幕上，通知用户正在打印源代码。`echo` 命令本身有一个 `@` 运算符，它会抑制实际 `echo` 命令的显示。`make` 将显示它执行的每个命令，除非使用 `@` 运算符指示不要。

赋值给变量的文件名列表实际上只是一个字符串。就像你可以将文件名分配给变量一样，你也可以分配编译器选项。对于变量来说，选项实际上只是字符串。选项用连字符加字母代码，有时跟一个参数表示。在下面的示例中，变量 `LINKFLAGS` 包含选项 `-o` 以及后续文件名。此选项允许用户为可执行文件指定另一个名称，在这种情况下为 `bookrec`。

## `makefile`

```
CFILES = main.c io.c
OBJECTS = main.o io.o
LINKFLAGS = -g -o bookrec
PRINTNOTICE = Printing out the source-code files
```

```
bookrec : $(OBJECTS)
cc $(LINKFLAGS) $(OBJECTS)
```

```
print :
@echo $(PRINTNOTICE)
lp $(CFILES) &
```

```
$ make print
Printing out the source-code files
lp main.c io.c &
```

## `make` 预定义变量

在执行 `make` 命令时，`make` 会定义从 `shell` 导出的变量，以及若干个供其自身使用的标准变量。预定义变量持有编译器名称和编译器选项。例如，`CC` 保存系统 C 编译器的命令名称（通常为 `cc`），`FC` 保存系统 Fortran 编译器的命令名称。编译器选项存储在名称以 `FLAGS` 结尾的变量中。例如，`CFLAGS` 持有标准的 C 编译器选项，如 `-O`（它会调用优化器）。`FFLAGS` 持有 Fortran 编译器的标准选项。

下表列出的预定义变量如果你对同一种编程语言有多个不同的编译器，或者系统编译器频繁更改，那么这些变量将很有用。假设你的系统上有几个不同的 C 编译器可供选择。其中一个将被视为默认编译器，并将其名称赋值给 `CC` 变量。然而，在你的 `makefile` 中，你可以更改任何预定义变量的值。要使用其中一个 C 编译器或另一个，只需将该编译器的命令名赋值给 `CC` 变量。选项变量也是如此。要向 `CFLAGS` 变量添加 `-g` 选项，只需在你的 `makefile` 中将其赋值为 `-O`。使用预定义变量的优势是，它们持有的命令名称也会用于隐式 `make` 操作，这些操作你不需要显式地输入依赖行。

| 预定义变量 | 默认值 | 说明 |
|---|---|---|
| `CC` | `gcc` | C 编译器 |
| `CFLAGS` | `-O` | C 编译器的选项 |
| `AS` | `as` | 汇编器 |
| `ASFLAGS` | | 汇编器的选项 |
| `FC` | `f77` | Fortran 编译器 |
| `FFLAGS` | | Fortran 编译器的选项 |
| `LD` | `ld` | 链接对象文件的加载器 |
| `LDFLAGS` | `lex` | 词法分析器：从 .files 创建 .c 文件 |
| `LFLAGS` | | 词法选项 |
| `MAKE` | `make` | `make` 工具 |
| `MAKEFLAGS` | `b` | `make` 的选项 |

## `make` 特殊变量

在执行 `make` 命令时，`make` 定义了从 `shell` 导出的变量，以及若干个供其自身使用的标准变量。预定义变量持有编译器名称和编译器选项。例如，`CC` 持有系统 C 编译器的命令名称（通常为 `cc`），`FC` 持有系统 Fortran 编译器的命令名称。编译器选项存储在名称以 `FLAGS` 结尾的变量中。例如，`CFLAGS` 持有标准的 C 编译器选项，如 `-O`（它会调用优化器）。`FFLAGS` 持有 Fortran 编译器的标准选项。

下表列出的预定义变量如果你对同一种编程语言有多个不同的编译器，或者系统编译器频繁更改，那么这些变量将很有用。假设你的系统上有几个不同的 C 编译器可供选择。其中一个将被视为默认编译器，并将其名称赋值给 `CC` 变量。然而，在你的 `makefile` 中，你可以更改任何预定义变量的值。要使用其中一个 C 编译器或另一个，只需将该编译器的命令名赋值给 `CC` 变量。选项变量也是如此。要向 `CFLAGS` 变量添加 `-g` 选项，只需在你的 `makefile` 中将其赋值为 `-O`。使用预定义变量的优势是，它们持有的命令名称也会用于隐式 `make` 操作，这些操作你不需要显式地输入依赖行。

`make` 有一组特殊定义的变量，持有关于当前依赖行的信息。它们的值会从一个依赖行变为另一个。三个特殊变量可以在普通依赖行中使用：`$$`、`$` 和 `$?`。`$` 和 `$$` 持有目标名称。`$?` 持有比目标更新的文件列表。某些特殊变量仅适用于特殊依赖行。例如，`*` 和 `<` 仅用于后缀规则，而 `%` 仅用于库依赖行。它们将在后面的章节中讨论。特殊变量如下表所示。

| 变量 | 说明 |
|---|---|
| `@@` | 依赖行中的目标 |
| `$$` | 目标文件名 |
| `$?` | 比目标更新的文件 |
| `$%` | 库的成员文件 |
| `$<$` | 用于后缀规则的第一个 |

在之前的 `Makefile` 中，`print` 依赖行打印了所有源代码。然而，如果你只想打印最近更改的文件，`$?` 变量将持有这些更改的文件名。你可以将该变量用于 `lp` 命令以打印文件。下面的 `print` 依赖行显示了如何这样做。

```
print : main.c io.c
lp $?
```

## 220 `make` 工具

`print` 依赖行最后执行了。注意在 `lp` 命令之后有一个 `touch` 命令。`touch` 之前的 `@` 是一个抑制显示的特殊 `make` 指令。

变量 `$@` 保存目标名称。当你需要在依赖行的 `Linux` 命令中引用目标名称时，它非常有用。在之前的 `makefile` 中，没有在 `gcc` 命令中重复 `bookrec`，而是使用了 `$@` 变量。这将确保如果你更改了目标名称，`gcc` 命令将使用相同的名称。

## `make` 目标

除了特殊变量，`make` 还有一组用于提供不同功能的特殊目标。特殊目标以点开头并使用大写字母。例如，特殊目标 `.SILENT` 将抑制通常的 `Linux` 命令显示，而 `.IGNORE` 将允许你的 `makefile` 在 `Linux` 命令失败时继续执行依赖行。默认情况下，如果 `make` 执行返回错误码的 `Linux` 命令，它将停止。`.IGNORE` 特殊目标忽略所有错误码。

`.PRECIOUS` 特殊目标指定了你不希望在 `make` 被中断时被删除的目标。在某些情况下，你需要保留目标文件以保存其时间戳。例如，`print` 目标文件的时间戳用于打印最近更改的文件。如果由于某种原因，`print` 依赖行中的 `lp` 命令在执行过程中中断，`make` 默认会删除目标文件 `print`。然而，你可以通过将 `print` 列入 `.PRECIOUS` 特殊目标来覆盖这一默认行为。`print` 文件不会被删除。

## `make` 工具 221

如果没有依赖行或内置规则来处理某个目标，则执行 `.DEFAULT`。例如，如果用户输入的目标作为 `make` 的参数并不存在，则执行 `.DEFAULT` 目标。（注意，目标并不非是显式的；它也可以是内置的。）

在接下来的 `Makefile` 示例中，用户使用 `.SILENT` 目标抑制命令的显示；使用 `.IGNORE` 目标忽略命令错误；使用 `.PRECIOUS` 目标在发生中断时保留 `print` 目标；如果目标没有显式或隐式的依赖行，则输出错误消息。

```makefile
.SILENT:
.IGNORE:
.PRECIOUS: print
```
