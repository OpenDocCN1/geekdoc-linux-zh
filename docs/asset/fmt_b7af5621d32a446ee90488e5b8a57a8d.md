## 合并

你可以通过 `cvs update` 命令的 `-j` 选项将分支上所更改合并到本地文件的工作副本中：

`$ cvs update -j release-1-0 print.c`

使用此命令，你可以将主主干中 `print.c` 的最新版本与 `release-1-0` 中的修改进行合并。在下次提交后，这些更改将并入主主干。

## 冲突解决

由于多个开发者可以同时检出并修改文件，可能会导致冲突。例如，假设你刚刚完成了文件版本 `1.4` 的工作，并运行了 `update` 命令：

`$ cvs update print.c`

`RCS file: /users/home/project/src/print/print.c,v`

`retrieving revision 1.4`

`retrieving revision 1.7`

`Merging differences between 1.4 and 1.7 into print.c`

`rcsmerge warning: overlaps during merge`

`cvs update: conflicts found in print.c`

`C print.c`

当源文件的公共部分发生冲突更改时，会打印这些信息。你必须手动处理这些冲突。在本示例中，`print.c` 文件的本地副本保存在文件 `.#print.c.1.4` 中。`print.c` 的新本地内容如下：

```c
#include <stdio.h>
int print(char *args[])
{
  if (parse(args) < 1)
  {
    <<<<<<< print.c
    fprintf(stderr, "Invalid argument list.\n");
    =======
    fprintf(stderr, "No arguments present.\n");
    >>>>>>> 1.7
  }
  ...
}
```

注意冲突条目是如何通过 `<<<<<<<`、`=======` 和 `>>>>>>>` 清晰标记的。你需要手动解决这段代码。在与负责该冲突更新的开发者协商并对文件进行适当更改后，可以使用以下命令提交更改：

`$ cvs commit -m "fix print module diagnostic" print.c`

`Checking in print.c`

`/usr/local/cvsroot/project/src/print.c,v <-- print.c`

`new revision: 1.8; previous revision: 1.7`

`done`

## 清理

在对源文件进行必要的修改后，假设你决定删除你的工作副本。一种方法是直接删除文件，如下：

`% rm -r src`

然而，首选方法是使用 `release` 命令。它告诉其他开发者该模块不再使用。考虑这个示例：

`% cvs release -d print`

`M print.c`

`You have [1] altered files in this repository.`

`Are you sure you want to release (and delete) module "print.c": n`

`** "release" aborted by user choice.`

在本示例中，CVS 注意到 `print.c` 的本地副本与存储中的版本不同。因此，自上次提交该文件以来已进行了修改。在移除你的工作副本之前，检查文件是否需要提交是一个良好的习惯。

## 关键字

`cvs status` 和 `cvs log` 命令提供了关于本地副本状态的有用信息。管理文件的另一种有用技术是被称为*关键字替换*的机制。其操作非常简单：每当执行 `cvs commit` 操作时，源文件中的某些关键字就会被替换为值。这些关键字实际上来自于底层的 RCS 命令。以下是可用关键字列表及其描述：

- `$Author$`：提交该版本的用户登录名。
- `$Date$`：提交该版本的日期。
- `$Header$`：包含 RCS 文件完整路径、日期和作者的标准头信息。
- `$Id$`：与 `$Header$` 相同，但 RCS文件名不包含完整路径。
