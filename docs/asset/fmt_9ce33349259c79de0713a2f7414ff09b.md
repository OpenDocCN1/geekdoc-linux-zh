
有时在讨论 `BIOS` 引导程序时，你会听到提到超级块（`superblock`）。超级块并不是引导程序的概念；而是文件系统的一部分。超级块描述文件系统的基本特征，例如文件系统的大小状态。在基于 `BIOS` 的计算机上，超级块可以包含引导程序的一部分，因此它的损坏会导致引导问题。如第 3 章所述，`debugfs` 和 `dump2efs` 命令提供一些基本的超级块信息。

## EFI 引导程序原理

刚刚描述的 `BIOS` 引导过程设计于 1980 年代，当时计算机固件中用于 `BIOS` 的空间按今天的标准来说非常小。因此，引导过程必须非常简单，大量的复杂性被推到了硬盘软件中。

较新的 `EFI` 固件比旧的 `BIOS` 复杂得多，因此其引导过程可以更加精密。`EFI` 不依赖存储在硬盘引导扇区的代码，而是依赖于存储在名为 `EFI` 系统分区（`ESP`）的磁盘分区中的引导程序，该分区使用文件表（`FAT`）文件系统。在 `Linux` 下，`ESP` 通常被挂载在 `/boot/efi`。引导程序位于具有 `.efi` 扩展的文件中，存储在 `ESP` 下以以 `OS` 或引导程序命名的子目录中。你可能有一个名为 `/boot/efi/EFI/ubuntu/grub.efi` 或 `/boot/efi/EFI/suse/elilo.efi` 的引导程序。

这种配置允许为你安装在计算机上的每个操作系统都拥有一个独立的引导程序。`EFI` 固件包含了自己的程序——引导管理器，以帮助你选择启动哪个引导程序。结果引导路径如图 5.2 所示。在该图中，有两个引导程序（`loader1.efi` 和 `loader2.efi`）可用，每个程序启动其各自分区上的 `OS` 内核。

考试目标交替使用引导程序（`boot loader`）和启动管理器（`boot manager`）这两个术语，但本书并非如此。引导程序负责将内核加载到内存中并将控制权交交给它，而启动管理器则显示一个启动选项菜单。许多程序（包括流行的 `GRUB`）结合了这两种功能，这正是许多资源缺乏清晰度的原因所在。

为了正常工作，`EFI` 必须了解硬盘 `ESP`（引导系统分区）上安装的引导程序。固件既可以使用固件自带用户界面的实用程序，也可以使用如 `Linux` 的 `efibootmgr` 程序之类的工具。或者，如果没有其他注册的引导程序，大多数 `x86-64` `EFI` 实现会将 `ESP` 上的引导程序 `/EFI/BOOT/bootx64.efi` 作为默认。这是大多数可移动磁盘的方式；你使用此名称在可移动磁盘的 `ESP` 上存储你的引导程序。

`Linux` 最流行的 `EFI` 引导程序基于 `BIOS` 引导程序，因此它们提供了通用 `EFI` 加载程序通常不需要的功能，例如它们自己的启动管理器功能，提供了链式加载另一个 `EFI` 引导程序的能力。因此，多操作系统计算机上的启动过程可能会运行单个 `EFI` 引导程序，由它链式加载其他 `EFI` 加载程序。事实上，这有时是实际需要，因为许多 `EFI` 实现提供的原始启动管理器在选择操作系统必须由单独的引导程序完成。

# 使用 GRUB Legacy 作为引导程序

`GRUB` 是大多数 `Linux` 发行版的默认引导程序；然而，`GRUB` 实际上是两个引导程序：`GRUB Legacy` 和 `GRUB 2`。尽管这两个引导程序在许多方面非常相似，但在许多重要细节上有所不同。`GRUB Legacy` 正如你预期的那样，是这两个引导程序中较旧的。它曾是 `Linux` 的主引导程序，但已被 `GRUB 2` 取代。尽管如此，由于这两个引导程序如此相似，我们先描述并更详细地介绍 `GRUB`。接下来的“使用 `GRUB 2` 作为引导程序”部分将重点介绍它与 `GRUB Legacy` 的区别。在接下来的页面中，我们现在描述如何配置、安装和与 `GRUB Legacy` 交互。

# 配置 GRUB Legacy

在基于 `BIOS` 的计算机上，`GRUB Legacy` 配置文件的通常位置是 `/boot/grub/menu.lst`。某些发行版（如 `Fedora`、`Red Hat` 和 `Gentoo`）使用文件名 `/boot/grub/grub.conf` 而不是 `menu.lst`。`GRUB` 配置文件分为全局部分和每个镜像部分，每个部分都有自己的选项。不过在进入部分细节之前，你应该了解 `GRUB` 的一些特殊特性。

`GRUB Legacy` 正式支持 `BIOS` 但不支持 `EFI`。由 `Fedora` 维护的深度补丁版本提供了对 `EFI` 的支持。如果你正在使用此版本的 `GRUB`，它的配置文件位于 `ESP` 上的与 `GRUB Legacy` 二进制文件相同的目录中，对于标准的 `Fedora` 或 `Red Hat` 安装，路径为 `/boot/EFI/redhat`。

# GRUB 命名法与特性

列表 5.1 显示了一个 `GRUB` 配置文件的示例。该文件为几个操作系统提供了定义——`/dev/sda5` 上的 `Fedora`、`/dev/sda6` 上的 `Debian` 以及 `/dev/sda2` 上的 `Windows`。`Fedora` 和 `Debian` 共享一个 `/boot` 分区（`/dev/sda1`），`GRUB` 配置位于其中。

```
Listing 5.1: 示例 GRUB 配置文件

# /boot/grub/menu.lst
#
# 全局选项:

default=0
timeout=15
splashimage=/grub/bootimage.xpm.gz
#
# 内核镜像选项:

title Fedora (3.4.1)
root (hd0,0)
  kernel /mlinuz-3.4.1 ro=/dev/sda5 mem=4096M
  initrd /initrd-3.4.1
title Debian (3.4.2-experimental)
root (hd0,0)
  kernel (hd0,0)/bzImage-3.4.2-experimental ro=/dev/sda6
#
# 其他操作系统
#
title Windows
rootnoverify (hd0,1)
chainloader +1
```

`GRUB` 不像 `Linux` 那样通过设备文件名来引用磁盘驱动器。

`GRUB` 对驱动器进行编号，因此不是使用 `/dev/hda` 或 `/dev/sda`，而是使用 `(hd0)`。

同样，`/dev/hdb` 或 `/dev/sdb` 可能是 `(hd1)`。`GRUB` 不区分 `PATA`、`SATA`、`SCSI` 和 `USB` 驱动器，在仅限 `SCSI` 的系统中，第一个 `SCSI` 驱动器是 `(hd0)`。在混合系统中，`ATA` 驱动器通常获得较小的数字，尽管并不总是如此。`GRUB Legacy` 的驱动器映射可以在 `/boot/grub/device.map` 文件找到。

此外，`GRUB Legacy` 在磁盘上的编号从 0 开始，而不是 `Linux` 使用的 1。`GRUB Legacy` 用逗号将分区号与驱动器号分开，例如 `(hd9,0)` 表示第一个磁盘上的分区（通常是 `Linux` 的 `/dev/hda1` 或 `/dev/sda1`），`(hd0,4)` 表示第一个磁盘上的第一个逻辑分区（通常是 `Linux` 的 `/dev/hda5` 或 `/dev/sda5`）。`GRUB Legacy` 将 `USB` 闪存盘视为普通硬盘，尽管它依赖固件来访问这些设备，因此如果你使用的是不支持此选项的老电脑，`GRUB` 将无法从 `USB` 闪存盘启动。

`GRUB Legacy` 定义了自己的根分区，它可能与 `GRUB` 的根分区不同。`GRUB` 的根分区是存放 `GRUB` 配置文件（`menu.lst` 或 `grub.conf`）的分区。由于此文件通常位于 `Linux` 的 `/boot/grub/` 目录下，如果你不使用单独 `/boot` 或引导分区，`GRUB` 的根分区将与 `Linux` 的根分区相同。如果你将 `/boot` 拆分为单独分区（这是很常见的），`GRUB` 的分区将与 `Linux` 的 `/boot` 分区相同。在引用 `GRUB` 配置目录中的文件时，必须记住这种差异。

# 核心 GRUB Legacy 选项

`GRUB` 的全局部分位于每个镜像的配置之前。通常，你会在这个全局部分只找到几个选项：

### 默认操作系统

`default=` 选项告诉 `GRUB` 启动哪个操作系统。列表 5.1 中的 `default=0` 启动第一个列出的操作系统（记住，`GRUB` 从 0 开始索引）。如果你想启动列出的第二个操作系统，则设置 `default=1`，以此类推，直到你所有的操作系统。

### 超时

`timeout=` 选项定义了在启动默认操作系统之前等待用户输入的时间长度（秒）。

### 背景图形

`splashimage=` 指向作为启动过程背景的图形文件。此行是可选的，但大多数 `Linux` 发行版指向一个镜像来美化启动菜单。文件名相对于 `GRUB` 根分区，或者如果 `/boot` 在单独分区上，则省略该部分路径。或者，路径可以以 `GRUB` 设备规范开头，例如 `(hd0,5)`，以引用该分区上的文件。

# 核心 GRUB Legacy 镜像选项

`GRUB` 的每个镜像选项通常在第一行之后缩进，但这是一种惯例，而不是文件格式的要求。选项从一个标识开始，随后是告诉 `GRUB` 如何处理该镜像的选项：

### 标题

`title` 行开始一个镜像语句，并指定在加载程序运行时显示的标签。`GRUB Legacy` 的 `title` 选项可以接受空格，并且惯例上适中，如 5.1 所示。

### GRUB 根

`root` 选项指定 `GRUB Legacy` 根分区的位置。如果存在单独分区，则为 `/boot` 分区；否则，它是 `Linux` 根。`Linux` 根可能位于 `FAT` 分区、`USB` 闪存盘或其他操作系统的分区上，因此 `GRUB` 的根理论上可能在某些奇异的地方。

### 内核规范

`kernel` 设置描述了 `Linux` 内核的位置以及传递给它的任何内核选项。路径相对于 `GRUB` 的根分区。作为替代方案，你可以使用 `GRUB` 的语法指定设备，例如 `kernel (hd0,5)/mlinuz root=/dev/sda5`。注意，大多数内核选项都在此行中传递。某些其他加载程序会将内核选项拆分成单独行，但在 `GRUB` 中，你将这些选项整合到内核行中。`ro` 选项告诉内核以只读方式挂载

其根文件系统是只读的（稍后会重新挂载为读/写），且 `root` 选项指定 `Linux` 根文件系统。由于这些选项被传递给内核，因此在需要时它们使用 `Linux` 风格的设备标识符，这与 `GRUB` 配置文件的其他选项不同。

### 初始内存磁盘 (Initial RAM Disk)

使用 `initrd` 选项指定一个初始内存磁盘，它包含一组最小的驱动程序、实用程序和配置文件，内核在完全访问硬盘之前使用这些文件来挂载其根文件系统。大多数 `Linux` 发行版严重依赖初始内存磁盘，用以保持主内核文件较小，并在启动过程中在从硬盘加载工具之前，为内核提供必要的工具。

### 非 Linux 根 (Non-Linux Root)

`rootnoverify` 选项与 `root` 选项相似，不同之处对于 `GRUB Legacy` 无法直接加载内核的操作系统（如 `Windows`），它将访问该分区上的文件。

### 链加载 (Chainloading)

`chainloader` 选项告诉 `GRUB Legacy` 将控制权交给另一个引导加载程序。通常，它会传递一个 `+1` 选项来加载目标操作系统根分区的第一个扇区（通常用 `rootnoverify` 指定），并将执行权交给此次级引导加载程序。

上述链加载方法适用于 `BIOS` 模式的计算机。如果你使用的是支持 `EFI` 的 `GRUB Legacy` 版本，可以进行链加载，但你必须告诉 `GRUB Legacy` 使用 `ESP`（通常通过指定 `root (hd0,0)`，尽管设备标识符可能不同），然后通过 `chainloader` 选项传递 `EFI` 引导加载文件的文件名，例如 `chainloader /EFI/Microsoft/boot/bootmgfw.efi`。

要向 `GRUB` 添加内核，请遵循以下步骤：

1. 以前 `root` 身份，将 `/boot/grub/menu.lst` 或 `/boot/grub/grub.conf` 文件载入文本编辑器中。
2. 复制一个可运行的 `Linux` 内核配置。
3. 修改标题行（`title` line），为你的新配置指定一个唯一的名称。
4. 修改内核行（`kernel` line）以指向新内核。如果你需要更改任何内核选项，请直接进行修改。
5. 如果你正在添加、删除或更改 `initramfs` 内存磁盘，请对 `initrd` 行进行相应的修改。
6. 如果需要，更改全局默认行（`default` line）以指向新内核。
7. 保存更改并退出文本编辑器。

此时，`GRUB` 已经配置好启动你的内核。当你重启系统时，你应该能看到它出现在菜单中，并能够成功启动它。如果遇到问题，请启动一个可运行的配置来调试问题。

> 在确定你的新内核工作正常之前，不要删除旧内核的有效配置。

# 安装 GRUB Legacy

在基于 `BIOS` 的计算机上，安装 `GRUB Legacy` 的命令是 `grub-install`。在安装引导加载程序时，你必须通过设备名称指定引导扇区。

运行的命令格式如下：

```
# grub-install /dev/sda
```

或者

```
# grub-install '(hd0)'
```

上述任一命令都会将 `GRUB Legacy` 安装到你第一块硬盘的第一个扇区（即 `MBR`）。在第二个示例中，你需要在设备名称周围加上单引号。如果你想将 `GRUB Legacy` 安装在分区的引导扇而非 `MBR`，请包含分区标识，例如 `/dev/sda1(hd0,0)`。

如果你正在安装 `Fedora` 支持 `EFI` 的 `GRUB Legacy` 版本，不应使用 `grub-install` 命令；而是将 `/boot/EFI/redhat/grub.efi` 文件复制到 `ESP` 上的合适子目录下（例如 `/boot/EFI/redhat`），如果使用的是 `Fedora` 的 `grub-efi` `RPM` 包，则复制 `/boot/EFI/redhat/grub.conf`。默认情况下，`grub.efi` 文件位于此位置。拷贝这些文件后，你需要使用 `efibootmgr` 将引导加载程序添加到 `EFI` 列表中：

```
# efibootmgr -c -l /EFI/redhat/grub.efi -L GRUB
```

此命令将存储在 `ESP` 的 `/EFI/redhat` 目录下的 `GRUB Legacy` 添加到 `EFI` 引导加载列表中。你必须使用双反斜杠（`\`）而不是 `Linux` 风格的正斜杠（`/`）作为目录分隔符。更多信息请参阅 `efibootmgr` 工具的 `man` 页面。

在更改配置文件后，你不需要重新安装 `GRUB`。（尽管某些较旧的引导加载程序需要这样做。）只有当你对磁盘配置进行某些更改时，才需要以此方式安装 `GRUB`，例如调整大小或移动 `GRUB` 根分区、将整个安装移动到新硬盘，或可能重新安装 `Windows`（这往往会擦除基于 `MBR` 的引导加载程序）。在某些情况下，你可能需要通过备份引导加载程序（例如安装在 `USB` 闪盘上的 `GRUB`）启动 `Linux`。

# 与 GRUB Legacy 交互

`GRUB Legacy` 引导加载程序显示的第一个界面是你在 `GRUB` 配置文件中通过 `title` 选项指定的所有操作系统列表。你可以等待超时以启动默认操作系统。若要选择备用系统，使用方向键高亮你想要启动的操作系统。一旦选中该选项，按下 `Enter` 键开始启动。

当你想要更改或向操作系统传递额外选项时，请遵循以下步骤：

1. 使用方向键高亮最符合你启动意图操作系统。
2. 按 `E` 键编辑此条目。你会看到一个列出该条目所有选项的新屏幕。
3. 使用方向键高亮内核选项行。
4. 按 `E` 键编辑内核选项。
5. 修改内核行以添加任何选项，例如添加 `1` 进入单用户模式。`GRUB Legacy` 会将额外选项传递给内核。
6. 按 `Enter` 键完成编辑。
7. 按 `B` 键开始启动。

你可以在第 5 步进行任何需要的更改，例如使用不同的初始化程序。通过在内核行末尾追加 `init=/bin/bash`（或你想使用的任何程序）来实现。

# 使用 GRUB 2 作为引导加载程序

从原理上说，配置 `GRUB 2` 与配置 `GRUB Legacy` 非常相似；然而，一些重要的细节不同。首先，`GRUB 2` 的配置文件是 `/boot/grub/grub.cfg`。（某些发行版将此文件放在 `/boot/grub2`，以便同时安装 `GRUB Legacy` 和 `GRUB 2`。）

`GRUB 2` 的进一步改进在于它利用了一系列脚本和其他工具来维护 `grub.cfg` 文件。其意图是让系统管理员永远不显式编辑该文件。如果你需要手动更改 `GRUB 2` 配置文件，请编辑 `/etc/default/grub` 文件或 `/etc/grub.d` 文件夹中的文件，然后使用 `update-grub` 或 `grub-mkconfig` 命令（取决于你的 `Linux` 发行版）将更改移动到 `/boot/grub/grub.cfg` 文件。

当你运行 `update-grub` 或 `grub-mkconfig` 命令时，它会将新的 `grub.cfg` 文件输出到标准输出。如果你想保存更改，可以输入 `update-grub` 或 `grub-mkconfig > /boot/grub/grub.cfg`。该命令会重新读取这些配置文件并写入一个全新的 `/boot/grub/grub.cfg` 文件。（某些安装在命令名称中 `grub` 后面带有 2，例如使用 `grub2-mkconfig` 而不是 `grub-mkconfig`。）
