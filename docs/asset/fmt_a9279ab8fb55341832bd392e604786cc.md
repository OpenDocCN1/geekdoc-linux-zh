
列出其他用户的目录，输入 `ls username`。在上述树结构中，用户之一是 tux。使用点 `.` 直接引用当前目录。树的上一层由两个点 `..` 表示。通过输入 `ls ..` 查看父目录的内容。`ls ../` 显示高两层目录的内容。

## 第二个示例：处理路径

另一个示例说明如何在 LINUX 系统中移动目录。使用命令 `cd` 进入你的主目录。然后通过 `mkdir test2` 在其中创建一个名为 test2 的目录。

使用 `cd test2` 进入新目录，并在其中创建一个名为 subdirectory 的子目录。要更改它，使用扩展功能：输入 cd 然后按 Tab。shell 将扩展剩下的目录名。

现在尝试将之前创建的文件 Testbackup 移动到当前目录（subdirectory）。为了实现这一点，指定文件的相对路径：`mv ../Testbackup`。命令末尾的点告诉 shell 当前目录是目标。在示例中，`..` 指向你的主目录。

## 25.1.5 通配符

shell 提供的另一个便利功能是通配符。Bash 中有四种不同类型的符号：

- `?` 匹配任意单个字符
- `*` 匹配任意数量的字符
- `[set]` 匹配括号内指定的字符之一，这里由字符串 set 表示
- `[^set]` 匹配不在 set 中的字符

假设 test 目录包含 Testfile1、Testfile2 和 datafile，命令 `ls Testfile*` 列出 Testfile1 和 Testfile2。使用 `ls Test*`，列表也将包含 Testfile。命令 `ls *file` 显示所有文件。最后，你可以使用匹配所有最后一个字符为数字的文件：`ls Testfile[1-9]`。

在四种通配符中，包含性最强的是星号。它可以用于一个目录中的所有文件复制到另一个，或删除所有文件。例如，命令 `rm *fil*` 将删除当前目录下所有包含字符串 fil 的文件。

## 25.1.6 More 或 Less

Linux 包含两个可以在 shell 中直接查看文本的小程序。与其启动编辑器读取 Readme.txt，只需运行 `less Readme.txt` 即可在控制窗口中显示文本。使用 Space 键向下翻页。使用 Page Up 和 Page Down 在文本中前后移动。按 \Q 退出。

less 程序的名称源于它也可以用于方便地查看命令输出的这一理念。要了解它是如何工作的，请阅读第 25.1.7 节。

除了 less，你还可以使用旧的程序 more。然而，它不够方便，因为它不允许向上滚动。

## 25.1.7 管道

通常，shell 中的标准输出是你的屏幕或控制窗口，标准输入是键盘。要将命令的输出传递给 less 等应用程序，请使用管道。

要查看 test 目录下的文件，输入命令 `ls test | less`。test 目录的内容将通过 less 显示。如果 ls 的正常输出过长，这样做才有意义。例如，如果你使用 /dev 查看 dev 目录的内容，窗口中只会看到一小部分。使用 /dev | less 查看完整列表。

也可以将命令的输出保存到文件中。例如，`ls test > Content` 生成一个名为 Content 的新文件，其中包含 test 中文件和目录的列表。使用 `less Content` 查看文件。

你可以将文件作为命令的输入。例如，使用 `sort < Testfile` 对 Testfile 中的行进行排序。sort 命令的输出发送到屏幕。文本按每行的首字母进行排序。

如果你需要一个包含排序列表的新文件，将 sort 命令的输出管道到文件。要测试这一点，在编辑器中创建一个未排序的列表并将其保存在 test 目录。然后进入 test 并输入命令 `sort < unsortedlist > sortedlist`。最后，使用 less 查看排序列表。

与标准输出一样，标准错误输出也会发送到控制台。然而，要把标准错误输出重定向到名为 errors 的文件，在相应的命令后附加 `2> errors`。如果附加 `>& alloutput`，则标准输出和标准错误都保存到一个名为 alloutput 的文件中。最后，要将命令的输出追加到已存在的文件，命令后面必须是 `>>` 而单个 `>`。

## 25.1.8 归档与数据压缩

现在你已经创建了许多文件和目录，请考虑存档和数据压缩主题。假设你想将整个 test 目录打包在一个文件中，保存在软磁盘上作为备份或通过电子邮件发送。执行此操作，请使用 tar 命令（用于归档器）。通过 `tar --help` 查看 tar 命令的所有选项。这里解释了其中最重要的选项：

- -c (create) 创建新归档
- -t (table) 显示归档内容
- -x (extract) 解包归档
- -v (verbose) 在创建归档时在屏幕上显示所有文件
- -f (file) 选择归档文件名。创建归档时，此选项必须作为最后一个

要将 test 目录及其所有文件子目录打包成名为 testarchive.tar 的归档，使用选项 -c 和 -f。为了示例的测试目的，添加 -v 以跟踪进度，尽管此选项并非强制性的。在使用 cd 进入 test 所在的主目录后，输入 `tar -cvf testarchive.tar`。之后，使用 `tar -tf testarchive.tar` 查看归档内容。test 目录及其所有文件在硬盘上保持不变。要解包归档，输入 `tar -xvf testarchive.tar`，但先不要尝试。

对于文件压缩，Linux 上明显的选择是流行的 gzip 程序。只需输入 `gzip testarchive.tar`。使用 ls，现在发现文件 testarchive.tar 不存在了，取而代之的是创建了 testarchive.tar.gz。这个文件小得多，因此更适合通过电子邮件传输或存储在软磁盘上。

现在，在之前创建的 test2 目录中解压此文件。要这样做，输入 `cp testarchive.tar.gz test2` 将文件复制到该目录。使用 `cd test2` 进入该目录。扩展名为 .tar.gz 的压缩包可以使用 `gunzip` 命令解压。输入 `gunzip testarchive.tar.gz`，这将生成 `testarchive.tar` 文件，然后需要使用 `tar -xv testarchive.tar` 对其进行提取。你也可以通过添加 `-z` 选项来一步完成压缩包的解压提取。完整的命令是 `tar xzvf testarchive.tar.gz`。通过 `ls`，你可以看到了一个新的 test目录，其内容与你主目录下的 test目录相同。

## 25.1.9 mtools

mtools 是一组用于处理 MS-DOS 文件系统的命令。mtools 中包含的命令允许你像在 MS-DOS 下一样将第一个软驱动器指定为 `a:`，这些命令与 MS-DOS 类似，但它们带有 `m:` 前缀：

- mdir a: 显示驱动器 a 中软盘的内容
- mcopy Testfile a: 将文件 Testfile 复制到软盘
- model Testfile: 删除 a: 中的 Testfile
- format a: 以 MS-DOS 格式格式化软盘（使用 `fdformat` 命令）
- cd a: 将 a: 设置为当前目录
- mmd a:test: 在软盘上创建子目录 test
- mrd a:test: 从软盘上删除子目录 test

## 25.2 用户与访问权限

自 20 世纪 90 年代初创立以来，Linux 被开发为一个多用户系统。任意数量的用户可以同时在上面工作。这导致它与微软终端用户 Windows 操作系统有一些显著的区别。

最重要的区别特征是，用户在工作站启动会话之前，必须登录系统。每个用户都有一个用户名和一个相应的密码。这种用户的区分保证了未经授权的用户无法查看他们没有权限的文件。对系统的更重大更改（如安装新程序）对于普通用户来说是不可能的或受到限制的。唯一的*root* 用户（或*超级用户*）具有对系统进行更改不受限制的能力，并且对所有文件具有无限的访问权限。明智使用这一概念的人（仅在必要时才以全 root 权限登录）可以减少数据意外丢失的风险。因为在正常情况下，只有 root 可以删除系统文件或格式化硬盘，因此来自木马效应或无意输入破坏性命令的威胁可以显著减少。

### 25.2.1 文件系统权限

基本上，Linux 文件系统中的每个文件都属于一个用户和一个组。这两个私有组以及所有其他组，都可以被授权写入、读取或执行这些文件。
