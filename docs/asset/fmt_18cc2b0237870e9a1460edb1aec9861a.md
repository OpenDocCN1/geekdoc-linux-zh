## 命令行（命令行提示符、CLI、命令行界面）

两种熟悉的界面之一。大多数人熟悉使用鼠标的图形界面 (`GUI`)，而命令行提供了计算机内部工作的接口。关键点：黑客的所有工作都是使用命令行。几乎所有的黑客工具都是面向命令的。来自 Hacking–Lexicon `http.org/LDP/Linux-Dictionary/html/index`

## 命令

你向计算机输入的内容告诉它做什么。现代计算机已经用精美的显示取代了命令输入，但从根本上说，发生的一切都是命令在秘密运行。只有在计算机接触后，你才能真正了解它。使用命令涉及输入单词、按回车并等待屏幕反馈。大多数命令是为了对文件执行某些有用操作。来自 Route–Users–Guide `http.org/LDP/Linux-Dictionary/html/index`

### Compiled Language

编译语言是一种需要编译器将编程源码转换为可执行的机器语言二进制文件的语言。编译一次后，程序就可以从其二进制形式继续运行，而无需再次编译。编译语言/程序通常比解释型或 p-code 更快，需要编译器（可能昂贵），且编程频率高于解释型和 p-code 语言。编译语言示例有 C 和 C++、COBOL 和 FORTRAN。源自 I–gloss

`http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

### Compiler

一种读取用人类可读的编程语言（如 Pascal 或 Modula–2）编写的语句，并将其翻译成机器可执行程序的程序。编译后的程序运行速度并不比解释型的显著快，因为程序直接与微处理器交互，且不需要与解释器共享内存空间。QUECID

`http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

### compiler

在编程中，编译器获取人类可读的源码并将其转换为计算机理解的二进制文件。关键点：编译器是有损压缩和单向加密的。代码中所有对人类有意义的内容都会被移除，只留下执行所需的信息。这意味着人类不再能轻松地读取生成的程序。由于操作的“单向性”本质，程序无法恢复现有的源代码。这在不同语言中有所不同。C++ 在反编译方面是最糟糕的语言；而大多数 Java 应用可以反编译为其之前形式的某种类似于。这导致了一个市场，专门通过进一步混淆 Java 二进制文件来隐藏原始源代码。某些编译器为了调试目的会保留人类可读的符号。它们无法显示原始源码，但对逆向工程仍然有用。这些符号可以从二进制文件中“剥离”。源自 Hacking-Lexicon

`http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

### compilercache

一个加速编译的缓存包装器。`Compilercache` 是你 C 和 C++ 编译器的包装器。每次你编译时，包装器会将编译结果放入缓存中。一旦你再次执行相同的操作，结果将从缓存中提取而不是重新编译。确保了有和无 `compilercache` 的编译结果产生相同的对象文件。源自 Debian 3.0r0 APT

`http://www.tld.org/LDP/Linux-Dictionary/html/index.html`
