
有些人批评 Linux，说它迫使用户在能够高效工作之前，必须对其用户界面投入大量的学习精力。他们认为，在 Linux 中，太容易自毁灭路了。这可能是真的。但正如 Linux 维护者 Jon "maddog" Hall 所断言的，与其让自己射中脚，远比永远不跑要好。

## 使操作系统内核保持小而轻量化

这是 Unix 纯主义者之间的一个热门话题，也是多年来许多辩论的主题。Unix 内核由那些程序组成，其他程序负责管理其内存子系统并与接口交互。在 X 窗口系统开发的早期，出现过关于是否将 X 服务器嵌入内核以获得更高性能的激烈争议。`X` 服务器运行在用户空间，捕捉鼠标和键盘输入并在屏幕上渲染图形对象。支持内核的派认为，减少内核与用户空间之间的上下文切换可以提高性能，因为现代 Unix 系统拥有充足的内存。

相反，用户空间派认为，将 X 服务器留在内核中将不再具有可移植性。任何修改 X 服务器的人将需要成为内核专家，而不仅仅是图形开发者。因此，X 服务器将遭受损失。内核派认为，内核的增长并无关系，因为 Unix 系统已经有了大量的内存。

这两个派是如何解决分歧的？系统本身为他们解决了。在一次看似成功的将 X 服务器植入内核后，测试人员发现 bug 不仅会导致窗口系统崩溃，还会导致整个操作系统崩溃。系统崩溃被认为比 X 崩溃更不可接受，如今大多数 X 服务器实现完全位于用户空间。这要归功于用户空间派。

通过避免将所有内容放入内核的诱惑，更容易保持内核小而轻量。小而轻量的内核通过减少启动任务时复制或修改的数据结构，防止在用户空间激活任务。这最终使得小型程序的集合能够高效运行。小型程序的快速启动对于 Unix 性能至关重要。

## 使用小写并保持简短

人们对 Unix 系统的第一印象点是，一切都是用小写写的。Unix 用户不需要一直开启大写键，而是使用小写字母操作。

这有几个原因。首先，小写字母对眼睛更友好。如果一个人必须长时间处理文本，很快就会发现查看小写文本比查看大写文本要舒服得多。其次，也许更重要的一点是，小写字母使用了升部和下降部。延伸到文本基线以上或以下的细线，如字母“c”、“g”和“p”中的那些线。这些线条传递了你在阅读时眼睛所捕捉的解释性线索。它们让阅读变得更容易。

大小写在 Unix 中也非常重要。例如，`MYFILE.TXT` 和 `File.txt` 并不代表同一个文件。Unix 对常用的命令和文件名使用小写字母。大写通常用于吸引人们的注意力。例如，在目录中将文件命名为 `README`，可以让用户在继续之前阅读文件内容。此外，目录中的文件名通常按字母排序。

`ls` 命令在文件列表中将大写名称排在小写名称之前。这增加了人们对该文件的额外关注。

大小敏感性通常会让那些长期使用不区分大小的操作系统后才接触 Unix 的人感到非常沮丧，但他们最终会适应它。许多人甚至学会了喜欢它。

Unix 的另一个特点是文件名通常非常短。最常用的命令名称通常不超过两个或三个字母。在这里，简洁就是黄金，你会发现诸如 `ls`、`mv`、`cp` 等这样晦涩的名称。非常长的多单词命令名称通常只被缩写为每个单词的首字母。例如，“parabolic anaerobic statistical table analyzer”被简单地缩减为 `pasta`。

使用简短名称是历史遗留。Unix 最初开发在带有电字机接口的 CRT 终端的系统上。在电字机上打字时，每按一个键都会伴随着“bzzzt-clunk”的声音，打字快的人每分钟大约能打十五到二十个单词。因此，物品的简短名称非常流行。

为什么现在的 Linux 用户仍然坚持使用简短名称？显然现在的 PC 键盘可以处理快多的速度，所以简洁不再是必要的。记住，Linux Shell 拥有一种管道机制，允许你在命令行上将一个命令的输出连接到另一个命令中。

这个强大的功能在 Linux 用户中非常受欢迎。他们经常在一行中组合许多命令，如果使用较长的名称，它们将超过他们使用的窗口宽度。解决这个问题的一种方法是保持单个命令的长度，这样当你在屏幕上打开多个窗口时，更多的命令可以适应较小的窗口。

当然，你可能在想：“为什么两个都要用？”为什么不直接用鼠标点击执行命令呢？如果你反复使用某个命令，这种方法确实可行。但请记住，Unix 和 Linux 的许多力量源于动态组合多个命令以形成新命令的能力。这在今天大多数流行的桌面环境中是不可能实现的。`WYSIWYG` 这个术语也是 `WYSIATI`。你所点击的你所得到的，仅此而已。提供图形化 shell 的尝试充其量产生了笨拙的、僵化的 Unix 新界面。

而使用“快捷键”通常只能确保访问单个命令所需的时间缩短。

## 节省树木

`Unix guru` 这个词之所以出现，可能是因为 Unix 是一个如此不平凡的操作系统。成为 Unix 专家的人往往被既敬畏又怀疑地看待：敬畏是因为他们掌握了这个迷人计算机环境的奥秘；怀疑是因为你纳闷，这个人是否可能不太正常，竟然把这么多时间都花在一个操作系统上。

我遇到的第一位 Unix 大师是我职业生涯早期，在纽罕布什尔州南部的一家小型高科技公司的老板。除了防止我们许多人在公司工作时间玩 `Rogue` 之外，他还负责我们 Unix 系统的日常管理。我们的系统运行在 Digital `PDP-11/70` 上，在他到来之前，这台 `PDP-11/70` 还运行着 Unix 之外的操作系统。

那时，很多编程是用汇编语言完成的。我们部门的工程师花费数小时编写和测试代码，这些代码会被交叉编译运行在目标架构的机器上。这种“位操作”需要纸质列表。大量的列表。为了调试程序，一个人会生成一份汇编列表并发送到我们最快的线式打印机上，在那里会变成一叠有时超过六英寸厚的折叠纸。程序员越资深，列表越厚。如果想在我们的工作坊里赢得尊重，只需生成列表即可。显然，任何能生成那些纸的人绝对是勤奋的工作者，在薪资审查时值得丰厚的报酬。管理层相信这一点，工程师们也知道如何应对。

有一天，我正走在走廊里，搬着一五英寸厚的木质副产品在干活，这时一位 Unix 大师停住我，问我拿着这么多纸干什么。“这是我的程序，”我回答道。我几乎把列表甩在他脸上，仿佛在说：“是的，我在努力工作。是的！”

Linux 提供的各种桌面环境允许你从单个快捷键执行多个命令。然而，这是一种静态能力，并不能轻松实现。

## 沉默是黄金

在 Unix 世界中，“言出必行”至关重要——不多，也不少。

一位 Unix 系统管理员指出，系统日志对他来说是真正的救命稻草。他说，如果没有这些额外的输出，他将无法解决他见过的某些配置问题。在出于调试目的而需要额外输出的情况下，可以很容易地仅将错误信息重定向到日志文件中以便日后查阅。

## 并行思考

计算机世界有一个流传已久的旧笑话，大概是这样的：如果一个女人需要九个月才能生一个婴儿，那是否意味着九个女性可以在一个月内生一个婴儿？这里显而见的暗示是，某些任务在本质上必须串行执行。任何试图让该过程并行运行的尝试都不会让结果更快。
