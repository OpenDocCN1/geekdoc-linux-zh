## 如何将多个备份存放在一条 8mm 磁带上？

你可以通过两种方法实现。这两种方法都使用设备`/dev/rmt0.1`，因为它是非回出的。

在第一种解决方案中，你可以使用`rdump`或通过`/dev/rmt0.1`进行备份。以下是一个示例：

```shell
# rsh remote1 -l root /etc/rdump host:/dev/rmt0.1 -Level -u /u
# rsh remote2 -l root /etc/rdump host:/dev/rmt0.1 -Level -u /u
# tctl -f /dev/rmt0.1 rewind   # 这将使磁带回绕
```

这些命令是从主机执行的。为了恢复第一个备份的内容列表，我将使用：

```shell
# restore -f /dev/rmt0.1 -sl -tv
```

在这个示例中，`-sl`标志告诉`restore`跳到磁带上的第一条记录。如果你再次输入相同的命令来获取第二条记录，`-sN`（其中`N`是整数）将告诉它从此处位置移动`N`条记录。

第二种解决方案使用了由 Clarkson 大学的 Steve Knodle 创建的脚本。`Dump.sh`文件的内容如下：

```shell
CONTENTSFILE='date |dd conv=lcase |sed -e 's/19//' |awk '{print $6 $2 $3}''
set -x
LEVEL=$1
shift
backup -c -b 56 -$LEVEL -uf /dev/rmt0.1 /
backup -c -b 56 -$LEVEL -uf /dev/rmt0.1 /usr
backup -c -b 56 -$LEVEL -uf /dev/rmt0.1 /u
tctl -f /dev/rmt0 rewind
touch /usr/local/dumps/Contents.$CONTENTSFILE
echo "Dumping /" >>/usr/local/dumps/Contents.$CONTENTSFILE
restore -t -s 1 -f /dev/rmt0.1 >>/usr/local/dumps/Contents.$CONTENTSFILE
echo "Dumping /usr" >>/usr/local/dumps/Contents.$CONTENTSFILE
restore -t -q -s 1 -f /dev/rmt0.1 >>/usr/local/dumps/Contents.$CONTENTSFILE
echo "Dumping /u" >>/usr/local/dumps/Contents.$CONTENTSFILE
restore -t -q -s 1 -f /dev/rmt0.1 >>/usr/local/dumps/Contents.$CONTENTSFILE
tctl -f /dev/rmt0 rewind
```

## `ps` 报告的内存字段说明

`G SIZE`——这会告诉你进程的文本段和数据段分配了多少 KB 为单位的分页空间。如果可执行文件位于本地文件系统中，文本的页空间使用量为 0。如果可执行文件位于 NFS 文件系统中，页空间使用量将大于 0。这个数字可能大于或小于 RSS，取决于进程有多少部分被分页入内存。RSS 可能更大，因为 RSS 包含文本，而 SIZE 不包含。

`G TSIZ`——这基本上是一个无用的字段，没有任何作用。

这里的字段仅报告进程的文本段和数据段。目前还无法报告的段大小包括：

- 共享库的文本部分（第 13 段）。
- 已打开或正在使用的文件。打开的文件以单独段的形式缓存在内存中，这与传统的内核缓存缓冲区方案不同。
- 使用`shmat`创建的共享数据段。

在 3.1 中，进程 0 的 `%MEM` 和 RSS 报告是虚假值。RSS 值异常地大，因为内核段 0 被计算了两次。

总而言之，`ps`并不擅长测量系统内存使用情况。它对内存去向提供了一些指示，但关于总使用量的许多问题仍未解决。

## 什么是 `kproc`？

`kproc`（始终为 PID 514）仅仅是内核的空闲进程。

## AIX 中的 Shell、命令和 InfoExplorer

本节将涵盖一些关于 AIX 中 Shell、命令和 InfoExplorer 程序的常见问题。

### 在 Shell 提示符中提供更多信息的最佳方法是什么？

三个主要的 Shell 有不同的实现方法。

在 Korn shell 中，有一个可以设置的变量。这是 PS1 变量，可以如下所示手动设置：

```shell
$ export myhost='hostname'
$ PS1='$LOGNAME@$myhost $PWD \\$'
```

这将为你提供一个包含登录名、机器主机名和当前目录的提示符，后面跟着`$`符号。

请注意，这仅持续到你当前注销。一旦注销你就会丢失它。在 Korn shell 中，你可以在`$HOME/.profile`文件中永久设置此变量。

在 C shell 中，你可以执行以下操作来设置提示符：

```shell
% set myhost='hostname'
% alias cd \`chdir \!\* >/dev/null; set prompt="$LOGNAME@$myhost $cwd % "
% cd
```

在 Bourne shell 中，没有 PS1 或 set prompt，因此从任何意义上说，都没有简单的方法可以实现。在大多数情况下，强烈建议使用 Korn shell 而非 Bourne shell，因为大部分只是对 Bourne shell 的增强。

### 我如何设置我的 Korn Shell 使用 `Emacs` 进行命令模式编辑而不是 `vi` 编辑器？

有一种未记录的方法。可以通过向你的`.kshrc`文件中添加以下行来绑定关键键映射：

```shell
alias __A='echo "\020"'   # 上方向键 = ^p = 后退一个命令
alias __B='echo "\016"'   # 下方向键 = ^n = 向前一个命令
alias __C='echo "\006"'   # 右方向键 = ^f = 向前一个字符
alias __D='echo "\002"'   # 左方向键 = ^b = 后退一个字符
alias __H='echo "\001"'   # Home键 = ^a = 行首
```

输入`set -o emacs`或将此行放入`.profile`中以永久设置。

如果你使用的是 3.2.5 之前的版本，你必须拥有 IBM 的补丁才能使其工作。PTF 为 U406855，该问题的 APAR（授权程序分析报告）编号为 IX25982。

### 当我用 `ls` 列出目录文件时得到了核心转储（Core Dump）。为什么？

这是一个出现在某些机器上的问题，当一个目录被超过 200 个用户共享时。通常只有在使用`-l`和`-o`选项显示用户名和组名时发生。

这个问题应该通过 PTF 带 U407548 修复。还有另一个带有 APAR IX31403 修复的带，你可能也想加载它。这将修复与大量账户相关的查找问题以及性能问题。

### 我可以将自己的文本放入 InfoExplorer 吗？

在 3.2 及之后的版本，有一个名为 InfoCrafter 的产品可以让你这样做。

### 哪些键可以在 InfoExplorer 中移动？

启动时，有一个你可以选择的选项称为`Basic Screen Operations`（基本屏幕操作）。这将显示几个选项。还有一个页面叫做`Using Keys and Key Sequences in the InfoExplorer ASCII Interface`。它将描述键序列及其关联的操作。这里是一些常用的键：

- Ctrl-W——这将在你阅读屏幕和导航屏幕之间切换。
- Ctrl-O——这将使菜单栏处于激活或非激活状态。如果你的文本光标位于文本区域，只需按 Ctrl-O 即可激活菜单栏。如果菜单栏已激活，Ctrl-O 将其变为非激活并将文本光标移动到文本区域。
- Tab——这将你移动到菜单栏中的下一个菜单选项。

### 有没有方法向系统添加 `man` 页面？

你可以将新的`man`页面放入`/usr/man`（例如，`/usr/man/man1/tcsh.1`）。在 AIX 3.1.10 及以上版本中，你可以使用`/usr/lib/makewhatis`更新`makewhatis-database /usr/man/whatis`，以便`apropos`和`whatis`感知到添加的`man`页面。

### 为什么 `man` 在我的机器上不起作用，为什么我没有 `nroff`？

在 3.2.5 之前的基础安装中，`nroff`或`troff`均未包含。即使在 3.2.5 中，它们也被提供，但可能没有安装在你的机器上。要安装这些，请使用 SMIT 从 3.2.5 媒体安装软件包`txtfmt.fs.obj`。

### 为什么我有多个 Shell，环境只加载了一次？

`.profile`文件仅由你的登录 shell 加载一次。之后的所有 Shell 将由`$HOME/.kshrc`初始化。`.profile`中的设置为`ENV=$HOME/.kshrc`。

### 为什么我找不到 `nawk`？

`nawk`只是`awk`的增强版本。AIX 的`awk`整合了如`atan2()`、`rand()`、`match()`、`gsub()`、`close()`等功能。支持`nawk`系统的最快速有效的方法是将`nawk`链接到`/bin/awk`。如果无法访问 AIX，请链接到`/bin/awk`。

### AIX 提供什么来跟踪我的系统数据包？

可以使用两个工具：`iptrace`和`ipreport`。使用`iptrace`你可以执行以下操作：

```shell
iptrace -i en0 /tmp/ipt
```

其中`en0`是以太网标识，`ipt`是存放统计信息的文件名。该命令将运行并写入`ipt`文件，直到你找到其 PID 并将其杀死，所以不要只运行它就不管了。一旦完成跟踪并杀死了`iptrace`进程，你可以用`ipreport`查看输出：

```shell
ipreport -r /tmp/ipt > /tmp/ipr
```

其中`ipr`是你可以查看的 ascii 文件。

在`/etc/inittab`中，你需要添加（或修改）以下行：

```shell
automount:2:once:/usr/etc/automount -T -T -T -v >/tmp/au.se 2>&1
```

### 我可以将 tty 端口设置为既可拨入又拨出吗？

可以。你只需要将`tty`的模式设置为`shared`或`delayed`即可。最好的方法是在 SMIT 中进行。

### 在网络上移动或复制完整目录并保持权限的最佳方法是？

你可以通过`rcp`或`tar`来这样做。

使用`rcp`，你可以复制整个目录树，同时保持所有修改时间和权限。其命令格式为：

```shell
rcp -rp /(directory) (hostname):/(directory)
```

其中`-r`允许复制子目录，`-p`选项将保持所有权限、用户 ID 和组 ID。`rcp`可能会阻塞网络，另一种对网络负担较小的方法是`tar`。你可以结合`rsh`使用`tar`：

```shell
rsh (remote hostname) "cd (target directory); tar -cB - ." | tar -xvB -
```

发生的是`rsh`用于在远程系统启动`tar`，将 tar 镜像写入`stdout`，通过管道返回给本地系统。在本地系统中，`tar`则被用于读取`stdin`并解压其文件内容到原始位置。这种“移动”是通过通过网络写入/读取 tar 镜像实现的。

这两种方法都需要你在远程系统上拥有相同用户名的账户，或者有`.rhosts`文件包含你的机器主机名和用户名。这在安全环境中可能会引起严重的安全问题，如果你选择这种方法，请考虑这很危险且困难。

### 我可以向没有主机名的系统发送邮件吗？

## 不同 AIX 版本的接口

AIX 的 SLIP 实现与其他版本略有不同。`ifconfig`命令用于启动串口接口，`slattach`命令用于将接口连接到用于连接的串口。调用`slattach`命令时也可以使用 UUCP 语法。

以下描述了两台机器之间的连接：

`local.j.k.l` IP 地址 129.11.1
`remote.a.b.c` IP 地址 129.22.1

以下是必须解决的相关问题：

### 1. 接口配置

每台机器必须有一个专门用于 SLIP 接口的 IP 地址。在`remote.j.k.l`上，使用以下命令启动 SLIP 接口：

```shell
ifconfig sl0 129.11.22.1 129.128.127.1 up
```

在`local.a.b.c`上：

```shell
ifconfig sl0 129.128.127.1 129.11.22.1 up
```

在 AIX 3.2.3+ 中，使用与 tty 端口相同的 SLIP 接口很重要（即，如果你使用`tty12`，请使用`ifconfig sl12`而不是`sl0`）。此时接口准备好连接。

### 2. tty 配置

两台机器上的`tty`端口均使用 SMIT 以相同的方式配置。

| 条目字段 | 值 |
| :--- | :--- |
| TTY 类型 | tty |
| TTY 接口 | rs232 |
| 描述 | 异步终端 |
| 父适配器 | sa0 |
| 端口号 | [] |
| 波特率 | [38400] |
| 奇校验 | [none] |
| 每个字符字节数 | [8] |
| 停止位数量 | [1] |
| 终端类型 | [dumb] |
| 启动时配置的状态 | [available] |
| DMA | on |
| 读取触发器 | 0,1,2,3 |
| 发送缓冲区计数 | [16] |
| 要运行的初始程序名称 | [/etc/getty] |

**注意：** 以下属性仅当指定`/etc/getty`为初始运行程序时才有效。

- 启用程序？respawn
- 运行级别 2
- 启用登录 禁用
- 进入下一个端口设置前的时间：[0]
- 运行时的 STTY 属性：[hupcl,cread,brkint,icr>
- 登录时的 STTY 属性：[hupcl,cread,echoe,cs8,
- 运行 shell 活动管理器：no
- 可选 LOGGER 名称：[]

在较旧版本的 AIX 上，我们遇到了禁用`getty`的某些问题，转而直接修改`/etc/inittab`文件。例如，将`tty0:2:respawn:/etc/getty /dev/tty0`更改为`tty0:2:off:/etc/getty /dev/tty0`。

这将禁用`getty`。在创建 SLIP tty 设备后，你需要更改其硬件配置以禁用 Xon/Xoff 流控。SLIP 不应使用软件流控。输入`smit chtty`，然后选择硬件设置。

### 3. 调制解调器配置

调制解调器的配置如下：启用 RTS/CTS 流控。禁用 Xon/Xoff 流控。固定速率。如果调制解调器支持，请使用压缩。自动应答——如果从任何一台机器发起 SLIP 连接，则两个调制解调器都应设置为自动应答。

### 4. UUCP 配置文件

`Devices`文件必须包含一个接口和串口速度的条目。在我们的示例中：

```shell
Direct tty0 38400 slipdialer
```

关键字`slipdialer`仅仅是`Dialers`文件中的索引。对于我们的目的，`Dialers`文件中的`slipdialer`条目简单为：

```shell
slipdialer
```

该条目也可以包含 UUCP 聊天命令，或者可以将聊天命令包含在`slattach`命令中。

### 5. slattach 调用

`slattach`将 tty 端口上的设备连接到由`ifconfig`创建的 SLIP 接口，并在需要时向 tty 设备发送任何命令。对于我们的示例，`remote.j.k.l`永远不会发起调用，只响应拨入电话。因此，我们执行：

```shell
slattach tty0 38400 '"" ATZ OK ""'
```

这一个以 38400 波特率连接`tty`。我们也可以简单地运行

```shell
slattach tty0
```

而无需任何调制解调器命令，但这种情况下调制解调器到端口的速度可能无法正确设置。此外，`ATZ`命令可以确保调制解调器被设置为 NVRAM 设置。

在`local.a.b.c`上执行：

```shell
slattach tty0 38400 '"" ATZ OK \pATDT4925871 BIS ""' 4
```

这在 38400 波特率下建立了连接，并执行所示的拨号字符串。该拨号字符串是一个 UUCP chat 字符串，并以 `expect send expect ... send` 的格式配置。该字符串：

```shell
'"" ATZ OK \pATDT4925871 BIS ""'
```

被解释为：

- `expect ""`（来自调制解调器的空字符串）
- `send ATZ` 给调制解调器
- `expect OK` 来自调制解调器
- `send \pATDT4925871` 给调制解调器
- `expect BIS` 来自调制解调器

BIS 是 CONNECT STRING（连接字符串）的结束。你可以使用调制解调器连接后返回的字符串的任何部分作为期望字符串。直接期望`CONNECT`可能更明智，因为所有连接都应该返回此字符串。

空字符串是必要的，因为 UUCP 的第一个参数是来自调制解调器的期望字符串，在向调制解调器发送命令之前，它只能是空的。

`slattach`命令的最后一个参数 (4) 是调试级别。

调试级别 4 会显示 UUCP chat 字符串，这有助于检查调制解调器的状态。

### 6. 路由

如果你只想在两个主机之间进行通信，`ifconfig`就足够了。如果你运行 SLIP 是为了与除另一个之外的其他主机通信，你就必须发布你的地址。

```shell
arp -s 802.5 iago 10:00:5a:b1:49:d8 pub
```

其中`802.5`是令牌环网络，硬件地址可以通过`netstat -v`获取，`iago`是 SLIP 客户端（我家里的 PC），`pub`是重要部分，意味着“已发布”。

你可能想在启动时运行此命令。

通过 SLIP 链路路由与任何网关的路由类似。

调用`ifconfig`命令会自动在两个 SLIP 机器之间建立路由。应该在`/etc/hosts`或命名数据库中创建一个条目，用于 SLIP 地址的机器名称与每个机器上的以太网地址相同。例如，在`remote.a.b.c`的`/etc/hosts`（以及`remote.a.b.c`上的任何其他以太网机器）：

```shell
129.11.22.44 remote.a.b.c   # 以太网地址
129.11.22.1 remote.a.b.c    # slip 地址
```

最好将以太网地址放在 hosts 文件中 slip 地址之前，这样`remote.a.b.c`就会解析为以太网地址。使用命名（named）时，在反向文件中具有相同两个地址是重要的。我们在通过 slip 链路挂载 NFS 时遇到过困难，这是由于 NFS 的锁定机制，当一个或多个`sendmail`守护进程或邮件读取器尝试同时访问用户的邮件文件时，你会遇到问题。

另一种可能更有意义的方法。在每个用户的`$HOME`目录下，放置一个名为`.forward`的文件，其中包含一行：

```shell
NNN@(hostname.domain.name)
```

其中 NNN 是用户节点。当邮件进入所有机器时，它会被转发到该服务器，而该服务器将忽略这一行。

## AIX 链接器的行为有不同吗？

事实上，它的工作方式非常不同。对象和库的顺序通常并不重要。链接器会将所有对象（包括来自库的对象）读到内存中，并一次性完成实际的链接。即使在其他系统上你可能需要在`ld`命令行中多次放置自己的库，在 RS6000 上是不需要的——这样做甚至会减慢你的链接速度。

链接器的功能之一是它可以用同一种对象的新版本替换可执行文件中的对象：

```shell
$ cc -o prog prog1.o prog2.o prog3.o   # 生成 prog
$ cc -c prog2.c                        # 编译 prog2.c
$ cc -o prog.new prog2.o               # 通过替换 prog2.o 生成 prog.new
```

- 标准库`/lib/libc.a`是共享的，这意味着实际代码没有被链接到你的程序中，而是在你的程序加载时加载一次并进行动态链接。
- `ld`程序实际上调用了`/usr/lib`中的绑定器（binder），你可以给`ld`传递特殊选项以获取有关绑定器调用的详细信息。这些信息可以在`ld`帮助页面或 Info 帮助文档中找到。
- 如果你的程序通常使用多个库（`.a`文件）进行链接，你可以将这些库中的每一个预链接到一个对象中，这将使你的链接更快。例如，执行以下操作：

```shell
$ cc -c prog1.c prog2.c prog3.c
$ ar libprog.a prog1.o prog2.o prog3.o
$ ld -r -o libprog.o libprog.a
$ cc -o someprog someprog.c libprog.o
```

这将解决`prog1.o`、`prog2.o`和`prog3.o`之间所有的内部引用并将其保存在`libprog.o`中。使用`libprog.o`链接你的程序而不是`libprog.a`将提高链接速度，即使`someprog.c`只使用了`prog1.o`和`prog2.o`，你的最终程序中也只有两个模块。这也是因为如前所述，绑定器可以处理一个对象内部的单个对象。

如果你在上面使用了`-l`选项（针对`libprog.a`）并且仍然想这样做，你应该用标准库名称为预链接对象命名，例如`libprogP.a`（`P`标识预链接对象），这可以通过`-lprog`指定。你不能对此类对象使用归档器（`ar`）。

你还应该查看此文章的第 3.01 节，特别是如果你有混合了 Fortran/C 程序。Dave Denner（`dad@adonis.05.bull.com`）声称，他在 AIX 上预链接的经验并没有节省多少时间，因为大多数人拥有独立的库，它们之间没有许多依赖关系，因此没有许多需要解析的符号。

## 我可以使用非共享库 `/lib/libc.a` 链接我的程序吗？

例如，如果你有三个对象，可以通过以下命令实现：

```shell
cc -o prog -bnso -bI:/lib/syscalls.exp obj1.o obj2.o obj3.o
```

在 3.2.5 中，你可以安装共享内存传输（Shared Memory Transport）。一旦安装，你必须使用`-bI:/usr/lpp/X11/bin/smt.exp`进行链接。此外，此可执行文件只会在安装了 SMT 的机器上运行。

## 为什么链接器会报奇怪的错误？

链接器或绑定器无法获得足够的内存。这可能是因为`ulimits`太小，或者你没有足够的分页空间（paging space）。AIX 链接器使用的虚拟内存比大多数普通链接器多得多。具体来说，如果发生 BUMP 错误，要么是`ulimits`太低，要么分页空间不足。如果出现`Binder killed by signal 9`错误，这绝对指向分页问题。

要检查你的内存和数据 ulimits，请在`ksh`中运行`ulimit -a`。要增加 ulimits，运行`ulimit -m NNNNN`和`ulimit -d NNNNN`，其中`NNNNN`是你设置的数字。如果这不能解决问题，那么你的分页空间太小了。

如果你受限于目前拥有的分页空间，可以尝试以下方法：

- 确保你没有在`ld`命令行上重复库。
- 尝试一次只链接一个库。
- 你可以进行部分链接（partwise linking），即使用`-r`选项链接某些对象或库，允许临时输出具有未解析的引用，然后与剩余的对象或库一起链接。你可以根据需要对此进行拆分，每一步使用的虚拟内存都会更少。这是大多数 UNIX 链接器使用的方案。

此外，如果你想在使用上述`-l`选项（针对`libprog.a`）的同时仍然能够这样做，你应该用标准库名称为预链接对象命名，例如`libprogP.a`（`P`标识预链接对象），这可以通过`-lprog`指定。你不能对此类对象使用归档器（`ar`）。

## BSD 的历史

大约在 30 年前，UNIX 操作系统在 AT&T 贝尔实验室通过 Ken Thompson、Dennis Ritchie 以及其他研究人员的努力诞生了。AT&T UNIX 第七版本的发行以低廉的价格提供给学术机构，导致了某些小组的形成。

其中一个小组就是加利福尼亚大学伯克利分校的计算机系统研究小组（CSRG），他们开发了自己的 UNIX 版本，称为伯克利软件发行版（BSD）。这个版本的 UNIX 引入了许多特性，最引人注目的是 TCP/IP 协议族，它已成为现代互联网的骨干。1992 年，AT&T 对伯克利小组提起诉讼，指控 BSD 违反了他们的 UNIX 商业秘密。该诉讼使 BSD 的开发陷入了超过一年的困境。在多次法律斗争后，在 AT&T 将公司出售给 Novell 之后，问题最终于 1994 年 2 月得到解决。根据解决的条款，UCB 被允许自由分发其最新的 BSD 版本，即 4.4BSD，这是所有现代发行版所基于的发布版本。

在 4.4BSD 发布后，CSRG 小组也解散了，两个小组接管了它，启动了 FreeBSD（**http://www.freebsd.org**）和 NetBSD（**http://www.netbsd.org**）项目。

目前，FreeBSD 和 NetBSD 小组都已成立多年，并远超了最初的起点。相比之下，386BSD 似乎已经完全死亡，并被其更活跃的兄弟版本所取代。第三种 BSD 变体——OpenBSD（**http://www.openbsd.org**）最近也从 NetBSD 项目中拆分出来，并作为一个完全独立的项目维护自己的源码库和目标集。鉴于 OpenBSD 仍与其较老的 NetBSD 兄弟之间保持着很大程度的共同性，关于 NetBSD 的章节大部分也适用于 OpenBSD。

这种有些奇特的安排是必要的，因为 FreeBSD 的商业用户比例高于其他免费变体，但它仍然需要在相同的志愿者开发者驱动模型下运行，在这一模型中，开发者的工作不应受到试图施压的商业用户的限制。这种三分支的方案为旧有、当前和未来的客户/开发者提供了一种获取其所需内容的方法，尽管代价是略高的开发开销。

## 通用问题

以下章节包含对常被问问题的解答。

### 我可以在哪里获取关于 BSD 的通用信息？

取决于你感兴趣的各种 *BSDs*，你可以访问相关的网页：

- FreeBSD 项目页面：**http://www.freebsd.org**
- NetBSD 项目页面：**http://www.netbsd.org**
- OpenBSD 项目页面：**http://www.openbsd.org**
- Berkeley Software Design, Inc. **http://www.bsdi.com**

在 FreeBSD 和 NetBSD 的情况下，通过向 **info@FreeBSD.ORG** 或 **info@NetBSD.ORG** 发送电子邮件，你可以联系到自动信息机器人。

每个小组都有一个中央 FTP 服务器站点，地址为 **ftp.FreeBSD.ORG**、**ftp.NetBSD.ORG**、**ftp.OpenBSD.ORG**、**ftp.BSDI.com** 等，你可以从那里下载更多信息以及（仅针对免费变体）最新的发布版本。

### 伯克利大学的 CSRG 项目还存在吗？

不，恐怕不再。它在 4.4 Lite 发布左右解散了。原始开发者后来仅聚了一次，在稍些时候完成了最后的 4.4 Lite2 发布。CSRG 及其 BSD 版本已经消失，维护操作系统技术的任务现在已交给了其他机构。

### 那么现在是谁在“运行”BSD 开发？

严格来说没有人“运行”BSD，尽管一些原始的 BSD 开发者后来去创立了 BSDI。成千上万的其他 BSD 用户和开发者继续支持一种免费的 *BSD 版本*，选择特定的变体很大程度上取决于用户的特定目标。

### 哪种 BSD 最适合我？

这个问题很难回答，仅因为每种版本都有自己的优缺点，而且用户需求也差异很大。然而，我可以相当肯定地说：

- 如果你需要在 x86（Intel PC）架构之外的设备上运行，请查看 NetBSD。它是 BSD 家族中最古老、最成熟的成员，可以在各种非 Intel 架构上运行。
- 如果你正在使用 x86 PC（或很快将使用 ALPHA），请查看 FreeBSD。开发者最大化地提高了 BSD 在 PC 上的性能和通用可用性，并在创建用于大型商业应用程序的高性能服务器方面拥有卓越记录。
- 如果你需要商业支持，或者由于某种原因对“免费”操作系统软件的想法反感，那么 BSDI 的产品确实是你唯一的实际选择。

### BSD 支持我的硬件吗？

请参阅本章的“BSD 支持的硬件类型”章节，获取 FreeBSD 和 NetBSD 支持硬件的完整描述（也很大程度适用于 OpenBSD 和 BSDI）。

### BSD 和 Linux 有什么区别？

简单来说，Linux 是一个从零开始的操作系统开发尝试，而 BSD 是一个现在近 20 年历史的项目延续。

你会发现重新开始这样的开发有很多好处，就像你会发现使用随时间经过测试和改进的软件有很多好处一样。哪个操作系统最适合你很大程度上取决于你的品味和需求。

我或许可以说，在用户群体方面，Linux 领先于 BSD，而且对奇特外设的支持也比平均 BSD 支持的更多。我也可以放心地说，在 TCP/IP 网络领域，BSD 是无与伦比的。TCP/IP 网络最初是在 BSD 环境下为 UNIX 开发的，这段历史体现在 BSD 网络代码的成熟和健壮中。

最后，BSD 和 Linux 之间最大的区别可能是意识形态而非其他任何东西。每个 Linux 发行版——以及 Linux 本身技术上只是内核——以不同的方式以及不同的打包和安装技术组合其工具，除了内核外，所有的开发很大程度上都是去中心化的。相反，BSD 小组是高度中心化的，并提供整个系统作为他们的产品，从`ls`命令到内核。鉴于他们控制着每一个工具，他们也可以使用源代码控制系统等来跟踪所有内容。这种做法在 Linux 世界中相当罕见，开发过程中刻意程度的无政府状态是其支持者通常认可的，用中心化控制换取更具“草根性”的开发方法。

### 我可以在商业产品中使用 BSD 技术吗？

是的，绝大多数 BSD 代码都受 BSD 版权保护，与 GNU 公用许可证（Linux 和其他 GNU 使用）不同，它允许以二进制和源码形式分发，而没有对过程进行不当的规定或限制。其他包含 BSD 源的代码（无论是全部还是部分）也不需要以源码形式分发，这是 GPL 有时令人不悦（且非常刻意）的结果。

### 我是一个互联网服务提供商；BSD 适合我吗？

绝对适合。通过各种 BSD 小组，你可以轻松创建 ISP 需要的任何东西，从服务器到路由器。FreeBSD 小组还提供了一个 Web 界面允许你查询和生成 PR。

访问以下站点可以找到 Windows 95 和 NT 连接：

- FreeBSD 项目页面
- NetBSD 项目页面
- OpenBSD 项目页面

### BSD 真的是免费的吗？

是的，除了 BSDI 的产品，你可以从许多公共网站免费下载，分发给你的朋友（或客户），甚至分发在商业产品中。有些人出售 BSD 的光盘版（约为 40 美元），但在这种情况下你支付的是方便媒介，而不是 BSD 本身。

### 我如何编译自己的内核？

首先，你显然需要内核源码，如果你的系统中没有名为`/usr/src/sys`的目录，那么你需要先加载它。你通常可以在给定 BSD 版本的较大源码分发包中找到内核源码。

BSD 系统还使用一个名为`config`的工具来生成内核构建区域；它接受内核配置文件名作为参数。在`config`在其上成功运行后，会创建一个名为`/sys/compile/*kernel*`的新目录。

创建你自己的配置文件的起点。

`config LINT`：此`config`文件包含了所有可能选项的列表，提供它更多是作为通用参考，而不是作为你可能想要使用的内核示例（而且你通常不会那样做——某些选项是相互冲突的）。

### 我如何编译我自己的完整系统？

由于 BSD 拥有完全集成的源码树，你可以直接进入`/usr/src`目录（假设你已经安装了源码）并输入`make`来构建整个系统。大多数 BSD 还有专门的构建目标，用于以最能确保构建成功的特殊顺序来编译工具（因为许多工具依赖于其他工具先构建）。其中一个目标被称为`world`，这意味着你可以通过输入`make world`来重新构建并安装操作系统中的所有内容，然后去吃顿饭（取决于你系统的速度，可能要吃几顿）。

### 我可以使用 BSD 实现 NAT 设备和/或 IP 防火墙吗？

当本地局域网（LAN）上有多台机器但对外部世界只有一个有效 IP 地址时，网络地址转换（NAT）非常有用。在这种情况下，你可以让具有有效 IP 地址的机器以某种方式为其他机器“伪装”，并路由它们的数据包。NAT 处理这项工作，FreeBSD 提供了名为`natd`的工具，它正好执行此任务。FreeBSD 还修改了`ppp`工具以支持`-alias`标志，如果你已经在使用`ppp`与你的 ISP 通信，它可以完成相同的工作（节省了运行`natd`的额外步骤）。更多信息，请参阅`natd`和`ppp`的 man 页。

IP 防火墙选择性地阻止来自或发往外部世界的包以防止未经授权的访问。FreeBSD 为这项工作提供了两个工具：`ipfw`和`ipfilter`（后者在其他 BSD 中也可用）。它们本质上做的是相同的事情，只是适用于不同人员偏好的不同实现。

更多信息，请参阅`ipfw`和`ipfilter`的 man 页。

## 安装 FreeBSD

安装是 BSD 世界中一个参差不齐的问题。鉴于 NetBSD 和 OpenBSD 支持超过 10 种架构，在任何机器上安装操作系统的工作在很大程度上取决于相关的硬件，而硬件在如此广泛的机器类型中显然存在巨大差异。

NetBSD 和 OpenBSD 的安装和维护工具更多地面向计算机科学家而非普通计算机用户这一事实，如果用户没有先前的 UNIX 经验将没有任何帮助，因此无论尝试描述安装工具都可能超出了本 FAQ 的范围。

相比之下，FreeBSD 项目很早意识到了这个问题，并选择不尝试支持这么多架构，而是转而追求小组认为“性价比”最高的单一平台——Intel x86 架构。拥有这个较小的领域使他们能够更多地关注先进的安装工具和用户支持，而不是跨平台移植问题，结果是其安装过程被广泛认为是所有 BSD 系统中最容易让新用户处理的。由于如此，我在这里介绍 FreeBSD 的安装。

## 创建 FreeBSD 安装启动软盘

安装 FreeBSD 的第一步是创建安装启动软盘，可以从 **ftp://ftp.freebsd.org/pub/FreeBSD/2.2.2-RELEASE/floppies/boot.flp** 获取（在本文编写时——当你读到这一章时可能存在更新的版本——请在 **ftp.freebsd.org** 附近查找）。它作为一个单个 1.44MB 的镜像提供，你必须将其“原始拷贝”到 3.5 英寸软磁盘上。如果你使用 MS-DOS，请下载`fdimage.exe`（从 **ftp://ftp.FreeBSD.ORG/pub/FreeBSD/tools/fdimage.exe** 获取）并如下运行：

```shell
C:\> fdimage boot.flp a:
```

该程序格式化 A 盘，并将`boot.flp`镜像拷贝到上面。

如果你使用 UNIX 系统，技术有些不同。在这种情况下，你输入

```shell
# dd if=boot.flp of=disk_device
```

其中`disk_device`是软盘驱动器的`/dev`设备。在 FreeBSD 系统上，你使用`/dev/fd0`作为 A 盘，使用`/dev/fd1`作为 B 盘。在其他系统上，你可能使用类似`/dev/floppy`的内容。

## FreeBSD 安装

创建安装磁盘后，将其放入 A 盘并重启电脑。经过一段时间的加载时间后，你应该得到一个这样的启动提示符：

```text
>> FreeBSD BOOT ...
Usage: [[[0:wd](0,a)]/kernel][-abcCdhrsv]]
Use 1:sd(0,a)kernel to boot sd0 if it is BIOS drive 1
Use ? for file list or press Enter for defaults

```

你可以直接在这里按回车，或者等待系统超时并开始启动软盘内核。然后你会进入一个屏幕，询问你是否配置内核以匹配你的硬件。这通常是一个好主意……

接下来的章节也仅关注 FreeBSD 和 NetBSD 的硬件要求，这两者是目前最受欢迎的 BSD 免费变体。（OpenBSD 的硬件要求也与 NetBSD 非常相似。）

在商业产品方面，你可以在 BSDI 主页上找到 BSDI 的 BSD/OS 产品支持的硬件列表（**http://www.bsdi.com**）。

## BSD 应用程序

如果你对操作系统做不了任何事情，那么它就毫无用处。幸运的是，BSD 能为你做的事情仅限于你的想象。有数万个应用程序和通用工具可用，而且每天都有新的出现。其中许多应用程序也是免费的，FreeBSD Ports Collection（**http://www.freebsd.org/ports**）是为了跟踪所有它们而设计的。目前，BSD 的商业软件列表很小但正在增长，例如来自 Xi Graphics（**http://www.xig.com**）的 CDE（通用桌面环境）以及来自 Progressive Networks 的 RealAudio（**http://www.realaudio.com**），为桌面用户提供了更多支持。

x86 平台的 BSD 也非常能够运行 Linux `a.out` 和 `ELF` 二进制文件，让你访问 Linux 市场中丰富的桌面应用程序，例如 StarOffice（**http://www.stardivision.de**）和 ApplixWare（**http://www.applix.com/appware/appware.htm**）。

无论如何，实际上比起桌面应用程序，它更适合互联网服务器市场。BSD 世界还提供许多商业互联网防火墙产品、高性能 Web 服务器（例如 **http://www.zeus.co.uk** 上的 Zeus）、数据库服务器以及用于创建功能完备、高成本效益的互联网和内网服务器系统的许多工具。ports 集合的精妙之处在于，它并不尝试保留那里成百上千应用程序的副本；它只是对它们进行“封装”，提供 FreeBSD 获取、解压、自定义（或打补丁）以及构建和安装软件所需的所有信息。你只需要输入`make install`，ports 集合就会完成其余所有工作。它包含不同的软件类别，包含了从 Web 服务器到冷门（以及不冷门）编程语言的一切。ports 中的一些应用程序包括：

- 音频工具：用于播放 MPEG、Amiga MOD 以及 Sun/Apple/Microsoft 格式音频的应用程序、格式转换、编写和播放 MIDI 轨道、双向会议、控制播放器等。
- 基准测试：用于基准测试和比较性能的工具。
- 通信：拨号器、终端模拟器、FAX 管理软件等。
- 数据库：广泛的选择，从 PostgreSQL 和 exodus 等大型完整数据库系统到 SQL 数据库库。这里还包含了对 Perl、C++ 以及几种不同流行语言和数据库类型的连接支持。
- 编辑器：文本和图形编辑器，从 Emacs 到 StarOffice。
- 图形：OpenGL 兼容库、图像转换工具、HP 扫描器驱动程序、动画工具、分形算法等，是 ports 集合中最多样化的类别之一。
- 语言：Ada、Basic、C++、Forth、Java 以及其他 50 多种计算机语言，其中大多数你可能从未听说过。
- 邮件和新闻：读取、发送或递送邮件和 USENET 新闻的一切。ISP 将发现这些部分特别有趣。
- 安全：用于审计、测试和实施几乎各种想象的安全机制的工具，从`tcp_wrappers`到`PGP`再到`ssh`以及更多。
- I18N：面向中国、日本、韩国、俄罗斯和越南市场的软件。
- WWW：从广受欢迎的 Apache Web 服务器到 Netscape 和 Mosaic Web 浏览器，这类 W3 工具规模很大。这里还有 Squid 和 Harvest 等搜索工具，以及许多用于编写 CGI 脚本、连接数据库等工具。
