# 加密

## 一般说明

### 为什么要加密数据？

加密是秘密性的同义词。在备份场景中，加密非常有用，例如，如果你需要将备份数据放在你无法控制访问的地方，例如你的提供商的服务器。

此外，加密也可以应用于电子邮件：通常情况下，邮件是不加密的，并且经常通过网络或互联网明文发送。如果你的信息包含敏感内容，最好对其进行加密。

## GNU 隐私卫士 (Privacy Guard)

在 Linux 系统上，你会找到 `GnuPG`，即 GNU Privacy Guard，这是一套与市售 `PGP`（Pretty Good Privacy）工具兼容的程序包。在本指南中，我们将讨论加密工具的简单用法，并展示生成加密密钥以及使用它为自己加密数据时需要什么，这些数据可以安全地存储在公共场所。更高级的用法可以在各种命令的帮助页中找到。

## 生成密钥

在开始加密数据之前，你需要创建一个密钥对。该密钥对由一个私钥和一个公钥组成。你可以将公钥发送给通信对方，他们可以使用它为你加密数据，而你用你的私钥对其进行解密。你始终保留私钥，绝不与他人共享，否则他们将能够解密本仅属于你的内容。只需确保不要发生意外，私钥已通过密码保护。密钥对是通过以下命令创建的：

```bash
willy@ubuntu:~$ gpg --key-gen
```

## 关于你的密钥

当密钥创建好后，你会收到一条关于指纹的消息。这是一个由 40 个十六进制组成的序列，它非常长，以至于在计算机上很难生成两次相同的密钥。你可以放心这是一个唯一的序列。该密钥的短格式由你的名字以及最后 8 个十六进制数字组成。

你可以通过以下方式获取关于密钥的信息：

```bash
willy@ubuntu:~ gpg --list-keys
/home/willy/.gnupg/pubring.gpg
---------------------------------------
pub      1024D/BF5C3DBB 2006-08-08
uid       Willy De Wandel (Willem) <wdw@mvg.vl>
sub      4096/A3449CF7 2006-08-08
```

此密钥的 ID 是 "`BF5C3DBB`"。你可以将密钥 ID 和姓名发送到密钥服务器，这样其他人就可以获取这些信息并用它加密数据。或者，你可以直接将公钥发送给需要它的人。你的公钥部分是在 `gpg` 命令中使用 `--export` 选项时看到的长串数字：

```bash
gpg --export -a
```

然而，就此而言，我们假设你只需要密钥为自己加密和解密数据。想了解更多请参阅 `gpg` 帮助页。

## 加密数据

现在你可以在将 `tar` 归档或压缩包保存到介质或传输到备份服务器之前对其进行加密。使用 `gpg` 命令：

```bash
gpg -e -r (part of) uid archive
```

`-e` 告诉 `gpg` 进行加密，`-r` 选项指定加密对象。请记住，只有拥有该 `-r` 选项的用户才能解密它。

## 解密文件

使用 `-d` 选项，你可以解密已经加密的文件。

## 网络概述

### OSI 模型

简单来说，协议就是一组通信规则。

例如，为了在网络上传输数据（比如从你的电脑发送电子邮件到世界上另一端的某台计算机），需要许多不同的硬件和软件协同工作。

所有这些硬件设备和不同的软件程序使用不同的语言。想象一下你的电子邮件程序：它能够通过特定的协议与计算机操作系统通信，但无法与计算机硬件通信。我们需要操作系统中有一个特殊程序来执行此功能。同样，计算机需要能够与电话线或互联网接入方法通信。而在后台，网络连接硬件需要能够通信，以便将你的电子邮件从一台设备传递到另一台，直到到达目标计算机。

所有这些类型的通信协议被分为 7 层，被称为开放系统互连参考模型，简称为 OSI 模型。为了方便理解，该模型被简化为 4 层协议描述，如下表所示：

表 10.1. 简化的 OSI 模型

| 层名称 | 层级协议 |
| --- | --- |
| 应用层 | HTTP, DNS, SMTP, POP, ... |
| 传输层 | TCP, UDP |
| 网络层 | IP, IPv6 |
| 网络接入层 | PPP, PPPoE, Ethernet |
