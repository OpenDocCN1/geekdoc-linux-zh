
另一个关于嵌入式系统任务随情况变化而增长的有趣例子是 NASA 的旅行者号 1 号和 2 号（参见 [www.jpl.nasa.gov/releases/97/vgrani97.html]）。旅行者 2 号是两艘航天器中率先发射的，于 1970 年 8 月 20 日开始旅程。旅行者 1 号在几周后的 9 月 5 日发射，运行在更快的轨道上。初，两艘航天器只被预期探测两个行星——木星和土星。那两次遭遇的惊人成功以及航天器的良好状况促使 NASA 将旅行者 2 号的任务扩展到天王星和海王星。随着航天器飞越太阳系，远程控制重新编程使得旅行者号拥有了比离开地球时更强大的能力。

> 对嵌入式计算机感兴趣的人可以在 NASA 网站上找到有趣的读物。请查阅 [www.hq.nasa.gov/office/pao/History/computers/contents.html] 上的标题为“无人航天器计算机”的章节。

## 硬件成本/软件复杂度比例

我们生活在一个时代，处理器、RAM 和闪存等嵌入式硬件组件的成本正在跌入谷底，然而运行在嵌入式系统中所需的软件复杂度却在爆炸式增长。这些趋势结合改变了嵌入式系统工程师的规则。工程师现在不再像过去那样仅仅担心将每一个可能的字节都挤进满载的内存空间，现在还必须担心寻找时间来实现市场所需的所有新功能。

在这样的市场中，像 Linux 这样的开源操作系统开始变得合理。基于 Linux 的解决方案比从专有软件供应商手工定制的解决方案更快推向市场，因为开发 Linux 的人比开发任何专有供应商技术的人多得多。人们认为这些开发者是业余黑客，他们并不真的懂编程，但事实完全非如此。Red Hat 和 VA Linux 等公司正花费大量资金聘请一些非常聪明的人才，以确保 Linux 操作系统尽可能完美。

## 软件成本

Linux 提供的显而易见（但不一定是最重要）的优势是不支付许可费、特许权或源代码许可费。事实上，你无需为使用 Linux 的特权支付任何费用。这可以积累成可观的节省。像 WindRiver 和 QNX 那样的商业嵌入式操作系统，仅开发可能花费数万美元，并且每销售每个产品都需要支付特许权费。

当然，在考虑这种“免费”操作系统时，必须考虑到你想要进行的任何更改的开发和维护成本——这很可能是长期的。

## 稳定性

每个人都听到很多轶闻证据证明 Linux 非常稳定，特别是与微软 Windows NT 相比。但有什么办法可以量化这一点吗？有人对比过 Windows 蓝屏频率与 Linux “Oops?” 的频率吗？Uptimes Project ([www.uptimes.net]) 的优秀人士们在回答这个问题上做得非常出色。他们的调查统计显示，Linux 仅次于 NetBSD 和 FreeBSD，是第二稳定的系统。截至 2000 年 3 月底，运行时间最长的 Windows NT 机器排名第 277 位。它已经运行了 76 天。如果你运行过 NT，你会同意这是一项惊不起的成就，但与顶级 Linux 机器的 575 天或 BSD 机器的 1,411 天相比，真的没有可比性。

## 上市时间

技术创新的速度一直在加速，甚至有人发明了“互联网时间”来描述这一现象。一方面，英特和摩托罗公司正在以飞快的速度创建新的芯片组。另一方面，数百家软件公司公司正在创建新的协议和相互连接的方式。这给 QNX 和 WindRiver 等嵌入式操作系统公司带来了巨大的压力。他们必须在这些技术出现时或不久后支持它们；然后必须长期支持这些技术。然而，嵌入式操作系统公司真正的问题是软件支持。他们不断追赶。许多软件技术都是使用 Linux 开发的，根据定义技术优先可用。

Linux 加快上市的一个原因是，你通常为开发主机使用目标主机相同的操作系统。

## 开源

除了成本，之前列出的所有原因都是技术问题。例如，Linux 非常稳定，但商业嵌入式操作系统选择也是如此。真正让 Linux 与众不同的领域它是开源的。这一事实在排除某些特定原因之前，应该让 Linux（或者可能是其他开源操作系统）成为首选；

### 什么是开源？

开源定义 1.7 版 ([www.opensource.com])

#### 自由再分发

许可不得限制一方作为包含来自不同来源程序的聚合软件发行包的一部分进行销售或赠送。许可不得对此类销售收取特许权或其他费用。

#### 源代码

程序必须包含源代码，并允许以源代码形式和编译形式分发。如果产品的某些形式没有随带源代码，必须有一种良好的途径可以获取源代码，且成本高于合理的复制成本——最好，通过互联网免费下载。源代码必须是修改程序的首选形式。不允许故意混淆代码。作为预处理器或翻译器的输出中间形式是不允许的。

#### 衍生作品

许可必须允许修改和衍生作品，并允许按照原始软件许可的相同条款进行分发。

### 作者源代码的完整性

许可证可能限制仅以修改后的形式分发源代码，前提是该许可证允许随源代码分发“补丁文件”，以便在构建时对程序进行修改。该许可证必须明确允许分发由修改后的源代码构建的软件。许可证可能要求衍生作品使用与原始软件不同的名称或版本号。

### 不对个人或团体产生歧视

许可证不得对任何个人或个人团体产生歧视。

### 不对从事领域产生歧视

许可证不得限制任何人在特定的从事领域内使用该程序。例如，它可能无法限制该程序在业务中使用，也不可能限制其用于基因研究。

### 许可证的分发

附带于程序的权利必须适用于所有重新分发该程序的人，且无需这些相关方执行额外的许可。

### 许可证不能针对特定产品

附带于程序的权利不取决于该程序是否是特定软件发行包的一部分。如果程序从该发行包中提取出来并在程序许可的条款内使用或分发，则所有分发该程序的各方都应拥有与原始软件发行包所授予相同的权利。

### 许可证不能污染其他软件

许可证不得对与许可软件一起分发的其他软件实施限制。例如，许可证不能坚持在同一介质上分发的所有其他程序必须是开源软件。

## 开源的优势

- 当你有源代码时，你可以发现任何 bug。

对于开发者来说，没有什么比在调试代码时碰壁更令人沮丧的，更糟糕的是尝试调试客户的问题时碰壁。碰壁意味着你必须一直追踪你的代码到某段你没有源代码且无法追踪的代码，结果软件在代码中运行失败。有时，问题确实出在你没有源代码的代码中，但很多时候问题出在你自己的代码中——而不是使用你没有源代码的代码上。这没关系——没有源代码，你可能盯着你的代码看几个小时甚至几天，也永远找不到问题。如果你有正在调用的函数的源代码，你可能很快就能看出问题所在并在几分钟内解决它。或者，你所调用的代码中确实有一个 bug——你可以修复它，或者让维护者修复它，然后继续你的工作。

许多开发者已经接受了无法看到他们使用的某些软件源代码的实；他们认为这些墙只是他们所选职业中的生活事实。事实并非如此。足够聪明能够深入挖掘到代码下一层（必要时一直到内核）的开源开发者根本不会碰壁，并且可以调试任何软件问题。事实上，任何无法通过调试解决的问题几乎可以确定是硬件问题。

- 你可以让其他人（专家）为你修复代码。

在1999年，我参与了一个软件应用程序项目，该项目的用户对该应用有丰富经验，但对 Linux并不了解。我们必须创建一个完整的包，包括一个自定义安装程序，重点强调我们现有客户群已经拥有的硬件套件。

测试周期进行几周后，一个客户发现主板存在问题。我们不仅能够将问题一直调试到驱动程序级别，而且向驱动程序的维护者提出了一个修复方案。他发现，虽然这个特定的修复适用于我们的独特情况，但更好的修复方案是处理一整类问题。他实施了该方案，并将新驱动程序的源代码给了我。如果我们当时不是在开发一个开源操作系统，我们就无法自己发现问题并进行修复。由于该问题发生在一个大型闭源操作系统的某个通用硬件的驱动程序上，我们将很难获得所需的关注，而问题可能仍然存在。

- 你可以查到事物应该是如何运作的。

拥有 Linux 中所有驱动程序的源代码让编写者的工作变得容易得多。如果代码编写者需要某个特定功能，他或她只需查看其他驱动程序是如何实现该功能的。事实上，编写驱动程序的第一步通常是找到一个与你需要的程序类似的驱动程序，复制它，然后根据你的情况修改新代码。

- 有良好的文档。

某些开源软件包的文档并不良好。相反，Linux 的文档非常详尽。Linux 文档项目（Linux Documentation Project）提供了许多免费文档，几十本书可供购买。当然，关于一个软件包如何运作的最终权威——源代码本身——对于任何开源软件产品都是可用的。
