## 其他考虑的选项

`proc_watch_timed.ksh` 脚本非常详尽，但可能需要根据特定需求进行定制。这里列出了一些额外的考虑。

## 常见用途

这些脚本适用于以下场景：监控进程运行了多久、在进程启动时记录日志、重启提前终止的进程，以及按用户或创建者监控问题。我们还可以监控特定 tty 活动并在进程启动时发送电子邮件。发挥你的想象力。

我们可以在命令行中启动监控脚本，或者作为 cron 任务在白天运行它。一个 cron 表目可能如下：

```
* 0 * * 1-5 /usr/local/bin/proc_watch_timed.ksh -h9 -p fred >/dev/null
```

此 cron 表目将从周一到周五上午 7 点开始监控进程表中包含 "`fred`" 的进程，持续九小时。注意：由于脚本在白天倒计时到零，这九小时可能会更长。

系统进程列表中的任何内容都可以从秒到天进行监控。

## 需要考虑的修改

这些脚本是通用的，你可能想要进行修改。可以考虑的一个选项是列出进程列表中的行，而不仅仅是 PID 和进程以及时间戳。你可能有更喜欢的不同 `ps` 命令——例如 `ps aux`。为了更准确的计时，你可能希望以更长的间隔检查日期/时间（而不是计数）；检查时间也会减少 CPU 负载。另一个好主意是检查计时数据并在指定时间运行命令杀死脚本。此外，还考虑使用 Korn 内置变量 `SECONDS`。首先将其初始化为 0，只要父进程在执行，它就会自动递增。特别是预处理、启动和后处理脚本。目前 `startup_event_script` 只在 (1) 监控开始且目标进程正在运行以及 (2) 在每个进程启动时的最开始进程启动时执行。你可能想要修改该函数的执行，使其仅在每个单独进程启动时运行，而不是在监控开始且目标进程已运行时执行。此外，取决于在这些事件中要执行的内容，可能需要休眠时间让一切稳定下来。正如我们所看到的，有许多方法可以实现所有这些，每个人都有不同的期望和需求。只需记住，我们永远没有最终的脚本；我们只是在保持灵活！

## 总结

在本章中，我们从监控进程启动或停止的基本想法开始。我们很快扩展了用户选项，在指定时间范围内监控进程状态并添加了时间戳。我们还允许用户指定执行预处理、启动和后处理事件作为选项。永远不要尝试一次完成所有工作。构建一个执行你目标基本步骤的短 shell 脚本，并对基础的良好功能进行扩展。

## 监控进程与应用程序

任何业务中最关键的部分都是确保应用程序能够无错误地运行。在本章中，我们将介绍监控应用程序以及应用程序所依赖的关键进程的几种技术。编写这一章的困难之处在于，企业世界中的应用程序非常多，因此监控它们的技术也大不相同。

从最低层次开始，我们可以 `ping` 机器来查看其是否在线。然而，`ping` 并不是操作系统的响应，而是机器的响应，用于确认网络适配器已配置。在更高层次层级上，我们查看应用程序正常运行所需的进程，但这并不能 100% 地完全确认应用程序正在正常工作。确保应用程序正常运行的唯一方法是与应用程序进行交互。例如，如果我们有一个运行正常的数据库，可以执行一个简单的 SQL 查询来确保数据库工作正常。对于交互式应用程序，我们可以尝试使用脚本登录应用程序，甚至可能执行一个微小的任务。由于应用程序的工作方式不同，因此确保应用程序启动并正常运行的解决方案也会大多样。

在本章中，我们将介绍本地进程、使用安全外壳 `SSH` 进行远程监控、检查活跃的 Oracle 数据库，以及检查应用程序 URL 和 HTTP 服务器状态。

## 监控本地进程

使该技术生效的关键是找到一个代表目标进程的唯一字符串。PID 并不理想，因为进程可能有一个子进程或父进程，它们在 `ps -ef` 输出的某处具有相同的 PID。找到一个与 `grep` 命令匹配的唯一字符串是关键。通过在命令行使用以下命令可以轻松测试这一点。

```
ps -ef | grep Appserver | grep -v grep
```

此命令语句假设我们正在寻找一个名为 `Appserver` 的进程。注意，我们总是将输出通过 `|` 传递给最后一个 `| grep -v grep`。需要最后一个 `grep` 是为了让系统不要报告 `grep Appserver` 进程。在进程表中，命令语句中的每个管道部分都有独立的 PID。

如果该命令在 shell 脚本中执行，还有其他需要考虑的情况。取决于 shell 脚本的写法，脚本名称可能会出现在 `grep` 输出中。为了解决这个小问题，我们需要查询系统以获取脚本文件名，并使用以下方法向 `ps -ef` 命令语句中添加另一个 `grep`：

```
SCRIPT_NAME=$(basename $0)

ps -ef | grep target_process | grep -v grep $SCRIPT_NAME
```

现在我们有了一个可以运行的命令，但前提是找到一个唯一的字符字符串，将目标进程与其他所有进程隔离开。对于我们要监控的每个应用程序，这通常需要尝试几次。
