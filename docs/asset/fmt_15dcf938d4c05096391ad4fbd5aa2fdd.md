## `top` 显示说明

在 `top` 显示的开头有五行特殊信息：

- 第一行显示 `uptime` 命令的输出。此行指示系统已运行的时间（自上次重新启动以来）、登录的用户数以及系统负载。
- 第二行显示进程总数以及处于睡眠、运行、僵尸状态和停止状态的进程数。
- 第三行显示用户模式、系统模式、负优先级任务和空闲状态下所占CPU时间的百分比。
- 第四行显示内存使用信息，包括总可用内存、已用内存、空闲内存、共享内存量以及分配给缓冲区的内存量。
- 第五行显示交换空间信息，包括总交换空间、已使用的交换空间量以及仍可使用的交换空间量。

### 守护进程的作用

如本章前面所述，守护进程是一种特殊类型的进程。与几乎总是与控制终端关联的普通进程不同，守护进程没有控制终端。查看本章前面 `ps` 输出中 `inetd` 或 `init` 等守护进程的 `TTY` 列，你会发现它们没有关联的 tty 终端。

在 UNIX 中，守护进程是一组执行特定系统任务的专业程序。下表列出了常见的 Linux 守护进程。

**表 8.3 常见的 Linux 守护进程**

| 守护进程 | 描述 |
|---|---|
| `init` | 这是系统中所有进程的始祖。如果 `init` 被终止或因任何原因停止运行，系统将重新启动。 |
| `kupdate` | 这是内核更新进程。它每30秒执行一次 `sync` 系统调用，并将所有超级块的最新版本写入磁盘。保持磁盘上的超级块最新非常重要，因为这会降低系统崩溃时文件系统受损的风险。 |
| `kswapd` | 该进程负责将页面从主内存交换到磁盘，并在需要时将其重新加载回内存。 |
| `inetd` | 这是 Internet 超级守护进程。它通过读取其配置文件 `/etc/inetd.conf` 启动。该文件告诉 `inetd` 应监听哪些端口。它监视这些端口以接收传入的网络连接请求。当请求到达时，它会生成一个适当的守护进程实例来处理该请求。关于此守护进程的更详细讨论见第18章“一般安全问题”。 |
| `crond` | 这是 cron 守护进程。它定期唤醒并运行 `/var/spool/cron/crontab` 目录中列出的作业。关于此守护进程的详细讨论见第7章“调度任务”。 |
| `named` | 这是 Internet 名称服务器守护进程。它映射主机名和IP地址。关于此守护进程的完整讨论见第22章“DNS”。 |
