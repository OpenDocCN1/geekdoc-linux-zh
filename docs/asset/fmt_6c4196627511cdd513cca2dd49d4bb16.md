## `XmDrawnButton`

`DrawnButton` 为程序员提供了一个带有边框的矩形区域。程序员可以对该窗口内的文本或图形进行尺寸调整、重绘或重新定位。该小部件提供了钩子（hooks），用于设置其边框的外观参数，并可以挂载函数以接受用户输入。

## `XmLabel`

这是一个由文本或图形组成的矩形框。它被实例化，同时也作为所有按钮小部件的基类。标签的文本可以是多行、多字体、甚至是多方向的。在 `xmdialogs` 示例中，这将是 Active Dialog 标签和 Motif Dialog 小部件标签。

标签的许多功能可以修改，例如字体、前景颜色、背景颜色以及对齐方式（左对齐、居中或右对齐）。事实上，它甚至可以存储一个 pixmap 图形图像。

## `XmPushButton`

这是一个带有边框的文本标签或 pixmap 图像。该小部件接受击键或鼠标按钮点击。在 `xmdialogs` 示例中，这些是创建（create）、销（destroy）、管理（manage）和取消管理（unmanage）按钮。当按钮获得焦点时，它会有一个粗边框。

当按钮获得焦点时，按下回车键或指针按钮。将光标移动到按钮上。按下并按住键或按钮。你已经激活了该按钮。按钮上的颜色会改变，边框颜色也会反转。这给人一种按钮被向内按下的印象。当你释放按钮时，按钮将恢复到原始状态。

在此小部件上按下鼠标按钮时，小部件的前景和背景颜色通常会反转。这模拟了按下按钮的过程。

## `XmSeparator`

这用于在屏幕的功能区域之间创建一条线。除了将其放置在屏幕上，用户实际上对这个小部件无法做什么。

## `XmText`

这用于在屏幕上创建一个功能全的多行文本编辑器。用户可以在按下 `Button1` 的同时通过将鼠标从一个位置到另一个位置来选择文本。用户还可以点击小部件的任何地方来标记插入点。如果文本小部件启用了用户输入，用户可以在插入点打字并将文本插入到文本小部件中。

## 下拉菜单 (Pull-Down Menus)

这些是窗口中的矩形区域，允许用户从一组项目中进行选择。这些项目通常布局在推按钮中。你可以通过将鼠标移动到该选择上或按下 Alt+K 来选择推按钮，其中 K 是菜单按钮中带有下划线的字母。在 `xmdialogs` 函数中，Meta+F 键选择文件项，Meta+H 键选择帮助项。

## 弹出菜单 (Pop-Up Menus)

Motif 窗口菜单是弹出菜单的一个良好示例。当你按下鼠标按钮时，会显示一个菜单。你可以通过将光标移动到项目上并按下 `Button1` 来选择菜单中的项目。

## `Xmscale`

`Xmscale` 小部件用于显示两个极值之间数据项的值。它也可以用于接受用户输入。比例小部件具有与滚动条非常相似的滚动区域。然而，它在两端没有箭头按钮。

## `XmScrolledWindow`

这是一个水平滚动条、垂直滚动条和绘制区域的组合。如果绘制区域的大小适合窗口，你将看不到滚动条。如果绘制区域的大小大于滚动窗口的可视区域，你将看到水平滚动条、垂直滚动条或两者兼有。然后你可以使用滚动条来移动绘制区域顶部的可见部分。这被称为窗口和平（panning）。

## `XmFrame`

这是一个简单的小部件，用于在单个小部件周围放置一致的边框。框架一次只能包含一个小部件。

## `XmRowColumn`

这是一个通用的小部件组织器。该小部件可以用多种方式布局其小部件集合，包括以下：

- 行优先（Row major）：行列小部件上的所有小部件都存储在这里，直到一行填满，当添加另一个无法放入该行的小部件时，就会创建一个新行。创建新行的过程有时被称为折行（wrap around）。

- 列优先（Column major）：这与行优先相同，但它是按列方式进行折行的。

你可以指定每列的宽度为最宽小部件的宽度、固定列的数量、打包方式（是否尽可能紧打包所有小部件），或由每个小部件单独决定。

正如前面提到的，Motif 小部件集中还有其他可用的小部件。你可以在开放软件基金会（OSF）的《程序员手册》中查看完整列表及其选项。

## Gadgets (小部件)

Motif 小部件在 X Windows 中创建窗口。一个复杂的 Motif 应用可以非常快地创建多个 X Windows。每个窗口使用服务器中的 X 资源，拥有许多窗口会降低你的整个系统性能。

Gadgets 是小部件的无窗口版本。大多数 gadget 的名称与小部件相同，但在名称后面加上了 `gadget` 字符串。因此 `XmLabel` 有一个对应的 `XmLabelGadget`。

Gadget 并不具备小部件的所有功能。例如，gadget 共享其父级的前景和背景颜色。此外，某些 gadget 实际上比它们试图替换的小部件更慢。

现在来看 `xterm` 客户端的资源声明。

```
XTerm\*foreground: white
XTerm\*background: blue
XTerm\*font: 10x20
...
aixterm\*foreground: white
aixterm\*background: blue
aixterm\*font: 10x20
```

在你的系统中，可能会看到 `cterm` 的声明，或者在 IBM 的 AIX 机器上，是 `aixterm` 而不是 `xterm`。这些仅仅是其他版本中 `xterm` 的名称。如果你有疑问，请在你的 `.Xresources` 文件中搜索 `XTerm`、`xterm` 或 `term` 单词。如果你还没有 `.Xresources` 文件，可以使用 ASCII 编辑器自己创建一个。

这些值可以是布尔值、数值或字符串值。它们也可以为应用程序中的部件（widgets）指定。例如，如果你想为名为 `myWorld` 的应用程序中的所有推送按钮设置背景颜色，你可以设置以下资源：

```
myWorld\*PushButton.background: red
myWorld\*background: blue
```

注意，星号用于表示实际 `myWorld` 应用程序与该应用程序所有推送按钮之间的部件。如果我们指定了 `myWorld.mainForm.PushButton: blue`，那么只有部件 `mainForm` 上的按钮（而 `mainForm` 必须存在于 `myWorld`）会受到影响。这是紧绑定（tight binding）。使用星号是松散绑定（loose binding），因为它允许星号两侧之间存在多层部件层级结构。如果你有一个层级为 `myWorld.mainForm.subForm.PushButton` 的应用程序，那么以下两个声明项会影响 `subForm` 上的按钮，但最后一个则不会：

```
myWorld\*PushButton.background: red
myWorld\*background: blue
myWorld.mainForm.PushButton: blue
```

另一个例子是 `xterm` 的设置。如果你尝试使用 `XTerm.scrollbar: true` 来设置滚动条，很可能不起。在顶层应用程序和滚动条部件之间可能会存在层级结构。在这种情况下，如果你使用以下命令将会生效：`XTerm\*scrollbar: true`

**提示：** 当你在资源文件中对部件使用非常通用的设置时，例如 `\*labelString`，这将影响所有文件中所有 `labelString` 的出现处。所以请小心！在修改 `.Xresources` 文件后，你可能期望立即看到变化。事实并非如此。你现在必须通过 `xrdb` 命令通知服务器你的默认值。使用以下命令：`xrdb -load .Xresources` 这将反映客户端后续执行的变化。这些更改将一直有效，直到被覆盖或会话结束。如果你将 `.Xresources` 文件保存在登录目录中，以后当你启动 X 并运行此命令时，这些更改将被加载：`xrdb -load .Xresources` 该命令在会话中首次创建 `.Xresources` 时很有用。这就是为什么在大多数情况下，该命令会在窗口首次创建时运行。如果你想保留之前的设置，请使用 `-merge` 选项代替 `-load`，例如 `xrdb -merge .myOwnResources`。

此外，你可以在输入行文本开始之前的任何位置使用感叹号作为注释字符。因此，以下行是注释：

```
! This is a comment
! another one
! commented\*labelString: This resource is not used.
```
