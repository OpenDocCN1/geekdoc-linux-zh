
# 文件系统安全

系统管理员倾向于更喜欢 `chmod` 的数字模式，因为它更快且更直观地与 `umask` 格式相关，而用户倾向于偏好 `chmod` 符号模式，因为它更类似于 `ls -l` 命令的输出。

## 使用 umask 设置默认权限

显然，整个系统中各种文件赋予的权限对任何特定用户所拥有的数据安全性有巨大影响。然而，要对系统中的每个文件逐个显式地设置权限是非常麻烦的，并且在每个新文件创建时都要保持这种纪律。发行版和包维护者在安装各种系统文件时已经付出了巨大精力来纠正这些权限以设置默认值。因此，通常没有必要逐个遍历整个 Linux 系统并手动设置权限。

幸运的是，也可以为新文件创建一个默认设置。通过 `umask` 命令可以实现。为了查看当前的 umask 值，输入：

```
umask
```

这将显示当前的 umask 值。系统管理员倾向于更喜欢 `chmod` 的数字模式，因为它更快且更直观地与 `umask` 格式相关，而用户倾向于偏好 `chmod` 符号模式，因为它更接近 `ls -l` 命令的输出。

`$HOME/.bashrc` 文件在非登录壳启动时会被加载。为了更改新账户的默认 `$HOME/.bashrc` 以反映更新后的 `umask` 值，请在 `/etc/skel` 中的文件末尾添加一行：

```
echo 'umask 177' >> /etc/skel/.bashrc
```

请注意，这些更改只影响 `bash` 壳；如果你在系统上选择了其他壳作为备选项，你也必须对它们进行类似的修改。

## 特殊情况、风险与收益

权限的构图比我们目前所描绘的要稍微复杂一些。虽然基本原理保持不变，但在一个具有安全意识的 Linux 系统语境下，还有一些特殊情况需要特殊处理。

### 额外的目录权限

除了目前为止涵盖的权限外，目录还有两个有趣的特殊情况。

第一个特殊情况被称为粘滞位，其命名源于一种已不再使用的功能。当将粘滞位应用于目录的其他权限时，粘滞位会创建一个特殊情况：具有写权限的用户可以创建文件，并修改和删除他们创建的文件。然而，其他用户创建并拥有的文件将保持限制状态。可以使用 `chmod` 的符号模式按如下启用粘滞位：

```
chmod +t mydirectory
```

如果你在 `ls` 输出的“其他执行权限”中看到字母 `t`，你就知道粘滞位已设置。

第二个特殊情况是当应用于目录的 SGID 位。 当此属性应用于目录时，在该目录内创建的任何文件将具有与父目录相同的组所有权。这对于需要更精细的组文件管理技术的情况非常有用。

### 设备节点

回想一下，某些类型的文件实际上指的是系统设备，而不是包含用户或程序数据的磁盘上的文件。这类文件通常被称为设备节点，位于 `/dev` 目录中。如果你访问 `/dev`，你会发现有很多这样的文件，特别是当你使用一种常见的 Linux 发行版之一时。

Linux 内核 2.4 实现了一种名为 `devfs` 的新方法来管理设备节点。在内核 2.4 中使用 `devfs` 时，设备节点仅存在于内存中的虚拟文件系统中，而不是磁盘上，并由内核自动分配安全的权限。

幸运的是，大多数发行版的安装程序在配置系统设备节点的所有权和权限方面做得相当不错。然而，在一种或两种情况下，我们应该重新评估并可能纠正设备节点的权限：

- 确保磁盘设备的权限配置正确非常重要。授予非 root 用户访问磁盘设备的权限是导致快速被黑客攻击、违规或崩溃的可靠方法。
- 对于任何似乎授予公共权限的设备，这也很重要。

对于磁盘设备，唯一安全的策略是确保只有超级用户 `root` 具有对设备节点的读写访问。与这些权限对应的 `chmod` 值是 `600`。要进行此更改，只需访问 `/dev` 并使用通配符：

```bash
# cd /dev
# chmod 600 sd* hd*
```

这将导致所有 IDE 和 SCSI 磁盘仅向 `root` 赋予写权限。请注意，这意味着普通用户将无法使用硬盘；这意味着只是普通用户将无法格式化硬盘或窃取他们原本没有权限访问的数据。

现在，我们需要确保没有设备节点对其他用户具有读或写权限。这可以通过符号模式下的单个 `chmod` 命令完成：

```
chmod o-rwx *
```

通常情况下，这样做没有真正的缺点。在极少数情况下，赋予所有用户访问设备的权限是一个好主意。然而，也有例外。一些特殊设备，例如 `/dev/null`、`/dev/zero` 和 `/dev/random`，应该为匿名用户提供一些可用的权限：

```
chmod a+rw /dev/null /dev/zero /dev/random
```

如果你对一次性更改这么多文件的权限感到谨慎，可以通过 `ls -l` 和 `grep` 配合简单模式获取具有匿名权限的文件列表：

```
ls -l | grep '^.......r...'
ls -l | grep '^.......w..'
ls -l | grep '^.......x'
```
