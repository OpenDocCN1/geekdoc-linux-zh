
`XAddConnectionWatch` 注册一个过程，每当 Xlib 打开或关闭指定显示器的内部连接时都会调用该过程。该过程接收显示器、客户端数据、连接的文件描述符、一个指示连接正在打开还是关闭的布尔值，以及指向私有数据位置的指针。如果 `opening` 为 `True`，该过程可以在 `watch data` 指向的位置存储指向私有数据的指针；当稍后为同一连接调用该过程且 `opening` 为 `False` 时，由 `watch data` 指向的过程将持有相同的私有数据指针。

此函数可以在显示器打开后的任何时间调用。如果已存在内部连接，则在 `XAddConnectionWatch` 返回之前，会立即为每个现有连接调用注册的过程。如果过程注册成功，`XAddConnectionWatch` 返回非零状态；否则返回 0。

注册的过程不应调用任何 Xlib 函数。如果过程直接或间接地导致内部连接或过程的状态发生变化，则结果未定义。除非使用 `XThreads` 成功初始化了 Xlib，否则此函数不起作用。

要解锁显示器，请使用 `XUnlockDisplay`。

```
XUnlockDisplay(display);
```

指定到 X 服务器的连接。

```
display
```

`XUnlockDisplay` 函数允许其他线程再次使用指定的显示器。任何在显示器上阻塞的线程都被允许继续。嵌套锁工作正常；如果一个线程多次调用了 `XLockDisplay`，那么在显示器实际解锁之前，必须调用相同次数的 `XUnlockDisplay`。除非使用 `XThreads` 成功初始化了 Xlib，否则此函数不起作用。

# 第3章 窗口函数

## 视觉类型

在显示硬件上，可能以超过一种方式处理颜色。例如，你可能处理一个任意映射到颜色的屏幕。这些处理屏幕视觉效果的不同方式被称为视觉类型（visuals）。对于每个屏幕，可能有一个支持的类型列表，大多数简单应用程序不需要处理这种复杂性。由于每个屏幕都定义了默认窗口和视觉类型，返回默认深度的 Xlib 宏和函数返回默认类型。

Xlib 是一个包含颜色映射信息的透明结构。视觉实用函数使用 `XVisualInfo` 结构返回此类信息。与此讨论相关的结构成员有 `class`、`red`、`green`、`blue mask`、`bits per rgb` 和 `colormap size`。`class` 成员指定可能的视觉类别之一，可以是 `StaticGray`、`StaticColor`、`TrueColor`、`GrayScale`、`PseudoColor` 或 `DirectColor`。

以下概念有助于更清晰地解释视觉类型。屏幕可以是彩色或灰色，可以具有可写或只读的调色板，还可以具有索引被分解为单独 RGB 像素的调色板，前提是不是在灰度屏幕上。

| | 颜色 (Color) | 灰色 (Gray-Scale) |
| --- | --- | --- |
| | 只读/可写 (R/O R/W) | 只读/可写 (R/O R/W) |
| 未分解 (Undecomposed) | 静态伪 (Static Pseudo) | 静态灰 (Static Gray) |
| 调色板 (Colormap) | 真色 (True Color) | 灰色 (Gray Scale) |
| 已分解 (Decomposed) | 直接 (Direct) | |

概念上，每个像素从显存中读取并显示在屏幕上，它通过索引调色板通过查找阶段。在某些硬件上可以任意操作调色板，在其他硬件上以有限的方式操作，而在其他硬件上完全无法操作。视觉类型以以下方式影响调色板和 RGB 值：

- 对于 `PseudoColor`，像素值索引调色板以产生独立的 RGB 值，且 RGB 值可以动态更改。
- `GrayScale` 的处理方式与 `PseudoColor` 相同，驱动屏幕的主通道未定义。因此，客户端应始终在调色板中为红、绿、蓝存储相同的值。

### 窗口函数

- 对于 `DirectColor`，像素值被分解为独立的 RGB 子字段，每个子字段分别索引对应值的调色板。RGB 值可以被动态更改。
- `TrueColor` 的处理方式与 `DirectColor` 相同，不同在于调色板是预定义的、只读的 RGB 值。这些 RGB 值取决于服务器，但在每个主色调中提供线性或近线性的范围。
- `StaticColor` 的处理方式与 `PseudoColor` 相同，不同在于调色板具有预定义的、只读的、取决于的 RGB 值。
- `StaticGray` 的处理方式与 `StaticColor` 相同，不同在于 RGB 值适用于任何单个像素值，从而产生灰调。具有两个条目的调色板的 `StaticGray` 可以被视为单色。

红掩码、绿掩码和蓝掩码成员仅为 `DirectColor` 和 `TrueColor` 定义。每个成员都有一组连续且互不相交的位集。`prgb` 成员定义了红、绿、蓝（分别）不同颜色值数量的对数 2。实际 RGB 值是无符号 16 位数。调色板的大小定义了新创建的调色表中可用的调色表项数。对于 `DirectColor` 和 `TrueColor`，这是单个像素子字段的大小。

要从 Visual 获取视觉 ID，请使用 `VisualIDFromVisual`。

```
VisualID VisualIDFromVisual(visual);
```

`visual` 指定了视觉类型。

`VisualIDFromVisual` 函数返回指定视觉类型的视觉 ID。

## 窗口属性

所有输入输出（InputOutput）窗口都具有零或多个像素的边框宽度、一个可选的背景、一个事件抑制（抑制事件从子窗口的传播）以及一个属性列表（见第 4.3 节）。窗口边界和背景可以是纯色或图案，称为平铺（tile）。除了根父窗口外，所有窗口都被其父窗口裁剪。如果一个窗口堆叠在另一个窗口上方，在输入方面它会遮挡该窗口。如果一个窗口具有背景（几乎所有窗口都有），则在输出方面它会遮挡另一个窗口。尝试向被遮挡区域输出将无无效，且不会为被遮挡区域生成输入事件（例如指针移动）。

窗口还关联有属性列表（见第 4.3 节）。

输入输出和输入仅（InputOnly）窗口具有以下共同属性，这些也是输入仅窗口的唯一属性：

- `win-gravity`
- `event-mask`
- `do-not-propagate-mask`

### 窗口函数

- `override-redirect`
- `cursor`

如果你为输入仅窗口指定了任何其他属性，将导致 `BadMatch` 错误。

输入仅窗口用于在不需要输入输出窗口的情况下控制输入事件。输入输出窗口是不可见的；只能用于控制光标、输入事件生成和抓取等内容；且不能用于任何图形请求。注意，输入仅窗口不能具有输入输出窗口作为其子窗口（inferiors）。

窗口具有可编程宽度和图案的边界，以及背景图案或平铺。像素值可用于纯色。如果在创建窗口后没有对它们进行显式引用，则背景和边界的位图（pixmaps）可以立即销毁。图案可以是相对于父窗口的或绝对的。如果是 `ParentRelative`（父相对），则使用父窗口的背景。

当数组首次创建时，它们在屏幕上是不可见的（未映射）。向不可见或没有备份存储（backing store）的窗口输出将被销毁。应用程序可能希望在窗口映射到屏幕之前创建窗口。当窗口最终映射到屏幕时（使用 `XMapWindow`），如果尚未维护备份存储，X 服务器将为该窗口生成一个 `Expos` 事件。

窗口管理器可以覆盖你对顶层窗口尺寸、边界宽度和位置的选择。你的程序必须准备好使用窗口的实际尺寸和位置。客户端响应人类命令自行调整大小是不可接受的。相反，你的程序应该使用分配给它的空间，或者如果空间太小无法进行有效工作，你的程序可以请求用户调整窗口大小。

为了设置窗口的适当成员，可以使用 `XSetWindowAttributes` 结构或在 `CreateWindow` 和 `XChangeWindowAttributes` 的后续调用中使用位或（OR）掩码。窗口边界对于窗口管理器是可以接受的。
