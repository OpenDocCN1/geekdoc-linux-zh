## 4.1.3.20 确保审计配置不可更改的（自动化）

**配置适用性：**

- 级别 2 - 服务器
- 级别 2 - 工作站

**描述：**

设置系统审计，使得审计规则无法通过 `auditctl` 进行修改。设置标记 `-e 2` 可强制将审计设置为不可更改模式（immutable mode）。审计的更改只能在系统重启时进行。

**注意：** 此设置需要重启系统以更新激活的 `auditd` 配置设置。

**原理：**

在不可更改模式下，未经授权的用户无法对审计系统执行更改以可能隐藏恶意活动，然后恢复审计规则。用户通常会注意到系统重启，这可能会警示管理员有人尝试进行未经授权的审计更改。

**审计：**

运行以下命令并验证输出是否匹配：

```bash
grep -Ph -- '^\h*-e\h+2\b' /etc/audit/rules.d/*.rules | tail -1 -e 2
```

# 修复

编辑或创建文件 `/etc/audit/rules.d/99-finalize.rules`，并在文件末尾添加行 `-e 2`：

示例：

```bash
printf -- "-e 2\n" >> /etc/audit/rules.d/99-finalize.rules
```

**加载审计规则**

将规则合并并加载到活动配置中：

```bash
augenrules --load
```

检查是否需要重启。

```bash
if [[ $(auditctl -s | grep "enabled") =~ "2" ]]; then printf "Reboot\nrequired to load rules\n"; fi
```

## 4.1.4.3 确保只有授权组被分配审计日志文件的所有权（自动化）

**配置适用性：**

- 级 2 - 服务器
- Level 2 - 工作站

**描述：**

审计日志文件包含有关系统和系统活动的信息。

**原理：**

访问审计记录可能会向攻击者泄露系统和配置数据，从而损害其机密性。

**审计：**

运行以下命令验证 `/etc/audit/auditd.conf` 中的 `log_group` 参数是否设置为 `adm` 或 `root`：

```
grep -Piw - '\h\*log_group\h=\*h*(adm|root)\b' /etc/audit/auditd.conf
```

验证输出结果：

```
log_group = adm
--OR-
log_group = root
```

使用包含审计日志的目录路径，通过以下命令判断审计日志文件是否属于 "root" 或 "adm" 组：

```bash
stat -c "%n %G" "$(awk -P="/\s*log_file\s*=\*/ (print $2)" /etc/audit/auditd.conf | xargs)" | grep -Pv '^\h\*H\*H+(adm|root)\b'
```

不应返回任何内容。

# 修复

运行命令将审计文件的所有权配置为 `adm` 组：

```bash
find $(dirname $(awk -F"-") '/\s*log_file/ (print $2)' /etc/audit/auditd.conf | xargs) -type f \( -group adm -a ! -group root \) -exec chgrp adm \ +
```

运行命令将审计文件的所有权配置为 `adm` 组：

```bash
chgrp adm /var/log/audit/
```

运行以下命令将审计配置文件中的 `log_group` 参数设置为 `log_group = adm`：

```bash
sed -ri '/\s*#\?\s*log_group\s*=\s*S+\((\s*#\*\)\?\.*?\/log_group = adm\l1/' /etc/audit/auditd.conf
```

运行以下命令重启审计守护进程以加载配置文件：

```bash
systemctl restart audit
```

## 4.1.4.7 确保审计配置文件属于 root 组（自动化）

**配置适用性：**

- 2 级 - 服务器
