
| 选项 | 说明 |
| :--- | :--- |
| `-O` | 优化编译。 |
| `-l filename` | 通过文件名链接系统库。（文件名前加 `lib` 且扩展名为 `.a`。`gcc` 命令行中不包含这些内容。`-l` 选项必须始终放在命令行中的源代码和目标代码文件名之后。） |

## 源文件、目标文件和可执行文件

你可以将你的 C 程序组织成许多不同的源代码文件。这允许你通过将程序切割成若干较小的源代码文件来更容易地管理一个大型程序。每个源代码文件都可以包含设计用于关注特定任务的函数。在数据库程序中，你可以将执行输入的函数放在一个文件中，将执行搜索的放在另一个文件中。按照习惯，主函数通常放在单独的文件中，有时称为 `main.c`。

在接下来的 `bookrec` 程序中，`bookinput` 和 `printbook` 函数被放在名为 `io.c` 的源代码文件中，因为它们处理输入和输出。

```c
#include <stdio.h>
void main(void) {
    printf("Hello, how are you\n");
}
```

## ELF 和 a.out 二进制格式

二进制文件（如可执行程序）有两种可能的格式。第一种是 `a.out` 格式，它是 Unix 系统以及早期 Linux 系统使用的原始格式。`a.out` 一词源于 Unix C 编译器为可执行文件赋予的默认名称。随着共享库的使用，`a.out` 格式出现了困难。将 `a.out` 格式适配并作为共享库使用是一项非常复杂的操作。因此，Unix System 5 Release 4 和 Solaris 引入了一种新格式。它被称为可执行与可链接格式（ELF）。它的设计允许易用地实现共享库。

ELF 格式已被采用为 Linux 系统的标准格式。由 `gcc` 编译器生成的所有 ELF 格式的二进制文件都采用这种格式（尽管可执行文件的默认名称仍为 `a.out`）。可能仍在使用 `a.out` 格式的旧程序仍然可以在支持 ELF 的系统上运行。

## C++ 和 Objective-C：g++

`gcc` 工具同样也是一个 C++ 编译器。它可以读取并编译任何 C++ 程序。然而，它不会自动与 C++ 类库进行链接。你需要在命令行中调用它。或者，你可以使用命令 `g++`，它会在带有 C++ 类库的情况下调用 `gcc` 编译器。

C++ 源文件的扩展名与普通 C 文件不同。C++ 识别多种不同的扩展名：`.C`、`.cc` 或 `.cxx`（其中 `xx` 可以是任意字符），以及 `.cpp`。除了这个区别，你编译 C++ 程序的方式就像编译 C 程序一样。相比于 `gcc`，更倾向于使用 `g++` 命令。下面的示例编译了一个 C++ 程序 `myprog.cpp`。

```
$ g++ myprog.cpp -o myprog
```

`gcc` 编译器还支持 Objective-C 程序。Objective-C 是一种最初为 NeXT 系统开发的面向对象的 C 语言版本。要编译 Objective-C 程序，你使用带有 `-lobjc` 选项的 `gcc` 命令。`-lobjc` 会链接到 Objective-C 库 `libobjc.so`。下面的示例编译了一个 Objective-C 程序 `myprog.c`。

```
$ gcc myprog.c -o myprog -lobjc
```

## 其他编译器：Pascal、Ada、Lisp 和 Fortran

你的 Linux 系统支持许多编程语言。许多语言可以在你的 OpenLinux CD 中找到。除了 C 和 C++，你还可以编译 Pascal、Ada、Lisp、Basic 和 Fortran 程序。在某些情况下，编译由 `gcc` 编译器处理，它被设计用于识别其他编程语言的源代码。例如，G77 是 GNU Fortran 编译器。该编译器与 `gcc` 编译器集成。`g77` 命令将通过带有识别 Fortran 代码选项的 `gcc` 编译器（使用 `gcc` 的 G77 特性）来编译 Fortran 程序。

ADA 95 编译器被称为 `gnat`。ADA 的 info 文件提供了关于 `gnat` 的详细信息。你可以使用 `gnatmake` 命令配合文件名编译 ADA 程序。下面的示例编译了名为 `hello.ada` 的 ADA 程序。

```
$ gnatmake hello.ada
```

编译操作由 `gcc` 调用，它识别 `.ada` 扩展名然后调用 `gnat` 编译器。随后 `gnatbind` 命令将目标代码链接成可执行的 ADA 程序。下表列出了 Linux 上提供的各种编译器的命令：

| 命令 | 说明 |
| :--- | :--- |
| `gnat` | ADA 95 编译器。 |
| `g++` | C++ 编译器（`gcc` 的前端）。 |
| `gcc` | C 编译器。也编译 Fortran 等其他语言。可以作为其他编译器的前端。 |
| `gcc -lobjc` | Objective-C 编译。 |
| `g97` | GNU Fortran 77 编译器 |
| `p2c` | `gcc` 的 Pascal 到 C 翻译器 |
| `basic` | Basic 解释器 |
| `gcl` | Common Lisp 解释器，CLISP |
| `regula-2` | Modula-2 编译器 |
| `smalltalk` | Smalltalk 解释器 |

## 创建和使用库：静态、共享和动态

C 程序中通常会有很少需要编译的函数。可能还有你希望在不同程序使用的函数。此类函数通常执行标准任务，例如数据库输入/输出操作或屏幕操作。你可以预编译此类函数，并将它们一起放在一种特殊类型的目标代码文件中，这种文件被称为“库”（library）。此类库中的函数可以通过链接器与程序结合。它们节省了你为每个开发的程序都重新编译这些的麻烦。

不同类型的应用程序使用放置在系统目录中的专用库，并供开发程序时使用。例如，有一个名为 `libdbm` 的库，它包含了实现文件数据库访问的 `db` 函数。你可以通过链接该库 `libm` 以及 X-Window 可以在自己的程序中使用这些函数。数学应用程序将使用数学库 `libm` 和 `libX11` 库。这些库被放置在 `/usr/lib` 等系统目录下，系统上的任何人都可以访问它们。你也可以创建自己的库供特定的程序使用，或者创建一个你想让其他人访问的库。

库可以是静态的、共享的或动态的。静态库代码在编译时合并到程序中的库。共享库代码在运行时加载到程序中的库。动态库是在加载时进行链接的库。

对于 `libmyio.so.1.0` 文件，对应有 `libmyio.so` 和 `libmyio.so.1`（参见下一节）。

```
$ gcc main.c -o bookrec -Lmydir -lmyio
```

## 共享库

共享库的设计目的是供许多不同的应用程序使用。这样，应用程序就不需要重复代码。应用程序使用的大多数库都是共享库。共享库的扩展名与普通库不同。共享库不使用 `.a` 扩展名，而是使用 `.so` 扩展名，后面跟着主版本和次版本号。次版本号是可选的，可以是你想要的值。例如，X-Window 的共享库是 `libX11.so.6`。

然而，在编译时搜索库的链接器（`ld`）以及在程序运行时运行时搜索库的动态链接器（`dl`）搜索的是共享库名称的不同形式。链接器搜索的是仅以 `.so` 结尾且没有版本号的名称。另一方面，动态链接器搜索的是所谓的 `soname`，这是一种存储在库文件内部的名称，它用于标识该库。这两者都与库文件的实际名称不同。为了链接器和动态链接器能够定位库文件，必须指向该库文件的链接，其名称格式为链接器可以识别的形式。通过引用链接，它们将引用库文件。对于链接器（`ld`），必须有一个名称以 `.so` 扩展名结尾的链接。对于动态链接器（`dl`），必须有一个名称与 `soname` 相同的链接。然后，需要一个带有 `.so` 扩展名的指向 `soname` 的链接。这就是链接器（`ld`）将识别的链接。例如，`libc.so.5.4.22` 将有一个名为 `libc.so.5`（`soname`）的链接，该链接又指向另一个名为 `libc.so` 的链接。

```
name.so -> soname -> libname.so.ver.min
libc.so -> libc.so.5.4.22
```

`soname` 是动态链接器用于标识共享库的名称。在编译引用共享库的程序时，是这个 `soname` 被放置在程序的可执行代码中，并标识在运行时加载哪个库。（对于静态库，文件的整个代码都被整合到程序的可执行代码中。）你使用 `ldconfig` 命令生成指向 `soname` 的链接。`ldconfig` 会自动从库文件中读取 `soname` 并创建一个指向该文件的同名链接。在系统启动时，`ldconfig` 程序会自动更新位于共享库目录中的库的链接，包括位于 `/usr/lib`、`/lib` 以及在 `/etc/ld.conf` 中列出的库。另一方面，必须为带有 `.so` 扩展名的链接器创建处理器。
