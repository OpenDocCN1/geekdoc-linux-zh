
列出硬件设备的信息。

### 语法

`lshw`命令的语法是`lshw [options]`

## 设备类别

`lshw`的输出将设备分组为若干类之一。你可以通过指定类来过滤结果。例如，使用`lshw -network`将仅输出关于网络设备的详细信息。要查看系统中当前的类别，使用`lshw -short | sort -k2`生成按类别排序的非详细设备列表。

## `dmidecode`命令

`dmidecode`命令转储桌面管理接口（DMI）表并以人类可读的格式呈现。DMI表是跟踪硬件组件信息的行业标准。它将组件分为不同的类型，每个类型都有一个数字——例如，`type 4`是处理器，`type 39`是电源等。与其他命令类似，你可以使用`dmidecode`验证连接的设备是否支持某些功能。然而，`dmidecode`的作者警告说，DMI表中的信息并非总是“准确、完整或完全正确”。因此，不要依赖DMI表作为硬件信息的唯一来源。

### 语法

`dmidecode`命令的语法是`dmidecode [options]`

## ABRT

自动错误报告工具（ABRT）是一个收集和报告崩溃的实用程序。它得到了改进。获取最新的驱动程序以确保最佳视频性能至关重要。这些驱动程序可以在供应商的网站上下载。

## 存储适配器问题

总线适配器故障有几种可能的指示标准，包括：

- 数据传输速度慢。
- 可用总空间小于预期。
- 过多的读/写错误。
- 完全无法读写。
- 系统无法检测设备。
- 以及更多。

问题可能出在物理HBA本身，也可能出现在HBA使用的接口上，如SCSI或SATA。第一步是确保HBA已供电。然后，你需要确保连接到HBA的存储设备使用了适当的接口。虽然不同版本的SCSI和SATA通常向后兼容，但如果总线接口使用的技术比驱动器旧，驱动器将受限于该规范。当然，要确保所有设备插槽正确，且所有电缆已连接并无损坏。

在某些情况下，如果系统无法识别SCSI设备，你可能需要重新扫描其连接的SCSI总线。

```bash
echo " - " > /sys/class/scsi_host/*/scan
```

`#`代表你正尝试扫描的总线编号。`echo`语句中的连字符是SCSI控制器、SCSI通道和逻辑单元号（LUN）的通配符。具体来说，这将提示系统扫描此总线上的新设备并添加任何检测到的设备。然而，此过程可能会干扰操作，因此应仅在必要时使用。

## RAID故障排除

如你所见，`mdadm`命令用于管理RAID阵列。`-f`激活监控模式，让你识别阵列中缺失或失败的驱动器。在移除故障驱动器后，可以使用命令的其他选项来重建阵列。

其他用于排除RAID问题的有用`mdadm`如下：

- `-f`—将指定设备标记为故障，为从阵列中移除做准备。
- `--remove`—从阵列中移除设备。`failed`指定所有标记为故障的设备都应被移除。
- `--re`—将移除的设备添加回阵列，以便恢复存储在设备上的数据。
- `-a`—将设备作为热备用添加到阵列。如果阵列处于降级状态，它将在该空间上重建数据。此二进制文件仅适用于无法读取或从未属于阵列的设备。

## `lshw`命令

`lshw`命令列出系统上检测到的每个硬件组件，并提供每个设备的详细信息。该命令从位于`/proc/`等多个设备文件位置的许多不同文件中提取信息，并以层次格式输出。`lshw`输出的信息包括主板、CPU、RAM模块、外围设备、存储设备等的厂商、产品名称、容量、速度和许多其他属性。

与其他检索设备信息的命令和文件一样，你可以使用`lshw`来识别设备是否被内核识别，并检索设备的能力和特征。

注意：根据版本不同，`lshw`命令可能检测不到FireWire设备。检查其`man`页以验证。

# TCP/IP

网络过程受协议的控制。就像人类对话一样，计算机网络通信由规则管理。这些规则控制了在任何时间通信的信息量、使用什么地址表示节点、节点如何在网络上进行通信，以及哪里可能存在错误检查。多年来存在许多协议族，如今唯一的协议套件是传输控制协议/网络协议（TCP/IP）。它是互联网以及大多数内部私有网络的默认协议。

# OSI模型

开放系统互结（OSI）模型对功能定义进行了标准化。OSI模型包含几层。每层都代表一个责任领域，只有满足了这些领域，才能使网络过程正常工作。IT专业人员需要了解这些层是如何运作的。你应该按顺序记住它们，并对每个层都有一个简短的定义。

OSI模型在与其他专业人员交流时也作为一个标准的参考点。例如，你可能对购买一台“二层交换机”或排错“三层”问题感兴趣。它是设备的通用参考点，也是创建网络应用程序的开发者的指南。

| 层级名称 | 基本功能 |
| :--- | :--- |
| 7 应用层 | 支持应用程序和终端用户。 |
| 6 表示层 | 对数据进行格式化处理。 |
| 5 会话层 | 建立、维护和拆除连接。 |
| 4 传输层 | 实现信息的可靠传输。 |
| 3 网络层 | 实现逻辑地址（IP 地址）。 |
| 2 数据链路层 | 实现物理地址（MAC 地址）。 |
| 1 物理层 | 实现物理网络连接。 |

> 注意：关于OSI模型还有许多极大的额外功能和细节。作为一名网络专业人员，你必须熟悉这些功能。此表仅作为简要概述。

# TCP/IP层级

TCP/IP协议套件通过四层结构满足了OSI模型的要求。该套件用于管理内部网络上的网络通信。它也是互联网的协议套件。Linux、Unix、macOS、Windows等均使用TCP/IP。对TCP/IP套件及其层有基本的理解至关重要。

理解TCP/IP套件有助于排错和网络配置。例如，IP地址支持发生在IP层，而应用支持发生在应用层。

# 网络身份

“节点”指的是在网络上具有身份的设备。该身份可以由物理地址或两个逻辑地址之一表示，也可以是这三者的任何组合。

- 标识符
- MAC地址
- IP地址
- 主机名
- 描述

每个网络网卡（NIC）内部都编码有一个唯一的身份，用于识别网络分段上的该网卡。该代码被称为媒体访问控制（MAC）地址。它是最基础的网络身份，被视为物理地址。

每个网卡都可能被分配一个称为IP地址的逻辑地址。IP地址在网络环境中唯一标识该网卡。

IP地址以点分十进制（十进制）显示，范围是0-9。计算机使用二进制（2进制）处理IP地址，范围是0-1。

节点可能有一个人类可读的名称，可以帮助人们更好地理解他们正在操作哪种设备。这种身份通常在安装操作系统期间配置，有时被称为“计算机名称”。主机名限制为255个字符。

注意：网络上的不同设备引用不同的地址。通常交换机会根据MAC地址管理流量，而路由器根据IP地址管理流量。
