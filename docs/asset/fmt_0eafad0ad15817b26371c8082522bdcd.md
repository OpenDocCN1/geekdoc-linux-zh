
如果你已经在某个时候更改了头文件，那么这样做太晚了。相反，你可以使用 `-o` 标志，它将文件标记为“旧”（参见第 9.7 节 [选项总结]，第 104 页）。这意味着它不会重新 `makefile`。这是正确的步骤：

1. 使用命令 `make` 重新编译真正需要重新编译的源文件，确保在开始之前对象文件是最新的。
2. 在头文件中进行更改。
3. 使用命令 `make -t` 将所有对象文件标记为最新。下次运行 `make` 时，头文件中的更改将不会导致任何重新编译。

或者，如果你已经更改了头文件，可以使用 `-o` 标志将其标记为“旧”。除非使用其他标志，否则它不会重新 `makefile`。

## 9.5 覆盖变量

当你想要在命令行上覆盖变量时，使用 `v=value`。例如，`make v=value`。这是使用的常用方法。如果你想在 Makefile 中覆盖变量，使用 `override` 指令：

```makefile
override v = value
```

这将允许命令行覆盖变量。然而，如果变量在 Makefile 中没有使用 `override` 指令，命令行将被忽略。

## 9.6 测试编译

通常，当执行命令时发生错误，`make` 会立即停止。`-k` 或 `--keep-going` 标志告诉 `make` 尽可能继续。例如，在编译一个文件出错后，`make -k` 将继续编译其他文件。

# 10 使用隐式规则

重新生成文件的标准方法被频繁使用。例如，使用编译器 `cc` 从 C 源文件生成对象文件的一种惯用方法。

隐式规则告诉系统如何使用常规技术，以便在你需要使用它们时无需显式指定。例如，C 编译的隐式规则决定了运行哪些隐式文件。例如，C 编译通常取一个 `.c` 文件并生成一个 `.o` 文件。因此，当文件名后缀出现这种组合时，`make` 会应用 C 编译的隐式规则。

隐式规则链可以顺序应用：例如，`make` 会从 `.y` 文件重新生成 `.o` 文件。参见第 10.4 节 [隐式规则链]，第 117 页。

内置隐式规则在其配方中使用了多个变量，因此通过更改变量，你可以改变隐式规则的工作方式。例如，变量 `CFLAGS` 控制 C 编译隐式规则传递给 C 编译器的标志。参见第 10.3 节 [隐式规则使用的变量]，第 115 页。

你可以通过编写模式规则来定义自己的隐式规则。参见第 10.5 节 [定义和重新定义模式规则]，第 118 页。

后缀规则在定义隐式规则方面非常有限。模式规则更通用且清晰，但保留后缀规则是为了兼容性。参见第 10.7 节 [旧式后缀规则]，第 125 页。

## 10.1 使用隐式规则

为了让 `make` 找到更新目标文件的自定义方法，你只需要避免自己指定配方即可。写一个没有配方的规则，或者干脆不写规则。然后 `make` 将根据存在或可以制作的源文件类型确定使用哪种规则。

例如，Makefile 如下所示：

```
foo : foo.o bar
	cc -o foo.o bar $(CFLAGS) $(LDFLAGS)
```

由于你命名了 'foo.o' 但没有为它提供规则，`make` 将自动查找指示如何更新它的隐式规则。无论 'foo.o' 文件当前是否存在，这种情况都会发生。

如果找到隐式规则，它可以同时提供配方和一个额外的先决条件（源文件）。如果你需要指定额外的先决条件（如头文件），隐式规则无法提供。

每个隐式规则都有一个目标模式和一个先决条件模式。例如，许多规则如 '.o 文件：一个，使用 C 编译器从 .c 文件生成'；另一个另一个，使用 Pascal 编译器从 .p 文件生成'；以此类推。实际应用的规则是那些先决条件存在或可以被制作的规则。因此，如果你有一个文件 'foo.c'，`make` 将运行 C 编译器；否则，如果你有一个文件 'foo.p'，`make` 将运行 Pascal 编译器；以此类推。

当然，当你编写 Makefile 时，你会知道想要使用哪种隐式规则，并且你知道它会选择那一个，因为你知道哪些可能的先决文件本应该存在。参见第 10.2 节 [隐式规则目录]，第 112 页获取所有预定义的隐式规则目录。

上面我们提到，如果所需的先决条件“存在”或可以制作，则隐式规则即可适用。如果一个文件在 Makefile 中被列为目标，或者可以递归找到如何制作它的隐式规则，则该文件“可以被制作”。当隐式先决条件是另一个隐式规则的结果时，我们称为发生了链式。参见第 10.4 节 [隐式规则链]，第 117 页。

通常，`make` 为每个目标搜索隐式规则，并为每个没有配方的双冒目标搜索隐式规则。作为先决条件提到的的文件没有指定内容的目标，因此隐式规则会对其搜索。参见第 10.8 节 [隐式规则搜索算法]，第 127 页了解搜索执行的细节。

注意，显式先决条件不影响隐式规则搜索。例如：

```
foo: foo.p
```

'foo.p' 的先决条件并不意味着 `make` 会制作 'foo'。如果找到隐式规则，它可以同时提供配方和一个额外的先决条件（源文件）。如果你需要指定额外的先决条件（如头文件），隐式规则无法提供。
