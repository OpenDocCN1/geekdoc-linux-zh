
| | 0.0% | 被“nice”（低优先级）进程占用的 CPU 百比。 |
| | 98.3%id | 98.3% 的 CPU 是空闲的。 |
| | 0.0%wa | CPU 等待 I/O 的百分比。 |
| 4 | Mem | 显示物理内存 RAM 的使用情况。 |
| 5 | Swap | 显示交换空间（虚拟内存）的使用情况。 |

## 控制进程

现在我们已经查看并监控进程了，让我们对它们进行一些控制。对于我们的实验，我们将使用一个名为 `xlogo` 的小程序作为实验对象。`xlogo` 程序是 X 系统（使显示器显示图形底层引擎）提供的示例程序，它只是显示一个包含 Logo 的可调整大小窗口。首先，我们将了解我们的测试对象。

```
$me@linuxbox~$ xlogo
```

输入命令后，一个包含 Logo 的小窗口应该出现在屏幕某个地方。某些系统上 `xlogo` 可能会打印警告消息，但可以安全忽略。

> 如果你的系统没有 `xlogo` 程序，请尝试 `edit` 或 `kwrite`。

我们可以通过调整窗口大小来验证 `xlogo` 正在运行。如果 Logo 按新大小重新绘制，说明程序正在运行。

注意我们的 shell 提示符返回了吗？这是 shell 等等待程序结束，与我们到为止使用的其他程序一样。如果我们关闭 `xlogo` 窗口（见图 10-1），提示符就会返回。

## 中断进程

让我们观察再次运行 `xlog` 时会发生什么。首先，输入 `xlogo` 命令并确认程序正在运行。接下来，返回终端窗口并按下 `CTRL-C`。

```
[me@linuxux ~]$ xlog
[me@linuxux ~]$
```

在终端中，按下 `CTRL-C` 会中断程序。这意味着我们正在礼貌地请求程序终止。在我们按下 `CTRL-C` 后，`xlogo` 窗口关闭，壳（shell）提示符也返回了。

许多（但不是所有）命令行程序都可以通过这种技术进行中断。

## 将进程放入后台运行

假设我们想在不终止 `xlogo` 程序的情况下获取 shell 提示符。我们可以通过将程序置于后台来实现这一点。可以将终端设为具有前台（表面有可见的内容，如 shell 提示符）和后台（隐藏在表面之后的内容）。要启动一个程序并使其立即在后台运行，请在命令后加上波浪符号 `&`。

```
[me@linuxux ~]$ xlog &
[1] 28236
[me@linuxux ~]$
```

输入命令后，`xlogo` 窗口出现了，shell 提示符也返回了，但出现了一些奇怪的数字。这条消息是 shell 功能“作业控制”（job control）的一部分。通过这条消息，shell 告诉我们已经启动了作业 1 `((1))`，它的 PID 为 `28236`。如果我们运行 `ps`，就可以看到我们的进程。

```
[me@linuxux ~]$ ps
PID TTY CMD
10603 pts/1 00:00:00 bash
28236 pts/1 00:00:00 xlog
28239 pts/1 00:00:00 ps
```

shell 的作业控制功能为我们提供了列出从终端启动的作业的方法。使用 `jobs` 命令，我们可以看到：

```
[me@linuxux ~]$ jobs
[1]+ Running xlog &
```

结果显示我们有一个编号为 1 的作业；它正在运行；且该命令是 `xlog &`。

### 将进程返回前台

在后台运行的进程不受终端键盘输入中断的影响，包括任何尝试 `CTRL-C` 中断它的尝试。要将进程返回前台，请按如下方式使用 `fg` 命令：

```
me[linuxbox ~]$ jobs xlogo &
[1]+ Running
me[linuxbox ~]$ fg %1
xlogo
```

`fg` 命令后跟一个百分号和作业号（称为作业规格，jobspec）即可起作用。如果我们只有一个后台作业，则作业规格是可选的。要终止 `xlogo`，按下 `CTRL-C`。

## 停止（暂停）进程

有时我们想在不终止进程的情况下停止它的运行。这通常是为了允许前台进程移动到后台。要停止前台进程并将其放入后台，按下 `CTRL-Z`。让我们试一下。在命令提示符下，输入 `xlogo`，按回车，然后按 `CTRL-Z`。

```
me[linuxbox ~]$ xlogo
[1]+ Stopped
me[linuxbox ~]$
```

停止 `xlogo` 后，我们可以通过尝试调整 `xlogo` 窗口的大小来验证程序已停止。我们会发现它看起来完全死掉了。我们可以使用 `fg` 命令在前台继续执行程序的执行，或者使用 `bg` 命令在后台恢复程序的执行。

```
me[linuxbox ~]$ bg %1
[1]+ xlogo &
me[linuxbox ~]$
```

与 `fg` 命令一样，如果只有一个作业，作业规格是可选的。如果我们从命令行启动图形化程序，但忘记通过附加 `&` 将其置于后台，那么将进程从前台移动到后台就是非常有用的。

我们为什么想要从命令行启动图形化程序呢？原因有两个：

- 你想运行的程序可能没有列在窗口管理器的菜单中（例如 `xlogo`）。
- 通过从命令行启动程序，你可能会看到错误信息，而如果程序是通过图形界面启动的，这些信息将是不可见的。有时，程序从图形菜单启动时会无法启动。通过转而从命令行启动它，我们可能会看到揭示问题的错误消息。此外，某些图形程序具有有趣且的命令行选项。

## 信号

`kill` 命令用于“杀死”进程。这允许我们终止需要被“杀掉”的程序（即某种暂停或终止）。这是一个例子：

```
me@linuxbox ~]$ xlogo &
[1] 28401
me@linuxbox ~]$ xkill 28401
[1]+ Terminated
xlogo
```

我们在后台启动 `xlogo`。shell 打印出作业规格和后台进程的 PID。接下来，我们使用 `kill` 命令并指定我们要终止的进程的 PID。我们也可以使用作业规格（例如 `x!`）而不是 PID 来指定进程。

虽然这一切看起来很直观，但其原理远不止于此。`kill` 命令并不真正“杀死”进程；相反，它发送的是信号。信号是操作系统与程序通信的多种方式之一。我们已经通过使用 `CTRL-C` 和 `CTRL-Z` 看到了信号的作用。当终端接收到这些按键之一时，它会向前台程序发送信号。在 `CTRL-C` 的情况下，会发送一个名为 `INT`（中断）的信号；对于 `CTRL-Z`，会发送一个名为 `TSTOP`（终端停止）的信号。程序“监听”信号并在接收时采取行动。这种机制允许程序在接收到终止信号时保存正在的工作。

### 使用 kill 发送信号

`kill` 命令用于向程序发送信号。最常用的语法如下：

```
kill -signal PID
```

如果命令上没有指定信号，则默认发送 `TERM`（终止）信号。`kill` 命令通常用于发送表 10-4 中列出的信号。

#### 表 10-4：常见信号

| 数字 | 名称 | 含义 |
|---|---|---|
| 1 | HUP | 挂起。这是终端通过电话线和调制解调器连接远程计算机时代的遗。该信号用于指示控制终端已“挂断”。可以通过关闭终端演示此信号的效果。 |
| 2 | INT | 中断。 |
| 3 | QUIT | 退出。 |
| 9 | KILL | 杀死。 |
| 15 | TERM | 终止。 |
| 18 | CONT | 继续。 |
| 19 | STOP | 停止。 |
| 20 | TSTP | 终端停止。 |

#### 表 10-5：其他常见信号

| 数字 | 名称 | 含义 |
|---|---|---|
| 11 | SEGV | 段错误。如果程序非法使用内存，将发送此信号；例如它尝试向不允许写入的地方写入。 |
| 28 | WINCH | 窗口变化。这是当窗口大小发生变化时系统发送的信号。某些程序（如 `top` 和 `less`）会对此信号做出响应，重绘自己以适应新的窗口尺寸。 |

为了演示，我们将启动几个 `xlogo` 程序的实例，然后将它们终止。

```
[melinuxbox ~]$ xlogo &
[1] 18801
[melinuxbox ~]$ xlogo &
[2] 18802
[melinuxbox ~]$ killall xlogo
[1]- Terminated
[2]+ Terminated
```

请记住，和使用 `kill` 一样，你必须拥有超级用户权限向不属于你的进程发送信号。

## 系统关机

关机过程涉及有序地终止系统上的所有进程，并在系统掉电之前执行一些关键的家务工作（例如同步所有挂载的文件系统）。有四个命令可以执行此功能：

- `halt`
- `poweroff`
- `reboot`
- `shutdown`

前三个命令非常自而易见，通常与任何命令行选项一起使用。这是一个示例：

```
[melinuxbox ~]$ sudo reboot
```

`shutdown` 命令稍微有趣一些。通过它，我们可以指定要执行的操作（停止、关机或重启），并为关机事件提供时间延迟。通常这样使用它停止系统：

```
[melinuxbox ~]$ sudo shutdown -h now
```
