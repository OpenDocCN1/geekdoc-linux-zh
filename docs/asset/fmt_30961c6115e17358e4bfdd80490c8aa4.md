
打开一个键。`key` 是一个打开的键或 `HKEY*`，`sub_key` 是标识要打开的键的字符串。`res` 是一个保留的整数，必须为零（默认值）。`sam` 是定义键的安全访问掩码的整数。默认值是 `KEY_READ`。以下是 `sam` 的其他可能值：

- `KEY_ALL_ACCESS`
- `KEY_CREATE_LINK`
- `KEY_CREATE_SUB_KEY`
- `KEY_ENUMERATE_SUB_KEYS`
- `KEY_EXECUTE`
- `KEY_NOTIFY`
- `KEY_QUERY_VALUE`
- `KEY_READ`
- `KEY_SET_VALUE`
- `KEY_WRITE`

`OpenKeyEx()`

与 `OpenKey()` 相同。

`QueryInfo(key)`

返回关于元组 `(num_subkeys, num_values, last_modified)` 的信息，其中 `num_subkeys` 是子键的数量，`num_values` 是值的数量，`last_modified` 是一个包含修改时间的长整型。时间从 1601 年 1 月 1 日起，单位为 100 纳秒。

`QueryValue(key, sub_key)`

以字符串形式返回键的未命名值。`key` 是一个打开的键或 `HKEY*` const。`sub_key` 是要使用的子键名称（如果有）。如果省略，函数将返回与 `key` 关联的值。此函数返回带有空句柄的第一个值的数据。但是，它返回的是类型（请使用 `QueryValueEx`）。

`QueryValueEx(key, value_name)`

返回一个包含数据值和类型的元组 `(value, type)`，`key` 是一个打开的键或 `HKEY*` 常量。`value_name` 是要返回的值的名称。返回的类型是 `EnumValue()` 中定义的整数代码之一。

`SaveKey(key, filename)`

将键及其所有子键保存到文件中。`key` 是一个打开的键或预定义的 `HKEY-*` const。`filename` 必须已经存在且不包含包含扩展名。此外，调用者必须具有备份权限操作才能成功。

`SetValue(key, sub_key, type, value)`

设置键的值。`key` 是一个打开的键或 `HKEY*` 常量。`sub_key` 是与键关联的值的子键名称。`type` 是一个整数类型代码，目前仅限于 `REG_SZ`。`value` 是包含值数据的字符串。如果 `sub_key` 不存在，则会创建。`key` 必须以 `KEY_SET_VALUE` 权限打开，此函数才能生效。

`SetValue(key, value_name, reserved, type, value)`

设置键的字段。`key` 是一个打开的键或 `HKEY*` 常量。`value_name` 是值的名称。`type` 是 `EnumValue()` 函数描述的整数类型代码。`value` 是包含新值的字符串。当设置数值类型（例如 `REG_DWORD`）的值时，`value` 仍然是包含原始数据的字符串。该字符串可以使用 `struct` 模块创建。`reserved` 目前被忽略，可以设置为任何值（该值未被使用）。

# 线程与并发

本章介绍了用 Python 当前程序的库模块和编程策略。主题包括线程、消息传递、多进程和协程。在介绍特定的子进程库模块之前，首先描述一些基本概念。

# 基本概念

运行中的程序被称为进程。每个进程都有自己的系统状态，包括内存、打开的文件列表、用于跟踪正在执行指令的程序计数器以及用于存放函数局部变量的调用栈。通常，进程在控制流中按顺序一个接一个执行语句，这有时被称为进程的主线程。在任何给定时刻，程序只在做一件事。

程序可以使用库函数创建新进程，例如在 `os` 或 `subprocess` 模块中的函数（例如 `os.fork()`、`subprocess.Popen()` 等）。然而，这些被称为子进程的进程是完全独立的实体——它们有自己的私有系统状态和执行主线程。由于子进程是独立的，因此它与原始进程并发执行。也就是说，创建子进程的进程可以去处理其他事情，而子进程在后台执行自己的工作。

尽管进程是隔离的，但它们之间可以相互通信——有时被称为进程间通信 (IPC)。IPC 最常见的形式之一是消息传递，即传递简单的原始字节缓冲区。像 `send()` 和 `recv()` 等原始操作用于通过管道或网络套接字通过 I/O 通道传输或接收消息。另一种常见的 IPC 机制使用内存映射区域（参见 `mmap` 模块）。通过内存映射，进程可以创建内存共享区域。对这些区域的修改在查看它们的所有进程中都是可见的。

多个进程可以被操作系统用来处理任务。

即使使用了线程，许多程序员仍然发现其扩展性特性相当神秘。例如，一个在 100 个线程下运行良好的线程网络服务器，如果扩展到 10,000 个线程，性能可能会变得糟糕。从一般规则来说，你真的不想编写一个包含 10,000 个线程的程序，因为每个线程都需要自己的系统资源，而且与上下文切换、锁定等方面问题相关的开销会变得非常显著（更不用说所有线程都受限于只能在单个 CPU 上运行）。为了解决这个问题，最好将此类类应用程序重构为异步事件处理系统。例如，一个中心事件循环可以使用 `select` 模块监控所有的 I/O 事件，并将异步事件分发给大量的处理器句集。这是库模块以及流行的第三方模块（如 Twisted (`{twisted/matrix`)）的基础。

展望未来，消息传递（message passing）可能是你在 Python 任何并发编程中都应该采纳的概念。在处理线程时，一种通常推荐的方法是将应用程序结构化为独立线程的集合，通过消息队列交换数据。这种方法往往不容易出错，因为它很大程度上减少了对锁和同步原语的需求。消息传递自然地扩展到了网络和分布式系统。例如，如果程序的某部分最初在一个你发送消息的线程上启动，随后可以通过网络连接发送消息，将组件迁移到单独进程或不同的机器上。消息传递还与 Python 的高级特性（如协程）紧密相关。例如，协程是一个可以接收并处理发送给它的消息的函数。因此，通过采用消息传递，你会发现你可以编写出具有高度灵活性的程序。

本章的剩余部分将介绍支持当前编程的库模块。在最后，提供了更多关于常见编程习惯的详细信息。

# multiprocessing

`multiprocessing` 模块提供了在子进程中启动任务、通信和共享数据以及执行各种形式同步的支持。其编程接口旨在模仿 `threading` 模块中线程的编程接口。然而与线程不同，必须强调的是进程没有任何共享状态。因此，如果一个进程修改了数据，该更改仅对该进程有效。

`multiprocessing` 模块的特性非常丰富，使其成为最大且最先进的内置库之一。在这里不可能涵盖该模块的每一个细节，但将给出核心部分以及示例。经验丰富的程序员应该能够利用这些示例并将其扩展到更大的问题上。

# Processes

`multiprocessing` 模块的所有特性都聚焦于进程。它们通过以下类进行描述。

## Process([group [, target [, name [, args [, kwargs]]]]]])

一个表示子进程中任务的类。构造函数应始终使用关键字参数指定。`target` 是在进程启动时执行的可调用对象，`args` 是传递给 `target` 的参数元组，而 `kwargs` 是传递给 `target` 的关键字参数字典。如果省略了 `args` 和 `kwargs`，则不带参数调用 `target`。`name` 是一个给进程提供描述性名称的字符串。`group` 未使用且始终被设置为 `None`。它的存在是为了让 `Process` 的构造模仿 `threading` 模块中线程的创建。

`Process` 实例具有以下方法：

```python
p.is_alive()
```

如果 p 仍在运行，则返回 `True`。

```python
p.join([timeout])
```

等待进程终止。`timeout` 指定了一个可选的超时时间。你可以根据意愿多次 `join` 一个进程，但进程尝试加入自身是一个错误。

```python
p.run()
```
