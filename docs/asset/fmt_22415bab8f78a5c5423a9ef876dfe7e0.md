
1. 检查客户端主机名是否与`hosts.equiv`和`shosts.equiv`文件匹配。如果主机具有条目，并且客户端和服务器的用户名相同，用户即可在无密码情况下登录。必须启用`RhostsAuthentication`选项。这是最不安全的方法，因为它依赖于`hosts.equiv`和`shosts.equiv`文件。

2. 主要的身份验证方法使用`.rohosts`、`.shosts`、`hosts_equiv`和`shosts_equiv`，以及基于RSA的主机身份验证。系统会检查主机文件，如果允许登录，服务器会从`/etc/ssh_known_hosts`和`~/.ssh/known_hosts`检查客户端的主机密钥。这可以防止IP、DNS和路由欺骗。欺骗是指另一台主机伪装成受信任的系统。这种方法仍然依赖于稍显不安全的主机文件。为此方法必须启用`RhostsRSAAuthentication`选项。

3. 第三种身份验证方法使用基于RSA的公钥密码学进行身份验证。用户的公钥存储在远程系统的`~/.ssh/authorized_keys`文件中。当用户连接时，客户端SSH告诉服务器它希望使用哪一对密钥进行身份验证。然后服务器检查该密钥是否被允许，如果是，它向客户端SSH进程发送一个挑战，这是一个用用户公钥加密的随机数。这个挑战只能使用正确的私钥解密。这种方法是最安全的，因为它使用了一种成熟的机制，并且私钥从未被泄露。

### 版本 2 身份验证方法

标准的SSH v2身份验证方法与v1的第三种方法类似。它不使用单纯的RSA，而是使用DSA（数字签名算法）或RSA。客户端使用`~/.ssh/id_dsa`文件而不是`~/.ssh/identity`。服务器使用`~/.ssh/authorized_keys2`而不是`~/.ssh/authorized_keys`。

如果标准方法失败，可以发送加密密码到远程系统以证明用户身份。

### 使用 SSH 文件

SSH使用几个文件来存储密钥和信息。它们如表 17-4 所示。默认情况下，当使用SSH连接到远程系统时，你会被提示输入密码，但为了提高安全性，你可以使用公钥密码学。

简而言之，公钥密码学为传统加密中最常见的问题提供了解决方案。在传统加密中，通常称为对称加密，消息的发送者和接收者都使用相同的加密密钥。密钥是用于加密和解密消息的一段数据。如果第三方得知这个共享密钥，他们就可以解密机密消息，也可以加密自己的消息以冒充受信任的参与者之一。公钥密码学通过为每个人提供两个密钥来解决这个问题。第一个密钥称为公钥。它的目的是发布给全世界，用于加密发送给用户的任何消息。分配的第二个密钥是私钥。此密钥必须保密，且只能由其发放者知道。它可以解密用匹配的公钥加密的消息。这样，你就可以分发你的公钥，让人们给你加密消息，而不会泄露也用来解密这些消息的密钥。

#### SSH 文件

| 文件 | 功能 |
| :--- | :--- |
| `~/.ssh/known_hosts` | 当用户登录到远程服务器时，服务器会发送一个密钥。这些密钥存储在此文件中。如果用户后来从服务器收到的密钥与此处记录的密钥不同，系统会显示一条警告消息，提示可能有人在冒充该远程服务器。 |
| `~/.ssh/identity` 或 `~/.ssh/id_dsa` | 包含用户的RSA和DSA私钥信息。此信息应仅对用户可读。如果其他人获取了这些文件中的信息，他/她就可以冒充该用户。 |
| `~/.ssh/identity.pub` 或 `~/.ssh/id_dsa.pub` | 包含用户的公钥信息。 |
| `~/.ssh/config` | `ssh`客户端的配置文件，可以覆盖系统级配置文件中的某些设置。 |
| `~/.ssh/authorized_keys` | 列出了可用于以该用户身份登录的RSA密钥。 |
| `~/.ssh/authorized_keys2` | 列出了可用于以该用户身份登录的公钥（DSA/RSA）。 |
| `/etc/ssh_known_hosts` 或 `/etc/ssh_known_hosts2` | 类似于用户的已知主机列表。管理员可以配置此文件，以便使用中心化的已知密钥库作为防止欺骗的措施。`/etc/ssh_known_hosts`包含RSA密钥，`/etc/ssh_known_hosts2`包含协议版本 2 的DSA或RSA密钥。 |
| `/etc/ssh_config` | 系统级`ssh`客户端配置文件。 |
| `/etc/sshd_config` | 系统级`ssh`服务器配置文件。 |
| `~/.rhosts` | 用于`.rhosts`身份验证，列出允许登录的主机/用户配对。此文件是从伯克利`r`命令继承而来的，而SSH替代了这些命令。如果您的系统不使用旧的`r`命令，您应该使用`.shosts`文件。 |
| `~/.shosts` | 用法与`.rhosts`完全相同。创建此文件的目的是允许使用`.rhosts`身份验证通过SSH登录，同时禁止使用`rlogin`或`rsh`登录。 |
| `/etc/hosts.equiv` | 在rhosts身份验证期间使用。它包含规范的主机名，每行一个。这是从伯克利r命令继承而来的另一项内容。如果您的系统不使用它们，您应该使用`shosts.equiv`文件。 |
| `/etc/shosts.equiv` | 处理方式与`/etc/hosts.equiv`完全相同。此文件可能很有用，因为它允许使用SSH登录，但禁止使用`rsh`或`rlogin`。 |
| `/etc/sshrd` | 此文件中的命令由SSH在用户登录后、用户的shell（或命令）启动前执行。这是一个系统级配置文件。 |
| `~/.sshrd` | 此文件中的命令由SSH在用户登录后、用户的shell（或命令）启动前执行。 |
| `~/.ssh/environment` | 包含环境变量的附加定义。 |

### 配置 SSH 服务器

SSH服务器由`sshd`守护进程组成。它使用`sshd_config`文件进行配置，该文件通常存储在`/etc/ssh`中。以下是`sshd_config`文件的一部分：

```
Port 22
#Protocol 2,1
ListenAddress 0.0.0.0
#ListenAddress ::
HostKey /etc/ssh/ssh_host_key
ServerKeyBits 768
LoginGraceTime 600
KeyRegenerationInterval 3600
PermitRootLogin yes
#
# Don't read ~/.rhosts and ~/.shosts files
IgnoreRhosts yes
# Uncomment if you don't trust ~/.ssh/known_hosts for
RhostsRSAAuthentication
#IgnoreUserKnownHosts yes
StrictModes yes
X11Forwarding no
X11DisplayOffset 10
PrintMotd yes
KeepAlive yes
```

格式非常简单：每一行都有一个条目和一个值。可能的条目列在表 17-5 中。

#### 表 17-5

#### sshd_config 条目

| 条目 | 功能 | 默认值 |
| :--- | :--- | :--- |
| `AFSTokenPassing` `<yes\|no>` | 指定是否允许将AFS令牌转发到服务器。AFS是一种有时与Kerberos安全系统一起使用的文件服务。 | Yes |
| `AllowGroups` `<group name>` | 仅允许列在此条目中的组登录。 | 允许任何组登录。 |
| `AllowTcpForwarding` `<yes\|no>` | 启用或禁用TCP流量转发。 | Yes |
| `AllowUsers` `<user list>` | 将登录限制为特定的用户名。 | 允许任何用户登录。 |
| `Ciphers` `<cipher list>` | 指定用于SSH协议v2的加密算法（或加密算法列表）。 | 3des-cbc, blowfish-cbc, arcfour, cast128-cbc |
| `CheckMail` `<yes\|no>` | 启用或禁用用户登录时的邮件检查。 | No |
| `DenyGroups` `<group list>` | 列出不允许通过SSH登录的组。 | 允许任何组登录。 |
| `DenyUsers` `<user list>` | 列出不允许通过SSH登录的用户。 | 允许任何用户登录。 |
