### 2.1.4 标准 I/O

C 库提供了标准输入和输出流（分别为 `stdin` 和 `stdout`）。这些流用于 `scanf`、`printf` 和其他库函数。在 UNIX 传统中，标准输入输出的使用是 GNU/Linux 程序的惯例。这允许使用 shell 管道以及输入输出重定向来链接多个程序。

C 库提供了 `stderr` 标准错误流。程序应该打印警告和错误消息，而不是标准输出。这允许用户分离正常输入和错误消息，例如，通过将标准输出重定向到文件，同时允许标准错误打印在控制台上。`printf` 函数可以用于打印到 `stderr`，例如：

```c
fprintf(stderr, "Error: ...");
```

这些流也可以通过文件描述符使用 UNIX I/O 命令（`read`、`write` 等）进行访问。这些文件描述符分别是 `stdin` 为 0，`stdout` 为 1，`stderr` 为 2。

在调用程序时，有时将标准输出和标准错误都重定向到文件或管道是有用的。这种语法在所有 shell 中都不同；对于 Bourne 风格的 shell（包括 `bash`，GNU/Linux 发行版上的默认 shell），语法为：

```bash
% program output_file.txt 2>&1
% program 2>&1 | filter
```

`2>&1` 语法表示文件描述符 2 (`stderr`) 应合并到文件描述符 1 (`stdout`)。注意，`2>&1` 必须在文件重定向（第一个示例）之后但在管道重定向（第二个示例）之前。

注意 `stdout` 是缓冲的。写入 `stdout` 的数据在缓冲区填充、程序正常执行或 `stdout` 关闭之前不会发送到控制台（或其他设备，如果已重定向）。你可以通过调用以下函数显式地刷新缓冲区：

```c
fflush(stdout);
```

相比之下，`stderr` 不是缓冲的；写入 `stderr` 的数据直接进入控制台。

这可能会产生一些令人惊讶的结果。例如，这个循环并不会每秒打印一个点；相反，点被缓冲了，当缓冲区填充时会将多个点一起打印。

```c
while (1) {
    printf(".*");
    sleep(1);
}
```

但在该循环中，点确实每秒出现一次：

```c
while (1) {
    fprintf(stderr, ".*");
    sleep(1);
}
```

#### 2.1.7 使用临时文件

有时，程序需要创建一个临时文件，用于临时存储大量数据，或将数据传递给另一个程序。在 GNU/Linux 系统上，临时文件存储在 `/tmp` 目录中。使用临时文件时，你应该注意以下陷阱：

- 你的程序可能同时运行（由同一用户或不同用户运行）。这些实例应该使用不同的文件名以防止发生冲突。
- 临时文件的权限设置应当确保未经授权的用户无法通过修改或替换临时文件来改变程序的执行。
- 临时文件名的生成方式不应该是可以从外部预判的；否则，攻击者可以利用测试给定名称是否已在使用与打开新临时文件之间的延迟进行攻击。

GNU/Linux 提供了 `mkstemp` 和 `tmpfile` 函数，它们可以为你处理这些问题。你依赖于哪一个，取决于你是否计划将临时文件交给另一个程序，以及你是想使用 UNIX I/O（`open`、`write` 等）还是 C 库的流式 I/O 函数（`fopen`、`fprintf` 等）。

#### 使用 mkstemp

`mkstemp` 根据文件名模板创建一个唯一的文件名，以特定的权限创建该文件（使得只有当前用户可以访问），并打开该文件进行读写。文件名模板是一个以 `"XXXXXX"`（六个大写 X）结尾的字符字符串；`mkstemp` 会用字符替换这些 X，使文件名是唯一的。返回值是一个文件描述符；使用 `write` 系列函数向临时文件写入数据。

用 `mkstemp` 创建的临时文件不会自动删除。你需要在不再需要时手动删除该临时文件。如果临时文件仅供内部使用且不再需要，那么立即对临时文件调用 `unlink` 是一个好主意。`unlink` 函数删除与文件对应的目录项，但由于文件系统中的文件是引用计数的，在没有针对该文件的打开的文件描述符之前，文件本身不会被删除。这样，你的程序可以继续使用该临时文件，一旦你关闭文件描述符，文件就会消失。由于 Linux 在程序结束时会关闭文件描述符，即使程序终止，临时文件也会被删除。
