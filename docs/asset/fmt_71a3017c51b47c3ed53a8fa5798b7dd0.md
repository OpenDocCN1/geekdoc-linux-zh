
由于 Ultra 的部分看起来像 8013，因此 Ultra 应该在 `wd8013` 探测程序有机会误识别它之前被找到。

Donald 提到，可以为 Ultra 的“Altego”模式更改链传输器编写单独的驱动程序，代价是接收缓冲器的使用效率低下，但这可能不会发生。

**总线主控 SCSI 热插适配器注意**：在与 Interactive UNIX 共享的手书中，提到 SMC Ultra 的一个错误会导致从 `aha-154X` 热插适配器运行的 SCSI 磁盘时出现数据损坏。这也会影响 BusLogic 主板以及 AMI-FastDisk SCSI 热插适配器。

SMC 已确认该问题在 Interactive 和旧版本的 Windows NT 驱动中存在。这是网卡早期的硬件冲突，可以通过驱动程序进行规避。目前的 Ultra 驱动通过仅在向网卡传输数据时启用共享内存来保护此。确保内核版本至少为 `1.1.84`，或者启动时报告的驱动程序版本至少为 `smc-ultra.vi12`，否则你将面临风险。

如果你将此驱动程序作为加载模块使用，你可能会看到 `Using the Ethernet Drivers as Modules` 以获取模块特定信息。

# SMC Elite Ultra32 EISA

状态：已支持，驱动程序名称：`smc–ultra32` (+8390)

此 EISA 卡与其 ISA 对应版本有许多共同点。v2.0 和 v2.2 内核均包含可工作（稳定的）驱动程序。感谢 Leonard Zuboff 购买了其中一些显卡，以便为它们添加 Linux 支持。

# SMC EtherEZ (8416)

状态：已支持，驱动程序名称：`smc–ultra` (+8390)

此卡使用 SMC 的 83c795 芯片并支持 PnP 规范。它还有一个与 SMC Ultra 兼容的模式，允许它与 Linux Ultra 驱动配合使用。为了获得最佳效果，请使用 SMC 程序（来自我们的 `/wftp` 站点）禁用 PnP 并将其配置为共享内存模式。请见上方关于 Ultra 驱动的说明。

对于 v1.2 内核，卡必须配置为共享内存操作。v2.0 内核可以使用共享内存或程序化 IO 模式。共享内存模式会快一点，且使用的 CPU 资源更少。

# SMC EtherPower PCI (8432)

状态：已支持，驱动程序名称：`de4x5`, `tulip`

注意：EtherPower II 是完全完全不同的卡。见下文！这些卡是 DEC 21040 的实现，即一个大芯片和几个收发器。Donald 使用了这些卡之一开发了他的通用 2140 驱动（作为 `tulip.c`）。再次感谢 Duke Kamstra 提供了一块卡用于开发。

此卡的某些后续修订版本使用了较新的 DEC 21041 芯片，这可能会导致旧版本的 `tulip` 驱动出现问题。如果你遇到问题，请确保你使用的是最新的驱动程序版本，该版本可能未包含在内核源码树中。

有关使用此类卡的详情以及驱动程序的当前状态，请参见 DEC 21040。

显然，卡的最新修订版 EtherPower-II 使用 9432 芯片。不清楚它是否能与目前的驱动程序配合。同样不确定，在购买网卡之前检查如果它无法与 Linux 驱动工作是否可以退货。
