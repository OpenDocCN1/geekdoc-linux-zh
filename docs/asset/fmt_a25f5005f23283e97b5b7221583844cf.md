## 窗口系统

### X 特性

意识到 X 服务器与 X 客户端应用程序之间的区别至关重要。X 服务器直接控制显示器，并通过键盘、鼠标和显示器负责所有的输入输出。而 X 客户端并不访问输入输出设备。它与处理输入输出的 X 服务器通信。真正的工作是由 X 客户端完成的，例如计算值、运行应用程序等。X 服务器仅为客户端打开窗口以处理其输入输出。

在正常操作（图形界面）下，每个 Linux 工作站都是一个提供服务的 X 服务器，即使它只运行客户端。你运行的所有应用程序（例如 Gimp、终端窗口、你的浏览器、办公软件、你的 CD 播放工具等）都是你 X 服务器的客户端。在这种情况下，服务器和客户端在同一台机器上运行。

X 系统的客户端/服务器本质使其成为应用程序和程序远程执行的理想环境。因为进程实际上在远程机器上执行，因此本地主机需要的 CPU 功率非常小。这种纯作为 X 服务器的方案被称为“终端”（terminals），曾经非常流行。更多信息可以在 [Remote X-applications mini-HOWTO](http://www.tldp.org/HOWTO/Remote-X-Apps.html) 中找到。

### Telnet 和 X

如果你想使用 telnet 显示运行在远程机器上的图形应用程序，首先需要使用 `xhost` 命令获取对显示器（你的 X 服务器！）的远程访问，可以在本地机器的终端窗口中输入类似下面的命令：

```
davy:~> xhost +remote.machine.com
```

之后，连接到远程主机并通过设置环境变量 `DISPLAY` 让其在本地机器上显示图形：

```
$ davy@remote ~ export DISPLAY="local.host.com:0.0"
```

完成此步骤后，在该终端窗口中启动的任何应用程序将在你的本地机器上显示。

## SSH 套件

### 简介

SSH 为不安全的 `rsh` 和 `telnet` 提供了一个安全的替代方案。对于常规的远程命令执行，建议使用 Secure Shell 或 `ssh`。我们将在本节的稍后部分讨论这种安全方法。

### X server

此过程假设在您想要从远程主机显示应用程序的客户端上，运行着一个运行中的 X server。客户端的架构和操作系统可能与远程主机不同，只要它能够运行 X server，例如 Cygwin（它为 Windows 客户端和其他系统实现了 X.org server）或 Exceed，就能够与任何 Linux 或 UNIX 机器建立远程连接。

### 安全身份验证

`ssh` 客户端/服务器系统会自动维护并检查一个包含其曾经使用过的所有主机标识符的数据库。主机密钥存储在用户主目录下的 `~/.ssh/known_hosts` 中。此外，系统会自动检查 `/etc/ssh/known_hosts` 文件以获取已知主机。新主机会自动添加到用户文件中。如果某个主机的标识符发生变化，`ssh` 会对此发出警告并禁用密码身份验证，以防止特马程序获取用户密码。该机制的另一个目的是防止中间人攻击，否则由于此类攻击可能被用于绕过加密。在需要高安全性的环境中，可以配置 `sshd` 以阻止主机密钥已更改或未知的节点进行登录。

### 安全远程复制

SSH 套件中的 `scp` 曾作为 `rcp` 命令的安全替代方案在仅存在 `rcp` 的时代流行。`scp` 使用 `ssh` 进行数据传输，使用相同的身份验证并提供与 `ssh` 相同的安全性。像 `rcp` 一样，如果身份验证需要，它会要求输入密码或短语：

```
lenny /var/tmp scp Schedule.sdc.gz blob:/var/tmp/
lenny@blob's password:
Schedule.sdc.gz 100% |************************************| 100 KB 00:00
```

```
lenny /var/tmp
```

任何文件都可以包含主机和用户指定，以指示该文件应从从该主机复制。允许两个远程主机之间的复制。更多信息请参见 Info 页面。

如果您更倾向于类似 FTP 的界面，请使用 `sftp`：

```
lenny /var/tmp sftp blob
Connecting to blob...
lenny@blob's password:
```

```
sftp cd /var/tmp
sftp get Sch*
Fetching /var/tmp/Schedule.sdc.gz to Schedule.sdc.gz
sftp bye
```

```
lenny /var/tmp>
```

### 安全复制或 FTP GUI

还对命令行还不够熟悉吗？尝试 Konqueror 的安全远程复制功能，或使用 Putty。

## 网络

### 身份验证密钥

`ssh-keygen` 命令生成、管理和转换 `ssh` 的身份验证密钥。它可以创建用于 SSH 协议版本 1 的 RSA 密钥，以及用于 SSH 协议版本 2 的 RSA 或 DSA 密钥。

通常，每个想要使用 RSA 或 DSA 身份验证使用 SSH 的用户都会运行一次以在 `$HOME/.ssh/identity_id_dsa` 或 `id_rsa` 中创建身份验证密钥。此外，系统管理员可以使用此为系统生成主机密钥。

通常，此程序会生成密钥并请求一个存储私钥的文件。公钥存储在同名但带有 `.pub` 后缀的文件中。程序还会询问短语。短语可以为空以表示无短语（主机密钥必须有短语），也可以是任意长度的字符串。

丢失的短语无法找回。如果丢失或忘记短语，则必须生成新密钥并复制到相应的公钥中。

我们将在练习中学习 SSH 密钥。所有信息均可在 `man` 或 Info 页面中找到。

### VNC

VNC 或虚拟网络计算（Virtual Network Computing）实际上是一种远程显示系统，允许查看并非运行在本地机器上的桌面环境，而是可以从互联网的任何地方以及各种机器和架构（包括 MS 和几个 Unix 发行版）。你可以在 Windows NT 机器上运行 MS Word，并将输出显示在你的 Linux 面上。VNC 提供了服务器和客户端，因此反之也可行，并用于在 PC 上建立连接。以下功能使得 VNC 与商业实现中的普通服务器或 X 不同：

- 服务器端不存储状态：你可以离开座位并在另一台机器上恢复，从离开的地方继续。当你运行 PC 服务器时，如果 PC 崩溃或重启，你运行的所有应用程序都会停止。而使用 VNC，它们会继续运行。
- 简单直接，无需安装，需要时可以从软盘运行。
- 使用 Java 客户端，平台无关，运行在所有支持 X 的设备上。
- 可共享：一个桌面可以在多个查看器上显示。

更多可以在 VNC 客户端页面（`man vncviewer`）或 VNC 网站 [http://www.realvnc.com/] 上找到。

- 免费。

### 桌面协议

为了方便管理 Windows主机，最近的 Linux 发行版支持远程桌面协议（RDP），该协议在 `rdesktop` 客户端中实现。该协议用于多个微软产品，包括 Windows NT Terminal Server、Windows 2000 Server、Windows XP 和 Windows 2003 Server。

用全屏模式、多类型键盘布局和单应用程序模式让你的朋友（或管理层）惊喜，就像真实的一样。`man rdesktop` 手册提供了更多信息。该项目的主页地址为 http://www.rdesktop.org。

经验法是，如果你不认识某个服务，你可能根本不需要它。还要记住，某些服务并不是真的为了在互联网上使用的。
