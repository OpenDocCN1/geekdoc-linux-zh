## 操控键盘编码

`KeyCode`（键码）代表物理（或逻辑）按键。`KeyCode` 位于 `[0,255]` 闭区间范围内。然而，`KeyCode` 值不包含任何内在信息，但实现者可能会以某种方式编码几何（例如矩阵）信息，以便以取决于服务器的方式进行解释。按键与 `KeyCode` 之间的映射无法更改。

`KeySym`（键符号）是按键上符号的编码。定义的 Keys 集合包括 ISO 拉丁字符集（1-4）、片假名、阿拉伯语、西里尔语、希腊语、技术、出版、希伯来语、泰语、韩语以及键盘上发现的一长串按键（Return、Help、Tab 等）。在很大程度上，这些集合源于国际标准。在没有标准的领域，这些集合源于数字设备（Digital Equipment）标准定义的符号列表可以在 `<X1/keysymdef.h>` 中找到。遗憾的是，某些处理器限制了定义符号的数量。如果你使用了不在 Latin 1-4 和杂类中的 `KeySyms`，那么你的应用程序可能只使用 `<X1/keysym.h>`，该文件定义了 ISO Latin-4、希腊语和杂类的符号。

每个 `KeyCode` 都关联一个 `KeySyms` 列表。该列表旨在传达对应按键上的符号集。如果列表（忽略 `NoSym` 条目）是单个 `KeySym` `'K1'`，则它被处理为 `'KeySym NoSym 'K1''`。如果列表（忽略 `NoSym` 条目）是一对 `KeySym` `'K1' 'K2'`，则该列表被处理为 `'KeySym NoSym 'K1' 'K2''`。如果列表（忽略 `NoSym` 条目）是三元组 `KeySym` `'K1' 'K2' 'K3'`，则该列表被处理为 `'KeySym NoSym 'K1' 'K2' 'K3''`。当列表中需要显式的 `'void'` 时，可以使用 `Void KeySym`。

列表的前四个元素被分成两组。组 1 包含第一个和第二个 `KeySym`；组 2 包含第三和第四个 `KeySym`。在每个组内，如果组的第二个元素是 `NoSym`，则该组应被处理为第二个元素与第一个元素相同，除非第一个元素是字母 `KeySym` `'K'`，且该 `KeySym` 同时定义了小写和大写形式。在这种情况下，该组应被处理为第一个元素是 ``K`` 的小写形式，第二个元素是 ``K`` 的大写形式。

## 输入设备函数

从 `KeyPress` 事件中附加 `KeySym` 的标准规则利用组 1 和组 2 `KeySym`；未给出列表中其他 `KeySym` 的解释。根据修饰符状态确定使用哪个按键。组与组之间的切换由名为 `MODE SWITCH` 的 `KeySym` 控制，方法通过将该 `KeySym` 附加到某些 `KeyCode`，并将该 `KeyCode` 附加到 `Mod1` 到 `Mod5` 的任何修饰符上来实现。此修饰符称为组修饰符。对于任何 `KeyCode`，当组修饰符关闭时使用组 1，当组修饰符开启时使用组 2。

当名为 `XK Caps` 的 `KeySym` 附加到某些 `KeyCode` 且该 `KeyCode` 附加到 `Lock` 修饰符时，`Lock` 修饰符被解释为 `CapsLock`。当名为 `XKShift_Lock` 的 `KeySym` 附加到某些 `KeyCode` 且该 `KeyCode` 附加到 `Lock` 修饰符时，`Lock` 修饰符被解释为 `ShiftLock`。如果 `Lock` 修饰符可以同时解释为 `CapsLock` 和 `ShiftLock`，则使用 `CapsLock` 解析。

数字键盘的操作由名为 `XK Num` 的 `KeySym` 控制，通过将 `KeySym` 附加到某些 `KeyCode` 并将该 `KeyCode` 附加到 `Mod1` 到 `Mod5` 的任何修饰符来实现。此修饰符称为 `numlock` 修饰符。带有 ``XK`` 前缀的标准 `KeySyms` 称为 `KeySym`；但在十六进制范围 `0xFF80-0xFFFD`、`0x100000` 到 `0x10FFFF` 也是数字键盘 `KeySyms`。

在一个组内，`KeySym` 的选择通过应用以下列表中满足的第一条规则来决定：

- `numlock` 修饰符开启且第二个 `KeySym` 是数字键盘 `KeySym`。在这种情况下，如果 `Shift` 修饰符开启，或者 `Lock` 修饰符开启且被解释为 `ShiftLock`，则使用第一个 `KeySym`，否则使用第二个 `KeySym`。
- `Shift` 和 `Lock` 修饰符均关闭。在这种情况下，使用第一个 `KeySym`。
- `Shift` 修饰符关闭，且 `Lock` 修饰符开启并被解释为 `CapsLock`。在这种情况下，使用第一个 `KeySym`，但如果该 `KeySym` 是小写字母，则使用对应的大写 `KeySym`。
- `Shift` 修饰符开启，且 `Lock` 修饰符开启并被解释为字母，使用对应的 `KeySym`，但如果该 `KeySym` 是小写字母，则使用对应的大写 `KeySym`。
- `Shift` 修饰符关闭，且 `Lock` 修饰符开启并被解释为 `CapsLock`。在这种情况下，使用第一个 `KeySym`，但如果该 `KeySym` 是小写字母，则使用对应的大写 `KeySym`。
- `Shift` 修饰符关闭，且 `Lock` 修饰符开启并被解释为 `CapsLock`。在这种情况下，使用第一个 `KeySym`，但如果该 `KeySym` 是小写字母，则使用对应的大写 `KeySym`。
- `Shift` 修饰符关闭，且 `Lock` 修饰符开启并被解释为 `CapsLock`。在这种情况下，使用第一个 `KeySym`，但如果该 `KeySym` 是小写字母，则使用对应的大写 `KeySym`。

`max_keys_per_mod` 指定 `map` 中预分配给修饰符的 `KeyCode` 条目数量。

`XModifiermap` 函数返回一个指向 `XModifierKeymap` 结构的指针，供以后使用。

要向 `XModifierKeymap` 结构添加新条目，请使用 `XInsertModifiermapEntry`。

```
XModifierKeymap *XInsertModifiermapEntry(modmap, keycode_entry, modifier);
```

`modmap` 指定 `XModifierKeymap` 结构。

`keycode_entry` 指定 `KeyCode`。

`modifier` 指定修饰符。

`XInsertModifiermapEntry` 函数将指定的 `KeyCode` 添加到控制指定修饰符的结构中，并返回生成的 `XModifierKeymap` 结构（根据需要扩展）。

要从 `XModifierKeymap` 结构中删除条目，请使用 `XDeleteModifiermapEntry`。

```
XModifierKeymap *XDeleteModifiermapEntry(modmap, keycode_entry, modifier);
```

`modmap` 指定 `XModifierKeymap` 结构。

`keycode_entry` 指定 `KeyCode`。

`modifier` 指定修饰符。

`XDeleteModifiermapEntry` 函数从控制指定修饰符的集合删除指定的 `KeyCode`，并返回指向生成的 `XModifierKeymap` 结构的指针。

要销毁 `XModifierKeymap` 结构，请使用 `XFreeModifiermap`。

```
XFreeModifiermap(modmap);
```

`modmap` 指定 `XModifierKeymap` 结构。

`XFreeModifiermap` 函数释放指定的 `XModifierKeymap` 结构。

要设置用作修饰符的键，请使用 `XSetModifierMapping`。

```
int XSetModifierMapping(display, modmap);
```
