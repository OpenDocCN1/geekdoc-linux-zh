# `nisrmdir` — 删除 NIS+ 目录

### 概要

```
/usr/bin/nisrmdir [-s hostname] dirname
```

## 描述

使用 `nisrmdir` 命令删除现有的 NIS+ 子目录。你可以直接删除目录，也可以简单地从某个目录中移除副本。此命令会修改描述目录 `dirname` 的对象，并通知每个副本移除目录 `dirname`。如果任何受影响的副本通知失败，除非你指定了 `-f` 选项，否则目录对象将恢复到原始状态。
如果 NIS+ 主服务器未运行，此命令将失败。

## 选项

- `-f`

强制命令成功，即使它可能无法联系受影响的副本。当已知副本已禁用且无法响应移除通知时，请使用此选项。当副本最终重启时，它会读取更新后的目录对象，注意到它不再是该目录的副本，并停止对该目录的查询响应。你可以通过删除 `/var/nis` 目录中的相应文件来手动清理现已删除目录的文件（更多信息请参见 `nisfiles(4)`）。

- `-i`

类似于系统 `rm(1)` 命令，在删除目录之前交互式地请求确认。如果由 `dirname` 指定的名称不是完全限定名，则强制开启此选项。此选项可以防止删除意外的目录。

- `-s hostname`

将主机名 `hostname` 作为目录 `dirname` 的副本移除。如果不存在此选项，则移除该目录的所有副本和主服务器，并从命名空间中移除该目录。

## 示例

以下示例删除了 `foo.com` 域下的 `bar` 目录。

```
castle% nisrmdir bar.foo.com.
```

以下示例删除了正在提供 `bar.foo.com.` 服务的副本。

```
castle% nisrmdir -s replica.foo.com bar.foo.com.
```

以下示例强制从命名空间中移除 `bar.foo.com.` 目录。

```
castle% nisrmdir -f bar.foo.com.
```

# `nistblad` — 管理 NIS+ 表

### 概要

```
/usr/bin/nistblad -a [-D defaults] colname=value... tablename
/usr/bin/nistblad -a -A [-D defaults] indexname
/usr/bin/nistblad -c [-D defaults] [-p path][-s sep] type colname=[flags, access...] tablename
/usr/bin/nistblad -d tablename
/usr/bin/nistblad -el -E colname=value... indexname
/usr/bin/nistblad -m colname=value... indexname
/usr/bin/nistblad -r -R [colname=value...] tablename
/usr/bin/nistblad -r|-R indexname
/usr/bin/nistblad -u [-p path][-s sep] -t type [colname=access...] ablename
```

## 描述

使用 `nistblad` 命令管理 NIS+ 表。它执行五项主要操作：

- 创建表。
- 删除表。
- 向表中添加条目。
- 修改表内的条目。
- 从表中移除条目。

尽管 NIS+ 对表或条目的大小没有限制，但数据的大小会对 NIS+ 服务器的性能和磁盘空间产生影响。NIS+ 并不是为了文件等巨大数据设计的。

NIS+ 的设计优化为支持总大小为 10 兆字节的 10,000 个对象。如果需求超过上述，建议你创建数据层次结构，或在表中存储指向数据的指针，而不是存储数据本身。

## `nistblack`

在创建表时，你必须指定表类型、`type` 以及列定义列表。

`type` 是存储在表中的字符串，稍后由服务用于验证添加的条目类型是否正确。列定义使用以下语法。

```
colname=[flags], access]
```

`flags` 是以下内容的组合：

- `S` 可以对列的值进行搜索（参见 `nmatch(I)`）。
- `I` 搜索忽略大小写（仅与 `S` 结合时有意义）。
- `C` 加密列值。
- `B` 二进制数据（仅与 `S` 结合时有意义）。
- `X` 编码数据（与 `B` 结合有意义）。

`access` 按照 `nismod(1)` 命令定义的格式指定。在操作条目时，此命令有两种形式：

```
[colname=[flags], access]
```

## 选项

- `-a` `A` 向表中添加条目。小写 `a` 和大写 `A` 的区别在于对已存在条目的处理。大写 `A` 指定即使条目已存在也进行添加。

- `-c` 在命名空间中创建一个名为 `tablename` 的表。创建的表必须至少有一列，且至少有一列是可搜索的。

- `-d tablename` 销名为 `tablename` 的表。被销的表必须为空。先使用 `-R` 选项删除表的内容。

- `-e` `E` 编辑由 `indexname` 指定的条目。`indexname` 必须唯一标识一个条目。可以编辑更改条目索引名的列。

如果更改（`colname=value`）导致索引名与 `indexname` 不同并匹配另一个现有条目，可能会影响表中的其他条目。在这种情况下，`e` 选项将失败并报错。`.E` 选项强制替换现有条目（相当于移除两个条目并添加一个新的）。

- `-D defaults` 在创建对象时，指定一组不同的默认值。默认字符串是一系列由冒号分隔的令牌。这些令牌代表用于通用对象的默认值。所有合法的令牌见下文描述。

- `ttl=time` 为此命令创建的对象设置默认生存时间（TTL）。指定 `nisl(1)` 命令定义的格式。默认值为 12 小时。

- `owner=ownername` 指定 NIS+ 实体 `ownername` 拥有创建的对象。通常，此值与执行命令的实体相同。

- `group=groupname` 指定组 `groupname` 为创建对象的组所有者。默认值为 `null`。

- `access=rights` 指定授予给定对象的访问权限集。按照 `nischmod(1)` 命令定义的格式指定权限值。默认值为 `---rmcdr---r---`。

- `-p path` 创建或更新表时，指定表的搜索路径。当你调用 `nis_list()` 函数时，可以指定 `FOLLOW_PATH` 标志，如果使用的搜索标准没有产生任何条目，则在表的路径中继续搜索。路径由有序的表名列表组成，用冒号分隔。路径中的名称必须是完全限定的。

- `-s sep` 在创建或更新表格时，请指定表的分隔符。`niscat(1)` 在标准输出上显示表格时会使用该分隔符。它的作用是在表格以 ASCII 格式存在时指定列数据。默认值为空格。

从表中删除条目。通过命令行上的一系列 `column=value` 对或指定作为 `entryname` 的索引名称来指定该条目。小写 `r` 和大写 `R` 的解释区别在于对非唯一条目规格的处理。通常情况下，如果为条目指定的搜索标准在表中解析出多个条目，NIS+ 服务器将不允许尝试删除条目。然而，你有时可以删除多个，例如，当你尝试删除表中的所有条目时。在这种情况下，使用大写 `R` 会强制 NIS+ 服务器删除所有匹配通过搜索标准的条目。如果该标准为空且未指定列值，则表中的所有条目都将被删除。

- `-r |R`

在更新表格属性时，请指定表的类型字符串。此选项允许更改表的连接字符（`-`）、分离访问权限和表字符串（`-t`）。列数或可搜索的列都无法更改。

- `-t type`

- `-u`
