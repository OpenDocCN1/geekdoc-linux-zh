> 从其他平台迁移的人有时会陷入“Linux 下软件安装困难”的神话中，认为不同发行版的软件包方案是一种障碍。好吧，这确实是一种障碍，但对于那些想要分发纯二进制版本的秘密软件供应商来说如此。

# 挂载和卸载存储设备

Linux 桌面系统的最新进展使得存储设备管理对于桌面用户来说变得轻而易举。在大多数情况下，我们只需将设备连接到系统，它就能“开箱即用”。在过去（例如 2004 年），这必须手动完成。在非桌面系统（即服务器）上，这在很大程度上仍然手动过程，因为服务器通常有极高的存储需求和复杂的配置要求。

管理存储设备的第一步是将设备挂载到文件系统树上。这个过程被称为挂载（mounting），它允许设备与操作系统交互。正如我们在第 2 章中所回顾的，Unix 类操作系统（如 Linux）维护一个单一的文件系统树，设备挂载在不同的点。这与 Windows 等其他操作系统不同，Windows 为每个设备维护独立的文件系统树（例如 C:\D:\ 等）。

文件 `/etc/fstab`（意为“文件系统表”）列出了启动时挂载的设备（通常是硬硬盘分区）。以下是一个来自 Fedora 系统的 `/etc/fstab` 示例：

| LABEL=/12 | | ext4 | defaults | 1 1 |
| LABEL=/home | /home | ext4 | defaults | 1 2 |
| LABEL=/boot | | ext4 | defaults | 1 2 |
| tmpfs | /dev/shm | tmpfs | defaults | 0 0 |
| devpts | /dev/pts | devpts | gid=5,mode=620 | 0 0 |
| sysfs | /sys | sysfs | defaults | 0 0 |
| proc | /proc | proc | defaults | 0 0 |
| LABEL=SWAP-sda3 | swap | swap | defaults | 0 0 |

列出的文件系统大多是虚拟的，不适用于我们的讨论。对于我们的目的来说，有趣的是前三个。

| LABEL=/12 | | ext4 | defaults | 1 1 |
| LABEL=/home | /home | ext4 | defaults | 1 2 |
| LABEL=/boot | /boot | ext4 | defaults | 1 2 |

这些是硬盘分区。该文件的每行包含六个字段，如表 15-1 所示。

# 表 15-1：/etc/fstab 字段

| 字段 | 内容 | 说明 |
|---|---|---|
| 1 | 设备 | Traditional上，此字段包含与物理设备对应的设备文件名称，例如 `/dev/sda`（第一个检测到的硬盘的第一个分区）。对于今天的计算机，由于有许多热插拔设备（如 USB 驱动器），许多现代 Linux 发行版改为将设备与文本标签关联。此标签（在格式化存储介质时添加）可以是简单的文本标签，也可以是随机生成的 UUID（通用唯一标识符）。当设备连接到系统时，操作系统会读取该标签。这样，无论为实际物理设备分配哪个设备文件，它都能被正确识别。 |
| 挂载点 | 设备挂载到系统树的目录。 |
| 选项 | 大多数原生 Linux 文件系统是第四扩展文件系统 (ext4)，但也支持其他系统，例如 FAT16 (isdos)、FAT32 (vfat)、NTFS (ntfs)、CD-ROM (iso9960) 等。 | 文件系统可以使用各种选项挂载。例如，可以将文件系统挂载为只读，或防止任何程序从其中执行（针对可移动介质的安全功能）。 |
| 频率 | 一个数字，用于指定是否以及何时使用 `dump` 命令对文件系统进行备份。 |
| 顺序 | 一个数字，用于指定使用 `fsck` 命令检查文件系统的顺序。 |
