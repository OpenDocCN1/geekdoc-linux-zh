
每一行都是一条提供信息的记录，告诉 DNS 守护进程配置每一项。每行（或每个记录）必须以对配置过程具有意义的关键字开头。以下是每条记录作用的描述：

- 关键字 `directory`，第一条记录告诉 DNS 守护进程所有数据库文件的位置，即服务器文件系统中 `/etc/named` 目录。

- 第二、第三、第四和第五条记录以关键字 `primary` 开头，后跟域名。这显式地告诉服务器它对每个指定的域具有权威性，并以主服务器的身份运行。每条记录的最后一个字段指定包含指定域记录的文件。例如，通过读取第二条记录，`named` 初始化为 `harmonics.com` 域的主服务器，并将内存初始化为 `/etc/named/named.hosts` 文件的内容。

- 最后一条记录指定该服务器作为根域的缓存服务器。此外，它指定 `named.ca` 为（在 `/etc/named` 目录下的）包含缓存初始化数据的文件。

## 数据库文件名

正如本章前面提到的，数据库文件名可以是任何你喜欢的。回顾 `named.boot` 文件的内容，注意服务器如何通过解释每条记录的第一个字段来判断哪些文件构成了数据库。因此，你应该决定为 `named.hosts` 文件使用不同的名称；例如，你只需要在 `named.boot` 启动文件中将 `named.hosts` 替换为你确定的文件名即可。

以上内容结束了配置和启动 DNS 主服务器所需的步骤。现在让我们来看看如何设置从服务器。

## 配置从域名服务器

根据定义，从域名服务器是从主权威服务器获取关于其支持的区域相关数据的服务器。从服务器没有它自己的 `named.hosts` 类型文件和 `named.rev` 文件。相反，每当启动时，从服务器都会进行区域传输，在此期间，它请求主服务器传输两个文件的副本。因此，从服务器使用传输的内容初始化其内存以响应查询。

由于你需要创建并更新 `named.hosts` 和 `named.rev` 文件，配置从服务器变成了一个涉及三个文件的简单问题：`named.boot`、`named.ca` 和本地。为了方便起，请将这三个文件从主服务器复制到你打算启动从服务器的机器上。在我们的场景中，该单元需要作为从服务器运行时，必须将这三个文件复制到它的文件系统中。

在复制到作为从服务器的主机后，唯一需要少量修改的文件是 `named.boot`。以下是 `named.boot` 的可能样子：

```
directory /usr/lib/named

secondary      harmonics.com      100.0.0.2

secondary 100.in-addr.arpa  100.0.0.2

secondary 237.53.198.in-addr.arpa  100.0.0.2

primary       0.0.127.in-addr.arpa  named.local

cache                         named.ca
```

由此可见，`named.boot` 的配置大部分包含了（而非）`primary` 语句。例如，第二个条目将 `named` 配置为 `harmonics.com` 域的从服务器，并告诉它从 IP 地址为 `100.0.0.2`（即 `jade`）的服务器获取主域数据库的副本。第三、第四和第五条目同样配置了 `jade` 上的 `named` 为剩余域 `100.in-addr.arpa` 和 `237.53.198.in-addr.arpa` 的从服务器。所有从语句都指向主机地址 `100.0.0.2` 以获取每个数据库的副本。

最后两个条目与 `jade` 上的 `named.boot` 中的对应条目完全相同。它们也让 `named` 指向

用于信息的本地文件名。由于 `named.local` 和 `named.ca` 的内容几乎不改变，因此本地访问它们包含的信息是有意义的，这可以节省因文件传输操作可能丢失的带宽

## 备服务器的启动

备服务器的启动方式与主服务器相同。当主机在启动时进入运行级别二，启动脚本会检查 `named.boot` 文件是否存在。如果该文件存在，`named` 就会根据文件中包含的语句进行启动和配置。数据库文件的副本属于服务器通过区域传输过程获得授权的域，这些文件由 `secondary` 语句指定的源提供。

## 手动启动 named

无论作为主服务器还是备服务器，都可以通过输入 "`named`" 命令来手动调用 `named`。如果没有指定命令行选项和参数，则假设 `named.boot` 为启动文件。要指定不同的启动文件，请使用所示的 "`-b`" 选项：

```
# -b /usr/lib/mynamed.boot
```

因此，`named` 会检查 `mynamed.boot` 文件以获取如何自配置服务器的指令。

为了健壮性的备服务器：只要在备服务器重启时主服务器处于运行状态，上述配置就能生效。如果主服务器宕机了呢？备服务器将无法启动，因为可能没有其他数据源。为了避免这种可能性，DNS 允许你做两件事：在 `secondary` 语句中指定最多十个 IP 地址，服务器从这些地址获取区域数据；并配置服务器通过区域传输维护文件的磁盘副本。

可以在第一个 IP 地址之后添加备用地址。它们可以持续到运行主名称服务的主机。以下是一个带有指定 IP 地址的 `secondary` 语句示例：

```
secondary harmonics.com 100.0.0.2 100.0.0.4
```

根据 `secondary` 的设置，如果 `jade` 响应了 `cello` 对区域传输数据的查询，名称服务器必须从 `100.0.0.4` 寻求数据。这里的假设是，主机 IP `100.0.0.4` 是域 `harmonics.com` 的另一个主服务器。

通过允许备服务器维护已传输数据文件的备份，可以提高健壮性。此备服务器将始终有一个可以从其获取区域数据的最后手段。然而，之处在于，如果数据已过期，备份将被丢弃。除非发现主服务器响应区域传输请求，否则备服务器将退出。

要使 `named` 维护备份副本，所需要的只是在每个 `secondary` 语句的最后一列指定指定应拷贝数据的文件名。以下是 `cello` 的 `named.boot` 文件的修订版本，包含了对备份文件的支持：

```
directory /usr/lib/mynamed

secondary harmonics.com 100.0.0.2 named.hosts

secondary 100.in-addr.arpma 100.0.0.2 100.rev

secondary    237.53.198-in-addr.papa    100.0.0.2    198.53.237.rev

primary       0.0.127-in-addr.papa    named.local
```

## 配置仅缓存服务器

仅缓存服务器不依赖于数据库文件，无论是自己的还是其他的。仅缓存服务器缓存与查询相关的数据以及它在寻求所需响应时参与的解析引用相关的数据。缓存数据被尽可能用于解析查询。

仅缓存服务器是所有服务器中配置最简单的。以下是一个假设连接到 `harmonics.com` 网络的假设仅缓存服务器的 `named.boot` 文件：

```
; Cache-only server for the harmonics.com domain
; primary       0.0.127-in-addr.papa    /usr/lib/named/named.local
cache          /usr/lib/named/named.ca
;
```

可以得出，除了 `named.boot` 之外，另外两个文件是 `named.ca` 和 `named.local`。`cache` 语句配置服务器通过从线路初始化缓存来缓存响应，数据维护在 `named.ca` 中。`primary` 语句具有相同章节中描述的功能。

这之所以是“仅缓存”，是因为缺少了将其声明为某个域权威服务器的 `primary` 或 `secondary` 语句。`cache` 语句一直是之前检查过的 `named` 启动文件的一部分。因此，将其在仅缓存服务器的 `named.boot` 中是绝对必要的，同样，避免对其所有形式的 `primary` 或 `secondary` 语句也是必要的，除了指向本地查找域的那个语句外。

## nslookup

如果不讨论 `nslookup` 命令，关于 DNS 名称服务的讨论就是不完整的。`nslookup` 是一个功能强大的命令，可以在交互模式下运行，用于测试、验证和排除 DNS 服务设置和运行的故障。以下讨论强调了 `nslookup` 命令的方面：

- nslookup 在线帮助
- 使用 nslookup 查询本地服务器
- 使用 nslookup 查询远程服务器
- 使用 nslookup 下载 DNS 数据库

### nslookup 在线帮助

### 使用 `nslookup` 查询本地服务器

你你使用 `nslookup` 通常有三种情况：测试新启动的服务器、验证对现有服务器配置的更改，或排查 DNS 服务故障。无论如何，开始 `nslookup` 的良好方法是查询本地服务器。根据结果，你可以通过针对你域内的服务器或互联网上的远程域名的服务器来扩大范围。

现在 `jade` 已经配置并启动，让我们测试它以验证其运行情况。为此，网络管理员以 `root` 身份登录并执行 `nslookup` 命令。默认情况下，`nslookup` 响应名称查询（多宿主地址）。下面是在 `nslookup` 提示符输入主机名（saturn）时的情况示例。

```
# nslookup
Default Server: jade.harmonics.com
Address: 100.0.0.2
```

```
> cello
Server: jade.harmonics.com
Address: 100.0.0.2
```

```
Name: cello.harmonics.com
Address: 198.53.237.2
```

注意响应中包含了解析结果，以及解析名称到地址查询的服务器的名称和地址。你应该再进行几次类似的测试，以验证本地服务器解析名称到地址查询的有效性。特别感兴趣的是多宿主主机，例如 `harmonics` 域中的 `jade`。如前所述，名称服务器应该响应分配给连接到网络的接口的所有地址。在接下来的示例中，使用 `nslookup` 解析 `jade` 的名称到其对应的 IP 地址：

```
# nslookup
Default Server: jade.harmonics.com
Address: 100.0.0.2
```

```
> jade
Server: jade.harmonics.com
Address: 100.0.0.2
```

```
Name: jade.harmonics.com
Addresses: 100.0.0.2, 198.53.237.1
```

`nslookup` 按接收到的顺序显示地址（首先接收到 100.0.0.2，然后是 198.53.237.1）。

接下来，你应该验证服务器处理反向 DNS 解析查询的能力。同样，只需输入你网络上存在的 IP 地址即可。以下是在 `jade` 上执行的示例示例：

```
# nslookup
Default Server: jade.harmonics.com
Address: 100.0.0.2
```

```
> 198.53.237.2
Server: jade.harmonics.com
Address: 100.0.0.2
```

尝试进行许多反向查询，以验证反向解析过程的可靠性。如果一切顺利，你就可以继续使用本地服务器上的 `nslookup` 进入测试其他服务器的下一阶段。

### 使用 `nslookup` 查询远程服务器

`nslookup` 的理想功能之一是它查询网络上远程服务器的能力。远程服务器可以在你的网络中，也可以在互联网的任何地方。此功能允许你排查服务器故障，或检查你最近在网络上启动的服务健壮性。在接下来的示例中，在主机（主服务器）上调用 `nslookup` 的远程功能，查询（备用服务器）`soprano` 的 IP 地址：

```
# nslookup
Default Server: jade.harmonics.com
Address: 100.0.0.2
```

```
> soprano cello.harmonics.com
Server: cello.harmonics.com
Address: 198.53.237.2
```

```
Name: soprano.harmonics.com
Address: 100.0.0.4
```

如所示，使用 `nslookup` 将查询发送到 `cello` 的功能要求在命令行中主机名（`.. soprano`）之后输入远程服务器的名称（即 `cello.harmonics`）。与远程服务器通信的更好方法是使用 `server` 命令，让 `nslookup` 默认指向远程服务器。以下示例展示了如何操作：

```
> server cello
Default Server: cello.harmonics.com
Addresses: 198.53.237.2
```

```
> soprano
Server: cello.harmonics.com
Addresses: 198.53.237.2
```

```
Name: soprano.harmonics.com
Address: 100.0.0.4
```

### 使用 `nslookup` 下载 DNS 数据库

`nslookup` 的另一个有用功能是内部 `ls` 命令。使用 `ls` 可以强制进行区域传输。默认情况下，数据被重定向到标准输出。可选情况下，你可以指定文件名，将数据发送到那里供以后检查。以下示例演示了 `ls` 命令的使用：

```
# nslookup
Default Server: jade
Address: 0.0.0.0
> ls harmonics.com
harmonics.com      server
harmonics.com      names = jade.100.0.0.2
harmonics.com      names = jade.198.53.237.1
harmonics.com      serial = 20231010
harmonics.com      refresh = 86400
harmonics.com      expire = 604800
harmonics.com      minimum = 3600
harmonics.com      tranay = 3600
harmonics.com      zone.data
```
