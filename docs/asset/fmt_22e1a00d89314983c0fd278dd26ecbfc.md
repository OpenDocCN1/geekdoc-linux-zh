# Samba 认证

Linux 系统可以配置为使用 Microsoft 数据库。可以使用旧的 Microsoft Windows NT4 风格数据库、Microsoft Windows 2000/2003 安全账户管理器 (SAM) 数据库，或与 Linux 认证兼容的 LDAP 数据库。除非使用 LDAP，否则 Microsoft 数据库的密码加密与 Linux 不兼容。也就是说，Microsoft NT4 数据库使用 MD4 加密，Linux 影子密码套件使用 MD5 加密。

认证系统取决于 Samba 主配置文件`/etc/samba/smb.conf`中的`passdb backend`指令。该指令有三个可选值：smbpasswd、tdbams 和 ldaps。`smbpasswd`选项是默认值；也就是说，如果在 Samba 配置文件中没有看到`passdb backend`指令，它就是激活选项。

# 第10章：网络身份验证与文件系统

`smbpasswd`选项意味着基于 Samba 的 NT4 风格认证数据库。`tdbsam`选项将微软安全账户管理器 (SAM) 信息与数据相结合。`ldapsam`选项将基于 LDAP 的身份验证集成到 Samba 网络共享中。

## Samba NT4 认证数据库

当微软结束对 NT4 服务器的官方支持时，许多团体能够通过将 Windows NT4 服务器替换为配置了 Samba 的 Linux 服务器，来保留其域网络结构。通过使用`passdb backend = smbpasswd`选项，这些团体发现配置 Linux 具有与许多 NT4 服务器相同的域控制器 (PDC) 功能是相当容易的。

有与创建 Samba NT4 认证数据库相关的两个关键命令。`smbpasswd`命令可用于为微软网络创建 MD4 加密密码和 Samba 用户。这是一个简单易了的命令；该选项会为本地服务器上的用户 michael 添加并配置密码。Samba 密码可以与 Linux 密码不同。

```
$ smbpasswd -a michael
```

同样，可以使用`-x`切换开关从数据库中删除 smbpasswd 用户：

```
$ smbpasswd -x michael
```

但那可能是一个长时间的过程。`mksmbpasswd`命令可以从`/etc/passwd`提取用户以生成 Samba 密码数据库。例如，以下命令序列设置了位于`/etc/samba/smbpasswd`的用户名数据库：

```
$ su su
# cat /etc/passwd | mksmbpasswd > /etc/samba/smbpasswd
# exit
```

这是少数必须以管理员身份运行的命令之一。`su`命令实际上登录了 root 账户——如果你的账户按照第 8 章所讨论的，在`/etc/sudoers`中配置了具有管理员权限。但这只是数据库。要向其中填充密码，你仍然需要使用上述的`smbpasswd`命令启用每个账户。

## Samba Windows 2000/2003 认证数据库

`/etc/samba/smb.conf`中的`passdb backend = smbpasswd`选项整合与微软用户和计算机账户概念相关的 SAM 信息。账户和连接数据库存储在`/var/lib/samba`和`/var/cache/samba`目录。认证数据库是加密的。

虽然 Samba 用户名和密码可以使用相同的`smbpasswd`与 LDAP 服务器一起创建，但需要`pdbedit`命令来读取数据库。

`pdbedit`命令也可用于添加或删除用户。用于`smbpasswd`命令的相同`-a`和`-x`切换具有相同的通用目的。但请看图 10-1，它说明了当我添加用户时 T 数据库中可用的信息范围。

`pdbedit -L`命令可列出用户。`pdbedit -w`命令以 Samba 密码格式列出用户；如果为特定用户添加了 MD4 加密密码，它将包含这些密码。

实际上，`pdbedit`命令可以完成更多。单独运行`pdbedit`命令。它将向你显示一系列选项，这些选项对应于微软 Windows 2000/2003 服务器同样提供的细粒度认证数据库。`mksmbpasswd`命令对 TDP 数据库不起作用。尽管如此， TDP 是“简易数据库（trivial database）”的缩写，但密码数据库并不简易。
