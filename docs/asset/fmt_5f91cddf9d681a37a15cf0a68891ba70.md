## 4.2 用户、密码、文件权限与安全

### 4.2.1 家目录、root 以及添加 root 用户

这是硬盘上（几乎）唯一允许普通用户（非 `root`）写入其家目录的地方，路径为 `/home/user_login`。

`home` 目录存放所有用户文件的目录：设置、程序配置、文档、数据、`netscape` 缓存、邮件。作为用户，你可以在家目录下创建子目录以保持整洁。除非你赋予权限，否则其他人无法读取你的文件或写入你的目录。

普通用户也可以读取、查看和编辑系统上的其他文件（家目录之外），但不能修改或删除它们。

`root`（也称为“超级用户”）是一个特殊的管理员账户，拥有修改系统上任何文件的权限。习惯性以 `root` 身份操作系统是不好的——如果你这样做，错误可能会让你付出沉重的代价。为你创建一个普通用户账户，为你的儿子创建一个账户，再为你的妻子创建一个。`root` 账户通常是 Linux 安装后唯一存在的账户。因此，你必须显式地为你的 Linux 系统创建“用户”账户进行普通工作。

用户账户可以由 `root` 创建，例如：

```
adduser joe
```

```
password joe
```

```
[输入用户 joe 的密码]
[再次输入用户 joe 的密码以防错误]
```

在上面的示例中，我使用密码（参数）`"joe"` 登录。这创建了账户 `"joe"`。

### 4.2.2 关于密码

弱密码可能是导致安全泄露最常见的根源。即使在家里，你也可能面临麻烦，因为别人可能黑入你的计算机。因此，请保持所有密码的安全。以下是一些危险密码的示例：

- 无密码（可能）

- 单词 `"password"`（哇，这真的太弱了！）

- 你的登录名（登录名和密码一样？嗯。）

- 你女儿、儿子、丈夫、女朋友或其他任何名字。

- 你的姓或任何姓氏。

- 你的狗、妻子或金丝雀的昵称。

- 你喜欢的运动队、名人、牙膏或洗剂的名字。

- 出生日期、社会安全号等；数字序列很容易被破解。

- 你的公司名称、部门、计算机工作组等。

- 写在桌上日历或订单单上的密码。

- 你在不安全的地方也使用的同一个密码，例如网上商店或邮件列表。

## 4.2.3 我忘记密码了

即使我从不忘记密码，我仍然会详细研究这个问题，因为它给了我启发，关于你妈妈是如何看到我的 IC 聊天历史的 :-)

第一种方法。解决“忘记密码问题”最简单的方法是在单用户模式下运行 Linux，即在（启动期间）的 `linux` 提示符处输入：

`linux single`

这将让你获得“`root`”权限而无需询问密码。现在，作为 `root`，你可以使用此命令更改 `root` 密码（无需旧密码）：

```bash
passwd
```

如果你觉得这极不安全，那是因为如果其他人对你的硬件有物理访问权限，那么没有任何计算机系统是安全的。尽管如此，我不喜欢我电脑上的“`linux single`”漏洞，并通过向我的 `/etc/lilo.conf` 文件添加以下行（在 `"image-section"` 的末尾）来封堵它：

```bash
password="my_password"
```

这个“`lilo`”密码是在：启动时的 LILO 提示符处，有人带任何参数输入单词“`linux`”时需要的（不带任何参数的正常启动仍然不需要密码）。为了让对 `/etc/lilo.conf` 的更改生效，我必须重新运行命令行。

由于 `lilo` 未加密，我必须让 `/etc/lilo.conf` 对 `root` 只有只读：

```bash
chmod 600 /etc/lilo.conf
```

第二种方法。解决“丢失 `root`”权限的另一种方法是从 Linux 磁盘或 CD 启动。然后在硬盘上找到你的 `root` 分区，并编辑 `/etc/shadow`（在从从软盘启动后我可以做到这一点，我成为 `root` 而无需被询问密码）。在密码文件中，我删除了 `root` 的密码（例如，使用编辑器，使其变为空）。

用户账户保留在 `/etc/passwd` 和 `/etc/shadow` 文件中。

`/etc/passwd` 文件包含我电脑上所有账户的、可读的信息。文件中的每行都包含一个账户的信息。它有 7 个由冒号分隔的字段：登录名、字母“`x`”、数值用户 ID、用户的数值组 ID、注释字段（例如用户名）、用户的 `HOME` 目录、`shell` 的名称（即正在运行的程序）。

关于我系统中账户的其余信息存储在 `/etc/shadow` 文件中。这更安全，因为只有 `root` 可以读取它。文件中，每行包含一个账户的“`shadow`”信息，并有 9 个由冒号分隔的字段：登录名、加密密码、自 1970 年 1 月 1 日以来上次更改密码的天数、密码可更改前距离过期的天数、密码过期后账户锁定或禁用的天数、自 1970 年 1 月 1 日以来账户禁用的天数以及预留字段。

某些（旧的）UNIX 或 Linux 系统不包含 `/etc/shadow`，并将加密的用户密码存储在 `/etc/passwd` 文件每行的第二个字段（即密码字段）。
