## `wb_writeback()` 函数分析

`vm.dirty_expire_centsecs` 可调参数在 `dirty_writeback_interval` 全局变量中维护。我们在列表 10-55 中检查该函数（省略了范围之外的 trace 和块设备钩子）。

```c
/* 显式刷新或对“旧”数据的周期性回写。 */
```

```c
1976 * 定义“旧”：当 inode 的页首次被变脏时，我们在 inode 的 address_space 中
1977 * 标记变脏时间。因此，这段周期性回写
1978 * 代码
1979 * 只是遍历 superblock inode 列表，回写任何早于
1980 * 特定时间点的 inode。
1981 *
1982 * 尝试每隔 `dirty_writeback_interval` 运行一次。但如果一次回写事件
1983 * 耗时超过了一个 `dirty_writeback_interval` 间隔，则留出
1984 * 一秒钟的间隙。
1985 *
1986 * `dirtied_before` 的优先级高于 `nr_to_write`。因此，只有当所有脏页都挂载到
1987 * “旧”映射上，我们才会回写所有脏页。
1988 */
```

```c
1988 static long wb_writeback(struct bdi_writeback *wb,
1989                 struct wb_writeback_work *work)
1990 {
1991     long nr_pages = work->nr_pages;
1992     unsigned long dirtied_before = jiffies;
1993     struct inode *inode;
1994     long progress;
1995     
1998     spin_lock(&wb->list_lock);
1999     for (;;) {
2000         /*
2001          * 当 nr_pages 被消耗完时停止回写
2002          */
2003         if (work->nr_pages <= 0)
2004             break;
2005 
2006         /*
2007          * 后台写入和 kupdate 风格的回写可能会
2008          * 无限运行。如果有其他工作要做，则停止它们
2009          *
2010          * 例如 sync 可以继续。它们将在其他工作完成后
2011          * 重新启动。
2012          */
2013         if ((work->for_background || work->for_update) &&
2014             list_empty(&wb->work_list))
2015             break;
2016 
2017         /*
2018          * 对于后台写入，当我们低于
2019          * 脏阈值时停止
2020          */
2021         if (work->for_background && !wb_over_bg_thresh(wb))
2022             break;
2023 
2024         /*
2025          * Kupdate 和后台工作是特殊的，我们希望
2026          * 包含所有需要写入的节点。活锁避免
2027          * 由这些工作让出给任何其他工作来处理，这样
2028          * 是安全的。
2029          */
2030         if (work->for_kupdate) {
2031             dirtied_before = jiffies -
2032                 msecs_to_jiffies(dirty_expire_interval * 10);
2033         } else if (work->for_background) {
2034             dirtied_before = jiffies;
2035         }
2036         if (list_empty(&wb->work_list)) {
2037             queue_io(wb, work);
2038         }
2039         if (work->sb) {
2040             progress = __writeback_inodes_wb(wb, work);
2041         } else {
2042             progress = __writeback_inodes_wb(wb, work);
2043         }
2044         /*
2045          * 脏页是过期 inode 的标准周期性
2046          * 这种回写。这种形式的回写可以
2047          * 循环，只要有进度。
2048          */
2049         if (progress) {
2050             continue;
2051         }
2052         /*
2053          * 没有更多可回写的 inode，
2054          */
2055         if (list_empty(&wb->b_io)) {
2056             break;
2056         }
2057         /*
2058          * 等待一些
2059          * 可用的回写。
2060          */
2061         inode = get_next_old_inode(wb);
2062         spin_lock(&inode->i_lock);
2063         spin_unlock(&inode->i_lock);
2064         /*
2065          * 释放锁
2066          */
2067         spin_unlock(&wb->list_lock);
2068         schedule();
2069         spin_lock(&wb->list_lock);
2070     }
2071 
2072     spin_unlock(&wb->list_lock);
2073     return nr_pages - work->nr_pages;
2074 }
```

## `__writeback_inodes_wb()` 函数

由于此项操作未发生，导致 inode 被转移到 `struct bdi_writeback->b_more_io`，这意味着等待我们计划处理的下一个 inode 提交其 I/O 是明智的，以避免在 `wb_writeback()` 中可能出现忙循环。

这是通过 `idle_sleep_on_writeback()` 实现的，如果该标志确实处于设置状态，它将导致进程睡眠，直到该标志被清除。

接下来，我们检查对所有调度执行回写的节点执行回写的函数 `__writeback_inodes_wb()`，我们在列表 10-56 中查看该函数。

```c
1917 static long __writeback_inodes_wb(struct bdi_writeback *wb,
1918                     struct wb_writeback_work *work)
1919 {
1920     unsigned long start_time = jiffies;
1921     long writeback = 0;
1922 
1923     while (!list_empty(&wb->b_io)) {
1924         struct inode *inode = wb_inode(wb->b_io->prev);
1925         struct super_block *sb = inode->i_sb;
1926 
1927         if (!trylock_super(sb)) {
1928             /*
1929              * trylock_super(sb) 可能会因为 s_umount
1930              * 被其他人占用而持续失败。不要使用
1931              * requeue_io() 来避免忙碌重试 inode/sb。
1932              */
1933             requeue_io(inode, wb);
1934             continue;
1935         }
1936         writeback += writeback_sb_inodes(sb, wb, work);
1937         up_read(&sb->s_umount);
1938 
1939         /* 参考 writeback_sb_inodes 末尾的测试
1940         */
1941         if (writeback) {
1942             if (time_is_before_jiffies(start_time + HZ / 10UL))
1943                 break;
1944             if (work->nr_pages <= 0)
1945                 break;
1946         }
1947     }
1948     /* 将任何未写入的 inode 留在 b_io 上 */
1949     return writeback;
1950 }
```

列表 10-56: fs/fs-writeback.c: `__writeback_inodes_wb()`

该函数遍历 `struct bdi_writeback->b_io` 中的每个 inode，反向操作，因此是从旧到新的顺序进行。

它尝试获取 inode 的 `struct super_block->s_umount` 锁 `trylock_super()`。它不会等待此锁，如果锁不可立即用，inode 会立即被“重定向”，通过 `requeue_io()` 放置在 `struct bdi_writeback->b_dirty` 列表上（我们在列表 10-59 中检查此项）。

每个 inode 然后将通过核心 `writeback_sb_inodes()` 函数进行回写（见列表 10-57）。此函数返回已成功调度回写的页数，我们累加这些数量并最终返回给调用者。

该函数受速率限制（方式与 `writeback_sb_inodes()` 类似），在迭代之间有一个硬编码的最大时间——十分之一秒，假设至少回写了 1 个页（我们处理所有 inode 直到我们至少回写了 1 个页为止）。此外，我们还会手动检查工作是否已完成，在该点我们退出。

这允许函数定期返回其调用者处，以查看是否发生了任何会导致终止回写的条件。

## `writeback_sb_inodes()` 函数

如第 10.1 节所述，回写核心使用 `writeback_control` 对象来管理过程（在列表 10-24 中探讨），我们必须根据 `struct wb_writeback_work` 参数生成它。

我们总是通过恰当地设置 `range_start` 和 `range_end` 来指定脏 inode 的整个范围。如果回写仅跨越属于某个 inode 的子集 folios，则必须使用 `fsync()` 和相关 API 进行文件回写（见第 10.3 节）。

在此阶段，我们不指定 `nr_to_write` 参数，稍后我们将在函数中根据我们将讨论的“块大小”来指定它。
