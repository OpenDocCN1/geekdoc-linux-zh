
`-a`选项告诉程序显示设备的所有信息。通用异步收发传输器（UART）是RS-232串口的核心。大多数UART是`16550`模块，但也存在其他类型。如果串口报告你的系统有一个`16450`，特别是`8250`，那么要么系统检测你的硬件时出现错误，要么你拥有一个非常古老的RS-232串口。此类端口可能无法远高于`38,400bps`地工作，因此你应该更换硬件。

如果你想更改RS-232串口的参数，你可以使用设备标识符（例如第一个端口的`/dev/tty50`）并配合如下选项：

### `port-number`
`port-number`更改设备标识符。
`port-number`通常表示为十六进制值，例如`0x38`

### `irq-number`
你可以使用此选项为设备分配中断请求（IRQ）线路。

### `uart-type`
如果系统误识别了UART，你可以用此选项纠正问题。有效的`uart-type`值为`8250`, `16450`, `16550`, `16550A`, `16650`, `16650V2`, `16654`, `16750`, `16850`, 和`16954`。指定`none`将禁用端口。

### `autoconfig`
此参数告诉内核尝试上述RS-232串口类型。
这需要你使用其他端口。

`skip_test`将此参数与`autoconfig`配合使用，告诉系统跳过UART检测，这会导致某些品牌的UART出现问题。

`baud_base rate`你可以使用此选项将RS-232并行端口的速度（每秒比特数）设置为指定的速率。

这些选项仅是可用选项的示例。如果你正在使用一个对时间非常敏感的RS-232串口应用程序（一种科学数据采集工具），你可能想要阅读`setserial`页面，以研究可能影响RS-232串口性能的许多选项。在大多数情况下，这些选项都不是必需的。你可能在使用昂贵的内部调制解调器时需要这些选项，它们可能使用了无法正确自动检测的旧UART；或者使用不知名的多口RS-232串口卡，这些卡支持四个以上的端口（Linux尝试自动配置前四个RS-232端口）。

带有两个RS-232串口的典型主板，但有时你可能需要更多——例如，如果你正在运行ISP的拨号银行。在这种情况下，你可能想要购买一个专用的RS-232卡。这些设备是不寻常的设备，在购买之前需要检查Linux驱动的可用性。如果你添加了一个内部ISA端口来托管你自己的RS-232串口硬件，你可能会遇到问题：传统上，前两个RS-232串口使用`IRQ 4`和`3`。许多内部调制解调器预配置了第三个RS-232串口，并尝试“共享”`IRQ 4`。这种配置在Linux中可能不起作用，因为ISA设备的中断共享是不行的。

## 克服键盘怪特性

在大多数情况下，键盘可以直接正常工作。在IA-32平台上，键盘支持是如此巨大且必要，以至于它甚至没有出现在内核配置菜单中作为一个选项——它理所当然地被编译进了内核中。在后台，Linux的键盘处理过程中发生了很多事情，因此可能会出现怪特性（quirks）。这些特性包括文本模式或X模式下按键与字符之间的奇异映射。当使用非美国键盘或不知名键盘（例如使用`Dvorak`布局的键盘）时，这些特性尤为常见。最后，如果你使用`USB`键盘，可能需要采取特殊步骤来确保它在Linux下正常工作。

## 理解 Linux 中的键盘

为了在Linux中管理键盘，了解键盘输入数据发生了什么将有所帮助。图3.3展示了键盘如何向计算机发送扫描码（scan code）。该代码映射到物理按键，但根据键盘类型，任何扫描码都可能代表不同的符号。例如，俄罗斯键盘返回的扫描码与美国键盘大致相同，但俄罗斯键盘的扫描码映射到西里尔字母，而美国键盘的扫描码映射到罗马字母。这种到单个符号的映射方式取决于计算机运行在文本模式还是X模式下。

**图 3.3**
Linux中的键盘输入处理可以采取两条路径。

| 键码 (Key Code) | 终端代码 (Terminal Code) |
| --- | --- |
| 由内核创建； | 由 X 创建； |
| 代表符号 | 代表符号 |

在文本模式下，内核解释扫描码并创建键码（key code）。大多数基于文本的Linux程序都被设计为同时可以在控制台和远程登录（哑终端、网络日志、`xterm`窗口等）工作。因此，终端驱动程序将键码转换为我称为“终端代码”的最终代码。这是键盘上符号的统一表示，无论由什么设备生成了按键。

当你运行X时，服务器直接读取扫描码，并将其自行转换为基于X的终端代码。基于X的程序根据此终端代码工作。当你在`xterm`窗口中运行文本模式程序时，`xterm`必须从X终端生成传统的文本模式终端代码。

概之，发生了三种主要的按键映射转换。你可以通过运行适当的实用程序或修改配置文件来修改这些去映射操作中的任何一个。当你安装Linux时，收到的问题之一是你使用什么类型的键盘。安装程序根据你对该问题的回答为模式和X设置了适当的键盘映射。不过你可能需要调整此映射，因为你可能在安装Linux时提供了错误信息，或者发行版供应商提供的映射是不正确的。你可能还想更改映射以根据自己的喜好个性化键盘。在接下来的章节“让键盘在文本模式下工作”和“让键盘在 X 下工作”将描述如何实现。

## 让键盘在文本模式下工作

`loadkeys`程序加载键映射文件（keymap），修改内核从扫描码到键码的映射。你通常向此程序传递映射文件的名称；如果省略了映射文件，该程序将使用默认映射。大多数发行版作为系统启动过程的一部分调用`loadkeys`，如表3.1所示。

### 表 3.1：键映射配置文件
| 发行版 | 调用来源 | 在何处指定默认键映射 | 键映射文件存储目录 |
| --- | --- | --- | --- |
| `Debian` | `/etc/init.d/keymap.sh` | `/etc/init.d/keymap.sh` | `/etc/console` 和 `/usr/share/keymaps` |
| `Mandrake` | `/etc/rc.d.sysinit` 和 `/etc/rc.d/init.d/keytable` | `/etc/sysconfig/keyboard` | `/usr/lib/kbd/keymaps` |
| `Red Hat` | `/etc/rc.d.sysinit` 和 `/etc/rc.d/init.d/keytable` | `/etc/sysconfig/keyboard` | `/lib/kbd/keymaps` |
| `Slackware` | N/A | `/etc/sysconfig/keyboard` | `/usr/share/kbd/keymaps` |
| `SuSE` | `/etc/init.d/kbd` | | `/usr/share/kbd/keymaps` |

大多数发行版直接将`loadkeys`指向表3.1“键映射文件存储”列指定目录的子目录下的键映射。`Debian`在这方面是一个异类；当你安装它时，它会将键映射文件从`/usr/share/keymaps`复制到`/etc/console/boottime.map`。`Slack`甚至更加奇异；它在启动过程中完全不调用`loadkeys`，它使用默认键盘，如果你想加载自定义键映射，则需要修改一个类似`/etc/rc.d/rc.local`的启动文件。

即使你的键盘设置正确，你也可能会由于奇怪的键盘速率设置而遇到问题。如果你发现按住按键一小会儿后出现的字符太多或太少，你需要调整键盘重复率。你可以使用`kbdrate`程序做到这一点，它接受重复和延迟参数，如下所示：

```
# kbdrate -r 12 -d 250
```
