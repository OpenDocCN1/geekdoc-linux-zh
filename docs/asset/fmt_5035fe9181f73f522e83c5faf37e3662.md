
在网络中，协议层层堆叠。对于 TCP/IP，协议栈如下：HTTP Telnet POP3 SNMP UDP ICMP ARP ETHER 你遵循这一点时的层：你使用 HTTP 请求获取网页。HTTP 客户端（网络浏览器）通过协议连接 HTTP 服务器（网站）。TCP 协议将其所有工作分分成 IP 数据包。互联网上的路由器知道如何转发 IP 数据包，但对 IP 包内部一无所知。

要点：加密可以在任何层发生。负载数据本身可以独立于传输它的协议进行加密。例如，一种类型是在发送电子邮件之前对消息进行加密。所有的程序和协议完全不知道这种情况的发生。应用层具有加密能力。传输层 SSL 是传输层的加密。网络层 Isec 在网络层提供加密，加密 IP 之上的所有内容，包括 TCP 和 UDP 处理器。

在通信中，代理（proxy）是一种作为服务器的角色，但在收到客户端的请求时，它又作为真实服务器的客户端。类比：想象通过翻译官与说外语的人交流。你与翻译官交流，翻译官接收你的陈述并向另一端重新生成内容。翻译官充当了你的代理。

关键点：通信在代理处终止。换句话说，除非完全分离，否则代理不会像通常那样转发数据。例如，HTTP 代理不会转发每一个请求。相反，如果它的缓存中已经有了请求的页面，它将返回该页面，而无需向目标服务器发送另一个请求。由于代理完全终止了通信通道，它们是比包过滤器更安全的防火墙技术，因为它们极大地增加了网络之间的隔离。

关键点：你偶尔会被扫描代理。ISP 会扫描代理代理。黑客会在互联网上扫描代理以匿名化连接。某些服务器（如 IRC 服务器）会扫描客户端以防止任何匿名连接。网站维护代理列表，例如 http://proxyall.egui.net/

# 代理服务器

代理服务器位于客户端与其尝试使用的“真实”服务器之间。客户端有时被配置为通过 HTTP 服务器使用代理服务器。客户端向代理服务器发出所有请求，由代理服务器向“真实”服务器请求并将结果返回给客户端。有时代理服务器会存储结果并提供存储的结果而不是创建新请求（以减少网络的使用）。代理服务器通常建立在局域网上。
