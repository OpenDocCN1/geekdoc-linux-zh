
接下来，在你的编辑器中输入以下源码，并将其保存为 `myproject` 中的 `foo.c`：

```c
/* $Header$ */
#include <stdio.h>
static char rcsid[] = "$Header$";
main() {
    printf("hello, world!\n");
}
```

验证你目录的内容：

`# ls`

（输出：`.  RCS  foo.c`）

现在，使用 `ci` 命令开始跟踪：

`# ci foo.c`

`ci` 命令响应如下：

`RCS/foo.v << foo.c`

`enter description, terminated with Ctrl+D`

`revision 1`

`date 1997/08/02 18:49:08`

`author root`

`state new`

现在查看 `myproject` 的内容：

`# ls`

（输出：`.  RCS  foo.c`）

发生了什么？`foo.c` 去哪了？通过查看：

`# cat RCS/foo.c,v`

（输出为文件内容）

`ci` 命令创建了 `foo.c,v`，版本为 1。但是，如果你想编辑并进行更改，必须锁定文件：

`# ci -l foo.c`

现在，写权限已对所有者启用。如果你打开 `foo.c`，你会看到：

```c
/* $Header$ */
#include <stdio.h>
static char rcsid[] = "$Header$";
main() {
    printf("hello, world!\n");
}
```

`$Header$` 关键字已被替换为文件的完整路径、修订号、日期、作者和锁定者。如果你将 RCS 信息作为嵌入字符串，程序的最终二进制文件将包含你的版本信息。如果你将关键字包含在注释中，源文档将包含更新信息。

以下是可用的一些 RCS 关键字：

- `$Author$`
- `$Date$`
- `$Header$`
- `$Id$`
- `$Locker$`
- `$Log$`
- `$Name$`
- `$RCSfile$`
- `$State$`

关于这些关键字的详情，请参阅 `co` 手页。然而，关于文档更改的历史，你可以使用 `rlog` 命令。例如，在两次编辑后，`rlog` 关于 `foo.c`（现在是版本1.3）报告如下：

如你所见，RCS 将每个版本的更改记录为 `foo.c,v` 文件中的 `diff` 命令。因此，你可以通过使用 `co -r*X.X*` 命令在任何时间成功地每个版本，其中 `*X.X*` 是你想要的版本。此外，由于更改是 `diff` 格式，原始文档的许多更改可以相当高效地存储。

有时你必须创建一个文件的“分支”版本，仅仅是为了在版本的中间进行临时的或专门的修复。在这种情况下，你使用 `co` 命令的 `-r*X.X*` 选项来创建一个分支。

例如，为了对 `foo 1.2` 进行特殊发布，你使用以下命令：

`# co -l -r1.2 foo.c`

`RCS/foo.c,v --> foo.c`

`revision 1.2 (locked)`

`done`

在进行更改并把 `foo.c` 回库时，`ci` 命令会将版本提升到 1.2.1.1 并响应如下内容：

`# ci foo.c`

`RCS/foo.c,v <-- foo.c`

`new revision: 1.2.1.1; previous revision: 1.2`

`enter log message, terminated with single \` or end of file:`

`>> a temporary fix`

`>> .`

`done`

你也可以合并程序的不同版本。例如，要将从 1.1 的更改引入 1.3，你可以使用 `rcsmerge` 命令，但首先你必须以锁定状态检出 `foo.c`：

`# co -r1.1 foo.c`

`RCS/foo.c,v --> foo.c`

`revision 1.1`

`done`

`# rcsmerge -p -r1.1 -r1.3 foo.c >foo.merged.c`

`RCS file: RCS/foo.c,v`

`retrieving revision 1.1`

`retrieving revision 1.3`

`Merging differences between 1.1 and 1.3 into foo.c; result to stdout`
