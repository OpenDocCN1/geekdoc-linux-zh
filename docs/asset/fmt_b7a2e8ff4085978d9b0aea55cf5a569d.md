该函数定义了 `readahead_control` 对象，正如你预期的那样使用了 `DEFINE_READAHEAD()` 宏（如上文列表 9-60 所示），但注意，它显式地将 `_index` 字段设置为 `folio->index`，即通过 `PG_readahead` 设置操作从包含的 folio 开始并向前进行。

我们将操作定义为 `page_cache_async_ra()`，该函数设置从此 folio 开始读取的整个数据范围。我们在下方的列表 9-69 中检查此函数。

正如在 `filemap_get_pages()` 附近讨论的那样（见列表 9-44），如果 folio 范围正在进行页对齐，且我们只读取了 folio 的部分，那么我们将读取范围后的一个 folio，即包含 `last_index` 的 folio。我们也可能标记此 folio 带有 `PG_readahead`，在这种情况下，我们将立即触发预读，调用 `filemap_readahead()` 且 `last_index` 等于 `struct folio->index`，从而向 `page_cache_async_ra()` 传递一个 `req_count` 为 0 的参数。

在页异常的情况下，只要是第一次尝试该异常，`filemap_fault()` 就会无条件地调用 `do_async_mmap_readahead()`。它执行此操作时不检查 `PG_readahead`，而是将其留给 `do_async_mmap_readahead()` 执行。我们在列表 9-68 中检查此函数。

```c
/*
 * 当我们找到页和 PG_readahead 时，会发生异步预读，
 * 因此我们可能进一步扩展预读。如果我们必须丢弃 mmap_lock 来执行 IO，
 * 则返回被锁定的文件。
 */
static struct file *do_async_mmap_readahead(struct vm_fault *vmf,
                                            struct folio *folio)
{
    struct file *file = vmf->vma->file;
    struct file_ra_state *ra = &file->f_ra;
    DEFINE_READAHEAD(ractl, folio, ra, file->f_mapping, vmf->pgoff);
    struct file **fpin = NULL;
    unsigned int mmap_miss;

    /* 我们不需要任何读取预读，在这里不理会 */
    if (vmf->vma->flags & VM_RAND_READ || !ra->ra_pages)
        return fpin;

    mmap_miss = READ_ONCE(ra->mmap_miss);
    if (mmap_miss)
        WRITE_ONCE(ra->mmap_miss, --mmap_miss);

    if (folio_test_readahead(folio)) {
        fpin = maybe_unlock_mmap_for_io(vmf, fpin);
        page_cache_async_ra(ractl, folio, ra->ra_pages);
    }

    return fpin;
}
```

## 9.7.3 按需预读 (On-Demand Readahead)

当发生预读时，或者在存在 `SEQ_READ` 标志时发生同步强制，这会导致内核执行“按需”。

在这种情况下，初始预读将扩展为 4 页，假设最大预读页数为 32 页（典型默认值）。这种异步预读会将预读大小翻倍到 32 页。

| 同步预读 | 页数 |
| :--- | :--- |
| 同步预读 | 4 |
| 异步预读 | 8 |
| 异步预读 | 16 |
| 异步预读 | 32 |

从这里开始，该过程将持续直到达到 32 页的最大预读大小。当我们进入在与下一个文件预读块相关的次异常开始时触发异步预读的模式时，因此持续避免顺序读取中的异常。

即使用户关闭了文件描述符并重新打开同一文件（此时无法访问 `struct file->f_ra` 中的 `struct file_ra_state` 对象），我们也能在遇到下一个 `PG_readahead` 时通过 `page_cache_next_miss()` 恢复该状态（在列表 9-71 中查看其上下文）。

事实上，对于文件中发生的不是第一次的同步预读，我们会尝试确定其任何证据。

通过 `try_context_readahead()` 实现基于上下文的顺序预读（参见下文列表 9-73）。

在所有情况下，只要有任何顺序读取的证据，按需预读（on-demand readahead）都会尽可能读取页，因为将这些数据留在内存中而不是等待从磁盘读取具有显著的性能优势。

正如我们在回收（reclaim）章节中所探讨的那样，内核会迅速读取页缓存，但在内存压力下会迅速回收它，因此大量产生这些页是完全没有问题的。

让我们检查执行按需预读的函数 `demand_readahead()` 中的这一细节，我们将从下方的列表 9-70 开始分析它。

```c
/*
 * 针对简单的顺序/随机读取的最小预读算法。
 */
static void demand_readahead(struct readahead_control *ractl) {
    struct folio *folio;
    unsigned long req_size;
    struct backing_dev_info *bdi = inode_to_bdi(ractl->mapping->host);
    struct file_ra_state *ra = ractl->ra;
    unsigned long max_pages = ra->ra_pages;
    unsigned long add_pages;
    goff_t index = readahead_index(ractl);
    goff_t expected, prev_index;
    unsigned int order = folio ? folio_order(folio) : 0;
}
```

```c
/*
 * 如果请求超过了预读窗口，允许读取大小
 * 达到最优硬件 IO 大小
 */

    max_pages = min(req_size, bdi->io_pages);
```

## 列表 9-70: `mm/readahead.c`: `demand_readahead()` 序言

我们首先从 `struct readahead_control` 对象中获取应该继续执行的索引，如果提供了 `folio`，则获取其 `folio order`（如果提供了 `folio`，意味着是异步预读）。我们还把可以预读的页（派生自 `struct file_ra_state->pages`）放入 `max_pages` 中。

然后我们检查并确保预读大小超过了最大页数。如果没有，则不将其视为硬限制，而是使用 `backing_dev_info->io_pages`（指示单次 I/O 操作中检索的最优页数）作为最大页数。

一旦确立了初始状态，我们开始启发式地确定我们处于预读的什么位置以及如何继续，我们将在列表 9-71 中进行探讨。

```c
/*
 * 文件开始
 */
if (!index)
    goto initial_readahead;

/*
 * 这是预期的回调索引，假设为顺序访问。
 * 增加大小，并向前推进预读窗口。
 */
expected = round_up(ra->start + ra->size + ra->async_size,
                    1UL << order);
if (index == expected || index == (ra->start + ra->size)) {
    ra->start += ra->size;
    ra->size = get_next_size(ra, max_pages);
    ra->async_size = ra->size;
    goto reread;
}

/*
 * 命中一个没有有效预读状态的标记 folio。
 * 例如：交错读取。
 * 查询页缓存的 async_size，它通常等于
 * 预读大小。增大它并将其作为新的预读大小。
 */
if (folio) {
    pgoff_t start;
    rcu_read_lock();
    start = page_cache_next_miss(ractl->mapping, index + 1,
                                max_pages);
    rcu_read_unlock();
    if (!start || start > max_pages)
        return;
    ra->start = start;
    ra->size = start - index; /* 旧的 async_size */
    ra->size += req_size;
    ra->size = get_next_size(ra, max_pages);
    ra->async_size = ra->size;
    goto reread;
}

/*
 * 越尺寸读取
 */
if (req_size > max_pages)
    goto initial_readahead;

/*
 * 顺序缓存缺失
 * 简单情况：(index - prev_index) == 1
 * 未对齐读取：(index - prev_index) == 0
 */
prev_index = (unsigned long long)ra->prev_pos >> PAGE_SHIFT;
if (index - prev_index < 1L)
    goto initial_readahead;

/*
 * 查询页缓存以及顺序访问会留下的
 * 痕迹（缓存的历史页）。
 */
if (try_context_readahead(ractl->mapping, ra, index, req_size, max_pages))
    goto readahead;
```

## 列表 9-74: `mm/readahead.c`

```c
static pgoff_t count_history_pages(struct address_space *mapping,
                                   pgoff_t index, unsigned long max)
{
    pgoff_t head;
    rcu_read_lock();
    head = page_cache_prev_miss(mapping, index - 1, max);
    rcu_read_unlock();
    return index - 1 - head;
}
```

该函数使用 `page_cache_prev_miss()` 通过描述 `struct address_space` 的页缓存对象的 xarray 扫描对象，返回第一个条目的索引，该索引从缓存中不存在的索引 -1 开始计算。从 `index - 1` 减即可得到连续范围。最后，在所有这些启发式策略都应用后，我们继续实际执行 `readahead`，如下方的列表 9-75 所示。

```c
/*
 * 独立的、小型随机读取
 * 原样读取，不污染 readahead 状态。
 */
do_page_cache_ra(ractl, req_size, 0);
return;

initial_readahead:
ra->start = index;
ra->size = get_init_ra_size(req_size, max_pages);
ra->async_size = ra->size > req_size ? ra->size - req_size : ra->size;

readahead:
/*
 * 这是否会命中由自己创建的预读标记
 * 如果是，则现在触发预读标记命中，并将
 * 下一个结果的预读窗口合并到当前窗口中。
 * 像上面一样处理最大 10 个页。
 */
if (index == ra->start && ra->size == ra->async_size) {
    add_pages = get_next_ra_size(ra, max_pages);
    if ((ra->size) + add_pages <= max_pages) {
        ra->async_size = add_pages;
        ra->size += add_pages;
    } else {
        ra->size = max_pages;
    }
}

ra->async_size = max_pages >> 1;
ractl->index = ra->start;
page_cache_ra_order(ractl, ra, order);
```

## 列表 9-75: `mm/readahead.c`: `ondemand_readahead()` 的 readahead 调用
