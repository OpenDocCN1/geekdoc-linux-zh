
变量名可以是任何不包含 `:`、`=` 或开头/结尾空格的字符序列。然而，应避免使用包含字母、数字和下划线以外字符的变量，因为它们在未来可能具有特殊含义，并且在某些 shell 中，它们无法通过环境传递给子 make（参见第 5.6.2 节 [将变量传递给子 make]，第 47 页）。

变量名是大小写敏感的。名称 `foo`、`FOO` 和 `Foo` 都指向不同的变量。

在变量名中使用大写字母是传统做法，但我们建议对 Makefile 内部用途的变量使用小写字母，并为用户可以通过命令行选项覆盖的参数保留大写字母（参见第 9.5 节 [覆盖变量]，第 93 页）。

有几个变量名是单个标点字符或几个字符。这些是自动变量，它们有特定的专门用途。参见第 10.5.3 节 [自动变量]，第 111 页。

### 6.1 变量引用的基础

要替换变量的值，写一个美元符号后跟括号内的变量名，或者：`$(foo)` 或 `${foo}` 都是对变量 `foo` 的有效引用。`'$'` 的这种特殊含义解释了为什么如果你在文件名或命令中想获得单个美元符号的效果，必须编写 `'$$'`。

变量引用可以使用于任何语文中：目标、前提、命令、大多数指令以及新变量值。这里有一个常见情况的示例，其中变量持有程序中所有对象文件的名称：

```
objects = program.foo foo.o utils
program : $(objects)
  cc -o program $(objects)

$(objects) : defs.h
```

变量引用通过严格的文本替换工作。因此，值

```
foo = c

prog.o : prog.foo $(foo) prog.$(foo)
```

可以用于编译 C 语言程序 `prog.c`。由于变量赋值中值之前的空格会被忽略，因此 `foo` 的值精确地为 `c`。（不要真的这样写你的 Makefile！）

美元符号后如果跟一个不是美元符号、左括号或左大括号的字符，会将该单个字符视为变量名。因此，你可以用 `$x` 引用变量 `x`。然而，这种做法被强烈不建议，除非是自动变量的情况（参见第 10.5.3 节 [自动变量]，第 111 页）。

### 6.2 变量的两种类型

GNU make 中的变量有两种方式获得值；我们称它们为变量的两种类型。这两种类型的区别在于如何定义它们以及在展开时的行为。

第一种类型的变量是**递归展开变量**。这类变量通过使用 `=` 的行（参见第 6.5 节 [设置变量]，第 62 页）或 `define` 指令定义（参见第 6.8 节 [逐字定义变量]）。你指定的值原样安装；如果它保留了对其他变量的引用，每当该变量被替换时（在展开某些其他字符串的过程中），这些引用就会被展开。当这种情况发生时，被称为递归展开。

例如，

```
foo = $(bar)
bar = $(ugh)
ugh = Huh?

all:echo $(foo)
```

将 echo `Huh?`： `$(foo)` 展开为 `$(bar)`，其展开为 `$(ugh)`，最后展开为 `Huh?`

这种类型的变量是其他版本 make 支持的。它有其优缺点。一个优点（我会说）是：

```
CFLAGS = $(include_dirs) -0
include_dirs = -Ifoo -Ibar
```

将按预期工作：`CFLAGS` 在命令中被展开时，它将展开为 `-Ifoo-Ibar -0`。一个主要的缺点是你不能在变量的末尾添加内容，例如：

```
CFLAGS = $(CFLAGS) -0
```

因为这会导致变量展开出现无限循环。（实际上会检测到无限循环并报告错误。）

另一个缺点是，定义中引用的任何函数（参见第 8 章 [文本转换函数]，第 75 页）会在每次变量展开时执行。这使得 make 运行得更慢；它使用通配符和 shell 函数来产生不可预测的结果，因为你无法容易控制何时调用它们或调用多少次。

为了避免递归展开变量的所有问题和不便，还有另一种类型：**简单展开变量**。

简单展开变量通过使用 `:=` 的行定义（参见第 6.5 节 [变量]，第 62 页）。简单展开变量的值会被扫描一次，在定义时就展开对其他变量的任何引用。简单展开变量的值是你所写的文本展开的结果。

这等同于

```
x := foo
y := later
```

上一个示例展示了两个层嵌套，但任何层数的嵌套都是可能的。例如，这里有三层：

```
x = y
y = z
z = u
a := $(($x))
```

最终，最内层的 `$(x)` 展开为 `y`，因此 `$(x)` 展开为 `$(y)`，接着展开为 `z`；现在我们有了 `$(z)`，它变成了 `u`。

变量名内部递归展开变量的引用将以通常的方式重新展开。例如：

```
x = $(y)
y = z
z = Hello
a := $(($x))
```

定义 `a` 为 `Hello`： `$(x)` 变成 `$(y)`， 变成 `$(z)`，最后变成 `Hello`。

嵌套的变量引用也可以包含修改后的引用和函数调用（见第 8 章 [用于转换的函数]，第 75 页），就像其他引用一样。例如，使用 `subst` 函数（见第 8.2 节 [字符串替换与分析函数]，第 76 页）：

```
x = variable1
variable2 := Hello
y = $(subst 1,2,$(x))
z = y
a := $(($($z))
```

最终定义 as 为 `Hello`。很难说有人会写出像这样复杂的嵌套引用，但它是可以的：`$(($($z))` 展开为 `$(y))`，然后变成 `$(subst 1,2,$(x))`。这从 `x` 中获取了值 `variable1`并通过替换更改为 `variable2`，使得整个字符串变成了 `$(variable2)`，这是一个简单的变量引用，其值为 `Hello`。

计算得的变量名不需要完全由单个变量引用组成。它可以包含多个变量引用，以及一些不变的文本。例如：

```
a_dirs := dira dirb
1_dirs := dirl dir2
a_files := filea fileb
1_files := file1 file2
```

## 第 6 章：如何使用变量

```
ifeq "$(use_a)" "yes"
a1 := a
else
a1 := 1
endif
eq "$(use_dirs)" "yes"
df := dirs
else
df := files
endif
```

`dirs := $((a1)) $((df))`

将根据 `use_a` 和 `use_dirs` 的设置，为 `dirs` 赋予与 `a_dirs`、`1_dirs`、`a_files` 或 `1_files` 相同的值。

计算得的变量名也可以用于替换引用：

```
a_objects := a.o b.o c.o
1_objects := 1.0 2.0 3.0
```

`sources := $((a1)_objects):.c`

根据 `a1` 的值，将 `sources` 定义为 `a.c b.c c.c` 或 `1.c 2.c 2.c 3.c`。

这种嵌套变量引唯一限制是它们不能指定要调用函数名称的一部分。这是因为对已识别函数名的测试是在嵌套引用展开之前完成的。例如：

```
ifdef do_sort
func := sort
else
func := strip
endif
```

```
bar := a d b g q c $(bar)
```

`foo := $((func)`

尝试将 `foo` 赋值为变量 `sort a d b g q c` 或 `strip a d b g q c` 的值，而不是将 `a d b g q c` 作为参数传递给 `sort` 或 `strip` 函数。如果这种更改被证明是一个好主意，未来可以移除此限制。

你也可以在变量赋值的左侧或 `define` 指令中使用计算出的变量名，例如：

```
dir := foo
$(dir)_sources := $(wildcard $(dir)/.c
define $(dir)_print
```

62 GNU make

```
lpr $((dir)_sources)
define
```

这定义了变量 `dir`、`dir_sources` 和 `dir_print`。

注意，嵌套引用与递归展开变量（见 6.2 节 [变量的类型]，第 56 页）有很大不同，尽管在复杂的 Makefile 中都会使用。

### 6.4 变量如何获取值

变量通过以下不同的方式获取值：

- 在执行时指定值（见 9.5 节 [覆盖变量]，第 93 页）。
- 在 Makefile 中指定值（见 6.5 节 [设置变量]，第 62 页），或者使用字面量定义（见第 65 页）。
- 通过环境变量设置值（见 6.9 节 [环境变量]，第 66 页）。
- 具有内置初始值（见 10.3 节 [隐式规则变量]，第 106 页）。
- 通过赋值获取值（见 10.5 节 [自动变量]，第 111 页）。
