
让我们看看如何改进这种设计。首先，通过加引号确保 `$dir_name` 变量只扩展为一个单词，并让 `rm` 的执行取决于 `cd` 的成功，这可能是明智的。

```bash
cd "$dir_name" && rm *
```

这样，如果 `cd` 命令失败，就不会执行 `rm` 命令。这更好，但留下了变量 `$dir_name` 未设置或为空的可能，这会导致用户主目录中的文件被删除。这通过检查 `$dir_name` 确实包含一个存在的目录也可以避免。

```bash
[[ -d "$dir_name" ]] && cd "$dir_name" *
```

通常，最好的办法是在之前发生的情况时包含逻辑来终止脚本并报告错误。

```bash
# 删除 $dir_name 目录中的文件
if [[ ! -d "$dir_name" ]]; then
    echo "No such directory: $dir_name" >&2
    exit 1
fi

if ! cd "$dir_name"; then
    echo "无法进入目录 $dir_name" >&2
    exit 1
fi

if ! rm *; then
    echo "文件删除失败。检查结果" >&2
    exit 1
fi
```

在这里，我们检查名称以确认它是一个现有目录，以及 `cd` 命令是否执行成功。如果其中任何一个失败，将向标准错误发送一条描述性错误信息，脚本将以退出状态一终止，以表示失败。

## set -e, set -u, and set -o pipefail

关于 `bash`，我们需要注意的一点是，当脚本执行且命令失败时（不包括脚本本身的语法错误），脚本会“乐意地”继续执行下一个命令。这通常是不符合预期的，POSIX 标准以及随后的 `bash` 试图解决这个问题。`bash` 提供了一项可以自动处理错误的设置，简单来说，意味着在启用此设置后，如果任何命令（在某些必要的例外之外）返回非零退出状态，脚本将终止。要调用此设置，我们在脚本开头附近放置 `-e` 命令。一些 `bash` 编码标准坚持在使用此功能的同时配合几个相关的设置一起使用：`set -u`（当存在未初始化的变量时终止脚本）以及 `set -o pipefail`（当管道中的最后一个元素执行失败时导致脚本终止）。

不建议使用这些功能。更好的做法是设计适当错误处理，而不是依赖 `set -e` 来替代良好的编码实践。

`Bash` 答 #105 (https://mwwiki.wodledge.org/BashFAQ/105) 对此提供了以下观点：

> `set -e` 曾尝试取消 shell 的“自动错误检测”。你的目标是让 shell 在发生错误时终止，而不需要在每个重要命令后面都加上 `exit`。

这个目标并非那么易事，因为许多命令会特意返回非零。例如：

`if [ -d foo ]; then ... else; fi`

显然，当 `[ -d foo ]` 命令返回非零时（因为目录不存在），我们并不希望退出——我们的脚本想要在 `else` 部分处理它。实现者决定制定了一系列特殊规则，“作为 if 测试一部分的命令是免疫的”，或者“管道中的命令，除了最后一个之外，统统都是免疫的”。这些规则极其复杂，而且它们仍然无法捕获一些非常简单的情况。更糟糕的是，规则会随着 `bash` 版本的更新而变化，因为 `bash` 试图追踪这一“功能”中极其难以捉摸的 POSIX 定义：当调用子 shell 时，情况更糟了——行为取决于 `bash` 是否在 POSIX 模式下被调用。

## ShellCheck 是你的朋友

许多发行版仓库中都有名为 `shellcheck` 的程序，它可以对 shell 脚本进行分析并检测许多故障和糟糕的脚本实践。检查我们脚本的质量是非常值得的。要在带有 shebang 的脚本中使用它，我们只需这样做：

```bash
shellcheck my_script
```

`ShellCheck` 会自动检测哪些 shell 不包含 shebang（例如函数库），我们可以根据 shebang 来使用它。对于测试脚本，我们可以这样使用 `ShellCheck`：

```bash
shellcheck -s bash my_library
```

使用 `-s` 选项来指定所需的 shell 方言。关于 `ShellCheck` 的更多信息，可以访问其网站：https://www.shellcheck.net。

## 注意文件名

这个文件删除脚本还有另一个更隐晦但可能非常危险的问题。Unix（或类 Unix 操作系统）在文件名方面的权限极度宽松，这存在一个严重的设计缺陷。事实上，只有两个字符不能包含在文件名。第一个是 `/` 字符（零字节），它在内部用于标记字符串的结束；第二个是空字符（零字节）。其他所有内容都是合，包括空格、制表符、换行符、前导连字符、回车符等。

特别需要关注的是前导连字符。例如，拥有名为 `-rf-` 的文件是完全合法的。考虑一下当文件名传递给 `rm` 时会发生什么。

为了防止这个问题，我们把文件删除脚本中的 `rm` 命令从：

```bash
rm *
```

改为：

```bash
rm ./*
```

这将防止以连字符开头的的文件名被解释为命令选项。作为一个通用规则，始终在通配符（如 `*` 和 `?`）之前加上 `/`，以防止命令误解。这包括像 `*.pdf` 和 `???.mp3` 等内容。

## 可移植文件名

为了确保文件名在多个平台之间（即不同类型的计算机和操作系统）具有可移植性，需要限制文件名包含的字符。有一个名为 POSIX 可移植文件名字符集的标准，可以最大限度地增加文件名在不同系统中运行的机会。该标准非常简单。允许的字符只有大写字母 A 到 Z、小写字母 a 到 z、数字 0 到 9、点 (`.`)、连字符 (`-`) 和下划线 (`_`)。标准进一步建议文件名不应连字符开头。

## 验证输入

```bash

这是非常具体的。只有当用户输入的字符串是零到三之间的数字时，它才会返回零退出状态。其他任何都不会被接受。有时这类测试编写起来很有挑战性，但为了产生高质量的脚本，这种努力是必要的。

## 调试

如果测试发现脚本存在问题，下一步是调试。“问题”通常意味着脚本以某种方式没有按照编程人员的预期运行。如果是这样，我们需要确定脚本实际上在做什么以及为什么。寻找 bug 有时可能涉及大量的侦查工作。

设计良好的脚本会尝试提供帮助。它应该是防御性编程，以检测异常情况并向用户提供有用的反馈。然而，有时问题非常奇怪且出乎意料，需要更复杂的技巧。

### 寻找问题区域

在某些脚本中（特别是长脚本），将与问题相关的脚本区域隔离出来有时很有用。这并不总是真正的错误所在，但隔离通常可以为了解实际原因提供线索。我们就可以用于隔离代码的一种技术是“注释掉”脚本的章节。例如，我们可以修改文件删除片段，以确定被移除的区域是否与错误有关。

```
if [[ -d $dir_name ]]; then
    if cd $dir_name; then
        rm *
    else
        echo "cannot cd to $dir_name" >&2
        exit 1
    fi
# else
    echo "no such directory: $dir_name" >&2
    exit 1
fi
```

通过在脚本中逻辑部分的每行开头放置注释符号，我们可以阻止脚本执行。然后可以再次进行测试，查看删除代码对错误行为是否有任何影响。

### 追踪 (Tracing)

Bug 往往是脚本内部出现意外逻辑流的情况。也就是说，脚本的部分要么从未被执行，要么以错误的顺序或在错误的时间执行。为了查看程序的实际流，我们使用一种名为*追踪*的技术。

一种追踪方法涉及在脚本中放置信息性消息，以显示执行位置。我们可以向代码片段中添加消息。

```
echo "preparing to delete files" >&2
if [[ -d $dir_name ]]; then
    if cd $dir_name; then
        echo "deleting files" >&2
        rm *
    else
        echo "cannot cd to $dir_name" >&2
        exit 1
    fi
else
    echo "no such directory: $dir_name" >&2
    exit 1
fi
```

echo "file deletion complete" >&2

我们将消息发送到标准错误（stderr），以便将其与正常输出分开。我们也没有对包含消息的行进行缩进，这样在需要删除它们时更容易找到。

现在当执行脚本时，可以看到文件删除已经执行。

```
@melinuxbox ~$ deletion-script
preparing to delete files
deleting files
file deletion complete
@melinuxbox ~$ 
```

`bash` 还提供了另一种追踪方法，通过 `-x` 选项以及带有 `-x` 选项的 `set` 命令实现。使用我们之前的故障脚本，可以通过在第一行添加 `-x` 选项来激活整个脚本的追踪。

```bash
#!/bin/bash -x
```

### trouble：演示常见错误的脚本

```

```
if [ $Number = 1 ]; then
  echo "Number is equal to 1."
else

```

通过追踪，我们可以看到应用了扩展后的执行命令。开头的加号表示显示追踪，以便将其与普通输出行区分开。加号是追踪输出的默认字符。它包含在 `PS4`（提示符字符串 4） shell 变量中。可以调整该变量的内容以使提示符更有用。在这里，我们修改了变量的内容，包含了执行脚本时的当前脚本行号。注意，需要单引号来防止在提示符使用之前展开。

```
@melinuxbox ~$ export PS4='$LINENO + ' '

```

```

为了对脚本的选部分而非整个脚本进行追踪，可以使用带有 `-x` 选项的 `set` 命令。

```bash
#!/bin/bash

# trouble:演示常见错误的脚本

number=1

set -x # 开启追踪
if [ $number = 1 ]; then
    echo "Number is equal to 1."
else
    echo "Number is not equal to 1."
fi
set +x # 关闭追踪
```

我们使用带有 `-x` 选项的 `set` 命令激活追踪，使用带有 `+x` 选项禁用追踪。这种技术可以用于检查故障脚本的多个部分。

### 在执行期间检查值

在追踪时，显示变量的内容以查看脚本执行期间的内部工作原理通常很有用。添加额外的 `echo` 语句通常可以解决问题。

```bash
#!/bin/bash

# trouble:演示常见错误的脚本

number=1

echo "number=$number" DEBUG
set -x # 开启追踪
if [ $number = 1 ]; then
    echo "Number is equal to 1."
else
    echo "Number is not equal to 1."
fi
set +x # 关闭追踪
```

在这个简单的示例中，我们只是显示了变量 `number` 的值，并为添加的行标记了注释，以便稍后识别和删除。这种技术在观察脚本中循环和算术的行为时特别有用。

## 总结

在本章中，我们查看了开发过程中可能出现的少数问题。这里描述的技术将使能够更有效地发现 Bug。

```bash
#!/bin/bash

read -r -p "enter word > " 

case "$REPLY" in
  [[:alpha:]]) echo "is a single alphabetical character."; ;
  [ABC[0-9]]) echo "is A, B, or C followed by a digit."; ;
  ???) echo "is three characters long."; ;
  *.txt) echo "is a word ending in '.txt'"; ;
  \*) echo "is something else."; ;
esac
```

也可以使用竖线字符 `|` 作为分隔符来组合多个模式。这创建了一个“或”逻辑条件模式。这对于同时处理大写字母和小写字母的情况非常有用。这里是一个示例：

```bash
#!/bin/bash

case-menu: a menu driven system information program

clear
echo ""
echo "nPlease Select:"

+   A. Display System Information
+   B. Display Disk Space
+   C. Display Home Space Utilization
+   Q. Quit

```bash

read -r -p "Enter selection [A, B, C or Q] " 

case "$REPLY" in

  q|Q) echo "Program terminated."

    exit

    ;;

  a|A) echo "Hostname: HOSTNAME"

    uptime

    ;;

  b|B) df -h

    ;;

  c|C) if [ "$(id -u)" -eq 0 ]; then

    echo "Home Space Utilization (All Users)"

    du -sh /home/*

  else

    echo "Home Space Utilization ($USER)"

    du -sh "$HOME"

  fi

    ;;

  *) echo "Invalid entry" >&2

    exit 1

    ;;

esac

```

在这里，我们修改了 `case-menu` 程序，使用字母而不是数字进行菜单选择。注意新模式允许输入大写字母和小写字母。

### 执行多个操作

在 `bash` 4.0 之前的版本中，`case` 在匹配成功后只允许执行一个操作。匹配成功后，命令就会终止。这里我们看到一个测试字符的脚本：

```bash

#!/bin/bash

# case-1: test a character

read -r n 1 -p "Type a character > "

  [[upper:]]) echo "$REPLY" is upper case.";

  [[lower:]]) echo "$REPLY" is lower case.";

  [[alpha:]]) echo "$REPLY" is alphabetic.";

  [[digit:]]) echo "$REPLY" is a digit.";
```
