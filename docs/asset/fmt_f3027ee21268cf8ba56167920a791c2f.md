# 低级 I/O

GNU/LINUX 程序员有两套输入输出函数供选择。标准 C 库提供了 I/O 函数，如 `printf`、`fopen` 等。Linux 内核本身提供了另一组 I/O 操作，其层级低于 C 库函数。

由于本书是面向熟悉 C 语言的人的，我们假设你已经接触并知道如何使用 C 库 I/O 函数。这些通常是内核系统调用，为应用程序提供了直接访问底层系统的能力。事实上，标准 C 库 I/O 程序是基于 Linux 低级 I/O 系统调用实现的的。使用后者通常是执行输入输出操作最高效的方法——有时也更方便。

- 1. 参见第 8 章“Linux 系统调用”，以了解系统调用与普通函数调用之间的区别。

## B.1 数据的读取与写入

你可以通过将此值与一个或多个标志进行按位或操作来指定额外的选项。这些是最常用的：

- 指定 `O_TRUNC` 以截断已打开的文件（如果该文件之前存在）。写入文件描述符的数据将替换文件之前的内容。
- 指定 `O_APPEND` 向现有文件追加内容。写入文件描述符的数据将添加到文件的末尾。
- 指定 `O_CREATE` 创建新文件。如果你提供的文件名不存在，则将创建一个新文件，前提是该文件所在的目录存在，且该进程有权在该目录中创建文件。如果文件已存在，则将打开它。
- 将 `O_EXCL` 配合 `O_CREATE` 使用强制创建一个新文件。如果文件已存在，则 `open` 将失败。

如果你用带有 `O_CREATE` 运行 `open`，请提供一个额外的参数来指定新文件的权限。请参阅第 10 章“安全”第 10.3 节“文件系统权限”，获取关于权限位及其如何使用的法的描述。

例如，列表 B.1 中的程序根据命令行上指定的文件名创建一个新文件。如果你在 `open` 中使用 `O_EXCL` 标志，如果文件已存在，就会发生错误。新文件将赋予所有者和所属组读写权限，并仅赋予其他人读取权限（如果你的 `umask` 设置为非零值，实际权限可能会更加严格）。

### Umasks（掩码）

当你用 `open` 创建新文件时，你指定的某些权限位可能会被关闭。这是因为你的 `umask` 设置为了非零值。进程的 `umask` 指定了所有新创建文件中被掩码的位。实际使用的权限是你指定的 `open` 权限与 `umask` 组件进行按位与运算的结果。

要从 shell 更改 `umask`，请使用 `umask` 命令并指定八进制表示的 `umask` 数值。要更改运行进程的 `umask`，请使用 `umask` 调用，为后续的 `open` 调用传递所需的值。

例如，在程序中调用此行：

```
umask (S_IRIXGO | S_IWGRP);
```

或者调用此命令：

```
% umask 027
```

这指定组成员的写权限以及他人的读、写、执行权限将始终从新文件的权限中掩码掉。

## B.1.2 关闭文件描述符

当你完成对文件描述符的操作后，使用 `close` 将关闭。在某些情况下，例如列表 B.1 中的程序，没有必要显式调用；Linux 在程序终止时（即程序结束时）会关闭所有文件描述符。当然，一旦你关闭了文件描述符，就不应该再使用它。

关闭文件描述符可能允许 Linux 执行特定操作，取决于文件描述符的性质。例如，当你关闭网络套接的文件描述符时，Linux 会关闭通过该套接通信的两个计算机之间的网络连接。

Linux 限制了一个进程同时打开的文件描述符数量。打开的文件描述符使用内核资源，因此在使用完毕后关闭它们是良好的习惯。典型的限制是每个进程 1,024 个描述符。你可以使用 `setlimit` 系统调用调整此限制；更多信息请参阅第 8.5 节“getlimit and setlimit: 资源限制”。

## B.1.3 写入数据

使用 `write` 调用向文件描述符写入数据。提供文件描述符、数据缓冲区指针以及要写入的字节数。文件描述符必须处于可写状态。写入文件的数据不需要是字符字符串；从缓冲区将任意字节写入文件描述符即可。

列表 B.2 中的程序将当前时间追加到命令行指定的文件。如果文件不存在，则会创建它。该程序还使用了 `time`、`localtime` 和 `asctime` 函数来获取并格式化当前时间；更多信息请参阅各自的页面。

### 列表 B.3 (write-all.c) 写入缓冲区的所有

```
#include <fcntl.h>
#include <stdio.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>
#include <assert.h>

/* 写入缓冲区的所有字节。 */
size_t write_all (int fd, const void* buffer, size_t count)
{
    size_t left_to_write = count;
    while (left_to_write > 0) {
        size_t written = write(fd, buffer, count);
        if (written == -1)
            /* 发生错误； */
            return -1;
        else
            /* 还需要写入的。 */
            left_to_write -= written;
    }
    /* 确保全部写入。 */
    return count;
}
```

## B.1.4 读取数据

使用 `read` 调用从文件描述符读取数据。提供文件描述符、缓冲区指针以及要读取的字节数。文件描述符必须处于可读状态。写入文件的数据不需要是字符字符串；从文件描述符读取任意字节到缓冲区。

`read` 返回 -1 或实际读取的字节数。注意，如果文件中没有足够的字节，读取结果可能小于请求的字节数。

### DOS/Windows 文本文件

完本书之后，我们确定你会为 GNU/Linux 选择所有程序。然而，你的程序可能需要读取由 Windows 程序生成的文件。预测这两个平台之间文本结构的差异很重要。

在 GNU/Linux 文本文件中，每行由换行符分隔。换行符由 `\n` 表示，其 ASCII 码为 10。在 Windows 上，行由两个字符组合分隔：回车（`\r`，ASCII 码为 13）后跟换行符。

某些 GNU/Linux 编辑器在显示 Windows 文件时会在行尾显示 M——这就是回车字符。Emacs 可以正确显示 Windows 文件，但通过在缓冲区底部显示 (DOS) 来指示。某些 Windows 编辑器（如 Notepad）会将 GNU/Linux 文本文件显示在单行内，因为它们期望行尾有回车。其他处理文本文件的程序在给定格式错误的输入文件时可能会报告奇怪的错误。

如果你的程序读取 Windows 程序生成的文件，你可能希望将 `\r` 替换为换行符。同样，如果你的程序写入必须被 Windows 程序读取的文本文件，请将换行符替换为 `\r\n` 组合。无论你是使用附录中介绍的底层 I/O 调用还是标准 库 I/O 函数，都必须这样做。
