
为了部署我们的第一台虚拟机，我们首先需要创建一个文件，用作虚拟存储的后端。QEMU 支持多种格式；原始图像最快，但现代`qcow2`格式并不慢，对磁盘或电源故障更具韧性，并支持快照。所以让我们用它创建一个 10GB 的图像：

```bash
qemu-img create -f qcow2 10gbqcow2 10G
```

`qemu-img`命令还可以转换、调整磁盘图像的大小等，因此请查阅手册页了解更多。与`VirtualBox`一样，我们需要某种安装介质来开始。这是一个机会，获取一个您本来不敢在裸机上尝试的发行版的ISO文件（来吧，试试 Linux 从零开始，这能有多难？），但我们将稍微讲究一点，试用一个每日构建的Ubuntu Server 20.04镜像。你可以从`http://cdimage.ubuntu.com/ubuntu-server/daily-live/current`获取这样的镜像。

现在我们可以开始安装了，如果安装介质和`qcow2`文件不在当前目录，请调整安装介质和`qcow2`文件的路径：

```bash
$ qemu-system-x86_64 -cdrom focal-live-server-amd64.iso -boot order=d -drive file=b.qcow2 -m 1G
```

默认情况下，`QEMU`仅为其创建的机器分配 128MB 内存，事实证明这远远不足以启动 Ubuntu。末尾的`-m`选项分配了 1GB，从而解决了这个问题。应该会打开一个窗口，你可以点击该窗口来导航设置问题。默认情况下，`QEMU`提供 NAT 和 DHCP 服务，并将为虚拟机设置形如`10.0.2.<number>`的 IP 地址，这通常能正常工作。然后我们选择了“使用整个磁盘”选项，以避免不必要的分区。Ubuntu 可以为你自动设置 SSH，这通常是一件好事™，但我们稍后会看到使用`QEMU`进行主机到客户机的网络通信很棘手；它还提供一个流行的snaps列表，所以随意安装你认为可能感兴趣的内容。如果你计划让虚拟机执行任何稍微费力的操作，你可能想要增加 1GB 内存并扩大镜像文件。

在安装进行期间，或者任何时候`QEMU`窗口打开时，你可以按下`Ctrl+Alt+2`来显示`QEMU`监控器，它允许你评估`QEMU`的状态。这样做后，输入`info kvm`来查看是否在使用`KVM`。你可能发现它并没有使用，这意味着我们正在模拟一台机器，而不是虚拟化它。哎呀。这在一定程度上解释了这种缓慢，并且只需一个命令行开关即可激活`KVM`。使用菜单或`Ctrl+Alt+1`返回虚拟机。安装完成后，关闭虚拟机。它确实提供了重新启动的选项，但请转到“机器”菜单并点击“关机”。正如标题栏告诉你的那样，如果鼠标被卡在虚拟机窗口中，请使用`Ctrl+Alt+G`来“脱离”鼠标。

### VIRTIO

我们提到`QEMU`/`KVM`二元体中`QEMU`的职责是模拟硬件，并且我们暗示这是一个相对缓慢的过程。因此，与其模拟这些东西，不如告诉虚拟化操作系统它是虚拟的，并且它看到的硬件不是真实的。这样，我们修改操作系统（或在这种情况下是其设备驱动程序），并让hypervisor呈现抽象的半虚拟化硬件，双方共同协作以妥善处理。`KVM`用于这种魔法的框架称为`virtio`，其驱动程序支持块设备、显卡、网络设备和名为气球设备（用于内存管理）的有趣命名的设备的半虚拟化。`virtio`驱动程序需要在来宾系统上安装，但它们长期以来一直是 Linux 内核的一部分——因此对于 Linux 来宾系统无需操作。

```bash
qemu-system-x86_64 -drive file=10gbqcow2,format=qcow2,if=virtio -net nic,model=virtio -m 1G -enable-kvm
```

如果在来宾系统中运行：

```bash
lspci
```

您会看到您的虚拟机现在拥有由`virtio`支持的显卡、以太网和 SCSI 磁盘。为了利用改进的虚拟视频设备，您需要安装桌面环境，您可以使用以下命令完成：

```bash
sudo apt install ubuntu-gnome-desktop
```

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_71_0.png)

QEMU 起初看起来不起眼，但它功能强大，使您能够在不承担报复风险的情况下执行破坏性操作。

现在使用正确的命令启动机器：

```bash
$ qemu-system-x86_64 -drive file=lfs.qcow2,format=qcow2 -m 1G -enable-kvm
```

并使用之前创建的凭据登录。Ubuntu 会告诉你它的 IPv4 和 IPv6 地址，但如果你尝试从主机 SSH 登录，你会发现它不起作用。`QEMU`的默认网络设置允许客户机访问主机上的服务（在地址`10.0.2.2`），但反之则不然。在此配置中，不同客户机之间的通信也是不可能的。我们可以深入研究设置`tap`设备（虚拟网络接口）或仅主机网络配置的方方面面，但由于我们将讨论`Libvirt`（它可以轻松完成所有这些操作），我们将参考 Arch Wiki 关于`QEMU`的页面，特别是冗长的“网络”部分。参见`https://wiki.archlinux.org/index.php/QEMU`。

### 不要害怕模拟器

> “QEMU 是一个模拟器，但我们会看到它实际需要进行模拟的量可以减少到几乎为零。”

如果你真的只是想要一个易于 SSH 连接的虚拟机，你可以使用`QEMU`的桥接助手来帮助你（对于有线连接）。这涉及创建一个名为`/etc/qemu/bridge.conf`的文件，其中只有一行：

```
allow bridge0
```

现在我们必须创建网桥，将我们的以太网连接（在我们的情况下是`enp3s0`）添加到其中，并将其连接到外部世界。如果你的发行版使用`NetworkManager`（很可能如此），最好使用`nmcli`而不是较低级别的`ip`命令来执行此操作：

```bash
$ sudo nmcli connection add type bridge ifname bridge0 stp no
$ sudo nmcli connection add type bridge-slave ifname enp3s0 master bridge0
$ sudo nmcli connection up bridge-bridge0
```

然后使用以下命令启动`QEMU`：

```bash
$ qemu-system-x86_64 -drive file=lfs.qcow2,format=qcow2 -m 1G -enable-kvm -net nic -net bridge,br=bridge0
```

这意味着你的虚拟机将加入与主机相同的网络，并从你的家庭路由器获取 IP。同样的效果可以通过访问`VirtualBox`虚拟机的网络设置并将适配器类型从 NAT 更改为“桥接适配器”来实现。

一旦安装了`virtio`驱动程序，我们为我们的 Ubuntu Server 20.04 虚拟机增加了 2GB 内存。

## 进入 Libvirt 的世界

将所有的部分整合在一起，向你展示如何让虚拟化更快、更容易、更安全。

你现在可能已经意识到，一旦开始避免使用默认设置，QEMU 的咒语可能会变得非常繁琐——因此，人们通常会将这些存储在一个脚本中，或者使用某种 QEMU 的前端。整理这个问题的现代方式是使用红帽的`Libvirt`。这不是一个前端——我们很快会遇到`Virtual Machine Manager`，它才是——而是一个通过其守护进程`libvirtd`提供对虚拟化功能访问的 API。`Libvirt`支持多个hypervisor，包括`KVM`和`VirtualBox`。

对于外行来说，这可能会在已经足够复杂的东西上增加另一层复杂性。这是一个合理的观点；如果你只是想设置一个虚拟机来尝试偶尔使用的 Linux 发行版，使用`VirtualBox`或其他友好的前端很容易做到。`Libvirt`的真正优势在于管理。它可以处理存储（调整虚拟磁盘大小或创建池）、网络（无需手动制作网络桥接的麻烦），并且当然可以创建、启动和停止虚拟机。在某种程度上，它还让用户免于处理运行虚拟机的业务，这通常是一件好事。

假设我们正在我们最喜欢的桌面环境中运行一个虚拟机，某样东西崩溃了，迫使我们注销。返回到该虚拟机时，我们可能会发现它处于糟糕的状态，因为运行它的进程（`QEMU`或`VirtualBox`）已经被清除。
