
我们可以在终端会话期间任何时候通过简单反转过程来恢复原始提示符。

```bash
me@linuxbox~$ PS1="$PS1_old"
```

现在我们准备好继续了，让我们看看如果提示符字符串为空会发生什么。

```bash
me@linuxbox~$ PS1=
```

如果我们不对提示符字符串赋值任何内容，我们就什么也得不到。没有任何提示符字符串！提示符仍然在那里，但什么都不显示，正如我们要求这样做的那样。由于这看起来有点不安，我们将用一个最小提示符来替换它。

```bash
PS1="\$ "
```

就是这样。至少现在我们可以看到自己在做什么了。注意双引号内的末尾空格。这在显示提示符时提供了美元符号和光标之间的空隙。

让我们在提示符中添加一个蜂铃声。

```bash
PS1="\\a\$"
```

现在，每次显示提示符时我们都应该听到哔哔声，尽管某些系统禁用了这个“功能”。这可能会令人心烦，但如果在执行了特别耗时的命令时需要通知的话。注意，我们包含了 `\[` 和 `\]` 序列。由于 ASCII 蜂铃 (`\a`) 并不“打印”，也就是说它不会移动光标，因此我们需要告诉 `bash`，这样它就能正确确定提示符的长度。

接下来，让我们创建一个包含主机名和时间信息的描述性丰富的提示符。

```bash
$ PS1="\h \u \$"
17:33 \linuxbox $
```

如果我们需要跟踪执行某些任务的时间，在提示符中添加时间将是有用的。最后，我们将创建一个与原始提示符类似的新提示符。

```bash
17:37 \linuxbox $ PS1="\h \u \$"
<ne|\linuxbox-> $
```

# 终端困惑

在古代，当终端连接到远程计算机时，有许多相互竞争的终端品牌，它们的工作方式也各不相同。它们有不同的键盘，解释控制信息的方式也各不相同。Unix 和类 Unix 系统有两个相当复杂的子系统来处理终端控制的嘈杂信息（称为 `termcap` 和 `terminfo`）。如果你在终端仿真器的最深层处查找，你可能会发现一个关于终端仿真类型的设置。

为了让终端拥有某种共同语言，美国国家标准学会（ANSI）开发了一套用于控制视频终端的标准字符集。老时代的 DOS 用户会记得 `ANSI.SYS` 文件，它曾用于启用对这些代码的解释。

## 第三部分

常见任务与核心工具

# 第 14 章

软件包管理

如果我们在 Linux 社区花费了任何时间，就会听到许多关于众多 Linux 发行版中哪一个“最好”的意见。通常，这些讨论会变得非常愚蠢，集中在桌面背景的美观程度（有些人人因为 Ubuntu 的默认颜色方案而不使用它！）以及其他无关事项上。

决定发行版质量最重要的因素是软件包管理系统和发行版支持能力的活力。随着我们与 Linux 共处的时间越长，我们发现它的软件格局极其动态。事物在不断变化。大多数顶级 Linux 发行版每六个月发布新版本，并且许多个人程序每天都会更新。为了跟上这股软件风暴，我们需要良好的软件包管理工具。

软件包管理是一种在系统上安装和维护软件的方法。今天，大多数人可以通过从他们的 Linux 发行版中安装软件包来满足所有的软件需求。这与 Linux 的早期阶段形成了对比，那时人们必须下载并编译源代码来安装软件。编译源代码并没有任何错误；事实上，能够获取源代码是 Linux 的大赢家。它赋予了我们（以及每个人）检查和改进系统的能力。只是拥有预编译的软件包在处理起来更快、也更简单。

在本章中，我们将查看一些用于软件包管理的命令行工具。虽然所有主要的发行版都提供了强大且复杂的图形化程序来维护系统，但学习命令行程序也同样重要。它们可以执行许多通过其图形化对应程序难以（或无法）完成的任务。

## 软件包系统

不同的发行版使用不同的软件包管理系统，按照一般规则，为某个发行版设计的软件包与另一个发行版不兼容。大多数发行版属于软件包技术的两个阵营之一：Debian `deb` 营和 Red Hat `rpm` 营。有一些重要的例外，例如 Gentoo、Slackware 和 Arch，但大多数用户使用这两个两种基本系统之一，如表 14-1 所示。

| 软件包类型 | 发行版（部分列表） |
| :--- | :--- |
| Debian 风格 (.deb) | Debian, Ubuntu, Linux Mint, Raspberry Pi OS |
| Red Hat 风格 (.rpm) | Fedora, CentOS, Red Hat Enterprise Linux, OpenSUSE |

## 软件包系统如何工作

专有软件行业中的软件分发方法通常涉及购买安装介质（如“安装磁盘”）或访问供应商网站下载产品，然后运行“安装向导”在系统上安装新应用程序。

Linux 并不是那样运行的。几乎所有 Linux 系统的软件都可以在互联网上找到。大部分软件将由发行版供应商以软件包文件的形式提供，其余部分将以源代码格式提供，可以手动安装。我们将在第 23 章中讨论如何通过编译源代码安装软件。

## 软件包文件

软件包系统中软件的基本单位是软件包文件。软件包文件是组成软件包的压缩文件集合。一个软件包可能由许多程序和支持该程序的数据文件组成。除了要安装的文件外，软件包文件还包含有关软件包的元数据，例如软件包及其内容的文本描述。此外，许多软件包还包含安装前和安装后脚本，用于在软件包安装之前之后执行配置任务。

软件包文件由名为软件包维护者（package maintainer）的人创建，他们通常（但并不总是）是发行版供应商的员工。软件包维护者从上游供应商（程序作者）获取源代码，进行编译，并创建软件包元数据以及任何必要的安装脚本。通常，软件包维护者会对原始源代码进行修改，以改进程序与 Linux 发行版其他部分的集成。

## 仓库

虽然某些软件项目选择自己进行打包和分发，但如今的软件包是由发行版供应商和相关的第三方创建的。发行版用户可以在中央仓库中获取软件包，这些仓库可能包含数千个软件包，每个软件包都是为该发行版专门构建和维护的。
