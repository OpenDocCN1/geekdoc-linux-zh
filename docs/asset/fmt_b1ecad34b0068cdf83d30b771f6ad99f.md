
## 描述

使用 `priocntl`（优先级控制）命令将进程分配到优先级类，并管理类内的进程优先级。你还可以使用 `priocntl` 显示系统调度器的当前配置信息，或使用指定的调度参数执行命令。

进程属于不同的类，每个类都应用单独的调度策略。目前支持的进程类有：

- 实时。
- 分时。
- 交互式。

这些类的特征以及它们接受的类特定选项在下文中有所描述。在适当权限的情况下，`priocntl` 命令可以显示系统调度器的当前配置信息，或使用指定的调度参数执行命令。

## priocntl 1069

实时优先级和时间片会跨 `fork(2)` 和 `exec(2)` 系统调用继承。

## 分时类 (Timesharing Class)

分时调度策略为具有不同 CPU 特性的进程提供了公平且有效的 CPU 资源分配。分时策略的目标是为交互式进程提供良好的响应时间，为 CPU 密集型作业提供良好的吞吐量，同时允许用户或应用程序对调度进行一定程度控制。

分时类有一系列分时优先级（`tsupri`）值可以分配给该类中的进程。用户优先级范围从 -x 到 +x，其中 x 的值可配置。您可以使用 `priocntl -1` 命令显示特定安装的范围。

用户优先级对进程调度提供了某种程度的用户或应用程序控制。提高或降低分时类中进程的 `tsupri` 值会提高或降低该进程的调度优先级。然而，不能保证具有较高 `tsupri` 的分时进程会在具有较低 `tsupri` 的进程之前运行，因为 `tsupri` 只是决定分时进程调度优先级的因素之一。系统根据最近 CPU 使用等其他因素动态调整分时进程的内部调度优先级。

除了系统范围的用户优先级限制（通过 `priocntl -1` 显示）外，每个进程的优先级限制（`tsupilim`）规定了给定进程可以设置的最大 `tsupri` 值。

`priocntl -d [-i type][list]` 命令显示由 `idtype` 和 `idlist` 指定的集合中每个分时进程的优先级和用户优先级限制。

任何分时进程都可以降低自身的 `tsupilim`（或降低具有相同用户 ID 的另一个进程的 `tsupilim`）。只有具有超级用户权限的分时进程才能提高 `tsupilim`。当将进程从其他类更改为分时类时，需要超级用户权限才能将初始 `tsupilim` 设置为大于 0 的值。

任何进程都可以设置小于或等于该进程 `tsupilim` 的任何值。将 `tsupri` 设置为高于 `tsupilim`（或将 `tsupri` 设置为低于当前值）会将 `tsupri` 设置为 `tsupilim`。

您可以在分时类中使用 `priocntl -s` 或 `priocntl -e` 结合 `-m` 和 `-p` 选项。如果省略某个选项且进程当前处于分时状态，相关的参数通常不受影响。例外是当您省略 `-p` 选项并使用 `-m` 将 `tsupilim` 设置为低于当前的 `tsupri`。在这种情况下，`tsupri` 将设置为正在设置的 `tsupilim`。当从某处更改进程类时省略了某个选项，相关参数将设置为默认值。`tsupilim` 的默认值为 0，`tsupri` 的默认值为设置为正在设置的 `tsupilim` 值。

分时用户优先级和用户优先级限制会跨 `fork(2)` 和 `exec(2)` 系统调用继承。

## 交互类 (Interactive Class)

交互调度策略为具有不同 CPU 特性的进程提供了快速、公平且有效的 CPU 资源分配，同时为用户交互提供良好的响应性。交互策略的目标是为交互式进程提供良好的响应时间，为 CPU 密集型作业提供良好的吞吐量。您可以像处理分时类一样更改交互类中进程的优先级，尽管修改后的优先级继续为用户交互提供良好的响应性。

在默认配置下，可运行的实时进程会在任何其他进程之前运行。因此，不当使用实时进程会对系统性能产生巨大影响。

如果存在 `idlist`，它必须出现在命令行的末尾，且列表元素必须用空格分隔。如果没有 `idlist`，`idtype` 参数（`pid`, `ppid`, `pgid`, `sid`, `class`, `user` 或 `group`）指定 `prioc` 命令本身的进程 ID、父进程 ID、会话 ID、类、用户 ID 或组 ID。

以下命令显示由 `idtype` 和 `idlist` 指定的进程的类及类特定的调度参数：

```
priocntl -d [-i idtype] [idlist]
```

以下示例使用了不带参数的 `-d` 选项：

```
castle@ priocntl -d

INTERACTIVE CLASS PROCESSES:

PID      IAUPRIM    IAUPRIM    IAMODE

422      0             1

cast@
```

以下命令根据命令行给出的值设置进程的类及类特定的参数：

```
# priocntl -s [-c class] [class-specific options] [-i idtype] [idlist]
```

`-c` 选项指定要设置的类。（有效的类参数为 RT 实时、TS 分时或 IA 交互。）

## 系统调度类 (sys Scheduling Class)

存在一种特殊的 sys 调度类，用于调度某些系统进程（如交换器进程）。无法更改 sys 类中任何进程的类。此外，`priocntl` 会忽略由 `idtype` 和 `idlist` 指定的集合中的 sys 类进程。例如，如果 `idtype` 为 `uid`，由 0 组成的 `idlist` 将指定 UID 为 0 的所有进程，除了 sys 类以及（如果使用 `-s` 选项更改）init 进程。

init 进程（id 1）是一个特殊情况。

## priocntl 1073

```
castle% priocntl -s -c RT -t 10 -1r -i idype idlist
```

当前处于实时类中的任何进程的实时优先级不受影响。所有指定进程的时间片被设置为 1/10 秒。

以下示例了在实时类中执行命令，其实时优先级为 15，时间片为 20 毫秒。

```
castle% priocntl -e -c RT -p 15 -t 20 command
```

以下时间分调度类示例将选定的由 `idype` 和 `idlist` 选定的任何非时间分调度进程的类别设置为时间分调度，并将其用户优先级限制设置为 0，而已经在时间分调度类中的用户优先级不受影响。

```
castle% priocntl -s -c TS -i idype idlist
```

以下示例了在时间分调度类中执行带有参数 `arguments` 且用户优先级为 -15 的命令。

```
castle% priocntl -e -c TS -m 0 -p -15 command [arguments]
```
