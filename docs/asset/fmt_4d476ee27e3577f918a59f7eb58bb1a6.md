
在程序使用显示器之前，必须与 X 服务器建立连接。一旦建立了连接，就可以可以使用本章讨论的 Xlib 宏和函数获取显示信息。本章讨论了如何：

- 打开（连接）显示器
- 获取显示、图像格式或屏幕信息
- 生成无操作请求
- 释放客户端创建的数据
- 关闭（断开）显示器
- 使用 X 服务器连接操作
- 使用线程 Xlib
- 使用内部连接

要打开控制显示器的 X 服务器连接，请使用 `XOpenDisplay`。

```
Display *XOpenDisplay(display_name);
display_name
```

指定硬件显示名称，它决定了要使用的显示和通信域。在 POSIX 兼容系统中，如果显示名称为 `NULL`，则默认为 `DISPLAY` 环境变量的值。

显示的编码和解释取决于实现。支持 Host 可移植编码的字符串；对其他字符的支持取决于实现。在 POSIX 兼容系统中，显示名称或 DISPLAY 环境变量可以是以下格式的字符串：

```
protocol/hostname:number.screen_number
```

指定协议族或其协议族的别名。支持的协议族取决于实现。协议项是可选的。如果未指定协议，则必须指定分离的协议和主机。

指定物理连接的主机名称。在主机名后后跟单冒号 (:) 或双冒号 (::)。

`protocol`

`hostname`

`number` | 指定该主机上显示服务器的编号。你可以选择性地用句点（.）包含此显示数字。单个 CPU 可以有多个显示器。多个显示器的编号通常从零开始编号。

`screen_number` | 指定在该服务器上要使用的屏幕。一个 X 服务器可以控制多个屏幕。屏幕编号设置了一个内部变量，如果你使用的是 C 语言以外的语言，可以使用 `DefaultScreen` 宏或 `XDefaultScreen` 函数来访问该变量（见第 2.2.1 节）。

`XOpenDisplay` 返回一个 Display 结构体，作为与 X 服务器的连接。`XOpenDisplay` 通过 TCP 或 DCNET 协议或某些本地通信协议连接到 X 服务器。如果协议指定为 'tcp'、'inet' 或 'inet6'，或者没有指定协议且主机名后用单个冒号（:）分隔主机名和显示数字，则 `XOpenDisplay` 将使用 TCP 流连接。如果协议为 'inet'，则使用基于 IPv4 的 TCP。如果协议为 'inet6'则使用基于 IPv6 的 TCP。决定使用的 IP 版本的实现将是最快的传输方式。如果主机名是主机名称且无论它认为是最快的传输方式，并用双冒号（:）分隔主机名和显示数字，则使用 XOpenDisplay 进行连接。单个 X 服务器可以同时支持所有这些传输机制。特定的 Xlib 实现可以支持更多此类传输方式。

如果成功，`XOpenDisplay` 返回一个指向 Display 结构体的指针，该结构体定义在 `<Xlib.h>` 中。如果 `XOpenDisplay` 未成功，则返回 NULL。在成功调用 `XOpenDisplay` 后，显示器中的所有屏幕都可以供客户端使用。显示名称指定的指定的编号由 `DefaultScreen` 宏（或 `XDefaultScreen` 函数）返回。你只能通过信息宏或函数来访问 Display 和 Screen 结构的元素。有关如何使用宏和函数从 Display 结构体中获取信息的详情，请参阅第 2.2.1 节。

X 服务器可能实现各种类型的访问控制机制（见第 9.8 节）。

Xlib 库提供了许多实用的宏和相应的函数，用于从 Display 结构中返回数据。这些宏用于 C 语言编程，其对应的函数用于其他语言绑定。本节讨论了：

- 显示器宏
- 图像格式函数和宏
- 屏幕信息宏

Display 结构的所有成员（即那些没有定义宏的成员）都是 Xlib 私有的，且不能使用。应用程序绝不能修改或检查 Display 结构的这些私有成员。后续章节中的 `XDisplayWidth`、`XDisplayHeight`、`XDisplayCells`、`XDisplayPlanes`、`XDisplayWidthMM` 和 `XDisplayHeight` 函数命名错误。这些函数应该被称为 Screenwhatever 和 XScreenwhatever，而不是 Displaywhatever 或 XDisplaywhatever。对于造成的混淆深表歉意。

应用程序不应直接修改 Display 和 Screen 结构的任何部分。成员应被视为只读的，尽管它们可能会因为显示器上其他操作的结果改变。
