
## PHP 配置建议

### `register_globals = off`
将旧的 PHP 代码迁移到新系统时最常见的问题之一是 PHP 如何处理表单数据和变量。在旧版本的 PHP 中，表单字段会自动转换为与 PHP 引擎同名的全局变量。虽然有些人觉得这很方便，但由于命名和使用上的混淆，它最终成为了安全风险。自 PHP 4.2.0 起，`register_globals` 的默认值为 `off`。您应保持此设置为 `off`，并使用 `$_GET`、`$_POST` 和 `$_COOKIE` 超全局变量，而不是依赖自动创建的变量。

在开发应用程序时，保持 `register_globals` 设置为 `off` 尤为重要，因为您无法确定任何最终可能部署该应用程序的生产服务器的设置。

### `display_errors = off`
虽然在开发环境中并非必要且实际上是一种负担，但在生产或公共 Web 服务器上的任何 PHP 应用程序中，将 `display_errors` 设置为 `off` 是个好主意。关闭 `display_errors` 可阻止 PHP 向用户的 Web 浏览器显示任何解析或运行时错误。终端用户看到的任何错误都可能揭示应用程序的内部工作机制，这对希望攻击您网站的恶意人员来说可能是有用的信息。

在开发或调试情况下，保持 `display_errors` 开启以辅助调试是完全可接受的。

### `log_errors = on`
此设置通常与 `display_errors` 配合使用，告诉 PHP 将通常显示在屏幕上的所有错误记录到文件中。您可以使用该文件进行后续分析或调试，或者使用自己选择的工具定期自动通知网站管理员。

### `error_log = filename` 或 `error_log = syslog`
`error_log` 指令告诉 PHP 在启用 `log_errors` 时将错误发送到何处。您可以指定 PHP 写入错误的文件名，或者指定 `syslog`，它将错误发送到系统日志守护进程。

### `error_reporting = E_ALL`
此指令只是告诉 PHP 报告它遇到的所有错误、警告和通知。默认情况下，PHP 显示除通知外的所有内容。显示通知通常是个好主意，尤其是在开发期间，因为它可以帮助您追踪未初始化的变量和其他微小的代码漏洞。

### `magic_quotes_gpc = off`
`magic_quotes_gpc` 指令告诉 PHP 是否在加载脚本时自动转义输入/表单数据。虽然此设置旨在节省时间，但如果您决定更换数据库，或者使用不使用反斜杠转义特殊字符的数据库，它实际上可能会引发问题。如果您认为有一天可能会更换数据库系统，或者目前使用混合数据库环境甚至根本不使用数据库，最好将此设置为 `off`。

### `variables_order = "GPCS"`
将 `variables_order` 设置为 `GPCS` 会告诉 PHP 不要自动生成通常保存环境变量的 `$_ENV` 数组——通常在 `variables_order` 设置为 `EGPCS` 时设置。此设置仅出于性能原因推荐，如果您仍需访问环境变量，可以使用 `getenv()` 函数。

### `allow_call_time_pass_reference = off`
此指令可能不会影响所有代码，但它可以帮助您防止代码因未来版本的 PHP 而过时。将 `allow_call_time_pass_reference` 设置为 `off` 可防止您强制通过引用传递函数参数。如果在此设置关闭时尝试通过引用传递参数，使用 `&` 前缀，系统将生成一个警告。虽然这对生产服务器目前并非关键问题，但在开发应用程序时使用此设置是个好习惯，以确保它们与 PHP 的未来版本兼容。

### `asp_tags = off`
虽然这在大多数设置中通常不是问题，但如果使用 ASP 风格标签 `<% %>` 而非标准 PHP 标签 `<?php ?>`，当您应用程序移动到具有不同 `asp_tags` 设置的服务器时，最终可能会成为问题。虽然不是关键要求、性能问题或安全问题，但在开发期间保持 `asp_tags` 设置为 `off` 是个好主意，以避免后来的代码兼容性问题。

### `short_open_tag = off`
与将 `asp_tags` 设置为 `off` 一样，将 `short_open_tag` 设置为 `off` 也有助于确保您的应用程序能够在不同的服务器上通用工作，而不是因简单的配置差异而损坏。

使用 `short_open_tag = off` 的另一个好处是，你可以在脚本中使用 `<?xml ?>` 语句，例如 XML 文档声明。如果将 `short_open_tag` 设置为 on，并试图使用 `<?xml`，则会尝试将 `<? ?>` 包裹内的任何内容解析为 PHP，并抛出错误。

### `zlib.output_compression = on`
将 `zlib.output_compression` 设置为 on 会指示 PHP 在将输出数据发送给最终用户之前，使用 zlib 库对输出数据进行压缩。这与在 Apache 中使用 `mod_gzip` 或 `mod_deflate` 的效果类似：输出字节数减少，从而改善互联网上的传输时间。

## 初次接触 PHP5

除了 PHP5 引入的极大地改进的对象模型外，还新增了一些配置设置。PHP5 新增的配置项如下：

- `mail.force_extra_parameters`
- `register_long_arrays`
- `session.hash_function`
- `session.hash_bits_per_character`
- `zend.zend_compatibility_mode`

以下部分将描述这些新指令。

### mail.force_extra_parameters
此新指令允许你在 `mail()` 函数中指定要传递给 `Sendmail` 的具体值。通常使用 `mail()` 函数时，你可以传递一个第五个参数，用于向 `Sendmail` 发送额外的命令行参数。当此指令被设置时，`mail()` 第五个参数中指定的任何 `Sendmail` 命令行参数都会被 `mail.force_extra_parameters` 中设置的值自动覆盖。

`mail.force_extra_parameters` 设置的任何值在发送邮件时始终会被使用——即使在安全模式下，其中 `mail()` 的第五个参数是被禁止的。

### register_long_arrays
通常，当网站提交表单时，PHP 会获取表单中每个字段的值，并根据表单的方法 `GET` 或 `POST` 将它们放入两个大数组中。如果表单使用 `GET` 提交，则名为 `$HTTP_GET_VARS` 的数组会被填充表单值，每个字段在数组中都有对应的命名索引，此外还有一个名为 `$_GET` 的相同数组，其中持有相同的值。这种重复主要是为了向后兼容——超全局变量 `$_GET` 和 `$_POST` 直到 PHP 4.1.0 才引入，因此许多旧应用程序仍在使用旧的 `$HTTP_*_VARS` 数组。

如果你的应用程序完全没有使用旧样式的数组，出于性能考虑，你应该将此设置为 `off`。

### session.hash_function
过去，当 PHP 为用户创建新的会话和会话 ID 时，你无法控制使用什么算法来创建会话 ID。有了 `session.hash_function`，你可以选择两种用于创建会话 ID 的哈希算法之一。

将此选项设置为 0 会告诉 PHP 使用 MD5 对会话 ID 进行哈希处理。128 位。如果你想使用 SHA-1，160 位，则将值设置为 1。

### session.hash_bits_per_character
为了进一步配置会话 ID，你可以使用 `session.hash_bits_per_character` 来指定在将会话 ID 转换为可读值时，每个字符中存储多少位。选项如下：

- 0: 0-9, a-f
- 5: 0-9, a-v
- 6: 0-9, a-z, A-Z, "-" 和 "+"

### zend.zend_compatibility_mode
最后一个新的配置设置 `zend.zend_compatibility_mode`，仅仅指定是否要启用与 Zend 引擎 1 `PHP4` 的兼容性。

## PHP 运行时的配置

直接检查并更改 `php.ini` 中指令的设置通常是监控和修改安装环境的快速且简单的解决方案，但很多时候你无法停机进行更改，或者你需要在脚本运行时了解某个设置。本章这部分的技术将帮助你在服务器仍然运行时进行更改。

### 获取当前运行时设置
如果你需要知道安装的确切 PHP 版本，PHP 提供了 `phpversion()` 函数，它返回一个列出完整安装版本的字符串。例如：

```php
<?php
echo "The current version of PHP installed is: " . phpversion();
?>
```
