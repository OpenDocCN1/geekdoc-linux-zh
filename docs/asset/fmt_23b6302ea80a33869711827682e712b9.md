
首先，让我们检查字体本身。使用 `xlsfonts` 命令在 `xterm` 上列出你的系统字体。由于 `xlsfonts` 的列表很长，请将其输出到文件中进行查看。你应该得到一个格式为 `foundry-family-sl-pts-hr-vr-ave-charset` 的列表。厂商是开发字体的公司。常见的厂商有 `misc.`、`Adobe` 和 `Helvetica`。你可以从 `xlsfonts` 命令的结果中看到更多你的系统字体。字体族是字体的通用类型：`Courier`、`New Century Schoolbook`、`Lucida` 等。有些字体是等宽的（即所有字符宽度相同）。其他字体是比例宽的（即每个字符有单独宽度）。`Courier` 和 `Luc` 是等宽的。`New Century Schoolbook` 是比例宽的。

`wt` 和 `sl` 参数分别用于权重和倾斜。常见的权重有 `bold` 和 `medium`。粗体文本比普通字体粗。常见的倾斜有 `roman` (`r`)、`oblique` (`o`) 和 `italic` (`i`)。`roman` 文字是正体；`oblique` 文字向右倾斜。`italic` 文字与 `oblique` 类似但效果更平滑。你可能还有反倾斜 (`ro`) 和反斜体 (`ri`)，当文本向左而不是右。`p` 代表字号，传统上是 72 英寸。大多数显示器传统上只支持 75 或 100 DPI（英寸）分辨率。由于 X 字体是位图，常见的字体有两种：75 dpi 和 100 dpi。这出现在 `hr` 和 `vr` 字段中，分别代表水平和垂直分辨率。在大多数情况下，你会在这些字段中指定 75 或 100。`sp` 指屏幕字符之间的间距。可以是 `m`（等宽）、`p`（比例宽）以及 `c`（每个字符占据固定框）。`ave` 是集合所有字符的平均宽度。字符集和样式通常设置为 `ISO8859-1`。这指的是 Latin-1 字符集，包含了 ASCII 和其他欧洲字符集。

现在你已经看到了定义字体的许多选项，你可以依靠通配符进行指定。服务器将匹配符合你规格的第一个字体。换句话说，你只需要指定你参数并对其使用星号。例如，`*courier-roman` 将获得 `roman` 字体的第一个规格。然而，`*courier` 将获得粗体 `Courier` 字体。这是因为粗体规格存在于 `Roman` 规格之前。

`提示：` 使用 `xset fppath` 命令将你想首先搜索的目录（75 dpi 或 100 dpi）设置为字体路径的前端。这将确保首先搜索正确尺寸（dpi）的目录。

字体路径是服务器用于搜索系统字体的路径。该路径通常设置为以下值：

`/usr/share/lib/X11/fonts/misc,/usr/share/lib/X11/fonts/75dpi,/usr/share/lib/X11/fonts/100dpi`

这些目录中的每个都有一个名为 `fonts.dir` 的文件。这是目录下所有字体的列表，每行有两个条目。第一个条目提供字体文件名；第二个条目提供完整的字体描述。文件的第一行给出了文件中的条目数量。

`提示：` 字体名称不区分大小写。`New Century Schoolbook` 等于 `new century schoolbook`。

你可以在字体路径中创建另一个文件来为自己的字体命名。该文件名为 `fonts.alias`。服务器只使用路径中找到的第一个，因此只需在字体路径的第一个目录下保留一个这样的文件。`fonts.alias` 的格式与 `fonts.dir` 文件非常相似，但第一个条目不是文件名，而是字体名的别名。所以如果你想为你所有的编辑器终端指定特殊的字体类型，会有像这样的一行：

`editor *lucida-medium-r-*100*`

然后你可以使用命令 `xterm -fn editor &` 调用 `xterm` 以获得带有所需字体的 `xterm` 窗口。这比输入完整的字体规格好得多。此外，通过更改更改更改，你可以更改使用该别名的所有脚本，而无需逐个修改脚本。

良好的起点是 `/usr/lib/X11/fonts/misc` 目录，那里在你初始安装 X 时存在一个 `fonts.alias`。该文件已经定义了固定和可变别名供你使用。

**X11R6 的增强**

X协会最新发布的 X11 版本 (`X11R6`) 包含了大量新功能，修复了许多 bug 修复。`X11R6` 与 `X11R5` 支持的库、协议和服务器向后兼容，另有说明外。

- X 图像扩展 (`XIE`)。涉及在客户端和服务器之间以压缩格式进行图像的压缩和传输。这种压缩基于独立 JPEG 组 (`IJG`) 的 JPEG Release 4 软件。此改进意味着大幅减少了局域网（LAN）流量。
- X 客户端间交换 (`ICE`)。为构建协议提供了一个通用框架。`ICE` 提供了认证、字节序协商、版本协商和错误报告惯例。它还支持在单一传输连接上多路用多个协议。代码库 `ICElib` 为这些机制提供了通用接口，使得协议实现者无需重新发明它们。这为 X11 软件提供了更广泛的开发基础。
- 会话管理 (`SM`)。为用户提供了一种统一的机制，可以使用基于网络的会话管理器服务来保存和恢复其会话。会话管理基于 `ICE` 标准以实现跨平台标准化。它使用 `SMlib` 作为协议的 C 接口。`Xt` 也支持 `XSMP`。
- `SM` 包含一个新协议 `rstart`，它极大地简化了在远程机器上启动应用程序的任务。这基于 `rsh` 等远程执行协议，并增加了向正在启动的应用程序传递环境变量和认证数据的能力。
- 输入法协议。该协议对于需要复杂的预编辑输入法的语言是必要的。这些输入法可以通过一个名为“输入法 (`IM`) 服务器”的进程独立于应用程序进行实现。`IM` 协议标准化了 `IM` 服务器与与应用程序链接的 `IM` 库之间的通信。`IM` 协议增加了以下新功能：支持用于与 `IM` 库连接的多种传输方式之一；`IM` 服务器和客户端均可以相互进行身份验证以确保安全；即使 `IM` 服务器在 `IM` 服务器之前启动，也可以连接到 `IM` 服务器而无需重新启动；向 `IM` 服务器发起字符串转换以对文本进行重转换；以及指定热键。
- X 逻辑字体描述 (`X Logical Font Description`)。该描述已增强，包含了字体的通用 2D 线性变换和字符集子集，以及对多态字体的支持。这减少了光栅化时间以实现更快速地更新屏幕，还支持字体的旋转、镜像和“拉伸”。
- `SYNC` 扩展。允许客户端通过 X 服务器进行同步，消除了网络延迟以及不同操作系统之间同步原语的差异。
- `BIG-REQUESTS` 扩展。允许长度大于 2^18 字节的请求。添加了协议扩展 `BIG-REQUESTS`，它允许客户端将协议请求中的长度字段扩展为 32 位值。添加此扩展是为了适应 `PEX` 以及其他向服务器传输复杂信息的扩展。
- `XC-MISC` 扩展。第 6 版本的新功能，它允许客户端从服务器获取 ID 范围，这对于在整个运行周期内使用大量 ID 的长时间运行应用程序非常有用。
- 树结构重组。`xc/` 下的目录（已从 `mit/` 重命名）已过移动，以简化构建过程中的依赖关系并使内容更容易查找。
- 配置文件。配置文件已经发生变化，它们位于 `xc/config/` 下各自的目录下。
- Kerberos。这是一种用于 X 客户端的新型授权方案，实现了用户与用户之间的认证。这基于 MIT 的 Kerberos 第 5 版本。如果你的系统中安装了 Kerberos 5，请将 `site.def` 中的 `HasKrb5 config` 变量设置为 `YES` 以启用 Kerberos 支持。
- `xtrans` (`X` 传输库)。这是尝试将所有系统和传输特定的代码合并到源码树中的单一位置，以实现跨平台兼容。
- 国际化。也称为 `I18N`，它被实现为 R5 中现有架构的增强，R5 引入了 `FontSet` 的概念。这尝试涵盖几乎所有可能的语言和文化习惯。
- `Xt`。针对 X 窗口系统编程和开发的 `Xt` 库进行了多项新增强。请参考关于程序员的 GUI 章节。
