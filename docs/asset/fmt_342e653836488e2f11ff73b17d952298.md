### 引言

到为止，我们一直在学习从 shell 执行命令，但我们也可以将命令输入文件，并将该文件设置为可执行。当执行该文件时，命令将一个接一个运行。这些可执行文件被称为脚本，它们对于任何 Linux 系统管理员来说都是至关重要的工具。基本上，我们可以认为 Bash 既是一种编程语言也是一种 shell。

### 输出

让我们从演示你可能在之前的课程中看到的命令开始：`echo` 向标准输出打印参数。

```
$ echo "Hello World"
Hello World!
```

现在，我们将使用文件重定向将此命令发送到一个名为 `new_script` 的新文件中。

```
$ echo "Hello World!" > new_script
$ cat new_script
echo "Hello World!"
```

`new_script` 文件现在包含与之前相同的命令。

### 使脚本可执行

让我们演示使此文件按照我们期望的方式执行所需的某些步骤。用户的第一个想法可能是简单地输入脚本名称，就像他们输入任何其他命令名称一样：

```
$ new_script
/bin/bash: new_script: command not found
```

我们可以放心地假设 `new_script` 存在于我们的当前位置，但请注意，错误信息并没有告诉我们文件不存在，而是告诉我们命令不存在。讨论 Linux 命令和可执行文件的关系将很有用。

### 命令与 PATH

例如，当我们向 shell 输入 `ls` 命令时，我们正在执行一个存在于文件系统中名为 `ls` 的文件。你可以通过 `which` 来证明这一点：

```
$ which ls
/bin/ls
```

如果每次想要查看目录内容时都输入 `ls` 的绝对路径，那很快就会变得非常疲惫，因此 Bash 有一个环境变量，其中包含了我们可能找到想要运行的命令的所有目录。你可以通过 `echo` 查看此变量的内容。

```
$ echo PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/games/games
```

这些每个位置都是 shell 期望找到命令的地方，并用冒号 (`:`) 隔开。你会注意到 `/bin` 存在，但可以安全地假设我们的当前位置不在。

shell 将在这些目录中搜索 `new_script`，但它找不到它，因此将抛出错误。

这个问题有三种解决方案：我们可以将 `new_script` 移动到 `PATH` 目录之一，可以将当前目录添加到 `PATH`，或者更改我们调用脚本的方式。最后一种方案最简单，它只需要在调用脚本时指定点斜杠 (`./`)。

```
$ ./new_script
/bin/bash: new_script: Permission denied
```

错误信息是权限拒绝。

### 执行权限

我们做的第一个调查是使用：

```
$ ls -l new_script
-rw-r--r-- 1 user group 24 Oct 25 10:00 new_script
```

`-rw-r--r--` 表示文件不可执行。为了使其可执行，我们使用 `chmod` 命令：

```bash
$ chmod +x new_script
$ ls -l new_script
-rwxrxr-x 1 user group 24 Oct 25 10:00 new_script
```

现在 `-rwxr-xr-x` 表示文件是可执行的。我们现在可以运行它：

```bash
$ ./new_script
Hello World!
```

### 定义解释器

脚本的第一行被称为 shebang。它告诉系统使用什么解释器来执行脚本。

```bash
#!/bin/bash
echo "Hello World"
```

变量

变量是任何编程语言的重要部分，Bash 也不例外。从终端启动新会话时，shell 已经为你设置了一些变量。`PATH` 变量就是其中的例子。我们称这些环境变量，因为它们通常定义了 shell 环境的特征。你可以修改和添加环境变量，但现在让我们关注在脚本内部设置变量。

### 文本编辑器

文本编辑器取决于个人喜好，你选择使用的编辑器对本节没有影响。熟悉并习惯一个或多个文本编辑器在未来将会有所回报。

`vi`

`vi` 是一款悠老的编辑器，并且默认安装在几乎每个系统中。虽然 `vi` 有学习曲线，但不同的模式最终会让熟练的用户变得更高效。

`nano`

`nano` 是一个较新的工具，旨在设计得比 `vi` 更简单且易用。`nano` 没有不同的模式。相反，用户在启动时可以开始输入，并使用 ctrl 访问底部显示的工具。

在此例中，我们创建了一个名为 `username` 的变量，并为它赋值了值 `Carol`。请注意，变量名、等号或赋值的值之间没有空格。

在下一行中，我们使用了 `echo` 命令配合该变量，但在变量名前面有一个美元符号 (`$`)。这很重要，因为它告诉壳层（shell）我们希望将 `username` 视为变量，而不仅仅是一个普通单词。通过在命令中输入 `$username`，我们表示想要执行替换，将变量名替换为赋值给该变量的值。

执行这个新脚本，我们得到了以下输出：

```
$ ./new_script.sh
Hello Carol!
```

- 变量名必须仅包含字母、数字和下划线，并且区分大小写。`Username` 和 `username` 将被视为不同的变量。
- 变量替换也可以采用 `${username}` 的形式，即添加了 `{ }`。这也是可以接受的。
- Bash 中的变量具有隐式类型，并被视为字符串。这意味着在 Bash 中执行函数比在 C/C++ 等其他编程语言中要复杂。

```bash
#!/bin/bash

# 这是我们的第一个注释。对所有脚本进行注释也是良好的习惯。

username=Carol
x=2
y=4
z=$x+$y
echo "Hello $username!"
echo "$x + $y"
echo "$z"
```

```
$ ./new_script.sh
Hello Carol!
2 + 4
2+4
```

### 在变量中使用引号

让我们对变量 `username` 的值进行更改：

```bash
#!/bin/bash

# 这是我们的第一个注释。对所有脚本进行注释也是良好的习惯。

username=Carol Smith

echo "Hello $username!"
```

运行此脚本将得到一个错误：

```
$ ./new_script.sh
./new_script.sh: line 5: Smith: command not found
Hello !
```

请记住，Bash 是一个解释器，因此它会逐行解释我们的代码。在这种情况下，它正确地将 `username=Carol` 解析为设置值为 `Carol` 的变量 `username`。但随后它将空格解释为赋值的结束，并将 `Smith` 解释为命令名称。为了将空格和名称 `Smith` 包含在变量的新值中，我们将名称周围加上双引号（""）。

```bash
#!/bin/bash

# 这是我们的第一个注释。对所有脚本进行注释也是良好的习惯。

username="Carol Smith"

echo "Hello $username!"
```
