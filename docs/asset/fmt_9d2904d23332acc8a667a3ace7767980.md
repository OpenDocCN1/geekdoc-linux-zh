
这种过时的石器时代 8 位卡用起来简直是脑残。像躲避瘟疫一样避开它。不要购买这张卡，即使是为了开玩笑也不行。它的性能糟糕，而且在很多方面都会出问题。

对于那些尚未信服的人，`3c501` 一时间只能做一件事——当你从单数据包缓冲区中移除一个数据包时，它无法接收另一个数据包；在加载发送数据包时它也无法接收数据包。这对于连接 8008–8088 计算机的网络来说是可以的，因为处理每个数据包并响应需要数百毫秒，但现代网络对于每笔交易都会发送连续的数据包。

支持 `AutoIRQ`，不使用 `DMA`，自动探测 `autoprobe` 只查看 `0x280` 和 `0x300`，调试级别通过启动时的第三个参数设置。

再次强调，强烈不建议使用 `3c501`！在使用 IP 多组播内核时更是如此，你在监听多组播数据包时会陷入停滞。更多细节请参见源代码顶部的注释。

状态：支持，驱动程序名称：`3c503 (+8390)`

`3c503` 没有 `EEPROM setup`，在 Linux 下运行该网卡之前不需要运行诊断/设置程序。`3c503` 的共享内存地址通过跳线进行设置，这些跳线与 PROM 地址共享。这对于熟悉其他 ISA 卡的人的人来说很困惑，因为除非有 BOOT，否则你总是将跳线设置为“禁用（disable）”。

这些卡的尺寸与总线宽度 WD803 相似，但事实证明后者速度慢一点。`8390` 功能（他们发现了许多 Bug!）。Linux `3c503` 驱动也可以在程序 I/O `programmed-I/O` 模式下与 `3c503` 工作，但这比共享内存模式慢且不可靠。在更新驱动程序时，程序 I/O 模式没有经过充分测试。除非你需要为了兼容 MS–DOS，否则你不应该使用程序 I/O 模式。

`3c503` 的 IRQ 线已设置，没有来自 EEPROM 的提示。与 MS–DOS 驱动不同，Linux 驱动具有自动中断 `autoIRQ` 能力；它使用 `[5,2,9,4]` 中第一个可用的 IRQ 线，每次配置网卡时都会选择一次（旧版驱动在启动时选择）。`config` 中的 `ioctl()` 如果在此时没有可用 IRQ 线，将返回 `EAGAIN`。

# Etherlink III, 3c509 / 3c509B

状态：支持，驱动程序名称：`3c509`

此卡相当廉价，对于 ISA 非主控设计来说具有良好的性能。缺点是原始的 `3c509` 需要极低的延迟。`3c509B` 由于拥有更大的缓冲区，不应该受到相同的问题。这些卡使用 PIO 传输，类似于 n2000 卡，因此相比之下，如 w8083 这样的共享内存会更好。

原始的 `3c509` 有一个小的数据包缓冲区（总共 4KB，2KB RX，2KB TX），导致如果中断屏蔽时间过长，驱动程序偶尔会丢弃数据包。为了尽量减少这个问题，你可以在 IDE 磁盘传输期间取消中断屏蔽（参见 `hdparm`）并/或增加你的 ISA 总线速度以更早完成。

较新的 `3c509B` 板载有 8KB，缓冲区可以分为 4/4。这些卡使用 PIO 传输，类似于 n2000 卡，因此相比之下，如 w8083 这样的共享内存会更好。
