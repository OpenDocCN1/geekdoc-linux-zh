
虽然这个函数很短，但是它的汇编代码并不简单。

### Non-optimizing MSVC 指清单17.0

```assembly
PUBLIC      d_max

TEXT        SEGMENT, a$ = 8, b$ = 8, size = 8

d_max       PROC

    push        ebp

    mov         ebp, esp

    mov         QWORD [esp+8] ; current stack: ST(0) = b

    fcomp       QWORD [esp+12] ; compare _a (ST(0))

    ja SHORT    LN1 ; stack is empty only if a>b

    mov         ax

    jmp SHORT   LN2

LN1:

    mov         ax

LN2:

    ...
```

不幸的是，是在Intel P6之前的CPU上，转移指令不能根据C3/C2/C0状态位进行判断。那时候FPU在物理上与CPU分离，所以这种是不够的。自Intel P6之后，这种指令不再受限于早期功能，而且新增了状态位`ZF`/`PF`/`CF`。

- 如果`a>b`，则`C3`、`C2`、`C0`寄存器的分别是0、0、0。
- 如果`a<b`，则寄存器的值分别是0、0、1。
- 如果`a=b`，则寄存器的值为1、0、0。
- 如果出现了错误（NaN或数据），则寄存器的值是1、1、1。

`FNST`指令将FPU状态器的值复制到`AX`寄存器后，`AX`寄存器各个位与`C0~C3`的关系所示：

| 14 | 10 | 9 | 8 |
|---|---|---|---|
| C3 | C2 | C1 | C0 |

若以`AX`寄存器的视角来看，`C0~C3`位的对应是：`"test ax, 5"`指令`ax`的值（FPU标志位的加权值）和0101（二进制的5）与（AND）运算，并设置标志位。接下来，首先介绍奇偶校验`PF`（parity flag）。`PF`标志位的作用是判断运算结果中的“1”的个数，如果“1”的个数为偶数则`PF`的值为1，否则值为0。检验奇偶用于判断处理过程是否异常，并不判断这个数值是奇数还是偶数。FPU有四个条件位（`C0`到`C3`）。必须将标志位组织起来存放在FPU寄存器中，才能进行奇偶校验的正确验证。此时`C0`是标志位`CF`，`C2`是奇偶校验`PF`，在使用`FUOM`指令（FPU比较指令）时，如果操作数据出现了不可比的浮点值（非数值包含NaN或无法被指令支持的格式），`C2`会被设为1。如果`CO`和`C2`都是0或者1，则`PF`位为1就会触发`JP`跳转（Jump on Parity）。目前对`C3`/`C2`/`C0`的值进行了分类讨论，`C2`和`C0`的数值相同的情况分为`a`和非`a`两种情况。因为`test`指令`ax`的值与5进行“与”运算，所以`C3`的值与之无关。在此之后的指令就很简单了。如果触发了`JP`跳转，则`FLD`指令将变量`_b`复制到`ST(0)`寄存器，否则变量`_`会被传递到`ST(0)`寄存器。
