
`display` 指定到 X 服务器的连接。

`db` 指定指向资源数据库的指针。

`res_name` 指定应用程序的完整资源名。

`res_class` 指定应用程序的完整类名。

`OpenOM` 函数打开与当前区域（locale）和修饰符（modifiers）匹配的输出方法。调用 `XOpenOM` 时，当前的区域和修饰符将绑定到输出方法。与输出方法相关的区域不可更改。

此调用将根据当前区域和修饰符识别特定的输出方法。`XOpenOM` 会识别一个与当前区域对应的默认输出方法。可以使用 `XSetLocaleModifiers` 进行修改以设置该输出方法。

`db` 是输出方法使用的资源数据库，用于查找该输出方法私有的资源。该数据库并非用于查找可以作为输出上下文中 `OC`（选项控制）进行设置的值。如果 `db` 为 `NULL`，则不向输出方法传递任何数据库。

`res_name` 和 `res class` 指定应用程序的资源名和类。它们旨在由输出方法在查找该输出方法可能创建的所有输出上下文的通用资源时作为前缀使用。用于资源名和类的字符必须是 X 移植字符集（X Portable Character Set）。如果 `res_name` 或 `res class` 为 `NULL`，则查找的资源将不完整。

不假设 `name` 和 `res class` 参数在调用 `XOpenOM` 之后存在。假设指定的资源数据库在输出方法的整个生命周期内存在。

如果无法打开输出方法，`XOpenOM` 返回 `NULL`。

要关闭输出方法，请使用 `XCloseOM`。

# X 输出

下表描述了输出方法如何解释 `XOM` 值。第一列列出了 `XOM` 值。第二列指示了特定的输出样式如何处理每个 `XOM` 值。

以下键适用于此表。

| 键 | 解释 |
| G | 此值可以使用 `XGetOMValues` 读取。 |

| `XOM` 值 | 键 |
| :--- | :--- |
| `XRequiredCharSet` | G |
| `XQueryOrientation` | G |
| `XNDirectionalDependentDrawing` | G |
| `XContextualDrawing` | G |

## 必需字符集

`XNRequiredCharSet` 参数返回加载该区域所需的字体所需的字符集列表。该参数的值指向一个类型为 `XOMCharSetList` 的结构指针。

`XOMCharSetList` 结构定义如下：

```c
typedef struct {
    int      charset_count;
    char     **charset_list;
} XOMCharSetList;
```

`charset_list` 成员是一个一个或多个空终止字符集名称的列表，`charset count` 成员是其中一个字符集的名称。

必需字符集列表由 Xlib 所有，不应由客户端释放。它将通过对关联 `XOM` 调用 `XCLOSEOM` 来释放。除非如此，否则其内容不会被 Xlib 修改。

# 查询方向

`XNQueryOrientation` 参数返回文本绘图时的全局方向。除了 `XOMOrientation_LTR_TTB` 之外，支持的方向集合取决于区域。该参数的值指向一个类型为 `XOMOrientation` 的结构指针。客户端负责使用 `XFree` 释放 `XOMOrientation` 结构；这也会释放该结构的内容。

```c
typedef struct {
    int             num_orientation;
    XOMOrientation  *orientation; /* 输入文本描述 */
} XOMOrientation;
```

```c
typedef enum {
    XOMOrientation_LTR_TTB,
    XOMOrientation_RTL_TTB,
    XOMOrientation_TTB_LTR,
    XOMOrientation_TTB_RTL,
    XOMOrientation_Context
} XOMOrientation;
```

`XOMOrientation` 的可能值为：

- `XOMOrientation_LTR_TTB` 从左到右、从上到下的全局方向
- `XOMOrientation_RTL_TTB` 从右到左、从上到下的全局方向
- `XOMOrientation_TTB_LTR` 从上到下、从左到右全局方向
- `XOMOrientation_TTB_RTL` 从上到下、从右到左全局方向
- `XOMOrientation_Context` 上下文方向

# 方向依赖绘图

`XDirectionalDependent` 参数指示文本渲染函数是否实现了隐式的方向处理。如果此值为 `True`，输出方法了解方向依赖关系并在渲染文本时必要时重新排序。如果此值为 `False`，则输出方法不实现任何方向文本，且所有字符方向均假定为从左到右。

无论字符渲染顺序如何，所有字符的起点均位于绘图的主区域。

此 `OM` 值提供了与 `XDirectionalDependentDrawing` 相同的功能。

# 上下文依赖绘图

`XContextDrawing` 参数指示文本渲染函数是否实现了隐式的上下文依赖绘图。如果此值为 `True`，输出方法了解上下文依赖关系并执行字符形状编辑，必要时组合字形以呈现单个字符。实际的形状编辑取决于本地实现和所使用的字体集。

此 `OM` 值提供了与 `XContextDrawing` 相同的功能。

# 输出上下文函数

输出上下文是一个包含了输出方法所需数据以及显示这些信息的抽象。一个输出方法可以有多个输出上下文。创建、读取或修改输出上下文的编程接口使用变长列表。参数列表中的元素称为 `XC` 值。设计上通过这些 `XOC` 值来控制输出方法。创建新的 `XOC` 值时，应向 X 联盟注册。`XOC` 可以用于任何可以使用 `FontSet` 的地方，反之亦然；保留 `FontSet` 是为了与之前的版本兼容。输出方法和输出上下文的概念比字体集包含了更广泛、更通用的抽象，支持复杂且更智能的文本显示，不仅处理多个字体，还处理上下文依赖关系。然而，由于 `FontSet` 在多个接口中被广泛使用，因此 `XOC` 被定义为 `XFontSet` 的向上类型。

# 区域与国际化文本函数

`XCreateOC` 函数在指定的输出方法内创建一个输出上下文（output context）。

基础字体参数在创建时是强制性的，除非提供该参数，否则将不会创建输出上下文。所有其他输出上下文值都可以稍后设置。

如果无法创建输出上下文，`XCreateOC` 返回 `NULL`。由于以下任何原因都可能返回 `NULL`：

-   未设置所需的参数。
-   设置了只读参数。
-   参数不被识别。
-   输出方法遇到了取决于具体实现的错误。

`XCreateOC` 可以产生 `BadAtom` 错误。

要销毁输出上下文，请使用 `XDestroyOC`；

```
void XDestroyOC(oc);
```

指定输出上下文。

`XDestroyOC` 函数销毁指定的输出上下文。

要获取与输出上下文关联的输出方法，请使用 `XOMOFOC`；

```
XOM XOMOFOC(oc);
```

指定输出上下文。

`XOMOFOC` 函数返回与指定的输出上下文关联的输出方法。

Xlib 两个用于设置和读取输出上下文的值：`XSetOCValues` 和 `XGetOCValues`。这两个函数都具有变长参数列表。在参数列表中，任何 `XOC` 值的名称必须使用 X 移植字符集（X Portable Character Set）用字符串表示。

要设置 `XOC` 值，请使用 `XSetOCValues`。
