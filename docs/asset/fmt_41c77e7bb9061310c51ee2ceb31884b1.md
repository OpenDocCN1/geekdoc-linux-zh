
## 高级 firewalld 配置

`firewalld` 还支持更高级的配置，例如创建自定义服务富规则（rich rules）。

## 在 iptables 和 firewalld 之间选择

选择 `iptables` 还是 `firewalld` 取决于你对防火墙配置的熟悉程度以及系统的特定需求。`iptables` 提供了细粒度的控制，但 `firewalld` 简化了过程，推荐给偏好友好界面的用户。

### 结论

防火墙配置是保护 Linux 系统的关键方面。无论选择哪一种，理解如何定义和管理防火墙规则都是至关重要的。配置良好的防火墙有助于保护系统免受未经授权的访问和恶意活动，增强 Linux 环境的整体安全性。

## 7.3. 实现安全审计与扫描

安全审计和扫描是 Linux 环境中稳健网络安全策略的要素组成部分。这些过程有助于识别漏洞、配置错误以及对系统安全的潜在威胁。在本节中，我们将探索安全审计与扫描的重要性，并讨论实现它们的工具和实践。

## 为什么安全审计与扫描是必要的

安全审计和扫描有几个关键目的：

- **漏洞评估**：它们识别系统、应用程序或网络配置中的弱点或漏洞。如果这些漏洞不被处理，攻击者可能会利用它们。
- **合规性要求**：许多组织必须遵守特定行业的法规或标准（例如 HIPAA、GDPR、PCI DSS）。安全审计通过识别不合规问题帮助确保合规。
- **风险缓解**：审计和扫描有助于评估与环境相关的风险。通过识别和缓解漏洞，你可以减少安全事件发生的风险。
- **持续改进**：定期的审计和扫描允许你通过处理新兴威胁和维护最佳实践来持续改进安全态势。

## 安全审计工具

在 Linux 环境中有多种可用于安全审计和扫描的工具和实践：

### 1. OpenVAS (开放漏洞评估系统)

`OpenVAS` 是一个广泛使用的开源漏洞扫描器，有助于识别安全问题，包括过时的软件、弱密码和配置错误。它提供详细的报告和修复建议。

#### 在基于 Debian 的系统上安装 OpenVAS

```bash
sudo apt-get install openvas
```

#### 启动 OpenVAS 扫描器

```bash
sudo openvas-start
```

#### 访问 Web 界面 `http://localhost:4000`

### 2. Nessus

`Nessus` 是一款商业漏洞扫描器，以其大量的漏洞数据库和全面的扫描能力而闻名。它可以识别广泛的漏洞并提供详细报告。

### 3. Lynis

`Lynis` 是一个开源安全审计工具，专注于系统加固和配置审计。它根据最佳实践检查你的系统，并提供改进安全性的建议。

#### 在基于 Debian 的系统上安装 Lynis

```bash
sudo apt-get install lynis
```

#### 在基于 Debian 的系统上安装 Nikto

### 5. 安全信息和事件管理 (SIEM) 系统

SIEM 系统如 `Elasticsearch`、`Logstash` 和 `Kibana` (ELK 栈) 用于实时监控、事件关联和日志分析。它们通过聚合和分析来自各种来源的数据帮助检测并响应安全事件。

## 安全审计与扫描的最佳实践

为了充分利用安全审计和扫描，请遵循以下最佳实践：

1. 定期扫描：定期进行安全扫描，以保持系统安全态势更新并及时处理漏洞。
2. 尽可能自动化：使用自动化来调度和定期执行扫描。自动化确保了一致性并减少了人为错误的可能性。
3. 审查并修复发现：仔细审查扫描报告，根据严重程度优先考虑漏洞，并采取适当的修复措施。
4. 保持系统更新：确保你的系统和软件拥有最新的安全补丁。许多漏洞可以通过补丁来缓解。
5. 文档记录：维护安全审计结果、修复工作以及对系统任何更改的记录。

### 结论

安全审计和扫描是 Linux 环境中识别和缓解安全风险必不可少的工具。通过实施这些实践并使用适当工具，你可以增强 Linux 系统的安全性，保护敏感数据并减少安全漏洞的风险。定期的审计和扫描结合及时的修复有助于构建更安全的设施。

## 7.4. SELinux 和 AppArmor：强制访问控制

强制访问控制 (MAC) 机制如 `SELinux`（安全增强 Linux）和 `AppArmor` 通过细粒度的访问控制和限制策略对增强 Linux 系统的安全性起着至关重要的作用。在本节中，我们将探索 `SELinux` 和 `AppArmor` 的概念、区别以及如何使用。

## 理解强制访问控制

传统的 Unix/Linux 系统依赖于自主访问控制 (DAC)，由文件或进程的所有者决定访问权限。相比之下，MAC 实施的是全范围内执行的安全策略，无论用户或进程所有权如何。

`SELinux` 和 `AppArmor` 等 MAC 系统定义并执行管理进程、文件和资源之间交互的规则。这些规则规定了允许或拒绝的操作，通过减小攻击面来增强安全性。

## SELinux (安全增强 Linux)

`SELinux` 是一个最初由国家安全局 (NSA) 开发并随后集成到许多 Linux 发行版中的 MAC 系统。它根据与文件、进程和网络连接相关的标签来执行安全策略。

## SELinux 模式

`SELinux` 以三种模式运行：

1. **强制模式 (Enforcing)**：在此模式下，`SELinux` 严格执行安全策略，拒绝违反策略的操作。
2. **许可模式 (Permissive)**：`SELinux` 会记录违反策略的行为但不阻止它们。它适用于策略开发和调试。
3. 已禁用：`SELinux` 已完全禁用，不会进行任何策略强制。

## SELinux 策略

`SELinux` 使用策略来定义访问规则。策略规定了对不同类型对象（文件、进程等）及其相关标签允许或拒绝的操作。常见的 `SELinux` 策略包括针对型（targeted）、严格（strict）和多级安全（mls）。

## 管理 SELinux

要操作 `SELinux`，你可以使用 `semanage`、`setenforce` 和 `sestatus` 等命令。以下是一些常见任务：

- 检查 `SELinux` 状态：

```bash
sestatus
```

- 将 `SELinux` 模式更改为允许（permissive）：

```bash
sudo setenforce 0
```

- 将 `SELinux` 模式更改为强制（enforcing）：

```bash
sudo setenforce 1
```

- 安装并配置 `SELinux` 策略管理工具：

```bash
# 在基于 Red Hat 的系统上
sudo yum install policycoreutils-python
```

```bash
# 在基于 Debian 的系统上
sudo apt-get install policycoreutils
```

## AppArmor

`AppArmor` 是另一种 MAC（强制访问控制）系统，主要用于 `Ubuntu` 和某些其他 Linux 发行版。与 `SELinux` 类似，它执行访问控制策略，但使用了基于与单个应用程序关联的配置文件（profiles）。

## AppArmor 配置文件

`AppArmor` 配置文件规定了应用程序可以访问哪些资源以及如何与之交互。配置文件使用人类可读的语法编写，并可以根据特定的安全需求进行自定义。

## 管理 AppArmor

要操作 `AppArmor`，你可以使用 `apparmor_status`、`aa-complain` 和 `aa-enforce` 等命令。以下是一些常见任务：

- 检查 `AppArmor` 状态：

```bash
sudo apparmor_status
```

- 将配置文件更改为投诉模式（complain，记录违规行为但不执行）：

```bash
sudo aa-complain /path/to/profile
```

- 强制执行配置文件（执行策略）：

```bash
sudo aa-enforce /path/to/profile
```
