
我与 Transmeta 的交易很清楚：我得到了模糊的保证，我也可以在工作时间研究 Linux。相信我，我充分利用了这一点。

很多人相信长时间工作和做双班、三班甚至四班倒。我不是其中之一。Transmeta 或 Linux 从未干扰过我一夜好眠。事实上，如果你想了解诚实的真相，我是睡眠的坚定信徒。有些人认为这只是懒惰，但我想把我的枕头扔给他们。我有一个完全合理的借口，并坚持它：如果你每天睡，哦，比如说十个小时，你可能会失去几个生产性的白天小时，但当你醒着的那几个小时，你神清气爽，你的大脑全功率运转。或者是四个汽缸，或者别的什么。

### 欢迎来到硅谷

我在这个奇怪的星系落地后做的第一件事之一，就是见明星。

我收到了一封来自史蒂夫·乔布斯秘书的电子邮件，说他希望见我，问我能否抽出一两个小时。不知道怎么回事，我说可以。

会议在苹果总部位于 Infinity Loop Drive。与会者有乔布斯和他的首席技术人员 Avie Tevanian。当时苹果正在开始开发 OS X，这是一个基于 Unix 的操作系统，直到 2000 年 9 月才发布。会议没有太多正式程序。基本上，乔布斯一开始试图告诉我，桌面上只有两个玩家，微软和苹果，他认为我能给 Linux 做的最好的事情就是与苹果“上床”，并尝试让开源人士支持 Mac OS X。

我留下来是因为我想了解新的操作系统。它是基于 Mach，卡内基梅隆大学开发的微内核。在 20 世纪 90 年代中期，Mach 被认为是终极操作系统，许多人对此感兴趣。事实上，IBM 和苹果使用 Mach 作为其不幸的 Taligent 合资操作系统的基础。

乔布斯特别强调 Mach 的低层内核是开源的。他有点淡化了这个设置的缺陷：谁在乎基本操作系统，真正的核心部分是否开源，如果你然后在上面有一层 Mac 层，它不是开源的？

他无法知道我对 Mach 的个人评价不高。坦白说，我认为它是一堆垃圾。它包含你可以犯的所有设计错误，甚至自己发明了一些。反对微内核的一个论点一直是性能。因此，许多人做了研究项目，旨在确定如何将微内核变成性能非常好的东西。所有结果的建议都进入了 Mach。结果是，它变成了一个带有自己规则的复杂系统。而且它的性能仍然不太好。

Avie Tevanian 当 Mach 还是一个大学项目时是 Mach 团队的一员。讨论他和史蒂夫认为的问题有点意思。与此同时，我们在技术问题上存在根本分歧。我真的认为没有理由让开源或 Linux 人士参与。当然，我理解他们为什么想要让更多的开源开发者进入他们的系统；他们看到了 Linux 背后的势头在积累。但我觉得他们看得不够多。我不认为乔布斯意识到 Linux 潜在的用户可能比苹果多，尽管用户群非常不同。我也不认为史蒂夫今天会比三年前那样急于将 Linux 作为桌面系统弃之不顾。

我解释了为什么我不喜欢 Mach。由于可以理解的原因，这反应并不太好。他们肯定以前听过这些论点。显然，我非常坚持 Linux，而 Tevanian 非常坚持 Mach。看看他们如何讨论一些技术问题很有趣。我能看到的立即问题之一涉及他们如何计划在新操作系统中支持旧 Mac 应用程序。他们希望用兼容层处理所有旧的东西。所有旧的 Mac 应用程序都将在一个新附加的进程中运行。但旧 Mac 的主要缺点之一是缺乏内存保护，这个解决方案并没有解决这个问题。只有新的 Mac 应用程序才有内存保护。对我来说，这没有道理。

#### 史蒂夫·乔布斯

我们在看待世界的方式上有着根本的分歧。史蒂夫就是史蒂夫，正如媒体所描绘的那样。他专注于自己的目标，尤其是营销方面。而我关注技术层面，对他的目标或论点都不太感兴趣。他的主要论点是，如果我想要进军桌面市场，就应该与苹果联手。我的反应是：我为什么要关心？我为什么会对苹果的故事感兴趣？我觉得苹果没有什么有趣之处。而且，接管桌面市场并不是我的人生目标。（当然，这事终归会发生，但从未成为我的目标。）

他并没有使用太多论据。基本上，他只是理所当然地认为我会感兴趣。他完全没意识到，世界上可能存在着整批对人类不增加 Mac 市场份额丝毫不在意的人。我想他真的对我不在乎 Mac 市场有多大——或者微软市场有多大——感到惊讶。而且，我也不能怪他事先不知道我有多讨厌 Mac。

但尽管我几乎不同意他说的所有内容，我其实在某种程度上挺喜欢他的。

### 初次见到比尔·乔伊

然后是我第一次见到比尔·乔伊。我当场就甩脸走人了。

好吧，公平地说，我第一次见到他时并不知道他是谁。那是在 Jini 预览会上。Jini 是太阳微系统公司（Sun Microsystems）的交互代理语言，是 Java 的扩展。它用于在完全不相同的系统之间实现无缝网络通信。你可以拥有一台支持 Jini 的打印机，同一网络上任何支持 Jini 的设备都能自动使用 Jini。

太阳微系统公司邀请我和大约十几名其他开源人士及技术专家参加一场私密的预发布说明会。会议将在硅谷世界的 Java World 期间，于圣何塞市中心的一家酒店房间内举行。他们邀请我们的原因是：他们正在以太阳微系统公司所谓的“开源”模式开发 Jini。

当我到达那里时，我大概知道比尔·乔伊也在场。他曾主导开发 BSD Unix，后来加入太阳微系统公司担任首席科学家。我之前从未见过他。他只是走过来告诉我他是比尔·乔伊，而我当时并没有特别反应。我去那里不是为了见他，而是为了看看太阳微系统公司对开源的看法，以及他们打算如何进入开源领域。几分钟后，比尔本人正在解释将其开源的原因，并进行了有限的系统演示。

接着他们开始解释其授权条款。那简直糟糕透了。纯愚蠢。基本归结为一点：如果其他人希望以哪怕半商业的方式使用该系统，它根本就不是开源的。我觉得这是个彻头彻尾的愚蠢主意。对于邀请函中他们大肆宣传其“开源性”这一事实，我感到非常愤怒。所谓的开源是指你可以阅读源代码，但如果你想进行任何修改或将其纳入你的基础设施，你就必须从太阳公司获得授权。如果红帽公司（Red Hat）的某人想让最新版的红帽 Linux CD 支持 Jini，该公司就得向太阳公司授权 Jini 技术。

我提了几个问题，以确认我是否理解正确。然后我就走开了。

我当时真的气炸了，因为他们声称自己是开源的从而把人骗来，等我搞清楚怎么回事后，我直接说了句：“算了，我没兴趣”，然后离开了。

我当时的理解是，他们希望我到场只是通知我，而且如果我表现出热情，他们可能还想要个新闻引用之类的。那个计划弄巧成拙了。但也许他们会吸取教训。显然，后来有人说服他们将其 Star Office 开源了。所以我想，这只是需要时间罢了。

我听说他们那天继续了会议并吃了晚餐，其他所有人都留下来了。

### 二次见到比尔·乔伊

第二次见到比尔·乔伊，结果要好得多。大约一年半后，他邀请我去吃寿司。

他的秘书打电话给我安排时间。比尔居住和工作在科罗拉多州，显然他每月有一周时间在硅谷。我们去了帕洛阿尔托的 Fuki Sushi。这是硅谷不错的寿司店之一。当然，它完全比不上旧金山的 Blowfish Sushi，那里有不断的日本动画片可以看；也比不上 Mission 区的 Tokyo Go Go，那里有着时髦的人群；也不同于 Sausalito 的 Sushi Ran，那里有显赫的顾客；更不同于 Sunnyvale 的 Seto Sushi，那里有着所有店中最好吃的辣味金枪鱼寿司。

好吧，我们在 Fuki Sushi，当时有点有趣，因为比尔试图拿到真正的山葵（wasabi）。当时我并不知道，但在美国大多数日料店里，所谓的山葵实际上只是染色的芥末。事实证明，山葵植物只生长在日本的溪流中，且很难商业化种植。比尔试图向女服务员解释这一点，但她完全没理解这个概念。她是日本人，但她以为山葵就是山葵（指真正的植物）。他让她去问问厨师。

这种来回有点滑稽。这是一顿社交晚餐。他基本表明，如果我想为太阳公司工作，只要给他一句话，他就会去促成此事。但这不是主要目的。这更多是一个讨论相关议题的机会。他开始回忆自己曾维护 BSD Unix 五年，以及他在太阳公司周围逐渐欣赏商业化的过程。他谈到像太阳公司这样的企业提供商业支持的重要性。听他讲述 Unix 的早期岁月，我觉得既有趣又引人入胜。我们最终没能尝到真正的山葵，这对我来说完全无关紧要。我清楚地记得当时心想，他可能是我在硅谷见过的最有名望的人中最友善、最有趣的一个。

### 比尔·乔伊的文章与我们的分歧

快进三年。我拿起《连线》（*Wired*）杂志，却意外读到一篇关于技术极其负面的文章，题为《未来不需要我们》。我有点失望。显然，未来不需要我们。但他没必要表现得如此消极。

我不想逐行抨击他的文章，但我有一个普遍的信念：对人类最悲哀的事情，莫过于我们原地踏步，而非进化。比尔似乎觉得像基因改造这样的进步让我们失去了人性。人们总是认为不同的东西是非人的，因为当下我们是人类。但随着我们继续随事件演进，按今天的标准，一万年后的我们就不再是人类了。我们只是另一种形式的人类。
