TCP-IP 创建于一个安全并不是被非常关注的时代和背景。最初，“互联网”（当时被称为 Arpanet）仅由极少数主机组成，全都是学术机构、公司或政府性质。每个人彼此认识，接入互联网是一件很了不起。TCP-IP 协议族异常健壮（它从未失败），但遗憾的是，它没有真正的安全机制，即身份验证、校验、加密等。在当今的互联网中，伪造数据包、拦截数据包、读取数据负载等都非常容易。最常见的攻击是拒绝服务攻击，这种攻击最容易执行也最难击败，其次是数据包嗅探、端口扫描和其他相关活动。

主机名并不总是指向 IP 地址，而 IP 地址也不总是反向查询到正确的主机名。如果可能，请不要使用主机名认证，DNS 缓存中毒相对容易；依赖 IP 地址进行身份验证会将问题简化为伪造问题，但其本身也存在缺陷。在广泛传播的网络中，没有机制可以验证谁发送了数据以及谁在接收数据（不过 IP/IPv6 和 VPN 技术正在开始获得动力）。

你可以从禁止声称源自你网络（们）的数据开始，因为这些数据显然是伪造的；为了防止你的用户进行伪造攻击，你应该阻止所有不是来自你 IP 地址的传出数据。这相对简单且易于管理，绝大多数网络都没有这样做（在他们开始之前我骚扰了我的 ISP 大约一年）。如果互联网上的每个人都有出站过滤器（即限制出站流量为特定的流量），那么伪造攻击将是不可能的，追溯攻击者到源头也会变得更容易。你还应该阻止预留网络（127.*, 10.* 等），我注意到有很多来自互联网的攻击标记为这些 IP 的数据包，如果你使用网络地址转换（如 IPMASQ）且没有正确配置防火墙，你可能会很容易受到攻击，或被用来将攻击转发给第三方。

如果你必须使用 VPN 技术与人们进行安全通信，“最好”的可能是 IPSec，它是一个由所有主要供应商支持的开放标准，且大多数主要供应商都有实际的实现。更多细节请参阅附录 B 或加密服务与数据章节。

### IPSec

IPSec 是数据包级别的加密，它不仅提供数据加密，如果你使用签名证书（类似于签名的 PGP 密钥），还可以提供参与方的身份验证。几个证书供应商（例如 Verisigen、Thwaite 等）计划提供 IPSec 证书签名，这样你就能确定你正在与谁交道，并让你实现公司级证书架构的能力。IPSec 在本文后文会有详细介绍。

## IPv6

IPv6 本身并不提供安全，但它为未来的增强提供了内置的钩子，如 IPSec 支持等。如果用于网络，它自然会使攻击者的生活变得更加困难，因为 IPv6 的使用尚未普及。如果你想了解更多，请访问：http://www.bieringer.de/linux/IPv6/。Linux 目前完全支持 IPv6（它是少数支持它的操作系统之一）。

存在多种导致 TCP-IP 中断的程序（大部分是拒绝服务攻击），但有几个通用型程序对管理员可能有用。

HUNT 项目是一组用于操纵 TCP-IP 连接（通常在以太网局域网上）的工具，也就是说，它可以重置连接、监视连接并执行其他“坏”事。它还包括多种基于 ARP 的攻击和其他恶作剧的趣味来源，你可以在这里获取 HUNT：http://www.cri.cz/kra/index.html。

## PPP 安全

PPP 在串口（可以连接到调制解调器）上提供 TCP-IP（以及 IPX/SPX 和 NetBEUI）连接。它是大多数人连接互联网的主要方法（几乎所有的拨号账户都是 PPP）。PPP 连接本质上由两个计算设备（计算机、Palm Pilot、终端服务器等）通过串口链路（通常通过调制解调器）连接组成，两端都调用 PPP，身份验证由处理（多种方法之一），并建立链路。PPP 对加密没有真正的支持，所以如果你需要安全链路，你必须投资一些 VPN 软件。大多数系统以相当笨拙的方式调用 PPP，即“登录”设备（终端服务器等），然后当你的登录 shell 被调用时，当然，你的用户名和密码会以明文形式发送到线路上，并且你必须在该设备设备上有一个账户，在这种情况下，PPP 完全没有处理身份验证。处理此问题的一种稍显安全的方法是使用 `PAP`（密码认证协议），由 PPP 处理身份验证，因此你不需要在服务器上拥有真实账户。
