
```c
#include <signal.h>
#include <string.h>
#include <sys/types.h>
#include <sys/wait.h>

sig_atomic_t exit_status;

void clean_up_process (int signal_number) {
    /* 清理子进程。 */
    int status;
    wait(&status);
    /* 将退出状态存储在全局变量中。 */
    exit_status = status;
}

int main () {
    /* ... */
    struct sigaction sigchld_action;
    memset(&sigchld_action, 0, sizeof(sigchld_action));
    sigchld_action.sa_handler = &clean_up_process;
    sigaction(SIGCHLD, &sigchld_action, NULL);

    /* 现在做一些事情，包括 fork 子进程。 */
    /* ... */
    return 0;
}
```

注意信号处理程序如何将子进程的状态存储在全局变量中，主程序可以从中访问它。由于变量在信号处理程序中赋值，它的类型是 `sig_atomic_t`。

## 4 线程

线程和进程一样是允许程序同时做更多事情的机制。与进程一样，线程看起来并发运行；Linux 内核异步调度它们，偶尔中断每个线程以给其他线程机会。

概念上，线程存在于进程内部。线程是进程更细粒度的执行单元。当你调用程序时，Linux 创建一个新进程并在该进程创建一个线程，该线程顺序执行程序。该线程可以创建额外的线程；所有这些线程在同一个进程中运行，但每个线程在任何时间都可以执行程序的不同部分。

我们已经看到程序如何 `fork` 进程。子进程最初运行父进程的程序，拥有父进程的虚拟内存、文件描述符等。子进程可以修改其内存、关闭文件描述符等而不影响父进程，反之亦然。但当程序创建另一个线程时，没有任何复制。创建线程和被创建线程共享原始线程相同的内存空间、文件描述符和其他系统资源。例如，如果一个线程更改了变量的值，另一个线程随后会看到修改后的值。同样，如果一个线程关闭了文件描述符，其他线程可能无法读取

GNU/Linux 实现了 POSIX 标准线程 API（称为 threads）。所有的线程函数和数据类型都在头文件 `<pthread.h>` 中声明。线程函数没有包含在标准 C 库中。相反，它们在 `libthread` 中，因此你应该在命令行中添加 `-lpthread` 来链接你的程序。

### 4.1 线程创建

每个线程通过线程 ID 标识。在 C 或 C++ 程序中引用线程 ID 时，请使用 `pthread_t` 类型。

创建时，每个线程都会执行一个线程函数。这只是普通的函数，包含了线程应该运行的代码。当函数返回时，线程退出。在 GNU/Linux 上，线程函数接受一个 `void*` 类型的参数，并具有 `void*` 返回类型。线程参数：GNU/Linux 直接将该值传递给线程，而不进行查看。你的程序可以使用此参数将数据传递给新线程。同样，你的程序可以使用返回值将数据从退出的线程传回给它的创建者。

`pthread_create` 函数创建一个新线程。你向它提供以下内容：

- 1. 指向 `pthread_t` 变量的指针，其中存储新线程的线程 ID。
- 3. 指向线程函数的指针。这是一个普通的函数指针，类型为：

```
void* (void*)
```

- 4. 一个 `void*` 类型的参数值。无论你传递什么，在线程开始执行时都会作为线程函数的参数传递。

对 `pthread_create` 的调用会立即返回，原线程继续执行调用之后的指令。同时，新线程开始执行线程函数。Linux 异步地调度这两个线程，你的程序不能依赖于这两个线程中执行指令的相对顺序。

列表 4.1 中的程序创建了一个持续向标准错误输出 `x` 的的线程。在调用 `pthread_create` 后，主线程持续向标准错误输出 `o` 的。

#### 列表 4.1 (thread-create.c) 创建线程

```c
#include <pthread.h>
#include <stdio.h>

/* 输出 x's 是未使用的。参数未使用。不返回。 */

void* print_xs (void* unused) {
    while (1)
        fputs('x', stderr);
    return NULL;
}

/* 主程序。 */
int main () {
    pthread_t thread_id;
    /* 创建新线程。新线程将运行 print_xs 函数。 */
    pthread_create (&thread_id, NULL, print_xs, NULL);
    /* 向 stderr 持续打印 o's。 */
    while (1)
        fputs('o', stderr);
    return 0;
}
```

`cc -o thread-create thread-create.c -lpthread`

在正常情况下，线程通过两种方式之一退出。一种方式如之前所示，通过从线程函数返回。函数的返回值被视为线程的返回值。另一种，线程可以通过调用 `pthread_exit` 显式退出。该函数可以从线程函数内部调用，也可以从线程函数直接或间接调用的其他函数调用。`pthread_exit` 的参数是线程的返回值。

#### 4.1.1 向线程传递数据

线程参数提供了一种向线程传递数据的方便方法。

由于参数类型是 `void*`，虽然你无法直接通过参数传递大量数据。相反，使用线程参数传递指向某些结构体或数据数组的指针。一种常用技术是为每个线程函数定义一个结构体，其中包含线程函数预期的“参数”。

使用参数，很容易为许多线程复用同一个线程函数。所有这些线程执行相同的代码，但处理不同的数据。

列表 4.2 中的程序与之前的示例类似。它创建了两个新线程，一个用于打印 `x`，另一个用于打印 `o`。尽管不是无限打印，但每个线程打印固定数量的字符并通过从线程函数返回来退出。同一个线程函数 `char_print` 被两个线程使用，但每个线程都使用 `struct char_print_parms` 进行了不同的配置。

#### 4.1.2 合并线程

列表 4.2 中的程序存在一个严重的错误：它在线程完成之前就退出了。一种解决方案是使用 `pthread_join` 等待线程完成。它接受两个参数：要等待的线程 ID，以及用于接收线程返回值的指针。如果你不在乎返回值，请向第二个参数传递 `NULL`。

列表 4.3 显示了 `thread-create2` 后的 `main` 函数。

```c
int main () {
    pthread_t thread_id;
    pthread_t thread_id;
    struct char_print_parms thread1_args;
    struct char_print_parms thread2_args;

    /* 创建新线程打印 30000 个 x。 */
    thread1_args.character = 'x';
    thread1_args.count = 30000;
    pthread_create (&thread_id, NULL, char_print, &thread1_args);

    /* 创建新线程打印 20000 个 o。 */
    thread2_args.character = 'o';
    thread2_args.count = 20000;
    pthread_create (&thread_id, NULL, char_print, &thread2_args);

    /* 确保第一个线程已完成。 */
    pthread_join(thread_id, NULL);
    /* 确保第二个线程已完成。 */
    pthread_join(thread_id, NULL);

    /* 现在我们可以安全地返回。 */
    return 0;
}
```

#### 4.1.3 线程返回值

如果 `pthread_join` 的第二个参数不为空，则线程的返回值将被放置在该参数指向的位置。线程返回值和线程参数一样，都是 `void*` 类型。如果你想传递单个 `int` 或更小的数字，可以轻松地通过将值转换为 `void*` 并在调用 `pthread_join` 后转换回相应的类型来实现。

列表 4.4 中的程序在单独的线程中计算第 $n$ 个质数。该线程将所需的质数作为其返回值返回。主线程在此期间可以自由执行其他代码。

### 4.1 线程创建

#### Listing 4.4 (primes.c) 在线程中计算质数

```c
#include <pthread.h>
#include <stdio.h>

/* 计算连续的质数（效率极低）。返回第 N 个数，N 是 arg 指向的值。 */

void* compute_prime(void* arg) {
    int candidate = 2;
    int n = *(int*)arg;

    while (1) {
        int factor;
        int is_prime = 1;

        /* 通过连续除法测试质数性。 */
        for (factor = 2; factor < candidate; ++factor) {
            if (candidate % factor == 0) {
                is_prime = 0;
                break;
            }
        }
        /* 这是我们正在寻找的质数吗？ */
        if (is_prime) {
            /* 将所需的质数作为返回值。 */
            return (void*)candidate;
        }
        ++candidate;
    }
    return NULL;
}

int main () {
    pthread_t thread;
    int which_prime = 5000;
    int prime;

    /* 计算线程，直到第 5,000 个质数。 */
    pthread_create(&thread, NULL, &compute_prime, &which_prime);
    /* 在这里做一些其他工作... */
    /* 等待质数线程完成并获取结果。 */
    pthread_join(thread, (void*)&prime);
    /* 打印计算出的最大质数。 */
    printf("%dth prime number is %d.\n", which_prime, prime);
    return 0;
}
```

### 关于线程 ID（Thread IDs）的更多信息

有时，确定代码序列是由哪个线程执行的是有用的。`pthread_self` 函数返回被调用时所在线程的线程 ID。可以使用 `pthread_equal` 函数将此线程 ID 与另一个比较。

这些函数用于判断特定的线程 ID 是否对应当前线程。例如，线程调用 `pthread_join` 自身是错误行为。在这种情况下，`pthread_join` 将返回错误代码 `EADLK`。为了提前检查，你可以使用如下代码：

```c
if (!pthread_equal (pthread_self(), other_thread))
    pthread_join (other_thread, NULL);
```

### 线程属性（Thread Attributes）

线程属性提供了一种精细调整单个线程行为的机制。回想一下，`pthread_create` 接受一个指向线程属性对象的参数。如果你传递一个空指针，则将使用默认线程属性来配置新线程。然而，你可以创建并自定义一个线程属性对象，以为属性指定其他值。

要指定自定义的线程属性，你必须遵循以下步骤：

- 1. 创建一个 `pthread_attr_t` 对象。简单的方法是直接声明一个类型为 `pthread_attr_t` 的自动变量。
- 2. 调用 `pthread_attr_init` 并传递该对象的指针。这会将属性初始化为其默认值。
- 3. 修改属性对象以包含所需的属性值。
- 4. 在调用 `pthread_create` 时传递属性对象的指针。
- 5. 调用 `pthread_attr_destroy` 释放属性对象。`pthread_attr_t` 变量本身被销毁；它可以通过 `pthread_attr_init` 重用。

单个线程属性可用于启动多个线程。在线程创建后，没有必要保留线程属性。

对于 GNU/Linux 编程任务，通常只有一个属性是有意义的（其他属性对于特殊实时编程来说是基础的）。这个属性是线程的分离状态（detach state）。线程可以被创建为可连接线程（joinable，默认值），也可以创建为分离线程（detached）。可连接线程像进程一样，在终止时不会被 GNU/Linux 自动清理。相反，线程的退出状态会悬挂在系统中（类似于僵尸进程），直到另一个线程调用 `pthread_join` 获取其返回值。只有那时，它的资源会被释放。与之相反，分离线程在终止时会被自动清理。由于分离线程会被立即清理，另一个线程可能无法通过 `pthread_join` 在其完成时进行同步，也无法获取返回值。

要在线程属性对象中设置分离状态，请使用 `pthread_attr_setdetachstate`。第一个参数是线程属性对象的指针，第二个参数是所需的分离状态。由于连接状态是默认值，因此有必要调用它来创建分离线程；将 `PTHREAD_CREATE_DETACHED` 作为第二个参数传递。

#### Listing 4.5 (detached.c) 创建分离线程的骨架程序

```c
#include <pthread.h>

void* thread_function(void* thread_arg)
{
    /* 在这里做工作... */
}

int main () {
    pthread_attr_t attr;
    pthread_t thread;

    pthread_attr_init(&attr);
    pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    pthread_create(&thread, &attr, &thread_function, NULL);
    pthread_attr_destroy(&attr);

    /* 在这里做工作... */
    /* 不需要连接线程。  */
    return 0;
}
```

即使线程是以连接状态创建的，稍后也可以将其转换为分离线程。要做到这一点，调用 `pthread_detach`。一旦线程被分离，它无法再变为可连接。

### 4.2 线程取消（Thread Cancellation）

在正常情况下，线程在从返回或调用 `pthread_exit` 时终止。然而，一个线程可以请求另一个线程终止。这被称为取消线程。要取消线程，调用 `pthread_cancel` 并传递要取消线程的线程 ID。取消的线程以后可以被连接（见 4.1.5 线程属性）。取消线程的返回值是特殊值 `PTHREAD_CANCELED`。

线程对于取消可以处于三种状态之一：

- 线程可以是异步取消的（asynchronously）。线程可以在执行过程的任何一点被取消。
