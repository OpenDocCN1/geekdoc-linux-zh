
最后，某些存根过程在请求后传输固定数量的变长数据。通常，这些过程（例如 `XMoveWindow` 和 `XSetBackground`）是通用函数 `XMoveResizeWindow` 和 `XChangeGC` 的特例。这些过程使用 `ReqExtra`，它与 `Req` 相同，只是多接收一个参数（在请求结构之后在输出缓冲区中分配的字节数）。该数字应该是 4 的倍数。注意，如果请求的长度超过 Xlib 的缓冲区大小（通常为 16K），作为防御性措施，`req` 可能被设置为 NULL。

# 变长参数

某些协议请求带有跟在 `xDoSomeReq` 结构之后的额外变长数据。这些数据的格式随请求而异。某些请求需要 8 位字节序列，另一些需要 16 位或 32 位实体序列，还有一些则需要结构序列。

有必要将任何长度的变长数据添加到请求结构的 `length` 字段中。`length` 字段的单位是 32 位长字（longwords）。如果数据是字符串或其他 8 位字节，你必须在添加之前先将长度向上取整并进行右移：

```c
req->length += (nbytes+3)>>2;
```

要传输变长数据，使用 `Data` 宏。如果数据适合输出缓冲区，则该宏会调用 `_XSend`。`Data`、`Data16` 和 `Data32` 是接受三个参数的宏：显示、数据的起始以及要发送的字节数。

```c
Data(display, data, nbytes);
```

```c
Data16(display, data, nbytes);
```

```c
Data32(display, data, nbytes);
```

如果协议需要回复，则用 `_XSend` 代替 `Data` 宏。`_XSend` 接受相同的参数，但因为它直接发送数据而不拷贝到缓冲区，所以速度更快。

# 回复

如果协议请求有回复，则带所有固定长度和变长参数调用 `_XReply`。`_XReply` 会刷新缓冲区并等待包到达。

```c
Status _XReply(display, rep, extra, discard);
```

- `display` 指定到 X 服务器的连接。
- `rep` 指定回复结构。
- `extra` 指定预期的 32 位字。
- `discard` 指定是否丢弃字节

`_XReply` 函数等待回复包并将其复制到指定的 `rep` 中。`_XReply` 处理接收回复之前发生的错误和事件包。`_XReply` 接受四个参数：

- `Display *` 结构
- 指向回复结构的指针（必须转换为 `XReply*`）
- 额外的 32 位字数量，size(xReply) = 回复结构中的 32 字节
- 表示是否丢弃超出 `extra` 指定字节的布尔

由于大多数回复结构长度为 32 字节，第三个参数通常为 0。核心协议的例外是 `GetWindowAttributes`、`QueryFont`、`QueryKeymap` 和 `GetKeyboardControl` 的回复，它们的回复更长。

如果回复后面还有额外的变长数据（例如列表或字符串），最后一个参数应为 `False`。如果没有变长数据，则应为 `True`。这个最后一个参数是为了向上兼容性考虑，允许客户端与发送数据比客户端预期的假设服务器版本正常通信。例如，后续版本的 `GetWindowAttributes` 可能会使用更大的、兼容的 `xGetWindowAttributes`，在结尾包含额外的属性数据。

对于不后跟变长数据的请求，你编写的代码类似于：

```c
_XReply(display, (XReply*)&rep, 0, True);
*rep1 = rep.rep1;
*rep2 = rep.rep2;
*rep3 = rep.rep3;
...
UnlockDisplay(dpy);
SyncHandle();
return (rep.rep4);
```

如果回复后有可变长度的数据，将 `True` 改为 `False`，并使用适当的 `_XRead` 函数读取可变长度的数据。

```c
_XRead(display, data_return, nbytes);
```

`display` 指定到 X 服务器的连接。

`data_return` 指定缓冲区。

`nbytes` 指定所需的字节数。

`_XRead` 函数将数量的字节数读取到 `data_return`。

```c
_XRead16(display, data_return, nbytes);
```

`display` 指定到 X 服务器的连接。

`data_return` 指定缓冲区。

`nbytes` 指定所需的字节数。

`_XRead16` 函数读取数量的字节数，将其解包为 16 位的数据量，并作为 shorts 类型存入指定的数组中。

```c
_XRead32(display, data_return, nbytes);
```

`display` 指定到 X 服务器的连接。

`data_return` 指定缓冲区。

`nbytes` 指定所需的字节数。

`_XRead32` 函数读取数量的字节数，将其解包为 32 位的数据，并作为 longs 类型存入指定的数组中。

```c
_XRead16Pad(display, data_return, nbytes);
```

`display` 指定到 X 服务器的连接。

`data_return` 指定缓冲区。

`nbytes` 指定所需的字节数。

`_XRead16Pad` 函数读取数量的字节数，解包到指定的数组中作为 16 位的数据量。如果字节数不是四的倍数，`_XRead16Pad` 会读取并丢弃多两个额外的填充字节（pad bytes）。

```c
_XReadPad(display, data_return, nbytes);
```

`display` 指定到 X 服务器的连接。

`data_return` 指定缓冲区。

`nbytes` 指定所需的字节数。

`_XReadPad` 函数将数量的字节数读取到 `data_return`。如果字节数不是四的倍数，`_XReadPad` 会读取并丢弃多三个额外的填充字节。

每个协议请求都略有不同。更多信息，请参阅 Xlib 源代码中的示例。

## 同步调用

每个过程在返回给用户之前，都应该有一个名为 `SyncHandle` 的宏调用。如果启用了同步模式（参见 `XSynchronize`），请求将立即发送。库将等待过程在服务器端可能产生的任何错误被处理。

如果你需要在临界区内部一个临时缓冲区（例如为了从线缆协议封装和解包数据），通用内存分配器在性能关键的输出函数中使用可能开销很大。以下函数返回一个供临界区内使用的临时缓冲区：

```c
char *XAllocScratch(display, nbytes);
```

- `display` 指定到 X 服务器的连接。
- `nbytes` 指定所需的字节数。

此存储只能在你的存根临界区内部使用。在任何可能允许另一个线程执行 Xlib 的调用之后，不能假设返回的指针是有效的。例如，在使用任何 `GetReq` `Data` 系列宏之后、在使用任何 `_XReply` 之后，或使用任何 `_XSend` 或 `_XRead` 系列函数之后，都不能假设该指针是有效的。

以下函数返回一个跨越临界区使用的临时缓冲区：

```c
char *XAllocTemp(display, nbytes);
```

- `display` 指定到 X 服务器的连接。
- `nbytes` 指定所需的字节数。

此存储可以在可能允许另一个线程执行 Xlib 的调用之间使用。该存储必须显式地返回给 Xlib。以下函数返回该存储：

```c
void _XFreeTemp(display, buf, nbytes);
```
