
软件未来的版本可能会发生微调，但核心思想和支持它的用户界面可能会保持不变。随着每个新版本的发布，用户对产品的体验不断提升，随着时间的推移，他们从一个“偶尔”用户转变为“高级”用户。

将用户转变为高级用户的过程从 Unix 的早期版本就开始就开始持续。在操作早期版本时学的大部分知识对于今天的 Linux 都是直接应用的。诚然，Linux 增加了一些自身的特性，但大体上，由于整个用户环境（从 shell 到常用的实用程序）的可移植性，经验丰富的 Unix 用户在 Linux 环境中会感到非常自如。

## 4.1.5 好程序永不消灭——它们会被移植到新的硬件平台

你是否注意到，某些程序以某种形式已经存在了多年？人们总是觉得它们很有用。它们具有真正的内在价值。通常会有人主动承担起任务，为了消遣或利润，将这些程序编写或移植到当前流行的硬件平台。

以 Emacs 风格的文本编辑器为例。虽然它们在某些方面是 Unix 应用的反面教材，但它们一直是程序员（尤其是 Unix 忠实者）的最爱。你不仅可以在 Unix 系统上找到它的版本，在其他系统上也能找到。尽管某些 Emacs 多年来已经变成了臃肿的单体结构，但在其最原始的形式，Emacs 仍然提供了一个体面的“无模式”工具，用于输入和操作文本。

另一个例子是典型的业务程序集，如 Microsoft Office 类似产品中的程序。人们发现，现代业务环境通常需要文字处理器、电子表格和演示文稿工具等桌面程序才能有效运行。

然而，没有任何个人、公司、组织甚至国家能独自将一个好的想法据为己有。最终，其他人会注意到，该想法的“合理复制品”开始出现。智能实体在识别出一个想法的价值后，应该努力在尽可能多的实际平台上实现它，以获得最大的市场份额。实现这一目标最有效的方法是编写可移植的软件。

## 案例研究：Atari 2600

让我们来看看 Atari 2600，它也被称为 Atari 视频计算机系统（VCS）。VCS 是第一个成功的家用视频游戏系统，是一个在正确的时间出现在正确位置的产品。它捕捉了人们的想象力——这些人刚刚在当地泳池和游戏机厅体验过《太空际入侵者》，并准备好将视频游戏的新世界带入客厅。作为第一台卡带可编程游戏机，它在开启整个行业之前，就将只存在于校园实验室和软件专业人士隐秘历史中的游戏乐趣带到了家庭电视屏幕上。如果说程序员对游戏有种兴趣，那么这种兴趣与美国主流社会乃至整个世界的兴趣相比，将是微不足道的。

2600 在推出时处于价格性能曲线的高位，它物物所值地提供了合理的性能。这台 8 位游戏机售价约为 100 美元。它配有几个摇杆和两对被称为“划板控制器”的电位器。Atari 为其配备了《战斗》（Combat），这是一张卡带，包含了包含喷战斗机、坦克和福克战斗机的各种双人战斗游戏。

Atari 在主机销售上获得的利润较少。大头来自游戏卡带的销售。单价从 14 美元到 35 美元不等，这些单元成了 Atari 以及许多希望从视频热潮中获利的小型软件公司的生源。从 Atari 的角度来看，一旦开发卡带的软件工程投资得以收回，剩下的就是纯利润。

我的朋友在一家生产 2600 卡带的软件公司找了工作。他解释说，将象棋游戏或“射击类”游戏挤进不足 8K 的 ROM 中是一项非常了不起的成就。这就像把人挤进一辆大众甲；但并不是每个人都有机会检查窗户。

在编写游戏卡带的代码时，他写下了职业生涯中最高效且最不可移植的软件。他将指令视为数据，将数据视为指令。某些操作是在水平行扫描期间执行的，此时电视机上的光束在完成屏幕右侧最后一个点后，返回到左侧。为了节省内存，必须采取一切可能的捷径。他的代码既是艺术品，也是软件维护者的最极噩梦。

在 2600 统治的某段时间，Atari 引入了 800，这是一种基于 `6502` 的系统，成为其家用电脑产品线的旗舰。800 在某种意义上是一台真正的计算机，因为它有一个类打字机的键盘，以及用于辅助存储设备和通信设备的接口。800 的售价接近 1000 美元，对 2600 的封闭利基市场几乎没有威胁——直到内存芯片的价格下降。

由于其他供应商的竞争压力以及 800 扩展的图形能力，Atari 面临巨大的压力，需要生产一种能够运行 800 软件的大众视频游戏机。这台新机器被命名为 5200，让大众市场的精英能够运行技术极客在 800 上玩的同样的游戏。

一旦大众发现了这台神奇的新机器，就抛弃了简陋的 2600，转向了 5200 更流畅的画面。随后，Atari 2600 游戏卡带的价格迅速崩跌。预计 2600 将灭亡的经销商开始大砍其现有库存的价格，实际上向市场倾销了廉价的 2600 游戏卡带。

## 4.1.6 原则 4：选择可移植性优于效率

因此，我们一直在讨论可移植软件与高效软件的优缺点。易于迁移到新平台的代码比利用硬件特性的代码价值得多。我们已经看到，这一准则可以用真实的标准来衡量（即金钱）。为了保护利润基础，软件公司应该在其产品中追求可移植性，可能在此过程中放弃效率。

然而，可移植的代码只能部分实现移植性目标。所有的应用程序由指令和数据组成。通过让指令可移植，你确保了你的代码可以在明年机器上运行。那么你的数据会发生什么？它们会被遗弃吗？完全不会。Unix 程序员选择不仅让代码可移植，也让数据可移植。

如何让数据可移植？Unix 哲学的下一个是一个解决方案。

## 原则 5：将数据存储在平面文件中

“平面文件”意味着你以文本形式存储所有数据。如此。禁止二进制文件。不允许特殊的文件系统格式。这排除了许多为了专有目的而发明的有趣的不可移植的格式。数据文件应仅由由行字符（Unix 世界术语中的“换行符”）分隔的字节流组成。

## 原则 5：将数据存储在平坦文本文件中

存储媒体最终必须存放在某个地方。留在磁盘上的数据价值会降低。为了让数据保持活力和价值，它必须经常移动。否则，它就应该被归档并删除。

无去处的数据是死数据。

如果你希望能够轻松移动数据，就必须使其具有可移植性。任何数据移动的障碍（无论是无意的还是设计过的）都会限制你数据的潜在价值。数据在某处存放的时间越长，它最终到达时的价值就越低。问题在于，如果你的数据在目的地不是有用的格式，就必须进行转换。这种转换过程需要时间。数据转换中的每一秒都在侵蚀你的数据价值。

美国新闻网（CNN）1991年因对海湾战争的报道荣获最高荣誉。CNN 为世界提供了冲突的生动画面，而且动作迅速。许多人每天晚上冲回家家里的电视机前观看事件的发展。如果制作人员花费几天时间将 VHS 录带从 VHS 转换为 VHS，然后通过航空邮件寄到亚特兰大，并且只在黄金时段播放，那么 CNN 的报道还会引人入胜吗？

你的数据也是如此。如果需要额外的时间将数据从不可移植的格式转换以便移动，那么当数据到达时价值就没那么高了。世界运行得太快，没时间等待你的数据。

### 4.2.1 文本是一种通交换格式

文本并不一定是性能最高的格式，但它是最常见的格式。其他格式已用于某些应用，但没有一种格式能像文本那样获得如此广泛的认可。在所有情况下，文本编码的数据都可以由目标平台处理。

通过使用文本，你消除了将数据从一种格式转换为另一种格式的困难。很少有二进制格式是标准化的。每个厂商都定义自己的二进制编码，而且其中大多数都是不一样的。从一个厂商的格式转换为另一个厂商的格式可能是一项艰巨的任务，需要几天到几个月不等。这段时间如果用于使用数据会好得多。

### 4.2.2 文本易于阅读和编辑

可以在不使用转换工具的情况下检查文本数据。如果数据看起来不对，可以使用标准的文本编辑器对其进行修改。不需要专门工具。你不需要为每种数据文件准备一个单独的编辑器。一个就能通用。

在开发在 Unix 下使用管道（`pipes`）的程序时，文本文件的真正威力变得显而易见。管道是一种在不使用临时文件的情况下，将一个程序的输出作为另一个程序的输入的机制。许多程序其实无非是由一系列管道连接的较小程序集合。当开发者编写程序原型时，可以轻松地检查流水线每个节点点的数据准确性。如果有问题，他们可以中断管道流，并确定是数据还是处理数据的操作器出了问题。这大大加快了开发过程，使 Unix 程序员相比于其他操作系统的程序员具有显著优势。

文本文件还简化了 Unix 用户与系统的界面。Unix 下的大部分管理信息都存储在平坦文本文件中，并可进行通用检查。这显著减少了个人访问信息以完成日常工作所花费的时间。只需极少的努力即可获取有关其他用户、网络系统和一般统计数据的信息。讽刺的是，这里可移植的数据反而带来了更高的效率。
