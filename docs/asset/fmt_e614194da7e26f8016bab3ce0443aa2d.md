## `fold`—将每行折叠到指定的长度

折叠是在指定的宽度处折断文本行的过程。与我们的其他命令一样，`fold` 接受一个或多个文件或标准输入。如果我们向 `fold` 发送一个简单的文本流，就可以看到它的工作原理。

```bash
me|box -s] echo "The quick brown fox jumps over the lazy dog." | fold -w 12
The quick br
own fox jump
s over the l
azy dog.
```

这里是 `fold` 的演示。`echo` 命令发送的文本被分为 `-w` 选项指定的段。在这个例子中，我们指定了12个字符的行宽。如果没有指定宽度，默认为80个字符。注意无论单词边界，行是如何折断的。添加 `-s` 选项会导致 `fold` 在达到行宽之前的最后一个可用空格处折行。

```bash
@linux -js echo "The quick brown fox jumps over the lazy dog." | fold -w 12 -s
The quick
row fox
jumps over
the lazy
dog.
```

# `fmt`—一个简单的文本格式化器

`fmt` 程序也可以折叠文本，此外还有很多。它接受文件或标准输入，并对文本流进行段落格式化。基本上，它会填充并合并文本中的行，同时保留空行和缩进。为了演示这一点，我们需要一些时间。假设我们想将此文本重新格式化为50字符的列。我们可以通过用 `fmt` 和 `-w` 选项处理文件来实现。

```bash
@linux -js fmt -w 50 fmt-info.txt
从指定的参数读取（如果没有提供，则从标准输入读取），并输出到标准输出。
```

默认情况下，空行、单词之间的空格和缩进在输出中保留；连续的具有不同输入的行不会被合并；制表符在输入时扩展并在输出时引入。嗯，这是一个很奇怪的结果。也许我们应该读读这段文本，因为它解释了发生了什么。

默认情况下，空行、单词之间的空格和缩进在输出中保留；连续的具有不同输入的行不会被合并。因此，`fmt` 保留了第一行的缩进。幸运的是，`fmt` 提供了一个选项来修复这个问题。

```bash
@linuxbox -js cat > fmt-code.txt
## 这是一个包含注释的文件。

## # 这一行是注释。
## 后面是另一行注释。
## 还有另一个。

另一方面，这是一行代码。
## 另一行代码。
## 另一个。
```

我们的示例文件包含以 `# `（井号加空格）开头的注释，以及不包含该字符串的“代码”行。现在使用 `fmt`，我们可以格式化注释并将代码保持。

```bash
@linuxbox -js fmt -w 50 -p ' ' fmt-code.txt
## 这是一个包含注释的文件。
```

## 这一行是注释。后面是另一行

## 注释行。另一行注释。

另一方面，这是一行代码。

另一行代码。

还有另一行。

> 注意，相邻的注释行会被合并，而空行以及不以指定前缀开头的行会被保留。

## `printf`—格式化并打印数据

与本章中的命令不同，`printf` 命令不用于管道操作（它不接受标准输入），也不会在命令行中直接频繁应用（它主要用于脚本）。那么，它为什么重要呢？因为它的使用非常广泛。

`printf`（源自短语 "print formatted"）最初是为 C 语言语言开发的，并实现在包括 Shell 在许多许多语言中。事实上，在 bash 中，`printf` 是内置命令。

`printf` 的工作如下：

```
printf [-v var] "format" arguments
```

命令接收一个包含格式描述的字符串，然后将其应用于参数列表。格式化后的结果将发送到标准输出，除非指定了 `-v` 选项，此时格式化结果将存储在变量 `var` 中。这里有一个 `printf` 应用的简单示例：

```
[melinux]$ printf I formatted the string: %s\n foo
I formatted the string: foo
```

这里使用了 `-v` 选项，结果被放在变量中，而不是发送到标准输出：

```
[me@linux]$ printf -v result "I formatted the string: %s\n" foo
[me@linux]$ echo "$result"
I formatted the string: foo
```

格式字符串可能包含字面（如 "formatted the string:"）、转义序列（如 `\n`，换行符）以及以 `%` 字符开头的序列，这些被称为转换规范。在这个示例中，转换规范 `%s` 用于格式化字符串 `foo` 并将其置于命令的输出中。这里再次演示：

```
[me@linux]$ printf "I formatted '%s as a string.\n" foo
I formatted 'foo' as a string.
```

我们可以看到，`%s` 转换规范在命令输出中被字符串 `foo` 替换。`%s` 用于格式化字符串数据。对于其他类型的数据还有其他的说明符。表 21-4 列出了常用的数据类型说明。

## 表 21-4：常用的 printf 数据类型说明符

## 文档格式化系统

到为止，我们检查了简单的文本格式化工具。这些对于小型简单任务很好，但更大的任务呢？Unix 成为技术和科学用户中流行的操作系统的原因之一（除了为各种软件开发提供强大的多任务、多用户环境外），是它提供了可以生成多种类型文档的工具，特别是科学和学术出版物。事实上，GNU 文档描述，文档准备对 Unix 的开发至关重要。

UNIX 的第一个版本是在贝尔实验室流行的一台 PDP-7 上开发的。1971 年，开发者想为其他操作系统获取一台 PDP-11。为了证明该系统的价值，他们提议为 AT&T 部门实现一个文档格式化系统。第一个格式化程序是 McIlroy 的 `roff` 的实现，由 J. Ossmann 编写。

两个主要的文档格式化家族主导着该领域：源自原始 `roff` 程序的家族（包括 `noff` 和 `troff`），以及基于 Donald Knuth 的 `tex`（读作 "tek"）排字系统的家族。而且，中间的“E”是其名称的一部分。

`roff` 程序源于术语 "run off"，意为“我为你印一份”。它用于为使用等宽字体的设备格式化输出，例如字符打印机打字机式打印机。在引入时，这包括所有连接到计算机的打印设备。随后的 `troff` 程序为在排版机上输出文档，排版机是用于为商业印刷制作“摄影版”的设备。今天大多数计算机打印机都能模拟排版的输出。`roff` 家族还包括一些用于准备文档部分的程序。这些包括 `eq`（用于数学方程）和 `tbl`。

TEX 系统（稳定形式）于 1989 年首次出现并在某种程度上取代了 `troff` 成为排版输出的首选工具。我们在这里不涵盖 TEX，是因为它的复杂性（有整本书在介绍它），也是因为没有安装。

在大多数现代 Linux 系统上默认如此。

## 注意事项

对于对安装 TEX 感兴趣读者，请查看 texlive 软件包（您可以在大多数发行版仓库中找到它）以及 LyX 图形内容编辑器。

## `groff`

`groff` 是一套程序，包含了 `troff` 的 GNU 实现。它还包含一个用于模拟 `roff` 以及该系列家族中其他工具的脚本。

虽然 `roff` 及其后代被用于制作格式化文档，但其实现方式对现代用户来说非常陌生。大多数文档都是使用文字处理器产生的，这些处理器能够在单一步内完成文档的排版和布局。在图形化文字处理器出现之前，文档通常通过一个两步过程产生：首先使用文本编辑器进行排版，然后使用如 `troff` 之类的处理器来应用格式化。格式化程序的指令通过使用标记语言嵌入到排版后的文本中。这种过程的现代对应物是网页，它是使用某种文本编辑器进行排版的，然后由网页浏览器使用 HTML 作为标记语言来渲染最终的页面布局。

我们不会完整介绍 `groff`，因为其标记语言的许多元素涉及排版学的奥秘细节。相反，我们将集中于其宏包中被广泛使用的一个。这些宏包将许多低级命令压缩为一组较小的高级命令，使得使用 `groff` 变得简单得多。

让我们先考虑一下简单的帮助页（man page）。它存储在 `/usr/share/man` 目录下，是一个 gzip 压缩的文本文件。如果我们检查其解压后的内容，将会看到以下内容（第 1 节帮助页）：

