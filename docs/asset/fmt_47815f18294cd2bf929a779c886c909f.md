
关于 `define` 的信息请参见下一节。

# 第 6 章：变量的使用

## 6.8 定义多行变量

设置变量值的另一种方法是使用 `define` 指令。该指令具有特殊的语法，允许在值中包含换行符，这对于定义所谓的命令序列（参见第 5.8 节 [定义预定义配方]，第 56 页）以及配合 `eval` 使用的 make 部分（参见第 8.9 节 [eval 函数]，第 30 页）非常方便。

`define` 指令同一行后面是被定义的变量名和一个（可选的）赋值运算符，外无其他内容。赋予变量的值出现在随后的行中。值的结束由一行仅包含 `endif` 的行标记。由于这种语法上的差异，`define` 的工作方式就像任何变量定义。变量名可以包含函数和变量引用，这些引用在读取 `define` 时会被展开以找到实际的变量名。

如果你愿意，可以省略赋值运算符。如果省略，`make` 会假设它为 `-` 并创建一个递归展开变量（参见第 6.2 节 [变量的类型]，第 60 页）。当使用 `+=` 运算符时，值将追加到之前的值之后，就像任何其他追加运算符一样：

你可以嵌套 `define` 指令：`make` 会跟踪嵌套的指令，如果它们没有用 `endif` 正确关闭，将报告错误。注意，以配方前缀字符开头的行被视为配方的一部分，任何 `define` 或 `endif` 字符串都不会被 `make` 考虑。

```makefile
define two-lines =

echo foo

echo $(bar)

endif
```

普通赋值的值不能包含换行符；但 `define` 中的换行符会成为变量值的一部分。在配方中使用时，以下示例功能上等同于：

```makefile
two-lines = echo foo; echo $(bar)
```

因为由分号分隔的两个命令类似于两个独立的 shell 命令。然而，注意使用两个独立的行意味着 `make` 会调用两次 shell，为每一行运行一个独立的 shell。参见第 5.3 节 [配方执行]，第 44 页。

如果你希望使用 `override` 指令定义的变量优于命令行变量，请将 `override` 指令与 `define` 配合使用：

```makefile
override define two-lines =

foo

$(bar)

endif
```

参见第 6.7 节 [override指令]，第 68 页。

## 6.9 未定义的变量

如果你想清除一个变量，将其值为空通常足够了。无论如何，展开此类变量都会得到相同的结果（空字符串）。但是，如果你在使用 `flavor`（参见第 8.11 节 [类型函数]，第 95 页）和 `origin`（参见第 8.10 节 [来源函数]，第 94 页）函数，未设置的变量与空变量之间存在差异。在这种情况下，你可能希望使用 `undefined` 指令让变量看起来像从未设置过一样：

```makefile
foo := foo

bar = bar

undefined foo

undefined bar

$(info $(origin))

$(info $(flavor))
```

此示例将为两个变量都打印 "undefined"。如果你想取消命令行变量的定义，可以使用 `override` 指令配合 `undefined`：

```makefile
override undefined CFLAGS
```

## 6.10 来自环境的变量

`make` 中的变量来自运行 `make` 的环境。`make` 启动时看到的每个环境变量都会转换为具有相同名称和值的 `make` 变量。然而，Makefile 中的显式赋值会覆盖环境变量。（如果指定了 "e" 标志，则 Makefile 中的环境变量赋值将生效。参见第 9.7 节 [选项摘要]，第 104 页。但这并不是推荐的做法。）

通过在环境中设置 `CFLAGS`，你可以让大多数 Makefile 中的所有编译使用你喜欢的编译器，因为 `make` 不会将它们用于其他事情。（注意，这并不可靠；Makefile 显式设置了 `CFLAGS`，因此不受环境变量的影响）。

当 `make` 配方时，Makefile 中定义的变量会被传递给每个 shell 环境。这允许你将值传递给递归的 `make` 调用（参见第 5.7 节 [递归使用 make]，第 50 页）。默认情况下，只有来自环境或命令行的变量会被传递给递归调用。你可以使用 `export` 指令传递其他变量。详细信息请参见第 5.7.2 节 [将变量传递给子 make]，第 52 页。

不推荐其他使用环境变量的方法。Makefile 依赖环境变量来设置控制是不明智的，因为会导致不同的用户从同一个 Makefile 获得不同的结果。这是大多数 Makefile 的要点。

在使用交互式 `SHELL` 时可能会出现此类问题，它通常存在用户选择的交互式 shell 中。这对 `make` 的影响是不理想的，因此 `make` 以特殊方式处理 `SHELL` 环境变量；参见第 5.3.2 节 [选择 Shell]，第 45 页。

## 6.11 特定目标的变量值

`make` 中的变量值通常是全局的；无论在哪里求值它们都是相同的。其中一个例外是自动变量（参见 10.5.3 节 [自动变量]，第 120 页）。

另一个例外是特定目标的变量。此功能允许你根据 `make` 当前正在构建的目标为同一个变量定义不同的值。与自动变量一样，这些值仅在目标的上下文中可用。

如下所示设置特定目标的变量：

```makefile
target := variable-assignment
```

多个目标会为目标列表中的每个成员单独创建一个特定目标的变量值。目标赋值中的所有变量都生效。注意，该变量实际上区别于任何“全局”值；二者不具有相同的类型（递归与简单）。

特定目标的变量优先级与任何其他变量相同。命令行上提供的变量（以及在强制执行 -e 选项时环境中的变量）具有更高的优先级。指定 `override` 指令将允许特定目标的变量值被优先。

特定目标变量还有一个特殊特性：当你定义一个特定目标的变量值时，它对该目标的所有依赖项、其所有依赖项等也有效（除非那些依赖项使用自己的特定目标变量值进行了覆盖）。例如，如下：

```makefile
prog : CFLAGS = -g

prog : prog.o foo.bar
```

这将 `prog` 的配方中的 `CFLAGS` 设置为 '-g'，但它也会在创建 `prog.o`、`foo.bar` 以及任何创建其依赖项的配方中设置 `CFLAGS`。

注意，如果同一个文件是多个目标的依赖项，且这些目标对特定目标变量有不同的值，那么在一次 `make` 调用中只会构建一次，第一个构建的目标将导致该依赖项继承第一个目标的特定目标值。它将忽略其他目标的特定目标值。

## 6.12 模式特定变量值

除了特定目标的变量（参见第 6.11 节 [特定目标的变量]，第 71 页），GNU `make` 还支持模式特定变量。在这种格式下，为任何匹配指定模式的目标定义变量。

如下所示设置模式特定变量值：

```
pattern ... : variable-assignment
```

其中 `pattern` 是一个 `%-pattern`。作为目标特定的变量值，多个模式值会为每个模式单独创建一个模式特定的变量值。变量赋值可以是任何有效的赋值形式。除非指定了覆盖（override），否则任何命令行设置都具有高优先级。

例如：

```makefile
%. : CFLAGS = -0
```

将为所有匹配模式 `%.o` 的目标分配 `CFLAGS` 值为 '-0'。
如果一个目标匹配了多个模式，则执行具有更长基准（stems）的匹配模式特定变量。这导致更具体的变量优先于通用的变量，例如：

```makefile
%.o:

$(CC) -$(CFLAGS) $(CPPFLAGS) $< -o $$
```

```makefile
lib/*.o: CFLAGS = -fPIC -g

%.o: CFLAGS = -g
```

```makefile
all: foo lib/bar.
```

在这个示例中，`CFLAGS` 变量的第一个定义将被用于更新 'lib/bar$，尽管第二个定义也适用于它。具有相同长度长度的模式特定变量按照它们在 Makefile 中定义的顺序被考虑。模式特定变量的搜索顺序是在该目标定义的目标特定变量之后，在父目标定义的目标特定变量之前。

## 6.13 抑制继承

如前面的章节所述，变量会被先决项（prerequisites）继承。这种能力允许根据先决项导致重新构建的目标来修改其行为。例如，你可以在 debug 目标上设置一个目标特定变量，使得 'make debug' 将不会有该赋值。有时，你可能希望某个变量不要继承。对于这些情况，make 提供了私有修饰符（private）。虽然该修饰符用于任何变量赋值，但用于目标特定是有意义的。任何标记为 private 的变量对其本地目标可见，但不会被递归目标继承。标记为 private 的全局变量在全局范围内可见，但不会被任何目标继承，且不会在任何配方（recipe）中可见。例如，考虑这个 Makefile：

```makefile
EXTRA_CFLAGS =

prog: a.o b.o

EXTRA_CFLAGS = -L/local/lib
```

由于 private 修饰符，a.o 和 b.o 将不会继承 prog 目标的 `EXTRA_CFLAGS` 赋值。

## 6.14 特殊变量

GNU make 支持具有特殊属性的变量。

`MAKEFILE_LIST`
包含 make 解析的每个 Makefile 的名称，按照它们解析的顺序排列。名称在 make 开始解析之前附加。因此，如果 make 的第一次操作是检查此变量中的最后一个单词，它将是当前 Makefile 的名称。然而，当前 Makefile 使用 include 后，最后一个单词是：

```makefile
name1 = $(lastword $(MAKEFILE_LIST))

include inc.mk

name2 = $(lastword $(MAKEFILE_LIST))

all:

  @echo name1

  @echo name2
```

那么你将看到如下输出：

```
name1 = Makefile

name2 = inc.mk
```

`.DEFAULT_GOAL`
当命令行没有指定目标时，设置使用的默认目标（参见第 9.2 own [指定目标的参数]）。`.DEFAULT_GOAL` 变量允许发现当前的默认目标、默认目标选择算法或显式设置我们自己的。下面的示例说明了这些情况：

```makefile
ifeq ($(DEFAULT_GOAL),)

$(warning no default goal is set)

endif

.PHONY: foo

foo: @echo $@

$(warning default goal is $(DEFAULT_GOAL))

.PHONY: bar

bar: @echo $@

$(warning default goal is $(DEFAULT_GOAL))

.DEFAULT_GOAL := foo
```

此文件将打印：
no default goal is foo
default goal is bar
注意，给 `.DEFAULT_GOAL` 分配多个名称是无效的，会导致错误。

`MAKE_RESTARTS`
此变量仅在此实例重启时被设置（参见第 3.5 节 [Makefile 是如何制作的]）；它将包含此实例重启的次数。注意，这不等同于递归（由 `LEVEL` 变量计数）。你不应该设置、修改或导出此变量。

`.RECIPEPREFIX`
该变量值的第一个字符被用作 make 假设引入配方行的字符。如果该变量为空（默认如此），则该字符是标准的制表符（tab）。例如，这是一个有效的 Makefile：

```makefile
.RECIPEPREFIX =

all:

  @echo Hello, world
```

`.RECIPEPREFIX` 的值可以被多次更改；一旦设置，它对于在修改之前解析的所有规则保持有效。

`.VARIABLES`
展开为目前为止定义的所有全局变量的名称列表。这包括值值的变量，以及内置变量（参见第 10.3 节 [隐式规则使用的变量]），但不包括任何仅在目标特定上下定义的变量。注意，你分配给此变量的任何值都将被忽略；它将始终返回其特殊值。

展开为此版本的 make 支持的特殊功能列表。可能的值包括但不限于：
- 'archives' 支持使用特殊语法处理 ar（归档）文件。参见第 11 章 [使用 make 更新归档文件]。
- 'check-symlink' 支持 -L (--check-symlink-times) 标志。参见第 9.7 节 [选项摘要]。
- 'else-if' 支持“else if”非嵌套条件判断。参见第 7.2 节 [条件判断语法]。
- 'observer' 支持“作业服务器”增强的并行构建。参见第 5.4 节 [并行执行]。
- 'oneshell' 支持 .ONESLL 特殊目标。参见第 5.3.1 节 [使用 Shell]。
- 'order-only' 支持仅相关的先决项。参见第 4.2 节 [先决项的类型]。
- 'second-expansion' 支持先决项列表的二次展开。
- 'shortest-stem' 使用“最短基准”方法选择多个适用选项中的模式。参见第 10.5.4 节 [模式如何匹配]。
- 'target-specific' 支持目标特定和模式特定的变量赋值。参见第 6.11 节 [目标特定变量值]。
- 'undefine' 支持 undefine 指令。参见第 6.9 节 [未定义指令]。
- 'guile' 有 GNU Guide 作为嵌入扩展语言可用。参见第 12.1 节 [GNU Guile 集成]。
- 'load' 支持动态加载。参见第 12.2 节 [加载动态对象]。

`INCLUDE_DIRS`
展开为 make 搜索的目录列表（参见第 3.3 节 [包含 Makefile]）。

```makefile
ifeq ($(CC),gcc)

libs=$(libs_for_gcc)

else

libs=$(normal_libs)

endif
```

```makefile
foo: $(objects)

  $(CC) -o $(objects) $(libs)
```

# 第 7 章：Makefile 的条件部分

## 7.2 条件判断的语法

没有 `else` 的简单条件判断的语法如下：

```makefile
条件指令

text-if-true 文本

endif
```

`text-if-true` 可以是任意文本，如果条件为真，则它被视为 Makefile 的一部分。如果条件为假，则不使用该文本。

复杂条件判断的语法如下：

```makefile
条件指令

text-if-true 文本

else

text-if-false 文本

endif
```

或者：

```makefile
条件指令

text-if-one-is-true 文本

else 条件指令-二

text-if-two-is-true 文本

else

text-if-one-and-two-are-false 文本

endif
```

可以根据需要包含任意数量的 `else 条件指令` 子句。一旦某个条件为真，就会使用 `text-if-true` 而不再使用其他子句；如果没有任何条件都为真，则使用 `text-if-false`。`text-if-true` 和 `text-if-false` 可以是任意行数的文本。

无论条件是简单的还是复杂的（无论是否有 `else`），条件指令的语法都是相同的。有四种不同的指令测试不同的条件。以下是它们的表格：

```makefile
ifeq (arg1, arg2)

ifeq 'arg1', 'arg2'

ifeq "arg1" "arg2"

ifeq "arg1" 'arg2'

ifeq 'arg1' 'arg2'
```

展开 `arg1` 和 `arg2` 中的所有变量引用并对其进行比较。如果它们相同，则 `text-if-true` 有效；否则，如果存在 `text-if-false`，则它有效。

通常你可能想要测试一个变量是否具有非空值。当该值是由变量和函数的复杂展开时，你认为为空的扩展实际上可能包含空白字符，因此不被视为为空。然而，你可以使用 `strip` 函数（参见第 8.2  [文本函数]）来避免将空白解释为非空值。

```makefile
ifeq($(foo))

text-if-empty 文本

endif
```

如果 `$(foo)` 的展开包含空白字符，将评估 `text-if-empty`。

```makefile
ifeq (arg1, arg2)

ifeq 'arg1', 'arg2'

ifeq "arg1" "arg2"

ifeq "arg1" 'arg2'

ifeq 'arg1' 'arg2'
```

展开 `arg1` 和 `arg2` 中的所有变量引用并对其进行比较。如果它们不同，则 `text-if-true` 有效；否则，如果存在 `text-if-false`，则它有效。

## ifdef 变量名

`ifdef` 取变量名为其参数，而不是变量的引用：该变量的值具有非空值，则 `text-if-true` 有效；否则，如果存在 `text-if-false`，则它有效。从未定义的变量具有空值。文本 `variable-name` 会被展开，因此它可能是一个变量或展开为变量名的函数。例如：

```makefile
bar = true

foo = bar

def $(foo)

frobozz = yes

endif
```

变量引用 `$(foo)` 被展开，得到 `bar`，这被视为变量名。变量 `bar` 不被展开，但会检查其值以确定其是否非空。

注意，`ifdef` 只测试变量是否具有值。它不会展开变量来查看该值是否非空。因此，使用 `ifdef` 的测试对所有定义的变量都返回真。因此，使用 `ifeq` 来测试值是否非空，以展开变量。例如：

```makefile
bar = true

foo = bar

ifeq ($(foo),bar)

frobozz = yes

endif
```
