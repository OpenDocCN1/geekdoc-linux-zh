
基本上，程序的操作从基数开始，并将其同时存储为乘数（存储在 `%ebx` 中）和当前值（存储在 `-4(%ebp)` 中）。它还将将指数存储在 `%ecx` 中。然后它将当前值乘以乘数，减少指数，如果指数（在 `%ebx` 中）降到 1，则退出循环。

到目前为止，你应该能够在没有帮助的情况下通过该程序了。你唯一需要知道的是 `imul` 执行整数乘法并将结果存储在第二个操作数中，而 `decl` 将给定的寄存器减 1。有关这些及其他指令的更多信息，请参见附录 B。

现在可以尝试的一个好项目是扩展该程序，使其在指数为 0 时返回该数字的值（提示：任何数的 0 次幂都是 1）。继续尝试。如果起初不起作用，尝试用草稿纸手动推演你的程序，跟踪 `%ebp` 和 `%esp` 指向哪里，栈上有什么，以及每个寄存器中的值是多少。

## 递归函数

下一个程序将进一步地考验你的大脑。该程序将计算一个数的阶乘。阶乘是一个数与其与 1 之间所有数的乘积。例如，7 的阶乘是 `7*6*5*4*3*2*1`，4 的阶乘是 `4*3*2*1`。现在，人们可能会注意到，一个数的阶乘等于该数与其下方阶乘的乘积。例如，4 的阶乘是 4 倍 1 的阶乘。3 的阶乘是 3 倍 2 的阶乘。这种定义被称为递归定义。这意味着，阶乘函数的定义包含了阶乘函数本身。然而，由于所有函数都需要结束，递归定义必须包含一个基础情况（base case）。如果没有基础情况，函数将无限递归调用，直到最终耗尽栈空间。在阶乘的情况下，基础情况是数字 1。当我们遇到数字 1 时，我们不再再次运行阶乘，只需说 1 的阶乘是 1。所以，让我们来看看阶乘函数的代码应该是什么样子的：

1. 检查数字。
2. 该数字是 1 吗？
3. 如果是，答案是一。
4. 否则，答案是该数字乘以该数字减后的阶乘。

如果没有局部变量，这将出现问题。在其他程序中，将值存储在全局变量中运行良好。然而，全局变量只为每个变量提供一个副本。在这个程序中，将有多个同时运行的函数副本，它们都需要它们自己的数据副本！由于局部变量存在于栈帧上，且每个函数调用都有自己的栈帧，所以我们没问题。

让我们看看代码是如何是如何运作的：

```assembly
## 目的 - 给定一个数字，此程序计算
## 阶乘。例如，3 的阶乘
## 是 3 * 2 * 1，或 6。4 的阶乘
## 是 4 * 3 * 2 * 1，或 24，依此类推。
```

## 此程序展示了如何递归调用函数。

.section .data

## 此程序没有全局数据

.section .text

```assembly
.global _start
.global factorial #除非我们要在与其他程序之间
## 共享此函数，否则是不需要的
```

```assembly
_start:
pushl $4          # 阶函数接收一个参数
call factorial
addl $4, %esp     # 清理栈
movl %eax, %ebx    # 设置退出状态
int $0x80         # 退出

factorial:
    pushl %ebp
    mov %esp, %ebp
    sub $4, %esp
    movl 4(%ebp), %eax # 加载参数
    cmpl $1, %eax      # 数字是1 吗？
    je base_case       # 如果是，答案是一
    
    movl %eax, -4(%ebp) # 存储当前值
    decl 4(%ebp)       # 减少指数
    pushl %eax         # 递归调用 factorial
    call factorial
    movl -4(%ebp), %ebx # 将结果乘以乘数
    imul %ebx, %eax
    
base_case:
    movl $1, %eax      # 基础情况
    movl %ebp, %eb
    ret
```

*(注：上面的汇编代码是根据提供的逻辑片段重构的，因为 OCR 识别严重破碎。）*

`.type` 指令告诉链接器 `factorial` 是一个函数。除非我们在其他程序中使用 `factorial`，否则这并不是真正需要的。为了完整性，我们包含了它。显示 `factorial:` 的这一行将符号 `factorial` 指向下一个指令的存储位置。这就是当我们说 `call factorial` 时，`call` 知道去哪里的地方。

函数的第一条指令是：

```
pushl %ebp
mov %esp, %ebp
```

如上一个程序所示，这为该函数创建了栈帧。这两行将是你启动每个函数的标准。

下一条指令是这个：

```
movl 8(%ebp), %eax
```

这使用基址指针寻址将函数的第一个参数移动到 `%eax` 中。记住，`(%ebp)` 是旧的 `%ebp`，`4(%ebp)` 是返回地址，而 `8(%ebp)` 是函数第一个参数的位置。如果你回想起来，在第一次调用时，这个值将是 4，因为这是我们在调用函数之前推入栈的值（通过 `pushl $4`），作为参数放入 `%eax`。由于这个函数会调用自己，它也将会有其他值。

接下来，我们检查是否达到了基础情况（参数为 1）。如果是，我们就跳转到标签 `end_factorial` 处的指令，并在那里进行返回。它在 `%eax` 中，正如我们之前提到的，那是返回值的地方。这是通过这些行实现的：

```
cmpl $1, %eax
je end_factorial
```

如果不是我们的基础情况，我们之前说要做什么？我们将用参数减1后再次调用 `factorial` 函数。因此，我们将 `%eax` 减 1：

```
decl %eax
```

`decl` 代表减（decrement）。它从给定的寄存器或内存位置（在我们例中为 `%eax`）减 1。`incl` 是反操作——它加 1。在减去 `%eax` 后，我们将其推入栈，因为这将是下一次函数调用的参数。然后我们调用 `factorial`！

```
pushl %eax
call factorial
```

好了，现在我们调用了 `factorial`。需要记住的一点是，在函数调用之后，我们永远无法知道寄存器的状态（`%esp` 和 `%ebp` 除外）。所以尽管我们有用 `%eax` 调用时的值，但它已经不再了。因此，我们需要从第一次获取值的相同位置从栈中取出（在 `8 (%ebp)`）。所以，我们这样做：

```
movl 8(%ebp), %ebx
```

现在，我们要把那个数字与 `factorial` 函数的结果相乘。如果你记得我们之前的讨论，函数的结果保存在 `%eax` 中。因此，我们需要将 `%ebx` 与 `%eax` 相乘。通过这条指令完成：

```
imull %ebx, %eax
```

这把结果也存储在 `%eax` 中，这正是我们希望函数返回值所在地！由于返回值已经到位，我们只需要离开函数。如果你记得，在函数开始时我们推入了 `%ebp`，并将 `%esp` 移动到 `%ebp` 以创建当前的栈帧。现在我们反向操作以销毁栈帧并激活上一个：

```
end_factorial:
movl %ebp, %eax
popl %ebp
```

现在我们已经准备好返回了，所以我们发出以下命令

```
ret
```

这从栈顶弹出一个值，然后跳转到该值。如果你记得我们关于 `call` 的讨论，我们说 `call` 在跳转到函数开头之前，首先将下一个指令的地址推入栈。所以，在这里我们将其弹出，以便返回到那里。函数执行完毕，我们得到了答案！

和我们之前的程序一样，你应该再次检查一遍程序，确保你理解每一项操作的作用。回顾本节和之前的章节，查找任何你不理解的内容的解释。然后，拿一张纸，逐步运行程序，跟踪每一步中寄存器的值以及栈上是着什么值。这样做应该能加深你对所发生情况的理解。
