- 错误的邮件别名。这些可能导致退回和循环。务必尝试避免在 `mail-daemon`、`root` 和 `postmaster` 等名称上出现退回，因为这些可能导致严重的循环。

## 打印与传真

许多初级系统管理员发现 `UNIX` 打印配置困难。事实并非如此。`LINUX` 使用 `BSD` 打印系统，其管理难度并没有某些人认为的那么。`BSD` 打印系统可能过时，`System V` 打印系统的可靠性可能较低，即使它受到了最大的商业 `UNIX` 供应商的支持。本章解释了 `LINUX` 打印系统的组件，以及它们之间是如何相互相关的。

用户级打印命令是 `lpr`，它可以由应用程序调用或直接在命令行中调用。`lpr` 查询 `printcap` 文件以确定为指定的打印机使用哪个池化目录，然后通过将任务作为两个文件写入相应的池化目录将其交给本地 `lpd` 守护进程。如果打印机是本地连接的（例如串口或并行口），则 `lpd` 将任务写入 `printcap` 文件中指定的设备，仅在打印机确认接收后才删除池化文件。如果 `printcap` 文件指定打印机连接到网络上的另一台主机或本身就是主机，则 `lpd` 在从池化目录删除任务之前，将打印任务通过网络传递给远程主机或打印机上的 `lpd` 守护进程。

## lpr

每个打印任务都由 `lpr` 处理。通常，`lpr` 由应用程序、脚本或直接在命令行中调用。`lpr` 实际上并不打印任何内容；它而是将打印任务放入队列，将其放在池化目录中供 `lpd` 处理。

`lpr` 的常用参数是 `-P` 选项，用于指定打印机。如果没有定义 `-P`，则使用默认打印机环境变量 `PRINTER`。如果未定义 `PRINTER`，`lpr` 默认使用 `lpd`，而 `lpd` 应该被定义为默认打印机的别名。`-m` 选项指示在任务完成后向用户发送通知。`-s` 选项在打印大文件时很有用。它在池化目录中创建一个同义词，而不是文件的副本。

其他参数可用于指定要打印的数据类型。现在很少使用，因为通用过滤器已经变得足够，可以自动发现数据类型并正确处理每一种。`lpr` 在控制文件中指示这一点。

`lpr` 解析 `printcap` 文件，搜索所需的名称以学习指定打印机的正确池化目录。`lpr` 然后向池化目录写入一个数据文件和一个控制文件。数据文件以 `df` 开头，控制文件以 `cf` 开头，其中 `cff` 是作业号。

`lpr` 最后的操作是打开 socket 通知本地 `lpd` 守护进程任务正在等待。

## 池化目录

通常位于 `/var/spool/lpd/` 的打印池目录可能随特定的 `Linux` 发行版而异。内容的所有权变化更大。最安全的方法是使用发行版包含的应用程序所预期的所有权。如果应用程序期望由 `lpd` 所有，那么由 `root` 的目录可能不再有效。

很少需要手动创建池化目录。通常，使用 `printtool` 应用程序完成。

## lpd

行打印守护进程。`lpd` 通过提供支持多用户环境打印所需的池化和调度功能来仲裁对打印机的访问。它是 `LINUX` 打印系统的核心。`lpd` 守护进程通过 socket 使用 Berkeley `lpd` 协议，该协议已被广泛理解并记录在 `RFC 1179` 中。大多数现代网络打印机都支持 `lpd` 协议。

- 1. 作为 `root` 身份，可以将文件直接 `cat` 到原始设备用于调试。

2. 在 `SysV` 环境中，`lpr` 是与 `lpr` 可比的命令。

`lpd` 通常在启动时由 `rc` 脚本启动。该 `rc` 脚本应验证 `lpd` 是否可加载、杀死任何过期的锁文件并启动守护进程。

`lpd` 运行的第一件事是读取 `printcap` 文件。然后，`lpd` 通过检查打印池目录是否有等待的打印作业来检查队列。一旦启动，`lpd` 会监听来自其他主机上运行的 `lpd` 实例的 `TCP` 连接。在接受远程主机的作业之前，`lpd` 会通过检查 `/etc/hosts.equiv` 或 `/etc/hosts.lpd` 文件中的条目对该主机进行弱身份验证。

## printcap 文件

`printcap` 文件通常位于 `/etc` 目录，它提供了一层抽象。`printcap` 中的每个条目定义了一个虚拟打印机，该打印机可以本地连接，也可以跨网络连接。通过在 `printcap` 文件中为同一物理打印机定义具有不同选项的多个条目，可以创建多个不同属性的虚拟打印机。

本地 `lpd` 守护进程接受任何具有正确 `printcap` 条目的打印机的本地作业。

`printcap` 文件故意遵循了与 `termcap` 类似的格式。为了便于原始软件快速处理，每个条目占一行，字段之间用冒号 (`:`) 分隔。第一个字段是一个一个或多个用于选择打印机的名称列表。为了适应长条目，可以在任何行的末尾放置反斜杠 (`\`) 来延续行。这种形式的换行延续在 `Unix` shell 和许多其他 `Unix` 上下文中（如配置文件）中很常见。（注意：反斜杠后的尾空格通常不起。）随后的行必须以制表符开头，并且通常也以另一个冒号开头，这在 `Unix` shell 中并不常见。

可以省略不需要的字段。对于本地连接的打印机，一个最小化的 `printcap` 条目如下：

```
generic:lpd=/dev/lpd0:sd=/var/spool/lpd0:sh:
```

使用换行延续功能以提高清晰度，该条目为：

```
generic:
:lpd=/dev/lpd0:\
sd=/var/spool/lpd0:\
sh:
```

这些功能等效的条目定义了一个可以通过 `lpd` 或 `generic` 访问的打印队列。到此队列的打印作业将临时作为文件存储在 `/var/spool/lpd0` 目录中，直到 `lpd` 验证 `/dev/lpd0`（典型 `PC` 上的第一个并行端口）已接受所有数据。

如上所述，第一个字段是用于访问虚拟打印机的一个或多个名称列表。所有其他字段采用三种格式之一：字符串、数字或布尔。字符串字段在等号 (`=`) 后取一个选项。数字字段在井号 (`#`) 后取一个选项。布尔函数在等号后可以接受 `true` 或 `false`。布尔选项可以不赋值，在这种情况下被视为 `true`。例如，`:sh:` 和 `:sh-true` 的解释相同。

请注意，如果打印机有足够的内存来接收完整作业，且在接受作业后断电，那么该作业将会丢失。`lpd` 守护进程负责确保打印机收到了作业，而不是确保打印机成功打印。由于打印机是耗能型设备，为它们提供不间断电源通常是不划值的。

`lpd` 作为打印机名称具有特殊含义：如果没有其他指定的默认打印机，则 `lpd` 是默认使用的打印机。

`sh` 抑制页眉——即宣布打印作业所有者的页面——因此抑制每个打印作业可以节省一张纸。如果需要通过页眉来识别作业，请使用 `sb`（短横幅），类似于现代机器顶部的横幅。`sh` 和 `sb` 接受布尔值。

连接到网络上另一台机器或直接连接到网络的打印机的 `printcap` 条目类似。将设备条目 (`lpd-device`) 替换为两个条目，描述服务的机器地址以及远程主机上的打印队列名称。考虑此示例：

```
lpd|generic:
:sd=/var/spool/lpd:rm=192.168.64.22:lp:
```

`rm` 可以是主机名或 `FQDN`，只要该名称可以正确解析即可。优选使用名称，因为网络打印机或其连接的主机 `IP` 地址的更改不应需要更改 `printcap` 文件。

多个 `printcap` 字段可用于向打印机发送控制信号。其中许多常用选项使用换页符 `ff`、在每个打印作业前发射换页 `fo`，并在打印后允许特殊输出（`tr` 设置尾信息，`h1` 将页眉放在最后而不是开头）。还有许多其他细微选项，可能随发行版而异。如果正在编写新的 `printcap` 文件，请参考 `printcap(5)` 手页。

## 过滤器

之前的 `printcap` 示例并未尝试纠正发送到打印机的数据——即以打印机期望的格式呈现数据。例如，文本打印机可能需要步进处理，而 `PostScript` 必须与 `PCL` 进行不同的处理。

解析数据并将其特定打印机能够理解的内容是过滤器的工作。`printcap` 条目允许几种类型的过滤器——某些针对特定类型的输入数据——包括 `of`（输出过滤）和 `if`（个体过滤）。尽管这些过滤器接受选项，但 `lpd` 会收集 `printcap` 文件中的其他条目，只需指定过滤程序或脚本的名称。
