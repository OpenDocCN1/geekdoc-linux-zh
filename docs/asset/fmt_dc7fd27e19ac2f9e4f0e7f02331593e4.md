
单词。单词是出现在空格、语句分隔符或运算符之间的任何连续字符序列。单词可以是单组普通命令、带引号的字符串、变量引用、命令替换、历史替换或文件名模式；它可以是这些元素的任何组合。单词的最终形式是所有替换和转换的结果，加上所有普通命令，组合在一起形成单个字符串。该字符串随后在命令执行期间用作命令名或命令参数。

## 文件名生成（通配符）

星号 `*` 也称为 splat，匹配任何字符。星号 `*` 也称为 star，匹配任何字符串。当星号使用在字符串开头时，它匹配所有文件名。当星号使用在模式末尾时，它匹配任何后缀。当星号使用在模式中间时，它匹配中间的序列。

使用 `{}`（大括号）的文件名提供了灵活性。通配符（Globbing）也称为 wildcarding。问号匹配任何字符。例如，`?` 匹配除一个字符以外的所有。多个问号可以指定特定的位置。

| 表达式 | 定义 |
| :--- | :--- |
| `*` | 匹配任何字符串。由于星号的存在，第一个字符可以跟随任何序列。 |
| `?` | 匹配任何字符。例如，`??` 匹配除两个字符以外的所有。多个问号可以指定特定的位置。 |
| `[]` | 方括号括起字符列表。文件名在相应的位置包含列表中任一字符。例如，`[abc]*` 匹配以 a、b 或 c 开头的任何文件名。 |
| `~` | 波浪号 `~` 表示字符范围。例如，`[1-3]` 匹配 `pay1.cc`、`pay2.cc` 和 `pay3.cc`，但不匹配 `pay4.cc` 或 `pay11.cc`。多个范围可以用单个括号列表。要匹配连字符，将连字符放在字符列表的开头或结尾：`[abc]` 或 `[abc-]` 匹配 a、b 或 c。 |
| `~name` | 替换为用户名家目录的完整路径。例如，如果家目录是 `/usr/ken`，`~ken/bin` 指向 `/usr/ken/bin`。搜索密码文件 `/etc/passwd` name；如果没有找到 name，shell 生成错误消息并退出。`~/` 被替换为你家目录的完整路径。如果波浪号不是作为单词且后面没有字母或斜杠，或者它出现在第一个位置之外，则不会替换为用户的家目录。 |
| `{}` | 大括号括起逗号分隔的模式列表。大括号表达式文件名在文件名相应的位置具有列表中任一模式。例如，`/usr/home/{kookla, fran, ollie}/.chsrc` 扩展为路径列表 `/usr/home/kookla/.chsrc` `/usr/home/fran/.chsrc` `/usr/home/ollie/.chsrc` |

与 `*`、`?` 和 `[]` 不同，大括号列表不会与文件名进行匹配；它们会被展开为单词，并且无论文件名是否存在，都会根据替换进行展开。大括号列表可以嵌套——例如，`/usr/{bin,lib,home/{joh,billi}}` 指向 `/usr/bin`、`/usr/lib`、`/usr/home/john` 和 `/usr/home/bill` 中的任何目录。

重要的是，使用模式生成文件名会导致一个变多个替换。文件名可以是一个单词。单词中字符和模式匹配字符的顺序描述了从当前目录或特定目录选择模式的规则。该单词将被替换为每个匹配模式的文件名或路径。如果你在当前目录下有三个文件（ch1.txt, ch2.txt 和 chlast.txt），那么模式 `*.txt` 就会展开这三个文件：

```
% echo Files: *.txt
Files: ch1.txt ch2.txt chlast.txt
```

你可以通过许多方式使用扩展；下例扩展用于将 shell 变量设置为一个包含三个项目的数组。通过查询该数组的长度和第二个元素。有关 C shell 的更多信息，请参见本章稍后的“数组变量”。

```
% set files=(*.txt)
% echo $#files
Found 3 files
% echo $files[2]
```

> 提示：用于确定目录中文件的强大 C shell 功能是命令/文件名查看功能，它使用 `D` `Ctrl-D`。该功能允许你在不终止命令的情况下，确定用于该命令的可用文件。例如，如果你输入 `cp -sdrew/docs/ind` 并想查看哪些文件匹配规范，`Ctrl-D` 将以多列格式显示匹配的文件列表。文件末尾会附加一个字符以识别文件类型（此行为类似于 `ls -F`）；可执行文件标记为星号 `*`，目录标记为斜杠 `/`，链接标记为符号 `@`。在显示完按列排序的列表后，命令会重新显示，你可以继续输入。列出的文件将是匹配模式 `-sdrew/ind*` 的文件。注意 `Ctrl-D` 会打印系统上所有拥有账户的用户列表。

如果 C shell 正在扩展你当前输入的一部分，可以以这种方式指定命令。shell 会在 `PATH` 环境变量每个目录中查找当前命令。别名不会通过 `Ctrl-D` 扩展。如果我的 `PATH` 设置为 `/bin:~/usr/bin/*~/bin/*` 且我使用 `Ctrl-D` 完成命令，输出大致相同。

除了命令和文件名列表外，转义键 `ESC` 还可用于完成部分输入的命令和文件名。自动补全被称为文件名补全，取决于你是在补全文件名还是命令。模式匹配在 `Ctrl-D` 查看工具中完成。如果模式名称是唯一的，则补全该名称；否则会响蜂声。如果遇到歧义（即有多个文件匹配模式），则会响蜂声。

假设你在目录中有一个文件 `veryLongName.txt` 和 `veryLongName.txt`（注：此处原文重复），你想编辑 `veryLongName.txt` 文件，你可以使用文件名补全来节省大量的输入工作。你可以输入 `vi` `Esc`，它会补全为 `viLong` 并响蜂声。如果你输入 `vi_` `Esc`，名称将补全为 `viLong_Name.txt`，此时你可以按回车键开始会话。

# 重定向输入和输出

C shell 提供了几种用于重定向命令输入和输出的命令。你可能熟悉前面的章节中提到的输入 `<` 或输出 `>` 重定向字符。C shell 为你提供了这些更多功能。

I/O 重定向是你附加到命令的 shell 操作。它导致一个标准文件描述符被分配给特定的文件。你可能在第 9 章讨论 Bourne shell 时遇到过标准文件。UNIX 操作系统定义了三个文件描述符：标准输入 `stdin`、标准输出 `stdout` 和标准错误 `stderr`。

> 注意：UNIX 操作系统实际上为命令提供了至少 25 个文件描述符可以使用。按照惯例，前三个设置为读取输入、写入输出和打印错误消息。除非另有说明，否则 shell 在执行命令之前总是打开这三个文件描述符并将全部分配给你的终端。

文件描述符并不是文件本身；它是一个通道，就像立体音响背面的音频接口一样——你可以将其连接到你使用的任何音频源。同样，作为标准的输入描述符必须连接到文件——默认是终端，或者是你选择的磁盘文件或可读设备。

你可以使用一个或多个 I/O 重定向操作符更改命令读取数据、写入输出和打印错误信息的位置。表 12.3 列出了这些操作符。

包含单词 `HERE` 的行不会出现在输出中；它只是一个让 shell 知道重定向行结束位置标记。

**输出重定向 `Output Redirection`** 重定向的标准形式为 `> filename >> filename`。第一个操作符创建一个指定文件名的新文件。在命令执行开始之前，文件就会被打开，即使命令失败或无法找到，或者 shell 在命令行上发现错误并停止，输出文件仍然会被创建。

注意：为了理解语法，你应该注意，在简单命令后附加 I/O 重定向会得到一个简单命令。除非明确禁止，否则带有附加重定向的命令可以在允许使用简单命令的地方，例如在单行语句中。

如果你使用了 `noclobber` 选项（通过 `set noclobber`），如果指定的输出文件已存在，shell 将拒绝创建它；因为这样做会破坏文件内容。如果你想在文件名已存在的情况下执行输出重定向，请使用重定向符 `>!`；它可以规避 `noclobber` 选项。

`>>` 命令允许将命令输出添加到命名文件的末尾。对于这种重定向，`noclobber` 选项要求命名文件必须已经存在。如果你使用替代方案 `||`，或者使用 `>>` 但未设置 `noclobber` 选项，shell 会在必要创建该文件。

`& >>` 将标准输出和标准错误都重定向到文件名。Bourne shell 允许你分别重定向标准输出和标准错误；而 C shell 不支持。

提示：虽然 C shell 没有提供同时重定向标准错误和标准输出的方法，但你可以通过牺牲子 shell 的代价来实现相同的效果。在 shell 中，先通过 `>` 操作符将非错误消息重定向到目标位置，然后使用 `&` 操作符将子 shell 中的标准错误和标准输出重定向到错误消息的目标位置。由于子 shell 中的输出已被重定向，因此来自子 shell 的标准输出和标准错误重定向将只包含标准错误。

假设你想要运行一个脚本 `buildSystem`，它构建一个大型软件库并生成近 1 MB 的输出，其中可能包含一些错误。以下命令将标准输出放在名为 `build.log` 的文件中，将错误消息重定向到 `buildErr.log`：

```
% (buildSystem -version 5.1 > build.log) & buildErr.log
```

# 特殊字符的引用或转义 `Quoting or Escaping`

正如前面的章节所示，某些字符对 shell 有特殊含义。当 shell 遇到特殊字符时，会执行该字符定义的动作。标准键盘上提供的标点符号对 shell 来说是特殊的，会破坏普通单词的扫描：

在某些上下文中，特别是在 `switch` 语句中，冒号 `:` 也是一个特殊字符。它只在预期的情况下（`case` 或 `default` 语句）以及语句标签处才被识别为特殊字符。它不需要引号来避免这些特定的解释。

要将这些字符之一作为单词的一部分而不产生其特殊含义，可以在字符前面直接放置一个反斜杠 `\` 对其进行转义。注意，意图作为普通字符的反斜杠必须写成两个连续的反斜杠：`\\`。要转义双字符操作符如 `$`，你必须在每个字符前插入一个反斜杠：`\$`。如果 `$` 字符后面跟着空格，则可以对其进行转义：

```
% echo escaped $ sign
escaped $ sign
```

或者，你可以用引号将特殊字符或包含该字符的单词部分括起来。C shell 识别单引号 `'`、双引号 `"` 和反引号 `` ` ``。C shell 不会将这些引号视为传递给命令的输入的一部分。以下命令的输出：

```
% echo "Enter name"
Enter name>
```

并不包含引号。使用两个单引号（也称为单引号、foreticks 或简单的 ticks）来包裹字符序列，并避免被 shell 解释。如果我将字符串包含在硬引用字符串 `hard-quoted string` 中，shell 将不会对引号之间的字符执行任何替换、替换或解释（替换除外）。反斜杠被视为普通字符，因此在单引号包裹的字符串内没有转义（`\\` 和 `\` 除外）。结果是，你无法在这种字符串中嵌入单引号。例如，字符串 `'who's` 会导致 shell 错误；C shell 将该字符串解释为与 `s` 拼接，接着是一个空格分隔符，然后是另一个字符串的开始。当 shell 找不到匹配的单引号时，会产生错误：

`Unmatched '`

使用的字符串之一是包裹包含字符、制表符和换行符的单个单词。使用以下代码，示例展示了如何使用单个 `echo` 打印两行输出：

```
% echo -n 'Hello.
Please enter your name: ' 
Hello.
Please enter your name:
```

双引号 `"` 也为字符字符串提供了特殊的括号。引号会隐藏 shell 观察到的多数特殊字符。引用字符串涉及两类的扫描和替换：变量引用和命令替换。

变量的任何引用形式（`$1`、`$name`、`$(name)`、`$nameindex`、`$*` 等）都会被识别为引用字符串，并带有相应的字符串值。替换发生在引用字符串内部，保持其作为一个单元的整体（即使替换的值包含变量、制表符或换行符）。

命令替换发生在由反引号 `` ` `` 包裹的字符串上。匹配的反引号之间的整个字符串将由当前 shell 执行。（注：原文此处有大量重复，翻译时已清理）。

```
% echo *.cc
main io.cc parse math.cc
% echo "*.cc"
* .cc
```

单引号可以出现在双引号字符串内部。在双引号字符串内部，单引号没有特殊含义，不需要反斜杠转义。下面的示例显示了引用字符串内的引号：

```
% echo '<input type=submit value="Return to Tracking Screen">
<input type=submit value="Return to Tracking Screen">
% echo Your shell: $SHELL
Your shell: /bin/csh
```

在单引号引用字符串内部，反斜杠会被保留并出现在字符串的值中，因为在单引号引用字符串内部不会发生任何替换，如下例所示：

```
% echo 'Single \ quote
Single \ quote
```

在双引号字符串或使用 `...` 的命令替换内部，在普通的引用词中，反斜杠的作用是抑制其后随的字符。随后，反斜杠将从字符串中移除。以下示例显示了反斜杠消除引号字符解释作用的效果：

```
% echo Double \" quote
Double " quote
% echo Single '\ quote
Single ' quote
```

> 提示：对于某些特别复杂的 shell 命令，有必要获取大量的引号和单引号，并仍保持预期的变量和命令替换。例如，简单的 awk 命令包含特殊字符，必须进行硬引号引用：

```
ls -l | awk '{printf("%s\t%s\t%s\n", $9, $5)}'
```

如果你想将此转换为别名 `alias`，这种引号的组合似乎是不可能的，因为只有两种类型的引号且有三层嵌套。以下别名产生错误的结果（注意：第一条命令设置了别名，第二条命令显示别名）：

```
% alias myls='ls -l | awk '{printf("%s\t%s\t%s\n", $9, $5)}''
% myls
ls -l | awk '{printf("%s\tt%s\n", , )}'
```

解决方案是交替使用方法以获得所需的结果。以下命令在双引号和单引号之间交替使用（被双引号包含的部分为**粗体**，被单引号包含的部分为*斜体*）：

```
alias myls="ls -l | awk '''{printf("%s\t%s\t%s\n", $9, $5)}\'"
ls -l | awk '{printf("%s\t%s\n", $9, $5)}'
```

## 目录与目录栈的操作

C shell 为你提供了几个用于处理目录的内置命令。`cd`、`chdir`、`pushd` 和 `pop` 命令都可以更改当前工作目录。

`pushd` 和 `pop` 命令提供了一种用于更改目录的推栈机制，而 `dirs` 命令则显示栈的内容。如果你使用 `pushd` 而不是 `cd` 切换到另一个目录，你上一个目录的路径名将“保存”在目录栈中。随后的 `pop` 将你带回上一个目录。请注意，`cd` 命令不会维护目录栈；你无法使用 `pop` 返回你通过 `cd` 离开的目录。

### 更改目录：`cd` 和 `chdir`

在 C shell 中，你可以选择两个命令来更改工作目录：`cd` 和 `chdir`。`chdir` 命令在各方面都等同于 `cd`。它们的语法如下：

```
cd { pathname }
chdir { pathname }
```

如果你使用 `pathname` 参数，命令将尝试切换到路径由 C shell 家目录变量值指定的目录。详见本章后部分的“使用预定义变量”获取更多信息。

如果你指定一个名称，`cd` 或 `chdir` 命令将使用搜索层次结构尝试定位引用的目录。它遵循以下过程：

1. 如果 `pathname` 的第一个字符是 `/`、`.` 或 `..`，命令将尝试切换到指定的目录；失败则立即终止。也就是说，如果你使用相对或绝对路径名，指定的目录必须存在且可访问；否则命令将失败。

2. 命令搜索你的当前目录。形式为 `name₁/name₂/nameₙ` 的部分路径名意味着在你的当前目录中搜索整个子树。
