
我们实际上通过 `rb_link_node()` 在树中插入节点，这是内核通用红黑树中执行此操作的。

## 4.4.5 VMA 遍历

遍历链表是直接的——`struct vm_area_struct` 字段 `vm_prev` 和 `vm_next` 提供了遍历它们的简单方法，每个 `mm_struct` 指定了其 mm 中虚拟地址最早的 VMA。通过地址查找 VMA 较为复杂——毕竟我们建立了一个整个红黑树结构以便高效实现此目标。其主要方法是通过列表 4-24 所示的 `find_vma()`。

```c
/* 查找 addr < vm_end 的第一个 VMA，如果没有则返回 NULL。 */
struct vm_area_struct *find_vma(struct mm_struct *mm, unsigned long addr)
{
    struct rb_node *rb_node;
    struct vm_area_struct *vma;

    mmap_assert_locked(mm);
    /* 首先检查缓存。 */
    vma = vmacache_find(mm, addr);
    if (likely(vma))
        return vma;

    rb_node = mm->mm_rb_node;
    while (rb_node) {
        struct vm_area_struct *tmp;
        tmp = rb_entry(rb_node, struct vm_area_struct, vm_rb);
        if (tmp->vm_end > addr) {
            vma = tmp;
            if (tmp->vm_start <= addr)
                break;
            rb_node = rb_node->rb_left;
        } else {
            rb_node = rb_node->rb_right;
        }
    }
    if (vma)
        return vmacache_update(addr, vma);
}
```

> 列表 24: mm/map.c: `find_vma()` VMA 维护在一个以其斥边界 `vm_end` 为键的树中，此函数返回满足输入地址小于 `vm_end` 条件的最早（即第一个）VMA，或者如果找不到这样的 VMA，则返回 NULL。这使得如果你搜索的是一个地址范围，则需要额外的检查，即检查你的范围起始处是否大于返回的 VMA 的 `vm_start`。返回一个 VMA 允许了最大的灵活性——如果我们需要，可以通过其 `vm_prev` 字段找到大于指定地址的最近的 VMA。此函数需要一个在 `mm_struct->map_lock` 上持有的锁。第一阶段是检查 VMA 缓存，通过 `vmacache_find()` 查看其是否包含指定地址处的 `struct vm_area_struct` (VMA)。如果是，我们返回此 VMA。如果不存在 VMA 条目，我们遍历红黑树。这简单地从 `mm_struct->mm_rb` 开始遍历树，检查每个节点——如果节点在我们的目标地址之后结束，我们就检查 `vm_end` 实际上可能包含目标地址的节点，因此我们进行额外的检查看 `vm_start` 是否小于或等于它——如果是，我们就可以退出。当我们完成时，我们通过 `vmacache_update()` 更新 VMA 缓存。

### 4.4.5.1 VMA 缓存

VMA 缓存与 `mm_struct->mmap` 保持同步，在链接被解的的 VMA 之前获取了该 VMA 之前之后的 VMA 拷贝，同时也考虑了这可能是地址空间中的第一个 VMA。最后，VMA 缓存通过 `vmacache_invalidate()` 失效，以此递增 `mm_struct->vmacache` 序列号。

```c
struct vmacache {
    unsigned int seqnum;
    struct vm_area_struct *vmas[VMCACHE_SIZE];
};
```

> 列表 25: include/mm_types.h: `struct vmacache` 维护了 VMA 映射的同步，在链接被解的 VMA 之前获取了该 VMA 之前和之后的 VMA 拷贝，同时也考虑了这可能是地址空间中的第一个 VMA，并恰当地处理了 `mm_struct->mmap`。

```c
#define VMCACHE_SIZE 32
#define VMCACHE_SHIFT 21
#define VMCACHE_MASK ((1 << VMCACHE_SHIFT) - 1)
```

> 列表 26: mm/vmacache.c: `VMCACHE_HASH()` 这通过 `VMCACHE_SHIFT` 值进行移位，在 x64 上是 21。这意味着对齐的地址将映射到相同的哈希条目。

```c
#define VMCACHE_HASH(addr) ((addr) >> VMCACHE_SHIFT)
```

> 列表 27: vmacache.c: `vmacache_find()` 我们首先通过 `vmacache_valid()` 确定缓存是否有效，在遍历所有条目之后，仅将哈希值作为起点。如果我们找到一个包含该地址的 VMA（我们无法合理缓存在目标地址之后的），则返回它，否则返回 NULL。

```c
struct vm_area_struct *vmacache_find(struct mm_struct *mm, unsigned long addr)
{
    int idx = VMCACHE_HASH(addr);
    int i;

    count_vmacache_event(VMCACHE_FIND_CALLS);
    if (!vmacache_valid(mm))
        return NULL;

    for (i = 0; i < VMCACHE_SIZE; i++) {
        struct vm_area_struct *vma = current->vmacache->vmas[idx];
        if (vma) {
            #ifdef CONFIG_DEBUG_VMA
            if (WARN_ONCE(vma->mm == mm && vma->vm_end > addr))
                break;
            #endif
            if (vma->vm_start <= addr && vma->vm_end > addr) {
                count_vm_vmacache_event(VMCACHE_FIND_HITS);
                return vma;
            }
            if (++idx == VMCACHE_SIZE)
                idx = 0;
        }
    }
    return NULL;
}
```

> 列表 28: vmacache.c: `vmacache_valid()` 这首先检查 VMA 是否属于当前任务的 `mm_struct` 且它不是内核线程。

```c
static bool vmacache_valid(struct mm_struct *mm)
{
    struct task_struct *curr;
    if (!vmacache_valid_mm(mm))
        return false;
    curr = current;
    if (mm->vmacache_seqnum != curr->vmacache_seqnum) {
        /*
         * 第一次尝试将总是无效的，在此初始化
         * 此任务的新缓存。
         */
        curr->vmacache_seqnum = mm->vmacache_seqnum;
        vmacache_flush(curr);
        return false;
    }
    return true;
}
```

# 页缓存引言

在内核内部，所有文件 I/O 缓冲区和其他相关的“可缓存”对象都存储在内存中的一个键缓存中——页缓存（page cache）。我们将简要介绍该主题的基础知识以及它们如何与进程内存相关，但关于该主题的更多细节，请参阅页缓存章节。

通常，所有的 I/O 都由此缓存介导（例外是使用直接 I/O 或直接访问 DA 的情况，这两个主题都在本书范围之外），内存映射和流式读取操作从此缓存中读取（后者参见 `filemap_read()`）。

页缓存中存在的每个对象都由一个 `struct address_space` 对象描述，由映射底层的 folios 指向，如列表 4-50 所示。

```c

 * @invalidate_lock: 保护页缓存内容与文件一致性。
 * file_offset: 失效期间文件系统中的磁盘块映射。
 * 它也用于阻塞内存映射期间对页缓存内容的修改。
 * memory_mappings
 * @gfp_map: 用于分配页的内存分配标志。

 * @i_mm: 私有和共享映射的树。
 * @i_mmsem: 保护 @i_mm 和 @i_mm_writable。
 * @nrpages: 页条目数量，受 i_pages 锁保护。
 * @writeback_index: 回写在此开始。
 * @a_ops: 方法。
```
