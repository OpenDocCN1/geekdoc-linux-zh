
“文件”（`file`）按钮将弹出一个列出当前目录下所有文件的窗口。要加载新的源代码文件，只需点击其名称即可。“搜索”（`search`）按钮将弹出一个允许你输入搜索模式的窗口。它将显示一个标记为 `<<` 的按钮用于在文件中向后搜索，以及 `>>` 用于在文件中向前搜索。点击“完成”（`done`）按钮关闭窗口。

# 编程工具

有多种可用工具可以帮助你准备和组织源代码。`f2c` 和 `p2c` 可以将 Fortran 和 Pascal 程序翻译成 C 程序。`cproto` 为你所有定义的函数生成函数声明列表，用于头文件。`indent` 工具将以一致的格式缩进用于块的括号，使代码易于阅读。`xwpe` 是一个类似于 Turbo C 的 X-Window 编程环境。

## C语言转换工具：`f2c` 和 `p2c`

`f2c` 和 `p2c` 执行从 Fortran 和 Pascal 到 C 的源代码转换。两者都会生成扩展名为 `.c` 的 C 源文件。保留原始名称。它们还有处理复杂程序转换的选项。以下示例将 Pascal 程序 `mytitle.pas` 转换为名为 `mytitle.c` 的 C 源文件。

```
$ p2c mytitle.pas
```

## `cproto`

对于由多个源代码组成的程序，`cproto` 为你所有定义的函数生成函数声明列表，用于头文件。使用 `cproto`，你可以快速生成包含所有声明的头文件，便于管理和维护代码，这在函数跨多个文件的项目中特别有用。

`indent` 工具将以一致的格式缩进用于块的括号，使代码易于阅读。它可以根据各种样式格式化你的代码，这对任何 C 程序员来说都是非常有用的工具。

`xwpe` 是一个类似于 Turbo C 的 X-Window 编程环境。它为编写、调试和编译 C 程序提供了图形化界面。它包含了编辑器、调试器和编译器，使其成为类 Unix 系统上完整的 C 开发环境。

## 复制程序的运行

`script` 命令允许将交互会话记录到文件中。由于输入和输出都被复制，`script` 可用于记录程序的运行。`script` 接受参数作为要写入会话的文件名。如果没有提供参数，则创建一个名为 `typescript` 的默认文件。该文件将保持打开，直到在命令行输入结束字符 `CTRL-D` 结束 `script` shell。一旦输入 `CTRL-D`，脚本文件关闭，`script` shell 结束。此时脚本文件包含会话的副本。该文件可以像其他文件一样使用 `lp` 打印。`script` 将记录日期时间。

在下一个示例中，用户在 `script` shell 中运行 `bookrec` 程序。所有输入和输出都保存在 `runbook` 中。运行结束后，用户用 `CTRL-D` 结束 `script` shell。然后你可以通过显示或打印脚本文件（在本例中为 `runbook`）来检查程序的运行。

```
$ script runbook
$ bookrec
Please enter a book record : 2.50
The book record is : 2.50
$ ^D
Script done, file is runbook
```

务必在检查脚本文件之前结束 `script` shell。如果你不这样做，使用 `cat` 命令显示脚本文件，字符不仅会输出到屏幕上，还会被记录为脚本文件的更多添加输入。此外，在 `script` shell 激活期间你将无法注销。如果你一直在使用 `script` 命令并发现无法注销，说明 `script` shell 仍处于活动状态，必须用 `CTRL-D` 结束。

也可以嵌套 `script` shell。在结束第一个 `script` shell 之前执行第二个 `script` 命令，会将第二个 `script` shell 中的所有输入和输出记录到第一个 `script` shell 中。当第一个 `script` shell 最后结束时，其文件将包含第一个 `script` shell 的所有内容以及第二个 `script` shell 的所有内容。

# 打包你的软件：`autoconf` 和 `rpm`

一旦你完成了软件开发，你可能想将其分发给其他人。通常情况下，你会将程序打包成 `tar` 归档文件。人们随后下载该文件并进行解压。你必须包含详细的说明，告知如何安装以及将任何支持文档和库放在什么位置。如果你分发源代码，用户必须设法如何将源码适配到他们的系统。存在许多可能导致程序编译停止的变量。

红帽软件包管理器 (`rpm`) 和 `autoconf` 旨在自动化这些任务。`autoconf` 用于自动将源代码配置到给定的系统。`rpm` 将自动在指定的目录中向系统上安装软件，连同任何文档、库或支持程序。两者都具有复杂且强大的功能，能够处理最复杂的程序。这里提供了它们用法的简单示例。

## `autoconf`

Unix 系统可以编译任何用 C 语言编写的软件。然而，不同的 Unix 系统具有不同的配置，有些系统使用不同的编译器，或者将程序和库放在不同的系统目录中。可能存在不同类型的支持库。在过去，为了在不同系统上编译软件，必须为每个系统手动配置软件。例如，如果你的系统拥有 `gcc` 编译器而不是 `cc` 编译器，你必须在软件的 `makefile` 中设置该功能。

`autoconf` 程序旨在自动化配置过程。它会自动检测当前 Unix 系统的配置，并生成一个适当的 `makefile`，然后可以用于在该特定系统上编译软件。互联网上大部分源码形式的软件都使用了 `autoconf`。你可以在 `/usr/info` 目录下找到 `autoconf` 的详细手册，名为 `autoconf.info`。你可以使用 `info` 命令查看它（你也可以用任何文本编辑器查看文本）。这里描述了通用的操作。

使用 `autoconf` 的软件执行配置时不需要实际的 `autoconf` 软件。软件包含的特殊 shell 脚本将检测软件所需的不同系统特性。`./configure` 命令通常会自动为你的系统配置软件。在执行配置时，它会逐个检查不同的特性，显示每次检查的结果。该操作完全自动的，甚至不需要知道正在运行的系统标识。

要为你自己的软件创建一个配置脚本，你需要使用特殊的 `autoconf` 命令。`autoconf` 应用程序软件包可以在你的 OpenLinux 光盘镜像中找到。生成配置涉及几个阶段，使用多个中间配置文件。`autoconf` 有许多设计用于处理复杂程序要求的选项。对于一个简单的程序，你只需要遵循基本步骤。

目标是创建一个 `configure` 脚本。这个过程中有两个阶段，分别使用 `autoscan` 和 `autoconf` 命令。第一阶段使用 `autoscan` 源码文件创建一个 `autoscan` `configure.scan` 文件。`autoscan` 命令直接应用于你的命令。检查 `configure.scan` 文件是否有任何错误，并进行你想要的任何更改或添加，然后将其重命名为 `configure.in` 文件。该文件将作为 `autoconf` 命令的输入，随后生成 `configure` 脚本。

`autoscan` 步骤是创建 `configure.in` 文件的辅助，但 `autoscan` 和它生成的 `configure.scan` 文件是可选的。你可以创建自己的 `configure.in` 文件，输入各种 `autoconf` 宏。这些在 `autoconf.info` 文件中有详细描述，这里描述了这些步骤：

- 源码文件 $\rightarrow$ [`autoscan`] $\rightarrow$ [`configure.scan`]

- [`configure.scan`] $\rightarrow$ `configure.in`

- `configure.in` $\rightarrow$ `configure`

此外，你还需要为你的程序创建一个名为 `makefile.in` 的 `makefile` 版本。这本质上是你原始的 `makefile`，其中引用了特殊的 `autoconf` 变量。当软件在另一个系统上编译时，`configure.in` 将检测系统特性，然后使用这些信息结合 `makefile.in` 文件为该特定系统生成一个 `makefile`。使用这个新的 `makefile` 来编译程序。

`autoconf` 设计用于为不同的创建值，这些值可以用于 `makefile.in` 以创建一个包含这些特性的新 `makefile`。特性值被放在称为输出变量的特殊 shell 变量中。在你想使用这些值的地方，你应该在 `makefile.in` 中放置这些 shell 变量的引用。例如，`CC` 变量将持有系统中 C 编译器的名称（`cc` 或 `gcc`）。`configure` 脚本中的 `AC_PROG_CC` 宏将检测使用的 C 编译器并将名称放入 `CC` 变量。在调用 C 编译器的 `makefile.in` 文件中应放置该变量的引用。变量名由两个 `@` 符号包围。例如，`makefile.in` 中的 `@CC` 将引用 `CC` 变量，并在该处替换。
