## 公共使用的 Shell 脚本

为公共开发的 shell 脚本应该设计具有持久的可移植性。现在的趋势是使用 Korn shell 语言编写脚本，这些人意识到自己正在冒险，尽管风险很小。

某些版本的 UNIX 允许你通过在脚本文件的第一行嵌入特殊命令来指定使用的 shell 解释器：例如在脚本的第一行使用 `# /bin/sh`，或者在现代 UNIX 系统上，强制使用 Bourne shell 执行脚本。这是一个使用你喜欢的 shell 语言开发脚本的方便设备，同时也允许用户无论选择何种交互式 shell 都能使用该脚本。然而，`#!` 在所有的 UNIX 版本上并不可用。

除 Bourne 或 POSIX 以外的 shell 脚本需要操作系统执行相应的脚本。例如，C shell 或 Korn shell 要求安装了 c 或 ksh。所有系统都满足这一要求，并且当前和未来的多个平台之间具有移植性。

在所有 UNIX 系统的实现中均可用，且 POSIX shell 变得几乎无处不在。

对于日常键盘操作，除了 Bourne shell 之外的任何 shell 都是不错的选择。当有其他 shell 时，Bourne shell 不是一个好的选择。Bourne shell 明显缺乏交互功能，命令历史和命令编辑会极大地降低效率。

然而，为编写脚本选择 shell 则是另一回事。

较新的 shell 为脚本编写者提供了必不可少的工具，如果没有这些工具将很难实现，例如命令替换的简化语法、数组变量、算术表达式，以及结构化更好的命令（如 `select`）。因为这些工具非常有帮助，它们应该适用于任何仅供个人使用的工作。在环境可以被准确预测的特定项目中，也应该优先使用它们。然而，对于那些受众群体更广泛的 shell 脚本，Bourne shell 在未来一段时间内仍将作为 UNIX 世界的通用语言。

脚本编写者无法预测硬件和软件环境，必须考虑脚本中使用的命令和命令选项，以及 shell 语言。很少有环境提供的命令和命令选项比大多数环境还要丰富，而且某些 UNIX 版本省略了一些 UNIX 运行时功能。对于大多数用途，与 UNIX V Release 1 兼容的实现可以被视为最小的可移植基础。在可移植性特别重要的情况下，应该将 POSIX 和 X/Open 标准视为可用的操作系统功能和能力，而不是厂商的手手册。

shell 编程可以根据你的需要变得简单，也可以变得复杂。shell 是足够先进的编程工具，可以允许高效的、生产级软件的实现。事实上，shell 脚本可以代替更传统的第三代语言，如 C 或 C++ 编程语言。事实上，我曾用一个 4 行的脚本替换了一个 500 行的 C++ 程序。shell 脚本的使用也因一种原型设计和快速开发方法而流行起来。

似乎虽然在键盘上选择了一个 shell 用于自定义，但为编写 shell 脚本选择 shell 环境需要对每个项目进行重新考虑。

## 什么是系统管理？

作者：Eric Goebel

系统管理是对计算机系统的规划、安装和维护。如果这看起来像是一个非常笼统的答案，那是因为“什么是系统管理”是一个宽泛的问题。

在本章中，我们将描述对系统管理员的期望，以及她可能如何处理她的职责。

> 诚聘信息

> 管理员负责 Sun 和 IBM Unix 系统的访问控制。协助某些数据库管理（Oracle）。管理员负责 Sun 服务器和网络：系统配置、用户 ID 创建/维护/维护、安全管理、系统备份，并确保所有应用程序在系统上正常运行。管理员负责互联网访问和业务：内部/外部安全、用户身份创建和维护，以及 Web 服务器维护。

这是一份 UNIX 系统管理岗的“诚聘”广告。从这个描述中你可以猜到，系统管理员必须安装和配置操作系统、添加新用户、备份系统、保持系统安全并确保它们持续运行。设置互联网访问并保持其运行也是工作的一部分。

遗憾的是，你只考虑了工作的一半。成为一个精通安装、运行和维护所有主要 UNIX 变体的专家，还不足以成为一个真正优秀的系统管理员。成为一名优秀的系统管理员有很大一部分非技术成分，特别是在规划、组织和人际技巧方面。

随着计算机在业务中变得越来越无处不在，系统管理在越来越多的组织中成为一项关键任务。管理员必须理解他负责的系统、使用这些系统的人以及他们所服务的业务性质。一项关键技能是规划，因为系统创建、翻新和扩展的速度非常快，试图即兴发挥和设计一个网络是行不通的。

公司正越来越多地不仅转向计算机，还转向销售点系统、网络电子商务以及复杂的店内系统（例如直接连接到库存和信誉系统的电子目录和收银机）。五年前可能已经将库存控制转移到计算机的公司，现在正忙于将订单输入计算机化并网络化，而尚未自动化库存和订单系统的公司则正忙于此以保持竞争力。电子邮件现在被认为与传真和电话一样重要，客户服务的每一个部分都可以由计算机和传真检索系统进行管理。这些公司几乎完全依赖它们的计算机，系统管理员需要理解的内容比分区硬盘、增加内存和安装 Adobe PhotoShop 要多得多。

本章介绍了系统管理员为了良好完成工作需要知道的一些基础技术和组织概念。它还涵盖了在大多数 UNIX 变体中已有的或包含在随书的 Unleashed CD 中的系统管理工具。

本章分为以下几个章节：

- 系统管理员技术概念——在本节中，我们介绍了 UNIX 的重要特性以及它们与 Windows 和 Macintosh 等操作系统的区别。

- UNIX 是异构的——本节描述了 UNIX 多样化且自矛盾的用户界面，以及这些界面是如何变成那样的。

- 系统管理任务——本章的部分内容介绍了基本的管理任务和职责。

- 管理资源——操作系统本身和互联网都为管理员提供了丰富的信息。本节提供了关于这些资源的一些提示。

- 行业工具——UNIX 为用户提供了一套惊人的工具。我们在本章末尾简要介绍了其中几个。

> 提示：无论某人在“行业内”混迹了多久，没有人能记住 UNIX 工具箱所有的配置选项、命令行开关、奇特之处以及显性的漏洞。经验丰富的用户学会了 UNIX 在线文档——即手册页（man pages）的价值。在使用任何工具之前，请阅读它的 man 页面；许多页面包含了实用的示例。如果你从 CD 安装了实用程序，请务必阅读随附的安装说明并也安装 man 页面。在本章稍后的部分，我们将涵盖 man 页系统中的一些高级功能。

## 系统管理员技术概念

UNIX 在基础层上与 Windows 和 Macintosh 不同。最初旨在供多个用户同时运行程序。（至少在从贝尔实验室之外分发时。）拥有低成本个人工作站并运行 Linux 或任何其他 UNIX 变体的现象，实际上是操作系统历史上的近期发展。事实是，UNIX 设计用于供一个以上用户使用，这体现在操作系统的文件系统、安全和编程模型中。

网络并不是 UNIX 的事后考虑或最近的开发，这在 Windows 和 Macintosh 上似乎是如此。对共享文件、在工作站之间移动以及在远程计算机上运行并在本地工作站上控制和查看应用程序的支持，在 UNIX 上并不直观自然，但在过去的 UNIX 版本以及最新的 Windows 和 Windows NT 中更加强大稳定。

## 多用户和多账户

DOS/Windows 和 Macintosh 环境在安全和定制方面是“以计算机为中心”的。 这

文件和进程（当前运行的程序）的所有权在很大程度上取决于它们所在的计算机，而不是取决于用户或 ID 的概念。如果一个人在物理上可以接触一台计算机，他就可以访问该计算机上的所有文件和进程。如果恶意人员想要访问 PC 内容，即使是受密码保护的屏幕保护程序通过重启系统来破解，文件和进程属于该 PC，而计算机将准备好供使用。（甚至 Windows 95 上的登录提示也可以通过“取消”按钮绕过，进入一个未连接网络的用户界面。）

针对 DOS 和 Macintosh 系统的扩展程序允许用户在受保护区域内识别和保存文件。但这些是应用程序，而不是操作系统的一部分，并且带有自己的一系列问题、局限性和规则。事实是，正如每一个曾与家庭成员或同事共享过计算机的人所同意的，个人电脑操作系统是单用户的，并且是针对单个用户和一组配置选项设计的。

UNIX 系统是多用户系统。用户必须登录系统。每个用户都有自己的保存文件区域（即主目录），并具有决定谁可以访问它们的属性（即权限模式）。所有运行的程序都与一个用户关联，类似于文件的访问控制，程序只能由某些用户启动或停止。登录为超级用户的用户无法访问另一个用户的文件，除非所有者通过直接或间接手段授予其许可。只有超级用户可以重启计算机（不通过电源开关）或停止另一个用户的进程。即使系统重启了，所有安全功能实际上仍然有效，因此重启不是绕过安全性的有效手段。

## 网络连接

网络化已成为 UNIX 不可缺的一部分。跨网络共享文件、网络登录、共享网络配置以及跨网络运行应用程序的能力已包含在所有主要的 UNIX 发行版中。更重要的是，它是操作系统的自然扩展，而不是由单个用户根据其对网络和管理的想法而设计的、需要单独购买的应用程序。

在配置允许的情况下，在 UNIX 系统控制台（主键盘和显示器）上执行的任何操作都可以通过网络连接在另一个系统上完成。（我们将这些其他系统称为远程节点或远程系统。）实际上，许多服务器系统（如 Web 服务器和文件服务器）具有功能有限的控制台（例如纯文本终端），并且在设计时就考虑到从中心之外的远程节点进行管理。

提供这些能力的两种机制是远程终端（或伪终端）和远程 shell。远程终端模拟终端会话，就像用户登录到通过串口线连接到系统的终端一样，其中网络是这条线，而应用程序（telnet）就是终端（远程终端被称为终端，因为 telnet 是最常用的应用程序）。这类似于拨入系统并使用像 Procomm 这样的应用程序。

远程 shell（或远程登录）是远程计算机上的会话，其核心是执行 shell（或 shell 命令），而不是远程系统上的终端。远程 shell 在远程主机上执行执行命令，而远程登录则运行一个 shell；通常该 shell 运行在本地系统上。管理员经常在 shell 脚本中使用远程 shell，在多个系统上执行命令并将结果整合到一个处，例如收集磁盘利用率统计数据或备份。

远程 shell 和本地会话之间的区别非常重要。Telnet 会话使用终端仿真并作为独立的应用程序运行。因此，除非使用剪切和粘贴等机制，否则结果无法与其他应用程序共享；而远程 shell 允许命令执行的结果与本地命令交替进行。

因此，一个工作站上的目录可以通过简单的 shell 命令备份到另一个工作站的驱动器：

```
tar cvfb - tgt_dir | rsh -n bilbo dd of=/dev/rmt0/
```

`tar` 命令创建 `tgt/` 的归包并将其发送到标准输出。该数据流被重定向到 `rsh` 命令，`rsh` 连接到主机 `bilbo`，执行 `dd`，并将 `tar` 的输出传递给它。`dd` 命令恰好知道如何将归包保存到 `/dev/rmt0` 带驱动。（这看起来可能复杂。在本章结束时，你将完全理解。）因此，不同计算机上的两个程序被连接在一起，无需任何特殊的配置要求或额外的软件。

既然远程登录就是 shell，为什么还要使用 telnet 呢？原因之一是 telnet 在慢链路（如 Internet 和不同站点之间的 WAN 连接）上比远程登录要健壮得多。我们将介绍远程 shell 带来的某些风险。

X-windows 是 UNIX 网络化的另一个例子。X 环境是一个图形化用户界面，类似于 Windows 或 Macintosh 环境。一个关键区别是它被分为客户端（应用程序）和服务器（服务器端）。服务器是一个管理键盘、鼠标和屏幕的进程，并通过 socket（网络连接）接受来自应用程序的连接。由于网络连接是两个程序之间的通信方法，应用程序可以运行在控制它的显示器不同的机器上。网络连接经常被更快的方法所绕过。这些增强功能是专有的扩展，并且不同供应商之间存在很大。

X-windows 的远程功能是一个非常强大的优势，特别是当考虑到需要安装在数据中心或设备房中的大型数据库、Web 或文件服务器时，这些服务器需要图形化管理和配置应用程序。另一种是在桌面上安装较慢、更便宜的工作站，同时可以在共享的、更强大的计算机上运行高要求的应用程序。

文件共享是另一个已成为 UNIX 连接自然且不可的一部分的一部分。所有的 UNIX 变体都支持 NFS（网络文件系统），并在它们与其他 UNIX 变体之间无缝共享文件。

由于 NFS 系统被处理为任何其他类型的磁盘（就像实现 SCSI、IDE 和软磁盘的方式一样），网络驱动器完全支持用户账户、文件权限以及 UNIX 用于添加、删除和管理其他类型文件系统的所有机制，即使对于不同的 UNIX 变体也是如此。

这意味着无论两个 UNIX 系统在什么种类型的计算机上，都可以共享文件（可能来自运行在第三种类型上的公共文件服务器）。用户 ID 必须协调以确保文件安全。不需要额外的软件或特殊的修改。

任何 UNIX 系统都可以导出或共享文件系统。这是模糊 UNIX 系统中服务器和客户端区别的途径之一；任何系统都可以提供或消费文件资源。当共享文件系统时，工作站可以指定哪些不能使用它，以及用户是否可以对其进行写入。

客户端指定文件挂载到其目录树中的位置。例如，一个系统可以将另一个系统的 `/export/applications` 目录挂载到 `/mnt/apps` 目录。

经常用于挂载 NFS 的系统是自动挂载（automounter）。该程序（或一组程序）允许管理员根据客户端引用它们的时间，按需要挂载（连接）和卸载（分离）文件系统。这一过程完全在后台进行，在自动挂载程序配置正确后，不需要任何的人为干预。

## LINUX

Linux 系统使用公开的应用程序 `amd` 代替 `automount`。虽然配置文件略有不同，但 `amd` 为 Linux 提供的功能是相同的。所有主要的 Linux 发行版都提供了 `amd`。一如既往，请参阅手册页以获取详细信息。

`automount` 通过映射（maps，对配置文件的专业术语）进行配置，每个映射指定一个顶层目录。因此，如果使用 `automount` 创建目录，包含在 `/etc/auto_master` 文件中的主映射可能如下所示：

```
/share auto_share
/home auto_home
/gnu auto_gnu
/apps auto_apps
/opt auto_opt
```

这为 `automount` 提供了它将创建的目录名称以及包含目录内容的文件。

例如，考虑一个机构决定将所有用户放在 `/home` 目录下。（因此，用户将在 `/home/dan` 找到他的文件）。前三个 home 目录位于文件服务器 `gandalf` 的 `/export/home` 目录下。

当下一个用户到来时，管理员发现 `gandalf` 没有足够的磁盘空间给新用户，因此，将几个用户移动到另一个文件服务器 `balrog`（目前为止一直用于应用程序）是一个好主意。

`automount` 简化了这种分布，允许在每个运行 `automount` 守护进程的工作站上创建一个虚拟的 `/home` 目录。`/etc/auto_master` 中指定的 home 目录映射 `/etc/auto_home` 如下：

```
eric gandalf:/export/home/eric
dan gandalf:/export/home/dan
mike balrog:/export/home/michael
```

在此映射中，eric、dan 和 mike 被称为目录键（directory key）。目录被称为值（values）。当程序首次为 `/home` 挂载文件系统时，系统识别出键 `eric`，并将 `/export/home/eric` 挂载到 `/home`。由于 `automount` 执行的是简单的键/值替换，Eric 和 Dan 的目录创建在 `gandalf` 上，而 Mike 的目录创建在 `balrog` 上。注意，`balrog` 中的目录和 `automunter` 虚拟目录并不一致。在活动一段时间后，`automount` 会卸载该目录。

`automount` 减轻了挂载用户或用户组需要的所有目录的繁琐任务。永久挂载所有文件系统会导致不必要的开销，并需要过度的人工干预。该系统还让用户在工作站之间移动变得更加容易，他们总可以在相同的地方找到重要的应用程序和数据文件。

## AIX

Hewlett Packard 的 HP-UX 和 IBM 的 AIX 都提供一个版本的 `automount`。由于 `automount` 使用 NFS，它可以兼容不同的 UNIX 变体。

较新版本的 `automount`（以及 `amd`）还允许为一个目录指定多个文件服务器，以便在一个文件服务器不可用或过载时提供备份。该系统经过一点规划和思考，可以简化分布式网络并使其更加可靠。

然而，映射仍然必须保持更新并分发到每个工作站。可以使用 ftp 甚至 nfs 完成，但在大型网络中这可能会变得繁琐。有两个优雅的解决方案，展示了经验丰富的系统管理员倾向于如何解决这些问题。

第一个是名为 `rdist` 的工具。它是用于在远程主机之间维护软件相同副本的工具。它可以接受命令行中的文件名，或使用配置文件（通常称为 `distfile`），该文件列出了要复制的文件。

为了分发一组 `automount` 映射，我们可以使用如下简单示例的 `distfile`：
