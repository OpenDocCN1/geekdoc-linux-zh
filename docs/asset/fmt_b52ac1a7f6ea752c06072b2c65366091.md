## 函数列出

```
list fcns # 列出可用函数
```

目前，只有 `debug` 函数可用。当执行此函数时，它会将发送给探针的参数以及详细字段中与 `sunw&debug` 属性关联的值（如果有）打印到标准错误。例如，对于该探针点：

```
TNF_PROBE_2(input_values, "testapp main",
sunw&debug "have read input values successfully",
tnf_long, int_input: x,
tnf_string, string_input, input);
```

如果 `x` 为 100 且 `input` 为字符串 `"success"`，那么探针函数的输出将为：

```
probe input_values; sunw&debug "have read input values successfully",
int_input=100; string_input="success";
```

## 连接与断开探针函数的命令

```
connect &fcn_handle $set_name
connect &fcn_handle selector_list
clear $set_name
clear selector_list
```

使用 `connect` 命令将探针函数（必须以 `&` 前缀）连接到探针。探针可以通过集（使用 `$`）或显式列出探针选择器来指定。探针函数必须是 `list` 命令列出的函数。此命令不会启用探针。

## 切换跟踪模式的命令

```
trace $set_name
trace selector_list
unntrace $set_name
unntrace selector_list
```

使用 `trace` 和 `untrace` 命令来切换探针点的跟踪操作（即如果探针被命中，是否发射跟踪信息）。此命令不会启用指定的探针。探针默认开启跟踪。关闭跟踪的最有效方法是使用 `disable` 命令。如果你需要调试输出但不需要跟踪，`untrace` 是非常有用的。如果是，将探针的状态设置为启用、未跟踪，并将调试函数设置为已连接。

## 启用和禁用探针的命令

```
enable $set_name
enable selector_list
disable $set_name
disable selector_list
list history # 列出探针命令
```

使用 `enable` 和 `disable` 命令控制探针是否执行其设置的操作。要跟踪探针，探针必须被启用并跟踪（使用 `trace` 命令）。探针默认是禁用的。使用 `list history` 命令列出发出的探针命令：`connect`, `clear`, `trace`, `untrace`, `enable` 和 `disable`。每当新的共享对象通过 `dlopen(3X)` 引入目标程序时，这些命令就会执行。有关更多信息，请参见第 1055 页的“动态加载的库”（`dlopen-ed Libraries`）。

# 列表历史

`list history` 命令显示跟踪会话中之前发布的探针控制命令列表，例如 `connect`（连接）、`clear`（清除）、`trace`（跟踪）、`disable`（禁用）。当通过 `dlopen(3)` 向目标程序引入新的共享对象时，历史列表中的命令会被重新执行。

```
list spec_list probes $set_name          # 例如：list probes all
list spec_list probes selector_list      # 例如：list name probes
                                            # file=test.c

```

前两个命令列出指定探针的属性和值。你可以使用它们检查探针的状态。第三条命令列出与所选属性相关的各种值。

# 进程控制

```
continue                  # 恢复目标进程
quit kill                 # 退出 prex并杀死目标
quit resume               # 退出 prex并继续目标
quit suspend              # 退出 prex并让目标保持挂起状态
quit                      # 退出 prex，继续或杀死目标
```

如果 `prex` 挂载到目标进程，默认的 `quit` 会继续目标进程。相反，如果是由 `prex` 启动的目标程序，`quit` 会杀死目标。

# dlopened 库

通过 `dlopen(3)` 引入的对象中的探针会根据 `prex` 的命令历史自动设置。当通过 `dlclose(3)` 移除共享对象时，`prex` 需要刷新其对该目标程序探针的理解。这一要求意味着 `dlopen(3)` 和 `dlclose(3)` 需要执行更多工作，因此它们耗时略长。如果你对此功能不感兴趣且不想干扰 `dlopen(3)` 和 `dlclose(3)`，请从目标中分离 `prex` 以禁用此功能。

# 发向目标程序的信号

`prex` 不干预直接传递给目标程序的信号。然而，`prex` 会接收从终端正常产生的所有信号，例如 `Control-C` (`SIGINT`) 和 `Control-Z` (`SIGSTOP`)，并且不会将它们转发给目标程序。要向目标程序发送信号，请从 shell 使用 `kill(1)` 命令。

# 与其他应用程序的交互

像 `dbx`、`truss(1)` 和 `prex` 等进程管理应用程序无法同时操作于同一个目标程序。`prex` 无法挂载到被另一个应用程序控制的目标。你可以通过以下方法串行跟踪和调试程序：首先，将 `prex` 挂载到目标（或通过 `prex` 启动目标），使用命令语言设置探针，然后输入 `quit suspend`。随后你可以将 `dbx` 挂载到挂起的进程，然后通过发送 `SIGSTOP` 信号对其进行调试，最后输入 `quit resume`。在这种情况下，在对停止的进程上调用 `dbx` 后，你应该也发送 `SIGCONT` 信号，否则 `dbx` 会挂起。

# 事件写入操作失败

在向跟踪文件写入事件时，可能会出现一些失败点，例如系统调用失败。这些失败会导致目标进程中设置一个失败代码。目标进程继续正常运行，但不会写入记录。每当你输入 `Control-C` 给 `prex` 以获取提示符时，`prex` 会检查目标中的失败代码，并在发生跟踪失败时通知你。

# 目标执行 fork 或 exec

如果目标程序执行了 `fork(2)`，任何子进程遇到的探针事件都会写入同一个跟踪文件。事件被标记了进程 ID（`PID`），因此可以确定某个特定事件是由哪个进程产生的。在多线程程序中，当其他线程仍在运行时执行 `fork(2)` 会导致竞态条件。为了确保跟踪文件不被损坏，请使用 `fork(1)` 或确保在执行 `fork(2)` ，所有其他线程都处于静止状态。

如果目标程序本身（而非其任何子进程）执行了 `exec(2)`，`prex` 将从目标中分离并退出。你可以使用 `pre-p pid` 重新连接 `prex`。

`fork(2)` 之后通常会紧接着在子进程中执行 `exec(2)`，在此期间子进程借用父进程的进程，而父进程则等待 `exec(2)`。子进程从父进程记录的所有事件似乎都是由父进程记录的。

# 内核模式

使用 `-k` 标志调用 `prex` 会在内核模式下运行 `prex`。在内核模式下，`prex` 控制 Solaris 内核中的探针。请参阅 `tnf_kernel_probes(4)` 获取 Solaris 内核中可用探针的列表。少数 `prex` 命令在内核模式下不可用；许多其他命令仅在内核模式下有效。

`-l`、`-o` 和 `-p` 选项在内核模式下无效（即你不能将其与 `-k` 选项组合）。

本节其余部分描述了 `prex` 在内核模式下运行时 `prex` 命令语言的差异。

# pre 不停止内核

当 `prex` 挂载到正在运行的用户程序时，它会停止该用户程序。显然，它在挂载到内核时无法这样做。相反，`prex` 提供了一个跟踪开关；当跟踪开关开启时，任何探都不会产生影响。此开关允许你迭代选择要启用的探针，然后通过开启主开关一次性启用它们。

使用以下命令检查并设置主开关的值。

```
pfilter [on | off]
```

不带参数时，`pfilter` 打印当前进程过滤器设置和主开关的状态。不带参数时，`pfilter` 输出当前进程过滤器设置。`on` 或 `off` 设置主开关的状态。

```
pidlist
```

从过滤器设置集中添加或删除进程。`pidlist` 是多个进程 ID 逗号分隔的列表。
