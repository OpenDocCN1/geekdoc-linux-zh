
| o | 其他人的权限 |

这种权限方案被执行得非常严格，即使在没有网络安全的情况下也能提供高水平的安全性。除了其他功能外，安全方案还负责用户对程序的访问，这可以根据“按需知”的原则保存文件，并保护家目录和配置文件等敏感数据。

你应该知道自己的用户名是什么。如果你不知道，可以通过 `id` 命令显示，它会显示你所属的默认组以及你最终所属的其他组：

```
tilly-> id
uid=504 (tilly) gid=504 (tilly) groups=504 (tilly),100 (users),2051 (org)
```

你的用户名也存储在环境变量 `USER` 中：

```
tilly-> echo $USER
tilly
```

## 工具

### chmod 命令

应用严格的文件权限的正常结果（且有时也是一种困扰）是由于各种原因需要更改访问权限。我们使用 `chmod` 命令来这样做，最终 `chmod` 已经变成了一个可以接受的英语动词，意为更改文件的访问模式。`chmod` 命令可以使用字母数字或数字选项，随你喜喜欢哪种。

下面的示例使用了字母数字选项来解决一个新用户经常遇到的问题：

```
asim-> ./hello
bash: ./hello bad interpreter: Permission denied

asim-> cat hello
#!/bin/bash
echo "Hello, World"

asim-> ls -l hello
-rw-rw-r--   1 asim asim   32 Jan 15 16:29 1629

asim-> chmod u+x hello
```

```
asim-> ./hello
Hello, World
```

```
asim-> ls -l hello
-rw-rw-r--   1 asim asim   32 Jan 15 16:29 1629*
```

`+` 和 `-` 运算符用于授予或拒绝特定组的访问。允许用逗号分隔组合。Info 页面和 man 页面包含了有示例。这里是另一个示例，它将之前的文件变为用户的私有文件：

```
asim-> chmod u+rwx,go-rw
asim-> ls -l hello
-rwx------   1 asim asim   32 Jan 15 16:29 1629*
```

导致某处出现“权限拒绝”错误信息的问题通常是访问权限问题。此外，像“昨天还好好的”和“我运行它时没问题”这样的评论，最可能是由权限错误引起的。

当使用数字参数运行 `chmod` 时，每个被授予的访问权限的值必须分组相加。我们使用三位数字，这是 `chmod` 设置设置的符号值。下表列出了最常用的命令：

### 表 3.9. 使用 chmod 保护文件

| 命令 | 含义 |
| --- | --- |
| `chmod 400 file` | 防止文件被意外覆盖。 |
| `chmod 500 directory` | 防止从此目录中意外删除或重命名文件。 |
| `chmod 600 file` | 仅由输入此命令的用户可以修改的私有文件。 |
| `chmod 644 file` | 公开读取的文件，但只能由发布的用户更改。 |

## 关于文件和文件系统

| 命令 | 含义 |
| --- | --- |
| `chmod 660 file` | 属于你组的用户可以更改此文件，其他人完全没有访问权限。 |
| `chmod 700 file` | 防止其他用户访问该文件，而发布用户拥有完全访问权限。 |

## 文件与目录

默认情况下目录拥有更多权限：它具有执行权限。如果没有该权限，它将无法被访问。尝试对目录执行 `chmod 644` 来测试一下吧！

如果你使用 `newgrp` 命令登录另一个用户组，掩码（mask）将保持不变。因此，如果掩码被设置为 `002`，那么你在新组期间创建的文件和目录将允许该组的其他成员访问；你不需要使用 `chmod`。

root 用户具有更严格的文件权限：

```
[root@estoban root]# umask
022
```

这些默认值设置在 shell 资源配置文件中，例如 `/etc/bashrc` 或 `/etc/profile`。你可以在自己的 shell 配置文件中更改它们，请参阅第 7 章“Home sweet/home”部分以了解如何自定义你的 shell 环境。

## 修改用户和组所有权

当文件的所有者错误的用户或组时，可以使用 `chown`（更改所有者）和 `chgrp`（更改组）命令来修复错误。在需要在组内共享文件的环境中，文件所有权是一项常见的管理任务。这两个命令都非常灵活，你可以通过使用 `--help` 选项来了解。

`chown` 命令可以同时更改文件的用户和组所有权，而 `chgrp` 仅更改组所有权。当然，系统会检查执行这些命令之一的用户是否对其想要操作的文件具有足够的权限。

要更改文件的用户所有权，请使用以下语法：

```
chown newuser file
```

如果你在名称后使用冒号（参见 Info 页面），组所有权也将被更改，更改为执行命令的用户所在的组。在 Linux 系统上，每个用户都有自己的主组，因此可以使用此文件来修改文件：

```
jacky-> id
uid=1304 (jacky) gid=(1304) groups=1304 (jacky),2034 (project)

jacky-> ls -l my_report
-rw-r--r-- 1 jacky project      29387 Jan 15 09:34 my_report

jacky-> chown jacky:my_report

jacky-> chmod o-r my_report
jacky-> ls -l - my_report
-rw-rw-r-- 1 jacky jacky      29387 Jan 15 09:34 my_report
```

如果 jacky 想共享此文件，但不想给所有人写入权限，他可以使用 `chgrp` 命令：

```
jacky-> ls -l report-20020115.xls
-rw-rw---- 1 jacky  45635 Jan 15 09:35 report-20020115.xls
```

```
jacky-> chgrp project report-20020115.xls
```

```
jacky-> chmod g+w report-20020115.xls
```

```
jacky-> ls -l report-20020115.xls
-rw-rw---- 1 jacky  project 45635 Jan 15 09:35 report-20020115.xls
```

这样，project 组中的成员就可以处理此文件了。该组中的其他用户则无权操作。

`chown` 和 `chgrp` 都可以使用 `-R` 选项递归更改所有权。在这种情况下，给定目录的所有底层文件和子目录将属于该用户和/或组。

## 限制

在大多数系统中，非特权用户限制使用 `chown` 和 `chgrp` 命令。如果你不是系统的管理员，出于安全考虑，你无法更改用户组权限。如果这些命令不受限制，恶意用户可能会将文件的所有权分配给其他用户/组，改变用户环境的行为并对其他用户的文件造成破坏。

## 特殊模式

为了让系统管理员不必一直解决权限问题，可以使用特殊的访问权限来进入目录或分离程序。有特殊模式：

- **粘滞位 (Sticky bit)**：作业执行后，命令将保留在系统内存中。这最初被用于节省内存：大文件只加载到内存一次。但现在内存非常廉价，且有更好的技术来管理它，因此它不再用于单文件的优化能力。当应用于整个目录时，粘滞位具有不同的含义。在这种情况下，用户只有在是文件的所有者或文件具有相应权限时，才能更改该目录中的文件。这种权限用于如 `/var/tmp` 这样的目录，这些目录必须对所有人开放，但不允许用户更改或删除彼此的数据。粘滞位通过文件权限字段末尾的 `t` 表示：

```
mark:> ls -ld /var/tmp
drwxrwt 19 root 8192 Jan 16 10:37 /var/tmp/
```

粘滞位使用 `chmod +t` 命令设置。“t”的历史起源源于 UNIX 的保存访问控制功能。
