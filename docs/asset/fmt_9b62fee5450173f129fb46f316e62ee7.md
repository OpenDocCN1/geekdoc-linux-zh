## 符号链接

当我们观察时，可能会看到一个目录列表（例如 `/lib`），其中包含如下条目：

```
lrwxr-xr-x 1 root root 11 2018-08-11 07:34 libc.so.6 -> libc-2.6.so
```

注意列表的第一个字母是 `l` 并且似乎有两个文件名？这是一种特殊类型的文件，称为**符号链接**（也称为软链接或 `symlink`）。在大多数类 Unix 系统中，一个文件可以被多个名称引用。虽然这种做的意义可能并不显而易见，但在这种情况下这是一个非常有用的功能：一个程序需要使用名为 `"foo"` 的文件中的某种共享资源，但 `"foo"` 频繁发生版本变化。在文件名中包含版本号会很好，这样管理员或其他感兴趣的相关方就可以看到安装了哪个版本的 `"foo"`。这带来了一个问题。如果我们更改了共享资源的名称，我们就必须追踪到每一个可能使用它的程序，并在每次安装新版本的资源时都更改它以查找新的资源名称。这听起来一点也不好玩。

这就是符号链接发挥用场的地方。假设我们安装了 `"foo"` 的 2.6 版本，文件名为 `"foo-2.6"`，然后简单创建一个名为 `"foo"` 的符号链接指向 `"foo-2.6"`。这意味着我们可以在文件名中包含版本号，这样管理员或其他感兴趣的相关方就可以看到安装了哪个版本的 `"foo"`。

## 硬链接

当我们在讨论链接时，还需要提到另一种类型：**硬链接**。在 Linux 文件系统中，硬链接是指向文件 `inode` 的目录。与符号链接不同，硬链接不能跨分区。
