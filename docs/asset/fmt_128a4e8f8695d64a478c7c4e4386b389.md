
`castle% pgrep -G other, daemon -U root, daemon`

120

`castle%`

`kill` 的功能与 `pgrep` 相同，但每个匹配的进程都通过 `kill(1)` 发送信号，而不是显示其进程 ID。您可以将信号名称或数字作为 `pkill` 的第一个命令行选项。

两个命令都将 ERE 模式参数与 `/proc/nnnnn/psinfo` 文件中的 `pr_fname` 或 `pr_psargs` 字段进行匹配。这些字符串的长度受到 `sys/proprofs.h` 中定义的限制。可以匹配比当前字符串更长的模式可能无法匹配预期的进程集。

如果模式参数包含既是 ERE 元字符又是 shell 元字符的内容，您可能需要用适当 shell 引将模式括起来。

僵尸进程（Defunct processes）永远不会被 `pgrep` 或 `pkill` 匹配。

当前的 `pgrep` 或 `pkill` 进程也不会考虑自身的潜在匹配项。

## 选项

+ `-d delim` 指定在每个匹配的进程 ID 之间打印的输出分隔符。如果没有指定 `-d` 选项，默认为换行符。`-d` 选项仅作为 `pgrep` 的选项时有效。

+ `-f` 针对完整的进程参数字符串（从 `/proc/nnnnn/psinfo` 文件的 `pr_psargs` 字段获取）匹配正则表达式模式。如果未指定 `-f` 选项，则仅对可执行文件的名称（从 `/proc/nnnnn/psinfo` 文件的 `pr_fname` 字段获取）匹配表达式。

- `-g pgrep` 仅匹配组 ID 在给定列表中的进程。如果列表中包含 0，则将其解释为 `pgrep` 或 `pkill` 进程的组 ID。

+ `-G gidlist` 仅匹配实际组 ID 在给定列表中的进程。您可以将每个组 ID 指定为组名或数字 ID。

+ `-l` 打印每个进程的进程名称及其进程 ID。进程名称取决于您是否指定了 `-f` 选项，从 `pr_psargs` 或 `pr_fname` 字段获取。`-l` 选项仅作为 `pgrep` 的选项时有效。

+ `-n` 匹配符合所有指定匹配标准的最新（最近创建的）进程。

+ `-P ppidlist` 仅匹配父进程 ID 在给定列表中的进程。

# 1010 pgrep, pkill

+ `-s sidlist` 仅匹配进程会话 ID 在给定列表中的进程。如果列表中包含 ID 0，将其解释为 `pgrep` 或 `pkill` 进程的会话 ID。

+ `-t termlist` 仅匹配与给定列表中 `/dev/` 之后的后缀关联的进程。每个终端由 `/dev` 中终端设备路径名称后的后缀指定，例如 `term/a` 或 `pts/0`。

+ `-u eidlist` 仅匹配有效用户 ID 在给定列表中的进程。您可以将每个用户 ID 指定为登录名或数字 ID。

+ `-U uidlist` 仅匹配实际用户 ID 在给定列表中的进程。您可以将每个用户 ID 指定为登录名或数字 ID。

+ `-v` 反转匹配方向。匹配所有不符合指定匹配标准的进程。

+ `-x` 仅当参数字符串或可执行文件名与指定模式完全匹配时，才视为匹配。当进程参数字符串或可执行文件名中的所有字符与模式匹配时，模式匹配被视为精确。

+ `-signal` 指定向每个匹配进程发送的信号。如果未指定信号，则为 `SIGTERM`。

### 操作数

+ `pattern` 针对 `/proc/nnnnn/psinfo` 中的 `pr_fname` 或 `pr_psargs` 字段指定 ERE 模式。如果模式参数包含既是 ERE 元字符又是 shell 元字符的内容，您可能需要用适当 shell 引将模式括起来。

## pkgmk — 生成可安装的包

### 概要

```
/usr/bin/pkgmk [-o] [-arch] [-b base-src-dir] [-d device] [-f prototype] [-l limit] [-p pstamp] [-r root-path] [-v version] [variable=value ...] [pkginst]
```

## 描述

使用 `pkgmk` 命令生成一个可安装包，作为 `pkgadd(1M)` 命令的输入。包的内容采用目录结构格式。

`pkgmk` 使用 `prototype(4)` 文件作为输入并创建一个 `pkgmap(4)` 文件。`prototype` 文件中每个条目的内容会被复制到相应的输出位置。有关内容（校验 Check和、文件大小、修改日期）的信息将被计算并存储在 `pkgmap` 文件中，同时包含 `prototype` 文件指定的属性信息。

你可以通过命令行 `-a` 选项或在 `prototype(4)` 文件中提供架构信息。如果未提供架构信息，`pkgmk` 将使用 `uname -m` 的输出。

你可以通过命令行 `-v` 选项或在 `pkginfo(4)` 文件中提供版本信息。如果未提供版本信息，将提供基于当前日期的默认格式。

架构和版本的命令行定义将覆盖 `prototype(4)` 中的定义。

## 选项

- `-a arch` 用 `arch` 覆盖 `pkginfo(4)` 文件中提供的架构信息。

- `-b base-src-dir` 在路径前加上指定的 `base-src-dir`，以定位源机器上的可重定位对象。

- `-d device` 在设备上创建包。`device` 可以是绝对路径名，或者是软盘或可移动磁盘的标识符（例如 `/dev/diskette`）。默认设备是安装暂存目录 (`/var/spool/pkg`)。

- `-f prototype` 使用 `prototype` 文件作为命令的输入。默认 `prototype` 文件名为 `Prototype` 或 `prototype`。
