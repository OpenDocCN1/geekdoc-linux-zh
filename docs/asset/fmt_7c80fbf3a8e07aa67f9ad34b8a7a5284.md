
发送订阅和取消订阅消息的地址是：

```
listname-request@domain
```

然而，你不能总是依靠这些地址。唉。在这种情况下，你必须依靠特定列表的指令，你需要从维护者或朋友那里获取。

# 自动邮件排序

我们不会太详细介绍邮件排序，因为这是一个复杂的话题，但有时它复杂到你无法将收件邮件文件视为一个单一的实体体。

我们每天真的会收到上百条消息，如果不使用程序作为邮件过滤器，我们会疯掉的。这些程序查看你的收件邮件，并根据你设置的头部项目内容或消息正文标准，在你处理邮件之前将你的邮件排序到几个邮箱箱中。

例如，Ron 订阅了几个邮件列表。他将这些列表的每个消息路由到独立的邮箱箱中以便空闲阅读。他一直都有 USENET 投票票——这些会进入一个特殊的投票过滤器，由 usenet 软件处理。剩下的就是我用于正常阅读的普通邮箱箱。

实际上，邮件过滤器可以做更多。你可以用它们选择性地将邮件转发给其他用户，或者对某些消息发送自动回复。你甚至可以让他们在你度假期间写信给任何人时只发送一条信息消息，而不论那个时间他们收到了多少消息。

个人过滤器的缺点是使用内置功能的邮件客户端（例如 Eura）进行设置可能很困难。你需要仔细检查你的配置文件，以确保你不会不小心把消息掉在地上！

`procmail` 可能是邮件过滤器中最流行的。你对消息有了一定的控制权，可以在保存之前将其传递给其他程序（例如格式化程序）。它可以执行其他程序，并可用于运行简单的邮件列表或你的邮件服务器。它经过了广泛测试，非常稳定。不过，要小心不要意外让它将某些邮件发到黑洞。

你可以通过匿名 ftp 到 `http://ftp.informatik.rwth-aachen.de` 获取最新版本：`/packages/procmail`。

`deliver procmail` 是所有邮件过滤器程序之王，我们个人喜欢 deliver。你编写 shell 脚本来处理所有入站消息。这通常需要你付出更多工作，通常 deliver 非常简洁、无限灵活，并且你对电子邮件的操作仅限于你编写脚本的优劣程度。在你那台运行飞快的机器上，速度不应该太令人。。我们通过匿名 ftp 在 `sunsite.unc.edu` 找到它，地址为 `http://sunsite.unc.edu/pub/Linux/distributions/slackware.gz`

`mailagent` 是另一个著名的过滤器。它是用 `perl` 语言编写的，这意味着如果你懂 `perl`，就可以通过扩展 `mailagent` 来对你的电子邮件进行操作。它带有几个内置功能。如果你懂 `perl`，我们建议使用这个。匿名 ftp 到 `http://ftp.foretune.co.jp` 和 `/get /pub/network/mailagent` 。

`elm` 附带了一个名为 `filter` 的支持程序，用于进行邮件过滤。

# USENET

正如引言所述，USENET 是世界最大的电子论坛。互联网最受欢迎的功能之一，它允许全球的人讨论话题并交换意见。

因为帖子到达不同机器的路径各异，因此无法保证你在回复帖子之前能看到某个特定的帖子。例如，某人从机器 A 发布了一条消息，该消息通过缓慢的机器 B 发送到你的机器。同时它也将帖子发送到了另一台机器 C，C 立即收到了。有人迅速回复了它，C 将帖子发送给他的邻居，包括发送到你电脑的机器 D。在此期间，原始帖子还没有跨越机器 B 到达你那里。这种情况非常常见，尽管场景通常更加复杂。请不要惊慌。

我们说过所有机器都能接收帖子。某种程度上如此——USENET 如此庞大，许多站点只加载可用组的子集。站点不会接收它不感兴趣的组的帖子，即使收到了，也不会保留它们。此外，还有一种称为“分发头”（Distribution header）的东西，你可以在消息中使用它将其分发限制在特定的区域，例如圣地亚哥。这对于仅影响圣地亚哥的消息非常有用。

新闻组（Newsgroups）的命名如下：

`comp_sys.ibm.pc.games.action`

这是一个从左到右读取的层级结构。读取组名，你看到了一个 IBM 系统的计算机组，确切来说是 PC 系统。你讨论的是针对这些系统的游戏，更具体地说是动作游戏。

这是另一个：

`talk.politics.guns`

你有一个关于政治讨论的组，更具体说是关于枪支控制。我们将介绍更多关于这些层级的内容。

你发帖的新闻组与消息头中 `Newsgroups` 项的组相关联。它看起来像这样：

`Newsgroups: news.announce.newgroups`

与传统的公告板系统（BBS）不同，每个帖子可以发布到多个组！如果我们执行：

`Newsgroups: alt.usenet.future,news.groups`

我的帖子将同时出现在这两个组中。这被称为“交叉发帖”（crosposting）。虽然你应该知道这是可能的，但在你观察一段时间之前，你不应该真的这样做，因为这种轻率的交叉发帖是不受欢迎的。

事实上，还有另一个头可以用于将任何回复发送到特定的组。例如，你可能向几个组发布发布一条信息性帖子，但指定讨论（如果有的话）应该只在单个组中进行。这就是 `Follow-To` 头。这些头看起来如下：

`Newsgroups: rec.arts.misc,rec.arts.fun`

`Follow-To: rec.arts.fun`

记住这种头信息的格式，只要后续行有缩进，一个头信息就可以跨越好几行。这就是你将 `Newsgroups` 拆分为两行的方法。

交叉发帖可能会被滥用，但稍后会详细说明。一个原始帖子及其所有回复被视为一个单一的“线程”（thread）。这看起来实际上比一条直线复杂，因为对回复的回复会不断分支，直到线程因无聊而终结。

每条 USENET 消息都有一个“主题”（Subject），用于总结消息内容（尽管通常并非如此）。跟踪线程的一种方法是记录那些偏离原始帖子太远的消息。完全跟踪线程的唯一方法是使用线程化阅读器（threaded readers），我们将在下一节中讨论。

## 新闻阅读器 (Newsreaders)

首要任务是选择你将使用哪种程序来读取 USENET。你对这些程序（称为阅读器）的选择会极大影响你阅读网络的方式、你从中获取信息的多少量，以及你必须费力处理多少垃圾信息。`rn` 是免费的，所以你使用的阅读系统很有可能将其作为默认。如果可能，请避免使用！

当 `rn` 第一次编写时，人们阅读发布到 USENET 的每一条消息仍然有时间。默认设置是逐条显示组中的所有消息。这听起来合理，但事实是新闻组中的大多数帖子对你来说毫无兴趣。总有一天，你不再希望费力阅读组中的每条帖子，并对阅读的帖子变得挑剔。由于每个组每天收到数百条消息，`rn` 显示你每一条消息的偏好浪费了你的时间。

### 消息概述与线程化 (Message Overview and Threading)

如果阅读器首先给你提供组的概述，你可以节省多少时间。它会为每个帖子提供一行摘要——它给出了发帖者的姓名、主题，可能还有消息大小。滚动查看摘要页面，选择哪些帖子看起来有趣。完成后，阅读你选择的帖子。

这已经是概念上的重大转变——你不再需要阅读所有内容来决定哪些是不想读的，而是选择哪些帖子看起来有趣。现在我们还要增加另一个概念——阅读器应该跟踪相互相关且分组的帖子，这样你就可以一次性选择或忽略一组帖子。它可以通过注意之前提到的线程和主题来实现这一点。这两个变化几乎解释了优秀的线程化阅读器与像 `rn` 这种工具之间的速度差异。现在我们已经擅长判断哪些线程看起来有前景，哪些没有，我们读取 USENET 的速度在字面上可以快几百倍。我之后会推荐一些工具。

### 杀毒文件 (Kill Files)

如果你知道某个特定主题对你没有兴趣，并且你再也不会阅读该名称的帖子，那么阅读器即使向你提供它也是浪费时间。这对于那些不会在 USENET 上产生噪音的人来说，无疑是完美的。如果能永远不再看到那些帖子就好了。这就是杀毒文件（kill file）的目的。在最原始的形式中，你提供一个主题或你不想再次听到某人的消息。通常你会被允许进行一点微调。在一个特定的新闻组中，你可能会杀掉（屏蔽）某个主题。

这可以节省时间。

在一个半数讨论都是关于你不感兴趣的话题的组（例如，某个幻想组）中杀掉（屏蔽）某个作者，让阅读器自动过滤掉与该作者相关的文章可以节省你的时间。

还有杀毒文件的反面。如果你知道你想阅读特定主题或来自某人的所有帖子，选择文件（selection file）可以让阅读器自动标记它们为可读。这不像杀毒文件那么常见。

## 哪种新闻阅读器？

这是一个宗教式的偏好问题，类似于“最好的编辑器是什么？”。我们认为任何具有以下功能的阅读器都是竞争者：

- 提供消息概述，让你在之前选择消息。
- 允许通过共同的主和线程将帖子分组。
- 允许指定阅读器自动杀掉作者或主题，以便你永远看不到它们。你应该能够执行相反操作——自动选择某些作者或主题。
- 允许单个组或所有组执行相反操作。

剩下的都是细节，尽管我们想将“非常可配置”加入列表。

遗憾的是，编译和配置新的阅读器可能是一个非常棘手的问题，特别是对于 USENET 新手来说。目前，你可能不得不使用系统提供的任何程序——如果只有 `rn`，请找你的管理员。

`NN`（无新闻）`nn` 快速、灵活、非常可配置，具有良好的选择选项以及管理旧消息的方法。每个都有它自己的组，`news.software.nn`。这绝对值得一看。

### 其他阅读器

其他值得查看的 UNIX 阅读器（如果你的站点提供）有 `TRN`、`STRN` 和 `TIN`。它们目前拥有最大的 UNIX 阅读器数量。它们符合或超过了给出的标准。你也可以阅读 USENET 组 `news.software.readers` 以获取最新信息。Netscape 网页浏览器提供了跟踪、回复和启动组的功能。要访问特定的新闻组，调用“文件”和“打开位置”菜单，并输入新闻组的 URL。新闻组的 URL 由单词 `news` 组成，后面跟着冒号和组名。例如，要访问 Oracle 数据库组，输入 `news:comp.databases.oracle`。你可以使用星号 (`*`) 来显示层级结构中特定级别的所有项目。URL `news:comp..*` 将列出所有讨论组。

请离线进行你的 USENET 处理。如果你是按连接时间计费，这将非常有用。请参考 `alt.usenet.offline-reader` 组来寻求帮助。

## 查找你的组

你可以参与的数千个新闻组。本节将帮助你找到感兴趣的组。

### 层级结构

如前所述，组名从左到右按层级排列。左侧的项目被称为层级结构的顶层。对于这样的组：

`alt.tv.animaniacs`

该组被认为“位于 alt 层级”（或“alt 层级”）。网络被组织为八个层级，其中是一个无政府状态，以及许多较小、不那么重要的层级。

### 八大层级

八大层级如下：

| | 描述 |
| :--- | :--- |
| `comp.` | 计算机主题。范围从编程、硬件、外围设备到民俗知识。大多数受欢迎的社区和操作系统在这里都有自己的一组组。 |
| `misc.` | 杂项。当没人能确定将新组放在什么处时，它通常会归入 misc. 下。例如，`misc.jobs` 组显然不属于其他六个层级中的任何一个，所以它们属于 misc.。USENET 的业务。人们在这里讨论 USENET 管理、组，以及关于 USENET 何时会解决它的烦恼。 |
| `rec.` | 娱乐主题。大多数爱好者的内容（如 `rec.crafts.jewelry`）都属于这里。它还包含了艺术音乐和讨论，而且并非徒劳。 |
| `sci.` | 科学。这是数学和物理类爱好者的聚集地。也包括医学，例如 `sci.med. radiology`。 |
| `soc.` | 社会主题。这是一个包含不同地区文化组的大包，例如 `soc.culture.chile`、社会研究组、讨论组和替代生活方式组。它是 militar. 的某种版本。 |
| `talk.` | 激烈的辩论。人们之间极度恶毒的人身攻击（其中大多数人甚至没听过“批判性思维”的概念），这些攻击围绕他们感兴趣的任何话题——政治和宗教。例如，参见 `talk.politics.mideast`。这里永远不需要真正的辩论。 |
| `humanities.` | 人文文学与美术。该层级包含了大量关于音乐、哲学和美术的讨论。例如，参见 `humanities.lit.author.shakespeare`。 |

这些层级有时被称为 USENET 本身（USENET proper），被许多管理员认为是“真正的”层级。在任何八个层级中创建新组，都必须通过组兴趣发布政策，该政策阻碍了过度轻率的组创建。见下文。

### alt. 的下水道

实际上，我最喜欢的一些组在 `alt.` 层级中，但它的声誉褒贬不一。与大层级不同，任何想为新组发送创建请求的人都可以创建一个 alt 组。随后，如果有人认为该组不符合要求，就会发送组移除消息，但这比大组要松散得多。例如，`alt` 层级有 `alt.sights`。该层级还包含一些争议性的组，如这里的 `alt.sex.stories`，并且由于 `alt.binaries.pictures` 组，图片占据了大量的空间。由于我们在处理 `alt.` 时面临的各种麻烦，许多站点并不提供任何此类组。

我们认为这是可耻的，因为 `alt.` 也是那些在八大层级中找不到家的小组的避风港。例如，对电视节的讨论通常是瞬时的，因为对节目的兴趣可能会避免地消灭。出于这个原因，我们不愿意在八大层级中为“双峰奇”（Twin Peaks）这样的组投票，但它们最终进入了 `alt.tv` 层级，在那里它们是多年快乐的源泉（当我们觉得自己像一个社区时）。

`alt.` 不是免费的，因为组可以被随时创建，而不像八大层级那样需要两个月。像 `alt.current-events-la-quake` 这样的组可以在一夜内创建以应对各种情况。

近年来，`alt.` 变得有些有组织了。任何人都可以创建一个新组，但任何人也可以发送移除消息，如果该组没有在 `alt.config` 上提议或者它显然是一个玩笑，几位 `alt.` 志愿者警察就会这样做。这减少了像 `alt.french.capital` 这样的“三词重复”类型组的数量（该组最初是由 `alt.swedish.chef.bork.bork` 组创建的）。但它远不是八大层级，我们还要等到它成为那一天。

### 其他层级

人们可以出于特殊原因创建层级（所有想说服他人留在组内的人），这样做通常有充分理由。特别是除非层级是区域性组。例如，有很多用于讨论加利福尼亚州的组（如 `ca.politics`）。这让本地工作人员可以看到网络其他地方看不到的内容。拥有活跃网络社区的城市有自己的层级，例如用于圣地亚的 `sd.net`。大学（`ucs.`）和公司也是如此。

还有旨在更广泛传播但受其他原因的层级。许多 BITNET 邮件列表在 USENET 的 `bit.groups` 中转播。许多基础教育的讨论在 `k12` 组中进行。

有少数尝试进入八大层级但失败了。`trial` 和 `us.` 都因为缺乏兴趣而失败了，尽管此时人们正尝试复兴 `us` 层级。

### 我该去哪里？

回到你最初的问题——如何知道某个特定主题应该去哪里？有几种方法。

你的第一种方法是 `news.`。

传销骗局。有时你会看到关于“快速致富”或其他其他类型的暴富计划。千万不要这样做！

这种链条永远不会消失，而且发布这些内容的人在发布地点上表现得非常讨厌人（甚至发布到 USENET 上的每一个组——考虑一下这一点），人们对这种行为是完全不容忍的。你会收到几千封愤怒的电子邮件，它们可能会导致你的电脑死机，并让你的管理员大不快。这可能是非法的。

### 过度多组发

之前，我们展示了如何将帖子同时发送到多个群组，这被称为“多组发”（crossposting）。除非是特殊的 USENET 信息发布，否则几乎从不需要，也只有在极少数情况下才有必要发到四个以上的群组。

新手通常把多组发作为一种求助——他们不确定该在哪里提问，所以他们发到任何看起来可能相关的组。他们往往会撞进几个不恰当的组，在对多组发的投诉以及由于多组发导致那些帮助过的人产生疏感之间，新手并得不到问题的答案。

花时间查看每个组的几条信息，看看是否合适。如果你发现某个组看起来很对，就发布你的问题。你可以注明你并不 100% 确定自己在正确的地方，并请求更好的指引。人们对这类帖子非常友好。当然，你也可以在 `news.questions` 组询问你应该把问题投递到哪里。

### 阅读 FAQ（常见问题解答）！

有一天，USENET 的人们注意到新用户问的都是相同的问题。他们决定创建一个“常见问题列表”（只是那个 L 听起来不太好），这个列表将提供这些问题的答案，防止它们被一遍又一遍、一遍又一遍地提问，这太棒了！

这效果非常好，现在很多群组都有 FAQ。这意味着如果你出现在某个群组并提问了 FAQ 中已有的问题，你会得到一些负面回应（“去读 FAQ FAQ！”）。如果你为了提问而进入一个新组，请确保寻找了标题中带有“FAQ”字样的帖子。如果你找到任何，请先阅读它们。你的答案（以及你甚至还没想到的问题）可能就在里面。

如果你在寻找通用的信息，大多数 FAQ 都发布在 `news.answers`。你可以去浏览所有精美的 FAQ。

## 将“回战”降至最低

在术语中，“flame”（回战）是对某人或某事的激烈攻击。一系列持续的交换回战（回战很容易蔓延，是真的）被称为“回战者”（flewer）。

偶尔的回战通常会触发警告并清理你的系统，但要小心让它带偏你。有些人名声是太急于回战——一个诚实的错误可能会让你换来这种人对你关于你母亲约会习惯的讽刺。另一些人以纯粹为了乐此而闻名。这些人有一个专门的组（`alt.flame`）。

然而，如果你想避免获得一个冷静、能力辩论者的声誉，请注意一言。我们发现让信息放置五分钟然后再回来处理很有用。你可能会像我们一样发现，一条看起来没有攻击性的信息实际上对对方的论点更有破坏性。如果你仔细观察，就能看到高手们学到了什么：如何用乙炔喷灯进行回战，用事实、风格以及巧妙地蒸发某人考虑不周的帖子，这比标准的“噢，是的，Monoron！”类型要致命得多！

### 不要装傻

在网络上，假装知道某些事情失败的次数比你想象的要高得多。网络上有大量见多识广的人（在某些主题上他们似乎是信息库），比你懂得多的人很有可能会拆穿你的装傻。

这同样适用于激进的主张——如果你打算提出一个主张，最好准备好支持它。网络之所以被称为“百万谎言之网”并非没有理由，大多数在上面待过久的用户都会持怀疑态度。而且还有那些反对你的立场并拥有事实来论证自己观点的人。
