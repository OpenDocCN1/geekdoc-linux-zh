
如果在源目录名称后添加一个结尾的 `/`，`rsync` 将只复制源目录的内容，而不是目录本身。

```
me@linuxbox-$ rsync source/ destination
me@linuxbox-$ ls destination
file1
```

如果我们只想复制目录的内容，而不希望在目标路径中多出一层目录，这种方法就非常方便。我们可以将其结果看作是类似于 `source/*`，但这种方法将复制源目录的所有内容，包括隐藏文件。

作为一个实际示例，让我们考虑之前用 `tar` 使用过的那个虚拟外部硬盘。如果我们再次将该硬盘挂载到系统，并且它挂载在 `/media/BigDisk`，我们可以在外部硬盘上创建一个名为 `/backup` 的目录，然后使用 `rsync` 将系统最重要的内容复制到外部硬盘，从而执行实用的系统备份。

```
me@linuxbox ~/ sudo rsync -av /etc /usr/local /media/BigDisk/backup
me@linuxbox ~/ sudo rsync -av --delete /etc /usr/local /media/BigDisk/backup
```

在这个示例中，我们从存储设备复制了内容。我们包含了 `--delete` 选项来删除备份设备上可能存在但在源设备上已不存在的文件（这在第一次备份时无关，但在随后的拷贝中非常有用）。重复挂载外部硬盘并运行此 `rsync` 命令的操作是维护小型系统备份的一种有效（尽管不是理想）的方法。当然，在这里使用别名（`alias`）也会很有。我们可以创建一个别名并将其添加到 `.bashrc` 中提供此功能：

## 通过网络使用 Rsync

`rsync` 的实际优势之一是它可以用于通过网络复制文件。毕竟，`rsync` 中的 `r` 代表“remote”（远程）。远程拷贝有两种实现方式。第一种是使用另一个安装了 `rsync` 的系统，并通过使用 `ssh` 的远程 shell 程序。假设我们在局域网上有另一个拥有大量可用硬盘的系统，我们想使用远程系统而不是外部硬盘来执行备份操作。假设它有一个名为 `/backup` 的目录可以让我们存放文件，我们将这样操作：

```
me@linuxbox ~/ sudo rsync -av --delete -rs=ssh /etc /home /usr/local remote-sys:/backup
```

为了方便网络拷贝，我们做了两个更改。首先，我们添加了 `--ssh=ssh` 选项，它指示 `rsync` 使用 `ssh` 程序作为其远程 shell。通过这种方式，我们能够使用 `ssh` 加密隧道安全地将数据从本地系统传输到远程主机。在现代系统中，`ssh` 是默认的，因此很少需要这样做。其次，我们通过在目标路径前加上主机名（在本中，远程主机名为 `remote-sys`）来指定远程主机。

`rsync` 用于网络同步文件的第二种方法是使用 `rsync` 服务器。`rsync` 可以被配置为守护进程（`daemon`），并监听用于同步的传入请求。这通常用于允许对远程系统进行镜像。例如，红帽软件为其 Fedora 发行版维护了一个大型的开发软件包仓库。对于软件测试人员来说，在发行版周期的测试阶段镜像该集合是非常有用的。由于仓库中的文件频繁变化（通常一天超过一次），因此通过定期同步而不是批量拷贝仓库来维护本地镜像是更明智的。其中一个仓库就保存在杜克大学；我们可以使用本地的 `rsync` 副本和他们的 `rsync` 服务器进行镜像，如下所示：

```
[me@linuxbox~$] mkdir fedora-devel
[me@linuxbox~$] rsync -av --delete rsync://archive.linux.duke.edu/
fedora/linux/development/rawhide/Everything/x86_64/os/ fedora-devel
```

在这个示例中，我们使用了 `rsync` 服务器的 URI，它由一个协议（`rsync://`）、一个远程主机名（`archive.linux.duke.edu`）以及仓库的路径名组成。

## 正则表达式

在接下来的几个章节中，我们将查看用于处理文本的工具。正如我们所见的，数据在所有 Unix 类系统（如 Linux）中都起着关重要的作用。但在我们充分利用这些工具所提供的所有功能之前，我们必须首先检查一种经常与这些工具的最复杂用法密相关的技术——*正则表达式*（regular expressions）。

当我们浏览了命令行提供的许多功能和设施时，我们遇到了一些真正深奥的功能和命令，例如 shell 扩展和引用、键盘快捷键以及命令历史，更不用说 *vi* 编辑器了。正则表达式延续了这种“传统”，并且可能是（可以争说是）所有功能中最深奥的一个。这并不是说学习它们的时间是不值得的。

### 什么是正则表达式

简单来说，它们是用于在文本中识别模式的符号。在某些方面，它们类似于 shell 的通配符，但规模大得多。正则表达式被许多命令行工具支持。

```
grep
```

我们用于处理正则表达式的主要程序是 `grep`。它的名字实际上源于“global expression print”（全局表达式打印），所以我们可以看到它与正则表达式有关。本质上，`grep` 在文件中搜索指定的正则表达式，并将任何匹配的行输出到标准输出。

到目前为止，我们使用 `grep` 处理固定字符串，如下：

```
@me@linuxbox~$ ls /usr/bin | grep zip
```

这将列出 `/usr/bin` 目录中所有包含 `zip` 字符串的文件。`grep` 程序接受如下选项和参数，其中 `regex` 是正则表达式：

```
grep [options] regex [file...]
```

### 元字符与字面量

虽然看起来并不显而易见，但 `grep` 使用正则表达式进行搜索，尽管这些通常是非常简单的正则。正则表达式 `bzip` 意味着，只有当文件中的行至少包含四个字符，并且在行的某处按顺序找到字符 `b`、`z`、`i` 和 `p` 且之间没有其他字符时，才会发生匹配。字符串 `bzip` 中的字符都是字面量字符，即它们与自身匹配。除了字面量外，正则表达式还可以包括用于指定更复杂搜索的元字符。正则表达式元字符包括以下内容：

```
^ $ . [ } ] ? * ( ) \
```

所有其他字符均被视为字面量，尽管反斜杠字符 `\` 在某些情况下用于创建元序列，并允许元字符被转义从而作为字面量处理，而不是被解释为元字符。

#### 注意

正如我们看到的，许多正则表达式元字符在执行扩展时对 shell 来说也是具有意义的字符。当我们从命令行传递包含元字符的正则表达式时，将它们括在引号内是关重要的，以防止 shell 尝试对它们进行扩展。

### 任意字符

我们将看到的第一个元字符是点或句号字符 `.`，它用于匹配任何字符。如果我们将其包含正则表达式中，它将匹配该字符位置上的任何字符。这是一个例子：

```bash
me@linuxbox ~$ grep -h '.zip' dirlist*.txt
bunzip2
bzip2
bzip2recover
gunzip
gzip
funzip
gpg -unzip
prezip
prezip
prezip-bin
unzip
unzipsfx
```

我们在文件中搜索匹配正则表达式 `.zip` 的任意行。关于结果，有几点有趣的地方需要注意。注意没有找到 `zip` 程序。这是因为在我们的正则表达式中包含点元字符 `.` 使得所需匹配的长度增加到了四个字符，其中一个必须在 `z` 之前。此外，如果我们列表中的任何文件包含 `.zip` 文件扩展名，它们也会被匹配，因为文件扩展名中的点字符也会被“任意字符”匹配。

### 锚点

脱字符符号 `^` 和美元符号 `$` 在正则表达式中被视为锚点。这意味着只有当正则表达式出现在行开头 (`^`) 或行尾 (`$`) 时，匹配才会发生。

```bash

zipcloak
gziprep
zipinfo
zipnote
zipsplit
me@linuxbox ~$ grep -h 'zip$' dirlist*.txt

gzip
funzip
gpg-zip
prezip
prezip
unzip
```

```bash
[@linuxbox ~]$ grep -h '^zip$' dirlist*.txt
zip
```

我们在文件列表中搜索位于行开头、行尾，以及在某些情况下既是行开头又是行尾的行（即在该行中只有该单词）的字符串 `zip`。请注意，正则表达式 `^$`（一个开头和一个结尾，之间什么都没有）会匹配空行。

### POSIX 字符类

传统的字符范围是一种易于理解且有效的方法，用于快速指定字符集。然而，它们并不总是有效。虽然我们目前在使用 `grep` 时没有遇到任何问题，但在其他程序中使用可能会遇到问题。

在第四章中，我们查看了通配符如何执行扩展。在那个讨论中，我们看到字符范围用法与在正则表达式中几乎相同，这里是问题所在：

```
ls -S /usr/sbin/[ABCDEFGHIJKLMNOPQRSTUVWXYZ]*
/usr/sbin/MAKEFLOPES
/usr/sbin/NetworkDispatcher
/usr/sbin/NetworkManager
```

（取决于 Linux 发行版，我们将得到不同的文件列表，可能是空列表。这个示例来自 Ubuntu。此命令产生了预期的结果——即所有以大写字母开头的文件列表，但使用此命令我们得到了完全不同的结果（仅显示结果的部分列表)：

```bash
ls -S /usr/sbin/[A-Z]*
/usr/sbin/biosdecode
/usr/sbin/chat
```

```
/usr/bin/chpgpwd
/usr/bin/chpasswd
/usr/bin/chroot
/usr/bin/cleanup-info
/usr/bin/complain
/usr/bin/console-kit-daemon
```

为什么呢？这是一个长故事，但简单来说是：在 Unix 最初开发时，它只认识 ASCII 字符，而这一特性反映了这一事实。在 ASCII 中，前 32 个字符（0–31）是控制代码（如制表符、退格和回车等）。接下来的 32 个（32–63）包含打印字符，包括标点符号和数字 0 到 9。接下来的 32 个（64–95）包含大写字母和几个标点符号。最后的 31 个（96–126）包含小写字母和几个标点符号。由于这种排列，使用 ASCII 排序的系统看起来如下：

```
ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

这与真正的字典不同，字典应该是：

```
aAbBcCdDeEeFgGhHiJkLlMnNoPqRsStTuUvWXyYz
```

随着 Unix 在美国以外的普及，对支持美国未发现字符的需求日益增长。ASCII 表扩展到使用完整的 8 位，增加了 128 到 255 的字符，这容纳了许多语言。为了支持这一点，POSIX 标准引入了一个名为 *locale*（区域设置）的概念，可以对其进行调整以选择特定区域所需的字符集。我们可以在这里查看系统的语言设置：

```
[me@linuxbox ~]$ echo LANG
en_US.UTF-8
```

有了此设置，符合 POSIX 标准的应用程序将使用字典排序而不是 ASCII 排序。这解释了之前命令的行为。[a-z] 字符范围包括除小写字母 *a* 以外的所有字母字符，该范围会返回结果。

为了部分解决这个问题，POSIX 标准包含了一许多字符类，它们提供了有用的字符范围，如表 19-2 所示。

### 表 19：POSIX 字符类

| 字符类 | 描述 |
|--- | --- |
| [:alnum:] | 字母和数字字符；在 ASCII 中，等同于 [A-Za-z0-9]。 |
| [:word:] | 等同于 [:alnum]；增加了下划线 (_) 字符。 |
