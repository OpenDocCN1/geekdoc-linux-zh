
# 理解 NFS 的安全模型

你应该记住，`NFS` 依赖客户端来处理某些安全任务。特别是，`NFS` 访问不需要密码。如果客户端在 `/etc/exports` 中被授权，客户端就可以访问相关的目录或文件。几十年前，只有经过管理员管理的 Unix 工作站才能具有访问权限，风险较低。在今天，任何可以伪造 `DNS` 记录或获得物理访问以入侵 `IP` 地址的人都可以入侵 `NFS` 服务器并读取任何假设用户名下的文件。

出于这个原因，通过 `exports` 文件授权远程访问时应保持谨慎。在某些环境中，可能需要对主目录拥有读/写权限，但对大多数目录的读/写权限可能是不必要的风险。

如果你修改了 `/etc/exports` 文件，可以使用 `exportfs` 程序通知 `NFS` 服务器这些更改。具体来说，你输入 `exportfs -r` 来更新服务器的可用导出列表以匹配 `exports` 文件。你还可以使用 `exportfs -u` 使特定导出不可用，或通过其他选项产生其他影响。详情请查阅 `exportfs` 帮助页。

# 挂载 NFS 导出

`Linux` 的 `NFS` 客户端本质上是 `Linux` 内核本身。内核将另一台计算机的 `NFS` 服务器视为一个可以通过 `mount` 命令或在 `/etc/fstab` 中挂载的文件系统。

第 5 章“在文本模式下工作”、第 10 章“使用多个操作系统”以及第 12 章“文件系统与文件”描述了这些任务。

`NFS` 客户端通常在 `Linux` 内核中。

挂载 `NFS` 导出时，通常使用 `mount` 命令。例如：

```bash
mount -t nfs server.luna.edu:/home /home
```

或者在 `/etc/fstab` 中配置以自动挂载：

```text
server.luna.edu:/home /home nfs defaults 0 0
```
