# `pvs` — 显示动态对象的内部信息

### 概要

```
/usr/bin/pvs [-dnorsv][-N name] file...
```

## 描述

使用 `pvs` 命令显示执行和链接格式 `ELF` 对象文件中包含的内部版本信息。通常 `ELF` 文件是动态可执行文件、共享对象以及可能的重定位对象。这些版本信息可以分为两类。

+ 版本定义描述了文件提供的接口。每个版本定义都与文件提供的全局符号相关联。版本定义可以在创建文件期间通过链接器使用 `-M` 选项和相关的 `mapfile` 指令进行分配（详细信息请《链接器和库指南》）。

- 版本定义描述了动态对象对任何共享依赖的版本定义的绑定需求。当使用共享对象构建动态对象时，链接器会在动态对象中记录信息，指示该共享对象是依赖。如果共享对象也包含版本定义，那么满足动态对象全局要求的版本定义也将记录在正在创建的动态对象中。

## 选项

如果你既没有指定 `-d` 也没有指定 `-r` 选项，两者都将启用。

- `-d` 打印版本定义信息。

- `-1` 与 `-s` 选项配合使用时，打印由于版本控制从全局绑定减少为局部绑定的符号。按照惯例，这些符号条目位于 `.symtab` 段，并位于表示输出文件的 `FILE` 符号与表示生成输出文件的第一个输入文件的 `FILE` 符号之间。

这些被归约 `reduced` 的符号条目被分配了伪造的版本定义标识 `_REDUCED_`。如果文件已剥离（参见 `strip(1)`）或无法确定符号条目约定，则不打印这些符号。

- `-n` 归一化版本定义信息。默认情况下，显示对象内的所有版本定义。然而，版本定义可以继承其他版本定义，在归一化下，只显示每个继承列表的头部。

- `-o` 创建单行版本定义输出。默认情况下，版本定义和任何符号输出都会缩进，以便人类检查。此选项在每行输出的前缀加上文件名和版本定义名称，可能更便于自动化工具进行分析。

- `-r` 打印版本依赖（需求）信息。

- `-s` 打印与每个版本定义相关的符号。在数据符号旁附带数据项的大小（单位为字节）。

- `-v` 显示任何弱版本定义和任何版本定义继承。与 `-n` 和 `-d` 选项配合使用时，还会显示基础版本定义的继承。与 `-s` 选项配合使用时还会显示符号定义。

- `-N name` 仅打印给定的版本定义名称及其任何继承的版本定义（与 `-d` 选项配合使用），或打印给定的依赖文件名（与 `-r` 选项配合使用）。

### 操作数

- `-file` 要显示版本信息的 `ELF` 文件。

## 示例

以下示例显示了 `libelf.so.1` 的版本定义。

```
castle% pvs -d /usr/lib/libelf.so.1
      libelf.so;
```

SUNW_1.1;
SUNW_0.7;

```

以下示例使用 `-n -o` 选项来产生归一化的单行显示，适用于创建 `mapfile` 版本控制指令。

```
castle% pvs -don /usr/lib/libelf.so-1

```

castle% pvs -r /usr/bin/ldd /usr/bin/pvs

/usr/bin/pvs:
libelf.so.1 (SUNW_1.2);
libc.so.1 (SUNW_1.1);
caste%
```

## 退出状态

如果未找到请求的版本信息，则返回非零值，否则返回 `0`。

当满足以下任一条件时，未找到版本信息：

- 你指定的 `-d` 选项，但未找到版本定义。

- 你指定的 `-r` 选项，但未找到版本需求。

- 你既没有指定 `-d` 也没有指定 `-r`，且未找到版本定义或版本需求。

## `pwd` — 返回工作目录名称

### 概要

```
/usr/bin/pwd
```

## 描述

使用 `pwd`（打印工作目录）命令向标准输出显示当前工作目录的绝对路径。Bourne shell `sh(1)` 和 Korn shell `ksh(1)` 都有内置的 `pwd` 命令。

> 注意 — 如果你移动了当前目录或其父目录，`pwd` 可能无法给出正确响应。使用带有完整路径名的 `cd(1)` 命令来纠正这种情况。

## 示例

以下示例显示当前目录，切换到另一个目录并显示新的当前目录。

```
castle$ pwd
/export/home/winsor
castle$ cd /etc
castle$ pwd
/etc
```

## 环境变量

参见 `environ(5)` 获取影响 `pwd` 执行的以下环境变量的描述：`LC_MESSAGES` 和 `NLSPATH`。
