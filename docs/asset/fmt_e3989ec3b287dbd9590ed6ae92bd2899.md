## 4.44 识别未知网卡

好了，假设你表哥的邻居朋友的兄弟在一个用作宠物仓鼠笼子的 AT 机机箱里发现了一块旧的 ISA 卡。你最终得到了这块卡，并想尝试在 Linux 下使用它，但没有人知道这块卡是什么，而且没有任何相关文档。

首先，寻找任何可能提供线索的型号数字。任何包含 2000 的型号极可能是 NE2000 的克隆卡。任何某处带有 8003 或 8013 标识的网卡都是 Western/Digital WD80x3 卡、SMC Elite 卡，或它们的克隆卡。

### 识别接口控制器

寻找网卡上最大的芯片。这可以通过其零件号来识别。如果你知道卡上是哪种网卡（NIC），以下信息可能帮助你判断它是哪种网卡。

最常见的网卡可能仍然国家半导体（National Semiconductor）的 DP8390、NS32490、DP8391、DP8392、DP8395 或 DP8397。而且这些都是国家半导体制造！其他公司如 Windbond 和 UTC 也制造了 DP8390 和 DP8395 的克隆产品，例如 Windbond 89c904 DP8395 克隆卡和 UMC 9090。如果卡上有某种形式的 8390 字样，那么它很有可能是 ne1000 或 ne2000 的克隆卡。第二常见的基于 8390 的卡是 wd80x3 克隆卡。带有 DP3895 的卡可以配置为 ne2000 或 wd8013。较版本的 wd80x3 和 SMC Elite 卡使用 83c790 代替了原始的 DP8390。SMC EtherEZ 卡使用 83c795，并与 SMC Ultra 使用相同的驱动。所有基于某些 8390 或 8390 克隆卡的 BNC 卡通常会在 BCC 附近有一个 8392（或 83c92，或 ???）16 DIP 引脚芯片。

在旧卡上找到的另一种常见网卡是 Intel `i82586`。带有这种网卡的卡包括 3c505、3c507、3c523、Intel Ethernet–ISA、Microdyne ECS–205 以及 Racal–Interlan N15210。

原始的 AMD LANCE 网卡是 AM7990，较新的版本包括 79c960、79c961、79c965、79c970 和 79c974。大多数带有上述任一芯片的卡都可以 LANCE 驱动，但 Racal–Interlan N6510 除外，它们有自己的驱动。

网卡上带有 DEC 21040、21041、21140 或类似数字的新型 PCI 卡应该能够使用 linux `tulip` 或 `deax25` 驱动。

其他带有标有 RTL8029、89c940 或 86c926 大芯片的 PCI 卡是 ne2000 克隆卡，Linux v2.0 中的驱动程序应在启动时自动检测这些卡。

### 识别以太网地址

每个以太网都有一个该网卡唯一的字节地址。对于该特定制造商的每块卡，地址的前三个字节是相同的。例如，SMC 卡以 00:00:c0 开头。后三个字节由厂家唯一标识，以便在生产时识别每块卡。

如果你的卡上贴有包含所有地址位位的贴纸，你可以通过前三个字节查询厂商。然而，更常见的是只有最后三个字节打印在带有插座式 ROM 的贴纸上，这无法提供任何信息。

你可以根据 RFC-1340 确定哪些厂商分配了地址。显然，在其他地方也有更新的列表。尝试在 WWW 或 FTP 上搜索以太网代码（Ethernet-codes），你会发现一些。

### 通过 FCC 编号识别网卡

作为认证流程的一部分，网卡在出售给用户之前必须通过测试，经过 FCC 测试后会获得一个 FCC ID，该 ID 应该打印在网卡的某处。例如，某块卡的 FCC ID 为 J158013EWC，这块卡恰好是 SMC/WD8013-EWC。一些像 `driverguide.com` 和 `drdriver.com` 的网站使用了 FCC ID 列表，可能有助于识别那些不明显的 ID。

### 使用未知网卡的技巧

如果你不确定这块卡是什么，但至少缩小了范围，那么你可以编译一个包含大量驱动程序的内核，看看是否有任何一个程序在启动时自动检测到该卡。

如果内核没有加载其他驱动程序，可能是因为网卡没有配置在驱动程序扫描网卡时的地址之一。在这种情况下，你可能想尝试从本地 ftp 站点获取 `scanport.tar.gz`，看看它是否能定位你的跳线强制设置的位置。它扫描 I/O 空间 0x100 到 0xff...（注：此处后续由于原文 OCR 错误显示为碎片化）。
