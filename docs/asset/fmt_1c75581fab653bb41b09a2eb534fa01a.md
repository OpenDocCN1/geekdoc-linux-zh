## lex 679

`{name}` 定义。

- `+ ?` 单字符 RE 重复拼接。
- `{m, n}` 范围表达式。
- `|` 备选择。

ERE 锚定操作符 (`^` 和 `$`) 未出现在表中。在 `lex` 正则表达式中，这些操作符的使用受到限制。你只能将 `^` 操作符用于整个正则表达式的开头，只能将 `$` 操作符用于结尾。操作符适用于整个正则表达式。因此，例如模式 `^(abc|def)$` 是未定义的。相反，你可以将其写为两个独立的规则：一个使用 `^abc` 的正则，另一个使用 `def$` 的正则，通过特殊动作共享相同的动作。如果你写成 `^abc|def$`，它将匹配单独成一行的 `abc` 或 `def`。

与通用的 ERE 规则不同，大多数历史 `lex` 实现都不允许嵌入式锚定（embedded anchoring）。嵌入式锚定的示例是模式如 `(^) foo($)` 用于在 `foo` 作为完整单词存在时匹配它。你可以使用 `lex` 特性实现此功能，如下所示：

```
^/([\n]\n* foo(/\n) / found foo as a separate word */
```

注意 `$` 是尾随上下文的形式（等同于 `\n`），你不能在包含另一个该操作符的正则表达式中使用它。

如果你在双引号内提供额外的正则表达式尾随上下文操作符 `/`，则可以将其作为普通字符使用，例如 `"/\\"`；状态操作符 `<` 和 `>` 仅在正则表达式开头的起始状态中具有特殊意义；在正则表达式的其他位置，它们被视为普通字符。

以下示例阐明了 `lex` 正则表达式与本文其他地方出现的正则表达式之间的区别。对于形式为 `r/x` 的正则表达式，将始终返回匹配 `r` 的字符串；当 `x` 匹配 `r` 的尾部部分时，可能会产生混淆。例如，正则表达式 `ab*/bc` 和输入 `aaabc`，`yytext` 在匹配时将包含字符串 `aab`。但是，给定正则表达式 `x*/` 和输入 `xxxy`，某些实现由于 `xxx` 匹配 `x.*` 会返回令牌 `xx` 而不是其他。

在规则 `ab*/bc` 中，`r` 结尾的 `b*` 将 `r` 的匹配扩展到尾随上下文的开头，因此结果是不指定的。如果规则是 `ab/bc`，则当文本后面跟着 `bc` 时，规则匹配文本 `ab`。在这种情况下，`r` 的匹配无法扩展到 `x` 的开头，因此结果是指定的。

## lex 中的动作 (Actions)

当匹配 ERE 时采取的动作可以是 C 程序片段或下述的特殊动作。程序片段可以包含一个或多个 C 语句，并包含特殊动作。空 C 语句 `;` 是一个有效动作；`lex.yy.c` 输入中任何匹配此类规则模式的字符串都会被有效忽略或跳过。然而，缺少动作是不合法的，`lex` 在这种情况下采取的动作是未定义的。

如果将包含 C 语句和特殊动作的动作括在大括号中，动作的规范可以跨多行：

`ERE <一个或多个空格> { program statement statement }`

默认动作是当 `lex.yy.c` 输入中的字符串未被任何表达式匹配时，将字符串复制到输出。由于 `lex` 生成的程序的默认行为是读取输入并将其复制到输出，最小的 `lex` 源程序具有 `%` 会生成一个仅仅将输入原封复制到输出的 C 程序。

可用四种特殊动作：`ECHO`；`REJECT`；`BEGIN`。

- 下一个规则的动作是当前规则的动作。与其他三个动作不同，你不能将其括在大括号中或用分号终止它。你必须在不包含其他动作的情况下指定它。
- `ECHO;` 将字符串 `yytext` 的内容写入输出。
- `REJECT;` 通常由 `a` 匹配单个表达式。
- `BEGIN;` 切换起始状态。

## lex 681

### `yylex(void)`

对输入进行词法分析；这是 `lex` 生成的主函数。当到达输入结束时，该函数返回 0；否则，它返回由动作确定的非零值（令牌）。

### `yymore(void)`

当调用时，表示识别下一次输入，并将其追加到 `yytext` 的当前值上，而不是替换它；调整 `yyeng` 的值。

### `yylless(int n)`

在 `yytext` 中保留前 `n` 个初始字符，并以空字符终止，将剩余字符视为未读入；调整 `yyeng` 的值。

### `input(void)`

从输入中返回下一个字符，在文件结束时返回 0。从流指针 `yyin` 获取输入，尽管可能通过中间缓冲区。一旦开始扫描，修改 `yyin` 值的影响是未定义的。

### `input(int c)`

将字符 `c` 返回输入；`yytext` 和 `yyyleng` 在匹配下一个表达式之前是未定义的。使用输入多于已输入字符的结果是不指定的。

### `yywrap(void)`

在文件结束时由 `yywrap` 调用；`yywrap` 默认返回 1。如果应用程序需要 `lex` 继续处理另一个源，应用程序可以包含 `yywrap`，将另一个文件与外部变量 `FILE *yyin` 关联并返回 0。

### `main(int argc, char *argv[])`

调用 `yylex` 执行词法分析，然后退出。用户代码可以包含 `main` 来执行特定操作，并根据需要调用 `yylex`。

## 使用

便携式应用程序注意：在“规则”（Rules）部分中，没有动作的正则表达式表达式（ERE）是不被允许的，但不需要被 `lex` 检测为错误。这可能导致编译或运行时错误。

输入的目的是从输入流中取出字符，并从词法分析的角度将其丢弃。一个常见的用途是在识别出注释开始后丢弃其主体。

`lex` 命令在处理 `lex` 源代码或生成的词法分析器中的正则表达式时，并未完全国际化。理想情况下，词法分析器应该根据执行分析器时指定的环境来解释 `lex` 源代码中提供的正则表达式，但在目前的 `lex` 技术下无法实现。此外，`lex` 生成的词法分析器的本质必须与所描述语言的词法需求密切相关；例如，编写一个用于法语文本的分析器对于处理其他语言并不会自动有用。

> 注意 — 如果 `.c` 文件中使用 `yyback()`、`yywrap()` 和 `yylock()` 的例要作为外部 C 函数，则编译 C++ 程序的命令行必须定义 `__EXTERN_C__` 宏，例如：

```c
gcc -D_EXTERN_C__... file
```
