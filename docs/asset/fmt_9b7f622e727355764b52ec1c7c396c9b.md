# io

`io` 模块实现了各种形式的 I/O 类，以及 Python 3 中使用的内置 `open()` 函数。该模块在 Python 2.6 中可用。

`io` 模块解决的核心问题是对不同形式 I/O 的无缝处理。例如，由于换行和编码的问题，处理文本与处理二进制略不同。为了处理这些差异，该模块构建了一系列层，每层都在在前层添加功能。

## 原始 I/O (Raw I/O)

I/O 系统的最低层涉及涉及原始字节的 I/O。其核心是 `FileIO`，它提供了对底层系统调用（如 `read()` 和 `write()`）的直接接口。

```
FileIO(name {, mode, closedef})
```

一个用于在文件或文件描述符上执行原始级 I/O 的类，文件描述符可以由 `os.open()` 函数或其他文件对象的 `fileno()` 方法返回。`mode` 是 'r'（默认）；'w' 或 'a' 分别用于读取、写入或追加。可以在模式中添加 'a+' 以进行更新，该模式同时支持读取和写入。`closed` 是一个标志，决定 `close()` 方法是否实际关闭底层文件。默认情况下，它是 True，但如果你正在使用 `FileIO` 封装一个已经打开的文件包装器，则可以为 False。如果给出了文件名，将直接使用操作系统的 `open()` 打开结果文件。没有内部缓冲，所有数据都以原始字节的形式处理。`FileIO` 的实例 `f` 具有之前描述的所有基础 I/O 操作：以下属性和方法：

| 属性 | 描述 |

| --- | --- |

| `f.closefd` | 标志，决定在 `f.close()` 时是否会关闭底层文件描述符（只读）。 |
| `f.mode` | 打开文件时使用的模式（只读）。 |
| `f.name` | 文件名（只读）。 |
| `f.read([size])` | 使用单次系统调用最多读取 `size` 字节。如果省略了 `size`，则使用 `f.read()` 返回尽可能多的数据。此操作返回的字节数可能比请求的要少，因此请使用 `len()` 进行检查。在非阻塞模式下，如果没有可用数据，则返回 None。 |
| `f.readall()` | 读取所有可用数据并作为字节字符串返回。在文件结束符 (EOF) 处返回空字符串。在非阻塞模式下，只读取立即返回的数据。 |
| `f.write(bytes)` | 使用单次系统调用将字节字符串或字节数组写入 `f`。返回实际写入的字节数——该值可能少于 `bytes` 中提供的字节数。 |

需要强调的是，`FileIO` 对象是非常底层的，它们在操作系统调用（如 `read()` 和 `write()`）之上提供了一个薄薄的层。具体来说，该对象的用户需要勤奋地检查返回码，因为无法保证 `f.read()` 或 `f.write()` 操作会读取或写入请求的所有数据。`f.tell` 方法可用于更改文件的低级特性，例如文件锁定、阻塞行为等。

`FileIO` 对象不应用于作为文本的行定向数据。虽然定义了如 `f.readline()` 和 `f.readlines()` 等方法；但这些方法来自基类，它们在 Python 中是通过使用 `f.read()` 每次读取一个字节的操作来实现的。无需多说，其性能非常糟糕。例如，在 `FileIO` 对象 `f` 上使用 `f.readline()` 的速度比在 Python 2.6 的 `open()` 函数创建的标准文件使用 `f.readline()` 慢 750 倍。
