
除了初始化应用程序外，运行时链接器还提供服务，通过映射额外的共享对象并绑定到它们的符号来扩展其地址空间。

运行时链接器执行以下功能：

- 分析应用程序的动态信息节（`.dynamic`）并确定需要哪些共享对象依赖项。
- 在这些依赖项中定位并映射，然后分析它们的动态信息节以确定是否需要额外的共享对象依赖项。
- 一旦定位并映射了共享对象依赖项，执行任何必要的重定位以绑定这些项，为执行做准备。
- 调用共享对象提供的任何初始化函数。默认情况下，按拓扑顺序调用。如果存在循环依赖，则使用消除循环的顺序进行调用。
- 将控制权传递给应用程序。
- 在应用程序执行期间，运行时链接器可以调用以执行任何延迟绑定。
- 删除共享对象时调用任何终结函数。默认情况下，按拓扑顺序调用。
- 应用程序还可以调用运行时链接器通过 `dlopen(3X)` 获取额外的共享对象并进行绑定。

### 668

可以在链接器与库指南中找到上述每个主题的详细信息。

运行时链接器使用指定的搜索路径来定位动态依赖项。默认搜索路径是对象中记录的运行路径，随后是 `/usr/lib`。当使用 `-R` 选项通过 `ld(1)` 构建动态对象时指定运行路径。你可以使用 `LD_LIBRARY_PATH` 指定在默认目录之前搜索的目录。

注意 - 用户兼容库 `/usr/lib/ld00.so.1` 提供了一种在位置建立值的机制。某些应用程序错误地假设空指针应该被视为空字符串。此类应用程序在访问空指针时会产生段错误。如果在运行时使用 `LD_PRELOAD` 将此库添加到应用程序，它提供了一个对这种行为的环境。该用户兼容库既不旨在此类应用程序的生成，也不支持这种特定的编程实践。

## 环境变量

- `LD_AUDIT` 指定冒号分隔的对象列表，这些对象由运行时链接器加载。每个对象加载后，检查其链接审计接口。存在的例将按照链接器与库指南中描述的链接审计接口调用。
- `LD_BIND_NOW` 通过将环境变量 `LD_BIND_NOW` 设置为任何非空值来覆盖运行时链接器的默认延迟绑定模式。通过此设置，运行时链接器将在进程初始化期间传递控制权给应用程序之前执行数据引用和函数引用重定位。也使用 `ld(1)` 的 `-z now` 选项。
- `LD_BREAD` 按反广度优先顺序调用任何初始化函数。按广度优先顺序调用任何终结函数。
- `LD_DEBUG` 指定逗号分隔的令牌列表，以便运行时链接器可以将调试信息打印到标准错误。`help` 特殊令牌指示可用的完整令牌列表。你还可以提供环境变量 `LD_DEBUG_OUTPUT` 来指定发送调试信息的文件。文件名将以生成调试信息的应用程序进程 ID 为后缀。

## ld.so.1

### `LD_LIBRARY_PATH`

增强运行时链接器用于查找动态依赖时使用的搜索路径。`LD_LIBRARY_PATH` 指定了一个由冒号分隔的目录列表，这些目录将在搜索默认目录之前被查找。另请注意，`LD_LIBRARY_PATH` 为 `ld(1)` 增加了语义。

### `LD_LIBRARY_PATH-64`

为 64 位依赖项覆盖 `LD_LIBRARY_PATH`。与环境变量 `LD_LIBRARY_PATH` 类似。

### `LD_LOADFLTR`

设置为非空值，则在过滤器被加载时立即处理它们。过滤器是共享对象的形式，它们允许在运行时选择备选的共享对象，并为过滤器中定义的任何符号提供实现。请参见 `ld(1)` 的 `-f` 和 `-F` 选项。默认情况下，备选共享处理直到对过滤器进行符号解析时才会进行。另参见 `ld(1)` 的 `-z loadfltr` 选项。

### `LD_NOAUXFLTR`

设置为非空值以禁用备选共享查找。辅助过滤器是共享对象的形式。它们允许在运行时选择备选的共享对象，并为过滤器中定义的任何符号提供实现。请参见 `ld(1)` 的 `-f` 选项。

### `LD_NOVERSION`

设置为非空值以禁用链接器版本检查。默认情况下，运行时链接器会验证主执行文件及其所有依赖项的依赖。

### `LD_ORIGIN`

通过将环境变量 `LD_ORIGIN` 设置为任何非空值，触发对 `$ORIGIN` 的立即处理。该变量对于在定位 `$ORIGIN` 字符串标记的依赖之前调用 `chdir(2)` 的应用程序非常有用。

### `LD_PRELOAD`

提供一个由空白分隔的共享对象列表，这些对象将由运行时链接器解释。指定的共享对象将在程序执行后、但在程序引用的其他共享对象之前链接。

### `LD_PROFILE`

定义一个由运行时链接器进行分析的共享对象。当启用分析时，会创建并生成分析缓冲区文件。缓冲区文件的名称为被分析的共享对象的名称并带有 `.profile` 后缀。默认情况下，此缓冲区放置在 `/var/tmp`。你也可以使用环境变量 `LD_PROFILE_OUTPUT` 指定用于放置分析缓冲器的替代目录。此缓冲区包含与 `cc(1)` 的 `-xpg` 选项链接的程序生成的 `gmon.out` 类似的信息。任何在使用命名共享对象且在此环境变量设置期间运行的应用程序都会累积在分析缓冲区中。你可以使用 `gprof(1)` 来检查分析缓冲区信息。注意，这种分析技术是编译系统可能提供的任何替代方案。被分析的共享对象不需要进行任何插桩，且 `LD_PROFILE` 不应与经过分析插的应用程序结合使用。

**注意** —— 以 `LD_` 字符开头的环境变量名留给 `ld` 和 `ld.so.1` 未来可能的增强。

## Security

为了防止恶意的依赖替换或符号拦截，对安全进程的依赖项评估可能适用某些限制。

如果用户不是超级用户且真实用户与有效用户 ID 不相等，或者真实组与有效组 ID 不相等，运行时链接器会将进程分类为安全。参见 `getuid(2)`, `getgid(2)` 和 `getegid(2)`。

如果安全进程生效了 `LD_LIBRARY_PATH` 环境，仅使用该变量指定的信任目录来增强运行时链接器的搜索规则。目前，运行时链接器唯一的信任目录是 `/usr/lib`，或 `/usr/lib/sparcv9` 64 位 SPARC V9 对象。

在安全进程中，应用程序或其任何依赖项提供的任何 run-path 均被使用，前提它们是全路径名；即路径以 `/` 开头。

你可以通过 `LD_PRELOAD` 环境变量为安全进程加载额外的对象，前提这些对象被指定为简单文件名且名称中不包含 `/`。这些对象根据之前描述的搜索路径定位。

## Files

- `/usr/lib/ld.so.1`: 默认运行时链接器。
- `/etc/lib/ld.so.1`: 替代运行时链接器。
- `/usr/lib/libc.so`: 用于 SVID ABI 性的替代解释器。
- `/usr/lib/ld.so`: AOUT(BCP) 运行时链接器。
- `/usr/lib/lib0.so.1`: 空字符指针兼容库。
- `/usr/lib/sparcv9/ld.so.1`: SPARC V9 架构的默认运行时链接器。
- `/usr/lib/sparcv9/@00@so.1`: SPARC V9 架构的空字符指针兼容库。

## let — 用于计算一个或多个算术表达式的 Shell 内建函数

### Synopsis

```ksh
let "arg"...
```

### Description

`ksh`

使用 `let` 命令根据一个或多个参数执行整数算术运算。每个参数可以包含常量、变量和算术表达式。表达式使用 shell 的算术规则进行求值。

如果参数是赋值，例如 `VAR=expression`，则表达式的结果将赋值给变量。如果参数不是赋值，则求值表达式并设置退出状态（真为0）。

### Examples

```bash
let x=1+2
let y=$x*3
echo $y
```

## lex — 为词法任务生成程序

### Synopsis

```
/usr/bin/lex [-c][-e][-w]][Q[y|n]] file
```

### Description

`lex` 命令从 lex 源生成符合 ISO 标准的 C 程序。通常，`lex` 将程序写入 `lex.yyc`；如果 `lex` 以非零状态退出，则该状态未知。

### Options

- `-c` 指定 C 语言（默认）。
- `-e` 生成处理 EUC 字符的程序（与 `-w` 选项配合）。`yytext` 为 unsigned char
- `-n` 抑制通常与 `-v` 输出的统计摘要。如果指定的表大小且未指定 `-v`，则隐含 `-n`。
- `-t` 将结果写入标准输出而不是 `lex.yyc`。
- `-Q[y|n]` 在标准错误上打印版本信息。使用 `-Qy` 输出版本信息。`-n` 选项不打印版本信息且是默认。
