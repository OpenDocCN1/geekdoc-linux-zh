
我在这里使用了10%，因为我所在地区的无线电接收效果特别差，大多数电台出现在12.5%左右。你将其重定向到文件，因为`fmscan`进程相当耗时，而且你可能希望稍后重新格式化数据。你可以用以下命令列出各种电台和频率：

```
cat fmstations | tr ^M \\n\\r | perl -lane 'print $_ if /\d:\s\d/'
```

或者按信号强度排序：

```
cat fmstations | tr ^M \\n\\r | perl -lane 'print $_ if /\d:\s\d/' | awk -F : '{ printf("%s %s\\n", $2, $1) }' | sort -r | head
```

在这两种情况下，`^M`符号是通过按`Ctrl+V`然后再按`Ctrl+M`输入的。

你会注意到，有些电台在列表中出现多次，例如88.4和88.6。只需挑选一个听起来最清晰的，或者核对一下电台呼号。

获得频率后，你就可以开始在网上搜索节目指南，寻找有趣的节目。这些节目必须从网页上抓取，而该网页是通过搜索电台自家网站找到的。像这样的搜索词：

```
radio 88.6 MHz uk
```

通常能返回不错的结果，前提是你把`uk`替换为你自己的国家。例如，你可以在`www.bbc.co.uk/programmes`找到BBC的主要电台。

还有一些预录的新闻报道以MP3格式提供，可以使用标准Linux工具下载或播放。下面是一个例子：

```
mplayer http://skyscape.sky.com/skynewsradio/RADIO/news.mp3
```

## CD数据

播放CD时，你通常希望保留两条信息：曲目名称和封面扫描图。前者更容易获取，并且已集成到大多数抓轨软件中，而后者则不然（尽管许多基于新媒体中心的软件正在加入这一功能）。

确定曲目名称的过程是：先确定CD上每首歌的起始位置和长度，然后通过哈希算法计算出一个“指纹”数字。由于市面上的每张CD歌曲数量不同，每首歌的长度也不同，这个数字应该是唯一的。（实际上，它几乎唯一，因为存在一些重复，但已经足够接近了。）然后将这个数字与已知专辑⁷数据库进行比较，以检索曲目名称列表，这些名称由世界各地的志愿者手动输入。然后，抓轨软件将这些曲目名称和标题添加到MP3或OGG文件的ID标签中，以供以后参考。

如果你使用的是CD本身，而不是抓取版本，那么每次想知道正在播放什么时，都必须手动检索这些信息。可以使用`cddb`包来部分解决这个问题，它允许你检索光盘的编号、名称、曲目及其时长。

```
cddb_tracks
```

上面的示例将产生如下开头的输出：

```text
Trying CDDB server http://www.freedb.org:80/cgi-bin/cddb.cgi
Connection established.
Retrieving information on 2f107813.
CDDB query error: cannot parse album name:
Total tracks: 19        Disc length:    70:18
```

| 曲目 | 长度 | 标题 |

|-------|--------|-------|

| 1: | [ 3:52.70] | |

| 2: | [ 3:48.53] | |

| 3: | [ 3:02.07] | |

| 4: | [ 4:09.60] | |

| 5: | [ 3:55.00] | |

虽然这可以让你看到当前曲目（由`>`指示），但它并不比任何其他媒体播放器提供的信息更有用。然而，如果你已经安装了`abcde`抓轨器，那么你也会（自动地）安装`cddb-tool`组件，它会为你执行CD哈希功能和数据库查询。因此，你可以用少量脚本代码确定光盘ID、其名称以及每个曲目的名称：

```sh
ID=`cd-discid /dev/dvd`
TITLE=`cddb-tool query http://freedb.freedb.org/~cddb/cddb.cgi 6 $app $host $ID`
```

`app`和`host`参数指的是当前机器的应用程序名称和主机名。虽然它们的内容被认为是必填的，但并非至关重要，只是出于对开发人员的礼貌而包含，以便他们可以跟踪哪些应用程序在使用数据库。魔术数字`6`指的是所使用的协议。从这个字符串中，你可以提取流派：

```sh
GENRE=`echo $TITLE | cut -d ' ' -f 2`
```

以及光盘的ID和名称：

```bash
DISC_ID=`echo $TITLE | cut -d ' ' -f 3`
DISC_TITLE=`echo $TITLE | cut -d ' ' -f 4-`
```

使用光盘ID和类型，你可以确定所讨论光盘的唯一轨道列表（因为类型用于区分哈希编号中的冲突），从而可以检索可解析的轨道列表：

```bash
cddb-tool read http://freedb.freedb.org/~cddb/cddb.cgi 6 $(app) $(host) $GENRE $DISC_ID
```

从该输出中还可以获得光盘标题、年份和真实流派。[^8]

更复杂的一种数据检索是专辑封面图像。这是抓轨工具（尤其是基于文本的工具）不会去做的事情，在开源世界中也是一件成败难料的事。这同样是因为缺乏可用的数据源。苹果经营着一家音乐商店，在那里封面被用来销售音乐，并在购买专辑时随之下载。如果你自己抓取音乐，就没有这样的选择。

一个可以提供帮助的图形工具是`albumart`。你可以从[www.unrealvoodoo.org/hiteck/projects/albumart](http://www.unrealvoodoo.org/hiteck/projects/albumart)下载该软件包，并用以下命令安装：

```bash
dpkg -i albumart_1.6.6-1_all.deb
```

它利用MP3文件内的ID标签在多个网站上执行搜索，例如[Buy.com](http://Buy.com)、[Walmart.com](http://Walmart.com)和Yahoo! 这种方法不过是屏幕抓取，但只要文件命名得当，结果就足够好，并且很少出现误报。然而，当它无法确定正确的图像时，它会采取谨慎态度，不分配任何图像，等待你手动点击“Set as Cover”，这可能需要一些时间来修正。一旦它抓取了封面文件，就会在相应目录中将其命名为`folder.jpg`，大多数操作系统和媒体播放器会识别并使用该文件。但额外的好处是，由于`albumart`软件包使用文件中的ID标签（而不是CD指纹），它可以用来查找你已经抓取过的音乐的封面图像。

> **注意** 与轨道列表不同，封面艺术仍然是受版权保护的材料，因此没有独立开发者尝试用自己的数据库来简化这一过程。

在没有ID或元数据的情况下正确定位专辑封面可能非常困难。如果出现这种情况，可以采用两阶段流程。第一部分涉及通过查看歌曲的音频属性来确定标签，从而确定标题和艺术家。`MusicBrainz`是这个领域的主要（免费）竞争者。然后，一旦你有了ID标签，就可以正常检索图像。这些步骤已合并到`Jaikoz`等软件中，它同时也是一个批量元数据编辑软件包，对于那些已经抓取了音乐但缺乏此类数据的人来说可能有用。

## 新闻

任何变化的数据都是新的，因此也就是新闻，使其成为实时访问的理想对象。大多数聚合器通过RSS源和自定义小工具来制作个性化新闻频道。例如，即将退役的`iGoogle`（`www.google.com/ig`）还整合了谷歌邮件和日历服务，使其作为主页时成为一个好用到令人不安的页面，但其封闭的特性使其难以作为家庭的数据输入来使用。相反，我将介绍如何将典型新闻条目作为独立数据元素来检索，并以适合我们的方式加以整合。这分为两种类型：推送（push）和拉取（pull）。

### 报道故事：推送

推送式媒体的引入可以追溯到24小时滚动新闻（1961年由阿瑟·W·阿伦德尔提出），也可以追溯到RSS源，取决于你的视角。这两种形式似乎都在收到信息后立即实时推送给观众。实际上，这两种方式都是让观众不断从数据流中拉取数据，并默默忽略未发生变化的内容。就电视而言，每次拉取包含一帧新图像，每秒钟发生数次。RSS拉取的频率要低得多，但这里感兴趣的是RSS。

### RSS源

`RSS`[^1]是一种基于XML的元数据文件格式。它描述大量频繁更新的信息。这些信息可能包括博客文章的引用、从国王十字车站9¾站台出发的下一班列车、新闻网站上的当前报道等。在每种情况下，每一次更改都会记录在RSS文件中，并附上至关重要的时间戳，使RSS阅读器能够判断其中提到的数据是否有更新。生成这些RSS源的软件也可能会在以前的报道变得无关紧要或过于陈旧时移除对它们的引用。然而，“陈旧”是由作者定义的。

这一事实标准允许你使用通用库来解析RSS源并相当简单地提取信息。其中一个库是基于PHP的`MagpieRSS`（http://magpierss.sourceforge.net），它还支持一种名为`Atom feeds`的RSS替代方案，并内置了数据缓存。这第二个功能使你的代码更简单，因为你可以重复使用RSS源中的所有数据，而无需担心最新内容，因为该库已经自动缓存了较早的报道。
