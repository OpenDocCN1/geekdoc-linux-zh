## 创建新群组

这个问题经常出现。“嘿，没有讨论独立兔子（indie feebles）的组！我该如何创建一个？

在这种情况下，我们双重建议在创建自己的群组之前，关注 `news.announce.newgroups` 和 `news.groups` 三个月。这似乎很极端，但这是一个完全不同的政治层面、成文和不成文的规则以及潜规则。

你可能完全认真地对待 USENET，也可能将其视为恶作剧游乐场。大多数人介于两者之间，但有许多人倾向于后者。

如果你看到某些看起来很反常的东西，它很可能确实如此。检查新闻组（Newsgroups）的头部行并查看交叉点——如果它发布在一个奇特的群组里，很有可能有人在开玩笑。如果你发布了激烈的回复，你只会让自己显得很愚蠢。

## Talk

Talk 是一个允许两个用户使用分屏界面进行实时通信的程序。用户在分屏的一个区域输入字与另一个用户“交谈”，并在另一个用户的文本出现在屏幕另一个区域时进行“倾听”。它可以用于同一系统上的用户，也可以通过 TCP/IP 网络使用。

在启动 talk 会话之前，你需要对方的地址。如果用户与你连接到同一本地机器，只需登录名就足够。

接下来，你需要确保另一个用户已登录。你可以通过 `finger` 命令查明。例如：

```
$ finger userid
leibnitz 24: finger tremble
Login name: tremble In real life: Frederick Trimble
Directory:/users/leibnitz/INFO780-543/leibnitz Shell: /bin/csh
On since Apr 28 00:21:37 on pty/tty0 from ts2.noc.drexel.e
```

```
$ No Plan.
$
```

在上面的示例中，`finger` 命令指示用户 `tremble` 已登录在系统的伪终端 `ttys0` 上。`finger` 命令也可以通过指定远程地址来确定远程用户是否登录。例如：

```
finger userid@domain
```

在你确认了你想要交谈的用户已登录后，他必须同意与你交谈。要启动 talk 会话，首先执行 `talk` 命令：

```
talk userid@domain
```

在 talk 发起者的屏幕上，屏幕将清空，talk 头部将出现在屏幕顶部：

[Waiting for connection...]

在另一个屏幕上，将出现以下文本：

```
talk: connection requested by username@host
talk: respond with: ntalk username@host
```

在用户用适当的消息回复后，连接就会建立。此后输入的所有内容将显示在另一个终端上，直到连接终止。当其中一个用户按下 `control-c` 时，talk 会话终止。

在某些情况下，接收 talk 连接请求可能会干扰工作。你可以使用以下命令禁用任何来自远程用户的此类请求：

```
mesg n
```

要启用此类请求，使用带有 `y` 选项的 mesg 命令：

```
mesg y
```

要查看当前 talk 请求模式的状态，请使用不带选项的 mesg 命令。

talk 命令基于一组允许通信发生的协议。talk 命令有两个协议：其中一个基于版本 4.2 BSD UNIX，另一个基于版本 4.3 BSD UNIX。遗憾的是，这些版本是不兼容的。因此，你无法在基于不同版本协议 UNIX 系统之间建立 talk 会话。

talk 命令的另一个变体是 `ytalk` 命令。ytalk 最感兴趣的特性是它允许两个以上的用户参与对话。此外，它同时支持两个版本的 talk 协议。因此，`ytalk` 命令可以与任何版本的 talk 命令建立连接。

要建立与多个用户的 ytalk 会话，请在命令行上输入每个用户的地址。例如：

```
ytalk mary@gwyned.edu fred@drexel.edu katherine@nova.edu
```

talk 命令将会话分成几个面板。每个屏幕都标记有相应的用户，因此你知道是谁在输入。

如果你需要任何 ytalk 选项的帮助，按下 ESC 键。会出现如下的 ytalk 命令小菜单：

```
################################################
# a) 向会话添加新用户 #
# b) 从会话中删除用户 #
# c) 将用户输出到文件 #
## 你的选择: #
################################################
```

> 提示：与真实对话相比，打字很慢，看着对方退格删除拼错的单词可能很烦恼。如果你觉得对方应该理解拼错单词的意图，那么在拼写错误后继续输入被认为是可以的。此外，经验丰富的用户缩写常用短语也并不罕见。以下是一些缩写列表：

- BCNU Be seeing
- BRB Be right back
- BTW By the way
- BYE Good-bye
- CU See you
- CUL See later
- FYI for information
- FWIW For its worth
- GA Go ahead
- IMHO In my opinion
- IMO In my opinion
- JAM Just a minute
- O Over
- OBTW Oh, the way
- ROTFL Rolling on the floor
- R U Are there

- WRT With respect

## 网络聊天 (IRC)

每天都有全球范围内成千上万的人使用网络聊天（IRC）进行“键盘对话”。就像 ytalk 功能一样，它允许多人同时交谈。当你在聊天时，字符将出现在所有登录该频道的用户那里。

> 注意：1993年俄罗斯发生尝试性政变期间，建立了一个 IRC 频道用于转发。

### 基础结构

IRC 使用客户端-服务器模型。IRC 频道名称类似于 `#game`。此外， IRC 用户拥有昵称并与其关联（你的昵称随其）。

### 获取 IRC 客户端

在进行任何操作之前，你需要一个 IRC 客户端。你可以指向 `ftp/cs-bu.edu` 获取 UNIX 客户端。软件位于目录下。

运行在 MS-DOS、OS/2 或 Windows 下的 PC 客户端访问 `ftp/cs-bu.edu` 并查看 `/irc/pc`。MIRC 现在是 Windows 环境下流行的客户端。

Mac 客户端也可以访问 `ftp/cs-bu.edu` 并查看 `/irc/mac`。

### 连接到服务器

一旦你有了客户端，你需要确定要与哪个 IRC 服务器连接。匿名访问 `cs.edu` 并查看 `/irc/support`。应该有一个名为 `servers.95301` 的文件（最后的数字是日期，所以那部分会变化）。

让你的客户端连接到这个服务器。运气好的，它会回复你并进入 IRC 世界。

### 选择频道

一旦你进入 IRC 服务器，所有命令都以 `/` 开头。

`/help` 显示命令列表。要获取新手帮助，执行 `/help intro` 然后 `/help newUser`。

`/list` 显示所有 IRC 频道。看起来像这样，只不过会有多得多的：

| *** | 用户 | 主题 |
| :--- | :--- | :--- |
| #wubba | 3 | Wherefore the wabba |
| #hoffa | 5 | i know where the body is |
| #litldog | 2 | oh where he has gone |

`/names` 显示感兴趣的内容。它显示每个频道上的登录用户以及该频道是私有还是公共：

```
Pub: #wubba @wubba jblow jdoe
Prv: * marla donald ivana bill hillary
Pub: #litldog @yakko dot
```

然后使用 `/join 频道` 加入频道。在这里你可能会执行 `/join 昵称 #wubba`。

`/nick 昵称` 允许你更改昵称改为新的或任何太蠢的名字。

`/msg 昵称 消息` 允许向昵称发送私信。使用 `/query 昵称` 与昵称进入私聊。使用 `/query` 退出。

如果你有雄心勃勃并想要创建一个频道（在不存在的频道上使用 `/join` 即可创建），请务必查看 `/mode` 命令，它可以让你决定频道的行为。

### 需要帮助？

`/join #Twilight_zone` 是 IRC 操作员聚集的地方，他们有些人乐意提供帮助。直接提问你的问题——不要先宣布你需要提问问题。

### 错误操作

如果可能，不要使用他人的昵称——人们对自己的昵称非常保护。

如果你不确定某人问你的问题是什么意思，千万不要回答。你可能会发现自己刚刚把客户端的控制权交给了别人！

不要滥用 telnet 服务器。如果你打算经常使用 IRC，请获取你自己的客户端。

### 更多信息

可以通过 `ftp://cs-ftp.bu.edu` 的 `/irc/support` 目录通过匿名 ftp 找到更多关于 IRC 的信息。IRC 还有几个专门设立的小组：`alt.irc.corruption`、`alt.irc.ircii`、`alt.irc.lamers`、`alt.irc.opers`、`alt.questions`、`alt.irc.recovery` 和 `alt.irc.undert`。

# 多媒体

多媒体被定义为同时使用一种以上媒介进行信息呈现的方式。除了文本外，使用动画和声音就是一个例子。通过使用一种以上的媒介，多媒体增强了我们交流和理解彼此的能力。配备了高分辨率显示器和扬声器的强大桌面电脑的出现增加了这种需求。

# 互联网基础设施

在互联网上传输多媒体面临着若干障碍。首先，互联网及其协议的设计是为了传输 7 位 ASCII 文本，以支持电子邮件和文件传输。最初的 NSFBNET 由 56K 数据通信线组成（互联网骨干网近年来已通过更高的网络速度进行了升级）。尽管这是为了其支持电子邮件和文件传输的原始初衷，但它不足以支持日益增长的多媒体需求。

文件包含大量空间。当文件跨越网络传输时，它们需要大量的网络带宽。当路由器处理数据包时，它并不了解数据流。它只处理单个数据包并对其进行单独处理。当使用 IP 等无连接协议跨越网络传输时，单个数据包可能会乱序到达。TCP 协议负责在数据包提供给应用程序之前对其进行重组。IP 协议中没有优先级信息可以使实时数据优于其他低优先级的数据类型。这种协议是为了支持如电子邮件和基于文本的会话等应用设计的。然而，对于对延迟敏感的数据包（如实时音频和视频），这是可以接受的。因此，为了支持大规模多媒体，互联网基础设施需要进行根本性的改变，包括数据通信线、路由器和协议。

MIME 还记得那种在互联网上发送二进制数据（如图形或声音）的技巧吗？在发送到互联网之前，它使用 `uuencode` 转换为 ASCII 字符。虽然这种技术在大多数时候是有效的，但在某些情况下可能会失败。例如，已知在 EBCDIC 和 ASCII 字符格式之间转换的邮件网关会修改 `uuencode` 格式中的某些字符。虽然大多数 `uuencode` 版本是可以交叉的，但并没有明确的标准。正如之前提到的，电子邮件标头在传输过程中会被 MUA 和 MTA 修改。偶尔，标头的修改可能会损坏已编码的内容。MIME 规范在某些方面更健壮，因为它能更好地生存标头的修改。

开发出了一种名为 MIME（多用途互联网邮件扩展）的规范，以增强电子邮件的多媒体能力。MIME 有效地扩展了电子邮件的能力，包括：

- 邮件消息中的多个对象
- 无限制长度的文本
- 除 7 位 ASCII 外的字符集
- 多字体消息
- 图像、音频和视频数据
- 二进制文件

Mime 使用名为 `base64` 的技术处理加密。这种编码方案旨在用 65 个字符的 ASCII 字符集（A-Z、a-z、0-9、`+/` 和 `=`）来表示任意字节序列。

大多数邮件程序（包括 Eudora、elm 和 mh）都是感知 MIME 的。大多数邮件程序都会为你执行加密/解密。如果你收到 MIME 格式的消息但使用的不是感知 MIME 的邮件程序，你可以使用 `munpack` 工具对其进行解码。如果你想向拥有感知 MIME 邮件程序的人发送消息，你可以使用 `mpack` 工具对其进行编码。这两个工具都可以在互联网上的多个平台上免费获取。可以通过 `ftp.andrew.cmu.edu` 的 `/pub/mail` 目录通过匿名 ftp 获取。请注意，如果你必须自己导入 MIME 数据，你将负责提取邮件的正确部分，例如，使用文本编辑器完成此操作。

如需了解更多信息，请查阅 Usenet 小组 `comp.mail.mime`。FAQ 列表是一个极佳的起点。MIME 的详细规范可以在 RFC 1521 中找到。

> 注意：尽管 MIME 能够在传输过程中保持数据的完整性，但它从未旨在为了平台间的兼容性而翻译数据。例如，Amiga 上的项目符号的非标准 ASCII 字符与 Macintosh 上是不同的。意识到你发送数据的目标系统是非常重要的。

在互联网上传输多媒体。如前所述，当前的互联网基础设施不足以支持多媒体。本节研究了更新基础设施以传输大规模多媒体的两种尝试。

RTP/RSVP IP 协议的无连接特性并不适用于携带实时音频和视频的数据包所需的时间敏感性。实时传输协议（RTP）和资源预留协议（RSVP）目前由 IETF（互联网工程任务组）开发，以使多媒体成为现实。RSVP 的初始规范定义了四种服务质量（QoS）：

- 保证延迟
- 延迟
- 预测服务
- 负载

虽然这些 QoS 处理数据包的优先级不同，但它们都增加了网络的确定性。从本质上说，预留定义了网络与应用程序之间的约。多媒体应用将使用兼容 socket 的编程接口（API）访问这些协议。更改 API 以支持新功能并非易事。

## 多媒体骨干网

如前所述，互联网骨干网由高速通信线组成。许多实验正在寻找升级硬件以支持传输实时音频和视频的方法。其中一种实验被称为多媒体骨干网（MBONE）。MBONE 并不独立于互联网，它是具有强大主机和高速连接的互联网站点。

遗憾的是，MBONE 只能处理每秒五帧的显示。而动态视频需要每秒三帧。它的潜力虽然不是广播级，但对于许多实用应用来说已经足够。如需更多信息，你可以访问 `http://www.mbone.com` 网站。

> 注意：1996年7月20日，国家科学基金会和 NASA 在 MBONE 上举办了一场直播。该演示为了纪念火星着陆二十周年。

## 互联网音频

目前互联网上处理音频有两种方法。第一种技术需要将音频文件传输到工作站，然后由相应的音频播放器处理。第二种技术不需要在传输完整文件之前即可开始播放。

音频文件传输互联网上有许多各种格式的声音文件。每种格式都有唯一的扩展名，例如 `.wav` 或 `.au`。以下列表显示了你可能会看到的文件扩展及其关联平台：

| 文件扩展 | 平台 |
|---|---|
| AU | UNIX |
| SND | Macintosh |
| WAV | PC |
| AIF, AIFF | Macintosh |

# RA (Real Audio) Macintosh, PC, UNIX

每种文件类型都需要特殊的“播放器”实用程序。在大多数情况下，这些实用程序可以配置为与常用的浏览器配合工作，这样在浏览器中引用时就可以自动播放。这些在 Web 术语中被称为“助手”应用程序。

然而，这种技术的主要的缺点是传输文件所需的时间。即使文件没有经过压缩，但它们仍然很大。

**流媒体音频** 开发名为流媒体音频的技术是为了提高普通文件传输方法的性能。这种方法允许在文件传输的同时进行播放。要利用这种技术，你必须使用音频文件以及支持流媒体音频的播放器应用程序。今天流行的流媒体技术是 RealAudio。

在音频播放期间，音频服务器和音频播放器交换有关连接的信息。如果是低速连接，则发送较小版本的文件；如果是高速连接，则将使用更大、质量更高的的文件。

为了减少在互联网上传输数据的时间，文件被压缩。用户数据报协议 (UDP) 配合 IP 协议传输数据包。与 TCP 不同，如果传输过程中出现问题，UDP 不重置数据包。如果是这样，音频播放器将由于频繁的中断而无法播放文件。
