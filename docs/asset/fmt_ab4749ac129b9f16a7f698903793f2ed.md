
这就是为什么我们费了巨大精力来描述打印子系统的概念基础。理解数据如何从应用程序通过 `lpr` 到达 `lp1`，通过 `/etc/printcap` 中指定的任何过滤器，最后到达设备至关重要。人们可以手动走一遍整个过程，以发现任何故障发生的位置。

与任何 Linux 客户端/服务器子系统一样，`syslog` 对于排查打印问题很有用。`lp` 守护进程报告的任何错误可能出现在 `/var/log/messages` 中。一旦开始排障之旅，请选择一个理想的虚拟控制台或在打印服务器上打开一个带有 `shell` 会话的额外 `xterm`（以及任何一个受网络影响的客户端系统），并执行如下命令：

```
tail -f /var/log/messages
```

随后就可以监控发生的错误消息和警告。`lpd` 守护进程可能需要使用 `-l`（日志）选项重启。此外，可以使用如下命令将跟踪信息附加到运行的 `lpd` 进程上：

```
trace -p 132
```

其中 `132` 是 `lpd` 守护进程的假设 `PID`（进程标识符）。遗憾的是，`lpd` 的错误消息通常非常晦涩且通常没有帮助。

花费精力精通配置和排查打印系统的系统管理员在大多数组织中都是不可或缺的。当系统正常工作时，它运行良好且往往很可靠。当它出现故障时，它是系统管理员面临的最令人沮丧和困难的问题之一。

## Windows 打印机 (Winprinters)

到目前为止，这一层打印问题最糟糕且最常见的原因是臭名昭著的 `winprinters` 或 Microsoft Windows GDI 驱动型。

普通打印机使用自己的 `CPU` 和一些用于存储字体、执行某些操作并作为缓冲区内存。20世纪90年代中期，几家公司开始生产由主机计算机极低级指令驱动的打印机。这要求在主机系统上运行其专有的驱动程序，而这些驱动程序通常仅供 Microsoft Windows 使用。这些打印机无法被任何其他系统——即使是 `MS-DOS` 系统。自然，这些打印机的价格比它们的“真实”亲戚低，并且作为低端外设非常受欢迎。

`Winprinters` 不适用于多用户系统。即使有适用于 `LINUX` 的驱动程序，`CPU` 的计算开销以及这些设备的时间和延迟要求使其成为业务用途的非常糟糕的选择。问题在于，目前没有这些它们的可用驱动程序，而且在历史上，与对开发此类驱动程序表示兴趣的开源程序员，以及提供必要规范和文档的制造商之间存在着不利的关系。

在 `Printing HOWTO` 中，有关于使用特殊过滤器支持 GDI 和 PPA 打印机的说明。`HOWTO` 还有一个部分提供了指向支持的打印机列表和数据库的链接。

## 传真 229

关于 `LINUX` 支持的任何硬件问题，请另参阅 `LINUX Hardware Compatibility HOWTO`<sup>1</sup>。如果对某个设备是否为“`winprinter`”有任何怀疑，最好的测试是在 `MS-DOS` 下启动系统（或将设备连接到 `PC`）并尝试使用旧的打印键，或如下命令：

```
COPY AUTOEXEC.BAT PRN
```

如果不起作用，且打印机已电源并处于“就绪”，且与计算机之间的电缆良好，那么它几乎肯定是一个“`winprinter`”。退货并买一台“真实的”打印机吧。

## 传真

大多数现代调制解调器都能发送和接收传真。使用流行的 `mgetty` 包，Linux 可以通过此类调制解调器接收传真，并区分接入传真、数据和其他通话。通过一些配置，单个调制解调器可以配置为拨入 `shell`、网络和接入传真——甚至是某些调制解调器的 `DTMF` 远程控制。

`mgetty` 包包含 `sendfax` 程序和一组管理入出传真的实用工具。许多与传真系统管理的过滤和格式转换问题仍然需要物理设备和接口（一种是打印机，另一种是调制解调器）将各种文件格式转换为适用于设备的格式。传真的“通用”格式是 `TIFF`（标记图像文件格式）。它统治传真世界的程度超过 `PostScript` 在打印机上的普及。

遗憾的是，Linux Documentation Project 对传真主题提供不多。有一份 Linux 简单打印服务器 `mini-HOWTO`<sup>1</sup>描述了非常简单的传真配置。大多数情况下，系统管理员应该依靠其所选传真包包含的文档，传真相当小且轻量。`mgetty` 更复杂，但它大部分是为了管理其他类型的接入通话。`Hylafax` 是一个大型复杂的专业系统。然而，它的网站包含详尽的文档。它是大多数企业的免费传真系统之选。

有很多用于查看和打印接入传真的工具。特别是，这里有针对 `KDE` 和 `GNOME` 的非常好程序，它们为传真系统提供了良好的界面。这些程序变化非常快，寻找它们的最佳方法是：

同一台调制解调器可以用于出站终端仿真、`PPP` 和/或 `SLIPIP` 网络、发送传真，并支持其他协议。

通过其他网络设施，将 `LINUX` 系统配置为各种协议之间的网关相对容易的——这允许我们配置神奇的“邮件地址”和 `lpd` 队列，将传真发送到我们的调制解调器。

## 使用 NFS

网络文件系统（`THE NETWORK FILE SYSTEM`）是创建跨网络共享的文件系统层次结构的构建块集合。在 `LINUX` 中，所有文件都显示为从 `/` 目录（也称为根目录）下的单一树形结构。`mount` 命令用于将文件系统挂载到此树上。`NFS` 客户端使用 `automounter` 或 `/etc/fstab` 中的条目来指定要挂载的文件系统，从而挂载由一个或多个 `NFS` 服务器提供的文件系统。`NFS` 服务器为本地挂载在服务器上的文件系统提供 `NFS`。`/etc/exports` 文件指定要导出的文件系统以及应用于它们的访问控制。访问 `NFS` 挂载的文件系统对用户和进程是透明的。从用户的角度来看，`NFS` 文件系统的表现与本地挂载的文件具有相同的语义和行为。

## NFS 基础

在最简单的情况下，使用 `NFS` 只需要五件事。在服务器上，将要导出的文件系统添加到 `/etc/exports` 文件，并使用 `/etc/rc.d/init.d/nfs start` 命令启动 `NFS`。在客户端，在 `/etc/fstab` 中指定要挂载的文件系统及其要挂载的目录。文件结构记录在 `exports(5)` 和 `fstab(5)` 手页中。有大量的 `NFS` 挂载选项，默认值适用于大多数情况。

如果只需要临时使用某个文件系统，可以直接使用 `mount` 命令，跳过 `fstab` 文件。以这种方式挂载的文件系统在客户端后续重启期间不会被挂载。

## 使用自动挂载器管理 NFS 挂载

在规模较小时，系统管理员通常会开始使用 `fstab` 方法挂载几个文件系统。这种技术变得繁琐，而自动挂载器就成为管理 `NFS` 挂载的首选机制。
