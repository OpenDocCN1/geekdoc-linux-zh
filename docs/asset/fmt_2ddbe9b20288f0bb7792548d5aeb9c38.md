
## make 选项

| `'-d'` | 除正常处理外，打印调试信息。调试信息会显示哪些文件正在被考虑重新制作、正在比较哪些文件时间以及结果如何、哪些文件实际上需要重新制作、考虑并应用了哪些隐式规则——关于 `make` 决定如何操作的一切信息。`-d` 选项等同于 `'--debug=a'`（见下文）。 |
| `'--debug=[options]'` | 除正常处理外，打印调试信息。可以选择不同的输出级别和类型。在不带参数时，打印“基础”级调试。可能的参数如下；仅考虑第一个字符，且值必须用逗号或空格分隔。 |
| `a (all)` | 启用所有类型的调试输出。这等同于使用 `'-d'`。 |
| `b (basic)` | 基础调试打印每个被发现过期的目标，以及构建是否成功。 |
| `v (verbose)` | 级别高于 `'basic'`；包含关于解析了哪些 Makefile、不需要重新构建的依赖项等信息。此选项也会启用‘basic’消息。 |
| `i (implicit)` | 打印描述每个目标隐式规则搜索的消息。此选项也会启用‘basic’消息。 |
| `j (jobs)` | 打印提供调用特定子命令详细信息的消息。 |
| `m (makefile)` | 默认情况下，在尝试重新制作 Makefile 时不会启用上述消息。此选项在重新构建 Makefile 时也会启用消息。注意 `'all'` 选项会启用此选项。此选项也会启用‘basic’消息。 |
| `-e`, `--environment-overrides` | 使从环境中获取的变量优先于 Makefile 中的变量。参见第 6.9 节 [环境中的变量]，第 66 页。 |
| `-f file`, `--file=file`, `--makefile=file` | 读取名为 `file` 的文件作为 Makefile。参见第 3 章 [编写 Makefile]，第 11 页。 |
| `-h`, `--help` | 提示你 `make` 识别的选项并退出。 |
| `-i`, `--ignore-errors` |  |
| `-I dir`, `--include-dir=dir` | 指定一个搜索包含的 Makefile 的目录。参见第 3.3 节 [包含其他 Makefile]，第 12 页。如果使用多个 `'-I'` 选项指定多个目录，将按指定的顺序搜索这些目录。 |
| `-j [jobs]`, `--jobs=[jobs]` | 指定同时运行的作业（命令）数量。如果不带参数，`make` 将尽可能同时运行多个作业。如果有多个 `'-j'` 选项，则最后一个有效。有关命令如何运行的更多信息，请参见第 5.3 节 [并行执行]，第 43 页。注意此选项在 MS-DOS 上会被忽略。 |
| `-k`, `--keep-going` | 错误后尽可能继续。虽然目标失败且依赖于它的目标无法重新制作，但这些目标的所有其他依赖项仍然可以被处理。参见第 9.6 节 [测试程序的编译]，第 94 页。 |
| `-1 [load]`, `--load-average=[load]`, `--max-load=[load]` | 指定如果有其他作业正在运行且平均负载至少为 `load`（一个浮点数），则不启动新作业（命令）。如果不带参数，则移除之前的负载限制。参见第 5.3 节 [并行执行]，第 43 页。 |
| `-n`, `--dry-print`, `--dry-run`, `--recon` | 打印将执行的命令，但不执行它们。参见第 9.3 节 [代替执行命令]，第 91 页。 |
| `-o file`, `--old-file=file`, `--assume-old-file` | 即使文件比其依赖项旧也不重新制作该文件，并且由于文件的更改而不重新制作任何内容。本质上，该文件被视为非常旧且其规则被忽略。参见第 9.4 节 [避免重新编译某些文件]，第 93 页。 |
| `-p`, `--print-data_base` | 读取 Makefile 后生成的数据库（规则和变量值）；然后按照通常或另指定的的方式执行。这还会打印由 `'-v'` 开关提供的版本信息（见下文）。要在不尝试重新制作任何文件的情况下打印数据库，请使用 `make -qp`。要打印定义的规则和变量的数据库，使用 `make -p f /dev/null`。数据库包含命令和变量定义的文件和行号信息，因此在复杂环境中它可以是一个非常有用的调试工具。 |
| `-q`, `--question` | “查询模式”。不运行任何命令；如果任何目标是最新的或遇到错误，则返回零状态码。 |
| `-r`, `--no-builtin-rules` | 消除对内置规则的使用（参见第 10 节 [隐式规则]，第 101 页）。你仍然可以定义自己的规则。 |
| `-R`, `--no-builtin-variables` | 消除对内置变量的使用（参见第 10 节 [隐式规则]，第 106 页）。你仍然可以定义自己的变量。 |
| `-s`, `--silent`, `--quiet` | 操作；执行命令时不打印它们。参见第 5.1 节 [命令回]，第 41 页。 |
| `-S`, `--no-keep-going`, `--stop` | 取消 `'-k'` 选项的影响。除非在递归 `make` 通过 `MAKEFLAGS` 继承 `'-k'`（参见第 5.6 节 [make 的递归使用]，第 46 页）或你在环境中设置了 `'-k'`，否则没有必要。 |
| `-t`, `--touch` | 触摸文件（标记它们为新的但不真正更改它们）而不是运行它们的命令。这用于伪装命令已经执行。参见第 9.3 节 [代替执行命令]，第 91 页。 |
| `-v`, `--version` | 打印 `make` 程序的版本以及版权信息、作者列表和无保修声明；然后退出。 |
| `-w`, `--print-directory` | 在执行 Makefile 之前和之后打印包含工作目录的消息。这对于追踪复杂的递归 `make` 命令中的错误可能有用。参见第 5.6 节 [make 的递归使用]，第 46 页。（在实践中，你很少需要指定此选项，因为 ‘make’ 会为你完成；参见第 5.6.4 节 [打印目录选项]，第 51 页。） |
| `--no-print-directory` | 禁用 `-w` 下的工作目录打印。当 `-w` 自动开启但你不想看到额外消息时，此选项有用。参见第 5.6.4 节 [不打印目录选项]，第 51 页。 |
| `-W file`, `--what-if=file`, `--new-file=file` | 伪装目标文件刚刚修改过。与 ‘n’ 标志一起使用时，它可以显示如果你修改该文件会发生什么。如果不带 ‘n’，它几乎等同于运行 `make` 之前对给定文件运行 `touch` 命令，只是修改时间仅在 `make` 的想象中改变了。参见第 9.3 节 [代替执行命令]，第 91 页。 |
| `warn-undefined-variables` | 每当 `make` 看到未定义变量的引用时都会发出警告消息。当你尝试调试以复杂方式使用变量的 Makefile 时，这非常有帮助。 |

# 10 使用隐式规则

某些生成目标文件的标准方法被频繁使用。例如，生成目标文件的一种习惯方法是使用 C 编译器 `cc` 从 C 源文件生成。

隐式规则告诉了你如何使用常规技术，这样当你想要使用它们时，就不需要详细指定它们。例如，存在一条 C 编译的隐式规则。文件名决定了运行哪些规则。例如，C 编译通常读取一个 `'.c'` 文件并生成一个 `'.o'` 文件。因此，当 `make` 看到这种文件后缀组合时，它就会应用 C 编译的隐式规则。

隐式规则链可以顺序应用；例如，`make` 会通过 `'.c'` 文件从 `'.y'` 文件重新生成 `'.o'` 文件。参见第 10.4 节 [隐式规则链]，第 108 页。

内置隐式规则在命令中使用了几个变量，因此通过更改变量的值，你可以改变隐式规则的工作方式。例如，变量 `CFLAGS` 控制由 C 编译隐式规则传递给 C 编译器的标志。参见第 10.3 节 [隐式规则使用的变量]，第 106 页。

你可以通过编写模式规则来定义自己的隐式规则。参见第 10.5 节 [定义和重新定义模式规则]，第 109 页。

后缀规则是定义隐式规则的一种更有限的方法。模式规则更通用、更清晰，但为了兼容性保留了后缀规则。参见第 10.7 节 [旧式后缀规则]，第 117 页。

### 10.1 使用隐式规则

例如，假设 `makefile` 如下所示：

```
foo : foo.o bar
	cc -o foo.o bar $(CFLAGS) $(LDFLAGS)
```

由于你命名了 `'foo.o'` 但没有为它提供规则，`make` 将自动查找一条告诉它如何更新它的隐式规则。无论文件 `'foo.o'` 目前是否存在，这种情况都会发生。

如果找到了隐式规则，它可以同时提供命令和一个或多个前提条件（源文件）。如果你需要指定隐式规则无法提供的额外前提条件（例如头文件），你可能需要为 `'foo.o'` 写一条没有命令行的规则。
