
# 超用户、PATH 与安全

当你以 `root` 身份工作时，`PATH` 中保留的目录越少，你就越不容易以 `root` 身份执行不可信的程序。永远不要包含工作目录（在 `PATH` 中的任何地方使用 `.` 或 `..`，作为 `PATH` 的最后一个元素）。更多信息请参阅第 302 页的“PATH：Shell 查找程序的地方”。

# Upstart 事件守护进程

传统的 SysVinit 无法良好处理现代硬件，包括热插拔（第 568 页）设备、USB 硬盘和闪存器以及网络挂载的文件系统，Ubuntu 将其替换为 Upstart init（upstart.ubuntu.com 和 upstart.ubuntu.com/wiki）。

还有多种 SysVinit 的替代方案。其中最著名的之一 initng（www.initng.org）适用于 Debian 和 Ubuntu。此外，Solaris 将使用 SMF（服务管理设施），macOS 将使用 launchd。随着时间的推移，Ubuntu 可能会将这些系统的特性整合到 Upstart 中。

基于运行级别的 SysVinit 守护进程（sysvinit 包）使用运行级别（单用户、多用户等）以及从 `/etc/rc.d` 到 `/etc/init.d` 中初始化脚本的链接来启动和停止服务。基于事件的 init 守护进程（upstart 包）使用事件来启动和停止系统服务。从 Feisty 版本开始，Ubuntu 切换到 Upstart 守护进程并开始从 SysVinit 系统向 Upstart 配置过渡。本节讨论了 Upstart 以及将保留的 SysVinit 部分：`/etc/rc.d`、`/etc/init.d` 以及运行级别的概念。请参阅第 487 页的该术语。

Upstart init 守护进程是基于事件的，并在系统上发生变化时运行程序。这些程序（通常是脚本）启动并停止服务。这种设置在概念上与 SysVinit 在进入系统时调用的初始化脚本链接相似，但 Upstart 更灵活。Upstart 不仅在运行级别更改时启动和停止服务，还可以在收到系统上发生变化的信息时启动并停止服务。这种变化被称为事件。

# Upstart 的未来

为了平滑地从 SysVinit 切换到 Upstart，并尽可能减少错误，Ubuntu 运行 Upstart 模拟运行级别（第 510 页）来实现的特性。从 Feisty 版本开始，Ubuntu 切换到 Upstart 守护进程并开始从 SysVinit 系统向 Upstart 配置过渡。Upstart 运行级别使用了 `/etc/rc.d` 和 `/etc/init.d` 目录。

Upstart 运行级别通常由 Upstart 软件包包含以下内容：

- 启动：使用 `initctl` 运行服务。
- 日志：使用 init 守护进程的定义文件。
- 启动-配置：使用 SysVinit 任务。
- 启动-任务：使用 init 任务。
- 系统-服务：使用 Upstart 任务。

## 定义

**事件**  
事件是状态的变化，可以手动触发 `initctl`。rc2 任务在系统进入运行级别时运行这些脚本。请参阅第 505 页关于 rc2 任务的讨论，参阅第 507 页关于初始化脚本的信息。Upstart 实现了运行级别（第 510 页）和 `telinit`（第 510 页）工具以与 SysVinit 系统兼容。

**initctl**  
`initctl`（init 控制）工具允许具有 `root` 权限的系统管理员与 Upstart init 守护进程通信。该工具可以启动、停止和报告作业。例如，`initctl list` 命令列出作业及其状态：

```bash
$ sudo initctl list
log (start) waiting
rc-default (stop) waiting
rc0 (stop) waiting
...
tty5 (start) running, process 4720
tty6 (start) running, process 4727
```

查看 `initctl` 手册页以及本节中的示例以获取更多信息。你可以输入 `initctl help`（help 前没有连字符）来显示 `initctl` 命令列表。或者，你可以输入以下命令显示有关 `initctl` 命令的更多信息：

```bash
$ initctl list --help
Usage: initctl list [OPTIONS]...
List known jobs.
```

**作业**  
作业是一个系列指令，当其完成时返回等待状态。作业被分为任务和服务。

**任务**  
任务是在完成后执行工作的作业。

**服务**  
服务是在停止时正常执行的作业。

**作业定义文件**  
`/etc/event.d` 目录包含作业定义文件。该目录是由 Upstart 软件包填充的。

**init 状态**  
在其核心，Upstart init 守护进程是一个状态机。它跟踪作业的状态，当它们更改状态时，可能会执行命令或终止作业。

**运行级别模拟**  
SysVinit 守护进程使用运行级别（第 510 页）来启动和停止进程。当 Ubuntu 使用 Upstart 守护进程时，没有运行级别的概念。

# 任务

选项：

- `--show-ids`：显示任务 ID 以及名称
- `-p, --pid=PID`：目标进程
- `-q, --quiet`：将输出仅限制为错误
- `-V, --verbose`：增加输出以包含信息性消息
- `--help`：显示此帮助并退出
- `--version`：输出版本信息并退出

将列表替换为您想要获取更多信息的 `initctl` 命令。`start`、`stop` 和 `status` 实用程序都是 `initctl` 的链接，它们运行与其名称同名的 `initctl` 命令。

`/etc/event.d` 目录下的每个文件都定义了一个任务，并且通常包含至少一个事件和一个命令。当事件被触发时，它会执行该命令。本节描述了管理员定义的任务以及通过 Upstart 软件包安装的任务的示例。

## 管理员定义的任务

### mudat 示例

管理员定义的任务使用 `exec` 关键字来执行 shell 命令行。您也可以使用该关键字执行存储在文件中的 shell 脚本或二进制可执行文件。

```bash
$ cat /etc/event.d/mudat
start on runlevel 2
exec echo "Entering multiuser mode on " $(date) > /tmp/mudat.out
```

此文件定义了一个任务：当系统进入多用户模式（runlevel 2）时，它运行 `echo` shell 命令。此命令将一个包含时间和日期的消息写入 `/tmp/mudat.out`。该 shell 使用命令替换（第 344 页）来执行 `date` 工具。在该任务运行完成后，`mudat` 任务停止并进入等待状态。在下一个示例中，`cat` 工具显示 `/tmp/mudat.out` 文件的内容，`initctl list` 报告该任务（`status` 实用程序）显示相同的信息：

```bash
$ cat /tmp/mudat.out
Entering multiuser mode on Tue Jul 10 17:34:39 PDT 2007
```

```bash
$ sudo initctl list mudat
mudat (stop) waiting
```

如果 `exec` 命令行包含 shell 特殊字符（第 146 页），`init` 会执行 `/bin/sh` 并将命令行传递给 shell。否则，`exec` 直接执行命令行。要运行多个 shell 命令，请使用 `exec` 运行存储在文件中的 shell 脚本，或使用 `script...end script`（下文讨论）。

Upstart init 守护进程只能监控使用 `exec` 执行程序的服务的任务。它无法监控使用 `script...end script` 运行的任务。另一种方法，需要使用 `exec` 任务的服务可以使用任一方法来运行程序。

您还可以定义并设置一个由该事件触发的任务。`myob` 任务定义文件定义了一个由 `hithere` 事件触发的任务：

```bash
$ cat /etc/event.d/myob
start on hithere
script
    echo "Hi there, here I am!" > /tmp/myob.out
    date >> /tmp/myob.out
end script
```

`myob` 文件显示了另一种执行命令的方法：它在 `script` 和 `end script` 关键字之间包含了两个命令。这些关键字始终通过 `/bin/sh` 执行。这些命令将消息和日期写入 `/tmp/myob.out` 文件。您可以使用 `initctl emit` 命令来触发该任务。随后，当您触发它时，`initctl` 会显示 `myob` 运行时的状态：

```bash
$ sudo initctl emit hithere
hithere
myob (start) waiting
myob (start) starting
myob (start) pre-start
myob (start) spawned, process 6064
myob (start) post-start, (main) process 6064
myob (start) running, process 6064
myob (stop) running
myob (stop)
myob (stop) stopping
myob (stop)
myob (stop) killed
myob (stop) post-stop
myob (stop) waiting
```

```bash
$ cat /tmp/myob.out
Hi there, here I am!
Sat Jul 7 20:19:13 PDT 2006
```

```bash
$ sudo initctl list myob
myob (stop) waiting
```

在前面的示例中，`cat`、`initctl start` 和 `stop` 显示了 `myob` 生成的输出并显示任务的状态。您可以使用 `initctl start myob`（或直接 `start myob`）运行相同的任务。当您想运行一个任务时，`initctl start` 命令非常有用，例如运行上一个示例中的 `mudat` 任务，而不触发运行级别 2 事件。

## /etc/event.d 中的任务定义文件

随着 Ubuntu 从 SysVinit 过渡到 Upstart init，`/etc/event.d` 目录中将定义更多的任务。本节描述了 Upstart 软件包（第 501 页）放入此目录的一些任务。

### 可选：使用参数指定事件

`telinit` 和 `shutdown` 实用程序会发出带有参数的 `runlevel` 事件。例如，`shutdown` 发出 `runlevel 0`，而 `telinit` 发出 `runlevel 2`。您可以在任务定义中使用以下语法匹配这些事件：

```
start on event [arg]
stop on event [arg]
```

其中 `event` 是一个事件，`arg` 是可选的参数。
