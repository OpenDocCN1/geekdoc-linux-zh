
```python
name = '__main__'
q = multiprocessing.JoinableQueue()
# 启动一些消费者进程
cons1 = multiprocessing.Process(target=consumer, args=(q,))
cons1.daemon=True
cons1.start()

cons2 = multiprocessing.Process(target=consumer, args=(q,))
cons2.daemon=True
cons2.start()
```

在编写此类代码时，请注意放入队列的每个项都会通过管道或套接字连接被选取并发送到进程。通常情况下，发送一个大对象比发送许多小对象更好。

在应用程序中，生产者可能希望向消费者信号不再会有更多项产生，它们应该关闭。为了实现这一点，你应该编写使用“哨兵”`sentinel`的代码——一种表示完成的特殊值。这里是一个使用 `None` 作为哨兵来说明这一概念的示例：

```python
import multiprocessing

def consumer(input_q):
    while True:
        item = input_q.get()
        if item is None:
            break
        # 处理项
        print(item)
        # 替换为有用的工作
    # 关
    print("Consumer done")

def producer(sequence, output_q):
    for item in sequence:
        # 将项放入队列
        output_q.put(item)

if __name__ == '__main__':
    q = multiprocessing.Queue()
    # 启动消费者进程
    cons_p = multiprocessing.Process(target=consumer, args=(q,))
    cons_p.start()

# 生成项
sequence = [1,2,3,4]
producer(sequence, q)

# 通过向队列放入哨兵来信号连接
q.put(None)
# 等待消费者进程关闭
cons_p.join()
```

如果你在此示例中使用哨兵，请注意你将为每个消费者都放入一个哨兵。例如，如果有三个消费者进程在队列上处理项，生产者需要在队列中放入三个哨兵，以便它们全部关闭。

作为队列的替代方案，可以使用管道 `pipe` 来执行进程之间的消息传递。

### Pipe(duplex)

在进程之间创建一条管道并返回一个元组 `(conn1, conn2)`，其中 `conn1` 和 `conn2` 是代表管道端的 `Connection` 对象。管道是双向的。如果 `duplex` 为 `False`，`conn1` 只能用于接收 `conn2` 只能用于发送。在创建和启动任何使用管道的进程之前，必须调用 `Pipe()`。

`Pipe()` 返回的 `Connection` 对象实例 `c` 具有以下方法和属性：

`c.close()`

关闭连接。如果 `c` 被垃圾回收会自动关闭。

`c.fileno()`

返回连接使用的整数描述符。

`c.poll({timeout})`

如果连接上有可用数据，则返回 `True`。`timeout` 指定了等待的最长时间。如果省略，该方法将立即返回结果。如果 `timeout` 设置为 `None`，则操作将无限等待数据。

`c.recv()`

通过 `c.send()` 接收一个对象。如果连接的另一端已关闭且没有数据，则抛出 `EOFError`。

`c.recv_into(buffer, offset)`

接收一个完整的字节消息并将其存储在缓冲区中（例如 `bytearray` 对象或类似对象）。`offset` 指定了缓冲区中的偏移量。返回接收到的字节数。如果消息长度超过了可用缓冲区空间，将抛出 `BufferTooShort`。

`c.send(obj)`

通过连接发送一个对象。`obj` 是任何与 `pickle` 兼容的对象。

`c.send_bytes(buffer, offset, size)`

通过连接发送数据缓冲区。`buffer` 是任何支持缓冲区接口的对象，`offset` 是缓冲区中的偏移量，`size` 是要发送的字节数。结果数据作为单个消息发送，通过单次调用 `c.recv_bytes()` 接收。

管道可以类似于队列的方式使用。这里有一个使用管道解决生产者问题的示例：

```python
import multiprocessing

# 在管道上消费项。
def consumer(pipe):
    output_p, input_p = pipe
    input_p.close()
    while True:
        try:
            item = output_p.recv()
        except EOFError:
            break
        # 处理项
        print(item)
    Shutdown
    print("Consumer done")

def producer(sequence, input_p):
    for item in sequence:
        # 将项放入队列
        input_p.send(item)

if __name__ == '__main__':
    (output_p, input_p) = multiprocessing.Pipe()
    # 启动消费者进程
    cons_p = multiprocessing.Process(target=consumer, args=(output_p, input_p))
    cons_p.start()

    # 在生产者端关闭输出管道
    output_p.close()

    # 生成项
    sequence = [1,2,3,4]
    producer(sequence, input_p)

    # 通过关闭输入管道信号完成
    input_p.close()

    # 等待消费者进程关闭
    cons_p.join()
```

## multiprocessing 423

应当对对管道端点进行妥善的管理。如果生产者或消费者都不使用管道的端点，则应该将其关闭。这解释了例如，为什么在生产者中关闭管道的输出端，而在消费者中关闭管道的输入端。如果你忘记了其中一步，程序可能会在消费者的 `recv()` 操作上发生挂起。管道由操作系统计数，必须在所有进程中都关闭以产生 EOF 错误。因此，在生产者中关闭管道没有任何影响，除非消费者也关闭了管道的同一个端。

管道可以用于双向通信。这可以用于编写程序，使用通常与客户端/服务器计算或远程过程调用相关的请求/响应模型与进程进行交互。这是一个示例：

```python
import multiprocessing
# 一个服务器进程
def adder(pipe):
    server_p, client_p = pipe
    client_p.close()
    while True:
        try:
            x,y = server_p.recv()
        except EOFError:
            break
        result = x + y
        server_p.send(result)
    print("Server done")
if __name__ == '__main__':
    (server_p, client_p) = multiprocessing.Pipe()
    # 启动服务器进程
    adder_p = multiprocessing.Process(target=adder, args=(server_p, client_p))
    adder_p.start()

    # 在客户端中关闭管道
    server_p.close()

    # 向服务器发送一些请求
    client_p.send((3,4))
    print(client_p.recv())

    client_p.send(('Hello', 'World'))
    print(client_p.recv())

    # 完成。关闭管道
    client_p.close()

    # 等待消费者进程关闭
    adder_p.join()
```
