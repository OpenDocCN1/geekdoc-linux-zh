一个音频编辑器。Audacity 可用于过滤、应用效果以及在不同的音频格式（如 MP3、WAV、OGG、FLAC 等）之间转换。

ImageMagick 是一个用于转换和编辑大多数图像文件的命令行工具。它还可以用于从图像文件创建 PDF 文档，反之亦然。

当网络浏览器从网站加载页面时，它实际上连接到一台远程计算机并请求特定的信息。在这种情况下，运行网络浏览器的计算机被称为客户端，而远程计算机被称为服务器。

服务器计算机（普通的台式电脑或专用硬件）需要特定的程序来管理它将提供的每种类型的信息。在提供网页方面，世界上大多数服务器都部署了开源服务器程序。这种程序被称为 HTTP 服务器（HTTP 代表超文本传输协议），最流行的有 Apache、Nginx 和 lighttpd。

即使是简单的页面也需要许多请求，这些请求可能是二进制文件——静态内容或从各种数据源渲染的动态内容。HTTP 服务器的作用是收集并把所有请求的数据发回浏览器，由浏览器根据响应式 HTML 文档（HTML 代表超文本标记语言）和其他支持文件来安排内容。因此，网页的渲染涉及在服务器端执行的操作和在客户端执行的操作。双方都可以使用自定义脚本来完成特定任务。在 HTTP 服务器端，通常使用 PHP 脚本语言。JavaScript 是在客户端（网络浏览器）上使用的脚本语言。

服务器程序可以提供各种信息。服务器程序请求其他服务器程序提供的信息的情况并不常见，但当 HTTP 服务器需要由数据库服务器提供的信息时，就会出现这种情况。

例如，当请求动态页面时，HTTP 服务器通常会查询数据库以收集所有所需的信息，并将动态内容发回客户端。同样地，当用户在网站上注册时，HTTP 服务器收集客户端发送的数据并将其存储在数据库中。

数据库是一组组织良好的信息。数据库服务器以格式化的存储内容，使得能够可靠且快速地读取、写入和链接大量数据。开源数据库服务器用于许多应用程序，而不仅仅是互联网。即使是本地应用程序也可以通过连接到本地数据库服务器来存储数据。最常见的数据库类型是关系型数据库，数据组织在预定义的表中。最流行的关系型数据库源是 MariaDB（源自 MySQL）和 PostgreSQL。

在局域网（如办公室和家庭中的网络）中，计算机不仅能够访问互联网，还能相互通信是理想的。有时一台计算机充当服务器，有时同一台计算机充当客户端。当你想访问网络中另一台计算机上的文件时（例如，从便携设备存储在台式电脑上的文件），这种需求是必要的，这样就可以避免将其复制到 USB 闪盘或通过链接的麻烦。

在 Linux 机器之间，通常使用 NFS（网络文件系统）。NFS 协议是配备有 Unix/Linux 机器的网络共享文件系统的标准方法。通过 NFS，计算机可以与特定的计算机共享一个或多个目录。NFS 甚至可以与客户端共享整个操作系统的目录树，客户端将使用它进行启动。这些被称为瘦客户端（thin clients）的设备通常用于大型网络，以避免维护每台机器上每个独立的操作系统。

如果网络上还连接了其他类型的操作系统，建议使用一种所有这些系统都能理解的数据共享协议。Samba 满足了这一需求。Samba 实现了一种最初为 Windows 操作系统设计的网络文件共享协议，但今天它与所有主流操作系统都兼容。通过 Samba，局域网内的计算机不仅共享文件，还共享打印机。

在某些局域网中，工作站登录时的授权由中央服务器授予，该服务器称为域控制器（domain controller），它管理对本地和远程资源的访问。域控制器是微软 Active Directory 提供的一种服务。Linux 工作站可以使用 Samba 或名为 SSSD 的身份验证系统与域控制器关联。从第 4 版本开始，Samba 还可以可以在异构网络上作为域控制器工作。

如果目标是实现一种云计算解决方案以提供各种网页数据共享方法，可以考虑两种替代方案：owncloud 和 Nextcloud。这两个项目非常相似，因为 Nextcloud 是 owncloud 的衍生项目，这在开源项目中并不稀奇。衍生项目通常被称为“分支（fork）”。它们都提供相同的的基础功能：文件共享与同步、协作工作、日历、联系人和邮件，所有通过桌面、移动和网络界面实现。Nextcloud 还提供私有的音视频会议，而 owncloud 更侧重于文件共享以及第三方软件的集成。更多功能作为插件提供，可以以后激活。

owncloud 和 Nextcloud 都提供带有额外功能和扩展支持的付费版本。它们与其他商业解决方案的不同之处在于可以免费在私有服务器上安装 Nextcloud 或 owncloud，避免将敏感数据保留在未知服务器上。由于它们依赖 HTTP 通信并用 PHP 编写，因此必须在先配置好的服务器（如 Apache）上进行安装。如果你考虑在自己的服务器上安装 owncloud 或 Nextcloud，请确保也启用 HTTPS 以加密到云端的所有连接。

计算机之间的通信只有在网络正常工作的情况下才可能。通常，网络配置由运行在路由器上一系列程序完成，负责设置和检查网络可用性。为了实现这一目标，使用了基本网络服务：DHCP（动态主机配置协议）和 DNS（域名系统）。

DHCP 负责在网络连接或设备进入无线网络时为主机分配 IP 地址。当连接互联网时，ISP 的 DHCP 服务器在局域网中非常有用，可以为所有连接的设备自动提供 IP 地址。如果未配置 DHCP 或其工作不正常，则需要手动配置连接到网络的每个设备的 IP 地址。在大型网络或小型网络中手动设置 IP 地址是不切实际的，这就是为什么大多数路由器默认都预配置了 DHCP 服务器。

DHCP 和 DNS 设置都可以通过路由器提供的 Web 界面进行修改。例如，可以将 IP 分配限制为仅已知设备，或为特定机器关联固定的 IP 地址。还可以更改 ISP 提供的默认 DNS 服务器。某些第三方 DNS 服务器（如 Google 或 OpenDNS 提供的服务器）有时可以提供更快的响应和额外的功能。

所有的计算机程序（客户端和服务器端程序、桌面应用程序以及操作系统本身）都是使用一种或多种编程语言编写的。程序可以是一个文件，也可以是由数百个文件组成的复杂系统，操作系统将其视为由处理器和其他设备解释并执行的指令序列。

有许多用于不同目的的编程语言，Linux 系统提供了许多语言。由于开源软件还包含了程序源代码，Linux 系统为开发者提供了完美的条件，让他们能够根据需求理解、修改或创建软件。

每个程序都从一个称为源代码的文本文件开始。这种源代码是用或或易于人类的语言编写的，描述了程序正在做什么。计算机处理器无法直接执行这些代码。在编译型语言中，源代码被转换为二进制文件，然后由计算机执行。名为编译器的程序负责完成从源代码到可执行文件的转换。由于编译后的二进制文件特定于某类处理器，因此该程序可能需要重新编译才能在另一种类型的计算机上运行。

在解释型语言中，程序不需要预先编译。相反，解释器会在每次运行程序时读取源代码并执行其指令。这使得开发变得更加简单和快速，但同时，解释型程序通常比编译型程序慢。

# Introduction

While the terms free software and open source software are widely used, there are still some misconceptions about their meaning. In particular, the concept of “freedom” needs closer examination. Let’s start with the definition of the two terms.

# Definition of Free and Open Source Software

# Criteria of Free Software

First of all, “free” in the context of free software has nothing to do with “free of charge”, or as the founder of the Free Software Foundation (FSF), Richard Stallman, succinctly puts:

> To understand the concept, you should think of “free” as in “free speech,” and not as in “free beer”.

— Richard Stallman, What is free software?

# Linux Essentials (Version 1.6) | Topic 1: The Linux Community and a Career in Open Source

Regardless of whether you have to pay for the software or not, there are four criteria which constitute free software. Richard Stallman describes these criteria as “the four essential freedoms”, the counting which he starts from zero:

- The freedom to run the program as you wish, for any purpose (freedom 0).

Where, how and for what purpose the software is used can neither be prescribed nor restricted.

- The freedom to study how the program works, and how it does your computing as you wish (freedom 1). Access to the source code is a precondition for this.

Everyone may change the software according to their ideas and needs. In this turn presupposes that the so-called source code, i.e all files of a software consists, must be available in a format readable by programmers. And, of course, this right applies to a single user who may want to add a single feature, as well as to software companies that build complex systems like smartphone operating systems or router firmware.

- The freedom to redistribute copies so you can help others (freedom 2).

This freedom explicitly encourages each user to share the software with others. It is therefore a matter of the widest possible distribution and thus the widest community of users and developers who, on the basis of these freedoms, further develop and improve the software for the benefit of all.

- The freedom to distribute copies of modified versions to others (freedom 3).

By doing this you give the community a chance to benefit from the changes. Access to the source code is a precondition for this.

This is not only about the distribution of free software, but about the distribution of software. Anyone who makes changes in software does not respect the original freedoms at the same time, for example there are restrictions on disclosure, change, or connections with other software components. This happens especially when a group of developers has different ideas about the direction and it can split off and continue as a new project. But, of course, all obligations associated with these freedoms remain. who regards software as lock and key. In contrast to free software, such software is proprietary.

# Open Source Software vs. Free Software

For many, free software and open source software are synonyms. The frequently used abbreviation FOSS for Free and Open Source Software emphasizes this commonality. FLOSS for Free/Libre and Open Source Software is another popular term, which undeniably emphasizes the idea of freedom also for other languages. However, a differentiation is worthwhile.

The term free software with the definition of the described freedoms goes back to Richard Stallman and the GNU project founded in 1985 — almost 10 years before the emergence of Linux. The name “GNU is not Unix” describes the intent with a wink of the eye: GNU started an initiative to develop a technically convincing solution — namely operating system — from scratch, to make it available to the general public and to improve continuously with the general public. The openness of the source code was a technical and organizational necessity for this, but in its self-image the software movement is a social and political — some say ideological—movement.

With the success of Linux, the collaborative projects of the Internet, and the thousands of projects and companies that emerged in this new software cosmos, the social aspect increasingly receded into the background. The openness of the source code itself changed from a technical requirement to a defining feature: as soon the source code was visible, the software was considered “open source”. The social motives gave to a more pragmatic approach to software development.

# 许可证

与电冰箱或汽车不同，软件并非实体产品，而是数字产品。因此，公司实际上无法通过销售产品并改变物理占有权来转移此类产品的所有权——相反，它转移的是该产品的使用权，而用户通过合同同意这些使用权。哪些使用权是允许的、哪些是不允许的，在软件许可证中并没有记录，因此可以理解其中包含的规定是多么重要。

虽然像微软或 SAP 这样的大型专有软件有其专门为其产品量身定制的许可证，但自由和开源软件的倡导者从一开始就力求使其许可证具有清晰的通用有效性，因为毕竟，每个用户都应该理解这些许可证，并在必要时为自己的开发工作亲自使用它们。

然而，不应认为这种简单化的理想是可以实现的，因为有许多特定的需求和在国际上并不总是兼容的法律理解阻碍了这一实现。举一个例子：德国法律和美国版权法在根本上是不同的。根据德国法律，存在一个“作者”（更准确地说：Urheber），其作品是他的知识产权。作者可以许可他人使用其作品，但他不能转让或放弃其作者身份。后者在美国法律中也是如此。这里也有作者（但可以是一家公司或机构），但他仅拥有开发权，这些权利可以部分或全部转移，并因此与他的作品完全脱离。一种国际有效的许可证必须根据不同的立法进行解释。

其后果是许多的，不同的自由开源软件（FOSS）许可证有时截然不同。更糟糕的是许可证的不同版本，或者许可证的混合（在一个项目中，甚至连接多个项目），这可能会导致困惑甚至法律纠纷。

自由软件的代表和明确以经济为导向的开源运动倡导者创建了自己的组织，这些组织现在对根据其原则制定软件许可证起着决定性作用，并支持其成员执行这些原则。

# 拷贝左（ (Copyleft)

上述的自由软件基金会（FSF）制定了 GNU 通用公共许可证（GPL），这是自由软件最重要的许可证之一，被许多项目使用，例如 Linux 内核。此外，它还发布了具有特定案例定制的许可证，例如 GNU 弱类型通用公共许可证（LGPL），它规定了自由软件与代码修改的结合，其中修改的源代码不需要向公众发布；GNU Affero 通用公共许可证（AGPL），它涵盖了销售托管软件的访问权限；或者 GNU 自由文档许可证（FDL），它将自由原则扩展到软件文档。此外，FSF 对第三方许可证提出支持或反对的建议，附属项目（如 GPL-Violations）会调查涉嫌违反自由许可证的行为。

FSF 认为，我们在使用自由许可证时所主张的原则也适用于软件拷贝左的变体——这与它所拒绝的限制性版权原则形成对比。因此，其思想是将自由许可证的自由原则尽可能受限制地转移到软件未来的变体中，以防止后续的限制。

然而，这听起来显而易见且简单，实际上会导致相当的复杂性，批评者称拷贝左原则是“病毒性”的，因为它会传播到后续版本中。

根据上述内容，例如，两个在不同许可证许可的软件组件可能互不兼容，因为这两个许可证无法同时被转移到后续产品中。这甚至适用于同一份许可证的不同版本！

出于这个原因，较新的许可证或许可证版本不再那么严谨地把握拷贝左。上述提到的 GNU 弱类型通用公共许可证（LGPL）在这种意义上是一种妥协，以便将自由软件与“非自由”组件（通常称为库）连接起来。库包含子程序或例程，这些程序反过来被许多其他程序使用。这导致了常见的情况：专有软件从自由库中调用此类子程序。

避免许可证冲突的另一种方法是双重许可，即一个软件在不同的许可证下许可，例如，一个自由许可证和一个专有许可证。一个典型的案例是软件的自由版本，该版本只有在遵守拷贝左限制的情况下才能使用；而另一种是在不同的许可证下获取软件的方法，作为交换，支付费用使被许可者免于某些限制，这些费用可以用于软件的开发。

因此，应当明确，软件项目许可证的选择应该以非常谨慎的态度做出，因为与其他项目的合作、与其他组件的兼容性以及产品的未来设计都取决于此。拷贝左在这一方面给开发者带来了特殊的挑战。

# 开源定义与宽容许可证

在开源领域，由 Eric S Raymond 和 Bruce Perens 于 1998 年创立的开源倡议组织（OSI）主要关注许可证问题。它还开发了一套标准程序用于检查软件许可证是否符合其开源定义。目前在 OSI 网站上可以找到 80 多种受认可的开源许可证。

在这里他们还列出了“OSI 批准”的、明确反对拷贝左原则的许可证，特别是 BSD 许可证组。伯克利软件发行（BSD）是最初在伯克利大学开发的 Unix 操作系统的变体，它后来催生了 NetBSD、FreeBSD 和 OpenBSD 等自由项目。这些项目的底层许可证通常被称为宽容的（permissive）。与拷贝左许可证不同，它们的目标不是建立修改变体的使用条款。相反，最大程度的自由有助于软件尽可能地分发，让软件的编辑者自行决定如何进行编辑——例如，他们是发布这些版本还是将其视为闭源并进行商业分发。

两条款 BSD 许可证（也称为简化 BSD 许可证或 FreeBSD 许可证）证明了这种宽容许可证可以有多精简。除了因软件造成的损害而引起责任索赔的标准免责条款外，该许可证仅包含以下两条规则：

允许以源码或二进制形式分发和使用，无论是否修改，前提是满足以下条件：

- 1. 分发源码必须保留上述版权声明、本条件列表和以下免责声明。
- 2. 二进制形式的分发必须在随分发的文档或材料中重制上述版权声明、本条件列表和以下免责声明。

# 知识共享（Creative Commons）

FLOSS 成功的开发模式以及相关的技术进步，尝试将开源原则转移到其他非技术领域。知识的准备和提供，以及解决复杂任务的创意协作，现在被认为是扩展的、内容开源原则的证明。

这导致了这些领域也需要可靠的基础，以便工作结果可以共享和处理。由于现有的软件许可证很难适用于

在此，曾有许多尝试将科学工作中的特定需求转化为“开源精神艺术”的数字化作品，并将其转化为类似的强许可协议。

如今此类此类最重要的倡议是知识共享（Creative Commons，简称 CC），它将其关注点总结如下：

- 知识共享是一个全球非营利组织，通过提供免费的法律工具来实现创意和知识的共享与重用。
- [什么是知识共享以及它是做什么的](https://creativecommons.org/faq#what-is-creative-commons-and-what-do-you-do) (https://creativecommons.org/faq#what-is-creative-commons-and-what-do-you-do)

通过知识共享，权利分配的重心从分发者回到了作者手中。在传统出版中，作者通常会将所有出版权（印刷、翻译等）转让给出版社，再由出版社负责确保作品得到最好的分发。互联网发生巨大变化的分发渠道让作者能够自己行使这些许多出版权利，并决定其作品如何被使用。知识共享提供了一个简单且法律可靠的方法来确定这些内容，但知识共享还希望更多：鼓励作者将他们的作品作为一种通用的交换与合作过程开放。与传统版权（赋予作者拥有所有可以根据需要转让给他人的权利）不同，知识共享采取了相反的方法：作者将其作品开放给社区，但可以从在使用作品时需要考虑的一系列特征中进行选择——选择的特征越多，许可越严格。

因此，CC 的“选择许可”原则要求作者对各个属性进行逐一回答，并生成推荐的许可，作者可以将该许可作为文本和图标分配给作品。

为了更好地理解，这里是 CC 提供的六种可能的组合和许可概述：

## CC BY（“署名”）

该免费许可允许任何人在标明作者的情况下编辑和分发该作品。

## CC BY-SA（“署名-相同共享”）

与 CC BY 相同，不同在于修改后的作品只能在相同的许可下分发，这里的原则同样是“继承”的。

## CC BY-ND（“署名-禁止衍生”）

与 CC BY 相同，不同在于作品只能以未经修改的形式传播。

## CC BY-NC（“署名-非商业”）

作品可以在标明作者的情况下进行编辑和分发，但仅限于非商业条件。

## CC BY-NC-SA（“署名-非商业-相同共享”）

与 BY-NC 相同，不同在于作品只能在相同的条件下共享（即类似于传染性许可的许可）。

## CC BY-NC-ND（“署名-非商业-禁止衍生”）

最严格的许可：允许在标明作者的情况下分发，但必须保持原封未且符合非商业条件。

## 开源中的商业模式

回溯过去，FLOSS（自由及开源软件）的胜利是一场由技术爱好者理想主义者发起的草根运动，他们不受经济限制，不依赖资金，将自己的工作服务于大众。同时，在 FLOSS 环境中诞生了价值数十亿美元的公司；仅举一个例子，成立于 1993 年的美国公司 Red Hat（年销售额超过 30 亿美元，2018 年）在 2018 年被巨头 IBM 收购。

所以，让我们来看看高质量软件的免费及大多免费分发与其创作者商业模式之间的张关系，因为有一点必须明确：无数高素质的自由软件开发者也必须赚钱，因此最初纯商业的 FLOSS 环境必须发展出可持续的商业模式以维持其生态系统。

一种常见的方法（特别是初始阶段的大型项目）是所谓的“众筹”，即通过 Kickstarter 等平台收集资金捐赠。作为回报，捐赠者在成功或实现预定义目标后，将获得开发者提供的预定义奖励，或者无限制访问产品或特殊功能的权限。

另一种方法是双重许可：免费软件同时以更严格的甚至专有的许可进行提供，反过来，这保证了客户可以获得更广泛的服务（发生错误时的响应时间、更新、特定平台的版本等）。许多例子中的一个是 ownCloud，它在 GPL 环境下开发，并根据专有许可向客户提供“商业版”。

让我们也将 ownCloud 作为广泛的 FLOSS 商业模式的示例：专业服务。许多公司缺乏必要的内部技术知识来可靠地、尤其是安全地设置和运行复杂的关键软件。这就是为什么他们直接从制造商处购买咨询、维护或帮助台等专业服务。责任问题在这一决策中也起了作用，因为公司将运营风险转嫁给了制造商。

如果一个软件在其领域取得成功并流行，那么客户会获得周边商品或证书等边缘可能性，并在使用该软件时指出其特殊地位。学习平台 Moodle 提供培训师认证，培训师通过这种方式向潜在客户记录他们的知识，而这只是无数例子中的其中之一。

软件即服务（SaaS）是另一种商业模式，特别是对于基于 Web 的技术。在这里，云提供商在其服务器上运行作为客户关系管理（CRM）或内容管理系统（CMS）的软件，并允许客户访问已安装的应用。这节省了客户安装和维护软件成本。作为回报，客户根据各种参数（例如用户数量）支付使用费用。可用性和作为业务关键因素起着重要作用。

最后，按需为客户开发特定扩展的模型在小型项目中特别常见。这通常由客户决定如何处理这些扩展，即他是否也发布它们，或将其留在自己的业务模式下。

应当明确的是：尽管自由软件通常是免费提供的，但其环境中产生了许多商业模式，全球无数自由职业者和公司以极具创造性的形式对其进行不断修改和扩展，这最终也确保了整个运动的持续存在。

自由软件基金会的 FAQ 在此处提供了相关信息：只要你的专有软件和自由软件保持相互分离，这种结合就是可能的。然而，你必须确保这种分离在技术上是保证的，并且对用户来说是可识别的。如果你整合自由软件使其成为你产品的一部分，你必须根据拷贝左原则在 GPL 下发布该产品。

4. 为什么自由软件基金会发布 GNU Affero 通用公共许可证（GNU AGPL）作为 GNU GPL 的补充？

GNU AGPL 弥补了托管在服务器上的自由软件所产生的许可证缺口：如果一个开发者对软件进行了更改，根据 GPL，他没有义务让这些更改可用，因为他只是允许访问程序，但并没有在 GPL 意义上对程序进行“分发”。而 GNU AGPL 规定软件必须提供包含所有更改的版本供下载。

## 桌面环境

Linux 采用模块化方法，系统的不同部分由不同的项目开发，每个项目都满足特定的需求或目标。因此，有多种桌面环境可以选择，结合软件包管理器一起，默认桌面环境是发行版之间的主要区别之一。不像 Windows 和 macOS 等专有操作系统（用户受限于自带的桌面环境），你可以安装多个环境并选择最适合你需求的那个。

基本上，Linux 世界有两个主要的桌面环境：Gnome 和 KDE。它们都是完整的，有大型社区支持，目标相同，但方法略有不同。简而言之，Gnome 尝试遵循 KISS（保持简单）原则，应用程序非常精简。另一方面，KDE 有另一种视角，提供了更丰富的应用程序，并赋予用户更改每个配置设置的机会。

虽然 Gnome 应用基于 GTK 工具（用 C 语言编写），而 KDE 应用使用 Qt 库（用 C++ 编写）。使用相同图形工具包编写应用程序的一个实际优势是，应用程序倾向于具有相似的外观和感受，这让用户在体验过程中有一种统一感。另一个重要特征是，许多常用应用程序使用相同的共享图形库可以节省某些内存，同时在库首次加载后会加快加载速度。

## 进入命令行

对于我们来说，最重要的应用程序之一是图形终端模拟器。它们之所以被称为终端模拟器，是因为它们确实在图形环境中模拟了旧式的终端（通常是打字机），而这些终端实际上是连接到执行实际计算的远程机器的客户端。这些机器是完全没有图形的简单计算机。

在 Gnome 中，此类应用程序被称为 Gnome Terminal，而在 KDE 中可以找到 Konsole。但还有许多其他选择，如 Xterm。这些应用程序为我们提供了一种访问命令行以便与 Shell（壳）交互的方法。

因此，你应该查看你选择的发行版的应用程序菜单来寻找终端应用程序。除了它们之间的任何区别外，每个应用程序都会提供让你获得使用命令行信心的必要。

进入终端的另一种方法是使用虚拟 TTY。你可以通过按下 Ctrl+Alt+F6 进入它们。例如，将 F# 读作 1 到 7 键中的一个键。某些初始组合可能会运行你的会话管理器或图形化环境。其他组合则会提示你输入登录名，如下所示：

```
