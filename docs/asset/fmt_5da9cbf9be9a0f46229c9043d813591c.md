
为了与 4.2 BSD make 兼容，`MFLAGS` 宏通过在 `MAKEFLAGS` 变量前面加上一个 `-` 来设置。`MFLAGS` 不会自动导出。

当 `SHELL` 宏被设置为单个单词值（如 `/usr/bin/csh`）时，表示要使用的备用 shell 的名称。默认是 `/bin/sh`。注意，`make` 执行不包含 shell 元字符的命令。除非 C shell 中的命令 `commands` 既不从环境导入也不向环境导入（无论 `-e` 参数如何），否则内置命令行将包含一个元字符（例如，分号）。为了正确设置它，你必须在每个需要它的 makefile 中定义此宏。

提供的宏供交叉编译使用。

`HOST_ARCH` 主机系统的机器架构。默认情况下，`arch(1)` 命令的输出前面带有 `-`。在正常情况下，你不应更改此值。

`HOST_MACH` 主机系统的机器架构。默认情况下是 `mach(1)` 命令的输出。

# 动态宏

如下格式的条目定义宏。

```
macro=value
```

`macro` 是宏的名称，`value` 是到注释字符或未转义换行符为止的所有字符组成的值。`make` 在接受值时会去除首部和尾部的空白。

对该宏的后续引用 `$(name)` 或 `$(name)` 将被 `value` 替换。在引用具有单字符名称的宏时，你可以省略括号或中括号。

宏引用可以包含对其他宏的引用，在这种情况下，嵌套引用会被先展开。

# 后缀替换宏引用

宏内部的替换可以如下所示进行：

```
$(name:string1=string2)
```

其中 `string1` 是宏定义中要替换的后缀或单词，而 `string2` 是替换的后缀或单词。宏值中的单词通过空格、制表符和转义的换行符分隔。

# 模式替换宏引用

模式匹配替换也可以应用于宏，其引用采用如下的形式：

```
$(name:op%os=np%ns)
```

其中 `op` 是现有的（旧）前缀，`os` 是现有的（旧）后缀，`np` 和 `ns` 是新的前缀和后缀，而 `%`（零或多个字符的字符串）匹配的模式将从被替换的值传递。例如，以下语句将 `DEBUG` 的值设置为：

```
tmp/fabricate-g.
```

```
PROGRAM=fabricate
```

```
DEBUG=$ $(PROGRAM:%=tmp/%-g)
```

注意 —— 不能在模式匹配规则的依赖列表中使用模式替换宏引用；`%` 字符不会独立求值。此外，等号后可以任意任意数量的 `%` 元字符。

# 追加宏

`macro += word ...`

### 隐式规则

当目标在 makefile 中没有时，`make` 会尝试确定它的类（如果有）并应用该类的规则。隐式规则描述了如何从相关的依赖文件构建给定类的任何目标。目标的类决定了用于构建该目标的对应依赖文件（具有相同的基名）。除了预定义的隐式规则集外，`make` 还允许你通过模式或后缀定义你自己的规则。

### 模式匹配规则

如下形式的目标条目是模式匹配规则，其中 `tp` 是目标前缀，`ts` 是目标后缀，`dp` 是依赖前缀，`ds` 是依赖后缀（其中任何一个都可以为空）。

```
tp%ts: dp%ds
```

`%` 代表零或多个字符的基名，这些字符在目标中被匹配并用于构造依赖名称。当 `make` 在搜索隐式规则时遇到匹配项，它将使用该目标条目中的规则从依赖文件构建目标。模式匹配隐式规则通常使用 `$@` 和 `$<` 动态宏作为目标和依赖名称的占位符。其他普通依赖可以出现在依赖列表中；然而，任何普通依赖都不能包含 `%`。如下形式的条目是有效的模式匹配规则。

```
tp%ts: [dependency...] dp%ds [dependency...]
```
