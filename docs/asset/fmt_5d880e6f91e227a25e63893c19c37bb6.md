
# 域名系统（DNS）

域名系统（DNS）提供主机名到 IP 地址的翻译。它还提供 IP 地址到主机名的反向翻译。当（当时的）Arpanet 用户意识到他们无法再在单个文件中维护主机信息时（该文件必须复制到 Arpanet 上的每台机器，且可能被更改或删除），DNS 就诞生了。DNS 将主机名管理委托给负责这些系统的管理员。DNS 随着互联网的快速增长而扩展。

DNS 的分层结构由叶子节点的主机和分支的域组成。带有其域的主机名被称为完全限定域名（FQDN）。主机名写在左侧，域的分支用点分隔。例如，名称 `sun.edu` 指向 `unc` 域内的一个主机，该域是 `edu` 顶级域名的一部分。在 DNS 层次结构的根部，一条 `NS`（名称服务器）记录指向 `edu` 域。在 `edu` 域内，另一组 `NS` 记录指向 `unc` 域。`unc` 域包含主机名。执行这种递归搜索的服务器通常会缓存其在途中学到的所有数据。随后的查询将访问任何其他服务器。所有缓存数据都有与其相关的生命周期，并在该时期后过期。

根域名服务器预加载到每台服务器上。这些系统对于处理查询至关重要，且无法动态学习。根服务器是相对静态的，但当前数据始终可用。

# DNS 配置与实现

DNS 是系统管理员在任何组织内部必须设置的基础服务之一。DNS 服务通过配置和运行名为 `named` 的名称服务器来实现。`named` 守护进程由 `BIND`（伯克利互联网名称守护进程）分发。`BIND` 分发版包含名称服务器以及作为解析器的客户端侧软件。`BIND` 可以从互联网软件联盟（ISC）获取。

`BIND` 使用 `ASCII` 实现名称数据库。这些数据库被分为若干区域文件（zone files）。`BIND` 将区域定义为一个域以及由同一台服务器管理的任何子域。DNS 的特殊之处之一是反向翻译出现在与正向翻译不同的区域文件中。这意味着系统管理员必须编辑两个文件来更改任何主机名。许多系统管理员认为这样繁琐，倾向于管理 `hosts(5)` 格式的文件，并使用 `h2n` 工具从其生成区域文件。

`named` 的实例与任何区域有三者可能的关系之一。它可以是特定区域的主服务器或缓存服务器。通常，名称服务器同时在多种模式下运行，因为许多服务器作为其既不是主也不是从的区域的缓存服务器运行。

解析器通常集成到运行时库 `lib11bc` 中，且对用户是透明的。`lib11bc` 的某些实现允许系统管理员配置查询名称服务的顺序，以解析主机名和其他系统数据。名称服务文件 `/etc/nwitch.conf` 用于存储这些配置信息。

# NTP

## 概述

网络时间协议（NTP）用于同步跨分组交换网络的计算机系统时钟。它是最古老的且广泛使用的网络协议之一。它的主要功能是尽可能准确地同步计算机系统的时钟。NTP 使用分层结构（strata）来描述与参考钟的距离。`Stratum 0` 设备是高精度的广域网计时设备，例如原子钟或无线钟。`Stratum 1` 设备是直接连接到层 0 时间设备上的计算机。`Stratum 2` 设备通过网络连接到层 1 设备，依此类推。

NTP 使用协调世界时（UTC）作为其时间尺度。UTC 基于原子时间，但通过闰秒进行调整以保持与地球旋转一致。NTP 提供了一种本地时钟与 UTC 同步的方法，考虑了网络通信中固有的延迟和抖动。

## 时间源

获取 NTP 时间信息有几种方法：

- **WWV 和 WWVB**：这些是来自不同基站广播的无线时间信号，例如北美的 WWV 和 WWVB，欧洲的 DCF7 和日本的 JJY。NTP 接收器可以使用这些信号同步其时钟。然而，这些信号可能会受到干扰，且并非在所有位置都可用。
- **GPS**：全球定位系统（GPS）是轨道上的一组卫星。这些卫星广播时间信息。GPS 接收器使用这些信息以高精度的度确定时间。
- **互联网服务器**：互联网上有许多 NTP 服务器。这些服务器可以用于同步本地时钟，但提供的时间准确性取决于网络连接和服务器质量。

NTP 用于多种应用程序，包括日志、文件时间标记和分布式系统。准确的时间同步对于许多现代技术至关重要，如数据库事务、安全协议和金融系统。

# BOOTP, DHCP, TFTP 和 RARP

这是一组执行操作系统任务的服务。BOOTP 和 DHCP 支持自动配置，不幸的是，DHCP 无法更新 DNS，而许多配置是需要它的。如果 DNS 不随 IP 地址更新，主机在获得新地址时名称将会更改。这会干扰主机名身份验证。如果所有工作站都有资源权限，那么这可能不是问题，为工作站使用 DHCP 是可行的。

此外 DHCP 和 BOOTP 可辅助网络安装，例如使用 RedHat 的 Kickstart 安装程序。第 15 章：“自动安装与升级。”

另一个辅助工具是简易文件传输协议（TFTP）。TFTP 通常在安装过程中从服务器下载文件到客户端。它不适用于安全环境，必须防止利用 TFTP 窃取或更改服务器上的文件。

最后，反地址解析协议（RARP）被某些系统用于发现其 IP 地址。Linux 不需要 RARP 服务。提供此服务是为了可能需要它的网络设备。不需要 RARP 的站点应将其禁用。

# RPC

远程过程调用（RPC）服务为应用程序提供了调用其他过程子程序的能力，这些过程通常运行在其他计算机上。开放网络远程调用（ON RPC）服务已成为 UNIX 社区的标准。存在许多其他 RPC 协议，但 ON RPC 受益于构建在其上的应用程序的流行。NIS 和 NFS 均使用 ON RPC 实现。

RPC 服务使用程序号的概念来识别 RPC 服务，RPC 端口映射守护进程（`portmapper`）根据需要将程序号映射到 TCP 或 UDP 端口。每个 RPC 服务向所在主机上的 `portmapper` 注册，并提供其监听的端口。

# 应用级服务

## NIS

网络信息服务（NIS）为 NIS 域内的所有系统提供有关用户、组、邮件别名和其他系统信息的统一系统数据。有关 NIS 的详情请参阅第 21 章“管理 NIS”。

## LDAP

轻量级目录访问协议（LDAP）旨在提供与 DNS 和 NIS 类似的服务。LDAP 克服了这两项服务的局限性，允许比 DNS 更多丰富的数据，并且与 NIS 不同，它具有分级结构。年前，MIT Athena 项目的开发者曾使用 DNS 创建了一项名为 `hesiod` 的服务。`hesiod` 使用 `TXT` 记录来管理用户和组数据。遗憾的是，`hesiod` 在大型组织中仍然存在。LDAP 本应能够胜任类似的角色，但进展一直缓慢：作为命名服务的 LDAP 的支持尚未被集成到 `libc` 中，因此 LDAP 的使用限于限于显式与其通信的程序。由于许多程序都是这样做的，因此 LDAP 目前处于休眠状态，等待互联网社区决定使用哪种目录服务以及使用什么数据来填充它。

## Samba

Samba 为 Microsoft Windows 客户端提供文件和打印服务。部署 Samba 使系统管理员能够 Linux 服务器作为组织的主要文件和打印服务器。这避免了尝试使用 Windows NT 服务器固有的稳定性问题。Samba 还能提供 NT 域服务，进一步减少对 Windows NT 系统的需求，从而提高计算环境的可靠性。

Samba 通过 `smb.conf` 文件进行配置。我们参考随软件提供的 Samba 文档。

- `http://www.samba.org/`

## NetNews

网络新闻（NetNews）是网上主要的讨论论坛。尽管它得到了 IRC（互联网中聊天）和基于 Web 的邮件存档浏览器的补充，但 NetNews 仍然处理互联网上的大部分讨论流量。

网络新闻传输协议（NNTP）是新闻服务器相互传递最新帖子的的机制。有两个软件包可以在组织内部提供 NetNews：`INN` 和 `nntp`，它们不应与同名的协议混淆。`INN` 使用更广泛，维护也更积极。

## 远程 Shell

有几个程序用于登录远程计算机并建立交互会话。最旧且最流行的是 `telnet`，它几乎适用于任何运行 IP 的计算机。`r-commands`（或远程 shell 程序）是为伯克利系统发行编写的，在大多数 Unix 系统上可用。`r-commands` 包括 `rsh`、`login` 和 `rep`，它们通常是一个巨大的安全漏洞。基于主机的验证的巨大优势是不进行密码挑战。这允许从 shell 脚本中调用 `r` 和 `rep`，从而实现网络任务的自动化。安全 Shell（`ssh`）利用公钥加密来与经过验证的主机建立会话。`ssh` 扩展了 `r-commands` 的功能，包括端口转发和 X Window 显示转发。这允许用户执行各种命令，并通过 `ssh` 为远程机器提供加密路径。`rsync` 文件分发工具和 `cv` 版本控制系统是可以使用 `ssh` 命令为自身提供安全通道的示例。
