
```c
/* 向由文件描述符 SOCKET_FD 提供的套字写入 TEXT。 */
void write_text(int socket_fd, const char* text)
{
    /* 写入字符串的字节数，包括 NUL 终止符。 */
    int length = strlen(text) + 1;
    write(socket_fd, &length, sizeof(length));
    /* 写入字符串。 */
    write(socket_fd, text, length);
}

int main(int argc, char* argv[])
{
    const char* socket_name = argv[1];
    const char* socket_message = argv[2];
    int socket_fd;
    struct sockaddr_un name;

    /* 创建套字。 */
    socket_fd = socket(PF_LOCAL, SOCK_STREAM, 0);
    /* 将服务器名称存储在套字地址中。 */
    name.sun_family = AF_LOCAL;
    strcpy(name.sun_path, socket_name);
    /* 连接套字。 */
    connect(socket_fd, &name, SUN_LEN (name));
    /* 将命令行上的文本写入套字。 */
    write_text(socket_fd, message);
    close(socket_fd);
    return 0;
}
```

在客户端发送消息之前，它通过通过发送变长变量的字节来发送该文本的长度。同样，服务器通过从套字读取到一个整数变量中来获取文本长度。这允许服务器分配一个适当大小的缓冲区来存放文本。

### 标准端口号

按照惯例，Web 服务器在 80 端口监听连接。大多数互联网网络服务都与一个标准端口号相关。例如，使用 SSL 的服务器在 443 端口监听连接，而许多服务器（使用 SMTP 的）使用 25 端口。

在 GNU/Linux 系统上，协议/服务名称与标准端口号之间的对应关系列在 `/etc/services` 文件中。第一列是协议或服务名称。第二列列出端口号和连接类型：`tcp` 用于面向连接，`udp` 用于数据。

如果您使用域域套接字（Internet-domain sockets）实现自定义网络服务，请使用大于 1024 的端口号。

例如，要从网站 www.codesourceury.com 获取主页，涉及以下操作：

```
% .socket-inet www.codesourceury.com
<html>
    <meta http-equiv="Content-Type" content="text/html;charset=iso-8859-1">
..
```

### 5.5.7 套接字对 (Socket Pairs)

之前之前，`pipe` 函数为管道的开头和结尾创建两个文件描述符。管道的限制是因为文件描述符必须由相关进程使用，因为通信是单向的。`socketpair` 函数为同一台计算机上两个连接的套接字创建两个文件描述符。这些文件描述符描述了相关进程之间的双向通信。

它的前三个参数与 `socket` 调用相同：它们指定了域、连接样式和协议。最后一个参数是一个包含两个整数的数组，其中填充了两个套接字的文件描述符，类似于 `pipe`。当您调用 `socketpair` 时，必须指定 `PF_LOCAL` 为域。

# 6 设备

LINUX 与大多数操作系统一样，通过称为**设备驱动程序**的模块化软件组件与**硬件设备**交互。设备驱动程序向操作系统隐藏了硬件设备通信协议的特殊性，并允许系统通过标准化接口与设备交互。

在 Linux 下，设备驱动程序是内核的一部分，可以是静态链接到内核中的，也可以按需加载内核模块。设备驱动程序作为内核的一部分运行，用户进程无法直接访问。Linux 提供了一种机制，进程可以通过类文件对象与设备驱动程序进行通信——并通过驱动程序与硬件设备进行通信。这些对象出现在文件系统中，程序可以像对待普通文件一样对它们进行读取和写入。通过使用 Linux 的低级 I/O 操作（见附录 B，“低级 I/O”）或标准 C 库的 I/O 操作，程序可以通过这些类文件对象与硬件设备通信。

Linux 还提供了几个直接与内核通信而非与驱动程序通信的类文件对象。这些对象没有到硬件设备；相反，它们提供了对应用程序和系统程序各种特殊行为。

## 访问设备时务必小心！

本章的技术提供了对运行在 Linux 内核中的设备驱动程序的直接访问，并通过它们连接到系统的硬件设备。请谨慎使用这些技术，因为误操作可能会损害或损坏 GNU/Linux 系统。

请特别注意侧栏“块设备的危险”。

### 6.1 设备类型

设备文件不是普通文件——它们不代表基于磁盘的系统数据区域。相反，从设备文件读取或写入设备文件的数据会传递给相应的设备驱动程序，从那里传递到底层设备。设备文件有两种：

- **字符设备**（character device）代表读取或写入串行数据字节流的硬件设备。串口和并行端口、磁带驱动器、终端设备和声卡都是字符设备的示例。

- **块设备**（block device）代表以固定大小块读取或写入数据的硬件设备。与字符设备不同，块设备提供对存储在设备上数据的随机访问。磁盘驱动器是块设备的示例。

典型应用程序将使用块设备。虽然磁盘被表示为块设备，但每个磁盘分区的内容通常包含一个文件系统，该系统被挂载到 GNU/Linux 的根文件系统树上。只有实现文件系统的内核代码需要直接访问块设备；应用程序通过普通文件和目录访问磁盘内容。

## 块设备的危险

块设备提供了对数据的直接访问。尽管大多数 GNU/Linux 系统配置为防止 root 进程访问这些设备，但 root 进程可能会破坏它们。务必非常小心访问这些设备。应用程序有时会使用字符设备，我们将在接后的章节中讨论其中几种。

### 6.2 设备号

Linux 使用两个数字识别设备：**主设备号**（major device number）和**次设备号**（minor device number）。主设备号指定对应于哪个驱动程序。次设备号的含义取决于设备。例如，次设备号 3 对应主 IDE 控制器。一个 IDE 控制器有两个设备（磁盘、磁带或 CD-ROM 驱动器）连接到上面；“主”设备次设备号为 0，“从”设备次设备号为 64。单独分区（如果设备支持分区）由次设备号 1、2 等表示。

主设备号列在 Linux 内核源码中。在任何 GNU/Linux 发行版中，此文档可以在 `/usr/src/Linux/documentation/devices.txt` 找到。特殊条目 `/proc/devices` 列出了与加载到内核的活动设备驱动程序对应的主设备号。

### 6.3 设备条目

设备条目在许多方面类似于普通文件。你可以使用 `mv` 命令移动它，使用 `rm` 命令删除它。然而，如果你尝试使用 `cp` 复制设备条目，你将从设备读取字节（如果设备支持读取）并将其写入目标文件。如果你尝试覆盖设备条目，你将写入到相应的设备。

你可以使用 `mknod` 命令（运行 `man 1 mknod` 查看帮助页）或 `mknod` 系统调用（运行 `man 2 mknod` 查看帮助页）在文件系统中创建设备条目。在文件系统中创建设备条目并不意味着设备驱动程序或硬件存在或可用；设备是与驱动程序通信的门户。只有超级用户进程可以使用 `mknod` 命令或 `mknod` 系统调用创建块设备和字符设备。

使用 `mknod` 命令创建设备时，将第一个参数指定为条目在文件系统中出现的路径。对于第二个参数，指定 `b` 表示块设备或 `c` 表示字符设备。将主、次设备号作为第三和第四参数提供。例如，此命令在当前目录下创建一个名为 `lp0` 的字符设备条目。该设备的主设备号为 6，次设备号为 0。

```
% mknod ./lp0 c 6 0
```

#### 6.3.1 /dev 目录

按照习惯，GNU/Linux 系统包含一个 `/dev` 目录，其中包含了 Linux 识别的全部字符设备和块设备条目。`/dev` 中的条目具有与主设备号和次设备号对应的标准名称。

例如，连接到主 IDE 控制器的主设备，其主次设备号分别为 3 和 0，其标准名称为 `/dev/hda`。该设备支持分区，其上的分区次设备号为 1，标准名称为 `/dev/hda1`。你可以在你的系统中检查这是否属：

```
ls -l /dev/hda /dev/hda1
crw-rw---- 1 root disk      3, May 5 1998 /dev/hda
crw-rw---- 1 root disk      3, May 5 1998 /dev/hda1
```

同样，`/dev` 也包含一个我们之前使用的打印端口字符设备条目：

```
ls -l /dev/lp0
crw-rw---- 1 root daemon      6, May 5 1998 /dev/lp0
```

在大多数情况下，你不应该使用 `mkod` 来创建自己的设备条目。相反应该使用 `/dev` 中的条目。非超级用户程序别无选择使用设备条目。通常，只有系统管理员和处理特殊硬件设备的开发者才需要创建设备条目。大多数 GNU/Linux 发行版都包含了工具，帮助管理员创建具有正确名称的标准设备条目。

### 6.3.2 通过打开文件访问设备

如何使用这些设备？对于字符设备，可以非常简单：像打开普通文件一样打开设备，并对其读取或写入。你甚至可以使用普通文件命令（如 `cat`）或你 shell 的重定向语法将数据发送到设备。

例如，如果你有一个打印机连接到计算机的第一个并行端口，可以通过将文件直接发送到 `/dev/lp0` 来打印文件。要打印 `document.txt` 的内容，请调用：

```
$ cat document.txt > /dev/lp0
```

你必须拥有写入设备条目的权限才能成功；许多 GNU/Linux 系统的权限设置为只有 root 和系统的守护进程（lpd）可以写入文件。此外，打印机输出的内容取决于打印机如何解释你发送的数据。某些打印机会打印发送给它们的纯文本文件，而另一些则不会。PostScript 打印机会渲染并打印发送给它们的 PostScript 文件。

在程序中，向设备发送数据就像示例所示简单。这段代码片段使用低级 I/O 函数将缓冲区的内容发送到 `/dev/lp0`。

```
int fd = open("/dev/lp0", O_WRONLY);
write(fd, buffer, length);
close(fd);
```

### 6.5 特殊设备

Linux 还提供了不对应于硬件设备的特殊字符设备。这些条目都使用主设备号 1，该号与 Linux 内核的内存设备相关，而不是某个设备驱动程序。

#### 6.5.1 /dev/null

条目 `/dev/null`，即空设备（null device），非常方便。它有两个用途；你可能至少熟悉第一个：

- Linux 会丢弃任何写入到 `/dev/null` 的数据。一个常用的技巧是在某些不需要输出的语境下，将 `/dev/null` 指定为输出文件。

例如，要运行一个命令并丢弃其标准输出（而不打印或将其写入文件），请将标准输出重定向到 `/dev/null`：

```
% verbose_command > /dev/null
```

- 从 `/dev/null` 读取内容将导致文件结束符（EOF）。例如，如果你使用 `open` 打开了 `/dev/null` 的文件描述符，并尝试从该文件描述符进行读取，`read` 将不会读取任何字节并返回 0。如果你从 `/dev/null` 拷贝内容到另一个文件，目标文件将是一个零长度的文件：
