
`mailRoutingAddress`用于邮件应发送到的目的地

`sendmail`还支持标签`mailHost`，如果存在，则将邮件路由到指定主机的MX指定邮件处理器。收件人地址仍为`mailRoutingAddress`标签的值。

LDAP数据库条目支持通配符条目`@domain`，可将发往指定域名的任何人的邮件重新路由（这与`virtusertable`中的做法相同）。

默认情况下，发往`user@host1.mydomain`的邮件会首先触发对`user@host1.mydomain`的查找。如果失败，`sendmail`会尝试`@host1.mydomain`，但不会尝试`user@mydomain`。包含以下行

```
LDAPROUTE_EQUIVALENT('host1.mydomain')
```

也会尝试键`user@mydomain`和`@mydomain`。此功能使单个数据库能够在复杂站点上路由邮件。你也可以从文件中获取`LDAPROUTE_EQUIVALENT`子句的条目，这使得该功能非常实用。该形式的语法为

```
LDAPROUTE_EQUIVALENT_FILE('filename')
```

`ldap_routing`功能的附加参数可让你指定有关LDAP模式的更多细节，并控制具有`+detail`部分的收件人名称的处理。如往常一样，请参阅`cf/README`文件以获取确切细节。

### Masquerading 功能

电子邮件地址通常由用户名、主机和域名组成，但许多站点不希望其主机的名称暴露在互联网上。`MASQUERADE_AS`宏可让你为其他机器指定一个单一身份以隐藏其后。所有邮件似乎都源自指定的机器或域名。这对普通用户来说是可以的，但出于调试目的，系统用户如`root`应被排除在伪装之外。

例如，序列

```
MASQUERADE_AS('atrust.com')
EXPOSED_USER('root')
EXPOSED_USER('Mailer-Daemon')
```

会将邮件标记为来自`user@atrust.com`，除非是由`root`或邮件系统发送的；在这些情况下，邮件会携带源主机的名称。`MASQUERADE_AS`只是庞大伪装冰山的尖端，其下延伸着十几种变体和例外。`allmasquerade`和`masquerade_envelope`功能（与`MASQUERADE_AS`结合使用）可隐藏恰到好处的本地信息。详情请参阅`cf/README`。

### MAIL_HUB 和 SMART_HOST 宏

伪装使所有邮件看起来都来自单个主机或域名，通过重写头信息以及可选的信封。但大多数站点希望所有邮件实际上都来自（或发往）一台单一机器，以便他们可以控制病毒、垃圾邮件和公司机密的流动。你可以通过DNS中的MX记录、用于传入邮件的`MAIL_HUB`宏以及用于传出邮件的`SMART_HOST`宏的组合来实现这种控制。

例如，在第754页的架构图中，MX记录会将来自互联网的入站邮件指向位于隔离区（DMZ）中的MTA。在验证收到的邮件不含病毒和垃圾邮件且发送给有效的本地用户之后，邮件可以通过以下定义被中继到内部路由MTA进行投递：

```
define(`MAIL_HUB', `smtp:routingMTA.mydomain')
```

同样，客户端机器会将其邮件中继到其配置中`nullclient`特性所指定的`SMART_HOST`。然后，`SMART_HOST`可以过滤病毒和垃圾邮件，从而让你的站点发出的邮件不会污染互联网。

`SMART_HOST`的语法与`MAIL_HUB`类似，默认投递代理同样是`relay`。例如：

```
define(`SMART_HOST', `smtp:outgoingMTA.mydomain')
```

你可以使用同一台机器同时作为入站和出站邮件的服务器。`SMART_HOST`和`MAIL_HUB`都必须允许中继，前者允许来自你域内客户端的中继，后者允许来自DMZ中MTA的中继。

### 客户端配置

如果你的站点遵循邮件系统设计一节（第753页）中展示的范例，那么你的大多数机器将需要被配置为客户端，它们只提交用户生成的出站邮件，完全不接收邮件。`sendmail`的一个`FEATURE`——`nullclient`恰好适合这种情况。它会创建一个配置文件，通过SMTP将所有邮件转发到中心集线器。在`VERSIONID`和`OSTYPE`行之后，整个配置文件简化为：

```
FEATURE(`noconanify')
FEATURE(`nullclient', `mailserver')
EXPOSED_USER(`root')
```

其中`mailserver`是你的中心集线器的名称。`noconanify`特性告诉`sendmail`不要进行DNS查找，也不要使用完全限定域名重写地址。所有这些工作都将由`mailserver`主机完成。该特性类似于`SMART_HOST`，并假定客户端将伪装（`MASQUERADE`）为`mailserver`。`EXPOSED_USER`子句将`root`排除在伪装之外，从而方便调试。

`mailserver`机器必须允许其`null`客户端进行中继。该权限在`access_db`中授予，参见第785页的描述。`null`客户端必须具有指向`mailserver`的关联MX记录，并且还必须包含在`mailserver`的`cw`文件（通常是`/etc/mail/local-host-names`）中。这些设置允许`mailserver`接受发给该客户端的邮件。

如果客户端机器上的用户代理可以被配置为使用端口587提交邮件，则`sendmail`应该以MSA模式运行（不带`-bd`标志）。否则，你可以以守护进程模式（`-bd`）运行`sendmail`，但需要设置`DAEMON_OPTIONS`配置选项，使其仅监听回环接口上的连接。

SUSE在`/etc/mail/linux.nullclient.mc`中提供了一个`null`客户端的示例`.mc`文件。填入你的邮件服务器名称，构建`sendmail.cf`文件，就完成了。

### 配置选项

你可以使用`m4`的`define`命令设置配置文件选项。可作为`m4`变量访问的完整选项列表（及其默认值）见`cf/README`文件。

对于不太担心安全、也不太在意性能的典型站点来说，默认值已经足够。默认设置通过关闭中继、要求地址使用完全限定域名、要求发件人域名解析为IP地址来保护你免受垃圾邮件的侵扰。如果你的邮件集线器机器非常繁忙且处理大量邮件列表，你可能需要调整一些性能参数。

下一页的表20.11列出了一些你可能需要调整的选项（约占175多个配置选项的10%）。其默认值显示在括号中。为节省空间，选项名称省略了`conf`前缀；例如，`FALLBACK_MX`选项实际上名为`confFALLBACK_MX`。我们将表格分成几个小节，以标识变量所解决的问题类型：资源管理、性能、安全与垃圾邮件抑制、以及其他选项。有些选项适合多个类别，但我们只列出一次。

### sendmail中与垃圾邮件相关的特性

`sendmail`具有多种特性和配置选项，可以帮助你控制垃圾邮件和病毒：

- 控制第三方（也称混杂式或开放式）中继的规则；也就是说，某个站外用户利用你的邮件服务器向另一个站外用户发送邮件。垃圾邮件发送者经常利用中继来掩盖其邮件的真实来源，从而避免被ISP发现。中继还让垃圾邮件发送者能够使用你的计算资源，节省他们自己的资源。
- 用于过滤收件人地址的访问数据库。该特性有点像电子邮件的防火墙。
- 黑名单，列出了开放的邮件中继和已知对垃圾邮件友好的站点，`sendmail`可以据此进行查对。
- 限流器，当检测到某些类型的不良行为时，可以降低邮件接收速度。
- 通过称为`libmilter`的通用邮件过滤接口进行邮件头检查和输入邮件过滤。它可以对邮件头和内容进行任意扫描，并允许你拒绝与特定配置文件匹配的消息。`Milter`数量众多且功能强大；参见`milter.org`。
