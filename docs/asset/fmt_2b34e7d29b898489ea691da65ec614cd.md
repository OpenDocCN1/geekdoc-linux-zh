
`fg` 命令后跟着百分号和作业编号（称为作业规格）就是诀窍。如果我们只有一个后台作业，作业规格是可选的。要终止 `xlogo`，请按 `CTRL-C`。

## 停止（暂停）进程

有时我们想停止一个进程而不终止它。这通常是为了允许前台进程移动到后台。要停止前台进程并放入后台，按下 `CTRL-Z`。让我们试一下。在命令提示符下输入 `xlogo`，按回车，然后按 `CTRL-Z`：

```
@me@linux ~ $ xlogo

[1]+ Stopped      xlogo

@me@linux ~-$
```

停止 `xlogo` 后，我们可以尝试调整 `xlogo` 窗口大小来验证进程已停止。我们会发现，虽然我们可以调整窗口，但标志不会重绘，这表明进程已停止。我们可以使用 `fg` 命令在前台继续执行程序，或者使用 `bg` 命令在后台恢复程序执行：

```
@me@linux ~$ bg %1

[1]+ xlogo &
@me@linux ~-$
```

与 `fg` 命令一样，如果只有一个作业，作业规格是可选的。
从命令行移动图形化程序但忘记通过附加 `&` 将其放入后台。

我们为什么想从命令行启动图形化程序呢？有两个原因。

- 我们想要的进程可能没有列在窗口管理器中（例如 `xlogo`）。
- 通过命令行启动程序，我们可能看到在图形化启动时看不到的消息。

## 修改进程优先级

正如我们在 `ps` 命令（以及 `top`）中看到的，有一个属性叫做 `niceness`，它指的是分配给进程的调度优先级。`Niceness` 的范围从 `-20`（最有利）到 `19`（最不利），默认值为零。让我们看看它是工作的。假设我们有一个名为 `cpu-hog` 的程序，我们想以比正常的优先级运行它。我们可以如下使用 `nice` 启动程序：

```
me@linuxbox ~js nice -n 10 cpu-hog
```

同样，如果我们有一个需要更高优先级的 `must-run-fast` 程序，我们（作为超级用户）可以这样做：

```
sudo nice -n 10 must-run-fast
```

很少需要以增加优先级运行命令，这样做会有导致系统进程所需 CPU 时间的风险，所以请小心。

`renice` 命令调整正在运行进程的优先级。例如，如果我们启动了 `cpu-hog` 程序并想在之后增加它的 `niceness`，可以这样做：

```
me@linuxbox ~js renice -n 19 379215
PID TTY             TIME
379287 pts/9        00:00:00 bash
379215 pts/9        00:00:00 cpu-hog
379223 pts/9        00:00:00 ps
```

## 信号

`kill` 命令用于终止需要杀掉的程序（即某种形式的暂停或终止）。有一个例子：

```
me@linuxbox ~js xlogo &
[1] 28401
me@linuxbox ~js kill 28401
[1]+ Terminated
 xlogo
```

我们首先在后台启动 `xlogo`。shell 打印作业规格和后台进程的 PID。接下来，我们使用 `kill` 命令并指定进程的 PID。

...想要终止。我们也可以使用作业规格（jobspec，例如 `%1`）而不是 PID 来指定进程。

虽然这些操作都非常直观，但其中意义不止于此。`kill` 命令并不完全是“杀死进程”；相反，它是发送信号。信号是操作系统与程序通信的多种方式之一。我们之前已经通过使用 `CTRL-C` 和 `CTRL-Z` 看到信号的作用了。当终端接收到这些按键之一时，它会向前台程序发送一个信号。在 `CTRL-C` 的情况下，会发送一个名为 `INT`（中断）的信号；对于 `CTRL-Z`，会发送一个名为 `TSTP`（终端停止）的信号。反过来，程序会“监听”信号并在接收到信号时可能相应的行动。程序能够监听并响应信号，这一事实允许程序在接收到终止信号时执行诸如保存正在进行的工作等操作。

## 使用 kill 向进程发送信号

`kill` 命令用于向程序发送信号。它最常用的语法格式如下：

```
kill [-signal] PID...
```

如果在命令行上没有指定信号，默认将发送 `TERM`（终止）信号。`kill` 命令经常用于发送表 10-5 所示的信号。

### 表 10-5：常用信号

| 数字 | 名称 | 含义 |
| :--- | :--- | :--- |
| 1 | `HUP` | 挂起（Hang up）。这是旧时代的遗留，当时终端通过电话线和调制调器连接到远程计算机。该信号用于指示程序控制终端已“挂起”。可以通过关闭终端会话来演示此信号的效果。运行在终端的前台程序将接收该信号并终止。许多守护进程（daemon）也使用此信号来触发重新初始化。这意味着当守护进程收到此信号时，它将重启并重新读取其配置文件。`Apache` Web 服务器就是一个以此使用 `HUP` 信号的守护进程示例。可以通过 `nohup` 命令（在后续章节中讨论）启动进程，使其对 `HUP` 信号免疫。 |
| 2 | `INT` | 中断（Interrupt）。这与从终端发送的 `CTRL-C` 执行相同的功能。它通常会终止程序。 |
| 9 | `KILL` | 杀死（Kill）。此信号是特殊的。程序可能会选择不同的方式处理发送给它们的信号（包括完全忽略它们），但 `KILL` 信号永远不会真正发送给目标程序。相反，内核会立即终止进程。当进程以这种方式终止时，它没有机会进行“清理”工作或保存其工作。因此，只有在其他终止信号失败时，才作为最后手段使用 `KILL` 信号。 |
| TERM | 终止（Terminate）。这是 `kill` 命令发送的默认信号。如果程序仍然足够“活跃”以便接收信号，它将将会终止。 |
| CONT | 继续（Continue）。这会在 `STOP` 或 `TSTP` 信号后恢复进程。该信号由 `bg` 和 `fg` 命令发送。 |
| STOP | 停止（Stop）。此信号导致进程暂停而不终止。`KILL` 信号不会发送给目标进程，因此它无法被忽略。 |
| TSTP | 终端停止（Terminal stop）。这是当按下 `CTRL-Z` 时由终端发送的信号。与 `STOP` 信号不同，`TSTP` 信号会被程序接收到，但程序可能会选择忽略它。 |

让我们尝试一下 `kill` 命令：

```
$me@$ xlogo [1] 13546
$me@$ kill -1 13546
[1]+ Hangup xlogo
```

在这个示例中，我们在后台启动了 `xlogo` 程序并使用 `kill` 向它发送了 `HUP` 信号。`xlogo` 程序终止，shell 表明后台进程已接收到挂起信号。在消息出现之前，我们可能需要按几次回车。注意，信号可以通过数字或名称指定，包括带有 `SIG` 前缀的名称：

```
$me@$ xlogo &
[1] 13601
$me@$ kill -INT 13601
[1]+ Interrupt xlogo
$me@$ xlogo &
[1] 13608
$me@$ kill -SIGINT 13608
[1]+ Interrupt xlogo
```

重复上一个示例并尝试其他信号。记住，我们也可以用 `jobsecs` 代替 `PID`。

进程像文件一样拥有所有者，你必须是进程的所有者（或超级用户）才能使用 `kill` 向其发送信号。除了表 10-5 所示的最常用于 `kill` 的信号列表外，还有表 10-6 所示的系统频繁使用的其他信号。

### 表 10-6：其他常用信号

| 数字 | 名称 | 含义 |
| --- | --- | --- |
| 3 | QUIT | 退出。 |
| 11 | SEGV | 段错误（Segmentation violation）。如果程序非法使用内存，则会发送此信号，即如果它尝试向未被允许写入的地方写入。 |
| 28 | WINCH | 窗口变化（Window change）。这是系统在窗口大小发生变化时发送的信号。某些程序（如 `tap` 和 `less`）将响应此信号，通过重绘自身来适应新的窗口尺寸。 |

对于好奇的读者，可以在 `man 7 signals` 页面找到完整的信号列表。

## 使进程挂起

如所述，许多程序在关闭时会对收到 `HUP` 信号时做出响应。为了防止这一点，我们可以使用 `nohup` 命令。这允许程序在终端断开后继续运行。这里有一个示例：

```
$me@$ xlogo &
[1] 13601
$me@$ nohup xlogo &
[1] 13602
```

当我们使用 `nohup` 时，shell 不向进程发送 `HUP` 信号，输出被重定向到名为 `nohup.out` 的文件中。

## 使用 killall 向多个进程发送信号

还可以使用 `killall` 向匹配用户名的多个进程发送信号。其语法如下：

```
killall [-signal] name...
```

为了演示，我们将启动多个 `xlogo` ：

```
$me@$ xlogo &
[1] 18801
$me@$ xlogo &
[2] 18802
$me@$ killall -INT xlogo
[1]+ Interrupt xlogo
[2]+ Interrupt xlogo
```

## 关闭系统

关闭系统的过程涉及有序终止所有进程以及执行一些清理工作（如同步文件系统）。四个命令可以执行此操作：`halt`、`poweroff` 和 `reboot`。前两个自而易见，通常不带命令行选项使用。这里有一个示例：

```
sudo halt now
```

它通常用于重启系统：

```
sudo reboot now
```

延迟可以通过多种方式指定。详情请参阅 `shutdown` `man` 页面。一旦执行 `shutdown` 命令，将向所有登录用户广播消息，警告他们即将发生的事件。

## 环境

正如我们之前讨论过的，shell 在我们的 shell 会话期间会维护一组信息，被称为环境。程序使用存储在环境中的数据来确定有关系统配置的事实。虽然大多数程序使用配置文件来存储程序设置，但某些程序还会查找存储在环境变量中的值来调整其行为。通过这一点，我们可以使用环境来定制我们的 shell 体验。

在本章中，我们将使用以下命令：

- `printenv`: 打印环境的部分或全部。
- `set`: 设置 shell 选项。
- `export`: 将环境变量导出到后续执行的程序中。
- `alias`: 为命令创建别名。
- `source`: 在当前 shell 中执行文件中的命令。

### 环境中存储了什么？

shell 在环境中存储了两种基本类型的数据；尽管在 `bash` 中，这些类型初看之下很大程度上是无法区分的。它们是环境变量和 shell变量。shell变量是由当前 `bash` 实例放置其中的数据，而环境变量是其他所有内容。除了变量外，shell 还存储了一些程序化数据，即别名（aliases）和 shell 函数（shell functions）。我们在第 5 章涵盖了别名，将在第四部分涵盖 shell 函数（与 shell 脚本相关）。

### 检查环境

要查看环境中存储了什么内容，我们可以使用 `bash` 中的内置命令 `set` 或 `printenv` 程序。`set` 命令将显示 shell 变量和环境变量，而 `printenv` 只显示后者。由于环境内容的列表相当长，最好将每个命令的输出通过到 `less`。

```bash
$me@linuxbox~$ printenv | less
```

这样做，我们应该会得到类似下面的内容：

```bash
$me@linuxbox~$ USER
```

`set` 命令在不带选项或参数使用时，将显示 shell 变量和环境变量，以及任何定义的 shell 函数。与 `printenv` 不同，它的输出会礼貌地按字母顺序排序。

```bash
@me@linuxbox~$ set | less
```

```bash
@me@linuxbox~$ echo HOME

```

```bash

alias vi='vi'
alias which='alias | /usr/bin/which --tty-only --read-alias --show-dot --show-tilde='
```

### 环境是如何建立的？

当我们登录系统时，`bash` 程序开始启动并运行一系列被称为“启动文件”（startup files）的脚本，这些脚本定义了所有用户共享的默认环境。随后是家目录下的启动文件，它们定义了我们的个人环境。确切的顺序取决于 shell 的类型。有两种：

**登录 shell（login shell）** 我们会被提示输入用户名和密码的。这发生在我们登录图形环境时（例如）。在我们启动终端会话时也会这样做。

**非登录 shell（non-login shell）** 通常发生在我们在 GUI 中启动终端会话时。登录 shell 读取一个或多个启动文件，如表 11-2 所示。

### 表 11-2：登录 shell 的启动文件

| 文件 | 内容 |
|---|---|
| `/etc/profile` | 适用于所有用户的全局配置脚本。 |
