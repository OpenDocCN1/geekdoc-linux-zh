还有几个选项可以执行打包过程中的不同阶段而不生成`rpm`包。这些构建命令的格式如下：

```bash
rpm [build-options] specfile
```

`-bp`选项执行`prep`阶段，解压存档中的源文件并对其应用补丁。`-bc`选项执行`prep`阶段和`build`阶段，将文件解压到`BUILD`目录并将源码编译为可执行程序。`-bi`选项执行`prep`、`build`和`install`阶段。它会在你的系统上解压、编译并安装软件文件。但它不会创建`rpm`包。这些选项的设计旨在根据你所处的阶段在过程中执行不同的任务。如果你只想解压存档并对软件进行修改，可以使用`-bp`选项。`-bl`选项检查软件所需的所有文件都存在。

如果你已经有了源码文件的`rpm`包，可以使用`--rebuild`选项为二进制文件创建包。此选项将安装源码文件、编译程序、安装它，然后将程序纳入`rpm`二进制包。使用`--recompile`选项，它只会编译并安装程序而不创建二进制包。

| 选项 | 功能 |
| :--- | :--- |
| `-ba` | 同时创建可执行二进制包和源码包。执行`spec`文件中的所有阶段：`prep`, `build`, `install`并创建包。 |
| `-bb` | 仅创建可执行二进制包。执行`spec`文件中的所有阶段：`prep`, `build`, `install`并创建包。 |
| `-bp` | 仅运行`spec`文件中的`prep`阶段(`%prep`)。 |
| `-bl` | 执行“列表”检查。对`spec`文件中的`%files`部分进行宏展开，并检查文件是否存在。 |
| `-bc` | 同时执行`prep`和`build`阶段，解压并编译软件(`%prep`和`%build`)。 |
| `-bi` | 执行`prep`、`build`和`install`阶段，解压、编译并安装软件(`%prep`, `%build`和`%install`)。 |
| `--short-circuit` | 跳到指定阶段，不执行之前的阶段。仅在`-bc`和`-bi`时有效。 |
| `--clean` | 在制作包后删除构建树。 |
| `--test` | 不执行任何构建阶段。用于测试`spec`文件。 |
| `--recompile source_package_file` | `rpm`安装源码包并执行`prep`、编译和`install`。 |
| `--rebuild source_package_file` | `rpm`首先安装指定的源码包，执行`prep`、编译和`install`，然后重建一个新的二进制包。 |
| `--showrc` | 列出`/etc/rpmrc`文件的配置变量。 |

## 安装包

一旦创建了包，就可以分发它。你可以将其发布到`ftp`站点供下载，或者将其放在磁盘上交给别人。当某人将其放置在系统中时，他们可以使用`rpm`命令配合`-i`选项进行安装。程序将被安装，同时还有任何文档、`man`文件或配置文件。以下示例在系统上安装`bookrec`包。检查不同的目录以确认安装已完成。

```bash
$ rpm -i bookrec-1.0-2.i386.rpm
$ ls /usr/bin/book*
/usr/bin/bookrec
$ ls /usr/doc/bookrec*
/usr/doc/bookrec-1.0-2:
README
$ ls /usr/man/man1/book*
/usr/man/man1/bookrec.1
```

## 开发工具

应用程序是程序员使用多种编程语言之一创建的可执行程序。`Linux`提供了若干实用程序，程序员可以使用它们来控制应用程序的开发。其中最主要的是`make`工具。`make`工具与`Linux`操作系统接口接，提供了一种易于维护和编译程序的方法。`r`允许你更好地控制程序的更改。它将更改组织成不同的版本，这些版本可以存储并在稍后访问。你甚至可以使用`man`工具为你的应用程序创建自己的在线文档。所有这些实用程序都是复杂且强大的工具。

### make 工具

你经常会处理一个包含许多源代码文件的程序。当你开发程序并进行修改时，你需要反复编译该程序。然而，你只需要编译那些你做过更改的源代码文件。链接器将新生成的目标代码文件与之前编译的目标代码文件链接在一起，创建一个新的可执行文件。每次实际上只编译了你的几个源文件，这一事实极大地减少了编译器的工作量。每当你需要一个新的可执行程序时，你不需要重新编译每个源代码文件。
