
```
smb.conf ---> testparam
               |    V
smb <------ network <------ smbd <------ unix
client                               
      tcpdump             log.smb
```

`tcpdump`程序是对网络数据包流量的探测器。Samba.org网站上提供了一个特殊的、感知Samba的`tcpdump`版本。`tcpdump`有助于识别客户端和服务器之间的通信。特别实用的技术是在查看或录制会话时运行`tcpdump`。如果你必须在会话中查看`tcpdump`，请确保过滤掉包（假设你的流量在端口1733上）：

```
$ tcpdump port 1733
```

如果你想限制端口到137、138和139，可以如下操作：

```
$ tcpdump port 137 or port 138 or port 139
```

通常最好不要让`tcpdump`将IP地址转换为名称。这可以通过`-n`关来实现，如下所示：

```
$ tcpdump -n port 137 or port 138 or port 139
```

`tcpdump`在探索程序时非常有用，因为你可以看到请求和响应，以及完整的实际列表。然而，默认的数据包大小（snaplen）不足以包含即使是很小的列表。但是，可以通过`-s`选项增加它，如下：

```
$ tcpdump -s500 port 1733
```

前面的行将`snaplen`增加到500字节。`tcpdump`手页建议使用能够容纳数据的最小`snaplen`。你可以通过运行以下命令来确定快长度的充分性：

```
$ tcpdump -s100 port 137 or port 138 or port 139 -i
```

运行时，从Windows客户端发出命令并查看是否出现以下错误消息：

WARNING: Short packet. Try increasing the snap length

不断增加`s`参数直到这些消息消失。

`tcpdump`是一个强大且复杂的工具。本章仅触了其能力的皮毛。更多信息，请参阅`tcpdump`手页和《Linux Networking Unleashed》。

`tcpdump`和`grep`的各种组合允许你作为测试来提取非常特定的信息。再加上恰当的注入（例如请求访问或列表的客户端），`tcpdump`就变成了一个非常强大的工具。

## ping

<img/3a3dd42091ecc215c9b779bbd31cd990_1.png>

`ping`程序快速确定网络连通性，是一项基本的快速检查。在UNIX或类UNIX机器的脚本中使用`ping`时，最好指定`-c`选项，它决定了在退出前发送包的次数。默认是无限，这在脚本中效果不好。注意在Windows机器上，`ping`发送四个包。以下是一个示例：

```
$ ping -c3 mainserv
```

如果`ping`不工作，这里是需要检查的一些项：

- 损坏的电缆
- 损坏的集线器
- 防火墙
- 配置错误的路由器
- 损坏的网卡 (NIC)
- 代理
- VPN

上述假设服务器主机名为`mainserv`（它及其客户端都属于工作组`mygroup`），拥有带有加密密码的客户端，并有一个在Windows客户端上的UNIX和Samba用户。

## 解决访问问题

如果你以前没读过，请阅读第7章“确定Samba访问”。该章节对这一复杂主题提供了清晰的解释，包括流程图。

第一步是确保问题确实是访问问题。缺乏经验的计算机用户可能会将驱动器映射丢失或无法导航到共享文件夹报告为访问问题，而实际上这可能是浏览问题或驱动器映射丢失导致的。

网络问题可能与访问问题相混淆。`ping`命令对于澄清这一问题有很大帮助。

身份验证问题也可能与访问问题相混淆。有时，建议在Samba服务器上创建一个新的用户和密码（如果你使用的是加密，则同时适用于UNIX和Samba加密），然后使用`smclient`尝试访问。

在转向Windows客户端之前，应在`smclient`级别对访问问题进行正确的测试。

一个非常好的测试是观察访问访问是发生在一个共享上还是所有共享上。是发生在一台机器还是所有机器上？是发生在服务器上吗？

对于共享访问问题，如果怀疑问题可能与UNIX权限有关，可以通过将用户添加到`admin users=`中进行调查。一个非常有意义的测试是尝试用另一个用户访问共享。临时注释掉`valid users=`和`invalid users=`可以得到结果，这在`root`权限下可以更容易进行探测。

## 解决浏览问题

浏览问题可能很困难，但有条理地使用故障排除过程会有极大帮助。第一步是让服务器实现浏览功能。同时，确保网络上的某些机器已接管作为本地浏览器。这通过`nmlookup -SM`命令完成：

```bash
$ nmlookup -SM
querying _MSBROWSE_ on 192.168.100.255
192.168.100.1 MSBROWSE <01>
Looking up status of 192.168.100.1
received 7 names
MAINSERV <00> M <ACTIVE>
MAINSERV M <ACTIVE>
MAINSERV <20> M <ACTIVE>
.._MSBROWSE_ <01> - <GROUP> M <ACTIVE>
MYGROUP <00> - <GROUP> M <ACTIVE>
MYGROUP          <1d> - M <ACTIVE>
MYGROUP          <1e> - <GROUP> M <ACTIVE>
num_good_sends=num_good_receives=0

[root@mainserv]#
```

本地主浏览器的IP地址出现在`__MSBROWSE_<01>`符号的左侧，表示它是本地主浏览器的地址。此外，`<1d>`名称的存在表示其工作组（MYGROUP）有一个本地主浏览器。如果打算让Samba服务器成为本地主浏览器，请确保`smb.conf`的`[global]`节中包含以下行：

```ini
os level=65
local master=yes
preferred_master=yes
```

此外，除非打算让Windows机器之一或另一个Samba机器充当WINS服务器，否则请插入以下行：

```ini
wins_support=yes
```

在域情况下，必须有一个域主浏览器。它在`mblookup -S`命令的输出中显示为`<1b>`名称。如果不存在域主浏览器，则必须采取措施创建一个，要么在NT机器上创建，要么通过在`smb.conf`中插入`domain master=yes`参数来强制Samba机器成为域主状态。更多信息请参见第33章“跨子网浏览”。

## 解决身份验证问题

简单的身份验证问题通过`DIAGNOSIS.txt`预定义的诊断进行隔离。最常见的原因是服务器和客户端加密方式不匹配。其他简单原因包括：在UNIX中没有使用客户端登录的用户名作为用户名，以及在密码中没有使用客户端登录的用户名（如果你使用的是加密密码）。访问问题也可能看起来像身份验证问题。尝试使用几个用户名进行访问。正如许多故障排除工作一样，先从服务器上的`mbclient`和`mblookup`开始，然后向外扩展。

必须使用加密密码来运行Samba。域身份验证会变得复杂。如果Samba服务器设置了`password server=IP`，请尝试将该IP连接到“已知良好”的验证器，可能是另一个Samba服务器，甚至是一个为身份验证目的而配置的测试用Linux/Samba盒子。通过交换机可以将问题隔离在密码服务器或Samba服务器上。至于身份验证问题是否扩展到非Samba服务器，请记住不断缩小问题范围。

> 如果可用，可能会发现使用一台不支持加密密码的旧Win95(A)机器，配合`smb.conf`中的`encrypt passwords=no`是一种快速的排查工具。如果是这样，尝试将旧的操作系统（如Win95(A)、Windows for Workgroups甚至DOS）保留在旧电脑上，专门用于此类测试。

## 常见陷阱、症状和解决方案

快速且有效的故障排除工作的一部分，是记住经常出现的问题及其解决方案。然而，非常重要的一点是，对原因的假设必须经过测试并证明真假。错误的假设是导致快速解决问题的第二大障碍，仅次于间歇性故障。

本节包含了一些常见问题及其产生原因和解决方案。

## 配置文件的更改有时需要重启 Samba

某些`smb.conf`的更改无需重启Samba即可生效，而另一些则需要。除了间歇性问题，故障排除困难的最常见原因是遵循了不准确的假设。应不惜地避免未经测试的假设。因此，建议在每次更改配置文件后重启Samba。这样，系统就处于已知状态，并可以得出可靠的结论。由于反复重启会浪费大量时间并中断工作流，在重启Samba之前，务始终使用`testpart`验证`smb.conf`的合法性。

## 并非所有 smb.conf 配置错误都会产生 testpart 错误

一个特定的实例是，取值必须在枚举中（类型P_ENUM）的参数不会产生错误。这是因为在加载过程中，`loadparam.c`中的`lp1_do_parameter()`会静默忽略任何设置为枚举范围之外值的P_ENUM参数，使其保持为默认值。因此，`do_global_checks()`函数没有发现任何问题。

此外，`testpart`程序不关注`smbd`或`nmbd`。通常这会导致故障隔离损坏，但它可能会让某些错误漏掉。

## 同时使用 wins support= 和 wins server=

因为你读过这本书，所以你不会这样做。然而，如果你被叫去排查别人的Samba服务器，你可能会发现这两个选项都启用了，以确保WINS已启用。在现代版本的Samba中，`testpart`会捕捉到此。

## 关于 lstat 的 SWAT Netscape 错误

这发生在SWAT中。当从Netscape Navigator访问SWAT时，会出现类似下面的错误消息：

```
sh: /usr/bin/lpstat: No file or directory HTTP/1.0 401 Authorization Required WWW-Authenticate: Basic realm="SWAT" Connection: Content-Type: text/html 401 Authorization Required You must authenticate to use this service
```

这是由于编译进去的`print-sysv`程序导致默认的`printcap name=`变为`lpstat`而不是`/etc/printcap`。这在带有发行Samba的Red Hat安装中被观察到，可能会再次发生。解决方案是显式指定`printcap-bsd`和`printcap name=/etc/printcap`。

## 上传速度远于下载速度

检查网卡的速度、双工模式和设置。检查网卡与网络其他部分之间是否存在匹配。网卡的速度和双工模式应与其连接的集线器匹配，且某些网卡对此更为敏感。观察是否某些客户端存在此问题而另一些没有，并找出网卡是否存在某种规律。虽然这种症状可能是由服务器磁盘缓慢引起的，但应首先怀疑网卡。

如果你设置了`null passwords=yes`，尝试将其设置为`no`。

## 其他速度问题

Samba 2.0.5a无意中将`socket options=`设置为`no options`，而不是正常的`TCP_NODELAY`。据报告，这会严重降低某些设置下的Samba性能。解决方案是显式指定`socket options= TCP_NODELAY`。

## 挂载的 Samba 共享间歇性掉线

这是Samba 2.0.5a（可能也包括早期版本）中的一个令人恼的间歇性问题。尽管在2.0.6中似乎消失了，解决方案是升级。

## 从 Samba 1.x 升级时认证中断

Samba 1.x默认使用`security=share`。Samba 2.0及更高版本默认使用`security=user`。如果你想使用`share`，请在Samba 2.x中显式定义。

## 漫游配置文件很奇怪

也许漫游配置文件从一个客户端更新但在另一个客户端没有，或者服务器对配置的更改未能“生效”。也许漫游配置文件仅仅表现出间歇性行为。

如果是这种情况，请同步所有时钟。确保所有时钟具有相同的日期、相同的时区和夏令设置。最简单的方法是通过以下命令：

```
C:\WINDOWS net time \servername /yes
```

参见第16章“将Samba作为你的Windows 98登录机制”，了解有关登录同步问题的详情。

## 浏览经常无效

检查是否存在浏览器选举。临时将主Samba服务器设置为`preferred=no`、`local=no`、`domain=no`、`level=0`和`wins=no`。然后看问题是否减轻。

## 源码故障排除

源代码在许多层面都可以作为故障排除工具。技术要求最低的层面是发现未文档的内容。打印=`和`printcap name=`到底是什么？另一个层面可能是重新编译并安装Samba，以验证安装的二进制文件是否匹配。更进一步的层面涉及通过调试器运行软件。这种主题的一种侵入性变体是插入调试语句——当然，是在备份原始源码之后。最后，可以使用源码修复错误或进行改进。

所有形式的源码故障排除都相对耗时，因此最好先尝试通过代码之外解决问题。然而，如果非代码方法陷入僵局，Samba的开源事实为无法解决的问题提供了出路。下一章“Samba学习工具”介绍了许多使搜索快速且有效的工具。它还讨论了一些实际代码更改的技术。

## 总结

任何系统的故障排除成功取决于使用有效的故障排除过程。大多数有效故障排除过程的主要步骤包括获取和重现系统、执行快速检查、逐步缩小范围范围以及测试解决方案。

每个系统都会为故障排除过程带来其独特的属性。Samba完美地封装了一个复杂的系统，将UNIX网络、安全和文件系统与不断变化的复杂的Windows网络、安全和文件系统互操作。Samba故障排除的独特属性都是积极的：

* Samba是模块化的。
* Samba极其稳定。
* Samba拥有大量的测试点和工具。
* Samba和Linux提供了一种廉价的创建测试系统的手段。
* 大多数Samba配置都在一个地方完成，`smb.conf`。
