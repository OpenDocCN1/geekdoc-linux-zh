
## 题目解析

### 1. C. 主引导记录 (MBR)
`MBR` 可以包含一个大小达 446 字节的引导程序，因此选项 C 是正确的。如果需要更多空间，引导程序必须加载二级引导程序。虽然引导程序被加载到 RAM 中（选项 A），但它不会被永久存储，因为 RAM 是易失性存储。`devboot` 和 `devmem`（选项 B 和 D）是对 Linux 文件系统上文件的引用；它们只有在系统启动并发生许多其他启动过程后才可用。交换分区（选项 E）用作 RAM 的辅助；BIOS 不会寻找引导程序。

### 2. 运行级别 (Runlevel)
`Runlevel` 1 是单用户模式，在引导程序的内核选项中添加数字 1 将在以此运行级别下启动系统，因此选项 C 是正确的。选项 A 和 B 均给出了无效的内核选项，因此是错误的。虽然选项 D 和 E 中指定的 `telinit` 命令会在计算机运行后更改运行级别，且运行级别 1 是单用户模式，但这些命令并不是通过引导程序传递给内核的，所以这两个选项都是错误的。

### 3. D. 内核环形缓冲区
内核环形缓冲区可以通过输入 `dmesg` 查看（通过 `less` 管道是一个很好的补充），它包含了来自内核的消息，包括来自硬件驱动程序的消息。这些消息可能提供关于磁盘未显示的线索，因此选项 D 是正确的。`var/log/diskerror` 文件（选项 A）是虚构的，`mnt/disks`（选项 B）也是。`etc/init.ab` 文件（选项 C）不直接控制磁盘访问，因此可能提供有用信息。选项 E 中指定的文件是 GRUB Legacy 和 GRUB 2 配置文件，它们不包含可以解释磁盘无响应的信息。

选项 D 是正确的 GRUB 2 配置文件。选项 A 是虚构文件；它不存在。虽然 GRUB 2 的某些启动代码可能被写入 MBR（如选项 B 所示），但并不是程序配置文件的所在地。选项 C 和 D 都是 GRUB Legacy 配置文件的可能名称，但该名称并不被 GRUB 2 共享。

### 6. A. initrd 关键字

### 7. 更改系统的目标
更改系统的目标。救援目标指定单用户模式。选项 B 将系统更改为默认目标，该目标可能是单用户模式也可能不是。选项 C 中的 `journalctl` 程序显示 systemd 日志文件。系统程序未用于更改目标（选项 D），且 `start` 命令只启动单个单元，而不是目标（选项 E）。

### 16. A. vi 删除命令
在 `vi` 中，`dd` 是删除行的命令-命令。在此命令前加上数字可以删除相应数量的行。因此，选项 A 是正确的。虽然 `yy` 的工作原理类似，但它是复制（yanks）文本而不是删除它，所以选项 B 是错误的。选项 C 在许多更现代的文本编辑器中有效，但在 `vi` 中不起作用。选项 D 在 `Emacs` 和类似的文本编辑器中有效，但在 `vi` 中不起作用。选项 E 在图形用户界面（GUI）文本编辑器中有效，但在 `vi` 中不起作用。

### 17. D. vi 退出命令
`vi` 命令 `:q!` 正如选项 D 所示。选项 A 和 E 都是错误的。如果如果在 `vi` 的插入模式下输入此命令，选项 B 将是正确的，但问题指定了正在使用命令模式。要实现选项 C，命令应该是 `:wq` 而不是 `:q`。

### 18. `Vi` 的特点
`Vi` 被包含在 Linux 应急系统、嵌入式系统以及其他空间有限的系统中，因为它的可执行文件非常小。相比之下，`Emacs` 是一个庞然大物。因此选项 E 是正确的。与选项 A 相，`vi` 不是基于 X 的程序（尽管有基于 X 的变体）；`Emacs` 可以在文本模式或配合 X 使用。扩展二进制编码交换码 (EBCDIC) 是一种用于非常老旧的主机操作系统的冷门 8 位字符编码系统。在 Linux 上运行时，`vi` 不使用 EBCDIC；此外，EBCDIC 相比美国信息交换标准 (ASCII) 几乎没有甚至优势。因此，选项 B 是错误的。选项 C 中提到的 `Vi` 模式与非英语语言支持无关。选项 D 是反向的；是 `Emacs` 包含了网页浏览器、邮件客户端和其他插件。

### 19. A, B, C. vi 插入模式
在命令模式下输入 `R`（选项 A）会进入插入模式，并配置系统覆盖现有文本。输入 `i` 或 `a`（分别是选项 B 和 C）会进入插入模式，并配置系统插入文本。（`i` 和 `a` 命令的区别在于光标放置的位置；`a` 向后移动一个空格。）在命令模式下输入 `:`（选项 D）会进入 ex 模式，你通常会在冒号后立即输入 ex 模式命令。按下 `Esc` 键（选项 E）从插入模式返回 `vi` 的命令模式。

### 20. B. vi 退出插入模式
`Esc` 键退出 `vi` 的插入模式，如选项 B 指定。输入波浪号 `~` 会向文件中插入字符，因此选项 A 是错误的。`Ctrl+X, Ctrl+C` 组合键退出 `Emacs`，但它不是定义的 `vi` 键序列，所以选项 C 是错误的。`F10` 键和 `Shift+Insert` 组合在 `vi` 中也没有定义，因此选项 D 和 E 都是错误的。

## 第 6 章：配置 X 系统、本地化和打印

### 1. A. X 配置测试
在大多数 Linux 系统上，某些运行级别（runlevels）默认不运行 X，因此使用其中一个配合 `start` 程序（启动运行 X 的程序）可以是快速测试 X 配置更改的有效方法，使得选项 A 正确。`telinit` 程序更改运行级别，与使用 `start` 相比，这是一个漫长的过程，因此选项 B 是错误的。拔掉计算机以避免关闭过程是适得其反的，因为你必须忍受漫长的启动（如果你使用非日志文件系统），而且它可能导致数据丢失，选项 C 是错误的。`startActivity` 工具不检查 X 配置文件的真实性；它从文本模式登录启动 X 运行，使得选项 D 是错误的。重新配置 X 服务器通常不需要网络访问；X 服务器运行在你就坐的电脑上。选项 E 是错误的。

### 2. `XF86Config` 和 `xorg.conf` 文件结构
`XF86Config` 和 `xorg.conf` 文件的设计允许你定义变体或多个组件，并根据选项 D 中指定的结构根据需要地组合或重新组合它们。选项 A、B 和 C 描述的都是虚构结构。选项 E 是错误的，因为 `Xorg-X11` 和 `XFree88` 配置文件使用文本模式结构，而不是二进制结构。

### 3. 垂直刷新率
垂直刷新率范围包含一个最大值，但当分辨率和垂直刷新率要求的水平刷新率高于显示器能处理范围时，该值可能会降低。因此，选项 C 是正确的。分辨率影响最大刷新率，选项 A 是错误的。色彩深度与分辨率和刷新率计算无关，所以选项 B 是错误的。选项 D 和 E 中的计算是伪造的，这些选项是错误的。

### 4. `ServerLayout` 与分辨率设置
选项 E 描述了此选项的正确位置。`ServerLayout` 部分（选项 A）将所有其他部分结合，但没有设置分辨率。`Monitor` 部分中的 `Modeline` 选项（选项 B 描述）定义了一个可能的分辨率，但可能有多个 `Modeline` 条目定义许多分辨率，并且无法保证其中任何一个会被使用。`Modeline` 选项不存在于 `Device` 部分（如选项 C 所示），该部分也不是设置分辨率的地方。没有 `DefaultResolution` 部分（如选项 D 引用）。
