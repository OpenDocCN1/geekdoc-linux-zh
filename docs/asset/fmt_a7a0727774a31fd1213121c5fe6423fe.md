### perldoc.pl: perdoc(1) 的 Web 前端
现在让我们让我们发明一个可能存在的问题。你发现 `perldoc(1)` 非常有用。你希望在家里使用它，但不想通过 `telnet(1)` 窗口使用；你更倾向于使用浏览器。

这是一个简单的任务。下一个列表显示了一个非常简单的 `perldoc(1)` 命令的 `<ISINDEX>` 接口，展示了简单的文本处理和对（潜在危险）用户输入的处理。

注意第一次运行 `perldoc.pl` 时的 URL。然后提交一个查询，并注意 URL。你的提交变成了 URL 查询字符串的一部分。为了对提交的命令进行查找，我们通过正则表达式运行它，然后使用反引用将查询字符串的值赋值给 `$query`。记住，来自用户的输入具有潜在危险性，因此我们需要确保没有在任何 shell 附近允许使用 shell 元字符。正则表达式 `/^(\w+)$/` 将确保变量中只剩下字母数字字符。然而，Perl 的 `-T` 选项会将此数据标记为“受污染的”（tainted），即不可信且具有潜在危险性。通过使用反引用 `$1` 将值赋值给新变量，我们告诉 Perl 我们知道自己在做什么，因此 Perl 允许我们继续操作。

（顺便提一下，值得注意的是，`perldoc(1)` 请求的结果与 `man(1)` 请求的格式相同：带有 `man` 宏的 `nroff`。正因如此，只需对 `perldoc.pl` 进行微小的修改即可创建 `man(1)` 的前端。为什么不尝试一下呢？）

`$ENV{'QUERY_STRING'} =~ /^(\w+)$/; # 仅匹配字母数字和 _`

`$query = $1; # 告诉 perl 我们自己在做什么`

`if ($query) {`

`open(PERLDOC,"man $query");`

`print <<EOD;`

`<!DOCTYPE HTML PUBLIC "-//IETF//DTD HTML//EN">`

`<html>`

` <head>`

` <title>perldoc(1)</title>`

` </head>`

` <body>`

` <h1>perldoc(1) Interface</h1>`

` <pre>`

`while(<PERLDOC>) {`

`print $_;`

`}`

`close(PERLDOC);`

`</pre>`

`</html>`

`EOD`

`}`

### CGI 编程忧虑

你会把你的机器连接到互联网吗，如果你知道这将允许人们运行命令？如果那台机器拥有所有个人数据？

好吧，让我再次强调这种情况是危险的。记住，CGI 程序是运行在你服务器上的程序。如果这些程序可以被骗执行超出你预料的任务，可能会遇到严重的安全问题。幸运的是，Perl 有非常有用的 `-T` 选项，它会告诉你此处的漏洞并拒绝运行。不要在没有指定 `-T` 选项的情况下运行 CGI 程序。

#### 不信任一切
考虑列表 19.6 中的代码。这个运行在你的服务器上的小型 CGI 程序在用户输入电子邮件地址以获取更多信息时被称为 Autoresponder。
