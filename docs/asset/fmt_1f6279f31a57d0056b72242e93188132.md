
网上银行自然是一个应考虑使用容器的领域。事实上，应采取所有可行的预防措施：长密码、定期检查可疑交易、仔细阅读任何声称来自他们的邮件以寻找欺诈迹象。特别是，要检查指向可疑域名的链接。读者经常对我们使用 `bit.ly`（缩短的 URL）持警惕态度。我们认为你应该信任我们（事后无法更改它们），而且 URL 往往长到令人不敢手动转录，所以我们要继续这样做。如果有疑虑，`checkshorturl.com` 或 `urlrx.org` 等服务是你的朋友（但你能信任它们吗？）。

### 更新状态

过去曾记录过更持久的浏览器感染，但现在流氓扩展必须与大量的浏览器安全措施抗争才能隐藏、访问文件或窃取个人数据。话虽如此，如果你对浏览器有任何担忧，安全总是比歉意更重要，既然任何不需要的浏览器附加功能通常都位于用户配置文件中，一个简单的解决方法就是删除旧配置文件并创建一个新配置文件。即使你认为里面没有任何异常，新配置文件也会有干净的缓存，从而可能加快你的浏览体验。

`Firefox` 甚至有一个选项可以直接从浏览器执行几乎相同的功能。只需导航到 `about:support` 并点击页面右上角的“刷新 Firefox”按钮。这将保留你的书签、自动填充信息和密码，但会清除任何扩展和主题。位于配置文件文件夹之外的附加组件将存活。但其偏好设置将被重置。旧配置文件文件夹将备份到桌面，如果问题未解决或你漏掉了什么，其内容可以复制回原始位置。

如果你想用传统方式删除你的配置文件目录，首先使用以下命令找出它的位置：

```
$ cd ~/.mozilla/firefox/
$ ls
```

配置文件目录的名称类似于 `zx9rh0lk.default`。移动它比立即删除它是个好主意，备份你的书签并确保你知道任何保存的密码（或者，更好的做法，将它们保存在密码管理器中）也是个不错的主意，因为这些信息都埋葬在配置文件中。`Cookie` 也存储在这里，因此任何网站偏好设置也将丢失。让我们将配置文件目录移动到我的主目录：

```
$ mv ~/.mozilla/firefox/zx9rh0lk.default ~/OldProfile
```

现在重启 `Firefox`，看看使用一个未使用过的配置文件生活会是什么样子。对于 `Chromium`，默认配置文件目录是 `~/.config/chromium/Default`（如果你使用的是 Google Chrome，则是 `chrome/Default`）。你可以通过访问 `chrome://version` 来检查这确实是活动配置文件的存储位置。将上述命令中的目录替换为此目录，即可获得一个干净的 `Chromium` 配置文件。

如果你使用的是 `Firefox` 同步，或者你的 `Chromium` 配置文件与 Google 账户同步，则书签、扩展和密码会自动同步。这很有用，但万一流氓扩展正在降低你的浏览体验，使用此功能很可能会复活这个问题。所以先尝试在不进行同步的情况下解决问题。如果这解决了你的问题并且一切正常，那么你应该

```
$ rm -rf ~/OldProfile
```

因为它包含加密的密码（如果你使用此功能，可能还包含支付信息），以及知识渊博的攻击者可以用来解密它们的密钥。

尽管每个人都希望不是这样，但仅仅访问一个网页就可能感染某种恶意软件——甚至无需点击、下载或运行任何内容，这种情况始终可能发生。浏览器开发人员付出了巨大的努力来排除这种结果，实际上他们做得非常出色，因为这种类型的恶意软件（除非你运行的是过时的软件）极其罕见。

为了站稳脚跟，浏览器中必须存在漏洞，也许是在字体或图像渲染库中。或者，也许弹窗能够以某种方式渲染，将恶意下载隐藏在关闭按钮后面。一般来说，一个允许直接从浏览器执行任意代码的未修补漏洞价值相当高，因此除非你是像活动人士、政治异见人士或暗网主谋那样的人，能够应对相当多的黑客资源（政府、国家行为者、其他暗网主谋）对此非常感兴趣，否则你可能没事。毕竟，这样的群体为何会冒着失去其 `0-day` 漏洞优势的风险去攻击一个疯子呢？

除了对其跟踪 `Cookie` 的隐私担忧（这不是本文的重点）之外，广告网络过去曾被用来传播恶意软件，通过注入恶意的 `JavaScript` 或 `Flash` 小程序。现在没有理由让后者成为问题：`Flash` 几乎已经死亡，应该将其卸载。`Chromium` 自带一个 `PPAPI` `Flash` 插件，它是高度沙箱化的，并且默认情况下应在启动前提示。通过访问 设置 > 隐私和安全 > 网站设置 > `Flash` 来检查。如果你想要确保，完全可以彻底禁用它。

不，你目前还无法在 `Firefox` 内部运行 `Docker`，但账户容器可以——借用 Wu Tang clans 的话——保护你的脖子。

### 应该使用的浏览器扩展

所有关于扩展和流氓脚本的讨论可能会促使你彻底清除它们，但请不要这样做。其中一些很棒，有些真的能帮助你。对于随意的网页浏览，我们一致推荐某种广告屏蔽工具（别告诉经理！）- Ed）。我们偏爱 `uBlock Origin`，但 `AdBlock Plus`（默认情况下可以提供更顺畅的浏览体验，而不会破坏流行网站）也很受欢迎。必备扩展列表中的第二有力竞争者是 `EFF` 的 `HTTPS Everywhere`，它强制进行 `HTTPS` 传输，保护隐私并防止窥探者嗅探密码。对于极端的浏览安全，`NoScript`（适用于 `Mozilla` 浏览器）是你的朋友。这禁止了所有地方的 `JavaScript`，允许你逐个或按域名将其加入白名单。这被打包在 `Tor Browser` 中，而 `Tor Browser` 正是那些受压迫政权用恶意软件针对的人群所使用的。

不过要注意，启用这个 `NoScript` 后，许多网站的行为会变得不可预测。特别是，它可能会让支付处理器困惑，这可能让你盯着空白页面担心自己是否被扣款。你很可能没有被扣款，但不确定性不值得——确保在试图花钱之前（例如订阅 Linux Format）将其禁用。例如，

### 漏洞与利用

恶意软件始于程序被攻破，终于泪流满面。看看我们如何将其驯服。

缺乏对内存管理、指针和执行栈的一些了解，就很难严格地解释程序是如何被攻陷的，从而使恶意软件得以作恶。现在既非深入探究之时，亦非其地，但我们至少可以提供一种略带含糊其辞的说法，来描述程序可能如何被利用。

程序处理输入，这些输入可能来自用户、网站、其他程序、某件硬件（如键盘或传感器）或文件。为了让程序正确运行，该输入必须是正确格式化的。如果并非如此，它就无法完美地装入内存，可怕的事情就会发生。稍后我们会更具体地说明那些可怕的事情是什么，请耐心等待。因此，某种形式的输入验证应该进行。如果没有，程序将试图消化一些大小或形状不适合其分配内存的东西。可想而知，这种不相容性的结果可能是不可预测的。为了把这个比喻说透，你可能会目睹介于反刍和食物昏迷之间的任何一种数字等价物。这可能是应用程序崩溃或系统减速。

### CVE、Bug 与赏金

报告新发现的漏洞有好办法也有坏办法。在披露给相关供应商或项目之前，这些被称为零日漏洞（zero-day bugs）。零日即披露发生之日。如果你掌握了一个零日漏洞，你可以在 `Twitter` 上吹嘘（并在允许超过 280 字符的某个媒介上发布完整细节）——这会让受影响方，尤其是相关项目，陷入恐慌，并可能引发一波脚本小子（script-kiddie）的攻击。

更好的做法是负责任地私下披露漏洞，以便在事态失控之前推出修复方案。一些项目甚至运行着 `Bug` 赏金计划，以奖励此类努力。漏洞被分配了 ID，列在 `Mitre` 的通用漏洞和暴露（`CVE`）列表中，一旦合适的补丁就位，将在 `https://cve.mitre.org` 提供该漏洞的公开细节。这将迅速被所有优秀的发行版捡起并打包，因为此事刻不容缓。相关方可能不会在合理的时间框架内回应，或者对此不感兴趣，此时公开化就成了一个选择。

在我们撰写本文时，最近可能影响我们的漏洞是 `CVE-2019-5953`，即古老 `wget`（一个通过 `HTTP` 获取事物（很可能是网页）的命令行实用程序）中的缓冲区溢出。使用此工具下载恶意构造的文件可能导致任意代码执行，以及非常糟糕的一天。
