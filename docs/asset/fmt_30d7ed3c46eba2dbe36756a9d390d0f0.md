
# 进程与内核基础

## 进程概述

进程是执行中的程序，由字节模式组成，CPU 将这些字节解释为机器指令（称为“文本”text、“数据”data 和“栈”stack）。许多进程看起来像在同时执行，因为内核调度它们进行执行。进程通过遵循严格的指令序列执行，这些指令是自包含的，且不会跳转到另一个进程；它读取和写入自己的数据段和栈段，但不能读取其他进程的栈和数据段。进程通过系统调用与其他进程通信。

## 进程创建

UNIX 进程是由 `fork()` 系统调用创建的实体。除了进程 0 (`sched`) 外，每个进程都是在其他进程调用 `fork()` 系统调用时创建的。调用 `fork()` 系统调用的进程称为父进程，新创建的进程称为子进程。内核通过进程号 PID 标识每个进程。

## 可执行文件结构

用户编译程序的源代码以创建一个可执行文件，该文件包含几个部分：

- (i) 一组描述文件属性的“头文件”（headers）。
- (ii) 程序文本。
- (iii) 数据的机器语言表示，其中指示了内核应为未初始化数据分配多大的空间，称为 bss（内核在运行时将其初始化为 0）。bss（由符号开始的块）源于 IBM 7090 机器上的一个汇编伪操作。
- (iv) 其他部分，如符号表信息。

## 进程内存布局

内核在执行期间将可执行文件加载到内存中。进程至少由三个部分组成：文本、数据和栈。文本和数据区域对应于可执行文件的文本和数据段，但栈区域是自动创建的，其大小由内核在运行时动态调整。

栈由逻辑栈帧组成，在调用函数时推入，返回时弹出；一个称为栈指针的特殊寄存器指示当前的栈深度。

## 执行模式与栈

在 UNIX 系统中，进程可以在 (i) 用户模式或 (ii) 内核模式下执行。它为每种模式使用独立的栈。

- **用户栈**：包含在用户模式下执行的函数的参数、局部变量和其他数据。
- **内核栈**：包含在内核模式下执行的函数的栈帧。内核中的函数和数据条目指的是内核中的函数和数据，而不是用户程序，但它的结构与用户栈相同。

当进程在用户模式下执行时，进程的内核栈为空。

# 文件系统接口

## 3.2.1 文件表

文件表是一个全局内核结构。

## 用户文件描述符表

它是为每个进程分配的，并标识该进程的所有打开文件。

当进程打开或创建一个文件时，内核会从每个表中分配一个条目，对应于文件 inode。这三个结构中的条目维护了文件的状态以及用户对文件的访问。文件表跟踪文件中字节的偏移量，用户下一次读取或写入将从这里开始；以及允许打开进程的访问权限。

例如，如果一个进程调用：

```
open("/dev/anoop/fl.C", 1);
```

内核获取 `/dev/anoop/fl.C` 的 inode。然后文件表包含该文件的条目。用户文件描述符表包含一个整数类型文件描述符的数字。

内核为 `open()` 和 `create()` 系统调用返回一个文件描述符，该描述符是用户文件描述符表中的索引。这个文件描述符由 `read()`、`write()` 等系统调用使用。

# 进程状态与控制

## 3.3 进程状态

进程可能处于以下状态：

- (iii) 该进程未在执行，但一旦调度器选择它，它就准备好运行。许多进程可能处于这种状态，由调度算法决定哪一个进程将执行。
- (iv) 进程处于睡眠状态。当进程无法继续执行时（例如等待外围设备的 I/O 完成），它会将自己置于睡眠。

只有当进程从“内核态运行”状态移动到“内存中睡眠”状态时，内核才允许上下文切换。在内核模式下运行的进程不会被其他进程抢占；因此，内核有时认为是非抢占的，尽管系统会对处于用户模式的进程进行抢占。

### 上下文切换示例

考虑以下代码：

```
Struct Queue { } * bP, * bP
bP -> head = bP -> tail
bP -> backP = bP
P -> tail = bP
/* context switch */
bP -> head -> backP = bP*
```

## 临界区与中断控制

为了解决并发问题，内核通过提高处理器的执行级别，在进入代码临界区域时防止中断。如果执行任意处理程序可能会导致一致性问题，那么该代码段就是临界区。

内核通过仅允许进程将自己放入睡眠以及防止一个进程改变另一个进程的状态来保护其一致性。它还在代码的临界区域周围提高处理器的执行级别，以防止可能导致不一致的中断。

## 3.5 睡眠与唤醒

进程进入睡眠是因为它们正在等待事件的发生，例如等待外围设备的 I/O 完成退出，等待系统资源变得可用。进程被认为在某个事件上睡眠，是指它们处于睡眠状态，直到该事件发生，届时会被唤醒并进入准备就绪的运行状态。许多进程可以同时在某个事件上睡眠；当该事件发生时，所有在该事件上睡眠的进程被唤醒。当进程唤醒时，它遵循从“睡眠”状态到“准备就绪”状态的状态转换，从而获得后续调度的机会；它不会立即执行。睡眠的进程不消耗 CPU 资源。内核不会不断检查进程是否仍在睡眠，而是等待事件发生并唤醒它们。

### 缓冲区锁竞争示例

| 进程 A | 进程 B | 进程 C |
|---|---|---|
| 锁定缓冲区 | 全部睡眠 | 进程 |
| 准备就绪 | 准备就绪 | 准备就绪 |
| 运行解锁缓冲区 | 加锁缓冲区 | |
| 因任意原因睡眠 | | |
| 运行已锁睡眠 | | 运行已锁睡眠的缓冲区 |
| 准备就绪 | 唤醒并解锁缓冲区，唤醒所有睡眠进程 | 准备就绪 |
| | 最终发生上下文切换 | |

例如，一个在内核模式下执行的进程有时必须锁定一个数据结构，以防它在稍后的阶段进入睡眠；尝试操作已锁结构的进程必须检查锁，如果另一个进程拥有该锁，则进入睡眠。内核以以下方式实现此类锁：

```
while (condition is true)
    sleep (event: the condition becomes false);
set condition true;
```

它以以下方式释放锁并唤醒所有在这些锁上睡眠的进程：

```
set condition false;
wakeup (event: the condition is false);
```

多个进程可在锁上睡眠。

## 3.6 内核数据结构

大多数内核数据结构占用固定大小的表格，而不是动态分配的空间。这种方法的优点是内核代码简单，但它限制了数据结构的条目数量，即生成系统时最初配置的数量。如果在系统运行期间内核某个数据结构的条目耗尽，它无法动态地为新条目分配空间，而必须向请求用户报告错误。如果内核配置得表格不太可能耗尽，那么额外的表格空间可能会被浪费，因为它们无法用于其他用途。

## 3.7 系统管理

管理进程是指为用户社区的整体福利执行各种功能的进程。这些功能包括新文件系统的磁盘格式化、受损文件系统的修复、内核调试等。管理进程与用户进程之间没有区别。它们使用针对通用社区提供的同一套系统调用。它们与普通用户进程的区别在于允许的权利和特权。内核不识别独立的管理进程类。
