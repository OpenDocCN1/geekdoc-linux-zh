
`TEMPDIR`变量仅在用于执行`my_script`产生的Shell中设置。它在你正在执行的交互式Shell中不会设置，即使已经设置了也不会更改。

在bash下，你可以在命令行任何位置放置赋值。Z Shell要求将赋值放在行开头。

## 编写简单的Shell脚本

Shell脚本是一个包含Shell可以执行命令的文件。脚本中的命令可以是你在提示符输入的任何命令。例如，一个脚本可以运行GNU/Linux工具、你编写的编译程序或另一个Shell脚本。

运行Shell脚本的最简单方法是在命令行上给出文件名。然后Shell会顺序解释并执行脚本中的命令。通过使用Shell脚本，你可以简单快速地启动一系列复杂任务或重复性程序。

## chmod：使文件可执行

要通过提供名称来执行Shell脚本，你必须对包含脚本的文件具有读取和执行权限（参见第118页的“访问权限”）。执行权限告诉Shell和系统所有者、组或公众可以执行该文件；它意味着文件内容是执行执行。

当你使用编辑器创建Shell脚本时，文件通常没有设置执行权限。下面的示例显示了一个名为`whos`的文件，它是包含三行命令的Shell脚本：

```bash
$ cat whoson
date
echo Users Currently Logged In
who
```

```bash
$ whoson
bash: ./whos: Permission denied
```

## 未找到？

当你在Shell提示符后输入`whoson`并收到错误信息`bash: whoson: command not found`时，你的登录Shell未设置为搜索工作目录中的可执行文件。给出此命令：

```bash
$ ./whos
```

这显式地告诉Shell在工作目录中查找可执行文件。要更改环境以便Shell自动搜索工作目录，请参阅第577页的`PATH`变量。

```bash
$ ls -l whoson
-rw-r-- 1 alex group      40 May 24 11:30 whoson
$ chmod u+x whoson
$ ls -l whoson
-rwx--r-- 1 alex group      40 May 24 11:30 whoson
```

```bash
$ whoson
Sat May 24 11:40:49 PST 2003
Users Currently Logged In
ny pts/7 May 23 18:17
hls pts/1 May 24 09:59
scott pts/12 May 24 06:29 (bravo.tcorp.com)
alex pts/4 May 24 09:08
```

**图12-1** 使用chmod使shell脚本具有可执行权限

当你创建一个像`whoson`这样的文件时，你无法通过输入其文件名来执行它，因为你没有该文件的执行权限。shell不会将`whoson`识别为可执行文件，当你尝试执行它时会发出错误信息。你可以通过将文件名作为参数传递给`bash whoson`来执行。当你这样做时，bash将该参数视为一个shell脚本并执行它。在这种情况下，`bash`是可执行的，而`whoson`是bash执行的参数，因此你不需要拥有`whoson`的执行权限。对`tosh`和`zsh`也可以进行相同的操作。

你可以使用`chmod`（第119和1103页）来更改与文件相关的访问权限。图12-1显示了使用`-l`选项，在`chmod`赋予所有者执行权限前后`whoson`访问权限变化。第一个`ls`显示的第四个字符是一个连字符（–），表示所有者没有执行该文件的权限。然后`chmod u+x`会导致`chmod`为所有者（`u`）添加（+）执行权限（`x`）。`u`代表*user*（用户），意味着文件的所有者，其在任何时候都是文件的用户。第二个参数是文件名。第二个`ls`在第四位置显示`x`，表示所有者拥有执行权限。

如果其他用户要执行该文件，你还必须更改组和/或公共权限。任何用户必须对文件具有执行权限才能将文件名作为命令使用。如果该文件是一个shell脚本（shell命令文件），尝试执行该文件的用户还必须对文件具有读取权限。你不需要二进制可执行文件（编译后的程序）的读取权限。最后，当名称作为命令给出时，shell会执行。更多信息请参阅“访问权限”（第118页）以及第三部分中的`ls`和`chmod`。

现在你已经知道如何编写和执行简单的shell脚本。“命令的分离与分组”（后文）和“重定向标准错误”（第552页）章节描述了在命令行或从脚本内部运行命令时实用的功能。“作业控制”（第554页）章节解释了命令与GNU/Linux系统进程之间的关系。

# 命令的分离与分组

本节适用于Bourne Again、TC和Z Shell。无论你是交互式地向shell提供命令还是编写shell脚本，必须将命令相互隔开。本节回顾了第5章涵盖的方法，并引入了一些新方法。

# 使用 ; 和换行符分离命令

换行符（NEWLINE）是一个独特的命令分隔符，因为它会启动其前一个命令的执行。在本书中，每当你在命令行末尾按下RETURN键时都会看到这一点。分号（`;`）是一种命令分隔符，它不会启动命令的执行，也不会改变命令函数的任何方面。你可以通过在单行命令行输入输入命令并用分号（`;`）将它们隔开来顺序执行它们。你通过按下RETURN启动命令序列的执行：

```bash
$ x ; y ; z
```

如果`x`、`y`和`z`是命令，则前面的命令行产生的结果与接下来的三个命令相同。区别在于，在接下来的示例中，shell在每个命令（`x`、`y`和`z`）执行完毕后都会给出一个提示符，而前面的命令行仅在`z`完成后才会给出提示符：

```bash
$ x
$ y
$ z
```

尽管前面的示例中分号周围的空格使得命令行更容易读，但并不是必须的。任何命令分隔符都不需要被空格（SPACES）或制表符（TABS）围绕。

# 使用\延续命令

当你输入长命令行且光标到达屏幕或窗口的右侧时，可以使用反斜杠（`\`）字符在下一行继续命令。反斜杠会引用或转义紧随其后的换行符，使shell不将其视为命令终止符（第55页）。

# 使用 | 和 & 分离命令并执行操作

其他命令分隔符是管道符号（`|`）和后台任务符号（`&`）。这些命令分隔符不会启动命令执行，但会改变命令函数的某些方面。管道符号更改标准输入的源或标准输出的终点；后台任务符号导致shell在后台执行任务，这样你就能立即获得提示符并继续处理其他事情。

以下每个命令都启动了一个包含三个任务的单一作业：

```bash
$ s | y | z
$ i | y | z
```

## () 命令分组

你可以使用括号来对命令进行分组。shell会为每个组创建一个自身的副本，称为子壳（subshell），将每组命令视为一个作业（job），并创建一个新进程来执行每条命令（有关创建子壳的更多信息，请参见第560页的“进程结构”）。每个子壳（作业）都有自己的环境；在其他方面，这意味着它拥有一套变量，其取值可能与其他子壳的变量不同。

以下命令行在后台按顺序执行命令`a`和`b`，同时在后台执行`c`。shell提示符立即返回。

```bash
$ (a ; b) & c &
15007
```

此示例与之前的`a & b & c`示例不同之处在于，任务`a`和`b`是顺序启动的，而不是并发的。

同样，以下命令同时顺序执行`a`和`b`，在后台顺序执行`c`和`d`，且运行`a`和`b`的子壳与运行`c`和`d`的子壳并发运行。提示符立即返回：

```bash
$ (a ; b) & (c ; d) &
15020
1521
$
```

在下面的shell脚本中，第二对括号创建了一个子壳来运行管道后的命令。由于这些括号的存在，第一个`tar`命令的输出可以供第二个`tar`命令使用，尽管中间插入了`cd`。如果没有这些括号，第一个`tar`命令的输出将会被发送给`cd`并丢失，因为`cd`不处理来自标准输入的输入。`$1`和`$2`是shell变量，代表第一个和第二个命令行参数（见第582页）。第一对括号创建了一个子壳来运行前两个命令，这是必要的，因为这样用户可以使用相对路径`cd cpdir`。如果没有这些括号，第一个`cd`命令将更改脚本的工作目录（随之，也会更改第二个命令的工作目录）；而有了括号，只有子壳的目录会发生改变：

```bash
$ cat cpdir
(cd $1 ; tar -cf . ) (cd $2 ; tar -xvf -)
$ cp /home/alex/sources /home/alex/memo/biblio
```
