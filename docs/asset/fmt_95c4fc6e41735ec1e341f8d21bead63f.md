# shell

一种命令解释器，允许用户运行代码。Shells 还存储关于可执行文件的信息。源自 Redhat-9-Gloss

一种文本模式的窗口，包含一个与操作系统交互的程序。用户输入的命令由 shell 传递给操作系统。结果随后由 shell 显示。源自 Linux Guide @FirstLinux

一种在 Unix 系统上提供的命令行界面。关键点：在 Windows 系统上，这类似于“命令提示符”或“Dos 提示符”。关键点：许多系统通过向 shell 传递特殊字符来实现。黑客中最流行的 shell 是 "`bash`"，以其创建者命名。文化："`bash`" 的缩写意思是 "Bourne Again Shell"，反映了它是重写。事实：通过网络获取某人的 `bash_history` 文件是一种常见的攻击。关键点：Unix 黑客的目标是获得 `root` shell。在其他情况下，缓冲区溢出通常包含所谓的“shell 代码”。由于这种原因，缓冲区溢出进程将开始运行 shell。对于，一个例子可能是向 `FTP` 服务器发送包含 shell 代码的长密码，将 `FTP` 服务器的 `TCP` 连接转换为完整的命令提示符，从那里可以启动 shell。源自 Hacking–Lexicon

# shell 码 (shellcode)

当黑客成功利用缓冲区溢出等漏洞时（这通常会在漏洞利用结束时打开一个 shell），黑客将能够执行任何任何东西。然而，在缓冲区溢出中打开 shell 可能是困难的。因此，黑客维护某些“shell 码”库：用于各种操作系统的代码片段，可以粘贴到缓冲区溢出中。关键点：在利用 SMTP 服务器中的 shell 时，你可能会发现服务器会剥离所有字节的高位（即会通过文本但不会通过二进制文件）。因此，所有来自 `0x00–7F` 的字节将通过，但 `0x80–0xFF` 不会。或者，一个限制是系统不会传递空字符 (`0x00`)，它们在 `strncpy` 等函数中终止字符串。然而，当黑客选择 shell 码附加到他们的脚本时，他们必须意识到他们正在使用的系统的局限性。关键点：当新的 shell 码是看起来像 "`/bin/sh;`" 或 "`execve(/bin/sh);`" 的 C 程序时，这需要大量的汇编知识。关键点：有时你无法获取 shell，所以你必须利用脚本运行。典型的命令选择将是那些快速通过密码、账户和密码相互的命令。关键点：绝大多数缓冲区溢出都会执行 `/bin/sh`；因此，通过删除此程序（或将其替换为某些检查已执行操作的东西），你可以保护自己免受许多 0 日漏洞攻击。来自 Hacking–Lexicon

http://www.tldp.org/LDP/Linux-Dictionary/html/index.html
