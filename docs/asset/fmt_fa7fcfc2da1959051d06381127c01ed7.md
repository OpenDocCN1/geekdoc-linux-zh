## 内核参数

现在所有产品都已从 CD 复制，Linux 内核可能需要配置。Progress 使用 Linux 内核控制的两组资源——共享内存和信号量。在我们决定每个参数的具体值之前，了解这些资源的背景非常重要。共享内存是为多用户访问留出的内存设施。与其将所有数据库信息直接写入磁盘（每个用户都会执行缓慢操作），Progress 使用更快的内存作为数据库缓存。块被读取到共享内存区域（称为 *缓冲区池*），在那里不仅对请求数据的用户可用，对所有用户可用。Progress 数据库引擎是多线程的，并在可用多个处理器时利用 SMP。由于多个用户同时修改共享内存，Progress 根据需要使用另一种资源信号量锁定共享内存，并确保共享内存的操作具有原子性。（实际上，信号量仅用于“慢”操作；互斥锁或旋锁用于“快”操作。）修改过的块最终会被写回磁盘，并可能从缓冲区池中剔出——但并非立即。如果这听起来很危险，请放心，数据库系统设计得非常稳定。尽管 Oracle 有崩溃记录，但 Progress 在用户调查中得分最高。更多信息请参见 PEG 的技术论文部分：http://www.peg.com。数据库引擎的架构师（通常被称为 *引擎小组*）编写了许多解释各种数据库内部原理的优秀论文。

以下是参数的列表以及如何设置每个参数的值。大多数参数基于系统中的用户数量或数据库数量。包含文件 `sem.h`

`shm.h` 包含了 Linux 内核中这些参数的描述。这两个文件通常位于 `/usr/src/linux/include/linux` 下。

### 共享内存

- `SHMMNI`—共享内存标识符的数量
- `SHMSEG`—每个进程的共享内存段数
- `SHMMAX`—共享内存段的最大 own

共享内存被组织成段；每组段被赋予一个唯一的标识符。每个数据库至少需要一个共享内存段和一个与之对应的标识符。取你打算在系统上运行的数据库数量，并四舍五入到最近的五倍数——结果就是 `SHMMNI` 的良好设置。RedHat Linux 的默认值为 10，这对于大多数系统来说足够了。`SHMSEG` 和 `SHMMAX` 成对工作。由于共享内存是按段组织的，共享内存的最大 own是段数乘以每个段的大小。在 V8.3 版本的进展下，将创建的段大小将是 `SHMSEG` 或 16777214 字节 (16MB) 中的较小值。由于 Progress 目前永远不会使用大于 16MB 的段，即使设置了 `SHMSEG`，将其设置为不大于 16777224 也是有意义的。那么需要多少共享内存呢？手册描述了具体的数量，但通常是缓冲区池使用的 RAM 以及任何其他共享内存使用的量。出于性能考虑，为生产系统中的每个用户分配至少约 2MB 的缓冲区池。如果可能，考虑使用 4MB 并在时购买更多内存。记住，共享内存必须包含在物理 RAM 中。如果你分配的内存超过了你拥有的物理 RAM，Linux 将将缓冲区池的部分换入换出以覆盖差异。这将对性能产生剧的负面影响。取每个数据库的用户数乘以你决定保留的 RAM 数量。对每个数据库执行此操作，确定哪一个需要的共享内存最多。这是设置 `SHMSEG` 所需的高水位线。将最大 RAM 除以我们为 `SHMMAX` 设置的 16MB，并向上取整。这是任何数据库所需的最大段大小，也是我们 `SHMSEG` 的值。

### 信号量

- `SEMMNI`—信号量标识符的数量
- `SEMMNS`—全系统的信号量数量
- `SEMMSL`—每个标识符的信号量数量

信号量像共享内存一样，被组织成带有标识符的名称集。同样， Progress 每个数据库需要一组信号量。`SEMMNI` 的计算方法是 `SHMMNI`——这两个参数通常被设置为相同的值。Progress 内部使用大约五个信号量，外加对每个登录到该数据库的并发用户使用一个信号量。`SEMSSL` 需要设置为具有并发用户最多的数据库的用户数。将其设置为单个数据库中的最大用户数加上那 5 个额外的，并额外增加 10% 作为安全余量。
