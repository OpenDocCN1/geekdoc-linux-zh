# 原则 9：让每个程序成为过滤器

计算机无法写书，就像锤子和一盒钉子无法盖房子一样。智能智能文字处理器——即我们所谓的“所见即所得”`WYSIWYG`类型——可能会通过格式化和对齐进行一些过滤，但它们从根本上并没有形成思想。

收集我们周围世界信息的实时程序也不创建数据。数据已经存在了。通过从环境中提取读取值，程序执行了一个选择过程。只有重要的数据才能通过程序的过滤器并被保存。

世界上充满了人类创造的数据。即使计算机从未被发明，这些数据仍然存在。计算机只是让更高效地收集和过滤这些数据成为可能。产生的任何“新”数据并非如此。计算机为我们提供了以不同方式管理数据的机会。如果世界上充满了计算机而没有任何人类，就不会有数据。

## 6.2.3 计算机将数据从一种格式转换为另一种格式

另一种观点是，数据为了某些应用程序有用，必须存储在便于对其操作的格式中。例如，人按下键盘键的动作对于软件来说没有任何价值。然而，当这些动作被转换为代表二进制数据的系列电子脉冲时，它们在机器内部突然获得了新的生命。然后，软件就可以将数据转换为多种形式，以服务任何目的。

这里有一个有趣的点是，音乐仅仅是另一种数据。它已经以某种形式存在了几个世纪。人们弹奏弦乐器已经几千年了。钢琴作为一种打击乐器已经存在了几个世纪。钢琴家使用带孔的纸卷来“记住”歌曲符号。然而，近年来，合成器已成为收集音乐家移动手腕和手指产生的“数据”的主要手段。一旦捕获，数据就会转换为`MIDI`文件，这是音乐行业电子音乐表示的标准格式。它可以以无限方式进行过滤，产生的不仅有钢琴音色，还有超越任何自然声学乐器能力的声音。在许多方面，音乐界对`MIDI`的使用仍处于婴儿阶段。未来的`MIDI`应用将带我们带来突破人类听觉感知边界的音乐飞行。这将随着能够以以前被认为不可能的方式过滤音乐数据的程序来实现。可以肯定，将是计算机修改并增强`MIDI`数据，以产生新的、创造性的声音。

## 6.3 Linux 环境：使用程序作为过滤器

你可能在想程序作为过滤器意味着什么。`Linux`程序员遵循一组非正式规则，这些规则简化了具有此类行为的软件的设计。然而，为了澄清这些规则，我包含了一些准则。在讨论这些之前，有必要对`Linux`中一个名为`stdio`的概念进行简短解释。

当程序在`Linux`下被调用时，它通常会有三个标准的 I/O 通道打开，被称为`stdin`、`stdout`和`stderr`，因此名为`stdio`。连接到这些 I/O 通道另一端取决于程序是如何被调用的。默认情况下，`stdin`收集用户输入，`stdout`将任何输出发送用户的显示屏幕。任何发送到`stderr`的输出也会出现在显示屏幕上，但这些数据通常被认为是“带外”信息或错误信息。

`Linux` `stdio`的有趣特性是，连接到 I/O 通道的设备并不是与程序“硬连线”的。在调用时，用户可以指定数据源于或发送到用户终端以外的其他地方。例如，`stdin`可能来自文件、通过`Linux`管道的另一个程序，甚至是通往世界另一端系统的卫星链路。同样，如果用户想将`stdout`发送到文件中以便审阅，他或她可以引导`Linux` shell 放置输出。这在数据源和目的地方面提供了巨大的灵活性。

`Linux`程序员处理`stdio`的方式对程序作为过滤器的能力有重大影响。如果程序编写得正确，那么就可以利用`stdio`的灵活性。否则，用户可能会被锁定在`CUI`中。关键是编写软件使其采用`stdio`。这里有三个重要的准则：

- I. 使用`stdio`进行数据输入 从`stdin`获取输入数据的程序假设其数据可以来自任何地方。事实上确实如此 通过避免“硬连线”输入通道，你让用户可以在调用程序时轻松指定输入来源。它的来源可以是键盘、文件、另一个`Linux`程序，甚至是`CLI`。
- II. 使用`stdout`进行数据输出 由于`stdin`允许程序从任何地方接受输入数据，使用`stdout`则允许程序的输出被发送到任何地方。“任何地方”在这里意味着用户的屏幕、文件、打印机，甚至是数字语音合成器。选择取决于用户，并且在程序运行时是任何合适的。
- III. 使用`stderr`处理带外信息 错误消息和其他警告应通过`stderr`发给用户。它们绝不应该是到`stdout`数据流的一部分。原因之一是，用户可能选择将错误消息捕获到单独的文件中，或者立即在终端查看。在与`stdout`相同的 I/O 通道上发送错误消息可能会以后引起混乱。记住，`Linux`命令很少单独使用。

注意这种方法与其他操作系统的不同。在大多数其他操作系统上运行的应用程序倾向于硬连线一切。

# 更多 Unix 哲学：十条次要原则

## 7.1 允许用户定制环境

因此，我们已经探索了构成`Unix`哲学核心的准则。它们是`Unix`世界赖以存在的基石。人们可以对这些准则表示强烈反对，并理直气壮地认为自己是一个“`Unix`人”。这样做会引起`Unix`社区（`Linux`也是其中的一部分）的怀疑，认为此类人对`Unix`及其代表的理念缺乏投入精神。

在对`Unix`“宗教”的教条发表了这番高论后，我们准备好开始接触它的一些教义了。`Unix`和`Linux`开发者竭尽全力去维护到为止所涵盖的准则的完整性。相比之下，这里讨论的准则属于“好吧，我倒有点赞同”这一类。虽然不是每个`Unix`战士都会同意本章中的观点，但`Unix`社区（以及现在的`Linux`社区）整体通常与这些观点保持一致。

你会发现，这里强调的某些项目更多是关于事情“应该如何被做”，而不是“应该怎么做”。我会尝试对这些内容提供一些解释，但请注意，有些事情之所以这样做没有其他原因，仅仅是因为它们一直以来如此。就像既定宗教一样，`Unix`有它自己的传统，而`Linux`正在表现出同样的“换汤不换药”的特征。

引人注目的是缺失了“开源”主题，这是大多数`Linux`“意外革命者”对此深信不疑的概念。开源已深根于`Linux`文化之中，并且在很久以前就成为了理查德·M·斯尔曼等先驱者的号召，它需要完整的对待，而不是这里介绍的这种简短的摘要。因此，我们将在以后更深入地探讨它。

其他操作系统的支持者也采纳了这些次要原则，这并不意外。好的主意在计算机世界往往容易传播。其他系统的软件开发者发现了`Unix`概念，这些概念在他们最初可能没有看到其价值的情况下显示出了优势。他们将这些概念整合到设计中，其中产生了一些具有`Unix`风味的系统和应用程序。

### 允许用户定制环境

许多年前，我编写了`uwm`，这是`X`窗口系统的一个“窗口管理器”或用户界面。它为用户提供了许多人在当今窗口系统中认为理所当然的能力：移动窗口、调整窗口大小、更改它们的堆叠顺序等。它在市场上广受好评，成为了“`X`版本 10 的窗口管理器”。它作为今天用于`X`窗口系统的流行窗口管理器的概念先祖，占据着一个鲜为人知但完全合法的地位。今天的窗口管理器大量借鉴了`uwm`及其后代中原始的定制思想。

导致`uwm`成功的因素之一是`Bob Scheifler`在麻省理工学院（`MIT`）一次早期`X`窗口系统设计会议上的一个感叹。`Bob`是`X`整体设计的重要贡献者，当时正在查看我关于“`Unix`窗口管理器”的规范。突然，他脱口而出：“假设我不想要左鼠标键执行那个操作呢！”接着建议用户可能喜欢选择每个鼠标按钮触发的功能。

如果我是一个漫画里的角色，你会看到我头顶上出现了一个灯泡。

`uwm`随后在“可定制”界面领域开辟了天地。`X`窗口系统让用户选择窗口管理器成为可能。`uwm`则进一步实现了定制，允许用户选择窗口管理器本身的视觉、感觉和行为。鼠标移动、按钮点击、颜色、字体和菜单选项的组合可以由用户决定。这种想法是如此强大，以至于`X Windows`的开发者后来设计了一个“资源管理器”，提供了对显示屏幕几乎每个元素的用户级控制。这种前所未有的灵活性在今天仍然无法比拟，即使是微软和苹果的桌面环境。其他系统将这种灵活性给了开发者，而`X Windows`将它交给了用户。

我们之前说过，一个人对某事的投入越大，他对其结果的利益关系就越大。在观察人们如何使用`uwm`时，我发现如果给人们机会定制自己的环境，他们就会这样做。内置的灵活性邀请用户投入精力学习，以最大限地发挥应用程序的价值。随着人们对自己定制的环境变得越来越熟悉，他们对那些难以或无法进行此类定制的环境就会变得越来越排斥。

如今的`Linux`环境很大程度上围绕着这一公理运转。人们通常觉得起初使用`Linux`很棘手，因为它太灵活了。众多的选择让他们无从下手。从一开始开始，`Linux`就提供了多种选择：多个发行版、多个窗口管理器、多个桌面、多文件系统等。你不需要从某一个供应商那里购买`Linux`。事实上，你甚至不需要购买。你可以从其中一个供应商的网站免费下载。

最终，用户会找到一种适合自己的`Linux`使用方法。他们选择一个发行版，并投入精力学习如何利用许多选项。一旦投入达到一定程度，想要回到其他操作系统就会变得非常困难。他们达到了一个点，他们在`Linux`中的利益增长得如此巨大，以至于他们宁愿修改他们不喜欢的地方，也不愿完全离开它。
