
被写为 `128.10.30.2`。

每个地址实际上包含一对标识符：一个用于其所属的网络（`netid`），另一个用于该网络上的主机（`hostid`）。这有许多重要的影响。`netid` 的显著性使得路由变得高效许多：路由器只需要知道通往特定网络的路径，而不是某个特定的主机。IP 地址实际上指定的是一个网络连接，而不是单台机器（例如，为了在信赖网络和互联网之间进行数据过滤，主机需要两个 IP 地址）。`netid` 和 `hostid` 的这种绑定还意味着当机器更换网络时，它也需要更改其 IP 地址。

每个 IP 地址属于三种经典形式之一：A 类、B 类和 C 类。这些对应于三类网络。给定一个 IP 地址，可以根据地址的前几位（高位）确定其类别。每个类别将不同数量的位分配给 `netid` 和 `hostid`。自然地，分配给 `netid` 的位越多，可以由 `hostid` 指定的主机就越少。表 13.1 总结了这三大类。

### 表 13.1 IP 地址

| 类别 | 高位位（值） | `netid`（大小） | `hostid`（大小） | 最大主机数 |
| --- | --- | --- | --- | --- |
| A 类 | 0 | 7 位 | 24 位 | 16,777,216 |
| B 类 | 10 | 14 位 | 16 位 | 65,536 |
| C 类 | 110 | 21 位 | 8 位 | 256 |

事实上，表中所示的每个最大主机数都应该减去 2。`hostid` 为 0 永远不会分配给特定的主机，它被预留用于标识网络。同样，网络中可能的最高主机值作为广播地址——这是一个可以到达该网络中所有主机的地址。

为了帮助你理解上面的表格，之前提到的 IP 地址 `128.10.30.2` 属于 B 类网络；IP 地址的前两个位是 `10`。此外，网络地址是 `128.10.0.0`，广播地址是 `128.10.255.255`。

还有 D 类地址（预留用于组播）和 E 类地址（预留用于实验性）。这两者在这里都不涉及。

# 协议分层

TCP/IP 是一个协议族，而不是一个单一的实体。它由多种标准组成，这些标准协作工作以建立和维护通信。当你考虑以下因素时，TCP/IP 设计者创建一组协议的原因就变得清晰了：

- 生存设计目标
- 数据通信中可能出现的所有困难

网络容易发生硬件故障：健壮的通信协议需要能够检测主机何时崩溃并绕过它进行路由。任何访问过万维网的人都知道，网络拥塞是互联网的持续特征：协议需要能够缓解那些被过多数据包流量困扰的主机。有时数据包会被吸入虚拟黑洞并导致网络出现丢包：协议必须知道这种情况何时发生并进行补偿。在其他时候，数据由于从电磁干扰到序列错误等任何原因而损坏：协议必须检测并补偿数据损坏。

为了使这些问题更易管理，TCP/IP 设计者创建了一个垂直协议栈，这些协议在每个连接的主机上层层堆叠运行。潜在问题的泥潭几乎被按层划分，每一层都有一个协议（或多个协议）专门负责处理特定问题。

共有四个概念层——应用层、传输层、网络层、网络接口层——它们位于第五层网络硬件之上。这四个概念层在表 13.2 中进行了解释。

### 表 13.2 TCP/IP 协议层

| 层级 | 层名称 | 描述 |
| --- | --- | --- |
| 4 | 应用层 | 这一最高层为允许用户访问 TCP/IP 服务的应用程序提供支持。应用程序向运行在传输层（第 3 层）的协议发送和接收数据。 |
| 3 | 传输层 | 该层提供从一个应用程序到另一个应用程序的端到端通信。它将数据流分割成包，并将每个数据包连同目的地址传递给网络层（第 2 层）。它还接收来自第 2 层的数据并将其传递给第 4 层。某些第 3 层协议确保数据无误且按顺序到达（即 TCP）。 |

### 表 13.2 TCP/IP 协议层（续）

| 层级 | 层名称 | 描述 |
| --- | --- | --- |
| 2 | 网络层 | IP 协议的这一层处理机器与机器之间的通信。它接收来自传输层的数据包及目的地址。它封装数据包并使用路由算法决定是直接交付还是发送到路由器。然后它将数据包直接交付给适当的网络接口进行传输。它还接收来自第 1 层的数据包，并使用路由算法决定它们应该在本地处理（到第 3 层）还是转发（传回第 1 层）。 |
| 1 | 网络接口层 | 这一最低层负责在网络硬件之间建立、维护和释放连接。 |

请注意，这种分层模型与国际标准组织发布的七层模型相似但有所不同，该模型正式称为“ISO 开放系统连接参考模型”。正如 TCP/IP 模型根据设定的规则运行一样：

- 概念层之下是网络硬件层，它构成了两个系统之间的物理链路。
- 每一后续层对网络流量细节的关注逐渐减少，对用户应用程序细节的关注增加。
- 每一层只能与栈中直接上方和下方的层进行通信。
- 消息在发送端通过较低层向下传递，并在接收端通过层级向上回传。

分层的组织方式使得接收端的第 `n` 层接收到的对象与发送端的第 `n` 层发送的完全相同。

## TCP

TCP 为运行在网络计算机或同一计算机上的进程之间提供可靠的端到端连接。它类似于电话交换电话。一台机器上的协议软件“调用”远程机器上的对应软件。一旦连接建立，双方机器上的软件就会持续通信以确保数据正确发送。如果通信失败，双方机器都会检测到失败并向相应的应用程序报告。

TCP 基于一种被称为“正确认重传”的技术。接收者在接收数据时必须通过发送确认消息向发送者进行通信。发送者记录每个发送的数据包，并在收到确认后才发送下一个数据包。

TCP 连接通过三次握手建立，以确保两个主机准备好对等通信。协议在每个数据包头中插入两个特殊位以协商新连接：`SYN` 和 `ACK`。为了启动连接，请求主机发送一个设置了 `SYN` 位未设置 `ACK` 位的数据包。接收主机通过发回一个设置了 `SYN` 和 `ACK` 位的数据包来响应。最后，请求主机发送第三个未设置 `SYN` 位而设置了 `ACK` 位的数据包。

> TCP 基于 Vinton G. Cerf（“互联网之父”）和 Robert E. Kahn 在 20 世纪 70 年代的工作。1981 年，Jon Postel 在 RFC 793 中将其正式化。更多信息请参阅 http://www.faqs.org/rfcs/rfc793.html

TCP 设计用于支持需要可靠双向数据流的服务。例如，FTP 和 Telnet 应用就是构建在 TCP 之上的。

## UDP

用户数据报协议是一种不可靠的无连接交付服务，依赖 IP 在机器之间传输消息。该协议为应用程序提供了一种以最少的协议机制向其他程序发送消息的程序。与 TCP 不同的是，该协议是面向事务的——不保证交付，也不防止重复。使用 UDP 的应用程序完全负责处理消息丢失、重复、延迟和乱序传输等问题。

与 IP 一样，UDP 对数据包的交付是“尽力而为”的。UDP 在局域网（LAN）上运行相当可靠，在公网上运行的可靠性较低。UDP 的优势在于其简单性和经济性——更少的报头开销意味着更高的吞吐量。

UDP 用于解析主机名、传输路由信息、Sun 系统的网络文件系统 (NFS) 以及一些偶尔丢失数据包而不会产生灾难性结果的冷门服务。

UDP 由 Jon Postel 在 RFC 768 中正式制定。欲了解更多信息请参阅 http://www.faqs.org/rfcs/rfc768.html。

## ICMP

最后一个值得提及的 TCP/IP 协议：互联网控制消息报协议（ICMP）。ICMP 是一种特殊的消息机制，允许路由器报告错误或意外情况。ICMP 是互联网协议不可或缺的一部分。ICMP 消息从一台机器的 IP 软件发送到另一台机器的 IP 软件。

ICMP 最重要的用途之一是测试可达性。`ping` 命令通过简单机制使用 ICMP 回显请求和回显应答消息类型：一个主机向第二个主机发送回显请求；接收主机收到该请求。
