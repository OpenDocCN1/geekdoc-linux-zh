
# 第 8 章 模块、包与发行

在此示例中，`from . import lines` 语句中的`.`指向调用模块相同的目录。因此，该语句加载了与`fill.py`相同目录下的模块`lines`。必须非常小心地避免使用`import module`语句来导入包的子模块。在 Python 的旧版本中，尚不清楚`import module`语句是指标准库模块还是包的子模块。旧版本的 Python 会首先尝试从`import`语句出现的包目录中作为子模块加载模块，如果没有找到匹配项，则移动到标准库模块。然而，在 Python 3 中，`import`假设是一个绝对路径并简单地尝试从标准库加载模块。相对导入能更清晰地表达你的意图。

相对导入也可用于加载位于同一包不同目录下的子模块。例如，如果`Graphics.Graphics.Dplot2d`模块想要导入`Graphics.Primitives.lines`，它可以使用如下语句：

```python
# plot2d.py
from .Primitives import lines
```

在这里，`..`向上移动一个目录，而`Primitives`进入另一个包目录。

相对导入只能通过`import`语句的模块导入符号来指定。诸如`import .Primitives.lines`或`import .lines`的语句是语法错误。此外，符号必须是有效的标识符。因此，如`from import .Primitives.lines`的语句也是非法的。最后，相对导入只能在包内使用；引用仅位于文件系统中不同目录的模块是非合法的。

单独导入包并不会导入包中包含的所有子模块。例如，以下代码无法工作：

```python
import Graphics
Graphics.Primitive.fillfill(img,x,color) # 失败！
```

由于`import Graphics`语句会执行`Graphics`目录下的`__init__.py`文件，可以使用相对导入以算法方式加载所有子模块，如下所示：

```python
# Graphics/__init__.py
from . import Primitive, Graphics3d
```

```python
# Graphics/Primitive/__init__.py
from . import lines, fill, text,
```

现在，`import Graphics`语句导入了所有子模块并使它们再次完全可用。再次强调，重要的是应该使用包相对导入。如果你使用简单的`import module`语句，可能会加载标准库模块。

最后，当 Python 导入一个包时，它定义了一个特殊变量`__path__`，其中包含一个在搜索包子模块时搜索的目录列表。`__path__`是`sys.path`变量的包特定版本。`__path__`可由`__init__.py`文件包含的代码访问，并包含一个项，即包的目录名称。如有必要，包可以向`__path__`列表提供额外的目录，以更改用于查找子模块的搜索路径。如果包在文件系统上的组织非常复杂且与包层次结构不匹配，这可能非常有用。

## 分发 Python 程序和库

要向他人发布 Python 程序，你应该使用`distutils`模块。作为准备，你应该将工作整洁地组织在一个包含`README`文件、支持性文档和你的源代码的目录中。通常，该目录将包含库模块、包和脚本的混合。模块和包是指通过`import`语句加载的源文件。脚本作为解释器的主程序运行，例如通过`python scriptname`运行。这是一个包含 Python 代码的目录示例：

```text
spam/
  Documentation.txt
  libspam.py
  spampkg/
    __init__.py
    foo.py
    bar.py
  runspam.py
# 单个库模块
# 支持模块的包
# 用于运行的脚本：python runspam.py
```

你应该组织你的代码，使其在顶层目录中运行时运行正常。例如，如果你在`spam`目录中启动 Python，你可以轻松地导入模块、导入包组件并运行脚本，而无需修改 Python 的任何设置，如模块路径。

组织好代码后，在最直接的目录，上例中的`spam`中创建一个`setup.py`。在该文件中放入以下代码：

```python
# setup.py
from distutils.core import setup
setup(name="spam",
     version="1.0",
     py_modules=['libspam'],
     packages=['spampkg'],
     scripts=['runspam.py'],
```

在`setup()`调用中，`py_modules`是一个列表，`packages`是目录列表，`scripts`是脚本文件列表。如果你的软件没有任何元数据，可以省略其中的这些参数。`name`是包的名称，`version`是字符串。表 8.1 显示：

| 参数 | 说明 |
| :--- | :--- |
| name | 包名（必需） |
| version | 版本号（必需） |
| author | 作者姓名 |
| author_email | 作者邮箱 |

| 参数 | 说明 |
| :--- | :--- |
| maintainer | 维护者姓名 |
| maintainer_email | 维护者邮箱 |
| url | 包的首页 |
| description | 包的短描述 |
| long_description | 包的详细描述 |
| download_url | 包下载位置 |
| classifiers | 字符串分类列表 |

创建一个`setup.py`文件就足以创建源码发行。输入以下命令创建源码发行：

```bash
% python setup.py sdist
```

这会在`dist`目录创建一个压缩文件`spam-1.0.tar.gz`或`spam-1.0.zip`。这是你给他人安装软件的文件。用户只需解压包并执行以下步骤：

```bash
% unzip spam-1.0.zip
% cd spam-1.0
% python setup.py install
```

这将软件安装到本地并供通用使用。模块和包通常安装在 Python 的`site-packages`目录中。要找到该目录的确切位置，请检查`sys.path`的值。脚本在 Unix 系统上安装在与 Python 解释器相同的目录，在 Windows 上安装在"Scripts"目录，典型安装为`C:\Python26\Scripts`。

在 Unix 上，如果脚本的第一行以`#`开头并包含文本`python`，安装程序将重写本地安装位置。因此，如果你编写的脚本编码了特定的 Python 位置，如`/usr/local/bin/python`，它们在 Python 位置不同的系统上仍然有效。

`setup.py`文件有许多关于软件分发的命令。如果你输入`setup.py bdist`，将创建一个二进制包，其中所有的`.py`文件已解压并放置在类似于本地的目录中。这种发行仅适用于应用程序具有平台依赖的情况，例如，你需要编译 C 扩展。如果你在 Windows 机器上运行`python setup.py bdist_wininst`，将创建一个`.exe`文件。打开时，将启动 Windows 安装程序，提示用户有关软件应该安装位置的信息。这种发行方式向注册表中添加条目，以便在日后卸载你的包。

`distutils`模块假设用户已经在其机器上安装了 Python，单独下载。虽然可以创建将 Python 运行时和软件捆在一起的软件包，但单个二进制可执行文件，这是此处所涵盖的范围，更多细节请查看第三方模块，如`py2exe`或`py2app`。如果你只是在分发库或简单的脚本，通常没有必要将代码与 Python 解释器和运行时环境一起打包。

最后，需要注意的是，`distutils`的选项比这里介绍的要多得多。第 26 章描述了如何使用`distutils`编译 C 和 C++ 扩展。

虽然不是 Python 分发的一部分，但 Python 软件通常以`.egg`文件的形式发行。这种格式由`setuptools`扩展创建，http://pypi.python.org/pypi/setuptools。为了支持`setuptools`，你可以如下所示修改`setup.py`的第一部分：

```python
# setup.py
try:
    from setuptools import setup
except ImportError:
    from distutils.core import setup
```
