
接下来检查标识 Samba 在 WINS、浏览和域等服务中角色的参数。按顺序参考有关这些服务的章节，以确认 Samba 是作为客户端还是服务器运行。验证 `smb.conf` 全局部分和服务部分中的访问控制参数是否反映了服务器和每个共享所需的访问权限。例如，你可能由于配置不当的 `hosts allow` 和 `hosts deny` 参数而导致访问阻塞。

对于具有大量服务器、服务和/或用户的复杂站点，`smb.conf` 文件可能会变得混乱无章。可以使用 `testpart` 和 `SWAT` 等工具来辅助验证正确性。`testpart` 验证你为 `smb.conf` 的每个部分指定的语法和选项。如果提供主机名或 IP 地址作为选项，它将检查指定主机的访问权限。

```
$ testpart < -s configfilename <hostname hostIP>
```

`SWAT` 是一项用于系统管理的工具，它为 `smb.conf` 中的每个部分提供了表单。可以使用 `SWAT` 简化通用配置任务，允许系统管理员专注于其感兴趣的章节参数定义。

如果你通过 `ps` 进程检查发现 Samba `smbd` 和 `nmbd` 守护进程其中一个或两个未运行，请验证你的守护进程启动配置是否正确。请记住，Samba 守护进程可能由 `init` 在系统初始化期间作为持久进程启动，也可能在 `inetd` 接收到服务请求时自动启动。

### 示例 15.11 Samba 守护进程启动配置

```
init boot-time startup - /etc/rc<file>

/usr/local/samba/bin/smbd -D
/usr/local/samba/bin/nmbd -D

-or-
inetd service startup - /etc/inetd.conf

netbios-ssn _stream tcp nowait /usr/sbin/tcpd \
    /usr/local/samba/bin/smbd smnb
netbios-ns _dgram udp wait /usr/sbin/tcpd \
    /usr/local/samba/bin/nmbd nmbd
```

## 服务端口

服务器连接问题可能与 `/etc/services` 中缺失或无效的端口号有关。确保 udp 端口 137 和 tcp 端口 139 分别被 `netbios-ns` 和 `netbios-ssn` 服务保留。

### 示例 15.12 Samba 端口配置

`/etc/services`

```
netbios-ns      137/udp
netbios-ssn     139/tcp
```

## smb.conf

Samba 的整体行为由 `smb.conf` 文件描述。`smb.conf` 的全局部分应包含标识服务器 NetBIOS 名称、工作组/域名称、安全类型以及密码是否将以明文形式加密的参数。

### 表 15.4 关键全局部分参数

```
security = <share, user, server, domain>
netbios name = <server NetBIOS name>
workgroup = <workgroup/domain name>
password server = <>
encrypt passwords = true
```

该参数用于指示何时关闭日志、将其重命名为 `log.old` 并启动新日志。消息详细程度由调试级别值控制。值从 0 开始向上递增。特殊值 100 与 `passwd` 聊天设置结合时，将在日志文件中记录密码。

```
log file = /usr/local/samba/var/log.wtm
max log size = 10000
debug level = 3
```

另一个选项是使用 `syslog only` 参数将 Samba 消息发送到 `syslog` 守护进程。`syslog` 参数指示 Samba 级别如何映射到相应的 `syslog` 级别。你可以通过 `syslogd` 直接让 Samba 记录消息。当使用 `syslogd` 将日志发送到本地机器上的公共收集点或远程服务器时，这可能非常有用。
