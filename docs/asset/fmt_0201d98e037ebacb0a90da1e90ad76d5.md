
在它的输出中，`free -m`命令提供了内存总量、已用内存和可用内存的概览。注意，总量显示为已用 + 空闲 + buff/cache内存。当`free`命令在RHEL 7.1中更新时，引入了`available`参数。该参数显示了作为空闲内存可用内存加上非活动文件内存（指最近未使用的缓存文件）。`free -m`命令的第二行显示了关于交换分区使用的信息。

如果需要关于交换空间组成的更多细节，可以使用`swapon -s`命令。如列表27.3所示，该命令显示当前哪些交换设备被分配为交换文件。你可以看到使用此命令的系统的交换空间是由`dm-0`和`dm-4`组成的，它们是LVM逻辑卷，通过`swapon -s`命令被错误地识别为分区设备。

## 使用 iostat

如果你想找出哪些I/O设备被频繁使用，以及这些设备上发生了多少I/O操作，那么`iostat`就非常用用。如果你在不带任何参数的情况下运行该工具，它将输出如列表27.4所示的内容。

### 列表 27.4 iostat 默认输出

```
[root@localhost #] iostat

avg-cpu:    user      %nice %system %iowait %steal  %idle
           0.18      0.00    0.32      0.00  0.00 99.50

sda           0.45    10.48       1.17 439818    493314
```

`iostat`输出显示了设备统计信息。第一列列出了三个设备：硬盘`/dev/sda`和两个LVM卷`dm-0`和`dm-1`。对于每一个设备，都显示了每秒平均事务数。然后你可以看到每秒读取和写入的字节数，以及总写入的字节数。

通过`iostat`，你还可以显示不同的性能参数。请查看相关页面获取详细概述。两个有趣的参数是`-c`，它显示CPU使用信息；以及`-d`，它显示设备使用信息。你还可以在连续模式下使用`iostat`，此时使用间隔和计数器。例如，命令`iostat -d /dev/sda 2 10`仅显示`/dev/sda`设备的使用统计数据，在2秒的间隔内总共进行10次轮询。当在此模式下使用`iostat`时，你会发现第一行中的读写数据值明显更高。这是因为第一行总结了自启动以来的总和，而其他行总结了每次轮询中的使用情况。

## vmstat

`vmstat`工具显示有关虚拟内存使用信息。像`iostat`一样，你可以在轮询模式下使用此工具，使用如`vmstat 2 5`的命令显示间隔2秒的5次轮询（见27.5节）。

### 列表 27.5 使用 vmstat 显示系统使用

```
[root@localhost ~]# vmstat 2 5
procs ---------memory---------- --swap------io------system----cpu----
r b swpd free buff cache si so bo in cs us us id wa
3 0 2192 16764 180 181148 0 0 10 48 89 0 0 100 0 0
0 0 2192 167640 180 181180 0 0 0 73 107 0 1 100 0 0
0 0 2192 167640 180 181180 0 0 0 69 107 0 0 100 0 0
0 0 2192 167640 180 181180 0 0 0 55 94 0 0 100 0 0
0 0 2192 167640 180 181180 0 0 0 68 127 2 1 98 0 0
```

`vmstat`显示的信息分类在不同的类别中：

- `procs`：提供有关上一次轮询中活动进程或等待I/O设备的进程数量的信息。
- `memory`：提供重要的内存使用参数信息，例如交换内存量、空闲内存以及当前分配给缓冲区或缓存的内存。
- `swap`：显示交换分区活动。
- `io`：显示I/O活动。
- `system`：提供有关系统发生的中断和上下文切换次数的信息。
- `cpu`：提供有关CPU使用信息，例如CPU花在用户空间、系统空间、空闲循环、等待I/O以及处理被窃取时间（stolen time）上的时间。

从`vmstat`可以获得的一个重要统计数据是交换出的块数。在Linux上，如果使用了交换分区，这并不糟糕。只有当有大量块从内存移动到交换分区时，情况才会糟糕。这通过`swap`下方的`si`和`so`参数指示。
