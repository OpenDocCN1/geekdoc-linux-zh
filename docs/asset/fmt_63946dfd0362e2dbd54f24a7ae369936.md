#将其标记为可用

## 变量与常量

在程序的开头，我们设置了两个位置：

```
heap_begin:
.long 0
```

```
current_break:
.long 0
```

记住，被管理的内存区域通常被称为堆（heap）。当我们汇程序时，我们不知道堆的起点在哪里，也不知道当前的断点在哪里。因此，我们为它们的地址留了空间，但目前只是用 0 填充。

接下来我们有一组常量来定义堆的结构。这个内存管理器的工作原理是：对于分配的每个内存区域，我们都会有一条描述内存的短记录。该记录包含一个留给可用标志的字，和一个留给区域大小的字。实际分配的内存紧随在该条记录之后。可用标志用于标记该区域是否可以用于分配，或者它当前是否正在使用。大小字段让我们知道该区域是否足够大以满足分配请求，以及下一个内存区域的位置。以下常量描述了记录：

```
.equ HEADER_SIZE, 8
.equ HDR_AVAIL_OFFSET, 0
.equ HDR_SIZE_OFFSET, 4
```

这表示头部信息总共 8 字节，可用标志从起始处偏移 0 字节，大小字段从起始处偏移 4 字节。如果我们足够小心，可以使用：

```
.equ UNAILABLE, 0
.equ AVAILABLE, 1
```

最后，我们有系统调用定义：

```
.equ BRK, 8
.equ LINUX_SYSCALL, 12
```

pushl %ep

### 分配函数（allocate）

这是分配函数。让我们看看它的概述：

- 1. 从堆的开始。
- 2. 检查是否到达堆的末端。
- 3. 如果到达堆的末端，从 Linux 获取内存，将其标记为“不可用”并返回。如果 Linux 不提供更多，返回 0。
- 4. 如果当前内存区域被标记为“不可用”，跳转到下一个并返回 2。
- 5. 如果当前内存区域太小无法满足请求，返回 2。
- 6. 如果内存区域可用且足够大，将其标记为“不可用”并返回。

现在带着这些思路回看代码。确保阅读注释以知道哪个寄存器持有哪个值。

```
pushl %ebp
movl %esp, %ebp
mov ST_MEM_SIZE(%ebp), %ecx
mov heap_begin, %eax
movl current_break, %ebx
```

这部分初始化了我们所有的寄存器。前两行是标准的函数操作。下一条移动指令从栈获取要分配的大小。这是我们唯一的函数参数。之后，它将堆的起始地址和断点移动到寄存器中。现在我准备好处理了。

下一个部分标记为 `alloc_loop_begin`。在这个循环中，我们将检查内存区域，直到找到一个可用的区域或确定我们需要更多内存。我们的第一条指令检查是否需要更多内存：

```
cmpl %ebx, %eax
je move_break
```

`%eax` 持有正在检查的内存区域，`%ebx` 持有末端之后的位置。如果要检查的区域在堆末端之后，意味着我们需要更多内存。让我们跳转到 `move_break` 看看发生了什么：

```
move_break:
addl $HEADER_SIZE, %ebx
addl %ecx, %ebx
```

### 第9章. 中级内存主题

```
pushl %eax
pushl %ecx
pushl %ebx
mov $SYS_BRK, %eax
int $LINUX_SYSCALL
```

当代码执行到这一步时，`%ebx` 存储了我们希望下一个内存区域的位置。因此，我们将头部大小和区域大小加到 `%ebx` 上，这就是我们希望系统断开点（system break）所在的位置。然后，我们将所有想要保存在的寄存器推入栈中，并调用 `brk` 系统调用。之后，我们检查是否有错误：

```
cmpl $0, %eax
je error
```

如果没有错误，我们将寄存器从栈中弹出，将该内存标记为不可用，记录内存的大小，并确保 `%eax` 指向可用内存的起始位置（即头部之后的位置）。

```
popl %ebx
popl %ecx
popl %eax
mov $UNAVAILABLE, HDR_AVAIL_OFFSET(%eax)
mov %ecx, HDR_SIZE_OFFSET(%eax)
addl $HEADER_SIZE, %eax
```

然后，我们存储新的程序断开点并返回分配内存的指针。

```
movl %ebx, current_break
movl %ebp, %esp
popl %ebp
ret
```

错误代码仅在 `%eax` 中返回 0，所以我们不再讨论它。

### 第9章. 中级内存主题

让我们回到循环的剩余部分。如果当前查看的内存没有超过堆的末尾会发生什么呢？让我们来看看。

```
movl HDR_SIZE_OFFSET(%eax), %edx
cmpl $UNAVAILABLE, HDR_AVAIL_OFFSET(%eax)
je    next_location
```

这里首先获取内存区域的大小并将其放入 `%edx`。然后它检查可用标志位，看它是否被设置为 `UNAVAILABLE`（不可用）。如果是，意味着该内存区域正在使用，因此我们必须跳过。所以，如果可用标志位设置为 `UNAVAILABLE`，就会跳转到标记为 `next_location` 的代码。如果可用标志位设置为 `AVAILABLE`（可用），则继续执行。

假设该空间是可用的，我们继续执行。然后我们检查此空间是否足够容纳请求的内存。该区域的大小存储在 `%edx` 中，因此我们执行以下操作：

```
cmpl %edx, %ecx
jle    allocate_here
```

如果请求的大小小于或等于当前区域的大小，我们就可以使用这个块。当前区域比请求的尺寸大关系，因为额外的空间将不会被使用。所以，让我们跳转到 `allocate_here` 看看发生了什么：

```
movl $UNAVAILABLE, HDR_AVAIL_OFFSET(%eax)
addl $HEADER_SIZE, %eax
movl %ebp, %esp
popl %ebp
ret
```

它将内存标记为不可用。然后它将指针 `%eax` 移动过头部，并将其作为函数的返回值。请记住，使用此函数的人甚至不需要知道我们的内存头部记录。他们只需要指向可用内存的指针。

好了，假设区域不够大。那该怎么办呢？那么，我们将到达标记为 `next_location` 的代码。每当我们发现当前内存区域无法分配内存时，就会使用这段代码。它做的仅仅是将 `%eax` 推进到下一个可能的内存区域，并回到循环开始。请记住 `%edx` 持有当前内存区域的大小，而 `HEADER_SIZE` 是内存区域头部大小的符号。所以这段代码将我们移动到下一个内存区域：

```
addl $HEADER_SIZE, %eax
addl %edx, %eax
jmp alloc_loop_begin
```

然后函数运行另一个循环。

每当你有一个循环时，你必须确保它总是结束的。最好的方法是检查所有可能性，并确保所有这些最终都会导致循环结束。在我们的情况下，有以下几种可能性：

- 我们将到达堆的末尾
- 我们将找到一个可用且足够大的内存区域
- 我们将前往下一个位置

前两项是会导致循环结束的条件。第三项会让循环继续。然而，即使我们找到了一个空闲区域，最终也会到达堆的末尾，因为它的尺寸有限的。因此，我们知道无论哪种条件成立，循环最终都将遇到终止条件。

### deallocate 函数

`deallocate` 函数比 `allocate` 函数要简单得多。这是因为它不需要进行任何搜索。它只需要将当前内存区域标记为 `AVAILABLE`，`allocate` 在下次被调用时就会找到它。所以我们有：

```
movl ST_MEMORY_SEG(%esp), %eax
subl $HEADER_SIZE, %eax
movl $AVAILABLE, HDR_AVAIL_OFFSET(%eax)
ret
```

在这个函数中，我们不需要保存 `%ebp` 或 `%esp`，因为我们没有改变它们，也不需要在最后恢复它们。我们所做的只是从栈中读取内存区域的地址，回退到头部开头，并将区域标记为可用。此函数没有返回值，所以我们不在乎在 `%eax` 中留下了什么。
