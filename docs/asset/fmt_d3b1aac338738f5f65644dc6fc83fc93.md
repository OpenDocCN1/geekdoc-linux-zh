
## 描述
使用 `nislink` 命令为名为 `name` 的 NIS+ 对象创建链接。如果 `name` 本身是一个链接，则跟踪它指向的链接对象。新链接将指向该对象而不是 `name`。在创建链接时，`nislink` 会验证链接对象是否存在。一旦创建链接，你可以删除或替换链接对象而不影响该链接。此时，链接将失效，尝试跟踪它时会向客户端返回 `NISERROR`。当表中的 `path` 属性指向链接而非另一个表时，如果在调用 `nis_list()` 时存在 `FOLLOWLINKS` 标志（见 `nis_tables(3N)`），则跟踪该链接；如果没有该标志，则忽略。如果标志存在且链接不再有效，则会向系统日志记录器发送警告并忽略链接。

## 选项
- `-D defaults` 指定创建链接时使用的另一组默认值。
- `-L` 如果 `name` 本身是一个链接，则跟踪它指向的链接对象。新链接将指向该对象而不是 `name`。

### 另
- `nisgrp(1)`
- `nismod(1)`
- `nisttl(1)`

## 示例

以下示例在 `foo.com` 域内创建一个名为 `hosts` 的链接，该链接指向 `hosts.bar.com` 对象。
```
castle% nisln hosts.bar.com hosts.foo.com.
```

以下示例创建一个 `example.sun.com` 链接，它指向 `eng.sun.com` 中 `hosts` 表中的一个条目...
```
castle% nisln '[name=example],hosts.eng.sun.com.' example.sun.com.
```

## 环境变量

- `NIS_PATH`: 如果设置了此变量且 NIS+ 名称不是完全限定的，则搜索每个指定的目录直到找到该对象（参见 `nisdefaults(1)`）。

## 退出状态

- `0` 成功。
- `1` 失败。

# nisls — 列出 NIS+ 目录内容

### 概要

```
/usr/bin/nisls [-dglmLMR][name...]
```

## 描述

使用 `nisls` 命令列出 NIS+ 目录或对象的内容。对于每一个 NIS+ 目录的名称，`nisls` 会列出该目录的内容。对于目录以外的每一个 NIS+ 对象，`nisls` 仅回显名称。如果你未指定名称，将列出搜索路径中的第一个目录（参见 `nisdefaults(1)`）。

## 选项

- `-d` 将 NIS+ 目录视为其他 NIS+ 对象，而不是列出其内容。
- `-g` 在长格式列出时，显示组所有者而非所有者。
- `-l` 以长格式列出，显示有关对象的额外信息，如类型、创建时间、所有者和访问权限。在长格式模式下，按以下顺序列出访问权限：所有者、组所有者和其他。
- `-L` 遵循链接。如果名称实际上指向链接，则跟随到被链接的对象。
- `-m` 在长格式列出时，显示修改时间而非创建时间。
- `-M` 仅限主服务器。从指定对象的主服务器返回信息。此选项保证了看到最新的信息，但代价是主服务器可能会忙碌。
- `-R` 递归列出目录。此选项在列出每个名称的过程中对找到的每个子目录重复列出。

## 环境变量

- `NIS_PATH`: 如果设置了此变量且 NIS+ 名称不是完全限定的，则搜索每个指定的目录直到找到该对象（参见 `nisdefaults(1)`）。

## 退出状态

- `0` 成功。
- `1` 失败。

## 属性

参见 `attributes(5)` 获取以下属性的描述：

| 属性类型 | 属性值 |
| --- | --- |
| 可用性 | SUNWnisu |

# nismatch, nisgrep — 搜索 NIS+ 表

### 概要

```
/usr/bin/nismatch [-AchMoPv] [-s sep] key tablename
/usr/bin/nismatch [-AchMoPv] [-s sep] colname=key... tablename
/usr/bin/nismatch [-AchMoPv] [-s sep] indexedname
/usr/bin/nisgrep [-AchiMov] [-s sep] keypat
/usr/bin/nisgrep [-AchiMov] [-s sep] colname=key...
```

## 描述

使用 `nismatch` 和 `nisgrep` 命令搜索 NIS+ 表。`nisgrep` 命令与 `nismatch` 命令的区别在于它能够接受正则表达式 `keypat` 作为搜索标准，而不是简单的文本匹配。

由于 `nisgrep` 使用回调函数，它仅限于搜索那些在表创建时专门设为可搜索的列。它比 `nismatch` 慢但更灵活。

使用 `nismatch` 时，服务器执行搜索；使用 `nisgrep` 时，服务器返回所有可条目，客户端进行模式匹配。
这两个命令的参数 `tablename` 都是要搜索表的 NIS+ 名称。如果你只指定一个键或 `keypat` 而不指定列名，则搜索第一列。你可以通过 `colname=key` 语法搜索特定的命名列。当你搜索多个列时，只有在所有列中都匹配的条目会被返回。此结果等同于逻辑连接操作。

`nismatch` 接受另一种形式的搜索标准 `indexedname`，

其 NIS+ 索引名称的格式为：

`[colname=value,...], tablename`

## 选项

- `-A` 返回表内的所有数据以及初始表拼接路径中所有表中的所有数据。
- `-c` 仅打印匹配搜索标准的条目计数。
- `-h` 在匹配条目之前显示表头行，其中包含表列名称。
- `-i` 在比较时忽略大小写区别。
- `-M` 仅限主服务器。将查询发送到指定数据的主服务器。此选项保证了看到最新的信息，但代价是主服务器可能会忙碌。
- `-O` 显示匹配的 NIS+ 对象的内部表示。
- `-P` 遵循拼接路径。指定如果初始搜索失败，则查询应遵循表的拼接路径。
- `-s sep` 指定分隔表列的字符。如果未指定字符，则使用表的默认分隔符（空格）。
- `-V` 在显示二进制数据时不抑制输出。

## 示例

`nismatch` 接受额外的搜索标准形式 `indexedname`，
其 NIS+ 索引名称的格式为：
`[colname=value,...], tablename`

## 示例

`nismatch` 在 `passwd` 域内搜索 `skippy` 的所有条目。

以下示例在 `passwd` 域内搜索名为 `skippy` 的所有条目。
```
castle% nismatch name=skippy passwd.org.com.
```

以下示例与上述类似，只是它在执行命令时的默认域不同于客户端默认域。
```
castle% nisgrep 'shell' passwd.org.com.
```

## 环境变量

- `NIS_PATH`: 如果设置了此变量且 NIS+ 名称不是完全限定的，则搜索每个指定的目录直到找到该对象（参见 `nisdefaults(1)`）。

## 退出状态

- `0` 成功。
- `1` 失败。

## 属性

参见 `attributes(5)` 获取以下属性的描述：

| 属性类型 | 属性值 |
|---|---|
| 可用性 | SUNWnisu |
