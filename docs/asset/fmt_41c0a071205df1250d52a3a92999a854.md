它大部分工作运行正常。问题出现在版本号的排序上。因为在字符集中 1 位于 5 之前，所以版本 10 排在了最顶端，而版本 9 则掉到了最后面。

为了解决这个问题，我们将对多个键进行排序。我们希望对第一个字段进行字母顺序排序，然后对第二个字段进行数值排序。`sort` 允许多次使用 `-key` 选项，以便指定多个键。事实上，一个键可以包含字段范围（正如我们之前的示例所示），`sort` 使用一个从第一个字段开始延伸到行尾的键。以下是我们的 `sort` 语法：

```
$me@linux]$ sort --key=1,-key=2n distros.txt
Fedora 5 03/20/2006
Fedora 6 10/24/2006
Fedora 7 05/31/2007
Fedora 8 11/08/2007
Fedora 9 05/13/2008
Fedora 10 11/25/2008
SUSE 10.1 05/11/2006
SUSE 10.2 12/07/2006
SUSE 10.3 10/04/2007
SUSE 11.0 06/19/2008
Ubuntu 6.06 06/01/2006
Ubuntu 6.10 10/26/2006
Ubuntu 7.04 04/19/2007
Ubuntu 7.10 10/18/2007
Ubuntu 8.04 04/24/2008
Ubuntu 8.10 10/30/2008
```

虽然为了清晰起见我们使用了选项的长格式，但 `-k 1,1 -k 2n` 是完全等价的。在第一个键选项中，我们指定了包含第一个键的字段范围。因为我们想将排序限制在第一个字段，所以指定了 `1,1`，这意味着“从字段 1 开始到字段 1 ”。在第二个实例中，我们指定了 `2n`，这意味着字段 2 是排序键，且排序应该是数值型的。可以在键末尾包含一个选项来指示要执行的排序类型。这些选项字母与 `sort` 程序的全局选项相同：`b`（数值排序）、`r`（反向排序）等。

我们列表中的第三字段包含一个格式不便于排序的日期。日期通常以 YYYY-MM-DD 顺序格式化以便按时间顺序排序，但我们使用的是美式格式 MM/DD/YYYY。我们该如何按时间顺序排序它呢？

幸运的是，`sort` 提供了一种字段内偏移量的指定方法，因此我们可以带范围的键。

```
[me@linux~$ sort -k 3,7nbr -k 3.1nbr -k 3.4nbr distros.txt
Fedora 10 11/25/2008
Ubuntu 8.10 10/30/2008
SUSE 11.0 06/19/2008
Fedora 9 05/13/2008
Ubuntu 8.04 04/24/2008
Fedora 8 11/08/2007
Ubuntu 7.10 10/18/2007
SUSE 10.3 10/04/2007
Fedora 7 05/31/2007
Ubuntu 7.04 04/19/2007
SUSE 10.2 12/07/2006
Ubuntu 6.10 10/26/2006
Fedora 6 10/24/2006
Ubuntu 6.06 06/01/2006
SUSE 10.1 05/11/2006
Fedora 5 03/20/2006
Fedora 10 11/25/2008
```

通过指定 `-k 3.7`，我们指示 `sort` 使用从第三字段第七个字符开始的键，这对应于年份。同样，我们指定了 `-k 3.1` 和 `-k 3.4` 来分离月份和日期。包含 `b` 选项是为了抑制前面的数字（这些数字随行而异，从而影响日期的输出）。

某些字段没有使用制表符和空格作为分隔符，例如这里的 `/etc/passwd` 文件：

```
[me@linuxbox ~]$ head /etc/passwd
root:x:0
daemon:x:1
bin
...
```

该文件的字段是用冒号（:）分隔的，那么如何使用键来排序此文件？使用 `-t` 选项来定义分隔符。对第七字段进行排序（默认），我们可以这样做：

```
[me@linuxbox ~]$ sort -t ':' -k 7 /etc/passwd
root:x:0
daemon:x:1
bin
sys:x:3
sync:x:5
games
man
lp
mail
news
me:x:10
root:x:11
dhcp:x:12
gdm
hplip:x:14
log
messagebus:x:16
polkituser:x:17
pulse:x:18
```

通过通过指定冒号作为字段分隔符，我们可以对第七字段进行排序。

## uniq

与 `sort` 相比，`uniq` 程序非常轻量。`uniq` 执行一项简单的任务：当给出一个排序后的文件（或标准输入），它会删除重复行并将结果发送到输出。它通常与 `sort` 配合使用以清理重复输出。虽然 `uniq` 是经常与 `sort` 的传统工具，但 GNU 版本的 `sort` 支持 `-u` 选项，它可以从输出中删除重复项。让我们创建一个文本文件尝试一下，如下：

```
[me@linuxbox ~]$ cat > foo.txt
a
b
c
```

记得输入 CTRL-D 来结束标准输入。现在，如果我们对我们的文本文件运行 `uniq`，我们会得到：

```
$ uniq foo.txt
```

结果与我们的原始文件不同；重复项没有被删除。为了让 `uniq` 完成工作，必须先进行排序。

```
$ sort foo.txt | uniq
```

这是因为 `uniq` 只删除相邻的重复行。`uniq` 有多个选项。表 20-2 列出了常用的选项。

### 表 20-2：常用选项

| 选项 | 长选项 | 描述 |
| :--- | :--- | :--- |
| `-c` | `--count` | 输出重复行列表，带有该行出现的次数。 |
| `-d` | `--repeated` | 输出重复行，而不是唯一行。 |
| `-f n` | `--skip-fields=n` | 忽略每行前面的 `n` 个字段。字段通过空格分隔，与 `sort` 相同；与 `sort` 不同，`uniq` 没有设置备用字段分隔符的选项。 |
| `-i` | `--ignore-case` | 在行比较期间忽略大小写。 |
| `-s n` | `--skip-chars=n` | 跳过（忽略）每行的 `n` 个字符。 |
| `-u` | `--unique` | 只输出唯一行。带有重复项的行会被忽略。 |
