
| Q | 退出 `sed` 不再处理后续行。 |

| s/regexp/replacement | 在找到 `regexp` 处替换 `replacement`。`replacement` 可以包含特殊字符 `&`，它相当于匹配到的文本。此外，`replacement` 可以包含 `\1` 到 `\9`，这些是 `regexp` 中对应子表达式的内容。在最后的斜杠之后，可以指定可选标记来修改 `s` 命令的行为。 |

| y/set1/set2 | 通过将字符从 `set1` 转换为 `set2` 来执行转写。注意，与 `tr` 不同，`sed` 要求两个集合的长度相同。 |

`sed` 命令是最常用的编辑命令。我们将通过对 `distros.txt` 文件进行编辑来演示它的部分威力。我们之前讨论过 `distros.txt` 中的日期字段不是“计算机友好”的格式。当日期格式为 `MM/DD/YYYY` 时，如果格式是 `YYYY-MM-DD` 会更好（方便排序）。手动对文件进行此操作既耗时又容易出错，但使用 `sed` 可以在一步内完成。

```
[me@linux ~]$ sed 's/\([0-9]{2})\//\([0-9]{2})\/\([0-9]{4})/\3-\2-\1/' distros.txt
SUSE 10.2 2006-02-12
Fedora 10 2008-11-25
SUSE 11.0 2008-06-19
Ubuntu 8.04 2008-04-24
Fedora 8 2007-11-08
SUSE 10.3 2007-10-04
Ubuntu 6.10 2006-10-26
Fedora 7 2007-05-31
Ubuntu 7.10 2007-10-18
Ubuntu 7.04 2007-04-19
Fedora 6 2006-10-24
Fedora 9 2008-05-13
Ubuntu 6.06 2006-06-01
Ubuntu 8.10 2008-10-30
Fedora 5 2006-03-20
```

哇！那是一个看起来很丑的命令。但它确实有效。在仅一步之内我们就更改了文件中的数据格式。这也是为什么正则表达式有时被称为“只写媒介”的完美示例。我们可以编写它们，但有时无法读取它们。在我们被这个命令吓得逃跑之前，让我们看看它是如何构建的。首先，我们知道命令将具有这种基本结构：

```
sed '/regex/replacement/' distros.txt
```

我们还剩下两个问题。第一个问题是正则表达式中额外的斜杠会干扰 `sed` 尝试解释 `s` command。第二点是，由于 `sed` 默认只接受基础正则表达式，因此我们正则表达式中的几个字符将被视为字面量，而不是元字符。我们可以通过在方地使用反斜杠来转义这些冲突字符，从而解决这两个问题。

```
sed 's/([0-9]{2})\\([0-9]{2})\\([0-9]{4})\$3-1-\2/' distros.txt
```

搞定！

`s` 命令的另一个特性是可以使用跟在替换字符串后面的可选标志。其中最重要的是 `g` 标志，它指示 `sed` 对整行进行全局搜索并替换，而不仅仅是针对第一个匹配项（这是默认行为）。这里有一个示例：

```
[melinuxbox ~] echo "aaabbccc" | sed 's/b/B/'
aAbbBbb
```

我们看到替换执行了，但仅针对字母 `b` 的第一个实例，而其余实例保持不变。通过添加 `g` 标志，我们能够更改所有的实例。

```
[melinuxbox ~] echo "aaabbccc" | sed 's/b/B/'
aaaBbb
```

所以，我们仅通过命令行向 `sed` 发送命令。也可以使用 `-f` 选项在脚本文件中构建更复杂的命令。为了演示，我们将使用 `sed` 配合我们的 `distros.txt` 文件生成一份报告。我们的报告将在顶部有一个标题、我们修改后的日期，并将所有发行版名称转换为大写。为了做到这一点，我们需要编写一个脚本，因此我们将启动编辑器并输入以下内容：

# sed script to produce Linux distributions report

1

\

## Linux Distributions Report

```sed
s/([0-9]{2})\\([0-9]{2})\\([0-9]{4})\$3-1-\2/\n/abcdefghijklmnopqrstuvwxyz/ABCDEFGHIJKLMNOPQRSTUVWXYZ/g
```

我们将脚本保存为 `distro.sed` 并像这样运行它：

```
[melinuxbox ~]$ sed -f distro.sed distros.txt
```

如我们所示，脚本产生了预期的结果，但它是如何实现的呢？让我们再次查看脚本。我们将使用 `cat` 为行进行编号。

```
[melinux ~]$ cat -n distro.sed
1 # sed script to produce Linux distributions report
2
3 i \
4 \
5 Linux Distributions Report
6
7 s/([0-9]{2})\\([0-9]{2})\\([0-9]{4})\$3-1-\2/\n/
g
```

我们脚本的第 1 行是注释。像 Linux 系统上的许多配置文件和编程语言一样，注释以 `#` 字符开头，后面跟着人类可读的文本。脚本中的注释（尽管不在命令内部）对于任何可能需要识别或维护脚本的人来说非常有帮助。

第 2 行是一个空行；添加空行可以提高可读性。

许多命令支持行地址。这些地址用于指定对输入的哪些行执行操作。行可以表示为单行号、行范围，以及特殊行号 `$`，它表示输入的最后一行。

第 3、4、5 和 6 行包含要在地址 1（输入的第一行）处插入的文本。`i` 命令后面紧跟一个反斜杠和一个回车符的序列，以产生一个转义的回车符和所谓的“续行符”。这种序列在许多情况下（包括 shell 脚本）允许将回车符嵌入到文本脚本中，而不会向解释器（在此例中为 `sed`）发出行结束的信号。`i` 和 `a`（替换文本）命令允许多行文本，只要该序列后面没有跟随另一个反斜杠。

第 7 行和第 8 行包含替换命令。
