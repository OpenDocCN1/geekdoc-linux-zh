## InfoObject (Info对象)

我们现在来看 InfoObject 以及 InfoObject 内部特定于查询定义的定义。正如讨论 InfoObject 作为数据提供者（InfoProvider）时提到的，InfoObject 特有的组件与用于定义数据/值在查询中的格式和显示方式组件是不同的。我们将讨论 InfoObject 标签页中出现的每个影响查询设计和格式的字段。在 InfoObject 的每个标签页上，都有影响查询的特定指示器——其中某些的影响比其他的更大。因此，我们将从初始屏幕开始向回操作。

图 23 显示了“常规”（General）标签页。在此屏幕上，“特征文档属性”（Characteristic document attribute）字段值得关注。在配置过程中，所有带有 BI 的对象都可以分配文档；如果已定义，它们可以在查询过程中分配文档。此指示器允许您不仅将文档分配给特征或值，还可以分配给特征和关键特性的组合。因此，如果您被需要为查询中的特定单元格分配文档（例如，如果您需要解释为什么特定区域和产品仅增长了 10%，因此您需要为查询中的特定单元格分配文档），您可以使用此指示器实现所有功能。只需记住，如果您对执行此操作感兴趣，必须对查询涉及的所有特征开启此指示器。否则，此功能将不可用。

图 231 显示了“业务资源管理器”（Business Explorer）标签页。该标签页包含查询过程中涉及的最多数指示器，如下列表所示：

- `Display`：适用于带有文本的特征。在此字段中，您可以选择是否要在业务资源管理器中显示文本，以及显示显示哪些文本。您可以从以下选项中选择：不显示（No Display）、键（Key）、键和文本（Key and Text）或文本和键（Text and Key）。此设置可以在查询中被覆盖。这将是查询的默认设置。

- `Text Type`：适用于特征和文本。在此字段中，您设置是否要在业务资源管理器中显示短文本、中等文本或长文本。当然，您还需要上传特定的文本类型才能使其生效。

- `BEx Description`：在此字段中，您可以确定出现在业务资源管理器中的描述。您可以在特征的长描述和短描述之间进行选择。此设置可以在查询中被覆盖。

- `Selection`：该选择描述了在查询中是否限制以及如何限制特征值。如果您选择了“每个单元格唯一”（Unique for Every Cell）选项，则该特征在所有查询的每一列和每个结构中必须限制为一个值。您不能在聚合中使用此特征。此类特征的典型示例是计划/实际 ID（Plan/Actual ID）和值类型（Value Type）。

- `Filter Selection in Query Definition`：此字段描述了在定义查询时如何确定值的选择或限制。因此，在查询设计器中，当您限制特征时，通常会显示来自主表的键值。对于没有主表的特征，则显示 SID 表中的值。在许多情况下，只显示包含在数据提供者中的值更有用。因此，您也可以选择“仅数据提供者中的值”（Only Values in InfoProvider）选择，并限制您在查询定义期间看到的值的总数。

- `Filter Selection in Query Execution`：此字段告诉您在执行查询时如何确定值的选择。当执行查询时，值的选择通常由查询所选的数据决定。这意味着只有在当前导航状态中已选数据的值会被显示。然而，在许多情况下，包含额外的值是有用的。因此，您也可以选择“仅数据提供者中的值”（Only Values in InfoProvider）设置和“主数据表中的值”（Values in Master Data table）。但是如果您这样做，在选择筛选值时可能会收到“未找到数据”的消息。
