
安装 Linux 时的根本问题在于，在大多数情况下，用户希望保留 Windows 及其所有程序。目前有几个发行版允许在 Windows 文件系统中安装 Linux，要么在所谓的磁盘映像（一个非常大的文件）中，就像某些旧发行版那样，要么直接在 Windows 文件系统中（例如 WinLinux 2000）。然而，为了获得良好的性能，最好将 Linux 安装在与 Windows 不同的分区上，使用 Linux 自己的文件系统。通常需要对硬盘进行分区，因为 Windows 在安装时通常占据了整个硬盘的大小。

直到最近，这种划分意味着不可避免地丢失硬盘上包含的所有信息。目前，在安装 Linux 发行版时，允许在不丢失信息的情况下划分硬盘，以缩小 Windows 分区的大小，并在安装 Linux 时创建一个新的分区。在 Red Hat 或 Mandrake 的情况下，存在自动分配的可能性，如果不知道如何操作分区，这将非常有用。

对于 Linux，必须至少创建一个根原生分区。它应具有所需的大小，并且必须创建一个交换分区，其大小至少是设备 RAM 的两倍，最高不超过 512 MB。在此过程中，务必小心不要擦除驻留 Windows 的分区，否则**所有**信息都将永久丢失。

### 系统配置
- **Root 密码**：安装程序要求输入 root 或管理员密码，通过该密码可以访问系统的所有配置区域，这是普通用户无法做到的。
- **创建用户**：安装程序要求输入登录名和密码以创建第一个用户，出于安全原因，该用户不具备必要的管理员权限。
- **引导加载程序**：另一个需要考虑的要点是你希望如何引导 Linux。如果存在 Windows，最简单的方法是安装 `LILO` 或 `GRUB`，这些程序负责根据用户在启动 PC 时指定的内容引导两个操作系统。在保存引导加载程序到磁盘第一个扇区的选项中必须进行选择。如果有一个重新安装 Windows 的选项，将引发引导 Linux 的问题，因为该操作系统将接管 PC 和引导系统的控制权，移除 `LILO`（并阻止 Linux 引导）。另一种非常简单的方法是使用在安装 Linux 时创建的启动软盘。
- **安装退出**：用户被告知已安装的服务，安装程序完成。

Linux 首次启动后，初始向导将启动，并允许配置基本系统项，例如要使用的桌面类型（`KDE`、`Gnome`、`WindowMaker` 等）以及一些服务如邮件。

## 结论
- 操作系统架构定义了一组组件，以及它们如何彼此交互并与环境交互。
- 研究操作系统架构时最重要的方面是系统核心（内核）的概念。内核的核心特性是它以特权模式运行。
- 操作系统架构的主要类型是基于单片和微内核的架构。单片架构要求系统的核心功能集中在内核中，其最重要的优势是性能。在微内核系统中，在特权模式下...模式，仅执行基本功能，此类系统的主要优势在于可靠性和灵活性。
- 操作系统直接与计算机硬件交互。现代计算机体系结构提供了许多操作系统支持工具。
- 操作系统与应用程序交互。它提供了一组系统调用，用于访问在核心中实现的功能。对于应用程序而言，系统调用连同系统库工具一起，可通过应用程序编程接口访问。

## 第 3 章：进程与流管理
考虑操作系统的两个主要抽象，用于描述程序代码的执行——进程和流——以及它们在操作系统中的实现特性、它们可能驻留的状态，以及与它们交互的基本机制（创建、完成和终止等手段等）。

### 进程和流的基本概念

#### 现代操作系统中的进程和流
在现代操作系统中，内核代码（属于其各个子系统）和用户程序代码同时执行。不同的操作各不相同：一些程序和子系统遵循处理器的指令。其他忙于 I/O，还有一些等待用户或其他应用的请求。为了简化系统中这些操作的管理，建议分配一组基本活动元素，并定义操作系统与这些元素交互的接口。

*进程*是指操作系统的抽象，它结合了在特定时间点执行某个程序所需的一切。程序是存储在磁盘上的机器指令序列，如有必要，会被加载到内存中并执行。可以说，在运行时，程序代表一个进程。程序与进程之间的一一对应关系仅在特定时间点建立：一个进程在同一时间可以执行多个程序的代码，一个程序的代码可以同时执行多个进程。

成功的程序需要某些资源。它们包括：
- 顺序执行程序代码所需的资源（主要是 CPU 时间）。
- 允许存储确保执行程序代码的信息的资源（CPU 寄存器、RAM 等）；这些资源组识别了进程的两个组件：
  - 处理器的可执行指令序列。
  - 这些指令及其数据所在的内存地址集（`$address\ space$`）。

这些部分的划分也有其合理性，因为在同一个地址空间中可能存在多个顺序执行的指令序列，它们共享相同的数据。需要区分为指令序列和地址空间，这导致了流的概念。

线程（控制流）是指使用共享进程空间的一组顺序执行的处理器指令。由于同一时间可以有多个线程，操作系统的任务是组织处理器在它们之间切换并安排它们的执行。在多处理器系统中，单个线程的代码可以在独立的处理器上执行。

因此，`$process\ is$` 被称为一个或多个线程以及这些线程在其中执行的受保护地址空间的集合。

进程地址空间的安全性是其最重要的特征。进程代码和数据不能被另一个进程直接读取或覆盖；从而保护自己免受严重 bug 和未经授权的访问尝试。

自然，只有 `$direct$` 访问是不可接受的（例如，使用简单的数据传输指令写入内存）；进程间的数据交换原则上是可能的，但为此目的，`$special\ means$`，即所谓的 `$interprocess\ interaction$` 手段，应该被使用。这些工具比直接访问更复杂，运行速度更慢，但提供了对数据访问时意外错误的保护。

与进程不同，管理总内存的流，其流数据不针对其他流的访问进行安全保护，前提是所有流都在同一进程的地址空间中执行。这提供了额外的应用程序开发能力，但使编程复杂化。

受保护的进程地址空间建立了在单台机器上执行代码的抽象，而线程提供了在单个专用处理器上顺序执行指令的抽象。进程的地址空间并不总是对应于 RAM 地址。例如，它可能映射文件或 I/O 控制器的寄存器，因此向该空间中的特定地址写入要么写入文件，要么执行 I/O 操作。这种技术被称为 *内存映射 (memory mapping)*。

### 进程和流模型
进程（安全地址空间）的最大数量以及它们执行的线程数在不同系统中可能有所不同。
- 在单任务系统中，只有一个地址空间，其中在任意时刻只能执行一个流。
- 一些嵌入式系统也有一个地址空间（一个进程），但允许许多线程执行。在这种情况下，可以组织并行计算，但未实现数据保护。
- 在类似传统 UNIX 版本的系统中，允许许多进程，但在进程地址空间内只执行一个线程。这是传统的单线程 *进程模型*。此模型中流的概念不适用，但使用术语“进程间切换”、“进程调度”、“进程指令序列”等（在此，术语进程指单个流）。
- 大多数现代操作系统（如 Windows XP 系列、UNIX 的现代版本）可以在每个进程的地址空间中拥有许多进程。这些系统支持多线程或实现 *流模型*。此类系统中的进程被称为 *多线程进程*。

将来，“流”一词用于指代执行指令的顺序，除非在讨论进程模型的实施时。

### 进程和流的组件
进程的元素包括：
- 受保护的地址空间。
- 整个进程共用的数据（这些数据可以由其所有流共享使用）。
- 资源使用情况信息（打开的文件、网络连接）。
- 进程流信息。

流包含以下元素：
- 处理器的状态（由其寄存器中的当前数据组成），包括处理器当前指令的计数器。
- 流堆栈（内存区域，其中调用其代码中的局部流变量和函数返回地址）。

### 进程和流状态
流允许以下状态：
- *创建* (new) - 线程正在创建过程中。
- 执行 (running) - 指令流处理器执行（在特定时间，在单个处理器上，只有一个线程可以处于此状态）。
- 等待 (waiting) - 等待某个事件流（如完成操作）；此状态也称为阻塞和终止流。
- 就绪 (ready) - 流期望调度器在其拥有所有必要资源（除 CPU 时间外）时切换 CPU 到它。
- 终止 (terminated) - 线程已完成执行（除非其资源已从系统中移除，否则它进入附加状态 - 僵尸状态）。

流在待机和就绪状态之间的转换基于任务调度或流调度。在调度线程时，确定哪些线程需要在完成 I/O 操作后恢复，如何组织系统期望。待机和执行状态之间的转换需要处理器时间调度。基于此类调度的算法，确定哪些已完成的线程需要在特定时间执行，何时需要中断线程的执行以切换到另一个就绪线程，等等。

对于实施进程模型的系统，通常谈论的是进程状态，而不是流状态，以及进程调度；实际上，在这种情况下，进程的状态明显对应于其单个流的状态。
