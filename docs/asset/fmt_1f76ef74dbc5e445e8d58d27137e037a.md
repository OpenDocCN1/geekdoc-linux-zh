
程序或脚本经常在执行过程中崩溃或无法启动。由于行为的不可预测性，且捕获事件发生时机需要精确的定时控制，这类问题很难解决。我们有时希望在进程启动之前、进程启动时（或监控开始时），或者在进程死亡作为后事件时执行某些命令。时机就是一切！我们可以编写脚本来等待进程启动或监控进程，我们可以执行一些操作并在结束时记录时间戳。监控进程在某些方面是独有的——例如，通过进程名、用户名、PPID 甚至是日期。

在本章中，我们涵盖了四个脚本：

- 监控进程启动。
- 监控进程停止。
- 监控进程启动以及事件发生时的监控。
- 监控进程停止，同时跟踪当前活动进程的数量，并提供带有时间戳和所有 PID 列表的用户通知。我们还添加了前、启动和后事件功能。

使用这些功能之一的两个示例是：在重启系统之前等待备份完成，以及在进程启动时发送电子邮件。

## 语法

与我们所有的脚本一样，我们首先获取正确的命令语法。为了查看系统进程，我们希望查看所有进程，而不是针对特定用户的限制视图。要列出所有进程，我们使用 `ps` 命令并配合 `-ef` 参数。使用 `grep` 配合 `ps -ef` 命令来过滤输出。`grep` 命令会产生额外的行输出。其中一行来自脚本名，这是没有必要的。为了移除这两行，可以使用 `grep -v` 或 `egrep -v` 来排除这些输出。根据此规范并使用变量，我们可以使用以下命令：

```bash
ps -ef | grep $PROCESS | grep -v "PROCESS" | grep -v $SCRIPT_NAME
```

之前的命令将给出一个完整的进程列表，排除脚本名和目标进程。这将只留下我们感兴趣的实际进程。如果至少有一个进程正在运行，该命令的返回值为 0；如果没有 `$PROCESS` 变量指定的进程正在执行，它将返回非零值。用于监控进程启动，或者保持循环直到从运行到执行结束发生转换，反之亦然。

## 监控进程启动

现在我们有了命令语法，就可以编写等待进程启动的脚本了。这个 shell 脚本非常简单，因为它会在循环中运行，直到进程启动。第一步是检查参数的数量——即要监控的进程。如果进程当前正在运行，我们将通知用户并退出。否则，我们将一直循环直到目标进程启动，然后显示启动的进程名。循环位于列表 8.1。

```bash
RC=1
until (( RC == 0 )) # 循环直到返回码为零
do
    # 在每次循环迭代中检查 $PROCESS
    ps -ef | grep $PROCESS | egrep -v "grep*" | grep -v $SCRIPT_NAME >dev/null 2>&1

# 检查返回码!!!
    if (( $? == 0 )); # 是否已启动????
    then
        echo "$PROCESS has Started Execution...`date`\n\n"
        # 显示是谁启动的！！
        ps -ef | grep $PROCESS | grep -v grep "PROCESS" | grep -v $SCRIPT_NAME

        echo "\n# 退出前留几空行\n"
        exit 0 # 退出...
    fi
    sleep SLEEP_TIME # 需要降低 CPU 负载!! 1 秒或更长
done
```

列表 8.1 进程启动循环（续）

列表 8.1 中有几点需要指出。首先，注意我们正在使用数值测试，它由双括号 `(( expression ))` 指定。数值测试可以在 `if` 和 `until` 控制结构中看到。当使用双括号数值测试时，我们不使用美元符号 `$` 来引用用户定义的变量——即 `$`。如果你使用 `$$`，测试可能会失败！这种测试方法知道该值是一个数值，并在测试之前需要将字符字符串转换为数值字符串。这通过节省 CPU 周期节省了时间。不要在 `until` 中使用 `$..`。我们必须对系统变量使用 `$`——例如，`$?` 和 `$!`。此外，在进行相等性测试时我们使用双等号——例如，`until (( RC == 0 ))`。如果你使用单等号，它会被视为赋值而不是相等性测试！未使用双等号是最常见的错误之一，而且在排故障期间很难发现。此外注意列表 8.1，我们在每次循环迭代中都执行了睡眠。如果你没有设置睡眠间隔，CPU 的负载可能会成为负担。尝试编写一个带有睡眠间隔的循环。循环位于列表 8.1。
