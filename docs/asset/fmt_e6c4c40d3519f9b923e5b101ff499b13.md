- `nautilus`：通常在 KDE 桌面上使用的文件管理器。关于操作此工具的优秀文档可以在 http://www.gnome.org/users/guide-latest/gos/nautilus.html 找到。
- `conqueror`：用于 KDE 桌面的文件管理器。手册位于 http://docs.kde.org/en/kdebase/conqueror。
- `mc`：Midnight Commander，仿 Norton Commander 风格的 Unix 文件管理器。所有文档均从 http://www.gnu.org/software/midnight-commander/doc 获取。

## 创建目录

使用 `mkdir` 命令创建目录。你可以使用 `ls -ld` 查看新创建目录的属性：

```
mkdir test
ls -ld test
```

你可以一次性创建多个目录，使用 `mkdir` 命令的多个参数：

```
mkdir dir1 dir2 dir3
```

如果你想创建一个嵌套的层级结构，可以使用 `-p` 选项：

```
mkdir -p a/b/c
```

`-p` 选项允许在父目录不存在时创建它们。如果目录已经存在，则不会报错。

## 删除目录

使用 `rmdir` 删除空目录：

```
rmdir empty_dir
```

如果目录不是空的，`rmdir` 会报错。在这种情况下，可以使用 `rm` 命令配合 `-r` 选项来删除目录及其内容：

```
rm -r non_empty_dir
```

**注意：** 使用 `rm -r` 时要非常小心，因为它会递归删除目录下的所有内容。

```
rm: descend into `archive`? y
rm: descend into directory `archive/reports`? y
rm: remove directory `archive/reports`? y
rm: descend into directory `archive/backup`? y
rm: remove archive/backup/sysbup200112.tar? y
rm: remove directory `archive/backup`? y
```

我们将在第 7 章“家甜 /home”中讨论如何将其设置为默认，该章节将讨论自定义你的 shell 环境。

## 查找文件

### 使用 shell 特性

所有的替换都可以同时使用；shell 在方面非常有逻辑性。例如，Bash shell 处理如 `ls dirname=*/[2-3].` 这样的表达式没有问题。

在其他 shell 中，星号 `*` 通常用于减少输入工作量：人们会输入 `dir*` 而不是 `cd directory`。但在 Bash 中，这是没有必要的，因为 GNU shell 具有文件名自动补全功能。这意味着你可以输入命令（在任何地方）或文件（在当前目录下）的前几个字符，如果你感到困惑，shell 会找出你的意思。例如，你可以通过输入 `ls` 并两次 Tab 键而不是按回车键来检查是否有以字母 A 开头的文件。如果只有一个以 "A" 开头的文件，该文件将显示作为 `ls`（或任何其他 shell 命令）的参数。

### which

查找文件的一种非常简单的方法是使用 `which` 命令，在用户搜索路径（search path）列出的目录中查找所需文件。当然，搜索路径包含包含可执行程序的目录路径，这对于普通文件无效的。在排除“Command not Found”（未找到命令）问题时，`which` 命令非常有用。在下面的示例中，你无法使用 `acreload` 命令，而她的同事在同一系统上却完全可以使用。这个问题与上一部分的 PATH 问题类似：Tina 的同事告诉她可以在 `/opt/acreload/bin` 中看到需要的程序，但这个目录不在她的路径中：

```bash
tina-> which acreload
/usr/bin/which: no acreload in (/bin:/usr/bin:/usr/bin/X11)
```

可以通过提供运行命令的完整路径或重新导出 PATH 变量来解决该问题：

```bash
tina-> export PATH=$PATH:/opt/acreload/bin
tina-> echo $PATH
/bin:/usr/bin:/usr/bin/X11:/opt/acreload/bin
```

### 关于文件和文件系统

使用 `which` 命令还会检查某个命令是否是另一个命令的别名：

```bash
gerrit-> which -a ls
ls is aliased to `ls -F --color=auto'
ls is /bin/ls
```

如果这在你的系统上不起作用，请使用 `alias` 命令：

```bash
tille@www:~/mail alias ls
alias ls='ls--color'
```

### Find 和 locate

当搜索搜索路径列出的路径之外的路径时，真正的工具。来自 UNIX 的 `find` 工具非常强大，这可能导致其语法稍微有些直接。然而，GNU `find` 在语法上存在问题。该命令不仅允许你搜索文件，还可以接受文件大小、最后修改日期和文件属性作为搜索标准。最常见的用法是查找文件：

```bash
find <path>-name <searchstring>
```

这可以被解释为“在给定路径包含的所有文件和子目录中查找，并打印包含搜索名称的文件名”（而不是内容中）。

`find` 的另一个应用是搜索特定大小的文件，如示例所示，用户 peter 想要在当前目录或其一个子目录下查找所有大于 5 MB 的文件：

```bash
peter-> find . -size +5000k
psychotic_chaos.mp3
```

如果你深入研究手册页（man pages），你会发现 `find` 还可以对找到的文件执行操作。一个常见的例子是删除文件。最好的方法是先不带 `-exec` 选项测试是否选中了正确的文件，之后运行命令删除所选文件。注意，以 .tmp 结尾的搜索：

```bash
peter-> find . -name "*.tmp" -exec rm {} \;
```

### 优化！

此命令每找到一个符合要求的文件，就会调用一次 `rm`。在最坏的情况下，可能会调用数千或数百万次。这对你的系统是一个很大的负担。

更现实的方法是使用管道（`|`）或 `xargs` 工具作为参数。这样，`rm` 只有在命令行满时才被调用，而不是每个文件调用一次。有关使用 I/O 重定向来简化日常任务，请参阅第 5 章 I/O 重定向。

后来（根据手册页，是在 find 出现 20 年后），`locate` 被开发了。这个程序更容易使用，但比 find 受限更多，因为它的输出在一个索引数据库上，该数据库每天更新一次。另一方面，在 locate 数据库中搜索使用的资源比 find 少，因此几乎可以瞬间显示结果。

如今大多数 Linux 发行版都使用 `locate`，增强型 locate 是 locate 的现代版本，它可以防止用户获取他们无权读取的输出。root 家目录下的文件就是一个例子，这些文件通常不对公众开放。想要查找了解 C shell 的用户执行 `locate .cahrc` 命令，以显示所有拥有 C shell 自定义配置文件的用户。
