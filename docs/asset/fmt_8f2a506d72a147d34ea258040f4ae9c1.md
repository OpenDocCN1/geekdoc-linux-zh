
邮件交换器 (MX) 记录标识将给定域的邮件递送到何处。当用户发送消息时，主机向 `/etc/resolv.conf` 文件中指定的服务器发送 MX 查询。MX 查询包括用户指定的域名。如果指定的收件者是 `jsmith@harmonics.com`，那么 MX 查询包含域名 `harmonics.com.`。查询的服务器获取其 MX 记录，找到与指定域名匹配的条目，并响应主机的 IP 地址。MX 记录遵循 `named.hosts` 文件。以下是 MX 记录的语法：

```
classname IN MX preference mx_host
```

其中

`domainname` 指定 `mx_host` 中指定的主机充当邮件交换器的域名。

- `IN` 指定类为 IN。
- `MX` 指定类型为 MX。
- `preference` 指定指定服务器的优先级。`preference` 可以取 0 到 65535 之间的值。

一个域名可能由有多个主机代表其担任邮件交换器的角色，每个主机分配一个不同的优先级值。优先级值具有顺序意义。邮件投递首先尝试递给优先级值较低的交换器。如果尝试失败，将尝试递给下一个邮件交换器。这里有一个有助于解释该概念的示例：

```
harmonics.com IN MX 1 flute.harmonics.com.
```

```
harmonics.com IN MX 2 bass.harmonics.com.
```

根据 MX 记录，`flute` 和 `bass` 两个主机都是 `harmonics.com` 域的邮件交换器，优先级分别为 1 和 2。因此，发往 `user@harmonics.com` 的邮件应该首先尝试递给 `flute`（因为优先级更高），如果 `flute` 未响应，则应尝试递给 `bass`。

`mx_host` 标识 `domainname` 应该递到的服务器

接下来的章节将帮助你实践已经解释的关于资源记录的内容。你将看到如何设置主服务器、备服务器以及缓存服务器。

## 配置主名称服务器

后续章节描述了在主机 `jade` 上启动 `named`（即作为主服务器的 DNS 守护进程）所需的数据库文件内容。如后文所示，实施 DNS 服务的成功几乎完全取决于主服务器的配置优坏和运行情况。设置主服务器比任何其他类型都更繁琐、耗时。设置主名称服务器涉及创建和更新文件：

- `named.hosts`
- `named.rev`
- `named.local`
- `named.zone`
- `named.boot`

`named.hosts` 主要维护指定区域内所有主机的主机到 IP 地址映射。在 `harmonics.com` 的情况下，由于该域名没有分区，`named.hosts` 必须包含所有主机的名称到地址映射。除了这些映射外，`named.hosts` 还可以包含其他信息，例如作为邮件交换器的主机（如邮件路由器）、CPU 类型以及主机支持的已知服务。为了简单起见，将描述名称到地址和地址到映射。该描述将基于主机 `jade` 和 `cello`（`jade` 为主，`cello` 为备）上维护的 `harmonics.com` 域 DNS 设置文件。

第 1 部分包含 SOA 记录，该记录将 jade.harmonics.com 声明为 harmonics.com 的 DNS 权威服务器。`named.hosts` 文件只能包含一个 SOA 记录，且它必须是文件的第一个条。该记录还指示该域的对应关系应根根于 root@domain（记住 root 之后的点 "." 应该替换为 @ 字符）。详细信息请参阅括号内的 SOA 记录描述。

第 3 部分包含两条 MX 记录，将 flute 和 bass 标识为 harmonics.com 域的邮件交换器。主机 flute 的优先级高于 bass。

回顾第 5 部分，根据 jade 是多宿主机（或任何多宿主机），`named` 简单地返回在其 A 记录中找到的所有地址。为了获得最佳性能，`named` 返回距离查询站最近地址，然后按优先级顺序返回其他地址。

对于这些领域具有权威性，同时也标识其 IP 地址的记录。`named.ca` 文件中包含的所有数据在每次启动 `named` 守护进程时都用于初始化 DNS 服务器的缓存缓冲区——这一过程减少了服务器发现 DNS 服务结构时所需的重引和相关的学习过程。

为了可靠性，你应该只包含你认为在长时间内稳定的信息。你还应该定期验证所包含数据的有效性和准确性。

`named.ca` 文件中最常见的包含信息项之一是关于互联网根服务器的信息。这些信息在很长范围内是稳定的。鉴于你网络上的用户可能会访问互联网上的地方，用这些信息初始化你的服务器缓存是有意义的。因此，`named.ca` 文件应该大致如下：

;

# 第 1 部分：根域名服务器的 NS 记录

```
99999999 IN NS A.ROOT-SERVERS.NET

99999999 IN NS B.ROOT-SERVERS.NET

99999999 IN NS C.ROOT-SERVERS.NET

99999999 IN NS D.ROOT-SERVERS.NET

99999999 IN NS E.ROOT-SERVERS.NET

99999999 IN NS F.ROOT-SERVERS.NET

99999999 IN NS G.ROOT-SERVERS.NET

99999999 IN NS H.ROOT-SERVERS.NET

99999999 IN NS I.ROOT-SERVERS.NET
```

;

# 第 2 部分：根服务器 A 记录

```
A.ROOT-SERVERS.NET 99999999 IN A 198.41.0.4

B.ROOT-SERVERS.NET 99999999 IN A 128.9.0.107

C.ROOT-SERVERS.NET 99999999 IN A 192.33.4.12

D.ROOT-SERVERS.NET 99999999 IN A 128.8.10.90

E.ROOT-SERVERS.NET 99999999 IN A 192.203.230.10

F.ROOT-SERVERS.NET 99999999 IN A 192.5.25.241

G.ROOT-SERVERS.NET 99999999 IN A 192.112.36.64

H.ROOT-SERVERS.NET 99999999 IN A 128.63.2.53

I.ROOT-SERVERS.NET 99999999 IN A 192.36.148.17
```

可见，`named.ca` 文件由两块条目组成。第一块包含标识根服务器名称的 NS 记录。在这个文件中，有两点你应该注意到：每条 NS 记录开头列中的点号 `.`，以及随后的 NS 记录中缺少对象的情况现象（详情请参阅 RR 的通用语法）。由于根由空字符表示，因此点 `.` 是 DNS 文件中使用的字符。此外，当多个连续的记录引用同一个对象时，可以在后续记录中将第一个留空，以包含受影响对象的名称（根域名）。

`named.ca` 的第二部分包含与第一部分定义的服务器相关的 A 记录。每当启动 `named` 时，它都会读取 `named.ca` 并缓存该文件中包含的所有信息，从而提供对根服务器的快速访问。

> 提示：当前的根服务器列表始终可以通过来自 nic.ddn.mil 的匿名 FTP 从 `/netinfo/root-servers.txt` 文件获取。

注意：定期验证 `named.ca` 中包含的信息（包括关于根服务器的信息）的有效性和准确性是你的责任。未这样做可能会严重干扰你在网络上的服务，导致性能出现不理想的下降。NIC 负责在下载上述 `root-server.txt` 文件时按“现状”提供相关信息。

## named.boot：启动文件

此时，DNS 服务器会引用 `named.boot` 文件中关于其权限和类型（主、从或缓存服务器）的信息。以下代码显示了如何在 SVR4 上启动 DNS：

```bash
#
if -f /etc/inet/named.boot -a x /usr/sbin/in.named
then
  /usr/sbin/in.named
fi
```

## 启动 named 守护进程

上述代码提取自适用于 SVR4 UNIX 系统的 TCP/IP 启动脚本 `/etc/inet/rc.int`，其他 UNIX 实现了相同任务的代码。

所示，调用了 DNS 守护进程 (`in.named`)，代码检查名为 `named.boot` 的启动文件是否存在。正如代码所示，启动文件可以赋予任何名称（不一定是 `named.boot`），只要代码经过修改以反映该名称即可。通过 `named.boot`，DNS 确定数据库文件的位置：`named.hosts`、`named.rev`、`named.ca` 和 `named.local`。它还利用该文件来确定前面提到的权限范围和类型。

以下是 `named.boot` 文件的列表，作为启动主域名服务器的模板：

```
directory /etc/named
primary harmonics.com named.hosts
primary 100.in-addr.arpa 100.rev
primary 237.53.198.in-addr.arpa 198.53.227.rev
primary 0.0.127.in-addr.arpa 127.localhost
cache named.ca
```
