# 软件尺寸

与通用计算机系统不同，嵌入式系统只需要足够完成特定一组任务的软件。这意味着你可以抛弃通常进入通用计算机系统中的许多冗余内容，如 X 窗口、电子邮件和时事等。通过这样做，你可以让软件镜像变得小得多。这很重要，因为你在嵌入式应用中通常没有硬盘。即使你有一个硬盘用于存储，将系统软件和应用程序放在 ROM 或闪（flash）中可能更好，这样它们就不会易受损坏。ROM 和闪都比硬盘贵得多，因此在嵌入式应用中通常只需要包含实际运行的软件。

限制嵌入式应用软件的另一个原因是简单的；如果它不在那里，它就不会坏。在嵌入式应用中进行升级通常是不方便的——有时是困难甚至是不可能的。

## 原地升级软件

然而，工程时间和内存尺寸之间存在权衡。通常，你对产品投入的时间越长，就能把它做得越小越高效，从而减少内存需求，并降低单位成本。然而，你在效率上花费的时间越多，产品的功能就越少。此外，如果产品在工程阶段停留得太久，你可能会失去竞争对手的市场优势。

## 减少内存占用

如何减少嵌入式应用的内存/存储需求？通常有三种方法：

- 仅包含你需要的软件。
- 编译软件以缩小尺寸。
- 压缩软件。

第2章“极简 Linux”详细介绍了如何减少你的嵌入式应用的大小。

## 原地升级软件设计

大多数软件系统在生命周期内的某时刻必须进行升级，原因有很多：发现并修复漏洞和安全漏洞、需要新功能等。然而，如果从一开始没有设计升级，升级过程将变得困难甚至不可能。例如，除非你希望客户对你的嵌入式设备进行“微手术”，否则你不应该将软件放在 ROM 中。替换 ROM 中软件的唯一方法是更换 ROM 芯片。此外，如果设备中的内存加存储仅足够运行应用程序，那么升级是非常危险的，因为没有好的地方存放它。你可以用新代码覆盖旧代码，但一个小错误，你的客户现在就拥有了一个废铁。

那么，你如何从开始设计你的升级过程？

1. 首先将唯一的低级代码放在 ROM 中，将其放在闪中。ROM 中的代码可能永远不会替换，所以你必须确保正确。你可能想将升级代码本身放在 ROM 中；这样，无论现场发生什么，用户在搞砸升级尝试后都可以“升级”到一组可以工作的代码。

## 极简 Linux

在构建嵌入式应用时，首要考虑几乎总是内核，始终是发行版的大小以及它将占用多少内存。你正在构建的设备在物理上通常比通用计算机小得多，内存和存储空间通常也更少。因此，嵌入式软件必须比运行在通用计算机上的软件高效得多。遗憾的是，过去已经做了大量的研究来优化软件的存储和内存使用——因为在多年前它们要昂贵得多。

本章探索了让运行中的 Linux 系统尽可能小的各种方法，并研究了嵌入式设备开发者可以使用的不同方法。

在我们深入研究尺寸优化之前，我们应该先看看典型的 Linux 系统是如何工作的，以及一些典型系统之外有趣的替代方案。典型的桌面 Linux 系统有三个主要的软件层：Linux 内核、C 库和应用程序代码（见图 2.1）：

- 内核对硬件拥有独占且完全的控制。它的驱动程序代表应用程序与硬件通信。
- 典型 Linux 系统中内核的上一层是 C 库。除其他外，C 库将 POSIX API 调用转换为内核喜欢的格式，然后调用内核，将来自应用程序代码的参数传递给内核。
- 最后，离硬件最远的是应用程序代码。应用程序导致 Linux 内核（从而导致硬件——无论是路由器、个人组织器还是相机）执行预期的任务。

在设计你的嵌入式应用时，意识到你可以打破这种层次结构是非常重要的。例如，你的应用程序不需要使用 C 库与内核通信；它们可以直接调用内核接口——这正是 C 库本身所做的事情。这会将你的代码与 Linux 内核绑定，降低其可移植性——但在嵌入式环境中这可能对你并不重要。你实际上不需要任何应用层代码。将你的应用程序作为内核线程在内核本身是可能的。

在本章的剩余部分，假设你将使用标准的三层方法：应用、C 库、内核。这显然是最灵活且可移植的方法。

### 精简发行版与自编译

构建嵌入式 Linux 应用最简单的方法是从你喜爱的、与你所选 CPU 兼容的商业 Linux 发行版开始——例如 Red Hat、SuSE 或 Debian。将其安装到硬盘上，让你的应用作为初始化过程的一部分启动，并称其为“完成”。这可以在一天内完成。如果你的硬件有可用的内存和存储空间，这不是一个糟糕的方法。当你失去对箱内具体发生什么的很多控制权时，结果会比“从零开始”的方法不那么健壮且不安全，但这可能是你为了节省时间而愿意做的权衡。这种方法可能需要几个小时来实施，而书中讨论的其他方法可能需要几天或几周。

如果你存储空间紧张——但不是太紧张——构建嵌入式应用的下一种简单方法与第一种类似：以极简形式安装 Linux 发行版，然后剔除组件，直到它适合你的可用空间。取决于应用的需求，如果你有超过 50MB 的可用存储空间，这种方法就是有效的。这可能可以在一两天内完成，取决于你对所选发行版的熟悉程度。

第三种选项是从许多 Linux 发行版之一开始。由于选择其中一个很困难，我们在编译 Linux 时需要考虑的问题有很多。

第四种选项是“自己编写”。在过去，这是大多数人的解决方案。通过这种方式，你对实际操作拥有最大的控制权——它也花费最多的时间。你必须在选择要使用的程序时非常小心，并在构建它们时尽可能小。然而，这可能是获得最小 Linux 系统的方法。
