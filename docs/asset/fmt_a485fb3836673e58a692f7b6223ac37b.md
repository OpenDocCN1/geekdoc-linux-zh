
它使用了索引寻址模式。它表示从`%eax`开始向前移动`%edi`个位置，每个位置的大小为1字节。它获取找到的值并将其放入`%cl`中。之后，它检查该值是否在小写a到小写z的范围内。为了检查该范围，它只需检查字母是否小于a。如果是，那么它就不可能是小写字母。同样，如果它大于z，它就不可能是小写字母。因此，在这些情况下，它只是跳过。如果它在正确的范围内，它会进行大大写转换，并将其存回缓冲区。

无论何种情况，它都会递增`%cl`进入下一个值；接着检查我们是否到达了缓冲区的末尾。如果不在末尾，就跳转回循环的开头（`convert_loop`标签）。如果到了末尾，它将继续执行到函数的末。由于我们是直接修改缓冲区，因此不需要向调用程序返回任何内容——更改已经在缓冲区中了。`end_convert_loop`标签不是必须的，但放在那里是为了方便查看程序部分的位置。

现在我们知道了转换过程是如何运作的。现在我们需要弄清楚如何在文件中读写数据。

在读写文件之前，我们必须先打开它们。UNIX `open`系统调用处理此工作。它接受以下参数：

- `%eax`像通常一样包含系统调用号——在本例中为5。
- `%ebx`包含一个指向字符串的指针，该字符串是要打开的文件名。字符串必须以空字符终止。
- `%ecx`包含打开文件的选项。这些选项告诉Linux如何打开文件。它们可以指示诸如读取打开、写入打开、或如果不存在则创建、如果文件已存在则删除文件等。我们将在位于第10章名为*真、假与二进制数字*的节中，再讨论如何创建这些选项的数字。目前，只需相信我们得出的数字即可。
- `%edx`包含用于打开文件的权限。这用于在必须先创建文件的情况下，以便Linux知道以什么权限创建文件。这些权限以八进制表示，就像普通的UNIX权限一样。

执行系统调用后，新打开的文件的描述符将存储在`%eax`中。

那么，我们要打开哪些文件？在示例中，我们将打开命令行上指定的。。坦率地说，命令行参数已经由Linux存储在一个易于访问的位置中，并且已经是空终止的。当一个Linux程序开始时，所有指向命令行参数的指针都存储在栈上。参数的数量存储在`8 (%esp)`，程序的名称存储在`12 (%esp)`，而参数从`16 (%esp)`开始存储。

- 6.如果不熟悉UNIX权限，只需在这里输入`$0666`即可。不要忘记开头的0，因为这意味着数字是一个八进制数。

在C语言语言中，这被称为`argv`数组，因此我们在程序中将这样引用它。

程序执行的第一件事是将当前的栈位置保存在`%ebp`中，然后在栈上留出空间来存储文件描述符。之后，它开始打开文件。

程序打开的第一个文件是输入文件，它是第一个命令行参数。我们通过设置系统调用来实现这一点。我们将文件名放入`%ebx`，将只读模式放入`%ecx`，将默认模式`%0666`放入`%edx`并将系统调用放入`%eax`。执行系统调用后，文件已打开，文件描述符存储在`%eax`中。然后将文件描述符传输到栈上的相应位置。

输出文件也是一样，只是它是以只写、如果不存在则创建、如果已存在则截断的模式创建的。它的文件描述符也被存储了。

现在进入核心部分——读/写循环。基本上，我们将从输入文件读取固定大小的数据块，调用我们的转换函数，并将其写回输出文件。循环的第一部分是读取数据。这需要一个用于读取的文件描述符、一个用于写入的缓冲区，以及缓冲区的大小（可以读取的最大字节数）。系统返回实际读取的字节数，或者是文件结束（0）。这使用了读系统调用。

读取一个块后，我们检查`%eax`是否为文件结束标记。如果是，则退出循环。否则继续进行。在读取数据后，调用转换函数，传入我们刚刚读取的缓冲区和上一次调用的字符数。在该函数执行后，缓冲区已经大写并准备好写入。然后寄存器恢复到之前的值。

最后，我们发出写系统调用，它与读系统调用完全相同，只是将数据从缓冲区移动到文件。现在我们回到循环开头。

在循环退出后（记住，如果在读取后检测到文件末尾，它将退出），它只需关闭其文件描述符并退出。`close`系统调用只需接收`%ebx`中的文件描述符。

程序执行完毕！

## 第6章：读取和写入简单记录

正如第5章提到的，许多应用程序处理的是持久化数据——这意味着数据通过存储在磁盘的文件中，其生命周期比程序更长。你可以关闭程序并重新打开它，发现你回到了起点。现在，持久化数据基本可以分为两种类型：结构化数据和非结构化数据。非结构化数据就像我们在`topper`程序中处理的内容。文件内容无法被程序使用，因为程序无法解释用户在随机文本中想要表达的内容。

另一方面，结构化数据是计算机最擅长处理的。结构化数据是被分为字段（fields）和记录（records）的数据。大多数情况下，字段和记录是固定长度的。由于数据被划分为固定长度记录和固定格式字段，计算机可以解释这些数据。结构化数据也可以包含变长字段，但在那种情况下，通常使用数据库会更好。¹

本章介绍读取和写入简单的固定长度记录。假设我们想存储一些关于认识的人的基本信息。我们可以想象以下关于人的固定长度记录示例：

| 名字 (Firstname) | 40字节 |
| :--- | :--- |
| 姓氏 (Lastname) | 40字节 |
| 地址 (Address) | 240字节 |
| 年龄 (Age) | 4字节 |

> 1.数据库是一个为你处理持久化结构化数据的程序。你不需要编写程序来读取和写入数据到磁盘、进行查找，甚至进行基础处理。它是一个指向结构化数据的高级接口，虽然它增加了一些开销和额外的复杂性，但对于复杂的数据处理任务非常有用。学习数据库如何工作的参考请参阅第13章。

## 第6章：读取和写入简单记录

在这里，除了年龄之外，所有内容都是字符数据，年龄仅仅是一个数值字段，使用标准的4字节字（我们也可以只用一个字节，但保持为字长更便于处理）。

在编程中，你通常会有某些在程序内或可能在多个程序内反复使用的定义。将这些定义分离到直接包含在汇编语言中的文件中是好的。例如，在接下来的程序中，我们需要使用基址址（base addressing）来访问上述记录的不同部分。这意味着我们需要每个字段相对于记录起始位置的偏移量。以下常量描述了上述结构的偏移量。将它们放在名为`record-def.s`的文件中：

```assembly
equ RECORD_FIRSTNAME, 0
equ RECORD_LASTNAME, 40
equ RECORD_ADDRESS, 8
equ RECORD_AGE, 32
equ RECORD_SIZE, 34
```

此外，还有几个我们在程序中反复定义的常量，将它们放在文件中是有用的，这样我们就不必重复输入。将以下常量放在名为`linux.s`的文件中：

```assembly
## 系统调用号
equ SYS_EXIT, 1
equ SYS_READ, 3
equ SYS_WRITE, 4
equ SYS_OPEN, 5
equ SYS_CLOSE, 6
equ SYS_BRK, 7
## 系统调用中断
equ LINUX_SYSCALL, 0x80
# 文件描述符
equ STDIN, 0
equ STDOUT, 1
equ STDERR, 2
# 用状态码
equ END_OF_FILE, 0
```
