# 扩展

`XInitExtension` 函数确定指定的扩展是否存在。然后，它会为在连接上维护有关该扩展的信息分配存储空间，将该扩展链接到该连接的扩展列表中，并返回存根实现者访问该扩展所需的结构体。如果扩展不存在，`XInitExtension` 返回 `NULL`。

如果名称不在主机字符编码中，结果取决于实现。大小写敏感；字符串 `Thing` 和 `thingG` 都被视为不同的名称。

在随后的调用中，需要 `XExtCodes` 中的扩展号结构体。此扩展号对于单个连接是唯一的。

```
XExtCodes *XAddExtension(display);
```

`display` 指定与 X 运行的连接。

对于 `Xlib` 扩展，`XAddExtension` 函数分配 `XExtCodes` 结构体，增加扩展号计数，并链接到扩展列表。（这允许对 Xlib 进行扩展扩展，而不需要服务器扩展。）

`XESetToEvent` 和 `XESetEvent` 函数允许你为库定义新事件。`XEvent` 结构始终有一个类型（type `int`）作为第一个组件。这唯一地标识了什么类型的事件。第二个组件是服务器处理的最后一个请求的序列号（type `unsigned`）。第三个组件始终是一个布尔（type `Bool`），指示事件是否来自协议。第四个组件是从读取的显示指针。第五个组件是某种类型的资源 ID，通常是窗口，为了便于工具包分发器而精心选择。这第五个组件必须存在，即使事件没有自然的目标；协议中没有可以放入此组件的值，将其初始化为零。存在实现限制，使得你的事件结构的大小不能超过 24 个元素，这样结构中的 96 个字符在机器之间是完全移植的。

# 扩展 (Extensions)

应根据 `XEvent` 结构指定的类型来填充该类型。您应该将所有其他成员从 `XEvent` 结构（线缆格式）复制到 `XEvent` 结构（主机格式）。如果事件应该放入队列，您的转换程序应返回 `True`；如果不放入队列，则返回 `False`。

要初始化事件的序列号部分，请调用 `_XSetLastRequestRead`。

```
unsigned long _XSetLastRequestRead(display, rep);
```

- `display`：指定到 X 服务器的连接。
- `rep`：指定事件结构。

`_XSetLastRequestRead` 函数根据事件中的部分序列号计算并返回完整的结果。

```
Status *XSetEventToWire(display, event_number, (*proc));
```

- `display`：指定到 X 服务器的连接。
- `event_number`：指定事件代码。
- `proc`：指定在转换事件时要调用的程序。

`XSetEventToWire` 函数定义了一个当事件需要从主机格式（`XEvent`）转换为线缆格式（`XEvent`）时调用的程序。事件编号定义了要为哪个协议 `XEvent` 编号安装转换程序：`XSetEventToWire` 返回之前定义的任何程序。如果转换失败或其他情况，它将返回零。您可以使用自己的一个函数来替换核心事件转换函数，尽管不鼓励这样做。然而，这允许您拦截核心事件并在发送到另一个客户端之前对其进行修改。当将事件从主机格式转换为线缆格式时，您的程序将带有这些参数被调用：

```
int (*proc)(display, re, event);
```

`re` 参数是指向主机事件格式的指针，`event` 参数是应该存储 32 字节事件结构位置的指针。您应该使用 `XEvent` 结构中的类型来填充该类型。然后，所有其他成员都应从主机格式复制到 `xevent` 结构中。

```
Bool *XSetWireToError(display, error_number, (*proc));
```
