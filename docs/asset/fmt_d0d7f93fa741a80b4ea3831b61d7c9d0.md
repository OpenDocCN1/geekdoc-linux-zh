
## 12.2 站点：Sun Forums

为 `forums.sun.com` 配置的参数与为 Sun Blogs 配置的参数（见第 12.1 节）非常相似。但需要注意一个例外，即为 HTTP 监听器配置的接收器线程数。第 2 章引入了接收器线程的概念，并指出一个经验法则是将接收器线程的数量配置为等于 CPU 的数量。

## 第 12 章 使用 Web Server 7.0 构建安全的动态 Web 2.0 站点

### 12.4 总结

Web Server 7.0 为部署任务关键型站点提供了一个经过验证的、稳定、安全且可扩展的环境。其连接处理架构特别适用于处理动态 Web 2.0 站点所面临的海量事务。它对 Ruby、PHP、Java 甚至甚至 ASP 等动态编程技术的支持，允许开发者在他们选择的任何平台上构建下一代站点。Web Server 7.0 管理整个服务器集群的能力与管理单台服务器一样简单，这使其成为构建安全、动态 Web 2.0 站点的自然选择。

### server.xml 文件的详细介绍

| 行号 | 描述 |
| --- | --- |
| 第 36–39 行 | `<thread-pool>` 元素配置用于处理 HTTP 请求的线程。在示例中，`<thread-pool>` 有两个子元素：`<max-threads>` 和 `<stack-size>`。`<max-threads>` 元素指定了为 HTTP 请求处理分配的最大工作线程数。取值范围为 1 到 4096。`<stack-size>` 元素指定了创建新工作线程时线程栈的大小（以字节为单位）。取值范围为 8192 到 61708864。 |
| 第 41 行 | `<default-auth-db>` 元素指定了用于访问控制处理的默认身份验证数据库的名称。该元素的值必须在 `server.xml` 文件的现有 `<auth-db>` 上下文中定义。在此示例中，`<default-auth-db>` 的值对应第 43 行定义并在第 44 行命名的身份验证数据库。 |
| 第 43–54 行 | `<auth-db>` 元素为访问控制过程中可能使用的身份验证数据库提供定义。在 `<auth-db>` 中可以定义多个子元素。它们指定了身份验证的名称 `<name>`、身份验证数据库的类型 `<url>` 以及在身份验证数据库上下文中使用的各种属性 `<properties>`（例如身份验证数据库的格式和大小）。在此示例中定义了一个基于文件的身份验证数据库（第 45 行），并通过名称和密钥文件（第 44 行）进行引用。实际文件的名称也称为 `keyfile`，可以直接在该实例的配置 `keyfile` 键下方（第 50–53 行）找到。文件中任何条目的句法均遵循 `keyfile` 格式（第 46–49 行）。 |
| 第 56 行 | `<acl-file>` 元素定义了一个用于指定访问各种服务器资源规则的文件。在示例中，`<acl-file>` 元素定义了一个名为 `default.acl` 的文件，可能用于访问控制处理。如果未指定完整文件名，则该文件名相对于此服务器实例的配置目录。 |
| 第 58 行 | `<mime-file>` 元素定义了一个用于为 Web 服务器配置多用途邮件扩展 (MIME) 类型映射的文件。该文件在 HTTP 请求处理期间用于将文件类型映射到适当的处理服务。在此示例中，`<mime-file>` 元素定义了一个名为 `mime` 的文件，可能用于此用途。文件可以在此服务器实例的配置目录下找到。 |
