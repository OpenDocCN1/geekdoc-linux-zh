## 4.1.1.2 确保 `auditd` 服务已启用并激活 (自动化)

**适用范围：**

- Level 2 - Server
- Level 2 - Workstation

**描述：**

开启 `auditd` 守护以记录系统事件。

**理由：**

捕捉系统事件为系统管理员提供信息，以确定其系统是否发生了未经授权的访问。

**审计：**

运行以下命令验证 `auditd` 是否启用：

```bash
# systemctl is-enabled auditd
enabled
```

验证结果为 `"enabled"`。

运行以下命令验证 `auditd` 是否激活：

```bash
# systemctl is-active auditd
active
```

验证结果为 `active`。

**修复：**

运行以下命令启用并启动 `auditd`：

```bash
# systemctl --now enable auditd
```

## 4.1.1.3 确保对在 `auditd` 之前启动的进程启用了审计（自动化）

**配置适用性：**

- 等级 2 - 服务器
- 等级 2 - 工作站

**描述：**

配置 `grub2`，使得能够被审计的进程即使在 `auditd` 启动之前启动也能被审计。

**原理：**

需要在在 `auditd` 之前启动的进程上捕获审计事件，以防潜在的恶意活动未被检测到。

**审计：**

运行以下命令：

```bash
# find /boot -type f -name 'grub.cfg' -exec grep -Ph -- '^\h*linux' {} + | \
grep -v 'audit=1'
```

不应有任何输出。

**修复措施：**

编辑 `/etc/default/grub` 并在 `CMDLINE_LINUX` 中添加 `audit=1`：

示例：

```bash
GRUB_CMDLINE_LINUX="audit=1"
```

运行以下命令以更新 `grub2` 配置：

```bash
# update-grub
```

**其他信息：**

此建议是围绕 `grub2` 引导程序设计的，如果你的环境中使用了其他引导程序，请实施等效的设置。

## 4.1.1.4 确保 `audit_backlog_limit` 足够（自动化）

**配置适用性：**

- 等级 2 - 服务器
- 等级 2 - 工作站

**描述：**

在内核级审计子系统中，使用套接字缓冲区队列来存储审计事件。当接收到新的审计事件时，会将其记录并准备添加到此队列中。

内核启动参数 `audit_backlog_limit=N`（`N` 代表消息数量）将确保队列不会增长超过特定大小。如果记录的审计事件会导致队列超过此限制，则会发生错误并由系统配置进行处理。

**原理：**

如果记录的审计事件导致队列超过 `audit_backlog_limit`，则会发生错误，审计记录将丢失，且潜在的恶意活动可能未被检测到。

**审计：**

运行以下命令并验证是否设置了 `audit_backlog_limit=` 参数：

```bash
# find / -type f -name 'grub.cfg' -exec grep -Ph -- '^\h*linux' {} + | \
grep -Pv 'audit_backlog limit=\d+\b'
```

不应有任何输出。

**修复措施：**

编辑 `/etc/default/grub` 并在 `GRUB_CMDLINE_LINUX` 中添加 `audit_backlog_limit=N`。

建议的 `N` 大小为 `8192` 或更大。

示例：

```bash
GRUB_CMDLINE_LINUX="audit_backlog_limit=8192"
```

运行以下命令以更新 `grub2` 配置：

```bash
# update-grub
```

**默认值：**

如果未设置 `audit_backlog_limit`，系统默认值为 `audit_backlog_limit=64`。
