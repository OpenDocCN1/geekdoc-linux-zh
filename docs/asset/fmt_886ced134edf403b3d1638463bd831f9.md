在该方法中，方法解析算法拒绝了 `Z`，因为它无法确定一个合理的基类排序顺序。例如，在继承列表中，类 `X` 位于类 `Y` 之前，因此它将首先被检查。然而，类 `Y` 继承自 `X`，因此它更具特化性（more specialized）。如果先检查 `X`，将无法解析 `Y` 中的特化方法。在实践中，这些问题本应该出现——如果它们真的出现了，通常意味着程序设计上存在更严重的问题。

作为一个通用规则，多重继承用于定义所谓的混入类（mixin classes）。混入类通常定义一组方法，以便“混合”到其他类中；混入类会假设其他方法已经存在并在其基础上进行构建。示例中的 `DepositCharge` 和 `Withdraw` 类说明了这一点。这些类通过将 `deposit_fee()` 等新方法添加到类中，将其包含作为基类之一。事实上，如果你没有创建一个可以用于任何有用地方的实例（即默认方法将无法正确执行）。

## 多态、动态绑定与鸭子类型

动态绑定（在继承语境下，有时称为多态，是指在不考虑其类型的情况下使用实例的能力）完全通过前一节描述的属性查找过程来处理的。每当通过 `obj.attr` 访问属性时，Python 都会按照顺序在实例内部、实例的类定义、然后是基类中搜索 `attr`。返回第一个匹配的项。

这种绑定过程的一个关键方面是，它独立于 `obj` 是什么种类型的对象。如果你执行 `obj.name` 查找，它将适用于任何恰好拥有 `name` 的 `obj`。这种行为被称为“鸭子类型”（duck typing），引用自谚言：“如果它看起来像鸭子，叫起来像鸭子，走起来也像鸭子，那么它就是一只鸭子。”

Python 程序员经常编写依赖于这种行为的程序。例如，如果你想创建一个现有对象的自定义版本，只要它们相互无关，你只需要创建一个看起来和行为都像它的新对象。这种方法通常用于保持程序组件的松耦合。例如，可以编写代码与任何种类型的对象工作，只要它具有一组特定的方法即可。最常见的示例之一是标准库中定义的各种“类文件”对象。尽管这些对象并没有继承自内置的 `file` 对象。

## 静态方法与类方法

在类定义中，所有函数都被认为在实例上操作，该实例始终作为第一个参数 `self` 传递。然而，还可以定义另外两种常见的方法。

静态方法是一个普通函数，它恰好存在于由类定义的命名空间中。它不对任何类型的实例操作。要定义静态方法，使用如下所示的 `@staticmethod` 装饰器：

```python
class Foo(object):
    @staticmethod
    def add(x,y):
        return x + y
```

调用静态方法，只需在其前面加上类名。不要向其传递任何额外信息。例如：

```python
x = Foo.add(3,4)      # x = 7
```

静态方法的常见用途是在编写类时，你可能有许多创建新实例的方法。因为只能有一个 `__init__()` 函数，因此定义了如下所示的备选创建函数：

```python
class Date(object):
    def __init__(self, day, month, year):
        self.day = day
        self.month = month
        self.year = year
    @staticmethod
    def from_ordinal(n):
        # ...实现逻辑
        pass
```

# 第7章 类与面向对象 编程

```python
class Foo(object):
    def __init__(self, name):
        self.__name = name
    @property
    def name(self):
        return self.__name
    @name.setter
    def name(self, value):
        if not isinstance(value, str):
            raise TypeError("Must be a string!")
        self.__name = value
    @name.deleter
    def name(self):
        raise TypeError("Can't delete name")
f = Foo("Guido")  # 调用 f.name() - 获取函数
f.name = "Monty"  # 调用 setter name(f,"Monty")
f.name = 45  # 调用 setter name(f,45) -> TypeError
# del f.name # 调用 deleter name -> TypeError
```

在例例中，`name` 首先使用 `@property` 装饰器和关联方法被定义为一个只读属性。`@name.setter` 和 `@name.deleter` 装饰器分别关联到对该属性的设置和删除操作。这些方法的名称必须与原始属性的名称完全匹配。在这些方法中，`name` 的实际值存储在属性 `__name` 中。存储的属性名称不需要遵循任何约定，但它必须与属性本身不同，以与其区分开来。

class Foo(object):

        return self.__name
