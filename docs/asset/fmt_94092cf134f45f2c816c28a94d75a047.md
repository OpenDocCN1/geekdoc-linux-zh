
Perl 编程语言已成为系统管理员和程序员的主流，填补了小型 shell 脚本和大型应用程序之间的空白。许多人在接触到 Perl 后，发现他们减少了大量的 C 或 C++ 编程。Perl 有一种优雅的扩展机制，称为模块系统。全面存档网络 (CPAN) `http://www.cpan.org/` 提供了可用模块集以及 Perl 语言本身。

最近，一种名为 Python 的新语言正在流行。它对于与 Perl 类似的任务非常有用。在有许多 Perl 脚本的组织中工作的系统管理员，即使为新脚本选择 Python，学习 Perl 也是重要的。

## 编写脚本的动机

经常需要为特定情况编写或修改脚本。可能最常见的用法是创建应用程序封装器，shell 脚本定义应用程序所需的环境变量，然后启动应用程序。

虽然大多数 shell 脚本都很短（少于 100 行），但某些脚本可能非常复杂。存在一个模糊的区域，越过那里，脚本就变成了“真正的”编程。这对于对编程感兴趣的系统管理员来说是合适的。在其他情况下，可能需要协商将某些脚本项目分配给编程团队，或者外包进一步的开发和增强。

问问“脚本为我们做了什么”很有用的。系统管理员经常问：“节省时间”、“让事情变得更简单”或“减少错误”。人们也可以从“ates”的维度来考虑：缩写（`Abbreviate`）、自动化（`Automate`）、调节（`Regulate`）和委托（`Delegate`）。

## 缩写 (Abbreviate)

系统管理员经常需要重复一系列命令。将它们封装在脚本中提供了一种调用命令序列的简便方法。这是最简单的一种脚本。

在输入了一个长长的、复杂的命令，或一组需要再次使用的 shell 命令序列后，可以使用如下这样的命令将其转换为脚本：

```bash
history > ~/bin/script
```

然后编辑该文件，删掉不需要的部分，在顶部添加适当的头信息，并设置执行权限。

这里有一个缩写 telnet 会话的示例脚本：

```expect
#!/usr/bin/expect -f
# Sample telnet automation
## 调用时带上 ~/.autotel 且
## 期望一个名为 ~/.autotel 的目录
## 以及其目录下一个对应于主机别名的文件。
## 从中读取真实的主机名、用户名和密码
```

```expect
set nick [index $argv 0]
set rcfile [ open ~/.autotel/$nick ]
gets $rcfile host
gets $rcfile user
gets $rcfile pass
spawn telnet "$host"
expect "$login:"
send "$user\r"
expect "word:"
send "$pass\r"
interact
```

该脚本从 `~/.autotel/` 目录下对应于主机名的“nick”文件（用户对远程系统的别名）中读取主机名、登录名和密码。

## 脚本的动机 (Motivations for Scripting)

它随后尝试使用用户名打开该主机的 telnet 会话，然后进入“交互”（`interact`）——让用户以交互方式运行生成的会话。

这仅仅是 expect 脚本语言及其构建基础 T 库所提供力量的最微小暗示。

大多数 LINUX 发行版和 expect 都带有几个示例 expect 脚本。两个对许多系统管理员特别有用的脚本是 `autopasswd` 和 `kibitz`。`autopasswd` 自动化了新用户用户密码，例如用于新学期的设置。`kibitz` 允许两个或多个用户在单个 shell 会话中协作——每个人都可以看到屏幕并在共享的 shell 会话中输入命令。`kibitz` 甚至可以支持图形/curses 程序，如 `vi` 和 `emacs`。

还有用于 Perl 和 Python 的模块实现了 expect 的核心功能，允许人们使用这些语言启动程序、期待它们的输出、向它们发送输入、与其交互，并通通过自动化方式处理那些不可避免的程序。

## 自动化 (Automate)

许多系统管理任务必须定期执行——这些单调的任务，如记录日志、清理 `/tmp` 目录和执行夜备份。通过自动化这些任务，系统管理员可以释放自己去从事其他工作。因此，系统管理员为这些任务编写脚本并让 `cron` 进行调度是典型的做法。`cron` 提供了按照指定时间表自动运行程序的能力，减轻了系统管理员忘记执行这些任务的负担。通常，维护工作由 `cron` 在晚上运行，而这些情况的脚本会将任务输出通过发送给系统管理员。

## 调节 (Regulate)

缩写命令列表不仅仅是为了节省时间。它调节了流程，确保命令在每次调用脚本时都会按相同的顺序运行，且不会遗漏任何步骤。

随着系统管理员获得使用特定脚本的经验，他们会添加各种类型的合理检查、测试和选项——特别是在其他用户和操作员可能使用它们的情况下。这样的脚本调节了操作，确保有足够的磁盘空间进行构建，或者临时文件已被删除等等。

在某些情况下，并不一定知道如何为特定操作编写脚本——人们只需要通过提示提醒熟练的用户/操作员要做什么，他们就会知道要提供什么命令和参数。对于这些情况以及任何脚本的早期原型阶段，只管使用简单的 `echo`、`read` 和 `eval` 命令序列来引导用户完成过程即可。

例如：

```bash
echo "Enter the directory to use"
read dirname
[ -d "$dirname" ] && cd "$dirname" || {
  while [ ! -d "$dirname" ]; do
    echo "This must be an existing directory: Try again:"
    read dirname
  done
  cd "$dirname"
}
echo "Issue your build command here ('make'?"
read cmd
eval $cmd
```

显然，这个脚本还可以进一步改进。例如，它可以测试以确保目录是可访问的，并在权限错误或文件系统未挂载等情况下设计适当的错误信息。

## 委托 (Delegate)

许多系统管理任务涉及长长的命令序列。这些序列通常根据中间命令的结果而异。有时序列中的错误可能会导致灾难性的结果，例如数据丢失或损坏。将此类任务交给初级或中级系统管理员通常是危险的。委托此类任务

脚本编写提供了一种将复杂困难的任务委托给更初级系统管理员的机制。高级系统管理员从编写一个自动化并调节某个过程的脚本开始。在进行一些检查工作后脚本得以进展，通过一些改进的诊断，脚本就可以将任务委托给许多初级系统管理员。

而不需要理解任务中每一步的所有细节，初级系统管理员只需要运行脚本。随着系统管理员对脚本经验的增加，他们可以开始修改现有脚本并编写新的。

## 日志文件过滤与老化 (Log File Filtering and Aging)

LINUX 优秀的系统日志设施。这些设施提供了丰富的数据，用于跟踪问题并预警即将发生的故障。LINUX

典型的 Linux 系统日志设置的问题是记录了过多的无关信息，导致日志不断增长。

因此，大多数系统管理员编写脚本或安装包来管理他们的日志文件。日志脚本很容易编写，为初级系统管理员学习脚本提供了相对安全的方法，丢失某些日志文件通常不是灾难。这里有一个这样的脚本（用 `awk` 编写）：

```awk
#!/usr/bin/awk -f
# filter.log
# James T. Dennis

## 语法 filter.log patternfile [datafile ...]

## 用途从第一个文件中列出的模式
## 从数据文件（如 /var/adm/messages）中修剪
## 模式文件中的模式应采用以下形式
## 无 / 斜杠且无 "" 引号

## 注意：如果你想从标准输入处理，请使用 - 作为数据文件参数
#（作为管道过滤器使用），否则此脚本将无法看到任何输入！

ARGIND == 1 {
## 拙劣的技巧
## 允许第一个参数特殊地用作模式文件
# 将其他参数作为待过滤的数据；避免了使用
# awk -v patterns=$filename ... 语法。
if ($0 ~ /^[\t]*$/) { next } # 跳过空行
  # 也跳过以 hash 开头的行
  # 以允许模式文件中存在注释。
  if ($0 ~ /^#\/) { killpat[++]=$0 }
}

ARGIND > 1 {
for (i in killpat)
if($0 ~ killpat[i]) { next }
}

ARGIND > 1 {
print FNR ": $0"
}
```

显然，大部分实际工作在于维护模式列表。一个过于通用的模式（如 `.*`）会过滤掉所有内容。因此，系统管理员必须深入理解 `awk` 正则表达式，以便使用此脚本并为每种类型的过滤日志维护模式文件。
