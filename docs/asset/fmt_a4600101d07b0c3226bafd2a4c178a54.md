
## command — 执行简单命令

### 摘要

- `/usr/bin/command [-p] command-name [argument...]`
- `/usr/bin/command [-v |V] command-name`

### 描述

你可以使用 `command` 命令来转义那些 shell 会被视为内置函数的命令。通过 `command`，shell 将参数视为一个简单命令。
如果 `command-name` 与某个特殊内置命令的名字相同，则不会使用该特有属性。在其他所有方面，如果 `command-name` 不是函数名，则 `command` 的效果与省略 `command` 相同。
`command` 还提供了有关 shell 如何解释命令名的信息；参见 `-v` 和 `-V`。

### 选项

- `-p` 使用默认的 `PATH` 值进行命令搜索，该值保证能找到所有标准命令。
- `-v` 向标准输出写入一个字符串，指示 shell 在当前 shell 执行环境中调用 `command-name` 时所使用的路径或命令。
  使用 `PATH` 变量作为绝对路径，写入命令、普通内置命令、包含斜杠字符的命令-name 以及找到的任何实现的函数。
  写入 shell 函数、特殊内置命令、与 `PATH` 搜索关联的普通内置命令以及 shell 保留字的名称。
  以命令行的形式写入代表其别名（alias）别别。
  否则，不输出任何内容并返回一个反映未找到名称的退出状态。
- `-V` 向标准输出写入一个字符串，指示 shell 在当前 shell 执行环境中如何解释 `command-name` 中给出的名称。虽然该字符串的格式未指定，但它指示了 `command-name` 属于以下类别之一，并包含了下面的信息。
  识别使用 `PATH` 变量找到的命令、普通内置命令以及任何实现的函数，并在字符串中包含绝对路径名。
  识别其他 shell 函数。
  - 识别别名并在字符串中包含它们的定义。
  - 识别特殊内置命令。
  - 识别与 `PATH` 搜索关联的普通内置命令。
  - 识别 shell 保留字。

#### 操作数

`argument` 一个被视为 `command-name` 参数的字符串之一

`command-name` 命令或特殊内置命令的名字。

### 示例

以下示例创建了一个 `cd` 的版本，它总是恰好打印一次新的工作目录。

```
cd() {
  command cd "$@" >/dev/null
  pwd
}
```

以下示例启动了一个安全的 shell 脚本，其中脚本避免了被其父进程欺骗。

```
IFS=''
# 前述述值应该是 <space><tab><newline>。
# 将 IFS 设置为默认值。
unalias -a
# 取消所有可能的别名。
# 注意 unalias 被转义了，以防止别名
# 用于 unalias。
\unset -f command
# 确保 command 不是用户函数。
PATH="$(command -p getconf _CS_PATH):$PATH"
# 放置一个可靠的前缀。
# ...
```

在此时，只要对由 `PATH` 调用的目录具有正确的权限，该脚本就可以确保它调用的任何命令都是预期的。该脚本非常谨慎，因为它假设可能存在实现扩展，允许用户函数在被调用时存在；虽然此功能未在本文中规定，但作为扩展是不被禁止的。例如，`ENV` 变量在调用脚本之前会触发一个用户启动脚本。此类脚本可以定义函数来伪装应用程序。

### 环境变量

参见 `environ(5)` 查看以下影响 `command` 执行的环境变量的描述：`LC_CTYPE`、`LC_MESSAGES` 和 `NLSPATH`。

`PATH` 确定命令搜索期间使用的搜索路径，使用 `-p` 选项描述的情况除外。

### 退出状态

当你使用 `-v` 或 `-V` 选项时，将返回以下退出值：

- `0` 成功完成。
- `>0` 找不到 `command-name` 或发生错误。

否则，返回以下退出值：

- `126` 找到了 `command-name` 指定命令但无法调用。
- `127` 在 `command` 命令中发生错误，或未找到 `command-name` 指定命令。

否则，`command` 的退出状态为 `command` 参数所指定的简单命令的状态。

### 属性

参见 `attributes(5)` 了解以下属性的描述：

| 属性类型 | 属性值 |
| :--- | :--- |
| 可用性 | SUNWcsu |

### 参见

`sh(1)`, `type(1)`, `attributes(5)`

## compress, uncompress, zcat — 压缩、解压缩文件或显示扩展后的文件

### 摘要

```
/usr/bin/compress [-fv] [-b bits] [file...]
/usr/bin/compress [-cfv] [-b bits] [file]
/usr/bin/uncompress [-cfv] [file...]
/usr/bin/zcat [file...]
```

### 描述

#### compress

`compress` 命令尝试通过自适应 Lempel-Ziv 编码减小命名文件的大小。除了输出到标准输出外，每个文件都被一个带有 `.z` 扩展的文件替换，同时保持相同的所有权模式、更改时间和修改时间。

如果在文件名后添加 `.z` 会导致名称超过 14 字节，则命令将失败。如果没有指定文件，则将标准输入压缩到标准输出。

实现的压缩程度取决于输入的大小、每个代码的比特数以及源代码或英语等常见子串的分布（减少了 50-60%）。压缩效果通常要好得多（> 注意：与哈曼编码 `pack(1)` 相比，计算时间更短）。

#### uncompress

`uncompress` 命令将由 `compress` 压缩的文件恢复到原始状态。如果未指定文件，则将标准输入还原到标准输出。

#### zcat

`zcat` 命令向标准输出写入使用 `compress` 压缩的文件解压缩形式。它是 `uncompress -c` 的等效。

### 选项

- `-c` 写入标准输出；不更改文件并创建 `.z` 文件。`zcat` 的行为与 `uncompress -c` 相同。
- `-f` 强制压缩，即使文件未减小或相应文件已存在。如果标准输入不是终端且未使用 `-f` 选项，则向标准错误写入诊断消息并以大于 0 的状态退出。
- `-v` 向标准错误写入有关每个文件百分比的消息。
- `-b bits` 设置子串代码的上限（比特）。比特必须在 9 到 16 之间（16 是默认值）。降低比特数会导致文件较大、压缩率较低。

#### 操作数

`file` 要压缩的文件路径。如果 `file` 为 `-` 或未指定文件，则使用标准输入。

### 示例

以下示例压缩并解压缩名为 `testcompress` 的文件，并使用 `ls -1` 命令显示解压缩和压缩文件的大小。你可以看到，压缩文件比解压缩文件小约 50%。

```
castle ls -1 testcompress
-r--r--r 1 winsor staff 13054 Dec 30 15:21 testcompress
castle compress testcompress
-r--r--r 1 winsor staff
castle ls -1 testcompress.Z
-r--r--r 1 winsor staff 6486 Dec 30 15:21 testcompress.Z
castle uncompress testcompress.Z
castle ls -1 testcompress
-r--r--r 1 winsor staff 13054 Dec 30 15:21 testcompress
castle
```

### 使用

参见 `largefile(5)` 了解 `compress`、`uncompress` 和 `zcat` 在遇到大于或等于 2 Gbytes (`2**31` 字节) 文件时的行为描述。

## compress, uncompress, zcat

### 退出状态

- `0` 成功完成。
- `1` 发生错误。
- `2` 一个或多个文件未被压缩，因为压缩会导致体积增大（且你没有指定 `-f` 选项）。
- `>2` 发生错误。
