## Linux 文件系统结构

### 文件：类型

Linux 文件系统的核心是文件，它不过是操作系统用于在物理设备（如硬盘、软盘、CD-ROM 或 DVD）上存储信息的结构。当然，文件可以包含您想要的任何类型信息，从 PNG 或 JPEG 格式的图片，到文本或 HTML 格式的网页。文件系统是允许 Linux 处理其所包含文件的结构。

所有 Linux 文件都有一个名称，必须符合某些规则：

- 文件名长度在 1 到 255 个字符之间。
- 您可以使用除斜杠 `/` 以外的任何字符，但不建议使用在 Linux 中具有特殊含义的字符，这些字符包括：`= \ ^ ~ " * ; - ? [ ] ! & ~ < >`
    - 要使用包含这些字符或空格的文件，必须将文件名放在引号之间。
- 如有需要，也可以使用方法数字。
- 大写字母和小写字母被视为不同，因此 `letter.txt` 与 `Letter.txt` 或 `letter.Txt` 不同

与 Windows 一样，可以使用特定的“类型”标准，通过在名称末尾使用一系列字符来标记不同类型的文件，以指示相关文件类型。因此，文本文件、HTML、PNG 或 JPEG 图像分别具有 `.txt`、`.htm`（或 `.html`）、`.png` 和 `.jpg`（或 `.jpeg`）扩展名。

尽管如此，Linux 只区分三种类型的文件：

- 文件或普通文件，即上述提到的文件。
- 目录（或文件夹），是一种以结构化方式分组其他文件的特殊文件。
- 特殊文件是 Linux 的基础，因为它们代表连接到计算机的设备，例如打印机。这样，在该文件中输入信息相当于向打印机发送信息。对于用户来说，这些设备的外观和使用方式与普通文件相同。

### 链接

链接是一种普通文件类型，其目的是为指定文件创建新名称。一旦创建符号链接，它就可以像将文件内容复制到另一个文件一样访问链接到的文件，其优势在于实际上并未进行复制。当您希望一组人协同处理同一个文件时，符号链接特别有用，因为它们允许共享文件，同时集中修改。

例如，假设存在一个名为 `balance.1999.txt` 的文件，为其创建符号链接 `balance.txt`。对 `balance.txt` 的任何访问都会由系统解释为访问 `balance.1999.txt` 的内容。

### 路径

在任何现代操作系统中，文件结构都是层次化的，并依赖于目录。通常，文件系统结构类似于树形结构，每个节点由一个目录或文件夹组成，其中包含其他目录或文件。在 Windows 中，每个磁盘驱动器都被识别为作为其他文件根的基本文件夹。在 Linux 中，存在一个称为 `/` 的单一根节点，所有文件和目录都悬挂在该节点下，且该节点独立于连接到计算机的设备。

文件或目录的路径是访问特定文件时必须遍历的目录序列，由 `/` 分隔。

路径有两种形式：

- 绝对路径，显示文件的完整路径，`/home/luis/Carta.txt`
- 相对于特定目录的路径，例如，如果我们找不到 `/ home` 目录，相对于文件 `Letter.txt` 的路径是 `Luis / Letter.txt`

为了使问题更加复杂，所有目录都包含两个特殊目录：

- 当前目录，用点 `"."` 表示
- 父目录，用冒号 `".."` 表示

位于 `/home` 目录中，您可以通过 `/home/luis/Carta.txt`（绝对路径）或 `/luis/Carta.txt`（相对路径）访问 `Carta.txt`。在 `Luis` 目录下，可以是 `./Carta.txt` 或简单地 `Letter.txt`。

Linux 文件系统遵循所有 UNIX 约定，这意味着它具有确定的、兼容且与其余 UNIX 系统同构的结构。与 Windows 或 MS-DOS 不同，任何 Unix 系统上的文件系统都不直接链接到硬件结构，也就是说，它不取决于给定计算机拥有 1、2 还是 7 个硬盘来创建 `c:\`、`d:\` 或 `m:\` 驱动器。

### UNIX 文件系统结构

每个 UNIX 文件系统都有一个由 `/` 表示的唯一根目录或根起点。在这个目录下，您可以找到操作系统可访问的所有文件。这些文件组织在不同的目录中，这些目录的功能和命名在所有 Unix 系统中都是标准的。

- `/`: 文件系统根目录
- `/dev`: 包含代表物理安装在该计算机上的设备的系统文件
- `/etc`: 此目录保留用于系统配置文件

在此目录中，不应出现二进制文件（程序）。其下应出现另外两个子目录：

- `/etc/X11`: X 窗口配置文件
- `/etc/skel`: 当创建新用户时复制到用户目录的基本配置文件
- `/lib`: 包含运行位于 `/bin` 中的程序所需的库（不是用户程序的库）
- `/proc`: 包含接收或向系统内核发送信息的特殊文件（建议不要修改此目录及其文件的内容）
- `/sbin`: 包含仅超级用户或 root 可访问的程序
- `/usr`: 这是系统最重要的目录之一，因为它包含所有用户共用的使用程序。其结构通常类似于以下：
  - `/usr/X11R6`: 包含运行 X 窗口的程序
  - `/usr/bin`: 通用程序，包括 C/C++ 编译器
  - `/usr/doc`: 通用系统文档
  - `/usr/etc`: 通用配置文件
  - `/usr/include`: C/C++ 头文件（.h）
  - `/usr/info`: GNU 信息文件
  - `/usr/lib`: 程序的通用库
  - `/usr/man`: 可通过 `man` 命令访问的手册
  - `/usr/sbin`: 系统管理程序
  - `/usr/src`: 程序的源代码

除了上述目录外，还有其他通常位于 `/usr` 目录中的目录，例如安装在系统中的程序所在的文件夹。

- `/var`: 此目录包含有关程序的临时信息（这并不意味着您可以删除其内容；事实上，不应该这样做）

## 第 1 章：操作系统的基本概念

### 操作系统的概念、目的和功能

#### 操作系统的概念

我们现代操作系统的主要思想和起点是创建 ISG 并使其纳入计算机系统使用的需求（*计算机信息系统*指的是是一套硬件和软件）。最初开发的计算机信息系统旨在解决用户责任问题和实际问题。由于仅靠硬件很难做到这一点，因此创建了应用程序。这些程序需要硬件管理、硬件资源分配等通用操作。这些操作被归入一个独立的软件层，即操作系统。

此外，操作系统的能力远远超出了应用程序所需的基本操作集，但此类系统在应用程序和硬件之间的中间位置保持不变。

#### 操作系统的目的

操作系统为我们提供了许多信息系统，其次是其工作效率和可靠性。第一种功能是作为扩展机器的操作系统特征，第二种是作为硬件资源分配者的操作系统特征。

#### 作为扩展机器的操作系统

使用操作系统，应用程序程序员（以及通过其程序的用户）应该有一种正在与先进机器打交道的印象。硬件不太适合直接用于应用程序。例如，如果您考虑在相应控制器的命令级别下工作于 I/O 设备，您会发现这类命令集是有限的，对于许多设备来说甚至是原始的。操作系统隐藏了这种硬件接口，但向程序员提供了使用更高级概念（称为抽象）的应用程序编程接口。

例如，在处理磁盘时，典型的抽象是文件。与直接处理磁盘控制器（无需考虑移动驱动头、启动和停止电机等）相比，处理文件更容易，结果是，程序员可以专注于其应用程序的本质。操作系统负责与磁盘控制器交互。

抽象凸显使得在迁移到新硬件时更改操作系统和应用程序代码变得容易。例如，如果您在计算机上安装新类型的磁盘设备（前提是操作系统支持它），操作系统级别将考虑其所有功能，应用程序将继续像以前一样使用文件。系统的这种特性称为硬件独立性。可以说操作系统为运行应用程序提供了硬件独立的环境。

#### 作为资源分配者的操作系统
