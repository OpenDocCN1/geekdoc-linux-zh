- `EX_NOUSER` 用户名未识别。
- `EX_UNAVAILABLE` 必要的资源不可。此退出状态是一个通用错误捕获。
- `EX_SYNTAX` 地址语法错误。
- `EX_SOFTWARE` 内部软件错误，包括错误的参数。

# newgrp — 登录新组

## 语法

`/usr/bin/newgrp [- | -l][group]`

```
sh

newgrp [argument]

sh

*

newgrp [argument...]
```

## Description

使用 `newgrp` 命令通过更改实际组 ID 和有效组 ID 来登录新组。你将保持登录状态，且当前目录不变。即使命令因错误（未知组）终止，`newgrp` 的执行总是会用新 shell 替换当前 shell。

任何未导出的变量都将重置为空或其默认值。已导出的变量保留其值。系统变量（如 `PS1`, `PS2`, `PATH`, `MAIL`, `HOME`）除非被系统或用户导出，否则将重置为默认值。例如，当你有一个除 `$`（默认值）之外的主提示符字符串 (`PS1`) 且没有导出 `PS1` 时，你的 `PS1` 将被设置为默认提示符字符串 `$`，即使 `newgrp` 因错误终止也是如此。

> 注意 — shell 命令 `export`（请参见 `sh(1)` 和 `set(1)`）是导出变量的方法，以便它们在调用新 shell 时保留其分配的值。

在没有操作数和选项的情况下，`newgrp` 将你的组 ID（实际和有效）更改为密码文件条目中指定的组。这样你就可以退出早先 `newgrp` 命令的影响。

如果某个组有密码，且你没有在 `/etc/group` 中列为该组的成员，则需要输入密码。

> 注意 — 为组创建密码的唯一方法是使用 `passwd(1)`，然后从 `/etc/shadow` 剪切并加密密码到 `/etc/group`。组密码已经过时，不经常使用。

# newgrp

对于 `newgroup` 命令，以一个或多个星号 (`*`) 开头的 `ksh(1)` 命令将按以下方式被特殊处理：

- `*` 位于命令前的变量赋值列表在命令完成后仍保持有效。
- I/O 重定向在变量赋值后处理。
- 错误会导致包含它们的脚本中止。
- 跟跟在 `**` 之后且格式为变量赋值的单词将按照变量赋值相同的规则进行扩展。这意味着波浪替换是在 `=` 之后进行的，且不执行单词拆分和文件名生成。

## 选项

- `-1` 将环境更改为用户实际作为新组成员重新登录时的预期状态。

### 操作数

- `group` 来自组数据库的组名或非负数字组 ID。指定用于设置实际和有效组 ID 的组 ID。如果组 ID是非负数字字符串且在组数据库中作为组名存在（参见 `getgrnam(3)`），则使用与该组关联的数字组 ID 作为组 ID。
- `argument` 仅限 `sh` 和 `ksh`。`newgrp` 命令的选项和/或操作数。

## 环境变量

关于影响 `newgrp` 执行的以下环境变量的描述请参见 `environ(5)`：`LC_TYPE`, `LC_MESSAGES` 和 `NLPATH`。

## 退出状态

如果 `newgrp` 成功创建了新的 shell 执行环境（无论组识别是否成功更改），其退出状态均为该 shell 的退出状态。否则，返回以下退出值：

- `>0` 发生错误。

## 文件

- `/etc/group` 系统组文件。
- `/etc/passwd` 系统密码文件。

关于以下属性的描述请参见 `attributes(5)`：

| 属性类型 | 属性值 |
|---|---|
| 可用性 | `SUNWcsu` |

# news — 打印新闻项目

## 语法

```
/usr/bin/news [-a][-n][-s] [items]
```

## Description

`news` 查询 `/var/news` 目录获取当前事件信息。使用 `news` 了解当前事件。按照惯例，这些事件由 `/var/news` 目录下的的文件描述。

在不带参数调用时，`news` 会打印当前事件。

## 选项

- `-a` 打印所有项目。
- `-n` 报告当前项目。
- `-s` 报告项目，但不更改。

## 示例

以下示例显示了如何。

```
castle% news
```
