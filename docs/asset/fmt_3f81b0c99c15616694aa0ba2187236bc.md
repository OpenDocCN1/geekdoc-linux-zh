
# 第 5 章

开发工具

应用程序是程序员使用多种编程语言之一创建的可执行程序。Linux 提供了若干实用程序，程序员可以使用它们来控制应用程序的开发。其中最主要的是 `make` 工具。`make` 工具与 Linux 操作系统接口，提供了一种易于维护和编译程序的方法。`r` 允许你更好地控制程序的更改。它将更改组织成不同的版本，这些版本可以存储并在稍后访问。你甚至可以使用 `man` 工具为你的应用程序创建自己的在线文档。所有这些实用程序都是复杂且强大的工具。

## make 工具

你经常会处理一个包含许多源代码文件的程序。当你开发程序并进行修改时，你需要反复编译该程序。然而，你只需要编译那些你做过更改的源代码文件。链接器将新生成的目标代码文件与之前编译的目标代码文件链接在一起，创建一个新的可执行文件。每次实际上只编译了你的几个源文件，这一事实极大地减少了编译器的工作量。每当你需要一个新的可执行程序时，你不需要重新编译每个源代码文件。

在具有许多源代码文件的大型程序中，要跟踪哪些文件已经更改并需要编译，哪些文件只需要链接，是非常困难的。`make` 工具会为你完成这项工作。`make` 设计用于一种开发环境，其中程序中的不同源代码文件被不断修改。`make` 会跟踪哪些源文件已更改，哪些没有更改。它会重新编译已更改的文件，将它们与其他目标代码文件链接，以创建一个新的可执行文件。在下一个示例中，用户在命令行输入命令 `make` 来调用 `make` 工具。然后 `make` 会编译那些最近修改的文件并创建一个新的可执行文件。`make` 会显示它执行的每条 Linux 命令。

```
$ make
gcc -c main.c
gcc -c io.c
gcc main.o io.o
```

如果你程序中的所有文件都是最新的，那么 `make` 工具只会返回一条消息告知你如此。

```
$ make
'a.out' is up to date.
```

要理解 `make` 工具的工作原理，你需要意识到它使用源代码文件的时间戳来确定是否应该对其进行编译。当文件被创建、重新创建或以任何方式被修改时，Linux 操作系统都会在其上放置一个新的时间戳。如果你在 1:00 创建了一个文件，该文件会被盖上 1:00 的时间。如果你随后在 6:00 更改了该文件，该文件会被重新盖上 6:00 的时间。编译程序时，只有那些已更改的源代码文件需要重新编译，可以使用时间戳来确定是哪些文件。通过这种方式，`make` 为程序员选择了要编译的文件。

在下一个示例中，用户管理一个由两个源代码文件组成的程序：`main.c` 和 `io.c`。这两个文件都有对应的代码文件：`main.o` 和 `io.o`。它们用于创建可执行文件 `a.out`。如果自从上次创建 `a.out` 后，`main.c` 或 `io.c` 任何一个被修改过，`make` 将再次编译修改过的源代码文件，生成一个新的目标文件，然后创建一个新的可执行文件。下面的 `ls -l` 命令使用长格式列出所有文件，其中包括文件最后修改的时间。注意，除了 `main.c` 之外，所有文件的时间都早于可执行文件 `a.out`。

```
$ ls -l
-rw-r--xr-x 1 rich 48728 Nov 3 04:31 a.out
-rw-r--r-- 1 rich 256 Nov 3 04:30 io.c
-rw-f--r-- 1 rich 2080 Nov 3 04:30 io.o
-rw-r--r-- 1 rich 136 Nov 3 05:05 main.c
-rw-f--r-- 1 rich 604 Nov 3 04:30 main.o
-rw-f--r-- 1 rich 66 Nov 3 03:00 types.h
```

用户随后执行 `make` 命令。`make` 发现 `main.c` 的更改时间比 `a.out` 更晚，因此编译了 `main.c` 创建了新的 `main.o` 文件。新的 `main.o` 和旧的 `io.o` 文件被用于创建一个新的 `a.out` 文件。接下来的 `ls -l` 命令显示 `main.o` 和 `a.out` 的时间现在比 `main.c` 更新。

```
$ make
gcc -c main.c
gcc main.o io.o
$ ls -l
-rwxr-xr-x 1 rich 48728 Nov 3 05:06 a.out
-rw-f--r-- 1 rich 256 Nov 3 04:30 io.c
-rw-f--r-- 1 rich 2080 Nov 3 04:30 io.o
-rw-f--r-- 1 rich 136 Nov 3 05:00 main.c
-rw-f--r-- 1 rich 604 Nov 3 05:05 main.o
-rw-f--r-- 1 rich 66 Nov 3 03:00 types.h
```

`make` 不会自动编译任何已更改的源代码文件。
