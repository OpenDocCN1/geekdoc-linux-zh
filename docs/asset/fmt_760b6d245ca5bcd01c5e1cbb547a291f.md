# 启动对比

Project Trailblazer 的工程师开发了如表 4.3 所示的目标对比表。该表比较了 Project Trailblazer 涉及的四个平台的“启动到 bash 提示符”的时间和根文件系统大小。

**表 4.3 Project Trailblazer 目标对比**

| 平台 | bash 提示符时间 | 目标根文件系统大小 |
|---|---|---|
| Embedded Planet RPX-CLLF, PowerPC 860 | 27 秒，包括 6 秒 TFTP 下载内核和 RAM 磁盘的时间 | 4262KB |
| Brightstar Engineering MediaEngine, StrongMZ110 | 13 秒，包括 6 秒 TFTP 下载内核和 RAM 磁盘的时间 | 4888KB |
| Tri-M MZ104, Pentium (100MHz) | 29 秒，包括 17 秒 BIOS 完成时间 | 4888KB |
| Micron COTS PC, Celeron (400MHz) | 27 秒，包括 20 秒 BIOS 完成时间 | 4888KB |

所有平台均在 30 秒内启动并进入提示符。最快的是 MediaEngine，只需 13 秒。RPX-CLLF 和 MediaEngine 的启动时间包含了 6 秒的 TFTP 内核传输时间。如果板载 Flash 内存存储内核镜像，这段时间将被消除。x86 MZ104 和 COTS PC 的启动时间包含了强制性的 PC BIOS 完成时间。文件系统大小的相似性表明，x86、ARM 和 PowerPC 微处理器的编译二进制文件大致相同。

无论天赋或专业知识如何，所有程序员都需要调试代码。Project Trailblazer 的工程师知道他们将需要进行调试，而且花费在调试上的时间将影响他们的进度。

Project Trailblazer 的工程师为他们的远程调试需要一个可靠且健壮的解决方案。他们希望方案能够跨项目的目标处理器（x86、ARM 和 PowerPC）、通过传输控制协议/网协议（TCP/IP）网络通信，并且是非专有的。GNU 调试工具 `gdb` 和 `gdbserver` 提供了这种解决方案。

在本章中，你将使用 `gdb` 和 `gdbserver` 在本地和远程调试 `helloworld` 程序。你需要通过配置项目目标通过网络文件系统 (NFS) 挂载根文件系统，以缩短编译/运行/调试的迭代周期。本章绝不是调试的全面说明；已经存在其他信息源。它没有使用基于 `gdb` 构建的图形用户界面（GUI）调试工具，如 `xgdb`、`DDD` 和 `insight`。本章介绍了如何跨网络远程调试简单程序。然后你可以使用这些调试知识和其他工具来增强你的环境并缩短开发时间。

### 介绍 gdb

GNU 调试器 `gdb` 允许你控制程序的执行、查看和更改程序变量、检查程序内部结构，并检查崩溃程序的核心文件。你可以使用 `gdb` 启动一个可执行文件、调试已经在运行的可执行文件，或连接到 `gdbserver`。`gdb` 和 `gdbserver` 处理了正确的跨处理器问题，例如大端序和小端序地址以及整数大小。`gdb` 作为控制台文本应用程序运行，没有 GUI。它的开源特性允许进行增强；你可以获得 GUI 工具，提供程序员已经习惯的集成开发环境（IDE）功能。

本章并没有深入讨论 `gdb` 的特性、能力和功能。相反，它展示了如何列出可执行文件的代码集、设置断点、打印变量以及设置变量值。然后你可以使用 Project Trailblazer 平台之一在网络上调试交叉编译的可执行文件。表 5.1 显示了本章使用的基本 `gdb` 命令。

**表 5.1 gdb 命令**

| 命令 | 快捷键 | 描述 |
|---|---|---|
| list | l | 列出程序 |
| run | | 启动程序 |
| break | b | 设置断点 |
| next | | 逐行执行程序 |
| continue | c | 继续运行程序 |
| print | p | 打印变量值 |

`gdb` 的在线帮助提供了额外信息。例如，在 `gdb` 内部，这是关于 `next` 命令的帮助部分：

### 本地调试

让我们首先在主机系统 `tbdev1` 上编译并调试 `helloworld`。`buildrootfilesystem` 脚本在 `/root/cross/builds` 中生成 `helloworld.c` 并为目标系统进行交叉编译。让我们使用该源码并在 `tbdev1` 上编译它。以下是安装 `gdb` 并编译调试 `helloworld` 的步骤：

1. 在 `tbdev1` 上安装 `gdb`：
```bash
root@tbdev1: apt-get install gdb
```

2. 进入 `/root/cross/builds` 目录并带有调试标志 `-g` 编译 `helloworld`：
```bash
root@tbdev1: cd /root/cross/builds
root@tbdev1: gcc -g -o helloworld-i386-linux helloworld.c
```

你需要检查几点。使用 `file` 程序确定程序的架构并查看是否包含符号表：
```bash
root@tbdev1: file helloworld-i386-linux
helloworld-i386-linux: ELF 32-bit LSB executable, Intel 80386, version 1, dynamically linked (used shared libs), not stripped
```
`stripped` 表示执行文件不包含符号表，而 `not stripped` 表示包含符号表。

如所示，这个编译版本的 `helloworld` 适用于 Intel 80386、x86，且没有被 strip。稍后可以使用 `strip` 程序移除调试符号表，然后使用 `file` 查看 `helloworld` 不包含调试符号。

3. 执行 `helloworld`，检查编译是否正确：
```bash
root@tbdev1: ./helloworld-i386-linux
Hello world 1 times!
Hello world 2 times!
Hello world 3 times!
Hello world 4 times!
Hello world 5 times!
Hello world 6 times!
Hello world 7 times!
Hello world 8 times!
Hello world 9 times!
```

4. 使用 `gdb` 调试 `helloworld`：
```bash
root@tbdev1: gdb helloworld-i386-linux
```

```
输入 "show copying" 查看条件。
GDB 没有任何绝对保证。输入 "show warranty" 查看详情。
此 GDB 配置为 "i686-pc-linux-gnu"
(gdb)
```

> **注意**
> 不要忘记最古老的调试工具——`printf` 语句。C 程序可以使用 `printf`，而内核模块可以使用 `printk`。在调试内核代码时，你可以使用 `printk`，因为内核驱动程序无法链接到标准 C 库。

5. 使用 `list` 命令查看 `helloworld-i386-linux` 可执行文件的源码，然后运行 `helloworld-i386-linux` 可执行文件：
```
(gdb) list
1 #include <stdio.h>
2
3 int main(void)
4 {
5 int i;
6
7 for (i = 1; i < 10; i++)
8 {
9 printf("Hello world %d times!\n",i);
10 }
```

```
(gdb) run
Starting program: /root/cross/builds/helloworld-i386-linux
Hello world 1 times!
Hello world 2 times!
Hello world 3 times!
Hello world 4 times!
Hello world 5 times!
Hello world 6 times!
Hello world 7 times!
Hello world 8 times!
Hello world 9 times!
Program exited with code 0.
(gdb)
```

在没有断点的情况下，`helloworld-i386-linux` 会执行完毕，并在屏幕上打印 Hello world 和变量 `i` 的值。

6. 使用 `break` 命令在第 9 行设置断点：
```
(gdb) break 9
Breakpoint 1 at 0x80483f8: file helloworld.c, line 9.
(gdb)
```

7. 使用 `run` 再次启动 `helloworld-i386-linux`：
```
(gdb) run
Starting program: /root/cross/builds/helloworld-i386-linux
Breakpoint 1, main ( ) at helloworld.c:9
9 printf("Hello world %d times!\n",i);
(gdb)
```

这意味着你准备执行第 9 行。

8. 使用 `next` 命令执行该行：
```
(gdb) next
Hello world 1 times!
7 for (i = 1; i < 10; i++)
(gdb)
```

"Hello world 1 times!" 是第 9 行 `printf` 语句的输出。

9. 使用 `continue` 继续执行。程序应该再次在第 9 行中断。使用 `print` 命令检查 `i` 的值：
```
(gdb) continue
Continuing.
Breakpoint 1, main ( ) at helloworld.c:9
9 printf("Hello world %d times!\n",i);
(gdb) print i
$1 = 2
(gdb) next
Hello world 2 times!
7 for (i = 1; i < 10; i++)
(gdb)
```

如预期所示，`i = 2`，因为这是第二次进入 `for` 循环。你可以这样继续，再检查 8 次 `i`。或者，将 `i` 改为 8 以加速。使用 `set variable` 命令，然后使用 `continue`：
```
(gdb) set variable i = 8
(gdb) continue
Continuing.
Hello world 8 times!
Breakpoint 1, main () at helloworld.c:9
printf("Hello world %d\n",i);
(gdb)
```
