## 介绍超文本传输协议 (HTTP)

*作者：James Edwards*

毫无疑问，互联网的爆炸式增长是由万维网（The Web）的巨大普及驱动的。Web 的持续成功归功于其简单性，它为用户提供了定位和检索来自互联网内部分散信息的能力。这一成功的很大程度上归功于超文本传输协议（HTTP）的有效性。

HTTP 是一种应用协议，为在 Web 服务器和客户端（称为*浏览器*）之间移动信息提供了机制。明确来说，HTTP 并不是通信协议；HTTP 是一个应用程序。HTTP 的功能类似于其他标准 UNIX 标准应用程序，如 Telnet、ftp 和 SMTP。与这些应用程序一样，HTTP 使用了自己已知的端口地址以及底层可靠通信协议（如 TCP/IP）的服务。

本章详细介绍了 HTTP 应用程序是如何运行的。这将通过检查协议的消息格式和返回代码来实现，还将通过提供逐步检查协议如何运作的示例。

本章重点强调了若干归因于 HTTP 运行的性能问题。我将尝试对这些问题的产生和原因提供见解；并指示重新配置某些服务器参数可能有助于缓解某些情况。

## HTTP 的功能

互联网是一个巨大的信息库。Web 的发展源于一种渴望简单且有效的方法，以从这些丰富的信息中搜索特定的思想或兴趣。

在 Web 内部，信息的存储方式使得可以通过标准地址进行引用。此外，HTTP 提供了拼图中的最后一块碎片；它为在 Web 服务器和客户端之间**识别已标识数据**提供了一种简单且有效的方法。

HTTP 应用程序的主要功能是请求传输。

在本章的稍后部分，我们详细概述定义的 HTTP 类型和协议标头格式。作为对该部分的介绍，一个有用的第一步将是检查 HTTP 的逻辑操作及其与 Web 内部其他组件的交互。图 21.1 概述了 HTTP 应用程序协议如何与 Web 服务器和客户端相关。如所示，浏览器被设计为解释 HTML 页面中包含的格式信息。HTML 页面可能包含指向互联网其他地方页面的 URL。这些链接被称为*超链接*，并在 HTML 页面中通常以颜色或下划线形式显示。

**图 21.1.**

*Web 的逻辑结构。*

HTTP 应用程序的主要功能是请求由这些链接引用的页面。这是通过以下步骤完成的：

- 1. 当浏览器*指向* Web 服务器时，HTTP 将启动客户端与端口 80 之间的 TCP 连接——80 是为 HTTP 服务器进程保留的已知端口号。

- 2. 在建立此 TCP 连接后，选定的 HTML 文档将通过该连接传输以进行显示。

- 3. 在 HTML 文档传输到客户端后，服务器会自动终止 TCP 连接。

**注意：** 即使客户端要在同一个会话中从同一服务器传输更多 HTML 页面，TCP 连接也会终止。每个新请求都要求建立另一个 TCP 连接。这种运行方法引发了一些严重的性能担忧，这些将在本章后面进行讨论。

HTML 的一个显著优势是可以在每个文档中编码对内容的额外引用。如前所述，这些可以是指向位于同一 Web 服务器上或位于不同 Web 服务器上的内容的指针。

除了超链接，HTML 页面通常还包含其他信息对象——特别是图形。随着

浏览器在遇到嵌入信息的引用时，它将向 HTTP 请求下载这些文件。HTTP 将为每个需要下载的文件启动单独的 TCP 连接。某些 HTML 页面可能包含多个对象，为了加速整个下载过程，某些浏览器将允许同时启动多个 TCP 连接。

**注意：** 网景领航者（Netscape Navigator）浏览器允许用户指定任意数量的可能并发 TCP 连接。通过逐渐增加最大连接数，可以观察到细微的性能提升；然而，任何性能收益在连接达到四个后似乎都会趋于平缓。这是由于浏览器设置了硬编码的四个并发连接限制，尽管客户端完全可以请求更多连接。

## 协议定义

HTTP 应用使用了一种由主版本号和次版本号组成的版本计数方案。这些数字按照以下格式排列：

`<主版本号> . <次版本号>`

**注意：** 这一设计的目的是通过更改主版本号来突出 HTTP 基础消息系统内部的变化。相比之下，次版本号的更改表示向协议添加了新的特性和功能。

目前的 HTTP 实现是基于在“意见请求 (RFC) 1945 中概述的设计规范。这些实现被归类为 HTTP 版本 1.0（表示为 HTTP/1.1）。RFC 1945 被称为信息性 RFC，因此它并不代表一个经过验证的应用标准。这导致来自不同供应商的许多 HTTP 实现在可用功能上表现出不同程度的差异。

HTTP 更新版本的初稿（称为版本 1.1，或 HTTP/1.1）已经完成。该升级版规范的细节已发布在 RFC 2068 中。

RFC 2068 中包含的指示更改被归类为 HTTP 应用的小版本升级。然而，更具意义的是，HTTP/1.1 正在开发作为互联网工程任务组 (IETF) 标准以待批准。其目标是为通用 HTTP 实现的开发制定清晰的指南，并提供某些增强的功能领域。

到目前为止，我们仅通过在较高水平上描述 HTML 页面如何在 Web 内部传输，对 HTTP 应用的一般操作提供了概述。接下来的部分将通过一个真实世界的示例研究 HTTP 应用的语法来扩展这一讨论。
