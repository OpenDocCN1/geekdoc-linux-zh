## 使用 .forward 文件创建“转发”账户

我在工作过的一家地方，除了邮件服务器之外，没有任何 Unix 机器允许发送外部邮件。这在检测到错误时产生了一个问题。解决方案是在 Unix 机器上创建一个 `bounce` 用户账户。假设我们创建 `bounce`，在 `/home/bounce` 目录下创建一个名为 `.forward` 的文件。然后我们在 `.forward` 文件中添加我们想要转发的地址。你可以向此文件添加任意数量的电子邮件地址，但请注意所有的邮件将转发到 `.forward` 中列出的每个地址。在具有外部能力的单机上，我们添加了 `bounce` 用户。在 `/home/bounce` 目录下创建了如下内容的文件：

```
randy@my.domain.com

1234567890@mypage_somebody.net
```

## 使用 sendmail 命令发送出站邮件

在我工作过的另一家地方，我不能以任何名为 root 的用户身份发送出站邮件。发件人必须是邮件服务器识别的有效电子邮件地址，而 root 是无效的。为了解决这个问题，我将使用的命令从 `mail` 改为 `sendmail`。`sendmail` 命令允许我们添加 `-f` 开关来指示有效的发件人字段地址。`sendmail` 命令在 AIX、HP-UX 和 Linux 上位于 `/usr/sbin/sendmail`，但在 SunOS 上位置更改为 `/usr/lib/sendmail`。查看列表 3.3 中的函数，我们将在最后介绍细节。

注意列表 3.3，我们又添加了另一个变量 `MAILOUT`。此变量用于开启或关闭电子邮件通知。如果 `$MAILOUT` 变量指向 `TRUE`，且 `$MAIL_FILE` 变量不为空，则会发送电子邮件。如果 `$MAILOUT` 变量不等于字符串 `TRUE`，则禁用电子邮件发送。这只是控制通知的另一种方法。

在 `case` 语句中，我们使用 `uname` 命令的输出为 Unix 平台上的 `sendmail` 命令设置正确的路径。对于 AIX、HP-UX 和 Linux，sendmail 命令的路径为 `/usr/sbin`。在 SunOS 上，sendmail 路径为 `/usr/lib`。我们将正确的路径赋值给 `SENDMAIL` 变量，并使用该变量作为发送邮件的命令。当定义定义后，我们执行该命令，如下：

```bash
$SENDMAIL -f randy@$THISHOST $MAIL_LIST < $MAIL_FILE
```

我们使用 `-f` 选项执行 sendmail 命令，并在后跟一个有效的电子邮件帐户名，即 `randy@$THISHOST`。记住我们将 `THISHOST` 变量定义为本地机器的主机。发件人地址之后是电子邮件地址列表，通过重定向输入到发送命令来使用消息文件。我们也可以使用以下语法：

```bash
cat $MAIL_FILE | $SENDMAIL -f randy@$THISHOST $MAIL_LIST
```

## SNMP 陷阱 (Traps)

大多数商店使用企业级监控工具从中央管理控制台监控所有系统。服务器软件安装在名为管理站的单一机器上。所有受管理/监控的机器都安装了客户端软件。该客户端软件是一个 SNMP 代理，使用本地 MIB 来定义被管理对象或管理变量。这些被管理对象定义了诸如要监控的文件系统以及检测文件系统满的触发阈值。当被管理对象（在本例中为满的文件系统）超过设定的阈值时，会生成本地 SNMP 陷阱，管理站捕获该陷阱并执行预定义的操作，这可能是向系统管理员发送文本呼机。为了理解什么是 SNMP 陷阱，让我们回顾一下每个组件的简短说明：

SNMP（简单网络管理协议）。SNMP 是一种用于代理通信的协议。SNMP 协议最常用的用途是客户端/服务器系统管理软件。

MIB（管理信息库）。SNMP 管理网络中的每个受管理机器或代理都维护一个由被管理机器定义的本地信息数据库（MIB）。符合 SNMP 标准的 MIB 包含有关每个被管理资源属性定义的信息。

SNMP 陷阱 (SNMP trap)。从代理生成的事件向管理服务器发送事件通知，称为 trap。服务器管理站接收并设置 MIB 中的对象，而本地机器（或代理）向管理站通知客户端生成的事件，即 trap。网络管理服务器与其代理（或管理客户端）之间的所有通信都使用简单网络管理协议（SNMP）。

使用企业级管理工具的优点是它利用了 SNMP。对于大多数产品，你可以使用 SNMP 陷阱编写自己的 shell 脚本。具体语法因每个产品而异，但根据安装的软件，你可以让你的 shell 脚本执行与企业管理软件产生相同的通知。使用 Tivoli、EcoTools 或 BMC Patrol（仅列举几个），你有能力将 SNMP 陷阱整合到你的 shell 脚本中进行事件通知。请参考产品文档获取有关创建和使用 SNMP 陷阱的详情。
