
可以使用 `chmod` 命令设置执行位来使脚本变为可执行。当 Bash 在 `PATH` 中搜索命令并找到一个文件时，它会派出一个子 shell 来执行它。换句话说，

```
filename ARGUMENTS
```

等同于执行

```bash
bash ARGUMENTS
```

如果 `filename` 是可执行脚本。此子 shell 会重新初始化自己，因此除了父进程记录的命令位置（参见 Info 页面中的 `bash`）外，其他都会重置。正如我们所见，脚本通常在 `bash` 解释器运行。

```bash
#!/bin/bash
```

### 一些示例

一个非常简单的脚本，向执行它的用户问好：

```bash
jeffry@nowhere ~ cat hello.sh
echo "Hello $USER"
```

另一个使用 `USER` 环境变量的值打印自定义字符串的脚本：

```bash
who | cut -d " " -f 1 | sort -u
```

这是一个包含行来复制目录下所有文件的脚本。脚本首先创建当前目录的文件列表并存入变量 `LIST` 中。然后为每个文件设置副本名称，并进行复制。

```bash
#!/bin/bash
# 为目录中的所有文件制作备份
LIST=`ls`
for i in $LIST; do
ORIG=$i
DEST=$i.old
cp $ORIG $DEST
echo "copied $i"
done
```

直接输入 `mv *.old` 将不起作用，你在一组测试文件上尝试时会发现这一点。为了使其工作：在每一步之后插入你就会发现错误。你系统上的脚本可能使用其他函数，位于其他文件中，或者完全不使用。

成功后，脚本向其父进程返回退出代码 0。

这个脚本是函数的很好的示例，函数使脚本更易读且工作更快。注意使用 `sh` 而不是 `bash`，以便它们在更广泛的系统中可用。在 Linux 系统上，调用 `bash` 作为 `sh` 会导致 shell 以 POSIX 兼容模式运行。

## X Window System

X Window System 是一种网络透明窗口系统，运行在各种计算和图形机器上。X Window System 服务器运行在带有位图显示（bitmap displays）的计算机上。X 服务器通过各种进程通信通道分发用户输入，并接收来自多个客户端程序的输出请求。虽然常见的情况是客户端程序运行在与服务器同一台机器上，但客户端也可以从其他机器透明地运行（包括不同架构和操作系统的机器）。我们将在第 10 章“网络上的网络与远程应用程序”中学习如何实现这一点。

X 支持分级子窗口以及文本和图形操作，均支持单色和彩色显示器。使用 X 服务器的 X 客户端程序非常多。X 联盟发行版中提供的一些程序包括：

- `xterm`: 一个终端模拟器

- `twm`: 一个极简主义的窗口管理器

- `xdm`: 一个显示管理器

- `xconsole`: 一个控制台重定向管理器

- `bitmap`: 一个位图编辑器

- `xauth`, `xhost` 和 `iceauth`: 访问控制程序

- `xset`, `xmodmap` 等：用户偏好设置程序

- `xclock`: 闹钟

- `xfonts` 等：字体显示、列出字体、窗口和显示器信息的工具

- `xfs`: 一个字体服务器

- ...

我们再次引用命令的 man 页面（帮助文档）以获取详细信息。更多解释可以从你的 X 发行版自带的 Xlib - C语言 X 接口、X Window System 协议规范以及 X 工具包的各种手册和文档中找到 `/usr/share/doc` 目录包含了这些以及许多其他文档的引用。

许多其他实用程序、窗口管理器、游戏和小工具也作为用户配置的软件包含在 X 联盟发行版中，或者可以通过互联网上的匿名 FTP 获取。良好的起点是这里 http://www.x.org 和 http://www.xfree.org。

此外，你所有的图形应用程序（如浏览器、电子邮件程序、图像程序、声音播放工具等）都是你的 X 服务器的客户端。请注意，在正常运行（即图形模式）下，Linux  X 客户端和 X 服务器运行在同一台机器上。

## 显示名称 (Display names)

从用户的角度来看，每个 X 服务器都有如下格式的显示名称：

```
hostname;displaynumber.screennumber
```

应用程序使用此信息来确定如何连接到服务器，以及默认使用哪个屏幕（在带有多个显示器的显示器上）：

- `hostname`（主机名）：指定指定物理连接显示器的客户端机器名称。如果没有给出主机名，将采用与同一台机器上的服务器通信的最有效方式。

- `display-number`（显示编号）：词“display”通常指的是一组共享公共键盘绑定和指针（鼠标、写板等）的显示器集合。大多数工作站通常只有一个键盘，因此也只有一个显示器。然而，较大的多用户系统经常有多个显示器，以便让多个人同时进行图形工作。为了避免混淆，当该显示器的 X 服务器启动时，机器上的每个显示器会被分配一个显示编号（从 0 开始）。显示名称中必须始终提供显示编号。

- `screen number`（屏幕编号）：某些显示器在两个或多个显示器之间共享同一个键盘和指针。每个显示器都有自己的一组窗口，当该显示器的 X 服务器启动时，每个屏幕会被分配一个屏幕编号（从 0 开始）。如果未给出屏幕编号，则将使用 0。

在 POSIX 系统上，显示名称存储在你的 `DISPLAY` 环境变量中。该变量由 X 终端模拟器自动设置。然而，当你登录到网络上的另一台机器时，你可能需要手动设置 `DISPLAY` 指向你的显示器，请参见“Telnet and X”章节。

更多信息可以在 X 页面中找到。

## 窗口和桌面管理器 (Window and desktop managers)

屏幕上窗口的布局由被称为窗口管理器的特殊程序控制。虽然许多窗口管理器会遵守给定的几何规范，但另一些可能会选择忽略它们（例如，要求用户使用指针显式地绘制窗口区域）。

由于窗口管理器是普通的（尽管复杂的）客户端程序，可以构建各种用户界面。X 联盟发行版使用一个名为 `twm` 的窗口管理器，但大多数用户更喜欢带有系统资源的华丽界面。`Swfish` 和 `Enlightenment` 是流行的例子，每个用户根据心情和风格拥有自己的桌面。

桌面管理器可以使用其中一种窗口管理器，或者以方便的方式安排你的图形桌面，带有工具栏、下拉菜单、信息性消息、时钟、程序管理器、文件管理器等。最流行的桌面管理器有 `Gnome` 和 `KDE`，它们都运行在任何 Linux 发行版和其他类 Unix 系统上。

# Gnome 中的 KDE 应用 / KDE 中的 Gnome 应用

你不需要启动 KDE 桌面来运行 KDE 应用。如果你安装了 KDE 库（`kdelibs` 包），你就可以从 Gnome 菜单中运行这些应用程序，或从 Gnome 终端启动它们。

在 KDE 环境中运行应用程序稍微棘手一些，因为 Gnome 中没有单一的基库。然而，在运行或安装应用程序时，你可能需要安装的依赖关系以及额外的包将会变得清晰。

# X 服务器配置 (X server configuration)

以前随 Linux 来的 FreeBSD 发行版使用 `XF86Config` 配置文件进行初始设置。该文件配置你的显卡并在多个位置进行搜索，尽管它通常位于 `/etc/X11`。

如果你看到系统上存在 `/etc/X11/XF86Config` 文件，可以在 Info 或关于 XF86 的页面中找到完整描述。由于 Free86 的许可问题，新系统通常带有 XOrg 发行版的 X 服务器和工具。主配置文件是 `xorg.conf`，通常位于 `/etc/X11`。该文件由若干部分组成，顺序任意。这些部分包含关于显示器、视频适配器、屏幕配置、键盘的信息。作为用户，你不需要太担心这个文件的内容，因为一切在系统安装时就已经确定了。

如果你需要更改图形服务器设置，可以运行配置工具或手动编辑设置 XFree86 接口的文件；由于配置错误可能导致图形模式出现不可读的乱码，在尝试更改之前你可能想要创建一个配置备份。

# 键盘特定设置 (Keyboard specific settings)

## 键盘设置 (Keyboard setup)

使用 `loadkeys` 命令为文本控制设置键盘布局。使用本地 X 配置工具手动编辑 `XF86Config` 中的 `Keyboard` 部分来配置图形模式的布局。`XkbLayout` 是你设置为：

```
XkbLayout      "us"
```

这是默认值。通过将引号内的值替换为 keymaps 子目录下列出的任何名称来更改你的本地设置。如果你找不到 keymaps，尝试使用命令显示它们在系统中的位置：

```
locate keymaps
```

可以组合键盘布局，例如：

```
Xkblayout      "us,ru"
```

在编辑之前备份 `/etc/X11/XF86Config` 文件！你需要使用 root 账户执行此操作。

注销并重新连接以加载 X 设置。
