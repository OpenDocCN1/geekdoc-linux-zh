
- 如果您认为 Intel 语言的指令使用等号（`=`）是赋值，那么您可以认为 AT&T 语法结构使用右箭头（`→`）进行赋值。应当说明的是，这两种格式里，部分标准函数的运算符单元的书写格式确实是相同的，例如`memcpy()`、`strcpy()`。

- AT&T 语言中，在寄存器名称之前使用百分号（`%`）标记，在立即数之前使用美元符号（`$`）标记。AT&T 语言使用圆号，而 Intel 语言则使用方号。

- AT&T 语言里，每个运算符操作都需要声明数据的类型：

  - `q`-quad(64位)
  - `l`指代32位long型数据。
  - `w`指代16位word型数据。
  - `b`指代8byte数据。
  - 其他区别参考公司发布的`x86 Assembly Manual`。

现在再来说 `hello world` 的 AT&T 语言，就会发现它和 IDA 看到的没有区别。有些人可能注意到，用于数据对齐的按照 32型数据进行写入后，就会发现两者一致。此外，在 `main()` 时，处理 `EAX` 寄存器的指令是 `MOV` 而不是 `XOR` 指令。某些硬件框架有更为直观的“LOAD”、“STORE”指令。

## 3.2 x86-64

### 3.2.1 MSVC-x86-64

若用64位 `MSVC` 编译程序，则得到如下指令。

指令清单3.7 MSVC生成的汇编指令

```
main PROC
    push   rbp
    mov    rbp, esp
    sub    rsp, 40h
    lea    rcx, OFFSET :LC0
    call   printf
    xor    eax, eax
    add    rsp, 40h
    pop    rbp
    ret
main ENDP
```

在 x86-64 框架的 CPU 上，所有的寄存器都被扩展为64 位寄存器。为了尽可能利用寄存器减少内存访问次数，编译器会利用寄存器传递参数（参见64.节）。也就是说，编译器会选用寄存器传递剩余的参数。Win64程序使用 `RCX`、`RDX`、`R8`、`R9` 这6个寄存器传递参数。稍后看到这种情况：`printf()`使用 `RCX` 传递参数，而像32位程序那样使用栈传递。在 x86-64 平台上，寄存器和指针都是64 位的。为了兼容性，64位寄存器的低32位充当32位。

### 3.2.2 GCC-x86-64

我们使用64位Linux 的 `GCC` 编译上述程序，可以如下所示的指令。

指令清单3.8 GCC生成的汇编指令

```
.LC0:
.string "hello, world\n"
main:
    pushq %ebp
    movq %esp,%ebp
    subq $16,%esp
    leaq .LC0(%esp),%di  # 注意：此处原文为di
    movl $-16,%esp
    subl $16,%esp
    movl (%esp),edi
    call printf
    movl $0,%eax
    leave
    ret
```

在 x86-64兼容的CPU中，`RAX`/`EAX`的关系如下：

| 7th(字符) | 6th | 5th | 4th | 3rd | 2nd | 1st |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `RAX` | | | | | | |
| `EAX` | | | | | | |

`main()`函数的返回值是整数，但是出于兼容性的，编译器仍然使用栈。然而，即使是64位的应用程序，在程序结束时 `EAX` 的值是零。此时，数据栈里有40字节。这部分有一个专用的名词，shadow space。本书将在8节详细介绍。

## 3.3 GCC的其他特性

只要C语言使用了字符串常量（参照3.1节），编译器就会把字符串置于常量区以保证内容不会变化。不过`GCC`有一个有趣的特征：它把字符串分开。我们来看这段程序：

```c
#include <stdio.h>
void f1() {
    printf("world\n");
}
void f2() {
    printf("hello world\n");
}
int main() {
    f1();
    f2();
}
```

多数C/C++编译器（包括`MSVC`编译器）会分配两个字符串，不过`GCC 4.8`编译结果更为可见。指令1在IDA中观察`GCC 4.8`汇编

```
proc near
    push   rbp
    mov    rbp, esp
    sub    esp, 1Ch
    lea    rcx, OFFSET :LC0
    call   printf
    add    esp, 1Ch
    pop    rbp
    ret

proc near
    push   rbp
    mov    rbp, esp
    sub    esp, 1Ch
    lea    rdx, OFFSET :LC0
    call   printf
    add    esp, 1Ch
    pop    rbp
    ret
```

在打印"hello world"的时候，这两个指针的地址实际上是相邻的。在调用的`puts`输出时，函数本身分为两个部分。实际上我们在编译清单可以看到这两个字符串并没有分开。在`f1()`调用`puts`时，它输出字符串“world”和前面的字符串（由于字符串可以连起来形成最终的），编译器这种技术来节省内存。
