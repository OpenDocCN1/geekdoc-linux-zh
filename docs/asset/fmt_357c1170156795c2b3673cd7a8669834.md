
`"Guest Volume" -uamlist uams_guest.so -loginmesg "Welcome guest!"`

`"User Volume" -uamlist uams_clrtxt.so -port 12000`

`"Guest Volume"`示例在用户登录服务器时会显示“Welcome guest!”消息。由于它是访客服务器（`uams_guest.so`），因此不需要密码。在`"User Volume"`中，该卷需要需要明文密码和有效用户账户。该服务在端口号`12000`上提供。`Guest Volume`和`User Volume`分别作为两个服务器名称出现在Mac的选择窗口中。

如果你的Linux计算机是一台路由器，其一个或多个网络接口连接到公共网络，你应该使用`-ipaddr`地址。通过该选项，你可以限制从特定网络接口对`netatalk`服务器的访问（可能仅允许访问本地局域网的接口）。`apfd.conf`中列出了30多个可以配置的选项。

## 设置用户

如前所述，`netalk`服务器（默认情况下）允许具有有效用户名和密码的用户使用明文（未加密）密码登录服务器，并访问（或）他们的家目录。请参阅本章后后的“保护`netalk`卷”部分，了解如何使用加密密码设置服务器。

## 共享 netatalk 卷

你使用`AppleVolumes.default`文件来指定`netatalk`服务器的哪些卷对你的Mac客户端可用。该文件位于`/etc/atalk/AppleVolumes.default`。

> 注意：请参阅“文件和目录级安全”部分获取有关隐藏文件和目录的详细信息，以及与共享卷相关的用户组权限问题。

查看`AppleVolumes.default`文件的最后一行。单独的波浪号（`-`）告诉AppleTalk守护进程将所有Linux家目录（通常在`/home`目录下）作为AppleTalk共享目录可用。当用户登录`netatalk`服务器时，用户的家目录将显示为可用的共享目录。选择打开该目录的用户与直接登录Linux时具有相同的更改和删除文件的权限。

一种常见的做法是在包含单个波浪号（`-`）的行中添加文本“Home Directory”，使其显示如下：

```
- - Home Directory
```

要共享额外的目录，只需向你想共享的目录添加完整路径名以及你想分配给它的卷名。例如：

```
/var/toyprojects "Linux Toys"
```

从这个示例可以看出，`/var/toyprojects`以`"Linux Toys"`的名称共享。卷名限制为27个字符，且不能包含`"-"`。在这种简单的情况下，对卷的访问权限由用户`host`决定。

## 保护 netatalk 卷

某些`netalak`特性可用于保护你的卷。接下来的部分描述了如何在用户、主机和文件级保护你的卷。

### 用户级安全

如果你想更改访客账户，可以添加你自己的账户。要更改身份验证方式，你可以使用以下之一：

- `AFPD_UAMLIST="-U uams guest.so"`
- `AFPD_UAMLIST="-U uams clrtxt.so"`

第一个示例使`netatalk`成为仅限访客的服务器。第二行允许Linux系统中使用明文密码的有效用户。下的一行允许你更改访客账户：

```
AFPD_GUEST=nobody
```

你可以将`nobody`更改为Linux任何有效用户账户，该账户将成为你的访客用户。

当你创建共享卷（在`AppleVolumes.default`中）时，你可以指定哪些用户可以访问该卷。使用默认明文密码，你只需像通常在Linux中那样设置用户账户（参见第11章）。然而，对于配置为使用加密密码的用户（服务器），你必须创建一个AppleTalk密码文件（`/etc/talk/afpasswd`）。作为`root`，输入：

```
# afpasswd -c
```

此命令收集所有用户（UID 100及以上）和访客用户（`nobody`），并将它们添加到`afpasswd`文件中。

接下来，需要为`afpasswd`文件中的每个用户添加正确的密码，允许他们访问你的`netatalk`共享。例如：

```
# afpasswd jake

Enter NEW password: ********

Enter NEW password again: ********
```

最初创建`afpasswd`后，你以后可以手动添加用户（前提是他们拥有有效的Linux账户）。对`afpasswd`使用该选项：

```
# afpasswd -a cindy

Enter NEW password: ********

Enter NEW password again: ********
```

与选择良好密码相关的问题（参见第14章）同样适用于设置AppleTalk密码。如果密码匹配，用户将能够使用指定的用户名登录，并在尝试从`netatalk`服务器挂载AppleTalk卷时，前提是`netatalk`服务使用的是加密身份验证（`uams_dx.so`）。

### 主机级安全

你使用`/etchosts.allow`和`/etc/hosts.deny`文件限制网络上的哪些计算机访问你的`netatalk`服务。这些文件在第14章的“使用TCP封装”部分中描述。这些文件是你用于允许或限制访问其他Linux网络服务的相同文件。

# 第 26 章：将 Fedora 与 Apple Mac 集成

以下是`hosts.allow`文件中的一个条示例。

```
ALL: .linuxtoys EXCEPT abc.linuxtoys.com
```

此示例允许`linuxtoys.com`域内的所有计算机访问`netatalk`（以及所有其他服务），但`abc.linuxtoys.com`计算机除外。关于指示服务（代替`ALL`）和主机的其他方法的详细信息，请参阅第14章。

## 文件级和目录级安全

`Netatalk`会创建文件和目录来处理Linux中不具备的Mac特性。理解这些文件和目录并结合标准的Linux所有权和权限，是精化你共享的AppleTalk卷访问控制的最佳方法。

## 理解隐藏的 Mac 文件和目录

`Netatalk`会创建你从Mac Finder中看不见的特殊文件和目录。由于这些文件以点（`.`）开头，它们在Linux的普通目录列表（`ls`）中也是隐藏的。以下描述将帮助你理解这些文件和目录。

> 注意：要从文件夹窗口（来自GNOME桌面）查看隐藏文件，请点击 编辑 -> 选项。在 视图 卡中，勾选“显示隐藏和备份文件”复选框。在终端窗口中输入`ls -a`来查看。

- `.AppleDouble`—你共享的AppleTalk (`netatalk`) 卷内的每个目录都包含一个`.AppleDouble`目录。一旦你在`netatalk`服务器上从Mac客户端创建文件或目录，该目录就会自动创建。该内包含单独的文件，代表关联目录中每个文件的属性。例如，在`/var/projects`中创建一个名为`mytext.txt`的文本文件将创建一个名为`/var/projects/.AppleDouble/mytext.txt`的文件，其中包含该文件的属性。

你可以在共享卷的任何`.AppleDouble`内部创建一个图标目录（例如`/var/projects/.AppleDouble/Icon`），以便你向共享卷添加自定义图标。这些目录的权限必须开放写入权限（对于你任何想要添加和更改图标的人）和读取权限（对于你任何想要看到图标的人）。

- `.AppleDouble/.Parent`—每个`.AppleDouble`目录下的此目录包含共享目录的信息。

- `.AppleDesktop`—对于每个共享卷，此目录位于顶层目录。该目录包含创建在卷上存储的数据的应用程序信息以及用于表示该数据的图标。

- `Network Trash Folder`—位于顶层共享目录中的此文件夹包含客户端删除的文件。（注意：目录名称中的空格必须在前面加反斜杠才能从Linux shell访问该文件夹）。

# 第四部分：Fedora 和 RHEL 网络与服务器设置

- **Temporary Items (临时项目)** —某些应用程序需要此文件夹（位于顶层目录）来创建临时文件。

其他目录也可能出现，因为处理卷中文件的应用程序需要特殊的目录来完成工作。

## 设置文件和目录权限

共享`netatalk`卷的权限通常比典型的共享Linux目录更开放，以匹配Mac用户对权限的通用预期。

特别是，`set-GID`（组）位通常会在目录上开启。通过使用`set-GID`特性，在该目录中创建的任何目录将由关联组所有。例如，请以`root`用户身份从shell中执行以下步骤（创建任何你想要共享的目录名）：

```bash
# mkdir /var/toyprojects
# chown chris /var/toyprojects
# chgrp toygroup /var/toyprojects
# chmod 2775 /var/toyprojects
```
