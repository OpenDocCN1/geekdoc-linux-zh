### 6.1 Windows

`Windows`的`DLL`加载不是`PIC`机制。如果`Windows`要把加载到另一个进程，它就会内存中进行“修补”（重定向），从而可以正确处理地址。这就意味着`Windows`无法在不同进程共享一份`DLL`，因为每个加载在内存内的实例只能访问自己的空间。

### 6.2 在Linux下的LD_PRELOAD

`Linux`程序可以加载其他库之前、甚至在系统库（例如`libc.so.6`）之前加载自己的库。借助这项功能，我们能够编写自定义函数“替换”系统库中的同名函数。进一步说，劫持函数如`read()`、`write()`等系统函数并非易事。

接下来，我们以`uptime`来进行演示。我们都知道，应用可以显示计算机工作多久。另一款`strace`可见，`uptime`通过`proc/uptime`获取工作时长：

```bash
$ strace uptime
open("/proc/uptime", O_RDONLY) = 3
lseek(3, 0, SEEK_SET) = 0
read(3, "166.8\n", 20) = 47
```

其实，`proc/uptime`并不是真正的磁盘文件。它有两个数值：

- 第一数值显示系统运行的总时长；
- 第二数值是计算机空闲的时间。

这两项数据都以秒为单位。我们编写一个`open()`、`read()`和`close()`函数的动态链接。首先的就是`open()`函数。它判断程序打开的文件。如果相同，`open()`函数记录文件描述，接下来处理的是`read()`函数。`read()`判断程序打开的是我们要关注的文件。如果相同，我们就用某些符代替，否则调用`libc.so`原来的`read`。最后需要处理的是`close()`函数，它确保关闭打开的外部文件。
