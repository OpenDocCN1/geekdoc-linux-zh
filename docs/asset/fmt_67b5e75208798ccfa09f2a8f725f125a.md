## 变量与常量

然而，我们的脚本存在一个问题。注意看 `System Information Report` 字符串是如何重复的吗？对于我们微小的脚本来说这不是问题，但想象一下如果我们的脚本非常长，并且有这个字符串的多个实例。如果我们想将标题改为其他内容，我们必须在多个地方更改它，这可能是一大量工作。如果我们能安排脚本，让字符串只出现一次而不是多次呢？这将使脚本未来的维护变得容易得多。我们可以这样做：

```bash
#!/bin/bash

## 输出系统信息页的程序

title="System Information Report"

echo "<html>
<head>
<title>$title</title>
</head>
<body>
<h1>title</h1>
</body>
</html>"
```

通过创建一个名为 `title` 的变量并赋值为 `System Information Report`，我们可以利用参数扩展并将字符串放置在多个位置。

那么，我们如何创建一个变量呢？简单，直接使用它就行了。当 shell 遇到一个变量时，它会自动创建它。这与许多编程语言不同，在那些语言中，变量在运行之前必须显式地声明或定义。shell 在这方面非常宽松，这可能会导致一些问题。例如，考虑这个在命令行上执行的场景：

```bash
me@linuxbox -j]$ foo=yes
me@linuxbox -j]$ echo foo
yes
me@linuxbox -j]$ echo fool
```

我们将值 `yes` 赋值给变量 `foo`，然后用 `echo` 显示它的值。接下来，我们显示拼写错误为 `fool` 的变量值，并得到空白结果。这是因为 shell 在遇到 `fool` 时没有创建该变量，并给了它默认值（或为空）。从这里我们学到必须密切注意拼写！理解这个例子中发生了什么也很重要。从我们之前观察 shell 是如何执行的，我们知道后续命令：

```bash
me@linuxbox -j]$ echo "<html>
<head>
<title>Page Title</title>
</head>
<body>
  Page body.
</body>
</html>
```

领先字符是包含在 `PS2` shell 变量中的 shell 提示符。每当我们向 shell 输入多行语句时，它就会出现。这个功能现在看起来有点模糊，但稍后当我们涵盖多行编程语句时，事实证明它是非常方便。

## Here Documents

我们查看了两种放置文本的方法，它们都使用了 `echo` 命令。第三种方法称为 here document 或 here script。here document 是 I/O 重定向的一种额外形式，在其中我们将一段文本嵌入到脚本中，并将其输入到命令的标准输入（standard input）。它的工作原理如下：

```bash
command << token
token
```

在这个示例中，`command` 是接受标准输入的命令名称，而 `token` 是用于指示嵌入文本结束的字符串。在这里我们将修改脚本以使用 here document：

```bash
#!/bin/bash
```

## 输出系统信息页的程序

```bash
TITLE="System Information Report For $HOSTNAME"
CURRENT_TIME="$(date +%X %Z)"
TIMESTAMP="Generated $CURRENT_TIME, by $USER"
```

```bash
cat << _EOF_
<<html>
<head>
<title>$TITLE</title>
</head>
<body>
<h1>$TITLE</h1>
<p>$TIMESTAMP</p>
</body>
</html>
EOF_
```

我们的脚本现在没有使用 `echo`，而是使用 `cat` 和 here document。字符串 `_EOF_`（意为“文件结束”，一种常见的惯例）被选为 `token` 并标记了嵌入文本的结束。注意，`token` 必须单独出现，且行尾不能有空格。

那么，使用 here document 的优势是什么？它与 `echo` 基本相同，不同在于默认情况下here document 内部的单引号和双引号会失去对 shell 的特殊含义。这是一个命令行示例：

```bash
[linux]$ foo="some text"
[linux]$ cat << _EOF_
> $foo
> "$foo"
> 'foo'
> \foo
> _EOF_
some text
"some text"
'some text'
```

如我们看到的，shell 不关注引号。它将其视为普通字符。这允许我们在 here document 中自由地嵌入引号。这对于我们的报告程序可能非常有用。

here document 内部的文本会参数扩展、命令替换和算术扩展，字面字符 `$` 和 `\` 必须用 `\` 进行转义。

然而，我们将起始 `token` 括在引号中时

```bash
cat << '_EOF_'
```

引号将从 `token` 中移除，且不会对文本执行任何扩展。

[me@linux~$] foo="some text"

[me@linux~$] cat << '_EOF_'

> foo

> "$foo"

> 'foo'

> _EOF_

foo

"some text"

'foo'

```

here document 可以用于任何接受标准输入的命令。示例中，我们使用 here document 将一系列命令传递给 `ftp` 程序，以从远程 FTP 服务器检索文件：

```bash
#!/bin/bash

## 通过 FTP 获取文件的脚本

FTP_SERVER="ftp.debian.org" FTP_PATH=/debian/dists/bookworm/main/installer-amd64/current/images/cdrom/

REMOTE_FILE="debian-cd-info.tar.gz"

ftp -n << _EOF_

open $FTP_SERVER

user anonymous me@linuxbox

cd $FTP_PATH

hash

get $REMOTE_FILE

bye

_EOF_

ls -l "$REMOTE_FILE"
```

如果我们将重定向操作符从 `<<` 改为 `<<-`，shell 将忽略 here document 开头的 `*` 字符（但空格）。这允许 here document 进行缩进，从而提高可读性。

```

## Shell 函数

```bash
echo "Step 2"

return

}

## 主程序在此开始

echo "step 1"

step2

echo "Step 3"
```

当 Shell 读取脚本时，它会跳过第 1 到 11 行，因为这些行包含了注释和函数定义。执行从第 12 行的 `echo` 命令开始。第 13 行调用了 Shell 函数 `step2`，Shell 会像执行任何其他命令一样执行该函数。随后程序控制移动到第 6 行，执行第二个 `echo` 命令。接着执行第 7 行。它的 `return` 命令会终止函数并将控制权返回到函数调用处之后的一行（第 14 行），最后执行最后一个 `echo` 命令。请注意，为了让函数调用被识别为 Shell 函数而不是解释为外部程序的程序，Shell 函数的定义必须在脚本中被调用之前出现。

我们将在脚本中添加最少的函数定义，如下所示：

  return

```bash

  return

  return

## 局部变量

在我们目前为止编写的脚本中，所有变量（包括常量）都是全局变量。全局变量在整个程序运行期间一直存在。这对于很多情况是可以接受的，但有时会增加 Shell 函数使用的复杂度。在 Shell 函数内部，通常希望使用局部变量。局部变量仅在定义它的 Shell 函数以及该函数可能调用的任何其他函数内部可见。一旦 Shell 函数终止，局部变量就会消失。

使用局部变量允许程序员使用可能在脚本全局范围或其他 Shell 函数中已经存在的同名变量，而不必担心潜在的冲突。

这里是一个示例脚本，演示了如何定义和使用局部变量：

```bash
#!/bin/bash

## local-vars: 演示局部变量的脚本

foo=0  # 全局变量 foo

funct_1 () {

  local foo  # 局部变量局部 funct_1

  foo=1

  echo "funct_1: foo = $foo"

}

funct_2 () {

  local foo  # 局部变量局部 funct_2

  foo=2

  echo "funct_2: foo = $foo"

}

echo "global: foo = $foo"

funct_1
```

```bash
echo "global: foo = $foo"

funct_2

echo "global: foo = $foo"
```

我们可以看到，局部变量是通过在变量名前加上 `local` 关键字来定义的。这创建了一个仅限于其定义所在 Shell 函数的局部变量。一旦在 Shell 函数外部，该变量就不再存在。当我们运行此脚本时，会看到如下结果：

```bash
me@linuxbox:~$ local-vars

global: foo = 0

funct_1: foo = 1

global: foo = 0

funct_2: foo = 2

global: foo = 0
```

我们看到，在两个 Shell 函数内部对局部变量 `foo` 赋值不会影响函数外部定义的 `foo` 的值。

这一特性允许编写函数时保持它们相互独立，并与它们所属的脚本保持独立。这非常有价值，因为有助于防止脚本的一个部分干扰另一个部分。它还允许函数具有良好的移植性，即根据需要，可以将它们在脚本之间进行复制粘贴。

## Shell 函数与重定向

如果我们仔细观察 Shell 函数的编写方式，可能会注意到我们在第 6 章中提到的内容。

```bash
my_func() {

  command1

  command2

  command3

}
```

大括号内的三个命令形成了一个组合命令。正如我们在第 6 章所回忆的，在涉及重定向时，组合命令会将多个命令合并成一个整体。通过组合命令，我们可以执行：

```bash
{ command1; command2; command3; } > some_output.txt
```

以及：

```bash
{ command1; command2; command3; } < some_input.txt
```
