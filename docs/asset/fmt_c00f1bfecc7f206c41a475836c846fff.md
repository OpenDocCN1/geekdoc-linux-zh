
请注意，本章中的许多示例依赖于`find`、`buffer`和`mt`等辅助命令。

### find

`find`是一个强大的命令。它搜索指定的目录结构并根据指定的表达式评估所有文件。每个匹配项都根据指定的操作进行处理。默认操作是打印文件名。完整信息请参帮助页（man page）。

### mt and mtx

`mt`和`mtx`命令提供磁带控制。`mt`可报告磁带驱动器的状态、报告或设置磁带头的绝对/或逻辑位置、倒带驱动器、弹出磁带（在某些驱动器上），以及向前寻道到最后一个数据块的末尾（允许下一个命令向给定的磁带添加新的数据集）。

UNIX 下这种磁带处理方式通常让新系统管理员感到困惑。一个磁带可以包含多个数据集——其中每一个都被视为磁带上一个独立的、无命名的文件。`mt`和`mtx`命令利用了`ioctl()`函数。

可以通过以下步骤识别未标记磁带的内容：

1. `mt -f /dev/nst0 eod`
2. `mt -f /dev/nst0 stat`
3. 读取输出——文件编号（磁带上最后一个文件的编号）指示了磁带上存储了多少成员。
4. `mt -f /dev/nst0 rewind`
5. 针对每个成员：
   (a) `cat /dev/nst0 | file -`
   (b) `mt -f /dev/nst0 fsf`（文件向前寻道）。

此后，倒带磁带并执行相应的命令从磁带上的成员中提取存档索引或文件。需要注意的是，在应用程序中使用 UNIX 磁带驱动器是可能的。因此，你可能会发现某个系统中，应用程序将大型数据集从磁带的缓冲部分存储到内存或临时目录中，对其进行处理并写入另一个驱动器。鉴于如今巨大的硬盘和相对昂贵的磁带驱动器，这种情况现在很少见，但在 Unix 或 Linux 下可以做到，就像几十年来在大型机上那样的。

Leonardhoff 的`mtx`命令针对最常见的磁带库进行了扩展。用户可以执行类似下面的命令：

```
mtx -f /dev/st0 next
```

来加载下一块磁带。还有其他选项通过槽位编号加载特定磁带，例如：即使命令提供的数据是突发性的，`buffer`也能工作——这在压缩、网络通信，甚至是繁忙的多任务系统上的正常存档操作中都很常见。

## bakdirs

此脚本测试所有文件系统挂点，以查看哪些是本地挂载，哪些是通过网络或可移动介质挂载。它用于将备份限制在适当的文件系统中。

```
mount | while read dev mpoint type options
do
[ "$type" -- NFS ] && continue
[ "$mpoint" -- /mnt/cdrom ] && continue
[ "$mpoint" -- /proc ] && continue
echo $mpoint
done
```

在此示例中，`mount`命令的输出被传递到`while/read`循环中。命令的每行输出如下：

```
/dev/hda5 on /usr type ext2 (rw)
```

它的格式为`device on mountpoint ftype (options)`。我们使用`$x`作为占位符来读取`on`和`type`处的单词。我们还获取了`opts`，尽管它在示例中没有被使用。解析选项字符串需要对`$1FS`等其他工作进行处理，而这在这种情况下是不必要的。然而，如果我们想自动排除以读模式挂载的文件系统；我们可以实现额外的脚本代码（或调用`sed`、`tr`或`awk`进行解析），或者用 Perl、Tcl 等语言重写脚本。

对于每行输入，脚本会对将被跳过的文件系统特征进行一系列测试。脚本会输出通过测试的文件系统的挂点。

在其他情况下，此脚本或其简单变体也可以与`find`一起使用，将遍历限制在本地挂载的文件系统中。

## IP 协议栈

计算机网络的目标是实现运行在独立计算机上的应用程序之间的通信。在设计 IPv4 时，其创建者决定将计算机应用程序与现有及未来可能各种网络硬件隔离开。这同时也预见到鼓励可靠通信的最佳方式是将可靠通信层集成到 IP 协议族中。基于此，他们设计了一种概念上的分层方法，我们称为 IP 协议栈或 IP 协议族。

以太网是一种数据链路层协议，运行在许多不同的物理层技术之上——甚至在一个网络中这些技术是混合使用的。这使得网络层协议可以将一个由光纤和双绞线组成的网络视为统一的以太网协议。同样，IP 网络可以跨越不同的数据链路协议，为跨越以太网、令牌环（Token Ring）和串行链路的网络提供统一视图。

就像网络栈中的某一层可以跨越其下层的不同实现一样，每一层都可以支持其上层的同时实现。例如，以太网支持同时运行的 IP、IPv6、IPX 和 Apptalk。从协议的角度来看，这不是一个问题，但可靠性往往会因为复杂性的增加而受到影响。同样，IP 支持同时使用多个层协议，如 TCP、UDP、ICMP 和 ARP。

为了能够自由通信，Linux 应用程序拥有作为`sockets`接口的简单 API。该 API 的可追溯到第一个 BSD 网络实现，在过去的二十年里，它只需要少少的工作就能满足网络程序员的需求。此外还存在其他 API，其中最突出的是 TLI 和 Streams API。这两者都没有提供足够的理由将现有应用程序从 Sockets API 迁移过来。Sockets API 可以使用 TCP 和 UDP 协议。此外，专用接口允许特定程序获取并操作低级网络信息。

互联网标准定义在称为 RFC（意见征询）的文档中。这些文档可以通过互联网上的许多来源获取。RFC 文档记录了协议、协议所依赖的编号分配、标准过程本身以及 RFC 背后的大部分历史。

## IPv4 地址体系

IPv4 地址是 32 位值，通常表示为 0 到 255 的十进制数，用点分隔（例如`127.0.0.1`）。IPv4 地址被划分为若干类。在每一类中，地址有两个不同的部分：网络地址和主机地址。这些类别如表 13.1 所示。

在 IPv4 诞生初期，完全不清楚大型网络中存在什么样的网络技术。因此，原始的类别划分并不匹配网络拓扑结构。开发的解决方案被称为子网划分（subnetting），它允许组织在特定网络地址的主机组件和网络组件之间选择任意边界。子网由子网掩码表示，并通常以点四位地址格式编写。零表示主机部分。因此，如果 A 类网络 10 使用`255.255.255.0`的掩码进行子网划分，则该网络内部将拥有 65,534 个（子）网络，每个网络有 254 个主机。主机和外部网关需要识别应用于网络内的子网掩码。这与 CIDR（无类路由）不同，CIDR 中网络是以外部网关可见的方式聚合的。

### 表 13.1 IPv4 地址分类

| 类别 | 地址范围 | 网络 | 主机 |
|---|---|---|---|
| A 类 | 1 到 126 | 126 | 16777214 |
| 回环（预留的 A 类） | 127 | 无 | 无 |
| B 类 | 128.0 to 191.255 | 16384 | 65534 |
| C 类 | 192.0.0 to 223.255.255 | 2097152 | 254 |
| D 类（组播地址） | 224.0.0.0 to 239.255.255 | 无 | 无 |
| E 类（预留） | 240.0.0.0 to 247.255.255 | 无 | 无 |

网络 127 留用于回环接口，该接口地址始终为`127.0.0.1`。回环接口在每个 IP 实现中都会使用。发送到回环地址的 IP 数据报由发送主机接收，且永远不会出现在物理网络上。

IP 支持多种形式的广播，这是一种向多个主机发送单个数据包的技术。广播机制有三种形式：本地、子网和全网。本地广播地址是全 1 地址，即`255.255.255.255`。该地址保证不被路由器转发。这种广播与 BOOT、DHCP 和 ARP 等维护和实用协议结合使用，用于在本地网段上寻找支持这些服务的机。子网地址指向子网内的所有主机，通过将子网划分地址的主机部分替换为全 1 来形成。最后，通过将 IP 地址的主机部分设置为全 1 并忽略任何子网掩码，可以对整个网络。注意，这会将全 1 子网地址留用于广播。
