# 引言

本章将介绍安装任何 Linux 发行版时需要了解的基础概念，并将专门使用来自 RedHat 安装的特定示例。

Linux 发行版通常提供大量的工具和产品；你必须决定哪些是你需要的，哪些不需要。许多发行版还包含一个免费版或演示版的数据库服务器。

Linux 也是许多网络和生产力服务的服务器，因此在计划安装之前，你必须决定如何使用这台服务器。通常情况下，你可以运行任何以下服务：动态主机配置协议 (DHCP)、域名服务器 (DNS)、Web、ftp、像 Oracle 这样的数据库产品（大多数发行版不提供），以及 Postgres (SQL) 服务器（某些 Linux 版本提供的免费版）。你可以在单台物理机上运行所有这些服务，也可以将它们分布到你想要的任何组合机器上。

> **注意：** 本章中的截图是在使用 VMware 在宿主机 NT 4.0 上安装 Linux 时获取的。这些截图仅用于说明；请注意，图 2.2、图 2.3 及后续图片中的标题栏在安装过程中不会出现。

自然地，强烈建议为你的数据库准备一台独立的服务器。这可以提供最佳响应速度、安全性和可靠性。大多数常见的数据库应用程序设计都非常复杂，并且非常消耗 CPU 和磁盘资源。你不希望你的数据库服务器与任何其他服务（例如 web、ftp、文件和打印）竞争 CPU 周期或磁盘系统中的文件，因为这从总体上会极大降低所有服务的整体性能。

通过分离数据库服务，你能够更安全地保护系统免受入侵，并保持数据及其备份与其他进程完全隔离且不受干扰。系统攻击的常见类型大多位于标准网络服务中。如果你将这些服务保留在另一台机器上，入侵者就不可能访问你的数据库服务器。即使这些系统之间的管理密码也应该不同，以增加针对攻入你网络中其他服务器的入侵者的额外安全性。

接下来要考虑的是使用哪个版本的 Linux 发行版。有很多供你选择；它们可能在某种程度上支持任何在 Linux 上认证的数据库，但更商业化的版本可能已经有了支持服务，或者已经与数据库产品公司建立了联盟。RedHat 支持许多数据库厂商的产品，如 Oracle，以及来自 Dell、Compaq 和 IBM 等硬件厂商的产品。

设计你的项目时应该考虑到每一个步骤。在本节中，你将接触在开始安装位置之前应该规划的一些基础主题。这包括你现在和未来所需的性能水平，并将引导你在实际安装之前的硬件和软件决策。

服务器最关键的部分是后续几节中概述的各种硬件方面。无论你决定使用什么操作系统，这一点都是的。

尽管在如今家用电脑廉价的时期这听起来很奇怪，但著名服务器供应商之所以规模大，是因为他们高端服务器确实如此——专为 24x7 全天候运行而设计，具有故障转移功能以及易于维护和服务的特性。在这一点上，我需要花时间获取一台能够处理长时间高 I/O、同时运行大量进程、在磁盘与内存、内存与 CPU 之间移动大量数据、保持大部分内存驻留，并具有某种形式硬件 RAID 以应对故障转移备用情况的机器。确保你的新系统可以在磁盘控制器、磁盘驱动槽和内存区域轻松扩展。

数据库服务器需要大量的 CPU 功率。廉价的处理器可以并行运行，以提供惊人的吞吐量和峰值负载。虽然你无法获得每个额外 CPU 的 100% 性能，但保持所有功能都在额外好处就是 CPU。

# 备份问题

磁带机的容量每个月都在增大。一个优秀的但基础的单带备份设备最多只能备份约 80 GB。为了冗余和速度，请至少获取 2GB 的设备。其他磁带驱动器还有很多选择；例如 DDS-3 和 Jazz 磁盘，它们在成本略高的情况下，可能提供比磁带更好的的可用性。你还可以选择最新的磁盘管理系统，它可以提供将数据从高需求 RAM 磁盘迁移到中需求磁盘驱动器，再到低需求 CD-ROM 或 Jazz 类型磁盘，最后到极少归档的层级，而这一切在你的机器或服务器看来都落在一个大系统中。磁带是传统方式，但你可以购买两个 Jazz 磁盘，或者购买另一个 6-10GB 的磁盘驱动器（这种容量正在不断增长），后者的恢复时间要长得多。将这些磁盘安装在另一台服务器上并作为备份介质——备份快、恢复快，而且更便宜。如果另一台服务器在异，取决于距离，你还拥有内置的灾难恢复能力。在继续之前检查所有选项，记住恢复时间是你决策中一个真正重要的考虑因素。
