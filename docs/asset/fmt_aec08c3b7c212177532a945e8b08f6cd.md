
其中的几个例子是围绕 Perl 和用于软件版本控制的并发版本系统（CVS）的社区。CVS 在开源社区中吸引了相当多的追随者。由于几乎所有的 CVS 命令都可以在脚本中使用，许多工具和插件应运而生，以新颖且有趣的方式它们组合在一起。CVS 的原始作者绝没有预测到会有这些用途。

CVS 在设计上避免了图形用户界面（GUI）。每个 CVS 命令都可以通过传递适当的参数从命令行运行。这有助于 CVS 插件的涌生。基础的 CVS 命令，如 `checkout`、`update` 和 `commit`，构成了许多旨在增强 CVS 的集成工具的基础。使用这些命令创建的各种插件工具通常具有 GUI。但基础的 CVS 命令没有。这是 CVS 繁荣的主要原因之一。

Perl 作为一种开源脚本工具已经获得了巨大的声誉。它比常见的 Unix Shell（如 Bourne shell 和 Korn shell）更强大，擅长与其他软件进行接口交互。几乎所有的 Perl 程序都充当着过滤器的角色。事实上，它的全称“实用提取报告语言”（Practical Extraction Reporting Language）告诉我们，Perl 的设计初衷就是这个目的。当一个程序从某处提取信息、对其进行修改并进行报告（即“输出”）它时，它就履行了过滤器的角色。

Perl 的普及也归功于它的扩展性（在词义的褒义意义上如此）。它在这个“大杂烩”式的语言池中发现了一个真正的游乐场，并继续添加所有库来适应各种情况。今天，你可以找到一个 Perl 模块来处理从复杂的数学、数据库开发到面向万维网的 CGI 脚本的任何问题。

意料之中，Perl 是 Unix 哲学中“差之优”这一次要原则的闪光范例——并有力地证明了更差的东西（例如 Perl）通常比更好的东西（例如 Smalltalk）具有更好的生存特性。很少有人会认同 Perl 是一种语法古怪且糟糕的语言的观点。而更少的人会认为 Perl 的成功不是疯狂的。

到此为止应该显而易见，开源软件遵循 Unix 哲学的频率往往高于其本身。开源软件适用于“集市式”（bazaar）开发风格，这种风格早期的 Unix 开发者这样称，而今天的 Linux 开发者则热烈地拥抱它。虽然 Unix 哲学关注设计方法，但来自开源社区的大部分辞藻强调的是软件开发过程。Unix 哲学与开源开发过程的结合是一场天作之合，用一句老生常谈来说，它们相得益彰。

开源社区取得重大进展的一个领域是营销。在当今竞争激烈的计算世界中，仅仅根据健全的设计原则生产高质量软件是不够的。你必须告诉人们你确实了。你可以拥有世界上最好的产品，但如果没有人知道你的产品，无论它有多好都没有意义。它将淡入无几，或者作为多年未被的遗迹而凋零。

许多 Unix 程序因为缺乏稳健的营销而消失了。如果我能记得的话，我可以列举其中几个。明白意思了吗？

微软充分理解了稳健营销的价值，可能比迄为止的任何其他公司都要得好。这是该公司如此成功的主要原因。微软生产了许多热门应用，但它的优势主要在于能够说服所有人它的软件是地球上最好的，无论质量如何。

我对微软软件的主要意见是，它们是在“大教堂式”（cathedral-fashion）的闭源环境中开发的。微软拥有一些非常有才的人，他们写了一些很好的软件。但微软并没有在技术创新上点亮全球。世界上其他地方有很多才华的人并不为微软工作，他们也写了一些非常好的软件。由于他们的教堂式开发风格，微软开发者将自己与其他隔离开来。

他们无法从软件杠杆作用中充分受益，因为他们没有分享任何可以增强并回给他们的东西。大多数 Windows 操作系统的创新是由微软开发者完成的，因此受到他们视野的限制。而开源开发者拥有庞大的开源开发社区可以汲取灵感。从纯规模来看，开源开发社区远超微软的内部开发社区。而且这一点——尽管微软有卓越的营销努力——最终将成为微软的失败之源。

在写作此时，Linux 社区（据传拥有超过一百万开发者）开始逃避桌面环境，桌面环境被认为是微软的堡垒，并被任何局外人士认为不可攻破。在短短 18 个月内，Gnome（一种 Linux 上流行的类 Windows 应用环境）的开发者就让 Linux 从 Unix 命令行用户界面提升到了几乎拥有 Windows 95 的能力。而微软花费了五个五年才完成从 MS-DOS 到 Windows 3.1 再到 Windows 95 的同等跨越。

大教堂？太不可思议了！

在某个时刻，每个人都必须决定是否信任用于保护信息的软件生产商。每个人都必须对软件提供者做出自己的道德和伦理判断。这真的可以信赖吗？当你的财务、声誉或国家安全面临风险时，唯一可以接受的解决方案是那种让你能够验证到软件最后一行代码的解法。

在我们所处的世界中，既有开放社会，也有封闭社会。封闭社会的运行方式非常像“大教堂式”开发环境，源代码由少数特权人士掌握，由他们来决定保留哪些内容、排除哪些内容。在这些社会中，新思想的传播非常缓慢。而开发出跟上新威胁出现速度的有效安全机制则需要数年时间。

这个世界的开放社会，如 OSS（开源软件）社区，看似混乱，但又充满了大胆的想象力。创造力没有界限。新技术（尤其是安全技术）的想法以疯狂的速度不断涌现。开放社会通过创新想法做出快速响应的能力，确保了没有任何威胁能长期保持威胁状态。就像 Unix 密码算法的开发者一样，他们保持脆弱性的意愿最终将他们引向最高级别的安全。

## 12 勇敢新（Unix）世界

> 一张不包含乌托邦的世界地图甚至不值得看一眼。
> ——奥斯卡·威尔尔德

如果你听听今天大多数软件公司的营销信息，你会发现每家公司都推崇通往软件乌托邦的特定路径：“我们的解决方案整合了系统”；我们的流程加速了开发周期”；我们的图形用户界面让你快速上手；以更低的成本运行数据库应用程序”。毫无疑问，他们花费了无数小时和巨额资金来为自己的方法寻找合理性。他们的论点听起来是非常有说服力。而且许多人为了传播信息所砍掉的树比我们为了住房推平的森林还要多。

我不是预言家，但我有一个简单的观察。Unix 操作系统及其配套的哲学已经存在了 25 多年。在一个创新速度不断加速的行业中，单一系统设计和软件架构方法能持续如此久，是最不寻常的。它不仅经受了成千上万百万批评者的风暴，而且持续繁荣，并在今天依然在取得进展。事实上，作为 Unix 的最新化身，Linux 在不久的将来将压倒全球最大的软件垄断。

大约 10 年前，计算机世界发生了一场大范式转移。20 世纪 60 年代初，主机计算牢固地根植于各地的计算机实验室。然后，70 年代，微机和分时共享产生了第三代硬件的黄金时代。80 年代见证了图形用户界面的出现，并种下了人们可以将计算机视为个人物品的观念。90 年代，我们见证了个人电脑的商品化以及随着互联网和万维网兴起的全球网络化。在新千年里，我们正经历着大规模的去中心化、大规模定制以及与一种被称为“开源”的行业现象的前所未有的合作。

有趣的是，Unix 不仅是这些范式转移的一部分，它实际上充当了大部分转移的催化剂。从微机开始，Unix（有些人可能会说像癌症一样！）扩散了整个计算世界。在 Unix 上开发的 X Window 系统是第一个大规模普及的图形应用平台。首次运行在 Unix 上的 Apache Web 服务器成为了互联网上领先的 Web 服务器。Linux 作为一种用于个人电脑的无限制 Unix 实现，其吸引力动员了庞大的程序员军团，他们致力于让重要的软件应用免费提供给所有人。

每一次范式转移都为及早察觉到事物发生根本性变化的资源个人和公司创造了机会浪潮。最先感应到范式转移的人往往能最好地顺势而为。过去和现在的 Unix 追随者们对这种动摇世界的变革保持着开放态度。

尽管 Unix 及其哲学追随者在重大技术进步发生时一直处于尖端，但有些人会声称 Unix 甚至 Linux 都是过时的、陈旧的技术，随着当年的微机一起消失了。他们说，外面是一个勇敢的新世界。这是一个 GUI（图形界面）世界。这是一个网络世界。这是一个商品世界。这是一个无线世界。

但实际上，这是一个 Unix 世界。因为 Unix 证明了它具有适应任何出现事物的惊人能力。当人们说除了业务服务器之外的任何设备上运行它都太贵时，Lin Torvalds 的 Linux 证明了他们是错。当人们说它在桌面端无法与微软 Windows 竞争时，基于 Linux 的 KDE 开发者看到了这样的挑战。而且——这是我最喜欢的——虽然许多人认为 Windows 是比 Linux 更好的平台，但我指出，早在游戏先驱雅达出售其第一台游戏机之前，人们就在 Unix 上运行游戏了。

因此，随着技术竞赛的持续，Unix 哲学将继续是一个驱动力，不仅在操作系统设计中，在其他创新领域也是。在本章中，我们将探讨 哲学是如何进入其他项目、技术、方法论和设计方法的。这些技术中的许多都声称带来了某种涅槃或软件乌托邦的子集。如果他们想以此获得关注，那是他们做出此类声明的权利。至少我们意识到了这一点。这些努力中的许多对我来说都充满了迷之处，要么是因为它们成就了什么，要么是因为它们所承诺的未来。
