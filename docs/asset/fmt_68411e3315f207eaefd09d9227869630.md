
## Description

`javac` 命令将 Java 源代码编译成 Java 字节码，这些字节码可以由 `java(1)` 解释器解释。

Java 源代码必须包含在以 `java` 扩展结尾的文件中。如果类是公共的，或从另一个源文件引用，则文件必须根据类名构建，即 `classname.java`。

对于由 `javac` 编译的每个源文件中定义的每个类，编译器都会将生成的字节码存储在命名为 `classname.class` 的类文件中。除非你指定了 `-d` 选项，否则编译器会将每个类文件放在与源文件相同的目录中。

当编译器必须引用自己的类时，你必须使用 `-classpath` 选项或 `CLSPATH` 环境变量来指定它们的位置。类路径是一系列目录（或文件），`javac` 在这些路径中搜索直接作为命令行参数指定的任何文件中已定义的类。编译器会在类路径中同时查找源文件和类文件，如果源较新，则重新编译源（或重新生成类文件）。

将属性 `javac.pipe.output` 设置为 `true` 以将输出消息发送到 `System.out`；将 `javac.pipe.output` 设置为 `false`（即不设置）以将输出消息发送到 `System.err`。

`javac_g` 是 `javac` 的非优化版本，适用于配合 `jdb(1)` 等调试器对 `javac` 本身进行调试。使用 `javac_g` 等同于使用命令 `javac -g`。

# Options

- `-classpath path`
指定一个用冒号分隔的目录列表作为路径，用于查找运行 `javac` 需要的类，或通过你正在编译的其他类查找记录。如果设置了默认或 `CLSPATH` 环境变量，则覆盖它。将包含源文件的目录放在类路径上通常很有用。始终将系统类放在路径末尾。例如：

```
% javac -classpath :/home/avh/classes:/usr/local/java/classes ...
```

- `-d directory`
指定类文件层次结构的根目录。换句话说，为你的编译类指定目标目录。例如：

```
% javac -d /home/avh/classes MyProgram.java
```
将 `MyProgram.java` 源文件中类的编译类文件保存到目录 `/home/avh/classes/demos/awt/` 中。如果类定义在包 `demos/awt` 中，则类被放置在 `/home/avh/classes/demos/awt` 目录下。

- `-depend`
让编译器考虑重新编译从其他类文件引用的类文件。如果没有此选项，只会重新编译源代码引用的缺失或过时的类文件。

对每个弃用（deprecated）成员或类的每次使用或覆盖生成警告。如果一个成员或类的文档注释中包含 `@deprecated` 标签，则该成员或类即为弃用。无论是否使用 `-deprecation`，编译器都会在编译结束时显示警告；此选项标记了每个单独使用或覆盖的位置。

在重新编译包含弃用信息的源文件中，被弃用的成员或类不会刻意提及。这可能是因为文件在命令行中，或者因为你使用了 `-depend` 且源文件已过期。

- `-encoding encoding-name`
指定源文件编码名称，例如 `EUC JIS/SJIS`。否则，使用平台默认转换器。

- `-g`
启用生成调试表。调试表包含 Java 调试工具使用的行号和局部变量信息。默认情况下，只生成行号，除非你开启优化 `-O`。

- `-Jjavaoption`
将 `javaoption` 字符串作为单个参数传递给运行编译器的 `java(l)` 解释器。该参数不应包含空格。多个参数单词以 `-J` 前缀开头，该前缀会被剥离。此选项对于调整编译器的执行环境或内存使用有用。

- `-nowarn`
关闭警告。编译器尝试通过内联静态、final 和私有方法来生成更快的代码。此选项可能会减慢编译速度，使类文件变大，并/或增加调试难度。`-0` 会隐式关闭 `-depend` 并关闭 `-g`。

此选项告知编译器，所有生成的类文件都保证作为一个单元交付和升级，从而启用可能可能破坏二进制兼容性的优化。请谨慎使用。

- `-verbose`
打印编译器和链接器关于正在编译哪些源文件以及加载了哪些类文件的消息。

> Note 注意 — `-d` 和 `-classpath` 选项具有独立的影响。编译器仅从类路径读取并写入目标目录。将目标目录放在类路径上通常很有用。如果你不指定 `-d` 选项，源文件应该存储在反映包结构的目录层次中，以便生成的类文件可以被易于找到。

Java 语言规范第 13.4.21 节描述了可以使用 Java 编译器内联方法的情况。编译器仅对编译期间的源码进行优化，因此编译器可以发现的唯一 `.java` 文件是作为单元交付的类。

# javadoc — Java API 文档生成器

### Synopsis

```
/usr/java/bin/javadoc [-author] [-classpath path] [-d directory]
-d] [-encoding name] [-encoding name] [-J flag] [-nodeprecated]
-noindex] [-notree] [-package] [-private] [-protected] [-public]
-sourcepath path [-verbose] [-version][package | source.java]*
```

## Description

`javadoc` 解析 Java 源文件的类和文档注释，并生成一组描述公共和保护类、接口、构造函数、方法和字段的 HTML 页面。作为参数传递一系列 Java 包名或源文件。

`javadoc` 为每个 `.java` 文件和遇到的每个包生成一个 `.html` 文件。此外，它还会产生类层次结构 `tree.html` 和这些成员的索引 `AllNames.html`。

当 `javadoc` 解析类和成员声明时，它会获取签名以便包含。你可以通过在源代码中包含文档注释来添加更多文档。

# Commenting the Source Code

你可以在源代码中包含文档注释。文档注释由开始注释的 `/**` 和结束注释的 `/*` 之间的字符组成。文本被分为行或多行，每行以星号 `*` 开头。当 `javadoc` 解析文档

注释，它会忽略每行开头的 `**` 字符。对于第一行以外的行，它会忽略初始 `*` 字符之前的空格和制表符。这些注释可以包含 HTML 标签。这里是一个文档注释的示例：

```java
/**
 * This is a b>doc</b> comment.
 */
```

将每个文档注释的第一句作为总结句，包含对所声明实体的简洁描述。该句结束于第一个后续跟着空格、制表符或行终止符的句号，或者第一个标签（下文定义）处。`javadoc` 会将第一句复制到 `.html` 文件顶部的成员摘要中。

文档注释只有在直接放置于类、接口、构造函数、方法或字段声明之前时，才会被识别。

在文档注释中嵌入 HTML 标签时，请勿使用 `<h1>` 和 `<h2>` 等标题标签，因为 `javadoc` 会创建一个完整的结构化文档，而这些结构性标签会干扰生成文档的格式。

有关文档注释的规范，请参阅 James Gosling、Bill Joy 和 Guy Steele 编写的《Java 语言规范》第 18 章“文档注释”。

# 标记标记段落

`javadoc` 解析嵌入在 Java 文档注释中会被识别的特殊标签。这些文档标签允许你从源代码自动生成一个完整的、格式良好的 API。这些标签以 `@` 符号开头。

标签必须在行首开始。在文档注释中，将同名的标签保持在一起。例如，将所有 `@author` 标签放在一起，以便 `javadoc` 能够判断列表的结束位置。

标签分为三类：

- 类和接口标签。
- 字段标签。
- 构造函数和方法标签。

接下来的章节将详细描述每类标签。
