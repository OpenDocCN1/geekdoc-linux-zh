# 流程控制：使用 FOR 循环

![](img/0cf46e6370424e4fc9bc72ba090b1e02_444_0.png)

在关于流程控制的最后一个章节中，我们将查看 shell 的另一种循环结构。`for` 循环与 `while` 和 `until` 循环的区别在于，它提供了一种在循环期间处理序列的方法。这在编程中证明非常有用。因此，`for` 循环是 bash 脚本中一种常用的结构。

`for` 循环的实现自然是使用 `for` 复合命令的。在 bash 中，`for` 有两种形式。

## for：传统的 Shell 形式

原始 `for` 命令的语法如下：

```bash

for variable [in words]; do

  commands

done

```

其中，`variable` 是变量名，它在循环执行期间会递增；`words` 是一个可选的项目列表，将按顺序赋值给 `variable`；`commands` 是循环每次迭代中要执行的命令。

`for` 命令在命令行上非常有用。我们可以很容易地演示它的工作原理。

```bash

[me@linuxbox ~]$ for i in A B C D; do echo $i; done

A

C

D

```

在这个示例中，`for` 被给了一个包含四个单词的列表：A、B、C 和 D。有了四个单词，循环执行了四次。每个单词都被赋值给变量 `i`。在循环内部，我们有一个 `echo` 命令来显示 `i` 的值以展示赋值。与 `while` 和 `until` 循环一样，`done` 关键字完成了循环。

`for` 真正强大的特性之一是创建单词列表的有趣方式之一。例如，我们可以通过大括号扩展（brace expansion）来完成，如下：

```bash

[me@linuxbox ~]$ for i in {A..D}; do echo $i; done

A

C

D

```

或者我们可以使用路径名扩展（pathname expansion），如下：

```bash

[me@linuxbox ~]$ for i in distros*.txt; do echo "$i"

distros-by-date.txt

distros-dates.txt

distros-key-names.txt

distros-key-vernums.txt

distros-names.txt

distros.txt

distros-vernums.txt

distros-versions.txt

```

路径名扩展提供了一个漂亮、干净的路径列表，可以在循环中进行处理。唯一需要预防的是是检查扩展是否匹配了内容。默认情况下，如果扩展没有匹配到任何文件，则扩展本身会被返回。为了防止这种情况，我们可以像这样编写脚本：

```bash

for i in distros*.txt; do

  if [[ -e "$i" ]]; then

    echo "$i"

  fi

done

```

生成单词的另一种常用方法是命令替换（command substitution）。

```bash

#!/bin/bash

# longest-word: 在文件中查找最长字符串

while [[ -n "$1" ]]; do

  if [[ -r "$1" ]]; then

    for i in $(strings "$1" | wc -c); do

      if (( i > max_len )); then

        max_len="$i"

        max_word="$i"

      fi

done

```

在这个示例中，我们在文件中查找最长的字符串。当在命令行上给出一个或多个文件名时，程序会依次处理每个文件并判断当前单词是否为为止为止长的。当循环完成后，将显示最长的单词。这里需要注意的是，与我们通常的做法不同，我们没有将命令替换包在双引号中，因为我们实际上希望进行单词拆分。

```bash

return

}
```

# 字符串与数字

计算机程序的核心在于处理数据。在之前的章节中，我们专注于关注文件层级的数据处理。然而，许多编程问题需要使用字符串和数字等更小的数据单元来解决。

在本章中，我们将查看几种用于处理字符串和数字的 shell 特性。shell 提供了多种执行字符串操作的参数扩展。除了算术扩展（我们在第 7 章中提到过）外，还有一个名为 `bc` 的常用命令行程序，它可以执行更高级数学运算。

## 参数扩展

虽然参数扩展在第 7 章出现过，但我们没有进行详细介绍，因为大多数参数扩展是在脚本中而非命令行中使用的。我们已经处理过某些形式的参数扩展，例如 shell 变量。shell 提供了更多扩展。

始终良好的做法是将参数扩展包围在双引号中，以防止意外的单词拆（word splitting），除非有特定的理由不这样做。这在处理文件名时尤为如此，因为文件名通常包含嵌入空格和各种复杂的字符。

### 基础参数

参数扩展的最简单形式体现在变量的普通使用中。这里有一个例子：

```
$a
```

扩展后，它将变为变量所包含的内容。简单参数也可以用大括号包围。

```
${a}
```

这对扩展没有影响，但如果变量紧邻其他文本，则是必须的，否则可能会混淆 shell。在这个示例中，我们尝试通过在变量 `a` 的内容后面附加字符串 `_file` 来创建一个文件：

```
[me@linux ~]$a="foo"
[me@linux ~]$ echo "$a_file"
```

如果我们执行这一系列命令，结果将是为空，因为 shell 会尝试扩展名为 `a_file` 的变量，而不是 `a`。这个问题可以通过在“真实”变量名周围添加大括号来解决。

```
[me@linux ~]$ echo "${a}_file"
foo_file
```

我们还看到，大于9的位置参数可以通过在大括号中包围数字来访问。例如，要访问第11个位置参数，我们可以这样做：

```
${11}
```

### 管理空变量的扩展

几种参数扩展旨在处理不存在和空变量。这些扩展对于处理缺失的位置参数以及为参数分配默认值非常有用。这里有一个扩展：

```
${parameter:-word}
```

如果 `parameter` 未设置（即不存在）或为空，则该扩展的结果为 `word` 的值。如果 `parameter` 不为空，则扩展的结果为 `parameter` 的值。

```
[me@linuxbox ~] foo=
[me@linuxbox ~] echo ${foo:-substitute value if unset}
substitute if unset
[me@linuxbox ~] echo $foo
```
