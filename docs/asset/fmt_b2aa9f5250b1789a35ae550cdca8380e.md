
`mv myfile.txt html`

（我假设非标准字符位于字母 e 和 y 之间。）

作为在文件名中使用不推荐字符可能面临的某些奇怪问题的示例，创建一个以连字符开头的文件然后删除它——似乎没有办法这样做（因为连字符通常会引起命令选项）。例如，

`dir -junk`

这将创建一个奇怪的文件（就像在 DOS 中，符号 `>` 将它们的输出重定向到名为 "junk" 的文件中）。由于删除 `-junk` 的常规方法无效，我使用：

`rm ./junk`

点斜杠表示“当前目录”，在这里起到隐藏前导连字符的作用，使其不被解释为 `rm` 命令的选项。观点是，我宁愿遵循传统的命名规范，而不是面临偶尔的麻烦。

除了使用自动补全、单引号和双引号，我还可以处理具有奇怪名称的文件。反斜杠对后续字符具有特殊含义。例如，我可以使用以下命令创建一个名为 `\*?` 的文件：

`touch \*?`

（`touch` 命令创建一个空文件，如果文件已存在，则更新其最后修改日期。）

## 4.1.2 不同的目录是做什么用的？

Linux 系统庞大且复杂。熟悉它将极大地提升你的技能。

简而言，典型的 Linux 包含五个文件系统。根据系统的大小和需求，这些文件系统可以存在于单个物理硬盘和/或硬盘分区上。（如果需要，单个文件系统也可以分布在不同的物理设备之间。）

`/root` 文件系统包含基础操作系统和维护工具。该文件系统的内容应该被保留，以便启动系统并在必要时执行紧急维护和修复。

`/usr` 包含所有命令、库、文档以及在正常运行期间不会更改的文件。它还包含随你的 Linux 发行版自带的主要应用程序，例如 Netscape。

`/var` 包含发生变化的文件：打印队列目录、日志文件、锁文件、临时文件和格式化后的手册页。

`/home` 包含用户的文件（用户所有权、自定义文件、数据、元数据、缓存等）。每个目录都有在操作系统升级时保留的选项。

`/proc` 包含虚拟文件。它们实际上并不存在于磁盘上，也不占用任何空间（尽管 `ls -l` 会显示它们的大小）。在查看它们时，你实际上是在访问存储在内存中的信息。它用于访问有关系统的信息。

根文件系统的各个部分如下：

- `/bin`：可执行文件（启动期间需要），可能被普通用户使用。
- `/sbin`：可执行文件（系统二进制文件），不供普通用户使用（用户仍可以使用它们，但该目录不在 `PATH` 中）。
- `/etc`：操作系统的宽泛配置文件。
- `/root`：系统管理员（称为超级用户或 `root`）的主目录。
- `/dev`：设备。在 Linux 中访问设备是因为硬件被抽象化，易于写入或读取。
- `/mnt`：可移动介质（软盘、CD-ROM、Zidrive）、其他操作系统的分区（例如 MS Windows）、网络共享以及任何其他临时挂载到文件系统上的挂载点。它通常为每个挂载共享包含一个子目录。这些子目录中的驱动器/共享的内容——Linux 上没有驱动器。
- `/lib`：位于根文件系统上的程序所需的库和内核模块。
- `/boot`：引导加载程序（`LILO`）使用的文件，它是计算机启动时加载的内容，如果你在电脑上有多多个操作系统，它会提供启动哪个操作系统的选项。它还包含内核（压缩的 `vmlinuz`），`LILO` 也配置在此处以知道内核的位置。
- `/opt`：大型应用程序。
- `/tmp`：临时文件。此目录可能会自动清理。
- `/lost+found`：从文件系统修复中恢复的文件。

`/usr` 文件系统最感兴趣的部分是：

- `/usr/X11R-X`：窗口系统（版本 11，发布 6）。
- `/X11`：与 `/usr/X11R` 相同（它是指向 `/usr/X11R` 的符号链接）。
- `/X11R6/bin`：小型 Windows 应用程序的链接，可能指向位于其他子目录中的某些大型窗口应用程序执行文件的符号链接。
- `/usr/share`：来自你计算机架构的数据输入，例如字典。
- `/usr/bin` 和 `/usr/sbin`：类似于根文件系统中的对应项（`bin` 和 `sbin`），基础启动（紧急维护期间）不需要。大多数命令将驻留在此处。

`/usr/local/bin`：本地管理员安装的应用程序（可能每个应用程序都在一个子目录中）。在“主”安装后，该目录是空的。此目录的内容在操作系统的正常重新安装或升级时应当保留。

`/usr/local/bin` 包含用户安装的可执行文件，以及指向 `local` 下独立目录中较大可执行文件的公共符号链接。

重要的是，所有目录都在单一的目录树中，即使这些目录位于不同的分区、驱动器（包括软盘等），或分布在网络上。因此，Linux 下没有 DOS 类型的“驱动器号”。在 DOS 或 MS Windows 下称为“驱动器”的东西，在 Linux 上表现为“挂载”位置下的一个子目录。

目录系统在大多数 Linux 发行版中都是完善且标准的（目前的差异正通过 Linux 标准基础进行解决）。它也与典型的商业 UNIX 系统非常相似。

- 用户将文件保存到 `/home/user/login_name`（及其子目录）中。
- 本地管理员可能将“额外”软件安装在 `/usr/local` 目录下，并在 `/usr/local/bin` 中创建指向主可执行文件的链接。
- 系统设置都在 `/etc` 目录中。
- 除非我确切知道做什么，否则不要动根目录（`/`）或 `/usr` 目录的内容。这些目录最好保持与我的 Linux 发行版自带的状态。

- 所有文件都在单一目录树中。没有驱动器号。

## 4.1.3 关于 `/proc` 文件系统的更多信息

`/proc` 文件系统是一个伪文件系统。它是内核的接口，提供有关系统状态的信息。它用于访问有关系统的信息。

`/proc` 文件系统的各个部分如下：

- `cmdline`：启动进程使用的命令行参数。
- `cwd`：进程的当前工作目录。
- `environ`：进程定义的环境变量。
- `fd`：进程打开的文件描述。
- `maps`：进程的内存映射。
- `lost+found`：从文件系统修复中恢复的文件。
- `meminfo`：关于内存使用的信息。
- `netdev`：关于网络接口的信息。
- `mounts`：关于挂载文件的信息。
- `partition`：关于分区分区的信息。
- `process`：关于进程的信息。
- `status`：关于进程状态的信息。
- `uptime`：系统运行了多久。
- `stat`：关于进程状态的信息。

`/proc` 文件系统最感兴趣的部分是：

- `atime`：文件最后访问的时间。
- `ctime`：inode 最后更改的时间。
- `mtime`：文件最后修改的时间。
- `birth`：文件创建的时间。
- `size`：文件的字节大小。
- `blocks`：文件使用的块数。
- `inode`：文件的 inode 节点。
- `link`：文件的硬链接数。
- `device`：文件的设备 ID。
- `type`：文件的类型。

## 4.1.4 我如何运行程序？

如果你想运行一个程序，有两种选择：

1. 如果程序在 `PATH` 中，你可以直接输入它的名称。
2. 如果程序不在 `PATH` 中，你必须指定可执行文件的完整路径。

要检查程序是否在 `PATH` 中，可以使用 `which` 命令：

```bash
which netscape
```

要查看 `PATH` 的内容，可以使用 `echo` 命令：

```bash
echo $PATH
```

如果你想将一个目录添加到 `PATH` 中，可以使用以下命令：

```bash
export PATH=$PATH:/path/to/your/directory
```

要使此更改永久生效，你应该将该行添加到你的 shell 中，例如 `.bashrc` 或 `.bash_profile`。
