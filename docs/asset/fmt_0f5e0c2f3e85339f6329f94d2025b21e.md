
事实上，这正是 `make` 在看到以 `'.a'` 为目标后缀的后缀规则时所做的事情。任何双后缀规则 `*.x.a` 都会被转换为目标模式为 `%.o` 前提模式为 `%.x` 的模式规则。

由于你想将 `*.a` 作为其他类型文件的后缀，`make` 也会以正常方式将存档规则转换为模式规则（参见第 10.7 节 [后缀规则](Suffix Rules)，第 117 页）。因此，双后缀规则 `*.x.a` 会产生两个模式规则：'`%.o: %.x`' 和 '`%.a: %.x`'。

# 第 12 章：GNU make 的特性

## GNU make 的特性

以下是 GNU make 功能的总结，用于与其他版本的 make 进行比较和致谢。我们以 4.2 BSD 系统中的 make 功能作为基准。如果你担心编写可移植的 makefile，则不应使用此处列出的 make 功能，也不包括第 13 节 [缺失](Missing)，第 129 页中的功能。

- 以下功能灵感源于不同版本的 make：

  - 使用 `%` 的模式规则。这在多个版本中均已实现。我们不确定是谁发明的，参见第 11.2 节 [存档更新](Archive Update)，第 121 页。
  - 自动变量 `$^` 包含当前目标所有前提的列表。我们没有发明它，但不知道是谁发明的。参见第 10.5 节 [自动变量](Automatic Variables)，第 111 页。
  - 自动变量 `+` 是 `$` 的简单扩展。
  - 同时做几件事的概念（并行性）存在于 make 的许多版本中，但在 System V 或 BSD 的实现中没有。参见第 5.2 节 [命令执行](Command Execution)，第 41 页。
  - 使用模式替换的修改引用源于 SunOS 4。参见第 6.1 节 [变量引用基础](Basics of Variable References)，第 55 页。该功能在 GNU make 中通过 `patsub` 函数提供，在为了兼容 SunOS 4 实现备选语法之前。由于目前还不完全清楚是谁的灵感启发了谁，因为 GNU make 在 SunOS 4 发布之前就已经有了 `patsub`。
  - 命令行行前的 `+` 字符的特殊意义（参见第 9.3 节 [执行命令](of Executing Commands)，第 91 页）由 IEEE 标准 1003.2-1992 (POSIX.2) 强制规定。
  - 用于追加变量值的 `=` 语法源于 SunOS 4。参见第 6.6 节 [追加文本](Appending Text to Variables)，第 63 页。
  - 在单个文件中列出多个成员的 'archive (mem12...)' 语法源于 SunOS 4 make。参见第 11.1 节 [成员](Archive Members)，第 121 页。
  - `--include` 指令在文件不存在时包含 makefile 源于 SunOS 4 make。（但注意 SunOS 4 不允许在一个 --include 中指定多个 makefile。）

- 剩余功能是 GNU make 的发明：

  - 使用 `-v` 或 `--version` 选项打印版本和版权信息。
  - 使用 `-h` 或 `--help` 选项总结选项。
  - 简单展开变量。参见第 6.2 节 [变量的两种类型]，第 56 页。
  - 通过变量 `MAKE` 自动将命令行变量赋值传递给递归 make 调用。参见第 5.6 节 [make 的递归使用]，第 46 页。
  - 使用 `C` 或 `directory` 命令行选项来切换目录。参见第 9.7 节 [选项摘要]，第 95 页。
  - 使用 `define` 创建逐字定义的变量定义。参见第 6.8 节 [逐字定义变量]，第 65 页。
  - 使用特殊目标 `.PHONY` 声明伪目标。

    AT&T Bell 实验室的 Andrew Hume 在他的 mk 程序中引入了具有不同语法的功能。这似乎是一个并行发现的案例。参见第 4.4 节 [伪目标]，第 27 页。
  - 通过调用函数处理文本。参见第 8 章 [用于转换文本的函数]，第 75 页。
  - 使用 `o` 或 `--old-file` 选项假装文件的修改时间为旧时间。参见第 9.4 节 [避免重新编译文件]，第 93 页。
  - 条件执行。

    此功能已在 make 的各个版本中实现过多次；它似乎是源自 C 预处理器和类似宏语言特性的自然扩展，而不是一个革命性的概念。参见第 7 章 [Makefile 的条件部分]，第 69 页。
  - 为包含的 makefiles 指定搜索路径。参见第 3.3 节 [其他 Makefiles]，第 12 页。
  - 使用环境变量指定要读取的 makefiles。参见第 3.4 节 [MAKEFILES 变量]，第 13 页。
  - 去除文件名开头的 `'.'` 或 `'/'` ，使得 `'./file'` 和 `'/file'` 被视为同一个文件。
  - 对于写在文件 `'-name'` 中的库先决项使用特殊的搜索方法。参见第 4.3.6 节 [链接库的目录搜索]，第 26 页。
  - 允许后缀规则的后缀（参见第 10.7 节 [旧式后缀规则]，第 117 页）包含任何字符。在 make 的其他版本中，它们必须以 `'.'` 开头且不包含任何 `'/'` 字符。
  - 使用变量 `MAKELEVEL` 跟踪 make 递归的当前级别。参见第 5.6 节 [make 的递归使用]，第 46 页。
  - 在变量 `MAKEMDGOALS` 中提供命令行上的任何目标。参见第 9.2 节 [指定目标的参数]，第 89 页。
  - 指定静态模式规则。参见第 4.10 节 [静态模式规则]，第 34 页。
  - 提供选择性的 vpath 搜索。参见第 4.3 节 [在目录搜索先决项]，第 22 页。
  - 提供计算变量引用。参见第 6.1 节 [变量引用的基础]，第 55 页。
  - 更新 makefiles。参见第 3.5 节 [如何重制 Makefile]，第 14 页。System V make 在此功能上的形式非常有限，因为它会为 makefiles 出 SCCS 文件。
  - 各种新的内置隐式规则。参见第 10.2 节 [隐式规则目录]，第 102 页。
  - 内置变量 `MAKE_VERSION` 给出 make 的版本号。

# 第 13 章：不兼容性与缺失的功能

## 13 不兼容性和缺失的功能

其他各种系统的 make 程序支持一些 GNU make 未实现的功能。指定 make 的 POSIX 2.standard（IEEE 标准 1003.2-1992）并不要求这些功能中的任何。

- 形式为 `'file((entry))'` 的目标代表存档文件 *file* 的成员。该成员的选择不是通过名称，而是通过它是定义链接器符号 *entry* 的对象文件。

  此功能没有被放入 GNU make，是因为将存档文件表内部格式的知识放入 make 中是不符合模块化的原则。参见第 11.2.1 节 [更新存档目录]，第 122 页。
- 以字符 `'-'` 结尾的后缀（用于后缀规则）对 System V make 具有特殊含义；它们指向与不带 `'-'` 的时可以获得的文件相对应的 SCCS 文件。例如，后缀规则 `'.c'` 会从 SCCS 文件 `'s.n.c'` 生成文件 `'n.o'`。为了完全覆盖，需要一系列后缀规则。参见第 10.7 节 [旧式 S 规则]，第 117 页。

  在 GNU make 中，这一系列情况通过两个从 SCCS 提取的规则，结合规则链的通用功能来处理。参见第 10.4 节 [隐式规则链]，第 108 页。
- 在 System V make 中，字符串 `'$$'` 具有奇怪的含义：在具有多个目标的 make 的先决项中，它代表正在处理的具体目标。

  这在 GNU make 中没有定义，因为 `'$$'` 将始终代表一个普通的 `'$'`。

  通过使用静态模式规则可以获得部分功能（参见第 4.10 节 [静态模式规则]，第 34 页）。System V make 规则：

```
$(targets): $$.o lib.a
```

  可以用 GNU make 的静态模式规则替换：

```
$(targets): %.o lib.a
```

- 在 System V make 中，字符串 `'$$'` 具有奇怪的含义：在具有多个目标的 make 的先决项中，它代表正在处理的具体目标。

  此功能在 GNU make 中没有定义，因为 `'$$'` 将始终代表一个普通的 `'$'`。

  通过使用静态模式规则可以获得部分功能（参见第 4.10 节 [静态模式规则]，第 34 页）。System V make 规则：

```
$(targets): $$.o lib.a
```

  可以用 GNU make 的静态模式规则替换：

```
$(targets): %.o lib.a
```

- 提供选择性的 vpath 搜索。参见第 4.3 节 [在目录搜索先决项]，第 22 页。
- 提供计算变量引用。参见第 6.1 节 [变量引用的基础]，第 55 页。
