
## 邮件客户端的理想功能

### 检索时删除
客户端应该提供在邮件被下载后自动删除服务器上该邮件的选项。另一方面，如果你只使用你的客户端阅读，那么服务器上就不会堆积一个巨大的文件。如果你偶尔使用你的邮件客户端，你可能希望将邮件留在宿主机上，以便你用你的 `UNIX` 邮件程序访问它们。

### 仅检索头信息
你只需查看邮件头就能了解一些关于消息的信息。重新连接到你的服务器很容易；你可能希望你的邮件程序只下载头信息。如果你想查看消息的实际正文，程序将下载该内容。如果有人给你发送了一个大文件，这非常有用——你可能节省将整个文件下载到你计算机上的时间。

### 域名服务器支持
像 `mailserv.bozo.edu` 这样的名称实际上只是由 IP 数字识别的计算机的逻辑名称，看起来类似于 `130.029.13.12`。显然，这个名字更容易记忆，而且如果 `mailserv` 发生了任何变化，导致机器需要移动到新的 IP 地址（例如硬件升级），管理员可以将该名称映射到新的 IP 地址，你甚至不会察觉。那些通过数字访问机器的人将找到新数字并输入。然而，为了将名称转换为 IP 数字，你的客户端需要足够智能以便使用域名服务器，该服务器记录了哪些数字对应哪些名称。

### POP3
这是邮件客户端从邮件服务器检索邮件的标准方式。如果你的客户端不支持此项，你最好有某种你的邮件服务器理解的检索邮件的方法（例如，`IMAP`）。

### 启动时检索
客户端应该允许你在每次启动它时都能立即联系你的邮件服务器并检索未读邮件，因为这可能可能是你最常见的操作。

### 独立的 SMTP 服务器
在某些情况下，你需要使用与检索邮件（`POP3`）不同的机器来发送邮件（`SMTP`）。一个良好的邮件客户端应该允许你为每个指定不同的服务器。

### SMTP 连接
这是邮件客户端向你的邮件服务器提供邮件的标准方式。如果你的邮件客户端不支持 `SMTP`，它应该有某种特殊协议来执行相同的操作。某些邮件客户端使用 `SMTP` 连接作为接收消息的方式，如果你预计计算机一直连接到网络，这可以是免费的。

### TCP、SLIP 或 PPP
你的客户端应该能够访问你的邮件主机所在的任何网络。否则，你就是在自言自语。`TCP/IP` 是你可能需要的最常用的网络邮件协议，而 `POP` 变得越来越流行。另一方面，`SLIP` 变得越来越不利。如果你有一个对于你的邮件看起来像 `TCP/IP` 的 `SLIP` 或 `PPP` 驱动，它只需要 `TCP/IP` 支持。

### 定时检索
客户端应该能够定期自动连接到你的邮件服务器并检查新邮件，如果它发现了新邮件……如果你正在使用它，你可能希望每隔几小时检查一次，或每天一次，但如果你与服务器直接连接网络（可能通过以太网），你可能希望每五分钟检查一次。

### 其他邮件项目
一个良好的邮件客户端让阅读邮件变得尽可能简单。你不应该放弃任何你喜欢的特征。
