**列表 11.8** `stale_VG_PV_PP_mon.ksh`脚本列表（续）

列表 11.8 中的 shell 脚本由于其所使用的技术而显得有趣。从 shell 脚本顶部开始，第一个变量定义是 `ATTEMPT_RESYNC`。我将此变量初始化为 `FALSE`；在 LV 级别进行重新同步可能会导致显著的系统负载。更好的方法是在不带任何参数的情况下运行 `varyvg` 命令。这种方法将只重新同步过期的分区。由于可能会导致系统负载并减慢响应时间，如果我在测试/开发或沙箱机器上工作，我通常会将 `ATTEMPT_RESYNC` 设置为大写的 `TRUE`。设置为 `TRUE` 之后，脚本将尝试在 LV 级别对每个 LV 进行重新同步。

其余的变量分别将 `LOGFILE` 和 `THIS_HOST` 变量初始化为日志文件名。几个计数器初始化为零，有几个变量初始化为 `NULL`。在下一节中，我们用页头信息初始化 `$LOGFILE`。

此脚本中唯一的函数是 `trap_exit` 函数。`trap_exit` 函数在捕获到 `trap`（信号）时会在屏幕上显示“...EXITING ON A TRAPPED signal...”。该脚本针对退出代码 1、2、3、5 和 15 设置了 `trap`；然后脚本将返回代码 1。此功能是对用户的一种通知措施。我们现在处于脚本的开头。

在脚本执行的每一步中，我们都想给用户提供反馈，让他们知道发生了什么。在编写 shell 脚本时，我们需要做两件事：注释所有内容并给用户提供反馈，让他们了解情况。在我们的第一次查询中，我们通知用户我们正在每个 VG 中寻找过期的 PV。在此步骤中，我们使用 `lsvg -o` 命令获取逻辑卷组列表。使用此活动 VG 列表，我们使用 `for` 循环遍历每个活动 VG，并使用 `lsvg` 命令查询 `STALE PV` 字段，同时使用 `grep` 和 `awk` 提取每个 VG 中过期 PV 的数量。当检测到任何过期的 PV 时，该 VG 被添加到 `STALE_VG` 列表变量，VG 中所有的 PV 都通过 `lpv` 命令添加到 `PV_LIST` 变量中。每有一个 PV，`STALE_PV_COUNT` 变量就会加一，使用数学符号 `((STALE_PV_COUNT = STALE_PV_COUNT + 1))`。此时，我们拥有了一个包含过期物理卷的组列表，以及一个已识别的具有过期 PV 的所有 VG 中所有 PV 的列表。

如果 `STALE_PV_COUNT` 变量为零，则系统中逻辑卷组中没有过期的磁盘分区。如果计数为零，我们通知用户没有发现过期的磁盘分区，并以返回代码 0 执行脚本。如果没有发现过期的磁盘分区，此脚本几秒钟即可执行完毕。如果计数大于零，我们通知用户发现了过期的磁盘分区，并继续进行下一步，即查询 `$PV_LIST` 中的每个 PV 以寻找过期的磁盘分区。
