## `/etc/services`

正如前所述，每个 TCP/IP 应用层服务（如 `FTP`、`TELNET` 和 `RLOGIN`）在传输层都被分配了端口号。`/etc/services` 数据库包含了信息，将每个已识别的服务协议映射到静态端口号（也称为已知端口）。应用程序使用唯一分配的端口号来识别传输提供者（在主机到主机层）以及跨网络的远程对端。

以下是 `RFC 1060` 中记录的某些常用服务的部分列表。此列表中的每个条目都包含服务名称及其关联端口号/传输协议提供者。某些服务同时在 `TCP` 和 `UDP` 上运行（例如 `time`）。在这种情况下，该服务列出两次，一次对应 `TCP`，一次对应 `UDP`。

### RFC 1060

除了分配的端口号外，`RFC 1060` 还包含了其他类别分配编号的完整列表（包括但不限于）协议号、`UNIX` 分配的服务以及以太网地址块。下载并维护此 `RFC` 的副本可能会很有用。此 `RFC` 以及书中引用的其他 `RFC` 均可在 `ds.internet` 网站获取。

`/etc/services` 数据库文件在安装 `TCP/IP` 时创建。你唯一需要担心它的时候是安装新的应用程序/服务。在这种情况下，你必须按照应用程序供应商的指示编辑该文件以包含条目。在排排除网络故障时，你可能会发现该文件是有用的参考。

## `/etc/protocols`

回顾了 `IP` 头（见图 20.6），包含一个 `PROTOCOL` 字段。该字段包含一个唯一标识所用 `IP` 协议的数字。与传输号的功能类似，协议号帮助 `IP` 将数据内部路由到各自的协议。`/etc/protocols` 在安装 `TCP/IP` 时在系统中创建，通常不需要更改。以下是一个示例文件列表：

```
## Internet (IP) protocols
ip 0 IP # internet protocol, pseudo protocol number
icmp 1 ICMP # internet control message protocol
ggg 3 GGP # gateway-gateway protocol
tcp 6 TCP # transmission control protocol
egp 8 EGP # exterior gateway protocol
pup 12 PUP # PARC universal packet protocol
dp 177 UDP # user datagram protocol
hmp 200 HMP # host monitoring protocol
xns-idp 22 XNS-IDP # Xerox NS IDP
rdp 27 RDP # "reliable datagram" protocol
```

`/etc/protocols` 文件在系统安装期间创建。作为管理员，你几乎不会更改或更新其内容。你不应该删除此文件或篡改其内容，因为系统每次启动时 `TCP/IP` 守护进程都会引用它。

注意：以下是 `/etc/conf.d/inet/interface` 内容示例：

```
lo0:localhost:/dev/loop
ne2k:0::/dev/ne2k
el3:orbit:/dev/el3-0:
```

根据此列表，支持两个网卡：`ne2k` 和 `e3`。第一个条目 `lo` 对应环回接口。每个条目由冒号分隔的字段组成。这里的 `interface` 文件格式如下：

```
prefix:unit#:addr:device:ifconfig_opts:slink_opts:
```

`prefix` 用于 `ifconfig` 或 `netstat` 命令配置接口或收集统计信息。`unit` 指该接口的单元（实例号）。`addr` 可以包含分配给接口的 `IP` 地址或 `/etc/hosts` 文件中的现有主机名。如果第二个条目包含 `null` 字符串，则 `null` 将扩展为 `'/bin/uname -n'` 接口配置为相应网络节点的 `IP` 地址。`device` 指传输提供者的名称。此字段用于 `slink` 命令以配置和安装协议栈。`ifconfig_opts` 通常包含 `ifconfig` 命令支持的选项。一个常用选项是 `trailers`（在后文中讨论）。`slink_opts` 用于 `slink` 初始化设备。`null` 字段允许配置 `config.boot`（由于长度未列出），它遍历 `/etc/conf.d/inet/interface` 文件指定的所有接口，包括环回接口，使用正确的 `IP` 地址、子网掩码和广播地址配置每个接口。它使用 `slink` 命令配置并加载协议栈。如果网络接口成功配置并启动，`/etc/init.d/inetinit` 会运行 `/etc/rc.inet` 脚本。

注意：`inetinit` 脚本最后是用于启动和停止 `TCP/IP` 服务。系统进入多用户级时启动 `TCP/IP`，关机时停止 `TCP/IP`。这通常通过将 `/etc/init.d/inetinit` 链接到 `/etc/rc6` 实现，与该目录下其他带有 `S` 的脚本一起运行。
