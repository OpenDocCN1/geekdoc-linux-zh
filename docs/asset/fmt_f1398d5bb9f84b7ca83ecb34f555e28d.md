
如第 3 章“软件配置”所示，每个脚本负责从`/mnt/env`文件提取参数并构建任何配置文件。通常可以通过几个`shell`脚本命令完成，但有时必须编写`C`程序来构建配置。`named-configuration`文件就是这种情况，它们复杂到用`shell`脚本编写太困难。

- 6. 构建并执行启动脚本。`ShareTheNet`用户能够使用基于`Web`的配置程序来管理软件。然而，某些功能还不够用，因此用户可以使用浏览器添加自己的启动命令。这些命令可以执行任何操作，但通常用于允许会被拦截的回地网络流量（例如`ICQ`流量）。这些命令在`ShareTheNet`启动过程的最后阶段执行。

# 第 7 章 嵌入式 Linux 工作坊

## 要求

我为了让`ShareTheNet`运行的多年教会了我许多如何在极其有限的环境下提升`Linux`性能的教训。在看了今天许多免费或付费的“嵌入式`Linux`”产品后，我认为一个简单、解释清晰、基础实用的极小`Linux`工具包示例将对开发者社区非常有帮助。因此，我决定在构建嵌入式`Linux`工作坊时，冒着花费更多时间盯着如下信息发呆风险：

`Kernel panic: No init found. Trying init= option to kernel.`

这个工作坊并不试图满足所有人的所有需求。正如我之前提到的，我整合它主要是作为一种教学工具，但我一直将其作为我所有嵌入式`Linux`项目的基础。让我们更详细查看嵌入式`Linux`工作坊的要求：

- 它必须运行在非常常见的硬件平台上，以便任何人都能使用它。
- 它必须足够小，让尝试学习嵌入式软件系统的人只需几天时间就能完全理解它。
- 嵌入式`Linux`工作坊的产物是一个`1.44MB`的软盘，用于引导机器进入应用程序。这几乎不是你最终产品要做的事，但它提供了一个合理的目标，让你可以使用易获取的硬件。如果你要制作这个项目，可能需要先购买额外的硬件。
- 它必须有良好的文档，确保没有任何部分是神秘的。所有二进制文件都不应从人的包中提取，除非源码可用。
- 构建环境不能有“隐藏步骤”。也就是说，进入软盘的每个软件部分都必须根据工具包自带的说明进行构建。
- 每个部分都可以在开源许可下可用。
- 示例应用程序应该非常简单，以免分散主旨——即从关机到运行应用程序的代码。

## 硬件

### 开发平台
嵌入式`Linux`工作坊明显的硬件平台是随处可见的`PC`。能够托管嵌入式`Linux`工作坊的完整开发平台价格比一根好的水管贵一点。

### 工作电脑
你需要确保这台电脑至少有一个空闲的串口并连接了网络。显示器非常重要。它应该有`8MB`内存才有用。显示器尤为重要，因为你总是开启很多窗口。我个人更喜欢在笔记本电脑上尽可能多工作。

当然，你并不只是在重新构建或重复操作，但快速调试循环具有明确的优势：

- 更高的生产率
- 更好地保留程序员关于问题的“工作集集”知识

使用`VMware`的另一个优势是，你实际上并不需要获取更多硬件来构建另一台机器。而且由于虚拟机可以与外部世界协同工作，它们可以表现得非常像你正在构建的真实机器。

当然，`VMware`虚拟机无法访问你生产机器中的专用硬件，因此它们不能用于整个开发过程。但如果你从开始使用这种技术，只有在必须开始与真实硬件集成时才放弃它，你就可以节省大量时间。

## 安装嵌入式 Linux 工作坊 (Embedded Linux Workshop)

安装嵌入式`Linux`工作坊通常非常顺利。基本上有两种不同的方法：`CVS`和`FTP`。使用`CVS`方法，你可以下载软件的最前版本。这可能有点危险；如果另一个开发者上传了某些代码，你可能会破坏你的开发环境。因此，大多数人更喜欢另一种方法：下载一个已知良好版本的代码`FTP`归包。这就是后续步骤中描述的方法。（如果你使用`CVS`，请访问`http://el.sourceforge.net`上的`ELW`站点。）

1. 如果你还没有`root`权限，请为你的机器获取权限。因为嵌入式`Linux`工作坊会挂载某些文件系统，除非作为`root`运行，否则真的没有办法运行它。

2. 下载嵌入式`Linux`工作坊。可以通过`http://el.sourceforge.net`或`ftp: http://el.sourceforge.net/pub/elw/`下载。如果你想下载完整的源代码，有很多文件需要下载。它将被命名为`elw-X.Y.Z.tgz`，其中`X.Y.Z`是当前版本号。如果你只想实验一下嵌入式`Linux`工作坊，你不需要下载所有的源代码和所有的包。但是，如果你的目标是非`x86 CPU`或者想做一些比玩玩软件更多的事情，你将需要随着时间下载大部分源代码。

3. 切换到`/usr/local`目录：

```bash
/usr/local
```

这是安装嵌入式`Linux`工作坊最简单的地方。如果你决定安装在其他地方，请确保将`/usr/local/elw`符号链接指向正确的位置。

## 第 7 章 嵌入式 Linux 工作坊

4. 在`/usr/local`目录下安装嵌入式`Linux`工作坊：

```bash
tar xvzf /tmp/elw-X.Y.Z.tgz
```

上面的命令假设你已经将`elw-X.Y.Z.tgz` `tar`包下载到了`/tmp`目录中。

5. 删除旧的`elw`符号链接并创建一个指向你安装目录的新链接：

```bash
rm -f elw && ln -s elw-X.Y.Z elw
```

如果你需要恢复到嵌入式`Linux`工作坊的之前的版本，你只需将此符号链接指向旧版本即可。

6. 删除任何旧的`/usr/bin/elw`链接并创建一个指向`elw`包中`elw`脚本的新链接：

```bash
(cd /usr/bin && rm -f elw && ln -s /usr/local/elw/elw elw)
```

## 你的第一个嵌入式 Linux 工作坊项目

如果你读完这本书，当你完成它时，你将对`Minicom`程序感到非常厌倦。我在几个示例中使用了它。`Minicom`的伟大之处在于，它不需要测试平台机器拥有任何比普通市售`PC`更多的硬件——它只需要一个串口。而且它确实有用处！

上一节向你介绍了嵌入式`Linux`工作坊的安装方法。在本节中，我将给你一个分步骤的程序，来构建一个可以直接运行`Minicom`的可引导软盘。

1. 切换到你想让新项目所在的目录：

```bash
cd ~yourhome/projects
```

2. 使用已安装的`elw`命令创建新项目。在新的`minicom`目录会创建几个目录和文件：

```bash
elw --new minicom
```

3. 切换到`src`目录：

```bash
cd minicom/arch/i386/src
```

4. 创建一个`minicom`子目录来存储`Minicom`的源码：

```bash
mkdir minicom
```

5. 切换到新的`minicom`目录。

```bash
cd minicom
```

6. 从`http://www.pp.clinet.fi/~walker/minicom.html`下载`Minicom`。如果那里没有，尝试在`http://www.freshmeat.net`寻找。如果你在下载时遇到困难，使用`http://ftpsearch.lycos.com`搜索文件名，然后选择一个附近的站点进行下载。在本文写作时，最新版本是`1.83.1`。

7. 解压`minimom`（如果你想看到创建的文件，请将命令中的`xzf`改为`xzvf`）：

```bash
tar xzf minimom-1.83.src.tar.gz
```

8. 创建一个名为`minimom`的符号链接，指向文件`minimom-1.83.1`：

```bash
ln -s minimom-1.83.1 minimom
```

此符号链接将被用于`minimom/Makefile`。如果你决定升级到更高版本的`Minimom`，你只需更改符号链接到新版本。

9. 切换到`minimom`目录：

```bash
cd minimom/src
```

我们需要对`Minimom`源码进行细小的更改，以确保它在我们的环境中正常工作。我们将通过删除`Minimom`源码中一个在嵌入环境中不需要的功能来实现。

10. 在`minimom.c`中搜索以下行：

```c
if (real_uid == 0 && dosetup) {
```

现在删除大约`6`行——但不包括以下行：

`buf[0] = 0;`

如果不删除这些行，`Minicom`将在此处退出。由于我们在嵌入式环境中不需要担心权限和正确的用户，可以跳过这段代码。

保存你的更改。

11. 生成`minimom`可执行文件：

```bash
make
```

12. 切换到内核目录：

```bash
cd ../../kernel
```
