
一旦你选择了适当的文件，就可以通过菜单栏上的“文件”（`File`）选项选择“恢复...”（`Restore...`）来启动恢复过程（或左键点击恢复恢复图标）。`KDat` 将显示一个对话框，允许你确认将恢复哪些文件。此外，你还可以选择指定将文件恢复到哪个目录。这将允许你将关键系统文件恢复到家目录，然后稍后比较、移动或更新这些文件到预定位置。这实际上是恢复文件最安全的方法。

要开始恢复过程，点击“确定”（`Okay`）按钮。`KDat` 将扫描磁带并恢复所选文件。

有时，你可能会发现有必要从没有使用 `KDat` 创建的备份集中恢复一个或多个文件。也许你希望在一个没有提供 GUI 环境的系统上恢复此类文件，或者想通过慢速网络连接通过远程执行 `KDAT` 来操作，而这在实际上是不现实的。幸运的是，`KDAT` 使用“`tar`”工具写入备份数据集，`tar` 是在任何 `nix` 系统上可用的命令行工具。

如果你想使用 `tar` 恢复由 `KDAT` 创建的备份集，请使用你在使用 `tar` 自己创建任何普通备份集时会使用的任何选项。然而，请记住，数据集不是以压缩格式存储的。

> 注意：当你尝试用 `tar` 访问 `KDAT` 备份集时，几乎会收到错误消息。这是因为 `KDAT` 在首次格式化磁带时添加了头和其他信息。只需重复 `tar` 命令两次或三次即可跳到实际归包文件的开头。

## 8.3. Cisco 路由器配置备份

在工作场所，我们有一个连接远程位置的 WAN。这些远程位置通过 ISDN 或某些情况下通过 Centrax 数据中心连接 Cisco 路由器，以提供 Internet 和 WAN 连接。Cisco 路由器产品允许通过网络服务器上的 TFTP（简单文件传输协议）读取和写入配置文件。每当路由器配置发生更改时，在 Linux 服务器上保存配置文件是非常关重要的，以便维持备份。

请注意，Red Hat 默认禁用了 TFTP 服务，因为如果配置不当，可能会成为一个真正的安全漏洞。TFTP 守护允许任何人在不进行身份验证的情况下读取和写入文件。我个人的设置方法是创建一个由 root 拥有的“`/tftpboot/`”目录，然后修改“`/etc/inetd.conf`”文件中现有的配置行以修复位置：

```
tftpd dgram wait root /usr/sbin/tcp in.tftpd /tftp-boot
```

> 注意：在上述行末尾添加 `/tftpboot` 路径专门指示了 TFTP 守护允许访问文件的位置。虽然实际上可以省略此部分并允许 TFTP 访问系统上的任何地方，但由于 TFTP 被认为具有安全风险，这可能是一个非常糟糕的主意。

一旦你启用了 TFTP 服务，别忘记输入：

```
killall -HUP inetd
```

上述命令重启 INETD 守护进程以识别你对 `inetd.conf` 文件所做的任何更改。

创建一个路由器配置文件的备份涉及 3 个步骤：对现有文件设置权限（或创建一个新文件）以允许写入，写入备份文件，然后重置权限以限制对文件的访问。

`/usr/`（又 user）文件系统挂载在 `/dev/hda2` 上，包含用户可安装的软件（即由系统管理员安装的软件），例如你的站点页面。这是最大的且增长缓慢的文件系统。网页页面的日志文件也可能存储在这里并随之增长；请根据需要定期检查并修剪它们。在我的机器上，每个月初，当前的日志文件会被移动到每月摘要日志（例如 `access_log.11` 代表 11 月的日志条目）。年底，这些日志将被全部删除，循环重新开始（这意味着每年 1 月 1 日可用空间都应该有明显的改善）。

> 提示：如果此文件系统增长迅速，请检查 `/usr/local/etc/httpd/logs` 和 `/usr/local/squid/logs/` 目录（如果有的话）。可能存在某些变得过大的日志文件（也许是因为网站的访问量很高）。然而，如果日志像我设置的那样定期自动清理，你就不会在这些地方遇到任何空间问题（事实上，日志用于对我的站点流量进行统计分析，如果可能的话，我并不想删除它们）。另一个可以检查可能删除文件的地方是 `/usr/tmp/`。

`/home/`（即用户个人主目录）文件系统挂载在 `/dev/hda3` 上，包含所有用户目录和个人文件。除非你提供 shell 账户，否则大部分内容对用户来说都是无用且不可访问的（这些目录在创建用户账户时创建，稍后可用于转发用户邮件等）。然而，shell 账户用户以及任何拥有网页（例如个人网页）的非 shell 账户可能会将它们存储在此处。此外，在 Red Hat发行版中，主 Web 服务器存储在 `/home/httpd` 下，而其他发行版通常将它们放在 `/usr` 文件系统中（更多信息请见第 7.1 节）。

此文件系统的增长可能是慢的，除非你提供了大量的 shell 账户。

> 提示：如果此文件系统的大小突然增加，可能是因为其中一个用户在其个人空间添加了网页或二进制文件。检查 `/var/adm/xferlog` 日志文件以获取最近活动，它应该显示是哪个用户向其网页添加了内容。

我还有一个 `archive/`（即归档文件）文件系统，挂载在 `/dev/hdb1` 上，这是一个备用的 1.02 Gb 硬盘，可用于任何目的（例如数据文件、软件套件等）。我将此驱动器的很大一部分（约 70%）用于系统的磁盘到磁盘全量当前备份。通常你可以根据意愿添加自己的设备并挂载它们。

我还有一个 CD-ROM 驱动器，挂载在 `/dev/scd0` 的 `mnt/cdrom/`，这是一个 24X 速的 SCSI CD-ROM 设备，可以读取 ISO9660 格式的 CD。它主要用于软件安装，通过 Samba 服务，DOS/Windows CD 可以从 Windows 3.x/95/NT 网络共享中进行挂载和访问（详情请见第 7.4 节）。

`rm` 命令将删除文件。用法是使用 `-i` 选项（例如 `rm -i *`）。随后你将在删除每个文件之前被要求进行确认。

（注意：这是普通 shell 用户的默认设置，但要小心——root 账户在未指定 `i` 选项的情况下不会在删除文件前进行确认！）

在使用此命令时要小心出现低级拼写错误——特别是当你以“root”身份登录时——因为你可能会因删错文件而追后悔。
