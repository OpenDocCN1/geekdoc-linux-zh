
`display` 指定到 X 服务的的连接。

`keycode` 指定 KeyCode。

`index` 指定 KeyCode 向量的元素。

`XkeycodeToKeysym` 函数使用内部 Xlib 表，并返回为指定的 KeyCode 和 KeyCode 向量元素定义的 KeySym。如果没有定义符号，则 `XkeycodeToKeysym` 返回 `NoKeysym`。

要获取具有 KeySym 的按键的 KeyCode，使用 `XkeysymToKeycode`。

```
KeyCode XkeysymToKeycode(display, keysym);
```

`display` 指定到 X 服务的的连接。

`keysym` 指定要搜索的 KeySym。

如果任何 KeyCode 都没有定义 KeySym，则 `XkeysymToKeycode` 返回零。

KeyCodes 与 KeySyms 之间的映射缓存在 Xlib 内部。当这些信息在服务器端更改时，必须调用 X 函数来刷新缓存。要刷新存储的映射和键映射信息，请使用 `XRefreshKeyboardMapping`。

```
XRefreshKeyboardMapping(event_map);
```

`event_map` 指定要使用的事件。

`XRefreshKeyboardMapping` 刷新存储的映射和键映射信息。你通常在发生请求方式为 `MappingKeyboard` 或 `MappingModifier` 的 `MappingNotify` 事件时调用此函数。其结果是更新 Xlib 对键盘的认知。

要获取 KeySym 的大写和小写形式，请使用 `XConvertCase`。

```
void XConvertCase(keysym, lower_return, upper_return);
```

`keysym` 指定要转换的 KeySym。

`lower_return` 返回 keysym 的小写形式，或 keysym。

`upper_return` 返回 keysym 的大写形式，或 keysym。

如果 KeySym 适用于大小写转换，则 `XConvertCase` 函数返回指定 KeySym 的大写和小写形式；否则，指定的 KeySym 将返回给 `lower_return` 和 `upper_return`。对于拉丁和西里尔字母 KeysSym 转换的支持取决于实现。

Keysym 既有字符串名称也有数字代码。要将 KeySym 的名称转换为 KeySym 代码，使用 `XStringToKeysym`。

```
KeySym XStringToKeysym(string);
```

`string` 指定要转换的 KeySym 的名称。

标准的 KeySym 名称通过从 `<X11/keysymdef.h>` 获取，方法是删除每个名称中的 `XK` 前缀。不属于 Xlib 标准的 KeySyms 也可以通过此函数获取。以这种方式可用的 KeySums 集合以及 Xlib 获取它们的机制取决于具体实现。

如果 KeySym 不在主机平台字符编码中，则结果取决于实现。如果指定的字符串不匹配有效的 KeySym，`XStringToKeySym` 返回 `NoSymbol`。

要将 KeySym 转换为 KeySym 的名称，使用 `XKeysymToString`。

```
char *XKeysymToString(keysym);
```

`keysym` 指定要转换的 KeySym。

返回的字符串位于静态区域中，不能修改。返回的字符串位于主机平台字符编码中。如果指定的 KeySym 未定义，则 `XKeysymToString` 返回 `NULL`。

# KeySym 分类宏

你可能想测试一个 KeySym 是否（例如）在小键盘上或某个功能键上。你可以使用 KeySym 宏执行以下测试。

- `IsCursorKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是光标键，则返回 True。
- `IsFunctionKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是功能键，则返回 True。
- `IsKeypadKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是标准小键盘键，则返回 True。
- `IsPrivateKeypadKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是私有小键盘键，则返回 True。
- `IsMiscFunctionKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是杂项功能键，则返回 True。
- `IsModifierKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是修饰键，则返回 True。
- `IsPFKey(keysym)`: `keysym` 指定要测试的 KeySym。如果指定的 KeySym 是 PF 键，则返回 True。

# 使用 Latin-1 键盘事件函数

第 13 节描述了国际化文本输入，但有时编写一个只处理 Latin-1 字符的应用程序更为方便，因此 Xlib 为此目的提供了一个函数，`XLookupString` 处理 12.7 节描述的标准。此函数不依赖于 13 节描述的输入方法。

要将键事件映射到 ISO 字符串，使用 `XLookupString`。

```
int XLookupString(event_struct, buffer_return, bytes_buffer, keysym_return, status_in);
```

`event_struct` 指定使用的事件结构。你可以传递 `XKeyPressedEvent` 或 `XKeyReleasedEvent`。

`buffer_return` 返回翻译后的字符。

`bytes_buffer` 指定缓冲区长度。最多返回三个字节的翻译。

`keysym_return` 如果此参数为 NULL，返回从事件计算出的 KeySym。

`status_in` 指定或返回 `XComposeStatus` 或 NULL。

`LookupString` 将事件转换为 KeySym 和字符串。KeySym 使用 Shift、Lock、group 和空修饰符的标准解释获取。如果 KeySym 已重新绑定（参见 `XrebindKeySym`），则绑定的字符串将存储在缓冲区中。否则，KeySym 将映射到 ISO Latin-1 字符（如果开启了 Control 修饰符则是 ASCII 控制字符），该字符存储在缓冲区中。`LookupString` 返回存储在缓冲区中的字符数量。

如果非空，`XComposeStatus` 结构存储结果，该结果是 Xlib 私有的，跨越 `XLookupString` 调用进行保存以实现组合处理。`XComposeStatus` 结构的创建取决于实现；可移植程序必须对此参数传递 NULL。

# 应用实用函数

要为 `XLookupString` 重新绑定 KeySym 的含义，请使用 `XRebindKeysym`。
`XRebindKeysym(display, keysym, list[], mod_count, string, num_bytes);`

- `display`: 指定与 X 服务的器的连接。
- `keysym`: 指定要重新绑定的 KeySym。
- `list`: 指定用作修饰符的 Keysym。
- `mod_count`: 指定修饰符列表中修饰符的数量。
- `string`: 指定被复制并将由 `XLookupString` 返回的字符串。
- `num_bytes`: 指定字符串的字节数。

`XRebindKeysym` 函数可用于为客户端重新绑定 KeySym 的含义。它不会对按键进行重新定义。当按下了一组合适的修饰符且该 KeySym 原应被用于翻译时，`XLookupString` 会返回此字符串。该过程不会执行任何文本转换；客户端负责提供经过正确编码的字符串。请注意，你可以重新绑定一个可能并不存在的 KeySym。

# 分配永久存储空间

要分配你永远不会释放的内存，请使用 `Xpermalloc`。
```
char *Xpermalloc(size);
```

`Xpermalloc` 函数分配在程序生命周期内永远无法释放的存储空间。内存分配时针对 C 类型 `double` 进行了对。与标准操作系统内存分配器相比，此函数可能提供一些性能和空间节省。
