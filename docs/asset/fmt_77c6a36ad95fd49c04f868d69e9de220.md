### Processes

### GRUB 特性

这种方法被称为*直接加载*，因为它是使用指令直接加载操作系统，在引导加载程序与操作系统主文件（如内核）之间没有中间代码。然而，操作系统所使用的启动过程可能与上述过程略有不同。例如，微软的操作系统和 Windows 操作系统在安装时会完全覆盖 MBR 上的任何内容，而不会包含当前的任何 MBR 配置。这会破坏由其他操作系统（如 Linux）存储在 MBR 中的任何其他信息。微软的操作系统以及各种专有操作系统（proprietary operating systems）是使用链式启动方法加载的。通过这种方法，MBR 指向持有操作系统的分区的第一个扇区，在该处找到启动该操作系统所需的特殊文件。

GRUB 同时支持这两种方法，允许你与几乎任何操作系统、最流行的文件系统以及你的 BIOS 可以识别的任何硬盘配合。

GRUB 包含许多特性，最最重要的：

- GRUB 在 x86 机器上提供了一个真正的基于命令的预操作系统环境，以最大限度地提高使用特定选项加载操作系统或收集系统信息的灵活性。
- GRUB 支持逻辑块寻址 `LBA` 模式，访问许多 IDE 和所有 SCSI 硬盘都需要此模式。在 LBA 之前，硬盘会遇到 1024 磁道的限制，此之后 BIOS 无法找到文件。
- GRUB 的配置文件每次系统启动时都会从磁盘读取，这防止了你每次更改启动选项时都需要重新写入 MBR。

可以通过执行 `info grub` 命令或访问 GRUB 网站 `[http://www.org/software/grub/]` 找到 GRUB 的完整说明。Linux 文档项目（Linux Documentation Project）有一份带有 GRUB MiniHOW 的 Multiboot `[http://www.tdlp.org/mini/Multiboot-with-GRUB]`。

### 初始化

内核一旦加载，就会在 `bin` 目录找到 `init` 并执行它。

当它启动时，它将成为你的 Linux 系统上自动启动的所有进程的父进程或祖进程。第一个 `init` 执行的事情是读取它的初始化文件 `/etc/inittab`。此 `init` 指令读取环境的任何初始配置脚本，这些脚本设置路径、启动交换（swapping）、检查文件系统等。这一步处理了系统在初始化时需要的所有内容：设置时钟、初始化串口等。

然后，`init` 继续读取 `/etc/inittab` 文件，该文件描述了系统在每个运行级别（run level）下应该如何设置，并设置了默认运行级别。运行级别是进程的配置。所有 UNIX 类系统都可以在不同的配置下运行，例如单用户模式，它被称为运行级别 1 或运行级别 5（或 s）。在模式模式下，只有系统管理员可以连接到系统。它用于执行维护，而不会有损坏系统或用户数据的风险。自然地，在这种种配置下，我们不需要提供用户服务，因此它们都将被禁用。另一个运行级别是重启级别，或运行级别 6，它会根据适当的程序关闭所有正在运行的服务并重启系统。

使用 `who` 来检查你当前的运行级别：

```
willy@ubuntu:-$ who -r
run-level 2 2006-10-17 23:22  last=S
```

关于运行级别的更多信息请见下一节，标题为“Init运行级别”（Init run levels）。

在为你的系统定义了默认运行级别后，`init` 通过查看运行级别对应的 rc 目录来启动系统运行所需的所有后台进程。`init` 带有 `stop` 参数运行每个 `kill` 脚本（其文件名以 K 开头）。然后，它在相应的运行目录中运行所有启动脚本（其文件名以 S 开头），以便所有服务和应用程序都能被正确启动。事实上，在系统完成启动后，你可以以 root 身份登录并使用 `/etc/init stop` 或 `service http stop` 等命令手动执行这些脚本，以备停止 Web 服务器之用。

### 特殊情况

注意，在系统启动时，`/etc/rc.d` 和 `rc3.d` 中的脚本通常会被执行。在这种情况下，没有服务被启动（至少不是永久启动）。只有那些服务会被启动。

在位于 `/etc/rcXX` 的实际启动和停止服务的文件中，是指向位于 `/etc/init.d` 中的实际脚本的符号链接。符号链接无非是一个指向另一个文件的文件，在这种情况下使用它是是因为可以在不影响实际脚本的情况下创建和删除它。指向各种脚本的符号链接按特定顺序命名，以便它们按顺序启动。在这种情况下，它们启动或调用的顺序是通过调用链接名称来实现的，引用指向控制服务的服务的脚本。如果某个服务在另一个服务之前或之后停止或重启，你可以多次使用相同的名称。

## 进程

请根据需要灵活配置未使用的运行级别（通常为运行级别 4）。许多用户会以最符合自己逻辑的方式配置这些运行级别，同时让标准运行级别保持默认状态。这使他们能够在自定义配置和标准功能集之间切换，而不会干扰标准运行级别下的正常功能。

如果你进入了某种由于 `/etc/init.d` 错误导致系统无法启动，或者由于 `/etc/passwd` 文件损坏导致你无法登录（或者你仅仅忘记了密码），请进入单用户模式启动。

### 没有图形界面怎么办？

当处于文本模式下，且机器的控制台上没有显示图形化登录界面时，你通常可以切换到运行级别 7 以获得图形化登录。如果此项被设置为 `/etc/init.d` 默认值之外的其他值，请使用命令 `-r` 检查运行级别。如果系统默认没有以图形模式启动，请联系你的系统管理员或运行 `man init`。请注意，切换运行级别最好使用 `telinit` 命令；从图形控制台切换或反之则并不涉及运行级别的切换。

本指南中对运行级别、脚本和配置的讨论尝试尽可能保持通用。存在许多变体。例如，Linux 将脚本存储在 `/etc/runlevel` 中。其他系统可能会先通过 (a) 较低的运行级别并执行那里的所有脚本，最后到达最终运行级别并执行它们。更多信息请参阅你的系统文档。你也可以通读 `/etc/init.d` 中引用的脚本，以更好地理解你的系统中发生了什么。

### 工具

如果你的系统上安装了 `chconfig` 或 `update-rc.d` 工具，它们提供了一个用于维护 `/etc/init.d` 目录层次结构的命令行工具。这让管理员无需手动操作 `/etc/rc[x].d` 目录下的符号链接。

在某些系统上使用 `ntysys` 工具，它提供了一个基于文本的界面；你可能会发现这比 `chconfig` 的命令行界面更容易用。在 SuSE Linux 上，你会发现 `yast` 和 `insert` 工具。对于 Mandrake，你可能想使用 `Drakconf`，它允许在运行级别 3 和 5 之间切换许多其他功能。在 Mandriva 中，这是 `Mandriva Linux Control Center`。

大多数发行版都提供用于配置进程的图形用户界面，具体取决于你的系统文档。

所有这些操作必须以 root 身份进行。系统管理员可以手动在每个运行级别目录中创建相应的链接，以便在特定的运行级别启动或停止服务。

### 关机

UNIX 的设计并不是为了关机，但如果你确实需要，请使用 `shutdown` 命令。完成程序后，`-h` 选项将停止系统，`-r` 将重启系统。

`reboot` 和 `halt` 命令现在能够在系统处于运行级别 1-5 时调用 `shutdown`，并确保系统正常关闭，但这不是一个好的习惯，因为并不是所有的 UNIX/Linux 版本都具有此功能。

如果你的电脑没有掉电，在看到指示系统已停止或完成关机的消息之前，不应关闭电脑，以便给系统留出卸载所有分区的时间。不耐烦可能会导致数据丢失。
