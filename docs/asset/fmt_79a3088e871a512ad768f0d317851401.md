
```abel
001- MODULE evpar2
002- INTERFACE (b0,b1)->par;"define interface
003- TITLE '2-bit even-parity generator'
004- DECLARATIONS
005- b1..b0 PIN;"declare interface pins
006- par PIN ISTYPE 'COM';
007- EQUATIONS
008- par = b1 $ b0;      "just a simple XOR
009- END evpar2        "end 2-bit parity module
```

`MODULE`关键字（第1行）开始定义2位奇偶校验发生器模块，后跟模块名称（`evpar2`）。第2行使用`INTERFACE`关键字定义括号内的输入列表（`b0`和`b1`）以及单个输出（`par`）。在此，`INTERFACE`关键字用于定义该模块的外部接口，供使用该模块的其他模块调用。两个输入和一个输出实际上是在第5行和第6行中，在`DECLARATIONS`关键字之后声明的。第8行的布尔方程将`b0`和`b1`输入进行异或，并在`odd`输出上输出奇偶校验结果。（该输出之所以称为`odd`，是因为当输入具有奇校验时，它变为逻辑1。但输入位与输出位的总组合具有偶校验。）然后`END`关键字结束2位奇偶校验发生器模块的定义。此ABEL代码存储在`EVPAR2.ABL`文件中。

### 4位偶校验发生器（列表4.2）

4位奇偶校验发生器模块`evpar4`的接口在第2行定义。它接收4个输入位（`b3..b0`）并生成一个奇偶校验输出（`par`）。这些输入和输出在第5行和第6行声明。第8行指定了2位奇偶校验发生器模块的接口。这复制了最初在`evpar2`模块的`INTERFACE`行中声明的接口信息。然后第10行使用`FUNCTIONAL BLOCK`关键字声明了两个2位模块实例。`evpar2`模块的两个实例分别命名为`par0`和`par1`。第12行声明了两个新节点（`tmp0`和`tmp1`），其唯一目的是保存`par0`和`par1`模块的输出（这有点像使用临时变量）。第15行和第16行指定将4位奇偶校验发生器的低2位输入（`b0`和`b1`）连接到其中一个2输入奇偶校验发生器（`par0.b0`和`par0.b1`）的输入。（注意，模块的输入和输出是通过给出模块名称，然后以点扩展形式附加输入名称来指定的。）第17行将该模块的输出（`par0.par`）连接到`tmp0`节点。第19–21行列出了使用第二个2位奇偶校验发生器处理高2位输入时的等价连接。最后，第23行将两个模块的输出（现在位于节点`tmp0`和`tmp1`上）进行异或，并将最终奇偶校验结果传递到当前模块的输出（`odd`）。此ABEL代码存储在`EVPAR4.ABL`文件中。

### 8位偶校验发生器（列表4.3）

8位奇偶校验发生器模块由两个4位奇偶校验器构成，其构建方式与上述4位奇偶校验器的构建方式类似。注意，这是设计的顶层，因此不需要`INTERFACE`定义来定义其输入和输出，因为没有其他模块会使用它。注意第15行和第18行中向量符号的使用如何减少了指定与较低层模块连接所需的行数。此ABEL代码存储在`EVPAR8.ABL`文件中。

您可以为`XS95`板创建一个名为`EVPAR_95`的原理图模式项目，或者为`XS40`板创建一个`EVPAR_40`项目。无论哪种情况，都将`EVPAR8.ABL`文件添加到项目中，然后用HDL编辑器打开它。通过在HDL编辑器窗口中选择`Synthesis → Synthesize`菜单项来为设计创建网表。综合器将自动在`EVPAR2.ABL`和`EVPAR4.ABL`文件中查找较低层模块的描述。

#### 清单4.2 4位偶校验生成器的ABEL描述

```
001- MODULE evpar4
002- INTERFACE ({b3..b0}->par); "4 inputs, 1 output
003- TITLE '4-bit even-parity generator'
004- DECLARATIONS
005- b3..b0 PIN;
006- par PIN ISTYPE 'COM';
007- "declare the interface to the 2-bit parity module
008- evpar2 INTERFACE (b0,b1->par);
009- "declare 2 instances of the 2-bit parity module
010- par1,par0 FUNCTIONAL_BLOCK evpar2;
011- "these hold the outputs of the 2-bit parity modules
012- tmp0,tmp1 NODE ISTYPE 'COM';
013- EQUATIONS
014- "compute parity for lower 2 bits
015- par0.b0 = b0;      "connect inputs of the 4-bit module
016- par0.b1 = b1;      " to the inputs of the 2-bit modules
017- tmp0 = par0.par;   "connect module output to tmp0 node
018- "compute parity for upper 2 bits
019- par1.b0 = b2;      "now connect the upper two inputs
020- par1.b1 = b3;      " to the second 2-bit module
021- tmp1 = par1.par;   "and connect module output to tmp1
022- "combine outputs of the 2-bit parity modules
023- par = tmp1 $ tmp0;
024- END evpar4
```

图4.3显示了该生成器。请注意，只有当`b0-b7`输入中值为1的位的总数为1、3、5或7时，`odd`输出才会变为高电平。因此，加入`odd`输出可使值为1的位总数变为偶数。

使用`XS95`板时，奇偶校验生成器8个输入的适当`XC95108` CPLD引脚分配如下所示。电路输出驱动7段LED的S0段。

```
NET b0      LOC=P46;
NET b1      LOC=P47;
NET b2      LOC=P48;
NET b3      LOC=P50;
NET b4      LOC=P51;
NET b5      LOC=P52;
NET b6      LOC=P81;
NET b7      LOC=P80;
NET odd     LOC=P21;# LED segment S0
```

将偶校验生成器编译为比特流，并将比特流转换为`EVPAR_95.SVF`文件后，您可以将其下载到`XS95`板（请记得将SVF文件存储到`EVPAR_95`项目的顶层目录中）：

```
C:\XCPROJ\EVPAR_95> XSLOAD EVPAR_95.SVF
```

现在您可以对奇偶校验生成器进行实际测试。例如，命令

```
C:\XCPROJ\EVPAR_95> XSPORT 01001001
```

应该点亮7段LED的S0段，因为该输入模式包含奇数个1。另一方面，命令

```
C:\XCPROJ\EVPAR_95> XCPORT 01011001
```

将熄灭S0段，因为该输入模式包含偶数个1。

在测试奇偶校验检测器时，您可能还会注意到，除了S0段以外的LED段在亮起和熄灭。如果出现这种情况，那是因为Foundation系列实现工具将较低层奇偶校验检测器模块的输出分配到了与LED数字的其他段相连的引脚上。（Foundation并非有意这样做——它只是在寻找一些可用的引脚，碰巧选中了一些连接到LED的引脚。）尽管这并非本意，但如果您知道每个奇偶校验检测器模块影响的是哪个段，这对于调试电路可能会很有用。您可以在引脚分配报告文件中找到此信息。

### 用于XS95板的VHDL奇偶校验生成器

让我们使用VHDL重新构建8位奇偶校验生成器。在`XCPROJ-V`目录中创建一个名为`EVPAR_95`的HDL模式项目。然后创建包含清单4.4中VHDL代码的`EVPAR.VHD`文件。（这很可能最容易通过使用空的HDL编辑器文件来完成，而不是尝试使用HDL设计向导。）

`EVPAR.VHD`文件包含三个模块：一个2位奇偶校验生成器（第3-17行）、一个4位奇偶校验生成器（第20-44行）和一个8位奇偶校验生成器（第47-81行）。每个模块首先包含IEEE库的`STD_LOGIC_1164`程序包，然后是描述模块接口的`ENTITY`块，接着是`ARCHITECTURE`部分。
