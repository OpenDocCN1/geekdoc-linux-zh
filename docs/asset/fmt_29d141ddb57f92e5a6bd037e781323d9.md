## 网络服务

### Telnetd

Telnet 是现今互联网上最早的服务之一，它允许你交互式地登录到远程机器，发布命令并查看结果。它仍然是大多数环境中远程管理的主要默认工具，并拥有几乎通用的支持（即使 NT 也有 telnet 守护进程和客户端）。它也是最不安全的协议之一，容易受到嗅探、劫持等攻击。如果你使用 telnet 连接服务器，你应该尽可能为你的账户加密，并使用 `tcp_wrappers` 限制 telnet 仅允许特定的主机使用。加固 telnet 的最佳解决方案是禁用它并使用 SSL 加密后的 telnet 或 ssh。

telnet 的问题：

- 明文身份验证，用户名和密码。
- 所有命令均为明文传输。
- 密码破解攻击（极少，会记录在日志文件中）。

最佳解决方案是关闭 telnet 并使用 ssh。然而，在所有情况下这并不可行。如果你必须使用 telnet，我强烈建议使用防火墙进行防护，设置规则允许主机/网络访问 23 端口，然后设置一个拒绝访问该端口的通用规则（这样效率更高，因为系统只检查 TCP 连接而不是每个数据包（防火墙规则）。使用 `tcp_wrappers` 允许人们发现你正在运行 telnet，它允许他们连接，评估连接，如果他们不在允许列表中则关闭连接）。防火墙规则的示例如下：

```bash
ipfwadm -I -a accept -p tcp -s 10.0.0.0/8 -D 0.0.0.0/0 23
ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 23
ipfwadm -I -a deny -p tcp -s 10.0.0.0/0 -D 0.0.0.0/0 23
```

或者在 ipchains 中：

```bash
ipchains -A input -p all -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 23
ipchains -A input -p all -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 23
ipchains -A input -p all -j DENY -s 0.0.0.0/0 -d 0.0.0.0 23
```

使用 `tcp_wrappers` 的示例：

在 `/etc/hosts.allow` 中

```
in.telnetd: 10.0.0.0/255.0.0.0, some.trusted.host
```

在 `/etc/hosts.deny` 中

```
in.telnetd: ALL
```

如前所述，有几种 telnet 的加密替代方案，如 ssh、SSLeay Telnet 以及其他第三方工具。我个人觉得，如果你打算费力关闭 telnet 并将其替换为更好的东西，那么“最佳”替代方案是使用 ssh。

为了针对 telnet 安全用户账户，你可以做几件事。第一是允许 root 通过 telnet 登录，这由 `/etc/security` 控制，在大多数发行版中默认限制为从控制台登录（这是一个好事）。要让用户成功登录，其 shell 必须是有效的（这由 `/etc/shells` 中的 shell 列表决定），设置允许登录的用户账户只需将他们的 shell 设置为 `/etc/shells` 中的某项，而排除用户则只需将他们的 shell 设置为 `/bin/false` 或 `/etc/shells` 中未列出的内容。现在来看一些通过将用户 shell 设置为非 shell 程序的可以实现的实际示例。
