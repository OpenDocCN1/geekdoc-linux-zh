
`{POSIX_CHOWN_RESTRICTED}` 默认启用。请参见 `system(4)` 和 `pathconf(2)`。

## 选项 (Options)

- `-f` 不报告错误。
- `-h` 如果文件是符号链接，则更改符号链接的组。如果没有此选项，则更改符号链接所引用文件的组。
- `-R` 递归地遍历目录及任何子目录，在 `chgrp` 执行过程中设置指定的组 ID。当 `chgrp` 遇到符号链接时，更改目标文件的组（除非指定了 `-h` 选项），但不再进行递归。

## 操作数 (Operands)

- `group` 来自组数据库的组名或数字组 ID。用于指定通过一个文件操作数赋给每个文件名的组 ID。如果组数据库中以组名形式存在数字组，则使用与该组名关联的组 ID 作为该组 ID。
- `file` 要修改其组 ID 的文件路径名。

## 用法 (Usage)

关于 `chgrp` 在遇到大于或等于 2 Gbytes (`2**31` 字节) 文件时的行为描述，请参见 `large(5)`。

### 示例 (Examples)

在以下示例中，文件所有者 `winsor` 将名为 `tryit` 的文件的组改为 `other`。

```
castle% chgrp other tryit

castle% ls -1 tryit

-rw-rw-rw- 1 winsor      other      18 Aug 27 17:45 tryit

caste%$
```

> 在以下示例中，用户 `ray` 尝试将名为 `tryit` 的文件的组改回 `staff`，但他并不是该文件的所有者。系统显示了错误消息。

```
castle% whoami

ray

castle% chgrp staff tryit

chgrp: tryit: Not owner

caste%$
```

> 在以下示例中，超级用户将名为 `tryit` 的文件的组改回 `staff`。

```
castle% su

Password:

castle% chgrp staff tryit

castle% ls -1 tryit

-rw-rw-rw- 1 winsor      staff      18 Aug 27 17:45 tryit

caste%$
```

## chmod — 139

> 注意 — 你不能在绝对模式下设置或清除 setgid 位；必须在符号模式下使用 `g+s`（或 `g-s`）来设置（或清除）。

## 符号模式

你通过以下语法指定符号模式：
`chmod symbolic-mode-list file...`

其中，`symbolic-mode-list` 是一个由逗号分隔的列表（中间没有空格），其形式为如下符号模式表达式：
`[who] operator [permissions]`

操作按照给定的顺序执行。单个操作符后的多个权限字母将同时执行相应的操作。
`chmod` 命令的模式如下所示。

- *who* | 字符 `u`, `g`, `o`, `a` 的零个或多个组合，指定要更改或分配谁的权限。
  - `u` | 用户权限。
  - `g` | 组权限。
  - `o` | 其他人权限。
  - `a` | 所有权限（用户、组和其他人）。
  如果你省略了 `who`，则默认为 `a`，但会考虑文件模式创建掩码的设置（更多信息请参见 `sh(1)` 或 `csh(1)` 中的 `mask`）。当你省略 `who` 时，`chmod` 不会覆盖你的用户掩码的限制。

- *operator* | 符号 `+`、`-` 或 `=`，表示权限如何更改。
  - `+` 添加权限。
    如果你省略了 `permissions`，则不添加任何内容。
    如果你省略了 `who`，则添加权限所代表的文件模式位，但文件模式创建掩码中已有的对应位除外。
    如果你指定了 `who`，则添加权限所代表的文件模式位。
  - `-` 移除权限。
    如果你省略了 `permissions`，则什么都不做。
    如果你省略了 `who`，则清除权限所代表的文件模式位，但文件模式创建掩码中已有对应位除外。
    如果你指定了 `who`，则清除权限所代表的文件模式位。

- `=` 绝对地分配权限。

如果你省略了 *who*，则清除所有文件模式位；如果你指定了 *who*，则清除由 *who* 代表的文件模式位。

如果你省略了 *permissions*，则不进行其他操作。

如果你省略了 *who*，则添加 *permissions* 所代表的文件模式位，但文件模式创建掩码中已有对应位除外。

如果你指定了 *who*，则添加 *permissions* 所代表的文件模式位。

与所有符号操作不同，`=` 具有绝对影响，因为它会重置由 *who* 代表的所有其他位。省略 `permissions` 仅在 `=+` 使用时有用，用于移除所有权限。

*permissions* 以下字母的任意组合：

+ `r` 读取权限。
+ `w` 写入权限。
+ `x` 执行权限。
+ `l` 强制设置 ID（Mandatory set-ID）。
+ `s` 用户或组 ID（Setuser-ID）。
+ `t` 粘滞位（Sticky bit）。
+ `u,g,o` 从当前用户、组或其他模式中获取权限。

文件的权限取决于你的用户标识或组标识 (`GID`)。权限描述以三组序列描述，每组包含三个字符。下面的示例显示了每个权限组的访问类以及权限本身。它赋予了用户、组和其他人读取、写入和执行给定文件的权限。

| 用户 | 其他人 |
| :--- | :--- |
| rwx | rwx |

字母 `s` 仅在 `u` 或 `g` 时才有意义，且 `t` 仅对 `u` 起作用。强制文件和记录锁定是指在程序访问该文件时锁定该文件读取或写入权限的能力。在设置了 set-group-id 位目录（在 `ls -1ld` 输出中显示为 --- 或 -----）中，创建的文件和子目录具有父目录的 set-group-id，而不是当前进程的。

你不能同时授予组执行权限并允许文件被锁定。此外，你不能同时开启 set-group-id 位并允许在执行时被锁定。以下示例是无效的并会导致错误消息。

```bash
chmod g+x,+1 file
```

```bash
chmod g+s,+1 file
```
