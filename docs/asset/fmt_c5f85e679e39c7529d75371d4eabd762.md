## base64

`base64` 模块用于使用 `base64`、`base32` 或 `base16` 编码将二进制数据编码和解码为文本。Base64 常用于在邮件附件中嵌入二进制数据以及 HTTP 协议部分。官方细节可参见 `RFC-3548` 和 `RFC-1421`。

Base64 编码的工作是将待编码的数据分组为每 24 位（3 字节）。每个 24 位组被细分为四个 6 位组件。每个 6 位值由以下字母表中的打印 ASCII 字符表示：

| 值 | 编码 |
| :--- | :--- |
| 0-25 | ABCDEFGHIJKLMNOP |
| 26-51 | abcdefghijklmnopqrstuvwxyz |
| 52-61 | 0123456789 |
| 62 | + |
| 63 | / |
| pad | = |

如果输入流中的字节数不是 3（24 位）的倍数，则填充数据形成完整的 24 位组。额外的填充由编码结尾的 '=' 字符指示。例如，如果是一个 16 字节字符序列，有 5 个 3 字节组，剩余 1 字节。剩余字节被填充形成 3 字节组。该组产生两个来自 base 64 字母表的字符（前 12 位，其中包含 8 位真实数据），随后是 '=' 序列，表示填充位。有效的 base64 编码在结尾仅有零、一个 (=）或两个（==）填充字符。

Base 32 编码通过将二进制数据分组为每组40位（5字节）一组来工作。每个 40 位组被细分为八个 5 位组件。每个 5 位值然后使用以下字母表进行编码：

| 值 | 编码 |
| :--- | :--- |
| 0-25 | ABCDEFGHIJKQRSTUVWXYZ |
| 26-31 | 2-7 |

与 base 64 类似，如果输入流没有形成一个 40 位组，则将其填充到 40 位，并在输出中使用 't' 字符表示额外的填充。由于会有六个填充字符（'======'），这在最后一个组仅包含 1 字节数据时就会发生。

Base 16 编码是数据的标准十六进制编码。每个 4 位组由数字 '0'-'9' 和字母 'A'-'F' 表示。base 16 编码没有额外的填充或填充字符。

```
b64encode(s, altchars)
```

使用 base 64 编码对字节字符串 `s`。如果给了 `altchars`，它是一个两个字符的字符串，用于指定替代字符来替换通常出现在 base 64 输出中的 '+' 和 '/'。如果 base 64 编码被用于文件名或 URL，则此输出非常有用。

```
b64decode(s, altchars)
```

解码 `s`（`s` 是用 base 64 编码的），并返回一个包含解码数据的字符串。如果给了 `altchars`，它是一个两个字符的字符串，用于指定 base–64 数据中出现的 '+' 和 '/' 的替代字符。如果输入 `s` 包含多余字符或填充不正确，则抛出 `TypeError`。

```
standard_b64encode(s)
```

使用标准的 base 64 编码对字节字符串 `s`。

```
standard_b64decode(s)
```

使用标准 base 64 编码解码 `s`。

```
urlsafe_b64encode(s)
```

使用 base 64 编码对字节字符串 `s`，但分别使用 '-' 和 '_' 代替 '+' 和 '/'。这与 `b64encode(s, '-_')` 相同。

```
urlsafe_b64decode(s)
```

解码用 URL 安全 base 64 编码的 `s`。

```
b32encode(s)
```

使用 base 32 编码对字节字符串 `s`。

```
b32decode(s, casefold, map01])
```

使用 base 32 编码解码 `s`。如果 `casefold` 为 True，则可能会出现大写和小写字母（默认值）。如果存在 `map01`，则指定数字 1 映射到哪个字母（例如，字母 'I' 或字母 'L'）。如果给了此参数，数字 '0' 也会映射到字母 '01'。如果输入字符串包含多余字符或填充不正确，则抛出 `TypeError`。

```
b16encode(s)
```

使用 base 16（十六进制）编码对字节字符串 `s`。

```
b16decode(s [, casefold)
```

使用 base 16（十六进制）编码解码字符串 `s`。如果 `casefold` 为 True，字母可以是大写的，也可以是小写的。否则，十六进制字母 'A'-'F' 必须是大写的（默认）。如果输入字符串包含多余字符或以任何方式格式化错误，则抛出 `TypeError`。

以下函数是旧版 base 64 模块接口的一部分，你可能在使用 Python 代码时看到它们：

```

```

解码 base 64 编码的数据。`input` 是一个文件名或用于读取的文件对象。`output` 是一个用于二进制模式写入的文件名或文件对象。

```

```

解码 base 64 编码的字符串 `s`。返回一个包含解码后二进制数据的字符串。

```

```

使用 base 64 编码数据。`input` 是一个用于二进制模式读取的文件名或文件对象。`output` 是一个用于写入的文件名或文件对象。

```

```

# binascii

`binascii` 模块包含低级函数，用于在二进制数据与多种 ASCII 编码（如 base 64、BinHex 和 UUEncoding）之间转换数据。

```
a2b_uu(s)
```

将一行 uencoded 文本 `s` 转换为二进制并返回一个字节字符串。行通常包含 45（二进制）字节，但较短的行除外。行数据后面可能会跟随空白字符。

```
b2a_uu(data)
```

将二进制数据字符串转换为一行 uencoded ASCII 字符。`data` 的长度不应超过 45 字节。否则将抛出 `Error` 异常。

```
a2b_base64(string)
```

将 base 64 编码的文本字符串转换为二进制并返回一个字节字符串。

```
b2a_base64(data)
```

将二进制数据字符串转换为一行 base 64 编码的 ASCII 字符。如果生成的输出要通过电子邮件传输，`data` 的长度不应超过 57 字节（否则可能会被截断）。
