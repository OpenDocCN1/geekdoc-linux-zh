## `roffbib` — 格式化并打印参考文献数据库

### 概要

```
/usr/bin/roffbib [-e] [-m filename] [-np] [-olist] [-Q] [-raN] [-sN] [-Tterm] [-V] [-x] [filename]...
```

### 描述

使用 `roffbib` 命令以参考文献格式打印数据库中的所有记录，而不是作为脚注和尾注。通常，`roffbib` 与 `sortbib(1)` 配合使用。

```
castle% sortbib database | roffbib
```

### 1127

### 选项

`roffbib` 接受 `nroff(1)` 理解的所有选项，但 `-i` 和 `-q` 除外。

- `-e`

  在调整行中产生等间距的单词，并使用全终端分辨率。

- `-h`

  使用输出制表符（Tabs）进行水平间隔以加速输出并减少输出字符数。假设制表设置为每 8 个标准字符宽度。

- `-m filename`

  在输入文件开头加上宏文件 `/usr/share/lib/tmac/tmac.name`。在 `-m` 和宏文件名之间留一个空格。这组宏替换了在 `/usr/share/lib/tmac/tmac.bib` 中定义的宏。

- `-np`

  在逗号分隔的数字列表中开头加上第一个数字。范围 `N-M` 表示从第 N 页到 M 页；初始 `-N` 表示从开始到第 N 页；末尾 `N-` 表示从第 N 页到结束。

- `-Q`

  为排版机排队输出。将页边距设为 1 英寸。

- `-raN`

  将寄存器（单个字符）设为 N。命令行参数 `-rN1` 使引用从 1 开始编号。

四个命令行寄存器控制参考文献列表的格式样式，类似于 `ms(5)` 的数字寄存器。标志 `-rV2` 使参考文献列表双行间距，而 `-rV1` 使引用部分双行间距，注释段落使用单行间距。你可以通过 `-rLI6` 将行长度从默认的 6.5 英寸改为 6 英寸，并通过指定 `-rOI`（大写 O，不是 0）将页边距从默认的 0 设置为 1 英寸。

- `-sN`

  每 N 页停止一次以加载或更改页面（默认 N=1）。要继续，请按回车键或 Return。

- `-Tterm`

  指定终端类型。

- `-V`

  将输出发送到 Versacet。将页边距设为 1 英寸。

- `-x`

  如果在 `%x` 字段键后输入摘要或注释，`roffbib` 将其格式化为带注释的参考文献段落。如果你需要多个注释段落，可以使用多个 `%x` 字段。

### 文件

```

```

`nroff.troff` 使用的宏文件。

## `rpcgen` — RPC 协议编译器

### 概要

```
/usr/bin/rpcgen infile
/usr/bin/rpcgen [-a][-b][-L][-N][-C][-Dname = value][ -i size]
[-I [-K seconds] [-L] [-M] [-T] [-Y pathname] infile
/usr/bin/rpcgen [-c -h] [-l -m -t -Sc -Ss -Sm]
[-o outfile][infile] [infile]
/usr/bin/rpcgen [-s netype][-o outfile] [infile]
/usr/bin/rpcgen [-n netid] [-o outfile] [infile]
```

### 描述

`rpcgen` 命令是一个用于生成 C 代码以实现远程过程调用（RPC）协议的工具。`rpcgen` 的输入是一种名为 RPC 语言（远程过程调用语言）的类 C 语言。`rpcgen` 通常用于第一个概要，它接受一个输入文件 `infile` 并生成输出文件。如果 `infile` 文件名为 `proto.x`，则 `rpcgen` 在 `proto.h` 中生成头文件，在 `proto_xdr.c` 中生成 XDR 程序，在 `proto_svc.c` 中生成服务端存根，在 `proto_clnt.c` 中生成客户端存根。通过 `-T` 选项，`rpcgen` 在 `proto_tbl.i` 中生成 RPC 分发表。`rpcgen` 可以生成示例客户端和服务器文件，并根据特定应用程序进行自定义。`-Sc`、`-Ss` 和 `-Sm` 选项生成示例客户端、服务器和 makefile。`-a` 选项生成所有文件，包括示例文件。如果 `infile` 是 `proto.x`，则客户端示例被写入 `proto_client.c`，示例 makefile 写入 `makefile.proto`。

创建的服务器既可以通过端口监控器（例如 `inetd` 或 `listen`）启动，也可以自己启动。当服务器由端口监控器启动时，它会为传递描述符 0 的传输创建服务器。你必须通过设置 `PM_TRANSPORT` 环境变量来指定传输名称。当执行 `rpcgen` 生成的传输时，它会为 `NETPATH` 环境变量指定的所有传输创建服务器句柄；如果未设置，则会为从 `/etc/netconfig` 可见的所有传输创建服务器句柄。

注意 — 传输是在运行时选择的，而不是在编译时。当服务器自启动时，默认会将自己放在后台。你可以使用特殊的定义符号 `RPC_SVC_FG` 在前台运行服务器进程。

第二个概要提供了允许创建更复杂的 RPC 服务器的特殊功能。这些功能包括对用户提供的 `#defines` 和 RPC 分发表的支持。RPC 分发表中的条目包含：

- 指向对应过程的服务例程的指针。
- 指向输入和输出的指针。

### 选项

- `-a`

  生成所有文件，包括示例文件。

- `-A`

  在服务器中启用自动 MT 模式。在这种模式下，RPC 库会自动创建线程处理请求。此选项通过隐含开启 `-M` 选项生成线程安全的存根。你可以通过 `rpc_control(3)` 调用设置多线程模式。

- `-b`

  为旧版本的操作系统生成特定的 RPC 代码。

- `-c`

  编译为 XDR 程序。

- `-C`

  生成可用于 ANSI 编译器的头文件和存根文件。你也可以在 C++ 程序中使用该选项生成的头文件。

- `-DName=[value]`

  定义符号。相当于源代码中的 `#define`。如果你未指定值，则值为 1。你可以多次指定此选项。

- `-h`

  编译为 C 定义（头文件）。你可以将此选项与 `-T` 选项配合使用，产生支持 RPC 分发表的头文件。

- `-i size`

  指定内联代码的大小。此选项有助于优化。默认大小为 5。
