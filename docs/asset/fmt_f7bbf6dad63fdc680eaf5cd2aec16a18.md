
```bash
$ /sbin/chkconfig --list | grep '5:on' | sort
anacron 0:off 1:off 2:on  3:on  4:on  5:on 6:off
apd    0:off 1:off 2:on  3:on  4:on  5:on 6:off
atd    0:off 1:off 2:off 3:on  4:on  5:on 6:off
autofs 0:off 1:off 2:off 3:on  4:on  5:on 6:off
canna  0:off 1:off 2:off  3:on  4:on  5:on 6:off
crond  0:off 1:off 2:off  3:on  4:on  5:on 6:off
```

并不是所有输出都显示在这里，但正如你所看到的，`chkconfig`可以显示每个服务在每个运行级别下的`off`或`on`值。示例输出仅显示了将在运行级别5中启动的服务。`chkconfig`命令可用于为每个运行级别和每个服务分配启动或停止值。例如，为了在运行级别5下使用Red Linux时，修改脚本以启动电源管理（由`/etc/rc.d/init.d`下的`apd`脚本控制），可以使用如下`chkconfig`命令：

```bash
# chkconfig --level 5 apmd
```

你可以通过如下方式再次`grep`过滤`chkconfig`的输出来验证此操作：

```bash
# chkconfig --list | grep apmd
apmd    0:off 1:off 2:on  3:on  4:on  5:on 6:off
```

`chkconfig`命令本身并不启动或停止服务，只是修改脚本以执行这些操作或报告服务状态。可以使用`--level`选项修改当前运行级别或其他运行级别。你可以按照本章稍后描述的内容使用`chkconfig`命令实际启动或停止服务。所有这些工具都有非常有用的帮助文档（man pages），可以帮助你回顾所有可用选项。

`sysconfig`是一个你可以用来访问`chkconfig`的图形化界面，它是一个基于`curses`的界面，这意味着它提供了可以通过选择并按下空格键来切换的图形元素（见图7.1）。当打开`sysconfig`时，你可以滚动服务列表并按空格键关闭某个服务。完成后，使用`Tab`键高亮显示OK（确定）或Cancel（取消）按钮。你的更改将在下次Red Hat Linux启动时保存并生效。`sysconfig`使用简单，对于没有X系统的系统来说是一个极佳的工具，但它只适用于你当前所处的运行级别。

# 手动启动和停止服务

在运行Red Linux时，有几种方法可以手动停止服务或更改运行级别。如果你更改了服务的配置文件，通常需要重启该服务以读取新配置。如果你正在重新配置X服务器，通常将运行级别5切换到运行级别3以便测试，然后返回运行级别5以启用图形登录。如果服务配置不当，停止并重启它是更容易；在配置正确之前，你需要重启机器。

手动管理服务（以root身份）传统方法是在命令行调用服务的`/etc/rc.d/init.d`名称，并带有相应的关键字（如start或stop）。例如，为了启动电源管理，如下所示调用`/etc/rc.d/init.d/apm`脚本：

```bash
# /etc/rc.d/init.d/apm start
```

脚本将执行程序并报告其状态。停止服务同样简单，事实上，你可以通过`status`关键字如下检查服务状态：

```bash
# /etc/rc.d/init.d/apm status
apm (pid 3156) is running...
```

在此示例中，`apm`脚本报告正在运行并显示其ID。此信息对于其他系统管理任务可能有用。

手动启动或停止服务的简单简单方法是使用`service`名称。使用`service`时不需要知道服务的完整路径；只需要操作的服务名称。使用这种方法，之前的自动化电源管理示例如下：

```bash
# service apmd start
Starting up APM daemon:             [ OK ]
```

当然，之前提到的GUI工具也具有在当前运行级别启动和停止特定服务的功能。选择哪种工具取决于个人偏好；优秀的系统管理员应该熟悉所有工具。

# 使用服务管理排查 Red Hat Linux 中的问题

在使用Red Hat Linux时，除非发生某些灾难，否则在特定的运行级别下重新排序或更改系统服务是必要的。但系统管理员必须对Linux如何启动以及如何控制服务有基本的了解，以便进行故障排除或诊断问题。通过使用额外的工具（例如使用`dmesg | less`命令在启动后读取内核输出，或通过`cat /var/log/messages | less`检查系统日志），在遇到故障的驱动程序或服务失败时，可以获取更多细节。

为了更好地了解如何排查Red Hat Linux中的问题，请查看一个典型服务相关问题的诊断和解决。在这个示例中，X无法启动：你看不到桌面，计算机对键盘输入没有响应。X服务器可能挂起在循环中、失败，或者退出到shell提示符而没有任何错误消息。X服务器仅在运行级别5中尝试重启自身，因此要确定服务器是否在循环中，请切换到运行级别3。

> 提示
>
> 如果你正在多用户系统上工作并可能无意中中断用户的工作，请他们保存当前工作；然后切换到更安全的运行级别，例如单用户模式。

通过Ctrl+Alt+F2切换到另一个虚拟控制台，以root身份登录并运行命令`telinit 3`来进入运行级别3。切换到运行级别3将停止X服务器尝试重启。现在你可以轻松地检查X服务器并尝试修复它。首先，尝试“裸运行”启动X服务器（不启动窗口管理器）。如果你成功了，将看到一个中间有一个大字母X的灰色屏幕。如果是这样，使用Ctrl+Alt+Backspace组合键杀死X，并根据你选择的窗口管理器查看你的窗口管理器配置。假设X无法“裸运行”。如果我们查看XFree6的日志（它在`/var/log`目录下有明确的标识），我们将关注任何以`(EE)`（特殊错误代码）开头的内容。如果家目录下存在此类文件，我们还可以检查`sessions-error`日志文件。如果我们发现错误，原因可能对我们来说显而易见，也可能不是。Linux社区的迷之处在于，你可能是第一个遇到该错误的人。将错误信息（其中的一个唯一部分）输入http://www.google.com/linux，发现其他人对该问题的看法。你可能需要调整搜索以获得可用的结果，但那种程度的细节已超出了本章的范围。修复X配置并运行`startx`启动X。根据需要重复。

> 注意
>
> 在对任何配置文件进行任何更改之前，务必对原始未修改的文件创建一个备份副本。我们的做法是在副本后添加扩展名`.original`，因为这是一个唯一且无歧的标识符。如果你需要恢复原始配置文件，不要重命名它，而是将其复制回原始名称。当这个建议为你节省了时间和精力的时——你可以通过给朋友买一本来表达你的感谢。当然，你应该始终咨询XFree6文档。它位于你电脑的`/usr/share/doc/`目录下，与你系统中安装的大量其他信息在一起。
