
`lpr` 和 `one` 之间的格式可以使用原生的打印机语言。幸运的是，大多数常见的打印机都支持 `Ghostscript`。

`UNIX` 和 `LINUX` 中使用的另外两种主要格式是 `troff` 和 `DVI`。

`troff` 和 `groff` 格式最常用于帮助手册（`man pages`）。`GNU groff` 软件包提供了对打印和显示这些文件的支持。使用 `troff` 文件的最简单方法是让“magic”过滤器通过 `groff` 过滤器（`gro` 到 `PostScript` 的转换）。还有一个名为 `grovi` 的过滤器，可以从 `troff` 源码生成 `DVI` 格式的输出。

`DVI`（设备缩进）文件由 `TeX`、`\LaTeX` 和其他程序生成。许多打印机都有直接的 `DVI` 驱动程序。这种 diabase（`TeTeX` 称之为）直接支持几乎任何打印机，而 `Ghostview`（以及 `dvips` 命令/过滤器允许 `DVI` 文件轻松地被任何 `PostScript` 打印机打印，或发送到任何 `Ghostview` 打印队列）。

为了减少纸张浪费，可以使用 `mpage` 强制每张纸打印两页、四页或八页纯文本文件——实际上是每张纸的双面。`mpage` 有许多选项，并以 `Postscript` 格式输出输出。

有一组 `putils` 可以强制 `PostScript` 页面进行多页打印。这并不是一个困难的技巧，因为 `PostScript` 编程语言支持缩放、旋转和平移原语。即使在常见的单面（单侧）打印机上，也可以通过两次通过相同的纸，交替过滤掉偶数页，来强制双面打印（在每页的两面都打印）。

为了预览文件（另一种减少纸张和碳粉——或非激光打印机的墨水浪费的方法），`X Window` 系统有 `thevi`、`ghostview` 和 `g` 程序。`g` 特别适合查看 `PostScript` 文档并选择要打印的页面子。

## 远程打印

当 `lpd` 接收到发往远程打印机的任务时，它将使用 `TCP` 套接字与 `printcap` 条目中 `rm` 字段指定的主机上的 `lpd` 守护进程建立连接。

在 `lpd` 守护进程确认接收任务后，本地 `lpd` 守护进程会从队列目录删除文件。`lpd` 守护进程运行在 `Unix` 主机上还是网络打印机上与本地 `lpd` 守护进程无关。

## 管理命令

`LINUX` 包含了 `BSD` 管理打印命令。`lpq` 列出由 `lpr` 汇存并仍在等待 `lpd` 处理的队列打印任务。`lprm` 从队列中删除任务。`lpc` 执行其他管理打印职责。

- 8. 作者在本书卷的制作过程中大量使用了这些程序。

## `lpq`

`lpq` 命令检查汇存区域并报告它找到的打印任务。`lpq` 报告的任务号是使用 `lpr` 杀死打印任务时所需的。

要检查的打印机可以使用 `-P` 选项指定，类似于 `lpr`。如果未指定，则会检查默认打印机的队列——由 `PR` 环境变量定义的打印机，如果未定义则使用 `lp`。`-l` 选项提供长格式的信息。

## `lprm`

`lprm` 命令从队列中删除打印任务。与其他打印命令一样，使用 `-P` 选项来指定打印机；否则假设使用默认打印机。命令行上指定的一个或多个数字参数将解释为任务号。可以使用 `lpq` 命令获取打印队列中任务的数字。包含非数字字符的参数被解释为用户 ID，其任务将从队列中删除。

## `lpc`

所有与现有打印机相关的其他管理任务都由 `lpc` 命令执行，该命令接受多种命令选项。或者，可以不带选项调用 `lpc`，在这种情况下它以交互模式运行，在自己的提示符下接受命令。

系统管理员可以使用 `lpc` 停止和启动打印机，并启用和禁用队列。遗憾的是，`lpc` 有许多名称相似且执行操作的命令。此外，它只能控制本地主机上的队列——没有控制远程打印队列的机制。

`lpc` 接受一个特别没用的 `-l` 命令。大多数其他命令接受单个参数，即打印机名称或 `-a` 关键字。（打印机绝不应命名为 `all`。）

其他命令见表 19.1。

由于 `lpc` 众所周知地不可靠，使用它解决问题的可能还不如完全重启打印系统。可以使用命令：

```
/etc/rc.init.d/lpd stop
/etc/rc.init.d/lpd start
```

与其他大多数守护进程一样，在发布这些命令之前，在另一个窗口或另一个虚拟控制台上运行命令

```
tail -f /var/log/messages
```

是查看进程错误信息的好方法。

## 表 19.1 `lpc` 命令

| `abort` | 杀死活动汇存守护进程并禁用指定打印机上的打印。 |

## 添加打印机

添加打印机时有几个步骤：

- 物理上将打印机连接到主机。
- 如果打印机连接到网络，确保 `lpd` 启动。
- 如果打印机直接连接，配置其主机名、IP 地址等，如文档所示。
- 创建汇存目录，确保相应的权限。
- 向 `printcap` 文件添加相应的条目。

## 安全

大多数打印套件的安装依赖于使用 `RFC179` 定义的端口验证。有很多的技术可以破解这种安全机制——它本质上是不安全的。传统的 `lpd` 守护进程尽管依赖不安全的验证通常以 `root` 身份安装。

`Linux` 提供了一种新的 `RFC179` 实现。它被称为 `LPRng`（下一代），并解决了旧实现的安全问题。特别是，`LPRng` 的 `lpd` 不需要以 `root` 身份安装。

## 诊断

在最简单的情况下，打印是将数据（作为纯文本）复制到某些接口（通常是并行端口）。在某些情况下，我们可以通过发布命令来测试打印系统的底层组件：

```
cat /tmp/foo > /dev/lp0
```

没有输出有几个原因。打印机可能没有连接到 `lp0`。它可能是旧的串口打印机（近年来并不常见）或 `USB` 设备。它可能只是位于 `/dev/lp1` 或 `lp2` 或其他并行端口。有时 `lpd` 检测端口的顺序与同一系统上的操作系统不同。`Linux` 下的 `MS-DOS` `PRN` 或 `LPT1` 并不一定对应 `lp0`。

## 诊断 227

与 `lp` 设备类似，而 2.2 及以后的内核使用 `usport` 驱动程序。这部分内容是为了标准化除 PC（`x86` 架构计算机）以外系统上并行端口的处理。

当然，打印机可能处于离线状态（一种它无法接受任何作业的模式）。许多打印机带有控制面板或一组按钮，可用于在各种模式之间进行切换，包括“就绪”和“离线”模式。某些打印机还带有 `LED` 或其他模式和状态指示灯。许多打印机在缺纸、色带用尽、喷墨打印机墨盒耗尽或硒粉用尽、进纸机构卡纸或遇到其他问题时，会切换到“离线”模式。

计算机内部的接口也可能错误或损坏。通常有一根从接口卡到计算机机箱连接器的电缆。`PC` 上的并行端口也会遇到与这些系统中其他设备类似的 `IRQ` 和 `I/O` 端口冲突。以太网适配器和声卡因引入此类冲突而臭名昭著。另一个偶尔出现与系统与打印机之间的电缆有关。可能是故障的，或者其“引脚定义”（一端到另一端的线连接设置）错误。

在尝试设置新打印机或排查 `Linux` 打印机问题时，这里是起点。使用最简单的命令（`cat`）直接与设备（`/dev/lp0`）通信。在它生效之前，其他任何方法都不可行。

如果 `cat` 重定向到相应的 `/dev/lp1` 设备节点不起作用，则需要编译一个链接了适当 `lp` 或 `parport` 驱动程序的内核。这是消除动态内核模块子系统（2.0 内核使用 `kernel2`，或 2.2 及以后的内核使用 `kmod`）中任何可能问题的常用技术。

`Linux` 打印子系统（包括 `lpr1` 和 `LPRng`）对与它们涉及的目录和文件的权限及所有权极其敏感。正如我们所描述的，这些子系统具有“活动部分”，所有部分都必须正确协调才能使任何功能正常。

诊断打印问题的关键通常是从基础开始。确保简单文件使用 `cat` 命令。在打印机必须具有特定格式（非文本）的输入的情况下，可以手动将数据通过适当的过滤器并将其重定向到临时文件，从而通过管道将 `lpr` 和 `printcap` 文件中指定的任何魔法过滤器连接起来。然后将临时文件传输到适当的主机（使用 `FTP` 或其他任何工具），并将其 `cat` 到适当的设备/端口。
