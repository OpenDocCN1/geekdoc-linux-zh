
# `fdisk /dev/da2`

正在处理设备 `/dev/da2`

从磁盘提取的参数：

```
cylinders=1116 heads=255 sectors/track=63 (16065 blks/cyl)
```

- 数字不适用于 BIOS 计算：
  `cyl=1116 heads=255 sectors/track=63 (16065 blks/cyl)`
- 介质扇区大小为 512
- 警告：BIOS 扇区编号从 1 开始

引导块的信息：

- 分区 1 的数据为：
  `sysid=166 (0xa5),(FreeBSD/NetBSD/38685)`
  `start=63; size=1728247 (8754 Meg), flag=80 (active)`
  `beg: cyl/0 head/0 sector 63`
  `end: cyl/103 head/254/ sector 63`
- 分区 2 的数据为：`<未使用>`
- 分区 3 的数据为：`<未使用>`
- 分区 4 的数据为：`<未使用>`

随后，我们看到了磁盘上四个可能的切片的信息。我们的第一个分区被标记为 FreeBSD。每个操作系统都有唯一的切片标识符，`165` 表示这是一个 FreeBSD 切片。切片 1 开始于扇区 63——内存，MBR 占据了第一个柱面上的第一个磁头，即扇区 1 到 62。切片 1 填充了 17,928,477 个扇区，结束于点 扇区 17,928,539（17,928,477+62=17,928,539）。磁盘总共有 17,928,540 个扇区，但不要忘记 MBR。

我们还看到数百万个扇区被分配了这个切片。一个令人生恼的问题是，MBR 的切片标识位中只能识别每个磁盘最多 1024 个柱面（这种限制导致了硬盘的 504MB 限制）。这块磁盘的柱面数量远多于此！这意味着你不能通过每个单独分区的柱面数量来衡量磁盘。唯一有数字是扇区的数量。

最后，2、3 和 4 是未分配的。

## 备份切片表

在更改磁盘上的切片表之前，请备份旧的切片表。这让你可以将磁盘恢复到之前的配置。要备份切片表，使用 `fdisk(8)` 的 `-p` 标记：

```
# fdisk -p /dev/da0 dao.slice.backup
```

要从备份恢复磁盘的切片表，请使用 `-f` 标记和备份文件名：

```
# fdisk -f dao.slice.backup /dev/da0
```

如果你在重新划分切片后没有动过硬盘，你可能会找回数据。大多数情况下，恢复切片表不会恢复这些切片中的数据，仅恢复磁盘配置。你必须从备份中恢复数据。

## 修改切片表

`fdisk(8)` 不仅允许你查看表格，还可以通过交互式或脚本进行编辑。初始化一个新的 FreeBSD 磁盘最简单的方法是告诉 `fdisk(8)` 将其标记为一个专门用于 FreeBSD 的单一切片。这非常常见，因此 `fdisk` 的 `-B` 标记专门用于此操作。在重新开始时，FreeBSD 始终是一个好主意。在这里，我们重新初始化 SCSI 切片 `/dev/da17` 以具有单个 FreeBSD 分区：

```
# fdisk -BI /dev/da17
```

你也可以按照 `fdisk(8)` 备份切片表时使用的格式编写自定义的切片表，并像恢复备份一样将该切片写入磁盘。这对于大多数用户来说通常是不可行的。

如果你使用备份文件，`fdisk(8)` 会假设你清楚自己在做什么——即使你显然并不清楚。`fdisk(8)` 包含一个交互模式，可以自动检测许多微妙的错误状况，并提供不会弄乱你硬盘的替代方案。我建议始终使用交互式模式来编辑切片。`-u` 标记进入 `fdisk(8)` 的交互模式。

记住，第 8 章中涵盖了使用 `sysinstall` 对硬盘进行重新划分、重新分区和格式化。由于某种原因，`sysinstall` 中的 `fdisk(8)` 可能无法工作，或者如果你对该过程有更详细的控制需求。

## 磁盘与数学

在处理 `fdisk(8)` 和 `disklabel(8)` 时，尽可能在草稿纸上预先完成数学计算。如果你必须在过程中进行更多数学计算，也请在草稿上进行。磁盘管理使用数字，你应该把宝贵的脑力花在确保数字准确上，而不是操作它们。简单的加、减、除法似乎看起来很容易，但大多数磁盘配置错误都是由三年级数学错误引起的。在之前写下所有数字，你将避免以后发现自己不会做三年级数学的尴尬。

让我们使用 `fdisk(8)` 将我们的示例硬盘分成两个大致相等的切片。我们知道这块硬盘有 17,928,477 个扇区。这意味着每个切片应该大约 8,964,238 个扇区。

`fdisk` 打印几何结构信息，并询问你是否想更改磁盘几何结构。除非你对特定的磁盘有彻底、深入的了解，否则更改几何结构总是个坏主意，所以先不管它：

> 你想要更改我们对 BIOS 想法的看法吗？[n] n

你将得到第一个切片的配置打印，并被问是否想更改它：

> 分区 1 的数据为：
> sysid 165 (0xa5), FreeBSD/NetBSD/386BSD
> start 63, 17928477 (8754 Meg), flag 80 (active)
> beg: cyl 0/ head 1/ sector 1;
> end: cyl 1023/ head 254/ sector 63
> 你想更改它吗？[n] y

今天，切片 1 使用了磁盘上所有的扇区。我们要减少切片 1 的扇区数量，并将剩余部分分配切片 2。切片 1 开始于扇区 63，使用大约 8,964,238 个扇区。我们只需要告诉 `fdisk(8)`。按回车进入默认值：

- 为 "sysid" 提供十进制值 (165=FreeBSD) [165]
- 为 "start" 提供十进制值 [63]
- 为 "size" 提供十进制值 [17928477]
- `fdisk: WARNING: partition未在柱面上结束`
- `fdisk: WARNING 可能会误导 BIOS 或某些系统`
- 自动修正？[n]
- `fdisk: WARNING: 调整分区大小为 8964207`
- 显式指定起始地址？[n]
  `sysid 165 (0xa5), FreeBSD/NetBSD/386BSD`
  `start 63, 8964207 (4377 Meg), flag 80 (active)`
  `beg: cyl 0/ head 1/ sector 1`
  `end: 557/ head 254/ sector 63`

我们对这个结果满意吗？我们将就在 FreeBSD 认为应该的地方切分，但更改切片中的扇区数量。`fdisk(8)` 进行了一些计算，并指出此切片没有整齐地结束在柱面上。你计算的切片大小落在柱面边界上的概率微乎其微。切片可能会出问题，特别是当你有一台多频机器时。始终让 `fdisk(8)` 修正这个问题。

`disklabel(8)` 提供了原生的磁盘标签管理。如果你正在一个不熟悉的硬件架构上工作，请务必在尝试编辑磁盘之前仔细阅读 `disklabel(8)`。

## 读取磁盘标签

要查看分片的标签，请将设备的设备名称作为参数运行 `disklabel(8)`。例如，磁盘 `ad0` 上的分片 1 为 `/dev/ad0s1`：

```
# disklabel /dev/ad0s1
# /dev/ad0s1:
# 8 partitions:
# size offset ftype size offset bps/cpg
a: 1048576 0 4.2BSDS 2048 16384 8
b: 2097152 1048576 swap
c: 3917989 0 unused 0 0 # "raw" 部分，不要编辑
d: 10485760 3145728 4.2BSDS 2048 16384 28552
e: 2097152 13613488 4.2BSDS 2048 16384 28552
f: 23451249 17528640 4.2BSDS 2048 16384 28552
```

磁盘标签显示该分片支持最多八个分区，尽管只配置了六个。分区由字母 `a` 到 `h` 命名。虽然分片支持“最多八个分区”，但这并不意味着你真的能从新磁盘中获得可用的分区。传统上，`a` 分区是根分区。你可以将其用于普通数据，但我倾向于不要让自己混淆。`b` 分区传统上是交换空间。FreeBSD 只对在 `/etc/fstab` 中标记为 swap 的分区进行交换，你可以打赌当我在凌晨 3 点排查故障时，会有一个 `b` 分区用于数据使用。最后，`c` 分区是整个分片的标签。虽然 FreeBSD 不再需要 `c` 分区，但这并不意味着我可能使用的所有插件都能理解带有数据的 `c` 分区！这意味着你的根磁盘上最多可以六个分区（`d` 到 `h`，可能还有 `a`）。

每个分区在分片的开头都有大小。偏移量是分区开始的距离。记住，计数从 0 开始。分区 `c` 覆盖整个磁盘，大小为 39,179,888，偏移量为 0。在这个示例中，`a` 分区的大小为 1,048,576，偏移量为 0。根分区是第一个。分区 `b` 从分片的 1,048,576 扇区处开始，紧接分片 `a` 之后，大小为 2,097,152。如果分区 `b` 占据 2,097,152 个扇区，那么下一个分区必须从 3,145,728 处开始（1,048,576 + 2,097,152）。查看分区 `d` 的偏移量。这些都是基础加法。

每个分区都需要文件系统类型。FreeBSD 中通常使用的文件系统类型只有 `4.2bsd`（任何 FreeBSD 文件系统如 UFS 或 UFS2）、`swap`（用于交换空间）或 `unused`（用于 `c` 分区或空区域）。FreeBSD 支持其他文件系统类型，但在你的 FreeBSD 硬盘中间插入 FAT 或 CD 文件系统是非常罕见的，而且你可能永远不会看到一个中间夹着第六版分区的磁盘。

接下来的两列给出了 UFS 和 UFS2 文件系统的碎片和块的大小。FreeBSD 默认使用 16KB 块和 2KB 碎片。我们在第 8 章中讨论过 UFS2 的设计。这些默认值在现代系统上是一个很好的平均值。如果你有一个只存放异常大小文件的特殊文件系统，你可能想要更改块大小。例如，如果你的应用程序使用了数百万个每个 6KB 的文件，那么将块大小改为 8KB 是有意义的。最小大小为 4KB。如果你的应用程序只使用几个文件，但它们大得惊人，你可能想使用 32KB 或 64KB 的块。然而，有一个警告：FreeBSD 期望分块大小恰好是块大小的八分之一。使用任何其他比例的块与碎片都会降低性能。

最后一列给出了该文件系统中柱面组的柱面数量。始终、始终，我的意思是“转换”——即硬盘和操作系统对磁盘几何结构执行的操作，而且你无法通过更改柱面组信息来做任何有用的事情，就让它保持吧。

现在你理解了磁盘标签，让我们来自己创建一个。

## 备份和恢复磁盘标签

在执行任何操作之前，先将当前磁盘标签备份到文件中：

```
# disklabel /dev/da0s1 > da0s1.label.backup
```

有了这个文件，你可以使用 `disklabel` 的 `-R` 标志将磁盘标签恢复到之前的状态：

```
# disklabel -R /dev/da0s1 da0s1.label.backup
```

阿布拉卡达！你的旧磁盘标签已经恢复！

## 编辑磁盘标签

要在分片上创建或重新排列分区，请更改磁盘标签。更改磁盘标签会破坏分片上的分区。这意味着该磁盘上的任何数据都将丢失。我建议只在没有数据的新磁盘上或有备份的磁盘上编辑磁盘标签。你不能在挂载了分区的分片上编辑磁盘标签。例如，这里是我测试磁盘之一的磁盘标签：

```
# disklabel /dev/ad0s1
# /dev/ad0s1:
# 8 partitions:
# size offset ftype size offset bps/cpg
c: 3917989 0 unused 0 0 # "raw" 部分，不要编辑
d: 10485760 3145728 4.2BSDS 2048 16384 28552
```

决定你想如何对此磁盘分区。根据 `disklabel(8)`，该分片有 675MB 的空闲空间。我想要 1GB 的交换空间，2GB 的分区，以及第四个分区包含所有剩余空间（5GB 或少）。所有这些分区都使用标准块大小。现在，使用 `-e` 标志编辑磁盘标签，你将在文本编辑器中获得磁盘标签的副本。要创建四个分区，磁盘标签看起来如下：

```
# disklabel /dev/ad0s1
# /dev/ad0s1:
# 8 partitions:
# size offset ftype size offset bps/cpg
a: 1048576 0 4.2BSDS 2048 16384 8
b: 2097152 1048576 swap
c: 3917989 0 unused 0 0 # "raw" 部分，不要编辑
d: 10485760 3145728 4.2BSDS 2048 16384 28552
e: 2097152 13613488 4.2BSDS 2048 16384 28552
```
