
如果指定的名称不以斜杠开头，且在当前目录下未找到该文件，则会搜索用 `-I` 或 `--include-dir` 选项指定的任何目录（见第 9.7 节 [选项摘要]，第 95 页）。然后将按顺序搜索以下目录（如果它们存在）：`/prefix/include`（通常为 `'/usr/local/include'`） `/usr/gnu/include/` `/usr/local/include/` `/usr/include/`。

如果在这些目录中均未找到包含的 make，将生成错误消息，但这不是立即的致命错误；包含该 include 的 Makefile 将继续处理。一旦完成 Makefile 的处理，`make` 将尝试重新构建任何过时或不存在的文件。见第 3.5 节 [Makefile 如何重新构建]，第 14 页。只有在尝试找到重新构建 Makefile 方法失败后，`make` 才会将缺失的 Makefile 诊断为致命错误。

如果你想简单地忽略不存在且无法重新构建的 make 而不产生错误消息，请使用 `-include` 指令代替 `include`，例如：

```
-include filenames...
```

这在每个方面都像 `include` 一样，只是如果任何文件名不存在，不会产生错误（甚至是警告）。为了兼容某些其他 make 实现，`include` 是 `-include` 的另一个别名。

### 3.4 变量 MAKEFILES

如果定义了环境变量 `MAKEFILES`，`make` 将其值视为一组名称（用空格分隔），这些是在读取其他文件之前读取的额外 Makefile。这的工作方式与 `include` 指令非常相似：会在目录中搜索这些文件（见第 3.3 节 [包含其他 Makefile]，第 12 页）。此外，默认目标绝不会从这些 Makefile 中获取，如果未找到 `MAKEFILES` 中列出的文件，也不会视为错误。

`MAKEFILES` 的主要用途是 `make` 递归调用之间的通信（见第 5.6 节 [递归使用 make]，第 46 页）。通常不建议在顶层调用 `make` 之前设置环境变量，因为通常最好不要从外部干涉 Makefile。

> 为 MS-DOS 和 MS-Windows 编译的 GNU Make 行为就好像 `prefix` 已定义为 DJTPP 树形层次结构的根目录。

然而，如果你在没有指定特定 Makefile 的情况下运行 `make`，`MAKEFILES` 中的 Makefile 可以执行一些实用的操作来帮助内置规则运行得更好，例如定义搜索路径（见第 4.3 节 [目录搜索]，第 22 页）。

某些用户倾向于在环境中自动使用 `MAKEFILES`，并编写 Makefile 期望这种操作被完成。这是一个非常糟糕的主意，因为如果由其他人运行，Makefile 将无法工作。在 Makefile 中编写显式的 `include` 指令要好得多。见第 3.3 节 [包含其他 Makefile]，第 12 页。

### 3.5 Makefile 如何重新构建

有时 Makefile 可以从其他文件（如 RCS 或 SCCS 文件）重新构建。如果 Makefile 可以从其他文件重新构建，你可能希望 `make` 获取一个最新版本的 Makefile 以进行读取。

为此，在读取所有 Makefile 后，`make` 将将每个文件视为一个目标并对其进行更新。如果 Makefile 有一条规则说明如何更新它（在该 Makefile 或另一个 Makefile 中找到），或有隐式规则适用于它（见第 10 章 [使用隐式规则]，第 101 页），则在需要时对其进行更新。在检查完所有 Makefile 后，如果任何文件实际上发生了变化，`make` 将从重新读取开始并再次读取所有 Makefile。（它也会尝试再次更新它们中的每一个，但通常这不会改变它们，因为它们已经是最新的了。）

如果你知道你的一个或多个 Makefile 无法重新构建，并且你想保持它们为最新，可以使用特殊目标 `.PHONY` 告诉 `make` 这些目标始终是最新的。然而，如果你想强制某个目标重新构建，可以使用 `-B` 选项（见第 4.4 节 [强制重新构建]，第 39 页）。

如果你想强制所有目标重新构建，你可以使用 `-B` 选项（见第 4.4 节 [强制重新构建]，第 39 页）。

如果你想强制特定目标重新构建，你可以使用 `-B` 选项（见第 4.4 节 [强制重新构建]，第 39 页）。
