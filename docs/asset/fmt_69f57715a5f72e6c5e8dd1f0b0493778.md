
数据库管理系统 (DBMS) 用于管理大量数据。它定义了存储信息的结构以及处理信息的机制。此外，DBMS 为数据提供了针对系统故障或未经授权访问的保护。

数据库系统的示例包括关系系统、公司和员工信息系统以及信用卡处理系统。

数据库系统的主要目的是为数据提供方便访问。数据如何存储和维护的细节可以存储在复杂的结构中，允许高效检索，同时使用简单易用的数据视图。DBMS 隐藏了数据实际存储的复杂性并详细说明了结构。

实体关系数据库模型基于一组基本对象、实体和它们之间的关系。实体是与其他对象区分的对象。例如，人是一个实体，银行账户也可以被视为实体。这些在数据库中通过一组属性来描述。例如，账户有号码和余额。

操纵语言使用户能够按照数据模型组织的数据来访问或操作数据。数据处理语言有几种基本类型：过程化数据处理语言要求用户指定需要哪些数据以及如何获取；非过程化数据处理语言则要求用户指定需要哪些数据，而无需描述如何获取。

在某些模型中，实例由某些类型的少量正式记录表示。每个记录都有一组字段。三种最广泛使用的基于记录的模型是关系模型、网络模型和层次模型。后者两种使用指针，而其他的则使用键。关系模型被广泛使用。基于关系模型的数据库被称为关系数据库。

查询是指指定信息的检索。数据处理语言中涉及查询的部分被称为查询语言。如果查询语言是非过程化的，那么将“查询”和“数据处理语言”作为同义词使用是正确的。

数据库同时支持数据定义语言和数据处理语言。尽管已经提到了许多语言，但 SQL 是基于关系数据库系统的标准语言，也是唯一能够支持类似于 SQL 的声明式查询语言的语言。SQL 提供了一个完整的数据定义语言允许允许具有指定属性、类型和完整性约束的表。

实例查询（QBE）是一种用于查询数据库的图形化语言。它被用于个人数据库，因为对于非技术用户来说，它比 SQL 更容易。

数据库中的信息存储在可以容纳大量数据的易失介质上；最具效益的此类介质可以存储比内存更多的数据，且单位数据的成本更低。

表单展示了数据的形式，并带有供用户填充的字段。某些字段可能由系统自动填充。报告报告与数据库查询相关的信息；查询结果以格式报告的形式显示。这些工具为构建数据库提供了新方法，并提供了另一种查看数据。

关系数据库组织为关系（表）的集合，用以表示数据和关系。每个表都有多个列，每列都有唯一的名称。表的每个值是一个元组，每个元组包含每个属性的值。

数据库管理系统设计用于支持由许多结构化属性组成的商业数据。近年来，数据库帮助管理了不同商业实体之间复杂的关系。

在本地，关系数据库被组织为关系的集合，每个关系由一组记录组成。查看数据的方法取决于实现方式。关系的物理实现由一组固定大小的磁盘组成，称为块。记录存储在块中。每个记录与一个或多个属性相关。通常，一个文件包含来自一个关系的记录，但出于性能考虑，也会使用来自多个关系的记录。

要检索关系数据库中的记录，需要对关系进行扫描；键查找寻找关系中所有符合搜索标准的记录。

通过关系上的键访问记录可以非常高效。索引是指向每个记录值所在位置的数据结构。如果索引包含了记录的一个或多个属性，且这些属性满足搜索标准，则可以使用该索引快速检索具有所搜索键值的记录。索引可能支持其他操作，例如获取落在某个值范围内的搜索键值。

一种导航形式，通过根据假设的距离和方向将之前的位置推算到新位置来确定船只的位置。推算的元素的要素是推算方向和运动，由于横流（风或洋流）或漂移的影响，运动可能与预期不符。如果要区分这两种方法，海员将前者称为转向（steering），将后者称为航向（heading）。使用罗盘指示方向。方向通常通过测量速度和时间来间接估计。

在船上，速度通过指示器或发动机转速来测量。计程仪使用皮托管管。福布斯仪在投影到船底下方的管中工作。电磁式使用一种元件，产生与水流速度成正比的电压。

在空中，速度通过指示器或马赫计来测量。速度以声速为单位表示，并考虑大气密度。测量空速使用皮托管管配合适当的阻力装置。

要通过推算确定位置，航空导航使用对地面的最佳方向估计。航海导航员使用估计的水中速度进行推算，且不考虑漂移；推算时通过加上风和洋流的预估效应来考虑位置。

然而，推算位置的不确定性随时间推移而增加，如果方向存在误差，位置误差将随时间增加，直到通过参考物确定位置。当参考物失效时，将从该点开始新的推算。

在大型海军舰艇和商船上，推算是通过累积陀螺仪和速度记录仪的输入并持续推算位置完成的，这些位置显示在图表或绘图表的轨迹上。
