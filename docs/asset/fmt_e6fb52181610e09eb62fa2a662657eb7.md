### 第 5 章

#### 用户管理

在 Linux 下，每个文件和程序都必须有一个用户作为所有者。每个用户都有一个唯一的标识符，称为用户 ID（UID）。每个用户还必须属于至少一个组，组是由系统管理员建立的一个用户集合。用户可以属于多个组。与用户类似，组也有唯一的标识符，称为组 ID（GID）。

文件或程序的可访问性基于其 UID 和 GID。正在运行的程序继承调用该程序的用户权利和权限。`set-UID`，将在本章稍后讨论，构成了这一规则的例外。每个用户的权限可以通过两种方式之一定义：普通用户或 root 用户。普通用户只能访问他们拥有的或获准运行的内容；授予权限的原因要么是用户属于该文件的组，要么是因为该文件对所有用户都可访问。root 用户被允许访问系统中的所有文件和程序，无论 root 是否拥有它们。root 用户通常被称为超级用户。

如果你习惯于 Windows NT，你可以将该系统的用户管理与 Linux 的用户管理进行类比。例如，Linux 的 UID 类似于 Windows 的 SID。与 Windows NT 相反，你可能会觉得 Linux 的安全模型令人抓狂地简单：要么你是 root，要么你不是。普通用户不能以 NT 下授予普通用户管理员访问权限的方式拥有 root 权限。你还会注意到 Linux 中明显缺乏访问控制列表（ACL）。哪个系统更好？这取决于你想要什么以及你问谁。

在本章中，我们将探讨单主机用户管理技术。跨网络的用户管理将在网络信息服务（NIS）章节（第 19 章）中讨论。让我们从探索包含用户信息的实际数据库文件开始。然后，我们将考察用于自动管理这些文件的系统工具。

## 关于用户

在 Linux 中，一切都附有一个所有者。鉴于此，一个没有用户的 Linux 系统是不可能存在的！至少，它需要一个 root 用户；然而，大多数 Linux 发行版都附带设置了几个特殊用户。这些用户作为自我文档化工具运行得很好，因为每个用户都拥有与其用户名相关的所有文件——例如，用户 www 被设置为拥有与万维网服务相关的所有文件。这些用户被配置为仅授予少数特定人员访问权限，因此你不必担心它们的滥用。

为了让用户账户正常工作，需要设置一些事项。在本节中，我们讨论这些项目以及为什么它们必须存在。实际的设置账户过程将在本章稍后讨论。

### 主目录

每个实际登录系统的用户都需要一个独特的配置文件存放位置。这允许每个用户在定制的环境中工作，而无需更改由另一个用户定制的环境——即使两个用户同时登录系统。这个位置被称为主目录。在这个目录中，用户不仅可以存放其配置文件，还可以存放常规工作文件。

为了保持一致性，大多数站点将主目录放在 `/home` 下，并以用户的登录名为目录命名。因此，如果你的登录名是 hid，你的主目录将是 `/home/hid`。系统账户（例如 root 用户的账户）是此规则的例外。主目录通常设置为 `/` 或特定于该账户需求的某个路径（例如，如果安装了 Apache Web 服务器，www 账户可能希望将其主目录设置为 `/usr/local/apache`）。在大多数 UNIX 变体中，root 的主目录传统上为 `/`。许多 Linux 安装使用 `/root`。

将主目录放在 linux 下是完全任意的——但它在组织上有一定道理。系统并不关心我们将主目录放在哪里，只要每个用户的位置在密码文件（本章稍后讨论）中指定即可。你可能会看到一些站点使用 `/u` 或按部门拆分主目录，从而创建 `/home/engineering`、`/home/accounting`、`/home/admin` 等，然后让用户位于每个部门之下。例如，工程部门的 Bozeme 博士将是 `/home/engineering/bozeme`。

### 密码

每个账户应该有一个密码，或者被标记为无法登录。这对系统的安全至关重要——弱密码往往是系统安全受损的原因。

最初密码背后的哲学其实很有趣，尤其是我们今天仍依赖其很大一部分。其理念很简单：不依赖受保护的文件来保持密码的秘密，而是系统使用 NSA 开发的一种名为 DES 的算法对密码进行加密，并允许加密值公开查看。最初使其安全的是，该加密算法在计算上很难破解。大多数人能做的最好事情是暴力字典攻击，即自动化系统遍历大型字典，并依赖用户倾向于为密码选择英文单词的特性。许多人试图破解 DES 本身，但由于它是一个任何人都可以研究的开放算法，它在实际部署之前变得更加防弹。

当用户在登录提示符下输入密码时，输入的密码会被加密。然后，加密值会与用户的密码条目进行比较。如果两个加密值匹配，用户被允许进入系统。执行加密的实际算法在计算上足够便宜，单次加密不会花太长时间。然而，字典攻击所需的数万次数加密将需要极其漫长的时间。除了加密的密码外，密码文件还可以包含关于用户主目录、UID、shell、真实姓名等信息，而无需担心如果任何由任何用户运行的应用程序都被允许读取它会导致系统安全受损。

但随后出现了问题：处理器速度每 18 个月翻倍的摩尔定律确实成真了，家用电脑变得足够快，程序能够在几天内而不是几周或几个月内执行暴力字典攻击。字典变得更大，软件变得更智能。密码的特性需要重新评估。

影子密码是一个解决方案。在影子密码方案中，加密的密码条目从 `passwd` 文件中移除，并放置在一个名为 `shadow` 的单独文件中。常规的 `passwd` 文件将继续对系统上的所有用户可读，而实际的加密密码条目只能被 root 用户读取。登录提示符以 root 权限运行。为什么不直接让常规密码文件仅 root 可读呢？嗯，事情没那么简单。由于密码文件开放了这么多年，围绕它成长起来的其余系统软件依赖于密码文件始终对所有用户可读这一事实。更改这一点只会导致软件故障。

另一个解决方案是改进用于执行密码加密的算法。一些 Linux 发行版遵循了 FreeBSD 操作系统的道路，使用了 MD5 方案。这增加了破解密码的复杂性，当与影子密码结合使用时，效果相当好。当然，这是假设你让你的用户选择了好的密码！

> 提示：选择好的密码总是一件麻烦事。你的用户最终会问：“那么，全能的系统管理员，什么样的密码才是好密码？” 这是你的答案：一个非词汇单词（不是英语、西班牙语、德语或任何人类语言的单词），最好包含混合大小写、数字和标点符号——像一个看起来像自由文本的字符串。嗯，这很简单且很棒，但作为一个对强密码的提醒，大多数人会通过将其写下来并放在容易看到的地方迅速使其失去作用。所以最好让它难忘！我更喜欢选择一句短语，然后选取短语中每个单词的首字母的技术。因此，短语“fool me VERY GOOD for you and me”变成 oGVyAm。即使生成的密码不可忘，该短语也是难忘的。
