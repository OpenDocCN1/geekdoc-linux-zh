# ct — 远程终端登录

### 概要

`/usr/bin/ct [options] telno...`

## 描述

`ct` 拨打连接终端的调制调器电话号码并在该终端启动登录进程。`telno` 是电话号码，等号表示拨号音，减号表示适当的延迟。(`telno` 的合法字符为 0 到 9、`-`、`*` 和 `#`。`telno` 的最大长度为 31 个字符)。如果你指定多个电话号码，`ct` 将依次尝试直到响应；此功能对于指定替代拨号路径有用。

`ct` 尝试 `/etc/uuc/Devices` 文件列出的每个行，直到找到具有适当属性的线路或用完项目。目标终端登录后，可能会发生两种情况，取决于端口监控类型。如果没有端口监控，`ct` 会提示：`Reconnect？` 如果响应以字母 `n` 开头，则丢线路；否则重新启动 `ttmon` 并打印登录提示。当端口监控正在监控端口时，监控器重新发布登录提示。用户应在断开之前正确登录。

> 注意 — `ct` 程序不支持 `DATAKIT` 多路接口。对于共用于拨入和拨出的端口，运行在线路上的 `ttmon` 程序必须指定 `-r` 和 `-b` 选项（参见 `ttmon(1M)`）。

# ctags

## Description

`ctags` 命令根据指定的 C, C++, Pascal, FORTRAN, `yacc(1)` 和 `lex(1)` 源码为 `ex(1)` 创建一个 `tags` 文件。`tags` 文件提供了一组文件中指定对象（在此例中为函数和类型定义）的位置。`tags` 文件的每行都包含对象名称、定义该对象的文件，以及该对象定义的地址规范。函数通过模式进行搜索，类型定义通过行号进行搜索。指定符在行中的独立字段中给出，用空格或制表符分隔。使用 `tags` 文件，`ex` 可以快速找到这些对象定义。

通常情况下，`ctags` 将标签描述存放在一个名为 `tags` 的文件中；你可以使用 `-f` 选项来覆盖此默认值。以 `.c` 或 `.h` 结尾的文件被假设为 C 或 C++ 源文件，并会在其中搜索 C/C++ 例程定义和宏定义。以 `.C` 或 `.xx` 结尾的文件被假设为 C++ 源文件。以 `.y` 结尾的文件被假设为 `yacc` 源文件。首先检查文件是否包含任何 Pascal 或 FORTRAN 例程定义；如果没有，则再次处理并查找 C 定义。

在 C 或 C++ 程序中，标签 `main` 被视为特殊。生成的标签是通过在文件名前加上 `M` 创建的，如果存在，会移除末尾的 `.c`, `.cc`, `.C` 或 `.c`，并同时移除路径名组件。这种行为使得 `ctags` 在包含多个程序的目录中非常实用。

## Options

打印时，先指定 `-x` 和 `-v` 选项，然后是剩余的选项。

- `-a` 将输出追加到现有的 `tags` 文件。
- `-B` 使用反向搜索模式 `(?...)`。
- `-f tagsfile` 将标签描述放在名为 `tagsfile` 的文件中，而不是 `tags`。
- `-F` 使用正向搜索模式 `(/.../)`（默认）。
- `-t` 为类型定义 (`typedefs`) 创建标签。`/usr/xx4/bin/ctags` 默认为类型定义创建标签。
- `-u` 更新 `tags` 中指定的文件，即删除对它们的所有引用，并将新值附加到文件中。注意：此选项的实现方式相当慢；直接重新构建 `tags` 文件更快。
- `-v` 在标准输出上产生索引，列出函数名、文件名和页码（假设每页 64 行）。因为输出按字典顺序排序，你可能希望对输出运行 `sort -f`。
- `-w` 抑制警告诊断。
- `-v` 在标准输出上产生对象名称列表、定义的行号和文件名，以及该行的文本，并打印到标准输出上。此列表提供了一个简单的索引，可以打印为离线可读的函数索引。

## Operands

- `- file.c` 将基名以 `.c` 结尾的文件视为 C 语言源码。
