
例如：`quota charlene` 会调出一个编辑器，允许（重新）设置总磁盘空间（单位为 KB）和使用的 inode 总数的硬限制（hard limit）和软限制（soft limit）。区别的区别在于硬限制是永远不能超过的。设置软限制会启动一个计时器。如果用户降低于软限制，计时器将重置。如果触发报警，该条件被处理为类似于达到硬限制的情况。`edquota -p charlene georgia` 除非指定了用户 `georgia` 的 `charlene` 配额信息，否则不会打开编辑器。

要检查账户，你可以运行 `quota -v username` ... 或 `repquota /user/filesystem`。`quota` 报告指定用户的磁盘使用情况和限制。如果省略 `-v` 参数，则只输出超出限制的限制。`repquota` 给出特定文件系统中密码文件中所有用户的摘要。磁盘使用量限制已过期。以下是 `quota` 命令及其输出的示例。

```
quota -v jamie (uid: 315)

Disk quota usage quota limit timeleft files quota limit

timeleft /usr 26015 25600 30720 5.1 days 488 500 750
```

用户名 `jamie` 已超过总使用量，并有 5.1 天的时间来减少她的用量。该用户在发出超额信号之前，还可以再创建 12 个文件（假设存在足够的空间）。


## 匿名 FTP

最后，除非有关于启用非常特定的用户账户的描述，否则用户管理讨论是不完整的。此列表详细介绍了如何设置匿名 ftp。

首先，在 `passwd` 文件中为账户创建一个用户 ID。该条目应该有一个唯一的用户 ID、匹配的组以及无效的密码。一个示例条目可以是：

```
ftp*:500:ftp:Anonymous ftp:/user_ftp/home_directory/ftp:/bin/false
```

其次，创建家目录。

```
mkdir /user_ftp/home_directory/ftp

cd /user_ftp/home_directory/ftp
```

```
mkdir bin etc pub

mkdir pub/incoming

chown -R root pub

chgrp ftp pub

chmod u+rx bin etc

chmod u+rwxt pub/incoming
```

第三，用适当的信息填充目录。

```
cp /bin /sbin/ls bin

chmod u+x bin/ls

cp /usr/lib/libdl.so.* lib

chmod u+rx lib/libdl.so.*

ls -l /dev/

mkdev dev/zero c major major/minor 是 ls 命令输出中日期左侧的逗号分隔的条目。

chmod u+gr dev/zero

create an etc/passwd file that includes root, daemon, and ftp

create an etc/group file that includes the root default group and the ftp
```

你现在应该是匿名 ftp 用户了。为了确保设置正确，查看匿名 ftp 目录。没有任何文件或目录归 ftp 所有。可能会插入木马版本的文件。以匿名 ftp 登录，尝试在当前工作目录创建一个文件。如果可以，则匿名 ftp 是安全的。

## 总结

尽管这似乎是一项没有回报的任务，但用户管理在无人察觉时是最好的。你应该随时回答问题，但对用户来说应该是隐形的。使用许多内置的 Unix 管理工具配合可选软件包来监督、监控和限制你的用户群。免于用户管理中琐碎任务的满意用户将使你有时间筛选系统的其他区域，将时间投入到提高效率而不是解决问题上。

# 文件系统与磁盘管理

作者 Steve Shah

本章讨论了创建、维护和修复文件系统的艰辛困折。虽然这些任务从用户的角度来看可能看似简单，但实际上它们非常复杂，并包含许多细微差别。在本章中，我们将逐步介绍许多细微差别，并希望对文件系统的原理和作用有深入的理解。

在跳入主题之前，你应该对 UNIX 目录、文件、权限和路径有良好的理解。这些是理解如何管理文件系统的关键区块，我假设你已经掌握了它们。如果“确保在 `$PATH` 中使用 `/usr/bin` 而不是 `/usr/local/bin`”的说法在任何程度上让你感到困惑，那么你应该去读一些基础知识。请参考第一部分“Unix 简介”获取 UNIX 中的一些基本指令。

本章对文件系统的解释方式与其他书籍略不同。我们首先讨论文件系统的维护和修复，然后是创建。这样做是因为你更有可能需要维护和修复现有的文件系统。理解如何维护也有助于更好地理解为什么文件系统是这样创建的。

我们在这里涵盖的技术适用于大多数常用的 UNIX 系统。唯一的例外是我们在实际创建文件系统时。这是与任何标准（如果曾经存在过）偏差最大的地方。我们涵盖了 SunOS、Solaris、Linux 和 IIX 实现的 UNIX 的文件系统创建。

## 什么是文件系统

文件系统是 UNIX 中存储文件的主要手段。每个文件系统都包含目录，这些目录作为一个整体，可以放置在 UNIX 树的任何地方。目录树的最顶端是根目录，起始于 `/`。嵌套在根目录下的子目录可以根据你的意愿任意深度嵌套，只要最长的绝对路径小于 1024 个字符即可。

随着厂商增强版 UNIX 的激增，你会发现许多“增强型”文件系统。从管理员的角度来看，你不必过于担心这些差异。你只需要担心涉及特定细节的两种情况：创建文件系统和执行备份时。

- SunOS 4.1.x，使用 4.2
- Solaris，使用 ufs
- Linux，使用 ext2
- IRIX，使用 efs 和 xfs

注意，`ufs` 和 4.2 系统实际上是同一种。

然而，文件系统只是 UNIX 在磁盘上保存数据的通用方案的一部分。在顶层，你找到的是目录。这些目录被划分为分区，每个分区的大小根据管理员的需求而异。实际的文件系统布局在每个分区上。在文件系统内部，你会找到目录、子目录，最后是单个文件。

尽管你很少需要处理比存储的单个文件更低层的文件系统，但理解两个概念至关重要：**inodes** 和 **superblock**。一旦你理解了这些，就会发现文件的行为和特征变得更容易理解了。

## inodes

一个 `inode` 包含关于每个文件的信息。根据文件类型，`inode` 可以包含 40+ 多项信息。然而，其中大部分信息仅对内核有用，与我们无关。我们关心的字段是：

| mode | Description |
| :--- | :--- |
| mode | 权限掩码和文件类型。 |
| link count | 包含此 inode 号条目的目录数量。 |
| user ID | 文件所有者的 ID。 |
| group ID | 文件所属组的 ID。 |
| size | 该文件的字节数。 |
| access time | 文件最后访问的时间。 |
| mod time | 文件最后被修改的时间。 |
| inode time | 该 inode 结构最后被修改的时间。 |
| block list | 包含文件第一段的磁盘块号列表。 |
| indirect list | 其他块列表的列表。 |

`mode`、`link count`、`user ID`、`group ID`、`size` 和 `access time` 在生成文件列表时使用。注意，`inode` 不包含文件名。该信息存储在目录文件中。

## Superblocks

这是存储在磁盘上最重要的信息。它包含了磁盘几何结构信息（磁头数、磁柱数等）、inode 头部信息以及空闲块列表。由于其重要性，系统会自动在磁盘各处散布这些数据的镜像以实现冗余。只有当你的文件系统严重损坏时，你才需要处理 `superblock`。

## 文件类型

文件有 8 种类型：

- 普通文件
- 目录
- 硬链接
- 符号链接
- 套接字
- 命名管道
- 字符设备
- 块设备

普通文件是你最常用的文件。它们可以是文本文件也可以是二进制文件；然而，从系统管理员的角度来看，它们的内部结构无关紧要。文件的特征由其描述的目录文件中的 `inode` 指定。对普通文件执行 `ls -l` 的结果看起来如下：

```
-rw------ 1 sshah admin 42 May 12 13:09 hello
```

目录是一种特殊文件，包含其他文件的列表。尽管 `inode` 到磁盘块之间是一对一的映射，但目录到条目之间可以是多对一映射。使用 `ls -l` 命令查看目录时，你可以通过权限中的 `d` 字符识别目录。对目录执行 `ls -l` 的结果看起来如下：

```
drwx------ 2 sshah admin 512 May 12 13:08 public_html
```

## 硬链接

硬链接实际上是一个普通的目录条目，只不过它不是指向一个唯一的文件，而是指向一个已经存在的文件。这在列出目录时会产生存在相同文件的错觉。系统将其视为另一个文件，并以此对待它。这在备份时是需要避免的，因为硬链接被备份的次数与其硬链接的数量相同。由于硬链接共享一个 `inode`，因此它们不能跨文件系统存在。硬链接使用 `ln` 命令创建。例如，我们通过 `ls -1` 看到的此目录列表：

```
-rw------ 1 sshah admin 42 May 12 13:04 hello
```

当你使用 `ln hello` 并使用 `ls -1` 执行另一次目录列表时，我们看到：

```
-rw------ 2 sshah admin 42 May 12 13:04 goodbye
-rw------ 2 sshah admin 42 May 12 13:04 hello
```

注意，这似乎是两个独立的文件，恰好长度相同。还要注意链接数（第二列）从一个增加到了两个。如何判断它们实际上是同一个？使用 `ls -il`。

观察：

```
13180 -rw------ 2 sshah admin 42 May 12 13:04 goodbye
13180 -rw------ 2 sshah admin 42 May 12 13:04 hello
```

你可以看到它们都指向同一个 `inode` 13180。

> **警告：** 在创建链接时要小心，尤其是当对目录进行硬链接时。这样做可能会修复文件系统，因为硬链接并不包含被指向的 i-node 需要被视为目录的事。

## 符号链接

符号链接（有时称为 symlink）与硬链接不同，因为它指向的不是节点，而是一个文件名。这使得符号链接可以跨文件系统存在，并被操作系统识别为特殊文件。你会发现符号链接对于文件系统的管理至关重要，特别是在试图在不存在无缝系统的情况下营造这种假象时。符号链接使用 `ln` 命令创建。

因此，通过挂载根目录，系统将无法再次看到自身的内核或本地配置文件。你的系统崩溃持续多久取决于你的供应商。

这条规则有一个例外。某些安装包会将网络文件系统挂载到根目录上。这样做是为了让安装软件能够访问许多无法放入启动磁盘的软件包。除非你完全理解如何进行此操作，否则请不要尝试。

## 手动挂载和卸载文件系统

要挂载一个文件系统，请使用 `mount` 命令：

```
mount /dev/device /directory/to/mount
```

其中 `/dev/device` 是你想要挂载的设备名称，`/directory/to/mount` 是你想要在本地文件系统中覆盖的目录。例如，如果你想将 `/dev/hda4` 挂载到 `/usr` 目录，你需要输入：

```
mount /dev/hda4 /usr
```

记住，在挂载任何内容之前，该目录必须存在于你的本地文件系统中。

可以向 `mount` 命令传递选项。最重要的特性由 `-o` 选项指定。这些特性包括：

```
rw 读/写
ro 只读
bg 后台挂载（如果挂载失败，
将进程置于后台
并持续尝试直到成功。）
interruptible 可中断挂载（如果进程在
挂载的分区上等待 I/O 操作，
它将允许进程被中断
并丢弃 I/O 调用）
```

这些参数的使用示例为：

```
mount -o rw,bg,intr /dev/hda4 /usr
```

请查看系统的 `man` 手册以获取特定供应商的附加内容。

要卸载文件系统，请使用 `umount` 命令。例如：

```
umount /usr
```
