## 列表 10-66: fs/fs-writeback.c: wb_io_lists_depopulated

当 `struct bdi_writeback` 列表为空时，这将重置 `wb_has_dirty_inode` 标记并更新回写统计数据。

```c
/*
 * 将 inode 及其脏页（或其部分脏页，取决于
 * @wb->nr_to_write 的值）写入磁盘，并从 i_state 中清除相关的脏位标记。
 * 这不会将 inode 从其所在的回写列表中删除，除非
 * 通过时间戳过期将其从 b_dirty_time 移动到 b_dirty。
 * 其他情况下由调用者处理回写列表。
 * 调用者还负责预先设置 I_SYNC 标记，并在之后
 * 调用 inode_sync_complete(inode) 来完成同步。
 */
static int
writeback_single_inode(struct inode *inode, struct writeback_control *wbc) {
    struct address_space *mapping = inode->i_mapping;
    long nr_to_write = wbc->nr_to_write;
    unsigned dirty;
    int ret;

    WARN_ON(inode->i_state & I_SYNC);
    ret = do_writepages(mapping, wbc);

    /*
     * 确保等待元数据的写入完成。
     * 这对于在数据 I/O 完成后修改元数据的
     * 文件系统至关重要。我们不对 sync(2) 回写进行这样做，
     * 因为它有独立的外部 I/O 完成路径和 ->sync_fs
     * 用来保证 inode 元数据被正确回写。
     */

    if (wbc->sync_mode == WB_SYNC_ALL && !wbc->for_sync) {
        int err = filemap_fdatasync(mapping);
        if (ret == 0)
            ret = err;
    }

    /*
     * 从 i_state 中获取并清除脏标记。这需要在调用
     * writepages 之后执行，因为某些文件系统可能会在
     * writepages 期间重试 inode 以释放。它还需要在
     * 处理时间戳过期后执行，因为那可能也会标记 inode。
     */

    spin_lock(&inode->i_lock);
    dirty = inode->i_state &= ~I_DIRTY_PAGES;

    /*
     * 与 __mark_inode_dirty() 中的 smp_mb() 配对使用。这允许
     * inode_dirty() 在不获取 i_lock 的情况下测试 i_state，
     * 要么看到 I_DIRTY 位被清除，要么我们看到脏的
     * inode。
     * 即使 @mapping 仍有脏页，I_DIRTY_PAGES 也会被一起清除。
     * 如果必要，在 smp_mb() 之后会恢复该标记。
     * 这保证了 __mark_inode_dirty() 要么看到清除的
     * I_DIRTY_PAGES，要么我们看到 PAGECACHE_TAG_DIRTY。
     */

    smp_mb();
    if (mapping_tagged(mapping, PAGECACHE_TAG_DIRTY)) {
        inode->i_state |= I_DIRTY_PAGES;
    }

    spin_unlock(&inode->i_lock);

    /* 如果只设置了 I_DIRTY_PAGES，则不写入 inode */
    if (dirty & ~I_DIRTY_PAGES) {
        int err = write_inode(inode, wbc);
        if (ret == 0)
            ret = err;
    }

    return ret;
}
```

## 列表 10-67: fs/writeback.c: __writeback_single_inode()

此函数立即调用了列表 10-23 和第 10.10 节所示的 `writepages()`，它执行实际的回写。剩余的函数清理任务在完成后完成。

我们涵盖了同步回写的情况，这种情况并非源于 `sync()` 或 `syncfs()` 等同步系统。在其他情况下，写入操作由调用函数 `writeback_inodes_sb()`（见列表 10-40）和 `sync_inodes_sb()`（见列表 10-39）处理，因此在这些实例中，`writeback_single_inode()` 不执行工作。对于其他同步情况，情况并非如此，我们必须显式说明，这是通过我们在后续文件回写第 10.13 节的列表 10-72 中检查的 `filemap_fdatawait()` 实现的。

在此函数的所有调用中，无论操作结果如何，在 `struct inode->i_lock` 下 inode 的脏标记都会被清除。

如果我们随后发现至少一个页缓存包含的 inode 数据仍为脏，我们无论如何都会通过仔细的锁协商来更新 inode 状态，将内存屏障与 `__mark_inode_dirty()`（见列表 10-2）配对，允许后者在不加锁的情况下检查 `inode->i_state`。最后，如果 inode 元数据是脏的，则通过 `write_inode()` 回写 inode，但这超出了本书的范畴。

## 10.13 文件回写

我们已经看到回写是如何以文件为粒度进行的，但还有另一种进行回写的方法——以页为粒度进行。用户可以通过 `fsync()` 或 `fdatasync()` 调用请求将打开的文件描述符同步到磁盘，并通过 `msync()` 请求对 `mmap()` 映射文件的单个页进行同步。

> **注意** 用户也可以通过 `sync_file_range()` 指定打开的文件描述符的单个页的同步，然而，非常不建议使用该系统调用因为它是危险的，因此我们不进行详细检查。在任何情况下，该系统调用最终都会调用我们在这里检查的相同函数。我们在第 10.6 节和图 10-4 中检查了这些同步方法，它们最终会调用内核函数 `filemap_flush()`（见列表 10-68）、`filemap_write_and_wait_range()`（见列表 10-74）和 `filemap_fdatawait()`（见列表 10-72）。此外，我们观察到 `writeback_single_inode()`（见列表 10-67）调用了 `filemap_fdatawait()`。

该函数使用 `mapping_needs_writeback()` 来决定是否继续，它简单地检查 `mapping->nrpages` 是否非零。此字段表示页缓存条目中存在多少页；如果没有页，则回写将无法进行，因此没有必要尝试这样做。

之后，实际的写入由 `filemap_fdatawrite_range()` 执行（见列表 10-75），并指定 `WB_SYNC_ALL` 指明所有写入都将是同步。

在其他情况下，当发生 `EIO` 错误时（表示通常情况下会阻止回写的错误），我们通过 `filemap_fdatawait_range()`（如在列表 10-77 所示）等待操作完成。

这看起来似乎是多余的，因为我们已经指定了 `WB_SYNC_ALL`，但此标志仅会在上述文件系统回写逻辑中导致回写；对于文件回写，我们必须亲自执行等待，此标志为底层逻辑提供了操作将同步进行的上下文。

最后，这会检查回写期间发生的错误，这些错误被放置在 `struct address_space->flags` 字段中。这是通过 `filemap_check_errors()` 完成的，它清除这些标志并报告相关的错误（优先考虑直接由 `filemap_fdatawrite_` 返回的错误）。

## 列表 10-72: include/linux/pagemap.h: filemap_fdatawait()

它委托操作给 `filemap_fdatawait_range()`，指定应等待文件空间的回写。这在列表 10-73 中所示。

```c
/**
 * filemap_fdatawait_range - 等待回写完成
 * @mapping:        要等待的地址空间结构
 * @start_byte:      范围开始的字节偏移
 * @end_byte:        范围结束的字节偏移（包含）
 *
 * 遍历给定地址空间在给定范围内正在回写的页列表
 * 并等待它们全部完成。检查地址空间的
 * 错误状态并返回它。
 *
 * 由于地址空间的错误状态由此函数清除，
 * 调用者负责检查返回值并处理和/或
 * 报告错误。
 *
 * Return: 地址空间的错误状态。
 */
int filemap_fdatawait_range(struct address_space *mapping, loff_t start_byte,
                            loff_t end_byte)
{
    __filemap_fdatawait_range(mapping, start_byte, end_byte);
    return filemap_check_errors(mapping);
}
```

## 列表 10-73: mm/filemap.c: filemap_fdatawait_range()

它将重型工作委托给 `__filemap_fdatawait_range()`（如在列表 10-77 所示），在运行 `filemap_check_errors()` 以提取附加在 `address_space` 对象上的任何错误之前。

最后，我们检查列表 10-74 所示的 `filemap_write_and_wait_range()`。

```c
/**
 * filemap_write_and_wait_range - 写入并等待文件范围
 * @file            指向带有页的 address_space 的文件
 * @start           范围开始的字节偏移
 * @end             范围结束的字节偏移（包含）
 *
 * 写入并等待直到文件偏移 [start, end]，包含。
 *
 * 注意 @end 是包含的（描述了要写入的最后一个字节），所以
 * 此函数可以一直使用到文件末尾（end = -1）。
 *
 * 在写入并等待数据后，我们检查并移动
 *     f_wb_err 游标到最新值，并返回那里检测到的任何错误。
 *
 * Return: 成功返回 %0，否则返回负错误代码。
 */
int filemap_write_and_wait_range(struct file *file, loff_t start, loff_t end)
{
    int err = 0, err2;
    struct address_space *mapping = file->f_mapping;

    if (filemap_needs_writeback(mapping)) {
        err = __filemap_fdatawrite_range(mapping, start, end,
                            WB_SYNC_ALL);
        /* 见 filemap_fdatawait_range 的注释 */
        if (err != -EIO)
            err = __filemap_fdatawait_range(mapping, start, end);
    }

    err2 = filemap_check_errors(mapping);
    if (!err)
        err = err2;
    return err;
}
```
