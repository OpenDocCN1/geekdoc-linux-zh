
## 描述

`gprof` 生成程序的执行分析报告。被调用例程的影响被整合到每个调用者的分析中。分析数据取自调用图分析文件，该文件是由使用 `cc(1)` 的 `-xpg` 选项编译的程序、使用其他编译器的 `-pg` 选项、或为共享对象设置 `LD_PROFILE` 环境变量生成的。参见 `ld.so(1)`。这些编译器选项还链接了为了分析而编译的库例程版本。可执行镜像文件 `image-file`（默认位 `a.out`）中的符号表会被读取，并与调用图分析文件 `profile-file`（默认位 `gmon.out`）关联。

`gprof` 命令按以下方式工作：

- 1. 每个例程的执行时间沿调用图的边进行传播。
- 2. 发现循环，并对进入循环的调用进行时间共享处理。第一个列表显示了根据其代表的时间排序的函数，包括其调用图后代所在的时间。在每个函数条目下方显示了它的（直接）调用图子节点以及它们的时间如何传播到该函数。函数上方的类似显示显示了该函数的时间及其后代的时间如何传播到其（直接）调用图父节点。
- 3. 还会显示循环，其中包含整个循环的条目，以及循环成员列表及其对循环时间和调用计次数的贡献。
- 4. 给出一个平化分析，类似于 `prof(1)` 提供的。该列表给出了程序中每个函数的总执行时间和调用次数，并按时间递减排序。
- 5. 最后，给出一个索引，显示函数名与调用图分析索引值之间的对应关系。

你可以通过 `MARK` 宏将单个函数拆分为子函数以进行剖析。参见 `prof(5)`。

> 注意 — 注意留意量化误差。显示的采样粒度充其量是统计性的。假设函数每次执行的时间可以通过函数的总时间除以函数被调用的次数来表示。因此，沿调用图弧传播到该函数的时间与该弧被遍历的次数直接正比。

被分析的程序必须调用 `exit(2)` 或正常返回，剖析信息才会保存到 `gmon.out` 文件中。

## 64 位剖析

你可以自由地对动态链接的可执行文件使用 64 位剖析，如果对象是为了分析而编译的，则会收集共享对象的分析信息。解释分析输出时要小心，因为不同的共享对象可能具有相同的符号。如果出现符号重复，可以使用模块名称前缀来识别符号。

> 注意 — 在使用 32 位分析文件时混合 64 位分析文件。

## 32 位剖析

你可以对动态链接的可执行文件使用 32 位剖析，但如果对象是为了分析而编译的，必须小心。在 32 位剖析中，`gprof` 无法分析共享对象。当你执行被分析的程序时，只有镜像部分被采样的。这意味着主对象之外的时间（共享对象中的时间）未包含在分析摘要中。因此，报告的程序总时间可能少于程序使用的总时间。

由于无法计算共享对象的时间，每当你使用 `gprof` 分析程序时，应将程序链接到库的分析版本（如果没有分析版本，则使用标准存档版本），而不是共享对象，以获取库函数的分析信息。位于 `/usr/lib/libp` 目录。考虑一个例子。被分析的程序在 C 库中花费 100 个单位的时间，例如 `malloc()`。假设 `malloc()` 被例程 B 调用并消耗了 1 个单位。假设例程 A 消耗了 10 个单位。这意味着主对象之外的时间（共享对象中的时间）未包含在分析摘要中。因此，报告的程序总时间可能少于程序使用的总时间。在这种情况下，`gprof` 得出大部分时间花费在 A 中，而 B 几乎没有时间。在这种情况下，分析器的价值被严重降低；解决方案是尽可能使用存档文件。

## 注意事项

如果可执行镜像已被剥离且没有符号表 `.symtab`，则 `gprof` 将读取动态符号表 `.dyntab`，如果存在。如果使用动态符号表，则只有全局符号的信息，其行为与使用 `-a` 选项相同。

在编译用于分析的程序时，`LD_LIBRARY_PATH` 不应包含 `/usr/lib` 组件；如果 `LD_LIBRARY_PATH` 包含 `/usr/lib`，程序将错误地链接到 `/usr/lib/libp` 中的系统库分析版本。

顺序报告的时间可能会因为与其他进程共享缓存导致缓存命中率不同而显示差异。如果程序似乎是唯一使用机器的程序，后台或异步进程可能会模糊数据。在少数情况下，程序计数器的初始化可能会因为程序中的循环而改变，从而扭曲测量。然而，计数总是精确的。

只有退出或从主函数返回的程序才能保证产生分析文件，除非显式编写了对 `monitor` 的最终调用。

## 错误 (Bugs)

未被分析的父函数会将其被分析子函数的时间传播给自身，但它们在调用图列表中中似乎是自发调用的，且其时间不会进一步传播。同样，信号捕获函数即使经过了分析，看起来似乎也是自发的（尽管原因更为隐晦）。信号捕获函数的任何被分析的子函数其时间应该被正确传播，除非信号捕获函数在分析例程执行期间被调用，在这种情况下所有数据都会丢失。

## 参数 (Options)

- `-a` 抑制打印静态函数。如果指定此选项，关于静态函数的所有相关信息（例如时间样本、对其他函数的调用、来自其他函数的调用）将属于 `a.out` 文件中在紧静态函数之前加载的函数。
- `-b` 抑制性能分析中每个字段的描述。
- `-C` 在打印 C++ 符号名之前取消混淆（Demangle）。
- `-c` 通过检查对象的测试空间的启发式方法发现程序的静态调用图。用调用次数 0 表示仅限静态的父函数或子函数。
- `-D` 生成一个 `gmon.sum` 性能分析文件，表示所有指定的性能分析文件中分析信息的差异。您可以将此摘要分析文件提供后续的 `gprof` 执行（也带有 `-D`），以汇总一个 `a.out` 文件多次运行的性能分析数据。参见 `-s` 选项。

  例如，假设函数 A 在 `gmon.sum` 中调用了 B n 次，在 `gmon.out` 中调用了 m 次。使用 `-D`，将创建一个新的 `gmon.sum` 文件，显示 A 到 B 的调用次数为 n-m。
- `-E function-name` 抑制打印例程 `function-name` 及其后代的图性能分析条目（见下文 `-e`），并从总时间和百分比时间计算中排除在 `function-name` 及其后代上花费的时间。您可以指定多个 `-E` 选项。例如，默认为 `-E mcount -E cleanup`。
- `-e function-name` 抑制打印例程 `function-name` 及其所有后代的性能分析条目（除非它们具有未被抑制的祖先）。您可以指定多个 `-e` 选项。每个 `-e` 选项只能指定一个 `function-name`。
- `-F function-name` 打印例程 `function-name` 及其后代的图性能分析条目（见下文 `-f`），并在总时间和百分比计算中仅使用打印例程的时间。每个 `-F` 选项可以指定多个 `function-name`。`-F` 选项会覆盖 `-E` 选项。
- `-f function-name` 打印例程 `function-name` 及其后代的图性能分析条目。您可以指定多个 `-f` 选项。每个 `-f` 选项只能指定一个 `function-name`。
- `-l` 抑制所有本地符号的图性能分析条目的报告。这等于将指定的可执行镜像的所有本地符号放在 `-E` 排除列表中。
- `-n number-of-functions` 将平化和图性能列表的大小限制为前 `number-of-functions` 个异常函数。
- `-s` 为 `gmon` 生成一个性能分析条目，表示所有指定的性能分析文件中分析信息的总和。您可以将此摘要分析文件提供后续的 `gprof` 执行（也带有 `-s`），以累积一个 `a.out` 文件多次运行的性能分析数据。参见 `-d` 选项。
- `-z` 显示使用率为 0 的例程（由调用次数和累计时间指示）。此选项与 `-c` 选项结合使用，用于发现哪些例程从未被调用。

## 环境变量 (Environment Variables)

- `PROFDIR` 将性能分析输出放在指定的目录下的名为 `pid.programname` 的文件中。（其中 `pid` 是进程 ID，`programname` 是被分析程序的名称，通过从调用程序的 `argv[]` 删除任何前缀确定）。如果该变量包含空值，则不产生性能分析输出。否则，性能分析输出被放在文件 `gmon.out`。
- 当为性能分析编译程序时，`LD_LIBRARY_PATH` 不能包含 `/usr/lib` 组件。如果 `LD_LIBRARY_PATH` 包含 `/usr/lib`，则程序无法与 `/usr/lib/lib` 中经过分析版本的系统库正确链接。
