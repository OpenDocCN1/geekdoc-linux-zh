
第一行输出将是 `ATH`，因为 `$P` 会被展开为 make 变量；而第二行输出将是 `$PATH` 环境变量的当前值，因为 `value` 函数避免了展开。

`value` 函数通常与 `eval` 函数结合使用（参见第 8.9 节 [Eval Function]，第 93 页）。

## 8.9 eval 函数 (Eval Function)

`eval` 函数非常特殊：它允许你定义不是常量的新的文件结构；因为它们是评估变量和函数的结果。`eval` 函数的参数会被展开，然后该展开的结果被解析为 makefile 语法。展开后的结果可以定义新变量、目标、隐式或显式规则。

`eval` 的结果始终是空字符串；因此，它可以放置在 makefile 的任何地方而不会引起语法错误。

重要的是，`eval` 的参数会被展开两次：第一次由 `eval` 函数展开，然后当这些展开的结果被解析为 makefile 语法时，再次被展开。这意味着在使用 `eval` 时，你需要提供额外的转义层级。`value` 函数（参见第 8.8 节 [Value Function]，第 93 页）在这些情况下非常有用，可以规避意外的展开。

这是一个 `eval` 的用法示例；此示例结合了多个概念和其他函数。虽然在这个示例中使用 `eval` 似乎多此了（而不是直接写规则），但请考虑两点：第一，模板定义（在 `PROGRAM_template` 中）可能需要比这里复杂得多；第二，你可能将此示例中复杂的、“通用”部分放入另一个 makefile，然后将其包含在所有的单独 makefile 中。现在，你的单独 makefile 变得非常简单。

```
PROGRAMS = server client
```

```
server_OBJECTS = server.o server_priv.o server_access.o
server_LIBS = priv protocol
```

```
client_OBJECTS = client.o client_api.o client_mem.o
client_LIBS = protocol
```

# 此之后的所有内容都是通用的

```
.PHONY: all
all: $(PROGRAMS)
define PROGRAM_template =
$(1): $$($(1)_OBJS) $$($(1)_LIBS)=-%)
ALL_OBJS += $$($(1)_OBJS)
```

```
foreach prog,$(PROGRAMS),eval $(PROGRAM_template,$(prog))
```

```
$(prog):
	$(CC) $(LDFLAGS) -o $@ $(prog_OBJS)
```

```
clean:
	rm -f $(ALL_OBJS
```

## 8.10 origin 函数 (Origin Function)

`origin` 函数与大多数函数不同，它不操作变量的值；它告诉你是变量来自哪里。`origin` 函数的语法为：

```
$(origin variable)
```

注意 `variable` 是变量名，而不是该变量的引用。因此，在编写它时通常不需要使用 `$` 或括号。（不过，如果你想让该名称成为常量，则可以在函数中使用变量。）

该函数的返回值是一个字符串，告诉你：

- `undefined`：如果变量从未定义。
- `default`：如果变量有默认值。
- `environment`：如果继承自环境变量。
- `environment override`：如果继承自环境变量，并且由于 `-e` 选项覆盖了设置（参见第 9.7 节 [Summary of Options]，104 页）。
- `file`：如果在 makefile 中定义。
- `command line`：如果在命令行中定义。
- `override`：如果在 makefile 中使用了 `override` 指令（参见第 6.7 节 [The Override Directive]，68 页）。
- `automatic`：如果变量是为规则执行定义的自动变量（参见第 10.5 节 [Automatic Variables]，115 页）。

这些信息在 make 中（除了好奇心外）主要有用。例如，假设你有一个文件 `foo` 包含了另一个 `bar`。你希望在运行 `make -f bar` 时在 `bar` 中定义变量 `blech`，即使环境中包含了 `blech` 的定义。然而，如果 `foo` 在包含 `bar` 之前定义了 `blech`，你不希望覆盖该定义。这可以通过 `foo` 中使用 `override` 指令来实现，使其优先级高于 `bar` 中的后续定义；不幸的是，`override` 指令也会覆盖任何命令行定义。因此，`bar` 可以包含：

```
ifndef bletch
ifeq "$(origin blech)" "environment"
blech = barf, gag, etc.
endif
endif
```

如果 `blech` 已从环境变量定义，这将重新定义它。
如果你想在即使有 `-e` 的情况下也覆盖之前的 `blech` 定义，你可以使用：

```
ifeq "$(findstring environment,$(origin blech))" ""
blech = barf, gag, etc.
endif
```

`flavor`（类型）函数的语法格式如下：

```
$($flavor variable)
```

注意，`variable` 是要查询的变量名称，而不是对该变量的引用。因此，在编写时通常不需要使用 '$' 或圆括号。（不过，如果你希望名称不是常量，可以在名称中使用变量引用。）

该函数的返回值是一个标识变量类型的字符串：

- `'undefined'`（未定义）
- 如果变量从未被定义。
- `'recursive'`（递归）
- 如果变量是一个递归展开的变量。
- `'simple'`（简单）
- 如果变量是一个简单展开的变量。

## 8.12 控制 Make 的函数

这些函数控制 make 的运行方式。通常，它们用于向使用 Makefile 的用户提供信息，或者在检测到某种环境错误时让 make 停止。

`$(error text...)`

生成一个致命错误，错误信息为 `text`。注意，每当此函数被评估时，就会生成错误。因此，如果你将其放在配方（recipe）中或递归变量赋值的右侧，它在稍后之前才会被被评估。文本会在生成错误之前进行展开。

例如，

```
ifdef ERROR1
$(error error is $(ERROR1))
endif
```

将在读取变量 `ERROR1` 定义期间生成致命错误“error is $(ERROR1)”。或者，

```
ERR = $(error found an error!)
```

```
.PHONY: err
err: ; $(ERR)
```

如果在 make 运行期间调用了 `err` 目标，将生成一个致命错误。

`$(warning text...)`

此函数的作用与上述 `error` 函数类似，不同之处是 make 不退出。相反，`text` 会展开并显示结果消息，但 Makefile 的处理将继续。

此函数的展开结果为空字符串。

`$(info text...)`

此函数唯一的作用是将其（展开后的）参数打印到标准输出。不会添加 make 文件名或行号。此函数的展开结果为空字符串。

## 8.13 shell 函数

`shell` 函数与通配符函数（见第 4.3.3 节 [函数 wildcard]，第 24 页）不同，它能与 make 外部的世界进行通信。

`shell` 函数的作用与大多数 shell 中反引号（``'``）的作用相同：它执行*命令展开*。这意味着它接受一个 shell 命令作为参数，并求值为该命令的输出。`make` 对此唯一的处理是将每个换行符（或回车/换行符对）转换并简单删除。

调用 `shell` 函数运行的命令会在函数调用展开时执行（见第 3.7 节 [Make 如何读取 Makefile]，第 16 页）。然而，由于涉及到创建一个新的 shell，你应该仔细考虑在 `shell` 函数中使用递归展开变量与简单展开变量的性能影响（见第 6.2 节 [变量的两种类型]，第 60 页）。

以下是使用 `shell` 函数的一些示例：

```
contents := $(shell cat foo)
```

*将* `contents` 设置为文件 'foo' 的内容，用空格（而不是换行符）分隔每一行。

```
files := $(shell echo \*.c)
```

*将* `files` 设置为 '*.c' 的展开。除非 `make` 使用了非常奇怪的 shell，否则其结果与 '$(wildcard \*.c)' 相同（只要存在一个 .c 文件）。

## 8.14 guile 函数

如果编译 `make` 时使用了 GNU Guile 作为嵌入式扩展语言，则可以使用 `guile` 函数。`guile` 函数接受一个参数，该参数首先由 `make` 以正常方式展开，然后传递给 GNU Guile 评估器。评估器的结果被转换为字符串，并作为 Makefile 中 `guile` 函数的展开。有关编写扩展的详情，见第 12.1 节 [GNU Guile 集成]，第 133 页。

你可以通过检查 `.FEATURES` 变量是否包含单词 `guide` 来判断是否支持 Guile。

## 第 2 章：如何运行 make

## 9 如何运行 make

用于说明如何重新编译程序的 Makefile 可以有多种使用方式。最简单的用法是重新编译所有过期的文件。通常，makefile 的编写方式使得你在不带任何参数的情况下运行 make，它就会执行操作。

但你可能只想更新某些文件；你可能想使用不同的编译器或不同的编译器选项；你可能只想找出哪些文件已过期而不改变它们。

通过在运行 make 时提供参数，你可以执行这些任何一项以及许多其他操作。

`make` 的状态始终为三个值之一：

- 0 如果 make 成功，则状态为 0。
- 2 如果 make 遇到任何错误，则状态为 2。它将打印描述特定错误的消息。
- 1 如果你使用 '-q' 标志且 make 确定某些目标不是最新的，则状态为 1。见第 9.3 节 [不执行配方]，第 101 页。

### 9.1 指定 Makefile 的参数

指定 make 名称的方法是使用 '-f' 或 '--file' 选项（'--makefile'也可以）。例如，'-f altmake' 使用文件 'altmake' 作为 make。

如果你多次使用 '-f' 标志并带参数使用 '-f'，所有指定的文件将共同作为 makefiles。

如果不提供 '-f' 或 '--file' 标志，默认尝试 'GNU Makefile'、'makefile' 和 'Makefile'，并使用这三者中的第一个（见第 3 章 [编写 Makefile]，页 11）。

### 9.2 指定目标的参数

目标是 make 最终努力更新的目标。其他目标如果作为目标的先条件（或目标的先条件），也会被更新。

默认情况下，目标是 makefile 中的第一个目标（不包括以点开头的目标）。因此，makefile 的编写通常使得第一个规则用于编译整个程序或程序。如果 Makefile 中的第一个规则有多个目标，只有第一个目标会成为默认目标，而不是整个列表。你可以使用 `.DEFAULT_GOAL` 变量管理默认目标的选择（见第 6.14 节 [其他特殊变量]，第 73 页）。

在运行 make 时提供参数，你可以执行这些任何一项以及许多其他操作。

`make` 的状态始终为三个值之一：

- 0 如果 make 成功，则状态为 0。
- 2 如果 make 遇到任何错误，则状态为 2。它将打印描述特定错误的消息。
- 1 如果你使用 '-q' 标志且 make 确定某些目标不是最新的，则状态为 1。见第 9.3 节 [不执行配方]，第 101 页。

`makefile` 中的任何目标都可以指定为目标（除非它以 '-'开头或包含 '='，会被解析为开关或变量定义）。`makefile` 中的目标也可以被指定，只要 make 能找到它们。Make 将将特殊变量 `EMMDGOALS` 设置为你指定的目标列表。如果没有在命令行上给出目标，该变量为空。一种用途是运行一个伪目标（见第 4.5 节 [伪目标]，第 29 页）或空目标（见第 4.7 节 [记录事件的空目标文件]，第 31 页）的配方。许多 Makefile 包含一个删除源文件的伪目标 'clean'。自然这在你显式调用 'make clean' 时才会执行。

- `all` - 生成 Makefile 知晓的所有目标。
- `clean` - 删除所有不是 make 创建的文件。
- `mostlyclean` - 类似于 'clean'，可能会克制删除某些通常不需要制作的文件。例如，GCC 的 'mostlyclean' 目标不删除 'libgcc.a'，因为重新编译它很少必要且耗时。
- `distclean` - 这些目标中的任何一个都可以定义删除比 'clean' 更多的。例如，这将删除你通常为编译准备工作创建的配置文件或链接，即使 Makefile 无法创建这些文件。
- `'install'` 将可执行文件拷贝到用户通常搜索命令的目录中；将可执行文件使用的任何辅助文件拷贝到它查找这些文件的目录中。
- `'print'` 输出已更改源文件的列表。
- `'tar'` 为源文件创建一个 tar 文件。
- `'shar'` 为源文件创建一个 shell 存档文件（shar 文件）。
- `'dist'` 为源文件创建一个发行文件。这可能是一个 tar 文件，或者上述任一文件的压缩版本，甚至可能是上述多个文件的组合。
- `'TAGS'` 更新此程序的的标签表。
- `'check'` `'test'` 对程序的 makefile 构建进行自测试。

### 9.3 暂不执行配方（Recipes）

`makefile` 通过 `how` 规则来判断目标是否是最新的，以及如何更新每个目标。更新目标并不总是你所希望的。某些选项可以为 make 指定执行其他活动。

- `-n`
--just-print
--dry-run
--recon

> “无操作（No-op）”。导致 make 打印出使目标保持更新所需的配方，但不会实际执行它们。请注意，使用此标志时，某些配方仍会被执行（参见第 5.7.1 节 [MAKE 变量的工作原理]，第 51 页）。此外，更新包含的 makefiles 所需的配方仍然执行（参见第 3.5 节 [如何重新makefile]，第 14 页）。

- `-t`
--touch

> “触摸（Touch）”。将目标标记为最新而不实际更改它们。换句话说，make 防止更新目标，但并未真正改变其内容；而是只更新它们的修改时间。

- `-q`
--question

> “提问（Question）”。静默检查目标是否是最新的，但不执行配方；退出代码显示是否需要任何更新。

- `-W file`
--what-if=file
--assume-new=file
--new-file=file

> “如果……（What if）”。-W 标志后跟着一个文件名。make 会将给定文件的修改时间记录为当前时间，尽管实际的修改行保持不变。你可以结合 '-w' 标志使用 '-n' 标志，查看如果你修改了特定文件会发生什么。

使用 '-n' 标志时，make 会打印它通常会执行的配方，但通常不会执行它。

使用 '-t' 标志时，make 会忽略规则中的配方，并（实际上）对每个需要重做的目标使用命令。touch 命令也会被打印出来，除非使用了 '-s' 或 -SILENT。为了速度考虑，make 不会实际调用 touch 程序；它会自己完成这项工作。

使用 '-q' 标志时，make 不打印任何内容并执行配方，但仅当所考虑的目标都已是最新的时，退出状态才返回零。如果退出状态为一，则需要进行某些更新。如果 make 遇到错误，退出状态为零，因此你可以区分错误和目标未更新的情况。

在 make 的同一次调用中使用这三个标志中的多个标志是错误的。

'-n' 和 '-q' 选项不影响以 '+' 开头或包含字符串 '${MAKE}' 或 '${MAKE}' 的配方行。请注意，只有包含 '+' 字符或 '${MAKE}' 或 '${MAKE}' 字符串的**行**不受这些选项影响。同一规则中的其他行不受影响，除非与 '+' 一起使用或包含 '${MAKE}' 或 '${MAKE}'（参见第 5.7.1 节 [Make 变量的工作原理]，第 51 页）。

'-t' 标志防止伪目标（参见第 4.5 节 [伪目标]，第 29 页）被更新，除非有以 '+' 开头或包含 '${MAKE}' 或 '${MAKE}' 的配方行。

'-w' 标志提供了两个功能：

- 如果使用 '-n' 或 '-q' 标志，你可以看到如果你修改了某些文件 make 会做什么。
- 在不使用 '-n' 或 '-q' 标志的情况下，当 make 实际执行配方时，'-w' 标志可以引导 make 像任何文件都已生成一样，而不实际运行这些文件的配方。

请注意，选项 '-p' 和 '-v' 允许你获取关于 make 或使用的 makefiles 的其他信息（参见第 9.7 节 [选项总结]，第 104 页）。

### 9.4 避免重新编译某些文件

有时你更改了一个文件，但不想重新编译所有依赖它的文件。例如，假设向其他文件依赖的头文件添加了宏或声明。为了保守起见，make 假设头文件中的任何更改都需要重新编译所有依赖文件，但你知道它们不需要重新编译，你不想浪费时间等待它们编译。

如果你在更改头文件之前预料到了这个问题，可以使用 '-t' 标志。该标志告诉 make 不要运行规则中的配方，而是通过最后修改日期将目标标记为最新。你可以遵循以下步骤：

1. 使用命令 `make` 重新编译真正需要重新编译的源文件，确保在开始之前对象文件是最新的。
2. 在头文件中进行更改。
3. 使用命令 `make -t` 将所有对象文件标记为最新。下次运行 make 时，头文件中的更改将不会导致任何重新编译。
