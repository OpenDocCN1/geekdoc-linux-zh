
```
HOSTS = (bilbo frodor thorin snowball)
FILES = /etc/auto_master /etc/auto_home /etc/auto_apps
${FILES}->${HOSTS}
    install;
```

`distfile` 是一个强大的机制。在这个例子，我们利用了创建变量的能力。通过指定要更新的主机和要发送的文件，我们可以轻松地添加它们。我们定义了 `$FILES` 和 `$HOSTS`，指示在列出的主机上应保持文件最新。`install`（依赖于它的单行命令）是许多 `rdist` 命令之一，它表示 `rdist` 应该保持文件与本地副本同步。有关指令和 `distfile` 选项的更多信息，请查看 man page。

要使用此功能，可以将 `distfile` 添加到创建自动挂载器映射主集的目录中。每当我们进行更改，就会执行：

`rdist`

`rdist` 可用于更复杂的任务，例如在冗余文件服务器之间同步用户目录，或者在未使用 NFS 的情况下分发新版本的软件包。

`rdist` 的缺点是它与任何其他远程 shell 命令具有相同的安全要求。执行 `rdist` 命令的用户必须能够连接到远程主机并在无密码的情况下执行命令。（参考下文“网络安全问题”）

如果与 `rdist` 相关的安全问题不可接受，我们该如何方便地分发这些映射？

Sun Microsystems 的网络信息服务 (NIS)（也经常被称为 "yp" 或黄页）可能是一个可以接受的替代方案。NIS 从服务器或一组服务器向网络中的主机提供常见的配置信息，如 IP 地址、服务端口号和 `automount` 映射。

NIS 服务器拥有主副本。NIS 客户端从服务器获取信息，而不是在网络中自行查找。

如果客户端无法联系服务器处理请求，请求将等待直到找到服务器。

显然，NIS 有它自己的问题，是一个在选择之前需要仔细检查的系统。

NIS 的主要优势是方便性。当使用了辅助服务器时，在一个地方看到所有信息是非常方便的，这对于保持网络正常至关重要。

然而，也有一些明显的缺点。

使用 NIS 的工作站如果没有某些修改无法解析 IP 地址。NIS 解决了这个问题，但尚未被其他版本支持（此处省略）。

如果 passwd 文件由 NIS 分发，加密密码字段可以被任何连接的人读取。这可以被许多黑客利用，通过可用软件破解密码。

知情用户只需要妥协其中之一，就可以对它们造成毁灭性的影响。

一些可能的预防措施包括：

- 尽可能少使用 root。root 绝不应用于远程操作，这是一个足够简单的通用规则。

- 避免在可以使用 telnet 的地方使用 login。

- 如果你必须使用 login，尝试在不使用 .hosts 或 hosts.equiv 的情况下进行。

- 如果你需要为备份或信息收集等操作使用非交互式登录，请为其创建一个特殊账户，该账户应具有访问任务所需的文件和设备的权限。

- 在任何直接连接到互联网的系统上，远程登录都是不可可能的。

（请注意，通过 ISP 拨号接入互联网的系统并非真正的直接连接。）

关于第一条规则的解释如下：在日常操作中，root 账户应尽可能少使用。许多人对 Unix 进行了神话化，认为 root 访问对于完成任何有意义的任务都是必须的，这完全并非如此。没有理由让普通操作（如执行备份、扫描日志或运行网络服务）以 root 身份运行。（历史原因，Unix 仅允许以 root 身份运行的进程监控小于 1024 的端口。）root 使用得越频繁，发生意外且灾难性后果的概率就越大。

即使在远程登录之外，Unix 还提供了许多网络服务。文件共享、电子邮件、X-windows 以及信息服务（如 DNS 和 NIS）仅是网络所提供的灵活性和扩展性的部分。然而，这些许多服务代表了风险，这些风险并非总是必要的，而且有时是不可接受的。

处理服务的正确方法是评估需要哪些服务，并启用每一个服务。许多网络服务由 inetd 管理。此守护进程监听对网络服务的请求，并执行相应的程序来提供服务。

例如，ftp 服务由 inetd 管理。当接收到 ftp 服务（服务端口号 21）的请求时，inetd 会查询其配置信息并执行 ftpd。它的输入和输出流与请求者连接。

网络服务通过端口识别。像 ftp 和 telnet 等常用服务具有众知的端口，即所有客户端都需要知道的数字。inetd 根据其包含在 `inetd.conf` 文件中的配置数据绑定并监听这些端口。

一个典型的配置文件如下：

```
# Configuration file for inetd(1M). See inetd.conf(4).
#
## To re-configure the running inetd process, edit this file, then
# send the inetd process a SIGUP.
#
# Syntax for socket-based Internet services:
# <service_name> <socket_type> <proto> <flags> <user> <server_pathname> <args>
ftp stream tcp nowait root /usr/sbin/in.ftpd in.ftpd
telnet stream tcp nowait root /usr/sbin/in.telnet in.telnet
# Tnamed services the obsolete IEN-116 name server protocol.
```

| name | dgram udp wait root /usr/sbin/in.tnamed in.tnamed | # Shell, login, exec, comsat and talk BSD protocols. |

- shell stream tcp nowait root /usr/sbin/in.rshd in.rshd

- login stream tcp nowait root /usr/sbin/in.logrind in.logrind

- exec stream tcp nowait root /usr/sbin/in.rexecd in.rexecd

- comsat dgram wait root /usr/sbin/in.comsat in.comsat

- talk dgram wait root /usr/sbin/in.talkd in.talkd

如注释所示，inet 的信息可以在两个不同的手册页中找到。

每个配置项输入了服务的端口名称，该名称由 `/etc/services` 文件（或 NIS 映射）解析，以及关于连接的更多信息、程序应该以哪个用户身份运行，以及要运行的程序。从安全角度来看，该文件最重要的方面是服务是什么以及它们运行的是什么。（关于网络连接的详细信息见第 20 节，网络。）

每个服务名称都对应一个数字。从 1024 开始编号的端口（ftp、telnet 和 login 都可以附加到 root），因此 root 本身必须以 root 身份运行，但它为我们提供了以其他用户身份运行单个程序的选项。其原因很简单：如果一个程序以 root 身份运行且被攻破，攻击者将拥有 root 权限的“后门”，允许用户修改文件，攻击者从理论上可以使用该程序读取、复制或修改底层主机上的任何文件。

一些最严重且有效的互联网攻击利用了以 root 身份运行的网络中未被记录的功能和漏洞。因此，防止下次攻击的最佳方法是完全避免该服务，或者在攻击者获得利用机会时，让他们拥有尽可能少的权限。

大多数 UNIX 变体都取消了以 root 运行，并且在某些情况下，如 rexec 等不受欢迎的服务在没有验证的情况下被频繁使用。如你所见，此服务来自供应商并配置为 root 身份。许多组织配置系统拒绝除其旨在提供的服务之外的所有网络服务，例如互联网和 ftp 服务器。

良好的网络软件还将这些问题纳入配置中。它监听 http 端口（端口号为 80），因此只能绑定到 root。Apache 并不是以 root 身份处理请求并带来巨大的安全风险，而是以 root 身份接受连接，但以几乎没有权限的用户身份处理实际请求。它通过运行多个副本来实现这一点。

相同的快捷键、菜单和鼠标移动。X-windows 并不具备这一优势。

X-windows 是一个应用程序集合，而不是操作系统的一部分。由于其结构是如此，它与 Macintosh 或 Microsoft Windows 上的窗口系统大不同。因此，X 应用程序与操作系统之间的关系往往比其他平台更松散。

赋予 X 桌面“个性”的特性之一是窗口管理器。这个应用程序为每个窗口提供边框，并允许它们进行移动和重叠。然而，它只是一个应用程序，而不是 X-window 系统的一部分。这种分离使用户可以选择他们所需的管理器，就像同一系统上的不同用户也可以使用不同的窗口管理器。窗口管理器之间的差异显著，对桌面的外观、鼠标操作以及哪些应用程序可以运行产生重大影响。

由 Sun 分发并适用于许多 Linux 发行版的 OpenLook 管理器具有许多专有扩展，并且非常轻量且快速。然而，它在外观和感受上与 Macintosh 或 Microsoft Windows 几乎没有相似之处。（有一点，它大量使用鼠标右键，而 Microsoft Windows 最近才引入这一功能，而在 Macintosh 上则不存在。）Sun OpenWindows 软件包带有 OpenLook 以及一组用于读取邮件、管理文件和一些常用任务的工具。

Motif 与 Microsoft Windows 有许多相似之处，在过去几年中变得更加流行，大多数主要供应商同意采用通用桌面环境 (CDE)，而 CDE 很大基于 Motif。CDE 还具有额外功能，例如图形化文件管理器、工具栏和对虚拟屏幕的支持。CDE 还带有一组用户应用程序。

窗口管理器还带有用于创建菜单和其他编程任务的程序库。因此，可能会创建一个在某些窗口下运行不佳，或需要 UNIX 不具备的库的应用程序。这是 Linux 上的 Motif 的一个常见问题，因为这些库不是免费的。出于这个原因，许多应用程序以非免费版本提供，或者通过静态链接库，这意味着它们被构建在应用程序内部。（这通常被认为是不理想的，因为会让应用程序变得更大，并需要更多的内存和磁盘空间。）

Windows 3.x 使用 .win 和 .ini 文件方案；Windows 95 和 Windows NT 使用注册表。两者都作为应用程序配置信息的中央存储库。X-windows 有它自己的用于配置管理的标准接口，称为 X resources。X resources 比许多 Windows 更加灵活。

X resources 支持参数，这允许管理员（以及用户）在不同的应用程序之间标准化行为。大多数 X-windows 开发人员都认可这种能力，并在配置参数使用标准的命名方案，这使得通配符的使用更加方便。

用户能够通过维护个人资源文件来定制应用程序以反映其个人偏好，而不影响他人，不像那些为整个系统维护一套参数的系统。管理员仍然有设置默认参数的能力，因此不希望自定义应用程序的用户仍然拥有基本的功能。

# 命令行界面

命令行真正展示了 UNIX 悠久的历史和多样性。人们可能会认为每个程序都是由不同的人为了不同的目的编写的，而且事实也确实如此。

在命令行选项方面，命令行工具之间几乎没有凝聚力。然而，`find` 命令对选项使用缩写而不是字母，看起来几乎像是一门新语言。大多数命令需要用 `-` 来区分不同的参数，而另一些则。某些命令使用不同方言的表达式。

同一个命令也经常有两个版本：一个来自 System V 世界，一个来自 BSD 世界。我最喜欢的例子是 `mail` 命令。`mail` 命令是一个简单的、基于文本的、几乎没有功能的邮件读取和发送工具。不过，这个命令有两个版本，因此在创建最基础的读取器时，一定有很多值得分歧的地方。

两个 `mail` 命令都可以用于从命令行发送电子邮件以及用于无人值守脚本作业，因为它们会通过电子邮件提醒管理员问题。BSD 版本允许你在命令行上指定主题：

```
mail -s "Backup Results" (hyperlink mailto:eric@niftydomain.com ) < backup.txt
```

其中 `-s` 是邮件主题的选项。System V 版本的 `mail`（Solaris 的默认版本）静静地忽略 `-s` 选项。这导致了在三个不同的场合我都在排查为什么我的邮件没有主题。

这两个主要变体之间的另一个区别是 `ps` 命令。两个命令都提供关于运行程序的相同信息。但命令行参数完全不同。

避免这些无意义且多余差异引起问题的最佳方法，是充分利用手册页（man pages）包含的丰富信息。（在本章的“管理资源”部分，我们涵盖了从它们中获取更多信息的几种方法。）并记住以下几点：

- UNIX 已经存在了 25 多年。你遇到的问题还没有被某人解决的概率有多大？在你花费大量时间解决问题之前，先花点时间阅读关于该问题以及你正在使用的工具的页面。

- UNIX 系统上的许多工具已经存在了 25 多年。能够持久的软件一定有其过之处。

- 尝试这些工具，并偶尔尝试使用不同的方法解决同一个问题。有时你可以学到新的花技巧，在未来为你节省几个小时的时间。

# 系统管理任务

系统管理通常可以分为两大类：支持用户和支持系统。

## 支持用户

用户是你的客户。没有他们，网络将变成一台计算机，可能只运行着像 Doom 这样无聊的应用程序，不会产生任何业务或创造新的销售额。（听起来很糟糕，不是吗？）

## 添加节点

系统管理中的一项常见任务是向网络中添加新节点。这也是工作中真正能够从规划和洞察中获益的环节之一。

并非所有系统都是平等的，并非所有系统的用途也都相同。在网络规划中，花时间了解你的网络真实用途，然后将其应用于系统设计是关键所在。工作站应该有明确定义的角色，并根据这些角色进行配置。

在系统进行设计和评估时，管理员可以提出的一些问题包括：

- 用户是否能够访问全部或部分系统？用户是否需要访问多个系统？是否存在用户永远不应该访问的系统？

- 每一个工作站需要访问哪些网络文件系统？是否有足够的文件能让 `automount`（自动挂载）有所帮助？

- 工作站需要提供哪些网络服务（例如 telnet、远程登录、共享文件系统和电子邮件）？每种服务的合理性何？

工作 工作站需要访问哪些网络？是否存在从其他网络无法访问的网络？

这些问题帮助我们为每个工作站制定一个配置文件（profile）。遵循配置文件使得工作站更容易构建、维护和故障排除，更不用说由于它们通常复杂性较低，因此更加可靠。

备份可能会复制、丢失、意外覆盖或删除。备份是我们防止这些情况的唯一保护，因为 UNIX 并没有“撤销”（undelete）功能。

UNIX 提供了几种备份工具，决定使用哪些工具可能是一项困难的任务。

在本章前面的部分，我们曾有一个关于使用 `tar` 和 `dd` 将目录备份到远程磁带驱动器的示例。在该示例中，`cd` 仅被是将数据流拷贝到磁带的方法，而 `tar` 才是执行备份的命令。

`tar`（存档）是一个常用的备份工具。

```
tar -c -f /dev/rmt0 /home/eric
```

不同变体的磁带驱动器的设备名称会有所不同。BSD 设备通常将它们称为 `/dev/rmt0`，其中 `0` 是第一个，`1` 依此类推。（Linux、HP/UX 和 SunOS 4.1x 使用这种命名法。）System V 衍生版本以相同的方式使用 `/dev/rmt`。（AIX 使用这种模型。）但然而，基于 System 的 Solaris 2.x 在路径中增加了一个目录，因此它是 `/dev/rmt/1`。

`-f` 选项允许 `tar` 写入驱动器，而 `-c` 选项用于创建一个新存档而不是修改现有存档。`tar` 的特性之一是，当给它一个路径作为回指（back specification）时，它会被添加到存档，因此当我们需要恢复 `/home/eric` 时，它将恢复在那里。实现此操作更灵活的方法是：

```
cd /home/eric
tar -cf /dev/rmt/0
```

`tar` 识别 `[点]` 意味着备份当前目录。当提取存档时，无论当前目录位于何处，它都会被放在当前目录下。

`cpio` 是另一个 UNIX 备份工具。它的接口比 `tar` 稍微复杂一点，但具有几个优点。

`cpio` 通常配合 `ls` 或 `find` 使用来创建存档。

```
find . -print | cpio -o > /dev/rmt0
```

`find` 命令将其当前目录下所有文件的完整路径提取到标准输出。`cpio` 接受这些文件名并将它们存档到标准输出。这被重定向到磁带，并在那里进行存档。该命令是 UNIX 组合命令来创建新工具的极佳示例。

`find` 是一个用于查找文件的工具。可以通过名称、大小、创建日期、修改日期以及此处未详述的海量标准来定位文件。（一如既常，请查看 man页（帮助页）！）这个示例利用了这个定位文件的工具并构建了操作备份系统的用户界面。

`cpio` 是文件拷贝和存档的“瑞士军刀”。除了以适合磁带的格式流文件外，它还可以：

- 备份特殊文件，例如设备驱动器 `/dev/rmt0`。

- 比 `tar` 或 `dd` 更高效地将数据放在磁带上。

- 在恢复时跳过磁带或文件上的区域，而 `tar` 会直接崩溃。使用 `cpio`，你至少可以恢复损坏存档的部分。

- 执行文件备份，包括将单个存档分散到多个磁盘上。`tar` 只能将单个存档放在磁盘上。

- 在存档或提取时交换字节，以帮助文件从一个架构传输到另一个架构。

这个示例还说明了我们如何将标准输出重定向到设备文件名，并期望设备驱动将其放置。

我们的示例可以扩展为一个功能完整的备份系统。由于 `find` 允许我们根据创建和修改日期选择文件，我们可以每周使用 `find` 列出所有文件并在磁带进行一次全备，并每隔一天对文件进行增量备份。UNIX 命令行是一个非常强大的工具，特别是那些在过去的三十年中为了其稳定性而设计的程序。
