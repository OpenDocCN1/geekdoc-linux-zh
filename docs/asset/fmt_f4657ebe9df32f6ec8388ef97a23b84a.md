
对 shell 具有特殊含义的字符需要进行转义。Bash 中的转义字符是反斜杠 `\`，大多数 shell 也是如此；它会消除后续字符的特殊含义。shell 识别许多非常特殊的字符，最常见的包括 `/` 和 `*`。你可以在 shell 的 Info 页面和文档中找到完整列表。

例如，假设你想显示文件 `"*"` 而不是目录下的所有文件，你必须使用：

```
less \*
```

对于包含空格的文件名也是如此：

```
cat This\ File
```

## less 胜于 more

无疑，你在 UNIX 环境下工作时，早晚会听到有人说这句话。一点 UNIX 知识可以解释这一点：

- 首先是 `cat`。输出以一种不可控的方式流出。
- 接着是 `pg`，在较旧的 UNIX 上可能仍然找到。该命令此时将文本输出到输出页。
- `more` 是 `pg` 的修订版本。该命令在每个 Linux 系统上仍然可用。
- `less` 是 `more` 的 GNU 版本，具有额外的功能，允许高亮搜索字符串、向上滚动等。其语法非常简单：

```
less name_of_file
```

更多信息位于 Info 页面中。

## 链接文件

### 链接类型

由于我们对文件及其在文件系统中的表示有了更多了解，理解链接（或快捷方式）轻而易举。链接无非是将两个或多个文件名映射到同一组文件数据。实现这一目标有两种方法：

- 硬链接（Hard link）：将两个或多个文件名与同一个 inode 关联。硬链接共享硬盘上的相同数据块，但它们继续表现为独立文件。有一个直接的缺点：硬链接不能跨分区，因为 inode 只有在给定的分区内是唯一的。
- 软链接或符号链接（Soft link or symbolic link，或简称：symlink）：一个指向另一个文件的小文件。符号链接包含硬盘上物理位置的目标文件的路径。由于该系统不使用 inode，软链接可以跨越分区。

有人可能会辩称存在第三种链接，即用户空间链接，类似于 MS Windows 中的快捷方式。这些是包含元数据的文件，只能由图形化文件管理器解释。对于内核和 shell 来说，这些只是普通文件。它们可能以 `.desktop` 或 `.link` 后结尾；可以在 `~/.gnome-desktop` 中找到示例：

## 符号链接

符号链接对于用户来说特别有趣，类似于 Windows 中的快捷方式。创建符号链接的命令是 `ln`。

为了创建符号链接，需要使用 `-s` 选项：

```
ln -s targetfile linkname
```

在下面的示例中，用户 freddy 在家目录下创建一个链接：

```
freddy:~/music> ls -l /opt/mp3/
```

```
-rw-r---- 5 Jan 15 12:39 Queen
```

```
lrwxrwxrxr-x 1 freddy 5 Jan 22 11:00 Queen -> /opt/mp3/Queen
```

符号链接被广泛使用。它们通常用于节省磁盘空间，而小文件的大小与原始文件相同。

## 文件安全

### 权限：Linux 的第一道防线

Linux 安全模型基于 UNIX 系统使用的模型，并且与其一样严格（有时甚至更健壮）。在 Linux 系统上，每个文件都由一个用户和一个组所有。还有第三类用户，即既不是文件所有者也不属于文件所有组的用户。对于每类用户，都可以授予或拒绝读、写、执行权限。

我们之前使用长选项通过 `ls -l` 命令列出文件是出于其他原因。该命令还显示了这三类用户的文件权限；它们由第一个字符之后的字符指示，第一个字符是权限开头的文件类型。如下例所示，这九个访问权限序列中针对实际所有者的前三个字符。接下来的三个是针对文件所有组，最后三个是针对其他用户的。权限始终以相同的顺序排列：用户、组和其他用户的读、写、执行。示例包括：

```
--rw-r---- 1 marise users 5 Jan 15 12:39 To_Do
-rwxr-xr-x 1 root root 45948 9 15:01 /bin/ls*
```

第一个文件是普通文件（第一个字符）。用户名 marise 或属于用户组的用户可以读取和修改（移动/删除）文件，但他们无法执行（第二个和第三个横杠）。所有其他用户只被允许读取此文件，不能写入或执行（第四个和第五个横杠）。
