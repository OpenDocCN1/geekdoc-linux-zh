
虽然 `locate` 程序可以仅根据名称找到文件，但 `find` 程序会根据各种属性在给定的目录（及其子目录）中搜索文件。我们将花费大量时间来研究 `find`，因为它有很多有趣的功能，当我们开始在后面的章节中涵盖编程概念时，会反复看到它们。

## 运算符

即使有了 `find` 提供的所有测试项，我们可能仍然需要更好的方法来描述测试项之间的逻辑关系。例如，如果我们需要确定一个目录中的所有文件和子目录是否具有安全权限呢？我们需要查找所有权限不是 `0600` 的文件以及所有权限不是 `0700` 的目录。幸运的是，`find` 提供了一种使用逻辑运算符组合测试项的方法，以创建更复杂的逻辑关系。对于上述测试，我们将这样操作：

```
me@linuxbox~$ find ~ -type f -not -perm 0600 -or -type d -not -perm 0700
```

哎呀！这看起来很奇怪。这些到底是什么？实际上，一旦你了解了它们，这些运算符并不复杂。表 17-4 描述了与 `find` 使用的逻辑运算符。

### 表 17-4：find 逻辑运算符

| 运算符 | 描述 |
| :--- | :--- |
| `-and` | 如果运算符两边的测试都为真，则匹配。这可以缩写为 `-a`。注意，当没有运算符存在时，默认隐式包含 `-and`。 |
| `-or` | 如果运算符一侧的测试任为真，则匹配。这可以缩写为 `-o`。 |
| `-not` | 如果运算符后的测试为假，则匹配。这可以使用感叹号进行缩写 `!`。 |

将测试项和运算符组合在一起以形成大的表达式。这用于控制逻辑求值的优先级。`find` 从左到右进行求值。通常需要覆盖默认的评估顺序以获得预期的结果。即使不需要，使用分组字符来增加命令的可读性也是有帮助的。注意由于括号对 `shell` 有特殊含义，因此在命令行上使用时必须对其加引号，以便允许它们作为参数传递给 `find`。通常使用反斜杠字符进行转义。

有了这个运算符列表，让我们来解构我们的 `find` 命令。从最高层看，我们看到测试项被排列为两个由 `-or` 运算符分隔的分组。

```
( expression 1 ) -or ( expression 2 )
```

这是合理的，因为我们正在寻找具有某组权限的文件和具有另一组权限的目录。如果我们同时寻找文件和目录，为什么我们使用 `-and` 而不是 `-or` 呢？当 `find` 扫描文件和目录时，每一项都会被评估是否匹配指定的测试项。我们想知道它是一个具有错误权限的文件，还是一个具有错误权限的目录。它不可能同时是两者。所以，如果我们扩展分组表达式，可以这样理解它：

```
( 具有错误权限的文件 ) -or ( 具有错误权限的目录 )
```

我们的下一个挑战是测试“错误权限”。我们如何做这一点？我们不这样做。我们将测试“非良好”，因为我们知道“良好权限”是什么。对于文件，我们将良好定义为 `0600`，对于目录，我们将其定义为 `0700`。测试“非良好”的表达式如下：

```
-type f -and -not -permissions 0600
```

对于目录，如下：

```
-type d -and -not -permissions 0700
```

如表 17-4 所示，`-and` 运算符可以安全地移除，因为它是默认隐式的。所以，如果我们把这一切整合在一起，可以得到：

```
find ~ -type f -not -perm 0600 -or -type d -not -perm 0700
```

并且动作的顺序非常重要。例如，如果我们重新排列测试和动作，让 `-print` 动作成为第一个，那么命令的行为将会有很大不同。

```
find ~ -print -and -type f -name '*.bak'
```

此版本的命令将打印每个文件（`-print` 动作始终为真），然后测试文件类型和指定的扩展名。

## 用户定义动作

除了预定义的动作外，我们还可以调用任意命令。这种传统方法是使用 `-exec` 动作。该动作的作用如下：

```
-exec command { } ;
```

在这里，`command` 是命令名称，`{}` 是当前路径的符号表示，分号是必须的分隔符，表示命令的结束。这里有一个使用 `-exec` 实现类似于之前讨论过的 `-delete` 动作的示例：

```
-exec rm '{}' ;
```
