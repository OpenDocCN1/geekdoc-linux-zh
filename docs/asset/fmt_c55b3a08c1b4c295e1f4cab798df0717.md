
# Linux 词典

## Unicode
国际字符集。美国 `ASCII` 使用 7 位编码文本。英语语言中少于 100 个字符（26 个大写、26 个小写、10 个数字和许多标点符号）。7 位有 128 种组合，足以覆盖少数正确的代码。然而，还有其他字母，如俄语、希腊语和希伯语。更糟糕的是，远东语言如中文、日语和韩语使用符号/意字表示没有字母表的单词。`Unicode` 字符集的建立是为了以 2 字节（16 位）格式表示所有这些字符。所有流行语言的约 30,000 个字符已达成国际格式。关键点：计算机的设计是为了处理 1 字节字符，不支持每个字符处理 2 字节。因此，设计了多字节字符集来存储 `Unicode`。`UTF8` 是一种原生字符集，其字节数取决于表示字符需要多少字节/位。关键问题是 7 位 `ASCII` 字符是否以所有形式编码。例如，旧的 Microsoft `IIS` Web 服务器会检查回溯头。然而，`UTF8` 编码的回溯将绕过 `IIS` 检查，但仍会被发布到文件系统。

`'.'` 的二进制编码：`0xxxxx`–7 位 `2E` `100000` `11xxxxx`–11 位 `10xxxxxx` `10xxxxxxx`–15 位 `0 E0 80 AE`

另见：编码，来自 Hacking-Lexticon

## Linux
考虑到 Unix 的成功，这是黑客文化对抗行业地位的最重要胜利（但某些关于 Unix 和 Unix 的阴谋论持有相反的观点）。参见 Version 7、`BSD`、`US Linux`。人们对这应该标记为 `Unix` 还是 `UNIX` 感到困惑；两种形式都很常见，且可以通用。丹尼斯·里奇（Dennis Ritchie）表示，“Unix 的拼写最初出现在 CACM 1974 年的论文《Unix 分享系统》中，我们当时有一台新的排版机，于是发明了它，我们沉浸在能够制作小型大写字母中。”德默（Demmer）曾尝试在贝尔实验室的论文中将拼写改为 `Unix`，理由该词并不是缩写词。他失败了，并最终在该问题上“彻底败北”。因此，虽然现在的商标是 `UNIX`，但两种大小写方式都源于古老的用法；J 文件使用 `Unix` 来维护德默的意愿。源自术语词典 (Jargon Dictionary) `http://www.tld.org/LDP/Linux-Dictionary/index.html`

操作系统（运行在计算机上的基础软件，位于文字处理程序和电子表格等软件之下）被许多人同时使用（它是多用户系统），并内置了 `TCP/IP`。它是互联网上最常见的操作系统。苹果计算机的 Macintosh 操作系统从第 10 版本开始基于 Unix。源自 Matisse `http://www.tld.org/LDP/Linux-Dictionary/index.html`

一种在互联网上使用的操作系统。上行（Uplink）：指从地面站到卫星的通信链路。源自远程教育与互联网术语表 (Glossary of Distance Education and Internet Terminology) `http://www.tld.org/LDP/Linux-Dictionary/index.html`

一种用于从大型机到个人电脑各种计算机、支持多任务处理的操作系统，非常适合高级用户的需求。`Unix` 是一个非常灵活的操作系统，适合高级计算机用户。由于有200 多个命令、不足的错误信息以及复杂的命令语法，`Unix` 给偶尔使用的和技术上不正统的人们带来了沉重的负担。随着像 NextStep 等 `UNIX` shell 的发展，该操作系统在计算中可能会扮演更广泛的角色。由于 20 世纪 80 年代之前监管 T&T 反垄断法禁止贝尔实验室销售 Unix，Unix 被免费提供给北美的大学，并于 1979 年被采用。1979 年，加州大学伯克利分校开发了适用于 VAX 计算机的流行 Unix 版本。20 世纪 80 代初，AT&T 获得了该系统的营销权，并在 1983 年获得了 System V。参见 Berkeley Unix Interface Definition (`SVID`) 和 Linux，广域信息服务器 (`WAIS`)。源自 QUEDIC `http://www.tld.org/LDP/Linux-Dictionary/index.html`

关键点：并没有“`UNIX`”，只有按照相同设计的实现。`Unix` 版本或多相关，存在大量的跨代思想，因此一个版本中的优点最终会合并到其他版本。对比：`UNIX` 有两个分支：`SVR4`（系统发行版4）和 `BSD`（伯克利发行）。许多安全问题取决于系统基于哪个基础。例如：`Solaris`、`IBMX`、`SGI Index`、`Apple/AIX`、`BSD`、`HP/UX`。

关键点：`Unix` 是大小写敏感的且“保留大小写”。`Windows` 有一个也可以处理大小写敏感的兼容模式，这种模式可以被其他技术利用以破坏系统。

关键点：`BSD` 分支有许多开源变体，例如 `FreeBSD` 和 `OpenBSD`。`OpenBSD` 被认为 `UNIX` 最安全的版本之一。安全专家花费最多时间在 `OpenBSD` 上清理缓冲区重叠等漏洞。然而，在 1999 年，极高的黑客率和漏洞发布导致了人们对这些问题的意识提高，这可能导致其他系统在漏洞方面也变得同样安全。

方法：为了加固 Unix，你通常需要执行以下操作：

- 始终从全新的全新安装系统开始。
- 安装时，不要安装任何绝对没有必要的程序。许多人不确定是否某个选项，所以为了保险起见就安装它。相反的（不安装它以确保你不会引入后门）。
- 安装后，删除所有不必要的程序；任何带有 Windows GUI 的程序都是很好的开始。
- 清理 `/etc/inetd/` 中所有不必要的服务。
- 对于任何连接到互联网的服务器，也许那里的所有内容都是不必要的。
- 安装 `Tripwire` 风格的包来检测文件是否发生更改。
- 使用防火墙阻止未经授权的访问。

## .zip 文件的解压程序
`InfoZIP` 的 `unzip` 程序。除了多卷存档外（即 `.ZIP` 文件通过 `PKZIP` 的 `-&` 选项分分在多个磁盘上的情况），该程序可以处理由 `PKZIP` 生成的任何文件，或相应的 `InfoZIP unzip` 程序生成。此版本支持加密。来自 Debian 3.0r0 APT `http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

## unzip
列出、测试和提取 `ZIP` 归档中的压缩文件来自 Whatis `http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

`unzip` 工具用于列出、测试或从 zip 归档中提取文件。zip 文件常见于 MS-DOS 系统。zip 软件包中包含的 zip 实用程序用于创建归档，并与 `PKWARE` 的 `PKZIP` 为 MS-DOS 创建的归档兼容，但该程序的选项和行为在某些方面有所不同。来自 Redhat 8.0 RPM `http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`

## unzip-crypt
`unzip-crypt` 的旧版本包，你应该将其删除。此包仅用于从旧 `unzip-crypt` 到新 `unzip` 的平滑升级。请将其删除。来自 Debian 3.0r0 APT `http://www.tldp.org/LDP/Linux-Dictionary/html/index.html`
