
让我们看看在与内核和应用交互时，不同的CPU模式是如何被使用的。在内核加载完成后，处理器切换至特权模式，并获得对计算机的完全控制权。每个应用程序都以用户模式启动并执行，在该模式下，应用程序无法访问内核资源或其他应用程序。当需要执行由内核实现的操作时，应用程序发起`系统调用`。内核会拦截该调用，将处理器切换到特权模式，执行相应操作，然后切换回用户模式，并将结果返回给应用程序。

系统调用比调用用户实现的函数慢，因为处理器需要在两种模式之间切换两次。对于某些操作系统，部分功能是在用户模式下实现的，因此访问这些功能无需使用系统调用。

## 操作系统架构的实现方式

考虑实现操作系统架构的几种方法。在实际的操作系统中，通常会采用这些方法的某种组合。

## 单体系统

在`单体系统`中，所有基本功能都集中在内核中。在实现单体内核时，操作系统效率更高（在组件交互过程中，处理器无需在模式之间切换），但可靠性较低（所有代码都在特权模式下执行，任何组件的错误都是致命的）。

单体内核并不意味着其所有组件都必须驻留在内存中。现代操作系统允许将代码片段（`内核模块`）动态地放置在内核地址空间中。内核模块的实现也使内核具有可扩展性（要添加新功能，只需开发并在内存中加载相应的模块即可）。

### 多层次系统

`多层次`操作系统的组件形成一个层次结构（层级），每一层都依赖于上一层的功能。最底层直接与硬件交互，最高层实现系统调用。

在传统的多层次操作系统中，从顶层到底层的控制转移是通过系统调用实现的。顶层必须拥有执行该调用的权限，这些权限由硬件支持进行验证。此类系统的一个例子是20世纪60年代开发的`Multics`操作系统。由于性能较差，这种方法在当今的实际应用中受到限制。

层次也可以在单体内核中隔离；在这种情况下，它们通过编程支持实现，但会导致系统实现复杂化。在单体系统中，内核确定以下层次：

- `设备抽象机制`：该层直接与硬件交互，使系统的其他组件免于直接交互
- `核心内核`：负责最基础、最简单的内核操作，例如向磁盘写入数据块。通过这些机制，高层指令在资源管理的协助下执行
- `资源管理工具`（或资源管理器）：实现操作系统的基本功能（进程管理、内存、输入/输出等）。在此级别，使用核心内核做出最重要的资源管理决策
- 系统调用接口：用于与系统软件和应用软件通信

## 微内核系统

现代操作系统的一个趋势是，在特权模式下实现一小部分内核功能，即微内核。其他操作系统功能由用户模式下的进程（服务器进程）执行。服务器负责支持文件系统和处理进程内存。

微内核在系统组件之间进行通信，并执行基本的资源分配。要执行系统调用，进程（客户进程）访问微内核。微内核将请求发送给服务器，服务器执行工作并发送响应回来。微内核将响应转发给客户。客户不仅是单一用户，也可以是其他操作单元。

微内核方法的优势包括：

- 微内核体积小巧，简化了其开发和调试
- 由于服务器在用户模式下运行，且无法直接访问硬件，因此系统可靠性高
- 系统的灵活性和可扩展性更强（不必要的组件不会占用内存空间，扩展系统功能只需添加新的服务器）
- 适应网络环境的能力（服务器与相关网络之间交换数据的方式，或者它们位于同一台计算机上）

微内核方法的主要缺点是性能下降。在系统调用中，处理器的模式切换从两次增加到四次（两次发生在客户与微内核之间，两次发生在服务器与微内核之间）。

这个缺点在理论上较为明显，实际上，微内核的性能和可靠性主要取决于其实现的质量。例如，在`QNX`操作系统中，微内核仅占用几KB内存，提供最小的功能集，系统性能符合实时操作系统标准。

## 虚拟机的概念

在`虚拟机系统`中，通过编程方式创建硬件的副本（发生模拟）。这些副本（`虚拟机`）并行运行，每个都在运行与应用程序和用户交互的软件。

## 架构特性：UNIX 和 Linux

### UNIX 基本架构

`UNIX`是操作系统架构相当简单的一个例子。该系统的许多功能都包含在内核中，内核通过系统调用与应用程序通信。

系统有三个主要组件：进程管理子系统、文件系统和I/O子系统。`进程管理子系统`控制进程的创建和删除、系统资源在进程间的分配、进程间交互以及内存管理。

`文件子系统`为访问存储在磁盘驱动器和外围设备上的数据提供了统一的接口。这种接口是`UNIX`最重要的特性之一。使用相同的系统调用，既可以与磁盘通信，也可以输出到终端或打印机（程序像处理文件一样处理打印机）。在这种情况下，文件系统将请求转发到I/O子系统的相关模块，而这些模块则直接转发到外围设备。此外，文件子系统还控制文件访问权限，这在很大程度上决定了用户在系统上的权限。

I/O子系统通过与设备驱动程序交互来执行文件系统请求。在`UNIX`中，有两种类型的设备：字符设备（例如打印机）和块设备（例如硬盘）。它们的主要区别在于，块设备允许直接访问。为提高块设备的效率，使用缓冲区高速缓存——即存储最近从磁盘扫描的数据的内存块。后续对这些数据的访问可以从高速缓存中获取。

### Linux 架构

`Linux`主要由三部分组成：

- 核心：实现操作系统的基本功能（进程管理、输入/输出、内存等）
- 系统库：为应用程序定义标准函数集（执行这些函数无需切换到特权模式）
- 系统实用程序：执行专门任务的应用程序

### Linux 内核的目的及其特性

`Linux`实现了单体内核技术。所有内核数据和数据结构都位于同一地址空间中。内核中有几个功能组件。

- 进程调度器：负责在系统中实现多任务处理（中断处理、定时器操作、进程的创建和完成、上下文切换）

## 内存管理器

- 为每个进程分配独立的地址空间，并实现虚拟内存的支持。

## 虚拟文件系统

- 提供一种通用接口，用于与各种文件系统和 I/O 设备进行交互。

## 设备驱动程序

- 提供对外围设备的直接访问。它们通过虚拟文件系统接口被访问。

## 网络接口

- 提供对网络协议实现和网络设备驱动程序的访问。

## 互操作子系统

- 提供机制，允许系统中的不同进程相互通信。

这些子系统中的某些是系统的逻辑组件；它们与内核一起加载到内存中，并永久保留在那里。其他子系统（例如设备驱动程序）的组件是这样实现的：它们的代码可以按需加载。为了实现这一点，`Linux`支持内核模块的概念。

### 内核模块

`Linux`内核允许按需加载和卸载代码的各个部分。这些部分被称为`内核模块`，并以特权模式运行。内核模块提供了诸多优势：

- 代码模块可以在系统启动后加载到内存中，这简化了内核组件（尤其是驱动程序）的调试。
- 它们能够在运行时改变核心组件集合；当前未使用的模块可以从内存中卸载。
- 模块是“扩展 Linux 内核功能的代码必须开源”这一规则的例外。这使得硬件制造商即使无法访问内核源代码，也能为 Linux 开发驱动程序。

`Linux`模块支持包含三个组件：

- 模块管理工具使模块能够加载到内存中，并促进模块与内核其余部分之间的通信。
- 驱动程序日志记录工具允许模块向内核的另一部分报告新的驱动程序已初始化。
- 冲突解决工具允许设备驱动程序保留硬件资源，并保护它们不被其他驱动程序意外使用。

如果需要，单个模块可以注册多个驱动程序（例如，用于两种不同的访问机制）。模块可以预先加载——在系统启动时（启动模块）或当程序触发其功能时。加载后，模块代码与其他内核代码驻留在相同的地址空间中。模块错误对系统是致命的。

## 系统库的特性

`Linux`系统`库`是`动态库`，仅在需要时加载到内存中。它们执行多项功能：

- 实现系统调用包装器。
- 扩展系统调用功能（此类库包括 C 语言 I/O 库，它基于系统调用实现 `printf()` 等功能）。
- 实现用户模式服务功能（排序、字符串处理等）。

## 用户应用程序

`Linux`用户应用程序使用系统库中的函数，并通过系统调用与内核交互。

## 安装

与微软 Windows 不同，安装 Linux 不是一个简单的过程，因为 Linux 允许控制并定制更多参数和选项。尽管如此，开发商正在朝着使 Linux 安装成为尽可能无创伤的过程这一目标取得巨大进展，具体取决于所用特定发行版的简单程度。

在安装 Linux 之前，有必要考虑一些基本方面。首先是阅读安装 CD 中包含的信息；这些信息可以以两种不同方式呈现：作为常规 `HOW-TO` 指南，或以为发行版开发的手册形式。

对于该操作系统的大多数发行版，安装过程遵循的一般步骤总结如下：

### 安装过程

- **语言选择**：安装程序使我们能够用现有大量语言配置我们的系统。
- **接受许可协议**：接受拥有该发行版的公司许可协议。
- **键盘和鼠标配置**：配置我们键盘和鼠标的类型和型号。
- **安全级别选择**：有四个默认安全级别可供选择，具体取决于我们执行此安装的计算机的用途，范围从互联网客户端到需要支持大量连接的服务器。

### 分区

在安装前需要考虑的主要概念之一是分区。每个操作系统都以其自己的文件系统组织其所包含文件的信息，因此组织方式各不相同。作为参考，不同操作系统的文件系统名称各异。这通常阻止在同一个硬盘上安装多个混合操作系统。为了解决这个问题，出现了所谓的分区，通过它可以将硬盘划分为不同的文件系统。就所有实际目的而言，制作分区相当于将硬盘一分为二，当然并不是物理划分，而是逻辑划分。
