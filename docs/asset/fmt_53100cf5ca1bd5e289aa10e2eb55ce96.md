
## 目录组织

- 为你的程序文件和脚本创建一个 `bin` 目录。
- 将非可执行文件组织在合适的目录中，并根据需要创建尽可能多的目录。例如为图像、文档、项目、下载文件、表格、个人文件等创建独立的目录。
- 使用 `chmod 700 dirname` 命令将目录设置为私有。
- 给你的文件起一个合理的名字，例如“给总理的投诉信 050302”，而不是“letteri”。

## 释放空间

在某些系统中，配额系统可能会迫你定期进行清理，或者硬盘的物理限制可能会迫你在你不运行任何监控程序的情况下释放更多空间。本节讨论了除了 `rm` 命令之外回收磁盘空间的多种方法。

### 空文件

有时你对文件的内容并不感兴趣，但你需要文件名作为标记（例如，你只需要一个文件的时间戳，提醒该文件存在或将在未来某个时间存在）。在 Bourne 和 Bash Shell 中，通过重定向空命令的输出来实现这一点：

```
andy-> cat wishlist > placeholder
andy-> ls -la placeholder
-rw-r-- 1 andy andy 200 Jun 12 13:34 placeholder
andy-> > placeholder
andy-> ls -la placeholder
-rw-r-- 1 andy andy 0 Jun 12 13:35 placeholder
```

将一个现有文件缩小为 0 字节的同名文件的过程被称为“截断”（truncating）。

创建新的空文件，使用 `touch` 命令可以获得相同的效果。对于现有文件，`touch` 只更新时间戳。更多细节请参见 `touch` 的 Info 页面。

要“几乎”清空一个文件，可以使用 `tail` 命令。假设用户 and 的清单变得很长，因为他总是留在末尾但从不删除现在得到的东西。现在他只想保留最后五个项目：

```
andy-> tail -5 wishlist > newlist
andy-> cat wishlist > newlist
andy-> rm newlist
```

### 更多关于日志文件

某些 Linux 程序坚持将各种输出写入日志文件。通常，有选项可以只记录错误，或者只记录极少的信息，例如设置程序的调试级别。但即使如此，你可能也不在乎日志文件。有一些方法可以摆脱它们，或者至少限制它们的大小：

- 当程序未运行时删除日志文件，且你确定再也不需要它。某些程序即使在重启时如果没有日志文件也不会进行记录。
- 如果你删除了日志文件而程序重新创建了它，请阅读该特定程序的文档，寻找避免创建日志文件的命令选项。
- 尝试通过只记录与你相关的信息或只记录重要信息来尝试创建更小的日志文件。
- 尝试用指向 `/dev/null` 的符号链接替换日志文件；如果你足够好，程序不会抱怨。不要对系统启动时运行的程序或从 cron 运行的程序执行这样做（参见第 4 章，进程）。这些程序可能会将符号链接替换为一个再次增长的小文件。

### 邮件

定期清理你的邮箱，使用 `procmail`（参见 Info）或你喜爱的邮件阅读应用程序的过滤器创建子文件夹和自动重定向。如果你有垃圾箱，请定期清理它。

若要重读邮件，请使用家目录下的 `.forward` 文件。Linux 邮件服务在投递本地邮件时会查找此文件。该文件的内容定义了邮件系统应该如何处理你的邮件。它可能包含一行完全限定的电子邮件地址。在这种情况下，它将把所有邮件发送到该地址。例如，在租网站空间时，你可能希望将邮件转发给网站管理员或你自己的账户，以免浪费磁盘空间。管理员的 `.forward` 可能看起来如下：

```
webmaster@www ~ -> cat .forward
mike@pandora.be
```

使用邮件转发也有助于防止你不得不检查几个不同的邮箱。你可以让每个地址都指向一个中心且易于访问的账户。

你可以请求你的服务器管理员为你定义一个转发。

### 使用链接节省空间

当多个用户访问同一个文件，且原始名称太长或难以输入时，请使用符号链接。在同一目录下，多个链接有不同的名称：

```
ls -l
```

### 限制文件大小

Shell 有一个内置命令 `ulimit` 来限制文件大小，它也可以显示资源：

```
ulimit -a
core size (blocks) 0
data seg (kbytes) unlimited
file size (blocks) unlimited
max locked memory (kbytes) unlimited
max user processes	512
virtual memory (kbytes) unlimited
```

```
open files	1024
pipe size (bytes) 512
stack size (kbytes) 8192
cpu time (seconds) unlimited
```

### 核心转文件

当程序在执行过程中出现问题时，有时会生成核心文件（core file）或转储（core dump）。核心文件包含了错误发生时的内存副本。如果你需要转储，可以使用 `ulimit` 设置它们的大小。

### 压缩文件

压缩文件很有用，因为它们占用了硬盘空间。另一个优势是，网络发送压缩文件所需的带宽更少。系统中的许多文件（如 man 页）以压缩格式存储。然而，为了获取一点信息而解压这些文件，然后重新压缩它们是非常耗时的。大多数人可能都会忘记清理他们所需的信息。

因此，我们有了可以直接处理压缩文件的工具，它们仅在内存中进行解压缩。磁盘上的实际压缩文件保持原样。大多数系统支持 `zgrep`、`zcat`、`blast` 以及其他 z 系列成员，以防止不必要的解压/压缩操作。参见你的系统二进制目录和 info 文件。

## 你的文本环境

### 环境变量

#### 通用

我们之前提到了一些环境变量，例如 `PATH` 和 `HOME`。到目前为止，我们只看到了它们为 Shell 服务于特定用途的示例。但许多 Linux 工具需要关于你的信息以便良好工作。

除了路径和家目录，程序还需要哪些其他信息？

许多程序想知道你使用的终端类型；这些信息存储在 `TERM` 变量中。在文本模式下，这将是 bash 终端仿真器；许多程序想知道你喜欢的编辑器是什么，以便它们在需要时启动编辑器子进程。你使用的 Shell 存储在 `SHELL` 变量中，操作系统类型存储在 `OS` 中，等等。可以通过输入命令查看当前会话中定义的所有变量。

参见第 9 章，基础备份技术以获取更多关于文件的实际压缩和制作归档的示例。

环境变量由 shell 管理。与普通 shell 变量不同，环境变量会被你启动的任何程序（包括另一个 shell）继承。新进程会被分配这些变量的副本，它们可以读取、修改并反将其传递给它们自己的进程。

变量名并没有特殊之处，只是按照惯例，常用的变量使用大写字母。你可以起任何喜欢的名称，尽管有些标准变量在每个 Linux 系统上保持一致至关重要，例如 `PATH` 和 `HOME`。

#### 导出变量

通常使用 `echo` 命令显示单个变量的内容，如下例所示：

```
debb:-> echo $PATH
/usr/bin:/sbin:/bin:/usr/X11R/bin:/usr/local/bin
```

```
debb:-> echo $MANPATH
/usr/man:/man/:/usr/local/man:/usr/X11R/man
```

如果你想以一种对其他程序有用的方式更改变量的内容，你必须将新值从你的环境导出到它运行的环境。一个常见的例子是导出 `PATH` 变量。你可以如下所示声明它，以便运行位于 `/opt/FlightGear/bin` 的飞行模拟器软件：

```
debb:-> PATH=$PATH:/opt/FlightGear/bin
```

这指示 shell 不要在当前路径 `$PATH` 中搜索程序，还要在额外的目录 `/opt/FlightGear/bin` 中搜索。

然而，由于环境不知道 `PATH` 变量的新值，程序将无法工作：

```
debb:-> runfgfs
bash: runfgfs command not found
```

导出变量使用 shell 内置命令 `export` 完成：

```
debb:-> export PATH
```

```
debb:-> runfgfs
--flight simulator starts--
```

在 Bash 中，我们通常在一行内完成此操作：

```
export VARIABLE=value
```
