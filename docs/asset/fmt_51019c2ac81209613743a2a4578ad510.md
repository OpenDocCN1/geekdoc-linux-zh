
为了查询已识别过期 PV 的 VG 中的每个 PV，我们使用 `for` 循环遍历分配给 `$PV_LIST` 变量的每个 `hdisk`。在查询之前，我们要检查该 PV 是否处于活动状态。如果磁盘未活动状态，我们就无法查询该磁盘。在 shell 脚本的这部分，我们在 `for` 循环内部使用了 `lsvg hdisk` 命令。第一次我们确保磁盘是活跃的，第二步我们查询磁盘的 STALE PARTITIONS 字段值。如果发现磁盘未活动状态，则仅将该磁盘添加到 `INACTIVE_PV_LIST` 变量中。如果磁盘处于活动状态且查询检测到任何过期分区，则将 `hdisk` 添加到 `STALE_PV_LIST` 变量中。注意启动磁盘查询之前检查未活动 PV 的语句语法：

```bash
$ $(echo $INACTIVE_PV_LIST | grep $HDISK) >/dev/null 2>&1
```

之前的测试确保磁盘没有列在 `INACTIVE_PV_LIST` 变量中。使用这种语法的用处在于我们使用 `if` 语句来检查命令的返回码。我们还对响应进行了取反，通过使用 `!` 运算符来测试磁盘是否不在列表中。为了停止任何屏幕输出，命令被重定向到 `/dev/null`，标准错误被重定向到标准输出，由 `2>&1` 符号表示。在 `for` 循环中，我们使用 `STALE_PV_LIST` 变量，它是系统中所有具有过期磁盘分区的活动磁盘列表。

在下一节中，我们填充 `LV_LIST` 变量，它是所有发现过期分区的磁盘列表。在这一步骤中，我们使用另一个 `for` 循环遍历每个 PV，使用 `lvs -l` 命令填充 `$PV`。然后我们使用新填充的 `$STALE_LIST` 来查询哪些 LV 具有过期 PV。对于该部分，我们使用 `lsvg -l $VG` 命令并结合 `grep` 和 `awk` 提取 STALE PP 字段。每个发现有一个过期 PV 的 LV 都添加到 `RESYNC_LV_LIST` 变量中，稍后将进行重新同步。信息也会记录在 `$LOGFILE` 中并显示在屏幕上。在通知每个受影响的 VG、PV 和 LV 之后，我们在 LV 级别尝试重新同步。如果 `$ATTEMPT_RESYNC` 变量为 TRUE，我们将尝试重新同步。其他任何值都会跳过此操作。如果启用了重新同步，则执行 `syncvg -l RESYNC_LV_LIST` 命令。检查返回码是否为零表示成功。如果返回码不是零，你需要联系 IBM 支持并更换磁盘。我们也可以使用 `varyvg` 命令仅重新同步过期分区。

# 日志文件

在本章的前两个 shell 脚本中，我们没有像方法3那样使用日志文件。在运行任何类型的系统查询时，有一个日志文件以便事后回顾总是好的。创建日志文件是一个简单的过程：定义一个变量指向你想要用于日志文件的文件，并将输出追加到日志文件变量中。如果你的系统倾向于填 `/tmp` 文件系统，我建议创建一个日志目录，可能在 `/usr/local/logs` 中，或者为日志文件创建一个独立的文件系统。如果 `/tmp` 填满了，你将无法向日志文件写入任何内容。你可能还想保留一个月份的日志以备系统出现问题时审查。做到这一点，你可以添加日期戳作为文件扩展名，并使用 `find` 命令删除所有 30 天以前的文件。

# 带通知的自动主机 ping 检测

在每个公司中，都有保持服务器运行的关键需求。对于系统可用性，你越快知道系统无法访问，就能越快地解决问题并减少公司损失。在系统访问的最低级别，我们可以 `ping` “关键机器”列表中的每台机器。如果 `ping` 正常，它会告诉你网络适配器是否正常工作，但它不能保证机器和应用程序正在运行。对于这种级别的检查，你需要实际访问应用程序或操作系统。

在本章中，我们将创建一个 shell 脚本，将使用机器列表来 ping 主机，该列表存储在易于编辑的单独文件中。此场景的其他选项包括 ping `/etc/hosts` 文件中的所有机器、使用 `ftp` 传输文件以及查询数据库来命名文件。我们在本章中的兴趣是在最低水平工作，并使用 `ping` 命令确保机器从网络是可访问的。当发现机器无法访问时，我们会发送通知提醒人员机器已宕机。由于某些公司的网络可能会被流量饱和，我们将在失败的 `ping` 测试上增加额外的测试级别，我们将在本章稍后介绍。但在继续之前，让我们先查看每种操作系统 AIX、HP-UX、Linux 和 Solaris 的命令语法。
