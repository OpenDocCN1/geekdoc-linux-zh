
DHCP 并不是这种方式租用 IP 地址的唯一协议。以前，Solaris 使用远程地址解析协议（RARP）从 RARP 服务器动态获取 IP 地址。该协议对于不从本地存储 IP 地址的无盘客户端特为重要。然而，DHCP 比 RARP 好，因为它支持 Solaris、Linux 和 Windows 客户端，并且能够提供比单纯 IP 地址更多的参数。此外，RARP 服务器只能为单个网络提供地址，而 DHCP 在路由设置正确的情况下，能够从单个服务器为多个网络提供服务。

另一方面，Windows 管理员会对引导协议（BOOTP）非常熟悉，它以与 DHCP 相同的方式动态提供 IP 地址。事实上，DHCP 可以被视为 BOOTP 的超集，且 DHCP 服务器通常与 BOOTP 向后兼容。DHCP 与 BOOTP 的关系是 DHCP 是基于 BOOTP 之构建的，尽管 BOOTP 数据包是固定的，而 DHCP 数据包是可变的。

DHCP 相比竞争协议的另一个优势是它是通过互联网工程任务组（IETF）开发的开放标准。由于 DHCP 是集中化管理的，它是安全的，并为网络提供可靠的信息。由于 DHCP 负责配置参数的分配，确保 SNMP 代理获取其管理的主机的正确信息至关重要。此外，DHCP 服务器需要意识到 IP 地址会随时间变化。

感兴趣的进一步了解 DHCP 如何工作的读者可以参考 RFC 2131。也可以从 ISC（`http://www.isc.org/`）获取相关信息。ISC 实现使用了模块化 API，设计用于兼容 POSIX 标准和非 POSIX 兼容的操作系统。它还包含了源代码，对于理解 DHCP 的工作原理非常有帮助。

## 客户端请求

客户端只需接受收到的 `DHCPOFFER`，随后广播一个 `DHCPREQUEST` 消息表示已获得租约。一旦服务器收到此请求，它将通过 `DHCPACK` 消息确认租约。在客户端完成 IP 地址的使用后，会向服务器发送 `DHCPPRELEASE` 消息。

在服务器在第一阶段提议租约但在第二阶段无法履行的情况下，它必须通过 `DHCPNACK` 消息进行响应，此时客户端将广播 `DHCPDISCOVER` 消息，过程重新开始。如果在原始的 `DHCPDISCOVER` 与服务器随后接收到 `DHCPREQUEST` 之间发生超时，通常会发送 `DHCPNACK`。所有 DHCP 消息列表所示表 38-1。

`DHCPOFFER` 指定了租约周期，期满后租约将被视为失效并供其他客户端使用。客户端还可以选择续租现有租约，以保留其 IP 地址。DHCP 协议在实际租约到期前定义了固定间隔，此时客户端应决定是否扩展租约。如果未进行续租，将广播 `DHCPRELEASE` 消息且租约将失效。

DHCP 有三种向客户端分配租约的方法。自动分配向客户端授予永久地址。这对于为需要静态 IP 地址的服务器分配 IP 地址有用。DNS 服务器通常需要静态 IP 地址，该地址可以在 InterNIC 的主机记录中注册。大多数客户端将由服务器动态分配地址，这允许地址的最大化重用。或者，管理员可以手动为特定客户端分配地址。分配 DHCP 租约的过程如图 38-1 所示。
