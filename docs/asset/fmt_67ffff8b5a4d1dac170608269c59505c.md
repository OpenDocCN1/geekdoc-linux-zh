`telnet` 在有人连接时默认会显示横幅。此横幅通常包含系统信息，如操作系统、版本，有时还有内核版本等详细信息。在历史上，这对于需要在多个操作系统上工作是有用的，但在当今充满敌意的网络环境中，它的害大于利。`telnet` 显示 `/etc/issue.net` 文件的内容，该文件与 `/etc/issue` 相同（后者显示在终端上），因此在大多数 Linux 发行版中，该文件会在启动时从 `rc.local` 启动文件重建。只需编辑 `rc.local` 文件，要么修改它写入 `/etc/issue` 和 `/etc/issue.net` 的内容，要么注释掉创建这些文件的行即可。

其他的 `sshd_config` 指令包括：

- `AllowGroups` - 显式允许组（`/etc/group`）使用 `ssh` 登录
- `DenyGroups` - 显式禁止组（`/etc/groups`）使用 登录
- `AllowUsers` - 显式允许用户使用 `ssh` 登录
- `DenyUsers` - 显式禁止用户登录
- `AllowHosts` - 允许某些主机，其余的将被拒绝
- `DenyHosts` - 阻塞某些主机，其余的将被允许
- `IdleTimeout` time - 单位为分钟/小时/天/等，通过进程中的 `SIGHUP` 强制注销

### RSH, REXEC, RCP

R 服务如 `rsh`, `rcp`, `rexec` 等非常不安全。没有其他方式可以描述这一点。它们的安全性基础基于连接机器的主机名/IP 地址，这可以轻易被伪造，或者通过 DNS 投毒等技术被破坏。默认情况下，它们并没有被全部禁用，请立即禁用它们。编辑 `/etc/inetd.conf` 查找 `rexec` `rsh` 等并将其它们注释掉，然后执行 `killall -1 inetd` 重启 `inetd`。

如果你绝对必须使用 `tcp_wrappers` 限制访问来运行这些服务，虽然作用有限，但会有帮助。此外，确保你的防火墙拦截了它们，因为 `tcp_wrappers` 会允许攻击者看到它们正在运行，这可能导致伪造攻击，如果处理得当，`tcp_wrappers` 无法防御这种攻击。R 服务的访问通过 hosts 文件控制，通常每个用户都有自己的 hosts 文件，遗憾的是这容易受到数据包伪造的影响。r 服务的问题还在于，一旦发生可以修改文件的微小安全漏洞，编辑用户的（如 root 的）root 文件将极易地破解整个系统。

如果你需要易用且类似于 `rsh/etc` 的远程管理工具，我推荐 `nsh` (Network Shell) 或 SSH，它们都支持加密，安全性高得多。或者，使用 VPN 软件可以减少风险，因为它可以拒绝伪造者攻击你系统的机会（IPSec 是发送者的身份验证，这在某些情况下比加密数据更重要）。

### Webmin

Webmin 是 Linux 更好的远程管理工具之一，主要用 Perl 编写，易用且易于设置。你可以分配不同的“用户”（用户名和密码由 webmin 维护），例如你可以分配用户来关闭服务器，或者创建/删除用户。此外，它适用于大多数 Linux 平台以及其他 UNIX 平台。Webmin 的主要问题是某些用法方面的文档较差，以及用户名/密码对是明文在网络传输的（通过允许访问某些主机可以稍微降低风险）。最重要的是，对于那些必须管理系统的非技术人员，Webmin 提供了可访问性。Webmin 位于：http://www.webmin.com/webmin/，目前默认运行在端口 10000，应该被防火墙拦截：

```
ipfwadm -I -a accept -P tcp -s 10.0.0.0/8 -D 0.0.0.0/21
ipfwadm -I -a accept -P tcp -s some.trusted.host -D 0.0.0.0/21
ipfwadm -I -a deny -P tcp -s 0.0.0.0/0 -D 0.0.0.0/21
```

或者在 `ipchains` 中：

```
ipchains -A input -p tcp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/21
ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/21
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/21
```
