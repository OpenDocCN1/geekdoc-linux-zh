
`linux_dmesg`插件可以恢复内核调试缓冲区。对于所有版本，恢复过程都从记录`log_buf`和`log_buf_len`变量的地址开始。如前所述，数据的格式取决于内核版本，插件要么解析字符（3.5之前），要么解析日志结构（3.5及以后）。

# 提取内核模块

当你发现恶意的rootkit时，通常想要提取它进行进一步分析。`linux_moddump`插件能够提取内存驻模块的段并创建一个包含这些内容的ELF文件。遗憾的是，在最初加载LKM后，内核会丢弃ELF头部。此外，它只存储了关于段的极少信息，并用运行时数据修复了符号表。`linux_moddump`插件必须反向操作，首先找到段头，以追溯出类似于原始文件的ELF头部。然后它必须填充段属性并修复损坏的符号表条目。

> 注意
> 有关ELF文件格式以及当这些文件加载到内存时会发生什么的信息，请参阅第20章。

```

Volatility Foundation Volatility Framework 2.4
lime 17991

format=lime
dio=Y
path=debian.lime
[snip]
```

### 总结

由于内核在系统的安全和整体功能中起着至关重要的作用，你经常可以在内核内存中发现有价值的证据。理解物理内存和虚拟内存的布局将使你能够将地址与特定的硬件设备、加载的内核模块等关联。内核调试缓冲区提供的信息可以帮助你确定可移动媒体是否（以及何时）被插入计算机中，以及系统连接了哪些无线网络。这些细节可以帮助你识别用户是如何外泄数据的，以及他们使用计算机系统物理上访问了哪些网站。你还可以列出并提取已加载的内核模块，正如你在接下来的章节中看到的，这是恶意软件分析和rootkit调查中的重要步骤。

## 24 内存中的文件系统

当文件被打开、创建、读取和写入时，操作系统会在多个数据结构中缓存这些操作的信息。相关的遗产物包括目录结构、元数据（包括时间戳），甚至最近访问的文件内容。

特别是在Linux上，由于几乎每个发行版都使用了纯内存文件系统，此类遗产物在机器关机时丢失。因此，在许多情况下，保留RAM是确定攻击者访问了哪些文件、rootkit隐藏在何处，或者客户端浏览器攻击的结果引入了什么的最佳（有时也是唯一的）方法。

## 挂载的文件系统

Linux在内核内存中维护了一个活动挂载的文件系统列表。最基本的分析任务之一是找到此列表并对哪些文件是可以访问的有一个初步印象。你的调查方向可能会根据文件是从本地硬盘、远程网络文件系统（NFS）或服务器消息块（SMB）驱动器，还是外部USB闪盘打开而受到影响。

### 分析目标

你的目标如下：

- 识别侦察和窥探：许多公司拥有托管知识产权的内部文件服务器。任何称职的攻击者都会立即尝试寻找并挂载感兴趣的网络共享，以获取特定文件或搜索任何包含与攻击者动机相关的特定术语的文件。如果你在此期间捕获了RAM，或者攻击者未能卸载该共享，那么此类活动的遗产物就会存在于内存转储中。
- 检测数据外泄：心不满的员工经常会将USB闪盘带入工作场所复制敏感文件并在稍后泄露。如果你确定最近使用了某个外部驱动器，你应该将有关该设备的信息添加到你的证据列表中。
