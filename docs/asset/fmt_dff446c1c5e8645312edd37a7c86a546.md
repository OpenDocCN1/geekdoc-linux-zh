
最后，该脚本对月份名称相当宽松；`febmana`完全可以正常工作，因为①处的`case`语句只检查指定单词的前三个字母。如果您愿意，可以通过测试常见缩写（如`feb`）以及完整拼写的月份名称（`february`）以及可能的常见拼写错误（`febuary`）来清理和改进这一点。如果您有此意愿，所有这些都很容易实现！

## 8 规避糟糕的 echo 实现

如第10页“什么是 POSIX？”中所述，虽然大多数现代 Unix 和 GNU/Linux 实现都有一个知道`-n`标志应抑制输出末尾换行的`echo`命令版本，但并非所有实现都如此。有些使用`\c`作为特殊嵌入字符来抵消这种默认行为，而其他则坚持包含尾随换行符。

判断您特定的`echo`是否实现良好很容易：只需输入以下命令并观察会发生什么：

```
$ echo -n "The rain in Spain"; echo " falls mainly on the Plain"
```

如果您的`echo`支持`-n`标志，您会看到如下输出：

```
The rain in Spain falls mainly on the Plain
```

如果不支持，您会看到如下输出：

```
-n The rain in Spain
falls mainly on the Plain
```

确保脚本输出按预期呈现给用户很重要，并且随着脚本变得更具交互性，这一点将变得越来越重要。为此，我们将编写一个名为`echon`的`echo`替代版本，它将始终抑制尾随换行。这样我们每次需要`echo -n`功能时都有一个可靠的调用对象。

### 代码

解决这个古怪的`echo`问题的方法与本书中的页数一样多。我们最喜欢的方法之一非常简洁；它只是将输入通过`awk printf`命令过滤，如清单1-16所示。

```
echon()
{
  echo "$s" | awk '{ printf "%s", $0 }'
}
```

清单1-16：使用`awk printf`命令的简单`echo`替代方案

然而，您可能希望避免调用`awk`命令带来的开销。如果您有用户级`printf`命令，您可以改写`echon`使其通过该命令过滤输入，如清单1-17所示。

```
echon()
{
  printf "%s" "$s"
}
```

清单1-17：使用简单`printf`命令的`echo`替代方案

如果你没有`printf`，也不想调用`awk`，那么可以用`tr`命令去掉末尾的回车符，如清单1-18所示。

```
echon()
{
    echo "$*" | tr -d '\n'
}
```

清单1-18：使用`tr`实用程序的一个简单`echo`替代方案

这个方法简单高效，而且应该具有相当好的可移植性。

### 运行脚本

只需将脚本文件添加到你的`PATH`中，就可以用`echon`替换任何`echo -n`调用，从而可靠地在打印输出后把用户的光标留在行尾。

### 运行结果

`echon` shell 脚本的工作方式是：接收一个参数并打印它，然后读取一些用户输入来演示`echon`函数。清单1-19展示了测试脚本的使用情况。

```
$ echon "Enter coordinates for satellite acquisition: "
Enter coordinates for satellite acquisition: 12,34
```

清单1-19：测试`echon`命令

### 破解脚本

我们不会隐瞒事实。有些 shell 的`echo`语句认识`-n`标志，有些则期望使用`\c`作为结束序列，还有一些似乎根本无法避免添加回车符，这对脚本编写者来说是一个巨大的麻烦。为了解决这种不一致性，你可以创建一个函数，自动测试`echo`的输出来判断当前属于哪种情况，然后相应地修改它的调用方式。例如，你可以写类似`echo -n hi | wc -c`的命令，然后测试结果是2个字符（`hi`）、3个字符（`hi`加回车符）、4个字符（`-n hi`）还是5个字符（`-n hi`加回车符）。

## 9 任意精度浮点计算器

在脚本编写中最常用的序列之一是`$(( ))`，它允许你使用各种基础数学函数进行计算。这个序列非常有用，可以方便地完成诸如递增计数器变量之类的常见操作。它支持加、减、除、取余（或模）以及乘运算，但不支持分数或小数值。因此，下面这条命令返回的是0，而不是0.5：

```
echo $(( 1 / 2 ))
```

所以当需要计算需要更高精度的数值时，你就面临一个挑战。在命令行上可用的优秀计算器程序实在不多。唯一的例外是`bc`，这个古怪的程序几乎没有几个 Unix 用户学过。`bc`程序自称为任意精度计算器，它起源于 Unix 的早期时代，带有隐晦的错误消息、完全没有提示符，并且假定如果你在使用它，你就已经知道自己在做什么。不过没关系。我们可以编写一个包装器让`bc`更加友好易用，如清单1-20所示。

### 代码

```
#!/bin/bash

# scriptbc--wrapper for 'bc' that returns the result of a calculation

if [ "$1" = "-p" ] ; then
    precision=$2
    shift 2
else
    precision=2      # Default
fi

bc -q -l << EOF
scale=$precision
$*
quit
EOF

exit 0
```

清单1-20：`scriptbc`脚本

### 工作原理

③处的`<<`表示法允许你从脚本中包含内容，并将其视为直接输入到输入流中，在这种情况下，它为向`bc`程序传递命令提供了一种简便的机制。这被称为编写一个 here 文档。在这种表示法中，你在`<<`序列后面写的内容，就是它随后要寻找（单独成行）来标记该输入流结束的内容。在清单1-20中，这个内容是`EOF`。

这个脚本还演示了如何使用参数使命令更加灵活。这里，如果脚本以`-p`标志①调用，它允许你指定输出数字所需的精度。如果没有指定精度，程序默认使用`scale=2`②。

在使用`bc`时，理解`length`和`scale`之间的区别至关重要。就`bc`而言，`length`指的是数字的总位数，而`scale`是小数点后的总位数。因此，`10.25`的`length`是4，`scale`是2，而`3.14159`的`length`是6，`scale`是5。

默认情况下，`bc`的`length`是一个变量值，但由于它的`scale`为零，不加任何修改的`bc`与`$(( ))`表示法的工作原理完全相同。幸运的是，如果你给`bc`添加`scale`设置，就会发现它内部隐藏着大量强大的功能，如下面的例子所示，它计算1962年到2002年之间（不包括闰日）经过了多少个星期：

```
$ bc
bc 1.06.95
Copyright 1991-1994, 1997, 1998, 2000, 2004, 2006 Free Software Foundation, Inc.
This is free software with ABSOLUTELY NO WARRANTY.
For details type `warranty'.
scale=10
(2002-1962)*365
14600
14600/7
2085.7142857142
quit
```

为了允许从命令行访问`bc`的功能，包装脚本必须屏蔽开头可能出现的版权信息——不过大多数`bc`实现如果输入不是终端（stdin），本来就会省略头部信息。包装脚本还会将`scale`设置为一个合理的值，把实际的表达式提供给`bc`程序，然后用`quit`命令退出。

### 运行脚本

要运行这个脚本，请将一个数学表达式作为参数传给程序，如清单1-21所示。

### 运行结果

```
$ scriptbc 14600/7
2085.71
$ scriptbc -p 10 14600/7
2085.7142857142
```

## 10 锁定文件

任何读取或追加共享文件（如日志文件）的脚本都需要一种可靠的方式来锁定文件，以防止脚本的其他实例在数据使用完毕前意外覆盖数据。一种常见的方法是为每个正在使用文件创建单独的锁定文件。锁定文件的存在充当信号量，表示文件正被另一个脚本使用且不可用。请求脚本随后会反复等待并重试，直到信号量锁定文件被移除，表示文件可以自由编辑。

不过锁定文件很棘手，因为许多看似万无一失的解决方案实际上并不可行。例如，以下代码是解决此问题的典型方法：

```
while [ ! -f $lockfile ] ; do
  sleep 1
done
touch $lockfile
```
