
`regcmp` 命令的功能与 `regcmp(3C)` C 语言库函数类似。在大多数情况下，`regcmp(1)` 命令消除了在 C 程序中调用 `regcmp(3C)` 函数的需求。绕过 `regcmp(3C)` 可以节省执行时间和程序大小。`regcmp` 命令编译 `filename` 中的正则表达式，并将输出放在 `filename.1` 中。

# regcmp

## 选项

将输出放在 `filename.c`。`filename` 中条目的格式为名称（C 变量），后跟一个或多个空格，然后是一个或多个用双引号括起来的正则表达式。`regcmp` 的输出是源代码。已编译的正则表达式表示为 `extern char` 向量。因此，`filename.i` 文件可以包含在 C 程序中，`filename.c` 文件可以被编译并在以后加载。在使用 `regcmp` 输出的程序中，`regex(abc,line)` 将名为 `abc` 的正则表达式应用到 `line` 上。不言自明。

## 示例

在以下示例中，`telno` 的三个参数必须在同一行输入：

```
name "([A-Za-z] [A-Za-z0-9]*)\$"
telno "((0,1) [2-9](01) [1-9])\$$(0,1)"
  "([0-9](2-9))\$[-1](0,1)"
  "([0-9](4))\$2"
```

在使用 `regcmp` 输出的 C 程序中，以下语句将名为 `telno` 的正则表达式应用到 `line`。

```
regex(telno, line, area, exch, rest)
```

## 环境变量

参见 `environ(5)` 获取 `LC_*` 环境变量的通用描述。

- `LC_TYPE` 决定 `regcmp` 如何处理字符。当 `LC_TYPE` 设置为有效值时，`regcmp` 可以显示和处理包含该区域有效字符的文件名。
- `LC_MESSAGES` 决定诊断和信息消息的呈现方式，包括消息的语言和样式以及肯定和否定响应的正确形式。在 C 区域中，消息以程序本身中找到默认形式呈现（大多数情况下是美国英语）。

## 属性

参见 `attributes(5)` 获取以下属性的描述：

| 属性类型 | 属性值 |
| --- | --- |
| 可用性 | `SUNWfoo` |
| CSI | Enabled |

# renice — 修改运行进程的优先级

## 概览

```
/usr/bin/renice [-n increment][-g -p] [-u] ID...
/usr/bin/renice priority [-p] pid...[-g gid...][-p pid...][-u user...]
/usr/bin/renice priority -g gid... [-g gid...][-p pid...][-u user...]
/usr/bin/renice priority -u user [-g gid...][-p pid...][-u user...]
```

## 描述

> 注意 — `priocntl` 命令包含了 `renice` 的功能。

使用 `renice` 命令修改一个或多个运行进程的调度优先级。默认，通过进程 ID 指定受影响的进程。

如果第一个操作数是优先级范围（−20 到 20）内的数字，`renice` 将其视为优先级（如所有第一个概览形式所示）；否则，`renice` 将其视为 ID（如第一个第一个概览形式所示）。

## 修改进程优先级

超级用户的用户只能修改其拥有的进程的优先级，并可以在 0 到 19 的范围内单调地增加其 nice 值。此限制防止了行政性操作。超级用户可以修改任何进程的优先级，并将优先级设置为 −20 到 19 范围内的任何值。有用的优先级是：

- 19—运行
- 0—默认
- -20—最高优先级

# rlogin — 远程登录

## 概要

```
/usr/bin/rlogin [-8EL] [-ec] [-l username] hostname
```

## 描述

使用 `rlogin` 从你的终端到名为 `hostname` 的远程系统建立远程登录会话。主机名列在 `hosts` 数据库中，该数据库可能包含在 `/etc/hosts` 文件、网络信息服务 `NIS` hosts 映射、互联网域名服务器或这些者的组合。每个主机都有一个官方名称（数据库条目中的第一个名称），并可选有一个或多个昵称。你可以指定官方主机名或昵称作为 `hostname`。

## login

> 注意 — 网络信息服务 `NIS` 被称为 Sun Yellow Pages `YP`。这两者的功能保持不变；仅名称发生了变化。

每个远程系统都可以有一个名为 `/etc/hosts.equiv` 的文件，其中包含一个与其共享用户名的信任主机名列表。在本地和远程系统上具有相同用户名的用户可以从远程 `/etc/hosts.equiv` 文件列出的系统调用 `login`，而无需提供密码。个人可以在其家目录下的 `.hosts` 文件设置类似的等效列表。该文件中的每行包含两个名称：一个由空格分隔的主机名和用户名。远程用户 `.hosts` 文件中的条目允许登录到 `hostname` 的用户 `username` 在不提供密码的情况下作为远程用户登录到远程系统。如果从远程系统的 `/etc/hosts.equiv` 文件中没有找到本地主机名，且在远程用户的 `.hosts` 文件中没有找到本地用户名和主机名，则远程系统将提示输入密码。在 `/etc/hosts.equiv` 和 `.hosts` 文件中列出的主机名必须是 `hosts` 数据库中列出的官方主机名；在这些文件中都不能使用昵称。

> 注意 — 当系统被列在 `hosts.equiv` 中时，其安全性必须与本地安全性一样。列在 `hosts.equiv` 中的任何不安全的系统都可能危及整个系统的安全。

出于安全考虑，`hosts` 文件必须由远程用户或 `root` 所有。

远程终端类型与你的本地终端类型相同（如你的环境变量 `TERM` 所示）。如果服务器支持该选项，终端或窗口的大小也会复制到远程系统，尺寸的变化也会反映出来。所有的显示都在远程端进行，因此远程登录（延迟外）是透明的。通过 `Control-S` 和 `Control-Q` 进行流控制以及输入输出的刷新都得到了适当处理。

> 注意 — 此实现只能使用 TCP 网络。

## 选项

- `-8` 向网络传递 8 位数据而非 7 位数据。
- `-ec` 为断开与远程主机连接的指定不同的转义字符 `c`。
- `-E` 停止任何字符识别为转义字符。
- `-l username` 为远程登录指定不同的用户名。如果不使用此选项，则使用的远程用户名与你的本地用户名相同。
- `-L` 在 `litout` 模式下运行会话。

# 转义序列

你用波浪字符 `~` 输入的行是转义序列（你可以通过 `-e` 选项更改转义字符）。

- `~` 断开与远程机的连接。此操作不同于注销，因为本地主机在不警告远程端的情况下断开了连接。
