### 构建用于交叉编译的 GNU 工具链

交叉编译器运行在处理器上，但会为不同的处理器生成可执行代码。例如，运行在 x86 处理器上的 ARM 交叉编译器会为 ARM 处理器生成代码，而 PowerPC 交叉编译器则为 PowerPC 生成代码。

为什么 Project Trailblazer 项目需要交叉编译器？通常，嵌入式系统没有足够的 RAM 或存储资源来编译自己的可执行文件。在这种情况下，主机处理器可以交叉编译代码以创建可执行文件。然后将该可执行文件传输到目标板卡并执行。GNU 工具链具备交叉编译的能力，但并不是作为命令行选项提供的。整个工具链需要经过编译才能作为交叉编译器运行。这不是一个简单的 `make`、`install`、`apt-get` 或 `rpm` 过程。交叉编译器的构建过程并没有完全的文档，也没有保持更新。

## 第 3 章 选择平台并安装工具集

Trailblazer 的工程师正在使用 Embedded Planet RPX-CLLF (PowerPC MPC860) 和 Brightstar MediaEngine (ARM SA-1110)。他们找到了两个解释 ARM 和 PowerPC 处理器 GNU 工具链的 HOWTO：

- 针对 ARM 的 GNU 工具链 HOWTO：<https://www.linux.org/docs/toolchain>
- PowerPC 嵌入式系统 Linux HOWTO：<http://penguinppc.org/usr/embedded/howto/PowerPC-Embedded-HOWTO.html>

阅读这些 HOWTO 后，工程师发现构建交叉编译版本的 GNU 工具链是一项巨大的工程。他们首先手动构建了工具链。后来，他们切换了内核版本，发现必须重新构建工具，因为 `gcc` 和 `glibc` 依赖于头文件。手动构建工具链既繁琐又容易出错，因此工程师通过开发名为 `buildtoolchain` 的 bash 脚本实现了流程自动化。

`buildtoolchain` 可以构建 PowerPC 和 ARM 交叉编译版本的 `gcc`、`glibc`、`gdb`、GNU 工具以及一个 `helloworld` 测试程序。`buildtoolchain` 脚本简化了 `powerpc-linux` 和 `arm-linux-gcc`、相应的 `glibc` 库文件以及 `gdb` 的编译。`buildtoolchain` 并不是一个包含 12 个步骤的单体脚本，而是 13 个脚本的集合。由于 `buildtoolchain` 被分成若干步骤，在失败时可以重新启动构建过程。`tbdev1`（一个 400MHz 的 Celeron）需要一个多小时才能完全运行 `buildtoolchain`。

`buildtoolchain` 从执行 `buildtoolchain-environment` 脚本开始，该脚本设置了一系列环境变量。`buildtoolchain` 通过执行执行步骤的额外脚本继续：

- 1. 检查所需的源码：
  ```bash
  buildtoolchain-step01-check
  ```
- 2. 清理构建内容：
  ```bash
  buildtoolchain-step02-clean
  ```
- 3. 创建构建目录：
  ```bash
  buildtoolchain-step03-makebuilddirectories
  ```
- 4. 构建 `binutils`：
  ```bash
  buildtoolchain-step04-binutils
  ```
- 5. 设置内核源码和头文件：
  ```bash
  buildtoolchain-step05-kernelsourceheaders
  ```
- 6. 构建交叉编译版本的 `gcc`：
  ```bash
  buildtoolchain-step06-gcc
  ```
- 7. 构建交叉编译版本的 `glibc`：
  ```bash
  buildtoolchain-step07-glibc
  ```
- 8. 构建交叉编译版本的 `gdb`：
  ```bash
  buildtoolchain-step08-gdb
  ```
- 9. 检查 `gcc` 版本：
  ```bash
  buildtoolchain-step09-gccversion
  ```
- 10. 通过交叉编译 `helloworld` 检查工具链构建：
  ```bash
  buildtoolchain-step10-helloworld
  ```
- 11. 重新构建 `gcc`：
  ```bash
  buildtoolchain-step11-rebuildgcc
  ```
- 12. 重新构建 `glibc`：
  ```bash
  buildtoolchain-step12-glibc
  ```
