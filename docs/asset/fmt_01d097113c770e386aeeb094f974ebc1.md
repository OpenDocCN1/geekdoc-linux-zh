
`keep state`关键字也适用于`UDP`和`ICMP`数据包，但由于这些协议是无状态的，其机制略为特殊：在过滤器看到入站包后，`IPFilter`会在60秒内允许对`UDP`或`ICMP`包进行响应。例如，如果来自`10.0.0.10`端口`32000`的`UDP`数据包目标是`192.168.10.10`端口`53`，则允许来自`192.168.10.10`的`UDP`回复，同样，在请求进入状态表后，允许`ICMP`回回复（ping响应）。

关于`NAT`的更多信息请参见第392页。

`IPFilter`使用`map`关键字来提供`NAT`服务。在以下规则中，来自`10.0.0.0/24`网络的流量被映射到`em0`接口上的当前可路由地址。

```
map em0 10.0.0.0/24 -> 0/32
```

如果`em0`的地址发生变化，必须重新加载过滤器，如果`em0`通过`DHCP`租用了动态`IP`地址，可能会发生这种情况。出于此原因，`IPFilter`的功能最好用于面向互联网接口具有静态`IP`地址的站点。表13.12列出了随`IPFilter`软件包一起的命令行工具。

### 表 13.12 IPFilter 命令

| Cmd | 功能 |
| --- | --- |
| `ipf` | 管理规则和过滤器列表 |
| `ipstat` | 获取入站过滤的统计信息 |
| `ipmon` | 监控日志信息 |
| `ipnat` | 管理 NAT 规则 |

在表13.12的命令中，`ipf`是最常用的。`ipf`接受文件作为输入，并将规则正确解析到内核的过滤器列表中。`ipf`将规则添加到过滤器的末尾，除非你使用`-F`参数，该参数会刷新所有现有规则。例如，要刷新内核的过滤器集并从`ipf.conf`加载规则，使用以下语法：

```
$ sudo ipf -f /etc/ipf.conf
```
