
- 实际用户和进程组标识符 (`uid`, `gid`) 对应于启动该程序的用户，使得生成的相应进程在该用户的上下文中出现在系统中。

- 有效用户和进程组标识符 (`euid`, `egid`) 用于特殊的进程执行模式（例如 `setuid` 程序），在这种模式下，进程以文件所有者的权限运行，而不一定是启动该进程的用户权限。

## 进程控制单元

让我们来看看 Linux 中进程控制单元的结构。

Linux 上的进程控制块由 `task_struct` 数据结构显示。

该结构中最重要的一些字段包含以下信息：

- 标识数据（包括 `pid` - 进程标识符）
- 进程状态（执行、等待等）
- 指向父结构和子结构的指针
- 进程创建时间和总执行时间（所谓的进程计时器）
- 处理器状态（寄存器内容和指令计数器）
- 进程安全属性 (`uid`, `gid`, `euid`, `egid`)

请注意，Linux 内核没有线程的独立数据结构，因此处理器状态信息包含在进程控制块中。除了上述内容外，`task_struct` 还有几个自定义字段，用于不同的 Linux 子系统：

- 信号处理信息
- 进程调度信息
- 与进程相关的文件描述符和目录项
- 用于管理内存子系统的数据结构

`task_struct` 的字段数据可以由几个特殊用途进程共享，在这种情况下，这些进程实际上是线程。进程的控制单元存储在内核中的特殊数据结构中。在 2.4 版内核发布之前，此结构被称为系统进程表；它是一个数组，其最大长度不能超过 4K。在后续的内核中，它已被两个动态数据结构取代，这些数据结构没有这样的限制：

- 哈希表（其中进程的 `pid` 作为键），此结构允许通过 ID 快速找到进程。
- 链接列表（环形列表），此结构确保对所有系统进程循环执行操作。

现在，最大进程数量的限制仅在 `fork()` 函数的实现中进行检查，并取决于可用内存的量（例如，有信息显示在具有 512 MB 内存的系统上可以创建大约 32,000 个进程）。

Linux 中控制单元的实现与 UNIX 系统中的传统实现不同。在大多数 UNIX 版本（System V, BSD）中，进程控制块由两个数据层组成 - 进程结构（`proc`）和用户结构（`u`）。

# 创建进程

## Linux 中 `fork()` 的实现

在 UNIX 兼容系统中，使用著名的系统调用 `fork()` 来创建进程。让我们来看看它在 Linux 中的实现。

1. 为新进程控制块（`task_struct`）分配内存。如果内存不足，则返回错误。
2. 将父数据结构中的所有值复制到子数据结构中。之后，那些值应与原始值不同的字段将被更改。如果用户超过其指定数量的进程，或者系统中的进程数超过可能的最大值（这取决于可用内存的量），则进程创建停止并返回错误。
3. 使用特殊算法为进程生成标识符（`pid`），以保证唯一性。
4. 对于子进程，复制必要的附加数据结构（文件描述符表、当前目录信息、信号处理程序表等）。
5. 形成进程的地址空间。
6. 将进程数据结构放入系统进程的列表和哈希表中。
7. 将进程置为就绪执行状态。

## 在应用程序中使用 `fork()`

考虑使用 `fork()` 系统调用创建进程的一个例子。根据 POSIX 的 `fork()` 描述如下：

```c
#include <unistd.h>
pid_t fork(); // 类型 pid_t 是一个整数
```

由于执行 `fork()` 会导致父进程和子进程的控制都切换到调用后的指令，因此在程序员看来，父进程和子进程之间的唯一实际区别在于 `fork()` 返回的代码。

对于子进程，`fork()` 返回零，而对于父进程，它返回创建的子进程的 id (`pid`)。如果由于某种原因未创建子进程，`fork()` 将返回 -1。因此，处理 `fork()` 的正常代码看起来像这样：

```c
pid_t pid;
if ((pid = fork()) == -1)
{
    /* 错误处理 */
}
if (pid == 0)
{
    // 是子进程
}
else
{
    // 这是父进程
    printf("Descendant started with code %d\n", pid);
}
```

一旦进程被创建，它就可以通过系统调用 `getpid()`（返回当前进程 ID）和 `getppid()`（返回父进程 ID）来访问标识信息。

```c
#include <unistd.h>
pid_t mypid, parent_pid;
mypid = getpid();
parent_pid = getppid();
```

# 进程终止

- 进程通过特殊信号通知其祖先进程和后代进程已经结束。
- 在 `fork()` 调用期间分配的资源会被释放。
- 调度器会被通知可以切换上下文了。

在应用程序中，你可以使用 `_exit()` 系统调用或其库函数 `exit()` 来完成进程。该函数关闭所有进程线程，正确释放所有资源，并调用 `_exit()` 以实际完成操作：

```c
#include <unistd.h>
void _exit(int status); // status 指定返回码

#include <stdlib.h>
void exit(int status); // status 指定返回码

exit(128);
```

请注意，当一个进程能够与其他进程联合使用资源时（例如，它是一个拥有祖先进程的后代进程，并且后代从祖先继承了资源描述符），最好不要调用 `exit()`。原因是，在这种情况下，尝试在子进程中释放资源也会导致祖先进程中的资源被释放。你必须使用 `_exit()` 来完成这些进程。

## 等待进程完成

当进程完成时，其控制块不会立即从进程列表和哈希表中移除，而是保留在那里，直到另一个进程（祖先）将其移除。如果进程实际上已不在系统中（已经结束），但仅保留其控制单元，则该进程被称为僵尸进程。

## waitpid() 系统调用

你可以使用 `wait()` 系统调用来从 Linux 中移除进程信息，但更常使用的是其功能更通用的版本——`waitpid()`。此调用检查相应进程的控制单元是否在系统中。如果在，且进程不处于僵尸状态（即仍在运行），则 `waitpid()` 处的进程将进入待机状态。当下进进程完成时，祖先进程退出待机状态并移除该后代进程的控制单元。如果祖先进程不为后代调用 `waitpid()`，后者可能会长时间停留在僵尸状态。

### 应用程序中进程的同步实现

让我们基于 `waitpid()` 来考虑进程的同步执行。根据 POSIX，该系统调用定义为：

```c
#include <sys/wait.h>

pid_t waitpid(pid_t pid,        // 预期进程的 pid
               int *status,      // 后代完成状态信息
               int options);     // 通常为 0
```

`pid` 参数可以设置为 `0`，这意味着进程正在等待与其所属组相同的组，或者设置为 `-1`，这意味着等待任意后代。以下是使用预期机制实现同步执行的示例：

```c
pid_t pid;
if ((pid = fork()) == -1)
    exit(-1);
if (pid == 0)
{
    // 后代 - 调用 exec()
}
else
{
    // 祖先 - 等待后代
    int status;
    waitpid(pid, &status, 0);
    // 继续执行
}
```

`status` 值为你提供了更多关于已完成后代进程的信息。`<sys/wait.h>` 中有许多宏：

- `WIFEXITED(status)` - 当后代正常完成时为非零值；
- `WEXITSTATUS(status)` - 后代的返回码（仅当 `WIFEXITED(status)` 非零时有效）。

后代的返回码获取方式如下：

```c
waitpid(pid, &status, 0);
if (WIFEXITED(status))
   printf("Descendant ended with code %d\n",
   WEXITSTATUS(status));
```

## 5.3.7 警报

在多任务环境中，需要报告系统中发生的事件或其他进程中的事件。POSIX 定义的最简单的此类警报机制是 *信号*。进程在接收到信号后，会立即响应其调用特殊函数——信号的 *处理程序*（信号处理函数），或对该信号采取默认操作。每个信号都对应一个在系统中唯一的数字。除了信号本身，无法传输其他信息。

信号是 UNIX 系统上最简单的进程间通信机制，但由于它们允许传输的数据有限，因此主要用于事件报告。
