
由于 GAS 是为了支持 32 位编译器而发明的，因此它使用了标准的 AT&T 语法，这种语法类似于标准 m86 汇编器的语法，并在 UNIX 世界中是标准。这种语法并不比 Intel 语法差，也不比更好。它只是不同。当你使用它时，你会发现它比 Intel 语法更有规律，有点无聊。

以下是关于 GAS 的一些注意事项：

- 寄存器名称以 `%` 为前缀，因此寄存器是 `%ax`、`%edx` 和 `dl`，而不仅仅是 `dl`。这使得在汇编源文件中直接包含外部 C 符号成为可能，而没有任何混淆的风险，也不需要下划线内核。
- 操作数的顺序是（源操作）在前，目标操作在后，这与 Intel 目标操作在前、在后的约定相反。因此，Intel 语法中的 `mov eax, %edx`（将寄存器 ed 的内容移动到 eax）在 GAS 中将是 `mov %edx, %ax`。
- 操作数的大小通过指令名称的后缀指定。后缀 `b` 代表（8位）字节（byte），`w` 代表（16位）字（word），`l` 代表（32位字）。然而，上述指令的正确语法应该是 `movl %edx, eax`。Gas 不要求严格的 AT&T 语法，因此当可以从寄存器操作数推算出大时，后缀是可选的，并默认为 32 位（带有警告）。
- 立即数操作数以 `$` 前缀标记，例如 `add $5, %ax`（将立即值 5 加到寄存器 `%ax`）。
- 缺少操作数前缀表示它是内存内容；`mov $foo, %eax` 将变量 `foo` 的地址放入寄存器 `%eax`，`mov foo, %eax` 将变量 `foo` 的内容放入 `%eax`。
- 索引或间接寻通过将索引寄存器或内存单元地址括在括号中来实现，`testb $0x80,17 (%ebp)`（位于 %ebp 指向的单元偏移 17 处的字节值的高位）。

注意：有少数程序可以帮助你在 AT&T 和 Intel 汇编语法之间转换源代码；其中一些能够进行双向转换。

GAS 具有 TeXinfo 格式的全面文档，这些文档至少随源码发行提供。浏览提取的 `.info` 页面一直可用。以前有一个名为 `gas.doc` 的文件。在疑问的情况下，终极文档是源码本身！一个你特别感兴趣的章节是机器依赖（Machine Dependencies）：i386依赖（i386-Dependent）：再次，Linux 的源码提供了示例；参见 `linux/arch/i386/` 下的文件：`kernel/*.S`、`boot/*.S`、`math/*.S`。

如果你正在编写某种汇编语言，可能会看到其他语言（OCaml、Gforth 等），或者线程包（QuickThreads、LinuxThreads 等），或其他任何内容。最后，编译 C 程序可能会为你展示你需要的语法。需要帮助吗？

## 3.2.3. Intel 语法

好消息是，自 binutils 2.10 起，GAS 支持 Intel 语法。可以通过 `.intel_syntax` 触发。遗憾的是，官方 binutils 手册尚未记录此模式，所以如果你想使用它，尝试 http://home.snafu.de/php/85.gz，这是 binutils 2.11 的 64 位端口。

## 3.2.4. 16 位模式

Binutils (2.9+) 现在支持 i386 16 位模式（寄存器和寻址）。使用 `.code16` 和 `.code32` 来切换模式。此外，几位作者使用的一种巧妙技巧是强制 GCC 生成 16 位代码，使用前缀。此外，虽然 GCC 识别 `.s` 文件为原始汇编，但在传递给 GAS 之前它也会识别 `.s` 文件。再次参见 Linux 源码。

## 3.2.5. 宏支持

GAS 包含了一些功能，如 TeXinfo 文档详细所示。GAS 还有 GASP（GAS 处理器），它将所有通用宏汇合在一起。它像 `CPP` 和 `M4` 一样工作。它没有细节说明，但带有你可能喜欢的文档。GASP 看起来像是一个普通的宏汇编器。

## 3.3. NASM

Netwide Assembler 项目提供了用 C 编写的酷 i386 汇编器，足以支持所有语法和对象格式。

### 3.3.1. 在哪里找到 NASM

`http://nasm.sourceforge.net`、`http://www.cryogen.com/nasm/` 以及 `devel/asm/` 目录下的二进制发布。在 Red/Debian 发行版中也提供 `.rpm` 或 `.deb` 包。

### 3.3.2. 它做什么

语法是 Intel 风格的。集成了全面的宏支持。支持的对象格式有 `bin`、`aout`、`coff`、`elf`、`as86`、`obj` (DOS)。

NASM 可以作为 BCC 编译器的后端（包含文件）。除非你使用的是 16 位（这本 HOWTO 范围之外），否则绝对应该使用 NASM 而不是 AS86 或 MASM，因为它运行在所有平台上。

- NASM 带有一个反汇编器 `NDISASM`。它的手写解析器使其比 GAS 快得多，尽管它并不支持无数不同的架构。如果你喜欢 Intel 风格语法而不是 GAS 语法，那么它应该是首选。注意：有少数程序可以帮助你在 AT&T 和 Intel 汇编语法之间转换代码，其中一些能够进行双向转换。

## 3.4. AS86

AS86 是一种 8086 汇编器，支持 16 位和 32 位，并带有宏支持。它大部分使用 Intel 语法，但在寻址模式上略有不同。

### 3.4.1. 获取 AS86

当前版本为 0.16，可以在 `http://www.cix.co.uk/~mayday/` 找到，带有链接器 (`ld86`) 的 bin86 包，或者作为独立的存档。

完全过时的 AS86 版本 0. 由 HJLu 发布，用于编译 2.4 之前的 Linux 内核，名为 bin86 的包，在任何 GCC 仓库中可用。但我建议不要用于编译以外的任何用途。此版本只支持一种修改过的文件格式，GNU binutils 或任何东西不支持，并且在 32 位模式有一些 bug，所以最好只用它编译 Linux。

### 3.4.2. 在哪里找到文档

查看源码包中的 man page 和 `as.doc`。在疑问的情况下，源码本身就是良好的文档：它们注释不多，但编程风格非常直接。你可以尝试查看 as86 在 ELKS、LILO 或 Tunes 0.0.0.25 中的用法……

### 3.4.3. 使用 BCC 使用 AS86

这是使用 BCC 将 `.s` 汇编转换为 a.out `.o` 对象和 `.l` 列表的 GNU Makefile：

```
.o: %.s
bcc -3 -G -C -A -A1 -AS* -o $* $<
```

如果你不需要任何列表，删除 `%.1`、`-A1` 和 `-AS*`。如果你需要 a.out 以外的东西，可以检查 BCC 输出支持的其他格式，并/或使用 binutils 包中的 `objcopy` 工具。

## 3.5. 其他汇编器

还有其他具有各种有趣且卓越功能的汇编器，你可能也感兴趣。

它们可能处于不同的开发阶段，可以是非经典的/高级的或其他任何形式。

### 3.5.1. YASM

YASM 是在 GNU GPL 下对 NASM 汇编器的完全重写（部分使用“新的”BSD 许可证）。它从底层开始设计，允许支持多种语法（例如 NASM、TASM、GAS 等）以及多种输出对象格式。 整体设计中的另一个主模块是优化器模块。

它看起来很有前景；它正在大力开发，你可能想参与。参见 `http://www.tortall.net/projects/yasm/`

### 3.5.2. FASM

FASM（flat assembler）是一种快速、高效的 80x86 汇编器，运行在“实实模式”下。与许多其他 80x86 汇编器不同，FASM 只要求源代码包含它真正需要的信息。它本身非常小且快速。它运行在 DOS/Windows/Linux 上，并可以产生平坦二进制、DOS EXE、Win32 PE 和 COFF 输出。参见 `http://fasm.sourceforge.net`。

### 3.5.3. OSIMPA (SHASM)

osimba 是一个针对 Intel 8038 及其后续处理器的汇编器，完全用 GNU Bash 解释器 shell 编写。osimba 的前身是 shasm。osimba 经过了大量的清理，可以创建实用的 Linux ELF 文件，具有各种类高级语言的扩展和程序员便利命令。

它的运行速度（课程）比其他汇编器慢。它有自己的语法（并使用自己的名称作为 x86 机器码），并包含了相当不错的文档。你可以查看一下：`ftp:/linux01_gwd/pub/clLeNUX/interim/`。你可能不会经常使用它，但至少它可以作为一个你兴趣的来源。

### 3.5.4. TDASM

表驱动汇编器 (`TDASM`) 是一个适用于任何汇编语言的免费可移植汇编器。通过一个定义编译过程的表，应该可以将其作为编译器到任何目标微处理器上。

你可以在 `http://www.penguin.cz/~-niki/tdasm/` 获取。
