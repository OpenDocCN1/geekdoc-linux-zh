
正如在“全屏编辑器与行编辑器”章节中所提到的，`vi` 实际上是 `ex` 编辑器的可视模式。因此，在 `vi` 中编辑时，随时可以使用 `ex` 编辑器的所有功能和特性，而无需离开文件位置。实际上是 `ex` 命令的 `vi` 命令会在命令参考表及本章其他地方以冒号 `:` 前缀显示。你可以从两种方式理解此前缀：(1) 作为特殊 `vi` 命令的前缀；(2) 作为将编辑器带入 `ex` 模式的命令，此时屏幕会变化，底部显示一个冒号，光标立即位于冒号右侧。此后，编辑器的行为与你在 `ex` 编辑器中完全相同。

## 处理文本块的 `ex` 命令

`vi` 的真正威力在于大多数编辑器并不具备某些功能。然而，从命令行使用 `ex` 时，你可以对文本块执行操作。

（注：提供的关于 `ex` 命令的文本包含大量重复和 OCR 异常，已根据源文本的逻辑流按行进行了合并清理。）

模式也适用于范围选择，如下例所示：

`:/humane/,/hesitation/p`

`奖励与惩罚。如果仁慈，他热爱人类，同情他人，并感激他们的辛勤劳作。如果勇敢，他会毫不犹豫地抓住机会赢得胜利。如果严厉，他的军队就会纪律严明。`

你也可以将模式和行号混合：

`:4,/awe/p`

并且感激他们的辛勤劳作。如果勇敢，他会毫不犹豫地抓住机会赢得胜利。如果严厉，他的军队就会纪律严明，因为他们畏他并害怕惩罚。

有一些特殊的 `ex` 行地址符号可以作为地址。当你在已知的功能的基础上添加这些功能时，行地址将具有更大的灵活性。特殊符号见表 3.10：

### 表 3.10. 特殊 `ex` 行地址符号。

| 命令 | 结果 |
| :--- | :--- |
| `.` | 当前行 |
| `$` | 文件的最后一行 |
| `%` | 文件中的每一行 |

另一个让行地址更具灵活性的特性是行号算术。该功能允许你在数字旁使用 `+` 和 `-` 符号来引用指定位置的偏移。例如，要引用当前行号之后的 20 行，你应该使用 `.+20`。

当使用两个行地址时，第二个地址不能小于第一个地址。有时当你尝试使用搜索模式选择行或使用行号算术时，可能会得到错误信息 `ex: The first address cannot exceed the second address.`。这是因为两个行地址都是相对于当前行确定的。在这种情况下，你将收到错误信息。你真正想要的是让第二个地址相对于第一个地址确定。`ex` 有一个功能可以使第二个行地址相对于第一个地址确定。你通过在两个地址之间使用分号而不是逗号来使用该功能。

下表 3.11 显示了目前为止介绍的所有各种行地址方法的若干示例。

### 表 3.11. 多种行地址方法。

| 命令 | 结果 |
| :--- | :--- |
| `1,5` | 第 1 到 5 行 |
| `.,20` | 从当前行到第 20 行 |
| `.,.+20` | 从当前行开始的 20 行 |
| `.,$` | 从当前行到文件末 |
| `1,$` | 文件中的所有行（与 `%` 相同） |
| `8,/*pattern*/` | 从第 8 行到下一个包含 `*pattern*` 的行 |
| `5;.+20` | 从第 5 行到第 5 行之后的 20 行 |

## 基础 `ex` 命令

`ex` 的特性是每个命令都有一个名称。你可以输入命令的完整名称，也可以任何足以将其与其他所有命令区分开来的任意长度的缩写。当我介绍新的 `ex` 命令时，我会首先使用完整命令名称。然而，示例将使用命令尽可能短的缩写，因为这才是你希望使用它们。表 3.12 显示了一些基础的 `ex` 命令：

### 表 3.12. 基础 `ex` 命令。

| 命令 | 结果 |
| :--- | :--- |
| `d` | 删除 |
| `m` | 移动 |
| `co` | 复制 |
| `t` | 复制（`co` 的同义词） |

表 3.13 展示了各种 `ex` 编辑命令的示例。它总结了本节关于处理文本块的信息。

### 表 3.13. `ex` 编辑命令的示例。

| 命令 | 结果 |
| :--- | :--- |
| `1,5d` | 删除第 1 到 5 行 |
| `.,20m$` | 将当前行通过第 20 行移动到文件末尾 |
| `.,.+20co` | 将当前行开始的 20 行复制到文件顶部 |
| `8,/*pattern*/t` | 将第 8 行到下一个包含 `*pattern*` 的行复制到当前行之后的位置 |

在本节中，我介绍了一些有助于扩展 `vi` 强大功能的基础 `ex` 命令。还有一些额外的 `ex` 命令提供了执行各种编辑任务的替代方法。然而，所有这些通过使用 `vi` 的功能都可以更更容易完成。因此，此处不涵盖此类命令。

## 搜索与替换

在 `vi` 内部使用 `ex` 命令的主要用途之一（除了处理文件和退出程序外）是执行搜索和替换操作。在本节中，介绍了基础的搜索和替换操作。下一节将介绍正则表达式主题。

正则表达式是搜索文本的极其强大的工具。如果你熟悉某些文本处理工具提供的所谓“通配符”搜索，你可以将正则表达式想象成“加强版的通配符”！使用正则表达式进行搜索将在本节后的第二节中介绍。

简单的搜索和替换操作在 `ex`（因此在 `vi`）中通过使用 `substitute` 命令完成。除非使用了行地址（见下文），否则 `substitute` 命令作用于当前行，因此先将光标移动到你想要编辑的行。以下示例假设你想将示例文本第 8 行中的单词 "plan" 替换为 "opportunities"。注意最后的斜杠是必须的：

```
:8 移动到缓冲区的第 8 行
:s/plans/opportunities/ 将当前行的 "plans" 替换为 "opportunities"
```

你也可以对整个文件或选定的范围执行搜索和替换操作。表 14 映了使用 `substitute` 命令操作缓冲区中所有行或选定范围的示例。

### 表 14. 使用 `substitute` 命令。

| 命令 | 结果 |
| :--- | :--- |
| `%s/warrior/general/g` | 将缓冲区中的每个 warrior 替换为 general。 |
| `.,.+20s/warrior/general/` | 从当前行开始的 20 行中的第一个 warrior 替换为 general。 |

另一种搜索方法是使用全局命令（global），如下：

`:g/plans/command` 当以这种方式使用时，命令作用于所有匹配模式的行。要反转搜索操作（即作用于所有不匹配模式的行），请使用 `:g!`。如果使用全局命令而不加最后的斜杠和命令，光标将定位到文件中包含模式的最后一行（如果使用了 `!`）。如果没有找到匹配项，屏幕将不会改变，光标将留在原地（以这种方式使用全局命令搜索的意义不大——使用 `vi` / 替替）。

你可以配合行地址使用全局命令来限制其作用范围。与其他命令配合使用全局命令的示例见表 15。

### 表 15. 与命令配合使用的全局命令。

| 命令 | 结果 |
| :--- | :--- |
| `:g/plans/d` | 删除所有包含 plans 的行 |
| `:g/plans/p` | 显示所有包含 plans 的行 |
| `:g!/plans/d` | 删除不包含 plans 的行 |
| `:8,12g/p` | 显示第 8 到 12 行之间包含 plans 的行 |

全局命令也可以用于替换。然而，该命令用于替换的真正威力直到你将其与搜索和替换操作中的正则表达式配合使用时才会显现，极大扩展了你可以编辑的力量和灵活性。正则表达式除了普通字符，还包括具有特殊属性的元字符组合。表 16 显示了 `vi` 中可用的元字符。（虽然有许多 *grep*、*sed*、*awk* 等处理正则表达式的 UNIX 工具，但表中某些元字符在这些工具中并未实现。仅限编辑器的元字符见注释。）

### 表 16. `vi` 可用的元字符。

| 元字符 | 匹配 |
| :--- | :--- |
| `.` | 除换行符以外的任意字符 |
| `\*` | 前一个字符零次或多次 |
| `^` | 正则表达式的起始字符，行首 |
| `$` | 正则表达式的最后一个，行尾 |
| `\<` | 单词的第一个字符（仅限编辑器） |
| `\>` | 单词的最后一个字符（仅限编辑器） |
| `\` | 转义字符；改变（转义）后续字符的标准解释。例如，要搜索元字符的字面存在，必须在它前面加上反斜杠进行转义。 |
| `\[ \]` | 括号内的任意字符；可以使用连字符使用范围。例如，`\[a-z\]` 匹配所有小字母，`\[a-zA-Z\]` 匹配大写和小字母。当元字符（除 ^ 外）出现在方括号内时，不需要转义。可以通过将其放在左括号后的第一个字符来包含字面连字符。 |
| `\[^\]` | 括号外的任意字符 |
| `\( \)` | 在搜索模式中，将括号内匹配的文本保存到编号缓冲区中以便以后“重放”（数字是自左到右扫描行时的位置；该元字符对第一次出现为 1，第二次为 2，依此类推） |
| `\n` | 在替换模式中，其中 n 是 1 到 9 的数字，“重放”括号保存的文本 |
| `&` | 使用产生匹配的整个搜索模式；用于节省输入 |
