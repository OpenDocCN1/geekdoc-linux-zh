## 总结

在研究了所有免费且开源的数据库后，发现只有 PostgreSQL 是最成熟、使用最广泛且最稳健的 RDBMS SQL 免费数据库。

问：我的所有服务器在并发访问表时都崩溃了。为什么？

答：这个问题可能是由于内核未配置支持信号量导致的。

问：我如何调优数据库引擎以提高性能？

答：当然，索引可以加速查询。`explain` 命令允许你查看 PostgreSQL 是如何解释你的查询的，以及使用了哪些索引。

如果你正在进行大量的插入操作，请使用 `copy` 命令进行大批量处理。这比单个单独插入要快得多。

其次，没有在 `begin work`/`commit` 事务块中的语句被认为处于自己的事务中。考虑在单个事务块中执行多条语句。这可以减少事务开销。此外，在进行大量数据更改时，考虑删除并重建索引。

有几项可以进行的调优工作。你可以通过通过带有 `-O -F` 选项启动 `postmaster` 来禁用 `fsync`。这将防止 `fsync()` 在每个事务后将数据刷新到磁盘。

你还可以使用 `postmaster -B` 选项来增加后端进程使用的共享内存缓冲区数量。如果你将此参数设置得过高，`postmaster` 可能无法启动，因为你超过了内核对共享内存空间的限制。每个缓冲区为 8K，默认为 64 个缓冲区。

你还可以使用后端的 `-S` 选项来增加每个后端进程用于临时排序的最大内存。`-S` 的值以千字节为单位，默认为 512（即 512K）。将此值设置得太大是不明智的，因为当查询调用多个并发排序时，你可能会耗尽内存。

你还可以使用 `cluster` 命令对基础表中的数据进行分组以匹配索引。更多细节请参阅 `cluster(1)` 手页。

问：PostgreSQL 提供了哪些调试功能？

答：PostgreSQL 具有若干可以报告状态信息的特性，这些对于调试非常有价值。

首先，通过带有 `--enable-cassert` 选项运行 `configure`，许多 `assert()` 会监控后端的进度，并在发生意外情况时停止程序。

`postmaster` 和 `postgres` 都有几个调试选项。首先，每当你启动 `postmaster` 时，请确保将标准输出和错误重定向到日志文件中：

```
cd /usr/local/postgresql
./bin/postmaster >server.log 2>&1
```

这会在 PostgreSQL 根目录下创建一个 `server.log` 文件。该文件包含了有关服务器遇到的问题或错误的有用信息。`postmaster` 有一个 `-d` 选项可以报告更详细的信息。`-d` 选项接受一个指定调试级别的数字。注意，高调试级别的值会生成巨大的日志文件。

你实际上可以从命令行运行 `postgres` 后端并直接输入 SQL 语句。这仅建议用于调试。注意，换行符终止查询而不是分号。如果你在编译时带有调试符号，可以使用调试器查看正在发生什么。由于后端不是从 `postmaster` 启动的，它并不是在相同的环境中运行，因此锁定/交互问题可能无法复现。某些操作系统可以直接附加到正在运行的后端以诊断问题。

`postgres` 程序具有 `-s`、`-A` 和 `-t` 选项，对于调试和性能测量非常有用。

你还可以通过性能分析（profiling）进行编译，查看哪些函数占用了执行时间。后端分析文件将位于 `pgsql/data/base/dbname` 目录下。客户端分析文件将放在当前目录。

问：尝试连接时遇到“Sorry, too many clients”。为什么？

答：你需要增加 `postmaster` 对其可以启动的后端进程数量的限制。

在 Postgres 6.5.* 中，默认限制是 32 个进程。你可以通过带有合适的 `-N` 值并重启 `postmaster` 来增加它。在默认配置下，你可以将 `-N` 设置为高达 1024；如果你需要更多，请在 `include/config.h` 中增加 `MAXBACKENDS` 并重新编译。如果你愿意，可以在配置时使用 `configure --with-maxbackends` 关来设置 `-N` 的默认值。

注意，如果你将 `-N` 设置得大于 32，你应该考虑将 `-B` 超过其默认值 64。对于大量的后端进程，共享内存的使用可能会成为问题。每个缓冲区为 8K，默认为 64 个缓冲区。总共享内存约为 `N * B * 8K`。

问：数据库集群（cluster）的要求是什么？

答：数据库集群必须由单个用户拥有。这是一个安全预防措施，因为任何用户都有可能将对象模块动态链接到数据库引擎中。
