## 1.2 问题与错误

如果你在使用 GNU `make` 时遇到问题，或者认为你发现了一个错误（bug），请向开发者报告；我们无法保证会采取任何行动，但我们可能想要修复它。

在报告错误之前，请确保你确实是发现了一个真实的错误。仔细重新阅读文档，查看它是否真的说明你可以执行你正在尝试的操作。如果你不确定是否应该执行某项操作，也请报告；那是文档中的一个错误！

在报告错误或尝试自行修复之前，请尝试将其隔离在能够重现该问题的最小制式文件（`makefile`）中。然后，将这个较小的 `makefile` 以及 `make` 输出给你的确切结果发送给我们。在生成此 `makefile` 时，请确保不要在命令中使用任何非免费或不寻常的工具：你几乎可以使用简单的 shell 命令来模拟此类工具的功能。最后，请务必解释你预期的发生情况；这将帮助我们判断问题是否真的出在文档中。

一旦你确定了精确的问题，请发送电子邮件至：

```
bug-make@gnu.org
```

请包含你正在使用的 `make` 版本号。你可以通过命令 `make --version` 获取此信息。请务必包含你正在使用的机器类型和操作系统。

# 第 2 章：Makefile 简介

## 2 Makefile 简介

你需要一个名为 `makefile` 的文件来告诉 `make` 要做什么。大多数情况下，`makefile` 告诉 `make` 如何编译和链接一个程序。

在本章中，我们将讨论一个简单的 `makefile`，它描述了如何编译和链接一个由 8 个 C 源文件和 3 个头文件组成的文本编辑器。`makefile` 还可以可以在被显式要求运行时运行杂杂命令（例如，删除某些文件作为清理操作）。要查看更复杂的 `makefile` 示例，请参阅附录 C [Complex Makefile]，第 157 页。

当 `make` 编译编辑器时，每个更改过的 C 源文件都必须重新编译。如果头文件发生了变化，为了安全起见，包含该头文件的每个 C 源文件都必须重新编译。每次编译都会产生一个与源文件对应的对象文件。最后，如果任何源文件被重新编译，所有的对象文件（新生成的或从之前的编译保存的）都必须链接在一起，以生成新的可执行编辑器。

### 2.1 规则的样貌

一个简单的 `makefile` 由具有以下形状的“规则”组成：

```
target ... : prerequisites
command
...
```

`target`（目标）通常是程序生成的文件的名称；目标的示例包括可执行文件或对象文件。`target` 也可以是要执行的操作的名称，例如 `clean`（参见第 4.4 节 [Phony Targets]，第 27 页）。

`prerequisite`（前提条件）是作为创建目标所需的输入文件。一个目标通常依赖于多个文件。
