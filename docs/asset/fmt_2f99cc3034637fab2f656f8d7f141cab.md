
# 图形函数

```
XImage *XSubImage(display, d, x, y, width, height, plane_mask,
format, dest_image, dest_x, dest_y);
```

- `display`: 指定可绘制 `drawable`。
- `d`
- `x`、`y`: 指定 `x` 和 `y` 坐标，它们相对于 `drawable` 的原点，并定义矩形的左上角。
- `width`: 指定子图像的宽度和高度，这定义了矩形的尺寸。
- `height`: 指定平面掩码。
- `plane_mask`: 指定图像的格式。你可以使用 `XPixmap` 或 `ZPixmap`。
- `format`: 指定目标图像。
- `dest_image`: 指定目标图像。
- `dest_x`、`dest_y`: 指定 `x` 和 `y` 坐标，它们相对于目标矩形的原点，指定其左上角，并确定子图像放置在目标图像中的位置。

`XGetSubImage` 函数以与 `XGetImage` 相同的方式通过指定的子图像更新 `dest_image`。如果 `format` 参数为 `XPixmap`，则图像仅包含你传递给 `plane_mask` 参数的位。如果 `format` 参数为 `ZPixmap`，`XGetSubImage` 在所有未在 `plane_mask` 参数中指定的位中返回零。该函数对 `plane_mask` 中的值不进行范围检查，并忽略多余的位。为了方便起见，`XGetSubImage` 返回一个指向 `dest_image` 指定的相同 `XImage` 结构的指针。

`XImage` 结构的深度必须与 `drawable` 的深度相同。如果指定的子图像不符合 `drawable` 图像上的指定位置，则右边缘和底边缘将被裁剪。如果 `drawable` 是 `pixmap`，矩形必须完全包含在 `pixmap` 内，否则会发生 `BadMatch` 错误。如果 `drawable` 是窗口，则该窗口必须是可见的，并且必须满足没有从属或重叠窗口、指定的窗口矩形完全在屏幕上并可能包含在窗口的外边缘内，否则发生 `BadMatch` 错误。如果窗口具有备份存储，则对于被从属窗口遮挡的窗口区域，将返回备份存储内容。如果窗口没有备份存储，则此类遮挡区域的返回内容未定义。如果从属窗口可见区域深度与指定的窗口深度不同，其返回内容也是未定义的。如果发生问题，`XGetSubImage` 返回 `NULL`。

`XGetSubImage` 可以产生 `BadDrawable`、`BadGC`、`BadMatch` 和 `BadValue` 错误。

# 第 9 章 窗口和会话管理器函数

很难将函数专门归类为应用程序、窗口管理器或会话管理器；本章中的函数通常由窗口管理器和会话管理器使用。预计大多数应用程序程序不会使用这些函数。Xlib 提供了以下管理函数：

- 修改窗口的父窗口
- 控制窗口的生命周期
- 管理已安装的颜色表（colormaps）
- 设置和检索字体搜索路径
- 提取服务器（Grab the server）
- 杀死客户端
- 控制屏幕保护程序
- 控制主机访问

## 修改窗口的父窗口

要将窗口的父窗口更改为同一屏幕上的另一个窗口，请使用 `XParentWindow`。没有在屏幕之间移动窗口的方法。

```
XParentWindow(display, w, parent, x, y);
```

- `display`: 指定到 X 服务器的连接。
- `w`: 指定窗口。
- `parent`: 指定父窗口。
- `x`、`y`: 在新父窗口中位置的 `x` 和 `y` 坐标。

如果指定的窗口已映射（mapped），`XParentWindow` 会自动对其执行 `Unmap` 请求，将其从当前的层次结构中移除，并作为指定父窗口的子窗口插入。相对于兄弟窗口的堆叠顺序处于顶端。

在重复 `ReparentNotify` 事件后，`XParentWindow` 会导致服务器生成 `ReparentNotify` 事件，返回的成员设置为窗口相应的属性。窗口管理器客户端通常忽略此成员。最后，如果指定的窗口原本是映射的，`XParentWindow` 会自动对其执行 `MapWindow` 请求。

服务器对被遮挡的窗口执行正常的显示（exposure）处理。服务器可能为初始 `Unmap` 请求后立即遮挡的区域生成 `Exposure` 事件。如果满足以下条件，会导致 `BadMatch` 错误：
- 新父窗口不在同一屏幕上。
- 新父窗口是指定窗口或指定窗口的从属。
- 新父窗口是 `InputOnly`，而窗口不是。
- 指定窗口具有 `ParentRelative` 背景，且新父窗口深度不同。

`XParentWindow` 可以产生 `BadMatch` 和 `BadWindow` 错误。

## 控制窗口的生命周期

集合是所有客户端窗口的列表，如果它们在连接关闭时是某个客户端窗口的从属，则不应被销毁并重新映射。有关关闭连接处理的更多信息，参见第 2.6 节。为了让应用程序窗口在窗口管理器渲染后生存，Xlib 提供了集合函数，你可以使用它们来控制通常会被销毁的窗口。例如，窗口管理器想通过添加帧（frame）为窗口添加装饰，当帧被销毁时，应用程序窗口不应被销毁，而是返回到它在窗口层次结构中的原有位置。

当窗口被销毁时，X 服务器会自动从客户端集合中移除它们。

要从客户端集合中添加或删除窗口，使用 `XChangeSaveSet`。

```
XChangeSaveSet(display, change_mode);
```

- `display`: 指定到 X 服务器的连接。
- `w`: 指定你想从客户端集合中添加或删除的窗口。
- `change_mode`: 指定模式。你可以使用 `SetModeInsert` 或 `Set`。

根据指定的模式，`XChangeSaveSet` 从客户端集合中插入或删除指定的窗口。指定的窗口可能由其他客户端创建，或者导致 `BadMatch` 错误。

`XChangeSaveSet` 可以产生 `BadMatch`、`BadValue` 和 `BadWindow` 错误。

## 窗口与会话管理器函数

```
XAddToSaveSet(display, w);
```

- `display`: 指定到 X 服务器的连接。
- `w`: 指定你想要添加到客户端保存集（save-set）的窗口。

`XAddToSaveSet` 函数将指定的窗口添加到客户端的保存集中。指定的窗口必须是由其他客户端创建的，否则将产生 `BadMatch` 错误。

`XAddToSaveSet` 可能会产生 `BadMatch` 和 `BadWindow` 错误。

要从客户端的保存集中移除窗口，请使用 `XRemoveFromSaveSet`。

```
XRemoveFromSaveSet(display, w);
```

- `display`: 指定到 X 服务器的连接。
- `w`: 指定你想要从客户端的保存集中删除的窗口。

`XRemoveFromSaveSet` 函数将指定的指定的窗口从客户端的保存集中移除。指定的窗口必须是由其他客户端创建的，否则将产生 `BadMatch` 错误。

`XRemoveFromSaveSet` 可能会产生 `BadMatch` 和 `BadWindow` 错误。

## 管理已安装的调色板（Colormaps）

X 服务器维护着一个已安装调色板列表。使用这些调色板的窗口保证以正确的颜色显示；使用其他调色板的窗口可能也无法以正确的颜色显示。Xlib 提供了你可以使用的函数来安装调色板、卸载调色板以及获取已安装调色板的列表。

在任何时候，已安装映射的子集被视为一个有序列表，并称为所需列表（required list）。所需列表的长度最大为 `M`，其中 `M` 是为屏幕指定的已安装调色板的数量。所需列表的维护方式如下：当通过 `XInstallormap` 指定调色板时，它被添加到列表头部；如果必要，会对列表尾部进行截断以保持其长度不超过 `M`。当调用 `UninstallColormap` 且调色板在所需列表中时，它会被从列表中移除。X 服务器不会隐式地卸载位于所需列表中的调色板。

要安装调色板，请使用 `XInstallormap`。

```
XInstallormap(display, colormap);
```

- `display`: 指定到 X 服务器的连接。
- `colormap`: 指定调色板。

`XInstallormap` 函数为其关联的屏幕安装指定的调色板。所有与该调色板关联的窗口立即以正确的颜色显示。调用 `CreateWindow`、`XCreateSimpleWindow`、`XChangeWindowAttributes` 或 `XSetWindowColormap` 创建的与该调色板关联的窗口，如果指定的调色板不是已安装的调色板，则会在每个拥有该调色板的窗口上产生 `ColormapNotify` 事件。此外，对于调用 `XInstallormap` 导致安装的其他调色板，会在每个拥有该调色板的窗口上产生 `ColormapNotify` 事件。

`XInstallormap` 可能会产生 `BadColor` 错误。

要卸载调色板，请使用 `UninstallColormap`。

```
UninstallColormap(display, colormap);
```
