
- `display` 指定与 X 服务器的连接。
- `keycode` 指定 `KeyCode` 或 `AnyKey`。
- `modifiers` 指定键位掩码集或 `AnyModifier`。掩码是有效键掩码位值的按位包含或运算结果。
- `grab_window` 指定要抓取的窗口。
- `owner_events` 指定一个布尔值，指示键盘事件是否按惯例报告。
- `pointer_mode` 指定指针事件的进一步处理。你可以传递 `GrabModeSync` 或 `GrabModeAsync`。
- `keyboard_mode` 指定键盘事件的进一步处理。你可以传递 `GrabModeSync` 或 `GrabModeAsync`。

`XGrabKey` 在键盘上建立被动抓取。在未来，如果键盘被积极抓取（如 `XGrabKeyboard`），且满足以下条件时，将产生 `KeyPress` 事件：

- 抓取窗口是 `grab_window` 的祖先（或其本身），且指定的修饰符在逻辑上处于按下状态（如 `XGrabKeyboard`）。
- 抓取是 `grab_window` 的后代，且指定的修饰符在逻辑上处于按下状态（对于无修饰符）。

请注意，修饰符的逻辑状态（客户端应用程序看到的）可能后于物理状态。

- `modifiers` 参数为 `AnyModifier` 等于对所有可能的修饰符组合发出请求（包括无修饰符的组合）。
- `keycode` 参数为 `AnyKey` 等于对所有可能的键码发出请求。否则，`keycode` 必须在指定的 `min keycode` 和 `max keycode` 范围内（对于连接设置）。

如果其他客户端已经在同一个窗口上对相同的按钮/键组合发出了 `XGrabKey`，会导致 `BadAccess` 错误。当使用 `AnyModifier` 或 `AnyKey` 时，如果任何抓取上存在冲突，请求将完全失败并产生 `BadAccess` 错误（未建立任何抓取）。

`XGrabKey` 可能会产生 `BadAccess`、`BadValue` 和 `BadWindow` 错误。

要取消抓取，使用 `XUngrabKey`。

```
XUngrabKey(display, keycode, modifiers, grab_window);
```

- `display`：指定与 X 服务器的连接。
- `keycode`：指定 `KeyCode` 或 `AnyKey`。
- `modifiers`：指定键位掩码集或 `AnyModifier`。掩码是有效键掩码位的按位或结果。
- `grab_window`：指定要抓取的窗口。

如果该组合被此客户端抓取，`XUngrabKey` 函数将释放该窗口上的组合。它对活跃的抓取无效。`modifiers` 为 `AnyModifier` 等同于对所有可能的修饰符组合（包括无修饰符的组合）发出请求。`keycode` 为 `AnyKey` 等于对所有可能的键码发出请求。

`XUngrabKey` 可能会产生 `BadValue` 和 `BadWindow` 错误。

## 恢复事件处理

之前的章节讨论了可以临时暂停服务器处理事件的抓取机制。本节介绍了恢复事件处理的机制。

要在设备被冻结后允许进一步处理事件，使用 `XAllowEvents`。

```
XAllowEvents(display, event_mode, time);
```

- `display` 指定与 X 服务器的连接。
- `event_mode` 指定事件模式。你可以传递 `AsyncPointer`、`SyncPointer`、`AsyncKeyboard`、`Keycode`、`ReplayPointer`、`ReplayKeyboard`、`AsyncBoth` 或 `SyncBoth`。
- `time` 指定时间。你可以使用时间戳或 `CurrentTime`。

如果客户端有要冻结的设备，`XAllowEvents` 函数将释放队列事件。如果指定的时间早于客户端最近一次活跃抓取的最后抓取时间，或者晚于当前 X 服务器时间，则将无效。根据 `event_mode` 参数，会发生以下情况：

# 输入设备功能

- `AsyncPointer`：如果指针被客户端冻结，指针事件处理将按照常进行。如果指针因两次独立的抓取（grab）被客户端冻结两次，`AsyncPointer` 对未被客户端冻结的指针无效，指针不需要被客户端抓取。

- `SyncPointer`：如果指针被冻结并被客户端活动抓取，指针事件处理将继续进行，直到向客户端报告了下一个按钮按下（`ButtonPress`）或按钮释放（`ButtonRelease`）。此时，指针看起来像是冻结了。然而，如果报告的事件导致抓取释放，则指针将不会冻结。`SyncPointer` 对未被客户端冻结的指针或未被客户端抓取的指针无效。

- `ReplayPointer`：如果指针被客户端活动抓取，并且由于发送给客户端的事件（来自 `XGrabButton` 的激活或来自之前的带有 `SyncPointer` 模式的 `XALLOWEvents` 触发）而被冻结，则指针将被释放并完全重新处理。然而，此时该函数将忽略刚刚释放的抓取处或上方（抓取根节点）的任何被动抓取。如果指针未被客户端抓取或指针未因事件而冻结，则该请求无效。

- `AsyncKeyboard`：如果键盘被客户端冻结，键盘事件处理将按照常进行。如果键盘因两次独立的抓取被客户端冻结两次，`AsyncKeyboard` 对未被客户端冻结的键盘无效，但键盘不需要被客户端抓取。

- `SyncKeyboard`：如果键盘被冻结并被客户端活动抓取，键盘事件处理将按照常进行，直到向客户端报告了下一个按按下（`KeyPress`）或按键释放（`KeyRelease`）。此时，键盘看起来像是冻结了。然而，如果报告的事件导致键盘释放，则键盘将不会冻结。`SyncKeyboard` 对未被客户端冻结的键盘或未被客户端抓取的键盘无效。

- `ReplayKeyboard`：如果键盘被客户端活动抓取，并且由于发送给客户端的事件（来自 `XGrabKey` 的激活或来自之前的带有 `SyncKeyboard` 但非来自 `XGrabKeyboard` 的 `XALLOWEvents` 触发）而被冻结，则键盘将被释放并完全重新处理。然而，此时该函数将忽略刚刚释放的抓取处或上方（抓取根节点）的任何被动抓取。如果键盘未被客户端抓取或键盘未因事件而冻结，则该请求无效。

- `SyncBoth`：如果指针和键盘都被客户端冻结，这两个设备的事件处理都将按照常进行，直到为被抓取的设备报告了下一个按钮按下、按钮释放、按按下或按键释放（指针对应按钮事件，键盘对应按键事件），此时设备看起来像是冻结了。然而，如果报告的事件导致抓取释放，它们就不会冻结（如果另一个设备也被 `XGrabbed`，则其随后的事件仍会导致两个设备都冻结）。如果键盘被客户端代表 `AsyncPointer`、`SyncPointer` 和 `ReplayPointer` 冻结，则 `SyncPointer` 对指针无效，且 `SyncKeyboard` 对此时的键盘事件的处理无效。`AsyncKeyboard`、`SyncKeyboard` 和 `ReplayKeyboard` 对指针事件的处理无效。指针抓取和键盘抓取（由相同或不同的客户端执行）可以同时激活。如果设备因任何一次抓取而被冻结，则对该设备不执行任何事件处理。单个设备可能因为两次抓取而被冻结。在这种情况下，在处理事件之前，必须代表抓取释放冻结。如果一个设备被同一个客户端冻结两次，则 `XAllowEvents` 会释放两者。

`XAllowEvents` 可能会产生 `BadValueError`。

## 移动指针

虽然指针的移动通常应该留给终端用户控制，但有时需要根据程序控制将指针移动到新位置。

将指针移动到窗口内的任意点，使用 `XWarpPointer`。

```
XWarpPointer(display, src_w, dest_w, src_x, src_y, src_width,
             src_height, dest_x, dest_y);
```
