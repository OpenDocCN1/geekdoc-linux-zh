
如果你将两个参数合并为一个，如 `ls -ld emptdir`，将获得额外分。

- 2. 使用命令 `touch emptyfile` 创建名为 `emptyfile` 的空文件。现在，使用 `chmod` 符号表示法为文件 `emptyfile` 的所有者添加执行权限，并移除其他人的执行权限。仅使用 `chmod` 命令完成。

这样思考：

- “对于文件的所有者 (u)，添加 (+) 执行 (x) 权限”，即 `u+x`。
- “对于组 (g) 和其他用户 (o)，移除 (-) 写 (w) 和执行 (x) 权限”，即 `go-wx`。

为了组合这两组权限，我们在它们之间添加一个逗号。最终结果是：

```
chmod u+x,go-wx emptyfile
```

- 3. 在我使用 `chmod 754 text.txt` 命令后，文件 `text.txt` 的权限是什么？

记住在数字表示法中，每个数字代表一组三项权限，每个权限都有相应的值：读取是 4，写入是 2，执行是 1，权限是 0。我们通过相加每个权限对应的值得到数字的值。7 是 4+2+1 对应 `rwx`，5 是 4+0+1，对应 `r-x`，4 仅仅是读取，即 `r--`。`text.txt` 的权限将是

```
rwx-xr--
```

- 4. 假设文件 `test.sh` 是一个 shell 脚本，具有以下权限和所有权：

```
-rwxr-sr-x 1 carol root      33 Dec 11 10:36 test.sh
```

- 文件所有者的权限是什么？
- `ls -l` 输出中所有者（第 2 到第 4 个字符）的权限是 `rwx`，所以答案是：“读取、写入和执行文件”。
- 如果用户 `john` 运行此脚本，它将在哪个用户的权限下运行？
- 注意组的权限。它们是 `r-s`，这意味着设置了 SGID 位。拥有该文件的组是 `root`，因此脚本即使由普通用户启动，也将以 `root` 权限运行。
- 使用数字表示法，`chmod` 的语法应该是什么，以“取消”授予此文件的特殊权限？

我们可以通过向 `chmod` 传递第 4 个数字 `0` 来“取消”特殊权限。当前权限是 `755`，所以命令应该是 `chmod 0755`。

## 探索性练习答案

### 1. 在终端上尝试此操作：使用 `touch emptyfile` 创建名为 `emptyfile` 的空文件。现在使用 `chmod 000 emptyfile` 将该文件的权限“清零”。如果你在数字模式下仅为 `chmod` 一个值来更改 `emptyfile` 的权限，例如 `chmod 4 emptyfile`，会发生什么？如果使用两个值，例如 `chmod 44 emptyfile` 呢？我们从 `chmod` 读取数值的方式中可以学习什么？

记住我们“清零”了 `emptyfile` 的权限。所以，其初始状态应该是：

```
1 carol      0 Dec 11 10:55 emptyfile
```

现在，尝试第一个命令 `chmod 4 emptyfile`：

```
$ chmod 4 emptyfile
$ ls -1 emptyfile
----r--r 1 carol 0 Dec 11 10:55 emptyfile
```

其他人的权限被更改了。如果我们尝试两个数字，例如 `chmod 44 emptyfile` 呢？

```
$ chmod 44 emptyfile
$ ls -1 emptyfile
----r--r 1 carol 0 Dec 11 10:55 emptyfile
```

现在，组和其他的权限都受到了影响。从我们可以得出结论，在数字表示法中，`chmod` 反向读取数值，从最低位（其他）到最高位（用户）。如果你传递一个数字，你修改的是其他的权限。两个数字修改组和其他，三个数字修改用户、组和其它，四个数字修改用户、组、其它以及特殊权限。

### 2. 你可以执行一个你拥有执行权限但没有读取权限（--x）的文件吗？

起初，答案显而易见：如果你有执行权限，文件应该运行。这适用于由内核直接执行的二进制格式程序。然而，有些程序（例如 shell 脚本）必须先被读取和解释，因此在这种情况下必须也设置读取权限 (r)。

### 3. 考虑 Linux 系统上临时目录 `/tmp` 的权限：

```bash
$ ls -l /tmp
drwxrwxrwt 19 root root 16K Dec 21 18:58 tmp
```

用户、组和其他用户都拥有完全权限。但普通用户可以删除该目录内的任何文件吗？为什么呢？

`/tmp` 是我们所说的“世界可写目录”，意味着任何用户都可以向其写入数据。但我们不希望一个用户修改他人创建的文件，因此设置了粘滞位（sticky bit）（如其他用户权限中的 `t` 所示）。这意味着用户可以删除 `/tmp` 中的文件，但前提是这些文件是他们创建的。

### 4. 一个名为 test.sh 的文件具有以下权限 -rwsr-xr-x，这意味着设置了 SUID 位。现在，运行以下命令：

```bash
$ chmod u-x test.sh
$ ls -l test.sh
-rwSr-xr-x 1 carol 33 Dec 11 10:36 test.sh
```

我们做了什么？大写的 S 代表什么？

我们移除了文件所有者的执行权限。`s`（或 `t`）在 `ls -l` 的输出中取代了 `x` 的位置，因此系统需要一种方法来显示用户是否具有执行权限。它通过改变特殊字符的大小写来实现。

第一组权限中的小写 `s` 意味着文件所有者具有执行权限且设置了 SUID 位。大写的 `S` 意味着文件所有者缺少（-）执行权限且设置了 SUID 位。

SGID 也是如此。第二组权限中的小写 `s` 意味着文件所属组具有执行权限且设置了 SGID 位。大写的 `S` 意味着文件所属组缺少（-）执行权限且设置了 SGID 位。

这对于粘滞位同样适用，它由第三组权限中的 `t` 表示。小写 `t` 意味着粘滞位已设置且其他人具有执行权限。大写 `T` 意味着粘滞位已设置但其他用户没有执行权限。

### 5. 你如何创建一个名为 Box 的目录，其中所有文件都自动属于组用户，并且只能由创建它们的文件的用户删除？

## Linux 基础（版本 1.6） | 主题 5：安全与文件权限

这是一个多步骤的过程。第一步是创建目录：

```bash
$ mkdir dir Box
```

我们希望在该目录下创建的每个文件自动分配给组用户。我们可以通过设置目录的所有者，然后在其上设置 SGID 位来实现。我们还需要确保该组的任何成员都可以向该目录写入内容。

由于我们并不不在乎其他权限是什么，并且只想“翻转”特殊位，因此使用符号模式是合理的：

```bash
$ chown :users Box/
$ chmod g+wxs Box/
```

注意，如果你的当前用户不属于 `users` 组，你必须在上述命令之前使用 `sudo` 命令以 `root` 身份进行更改。

现在是最后一部分，确保只有创建文件的用户才允许删除该文件。这是通过在目录上设置粘滞位（用 `t` 表示）来实现的。记住它是设置在其他用户（o）的权限上的。

```bash
$ chmod o+t Box/
```

目录 Box 的权限应该显示如下：

```bash
drwxwxrxr-t 2 carol users 4.0K Jan 18 19:09 Box
```

当然，你也可以用一个 `chmod` 命令就可以指定 SGID 和粘滞位：

```bash
$ chmod g+wxs,o+t Box/
```
