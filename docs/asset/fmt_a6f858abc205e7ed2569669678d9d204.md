## wget

另一个流行的下载程序是 `wget`。它适用于从 Web 和 FTP 下载内容。单文件、多个文件甚至整个站点都可以下载。要下载 `linuxcommand.org` 的首页，我们可以这样操作：

```bash
[me@linux~$] wget http://linuxcommand.org/index.php
--12:02:51-- http://linuxcommand.org/index.php
=> 'index.php'
Resolving linuxcommand.org... 66.35.250.210]:80... connected.
HTTP request sent, awaiting response... 200 OK
Length: unspecified [text/html]
```

```
[ <=> ] 3.12 KB/s 'index.php' saved [3120]
```

该程序的许多选项允许 `wget` 递归下载、后台下载（允许你注销后继续下载）以及完成部分下载的文件。这些功能在其优于平均的 man 页面中有详细介绍。

## 与远程主机的安全通信

多年来，Unix 类操作系统一直具有通过网络进行远程管理的能力。在互联网广泛普及的早期，有两个流行的程序用于远程登录。这些是 `login` 和 `telnet` 程序。然而，这些程序与 `ftp` 程序存在相同的致命缺陷；它们以明文传输所有通信（包括用户名和密码）。这使得它们在互联网时代完全不适用。

为了解决这个问题，开发了一种名为 Secure Shell (`SSH`) 的新协议。`SSH` 解决了与远程主机安全通信的两个问题：

* 它防止所谓的中间人攻击。
* 它加密了本地和远程主机之间的所有通信。

`SSH` 由两个部分组成。`SSH` 服务器运行在远程主机上，监听传入的连接（默认在端口 `22`），而 `SSH` 客户端用于在本地系统中与远程服务器进行通信。

大多数 Linux 发行版都自带了来自 OpenBSD 项目的名为 OpenSSH 的 SSH 实现。某些发行版默认同时包含客户端和服务器包（例如 Red Hat），而其他一些（如 Ubuntu）则仅提供客户端。要使系统能够接收远程连接，必须安装、配置并运行 OpenSSH-server 软件包，并且如果系统正在运行或位于防火墙之后，它必须允许通过 TCP 端口 `22` 的入站网络连接。

### 提示

如果你没有可以连接的远程系统，但想尝试这些示例，请确保你的系统已安装 OpenSSH-server 软件包，并使用 `localhost` 作为远程主机的名称。这样，你的机器就会与它建立网络连接。

用于连接远程服务器的 SSH 客户端程序形象地被称为 `ssh`。要连接到名为 `remote-sys` 的远程主机，你可以使用 `ssh` 客户端程序：

```
@linuxux ~$ ssh remote-sys
The authenticity of host 'remote-sys (192.168.1.4)' can't be established.
RSA key fingerprint is 41:ed:7a:df:23:19:bf:3c:a5:17:bc:61:b3:7f:d9:bb:
Are you sure you want to continue connecting (yes/no)?
```

在第一次尝试连接时，会显示一条消息，无法无法远程主机的真实性。这是因为客户端程序从未见过这个远程主机。要接受远程主机的凭据，请在提示时输入 `yes`。一旦连接建立，用户会被提示输入密码。

警告：永久地将 'remote-sys,192.168.1.4' (RSA) 添加到已知主机列表中。

me@remote-sys's password:

成功输入密码后，我们就会来自远程系统的 shell 提示符。

```
Last login: Sat Aug 25 13:00:48 2018
me@remote-sys~$
```

远程会话一直持续，直到用户在远程 shell 提示符输入退出命令，关闭远程连接。此时，本地 shell 会话恢复，本地 shell 提示符重新出现。

```
@linuxux ~$ ssh remote@remote-sys
bob@remote-sys's password:
Last login: Sat Aug 25 13:03:21 2018
[bob@remote-sys~$]
```

如前所述，`ssh` 会验证远程主机的真实性。如果远程主机未通过验证，将出现以下消息：

```
~me@linuxbox ~$ ssh remote-sys
################################################################################################@
@  WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!  @
################################################################################################@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
```

现在可能有人正在监听你的连接（中间人攻击）！也可能是远程主机的 RSA 密钥已经更改。

远程主机 RSA 密钥的指纹为

41:ed:7a:df:23:19:3f:ca:57:c6:b3:7f:d9:bb。

请联系你的系统管理员。

将主机密钥添加到 `/home/.ssh/known_hosts` 中以消除此消息。

Offending key in `/home/.ssh/known_hosts`:1

`remote-sys` 的 RSA 主机密钥已更改，且你请求了严格检查。

host verification failed.

此消息是由两种可能的情况之一引起的。首先，攻击者可能正在尝试中间人攻击。这种情况很少见，因为任何触发 `ssh` 威胁警告的人都会收到警告。更可能的魁祸首是远程系统、操作系统或 SSH 服务器被重新安装了。然而，出于安全考虑，不应忽视第一种可能性。每当出现此消息时，请务必向远程系统的管理员确认。

在确定消息是由良性原因引起后，在客户端侧修复问题是安全的。这可以通过使用文本编辑器（可能是 `vim`）从 `~/.ssh/known_hosts` 文件中删除过密钥来实现。在前面的示例中，我们看到：
