### 总结

在这节课程中，我们发现了 Linux 用户和组数据库。我们学习了用户和组的最重要属性，包括它们的名称和数字 ID。我们还研究了 Linux 上密码哈希是如何工作的，以及用户是如何分配到组的。

所有这些信息都存储在以下四个文件中，这些文件提供了 Linux 系统上最基本的本地安全控制：

```
/etc/passwd
```
除密码哈希外的所有系统本地用户账户的 POSIX 属性，所有人均可读。

```
/etc/group
```
所有系统本地组账户的 POSIX 属性，所有人均可读。

```
/etc/shadow
```
所有系统本地用户密码哈希（以及过期信息），任何用户均不可读（仅限特定用户）。

```
/etc/sudoers
```
通过 `sudo` 命令实现的所有系统本地权限提升信息/允许项。

### 探索性练习答案

1. 比较 `last`、`w` 和 `who` 命令的结果。相比之下，每个命令分别缺少了哪些细节？

`w` 和 `who` 只列出当前用户，而 `last` 列出已离开的用户。

2. 尝试执行 `who` 和 `w -h` 命令。
- 使用“无表头” (`-h`) 和“短格式” (`-s`) 选项后，`w` 命令输出中删除了哪些信息？
不再打印表头（便于解析），分别不再显示登录时间和 CPU 信息。
- 使用“IP 地址” (`-i`) 选项后，`w` 命令输出中增加了哪些信息？
它打印 IP 地址，而不是尝试 DNS 解析。

3. 哪个文件存储了用户账户的单向密码哈希？

`/etc/shadow` 文件存储用户账户的单向密码哈希，因为它对普通账户不可读，不像 `/etc/passwd`。

4. 哪个文件包含了用户账户所属的组列表？可以使用什么逻辑来编译一个用户账户所属的组列表？

`/etc/group` 文件是任何行最后字段“members”中的用户名 CSV 列表。此外，用户在 `/etc/passwd` 文件中的主组关系在 `/etc/group` 中也有对应的组名和 GID 条目。

5. 默认情况下，以下文件中有一个或多个 (1+) 是无法普通非特权用户读取的。是哪几个？
`/etc/shadow` 和 `/etc/sudoers`

默认情况下 `/etc/shadow` 和 `/etc/sudoers` 不可读，仅限特定服务或超级用户。

6. 你如何在非交互模式下将当前用户的登录 shell 更改为 Korn Shell (`/usr/bin/ksh`)？

```bash
$ chsh -s /usr/bin/ksh
```

7. 为什么 root 用户的家目录不放置在 `/home` 目录下？

因为 root 账户用于排故障和修复错误，这些错误可能与 `/home` 目录相关的文件系统问题。在这种情况下，即使 `/home` 文件系统尚未可用，root 也应该能够正常运行。

/etc/gshadow
