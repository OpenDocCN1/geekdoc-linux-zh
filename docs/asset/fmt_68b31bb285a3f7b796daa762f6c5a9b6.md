## 逐行处理文件的两种方法 73

第一个测试检查确保由 `$#` 算符指定的命令参数数量恰好为一。我们注意到用到了双括号数学测试，其表示方式为 `(( math test ))`。此外，我们还使用了逻辑或 `||`，当参数数量不等于 1 时执行用法函数。

我们使用相同类型的测试来检查文件是否存在以及该文件是否为普通文件（而不是字符或块特殊文件）。在测试字符数据时，我们使用了双括号测试，表示为 `[[ character test ]]`。如果测试的返回码不为 0，我们使用逻辑或执行用法函数。

现在我们开始实际测试。在这些测试中，我们一个接一个执行 `Method` 函数。函数的 `while` 循环负责文件处理，我们将每个函数的输出重定向到一个文件中，这样我们就有了可衡量的活动。正如我所说的，`time` 命令的测量结果会发送到 `stderr`（即文件描述符 2），这将直接显示在屏幕上。当 shell 脚本执行时，会有三项内容输出到屏幕，如列表 2.17 所示。你也可以通过以下语法将这些输出的任何部分发送到文件：

```
12_ways_to_parse.ksh /scripts/bigfile > /tmp/timing_data.out 2>&1
```

之前的命令以脚本名称开头，随后是需要解析的文件。输出被重定向到文件 `/tmp/timing_data.out`，并通过 `2>&1` 指定 `stderr`（文件描述符 2）。不要忘记 1 之前的和符号 `&`。如果省略了 `&`，将创建一个名为 1 的文件。这是处理文件描述符时的常见错误。在这种情况下，将 `stderr` 重定向到 `stdout` 的位置很重要。如果 `2>&1` 位于命令末尾，你将无法想要的结果（即所有计时数据都进入数据文件）。在某些情况下，`2>&1` 重定向的位置并不重要，但在这里很重要。
