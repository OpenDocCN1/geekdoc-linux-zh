## Extended Description

每个输入文件包含 `lex` 源，即一个带有以 C 程序片段形式对应的动作的正则表达式表。

### 674

### lex

当 `lex.yy.c` 编译并与 `lex` 库链接（使用 `c89` 或 `cc` 时使用 `-l` 运算符）时，生成的程序将从标准输入读取字符输入，并将其划分成匹配表达式的字符串。

当匹配到表达式时，会发生以下操作：

- 留在 `yyytest` 中的输入字符串将以空终止字符串的形式形式存在；`yyytest` 既可以是外部数组，也可以指向字符字符串的指针。你可以通过 `%array` 或 `%pointer` 声明显式选择类型。默认是 `%array`。
- 外部整数 `yyleng` 被设置为匹配字符串的长度。
- 执行该表达式对应的程序片段（或动作）。

在匹配过程中，`lex` 会在模式集中寻找单个最长匹配项。在匹配相同字符数量的规则中，选择选择在源文件中第一个给出的规则。

`lex` 源代码的通用格式为：

```
Definitions %%
Rules %%
Subroutines
```

第一个 `%%` 用于标记规则（正则表达式和动作）的开始；第二个 `%%` 只有在后面跟着用户子程序时才需要。

`Definitions` 部分中任何以空白字符开头的行都被假定为 C 程序片段，并复制到 `lex.yy.c` 文件的外部定义区域。同样，`Definitions` 部分中包含在仅包含 `% {` 和 `}` 的分隔符行之间的任何内容也会原封不动地复制到 `lex.yy.c` 的外部定义区域。

在 `Rules` 部分开头、指定任何规则之前出现的任何输入（以空白字符开头或在 `% { }` 分隔符行内），都将在 `yyylex` 函数变量声明之后、`yyylex` 的第一行代码之前写入 `lex.yy`。因此，`yyylex` 的局部变量可以在此处声明，也可以在此编写在 `yylex` 上执行的应用代码。

当 `lex` 在 `Rules` 部分遇到任何以空白字符开头或在 `% { }` 分隔符行内的输入，且该输入出现在一个或多个规则之后，`lex` 所采取的动作是未定义的。此类输入的存在可能导致 `yyylex` 函数定义错误。

## lex 中的 Definitions

`lex` 中的 `Definitions` 出第一个 `%%` 分隔符之前。该部分中任何未包含 `% {` 和 `}` 行之间且不以空白字符开头的行都被假定为定义了一个 `lex` 替换字符串。这些行的格式为：

```
name substitute
```

### lex 675

如果名称不符合 ISO C 标准中标识符的要求，则结果是未定义的。字符串 `substitute` 在规则中使用时替换字符串 `{ name }`。`name` 字符串只有在提供且未出现在括号表达式或双引号内时，在此上下文中被识别。

在 `Definitions` 部分，任何以 `%`（百分号）字符开头并跟随以 `s` 或 `S` 开头的字母数字单词定义定义一组启动条件（start conditions）。任何以 `%` 开头后跟以 `x` 或 `X` 开头的单词定义一组排斥启动条件（exclusive start conditions）。当扫描器处于 `%x` 状态时，此类模式是不活跃的；第一个单词后的剩余被视为一个或多个由空白字符分隔的启动条件名称。启动条件的构建方式与定义名称相同。启动条件可以用于限制正则表达式的匹配到一个或多个状态。

实现可以接受 `Definitions` 部分中两种互斥的声明之一：

- 声明 `yytext` 的类型为空终止数组
- 声明 `yytext` 的类型为指向空终止字符串的指针

> 注意 — 使用 `%pointer` 选项时，你无法使用 `yyll` 函数修改 `yy`。

`%array` 是默认值。如果你指定 `%array`（或不指定 `%array` 或 `%pointer`），对 `yytext` 进行外部引用的正确方法是使用如下形式的声明：

```
extern char *array[];
```

如果你指定 `%pointer`，对 `yytext` 进行外部引用的正确方法是使用如下形式的声明：

```
extern char *yytext;
```

`lex` 接受在 `Definitions` 部分通过声明设置某些内部表的大小。声明所示表。

| 声明 | 描述 | 默认值 |
|---|---|---|
| `%p n` | 位置数量 | 2500 |
| `%n n` | 状态数量 | 500 |
| `%a n` | 转换数量 | 2000 |
| `%e n` | 解析树节点数 | 1000 |

| 声明 | 描述 | 默认值 |
|---|---|---|
| `%k n` | 紧凑字符类数量 | 10000 |
| `%o n` | 输出数组大小 | 3000 |

`lex` 生成的程序需要 `-e` 或 `-w` 选项来处理包含补充字符集中 EUC 字符的输入。如果这两个选项都没有指定，`yytext` 的类型为 `char[]`，生成的程序只能处理 ASCII 字符。

当你使用 `-e` 选项时，`yytext` 的类型为 `unsigned char[]`，`yyleng` 给出匹配字符串的总字节数。使用此选项时，宏 `input(c)`、`unput(c)` 和 `output(c)` 应该像带有 `-e` 选项的普通 ASCII `yytext` 和 `yyleng` 一样进行基于字节的 I/O。还有两个变量，其行为与 `-w` 选项下的 `yytext` 和 `yyleng` 相同。

当你使用 `-w` 选项时，`yytext` 的类型为 `wchar[]`，`yyleng` 给出匹配字符串的总字符数。如果你在使用此选项时提供了 `input(c)`、`unput(c)` 或 `output(c)` 宏，它们必须返回或接受形式为 EUC 的字符。

## lex 中的 Rules

`lex` 中的 `Rules` 是一个表格，左列包含正则表达式，右列包含在识别时执行的动作。

```
ERE action
ERE action
...
```

`Rules` 源文件的 ERE 表左列包含正则表达式，右列包含在识别时执行的动作（C 程序片段）。ERE 表达式部分通过一个或多个空白字符与动作隔开。包含空白字符的正则表达式 只有在满足以下条件之一时被识别：

- 整个表达式位于双引号内。
- 空白字符位于双引号内。
- 每个空白字符都由反斜杠引导。

## lex 中的 User Subroutines

用户子程序部分的任何内容都复制到 `lex.yy`。

## lex 中的正则表达式

`lex` 支持 `regex(5)` 中描述的扩展正则表达式（ERE），并带有以下附加和例外。

...

任何在双引号内的字符串表示双引号内的字符本身，但反斜杠转义会被结束引号终止。例如，`"01"` 表示单个字符：八进制值 1。

```
<state>r <state,state2>
```

只有当程序处于 `state`、`state2` 等指示的启动条件时，才匹配正则表达式 `r`。（与本文其他排版约定不同，此处 `<state>` 不代表元变量，而是字角括号符号。）启动条件仅在正则表达式的开头处识别。

```
r/x
```

只有当 `r` 后面跟着正则表达式 `x` 时，才匹配正则表达式 `r`。返回的标记匹配 `r`。如果 `r` 的后续部分匹配 `x` 的开头，则后续未定义。`r` 表达式不能包含进一步的上下文，也不包含 `^`（匹配行首）运算符，也不包含 `^`（匹配行尾）运算符或 `$` 运算符。也就是说，`lex` 正表达式允许一次上下文，且该运算符只能出现在开头。

```
{name}
```

当 `name` 是 `Definitions` 部分的替换符号之一时，将大括号字符串替换为替换值。在扩展正则表达式中处理替换值就像在括号中一样。如果 `(name)` 出现在括号表达式或双引号内，则不发生替换。
