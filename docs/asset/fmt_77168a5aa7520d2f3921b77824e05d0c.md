
你可以修改单词选择器以在插入新命令之前更改单词的形式。修饰符的格式为 `:x`，其中 `x` 是一个指定如何修改单词的字母。例如，`!vi*:t` 替换 `vi` 命令的第一个参数；对于参数 `/usr/X/lib/samples/xclock*`，`:t` 的值为 `xclock.c`。

## 表 12.7. 历史替换修饰符

| 修饰符 | 功能 |
| :--- | :--- |
| `:e` | 删除“文件”后缀以外的所有内容。对于参数 `foo.sh`，`:e` 返回 `.sh` |
| `:h` | 删除末尾的路径组件。连续的 `:h` 修饰符从右到左一次删除一个路径组件。对于参数 `/usr/local/etc/http/htdocs/index.html`，`:h` 返回 `/usr/local/etc/http/htdocs`，而 `:h:h` 返回 `/usr/local/etc/http/htpd` |
| `:p` | 在命令行的任何历史替换中使用时，导致 shell 在替换后打印命令但不执行它。使用 `:p` 在执行之前尝试历史替换的效果。 |
| `:q` | 将替换后的单词或多个单词括在引号中以防止进一步替换。 |
| `:r` | 删除 `.string` 文件名后缀。例如，对于参数 `:foo.cc`，`:r` 返回 `foo`。`:r` 运算符一次删除一个后缀。例如，`:r` 应用于 `arch.tar.gz` 返回 `arch` |
| `:s/x/y` | 将替换字符串中的 `x` 替换为 `y`。字符串 `:x` 不能是正则表达式。`y` 中的符号 `&` 被替换为搜索字符串 `x`——例如，`:s/bill/&/substitutions` `:s/?user/?user?`。如果后面跟着换行符，则省略最后的。任何字符都可以通过反斜杠 (`\`) 转义作为分隔符（`/` 或你的分隔符）或 `&` 的文本字符——例如 `:s\/usr\/user/`。可以省略搜索字符串 `x`，此时使用行的搜索字符串。或者，如果没有之前的 `:s`，则使用 `!?string` 的搜索。 |
| `:t` | 删除路径的所有组件，仅返回文件名。对于单词 `/usr/bin/ls`，`:t` 的值为 `ls`。 |
| `:x` | 在空格、制表符和换行符处分割所选单词。 |
| `&` | 重用上一个字符串替换修饰符。例如，如果命令行中出现 `:s`，则 `!grep:2:s/bill/marty/ !3:&` 等同于 `!grep:2:s/bill/marty/ !3:s/marty/` |

通常情况下，`:a` 只影响第一个单词。在选择多个单词时（例如使用 `!12:2*`），你可以在修饰符列表前插入 `g` 来对所有所选单词应用修饰符。例如，`!12:2*:gh` 对所有单词应用 `:h` 修饰符。`g` 不适用于 `:p`、`:q` 和 `x` 修饰符。

在同一行使用两个或多个表达式时，可以在历史替换中省略命令标识符；连续的引用指向第一个命令。

```
% vi %grep^t: :3:t %4:
```

都指向 `grep` 命令，但选择了第一、第三和第四参数。

历史机制支持缩写 `^`，这对于纠正上一行的输入错误非常有用。缩写的一般形式为 `x:y`，其中 `x` 和 `y` 是字符串。选择命令行并搜索字符串；如果找到，则将其替换为 `y` 然后执行。例如，对于命令 `cd /usr/ban`，输入行 `^ban-bin`（或 `^a`）来执行 `cd /usr/bin`。脱字符 `^` 是行中被识别为行编辑替换的第一个空字符。这仅适用于紧之前的命令；要编辑最后之外的其他命令，必须使用行编辑器 `line:s/x/y`。

历史替换机制的最后一个重要规定是，你可以将任何历史引用括在大括号 `{}` 中以将其与随后的字符隔离。因此，`{!vi^h}.cc` 形成一个以所选历史引用开头并以 `.cc` 结尾的单词。

**提示：** 使用历史替换 `*` 防止意外删除文件。在创建用于删除文件的表达式时，使用 `ls` 命令查看结果。当你确认只有预期的文件被删除后，使用带有 `*` 替换的 `rm` 命令。在下面的示例中，用户正尝试删除所有与 C++ 相关的源文件和一个 Makefile。

```
ls pub* Makefile

Makefile pubList.txt publish.cc publish.hh

ls pub* Makefile

Makefile publish.cc publish.hh

rm *
```
