
| `check-update` | 检查是否有可用更新。如果有，`yum`将显示它们的名称、版本和仓库区域（例如`updates` `extras`）。 |

| `upgrade` | 作用类似于设置了`--obsoletes`标志的`update`，在执行发行版升级时，它处理过时包的方式更优。 |

| `remove`或`erase` | 从系统中删除包；类似于`rpm -e`，但也会删除被依赖的包。 |

| `list` | 显示有关包的信息，例如已安装的版本以及是否有可用更新。 |

| `provides`/`whatprovides` | 显示提供特定程序或功能的包的信息。例如，输入`yum provides samba`会列出所有Samba相关的包，包括所有可用更新。注意输出可以复制。 |

| `search` | 针对指定的关键词搜索包名、摘要、打包者和描述。如果你不知道包的名称但能想起关键词，这很有用。 |

| `info` | 显示有关包的信息，类似于`rpm -qi`命令。 |

| `clean` | 清理Yum缓存。建议定期运行此命令，以免下载的包占用过多空间。 |

| `shell` | 进入`yum`模式，在其中你可以连续输入多个`yum`命令。 |

| `resolvedep` | 显示指定的依赖项。 |

| `localinstall` | 安装指定的本地RPM文件，使用`yum`仓库解析依赖项。 |

| `localupdate` | 使用指定的本地RPM文件更新系统，使用`yum`仓库解析依赖项。除了本地更新的包外。 |

| `deplist` | 显示指定包的依赖列表。 |

在大多数情况下，使用Yum比直接使用RPM管理包要简单，因为Yum会查找可用包、下载它并安装所需的依赖项。不过Yum也有局限性；它取决于仓库，因此无法安装未存储在仓库中的软件。

如果你使用Yum自动升级包，你实际上是将控制权交给了发行版维护者。虽然Red Hat或其他发行版维护者不会这样入侵你的计算机，但在缺乏监督的情况下自动更新很容易损坏你的系统，特别是如果你过去从异常来源获取过包。

如果你不想安装包只想获取它，可以使用`yumdownloader`。输入此命令加上包名，最新版本的包将下载到当前目录。如果你需要更新未连接互联网的系统，这可能非常方便；你可以使用另一台运行相同发行版的计算机获取包，然后将其传输到目标系统。

如果你倾向于使用GUI工具而不是命令行工具，你应该知道`yum`有GUI前端。例如`yumex`和`kyum`。你可以使用文本模式`yum`安装这些前端，如`yum install kyum`。

### 练习 2.1

#### 使用 RPM 管理包

要使用`rpm`工具管理包，请遵循以下步骤：

1. 以普通用户登录Linux系统。

2. 获取一个用于测试目的的包。你可以尝试使用发行版中你已知未安装的包，或者随机尝试一个包，可能会发现它已经安装或存在未满足的依赖项。例如，本实验使用`zsh-5.0.6-1.fc20.x86_64.rpm`（一个大多数系统默认未安装的shell）从Fedora 20 DVD安装到Fedora 20系统。

   如果你在测试中使用另一个RPM文件，必须根据需要调整命令。

3. 如果你使用的是GUI登录，请从桌面环境的菜单系统启动`xterm`。

4. 获取`root`权限。你可以通过在`xterm`中输入`su`、在`Konsole`窗口中选择`Session » New Root Console`或使用`sudo`（如果已配置）来运行后续步骤中的命令。

5. 输入`rpm -q zsh`以验证该包当前未安装。系统应该返回消息`package zsh is not installed`。

6. 输入`rpm --qi zsh-5.0.6-1-fc20.x86_64.rpm`（如果该文件不在当前目录中，你需要提供包文件的完整路径）。系统应该响应并显示包的信息，例如版本号、供应商、构建该包的主机主机以及包描述。

7. 输入`rpm -ivh zsh-5.0.6-1-fc20.x86_64.rpm`。系统将安装包并在过程中显示一系列哈希值（`#`）。

8. 输入`rpm -q zsh`。系统应该响应完整的包名，包括版本号和构建号。此响应证实了包已安装。

9. 输入`zsh`。这会启动一个Z shell，它的功能与更常见的`bash`和`tsh` shell类似。你可能会看到命令提示符，但你可以执行许多与`bash`或`tsh`使用的相同命令。

10. 输入`rpm -v zsh`。系统不应产生任何输出——只有一个新的命令提示符。`verify`（`-v`或`--verify`）命令会将包文件与数据库中存储的数据进行比对。安装完成后，绝大多数包都应该显示没有差异。（少数包在安装期间会被修改，但`zsh`不在其中。）

11. 输入`rpm -e zsh`。系统不应产生任何输出——只有一个新的命令提示符。此命令从系统中删除该包。请注意，你是在运行`zsh`程序时删除了`zsh`包。Linux会继续运行你正在使用的`zsh`程序，但你将无法启动该程序的新实例。如果你这样做，某些程序可能会运行异常，因为在删除包后文件将会缺失。

12. 输入`exit`退出`zsh`并返回你的普通shell。

13. 输入`rpm -q zsh`。系统应该返回`package zsh is not installed`错误，因为你刚刚卸载了该包。

14. 输入`yum install zsh`。系统将检查你的仓库，下载`zsh`并安装它。它会在开始下载前请求你确认。

15. 输入`rpm -q zsh`。结果将与步骤8类似，尽管版本号可能不同。

16. 输入`rpm -e zsh`。此步骤将从系统中移除`zsh`但但不产生输出，与步骤11一样。

最后三个步骤仅在你的发行版使用Yum时有效。如果你使用的是使用其他工具的发行版，你可能找到并使用其等效工具，例如SUSE的`zipper`。

## RPM 和 Yum 配置

通常情况下，你不需要显式配置RPM或Yum；使用RPM的发行版会默认以合理的方式进行配置。尽管如此，你可能想要调整一些细节，特别是当你经常构建RPM包并希望为你的计算机优化输出时。你还可能为你运行的某些特殊软件添加Yum仓库。为此，你通常需要编辑RPM或Yum配置文件。

主要的RPM配置文件是`/usr/lib/rpm/rpmrc`。该文件设置了多种选项，大部分与编译包时使用的CPU优化有关。你不应该编辑此文件；相反你应该创建并编辑`/etc/rpmrc`（进行全局更改）或`~/.rpmrc`（按用户进行更改）。创建此类文件的主要目的是为了实现架构优化——例如，在将源码RPM构建为二进制RPM时，通过传递适当的选项为你的CPU模型优化代码。这是通过`optflags`行实现的：

```
optflags: athlon -O2 -g -march=i686
```

此行告诉RPM每当它为`athlon`平台进行构建时，都将`-O2 -g -march=i686`选项传递给编译器。尽管RPM可以确定你的系统架构，但仅凭`optflags`行可能不足以设置正确的标志。大多数默认的`.rpmrc`文件包含一系列`buildarchtranslate`行，这会导致`rpmbuild`（或旧版本RPM的`rpm`）对整个CPU家族使用一套优化方案。对于x86系统，这些行通常如下：

```
buildarchtranslate: athlon: i3886
buildarchtranslate: i686: i3886
buildarchtranslate: i586: i3886
buildarchtranslate: i486: i3886
buildarchtranslate: i386: i3886
```

这些行告诉RPM将`athlon`、`i686`、`i586`、`i486`和`i386` CPU代码转换为使用`i386`优化方案。这实际上抵消了你在`optflags`行中为架构创建的任何特定CPU优化的目的，但它保证了包可以运行。如果你想使用特定CPU的优化，你必须修改该行：

```
buildarchtranslate: athlon: athlon
```

主要的Yum配置是`/etc/yum.conf`。该文件设置了Yum的选项，例如它搜索包的仓库。你不应该直接编辑此文件；相反你应该在`/etc/yum.repos.d/`中创建新文件。每个文件代表一个仓库并包含几个关键字段：

- `[repository id]`：仓库的名称。
- `baseurl`：仓库的URL。
- `enabled`：仓库是否启用（1）或禁用（0）。
- `gpgcheck`：是否检查包的数字签名。
- `gpgkey`：用于验证的GPG密钥路径。

一个仓库文件的示例如下：

```
[myrepo]
baseurl=http://www.example.com/repo/
enabled=1
gpgcheck=1
gpgkey=http://www.example.com/repo/RPM-KEY
```

当你添加仓库时，Yum会自动将其包含在搜索中。你可以使用`yum repos list`查看所有启用和禁用的仓库，使用`yum config-repo-enable <id>`或`yum config-repo-disable <id>`。要移除仓库，只需删除`/etc/yum.repos.d/`中的文件。

## RPM与其他格式的对比

RPM是一个非常灵活的包管理系统。在大多数方面，它与Debian的包管理器可以媲美，并且提供的功能比`tarball`多得多。与Debian包相比，RPM的最大优势可能是它的通用性。许多软件包由开发者和/或发行版维护者以RPM格式提供。

![](img/f74c2c51e1985d4d3a6804ba2887d2f4_167_0.png)

`RPMFind`网站`http://rpmfind.net`是你想要查找特定程序的RPM时的一个非常有用的资源。另一个具有类似特征的网站是`Fresh RPMs`，`http://freshrpms.net`。这些网站包含了程序作者构建的RPM、特定发行版的RPM以及由第三方构建的RPM链接。将此类站点作为Yum仓库添加到你的仓库库中，可以让安装新程序变得更加简单。

与`tar`包（`tarballs`）相比，RPM提供了更复杂的软件包管理工具。这在你升级或删除软件包以及验证已安装软件包的完整性时可能非常重要。另一方面，尽管RPM在Linux世界中很常见，但在其他平台上并不常见。因此，你更有可能找到通用Unix源码的`tar`包，如果你编写了一个打算分发到其他平台的程序，通常会选择`tar`包。

## 使用 Debian 包

在整体功能上，Debian包与RPM软件包相似，但每个包的操作细节有所不同，且Debian包使用的发行版也与RPM不同。由于每个系统都使用自己的数据库格式，如果不进行格式转换，RPM和Debian包无法互换。使用Debian包需要知道如何使用`dpkg`、`dselect`和`apt-get`命令。其他几个命令也会很有帮助。

## Debian 发行版与惯例

顾名思义，Debian包源于Debian发行版。从那时起，该格式已被其他几个发行版采用，包括`Ubuntu`、`Linux Mint`和`Xandros`。这些发行版源自原始的Debian，这意味着来自原始Debian的包可能可以在其他基于Debian的系统中运行。尽管Debian不强调花哨的GUI配置工具，但它的派生版本往往更以界面为中心，这使得这些发行版对Linux初学者更有吸引力。原始Debian倾向于一个尽可能自由的系统，并尝试严格遵守开源软件原则，而不是将精力投入到GUI配置工具上。原始Debian的独特之处在于，它不是由任何受利润驱动的公司维护，而是由渴望构建自己想要使用的产品的志愿者们维护的。

与RPM一样，Debian包在操作系统和CPU类型方面是中性的。尽管人们曾尝试在非Linux内核上使用Debian包系统和软件库的各种系统，但这些尝试大多已被放弃，除了`kFreeBSD`(`www.debian.org/ports/kfreebsd-gnu/`)之外。

原始Debian已移植到许多不同的CPU，包括`x86`、`x86-64`、`IA-64`、`ARM`、`PowerPC`、`Alpha`、`680x0`、`MIPS`和`SPARC`。原始架构是`x86`，随后的移植处于不同的成熟水平。派生发行版通常只运行在`x86`或`x86-64`系统上，但未来可能会发生变化。

Debian包遵循与RPM类似的命名惯例，但Debian包有时会在文件名中省略指定包架构的代码，特别是对于`x86`包。当这些代码存在时，它们可能与RPM惯例不同。例如，以`i3386.deb`结尾的文件表示`x86`二进制文件，`powerpc.deb`是`PowerPC`二进制文件，而`all.deb`表示CPU无关的包（如文档或脚本）。与RPM文件一样，这种文件名惯例仅仅是一个惯例。你可以根据自己的需要重命名文件，包含或省略处理器代码。Debian源码包没有代码，因为正如接下来的章节“Debian包与其他软件包格式的比较”所示，Debian源码包由单独的文件组成。

## dpkg 命令集

Debian包与RPM包不兼容，但基本操作原理在软件包类型之间是相同的。RPM和Debian包都包含依赖信息，且Debian包实用程序维护着一个已安装软件包、文件等的数据库。你使用`dpkg`命令来安装Debian包。该命令的语法与`rpm`类似：

```
dpkg [options][action] [package-files|package-name]
```

`action`是要执行的操作；常用操作总结在表 2.4 中。选项（表 2.5）修改操作的行为，类似于`rpm`的选项。

**表 2.4** `dpkg` 主要操作

| 操作 | 描述 |
| :--- | :--- |
| `-i`或`--install` | 安装软件包 |
| `--configure` | 重新配置已安装的包：运行安装后脚本以设置特定特定的选项 |
| `-r`或`--remove` | 移除软件包但保留配置文件 |
| `-P`或`--purge` | 移除软件包，包括配置文件 |
| `--get-selections` | 显示当前安装的软件包 |
| `-p`或`--print-avail` | 显示已安装包的信息 |
| `-I`或`--info` | 显示未安装包文件的信息 |
| `-l pattern`或`--list pattern` | 列出所有名称匹配模式的已安装包 |
| `-L`或`--listfiles` | 列出与包相关的已安装文件 |
| `-S pattern`或`--search` | 查找拥有搜索模式指定的文件（包） |
| `-C`或`--audit` | 搜索部分安装的包并建议如何处理它们 |

**表 2.5** 用于微调 `dpkg` 操作的选项

| 选项 | 配合操作使用 | 描述 |
| :--- | :--- | :--- |
| `--root=dir` | 所有 | 修改根目录。可用于安装到根目录。 |
| `-B`或`--auto-configure` | 所有 | 禁用自动配置。 |
| `--force-conflicts` | 所有 | 覆盖会导致`dpkg`中止的冲突。 |
| `--ignore-depends` | 所有 | 忽略指定包的依赖。 |
| `--recursive` | 所有 | 检查依赖、冲突和其他问题。 |
| `-G` | 所有 | 安装所有匹配的包。 |
| `-E`或`--skip-version` | 所有 | 如果已安装更高版本则不安装该包。 |
