## MIME--多用途邮件扩展

*by Robin Burk*

HTML是全球维度网的基础，但它只是使Web成为可能的标准数据类型之一。在本章中，我们将查看Web和程序用于桥接不同操作系统和硬件平台的更广泛的数据格式。

本章涵盖的主题包括：

- MIME如何成为互联网标准
- 常见的MIME数据类型
- 网页、Web服务器和MIME

（注：此处根据原文要求翻译对应内容）

**提示：** 理解什么是MIME格式以及它是如何产生的，可以帮助你和用户解决解释电子邮件附件或选择浏览器插件时遇到的问题。

### MIME如何成为互联网标准

MIME（多用途邮件扩展）是互联网工程任务组（IETF）定义的互联网协议标准之一。它最初主要与电子邮件相关，但现在已演变为支持网上多媒体应用的重要元素。为了理解MIME及其运行方式，回顾一下它是如何变成今天非常有帮助。

### 互联网标准如何被采纳

IETF是负责提出并采用公共互联网支持的通信协议、数据格式及类似规范的官方机构。例如，所有熟悉的互联网通信协议（如`TCP`、`IP`、`PPP`和`SLIP`）都由IETF的的“请求意见”（RFC）文档正式定义。IETF还定义了简单邮件传输协议（`SMTP`）、网络时间协议（`NTP`），以及支持交互式会议的新多媒体协议，如资源预留协议（`RSVP`）和实时传输协议（`RTP`）。

并非所有被 IETF 采纳的 RFC 都能成为互联网标准。那些提用于标准轨道（standards track）的 RFC 通常由一个或多个工业界或学术界的人提交互联网草案（Internet Drafts）开始。互联网草案必须在发布后六个月内提升到 RFC 状态，否则将被移除考虑范围。

一旦提升到 RFC 状态，拟议的协议将开放征求意见，并可能根据技术社区的反馈被修订后的版本所取代。任何感兴趣的方都可以通过在线或面对面会议参与讨论。每份 RFC 都会由 IETF 的一个特定工作组（Working Group）进行引导和辩论。工作组定期召开会议，以敲定拟议协议的细节。

有些 RFC 并不打算被采纳为互联网标准。少数 RFC 包含了关于特定技术场景或标准制定过程本身的注释或信息。其他信息性 RFC（informational RFC）详细定义了协议，但并未提议将其为标准，因为它们是由一家公司开发的，该公司公司选择保留对其演进的控制。描述 Sun 网络文件系统（`NFS`）连续版本的 RFC 就属于此类。通过通过发布 NFS 协议的定义，Sun 允许并鼓励其他供应商在自己的操作系统中支持 NFS。通过这种方式，`NFS` 已成为了一种*事实上的*（de facto）而非官方的互联网标准。

最后，某些 RFC 被指定为实验性的（experimental，供限范围实施以评估其有效性）或历史性的（historical，曾使用，现已实际上被替代协议所取代）。

官方标准并不要求所有互联网服务器或客户端系统都采纳。标准可能属于以下几类：

- 强制性（Required）——所有系统必须实现此协议。互联网协议（`IP`）和相关的互联网控制消息协议（`ICMP`）是所有直接连接到公网的系统的强制标准协议。
- 推荐性（Recommended）——除非有强有理由这样做，否则所有系统都应实现此协议。传输控制协议（`TCP`）、文件传输协议（`FTP`）和 `Telnet` 是互联网的一些推荐标准协议。
- 可选性（Elective）——任何要实现此类内容的系统都必须按照 RFC 进行。例如，`MIME` 是互联网的一种可选性标准协议。
- 局限使用（Limited Use）——由于协议的实验性、历史性或专门性，这些协议的使用仅限于特殊情况。
- 不推荐（Not Recommended）——由于其功能有限、专门性或实验性或历史状态，不建议通用使用这些协议。
