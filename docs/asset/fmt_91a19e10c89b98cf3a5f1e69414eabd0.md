添加 `-x` 选项（没有前导连字符）会告诉 `ps` 显示我们所有的进程，无论它们由什么种终端（如果有的话）控制。列中出现 `?` 表示没有控制终端。使用此选项，我们可以看到一个由我们拥有的进程列表。

由于系统正在运行许多进程，`ps` 会生成一个列表。将 `ps` 的输出通过到 `less` 中以便于查看通常是有帮助的。某些选项组合会产生很长的输出行，因此将终端模拟器窗口最大化也是个好主意。

输出中增加了一个新列 `STAT`。`STAT` 用于进程的状态和当前状态，如表 10-1所示。

## 表 10-1: 进程状态

| 状态 | 含义 |
| --- | --- |
| R | Running（运行）。这意味着进程正在运行或准备就绪运行。 |
| S | Sleeping（睡眠）。进程没有在运行；它正在等待某个事件，例如键入或网络包。 |
| D | Uninterruptible sleep（不可中断睡眠）。进程正在等待 I/O，例如磁盘驱动器。 |
| T | Stopped（已停止）。进程已被指示停止。你将在本章后面学习更多信息。 |
| Z | A defunct or "zombie" process（僵尸或死亡进程）。这是一个已终止但尚未被父进程清理的子进程。 |
| < | 高优先级进程。可以赋予进程更高的重要性，为其分配更多的 CPU 时间。进程的这种属性被称为 niceness（nice性值）。高优先级进程被认为“不那么 nice”，因为它占用了更多的 CPU 时间，留给其他人的时间就更少了。 |
| N | 低优先级进程。低优先级的进程（一个 nice 属性较高的进程）只有在其他高优先级进程处理完后才能获得处理器时间。 |

状态后面可能跟着其他字符。这些字符表示各种奇特的进程特性。更多信息请参阅 `ps` 的 `man` page。另一个常用的选项组合是 `aux`（没有前导连字符）。这为我们提供了更多信息。

```
[me@linuxbox ~]$ ps aux

root 1 0.0 0.0 2136 ? Ss Mar05 0:31 init
root 2 0.0 0.0 0 ? S Mar05 0:00 [kt]
root 3 0.0 0.0 0 ? S Mar05 0:00 [mi]
root 4 0.0 0.0 0 ? S Mar05 0:00 [ks]
root 5 0.0 0.0 0 ? S Mar05 0:06 [wa]
root 6 0.0 0.0 0 ? S Mar05 0:36 [ev]
root 7 0.0 0.0 0 ? S Mar05 0:00 [kh]

```

这组选项显示每个用户的进程。使用不带前导连字符的选项会以“BSD 风格”调用命令。Linux 版本的 `ps` 程序在几个不同的 Unix 实现中都存在。通过这些选项，我们得到了表 10-2 所示的额外列。

## 表 10-2: BSD ps 列表头

| 表头 | 含义 |
| --- | --- |
| USER | 用户 ID。这是进程的所有者。 |
| %CPU | CPU 使用百分比。 |
| %MEM | 内存使用百分比。 |
| VSZ | 虚拟内存大小。 |
| RSS | 驻存集大小。这是进程正在使用的物理内存（RAM）量，单位为千字节。 |
| START | 进程启动的时间。对于超过 24 小时的值，使用日期。 |

## 使用 top 动态查看进程

虽然 `ps` 命令可以揭示很多机器正在做什么，但它只提供了 `ps` 命令执行瞬间机器状态的快照。要查看机器活动更动态的视图，请使用 `top` 命令。

```
[me@linuxbox ~]$ top
```

`top` 程序显示按活动顺序列出的系统进程，并持续更新（默认每秒更新一次）。`top` 这个名字源于该程序用于查看系统中的“顶端”进程。`top` 显示由两部分组成：显示顶部的摘要，随后是按 CPU 排序的进程表格。
