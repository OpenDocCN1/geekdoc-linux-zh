
当嵌入式 Linux 设备供电时，硬件会经历一系列事件，最后使处理器处于某种重置状态。当硬件将处理器从重置状态释放时，它开始从一个已知位置执行指令。这些指令通常存储在 ROM 或闪存内存中。在 PC 上，这些指令被称为 BIOS。BIOS 代码负责让 PC 上的硬件为操作系统做好准备。在这一设置过程的一部分，早期 BIOS 会执行许多低级操作，例如启用 L1 和 L2 缓存、检测安装了多少内存以及设置 RAM 刷新。如果你正在编写这些代码，你将深埋于你的处理器、处理器的支持芯片组以及你正在设置的设备的手书中。在完成初始芯片组和硬件初始化后，BIOS 将内核（或内核加载器）加载到内存并开始运行。在 PC 上，一旦 Linux 运行，它通常会忽略 BIOS，因此在本书中，我们将忽略 Microsoft Windows 等其他操作系统使用但被 Linux 忽略的所有 BIOS 功能。Linux 也运行在许多架构上，如 ARM、MIPS、PowerPC 等，我们并不使用 PC BIOS。通常，这些其他架构具有特定特定的低级启动程序（如 PCBIOS、OpenFirmware、RedBoot 等），提供了类似于 PC BIOS 提供的功能。在本书的剩余部分，我们将这种启动代码称为“BIOS”，但理解我们实际上是在讨论适用于该架构的程序。

## 内核加载器

内核加载器是一个小型程序，它对操作系统规则和质存储布局的理解比 BIOS 更深。因此，它可以加载并启动操作系统。在运行 Red Hat、SuSe 或 Debian 等标准 Linux 桌面发行版的 x86 PC 上，像 `LILO` 或 `GRUB` 等内核加载器管理内核。对于基于 x86 的嵌入式应用，`syslinux` 也运行良好。

对于非 x86 架构，可能需要 `MILO` 等其他引导加载器。如果你从头编写 BIOS，或者使用专门为内存中 Linux 设计的系统，内核加载器可能直接集成到 BIOS 中。无论在你的特定平台上是如何实现的，在内核加载器完成工作后，内核位于内存中，加载器会跳转到内核。

## 内核

内核加载加载器跳转到 Linux 内核之后，内核开始初始化自身及其所有编译的驱动程序。如果计算机连接了显示器（或启用了串口控制台），内核查找的第一内容内容所示：

```
Linux version 2.2.18-20 (root@porky.devel.redhat.com)
(gcc version egcs-2.91.66+19990314/Linux (egcs-1.1.2 release)) #f1
Mon Nov 23 10:25:54 EDT 2000
```

此列表给出了 Linux 内核版本、编译该内核的用户和机器、编译器版本以及内核编译细节（细节之多，以至于我们在上面不得不将其分成三行）。接下来是关于内核启动过程的大量信息。每个编译的驱动程序通常都会打印一些关于自身的信息。在内核完全初始化后，计算机终于准备好运行嵌入式应用程序。

在 Linux 中（在任何版本的 UNIX 中），可以运行的软件可以是内核代码或用户进程。如果处理器具有内存管理单元（MMU），用户代码的运行权限级别低于内核代码，这防止了它执行可能导致计算机崩溃的操作。Linux 也可以运行在没有 MMU 的计算机上（使用内核补丁）。在这些情况下，没有权限差异的概念——所有代码都像内核代码一样运行，并具有导致机器崩溃的。虽然这可能使调试变得比常困难，但不应该阻碍开发者考虑成本较低的无 MMU 处理器。由于用户通常不会在他们的嵌入式设备上放置任意软件（就像他们在 PC 上所做那样），嵌入式设备更容易崩溃。软件是由嵌入式系统设计人员放置的，并且经过了良好的测试。

嵌入式应用程序通常包含一个或多个用户级应用程序，其中第一个被称为 `init`。在列表 4.1 位于 `/usr/src/linux/init/main.c` 的内核代码中，程序不必非称为 `init`；你可以从引导加载器向内核传递 `init=/some_program` 命令行参数，并在启动时指定该程序。

### 什么是 LinuxBIOS？

我们正致力于制作自己的 BIOS。换句话说，我们计划将主板 NVRAM 中的 BIOS 替换为 Linux 镜像，并且在启动启动时不运行 BIOS，而是运行 Linux。我们这样做有几个原因：

- 我们初始化集群节点，使其按照它们应该启动方式（无盘、本地磁盘、重载等）进入和退出。虽然有一个标准（来自英特的 `PXE`），但它有很多局限性。

- 到目前为止，BIOS 最重要的功能是支持像 DOS 这样的过时代码。Linux 等现代操作系统完全不需要 BIOS 的功能。尽管如此，许多 BIOS 在为 Linux 等系统配置 PCI 总线方面表现不佳。将 BIOS 替换为 Linux 可以实现更快的重启和更好的系统配置。

- NVRAM 可以写入我们最常用的内核。我们可以设想在 10 毫秒左右启动 Linux——这是一个非常有吸引的想法。

### 它是如何工作的？

1. 当 PC 进入 `RESET` 状态时，它开始从位置 `0xfff0` 处执行指令。此时，Pentium 正在模拟一个 20 年份的微处理器 16 位的 8086。该地址位于 NVRAM 中。我们将用 LinuxBIOS 的存根重写 NVRAM。

2. 我们初始化芯片组使中断正常工作，并开启 DRAM。

3. 一旦有了 DRAM，我们就会开启 `GDT` 并跳转到 32 位汇编代码。

4. 32 位汇编代码执行更多工作，并跳转到 C。

5. 代码很短：它将 Linux 镜像从 NVRAM 解压缩到 RAM 中并跳转到那里。
