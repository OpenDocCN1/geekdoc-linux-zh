### 进程信息
- `r`：等待中可运行的进程数
- `b`：阻塞的进程数（不可中断状态）

### 内存信息（单位：千字节）
- `swpd`：使用的虚拟内存
- `free`：用作缓冲的空闲内存
- `buff`：用作缓存的内存

- `si`：从磁盘换入的内存
- `so`：交换到磁盘的内存

### 系统 I/O 活动（单位：每秒块）
- `bi`：从块设备接收的块
- `bo`：发送到块设备的块

### 系统活动
- `in`：每秒中断数
- `cs`：上下文切换

### CPU 时间百分比
- `us`：用户（非内核）
- `sy`：系统（内核）
- `id`：空闲
- `wa`：等待 I/O

# parted：报告硬盘分区

`parted`（分区编辑器）工具报告并操作硬盘分区。以下示例显示了如何使用命令行。它使用 `print` 命令显示 `/dev/hda` 驱动器的分区信息：

```
$ parted /dev/hda print

Disk label type: msdos

Number  Start   End     Size    Type      File system  Flags
 1      32kB    1045MB  1045MB  primary   ext3         boot
 2      1045MB  12GB    10GB    primary   ext3
 3      12GB    22GB    10GB    primary   ext3
 4      22GB    165GB   143GB   extended
 5      23GB    41GB    18GB    logical   linux-swap
 6      41GB    82GB    41GB    logical   ext3
 7      82GB    165GB   83GB    logical   ext3
```

信息：如有必要，不要忘记更新 `/etc/fstab`。

# 图 17-5 示例中的主分区和扩展分区

图 17-5 展示了示例所示的分区。`parted` 显示的第一行指定了正在报告的设备 (`/dev/hda`) 及其大小（165 吉字节）。`print` 命令显示以下列：

- **Number**：存放分区的设备的次设备号。这与设备名称中的数字相同。在示例中，5 对应 `/dev/hda5`。
- **Start**：分区开始的磁盘位置。`parted` 工具将磁盘上的位置指定为从磁盘起始处的距离。因此，分区 3 从磁盘起始处 12 吉字节处开始。
- **End**：分区停止的磁盘位置。虽然分区 2 在磁盘起始处 12 吉字节结束，分区 3 在相同位置开始，但 `parted` 确保分区不会在该字节处发生重叠。
- **Size**：分区的大小，单位为千字节 (kB)、兆字节 (MB) 或吉字节 (GB)。
- **Type**：分区类型：主、扩展或逻辑。关于分区的更多信息请参见图 17-5 和第 31 页。
- **File system**：文件系统类型：ext2、ext3、fat32、linux-swap 等。文件系统类型列表请参见第 570 页的表 13-1。
- **Flags**：为分区开启的标志，包括 `boot`、`raid` 和 `lvm`。在示例中，分区 1 是可启动的。

除了报告硬盘的布局和大小外，你还可以交互式地使用 `parted` 来修改磁盘布局。在这种方式使用时要极其小心，并在开始使用此工具之前务必始终备份系统。更改磁盘上的分区信息（分区表）可能会破坏磁盘上的信息。在尝试修改分区表之前，请阅读 info 页面。

## parted 可能会破坏一切

使用 `parted` 时要像对待包含大量数据的工具一样小心。使用 `parted` 进行的更改很容易导致大量数据丢失。如果你正在使用 `parted` 并且对你正在进行的操作有任何疑问，请在做出更改之前使用 `q` 命令退出。如果你给了 `parted` 命令，它会立即执行你请求的更改。

要对磁盘进行分区，请输入 `parted` 命令以及你要操作的设备名称。在以下示例中，启动后用户输入 `help`（或直接 `h`）命令，这将显示 `parted` 命令列表：

响应 `(parted)` 提示符，输入 `help` 命令并后跟你想获取更多信息的命令名称。当你输入 `print`（或只需 `p`）命令时，`parted` 会显示当前分区信息，就像在命令行上执行 `print` 命令一样。

`parted` 工具允许你设置重叠分区（逻辑分区与扩展分区重叠除外）。同样，它不会允许你创建一个从磁盘最开始（磁道 0）开始的分区。这两种情况都可能导致数据丢失。

在为磁盘定义分区表时需要记住的指南。更多信息，请参阅第 31 页的“磁盘分区”。

- 不要删除或修改定义扩展分区的分区，除非你愿意丢失扩展分区内所有逻辑分区的数据。
- 如果你将 `/boot` 放在单独的分区上，最好将其放在驱动器的开头（分区 1），这样就不会出现 Linux 从离驱动器太远的分区启动的问题。
- 当你有足够的磁盘空间时，最好将每个主要文件系统放在单独的分区上。许多人选择将 `/`、`/var` 和 `/usr` 合并为一个分区，这通常会产生更少的浪费空间，但可能会导致问题。
- 虽然 `parted` 可以创建某些类型的文件系统，但最好的方法是使用 `parted` 创建分区，然后使用 `mkfs` 和 `mkswap` 在分区上创建文件系统。

## 保持用户知情

作为系统管理员，你的主要职责之一是与用户通信。你需要发布公告，例如系统何时进行维护、何时举行软件课程以及用户如何访问新系统。

不同的通信有不同的优先级。例如，两个月后的公司聚餐的信息没有你将在五分钟后关机的信息那么敏感。为了满足这些需求，Linux 提供了多种通信方式。下表描述并对比了这些常用方法。所有方法通常对所有人可用，每日消息通常留给具有 root 权限的用户。

使用 `write` 工具与登录本地系统的用户进行通信。你可能会使用它，例如要求用户停止一个运行缓慢的程序；用户可能会回复几分钟内完成。用户还可以使用 `write` 请求系统管理员挂载磁带或恢复文件。来自 `write` 的消息可能在图形环境中无法显示。

`wall`（write all）工具可以有效地与所有登录用户进行实时通信。该工具从标准输入获取输入，工作方式与 `write` 类似，但用户无法使用 `write` 只写回给你。当你准备关闭系统或处于其他危机情况时，请使用 `wall`。未登录的用户不会收到消息。

电子邮件适用于向一个或多个系统和远程用户发送紧急信息。当你发送邮件时，他们会等候它来阅读。电子邮件适用于提醒用户他们忘记注销、账单过期或占用过多磁盘空间。

用户可以轻松地对通过电子邮件收到的消息制作永久记录，而通过 `write` 接收的消息则不然，这样他们就可以记录重要的细节。例如，使用电子邮件告知用户一项新的、复杂的程序是恰当的，这样每个用户都可以保留该信息的副本供参考。

# 每日消息

用户每次在文本环境中登录时都会看到每日消息，但在打开终端模拟器窗口时不会看到。你可以根据需要编辑 `/etc/motd` 文件来更改此消息。每日消息可以提醒用户即将到来的维护、新系统功能或流程的变更。

## 产生问题

即使是经验丰富的系统管理员也会犯错；而新系统管理员只会犯更多错。虽然通过仔细阅读并遵循软件附带文档可以增加避免问题的概率，但许多事情仍然会出错。无论列表多长，详尽列表是不可能的，因为每天都会发现新的、令人有趣的产生问题方法。本节描述了一些较为常见的技巧。

### 未能定期备份

比起信息丢失，情绪波动对系统来说更加痛苦。如果本地系统支持多用户，拥有最近的备份可能是你免受“公共午餐”风险的保护。如果是单用户系统，在丢失硬盘或误删文件时，拥有备份无疑会让你心情愉快。

### 未阅读并遵循说明

软件开发者编写文档是有原因的。即使你以前安装过某个软件包，也请仔细阅读说明。它们可能已经发生了变化，或者你可能只是记忆有误。软件的变化速度比书籍修订的速度快，因此任何书籍都不应被视为万无一失的建议。相反，请在网上查找最新文档。`/usr/share/doc` 目录包含许多工具、库和软件包的信息。

### 在说明不明确时未能寻求帮助

如果某些事情说不通，请尝试找出符合逻辑的部分——不要尝试猜测。参见附录 B，获取可以找到帮助的地方列表。

### 在关键文件中删除或输错信息

导致自己出错的一种方法是执行命令：

```bash
$ rm -rf /etc/  # 不要这样做
```

可能没有其他什么命令会让一个 Linux 系统变得如此毫无用处。唯一的解决办法是使用安装光盘重启到恢复模式，并从最近的备份中恢复丢失的文件。这个示例描述了一个极端情况，即文件对系统的正常运行至关重要。删除其中任何一个文件或在其中输入错误信息几乎肯定会导致问题。例如，如果你直接编辑 `/etc/passwd`，在某个字段中输入错误信息可能会导致一个或多个用户无法登录。不要对包含通配符的参数使用 `rm -rf`；请在输入命令后停顿，并在按下回车键之前检查它。仔细检查你所做的一切，并在编辑关键文件之前对其进行复制。

### 在使用 rm 使用通配符时要小心

注意：当你必须在 `rm` 命令的参数中使用通配符（如 `*`）时，请先使用相同参数的 `echo` 命令来查看确切是哪些文件将被删除。当你以 root 权限工作时，这种检查尤为重要。

## 解决问题

作为系统管理员，保持系统安全和运行良好是你的责任。当用户遇到问题时，通常由管理员来帮助用户回到正轨。本节建议了让用户满意并让系统处于峰值性能的方法。

## 用户无法登录时提供帮助
