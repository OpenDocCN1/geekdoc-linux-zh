
使用所示命令，Janet 将目录的组所有者设为 `music`，然后使用 `chmod` 将 `setgid` 设置为 `2775`。这设置 `setgid` 以导致目录中的所有文件继承目录的组所有权。但我们也可以通过符号方法 `chmod 2775,g+` 完成同样的操作。

但我们仍然有一个问题。系统的默认 `umask` 是 `0022`，这阻止了组成员向组内其他成员写入文件。如果共享目录只包含文件，这不是问题，但由于此目录将存储音乐，而音乐通常按艺术家和专辑的层级结构组织，组成员需要在其他成员创建的目录内部创建文件和目录。我们需要将 janet 和 tony 使用的 `umask` 改为 `0002`。
Janet 将 `umask` 设为 `0002` 并创建了新文件和目录：

```
[janet@linuxbox ~$] umask 0002
[janet@linuxbox ~$] cd /usr/local/share/Music/test_file
[janet@linuxbox ~$] mkdir /usr/local/share/Music/test_dir
[janet@linuxbox ~$] ls -l /usr/local/share/Music
drwxr-xr-x 2 janet music 4096 2025-03-24 20:24 test_dir
-rw-rw-r-- 1 janet music 0 2025-03-24 20:22 test_file
```

## 进程是如何工作的

当系统启动时，内核会将若干活动作为进程启动，并启动一个名为 `init` 的程序。`init` 随后启动 `systemd`，再由 `systemd` 启动所有系统服务。在 Linux 发行版中，`init` 运行一系列位于 `/etc` 中的 shell 脚本（称为 init 脚本）来执行类似的功能。许多系统被实现为守护程序，它们在后台运行，没有任何用户界面即可完成自己的工作。因此，如果我们没有登录，系统至少在忙于执行例行任务。

程序可以启动其他进程的事实是在进程体系中表示为父进程产生子进程。

内核维护关于每个进程的信息以帮助组织结构。例如，每个进程都被分配有一个数字，称为进程 ID `PID`。`PID` 按升顺序分配，其中 `init` 获得 `PID 1`。内核跟踪分配给每个进程的内存，以及进程恢复执行的就绪状态。像文件一样，进程也有所有者和 UID、有效 UID 等。

## 查看进程

查看进程最常用的工具（其实有几个）是 `ps` 命令。`ps` 程序有很多选项，但在最简单的形式下，它的用法如下：

```
PID TTY TIME CMD
5198 pts/1 00:00:00 bash
1029 pts/1 00:00:00 ps
```

此列表列出了两个进程，进程 `5198` 和 `1029`，分别是 `bash` 和 `ps`。正如我们所看到的，默认情况下，`ps` 不显示很多与当前终端会话相关的进程。要查看更多信息，我们需要添加一些选项，但在在此之前，让我们看看 `ps` 产生的其他字段。`TTY` 是 "teletype"电打字）的缩写，指的是控制终端。`TIME` 字段是进程消耗的 CPU 时间。正如我们所看到的，这两个进程都没有让计算机高负载运行。

如果我们添加一个选项，就可以很好地了解系统正在做什么。

```
PID TTY STAT COMMAND

2820 ? Sl 00:01 /usr/libexec/evolution-data-server-1.10 --
15647 ? Ss 00:00 /bin/sh /usr/bin/startkd
15751 ? Ss 00:00 /usr/bin/ssh-agent /usr/bin/dbus-launch -
15754 ? S 00:00 /usr/bin/dbus-launch --exit-with-session
15755 ? Ss 00:01 /usr/bin/dbus-daemon --print-pid 4 -pr
15774 ? Ss 00:02 /usr/bin/gpg-agent -s -daemon
15793 ? S 0:00 start_kdeinit --new-startup +kminit_start
15794 ? S 0:00 kdeinit Running...
15797 ? S 0:00 dcserver -nosid
以及许多更多...
```

添加选项 `ps`（注意没有前导横杠）来显示我们所有的进程，无论它们被哪个终端（如果有）控制。`TTY` 列中出现 `?` 表示没有控制终端。通过这一点，我们可以看到我们拥有的每一个进程的列表。

由于系统运行着许多进程，`ps` 会产生一个列表。将 `ps` 的输出通过到 `less` 以于查看通常很有帮助。某些选项组合会产生长输出，因此最大化终端模拟器窗口可能也是好主意。

输出中添加了一个新列 `stat`。`stat` 是 “state”（状态）的缩写，显示了进程的当前状态，如表 10-1 所示。

### 表 10-1：进程状态

| 状态 | 含义 |
| --- | --- |
| R | Running（运行中）。这意味着进程正在运行或准备好运行。 |
| S | Sleeping（睡眠中）。进程没有运行；它在等待某个事件，例如按键或网络包。 |
| D | Uninterruptible sleep（不可中断睡眠）。进程等待 I/O，例如磁盘驱动器。 |
| T | Stopped（停止）。进程已被指示停止。在本章后面会详细介绍。 |
| Z | 死亡或“僵尸”进程。这是一个已终止但尚未被父进程清理的子进程。 |
| < | 高优先级进程。可以赋予进程更高的重要性，从而获得更多的 CPU 时间。进程的这种属性称为 nice（nice值）。高优先级的进程被认为“不 nice”，因为它占用了更多的 CPU 时间，为其他人留下的时间更更少。 |
| N | 低优先级进程。低优先级的进程（nice 进程）将在其他高优先级的进程处理完后获得处理器时间。 |

进程状态后面可能会紧跟其他字符。这些字符表示各种奇特的进程特性。更多细节请参见 `ps` 的 man 页。

## 控制进程

现在我们可以监控进程了，让我们对它们进行一些控制。在我们的实验中，我们将使用一个名为 `xlogo` 的小程序作为“实验小白鼠”。`xlogo` 程序是 X Window 系统 提供的一个示例程序（它是在我们显示器上生成图形的底层引擎，尽管它正逐渐被 Wayland 取而代之），它只是显示一个包含 X 标志的可调整大小的窗口。首先，我们将认识我们的测试对象。

```
@linuxbox -js xlogo
```

输入命令后，一个包含标志的小窗口应该出现在屏幕某个地方（图 10-1）。在某些系统中，`xlogo` 可能会打印警告消息，但可以安全地忽略。

图 10-1：`xlogo` 程序

> 注意
> 如果你的系统没有包含 `xlogo` 程序，请尝试使用 `edit` 或 `kwrite`。

我们可以通过调整其窗口大小来验证 `xlogo` 是否正在运行。如果标志按新大小重绘，则程序正在运行。

注意到我们的 shell 提示符还没有返回？这是因为 shell 在等待程序结束，就像我们目前为止使用的所有其他程序一样。如果我们关闭 `xlogo` 窗口，提示符就会返回。

## 中断进程

让我们观察再次运行 `xlogo` 时会发生什么。首先，输入 `xlogo` 命令并验证程序正在运行。接下来，返回终端窗口并按下 `CTRL-C`。

```
@linuxbox -js xlogo
@linuxbox -js
```

在终端中，按下 `CTRL-C` 会中断程序。这意味着我们正在礼貌地请求程序终止。在我们按下 `CTRL-C` 后，`xlogo` 窗口关闭，shell 提示符返回。

许多（但不是所有）命令行程序都可以通过这种技术被中断。

## 将进程放入后台

假设我们想在不终止 `xlogo` 程序的情况下取回 shell 提示符。我们可以通过将程序放在后台来实现。将终端想象为有前台（表面可见的内容，如 shell 提示符）和后台（表面背后隐藏的内容）。要启动一个程序使其立即置于后台，我们在命令后面加上一个安培符 `&` 字符。

```
@linuxbox -S xlogo &
[1] 28236
@linuxbox -JS
```

输入命令后，`xlogo` 窗口出现，shell 提示符返回，但打印了一些奇怪的数字。这条消息是 shell 作业控制功能的一部分。通过这条消息，shell 告诉我们已经启动了作业 1 (`[1]`)，它的 PID 为 `28236`。如果我们运行 `ps`，就可以看到该进程。

```
@linuxbox -S ps
PID TTY CMD
10603 pts/1 00:00:00 bash
28236 pts/1 00:00:00 xlogo
28239 pts/1 00:00:00 ps
```

shell 的作业控制设施为我们提供了列出从终端启动的作业的方法。使用该命令，我们可以看到：

```
@linuxbox -JS jobs
[1]+ Running xlogo &
```

结果显示我们有一个编号为 1 的作业，它正在运行，且命令是 `xlogo &`。注意，我们可以通过这里的快捷方式将多个命令放入后台：

```
@linuxbox:-$ xlogo & edit &
[1] 47211
[2] 47212
```

## 将进程返回前台

在后台运行的进程对终端键盘输入是免疫的，包括任何尝试用 `CTRL-C` 中断它的尝试。要将进程返回前台，按如下方式使用 `fg` 命令：

```
@linuxbox -JS jobs
[1]+ Running xlogo &
@linuxbox -JS fg %1
```
