
名称跟踪的主要原因之一是 Korn shell 考虑了 `PATH` 变量中的搜索路径可能包含当前目录 `(.)`。如果你切换了目录，之前可用的命令可能会变得不可用，或者可能需要通过不同的路径名访问。跟踪跟踪与 `cd` 命令交互以保持跟踪别名的完整路径名。换句话说，当你在目录之间切换并创建、删除或移动可执行文件时，跟踪跟踪会跟踪命令的正确路径名。你可以使用 `set` 命令来开启或关闭跟踪跟踪。

```
set -o trackall
```

强制 shell 跟踪你使用的每一个命令，而

```bash
set o trackall
```
将关闭跟踪功能。

## Shell 选项

由于 Korn 是一个相当复杂的程序，它处理许多可以通过两种或两种多种方式解决的人机交互问题。为了帮助你以最方便的方式使用 shell，shell 允许你通过设置选项（options）来选择它的行为。

你可以通过两种方式设置 Korn 选项：在调用 shell 时使用 `ksh` 命令，以及在启动 shell 后在其内部使用 `set` 命令。你未指定的选项将采用默认值。因此，除非你有意图，否则你永远不需要操心选项的设置。

`ksh` 命令通常由 UNIX 登录进程代表你调用，并使用 `/etc/passwd` 文件中的模板作为登录名。系统管理员会为每个条目构造密码，除非他非常忙或者心肠很小；他会乐意调整你的密码，以便以你偏好的设置启动 shell。当然，你可以随时使用此命令将你的登录 shell 替换为 Korn shell：

```bash
$ exec ksh options ...
```

你在学习 Bourne shell 时遇到的 `exec` 语句在 Korn shell 中具有相同的作用。它用其第一个参数命名的命令替换当前的 shell——通常通常也是一个 shell，但可能是不同的类型，或者带有不同的选项和参数。

`ksh` 命令的语法如下：

`ksh [+/-aefkmnpstuvx-] [-cirs] [+/-o option] ... +/-A name] [arg ...]`

`-c`、`-i`、`-r` 和 `-s` 选项只能在 `ksh` 命令行指定。所有其他选项也可以在命令中指定。

### 仅在 ksh 命令行中指定的选项

| 选项 | 指定内容 | 描述 |
|---|---|---|
| `-c` | 命令 | 第一个（也是唯一的）参数是一个命令。`-c` 选项防止 shell 尝试从任何其他源读取命令。它仅仅执行作为参数给定的命令然后退出。这通常不会从键盘或 shell 脚本中频繁使用。它通常由 C 语言编写的程序内部使用。 |
| `-i` | 交互式 shell | 强制 shell 的行为就像输入和输出是一个终端。通常，你不需要显式地指定 `-i` 选项。它的主要目的是防止由 shell 调用的命令异常终止导致 shell 本身终止。 |

### 受限 shell

Korn 以受限 shell 模式运行，防止用户使用 `cd` 命令、修改 `PATH`、重定向输出以及通过全路径调用命令。此选项仅对系统管理员设置特殊用户账户感兴趣。如果调用的是其名称的第一个字符或 `r`，Korn 也会作为受限 shell 启动。（例如，复制或使用链接到 ksh，然后运行 `rsh` 的结果与 `ksh -r` 相同）。`rsh` 形式存在是因为，如果 `ksh` 在密码数据库 `/etc/passwd` 中定义为登录 shell，则无法保证 `ksh -r` 一运行受限 shell。）

### 标准输入

Korn 不激活选项 `-i` 提供的防止异常终止的保护。shell 从标准输入读取直到遇到文件结束符（EOF），然后正常结束。这是一个方便的选项，因为允许你将一组命令流通过管道传递给 shell 执行。

表 11.4 列出了你可以通过 `ksh` 命令或 `set` 命令指定的选项。你可以按照通常的方式用字母指定选项（例如 `-a`）或通过名称指定（例如 `-o allextport`）。任何选项都可以显式地或通过 `+` 标志关闭，如 `+a` 或 `+o allextport`。

| `nolog` | 禁止在命令历史记录文件中存储函数。 |
| `vi` | 启用带有行输入的 Vi 编辑模式。输入仅提供 `vi` 命令编辑的部分功能，但其性能比 `viraw` 选项更好。你可以通过 `set +vi` 或 `-emacs` 关闭 Vi 编辑模式。 |
| `viraw` | 启用带有字符输入的 Vi 编辑模式。输入提供了 Vi 编辑模式的所有功能，但开销比 `vi` 选项要大。 |

`-A` 选项可用于 `set` 行或 `set` 命令，以定义一个具有初始值的数组变量。当你指定 `-A` 时，下一个参数必须是数组变量名。后续参数是数组的连续元素，从元素 0 开始。`-A` 选项在赋值之前会重置数组变量的任何之前值。数组的结束值仅由指定为 `arg` 的部分组成。

`+ -A` 从元素 0 开始连续分配 `arg` 值，但它不会重置数组的任何之前值。如果数组之前有 12 个值，通过 `+A` 提供了 6 个值，执行后，数组的前六个元素将是 `arg` 值，后六个值将保留在数组中。

`arg` 值的意义取决于指定的选项。如果指定了 `-A`，值被视为初始数组值。如果指定了 `-s` 或 `-i`，或者因为 shell 是终端导致选项 `-i` 默认开启，则 `arg` 值被用于初始化位置参数 `$1`、 `$2` 等。如果指定了选项 `-c`，第一个 `arg` 被视为要执行的字符串。如果未指定 `-A`、`-c`、`-i` 或 `-s`，第一个 `arg` 被视为要执行的 shell 命令文件名，随后的 `arg` 值在文件执行期间被临时设置为位置参数 `$1`、 `$2` 等。

## 命令历史记录

命令历史记录和命令编辑是某些相互关联的特性。为了利用命令编辑的所有优势，你需要了解命令历史记录的工作原理。

命令历史记录简单来说就是你输入的命令以编号列表的形式自动记录。该列表保存在你主目录的一个特殊磁盘中，以使其在登录会话与会话之间得以保留。当你登录时，上一个会话的命令历史列表可供参考和使用。新命令会被添加到列表末尾。为了防止列表变得过大，当列表增长到固定大小时，列表开头的最旧命令会被删除。

你不需要执行任何操作来激活命令历史记录功能，也不需要指定其最大尺寸。它的运行完全是自动。如果你决定接受任务，你的任务就是使用该列表让生活变得更轻松。

你可以通过三种方式之一使用命令历史列表：

- 使用 `history` 命令查看历史列表中的命令。当你不确定是否已经执行过某项操作，或者想参考以前命令的语法和操作数时，请使用 `history` 命令。
- 使用 `r` 命令从历史列表中重新提交命令。除了短命令外，使用 `r` 重新提交你之前输入过的命令比再次输入命令要快。`r` 命令提供了几种替代方法来识别历史列表中要重新执行哪条命令。你也可以修改历史列表中的命令并执行修改后的命令。
- 使用 `fc` 命令修改列表中的命令。你可以使用任何文本编辑器编辑选定的命令。默认情况下，Korn 会包含旧的 `ed` 命令，但你可以通过更改 `FCEDIT` 变量的值将默认改为任何文本编辑器。修改后的命令将在离开编辑器后立即执行。

> 注意：使用 `fc` 命令进行命令编辑虽然是历史记录一个方便且实用的功能，但与后面“命令编辑”部分讨论的命令编辑功能不同。

仔细查看这些查看和操作命令历史记录的命令。

### 显示命令历史列表

命令历史显示命令历史列表中的命令。每个命令前面都有一个行号。行号唯一标识历史列表中的每条命令，它是你引用历史列表中特定某行的一种方法——例如：

```
$ history
[122] cd /usr/home/jim/src/payapp/pay001
[123] vi main.c
[124] cc -I../include -o main.c
[125] fgrep include *c | grep '^\$'
[126] vi checkfile.c checkedit.c
[127] lint -I../include checkfile.c >$ errs
[128] vi checkfile.c
[129] cc -I../include -o checks*.c
[130] cp checks /usr/home/jim/bin
```

> 注意：`history` 实际上是 `fc` 命令的别名——具体来说是 `fc -1`。

`history` 命令的完整语法如下：

```
history [first] [last]
```

默认情况下，`fc` 命令会针对选定的行调用文本编辑器并在编辑后重新执行它们。你可以通过表 11.6 所示的选项修改此行为。

### 修改 fc 命令行为的选项

| 选项 | 含义 | 描述 |
|---|---|---|
| `-e` | 编辑器 | 使用 `-e` 选项来覆盖 Korn 的默认编辑器。例如，要使用 `vi` 编辑器修改并重用命令，可以输入 `fc -e vi ...`。使用 `fc -vi ...` 来覆盖默认编辑器。特殊的 `-e` 会抑制编辑器的使用。选定的行将立即执行，没有机会修改。这种形式的 `fc` 命令如 `fc -e-135` 等同于 `r` 命令。当你使用它时，第二个连字符必须是一个独立的单词。命令 `fc -e -135` 会立即重新执行命令历史中的第 135 行，而命令 `fc -e -135` 则尝试使用名为 `-135` 的编辑器来编辑历史列表中最近的命令（该编辑器可能并不存在）。或者，命令 `fc -e-135` 会产生另一种错误，因为 `-e` 不是 `|` 的有效选项。 |
| `-l` | 列表 | 调用选定的行，但不重新执行。命令 `fc -l` 等同于别名 `history`。 |
| `-n` | 数字 | 使用 `-n` 选项抑制打印命令历史之前的行。`-n` 选项仅在与 `-l` 选项结合时才有意义——例如 `fc -nl`。 |
| `-r` | 反转 | `-r` 选项允许按反序打印命令历史。最近输入的命令首先显示，随后的行显示逐渐旧的命令。将 `-r` 选项与 `-l` 选项结合使用——例如 `fc -lr`。 |

## 命令编辑

命令编辑无疑是 Korn shell 包含的最重要的最重要的扩展。它非常节省时间，并让 UNIX 初学者使用起来变得容易得多。

命令编辑的基本思想是允许你使用大多数键盘上的一些常用键在输入时纠正按键错误。

为了将这一基本思想变为现实，Korn shell 必须得到你正在使用的终端的支持。例如，如果你打算退格并重新输入一个字符，如果终端能够执行退格、删除已显示的字符并在原位输入一个新字符，那将非常有帮助。出于这个原因，命令编辑在视频显示终端（VDT）上最有用。作为电打字机的硬拷贝终端不适用于 Korn shell 的命令编辑功能。

Korn shell 支持两种命令编辑样式：**vi 编辑模式**（以 vi 编辑器命名）和 **EMACS 编辑模式**（以 EMACS 命名）。如果你熟悉这些编辑器中的任何一个，就可以开始使用命令编辑。

### 激活命令编辑模式

在使用命令编辑之前，你必须先激活它。在在此之前，Korn shell 的命令行工作方式与 Bourne shell 非常相似：你输入命令行的所有内容都会无差别地作为文本发送，包括控制和功能键。这是一个你可能想要尽快禁用的兼容特性——通常通过在你的登录配置文件中激活命令编辑来实现。

要启用 vi 编辑模式，请输入以下命令行或将其放置在你的配置文件中（参见本章后半部分的“自定义 Korn Shell”）：

```
set -o vi
```

要启用 EMACS 编辑模式，请输入以下命令行或将其放置在你的配置文件中：

```
set -o emacs
```

如果你不熟悉 vi 或 EMACS 文本编辑器，但想使用命令编辑，请阅读以下章节并选择一个你认为最自然的编辑界面。

### vi 编辑模式

vi 编辑使用了 vi 文本编辑器的编辑命令和方法，尽管由于你只编辑一行文本而不是整个文件，会有一些细微的。

你可以通过输入此命令来激活 vi 模式：

```
set -o vi
```

如果你喜欢始终使用 vi 编辑模式，请将该命令添加到你的配置文件中。注意，你不能同时激活 vi 和 EMACS 编辑模式。你可以在它们之间切换，或者将它们都关闭。

就像编辑器一样，vi 编辑使用两种模式：**命令模式（Command）**和**输入模式（Input）**。通常，你的键盘处于输入模式，你输入的每个字符都会进入命令行。要进入命令模式，按下 `ESC`。在命令模式下，键盘的大小字母代表编辑命令，按下按键会触发编辑动作。如果没有命令对应于给键，在命令模式下按下它会导致终端鸣响；你不能在命令模式下进行编辑。初学者在使用 vi 风格编辑时最犯的常见错误是一个障碍，也是导致该编辑器作为文本编辑器时声誉不佳的原因。

按下 `Enter` 键返回输入模式。在对行进行任何编辑更改后，无论光标在行的哪个位置，你都可以按下 `Enter` 来进入并执行命令。
