## 1.1.2 配置 /tmp

`/tmp` 目录是一个全局可写目录，供所有用户和某些应用程序用于临时存储。

### 1.1.2.1 确保 /tmp 是独立分区（自动化）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

描述：

`/tmp` 目录是一个全局可写目录，供所有用户和某些应用程序用于临时存储。

原理：

将 `/tmp` 设置为独立的文件系统，允许管理员在挂载时设置额外的挂载选项（例如 `noexec` 选项），使得 `/tmp` 无法被攻击者用于安装可执行代码。它还能防止攻击者对系统 `setuid` 程序的副本建立硬链接，并等待其更新。一旦程序被更新，硬链接就会失效，攻击者将拥有该程序的自己的副本。如果该程序存在安全漏洞，攻击者就可以继续利用已知的缺陷。

可以通过将 `tmpfs` 挂载到 `/tmp`，或者为 `/tmp` 创建一个独立分区来实现。

影响：

由于 `/tmp` 目录被设计为全局可写，如果不将其绑定到独立分区，则存在资源耗尽的风险。

无论底层是什么种文件系统，`/tmp` 空间不足都是问题，但在 `/tmp` 不是独立文件系统的配置中，它将会占用整个磁盘，因为默认安装会创建一个单一的 `/` 分区。另一方面，基于内存的 `/tmp`（如 `tmpfs`）通常要小得多，这可能导致应用程序更容易填文件系统。另一种替代方案是从单独卷或磁盘为 `/tmp` 创建专用分区。基于磁盘的专用分区的缺点之一是它比基于内存的 `tmpfs` 慢。

利用 `tmpfs` 的 `/tmp` 可以通过 `/etc/fstab` 中相关条目中的 `size={size}` 参数进行调整大小。

#### 审计：

运行以下命令并验证输出显示 `/tmp` 已挂载。有关挂载选项的特定要求将在后续章节中介绍。

```bash
findmnt --kernel /tmp
TARGET SOURCE FSTYPE OPTIONS
/tmp tmpfs tmpfs rw,nosuid,nodev,noexec,inode6
```

确保 `systemd` 将在启动时挂载 `/tmp` 分区。

```bash
systemctl is-enabled tmp.mount
enabled
```

注意，默认情况下，如果 `/etc/fstab` 中存在 `/tmp` 的条目，`systemd` 将输出 `generated`。这意味着 `systemd` 将使用 `/etc/fstab` 中的条目，而不是其针对 `/tmp` 的默认文件配置。

#### 修复：

首先确保 `systemd` 配置正确，以确保 `/tmp` 在启动时被挂载。

```bash
systemctl unmask tmp.mount
```

根据你环境对 `/tmp` 挂载的具体配置要求，请修改 `/etc/fstab` 或 `tmp.mount`。

配置了特定挂载选项的 `tmpfs` 文件系统的 `/etc/fstab` 示例：

| tmpfs | /tmp | tmpfs | defaults,rw,nosuid,nodev,noexec,relatime,size=2G | 0 |

配置了特定挂载选项的 `tmpfs` 文件系统的 `tmp.mount` 示例：

```ini
[Unit]
Description=Temporary Directory /tmp
PathIsSymbolicLink=/tmp
DefaultDependencies=no
Conflicts=mount.target
Before=local-fs.target mount.target
After=swap.target

[Mount]
What=tmpfs
Where=/tmp
Type=tmpfs
```

## 1.1.3 配置 /var

`/var` 目录被守护进程和其他系统服务用于临时存储动态数据。这些进程创建的某些目录可能是 world writable。

### 1.1.3.1 确保为 /var 存在独立分区（自动化）

配置方案适用性：

- Level 2 - 服务器
- Level 2 - 工作站

描述：

`/var` 目录被守护进程和其他系统服务用于临时存储动态数据。这些进程创建的某些目录可能是 world writable。

理由：

将 `/var` 挂载在独立分区上的理由如下。

#### 防止资源耗尽

默认安装只创建一个单个 `/` 分区。由于 `/var` 目录可能包含 world 写入的文件和目录，存在资源耗尽的风险。它本质上可以使用整个磁盘空间来填满整个系统。此外，系统上的其他操作可能会填满与 `/var` 无关的磁盘，并由于磁盘满导致整个系统的意外行为。详情请参见 `auditd.conf`。

#### 挂载的细粒度控制

将 `/var` 配置为自己的文件系统允许管理员设置额外的挂载选项，例如 `noexec/nosuid/nodev`。这些选项限制了攻击者在系统上创建漏洞的能力。其他选项允许特定的行为。有关文件系统无关和文件系统特定选项的详细信息，请参阅 `mount`。

#### 防止利用

利用 `/var` 的一个示例可能是攻击者对系统 `setuid` 程序建立硬链接，并等待其更新。一旦程序被更新，硬链接就会断，攻击者将拥有该程序的自己的副本。如果该程序恰好存在安全漏洞，攻击者可以继续利用已知漏洞。

影响：

调整文件系统大小是云托管服务器的常见活动。独立的文件系统分区可能会防止成功调整大小，或者可能需要安装额外的工具专门用于调整大小的操作。使用这些额外工具可能会引入安全考虑因素。

审计：

运行以下命令并验证输出显示 `/var` 已挂载。

示例：

```bash
findmnt --kernel /var
TARGET SOURCE FSTYPE OPTIONS
/var /dev/sdb ext4 rw,relatime,seclabel,data=ordered
```

修复：

对于新安装，在安装期间创建自定义分区设置并为 `/var` 指定独立分区。

对于以前安装的系统，创建一个新分区并根据情况配置 `/etc/fstab`。

参考：

1. AJ Lewis, "LVM HOWTO", http://tldp.org/HOWTO-LVM-HOWTO/
