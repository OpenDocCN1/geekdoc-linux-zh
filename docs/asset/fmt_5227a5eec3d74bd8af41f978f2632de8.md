
$me@linuxbox ~$ cat > lazy_dog.txt

```
红色的狐狸跳过了懒狗。
```

输入命令并跟上想要放入文件的文本。记得在结束时按 `CTRL+D`。通过命令行，我们实现了世界上最笨的处理器（此处应为 joke）！为了查看我们的结果，我们可以使用 `cat` 将文件复制到标准输出（stdout）：

```
me@linuxbox~$ cat lazy_dog.txt
```

红色的狐狸跳过了懒狗。

现在我们知道 `cat` 除了接受文件名参数外，还接受标准输入，让我们尝试使用标准输入：

```
me@linuxbox~$ cat < lazy_dog.txt
```

红色的狐狸跳过了懒狗。

使用 `<` 重定向操作符，我们从文件 `lazy_dog.txt` 管理标准输入源。这在传递文件名参数时并不特别有用，但它演示了将文件作为标准输入源。其他命令会更好地利用标准输入，我们很快就会看到。

在继续之前，查看 `cat` 的帮助页，因为它有很多有趣的选项。

## 管道

命令从标准输入读取数据并发送到标准输出的能力被一种称为管道的 shell 功能利用。使用管道操作符 `|`（竖线），一个命令的标准输出可以传递给另一个命令的标准输入：

```
command1 | command2
```

为了充分演示这一点，我们需要一些命令。记得我们说过有一个命令已经知道接受标准输入吗？是 `less`。当我们使用 `less` 显示时，我们捕获了任何向标准输出发送内容的命令：

```
me@linuxbox~$ ls -l /usr/bin | less
```

## 过滤器

管道通常用于对数据执行复杂操作可以将多个命令组合到管道中。通常，使用的命令被称为过滤器。过滤器接收输入，对其进行某种处理，然后输出。我们将尝试的第一个是：假设我们想创建一个 `/bin` 和 `/usr/bin` 中所有可执行程序的合并列表，但按排序排列，并查看结果列表：

```
me@linuxbox~$ ls /bin /usr/bin | sort | less
```

由于我们指定了两个目录（`/bin` 和 `/usr/bin`），`ls` 的输出将包含两个排序后的列表，每个目录一个。通过在管道中包含 `sort`，我们更改了数据以生成一个单一的排序列表。
`sort` 是一个功能强大的命令，具有许多特性和选项。我们将在第 20 章详细介绍它们。

## `>` 和 `|` 之间的区别

一看，可能很难理解管道操作符 `|` 执行的重定向与重定向操作符 `>` 之间的区别。简单来说，重定向操作符将命令与文件连接，而管道操作符将一个命令的输出与第二个命令的输入连接：

```
command1 > file1
command1 | command2
```

许多人在学习管道时，会尝试以下操作，“仅仅为了看看会发生什么”：

```
command1 > command2
```

答案：有时结果非常糟糕。

这是一个由管理 Linux 服务器设备的读者提供的真实示例。作为超级用户，他执行了：

```bash
## cd /usr/bin
## ls > less
```

第一条命令让他进入了存储大多数程序的目录，第二条命令告诉系统用 `ls` 命令的输出覆盖文件 `less`。由于 `/usr/bin` 目录下已经包含一个名为 `less` 的文件（`less` 程序），第二条命令用 `ls` 的文本覆盖了 `less` 程序，从而破坏了他系统上的 `less` 程序。

这里的教训是，重定向操作符会静默地创建或覆盖文件，因此你需要谨慎对待它。

## `uniq`—报告或显示所有重复行

`uniq` 命令通常与 `sort` 配合使用。`uniq` 接受标准输入的排序数据或单个文件名参数（详情见 `uniq` 手页），并默认删除列表中的任何重复。为了确保我们的列表没有重复（即任何同名程序同时出现在 `/bin` 和 `/usr/bin` 目录中），我们在管道中添加了 `uniq`：

```bash
[me@linuxbox ~]$ ls /bin /usr/bin | sort | uniq | less
```

在这个示例中，我们使用 `uniq` 来移除 `sort` 命令输出中的重复。如果我们想查看重复列表，则像这样给 `uniq` 添加 `-d` 选项：
`me@linuxbox:~$ ls /bin /usr/bin | sort | uniq -d | less`

## `wc`—打印行、字和字节数

`wc` (word count) 命令用于显示文件中的行数、字数字节数。这里有一个示例：
`me@linuxbox:~$ wc ls-output.txt
7902 64566 59364 ls-output.txt`

在这种情况下，它输出了三个数字：`ls-output.txt` 的行、字和字节。与之前没有执行命令行参数的命令不同，`wc` 接受标准输入。`-l` 选项限制其输出仅报告行。添加该选项是计数的一种方便方法。要查看我们排序列表中的项目数量，可以这样做：
`me@linuxbox:~$ ls /bin /usr/bin | sort | uniq -l
2728`

## `grep`—打印匹配模式的行

`grep` 是一个在文件中查找模式的强大程序。它的用法如下：
`grep pattern [file...]`

当 `grep` 在文件中遇到“模式”时，它会打印包含该模式的行。`grep` 可以匹配的模式可以很复杂，但目前我们专注于简单的文本匹配。我们将在第 19 章介绍称为正则表达式的高级模式。
假设我们想在程序列表中找到所有名称中包含 `zip` 单词的文件。搜索可以让我们了解系统上一些与文件压缩相关的程序。我们将这样做：
`me@linuxbox:~$ ls /bin /usr/bin | uniq grep zip
bunzip2
dzip2
gunzip
gzip
unzip
zip
zipcloak
zipgrep
zipinfo
zipnote
zipsplit`

以下是几个实用的 `grep` 选项：

- `-i`，使 `grep` 在执行搜索时忽略大小写（通常搜索是区分大小写的）
- `-l`，使 `grep` 输出包含匹配模式文本的文件名
- `-v`，使 `grep` 仅打印不匹配模式的行
- `-w`，使 `grep` 仅在匹配整个单词时进行匹配

## 扩展

每当我们输入一个命令并按下回车键时，`bash` 都会在执行之前对文本进行多次替换。我们已经见过简单的字符序列（例如 `*`）对 shell 具有很多含义的情况。产生这种现象的过程被称为扩展（expansion）。通过扩展，我们输入某些内容，在 shell 对其处理之前，它会被变成其他内容。为了演示我们的意思，让我们来看 `echo` 命令。`echo` 是一个执行简单任务的 shell 内置命令。它将其参数打印到标准输出。

```
[me@linuxbox~$ echo this is a test
is this a test
```

这非常直接。任何传递给 `echo` 的参数都会被显示。让我们尝试另一个例子：

```
[me@linuxbox~$ echo *
Desktop Documents ls-output.txt Music Pictures Public Templates Videos
```

那么，刚才发生了什么？为什么 `echo` 没有打印 `*` 呢？正如我们在通通配符中所回忆的，`*` 字符匹配文件名中的任何字符，但我们在最初的讨论中并没有看到 shell 是如何做到的。简单的答案是，在 `echo` 命令执行之前，shell 会将 `*` 扩展为其他内容（在本例中，是当前工作目录下的文件名）。当按下回车键时，shell 会在命令执行前自动扩展命令行上的任何符合条件的字符，因此 `echo` 命令从未见过 `*`，只看到了它的扩展结果。知道这一点，我们可以看到 `echo` 的行为符合预期。

## 路径名扩展

通配符的工作机制被称为路径名扩展（pathname expansion）。如果我们尝试在前面的章节中使用过一些技术，我们会发现它们实际上都是扩展。考虑一个如下的主目录：

```
@me@linuxbox ~~$ ls
Desktop ls-output.txt Pictures Templates
Documents Music Public Videos
```

我们可以执行以下扩展：

```
@me@linuxbox ~~$ echo D*
Desktop Documents
```

以及

```
@me@linuxbox ~~$ echo *s
Documents Pictures Templates Vidos
```

或者甚至：

```
@me@linuxbox ~~$ echo [[:upper:]]*
Desktop Documents Music Public Templates Vidos
```

看一眼我们的主目录之外，我们可以这样做：

```
@me@linuxbox ~~$ echo /usr/*/share
/usr/kerberos/share /usr/local/share
```

| echo * |
| 乍一看，我们似乎可以通过在模式开头加点将隐藏文件包含在扩展中，如下： |

```
ls -d .* | less
```

为了在这种情况下更好地执行扩展，我们必须使用更特定的模式。

```
ls -A
```

这对于大多数文件有效（尽管不包含）。

## 波浪号扩展

正如我们在介绍 `cd` 命令时回忆的，波浪号（`~`）具有特殊含义。当位于单词开头时，它扩展为用户名，如果没有指定用户名，则扩展为当前用户的目录。

```
[user@linux]$ echo ~
/home/me
```

如果 bob 有账号，它会扩展为：

```
[user@linux]$ echo ~bob
/home/bob
```

## 算术扩展

shell 允许通过扩展执行算术运算。这允许我们将命令行提示符作为计算器。

```
[user@linux]$ echo $((2 + 2))
4
```

算术扩展使用以下形式，其中 `expression` 是由值和算术运算符组成的算术表达式：`((expression))`

算术扩展仅支持整数（整数，无小数），但可以执行许多操作。表 7-1 描述了部分运算符。

## 参数扩展

我们在此将简要介绍参数扩展，但稍后会进行广泛介绍。它在 shell 脚本中的用途比直接在命令行中使用用得多。它的许多功能与系统存储小块数据并为每个块数据命名的能力有关。许多此类块数据（正确名称为变量）可供我们检查。例如，名为 `USER` 的变量包含我们的用户名。要调用参数扩展并显示 `USER` 的内容，我们可以这样做：

```
me@linuxbox-$ echo USER
me
```

要查看可用变量列表，请尝试这个：

```
me@linuxbox-$ env less
```
