### 安装 M4

如果你的基础系统运行的是 2.0 内核且 Glibc 版本为 2.1，那么在 chroot 环境中执行 M4 可能会遇到问题，因为 M4 程序、Glibc–2.1 与运行中的 2.0 内核之间存在不兼容。如果你在 chroot 环境中执行 `m4` 程序（例如在安装 `autoconf` 和 `automake` 软件包时）遇到问题，你必须退出 chroot 环境并完成 M4 的静态编译。内核 2.0 和 Glibc–2.1 并不兼容。

root:m4-1.4# ./configure --prefix=/usr --disable-nls
root:m4-1.4# make LDFLAGS=-static
root:m4-1.4# make prefix=$LFS/usr install
root:m4-1.4# chroot $LFS env -i HOME=/root bash --login

## 目录

Autoconf 软件包包含 `autoconf`, `autoheader`, `autoreconf`, `autoscan`, `autoupdate` 和 `ifnames` 程序

### 描述

### `autoconf`

`Autoconf` 是一个用于 shell 脚本的工具，用于自动配置软件源码包以适应各种 UNIX 类系统。由 `Autoconf` 生成的配置脚本在运行时独立于 `Autoconf`，因此其用户不需要安装 `Autoconf`。

### `autoheader`

`autoheader` 程序可以为 `configure` 创建一个供其使用的 C `#define` 语句模板文件

### `autoreconf`

如果你有很多由 `Autoconf` 生成的 `configure` 脚本，`autoreconf` 程序可以为你节省一些工作。它会重复运行 `autoconf`（在适当的情况下运行 `autoheader`），在以当前目录为根的目录树中重新制作 Autoconf 配置脚本和配置头文件模板。

### `autoscan`

`autoscan` 程序可以帮助为软件包创建一个 `configure.in` 文件。`autoscan` 检查以命令行参数指定的目录（或未指定时的当前目录）中的源文件。它会在源文件中搜索常见的移植性问题，并创建一个 `configure.scan` 文件，作为该包的初步 `configure.in`。

### `autoupdate`

`autoupdate` 程序更新 `configure.in` 文件，将按旧名称调用 Autoconf 宏的地方更新为当前的宏名称。

### `ifnames`

在为软件包编写 `configure.in` 时，`ifnames` 可以提供帮助。它会打印该包在 C 预处理器条件中已使用的标识符。如果一个包已经设置好具有某些可移植性，此程序可以帮你确定其 `configure` 需要检查的内容。它可能帮助填补 `autoscan` 生成的 `configure.in` 中的某些空白。
