
所有访问你的系统的用户都必须在系统本身上拥有帐户。Ubuntu 使用 `/etc/passwd` 文件来存储系统上现有用户帐户的信息。所有用户，无论其类型如何，都会在此文件中占有一行记录，该记录包含他们的用户名、一个密码字段、一个用户 ID（通常称为 `UID`）和一个组 ID（通常称为 `GID`）。最后两个字段显示主目录的位置（通常是 `/home/username`）以及用户的默认 shell（新用户的默认 shell 是 `/bin/bash`）。

> **注意：**
>
> 仅仅因为密码字段包含一个 `x` 并不意味着这就是你的密码！实际上，所有密码都会被加密并存储在 `/etc/shadow` 中以确保安全。每当需要密码时，Ubuntu 都会自动引用该文件。

与其他基于 UNIX 的操作系统一样，Linux 和 Ubuntu 也使用成熟的 UNIX 文件所有权和权限系统。所有文件都可以被赋予读取、写入和/或执行权限中的一种或多种。这三个“标志”也可以分配给文件的所有者、组的某个成员或系统上的任何人。文件的安全性来自这些权限以及文件所有权。作为系统管理员，你有责任有效管理这些设置，并确保用户拥有合适的 `UID` 和 `GID`。你需要通过文件权限，将敏感文件锁定起来，使那些不应访问它们的用户无法访问。

### 超级用户/Root 用户

无论一个系统有多少系统管理员，超级用户帐户始终只能有一个。超级用户帐户对系统的所有方面拥有完全且彻底的控制权。他们可以进入文件系统中的任何位置，授予或撤销对文件和目录的访问权限，并可以执行系统上的任何操作，包括在需要时销毁系统。`root` 用户的独特之处在于其 `UID` 为 `0`，`GID` 也为 `0`。

鉴于 `root` 用户对系统拥有至高无上的权力，重要的是不要一直以 `root` 身份工作，因为你可能会无意中对系统造成严重损坏，甚至使其完全无法使用。相反，只有在需要对系统进行需要 `root` 权限的特定更改时，你才应该依赖 `root`。一旦完成工作，你就可以切换回普通用户帐户继续工作。

在 Ubuntu 中，你可以通过 `sudo` 命令以 `root` 权限执行命令，如下所示：

```
sudo apt-get update
```

系统会提示你输入密码，然后 Ubuntu 将像你以 `root` 身份运行该命令一样执行该命令。

### Root 用户登录方式

如果你使用过其他 Linux 发行版，那么你可能会对 `sudo` 命令的使用感到有些困惑。Ubuntu 允许系统上的第一个用户通过 `sudo` 命令获得完全的 `root` 权限。它还禁用了 `root` 账户，因此没有任何人可以用用户名 `root` 实际登录。

在其他 Linux 发行版中，你会通过输入命令 `su -` 然后输入 `root` 密码来切换到 `root` 用户。这会将你带到 `root` 提示符，该提示符显示为井号（`#`）。从这里你可以执行任何你想要的命令。要在 Ubuntu 中进入 `root` 提示符，你需要执行命令 `sudo -i`，在输入密码后，它会给你其他 Linux 发行版用户所熟悉的提示符。当你完成 `root` 工作后，只需输入 `exit` 并按 Enter 即可返回到普通用户提示符（`$`）。

普通用户是指登录系统以用于非管理任务的人。这些用户不需要进行系统范围的更改或管理其他用户。然而，他们可能希望能够更改特定于他们自己的设置。例如，这取决于 `root` 用户的严格程度，普通用户可能甚至无法做到这一点！

超级用户通过文件和目录权限授予普通用户权限。例如，如果超级用户不希望你更改 `~/.profile` 中的设置，`root` 可以更改权限，使你只能读取该文件，而不能写入。

### 警告

由于作为超级用户犯下灾难性错误的可能性，始终以普通用户身份使用你的系统，并且仅在临时执行系统管理员任务时才成为 `root`。在多用户系统上，请将此建议视为绝对规则；在你的家庭系统上，以 `root` 身份运行会使许多事情变得更容易，但也更不安全。然而，在任何环境中，以 `root` 身份运行的风险都是显著的。

第三种用户类型是系统用户。系统用户不是人，而是系统在日常运行各种服务时使用的管理账户。例如，名为 `apache` 的系统用户拥有 `apache` Web 服务器及其所有相关文件。只有它自己和 `root` 可以访问这些文件。系统用户没有主目录或密码，也不会允许通过登录提示符访问系统。

你可以在 `/etc/passwd` 文件中找到系统中所有用户的列表。Ubuntu 将这些用户称为标准用户，因为它们是作为初始安装期间提供的默认系统用户集出现在每台 Ubuntu 计算机上的。

### 用户 ID 和组 ID

计算机通过称为用户 ID（`UID`）和组 ID（`GID`）的数字来识别用户和组。字母名称仅为了方便使用而显示在你的屏幕上。

如前所述，`root` 用户的 `UID` 为 `0`。`1` 到 `499` 和 `65,534` 之间的数字是系统或逻辑用户。普通用户的 `UID` 从 `1,000` 开始；Ubuntu 从该数字开始按顺序分配它们。

除了少数例外，`GID` 与 `UID` 相同。

Ubuntu 为每个 `UID` 为 `1,000` 及以上的用户创建一个私有 `GID`。系统管理员可以向 `GID` 添加其他用户，或创建全新的组并向其添加用户。与 Windows NT 和某些 UNIX 变体不同，Linux 中的组 ID 不能是另一个组的成员。

### 文件权限

权限有三种类型：读、写和执行（`r`, `w`, `x`）。对于任何文件或目录，权限可以在三个类别中建立：用户、组和全局。

用于更改文件或目录的组、用户或访问权限的命令：

- `chgrp` — 更改文件或目录的组所有权
- `chown` — 更改文件或目录的所有者
- `chmod` — 更改文件或目录的访问权限

这些命令修改文件所有权和权限，可以用来将现实世界中的组织结构和权限映射到你的 Ubuntu 系统上。例如，人力资源部门可以通过将文件设为可读并放在可访问的目录中，与公司所有员工共享健康福利备忘录。

这些命令可用于从命令行轻松管理组和文件所有权及权限。这至关重要，因为有时你可能只有命令行界面可用。

### 用户刻板印象

针对用户和系统管理员出现了夸张的刻板印象。“`luser`”和“`BOFH`”的刻板印象也充当了警示故事，描述了在计算社区中哪些行为是可以接受的，哪些是不可以接受的。

理解这些刻板印象可以帮助你更好地定义系统管理员、用户和其他人的适当和不适当角色。你可以在 Wikipedia 上找到两者很好的参考资料：`http://en.wikipedia.org/wiki/BOFH` 和 `http://en.wikipedia.org/wiki/Luser`。

### 管理组

组可以让管理用户变得容易得多。无需为每个用户单独分配权限，你就可以使用组来快速、轻松地向大量用户授予或撤销权限。设置组权限允许你为协作工作设置工作区，并控制可以使用哪些设备。

作为示例，`sysadmin` 可以将用户 `andrew`、`paul`、`michael`、`bernice`、`mark` 和 `john` 放入一个名为 `unleashed` 的新组中。这些用户可以各自创建用于组工作的文件，并将这些文件 `chgrp` 到 `unleashed`。

现在，`unleashed` 组中的每个人——除了 `root` 之外的其他人——都可以操作这些文件。`sysadmin` 很可能会为该组创建一个目录，以便其成员有一个易于访问的地方来存储这些文件。`sysadmin` 还可以将其他用户如 `bernice` 和 `ildiko` 添加到该组，并在他们的工作完成后移除现有用户。`sysadmin` 可以让用户 `andrew` 成为管理员，以便 `andrew` 可以决定组成员身份应如何更改。你也可以对 DVD 刻录机设置限制，使只有 `andrew` 能够刻录 DVD，从而防止敏感材料落入错误的人手中。
