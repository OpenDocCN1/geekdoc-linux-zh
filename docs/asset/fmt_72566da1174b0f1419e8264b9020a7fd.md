
## 描述

`pcmmapkeys` 命令允许你在文本模式下激活输入输出字符映射以及 PC 控制台的键盘扩展映射。键盘扩展映射包括对死键和组合键序列的支持。

## 一致的键盘-显示映射

原始 UNIX 操作系统是为了支持 ASCII 代码集而编写的。ASCII II 是字符内部表示为某些数字的标准之一。ASCII 通常支持 128 个不同字符，每个由一个字节表示，其中第 8 位未使用。UNIX 系统应用程序（包括 shell）利用了这种表示。从 UNIX System Release 3.1 开始，大多数此类应用程序已经过修改，以正确支持带有第 8 位的字节表示字符。有了第 8 位，可以同时支持 256 个字符。然而，需要应用一种一致的编码规范。在 IBM PC 中，已使用多年 8 位编码，称为 IBM 扩展 ASCII；MS-DOS 用户对该代码集非常熟悉。在异构 UNIX 系统环境中，推广了一种名为 ISO8859 的不同代码集。在这两个代码集中，ASCII 中的字符表示方式相同。其他 128 个字符的编码方式不同，一个代码集中找到的某些字符在另一个中是缺失的。Solaris x86 系统支持任何 8 位单字节代码集，包括 IBM 扩展 ASCII 和 ISO 8859 代码集。

# 普通键

PC 键盘上所有按键生成的扫描码（`scancodes`）也可以通过不同的方式翻译。对于每个按键，你可以针对以下四种情况指定不同的翻译：

- 键被按下。
- 键与 Shift 键同时按下。
- 键与 Alt 键同时按下。
- 键、Shift 和 Alt 键同时按下。

对于这些每种情况，扫描码可以翻译为以下内容之一：

- 单个字节。
- 前带有 Escape N 的单字节字节。
- 前带有 Escape O 的单字节字节。
- 前带有 Escape [ 的单字节字节。

在内部，会设置特殊的位位以指示需要生成转义序列（`escape sequence`）。其他位则用于指示翻译后的代码是否应该受到某些特殊键的影响。

**Num Lock** | 如果 Num Lock 位被设置，则当 Num Lock LED 开启时，交换普通值与 Shift 值，以及 Alt 值与 Shift 值。默认情况下，只有数字键盘上的按键设置了此位位。这就是为什么这些按键生成 7, 8, 9 时，Num Lock LED 是开启的，而这与使用 Shift 产生的值相同，这些按键亦此类推。

**Caps Lock** | 与 Num Lock 键的效果相同。默认情况下，所有字母都设置了此位位，而标点符号则未设置。

**Control** | 当按键被翻译为单字节（无转义序列）且此位位被设置时，每当 Control 键与另一个键同时按下时，生成相应的控制字符。此设置对于 Shift、Alt 以及 Shift Alt 组合同样有效。不使用此设置时，Control 键组合将不会产生任何结果。

# Mapfile

本节描述了 `pcmapkeys` 程序读取的 `mapfile` 布局。
`mapfile` 是一个由多个部分组成的文本文件。你可以使用井号 (`#`) 添加注释。`pcmapkeys` 程序会忽略行尾之前的所有内容。在行内，你也可以使用 C 风格的注释 (`/* */`)。使用关键字指示每个部分的开始。空格和制表符会被静默忽略，并且可以随时使用它们来提高可读性。定义组合字符（compose character）的部分是必须的；其他部分均为可选的。部分必须按照以下预定义的顺序出现。

```
input:

toggle:

dead:

compose:

output:

ancodes:
```

你可以用几种不同的方式描述字符。ASCII 字符可以通过将字符放在单引号之间来描述。例如：

```
'a'
```

你可以在需要引号的字符前加上脱扬符符号（`^`），在单引号之间列出控制字符。例如：

```
'^x'
```

当你使用反斜杠 (`\`) 时，随后的序列被解释为字符的十、八进制（以 0 开头）或十六进制（以 x 或 X 开头）表示，尽管不是强制使用单引号。例如：

```
'\x88'
```
同于：

```
0x88
```

当序列未加引号时，需要 0，且：

```
'007'
```
同于

```
007
```

当需要字符串时，请使用字符表示列表。未来将支持引号字符串。接下来的段落描述了 `mapfile` 中每个部分的内容。

# Input Section

`input` 部分描述哪些输入字符应该被映射为单字节。一个非常小的 `input` 部分示例可以是：

```
input:

'A'    # 输入时将 A 映射为 B

'#'   0x9c  # 将井号映射为磅符号
```

`deadkey` 部分定义了哪些按键应该被视为死键（`deadkeys`）。对于每个字符，使用 `dead:` 关键字后跟字符的规范。随后的行描述了在死键之后的每个按键应该生成什么键。如果死键后面跟着一个 `mapfile` 此部分未描述的按键，则不会产生任何键，并在终端上产生蜂哔声。例如：

```
dead:

'^      # 脱扬符是一个死键

  'e'  0x88      # 脱扬符后跟空格生成脱扬符

dead:

  '"'   # 双引号用作死键

  '"'   # 双引号加空格生成双引号

'a'   0x84      # 双引号生成变音符号
```

# Compose Section

`compose` 部分的第一行定义了组合字符（`compose character`）。该行在 `mapfile` 中必须始终存在。随后的行由三个字符表示组成，表示当组合字符后跟随前两个字符时，输入时需要生成第三个字符。将具有相同第一个字符的组合序列分组。例如：

```
compose:

  '^x'

  'e'  0x89      # 输入 ^x e 时生成带变音符号的 e

  'a'  0x84      # 带变音符号的 a

  'e'  0x89      # 输入 ^x e 时生成带变音符号的 e

  'a'  0x84      # 带变音符号的 a
```

下面的错误示例会导致错误。相反，你应该将具有相同字符规范的所有行分组。

```
compose:

  '^x'

  'e'  0x89      # 输入 ^x e 时生成带变音符号的 e

  'a'  0x84      # 带变音符号的 a

  'e'  0x89      # 输入 ^x e 时生成带变音符号的 e

  'a'  0x84      # 带变音符号的 a
```

# Output Section

`output` 部分描述输出时的映射，可以是单字节到单字节，或单字节到字符串。字符串是字符表示的序列。例如：

```
output:

  0x82 '('          # 将 0x82 映射为 {

  'u'('K''L'')  # 打印 KILL
```

# Scancodes Section

`scancodes` 部分仅当终端为扫描码设备时起作用。此部分的行可以有两种不同的格式。一种格式描述了功能键的值。另一种格式描述了扫描码到字节或转义序列的翻译。不需要特定的顺序。

## Function Keys

下面的行是为功能键定义字符串的示例。
`F13` `'d''a''t''e''`  # Shift F1 是 date 命令

功能键的编号在之前的章节中描述。目前不支持引号字符串如 `"date\n"`。

## Scancodes

指定如何翻译扫描码是一项更复杂的任务。行具有通用格式：
`scancode normal shift alt shiftalt`

`scancode` 列出按键生成的扫描码的十六进制表示（无引号）。按键与扫描码的对应关系可以在 `keyboard(7D)` 中找到。`normal`、`shift`、`alt` 和 `shiftalt` 是在本文描述的格式之一的字符表示，可选跟随以下一个特殊关键字：

- `|C` 按键受到 Control 键的影响。
- `|N` Escape N 应该出现在字符之前。
- `|O` Escape O 应该出现在字符之前。
- `| ` Esc 应该出现在字符之前。

`normal` 字段定义了在没有按下其他键时如何翻译扫描码，`shift` 字段定义了同时按下 Shift 键时的翻译，`alt` 字段指定了当按下 Alt 配合此键时做什么，`shiftalt` 字段包含了当按下 Shift 和 Alt 键时生成的信息。你必须填写前五个字段。当不需要翻译时（即不更改当前激活的翻译），可以使用破折号 (`-`)。第六个字段 `flags` 是可选的。`flags` 可以包含特殊关键字 `CAPS` 或 `NUM` 或两者，以指示 Caps Lock 键或 Num Lock 键状态是否有任何影响。下面的示例行描述了 Q 键的默认翻译。

```
0x10 'q'|C 'Q'|q|N 'Q'N CAPS
```
