
- 内核签名检查 (EXPERIMENTAL) (`CRYPT_SIGNATURE`) [Y/y]

- 处理 DSA 签名 (EXPERIMENTAL) (`CRYPT_SIGNATURE_DSA`) [Y/n/y]

- 多精度数学库 (EXPERIMENTAL) (`CRYPT_MPILIB`) [Y/y]

## 第 21 章：软件安装与更新

你还可以启用对某些硬件加密设备的支持，并为几个循环冗余校验（CRC）算法构建模块。

## 构建内核

在配置内核选项后，你必须构建内核。这部分可能需要一段时间时间。取决于你的系统，构建新内核可能需要几分钟到一小时不等。

输入以下命令启动该过程：

```
make
```

`make`命令会创建新内核以及你在配置步骤中指定的任何模块。

在构建内核时，你会在屏幕上看到大量信息。完成后，一个名为`bzimage`的压缩文件新内核将位于内核源码所在的`arch/i386/boot`子目录下。

要使用新内核，你必须将内核文件和`System.map`文件复制到`/boot`目录并命名为特定名称，同时编辑`/etc/grub.conf`中的GRUB菜单来设置引导程序GRUB。在继续安装内核之前，你必须安装模块并构建一个新的RAM disk。

## 安装模块

如果你在内核配置期间选择了任何模块，内核构建步骤也会构建这些模块。你只需要安装它们。使用以下命令执行此任务：

```
cd /usr/src/kernels/linux-*
make modules_install
```

`modules_install`命令将所有模块复制到`/lib/modules`目录下的新子目录下。子目录名称应与内核版本号相同。

现在你可以安装内核并供GRUB启动。

## 创建初始 RAM 磁盘文件

内核需要一个新的初始RAM磁盘，你可以使用`mkinitrd`命令创建它。通常，初始RAM磁盘镜像存储在以`initrd`开头的文件中。正如你所猜的，initrd是initial RAM disk的缩写，而`mkinitrd`命令是因为它可以创建initrd文件。`mkinitrd`程序位于`/sbin`目录，你必须以root身份登录并使用以下命令行来创建initrd文件：

```
/sbin/mkinitrd /boot/initrd-filename module-directory
```

initrd文件必须位于内核所在的`/boot`目录。你可以使用任何文件名作为`initrd-filename`。`module-directory`是`/lib/modules`中存放新内核文件的目录名称。`modules_install`步骤将模块放置在内核版本命名的目录中。例如，如果你的内核版本（通过`uname -r`命令报告）是`2.6.11`，那么`modules_install`步骤之后的`module-directory`就是`2.6.11`。另一种常见做法是使用通过附加目录名到缀创建的initrd文件。因此，对于目录`2.6.11`，initrd文件将是`initrd-2.6.11.img`。当新内核可用时，必须参考GRUB文件(`/etc/grub.conf`)中的initrd文件。

## 安装新内核并设置 GRUB

Fedora Linux使用GRUB从磁盘加载Linux内核。配置文件`/etc/grub.conf`列出了GRUB运行的内核。你可以通过输入以下命令检查GRUB配置文件的内容：

```
cat /etc/grub.conf
```

这是我在我的一个系统上尝试此命令时看到的内容：

```
# grub generated by anaconda
# 注意：修改此文件后不需要运行 grub
# 警告：有一个 /boot 分区。这意味着
# 所有内核和 initrd 路径都是相对于 /boot/ 的
# root(hd0)
# kernel/vmlinuz-version root=dev/hda
# initrd/init.img
boot=/dev/hda
default=0
timeout=5
splashimage=(hd0,5)/splash.gz
hiddenmenu
title Fedora Core (2.6.11)
root(hd0)
kernel/vmlinuz-2.6.11 root=LABEL=/ acpi-off quiet
initrd/initrd-2.6.11.img
title Windows XP
root(hd0,1)
chainloader +1
```

你可以在终端窗口输入`info grub`来了解GRUB及其配置文件(`/etc/grub.conf`)。在讨论中，你应该注意以下几：

- `timeout=0`指定第一项为GRUB应该启动的默认项。

- `timeout=5`使GRUB在等待5秒后自动启动默认项。如果文件中其他启动项，用户可以从GRUB显示的菜单中选择另一个。

- `hiddenmenu`行隐藏可以启动的分区的GRUB菜单。当GRUB等待启动默认分区时，如果你按任何键就会显示菜单。

- 以`title`开头的四行定义了GRUB可以启动的特定内核文件。你可以通过在配置文件添加类似的部分让GRUB启动另一个内核。

- `kernel`行标识GRUB加载的内核。在这种情况下，是`vmlinuz-2.6.11`，它位于根设备——第一个硬盘的第三分区。在我的系统中，GRUB加载内核文件`/boot/vmlinuz-2.6.11`。该行的`root=LABEL=`部分指定Linux文件系统位于该标签设备上。此位置在你的系统中可能有所不同。

- `initrd=/initrd-2.6.11.img`指定一个包含初始RAM磁盘(initrd)镜像的文件，在磁盘可用之前作为文件系统。Linux内核使用RAM disk（用作磁盘的内存块）来启动；然后加载其他驱动程序并使用硬盘。

在具有Windows分区的系统上，GRUB配置文件通常包含另一个部分，带有分区上操作系统（可能是Windows 98、Windows 2000或Windows XP）的详情。

要配置GRUB启动另一个内核（你刚刚构建的），你需要遵循以下步骤：

1. 将新内核二进制文件复制到`/boot`目录。新的压缩内核位于内核源码所在的`arch/i386/boot`子目录下。内核文件名通常为`bImage`。我只需将该文件复制到`/boot`目录。

```
/usr/src/kernels/linux-*/arch/i386/boot/bImage /boot
```

2. 如果内核是`zimage`，确保你使用的是`image`而不是`bImage`。你可以使用任何其他文件名，只要在步骤3的`/etc/grub.conf`文件引用内核时使用相同文件名。

3. 使用你喜欢的编辑器编辑`/etc/grub.conf`文件，在文件的`splashimage`行之后添加以下行。（如果你需要编辑器，请参阅第14章了解vi和Emacs，这是Linux两种流行的文本编辑器）

```
title Linux kernel
root (hd0,2)
kernel /bImage root=LABEL=/\initrd=/initrd-VERSION
```

在`kernel`行后附加你系统所需的任何其他选项（例如，我的其中一个系统上需要`acpi=off`）。记得将`initrd`行上的`VERSION`更改为你构建的新内核版本号。

4. 保存`grub.conf`文件并退出编辑器。

# 第四部分：管理 Linux

在你的系统中，你应该确保`root (hd0,2)`这一行是正确的——不要使用`(hd0,2)`（它指的是硬盘的第三个分区），而应该列出Linux `/boot`文件系统所在的正确分区。此外，确保你为内核镜像文件使用了正确的文件名（例如，如果内核名为`vmlinuz`，则使用`/boot/vmlinuz`）。

在准备好`/etc/grub.conf`文件后，你就可以重启系统并尝试新内核了。

## 重启系统以测试新内核

当你仍以root登录时，输入以下命令重启系统：

```bash
reboot
```

当你看到GRUB界面时，选择你在`/etc/grub.conf`中为新内核分配的。

> 在系统使用新内核重启后，你应该能看到熟悉的图形化登录界面。为了证明你正在运行新内核，请以用户身份登录，打开终端并输入`uname -srv`。此命令将向你显示内核版本，以及该内核构建的日期时间。如果你升级了内核，请查看新内核的版本号。如果你是针对同一个旧内核版本重新构建的，则日期时间应该与你重新构建内核的时间一致。这就是系统正在运行新内核的证明。
