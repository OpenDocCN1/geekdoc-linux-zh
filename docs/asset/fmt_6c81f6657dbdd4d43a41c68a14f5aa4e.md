
其他部署都很简单，比较困难的步骤是如何编写 `crontab` 计划配置位置。以刚刚执行的行为为例，可以分为三个部分（如图 10-2 所示）：

- 第二部分是用哪个用户的身份去执行的，这里是用户。
- 第三部分就是在何时执行该任务，该部分较为复杂。这里提供了一张图（如图 10-3 所示）和一张表（表 10-1 所示），清晰地说明了 `crontab` 执行时间部分的格式如下：

## 10.3 必要知识

### 10.3.1 进程和守护进程

计算机中基本的操作（如数字等）称为指令（instruction），程序（program）则是由一系列指令整合成的。通过过程可以让计算机完成复杂的操作。程序存储为可执行的文件，比如复制命令 `cp`，编辑工具 `vi`。进程（process）则是程序的一次执行，是具体的实现，在 Linux 中进程是唯一的实现。

- 进程与程序是两个概念；程序只是一个静态的指令集合，不占用资源；进程是一个随时可能变化的、动态的、使用资源的实体。
- 一个进程的运行，在 Linux 上的 Web 服务器是 `Apache Server` 来提供服务。

#### Linux 中的守护进程

在 Linux 中的守护进程是运行在后台的一种特殊进程，它独立于控制终端并且周期性执行某些任务或处理某些事件。典型的例子：Linux 上的 Web 服务器 `Apache Server` 的守护进程叫做 `httpd`；Linux 的任务守护进程 `cron`。启动后每分钟都会读取 `/etc/crontab` 配置文件是否有任务需要执行。

> **注意**
> - 守护进程被载入就开始在后台运行，除非出现异常或用户杀死，将一直运行直到内核才结束。
> - 守护进程是非交互式进程，其本身没有与用户交互的功能，它无标准输入也不会标准输出，一般通过配置参数或者特定的命令来控制进程。
> - 守护进程经常以用户（`root`）权限运行，因为它们要使用端口（1~1024）或访问特定的系统资源。

某些守护进程对系统用户非常重要，甚至不可或缺。在其他操作系统（UNIX）中，进程与线程有不同的两个概念，但在 Linux 中线程是一个特殊的进程，所以线程是唯一的实现方式。

### 10.3.2 知识点之 `ps` 查看进程

Linux 中的 `ps` 命令是进程的扩展。`ps` 命令列出系统中当前运行的那些进程。`ps` 命令列出的当前进程快照（snapshot），就是执行 `ps` 命令时刻系统中的进程，通过合适的选项，可以获取并显示进程中的大部分信息。

- `ps` 提供的状态查看并不是连续的，如果想对进程进行实时的连续监控，应该使用 `top` 命令。
- 由于历史原因，`ps` 命令支持 3 种选项的格式：
  - UNIX 风格：选项组合在一起，且选项必须有 `-` 字符。
  - BSD 风格：选项组合在一起，但选项前不能有 `-` 字符。
  - GNU 风格：选项前有两个 `-` 字符。
- 在 `ps` 中，可以混用这几种格式的选项。

在本节中，我们将介绍 `ps` 命令的语法和常用选项，并用若干例子来展示 `ps` 命令的类型。

#### 命令 `ps`

用法：`ps [选项]`
功能：查看系统中的进程状态；其说明见表 10-2 所示。

#### 表 10-2 `ps` 命令的常用选项及其说明

| 选项 | 说明 |
| :--- | :--- |
| `-e` | 列出系统内的所有进程（等价于 `ps -A`） |
| `-f` | 使用完全（full）格式显示进程状态，通常和其他选项联用 |
| `-F` | 在 `-l` 选项基础上显示额外的格式的进程信息 |
| `a` | 列出当前终端的所有进程，包括其他用户的进程 |
| `x` | 列出所有终端下的进程 |
| `u` | 使用用户为主的格式显示 |
| `f` | 显示层级结构 |
| `j` | 使用作业组显示 |
| `--sort<字段名>` | 按字段进行排序 |
| `-o<字段名>` | 指定显示的字段 |
| `-p <pid>` | 列出指定 PID 的进程 |
| `-u <user>` | 列出指定用户的进程 |

### 10.3.3 知识点3 用 `kill` 操纵进程

`kill` 系列命令是 Linux 用于操控进程的主要工具，能够将指定的信号发送给进程。在本节中，将介绍 `kill`、`killall` 和 `skill` 命令的语法，并通过若干实例展示这些命令的具体用法。

#### (1) `kill` 命令

##### `kill` 命令

用法：`kill [选项] <进程> [信号]`
功能：向进程发送指定信号。常用选项及其说明，如表 10-9 所示。

#### 表 10-9 `kill` 命令的常用选项及其说明

| 项目 | 说明 |
|---|---|
| `-l` | 列出全部信号名称 |
| `-p` | 只打印进程号，而不发送任何信号 |
| `-s` | 指定要发送的信号，如果没有指定任何信号，默认发送的信号为 `SIGTERM` (-15) |

`kill` 常用的信号有表 10-10 所示的几种。如果你想了解信号的用途，可以通过 `man 7 signal` 命令来查看相应的帮助手册。

#### 表 10-10 `kill` 常用信号

| 信号 | 说明 |
|---|---|
| `SIGHUP` (1) | 挂起进程，通常是因为终端断线或者用户退出引起 |
| `SIGINT` (2) | 中断信号，与按下 `Ctrl+C` 组合键等效 |
| `SIGQUIT` (3) | 退出进程，与按下 `Ctrl+\` 组合键等效 |
| `SIGTERM` (15) | 终止信号，默认发送信号 |
| `SIGKILL` (9) | 强制终止进程，不可捕获和忽略 |
| `SIGSTOP` (19) | 暂停进程，与按下 `Ctrl+Z` 组合键等效 |
| `SIGCONT` (18) | 继续进程，与 `STOP` 信号相反 |

用 `kill` 终止进程很简单，一般分两步：查找确定进程 PID，用 `kill` 终止进程，如清单 10-21 所示。

#### 清单 10-21

```bash
ps -ef | grep sde | grep -v grep

root 3079 92 22:17 pts/0 00:00:24 ./sde8912ue_auth
root 3080 3079 92 22:17 pts/0 00:00:24 ./sde8912ue_auth

kill 3079 3080

[2]+ 终止 ./sde8912eu_auth
# ps -ef | grep sde | grep -v grep
```

如果用默认发送的 `SIGTERM` (15) 信号无法让进程结束，那么可以发送更强力的 `SIGKILL` (9) 信号，如清单 10-22 所示。

#### 清单 10-22

```bash
kill -s 9 3079
kill -9 3080

[1]+ 已终止 ./sde8912eu_auth
```

- 发送 `SIGKILL` (9) 信号要十分小心，这个信号不能被进程忽略或捕获，会直接结束进程，导致在结束前无法释放资源，一般不推荐使用，除非其他办法无效。
- 当发送 `SIGKILL` (9) 信号后，通过 `ps -ef` 确认是否有残留僵尸进程。如果有，就需要通过终止其父进程来及时清理僵尸进程。

#### (2) `killall` 命令

`kill` 命令用于终止进程发送信号。它也可以用 `kill` 命令通过进程 pid 发送信号，这往往需要在之前用 `ps` 或者 `top` 命令确定进程 pid，而 `killall` 把两个步骤合并为一，是一个很好用的命令（系统中另外有一个 `pkill` 命令与 `killall` 命令功能类似，后面就不再赘述）。

##### `killall` 命令

用法：`killall [选项] [进程名]`
功能：通过名字终止进程。
`killall` 命令常用的选项及其说明如表 10-11 所示。

#### 表 10-11 `killall` 命令常用的选项及其说明

| 选项 | 说明 |
|---|---|
| `-l` | 列出全部信号名称 |
| `-s` | 指定发送的信号，如果没有指定信号，默认发送的信号为 `SIGTERM` (-15) |
| `-I` | 忽略进程名中的大小写 |
| `-i` | 交互模式，终止进程前询问用户 |
| `-q` | 静默模式，如果未成功终止进程，不提示 |
| `-u` | 向指定的用户的进程发送信号 |
| `-w` | 等待所有需要终止的进程终止。`killall` 会每次检查一次是否已被终止的进程仍然存在，仅当这些进程结束后才返回。注意：如果信号被忽略或没有作用，或者进程停留在僵尸状态，`killall` 可能会一直等待 |

用 `killall` 终止进程非常简单，在后面加上进程名即可，如清单 10-23 所示。

#### 清单 10-23

```bash
ps -ef | grep sde | grep -v grep  #系统中有三个名为 sde_auth 的进程

root      3079 3022 22:17 pts/0 00:00:24 ./sde_auth
root      3080 3079 22:17 pts/0 00:00:24 ./sde_auth
root      3081 3079 22:17 pts/0 00:00:24 ./sde_auth

killall sde_auth

[1]- 已终止 ./sde_auth
[2]- 已终止 ./sde_auth
[3]+ 已终止 ./sde_auth
```

在 `killall` 中可以使用通配符指定多个进程，例如如清单 10-24 所示结束所有 `sde` 开头的进程。

在 `killall` 中未使用通配符指定进程时要确认，以杀死进程。在 `killall` 加上 `-i` 选项确认结束进程，如清单 10-25 所示。

#### 清单 10-25

```bash

杀死 sde_auth(3)? (y/n)
杀死 sde_auth(4)? (y/n)

[1]- 已终止 ./sde_auth
[2]+ 已终止 ./sde_auth
```

在 `killall` 中加上 `-u` 选项指定某个用户的进程，如清单 10-26 所示。

#### 清单 10-26

user      4145 2141 23:08 pts/0 00:02:41 ./test
user      4149 2956 23:08 pts/0 00:02:26 ./test

root      4263 4187 69:13 pts/0 00:00:20 /test
