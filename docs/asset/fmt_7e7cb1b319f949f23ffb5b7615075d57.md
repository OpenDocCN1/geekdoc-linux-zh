
| `u.readline()` | 将单行文本作为字节字符串读取。 |
| `u.readlines()` | 读取所有输入行并返回一个列表。 |
| `u.fileno()` | 返回整数文件描述符。 |
| `u.close()` | 关闭连接。 |
| `u.info()` | 返回一个与 URL 相关的元信息的映射对象。对于 HTTP，返回服务器响应中包含的 HTTP 标头。对于 FTP，标头包含 'content-length'。对于本地文件，包含 'content-length' 和 'content-type' 字段。 |
| `u.getCode()` | 返回整数格式的 HTTP 响应码——例如，200 表示成功或404 表示文件未找到。 |
| `u.geturl()` | 返回数据的真实 URL，并考虑可能发生的任何重定向。 |

需要强调的是，类文件对象是以二进制模式运行的。如果你需要将响应数据作为文本处理，将需要使用 `codecs` 模块或其他手段对其解码。

如果在加载过程中发生错误，则会抛出 `URLError`。这包括与 HTTP 协议本身的错误，如禁止访问或身份验证请求。对于这类错误，服务器通常会返回提供更多描述性信息的内容。要获取这些内容，异常实例本身作为一个类文件字典。你可以通过以下方式读取它：

```python
try:
    u = urlopen("http://www.python.org/perl.html")
    resp = u.read()
except HTTPError as e:
    resp = e.read()
```

### 自定义打开器 (Custom Openers)

`urlopen()` 函数不支持身份验证、cookies 或 HTTP 的其他高级功能。要添加这些支持，你必须使用 `build_opener()` 函数创建自己的自定义打开器：

```
build_opener({handler1, handler2, ...})
```

构建一个用于打开 URL 的自定义打开器。参数 `handler1`, `handler2` 等都是特殊处理器对象的实例。这些处理器的目的是为生成的打开器对象添加各种功能。列表列出了所有可用的处理器：

| 处理器 | 描述 |
| --- | --- |
| `CacheFTPHandler` | 具有持久 FTP 连接的 FTP 处理器 |
| `FileHandler` | 打开本地文件 |
| `FTPHandler` | 通过 FTP 打开 URL |
| `HTTPAuthHandler` | 基础 HTTP 认证处理 |
| `HTTPCookieProcessor` | HTTP cookies 的处理 |
| `HTTPDefaultErrorHandler` | 通过抛出 HTTPError 异常处理 HTTP 错误 |
| `HTTPDigestHandler` | HTTP 摘要认证处理 |
| `HTTPHandler` | 通过 HTTP 打开 URL |
| `HTTPRedirectHandler` | 处理 HTTP 重定向 |
| `HTTPSHandler` | 通过安全 HTTP 打开 URL |
| `ProxyHandler` | 通过代理重定向 |
| `ProxyAuthHandler` | 基础代理认证 |
| `ProxyDigestHandler` | 摘要代理认证 |
| `UnknownHandler` | 处理所有未知 URL 的处理器 |

默认情况下，创建打开器时带有 `ProxyHandler`、`UnknownHandler`、`HTTPHandler`、`HTTPSHandler`、`HTTPDefaultErrorHandler`、`HTTPRedirectHandler`、`FTPHandler`、`FileHandler` 和 `HTTPErrorProcessor`。这些处理器提供了基本功能。但是，如果任何额外的处理器与默认类型相同，它们将具有优先级。例如，如果你添加了 `HTTPHandler` 实例或派生自 `HTTPHandler` 的类，它将替代默认处理器。

`build_opener()` 返回的对象有一个方法 `open(url [, data [, timeout]])`，用于根据各种处理器提供的规则打开 URL。打开器的参数与传递给 `urlopen()` 函数的参数相同。

```
install_opener(opener)
```

安装一个不同的打开器对象，作为 `urlopen()` 使用的全局打开器。`opener` 通常是由 `build_opener()` 创建的打开器对象。

接下来的章节将展示如何在使用 `urllib.request` 模块时为某些更常见的场景创建自定义打开器。

## urllib 包

### 密码认证

要处理需要密码认证的请求，你创建一个包含了 `HTTPBasicHandler`、`HTTPDigestAuthHandler`、`ProxyBasicHandler` 或 `ProxyDigestHandler` 组合的打开器。这些处理器都具有以下方法用于设置密码：

```
h.auth_password(realm, uri, user, passwd)
```

为指定的 realm 和 URI 添加用户和密码信息。所有参数都是字符串。`uri` 可选为 URIs 序列，在这种情况下，用户和密码信息适用于序列中的所有 URIs。`realm` 是与认证相关的名称或描述。它的值取决于远程服务器。然而，它是与一组相关网页关联的常用名称。`realm` 和 `user` 的典型值可能像 `('Administrator', 'http://www.somesite.com')`。`user` 和 `password` 指定用户名和密码。

以下是如何设置带有基础认证的打开器的示例：

```
auth = HTTPBasicHandler()
auth.add_password('Administrator', 'http://www.secretlair.com', 'drevil', '12345')
```

```python
# 创建已添加认证的打开器
opener = build_opener(auth)
```

```python
# 打开 URL
u = opener.open('http://www.secretlair.com/evplan.html')
```

### HTTP Cookies

要管理 HTTP cookies，创建一个添加了 `HTTPCookieProcessor` 的打开器对象。例如：

```
cookiehandler = HTTPCookieProcessor()
opener = build_opener(cookiehandler)
u = opener.open('http://www.example.com/')
```

默认情况下，`HTTPCookieProcessor` 使用 `http.cookiejar` 模块中的 `CookieJar` 对象。通过向 `HTTPCookieProcessor` 传递不同的 `CookieJar` 参数可以支持不同类型的 cookie 处理。例如：

```
cookiehandler = HTTPCookieProcessor(
    http.cookiejar.MozillaCookieJar("cookies.txt")
)
opener = build_opener(cookiehandler)
u = opener.open('http://www.example.com/')
```

### 代理 (Proxies)

如果请求需要通过代理重定向，请创建一个 `ProxyHandler` 实例。

`ProxyHandler(proxies)`

创建一个通过代理路由请求的代理。参数 `proxies` 是一个字典，将协议名称（例如 'http'、'ftp' 等）映射到相应代理服务器的 URL。

下面的示例展示了如何使用：

```python
proxy = ProxyHandler({'http': 'http://someproxy.com:8080/'})
auth = HTTPBasicAuthHandler()
auth.add_password('realm', 'host', 'username', 'password')
opener = build_opener(proxy, auth)
nu = opener.open('http://www.example.com/doc.html')
```
