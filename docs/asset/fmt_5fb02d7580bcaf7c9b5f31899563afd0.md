## 何时考虑异步网络

异步 I/O 的使用，即是异步 I/O（`asyncore` 和 `asyncio`），协程在许多示例中仍然是最神秘的方面之一。然而，这些技术的使用比你想的要频繁。使用异步 I/O 的常见理由是为了减少大量线程编程的感知开销。从历史上看，`asyncore` 模块是支持异步 I/O 的库之一。`asyncio` 随后出现，目标是简化代码。然而，这两个模块都采用了将 I/O 作为事件的方法。例如，当 I/O 事件发生时，会触发回调函数。回调函数随后响应 I/O 并执行某些处理。如果你以这种风格构建大型应用程序，这将渗透到应用程序的每一个部分（例如：I/O 事件触发回调，回调触发更多回调，再触发其他回调）。更流行的网络包之一 `Twisted`（http://twistedmatrix.com）采用了这种方法并对其极大改进。

协程更加现代，但自其引入 Python 版本以来已被广泛理解和使用。协程的一个重要特性是你可以编写在整体控制流上像线程程序的程序。例如，示例中的 Web 服务器没有使用任何回调函数，看起来和你使用线程时编写的一一样。`Stackless Python`（http://www.stackless.com）更进一步。

通常，对于大多数应用程序，你应该克制使用异步 I/O 技巧的冲动。例如，如果你需要在一个百上千个并发连接上不断传输数据的服务器，那么线程将具有更优的性能。这是因为 `select()` 的性能随着连接数量的增加而下降。在 Linux 上，可以使用 `epoll()` 等特殊函数减少这种惩罚，但这限制了代码的移植性。也许异步 I/O 的主要优势在于网络需要与其它事件循环（例如 GUI）集成的应用程序，或者网络功能被添加到同时也执行大量 CPU 处理的应用程序中。在这些情况下，异步网络的使用可能会带来更响应时间。
