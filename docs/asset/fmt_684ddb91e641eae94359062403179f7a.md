
## RCS 关键字

- `$Log$`：RCS 文件名、版本号、作者、日期以及提交时的消息。
- `$RCSfile$`：包含路径的 RCS 文件名。
- `$Revision$`：版本号。
- `$Source$`：文件的完整路径。
- `$State$`：已分配的状态。

例如，假设在提交之前，C 程序开头有如下行：

`static char rsid = "$Id$"`

提交后，字符串 `"$Id$"` 将替换为：

`static char rsid = "s:term.c,1.2;May 26 15:02:14 1997;user:1";`

## 环境变量

`cvs status` 和 `cvs log` 命令提供了关于本地副本状态的有用信息。管理文件的另一种有用技术是被称为*关键字替换*的机制。其操作非常简单：每当执行 `cvs commit` 操作时，源文件中的某些关键字就会被替换为值。这些关键字实际上来自于底层的 RCS 命令。以下是可用关键字列表及其描述：

- `CVSROOT`：此变量应包含存储的完整路径。
- `CVSREAD`：设置此变量后，所有检出的文件均为只读权限。
- `CVSED`：此变量指定 CVS 提示日志时使用的编辑器。
- `CVSSH`：CVS 使用此变量确定要使用的 shell。
- `CVSSERVER`：此变量决定服务器名称。
- `CVSWRAPPERS`：CVS 使用此变量确定封装器的名称。

## 总结

RCS 和 SCCS 都采用锁定-解锁范式来处理源代码。虽然这对于某些类型的项目是足够的，但在多个开发者想要修改同一个文件的不同部分的情况下，可能会阻碍进度。CVS 通过使用复制-合并范式来支持这种并行开发。

SCCS 仅向 SCCS 文件 `s.3liner.txt` 中添加最后一行，并将其记录为下一个修订。这种逐个跟踪更改的方法允许你快速、方便地回溯到工作文件的以前版本。

请注意，文件的实际机制与此抽象略有不同，但从概念层来说，这就是你唯一需要担心的了。

## SCCS 命令摘要

你使用 SCCS `admin` 命令与源码控制系统数据 `SCCS` 文件进行交互。你使用它来创建源码控制文件、控制修订的可用性，以及更改提交修订的要求。

你使用 `get` 和 `delta` 命令来检索修订并创建新的*增量* `delta`，即版本。你使用 `unget` 来撤消增量的创建。

SCCS 使用临时文件来存储内部状态并跟踪文件锁。这些文件存储在 SCCS 目录中，且不应被操作。

SCCS 命令需要 SCCS 文件的名称，例如 `s.3liner.txt`，而不是工作文件名。然而，CD 和大多数 BSD 系统中的 `sccs` 程序接受文件名。

## 初始修订

在执行任何其他操作之前，你必须使用 `admin` 命令初始化 SCCS 文件。这些文件可以用空修订进行初始化，也可以用工作文件的内容作为初始修订。

通过执行以下命令创建一个空修订的 SCCS 文件：

```
$ admin -n s3liner.txt
```

该命令创建一个具有适当 SCCS 文件结构的 `3liner.txt` 以及一个空修订 `1.1`。与 RCS 不同，空修订 `1.1` 将始终留在 SCCS 数据文件中。

要创建一个带有另一个文件初始内容的 SCCS 文件，请输入：

```
$ admin -i 3liner.txt s3liner.txt
```

两个 `3liner.txt` 的出现顺序不需要一致，但通常情况下它们这样做是有用的，因为其他 SCCS 命令假设工作文件是 `3liner.txt`。

`sccs` 命令提供了一种创建 SCCS 文件的简化方法：

```
$ sccs create 3liner.txt
```

该命令在当前工作目录的名为 `SCCS` 的目录下创建 `3liner.txt`。

## 检出文件

你使用 `get` 命令从 SCCS 文件中检索修订副本。你可以通过编号或日期检索任何版本，如下所示：

```
$ get 3liner.txt
1.1
3 lines
No id keywords
```

在没有任何任何选项的情况下，`get` 从 SCCS 文件检索最新修订，将其放在 `3liner.txt` 的只读副本中，因为它假设你没有进行任何更改并创建一个新修订。命令后的三行告诉我们检索的是哪个版本、文件的行数以及展开了多少关键字。

现在考虑以下情况：

```
$ get -e 3liner.txt
1.1
delta 1.2
3 lines
```

这里的 `-e` 选项表示你正在检出 `3liner.txt` 进行编辑。`get` 命令为你提供一个可写副本并创建一个名为 `p.3liner.txt` 的锁文件。该锁文件防止其他用户在通过 `delta` 或 `unget` 提交之前检索同一版本进行编辑。只读副本是可以检出的。你可以同时对不同的版本使用 `-e` 选项；但如果两个用户同时修改同一个文件，修订树中可能会出现*分支*。第 24 章“源码控制简介”包含了关于修订树、分支和其他基本修订控制概念的详细信息。

你使用 `-p` 和 `-c` 选项检索最新版本以外的修订。你可以结合这两个选项使用 `-e`。

现在看另一个示例：

```
$ get -r1.1 3liner.txt
1.1
3 lines
No id keywords
```

该命令无论最新版本是什么，都会检索版本 `1.1`。不需要指定*次*版本号。`-r2` 检索版本 `2` 中的最高修订。

这是另一个示例：

```
$ get -c970227 3liner.txt
1.1
3 lines
No id keywords
```

`-c` 标志允许你以 `YY[MM[DD[HH[MM[SS]]]]]` 的格式指定日期。也就是说，你可以指定两位年份，后面跟着可选的月、日、小时和秒。与其他 `sccs` 命令一样，你省略的任何可选参数都会被设置为最大值。因此，前面的示例检索的是截至 1997 年 2 月 27 日下午 11:59:59 的 `3liner.txt` 最新版本。

`sccs` 命令还为 `get` 命令提供了一个极大简化的接口：

```
$ sccs get 3liner.txt
```

该命令检索位于 `SCCS` 子目录下的 `s.3liner.txt` 中最新版本 `3liner.txt` 的只读副本。你可以将所有适用于 `get` 的命令行传递传递此子命令。

以下命令检索版本 `1.3` 的只读副本：

```
$ sccs get -r1.3 3liner.txt
```

`edit` 子命令执行 `get -e`，如下：

```
$ sccs edit -e 3liner.txt
```

它也接受所有的 `get` 标志。`sccs` 命令通常允许你不指定控制文件而使用任何 SCCS 命令。`get` 拥有比这里涵盖的得多的命令行选项。

## 提交文件

你使用 `delta` 命令提交修订。这个过程也称为*创建增量*。方法如下：

```
$ delta s.3liner.txt
Added fourth line.
No id keywords
1.1
3 lines
```
