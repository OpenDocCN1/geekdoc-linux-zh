
创建一个新的信号量。`value` 是计数器的初始值。如果省略，则计数器设置为 `1`。

```python
s.acquire(blocking=True)
```

获取信号量。如果进入时内部计数器大于零，此方法将其递减并立即返回。如果是零，此方法将阻塞直到另一个线程调用 `release()`。

```python
s.release()
```

通过将内部计数器加 `1` 来释放信号量。如果有线程在等待，则该线程会被唤醒。

## BoundedSemaphore（有界信号量）

`BoundedSemaphore` 的工作与 `Semaphore` 完全相同，但 `release()` 操作次数不能超过 `acquire()` 操作次数。

```python
BoundedSemaphore([value])
```

创建一个有界信号量。`value` 是计数器的初始值。如果省略，则计数器设置为 `1`。

信号量与互斥锁之间的细微区别在于，信号量可以用于信号。例如，`acquire()` 和 `release()` 方法可以在不同的线程中调用，以便在生产者和消费者之间进行通信。

```python
produced = threading.Semaphore(0)

consumed = threading.Semaphore(1)

def producer():
    while True:
        consumed.acquire()
        produce_item()
        produced.release()

def consumer():
    while True:
        produced.acquire()
        item = get_item()
        consumed.release()
```

## 事件 (Events)

事件用于线程之间的通信。一个线程发出一个“事件”，一个或多个线程等待该事件。`Event` 实例管理一个内部标志，该标志可以通过 `set()` 方法设置为真，并通过 `clear()` 方法重置为假。`wait()` 方法会阻塞，直到该标志为真。

```python
Event()
```

创建一个新的 `Event` 实例，其内部标志初始化为假。`Event` 实例 `e` 支持以下方法：

- `e.is_set()`
  仅在内部标志为真时才返回真。在旧的代码中，此方法名为 `isSet()`。
- `e.set()`
  将内部标志设置为真。所有等待该标志变为真的线程都会被唤醒。
- `e.clear()`
  将内部标志重置为假。
- `e.wait([timeout])`
  阻塞直到内部标志为真。如果在进入时标志已为真，则该方法将立即返回。否则，它将阻塞直到另一个线程调用 `set()` 将标志设置为真，或者发生了可选的超时。`timeout` 是以秒为单位的浮点数。

虽然 `Event` 对象可以用于通知其他线程，但不应将其用于实现生产者/消费者问题中典型的通知机制。例如，你应该避免像这样的代码：

```python
evt = Event()

def producer():
    while True:
        # 生产项目
        ...
        evt.signal()

def consumer():
    while True:
        # 等待项目
        evt.wait()
        # 消费项目
        ...
        # 清除事件并再次等待
        evt.clear()
```

这段代码无法工作，因为生产者在 `evt.wait()` 和 `evt.clear()` 操作之间可能会产生新项目。通过清除事件，在生产者创建新项目之前，消费者将无法看到这个新项目。在最好的情况下，程序在处理项目出现其其妙延迟之前会经历轻微的卡顿；在最坏的情况下，整个程序将由于丢失事件信号而挂起。对于这类问题，使用条件变量会更好。

## 条件变量 (Condition Variables)

条件变量是一种同步原语，构建在另一个锁之上，当线程对特定状态的变化或发生的事件感兴趣时使用。典型的用法是生产者-消费者问题，其中一个线程产生数据供另一个线程消费。使用以下构造函数创建一个新的 `Condition` 实例：

```python
Condition(lock)
```

创建一个新的条件变量。`lock` 是可选的 `Lock` 或 `RLock` 实例。如果没有提供，则新的条件变量 `cv` 将支持以下方法：

- `cv.acquire(*args)`
  获取底层锁。此方法调用底层锁上相应的 `acquire(*args)` 方法并返回结果。
- `cv.release()`
  释放底层锁。此方法调用底层锁上相应的 `release()` 方法。
- `cv.wait(timeout)`
  等待直到被通知或发生超时。当被调用时，调用线程已经获取了锁，底层锁会被释放，线程进入睡眠，直到被另一个线程在条件变量上执行的 `notify()` 或 `notifyAll()` 调用唤醒。一旦被唤醒，线程将重新获取锁并返回方法。`timeout` 是以秒为单位的浮点数。如果该时间过期，线程将被唤醒，锁被重新获取，并返回控制权。
- `cv.notify(n)`
  唤醒等待此条件变量的一个或多个线程。此方法在调用线程获取锁后才被调用，如果没有线程在等待，则不会唤醒。`n` 指定了要唤醒的线程数，默认为 `1`。线程在能够获取锁之前不会从 `wait()` 调用中返回。
- `cv.notify_all()`
  唤醒所有等待此条件的的线程。在旧的代码中，此方法被称为 `notifyAll()`。

这里有一个使用条件变量的模板示例：

```python
cv = threading.Condition()

def producer():
    while True:
        cv.acquire()
        produce_item()
        cv.notify()
        cv.release()
```

```python
def consumer():
  while True:
    cv.acquire()
    while not item_is_available():
      cv.wait() # 等待项目出现
    cv.release()
    consume_item()
```

使用条件变量的一个子集情况是：多个线程等待同一个条件，`notify()` 操作可能会唤醒其中一个或多个线程（这种行为通常取决于底层操作系统）。因此，始终存在一种可能性，即线程发现感兴趣的条件不再成立。这解释了为什么在 `consumer()` 函数中使用 `while` 循环。如果线程唤醒了，但产生的项目已经消失了，它只会回去等待下一个信号。

## 使用锁 (Working with Locks)

在使用任何锁原语（如 `Lock`、`RLock` 或 `Semaphore`）时，必须非常小心。锁的管理不当是死锁或竞态条件的常见源。依赖锁的代码应该始终确保在发生异常时释放锁。典型的代码如下：

```python
try:
  lock.acquire()
  # 临界区域
  ...
finally:
  lock.release()
```

或者，所有的锁都支持上下文管理协议，这更整洁：

```python
with lock:
  # 临界区域
  ...
```

在最后一个示例中，锁由 `with` 语句自动获取并在离开作用域时释放。此外，作为一条通用规则，你应该避免在任何时间获取多个锁。例如：

```python
with lock_A:
  # 临界区域
  ...
with lock_B:
  # 临界区域
  ...
```

这通常是避免这种情况的方法。

## 线程终止与挂起 (Thread Termination and Suspension)

线程没有任何强制终止或挂起的方法。这种缺失是有设计的，是由于编写线程程序的复杂性导致的。例如，如果线程获取了锁，在它释放锁之前强制终止它会导致整个应用程序死锁。此外，通常无法“释放所有锁”，因为同步涉及锁定操作。

如果你想支持终止或挂起，你需要自己构建这些功能。通常通过让线程在循环中运行定期检查状态来实现。例如：

```python
class StopableThread(threading.Thread):
    def __init__(self):
        super().__init__()
        self._terminate = False
        self._suspend_lock = threading.Lock()

    def terminate(self):
        self._terminate = True

    def suspend(self):
        self._suspend_lock.acquire()
```
