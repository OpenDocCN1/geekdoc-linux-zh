## 第 1 章：工具安装与配置

我从该系列的第一本书（*初学者 Linux 漏洞利用开发：Kali Linux 二进制分析分步指南*）中包含了这一章节，以防你还没有读过。能够设置好你的环境非常重要，有时可能很麻烦，所以，在这一节中，我将介绍我们将使用的工具以及你需要运行以安装和配置它们的命令。

Kali Linux 预装了许多工具，鉴于此原因，我强烈建议你起初使用它。如果你想使用其他版本的 Unix 或 Linux，请随意，但本书中的所有解释都将基于 64 位 Kali Linux 虚拟机。

我将使用适用于 Virtualbox 的最新滚动版 64 位 Kali Linux。我们需要一些 Kali 中没有的工具以及一些额外的库，这些库将允许我们既编译 32 位应用程序也编译 64 位应用程序。

我们将使用的调试器称为 `gdb`，而在 `gdb` 之上我们将添加 `gef`，这使得 `gdb` 更强大且更易用。`AFL` 是一个极好的模糊测试器，虽然我们在本书中不会使用它，但你将在我们稍后进行的后续工作中需要它，所以不如现在就安装。

让我们开始：
- `apt-get install gdb`
- `git clone https://github.com/hugsy/gef.git`
- `echo 'source /root/gef/gef.py' >> ~/.gdbinit`
- `wget http://lcamtuf.coredump.cx/afl/releases/afl-latest.tgz`
- `tar -xvf afl-latest.tgz`
- `cd afl-2.52b/`
- `make`
- `make install`
- `echo 0 > /proc/sys/kernel/randomize_va_space`
- `apt install libc6-dev-i386`
- `init 6`

我想花一分钟时间讨论一下 `gdb` 和 `gef`。`gdb` 已经存在很长时间了，直到你大量练习前它有点难以使用。即使那样，对于漏洞利用开发来说它也不是最简单的。但这就是 `gef` 的用武之地。它很棒。与其试图解释它，我将提供文档链接，并在下方摘录文档中的一段简介：

> “GEF（发音为 *gef* - “Jeff”）是一套适用于 X86、ARM、MIPS、PowerPC 和 SPARC 的强力命令集，旨在让 GDB 在漏洞利用开发领域重新变得酷起来。它主要面向漏洞利用开发者和逆向工程师，使用 Python API 为 GDB 提供附加功能，以协助动态分析和漏洞利用开发过程。它对 Python2 和 Python3 都有完全支持，且不加区分（随着越来越多发行版开始推送编译有 Python3 支持的 gdb）。”

如果你想知道更多，可以在 https://gefreaddthedocs.io/en/master/ 找到相关信息。

## 第 2 章：C 语言中的缓冲区溢出

![](img/d796c02933776b602cdcee4375b55ece_7_0.png)

缓冲区溢出通常存在于 C 等低级语言中。这并不是说其他语言没有溢出漏洞，但大部分情况下，C 和 C++ 是主要罪魁祸首。原因涉及程序控制流与用户数据混合的概念，因为该语言允许犯各种错误。

编写代码并不容易，当程序变得庞大且复杂时，出现错误是在所难免的。有时，编译器在尝试优化代码时会引入漏洞。开发人员造成的和编译器生成的问题都存在被滥用的机会。像 C 这样的语言允许访问和操作内存。这为导致非预期程序行为和被利用的错误提供了许多机会。

经典的基于堆栈的缓冲区溢出最常见于当发生意外写入操作，越过缓冲区末端写入内存的其他区域时。为了利用此漏洞，必须采取额外步骤来确定是否可以写入我们选择的代码，并最终使该代码得以执行。

如你所想，事情并不像仅仅写入缓冲区末端那么简单。现代操作系统和编译器拥有一长串内置的安全机制或漏洞缓解控制，你必须学会识别并绕过它们。

在开始时，我们将关闭其他所有安全机制，以便了解底层漏洞。进一步深入后，我们可以拆掉训练轮，并着手对抗漏洞缓解控制。

我尽量避免过多的“理论”，不过，我觉得展示一些存在溢出漏洞的烂代码示例是有益的。这将给读者更多分析代码的机会（这是一项需求旺盛的有用技能）。

代码分析、漏洞挖掘、安全代码审查，这些都是你会听到的术语，并且**大致**传达相同类型的含义。这三个术语暗示了查看代码以查找可能导致非预期程序行为或程序被利用的问题这一概念。

我将从卡内基梅隆大学软件工程研究所的《Cert C 编码标准》（2016 年版）中引用几个示例。可以从该研究所的网站免费获取副本下载。

![](img/d796c02933776b602cdcee4375b55ece_7_1.png)

我们的第一个示例包含一个未初始化的局部变量和未检查输入大小的失败。如果函数读取与未初始化变量关联的内存，它将读取一个不确定的值，在这种情况下，`sprintf()` 函数随后会将该不确定值从任意内存位置复制，直到遇到字符串终止符或空字符。

从内存中读取不确定数据意味着它可能是 1 字节到未知数量的字节，直到 `sprintf()` 到达空终止符。根据值的大小，可能会发生缓冲区溢出。

在下文中您将看到缓冲区仅为 24 字节。

### 未初始化局部变量 – 缓冲区溢出漏洞

```c
#include <stdio.h>
/* Get username and password from user, return -1 on error */
extern int do_auth(void);
enum { BUFFERSIZE = 24 };
void report_error(const char *msg) {
const char *error_log; /*Uninitialized Local Variable*/
char buffer[BUFFERSIZE];
sprintf(buffer, "Error: %s", error_log);
printf("%s\n", buffer);
}
int main(void) {
if (do_auth() == -1) {
report_error("Unable to login");
}
return 0;
}
```

假设一下，上述程序已经修复，并且 `error_log` 变量被初始化为 `msg` 引用的输入值（`void report_error(const char *msg)`）。
