
字段描述如下：

- `job-number`（作业号）：用于标识 `fg`、`bg` 和 `kill` 命令等待进程组的数字。使用这些命令时，你可以通过在作业号前加上 `%` 来标识作业。

- `current`（当前）：字符 `+` 标识将作为 `fg` 或 `bg` 命令默认值的作业；该作业也可以 `job-id +` 或 `%` 指定。该字符标识将成为当前默认退出作业的作业；该作业也可以通过 `Job-id %` 指定。对于其他作业，这是一个空格。一个作业可以用 `+` 标识，一个作业可以用 `-` 标识。如果有任何挂起的作业，那么当前作业就是挂起的作业。如果至少有两个挂起的作业，那么上一个作业也是挂起的作业。

- `state`（状态）：POSIX 区域设置中的以下字符串之一：
  `Running` 作业未被信号挂起且未退出。
  `Done` 作业已完成并返回状态 0。
  `Done (code)` 作业完成并以非零状态退出。
  `Stopped (SIGSTP)` 作被 SIGSTP 信号挂起。
  `Stopped (STOP)` 作被 STOP 信号挂起。
  `Stopped (TTIN)` 作业被 TTIN 信号挂起。
  `Stopped (TOU)` 作业被 TOU 信号挂起。

默认情况下，`jobs` 显示所有挂起的作业、运行的后台作业以及所有状态已改变但尚未由 shell 报告作业。

如果你正在运行一个作业并想做其他事情，可以使用 `^Z` (Control-Z) 组合向当前作业发送 STOP 信号。shell 通常会指示作业已挂起并显示另一个提示符。然后你可以操纵作业状态，通过 `bg` 命令将其放入后台，或者运行其他命令并最终通过 `fg` 命令将其带回前台。`^Z` 立即生效，并会中断待处理的输出并丢弃重读输入。

你可以通过进程 ID 或以下任意内容引用 shell：

- `%number` 给出数字的作业。
- `$string` 命令行以 string 开头的作业。此语法仅在历史文件激活的交互模式下有效。
- `?string` 命令行包含 string 的作业。此语法仅在历史文件激活的交互模式下有效。

以下列表描述了 Korn shell 作业控制命令。

- `fg` 将后台作业从当前环境移动到前台。使用 `fg` 将作业置于前台会将其进程 ID（PID）从当前 shell 执行环境中已知的列表中移除。`fg` 命令仅在支持作业控制的系统中可用。如果没有指定 `job-id`，则将当前作业带入前台。

- `bg` 通过作为后台作业运行来恢复当前环境中挂起的的作业。如果由 `job-id` 指定的作业已经是正在运行的后台作业，则 `bg` 将不起作用并成功退出。使用 `bg` 将作业放入后台会使其进程 ID 在当前 shell 执行环境中变为可 own，就好像它是作为异步列表启动的一样。`bg` 命令仅在支持作业控制的系统中可用。如果未指定 `job-id`，则将当前作业放入后台。

- `stop` 通过其 `job-id` 停止后台作业的执行，或通过其 `pid` 停止任何进程，见 `ps(1)`。

每当进程状态改变时，shell 会立即退出。通常情况下，每当作业变为阻塞状态（无法继续进行）时，它会通知你，但仅在显示提示符之前。这样这样做是为了避免干扰你的其他工作。当监控模式开启时，每个完成的后台作业都会触发任何为 CHLD 设置的 trap（陷获）。

当你在作业运行或停止时尝试退出 shell 时，你会收到警告：你已停止了（运行中的）作业。你可以使用 `jobs` 命令查看它们是什么。如果你这样做或立即再次退出，shell 将不再再次警告你，且停止的作业将被终止。如果你在尝试注销时有 `nohup` 作业运行，你将收到以下消息：

You have jobs running.

你需要再次登录才能实际注销；但是，你的后台作业将继续运行。

### 波浪线扩展 (Tilde Expansion)

波浪线前缀由单词开头的一个未引号波浪线字符 (`~`) 组成，后面跟着单词中第一个未引号斜杠之前的所有字符，或者如果没有斜杠，则为单词中的所有字符。在赋值中，你可以使用多个波浪线前缀：单词开头（即赋值的等号之后）、任何未引号冒号之后；或两者兼有。赋值中的波浪线前缀由第一个未引号冒号或斜杠终止。如果波浪线前缀中的字符都没有加引号，则前缀中波浪线之后的字符被视为用户数据库中可能的登录名。

可移植的登录名不能包含 `LOGNAME` 环境变量描述中集合之外的字符。如果登录名为空（即前缀仅包含波浪线），则波浪线前缀被替换为变量 `HOME` 的值。如果 `HOME` 未设置，结果未定义。否则，波浪线前缀被替换为与 `getpwnam` 函数获取的登录名相关的主目录路径。如果系统不识别该登录名，结果未定义。

波浪线扩展通常只发生在单词开头，但一个基于历史习惯的例外包括：
`PATH=/posix/bin:-dgk/bin`

该路径符合波浪线扩展条件，因为波浪线位于冒号之后，且所有相关字符都没有加引号。曾考虑过禁止这种行为，因为以下任何一种都是合理的替代方案：

```
PATH=$(printf %-krels/bin :bostic/bin)

for Dir in ~maart/bin ~srb/bin...

do

PATH=$(PATH:$PATH):$Dir

done
```

在第一个命令中，每个目录都使用了显式冒号。在所有情况下，shell 都对每个目录执行波浪线扩展，因为对 shell 来说它们都是独立的单词。

注意 — 操作中的表达式，例如：

```
make -k mumble LIBDIR=~chet/lib
```

不属于 shell 变量赋值，因此不执行波浪线扩展（除非命令本身执行，但 `make` 不执行）。特殊序列 `~$` 被指定用于未来实现，作为一种在任何单词中强制执行波浪线扩展的手段。

由于单词不能加引号的要求，以下内容是不等价的；只有最后一个会执行波浪线扩展。
`~-hlj/ -hlj/ ~"hlj" /-hlj/`

使用未知登录名的波浪线扩展结果未定义，因为 Korn shell 的 `+` 和 `--` 构造利用了这种情况。通常情况下，使用波浪线提供错误的登录名是一个错误。`HOME` 未设置的结果未定义，因为某些历史上的 shell 将其视为错误。

### 命令替换 (Command Substitution)

在括号内并以美元符号 `$` 开头的命令 `$(command)` 或一对反引号 `` `` `` 包围的命令的标准输出可以用单词的一部分或全部；末尾换换符会被移除。在第二种（古老的）形式中，在执行命令之前会对引号之间的字符串进行特殊引号字符的处理（见第 618 页的“引号（转义）”）。命令替换 `$(cat file)` 可以被等效但更快的 `<file>` 替换。大多数不执行输入输出重定向的特殊命令的替换是在不创建子 shell 的情况下进行的。

命令替换的结果字段分割和路径名扩展会被波浪线扩展、参数扩展或算术扩展处理。如果命令替换发生在双引号内部，则不会对结果执行替换。

命令替换可以嵌套。要在反引号版本中指定嵌套，需要在内部反引号前加反斜杠；例如：

```
\`command\`
```
