
- `attr` 是指向包含线程属性结构的指针（要使用默认属性，需要传递空指针；某些属性稍后将被审查）。

- `thread_fun` 是指向线程函数的指针，应描述为：

```c
void *mythread_fun(void *value)
{
    // 执行线程代码
}
```

- `arg` - 传递给线程函数的数据（在那里它们将获得参数值）。

创建 POSIX 线程的示例：

```c
#include <pthread.h>
// 线程函数
void *thread_fun(void *num)
{
    printf("线程编号 %d\n", (int)num);
}
// ....................
pthread_t th;
// 创建第二个线程
pthread_create(&th, NULL, thread_fun, (void *)++thread_num);
// 有两个线程正在并行运行
```

新线程开始与创建它的线程并行运行。例如，如果在 `main()` 函数中创建了一个线程，则两个线程将继续执行：一个执行 `main()` 代码的原始程序，以及一个新线程。

### POSIX 线程的完成

要结束一个线程，只需到达其线程函数 `thread_fun()` 的末尾，或者从中调用 `pthread_exit()`：

```c
#include <pthread.h>
void pthread_exit(void *retval);
```

`retval` 参数指定返回代码。这是一个结束线程的示例：

```c
void *thread_fun(void *num)
{
    printf("线程编号 %d\n", (int)num);
    pthread_exit(0);
}
```

对于应用程序启动代码，有两种不同的情况：

- 执行 `return` 语句或执行完 `main()` 中的所有语句会结束整个进程，所有线程也同时结束其执行。

- 在 `main()` 函数内执行 `pthread_exit()` 函数仅结束初始线程；此操作不影响程序中的其他线程——它们将继续执行直到完成。

调用 `pthread_exit()` 函数仅用于连接线程，因为它不释放线程资源——这是线程连接者的责任。

### 等待线程完成

要等待线程完成，请使用 `pthread_join()` 函数。其语法如下：

```c
int pthread_join(pthread_t thread, void **status);
```

此函数会阻塞调用它的线程，直到由句柄指定的线程完成其执行。如果 `status` 不是空指针，它将在调用后指向线程返回的数据（`pthread_exit()` 的参数）。如果在调用 `pthread_join()` 函数时线程已经完成，应立即读取其信息。

## 结论

- 进程和线程是实现代码执行的计算机系统活动资源。线程是一组按顺序执行的处理器指令。进程是一个或多个线程以及它们执行期间所处的受保护地址空间的集合。同一地址空间中的线程可以共享数据，而对于不同进程的线程，除非采取特殊措施，否则无法共享。在传统系统中，每个进程只能执行一个线程的代码执行。现代操作系统支持多线程的概念。

- 在应用程序中使用线程意味着将其并行化——能够同时使用不同的代码片段执行操作。程序并行性反映了外部世界的异步特性，其来源包括多处理器上的代码执行、I/O 操作、用户交互以及客户端应用程序请求。多线程允许应用程序实现这种流程，并达到并行性和效率。

- 存在在进程地址空间的用户模式下运行的用户线程，以及操作系统内核操作的内核线程。它们之间的关系决定了线程模型实现方案。在实践中，通常使用 1:1 方案，即每个用户线程对应一个内核线程，并且内核本身负责管理用户线程。

- 线程可以处于不同的状态（执行、等待、就绪等）。从一个状态移动到另一个状态的原则取决于线程调度和处理器时间调度的原则。将线程从执行状态移动到任何其他状态涉及上下文切换——在保存处理器状态的同时，将控制权从一个线程转移到另一个线程。

- 系统中的每个进程和线程都对应于其控制单元——一个包含所有必要信息的数据结构。在创建过程中（通常通过系统调用 `fork()`），会创建一个控制单元，分配内存并启动主线程。创建线程更快且更容易，因为它们不需要为新地址空间分配内存。

## 第 4 章：进程与线程调度

并行运行线程的能力取决于可用的处理器数量。如果只有一个处理器，原则上不可能并行执行（任何时刻只能执行一个线程）。如果处理器数量为 N > 1，则只能为 N 个线程（每个处理器一个线程）实现并行执行。

单处理器系统调度的主要目的是在单个处理器上安排多个线程，使系统用户产生它们同时运行的错觉。如果线程数量超过可用处理器数量的情况发生调度任务时，此定义可扩展到多处理器系统。

考虑调度的基本类型、原则和算法。

### 调度的基本原则

考虑支持调度的基本原则。

### 线程执行的特点

就调度而言，线程可以表示为计算（CPU 使用）和 I/O 阶段的交替周期。线程仅执行处理器指令的时间间隔称为 CPU 使用间隔（CPU 突发时间），线程等待 I/O 的时间间隔称为 I/O 突发间隔。大多数这些间隔为 2 到 8 毫秒。

那些花更多时间进行计算而较少时间进行 I/O 的线程被称为*CPU 密集型*。它们积极使用处理器。它们的主要特征是花在计算上的时间；对它们来说，CPU 使用间隔较长。那些大部分时间都在等待 I/O 的线程被称为*I/O 密集型*。这类线程对处理器的负载要小得多，它们对处理器使用间隔的平均长度较小。处理器的时钟速度越高，越多的线程可以被归类为第二类。

*   处理器受限线程（矩阵乘法）

*   I/O 受限线程（文本编辑器）

*   I/O 间隔（I/O 密集型）

*   CPU 使用间隔（CPU 密集型）

### 调度机制与策略

应区分调度*机制*和*策略*。调度机制包括上下文切换工具、线程同步工具等，而调度策略是决定何时切换上下文的工具。系统中负责策略的部分称为*调度器*，为此使用的算法称为*调度算法*。

对于调度策略有各种评估标准，其中一些适用于所有系统，另一些仅适用于批处理系统或交互系统。如今，最常用三个标准来评估目标达成情况。

- **最小响应时间。** 这是交互系统最重要的标准。响应时间是指运行线程（或输入交互命令）与获得首次响应之间的时间。对于现代系统，我们采用的时间为 50-150 毫秒。

- **最大吞吐量。** 这是系统单位时间（例如，每秒）可以执行的任务数量。这种标准适用于批处理系统；在交互系统中，可用于后台任务。为了提高吞吐量，必须：

    - 减少浪费的加载时间（例如，上下文切换所需的时间）

    - 更高效地使用资源（确保处理器和 I/O 设备都不空闲）

- 第三个标准是*公平性*，意味着根据重要性分配 CPU 时间。公平性提供了处理器时间的一种分配方式，使所有线程都在其执行中前进，没有任何一个停滞。请注意，实施公平的调度策略并不总是减少平均响应时间。有时这需要使系统变得不太公平。

### 调度原则

线程调度原则首先适用于采用 1:1 方案实现的多线程系统（此处只调度内核线程），也适用于实现进程模块的系统。在后一种情况下，可以用“进程”一词代替“线程”一词，并且调度所需的信息可以存储在这些进程的结构中。对于用户线程数量与内核线程数量不匹配的多线程系统（1:M 和 M:N 方案），使用更复杂的调度原则。它们需要两个调度器：一个用于内核级操作，另一个用于用户模式。

### 调度的类型

区分长期调度、中期调度和短期调度。

#### 长期调度

长期调度意味着确定哪些程序应进入系统以执行负载。由于它不依赖于系统的当前状态，因此也称为静态调度。在批处理系统中，它扮演了重要角色，当时可以预知需要完成哪些进程，并且可以安排任务。在交互系统（例如，具有时间共享的系统）中，加载进程原则上由用户参与，不受调度控制；因此，它们通常使用简化的长期调度策略。系统允许创建进程和线程以达到某个最大限制，之后尝试创建新进程或线程将导致错误。这种策略还基于用户心理，用户在过载系统中感到不适时，可能会中断与系统的工作，这会导致负载降低。

#### 中期调度

中期调度控制暂停线程与就绪状态之间的转换。在准备好执行的控制单元中，线程立即组织到称为就绪线程队列（或就绪队列）的结构中。

以下因素可能导致状态转为暂停状态：

- 等待 I/O 操作

- 等待另一个线程完成（联接）

- 由于需要与其他线程同步而阻塞线程

通常，为了正确组织这种等待，除了就绪线程队列外，还会实现额外的队列集合。每个这样的队列都关联到一个可能导致线程等待的资源（例如，I/O 设备）；这些队列称为*调度队列*或*等待队列*。中期调度器通过在线程之间以及线程与就绪线程队列之间移动线程来管理所有这些队列。

#### 短期调度

短期调度或*CPU 调度*是调度的最重要类型。它回答两个基本问题：

- 何时中断进程流？

- 此时处理器应转移给哪一个待执行的线程？

短期调度器是一个操作系统子系统，它在出现需求时中断活动进程流，并从队列中选择应当执行的那个线程。由于它非常频繁地获取控制权，其性能表现极佳。还有一个控制器（调度程序），它直接控制预先选定的进程流（上下文切换）。
