
`XIMPrimary`、`XIMSecondary` 和 `XIMTertiary` 的值在 R5 规范中定义错误。X way R5 实现正确实现了这些高亮值。这些高亮值在规范中已修正，以与 R6 实现一致。使用 `XIMReverse` 绘制的字符应通过交换前景和背景颜色来绘制未高亮的字符。使用 `XIMUnderline` 绘制的字符应下划线。使用 `XIMHighlight`、`XIMSecondary` 和 `XIMTertiary` 应以独特的方式绘制。

## 预编辑光标回调

输入法可能有自己的导航键，允许用户在预编辑区域移动文本插入点（例如向前或向后移动）。因此，输入法需要指示它应该移动插入点。它调用 `PreeditCaretCallback`。

```c
void PreeditCaretCallback(ic, client_data, call_data);
```

- 指定上下文。
- 指定额外的客户端数据。
- 指定预编辑光标信息。

输入法会在编辑期间触发 `PreeditCaretCallback` 以移动插入点。`call_data` 包含一个指向 `XIMPreeditCCallbackStruct` 的指针，该结构指示光标应该移动的位置。回调函数必须将插入点移动到新位置，并在 `position` 字段中返回相对于初始位置的新偏移值。

```c
typedef struct _XIMPreeditCCallbackStruct {
    int position; /* 预编辑字符串内的光标偏移 */
    XIMCaretDirection direction; /* 光标移动方向 */
    XIMCaretStyle style; /* 光标的反馈 */
} XIMPreeditCCallbackStruct;
```

`XIMCaretStyle` 结构定义如下：

```c
typedef enum {
    XIMIsVisible, /* 禁用光标反馈 */
    XIMIsPrimary, /* UI 定义的光标反馈 */
    XIMIsSecondary /* UI 定义的光标反馈 */
} XIMCaretStyle;
```

`XIMCaretDirection` 结构定义如下：

```c
typedef enum {
    XIMForwardChar, XIMBackwardChar,
    XIMForwardWord, XIMBackwardWord,
    XIMCaretUp, XIMCaretDown,
    XIMNextLine, XIMPreviousLine,
    XIMLineStart, XIMLineEnd,
    XIMAbsolutePosition,
    XIMDontChange;
} XIMCarearetDirection;
```

这些值的定义如下：

- `XIMForwardChar`: 将光标向前移动一个字符位置。
- `XIMBackwardChar`: 将光标向后移动一个字符位置。
- `XIMForwardWord`: 将光标向前移动一个单词。
- `XIMBackwardWord`: 将光标向后移动一个单词。
- `XIMCaretUp`: 在保持水平偏移的情况下将光标向上移动一行。
- `XIMCaretDown`: 在保持水平偏移的情况下将光标向下移动一行。
- `XIMPreviousLine`: 将光标移动到上一行的开头。
- `XIMNextLine`: 将光标移动到下一行的开头。
- `XIMLineStart`: 将光标移动到包含该光标的当前显示行的开头。
- `XIMLineEnd`: 将光标移动到包含该光标的当前显示行的末尾。
- `XIMAbsolutePosition`: 回调必须移动到回调数据中 `position` 字段指定的位置，该位置以字符为单位，从预测文本的开始计算。因此，值为零意味着返回到预测文本的开头。
- `XIMDontChange`: 光标位置不变。

## 状态回调

输入法可以通过三个状态回调与输入上下文状态的变化（例如创建、销毁或焦点变化）进行通信：`StatusStartCallback`、`StatusDoneCallback` 和 `StatusDrawCallback`。

当输入上下文被创建或获得焦点时，输入法会调用 `StatusStartCallback`。

```c
void StatusStartCallback(ic, client_data, call_data);
```

`ic` 指定输入上下文。
`client_data` 指定额外的客户端数据。
`call_data` 此回调未使用，并始终作为 `NULL` 传递。

回调应该为显示状态和响应 `StatusCallback` 调用初始化适当的数据。一旦 `StatusStartCallback` 被调用，在 `StatusDoneCallback` 被调用之前，它将不会被再次调用。

当输入上下文被销毁或失去焦点时，输入法会调用 `StatusDoneCallback`。

```c
void StatusDoneCallback(ic, client_data, call_data);
```

`ic` 指定输入上下文。
`client_data` 指定额外的客户端数据。
`call_data` 此回调未使用，并始终作为 `NULL` 传递。

回调可以释放任何在 `StatusStart` 上分配的数据。

当输入上下文状态已更新更新时，输入法会调用 `StatusDrawCallback`。

```c
void StatusDrawCallback(ic, client_data, call_data);
```

`ic` 指定输入上下文。
`client_data` 指定额外的客户端数据。
`call_data` 指定状态绘制信息。

回调应该通过在状态区域绘制字符串或在状态区域中映射位图来更新状态区域。

`XIMStatusDataType` 和 `XIMStatusDrawCallbackStruct` 结构定义如下：

```c
typedef enum {
    XIMTypeText,
    XIMBitmapType,
} XIMStatusDataType;
```

```c
typedef struct _XIMStatusDrawCallbackStruct {
    XIMStatusDataType type;
    union {
        XIMText *text;
        Pixmap bitmap;
    } data;
} XIMStatusDrawCallbackStruct;
```

反馈样式 `XIMVisibleToForward`、`XIMVisibleToBackward` 和 `XIMVisibleToCenter` 无关，且不会出现在 `XIMText` 结构的 `XIMFeedback` 元素中。

## 事件过滤

Xlib 提供输入法在 Xlib 内部注册过滤的能力。该过滤器由客户端（或工具包）在调用 `XNextEvent` 后通过调用 `XFilterEvent` 调用。任何使用 `XIM` 接口的客户端都应该调用 `XFilterEvent`，以允许输入法在不知道客户端分发机制的情况下处理它们的事件。客户端的用户界面策略可能会决定事件过滤器相对于其他事件处理机制（例如，模态捕获）的优先级。

客户端可能不知道有多少个过滤器（如果有的话）以及它们的作用是什么。它们可能只知道在 `XFilterEvent` 返回时事件是否被过滤了。客户端应该丢弃被过滤的事件。

要过滤事件，请使用 `XFilterEvent`。

```c
Bool XFilterEvent(event, w);
```

- `event`: 指定要应用过滤器的窗口。
- `w`: 指定要应用过滤器的窗口。

如果窗口参数为 `None`，`XFilterEvent` 将过滤器应用到 Xstructure 中指定的窗口。提供窗口参数是为了让 Xlib 之上的事件重定向层能够指示是哪个窗口事件被重定向了。

如果 `XFilterEvent` 返回 `True`，则某些输入法过滤了该事件，客户端应该丢弃该事件。如果 `XFilterEvent` 返回 `False`，则客户端应该继续处理该事件。

如果客户端中发生了捕获（grab）且 `XFilterEvent` 返回 `True`，客户端应该释放键盘捕获。

## 获取键盘输入

要从输入法获取组合输入，请使用 `XmbLookupString` 或 `XwcLookupString`。

```c
int XmbLookupString(ic, event, buffer_return, bytes_buffer,
keysym_return, status_return);
int XmbLookupString(ic, event, buffer_return, wchars_buffer,
keysym_return, status_return);
```
