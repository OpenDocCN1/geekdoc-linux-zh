
`var5 = ''`

如果没有提供变量名，壳变量 `REPLY` 将包含该行数据。

等等，OCR 文本有一些片段：

```
[me@linuxbox]$ read-multiple

Enter one or more values > a b c

var1 = 'a'

var2 = 'b'

var3 = 'c'

var4 = ''

var5 = ''
```

实际上：

可以使用 `-e` 和 `-i` 选项一起为用户提供默认响应。

```bash
#!/bin/bash

# read-default: 如果用户按下回车键，提供默认值。

read -e p "What is your user name? " -i $USER

echo "You answered: '$REPLY'"
```

## Options

`read` 支持表 28-1 中描述的选项。

表 28-1：read 选项

| 选项 | 说明 |
| --- | --- |
| `-a` | 将输入赋值给数组，从零开始。我们将在第35章介绍数组。 |
| `-d` | 使用分隔符中的第一个字符指示输入结束，而不是换行符。 |
| `-e` | 使用 readline 处理输入。这允许以命令行的方式进行输入编辑。 |
| `-i` | 如果用户只需按下 ENTER，使用字符串作为默认回复。 |
| `-n` | 读取输入的 `num` 个字符，而不是整行。 |
| `-p` | 使用字符串显示输入提示。 |
| `-r` | 原始模式。不将字符解释为转义字符。 |
| `-s` | 静音模式。输入时不将字符显示到屏幕上。这在输入密码和其他敏感信息时很有用。 |
| `-t` | 超时。几秒后终止输入。如果输入超时，`read` 返回非零退出状态。 |
| `-u` | 使用文件描述符 fd 的输入，而不是标准输入。 |

使用各种选项，我们可以对 `read` 执行一些有趣的事情。例如，通过 `-p` 选项，我们可以提供一个提示字符串。

```bash
#!/bin/bash

# read-single: 将多个值读入默认变量

read -p "Enter one more values > "

echo "REPLY = '$REPLY'"
```

通过 `-t` 和 `-s` 选项，我们可以编写一个脚本来读取 "secret"，如果输入未在指定时间内完成，则超时。

```bash
#!/bin/bash

# read-secret: 输入密钥密码

if read -t 10 -sp "Enter secret passphrase > secret_pass"; then

    echo -e "\nSecret passphrase = '$secret_pass"

else

    echo -e "\nTimed out" >&2

    exit 1

fi
```

在此脚本中，我们提示用户输入用户名，并使用环境变量 `USER` 来提供默认值。当运行脚本时，它会显示默认字符串，如果用户按下回车键（ENTER），`read` 将把默认字符串赋值给 `REPLY` 变量。

```
$melinuxbox ~]$ read-default

What is your user name? me

You answered: 'me'
```

# IFS

通常情况下，shell 对提供给 `read` 的输入进行单词拆分（word-splitting）。正如我们所看到的，这意味着由一个或多个空格分隔的多个单词将成为输入行的项，并由 `read` 赋值给不同的变量。这种行为由 shell 变量 `IFS`（内部字段分隔符，Internal Field Separator）配置。`IFS` 的默认值包含一个空格、一个制表符和一个换行符，每一个字符都会将项分隔开。

我们可以调整 `IFS` 的值来控制读取时字段的分隔。例如，`/etc/passwd` 文件中的数据行使用冒号作为字段分隔符。通过将 `IFS` 的值改为单个冒号，我们可以通过 `read` 读取 `/etc/passwd` 的内容，并成功将字段分离到不同的变量中。这里有一个执行此操作的脚本：

```bash
#!/bin/bash

# read-ifs: 从文件中读取字段

FILE=/etc/passwd

read -p "Enter a username > " user_name

file_info=$(grep "^$user_name:" "$FILE")

if [ -n "$file_info" ]; then

  IFS=\: read pw uid gid name home shell <<< "$file_info"

  echo "User = $pw"

  echo "UID = $uid"

  echo "GID = $gid"

  echo "Full Name = $name"

  echo "Home Dir. = $home"

  echo "Shell = $shell"

else

  echo "No such user '$user_name'" >&2

  exit 1

fi
```

该脚本提示用户输入系统中账户的用户名，并显示在 `/etc/passwd` 文件用户记录中找到的不同字段。脚本包含两个有趣的行。第一行如下：

```
file_info=$(grep "^user_name:" $FILE)
```

这一行将 `grep` 命令赋值给变量 `file_info`。`grep` 使用的正则表达式确保用户名只会匹配 `/etc/passwd` 文件中的单行。
第二行是这一行：

```
IFS=\: read pw uid gid name home shell <<< "$file_info"
```

行由三部分组成：一个变量赋值、一个带有变量列表作为参数的 `read` 命令，以及一个奇怪的重定向运算符。我们先看变量赋值。
shell 允许在命令之前立即执行一个或多个变量赋值。这些赋值会更改后续命令的环境。这种效果是暂时的，仅在命令执行期间更改环境。在我们的案例中，`IFS` 的值被改为了冒号字符。或者，我们可以这样编写：

```bash
OLD_IFS="$IFS"

IFS=":"

read user pw uid gid name home shell <<< "$file_info"

IFS="$OLD_IFS"
```

在这里我们存储了 `IFS` 的值，分配一个新值，然后将 `IFS` 恢复为原始值。显然，将变量赋值放在命令前面是实现此操作更简洁的方法。
`<<` 运算符表示一个“在此字符串”（here string）。字符串类似于“在此文档”（here document），简而言之由单个字符串组成。在我们的示例中，来自 `/etc/passwd` 文件的行数据被输入到 `read` 命令的标准输入。我们可能会奇怪为什么选择这种晦晦的方法，而不是这种：

```bash
echo "$file_info" | IFS=: read user pw uid gid name home shell
```

# 你不能对 read 使用管道

虽然 `read` 命令通常从标准输入读取内容，但你不能执行以下操作：

```bash
echo "foo" | read
```

我们期望这能正常工作，但它并没有。命令看起来执行成功了，但 `REPLY` 变量将始终是空的。这是为什么？
这与 shell 处理管道的方式有关。在（以及其他 shell 如 `sh`）中，管道会创建子 shell（subshells）。这些是 shell 及其环境的副本，用于执行管道中的命令。在上一个示例中，`read` 在子 shell 中执行。
Unix 类系统中的子 shell 在执行时会创建环境的副本。当进程结束时，环境副本会被销毁。这意味着子 shell 可以更改其父进程的环境。`read` 分配变量，这些变量随后成为环境的一部分。在上一个示例中，`read` 在其子 shell 环境中为变量 `REPLY` 赋值 `foo`，但当命令退出时，shell 及其环境被销毁，赋值的效果丢失了。
使用在此字符串（here strings）是规避这种行为的方法之一。另一种方法将在第36章中讨论。
