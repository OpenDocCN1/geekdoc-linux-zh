
```bash
#!/bin/sh
## 差异备份
# 这使用哨兵文件的时间戳
touch HOME/backup/last-full
# 以允许我们使用这个
find $(bakdirs) -mount -type d
-newer $HOME/backup/last-full -print
| tar c12zf - - buffer -o /dev/sto
```

正在运行的文件不会在下一次增量备份中备份。我们可以尝试其他选项来 `touch` 文件，但在使用 `GNU-date` 命令和 shell 算术（或 `expr` 命令）来计算这些日期时，这些操作并不是必需的。另一种方法是在执行 `tar` 之前 `touch` 临时文件，然后在 `tar` 完成后使用 `mv` 更改临时文件的名称，如下所示：

```bash
touch filename.NEW
tar
mv filename.NEW filename
```

因此，这里是脚本的改进版本。第一个执行的是**差异备份（differential backups）**，第二个执行的是**增量备份（incremental backups）**：

```bash
#!bin/sh
# 差异备份脚本（带有日期运算）
# 这使用 -root/backup/last-full 的时间戳
# 因此该文件必须由我们的零级备份方案
# touch（且不再进行其他操作）
START_TIME=$(( $((date +%s)) - \
DAYS_SINCE=$(( $((date -d "$HOME") +%s)) / 86400 ))
find $(backdirs) -mount -type d \ -ntime="$DAYS_SINCE" \
tar cSlZf -- buffer -o /dev/nst0
```

```bash
#!bin/sh
# 增量备份脚本
# 这使用 -root/backup/last-full 的时间戳
# 因此该文件必须由我们的零级备份方案
# touch（即由本脚本*且不再进行其他操作*）。
touch $HOME/backup/last-backup.new
find $(backdirs) -mount -type d \ -nt - $HOME/backup/last-backup -print0 \
tar cSlZf -T - | buffer -o /dev/nst0
mv $HOME/backup/last-backup.new $HOME/backup/last-backup
```

这里的的主要区别在于（这看起来并不明显）使用了哪个哨兵文件（或日期戳）。在后一种情况下，我们在开始备份之前 `touch` 一个“新”文件，并使用该文件的时间戳作为“引用”来设置哨兵文件的时间戳。

如果有这些备份脚本或任何程序并发运行该驱动器的可能，那么设置锁文件（`lock files`）是明智的。`procmail2` 带的 `lockfile` 程序应该足够了。

注意：我们还在此示例中包含了另一个增强——在对应的 `--null` tar 选项上使用 `-print0` 指令。此命令生成

```
4. http://www.procmail.org/
```

一个以 NUL 终止的链接列表（也称为 ASCIIZ 字符串），此 cpio 示例中的 `-0` 标志对应于来自 find 的 `-print0` 指令。因此，此命令将正确处理退化文件名。

## 使用 cpio

`cpio` 是另一种传统的备份和文件系统归档工具。它的工作方式与 `tar` 非常不同。早期版本相比旧版本的 `tar` 具有主要优势。目前 GNU 版本的 `tar` 和 `cpio` 具有相当的功能，尽管它们的使用方法仍然大不。

在许多方面，`cpio` 指定要备份和恢复的文件和目录的方法与 `tar` 方法似乎相反。在创建归档时，`tar` 将文件和目录名称列表作为命令行参数。每个命名为 `tar` 的目录都会递归遍历。要使用 `cpio` 创建归档，必须为其提供一个对象列表（文件和目录名称、任何设备节点名称、UNIX 套接字、命名管道等）。这通常通过管道输入到 `cpio` 的标准输入（`stdin`），并通常通过命令生成。

备份整个文件的简单命令如下：

```bash
find / -print0 | cpio -o0 > /dev/st0
```

这比最少需要的要复杂一些，因为再次使用了 `-print0` 指令和 `cpio` 的“零”选项，以使脚本在面对“奇怪”文件名时更加健壮。

当然，这个示例遇到了我们之前提到的问题之一，例如我们的第一个 `tar` 命令会链接到 `/proc` 等目录。我们通过调整 `find` 的参数来修复这个问题：

```bash
find * -fype ext2 -print0 | cpio -o0B > /dev/st0
```

在这个示例中，我们将备份限制为仅 `ext2` 文件系统。隐藏的文件和目录（以点开头的）被跳过了。

## 备份：远程磁带驱动

磁带驱动是昂贵的。UNIX 的优点之一是我们可以轻松访问远程设备。访问远程磁带驱动几乎和访问本地连接的磁带一样容易。

```bash
find /* -fype ext2 -print0 | ssh $TAPEHOST "cpio -o0B buffer -o /dev/st0"
```

在这个示例中，我们使用了 `ssh`，它是 `rsh` 流行的安全替代品。`rsh` 效果确实很好，但允许使用 BSD `r*` 命令通常是糟糕的安全策略。存在 Kerberos 增强版本的 `rsh`、`login` 和 `rcp`，它们提供了合理的安全性和加密。

注意在使用远程驱动器时始终使用 `buffer`。更多关于 `buffer` 的信息请参见143页。

此外，`buffer` 也可以反向使用，从远程系统提取文件并写入本地磁带驱动器：

```bash
ssh $OTHERHOST
find /* -fype ext2 -print0 | cpio -oB | buffer -o /dev/st0
```

## 备份：本地挂载的文件系统

在本地挂载的可移动文件系统上备份的唯一技巧是确保不要递归进入目标目录。

考虑对挂载在 `/mnt/more`（一个磁光驱动器）的可移动驱动器进行备份。如果我们使用 `find` 的 `-xdev` 选项来防止进入其他文件系统，这就不是问题。然而，如果我们不使用 `-xdev`，就必须小心。

## 恢复：本地磁带驱动

`cpio` 和 `tar` 的另一个区别在于绝对路径。默认情况下，`cpio` 不恢复目录，所以我们必须添加 `-d` 关。

```bash
cpio -id < /dev/st0
```

从本地磁带恢复：

`cpio -id < /tmp/tst.cpio`

## 恢复：远程磁带驱动

从远程磁带恢复只需是“反转”我们发送时的操作。例如：

```bash
ssh $TAPEHOST -buffer i /dev/st0 | find /* -fype ext2 -print0 | cpio -id
```

## NFS

你可能注意到我们避免了在 NFS 上执行备份的示例。这有很多原因。通过 TCP 管道传递数据归档通常比 NFS 更可靠。此外，大多数 NFS 安装执行根抑制（root squashing）并有其他局限性。

## 使用 AMANDA

许多系统管理员编写自己的脚本并手动进行大部分卷管理和磁带处理。其他人使用如 Legato Networker 和 Cheyenne/CA ARServer 这样的大型商业软件包。

两者之间的折中方案是 AMANDA，由马里兰大学开发并由整个开源社区维护的高级 Maryland自动磁盘归档工具。尽管它有一些局限性，但 AMANDA 仍在不断改进。

AMANDA 管理从一组网络客户端（服务器和工作站）到磁带主机上的临时磁盘溢出全量和增量备份的过程。然后，这些数据集被写入磁带。

完全是自动的。一个 `cron` 任务（在每个磁带主机上）会检查并确保每个磁带驱动器加载了正确的磁带，确保所有客户端均可访问，并且存储磁盘上有足够的可用空间。这通常在白天进行，以便任何错误都能通过邮件发送给备份操作员和系统管理员列表，从而及时更换磁带并修正其他错误。另一个 `cron` 任务（通常在深夜）实际上执行备份工作——从磁带主机连接到每个客户端。它具有并行执行这些连接的功能，并能监控和限制自身的带宽利用率。一个模块（计划器）决定了对每个文件文件或主机执行何种级别的增量备份。

在底层，AMANDA 使用 `dump` 或（可选的）`tar` 进行存档。因此（通过一些 `dd` 和 `mt` 脚本），可以使用传统工具提取 AMANDA 存档。通常使用 AMANDA 的 `amrecover` 命令。
