
`display` 指定到 X 服务的器的连接。

`XDisableAccessControl` 函数会在每次连接设置时禁用访问控制列表。

`XDisableAccessControl` 可能会产生 `BadAccess` 错误。

# 第 10 章 事件

客户端应用程序通过你用 `XOpenDisplay` 函数建立的连接与 X 服务器通信。客户端应用程序通过此连接向 X 服务器发送请求。这些请求是由客户端应用程序中调用的 `Xlib` 函数发出的。许多 `Xlib` 函数会引起 X 服务器产生事件，用户的打字或移动指针也可以异步产生事件。X 服务器通过同一条连接将事件返回给客户端。

本章讨论了与事件相关的以下主题：

- 事件类型
- 事件结构
- 事件掩码（Event masks）
- 事件处理

处理事件的函数将在下一章中讨论。

## 事件类型

事件是由 X 服务器根据某些设备活动或作为 `Xlib` 函数发送的请求的副作用而异步生成的。与设备相关的事件从源窗口传播到祖先窗口，直到客户端应用程序选择了该事件类型，或者该事件被显式地丢弃。通常，只有当客户端专门请求通知其该类型的事件时（通常通过设置窗口的 `event-mask` 属性），X 服务器才会向客户端应用程序发送事件。掩码也可以在创建窗口时或通过更改窗口事件时设置。你也可以通过操作窗口属性的 `do-not-propagate` 掩码来屏蔽传播到祖先窗口的事件。然而，`MappingNotify` 事件会被发送给所有客户端。

事件描述了 X 服务器生成的特定事件。对于每个事件类型，`<Xlib/X.h>` 中都定义了相应的常量名，在引用事件类型时使用。下表列出了事件类别及其相关的事件类型或类型。与这些事件相关的处理将在第 10.5 节讨论。

### 事件

| 事件类别 | 事件类型 |
| --- | --- |
| 键盘事件 | KeyPress, KeyRelease |
| 指针事件 | ButtonPress, ButtonRelease, MotionNotify |
| 窗口跨越事件 | EnterNotify, LeaveNotify |
| 输入焦点事件 | FocusIn, FocusOut |
| 键位映射状态通知事件 | KeymapNotify |
| 暴露事件 | Expose, GraphicsExpose, NoExpose |
| 结构控制事件 | CirculateRequest, ConfigureRequest, MapRequest, ResizeRequest |
| 窗口状态通知事件 | CirculateNotify, ConfigureNotify, CreateNotify, DestroyNotify, GravityNotify, MapNotify, MappingNotify, ReparentNotify, UnmapNotify, VisibilityNotify |
| 颜色映射状态通知事件 | ColormapNotify |
| 客户端通信事件 | ClientMessage, PropertyNotify, SelectionClear, SelectionNotify, SelectionRequest |
