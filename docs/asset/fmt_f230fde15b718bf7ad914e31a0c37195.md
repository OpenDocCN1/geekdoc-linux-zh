
## 描述

使用 `mv` 命令将文件从一个位置移动到另一个位置，或重命名文件。

在种概要形式中，`mv` 命令将源操作数指定的文件移动到 `target-file` 指定的目标位置。`source` 和 `target-file` 不能有相同的名称。如果 `target-file` 不存在，`mv` 将创建一个名为 `target-file` 的文件。如果 `target-file` 存在，则其内容将被覆盖。当最后一个操作数没有指定已存在的目录时，采用此种概要形式。

在第二种概要形式中，`mv` 将每个源操作数指定的文件移动到名为 `target-dir` 的现有目录中的目标文件。每个源的目标是目标目录、单个斜杠字符 (`/`) 以及源的最后一个路径名组件的拼接。当最后一个操作数指定了一个已存在的目录时，采用此第二种形式。

如果 `mv` 确定 `target-file` 禁止写入，它将打印模式（参见 `chmod(2)`），请求响应，并从标准输入读取一行。如果响应为肯定，则在许可的情况下执行移动；否则，命令退出。

请注意，如果目标与访问控制列表（ACL）关联，则显示的命令可能无法完全代表访问权限。当源的父目录可写且设置了粘滞位（sticky bit）时，必须满足以下条件之一：

- 用户必须拥有该文件。
- 用户必须拥有该目录。
- 文件对用户可写。
- 用户必须是特权用户。

如果 `source` 是文件且 `target-file` 是指向另一个带有链接文件的链接，则其他链接将保留，`target-file` 将变为一个新文件。

如果 `source` 和 `target-file` 或 `target-dir` 在不同的文件系统上，`mv` 会复制源并删除原始；对其他文件的任何硬链接都会丢失。`mv` 将源特性复制到目标，即所有者和组 ID、权限模式、修改和访问时间，以及如果适用的 ACL。对于符号链接，`mv` 仅保留链接本身的所有者和组。

如果无法保留所有者和组，`mv` 将清除目标中的 `setuid` 和 `setgid` 位。如果无法清除这些位，`mv` 会向标准错误打印诊断信息，但退出码不受影响。`/usr/xpg4/bin/mv` 会对所有失败复制文件特性的尝试向标准错误打印诊断信息；退出码不受影响。

为了保留源文件特性，你必须具有适当的文件访问权限，包括超级用户权限或与目标文件具有相同的所有者 ID。

> 注意 — 你可以使用 `--` 来显式标记任何命令行选项的结束，使 `mv` 能够识别以 `-` 开头的文件名参数。对于 BSD 迁移，`mv` 接受 `--` 的同义词。此迁移辅助可能会在未来的版本中消失。如果同一命令中同时出现 `--` 和 `--`，则该行被解释为文件名。

## 选项

- `-f` 移动文件(s) 而不提示，即使它正在覆盖现有目标。注意，如果标准输入不是终端，则这是默认设置。
- `-i` 每当移动将覆盖现有目标时，提示确认。肯定的回答意味着继续移动。任何其他回答都会阻止 `mv` 覆盖目标。

`usr/bin/mv` 同时指定 `-f` 和 `-i` 选项被视为错误。`f` 选项覆盖 `-i` 选项。

`/usr/xpg4/bin/mv` 同时指定 `-f` 和 `-i` 选项被视为错误。最后一个选项决定 `mv` 的行为。

## 参数

`source` 要移动的文件或目录的路径名。

`target-file` 被移动的文件或目录的新路径名。

`target-dir` 输入文件的现有目录路径名。

## 使用

遇到大于 2GB 文件的 `mv` 行为请参见 `largefile(5)`。

## 环境变量

参见 `environ(5)` 影响 `mv` 执行的环境变量：`LC_CTYPE`、`LC_MESSAGES` 和 `NLPATH`。

## 状态

- `0` 所有文件已成功移动。
- `>0` 发生错误。
