### 为什么要通信？

在技术领域内有四种通信方式：

- 计算机对计算机
- 人与人
- 计算机对人
- 人对计算机

出于不同的原因，这些对我们都很重要。第一种（计算机对计算机）已在第1章中介绍，它允许根据基于时间或逻辑的程序来自动控制设备。

人与人之间的通信是每天都会发生的，但现在可以由技术来促进。在电话问世之前，我们唯一的实时通信形式是面对面交流。现在我们有了电子邮件、互联网中继聊天（IRC）、即时通信（IM）和短信来完成同样的任务。这些都去掉了“面对面”的元素。

我们还精简了现有的通信媒介。电话曾经音质差且必须用线路连接到固定地点，现在则已成为移动设备。通过IP语音（VoIP）技术，你可以利用互联网（几乎）免费的成本来节省开支，而一旦与移动技术相结合，就出现了一个有趣的场景：用手机通过网页在线订购披萨！

当我们谈到计算机对人类的通信时，我们关注的是计算机适时发送给我们的关于房屋的报告和信息。在最简单的情况下，这可能是每日的唤醒呼叫，或一封包含当天电视节目单的电子邮件。在更复杂的场景中，它可能是关于家中各台计算机及其运行状况的完整报告。³

³ 如果你有多台机器，像`Nagios`这样的软件可以自动监控服务和应用程序，在出现故障时发送消息并更新网页。

最后，人对计算机的通信最为常见，涉及我们通过电子邮件、短信或网页告诉机器我们想做什么。要成为真正智能和自动化的房屋，这个列表还应包括触觉接口。我们不需要发出明确的命令来告诉计算机该做什么；它通过感知环境就能知道该做什么。例如，当前门被打开时，计算机会知道要打开灯；紧接着，由于判断出有人正在进入房屋，门内的地垫传感器会闭合。你在第2章中已经构建了类似的触觉功能，所以本章将介绍显式通信。

### IP电话

IP电话或VoIP通信已很常见，是任何智能家居的标配功能。然而，由于电话通信具有个人属性，对大多数人来说，VoIP的安装将是私人性质的，只存在于个人笔记本电脑或台式机上。但它可以与语音识别结合使用，提供一种有趣（尽管容易出错）的数据输入方式，以及添加家庭内部对讲系统的方法。

#### Skype

正如*胡佛*已成为吸尘器的代名词，*谷歌*现在是一个意为“搜索”的动词一样，*Skype*是VoIP的代名词。`Skype`始于2003年，以免费软件形式发布，为Linux、Mac和Windows提供了客户端，各自功能不尽相同，所有版本都允许你像使用任何标准电话一样，免费呼叫其他`Skype`用户，并以补贴价格呼叫手机号码和固定电话。大多数版本允许你从多个不同位置使用同一账户登录，这意味着你可以在家中的每台终端上安装`Skype`，并使用同一个面向家庭的电话号码，从而在家中的任何房间接打电话。借助额外的硬件，你可以采用免提方式，在通话过程中在不同房间之间走动，比如去查看晚餐的情况，这让你重新体验到自20世纪80年代无绳电话问世以来就存在的漫游能力！

#### Asterisk

`Asterisk`是另一个基于软件的电话解决方案，同样支持VoIP、移动电话和固定电话呼叫。它对我们的好处在于，它是真正意义上的自由软件，并且支持多种协议，因为它是一个完整的专用交换机（PBX），支持高度可配置的呼叫转接、语音邮件、电话会议和电话菜单（所以你可以实现自己的“按1打开你的灯”系统！）。与`Skype`一样，你需要一个服务提供商网关，将基于IP的协议连接到普通电话网络。这是一项付费服务，可以从很多地方购买，包括`Skype`自己的`Skype`转`Asterisk`模块。作为替代方案，可以使用FXO接口，让你将SIP与PSTN对接。你仍然需要购买FXO接口（大约15美元），但你只需要从电话服务提供商那里购买即可。

目前，安装`Asterisk`这堆代码的最简单方式是通过`FreePBX`，但即便如此，只有在你的房子大到喊人都听不见，或者你是手机重度用户时，才值得花这个时间，因为你可以通过电子邮件、网页（现在大多数手机都能使用这两者）或短信获得更稳定的通信。

### 电子邮件

电子邮件现在是全世界个人和职业生活的命脉。在任何时间给任何人发送和接收消息都非常容易——事实上是太容易了，大多数垃圾邮件文件夹的状态就是明证！但电子邮件已成为常驻技术，所以我们可以将电子邮件添加到房屋将支持的协议列表中，让我们可以向视频设备、电灯开关或电视发送消息，也让房屋向我们发回消息。

#### 在Linux中准备电子邮件

电子邮件的传输路径在任何地方都是相同的，由三部分组成：

- *邮件传输代理（MTA）：* `MTA`也称为电子邮件服务器，它是通过简单邮件传输协议（SMTP）与其他`MTA`通信的软件，将收到的电子邮件路由到正确的收件人，它记录目标地址并将其传递给那台机器上的服务器。
- *邮件获取：* 这是将电子邮件从邮件服务器传输到客户端的方法。这种数据传输通过邮局协议（POP）或互联网消息访问协议（IMAP）进行。在我们的场景中，这两者将在同一台机器上，因为我们将运行自己的`MTA`，但它们不必在同一台机器上，因为我们也可以将Google Mail下载到本地机器进行处理，这将在第6章中介绍。
- *邮件用户代理（MUA）：* 这是实际阅读和发送电子邮件的客户端软件。这包括`Thunderbird`等大型GUI应用程序、AtMail等Web邮件解决方案，以及`Mutt`等较小的基于控制台的程序。

尽管企业人士会喋喋不休地吹捧`Exchange`作为`MTA`的优势（http://en.wikipedia.org/wiki/Comparison_of_mail_servers），但你有四个主要的电子邮件服务器可供选择，而且`MUA`的选择也远不止`Outlook`一种。此外，由于Linux（以及一般的类Unix系统）的设计，你可以非常灵活地自动处理收到的邮件，并发出非交互式命令来发送回复。

每个`MTA`都有其他`MTA`不具备的优点和功能。四大`MTA`——`Exim`、`qmail`、`Postfix`和`Sendmail`——各有其支持者和批评者。我个人使用`Exim`，因为它有引导式安装，之后“直接就正常工作了”。如需其他看法，有一个wiki页面介绍了这些软件包的最新版本以及一些商业产品。我会在这里等你安装其中一个。

#### 发送电子邮件

在安装服务器，并通过给自己（以及第二个用户）发送一两封邮件进行测试之后，你就可以开始编写自动发送脚本这个简短的任务了。这是用Linux做的最简单的事情之一，涉及`mail`命令，该命令可以发送带有任意数量附加标题和设置的电子邮件。在这里，你只需要一个如下所示的抽象脚本：

```bash
#!/bin/bash

SUBJECT=$1; shift
TOADDR=$1; shift
MSG=$*

echo "$MSG" | mail -s "$SUBJECT" "$TOADDR"
```

```
xmitemail "Hello" "steev@workaddress.com" "I bet you didn't think this would work!"
```

这条命令会发送所示的那封简单电子邮件，你可以通过在命令行输入来调用它，从每日的 `crontab` 触发它，或作为某个其他家庭事件的后果来运行。例如，有人穿过前门（使用第 2 章的 Arduino 门垫）时就可以发出这样一封邮件，或者当某个硬盘空间过满时，也可以将其作为警告发出。

我在这里颠覆了 `mail` 的原始接口，因为用户更习惯以之前所示的方式调用该命令。然而，有时你可能想恢复 `mail` 的原始用法，让脚本接受来自 STDIN 的任何输入。这需要用下面所示的三行代码替换来接管 `MSG`：

```
if [ $# -eq 0 ]; then
    while read LINE ; do
        MSG="$MSG"^M"$LINE"
    done
else
    MSG=$*
fi
```

请注意 `^M` 字符，该字符在 `vi` 等编辑器中通过按 Ctrl+V 后跟 Ctrl+M 输入。现在可以从文件输入消息了，如下所示：

```
cat filename | xmitemail "Here's the file" "steev@myworkaddress.com"
```

在第 7 章中，你将学习如何扩展此功能，以支持基本地址簿和多个收件人。

## 自动处理电子邮件

代表程序（而非人类用户）接收电子邮件，可以用一个词来概括：`Procmail`。[^4] `Procmail` 是 Stephen R. van den Berg 于 1990 年开始的一个项目，用于控制电子邮件消息的投递；尽管有些人认为它已是一个死项目，但这反倒使它成为一个稳定的项目，一个不太可能很快出问题或引入新麻烦的项目！

`Procmail` 由电子邮件服务器（`MTA`，如 `Exim`）触发，服务器将每条消息依次传递给一系列规则（recipe）进行进一步处理。如果这些规则中没有一个认领该消息，则按正常方式投递。

我将从创建一个简单的方案开始，通过它你可以用电子邮件控制卧室的灯开关。因此，首先用以下命令创建一个用户，并填写所有必要的用户详细信息：

```
adduser bedroom
```

然后，在其主目录中创建一个 `.procmailrc` 文件（注意那个点！），并添加以下规则代码：
