
# 零信任原则

零信任原则由 Forrester Research 开发，它放弃了不可信的外部网络和信任内部网络的想法，而是假设所有流量都是不可信的，所有资源都可能已被入侵，因此你网络中的一切内容都必须经过单独保护。这种想法类似于安全的办公大楼：进入大楼有门禁、访问每楼层的安全控制、所有走廊都有闭路电视摄像头、所有门都有卡锁、保险箱有钥匙或访问代码、电脑甚至储物柜等，从不假设之前的安全措施是成功的。

零信任原则也可以表示为“从不信任，始终验证”，这意味着你必须对安全（特别是对内部威胁）做最坏的打算。（有关涉及信任的极端风险情况，请参见“不信任任何人”侧栏。）这都归结为以下三条规则：

- 1. 无论资源位置或流量来源，对内部或外部资源的所有访问必须是安全的。所有连接都应被视为数据中心外部的。通常情况下，内部用户的连接受到的限制和控制较少。这通常可以通过加密隧道来实现——一种广为人知、标准且广泛提供的安全措施，在原则上应证明易于应用于任何网络。
- 2. 所有用户均受“按需告知”限制性访问策略限制，根据他们在公司内的职责，允许他们使用特定资源。这是“最小权限原则”（我稍后会描述）的应用。
- 3. 所有网络流量必须经过记录和检查。记录（一种被动解决方案，便于后续取证分析）通常在系统中完成，但实时检查（一种防止当前问题的主动哨兵）更为罕见。

## 最小权限

这可能是我在这里涵盖的最老的原则。它于 20 世纪 70 年代起源国防部（`DOD`）。尽管年代久远，它仍然是一个基础且重要的设计考虑因素，不仅从安全角度，还从容错性（处理组件或系统的故障）角度。

最小权限原则（或“最小授权”）基本上意味着进程或用户应该只有完成其工作不受阻碍所需的权限（特权、许可），而不再更多——换句话说，是“几乎不存在”的权限。这条规则有两个推论：

- 默认权限：默认访问规则应为“零访问”——完全缺乏访问。
- 权限封锁：如果需要并授予了临时访问，应在在使用后立即撤销。

针对系统级操作的限制使得利用漏洞变得困难。部署（应用程序所需的权限越少，其部署越简单）和稳定性（对系统产生的更改越受限，对其他程序产生负面副作用的可能性越低）也受到这一原则的积极影响。

一种受网络访问控制和基础设施软件支持的标准技术是基于角色的访问控制（我之前提到的）。回顾一下，首先为不同的功能定义角色，并为这些角色分配所需的权限。`RBAC` 优于经典的 `ACL`（访问控制列表），因为它允许更精细的粒度方法。例如，`ACL` 可能会允许或禁用对给定文件的访问，但用户在其实际操作方面将受到更多限制。一方面，通过 `RBAC`，你可以定义“创建账户”或“更改地址”等操作，并且用户受到更多限制；另一方面，更细粒度也意味着更多的角色需要管理——所以有得有失。

然而，实施最小权限并非如此简单。定义细粒度策略（以便进程获得所需的权限）是复杂的，因为某些需求可能是动态定义的，导致可能会实施宽松策略。一个完整的实施计划包括以下步骤：

- 汇总所有资源的信息，包括软件（系统、数据库）和硬件（计算机设备、通信设备），以定义适当的安全级别。
- 根据工作职责定义角色和子角色列表，并为每个角色指定所需的访问。此任务应涉及所有利益相关者以阐述需求；让 IT 部门集中完成会导致失败。
- 在所有系统中整合 `RBAC`，包括内部开发的、商业应用、遗留系统等，并进行测试。
- 对上述所有内容进行定期审查。每年一次是合适的，并检查所有工作、功能、角色和权限。

## 实时可见性

攻击总是实时发生的，这使得实时安全成为基本需求。你的工具必须是主动的并有助于阻止事件，而不是被动的仅仅让你知道事实。安全团队检测入侵的时间越长，恶意软件利用的时间就越长，因此及时发现红旗并拥有足够的信息来采取行动是值得的。你必须立即监控各种事件，包括：

- 系统资源和指标，例如内存使用率、`CPU` 负载或运行进程，这些可以让你知道入侵者正在运行。
- 网络相关事件，例如失败的访问尝试、`DNS` 查询和异常的端到点连接，这些指向恶意软件感染或入侵尝试。
- 关键（可能是系统）文件和其他配置更改，因为意外的更改可能意味着存在根程序。
- 可执行文件的到达（及执行），需特别注意不符合逻辑的扩展名：计算机图形文件不应该是可执行的，而办公套件不应派生外部进程。
- “传输中”的敏感数据（文件、数据库），可能预示着正在进行数据窃取攻击。
- `USB` 设备，它可以被用作入口、键盘记录器或许多其他恶意软件种的载体。

更复杂的情况是，并非每一个异常都意味着实际的安全威胁或入侵。举一个简单的例子，不常见登录的激增可能与销售人员根据特定公司的销售周期使用 `CRM` 软件规划其每月计划有关。因此，持续的日志分析必须足够灵活并允许微调，这样你才不会淹没在假阳性报警中。

## 合规性保证

这一原则意味着能够证明你正在遵守任何和所有相关法规。如果执行不当，成本可能会非常高，因为它可能导致罚款或法律成本，这些与恶意软件造成的任何损害是独立的。

公司必须遵守几项强制性法规（法律、联邦和地方标准、合同等），这不可避免地意味着要为内部和外部审计产生适当的轨迹；参见表 3。

安全领域没有单一的“银弹”，你所能做的只是在攻击者的道路上设置一系列障碍，使入口变得尽可能复杂；如果失败了，则让他们难以利用入侵后的结果。这种多层方法是一件好事。如果你依赖单一防御，攻击者可以集中精力攻击它，在获得访问权限后，你服务器中的所有东西都将大敞开。

# 不信任任何人

开源通常被认为在安全性方面更好，因为有“众目效应”的概念——只要有足够的人检查某个软件，所有的 Bug 都是微不足道的，所有问题都能被检测和修复。

`UNIX` 的创建者之一肯·汤普森（Ken Thompson）在获得 `ACM` 图灵奖时发表的“信任”（Trusting）演讲中，解释了如何编写一个编译器，能够在所有编译后的程序中植入任何特定的、所需的木马代码（例如“登录”工具），并展示了编译器本身如何被黑客利用，使用户永远察觉不到修改，即使他们拥有原始源代码也是如此——精妙又邪恶！

访问 `http://cm.bell-labs.com/who/ken/trust.html` 查看汤普森的演讲；这绝对值得读。

为了获得最可靠的保护，你需要同时考虑防御和监控，以防你的防御失效。

## 实时风险管理

正如我提到的，安全威胁格局在不断变化和演变，因此你的安全实践应该能够处理这些变化。企业系统也在许多驱动因素的推动下快速变化：移动性、云计算、服务、虚拟化和容器、`Web` 等等。新环境加上新威胁构成了一个不稳定的混合物。`ESG`（企业战略集团，`http://www.esg-global.com`）将实时风险管理（`RTRM`）定义为基于以下三个原则的实践：

- 瞬时知识：需要资产变化、漏洞评估和威胁数据的实时信息，以便你尽快采取行动。
- 全面可见性：信息覆盖范围应足够广泛，并考虑到所有存在的漏洞。
- 对控制措施的持续评估和调整：安全不是一个“设置后即忘记”的功能；相反，控制措施需要定期修订以确保它们运行良好。

实现这些目标需要能够检测复杂威胁的能力、超越特定热点检测的高级网络监控、跟上安全和恶意软件格局所有变化的威胁监控情报，以及高水平的自动化以确保完整、一致的24/7监控。

## 杀毒软件

正如我之前提到的，这本质上是一个事后工具，只有在发现并分析给定威胁后才起作用。这自动施加了两个限制：首先，只有已经出现（且出现在足够地方）的恶意软件才会进入杀毒公司的范畴；其次，由于 Windows 更容易受到感染，这些公司可能会少关注 Linux 服务器，从而延迟可能的解决方案。

## 补丁策略

鉴于大多数缺陷源于系统软件的漏洞，你可以认为保持系统更新是最必要的措施。当然，你不能盲目地安装任何种类的更新，否则可能会遇到麻烦。大多数 Linux 发行版识别两种更新：安全更新（自动下载并应用）和其他所有更新（需要特定批准）。这意味着，如果补丁不被视为严重威胁，你可能会错过重要的补丁，因此你需要对所有更新保持警惕。

另一方面，有时你需要前沿的软件包，并可能希望直接从开发者网站使用最新的代码。这在某些方面是有益的（例如消除某些缺陷），但它增加了安全风险。如果采取“接受一切”的策略，你可能会获得带有新的、未检测问题的软件包。

在生产服务器上，你必须在经过严格测试的旧版本（可能存在攻击者可以利用的旧 Bug）和全新的最新版本（可能存在未发现的 Bug）之间取得平衡。

总结来说，良好的补丁管理策略应该包括：

- 一个通用的硬件和软件清单，包括所有使用的软件软件包的版本号，并保持更新。此清单可以与发现的漏洞关联以帮助程序补丁活动。
- 使用标准化配置来简化补丁测试和软件更新。
- 在通用应用之前的补丁测试流程，检查它们是否会影响正常操作。
- 补丁部署和验证流程，可能包括特定的备份，以便在补丁产生意外影响时将系统恢复到之前的状态。

## 应用白名单

应用白名单的基本思想与零信任原则有关。与其尝试阻止可疑软件但默认运行其他一切，你选择默认阻止所有软件并仅允许特定程序运行。
