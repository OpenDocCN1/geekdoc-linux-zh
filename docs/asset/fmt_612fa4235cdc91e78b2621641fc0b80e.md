
### 9. 脚本参数解析
`cp` 命令是脚本中调用的唯一命令，该命令复制文件。由于脚本反向将参数（`$1` 和 `$2`）传递给 `cp`，它们的顺序反转了——`cp` 将第一个参数复制到第二个名称，`cp1.sh` 将第二个参数复制到第一个名称。因此，选项 C 是正确的。由于 `cp` 参数的顺序反转，选项 A 是错误的。`cp` 命令与编译（选项 B）或转换（选项 D）C 或 C++ 程序无关，脚本也是如此。脚本第一行对 `bash` 的引用标识了该脚本本身是一个 `bash` 脚本；它并没有导致脚本的参数作为 `bash` 运行；

### 10. 循环结构
`for`、`while` 和 `until` 循环位于 `do` 和 `done` 之间。因此，选项 E 是正确的。`if-then` 语句是条件判断而不是循环，所以选项 A 是错误的。双分号用于 `case` 语句而不是循环，所以选项 B 是错误的。`case` 关键字以 `esac` 结束，因此选项 C 是错误的。

### 11. 脚本解释器
C。有效的脚本以 `#` 和程序的完整路径开头。选项 B 和 C 都符合描述，因为 `bash` 是一个 `shell` 且在 Linux 系统可用，但前两个字符顺序反反了，所以这些选项是错误的。

### 12. 有效循环语句
A, B, D。`for`、`while` 和 `until` 语句都是 `bash` 中有效的循环语句，所以 A、B、D 都是正确的。`bash` 中的 `if-then` 语句测试条件，如果为真则执行其命令。因此，选项 C 是错误的。`case` 语句是条件判断而不是循环语句，所以选项 E 是错误的。

### 13. 邮件别名
当别名配置正确时，发送到别名的任何邮件由别名账户接收。因此，选项 B 是正确的。`postmaster` 用户不会接收该邮件，因为别名被设置为 `john`，所以选项 A 是错误的。`~/.forward` 文件与邮件重递有关，而不是别名。因此，选项 C 是错误的。`root` 没有理由接收这封邮件，所以选项 D 是错误的。别名允许邮件发送到别名账户，所以选项 E 中的陈述没有意义且是错误的。

### 14. Fetchmail 工具
`Fetchmail` 程序是从远程 POP/IMAP 服务器检索邮件并注入本地（或远程）SMTP 队列的工具。因此，它不是 SMTP 服务器，所以选项 C 是正确的。`Postfix`（选项 A）、`sendmail`（选项 B）、`Exim`（选项 D）和 `qmail`（选项 E）都是流行的 SMTP 服务器。

### 16. 查看邮件队列
要查看邮件队列，使用 `mail` 命令（选项 D）。`sendmail status` 命令是 SysV 服务状态命令，不显示邮件队列，所以选项 A 是错误的。选项 B 是错误的。选项 C 接近，但正确的命令是 `sendmail -bp` 而不是 `-bq`。选项 E 将显示 spool 中的各种目录，不是正确的命令。

### 17. 邮件重递配置
`/etc/aliases` 文件配置系统级邮件重递。指定的行正如选项 B 所示运行。这种配置很常见。选项 A 把东西搞反了。仅凭这些证据无法得出选项 C 的结论，尽管入侵者可能对重定向 `root` 的邮件感兴趣，所以如果 `jody` 不应该接收 `root` 的电子邮件，这应该被进一步调查。虽然选项 D（`jody` 读取 `root` 的电子邮件）的效果与正确答案的效果几乎相同，但它们是不同的；`jody` 无法直接访问作为 `root` 邮件队列的目录或目录。相反，所描述的配置将 `root` 的电子邮件重定向到 `jody` 的邮件队列中。因此，选项 D 是错误的。因为 `/etc/aliases` 是一个电子邮件配置文件，而不是账户配置文件，所以它无法产生选项 E 中描述的效果。

### 18. 创建数据库
`CREATE DATABASE` 命令创建一个具有指定名称的新数据库。由于 SQL 命令对大小写不敏感，因此该命令可以使用大写或小写输入，选项 B 是正确的。选项 A 和 C 都使用了错误的命令 `NEW` 而不是 `CREATE`，且选项 C 指定的数据库名称为 `FISH` 而不是 `fish`。（数据库名称是区分大小写的。）选项 D 颠倒了 `CREATE` 和 `DATABASE` 关键字的顺序。选项 E 使用了虚假的命令 `DB`。

### 19. 数据库表与压缩
A. D. 如选项 A 所示，数据库可以包含多个表。选项 D 也是正确的；如果数据分布在多个表中（例如分到描述通用对象和特定对象的表中），数据库可以更节省空间。选项 B 是错误的，因为 `DROP` 命令并不是合并表——它是删除一个表！选项 C 是错误的，因为它颠倒了 SQL 表中行和列的含义。正如名称所示，有损压缩算法会故意损坏或丢失某些数据——这对于数据库来说是一个不可接受的选项，使得选项 E 是错误的。（有损压缩用于某些音频和视频文件格式。）

### 20. 更新数据库条目
C. `UPDATE` 命令修改现有数据库表条目，在这种情况下，它是按照选项 C 描述的那样执行。选项 B 也描述了一个更新操作，但方式混乱且错误。选项 A 和 D 都描述了数据库检索操作，但 `UPDATE` 并不检索数据。选项 E 错误地将 `*` 识别为数据库名，但它只是一个名称，并且错误地将操作识别为添加新条目（SQL 中的 `INSERT`）而不是修改现有条目（SQL 中的 `UPDATE`）。

## 第 10 章：保护您的系统

### 1. 服务器合法性判断
E. 单凭服务器名称不足以判断它们是否合法。涉及的计算机可能可能不需要运行这些服务器中的任何一个，它们的存在可能是故意的、无意的，或者是入侵的迹象。因此，选项 E 是正确的。与选项 A 相反，仅仅 `SSH` 服务器的存在并不能确保安全。虽然选项 B 中的 `FTP` 不是一个安全协议，但它在某些情况下仍然有用，仅仅存在 `FTP` 服务器本身并不构成怀疑的理由。同样，在选项 C 中，某些管理员出于安全考虑倾向于使用 `Postfix` 或 `qmail` 而不是 `sendmail`，`sendmail` 并不一定不好，仅凭名称无法保证 `ssh` 和 `proftpd` 服务器是合法的。正如选项 D 所示，`sendmail` 和 `proftpd` 都使用未加密（文本模式传输），但这在某些情况下是恰当的。

### 2. 端口扫描权限
C. 虽然 `Nmap` 和其他端口扫描器是有用的工具，破坏者也会使用它们，并且许多组织限制了它们的使用。因此，在使用此类工具之前应该始终获得权限，使得选项 C 是正确的。端口扫描器不会造成损坏，因此不需要备份它，与选项 A 相反。端口扫描器运行也不需要目标系统的 `root` 密码，不需要这些信息，使得选项 B 是错误的。（事实上，询问 `root` 密码可能是极可疑的！）虽然你可以使用 `sudo` 来运行 `Nmap`，但不需要这样做来执行 TCP 扫描，你可以通过其他方式（如直接登录或使用 `su`）执行 UDP 扫描。因此，选项 D 并不是必要的。因为防火墙是网络安全的一部分，在执行网络扫描时你可能希望它运行，与选项 E 相反。此外，为了防止防火墙被破解，让防火墙保持运行更安全。

### 3. 用户访问限制配置
`/etc/security/limits.conf`（选项 C）包含了限制用户访问的配置设置。列出的其他选项没有提供正确的路径。

### 4. 识别开放端口
A, B, C. `Nmap`（选项 A）通常用于对远程计算机进行扫描，但也可以扫描本地计算机。`netstat`（选项 B）和 `lsof`（选项 C）工具都可以识别在本地计算机上监听的连接（即开放端口）。网络文件系统 (NFS) 和一些其他服务器使用 `portmap` 程序（选项 D），但它不是用于识别开放端口。没有标准的 Linux `services` 程序（选项 E），尽管 `/etc/services` 文件映射了端口号到服务名称。

### 5. 查找 SUID 文件
B. `-perm` 选项用于查找指定权限的文件，`+4000` 是一个匹配 SUID 文件的权限代码。`-f` 类型限制匹配目录。选项 B 正确使用了这些功能。选项 A、C 和 D 错误地使用了这些功能。选项 E 指定了虚假的 `-suid` 参数来查找。

### 6. sudoers 配置解析
A. 选项 A 正确描述了该行的含义。`%` 识别 Linux 组名，剩余部分告诉 `sudoers` 允许该组的用户以 `root` 身份运行所有程序。其余选项可能误解了配置文件的一个或多个元素。

### 7. 监控网络连接
B. `netstat` 命令可以完成描述的功能。`-ap` 选项是发现所有开放连接的选择，尽管 `lsof` 也可以完成这项工作，但 `-c` 选项是错误的；`lsof` 将输出限制为以某个字符开头的进程。因此，选项 A 是错误的。C 的 `ifconfig` 命令不显示开放连接，所以它是错误的。虽然选项 D 的 `map` 命令会定位本地接口上开放的端口，但它不会定位所有连接，也不会定位本地接口以外的任何连接。选项 E 的 `top` 命令显示按 CPU 排序的进程列表，`-net` 是 `top` 的无效选项。

### 8. TCP Wrappers 配置
D 是正确的。TCP wrappers 使用此功能允许通过在 `hosts.allow` 中添加更具体的访问权限来覆盖广泛的拒绝，当在 `hosts.deny` 中设置默认策略（`ALL : ALL`）时。
