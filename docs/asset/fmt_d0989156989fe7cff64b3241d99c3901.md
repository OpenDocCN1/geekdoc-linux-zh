### A.2.5 Electric Fence

`Electric Fence` 由 `Bruce Perens` 编写，它会在分配之外发生写入或读取的精确位置停止执行程序。这是唯一能发现非法读取的工具。它包含在大多数 `GNU/Linux` 发版中，可以在 `http://www.perens/FreeSoftware/` 找到源码。

# 266 附录 A 其他开发工具

与 `cmalloc` 一样，你的程序对象文件必须在链接命令中添加 `-lfefence` 以与 `Electric Fence` 库链接，例如：

```bash
gcc -g -Wall -pedantic malloc-use.o -o emalloc-use -lfence own
```

在程序运行时，系统会检查分配的内存使用的正确性。违反规则会导致段错误（`segmentation fault`）。

```
% emalloc-use 12

Electric Fence 2.0.5 Copyright (C) 1987-1998 Bruce Perens.

Please enter a command: a 12

Please enter a command: r 12

Segmentation fault
```

使用调试器，你可以确定非法操作的上下文。
默认情况下，`Electric Fence` 仅检测超出分配范围的访问。若要检测分配开始之前的访问（而非结束之后的访问），请使用以下代码：

```bash
% export EF_PROTECT_BEFORE=1
```

要检测已释放的内存，请将 `EF_PROTECT_FREE` 设置为 1。更多功能请参见 `libefence` 手页。
`Electric Fence` 通过将每次分配存储在至少两个内存页上检测非法内存。它将分配放在第一页的末尾；任何超出分配结束位置（位于第二页）的访问都会导致段错误。如果你将 `EF_PROTECT_BELOW` 设置为 1，它会将分配放在第二页内部内部。由于每次调用 `malloc` 都会分配两个内存页，`Electric Fence` 会消耗大量的内存。请仅用于调试。

## A.2.6 在不同的内存调试工具之间进行选择

我们讨论了四种不兼容的工具来诊断动态内存使用的错误。`GNU/Linux` 程序员如何确保动态内存被正确使用？没有工具能保证诊断所有错误，但使用其中任何一种都能增加发现错误的概率。为了发现动态分配内存错误，请单独开发和测试处理动态内存的代码。这可以减少你需要搜索的代码量。如果你使用 `C++`，请使用处理所有动态内存的类，并尽量减少使用分配和释放的函数数量。在测试此代码时，确保一次只使用一种工具，因为它们是不兼容的。在测试程序时，要改变程序的执行方式，测试代码中执行最频繁的部分。
