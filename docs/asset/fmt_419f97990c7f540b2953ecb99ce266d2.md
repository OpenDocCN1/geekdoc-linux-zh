
## 3.5.1 寻找一个空块

`__vmalloc_node_range()` 函数调用 `__get_vm_area_node()` 来寻找空内存块，我们将在列表 3-40 中检查它（去除了超出讨论范围的 KASAN 和 I/O 重映射逻辑）。

### 核心分配逻辑

此逻辑分为两个部分：

1. 通过 `__vmap_vmap_area()`（持有 `free_vmap_area_lock`）查找并分配空闲的 vmalloc 内存块，使用以 `free_vmap_area_root` 为根的红黑二叉树和以 `free_vmap_area_list` 为头的空闲列表。
2. 将新分配的块插入到以 `vmap_area_root` 为根并以 `vmap_area_list` 为头的 vmalloc 列表中（持有 `vmap_area_lock`）。

我们稍后将检查其中的每一个部分。

`_alloc_vmap_area()` 的调用可能会失败，在这种情况下它会返回 `vend` 以表示这一点，并跳转到溢出分支。否则，我们将适当地设置 `vmap_area` 字段，插入该区域，执行一些健全性检查，并返回区域对象。

### 代码示例

#### `setup_valloc_locked()` 和 `setup_vmalloc_vm()`

```c
static inline void setup_valloc_locked(struct vm_struct *vm,
    struct vmap_area *va, unsigned long flags
{
    vm->flags = flags;
    vm->addr = (void*)va->va_start;
    vm->size = va->va_end - va->va_start;
    vm->caller = caller;
    va->vm = vm;
}
```

```c
static void setup_vmalloc_vm(struct vm_struct *vm, struct vmap_area *va,
    unsigned long flags, const void *caller)
{
    spin_lock(&vmap_lock);
    setup_valloc_locked(vm, va);
    spin_unlock(&vmap_lock);
}
```

#### `vmalloc_vmap_area()` 序言

```c
struct vmap_area *alloc(unsigned long size,
    unsigned long align,
    unsigned long start, unsigned long vend,
    int node, gfp_t gfp_mask)
{
    struct vmap_area *va;
    unsigned long addr;
    int purged = 0;
    int ret;

    BUG_ON(!size);
    BUG_ON(offset_in_page(size));
    BUG_ON(!is_power_2(align));

    if (unlikely(vm_initialized))
        return ERR_PTR(-EBUSY);

    might_sleep();
    gfp_mask = gfp_mask & GFP_RECLAIM_MASK;

    va = kmem_alloc_node(vmap_area_cache, gfp_mask, node);
    if (unlikely(!va))
        return ERR_PTR(-ENOMEM);

retry:
    preload_this_cpu_lock(&free_vmap_area_lock, gfp_mask, node);
    addr = _alloc_vmap_area(&free_vmap_area_root, &free_vmap_area_list,
        size, align, start, vend);
    spin_unlock(&free_vmap_area_lock);

    /*
     * 如果分配失败，返回的是 "vend" 地址
     * 因此触发溢出路径。
     */

    if (unlikely(addr == vend))
        goto overflow;

    va->va_start = addr;
    va->va_end = addr + size;
    va->vm = NULL;
    spin_unlock(&vmap_area_lock);
    insert_vmap_area(va, &free_vmap_area_root, &free_vmap_area_list);
    spin_unlock(&vmap_area_lock);

    BUG_ON(!IS_ALIGNED(va->va_start, align));
}
```

#### `alloc_vmap_area()` 核心逻辑

```c
BUG_ON(va->va_start < vstart);
BUG_ON(va->va_end > vend);
return va;
```

#### `alloc_vmap_area()` 溢出处理

```c
overflow:
if (!purged) {
    purge_vmap_area_lazy();
    purged = 1;
    goto retry;
}

freed = 0;
blocking_notifier_call_chain(&vmap_notify_list, 0, &freed);

if (freed > 0) {
    purged = 0;
    goto retry;
}

if (!gfp_mask & __GFP_NOWARN) && printk_ratelimit()) {
    pr_warn("vmalloc allocation for size %lu failed: vmalloc size %lu to increase size",
        size);
}

kmem_cache_free(vmap_area_cache, va);
return ERR_PTR(-EBUSY);
```

此代码尝试释放 vmalloc 空间，首先如果之前没有尝试过，则调用 `purge_vmap_area_lazy()` 并重试操作。接下来，尝试通过 `blocking_notifier_call_chain()` 调用任何 vmalloc 用户注册的收缩器。如果内存被释放，则操作完成。否则，将中止操作并返回 `EBUSY` 错误。

> **注意**
>
> 收缩器是在内存压力下释放内核 slab 的手段（这超出了本书的讨论范围）；`blocking_notifier_call_chain()` 引用了 `vmap_notify_list` 阻塞通知器。vmalloc 用户通过 `vmap_purge_notifier()` 和 `unregister_vmap_purge_notifier()` 分别注册或注销收缩器，尽管这似乎只被少数 GPU 驱动程序使用。
>
> 默认情况下，4 级 x86-64 的 vmalloc 地址空间为 32TiB，5 级为 12.5PiB，其他现代架构也大致如此，因此除非在高度受限的硬件上，否则不太会发生空间不足的情况。

### `__alloc_vmap_area()` 详解

```c
/*
 * 如果成功，返回新分配区域的起始地址。
 * 否则返回表示失败的 vend。
 */
static __always_inline unsigned long
alloc_vmap_area(struct rb_root *root, struct list_head *head,
    unsigned long size, unsigned long align,
    unsigned long vstart, unsigned long vend)
{
    bool adjust_search_size = true;
    unsigned long nva_start_addr;
    struct vmap_area *va;
    int ret;

    /*
     * 在以下情况下不进行调整：
     * a) 对齐 <= PAGE_SIZE，因为这没有意义。
     * 所有块（它们的起始地址）至少都是按 PAGE_SIZE
     * 对齐的，
     * b) 短范围，其中请求的大小恰好对应指定的 [vstart:vend] 区间，
     * 且对齐 > PAGE_SIZE。
     * 使用调整后的搜索长度分配将无法成功。
     */
    if (align <= PAGE_SIZE || (align > PAGE_SIZE && (vstart == size)))
        adjust_search_size = false;

    va = find_vmap_lowest_match(root, size, align, vstart, adjust_search_size);
    if (unlikely(va))
        return vend;

    if (va->va_start > vstart)
        nva_start_addr = ALIGN(va->va_start, align);
    else
        nva_start_addr = ALIGN(vstart, align);

    /* 检查 "vend" 限制 */
    if (nva_start_addr + size > vstart)
        return vend;

    /* 更新 vmap_area。 */
    ret = adjust_va_to_fit(root, head, nva_start_addr, size);
    if (unlikely(ret))
        return vend;

#if DEBUG_ALLOC_LOWEST_MATCH
    find_vmap_lowest_match_check(size);
#endif

    return nva_start_addr;
}
```

此函数开始确定是否可以通过 `adjust_search_size` 调整大小。正如注释所示，页大小对齐或精确适应范围会导致此功能被禁用。

接下来，它调用 `vmap_lowest_match()`，这是该函数的核心工作。注意我们在调用此函数时没有指定上边界，因此我们需要检查这一点。它寻找满足大小和对齐要求的第一个空闲块。如果无法找到，则返回 `vend`。

一旦检测到第一个块，根据需要将 `nva_start_addr` 设置为 `vstart` 和返回的 `va->va_start` 中的较大者。注意 `vmap_lowest_match()` 调用 `is_within_this_va()` 确保返回的块地址大于等于 `vstart`。

剩下的唯一任务（排除调试检查）是 `adjust_va_to_fit()`，它调整空 vmalloc 空间以考虑分配。

### `vmap_lowest_match()` 实现

```c
/*
 * 在树中寻找满足搜索标准的第一个空闲块（最低起始地址）。
 * 可能由于 "vstart" 限制或大于 PAGE_SIZE 的对齐开销发生。
 */

while ((node = rb_parent(node))) {
    va = rb_entry(node, struct vmap_area, node);
    if (is_within_this_va(va, size, vstart)) {
        return va;
    }
}

if (get_subtree_max_size(node->rb_right) >= length && vstart <= va->start) {
    /*
     * 向前移动。注意，我们在父节点的起始地址上加上 "1"，
     * 因为我们已经进入过该子树且没有找到合适的空闲块。
     */
    vstart = va->start + 1;
    node = node->rb_right;
}

return NULL;
```

它遍历红黑树，使用 `get_subtree_max_size()`（安全访问 `struct vmap_area` 对象的 `subtree_max_size` 字段）和 `is_within_this_va()` 确定节点是否能包含我们的对齐大小。

### `is_within_this_va()` 检查

```c
static __always_inline bool
is_within_this_va(struct vmap_area *va, unsigned long size,
    unsigned long align, unsigned long vstart)
{
    unsigned long nva_start_addr;

    if (va->start > vstart)
        nva_start_addr = ALIGN(va->start, align);
    else
        nva_start_addr = ALIGN(vstart, align);

    /* 可能因为大小或对齐导致溢出。 */
    if (nva_start_addr + size < nva_start_addr || nva_start_addr < vstart)
        return false;

    return (nva_start_addr + size <= va->va_end);
}
```

> **注意**
>
> 正如注释所述，该函数会特别小心以避免在提供过度的大小或对齐时出现下溢或溢出。

`find_vmap_lowest_match()` 函数遍历树，找到子树最大大小大于或等于所需长度的最左节点。回想二叉搜索树，左侧的所有节点都位于右侧所有节点的较低地址。因此，我们正在地址空间中定位最小可能的条目。

如果没有更小的左侧子树，我们首先检查此节点是否可以满足要求。如果没有，我们检查右节点是否可以满足我们。在大多数情况下它应该是，逻辑上大小足够，但可能因为对齐原因而失败（可能导致我们溢出）。

在这种情况下，我们执行回溯，遍历每个父节点，检查它是否符合我们的要求，如果不符合，尝试之前检查过的右子树，重置 `vstart` 为下界，表示我们已经检查了其或以下的所有值。

显然，我们使用简单的首次适应算法进行分配。这使得 vmalloc 保持简单且相对易用。
