## 5.5.1 设置 Shadow 密码套件参数

虽然大多数密码控制参数已移动到 PAM，但某些参数仍通过 `shadow` 密码套件可用。对 `/etc/login.defs` 进行的任何更改只有在使用 `usermod` 命令时才会生效。如果通过其他方式添加了用户 ID，请使用 `chage` 命令对单个用户 ID 进行更改。

### 5.5.1.1 确保配置了密码更改之间的最小天数（自动化）

**策略适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

`/etc/login.defs` 中的 `PASS_MIN_DAYS` 参数允许管理员防止用户在距离上次更改密码未满最小天数之前更改密码。建议将 `PASS_MIN_DAYS` 参数设置为 1 天或更多。

**原理：**

通过限制密码更改的频率，管理员可以防止用户通过反复更改密码来试图规避密码重用控制措施。

**审计：**

运行以下命令并验证 `PASS_MIN_DAYS` 是否符合站点策略（不少于 1 天）：

```bash
grep PASS_MIN_DAYS /etc/login.defs
PASS_MIN_DAYS 1
```

运行以下命令并检查用户列表和 `PASS_MIN_DAYS`，以验证所有用户的 `PASS_MIN_DAYS` 是否符合站点策略（不少于 1 天）：

```bash
awk -F ':' '/^[^:]+:/{print $1 " " $4}' /etc/shadow

```

**修复措施：**

在 `/etc/login.defs` 中将 `PASS_MIN_DAYS` 参数设置为 1：

```bash
PASS_MIN_DAYS 1
```

修改所有已设置密码的用户参数以匹配该设置：

```bash
chage --mindays 1 <user>
```

`PASS_MIN_DAYS 0`

## 5.5.2 确保系统账户已安全（自动化）

**配置适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

大多数发行版都提供了许多账户，用于管理应用程序，且不打算提供交互式 shell。

**原理：**

确保普通用户未使用的账户不被用于提供交互式 shell 是至关重要的。默认情况下，大多数发行版将这些账户的密码字段设置为无效字符串，但建议将密码文件中的 shell 字段设置为 `nologin` shell。这可以防止账户可能被用于运行任何命令。

**审计：**

运行以下命令并验证没有返回结果：

```bash
awk -F: '$1!~/(root|sync|halt)/ && $3<$(awk '^\*UID_MIN/{print $2}' /etc/login.defs) && $7!~/((user)?\/sbin\/nologin)/ && $7!~\/(bin)?\/false/ {print $1}' /etc/shadow
awk -F: '$1!~/(root|sync|halt)/ && $3<$(awk '^\*UID_MIN/{print $2}' /etc/login.defs) && $7!~/((user)?\/sbin\/nologin)/ && $7!~\/(bin)?\/false/ {print $1}' /etc/passwd | xargs -I {} awk '$2 !~ /(^.*\/(sbin\/nologin|bin\/false)$)/ {print $1}'
```

> **注意：** `root`, `sync`, `halt` 用户不要求登录

**修复：**

将审计返回的账户 shell 设置为 `nologin`：

```bash
usermod -s $(which nologin) <user>
```

锁定审计返回的账户：

```bash
usermod -L <user>
```

以下命令将所有账户切换到 `nologin` shell：

```bash
awk -F: '$1!~/(root|sync|halt)/ && $3<$(awk '^\*UID_MIN/{print $2}' /etc/login.defs) && $7!~/((user)?\/sbin\/nologin)/ && $7!~\/(bin)?\/false/ {print $1}' /etc/passwd | while read -r user; do usermod -s "$(which nologin)" "$user"; done
```

以下命令将锁定 `root` 系统账户：

```bash
awk -F: '$1!~/(root|)/ && $3<$(awk '^\*UID_MIN/{print $2}' /etc/login.defs) {print $1}' /etc/passwd | xargs -I {} awk '$2 !~ /(^.*\/(sbin\/nologin|bin\/false)$)/ {print $1}' | while read -r user; do usermod -L "$user"; done
```

## 5.5.4 确保默认用户 umask 为 027 或更严格

**配置适用性：**

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

用户文件创建模式掩码 `umask` 用于确定新创建目录的权限。在 Linux 中，任何新创建的目录的默认权限为 `0777` (`rwxrwxrwx`)，任何新创建的文件的默认权限为 `0666` (`rw-rw-rw-`)。`umask` 通过限制（掩码）这些权限来修改默认权限。`umask` 并不是简单的减法，而是通过位运算处理的。`umask` 中设置的位会在生成的文件模式中被清除。

`umask` 可以使用八进制值或符号值设置：

- 八进制（数值）值 - 由三或四位数字表示。例如 `umask 027`。如果使用数字掩码，则忽略第一位。剩余的三个数字会影响用户、组和世界/其他生成的权限。
- 符号值 - 用逗号分隔的列表表示用户 `u`、组 `g` 和世界/其他 `o`。权限通过 `umask` 标记。例如通过 `umask u=rwx,g=rx,o=` 设置的 `umask` 是八进制 `umask 027` 的符号等效值。这将使新创建的目录文件模式设置为 `drwxr-x---`，新创建的文件文件模式设置为 `rw-r-----`。

设置默认 `umask` 模块：

- 将根据 `/etc/login.defs` 中的系统默认值和用户设置设置 `umask`，解决不同 shell、显示管理器、远程会话具有不同 `umask` 设置的问题。
- `/etc/login.defs` 文件中的 `UMASK` 值被解释为八进制。
- 在 `/etc/login.defs` 中将 `USERGROUPS_ENAB` 设置为 `yes`（默认）：
    - 允许设置用户组位与其他位相同。（对于非 `root` 用户，如果 `uid` 与 `gid` 相同，且用户与主组名相同）。
    - `userdel` 如果用户组不再包含成员，将删除该用户组，而 `useradd` 将默认创建一个与用户名同名的组。

系统级 Shell 配置文件：

- `/etc/profile` - 用于在用户的 shell 中设置系统范围的环境变量。这些变量有时是 `.profile` 中的变量，但此文件用于为系统的所有 shell 用户设置初始 `PATH` 或 `PS1`。它仅对交互式登录 shell 和使用 `-login` 参数执行的 shell 执行。
- `/etc/profile.d/*` - `/etc/profile` 会执行 `/etc/profile.d/*.sh` 内部的脚本。建议将您的配置放置在 `/etc/profile.d` 内部的 shell 脚本中，以设置您的系统范围环境变量。
- `/etc/bash.bashrc` - `.bashrc` 的系统级版本。如果是非登录 shell，`.bashrc` 也会调用 `/etc/profile.d/*.sh`，但如果是非交互性的，则将输出重定向到 `/dev/null`。只有当 `BASH_ENV` 设置为 `/etc/bash.bashrc` 时，它才会对交互式 shell 执行。

**用户 Shell 配置：**

- `~/.profile` - 在初始命令提示符之前执行，以配置您的 shell。仅由登录 shell 读取。
- `~/.bashrc` - 为交互式 shell 执行。仅由既是交互式又非登录的 shell 读取。

**原理：**

为 `umask` 设置一个非常安全的默认值，可以确保用户对其文件权限做出有意识的选择。`077` 的默认 `umask` 设置会导致用户创建的文件和目录无法被系统上的任何其他用户读取。`027` 的 `umask` 将使文件和目录可以被同一 Unix 组的用户读取，而 `022` 的 `umask` 将使文件对系统上的每个用户都可读。

**影响：**

在 `/etc/login.defs` 中将 `USERGROUPS_ENAB` 设置为 `no` 可能会更改 `useradd` 和 `userdel` 的预期行为。

在 `/etc/login.defs` 中将 `USERGROUPS_ENAB` 设置为 `yes`，如果它不再包含成员：

- `userdel` 将删除该用户组
- `useradd` 将默认创建一个与用户名同名的组。

**审计：**

运行以下命令进行验证：

- 设置了默认用户 `umask`，以强制新创建的目录权限为 `750` (`drwx-x---`)，且新创建的文件权限为 `640` (`rw-r-----`)，或更严格。
