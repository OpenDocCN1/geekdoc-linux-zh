
### 代码片段

```
<dt>Address</dt>

<dd>[% student.address %]</dd>

<dt>Tuition</dt>

<dd>[% student.tuition %]</dd>

<dt>Course</dt>
[% FOREACH course IN student.courses %]

<dd>[% course %]</dd>

[% END %]

</dl>

[% END %]

</div>

</div>

</div>
```

### 解释

1. 此文件不以 `<html>` 或 `<!DOCTYPE>` 开头。相反，它以 `<div>` 开头。该文件将导入 `views/layout/main.tt`，因此只需包含特定于学生列表页面的 HTML。`main.tt` 包含 `DOCTYPE` 和 `<html>` 元素。这使我们能够创建新页面，同时保持一致的主题和框架。
2. 通过保留部分原始 HTML，可以避免进行许多额外的样式设计。我们将保留其中的 `content` `div` 及其内部的 `header` `div`，这将使新页面看起来与旧页面相似。
3. 创建了一个新的 `div`，其 `ID` 为 `students`。如果希望的话，我们稍后可以使用 `CSS` 对此进行样式设计。
4. `Template::Toolkit` 定义了 `FOREACH` 指令，其行为类似于 Perl 中语法不同的 `foreach` 循环；例如，使用 `IN` 代替 Perl 语法中的括号。`Template::Toolkit` 期望 `students` 是一个 `arrayref`，并对其进行迭代，依次将每个元素赋值给 `student` 变量。`Dancer` 使用 `<% %>` 语法配置 `Template::Toolkit` 以识别模板区域；其他所有内容均作为纯文本输出。
5. 这是 `FOREACH` 循环体的第一行。它定义了一个 `<h2>`。对于 `students` 数组中的每个学生，此行将输出一次。

### 说明（续）

6. 输出学生的姓名。当变量放入模板标签中时，默认行为是打印它。当前学生由 `student` 变量引用，变量的属性可以通过点号访问。`Template Toolkit` 足够智能，能够理解 `student` 引用的是一个对象，并获取其 `name` 属性。如果 `student` 是一个哈希引用，它将获取与 `name` 键关联的值。它试图在所有情况下都做正确的事情。
7. 关闭 `<h2>` 标签。现在学生的姓名变成了页面中的二级标题。每个学生都会有一个包含其姓名的 `<h2>` 标签。
8. 开始一个 `<dt>` 标签。这是一个描述列表。得益于 `FOREACH` 循环，每个学生都会有这样一个列表。
9. 一个 `<dd>` 标签包含 `ID`。这是 `description` 列表（`dt` 代表“描述标题”）中项目的标题。对于我们希望输出的 `Student` 对象的每个属性，都会使用其中一个。
10. 一个 `<dd>` 标签包含实际值。这就是描述本身。与 `name` 类似，访问了学生变量的 `id_number` 属性，并且由于该 `Template Toolkit` 标签内部没有其他指令，因此直接输出其值。
11. 更多的 `<dd>` 和 `<dd>` 对完成了学生信息的构建，使用与类本身的 `show_student` 相同的信息。
12. 在 `Student` 类中，`courses` 被定义为一个数据 `array`。另一个 `FOREACH` 指令开始循环遍历当前 `Student` 对象 `student` 的 `student.courses` 属性中的所有值。因为内部有指令 `FOREACH`，`Template Toolkit` 不会直接输出 `student.courses` 的值。相反，每个课程会被分配给 `course` 变量，就像 Perl 中正常的 `foreach` 循环一样。
13. 列表中的每个课程都会创建一个 `<dd>` 标签，其中包含课程名称。
14. `END` 指令完成最近打开的块指令，在本例中是 `FOREACH`。缩进在这里很重要，因为很容易迷失哪个 `END` 实际上结束了哪个指令。
15. `</dd>` 关闭 `<dd>` 标签，并结束单个学生的所有数据输出。
16. `END` 指令关闭另一个 `FOREACH` 块指令，即循环遍历学生的那个。如果在处理过程中还有更多学生，整个过程将对下一个学生重复。因此，所有学生都使用相同的 HTML 表示，只有 HTML 内的实际数据会发生变化。

由于对 `Example.pm` 进行了修改，有必要重启开发 `Dancer` 服务器。只需通过 `CTRL+C` 终止它并再次运行。脚本 `app.pl` 确实有一个选项，在检测到文件更改时重启自身，但这可能不可靠，尤其是在 Windows 上，因此手动重启通常更简单。手动重启还意味着你可以在实际重启之前多次修改多个文件。

一旦服务器进程重启，在浏览器中重新加载页面将显示类似图 E.2 的页面，利用 Dancer 开发的主要原则：服务器进程 `app.pl`、配置 `config.yml`、路由处理 `get "/"` 和模板系统 `index.tt`。

### E.1.3 参数

`GET` 请求仅包含资源 URL 并不一定是完整的。许多资源实际上是一组资源的入口。我们到目前为止的整个应用程序实际上是可用于应用程序的所有 `Student` 资源的入口。通常，我们希望能够过滤此类页面或访问单个资源。

现代 Web 提供两种常见的参数化方式。它们在运作方式上有所不同，因此其使用方式也应有所区别。它们都是 URL 的一部分。

**查询字符串** 是 URL 中问号后面的部分。通常它是键值对字符串，其中键和值由等号分隔，对本身由符号分隔：

```
?name=John&course=java
```

通常，这被称为 **GET 字符串**，但这是一个误称；因为它是 URL 的一部分，所使用的 HTTP 动词并不重要。`POST` 请求可以有查询字符串，当然，它首先甚至不需要是 HTTP 请求。像 `file://home/user/html/index.html?user=me` 这样的 URL 是完全合法的，它根本不使用 HTTP。³ 查询字符串之所以这样称呼，是因为它们通常用于查询索引资源以获取更具体的集合。在前面的示例中，预期我们会找到名为 "John" 且课程为 "Java" 的学生。

另一种类型的参数位于路径本身中。这通常用于更具体地说明我们想要哪个资源。如果我们处理的是一个更大的系统，拥有许多学校和大学，我们可能希望更具体地说明我们要找的是谁的学生。在这种情况下，URL 可能看起来像这样：

```
http://0.0.0.0:3000/univ/mit/students/
```

这将使用我们之前见过的技术以及即将见到的技术来构建。`get`/`route` 的使用几乎肯定会出现在这里；但是一旦系统变得这么大，很可能会在 `lib/` 中添加一个新模块，例如，`University.pm` 以保持系统的良好组织。

当然，这些参数类型可以组合。以下 URL 可能指的是所有在 MIT 就读的、名为 Joe 且学习高等数学的学生：

```
http://0.0.0.0:3000/univ/mit/students/?name=Joe&course=advanced_math
```

我们也可以通过指定路径参数化形式中的学生 ID，从整个数据库中获取特定的学生，如下所示：

```
http://0.0.0.0:3000/students/1
```
