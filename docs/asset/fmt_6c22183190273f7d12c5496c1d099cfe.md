
首先，让我们看看如何使用 `getopts` 来解析命令行。`getopts` 命令处理跟在 `-`（减号）或 `+`（加号）后面的单字符选项。要指定某个开关需要参数，则该字符后面必须跟一个 `:`（冒号）。如果开关不需要任何参数，则应省略冒号。所有的开关都组合在我们定义的变量名中。每个开关的参数存储在名为 `$OPTARG` 的变量中，如果整个 `OptionString` 前面有一个 `:`（冒号），那么任何不匹配的开关都会导致 `?` 加载到定义的变量中。命令格式如下：

```
getopts OptionName [ Argument ]
```

解释 `getopts` 命令最简单的方法是使用示例。对于我们的脚本，我们需要分钟、小时、天和一个监控项。对于每一个，我们希望提供一个参数——例如 `-s 5 -m10 -py my_backup`。在这个示例中，我们提供了 5 个开关、10 分钟，并且进程是 `my_backup`。注意开关和参数之间没有空格。这正是 `getopts` 如此棒的地方！设置我们的示例的代码如列表 8.7 所示：

```bash
SECS=0              # 全部初始化为零
MINUTES=0
HOURS=0
DAYS=0
PROCESS=           # 初始化为空
while getopts ":s:m:h:d:p" TIMED 2>/dev/null

  case $TIMED in
    s) SECS=$OPTARG
```

在 Listing 8.7 中有几点需要注意。**getops** 命令需要包含在一个 `while` 循环中，并在循环内部包含一个 `case` 语句。对于我们指定的每个选项（`-s,-m,-h,-d,-p`），我们在每个开关后面都添加了 `:`（冒号）。该字符告诉 `getops` 该特定字符需要一个参数。`OptionString` 列表之前的 `:`（冒号）告诉 `getops`：如果在命令行上给了一个未指定的选项，则将 `TIMED` 变量设置为 `?`。该字符允许我们在遇到错误的命令行选项时调用 `usage` 函数并以返回码 1 退出。唯一需要小心的是 `getops` 不关心它接收到什么参数，因此我们有责任检查它是否符合我们的预期；如果我们要想退出，就必须采取行动。Listing 8.7 中最后需要注意的是的是，`while` 循环的第一行将标准错误（文件描述符 2）重定向到了“黑洞”（bit bucket）。当遇到意外错误时，`getops` 会向标准错误发送一条消息，但这并不被视为错误，只是信息性的。我们预计可能会输入错误的命令行参数，我们可以忽略这些消息并通过重定向到 `/dev/null`（即黑洞）将其丢弃。

我们还需要处理协同进程（co-process）。协同进程是前景进程和后台进程之间的通信链路。最常见的问题是“为什么需要这个？”我们的下一个脚本将调用一个函数来处理所有的监控，因为我们在主脚本中进行计时。该程序的出现是因为我们需要在后台运行这个函数。那里的后台处理函数有两个循环，其中一个循环始终在执行。如果没有告诉循环跳出内部循环的能力，它将继续在自己的主脚本、函数中执行并由于中断而存在。我们知道这会导致什么——一个或多个僵尸进程！从主脚本，我们需要一种方法与后台函数中的循环通信，告诉它跳出循环，或者在倒计时完成且脚本被中断时（例如通过 CTRL-C）干净地退出函数。为了解决这个小问题，我们将后台 `proc_watch` 函数作为协同进程调用。你问“我们如何做到？”“将其管道到后台”是最简单的说法，这也是 Listing 8.8 中下一个示例的实现方式。

{

  # 此函数作为协同进程启动的！！

  while :  # 无限循环

    do

      Some Code Here

      read BREAK_OUT # 不需要 "-p" 来读取

      if [[ $BREAK_OUT = 'Y' ]]

      then

        return 0

      fi

    done

  #####################
  ###### Start of Main #######
  #####################

### Set a Trap ###
trap 'BREAK=Y'; print -p $BREAK; exit 2 1 2 3 15

TOTAL_SECONDS=300

BREAK_OUT='N'

proc_watch | & # 将 proc_watch 作为协同进程启动!!!!
until (( TOTAL_SECONDS == 0 ))
  do
    (( TOTAL_SECONDS = TOTAL_SECONDS - 1 ))
    sleep 1
  done

BREAK_OUT='Y'
# 使用 "print -p" 与协同进程变量通信
print -p $BREAK_OUT
exit 0

**Listing 8.8** 使用协同进程的示例。

在 Listing 8.8 的代码块中，我们定义了 `proc_watch` 函数，这是我们想要作为后台进程启动的函数。如你所见，`proc_watch` 函数有一个无限循环。如果主脚本被中断，如果不退出 `proc_watch` 后台进程中的循环，循环将继续执行。为了解决这个问题，我们通过使用管道符号 `|&` “管道到后台”，将 `proc_watch` 作为协同进程使用。现在我们可以从主脚本与该函数通信，我们使用 `print -BREAK_OUT`。在函数内部，我们使用标准的 `read` 命令 `BREAK_OUT`。协同进程是我们将使用的机制，以便在主脚本被捕获的信号中断时跳出循环，并在脚本结束正常终止时跳出循环。当然，我们永远无法通过 trap 捕获 `-9` 信号。

尝试上述的场景，在没有协同进程的情况下，使用带有无限循环的后台函数。然后按下 CTRL-C 键杀死主脚本并执行 `ps -ef | more`。你会发现后台循环仍在执行！获取 PID，并使用 `-9` 杀死它。当然，如果满足了退出条件，循环将自行退出。
