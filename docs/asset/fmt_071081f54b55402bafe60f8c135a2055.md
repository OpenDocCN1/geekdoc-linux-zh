## Description

`zip`用于列出、测试或从 ZIP 归档提取文件。默认行为（不带任何选项）是将指定的 ZIP 归档中的所有文件提取到当前目录（及其下的子目录）。你可以使用辅助程序`zip`（可在`http://www.cdrom.com/pub/infozip/`获取）来创建 ZIP 归档。这两个程序都与 PKWARE 为 MS-DOS 的`PKZIP`和`PKUNZIP`创建的归档兼容，但在许多情况下，程序选项或默认行为有所不同。

## Arguments

- `file[.zip]` ZIP 归档的路径。
- `file[.zip]` ZIP 归档的路径。如果对`file`指定了通配符，则将按照操作系统（或文件系统）确定的顺序处理每个匹配的文件。只有文件名可以是通配符；路径本身不能。通配符表达式与 UNIX `grep(1)`（常规）正则表达式相似，可以包含：
    - `*` 匹配 0 个或多个字符的序列。
    - `?` 匹配恰好一个字符。
    - `[...]` 匹配括号内的任何单个字符；使用起始字符、破折号和结束字符指定范围。如果左括号后跟着感叹号 (`!`) 或插入符号 (`^`)，则括号内的字符范围将取反（即除括号内的字符以外的任何字符都被视为匹配）。
    - 请对任何可能被操作系统解释或修改的字符加上引号，特别是在 UNIX 和 VMS 下。如果未找到匹配项，则假设为字面名称；如果仍然失败，则追加`.zip`。注意，支持自解压 ZIP 文件以及任何其他 ZIP 归档；只需显式指定`.exe`后缀（如果有）。
- `file(s)` 一个可选的、用空格分隔的待处理归档项列表。（使用 MS VMSCLI 编译的 VMS 版本必须在内部用逗号分隔文件。参见`-v`。）你可以使用正则表达式（通配符）来匹配多个项。确保对任何可能被操作系统扩展或修改的表达式加上引号。
- `-x file(s)` 一个可选的、要从处理中排除的归档项列表。由于通配符字符匹配目录分隔符 (`/`)，你可以使用此选项排除任何子目录中的文件。例如，
  `unzip foo *. -x /*`

### unzip 1417

提取主目录中的所有 C 源文件，但不提取任何子目录中的文件。如果没有`-x`选项，则提取文件内所有目录中的 C 源文件。

- `-d exdir` 一个可选的提取文件目录。默认情况下，所有文件和子目录会在当前目录中重新创建；`-d`选项允许你提取到任意目录（假设你拥有该目录的写入权限）。此选项不需要出现在命令行的末尾；它也可以出现在文件规范之前（带有普通选项），或者位于`file(s)`与`-x`选项之间。你可以将选项和目录连接在一起而不留任何空格，但注意这将抑制正常的 shell 行为。特别是，`-d ~`（波浪号）会被 Unix shell 扩展为用户的家目录名称，但`-d~`则被视为当前目录的字面子目录 `~`。

## unzip

> 注意 —— 为了支持过时系统，`unzip`屏幕限制为 22 或 23 行。将用法信息视为对基本`unzip`语法的提醒，而不是所有可能选项的详尽列表。

以下示例显示了`unzip`屏幕。

```
castle$ unzip

UnZip 5.32 of 3 November 1997, by Info-ZIP. Maintained by Greg Roelofs. Send bug reports to the authors at Zip-Bugs@lists.wku.edu; see README for details.

```

用法: `unzip [-Z] [-options] file[.zip] [list] [-x exdir]`
默认操作是提取`list`中的文件（`list`中的文件除外）到`exdir`；`file[.zip]`可以是通配符。`-Z = ZipInfo`模式（"`unzip -Z`"用于用法）。

```
-p 将文件提取到管道，不显示消息  -l 列出文件（短格式）

-f 刷新现有文件，不创建新文件 -t 测试压缩归档数据

-u 在必要时更新文件  -z 显示归档内容

-x 从（在）列表中排除文件  -d 将文件提取到 exdir
```

```
修饰符:

-q 静默模式 (-qq = 更静默)

-n 覆盖现有文件 -a 自动转换任何文本文件

-o 在不提示的情况下覆盖文件 -aa 将所有文件视为文本

-j 丢弃路径（不创建目录） -L 将（某些）名称转换为小写

-c 不区分大小写匹配文件名 -V 保留 VMS 数字

-X 恢复 UID/GID -M 通过 "more" 分页器管道传输
```
