# 自动挂载NFS文件系统

为了设置NFS文件系统以便在每次启动Fedora或RHEL系统时自动挂载，你需要在`/etc/fstab`文件中添加NFS文件系统的条目。`/etc/fstab`包含了关于你的Fedora或RHEL系统所有各种已挂载（以及可挂载）文件系统的信息。

将NFS文件系统添加到本地系统的格式如下：

| host:directory | mountpoint | nfs选项 | 0 | 0 |
| :--- | :--- | :--- | :--- | :--- |

第一项 (`host:directory`) 识别NFS服务器计算机和共享目录。`mountpoint`（挂载点）是挂载NFS目录的本地挂载点，随后是文件系统类型 (`nfs`)。与挂载相关的选项将出现在其后，以逗号分隔的列表形式出现。（最后两个零只是告诉Fedora或RHEL不要转储文件系统的内容，并且不对文件系统运行`fsck`）

以下是`/etc/fstab`中NFS条目的两个示例：

```
maple:/home/chris/files /media/maple nfs size=8192,size=8192 0 0

o:/apps /oak/apps nfs noauto,ro 0 0
```

在第一个示例中，名为`maple`的计算机上的远程目录`/home/chris/files` (`maple:/home/chris/files`) 被挂载在本地目录`/media/maple`（该本地目录必须存在）。文件系统类型为`nfs`，读 (`size`) 和写 (`size`) 缓冲区大小均为`8192`，以加快与此连接相关的数据传输。在第二个示例中，远程目录是名为`oak`的计算机上的`/apps`。它被设置为NFS文件系统 (`nfs`)，可以挂载在本地的`/oak/apps`目录上。然而，该文件系统不会自动挂载 (`noauto`)，并且在系统运行后，可以使用`mount`命令仅以只读 (`ro`) 模式挂载。

> 提示：默认是将NFS文件系统挂载为读/写。然而，导出文件系统的默认设置是只读的。如果你无法写入NFS文件系统，请检查它是否已从服务器以读/写权限检出。

# 挂载自动文件系统

在你的`/etc/fstab`文件中，可以存在不自动挂载的其他文件系统的设备。例如，你的硬盘上可能有多个磁盘分区，或者你可能只想偶尔挂载某个NFS共享文件系统。文件系统可以手动挂载。这样做的处是，当你输入`mount`命令时，可以输入少的信息，其余部分由`/etc/fstab`文件的内容填充。例如，你可以输入：

```
# mount /oak/apps
```

通过此命令，`mount`知道要检查`/etc/fstab`文件以获取要挂载的文件系统 (`/oak/apps`)、文件系统类型 (`nfs`) 以及与其配合使用的选项（在这种情况下为只读`ro-only`）。你不需要显式指定本地挂载点 (`/oak/apps`)，而是输入远程文件系统名称 (`oak:/apps`) 并让系统填充其他信息。

> 提示：在命名挂载点时，在名称中包含远程NFS服务器的名称有助于你记住文件实际存储在何处。如果你共享家目录 (`/home`) 或邮件目录 (`/var/spool/mail`)，这可能无法实现。

# 使用 mount 选项

你可以向`/etc/fstab`文件（或`mount`命令行本身）添加一些挂载选项，以影响文件系统的挂载方式。当你向`/etc/fstab`中添加选项时，必须用逗号分隔。以下是一些挂载NFS文件系统非常有价值的选项：

- `hard`: 使用此选项时，如果进程在等待访问NFS服务器时服务器断开或宕机，进程将挂起，直到服务器恢复。如果你未处理的数据与访问它的程序保持不同步至关重要，则此选项很有帮助。（这是默认行为）
- `soft`: 如果服务器断开或宕机，尝试从服务器访问数据的进程将在一段时间后超时。
- `rsize`: 每次从NFS服务器读取的数据字节数。默认值为`1024`。在快速（如局域网LAN）且相对无错误的网络上，使用较大的数字（如`8192`）将为你带来更好的性能。
- `wsize`: 每次从NFS服务器读取的数据字节数。默认值为`1024`。性能问题与`rsize`相同。
- `timeout=#`: 设置RPC超时发生的时间，其中`#`代表以十分之一秒为单位的数字。默认值是几十秒。每次连续的超时都会导致超时值翻倍（最高为`60`秒）。如果你认为超时是因为服务器响应缓慢导致的，则应该增加此值。
- `retrans=#`: 设置在发生主超时之前发生的次要重传超时次数。当发生主超时时，进程将被中止 (`soft`) 或在你的控制台上显示“服务器未响应 (Server Notponding)”消息。
- `retry=#`: 设置继续失败挂载请求的分钟数，由重试的分钟数代替。默认值为`10000`（大约一周）。
- `bg`: 如果第一次挂载尝试超时，则在后台尝试后续的挂载。如果你正在挂载一个缓慢或偶尔添加的文件系统，此选项非常有价值。通过将挂载置于后台，Fedora或RHEL可以继续挂载其他文件系统，同时等待当前挂载完成。

> 注意：如果缺少挂载点，会发生超时以允许添加挂载点。例如，如果你挂载`/usr/trip`和`/usr/trip/extra`为NFS文件系统，当`/usr/trip/extra`尝试挂载时如果`/usr/trip`尚未挂载，`/usr/trip/extra`将超时。希望`/usr/trip`出现后，`/usr/trip/extra`能在下次重试时挂载。
- `fg`: 如果第一次挂载尝试超时，则在前台尝试后续的挂载。这是默认行为。如果在继续操作之前必须挂载成功，请使用此项（例如，如果你正在挂载`/usr`）。

任何不需要值的选项都可以加上前缀以产生相反的效果。例如，`nobg`表示不应在后台进行挂载。

# 使用 autofofs 按需挂载 NFS 文件系统

最近自动检测和挂载移除设备的改进意味着，你可以插入或接上这些设备以使它们被检测、挂载并显示。然而，为了让检测和挂载远程NFS文件系统的过程自动化，你仍然需要使用如`autofofs`等功能。

配置并启用`autofofs`功能后，你可以按需挂载NFS共享目录。如果你知道任何主机共享的主机名和目录，只需切换到`autofofs`挂载目录（默认为`/net`），共享资源就会自动挂载并供你访问。

以下步骤说明了如何开启`autofofs`功能：

# 第四部分：Fedora RHEL 网络与服务器设置

- 1. 以`root`用户身份从终端窗口打开`/etc/auto.master`文件，并查找如下所示的一行：
```
/net      -hosts
```
这会导致`/net`目录作为你想要在网络上访问的NFS共享目录的挂载点。（如果该行开头有注释字符，请将其删除。）

- 2. 以`root`用户身份输入以下命令启动`autofofs`服务：
```bash
# service autofofs start
```

- 3. 设置`autofofs`服务在每次启动系统时重启：
```bash
# chconfig autofofs
```
