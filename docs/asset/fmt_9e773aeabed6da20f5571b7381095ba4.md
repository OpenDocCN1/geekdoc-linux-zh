
# 标准化解决方案

标准化解决方案为组织节省了大量资金。没有什么比可以任意复制的解决方案更具扩展性了。即使最初的时间投入看起来很大，但部署架构良好的环境所带来的周期性成本节省将很快超过设计和文档编制的初始开支。此外，一个遵循架构环境的不断发展的组织可以将工程成本分摊到更多的桌面设备上。

相反，允许以不受控方式增长的网络计算环境，其维护成本将呈指数级增长。最终，几乎所有的系统资源都将由于意料之外的不兼容性、依赖关系以及短期解决方案的严重后果而产生的问题所耗尽。

这导致组织无法及时响应所需的变化。没有按照架构模型构建的网络计算环境总是存在这个问题。有些甚至陷入了完全瘫痪的状态。此时，唯一的解决方案是创建一个全新的环境，并将用户和硬件迁移过去。更糟糕的是，如果新环境没有经过架构设计，同样的退化将再次开始。这是一笔巨大的支出，但许多组织由于缺乏远见而反复付出代价。

一些 IT 经理通过声称需要维护灵活性来为自己免除规划责任。没有增长的网络所施加的限制与计划内的网络一样确定。区别在于，计划内的网络施加的是计划内的限制，而非计划的网络施加的是非计划的限制。

## 关于命名空间的几语

命名空间是指一个将符号名称映射到对象的系统。在系统管理的范围内，我们将命名空间定义为存在特定网络命名协议中的名称集。最需要命名的对象是主机，但命名空间适用于每个网络资源。

名称服务确保网络服务免受网络环境细节的影响。提供网络服务的主机可以移动到网络不同的物理位置，但保留相同的符号名称。这极大地减少了更改网络环境时所需的工作，因为对该主机的所有引用都不需要更改。

就目前世界而言，有很多提供重叠功能的名称服务。专有操作系统供应商致力于确保网络环境包含任意数据。新一代命名服务器（被称为目录服务器）正在开发。目录服务可以将所有命名空间合并为一个服务。遗憾的是，操作系统在集成目录服务方面进展缓慢。

在 Linux 中，有三种基本的命名服务，其中两个与网络相关：`NIS` 和 `DNS`。Linux 还可以使用 `/etc/hosts` 文件来解析名称。Linux 通过 `/etc/nswitch.conf` 文件管理对这些命名服务的访问。通过修改访问命名服务的顺序来配置此文件，允许每台计算机拥有自定义的命名空间。不要这样做。每台计算机必须具有相同的命名空间以避免创建不必要的环境。选择一个 `nswitch.conf` 配置并部署到所有主机。

# 术语

近期网络领域出现了一些术语。互联网（Internet）自 20 世纪 80 年代初从 `ARPANet` 演变以来就有了名称。然而，“内网”（`intranet`）和“外网”（`extranet`）是在 20 世纪 90 年代后期使用的。我们从网络服务的角度定义这些术语基础的概念。

## 互联网

每个现代组织都需要连接到互联网，因为电子邮件和网页访问正在逐渐取代语音信箱和传真。大多数组织都希望通过防火墙来管理互联网访问。防火墙是一种专用计算机，专门允许从内部使用互联网，并防止外部的滥用。

大多数组织还希望在互联网上维护网站。`ISP`（互联网服务提供商）和集成公司正越来越多地提供安全接入和网页托管，这对于那些缺乏必要专业知识来维护这些服务的公司来说非常有吸引力。

# 内网

这个术语已成为描述使用 Web 服务器内部发布数据的流行方式。它还意味着已经具备了任何系统连接到其他系统所需的低级服务。虽然很难想象这是一项成就，但全公司范围内的数据访问是许多公司演进中的里程碑。

对内网的复杂定义还包括向所有内部数据提供标准化访问的能力，从而极大地提高了提供即时报告的能力以及部门间的数据共享能力。

# 外网

这个术语是为了反映与关键伙伴建立专用连接的业务实践，允许双方直接访问对方的应用。例如，制造商实施了与其供应商的直接链接，以自动化订单和账单。这样制造商就可以自由地实施制制管理，根据产品订单直接向供应商生成请求。

“外网”一词很可能在未来几年内消失。公司已经开始用虚拟专用网络（`VPNs`）取代专用连接。随着互联网商业和加密标准的稳定，对外网的感知需求将逐渐减少。

# Linux 与网络技术

`LINUX` 支持上一节提到的所有服务。此外，`LINUX` 还支持几乎所有将这些服务集成到现有 PC 计算环境所需的网络协议。`LINUX` 可以集成到 `Macintosh`、`Microsoft Windows`、`NetWare`，以及当然，还有商用 `UNIX` 环境中。许多管理 `Microsoft Windows` 网络的系统管理员倾向于使用 `LINUX` 而不是原生服务器来提供文件和打印服务。

`LINUX` 已经为 `IPv6` 协议的出现做好了准备，该协议将在未来几年内取代如今的标准网络协议 `IPv4`。`IPv6` 提供了 `IPv4` 相同的基本服务，但它支持极大扩展的地址空间，为了更高效的处理进行了简化，并提高了安全性。

除了各种高层协议外，`LINUX` 还支持多种物理网络类型。以太网（`Ethernet`）、令牌环（`Token Ring`）和 `FDDI` 接口，以及多种高速串行接口。

关于网络的更多技术讨论可见第 13 节“网络技术”和第 17 节“网络服务”。

在大多数 IT 机构中，安全是最重要的考虑因素——其他所有考虑因素除外。

# 安全策略

为了在系统管理的背景下理解安全（`SECURITY`），让我们回想我们的首要准则（`Prime Directive`）涉及服务的提供。安全也涉及其推论：拒绝服务。拒绝服务既是为了保护数据不被不当泄露，也是为了确保向合法需要的人提供服务。由于所提供的服务必须建立在正确的数据的基础上，安全还涉及数据完整性。

策略源于需求分析。安全需求往往与其他需求发生冲突。在大多数组织中，每个人都会说安全至关重要。通常，以一种舒适、熟悉且能防止备责的方式完成工作比安全更优先。高级系统管理员在将安全需求转化为策略并选择措施以实现策略目标时，通常必须记住这一点。

与其他策略一样，组织的安全策略必须传发给受影响的人员。内网通常是实现这一点的最佳方式。一份秘密的安全策略只会引发异议，因为用户在不知道某些服务被禁止的情况下要求提供这些被禁止的服务。

关于应该提供和拒绝哪些服务——以及向谁以及在什么情况下提供——这些策略问题，应该先于所有其他安全考虑因素。只有这样，执行策略的机制（即安全工作的日常任务）才能发挥作用。

安全策略的目标是维护数据完整性；确保可用性，并保护数据机密性。实现这些目标的措施是预防、检测和恢复。我们考虑每种措施如何适用于每个目标。

本章关注的是安全策略，而不是该策略的执行。后者将在下一节“执行安全”中介绍。

## 数据完整性

数据的价值取决于其完整性。无论是意外还是故意损坏的数据很少是有用的，而且往往是危险的。例如，医生可能会依赖损坏的医疗数据来开处方药物或计划手术程序。

系统管理员必须采取措施来维护数据完整性：防止其损坏、在损坏发生时检测损坏以及通过恢复数据从损坏中恢复。防止数据完整性的难度各不相同。然而，如果采取了适当措施，检测和恢复数据损坏是很容易的。

### 防止损坏

防止数据损坏的明显防御是将写访问权限限制给那些真正需要的人。理想情况下，所有访问都将被记录，记录谁在何时更改了数据。

### 从损坏中恢复

一旦发现数据损坏，恢复工作就意味着将损坏的数据替换为仍然完好的副本。通常，这通过从存档恢复数据、从原始（可能是外部的）源获取另一个副本，或从源数据重新生成来实现。当然，任何无法从源数据重新生成的有价值的数据都应该进行备份或存档。有关各种备份方法的详尽信息，请参阅第 12 章“备份”。

## 确保可用性

黑客和不满的员工通常都会尝试进行拒绝服务（`DoS`）攻击。这些手段范围广泛，从外部人员使用精心构造的数据包轰击网关机器，到内部人员故意拔掉网络，或者（通常是内部人员）植入特洛伊马和逻辑炸弹。

这类攻击涉及受信任用户恶意在软件将被执行的地方运行该软件。此类软件可能会关闭系统（通常是间歇性的）、损坏数据或销毁数据。不满的软件开发者和系统管理员经常面临此类问题。针对此类攻击的最佳防御是维持良好的团队精神。

拒绝服务攻击通常难以防止，通常（但并非总是）容易检测，并且会带来各种恢复挑战。
