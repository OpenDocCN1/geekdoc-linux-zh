
### 5.4 `cuA` 设备

每个 `ttyS` 设备都有一个对应的 `cua` 设备。计划最终废除 `cua`，因此最好使用 `ttyS`。

从 Linux 内核 `2.2` 开始，使用 `cua` 时内核日志中会出现一条警告信息。这是 `cua` 将消失的预兆。

## 6. 你应该了解的程序

### 6.1 什么是 `getty`？

“`getty`”是一个在登录 Linux 时处理登录过程的程序。如果你想通过调制解调器拨入你的 Linux PC，你需要使用某种类型的 `getty`。如果你只想通过调制解调器拨出，则不需要 `getty`。有三种 `getty` 版本可以在 Linux 下配合调制解调器工作：`getty`、`getty_ps` 和 `aget`。`getty` 是最简单中最弱的，主要用于文本终端。这些程序的语法不同，请确保你使用的 `getty` 具有正确的语法。如果这个句子出现在此 howto 的最新版本中，那么如果你能写几段比较 `getty` 和 `getty_ps` 等的文字，请提交给我以便包含在这里。`getty` 只有几年历史，似乎比旧的 `getty_ps` 更受欢迎。

### 关于 `mget`

`mget` 是一个主要用于调制解调器的 `getty` 版本。它可以用于硬接终端，但文档 `99%` 是关于调制解调器的。除了允许拨号登录外，它还提供了 `FAX` 支持和自动 `PPP` 检测。还有一个名为 `vgetty` 的补充程序可以处理某些调制解调器的语音箱。`mget` 文档（`textinfo` 格式）很好，不需要补充。请参阅安装说明。

## 关于 `getty_ps`

`getty_ps` 包含两个程序：`getty` 用于控制台和终端设备，`uugetty` 用于调制解器。Greg Hanks（Serial-HOWTO 前作者）编写了 `uugetty`，因此关于它的文章包含在这里。请参见 `Uugetty`。其他的 `getty` 在随附的文档中有详细介绍。

## 关于 `getty` 和 `metingetty`

`getty` 是 `getty` 的第三种变体。它是简单且功能完整的 `getty` 实现，最适用于虚拟控制台或终端，而不是调制解器。但在良好条件下，它也能很好用于调制解器。

## 6.2 什么是 `setserial`？

### 介绍

`setserial` 是一个程序，允许你告诉设备驱动软件串口的 `I/O` 地址，`IRQ` 则在端口的硬件中设置。通过适当的选项，它还可以（在给定的 `I/O` 地址）探测串口，但你必须猜测 `I/O` 地址（或者它可能会使用驱动程序认为 `/dev/ttyS` 的任何地址）。`setserial` 不会在串口硬件本身设置 `IRQ` 或 `I/O` 地址。你必须告诉 `setserial` 与硬件中设置的相同的值。这些值在硬件中通过跳线帽或即插即用设置。不要只插入你认为好用的值。然而，如果你知道 `I/O` 地址，也可以命令 `setserial` 尝试确定它。

你可以通过不带任何参数输入 `setserial` 来查看可用的命令列表（但不包括单字母选项，如用于详细输出的 `-v`——你通常在排查故障时应该使用它）。注意 `setserial` 将 `I/O` 地址称为“端口”（`port`）。如果 `setserial` 的参数是 `/dev/tty1`，你将看到一些关于设备驱动如何为该端口配置的信息。但这并不能告诉你硬件是否已设置了这些值。事实上，你可以运行 `setserial` 并输入一个纯虚构的 `I/O` 地址、任何 `IRQ` 以及你想要的任何 `uart` 类型。那么下次当你输入 "setserial..." 时，它将毫无抱怨地显示这些虚假值。注意，`setserial` 进行的赋值在 PC 关机时会丢失，因此通常在每次 Linux 启动时都会自动执行。

### 探测

为了确定你是否有某个串口硬件，必须首先知道它的 `I/O` 地址（设备驱动程序可能有，且很可能是之前由 `setserial` 设置的）。要尝试检测物理硬件，请对 `setserial` 使用 `-v`（详细）和 `autoconfig` 命令。如果结果消息显示 `uart` 类型为 `1650A`，则说明没问题。如果 `uart` 类型显示为“`unknown`”（未知），则在该 `I/O` 地址处没有串口。某些廉价的串口无法正确识别自身，所以当你看到“`unknown`”时，那里可能仍有设备。启动时运行“`setserial`”的文件。自动探测 `uart` 类型功能（`setserial auto-probe for ttyS-`）也不好工作。

### 启动时配置

通常某个地方有一个在启动时运行的文件。如果没有在启动时运行，你的 Linux 系统将使用默认 `IRQ` `4` 和 `3` 自动配置 `ttyS{0-3}`（会导致 `IRQ` 冲突）。在 `1998` 年，它（临时）更改为仅 `ttyS{0-1}`。如果你有超过 `2` 个串口，或者想控制端口的配置方式，应该使用 `setserial`。事实上，你的发行版可能已经设置好了，使得 `setserial` 程序在启动时自动运行。

启动时运行的文件可能位于 `/etc` 目录的某处。你可能使用“`locate`”查找名为 `rc.serial` 或 `setserial` (`Debian`) 的文件。这个在启动时提供的文件可能包含许多被注释的示例。通过取消部分示例的注释并修改它们，你可能能够正确设置或运行一些测试。你可以将其中几个复制到另一个文件并作为 `shell` 脚本执行，但不要忘记复制任何所需的定义，如 `SETERIAL=/bin/serial`。

如果你使用 `setserial`，它会首先在命令行执行，而当你在启动时运行 `/etc/rc.d/rc.serial` 或 `/etc/rc.boot/setserial` 时，它会在启动时运行。如果这些文件不存在，可以使用 `/etc/rc.d/rc.local`（某些人报告说在某个内核下，在串口打开后 `rc.local` 也会执行）。或者，你只需要编辑上述文件之一并碰运气。确保你为 `setserial` 使用了有效的路径和有效的设备名称。

### `IRQs`

默认情况下，`ttyS0` 和 `ttyS2` 共享 `IRQ` `4`，而 `ttyS0` 和 `ttyS3` 共享 `IRQ` `3`。但除非你拥有内核 `2.2` 或更高版本，否则不允许共享串口中断。如果你没有这个现代内核，只有两个串口 `ttyS0` 和 `tty1`，那么你仍然没，因为不存在的设备不存在 `IRQ` 共享冲突。

如果你有超过 `2` 个串口，那么对于小于 `2.2` 的内核，如果两个设备共享相同的 `IRQ`，共享可能是危险的。共享串口中断可能导致数据丢失或系统不稳定。在内核 `2.2` 及以后版本中，内核会正确处理共享情况。

常用的 `setserial` 选项有：
- `-irq <number>` 设置 `IRQ`
- `-io <address>` 设置 `I/O` 地址
- `-uart <type>` 设置 `UART` 类型（例如 `16550A`）
- `-fv <number>` 设置 `FIFO` 模式
- `-parity <number>` 设置校验位
- `-stop <number>` 设置停止位
- `-v` 详细输出

### 7.1 准备好拨号了吗？

在拨号之前，你必须确保调制解器已正确配置并连接到计算机。这涉及检查串口设置、波特率以及调制解器自身的设置。

### 7.2 使用 `Minicom` 拨号

大多数发行版都带有 `Minicom`。要配置它，应该是 `root` 用户。输入“`minicom -s`”，这将带你直接进入配置（设置）菜单。或者你也可以直接运行“`minicom`”，然后按 `^A` 进入状态行。
