
```
all : prog1 prog2 prog3
.PHONY : all

prog1 : prog1.o utils.o
cc -o prog1.o utils.o

prog2 : prog2.o
cc -o prog2 prog2.o

prog3 : prog3.o sort.o utils.o
cc -o prog3.o sort.o utils.o
```

现在你只需要说 `make` 就可以重新制作所有三个程序，或者作为参数指定要制作的程序（例如 `make prog1 prog3`）。

当一个伪目标是另一个伪目标的前提条件时，它充当后者的子程序。例如，这里的 `make cleanall` 将删除对象文件、差异文件以及文件 `program`：

```
cleanall : cleanobj cleandiff
rm program

cleanobj :
rm *.o

cleandiff :
rm *.diff
```

### 4.5 无命令或前提条件的规则

如果一个规则没有前提条件或命令，且该规则的目标是一个不存在的文件，那么 `make` 将认为每当运行其规则时，该目标已更新。这意味着所有依赖于此目标的目标都将执行其命令。

一个示例将说明这一点：

```
clean FORCE
rm $(objects)
```

`FORCE`:

目标 `FORCE` 满足特殊条件，因此依赖于它的目标 `clean` 被强制运行其命令。`FORCE` 这个名字并没有特殊之处，但它是这种常用的名称。

正如你所看到的，这样使用 `FORCE` 的结果与使用 `.PHONY: clean` 相同。

使用 `.PHONY` 更加显式且高效。然而，其他版本的 `make` 不支持 `.PHONY`；因此 `FORCE` 出现在许多 `makefile` 中。参见第 4.4 节 [伪目标]，第 27 页。

### 4.6 用于记录事件的空目标

空目标是伪目标的一种变体；它用于通过其最后修改时间记录命令最后一次执行的时间。与伪目标不同，此文件可以存在；但它的内容并不重要，且通常为空。空目标的目的是执行一个你显式请求的操作。空目标应该有一些前提条件（否则没有意义）。其命令通常是 `touch` 以更新目标。这里有一个示例：

```
print: foo.c bar.c
touch
```

### 4.7 特殊内置目标名称

某些名称作为目标出现时具有特殊含义。

#### `.PHONY`

特殊目标 `.PHONY` 的前提条件被认为是伪目标。当需要考虑此类目标时，无论文件是否存在或其最后修改时间如何，`make` 都会无条件运行其命令。参见第 4.4 节 [伪目标]，第 27 页。

#### `.SUFFIXES`

特殊目标 `.SUFFIXES` 的前提条件是用于检查后缀规则的后缀列表。参见第 10.7 [旧式后缀规则]，第 117 页。

#### `.DEFAULT`

为 `.DEFAULT` 指定命令用于任何未找到规则（显式规则或隐含规则）的目标。参见第 10.6 节 [最后手段]，第 116 页。指定了 `.DEFAULT` 命令，每个作为前提出现但未作为规则目标的文件，都将代其执行这些命令。参见第 10.8 节 [隐含搜索算法]，第 118 页。

#### `.PRECIOUS`

`.PRECIOUS` 依赖的目标将受到以下特殊处理：如果在执行其命令期间 `make` 被杀死或中断，目标将不会被删除。第 5.5 节 [中断或杀死 make]，第 46 页。此外，如果目标是一个中间文件，在它不再需要时将不会被删除，正如通常执行的那样。参见第 10.4 节 [隐含规则链]，第 108 页。在这一点上它与 `.SECONDARY` 目标重叠。

你也可以列出隐含规则的目标模式（例如将 `%.o` 作为特殊目标 `.PRECIOUS` 的前提文件），以保留匹配该文件名的中间文件。

#### `.INTERMEDIATE`

`.INTERMEDIATE` 依赖的目标被视为中间文件。参见第 10.4 节 [隐含规则链]，第 108 页。没有前提条件的 `.INTERMEDIATE` 无影响。

#### `.SECONDARY`

`.SECONDARY` 依赖的目标被视为中间文件，不同之处是它们从不会被自动删除。参见第 10.4 节 [隐含规则链]，第 108 页。

没有前提条件的 `.SECONDARY` 会导致所有目标都被视为二级目标（即没有目标因为被认为是中间文件而被删除）。

#### `DELETE_ON_ERROR`

如果 `DELETE_ON_ERROR` 在 `Makefile` 的任何地方被提及目标，那么当规则的目标发生变化且其命令以非零退出状态结束时，`make` 将删除该目标，就像它接收到信号时一样。参见第 5.4 节 [命令中的错误]，第 44 页。

#### `IGNORE`

如果你为 `.IGNORE` 指定了依赖项，那么 `make` 将忽略这些特定文件在执行命令时产生的错误。`.IGNORE` 的命令是没有意义的。

如果作为没有依赖项的目标被提到，`.IGNORE` 表示忽略所有文件在执行命令时的错误。这种对 `.IGNORE` 的用法仅为了兼容历史版本。由于这会影响 `Makefile` 中的每条命令，因此并不有用；我们建议使用更具选择性的方法来忽略特定命令的错误。参见第 5.4 节 [命令中的错误]，第 44 页。

#### `SILENT`

如果你为 `.SILENT` 指定了依赖项，那么 `make` 将在执行重制这些特定文件之前不打印命令。`.SILENT` 的命令是没有意义的。

如果作为没有依赖项的目标被提到，`.SILENT` 表示在执行任何命令之前不打印它们。这种对 `.SILENT` 的用法仅为了兼容历史版本。我们建议使用更具选择性的方法静默特定命令。参见第 5.1 节 [命令回]，第 41 页。如果你想在某次运行 `make` 时静默所有命令，请使用 `-s` 或 `--silent` 选项（参见第 9.7 节 [选项总结]，第 95 页）。

#### `EXPORT_ALL_VARIABLES`

只需作为目标提及，即可告诉 `make` 默认将所有变量导出到子进程。参见第 5.6.2 节 [向子 make 传递变量]，第 47 页。

#### `NOTPARALLEL`

如果 `NOTPARALLEL` 被提及目标，则本次 `make` 调用将串串行运行，即使给出了 `-j` 选项。任何递归调用的命令仍将并行运行（除非其 `Makefile` 包含此目标）。它的任何依赖项将被忽略。

任何定义的隐式规则后缀如果作为目标出现，也被视为特殊目标，两个后缀的连接（例如 `.c.o`）也是如此。这些目标是后缀，是一种定义隐式规则的过时方法（但仍被广泛使用）。原则上，任何目标名称如果被拆分为两部分并将两部分都添加到后缀列表中，都是特殊的。在实践中，后缀通常以 `.` 开头，因此这些特殊目标名称以 `.` 开头。参见第 10.7 节 [旧式后缀规则]，第 117 页。

### 4.8 规则中的多个目标

具有多个目标的规则等于编写许多规则，每个规则都有一个目标，除外它们都完全相同。相同的命令适用于所有目标，但它们的效果各异，因为你使用 `$0` 在命令中替换实际的目标名称。该规则为所有目标贡献相同的依赖项。

这在两种情况下有用：

- 你想要依赖项但不需要命令。例如：

```
kbd.o command.o files.o: command.h
```

这为提到的三个对象文件中的每个文件提供额外的依赖项。

- 相似的命令适用于所有目标。命令不需要完全相同，因为自动变量 `$0` 可以用于在命令中替换要重制的特定目标（参见第 10.5.3 节 [自动变量]，第 111 页）。例如：

```
bigoutput : text.g
generate text.g -$(sub output,$0) > $0
```

等同于

```
bigoutput : text.g
generate text.g -big > bigint
littleoutput : text.g
generate text.g -little > littleoutput
```

我们假设假设程序 `generate` 生成两种输出，一个给定 `big`，另一个给定 `little`。参见第 8.2 节 [字符串替换与分析函数]，第 76 页，关于 `sub` 函数的解释。

假设你想根据目标来更改依赖项，就像变量 `$0` 允许你更改命令一样。你不能在普通规则中通过多个目标来实现这一点，但可以通过静态模式规则实现。参见第 4.10 节 [静态模式规则]，第 34 页。

### 4.9 同一个目标的多个规则

一个文件可以是多个规则的目标。所有规则中提到的依赖项将合并为该目标的依赖项列表。如果目标比任何规则中的任何依赖项都旧，则执行命令。

一个文件只能执行一组命令。如果有多个规则为同一个文件提供了命令，`make` 将使用最后给出的一组命令并打印错误信息。（作为一个特殊情况，如果文件名以 `.` 开头，则不打印错误信息。这种奇怪的行为仅是为了兼容其他实现……你应该避免使用它。）有时，让同一个目标调用在 `Makefile` 不同部分定义的多个命令是有用的；你可以使用双冒号规则（参见第 4.1 节 [双冒号]，第 37 页）来实现。
