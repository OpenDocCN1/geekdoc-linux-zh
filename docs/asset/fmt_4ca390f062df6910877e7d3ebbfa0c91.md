
```
[melinuxbox ~]$ sudo shutdown -r now
```

延迟可以用多种方式指定。详情请参见 `shutdown` 页面。一旦执行 `shutdown` 命令，消息将“广播”给所有登录用户，警告他们即将发生的该事件。

## 总结

大多数现代系统都有管理多个进程的机制，Linux 为此提供了丰富的工具。鉴于 Linux 是全球部署最广泛的服务器操作系统，这非常有意义。然而，与其他一些系统不同，Linux 主要依赖命令行工具进行进程管理。虽然 Linux 有图形化进程工具，但由于速度快且占用小，命令行工具更受欢迎。虽然 GUI 工具可能看起来很好，但它们通常会产生大量的系统负载，这在某种程度上违背了初衷。

# 第二部分 配置与环境

# 11 环境

正如我们之前讨论的，shell 在 shell 会话期间维护一组被称为环境的信息。程序使用存储在环境中的数据来确定系统配置的事。虽然大多数程序使用配置文件来存储程序设置，但某些程序还会查找环境变量中的值来调整其行为。了解这一点，我们可以使用环境来定制 shell 体验。

在本章中，我们将使用以下命令：

- `printenv` 打印部分或全部环境变量
- `set` 设置 shell 选项
- `export` 将环境变量导出到后续执行的程序
- `alias` 为命令创建别名

## 环境中存储了什么？

shell 在环境中存储了两种基本类型的数据；尽管在 `bash` 中，这些类型很大程度上无法区分。它们是环境变量和 shell 变量。shell 变量是 `bash` 放置在那里的数据，而环境变量是其他所有内容。除了变量，shell 还存储了程序数据，即别名和 shell 函数。第 5 章涵盖了别名，我们将在本书的第四部分介绍 shell 函数（与 shell 脚本相关）。

## 检查环境

要查看环境中存储了什么，我们可以使用 `bash` 的内置命令 `set` 或 `printenv` 程序。`set` 命令将同时显示 shell 变量和环境变量，而 `printenv` 只显示环境变量。由于环境内容的列表相当长，最好将每个命令的输出管道到 `less`：

```
me@linuxbox ~$ printenv | less
```

这样做，我们得到类似下面的内容：

```
USER=me
PAGER=less
LSCOLOR=Gfxxccdxbxegedababagacad
XDG_CONF_DIRS=/etc/xdg/xdg-ubuntu=/usr/share/upstart/xdg:/etc:/xdg
PATH=/home/me/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/bin:/bin:/usr/games:/usr/local/games
DESKTOP_SESSION=ubuntu
QT_IM_MODULE=ibus
QPA_PLATFORM=
```

## 表 11-2：登录会话的启动文件

| 文件 | 内容 |
| :--- | :--- |
| `/etc/profile` | 一个适用于所有用户的全局配置脚本。 |
| `~/.bash_profile` | 用户的个人启动文件。它可以用于扩展或覆盖全局配置脚本中的设置。 |
| `~/.bash_login` | 如果未找到 `~/.bash_profile`，`bash` 会尝试读取此脚本。 |
| `~/.profile` | 如果既未找到 `~/.bash_profile` 也未找到 `~/.bash_login`，`bash` 会尝试读取此文件。这是基于 Debian 的分发行版（如 Ubuntu）的默认设置。 |

非登录 shell 会话会读取表 11-3 所示的启动文件。

## 表 11-3：非登录 shell 会话的启动文件

| 文件 | 内容 |
| :--- | :--- |
| `/etc/bash.bashrc` | 一个适用于所有用户的全局配置脚本。 |
| `~/.bashrc` | 用户的个人启动文件。它可以用于扩展或覆盖全局配置脚本中的设置。 |

除了读取表 11-3 中列出的启动文件外，非登录 shell 还会从其父进程（通常是登录 shell）继承环境。看看这些启动文件中安装了哪些。请记住——由于列出的文件名以点开头（意味着它们是隐藏文件），我们在使用它们时需要使用 `-a` 选项。

从普通用户的角度来看，`~/.bashrc` 可能是最重要的启动文件，因为它几乎总是会被读取。非登录 shell 默认会读取它，而大多数登录 shell 的启动文件在编写时也会设计为读取 `~/.bashrc` 文件。

## 启动文件中包含什么？

如果我们查看一个典型的 `.bash_profile`（取自 CentOS 6 系统），它看起来像这样：

```
## .bash_profile

## 获取别名和函数
if [ -f ~/.bashrc ]; then
  ~/.bashrc
fi
```

以 `#` 开头的行是注释，shell 不会读取它们。这些内容是为了人类可读性。第一个有趣的事情出现在第四行，代码如下：

```
if [ -f ~/.bashrc ]; then
  ~/.bashrc
fi
```

这被称为 `if` 复合命令，当我们在第四部分学习脚本时会详细介绍，但现在，这里是它的翻译：

如果文件 `~/.bashrc` 存在，则读取 `~/.bashrc` 文件。

我们可以看到，这段代码是登录 shell 获取 `.bashrc` 内容的方式。我们启动文件中下一个内容与 `PATH` 变量有关。

你是否想过，当我们在命令行输入命令时，shell 是如何知道去哪里寻找命令的？例如，当我们输入 `ls` 时，shell 并不会搜索整个计算机来寻找 `/bin/ls`（`ls` 命令的完整路径），而是搜索 `PATH` 变量包含的目录列表。

`PATH` 变量通常（但并非总是，取决于发行版）由 `/etc/profile` 启动文件通过以下代码设置：

```
PATH=$PATH:$HOME/bin
export PATH
```

`PATH` 被修改为将 `$HOME/bin` 目录添加到列表末尾。这是参数扩展的一个示例，我们在第 7 章中提到过。为了演示它是如何工作的，请尝试以下操作：

```
[melinux] $ foo="This is some"
[melinux] $ echo foo
This is some
[melinux] $ foo=$foo"text."
[melinux] $ echo foo
This is some text.
```

使用这种技术，我们可以向变量内容的末尾追加文本。

通过在输入命令时将 `$HOME/bin` 添加到搜索目录列表中，这意味着我们可以在家目录下创建一个目录来存储自己的私有程序，shell 已经准备好支持我们了。我们只需要将其命名为 `bin`，就可以开始工作了。

许多发行版默认提供此 `PATH` 设置。像 Ubuntu 等基于 Debian 的发行版在登录时会检查 `~/bin` 目录是否存在，如果找到该目录，则动态将其添加到 `PATH` 变量中。

最后，我们有这个：

```
export PATH
```

`export` 命令告诉 shell 让 `PATH` 的内容对该 shell 的子进程可用。

## 修改环境

由于我们知道启动文件所在的位置以及它们包含的内容，因此我们通过修改它们来定制自己的环境。

## 我们应该修改哪些文件？

作为一个通用规则，若要向你的 `PATH` 中添加目录或定义环境变量，请将这些更改放在 `~/.bash_profile`（或根据你的发行版使用的对应文件）中；例如，Ubuntu 使用 `~/.profile`。对于其他所有内容，将更改放在 `~/.bashrc` 中。

> 除非你是系统管理员并需要更改系统中所有用户的默认设置，否则请将你的修改限制在主目录下的文件中。更改 `/etc` 中的文件作为配置文件是完全可能的，在许多情况下这样做也是明智的，但目前让我们安全起见。
