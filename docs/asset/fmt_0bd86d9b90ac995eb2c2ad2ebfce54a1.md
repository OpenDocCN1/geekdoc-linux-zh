### 状态报告

在交互式运行时，shell 会跟踪每个作业的状态，并在作业完成或被阻塞时报告。为了避免干扰你的输入外观，shell 通常会在发布提示符时显示此类此类信息的消息。如果设置了 `notify` 变量，则表示 shell 将立即报告状态变化。默认情况下，`notify` 命令标记当前进程；在启动后台作业后，输入 `notify` 即可标记它。

### 内置命令

内置命令在 C shell 内部执行。如果内置命令作为管道中除最后一个之外的任何组件出现，它将在子 shell 中执行。

> 注意 — Shell 内置函数是不可停止/不可重启的。形式为 `a; b; c` 的 shell 命令在尝试停止时，也不会被优雅地处理。如果你挂起 `b`，shell 永远不会执行 `c`。如果展开结果源于别名 `alias`，这个问题会尤为明显。可以通过将序列放在括号中强制其进入子 shell 来避免这个问题。

用户有责任手动删除通过多次使用 `set path = paths` 或 `setenv paths` 等内置命令积累的所有重复路径。例如，这些重复通常是因为 shell 脚本或 `.cshrc` 文件执行了类似 `set path=(/usr/local /hosts $path)` 的操作，以确保这些目录在路径列表中。

```

```

限制当前进程或任何派生进程的消耗，使其在指定的资源上超过 `max-use`。如果你省略 `max-use`，则打印当前限制；如果你省略 `resource`，则显示所有限制。（运行 `getsize(M)` 命令以获取系统的最大限制。报告的值是十六进制，但你可以使用 `bc(1)` 命令将其转换为十进制数字）。
- `-h` 使用硬限制代替当前限制。硬限制对当前限制的值设定了上限。只有超级用户可以提高硬限制。

`resource` 可以是以下值之一：
- `-cputime` 每个进程的最大 CPU 秒数。
- `-filesize` 单个文件限制；受文件系统限制。参见 `df(1)`。
- `-datasize` `heapsize` 进程的最大数据大小（包括栈）；你的虚拟内存大小。参见 `swap(1M)`。
- `-stacksize` 进程的最大栈大小。参见 `swap(1M)`。

`coredumpsize` 核心转储（文件）的最大大小；受限于文件系统的大小。

`descriptors` 文件描述符的最大数量。运行 `sysdef()`。

`memoryize` 虚拟内存的最大大小。

`memoryize-max-use` 是一个数字，带有可选的缩放因子，如下所示：
- `-nh` 小时（用于 `cputime`）
- `-nk` v 千字节，除 `cputime` 以外所有项的默认值。
- `-nm` v 兆字节或分钟（用于 `cputime`）。
- `-mm:v` 分和秒（用于 `cputime`）。

限制示例：要将核心转储的大小限制为 0 兆字节，请输入以下内容：

```
limit coredumpsize 0M
```
