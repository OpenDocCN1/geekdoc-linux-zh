
这些是归档程序：

- `tar`: 磁带工具。

## 压缩文件

在整个计算历史上，一直存在着将尽可能多的数据放入最小可用空间的斗争，无论是内存、存储设备还是网络带宽。我们今天认为所当然的许多数据服务，如手机、高清电视或宽带互联网，它们的生存都归功于有效的压缩技术。

让我们考虑一个假设的例子。假设有一张尺寸为 100x100 像素的全黑色图片。从数据存储的角度来看（假设每个像素 24 位，即 3 字节），该图像将占用 30,000 字节的存储空间。100 × 100 × 3 = 30,000。全单色的图像包含冗余数据。如果我们足够聪明，可以以这种方式编码数据，只需描述我们拥有一块 10,000 个黑色像素即可。因此，与其存储一个包含 30,000 个零的数据块（黑色在图像文件中通常表示为零），我们可以将数据压缩为数字 10,000 后面跟一个零来表示我们的数据。这种压缩方案被称为等长长度编码（`run-length encoding`），是最基础的压缩技术之一。今天的技术要先进且复杂得多，但基本目标仍然保持不变——消除冗余数据。

**算法**（用于执行压缩的数学技术）分为两个大类。

**无损压缩**保留原始文件中的所有数据。这意味着当从压缩版本恢复文件时，恢复后的文件与原始未压缩版本完全相同。

**有损压缩**在执行压缩时会删除数据，以便应用更多的压缩。当恢复有损文件时，它与原始版本不匹配；而是一个接近的近似值。有损压缩的例子包括 `JPEG`（用于图像）和 `MP3`（用于音乐）。

在我们的讨论中，我们将专门讨论无损压缩，因为计算机上的大多数数据无法忍受任何数据丢失。

## gzip

`gzip` 程序用于压缩一个或多个文件。执行时，它用原始文件的压缩版本替换原始文件。相应的 `gunzip` 程序用于将压缩文件恢复到其未压缩的形式。以下是一个示例：

```
$ ls -l /etc/ > foo.txt
$ ls -l foo.*
-rw-r--r-- 1 me 15738 2025-10-14 07:15 foo.txt
$ ls -l gzip foo.txt
$ ls -l foo.*
-rw-r--r-- 1 me 32380 2025-10-14 07:15 foo.txt.gz
$ ls -l foo.*
-rw-r--r-- 1 me 15738 2025-10-14 07:15 foo.txt
```

在这个示例中，我们从目录列表创建了一个文本文件 `foo.txt`。接下来，我们运行 `gzip`，它用压缩版本 `foo.txt.gz` 替换原始文件。在 `foo.*` 的目录列表中，我们看到原始文件已被压缩版本替换，且压缩版本的大小是原始文件的五分之一。我们还可以看到压缩文件的权限和时间戳与原始文件相同。

接下来，我们运行 `gunzip` 解压缩文件。之后，我们看到压缩版本具有权限和时间戳。`gzip` 有许多选项，如表 18 所示。

### 表 18-1：gzip 选项

| 选项 | 描述 |
| :--- | :--- |
| `-c` | 将输出写入标准输出 `stdout`。 |
| `-d` | 解压缩。 |
| `-f` | 即使文件存在也强制执行。 |
| `-h` | 显示用法。 |
| `-l` | 列出统计信息。 |
| `-r` | 递归。 |
| `-t` | 测试文件的完整性。 |
| `-v` | 显示信息。 |
| `-number` | 设置压缩程度 `1-9`。 |

如果我们的目标只是查看压缩文件的内容，我们可以这样做：

```
$ gzip -c foo.txt | less
```

或者，`gzip` 提供了一个名为 `zcat` 的程序，等同于带有 `-c` 选项的 `gzip`。它可以像 `zcat` 一样用于 `gzip` 压缩的文件：

```
$ zcat foo.gz | less
```

还有一个 `zless` 程序。它执行与之前的管道相同的功能。我们讨论过的所有选项（`-r` 除外）都受支持。然而，压缩级别选项 `-number` 与 `bzip2` 的含义略有不同。`bzip2` 还提供了 `bunzip2` 和 `bcat` 用于解压缩文件。`bzip2` 还带有 `bzip2recover`，它可以恢复损坏的 `.bz` 文件。

## bzip2

`bzip2` 程序由 Julian Seward 开发，与 `gzip` 类似，但使用了不同的压缩算法，以压缩速度为代价获得了更高的压缩率。在大多数方面，它的工作方式与 `gzip` 相同。用 `bzip2` 压缩的文件以 `.bz2` 为结尾。

```
$ ls -l /etc > foo.txt
$ ls -l foo.*
-rw-r--r-- 1 me 15738 2025-10-14 07:15 foo.txt
$ ls -l bzip2 foo.txt
$ ls -l foo.txt.bz2
-rw-r--r-- 1 me 2792 2025-10-17 13:51 foo.txt.bz2
$ bunzip2 foo.txt.bz2
```

正如我们所看到的，`bzip2` 可以像 `gzip` 一样使用。我们讨论过的所有选项（`-r` 除外）`bzip2` 都支持。然而，压缩级别选项 `-number` 与 `bzip2` 的含义略有不同。`bzip2` 提供了 `bunzip2` 和 `bcat` 用于解压缩文件。

## 不要过度强迫症

我偶尔会看到人们尝试对已经用有效压缩算法压缩的文件再次压缩，就像如下操作：

```
gzip picture.jpg
```

不要这样做。你可能在浪费时间和空间！如果你对一个已经压缩的文件应用压缩，通常会得到一个更大的文件。这是因为所有压缩技术都涉及某些添加到文件中的开销，用于描述该压缩信息。如果你尝试压缩一个已经不包含冗余信息的文件，压缩通常不会产生任何用以抵消额外开销的节省。

## 文件归档

文件管理中一个经常与压缩配合使用的常见任务是归档。归档是将许多文件收集并将它们打包成单个大文件的过程。归档通常作为系统备份的一部分进行。当旧数据从系统移动到某种长期存储类型时，也会使用它。

## tar

在类 Unix 软件世界中，`tar` 程序是归档文件的经典工具。它的名字是 `tape archive`（带存档）的缩写，揭示了它作为制作备份带工具的起源。虽然它仍被用于传统任务，但在处理其他存储设备时同样得心。我们经常看到以 `.tar` 或 `.tgz` 结尾的文件名，这表示“纯”`tar` 归档和 `gzipped` 归档。一个 `tar` 归档可以由一组单独的文件、一个或多个目录，或者两者的混合组成。命令用法如下：

```
tar mode[options] pathname...
```

在这里，`mode` 是表 18-2 中列出的运行模式之一（此处仅显示部分列表；完整列表请参见 `tar` man 手页）。

### 表 18-2：tar 模式

| Mode | 描述 |
|---|---|
| `c` | 从文件和/目录列表创建归档 |
| `x` | 提取归档。 |
| `r` | 将指定的路径追加到归档末尾。如果归档不存在，则创建它。 |
| `t` | 列出归档的内容。 |

`tar` 使用选项的方式略显奇异，因此我们需要一些示例来展示它是如何运作的。首先，让我们重新创建上一章中的实验场：

```
melinuxbox ~$ mkdir -p playground/dir-(001..100)
melinuxbox ~$ touch playground/dir-(001..100)/file-(A..Z)
```

接下来，让我们创建整个实验场的归档：

```
melinuxbox ~$ tar cf playground.tar playground
```

此命令创建了一个名为 `playground.tar` 的归档，包含了整个目录层次结构。我们可以看到 `mode` 和 `f` 选项（用于指定 `tar` 归档名称）可以合并，且不需要前导横杠。但请注意，`mode` 必须在任何选项之前指定。

要列出归档的内容，我们可以这样做：

```
melinuxbox ~$ tar tf playground.tar
```

为了获得更详细的列表，我们可以添加 `v`（详细）选项。

```
melinuxbox ~$ tar vf playground.tar
```

现在，让我们在一个新位置提取 `playground`。我们将通过更改目录并提取 `tar` 归档来实现。

```
melinuxbox ~$ mkdir foo
melinuxbox ~$ cd foo
melinuxbox ~$ tar xf ../playground.tar
melinuxbox ~$ ls
playground
```

如果我们检查 `~/foo/playground` 的内容，可以看到归档已成功安装，创建了原始文件的副本。然而，有一个例外：除非我们以超级用户身份操作，否则从归档中提取的文件和目录将归执行还原操作的用户所有，而不是原始所有者。

`tar` 的另一个有趣行为是它处理归档中路径的方式。路径的默认值是相对的，而不是绝对的。`tar` 通过在创建归档时简单地删除路径中的任何前导横杠来实现这一点。为了演示这一点，我们将指定绝对路径来创建归档：

```
melinuxbox ~$$ cd
melinuxbox ~$ tar cf playground2.tar ~/playground
```

记住，当我们按下回车键时，`~/playground` 将展开为 `/home/me/playground`，我们将获得演示所需的绝对路径。接下来，我们将像之前一样提取归档看看发生了什么：

```
[me@linuxbox ~]$ cd foo
[me@linuxbox foo]$ tar xf ../playground2.tar
[me@linuxbox foo]$ ls
home playground
[me@linuxbox foo]$ ls home
[me@linuxbox foo]$ ls home/me
playground
```

在这里，我们可以看到我们提取第二个归档时，`~/` 相对于我们的工作目录 `~/foo` 重新创建了 `home/me/playground` 目录，而不是相对于根目录（如果是绝对路径将会如此）。这看起来像是一个很奇怪的方式，但实际上它比这更有用，因为允许我们将归档提取到任何位置，而不是被迫将它们提取到原始位置。通过包含详细选项 `v` 重复该练习，将让我们更清晰地看到发生了什么。

让我们考虑一个 `tar` 的假设性示例。假设我们想将 `home` 目录及其内容从一个系统复制到另一个系统，并且我们有一个用于传输的大型 USB 驱动器。在我们现代 Linux 系统上，驱动器会“自动”挂载在 `/media` 目录中。让我们假设在连接磁盘时，磁盘的卷名称为 `bigDisk`。为了制作归档，我们将使用：

```
tar cvf /media/bigDisk/home.tar ~/
```

归档创建后，我们可以将 USB 驱动器移动到另一台计算机上并提取它：

```
[me@linuxbox ~]$ cd /
[me@linuxbox ~]$ tar xvf /media/bigDisk/home.tar
```

这演示了 `tar` 如何在系统之间移动数据。通过在归档中使用相对路径，我们确保了目录结构相对于提取点被保留。

```
$me@linuxbox-$ mkdir remote-stuff
$me@linuxbox-$ cd remote-stuff
$me@linuxbox-remote-stuff-$ ssh remote-sys 'tar cf - Documents' | tar xf -
me@remote-sys$ password: 
$me@linuxbox-remote-stuff-$ ls
```

在这里，我们将名为 `Documents` 的目录从远程系统复制到本地系统中名为 `remote-stuff` 的目录中。我们是如何到的？首先，我们通过 `ssh` 在远程系统上启动了 `tar` 程序。记住，`ssh` 允许我们在网络计算机上远程执行程序，并在本地系统上“查看”结果。我们可以利用这一点，让 `tar` 创建一个存档（`c` 模式）并发送到标准输出，而不是文件（带横杠参数的 `f` 选项），从而通过 `ssh` 将该存档传输到本地系统。在本地系统中，我们执行 `tar` 并从标准输入提供存档（同样使用带横杠的 `f` 选项，即 `x` 模式）。

## zip

`zip` 程序既是压缩工具也是归档工具。该程序使用的文件格式对 Windows 用户来说非常熟悉，因为它读取和写入 `.zip` 文件。在 Linux 中，`zip` 是最主要的压缩程序，`zip2` 紧随其后。

在最基本的情况下，`zip` 的调用方式如下：

```
zip options zipfile...
```

例如，为了为我们的实验场创建一个 `.zip` 存档，我们将执行如下操作：

```
$me@linuxbox-$ zip -r playground.zip playground
```

除非我们使用 `-r` 选项进行递归，否则只会存储 `playground` 目录（但不包含其任何内容）。尽管添加 `.zip` 扩展是自动的，但为了清晰起见我们将包含文件扩展名。

在创建 `.zip` 存档期间，`zip` 通常会显示一系列消息：

```
adding: playground/dir-020/file-Z (stored 0%)
adding: playground/dir-020/file-Y (stored 0%)
adding: playground/dir-020/file-X (stored 0%)
adding: playground/dir-087/ (stored 0%)
adding: playground/dir-087/file-S (stored 0%)
```

这些消息显示了添加到存档中的每个文件的状态。`zip` 将使用两种存储方法之一将文件添加到存档中：它会“存储”`store` 一个不压缩的文件（如下所示），或者会通过“压缩”`deflate` 来对其进行压缩。存储方法后显示的数字值表示所实现的压缩程度。由于我们的实验场只包含空文件，因此对其内容没有进行任何压缩。

## 使用 `unzip` 程序提取 `zip` 文件的内容是非常直观的：

```
[me@linuxbox]$ cd foo
[me@linuxbox]$ unzip ../playground.zip
```

关于 `unzip` 需要注意的一点（与 `tar` 不同）是，如果指定已存在的存档，它将进行更新而不是替换。这意味着现有的存档会被保留，但会添加新文件并替换匹配的文件。

可以通过向 `unzip` 指定特定的文件来从 `zip` 存档中列出并提取文件。

```
[me@linuxbox]$ unzip -l playground.zip playground/dir-087/file-Z
Archive: .../playground.zip
Length  Date         Time    Name
0       10-05-25 09:25 playground/dir-087/file-Z
0                               1
```

```
[me@linuxbox]$ unzip ../playground.zip playground/dir-087/file-Z
Archive: ..//playground.zip
replace playground/dir-087/file-Z? [y]es, [n],[A]ll, [N]one, [r]name: y
extracting: playground/dir-087/file-Z
```

使用 `-l` 选项会导致 `unzip` 在不提取的情况下列出存档内容。如果没有指定文件，`unzip` 将列出存档中的所有文件。可以添加 `-v` 选项来增加输出的详细程度。注意，当存档提取与现有文件冲突时，会在替换文件之前提示用户。

默认情况下，`unzip` 将文件提取到当前目录。要指定备选的提取目录，请使用 `-d` 选项后跟目标目录的名字。

与 `tar` 类似，`unzip` 可以使用标准输入和输出，尽管它的实现稍微没那么灵活。可以通过 `-@` 选项将文件列表管道传输给 `unzip`。

```
[me@linuxbox]$ cd foo
[me@linuxbox]$ find playground -name "file-A" | zip -o file-A.zip
```

在这里，我们使用 `find` 生成匹配测试 `-name "file-A"` 的文件列表，然后将该列表传递给 `zip`，创建一个包含所选文件的 `file-A.zip`。

`zip` 也支持将输出写入 `stdout`，但它的用途很有限，因为很少有程序可以使用该输出。遗憾的是，`unzip` 程序不接受标准输入。这阻止了 `unzip` 像 `tar` 那样用于网络文件复制。

然而，`zip` 可以接受标准输入，因此它可以压缩其他程序的输出。

```
[me@linuxbox]$ ls -l /etc/ | zip ls-etc.zip
adding: (deflated 80%)
```

在这个中，我们将 `ls` 的输出管道到 `zip`。像 `tar` 一样，`zip` 将结尾的横杠解释为“文件列表的标准输入”。注意，`zip` 将存储压缩后的文件——从而对其进行压缩——存储方法后显示的数字值表示所实现的压缩程度。由于我们的实验场只包含空文件，对其内容没有进行任何压缩。

## 同步文件和目录

维护备份的常用策略是保持目录镜像。`rsync` 检测源和目标目录之间的差异并复制更改。

`rsync` 非常快，因为它检测源和目标之间的差异并只复制更改。

当我们指定 `rsync` 源时，有一个用的功能。让我们考虑这两个目录：

```
me@linuxbox-$ ls
source
```

`source` 目录包含一个文件 `file1`，而 `destination` 目录是空的。我们执行如下从 `source` 到 `destination` 的复制：

```
me@linuxbox-$ rsync source destination
```
