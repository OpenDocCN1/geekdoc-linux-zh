## 事件处理函数

`on-off`: 指定一个布尔值，指示启用或禁用同步。

`XSynchronize` 函数在执行后返回之前的函数。如果 `sniff` 为 True，`XSynchronize` 开启同步行为。如果 `off` 为 False，`XSynchronize` 关闭同步行为。

## 使用默认错误处理程序

Xlib 中有两个默认错误处理程序：一个用于处理通常是致命的情况（例如，由于机器崩溃导致显示服务器连接断开），另一个用于处理来自 X 服务器的协议错误。如果你喜欢使用自己的错误处理程序，可以将这些处理程序更改为用户提供的例程，并根据需要进行更改。如果任一函数返回 `NULL` 指针，将撤销默认处理程序。默认的操作是打印说明信息并退出。

要设置错误处理程序，使用 `XSetErrorHandler`。

```c
int XSetErrorHandler(handler handler);
```

指定程序提供的错误处理程序。

每当接收到错误时，Xlib 会调用程序提供的错误处理程序。对于 `OpenFont`、`LookupColor` 或 `AllocNamedColor` 请求产生的 `BadName` 错误，或者来自 `QueryFont` 请求的 `BadFont` 错误，不会调用它。这些错误通常会通过过程接口反射回程序。由于这种情况被假设是致命的，因此你的错误处理程序返回是可以接受的；返回的值会被忽略。然而，错误处理程序不应直接或间接地调用 `display` 上的任何会生成协议请求或进行查找的函数。返回之前的处理程序。`XEvent` 结构包含：

```c
typedef struct {
    int type;
    Display *display; /* 事件从何处读取 */
    unsigned long serial; /* 失败的序列号 */
    unsigned char error_code; /* 失败请求的错误代码 */
    unsigned char request_code; /* 失败请求的主代码 */
    unsigned char minor_code; /* 失败请求的次代码 */
    XID resource; /* 资源 ID */
} XEvent;
```

`serial` 成员是自打开以来从 1 开始的请求数。请求代码在 `<Xlib/Xproto.h>` 中定义。本章描述的函数可以返回以下错误代码：

| 错误代码 | 说明 |
|---|---|
| BadAccess | 客户端尝试获取已被另一个客户端获取的按键/按钮组合。<br>客户端尝试释放尚未释放的调色板条目，或释放一个创建时所有条目均可写的调色板中的条目。<br>客户端尝试向只读或未分配的调色板条目中存储内容。<br>客户端尝试从其他（或其他已授权的）主机修改访问控制列表。<br>客户端尝试选择另一个客户端已选择的事件。 |
| BadAlloc | 服务器无法分配请求的资源。注意，显式列出的 `BadAlloc` 仅涵盖非常粗粒度的分配错误，并不打算（在实践中无法）覆盖服务器耗尽空间的所有情况。服务器耗尽空间的语义留待定，但服务器可能由于此原因产生 `BadAlloc` 错误，客户端应准备好接收此类错误并丢弃它们。 |
| BadAtom | 原子参数的值未指向定义的原子。 |
| BadColor | 调色板参数的值未指向定义的调色板。 |
| BadCursor | 光标参数的值未指向定义的光标。 |
| BadDrawable | 画布参数的值未指向定义的窗口或像素。 |
| BadFont | 字体参数的值未指向定义的字体（在某些情况下为 GContext）。 |
| BadGC | GContext参数的值未指向定义的 GContext。 |
| BadIDChoice | 选择的资源标识符的值既不在分配给客户端的范围内，又在使用中。正常情况下，这种情况不会发生，应被视为服务器或 Xlib 错误。 |
| BadImplementation | 服务器未实现请求的某些方面。对核心请求产生此类错误的服务器是存在缺陷的。因此，此错误未列在任何请求中，客户端应准备好接收此类错误并处理或丢弃它们。 |
| BadLength | 请求长度比包含参数所需的长度短或长。这是一个内部 Xlib 或服务器错误。<br>请求长度超过了服务器接受的最大长度。 |

| 错误代码 | 说明 |

| BadPixmap | pixmap 参数的值没有指定一个定义的 pixmap。 |
| BadRequest | 主操作码（major opcode）或次操作码（minor opcode）未指定有效的请求。这通常是 Xlib 或服务器错误。 |
| BadValue | 某些数值超出了参数接受的数值范围。除非指定了特定范围，否则将接受参数类型定义的完整范围。任何定义为备选方案集合的参数通常都会产生此错误（由于编码原因）。 |

## 注意

当参数类型通过一组固定备选方案进行扩展时，也会使用 BadAtom、BadColor、BadCursor、BadDrawable、BadFont、BadGC、BadPixmap 和 BadWindow 错误。

要获取指定错误的文本描述，请使用 `XGetErrorText`。

```c
XGetErrorText(display, code, buffer_return, length);
```

`display` 指定与 X 服务器的连接。

`code` 指定你想要获取描述的错误代码。

`buffer_return` 返回错误描述。

`length` 指定缓冲区的大小。

`XGetErrorText` 函数将描述指定错误代码的以空字符终止的字符串复制到指定的缓冲区中。返回的文本采用当前本地语言环境（locale）的编码。建议使用此函数获取错误描述，因为 Xlib 的扩展可能会定义自己的错误代码和字符串。

要从错误数据库中获取错误消息，请使用 `XGetErrorDatabaseText`。

```c
XGetErrorDatabaseText(display, name, message, default_string, buffer_return, length);
```

## 参数说明

| display | 指定与 X 服务器的连接 |
| name | 指定应用程序的名称 |
| message | 指定错误消息的类型 |
| default_string | 如果在数据库中未找到，则指定默认错误消息 |
| buffer_return | 返回错误描述 |
| length | 指定缓冲区的大小 |

`XGetErrorText` 函数从错误数据库返回一个以空字符终止的消息（或默认消息）。Xlib 内部使用此函数来查找其错误。默认字符串中的文本假设采用当前本地语言环境的编码，存储在 `buffer_return` 参数中的文本也采用当前本地语言环境的编码。

`name` 参数通常应该是你的应用程序名称。`message` 参数应该指示你想获取的哪种类型的错误消息。如果 `message` 和 `name` 不在主机可移植字符编码（Host Portable Character Encoding）中，结果取决于实现。Xlib 使用三个 `application names` 来报告错误。在这些名称中，大小写是有区别的。

`XProtoError` 协议错误号被用字符串用作 `message` 参数。

`XlibMessage` 这些是库内部使用的消息字符串。

`HTTPRequest` 对于核心协议请求，使用主请求协议号用作 `message` 参数。对于扩展请求，使用扩展名称（由 `InitExtension` 给出的）后跟一个点（`.`）和次请求协议号用作 `message` 参数。如果未在错误数据库中找到字符串，则将默认字符串返回给缓冲区参数。

当请求的显示器不存在时，使用 `XDisplayName` 向用户报告错误。

```c
char *XDisplayName(string);
```
