# 术语表

由于这不是一本关于操作系统原理的通用书籍，书中描述了许多与操作系统相关的术语，但没有提供完整的定义。本章提供了这些术语以及文件系统相关术语的表。

### `/proc`
进程文件系统，也称为 `/proc` 文件系统，是一个伪文件系统，向用户显示机器上运行进程的层次结构视图。文件系统中每个用户进程都有一个目录，其中包含了关于每个进程的大量信息 `/proc` 文件系统还提供了跟踪运行进程和调试另一个进程的方法。

### `ACL`
访问控制列表，或常被称为 `ACL`，在传统的 UNIX 安全模型之上提供了额外的安全层级。`ACL` 是一个允许访问文件的用户列表，并规定了它们被允许的访问类型。

### `address space`
地址空间一术语主要有两个用途。它可以指用户进程可以访问的地址——这些用户指令、数据、栈、库和映射文件就位于此处。通过使用硬件机制，一个用户地址空间受到免受另一个用户的保护。该术语的另一个用途是描述内核的指令、数据和栈区域。通常只有一个内核地址空间，它免受用户进程的保护。

### `AFS`
Andrew 文件系统 (`AFS`) 是由 CMU 的 Andrew Project 开发的分布式文件系统。`AFS` 的目标是创建一个跨越多个校区的统一、分布式命名空间。

### `aggregate`
聚合。UNIX 文件系统占用磁盘分片、分区或逻辑卷。文件系统内部是一个层次结构命名空间，它导出一个可以挂载的根文件系统。在 DFS 文件系统组件中，每个磁盘分片都复制文件集的聚合，每个文件集都有自己的层次结构命名空间，并且都导出一个根目录。每个文件集可以被单独挂载，在 DFS 中，文件集可以从一个聚合迁移到另一个聚合。

### `AIX`
这是由 IBM 分发的 UNIX 版本。

### `allocation unit`
分配单元（在 `VxFS` 文件系统中找到）是文件系统内整体存储的子集。在旧的 `VxFS` 文件系统中，文件系统被分为若干固定大小的分配单元，每个单元都有自己的一组索引节点 (`inodes`) 和数据块。

### `anonymous memory`
内存页通常由文件系统中的底层文件支持。例如，用于程序代码的内存页由一个可执行文件支持，内核可以通过从该文件读取数据来满足缺页错误。进程数据（如数据段或栈）在文件系统内没有存储的后端。此类数据由匿名内存支持，而匿名内存又由交换设备上的存储支持。

### `asynchronous I/O`
当用户进程执行 `read()` 或 `write()` 系统调用时，该进程会阻塞，直到数据从磁盘读取到用户缓冲区，或者写入磁盘或系统页缓冲区缓存。使用异步 I/O 时，I/O 请求仅被放入队列，内核随后返回用户进程。进程可以在稍后阶段进行调用以确定 I/O 状态，或接收异步通知。对于执行大量 I/O 的应用程序，异步 I/O 可以让应用程序执行其他任务，而不是等待 I/O。

### `automounter`
自动挂载器。在许多环境中，没有必要总是 `NFS` 挂载文件系统。自动挂载器提供了一种方法，当请求打开远程文件系统中的文件时，自动挂载 `NFS` 文件系统。

### `bddev`
自 UNIX 诞生以来一直存在，用于访问块设备驱动程序。驱动的主设备号（通过 `ls -l` 显示）用于索引此数组。

### `bflush`
许多通过缓冲区缓存到普通文件的写入不会立即写入磁盘，以优化性能。当文件系统完成向缓冲区缓存写入数据后，它会释放缓冲区，以便在需要时供其他进程使用。这在缓冲区缓存中留下了大量的脏（已修改）缓冲区。一个名为 `bflush` 的内核守护进程或线程定期运行，并刷新缓冲区以释放缓冲区缓存空间，通过不长时间缓存已修改的数据来帮助提供更好的数据完整性。

### `block device`
块设备。UNIX 中的设备可以是块设备或字符设备，这取决于 I/O 采取的方法。对于块设备（如硬盘），数据以固定大小的块进行传输，这些块通常至少为 512 字节。

### `block group`
块组。类似于 `UFS` 上的柱面组和 `VxFS` 上的分配单元，`ext2` 文件系统将可用空间划分为块组，每个块组管理一组索引节点和数据块。

### `block map`
块映射。文件系统中的每个索引节点都有若干关联的数据块，这些数据块直接从索引节点或直接块指向。索引节点与数据块之间的映射就是块映射。

### `bmap`
`bmap` 函数。在内核和文件系统中有许多地方需要将文件偏移量转换为磁盘上相应的块。`bmap()` 函数用于实现这一点。在某些 UNIX 内内核上，文件系统导出供内核其他部分使用的 `bmap` 接口，而在另一些内核上，该操作是文件系统内部的。

### `BSD`
Berkeley Software Distribution（`BSD` 软件发行版）是伯利大学计算机系统研究小组 (`CSRG`) 分发的 UNIX 版本名称。

### `BSDI`
Berkeley Software Inc. (`BSDI`) 是一家为了开发和分发受完全支持的商业版 `BSD` UNIX 而建立的公司。当内核从硬盘等块设备读取数据时，它使用缓冲区缓存，通过它可以缓存数据块以供后续访问。传统上，普通文件数据被缓存在缓冲区缓存中。在 `SVR4` 版本 UNIX 和某些其他内核中，缓冲区缓存仅用于缓存文件系统元数据（如目录块和索引节点）。

### `buffered I/O`
缓冲 I/O。文件 I/O 通常在用户缓冲区与磁盘之间或磁盘与系统页缓冲区缓存之间传输。缓冲 I/O 是在缓冲区缓存或页缓存之间进行传输的。

### `cache coherence`
缓存一致性。缓存可以在计算机系统的多个层级使用。当提供多个缓存时，通过使用分布式锁，可以确保应用程序不会看到过时数据。

### `caching advisory`
缓存建议。某些应用程序可能希望控制 I/O 的执行。某些系统导出此功能，允许应用程序选择 I/O 类型。例如，应用程序可以选择顺序、直接或随机 I/O。

### `cddevsw`
`cddevsw`。该结构自 UNIX 诞生以来一直存在，用于访问字符设备驱动程序。驱动的主设备号（通过 `ls -l` 显示）用于索引此数组。

### `Chorus`
`Chorus` Systems 开发的 `Chorus` 内核是 80 年代 90 年代流行的内核，它是许多 UNIX old的基础。

### `clustered filesystem`
集群文件系统。集群文件系统是运行在不同机器上的文件系统集合，它向用户呈现单一底层文件系统的视图。集群内的机器从机器故障等事件中恢复。

### `context switch`
上下文切换。多任务操作系统中的术语。内核为每个进程实现一个独立的上下文。由于进程会被切片或可能等待资源，内核会切换到另一个进程。

### `copy on write`
写时复制。文件系统相关功能（如内存映射文件）在数据的单份副本上运行。如果多个进程同时读取，则没有需要拥有相同数据的多个副本。然而，当文件被映射为写访问时，当一个进程想要修改数据时，将创建数据的副本（通常在页级）。写时复制技术贯穿整个内核。

### `crash`
`crash` 程序是一个工具，用于分析系统崩溃后内核转储（dump）。它提供了一系列丰富的例程来检查各种内核结构。

### `CSRG`
计算机系统小组，伯克利大学内的该小组负责产生 `BSD` 版本的 UNIX。

### `current working directory`
当前工作目录。每个进程都有两个关联目录：根目录和当前工作目录。在执行路径解析时会使用这两个目录。以 `'/'` 开头的路径（如 `/etc/passwd`）从根目录解析，而像 `bin/myls` 这样的路径从当前工作目录解析。

### `cylinder group`
柱面组。`UFS` 文件系统将文件系统分为固定大小的单元，称为柱面组。每个柱面组管理一组节点和数据块。在 `UFS` 创建时，柱面组实际上映射到磁盘的物理柱面上。
