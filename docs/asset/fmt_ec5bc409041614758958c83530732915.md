## 后缀规则 (Suffix Rules)

后缀规则是一种特殊的依赖关系，指定了不同后缀之间的依赖关系。例如，`main.o` 文件具有相同的名称但不同的后缀：`.c` 和 `.o`。对于以 `.c` 和 `.o` 结尾的文件，后缀规则将显示 `main.o` 文件如何依赖于 `main.c` 文件。换句话说，就是如何使用 `main.c` 文件来创建 `main.o` 文件。

后缀规则为依赖行提供了通用性。后缀规则不是适用于某一组特定的文件，而是适用于整类文件。这些类别是由后缀决定的。例如，你可以编写一个适用于所有以 `.o` 结尾和以 `.c` 结尾的文件的后缀规则。由于这种通用性，后缀规则可以大幅减少你在 `Makefile` 中需要的依赖行数量。对于那些执行相同操作且仅在文件名上有所不同的文件依赖行，这一点尤为真实。在之前的 `Makefile` 示例中，`main.o` 和 `io` 的依赖行在各方面都是相同的：它们都执行相同的操作，指定了 `.o` 文件如何依赖于 `.c` 文件，以及 `gcc` 命令如何创建 `.o` 文件。你可以用一个后缀规则替换这两个依赖行，该规则指定了 `.o` 和 `.c` 文件的依赖关系。此外，该后缀规则将适用于你之后可能添加的所有 `.c` 和 `.o` 文件。你不需要为它们添加任何新的依赖行。

后缀规则的目标由两个后缀组成的序列组成，每个后缀以点（`.`）开头。第二个后缀依赖于第一个后缀。对于 `.c` 和 `.o` 文件的后缀规则目标由后缀后跟 `:o` 组成。`.o` 文件依赖于 `.c` 文件。后缀规则的语法如下：

```makefile
.suffix1.suffix2:
Linux command
```

## makefile

要指定 `iolib.a` 库中的 `input.o` 成员，你需要输入 `iolib.a(input.o)`。`make` 随后将使用一种特殊的库后缀规则来确定库成员是否需要更新。如果需要，`make` 将重新编译该库成员的源代码文件，然后使用带有 `r` 选项的 `ar` 命令将生成的目标代码文件写入库文件。例如，`iolib.a` 库包含 `input.o` 和 `print.o` 文件。在接下来的 `make` 示例中，用户在 `bookrec` 依赖行上将这两个文件都被指定为 `iolib.a` 库的成员：`iolib.a(input.o)` `iolib.a(print.o)`。如果你修改了 `input.c`，那么当你执行 `make` 时，`input.c` 将被重新编译，生成的 `input.o` 文件将写入 `iolib.a` 库中。

```
bookrec : main.o iolib.a(input.o) iolib.a(print.o)
ranlib iolib.a
cc main.o iolib.a -o bookrec
```

```
$ touch input.c
$ make
gcc -c -O input.c
ar rv iolib.a input.o
a - input.o
rm -f input.o
ranlib iolib.a
gcc main.o iolib.a -o bookrec
```

注意，标准的库后缀规则在目标代码文件复制到库文件后也会将其删除。此时，目标代码文件已不再需要，因为它已经添加到库中了。

标准的库后缀规则使用特殊后缀 `a` 来表示库文件。尽管如此，库文件实际上并不非要有 `a` 扩展名。在库后缀规则的目标中使用的 `a` 后缀适用于所有库文件，无论它们的扩展名是什么或是否有扩展名。在库后缀目标中，`a.c` 前之前的 `a .c` 表示该库文件依赖于 C 源代码文件（即具有 `a .c` 后缀的文件）。下面是标准库后缀规则的一个示例。

```
.c:
gcc -c $<$
ar rv $@ $%
rm -f $
```

## make Utility 227

库后缀规则包含三个 Linux 命令。第一个命令编译源代码文件，创建一个目标代码文件。在 `gcc` 命令中，`$<` 变量引用需要更新的当前 `.c` 文件。例如，如果 `print.c` 文件发生了变化，那么 `$<` 的值就是 `print.c`。第二个命令是归档命令，将目标代码添加到库文件中。在 `ar` 命令中，`$@` 变量持有目标文件的名称，在这种情况下为库文件。如果目标库是 `iolib.a`，那么 `$@` 的值将是 `iolib.a`。`$%` 变量持有正在更新的库成员的名称。如果 `print.o` 成员文件需要更新，那么 `$%` 将持有该成员名称 `print.o`。在最后一个命令中，`rm` 命令删除了目标代码文件。`$%` 变量是一个仅用于库依赖的特殊变量。你可以将其用在包含库成员的依赖行中，也可以用在库后缀规则。

如果你愿意，可以使用 `.c` 目标创建你自己的库后缀规则。例如，假设你不希望在目标代码文件添加到库中后将其删除。在接下来的 `makefile` 示例中，用户创建了一个不删除目标代码文件的库后缀规则。它还通过在每个 Linux 命令前加上 `@` 运算符来抑制每个 Linux 命令的输出信息。后缀规则不再打印命令输出，而是打印一条消息，说明哪个成员文件正在被更新到哪个库中。

## Libraries and Directories

当你开发较大的程序时，你可能会使用多个库，每个库都有自己的源代码文件。保持库组织整齐的一种方法是将它们放在各自的目录中。然后，你可以为每个目录创建一个单独 `makefile` 来更新该库。你主程序的 `makefile` 和源代码文件将位于它们自己的目录中。虽然你可以显式地运行库目录中的每个 `makefile`，你也可以指示你的主 `makefile` 切换到那些目录并执行 `makefile`。在接下来的示例中，用户创建了一个名为 `ioir` 的目录，其中放置了 `iolib.a` 的文件：`input.c` 和 `print.c`，以及 `iolib.a` 文件。在 `ioir` 目录内，用户创建了一个包含一条依赖行的 `makefile`，用于更新 `iolib.a` 库的成员。`ioir` 的父目录中存在程序源代码文件，如 `main.c` 和可执行文件 `bookrec`。下所示的父目录中的 `makefile` 为用户命名的 `ilib` 的特殊目标指定了两个 Linux 命令。`ilib` 目标将始终是过时的。它的依赖行包含了 `cd` 命令，用于切换到 `ioir` 目录。
