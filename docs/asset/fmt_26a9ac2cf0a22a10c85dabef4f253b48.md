
记住，第一行的反斜杠表示命令在下一行继续。`-dynamic-linker /lib/ld-linux.so.2` 允许我们的程序链接到库。这构建了可执行文件，以便在执行之前，操作系统将加载程序 `/lib/ld-linux.so.2` 来加载外部库并将其与程序链接。这个程序被称为动态链接器。

`-lc` 允许链接到 C 库，在 GNU/Linux 系统上名为 `libc.so`。给定一个库名称，在这种情况下为 `c`（通常库名称比单个字母长），GNU/Linux 链接器会在字符串开头前缀 `lib`

## 第 8 章：与代码库共享函数

库的名称并在末尾添加 `.so` 以形成库的文件名。该库包含许多函数，可以自动化所有类型的任务。我们正在使用的两个函数是 `printf`（它用于打印字符串）和 `exit`（它用于退出程序）。

注意，在程序内部，`printf` 和 `exit` 符号只是直接通过名称引用的。在之前的章节中，链接器会将所有名称解析为物理内存地址，并会丢弃这些名称。当使用动态链接时，名称本身存在于可执行文件中，并在运行时由动态链接器进行解析。当用户运行该程序时，动态链接器会加载我们在链接语句中列出的共享库，然后找到我们的程序中命名的、但在链接时未找到的所有函数和变量名，并将它们与所加载的共享库中相应的条目（entries）进行匹配。这听起来很耗时。在某种程度上上确实如此，但它只发生一次——即在程序启动时。

### 共享库的工作原理

在我们的第一个程序中，所有的代码都包含在源文件中。这类程序被称为静态链接的可执行文件，因为它们包含了程序所需的全部未由内核处理的功能。我们在第 6 章中编写的程序，使用了我们的主程序文件以及包含多个程序例程的文件。在这些情况下，我们在链接时使用链接器将所有代码组合在一起，因此它仍然是静态链接的。然而，在 `helloworld-lib` 程序中，我们开始使用共享库。当你使用共享库时，你的程序就是动态链接的，这意味着运行程序所需的所有代码并不实际上包含在程序本身，而是在外部库中。

当我们在链接 `helloworld` 程序的命令上加上 `-lc` 时，它告诉链接器使用 C 库 `libc.so` 来查找 `helloworld.o` 中尚未定义的任何符号。然而，它并没有实际上向我们的程序中添加任何代码，它只是在程序中记下了要去哪里查找。当 `helloworld` 程序开始运行时运行时，文件 `/lib/ld-linux.so.2` 首先加载。这是动态链接器。它查看我们的 `helloworld` 程序，并发现它需要 C 库才能运行。因此，它在标准位置（列在 `/etc/ld.so.conf` 以及 `LD_LIBRARY_PATH` 环境变量的内容中）搜索文件 `libc.so`，然后查找所有需要的符号（在此情况下为 `printf` 和 `exit`），然后将库加载到程序的虚拟内存中。最后，它将程序中所有的 `printf` 实例替换为库中 `printf` 的实际位置。

运行以下命令：

```
ldd ./helloworld-nolib
```

它应该报告不是动态可执行文件。正如我们所，`helloworld-nolib` 是一个静态链接的可执行文件。然而，尝试这个：

```
ldd ./helloworld-lib
```

它将报告类似的内容：

```
libc.so.6 => /lib/libc.so.6 (0x4001d000)

lib/ld-linux.so.2 => /lib/ld-linux.so.2 (0x40000000)
```

括号中的数字在你的系统上可能不同。这意味着程序 `helloworld` 链接到了 `libc.so.6`（`.6` 是版本号），它位于 `/lib/libc.so.6`，而 `/lib/ld-linux.so.2` 位于 `/lib/ld-linux.so.2`。这些库必须在程序运行之前被加载。如果你感兴趣，可以在你的 Linux 发行版上的各种程序上运行 `ldd` 程序，看看它们依赖哪些库。

### 查找关于库的信息

好了，既然你已经了解库，问题是，你如何发现系统上有哪些库以及它们是做什么的？嗯，让我们先跳过这个问题，问另一个：程序员是如何描述函数的？好吧，让我们先跳过这个问题，问另一个：程序员是如何向彼此描述函数的？让我们来看看，`printf` 的原型看起来如下：

```
int printf(char *string, ...);
```

在 Linux 中，函数是这样描述的。`printf` 的定义意味着它可以使用字符串。`printf` 实际上可以接受不定数量的参数。所以，正如你所见，`printf` 可以让很多事情变得简单，但它也有很多开销。这是一个例子：

```c
#PURPOSE: 这个程序是用来演示如何调用 printf

.section .data

firststring:

ascii "Hello! %s is a %s who loves the number %d\n"

name:

ascii "Jonathan\0"

personstring:

ascii "person\0"

numberloved:

.long 3

.section .text

global _start

_start:

# 注意，参数是按照它们在原型中列出的反向顺序传递的。

pushl numberloved # 这是 %d

pushl $personstring # 这是第二个 %s

pushl $name # 这是第一个 %s

pushl $firststring # 这是格式字符串

call printf

pushl $0

call exit
```

将它输入到命名为 `printf-example.s` 的文件中，然后执行以下命令：

```
as printf-example.s -o printf-example.o
ld printf-example.o -o printf-example -lc \
-dynamic-linker /lib/ld-linux.so.2
```

然后用 `./printf-example` 运行程序，它应该显示：

Hello! Jonathan is a person who loves the number 3

现在，如果你查看代码，你会发现我们实际上最后推入了格式字符串，尽管它是列出的第一个参数。你总是以反向顺序推送函数参数。你可能好奇 `printf` 如何知道有多少个参数。嗯，它搜索你的字符串，并计算发现了多少个 `%d` 和 `%s`，然后从栈中获取相应数量的参数。如果参数匹配 `%`，它将其视为数字；如果它匹配 `%s`，它将其视为指向空终止字符串的指针。`printf` 有比这多得的功能，但这些是最常用的功能。所以，正如你所见，`printf` 可以让很多事情变得简单，但它也有很多开销，因为它必须计算字符串中的字符数，遍历它查找所有它需要替换的控制字符，从栈中取出它们，将其转换为

合适的表示形式（数字必须转换为字符串等），将它们都恰当地地组合在一起。

我们已经看到如何使用 C 语言函数原型来调用库函数。然而，为了有效地使用它们，你还需要了解用于读取函数的几种更多可能用到的数据类型。以下是主要的类型：

## int
- `int` 是一个整数（在 x86 处理器上占用 4 字节）。

## long
- `long` 也是一个整数（在 x86 处理器上占用 4 字节）。

### long long
- `long long` 是比 `long` 更大的整数（在 x86 处理器上占用 8 字节）。

## short
- `short` 是比 `int` 更短的整数（在 x86 处理器上占用 2 字节）。

### char
- `char` 是单字节整数。这主要用于存储字符数据，因为 ASCII 字符串通常以每个字符一个字节的形式表示。

## float
- `float` 是浮点数（在 x86 处理器上占用 4 字节）。浮点数将在第 10 章的“浮点数”章节中进行更深入的解释。

## double
- `double` 是比 `float` 更大的浮点数（在 x86 处理器上占用 8 字节）。

## unsigned
- `unsigned` 是一个用于上述任何类型的修饰符，防止它们被用作符号数值。有符号数和无符号数之间的区别将在第 10 章中讨论。

### *
- 星号 `*` 用于表示数据不是实际值，而是指向持有给定值的位置的指针（在 x86 处理器上占用 4 字节）。假设在内存位置 `my_location` 中存储了数字 20。如果函数原型说传递一个 `int`，你将使用直接寻址模式模式并执行 `pushl my_location`。然而，如果原型说传递一个 `int *`，你将执行 `pushl $my_location` ——这是一个对值所在地址的立即数模式推入。除了指示单个值的地址外，指针还可以用于传递一系列连续的位置，从给定值所指向的位置开始。这被称为数组。

- `struct` 是一组放在一个名称下的数据项。例如，你可以声明：

struct teststruct {

  int a;
