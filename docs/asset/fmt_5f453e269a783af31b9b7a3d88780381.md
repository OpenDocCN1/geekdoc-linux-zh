## 打印的历史

要完全理解类 Unix 系统使用的打印功能，我们必须首先学习历史。类 Unix 系统上的打印追溯到操作系统的初期。那时，打印机的使用方式与现在大相同。

### 早期打印

与计算机一样，PC 时代的打印机倾向于是大型、昂贵且集中的。典型的计算机用户在一段距离外的终端上工作。打印机位于计算机附近，并在计算机操作员的监视下。

当打印机昂贵且集中时，在 Unix 早期多个用户共享一台打印机是常见做法。为了识别属于特定用户的打印文件，通常会在每个打印作业开始时打印一张显示用户名的横幅页（banner page）。然后，计算机支持人员会装满包含当日打印文件的推车并交付给个人用户。

### 字符打印机

1980 年代的打印机技术在两个方面与今天不同。首先，那个时期的打印机几乎都是击式打印机。击式打印机使用机械机构撞墨水和纸张，在页面上形成字符印象。当时的两种流行技术是*针轮打印*（daisy-wheel printing）和*点矩阵打印*（dot-matrix printing）。

早期打印机的第二个且重要的特征是，打印机使用设备固有的固定字符集。例如，针轮打印机只能打印模刻在针轮瓣上的字符。这使得打印机变得像高速打字机。对于大多数打字机，它们使用等宽字体（固定宽度）字体。这意味着每个字符的宽度都是相同的。打印是在页面上的位置进行的，页面打印区域包含固定数量的字符。大多数打印机水平每英寸打印10个字符（CPI），垂直每英寸打印6 行（LPI）。使用这种方案，美国信尺寸纸张宽 85 个字符，高 6 行。考虑到两侧的小边距，80 个字符被认为是打印行的最大宽度。这解释了为什么显示器（我们的终端）通常是 80 个字符宽。使用等宽字体和 80 字符终端可以提供所见即所得（WYSIWYG）的打印输出视图。

数据发送到类打字机打印机的是包含要打印字符的简单字节流。为了打印字母 *a*，发送 ASCII 字符代码 97。此外，低编号 ASCII 控制码提供了移动打印机架和纸张的方法，使用了回车、换行等代码。使用控制码可以实现一些有限的字体效果，例如**粗体**是通过让打印机打印一个字符、退格，然后再次打印该字符，从而在页面上获得更深色的打印效果。如果我们使用 `nroff` 渲染页面并使用 `cat -A` 检查输出，就可以观察到这一点。

```
me@linux~$ zcat /usr/share/man/man1/ls.1.gz | nroff -man | cat -A | head

LS(1)

User Commands LS(1)

$

$

N^HNA*HAM*HME*HE$

ls directory contents$

$

S^HVS*HYN*HYN0*OP*HPS*HSI1*H5*HS

nH1*Hs [_O_HP_HT_HI_O0_HN]...[_HF_HI_HL_HE]...$
```

`^H` (CTRL-H) 字符是创建粗体效果的退格键。同样，我们也可以看到退格/下划线序列来产生下划线。

### 图形打印机

GUI 的发展导致打印机技术的重大变化。随着计算机转向基于图像的显示，打印从基于字符的技术转向了图形技术。低成本激光打印机的出现促进了这一进程，它不再打印固定字符，而是在页面可打印区域的任何地方打印微小的点。这使得打印比例字体（如排字员使用的字体）、甚至是照片和高质量图表成为可能。

然而，从基于字符的方案转向图形方案面临着严峻的技术挑战。原因如下：使用基于字符的打印机填充一页纸所需的字节数可以这样计算（假设每页 60 行，每行 80 个字符）：

60 × 80 = 4,800

相比之下，一台 300 DPI（每英寸点数）激光打印机（假设每页区域为 80 英寸）需要这么多字节：

(8 × 300) × (10 × 300) / 8 = 900,000 字节

许多缓慢的 PC 网络根本无法处理在激光打印机上打印整页纸所需的数据延迟，因此显然需要一种巧妙的发明。

这种发明被证明是页面描述语言（PDL）。页面描述语言是一种描述页面内容的编程语言。基本上，它说：“去这个位置，用 10 磅 Helvetica 字体在那个位置画一个字符…… 直到整个页面被描述。”第一个 PDL 是 Adobe Systems 的 PostScript，它今天仍被广泛使用。PostScript 语言是一门专门为排版和其他图形及成像定制的完整编程语言。它包含了对 35 种标准高质量字体的内置支持，并具有在运行时接受额外字体定义的能力。起，对 PostScript 的支持内置在打印机内部。这解决了数据传输传输问题。与简单的基于字符的打印机流相比，典型的 PostScript 程序非常冗长，但其体积远小于表示整个页面所需的字节数。打印机接受 PostScript 程序作为输入。它包含了自己的处理器和内存（这通常使打印机变成比其连接的计算机更强大的计算机），并执行一种名为 PostScript 解释器的特殊程序，该解释器读取传入的 PostScript 程序并将结果渲染到其内部内存中，形成传输到纸上的位模式（点）。这种将某些内容渲染为大图案的过程的通用名称是渲染（而位图是一个光栅图像处理器 (RIP)）。

随着时间的推移，计算机和网络都变得快得多。这使得 RIP 可以从打印机移动到主机计算机，反过来允许高质量打印机变得便宜得多。

今天许多打印机仍然接受基于字符的字符串，但许多低成本打印机不再接受。它们依赖主机的 RIP 提供位流以打印点。也有一些 PostScript 打印机。

## 使用 Linux 打印

现代 Linux 系统采用两个软件套来执行和管理打印。第一个是通用 Unix 打印系统 (CUPS)，提供打印驱动程序和打印作业管理；第二个是 Ghostscript，作为一个 PostScript 解释器充当 RIP。

CUPS 通过创建和维护打印队列来管理打印机。正如我们在之前的历史课程讨论过的，Unix 打印最初的设计是为了让多个用户管理一台中央打印机。由于打印机本质上很慢，与提供数据的计算机相比，打印系统需要一种方法来调度多个打印作业并保持组织有序。CUPS 还有识别（在范围内）不同类型数据的能力，并可以将文件转换为可打印格式。

### 向打印机发送作业

CUPS 打印套件支持历史上在类 Unix 系统上使用的两种打印方法。一种方法称为 LPD（用于 BSD 软件发行版），使用 `lpr` 程序，而另一种方法 SysV（来自 System V）使用 `lp` 程序。这两个程序的功能基本相同。选择哪一个取决于个人喜好。

#### pr 打印文件（Berkeley 风格）

`lpr` 程序可将文件发送到打印机。它也可以用于管道。例如，为了打印我们之前的多列列表，可以这样做：

```
@meluxbox]$ ls /usr/bin | pr -3
```

报告将发送到默认打印机。要将文件发送到不同的打印机，可以使用 -P 选项：

```
lpr -P printer_name
```

在这里，`printer_name` 是打印机名称。要查看系统知的打印机列表，请使用：

```
@meluxbox]$ lpstat -a
```
