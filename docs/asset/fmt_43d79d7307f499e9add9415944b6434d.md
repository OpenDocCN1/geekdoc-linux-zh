## 某些特殊权限

虽然我们通常将八进制权限表示为三位数字，但使用四位执行它在技术上是更正确的。为什么？因为除了写入和执行权限之外，还有其他一些不常使用的权限设置。

其中第一个是 setuid 位（八进制 `4000`）。当应用于可执行文件时，它会将有效用户 ID 从实际用户用户（实际运行程序的用户）设置为程序的所有者。大多数情况下，这被赋予少数超级用户拥有的程序。当普通用户运行 setuid root 的程序时，该程序以超级用户的权限运行。这允许程序访问文件和目录。

普通用户通常被禁止访问这些内容。显然，由于这涉及到安全考量，setuid 程序的数量必须保持在最低水平。

第二个使用的设置是 setgid 位（八进制 `2000`），它与 setuid 类似，会将有效组 ID 从真实用户的真实组 ID 更改为文件所有者的组 ID。如果在一个目录上设置了 setgid，则在该目录中新创建的文件将获得目录的组所有权，而不是创建者的组所有权。这在共享目录中非常有用，当共同组的成员需要访问该目录下的所有文件时，无论文件所有者的主组是什么。

第三个称为 sticky bit（粘滞位，八进制 `1000`）。这是古老 Unix 的遗留物，当时可以将一个可执行文件标记为“不可交换的”。Linux 忽略粘滞位，但如果将其应用于目录，它可以防止用户删除或重命名文件，除非该用户是目录的所有者、文件的所有者或超级用户。这通常用于控制对共享目录（如 `/tmp`）的访问。

以下是一些使用 `chmod` 符号表示设置这些特殊权限的示例。这里有一个为程序分配 setuid 的示例：

```
chmod u+s program
```

接下来，这是一个为目录分配 setgid 的示例：

```
chmod g+s dir
```

最后，这里有一个为目录分配粘滞位的示例：

```
chmod t+t
```

在查看 `ls` 的输出时，你可以判断出特殊权限。这里是一些示例。首先，这是一个分配了 setuid 的程序示例：

```
-rws-xr-x
```

这里是一个具有 setgid 属性的目录示例：

```
drwxrxr-x
```

这里是一个设置了粘滞位的目录示例：

```
drwxrwxrwt
```

## 更改身份

有时，我们可能发现必要采用另一个用户的身份。当我们想要获得超级权限来执行某些管理任务时，但也可能“变成”另一个普通用户，用于测试账户等操作。有三种方法可以采用替代身份。

- 注销并以替代用户重新登录。
- 使用 `su` 命令。
- 使用 `sudo` 命令。

我们将跳过第一种技术，因为我们知道如何操作，而且它不像其他方法那样方便。在我们自己的 shell 会话中，`su` 命令允许我们假设另一个用户的身份，并以该用户的 ID 启动新的 shell 会话，或者作为用户执行单个命令。`sudo` 命令允许管理员配置名为 `/etc/sudoers` 的配置文件，并定义特定用户在假设身份下允许执行的特定命令。使用哪种命令在很大程度上取决于你使用的 Linux 发行版。你的发行版可能同时包含这两个命令，但其配置会倾向于其中一种。我们将从 `su` 开始。然而，请注意，使用 `su` 在现代发行版中已不再流行。

## su—以替换用户和组 ID 运行 Shell

`su` 命令用于以另一个身份启动 shell。命令语法如下：

```
su [-l] [user]
```

如果包含了 `-l` 选项，生成的 shell 会话将是指定用户的登录 shell。这意味着用户的环境被加载，并且工作目录被更改为用户的家目录。这通常是我们我们想要的。如果未指定用户，则假设为超级用户。注意（严格来说）`-l` 可以缩写为 `-`，这通常是它的使用方式。假设 root 账户设置了密码（这在现代发行版中并不常见），我们可以以此方式为超级用户启动 shell：

```
[me@linuxbox ~$] su -

Password:

[root@linuxbox]#
```

输入命令后，系统提示输入超级用户的密码。如果输入成功，会出现一个新的提示符，指示此 shell 具有超级权限（结尾是 `#` 而不是 `$`），并且当前工作目录现在超级用户的家目录（通常是 `/root`）。进入新 shell 后，我们可以以超级用户的身份执行命令。完成后，输入 `exit` 返回上一个 shell：

```
[root@]# exit

[me@linuxbox ~$]
```

还可以通过这种方式使用 `su` 执行单个命令，而不是启动新的交互式命令：

```
su -c 'command'
```

使用这种形式时，单个命令被传递给 shell 执行。将命令包含在引号中是重要的，因为我们不希望扩展在我们的 shell 中发生，而是希望它在新的 shell 中发生：

```
[me@linuxbox ~]$ su -c 'ls /root/*'

Password:

-rw------- 1 root 754 2025-08-11 03:19 /root/anaconda-ks.cfg
```

```
/root/Mail:

total 0

[me@linuxbox ~]
```

## 现代 Linux 发行版与 SUDO

普通用户经常遇到的问题之一是执行某些需要超级权限的任务。在 Windows 世界中，这通常通过赋予用户管理员权限来实现。这允许用户执行任务，但也允许恶意软件（自由软件，如病毒）在计算机上肆意妄为。

在 Unix 世界中，由于 Unix 的多用户传统，普通用户和管理员之间一直存在较大的划分。Unix 采用的方法是仅在需要时授予超级权限。为了实现这一点，通常使用 `su` 和 `sudo` 命令。多年前，某些 Linux 发行版依赖 `su` 来此目的；`su` 不需要 `sudo` 所需的配置，而且拥有 root 账户在 Unix 中是传统。然而，这引入了一个问题。用户倾向于在不需要的情况下以 root 身份操作。事实上，某些用户以 root 用户身份运行系统，因为这消除了所有烦人的“拒绝访问”消息。这就是你将 Linux 系统的安全性降低到 Windows 系统水平的方法。这不是一个好主意。

当 Ubuntu 引入时，它的创建者采取了不同的任务。默认情况下，Ubuntu 禁用 root 账户的登录（通过不对该账户设置密码），而是使用 `sudo` 来授予超级权限。初始账户通过 `sudo` 获得超级权限的完全访问，并可以授予后续账户类似的权限。这种授予权限的方法现在是大多数发行版接受的标准。

## chown–更改文件所有者和组

`chown` 命令用于更改文件或目录的所有者和组组。使用此命令需要超级权限。`chown` 的语法如下：

```
chown [owner][[:group]] file...
```

`chown` 根据命令的第一个参数更改文件所有者或组所有者。表 9-7 提供了一些示例。

## 表 9-7: chown 参数示例

| 参数 | 结果 |
| :--- | :--- |
| bob | 将文件所有者从当前所有者更改为用户 bob。 |
| bob:users | 将文件所有者从当前所有者更改为用户 bob，并将文件组所有者更改为组 users。 |
| :admin: | 将组所有者更改为组 admin。文件所有者不变。 |
| bob: | 将文件所有者从当前所有者更改为用户 bob，并将组所有者更改为用户 bob 的登录组。 |

假设我们有两个用户：janet，她拥有超级权限，而 tony，

不这样做。用户 janet 想要从家目录复制文件到用户 tony 的家目录。由于 janet 希望让 tony 能够编辑该文件，janet 将复制文件的所有权从 janet 改为 tony。

```
[janet@linuxbox~$] sudo cp myfile.txt -tony

Password:
```

```
[janet@linuxbox~$] sudo ls -l -tony/myfile.txt

-rw-r--r-- 1 root root 2025-03-24 14:30 /home/tony/myfile.txt
```

```
[janet@linuxbox~$] sudo chmod ls -l -tony/myfile.txt

-rw-r--r-- 1 tony tony 2025-03-24 14:30 /home/tony/myfile.txt
```

在这里我们使用用户 janet 将文件从家目录复制到用户 tony 的家目录。接下来，janet 将文件的所有权从 root（使用 sudo 的结果）改为 tony。通过第一个参数中的末尾命令，janet 还将文件的组所有权更改为 tony 组（恰好是组 tony）。

请注意，在第一次使用 `sudo` 后，janet 并没有被提示输入密码。这是因为在许多配置中，`sudo` 会在几分钟内“信任”该用户，直到计时器超时。

## 练习我们的权限

现在我们已经学习了这些操作是如何运作的，是时候展示一下了。我们将演示一个常见问题的解决方案——建立一个共享目录。让我们重新回到我们的朋友 janet 和 tony 身上。他们都有自己的音乐收藏，并想要建立一个共享目录，在其中共享 Ogg Vorbis 或 MP3 格式的音乐文件。在此之前，用户 janet 可以通过 `sudo` 访问超级用户权限。

需要创建一个 janet 和 tony 均为成员的组。这分两步完成。首先，使用 `groupadd` 命令创建组，然后使用 `usermod` 命令将用户添加到组中：

```
[janet@linuxbox~$] sudo groupadd music

[janet@linuxbox~$] sudo usermod -G music janet

[janet@linuxbox~$] sudo usermod -G music tony
```

`usermod` 使用的选项是 `--append` 和 `--group` 的缩写，它们将指定的用户添加到 `/etc/group` 文件中对应的组中。
接下来，janet 为音乐文件创建目录：

```
[janet@linuxbox~$] sudo mkdir /usr/local/share/Music

Password:
```

由于 Janet 正在操作家目录之外的文件，因此需要超级用户权限。目录创建后，它将具有以下所有权和权限：

```
[janet@linuxbox ~$] ls -ld /usr/local/share/Music

drwxr-xr-x 2 root 4096 2025-03-21 /usr/local/share/Music
```

如我们所示，该目录由 root 所有，且权限模式为 755。为了让此目录可写，Janet 需要更改组所有权并将组权限设置为可写：

```
[janet@linuxbox ~$] sudo chown music /usr/local/share/Music

[janet@linuxbox ~$] sudo chmod 2775 /usr/local/share/Music

[janet@linuxbox ~$] ls -ld /usr/local/share/Music

drwxrws-x 2 root 4096 2025-03-21 18:05 /usr/local/share/Music
```

使用所示命令，Janet 将目录的组所有者设为 music，然后使用 `chmod` 将 `setgid` 设置为 2775。这设置 `setgid` 使得目录中的所有文件都能继承目录的组所有权。但我们也可以通过符号方法 `chmod 2775,g+` 实现同样的操作。

但我们仍然面临一个问题。系统的默认 `umask` 为 0022，这阻止了组成员向组内其他成员写入文件。如果共享目录只包含文件，则不是问题，但由于此目录将存储音乐，而音乐通常按艺术家和专辑的层级结构组织，组成员需要能够在其他成员创建的目录内部创建文件和目录。我们需要将 janet 和 tony 使用的 `umask` 改为 0002。
Janet 将她的 `umask` 设为 0002 并创建了新文件和目录：

```
[janet@linuxbox ~$] umask 0002

[janet@linuxbox ~$] cd /usr/local/share/Music/test_file

[janet@linuxbox ~$] mkdir /usr/local/share/Music/test_dir

[janet@linuxbox ~$] ls -l /usr/local/share/Music

drwxr-xr-x 2 janet music 4096 2025-03-24 20:24 test_dir

-rw-rw-r-- 1 janet music 0 2025-03-24 20:22 test_file
```

Janet 正在操作家目录之外的文件，需要超级用户权限。目录创建后，它具有以下所有权和权限：

```
[janet@linuxbox ~$] ls -ld /usr/local/share/Music

drwxr-xr-x 2 root 4096 2025-03-21 /usr/local/share/Music
```

如我们所示，目录由 root 所有，权限模式为 755。为了让此目录可写，Janet 需要更改组所有权并将组权限设置为写：

```
[janet@linuxbox ~$] sudo chown music /usr/local/share/Music

[janet@linuxbox ~$] sudo chmod 2775 /usr/local/share/Music

[janet@linuxbox ~$] ls -ld /usr/local/share/Music

drwxrws-x 2 root 4096 2025-03-21 18:05 /usr/local/share/Music
```
