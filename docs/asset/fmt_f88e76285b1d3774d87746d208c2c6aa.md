
设置 `chroot`（切换根目录）最简单的方法是直接安装 `dhcpd`（最好是最新版本）并移动必要的文件。一个好主意创建一个目录（例如）`/chroot/dhcpd/`，最好位于与 `/`、`/usr`、`/etc`（符号链接）独立的文件系统，然后在它下面为 `dhcpd` 创建文件结构。以下是一个示例，只需将 `/chroot/dhcpd/` 替换为你的选择。你必须执行这些步骤才能让 `root` 用户工作。

```bash
## 安装以获得适当的文件
rpm -i dhcpd-2.0.1.i386.rpm

### 创建目录结构
cd /chroot/dhcpd/
mkdir ./etc
mkdir ./usr/sbin
mkdir ./var
mkdir ./lib

### 填充文件
cp /usr/sbin/dhcpd /usr/sbin/dhcpd
cp /etc/dhcpd.conf /etc/dhcpd.conf
cp /etc/rc.d/init /etc/rc.d/init
cp /etc/rc.d/functions /etc/functions

### 现在获取最新库，根据需要更改
cp /lib/ld-linux.so.2 /lib/
cp /lib/libc.so.6 /lib/

### 如果你使用 chroot，只需修改随附的那个
### 然后创建符号链接
ln -s /chroot/dhcpd/
```

- `secure` - NFS 系统必须源自特权端口，即 `root` 必须是挂载该目录的人员。如果你导出的目标服务器安全性良好，这会非常用。
- `ro` - 一个很好的选项，只读（Read Only），多说无言。
- `noaccess` - 用于切断访问，例如导出 `/home/` 但不对 `/home/root` 允许任何访问。
- `root_squash` - 将 `root` 的 UID 压缩为匿名用户的 UID/GID（通常为 'nobody'），如果你将目录导出给那些并不 100% 信任的管理员，这非常有用（`root` 始终可以读取任何文件…… 提示）。
- `no_root_squash` - 如果你想以 `root` 身份在导出的目录中忙碌修复问题（例如你的 `www` 网站的权限），则此很有用。
- `squash_uids` and `squash_g` - 将特定的 UID 或 GID 映射为匿名用户，在 RedHat 中一个很好的例子是 5-10000（RedHat 默认从 500 开始分配用户和组），允许任何具有较低 UID 的用户（即特殊账户）访问特殊内容。
- `all_squash` - 一个很好的选项，基本上撤销了所有权限，每个人都是访客。
- `anoid` and `anonid` - 专门设置匿名用户的 UID / GID（你可能想要一些特殊的，如 'anonnfs'）。

`man` 导出页面（exports page）非常不错。

除此之外，你无法做更多操作来防止 NFS 被彻底卸载并替换为其他产品（如 NFS、Coda 等）。NFS 很好，每种口味的 UNIX 都支持它，而且工作起来非常方便。它还是“老实实派”，已经存在很久了。只需查看《Practical Unix and Internet Security》，他们也明确表示如果安全是一个真实问题，就不要使用 NFS。

NFS 应该从外部世界限制，它运行在端口 `111` (`udp/tcp`)，并且运行在端口 `2049`，同时使用 RPC，而 RPC 运行在端口 `635` (`udp`) 上利用 `mount`。将 `2049` 替换为 `111`，将 `635` `udp` 和 `tcp` 替换以保护这些服务（再次，最好的主意是使用 1 到 1024 端口的全局规则，或者更好的默认拒绝策略）。

```
ipfwadm -I -a accept -P udp -S 10.0.0.0/8 -D 0.0.0.0/0 2049
ipfwadm -I -a accept -P udp -S some.trusted.host -D 0.0.0.0/0 2049
ipfwadm -I -a deny -P udp -S 0.0.0.0/0 -D 0.0.0.0/0 2049
```

或者

```
ipchains -A input -p udp -j ACCEPT -s 10.0.0.0/0 -d 0.0.0.0/0 2049
ipchains -A input -p udp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 2049
ipchains -A input -p udp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 2049
```

`tftp`（简单文件传输协议）用于需要从网络服务器获取信息的设备，通常在启动时使用。它是 `ftp` 的一种极其简单的形式，剥离了大部分安全功能和高级命令，它基本上允许设备以一种非常简单的方式从服务器检索（上传）文件。`tftp` 几乎专门用于工作站、路由器配置以及任何启动时需要信息的设备，因为它呈现了一个巨大的安全漏洞，如果有人连接到你的 `tftp` 服务器并抓取了你 Cisco 路由器的文件，就了。此外，`tftp` 默认授予对文件系统（包括 `/etc/passwd` 文件）的访问。现代版本的 `tftp` 限制了访问，并使用 `TCP_WRAPPERS` 来限制对主机的访问。默认情况下，`tftp`（至少对于 RedHat）只提供对 `/tboot` 目录的访问。将 `tftp` 目录尽可能与系统分开是一个好主意。这通过在 `ftp` 命令启动 `inetd.conf` 后指定 `tftp` 有权访问的目录来实现。此示例正常启动 `tftp` 并授予对 `/tboot` 目录和 `/kickstart` 目录的访问。

```
tftp dgram root /usr/bin/tcp in.tftp /tboot
/kickstart
```

还要记住 `tftp` 使用 '`ps aux`' 不一定会显示谁登录了或他们正在做什么（与 `ftp` 不同，除非他们正在下载文件，否则不会显示，因为你不太可能抓到他们）。监控 `tftp` 的最佳地方是 `syslog`，但即使是 `tftp` 也不记录地址或任何有用信息。以下是活动 `tftp` 会话的 `ps` 输出和 `syslog` 输出。

```
nobody 744 0.0 6 780 R 14:31 0:tftp
Apr 24 14:31 hostname tftpd[744]: trying to get file
Apr 24 14:31 hostname tftpd[744]: serving file from /tboot
```

TFTP 可以使用 `TCP_WRAPPERS` 和防火墙轻松地限制，`tftp` 运行在端口 `69`，只需限制到你的工作站所需的访问即可。此外，在网络边界阻止所有流量也是一个好主意，因为没有必要机器跨互联网使用 `tftp` 进行远程启动。此外，`tftp` 以 `nobody` 身份运行，但由于没有进行身份验证且所有访问 `tftp` 服务器的设备都是这样做的，因此文件级安全相当没用。`tftp` 仅运行在端口 `69`。

```
ipfwadm -I a accept -P udp -S 10.0.0.0/8 -D 0.0.0/0 69
ipfwadm -I a accept -P udp -S some.trusted.host -D 0.0.0/0 69
ipfwadm -I a deny -P udp -S 0.0.0/0 -D 0.0.0/0 69
```

或者

```
ipchains -A input -p udp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0/0 69
ipchains -A input -p udp -j ACCEPT -s some.trusted.host -d 0.0.0/0 69
```

```
iptchains -A input -p udp -j DENY -s 0.0.0/0 -d 0.0.0/0 69
```

### utftpd

`utftpd` 是 `tftpd` 的安全替代品，它提供了更精细的访问控制和对某些功能的支持（如修订）。你还可以根据客户端 IP 设置访问，这意味着路由器配置和工作站配置可以分开。`utftpd` 是 GPL 许可的，地址：`http://www.gnu.org/utftpd`。

`bootp` 基本上是 DHCP 的前身，选项和配置性较少，但执行相同的任务，帮助设备启动网络并获取所需信息。除非你有某些在 DHCP 服务器上崩溃的老旧设备，否则我不建议运行 `bootp`。如果真的有人让我通过邮件写更多，我会写的。否则，我认为 `bootp` 仅具有历史意义。

```
ipfwadm -a accept -P udp 10.0.0/8 -D 0.0.0/0 69
ipfwadm -I a accept -P udp -S some.trusted.host -D 0.0.0/0 69
ipfwadm -I a deny -udp -S 0.0.0/0 -D 0.0.0/0 69
```
