### 一系列技术

描述与 UNIX 相关的 GUI 是一项巨大的任务，因为它们有许多种，每种都有其自己的商业和技术历史、可移植性、编程模型、辅助 GUI 构建器以及其他维度。本章提到了其中的几个亮点，并邀请感兴趣的读者查阅本章末尾的。

OSF/*Motif * 是一套用户界面指南，由开放软件基金会 (http://www.osf.org) 于 1989 年首次发布。它是一个构建在 *X Toolkit* (Xt) 机制之上的“外观和感觉”。虽然 Xt 可以从 X 联盟 (http://www.x.org) 免费获取，但 OSF 对 Motif 收取许可费。Motif 基本上适用于所有 UNIX，也适用于 OpenVMS 和 Windows NT。它的原生绑定是 C 语言。

Bristol (http://bristol.com) 为大多数 UNIX 版本提供了用于 *Microsoft Foundation Classes* 的 *API*（应用程序编程接口）。在 UNIX 下开始开发 MFC 的技术理由很少，但可以这样做。

*Tk* (http://www.sun.com/Tk/) 提供了一种有趣的替代方案，它适用于 OSF、VMS、Windows 95、Windows NT、Amiga DOS、OS/2 以及 Java。它在 Motif 方面更健壮且易于使用。Java (http://java.sun.com) 布者将抽象窗口工具视为未来的 GUI 技术。尽管截至 1997 年，它的移植性较差、稳定性差、使用起来更繁琐。它的*重入性*、*线程安全*和*面向对象*编程模型将很好地服务它。

这四种方法展示了免费的 GUI 的多样性，包括 XVT、Neuron Data、SL-GMS、MetaCard 等。理解这些许多产品是共存的重要的，它们功能重叠，也有独特的差异。有些产品专门支持特定的网络协议、主机托管或可移植性需求或其他许多可能性。这种复杂性加强了本章的方法：彻底且易于理解地教授 Motif 的几个步骤，以便读者在坚实的基础上进行探索和成就。

## 编写 Motif 应用程序

本章介绍了*事件驱动编程*。学习 Motif 编程的主要里程碑是理解事件驱动模型。传统的 C 程序从 `main()` 开始控制流，按顺序执行到 `exit()`。当它需要信息时，它从文件或键盘等源寻求信息，并在请求时立即获取。相比之下，事件驱动编程是在*异步*的基础上执行的。事件发生的顺序和时间并不由程序员决定。

X 窗口编程依赖于事件输入队列。应用程序的执行是对事件的响应序列。在 X 世界中，通常将其视为客户端/服务器编程的一个实例：服务器等待来自客户端的事件，然后将事件的结果报告给客户端。

X 通过三层实现这种客户端/服务器功能。在中间层，X 工具包（简称 Xt）是一个面向对象的 C API，管理事件处理和*小部件*交互的抽象概念。小部件是用户界面的构建块。实际的 GUI 构建始终在 Xt 之上完成；Motif、Athena、Tk 以及其他开发 API 有时被称为小部件集，因为它们定义了构建应用程序有用的按钮、标签、绘图区域等。在 Xt 之下还有一层：Xlib 是 X11 通信协议的 API。本章将很少需要引用 Xlib。

该循环通过调用函数 `XtAppMainLoop()` 实现。主体的根本作用是等待事件，并对它们做出响应，或者像大多数情况那样，将它们分发给具备响应能力的部件（widgets）。

部件是编程对象，拥有关于如何响应事件的知识。部件通常具有图形化行为——它们在屏幕上以图片的形式显示——并通过*注册*一组*回调函数*来实现它们的事件响应。例如，当显示区域内的指针按钮被点击时，某些部件会重绘自身。为了实现这一点，它们会在按钮点击时注册一个重绘回调函数。Xt 还支持动作（actions），这允许应用程序向 Xt 注册函数。当接收到一个或多个特定事件类型的序列时，就会调用动作。例如，Ctrl+X 可能会绑定到 `exit()` 函数。Xt 的职责之一是维护一个将动作映射到事件的翻译表。事件处理器就是这些绑定到特定事件的函数。

## 命名规范

大多数 Xlib 函数以字母 "X" 开头，但有足够多的例外令人感到困惑。X 就像英语拼写一样，是一项具有历史的技术，且不一致性相当严重。几个宏和函数，如 `BlackColor` 和 `WhiteColor`，并不以 X 开头。通常，如果 Xlibrary 中的一个名称以 X 开头，它就是一个函数。如果名称以任何其他大字母开头，它就是一个宏。

在 Xt 本身中，命名规范显示出更刻意的工程设计，例外极少。Xt 不区分宏和函数。

**提示：** 不要依赖工具包函数的名称来判断它是否为宏。请阅读手册。

在 Motif 中，几乎所有的声明都以 `Xm` 开头。`XmC` 指代类。`XmR` 指资源。`XmN` 指名称。`XtN` 指 Motif 使用的 Xt 资源。

在 Motif 中，以单词 `WidgetClass` 结尾的声明定义了部件类型的基类。关于大多数 X 库函数调用中的参数，需要记住的约定有：`width` 始终在 `height` 的左侧（或之前）。`x` 在 `y` 的左侧。`Source` 在 `destination` 的左侧。`Display` 通常是第一个参数。

通过练习，你将能够识别要传递的参数类型以及函数属于哪个工具包，并且你能够“猜”出未知函数可能期望的参数。
