
当你首次在计算机中设置用户 ID 时，系统或安全管理员将使用 `root` 用户 ID 为你分配一个临时密码。第一次尝试登录时，系统会要求你更改密码；后续所有登录都将使用新密码。

然而，如果你认为别人已经知道了你的密码，你可以更改密码。作为安全措施，频繁修改密码是一个好习惯。你可以使用 `passwd` 命令来更改密码。

当你执行 `passwd` 命令时，系统首先提示你输入当前密码，然后是输入新密码。

```
/usr/bin/which
```

## whence

`whence` 命令是 Korn shell 中 `which` 命令的更详尽的形式。它带有一个 `-v` 参数，用于以详细的形式产生输出。对于没有设置别名的原生命令，它生成的输出与 `which` 类似。

示例：要获取关于 `which` 命令的信息，你可以执行以下命令：

```
whence which
/usr/bin/which
```

如果你使用 `-v` 标志，你将获得详细输出：

```
which is /usr/bin/which
```

然而，如果你设置了别名，输出会有所不同。例如，如果你将 `rm` 别名为 `rm -i`（设置了确认标志的删除命令），则命令：

```
which rm
```

将生成输出：

```
rm -i
```

而带有 `-v` 标志时，它生成的输出：

```
rm is an alias for rm -i
```

## where

`where` 命令用于获取一个或多个文件或目录的完整路径。`where` 命令没有关联的标志。当显示路径时，它以主机名名前缀；如果没有参数，则显示当前目录的完整路径。

示例：如果你想找到当前目录的路径，假设你处于 `/u/testeser` 目录，执行以下命令：

```
where
```

将导致：

```
box:/u/testeser
```

UNIX 提供了在线帮助来帮助你学习各种命令及其选项和标志。你可能熟悉最常用的命令及其各种选项，但要查找不那么常用的命令或命令用法，你可以使用 UNIX 提供的在线帮助。

## man

`man` 命令用于显示 UNIX 手册页，其中包含命令、文件、子程序等。你必须为 `man` 命令提供你正在查找的对象名称。如果你不知道全名，可以使用 UNIX 通配符来指定对象名称。你甚至可以通过使用 `man` 命令来找到更多关于 `man` 命令本身的信息。

以下是可用于 `man` 命令的一些标志和参数：

- `-k keyword`：在关键字数据库中列出指定关键字的手册章节摘要列表。
- `-f command`：与命令相关的详细信息。在使用此选项之前，root 用户必须设置文件 `/usr/man/whatis`。
- `-M path`：指定 `man` 命令的搜索路径。

你可以将章节名称作为命令的一部分。这将允许你在指定的章节中搜索标题。以下是可以指定的章节列表：

- 1--命令
- 2--系统调用
- 3--子程序
- 4--文件格式
- 5--杂项
- 7--特殊文件
- 8--维护

示例：如果你想找到关于 `find` 命令的信息，请执行以下命令：

```
man find
```

要查找与文件系统相关的关键字，请执行以下命令：

```
man -k filesystem
```

## 管理

某些功能只有你安装位置的 UNIX 系统管理员才能执行。这些包括启动系统、关闭系统、设置新用户账户、监控和维护各种文件系统、在系统上安装新软件等。在本节中，我们将讨论履行这些职责所需的命令。

### install

`install` 命令用于安装当前软件程序的新版本或全新的软件程序。`install` 命令的基本功能是将二进制执行文件和任何关联文件复制到适当的目录。对于现有软件的新版本，文件将覆盖现有文件并保留其权限。`install` 命令还会打印其所执行操作的日志消息。系统管理员随后可以修改为该安装定义的权限和所有权。

> 注意：对于新软件，默认权限设置为 755，所有者和组都设置为 `bin`。用于查找命令是否存在的默认搜索目录顺序为 `/usr/bin`、`/etc` 和 `/usr/lib`。

以下是可用于 `install` 命令的一些标志：

- `-d directory`：在指定的目录中安装文件，当且仅当命令已不存在时。如果操作中止。
- `-f directory`：在指定的目录中安装文件，即使命令在目录目录中已存在。如果文件是新的，则应用默认的所有者、组和权限。
- `-G group`：将安装文件的组设置为指定的组，而不是默认组 `bin`。
- `-O owner`：将安装文件的所有权设置为指定的用户，而不是默认所有者 `bin`。
- `-o`：用前缀 `OLD` 保存当前版本；即，如果文件名为 `sample`，则将其保存为 `OLDsample`。
- `-n directory`：如果你不想搜索默认目录，而是想搜索命令行指定的目录。

示例 你可以执行以下命令将文件 `sample_program` 安装到目录 `/usr/bin`（默认目录）：

```
install sample_program
```

假设 `sample_program` 已存在于 `/u/testester/exe` 目录，你可以通过执行以下命令安装新版本：

```
install -f /u/testester/exe sample_program
```

要将 `sample_program` 的旧版本备份为 `OLDsample_program` 并在 `/u/testester/exe` 目录中安装新版本，请执行以下命令：

```
install -f /u/testester/exe sample_program
```

获取 `umask` 默认值的示例，请执行以下命令：

```
umask
```

要将权限设置为 751，您应该将 `umask` 设置为值 026 `777 - 751`。要实现这一点，请执行以下命令：

```
umask 026
```

## 进程相关命令

在 UNIX 中，进程是一个拥有独立地址空间的程序。通常，您执行的命令或脚本由一个或多个进程组成。像 `umask` 这样的简单命令只关联一个进程，而通过管道连接的命令字符串则关联多个进程。

进程可以分为以下几大类：

- **交互式进程**，在终端执行。交互式进程可以在前台或后台执行。在前台进程中，输入从标准输入接收，输出显示到标准输出中，错误消息发送到标准错误输出。在后台执行进程时，终端会与进程分离，以便用于执行其他命令。可以将进程从前台移动到后台，反之亦然。
- **批处理进程**不从终端提交。它们被提交到作业队列中按顺序执行。
- **守护进程** 是永结束的进程，等待服务其他进程的请求。

在 UNIX 中，每个进程都有若干关联属性。以下是某些属性的列表：

- **进程 ID** 是 UNIX 分配给每个进程的唯一标识符。您可以使用进程 ID 在其生命周期内识别进程。
- **真实用户** 是启动进程的用户 ID。
- **有效用户 ID** 与每个进程关联的用户 ID。它决定了进程对资源的访问权限。在正常情况下，真实用户 ID 和有效用户 ID 是相同的。但通过在可执行程序上设置用户 ID `Set User ID`，有效用户 ID 可能与真实用户 ID 不同。如果您希望程序在不实际授予用户权限的情况下以特殊权限运行，则可以这样做。
- **真实组 ID** 是启动进程的用户组 ID。
- **有效组 ID** 是决定访问权限的组 ID。有效组 ID 类似于有效用户。
- **优先级** 是进程相对于系统中正在执行的其他进程的优先级。

### kill

`kill` 命令用于向正在执行的进程发送信号。该进程必须是非前台进程，您才能使用此命令向其发送信号。

该命令的默认操作是通过发送信号来终止进程。然而，进程可能被设计为接收此类信号。在这种情况下，进程将按照程序设计处理该信号。您只能杀死自己启动的进程。但是，`root` 用户可以杀死系统中的任何进程。

与 `kill` 命令相关的标志如下：

- `-1` 用于获取系统支持的所有信号及其名称列表。
- `-signal number` 是要发送给进程的信号。您也可以使用信号名称代替数字。您能向进程发送的最强信号是 9 或 `kill -9`。

`kill` 命令的参数是进程 ID `PID`。您可以指定多个 PID 作为参数来杀死多个进程。PID 的值可以是以下值之一：

- `-PID` 大于 0：杀死指定的进程。
- `-PID` 等于 0：杀死所有进程组 ID 与启动命令的用户进程组 ID 相同的进程。
- `-PID` 等于 -1：杀死由启动 `kill` 命令的用户有效用户 ID 的的所有进程。
- `-PID` 等于一个负数但不是 -1：杀死 PID 等于所指定数字绝对值的进程。

示例 如果您正在后台运行一个命令并认为它已经进入了循环，您将想要终止它。如果进程号是例如 2060，请执行以下命令：

```
kill 2060
```

如果由于某种原因这没有杀死它，使用更强力的：

```
kill -9 2060
```

如果您想杀死所有属于您的进程，请执行以下命令：

```
kill -9 0
```

但是，您应该注意，此命令也会让您注销，因为指定 0 意味着所有进程（包括您当前的登录）将被杀死。

### nice

正如您所看到的，每个进程都关联有一个相对优先级。相对优先级控制操作系统分配给它的资源。`nice` 命令允许您修改一个或多个进程的优先级，以便为它们分配更高或更低的优先级。只有在您拥有 `root` 权限时才能增加优先级。

负数表示优先级高于正数。该值通常在 -20 到 20 之间。

如果您没有指定值，只要您拥有相应的权限，`nice` 命令将取一个等于或高于当前进程的值。如果您没有足够的权限，优先级将完全不受影响。

通常情况下，您应该使用 `nice` 命令降低不需要快速周转的后台或批处理进程的优先级。

示例 如果您想以较低的优先级在后台查找当前目录或其子目录中的所有 C 源文件，请执行以下命令：

```
nice find -name *.c -print &
```

### ps

`ps` 命令用于查找哪些进程正在运行。根据选项，您可以查找所有进程或仅查找由用户启动的进程。此命令提供了有关各种后台和批处理进程的信息。

当不带任何标志或参数执行 `ps` 命令时，它会列出从当前终端启动的所有进程。

以下是决定 `ps` 列出哪些进程的标志列表：

- `-A` 列出系统中运行的所有进程。
- `-e` 列出除内核外的所有进程。
- `-k` 列出所有内核进程。
- `-p` 列出列表中指定进程的详情。
- `-t` 列出从指定终端启动的进程详情。
- `-U` `-u` 列出由指定用户启动的所有进程详情。
- `-a` 列出与终端关联的所有进程详情。
- `-g` 列出所有进程详情。
- `-x` 列出未关联终端的所有进程详情。

以下是 `ps` 命令中决定列出的进程显示哪些详情的标志列表：

- `-1` 以长格式生成列表
- `-f` 生成完整列表
- `-F` 格式化生成格式化输出

> 注意：`ps` 中使用的某些标志前面没有连字符 `-`。

如果不使用格式化标志，将显示以下详情：

- 进程的进程 ID。
- 与进程关联的终端 ID。如果没有关联终端，则显示连字符 `-`。
- 进程消耗的 CPU 时间。
- 作为进程执行的命令。

通过格式化命令 `-1`, `-f`, `-F`，可以获得的某些详情如下：

- 启动进程的用户 ID。
- 进程的进程 ID。
- 父进程 ID。
- 进程的 CPU 利用率。
- 进程的启动时间。如果进程是当天启动的，显示时间；否则只显示日期。
- 与进程关联的终端 ID。如果没有关联终端，则显示连字符 `-`。
- 进程消耗的 CPU 时间。
- 作为进程一部分正在执行的命令。

结果显示如下：

```
PID TTY TIME CMD
66874 2 0:00 -ksh
71438 2 0:00 ps
```

显示的两个进程是正在运行的登录 shell `Korn shell` 和 `ps` 命令本身。

如果你想获取更多细节，执行以下命令：

```bash
ps -f
```

这将生成以下显示：

```
USER PID PPID TTY TIME CMD
testuer 66874 1 1 22:52:26 2 0:00 -ksh
testuer 480076 66874 6 00:21:33 2 0:00 ps -f
```

如果你想知道在终端 `tty2` 上执行的所有进程，请执行以下命令：

```bash
ps -f -t tty2
```

结果为：

```
USER PID PPID C STIME TTY TIME CMD
testuer 66874 1 1 22:52:26 2 0:00 -ksh
testuer 703277 66874 6 00:24:17 2 0:00 ps -f tty2
```

如果一个进程没有与终端关联，则会显示一个连字符 `-`。因此，你可以使用连字符来获取未与任何终端关联的列表。例如，你可以执行以下命令：

```bash
ps -t -
```

要找到用户 ID 为 `friend` 的朋友正在执行的所有进程，请执行以下命令：

```bash
ps -f -u friend
```

## jobs

在 UNIX 中，进程 `processes` 和作业 `jobs` 之间存在细微的差异。作业通常是指一行命令，实际上它可以是一个单条命令、一个 shell 脚本，或者一组通过管道的命令。在管道命令链中，每个命令都有一个唯一的 PID，但它们都具有相同的作业 ID。

`shell` 以及某些版本的 Korn 和 Bourne 提供了 `jobs` 命令。你可以使用 `jobs` 命令来查找活动作业的细节。如果你拥有该作业，可以开始使用它来执行作业控制。

你可以在作业号前面加上 `%`（百分号）来表示该数字是作业号而非进程 ID。

示例 如果你想将作业号 5 从后台调到前台，执行以下命令：

```bash
fg %5
```

如果你使用的是 5 而不是 `%5`，UNIX 将其解释为进程 ID 5。

如果你有一个名为 `sample_job` 的作业在后台运行，执行以下命令：

```
jobs
```

来获取作业的细节。显示如下：

```
[1] + Running nohup sample_job > sample_log &
```

如果你使用 `-1` 选项，进程号也将显示如下：

```
[1] + 270384 Running nohup sample_job > sample_log &
```

你不需要知道作业 即可对其进行任何操作。你可以使用以 `%`（百分号）开头的作业名称来识别该作业。你可以使用 UNIX 通配符来实现这一点。

在前面的示例中，你可以使用名称 `sample_job` 来识别该作业。UNIX 同样允许你使用 `% \?` 来识别作业名称的唯一部分。在这个示例中，它可能是 `\?\job`（请注意，字符 `\` 通过在字符前转义 `\` 用来告诉 UNIX 不要将该字符解释为控制字符）。要杀死作业 `sample_job`，使用以下命令：

```bash
kill %sample_job
```

或者，如果 `sample_job` 是你当前执行的唯一作业，会导致以下结果；否则，它将杀死所有以 `job` 结尾的作业：

```bash
kill \?\job
```

```bash
wait
```

你可以使用 `wait` 命令等待作业完成。该命令接受一个或多个进程 ID 作为参数。这在进行 shell 编程时非常有用，当你希望在调用下一个进程之前某个进程完成时。如果你不指定进程 ID，UNIX 将找到当前环境下运行的所有进程，并等待它们全部终止。

示例 如果你想找出你启动的所有进程都已完成，执行以下命令：

```bash
wait
```

如果你想知道进程 ID 15060 是否已完成，执行以下命令：

```bash
wait 15060
```

如果你在不带任何参数的情况下调用 `wait` 命令，则返回码为零。如果你带有多个进程 ID 调用 `wait` 命令，则返回码取决于最后一个指定的进程的返回码。

## nohup

在 UNIX 下执行进程时，它们可以在前台或后台运行。在前台进程中，你在终端等待进程完成。在这种情况下，在进程完成之前你无法使用该终端。你可以如下所示将前台进程放入后台：

```bash
Ctrl-z
```

```bash
bg
```

当你退出系统或退出当前 shell 时，无论 UNIX 中的进程是在前台还是后台，都会被终止。确保运行进程时不终止的唯一方法是使用 `nohup` 命令。

`nohup` 命令对标准输出有默认重定向。它将消息重定向到命令执行目录下名为 `nohup.out` 的文件中。也就是说，符号 `&` 允许你在后台运行命令。
