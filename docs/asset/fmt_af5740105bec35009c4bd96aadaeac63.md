
操作系统是机器上其他一切事物的基础。创造一个操作系统是终极挑战。当你创建操作系统时，你正在创建所有运行计算机的程序所生存的世界——基本上，你是在制定什么是可接受的、什么可以做以及什么不能做的规则。每个程序都这样做，但操作系统是最基本的。这就像为你所创造的土地制定宪法，而计算机上运行的其他所有程序只是普通法律。

有时法律没有意义。但理性是你追求的目标。你希望看着解决方案并意识到你以正确的方式得出了正确的答案。

还记得学校里那个总是得到正确答案的人吗？那个人比其他人快得多，因为他或她没有试图学习问题*应该*怎么做，而是以正确的方式思考问题。一旦你听到答案，它就变得合情合理。

计算机也是如此。你可以用蛮力方式，愚蠢地、把问题磨掉直到它不再是问题的方式，或者你可以找到正确的方法，突然问题就消失了。你用另一种方式看待问题，并产生顿悟：它之所以成为问题，只是因为你以错误的方式看待它。

这个现象最伟大的例子可能不是来自计算，而是来自数学。故事是这样的：伟大的德国数学家卡尔·弗里德里希·高斯在学校时，他的老师厌倦了，为了让学生忙碌，他指示他们计算1到100之间所有数字的总和。老师预计年轻人会花一整天来做这件事。但这位新兴的数学家五分钟后就带着正确答案回来了：5,050。解决方案并不是实际相加所有数字，因为那将是令人沮丧且愚蠢的。他发现的是，通过将1和100相加得到101。然后通过将2和99相加得到101。然后3和98是101。所以50和51是101。几秒钟内，他注意到这是50对101，所以答案是5,050。

也许这个故事是虚构的，但重点很清楚：一位伟大的数学家不会用漫长而无聊的方式解决问题，因为他看到真正的模式在问题背后，并应用该模式以更好的方式找到答案。这在计算机科学中绝对是正确的。当然，你可以只写一个计算总和的程序。在今天的计算机上，这很容易。但伟大的程序员会通过聪明才智直接知道答案是什么。他会知道如何编写一个美丽的程序，以新的方式攻击问题，最终这也是正确的方式。

仍然很难解释，花三天时间对着墙撞头，不知道如何用更好、更美观的方式解决某事，为什么如此迷人。但一旦你找到那种方式，那就是世界上最棒的感觉。

# 六

我的终端模拟器长出了腿。我定期使用它登录大学计算机阅读电子邮件或参与 Minix 新闻组的讨论。麻烦的是，我想要下载和上传东西。这意味着我需要能够保存东西到磁盘。为了做到这一点，我的终端模拟器需要一个磁盘驱动程序。它还需要一个文件系统驱动程序，以便它能够查看磁盘的组织结构并将我正在下载的内容保存为文件。

那几乎是我放弃的时刻，我觉得工作太多，不值得做。但没什么别的可做的。那个春天我在上课，课程并不特别有挑战性。我唯一的外界活动是每周三晚上 Spektrum 的定期会议（聚会）。作为一个社交上的非动物（指我不善社交），那成了我除了编程或学习之外做任何事情的唯一机会。没有那些会议（聚会），那个春天我会成为一个彻底的隐士，而不是近乎彻底的隐士。Spektrum 提供了一种类社会生活的内置框架，我认为我从未错过他们的任何活动。他们对我很重要——事实上重要到有时我期待这些会议时会失眠，希望不要因为自己缺乏社交礼仪、鼻子或明显没有女朋友而感到不自在。这是标准的书呆子行为。

我想说的是，我没有太多其他有趣的事情在做。而磁盘驱动程序/文件系统驱动程序项目会很有趣。所以我决定做这个。我写了一个磁盘驱动程序。并且因为我想将文件保存到我的 Minix 文件系统——并且 Minix 文件系统无论如何都有很好的文档——我使我的文件系统与 Minix 文件系统兼容。这样，我就可以读取我在 Minix 下创建的文件，并将它们写入同一个磁盘，以便 Minix 能够读取我从我的终端模拟东西创建的文件。

这需要大量的工作——程序-睡觉-程序-睡觉-程序-吃（椒盐脆饼）-程序-睡觉-程序-洗澡（短暂）-程序的日程。当我这样做的时候，很明显该项目正在朝着成为操作系统的方向发展。所以我把它从终端模拟器的思维转变为了操作系统的思维。我认为这种转变发生在其中一个马拉松式编程会面的恍惚中。白天还是晚上？我不记得了。前一分钟，我还穿着破烂的长袍在敲终端模拟器，增加额外的功能。下一分钟，我意识到它积累了如此多的功能，以至于已经变成了一个正在开发中的新操作系统。

我称之为我的“终端模拟程序的 Gnu-emacs”。Gnu-emacs 起初是一个编辑器，但创造它的人内置了一堆功能。他们打算让它成为一个可编程的编辑器，但后来可编程性部分占了上风，它变成了地狱般的编辑器。它什么都有，除了厨房水槽（意指包罗万象），这就是为什么有时编辑器的图标实际上是一个厨房水槽。它以拥有比任何编辑器需要的都多的功能而闻名。同样的事情也在我的终端模拟器上发生。它正在成长为远不止这些。

由于我正在参与的一个项目（基于 Minix），我对 POSIX 标准定义很感兴趣。有人能给我指指路，最新 POSIX 规则的（最好是）机器可读格式在哪里吗？Ftp 站点就更好了。

好吧，这是最早公开的证据，表明芬兰有一位极客愿意测试他计算技能的边界。POSIX 标准是针对 Unix 中数百个系统调用中的每一个的冗长规则——你需要这些规则才能让计算机执行其操作，从 Read（读）、Write（写）、Open（打开）、Close（关闭）开始。POSIX 是一个 Unix 标准机构，由那些希望就共同准则达成一致的公司的代表组成。标准之所以重要，是因为它使程序员能够为操作系统编写应用程序，并使其在多个版本上运行。系统调用——特别是那些重要的调用——可以给我一个操作系统所需的各种功能列表。然后我会编写代码，以我自己的方式使这些功能得以实现。通过遵循 POSIX 标准编写代码，我的代码就可以被他人使用。

当时我不知道我可以以纸质形式直接从 POSIX 购买这些规则，但无论如何都没关系。即使我负担得起费用，货物运到芬兰也总是需要很长时间。因此，我呼吁获取一个我可以从 ftp 站点免费下载的版本。

没有人提供 POSIX 标准的来源，所以我转向了 B 计划。我找到了大学里 Sun Microsystems 版本的 Unix 手册，因为大学当时正在运行一台 Sun 服务器。手册中包含系统调用的基本版本，足以让我应付过去。你可以查看手册页，看看系统调用应该做什么，然后着手实现它。手册页没有说明如何做，只说明了最终结果是什么。我还从 Andrew Tanenbaum 的书和其他几本书中获取了一些系统调用信息。最终，有人寄给我了包含 POSIX 标准的厚厚几卷书。

但我的电子邮件消息并未被忽视。任何懂行的人（只有懂行的人才会阅读 Minix 网站）都能看出，我的项目肯定是一个操作系统。否则我为什么要 POSIX 规则？这条消息激起了阿里的强烈兴趣，阿里（Ari Lemke）是赫尔辛基理工大学（如果我没有如此热衷于学习理论，本会在那里上学）的一名助教。阿里回了我一封友好的邮件，表示愿意在大学的 ftp 站点上创建一个子目录，供我在我准备好发布我的操作系统时，让任何感兴趣的人下载。

# 第七章

阿里·莱姆克（Ari Lemke）一定是个相当乐观的人。他在我还有任何东西想要发布之前很久就创建了该子目录（`ftp.funet.fi`）。我有密码，一切都设置好了，我只需登录并上传内容即可。但花了大约四个月时间，我才觉得自己有了一些愿意与世界分享，或者至少与阿里以及几位我曾通过电子邮件交流过的操作系统狂热者分享的东西。

我最初的目标是创建一个最终可以用作 Minix 替代品的操作系统。它不需要比 Minix 做更多事情，但它必须做到 Minix 中我在意的功能，以及其他一些我在意的功能。例如，不仅 Minix 的终端模拟很差，而且没有任何方法来实现作业控制功能——在你不使用程序时将其放入后台。此外，内存管理非常简单，顺便说一下，Mac OS 至今仍如此。

创建操作系统的方法是弄清楚系统调用应该做什么，然后编写自己的程序以你自己的方式实现这些系统调用。一般来说，有几百个系统调用。其中一些可以代表多个功能。另一些则非常简单。一些更基础的系统调用确实很复杂，并且依赖于大量基础设施的存在。以“Write”和“Read”系统调用为例。你需要创建磁盘驱动程序才能将内容写入磁盘或从磁盘读取内容。以“Open”为例，你必须创建整个文件系统层，以解析名称并确定磁盘上所有内容的位置。光是编写“Open”系统调用就花了几个月时间。但一旦到位，同样的代码就可以用于其他功能。

这就是早期开发的方式。我从 Sun OS 手册或各种书籍中阅读标准，逐个挑选系统调用并尝试制作可用的东西。这真的很令人沮丧。
