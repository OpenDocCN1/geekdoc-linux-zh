
这可以防止 `make` 被一个名为“`clean`”的实际文件搞混，并导致它在忽略 `rm` 产生的错误的情况下继续执行。（参见第 4.5节 [伪目标]，第 29 页和第 5.5节 [配方中的错误]，第 49 页）。

这样的规则不应该放在 Makefile 的开头，因为我们不希望它默认运行！因此，在示例 Makefile 中，我们希望重新编译编辑器的 `edit` 规则保持为默认目标。

由于 `clean` 不是 `edit` 的依赖项，如果在不带参数的情况下提供 `make` 命令，此规则将完全不会运行。为了让规则运行，我们必须输入 `make clean`。参见第 9 章 [如何运行 make]，第 99 页。

告诉 `make` 如何重新编译系统的信息来自于读取一个名为 `makefile` 的数据库。

Makefile 包含五类内容：*显式规则*、*隐式规则*、*变量定义*、*指令*和*注释*。规则、变量和指令将在后面的章节中详细描述。

- *显式规则*说明了何时如何制作一个或多个文件，这些文件被称为规则的*目标（targets）。它列出了目标依赖的其他文件，称为目标的*依赖项（prerequisites），还可以提供一个用于创建或更新目标的配方。第 4 章 [编写规则]，第 21 页。
- *隐式规则*说明了根据名称何时如何制作一类文件。它描述了目标如何依赖于一个与目标类似的名称，并给出创建或更新此类目标的配方。第 10 章 [隐式规则]，第 111 页。
- *变量定义*是一行，它为变量定义了一个文本值，该值可以在随后的文本中替换。简单的 Makefile 示例显示了对象的变量定义，它是所有对象文件的列表（参见第 2.4 节 [变量让 Make 更简单]，第 6 页）。
- *指令*是让 `make` 在读取makefile 时执行某些事的指令。这些包括：
    - 读取另一个 makefile（参见第 3.3 节 [包含其他 Makefile]，第 13 页）。
    - 决定（基于变量的值）是否使用或忽略makefile 的部分内容（参见第 7 章 [Makefile 的条件部分]，第 77 页）。
    - 从一个包含多行的逐字字符串中定义变量（参见第 6.8 节 [多行变量]，第 69 页）。
- 文件中行中的 `#` 开始一个注释。它和该行的其余部分都会被忽略，除非你想要一个字面上的 `#`，否则使用反斜杠对其进行转义（例如 `\#`）。

Makefile 使用“基于行”的语法，其中换行符是特殊的并标记了语句的结束。GNU make 对语句的长度没有限制。然而，长行很难阅读。你可以通过添加换行来格式化你的 makefiles以便可读性：当我们需要区分时我们将“物理行”称为以换行符结尾的行，将“逻辑行”称为完整的语句。

反斜杠/换行的处理方式取决于语句是配方还是非配方。配方中反斜杠/换行的处理将在以后讨论（参见5.1.1 [拆分配方行]，第 41 页）。在配方行之外，反斜杠/换行转换为单个空格。一旦完成，反斜杠周围的所有空格都会压缩：这包括反斜杠之前的所有空格、行首空格以及任何连续的反斜杠/换行。

如果定义了 POSIX 特殊目标，则反斜杠/换行的处理将稍微修改以符合 POSIX：首先，反斜杠之前的空格不会被移除，其次连续的反斜杠/换行不会被压缩。

默认情况下，当 make 寻找makefile 时，它按顺序尝试以下名称：`makefile`、`makefile` 和 `Makefile`。

通常你应该将你的命名为 `makefile` 或 `Makefile`。（我们推荐 Makefile，因为它在目录列表的开头非常显著，其他文件如 'README'。）第一个命名的 `makefile` 对于大多数makefile 并不推荐。如果你有一个特定于 GNU make 且不会被其他版本的理解的 myfile，你应该使用这个名称。其他程序查找 `makefile` 和 `Makefile`，但不查找 `makefile`。

如果 make 找不到这些名称之一，它将不使用任何makefile。你必须带命令参数指定一个目标，make 将尝试仅使用其内置规则找出如何制作它。第 10 章 [使用隐式规则]，第 111 页。

如果你想为你的 myfile 使用非标准名称，可以通过 `-f` 或 `--file` 选项指定名称。`--file=name` 参数告诉 make 读取该文件名作为 makefile。如果你使用了多个 `-f` 或 `--file` 选项，你可以指定多个makefile。makefile 在实际上是按顺序连接的。如果你指定了 `-f` 或 `--file`，则不会自动检查默认的 make 名称 `makefile`、`makefile` 和 `Makefile`。

## 3.3 包含其他 Makefile

`include` 指令告诉 make 暂停当前的 Makefile 并在继续之前读取一个或多个 Makefile。该指令是 Makefile 中形如所示的一行内容：

```
include filenames...
```

如果 `filenames` 为空，则不包含任何内容，且不打印错误。行首允许额外的空格并会被忽略，但第一个字符不能是制表符（或 `RECIPE` 的值）——如果行以制表符开头，它将被视为一个配方（recipe）。`include` 与文件名之间、文件名之间的空白字符会被忽略，行尾的额外空白字符也会被忽略。允许允许以 `#` 开头的注释。如果文件包含任何变量或函数引用，它们会被展开。参见第 6 节“变量”。

例如，如果你有 'a.mk'、'b.mk' 和 'c.mk'，且 `$(bar)` 展开为 `bash`，那么以下表达式

```
include $(bar)
```

等价于

```
include a.mk b.mk c.mk
```

当 make 处理 `include` 指令时，它会暂停读取包含该指令的 Makefile，并从每个出的文件中读取。完成后，make 将恢复读取该指令所在的 Makefile。

使用 `include` 的一种情况是：当由不同目录下的独立 make 处理的多个程序需要使用一组公共变量定义（参见第 6.5 节“设置变量”）或模式规则（参见第 10.5 节“重定义模式规则”）。

另一种情况是你想从源文件自动生成依赖项；这些依赖项可以放在一个由主 make 包含的文件中。这种做法通常比将依赖项附加到主 make 的末尾更整洁。参见第 4.3 节“自动依赖项”。

如果指定的名称不包含斜杠，且在当前目录下未找到该文件，则会搜索其他目录。首先搜索使用 `-I` 或 `--include-dir` 选项指定的任何目录（参见第 9.7 节“选项摘要”）。然后按顺序搜索以下目录（如果存在）：`prefix/include`（通常为 `/usr/local/include`）。

如果在这些目录中都找不到被包含的 Makefile，将生成一条警告信息，但这不是立即的致命错误；包含该 `include` 的 Makefile 的处理将继续。一旦完成对 Makefile 的读取，make 将尝试重新制作任何过时或不存在的文件。参见第 3.5 节“Makefile 是如何重做的”。

用于 MS-DOS 和 MS-Windows 的 GNU Make 行为类似于 `prefix` 定义为树形层次结构的根节点。

只有在尝试查找 Makefile 的重制失败后，make 才会将缺失的 Makefile 诊断为致命错误。

如果你想让 make 简单忽略不存在或无法制作的 Makefile 而不显示错误信息，请使用 `-include` 指令代替 `include`，如下所示：

```
-include filenames...
```

这在每个方面都与 `include` 相似，不同之处在于如果任何文件名（或任何文件名的任何依赖项）不存在或无法制作，则不会产生错误（即使是警告）。

为了与其他 make 实现兼容，`include` 是 `-include` 的另一个别名。

如果定义了环境变量 `MAKEFILES`，make 将其值视为一组名称（由空格分隔），这些名称是在读取其他 Makefile 之前读取的额外 Makefile。这的工作原理类似于 `include` 指令：会在各个目录中搜索这些文件（参见第 3.3 节“包含其他 Makefile”）。此外，默认目标永远不会从这些 Makefile（或它们包含的任何 Makefile）中获取，如果未找到 `MAKEFILES` 中的文件，也不会报错。

`MAKEFILES` 的主要用途是用于递归调用 make 之间的通信（参见第 5.7 节“make 的递归使用”）。通常不建议从 make 的顶层调用中设置该环境变量，因为最好不要在 Makefile 外部大搞手脚。但是，如果你在没有指定特定 Makefile 的情况下运行 make，`MAKEFILES` 中的 make 可以执行一些有用操作来帮助内置规则工作得更好，例如定义路径（参见第 4.4 节“目录搜索”）。

某些用户倾向于在登录时自动在环境中设置 `MAKEFILES`，并在程序 Makefile 中期望执行此操作。这是一个非常糟糕的主意，因为其他人将无法运行这些 Makefile。更好的做法是在 Makefile 中直接写明 `include` 指令（参见第 3.3 节“包含其他 Makefile”）。

有时 Makefile 可以从其他文件（如 RCS 或 SCCS）重制。如果一个 Makefile 可以从其他文件重制，你可能希望 make 获取该文件的更新版本进行读取。

为此，在读取了所有 Makefile 后，make 将将每一个视为一个目标并尝试更新它。如果一个 Makefile 有关于如何更新它的规则（在在该 Makefile 或另一个 Makefile 中找到），或者有隐式规则适用于它（参见第 10 节“使用隐式规则”），则在需要时对其进行更新。在检查完所有 Makefile 后，如果任何文件实际上发生了变化，make 将从零开始并重新读取所有 Makefile。

如果你知道一个或多个目标已经是更新的，你可以写一个空配方（参见第 5.9 节“此处为空配方”）。使用双冒号规则（参见 4.1节“双冒号”）会导致无限循环：make 会不断重制 Makefile。

如果你执行 `make foo`，make 将找到 'GNUmakefile'，读取它，并发现生成 'foo' 需要运行配方 `frobnicate > foo`。如果你执行 `make bar`，它在 'GNUmakefile' 中没有找到生成 'bar' 的方法，因此它将使用模式规则中的配方：`make -f Makefile bar`，这提供了一个更新 'bar' 的规则，make 将应用该规则。对于 'GNUmakefile' 未说明如何生成的其他目标，也是如此。

这种工作原理是模式包含一个字符 `%`，它可以匹配任何目标。该规则提供了一个前置条件 `force`，以确保即使目标文件已存在，配方也会运行。我们给 'force' 目标一个空的配方，以防止为了隐式规则来构建它——否则它将一直应用相同的匹配直到 'force' 本身，从而导致前置条件循环！

GNU make 分两个阶段完成工作。在第一阶段，它读取所有的 Makefile、被包含的 Makefile，并将所有的变量和值、隐式规则和显式规则内部化，构建一个包含所有目标及其前置条件的依赖图。在第二阶段，make 使用这些内部结构来确定哪些目标需要重新构建，并使用必要的操作进行构建。

理解这种双阶段方法至关重要，因为它直接影响变量展开的发生；这通常是编写 Makefile 时的困惑来源。我们将总结 Makefile 中不同结构在发生展开的阶段。如果展开发生在第一阶段，我们称其为**立即展开**（immediate）：在这种情况下，make 在解析 Makefile 时就会展开该结构中的任何变量或函数。如果延迟结构的展开直到该结构在后后的隐式文中出现，或者直到第二阶段才执行，我们称其为**延迟展开**（deferred）。

你可能还不熟悉这些构造结构。在后面的章节中，当你熟悉它们时，可以参考本节。

immediate := immediate

```

deferred endif

```

```

deferred endif
```

```

```

对于 Shell 赋值运算符 `*=`，右侧立即求值并传递给 Shell。结果存储在左侧指定的变量中，该变量将变为简单变量（因此在每次引用时都会被重新求值）。

条件指令是立即解析的。这意味着例如，自动变量不能在条件指令中使用，因为自动变量直到相应的配方被调用时才会被设置。如果你需要在条件指令中使用自动变量，必须将条件移动到配方中，并使用 Shell 的条件语法。
