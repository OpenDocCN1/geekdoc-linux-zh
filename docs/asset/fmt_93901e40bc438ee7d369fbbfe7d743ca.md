如你所见，`/etc/hosts.deny`文件被设置为拒绝所有主机。单一配置行`ALL : ALL`告诉TCP包装器（`tcpd`）拒绝所有守护进程访问所有主机。如果保持原样且系统中没有`/etc/hosts.allow`文件，则没有任何主机将能够访问任何三个由`inetd`运行的服务（Telnet、FTP和POP3）。因此，你必须在`/etc/hosts.allow`文件中允许特定的主机（特别是`206.171.50.0`网络）访问这些服务。这在列表18-5中所示。

列表18-5：`/etc/hosts.allow`文件

```
# # hosts.allow
# 允许使用本地 INET
# 服务的主机列表，
# 由 /usr/sbin/tcpd 程序决定。
# 
# 禁止所有守护进程访问所有主机。
ALL : 206.171.50.0/255
```

# 明确`spooky.badguy-domain.com`不受此服务器的欢迎。
`in.telnetd: spooky.badguy-domain.com: twist /bin/echo \`你不欢迎这里！

或者，如果你想在`spooky`主机尝试Telnet时立即收到电子邮件，可以使用`/bin/mail`程序向给自己发送消息。在这种情况下，你需要一个类似下面的`/etc/hosts.allow`配置：

```bash
# 允许除 spooky 以外的所有人 进行 telnet 访问
in.telnetd: ALL EXCEPT spooky.badguy-domain.com
# 明确 spooky.badguy-domain.com 
# 不受此服务器的欢迎。
in.telnetd: spooky.badguy-domain.com: linger 5: /bin/mail \
-s "%a (%c) tried to access (%p) your@emailaddress </etc/badguy-came.txt
```

在这里，当`spooky`尝试Telnet时，会调用`/bin/mail`程序。调用邮件程序时使用了`-s`选项将主题行设置为`"%a (%c) tried to access (%p)"`，这会被展开为`"x.x.x.x (spooky.badguy-domain.com) tried to access in.telnetd (xyz)"`，其中`x.x.x.x`是主机的IP地址，PID是守护进程的ID。

### 检查你的TCP WRAPPER配置

`/etc/inetd.conf`中的错误在安全方面可能是代价昂贵的，因此使用像`tcpd`这样的程序检查配置是有值的。该程序将检查你的`/etc/inetd.conf`文件并报告包括不存在的路径、`/etc/hosts.allow`或`/etc/hosts.deny`文件中的配置错误、无效参数等问题。你可以如下所示运行`tcpdchk`：

```
/usr/sbin/tcpdchk
```

你还使用`tcpdchk`实用程序测试你的`/etc/hosts.allow`和`/etc/hosts.deny`配置。例如，假设你在`/etc/hosts.allow`文件中有行`ALL: 206.171.50.48/255.255.250`，而在`/etc/hosts.deny`文件中有行`ALL:ALL`。此时你应该能看出，上述配置仅允许来自`206.171.50.48`网络的主机访问`inet-d`运行的服务。现在，要发现当来自名为`blackhole.nitec.com` (`206.170.189.100`)的主机的Telnet请求时`tcpd`会做什么，你可以运行以下命令：

```
/usr/sbin/tcpdchk match. telnetd blackhole.nitec.com
```

# 用安全Shell (SSH)替换r命令

首先，如果你不使用包括`login`、`rsh`、`rexec`等在内的`r*`命令，请考虑将它们从你的系统中完全删除。你已经学习了如何在`/etc/inetd.conf`文件中禁用服务。这些服务被认为容易受到攻击。如果你使用这些服务访问你的系统，请考虑用一个名为Shell或`ssh`的安全解决方案来替换它们。`ssh`解决方案提供了`r*`命令的所有优点，甚至更优。例如，使用`ssh`可以通过安全的加密连接登录远程系统或在远程系统上执行命令。它提供了丰富的日志功能，并与`syslog`良好配合。通过`ssh`，你还可以创建安全的远程X会话。它可以提供针对IP和DNS欺骗、基于X身份验证协议弱点的攻击等的保护。你可以从以下网站准备运行`ssh`的RPM包：`http://www.replay.com/redhat/ssh.html`。

你需要基础`ssh`包、`ssh`客户端包和`ssh`服务器包。由于美国对加密软件的出口控制法，对`ssh`可能会有一些某些法律限制。请务必阅读上述网站上找到的文档。

# 保护你的文件和文件系统

在涉及保护时，文件和文件系统是最重要的。你希望确保你的文件和文件系统得到了良好的保护。正如本章其他内容一样，核心思想是给予最小的权限。如果你通过读取访问就可以完成，那么不要仅仅因为可以就给予写入或执行权限。在接下来的章节中，我将讨论几个问题。

### 将文件系统挂载为只读

在可能的情况下将某些系统维护为只读是一个好主意。例如，如果你确定不需要写入，可以将分区挂载为只读。假设你在`/etc/fstab`中有这样一行：

```
/dev/sda1  /home  ext3  rw  0  1
```

要使文件系统变为只读，你需要将`rw`改为`ro`：

```
/dev/sda1  /home  ext3  ro  0  1
```

然后，你可以通过以下命令重新挂载为只读：

```
mount -o remount,ro /home
```

如果你需要将文件系统恢复为读写，可以使用：

```
mount -o remount,rw /home
```

这个故事的教训是对`root`要非常小心。事实上，我建议使用一些Linux `ext2`文件系统的特性来防止此类灾难。例如，你可以使用`chattr`命令来防止意外修改。方法如下：

Red Hat Linux使用的`ext2`系统提供了一些独特特性。一个特性允许文件对`root`用户是不可变的。例如：

```
chattr +i filename
```

该命令将设置`ext2`文件系统中文件的“i”属性。当设置该属性时，任何人无法修改、删除或重命名该文件。无法为该文件添加链接。该属性只能由`root`用户设置或清除。因此你可以使用该属性防止文件意外。当你需要清除该属性时，可以运行：

```
chattr -i filename
```
