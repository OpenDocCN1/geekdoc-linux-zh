# 使用关联数组模拟多维数组

虽然 bash 直接支持单维数组，但通过使用关联数组索引看起来像多维数组地址的字符串来“伪造”多维数组并不困难。这是一个示例：

```bash
#!/bin/bash

# array-multi - 模拟多维数组
```

```bash
declare -A multi_array

# Load array with a sequence of numbers

counter=1

for row in {1..10}; do
  for col in {1..5}; do
    address="$row,$col"
    multi_array["$address"]=$counter
    ((counter++))
  done
done
```

```bash
# Output array contents

for row in {1..10}; do
  for col in {1..5}; do
    address="$row,$col"
    echo -ne "${multi_array["$address"]}\t"
  done
done

echo
```

# 命令组与子 shell

bash 允许将命令组合在一起。这可以通过两种方式实现：使用命令组或子 shell（subshell）。我们在第 6 章中介绍过命令组，正如我们记忆的，命令组使用以下语法：

```bash
{ command1; command2; [command3; ...] }
```

子 shell 使用类似的语法。

```bash
command1; command2; [command3;...]
```

命令组用大括号包裹其命令，而子 shell 使用括号。需要注意的是，由于 bash 实现命令组的方式，大括号与命令之间必须有空格，并且最后一个命令在闭合大括号之前必须以分号或换行符终止。

那么，命令组和子 shell 有什么用？虽然它们有重要的区别（我们稍后会提到），但两者都可以用于管理重定向。让我们考虑对多个命令执行重定向的脚本片段。

```bash
ls -l > output.txt

echo "Listing of foo.txt" >> output.txt

cat foo.txt >> output.txt
```

这非常直观。三个命令的输出都被重定向到名为 `output.txt` 的文件中。使用命令组，我们可以这样编写代码：

```bash
{ ls -l; echo "Listing of foo.txt"; cat foo.txt; } > output.txt
```

使用子 shell 类似。

```bash
(ls -l; echo "Listing of foo.txt"; cat foo.txt) > output.txt
```

使用这种技术我们节省了一些输入量，但命令组或子 shell 真正放异彩的地方在于：在构建命令管道时，将多个命令的结果合并到一个流中通常非常有用。命令组和子 shell 让这变得简单。

```bash
{ ls -l; echo "Listing of foo.txt"; cat foo.txt; } | lpr
```

在这里，我们将三个命令的输出合并并将其管道到 `lp` 的输入中，以生成打印报告。

虽然命令和子 shell 看起来相似，并且可以组合命令进行重定向，但它们之间存在着重要的区别。命令组在当前 shell 中执行其所有命令，而子 shell（顾如其名）在当前 shell 的子副本中执行其命令。这意味着环境（包括 shell 函数、别名和变量）被复制并提供给一个新的 shell 实例。这种环境的复制与进程在 shell 中通常的工作方式不同：进程会继承父 shell 环境的完整副本，而子进程只继承父 shell 导出的（exported）变量。当子 shell 退出时，它的环境副本就会丢失，因此对子 shell 环境进行的任何更改（包括变量赋值）也会丢失。

最重要的是，子 shell 像子进程一样，与命令组不同，不能修改父环境。让我们先用命令组演示：

```bash
VAR=original

{ VAR=changed }

echo $VAR
```

接下来，我们用子 shell 执行同样的操作：

```bash
VAR=original

( VAR=changed )

echo $VAR
```

正如我们看到的，命令组能够修改当前 shell 的值，而子 shell 则不能。通常，除非脚本需要执行切换目录等操作，否则在返回父 shell 后，当前目录保持不变。

让我们来看这个脚本的机制：

## 第 5 行

关联数组必须使用 `declare` 命令并配合 `-A` 选项来创建。在这个脚本中，我们如下创建了五个数组：

- `files` 包含目录中的文件名，以文件名索引。
- `file_group` 包含每个文件的组所有者，以文件名索引。
- `file_owner` 包含每个文件的所有者，以文件名索引。
- `groups` 包含属于索引组的文件数。
- `owners` 包含属于索引所有者的文件数。

## 第 7–10 行

这些行检查是否传递了一个有效的目录名称作为位置参数。如果不是不是，则会显示用法信息并且脚本以状态码 1 退出。

## 第 12–20 行

这些行遍历目录中的文件。使用 `stat` 命令，第 13 和第 14 行提取文件所有者和组所有者的名称，并使用文件名作为数组索引将值赋值给各自的数组（第 16 和第 17 行）。同样，文件名本身被赋值给 `files` 数组（第 15 行）。

## 第 18–19 行

属于文件所有者和组所有者的文件总数加 1。

## 第 22–27 行

输出文件列表。这是通过 `${array[@]}` 参数扩展完成的，它会展开为数组元素的整个列表，其中每个元素被视为一个独立的单词。这允许文件名可能包含嵌入空格的可能性。另外注意，整个循环被包含在大括号中，形成了一个组命令。这允许将循环的输出通过到 `sort` 命令中。这是必要的，因为关联数组元素的展开并不是排序的。

## 第 29–40 行

这两个循环与文件列表循环相似，不同之处它们使用了 `${array[@]}` 扩展，该扩展展开的是数组索引列表而不是数组元素列表。

## 进程替换 (Process Substitution)

我们在第 28 章中见过子壳环境问题的示例，当时我们发现管道中的 `read` 命令并不并不像我们直觉预期的那样工作。回顾一下，我们构建了如下管道，`REPLY` 变量的内容始终是空的，因为 `read` 命令在子壳中执行，当子壳终止时，它的 `REPLY` 副本会被销毁。

```
echo "foo" | read

echo $REPLY
```

因为管道中的命令始终在子壳中执行，任何赋值变量的命令都会遇到这个问题。幸运的是，shell 提供了一了一种奇特的扩展形式称为“进程替换”，可以用来绕过这个问题。

进程替换有两种表示方式。对于产生标准输出的进程，它看起来如下：

```
$(list)
```

或者，对于读取标准输入的进程，它看起来如下：

```
$(list)
```

`list` 是一个命令列表。

为了解决我们 `read` 的问题，我们可以如下使用进程替换：

```
read <(echo "foo")

echo $REPLY
```

进程替换允许我们认为子壳的输出视为普通文件以便进行重定向。事实上，它是一种扩展形式，我们可以检查它的真实值。

```
[me@linuxbox ~$] echo <(echo "foo")/dev/fd3
```

通过使用 `echo` 查看扩展的结果，我们看到子壳的输出是由一个名为 `dev/fd6` 的文件提供的。这是一个 `read` 循环示例，它处理由子壳创建的目录列表内容：

```bash
#!/bin/bash

# pro-sub: 进程替换演示

while read -r attr links group size date time filename; do
cat <<EOF_
Filename: $filename

Size: $size

Owner: $owner

Group: $group

Modified: $date $time

Links: $links

Attributes: $attr

EOF_
done <(ls -l --time-style="+F %H:%M:%S" | tail -n +2)
```

循环为目录列表的每一行执行。列表本身在脚本的最后一行生成。这一行将进程替换的输出重定向到循环的标准输入。`tail` 命令被包含在进程替换管道中，以消除列表的第一行，该行是不需要的。

## Wordle 助手

Wordle 是一种由威尔士工程师 Josh Wardle 创建并开发的网页文字游戏。玩家有六次机会猜一个五个字母的单词，每次猜测都会以彩色磁砖的形式指示哪些字母占据了正确的位置。

该脚本通过选择标准和剩余部分对字典 (`/usr/share/words`) 进行过滤。为了这一点，我们需要构建一个根据命令行位置参数数量变化的变化的管道。通过这样做，我们消除了使用临时文件存储中间结果的需求。

```bash
#!/bin/bash

# eval-wordle - 通过解决 wordle 谜题来演示 eval

PROGNAME=${0##*/}

DIRECTORY=/usr/share/words

usage() {

  printf "%s\n" "Usage: $PROGNAME [-h|--help]"

  printf "%s\n" "$PROGNAME regex +char..."

}

help_message() {

cat <<_EOF_

$PROGNAME - Wordle 助手

$(usage)

选项:

-h, --help 显示此帮助信息并退出。

参数:

第一个参数必须是五个字符的正则表达式，至少为 '......'，代表答案中五个未知字符。其后是零或多个已知在答案中存在或缺失的字符。这些字符表示为 +char（已知位置的字母）或 -char（已知不在答案中的字母）。

示例：

$PROGNAME a....o -v

这意味着我们知道答案以第一个位置的'a'开头，并且包含 'o' 但不包含 'v'。

EOF_

return

}

add_plus() { # 添加字母

local char="$1"

echo " " | grep "$char"

return

}
```
