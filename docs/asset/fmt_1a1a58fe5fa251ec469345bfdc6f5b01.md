
# Windows 安全模型

Windows 在工作站环境或域环境中管理安全机制的方式是完全相同的。区别在于匹配名称和密码的是哪个账户数据库。对于非域成员，账户数据库位于本地机器上，并存储在注册表中。如果该机器是域的成员，则账户数据库要么在 NT 4.0 域控制器上（在相应机器的注册表中），要么在 Windows 2000 和 Windows NT 的活动目录中。在所有情况下，一旦验证了名称和密码，就会从账户数据库（本地注册表、NT 4.0 域控制器的注册表或 Windows 2000/Windows NT 中的活动目录）构建安全令牌。

非域机器的登录机制也是不同的。如果 Windows NT 4.0、Windows XP 或 Windows 2000 机器不是域成员，则机制是使用存储在注册表中的哈希密码进行密码验证。如果该机器是 NT 4.0 域成员，则机制采用相同的算法，但验证在域控制器处执行。在这种情况下，明文或加密密码都不会在网络上传输。哈希密码用于加密服务器发送的随机数。加密后的随机数通过网络发送，服务器使用共享密钥（哈希密码）对客户端发送的随机数执行相同的加密操作。如果客户端和服务器可以使用随机数和共享密钥得出相同的加密随机数，那么客户端必须是其所声称的身份。

对于 Windows 2000 域，机制是 Kerberos。Kerberos 票据授予服务与公共实现兼容。Windows NT 4.0 和 Windows 2000 使用 LAN Manager 机制，因为 Windows NT 4.0 对 Kerberos 一无所知。一旦登录，用户就拥有一个安全令牌。它用于 Windows 中所有需要 ACL 或权限的访问。对于 FAT 文件（不存在 ACL 概念），FAT 文件本身是文件的唯一守护者。对于此类访问，SID 是无关的。人们倾向于使用 NTFS 系统，因为它是为使用 Windows 安全模型而设计的。SID 标识安全主体。人、组和机器都是安全主体。Windows 中的组是 SID 的集合。组非常复杂，因为有许多不同类型的组：

- **本地组** 定义了一个只可以出现在本地计算机上的 SID。
- **全局组** 定义了一个可以跨多个域的 SID。
- **域本地组** 定义了一个只出现在特定域的 SID。
- **通用组** 定义了一个可以出现在森林中任何位置的 SID。
- **分配组** 定义了一个用于电子邮件目的的组。

ACL 中可以包含三种类型的访问控制项：

- **允许访问项** 包含一个单一 SID 和访问掩码，指定允许的操作。
- **拒绝访问项** 包含一个单一 SID 和访问掩码，指定拒绝的操作。
- **系统审计项** 包含一个可选的 SID 和访问掩码。如果 SID 匹配或与项中的 SID 匹配，且访问匹配访问掩码，则生成审计消息。

Windows NT、Windows XP 和 Windows 2000 完全支持安全审计。结果写入安全日志，可以通过事件查看器查看。

# Linux 安全模型

类似于 Windows NT 4.0 和 Windows 2000；Linux 的用户 ID 和组 ID 是复用的。用户经过与 Windows 相同的登录步骤。如果未启用密码，用户名和密码将存储在 `/etc/passwd` 文件中。如果启用了密码，密码从全局可读的 `/etc/passwd` 文件中移除，并存储在 `/etc/shadow` 文件中，该文件只有超级用户账户可以读取。Linux 中没有权限或特权的概念。

Linux 的授权模型比 Windows 简单得多。Linux 基于 UNIX 安全模型，并且几乎完全绑定于文件系统。在 Linux 中，每个受保护的对象（文件或目录）都关联有三个字段。这三个字段分别对应所有者、组和世界。每个字段包含关于文件的三位信息：读、写和执行。访问权限根据这三个字段授予。对于每个文件，所有者有一个访问字段，组有一个访问字段，世界也有一个访问字段。从“世界”开始，如果“世界”具有读权限，则任何人都可以读取该文件；如果“世界”具有写权限，任何人都可以写入该文件。“组”的情况也是如此。如果访问文件的程序组与文件的组匹配，且请求的访问（读、写或执行）被文件允许，则授予访问。所有者也一样，如果执行程序的所有者与文件所有者匹配，且请求的访问被允许，则授予访问。

Linux 模型没有访问控制列表的概念，不支持通用的拒绝访问功能。有一个名为“Extended Attributes and Access Control Lists for Linux”的开源项目，可以在 http://acl.bestbits.at 找到。

我们尚未下载并安装该包。

Linux 中的权限通过 `chmod` 命令更改，并可以使用桌面文件管理器或 `ls` 命令进行显示。图 1-2 显示了 `chmod` 命令对文件的影响。

Linux 拥有一种定义默认权限的机制。当创建一个文件时，创建程序会指定访问掩码的 9 位（所有者、组和世界各 3 位）。操作系统将根据 9 位 `umask` 变量中的位修改请求的位。`umask` 中的每一位都会强制将文件中存储的实际访问掩码置零。实际上，`umask` 值与请求的访问掩码之间执行异或运算，产生最终的访问掩码。`umask` 变量可以为登录会话设置，通常情况下红帽 Linux 系统的默认 `umask` 值为 022（八进制 022）。提到这 9 位，.022 看起来像 000100010。在实际权限方面，`umask` 看起来像 `r-x r-- r--`（位之间是异或关系）。因此，文件的组内其他成员和世界可读可执行，但只有所有者可以写入。`umask` 可以 `chmod` 命令设置，也可以在程序中使用 `umask` 系统调用设置。

## DNS

Elsolutions 必须始终保持其 DNS 信息是最新的。此外，管理员必须始终了解网络上的主机。如果入侵者附接到网络，它可能缺少 DNS 条目。在服务允许的情况下，Elsolutions 将配置服务，不接受来自没有有效 DNS 条目的外部主机的连接。

## NFS 和 Samba 共享

网络文件系统 和共享 Samba 目录自然会带来安全风险。远程超级用户管理员可以访问导出的或共享的用户文件。教训是，用户应仅在需要时导出目录。Elsolutions 的人员不会远程导出整个根目录树。`/etc/exports` 配置应设置 NFS 具有尽可能严格的访问权限。

## 主机安全

让我们讨论物理访问、本地软件系统访问、权限、密码、文件系统安全、inetd 服务、tcp wrappers 和系统备份。

### 物理安全

物理安全是实现主机级安全的第一层防线。一种假设的极端情况是，计算机被锁在一个安全房间内，所有人无法触及。在主机安全级别，它将和房间一样安全，但完全没用处。另一个极端是，一台放在公共人行道上无人看的计算机。

服务器机器，无论是 Windows 服务器还是 Linux 服务器，都应该放在受控访问的房间内。交换机、集线器和电缆间应放在具有类似访问控制的锁定房间内。除了直接参与物理布线和机器维护的技术人员和管理员外，任何人都不应该进入这些房间。软件和服务管理将通常在网络安全涵盖的条件下通过网络进行。

### 本地机器访问

Elsolutions 的机器用户在保护其系统逻辑访问时应采取合理的预防措施。当机器无人看管时，应锁定用户界面。对于 Linux GUI 桌面，这意味着使用 `xlock`。该程序会锁定 X 服务器，直到用户在本地键盘上输入密码为止。应该设置一个合理的锁定超时时间（例如五分钟），当键盘无人看管状态达到该时间时，UI 将被锁定。Windows 2000 桌面和服务器应该设置屏幕密码，并配有类似的合理超时时间。

Linux 和 Windows 本地服务器管理员在完成工作后应该注销，即使只离开几分钟。

### 密码

Elsolutions 需要实施一套密码规则，使得每个密码可以在不写下的情况下被记住，但又容易破解。Linux 提供了一种名为可插即身份验证模块 的机制，允许管理员动态指定身份验证方法。Linux 在历史上将密码存储在 `shadow` 文件中。这会暴露于字典攻击。

`/etc/passwd` 文件包含账户 ID。`/etc/passwd` 文件是公开可读的。此标志可以由 root 设置或重置。不可变位是系统。

### 文件系统安全

文件权限是保护 Elsolutions 数据的重要因素。尽可能将文件系统挂载为只读是一个好主意。例如，DMZ 中的匿名 FTP 分发版应该是只读的。Linux 管理员应该利用 Linux ext2 文件系统。它的权限包括一个不可变位。这使得文件变为不可变，即使是 root 也是如此。可以使用 `chattr +i` 由 root 设置或重置。

### 服务安全

管理员忘记关闭的不必要的服务将不可避免地损害服务器。Elsolutions 必须列出每台服务器运行的服务列表。其余服务应在安装时被剔除。

Linux 守护进程 是一个提供许多网络服务的超级服务器。它在这些服务使用的端口上监听请求。当请求被识别时，它会启动相应的服务来处理请求。这种范式对于在不使用时将守护进程留在系统之外以节省资源非常有用。inetd 提供了一个共同的监听点，使用一组可以分摊到各个服务中的公共资源，而不是让服务重复监听逻辑。`/etc/inetd.conf` 文件用于在 Linux 中配置 inetd 服务。MMC 插入程序用于配置 Windows 中的所有服务。它可以在开始菜单树中找到，也可以从 cmd 命令行启动：

```
services.msc
```

Linux、Windows XP 和 Windows 2000 的默认服务可能提供了机器不需要的服务。因此，管理员应该移除任何服务器（无论是 Linux 还是 Windows 服务器）不必要的服务。在 inetd 下运行高需求服务是不高效的，因为守护进程会消耗大量的 CPU 周期来启动和重启服务。如果服务的使用率很高，则应该将其从 `inetd.conf` 文件移动到所需的 `init` 级别中。

### TCP Wrappers

如果你检查 Linux 的 `/etc/inetd.conf`，你会发现每个服务都是通过另一个名为 `tcp daemon` 或 `tcpd` 的中间人启动的。这就是 tcp wrapper 守护。它通过以下功能提供了增强的安全：

- 客户端主机名和地址验证，以防止 IP 欺骗——即客户端伪装成其他主机。
- 每个请求信息的日志记录。
- 使用模式过滤器进行基于级访问控制，以拒绝或允许访问。

Microsoft Windows 2000 和 Windows XP 具有相同的能力。该功能可以通过 GUI 面板或 Windows 管理接口 管理。`linuxconf` 服务没有被 `tcpd` 包裹，因为它在 `tcpd` 环境中会发生故障。允许/拒绝功能意味着我们可以通过拒绝来自非路由 `10.0.0.0/subnet` 子网主机的访问，来锁定 Elsolutions 内部的 Linux 和 Windows 服务。日志功能意味着管理员可以发现异常情况。地址验证可以防止（例如）不满的员工伪装他人，从而获得其权限并访问其数据。

### 备份

合理的备份策略是防御错误、混乱、中间故障、意外、破坏者以及可能的法外者的主要手段。Elsolutions 大多数活动数据（包括属于桌面用户的数据）存储在 Linux 服务器上。设置一个 Linux `cron` 任务来定期执行 `tar` 命令以保存重要数据是简单的，但我们必须确保将其保存在与其存储地不同的介质上。将崩溃磁盘上的目录备份到同一块崩溃磁盘的目录并不是真正的备份。
