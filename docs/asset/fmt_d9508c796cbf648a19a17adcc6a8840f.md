我们首先检查交换设备上是否设置了 `SWP_FS_OPS`，这表示交换操作应该通过文件系统进行。在这种情况下，我们将操作推迟到 `swap_readpage_fs()`。为了简单起见，我们不再详细检查此部分。

如果交换设备通过 `SWP_SYNCHRONOUS_IO` 标志顺序访问数据的效率更高，那么我们将直接通过 `dev_read_page()` 读取页面。

然后，我们最终会生成一个 `struct bio` 对象（详细信息请参阅第 9 章第 9.10.5 节），并通过 `submit_bio()` 将提交给块设备。

如果指定了 `synchronous` 参数，我们会在 `blk_io_schedule()` 等待 IO 完成期间将页面置于不可中断睡眠状态。总的来说，该函数最终调用块 I/O 层从磁盘读取数据，异步进行（除非是同步）。

当执行由 `do_swap_page()` 触发的预读时，会调用 `swap_readahead` 函数。参见列表 12-41。

### 列表 12-41: mm/swap.c: swapin_readahead()

```c
/**
 * swapin_readahead - 换入页面，希望我们很快就会需要它们
 * @entry: 此内存的交换条目
 * @gfp_mask: 内存分配标志
 * @vm: 缺页信息
 *
 * 队列交换后，返回对应 entry 和 addr 的 struct page。
 *
 * 它是交换预读的主入口点。根据配置，它将基于簇（即基于物理磁盘）
 * 或基于 VMA（即基于缺页地址的虚拟地址）进行块预读。
 */
struct page *swapin_readahead(swap_entry_t entry, gfp_t gfp_mask,
                              struct vm_fault *vmf)

        swap_use_vma_readahead(entry, gfp_mask, vmf) :
        swap_cluster_readahead(entry, gfp_mask, vmf);
}
```

### 列表 12-42: mm/swap.c: read_swap_cache_async()

```c
/**
 * 在物理内存中定位交换页面，预留交换缓存空间
 * 并在未缓存时从磁盘读取。
 *
 * 失败意味着页面分配失败或
 * 交换条目不再使用。
 */
struct page *read_swap_cache_async(swap_entry_t entry, gfp_t gfp_mask,
            struct vm_area_struct *vma,
            unsigned long addr, bool poll,
            struct page **page)
{
            bool page_allocated;
            struct swap_info_struct *si;
            page_allocated = false;
            for (;;) {
                int err;
                /*
                * 首先检查交换缓存。由于
                * lookup_get() 失败，
                */
                si = get_swap_device(entry);
                if (!si)
                    return NULL;

                page = find_get_page(address_space(entry),
                            swap_offset(entry));
                if (page)
                    return page;

                /*
                * 交换条目可能在我们观察到后
                * 已被释放。
                */
                err = swap_cache_prepare(entry);
                if (err)
                    break;

                put_page(page);
                if (err != -EEXIST)
                    return NULL;

                /*
                * 我们可能与 delete_from_swap_cache() 竞争，
                * 并遇到一个尚未清除 SWAP_HAS_CACHE 的
                * 交换条目。或者与
                * _read_swap_cache_async(entry) 竞争，
                * 它设置了 SWAP_HAS_CACHE，
                * 但尚未将其页面添加到交换缓存。
                */
                schedule_timeout_uninterruptible(1);

                /*
                * 交换条目是我们要换入的。在
                * 标记 swapmap 为 SW_HAS_CACHE 之前准备新页面。
                */
                _SetPageLocked(page);
                _SetPageSwapBacked(page);

                * 如果 Xarray 节点分配失败则可能失败 (ENOMEM)。
                */
                if (add_to_swap_cache(page, entry, gfp_mask & GFP_RECLAIM_MASK, shadow))
                    goto fail_unlock;

                * 调用者将对锁定页面进行读取
                lru_cache_add(page);
                page_allocated = true;
                return page;

            fail_unlock:
                put_swap_page(page, entry);
                unlock_page(page);
                put_page(page);
                return NULL;
            }
}
```

`read_swap_cache_async()` 函数封装了 `__read_swap_cache_async()`，后者在列表 12-40 中讨论。它在交换缓存中将数据从磁盘换入。如果交换缓存禁用，则 `swapoff` 会中止。

在准备此条目时，我们调用了交换文件特定的逻辑，通过 `swapcache_prepare()` 将该条目添加到交换缓存中。我们不会详细探讨这一细节，交换文件的具体实现超出了本文范围（那更接近于文件系统代码，而非内存管理），但值得注意的是，这可能会导致错误，特别是当交换条目在底层被释放时。

如果没有发生错误，我们就跳出循环。如果确实发生了错误，我们会通过减少其引用计数来释放该页面，然后确定错误是否为该条目在此期间被释放（由 `-EEXIST` 表示），如果不是则返回 `NULL`，否则等待一段时间，循环并重试。

循环结束后，我们现在准备好准备文件并将其添加到交换缓存中。我们将其标记为锁定和交换支持（它将保持锁定状态，直到在其他地方从磁盘读入），然后通过 `add_swap()` 将其添加到交换缓存（参见列表 12-22）。

如果此操作失败，我们将释放它并返回错误，通过 `lru_cache_add()` 将其添加到适当的 LRU 列表中（参见第 11 章第 11.2 节更多关于 LRU 列表的信息），该函数最终会调用 `folio_add_lru()`（参见第 11 章列表 11-88）。

## 12.3.4 交换簇预读 (Swap Cluster Readahead)

交换预读是一种简单的预读方法，它使用 `swap_readahead_hits` 原子静态值来跟踪在从交换缓存查找时，页面遇到 `PG_readahead` 标记的次数（该标记由预读逻辑在逻辑确定加载另一批页面是高效的节点，在读入若干页面后设置）。

该值随后被用于确定每批次要预读多少页面。

簇预读实现在 `swap_cluster_readahead()` 中，我们在列表 ?? 中检查了它（省略了超出范围的块插头逻辑）。

```c
/**
 * swap_cluster_readahead - 交换页面，希望我们很快需要它们
 * @entry: 此内存的交换条目
 * @gfp_mask: 内存分配标志
 * @vmf: 异常信息
 *
 * 在队列交换入后，返回 entry 和 addr 的 struct page。
 *
 * 基础交换预读代码。我们简单地在交换区域读取一个对齐的
 * (1 << page_cluster) 个条目的块。选择这种方法是因为
 * 它并没有消耗我们的任何时间。我们还把
 * “原始”请求与预读请求一起队列……
 *
 * 此处已扩展到使用触发预读的 mm 的 NUMA 策略。
 *
 * 如果 vmf->vma 不为 NULL，调用者必须持有读锁 mmap_lock.
 */
struct page *swap_cluster_readahead(swp_entry_t entry, gfp_t gfp_mask,
                                    struct vm_fault *vmf)
{
    struct page *page;
    unsigned long entry_offset = swap_offset(entry);
    unsigned long offset = entry_offset;
    unsigned long start_offset, end_offset;
    unsigned long mask;
    struct swap_info_struct *si = swp_swap_info(entry);

    bool do_page = true, page_allocated;
    struct vm_area_struct *vma = vmf->vma;
    unsigned long addr = vmf->address;

    mask = swapin_nr_pages(offset) - 1;
    if (!mask)
        goto skip;

    do_page = false;
    /* 在 offset 周围读取 page_cluster 大小且对齐的簇。 */
    start_offset = offset & ~mask;
    end_offset = offset | mask;
    if (!start_offset) /* 第一页是交换头。 */
        start_offset++;
    if (end_offset >= si->max - 1)
        end_offset = si->max;

    for (offset = start_offset; offset < end_offset; offset++) {
        /* 好的，现在执行异步预读 */
        page = __read_swap_cache_async(
            swp_entry(entry), offset),
            gfp_mask, vma, addr, &page_allocated);
        continue;
        if (page_allocated) {
            swap_readpage(page, false, &slug),
            if (offset != entry_offset) {
                SetPageReadahead(page);
                count_event(SWAP_RA);
            }
        }
    }
    put_page(page);
}

lru_add_drain();      /* 将任何新页面推入 LRU */
skip:
read_swap_cache(entry, gfp_map, addr, do_page, NULL);
}
```
