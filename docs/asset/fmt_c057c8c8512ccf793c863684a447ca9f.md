## 本指南是什么，以及它不是什么

本指南并不是一份通用的安全文档。本指南专门关于如何保护 Linux 操作系统免受通用和特定威胁的攻击。如果你需要对安全的概概述，请去 www.ora.com 购买《Practical Unix and Internet Security》（《实用 Unix 与网络安全》）。

O'Reilly 及其关联公司是我最喜欢的计算机书籍出版社之一（他们还制作很漂亮的 T 恤），附录列出了我推荐的其他各种计算机书籍。

## 如何确定需要保护的内容以及如何保护

你是否正在保护数据（专有的、机密的或其他）？你是否正尝试保持某些服务（你的邮件服务器、Web 服务器等）？你是否只想保护物理硬件免受损坏？你正在防止什么？恶意破坏（如 8 Sun Enterprise 10000 的损坏）、删除（调查数据、你妈的食谱集）、篡改（带有医疗记录的物理介质、银行）、泄露（涉及诉讼的机密内部通信、应对未婚母亲的计划）。“坏”事件发生的概率有多大？网络探测（我每天都会遇到）、物理入侵（尚未发生在我身上）、社会工程学（“你好，我是 IT 部门的 Bob，我需要你的密码以便我们重置……”）。

你需要列出所有包含数据、提供服务、构成你公司基础设施等的资源（服务器、数据和其他组件）。以下是一个简短列表：

- 物理服务器设备
- 邮件服务器及服务
- DNS 服务器及服务
- WWW 服务器及服务
- 文件服务器及服务
- 公司内部数据，如会计记录和人力资源数据
- 你的网络基础设施（线缆、集线器、交换机、路由器等）
- 你的电话系统（PBX、语音信箱等）

你需要确定你想要防止什么情况的发生：

- 物理损坏（烟雾、水、食物等）
- 数据的删除/修改（会计记录、你 WWW 网站的篡改等）
- 数据泄露（会计数据等）
- 服务连续性（保持邮件/网页/文件服务器正常运行）
- 防止他人非法/不当使用你的服务（邮件垃圾邮件等）

最后，事件发生的概率有多大？

- 网络扫描——每天一次是稳妥的预期
- 社会工程学——各异，通常最脆弱的人往往是目标人物
- 物理入侵——视情况而定，通常罕见，但一个拿着电线钳的敌对员工在电信机房可以造成巨大破坏
- 员工将你的数据卖给竞争对手——这种情况会发生
- 竞争对手雇佣技术人员渗透你的网络——如果这种情况发生，没人会谈论它

一旦你明确了内容，就可以采取相应的保护措施。

心情不好时电话响起来让人心烦。除非有强迫需求，否则请将使用交互式 shell（`bash`, `pine`, `lynx` 等）的用户数量保持在极少数。将服务进行分段（设置邮件服务器、Web 服务器等），以最大限度地减少单点故障。通常情况下，一个配置得当的服务器会运行而不需要维护（我在客户那里有一台邮件服务器已经运行了 2 年，总共维护时间仅约 10 小时）。任何升级都应该经过仔细计划并在测试环境中执行。关于服务器需要记住的几个点点：

- 1. 限制对服务器的物理访问。
- 2. 遵循最小权限原则，他们破坏的范围会更小。
- 3. **务必备份！**
- 4. 定期检查服务器的更改（端口、软件等），自动化工具对此非常有帮助。
- 5. 软件更改应该经过仔细计划/测试，因为它们可能会产生不利影响（例如内核 2.2.x 不再使用 `ipfwadm`，如果你忘记安装 `ipchains`，那将不是很尴尬吗）。

权限最小化意味着赋予用户（以及管理员）完成工作所需的最少访问权限。赋予用户工作站“root”权限，如果所有用户都精通 Linux 且值得信赖，这样做是合理的，但他们通常并非如此（在这方面都不如此）。即使他们确实如此，这也是个坏主意，因为他们很可能会安装某些损坏/不安全的软件等。如果用户访问的需求仅是关闭/重启工作站，那么这就是他们应该被授予的访问权限量。你绝不会将财务文件留在具有“世界可读”权限的服务器上供会计人员查看，这一概念一直延伸到整个网络。限制访问还可能在账户被渗透时限制损害（你读过人们贴在显示器上的贴签上写的内容吗？）。

### 物理启动安全

#### 物理访问

这部分在《实战 Unix 与 网络安全》一书中有深入介绍，但我将简要概述一下基础知识。关闭你的主会计服务器，重新开启，从特制的软盘启动，并将 `payroll.db` 传输到异地的 `ftp` 站点。除非你的会计服务器被锁定，以防止恶意用户（或大楼保洁人员、快递员等）这样做！我听听过保洁人员为了插上清洁设备而拔掉服务器插头的恐怖故事。我曾见过有人点击电源插线的小开关并重启他们的服务器（尽管我从未这样做过）。将你的服务器锁在安全房间内（甚至是封闭的柜子内）是有意义的。将服务器放在架高的表面上也是一个非常好的主意，以防止洪水导致的损坏（无论是屋顶漏水还是洒了一桶冰沙）。

### 计算机 BIOS

#### LILO

```
delay=x
控制 LILO 在启动到默认选择之前等待用户输入的时间（以 1/10 秒为单位）。C2 安全要求之一是将此间隔时间设置为 0（显然，双系统启动意味着大部分出了问题）。除非系统要双启动其他内容，否则将其设置为 0 是个好主意。
```

强制用户输入内容。`LILO` 不会自动启动系统。这在服务器上可能有用，可以作为一种在没有人工值守的情况下禁用重启的方法，但通常如果黑客有重启系统的能力，他们可以使用新的启动选项重写 MBR。如果你添加了超时选项，系统将在超时后继续启动。

`restricted` 意味着如果向引导程序传递了启动选项（如 "`linux single`"），则需要使用密码。确保在每个镜像上都使用这一个（否则服务器启动时需要密码，如果你从未计划重启它，这没问题）。

`password=XXXXX` 需要输入密码，与 `restricted` 配合使用，同时确保 `lilo.conf` 不再可读，否则任何用户都能读取密码。

这里是我其中一台服务器的 `lilo-conf` 示例（密码当然已经更改）。

```
boot=/dev/hda
map=/boot/map
install=/boot/boot.b
prompt
timeout=100
default=linux
image=/boot/vmlinuz-2.2.5
label=linux
root=/dev/hda1
read-only
restricted
password=some_password
```

这使用 `/boot/vmlinuz-2.2.5` 内核启动系统，该内核存储在系统第一个 IDE 硬盘的 MBR 上。`prompt` 关键字通常会停止重启，但由于在系统中已设置，它可以无问题地启动 "`linux`" ，但如果你想进入 "`linux single`" ，你有 10 秒时间输入它，此时系统会提示你输入密码（"`some_password`"）。结合 BIOS 设置为仅启动保护模式，你就有了一个相当安全的系统。

Linux（根据 Stallman 的说法，如果你指的是复杂的发行版，应称为 GNU/Linux）只是操作系统的核心。内核处理硬盘访问、安全机制、网络以及几乎一切事务。此外，我们还有诸如内核 2.2.x 不再使用 `ipfwadm` 等问题。关于服务器需要记住的几个重要点点：
