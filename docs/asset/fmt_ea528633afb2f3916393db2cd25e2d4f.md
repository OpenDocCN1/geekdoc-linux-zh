
## 描述

使用 `nismdir` 命令在现有域内创建子目录。在没有选项的情况下，该命令创建一个具有相同主服务器和副本的目录。

访问权限。`dirname` 是要创建目录的 NIS+ 名称。

注意 — 服务 NIS+ 目录的主机必须是该目录上方目录的客户端。根 NIS+ 服务器是例外，它们是客户端也是服务器。

当执行命令时的主机默认域与默认域不同时，作为参数提供的 `-s` 或 `-m` 选项必须是完全限定。

## 选项

- `-D defaults`: 指定创建目录时使用的不同默认值。默认字符串是由冒号分隔的令牌序列。这些令牌代表用于通用对象属性的默认值。所有合法的令牌下文所示。
- `ttl=time`: 设置由此命令创建对象的默认生存时间。指定时间值应符合 `nichttl(1)` 命令定义的格式。默认值为 12 小时。
- `owner=ownername`: 指定 NIS+ 所有者 `ownername` 应拥有创建的对象。该值的默认值是执行命令的执行者。
- `group=groupname`: 指定组 `groupname` 应为创建对象的组所有者。默认值为空。
- `access=rights`: 指定要授予给定对象的访问权限集。按 `nichmod(1)` 命令定义的格式指定权限值。默认值是 `----rcmdr----`。
- `-m hostname`: 如果目录 `dirname` 不存在，则创建一个以 `hostname` 为主服务器的非副本目录。如果目录名 `dirname` 已存在，则将名为 `hostname` 的主机成为其主服务器。
- `-s hostname`: 指定主机是现有目录 `dirname` 的副本。

### 示例

以下示例为 `bar.foo.com.` 目录添加一个副本服务器。
`castle@ nismkdir -s replica.foo.com. bar.foo.com.`

## 环境变量

`NIS_DEFAULTS`

指定一个字符串来覆盖 NIS+ 标准默认值。如果你使用 `-D` 选项，则这些值将同时覆盖 `NIS_DEFAULTS` 变量和标准默认值。

如果设置了此变量且 NIS+ 目录不是完全限定的，则搜索每个指定的目录，直到找到该目录为止（参见 `nismdefaults(1)`）。

## 退出状态

- `0` 成功。
- `1` 失败。

# nispasswd — 修改 NIS+ 密码信息

### 概要

```
/usr/bin/nispasswd [-ghs] [-D domainname][username]

/usr/bin/nispasswd -a

/usr/bin/nispasswd -D domainname [-d [username]

/usr/bin/nispasswd [-l][-f][-n min][-x max] [-w warn][-D domainname]

username
```

## 描述

注意 — 不建议使用 `nispassd`，因为它现在只是 `passwd(1)` 命令的链接，你应该改用 `passwd(1)`。
使用 `passwd(1)` 并配合 `-r` 选项可以相同的结果，并且在所有可用的服务中保持一致。

登录程序、文件访问程序（例如 `ls -l`）以及需要密码的网络程序（如 `login(1)` 和 `ftp(1)`）使用标准的 `getpnam(3C)` 和 `getspnam(3C)` 接口来获取密码信息。`nispassd` 仅当 `/etc/nsswitch.conf` 文件包含 `passwd` 时才会修改密码信息。

使用 `nispassd` 命令修改密码、注释（finger）字段 (`-g` 选项) 或登录 shell (`-s` 选项)，这些操作默认与 NIS+ 表格中的用户名关联。此外，可以使用该命令查看或修改指定用户的密码年龄信息。

`nispassd` 使用 RPC 与 NIS+ 服务器通信，并且不在通信媒介上发送明文密码。`nispassd` 不读取或修改存储在 `/etc/passwd` 和 `/etc/shadow` 文件中的本地密码信息。

当用于更改密码时，`nispassd` 会提示特权用户输入旧密码。然后会提示两次新密码以防止错误。当你输入旧密码时，`nispassd` 会检查年龄是否已“足够”。如果年龄不足，`nispassd` 将终止；参见 `getspan(3)`。

旧密码也用于确保新密码与旧密码至少有三个字符的差异。`nispassd` 会提示非特权用户密码。如果失败，它会给用户一次机会。假设年龄足够，将检查确保新密码符合下面描述的构造要求。当你第二次输入新密码时，会对两个新密码的副本进行比较。如果它们不同，则重复提示新密码的循环。新密码将用于重新加密用户的密钥并成为密码。

密码必须满足以下要求：

- 每个密码必须至少有六个字符。
- 每个密码必须包含至少两个字母和至少一个数字或特殊字符。在这种情况下，“字母”指的是所有大写或小写字母。
- 每个密码必须与登录用户名及其任何反转或循环位不同。为了比较，大写字母与其对应的小写字母是相同的。
- 新密码必须与旧密码至少有三个字符的差异。

拥有 NIS+ 表格的网络管理员在调用 `nispassd` 之前建立凭据，可以更改任何密码属性。`nispassd` 不会提示特权用户旧密码，并强制遵守密码年龄和构造要求。

任何用户可以使用 `-d` 选项显示其登录名的属性。显示格式为：

```
username status mm/dd/yy min warn
```

或者，如果没有密码年龄信息：

```
username status
```

其中

| username | 登录 ID。 |
| --- | --- |
| status | 密码状态：PS 表示密码存在或锁定，LK 表示锁定，NP 表示无密码。 |
| mm/dd/yy | 用户最后更改密码的日期。（注意，所有密码年龄日期均格格林治标准时间确定，因此在其他时区可能会相一天。） |
| min | 用户更改密码之间的最小天数。 |
| max | 用户密码有效的最大天数。 |
| warn | 密码过期前警告用户的天数。 |

## 选项

- `a` 显示所有条目的密码属性。
- `d` 显示登录名的密码属性。
- `D` NIS+ 表中的域名。
- `f` 尝试强制删除，如果由于原因失败，则尝试 `nischmod(1)` 操作并重试删除。如果命令失败，则静默失败。
- `g` 修改注释（finger）字段。
- `h` 修改主目录。
- `l` 锁定密码条目。
- `n` 设置更改密码之间的最小天数。
- `max` 设置密码有效的最大天数。
- `s` 修改登录 shell。
- `w` 设置警告字段。
- `x` 设置密码有效的最大天数。

## 退出状态

- `0` 成功。
- `1` 权限拒绝。
- `2` 选项组合无效。
- `3` 意外失败。NIS+ 表格未更改。
- `4` NIS+ 表缺失。
- `5` NIS+ 忙。请稍后再试。
- `6` 选项参数无效。
- `7` 年龄已禁用。

# nisrm — 从命名空间中删除 NIS+ 对象

### 概要

```
/usr/bin/nisrm [-if] name ...
```

## 描述

使用 `nisrm` 命令从 NIS+ 命名空间删除名为 `name` 的 NIS+ 对象。如果 NIS+ 主服务器未运行，此命令失败。

## 选项

- `i` 像系统 `rm(1)` 命令一样，在删除对象之前交互式确认。如果指定的名称不是完全限定名称，则强制开启此选项。此选项防止删除意外的对象。

## 示例

以下示例从命名空间删除 `foo`、`bar` 和 `baz` 对象。

```
castle$ nisrm foo bar baz
```
