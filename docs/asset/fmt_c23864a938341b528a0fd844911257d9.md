# sccs-admin, admin — 创建和管理 SCCS 历史文件

### 概要

```
/usr/ccs/bin/admin [-bhnz] [-a username | groupid]... [-d flag...] [-e username | groupid]... [-f flag value]... [-i [filename]] [-m mr-list] [-r release] [-t [description-file]] [-y[comment]] ns.filename...
```

使用 `SCCS admin` 命令创建或修改 SCCS 历史文件的标志和其他参数。SCCS 历史文件以 `s.` 前缀开头，被称为 `s.` 文件或历史文件。如果命名的 `s.` 文件不存在，则创建它。其参数将根据你指定的选项进行初始化或修改。未指定的参数在初始化文件时会赋予默认值；否则，它们保持不变。

如果你用目录名代替 `s.filename` 参数，则 `admin` 命令适用于该目录下的所有 `s.` 文件。不可读的文件会产生错误。使用横杠 `-` 作为 `s.filename` 参数表示从标准输入中读取文件名，每行一个 `s.` 文件。

## 选项

`-a username | groupid`

将用户名或数值组 ID 添加到可以提交或检出 delta 的用户列表中。如果列表为空，则允许任何用户提交或检出 delta。

`-b`

强制对二进制数据进行编码。包含 ASCII 空字符或其他控制字符，或不以换行符结束的文件将被识别为二进制数据文件。以编码的形式将此类文件的内容存储在历史文件中。有关编码的详情，请参见 `uuencode(1)`。此选项通常与 `-i` 配合使用，以强制 `admin` 对未识别为包含二进制数据的初始版本进行编码。

`-d flag`

从 SCCS 文件中删除指定的 `flag`。你可以仅对现有的 `.s` 文件指定 `-d` 选项。请参见 `-f` 获取可识别的标志列表。

`-e username | groupid`

从允许创建增量（deltas）的用户列表中删除用户名或组 ID ID。

`-f flag [value]`

将指定的 `flag` 设置为指定的（可选）`value`。可识别的后续标志包括：

- `b` 启用分支增量。当设置了 `b` 时，你将使用 SCCS 命令的 `-b` 选项创建分支（参见 `sccs-get(1)`）。
- `c ceil` 为可以检出的版本设置上限。`ceil` 是一个小于或等于 9999 的数字。如果你没有设置 `c`，上限为 9999。
- `f floor` 为可以检出的版本设置下限。`floor` 是一个大于 0 但小于 9999 的数字。如果你没有设置 `f`，下限为 1。
- `d sid` SCCS 命令将使用的默认增量号 (`sid`)。
- `i` 将 SCCS `get` 或 `delta` 命令发出的“无 ID 关键字 (ge6)”消息视为错误而非警告。
- `j` 允许并发更新。
- `la release[...]` 锁定指定的版本列表以防止创建增量。如果你使用 `a`，则锁定所有版本的增量。当对已锁定的版本应用时，SCCS `-e` 命令将失败。
- `n` 在跳过版本时创建空版本。这些空（null）增量用作分支增量的锚点。
- `q value` 在使用 SCCS `get` 命令检索只读版本时，提供一个值，使 `%Q` 关键字在检索时展开为该值。
- `m module` 为模块名提供一个值，使 `%M` 关键字向其展开。如果你没有指定 `m` 标志，分配的值是删除前缀 `s.` 的 SCCS 文件名。
- `t type` 为模块类型提供一个值，使 `%Y` 关键字向其展开。
- `v[program]` 为与新增量相关的修改请求 (MR) 编号指定验证程序。可选程序指定了 MR 编号有效性检查程序的名称。如果你在创建 SCCS 文件时设置了此标志，则必须同时使用 `-m` 选项，在这种情况下将检查 MR 列表。

`-h` 检查现有 `s` 文件的结构（参见 `sccs-file(4)`）并并将新计算的校验和与存储在类文件第一行的校验和进行比较。`-h` 抑制对文件的写入，从而消除任何其他选项的效果。

`-i[filename]` 从指定的文件初始化历史文件。此文本构成了初始增量或一组已提交的更改。如果你省略了 `filename`，则从标准输入获取初始文本。省略 `-i` 选项将创建一个空的 `s` 文件。使用 `-i`，你可以仅用文本初始化一个 `s` 文件。此选项隐含 `-n` 选项。

`-m[mr-list]` 在初始版本的注释字段中插入指定的修改请求 (MR) 编号。当在命令行上指定多个 MR 编号时，请将 `mr-list` 指定为带引号的空格分隔的列表。如果你没有设置 `v` 标志或 MR 验证失败，将产生警告。

`-n` 创建一个新的 SCCS 历史文件。

`-r release` 指定初始增量的版本。你可以将 `-r` 与 `-i` 使用。如果你省略此项，初始增量将插入到版本 1。初始增量的级别为 1；初始增量默认名为 `1.1`。

`-t[description-file]` 从描述文件中插入描述性文本。当你将 `-t` 与 `-n` 或 `-i` 用于初始化一个新的 `s` 文件时，必须提供描述文件。在修改现有文件的描述时，不带 `description-file` 的 `-t` 选项将移除任何描述性文本；带有 `description-file` 的 `-t` 选项将替换现有文本。

`-y[comment]` 在初始增量的 `Comments:` 字段中插入指定的注释。仅与 `-i` 或 `-n` 配合使用。如果你省略了 `-y` 选项，将插入一条默认注释行，记录历史文件创建的日期和时间。

`-z` 重新计算校验和并存储在 `s` 文件的第一行。注意：验证历史文件的内容非常重要（参见 `sccs-val(1)` 和 `sccs(1)` 中的 `print` 命令），因为对真正损坏的文件使用 `-z` 可能会导致错误失效。

## 退出状态

- `0` 成功完成。
- `1` 发生错误。

## 文件

- `s.*` 历史文件。
- `SCCS/s.*` SCCS 子目录下的历史文件。
- `z..*` 临时锁文件。

## sccs-comb, comb

### 概要

```
/usr/ccs/bin/comb [-os] [-c sid-list] [-p sid] s.filename ...
```

使用 SCCS `comb` 生成一个 shell 脚本（参见 `sh(1)`），你可以使用该脚本重构指定的 `s.files`。该脚本被写入到标准输出。

如果你使用目录名代替 `s.filename` 参数，`comb` 命令将适用于该目录下的所有 `s.` 文件。不可读的 `s.` 文件会产生错误；程序将继续处理下一个文件（如果有）。使用连字符 `-` 作为 `s.filename` 参数表示从标准输入读取读取的文件名，每行一个 `s.` 文件。

如果你未指定任何选项，`comb` 将仅保留最近的（叶节点）增量以及保留历史所需的最少祖先数量。

## 选项

`-c sid-list`

包含列出的增量列表。省略所有其他增量。

`sid-list` 是用逗号分隔的 SCCS 增量 ID (`sid`) 列表。要指定增量范围，请在列表中的两个 `sid` 之间使用连字符 `-` 分隔代替逗号。
