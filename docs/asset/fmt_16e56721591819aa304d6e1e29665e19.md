### 百比–MB 剩余空间与大文件系统

现在才是重点了！即使你的大多数文件系统都启用了大文件支持或者体积非常巨大，小型文件系统最终也会让你头恼。对于小型和大型文件系统的组合，我们需要结合使用百分比率和剩余空间 MB 技术。为了让这种组合生效，我们需要一种能够自动检测正确使用技术的方法，以便监控能够不同的方式工作。对于大文件系统，我们需要使用剩余空间 MB，而对于普通文件系统，我们使用百分比法。

我们需要定义一个允许剩余空间与百分比转换的触发器。触发器值会随环境而异，但本示例使用 1GB 作为从百分比率到剩余空间 MB 的切换点。当然，该值应该是 4–6GB，但我们需要考虑 `$EXCEPTIONS` 文件的格式。异常处理的选项是一个合并文件，或者是两个独立的文件（一个用于百分比率，一个用于 MB 剩余）。显然的选择是一个合并文件。条目看起来应该是什么样？我们如何处理错误的条目类型以符合脚本正在寻找的特定测试类型？最好的处理方法是要求在异常文件的每个新条目后添加 `%` 或 `MB` 作为后缀。有了 `MB` 或 `%` 后缀，我们不仅可以覆盖触发级别，还可以覆盖测试方法！如果条目只有数字而没有后缀，则该异常条目将被忽略，并使用脚本的默认值。这种后缀方法最灵活，但也容易在异常文件中出错。对于这些错误，我们需要测试异常文件中的异常，以确保它们符合我们设定的标准。

创建这种更健壮脚本的最简单方法是提取之前脚本的大部分并将其转换为函数。我们只需插入 `function` 单词后跟一个函数名，并在括号内编码代码——例如 `function test_function (function_code )`。如果你更喜欢 C 类型的函数，可以使用这个示例 `test_function () (function_code )`。这两个函数唯一的区别在于一个使用 `function` 单词来定义函数，另一个只是在函数名后添加一组括号。当我们使用函数时，很容易建立一个可以调用函数的逻辑框架。先建立框架再填充中间总是很容易的。此脚本的逻辑代码类似于列表 5.11。

```bash
if [ $VAR1 -gt $VAR2 
```

我们现在将括号测试仅用于字符字符串，并对所有的数值比较使用这种方法：

```bash
if ( VAR1 == VAR2 )
```

这种方法的运算符是 `<`、`<=`、`==`、`!=`、`>=`。当我们进行这个小更改后，脚本变得更容易遵循，因为我们立即知道处理的是数值数据还是字符串，而不需要非常了解测试的数据。注意，我们在数值测试中没有用 `$`（美元符号）引用变量。省略 `$` 不是唯一的区别，但也容易在异常文件中出错。对于这些错误，我们需要测试异常文件中的异常，以确保它们符合我们设定的标准。
