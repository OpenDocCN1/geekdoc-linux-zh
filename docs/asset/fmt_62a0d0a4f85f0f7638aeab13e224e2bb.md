
登录并返回本地机器的 shell 来挂载文件系统。

在执行 `mount` 命令时也有额外的步骤需要执行。具体来说，通过 NFS 挂载文件系统需要指定 NFS 类型，并且你必须为文件系统所在的远程机器以及文件系统本身提供特定的路径。假设远程机器名为 barney，你执行命令：

```
mount -t nfs barney:/sports /news
```

将远程的 sports 文件系统挂载到本地挂载点 `/news`。远程文件系统的卸载方式与本地设备相同，使用以下命令：

```
umount /news
```

NFS 的实现取决于你所使用的 Unix 变体。FreeBSD、Linux 和类似的 Unix 变体使用此处描述的方法。其他变体的用户应查阅其文档。

## 备份

系统管理员的一个非常常见的任务是对计算机系统中所包含的数据进行备份。备份在发生磁盘故障或崩溃攻击等灾难性事件时保护数据。对于服务器或大型机等大型机器，备份数据至关重要，这些机器可能包含对组织运行至关重要的数据。

有很多方法可以进行备份。大型组织有时会使用专业编写的备份和恢复软件。较小的组织和个人系统可以使用常用工具。备份应定期进行，变化频繁的数据（例如数据库、`/home`）备份频率应高于长期内保持不变的数据（例如系统级配置）。

虽然很难描述一种适用于所有情况的程序，但以下步骤将为给定目录创建一个简单的压缩归档包：

1. 创建一个存储备份归档包的目录。该目录应该在自己的分区上，并且应该有足够的空间，因为归档包文件可能很大。在示例中，该目录名为 `/backup`。
2. 识别示例中要归档的目录，`/home`。
3. 使用 `tar` 命令和压缩工具（在此情况下为 `gzip`）创建一个放在 `/backup` 目录下的归档包文件，如下：
```
tar cvfz /backup/homedirs.tgz /home
```
归档包文件将名为 `homedirs.tgz`。
4. 在第二个介质上复制归档包文件。例如，如果归档包小于约 650 MB，你可以将其刻到 CD-ROM 上。较大的归档包可能需要更多空间的介质，例如磁带驱动器或独立机器的硬盘。如果可能，备份副本应存储在制作它们的其他建筑中。（例如，如果火灾毁了建筑，备份仍然可用。）

## 系统安全

无论你是在管理一个拥有数千台机器的大型网络，还是家中的 Linux 网络，都应该关注安全。新闻几乎每周都会带来关于安全泄露的新故事，从对他人网页的滑稽重新设计，到对竞争对手网络的技术性间谍，或是对另一个国家政府文件的窥探。安全是一门大生意，有数百家公司提供软件和咨询来使网络更安全。

虽然可以在安全上花费数百美元，但即使是最小的网络也可以建立一些习惯。安全既是一种心态，也像是一个程序或硬件。管理员时刻将安全记在心中，以做出更好的决定并运行更严密的网络。在这些时代，很少能找到一个完全不考虑安全的管理员。

### 物理安全

奇怪的是，当谈到网络安全时，物理安全有时会被忽视。虽然软件是一个非常有用的工具且在大多数安全情况下都有效，但物理安全是另一个关注点。如果有人闯入你的公寓并拿走你的电脑，那就是安全泄露。他们拿走了你的机器及其所有数据，以及他们拿走的任何通信硬件。这种盗窃对你造成的伤害可能与下载文件中的破解或病毒一样。

物理安全解决方案是常识。锁好门窗。购买房屋主险或租赁险，并用你的驾照号码标记机器。保留一份硬件清单，如果可能的话附上序列号和收据。如果你的财产被盗，这将帮助警察。如果你有一个倾向于开愚蠢玩笑的室友或朋友，想办法把机器锁好。即使在空闲卧室上装一个简单的旋锁可能也足以震慑那些为了“装好玩”而捣乱你网络的人。在工作中，如果你有很多机器，考虑准备一个独立的房间。

### 内部安全

连接到机器。请注意，在本书编写期间，像 `SSH` 这样的加密软件被禁止出口到美国和加拿大以外。如果你在其他国家，将需要寻找当地提供的加密软件来满足你的安全需求。通常情况下，请保持所有软件处于更新状态。一旦在任何程序中发现安全漏洞，消息就会迅速传遍互联网。请密切关注补丁和新发布版本。

定期读取你的日志文件。寻找异常的行为或模式，并尝试弄清楚它们发生的原因。也许那个奇怪的条目是由黑客引起的，也可能是某个用户因为睡眠习惯在不寻常的时间登录。日志并非无懈可击，因为大多数精明的黑客会运行更复杂的程序来删除任何关于其活动的记录，或者，初学者或愚蠢的黑客很容易通过日志数据被发现。

考虑安装安全软件。端口扫描器从外部查看你的网络，试图寻找正在开放并接受连接的未控端口。与另一个网络上的管理员一起运行端口扫描，这样你们都能获益。然后，关闭那些悬挂开启状态的未使用端口。开放的端口是他人访问你系统的最易途径，也是使用电缆调制解调器或 DSL 用户最常见的破解手段。

更高级的解决方案涉及防火墙，入侵检测系统可以发现入侵。防火墙是访问控制的关键，也是电缆调制解调器或 DSL 用户最常见的防护手段。

## 管理软件

管理员最常见的任务之一就是安装软件。如果你曾经在 Mac 或 Windows 上安装过软件，你可能已经熟悉了。在 Unix 世界中，管理员通常需要处理软件包。

## 从源码安装软件

源码通常以压缩包的形式分发。你可以通过命令 `make` 在终端中编译安装源码。

### 获取源码

软件包通常以压缩包（tarball）的形式出现。压缩包是将多个文件和子目录归档成单个文件。压缩包在归档后通常会进行压缩，以尽可能减小文件体积。压缩包的文件名通常遵循特定的语法，让你一眼看出其格式。文件名 `filename.tar` 表示未压缩的归档，而 `filename.tgz` 或 `filename.tar.gz` 表示使用 `gzip` 程序压缩的归档。文件名 `filename.tar.bz2` 或 `filename.tbz2` 或 `filename.tbz` 表示使用 `bzip2` 程序压缩的归档。`bzip2` 与更广泛使用的 `gzip` 类似，但创建的文件更小。通常在压缩的文件很大时使用 `bzip2`，它是系统中一个非常有用的程序。

为了解压这些文件，你必须使用 `tar` 命令。`tar` 是“tape archive”（磁带归档）的缩写。该程序最初用于创建存储在磁带驱动器上的备份文件。虽然它有时仍用于某些目的，但现在也经常被用于创建压缩软件包。要解压下载的软件包，请执行命令：

- 如果软件包是 `*.tar` 文件：
```
tar xvf file_name
```
- 如果软件包是 `*.tgz` 或 `*.tar.gz` 文件：
```
tar xzvf filename
```
- 如果软件包是 `*.bz2`、`*.tar.bz2`、`*.tbz2` 或 `*.tbz` 文件：
```
tar xjvf filename
```

根据压缩包的大小，此过程可能需要一些时间。“v” 选项会产生详细输出，这意味着你将看到每个文件从压缩包中提取时的名称。在压缩包解压后，使用 `ls` 命令列出目录内容。你将看到一个与你刚刚解压的包同名的新子目录。使用 `cd` 命令进入该子目录；现在你就可以准备进行安装过程的下一步了。

### 阅读文档

将阅读文档被认为是安装新软件过程的一个步骤可能看起来很奇怪。然而，当你从源代码安装软件时，阅读文档是极其重要的。在解压压缩包创建的目录中，应该会有文档文件。特别是，你应该会有名为 `README` 和 `INSTALL` 的文件。请仔细且完整地阅读这些文件。

除了 `README` 和 `INSTALL` 文件外，软件包还可能提供其他文档。这些文件通常存储在名为 `doc` 的子目录中，或者从它们的名称就能看出。`README` 文件也可能指示哪里找到额外文档。请注意，在某些情况下，额外文档是在安装后的程序内部阅读的，其格式可能非常特殊，或者是不可读的文本。

在继续安装之前，务必阅读软件包的所有文档，或尽可能多地阅读。至少，你必须阅读 `README` 和 `INSTALL` 文件，以了解该程序是否有独特的要求。

为什么阅读文档如此重要？安装过程中的任何特殊之处都将在 `INSTALL` 和 `README` 文件中进行解释。这些文件还提供了你可能在编译期间需要提供的信息，或者警告需要外部或系统信息。这让你有时间在开始编译过程之前获取必要的信息，而编译过程一旦开始，如果不放弃安装是无法停止的。针对特定系统编译此软件时涉及的特殊考虑因素将在这些文件中解释。在开始处理软件包之前阅读文档，可以最大限度地提高成功安装的几率，并最少地浪费时间。

本节中的后续步骤是许多 Unix 变体中许多软件安装中通用的通用程序。然而，这些步骤并不是通用的，因此你应该随时留意任何单个软件包安装程序与下文描述不同的地方。无论两个过程是否不对应，软件包文档中描述的程序始终优于这些更通用的指令。

> 警告：

### 配置安装

许多软件程序带有一个名为 `configure` 的自定义 shell 程序。可能是 `configure`、`setup` 或类似的名称。`INSTALL` 文档将告诉你该程序的名称。确保你处于软件包目录中：

```
./configure
```

如有必要，将“configure”替换为该程序的实际名称。

配置程序通常不需要用户输入。然而，某些版本是交互式的，你应该准备好在必要时提供所需信息。此外，某些 `configure` 程序在你想启用应编译到程序中的选项时可以接受参数。在这里，文档再次告诉你那些选项是什么。但在大多数情况下，你只需要运行该程序，它将恰当地处理好一切。`configure` 程序将检查你的编译器、所需的库以及成功安装所需的其他重要元素。

### 编译软件

一旦配置程序运行完毕（或者如果该软件包没有配置），你就可以准备编译程序了。这通常是一个简单的过程。在 shell 提示符处输入命令：

```
make
```

`make` 程序使用配置程序的输出（存储在名为 `Makefile` 的新文件中），来指导 C 编译器的操作。此时，编译器将开始工作。在程序编译时，你可能会看到许多信息在屏幕上滚动。

根据软件包的大小和你计算机的速度，这个过程可能从几秒钟到几小时甚至更长。如果编译看起来耗时很长，你几乎无能做什么来加速该过程。某些软件包甚至建议你在此期间去喝杯咖啡。

一旦编译完成，只要没有出现错误，你将获得一个可以运行的软件。如果发生了某些问题，你应该看到编译器生成的错误信息。这些信息可以为你关于问题可能的原因提供非常有用的线索。你可能缺少某个库，或者将必要的 shell 程序安装在了不寻常的位置。进行必要的修复或安装所需的库，然后再次尝试安装过程。

此时，剩下的工作就是将二进制文件和配置文件安装到文件系统中适当的位置。某些软件包如果你只需在提示符处输入 `make install` 它们就可以为你完成这些工作。其他软件包则不会。一如既往，文档是你的指南。如果你选择执行 `make install`，请记住文件将安装在软件编写人员认为合适的目录中。如果你想让它们安装在其他地方，你必须手动移动它们。

## 软件包管理系统

从源代码安装软件既有优点也有缺点。一方面，当你从源代码安装时，你对该过程拥有很大的控制权。许多源代码软件包提供了大量的编译选项。这些选项让你创建一个完全按照你意愿运行的二进制文件，而不会在不必要的功能上浪费系统资源。你为这种灵活性所付出的代价是大量的复杂性，范围从单调乏味到晦涩不等。

并没有规定特定系统只能安装由包管理器安装的软件或从本地源码编译的软件。大多数系统两者兼备，且大多数管理员对这两种情况所需的程序同样熟练。在这种情况下，唯一的限制是，如果包管理系统有数据库，它将不知道你自己编译的程序。这并不是一个规模巨大的问题，最坏的情况下可能只是一个微小的困扰，而不是避免源代码的正当理由。

### 案例说明：RPM
