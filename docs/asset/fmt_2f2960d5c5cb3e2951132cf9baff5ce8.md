
## 各种硬件问题

本节介绍 HP-UX 如何处理硬件。

### 我有一个带有扫描仪和 CD-ROM 驱动器的 9000/715 工作站。手册说不要关掉 SCSI 链上的任何设备。我们真的需要一直开启扫描仪吗？

解决这个问题的可能方法是将所有外设连接到保护器上，让所有开关处于开启位置，只关闭保护器。使用这种策略应该防止出现小反馈和其他问题。

### 我能让 Netscape 3.0 使用我的 735 工作站的功能吗？

Netscape 没有为 UNIX 提供 `mime.types` 和 `mailcap` 文件，也没有用于 `make install` 的 Makefile。你可以在 `/usr/local/lib/netscape` 创建一个 `mime.types` 文件并包含以下内容：

`audio/basic au`
`audio/x-wav wav`

你可能还会为特定的扩展名（`.wav`, `.doc` 和 `.zip` 等）创建一个 `mime-type` 文件。下一步是创建一个 `/usr/local/lib/netscape/mailcap` 的文件。你应该包含以下几行：

`audio/basic; /audio/bin/send_sound %s`
`audio/x-wav; /audio/bin/send_sound -wav %s`

（如果你在使用 X1，必须使用 `/audio/bin/send_sound`）。下一步是启动服务器并运行 Netscape。现在你有了这些文件，每当你点击 `.au` 或 `.wav` 文件时，都应该播放声音。

### HP 的工作站和 X 终端有不同的键盘吗？

HP 工作站和 X 终端实际上有两种不同的键盘。工作站默认是标准的，X 终端默认是 PC 键盘。所有 712、715 和更新的工作站都支持 PS/2 兼容键盘和鼠标。

### 有办法在 HP 上播放音频 CD 吗？

有一个贡献的应用 `xcd`，可以在 X Windows 中弹出播放器面板。它可以在 HP-UX 7.0 和 HP-UX 8.0 以及 300、400 和 700 系列机器上运行。它也支持 SCSI 或 HP-IB CD-ROM 驱动器。为了让 SCSI 驱动器工作，必须使用 HP 提供的或东芝 XM301B 或 XM331B。官方上，`xcd` 尚未支持 9.x，但有些人已经尝试在 9.x 上运行且没有问题。遗憾的是，`xcd` 只通过 CD 播放器的耳机孔播放，而不通过工作站的扬声器。有两个类似的程序 `xdp` 和 `xmcd`。它们与 `xcd` 基本相同，但功能更多。

### 我能让 Exabyte 带器在 HP 上工作吗？

在 HP-UX 8.0 下，人们使用了主号为 54、次号为 `0x20122` 和 `0x20123` 的设备文件分别对应 `/dev/rmt/0n` 和 `/dev/rmt/0n`。其他人用过 `0x20142` 和 `0x20143`。注意在 HP-UX 9.0 中，低密度意味着 8500 驱动器的 8200 格式。主号 54、次号 `0x20122` 和 `0x20123` 是低密度句。对于 8200 驱动器，密度并不重要。使用 8505 驱动器的软件压缩控制需要一个 HP-UX 9.0 的补丁。某些 Exabyte 驱动器不支持 HP 大于 64 的块因子。其他的在接受的命令上有限（TTI 指出其 8501 磁带在所有条件下都不会与 HP 正常接口；然而，TTI 8510 接口正确）。TTI 有一个固件问题，应该在近期的 8510 中修正。注意 8500 驱动器作为 SCSI-2 工作，而 8200 是 SCSI-1。人们在让 8500 与 9.0 工作方面似乎更成功。经验表明你可能需要 `PHKL_2898`。人们还报告说 HP-UX 9.x 需要补丁 `PHKL_2838` 来让压缩工作。

### 700 系列工作站有节点 ID 吗？

700 系列工作站确实有节点 ID。大多数许可系统（如 `FLEXlm` 和 `NetLS`）都由 LLA 驱动，该 LLA 位于 `/etc/scan` 或 `/usr/etc/net/ls_targetid`。HP 还使用一个 CPU ID 用于 `/etc/update`，这可能是 LLA 的转换。这不能保证保持不变，并且由于更换网卡而受到干扰。此外，LLA（许可代码）可以由 CE（现场工程师）重置，如果他使用正确的秘密程序。

### 对于 700 系列工作站，在 9.x 操作系统下 DDS 驱动器的正确主号（major number）是多少？

从 9.01 开始，DDS 驱动器主号为 121，之前的为 54。主号 54 支持分区，而 121 不支持，但 121 支持 LUN（逻辑单元号）。LUN 是向操作系统定义和划分磁盘（有时也是磁带）的另一种方式。

通过这种方式，你可以设置系统为磁带驱动器定义一个 LUN。

### 如何让音频驱动器指向我 700 系列工作站的外部插孔？

音频设备文件为 `/dev/audio`。外部插孔和内部扬声器的正确设置为：

`crw-rw-rw- 1 root sys 57 0x208011 /dev/audio ; external jack`
`crw-rw-rw- 1 root sys 57 0x208000 /dev/audio ; internal speaker`

确确，若要对设备驱动程序进行此更改，请使用 `mknod` 命令：

`mknod /dev/audio c 57 0x2080??`

你只需要将 `*??` 替换为 11（外部插孔）或 00（内部扬声器）。

### PA-RISC 架构的修订历史是什么？

在从*测试版* PA-RISC 1.0 架构到 1.1 的过程中，HP 保留了 PA-RISC 1.0 标准并扩展了其功能。因此，任何在 1.0 上运行的内容在 1.1 上也能运行。转向 PA-RISC 1.1 的主要变化是：
- 16 个额外的浮点寄存器
- 将双精度浮点寄存器寻址为单精度的能力
- 新的浮点操作
- 整数处理的微调

PA-RISC 1.1 的初始版本随第一 700 系列工作站推出，被称为 Snakes 系列。紧随 Snakes 发布后，Nova 系列推出。这些是带有 PA-RISC 1.1 CPU 的 800 系列服务器。从该点起，每一台新的基于 PA-RISC 的机器都基于 PA-RISC 1.1 架构。

在 700 系列机器上，编译程序默认会生成 PA-RISC 1.1 代码。然而，对于所有 800 系列机器，默认生成 PA-RISC 1.0 代码。你可以通过使用 `+DA 0` 选项强制编译器生成 PA-RISC 1.0 代码。只要你小心不要链接到任何为 PA-RISC 1.1 编译的库，就可以正常工作。如果你编译程序中的任何对象模块，整个程序将被标记为 PA-RISC 1.1。如果你对程序使用 `file` 命令，它将显示所需的架构。

HP 提供的几乎所有系统库都是为 PA-RISC 1.0 架构编译的，唯一的例外是数学库（math library）。它同时提供 1.0 和 1.1 版本；PA-RISC 1.1 版本位于 `/lib/pa1.1`。1.1 版本包含了 1.0 版本中没有的几个入口。如果你使用调度选项（+xxx），不会影响代码的兼容性。它唯一的影响是优化器如何调度延迟指令。考虑到这一点，为生产环境中最快的机器调度代码可能是一个好主意。在一个平台编译代码并在另一个平台运行时，你真正需要担心的是操作系统版本。例如，你可以在 700 系列机器上使用 `+DA1.0` 选项编译程序，一切运行正常。唯一的要求是程序将在编译时相同或更高版本的操作系统上执行。代码无法运行的一个示例：在运行 9.0 的 700 机器上编译代码，尝试在运行 HP-UX 8.0 的 800 服务器上运行。这是不可行的。我在 SGI 机器上将 tar 归档写入 DDS 磁带，我的 HP 机器无法读取。

### 如何让它读取磁带？

为了读取磁带，你必须执行一次交换操作来让 tar 读取。这是一个示例命令：
`dd if=/dev/rmt/0m ibs=512k obs=10k | tar -xvf -`

你只需要对在交换设备上创建的磁带执行此操作。在 IRIX 4 机器上，交换设备是默认的，而 IRIX 5 机器提供非交换设备。对于任何系统，你都可以在任何系统上使用该命令产生非字节交换磁带。此外，IRIX 5.0x 及更高版本使用 512 KB 块大小。以下是从 Irix 5.0x 或更高版本读取 tar 磁带的示例命令：
`dd if=/dev/rmt/0m ibs=512k obs=10k | tar -xvf -`
