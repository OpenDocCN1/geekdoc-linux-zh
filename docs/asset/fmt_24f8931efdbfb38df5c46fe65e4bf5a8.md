echo "never" > /sys/kernel/mm/transparent_hugepage/enabled
```

内核调优是一个复杂的主题，参数更改的影响取决于你的具体用用例。理解每个参数的含义并在做出更改后仔细监控系统性能至关重要。此外，请咨询相关文档和资源，以获取针对特定负载或应用程序进行内核参数调优的指导建议。

## 第 15.3 节：优化磁盘 I/O

优化磁盘 I/O（输入/输出）是任何 Linux 系统性能调优的关键方面，特别是在处理 I/O 密集型负载或应用程序时。磁盘 I/O 指的是读取或写入存储设备（如硬盘器或 SSD）的过程。高效的磁盘 I/O 可以显著提高整体系统性能。

在本节中，我们将探索在 Linux 系统上优化磁盘 I/O 的各种技术和策略。

### 1. 文件系统选择

文件系统的选择对磁盘 I/O 性能有显著影响。Linux 提供了多种文件系统，每种都有其自身的优缺点。例如，`ext4` 是一种广泛使用的文件系统，以其可靠性和性能而闻名，而 `XFS` 以其可扩展性和处理大文件的能力而闻名。

在选择文件系统时，考虑预期负载、数据完整性要求和文件系统特性等因素。在特定负载下对不同文件系统进行基准测试，以确定哪一个性能最佳。

### 2. 磁盘分区与布局

适当的磁盘分区和布局可以提高磁盘 I/O 性能。考虑以下策略：

- 分离数据和系统分区：将数据和系统文件放在不同的分区或驱动器上。这种分离可以防止系统相关的 I/O 操作影响数据 I/O。
- 使用多个磁盘：将 I/O 分布在多个磁盘或磁盘阵列（RAID）上。这可以增加 I/O 并行性和吞吐量。
- 分区对齐：确保分区与底层存储设备的块大小对齐。未对齐的分区会导致性能不佳。

### 3. 磁盘调度

I/O 调度器的选择会影响磁盘性能。Linux 提供了多种调度器，包括 `no`、`cfq`（完全公平队列）和 `deadline`。默认调度器取决于你的内核版本和配置。

要更改特定块设备（例如 `/dev/sda`）的 I/O 调度器，可以使用以下命令：

```
echo "deadline" > /sys/block/sda/queue/scheduler
```

`deadline` 调度器通常是通用系统的良好选择，但你应该测试不同的调度器，以找到最适合你工作负载的一个。

### 4. 磁盘缓存

磁盘缓存通过在内存中存储频繁访问的数据来提高读取性能。Linux 使用部分 RAM 作为磁盘缓存，称为页缓存（page cache）。你可以通过 `vm.dirty_ratio` 和 `vm.dirty_background_ratio` 等内核参数控制磁盘缓存的行为。

固态硬盘（SSD）的速度比机械硬盘（HDD）快得多。调优这些参数可以帮助提高性能。

### 6. 监控磁盘 I/O

使用 `iotop`、`iostat` 或 `sar` 等工具定期监控磁盘 I/O。这些工具可以提供对 I/O 使用情况的洞察。

## 第 15.4 节：网络调优

网络调优对于优化网络性能至关重要。无论你是运行 Web 服务器、管理大规模数据传输还是处理实时应用程序，精细网络都能显著改进结果。

### 1. 使用千兆或万兆以太网

提高网络性能的第一步是确保你有快速的网络连接。如果可能，使用千兆以太网（1 Gbps）或万兆以太网（10 Gbps）适配器和交换机。

### 2. 优化 MTU（传输单元）

传输单元（MTU）定义了以太帧的最大尺寸。默认情况下，大多数网络使用 1500 字节的 MTU。然而，MTU 可以通过减少数据包开销来提高性能。更改 MTU 请使用 `ifconfig` 或 `ip` 命令：

```
eth0
```

请注意，你的网络硬件和网络基础设施必须支持所选的 MTU 大小才能使其有效。

### 3. 使用巨帧

巨帧是 MTU 大于 1500 字节的以太帧。它们对于高吞吐量应用（例如存储网络 SAN 或 服务器之间的数据传输）特别有利。确保你的网络设备支持巨帧并进行配置。

### 4. TCP 窗口大小

TCP 窗口大小决定了在接收确认之前可以发送的数据量。较大的窗口可以提高网络吞吐量，特别是对于高延迟连接。你可以使用 `sysctl` 命令调整 TCP 窗口大小：

```
sudo sysctl -w net.ipv4.tcp_window_scaling=1
```

```
sudo sysctl -w net.core.rmem_max=16777216
```

sudo sysctl -w net.core.rmem_max=16777216
```

### 5. 调优网络缓冲区

Linux 使用内核级网络缓冲区存储传输中的数据。适当调优这些缓冲区有助于优化网络性能。使用 `sysctl` 命令调整接收发送缓冲区：

```
sudo sysctl -w net.core.rmem_default=65536
```

```

```

### 6. 启用 TCP 卸载

TCP 卸载引擎 (TOE) 将 TCP/IP 处理从 CPU 卸载到网络适配器，提高网络性能。确保您的网络适配器支持 TOE，并在内核配置中启用它。

### 7. 使用多队列网卡

多队列网卡将网络流量分到多个 CPU 核心上，减少瓶颈并提高吞吐量。要启用多队列支持，请使用 `ethtool` 命令：

```
sudo ethtool -L eth0 combined 4
```

### 8. 启用接收侧扩展 (RSS)

接收侧扩展 (RSS) 将入的网络流量分到不同的 CPU 核心，允许更好的并行处理。使用 `ethtool` 在您的网络接口上启用 RSS：

```
sudo ethtool -N eth0 rx on
```

### 9. 监控网络性能

使用 `netstat`、`iftop`、`iperf` 或 `nload` 等工具定期监控网络性能。这些工具可以帮助识别瓶颈并衡量调优工作的影响。

## 10. 优化防火墙规则

如果您正在使用防火墙，请仔细检查并优化您的规则。低效或过于复杂的防火墙规则会影响网络性能。

使用像 `iptables` 这样的状态防火墙可以最大限度地减少跟踪连接状态的开销。

在 Linux 上优化网络性能涉及硬件和软件优化的结合。通过使用高速网络硬件、调整网络参数和监控性能，您可以确保您的 Linux 系统高效地处理网络通信和数据传输。

## 第 15.5 节：应用程序性能分析

分析运行在 Linux 系统上的应用程序的性能，对于识别瓶颈、优化资源利用以及确保流畅的用户体验至关重要。在本节中，我们将探索用于在 Linux 环境下分析应用程序性能的各种工具和技术。

### 1. top 和 htop：监控进程

`top` 和 `htop` 是命令行实用程序，提供运行进程的实时信息。它们显示 CPU 和内存使用情况、进程 ID 和其他相关数据。使用这些工具识别消耗过多系统资源的进程。

`top`

or

`htop`

### 2. strace：跟踪系统调用

`strace` 允许您跟踪进程执行的系统调用。这对于理解应用程序如何与内核交互以及识别由系统调用引起的性能瓶颈非常有用。

```
strace -p <pid>
```

### 3. lsof：列出打开的文件

`lsof` 命令列出与运行进程相关的所有文件和套接字。它可以帮助您识别文件相关的问题，例如打开文件过多或资源泄漏。

`lsof -p <pid>`

### 4. vmstat：系统统计

`vmstat` 提供各种系统统计情况的洞察，包括内存、CPU 和磁盘使用情况。监控这些指标可以帮助确定与资源利用相关的性能问题。

`vmstat 1`

### 5. iostat：磁盘 I/O 统计

`iostat` 报告磁盘 I/O 统计，包括数据传输率和磁盘活动。有助于识别与磁盘相关的性能问题。

`iostat -x 1`

### 6. sar：系统活动报告器

`sar` 命令收集并报告系统活动数据。它提供了随时间推移的 CPU、内存、磁盘和网络使用的全面见。

`sar -u 1`

### 7. perf：性能分析

`perf` 是一个强大的性能分析工具，可以跟踪 CPU 内存事件、监控内核函数并对应用程序代码进行分析。它需要特定的性能计数器来进行硬件事件监控。

```
perf record -e <event> <command>
```

### 8. strace：应用程序剖析

除了跟踪系统调用，`strace` 还可用于应用程序剖析，以确定哪些函数消耗了最多的时间。结合 `-c` 选项获取摘要报告。

```
strace -c <command>
```

### 9. Valgrind：内存分析

`Valgrind` 是一个内存分析工具，有助于识别 C/C++ 应用程序中的内存泄漏、缓冲区溢出和其他内存相关问题。
