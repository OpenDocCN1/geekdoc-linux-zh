
X 窗口系统支持一个或多个包含重叠窗口或区域的屏幕。屏幕是物理显示器和硬件，可以是彩色、灰度或单色的。每个显示器或工作站可以有多个屏幕。单个服务器可以为任意数量的屏幕提供显示服务。对于拥有键盘和一个指针（通常是鼠标）的用户，一组屏幕被称为显示（`display`）。

# Xlib 简介

X 服务器中的所有窗口都按照严格的层次结构排列。每个层次结构的顶端是一个根窗口（`root window`），它覆盖每个显示屏幕。每个根窗口都被子窗口部分或完全覆盖。除根窗口外，所有窗口都有父窗口。每个应用程序通常至少有一个窗口。子窗口也可以拥有它们自己的子窗口。借此，应用程序可以在每个屏幕上创建任意深度的树。X 为窗口提供了图形、文本和主控操作。

子窗口可以由其父窗口移动。也就是说，它可以超出父窗口的边界，但所有到窗口的输出都会被父窗口裁剪。如果一个窗口的多个子窗口位置重叠，则其中一个被认为在其他窗口之上或高于其他窗口，从而遮挡它们。被另一个窗口覆盖的输出会被窗口系统抑制，除非该窗口具有备份存储（`backing store`）。如果一个窗口被第二个窗口遮挡，则第二个窗口只观察那些既是第二个窗口祖先又是第一个窗口祖先的部分。

窗口的宽度为零或多个像素，可以是任何模式（`pixmap`）或纯色。窗口通常（但并非总是）有一个背景模式，当它未被覆盖时，系统会重新绘制该模式。子窗口会遮挡父窗口，父窗口中的图形操作通常会被子窗口裁剪。

每个窗口和 `pixmap` 都有自己的坐标系。坐标系中 X 轴水平，Y 轴垂直，原点 `[0, 0]` 位于左上角。坐标以像素表示，并与像素中心对齐。对于窗口，原点是内部左上角的边界。

X 不保证保留窗口的内容。当窗口的一部分被隐藏然后重新带回屏幕时，其内容可能会丢失。服务器会向客户端程序发送一个暴露事件（`expose event`），以通知它任何或所有窗口需要重新绘制。程序必须准备好根据需要重新生成窗口内容。

X 还提供了对象的离屏图形，称为 `pixmap`。单平面（深度为 1）`pixmap` 有时被称为位图（`bitmaps`），与窗口通用，并用于各种图形操作以定义模式或瓷砖。窗口和 `pixmap` 合称为可绘制实体（`drawables`）。

Xlib 中的大多数操作只是将内容添加到输出缓冲区中。这些请求稍后会在 X 服务器上异步执行。返回存储在服务器中的信息值的函数在收到显式回复或发生错误之前，不会返回（即会阻塞）。你可以提供一个错误处理程序，它会在报告错误时被调用。

如果客户端不希望请求异步执行，它可以在请求后调用 `XSync`，这会阻塞，直到所有缓冲区中的异步事件都已发送并处理完毕。一个重要的副作用是，Xlib 中的输出缓冲区始终通过调用任何返回服务器值的函数或等待输入的函数来被冲刷。

许多 Xlib 函数会返回一个整数资源 ID（`resource ID`），这允许你引用存储在服务器上的对象。X 的类型可以是 `Window`、`Font`、`Pixmap`、`Colormap`、`Cursor` 和 `GContext`，如文件 `<Xlib/X.h>` 中定义的那样。这些资源通过请求创建，并在连接关闭时销毁（释放）。这些资源大部分可以在应用程序之间共享，事实上，窗口是被显式操作的。字体和光标在多个屏幕之间共享。

```
<X11/cursorfont.h>
<X11/keysymdef.h>
<X11/keysym.h>
<X11/Xlibint.h>
<X11/Xproto.h>
<X11/Xprotostr.h>
<X11/X10.h>
```

以下符号由 Xlib 定义并贯穿整个手册：

- Xlib 定义了类型 `Bool` 以及布尔值 `True` 和 `False`。
- `None` 是通用的资源 ID 或原子操作（`atom`）。
- `XID` 类型用于通用资源 ID。
- `XPointer` 类型定义为 `char*`，用作数据的通用不透明指针。

Xlib 在函数的命名和语法上遵循了一系列约定。只要你还记得函数所需的信息，这些约定旨在使函数的语法更具可预测性。

## 主要的命名约定

- 为了区分 X 符号与其他符号，库对外部符号使用了混合大小。按照现有约定，变量使用小写，所有宏使用全大写。
- 所有 Xlib 函数都以大写 `X` 开头。
- 所有函数名和符号的首字母均大写。
- 所有用户可见的数据结构都以大写 `X` 开头。更广泛地说，任何用户可能引用的内容都以大写 `X` 开头。
- 宏和其他符号不以大写 `X` 开头。为了与所有用户符号区分开，宏中的每个单词的首字母均大写。
- 数据结构中的所有元素或变量均为小写。需要时，复合词使用下划线 `_` 构建。
- 使用的 `display` 参数始终位于参数列表的第一位。
- 所有使用的资源对象都出现在参数列表的开头，紧跟在另一个资源（最常见的是 `drawable`）之后；图形上下文（`graphics context`）出现在另一个资源之后。`drawable` 的优先级高于所有其他资源。
- 在参数列表中，`x` 参数始终在 `y` 参数之前。
- 在参数列表中，`width` 参数始终在 `height` 参数之前。
- 当同时使用 `x`、`y`、`width` 和 `height` 参数时，`x` 和 `y` 参数始终在 `width` 和 `height` 参数之前。
- 当掩码（`mask`）与结构体一同使用时，掩码在参数列表中始终位于指向结构体的指针之前。

## 主要的编程考量

- X 中的坐标和尺寸实际上是 16 位数值。做此这一决定是为了最大限度地减少给定性能水平下所需的带宽。坐标在接口中通常声明为 `int`。大于 16 位的数值会被静默截断。尺寸（宽和高）声明为无符号数值。
- 键盘是不同制造商工作站之间最大的变量。如果你希望你的程序具有可移植性，在这一方面应该特别保守。
- 显示系统的离屏内存是有限的。如果可能，你应该尽量减少使用位图（`pixmaps`）和备用存储器（`backing store`）。
- 用户应该对自己的屏幕空间拥有控制权。因此，你应该将你的应用程序提交给窗口管理器，而不是假定拥有整个屏幕的控制权。你在顶层窗口内部做什么取决于你的应用程序。有关更多信息，请参阅第 14 章和《客户端间通信规范手册》。

## Xlib 使用的约定

Xlib 使用以下约定来定义命名和语法：

- 全局符号使用斜体。
- 符号名使用斜体。
- 所有的参数使用普通字体。
- 函数使用 ANSI 原型，这取决于实现实现。
- 为了消除传递的参数与返回的参数之间的歧义，传递的参数以 *specifies* 开头（在有多个参数的情况下为 *specify*）；返回的参数以 *returns* 开头（在有多个参数的情况下为 *return*）。所有传递和返回的参数使用 *specifies* 或 *returns* 单词。
- 用于返回值的指针以 `_return` 后缀命名。传递给这些函数的其他指针仅用于读取。
- 同时用于输入和输出的结构指针使用 `in out` 后缀。
