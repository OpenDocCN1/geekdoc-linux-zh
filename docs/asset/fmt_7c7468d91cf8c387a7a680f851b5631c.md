## 扩展制表符 (EXPANDING TABS)

我们的 `distros.txt` 文件格式非常适合使用 `cut` 提取字段。但如果我们想要一个可以通过字符完全由 `cut` 操作的文件，而不是通过字段呢？这将我们需要将文件中的制表符替换为相应数量的空间。幸运的是，GNU Coreutils 软件包包含一个为此设计的工具。该程序名为 `expand`，它接受一个或多个文件参数或标准输入并将并将后的文本输出到标准输出。

如果我们用 `expand` 处理 `distros.txt` 文件，就可以使用 `cut -c` 从文件中提取任何字符范围。例如，我们可以使用以下命令，通过扩展文件并使用 `cut` 提取从第 23 个位置到行尾的每个字符，从而从列表中提取发布年份：

```
[me@linuxbox~]$ expand distros.txt | cut -c 23-
```

Coreutils 还提供了 `unexpand` 程序来用空格替换制表符。

在处理字段时，可以指定不同的字段分隔符而不是制表符字符。在这里，我们将从 `/etc/passwd` 文件中提取第一个字段：

```
[me@linuxbox~]$ cut -d ':' -f 1 /etc/passwd | head
```

使用 `-d` 选项，我们能够指定冒号作为字段分隔符。

## paste (粘贴)

`paste` 命令的作用与 `cut` 相反。它不是从文件中提取一列文本，而是向文件中添加一或多列文本。它通过读取多个文件并将每个文件中找到字段合并到标准输出的单个流来实现。与 `cut` 类似，`paste` 也接受多个文件和或标准输入。为了演示 `paste` 如何运行，我们将对 `distros.txt` 文件进行“手术”，生成一个按时间排序的发布列表。

根据之前对 `sort` 的使用，我们将首先生成按日期排序的发行版列表，并将结果存储在名为 `distros-by-date.txt` 的文件中。

```
$[linuxbox~$ sort -k 3.nbr -k 1.nbr -k 3.4br distros.txt > distros-by-date.txt
```

接下来，我们将使用 `cut` 从文件中提取前两个字段（发行版名称和版本），并将其存储在名为 `distros-versions.txt` 的文件中。

```
$[linuxbox~$ cut -f 1,2 distros-by-date.txt > distros-versions.txt
[linuxbox~$ head distros-versions.txt
```

最后一步准备工作是提取发布日期并将其存储在名为 `distros-dates.txt` 的文件中。

```
$[linuxbox~$ cut -f 3 distros-by-date.txt > distros-dates.txt
[linuxbox~$ head distros-dates.txt
```

现在我们有了所需的部分。为了完成整个过程，我们将使用 `paste` 将日期列放在发行版名称和版本旁边，从而创建一个按时间排序的列表。这通过简单使用 `paste` 并排列其参数来实现。

```
linuxbox~$ paste distros-dates.txt distros-versions.txt
```

## join (连接)

在某些方面，`join` 类似于向文件添加列的 `paste`，但它使用了一种独特的方法来实现。`join` 是一种通常与关系型数据库相关的操作，将具有共享键的多个表中的数据合并形成所需的结果。`join` 操作根据共享键连接多个文件。

为了查看 `join` 操作如何用在关系型数据库中，假设有一个包含单条记录的两个表的小型数据库。第一个表名为 `CUSTOM`，有三个字段：客户编号（CUSTOM）、名（FNAME）和姓（LNAME）。

| CUSTOM | FNAME | LNAME |
| :--- | :--- | :--- |
| 4681934 | John | Smith |

第二个名为 `ORDERS`，包含四个字段：订单号（ORDERNUM）、客户编号（CUSTOM）、数量（QUAN）和订单物品（ITEM）。

| ORDERNUM | CUSTOM | QUAN | ITEM |
| :--- | :--- | :--- | :--- |
| 30149508 | 1 | Blue | Widget |

注意两个表共享字段 `CUSTOM`。这很重要，因为它允许表之间建立关系。执行 join 操作合并两个表的字段以获得实用的结果，例如准备发票。通过匹配两个表的 `CUSTOM` 值，`join` 操作可以产生以下结果：

| FNAME | LNAME | QUAN | ITEM |
| :--- | :--- | :--- | :--- |
| John | Smith | Blue | Widget |

为了演示 `join` 程序，我们需要创建两个共享键的文件。为了实现这一点，我们将使用 `distros-by-date.txt` 文件。从该文件中构造两个文件：一个包含发布日期（将是我们本次演示的共享键），另一个包含发布名称，如下：

```
me[linuxux~]$ cut -f 1 distros-by-date.txt distros-names.txt
me[linuxux~]$ paste distros-dates.txt distros-names.txt > distros-key-names.txt
me[linuxux~]$ head distros-key-names.txt
```

第二个文件包含发布日期和版本号，如下：

```
me[linuxux~]$ cut -f 2 distros-by-date.txt > distros-vernums.txt
me[linuxux~]$ paste distros-dates.txt distros-vernums.txt > distros-key-vernums.txt
me[linuxux~]$ head distros-key-vernums.txt
```

我们有两个具有共享键（日期字段）的文件。这很重要，因为它允许表之间建立关系。还要注意，默认情况下 `join` 使用空白作为输入分隔符。可以通过指定选项来修改此行为。详情请参手册页。

## tac

`tac` 命令的作用与 `cat` 相同，只是方向相反。它以反顺序连接文件。我们可以看到，日志存在且最新的条目在底部。如果我们想在列表顶部看到最新的条目，可以这样做：

```
[me@linuxbox~]$ tail /var/log/backup.log | tac
```

```
[me 15 07:45:57 EDT 2025: backup finished.
Thu Aug 15 07:36:30 EDT 2025: backup (0.6) started.
```

## rev (反转)

类似地，`rev` 反转字符串中的字符。

```
[me@linuxbox~]$ echo "This is a test." | rev
```

很有趣，它有什么用？`rev` 命令经常与 `cut` 一起使用。让我们再次考虑 `backup.log` 文件。假设我们想删除每行末尾的句号字符。由于行长度不一，没有办法指定 `cut` 命令从行尾删除。这就是 `rev` 派上用场的地方。通过反转行的字符，我们可以将句号移动到开头，让 `cut` 轻松地删除它们。

```
[me@linuxbox~]$ tail /var/log/backup.log | rev | cut -c 2 | rev
```

Fri Aug 16 07:37:57 AM EDT 2025: backup (0.6) of linuxbox started
Fri Aug 16 07:44:11 AM EDT 2025: backup of linuxbox finished

在这个示例中，我们使用 `rev` 来反转每行的字符，从第 2 个位置（反转后的字符串中点号之后的字符）到行尾截取该行的内容，然后再次反转字符以恢复其可读的格式。

## 比较文本

比较文本文件的版本通常很有用。对于系统管理员和软件开发者来说，这一点尤为重要。例如，系统管理员可能需要将现有的配置文件与之前的版本对比以诊断系统问题。同样，程序员经常需要查看程序随时间推移发生了哪些。

## comm

`comm` 程序比较两个文本文件，并显示每个文件特有的行以及它们共有的行。为了演示，我们将使用 `cat -` 创建两个几乎完全相同的文本文件：

```
[me@linuxbox ~]$ cat > file1.txt
```

```
[me@linuxbox ~]$ cat > file2.txt
```

接下来，我们将使用 `comm` 比较这两个文件：

```
[me@linuxbox ~]$ comm file1.txt file2.txt
```

正如我们所看到的，`comm` 生成三列输出。第一列包含第一个文件参数特有的行，第二列包含第二个文件参数特有的行，第三列包含两个文件共有的行。`comm` 支持形式为 `-n` 的选项，其中 `n` 为 1、2 或 3。使用时，这些选项指定了抑制哪些列。例如，如果我们只想输出两个文件共有的行，就会抑制第一和第二列的输出。

```
me@linuxbox ~]$ comm -12 file1.txt file2.txt
```

## diff

与 `comm` 程序一样，`diff` 用于检测文件之间的差异。然而，`diff` 是一个复杂得工具，支持许多输出格式，并能够一次处理大量文件。软件开发者经常使用 `diff` 来检查程序源代码不同版本之间的更改，并且它能够递归地检查源代码目录（通常称为源码树）。`diff` 的一个用例是创建 diff 文件或补丁，这些补丁可用于 `patch` 等程序（我们稍后会讨论）将一个文件（或多个文件）转换为另一个版本。

如果我们对之前的示例文件使用 `diff`，将看到它的默认输出样式：两个文件之间差异的摘要。

```
me@linuxbox ~]$ diff file1.txt file2.txt
```

在默认格式中，每组更改之前都有一个范围操作形式的更改命令，描述了将第一个文件转换为第二个文件所需的位置和更改类型，如表 20-4 所示。

## 表 20-4：diff 更改命令

| 更改 | 描述 |
| --- | --- |
| r1r2 | 将第二个文件中 r2 处的行追加到第一个文件的 r1 处。 |
| r1cr2 | 将第一个文件中 r1 处的行替换为第二个文件中 r2 处的行。 |
| r1dr2 | 删除第一个文件中 r1 处的行，这些行本应出现在第二个文件的 r2 范围内。 |

在这种格式中，范围是起始行和结束行的逗号分隔列表。虽然这种格式是默认格式（主要是为了符合 POSIX 标准并与传统 Unix 版本的 diff 向后兼容），但它不像其他或其他可选格式那样广泛使用。两种流行的格式是上下文格式（context format）和统一格式（unified format）。

使用上下文格式（-c 选项）时，我们将看到：

```
me@linuxbox ~]$ diff -c file1.txt file2.txt
```

### *** 1,4 ****

稍后我们看到这个，它表示第二个文件的第 1 到 4 行：

+   --- 1,4

在更改组内，行以表 20-5 所示的四个指示符之一开头。

### 表 20-5：diff 上文格式更改指示符

| 指示符 | 含义 |
| --- | --- |
| 空 | 上文中显示的行。 |
| - | 从第一个文件中删除的行。 |
| + | 添加到第二个文件的行。 |
| ! | 文件中被更改的行。 |

统一格式与上下文格式类似，但更简洁。它使用 `-u` 标志来显示更改。

```
me@linuxbox ~]$ diff -u file1.txt file2.txt
```

## 即时编辑

我们对文本编辑器的经验很大程度上是交互式的，这意味着我们手动移动光标并输入更改。然而，也有非交互式的文本编辑方法。例如，可以使用单个命令应用一组字符来更改多个文件。

## tr

`tr` 程序用于转置字符。我们可以将其视为一种搜索和替换操作。字符转置是将字符从一种字母表变为另一种字母表的过程。例如，将小写字母转换为大写字母就是翻译。我们可以通过 `tr` 执行此类转换：

```
[me@linuxbox ~]$ echo "lowercase letters" | tr a A-Z
```

- • 范围（例如，A-Z）。注意，由于区域设置排序顺序（locale collation order），此方法有时会遇到与其他命令相同的问题，因此应谨慎使用。

- • POSIX 字符类（例如，[:upper:]）。

在大多数情况下，两个字符集的长度应该是相等的；然而，第一个集可能会比第二个集大，特别是当我们想要将多个字符转换为单个字符时。

```
@linux -js echo "lowercase letters" tr [:lower:] A
```

除了转录之外，`tr` 还允许从输入流中删除字符。在本章前面的部分，我们讨论了将 MS-DOS 文件转换为 Unix 风格的问题。要执行此转换，需要从每行的末尾删除回车符。可以使用 `tr` 如下操作：

```
tr -d 'r' < dos_file > unix_file
```

在这里，`dos_file` 是要转换的文件，`unix_file` 是结果。命令的形式使用转义序列 `\` 来表示回车符。要查看 `tr` 支持的序列和字符的完整列表，请尝试以下操作：

```
@linux -js tr --help
```
