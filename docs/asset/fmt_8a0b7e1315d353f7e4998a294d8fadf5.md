
除了附加在 URL 中 `?` 之后的查询字符串（通过环境变量 `QUERY_STRING` 返回）外，还可以通过 `STDIN`（标准输入）获取数据。数据将以 `CONTENT_TYPE` 描述的形式存在，长度为 `CONTENT_LENGTH` 字节。

无法保证输入末尾会有文件结束符。你可以读取 `CONTENT_LENGTH` 数量的字节，然后根据需要解码数据。从表单提交的数据通常 `CONTENT_TYPE` 为 `'application/x-www-form-urlencoded'`，它会将任何非文本字符转换为十六进制等效字符（空格变为 %20）。

CGI 脚本的输出被写入 `STDOUT`（标准输出）。它应该包含一个 `HTTP` 头部，告诉浏览器获取的是什么类型的数据。之后的所有内容都会被浏览器解释为该类型的数据。如果告诉浏览器它获取的是 HTML，它将将其解释为 HTML；如果告诉它服务器发送了一个 gif 文件，它将尝试将后续内容解释为 gif 。

## 输出类型

在每个 CGI 脚本的开头，你需要告诉客户端浏览器你发送的是什么。通过前两行实现：

`Content-type: text/html`

`_`

第一行是数据类型，第二行始终为空。服务器会根据需要添加额外信息。

最基本的类型是 `text/html`，正如名称所示，用于表示其中包含文本格式的 HTML 代码（无二进制数据）。这些被称为 MIME（多用途互联网邮件扩展）类型（MIME 在第 2 卷第 16 章中解释），用于指定数据类型以及传输该数据的编码方法。浏览器可能无法直接处理特定类型。在这种情况下，它将使用所谓的“助手”（helpers）或“辅助应用程序”来处理内容。

## 最小响应

至少，你的 CGI 脚本需要向浏览器返回内容类型，并返回一些有意义的内容（毕竟执行 CGI 脚本是为了做某些事）。

如前所述，取决于所使用的服务器，用于 CGI 脚本的 URL 可能不同。有些服务器在一个位置查找文件，而另一些则需要不同的位置。你应该咨询本地管理员或 ISP 获取关于如何编写 CGI 脚本 URL 以及放置文件的更多信息。我使用的 ISP 要求 CGI 脚本放在 `public_html` 下的 `cgi-bin` 子目录中。引用脚本时，只提到了 `cgi-bin` 目录。在 CGI 脚本中创建 HTML 代码的技术被称为“动态 HTML”，因为它可以根据执行脚本的结果而改变。普通文件中的 HTML 除非替换否则是静态的。每个用户都能从 CGI 脚本看到不同的内容，所以它是非常动态的。

## 表单

CGI 脚本的常见用途之一是处理来自 HTML 表单的数据。表单方法编码为 `POST`，动作 是脚本的 URL。用户通过浏览器在 HTML 描述的表单中输入数据，当他点击 `submit` 按钮时，你的脚本就会执行。

处理来自表单的数据有很多方法。你可以将其保存到文件，发送给支持邮件的应用程序，或者执行更复杂的处理。你可能将某人输入数据库，发送确认电子邮件，然后将其加入邮件列表。或者你只需保存数据（网页留言板或填写评论表单是常见示例）。

将数据作为电子邮件发送给用户是最简单的方法，因为你不需要处理文件或记录锁定问题。如果你的 ISP 或系统管理员不允许你在系统上执行二进制文件，这一点尤为重要。如果你可以执行二进制文件，你就可以使用程序访问数据库。

确保为用户提供反馈。让他们知道表单内容已提交并接受是非常重要的。如果发生某种错误，也告诉他们。你应该执行数据验证——要么在你的 CGI 脚本中，要么在 HTML 中使用 JavaScript 等工具。

## CGI-BIN 包装器

某些互联网提供商不允许你直接执行我的 CGI 脚本。我的服务执行此限制。我必须执行一个程序，然后由该程序执行我的脚本。这被称为包装（wrappering or wrapping）——我的代码由其他代码运行。这样做有很多目的。包装器可以控制脚本可以使用 CPU、I/O 和其他资源量（防止失控或占用系统资源的脚本），可以提供额外的安全性，并通过解析环境变量为你完成部分设置。另一个重要功能是能够在调试模式下运行包装器。在模式模式下，它会显示传递给脚本的所有环境变量，调试变得容易得多。

到目前为止，我看到的包装器的唯一缺点是在适应之前，URL 有点困惑。而不是编写：

`<a href="~joeuser/cgi-bin/test.ksh">链接文本</a>`

我的代码：

`<a href="/cgi-bin/cgiwrap/joeuser/test.ksh">链接文本</a></a></a>`

## Netscape Cookies

Cookies 是维护状态信息的另一种方式。Cookie 仅仅是包含多个名称/值对的数据，它在 HTTP Header 中在客户端和服务器之间传递，而不是在查询字符串中。除了名称/值对外，还有许多可选属性。

请注意，Cookies 的规范仍处于初步阶段。你可能会发现，当有人使用不同版本的支持 Cookie 的浏览器时，某些功能的行为突然不再符合你的预期。官方规范保存在：

`http://home.netscape.com/newsref/std/cookie_spec.html`。

### 过期时间 (expiration time)

- 你可以使用此属性来定义 Cookie 的寿命。该字段本身是一个特殊的日期/时间字符串（GMT 时间），指定了客户端保留 Cookie 的时长。在此时间到达之前，客户端会在每次发出请求时继续将 Cookie 发送给服务器，即使用户重启了客户端也是如此。如果没有提供日期，Cookie 只在客户端运行时保持有效；一旦重启，Cookie 就会丢失。

### 域 (domain)

- 这定义了 Cookie 允许的域名。在“七大”顶级互联网域名（COM, EDU, NET, ORG, GOV, MIL 和 INT）中的域名必须至少包含两个点。其他域名至少需要三个点。因此，如果你将 .myhouse.com 指定为 Cookie 的域，则 Cookie 将传递给 www.myhouse.com、www.lab.myhouse.com 和 frontdoor.myhouse.com。不过，它不会发送到 .myhouse.com 域之外的任何地方。如果没有指定此属性，则 Cookie 只在发布它的主机上有效。因此，你的程序无法获取他人提供给客户端的 Cookie，反之亦然。

### 路径 (path)
