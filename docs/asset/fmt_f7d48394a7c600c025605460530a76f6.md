
| 地址范围 | 网络类别 |
| --- | --- |
| 10.0.0.0–10.255.255.255 | A（1 个 A 类网络） |
| 172.16.0.0–172.31.255.255 | B（16 个 B 类网络） |
| 192.168.0.0–192.168.255.255 | C（256 个 C 类网络） |

还有另一个保留的 A 类网络，地址范围为 127.0.0.0–127.255.255.255。这被称为环回网络。它是一个虚拟网络，指向数据包源所在的同一主机。任何系统中的常规环回地址是 127.0.0.1。如果你希望程序连接到其运行的本地主机（localhost，即同一系统），你可以打开到 127.0.0.1 的连接。这在例如运行网络软件但未连接到网络的系统中，或测试本地系统上的守护进程时非常有用。

**注意**

C 类 IP 地址范围旨在作为内部局域网（LAN）使用的私有网络地址，特别是由于终端或工作站不直接连接到互联网。大多数 Red Hat Linux 用户会设置一个网关计算机，该计算机随后为 LAN 转发或检索信息——这被称为 IP 伪装。

## 路由

网络通过路由器连接。路由器是一种设备，它有两个或更多网络的连接，并负责在它们之间传输数据包。当主机发送一个目的地在同一网络内的数据包时，它直接将其发送到目标主机。然而，如果数据包的目的地在不同的网络中，它会将数据包发送到路由器，以便路由器将其发送到正确的网络。这就是为什么正确设置主机的子网掩码非常重要——它是告诉主机是将数据包直接发送到目标主机还是路由器的参数（参见图 20.2）。

![](img/6bd28cbdb5cafd4e9d424d0c660b83ee_691_0.png)

一个网络通常有一个默认路由器，它将其连接到其他网络。在这种配置中，所有目的地不在本地网络内的流量都会被发送到默认路由器。一个网络中可能有多个路由器；例如，一个连接到互联网，另一个连接到其他内部网络。在这种情况下，可能需要使用静态路由来告诉主机将发往特定子网的数据包发送到特定路由器，或者通过路由守护进程（如 `lgprd` 或 `routed`）使用动态路由。这些守护进程将在本章后面的“网络守护进程”部分讨论。

## TCP/IP 协议套件

TCP/IP 实际上不仅仅是一个协议，而是一个协议套件。在低级别上，它由以下协议组成：

- IP
- TCP
- UDP

IP 是 TCP/IP 的最大公约数。每个更高级别的协议最终都必须转换为 IP 数据包。IP 数据包是自包含的，因为它本身包含源和目的地的地址。然而，它可能是更大对话的一部分。

TCP 是位于 IP 之上的基于连接或面向流的协议。这意味着使用 TCP 与其他应用通信的应用程序以字节流的形式发送和接收数据，并且 TCP/IP 堆栈负责将数据拆分为数据包并在接收端重新组装数据包。它还确保数据包按顺序到达，并重传丢失或损坏的数据包。

另一方面，UDP 协议是基于数据报或面向包的协议。它是一个无连接协议。该协议没有内置检查来确保数据包按顺序到达，或检查丢失的数据包。然而，由于缺少协议开销，UDP 在使用发送少量信息的应用程序，或在快速且可靠的网络（如私有 LAN 上的以太网）上使用时可以相当高效。

特定于应用程序的协议运行在 TCP 和 UDP 之上。其中一些如下：

- SMTP（简单邮件传输协议）
- HTTP（超文本传输协议）
- FTP（文件传输协议）
- SNMP（简单网络管理协议）
- NFS（网络文件系统）

每个协议根据其预期用途具有不同的特征。图 20.3 显示了 TCP/IP 套件的层次以及 OSI 参考模型中对应的层次。OSI 模型从未被广泛采用。它由七个层次组成：应用层、表示层、会话层、传输层、网络层、（数据）链路层和物理层。

## 套接字

在术语中，套接字是两个进程之间的网络连接，这些进程可能运行在相同或不同的计算机上。技术而言，一个打开的套接字有四个部分：源主机、源端口、目标主机、目标端口。一个关闭的套接字只有源端口和源主机。

注意套接字在连接的两侧都有端口。当客户端尝试连接到服务器时，它首先向系统请求一个空闲端口（未被其他任何程序使用的端口）。然后它请求系统使用该源端口连接到目标主机和端口。这就是为什么在相同两个主机之间可以有多个程序连接；例如，浏览器可以打开两个或更多到同一主机的窗口。系统跟踪源端口和目标端口，并为每个连接维护不同的套接字。

## 配置网络

在 Red Hat 中，基本网络配置通常在安装时进行，即配置基础系统时，但可以随时添加或删除网络接口。与其他 UNIX 系统一样，所有配置数据都存储在 `/etc` 树中的文本文件中。

需要考虑的一个重要事项是，Linux 与其他 UNIX 系统一样，可以即时重新配置。换句话说，几乎任何参数都可以在系统运行时更改，而无需重启。这使得实验和纠正配置问题变得容易。然而，如果你是第一次进行永久性配置更改，建议在进行任何重要配置更改后重启，以确保在系统重启时使用的是正确的配置。

如果你是 Red Hat Linux 的新手，只想配置网络以运行系统或对现有配置进行基本更改，那么以下部分适合你。它将快速概述如何更改你的网络在不编辑单个文件的情况下进行配置。如果您想执行更高级的任务，例如设置路由函数、ipchains 或 IP 伪装，那么您可能希望直接跳到下一节。本节将指导您如何使用 `linuxconf` 更改和设置主机名、IP 地址、默认网关、DNS 以及其他网络路由。

下一节介绍通过编辑 `/etc` 目录下存储的文件来配置网络。NIS 在第 15 章“NIS：网络信息服务”中有所涉及。

## 配置文件

Linux 系统中最重要的网络配置文件如下：

- `/etc/sysconfig/network`
- `/etc/HOSTNAME`
- `/etc/hosts`
- `/etc/services`
- `/etc/host.conf`
- `/etc/nsswitch.conf`
- `/etc/resolv.conf`

我们将逐一介绍这些文件。所有这些文件都可以在系统运行时进行修改。修改（`/etc/sysconfig/network` 除外）会立即生效，无需启动或停止任何守护进程。请注意，这些文件中的大多数都接受以井号（#）符号开头的注释。这些文件中的每一个在 UNIX 手册的第 5 部分中都有条目，因此您可以使用 `man` 命令访问它们。

### 网络设置：`/etc/sysconfig/network`

`network` 文件包含控制其他网络相关文件和守护进程如何填充的信息。以下是一个 `network` 文件示例：

```text
NETWORKING=yes
FORWARD_IPV4=false
HOSTNAME=lorvalsds.tech.access.com
DOMAINNAME=tech.access.com
GATEWAY=205.185.225.1
GATEWAYDEV=eth0
NISDOMAIN=loneytunes
```

最好通过 GUI 工具 `linuxconf` 来编辑此文件。该工具要求您拥有对 X 服务器的显示访问权限。如果您安装了 Red Hat Linux 7 并采用了默认设置，那么您将已安装 Gnome 桌面。您可以通过 Gnome 桌面访问 `linuxconf`，方法是点击 Gnome 起始点（这是屏幕左下角看起来像大写字母"G"的小脚印），并按照菜单序列（程序、系统、Linuxconf）操作。

### 主机名：`/etc/HOSTNAME`
