
# `case` 结构

`case` 结构（图 11-7，第 420 页）是一种多分支分支机制。通过结构的路径取决于 `test-string` 与某个模式之间是否匹配或不匹配。`case` 结构具有如下语法：

```bash
case test-string in
  pattern-1)
    commands-1
  pattern-2)
    commands-2
  pattern-3)
    commands-3
esac
```

## 示例：`safedit` 脚本

你还可以使用 `case` 控制结构在脚本中执行各种操作，取决于调用脚本时带有多少参数。以下名为 `safedit` 的脚本使用了 `case` 结构，根据命令行参数的数量 (`$#`) 进行分支处理。它会为你正在用 `vim` 编辑的文件保存一个备份副本。

### 脚本内容

```bash
#!/bin/bash
# UNIX/WORLD, IV:11

PATH=/bin:/usr/bin
script=$(basename $0)
case $# in
  0)
    vim
    exit 0
    ;;
  1)
    if [ ! -f "$1" ]
    then
      vim "$1"
      exit 0
    fi
    if [ ! -r "$1" -o ! -w "$1" ]
    then
      echo "$script: check permissions on $1" 1>&2
      exit 1
    else
      editfile=$1
    fi
    if [ ! -w "." ]
    then
      echo "$script: backup cannot be created in the working directory" 1>&2
      exit 1
    fi
    ;;
  *)
    echo "Usage: $script [file-to-edit]" 1>&2
    exit 1
    ;;
esac

tempfile=/tmp/$$.script
cp $editfile $tempfile
if vim $editfile
then
    mv $tempfile bak.$(basename $editfile)
    echo "$script: backup file created"
else
    mv $tempfile editerr
    echo "$script: edit error--copy of original file is in editerr" 1>&2
fi
```

### 逻辑解析

1.  **无参数调用 (`$# = 0`)**：`case` 结构执行第一个分支，在不带文件名参数的情况下调用 `vim`。由于没有编辑现有文件，`safedit` 不会备份文件。
2.  **单参数调用 (`$# = 1`)**：执行第二个分支。
    *   验证 `$1` 指定的文件不存在，或者该文件是用户具有读写权限的文件。
    *   验证用户是否对工作目录具有写权限（用于创建备份）。
    *   设置 `editfile=$1` 供后续使用。
3.  **多参数调用 (`$# > 1`)**：执行 `*)` 分支，显示用法信息并以状态 1 退出。

### 脚本特性详解

#### 1. 设置 `PATH` 变量
在脚本开头，`PATH` 变量被设置为 `/bin:/usr/bin`。通过这种设置 `PATH`，确保脚本执行的命令是存储在这些目录中的标准实用程序。通过在脚本内部设置 `PATH`，你可以避免当用户的 `PATH` 包含其自己的目录，且存在了与实用程序调用同名的脚本或程序时可能发生的问题。你也可以在脚本中包含绝对路径来实现这一目的，但这种做法会降低脚本的可移植性。

#### 2. 获取脚本简单文件名 (`script` 变量)
以下行创建了一个名为 `script` 的变量，并将脚本的简单文件名赋值给它：
```bash
script=$(basename $0)
```
`basename` 工具将其参数的简单文件名部分输出到标准输出，通过命令替换，将其赋值给 `script` 变量。`$0` 持有调用脚本时使用的命令（第 439 页）。无论用户通过以下哪个命令调用脚本，`basename` 的输出都是简单文件名 `safedit`：
```bash
$ /home/alex/bin/safedit memo
$ /.safedit memo
$ safedit memo
```
设置 `script` 变量后，它将替换用法和错误消息中的脚本文件名。通过使用派生自调用脚本的命令的变量，而不是硬编码在脚本中的文件名，你可以创建脚本的链接来重命名它，而用法和错误消息仍然提供准确的信息。

#### 3. 临时文件名中的 `$$` 变量
`else` 语句后的语句创建并为 `tempfile` 变量赋值了一个值：
```bash
tempfile=/tmp/$$.script
```
该变量包含一个存储在 `/tmp` 目录下的临时文件名称。临时文件以 shell 的 PID 数字 (`$$`) 开头，确保了文件名的唯一性，`safedit` 不会尝试覆盖现有文件（这在多个人同时使用 `safedit` 时可能会发生）。末尾附加脚本名称，这样如果文件由于某种原因留在 `/tmp` 中，你也可以查出它是从哪里来的。

PID 数字放在脚本名前面而不是后面，是因为某些旧版本的 UNIX 对文件名有 14 个字符的限制。Linux 系统没有这个限制。PID 数字确保了文件名的唯一性，它被放在第一个以确保不会被截断（如果脚本名部分被截断，文件名仍然是唯一的）。出于相同的原因，当脚本几行后的 `if` 结构内部创建备份文件时，文件名由字符串 `bak` 后面跟着正在编辑的文件名组成。

# `select` 结构

`select` 结构基于 Korn Shell。它显示一个菜单并将值赋值给变量。`select` 结构具有以下语法：

```bash
select varname in [arg ...]
do
  commands
done
```

菜单以每个项目前的数字进行格式化。例如，一个如下 `select` 结构：
```bash
select fruit in apple banana blueberry kiwi orange watermelon STOP
```
显示如下：
```text
1) apple      3) blueberry  5) orange     7) STOP
2) banana     4) kiwi       6) watermelon
```

### `PS3` 变量
在显示菜单后，`select` 显示 `PS3` 的值，这是一个特殊的 `select` 提示符。`PS3` 的默认值为 `#?`，但通常设置为更有意义的值。

### 交互逻辑
*   当你响应 `PS3` 提示输入有效数字（菜单范围内的数字）时，`select` 将 `varname` 设置为你输入的数字对应的参数。
*   如果你输入无效，`varname` 将被置为空。
*   `select` 将你的响应存储在关键字 `REPLY` 中。
*   随后执行 `do` 和 `done` 之间的命令。
*   如果你在不输入选择的情况下按回车，shell 将重新显示菜单和 `PS3` 提示。

`select` 结构继续使用 `PS3` 提示并执行命令，直到某些因素导致其退出——通常是 `break` 或 `exit` 语句。`break` 语句退出循环，`exit` 语句退出脚本。

### 示例脚本：`fruit2`

```bash
$ cat fruit2
#!/bin/bash
PS3="从这些中选择你喜欢的水果: "
select fruit in apple banana blueberry kiwi orange watermelon STOP
do
  if [ "$fruit" = "" ]; then
    echo -e "无效输入.\n"
    continue
  elif [ "$fruit" = STOP ]; then
    echo -e "感谢参与!"
    break
  fi
  echo "你选择了 $fruit 作为你喜爱的。"
  echo -e "那是选择号 $REPLY.\n"
done
```

### 运行示例
```text
$ fruit2
1) apple      3) blueberry  5) orange     7) STOP
2) banana     4) kiwi       6) watermelon
从这些中选择你喜欢的水果: 3
你选择了 blueberry 作为你喜爱的。
那是选择号 3。

从这些中选择你喜欢的水果: 99
无效输入。

从这些中选择你喜欢的水果: 7
感谢参与！
```

在设置了 `PS3` 提示符并使用 `select` 语句建立菜单后，`fruit2` 会执行 `do` 和 `done` 之间的命令。如果用户输入无效内容，shell 将变量 (`fruit`) 设置为空值，因此 `fruit2` 会先测试 `$fruit`。如果为空，`echo` 将显示错误，`continue` 会导致 shell 重新显示 `PS3`。如果输入有效，脚本将测试用户是否想要停止。如果是，`echo` 显示消息，`break` 退出 `select` 结构（并退出脚本）。如果用户输入了有效响应且不想停止，脚本将显示用户响应的名称和编号。（有关 `echo` 的 `-e` 选项信息请参见第 422 页。）

# Here Document（此处文档）

Here document 允许你在 shell 内部将输入重定向到脚本本身。它之所以被称为 Here document，是因为它“在这里”（here）——在脚本中可以立即访问——而不是在“那里”（there），可能在另一个文件中。

## 示例：`birthday` 脚本

以下名为 `birthday` 的脚本包含一个 Here document。第一行的两个小于符号（`<<`）表示 Here document 的开始——此示例定义了跟在小于符号之后的 `+` 作为 Here document 边界分隔符。起始分隔符必须紧邻小于符号，结束分隔符必须独占一行。shell 将两个分隔符之间的内容作为标准输入发送给进程。在示例中，这就像是从一个文件将标准输入重定向到 `grep`，只不过该文件嵌入了 shell 脚本中：

```bash
$ cat birthday
grep -i "$1" <<+
Alex June 22
Barbara February 3
Darlene May 8
Helen March 13
Jenny January 23
Nancy June 26
+
```

```text
$ birthday Jenny
Jenny January 23
$ birthday june
Alex June 22
Nancy June 26
```

当你运行 `birthday` 时，它会列出包含你调用时参数的所有 Here document 行。在这种情况下，第一次运行 `birthday` 时，它显示 Jenny 的生日，因为它是作为参数 `Jenny` 被调用的。第二次运行显示所有 6 月的生日。`-i` 参数导致 `grep` 搜索忽略大小写。

## 示例：`bundle` 脚本（创建 Shell 归档）

下一个名为 `bundle` 的脚本包含了对 Here document 的巧妙使用。`bundle` 脚本是一个创建 shell 归档（shar）文件的优雅示例。该脚本创建一个文件，该文件本身是一个 shell 脚本，包含几个文件以及重建原始文件的代码。

```bash
$ cat bundle
#!/bin/bash
# bundle: group files into distribution package

echo "To unbundle, bash this file"
for i
do
  echo $i 1>&2
  echo "cat >$i <<'End of $i'"
  cat $i
  echo "End of $i"
done
```

正如 shell 不会将 shell 脚本标准输入中出现的特殊字符视为特殊一样，shell 也不会将 Here document 分隔符之间的特殊字符视为特殊。

### 使用示例

**源文件：**
```text
$ cat file1
This is a file.
It contains two lines.
$ cat file2
This is another file.
It contains
three lines.
```

**生成归档脚本 `bothfiles`：**
```bash
$ bundle file1 file2 > bothfiles
$ cat bothfiles
# To unbundle, bash this file
echo file1 1>&2
cat >file1 <<'End of file1'
This is a file.
It contains two lines.
End of file1
echo file2 1>&2
cat >file2 <<'End of file2'
This is another file.
It contains
three lines.
End of file2
```

**解包执行：**
```bash
$ rm file1 file2
$ bash bothfiles
file1
file2
$ ls
bothfiles
file1
file2
```

在下一个示例中，在运行 `bothfiles` 之前删除了 `file1` 和 `file2`。`bothfiles` 脚本在创建文件时会 `echo` 这些文件名。`ls` 命令显示 `bothfiles` 重新创建了 `file1` 和 `file2`。
