
csh 使用百分号作为提示符。在 `csh` 命令启动 shell 后，提示符变为百分号。`ps` 命令显示 `csh` 是 `ksh` 的子进程和子 shell。要退出 `csh` 并返回 shell，你输入 `exit`。

### 进程权限

默认情况下，进程以运行它的用户的权限运行。在大多数情况下，这是合理的，允许你仅运行命令或工具。然而在某些情况下，用户需要访问他们并不拥有的文件。很好的例子是 `passwd` 命令，它通常存储在 `/bin/passwd`。它用于更改密码并修改 `/etc/passwd` 和 shadow 文件（如果系统配备）。普通用户没有权限写入密码；程序本身拥有这些权限。如果你使用 `ls` 查看文件，你会发现权限中有一个字母 `s`。`/bin/passwd` 的所有者是 `root`，属于 `sys` 组。无论谁运行，它具有 root 用户权限。

### 覆盖当前进程 (exec 命令)

除了创建（派遣）子进程外，你还可以另一个进程覆盖当前进程。谨慎使用此命令。如果你在主（登录）shell 解释器中使用 `exec`，该解释器（例如之前的示例中 pid 为 3662）将被新进程替换。

在 shell 中运行 `exec ls` 命令会给你目录列表然后断开连接。因为 `exec` 覆盖了你的 shell（例如 `ksh`），当 `ls` 完成并退出时，没有程序可以处理你的命令。

你可以使用 `exec` 完全更改你的 shell 解释器而不创建子 shell。要从 `ksh` 转换为 `csh`，可以使用以下命令：

```
$ exec csh
$ ps -f
UID PID PPID C STIME TTY TIME CMD
billing 3662 3657 0 08:10:53 pts/6 0:00 csh
billing 3266 3662 1 11:50:40 pts/6 0:00 ps -f
```

提示符发生了变化，`ps` 显示的是 `csh` 而不是 `ksh`，但保持了原始的 pid 和启动时间。

### 总结

在本章中，你查看了 shell 提供的有关进程的四个主题：

- 启动进程
- 列出运行中的进程
- 杀死进程（`kill` 命令）
- 父进程和子进程

在你编写脚本和使用 shell 时，了解如何处理进程将提高你的工作效率。

### 术语

`Background` 后台描述通常以较低优先级运行，且其输入与交互式会话断开的进程。输入和输出通常重定向到文件或其他进程。

`Background Processes` 后台进程 --后台进程是在 UNIX 下运行的、不需要用户交互的自主进程。

`bash` --`bash` 代表 GNU Bourne Again Shell，它基于原始命令解释器 `Bourne shell`（`sh`）。

`Bourne Shell` --这是 UNIX 的原始标准用户界面，支持有限的编程能力。

`BSD` --`BSD` 是伯克利软件发行版（Berkeley Software Distribution）的缩写。

`BSD UNIX` --这个版本的 UNIX 由伯克利软件发行版开发，并在加利福尼亚大学伯克利分校编写完成。

`C Shell` --这种用于 UNIX 的用户界面由 Bill Joy 在伯克利编写，具有类似于 C 语言编程的语法。

`Child Processes` --参见 `subprocesses`。

`Child Shells` --参见 `subshells`。

`Daemons` --守护进程是系统级的后台进程，通常以 root 权限运行，并处理来自其他进程的服务请求。

`Korn Shell` --这是一种具有广泛脚本（编程）支持的 UNIX 用户界面。由 David G. Korn 编写。该 shell 具有命令行编辑功能，并接受为 Bourne shell 编写的脚本。

`Parent Process Identifier` --父进程标识符在 `ps` 命令的标题中显示为 `PID`。这是父进程的进程标识。参见 `parent processes`。

`Parent Processes` --这些进程控制其他进程，这些进程通常被称为子进程或进程。参见 `processes`。

`Parent Shell` --此 shell 控制其他 shell，这些 shell 通常被称为子 shell 或子进程。登录 shell 通常是父 shell。参见 `shells`。

`Process Identifier` --进程标识符在 `ps` 命令的标题中显示为 `pid`。它是分配给系统中运行每个进程的唯一数字。

`Processes` --进程是 UNIX 下离散的运行程序。用户的交互式会话是一个进程。进程可以调用（运行）并控制另一个程序，该程序随后被称为子进程。最终，每个用户都是操作系统的一个子进程。

`Shell` --`shell` 是 UNIX 中处理用户输入并调用其他程序运行命令的部分。它包含一种编程语言。另见 Bourne shell, C shell, Korn shell, `tcsh` 和 `bash`。

`Shell or Command Prompt` --提示符是 UNIX shell 显示的单个字符或一组字符，用户可以在其处输入一个或多个命令。

`Shell Scripts` --`shell scripts` 是用 shell 编程语言编写的程序，例如 Bourne、Korn 或 C shell 支持的语言。

`Subprocesses` --子进程在其他进程（通常被称为父进程）的控制下运行。它们是进程。

`Subshells` --子 shell 在另一个 shell（通常被称为父 shell）的控制下运行。通常，登录 shell 是父 shell。它们是 shell。

`tcsh` --这是一种具有命令行编辑功能的类 shell 用户界面。

## 变量

变量是持有 *value* 的“词汇”。`shell` 允许你创建、分配和删除变量。虽然 shell 会管理某些变量，但很大程度上取决于程序员如何管理 shell 脚本中的变量。

本章将向你展示如何

- 创建变量
- 删除变量

本章还解释了什么是环境变量以及如何正确使用它们。通过使用变量，你可以让你的脚本更具活性和可维护性。

### 定义变量

- 变量名
- 访问数组值
- 只读变量
- 数组变量

变量的定义如下：

```
name=value
```

在此示例中，`name` 是变量名，`value` 是它应该持有的值。例如，

```
FRUIT=peach
```

定义变量 `FRUIT` 并赋值赋值值 `peach`。

这种类型的变量被称为 *scalar* 变量。在本章稍后的部分，你将看到另一种类型的，称为 *array* 变量，它可以持有多个值。

标量变量也称为 *name-value pairs*，因为变量名和它的值可以被看作一对。

### 变量名

变量名只能包含字母 (`a-z A-Z`)、数字 (`0` 到 `9`) 或下划线字符 (`_`)。此外，变量名只能以字母或下划线开头。

以下示例是有效的变量名：

```
_FRUIT
FRUIT_BASKET
TRUST_NO_1
TWO_TIMES_2
```

但

```
2_TIMES_2_EQUALS_4
```
