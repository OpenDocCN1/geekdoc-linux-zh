
## `brk` 与 `sbrk`

**increment**：按指定的字节数改变当前的 break 值。
**oldends**：调用之前的 break 值。

`Sbrk` 是一个调用 `brk` 的 C 库例程。

### 算法：`brk`

**输入**：new break value
**输出**：old break value

```
lock process data region;
if (region size is increasing)
    if (new region size is illegal)
    {
        unlock data region;
        return (error);
    }
change region size;
zero out addresses in new data space;
unlock process data region;
```

## 9.5.2 进程终止

UNIX 系统上的进程通过执行 `exit` 系统调用来终止。退出的进程进入僵尸状态，释放其资源，并将其在进程表中的槽位上下文拆解。

**语法**：
```
exit(status)
```

**Status**：被返回给父进程供其检查。进程可以在程序结束时显式地退出，也可以是隐式地退出。与所有 C 程序链接的启动例程在程序从 `main` 函数返回时调用 `exit`，它是所有程序的入口点。或者，内核可能在接收到未捕获的信号时，内部为该进程调用 `exit`。如果是这样，status 的值就是信号号。

### 算法：`exit`

**输入**：return code for parent process
**输出**：none

```
ignore all signals;
if (process group leader with associated control terminal)
    send hangup signal to all members of process group;
    reset process group for all members too.
close all open files;
release current directory;
de-allocate current (changed) root, if exist;
free regions, memory associated with process;
write accounting record;
make process state zombie;
assign parent process ID of all children to init process (1);
if any children were zombie, send death of child signal to init;
send death of child signal to parent process;
context switch;
```

系统对进程执行没有时间限制，进程经常长时间存在。例如进程 0 (swapper) 和 1 (init) 在整个系统生命周期内存在。以及监控终端等待用户登录的 `getty` 进程和特殊的管理进程。IPC 机制允许任意进程交换数据并同步执行。我们已经考虑了若干进程间通信的形式，如管道、命名管道和信号。管道的缺点是它们仅对执行管道调用的后代进程可见：无关进程无法通过管道进行通信。虽然命名管道允许无关进程进行通信，但它们通常无法跨网络使用，也不易于为不同的进程组设置多条通信路径。任意进程也可以通过 `kill` 系统调用发送信号来通信，但消息仅包含信号号。

# 第 10 章 进程间通信

IPC 机制允许任意进程交换数据并同步执行。我们已经考虑了若干进程间通信的形式，如管道、命名管道和信号。管道的缺点是它们仅对执行管道调用的后代进程可见：无关进程无法通过管道进行通信。虽然命名管道允许无关进程进行通信，但它们通常无法跨网络使用，也不易于为不同的进程组设置多条通信路径。任意进程也可以通过 `kill` 系统调用发送信号来通信，但消息仅包含信号号。

子进程并将其放入“就绪”状态，直到子进程做出响应。当子进程恢复执行（在内核模式下）时，它会执行相应的跟踪命令，将其回复写入跟踪数据结构，并唤醒调试器。根据命令类型，子进程可能会重新进入跟踪状态并等待新命令，或者从处理信号中返回并恢复执行。当调试器执行时，内核会保存被跟踪进程提供的“返回值”，解锁跟踪数据结构并返回给用户。

如果调试器进程在子进程进入跟踪状态时没有处于 `wait` 系统调用睡眠状态，那么它在调用之前无法发现被跟踪的子进程。

## 10.1.1 `ptrace` 的缺点

- (i) 内核必须进行上下文切换以便在调试器和被跟踪进程之间传输一个字的数据。在 `ptrace` 中，内核会在调试器中进行上下文切换，直到被跟踪进程响应查询，在被跟踪进程之间进行上下文切换，并带有答案切换回调试器进程。
- (ii) 调试器进程可以同时跟踪多个子进程。
- (iii) 如果被调试进程没有调用 `ptrace` 让内核知道它同意被跟踪，那么调试器无法跟踪一个正在执行的进程。
- (iv) 无法跟踪适当的程序，因为用户可以通过 `ptrace` 写入其地址空间并执行非法操作来违反安全性。

## 10.2 SYSTEM V IPC

该包包含三种机制：

- (i) 消息
- (ii) 共享内存
- (iii) 信号量

它们具有共同属性：

- 每个机制都包含一个表，其条目描述了机制的所有实例。
- 每个条目包含一个数值键，这是用户选择的名称。
- 每个机制包含一个“get”系统调用，用于创建新条目或检索现有条目，调用参数包括 key 和 flag。内核在相应的表中查找由 key 命名的条目。
- 进程可以带有 `IPC_PRIVATE` 调用“get”系统调用。
- 它们可以在 flag 字段中设置 `IPC_CREAT` 位，以便在键不存在时创建一个新条目；如果该键已存在条目，它们可以通过设置 `IPC_EXCL` 和 `IPC_CREAT` 标志来强制触发错误通知。
- 对于每个机制，内核使用以下公式从描述符找到数据结构表的索引：
  `index = descriptor modulo (表中条目的数量)`
- 例如，如果消息结构表包含 100 个条目，则条目 1 的描述符为 1, 101, 201 等。当进程移除一个条目时，内核将与其相关的描述符增加表中条目的数量。

### 10.2.1 消息

消息允许进程向任意进程发送格式化数据流。消息有四种系统调用：

- (a) `msgget`——返回一个消息描述符，用于指定供其他系统调用的消息队列。

  **语法**：
  ```
  msgqid = msgget(key, flag);
  ```

  - `msgqid`：调用返回的描述符。
  - `key`：是一个数值键，是用户选择的名称。内核在相应的表中查找由 key 命名的条目。
  - `flag`：它指定了内核应该执行的操作。

  `msgqid` 作为消息队列头数组的索引。队列结构包含以下字段：
  - 指向链表中第一条和最后一个消息的指针。
  - 链表上的消息数量和数据字节总数。
  - 链表上允许数据的最大字节数。
  - 最后发送和接收消息的进程 ID。
  - `msgid`、`msgrcv` 和 `msgctl` 操作的时间戳。

  当用户调用 `msgget` 创建新描述符时，内核在消息队列数组查找是否存在由 key 命名的条目。如果没有该条目，内核将分配一个新的队列结构并初始化它，然后返回给用户。

- (b) `msgsnd`

  **语法**：
  ```
  msgsnd(msgqid, msg, count, flag);
  ```

  - `msgqid`：由 `msgget` 返回的消息队列描述符。
  - `msg`：指向结构的指针，由用户选择的整数类型和字符数组组成。
  - `count`：数据数组的大小。
  - `flag`：如果缓冲区空间不足，内核应该采取的操作。

  内核检查发送进程是否有消息描述符的写权限、消息长度是否超过系统限制、消息队列是否包含过多字节以及类型是否为整数。如果所有测试通过，内核为消息分配空间并从用户空间拷贝数据。内核分配一个消息头并将其放在消息队列链表的末尾。

## 10.2.3 信号量

信号量系统允许进程通过一组信号量来同步执行。在实现信号量之前，进程如果锁定资源，可以使用 `creat` 系统调用创建一个锁文件。如果文件已存在，`creat` 将失败，进程将假设另一个进程已锁定了资源。

**缺点**——进程不知道何时重试锁，并且当系统崩溃或重启时，锁文件可能会无意中遗留。

```
P: if (S > 0)
       S--;
V: if (S < 0)
       S++;
```

`S` 是信号量变量。UNIX System V 中的信号量由以下元素组成：

- (i) 信号量的值。
- (ii) 上一个操作信号量的进程 ID。
- (iii) 等待信号量值增加的进程数。
- (iv) 等待信号量值等于 0 的进程数。
