## 修改文件

现在你可以对 `file2` 和 `file3` 进行更改以准备初始发布。这些简单的更改将涉及锁定文件、编辑文件以及将更改提交到源码控制。你将通过两种方式执行这些任务，以观察在编辑前正确锁定文件有多重要。

### 锁定、修改、提交

首先，在锁定文件后进行更改，并将其提交回源码控制。在本示例中，按如下方式更改 `file2`：

```text
This is file2
Added line 1
Added line 2
Added line 3
Added line 4
```

此添加操作创建一个包含你所做更改的版本 1.2。对于 SCCS，你应该运行以下：

```text
$ get -e s.file2

Retrieved:
1.1
new delta 1.2
1 lines
```

现在使用你喜欢的编辑器编辑 `file2`。

```text
$ delta s.file2
comments?
No id keywords (cm7)
1.2
4 inserted
0 deleted
1 unchanged

$ get s.file2

Retrieved:
1.2
5 lines

No id keywords (cm7)
```

此方法会在提示你输入注释后，创建一个包含你所做更改的版本 1.2。注意，`delta` 命令会告诉你插入、删除和未更改的行数。最后的 `get` 命令保留了一个只读副本。

### 修改、锁定、提交、恢复

如果你在没有锁的情况下更改了文件，仍然可以锁定源码控制文件并提交更改。在本示例中，按如下方式更改 `file3`：

```text
This is file3
A line called A
A line called B
A line called C
A line called D
```

**警告：** 在工作组项目中，在不检出文件的情况下对文件修改是非常危险的操作。在现实生活中请务必谨慎对待这种做法。此程序是作为恢复程序提出的，而不是日常实践。

使用 SCCS，执行这些命令：

```text
$ get s.file3

Retrieved:
1.1
1 lines

No id keywords (cm7)

$ chmod u+w file3
```

```text

Retrieved:
1.1
new delta 1.2
1 lines

$ delta s.file3
comments?
No id keywords (cm7)
1.2
4 inserted
0 deleted
1 unchanged

$ get s.file3

Retrieved:
1.2
5 lines

No id keywords (cm7)
```

你使用第一个 `get` 命令是为了确保你有 `file3` 的正确内容，但它并没有设置锁定。`chmod` 应该是一个警信号，说明你正在做某些危险的事；如果你在 SCCS 管理的文件上使用 `chmod`，那么你可能在做错！`get -e -p` 命令在 `file3` 的头部版本上设置了锁定。

## 对象数据库是指什么？它有什么什么用？

与大多数 UNIX 变体不同，AIX 提供了一个“抽象层”，允许人们在无需重启的情况下动态重新配置系统内核。

AIX 使用对象数据库（Object Database）来实现这种动态配置。它将大部分系统管理信息存储在 `/etc/objrepos`、`/usr/lib/objrepos` 和 `/usr/share/lib/objrepos` 中。对象数据库管理器（ODM）用于管理这些目录下的文件或对象。

ODM 仅仅是一组库例和程序，提供了基本的面向对象的数据库功能，用于动态修改系统。

系统管理实用工具菜单（被称为 SMIT）在大多数情况下，应用于操作系统对象类。

## 我如何查看我使用的是哪个版本的 AIX？

在 3.2.5 及以上版本中，你可以运行 `oslevel` 命令。使用 `-h` 选项查看此命令提供的选项。

在所有版本中，你都可以使用命令 `lslpp -h bos.obj` 显示所有引用基础操作系统（BOS）的数据库行。这还将显示加载到系统中的每个补丁的特定修复 ID（fix ID）和发布版本，以及加载的时间和加载提交（commit）是否成功。

从 AIX 3.2.4 开始，操作系统被拆分为多个子系统，以帮助避免多个版本的补丁和修复之间的混淆。通过这种方式，更新可以应用于整个子系统。

你还可以使用 `lslpp` 的另一个选项（例如 `lslpp -m bos.obj`）显示系统正在运行的特定更新和级别。强烈建议你至少更新到 3.2.4，除非你有只能早期版本运行的应用程序。

## SMIT 实用工具

SMIT 是一个非常实用的系统管理实用工具。类似于 HP-UX 中的 `SAM` 和 Solaris 中的 `admintool`，它简单地将执行任务所需的所有命令行命令及其所有正确选项进行编译。这些内容存储在你家目录下的 `smit.log` 和 `smit.script` 文件中。

由于 AIX 有一个抽象层，某些系统命令不仅命名不同，其工作方式也可能大不同。在大多数情况下，SMIT 可以让你免于麻烦，因此即使你习惯于命令行管理，学习 SMIT 也是值得的。

## 我如何从另一台机器导入 `/etc/passwd` 和 `/etc/group` 文件？

要成功执行操作，你需要对 `/etc/passwd` 运行 `usrck` 和 `pwdck`，并对 `/etc/group` 运行 `grpck`。AIX 将会将密码和组整合到它的数据库中。

## 我如何去掉 SMIT（GUI 界面）中的运行人界面？

你可以通过运行 `smitty` 直接使用 SMIT 的文本版本，也可以在你的 `.kshrc` 文件中添加一个别名：

```text
alias smit="smit -C"
```
