## 日志轮转

日志由 `logrotate` 包每天或每周轮转一次。其配置文件是 `/etc/logrotate.conf`。对于每个产生日志文件的包，在 `/etc/logrotate.d/` 下都有额外的配置文件。编写自己的配置也很容易，可以使用现有的文件之一作为示例。轮转意味着日志文件被命名为 `.1` 然后被截断为零长度。通过 `logrotate` 程序通知服务，有时会带有 `SIGHUP` 信号。你的 `/var/log/` 可能包含许多命名为 `.2`、`.3` 等的旧日志文件。源自 Route–Users–Guide

## 日志文件

UNIX 有一项严格的策略，不报告可能没有用户读取这些消息的错误。交互式命令产生的错误消息是在终端屏幕，而非交互式命令产生的错误或信息消息被“记录”到 `/var/` 目录下的文件中。日志文件是一个纯文本文件，守护进程不断向其追加单行状态消息。日志文件的常用目录是 `/var/log`。主日志文件是 `/var/log/messages` 和 `/var/log/syslog`。它包含了内核消息和来自几个服务的消息。当某个服务产生大型日志文件时（例如，每小时有数千次访问），该服务将使用它自己的日志文件。例如，`sendmail` 并没有它自己的日志文件——这是它的缺点之一。使用 `tail` 选项查看系统日志：

```
tail -f /var/log/messages
tail -f /var/log/syslog
```

重启日志服务会产生消息：[Not all logs in distribution]。Jun 27 16:06:43 ser lpd shutdown shutdown; Jun 27 16:06:45 cron lpd startup succeeded。

源自 Users–Guide http://www.tdlp.org/LDP/Linux-Dictionary/html/index.html
