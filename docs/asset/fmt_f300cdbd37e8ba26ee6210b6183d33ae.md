## 引言

GNU/Linux 席卷了计算机世界。曾几何时，个人电脑被迫在专有的操作系统环境和应用程序之间做出选择。用户无力修复或改进这些程序，无法查看其“内部机制”，并且往往被迫接受具有限制性的许可协议。GNU/Linux 和其他开源系统改变了这一切——现在，PC 用户、管理员和开发者可以选择一个包含完整工具、应用程序和全源代码的免费操作系统环境。

GNU/Linux 的巨大成功很大程度上归功于它的开源。由于程序源代码是公开的，每个人都可以参与开发，无论是修复一个微小的错误，还是开发和分发一个大型应用程序。这种机会让全球成千上万优秀的开发者为 GNU/Linux 贡献了新的组件和改进，以至于现代 GNU/Linux 系统可以与任何专有系统相媲，其发行版包含了跨越多个光光盘和 DVD 的数千个程序和应用程序。

GNU/Linux 的成功很大程度上继承了 UNIX 哲学。在 AT&T 和 BSD 变体中引入的许多应用程序接口 (API) 在 Linux 中得以延续，并构成了构建程序的基础。许多小型命令行程序协同工作的 UNIX 哲学是使 GNU/Linux 如此强大的组织原则。当这些程序被封装在易用的图形用户界面中时，底层命令对于高级用户和自动化脚本来说仍然可用。

一个强大的 GNU/Linux 应用程序在其内部运作中利用了这些 API 和命令的力量。GNU/Linux 的 API 提供了高级功能，如进程间通信、多线程和高性能网络。许多问题只需通过组合现有的命令和使用简单的脚本即可解决。

## GNU 和 Linux

GNU/Linux 这个名字是从哪里来的？你以前一定听过 Linux，也可能听过 GNU 项目。你可能没有听过 GNU/Linux 这个名字，尽管你可能对它所指的系统非常熟悉。

Linux 以内核的创建者和原始作者林斯·托瓦尔斯（Lin Torvalds）命名的。内核是执行操作系统最基本功能的程序：它控制并与计算机硬件接口，处理内存和其他资源的分配，允许多个程序同时运行，管理文件系统等等。

内核本身并不提供对用户有用的功能。它甚至不能为用户提供一个用于输入基本命令的简单提示符。用户无法管理或编辑文件、与其他计算机通信或编写其他程序。这些任务需要使用大量的其他程序，包括 shell、文件实用程序、编辑器和编译器。这些许多程序反过来又使用通用函数库，例如包含标准 C 函数的库，而这些函数并不在内核中。

在 GNU/Linux 系统上，许多其他程序和库是作为 GNU 项目的一部分开发的软件。它的目标是“开发一个自由软件的类 UNIX 操作系统”（源自 GNU 项目网站，http://www.gnu.org）。

Linux 内核和来自 GNU 项目的软件被证明是一个强大的组合。尽管这种组合通常简称为“Linux”，但如果没有 GNU 软件，系统就无法工作，就像没有内核就无法运行一样。因此，在本书中，我们将整个系统称为 GNU/Linux，除非我们专门讨论 Linux 内核。

## GNU 通用公共许可协议

本书中包含的源代码受 GNU 通用公共许可协议 (GPL) 保护，该协议列在附录 F“GNU 通用公共许可协议”。许多自由软件，特别是 GNU/Linux 软件都是根据该协议授权的。例如，内核内核本身根据 GPL 授权，你在 GNU/Linux 发行版中找到许多其他 GNU 程序和库也是如此。如果你使用书中的源代码，务必阅读并理解 GPL 的条款。

GNU 项目网站包含对 GPL (http://www.gnu.org/copy/) 和其他自由许可的广泛讨论。你可以在 http://www.opensource.org/licenses/index.html 找到关于开源许可的信息。

## 谁应该读这本书？

本书旨在面向三类读者：

- 你可能是一个已经具有为 GNU/Linux 系统编程经验的开发者，你想学习它的一些高级功能和能力。你可能对编写具有复杂功能的程序感兴趣，例如具有多处理、多线程、进程间通信以及与硬件设备交互功能的程序。你可能想通过让程序更快、更可靠、更安全来改进你的程序，或者通过设计它们与 GNU/Linux 系统的其他部分进行交互。

- GNU 是一个递归缩写：它代表“GNU's Not UNIX”（GNU 不是 UNIX）。

- 你可能是一个拥有另一个类 UNIX 系统开发经验的开发者，也对开发 GNU/Linux 软件感兴趣。你可能已经熟悉如 POSIX 规范之类的标准 API。要开发 GNU/Linux 软件，你需要了解该系统的特殊性、局限性、额外功能和约定。

- 你可能是一个正在从非 UNIX 环境（如微软的 Win32 平台）过渡的开发者。你可能已经熟悉编写良好软件的一般原理，但你需要了解 GNU/Linux 程序与系统以及相互交互的特定技术。你希望确保你的程序能够自然地融入 GNU/Linux 系统，并按照用户所预期的方式运行。

本书并非作为 GNU/Linux 编程各方面的全面指南或参考书。相反，我们将采用教程教学方法，介绍最重要的概念和技术，并提供如何使用它们的示例。第一章“入门”中的第 1.5 节“查找更多信息”包含了对额外文档的引用，你可以在那里查阅。

由于这是一本关于高级主题的书，我们假设你已经熟悉 C 语言和标准库函数。C 语言是开发 GNU/Linux 最广泛使用的语言；即使你使用其他语言，也会发现这些信息很有用。

如果你在其他 UNIX 系统上编写过程序，可能已经熟悉 Linux 的 I/O 函数（`open`, `read`, `stat` 等）。这些与标准库 I/O 函数（`fopen`, `fprintf` 等）不同。两者在 GNU/Linux 编程中都有用。如果不熟悉这些函数，请跳到书末阅读附录 B“低级 I/O”，然后再开始第 2 章“编写良好的 GNU/Linux 代码”。

本书不提供 GNU/Linux 的通用介绍。我们假设你已经具备与 GNU/Linux 系统交互以及在图形和命令行的基本知识。如果你是 GNU/Linux 新手，可以从许多入门书籍开始，例如 Michael Tobias 的《Inside Linux》（New Riders Publishing, 2001）。

## 使用 Emacs 编辑

编辑器是你用于编辑源代码的程序。Linux 有许多不同的编辑器可用，最流行且功能最全的编辑器可能是 Emacs。

#### 关于 Emacs

Emacs 不仅仅是一个编辑器。它是一个极其强大的程序，以至于在 CodeSource，它被亲切地称为“真之程序”（The One True Program，简称 OTP）。你可以在 Emacs 内部读取和发送邮件，并且可以用多到无法在此处详尽讨论的方式自定义和扩展 Emacs。你还可以从 Emacs 浏览网页！

如果你熟悉另一个编辑器，完全可以使用它来替代。本书的其余任何内容都不依赖于使用 Emacs。如果你没有喜欢的 Linux 编辑器，应该按照这里提供的微教程进行。

如果你喜欢 Emacs 并想学习它的高级功能，可以考虑阅读市面上许多关于 Emacs 的书籍。其中一本非常优秀的教程 *Learning Emacs* 由 Debra Cameron、Bill Rosenblatt 和 Eric S Raymond 编写（O'Reilly, 1996）。

### 打开 C 或 C++ 源代码文件

你可以通过在终端窗口中输入 `emacs` 并按回车键开始。当 Emacs 启动后，你可以使用顶部的菜单创建新的源文件。点击 `Files` 菜单，选择 `Open Files`，然后在屏幕底部的“minbuffer”中输入你想要打开的文件名。如果你想创建一个 C 源文件，请使用以 `.c` 或 `.h` 结尾的文件名。如果你想创建一个 C++ 源文件，请使用以 `.cpp`、`.hpp`、`.cxx`、`.hxx`、`.c` 或 `.h` 结尾的文件名。当文件打开后，你可以像在任何普通的文字处理程序中那样输入。要保存文件，选择 `Files` 菜单中的 `Save Buffer` 项。用完 Emacs 后，可以选择 `Files` 菜单上的 `Exit Emacs` 选项。

如果你不喜欢点击，可以使用键盘快捷键来自动打开文件、保存并退出 Emacs。打开文件，输入 `C-x C-f`（`C-x` 表示按住 Control 键然后按 x 键）。保存文件，输入 `C-x C-s`。退出 Emacs，输入 `C-x C-c`。如果你想更熟悉一下 Emacs，请选择 `Help` 菜单上的 `Emacs Tutorial`。该教程将为你提供许多如何有效使用 Emacs 的技巧。

- 1. 如果你没有在 X Window 系统中运行，必须按 F10 来访问菜单。

#### 1.1.2 自动格式化

如果你习惯在集成开发环境（IDE）中编程，你也会习惯让编辑器帮助你格式化代码。Emacs 提供了相同的功能。如果你打开一个 C 或 C++ 源文件，Emacs 会自动识别出该文件包含源代码而不仅仅是普通文本。如果你在空行上按下 Tab 键，Emacs 将光标移动到适当的缩进点。如果你在包含某些文本的行上按下 Tab，Emacs 会对文本进行缩进。例如，假设你输入了以下内容：

```
int main ()
{
    printf("Hello, world\n");
}
```

如果你在调用 `printf` 的那行按下 Tab 键，Emacs 将这样重新格式化你的代码：

```
int main ()
{
    printf("Hello, world\n");
}
```

注意该行是如何被适当缩进的。

在你使用 Emacs 时，你会看到它是如何帮助你执行各种复杂任务的。如果你野心勃勃，可以为 Emacs 编写任何你能想象的自动格式化程序。人们已经利用这一功能实现了编辑几乎各种文档的 Emacs 模式，实现了游戏，以及数据库前端。

#### 1.1.3 语法高亮

除了格式化代码外，Emacs 还可以通过为元素着色让 C 和 C++ 代码更易读。例如，Emacs 可以为关键字、内置类型和注释上色。发现错误简单的方法是使用语法高亮。例如，Emacs 可以为以下内容上色（注意：假设下面的代码是有色的）：

```c
int main() {
    printf("Hello, world"); // A comment
}
```

Emacs 还可以为字符串和数字上色。例如：

```c
int x = 10;
char *s = "Hello";
```

这使得代码更容易阅读和维护。

### 1.2 使用 GCC 编译

第一步是将 C 和 C++ 源代码转换为代码。

#### 1.2.1 编译单个源文件

编译器的名称是 `gcc`。要编译 C 源文件，你使用 `-c` 选项。例如，在命令行提示符输入以下内容可以编译 `main.c` 源文件：

```
% gcc -c main.c
```

生成的对象文件名为 `main.o`。

C++ 编译器是 `g++`。它的操作与 `gcc` 非常相似；编译 `reciprocal.cpp` 通过输入以下完成：

```
% g++ -c reciprocal.cpp
```

- `-c` 允许 `g++` 只将程序编译为对象文件；如果没有它，`g++` 将尝试链接程序以产生执行文件。输入此命令后，你将得到一个名为 `reciprocal.o` 的对象文件。

构建任何较大的程序可能都需要其他选项。`-I` 用于告诉 GCC 搜索头文件。默认情况下，GCC 在当前目录和标准头文件目录中搜索。如果你需要包含其他地方的头文件，你需要 `-I` 选项。例如，假设你的项目有一个用于源文件的目录 `src` 和另一个目录 `include`。你可以这样编译 `reciprocal.cpp`，指示 `g++` 使用 `../include` 目录来查找 `reciprocal.hpp`：

```
% g++ -c -I ../include reciprocal.cpp
```

- 3. 有更多关于 GCC 的信息，请访问 http://gcc.gnu.org。

- 4. 在 Windows 中，可执行文件的名称通常以 `.exe` 结尾。相反，Linux 程序通常没有扩展名。因此，该程序的 Windows 等效版本被称为 `reciprocal.exe`；Linux 版本只是 `reciprocal`。
