
使用带有调试符号编译的程序意味着你可以通过调试器运行程序或库，并且调试器的输出将是用户友好的。这些调试符号还会显著增大程序或库的体积。

要从二进制文件（必须是 `a.out` 或 `ELF` 二进制文件）中移除调试符号，请使用 `strip --debug filename`。如果你需要从多个文件中移除调试符号，可以使用通配符（类似于 `strip --strip-debug SLFS/usr/bin/*`）。另一种更简单的方法是在编译程序时不带调试符号。大多数人可能永远不会在软件上使用调试器，因此通过省略这些符号，你可以节省大量的磁盘空间。

在使用这些调试符号之前和之后会有巨大的差异，以下是一些统计数据：

- 带有调试符号的动态二进制文件：1.2MB
- 不带调试符号的动态二进制文件：478KB
- 带有调试符号的 `/lib` 和 `/usr/lib`（`libc` 和 `gcc` 文件）：87MB
- 不带调试符号的 `/lib` 和 `/usr/lib`（`libc` 和 `gcc` 文件）：16MB

大小取决于使用了哪种编译器以及使用哪种 C 库链接动态程序，但如果你比较带和不带调试符号的程序，结果将是类似的。在我完成这一章并从所有 LFS 二进制文件中删除所有调试符号后，我找回了超过 102 MB 的磁盘空间。差异确实很大。

更改默认编译器选项的方法有几种。一种是编辑软件包中的 `Makefile` 文件，例如 `CFLAGS` 和 `CXXFLAGS`（一个设计良好的软件包使用 gcc 编译器选项和 CXX 编译器选项），并更改它们的值。`binutils`、`gcc`、`glibc` 等软件包在子目录中有许多 `Makefile` 文件，因此需要花费大量时间。相反，有一种更简单的方法：创建 `CFLAGS` 和 `CXXFLAGS` 环境变量。大多数脚本都会读取 `CFLAGS` 和 `CXXFLAGS` 变量并在 `Makefile` 中使用。少数软件包不遵循这一惯，这些软件包需要手动编辑。

在下一节中，我们将创建 `SLFS/root/bash_profile`，其中包含以下优化：

```
CFLAGS=-O3 -mcpu=xxx -march=xxx
CXXFLAGS=$CFLAGS
```

这是一组确保在几乎所有平台上运行的最小化优化。这两个选项（`mcpu` 和 `march`）将根据你指定的 CPU 特定指令编译二进制文件。这意味着你不能将此二进制文件复制到低级 CPU 上并执行。它要么运行得非常不稳定，要么完全无法运行（会产生如 Illegal Instruction, core dumped 等错误）。你需要阅读 GCC Info 页面以找到更多可能的优化标志。在上面的环境变量中，你必须将 `xxx` 和 `yyy` 替换为相应的 CPU 标识符，如 `i586`、`i686`、`powerpc` 等。

请记住，如果你发现软件包无法编译并给出如“segmentation fault, core dumped”之类的错误，这很可能与这些编译器优化有关。尝试通过将 `-O3` 改为 `-O2` 来降低优化级别。如果无效，尝试 `-O` 或干脆不使用。也尝试更改 `-mcpu` 和 `march` 变量。编译器对某些硬件也非常敏感。当使用高级优化（如 `-O3` 设置）时，坏内存会导致编译问题。我使用 `-O3` 编译一切都没有问题的事实，并不意味着你也不会遇到问题。另一个问题可能是你系统中安装的二进制文件，这通常会在 Glibc 中引起问题（在 RedHat 中最为明显，因为 RedHat 经常使用并不总是非常稳定的测试软件。“RedHat 喜欢生活在尖端边缘，但把流血留给你自己”（引自某人的话）。

## 创建 `$LFS/root/bash_profile`

当我们在下一节进入 chrooted 环境后，我们想要导出一些环境变量，如 `TERM`、`CFLAGS` 以及其他你想设置的变量。为了这个目的，我们将创建 `$LFS/root/.bash_profile` 并在进入 chrooted 环境后进行 `source`。

创建一个新文件 `$LFS/root/.bash_profile`，内容如下。将 `xxx` 和 `yyy` 替换为你机器的相应值：

```
# Begin /root_profile
TERM=xterm
CFLAGS=-O3 -mcpu=xxx -march=yyy
CXXFLAGS=$CFLAGS
export TERM CFLAGS CXXFLAGS
# End /root_profile
```

你可以根据需要添加更多的环境变量。

## 进入 chrooted 环境

是时候进入我们的 chrooted 环境安装剩余软件了。运行以下命令进入 chrooted 环境。从现在开始不再需要使用 `$LFS`，因为 `/` 实际上是 `/mnt/lfs` 但 shell 并不知道。

```
root:~# cd $LFS
root:lfs# chroot $LFS env -i HOME=/root bash --login
```

进入 chrooted 环境后，我们可以继续安装所有基础系统软件。确保在 chrooted 环境中执行本章中的所有命令。

## 安装 GCC

### GCC 的安装

在解压 `gcc-2.9.2` 存档后，不要进入新创建的 `gcc-2.9.2` 目录，而是留在 `/usr/src` 目录。运行以下命令安装 GCC：

### 描述

`Bison` 是一个解析器生成器，是 `YACC` 的替代品。`YACC` 代表 Yet Another Compiler Compiler（又一个编译器编译器）。什么是 `Bison`？它是一个用于生成能够分析文本文件结构的程序。你不需要编写实际的程序，只需指定各项应如何连接，并根据这些规则构建出一个分析文本文件的程序。

在很多需要结构的示例中，计算器就是其中之一。

给定字符串：

`1 + 2 * 3`

你可以轻松地得到结果 7。为什么？因为有了结构。你知道如何解释这个字符串。计算机并不知道，而 `Bison` 是一个工具，通过以以下方式向编译器呈现字符串来帮助它理解：

```
+
/\
* 1
/\
2 3
```
