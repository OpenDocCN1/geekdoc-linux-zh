### 4.1.3 配置 `auditd` 规则

审计系统基于一组规则运行，这些规则定义了日志文件中捕获的内容。

可以指定以下类型的审计规则：

- **控制规则**：允许修改审计系统的行为及其部分配置。
- **文件系统规则**：允许对特定文件或目录的访问进行审计。（也称为文件监视）
- **系统调用规则**：允许记录任何指定程序执行的系统调用。

审计规则可以通过以下方式设置：

- 使用 `auditctl` 工具在命令行中设置。注意这些规则在重启后依然有效。
- 在 `/etc/audit/audit.d/` 目录下以 `.rules` 结尾的文件中设置。

#### 4.1.3.1 确保收集系统管理范围 (`sudoers`) 的更改（自动化）

**配置方案适用性：**

- 等级 2 - 服务器
- 等级 2 - 工作站

**描述：**

**原理：**

`/etc/sudoers` 和 `/etc/sudoers.d` 文件的更改可能表明对系统管理员活动范围进行了未经授权的修改。

#### 审计：

**磁盘配置**

运行以下命令检查磁盘规则：

```
# awk '/^ *w/ && /\etc\/sudoers/ && +-p *wa/ &&(/ key = *[!~]* * $/|// -k *[!~]* * $)/' /etc/audit/rules.d/*
```

验证输出是否匹配：

```
-w /etc/sudoers -p wa -k scope
-w /etc/sudoers.d -p wa -k scope
```

**运行配置**

运行以下命令检查已加载的规则：

```
# auditctl -l | awk '/^ *w/ &&/\/etc\/sudoers/ && +-p *wa/ &&(/ key = *[!~]* * $/|// -k *[!~]* * $/)'
```

验证输出是否匹配：

```
-w /etc/sudoers -p wa -k scope
-w /etc/sudoers.d -p wa -k scope
```

#### 修复：

在 `/etc/audit/rules.d/` 目录下编辑或创建一个以 `.rules` 结尾的文件，并包含相关规则以监控系统管理员范围的更改。

示例：

```
# printf "
-w /etc/sudoers -p wa -k scope
-w /etc/sudoers.d -p wa -k scope
" >> /etc/audit/rules.d/50-rules
```

合并并将规则加载到活动配置中：

```
# augrules --load
```

检查是否需要重启。

```
# if [ $ (auditctl -s | grep "enabled") == "2" ]; then printf "Reboot
required to load rules\n"; fi
```

#### 其他信息：

如果审计被锁定 (`-e 2`)，`augrules` 将不会以任何方式警告规则无法加载到运行配置中。需要重启系统才能将规则加载到运行配置中。

#### 4.1.3.3 确保修改 `sudo` 日志文件的事件被收集（自动化）

**配置适用性：**

- 级别 2 - 服务器
- 级别 2 - 工作站

**描述：**

监控 `sudo` 日志文件。如果系统已正确配置为禁用 `su` 命令的使用，并强制所有管理员必须先登录，然后使用 `sudo` 执行特权命令，那么所有管理员命令都将记录到 `/var/log/sudo.log`。每当执行命令时，都会触发一个审计事件，因为 `/var/log/sudo.log` 文件将被打开以写入，且执行的管理员命令将写入日志文件中。

**原理：**

`/var/log/sudo.log` 的变化表明管理员执行了命令，或者日志文件本身被篡改了。管理员希望将写入审计跟踪轨迹的事件与写入 `/var/log/sudo.log` 的记录进行关联分析，以核实是否执行了未经授权的命令。

#### 审计：

##### 磁盘配置

运行以下命令检查磁盘上的规则：

```bash
SUDO_LOG_FILE_ESCAPED=$(grep -r logfile /etc/sudoers* | sed -e 's/.*logfile=;//s/.*//' -e 's|//g' -e 's|\\|\\|g')
[ -n "${SUDO_LOG_FILE_ESCAPED}" ] && auditctl -l | awk "-w/${SUDO_LOG_FILE_ESCAPED}/ -p wa -k / key= *[!-]* *//$ -k [*!-]* /etc/audit/rules.d/*.rules*" || printf "ERROR: Variable 'SUDO_LOG_FILE_ESCAPED' is unset.\n";
```

验证输出是否匹配：

```
-w /var/log/sudo.log -p wa -k sudo_log file
```

##### 运行配置

运行以下命令检查加载的规则：

```bash
SUDO_LOG_FILE_ESCAPED=$(grep -r logfile /etc/sudoers* | sed -e 's/.*logfile=;//s/.*//' -e 's|//g' -e 's|\\|\\|g')
[ -n "${SUDO_LOG_FILE_ESCAPED}" ] && auditctl -l | awk "-w/${SUDO_LOG_FILE_ESCAPED}/ -p wa -k / key= *[!-]* *//$ -k [*!-]* /etc/audit/rules.d/*.rules*" || printf "ERROR: Variable 'SUDO_LOG_FILE_ESCAPED' is unset.\n";
```

验证输出是否匹配：

```
-w /var/log/sudo.log -p wa -k sudo_log file
```

#### 修复：

在 `/etc/audit/rules.d/` 目录下编辑或创建一个以 `.rules` 结尾的文件，并包含相关规则以监控修改 `sudo` 日志文件的事件。

例如：

```bash
UDO_LOG_FILE=$(grep -r logfile /etc/sudoers* | sed -e 's/.*.logfile//;s/$/$/' -e '$s///g')
[ -n "$UDO_LOG_FILE" ] && auditctl -w <($UDO_LOG_FILE) -p wa -k sudo_log_file || printf "ERROR: Variable 'UDO_LOG_FILE' is unset.\n"
```

合并并加载规则到活动配置：

```bash
aurules --load
```

检查是否需要重启：

```bash
if [[ $(auditctl -s | grep "enabled") ~ "2" ]]; then printf "reboot required to load rules\n"; fi
```

#### 附加信息：

##### 可能的重启

如果审计配置被锁定（`-e 2`），则 `aurules` 将无法以任何方式规则无法加载。需要重启系统。

##### 系统调用结构

出于性能考虑，最好将所有系统调用放在同一行。然而，您的配置可能是将它们分在一行或或其他组合中。对于审计和修复部分，理解这一点非常重要，因为示例是根据手册页针对性能进行了优化。

#### 4.1.3.4 确保修改日期和时间的事件被收集（自动化）

**配置适用性：**

- 级别 2 - 服务器
- 级别 2 - 工作站

**描述：**

捕获系统日期/或时间被修改的事件。此部分的参数用于确定：

- `adjtimex` - 调整内核时钟
- `setofday` - 使用时区设置时间
- `stime` - 自 1970 年以来的秒
- `clock_settime` - 设置多个内部时钟和计时器

此外，确保在退出时将记录写入审计文件，并使用 “`time-change`” 等唯一标识符标记记录。

**原理：**

系统日期或时间的意外变化可能是恶意信号。

##### 审计：64 位系统

运行以下命令检查磁盘上的规则：

```bash
awk '^-a always,exit/ -F arch=b236 -S/adjtimex/settimeday/clock_settime/ -k time-change' /etc/audit/rules.d/*.rules
awk '^-w /etc/localtime -p wa -k time-change' /etc/audit/rules.d/*.rules
```

验证输出是否匹配：

```
-a always,exit -F arch=b64 -S adjtimex,settimeday,clock_settime -k time-change
-w /etc/localtime -p wa -k time-change
```

##### 运行配置

运行以下命令检查加载的规则：

```bash
auditctl -l | awk '^\* -a always,exit/ -F arch=b236 -S/adjtimex/settimeday/clock_settime/ -k time-change'
auditctl -l | awk '^\* -w /etc/localtime -p wa -k time-change'
```

验证输出包含：

```
-a always,exit -F arch=b64 -S adjtimex,settimeday,clock_settime -k time-change
-w /etc/localtime -p wa -k time-change
```

##### 32 位系统

按照 64 位系统的相同程序进行操作，并忽略任何 `b64` 条目。此外，还要审计 `stime` 系统调用规则。例如：

```
-a always,exit -F arch=b32 -S adjtimex,settimeday,clock_settime,stime -k time-change
```

#### 修复：

**创建审计规则**

在 `/etc/audit/rules.d/` 目录下编辑或创建一个以 `.rules` 结尾的文件，并包含相关规则以监控修改日期和时间的事件。

##### 64 位系统

例如：

```bash
printf "-a always,exit -F arch=b64 -S adjtimex,settimeday,clock_settime -k time-change\n-a always,exit -F arch=b32 -S adjtimex,settimeday,clock_settime -k time-change\n-w /etc/localtime -p wa -k time-change\n" > /etc/audit/rules.d/50-time-change.rules
```

#### 4.1.3.5 确保收集了修改系统网络环境的事件（自动化）

**策略适用性：**

- 级别 2 - 服务器
- 级别 2 - 工作站

**描述：**

记录对网络环境文件或系统调用的更改。以下参数监控特定的系统调用，并在系统调用退出时写入审计事件：

- `sethostname` - 设置系统的主机名
- `setdomainname` - 设置系统的域名

正在监控的文件有：

- `/etc/issue` 和 `/etc/issue.net` - 登录前显示的消息
- `/etc/hosts` - 包含主机名及关联 IP 地址的文件
- `/etc/networks` - 网络的符号化别名称
- `/etc/network/` - 包含网络接口脚本和配置文件的目录

**原理：**

监控 `sethostname` 和 `setdomainname` 可以识别对系统主机和域名的潜在未经授权的更改。更改这些名称可能会破坏基于这些名称的安全参数。监控 `/etc/hosts` 文件是为了检测更改，这些更改可能表明未经授权的入侵者正试图更改机器与 IP 地址的关联，并诱骗用户连接到非预期的机器关联。监控 `/etc/issue` 和 `/etc/issue.net` 是重要的，因为入侵者可能向这些文件中注入虚假信息，并诱骗用户提供信息。监控 `/etc/network` 是重要的，因为它可以显示网络接口或脚本是否被修改，导致机器不可用或受到破坏。所有审计记录都应关联一个相关的标签。

**审计：**

##### 64 位系统

**磁盘配置检查**

运行以下命令检查磁盘规则：

```bash
# awk '/^*-a *always,exit/ -F *arch-b(32|64) -S/sethostname/|setdomainname/ -& key = [!~]* *$/ -k [!~]* *' /etc/audit/rules.d.*rules

# awk '/^*-w \/etc\/issue/|\/etc\/issue.net/|\/etc\/hosts/|\/etc\/network/ -p wa -& key = [!~]* *$/ -k [!~]* *' /etc/audit/rules.d.*
```

核对输出是否匹配：

```
-a always,exit -F arch=b64 -S sethostname,setdomainname -k system-locale
-a always,exit -F arch=b32 -S sethostname,setdomainname -k system-locale
-w /etc/issue -p wa -k system-locale
-w /etc/issue.net -p wa -k system-locale
-w /etc/hosts -p wa -k system-locale
-w /etc/networks -p wa -k system-locale
-w /etc/network/ -p wa -k system-locale
```

**运行中配置检查**

运行以下命令加载规则：

```bash
# auditctl -l awk '/^*-a *always,exit/ -F *arch-b(32|64) -S/sethostname/|setdomainname/ -& key = [!~]* *$/ -k [!~]* *'

# auditctl -l awk '/^*-w \/etc\/issue/|\/etc\/issue.net/|\/etc\/hosts/|\/etc\/network/ -p wa -& key = [!~]* *$/ -k [!~]* *'
```

核对输出是否包含：

```
-a always,exit -F arch=b64 -S sethostname,setdomainname -F key=system-locale
-a always,exit -F arch=b32 -S sethostname,setdomainname -F key=system-locale
-w /etc/issue -p wa -k system-locale
-w /etc/issue.net -p wa -k system-locale
-w /etc/hosts -p wa -k system-locale
-w /etc/networks -p wa -k system-locale
-w /etc/network/ -p wa -k system-locale
```

遵循与 64 位系统相同的步骤，并忽略任何包含 `b64` 的条目。
