
使用 `-i` 选项指定格式，使用 `rate`（采样）、`encoding`（编码）和 `channels`（通道）关键字来识别输入数据格式。

输出文件通过使用 `-f` 规范中的选项更新第一个输入文件的格式来生成。如果不指定 `-p`，则后续所有输入文件都将被转换并合并。输出文件包含音频文件头，除非你在输出格式中指定了 `format=raw`。

你可以使用 `-p` 选项原地转换输入文件。当 `-p` 效用时，每个输入文件的格式将根据 `-f` 选项进行修改，以确定输出格式。然后用转换后的数据覆盖现有文件。

`file(1)` 命令解码并打印 Sun 音频文件的数据格式。

用于将多道数据转换为单道数据的算法是通过简单地累加通道来实现的。如果输入数据完全同相（例如将单声道文件转换为立体声再转回单声道），则生成的数据可能包含失真。

## 选项

- `-p` 原地转换，将单个输入文件转换为 `-f` 选项指定的格式并重写它们。如果目标文件是符号链接，则将重写其底层文件。你不能结合使用 `-o` 和 `-p` 选项。
- `-F` 对于由 `-i` 选项指定格式的输入文件，忽略任何文件头。如果不指定 `-F`，`audioconvert` 将忽略包含有效音频文件头的输入文件的 `-i` 选项。
- `-f fmt` 指定输出文件的文件格式和数据编码。从输入文件格式中为未指定的字段推导默认值。有效的关键字和值列在下一节。
- `-o outfile` 合并所有输入文件，将其转换为输出格式并写入指定的输出文件。如果不指定 `-o` 或 `-p`，则将合并后的输出写入标准输出。你不能结合使用 `-p` 和 `-o` 选项。
- `-i infmt` 指定输入文件的数据。通常，输入数据源自音频文件头。当转换不带有效音频文件头的音频数据时，需要此选项。如果你为包含音频文件头的输入文件指定了 `-i`，除非也使用 `-F` 选项，否则输入格式将被忽略。格式规范与 `-f` 输出格式相同。你可以指定多个输入格式。输入格式描述了新输入文件之前的所有输入文件。

## audioconvert

`file`

合并并将命名的音频文件转换为输出格式，然后写它们。如果你不指定文件名或指定 dash (`-`)，则从标准输入读取音频数据。

`-?` 帮助：打印命令的用法信息。

# 格式规范

输入和输出格式的语法是一组关键字=值的对，中间没有空格。

```
keyword=value[, keyword=value ...]
```

如果值是唯一的，可以省略前面的 `keyword=`。

`rate` 指定每秒音频采样率。如果数字后面跟着字母 `k`，则乘以 1000（例如，`44.1k =44100`）。常用的采样率有 `8k`、`16k`、`32k`、`44.1k` 和 `48k`。

`channels` 以整数指定交错通道数。你也可以使用 `mono` 或 `stereo` 指定单或双通道数据。

`encoding` 指定数字数据表示形式。编码隐式决定精度（意味着 8 位精度）或显式作为名称的一部分（例如 `linear16`）。有效的编码值有：

- `ulaw` CCITT G71 u-law 编码主要用于电话质量的 8 位格式。
- `alaw` CCITT G71 a-law 编码主要用于欧洲电话质量的 8 位格式。
- `linear8`, `linear16`, `linear32` 脉冲调制 (PCM) 编码。名称指定位数。`linear16` 通常用于高质音频数据。
- `pcm` 与 `linear16` 相同。
- `g721` CCITT g721 格式使用 4 位精度的自适应脉冲调制 (ADPCM)。其主要用途是将 u-law 数据以 2:1 的比例压缩。
- `g723` CCITT g723 格式使用 3 位精度的自适应脉冲调制 (ADPCM)。其主要用途是将 u-law 数据以 8:3 的比例压缩。音频质量与 `g721` 相似，但在用于语音数据时可能会较低。

以下编码也可以作为采样率、通道和编码的简写：

`voice` 相当于 `encoding=ulaw, rate=8k, channels=mono`。

`cd` 相当于 `encoding=linear16, rate=44.1k, channels=stereo`。

`dat` 相当于 `encoding=linear16, rate=48k, channels=stereo`。

`format` 指定文件格式。有效的格式有：

- `sun` Sun 兼容的文件格式（默认值）。
- `raw` 读取或写入不带音频头的数据，或结合 `offset` 导入外部文件格式。
- `offset` (-仅限 i) 指定字节偏移以定位音频数据的起始。你可以使用此选项导入包含未知文件头的音频数据。

## 用法

以下示例使用命令验证音频已经转换了。

```
castle@ audioconvert -f voice | audioplay
```
