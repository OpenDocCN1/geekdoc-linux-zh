### Fsh

Fsh 代表“远程命令执行”，概念上与 rsh/rep 类似。它通过使用 ssh 建立加密隧道或在隧道上运行所有命令，避免了不断创建加密会话的消耗。你可以从这里获取：http://www.lysator.liu.se/fsh/

### secsh

secsh（Secure Shell）提供了另一层登录安全，当你通过 ssh 或 SSL telnet 登录后，系统会提示另一个密码，如果你获取了 secsh，它会终止登录尝试。你可以在这里获取 secsh：http://www.leenux.com/

## 访问

### Telnet

Telnet 是目前最古老且广为人知的远程访问工具，几乎每个 Unix 系统都带有它，甚至连 NT 系统也支持它。只有当你能从命令提示符管理系统时（NT 系统并不擅长这一点），Telnet 才会真正有用，这使其非常适用于 Unix。Telnet 极不安全，密码、用户名以及会话数据均以明文形式传输，是嗅探器的首选目标。所有 Linux 发行版都带有 Telnet。你永远不应该使用 telnet 来远程管理系统。

### SSL Telnet

SSL Telnet 在 Telnet 的基础上增加了 SSL 加密，这使其变得更加安全、更可靠。通过使用 X.509 证书（也称为个人证书），你可以轻松地管理远程系统。与 SSH 系统不同，SSL Telnet 是完全的 GNU 程序且供所有人免费使用。你可以从这里获取 SSLnet 服务器和客户端：http://ftp.replay.com/

## SSH

SSH 最初是免费的，但现在采用了商业许可，不过它具有许多功能，使其值得使用。它支持多种形式的身份验证（密码、rho、RSA 密钥），允许你重定向端口，并轻松配置允许登录哪些用户。SSH 可从这里获取：http://ftp.replay.com/。如果你打算将其用于商业，或者想获得最新版本，应该前往：http://www.ssh.fi/

### LSH

LSH 是 SSH 协议的免费实现，LSH 采用 GNU 许可，并且开始看起来是 SSH（从商业角度来看，SSH 已不再如此）的替代品。你可以从这里下载：http://www.net.lu.ac.uk/psst/，请注意它仍在开发中。

### REXEC

REXEC 是较老的远程 Unix 工具之一，它允许你在远程系统上执行命令，它有一个严重的缺陷，即没有真正的安全模型。安全性是通过使用 `hosts` 文件来实现的，该文件指定了哪些主机/等可以运行命令，但这容易受到欺骗和其他形式的攻击。你永远不应该使用 REXEC 来远程管理系统。

### Slush

Slush 基于 OpenSSL，目前支持 X.509 证书，这对于大型组织来说，这比在各种服务器上记住几十个密码要好得多（也更明智）。Slush 是 GPL 协议的，但尚未完成（它实现了大部分实用功能，但有局限性）。另一个是完全基于开源软件，使得后门/等远程访问成为可能。最终，它可以使用更优的工具替代 SSH。你可以从这里获取：http://violet.ibs.com.au/slush/

## 本地

### YaST

COAS 项目（Caldera Open Administration System）是一个非常有野心的项目，旨在为系统管理提供一个开放框架，范围涵盖了从命令行（带有半图形化界面）、X 环境内（使用 qt 组件集）到 Web 端。它通过提供一个中间层来抽象实际的配置数据，使其适用于不同的 Linux 平台。版本 1.0 刚刚发布，看起来 Caldera 终于在推进该项目。COAS 网站地址为：http://www.coas.org/。

### /etc/passwd

密码文件无疑是 Linux（以及大多数 Unix 系统）中最关键的系统文件。它包含了用户名、用户 ID（UID）以及用户所属的主组 ID（GID）的映射。它可能包含实际密码，但更可能（也安全得多）是使用影子密码将密码存储在 `/etc/shadow` 中。该文件`必须`对世界可读，否则即使是像 `edit` 简单的命令也无法正常工作。GECOS 字段可以包含真实姓名、电话号码等数据；家目录是用户交互式登录时放置的默认目录；登录 shell（login shell）必须是一个交互式 shell（如 bash 或菜单程序），并列在 `/etc/shells` 中，用户才能登录。其格式为：

```
username:password:UID:GECOS_field:home_directory:login_shell
```

### /etc/shadow

影子文件存储用户名和密码对，以及过期日期等账户信息和其他任何特殊字段。此文件必须不惜一切受到保护。

### /etc/groups

组文件包含所有的组成员信息，以及可选项目如组密码（在当前系统中通常存储在 `gshadow` 中），此文件必须对世界可读，系统才能正常运行。其格式为：

```
groupname:password:GID:member,member,member
```

一个组可以不包含成员（即未未使用）、单个成员或多个成员，密码是可选的。

### /etc/gshadow

与密码影子文件类似，此文件包含组、密码和成员。

### /etc/logins.def

该文件（`/etc/logins.def`）允许你为各种程序（如 `usadd` 和密码过期）定义一些有默认值。它在不同的发行版甚至版本之间略有不同，但通常有良好的注释并倾向于包含合理的默认值。

### /etc/shells

shells 文件包含有效 shell 列表，如果用户的默认 shell 未列在此处，他们可能无法进行交互式登录。更多信息请参见 Telnet 章节。

```
/etc/securetty
```

此文件包含 root 用户可以登录的 tty 列表。控制台 tty 通常是 `/dev/tty1` 到 `/dev/tty6`。串口（如果你想通过调制解调器以 root 登录）通常是 `/dev/tty0` 及以上。如果你允许 root 通过网络登录（这是一个非常糟糕的主意，请使用 `sudo`），则添加 `/dev/ttyp1` 及以上（如果有 30 个用户登录且 root 尝试登录，root 将来自 `/dev/ttyp31`）。通常你只应该允许 root 从 `/dev/tty1` 登录，并且建议完全禁用 root 账户。
