
创建一个遍历目录树的生成器对象。`top` 指定目录的类型，`topdown` 是一个布尔值，指示按从上而下（默认）或从自下而上的顺序遍历目录。返回的生成器产生元组 `(dirpath, dirnames, filenames)`，其中 `dirpath` 是一个包含目录路径的字符串，`dirnames` 是 `dirpath` 中所有子目录的列表（不包括目录本身）。`onerror` 参数是一个接受单个参数的函数。如果在处理过程中发生任何错误，该函数将带有 `os.error` 实例被调用。默认行为是忽略错误。如果以从上而下的方式遍历目录，对 `dirnames` 的修改将影响遍历过程。例如，如果从 `dirnames` 中删除目录，则这些目录将被跳过。默认情况下，不会跟随符号链接，除非 `followlinks` 设置为 `True`。

# 进程管理

以下函数和变量用于创建、销毁和管理进程：

`abort()`

产生一个发送到调用进程的 `SIGABRT` 信号。除非用信号处理程序捕获该信号，否则默认情况下进程将带错误终止。

`defpath`

如果环境变量中没有 `'PATH'` 变量，此变量包含 `exec*p()` 函数的默认搜索路径。

`execcl(path, arg0, arg1, ...)`

等同于 `execv(path, arg0, arg1, ...)`。

`execle(path, arg0, arg1, ..., env)`

等同于 `execve(path, arg0, arg1, ..., env)`。

`execpl(path, arg0, arg1, ...)`

等同于 `execvp(path, arg0, arg1, ...)`。

`execv(path, args)`

使用参数列表 `args` 执行程序路径，替换当前进程（即 Python 解释器）。参数列表可以是字符串的元组或列表。

## `exit(n)`

立即退出系统且状态码为 `n`，不执行任何清理操作。这通常在 `fork()` 产生的子进程中完成。这与调用 `sys.exit()` 不同，后者会执行解释器的平滑退出。退出代码 `n` 通常为 0 表示成功，而非零值表示某种错误。根据系统的不同，可能会定义一些标准代码值：

| 值 | 描述 |
|--- | --- |
| `EX_OK` | 无错误 |
| `EX_USAGE` | 用法错误 |
| `EX_DATA` | 数据错误 |
| `EX_NOINPUT` | 输入缺失 |
| `EX_NOUSER` | 用户不存在 |
| `EX_NOHOST` | 主机不存在 |
| `EX_NOTFOUND` | 未找到 |
| `EX_UNAVAILABLE` | 服务不可用 |
| `EX_SOFTWARE` | 错误 |
| `EX_OSERR` | 操作系统错误 |
| `EX_OSFILE` | 文件系统错误 |
| `EX_CANTCRE` | 无法创建 |
| `EX_IOERR` | I/O 错误 |
| `EX_TEMPFAIL` | 临时失败 |
| `EX_PROTOCOL` | 协议错误 |
| `EX_NOPERM` | 权限不足 |
| `EX_CONFIG` | 配置错误 |

`forkpty()`

使用伪终端创建子进程。返回一个元组 `(pid, fd)`，其中 `pid` 是子进程，`fd` 是伪终端主端的文件描述符。该函数仅在某些 UNIX 版本中可用。

`kill(pid, sig)`

向进程 `pid` 发送信号。信号列表可以在 `signal` 模块中找到（UNIX）。

`killpg(pgid, sig)`

向进程组 `pgid` 发送信号。信号列表可以在 `signal` 模块中找到（UNIX）。

`nice(increment)`

对调度优先级增加增量（nice 值）。返回新的 nice。通常用户只能降低进程优先级，提高优先级需要 root权限。更改优先级的影响取决于系统，降低优先级通常是为了不影响其他进程的后台运行。

`plock(op)`

将段锁定内存，防止其被交换。`op` 整数值决定锁定哪些段。`op` 的值取决于平台，通常为 `UNLOCK`、`PROLOCK`、`TXTLOCK` 或 `DATLOCK`。这些常量未由 Python 定义，但在 `<sys/lock.h>` 头文件中找到。此函数在所有平台上均可用，且通常只有有效用户 ID 为 0 (root) 时才能执行（UNIX）。

`popen(command, mode, bufsize)`

打开命令管道。返回值是一个与管道连接的文件对象，取决于模式是 `'r'`（默认）还是 `'w'`，可以读取或写入。`bufsize` 与内置 `open()` 函数同名。命令的退出状态通过返回对象的 `close()` 方法返回，除非退出状态为零，此时返回 `None`。

`spawnv(mode, path, args)`

在新进程中执行程序路径，并传递在 `args` 中指定的参数作为命令行参数。`args` 可以是列表或元组。`args` 的第一个元素应该是程序的名称。`mode` 是以下常量之一：

| 常量 | 描述 |
|--- | --- |
| `P_WAIT` | 执行程序并等待其终止。返回程序的的退出码。 |
| `P_NOWAIT` | 执行程序并返回进程句柄。 |
| `P_NONOWAIT` | 与 `P_WAIT` 相同。 |
| Constant | Description |
| :--- | :--- |
| `P_OVERLAY` | 执行程序并销毁调用进程（与 exec 函数相同）。 |
| `P_DETACH` | 执行程序并与之分离。调用程序继续运行，但不再包含派生的进程。 |

`spawnv()` 在 Windows 和某些 UNIX 版本上可用。

`spawnve(mode, path, args, env)`

在新进程中执行 `path` 路径的程序，将 `args` 中指定的参数作为命令行参数传递，并将 `env` 映射的内容作为环境传递。`args` 可以是一个列表或元组。`mode` 的含义与 `spawnv()` 中的描述相同。

```
spawnl(mode, path, argl, ..., arg)
```

与 `spawnv()` 相同，但所有参数都是作为额外参数提供的。

```
spawnle(mode, file, argl, ..., argn, env)
```

与 `spawnve()` 相同，但参数是作为参数提供的。最后一个参数是一个包含环境变量的映射。

```
spawnlp(mode, file, argl, ..., argn)
```

与 `spawnv()` 相同，但使用 `PATH` 环境变量的设置查找文件（UNIX）。

```
spawnlpe(mode, file, argl, ..., argn, env)
```

与 `spawnve()` 相同，使用 `PATH` 环境变量的设置查找文件（UNIX）。

```
spawnvp(mode, file, args)
```

与 `spawnv()` 相同，但使用 `PATH` 环境变量的设置查找文件（UNIX）。

```
spawnvpe(mode, file, args, env)
```

与 `spawnve()` 相同，但使用 `PATH` 环境变量的设置查找文件（UNIX）。

```
startfile(path, operation)
```

启动与文件路径关联。在 Windows 中，此执行的操作与在 Windows 资源管理器中双击文件相同。函数在应用程序启动后立即返回。此外，没有方法完成或退出应用程序路径。`operation` 是一个可选字符串，指定在打开 `path` 时执行的操作。默认情况下，它设置为 `'open'`，但可以设置为 `'print'`、`'edit'`、`'explore'` 或 `'find'`（列表取决于路径的类型（Windows））。

```
system(command)
```

在 shell 中执行命令（字符串）。在 Unix 上，返回值是 `wait()` 返回的进程的退出状态。在 Windows 上，退出模块提供了强大的功能，是启动子进程的首选方法。
