
`username` 是 `/etc/passwd` 文件名称名称副本。

`pswd` 字段包含 13 个字符的加密密码；空表示登录不需要密码；或者包含一个属于以下字符集 `-[0-9A-z]` 之外字符的字符串。如果密码包含加密集之外的字符，则无法登录该用户名。通常，系统管理员会在条目中使用 `*` 或 `LK*`。

`lastchg` 字段是自纪元（epoch）以来密码更改的天数。

`min` 字段是成功更改密码与另一次更改之间经过的最少天数。

`max` 字段是密码有效的最大天数。

`warn` 字段包含密码过期前用户开始收到密码即将过期的警告的天数。

`inactive` 字段是用户名在允许登录之前保持非活动的天数。

`expire` 字段是绝对天数指定。使用时，它指定了用户名何时不再被视为有效登录用户。

`flag` 字段目前未使用。

HP-UX 在受信任系统中采用了另一种方案对密码文件进行加密。每个用户名都有一个名为 `/etc/files/auth/[第一个字母]/[username]` 的文件，其中第一个字母是用户名的开头，`username` 是该用户的登录名。对于用户名 `buster`，会存在 `/etc/files/auth/b/buster` 文件。该文件包含了外观和至少数量上类似于 termcap 信息，文件中有 32 种处理可能的选项。字段名及其可能的值可以在 `prpwd(4)` 的主页中找到。通常，该文件持有：

- 从密码文件镜像的用户名和用户 ID。
- 用户的加密密码（如果有）。
- 以下内容的名称：账户所有者。如果不是账户本身，则最后更改密码的账户。最后一次成功和失败登录尝试的终端名称或主机名。
- 指明的时间：成功更改密码之间的秒数。密码何时过期（下次登录将要求用户更改密码）。密码有效期何时过期（只有系统管理员可以重新允许登录）。最后一次成功和失败密码更改或尝试的时间。账户何时过期（相对于密码更改的绝对寿命偏移）。登录之间允许的最大时间。在过期前应通知用户多久。该账户有效的登录日期。最后一次执行成功和失败的登录条目尝试的时间。
- 标志（Flags）：显示用户名是否用于启动账户。对用户名进行审计。用户是否可以选择账户密码或使用系统密码。用户是否可以为账户生成系统密码。密码是否经过了易被猜测的检查。账户是否有密码（空）。用户是否可以为密码生成“随机”字符和字母。账户是否被管理锁定。
- 指定的数字：账户的审计 ID。密码的最大长度。如果系统管理员重置了密码，账户必须为密码指定的额外随机数。在下一次成功登录之前的失败登录次数。账户锁定前允许的最大失败登录尝试次数。

Berkeley 类型的系统还有另一种类型的加密系统，使用文件 `/etc/master.passwd` 或 `/etc/spwd.db`。

## 组文件

之前提到的另一个包含组信息的文件是 `/etc/group`。它是 Unix 采用的通用保护方案的一部分：文件的冒号分隔模板显示如下：

```
group_name:password:group_id:list
```

`group_name` 字段包含组的文本名称。

`password` 字段是组加密密码的占位符。如果为空，则不需要密码。

`group_id` 字段包含该组的唯一数值值。

`list` 字段包含属于该组的用户逗号分隔列表。在 `/etc/passwd` 中指定的组的用户不会列在组中。一个示例 `/etc/group` 文件如下：

# Linux 常用命令

命令行指令构造如下：

```
useradd [-c uid comment] [-d dir] [-e expire] [-f inactive] [-g gid]
[-G gid,gid,... ]
[-m [-k skel_dir]] [-s shell] [-u uid [-o]] username
```

此外，还可以为以下项设置默认值：基础目录、expire、inactive、gid、skel_dir 和 shell。

`adduser [-batch username [gid,gid...]] [uid comment [password]]` 或者不带参数运行 `addUser` 将以交互式运行。此命令还可以设置默认值，这些将：
1. 将用户的登录或个人资料信息复制到其家目录中，
2. 将新用户设置为默认组，
3. 为新用户定义家目录分区，
4. 向新用户发送欢迎消息，
5. 为新用户设置默认 shell，
6. 从一组组中选择新用户。

```
userdel [-r] username
rmuser username
usermod [-c uid comment] [-d dir [-m]] [-e expire] [-f inactive]
[-g gid] [-G gid,gid]
[-l new username] [-s shell] [-u uid [-o]] username
```

在上述每个命令中：

`username` 是用户的登录名。

`uid comment` 是将存储在用户注释 (GECOS) 字段中的内容。

`dir` 是用户的初始目录或家目录。

`expire` 是用户名停止有效登录的绝对日期。

`inactive` 是用户名被锁定之前连续非活动的天数。

`gid` 是用户名所属的组 ID 或组名。

`new_username` 是现有用户的替换名称。

`shell` 是用户初始的 shell。

`skel_dir` 是包含文件的目录，这些文件将被复制到新创建的家目录。

`uid` 是用户的唯一标识符。

- `-m` 表示创建家目录（add）或将当前家目录文件移动到新家目录（mod）。
- `-o` 允许用户 ID 不唯一且命令依然成功。
- `-g` 为用户名选择主组。
- `-r` 为用户名选择次要组。
- `-r` 命令表示删除用户的家目录。

如果更改了用户的家目录，则必须将先的初始目录文件移动到新目录。要移动用户目录，请执行命令：

```
cd /old_dir; tar -cf - /new_dir; tar -xpf -
```

验证结果并删除 `old_dir`。如果用户并不完全了解，请在现有文件中查找 `old_dir` 并为用户更改为 `new_dir`。系统可能包含如下条目：

```
find /new_dir -exec grep -l old_dir {} \;
```

对于 `find` 找到的任何条目，将条目更改为 `new_dir`，或者在适当的情况下，将绝对路径更改为通用 `HOME` 变量。特别注意用户家目录中的以点（dot）开头的文件，因为这类文件的错误会迅速引起用户的注意。

常见的点文件包括：

| 文件 | 说明 |
| :--- | :--- |
| .login | 系统登录后执行的 Csh 和 tcsh-exec。 |
| .cshrc | 启动子 shell 时执行的 Csh-exec。 |
| .tcshrc | 启动子 shell 时执行的 Tcsh-exec。 |
| .profile | 系统登录后执行的 Sh 或 csh-exec。 |
| .kshrc | 分生新子 shell 时执行的 Ksh-exec。 |
| .bashrc | Bash 包含 shell 指令列表。 |
| .hosts | 列出的远程主机/用户名列表。登录, rexec, rsh/remsh。使用此文件允许无需密码即可进行登录、文件访问和命令处理。 |
| .netrc | FTP 自动登录过程使用。 |
| .forward | 允许邮件程序将邮件重定向到其他地址，或供程序员使用。 |
| .mailrc | 邮件的启动文件，允许设置邮件选项或别名。 |
| .exrc | ex 或 vi 的启动文件，允许设置编辑器选项。 |
| .xinitrc | X 窗口的启动文件。 |
| .xsession | X 窗口的另一个启动文件。 |
| .xdefault | X 窗口的另一个启动文件。 |

当从密码文件中删除用户名时，你必须找到该用户的所有文件并删除它们。再次使用 `find` 可以为你完成此：

```
find / -user username
```

搜索所有属于 `username` 的文件。为了安全起见，你可能想在删除之前备份这些文件。要在单个命令中搜寻并删除，可以执行后续命令：

```
find -user username -exec rm \;
```

在清理用户名文件后，应通过从组文件和系统邮件别名文件中删除用户名来修改它们。应运行新别名以更新别名数据库。

## 用户监控命令

偶尔，用户管理功能会像侦探一样工作，因为由于其他原因，机器变得过载、安全被破坏或被请求统计信息。在这种情况下， UNIX 提供了工具来收集有关普通用户或特定用户的信息。

第一类指令告诉你现在正在发生什么。这些命令可以指示是否有人获取了超过其份额的资源。此外，它们应该用于避免潜在问题，通过减少对更多 CPU、内存或磁盘资源的需求来适应你社区的需求。

`uptime` 显示当前时间、机器运行天数、登录系统的用户数以及系统负载。`uptime` 显示当前时间、机器运行天数、登录系统的用户数以及系统负载。`uptime` 显示当前时间、机器运行天数、登录系统的用户数以及系统负载。

用户登录时接收的默认 `usmask`。可能需要设置 077 的 `usmask`。用户的 `.hosts` 和 `.netrc` 文件也应该是不可读的，否则会为攻击者提供帮助。

```
find /user_directory_home \(-name .hosts -o name .netrc \) \(-perm -o=r -o -perm -g r \)
```

查找所有全局的 `.hosts` 和 `.netrc` 文件。特别是在用户目录中，系统中不应该有许多未知的设置 ID (SUID) 程序，这些程序最终会损害每个用户和整个系统。

```
find /perm -u=s
```

生成系统中所有 SUID 程序的列表。在命令中添加 `-user root` 参数可以列出所有 root 权限的 SUID 文件，你可以验证所有文件是否都处于预期的位置。Dan Farmer 的 COPS 软件包可以从网络 ftp，并配置为执行诸如之前的检查以及更深层次的安全查询。

保护用户免受伤害最好的方法是每天备份他们的文件。根据需要备份的信息量，良好的策略是进行增量备份，并每周进行一次全量备份。

该领域的另一个策略是给用户另一个 `rm` 命令，但该命令实际上不会删除文件（至少不是彻底删除）。该命令会将文件移动到一个临时存放区域，该区域会清理掉超过预定时间的文件的。

## 用户限制命令

使用磁盘配额（disk quotas）可以保护系统不被少数用户耗尽。你可以通过运行 `quota /user_filesystem` 开始限制磁盘使用。该命令允许对位于 `user_filesystem` 的用户进行精细化管理。通过执行 `edquota` 命令可以定义每个用户可以积累的量。该命令的一般形式为：

```
edquota [-p previously_defined_quota_username] username
```
