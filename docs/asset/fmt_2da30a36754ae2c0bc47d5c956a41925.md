
下一个实体定义了地址簿 `People`，所有人员都将存储在其中。它被定义为一个组织单位，这就是 `ou` 的含义。组织单位实际上只是你公司的一个任意分区。例如，你可能有用于市场营销、会计和管理部门的 `OU`。

你需要根据自己的需求自定义该文件。具体来说，将 `DCs` 改为你在 `slapd.conf` 中指定的那些。

接下来，创建并编辑一个名为 `people.ldif` 的新文件。这就是你将使用 `LDIF` 定义地址簿条目的地方。以下是我们示例中使用的联系人：

```
dn: cn=Paul Hudson,ou=People,dc=hudzilla,dc=org
objectClass: inetOrgPerson
cn: Paul Hudson
cn: Hudzilla
mail: paul@hudzilla.org
jpegPhoto: file:///home/paul/paulhudson.jpg
sn: Hudson
```

```
dn: cn=Andrew Hudson,ou=People,dc=hudzilla,dc=org
objectClass: inetOrgPerson
cn: Andrew Hudson
cn: IzAndy
mail: andrew@hudzilla.org
sn: Hudson
```

```
dn: cn=Nick Veitch,ou=People,dc=hudzilla,dc=org
objectClass: inetOrgPerson
cn: Nick Veitch
cn: CrackAttackKing
mail: nick@hudzilla.org

sn: Veitch
```

那里有三个条目，同样用空行分隔。每个人的 `DN` 由他的通用名 `CN`、组织单位 `OU` 和域组件 `DC` 组成。他还有一个 `objectClass` 定义，`inetOrgPerson`，这赋予了他标准属性，例如电子邮件地址、照片和电话号码。`inetOrgPerson` 类型的实体必须具有 `CN` 和 `SN`，因此你会在此代码中看到它们。

还要注意，每个人有两个通用名：他的真实姓名和一个昵称。并非所有 `LDAP` 客户端都支持多个 `CN`，但只要主要的 `CN` 排在第一位并出现在 `DN` 中，拥有多个 `CN` 也无妨。

### 提示

拥有多个键/值对（如多个 `CN`）是 `LDAP` 的定义性特征之一！在当今互联互通的世界，很少有人能用单一的一组属性来定义，因为人们现在拥有家庭电话、工作电话、手机号码、寻呼机号码，还有多个电子邮件地址，甚至可能还有多个可供他们共享办公的办公室。使用多个 `CN` 和其他属性，可以让你正确地记录这些复杂场景。

第一个实体的 `jpegPhoto` 属性有非常特殊的语法。在冒号之后，紧跟一个左尖括号 `<`，后面跟一个空格，然后是此人照片的位置。由于照片是本地的，因此以 `file://` 作为前缀。它位于 `/home/paul/paulhudson.jpg`，所以整个 `URL` 是 `file:///home/paul/paulhudson.jpg`。

编辑文件以包含你组织中的人员后，保存并关闭编辑器。以 `root` 身份，执行以下两条命令：

```
ldapadd -x -W -D "cn=root,dc=hudzilla,dc=org" -f base.ldif
ldapadd -x -W -D "cn=root,dc=hudzilla,dc=org" -f people.ldif
```

`ldapadd` 命令用于将 `LDIF` 转换为实时的目录内容，而且最重要的是，可以在 `LDAP` 服务器运行时执行。`-x` 参数表示仅使用基本认证，这意味着你需要提供 `root` 用户名和密码。`-W` 表示提示你输入密码。`-D` 允许你为用户名指定一个 `DN`；在 `-D` 之后紧跟的是我们之前在 `slapd.conf` 中设置的 `root DN`。最后，`-f` 表示使用来自以下文件的 `LDIF`。

当你运行它们时，系统会提示你输入之前设置的 `root` 密码。输入密码后，你应该会在条目添加时看到确认消息，如下所示：

```
adding new entry "cn=Paul Hudson,ou=People,dc=hudzilla,dc=org"
```

如果你看到类似 `ldap_bind: Can't contact LDAP server (-11)` 的错误，你需要通过输入 `/etc/init.d/slapd start` 来启动 `LDAP` 服务器。其他错误最可能的来源是输入错误。`LDIF` 是一种精确的格式，即使是在空白字符的使用上也是如此。

要测试目录是否已填充以及你的配置设置是否正确，请运行以下命令：

```
ldapsearch -x 'objectclass=*'
```

`ldapsearch` 命令的作用正如你所料：它从命令行查询 `LDAP` 目录。同样，`-x` 表示使用简单认证，尽管在这种情况下你不需要提供任何凭据，因为你只是在读取目录。`objectclass=*` 搜索指定返回任何对象类的任何条目，因此搜索将返回目录中的所有条目。

你可以修改搜索以使其更具体。例如：

```
ldapsearch -x 'cn=Ni*'
```

此命令返回所有通用名以 `Ni` 开头的人员。如果你获得了搜索结果，就可以配置客户端了。

### 提示

`OpenLDAP` 需要为它的文件设置特定权限。`/var/lib/ldap` 目录应归属于用户 `ldap` 和组 `ldap`，权限为 `600`。如果你遇到问题，请尝试运行 `chmod 600 /var/lib/ldap`。
