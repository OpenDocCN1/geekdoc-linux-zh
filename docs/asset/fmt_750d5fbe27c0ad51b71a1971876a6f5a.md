
最后一步是精确定义 `User_Alias` 组的用户可以执行哪些命令。在我们的案例中，我们有一个单独的 `User_Alias` 组，专门给可以使用 root 脚本的用户。注意，该定义还指定了可以执行命令的机器。我总是让 sudo 执行一次只在单台机器上进行，这里由 `LOCAL` 指定。

```
ROOTADMIN    LOCAL=BROOT
```

一旦设置好 `/etc/sudoers` 文件，你可以更改 root 密码并仅允许使用 root 脚本访问 root 权限。使用这种方法，你可以获得系统访问的审计轨迹。

## 发送审计日志

根据你需要的监控和审计范围，你可能想将这些文件发送到几台不同的机器。我选择电子邮件作为传输方式，但你可能有其他技术，例如自动化 FTP。你可能还想在发送邮件之前对文件进行压缩，或者对日志文件进行其他处理。要发送压缩后的文件，你需要类似 `metasend` 的工具或具有 uucoding 功能的工具。有时需要这样做，因为邮件程序会认为某些字符或控制字符会导致某些奇怪情况的发生。你应该能在网上找到一些邮件工具。

注意磁盘空间！在启动记录活动时，你需要紧密监控磁盘空间。大多数系统将邮件存储在 `/var` 中。如果你长时间导致 `/var` 满，可能会导致系统崩溃。对于日志文件，我创建了一个名为 `/usr/local/logs` 的大型专用文件系统。通过独立的文件系统，即使我填满了该文件系统，也不必担心会导致系统崩溃。你可以考虑在接收到邮件时，使用其他方法来移动这些文件。

## 压缩

对于所有这些操作，我们都使用 `compress` 命令。这种压缩算法还可以，但我们可以做得更好。我发现 `gzip` 具有更好的压缩算法，而且压缩率可以根据你的需求进行调整。调整是通过使用数字作为 `gzip` 命令的参数完成的，如下：

```
gzip -9 $LOGFILE
```

有效数字为 1 到 9，这表示额外的压缩是有代价的——数字越大，压缩文件所需的时间越长。通过省略数字，你使用的是 `gzip` 的默认模式，即 `-5`。对于我们的需求，相比 `compress`，我们仍然能看到压缩率的大幅提升，而花费的时间相当。

## 需要更安全的安全性？

这种击键审计的另一种方案是使用 `open shell`，通过创建一个命名管道（named pipe）来与服务器保持真实的加密连接。这可以实现，但存在一些潜在问题。第一个主要问题是你为记录引入了依赖。如果连接正常，日志会话就会结束。对于审计 root 活动，特别是当所有其他 root 访问都被禁用时，你可能会遇到真正的噩梦。我把这个主意留给你自己尝试，因为它超出了本书的范围。

## 通知用户

我没有将这一章加入书中，并不是为了让大家开始秘密监控每个人的击键。务必对用户社区保持透明，让他们知道审计正在进行。我确切知道系统管理员不喜欢 root 密码被他们夺走。我亲身经历过这种反应。

如果你打算更改用户密码，请将 root 密码放在安全的地方，以防紧急情况下可以及时获取密码。
你们的小组必须想出如何实现这一点。

## Sudoers 文件

如果你开始运行这些脚本并遇到问题，请先通过查看 `/etc/sudoers` 文件来检查你的 sudo 配置。有些需要注意的地方是 `visudo` 编辑器无法捕捉的：

- 检查 `LOCAL` 行。该变量应该分配你机器的主机名。
- 检查文件的精确路径。
- 确保将正确的用户分配给正确的命令。

`visudo` 编辑器可以捕捉大多数错误，但有些情况是不容易测试的。
