## 部分下划线

下划线很有用，但可能你并不想下划线整行。也许你只想下划线行中匹配正则表达式的部分。这并没有那么难实现。我们将从下划线命令开始并对其进行修改。

我们需要将复制的行拆分为将变成空白的内容和将变成下划线的内容。虽然处理这个问题有很多方法，但我的方法是在替换过程中通过插入换行符来分割行。为了清晰起见，我掉了转义反斜杠，因为剩余的反斜杠是重要的。

`s/(.*)(the).*/x\1\2/`

替换中的正则表达式部分包含两个子表达式。第一个是我们目标正则表达式之前的所有内容 `(.*)`。第二个是正则表达式本身 `(the)`。正则表达式还有第三部分 `,.*`，代表所有内容。第三部分不是子表达式，所以 `ed` 不会费心记住它。（严格来说，第三部分并不是必要的，但我发现，在几天或几年后阅读自己的代码时，明确地表示“这里可能还有东西”会更容易。）

在我们的第一组三行中，第二行只包含一个“x”，因为正则表达式匹配之前没有任何内容。第三行包含了匹配我们正则表达式的内容。

# 第 111 章：脚本

脚本是系统管理中至关重要的组成部分。在脚本中使用 `ed` 不仅会简化某些任务，还将证明你相对于所谓的系统管理员的道德优越性。

考虑我们上一章中在每行上对正则表达式加下划线的命令。你真的不想在每次需要这种转换时都输入一遍，对吧？一个可重用、可编辑的脚本要好得多。

脚本的关键在于记住 `ed` 与平级编辑器不同，它接受来自标准输入的指令。它不需要区分人类输入和脚本输入。你不能在 `ed` 脚本中包含注释，但你有各种运行它的方法。

## Ed 命令文件

使用 `ed` 脚本的最简单方法是创建一个包含要运行的所有 `ed` 命令的文件。然后像这样运行它。

```
$ ed textfile < ed-commands.ed
```

命令文件只包含你想运行的 `ed` 命令。

当你学习任何脚本方法时，从创建一个复制匹配正则表达式行的脚本开始。打开你的编辑器并跟随操作。

```bash
$ ed dup.ed
dup.ed: No such file or directory
P
*H
cannot open input file
*a
g/the/t.
,p
Q
.
*wq
14
$
```

我们打开一个 `ed` 会话并开启提示和详细错误消息。虽然 `ed` 不在乎文件不存在，但启用详细错误命令可以提醒我们已存在的错误。然后我们向缓冲区添加内容。脚本中的第一个命令是我们的朋友 `g/the/t..,` 直接来自上一章。

一旦搜索和复制完成，`,p` 命令将从头到打印文件。

我们脚本中的最后一个命令是 `q,`，立即退出而不保存。点符号带我们回到编辑会话的命令行，让我们 `wq` 保存并退出。


## Shell 脚本中的 ed

虽然命令文件对于一次性任务很好，但有时你想将 `ed` 集成到更复杂的工作流中。虽然你可以写一个调用命令文件的 shell 脚本，但没有理由不将这些命令直接集成到脚本中。

假设你有一堆运行 Wordpress 的网站。（我知道你不会以那种不体面的方式提供内容，但你的大多数客户可能无法处理像 Usenet 那样健康、优雅的内容。）需要在所有这些网站上部署像 Wordfence 这样的应用程序防火墙。`Wordfence` 需要更改每个网站的 `.htaccess` 文件。你可以进行大量容易出错的手工编辑，或者使用 `ed` 系统且可靠地为你完成这些编辑。
