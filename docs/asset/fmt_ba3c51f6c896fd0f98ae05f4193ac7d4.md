# 指定模式

如前所述，`emacs`根据你使用的文件类型提供不同的按键绑定和函数；这些被称为模式（modes）。当你未指定要编辑的文件而启动基础模式（Fundamental mode）时，emacs使用的默认模式可以被定制，使其始终默认使用另一种模式，无论文件名是什么。例如，为了设置每次启动`emacs`默认模式，你可以在`~/.gnu-emacs`中添加以下行：

```
(set-default-mode 'fundamental-mode)
```

## 使用软件包

最初，Linux中并没有“软件包”这个概念。对于那些追求组织良好、可管理且最重要的干净系统的人来说，那是一段黑暗时期。软件包是一个包含了应用程序、库或任何其他内容的文件，它可以作为一个整体被安装、删除、查询和管理。RPM（软件包管理器）格式已成为Linux的事实标准（在其他操作系统中也可用）。

在旧日子里，当你需要安装新程序时，你需要下载源代码、配置构建环境并进行编译。在安装程序时，你无法判断哪个文件属于哪个程序。这导致当你想删除或升级程序时，系统中会出现孤立文件。

RPM解决了这个问题。RPM使用一个包含系统中所有安装软件的中心数据库。你可以查询此数据库查看安装了哪些软件包、它们的版本以及它们拥有哪些文件。如果你想升级软件包，可以下载RPM并简单地告诉它你想将软件升级到后续版本。这有助于控制并抑制孤立文件，并提供了一种快速查看系统中安装了哪些软件的方法。

本章介绍使用RPM进行软件包维护。RPM是一个非常强大的系统，不仅可以安装和管理软件包，还能自动化软件构建过程以生成二进制RPM。

## 二进制RPM

一个RPM包包含应用程序的二进制文件、配置和文档。它还包含了关于它依赖于什么以及它为系统提供了什么信息（这样如果需要，其他软件包就可以依赖于你正在处理的RPM）。而源代码需要你解析并弄清楚需要哪些依赖项，但RPM已经将这些信息都包含在包本身中了。

当你安装SUSE时，大量的RPM文件会随着你选择的软件一起安装。这些RPM可能依赖其他RPM来实现功能等。依赖关系的控制由YaST自动处理。如果你想安装Mozilla，YaST会从RPM文件知道Mozilla依赖于X库等。YaST会为需要安装的RPM创建依赖树，并解决任何依赖关系以及冲突。

YaST的这一功能被证明极其有用，这意味着用户在安装时不需要手动解决包的依赖关系。

- RPM直接管理软件包，负责安装、查询和构建树。而YaST则处理RPM的功能并围绕其构建一个安装程序。YaST将解析依赖关系，为你提供有关软件包的信息，并允许你搜索介质上所有的SUSE软件包以找到你需要安装的内容。

依赖关系是RPM过程中的重要部分。RPM系统管理依赖关系这一事实，消除了手动解析源代码依赖关系的繁琐且有时困难的过程。

## 安装RPM

要安装RPM，你可以使用我们在第1章中讨论过的YaST软件包选择工具，也可以手动安装。手动安装RPM涉及使用`rpm`的命令行功能，而不是使用YaST软件包管理器。我们将讨论手动安装、查询和删除RPM包，以便你熟练地管理和检查已安装的软件。

`rpm`命令用于控制系统上所有的包操作。要安装软件包，你需要使用`-i`（install）参数。在大多数情况下，直接安装是可以的，但如果软件包已经安装（尽管版本较低），你可能需要先删除该包再安装高版本，或者使用`-U`（upgrade）参数。

## 第12章 ✦ 软件包操作

对一个没有安装更低版本的软件包进行升级，将执行直接安装，因此我们通常只使用升级参数。

为了说明我们在上一节中讨论的依赖问题，列表12-1显示了`bb-tools`软件包的安装。`bb-tools`软件包是一组作为Blackbox窗口管理器应用程序。如果你想使用Blackbox，我们建议你也安装`bb-tools`软件包。

### 列表12-1：安装bb-tools RPM包

```
media:/media/dvd/iso/i586 # rpm -Uvh bbtools-2005.1.24-3.i586.rpm
er: Failed dependencies:
blackbox is needed by bbtools-2005.1.24-3
```

我们使用了`-U`（升级）、`-v`（详细输出）和`-h`（显示哈希值）参数。`-v`和`-h`参数在提供软件包安装的反馈时通常非常有帮助。

`bb-tools`软件包依赖于许多其他软件包；其中许多在安装SUSE期间已经安装了。然而，你可以看到我们还没有安装Blackbox窗口管理器，因为RPM的依赖树可以从RPM本身告诉我们这一点。

要成功成功，你需要同时安装Blackbox和`bb-tools`。RPM系统能够安装多个RPM文件，并考虑到要安装的软件包之间是相互依赖的。这在这些情况下非常有用。列表12-2显示了`bb-tools`和Blackbox RPM同时安装。

### 列表12-2：同时安装bb-tools和Blackbox

```
media:/media/dvd/iso/i586 # rpm -Uvh bbtools-2005.1.24-3.i586.rpm blackbox-0.65-0.313.i586.rpm rpm
###################################################### [100%]
Preparing...
########################################################### [50%]
1:blackbox
2:bbtools
########################################################### [100%]
```

注意，尽管我们将`bb-tools`指定在Blackbox之前，但RPM能够在软件包安装的准备阶段看到必须先安装Blackbox。

## 查询RPM软件包

要获取某个RPM包的信息，你必须查询RPM数据库或直接查询RPM包。你通过`-q`命令行选项来实现这一点。如果你查询的是已安装的RPM，只需要使用`-q`参数配合你想使用的查询即可。如果你需要直接查询RPM软件包文件，必须添加`-p`（package）指令。

查询RPM是管理基于RPM的系统非常重要的一部分，因为你可能需要查看安装了哪个版本的软件，确定你在系统中遇到的某个文件是否由某个RPM包所有，或者属于某个RPM的列表。
