### 设置 SSH 密钥认证

Ansible 需要 SSH 密钥。要设置无密码认证，请遵循以下步骤：

- **生成 SSH 密钥**：如果管理员还没有密钥对，请使用以下命令生成一个。在提示时按回车（如果不想使用密码，请留空）。

```bash
ssh-keygen -t rsa -b 4096
```

密钥将存储在文件中：

* 私钥 `~/.ssh/id_rsa`

* 公钥 `~/.ssh/id_rsa.pub`

- **将公钥复制到远程主机**：为了实现无密码登录，使用 `ssh-copy-id` 命令将密钥复制到每个主机。第一次，系统会提示输入远程服务器的密码。

```bash
ssh-copy-id admin@172.17.0.1
ssh-copy-id admin@172.18.0.1
ssh-copy-id admin@172.19.0.1
```

- **验证 SSH 认证**：复制密钥后，测试 SSH 连接以确认无密码登录是否生效：

```bash
ssh admin@172.17.0.1
ssh admin@172.18.0.1
ssh admin@172.19.0.1
```

如果在无需输入密码的情况下登录，说明 SSH 认证设置正确。

- **测试连通性**：使用 `ping` 模块测试与受管理节点的连通性：

```bash
ansible all -m ping
```

## 编写 Ansible Playbooks
Ansible playbooks 是 YAML 文件，定义了在受管节点上执行的任务。Playbooks 允许管理员自动化复杂的工作流和配置。以下是编写简单 playbook 的方法：

### 1. 创建 Playbook

创建新的 YAML 文件，例如 `setup-webserver.yml`：

```bash
ssh-copy-id cmorera@web2
sudo nano setup-webserver.yml
```

```
---
- name: Setup Web Server
  hosts: webservers
  become: yes
tasks:
  - name: Install Nginx
    yum:
      name: nginx
      state: present
  - name: Start Nginx
    service:
      name: nginx
      state: started
      enabled: yes
```

### 2. 运行 Playbook
使用以下命令执行该 playbook：

```bash
ansible-playbook setup-webserver.yml --ask-become-pass
```

### 3. 理解 Playbook 结构
每个 playbook 由一个或多个 play 组成，这些 play 定义了目标主机和要执行的任务。任务可以包括安装软件包、管理服务、复制文件等。

## 使用 Ansible 管理基础设施

Ansible 不仅可以管理应用程序，还可以管理底层基础设施。这包括准备服务器、配置网络以及管理云资源。

### 1. 准备 AWS 资源

- Ansible 可以使用 `boto` 库与 AWS 服务进行交互。确保管理员已经在管理员环境中配置了必要的 AWS 凭证。

- 准备 EC2 实例的示例：

```yaml
  name: Provision EC2 Instance
  hosts: localhost
  tasks:
    - name: Launch EC2 Instance
      ec2:
        key_name: my-key
        instance_type: t2.micro
        image: ami-0abcdef1234567890
        wait: yes
        region: us-west-2
        group: my-security-group
        count: 1
      register: ec2
```

### 2. 配置管理
使用 Ansible 确保管理员服务器的配置是一性。例如，管理员可以在整个基础设施中强制特定的软件包安装、防火墙规则和用户账户。

### 3. 等幂性
Ansible 的核心特性之一是等幂性，这意味着多次运行相同的 playbook，如果系统已经处于所需的配置状态，则不会更改系统状态。

## 在 AWS 中自动化 Rocky Linux 部署

在 AWS 上自动化 Rocky Linux 的部署可以显著减少设置和管理管理员基础设施所需的时间和精力。以下是自动化部署的方法：

- **创建部署 Playbook：** 创建一个安装必要软件包并配置服务器的 playbook：

```yaml
  name: Deploy Rocky Linux Application
  hosts: rocky_servers
  become: yes
  tasks:
    - name: Install Required Packages
      yum:
        - httpd
        - git
      state: present
    - name: Start Apache
      service:
        name: httpd
        state: started
        enabled: yes
```

- **运行部署：** 执行该 playbook 以部署管理员应用：

```bash
ansible-playbook deploy-rocky-app.yml
```

- **与 CI/CD 集成：** `Ansible` 可以集成到 CI/CD 流水中以进一步实现自动化部署。例如，管理员可以在代码推送到仓库后，从 Jenkins 或 GitLab CI 触发 Ansible playbooks。

## 用于大规模自动化的 Ansible Tower

Ansible Tower 是一个用于大规模管理 Ansible 自动化的 Web 界面。它提供了一个易于使用的仪表板、基于角色的访问控制和作业调度功能。

### 1. 安装 Ansible Tower
Ansible Tower 可以安装在专用服务器或虚拟机上。按照官方安装指南进行设置。

### 2. 创建项目和主机清单
在 Ansible Tower 中，管理员可以创建链接到存储在版本控制系统中的管理员 playbook 项目。管理员还可以定义主机清单来管理管理员主机。

### 3. 作业模板
在 Tower 中创建作业模板，以定义如何执行 playbook。管理员可以为每个作业指定参数、主机清单和凭据。

### 4. 监控和报告
Ansible Tower 提供对作业执行的实时监控和详细报告，允许管理员跟踪管理员自动化任务的状态。
