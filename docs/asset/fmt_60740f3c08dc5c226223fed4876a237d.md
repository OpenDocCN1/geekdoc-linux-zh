# 图形

`qemu-kvm`的图形始终由两个部分组成。

- 前端 - 通过`-vga`参数控制 - 提供给虚拟机。通常是`cirrus`、`std`、`virtio`之一。默认是`qxl`，它在虚拟机兼容性和性能之间取得了很好的平衡。虚拟机需要所选项的驱动程序，这是从默认切换到`cirrus`（例如非常旧的 Windows 版本）的最常见原因。
- 后 - 通过`-display`参数控制 - 主机使用它来显示图形内容。此外，可以使用带有`gtk`的应用程序窗口或`vnc-back-end`（可以在`vnc`之外额外使用），这比默认方案更快并提供更多选项。
- 如果你完全不运行图形输出，可以使用`-nographic`来节省内存和 CPU 周期。

如果你使用`spice`运行，可以使用原生`vnc`工具或专注于虚拟化的工具（如`virt-viewer`）。更多信息请见`libvirt`部分。

上述所有内容都被视为图形的基本用法。对于进一步的需求，有高级选项。这些情况在易用性和能力上有所不同：

- 需要 3D 加速：`-vga virtio`。
- 如果使用`spice`运行，可以使用原生`vnc`工具或专注于虚拟化的工具如`virt-viewer`。更多信息请见`libvirt`部分。

```bash
$ sudo qemu-system-x86_64 -M ubuntu-q35 -cpu host -m 1024 -enable-kvm -serial stdio -display curses -append 'console=ttyS0,115200,8n1' -kernel vmlinux-5.4.0-21 -initrd boot/initrd.img-5.4.0-21-workload
```

要使用`microvm`和精简版的`qemu`运行相同的，可以执行以下操作：

1. 使用`microvm`类型运行。
2. 使用`qboot` BIOS，`-bios /usr/share/qemu/bios-microvm.bin`。
3. 安装特性最小化的`qemu-system`软件包，执行`sudo apt install qemu-system-x86-microvm`。

调用方式如下所示：

```bash
$ sudo qemu-system-x86_64 -M microvm -bios /usr/share/qemu/bios-microvm.bin -cpu host -m 1024 -enable-kvm -serial stdio -display curses -append 'console=ttyS0,115200,8n1' -kernel vmlinux-5.4.0-21 -initrd /boot/initrd.img-5.4.0-21-workload
```

这将极大地缩短`qemu`和`virt-hv`的初始化时间。你现在会比之前更多将大部分工作放在虚拟机内部完成，这意味着进一步的优化需要放在内核和用户空间的初始化时间上。

> **注意：** 对于目前的`microvm`、`qboot` BIOS以及此项的其他组件属于相当新的上游代码，尚未像虚拟化栈中的许多其他部分那样经过验证。因此，上述任何内容都不是默认设置。此外，将其作为默认还意味着许多升级用户将拒绝使用不包含他们习惯功能的`qemu`。由于`qemu-system-x86-microvm`软件包被故意设计为强选择开启，并与标准的`qemu-system-x86`软件包冲突。

# libvirt

`libvirt`库用于与不同的虚拟化技术交互。在开始使用`libvirt`之前，确保你的硬件支持 KVM 所需的虚拟化扩展。在终端提示符输入以下内容：

```bash
kvm-ok
```

系统将打印一条消息，告知你的 CPU 是否支持硬件虚拟化。

> **注意：** 在许多带有支持辅助虚拟化处理的计算机上，必须在 BIOS 中激活它。

## 虚拟网络

有几种方法允许虚拟机访问外部网络。默认的虚拟网络配置包含了桥接（bridging）和实现用户模式网络的`iptables`规则，它使用了 SLIRP 协议。流量通过主机接口 NAT 到外部网络。

为了让主机直接访问虚拟机上的服务，需要配置一种与默认不同的桥接。这允许虚拟接口通过物理接口连接到外部网络，使其在网络的其余部分看起来就像普通主机。

有一个关于如何配置所有桥接并与`libvirt`结合以让虚拟机使用`netplan.io`的优秀示例。

### 安装

要安装必要的软件包，请在终端提示符输入：

```bash
sudo apt update
sudo apt install qemu-kvm libvirt-daemon-system
```

安装`libvirt-daemon-system`后，通常管理虚拟机的用户需要被添加到`libvirt`组。对于`sudo`组的成员会自动完成，但对于其他任何访问系统级`libvirt`资源的成员，都需要手动执行。这将授予用户访问高级网络选项的权限。

在终端输入：

```bash
sudo adduser $USER libvirt
```

> **注意：** 如果用户是当前用户，你需要注销并重新登录，新的组成员身份才能生效。

你现在准备好安装客户操作系统了。安装虚拟机的过程与直接在硬件上安装操作系统的过程相同。

你可能：

- 一种自动化安装的方法 - 需要在物理机上连接键盘和显示器。
- 使用旨在自初始化的云镜像（参见`Multipass`和`UVTool`）。

在虚拟机的情况下，图形用户界面（GUI）类比在真实计算机上使用物理键盘和鼠标。与其安装 GUI，可以使用`virt-viewer`或`virt-manager`通过`VNC`连接到虚拟机的控制台。更多信息请参见`Virtual Machine Manager / Viewer`。

# virsh

有几种实用程序用于管理虚拟机和`libvirt`。`virsh`工具可以从命令行调用。示例：

- 列出正在运行的虚拟机：`virsh list`
- 启动虚拟机：`virsh start <username>`
- 同样，在启动时启动虚拟机：`virsh autostart <username>`
- 重启虚拟机：`virsh reboot <username>`
- 虚拟机的*状态*可以保存到文件中以便以后恢复。以下操作会将虚拟机状态保存到按日期命名的文件：`virsh save <username> save-my.state`
- 一旦虚拟机被恢复：`virsh restore <username> save-my.state`
- 关闭机器：`virsh shutdown <username>`
- 挂载 CDROM：`virsh attach-cdrom <username> /dev/cdrom`
- 卸载 CDROM：`virsh detach-cdrom <username> /dev/cdrom`
- 编辑配置：`virsh edit <username>`

```bash
$ sudo modprobe vfio-pci

# 识别设备

$ lspci -n -s 0005:01:01.3

0005:01:01.3 0200: 1dfe:ef2f (rev 10)

# 注册并请求 VF

$ echo 1dfe ef2f | sudo tee /sys/bus/pci/devices/vfio-pci/new_id

$ echo 4 | sudo tee /sys/bus/pci/devices/0005:01:00.0/sriov_numvfs
```

然后，你可以通过`libvirt`将虚拟机与 XML 片段关联来挂载或卸载设备。

```bash
virsh attach-device <username> <device-xml>
virsh detach-device <username> <device-xml>
```

# 通过 libvirt 访问 QEMU Monitor

QEMU Monitor 是在虚拟机运行时与`qemu`/`KVM`交互的窗口。该接口对于经验丰富的用户来说具有许多非常强大的功能。当运行`libvirt`时，该监控接口由`libvirt`为了管理目的进行绑定，但用户仍然可以通过`libvirt`运行`qemu monitor`命令。其语法为`qemu-monitor-command [options] [guest] 'command'`。
