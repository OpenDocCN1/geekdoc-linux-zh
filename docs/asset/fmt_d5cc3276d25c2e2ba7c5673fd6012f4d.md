
以下是使用`bookrec`程序源码文件进行`autoconf`过程的示例。这些文件保留在一个名为`bookrec-1.0`的目录中。`autoconf`命令接收持有源码文件的目录作为参数。确保它也包含了该程序的`makefile.in`文件。`autoconf`将在该目录下创建一个名为`configure.scan`的新文件。然后我们将`configure.scan`重命名为`configure.in`。`autoconf`只会从`configure.in`读取。

```
$ autoconf bookrec-1.0
$ ls bookrec-1.0
configure.scan io.c makefile.in
$ cd bookrec-1.0
$ mv configure.scan configure.in
$ ls
configure.in io.c makefile.in
```

接下来是一个简单的`configure.in`文件的示例。最后一行`AC_OUTPUT`宏指示`autoconf`生成`makefile`。许多此类`autoconf`宏可以包含在`configure.in`中。

```
$ cat configure.in
```

```
dnl 使用 autoconf 处理此文件以产生 configure 脚本
AC_INIT(bookrec)
dnl 检查程序
AC_PROG_CC
```

然后输入`autoconf`命令生成`configure`。你单独输入`autoconf`，不带任何参数。它会自动查找并读取`configure.in`文件。

```
$ autoconf
$ ls
configure main.c makefile
```

如果你的程序使用了特殊的头文件（例如位于特殊库中的文件），你需要执行一个行的过程来创建`config.h.in`文件。假设你的程序使用`Xview`库来创建`Xview`窗口。你的程序需要知道特定系统上`Xview`头文件的位置。`config.h.in`文件由`autohader`命令生成。`autoconf.info`文件详细介绍了如何创建此类文件。

一旦你拥有了`configure`文件，就不再需要`configure.in`文件。你只需要`configure`、`makefile.in`和源码文件以及任何头文件。`configure`文件是一个旨在独立运行的`shell`脚本。它不需要`autoconf`。

一旦另一个用户接收到软件包并解压它，只有三个步骤要执行：配置、编译和安装。`./configure`将为用户的系统生成自定义的`makefile`，`make`使用该`makefile`编译程序，`make install`将程序安装到用户的系统上。

```
./configure
make
make install
```

`make install`操作通过`make`命令执行，将文件复制到某些目录。确保将其放在原始的`makefile.in`文件中。这里了一个示例。

```
install:
  chmod 644 bookrec
  cp bookrec /usr/local/bin
```

# `rpm`

`Redhat`软件包管理器(`rpm`)旨在为系统提供方便的软件安装功能。它可以安装程序、配置文件、文档以及源代码文件。`rpm`提供了许多选项，允许你创建自己的`rpm`包。用户可以使用此类包在他们的系统上自动安装你的软件。程序、`man`页面和支持库等组件将被放置在给定系统的正确目录中。此类包可以包含可执行二进制文件或源代码文件。你可以在`www.rpm.org`网站找到关于如何使用`rpm`构建包的详细信息。该网站有详细描述该过程的`RPM-HOWTO`。

软件包创建过程设计用于让程序经过几个阶段，从从归档中解压开始，然后编译其源代码，最后生成`rpm`包。如果你的软件已经解压，可以从编译开始。如果它已经安装，你可以直接开始创建`rpm`包。

`rpm`使用三个组件来构建包：构建树(build tree)、`/etc/rpmrc`配置文件和`rpm`规范树(`rpm` spec tree)。构建树是一组用于执行打包过程不同阶段的特殊指令。`rpm`脚本包含了创建包的指令以及要放置的文件列表。`/etc/rpmrc`文件用于设置`rpm`的配置功能。`rpm`相比`/etc/rpmrc`文件有几个选项。如需获取列表，请输入：

```
$ rpm -showrc
```

下表列出的构建树目录用于存放打包过程中每个阶段生成的不同文件。`SOURCES`目录存放从该归档中解压出的源代码。`BUILD`目录是存放包含可执行程序的`rpm`包的地方，而`SRPMS`是存放包含源代码的`rpm`包的地方。如果你正在从存储在压缩归档（如`tar.gz`文件）中的软件创建包，你必须首先将该文件拷贝到构建树的`SOURCES`目录。

| 目录名称 | 说明 |
| :--- | :--- |
| `BUILD` | `rpm`执行所有构建操作的目录 |
| `SOURCES` | 你应该存放源归档文件和补丁的目录 |
| `SPECS` | 所有的规范文件(spec files)都应该存放的目录 |

`/etc/rpmrc`文件中的`topdir:`条目指定了构建树的位置。在那个文件中，你会找到一个`topdir:`条目：目前，`OpenLinux`系统已将此目录设置为`/usr/src/redhat`。在这里你将找到`SOURCES`、`BUILD`、`RPMS`和`SRPMS`目录。你可以在`/etc/rpmrc`文件中为`topdir:`条目指定不同的目录。

`topdir: /usr/src/redhat`

默认情况下，`rpm`设计用于与由名称和发布版本号（用连字符分隔）组成的目录中的源代码工作。例如，名为`bookrec`发布版本为`1.0`的程序，其源代码文件应该放在名为`bookrec-1.0`的目录中。如果`rpm`需要编译软件，它将期望在`BUILD`目录下的`bookrec-1.0`目录中找到源代码。相同的名称和发布版本也需要在规范文件(spec file)中指定。以下示例展示了如何使用包含源代码文件的`bookrec-1.0`目录对`bookrec`软件进行归档。
