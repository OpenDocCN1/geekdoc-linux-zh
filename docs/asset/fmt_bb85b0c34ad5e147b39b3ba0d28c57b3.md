
内核分配一个指向具有 `count` 个元素的信号量结构数组的项。该项还指定了数组中信号量的数量、上一次 `semget` 调用的时间以及上一次 `semctl` 调用的时间。

### semop

进程使用 `semop` 系统调用操作信号量。

```
oldval = semop (id, oplist, count);
```

- `id`：由 `semget` 返回的描述符。
- `oplist`：指向信号量操作数组的指针。
- `count`：数组的大小。
- `oldval`：在操作完成之前，集合中最后一个操作的信号量的值。

`oplist` 中每个元素的格式为：
1. 标识正在操作的信号量数组的信号量编号。
2. 操作。
3. 标志。

### semctl

包含了许多信号量的控制操作：

```
semctl (id, number, arg):
```

## UNIX SHELL 编程

具有共同通信属性（如命名规范和协议地址格式）的 socket 被分为不同的域。4.2 BSD 域系统支持用于单机进程通信的“UNIX 系统域”，以及用于跨网络通信（使用 DARPA，国防先进研究计划署）的“互联网域”。

每个 socket 都有一种类型：

- **虚拟电路（V.C.）**：允许数据的顺序可靠传输。它们很昂贵。
- **数据报（Datagrams）**：不保证顺序、可靠或不重复传输，但它们并不昂贵，因为不需要昂贵的设置操作。

socket 机制包含几个系统调用：

1. **Socket 系统调用**：建立通信链路的端点。
   ```
   sd = Socket (format, type, protocol)
   sd = Socket Descriptor
   ```
   - `format`：指定通过 socket 进行的通信类型。
   - `protocol`：指示通信的类型。

2. **bind 系统调用**：将名称与 socket 关联。
   ```
   bind (sd, address, length)
   ```
   - `address`：地址。
   - `length`：地址的长度。

3. **Connect**：连接到目标。
   ```
   connect (sd, address, length)
   ```
   - `address`：地址。
   - `length`：地址的长度。

   ![](img/3e60d797e15e867a6d5f9f3c8d5cf7c0_104_0.png)
   图 11.2 多处理器系统架构

4. **close**：关闭连接。
   ```
   close (sd)
   ```
   - `sd`：socket 的文件描述符。

5. **listen**：等待 socket 上的传入连接。
   ```
   listen (sd, backlog)
   ```
   - `sd`：socket 的文件描述符。
   - `backlog`：队列中等待连接的最大数量。

6. **accept**：接受传入的连接。
   ```
   accept (sd, address, length)
   ```
   - `sd`：新连接的文件描述符。
   - `address`：指向存储客户端地址的结构的指针。
   - `length`：指向结构大小的指针。

7. **send**：通过 socket 发送数据。
   ```
   send (sd, buffer, length, flags)
   ```
   - `sd`：socket 的文件描述符。
   - `buffer`：包含要发送数据的缓冲区指针。
   - `length`：要发送数据的长度。

8. **recv**：从 socket 接收数据。
   ```
   recv (sd, buffer, length, flags)
   ```
   - `sd`：socket 的文件描述符。
   - `buffer`：将存储数据的缓冲区指针。
   - `length`：接收数据的最大长度。

9. **shutdown**：终止连接。
   ```
   shutdown (sd)
   ```
   - `sd`：socket 的文件描述符。

## 11.2 多处理器的问题

但在多处理器上，如果两个或多个 CPU 在不同的处理器上同时执行，内核可能会损坏数据结构。

```
struct queue {
  * bp, *blp;
  blp -- torp = bp;
  /* 在此处考虑上下文切换 */
  bp -- torp = blp;
}
```

如果中断可能会损坏数据结构，那么内核在内核模式下执行时无法阻止进程并切换上下文。内核必须确保这种损坏永远不会发生。

防止此类损坏的方法有：

- I. 在一个处理器上执行所有关键活动，依赖单处理器方法。
- II. 使用锁原语对关键区域进行序列化访问。
- III. 重新设计算法以避免数据结构的竞争。

## 11.3 主从处理器的解决方案

主处理器可以在内核模式执行，而从处理器仅可以在用户模式执行。主处理器负责处理所有的系统调用和中断。

调度算法决定哪个处理器执行哪个进程。当从处理器上的进程执行系统调用时，从内核保留 PID 字段，指示该进程应仅在主处理器上运行，并进行上下文切换以调度其他进程。主内核调度，优先级最高的必须在主处理器上运行并执行。当它完成系统调用时，设置从处理器的字段，允许该进程在从处理器上运行。

从处理器上的时钟中断处理程序确保进程定期重新调度，以便没有进程垄占处理器。来自时钟处理程序的侧写每秒一次将从处理器从空闲状态中“唤醒”。从处理器会调度那些不需要在主处理器上运行的高优先级进程。

内核数据结构发生损坏的唯一机会出现在调度算法中，因为它没有防止一个进程被同时选择在两个处理器上执行。

例如，如果一个配置包含一个主处理器和两个从处理器，可能导致两个从处理器中的一个进程以用户模式执行，而另一个也在执行。如果两个处理器同时调度该进程，它们将读取、写入并损坏其地址。

系统可以避免这个问题：

- 主处理器可以指定进程应该在哪个从处理器上执行，这允许多个进程被分配给某一个处理器。一个处理器可能被分配了大量进程，而其他处理器处于空闲状态。主内核必须在各个处理器之间分配进程负载。
- 内核可以限制一次只允许一个处理器执行调度循环。

## 11.4 使用信号量的解决方案

使用这种方法支持多处理器配置的 UNIX 系统，是将内核划分为临界区域，同一时间最多有一个处理器可以在临界区域内执行代码。这里有两个问题：

- 如何实现信号量？
- 在哪里定义临界区域？

在单处理器 UNIX 系统中，各种算法使用睡眠锁来防止其他进程进入临界区域，以防第一个处理器在临界区域内部睡眠。设置锁的机制为：

```
while (lock is set) /* 测试操作 */
  sleep (condition until lock is free);
set lock:
```

并且解锁锁的机制是：
```
释放锁;
wake up (所有在条件锁设置时睡眠的进程);
```

sleep-delineate 划分某些临界区域，但它们在多处理器系统上不起作用。

## 11.4.1 信号量的定义

信号量是一个由内核操作的整数对象，它被定义了以下原子操作：

1. 将信号量初始化为非负值。
2. **P 操作**：减小信号量的值。如果减小后信号量的值小于 0，则执行 P 操作的进程将睡眠。
3. **V 操作**：增加信号量的值。如果结果导致信号量的值大于或等于 0，则一个之前因 P 操作而睡眠的进程将唤醒。
4. **条件 P 操作（CP）**：减少信号量的值，如果其值大于 0 则返回真。如果信号量的值小于或等于 0，则信号量的值保持不变且返回值为假。

如图 11.4 所示。假设一个锁是空闲的，两个处理器上的两个进程同时尝试测试并设置它。它们发现在时间 t 处锁是空闲的，于是设置了它，进入临界区域，并可能损坏内核数据结构。为了防止这种情况，锁原语必须是原子的，即测试锁状态和设置锁的操作必须作为一个单一的、不可分割的操作完成，以便同一时间只有一个进程可以操纵该锁。

## UNIX 命令

## 12.1 SHELL 简介

Shell 是一个在用户和 UNIX 操作系统之间提供解释器和接口的程序。它执行从终端或文件中读取的命令。可以创建包含命令的文件，允许用户构建自己的命令。通过这种方式，用户可以根据个人的需求和风格量身定制 UNIX。

有许多不同的 Shell。每种 Shell 在用户和 UNIX 操作系统之间都提供略有不同的接口。UNIX 中三种类型的 shell，分别是：

- Bourne Shell (波恩壳)
- C-Shell
- Korn Shell (科恩壳)

还有其他使用得不广泛的 shell，在许多机器上不可用。用户发布的命令可以在当前 shell 中运行，或者 shell 本身可以启动任何副本来运行该命令。通过这种方式，用户可以同时运行多个命令。次级称为 sub-shell（子 shell）。

当用户登录系统时，shell 会自动启动。它将监控用户的终端，等待任何命令的发布。使用的 shell 类型存储在子目录条目的 `passwd` 文件中。任何其他 shell 都可以通过发布命令作为子级 shell 运行。例如，`/usr/bin/ksh` 将运行一个 Korn shell。原始 shell 将继续后台模式运行——直到 Korn shell 终止。

UNIX/Linux 中有三种提示符：

- `#`：由超级用户或系统管理员使用。
- `$`：用于普通用户。
- `%`：用于普通用户。但在与 c-shell 工作时使用。
