### 3.5.2.4 确保存在 `nftables` 表（自动化）

**配置适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

表（`tables`）包含链（`chains`）。每个表仅有一个地址族，且仅适用于该族的数据包。表可以具有五种族中的一种。

**原理：**

`nftables` 没有任何默认表。如果没有构建表，`nftables` 将不会对网络流量进行过滤（注：此处原文为 "filter, nftables will not filter network traffic" 意为：`nftables` 将不会过滤网络流量）。

**影响：**

在运行中的 `nftables` 中添加规则可能会导致与系统的连接丢失。

**审计：**

运行以下命令验证是否存在 `nftables` 表：

```
# nft list tables
```

返回结果应包含一个 `nftables` 列表：

示例：

```
table inet filter
```

**修复措施：**

运行以下命令在 `nftables` 中创建一个表：

```
# nft create table inet <table name>
```

示例：

```
# nft create table inet filter
```

### 3.5.2.5 确保存在 `nftables` 基础链（自动化）

**配置适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

链（`chains`）是规则的容器。它们分为两种：基础链（`base chains`）和普通链（`regular chains`）。基础链是来自网络栈数据包的入口，普通链可以作为跳转目标，并用于更好地组织规则。

**原理：**

如果不存在具有输入（`input`）、转发（`forward`）和删除（`delete`）钩子（`hook`）的基础链，将流经这些链的数据包将不会被 `nftables` 处理。

**影响：**

如果通过 `ssh` 配置 `nftables`，创建一个策略为 `drop`（丢弃）的基础链会导致连接丢失。

请确保在将基础链的策略设置为 `drop` 之前，已向基础链中添加了允许 `ssh` 的规则。

**审计：**

运行以下命令并验证是否存在针对 `INPUT` 的基础链。

```
# nft list ruleset | grep 'hook input'
type filter hook input priority 0;
```

运行以下命令并验证是否存在针对 `FORWARD` 的基础链。

```
# nft list ruleset | grep 'hook forward'
type filter hook input priority 0;
```

运行以下命令并验证是否存在针对 `OUTPUT` 的基础链。

```
# nft list ruleset | grep 'hook output'
type filter hook output priority 0;
```

**修复措施：**

运行以下命令创建基础链：

```
# nft create chain inet <table name> <base chain name> type filter hook <input|output> priority 0;
```

示例：

```
# nft create chain inet filter input filter hook input priority 0;
# nft create chain inet filter forward type hook forward priority 0;
# nft create chain inet filter output type hook output priority 0;
```

### 3.5.2.6 确保配置了 `nftables` 回环流量（自动化）

**配置适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

配置环回接口以接受流量。配置所有其他接口拒绝发往环回网络的流量。

**原理：**

环回流量产生于机器上的进程之间，通常对系统的运行至关重要。环回接口是应该是环回流量的唯一地方，所有其他接口都应忽略此类流量。

**审计：**

运行以下命令验证是否配置了环回接口：

```
# nft list ruleset | grep 'hook input'
# ... 检查包含 127.0.0.0/8
```

如果系统启用了 IPv6，运行以下命令验证是否存在 IPv6 回环接口配置：

```
# nft list ruleset | grep 'ip6 ::1'
```

**修复措施：**

运行以下命令创建回环规则：

```
# nft add rule inet filter input iif lo accept
# nft add rule inet filter input ip addr 127.0.0/8 drop
```

如果系统启用了 IPv6，运行以下命令创建 IPv6 回环规则：

```
# nft add rule inet filter input iif lo accept
```

### 3.5.2.7 确保配置了 `nftables` 出站和已连接（手动）

**配置适用性：**

- Level 1 - 服务器
- Level 1 - 工作站

**描述：**

为新的出站和已建立连接配置防火墙规则。

**原理：**

如果没有为新的出站和已建立连接配置规则，所有数据包将由默认策略丢弃，导致无法使用网络。

**审计：**

运行以下命令并验证所有已建立入站连接的规则符合策略：

```
# nft list ruleset | awk '/hook input/' | grep -E 'ip protocol (tcp|udp|icmp) ct state'
```

输出应类似于：

| 规则 |
|---|
| ip protocol tcp ct state established accept |
| ip protocol udp ct state established accept |
| ip protocol icmp ct state established accept |

运行以下命令并验证所有新的和已建立出站连接的规则符合策略：

```
# nft list ruleset | awk '/hook output/' | grep -E 'ip protocol (tcp|udp|icmp) ct state'
```

输出应类似于：

| 规则 |
|---|
| ip protocol tcp ct state established,related,new accept |
| ip protocol udp ct state established,related,new accept |
| ip protocol icmp ct state established,related,new accept |

根据站点策略配置 `nftables`。以下命令将实施一项允许所有出站连接和所有已建立连接的策略策略：

```
# nft add rule inet filter input ip protocol tcp ct state established accept
# nft add rule inet filter input ip protocol udp ct state established accept
# nft add rule inet filter input ip protocol icmp ct state established accept
# nft add rule inet filter output ip protocol tcp ct state accept,related,established accept
# nft add rule inet filter output ip protocol udp ct state accept new,related,established accept
# nft add rule inet filter output ip protocol icmp ct state accept new,related,established accept
```

### 3.5.2.8 确保 `nftables` 默认拒绝防火墙策略（自动化）

**配置适用性：**

- 等级 1 - 服务器
- 等级 1 - 工作站

**描述：**

基础链策略是应用于到达链末端的数据包的默认裁决。

**原理：**

有两种策略：`accept`（接受）和 `drop`（丢弃）。如果策略设置为 `accept`，防火墙将接受任何未配置为拒绝的数据包，且数据包将继续遍历网络栈。

设置白名单允许允许的使用比列黑名单不可接受的使用要容易得多。

注意：在网络连接时更改防火墙设置可能会导致系统被锁定。

**影响：**

如果通过 `ssh` 配置 `nftables`，创建一个策略为 `drop` 的基础链会导致连接丢失。

确保在将基础链策略设置为 `drop` 之前，已向基础链中添加了允许 `ssh` 的规则。

**审计：**

运行以下命令并验证基础链包含 `DROP` 策略。

```
# nft list ruleset | grep 'hook input'

type filter hook input priority 0; policy drop;
# nft list ruleset | grep 'hook forward'

type filter hook forward priority 0; policy drop;
# nft list ruleset | grep 'hook output'

type filter hook output priority 0; policy drop;
```

**修复措施：**

针对具有 `input`、`forward` 和 `output` `hook` 的基础链运行以下命令以实施默认 `DROP` 策略：

```
# nft chain <table family> <table name> <chain name> ( policy drop \; )
示例：
# nft chain inet filter input { policy drop \; }
# nft chain inet filter forward { policy drop \; }
# nft chain inet filter output { policy drop \; }
```

**默认值：**

`accept`

### 3.5.2.10 确保 `nftables` 规则持久化（自动化）

**配置适用性：**

- 等级 1 - 服务器
- 等级 1 - 工作站

**描述：**

`nftables` 是 Linux 内核的一个子系统，提供网络包/数据报/帧的过滤和分类。`nftables` 服务读取 `/etc/nftables.conf` 以获取包含的文件。

**原理：**

对 `nftables` 规则集的更改仅影响运行系统，您还需要配置 `nftables` 规则集在启动时应用。

**审计：**
