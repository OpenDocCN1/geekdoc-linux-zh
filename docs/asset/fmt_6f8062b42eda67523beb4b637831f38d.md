
负数系数可以通过将系数的二补码表示转换为无符号长型，并将结果存储在相应的 `mult` 字段中来实现。通过 `0xFFFFFFFF` 进行掩码操作可以有效地将生成的正系数转换为负数。在许多架构上，取决于用于计算的整数类型的大小，掩码步骤将原子方式进行。

`visual` 提供了创建该调色板的 `visual` 编号。`killed` 成员提供一个资源 ID，描述此标准调色板所持有的单元是通过释放调色板 ID 释放，还是在指定的资源上调用 `XKillClient` 函数来释放。（注意，这种方法对于挂载现有的调色板是必要的。）

包含 `XStandard` 调色板信息的属性具有 `RGB COLOR_MAP`。

本节剩余部分讨论了标准调色板属性和原子，以及如何操作标准调色板。

# 标准调色板属性和原子

提供了多种标准调色板。每个标准调色板由一个属性定义，每个属性由一个原子（atom）标识。以下列表列出了原子并描述了每个原子关联的调色板。`<X11/Xatom.h>` 头文件包含了以下每个原子的定义，这些原子带有 `XA_` 前缀：

### `RGB_DEFAULT_MAP`

该属性的值是 `XStandardColormap` 结构数组。数组中的每个元素描述了由 `visual_id` 指定的 `visual` 默认调色板的 RGB 子集。

某些应用程序只需要少数 RGB 颜色，并可能从系统默认调色板中分配它们。这是理想的情况，因为系统中的活跃的调色板越少，应用程序始终以正确的颜色显示的情况就越多。

在 8 位显示器上，`RGB_DEFAULT_MAP` 的典型分配是 6 红、6 绿和 6 蓝。这提供了 216 种均匀分布的颜色（36 种不同颜色的 6 种强度），并为 256 元素调色板留下了 40 个元素用于文本、边框等的特殊颜色。

### `RGB_BEST_MAP`

此原子标识一个属性。该属性的值是一个 `XStandardColormap`。

该属性定义了屏幕上最佳 RGB 调色板。（当然，这是一种主观评估。）许多图像处理和三维应用需要使用所有可用颜色单元，并在这些单元上分布尽可能多的感知上不同的颜色。这意味着可用的绿色可能比红色多，绿色或红色也比蓝色多。

对于 8 位伪色彩（PseudoColor）`visual`，`RGB_BEST_MAP` 可能是 3/3/2 分配。对于 24 位直接色彩（DirectColor）`visual`，`RGB_BEST_MAP` 通常是 8/8/ 分配。

### `RGB_RED_MAP`, `RGB_GREEN_MAP`, `RGB_BLUE_MAP`

每个属性的值都是 `XStandardColormap`。

这些属性分别定义了全红、全绿和全蓝调色板。这些映射被想要制作颜色分离图像的应用程序使用。例如，用户可以通过在 8 位显示器上分别用红色、绿色和蓝色渲染，也可以通过相机对单帧进行多次倍数曝光来生成全彩色图像。

### `RGB_GRAY_MAP`

此原子标识一个属性。该属性的值是 `XStandardColormap`。

该属性描述了屏幕上最佳的灰度调色板。如前所述，灰度调色板仅使用 `XStandardColormap` 结构中的 `colormap`、`red_max`、`red_mult` 和 `base_pixel` 成员。

# 设置和获取标准调色板

`Xlib` 提供了用于设置和获取 `XStandardColormap` 结构的函数。

要设置 `XStandardColormap` 结构，使用 `XSetRGBColormaps`。

```
void XSetRGBColormaps(display, w, std_colormap, count, property);
```

| `display` | 指定到 X 服务器的连接。 |
| `w` | 指定窗口。 |
| `std_colormap` | 指定要使用的 `XStandardColormap` 结构。 |
| `count` | 指定调色板的数量。 |
| `property` | 指定属性名称。 |

`XSetRGBColormaps` 替换命名窗口上指定属性中的 RGB 调色板定义。如果属性不存在，`XSetRGBColormaps` 将命名窗口的指定属性中设置 RGB 调色板定义。该属性类型为 `RGB COLOR MAP`，格式为 32。随后由调用者负责处理 ICCCM 限制，即只有 `RGB_DEFAULT_MAP` 可以包含多个一个定义。

`XSetRGBColormaps` 函数通常由窗口管理器或会话管理器使用。要创建标准调色板，请遵循此程序：

- 打开新窗口。
- 获取服务器（Grab）。
- 检查属性是否在属性的列表中。
- 如果属性不存在：
    - 创建调色板（除非你使用的是默认值）。
    - 确定 `visual` 的特性。
    - 分配调色板。
    - 填充调色板。
    - 使用属性将其存储。
- 释放服务器。

`XSetRGBColormaps` 函数可能会产生 `BadAtom` 或 `Window` 错误。要获取标准调色板，使用 `XSetRGBColormaps(display, w, std_colormap, count, property)`：

| `display` | 指定到 X 服务器的连接。 |
| `w` | 指定窗口。 |
| `std_colormap` | 返回 `XStandardColormap` 结构。 |
| `count` | 返回调色板的数量。 |
| `property` | 指定属性名称。 |

合并（incorporate）按钮可能需要以下资源：标题字符串、字体、非激活状态的前景颜色、非激活状态的背景颜色、激活状态的前景颜色以及激活状态的背景颜色。每个资源都被视为按钮的一个属性，因此它都有一个名称和一个类。例如，按钮在激活状态下的前景颜色可能命名为 `"activeForeground"`，其类名可能是 `"Foreground"`。

当应用程序查找资源（例如，某种颜色）时，它会将资源的完整名称和完整类名传递给查找例程。资源管理器将此完整规范与资源数据库中条目的不完整规范进行匹配，找到最佳匹配项，并返回该条目对应的值。

资源管理器的定义包含 `<X11/resource.h>` 中。

# 资源文件语法

资源文件的语法是一系列资源行，以换行符或文件结束作为结束。单行资源行的语法如下：

```
ResourceLine = Comment | IncludeFile | ResourceSpec | <empty line>
Comment = "!" <除空字符或换行符以外的任何字符>
IncludeFile = "#" WhiteSpace "include" WhiteSpace FileNameWhiteSpace
FileName = <操作系统的有效名称>
ResourceSpec = WhiteSpace ResourceName WhiteSpace ": WhiteSpace Value
ResourceName = [Binding] Component Binding ComponentName
Binding = "<空格> <水平制表符>
WhiteSpace Component = Name(ResourceName)
ComponentName = "a-z" | "A-Z" | "0-9" | "_"
Value = <除空字符或未转义换行符以外的任何字符>
```

用竖线 (`|`) 分隔的元素表示可选。大括号 (`{...}`) 表示包含的元素零次或多次重复。方括号 (`[]`) 表示包含的元素是可选的。引号 (`"..."`) 用于围绕字面字符。

`IncludeFile` 通过将该行替换为指定文件的内容来解析。`"include"` 一词必须小写。文件名相对于出现该行所在的文件的目录进行解析（例如，如果该文件没有目录或包含相对目录规范）。

如果 `ResourceName` 包含连续的两个或多个 `Binding` 字符的序列，如果该序列仅包含 `".."` 字符，则该序列将被替换为单个 `".."` 字符；否则，该序列将被替换为单个 `".."` 字符。

资源数据库对应一个 `ResourceName` 永远包含一个条目，如果资源文件包含多个行具有相同的 `ResourceName`，则使用文件中的最后一行。

`ResourceSpec` 中名称或冒号之前或之后的任何空白字符都会被忽略。为了允许 `Value` 以空格开头

作为这些字符的示例，下面的资源行包含一个由四个字符组成的值：一个反斜杠、一个空字符、“z" 和一个换行符：

```
magic.values: \0000\nzn
```
