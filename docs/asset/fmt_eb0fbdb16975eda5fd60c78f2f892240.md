## 描述符 (Descriptors)

通过属性，对属性的访问由一组用户定义的 get、set 和 delete 函数控制。这种属性控制可以通过使用描述符对象来泛化。描述符是一个表示属性值的对象。通过实现一个或多个特殊方法 `__get__()`、`__set__()` 和 `__delete__()`，它可以钩入属性访问机制并自定义这些操作。这里有一个用例：

## 数据封装与私有属性

```python
class TypedProperty(object):
    def __init__(self, name, type, default=None):
        self.name = "" + name
        self.type = type
        self.default = default if default else type()
    def __get__(self, instance, cls):
        return getattr(instance, self.name, self.default)
    def __set__(self, instance, value):
        if not isinstance(value, self.type):
            raise TypeError("Must be a %s" % self.type)
        setattr(instance, self.name, value)
    def __delete__(self, instance):
        raise AttributeError("Can delete attribute")

class Foo(object):
    name = TypedProperty("name", str)
    num = TypedProperty("num", int, 42)
```

在此例中，类 `TypedProperty` 定义了一个描述符，在给属性赋值时会进行类型检查，如果尝试删除属性则会返回错误。例如：

```python
f = Foo()
f.name                  # 隐式调用 Foo.name.__get__(f,Foo)
f.name = "Guido"        # 调用 Foo.name.__set__(f,"Guido")
del f.name              # 调用 Foo.name.__delete__(f)
```

描述符可以在类级别实例化。在 `__init__` 和其他方法中创建描述符对象以按每个实例为基础创建描述符是不允许的。类用于存储描述符的属性名称优先级高于存储在实例上的属性。在之前的例中，描述符接收一个 `name` 参数，并且该名称通过插入下划线被更改了。为了让描述符在实例上存储值，它必须选择一个与描述符本身使用的名称不同的名称。

## 数据封装与私有属性

默认情况下，类的属性和方法是“公共的”。这意味着它们在可以在任何限制的情况下被访问。这同时也意味着在基类中定义的所有内容都会被继承并在派生类中被访问。这种行为在面向对象编程中是不可取的，因为它暴露了对象的内部实现，并可能导致类中定义的对象与基类中定义的对象之间发生命名冲突。

为了解决这个问题，类中所有以下划线开名称（例如 `__Foo`）会被自动修饰为形式如 `_ClassName__Foo` 的名称。这有效地为类提供了一种拥有私有属性和方法的方法，因为派生类中的私有名称不会与基类中的私有名称冲突。

```python
class A(object):
    def __init__(self):
        self._X = 3          # 修饰为 self._A_X
    def __spam(self):
        pass                 # 修饰为 self._A__spam
    def bar(self):
        self.__spam()        # 只调用 A.__spam
```

## 第7章 类与面向对象 编程

```python
class B(A):
    def __init__(self):
        A.__init__(self)
        self.__X = 3  # 修饰为 self._B__X
    def __span(self):      # 修饰为 _B__span
        pass
```

尽管这种方案提供了数据隐藏的幻象，但并没有严格的机制可以阻止对“私有”属性的访问。特别是如果已知类和对应的私有属性，可以使用修饰后的名称进行访问。尽管这种命名看起来像是一个额外的过程，但修饰过程实际上是在类定义时发生一次。它不会在方法执行期间发生，也不会给程序执行增加额外开销。此外，注意在 `getattr()`、`setattr()` 或 `delattr()` 等指定字符串的函数中不会发生命名。对于这些函数，你需要显式使用修饰后的名称。

## 内存管理

实例创建后通过引用计数进行管理。当引用计数为零时，实例会被销毁。当实例即将销毁时，解释器首先查找与对象关联的 `__del__()` 方法并调用它。在实践中，很少需要定义 `__del__()` 方法。唯一的例外是对象的销毁需要清理操作，例如文件、关闭网络连接或释放系统资源。即使在这些情况下，依赖 `__del__()` 来安全关闭也是危险的，因为无法保证解释器退出时会调用该方法。更好的方法是定义一个如 `close()` 的方法，程序可以使用它来明确执行关闭。

偶尔，程序会使用 `del` 语句删除对对象的引用。当对象的引用计数达到零时，`__del__()` 方法会被调用。然而，`del` 语句无法直接调用 `__del__()`。

涉及对象销毁的一个微妙危险在于，Python 的循环垃圾回收器对于实例定义的 `__del__()`（这是一个除非必要，否则不要定义 `__del__()` 的有力理由）。来自没有自动垃圾回收的语言（例如 C++）的程序员无法负担起不必要的定义 `__del__()` 的编程风格。通过定义 `__del__()` 很少破坏垃圾回收，但在某些类型的编程模式（特别是涉及父子关系或图的）中，

可能会产生问题。例如，假设你有一个实现了“观察者模式”变体的对象。

```python
class Account(object):
    def __init__(self,name,balance):
        self.name = name
        self.balance = balance
        self.observers = set()
    def __del__(self):
        for ob in self.observers:
            ob.close()
        del self.observers
    def register(self, observer):
        self.observers.add(observer)
    def unregister(self, observer):
        self.observers.remove(observer)
    def notify(self):
        for ob in self.observers:
            ob.update()
    def withdraw(self,amt):
        self.balance -= amt
        self.notify()
```
