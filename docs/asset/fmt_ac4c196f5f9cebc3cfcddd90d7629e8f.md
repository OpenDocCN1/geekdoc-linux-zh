
**注意：** 修订号可以被认为是修订控制对 UNIX 文件系统相似性的扩展。修订号标记版本的方式与目录名称标识子目录的方式非常相似。

通过分支，管理员能够在不向原始树中添加不必要目的的情况下，将现有文件的内容包含在新版本中。但当新的 shell 用户注册时会发生什么？管理员仍然必须两个地方添加相同的信息。

## 合并

没有人想重复做同样的事情，尤其是可能已经工作过载的系统管理员。但什么机制能让添加到 shell 系统的用户出现在 POP 系统中，而不会无意中将 POP 用户添加到 shell 用户列表中呢？

大多数修订控制系统都支持*合并*分支以避免手动添加更改。此过程允许管理员将主树中的条目添加到分支，而无需同时将其添加回主树。在图 23.3 中，版本 1.4 与 1.2.1.2 合并创建了版本 1.2.1.3。

**图 23.3.**

*带有单向合并的分支修订树。*

合并文件可能是一个非常复杂的过程，它是一个强大的功能，用途比我们刚刚涵盖的要多。更多信息请参阅第 24 章“我如何使用 RCS?”获取由 RCS 管理的文件合并详情，参阅第 25 章的“合并”部分获取 CVS 信息，以及第 26 章“合并修订版本”标题获取用于 SCCS 的方法。

## 文件锁定

我们已经涵盖了在进行更改之前检出文件进行编辑如何防止冲突。让我们来看一个在没有文件锁的情况下更改文件的情况。我们将参考图 23.4，Arthur 和 Beverly 正在尝试为一个大客户完成一个 Web 项目。

**图 23.4.**

*没有文件锁的双人 Web 项目。*

Arthur 获取了 `index.html` 修订 1.5 的副本并开始编辑。在他进行更改时，Beverly 也获取了 `index.html` 修订 1.5 的副本并独立地开始进行她的更改。

可以通过操作修订号来替换符号名称。当项目达到某个里程碑时，你可以同步所有文件的修订号（将它们都对齐到同一水平，例如 1.7），或者增加下一次修订的主版本号（所有文件的下一次更改将以 2.1 检入）。

第二种方法非常有效，因为当只指定主修订号时，大多数系统会自动检索最高的次要修订号。因此，如果一个项目在发布时带有版本分别为 1.1、1.5 和 1.7 的三个文件，那么下当下次检索主修订号 1 时，系统将自动检索这些版本，因为没有指定次要数字。

## 总结

在本章中，我们涵盖了修订控制背后的基本概念，以及如何使用它来管理各种活动。我们演示了用户如何首先向系统注册文件，然后检出（check out）进行编辑，最后在完成后检回（check in），以便系统感知文件的新状态。然后我们讨论了这一系列修订如何被视为一个修订树，以及如何从该树的任何点提取文件。从那里，我们涵盖了高级概念，例如通过“分支”树来创建项目的多个版本，以及如何查看文件的修订历史。

高级部分还涵盖了为了防止编辑冲突的文件锁定，以及如何让版本控制系统在文件检出时自动为文件添加注释。我们还提到了合并文件修订的过程，以及项目版本中使用符号名称和基线（baselines）。通过理解这些概念，你不仅能够选择一个源码控制系统并快速学习，还能识别出采用修订控制系统将有助于你提高效率的情况。

RCS 在第 24 章中有深入介绍，它已成为最广泛使用的“免费”修订控制系统，这主要是因为具有符号名称等高级功能，并且在所有 UNIX 变体中可用。它还是 CVS 的基础，CVS 在第 25 章中有深入介绍。CVS 存在许多网络开发环境中，因为它简化了跟踪更改的同时以控制的方式分发文件的过程。

第 26 章介绍了 SCCS，它是最学习的修订控制系统，也是经常与 UNIX 变体捆绑的系统。它通常用于需要基本文件锁定和备份能力的单双人项目。

# RCS 简介

作者：Bill Ball

对于经验丰富的计算机用户来说，跟踪软件和文档的更改并组织和控制这些更改可能是一项艰巨的任务。但得益于修订控制系统（RCS），你可以利用计算机来掌控关键软件和文档项目。尽管它有许多名称，如代码管理、源码控制或配置管理，但修订控制可以帮助你组织项目生产流程。

## 什么是 RCS？

RCS 是由 Walter F. Tichy 在 20 世纪 80 年代初于印第纳大学开发的，其部分程序的起源可以追溯到 70 年代中期到晚期。早在*协作软件*（groupware）等术语流行之前，RCS 就被用于自动处理程序修订的存储、检索、记录、识别和合并。由于其简单性、高效性和可用性，它仍然是目前最流行的版本控制系统。正如你在本章后面将看到的，RCS 能够提供的帮助比程序开发多得多。

你通常可以在你的系统中找到以下程序。它们包含了 GNU 版本 RCS（版本 5.7）：

- `ci`: 检入 RCS 修订
- `co`: 检出 RCS 修订
- `ident`: 识别文件中的 RCS 关键字字符串
- `rcs`: 修改 RCS 文件属性
- `rcsclean`: 清理工作文件
- `rcsdiff`: 比较 RCS 修订
- `rcsmerge`: 修改 RCS 文件属性（注：OCR 可能想表达“合并”，但文本写的是“修改 RCS 文件属性”）
- `rlog`: 打印关于你 RCS 文件的日志消息和其他信息

## 为什么使用 RCS？

UNIX 有许多不同的修订控制系统。以下是其中一些：

- CLEAR/CASTER
- SCCS
- SDC
- CMS
- CVS
- UCM
- ClearCase
- Continuus

通常，所有的版本控制系统都为作者或经理提供维护源文档不同版本的方法。在很多情况下，能够检索程序的原始版本或维护同一程序的不同版本是非常重要的。通过使用 RCS，你可以跟踪软件包的所有更改，维护具有不同特征的版本，为不同的系统开发新版本，并为早期版本提供维护发布，而不会在多人共同处理同一文件时产生可能的混淆。

## 我如何使用 RCS？

RCS 之所以受欢迎的原因之一是它的简单性。大部分工作通过 `ci` 和 `co` 命令完成。下面的简单示例展示了如何使用 RCS。首先，为你的项目创建一个目录并命名为 `myproject`，如下：

`# mkdir myproject`

然后使用 `cd` 进入 `myproject` 目录并创建一个名为 `RCS` 的目录：

`# cd myproject`

`# mkdir RCS`

接下来，在你的编辑器中输入以下源码，并将其保存为 `myproject` 中的 `foo.c`：

```c
/* $Header$ */
#include <stdio.h>
static char rcsid[] = "$Header$";
main() {
    printf("hello, world!\n");
}
```

验证你目录的内容：

`# ls`

（输出：`.  RCS  foo.c`）
