
`vpath`：清除之前通过 `vpath` 指令指定的所有搜索路径。

`vpath pattern` 是一个包含 `%` 字符的字符串。该字符串必须匹配正在搜索的先置条件的文件名（类似于模式中的字符匹配任意零个或多个字符的序列（在模式规则中；见第 10.5 节 [定义和重新定义模式]，第 109 页））。

例如，`%.h` 匹配以 .h 结尾的文件（如果没有 `%`，则模式必须精确匹配先置条件，这通常并不常见）。

`vpath` 指令模式中的 `%` 字符可以用前面的反斜杠 (`\`) 进行转义。原本会转义 `%` 字符的反斜杠可以用更多的反斜杠进行转义。用于转义 `%` 字符或其他反斜杠的反斜杠在与文件名比较之前会从模式中移除。没有转义 `%` 字符风险的反斜杠则保持不变。

当先置条件在当前目录中不存在时，如果 `vpath` 指令的模式匹配先置条件的文件名，则搜索该指令中的目录，其方式类似于（且早于）`VPATH` 变量中的目录。

例如，

```
vpath %.h ../headers
```

告诉 `make` 如果在当前目录未找到文件，则在目录 `../headers` 中查找任何以 .h 结尾的先置条件。

如果多个 `vpath` 模式匹配先置条件的文件名，`make` 将逐个执行匹配的 `vpath` 指令，搜索每个指令中提到的所有目录。`make` 按照它们在 Makefile 中出现的顺序处理多个 `vpath` 指令；具有相同模式的多个指令之间是相互独立的。

因此，

```
vpath %.c foo
vpath %   blish
vpath %.c bar
```

将先在 `foo` 中查找以 .c 结尾的文件，然后是 `blish`，然后是 `bar`，然后：

```
vpath %.c foo:bar
vpath %     blish
```

将先在 `foo` 中查找以 .c 结尾的文件，然后是 `bar`，然后是 `blish`。

### 4.3.3 目录搜索是如何执行的

通过目录搜索找到先置条件时，无论何种类型（通用或选择性），定位的路径可能并非先置条件列表中实际提供给你的路径。有时，通过目录搜索发现的路径会被丢弃。

用于决定保留还是放弃通过目录搜索找到的路径的算法如下：

- 1. 如果目标文件在 Makefile 指定的路径不存在，则执行目录搜索。
- 2. 如果目录搜索成功，则保留该路径并将该文件暂存为目标。
- 3. 使用相同方法检查该目标的所有先置条件。
- 4. 在处理完先置条件后，目标可能需要也可能不需要重建：
  - 如果目标不需要重建，则在目录搜索期间找到的文件路径将用于任何包含该目标的先置条件列表。简而言之，如果 `make` 不需要重建目标，你就会使用通过目录搜索找到的路径。
  - 如果目标需要重建（已过期），则目录搜索期间找到的路径将被丢弃，并使用 Makefile 中指定的文件重建目标。简而言之，如果 `make` 必须重建，则目标将在本地重建，而不是在目录搜索找到的目录中重建。

这个算法看起来很复杂，但在实践中它恰恰是你想要的。

其他版本的 `make` 使用更简单的算法：如果文件不存在且通过目录搜索找到，无论目标是否需要构建，始终使用该路径。因此，如果目标需要重建，它将在目录搜索期间发现的路径处创建。

如果实际上这正是你对部分或所有目录所期望的行为，你可以使用 `PATH` 变量来指示这一点，或者 `-PATH` 具有与 `VPATH` 相同的语法和格式（即由空格或冒号分隔的路径列表）。如果在同时也出现在 `PATH` 中的目录中通过目录搜索发现了过期的目标，则该路径不会被丢弃。

### 4.3.4 编写 Shell 命令

当通过目录搜索在另一个目录找到先置条件时，这不会改变规则的命令；它们将按原写的方式执行。因此，你必须仔细编写命令，以便它们能在 `make` 找到先置条件的目录中查找。

这是通过自动变量 `$^` 实现的（见 [自动变量]，第 111 页）。例如，`$^` 的值是所有先置条件的列表，包括它们所在的目录名称，而 `$@` 的值是目标。因此：

```
foo.o : foo.c
  cc $(CFLAGS) ^ -o $@
```

### 4.3.5 目录搜索与隐含规则

通过 `VPATH` 或 `vpath` 指定目录搜索也会发生在考虑隐含规则期间（见第 10 章 [隐含规则]，第 101 页）。

例如，当文件 `foo.o` 没有显式规则时，`make` 会考虑隐含规则，例如编译 `foo.c` 的内置规则。如果该文件在当前目录缺失，则会对相应的目录进行搜索。如果 `foo.c` 存在于任何目录中（或在 Makefile 中提到），则应用 C 编译的隐含规则。

隐含规则的命令通常会使用自动变量；因此它们无需额外努力就能使用目录搜索找到的文件名。

### 4.3.6 链接库的目录搜索

目录搜索以特殊方式应用于与链接器使用的库。当你编写一个名称形式为 `-lname` 的先置条件时，这一特殊功能就会生效。（你可以判断出发生了异常，因为先置条件通常是文件名，而库的文件名通常看起来像 `libname.a`，而不是 `libname.o`）。

当先置条件的形式为 `-lname` 时，`make` 会对其进行特殊处理，在当前目录、由匹配的 `vpath` 搜索路径指定的目录以及 `VPATH` 搜索路径指定的目录中进行搜索，最后在 `/lib`、`/usr/lib` 和 `prefix/lib` 目录（通常为 `/usr/local/lib`，但 MS-DOS/MS-Windows 版本的 `make` 取决于 `prefix` 定义为 DJG 安装树的根目录）中搜索文件 `libname.so`。

如果未找到该文件，则将在与上方相同的目录中搜索 `libname.a` 文件。

例如，如果你的系统上存在 `/usr/lib/libcurses.a` 库（且没有 `/usr/lib/libcurses.so` 文件），

```
foo foo.c -lcurses
cc $ -o $
```

当 `foo` 比 `foo.c` 旧或比 `/usr/lib/libcurses.a` 旧时，这将会导致执行命令 `cc foo.c /usr/lib/libcurses.a -o foo`。

虽然默认的待搜索文件集是 `libname.so` 和 `libname.a`，但此可以通过 `.LIBPATTERNS` 变量进行自定义。该变量中的每个单词都是一个模式字符串。当看到像 `-name` 这样的前提条件时，`make` 会将列表中每个模式中的 `%` 替换为 `name`，并使用该库文件名执行上述目录搜索。如果没有找到相应的库，则将使用列表中的下一个单词。

`.LIBPATTERNS` 的默认值为 `'lib%.so lib%.a'`，它提供了上述描述的默认行为。

你可以通过将此变量设置为空值来完全关闭库扩展。

### 4.4 伪目标 (Phony Targets)

伪目标（phony target）不是一个真实的文件名。它只是在收到显式请求时执行某些命令的名称。使用伪目标目标有两个原因：避免与同名文件冲突，以及提高性能。

如果你编写的规则其命令不会创建该目标，那么每当该目标需要重新制作时，这些命令都会被执行。这里有一个示例：

```
clean:
rm *.temp
```

由于 `rm` 命令不会创建一个名为 `clean` 的文件，可能永远不会存在这样的文件。因此，每当你说 `make clean` 时，`rm` 命令都会被执行。

如果此目录中任何操作创建了名为 `clean` 的文件，伪目标将停止工作。由于它没有前提条件，文件 `clean` 将不可避免地被认为是最新的，其命令将不会被执行。为了避免这个问题，你可以使用特殊目标 `.PHONY` 显式声明该目标为伪目标（参见第 4.7 节 [特殊内置目标]，第 30 页），如下所示：

- `.PHONY: clean`

一旦完成，无论是否存在名为 `clean` 的文件，`make clean` 都会运行命令。

```
SUBDIRS = foo bar baz

.PHONY: subdirs $(SUBDIRS)

subdirs: $(SUBDIRS)

$(SUBDIRS):
  $(MAKE) -C $$$

foo: baz
```

# 第 4 章：编写规则

在这里我们还声明了 `foo` 子目录在 `baz` 子目录完成之前不能构建；这种关系声明在尝试并行构建时尤为重要。

伪目标不应该是真实目标文件的前提条件；如果是 true 的，那么每当 `make` 尝试更新该文件时，它的命令都会运行。只要伪目标从不是真实目标的前提条件，伪目标的命令就只会在伪目标作为指定目标时执行（参见第 9.2 节 [指定目标的参数]，第 89 页）。
