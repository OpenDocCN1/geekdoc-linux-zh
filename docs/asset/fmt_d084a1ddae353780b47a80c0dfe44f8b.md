## 自动化 FTP 操作

注意本地远程目录是硬编码在 shell 脚本中的。如果你愿意，可以修改此 shell 脚本并使用 `getopts` 来解析某些命令行开关。这超出了本章的基本概念。

由于我们现在要求命令行上有一个单独参数，我们还需要向此 shell 脚本添加一个用法函数。我们正在寻找恰好一个行参数。如果不是如此，我们就执行 `usage_error` 函数，该函数反过来又执行 `usage` 函数。

由于命令行上可能指定了多个文件名，我们需要使用 `ftp mget` 而不是 `get`。我们已经通过使用 ftp 命令的 `-i` 关闭了交互式提示，因此在使用 `mget` 时不会有提示。

## 前事件和后事件

注意列表 17.5，我们添加了两个函数：`pre_event` 和 `post_event`。默认情况下，这两个函数只能是空操作字符 `:`（冒号）。一个 `:` 什么都不做，但返回码为 0（零）。我们将其用作函数中某些内容的占位符。

如果你决定在 ftp 活动之前或之后执行任务，请在 `pre_event` 和/或 `post_event` 函数中输入任务。只输入外部 shell 脚本的文件名比编辑此 shell 脚本并尝试在已运行的 shell 脚本中调试函数要好。只需要一个可执行的外部脚本文件名即可执行前、后事件。

在 shell 脚本中输入所有为 ftp 文件传输设置环境的内容。你可能想要执行的操作包括：在下载新文件之前从目录中删除旧文件，或者获取远程主机的目录列表以查看可下载的内容。你可以根据需要缩短代码以完成当前的任务。

## 用变量替换硬编码密码

传统上，当我们在 shell 脚本中使用这种硬编码技术时，会面临许多挑战，从安全噩梦到无法定期更改关键密码。本节中介绍的变量技术非常容易实现，只需对每个 shell 脚本进行细小的更改即可。

# 自动化 FTP 工具 453

**注意** 重要：*每个 shell 脚本都必须更改，以便在整个基础设施中正确实现该技术。*

变量替换技术由单个文件组成，该文件包含系统中 shell 脚本所需的每个密码的唯一变量赋值。示例密码文件如下：

```bash
DBORAPW=alpha

DBADPW=beta

BACKUPW=gamma

RANDY=password
```

实现此变量替换技术的一些考虑因素包括：

- 包含密码的变量的作用范围可见
- 包含硬编码密码的密码变量文件的文件权限

为了限制变量的作用范围，极其重要的一点是**不要**在密码变量文件中导出（export）。如果变量被导出，那么你将在使用密码变量的 shell 脚本的环境中以*明文*看到密码。此外，由于所有密码都在同一个文件中，该文件必须由 root 身份锁定为*只读*。

该技术的最佳说明是其工作方式的真实示例。在下面的代码段中（显示在列表 17.8、17.9、17.10 中），有一个包含密码变量赋值的密码文件，名为 `setpwenv.ksh`（注意此文件是一个脚本！）。在第一个文件中，密码变量**被**导出了。在第二个文件中，密码变量**没有**被导出。这两个文件之后的是一个 shell 脚本 `pwdtest.ksh`，它执行密码环境文件 `setpwenv.ksh`，并测试密码在环境中是否可见。

**注意** 使用每种技术的测试结果详见本章的下一节。
