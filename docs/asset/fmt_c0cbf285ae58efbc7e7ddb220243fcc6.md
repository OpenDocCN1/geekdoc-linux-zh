`man` 命令根据命令或主题名称搜索文档。因此，命令

```
man ls
```

为我们提供了关于 `ls` 命令的文档，它恰好位于第一部分（section one）。

尽管 `man` 页面看起来简单，但它们实际上具有复杂的结构。这些页面被分为若干章节，其中某些章节进一步细分为子章节。

章节布局如下：

- 用户命令--如 `ls`、`tar` 和 `cpio` 这样的命令。
- 系统调用--被视为系统调用的 C 语言函数，例如打开和关闭文件。
- C 库函数--不被视为系统调用的 C 语言函数，例如打印文本。
- 文件格式--文件布局的描述，如 `hosts.equiv` 和 `inetd.conf`。
- 头、表格和宏--杂杂文档，例如尚未涵盖的字符集和头文件。
- 游戏和演示--游戏软件。（即使是 UNIX 版 Doom 也有 man 页面！）

这是一个通用的目录。BSD 和 System V 初始的章节方案略有不同，厂商会添加自己的章节并进行自己的“改进”（还能有别的方式吗呢？）

为了查看每个章节的信息，我们可以查看该章节的介绍页（intro page）。为了查看每个章节的信息，我们执行以下命令：

```
man -s 1 intro
```

`-s` 选项用于 System V 版本的 `man` 命令选择搜索哪些 man 页面。BSD 版本接受章节号作为第一个参数且不带开关，而 Linux 将从环境变量或 `-s` 选项中选择章节。

所有版本都接受 `-a` 选项，它强制 `man` 命令搜索所有章节并显示所有匹配的页面。由于存在同名的不同页面，了解不同的章节以及每个章节包含的内容是有帮助的。然而，还有额外的工具，没有必要记忆每个章节的布局。

`man` 页面可以使用名为 `catman` 的工具进行索引和预格式化。预格式化部分使页面显示更快，并允许我们使用更强大的检索工具，即 `what` 和 `apropos`。

`apropos` 显示包含指定关键字的页面的章节号、名称和描述。`what` 为我们提供 man 页面名称和章节号。

例如，让我们尝试对关键字 `nfs` 使用 `apropos` 命令：

```bash
apropos nfs
```

响应的一部分如下：

| autoumount (8) | 自动挂载 NFS 文件系统 |
| exports (8) | 向 NFS 客户端导出和取消目录 |
| exports, xtab (5) | 导出到 NFS 客户端的目录 |
| nfs, NFS (4P) | 网络文件系统 |
| nfsd, biod (8) | NFS 守护进程 |

（输出经过编辑，因为实际请求返回了12个响应。）

现在让我们尝试 `what`：

```bash
whatis nfs
```

`nfs`, `NFS` (4P) 网络文件系统

通过 `whatis`，我们只看到实际 nfs 手册页的名称及其章节号。

## UNIX 安装基础

在机器上安装 UNIX 比安装 DOS 或 Microsoft Windows 需要经过更多的思考。你需要决定该系统是独立运行的，还是依赖于网络上的服务器。你还必须密切关注系统资源（如硬盘空间、处理器速度、内存等），以及需要哪些包来根据你的需求（可能也是未来用户的需求）来定制此 UNIX 系统。

为什么呢？DOS 是一个磁盘空间小于 10 MB 的系统。Windows 占用的空间稍多一点，但仍然很小。UNIX 是一个取决于配置的大型系统。例如，Sun 的 `Solaris 2.3` 仅操作系统及其所有附属内容的完整安装程序大约就有 300 MB。在使用如此多磁盘空间的情况下，在多个系统之间共享它通常是明智的。此外，安装 DOS 或 Windows 时，安装程序可以完成的配置选项较少。UNIX 将安装分为许多不同的部分，称为“包”（packages）。每个包由提供特定功能的文件组成。这些功能涵盖了网络工具、必要的系统实用程序、应用程序等。根据你的需求，许多包可以安装在本地、远程安装在服务器上，或者完全不安装。

你还必须考虑提供的各种 UNIX 版本，以及你需要花费的费用。Linux 是免费的，可以通过互联网或 CD-ROM 公开放。FreeBSD 和 NetBSD 是基于 BSD 的操作系统示例；它们通常被用于更大、更具任务关键性的站点；且它们也是免费的。如果你从未用过任何 UNIX 版本，应该根据你的需求和预期对它们进行尝试。

> **提示**：Linux 和 FreeBSD 都可以通过 Walnut 的 CD-ROM 获取。其网址地址是 http://www.cdrom.com。

FreeBSD 的网页为 http://www.freebsd.org。

NetBSD 的地址为 http://www.netbsd.org。

Linux 的网页为 http://www.linux.org。

另外，你还有如 BSDI、SCO、Unixware、NeXT、Solaris 等商业操作系统。这些系统通常很贵，尽管它们提供电话技术支持和打印文档。如果你处于任务关键型，并且可能在未来服务器发生任何灾难性事件时有人可以依靠，这些就是你需要考虑的因素。

## 不同发行版之间有什么区别？

虽然我无法遍历每一个可用发行版，但我将对这些优秀的 Unix 操作系统进行简要描述。

- Unixware 基于 Svr4，最初由 AT&T 开发。Novell 曾控制过它一段时间，现在由 SCO 为其进行开发。Unixware 主要运行在 x86（Intel 或 100% 兼容）的机器上。
- BSDI Internet Server 是由伯克利大学最初设计和编写的 BSD/OS 商业软件。BSDI 引入了 BSD/OS 并添加了许多新的实用程序、程序和功能，使该发行版成为任何企业互联网或互联网网关非常稳定且高效的补充。它的主要关注点在于其完美的网络能力，面向互联网服务提供商（ISP）。BSD 运行在所有 x86（Intel 或 100% 兼容）机器上。
- FreeBSD 和 NetBSD 是 BSDI Server 的替代方案。它们包含了许多让 BSD/OS 非常受欢迎的优秀功能，但缺乏商业发行版的专业支持。如果你不需要电话技术支持，并且希望在专注于互联网/局域网的操作系统中所寻求稳定性和可靠性，这些正适合你。我提到这两个版本是因为 FreeBSD 运行在 x86 平台上，而 NetBSD 运行在以下平台：De M、Alpha、Acorn RiscPC、Atari、HP/9000 系列、x86、m86k Macintosh、PowerPC、SPARC 服务器、Sun 3、DEC VAX 等。NetBSD 是目前可移植性最高的操作系统，而 FreeBSD 似乎是 x86 用户更受欢迎的选择。
- SCO 的 OpenServer 是 UNIX 的另一种变体，它基于微软开发的操作系统 XENIS。它在企业服务器上非常流行，尽管它缺乏 BSD 的多功能性。它的技术支持是无可比拟的，这就是为什么许多公司选择此操作系统作为他们的服务器。SCO 还拥有一系列应用程序——如 Word 和 Excel 等微软产品。
- Linux (RedHat)、Slackware、Debian 等最初开发自 Minix 源码。它始于爱好，成长为一个频繁更新、完善且受支持的操作系统。Linux 很大程度上基于 POSIX 标准，SysV 拥有广泛的应用（比 SCO 多），并且也是免费的。有许多发行版可用（例如 RedHat 的 Appliance）。Linux 在初次使用 UNIX 用户中非常流行，且安装简单。Linux 频繁更新内核，其稳定性并不总是如人们所希望。虽然 Linux 在工作站上非常流行，但它通常不被赋予任务关键型服务器的任务，因为它缺乏像 BSDI Server 这种高质量专业开发操作系统的支持、稳定性和功能。

到目前，本章仅触及了磁盘安装。仍有许多内容需要讨论。你必须为用户、网络及其流量、应用程序、打印机、远程访问、备份、安全性等进行规划。

因此，规划 UNIX 安装不仅需要为该系统进行规划，还需要为网络中的所有系统进行规划。

## 谁将使用此系统？

用户通常使用机器进行文字处理和其他通用办公应用，不需要极大量的磁盘空间或系统资源。然而，高级用户或应用程序开发者需要安装更多内容，包括编译器和开发库。为了决定在局域网（LAN）的这一网段上安装什么（更不用说在该系统上了），你需要确定哪些类型的用户将使用该系统。

> 提示：用户类型不仅决定了安装什么，它还会决定该局域网网段可以放置多少台系统、服务器容量以及交换空间的需求。

## 哪些类型的用户

UNIX 用户通常分为以下几类中的一种或多类：

- **应用程序用户。** 这些用户运行商业或本地开发的应用程序。他们很少与 shell 直接交互，也不编写自己的程序。这些用户可能正在运行数据库应用程序、文字处理器或桌面出版系统、电子表格或某些内部开发的程序集。他们大部分时间处于“思考模式”下，即决定如何处理呈现的结果；或者处于“数据输入模式”下，向系统输入响应或数据。他们对大量磁盘访问的需求极低，而且不会频繁更改应用程序，也不会同时运行许多程序。（尽管他们开启了程序，但通常一次只与其中几个进行交互——其他的都在等待用户输入。）尽管应用程序用户可能会给数据库服务器带来巨大负载，但他们通常不会给系统带来负载。
- **高级用户。** 这些用户像应用程序用户一样运行程序，但还会运行脚本并与系统进行更紧密的交互。他们可能同时运行多个应用程序，所有程序并行处理。这些用户使用多个应用程序频繁地访问磁盘，并比普通应用程序用户消耗更多资源。
- **开发者。** 开发者不仅运行程序，还运行编译器，访问与用户不同的应用程序，需要访问开发库，并且通常比用户使用更多的操作系统组件。此外，他们需要使用调试工具，这些工具比应用程序用户通常需要更多的交换空间和更多的磁盘资源访问。UNIX 操作系统包含只有开发者需要的软件包，如果这是局域网的一个网段，这些文件必须安装并供开发者使用的系统访问。编译会消耗大量的处理器性能；因此，你必须通过合适的系统类型来满足这一需求。十名程序员并行编译 10,000 行代码就能轻松让一台 200 MHz 的 Pentium 卡顿。

> 提示：你不应该只考虑谁将使用系统，而是由于你只用一次 UNIX，要考虑未来六个月到一年内谁可能会使用该系统。记住，取决于你设置的是什么类型的用户，你将向机器中添加用户。如果他们使用的程序不可用，你将被迫重新安装整个系统，或者根据操作系统安装适当的软件包。由于如今硬件成本很低，你投资额外的硬件并安装所有未来可能对其他人有用的软件包是更明智的。

**出于什么目的？** UNIX 系统被用作共享开发机或准备被放置在公共用户区域，需要大量的交换空间和大量的磁盘空间存放临时文件。与在单用户设备上使用的系统相比，它们还需要更多的操作系统软件包。此外，如果系统将用作计算或数据库服务器，它需要增加交换空间和处理器性能。

## 局域网的该网段上还有哪些系统？

正如“从开始需要知道什么？”节所示，你必须考虑该局域网网段上的所有系统。你正在寻找那些提供操作系统部分访问、提供应用程序磁盘访问、拥有足够的内存资源来容纳你的客户，并为其他系统提供合适服务器的系统。

如果你有一个装满相同机器的办公室或实验室，运行所有应用程序而不需要任何重大定制，那么采用集中式安装会更容易维护。但由于我们现在有了硬件、16 倍容量的 CD-ROM（传输速度最高可达 700 kbps）以及速度在 10Mbps 到 100Mbps 之间的以太网（分别为以太网和快速以太网），因此通过网络安装非常容易。升级机器也一样，只需提供操作系统的升级；这完全取决于机器在网段上的功能。

**确定合适的服务器**通常比确定合适的客户端更容易确定服务器，所以何从这里开始。要构建一个良好的服务器系统，你需要以下条件：

- **充足的 RAM--** 服务器必须有大量的可用 RAM 供其使用。你的服务器必须能够处理许多客户端，每个客户端同时运行进程。为了提高效率，你不希望发生内存交换（swapping）。最好的方法是在服务器中使用尽可能多的 RAM；这将为升级（在高负载下）留出空间。通常，64 到 128 MB 对于许多安装是足够的。存在一些例外，例如 UNIX 使用了大量 RAM，而且对于完整的新闻馈，64 MB 无法维持多久。
- **快速磁盘--** 服务器需要快速磁盘以避免成为客户端的瓶颈。服务器处理许多 I/O 请求，因此，高速磁盘访问对性能至关重要。
- **足够的磁盘空间--** 服务器不仅要存放自己的文件和操作系统的副本，还需要交换空间和临时空间。一个合适的服务器应该留有额外的空间以备增长。以下是频繁使用软件包的分类：

| 软件包 | 大小 |
| :--- | :--- |
| Core /var | 0.4 MB |
| Core /root | 4.0 MB |
| Core /usr | 23.6 MB |
| 附加 /usr | 9.9 MB |
| 网络 /usr | 12.3 MB |
| 手册页 /usr/share/man | 17.3 MB |
| X11 免费服务器、开发、手册 /usr/X11R6 | 92.7 MB |
| Emacs /usr/contrib | 26.3 MB |
| TeX & LaTeX | 39.7 MB |

你可以看到，BSD 占据了大量空间。仍然有一些如 Hylax、内核节点、ghostscript 以及任何你可能需要或其他软件包。
- **空闲的 CPU 资源--** 服务器需要足够的 CPU 周期来服务本地用户，并为客户端提供磁盘和网络访问服务。但并不意味着要做最快的服务器。通常你应该反其而行之。当服务器不需要很多 CPU 。文件访问非常高效，网络流量也是如此。负载过大的系统会延迟客户端的块响应。为了保持客户端的响应时间，请将用户留在快速系统中，并使用资源充足且负载负载的系统作为服务器，即使其 CPU 较。

## 管理网络流量

在决定如何安装新系统之前，你需要检查网络上的流量。这些流量的来源包括：

- 部门内部系统到其本地服务器的流量，用于：
  - 远程文件系统，包括共享的 UNIX 和用户分区。
  - 访问托管在部门服务器上的客户端/服务器应用程序。
  - 无盘客户端对交换、临时和打印分区的访问。
- 部门内部系统之间的流量，包括：
  - 客户端/服务器应用程序流量。
  - 远程显示更新（一个系统上的窗口显示另一个系统上进程的输出）。
  - 共享不在服务器上的本地系统。
- 部门内部系统与骨干服务器之间的流量，包括：
  - 对公司范围文件的远程访问。
  - 访问运行在骨干网上的客户端/服务器应用程序，例如主数据库。
- A 部门系统与 B 部门系统之间的流量，包括以下：
