# patch — 对文件应用更改

### 概要

```
/usr/bin/patch [-b|c|n] [-d dir] [-D define] [-i patchfile] [-o outfile] [-p num] [-r rejectfile][file]
```

## 描述

使用 `patch` 命令编辑由 `diff(1)` 创建的文本文件，`patch` 读取包含 `diff(1)` 命令产生的三个差异列表形式之一（普通、上下文或 ed 风格）的源文件，并将这些差异应用到文件中。默认情况下，`patch` 从标准输入读取。除非被 `-C`、`-e` 或 `-n` 选项覆盖，否则 `patch` 会尝试确定差异列表的类型。如果补丁文件包含多个补丁，`patch` 会尝试应用每个补丁，就像它们来自单独的补丁文件一样。（在这种情况下，必须能够确定每个差异的补丁文件名称。）

## 选项

- `-b` 在应用差异之前，将每个修改文件的原始内容另存为副本，位于相同位置，并加上 `.orig` 后缀。如果文件已存在，则覆盖它；如果多个补丁应用于同一个文件，则仅为第一个补丁写入 `.orig` 文件。如果你也指定了 `-o outfile`，则创建 `outfile`。
- `-c` 将补丁文件解释为上下文差异（当你指定 `-c` 或 `-C` 选项时 `diff` 命令的输出）。
- `-d dir` 在处理之前将当前目录更改 `dir`。
- `-D define` 使用 C 预处理器结构标记更改。

```
#ifdef define

...

#endif
```
使用 `define` 作为区分符号。
- `-e` 将补丁文件解释为 `ed` 脚本而不是 `diff` 脚本。
- `-i patchfile` 从路径名 `patchfile` 读取补丁信息而不是标准输入。
- `-l` 将差异脚本中的任何空白序列与输入文件中的任何空白序列匹配。其他字符精确匹配。
- `-n` 将脚本解释为普通差异。
- `-N` 忽略已应用于文件的补丁；默认情况下，拒绝已应用的补丁。
- `-o outline` 不直接修改文件（由文件操作数或差异列表指定），而是将每个补丁引用的文件副本写入 `outline` 并应用相应的差异。将单个文件的多个补丁应用于前一个补丁创建的中间版本，并将多个合并后的文件版本写入 `outline`。
- `-p num` 对于补丁文件中所有指示要修复的文件名称，从每个路径开头删除 `num` 个路径组件。如果补丁文件中的名称是绝对路径，则将任何领先斜杠视为第一个组件（即 `-p 1` 移除领先斜杠）。指定 `-p 0` 则仅使用文件名（最终路径组件）。
- `-R` 反转补丁脚本的含义；即假设差异脚本是从新版本到旧版本创建的。你可以在 `ed` 脚本使用 `-R` 选项；`patch` 在应用之前尝试反转脚本的每个部分。以交换格式保存拒绝的差异。如果没有指定此选项，在补丁文件的部分成功应用之前，`patch` 会尝试以反向含义应用每个部分。如果尝试成功，提示用户确定是否设置 `-R` 选项。
- `-r reject` 覆盖默认的拒绝文件名。默认情况下，拒绝文件名与输出文件名相同，并加上 `.rej` 后缀。

### 操作数

`file`

要补丁的文件路径。

## 用法

`-p` 选项不适用于编辑脚本，因为信息太少，无法重建反向操作。

`-p` 选项允许在无需手动编辑补丁文件的情况下，将其自定义到本地用户目录结构。例如，如果补丁文件中的名称为

```
/curds/whey/src/blurfl/blurfl.c
```

那么设置 `-p` 将导致整个路径名保持不变。设置 `-p 1` 返回以下路径：

```
curds/whey/src/blurfl/blurfl.c
```

在没有前斜杠的情况下，`-p 4` 返回以下路径：

```
blurfl/blurfl.c
```

完全不指定 `-p` 则返回以下路径：

```
blurfl.c.
```
