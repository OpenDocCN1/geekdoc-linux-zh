
```
$ ldd /bin/ls
librt.so.1 => /lib/librt.so.1 (0x0000002a9566c000)
libncurses.so.5 => /lib/libncurses.so.5 (0x0000002a95784000)
libacl1.so.1 => /lib/libacl1.so.1 (0x0000002a958ea000)
ibc.so.6 => /lib/libc.so.6 (0x0000002a9599f1000)
libthread.so.0 => /lib/libthread.so.0 (0x0000002a95c17000)
/lib64-/ld-linux-x86-64.so.2 (0x0000002a95556000)
libatattr.so.1 => /lib/libatattr.so.1 (0x0000002a95d5d000)
```

每一行输出一个库名称，例如`librt.so.1`或`libncurses.so.5`。如果库名不包含完整路径，`ldd`会尝试找到真实的库并显示符号`=>`后的路径，如`/lib/librt.so.1`或`/lib/libncurses.so.5`。前面的示例显示（`/lib64/ld-linux-x86-64.so.2`）引用可执行文件的完整路径。符号`~`。`ldd`命令接受几个选项。最显著的是`-v`，它显示版本信息列表。这些信息对于追踪程序使用的库版本很有帮助。记住，库本身可以依赖其他库。由于这种潜在的依赖链，即使所有库都存在，程序也可能失败。在使用`ldd`追踪问题时，确保检查程序的需要以及它使用的所有库，直到耗尽该链。`ldd`工具可以由普通用户以及`root`运行。如果你无法作为普通用户读取文件，必须以`root`身份运行它。

### 重建库缓存

Linux（或更准确地说，`ld-linux.so`和`ld.so`管理库的加载）在每次程序运行时都不会读取`/etc/ld.so.conf`。相反，系统依赖于目录及其包含文件的缓存列表，该列表以二进制格式存储在`/etc/ld.so.cache`中。这种列表比纯文本目录列表高效得多。缺点是，每当你添加或删除库时必须重建该缓存。执行此工作的工具是`ldconfig`。通常在不带任何选项的情况下调用它：

```
$ ldconfig
```

## 管理进程

该程序有以下选项来修改其行为：

- `ldconfig` -v 选项会导致程序总结它正在处理的目录的文件。

- `-n` 选项导致 `ldconfig` 不执行更新库缓存的首要职责。尽管它会更新指向库的符号链接。

- `-n` 选项导致 `ldconfig` 更新命令行上指定的链接。系统不会检查 `/etc/ld.so` 中指定的目录。

- `-X` 选项是 `-N` 的反反；它导致 `ldconfig` 更新缓存但不管理链接。

- 你可以使用 `-f` 选项 `/etc/ld.so.conf` 更改你想使用的配置文件。

- 你可以通过传递 `-C` 选项更改 `ldconfig` 创建的缓存文件，使用你想使用的。

- `-r` 选项告诉 `ldconfig` 将目录视为根目录 `/`。当你恢复损坏的系统或安装新操作系统时，此选项很有用。

- `-p` 选项导致 `ldconfig` 显示当前缓存——所有库目录及其包含的库。

RPM 和 Debian 包通常在安装或删除后自动运行`ldconfig`。许多从源码编译的包在安装过程中也是。因此你运行`ldconfig`的次数比你想象的要多。如果你以任何方式手动修改配置，你可能需要自己运行该程序。

当你输入命令名称时，该程序运行并为它创建一个进程。知道如何管理这些进程对于Linux至关重要。此任务的关键细节包括识别进程、操作前景后台进程、杀死进程以及调整进程优先级。

## 理解内核：第一个进程

Linux内核是每个Linux系统的核心。虽然你不能像管理其他进程那样管理内核进程，但重启电脑你可以了解它。你可以使用`uname`命令，它接受多个选项来显示信息：

- `-n`或`--nodename`选项显示系统的节点名称——即其网络主机名。

- `-s`或`--kernel-name`选项显示Linux系统上的内核名称。

- 你可以通过`-v`或`--kernel-version`选项找到内核版本。通常，它持有内核的编译日期时间，而不是实际的版本号。

- 可以通过`-r`或`--kernel-release`选项找到实际的内核版本号。

- `-m`或`--machine`选项返回有关机器的信息。这可能是CPU代码，例如`i686`或`x86_64`。

- 使用`-p`或`--processor`选项可能会返回有关CPU的信息，如制造商、型号和时钟频率；在实践中，许多系统上返回`unknown`。

- 理论上`-i`或`--hardware-platform`选项返回硬件平台信息，但通常返回`unknown`。

- `-o`或`--operating-system`选项返回OS名称——Linux系统通常为`GNU/`。

- `-a`或`--all`选项返回所有可用信息。

在实践中，你最可能在命令行使用`uname -a`来了解关于内核和系统的基础知识。其他选项对于多平台脚本最有用，这些脚本可以使用这些选项快速获取关键信息，以帮助它们根据运行的系统调整操作。

这种形式上的简单性隐藏了相当大的复杂性，因为`ps`支持三种不同类型的选项，而且每种类型中都包含许多选项。这三类选项如下：

- `ps` 选项：这些单字符选项可以组合在一起，并以单个短横线（-）开头。

- `ps` 选项：这些单字符选项可以组合在一起，但前面不能有横线。

- `ps` 长选项：这些多字符选项绝不会组合在一起。它们以两个短横线（--）开头。

可以组合的选项可以在不留空格的情况下进行聚类。例如，与其输入`ps -f`，你也可以输入`ps -af`。之所以有如此复杂性，是因为`ps`在历史上于不同的Unix操作系统之间存在很大差异。Linux发行版附带的`ps`版本尝试实现所有这些`ps`版本的功能，因此它支持许多特性（personalities）。事实上，你可以通过将`PS_PERSONALITY`变量设置为`posix`、`linux`、`bsd`、`sun`、`digital`或其他来更改它的任何默认行为。本节的其余部分描述了大多数Linux系统上的`ps`行为。

一些更有用的`ps`特性包括：

- 显示帮助：`--help`选项总结了一些常用的`ps`进程。

- 显示所有进程：默认情况下，`ps`显示从其自身终端（xterm、文本模式登录或远程登录）运行的进程。`-A`和`-e`选项使其显示系统上的所有进程，而`-u`显示用户拥有的进程。`-x`选项还增加了每个进程显示的信息。

- 显示特定用户的进程：你可以通过`-u`、`-U`和`--user`选项显示用户拥有的进程。user变量可以是用户名或用户ID。

- 显示额外信息：`-f`、`-j`、`-l`和`-v`扩展了`ps`输出的信息。大多数`ps`输出每个进程占一行，但`ps`可以显示足够多列宽的信息，因此这些选项提供了多种信息组合。

- 显示层次结构：`-H`、`-f`和`--forest`选项将进程分组并使用缩进显示进程之间的层次关系。如果你试图追踪某个进程的祖先，这些选项非常有用。

- 显示宽输出：`ps`命令的输出可以超过80列。通常`ps`会截断输出以适应屏幕。`-w`和`ww`选项告诉`ps`不要这样做，这在你将输出重定向到文件（如`ps w > ps.txt`）时有用。然后可以使用文本编辑器查看文件。你可以有很多方式组合这些`ps`选项以生成你需要的输出。你可能需要实验哪些选项产生想要的结果，因为每个选项有时都会影响对每个进程的选择。
