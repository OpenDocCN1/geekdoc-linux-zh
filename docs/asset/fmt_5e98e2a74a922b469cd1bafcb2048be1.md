# Pascal

一种高级过程化编程语言，利用了现代控制结构并避免了“面条代码”的产生。Pascal 作为一种教学和应用开发语言已获得广泛认可，尽管专业程序员更倾向于使用 C 或 C++。Pascal 既有解释版也有编译版。Pascal 的主要缺点是其标准版本（Standard Pascal）存在许多缺陷。该语言的发明者尼古拉斯·沃特（Nicholas Wirth）开发了新语言 Modula-2 作为 Pascal 的继任者，修复了该语言的一些问题，而 Borland International 的 Turbo Pascal 则让个人电脑用户能够更易地使用 Pascal。参阅来自 QUEDIC 的 BASIC 和 FORTRAN http://www.tdlp.org/LDP/Linux-Dictionary/html/index

# Pascal

一种由尼古拉斯·沃特于 1967 年左右在 CDC 6600 上开发的基于算法（Algo-descended）的语言——作为基础编程教学工具。这种语言的设计初衷是防止学生自乱阵脚，因此从通用编程的角度来看极其严格，但它后来被作为一种通用工具推广，并实际上成为了包括 Modula-2 和 Ada 在内的一大语言族的祖先。源自 Linux Guide@FirstLinux http://www.tdlp.org/LDP/Linux-Dictionary/html/index

一种由尼古拉斯·沃特于 1967 年左右在 CDC 6600 上开发的基于算法（Algo-descended）的语言——作为基础编程教学工具。这种语言的设计初衷是防止学生自乱阵脚，因此从通用编程的角度来看极其严格，但它后来被作为一种通用工具推广，并实际上成为了包括 Modula-2 和 Ada 在内的一大语言族的祖先（也称为“束缚纪律语言”）。对 Pascal 的讽刺观点可能是布莱恩·柯根（Brian Kernighan，K&R 框架作者）在1981年发表的一篇具有毁灭性的（在其巅峰时期是震撼性的）论文——《为什么 Pascal 不是我最喜欢的编程语言》，该论文曾因复印件传阅的技术细节被拒绝。它最终发表在 Alan Fleer 和 Narain Gehani 编写的《比较与评估编程语言》（Prentice–1984）中。他的讨论有一部分值得在这里重复，因为在十年的改进后，它可以作为对许多其他束缚纪律语言的控诉。在反对 Pascal 的总结陈述最后，柯根写道：9. 无处可逃。这一点也许是最重要的。这种语言是不完善且受限的，因为没有办法逃脱它的局限性。没有方法在必要时禁用类型检查。没有方法将缺陷的运行时环境替换为无意义的环境，即通过控制编译器来定义“标准过程”。这种语言是封闭的。使用 Pascal 进行严肃编程的人会掉入致命的陷阱。这种语言是无能的，它必须被扩展。但每个群体都按自己的方向进行扩展，使其看起来像任何他们真正想要的样子。针对单独编译的扩展、类似 FORTRAN 的 COMMON、字符串类型、内部变量、初始化、八进制数、位操作符，都增加了某一组对该语言的实用性，但破坏了它对其他人的可移植性。我觉得将 Pascal 用于其原始目标之外的任何地方都是错误的。在纯粹意义上，Pascal 是一种玩具语言，适用于教学但不适用于真实的编程。Pascal 在其在严肃应用和系统编程中所占据的领域几乎完全被 (C) 取代，但在 MS-DOS 和 Macintosh 世界中仍作为一种爱好语言保持着一定的人气。源自 Junior Dictionary http://www.tld.org/LDP/Linux-Dictionary/index.html

# passphrase

某些系统允许你输入整个句子（或短语）而不是短密码。长短语比简单的密码要难猜得多，安全性也更高。由于短语可能难以输入，它们通常在需要极高安全性时使用。源自 Hacking-Lexicon http://www.tld.org/LDP/Linux-Dictionary/index.html
