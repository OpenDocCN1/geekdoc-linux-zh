
## 网络电话
另一种互联网上的音频形式是拨打电话。技术上讲，你可以拨打任何拥有电子邮件地址的电话。只需要为台式电脑配备扬声器和麦克风，以及用于解释数字化数据包的软件。许多竞争公司正在为互联网制作电话产品，包括 Quarterdeck 的 "WebTalk"、Electric Magic 的 "NetPhone" 以及 Vocatec 的 "Internet Phone"。

网络电话的主要优势是免费的。唯一的费用是互联网连接的成本。主要的缺点是质量差以及网络电话产品之间的兼容性。其他用户必须与你使用完全相同的软件才能进行电话通话。

# 互联网视频

与音频一样，在互联网上处理视频数据有两种主要方法。第一种技术要求将视频文件传输到工作站，然后由相应的视频播放器进行处理。第二种技术不需要在过程完成之前传输整个文件。

### 视频文件传输
互联网上有各种格式的文件。每种格式都有与其相关的唯一扩展名。以下列表了你可能会看到的视频文件扩展名及其关联平台：

| 文件扩展名 | 平台 |
|---|---|
| `QT (QuickTime)` | Macintosh, PC |
| `AVI` | PC |
| `MPG, MPEG` | Macintosh, PC, UNIX |
| `MOV` | Macintosh, PC |

就像音频文件一样，每种文件类型都有相应的“播放器”应用程序。即使经过压缩，它们也面临与音频文件相同的问题：太大了。

### 流媒体视频
从概念上说，流媒体视频的工作原理与流媒体音频相同。即压缩文件通过 `UDP/IP` 协议传输。用户实际上在文件传输完成之前就能看到视频播放。在像 `MBONE` 等高速网络上，这可以提供合理的性能。

在互联网上实现流媒体视频的首次尝试是一个名为 `VDOLive` 的项目。像 `RealAudio` 一，它尝试根据连接速度调整视频质量。`VDOLive` 在 28.8 Kbps 的线路上能够在屏幕的两英寸区域内每秒交付 10 到 15 帧。在 `ISDN` 线上，可以达到每秒 35 帧。在传输视频数据之前，必须对其进行压缩。因此它不适用于直播。尽管有这些限制，`VDOLive` 仍然有很多。

两个新产品是 `RealPlayer` 和 `Streamworks`。它们能够结合音频和视频。

### 视频会议
一种在互联网上同时使用音频和视频的应用程序是。除了配备麦克风和视频摄像机的专用工作站外，还需要特殊的软件。

目前最常用的视频会议软件是一种名为 `CU-SeeMe` 的产品。这种技术的工作原理类似于流媒体音频和视频。当某人想参加视频会议时，必须先加入一个名为反射器（`reflector`）的系统。反射器托管许多你可以加入的会议。登录后，语音和视频数据在传输到互联网之前会进行数字化和压缩。为了提高效率，使用了 `UDP` 协议而不是 `TCP`。任何丢失的数据包都会被应用程序忽略。

`CU-SeeMe` 还尝试通过只发送图像的相关部分来减少所需的带宽。例如，如果某人在说话，但在摄像范围内很少活动，则只需要发送与之前的视频帧相比的变化部分。

可以在没有反射器站点的情况下进行视频会议。如果你知道对方的 `IP` 地址，你可以直接联系他们并进行双向会议。

> 注意：`NASA` 拥有许多可以使用 `CU-SeeMe` 查看现场视频的反射器站点。他们还有一系列出色的音频视频片段可供下载。详情请访问 `http://www.nasa.gov`。

# 未来方向

互联网，作为信息高速公路，仍在演变。它的建立是为了支持电子邮件和文件传输等应用程序。为了支持音频和视频等多媒体，基础设施将需要升级。研究人员正在研究如何在不进行大规模改组的情况下升级基础设施。诸如 `RSVP/RTP` 等努力正在进行中，但仍遥遥无期。

登录过程会将你带到你的目录，然后将控制权交给 `/etc/passwd` 控制的 shell 启动程序；用户名和密码均由 `/etc/passwd` 中的条目指定。尽管这可能是一个特定的应用程序（例如菜单程序），但通常 shell 启动程序是一个名为 `/bin/sh` 的 shell 程序，即 Bourne shell。

从这里开始，shell 程序读取 `/etc/profile` 和 `.profile` 文件，这些文件设置了系统级和用户特定的环境标准。此时，shell 以 `$` 发出命令。

当 shell 终止时，内核会将控制权返回给 `init` 程序，该程序重新启动登录过程。终止可以通过两种方式发生：使用 `exit` 命令，或者当内核向 shell 进程发出信号时。终止时，内核会回收用户和 shell 程序使用的所有资源。

在 Unix 系统中，存在许多层层程序，从内核开始通过给定的应用程序，这些层之间的关系如图 8.2 所示。

登录完成后，shell 层与内核直接接触，如图 8.2 所示。当你输入 `$` 输入命令时，shell 定位到实际程序 `/bin/ls` 并将其传递给内核。内核创建一个新的子进程，加载程序并执行 `/bin/ls` 中的指令。程序执行完成后，内核回收进程区域并将控制权返回给父 shell 程序。要查看此示例，请输入以下命令：

```
$ps
```

这列出了你当前正在运行的进程。你将看到 shell 程序和 `ps` 程序。现在你输入以下内容：

```
$sleep 10 &
$ps
```

第一个命令创建了一个在后台运行的 `sleep` 子进程，你可以通过 `ps` 命令看到它的列表。每当你执行一个命令时，都会创建一个子进程，并从父进程或 shell 独立执行。这使得父进程保持完好并继续其他工作。

## Shell 的自动执行

某些 `UNIX` 资源（如 `cron`）可以在没有人工干预的情况下执行 shell 程序。使用此功能时，用户需要在 shell 程序的首行指定要运行的哪种 shell，如下所示：

```
#! /bin/sh
```

这指定了 Bourne shell。

你还应该重定向任何输出，因为自动执行没有关联终端。这将在本文章后的“文件处理：输入/输出重定向和管道”部分进行描述。

## Shell 的功能与特性

你选择哪种标准 shell 并不重要，因为它们的目的相同：为 `UNIX` 提供用户界面。为了提供这一界面，所有 shell 都提供相同的基本特性：

- 命令行解释
- 保留字
- Shell 元字符（通配符）
- 对程序命令的访问和处理
- 文件处理：输入/输出重定向和管道
- 变量维护
- 环境控制
- Shell 编程

### 命令行解释

当你登录时，会启动一个名为交互式 shell 的特殊版本 shell，你会看到 shell 提示符，通常表现为美元符号（`$`）、百分号（`%`）或井号（`#`）。当你在 shell 提示符处输入一行内容时， shell 会尝试解释它。到提示符的输入被称为“命令行”。命令的基本格式为：

```
command arguments
```

**`command`** 是一个可执行的 `UNIX` 命令、程序、工具或 shell 程序。**`arguments`** 是传递给可执行文件的参数。大多数 `UNIX` 工具程序期望 **`arguments`** 采用以下形式：

```
options filenames
```

例如，在命令行中

```
$ ls -l file12
```

对于 **`ls`** 来说三个参数；第一个是选项，最后两个是文件名。

shell 为内核做的事情之一是消除不必要的信息。对于计算机来说，一种不必要的信息是空白字符；因此，知道 shell 在遇到空白时会做什么非常重要。空白由空格字符、水平制表符和换行符组成。考虑这个示例：

```
$ echo part A      part B      part C
part A part B part B part C
```

在这里，shell 将命令行解释为带有六个参数的 **`echo`** 命令，并删除了参数之间的空白符。例如，如果你在报告中使用标题并想保留空白，你必须将数据包含在引号中，如下所示：

```
$ echo 'part A      part B      part C'
part A      part B      part C
```

单引号防止 shell 检查引号内部的内容。现在 shell 将此行解释为带有单个参数的 **`echo`** 命令，该参数恰好是一个包含空白的字符字符串。

### 保留字

所有版本的 shell 都有具有特殊含义的单词。在 shell 编程中，如 `do`、`done`、`for` 和 `while` 等循环控制——以及 `if`、`then`、`else` 和 `fi` 提供了条件控制。每个版本的 shell 针对其特定特性有不同的方式。

### Shell 元字符（通配符）

所有版本的 shell 都有元字符，允许用户指定文件名。以下是通配符：

| 通配符 | 说明 |
| --- | --- |
| `*` | 匹配任意部分 |
| `?` | 匹配任意单个字符 |
| `[]` | 匹配字符范围或列表 |

通配符在处理多个特定文件时非常有用。以下是一些示例：

```
$ls t*
```

这列出了所有以 t 开头的文件。

```
$ls test?5.dat
```

这列出了所有以 test?5 开头的文件。

```
$ls [a-c]*
```

这列出了以 a 到 c 开头的文件。

```
$ls [e,mt]*
```

这列出了 e 到 t 文件。

### 程序命令

当输入命令时，shell 查找路径。然后 shell 将文件名传递给内核。

### 文件处理：输入/输出重定向和管道

在之前的章节中，你学习了标准输入和输出。除非用参数指定，否则 `UNIX` 命令从键盘输入。要将输出重定向到文件，使用 `>` 符号。例如：

```
$ls > myfiles
```

列出当前目录并放入名为 myfiles 的文件中。同样，你可以使用 `<` 重定向输入。例如：

```
$wc -l myfiles
```

将 myfiles 输入 `wc` 命令。虽然你可以通过文件名作为参数获得相同的输出，但输入的需求在 shell 编程中变得更加明显。

要将一个命令的输出连接到下一个命令的输入，可以使用 `|` 符号。例如，

```
$ls -s | sort -nr | pg
```

这列出当前目录的文件块大小并将其传递给 `sort`，按数字降序排序，然后传递给分页命令 `pg` 以在终端显示。

### 命令替换

命令替换与重定向相似，但用于从一个命令的输出为另一个命令提供参数。例如：

```
$grep 'wc -l myfiles' *
```

从 `wc` 命令获取 myfiles 文件的行数，并将该数字作为参数传递给 `grep` 命令，以搜索当前目录的所有文件。

### 变量维护

shell 能够维护变量。变量是你存储数据供以后使用的位置。你使用等号（`=`）给变量赋值：

```
$ LOOKUP=/usr/dir
```

在这里，shell 建立了变量 `LOOKUP` 并赋值为 `/usr/dir`。后，你可以通过在变量名前前加美元符号（`$`）在命令行中使用存储在 `LOOKUP` 中的值。考虑以下示例：

```
$ echo $LOOKUP
/usr/dir
$ echo LOOKUP
LOOKUP
```

要使变量对子进程可用，可以使用 `export` 命令——例如：

```
$ LOOKUP=/usr/dir
$export LOOKUP
```

> 注意：在 C shell 中为变量赋值与 Bourne 和 Korn shell 不同。在 C shell 中为变量赋值，请使用 `set` 命令：

```
% set LOOKUP = /usr/dir
```

注意等号前后有空格。

文件名替换、变量名替换发生在程序调用之前。第二个示例省略了美元符号（`$`）。因此，shell 仅仅将字符串作为参数传递给 `echo`。在变量名替换中，变量的值会替换变量名。

例如，在

```
$ ls $LOOKUP/filename
```

调用 `ls` 程序时，其唯一参数为 `/usr/mydir/filename`。

### Shell 启动--环境控制

当用户开始使用 `UNIX` 并执行 shell 时，shell 会为用户创建一个指定的环境。接下来的章节描述了这些过程。

#### Shell 环境变量

当登录程序调用你的 shell 时，它会设置你的环境变量，这些变量是从初始化文件 `/etc/profile` 和 `.profile` 中读取的。这些文件通常在变量 `$TERM` 中设置终端类型，并在变量 `$PATH` 中设置搜索可执行文件的默认路径。尝试这些示例：

```
$ echo $TERM
echo $PATH
```

你可以像给任何 shell 变量赋值一样，轻松地相同的方式更改这些变量。

> 注意：C shell 使用 `setenv` 命令给环境变量赋值：

```bash
setenv TERM vt100
```

#### Shell 启动文件

`.profile` 文件是 Bourne shell 的本地启动文件。Korn shell 使用 `.shrc`，而 C shell 使用 `.cshrc`。你可以编辑这些文件来操作你的启动环境。你可以根据需要添加额外的变量。如有必要，你可以添加 shell 编程以实现条件环境设置。

#### Shell 启动选项

当从 `/etc/passwd` 或命令行调用 shell 时，你可以将多个选项作为 shell 程序的参数。例如，Bourne shell 有一个 `-x` 选项，可以在执行命令前显示命令及其参数。这对于调试 shell 程序非常有用。这些选项将在接后的章节中详细描述。

## Shell 编程

你已经看到 shell 被用于解释命令行、维护变量和执行程序。shell 也是一种编程语言。你可以将一组 shell 命令存储在文件中：这被称为 shell 脚本（shell script）或 shell 编程。通过将命令、变量赋值与流程流控制和决策制定相结合，你就拥有了一个强大的编程工具。使用 shell 作为编程语言，你可以自动化重复性任务、编写报告、构建并处理你自己的数据文件。第二部分的剩余章节将更详细地讨论 shell 编程。

## 总结

shell 在用户与 `UNIX` 核心——内核之间提供了一个接口。shell 解释命令行作为输入，进行文件名和变量替换，重定向输入和输出，定位可执行文件并启动程序。shell 创建子进程并可以管理它们的执行。shell 维护每个用户的环境变量。shell 也是一种强大的编程语言。

虽然本章提供了 `UNIX` shell 的概述，但第 9 到 13 章详细描述了各种 shell、特性和语言细节。还描述了 shell 编程和执行的基础知识。强烈建议继续阅读。

# Shell 基础

Stephen Bourne 在贝尔实验室编写了 Bourne shell，那里是 `UNIX` 的开发中心。当时，贝尔实验室是 `AT&T` 的子公司。从那时起，许多系统公司产生了特定硬件版本的 `UNIX`，但 Bourne Shell 保持了高度性。

> 注意：在 `UNIX` 系统上运行 `$man sh` 或 `$man bsh` 将列出 Bourne Shell 的通用介绍以及对该版本 `UNIX` 的要求。建议读者在阅读本章前后，熟悉自己正在使用的版本。

# Shell 调用环境

第一级调用发生在用户登录 `UNIX` 系统时，由其在 `/etc/passwd` 文件中的条目指定。例如：

```
farrawa::411:102:William Farra, Systems Development,x385:home/farrawa:/bin/bash
```

该条目（以 `:` 分隔）包含登录 ID、加密密码（用 `!` 表示）、用户 ID # 默认组 ID # 注释字段、主目录和启动 shell 程序。在 particular情况下，它是 Bourne shell。当它执行时，它会读取系统配置文件 `/etc/profile`。这可能会设置各种环境变量，例如 `PATH`（shell 用来搜索可执行文件）和 `TERM`（使用的终端类型）。然后 shell 继续将用户放入主目录并读取本地的 `.profile`。最后，shell 显示提示符 `$`。

> 注意：在 `UNIX` 系统上，超级用户（也称为 root）不受限制。当超级用户登录时，他看到提示符符号 `#` 作为默认提示符。这提醒超级用户，某些内置保护不可用，在此模式下需要额外小心。超级用户可以进入任何目录并删除任何文件，文件权限不适用。通常只使用 root 登录。

Shell 调用选项

当从 `/etc/passwd` 或命令行调用 shell 时，你可以将多个选项作为 shell 程序的参数。例如，Bourne shell 有一个 `-x` 选项，可以在执行命令前显示命令及其参数。这对于调试 shell 程序非常有用。这些选项将在接后的章节中详细描述。
