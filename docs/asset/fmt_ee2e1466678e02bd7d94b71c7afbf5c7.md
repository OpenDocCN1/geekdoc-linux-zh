
为了使用元类新的 `__prepare__` 方法进行任何形式的有用处理，你通常需要返回一个自定义的字典。例如，如果你想在定义类时执行特殊处理，你可以定义一个继承自 `dict` 的类，并实现 `__setitem__` 方法来捕获对类字典的赋值。下面的示例通过定义一个元类这一点，如果类名或变量被重复定义，它将报告错误。

```python
class Multiple(dict):
    def __init__(self):
        self.multiple = set()
    def __setitem__(self, name, value):
        if name in self:
            self.multiple.add(name)
        dict.__setitem__(self, name, value)
```

```python
class MultiMeta(type):
    @classmethod
    def __prepare__(cls, name, bases, **kwargs):
        return Multiple()
    def __new__(cls, name, bases, classdict):
        for name in classdict.multiple:
            print(f"{name}, \"multiply defined\"")
        
        if classdict.multiple:
            raise TypeError("Multiple definitions exist")
        return type.__new__(cls, bases, classdict)
```

如果你在类定义中应用任何元类，如果任何方法被重定义，它将报告错误。例如：

```python
class Foo(metaclass=MultiMeta):
    def __init__(self):
        pass
    def __init__(self, x): # 错误.__init__ 重复定义。
        pass
```

## 常见陷阱

如果你正在从 Python 2 迁移到 3，请注意 Python 3 不仅仅是新的语法和语言特性。核心语言和库的大部分已经以微妙的方式进行了重构。Python 3 的某些方面在 Python 2 程序员看来可能像错误。在其他情况下，在 Python 2 中曾经“简单”的事情现在被禁止了。

本节概述了 Python 2 程序员在切换时可能会遇到的一些主要陷阱。

### 文本与字节 (Text Versus Bytes)

Python 3 在文本字符串（字符）和二进制数据（字节）之间有着非常严格的区别。像 `"hello"` 这样的字面量表示一个存储的字符串。`"hello"` 则表示一个字节流。由于 Python 3 的这种严格区分，Python 2 程序员可能会认为某些问题是 bug。在其他情况下，在 Python 2 中是“容易”的现在被禁止了。

# 附录 Python 3

仅仅修改了局部变量的副本，而不是局部变量本身。这里有一个解决方法：

```python
def foo():
    _locals = locals()
    exec('a = 42', globals(), _locals)
    a = _locals['a']  # 提取魔法变量

```

作为一个一般规则，不要期望 Python 3 支持像 Python 2 中使用 `exec()`、`eval()` 和 `execfile()` 那样程度的“魔法”。实际上，`execfile()` 已经完全消失了（你可以通过向 `exec()` 传递一个打开的文件对象来模拟其功能）。

# 迭代器和视图的使用

Python 3 对迭代器和生成器的使用比 Python 2 多得多。内置函数如 `zip()`、`map()` 和 `range()` 以前返回列表，现在返回可迭代对象。如果你需要从结果创建列表，请使用 `list()` 函数。

Python 3 在从字典中提取键和值信息方面的方法略有不同。在 Python 2 中，你可以使用 `d.keys()`、`d.values()`、`d.items()` 等方法来分别获取键列表或键值对。在 Python 3 中，这些方法返回视图对象（view-objects）。例如：

```python
>>> s = {'GOOG': 490.10, 'AAPL': 123.45, 'IBM': 91.10}
>>> k = s.keys()
>>> k
>>> dict_keys object at 0x33d950
>>> v = s.values()
>>> v
>>> dict_values object at 0x33d960
```

这些对象支持迭代，所以如果你想查看内容，可以使用 `for` 循环。例如：

```python
>>> for x in k:
    ...     print(x)
GOOG
AAPL
IBM
>>>
```

视图对象始终与其创建的字典绑定。这其中一个微妙的方面是，如果底层字典发生了变化，视图产生的项随之改变。例如：

```python
>>> s['ACME'] = 5612.25
>>> for x in k:
    ...     print(x)
    ...
GOOG
AAPL
IBM
ACME
>>>
```

如果有必要构建字典键或值的列表，只需使用 `list()` 函数即可——例如 `list(s.keys())`。

# 整数和整数除法

Python 3 不再区分 32 位整数的 `int` 类型和用于长整数的 `long` 类型。`int` 类型现在表示任意精度的整数（其细节对用户不可见）。

此外，整数除法现在总是产生浮点结果。例如，`3/5` 是 `0.6`，而不是 `0`。即使结果本应是整数，也会转换为浮点数。例如，`8/2` 是 `4.0`，而不是 `4`。

# 比较

Python 3 对值的比较方式更加严格。在 Python 2 中，任何两个对象即使在没有意义也可以进行比较。

```python
>>> 3 < "Hello"
True
>>>
```

在 Python 3 中，这会导致 `TypeError`。例如：

```python
>>> 3 < "Hello"
Traceback (most recent call last):
  File "<module>", line 1, in <module>
TypeError: unorderable types: 'int' < 'str'
>>>
```

这种变化是微小的，但意味着在 Python 3 中，你必须非常小心确保数据类型正确。例如，如果你使用列表的 `sort` 方法，列表中的所有项必须与 `<` 运算符兼容，否则就会得到错误。在 Python 2 中，该操作无论如何都会默默执行，但结果通常没有意义。

# 迭代器和生成器

Python 3 对迭代器协议有细微调整。不再调用 `__iter__()` 和 `next()` 来执行迭代，`next()` 方法已重命名为 `__next__()`。如果你编写了手动迭代迭代器的代码，或者定义了自定义的迭代器对象，大部分将不受此更改影响。你需要确保更改类中 `next()` 方法的名字。使用内置的 `next()` 以可移植的方式调用迭代器的 `next()` 或 `__next__()` 方法。

# 文件名、参数和环境变量

在 Python 3 中，文件名、`sys.argv` 中的命令行参数以及 `os.environ` 中的环境变量取决于本地环境，可能是 Unicode 也可能不是。唯一的问题是，操作系统环境并不完全保证可以使用 Unicode。例如，在许多系统中，技术上可能指定仅为原始字节序列且不对应有效 Unicode 编码的文件名、命令行选项和环境变量。虽然在实践中这种情况很少见，但在使用 Python 执行与系统管理相关的任务时，可能会引起关注。正如之前提到的，以字节字符串（byte strings）提供文件和目录名称将解决许多问题。例如 `os.listdir(b'/foo')`。
