
一个典型的 ArubaOS 网络由一个或多个控制器和一组 AP 组成。在大多数情况下，当客户端数据传输到 AP 时，AP 将数据转发给控制器，然后由控制器处理数据并将其转发到网络。本章的目标是解释控制器和 AP 如何协同工作的细节，并描述客户端流量是如何转发的。现在，请放松心情，试着理解正在解释的过程、概念和组件。

# ArubaOS 架构

让我们先假设你正在一家私有公司工作。你的老板（公司所有者）决定安装一个无线网络。她从一个在另一家公司的朋友那里听说了 Aruba，那家公司已经安装了 Aruba 网络。那个朋友告诉你的老板，他的公司是如何从一小部分 AP 和一个单一中央控制器管理这些 AP 开始的。随着公司的发展，他们能够添加额外的 AP 以及额外的控制器，以支持 AP 和用户日益增长的需求。令他印象深刻的特征之一是可以从一个中央控制器管理所有的控制器和 AP。他解释说，这个主控制器被称为主控制器 (master controller)。在了解 Aruba 系统的功能并看到演示后，你的老板让你去购买 Aruba 无线网络设备，最初为位于多层办公楼内的行政办公室和销售办公室提供无线覆盖。

在与 Aruba 销售人员和系统工程师交流后，确定你需要 32 个 AP 来为行政和销售办公室提供必要的 RF 覆盖。你决定购买一个支持最多 32 个 AP 的单一控制器。你意识到这个特定型号的控制器将达到 AP 数量上限，未来的任何增长都将要求你购买另一个控制器。理想情况下，你应该购买一个具有更多增长潜力的更大的控制器；然而，这完全是一个虚构的故事，选择这种配置是为了解释架构以及 Aruba 设备的工作原理。

## AP 启动过程

AP 用于发现控制器的第一种方法是在一个名为 `master`（主）的配置参数中静态设置控制器 IP 或 DNS 节点。由于本示例引用的是一个新 AP，此参数将尚未设置。如果你想设置此参数或任何其他 AP 参数，最佳实践是使用控制器的 Web 用户界面 (WebUI) 进行设置。或者，你也可以从控制器的命令行界面 (CLI) 使用 `provision-ap` 命令设置或更改 AP 参数，或者通过控制台连接直接到 AP 并使用 `setenv` 命令。你将在第 3 章“Aruba 控制器和软件概述”中学习用户界面。

如果 AP 上没有静态设置控制器 IP 地址，那么 AP 尝试发现控制器的下一种方法是使用 DHCP 选项 43 和 60。大多数人仅将其称为选项 43，但我喜欢引用这两个选项，因为它们协同工作且都必须进行配置。选项 43 包含控制器 IP 地址，在没有选项 60 的情况下它是没用的。我见过有人只设置选项 43 而不设置选项 60，然后纳闷为什么不起作用。事实上，我第一次设置它时，我没有意识到这两个选项都需要配置。我们将更详细地查看该过程。

除了提供 IP 地址、子网掩码和默认网关外，你可能已经知道 DHCP 服务器还可以提供其他信息，如 DNS 服务器 IP 地址、DNS 域名以及 WINS 服务器 IP 地址。DHCP 还可以被配置为监听 DHCP 请求中的某些信息。当 Aruba AP 发送 DHCP 请求时，它通过将请求中的“供应商特定/厂商类标识符”（vendor class identifier）设置为 `ArubaAP` 来向 DHCP 服务器标识自己的身份。如果 DHCP 选项 60 设置为监听此值，并收到了一个带有此厂商类标识符的请求，则 DHCP 回复中将包含你为 DHCP 选项 43 设置的值。在此例中，它将是 AP 初始与之通信的 Aruba 控制器的 IP 地址。本质上，如果 DHCP 服务器听到了 Aruba AP，它就会告诉 AP 初始控制器的 IP 地址。《ArubaOS 用户指南》包含了关于如何在各种 DHCP 环境中配置这些选项的额外信息，因此本书中将不再进一步解释此主题。

### Aruba 发现协议

下一种发现方法是 Aruba 发现协议（ADP）。通过 ADP，AP 将发送多播和广播请求以尝试发现控制器。为了让 AP 使用 ADP 发现控制器，这两台设备都必须位于同一个二层网络上。如果使用 ADP 发现位于不同网络或 VLAN 的控制器，则需要在路由器上配置互联网组管理协议（IGMP），以便它们能够将多播数据包路由到另一个网络。

当 AP 和控制器之间进行控制流量通信时，它们使用一种名为专有访问协议接口（PAPI）的 Aruba 协议。PAPI 使用 UDP 端口 8211 执行这些通信。注意，端口 8211 是由 802.11（IEEE 无线网络标准）缩写派生而来的。当工程师们定义 ADP 时，他们在分配 239.0.82.11 的 IP 多播组地址时也很有创意，将 802.11 的衍生值整合到 IGMP 地址中。这使得记住 UDP 值和多播值变得稍微容易一些。

### DNS 查找

AP 用来发现控制器的最后一种方法是执行 DNS 查找。每个 AP 在出厂时都配置为在通过 DNS 尝试发现控制器时使用 `aruba-master` 域名。这是通过在 DHCP 服务器提供的域名之前加上 `aruba-master` 实现的；因此，域名看起来将像 `aruba-master.westcott-consulting.com`。使用 DNS 的优点之一是 DNS 服务器可以将 `aruba-master` 域名解析为多个 IP 地址。如果返回了多个 IP 地址，AP 将一个一个地尝试，最多尝试四个 IP。如果 AP 与控制器的通信失败，它将重启并重试。

### OS 更新

一旦 AP 成功连接到初始控制器，它将进行检查，以查看控制器上的操作系统（ArubaOS）版本是否与 AP 上的操作系统版本匹配。如果不同，AP 将开始使用文件传输协议（FTP）从控制器下载 OS，如图 2-2 中的步骤 4 所示。此 FTP 传输将需要大约四分钟完成；然而，如果有许多 AP 同时正在下载，时间可能会更长。AP 将升级或降级其 OS，以与控制器上的 OS 匹配。如果环境中存在多个控制器，确保所有控制器都安装了相同版本的 ArubaOS 是至关重要的。如果所有控制器的 ArubaOS 版本不匹配，AP 可能会陷入在不同控制器之间来回乒乓式切换的境地；从一个控制器升级其 OS，重启，然后从另一个控制器降级其 OS，可能永远无法完成启动周期。下载 OS 后，AP 将重启并再次通过初始化过程。这一次，当它执行操作系统检查时，AP 上的 OS 将与控制器的 OS 匹配，因此 AP 将跳过下载过程并继续启动。一旦 AP 上的 OS 与控制器的 OS 匹配，在控制器上的 OS 发生变化之前就不会再次发生 FTP 下载。
