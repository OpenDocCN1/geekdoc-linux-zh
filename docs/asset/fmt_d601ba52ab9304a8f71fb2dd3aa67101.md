
要为您的目标构建`microperl`，您必须首先从CPAN下载Perl版本，并将其解压到`$[PRJROOT]/[sysapps]`目录。将该包放置在`sysapps`目录中，因为它只会在目标上运行，不会用于构建目标的其他软件包。解压包后，进入其目录进行构建（此处不能使用不同的构建目录，就像我们为GNU工具链所做的那样，因为Perl不支持这种构建方法）：

```
$ cd $[PRJROOT]/[sysapps]/perl-5.10.0
```

由于`microperl`是Perl的最简构建，您无需配置任何内容。使用相应的`Makefile`构建包，并指示其使用`uClibc`编译器包装器而不是标准的`GCC`编译器：

```
$ make -f [Makefile.micro] CC=[c1386-uclibc-gcc]
```

这将在包的根目录中生成一个`microperl`二进制文件。该二进制文件不需要其他Perl组件，可以直接复制到目标根文件系统的`/bin`目录，即`$[PRJROOT]/[roots]`。

当使用`glibc`或`uClibc`动态链接并去除符号表（stripped）后，`microperl`二进制文件的大小约为`1.5 MB`。

有关如何构建`microperl`的更多信息，请查看`Makefile.micro`文件及`uconfig.sh`脚本。随着`microperl`工作的进展，预计将有更多文档可用。

## Miniperl

`Miniperl`比`microperl`少一些极简主义，提供了标准Perl解释器预期的大多数功能。它缺少的主要组件是`Dyna-Loader` `XS`模块，该模块允许Perl子例程调用C函数。因此，它无法动态加载`XS`模块。不过，考虑到`miniperl`将要运行的系统类型，这是一个次要问题。

与主Perl构建一样，`miniperl`需要运行`Configure`脚本以确定系统能力。由于需要构建Perl的系统是您的目标，该脚本要求您指定与该目标通信的信息：主机名、远程用户名以及映射到目标的目录。脚本利用这些信息在您的目标上运行测试并生成适当的构建文件。

关于此方法的主要注意事项是，它需要主机和目标之间直接的网络连接。从本质上讲，如果您的目标不具备某种形式的网络功能，您将无法为其构建`miniperl`。

`miniperl`的安装方法在`5.10.0` Perl包附带的`INSTALL`文件中有详尽说明，位于“Cross-compilation”标题下。

### 无法交叉编译的困境

正如我们刚才在Perl中看到的，并非所有包都能轻松地进行交叉编译。事实上，大量包在设计上并未允许交叉编译。我们提到了其中一些，但肯定无法列举全部。

除了尝试修改构建脚本和使用编译技巧来强制包为另一种架构编译外，有时唯一现实的解决方案实际上是在该包应该运行的目标上构建该包。起初，对于大多数嵌入式系统而言，由于存储空间的限制，这似乎是不可行的。然而，正如我们将在第9章中看到的，可以通过`NFS`将系统的根文件系统挂载到服务器上。通过使用`NFS`挂载的根文件系统，目标可以获得服务器允许的任何存储空间。

在此类设置中，因此可以为目标交叉编译`GCC`编译器本身，然后使用该编译器直接在目标上原生编译任何包，完全按照该包的构建脚本预期的方式操作。一旦包被编译，生成的二进制文件和库随后可以复制到针对目标内部存储设备定制的小型根文件系统中，并像其他目标应用程序一样在现场使用。显然，没有必要将交叉编译的`GCC`与系统的其余部分一起打包到现场使用。

Guido van Rossum在1991年向世界介绍了Python。自那时起，它聚集了许多追随者，和Perl一样，是一个独立的世界。如果您对Python感兴趣，请阅读Mark Lutz的《Programming Python》或他的《Learning Python》（均由O'Reilly出版）。Python经常与Perl进行比较，因为它常常服务于相同的目的，但由于这是另一场“神圣战争”的主题，我们将不再深入。相反，请自由浏览Python主网站`http://www.python.org`以获取更多信息。Python包，包括Python解释器和Python库，可以从该网站获取，其许可证称为Python许可证，这是一种组合许可证，也是经过认证的开源许可证。

与Perl一样，您需要一个配置正确的解释器才能在目标上运行Python代码。虽然主要的Python发行版不支持交叉编译，但Christopher Lambacher提供了一个允许交叉编译Python 2.5的补丁，可在`http://whatschrisdoing.com/~lambachk/Python2.5_xc.compile.patch`获取。Lambacher在`http://whatschrisdoing.com/blog/2006/11/06/howto-cross-compile-python-25`发表的博客文章详细解释了如何使用此补丁使Python进行交叉编译。

### 安装 Eclipse

Eclipse是一个Java应用程序，这使其具有跨平台性。然而，这意味着你需要一个Java运行时虚拟机（`JVM`）来运行它。大多数当前的Linux发行版都预装了一个名为`GCJ`的`JVM`。不幸的是，虽然Eclipse可以在`GCJ`上运行，但它并不是定期测试的参考`JVM`之一。因此，我们建议你首先从Sun Java下载网站`http://www.java.com/en/download/manual.jsp`安装一个用于Linux的免费`JVM`。

![](img/617fee0f2d5cdaf31b3f8601bc6c454f_157_1.png)

Sun Java `JVM`可以与`GCJ`和平共存，因此你不必担心破坏当前的`JVM`安装。

成功安装Sun `JVM`后，请前往项目下载页面`http://www.eclipse.org/downloads`下载Eclipse。你需要下载面向C/C++开发者的Eclipse IDE版本，该版本将基本的通用Eclipse核心与面向C/C++开发者的`CDT`插件集成在一起。

下载压缩的`tar`归档文件后，进入你希望安装Eclipse的目录，并解压缩`tar`归档文件。

![](img/617fee0f2d5cdaf31b3f8601bc6c454f_158_0.png)

你可以将Eclipse安装在任何你希望的位置，包括你的主目录，但如果你希望与其他使用同一台计算机的人（例如共享网络服务器）共享Eclipse安装，我们建议你在所有用户都可以访问的位置打开归档文件。这可能要求你以超级用户身份解压缩归档文件。

```ini

-vm
/ust/lib/jvm/java-6-sun/jre/bin/java
...
```

现在按照以下步骤配置Eclipse插件框架，以从更新站拉取插件：

在受管构建项目中，Eclipse会根据你定义的项目属性（例如，要使用的工具链）以及
