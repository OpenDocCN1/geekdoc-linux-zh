
# 配置指令

配置指令（或简称指令）是配置文件中的行，用于控制 Apache 功能的某些方面。配置指令由一个关键字后跟一个由空格隔开的一个或多个参数（值）组成。例如，以下配置指令将 `Timeout` 设置为 300（秒）：

```
Timeout 300
```

你必须将包含空格的参数括在双引号内。关键字不区分大小写，但参数（文件名、模式名等）通常区分大小写。

## 主要配置文件

### apache2.conf

包含 Apache 配置指令的主文件默认是 `/etc/apache2/apache2.conf`。此文件包含影响 Apache 服务的所有内容的全局指令。`apache2.conf` 中的 `Include` 指令将其他内容包含进来，作为 `apache2.conf` 的一部分。

### .htaccess

本地指令出现在 `.htaccess` 文件中。`.htaccess` 文件可以出现在文档根层次结构内的任何目录中；它影响其所在目录为根的目录层次结构中的文件。

### 路径名

当你在配置指令中指定绝对路径时，该指令将使用该路径而不对其进行修改。当你指定相对路径时，该指令将其附加到配置文件所在的目录。

## 指令详解

配置指令控制 Apache 如何启动和提供内容。本节详细介绍了你可能想要添加的一些指令。

Apache 启动时会读取配置文件。以下是你可能想要使用的指令：

- **DocumentRoot**：指定文档根。默认情况下，文档根是 `/var/www`。你可以通过 `DocumentRoot` 指令更改此位置。除了 Apache 服务的 Web 页面内容外，此目录还可以存放 `webalizer` 目录，其中包含 `webalizer` 输出。

- **.htaccess 文件**：包含配置指令，可以出现在文档根层次结构中的任何目录。`.htaccess` 文件的位置至关重要：`.htaccess` 文件中的指令适用于以包含 `.htaccess` 文件的目录为根的层次结构中的所有文件。`AllowOverride` 指令控制 Apache 是否检查 `.htaccess` 文件。由于默认站点包含 `AllowOverride None` 指令，你必须使用 `AllowOverride` 指令让 Apache 检查 `.htaccess` 文件并处理这些文件中的指令。这种保护在 Ubuntu 分发的 `apache2.conf` 文件中得到了复制和增强，该指令指示 Apache 不提供名称以 `.ht` 开头的文件。由于该指令，Apache 不提供 `.htaccess` 文件。

- **Listen**：包含 `Listen` 指令，控制 Apache 监听的 IP 地址和端口。

- **sites-available**：包含描述虚拟主机代码的文件。有关使用 `aensite` 启用站点的信息，请参阅相关文档。

- **sites-enabled**：包含指向 `sites-available` 的链接。使用 `aensite` 创建链接，使用 `a2dissite` 移除链接。

- **httpd.conf**：包含本地配置指令。此文件补充了相同目录下的 `apache2.conf` 文件。

- **conf.d**：包含配置指令。

- **access_log**：记录对服务器的请求。

- **error_log**：记录请求和服务器运行时错误。

- **icons**：包含用于显示目录条目的图标。此目录被别名为 `/icons/`。

- **error**：包含默认错误文档。你可以修改这些文档以符合你 Web 站的风格。此目录被别名为 `/error/`。参见 `ErrorDocument`。

## Redirect

`Redirect` 告诉客户端从不同的位置获取请求资源。

```
Redirect [status] requested-path [new-URI]
```

其中 `status` 是 Apache 在重定向时返回的状态。如果你省略了 `status`，Apache 假设为 `temp`。`status` 可以是 300–399 范围内的 Apache 代码，或以下之一：

- `permanent`：返回状态 301（资源已永久移动）
- `temp`：返回状态 302（资源临时移动）
- `other`：返回状态 303（资源已替换）
- `gone`：返回状态 410（资源已移除）

`requested-path` 是 Apache 要重定向的普通文件或目录的绝对路径。Apache 重定向所有以 `requested-path` 指定的绝对路径开头的请求。如果你想在该参数中使用正则表达式，请使用 `RedirectMatch`。

`new-URI` 是 Apache 重定向到的 URI。如果 `new-URI` 以斜杠 (`/`) 开头而不是 `http://` 或 `ftp://`，Apache 使用与其调用时相同的前缀。大多数 `Redirect` 指令都需要一个 `new-URI` 参数。

## RedirectMatch

`RedirectMatch` 告诉客户端从正则表达式指定的不同位置获取请求资源。

```
RedirectMatch [status] requested-path-re [new-URI]
```

该指令与 `Redirect` 相同，你可以在 `requested-path-re` 中使用正则表达式。

`apache2-default` 安装在 `/etc/apache2/sites-available/default` 的文件包含以下注释：

```
#RedirectMatch /$ /apache2-default/
```

如果你移除开头的井号（即取消该行），此指令会将所有指向 `/`（根目录）的请求重定向到同一服务器上的 `/apache2-default`。正则表达式 `^$` 匹配所有带有 `/` 的 URI（`^` 匹配字符串开头，`$` 匹配字符串结尾）。由于 `requested-path` 指定了 URI 的开头，因此此正则表达式匹配所有对根目录的请求。当用户将浏览器指向服务器根目录时，Apache 将用户的请求重定向到 `apache2-default` 目录并立即显示它！

- **上下文**：服务器配置、虚拟主机、目录、.htaccess
- **指定位置**：sites-available/*
- **默认值**：无
- **Ubuntu**：无，但见上文

## ServerAdmin

`ServerAdmin` 设置错误页面上 `mailto` 链接使用的电子邮件地址。

```
ServerAdmin email-address
```

其中 `email-address` 是负责管理 Web 内容的人员邮箱。Apache 将此链接作为 Apache 生成的错误页面包含。Ubuntu Linux 将 `ServerSignature` 设置为 `On`，这会导致 Apache 在错误页面上显示服务器信息而不是电子邮件地址链接。如果你想在错误页面上显示链接，请将 `ServerSignature` 设置为 `Email`。确保 `email-address` 指向一个有人经常检查的账户。用户可以使用此地址获取网站帮助或告知管理员存在的问题。`ServerAdmin` 没有默认值；如果你没有使用此指令且 `ServerSignature` 设置为 `Email`，错误页面上的 `mailto:` 链接将指向[未给出地址]。

### 安全提示：ServerAdmin 吸引垃圾邮件

你在 `ServerAdmin` 中填写的邮箱经常会吸引垃圾邮件。请使用垃圾邮件保护的地址，例如 `"msg at some bob dot com"`（你必须使用引号），或使用自定义错误页面指向一个发送邮件给正确人员的 Web 页面。

你可以使用如域名下的 `webmaster` 别名，并使用邮件别名将发送给 `webmaster` 的邮件转发给维护网站的人员。

- **上下文**：服务器配置、虚拟主机
- **指定位置**：sites-available/*
- **默认值**：无
- **Ubuntu**：webmaster@localhost

## ServerName

`ServerName` 指定服务器名称以及其监听的端口。

```
ServerName FQDN [:port]
```
