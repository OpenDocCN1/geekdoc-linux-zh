### 9.1 向内核传递以太网参数

这里有两个可以在启动时传递给内核的通用内核命令（`ether` 和 `reserve`）。可以通过 `LILO`、`loadlin` 或任何接受可选参数的启动工具完成。

例如，如果命令为 'blah' 并且添加了 3 个参数（例如 123, 456 和 789），那么在 `LILO` 中，你将使用：

```
LILO: blah=123,456,789
```

有关启动时参数（以及完整列表）的更多信息，请参 BootPrompt–HOWTO。

#### ether–argument 命令

`ether–argument` 与直接构建在内核中的驱动程序配合使用。`ether–argument` 对模块化驱动程序没有任何影响。在最通用的形式下它看起来像这样：

```
ether=IRQ, BASE_ADDR, PARAM_1, PARAM_2, NAME
```

# Linux 以太网指南

所有参数都是可选的。第一个非数字参数被视为 `NAME`。

- `IRQ`: 显而易见。`IRQ` 值 `0`（通常为默认值）意味着自动 IRQ。`IRQ` 设置是固定而非 base_addr 定的是一个历史偶然——每当发生变化时，它就会被修复。
- `BASE_ADDR`: 显而易见。值 `0`（通常为默认值）意味着使用以太卡的板载类型特定地址列表。
- `PARAM_1`: 它最初用于共享内存以太网卡 `WD80*3` 的内存起始地址覆盖。某些驱动程序使用此值的四位来设置调试级别 0 — 默认，1–7 — 1…7（最大详细程度），8 — 级别（无消息）。`LANCE` 驱动程序使用此值的四位来选择 DMA 通道。否则，它使用自动 DMA。
- `PARAM_2`: `3c503` 驱动程序使用此在内部和外部收发器之间选择。0 — 默认/内部，1 — AUI 外部。Carleton `E21XX` 卡也使用 `PARAM_2` 的 4 位来选择输出介质。它会自动检测它们。
- `NAME`: 网络设备值指向此处。标准使用 `eth0`、`eth1`、`eth2` 和 `eth3` 名称用于总线连接的以太卡，`atp0` 用于并行端口 `口袋以太网适配器`。`arcent` 驱动程序使用 `arc` 作为名称。默认设置是启用 `eth0` 的探测。可以通过 `LANCE` 参数显式设置这些探测来启用多块卡。1.0 内核中基于 `LANCE` 的以太卡是一个规模事实。`LILO` 参数被忽略，且 `LANCE` 卡始终被分配为 `eth<n>`。额外的非 `LANCE` 以太卡必须显式分配为 `eth<n+1>`，而通常的 `eth0` 探测某些东西诸如 `eth0=0,-1,eth0`。（是的，这是一个 bug）。

### reserve 命令

此 `lilo` 命令与上述的 `eth=` 类似，它被附加到 `lilo` 中指定的启动选择名称之后：

```
reserve=IO-base,extent(, IO-base,extent...)
```

在某些机器上，它可能需要防止设备驱动程序在特定区域检查设备（自动探测）。这可能是因为硬件设计不当导致启动冻结（例如某些以太卡）、硬件被错误识别（其状态被早期的探测更改），或硬件不知道要初始的内核。

`reserve` 启动时间通过指定一个不应探测的 I/O 端口区域来解决这个问题。该区域在内核的端口注册表中被保留，仿佛在该区域已经找到了一个设备。这种机制在大多数机器上是不需要的。只有在出现问题或特殊情况时才需要使用它。

指定区域内的 I/O 端口受设备探测的保护。这用于当一个驱动程序运行在 `NE2000` 上，或将某些其他设备误识别为我们的设备时。正确的驱动程序不应该保留一个区域，除非另一个启动参数显式指定这样做。这意味着 `reserve` 经常必须与某些启动参数一起使用。

## 9.2 作为模块使用以太网驱动

大多数 Linux 发行版现在提供的内核包含极少的内置驱动。驱动程序改为以可加载模块的形式提供。这些模块驱动程序通常由管理员使用 `modprobe` 命令加载，在某些情况下由内核自动加载。

特定的发行版可能提供用于设置模块的良好图形化工具。随后的描述提供了有关这些程序的信息。

控制使用哪些模块以及向每个模块提供哪些选项的信息通常存储在 `/etc/conf.modules` 文件中。两个两个主要选项（针对以太卡）将在文件中作为 `alias` 和 `options` 使用。`modprobe` 命令查询此信息。

模块本身通常存储在名为 `/lib/modules/` 的目录中（`uname -r` 给内核版本，例如 2.0.34）。你可以在那里查看哪些模块匹配你的卡。
