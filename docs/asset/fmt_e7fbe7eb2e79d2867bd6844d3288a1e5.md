简单来说，“熟制磁盘”（cooked disk）安装允许你创建特定大小的 Linux 文件，由 Linux 连同 Informix 一起管理。熟制文件被创建出来，并且看起来就像普通的 Linux 文件。创建熟制文件时考虑了特定的大小，只要 Informix 服务器处于离线且关闭状态，就可以使用标准备份工具对其进行备份。为了备份这些文件，必须像处理普通的 Linux 文件一样先关闭它们。熟制文件的优点在于它们仅仅是 Linux 文件，因此备份它们就像备份任何其他 Linux 文件一样简单。

## 为 Informix 设置数据文件

创建一个独立的驱动器，`/opt/data` 或 `/db/data`，最好是一个名为 `/data` 的独立硬盘，并在其下创建一个名为 `/data/informix` 的独立目录。我有一个称为 `/db` 的独立驱动器，我们创建了一个 `/db/data` 目录作为所有数据的家。对于我们的安装，我们将使用 `/opt/data`，但你应该有一个不同的目录。如果可能，建议将数据与软件分开。正如我稍后决定的，你应该至少为数据分配 500MB 。除非无法避免，否则在数据空间上吝啬是没有意义的。当我谈到空间分配时，指的是总空间，而不是特定文件。你的总聚合空间应小于 500MB，我们在这个空间内创建不同大小的熟制文件。

Informix 使用“块”（chunks）来描述数据空间的最大值。所有数据作为“页”（pages）存储在块内部，页是数据空间的最小单位。请参阅《管理员指南》获取关于块和页的完整描述。本章将使用这些术语来完成安装，因此理解这些概念对你来说。你会发现 Informix 软件拥有获奖文档。它们的文档已获得众多奖项。

一旦你熟悉了块和 dbspaces 的概念，就可以准备好配置服务器运行了。我们将设置一个服务器，允许你自行指定使用多少数据空间以及留出的最小运行空间。这样你就可以以最小的烦恼扩展系统。

有几个需要预留磁盘空间的最小 dbspaces。这些是最小的；其余的由你决定作为额外 dbspaces 添加的数据空间。以下是运行空间：

- **Rootdb**：包含 `sysmaster` 数据库的 dbspace，它是数据库引擎的智能中心。

- **Physdbs**：用于在数据写入磁盘之前进行缓冲的 dbspace。它包含在 `rootdbs` 中，但为了提高性能和方便管理，应将其移动到它自己的 dbspace 中。你可以给这个 dbspace 起任何喜欢的名称；然而，建议使用与其功能一致的名称。

- **Logdbs**：用于逻辑日志的 dbspace。在安装时，它包含在 `rootdbs` 中，为了更好的运行，应将其放置在它自己的 dbspace 中。你可以给这个 dbspace 起任何喜欢的名称；然而，建议使用与其功能一致的名称。

- **Tempdbs0**：用于临时表和查询排序的 dbspace。你可以给这个 dbspace 起任何喜欢的名称；然而，建议使用与其功能一致的名称。

以下是数据空间。你可以给这些 dbspaces 起任何喜欢的名称。

- **Dbs_dbs**：用于创建数据库但不是创建表的 dbspace。会创建一个数据库条目，并带有基本的系统表条目，但用户表是在此空间之外的。

- **Datadbs01**：用于用户表的 dbspace。

- **Indexdbs01**：用于用户索引的 dbspace。

如果你创建了这组最小的 dbspaces，你将拥有一个最小安装，可以在你学习 IDS 引擎如何工作时满足你的大部分需求。它还允许你随着需要的增加而进行扩展。

## 关于磁盘

你应当在你的系统上设置一个区域来容纳 Informix。有三个区域需要考虑：软件、dbspaces 以及用于备份、日志等的工作区域。

出于速度和灵活性，推荐使用 SCSI 而非 IDE。SCSI 允许你比 IDE 更容易地链驱动器；然而，如果你对 IDE 足够熟悉，你可以实现类似的磁盘设置，但 IDE 有一些局限性，无法提供与 SCSI 相同的灵活性。如果可能，为你的系统获取一个 SCSI 控制器并使用 SCSI 驱动器。
