
# 自动化一个 FTP 文件传输

## 连接到远程机器并开始一个 here document

```bash
ftp -i -v -n wilma <<END_FTP
user randy mypassword
binary
lcd /scripts/download
cd /scripts
get auto_ftp_xfer.ksh
bye
END_FTP
```

## 列表 17.2 脚本中用于 FTP 传输的简单 here document（续）

注意列表 17.2 中开始和结束标签的位置。第一个标签 `<<END_FTP` 开始了 here document，它紧跟在需要输入的交互式命令之后（在我们的案例中就是 `ftp` 命令）。接下来是用户必须为交互式命令提供的所有输入。在这个示例中，我们使用 `user randy mypassword` 语法登录到远程机器 wilma。此 `ftp` 命令指定用户为 randy，并通过将传输模式设置为二进制、本地目录更改为 `/scripts/download`，然后将远程机器的目录更改为 `/scripts/auto_ftp_xfer.ksh` 来设置传输环境。最后一步是获取 `auto_ftp_xfer` 脚本。要退出 `ftp` 会话，我们使用 `bye`；`quit` 也可以。最后一个标签 `END_FTP` 结束了 here document，脚本退出。

还要注意列表 17.2 中的 `ftp` 命令开关。`-i` 命令开关关闭了多个文件传输期间的交互式提示，因此不会提示用户名和密码。请查看 FTP 手页中的 `prompt`、`mget`、`mput` 和 `mdelete` 命令以了解多个文件传输期间的提示。`-n` 开关防止初始连接时的自动登录。否则，`ftp` 命令会搜索 `$HOME/.netrc` 条目，描述远程主机的登录和初始化过程。请查看 `ftp` 手页中的 `user` 子命令。`-v` 开关被添加到 `ftp` 命令中以设置详细模式，允许我们从 `ftp` 会话运行时看到命令。列表 17.2 中的 `tst_ftp.ksh` shell 脚本在列表 17.3 中运行。

################################################################
usage_error ()
{
    echo "\n错误：此 shell 脚本需要一个一个或多个
    从远程站点下载的文件列表。\n"
    usage
}

################################################################
################################################################ 主体开始
################################################################

# 测试以确保文件（s）已在 $1
# 命令行参数中被指定。

(( $# != 1 )) && usage_error

pre_event

# 连接到远程站点并开始在此在此化。
