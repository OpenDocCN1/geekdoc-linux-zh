
通过发布越来越复杂的命令，你可以开始收集关于使用的真正有用信息。这些脚本编写耗时，执行缓慢，而且每次你想提取不同的统计数据时都需要修改。除非你需要以特定格式收集特定的统计数据，否则可能使用市场上的许多分析程序会更好。

## 高级分析

我提到过的基础报告仅仅是以不同的方式总结访问日志。某些更高级的分析方法会在日志条目寻找模式。访问日志条目产生的两种有用模式是用户会话（sessions）和会话路径（session paths）。

### 会话化

某些高级分析程序允许你尝试区分对网站的*唯一访问*。这些程序通常将会话定义为在特定时间内来自同一 IP 地址的一系列请求。定义会话后，程序可以给你提供以下信息：

- 每个时期的总唯一访问人数
- 平均会话时长
- 每个会话访问的平均页面数

会话化并不是门精确的科学。如果多个用户在同一时期来自同一个 IP 地址，这些访问无法通过会话化进行跟踪。此外，频繁重新分配的动态 IP 地址无法可靠地跟踪。尽管有这些缺点，你可能仍然从允许会话化的分析程序中获得一些有趣的信息。

### 路径分析

如果你能识别特定的用户会话，你就可以跟踪用户在你的网站导航时的路径。高级分析程序查看每个会话并找到最常用的路径。经验网站管理员利用这些数据来确定热门入口页面、出口页面和常见的导航路径。

## 日志准确性

你的 Web 服务器日志为网站管理员、营销人员和广告商提供了丰富的数据。遗憾的是，原始日志本身并不是准确计数的可靠来源。许多因素会导致对日志生成的报告被严重高估或低估。

如果你的日志低估了使用量，会对你的利润造成可衡量的损害。想象一下，如果你根据原始日志仔细扩展了网站以确保在峰值负载下良好运行，结果发现自己低了 25%！在接下来的章节中，我将描述导致这些不准确的原因以及减轻这些风险的方法。

处理广告轮播。这些广告服务器通常具有内置功能，可以绕过某些缓存系统。

- 动态内容：大多数内容每几小时或几天更新一次。对于这类内容，你可能不需要担心缓存。每几小时更新一次不会影响你数据的及时性。但如果你的数据确实每几分钟更新一次（例如股票报价），你可能想要绕过缓存。请注意，你只需要对 HTML 页面本身禁用缓存；让图片被缓存。

- 安全数据：你可能正在处理敏感数据，你不希望它们保存在代理或本地缓存中。请注意，大多数代理系统和浏览器都不会缓存 SSL 加密的数据，所以如果你正在使用这种形式的安全防护，你已经妥妥了。

如果你想利用用户的代理和本地缓存，你应该尝试确定你的访问量中有百分之几是因为缓存而被低估的。然后你可以将这个数字作为未来分析的经验法则。

## 本地缓存

大多数 Web 浏览器都会保留内容的本地缓存，并尽可能从该缓存中提供服务。某些浏览器会发送一种称为 `get-if-modified-since` 的特殊请求，这实际上是在询问服务器文档是否已更新。如果服务器发现文档已更新，它会返回新文档。如果它发现文档相同，它会返回状态码 `304`。状态码 `304` 告诉浏览器从缓存中提供文档。

**提示：** 根据 FIND/SVP 的数据，所有 Web 流量的三分之一来自 America Online 用户。根据你的受众，你的大部分流量可能来自 AOL 缓存系统之后，并通过其专有的浏览器。要了解如何针对该环境进行最佳编程的内部消息，请查看 AOL 网站：

http://webmaster.info.aol.com

该网站包含了有关 AOL 浏览器、代理系统和其他有用内容的详细信息。

某些浏览器支持按页面逐绕过缓存的方法。你应该谨慎使用这些方法；缓存是你的朋友！通过插入以下 HTTP 头部，你可能能够绕过其后续页面的缓存：

- HTTP 1.0 头部: `Pragma: no-cache`
- HTTP 1.0 头部: `Expires: Thu, 01 Dec 1997 16:00:00 GMT`
- HTTP 1.0 头部: `Expires: now`
- HTTP 1.1 头部: `Cache-Control: no-cache`
- HTTP 1.1 头部: `Cache-Control: no-store`

## 代理缓存

许多公司和大型 ISP（包括 America Online）为其成员的 Web 访问使用缓存代理。除了普通的安全角色外，这些服务器会在离成员的地方保留某些内容的副本。这样，这些 ISP 就能提供更 Web 服务，并显著减轻互联网的负载。

代理缓存可以配置为保留一段时间的内容，或者直到文件达到特定的年龄。如果你想确保内容不被缓存，可以尝试几种方法。首先，许多缓存代理遵循上一节列出的 `expires` 和 `cache-control` 头部的指令。此外，某些代理不会缓存任何包含 `cgi-bin` 或问号的请求，因为这些字符通常表示动态的脚本生成页面。
