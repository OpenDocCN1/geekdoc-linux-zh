
`init`用于设置每个运行级别的脚本存储在目录`/etc/init.d/`中。每个运行级别在`/etc/`中都有一个对应的目录，命名为`/etc/rc0.d/`、`/etc/rc1.d/`、`/etc/rc2.d/`等，其中包含在相应运行级别启动时应执行的脚本。由于同一脚本可被不同的运行级别使用，这些目录中的文件只是指向`/etc/init.d/`中实际脚本的符号链接。此外，运行级别目录中链接文件名的第一个字母指示该服务在对应运行级别下是被启动还是被终止。以字母`K`开头的链接文件名表示进入该运行级别时服务将被终止（kill）。以字母`S`开头的链接文件名表示进入该运行级别时服务将被启动（start）。例如，目录`/etc/rc1.d/`将包含许多以字母`K`开头的网络脚本链接，因为运行级别1是单用户运行级别，没有网络连接。

命令`runlevel`显示系统的当前运行级别。`runlevel`命令显示两个值，第一个是之前的运行级别，第二个是当前的运行级别：

```bash
$ runlevel
N 3
```

输出中的字母`N`表示自上次引导以来运行级别没有发生变化。在此示例中，`runlevel 3`是系统的当前运行级别。

相同的`init`程序可用于在运行中的系统之间切换运行级别，而无需重启。命令`telinit`也可用于在运行级别之间切换。例如，命令`telinit 1`、`telinit s`或`telinit S`会将系统更改为运行级别1。

### systemd

目前，systemd是管理系统资源和服务最广泛使用的一组工具，这些在systemd中被称为单元（units）。单元由名称、类型和相应的配置文件组成。例如，`httpd`服务器进程（如Apache Web服务器）的单元在基于Red Hat的发行版中将是`httpd.service`，其配置文件也将命名为`httpd.service`（在基于Debian的发行版中，此单元命名为`apache2.service`）。

systemd单元有七种不同的类型：

#### service

最常见的单元类型，用于可启动、中断和重新加载的活动系统资源。

#### socket

socket单元类型可以是文件系统套接字或网络套接字。所有socket单元都有一个对应的service单元，当socket接收到请求时加载该service单元。

#### device

设备单元与内核识别的硬件设备相关联。只有当存在用于此目的的udev规则时，设备才会被视为systemd单元。当检测到特定硬件时，设备单元可用于解决配置依赖关系，因为udev规则中的属性可作为设备单元的参数使用。

#### mount

挂载单元是文件系统中的挂载点定义，类似于`/etc/fstab`中的条目。

#### automount

自动挂载单元也是文件系统中的挂载点定义，但是自动挂载的。每个自动挂载单元都有一个对应的挂载单元，当访问自动挂载挂载点时，该挂载单元将被启动。

#### target

目标单元是其他单元的分组，作为一个单一单元进行管理。

#### snapshot

快照单元是systemd管理器的保存状态（并非所有Linux发行版都可用）。

控制systemd单元的主要命令是`systemctl`。命令`systemctl`用于执行有关单元激活、去激活、运行、中断、监控等所有任务。对于一个名为`unit.service`的虚构单元，例如，最常用的`systemctl`操作将是：

- `systemctl start unit.service`

  启动单元。

- `systemctl stop unit.service`

  停止单元。

- `systemctl restart unit.service`

  重启单元。

- `systemctl status unit.service`

  显示单元的状态，包括它是否正在运行。

- `systemctl is-active unit.service`

  如果单元正在运行则显示*active*，否则显示inactive。

- `systemctl enable unit.service`

  启用单元，即该单元将在系统初始化期间加载。

- `systemctl disable unit.service`

  该单元不会随系统启动。

- `systemctl is-enabled unit.service`

  验证单元是否随系统启动。答案存储在变量`$?`中。值`0`表示单元随系统启动，值`1`表示单元不随系统启动。

较新版本的systemd实际上会列出单元在引导时的配置。例如：

> 注意

> `$ systemctl is-enabled apparmor.service`

> `enabled`

如果系统中不存在其他同名单元，则点号后的后缀可以省略。例如，如果只有一个类型为service的httpd单元，那么对于`systemctl`来说，仅使用`httpd`作为单元参数就足够了。

`systemctl`命令还可以控制系统目标。例如，`multi-user.target`单元结合了多用户系统环境所需的所有单元。这类似于使用SysV的系统中的运行级别3。

命令`systemctl isolate`在不同的目标之间切换。因此，要手动切换到目标multi-user：

```bash
# systemctl isolate multi-user.target
```

存在与SysV运行级别对应的目标，从`runlevel0.target`到`runlevel6.target`。然而，systemd不使用`/etc/inittab`文件。要更改默认系统目标，可以将选项`systemd.unit`添加到内核参数列表中。例如，要将`multi-user.target`用作标准目标，内核参数应为`systemd.unit=multi-user.target`。通过更改引导加载程序配置，可以使所有内核参数持久化。

更改默认目标的另一种方法是修改符号链接`/etc/systemd/system/default.target`，使其指向所需的目标。可以使用`systemctl`命令本身来重新定义该链接：

```bash
# systemctl set-default multi-user.target
```

同样，你可以使用以下命令确定你系统的默认引导目标：

```bash
$ systemctl get-default
graphical.target
```

类似于采用SysV的系统，默认目标绝不应指向`shutdown.target`，因为它对应运行级别0（关机）。

与每个单元相关的配置文件位于`/lib/systemd/system/`目录中。命令`systemctl list-unit-files`列出所有可用的单元，并显示它们是否被启用以在系统启动时启动。选项`--type`将仅选择给定类型的单元，例如`systemctl list-unit-files --type=service`和`systemctl list-unit-files --type=socket`。

`systemctl list-unit-files --type=target`.

处于活动状态的单元，或者在当前系统会话期间曾处于活动状态的单元，可以使用命令`systemctl list-units`进行列出。与`list-unit-files`选项类似，命令`systemctl list-units --type=service`将仅选择类型为service的单元，而命令`systemctl list-units --type=target`将仅选择类型为target的单元。

systemd还负责触发和响应与电源相关的事件。`systemctl suspend`命令会将系统置于低功耗模式，并保持当前数据在内存中。命令`systemctl hibernate`会将所有内存数据复制到磁盘，以便在关机后能够恢复系统的当前状态。与此类事件相关的操作定义在文件`/etc/systemd/logind.conf`或目录`/etc/systemd/logind.conf.d/`内的单独文件中。然而，只有当系统中没有运行其他电源管理器（如`acpid`守护进程）时，才能使用此systemd功能。`acpid`守护进程是Linux的主要电源管理器，允许对电源相关事件（如合上笔记本电脑盖子、低电量或电池充电级别）后的操作进行更精细的调整。

### Upstart

Upstart使用的初始化脚本位于目录`/etc/init/`中。可以使用命令`initctl list`列出系统服务，该命令还会显示服务的当前状态，以及（如果可用）其PID号。
