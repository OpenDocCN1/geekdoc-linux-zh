
现在你已经准备好使用 PostgreSQL 接口程序了。最常用的 PostgreSQL 接口是 `pgaccess` 和 `psql`。`psql` 是一个基于终端的命令行交互程序，而 `pgaccess` 是一个用 Tcl/Tk 程序编写的基于 X Windows GUI 的应用程序。它非常友好，你可以使用鼠标按钮点击各种功能来创建表和数据库、运行查询和报告等。由于 `pgaccess` 是 X Windows 应用程序，你必须赋予其他 UNIX 用户使用 X Windows 显示器的权限。要为其他 UNIX 用户提供 `pgaccess` 的 X Windows 显示访问，请输入

```bash
# xhost +
```

`xhost +` 意味着向系统上的所有 UNIX 用户提供显示访问。请参考标准的 X Windows 教书以获取更多帮助，并查看在线手册页：

```
# man xhost
```

输入以下命令以 `postgres` 身份登录：

```bash
# su - postgres
```

有关 `su` (`setuser`) 命令的详细信息请参见 `man su`。

现在你已以 `postgres` 用户身份登录。提示符符号从 `#` 变为 `bash$`。现在输入

```bash
bash$ id
postgres(uid=10 gid=4)
```

你已准备好创建第一个数据库了！通过使用创建的 `createddb` 命令来实现。查看关于 `createddb` 的在线手册页：

```bash
bash$ man createddb
bash$ createddb
```

这将创建一个名为 `database` 的数据库。创建数据库后，你可以通过 `psql` 接口访问它。输入以下命令查看在线文档

```bash
bash$ man psql
```

并输入以下命令访问数据库

```bash
bash$ psql
```

这将带你进入带有 `psql` 提示符的 `psql` 程序。在 `psql` 内部，你可以按向上和向下键进行历史记录编辑，或者使用命令。现在你可以在 `psql` 提示符下输入所有标准 SQL 命令。请参考 SQL 教程获取帮助。输入以下命令退出 `psql` 程序

```bash
bash$ q
```

这将让你回到 `bash$` 提示符。现在，要使用 `pgaccess` 接口连接 PostgreSQL，你应该导出一个名为 `DISPLAY` 的 Linux 环境变量

```bash
bash$ export DISPLAY=<hostname>:0.0
```

`<hostname>` 是 `/etc/hosts` 文件中指定的 Linux 主机名称，或者是主机的 IP 地址。例如，在我的机器上我输入：

```bash
bash$ export DISPLAY=localhost:0.0
```

或者输入：

```bash
bash$ export DISPLAY=192.168.1.10:0.0
```

其中 `10:0.` 是名为 `localhost` 的主机的 IP 地址。输入以下命令查看 `pgaccess` 的手册页

```bash
bash$ man pgaccess
```

并输入以下命令访问数据库

```bash
bash$ pgaccess
```

这将在你的 X Windows 系统或 KDE 上弹出一个精美的 GUI 应用程序。还有一个帮助按钮，可以提供关于 `pgaccess` 的更多细节。现在你可以开始在 `psql` 或 `pgaccess` 中疯狂敲击 SQL 命令了！所有文档都安装在 RedHat 系统的 `/usr/doc` 目录下。要阅读所有的 FAQ、用户指南、程序员和管理员指南及教程，请输入

```bash
bash$ cd /usr/doc/postgresql
```

你可以使用以下命令读取压缩的 postscript 文件

```bash
bash$ cat admin.gz
```

另请关于 `make` 命令的在线文档

```bash
bash$ man make
```

如果上述步骤对你不起，那么你可以从安装步骤（Installation Steps）http://www.redhat.com/postgres 获取更多信息。Lamar Owen 是 PostgreSQL 的维护者，他的电子邮件地址为 lamar.owen@gnu.org。此外，请熟悉 RedHat 软件包管理器以管理 PostgreSQL 的安装。从 http://www.rpm.org 下载 Maximum RPM 并寻找名为 `maximum-rpm.gz` 的文件。在 Linux 上使用 `cat` 命令读取

```bash
bash$ cat maximum-rpm.gz
```

## 源码发行版的安装

除了这些工具之外，你还需要 GNU 工具 `gcc` 和 `make`。你可以通过以下命令判断你是否拥有这些工具

```bash
shell$ which gcc
/usr/bin/gcc
shell$ which make
/usr/bin/make
```

安装的 `gcc` 必须是 2.81 或更高版本。你可以通过以下命令确定版本：

```bash
shell$ gcc -v
Reading specs from /usr/lib/gcc-lib/i386-redhat-linux/2.91.66/specs
gcc version 2.91.66 19990314/Linux-1.1.2 release
```

如果这不是正确的版本，请参考你的 Linux 发行版文档以查找如何升级。此外，访问之前列出的 GNU 网站获取安装这些工具的帮助。命令在 RedHat Linux 5.2 上使用 `bash` shell 进行过测试。除非另有说明，否则它们可能在大多数系统上运行。`ps` 和 `tar` 等命令在不同平台上的选项可能差异巨大。在输入这些命令之前，请运用常识。

如果你还没有 PostgreSQL 发行版，请从 `ftp.postgresql.org` 获取并解压

```bash
$ gunzip postgresql-7.0.tar.gz
$ tar -xvf postgresql-7.0.tar
$ mv postgresql-7.0 /usr/src
```

## 在开始之前

构建 PostgreSQL 需要 GNU `make` 命令。它无法在其他工具上工作。你可以通过以下命令判断你是否拥有这些工具：在 GNU/Linux 系统上，`make` 是默认工具；在其他系统上可能会发现它被命名为 `gmake`。从现在起使用该名称。要测试 `make`，输入

```bash
$ gmake --version
```

如果你需要 `make`，可以从 `ftp://gnu.org` 获取。关于支持平台的最新信息请访问 http://www.postgresql.org/docs/admin.htm。确保你有足够的磁盘空间。编译期间源码树大约需要 30MB，安装目录需要 5MB。一个空数据库占用 1MB；否则，它们占用空间文件的五倍。如果你运行回归测试，将额外需要 20MB。检查磁盘空间，请使用

```bash
$ df -k
```

考虑到如今硬盘的价格，在投入生产使用之前可能应该准备一个大硬盘

## 步骤说明

对于全新安装，或从之前的 PostgreSQL 版本升级：

- 1. 创建 PostgreSQL 超用户——服务器将以该用户运行。对于生产使用，你应该创建一个无权限账户（通常使用 `postgres`）。如果你没有 root 权限或只是想玩玩，你自己的用户账户就足够了。以 root、bin 或任何具有特殊权限的账户运行 PostgreSQL 存在安全风险且是不允许的。你不需要在此账户下进行构建和安装（尽管你可以这样做）。

- 2. 如果你不是升级现有系统，请跳到第 4 步。

现在你需要备份现有的数据库。要导出你最近的 6.0 数据库安装，输入

```bash
$ pg_dumpall > db.out
```

如果你希望保留对象 ID (`OIDs`)，在运行 `pg_dumpall` 时使用 `-o` 选项。但是，除非你有特殊理由（例如在表中使用 OIDs 作为键），否则不要这样做。

确保你使用与你当前运行版本的 `pg_dumpall` 命令。但是，不要使用 6.0 版本的 `pg_dumpall` 脚本，否则所有内容都将属于 PostgreSQL 超用户。在这种情况下，你应该从较后的 6.x.x 版本中获取 `pg_dumpall`。版本 7.0 的 `pg_dumpall` 将无法工作

在旧版本的数据库上。如果您正在从 Postgres 95 v1.09 之前的版本升级，您必须备份数据库、安装 Postgres 95 v1.09、恢复数据库，然后再次进行备份。

**警告** 您必须确保您的数据库在备份过程中没有被更新。如有必要，请停止主进程（`postmaster`），编辑 `/usr/local/postgresql/data/pg_hba.conf` 文件中的权限以仅允许您本人登录，然后重新启动 `postmaster`。
