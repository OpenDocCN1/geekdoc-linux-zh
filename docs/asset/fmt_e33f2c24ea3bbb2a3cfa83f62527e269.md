## 2 编写良好的 GNU/Linux 软件

本章涵盖了大多数 GNU/Linux 程序员使用的一些基本技术。通过遵循所提出的指南，你将能够编写在 GNU/Linux 环境中运行良好，并符合 GNU/Linux 用户对程序运行方式的程序。

### 2.1 与执行环境的交互

当你第一次学习 C 或 C++ 时，你学习了特殊的 `main` 函数是程序的主要入口。当操作系统执行你的程序时，它会自动提供某些设施，帮助程序与操作系统以及用户进行通信。你可能学习过 `main` 的两个参数，通常称为 `arg` 和 `argv`，它们接收程序的输入。你学习了 `stdout` 和 `stdin`（或 C++ 中的 `cout` 和 `cin` 流），它们提供了控制台输入输出。这些功能由 C 和 C++ 语言提供，并且它们以某些方式与 GNU/Linux 系统交互。GNU/Linux 也提供了与运行环境交互的其他方式。

#### 2.1.1 参数列表

你通过在 shell 中提示输入程序名称来运行程序。可选地，你可以在程序名称后输入一个或多个由空格分隔的单词，为程序提供额外信息。这些被称为命令行参数。（你也可以通过将参数括在引号中来包含包含空格的参数。）更通地说，这被称为程序的参数列表，因为它并不一定源自命令行。在第 3 章“进程”中，你将看到另一种调用程序的方式，在那种方式下，程序可以指定另一个程序的参数列表。

当程序从 shell 调用时，参数列表包含整个命令行，包括程序名称和任何可能提供的命令行参数。例如，假设你在 shell 中调用 `ls` 命令来显示根目录的内容以及相应的文件大小，使用如下命令：

```bash
ls -s
```

`ls` 程序接收到的参数列表有三个元素。第一个元素是命令行上指定的程序名称，即 `ls`。参数列表的第二个和第三个元素是两个命令行参数 `-s` 和 `/`。

你的程序的 `main` 函数可以通过 `argc` 和 `argv` 参数访问参数列表（如果你不使用它们，可以简单地省略它们）。第一个参数 `argc` 是一个整数，被设置为参数列表中的项数。第二个参数 `argv` 是一个字符指针数组。数组的大小为 `argc`，数组元素指向参数列表中的元素，格式为以 NULL 结尾的字符字符串。

使用命令行参数就像检查 `argc` 和 `argv` 的内容一样简单。如果你对程序本身本身，不要忘记跳过第一个元素。

2.1 展示了如何使用 `argc` 和 `argv`。

#### 2.1 (arglist.c) 使用 argc 和 argv

```c
#include <stdio.h>

int main (int argc, char *argv[]) {
    printf('The name of this program is %s.\n', argv[0]);
    printf('This program was invoked with %d arguments.\n', argc - 1);

    /* 是否指定了命令行参数? */
    if (argc > 1) {
        /* 是的，打印它们。 */
        int i;
        printf('The arguments are:%s\n', argv[i]);
        for (i = 1; i < argc; ++i) {
            printf ("%s\n", argv[i]);
        }
    }
    return 0;
}
```

#### 2.1.2 GNU/Linux 命令行约定

几乎 GNU/Linux 程序都遵循关于命令行参数解释方式的一些约定。程序的参数分为两类：选项（或标志）和其他参数。选项修改程序的行为，而其他参数提供输入（例如，文件名）。

选项有两种形式：

- - 短选项由单个连字符和一个单个字符（通常是小写或大写字母）组成。短选项输入起来更快。

- - 长选项由两个连字符组成，后面跟着一个由小写和大大写字母组成的名称。长选项更容易记忆也更容易阅读（例如在 shell 脚本中）。

为了简洁和清晰，程序通常会对其支持的大多数选项同时提供短形式和长形式。例如，大多数程序都理解 `-h` 和 `--help` 选项，并以相同的方式处理它们。通常，当程序从 shell 调用时，它们期望紧随其后有一个参数。许多程序，例如，会解释选项 `--output foo` 以指定程序的输出应该存放在名为 `foo` 的文件中。在选项之后，可能会跟随其他的命令行参数，通常是输入文件或数据。

对于示例

《编码标准》（Coding Standards）列出了一些常用命令行选项的名称。如果你计划提供任何类似于这些选项，使用编码标准中指定的名称是一个好主意。你的程序行为将更像其他程序，并且对用户来说更容易学习。你可以通过在大多数 GNU/Linux 系统的 shell 提示符执行以下命令来查看 GNU 编码标准的命令行选项指南：

```bash
% info 'standards'
```

#### 2.1.3 使用 getopt_long

解析命令行选项是一项乏味的工作。幸运的是，GNU C 库提供了一个函数，可以在 C 和 C++ 程序中使用它来让这项工作变得简单一些（尽管仍然有点烦人）。这个函数 `getopt_long` 同时理解短选项和长选项。如果你使用此函数，请包含头文件 `<getopt.h>`。

假设，你正在编写一个要接受三个参数的程序。`getopt_long` 函数同时理解短选项和长选项。

2.1 示例

| 短形式 | 长形式 | 目的 |

| --- | --- | --- |

| -h | --help | 显示帮助信息 |

| -o | --output | 指定输出 |

| -v | --verbose | 输出详细信息 |

此外，`getopt_long` 接受零或多个命令行参数，通常是输入文件。

要使用 `getopt_long`，必须提供包含短选项的字符串。`getopt_long` 需要一个结构数组来描述长选项。你可以这样构造数组：

```c
struct option options[] = {
  {"help", 0, NULL, 'h'},
  {"output", 1, NULL, 'o'},
  {"verbose", 0, NULL, 'v'},
  {NULL, 0, 0}
};
```

在 `getopt_long` 完成解析所有选项后，全局变量 `optind` 包含非选项参数的索引。当 `getopt_long` 处理带参数时，全局变量 `optarg` 指向该参数的文本。如果 `getopt_long` 遇到无效选项（你未指定的短或长选项），它会打印错误消息并返回 `?`（问号）。
