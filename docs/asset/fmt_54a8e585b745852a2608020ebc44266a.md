## 为树莓派 Pico 优化电池使用

## 节能模式

树莓派 Pico 的高性能芯片针对 I/O 进行了精简，并不是为了省电。然而，电池模式下的一些技巧可以让它运行得更久。作者： Bernhard Bablok

大量的引脚、可变电压输入和良好的社区支持使得树莓派 Pico 成为初学者和专业人士通用的强大单板计算机 (SBC)。它通过 USB 连接到你的 PC 并快速启动供电。当你想要让 Pico 独立运行时，你将面临电池供应能持续多久的问题。与大多数微控制器一样，Pico 耗电相对较小，但在电池运行方面存在局限性，而且在睡眠期间它会继续耗电。一些技巧将帮助你减少这些阶段的功耗，以延长电池运行时间。

## MAKERSPACE Pico 睡眠模式

在功耗方面，使用 `alarm` 的深度睡眠比使用 `sleep` 高效得多；电流从 6mA 降至 1mA。你不需要将按键连接到引脚上，任何将引脚拉低的组件工作方式都是相同的。如果有像 `DS3231` 这种带有中断引脚的外部 RTC 也可以。

`CircuitPython` 实现的另一个在此情况下非常有用的特性是：`alarm.sleep_until()` 函数可以接受任意数量的报警。如果设备带有按钮，你就不需要专门的唤醒按钮。报警可以通过几个定时器和引脚报警触发，但并非每个芯片都支持这些变体。

**图 2：** 浅睡眠模式（顶部）和深度睡眠模式（底部）的功耗。

通过这些模式，浅睡眠的功耗降到 17mA，深度睡眠降到 6mA（图 2）。从深度睡眠中唤醒时的额外开销在相同情况下可能高达 10mA。电池电量完全足够。在 `ESP32-S2` 上，深度睡眠的电流消耗降到 1mA 以下，平均时间为 2ms，相应的运行时间更长。

同样重要的是 Pico 不会关闭 3V3。如果连接了外围设备，它将继续运行。如果你不希望这样，你需要在发送 Pico 进入睡眠之前（如果可能的话）关闭连接到它的设备，或者使用简单的电路来禁用它们。

如果你想测试睡眠模式，请注意深度睡眠在活跃的 USB 连接下是无法工作的。这意味着某些安全机制防止代码在用户无法激活的情况下立即将 Pico 送入深度睡眠。

# MADDOCK 的狗舍

编程语言的效率并不能说明问题。作者：JOHN "Maddog" HALL

## 语言“效率”

我理解跨云架构的重要性，它允许你在某个特定供应商的成本过高或云供应商消失时，迁移你的应用程序。

这篇文章的灵感源于与 Lincoln 的一次对话，内容关于一份发布各种语言效率的白皮书，该白皮书声称 Python 的效率非常高，仅次 C 和 C++ 等编译语言。许多人的观点不一，从“Python 正在毁灭地球”到“像 Python 这样的语言到底是什么？”。

首先，指着一种语言并说效率其实并不真正有用。语言涉及到人类能够理解的语法和语义，以及计算机可以执行的二进制代码，通常通过作为编译器或解释器的程序来实现。

编译器和解释器在转换过程中都会消耗 CPU 周期。编译器倾向于在转换阶段而不是运行时完成工作，而运行机器码才是效率的唯一关键。这种效率的代价是失去了许多解释器“保留”的额外信息。例如，解释器可能在执行期间捕获错误并指向问题发生的源代码。而使用编译器时，这些源代码映射可能非常复杂。

其次，在同一种语言的编译器之间，我们有不同程度的效率。在 C 语言中，有由不同团队在不同时期创建的许多版本的编译器，它们通常满足不同程度的需求。

某些编译器倾向于生成针对大小优化的代码。另一些则可能更关注速度，对代码进行不同的优化。如果你查看 `GCC` 编译器，你可以看到代码中以各种方式进行的许多不同优化，这些都会影响代码的“效率”。

解释器将使用代码并在不进行任何优化的情况下使其运行，这使得实现实际性能变得困难，但随后会进行即时优化。

这样做很好，但优化可能会引入错误，而且这些错误往往很难找到。

许多阅读白皮书的人认为，解释器和脚本语言的效率总是较低。

我经常听到关于脚本效率低下的说法。然而，Unix 和 Linux 多年来一直被重写得非常高效，取决于应用程序，一个编写得良好的脚本可能与编写得当的 C 一样高效。

解释器通过预编译来减少“停止点”（或循环），这些停止点是由非常高效的运行时消耗的。

还有一种“精简解释型语言”的概念，其中“线程”简单地在每个模块调用后收集调用。

C 是一种非常强大但极简的语法，但它迫使编译器创建自己的例程或使用来自各种操作系统的库。“指针”的使用如果用得当是极其有力的，但如果编译器不小心，也会导致错误。

Python 有许多实用的函数，例如垃圾回收，使得该语言与不同类型的函数良好配合工作。另一方面，语法如此复杂以至于凡人难以学习的语言则增加了复杂性。

人们问我如何开始编程。我指向 Unix 和 Linux Shell 空间中的脚本作为“第一门语言”，那里的所有工具都既好用又强大。

然后我推荐一种易于学习的第一种编程语言，有很多，其中大多数只需要程序员学习如何操作即可。

之后，我建议学习 C 或 C++ 或（现在的）Rust。

最后，一个优秀的程序员会学习更多特殊的语言，或者仅仅为了某些工作而需要修复其他程序员编写的代码。

权衡是编程的易用性与算法效率之间的平衡，这与语言语法的关系很小。
