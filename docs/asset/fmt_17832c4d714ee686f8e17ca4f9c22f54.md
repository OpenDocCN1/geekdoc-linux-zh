
# truss — 跟踪系统调用和信号

### 概要

```
/usr/bin/truss [-fcaildD] - [tTvx] [!]syscall,... 
[-s [!]signal,... -mM [!]fault,... - [rw] [!]fd,... 
[-UU] [!]lib,...:[!]func,... -o outfile command -p pid
```

## 描述

`truss` 命令执行指定的命令，并对其所执行的系统调用、接收到的信号以及引发的系统故障生成跟踪。跟踪输出的每行都会报告故障名称、信号名称，或者带有参数和返回值的系统调用。在可能的情况下，使用来自相关系统头文件的定义以符号形式显示系统调用参数；对于任何路径名指针参数，将显示其指向的字符串。使用 `intro(2)` 中描述的错误代码报告错误返回。

可选地（使用 `-u` 选项），`truss` 还会对跟踪进程执行的用户级函数调用生成进入/退出跟踪，这指示了嵌套关系。

## 注意事项

第 2 节描述的某些系统调用与实际操作系统接口有所不同。对于跟踪输出与第 2 节描述之间的细微偏差，不要感到惊讶。

每个系统故障（页异常除）都会导致向引发故障的轻量级进程发送信号。在每个系统故障报告（页异常除）之后，会紧接着报告接收到的信号，除非该信号正在被阻塞。

操作系统对进程跟踪实施了某些安全限制。特别是，任何用户无法读取对象文件（`.out`）的命令都无法被该用户跟踪；`setuid` 和 `setgid` 命令只能由超级用户跟踪。除非由超级用户运行，否则 `truss` 将失去对任何执行 `set ID` 或不可达对象文件 `exec()` 的进程的控制；这些进程将从 `exec()` 点开始，独立于 `truss` 继续正常运行。

为了避免与其他控制进程冲突，`truss` 不会跟踪通过 `/proc` 接口检测到受另一个进程控制的进程。这允许 `truss` 应用于 `proc(4)` 调试器以及自身的另一个实例。

跟踪输出包含制表符字符，假设标准制表符每八位设置一个。

多个进程或多线程进程（包含多个轻量级进程的）的跟踪输出不是按照严格的时间顺序生成的。例如，对管道的 `read()` 可能会在相应的 `write()` 之前报告。对于任何轻量级进程（传统进程只包含一个），输出是严格排序的。

并不是所有在所有系统调用传递的结构都在 `-v` 选项下显示。

## 选项

对于接受列表参数的选项，你可以使用名称 `all` 作为简写来指定列表的所有可能成员。如果列表以 `!` 开头，则该选项的含义取反（例如，是排除而不是跟踪）。你可以指定多次出现同一个选项。对于列表中相同的名称，后续的出现（右侧）将覆盖之前的出现（左侧）。

- `-a` 显示在每个 `exec()` 系统调用中传递的参数字符串。
- `-c` 统计系统调用、故障和信号的数量，而不是逐行显示跟踪。在跟踪命令终止或 `truss` 被中断时产生摘要报告。如果你还指定了 `-f`，则在计数中包含子进程的所有跟踪系统调用、故障和信号。
- `-d` 在跟踪输出的每行包含一个时间戳。时间戳是行开头包含“秒.小数”的字段。该值表示相对于跟踪开始的秒数。跟踪输出的第一行显示测量各个时间戳的基时间，包括自 Epoch 以来的秒数（参见 `time(2)`）和日期字符串（参见 `ctime(3)` 和 `date(1)`）。报告事件发生的时间。对于所有系统调用，事件是系统调用的完成而不是开始。
- `-D` 在跟踪输出的每行包含一个增量。该值是包含“秒.小数”的字段，表示自上一个报告事件以来经过的时间。
- `-e` 显示在 `exec()` 中传递的环境字符串。
- `-f` 跟踪由 `fork()` 创建的所有子进程。
- `-i` 在每行包含轻量级进程的 ID。
- `-l` 显示进程的完整名称。
- `-M` 显示停止进程的系统调用。
- `-o` 指定用于跟踪输出的文件。
- `-p` 将参数解释为 PID 列表。
- `-r` 显示每个描述符的 I/O 缓冲器的完整内容。
- `-s` 指定要跟踪或排除的信号。
- `-t` 跟踪列表中指定的系统调用。
- `-T` 显示停止进程的系统调用。
- `-u` 指定用户级函数调用。
