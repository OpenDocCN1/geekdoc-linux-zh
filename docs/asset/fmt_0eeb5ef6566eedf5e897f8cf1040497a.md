
- 隔离特定平台的代码：当必须包含特定平台的代码时，将其隔离在单独的模块或函数中。这使得管理和维护更加容易。

## 3. 在多个平台上进行测试

跨平台开发需要对每个目标平台进行彻底的测试。为您打算支持的每个平台设置测试环境，无论是 `Windows`、`macOS` 还是各种 `Linux` 发行版。像 `Selenium` 或 `Appium` 这样的自动化测试框架可以简化这一过程。

## 4. 用户界面注意事项

由于设计指南和用户期望的不同，用户界面（UI）在不同平台之间通常会有差异。创建跨平台应用时，考虑以下 UI 相关的方面：

- 原生外观和感受：努力在每个平台上提供原生的外观和感受。使用模拟该行为的特定平台 UI 组件或库。

- 响应式设计：确保您的 UI 能够适应各种屏幕尺寸和分辨率，特别是当同时针对桌面和移动平台时。

## 5. 处理文件路径和系统调用

文件路径和系统调用存在不同操作系统之间存在显著差异。使用平台无关函数和库进行文件操作，例如 C++ 标准库或 `Python` 的 `os` 模块。此外，正确处理特定平台的系统路径分隔符（例如，在 `Linux` 和 `macOS` 上使用 `/`，在 `Windows` 上使用 `\`）。

## 6. 版本控制与协作

在跨平台项目上协作时，使用 `Git` 等版本控制系统来管理代码更改并跟踪不同的特定平台分支或配置。利用有助于特定平台开发和合并的分支策略。

## 7. 持续集成 (CI)

实施持续集成流水线，自动在所有目标平台上构建并测试您的应用程序。`Jenkins`、`Travis CI` 或 `GitHub Actions` 等 CI 工具可以帮助确保一致的跨平台兼容性。

总之，`Linux` 下的跨平台开发涉及周密的规划、平台无关的代码设计和彻底的测试。选择合适的工具和库、编写适应不同平台的代码以及处理 UI 和文件系统的差异，都是创建成功的跨平台应用的关键步骤。通过遵循这些考虑，开发者可以在保持各种操作系统用户体验一致的同时，让软件触及更广泛的受众。

## 第 15 章：性能调优与优化

## 第 15.1 节：系统监控工具

系统监控是维护 `Linux` 系统健康和性能的关键方面。通过持续监控各种系统指标，管理员可以识别性能瓶颈、跟踪资源利用并及时响应问题。在本节中，我们将探索基本的系统监控工具和技术。

### 1. Top

`top` 命令是一个命令行实用程序，提供系统进程和资源使用的实时视图。它显示了关于 CPU 使用率、内存利用率以及资源密集型进程的信息。要运行 `top`，只需打开终端并输入：

```
top
```

`top` 显示定期更新，允许你观察系统性能随时间的变化。你可以按下各种键，根据不同的标准对显示的进程进行排序和过滤。例如，按下 `M` 将根据内存使用情况对进程排序。

### 2. Htop

`htop` 是 `top` 的交互式增强型替代品。它提供了更友好的界面，带有彩色显示和额外功能。要安装和运行 `htop`，你可以在不同的 `Linux` 发行版上使用 `apt`、`yum` 或 `dnf` 等包管理器：

#### 基于 Debian/Ubuntu 的系统

```
sudo apt install htop
```

#### 基于 CentOS/RHEL 的系统

```
sudo yum install htop
```

安装完成后，运行以下命令启动 `htop`：

```
htop
```

### 3. Glances

`Glances` 是另一个强大的系统监控工具，提供有关系统资源和进程的详细信息。它提供了一个基于 Web 的界面，可以通过浏览器访问。要安装 `Glances`，请使用你发行版的包管理器：

#### 基于 Debian/Ubuntu 的系统

```
sudo apt install glances
```

#### 基于 CentOS/RHEL 的系统

```
sudo yum install glances
```

运行以下命令启动 `Glances`：

```
glances
```

你可以通过打开浏览器并输入 URL `http://localhost:61208` 来访问 `Glances` Web 界面。

### 4. Sysstat

`Sysstat` 是一个性能监控工具的集合，包含了 `sar`、`iostat`、`mpstat` 等。它提供了系统资源使用的历史数据，允许你分析随时间变化的性能趋势。要安装 `Sysstat`，请使用你发行版的包管理器：

```bash
# 基于 Debian/Ubuntu 的系统
sudo apt install sysstat
```

```bash
# 基于 CentOS/RHEL 的系统
sudo yum install sysstat
```

安装后，你可以访问 `sar` 和 `iostat` 等各种性能监控工具来收集和分析系统统计数据。

### 5. Prometheus 和 Grafana

对于更高级和长期的监控需求，`Prometheus` 和 `Grafana` 提供了一对强大的组合。`Prometheus` 是一个时间序列数据库和监控系统，而 `Grafana` 是一个可视化和仪表板工具。它们共同为 `Linux` 提供了全面的监控和告警功能。

设置 `Prometheus` 和 `Grafana` 需要更多的配置和管理，但提供了扩展性和可定制性。它们通常用于大规模或云环境。

总结，`Linux` 提供了系列系统监控工具，帮助管理员和用户跟踪系统性能。无论你倾向于使用 `top` 和 `htop` 等命令行工具，还是选择 `Glances` 和 `Sysstat` 等更高级的解决方案，监控系统的资源利用和性能对于维护稳定响应的 `Linux` 环境至关重要。根据你的监控需求和偏好选择合适的工具。

## 第 15.2 节：内核调优与参数

内核调优是优化 `Linux` 系统性能和行为的关键。内核作为操作系统的核心，管理系统资源并为用户进程提供各种服务。通过调整内核参数，你可以微调系统运行方式并针对特定负载或硬件配置进行优化。

在本节中，我们将探索影响系统性能和行为的内核调优和重要参数。

### 1. sysctl：内核参数管理

`Linux` 提供了 `sysctl` 机制在运行时调整内核参数。`sysctl` 命令允许你查看和修改这些参数。内核参数按分级结构组织，可以使用点分隔的路径访问。

要查看特定的内核参数，请使用 `sysctl` 命令加上参数路径。例如，检查每个进程允许的最大打开文件描述符数量：

```
sysctl fs.file-max
```

要临时更改内核参数，可以使用带有 `-w` 标志的 `sysctl` 命令：

```
sysctl -w fs.file-max=65535
```

此更改是临时的，系统重启后将丢失。要使更改持久化，请将其添加到 `/etc/sysctl.conf` 文件中。编辑该文件并按 `参数 = 值` 的格式添加行。例如：

```
fs.file-max = 65535
```

然后，使用不带 `-w` 标志的 `sysctl` 命令应用更改：

```
sysctl -p
```

### 2. Swappiness（交换倾向）

`Swappiness` 是一个内核参数，用于控制 `Linux` 内核使用交换空间（swap space）的倾向。交换空间是物理内存耗尽时用作虚拟内存的磁盘区域。`Swappiness` 的范围从 0 到 100，较低的值（例如 0）会优先使用物理内存而非交换空间，而较高的值（例如 100）则会优先使用交换空间。

查看当前的 `swappiness` 值：

```
cat /proc/sys/vm/swappiness
```

临时更改 `swappiness` 值：

```
sysctl vm.swappiness=10
```

要使更改持久化，请将以下行添加到 `/etc/sysctl.conf`：

```
vm.swappiness = 10
```

### 3. 文件系统 I/O 调度器

I/O 调度器负责确定磁盘 I/O 操作的处理顺序。不同的调度器具有不同的行为，可能更适用于特定的负载。

查看设备（例如 `/dev/sda`）的当前 I/O 调度器：

```
cat /sys/block/sda/queue/scheduler
```

临时更改 I/O 调度器：

```
echo "deadline" > /sys/block/sda/queue/scheduler
```

要使更改持久化，你可以创建一个 `Udev` 规则或在启动加载器配置中修改内核命令行参数。

### 4. 透明巨大页 (THP)

透明巨大页（`THP`）是一项允许内核管理比标准 4KB 更大的内存页的功能。`THP` 可以提高某些负载的内存效率，但在某些情况下可能会引入延迟。

检查是否已启用 `THP`：

```
cat /sys/kernel/mm/transparent_hugepage/enabled
```

临时禁用 `THP`：

```
echo "never" > /sys/kernel/mm/transparent_hugepage/enabled
```

要使更改持久化，请将以下行添加到系统的启动脚本中：

```
