
### 3. 如果在当前目录中找不到 `pathname`
命令将检查变量 `cdpath` 是否存在且是否有值。如果是，将检查 `cdpath` 中命名的每个目录，看其是否包含 `pathname`。如果成功，命令将切换到该目录并返回当前目录的完整路径名。

### 4. 如果不存在 `cdpath`，或者在 `cdpath` 列出的任何目录中都找不到 `pathname`
命令将检查 `pathname` 是否为变量名，且是否具有一个以 `/` 开头的值。如果是，命令将切换到该目录。

### 5. 如果仍然无法找到
命令将失败。

关于 `cdpath` 变量的更多信息，请参见本章后部分的“使用预定义变量”。

C shell 实现的 `cd` 和 `chdir` 命令为生成目录名的快捷方式提供了极大的活性。没有比反复向 `cd` 命令提供目录名更痛苦的事情了。命令搜索层次结构的威力在于提供了许多你可以用于缩短目录名引用的机制。`cdpath` 变量是你的主要工具。如果你将其设置为你经常访问的目录列表，你只需提供基本名即可引用其中之一。如果 `cdpath` 不足以满足你的需求，你可以定义一个 shell 变量作为目录完整路径名的别名，通过 `cd dirname` 只需几次击键即可切换到该目录。

注意：使用 shell 变量作为目录路径的别名时，变量名前名前加上 `$`。这样做是允许的，并且由于 shell 变量替换机制可以工作，但不需要使用环境变量（`set` 命令）。

## 目录栈

`dirs` 目录栈是一种机制，你可以用它存储和召回通过特殊切换命令 `pushd` 和 `pop` 更改的目录，这些命令将在下一节讨论。`dirs` 命令列出栈中的目录：

```
% dirs
/usr/local/bin ~/html/manuals
```

在这个例子中，栈上有三个目录。列出的第一个目录是当前目录（如果你使用 `pwd` 命令看到的）。右侧的目录是之前的目录，最右侧的是最近的。在这个例子中，`/users/wadams/bin` 是第一个被更改并“推入”栈的；`~/html/manuals` 是最近更改的。

### 使用目录栈更改目录：`pushd`

为了将目录名保存在栈中，可以使用 `pushd` 命令切换到另一个目录。使用 `pushd` 将你上一个目录的路径名保存在栈中，以便通过使用 `pushd` 命令快速方便地返回。每次 `dirs` 显示 `pushd` 栈上的目录。

`pushd` 有三种形式：

```
pushd
pushd name
pushd +n
```

以 `pushd` 形式使用时，命令交换两个顶栈元素，使你的上一个目录变成当前的，当前的目录变成之前的。连续的 `pushd` 命令不带参数可以在两个目录之间切换。

以 `pushd name` 形式使用时，命令以与 `cd` 相同的方式切换到目录；`pushd` 使用 `cdpath` 列表并在相同的情况下失败。在更改之前，当前目录的路径名会被保存在栈中。目录栈是 shell 维护的隐式数组；每个 `pushd` 将目录向左并将所有元素向右推。顶部（或第一个）元素是你的当前目录，后续元素是你之前目录的反序路径。`pop` 命令丢弃栈并移动到新的顶部，使栈上的元素总减少一。

使用 `pushd +n` 形式执行目录栈的 n 位位移，切换到新的顶部目录。循环位移将元素置于环中，第一个元素的前面是最后一个，最后一个后面是第一个。位移改变了你在环中的位置，而不删除任何元素。考虑以下示例：

```
% dirs
/home/john /home/mary /home/doggie /home/witherspoon
% pushd +2
/home/doggie
% dirs
```

`/home/doggie /home/witherspoon /home/john /home/mary`

注意在执行 `pushd` 之前之后，`/home/john` 都在 `/home/mary` 之前，且 `/home/doggie` 都在 `/home/witherspoon` 之前。示例还显示，对于 `pushd +n` 命令而言，`/home/witherspoon`（最后一项）实际上是由 `/home/john`（第一项）紧接的。

## 使用栈返回到之前的目录：`popd`

在用 `pushd` 将目录保存到目录栈后，你可以使用 `popd` 返回到之前的目录。`popd` 命令的语法如下：

```
popd [ +n ]
```

当以 `pushd +n` 的形式使用时，该命令会删除栈中的第 n 个项。栈项从 0 开始编号，当前目录为 0。以下示例显示了 `pushd`、`dirs` 和 `popd` 的结合使用：

```
% pwd
/usr/home/john
% pushd /home/spool
% pushd uucppublic
% pushd receive
% dirs
/usr/spool/uucppublic/receive /usr/spool/uucppublic /usr/spool
/usr/home/john
% popd
/usr/spool/uucppublic
% dirs
/usr/spool/uucppublic /usr/spool /usr/home/john
% popd +1
/usr/spool/uucppublic /usr/home/john
% popd
/usr/home/john
% dirs
/usr/home/john
```

## 更改活动 Shell

C shell 提供了许多命令来更改活动 shell。尽管你的登录 shell 可能是 C shell，但你并不限于它；你可以随时使用 `exec` 命令将你的 shell 更改为 Bourne shell 或 Korn shell。`exit` 和 `logout` 命令也会通过让你返回到当前 shell 之前的活动 shell 来更改活动 shell。当你从登录 shell 发出这些命令时，它们会将你带回登录界面，登录界面本身也是一种 shell（功能相对有限）。

其他命令如 `umask` 和 `nohup` 则改变了 UNIX 处理 shell 的方式。

## 调用新进程：`exec`

`exec` 命令将控制权转移给指定的命令，替换当前的 shell。你指定的命令将成为你新的当前 shell。`exec` 命令的语法如下：

```
exec command
```

控制权无法返回到调用的环境，因为它被新环境替换了。用 `setenv` 命令导出的 shell 变量按通常的方式传递给新 shell；所有其他命令上下文（包括局部变量和别名）都会丢失。

`exec` 命令主要用于 C shell 脚本。执行 C shell 脚本命令的正常 C 行为使用两个进程：一个是解释脚本的新 shell，另一个是正在执行的 `command()` 进程。`exec` 命令通过将 shell 替换为命令进程，导致 C shell 消除其中一个进程。如果使用脚本为命令设置环境（例如设置变量和检查参数）然后运行该命令，通常会使用 `exec` 命令。

`exec` 命令等同于 Bourne shell 中的。

## 退出当前 Shell：`exit`

`exit` 命令导致当前的 shell 调用退出。其语法如下：

```
exit [ (exitExpression) ]
```

如果从 shell 脚本内部发出该命令，则 shell 脚本将终止，控制权返回到调用的 shell。如果在你的 shell 中发出 `exit`，则在 shell 退出之前会执行家目录下的 logout 脚本。通常情况下，UNIX 操作系统会在退出后重新显示登录界面。

如果你提供了一个可选的 `exitExpression` 参数（必须括在括号内），该参数将作为算术表达式进行求值，并将结果用作 shell 的退出状态；否则，取状态变量的当前值作为 shell 的退出状态。状态变量在本章的“使用预定义变量”中进行了描述。

## 调用系统登录程序：`login`

你可以使用 `login` 命令退出当前的 shell，并立即以相同或不同的用户 ID 登录。其语法如下：

```
login name [ arg ... ]
```

使用内置 shell 命令并不等同于正常方式注销然后重新登录。如果你从远程终端使用 `login` 命令，线路连接不会断开，而按正常方式退出会断开线路，你需要在再次登录之前重新建立连接。

你不能在子 shell 中执行 `login` 内置命令；它只对你的登录 shell 合法。

对于 `name`，请指定你登录时使用的用户名。在 `name` 之后指定的任何参数都会传递给 `/bin/login` 命令，并由 `/bin/login` 而非 shell 定义。

## 退出登录 Shell：`logout`

你可以使用 `logout` 命令退出你的登录 shell：

```
logout
```

你也可以用 `exit` 命令终止 shell（或任何子 shell）。如果你设置了 `ignoreoreof` 选项，则无法使用 EOF 键（通常是 Ctrl-D）退出 shell；在这种情况下，请使用 `logout` 或 `exit`。关于 `ignoreoreof` 选项的定义，请参见本章的“使用预定义变量”。

## 防止命令在注销后终止执行：`nohup`

你可以使用 `nohup` 命令运行对挂断信号不敏感的命令：

```
nohup command
```

UNIX 操作系统总是向进程组发送挂断信号（SIGHUP）。由于 UNIX 命令的这种默认行为，文件创建掩码（`umask`）的作用就是指定你不想要的权限。当你在文件创建掩码中设置一个位时，它会导致相应的文件权限位被强制置 0。在文件创建掩码中未设置的位被解释为忽略：文件权限位保持不变。

文件权限位表示为 `rwxrwxrwx`。前三个位代表所有者的读、写、执行权限；第二组三个位代表组的读、写、执行权限；第三组三个位代表其他人的读、写、执行权限。

文件的组；第三组三位指定其他用户的权限。为了仅给文件所有者读和写权限，而给其他用户只有读取权限，适当的文件权限设置是 11010100。将此转换为八进制，你将得到熟悉的权限值 644，你可能已经已经在 `ls` 命令的输出中见过它。

记住，UNIX 命令在创建文件时会带有所有合理的权限。对于数据文件，这些位是 110101010，对应于 rw-rw-r--。要获得 rw-r--r-- 权限，你需要关闭第八位。使用 000010010（八进制为 022）的文件创建掩码即可解决问题。当文件创建时，UNIX 会将命令请求的文件位和你的文件创建掩码对齐如下：

```
1 1 0 1 0 1 0 1 0      尝试设置的文件权限
0 0 0 0 1 0 1 1 0      文件创建掩码
1 1 0 1 0 0 1 0 0      实际的文件权限
```

因此，使用 `umask` 命令时，首先要决定你想默认为新文件分配什么文件权限，然后写一个八进制形式的掩码，将适当的文件权限位设置为 0。

恰好，大多数 UNIX 用户希望为自己保留写权限，但他们愿意让他们查看文件。适当的文件创建掩码是八进制的 022。在许多情况下，系统管理员会设置系统，使得在你登录时执行 `umask 022` 命令。如果管理员没有设置默认，或者你使用了另一个文件创建掩码，可以在你的登录配置文件（profile）中设置新掩码。

`umask` 命令的实际语法非常简单。要显示当前进程的文件创建掩码，可以使用如下方式使用 `umask` 命令：

```
% umask
022
```

你可以通过指定八进制参数使用 `umask` 设置文件创建掩码：

```
% umask octal
```

进程的文件创建掩码设置为与八进制数 `octal` 中每个数字低三位对应的位模式。

## 将参数输出到标准输出

Shell 提供了两个将参数输出到输出的命令：`echo` 和 `glob`。它们之间唯一区别是输出行中分隔单词的分隔符。

`echo` 命令虽然在编写脚本时经常使用，但在许多键盘操作中也很有用——例如，构建指向非交互式命令的管道（`echo arg` | command )）。`echo` 命令最好的功能之一是显示 shell 变量的值：

```
% echo $path
/usr/bin /bin /usr/local/bin /users/chen/bin
```

在这种情况下，变量替换 `$path` 执行了实际工作；`echo` 命令仅提供在终端上打印该值的步骤。尽管如此，如果没有 `echo` 命令，检查变量的值将非常麻烦。`set` 命令只打印单个变量，但 `set` 可以用来打印所有变量。使用 `set` 打印 shell 变量可以产生一个长列表，以便查找你需要的条目。

另一方面，`glob` 命令在任何语文中都很少使用。最初，它的设计目的是是从 C 程序（而不是 shell 脚本）调用，以让 shell 扩展文件名通配符。大多数 C 程序员并不使用这种技术，尽管它依赖于 C shell 的存在。

## 使用 `echo` 命令

`echo` 命令将包含其参数的一行打印到标准输出。该命令的语法如下：

```
echo [-n ] wordlist
```

参数打印时，它们之间有一个空格，最后一个参数之后紧跟一个换行符。`echo` 命令不会以任何方式修改 `wordlist` 中的单词，但 `echo` 实际看到的参数可能与原始命令中的参数不同，因为存在变量、命令和历史替换以及文件名通配符展开。例如，命令

```
echo Directory $cwd contains these files: *.cc
```

可能会向标准输出生成以下行：

```
Directory /usr/bin contains these files: myprog.cc bigprog.cc
```

- 选项 `-n`：抑制打印换行符；这使得下一次输入或输出与 `echo` 命令的输出发生在同一行。

## 使用 `glob` 命令

`glob` 命令同样将包含其参数的一行打印到标准输出。`glob` 的语法如下：

```
glob [ wordlist ]
```

使用 `glob` 将 `wordlist` 中的单词打印到标准输出。单词之间用空字符分隔（与 `echo` 一样使用空白字符）。`wordlist` 中的最后一个单词后面没有换行符。

`wordlist` 中的单词通常会经历变量、命令和历史扩展。在扫描完替换项后，结果字符串被重新划分为单词，然后使用空描述符写入。

`glob` 命令与 `echo` 相似，区别仅在于输出行中分隔单词的分隔符。由于大多数终端无法打印空字符，`glob` 通常不用于生成终端输出。它的设计目的是在 C 语言程序中被调用：

```
system("/bin/csh -c 'glob *.doc'");
```

以调用 shell 替换和文件名展开机制。

> TIP：C shell 提供了直接将消息记录到标准错误的方法。缺乏直接将消息记录到标准错误的方法对于 C shell 来说是一个问题。

你可以通过 shell 脚本来实现更复杂的处理，其中使用的 shell 脚本文件名所执行的功能可以是任意复杂的。`alias` 命令仅提供作为键盘快捷键使用，任何可以通过 `alias` 实现的功能都可以通过 shell 脚本完成。

你应当将经常使用的别名（aliases）添加到 `.login` 文件中，这样在每次登录时都会定义该别名。然而，对于当前会话中将使用的特殊命令，在键盘上定义别名非常方便。如果你没有将别名整合到 `.login` 文件，它们在注销时将会丢失。

## 定义、列出和更改别名：`alias`

`alias` 命令允许你列出已定义的别名、定义新的命令别名或更改现有的别名。命令格式如下：

```
alias [ name definition ... ]
```

对于 `name`，请选择一个由大小写字母和数字组成的单词。对于 `definition`，编写任何可以定义你想要代表的字符串的单词序列。为 `login` 命令定义两个别名，每个为该主机提供一个定义。输入目标主机的别名名称比输入 `login` 命令及其选项要短得多。

```
alias druid druid -l root
alias ducati rlogin ducati.moto.com
```

如果你想更改别名的定义，只需再次定义该别名即可。

定义别名后，你可以通过不带参数输入 `alias` 命令来显示它们的名称和定义列表，例如所示：

```
% alias
druid (login druid -l root)
ducati (login ducati.moto.com)
```

你也可以通过指定名称作为参数来显示特定别名的定义：

```
% alias druid
login druid -l root
```

别名替换发生在 shell 处理命令循环周期的早期，从而使你能够在单词列表中中使用通配符替换（文件名替换）、变量替换、命令替换和命令替换。因此，你可能需要对定义中的至少一个单词加引号，甚至可能对整个别名加引号。有些人通过使用带引号的别名来避免意外。考虑以下别名：

```bash
alias lc ls *.{cc,hh}
```

对于一个 C++ 语言程序员来说，这个别名非常自然：只需输入 `lc`，你就能获得当前目录下所有文件的列表，且没有任何其他过滤子句。

> 注意：请注意，除非对单词列表的所有部分加引号，否则在处理 `alias` 命令时会发生替换。

然而，上述别名定义并未按预期工作。文件名 *.{cc, hh} 在 `alias` 命令本身被替换，当你输入别名命令时，实际存储的存储（取决于实际目录内容）如下：

```
% alias lc
ls CIM_EnvImp.cc CIM_Util.hh EventManager.cc LogInstances.cc
```

由于文件名模式在 shell 存储别名定义之前被替换，`lc` 别名并没有列出所有以 .cc 或 .hh结尾的文件。它尝试列出 `CIM_EnvImp.cc`、`CIM_Util.hh`、`EventManager.cc` 和 `LogInstances.cc`，无论它们是否存在于当前目录中。

别名已定义为：

```
% alias lc ls '*.{cc,hh}
```
