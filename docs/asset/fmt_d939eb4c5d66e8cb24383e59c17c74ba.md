
| `[:alpha:]` | 字母字符；在 ASCII 中，等同于 `[A-Za-z]`。 |

| `[:blank:]` | 包括空格和制表符。 |

| ASCII 控制代码；包括 ASCII 字符 0 到 31 以及 127。 |

| 数字 0 到 9。 |

| 可见字符；在 ASCII 中，它包括字符 33 到 126。 |

| 小写字母。 |

| 标点符号 字符；在 ASCII 中，等同于 `[–"!#$&'*+,-./:;<=>?@[\]^_`|~]`。 |

| 可打印字符；`[:graph:]` 中的所有字符加上空格字符。 |

| 空白字符，包括空格、制表符、回车、换行、垂直制表符和分页符；在 ASCII 中，等同于 `[[:space:]]`。 |

| 大写字母。 |

| 用于十六进制数的字符；在 ASCII 中，等同于 `[0-9A-Fa-f]`。 |

有了字符类，仍然没有方便的方法来表示部分范围，例如 `[A-M]`。

使用字符类，我们可以重复列目录并看到改进后的结果：

```
@linuxbox-$ ls -d /usr/bin/[:upper:]*
/usr/sbin/MAKEFLOPPIES
/usr/sbin/NetworkManagerDispatcher
/usr/sbin/NetworkManager
```

然而，请记住这并不是正则表达式的示例；而是 shell 正在执行路径名扩展。我们在这里展示它，是因为 POSIX 字符类可以同时用于这两者。

# 基础正则表达式与扩展正则表达式

当我们认为这已经不会变得更复杂时，发现 POSIX 将正则表达式分为两种类型：基础正则表达式 `BRE` 和扩展正则表达式 `ERE`。我们目前为止涵盖的特征被任何符合 POSIX 的应用程序支持。

`BRE` 和 `ERE` 之间的区别是什么？这是一个元字符的问题。在 `BRE` 中，以下元字符被识别：

+ * ]

然而，在 `BRE` 中，`( )` 和 `{ }` 字符在加上反斜杠时被视为字面量，而在 `ERE` 中，以下元字符是：

```
( ) { } ?
```

由于我们接下来要讨论的特征属于 `ERE`，我们将使用不同的 `grep`。传统上这是由 `grep` 程序实现的，但使用 `-e` 选项也支持扩展表达式。

## POSIX

20 世纪80年代，Unix 变成了流行的操作系统，但到 1988 年，Unix 世界陷入了混乱。许多计算机制造商从其创建者 AT&T 处获得了 Unix 源码许可并提供了各种版本。然而，为了产品差异化，每家制造商都增加了专有的更改和扩展。这限制了软件的兼容性。

引入电气电子工程师学会（IEEE）。20 世纪 80 年代，IEEE 开始制定一套标准，以定义 Unix（以及类 Unix）系统将如何运行。这些标准正式称为 IEEE 1003，定义了标准类 Unix 系统中可以找到的应用编程接口（API）、shell 和工具。POSIX 这个名字意为“可移植操作系统接口”，末尾加上 X 是为了额外的速度，是由 Richard Stallman（是的，就是那个 Richard）建议并被 IEEE 采用的。

# 或逻辑

我们将讨论的第一个扩展正则表达式特征是“或逻辑”（alternation），它是允许从一组表达式进行匹配的机制。正如括号表达式允许单个字符从指定的字符集中进行匹配一样，“或逻辑允许从一组字符串或其他正则表达式进行匹配。

为了演示这一点，我们将 `grep` 结合 `echo` 使用。首先，让我们尝试一个普通的字符串匹配。

```
[me@linuxbox ~]$ echo "AAA" | grep AAA
AAA
[me@linuxbox ~]$ echo "BBB" | grep AAA
[me@linuxbox ~]$
```

这是一个非常简单的示例，我们将 `echo` 的输出管道给 `grep` 并查看结果。当发生匹配时，我们会将其打印出来；当没有匹配时，我们将不显示结果。

现在我们将添加“或逻辑”，它由竖线元字符表示：

```bash
[me@linuxbox ~]$ echo "AAA" | grep -E 'AAA|888'
AAA
[me@linuxbox ~]$ echo "888" | grep -E 'AAA|888'
BBB
[me@linuxbox ~]$ echo "CCC" | grep -E 'AAA|888'
[me@linuxbox ~]
```

这里是正则表达式 `AAA|888`，它的意思是“匹配字符串 AAA 或字符串 BBB”。注意这是一个扩展功能，我们为 `grep` 添加了 `-E` 选项（尽管我们也可以使用 `egrep` 程序代替），并且我们将正则表达式括在引号中，以防止 shell 将竖线元字符 `|` 解释为管道操作符。分支并不局限于两种选择。

```bash
[me@linuxbox ~]$ echo "AAA" | grep -E 'AAA|888|CCC'
AAA
```

要将分支与其他正则表达式结合，我们可以使用 `()` 来分隔分支。

```bash
[me@linuxbox ~]$ grep -Eh "[bz|gz|zip]*" dirlist*.txt
```

该表达式将匹配我们列表中以 `bz`、`gz` 或 `zip` 开头的文件。如果我们省略了括号，该正则表达式的意思将变为匹配任何包含 `bz`、包含 `gz` 或包含 `zip` 的文件名。

```bash
[me@linuxbox ~]$ grep -Eh "[bz|gz|zip]*" dirlist*.txt
```

## 量词

扩展正则表达式支持多种方式来指定元素匹配的次数，下文将进行描述。

### 匹配零次或一次元素

这个量词在效果上意味着“使前一个元素成为可选的”。假设我们想要检查电话号码的有效性，并且如果电话号码符合以下两种形式之一，我们认为该电话号码是有效的，其中 `n` 是数字。

```
(0-9)-0-9-nnnn
nnnnn 0-9-0-nnnn
```

我们可以构建这样一个正则表达式：

```bash
^([0-9][0-9][0-9])? [0-9][0-9]\.[0-9][0-9][0-9]$
```

在这个表达式中，带有问号的括号字符表示它们将被匹配零次或一次。同样，由于括号在（ERE）中通常是元字符，我们在它们前面加上反斜杠，以使它们被视为字面量。

让我们来试一下。

```bash
[me@linux ~]$ echo "(555) 123-4567" | grep -E '^\([0-9][0-9]\)([0-9][0-9])([0-9][0-9][0-9])$'
(555) 123-4567
[me@linux ~]$ echo "555 123-4567" | grep -E '^\([0-9][0-9]\)([0-9][0-9])([0-9][0-9])([0-9][0-9][0-9])$'
555 123-4567
[me@linux ~]$ echo "AAA 123-4567" | grep -E '^\([0-9][0-9]\)([0-9][0-9])([0-9][0-9])([0-9][0-9][0-9])$'
[me@linux ~]
```

在这里我们看到该表达式匹配电话号码的两种形式，但不匹配任何非数字字符。这并不完美，因为它仍然允许区号周围出现不匹配的括号，但它将执行第一阶段的验证。

### 匹配零次或多次元素

与 `?` 元字符类似，`*` 用于表示可选项目；但与 `?` 不同，它可以出现任意次数，而不止一次。假设我们想查看字符串是否以大写字母开头，包含任意数量的大小写字母和空格，并以句结尾。为了匹配这种（粗糙的）句子定义，可以使用如下正则表达式：

```bash
^([^[:upper:][:lower:]]*$)
```

该表达式由三个项目组成：一个包含 `[:upper:]` 和 `[:lower:]` 字符类以及空格的括号表达式，以及用反斜杠转义的句号。第二个元素后面跟着一个 `*` 元字符，以便我们句子开头的大写字母后面可以跟随并匹配任意数量的大写字母和小写字母。

```bash
[me@linux ~]$ echo "This Works." | grep -E '^[:upper:][:lower:]*$'
This works.
[me@linux ~]$ echo "This Works." | grep -E '^[:upper:][:lower:]*$'
This works.
[me@linux ~]$ echo "does not" | grep -E '^[:upper:][:lower:]*$'
[me@linux ~]
```

该表达式匹配前两个测试，但没有匹配第三个，因为缺少所需的开头大写字母和结尾句号。

### 匹配一次或多次元素

`+` 元字符的工作原理与 `*` 非常相似，但要求前一个元素至少有一个实例才能导致匹配。以下是一个将匹配由一个或多个字母组组成、并用单空格分隔的行的正则表达式：

```bash
[me@linuxbox ~]$ echo "This that" | grep -E '^([[:alpha:]]+ )+$'
```

This that

```bash
[me@linuxbox ~]$ echo "a b c" | grep -E '^([[:alpha:]]+ )+$'
```

a b c

```bash
[me@linuxbox ~]$ echo "a 9" | grep -E '^([[:alpha:]]+ )+$'
```

[me@linuxbox ~]

## 指定特定次数

`{` 和 `}` 字符用于表示所需的次数。它们可以通过四种方式指定，如表 19-3 所示。

表 19-3：指定次数

| 标识符 | 含义 |

| :--- | :--- |

| (n) | 恰好匹配 $n$ 次 |

| {n,m} | 匹配至少 $n$ 次且最多 $m$ 次 |

| {n,} | 匹配至少 $n$ 次 |

| {0,m} | 匹配最多 $m$ 次 |

回到我们之前的示例，我们可以使用大括号来限制输出。

```bash
[me@linux ~]$ echo "(555) 123-4567" | grep -E '^([0-9]{3}\) [0-9]{3}-[0-9]{4}$'
```

## cat

`cat` 有许多有趣的选项。其中许多用于帮助文本内容的可视化。一个例子是 `-A` 选项，它用于显示非打印字符。有时我们需要知道文本中是否嵌入了控制字符。这些字符中最常见的是制表符（tab）和回车符。让我们使用 `cat` 作为一个原始的文字处理器创建一个测试文件。要做到这一点，我们只需输入 `cat` 命令（以及指定重定向输出的文件）并输入你的文本，然后按下 `Ctrl+D` 结束，以显示我们到达了文件末尾。（*注：原文此处逻辑略有混乱，根据上下文意译*）

并来自 DOS 格式。然而，如果你的系统上没有 `dos2unix`，不用担心。将文本从 DOS 格式转换为 Unix 格式的过程非常简单；它涉及删除多余的回车符。这可以通过本章讨论的几个程序轻松完成。

`cat` 还有一些用于修改文本的选项。最显著的两个是 `-n`（它对行进行编号）和 `-s`（它抑制多个空行的输出）。我们可以演示一下：

```
me@linuxbox ~$ cat foo.txt
The quick brown fox
```
