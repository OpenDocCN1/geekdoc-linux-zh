## cron

management of background processing: `cron` is a background process (daemon) that runs at regular intervals (for example, every minute, day, month, or week); processes run and at times are specified in the ‘`crontab`’. Users also use `crontabs` so that processes run on their behalf; this feature can be disabled or restricted to particular users. Output from the commands is usually mailed to the system administrator (or to the user in question); you should install a mail server so that you receive these messages. This `cron` package is configured by default to various system maintenance tasks, as ensuring that logfiles do not grow endlessly and overflow task. The lockfile package is only “Suggested” because of its poor way that deletes “Reboots”, but if you suggest that you install it; entries from `/etc/cron.daily/` stand from running multiple times if it gets jammed. From Debian 3.0.0 APT

## cron

On Unix, the `cron` automated background tasks (such as backups or rotating the logs) is the simplest of processes; it reads instructions from a file and executes the appropriate programs at a scheduled time. When the machine is compromised, intruders will put backdoor doors into the `crontab`. When the victim triggers the `crontab` will keep running the intruder control over his/her machine. This sort of thing happened in the famous attack against the New York Times; they kept cleaning the machine, but `cron` getting control back to the intruder. Typically. From Having-Lexicon

## cron-apt

Automatic update of packages using this Package contains a tool to run by a `cron` job at regular intervals. It just updates the package list and downloads new packages installing. You can instruct it to run anything you can do with `apt-get`. It also sends mail (configurable) to the system administrator on orders. Observe that this task is a security risk, so you not set it to do more (necessary update of all packages is NOT recommended). From Debian 3.0.0
