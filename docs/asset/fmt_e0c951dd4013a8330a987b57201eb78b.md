
其实就是这些。重启你的系统，你就会发现你正在运行最新的错误修复分支！

# 调度二进制更新

最佳实践建议在固定的时间按定期的时间表下载并应用更新，例如你的每月维护日。FreeBSD Update 包含了对此项的特定支持，以避免每小时整点用请求淹没下载服务器。FreeBSD 的 `cron` 命令告诉系统在下一小时内的某个随机点下载更新。将此命令放在 `/etc/crontab` 中，以便在一个小时的窗口内下载更新。这有助于减轻下载服务器的负载。

当系统有更新时，你会收到一封邮件，因此你可以根据方便的时间安排重启。

# 优化和自定义 FreeBSD Update

关于 FreeBSD Update 的两个常见问题涉及 FreeBSD 的自定义构建和本地分发更新。

许多人为内部使用构建了自己的 FreeBSD 版本。通常情况下，这是一个删除了某些部分的 FreeBSD 版本，正如我们在第 20 章中对 NanoBSD 所做的那样，但某些公司使用了广泛的修改。如果你从 FreeBSD 安装中删除了文件，`freebsd-update(8)` 将不会尝试进行补丁。

同样，许多公司喜欢拥有内部更新服务器进行补丁管理。FreeBSD Update 系统专门设计用于与缓存网络代理协同工作。虽然所有文件都经过加密签名和验证，但它们通过标准的 HTTP 传输，因此你的代理可以减少带宽消耗。

如果你真的想构建自己的 FreeBSD Update 服务器，更新服务器的代码可以在 FreeBSD 仓库的 `projects` 目录下找到。如果你不理解这意味着什么，那么你不应该构建自己的更新服务器。

## 通过源码升级

更新系统的另一种方法是从源码开始进行编译。FreeBSD 具有自愈能力，这意味着它包含了构建 FreeBSD 所需的所有工具。如果你想从源码构建最新版本的 FreeBSD，第一步是获取最新的源码。

当开发者发布 FreeBSD 的改进版时，这些更改会在大约一小时内在全球范围内可用（如果要严谨地说，是 66 分钟）。FreeBSD 主源码服务器跟踪代码、对该代码进行的所有更改以及这些更改的作者。开发者可以提交新代码，用户可以通过并发版本控制系统 (CVS) 检出最新版本的源码。CVS 是一个不错的源码管理系统，但对于源码分发来说，它是一个非常糟糕的工具。CVS 需要大量的系统资源和带宽，频繁使用会消耗硬盘。FreeBSD 的资源都是捐赠的，我们不应该浪费它们。因此，该项目没有使用 CVS，而是使用了一种自定义的 CVS 仓库协议。这种方式更快、更高效、对服务器更友好，而且在支持全球数百万用户时通常表现更好。主源码仓库被复制到 CVSup 服务器，用户使用一个名为 `csup` 的工具从这些镜像服务器下载源码。

`csup` 连接到 FreeBSD CVS 镜像，将你机器上的源码与服务器上的源码进行对比，并将更改复制到本地硬盘。这听起来可能很复杂，但实际上用起来非常简单。

## CSUP, CVSUP, CVS, AND SUP?

> 许多 FreeBSD 文档和网站提到使用 CVSup 工具进行源码更新，对于普通用户而言，`csup` 已取代了 CVSup，因此你可以忽略任何关于 CVSup 或 `csup(1)` 程序的引用。然而，许多相关文档都提到了 CVS；镜像服务器被称为 csup 服务器，示例配置位于 `/usr/share/examples/csup` 等。同理，CVSup 是 CVS 和 sup（软件更新协议）的结合。你会偶尔看到这些工具的提及，但你不需要了解它们。

首先确认你的系统在 `/usr/src` 下已安装了 FreeBSD。源码看起来如下：

```
# ls /usr/src
COPYRIGHT      UPDATING include       sbin
LOCKS          bin             kerberos secure
MAINTAINERS     contrib         lib            share
Makefile       crypto         libexec       sys
Makefile.inc1  etc            ports-supply tools
obsolete.files games release usr.bin
README         gnuusr.sbin
```

这是 FreeBSD 源码树的根目录，包含了构建整个 FreeBSD 所需的所有代码。我们在第 11 章讨论过源码。你可以继续查看这些目录，直到看到一个源码的样子。

如果你发现此目录是空的，说明你还没有安装源码。别担心，你可以通过 root 身份执行以下操作从安装光盘安装源码：

```
# mount /dev/acd0 /cdrom
# cd /cdrom/src
# ./install.sh
```

如果你没有光盘，可以从 FreeBSD FTP 镜像获取源码归档包（tarball）。

无论你如何安装源码，都将从你安装的 FreeBSD 版本的源码开始。例如，FreeBSD 7.0 的光盘包含了 FreeBSD 7.0 的源码，这对于管理当前安装的系统很有用，但并不是你升级时需要的；如果你编译并安装了 FreeBSD 7.0 的源码，你最终运行的是 FreeBSD 7.0。`csup` 会对比你磁盘上的源码与互联网上的可用源码，并下载两个版本之间的差异。然后 `csup` 会对你磁盘上的源码应用*差异补丁 (diffs)*，将其更改为你目标版本的源码。这比每次升级都重新下载整个 450MB 的源码树要高效得多！即使你在升级之间跳过了一两个版本，`csup` 也只需要下载几兆字节的新源码即可完成更改。

要更新你的源码树，请告诉 `csup` 要更新什么、从哪里更新以及如何执行更新。

## 选择你的 Supfile

`csup` 使用配置文件（或称为 *supfile*）来更新你的源码仓库。参见 `/usr/share/examples/csup` 以获取更新到不同版本的示例 supfile。一旦你选择或编写了符合你需求的 supfile，就可以永久使用该 supfile。最近的 `/usr/share/examples/csup` 包含了以下示例：

- **cvs-supfile** 此 supfile 维护整个 FreeBSD 仓库。虽然大多数用户不需要它，但 FreeBSD 开发者需要它。只有在你自己制作发布版（包括软盘镜像、CD 镜像等）时才使用它。要获取整个仓库，你必须使用 CVS 而不是 csup。
- **doc-supfile** 此 supfile 告诉 csup 更新系统的本地文档（FAQ、手册和相关文章）。
- **gnats-supfile** 使用此文件创建 FreeBSD 问题报告 (PR) 的本地副本。同样，大多数用户并不想要这个。
- **ports-supfile** 此 supfile 将你的 ports 更新到最新版本（见第 11 章）。
- **stable-supfile** 使用此 supfile 将你的源码升级到最新的 -stable 版本。
- **standard-supfile** 将你的源码更新到你正在运行的 FreeBSD 版本的最新版。如果你安装了 FreeBSD 7-stable 的快照，它会将源码升级到最新的 FreeBSD 7-stable。如果你运行的是 -current，它会将源码升级到最新的 -current。
- **www-supfile** 此 supfile 下载 FreeBSD 网站的最新版本。可以使用 csup 更新的各种集合。例如，源码集合（doc-supfile）、Ports 集合（ports-supfile）等。许多集合被划分为子集合。

## 修改你的 Supfile

一旦你选择了所需的 supfile，就必须修改它以适应你的环境。首先，在 `/etc` 下选择你的 supfile 并用你喜欢的编辑器打开它。任何以井号 (`#`) 开头的行都是注释，大多数 supfile 注释比配置条目多，如下：

```
*default host=CHANGE_THIS
*default base=/var/db
*default prefix=/usr
*default release=RELENG_6
*default delete use-rel-suffix compress
src-all
```

你的第一步是选择主机。除非你想将源码存储在非标准位置，否则不要更改此处。`csup(1)` 期望控制其目录下的所有内容并可以删除不属于它的东西。`delete` 关键字允许 csup 这样做。同样，`use-rel-suffix` 选项允许 csup 在多个版本之间共享一个基础目录而不会混淆。

| Tag | Version |
|---|---|
| RELENG_7 | FreeBSD 7-stable |
| RELENG_6 | FreeBSD 6-stable |
| RELENG_7_0 | FreeBSD 7.0-release with errata |
| . | FreeBSD-current |

当开发者从 FreeBSD 主仓库移动某些源码文件时，`csup` 必须从你的系统中删除这些文件以保持副本一致。`delete` 关键字允许 csup 这样做。压缩节省了带宽，代价仅仅是 CPU 时间。最后，告诉 csup 更新整个源码。示例 stable-supfile 包含一个被注释的子集合列表，例如 `bin`（`/usr/bin` 的内容）、`contrib`（`/usr/src/contrib` 目录）、`sys`（内核）等。

理论上你可以只更新源码树的一部分，但这是一个极其糟糕的主意。在你的 FreeBSD-stable 系统上安装来自 FreeBSD-current 的 `/usr/bin` 二进制文件会导致各种不可预测的问题，并且完全不受支持。

你可以在一个文件中指定多个集合。例如，我需要 FreeBSD 7-stable 的源码集合。作为文档提交者，我需要最新的文档集合。最后，我需要最新的 ports 树，以便在我的电脑上安装最新的软件。如果不想为每个集合运行一次 csup，可以在 `/usr/share/examples/csup` 中找到每个集合的示例 supfile。我在我的 supfile 中列出这些集合。

# 完整的 supfile

这里是我完整的 supfile，其中包含了更新我的源码所需的所有更改：

```
*default host=cvsup15.freebsd.org
*default base=/var/db
*default prefix=/usr
*default release=cvsup tag=RELENG_7
*default delete use-rel-suffix
*default compress
src-all
ports-all tags.
doc-all tags.
```

注意看我对示例做的改动非常小。我选择了一个最近的 CVSup 服务器，并设置了我需要的 FreeBSD 版本。最后两行是有趣的地方，我添加了 `ports-all` 和 `doc-all` 集合（collections）。源代码集合有发布版本或分支；如果我请求 `RELENG_7` 版本的 ports，CVSup 服务器将不知道我在说什么，我也无法获得任何更新。通过在集合名称末尾添加标签，我告诉 csup 获取该内容的最新版本。

# 阻塞更新：Refuse 文件（拒绝文件）

虽然我想要源码树和整个文档树，但我只使用 ports 树的部分内容。如果你查看 `/usr/ports`，你会看到阿拉伯语、法语、德语、希伯来语、匈牙利语、日语、韩语、葡萄牙语、俄语、乌克兰语和越南语软件的子目录。很高兴这些语言的人可以使用这些软件，但我需要其中任何程序的概率微乎其微或不存在。要告诉 csup 不要更新你不想更新的目录，可以使用一个 `/var/db/sup/refuse` 文件，如下所示：

```
ports/arabic
ports/french
ports/german
...
ports/vietnamese
```

refuse 文件不能包含注释。
虽然你可以拒绝任何你想要的内容，但最好不要拒绝 `/usr/src` 下的任何内容。如果你拒绝了关键系统的更新，该程序最终将与系统的其他部分不兼容。

通过模式匹配进行拒绝工作，因此一个名为 `sys` 的 refuse 文件条目会拦截所有包含 `sys` 单词的内容，这恰恰包含了 `/usr/src/sys` 下的整个内核源码。让你的拒绝条目足够具体，以便只拦截你想要拦截的内容。

如果你使用 refuse 文件，最好从硬盘上删除相应的文件。与其因为软件不存在而导致失败，不如让它以一种“创意”的方式失败，然后诊断为什么它已经三年没有更新了。

此外，refuse 文件会带来风险。只更新源码树的一部分几乎会导致构建失败。Ports Collection 被设计为作为一个整体运行，拒绝它的某些部分可能会产生问题。虽然文档树分段得很好，但你可能会遇到麻烦。一个 refuse 文件带来的麻烦可能比它的价值还大，但只有你才能做决定。

# 使用 csup 获取整个源码树

你可以在没有安装本地源码树的情况下运行 csup。csup 会比较你拥有的（无）和你需要的（全部），并安装你缺失的（整个）。镜像站维护者倾向于在你有 CD 的情况下从 CD 安装源码；然而，他们正在为这项服务捐赠服务器和带宽，并希望尽可能多的人从中受益。一个完整的未压缩源码树会占用约 450MB 的磁盘空间，而对现有树下载更新仅需要几兆字节。即使使用了压缩，你也使用了大量的捐赠带宽。对于这种活动来说，这种行为是不礼貌的。

# 从源码编译 FreeBSD

一旦你有了最新的源码，查看 `/usr/src/UPDATING`。该文件按时间倒序，列出了关于 FreeBSD 更改的任何警告和特殊通知，这些更改对于从源码构建的人来说具有特殊意义。它会告诉你你在重新编译系统之前是否必须采取任何特殊操作，或者是否有任何主要功能发生了变化。如果你希望你的系统在升级后仍能工作，请严格遵循这些指令。还要检查新的 `GENERIC` 或 `NOTES` 内核配置，查看是否有任何新的或有趣的内核更改。

# 自定义你的 FreeBSD 构建

还记得第 11 章我们讨论过 `/etc/make.conf` 吗？FreeBSD 使用一个单独的文件来处理 FreeBSD 自身的构建自定义。虽然 `/etc/make.conf` 中的设置会影响系统上构建的所有软件，但 `/etc/src.conf` 中的任何内容只影响从源码构建的 FreeBSD。

如果你在 FreeBSD 社区呆一段时间，你会听到关于人们用于构建 FreeBSD 的特殊方法的故事。你会听到一些传闻证据，说明某种方法比标准方法更好、更快或更强。虽然你可以自由使用任何方法来更新你的系统，但 FreeBSD 项目支持的唯一方法记录在 `/usr/src/UPDATING` 的结尾。如果你遵循了其他程序并遇到麻烦，你将被引导回到记录的程序。即书中描述的程序。

# 构建世界（Build the World）

首先，构建世界：

```
# cd /usr/src
# make buildworld
```

`make buildworld` 命令构建用户空间，但不安装它。在 `buildworld` 之后运行 `make installkernel` 来安装内核。`make kernel` 命令会接着运行这两个命令。根据你的时间表选择使用。例如，如果我在周日的维护窗口在公司进行系统升级，我可能会在之前的几天运行 `make buildworld` 以节省我宝贵的周末。如果机器在周五出现问题需要重启，我会启动生产内核而不是升级后的内核。周日早上，当我准备好实际升级时，我运行 `make installkernel`。另一方面，在升级笔记本电脑时使用 `make kernel` 是合理的。所以，为了我的自定义内核：

```
# make KERNCONF=HUMVEE kernel
```
