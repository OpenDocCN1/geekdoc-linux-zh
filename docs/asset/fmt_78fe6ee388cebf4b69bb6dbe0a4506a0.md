# 引言

内存管理子系统无疑是 Linux 内核的核心，它构成了整个内核的基础。

内存管理子系统的核心哲学在于通过深入探讨内核代码，让读者理解内存是如何运作的。

# 2 物理内存

物理内存描述了系统中所有可以被至少一个内核任意寻址的内存。通常这以 RAM 模块的形式存在，但也可能包括其他形式的随机访问存储器。在本章中，我们将探索内核如何管理、分配和抽象这一资源。

> **物理地址** 告诉 CPU 在哪里找到特定的内存字节。例如，DRAM 将每个单独的字节存储在名为存储体的特定数组的特定行和列上，该数组通过存储在特定插槽中的 DIMM 上的特定通道进行访问。物理地址编码了所有这些信息。

在内核中，物理地址被分配为 `phys_addr_t` 类型，其值等于字大小，例如，对于 64 位系统，这简单是一个无符号 64 位整数。

如果我们逐个管理每个字节的内存，那么为了跟踪内存所需的内存开销将超过系统可用内存的量。这显然是不可行的，因此我们必须妥协，将内存划分为聚合块，我们称之为“页”。

一个架构的基页大小是硬件配置支持的页大小，也是内存的基本单位。对于 x86-64，它是 2^12 或 4096 字节；对于 arm64 和其他架构，它可以变化。在内核中，基页大小由 `PAGE_SIZE` 定义（这是特定于架构的，并在相应的 `arch/` 头文件中声明）。

我们将页进一步细分为节点和区域。让我们来看看这些术语的具体含义：

- 大型服务器箱可能有多个 CPU 插槽，某些内存模块连接到一个 CPU，另一些连接到另一个 CPU，以此类推，并且远程内存块之间有某种互连方式。
- 以这种配置排列内存的系统被称为具有非统一内存访问（NUMA）内存架构。

### 注意

此外，系统甚至可能拥有没有与 CPU 关联的内存块，这些块对任何核心来说访问都很慢；或者相对于连接到同一 CPU 的其他内存，访问某个 CPU 具有局部性，但具有其他特征降低了访问它们的速度。

即使是现代硬件上的单 CPU 系统通常也被视为 NUMA，定义了一个单一的 NUMA 节点，它拥有所有物理内存。

为了让内核考虑这些异构内存块，它将它们细分为物理上连续的域，称为“节点”，每页物理内存仅且仅属于一个节点。

在每个节点内部，内存进一步根据物理地址范围划分为不同的区域，其中内存范围自然具有某个重要特征，或者因为某个内存范围被任意分配给特定用途。区域与节点重叠。

需要注意的是，对于启用 NUMA 的现代系统，物理内存分配将根据节点和区域参数化（即使它们已由栈上高处的函数自动确定）。

为了高效地分配内存，内核一次分配 2 的幂次方页数的内存，分配页的阶数就是这个 2 的幂次方，例如，一个阶数为 3 的分配包含 2^3 = 8 页内存。

每页物理内存都有与其关联的元数据，这些元数据存储在 `struct page` 对象中，1 页或更多页的聚合块被表示为一个 `struct page` 对象。

为了方便起见，我们定义了页帧数（PFN）的概念，它简单来说就是物理地址除以页大小，换句话说，如果你将物理页视为数组中的元素，那么 PFN 就是该页在数组中的索引。`PHYS_PFN()` 和 `PFN_PHYS()` 用于在这两者之间进行转换。

内存进一步划分为页块，其阶数由 `pageblock_order` 定义（在 x86-64 上为 9，即 512 页）。这些可以应用迁移类型的最少页数。迁移类型决定页是否可以被迁移（即移动），由 `enum migratetype` 描述。稍后会有详细介绍。

每个节点和区域将物理地址空间划分为连续的内存块，区域与节点重叠。每个节点和区域都是页对齐的，因此基页确定地属于某个节点和一个区域。

## 2.1 `struct page`

为了管理内存页，我们必须存储关于页的元数据——标志位、用于判断是否可以释放该页的引用计数，以及特定使用方式的一系列元数据。

为了不弄乱事情并包含内核配置和平台的每种排列，我们专注于具有合理配置的 64 位小端架构。这看起来可能像是异端邪道，但试图涵盖所有内容将使这本书变得不可读，我的理智也将无法想象。

封装这些数据的数据类型是 `struct page`，对于现代 64 位系统：

- 一个指定页属性的字段，此外还有区域和可选的节点信息（它在某些配置选项下还可以编码“section”信息，这超出了本文的讨论范围），通过 `set_page_zone()` 和 `set_page_node()` 设置，并通过 `page_zonenum()` 和 `page_to_nid()` 访问。
- 标志位，用于记录页的状态。
- 引用计数，用于判断是否可以释放该页。
- 一系列特定于使用方式的元数据。

```c
union {
    /* 此联合体的大小为 4 字节。 */
    /* 如果该页可以映射到用户空间，它编码了
     * 该页被页表引用的次数。 */
    atomic_t _mapcount;
    /* 如果该页既不是 Slab 也无法映射到
     * 用户空间的页，那么
     * 存储在此处的值可能帮助确定该页的
     * 用途。请参见 page-flags.h 以获取当前存储
     * 在此处的页类型列表。 */
    unsigned int page_type;
};
```

```c
/* 使用计数。切勿直接使用。请参见 page-ref.h */
atomic_t _refcount;

unsigned long memcg_data;
#endif
```
