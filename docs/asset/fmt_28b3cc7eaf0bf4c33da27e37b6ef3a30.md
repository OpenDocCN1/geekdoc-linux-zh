
进程间通信是一种使用各种通信协议在不同进程之间共享数据的过程。服务器和客户端是使用进程间通信的两种类型的应用程序。在这种应用程序中，客户端映射到一个或多个服务器，并向其请求数据形式的信息。服务器或服务器发送这些数据。不同的平台提供了不同的方式供客户端访问数据。以下是 Linux 为进程间通信提供的机制：

- 1. 内核或进程向它们希望通信的进程发送信号。信号是 Linux 平台提供的最廉价的进程间通信形式，可以是事件或状态的形式。事件和状态都暗示或通知某个进程或内核中发生了一些变化。

- 2. `|` 被称为管道。它由平台使用的 shell 设置，用于将一个进程的输入传输到另一个进程。管道的两端通过两端的文件描述符链接为一对一通信机制。这些文件描述符与单一功能相关联，即只读或只写。发送详情的端使用读取文件描述符从进程中读取数据。同时，需要接收数据的端将使用写入描述符，以便可以写入接收到的数据。由于数据流是单侧的，该机制被称为半双工机制。具有父子关系的进程，其中父进程创建管道与其子进程通信，并在其子进程之间创建管道以便它们可以相互通信，可以使用这些管道。这是因为文件描述符被复制到它们的地址空间中。

- 3. 先进先出（FIFO）管道也称为命名管道，其使用方式与无名管道相同。唯一的区别是，这些管道用于进程之间没有关联的情况。使用这些管道的进程使用 FIFO 文件而不是文件描述符进行通信。FIFO 文件具有与文件描述符相同的机制：一个 FIFO 文件具有读取功能，另一个具有写入功能。因此，这种机制也是半双工的。

- 4. 为了允许单个或多个进程从单个或多个进程读取或写入，我们使用消息队列。这种机制类似于信箱。想要共享数据的进程过来将包含数据的包放到消息队列上然后离开。想要获取数据的进程过来取出包。这节省了大量时间，因为共享数据的进程无需等待另一个进程。消息队列有两种不同的规范。首先是 SysV 消息队列，其中正在发送的消息包含一个数字，以便接收消息的进程可以获取与特定数字匹配的数据，或者接受除与特定数字匹配的包之外的所有内容。第二种是 POSIX，这是一种基于优先级的机制。它按优先级顺序发送包。当进程发送数据时，优先级数字附加在包上。因此，当其他进程接收到详情时，首先获取最高优先级包中的数据。

- 5. 有计数器对将依次接收共享资源的进程顺序进行排队。这些计数器被称为信号量。它们锁定共享资源，使得只有一个进程可以访问共享资源。一旦该进程使用完资源，资源就会被释放。然后，优先级中下一个的进程将获得资源，或者无论优先级如何，请求资源的进程将获得资源。这与消息队列的 SysV 和 POSIX 机制类似，因此这些被称为 SysV 信号量和 POSIX 信号量。

- 6. 多个进程共享可用内存空间的机制称为共享内存机制。这有助于共享内存的两个或更多进程更高效地通信，从而减少对内核的干扰。还有两种类型的共享内存，SysV 共享内存和 POSIX 共享内存，它们的工作方式如上所述相同。也就是说，一种考虑优先级，而另一种则不考虑。

# 第7章：Linux Shell

正如你已知，计算机只能理解零和一，即二进制语言。在计算的第一代中，指令直接以二进制语言给出。但二进制语言极其难以理解，且用其编写代码既费时又困难。为了解决这个问题，一种名为 shell 的特殊程序被引入到操作系统中。Shell 接受以英语给出的命令，并检查它们是否有效。

如果给定的命令是有效的，shell 将其传递给内核。Shell 可以被视为简化用户与内核之间交互的程序。Shell 是一个命令行解释器。它可以接受来自文件或标准输入设备（如键盘）的输入。虽然 shell 不是内核的一部分，但它使用内核来创建文件、执行程序等。

最基本的是，shell 是用户与系统内核之间的接口，但 shell 可以执行一些基本命令而无需将其传递给内核。

如果你想知道系统中可用的 shell，请使用以下命令：

```
$ cat /etc/shells
```

虽然在一个操作系统中有许多可用的 shell，但它们都被设计来做同样的工作。不同的 shell 具有不同的语法和不同的内置功能。在 MS-DOS 中，`command.com` 是 Windows 操作系统使用的 shell。它不如 Linux 中存在的 shell 强大。

所有 shell 都通过文件或键盘等输入设备从用户那里获取命令，并向 Linux 操作系统传达用户所需的信息。

如果用户使用键盘等输入设备给出命令，则称为命令行接口。下面给出的命令显示了您当前正在使用的那个 shell：

```
$ echo $SHELL
```

## Shell 脚本

所有的 shell 都是交互式的，这意味着它们接受用户输入的命令并可以执行这些命令。你可以逐个输入命令，也可以将它们按顺序存储在文本文件中，然后将其交给 shell 执行。一次性输入所有命令被称为 shell 脚本编程。

Shell 脚本通常定义如下：

“Shell 脚本是一系列写在纯文本文件中的命令。Shell 脚本就像 MS-DOS 中的批处理文件一样，但它的功能比 MS-DOS 批处理文件更强大。”

### 编写 shell 脚本的原因

- 你可以直接通过文件或直接向 shell 脚本提供输入，它会在屏幕上给出输出。
- 你可以使用 shell 脚本创建自定义命令。
- Shell 脚本通过一次性处理所有命令为你节省大量时间。
- Shell 脚本可用于自动化日常任务。
- 你还可以使用 shell 脚本来自动化系统管理。

### 如何编写 shell 脚本

在编写 shell 脚本时，请遵循以下步骤：

- 使用编辑器，例如 `mcedit` 或 `vi`。
- 在 shell 脚本中写好命令集后，你需要设置脚本的执行权限，使用 `chmod` 权限 `your-script-name`。例如，`$ chmod +x your-script-name` 或 `$ chmod 755 your-script-name`。系统管理员或所有者应具有读/写/执行权限（7）。在为组设置权限时，应仅使用读和执行权限（5）。
- 现在你应该按照以下语法执行你编写的脚本：

```
syntax: bash your-script-name
sh your-script-name
./your-script-name
```

示例：

```
$ bash bar
$ sh bar
$ ./bar
```

- 注意，`./` 指示当前工作目录，而点 `.` 指示在当前 shell 中执行给定的命令文件，而不初始化一个新的 shell 副本。使用点的语法是 `. command-name`；例如，`$ .foo`。
- 现在你可以使用 `vi` 命令列表（或任何其他编辑器）编写你自己的新 shell 脚本，名为 First Shell：

```
$ vi first
#
### My first shell script
#
clear
echo "First Shell"
```

- 保存脚本后，你可以使用 `$ .first` 运行它，但首先你必须使用 `$ chmod 755 first` 设置权限。现在当你输入 `$ .first` 时，屏幕将被清除，然后你的 shell 脚本中给出的消息将被打印：

输出：First Shell

| 命令(s) | 含义 |
|---|---|
| `$ vi first` | 启动 vi 编辑器 |
| `# My first shell script` | `#` 后跟任何文本被视为注释。注释提供有关脚本的更多信息；它是关于 shell 脚本的逻辑解释。语法：`# comment-text` |
| `clear` | 清屏 |
| `echo "First Shell"` | 要在屏幕上打印消息或变量值，我们使用 `echo` 命令。`echo` 命令的一般形式如下：`echo "Message"` |

### 基本命令行编辑

为了编辑和调用命令，你可以使用以下按键组合：

- `CTRL + L`：清屏。
- `CTRL + W`：删除光标处开始的单词。
- `CTRL + U`：清除行，即删除命令行中的所有单词。
- 向上和向下箭头键：调用命令。
- `Tab`：自动完成文件、目录、命令名称等。
- `CTRL + R`：搜索以前使用过的命令。
- `CTRL + C`：取消当前正在运行的命令。
- `CTRL + T`：交换光标前的最后两个字符。
- `ESC + T`：交换光标前的最后两个单词。
- `CTRL + H`：删除光标处开始的字母。

### 执行命令

要执行命令，只需在终端输入该命令并按下回车键。

例如，`date` 命令将输出当前的日期和时间，因此当你输入 `date` 并按下回车时，你会得到类似以下内容：Wed Jan 27 05:35:56 IST 2015。
