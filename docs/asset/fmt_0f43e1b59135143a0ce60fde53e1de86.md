## 创建 UFS 系统

你可以使用 `mkfs(1M)`、`mkfs_ufs(1M)` 和 `newfs(1M)` 命令创建 UFS 文件系统。`mkfs_ufs` 命令通常不直接使用。当使用 `mkfs` 创建 UFS 文件系统时，会被 `mkfs` 命令调用。`newfs` 命令是创建 UFS 文件系统的首选方法，因为它为 `mkfs` 命令提供了友好的界面。

`newfs` 命令计算相应的参数并调用 `mkfs` 创建文件系统。你可以指定命令行参数来覆盖计算出的参数。唯一的必需命令行参数是分区的原始设备名称。以下列表使用 `newfs` 命令在 1GB 分区中创建一个 UFS。`-v` 命令行参数指定详细模式，导致 `newfs` 命令显示其操作：

```
newfs -v /dev/rdsk/c0d1s1

newfs: 在 /dev/rdsk/c0d1s1 构建新文件系统？ (y/n)? y

mkfs -F ufs /dev/rdsk/c0d1s1 2104515 63 240 8192 1024 ... 8 7

Warning: 最后磁道有 12286 个扇区未分配

/dev/rdsk/c0d1s1: 2104515 个扇区，位于 140 个磁道的每磁道 24 ，

# 63 扇区

1027.6MB 位于 24 个柱面组（6 c/g, 44.30MB/g, 10688 i/g）
超级块（用于 fsck -F ufs -o b=#）位于位置：
32, 90816, 181600, 272384, 363168, 435952, 544736, 635520,
726034, 817088, 907872, 998656, 1089440, 1180224, 1271008,
1361792, 1452756, 1453360, 1631444, 1724928, 1815712,
1906496, 1997280, 2088064
```

另一个有用的 `newfs` 命令行选项是 `-N`，它会使 `newfs` 命令计算用于调用 `mkfs` 命令的参数；然而，`mkfs` 命令并不会实际执行，也不会创建文件系统。`-v` 命令行参数用于查看文件系统参数。此外，大多数 `mkfs` 命令行参数都可以指定为 `newfs` 命令行参数。如果指定了其中任何一个参数，它们将覆盖任何计算出的参数并传递给 `mkfs` 命令。详情请参阅 `newfs(1M)` 和 `mkfs(1M)` 手册页。

如果你直接使用 `mkfs` 命令，应该使用 `-F` 命令行参数来指明要创建的文件系统类型。如果不指定文件类型，则默认使用 `/etc/default/fs` 中列出的类型。本地（基于磁盘）文件系统的默认类型是 UFS。还可以指定 FS 参数，例如块大小和磁盘几何结构（每条磁道的扇区数、每个柱面的磁道数等）。

> **考试警示**
>
> 用于创建文件系统的命令识别原始（字符）逻辑设备名称。此外，在标准的 Solaris 8 操作系统上可以创建的基于磁盘的文件系统类型只有 UFS。然而，当格式化软盘时，磁盘上会自动创建 PCFS，而 PCFS 格式化的是 DOS 磁盘格式。

## 检查和修复文件系统

当定义文件系统的数据损坏时，文件系统就会受损。这种损坏可能是由软件错误或底层物理磁盘硬件的故障引发的。`fsck(1M)` 命令检查（审核）文件系统的逻辑一致性，并尝试进行必要的修复以消除任何不一致性。`fsck` 命令检查超级块、节点、间接块和目录数据块。

`fsck` 命令通常在文件系统自动挂载或作为系统启动的一部分时执行。它也可以手动在一个或多个文件系统上执行。只应该对未挂载的文件系统进行检查和修复，因为更改可能会影响访问文件系统的程序，从而导致更严重的损坏。可以一个或多个逻辑设备名称（分区）作为命令行参数。使用 `fsck` 命令时，你应该使用 `-F` 命令行参数来指定正在检查的文件系统类型。以下列表显示了使用 `fsck` 命令检查之前创建的 1GB 文件系统：

```
fsck -F ufs /dev/rdsk/c0d1s7

** /dev/rdsk/c0d1s7

** Last Mounted on

** Phase 1 - Check Blocks and Sizes

** Phase 2 - Check Pathnames

** Phase 3 - Check Connectivity

** Phase 4 - Check Reference Counts

** Phase 5 - Check Cyl groups

2 files, 9 used, 1019783 free

#
```

如果你不指定 `-F` 命令行参数，则默认使用 `/etc/default/fs` 中定义的文件系统类型。如果没有指定分区（原始逻辑设备名称），则将检查 `/etc/vfstab` 文件中列出的所有文件系统。

> **警示**
>
> 用于检查文件系统的命令中，`fsck` 命令期望原始逻辑设备名称。你可以使用 `fsck` 命令来检查和修复 CacheFS、UDF 和 UFS 文件系统。切记先卸载文件系统。

## 监控和卸载文件系统

使用 `mount(1M)` 命令使文件系统变得可用。该命令将文件系统与当前挂载的文件系统的子目录关联起来。

`mount` 命令通常带有两个命令行参数：与文件系统关联的逻辑块设备（分区）以及文件系统应该挂载的挂载点。如果只指定了一个命令行参数（设备名称或挂载点），将搜索 `/etc/vfstab` 文件中匹配的条目，如果找到，则使用 `/etc/vfstab` 条目的信息挂载文件系统。此外，可以指定 `-F` 命令行参数识别正在挂载的文件系统类型。挂载的文件系统列在 `/etc/mnttab` 文件中（除非指定了 `-m` 命令行参数）。使用 `mount` 命令时不带任何命令行参数，将显示 `/etc/mnttab` 中列出的所有挂载文件系统。

`mount` 命令支持作为命令行参数指定的多个选项。一个重要的选项是 UFS 大文件支持。默认情况下，UFS 文件系统支持大文件（大小大于 2GB）。此默认设置与指定 `-o largefiles` 作为命令行参数相同。要禁用大文件支持，请为 `mount` 命令指定 `-o nolargefiles` 作为命令行参数。如果指定了此选项且文件系统中存在大文件，则挂载将失败。

表 9.3 列出了 `mount` 命令常用的命令行参数。

| 表 9.3: 选择的 mount 命令命令行参数。 |
| 参数 | 用途 |
|---|--- |
| -F type | 指定文件系统类型（NFS、UFS 等） |
| -m | 挂载文件系统不在 /etc/mnttab 中创建条目 |
| -o | 指定文件系统特定的选项 |
| -p | 列出已挂载的文件系统（简列表） |
| -r | 以只读模式挂载文件系统 |
| -v | 列出已挂载的文件系统（详细） |

一些常用的选项：
- `atime`/`noatime`: 通过不更新访问时间来减少活动。
- `intr`/`nointr`: 允许/不允许中断进程。
- `largefiles`/`nolargefiles`: 允许/禁止大于 2GB 的文件。
- `nosuid`: 不允许 setuid。

以下（简略）列表显示了 `mount` 命令的使用：

```
mount /proc /proc

mount /dev/dsk/c0d1s0 /

mount /dev/dsk/c0d1s6 /usr

mount /dev/dsk/c0d1s3 /var

mount /dev/dsk/c0d1s5 /opt

mount /dev/dsk/c0d1s7 /tmp
```
