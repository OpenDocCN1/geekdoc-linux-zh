# 前言

嵌入式系统曾是信息技术领域寂静的角落，如今已成为一个价值数十亿美元的行业，渗透到我们的日常生活并改变了我们的生活。在全球范围内，“智能设备”正渗透进每个人的日常生活中：你开着电子控制的汽车上班，或乘坐数字通勤火车，用手机接听电话，在办公室复印，参加数据会议，然后回家通过电缆机盒或 DVD 播放器看电影。如果你环顾四周，你会发现每天有 50 到 100 台嵌入式计算机影响着你的生活。

Linux 正在席卷这个嵌入式和无处不在的世界。嵌入式设计曾由专有且模糊的操作系统、工具和应用程序主导，而如今的嵌入式设计受益于开源软件（特别是 Linux）的透明性和功能性。即使是保守估计，到 2002 年底，嵌入式 Linux 将占据所有嵌入式设计的一半。

在 MontVista Software 工作的期间，我荣幸与数千名嵌入式开发者交流，并窥探了他们各种多样的项目。我是在 2001 年于纽约的 LinuxWorld 大会上首次结识 Craig Mollough 博士的。在编写这本书期间，我有幸多次与他共处，并在电话中进行了许多次深入交流。

我发现 Craig 的方法既合理又全面。他选择一个应用程序来运行著名的 Silverjak 冬季滑雪胜地，这既让人回想起了嵌入式应用领域（控制与仪器仪表）的“核心内容”，又开启了当今无处不在计算的热门领域（嵌入式 Web 接口、多媒体和消息传递）。他对可用嵌入式硬件和关键接口技术的调查，以及对嵌入式 Linux 开发过程的逐步描述，为有志的系统设计师提供了无价的指路路标。

Craig 的开拓者工程师团队面临着获取和使用嵌入式 Linux 开发工具及部署组件的艰巨任务。Silverjak 的场景和工程努力的细节反映了许多开发者面对首个嵌入式 Linux 项目时的经历。坡度很陡，但回报非常巨大。像《嵌入式 Linux》这样的书籍，嵌入式 Linux 联盟、EMBLIX 和 LinuxDevices 等组织，以及嵌入式 Linux 厂商的努力，为下一代基于 Linux 的智能设备的成功开发和部署扫清了道路。

# 引言

这是一个令人兴奋的时代。互联网技术的普及改变了我们对信息的认知。每天 24 小时，人们都依赖网络设备进行业务和个人使用。随着时间的推移，这种依赖性将进一步增长。今天的网络设备，如服务器、路由器和桌面电脑，构成了互联网的基础设施。未来的设备将控制你家中的温度，维护你业务的库存水平，并监控汽车流量模式。在每年生产的数十亿处理器中，只有极少数被制成桌面或服务器型计算机。其余的处理器则监控并控制着世界的各个方面。

个人和企业都希望通过智能、网络连接的设备来提高生活质量、效率和利润。这些设备必须易于操作、可靠且廉价。技术的进步伴随着竞争性的定价，使得 Linux 能够从桌面和服务器环境扩展到嵌入式设备。Linux 提供了可靠性、功能、开源代码和经实践的良好记录；这些特征使其完美适用于嵌入式系统设计。在书中，你将找到创建嵌入式 Linux 基础的信息。然后你可以根据自己的需求扩展这一基础。

所以你想在下一个嵌入式系统设计中使用 Linux？太棒了！你并不孤单：全球成千上万的开发者都在这样做。和你一样，他们希望利用大量的代码工作来使自己的产品变得可靠、功能丰富、健壮并快速上市。嵌入式 Linux——将 Linux 作为嵌入式设备的操作系统——现在已成为常见。许多开发者将 Linux 视为嵌入式设计的一个选项。然而，今天 Linux 已经准备成为嵌入式操作系统市场的领导者。

在未来几年里，预计每年产生的数十亿处理器中将很大一部分运行 Linux。Linux 的大规模互联网采用，结合硬件（CPU）和内存（闪存和 RAM）的技术进步和价格下降，终于使嵌入 Linux 成为一个可行的方案。自 1999 年以来，嵌入式 Linux 的使用从零增长到在市场份额上仅次于 Wind River。专家预计嵌入式 Linux 将在 2002 年底获得第一市场份额。这非常有趣，考虑到 Linux 实际上在年前还是一个学生项目。通过在产品设计中使用嵌入式 Linux，Linux 可以成为第一。

## 为什么是 Linux，为什么是现在

微处理器行业的进步为将 Linux 作为嵌入式操作系统提供了基础。使用 4 位或 8 位处理器的嵌入式设计时代已经过去；今天它同样容易且具有竞争力地拥有数兆字节内存的 32 位微处理器。硬件创新与过时的速度瞬息万变，为实时操作系统（RTOS）供应商带来了巨大的开发挑战。由于资源有限，这些 RTOS 供应商所做出的商业决策使得许多开发者无法获得支持。开发者总是希望为新的嵌入式设计选择最新、最强大的硬件和软件，同时要求更高的可靠性。桌面操作系统提供了更多的内存和 CPU 资源。供应商提供了可靠性，但在瞬息万变的技术世界中却苦苦挣扎。这正是 Linux 的用武之地。

Linux 提供了可靠性和效率，并有经证明的记录。开源的可用性在性能、功能、驱动程序开发和移植活动方面催生了无数改进、增强和新增。嵌入式系统设计师喜欢开源软件，因为他们经常为自己的设计修改子系统代码。Linux 支持可移植操作系统接口（POSIX），这允许开发者轻松地移植现有代码。Linux 已成功移植到多种微处理器上，包括 x86、SPARC、ARM、PowerPC、MIPS 和 SuperH。

最初，开发者对将 Linux 作为嵌入式操作系统持疑虑态度，因为其分布式开发方法以及感知上缺乏支持结构。得益于嵌入式 Linux 联盟（ELC），嵌入式 Linux 的支持结构自 1999 年以来发生了巨大变化。该联盟成立于 2000 年 5 月，最初有 50 个成员，现在已拥有用于嵌入式应用的成员。该联盟致力于标准化和促进 Linux 用于嵌入式应用。此外，还有几家公司专门为了嵌入式 Linux 而成立。这些公司并不重新打包发行版销售 CD。它们拥有广泛的嵌入式 Linux 产品以及设计和支持服务。使用嵌入式 Linux，开发者可以使用最新最强大的硬件和软件设计高可靠性的产品。

## 什么是嵌入式系统？

如果你让十个工程师定义嵌入式系统，你会得到十个不同的答案。大多数嵌入式系统执行特定任务。假设最简单的嵌入式系统包含输入和输出能力以及控制逻辑。该系统根据其配置执行某种功能。根据这些标准，一个包含 74123 计数器和状态机控制逻辑的离散逻辑电路可以被视为嵌入式系统。你可能会补充说该系统需要通过软件进行编程，并存储在系统固件中。这种嵌入式系统的新定义由存储在系统固件中的输入/输出（I/O）和控制逻辑组成。一台带有鼠标、键盘、网络连接并运行图形用户界面（GUI）的多任务操作系统的桌面电脑完全符合这些要求，但它被视为嵌入式系统吗？

如果你不认为桌面电脑是嵌入式系统，那么手持设备呢？它们具有 I/O 能力，并可以运行存储在固件中的控制逻辑。有些人说，桌面电脑和手持设备是通用计算设备，能够运行软件执行许多不同的任务。另一方面，嵌入式系统主要设计为特定任务设计——例如，洗碗机控制器或飞行导航系统。这种特定功能定义了嵌入式设计的唯一目的。如果是这样的话，为什么有些嵌入式系统具有额外的容量，例如易失性内存中的程序存储，以及运行多任务操作系统的能力，能够执行原始设计之外的任务？

在过去，区分嵌入式系统和通用计算机比现在要容易得多。例如，你可以很容易判断出基于 8051 的 T1 帧卡是来自 Sun 的嵌入式系统。在今天，从功能上，工作站与一个带有 32MB 内存和 16MB Flash 内存的 PowerPC 顶盒之间是高度可区分的。顶盒运行带有 GUI 的多任务操作系统，它是完全可升级的，同时运行多个程序（如视频控制器、数字录像机和 Java 虚拟机），并进行安全的 Internet 交易。现在很难说这个顶盒是否是一个嵌入式系统。显然，硬件性能的提高和硬件成本的降低模糊了通用计算机和嵌入式系统之间的界限。技术的进步使得判断什么是嵌入式变得困难。

## “实时”意味着什么？

如果你问工程师实时意味着什么，你会得到许多不同的答案，其中充满了保证、硬实时、软实时、确定性、抢占式、优先级反转、延迟、中断和调度等术语。来自 `linuxdevices.com` 的 Rick Lehrbaum 向七位专家提出了这个问题。这些专家认为，实时系统保证对事件的响应是具有确定性的，且延迟响应被视为系统失败。他们还认同，软实时系统尝试尽可能地缩短响应时间，而不将延迟响应视为系统失败。在处理实时实现和系统性能表征时，专家们的意见产生了分歧。

Linux 的一个性能方面是显而易见的：原生 Linux 内核和设备驱动程序启用中断。这可能会严重影响系统的响应能力。幸运的是，开源代码的可用性允许开发解决方案来克服这一局限性。这些解决方案遵循两种方法：通过使内核具有抢占性来改进 Linux 调度器，并将 Linux 作为小型 RTOS 内的线程运行。自然地，每种方法都有其优点、缺点、支持者和反对者。
