
# 变量说明

*   `@L`：`ugetty` 连接的串口。
*   `@S`：系统名称。
*   `@T`：当前时间，`HH:MM:SS`（24小时制）。
*   `@U`：当前登录的用户数。这是 `/etc/utm` 文件中非空字段的数量。
*   `@V`：默认文件中给出的 `VERSION`。

要显示 `@` 字符，请使用 `\@` 或 `@@`。

## 7. 自定义 ugetty

对于你的每个端口，都有许多可以调整的参数。这些参数是在每个独立的文件中实现的。`/etc/conf.uugetty` 将被所有 `ugetty` 实例使用，而 `/etc/conf.uugetty.ttySN` 仅由该端口使用。示例默认配置可以在 `tty_ps` 源文件中找到，适用于大多数 Linux 发行版。此处未列出它们。注意，如果你使用的是旧版本的 `ugetty`（低于 2.0.7），或不使用 `FSTND`，默认文件为 `/etc/conf.uugetty.ttySN`。

如果你在串口口上有一个 `DB9` 接口，请尝试以下操作：

| DB9 | | Terminal DB25 | | |
|---|---|---|---|---|
| RxD | 接收数据 | 2 <-- | TxD | 传输数据 |
| TxD | 传输数据 | 3--3 | RxD | 接收数据 |
| SG | 信号地 | 5--7 | SG | 信号地 |

或者，使用一根 `DB9`-`DB25` 调制线（可能不支持终端硬件握手；见上文）：

| DB9 | | Terminal DB25 | | |
|---|---|---|---|---|
| RxD | 接收数据 | 2 <-- | TxD | 传输数据 |
| TxD | 传输数据 | 3--3 | RxD | 接收数据 |
| | | 6 | DSR | 数据设备准备就绪 |
| DTR | 数据终端就绪 | 4--8 | DCD | 载波检测 |
| GND | 信号地 | 5--7 | GND | 信号地 |
| DCD | 载波检测 | 1 | | |
| DSR | 数据设备准备就绪 | 6 <--20 | DTR | 数据终端就绪 |
| RTS | 请求发送 | 7--5 | CTS | 允许发送 |
| CTS | 允许发送 | 8 <--4 | RTS | 请求发送 |
| (RI) | 振铃指示 | 9 不需要 | | |

（是的，`DB9` 接口中的引脚 2 和 3 的含义与 `DB25` 接口中的含义确实是相反的！）

如果你没有使用调制解调器线，可能需要采用以下技巧：在连接器的这一端，将 `RTS` 和 `CTS` 连接在一起，同时将 `DSR`、`DCD` 和 `DTR` 连接在一起。这样，当计算机需要某个握手信号时，它就能获取到该信号（来自自身）。

现在你已经有了正确的线缆，将你的终端连接到电脑。如果可以，告诉终端忽略调制解调器控制信号。尝试使用 9600 bps、8 位数据位、1 位停止位、无奇偶校验位进行终端设置（如果你想更复杂一些，可以开启奇偶校验）。

## 8.2 设置 getty (getty_ps 的一部分)

查阅你的 `getty` 手册获取其他 `getty` 程序（如 `getty`）。如果 `/etc/getdefs` 中还没有，请为用于你终端的 `getty` 添加条目：

```text
# 38400 bps 哑终端项
DT38400# B38400 CS8 CLOCAL # B38400 SANE -ISTRIP CLOCAL ##S @L login:
#DT38400

# 19200 bps 哑终端项
DT19200# B19200 CS8 CLOCAL # B19200 SANE -ISTRIP CLOCAL ##S @L login:
#DT19200

# 9600 bps 哑终端项
DT9600# B9600 CS8 CLOCAL # B9600 SANE -ISTRIP CLOCAL ##S @L login:
#DT9600
```

如果你愿意，可以让 `getty` 在登录横幅中打印一些有趣的内容。在我的示例中，我打印了系统名称和串口号。你可以添加其他的：

*   `@B` 当前的 bps（在显示时评估）
*   `@D` 当前日期，格式为 `MM/DD/YY`。
*   `@L` `getty` 挂载的串口。
*   `@S` 系统名称。
*   `@T` 当前时间，格式为 `HH:MM:SS`（24小时制）。
*   `@U` 当前登录的用户数
*   `@V` `VERSION` 的值，如默认设置中给出的值
*   `@` 字符或 `'@'`。

当你编辑 `/etc/getdefs` 时，可以通过执行以下命令来验证语法是否正确：

```
linux# -c /etc/getdefs
```

确保你的终端所连接的串口上没有 `getty` 配置（`/etc/default/tty` 或 `/etc/conf/tty`），因为这可能会干扰在终端上的运行。如果该文件存在，请将其删除。编辑你的 `/etc/init` 以在串口上运行 `getty`（将 `port` 替换为速度，将 `default` 终端类型）：

```
S1:4,respawn:/bin/getty ttyS19600
```

重启 `init`：

```
linux# q
```

## 8.3 关于将 PC 设置为终端的注意事项

很多人将其他 PC 设置为连接到 Linux 盒的终端。例如，旧的 8088 或 8086 PC 非常适合这个用途。你只需要一个包含适用于你终端的 DOS 版本的启动盘，以及一个供终端 PC 运行的通信程序。`Kermit` 非常适合这个目的。你可以在 `http://www.columbia.edu/k/` 找到适用于所有系统的 `Kermit` 预编译版本。其他流行的 DOS 程序（如 `telix` 和 `procomm`）效果同样良好。请确保在终端的设置中输入正确的串口口信息。

## 9. 我可以使用两个以上的的串口设备吗？

除非你想使用三个或更多串口设备（假设你没有多端口板卡），否则你不需要阅读这一节。

只要你还有另一个串口，是的，你可以的。你使用的串口数量受限于我们必须使用的中断请求（IRQs）和端口 I/O 地址的数量。这不是 Linux 的限制，而是 PC 总线的限制。每个串口设备都必须分配其自己的中断。如果两个设备共享同一个中断，只要这两个设备不同时运行，它们可能运行得良好（在大多数情况下，这些程序不能同时运行）。串口设备可以是内部调制解调器，也可以是多端口串口卡。

多端口串口卡专门设计为具有多个串口，且板卡上的所有端口共享同一个 IRQ。Linux 通过为板卡上的每个端口使用不同的 I/O 地址从它们获取数据。

如果你有一个 14400 bps (V.32bis) 的调制解调器并带有 V.42bis 数据压缩，请使用 57600 bps。

如果你有一个 9600 bps (V.32) 的调制解调器并带有 V.42bis 数据压缩，请使用 38400 bps。

如果你使用的比 9600 bps (V.32) 调制解调器更慢，请将速度设置为调制解调器支持的最高速度。例如 300 bps (V.21/Bell 103)、1200 bps (V.22/Bell 212A) 或 2400 bps (V.22bis)。

如果你先在命令行上使用 `setserial test`，在它们运行正常后，将它们放入 `/etc/rc.d/rc.serial`、`/etc/rc.d/rc.local` 或 `/etc/rc.boot/0setserial`，以便它们在启动时运行。确保你使用的是 `setserial` 的有效路径和有效的设备名称。你可以通过运行以下命令来检查串口的设置：

```
setserial -a /dev/tty3
```
