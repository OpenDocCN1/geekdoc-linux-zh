
在接下来的练习中，你将看到文件名生成的示例，以及在不需要时如何抑制它。包含未引号的 `*`、`?` 的单词以及成对 `[]` 内的字符被 shell 视为模式。shell 会生成一个匹配模式的排序后的文件名列表（包括目录）。如果此列表为空（即未找到匹配项），则该单词保持不变。否则，文件名列表将替换该单词。

识别的模式并不像 `ed` 和 `vi` 中的正则表达式那样复杂。shell 的行为也略有不同。Bourne shell 和 C shell 之间也有细微差异。这里将集中在 Bourne shell 上（shell 变体参见附录 A）。

- `*` 匹配任何字符串，包括空字符串（空字符串），但不包含点开头的文件（即以点开头的文件）。在 `ed` 和 `vi` 中，`x*` 匹配 `x` 的零次或多次出现。
- `?` 匹配任何单个字符，但点文件开头的点除外。（在 `ed` 和 `vi` 中，点用于单字符匹配，包括点本身，但不包括换行符）。
- `[xyz...]` 匹配括号内的任意一个字符。
- `[a-x]` 匹配范围内的任何字符。

紧跟在 `[` 之后的 `!`（读作 bang）会反转匹配的含义。因此：

- `[!xyz]` 匹配括号内**不在**的任何字符。
- `[!a-x]` 匹配范围内**不在**的任何字符。（在 `ed` 和 `vi` 中，使用脱字符 `^` 而不是 `!` 来反转匹配）。

一个可能误导不智者的关键点是，当没有匹配项时，文件名生成**确实**会发生。考虑这个例子：

```bash
$ echo ?
```

你通常会预期使用 `'?'` 或 `"?"` 来显示像 `?` 这样的元字符。但在这里，shell 将无法在当前目录下找到任何单字符文件名！因此，“单词” `?` 被原封不动地传递了。

# 利用 shell

显然，显示字面量 `?` 最安全的方法是对其进行转义或引用，因为我们永远无法确定找不到任何单字符文件名。

- `$ echo \\`

  `?`

- `$ echo '?'`

  `?`

- `$ echo "?"`

  `?`

将这些示例与以下示例进行比较：

- `$ echo /bin/??`

  `/bin/ed /bin/dw/bin/vi`

- `$ echo ???`

  `bin tom tmp usr`

- `$ echo \*`

- `$ echo '*'`

  `*`

- `$ echo "*"`

  `*`

- `$ echo *`

  `<列出所有不以点开头的文件名>`

- `$ echo ,*`

  `<列出所有以点开头的文件名>`

- `$ echo *+`

  `lost+found`

- `$ echo wx*yz`

  `wx*yz`

  `<未找到匹配项>`

- `$ echo wx*yz'`

  `wx*yz`

- `$ echo 'What's that?' \ \''`

  `> OK`

  `> OK'`

  `What's that?`

  `OK`

  `OK`

- `$ _`

注意最后一个例子中不匹配的单引号 `'`：由于缺少一个 `'`，shell 期望更多输入，并会一直提示，直到你提供最后的引号为止。
