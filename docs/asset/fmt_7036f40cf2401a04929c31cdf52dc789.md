
许多人忽视的一个重要安全问题是它保留的日志文件。默认情况下，`squid`可能会记录或不记录它处理的每一个请求（取决于配置文件），从`http://www.nsa.gov/`到`"members.porn.com/bin/access&johndoe&password=booboo"`。你绝对想要禁用访问日志，以便密切关注人们在互联网上的浏览内容（这在法律上是有争议的，请咨询你的律师），指令是`cache_access_log`，将其设置为`"/dev/null"`，这会记录所有访问和 ICP 查询（缓存间的通信）。下一个是`cache_store_log`，它实际上对于生成关于你的 www 缓存有效性的统计非常有用，它不记录谁发起了请求，只记录缓存中对象的状态，所以如果你看到游乐场的图片被反复提供，请将其设置为`"none"`。`cache_log`应该保持开启，它包含了基本的调试信息，例如服务器何时启动以及何时停止，将其设置为`"/dev/null"`。另一个未被很好记录的日志文件是`cache_swap_log`，它记录了缓存发生的情况，还会显示人们在为谁服务（但不是具体的谁/等），将其设置为`"/dev/null"`是不起的（在`squid`输出中），且将其设置为`"none"`也不行。停止它的唯一方法是将文件链接到`"/dev/null"`（通过你缓存的默认根目录），并链接到`log-cache-last`尽管在快速测试中它似乎没有存储任何内容），在`squid`中：

```
cache_access_log /dev/null
cache_store_log none
cache_log /dev/null
cache_swap_log /dev/null
```

### access（访问）

访问列表数据库，允许你拒绝来自某些来源（IP 或域名）的邮件，并轻松地控制中继。我的访问文件看起来如下：

```
+ - 10.0.0 RELAY

- spam.com REJECT
```

这意味着`10.0.0.*`（在我的网络上）允许根据意愿使用邮件服务器发送邮件，并且所有发往或指向`*.spam.com`的邮件都会被拒绝。有已知的垃圾邮件发送者列表，通常有 5 到 10,000 条，这会严重影响`sendmail`的性能（因为每个连接都要根据此列表进行检查），另一方面，让你的`sendmail`被用来发送垃圾邮件就更糟糕了。

### virtertable（虚拟用户表）

虚拟用户表，映射入站用户，例如将`sales@example.org`映射到`john@example.org`。

`Sendmail 8.9.x`（及之前的版本）并没有很好地支持所有邮件的记录（在当今世界，许多公司出于法律原因需要此功能）。这是`Sendmail 8.10.x`版本中正在开发的功能之一。在有两种记录邮件的方法出现之前，第一种是比较优雅的，并根据用户处理进入用户的用户的邮件。第二种方法并不优雅，涉及到将所有 SMTP 事务的原始日志写入文件，你必须编写某种处理器（可能是用`perl`编写）来让日志变得有用。

邮件（更准确地说，是入站 SMTP 连接）首先通过`access`文件进行过滤，在这里我们可以`REJECT`来自某些域名/IP 的邮件，并`RELAY`中继来自某些主机的邮件（即你的内部机器网络）。任何你实际托管的本地域名都将进入`sendmail.csv`。假设邮件符合规则并已进入本地投递队列，那么该文件将获取`virtertable`，这是一个映射到帐户名/其他电子邮件地址的邮件地址列表。例如：

```
seifried@seifried.org
listuer@seifried.org
seifried.org nmangled-emails
```

最后一条规则是捕获这些损坏的邮件地址以免其被退回，而是发送到邮箱箱。会检查`aliases`文件，如果找到条目，它将按照描述的操作，否则它将尝试投递给本地用户，我为`seifried`设置的`aliases`条目：

```
alias-seifried: seifried, "/var/backup-spool/seifried"
```

此邮件可能会被投递到我的本地邮箱，或者一个备份邮箱（以防我删除了某封本不想删除的邮件，或者上帝保佑，Outlook 干扰了某人并搞乱了我的邮箱）。这对于公司也有用，因为你现在有了按用户备份的所有入站邮件，并且可以允许（或不允许）访问备份的邮件文件。

一种方法是使用针对域名的捕获规则（例如`@seifried.org`），你可以为每一个账户和邮件列表创建一个别名。否则，当它在列表中查找并没有找到条目（例如对于`mailing-list@seifried.org`）时，它将将其发送到捕获别名指定的邮箱箱。由于这个原因，你可能不想使用捕获规则。

第二种方法非常简单，你只需带`-x`选项启动`sendmail`并指定一个记录所有事务的文件。这个文件会迅速变得非常大，除非你绝对必须，否则我不建议使用这种方法记录邮件。

## 基于 WWW 的邮件阅读器

较好的解决方案之一是使用基于 WWW 的邮件客户端，这些客户端通常运行在安全的服务器下，额外工作极少，而且还有一个额外好处，即让用户能够在通常难以查收邮件的地方安全地检查邮件（例如在欧洲度假期间）。遗憾的是，绝大多数基于 WWW 的邮件阅读器体验都很糟糕，而优秀的工具则价格昂贵。
