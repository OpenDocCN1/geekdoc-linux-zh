# Linux 文件系统的概览

## 文件

### 通用

对 UNIX 系统的简单描述也适用于 Linux，如下：

> 在 UNIX 系统中，一切皆文件；如果某个东西不是文件，它就是一个进程。

这个说法是正确的，因为存在比文件更特殊的文件（例如命名管道和套接字），简单来说，一切皆文件是可以接受的概括。Linux 系统与 UNIX 不同，文件和目录之间没有区别，因为目录本身也是文件。根据系统，为了以有序的方式管理所有文件，人们在硬盘上使用树形结构，正如我们从 MS-DOS（操作系统）中了解的那样。分支包含更多分支，而树的末端叶子包含普通文件。现在我们将使用这种树形结构，但它并不完全准确。

### 文件的分类

大多数文件都是普通文件；它们包含数据，例如文本文件、可执行文件或程序、输入或输出等。

### 关于文件和文件系统

在 Linux 系统中将遇到的一切保存为文件是安全的，但也有例外：

- 目录：列出其他文件的。
- 特殊文件：用于输入输出的机制。大多数特殊文件位于 `/dev`，我们稍后会讨论。
- 链接：使文件或目录在部分可见。我们将详细介绍链接。
- 套接字：特殊文件类型，类似于 TCP/IP 网络，受文件访问控制保护。

`ls -l` 显示文件类型，使用每行的第一个字符：

```
ls -l
total 80
-rw-r--r-- 1 744 Feb 21
-rw-r--r-- 1 1472 Feb 21
drwxr-xr-x 2 4096 Feb 25 11:50
```

此表提供了决定文件类型的概述：

#### 表 3.1 文件类型

| 符号 | 含义 |
|---|---|
| - | 普通文件 |
| d | 目录 |
| l | 链接 |
| c | 特殊文件 |
| s | 套接字 |
| p | 命名管道 |
| b | 设备 |

为了始终对文件类型执行长列表，许多系统不仅使用 `ls`，还使用带有后缀的 `ls -l`。为了方便用户，通常会将 `-l` 和 `--color` 结合。本文使用 `-l` 以提高可读性。作为用户，你只需要处理普通文件、可执行文件、目录和链接。特殊文件是为了管理员和程序员的需求。

现在，在查看重要的文件和目录之前，我们需要了解更多关于分区的信息。

# 关于文件系统

## 关于分区

### 为什么要分区？

大多数人对什么是分区了解模糊，因为每个操作系统都有创建或删除它们的能力。Linux 在同一块硬盘上使用多个分区似乎很奇怪，即使在使用标准安装程序时也有一些解释。

拥有不同分区的目标之一是在灾难发生时获得更高的数据安全。通过将硬盘划分分区，数据可以分组并隔离。当意外发生时，只有受影响的分区会损坏，其他分区的数据可能会幸存。

这一原则源于 Linux 没有文件系统且掉电可能导致灾难的时代。使用分区来确保安全健壮性意味着系统部分的故障并不意味着整个计算机面临危险。这是分区最重要的原因。一个简单的例子：你创建的脚本、程序或 Web 应用开始填充磁盘。如果硬盘只有一个分区，当磁盘满了，整个系统将停止工作。如果用户将数据存储在单独的分区，那么只有该分区受到影响，而系统分区和其他数据分区将继续运行。

请注意，合并的文件系统仅在掉电和设备突然连接的情况下提供数据安全。这不能保护你的数据免受坏块和文件系统逻辑错误的影响。在这些情况下，你应该使用 RAID（磁盘阵列）解决方案。

### 分区布局和类型

Linux 系统上有两种分区：

- 根分区：普通的 Linux 系统数据，包括包含启动和运行系统所需所有数据的分区；
- 交换分区：计算机物理内存的扩展，硬盘上的额外内存。

大多数系统包含一个根分区、一个或多个数据分区和一个或多个交换分区。混合环境中的系统可能包含其他系统数据的分区，例如用于 MS Windows 的 FAT 或 VFAT 文件系统的分区。

大多数 Linux 系统在磁盘安装时设置分区类型。如果你注意了第 1 章的练习，这通常会自动完成的。然而，你可能没有那么幸运。在这种情况下，你需要选择分区类型，甚至手动进行实际分区。标准的 Linux 分区有 2 个交换分区和 3 个数据分区，它们可以是日志型的（ext3）或普通型的（ext2）。

无论发生什么，都能正常工作。在 Linux 上，由于有了这部分额外的内存，你几乎不会看到诸如“内存不足，请先关闭某些应用程序并重试”之类的令人恼恼的提示。交换分区（swap）或虚拟内存程序已被 UNIX 世界之外的操作系统广泛采用。

在硬盘上使用内存自然比使用计算机的真实内存芯片要慢，但拥有这部分额外空间是一个巨大的慰藉。我们将在第 4 章“进程”中学习更多关于交换分区的知识。

Linux 通常在硬盘的交换分区空闲空间中预留物理内存两倍的容量。在安装系统时，你必须知道打算如何操作。一个拥有 512 MB RAM 的系统示例：

- 第 1 种可能：一个 1 GB 的分区
- 第 2 种可能：两个 512 MB 的交换分区
- 第 3 种可能：两个硬盘：每个硬盘上一个 512 MB 的分区。

当预期会有 I/O 操作时，最后一个选项将产生最佳结果。

请阅读软件文档以获取特定指南。某些应用程序（如数据库）需要更多的交换空间。而其他应用程序（如手持系统）可能因为缺少硬盘而完全没有交换空间。交换空间可能取决于你的内核版本。

在许多发行版中，内核位于单独的分区上，因为它是你系统中最重要的文件。如果是这种情况，你会发现你还有一个还有一个启动分区（boot partition），其中存放着内核以及相关的数据文件。

硬盘的其余部分通常被划分为数据分区，尽管可能所有系统关键数据都储存在一个分区上（例如你执行了标准的工作站安装时）。当非关键数据被分离在不同的分区上时，通常会遵循如下模式：

- 一个用于用户的分区 (`/usr`)
- 一个包含用户个人数据的分区 (`/home`)
- 一个用于存储临时数据（如打印队列和邮件队列）的分区 (`/var`)
- 一个用于第三方软件和额外交换空间的分区 (`/opt`)

一旦创建了分区，你只能增加更多的分区。更改现有分区的尺寸或属性是可能的，但不建议这样做。

硬盘划分为分区的由系统管理员决定。在较大的系统中，他可以使用适当的软件将一个分区扩展到多个硬盘上。大多数发行版允许针对工作站（普通用户）和通用服务器用途优化的标准设置，但也允许自定义分区。在安装过程中，你可以使用发行版特定的工具来定义你的分区布局，该工具通常是一个直观的图形化界面，或者是 `fdisk`（一个用于创建分区和设置其属性的文本工具）。

工作站或客户端安装主要供同一个人使用。所选的安装软件反映了这一点，并且在用户程序包中很常见，例如桌面主题、开发工具、电子邮件客户端程序、多媒体软件、网页和其他服务。所有内容都被放在一个大分区中，添加了倍于 RAM 容量的交换空间，你的通用工作站就大告成了。这为个人使用提供了最大的磁盘空间，但缺点是在出现问题时可能会导致数据完整性的丢失。

在服务器上，系统数据倾向于与用户数据分离。提供服务的程序存储的位置与该服务处理的数据不同。在类系统上会创建不同的分区：

- 一个包含启动机器所需所有数据的分区
- 一个包含配置数据和服务器程序的分区
- 一个或多个包含服务器数据（如数据库表、用户邮件、ftp 存档）的分区
- 一个包含用户程序和应用程序的分区
- 一个或多个用于用户特定文件（家目录）的分区
- 一个或多个交换分区（虚拟内存）

服务器通常拥有更多的内存，因此有更多的交换空间。服务器进程（如数据库）可能需要比通常更多的空间；请查看特定文档获取详细信息。为了获得更好的性能，交换经常被划分为不同的交换分区。

## 挂载点

所有分区都通过挂载点（mount point）连接到系统。挂载点定义了特定数据集在文件系统中的位置。通常，所有分区都通过*根*分区连接。在这个用斜杠 (`/`) 表示的分区上，了目录。这些空目录将成为挂载在其上的分区的起点。示例：一个包含以下目录的分区：

```
videos/ cd-images/ pictures/
```

我们想在文件系统中将此分区挂载到目录 `/opt/media`。为了实现这一点，系统管理员必须确保系统上存在 `/opt/media` 目录。最好它是一个空目录。这将在本章的稍后部分进行解释。然后，使用 `mount` 命令，管理员可以将该分区挂载到系统。当你查看空目录 `/opt/media` 的内容时，它将包含位于挂载介质（硬盘或软磁盘、CD、DVD、闪存、USB或其他存储设备）上的文件和目录。

在设置期间，所有分区都如 `/etc/fstab` 文件所述的那被挂载。某些分区默认不挂载，例如它们没有持续连接到系统，如你的数码相机使用的存储器。如果经过配置，设备在系统注意到它已连接时就会被挂载，或者它可以是用户可挂载的，即你不需要是系统管理员就可以将设备挂载到系统或从系统卸载。在“使用 rsync”部分有一个示例。
