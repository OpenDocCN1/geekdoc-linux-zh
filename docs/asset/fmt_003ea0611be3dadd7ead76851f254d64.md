## hgrep：高亮 grep 脚本

是否曾经想在大文件中方便地查找文本？文本文件越大，你就会越能体会这个 shell 脚本的好处。在 shell 脚本中使用反色视频不仅仅是为了制作菜单。那么在文件或命令输出中进行高亮呢？在本章中，我们展示了一个在 shell 脚本中使用反色视频的示例，其工作原理类似于 grep 命令。我们不再显示匹配模式的行，而是显示整个文件（或命令输出），并用反色视频高亮匹配的模式。我喜欢称之为 hgrep。

在创建这个 shell 脚本的过程中，最初开发了一个测试脚本，但结果变得非常复杂。它首先对每行进行指定模式的 grep 搜索。如果在行中找到了模式，就会对该行开始逐字符扫描，以找到行中的精确模式以进行高亮，然后再次 grep 文本行中的模式，依此类推。这段初始代码存在相当的问题，除了脚本本身的复杂性外，还由于 Unix 字符在扫描 shell 脚本代码时会导致输出出现非常奇怪的情况。纯文本文件可以工作，但脚本执行速度非常慢。

随后发现，`sed` 应该处理模式匹配——而且速度比用 shell 脚本解析文件快得多。Korn shell 脚本实际上并不是为了逐行逐字符地处理文件设计的；虽然可以做到，但那是 Perl 的用场。问题涉及如何使用 sed 在 sed 语句中添加高亮控制。在思考了 sed 和命令替换了一段时间后，我在 脚本中写了大约 15 分钟（这可是有记录的！），以下是我的成果。

## 反色视频控制

有两个命令控制反色视频：`tput smso` 开启反色视频高亮，以及 `tput rmso` 关闭高亮。`tput` 命令有许多其他控制终端的选项，`tput scgr0` (sgr-zero) 会关闭所有 tput 选项。要开启文本反色高亮，先打印我们想要的内容，然后开启反色。我们还可以将带有高亮文本的输出保存到文件中。要显示带有高亮文本的文件，我们可以使用 `pg` 或 `page`，在某些操作系统上则需要更多操作。该命令在 AIX 或 HP-UX 系统上不起作用。相反，`more` 命令显示的是构成高亮文本的转义序列字符，而不是高亮文本本身。使用 vi 编辑器也会得到相同的结果。在 Solaris 上，两个操作系统都显示了高亮文本，但 `pg` 和 `page` 命令则没有。

有一个会导致此脚本无法的常见错误：对变量使用双引号，例如 `"$STRING"`。双引号对于单单词模式匹配没有影响，但对于多单词字符串模式，变量必须加引号，否则标准错误将会在脚本中产生命令用法错误。这些错误产生是因为每个单词都导致字符串模式被解释为独立的参数，而不是一个整体。在处理字符串变量时，双引号非常重要。在排排除代码时，忘记加双引号是一个非常难发现的错误。
