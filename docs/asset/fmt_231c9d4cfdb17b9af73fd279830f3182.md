
`gzip` 程序用于压缩一个或多个文件。执行时，它会将原始文件替换为原始文件的压缩版本。相应的 `gunzip` 程序用于将压缩文件恢复为原始的未压缩形式。这里有一个示例：

```
me@linuxbox ~$ ls -l /etc > foo.txt
me@linuxbox ~$ ls -l foo.txt
me@linuxbox ~$ gzip foo.txt
me@linuxbox ~$ ls -l foo.txt.gz
```

在这个示例中，我们通过 `ls -l /etc` 创建了文件。接下来，我们看到 `gzip` 压缩版本。`gzip` 有许多选项：

| 选项 | 说明 |
|---|---|
| `-c` | 将输出到标准输出。 |
| `-d` | 解压缩。这导致 `gzip` 像 `gunzip`。 |
| `-f` | 强制压缩，即使压缩已存在。 |
| `-h` | 显示帮助信息。 |
| `-l` | 列出每个文件的压缩统计信息。 |
| `-t` | 测试文件的完整性。 |
| `-v` | 在压缩时显示详细信息。 |
| `-n` | 设置压缩程度。数字范围从 1（最快）到 9（最慢）。1 和 9 分别也可以表示为 `--fast` 和 `--best`。默认值为 6。 |

让我们回到之前的例子。

```
me@linuxbox ~$ gzip foo.txt
me@linuxbox ~$ gzip -tv foo.txt.gz
foo.txt.gz: OK
me@linuxbox ~$ gzip -d foo.txt.gz
```

在这里，我们将 `foo.txt` 替换为 `foo.txt.gz` 的压缩版本。接下来，我们使用 `-t` 和 `-v` 选项测试压缩版本。最后，我们将其解压缩到原始形式。`gzip` 也可以通过标准输入使用。

```
me@linuxbox ~$ ls -l /etc | gzip > foo.txt.gz
```

此命令创建了目录列表的压缩版本。`gunzip` 程序解压缩 `gzip` 文件，由于文件名以 `.gz` 结尾，因此不需要指定它，只要指定的名称与未压缩文件不冲突。

```
me@linuxbox ~$ gzip foo.txt
```

如果我们的目标只是查看压缩文件的内容，我们可以这样做：

```
me@linuxbox ~$ gzip -c foo.txt | less
```

或者，`gzip` 提供了一个名为 `zcat` 的程序，它等同于带有 `-c` 选项的 `gzip`。它可以像 `cat` 命令一样用于 `gzip` 压缩的文件。

```
me@linuxbox ~$ zcat foo.txt.gz | less
```

还有一个 `zless` 程序。它与之前的管道操作的功能相同。

正如我们看到的，`bzip2` 的用法与 `gzip` 相同。我们为 `gzip` 讨论的所有选项（除 `-r` 之外）在 `bzip2` 中也受支持。但请注意，压缩级别选项（`-number`）在 `bzip2` 中的含义不同。`bzip2` 附带了用于解压文件的 `bzip2` 和 `bcat`。此外，`bzip2` 还附带了 `bzip2recover` 程序，它可以尝试恢复损坏的 `bzip2` 文件。

## 不要有压缩迫症

我偶尔会看到人们尝试对已经用有效压缩算法压缩的文件进行再次压缩，方法如如下所示：

```
$ gzip picture.jpg
```

不要这样做。你可能只是在浪费时间和空间！如果你对一个已经压缩的文件应用压缩，通常会导致生成的文件变大。这是因为所有压缩技术都会向文件中添加一些开销来描述压缩信息。如果你尝试压缩一个已经不包含冗余信息的文件，压缩可能无法产生任何足以抵消额外开销的节省。

## 归档文件

与压缩配合的一个常用文件管理任务是归档。归档是将许多文件收集并将它们打包成一个大文件的过程。归档通常作为系统备份一部分进行。它也用于将旧数据移动到某种长期存储中。

## `tar`

在 Unix 类的软件世界中，`tar` 程序是归档文件的经典工具。它的名字是 tape archive（磁带存档）的缩写，揭示了它作为备份磁带工具的起源。虽然它仍用于传统任务，但它在其他存储设备上同样高效。我们经常看到扩展名为 `.tar` 或 `.tgz` 的文件名，它们分别表示“纯”`tar` 归档和经过 `gzip` 压缩的归档。`tar` 归档可以由一组单独的文件、一个或多个目录层次结构或这两者的混合组成。命令语法如下：

```
tar mode[options] pathname...
```

在这里，`mode` 是表 18-2 列出的操作模式之一（此处仅显示了部分列表；完整列表请参 `tar` 的 man 页）。

表 18-2：`tar` 模式

| Mode | Description |
|---|---|
| `c` | 从文件和/或目录列表创建归档。 |
| `x` | 提取归档。 |
| `r` | 将指定的路径添加到归档的末尾。 |
| `t` | 列出归档的内容。 |

`tar` 表示选项的方式略显奇异，因此我们需要一些示例来展示它是如何工作的。首先，我们将重新创建上一章节中的实验场。

```
me@linuxbox ~ $ mkdir -p playground/dir-{001..100} 
me@linuxbox ~ $ touch playground/dir-{001..100}/file-{A..Z}
```

接下来，让我们创建一个整个实验场的归档。

```
me@linuxbox ~ $ tar cf playground.tar playground
```

此命令创建了一个名为 `playground.tar` 的归档，包含整个 `playground` 目录层次结构。我们可以看到 `mode` 和 `f` 选项（用于指定归档名称）可以合并，且不需要前导连字符。但请注意，模式必须在任何其他选项之前指定。

要列出归档的内容，我们可以这样做：

```
me@linuxbox ~ $ tar tf playground.tar
```

为了获得更详细的列表，我们可以添加 `v`（详细模式）选项。

```
me@linuxbox ~ $ tar vf playground.tar
```

现在，让我们在一个新位置提取 `playground`。我们将通过创建一个名为 `foo` 的新目录、切换到目录并提取归档来实现。

```
me@linuxbox ~ $ mkdir foo 
me@linuxbox ~ $ cd foo 
me@linuxbox foo$ $ tar xf ../playground.tar 
me@linuxbox foo$ $ ls 
playground
```

如果我们检查 `~/foo/playground` 的内容，会发现归档已成功提取，创建了原始文件的精确复制。然而，有一个例外。除非我们以超级用户身份操作，否则从归档中提取的文件和目录将属于执行还原的用户，而不是原始所有者。

`tar` 的另一个有趣行为是它处理归档中路径的方式。路径默认是相对路径，而不是绝对路径。`tar` 通过在创建归档时简单地删除路径中的任何前导斜杠来实现此点。为了演示，我们将重新创建归档，这次指定一个绝对路径。

```
@me@linuxbox$ cd
@me@linuxbox~$ tar cf playground2.tar ~/playground
```

记得，当我们进入时，`~/playground` 会展开为 `/home/me/playground`，因此我们的演示将获得一个绝对路径。接下来，我们将像之前一样提取归档并观察发生什么。

```
@me@linuxbox ~$ cd foo
@me@linuxbox~$ tar xf ../playground2.tar
@me@linuxbox~$ ls
home
@me@linuxbox foo$ ls
me
@me@linuxbox foo$ ls home/me
playground
```

在这里我们可以看到，我们提取了第二个归档，相对于我们当前的工作目录 `~/` 重新创建了目录 `/home/me/playground`，而不是相对于根目录（如果是使用绝对路径的话）。这种工作方式看起来可能很奇怪，但它实际上更有用，因为它允许我们将归档提取到任何位置，而不是被强制提取到特定位置。

虽然我们之前是在外部使用 `gzip` 程序生成压缩归包，但现代版本的 GNU `tar` 已经通过分别使用 `z` 和 `j` 选项支持 `gzip` 和 `bzip2` 压缩。以之前的示例为基础，我们可以这样简化它：

```
[me@linuxbox ~]$ find playground -name 'file-A' | tar czf playground.tgz -T -
```

如果我们想创建一个用 `bzip2` 压缩的归包，可以这样做：

```
[me@linuxbox ~]$ find playground -name 'file-A' | tar cjf playground.tbz -T -
```

通过简单地将压缩选项从 `z` 改为 `j`（并将输出文件扩展名改为 `.bz2` 以指示 `bzip2` 压缩文件），我们就启用了 `bzip2` 压缩。
