
在 Linux 上可用的 C 编译器是 GNU C 编译器，简称为 `GCC`。该编译器是在自由软件基金会的编程许可证下创建的，因此可以自由分发。你可以在随书附赠的 CD-ROM 中找到它。

## GNU C 编译器

Slackware Linux 发行版中打包的 GNU C 编译器（`GCC`）是一个功能完整、兼容 ANSI C 的编译器。如果你熟悉其他操作系统或硬件平台上的 C 编译器，你将能够非常快地学会使用 `GCC`。本节描述了如何调用 `GCC`，并介绍了一些常用的 `GCC` 编译器选项。

### 调用 GCC

通过向 `GCC` 编译器传递一系列选项和若干文件名来调用它。调用 `gcc` 的基本语法如下：

```
gcc [options] [filenames]
```

由命令行选项指定的操作将在命令行中指定的每个文件上执行。下一节将描述你最常使用的选项。

### GCC 选项

可以传递给 `GCC` 的编译器选项有 100 多个。你可能永远不会使用其中的许多选项，但你会经常使用其中的一些。许多 `GCC` 选项由多个字符组成。因此，你必须使用各自的连字符来指定每个选项，而不能像大多数 Linux 命令那样在单个连字符后组合选项。例如，以下两个命令并不相同：

```
gcc -p -g test.c
gcc -pg test.c
```

第一个命令告诉 `GCC` 编译 `test.c`，为 `prof` 命令生成性能分析信息，并将调试信息存储在可执行文件中。第二个命令则简单地告诉 `GCC` 编译 `test.c`，为 `gprof` 命令生成性能分析信息。

当你使用 `gcc` 且不带任何命令行选项编译程序时，它会创建一个可执行文件（假设编译成功），并将其命名为 `a.out`。例如，以下命令在当前目录中创建一个名为 `a.out` 的文件：

```
gcc test.c
```

如果要为可执行文件指定 `a.out` 以外的名称，可以使用 `-o` 编译器选项。例如，要将名为 `count.c` 的 C 程序文件编译为名为 `count` 的可执行文件，请输入以下命令：

```
gcc -o count count.c
```

> **提示**
>
> 当使用 `-o` 选项时，可执行文件名必须紧跟在命令行中的 `-o` 之后。

还有一些编译器选项允许你指定编译要进行的程度。`-c` 选项告诉 `GCC` 将代码编译为对象代码，并跳过编译过程中的汇编和链接阶段。这个选项使用相当频繁，因为它使多模块 C 程序的编译更快且更易于管理。`GCC` 创建的对象代码文件默认具有 `.o` 扩展名。

`-S` 编译器选项告诉 `GCC` 在生成 C 代码的汇编器文件后停止编译。`GCC` 生成的汇编器文件默认具有 `.s` 扩展名。`-E` 选项指示编译器仅对输入文件执行预处理阶段。当使用此选项时，预处理器的输出会被发送到标准输出，而不是存储在文件中。

### 优化选项

当你使用 `GCC` 编译 C 代码时，它试图以最少的编译时间编译代码，并试图生成易于调试的编译后代码。使代码易于调试意味着编译后代码的顺序与源代码的顺序相同，并且没有代码被优化掉。有许多选项可以用来告诉 `GCC` 以牺牲编译时间和调试便利性为代价，生成更小、更快的可执行程序。在这些选项中，你通常使用的是 `-O` 和 `-O2` 选项。

`-O` 选项告诉 `GCC` 对源代码执行基本优化。在大多数情况下，这些优化会使代码运行得更快。`-O2` 选项告诉 `GCC` 使代码尽可能快和小。与使用 `-O` 选项相比，`-O2` 选项会使编译速度变慢，但通常会导致代码执行得更快。

除了 `-O` 和 `-O2` 优化选项外，还有许多低级选项可用于使代码更快。这些选项非常具体，只有在你完全理解这些选项对编译后代码的后果时才应使用。有关这些选项的详细说明，请在命令行输入 `man gcc` 参考 `GCC` 的手册页。

### 调试和性能分析选项

`GCC` 支持几个调试和性能分析选项。在这些选项中，你最可能使用的是 `-g` 选项和 `-pg` 选项。

`-g` 选项告诉 `GCC` 生成调试信息，以便 GNU 调试器（`gdb`）可以使用这些信息来帮助你调试程序。`GCC` 提供了一项许多其他 C 编译器不具备的功能。使用 `GCC` 时，你可以将 `-g` 选项与 `-O` 选项（生成优化代码）结合使用。如果你试图调试尽可能接近最终产品状态的代码，这会非常有用。当同时使用这两个选项时，你应该意识到，当你编写的一些代码在 `GCC` 优化时可能会被修改。有关调试 C 程序的更多信息，请参见本章中“使用 `gdb` 调试 `GCC` 应用程序”一节。

`-pg` 选项告诉 `GCC` 向你的程序添加额外的代码，当执行这些代码时，会生成 `gprof` 程序可以用来显示关于你程序的计时信息的性能分析信息。有关 `gprof` 的更多信息，请参见本章中“`gprof`”一节。

### 使用 gdb 调试 GCC 程序

Linux 包含名为 `gdb` 的 GNU 调试程序。`gdb` 是一个非常强大的调试器，可用于调试 C 和 C++ 程序。它使你在程序执行期间能够查看程序的内部结构或正在使用的内存。`gdb` 为你提供的功能包括：

- 它允许你监视程序中包含的变量的值。
- 它允许你设置断点，以便在特定的代码行处停止程序。
- 它允许你逐行遍历代码。

你可以在命令行输入 `gdb` 并按 Enter 键来运行 `gdb`。如果你的系统配置正确，`gdb` 将启动，你会看到一个类似于以下内容的屏幕：

```
GDB is free software and you are welcome to distribute copies of it
under certain conditions; type "show copying" to see the conditions.
There is absolutely no warranty for GDB; type "show warranty" for details.
GDB 4.12 (i486-unknown-linux), Copyright 1994 Free Software Foundation,
Inc.
(gdb)
```

当你启动 `gdb` 时，可以在命令行上指定许多选项。你可能会以如下方式运行 `gdb`：

```
gdb <fname>
```

以这种方式调用 `gdb` 时，你正在指定想要调试的可执行文件。这告诉 `gdb` 加载名为 `fname` 的可执行文件。还有其他启动 `gdb` 的方式，可以告诉它检查由正在检查的可执行文件创建的核心转储文件，或将 `gdb` 附加到当前正在运行的进程。要获取这些其他选项的列表和简要说明，你可以参考 `gdb` 的手册页或在命令行输入 `gdb -h`。

### 为调试编译代码

为了让 `gdb` 正常工作，你必须编译你的程序，使编译器生成调试信息。生成的调试信息包含程序中每个变量的类型以及可执行程序中的地址与源代码中行号之间的映射关系。`gdb` 使用此信息将可执行代码与源代码关联起来。

要启用调试信息来编译程序，请使用 `-g` 编译器选项。

### gdb 基本命令

`gdb` 支持许多命令，允许你执行不同的调试操作。这些命令的复杂程度从非常简单的文件加载命令到允许你检查调用栈内容的复杂命令不等。

表 26.1 描述了你在使用 `gdb` 进行调试时需要使用的命令。若要了解所有 `gdb` 命令的说明，请参阅 `gdb` 手册页。

## 表 26.1. 基本 gdb 命令。

| 命令 | 描述 |
| :--- | :--- |
| `file` | 加载要调试的可执行文件。 |
| `kill` | 终止当前正在调试的程序。 |
| `list` | 列出用于生成可执行文件的源代码片段。 |
| `next` | 在当前函数中推进一行源代码，但不进入其他函数。 |
| `step` | 在当前函数中推进一行源代码，并进入其他函数。 |
| `run` | 执行当前正在调试的程序。 |
| `quit` | 终止 `gdb`。 |
| `watch` | 允许你在程序变量的值发生变化时检查该值。 |
| `break` | 在代码中设置断点；每当程序执行到达此点时，程序的执行将被暂停。 |
| `make` | 允许你在不退出 `gdb` 或使用另一个窗口的情况下重新编译可执行程序。 |
| `shell` | 允许你在不离开 `gdb` 的情况下执行 UNIX shell 命令。 |

`gdb` 环境支持许多与 UNIX shell 程序相同的命令编辑功能。你可以像在使用 `bash` 或 `tcsh` 时那样，通过按下 Tab 键来让 `gdb` 自动补全唯一的命令。如果你输入的内容不唯一，你可以再次按下 Tab 键，让 `gdb` 打印出所有匹配你目前输入的 commands 列表。你还可以通过按下向上和向下箭头键来滚动查看你之前输入的命令。
