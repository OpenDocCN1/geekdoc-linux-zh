
## 配置方案适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

## 描述

邮件传输代理 (MTA)，例如 `sendmail` 和 `Postfix`，用于监听入站邮件并将消息传递给适当的用户或邮件服务器。如果该系统不打算作为邮件服务器，建议将 MTA 配置为仅处理本地邮件。

## 理由

所有邮件传输代理的软件都是复杂的，且大多数具有长期的安全问题历史。虽然确保系统能够处理本地邮件消息很重要，但除非服务器旨在作为一个接收和处理来自其他系统邮件的邮件服务器，否则没有必要让 MTA 守护进程在端口上。

## 注意

- 此建议是围绕 `postfix` 邮件服务器设计的。
- 根据您的环境，您可能安装了替代的 MTA（如 `exim4`）。如果是这种情况，请查阅您已安装 MTA 的文档以配置推荐状态。

## 审计

运行以下命令以验证 MTA 是否没有在任何非回环地址 `127.0.0.1` 或 `::1` 上监听。

```bash
# ss -intu | grep -E ':25\s' | grep -E -v '\s(127.0.0.1|::):25\s'
```

不应有任何输出。

## 修复

编辑 `/etc/postfix/main.cf` 并在 `RECEIVING MAIL` 部分添加以下行。

如果该行已存在，请将其修改为像下行所示的内容：

`inet_interfaces = loopback-only`

运行以下命令重启 `postfix`：

```bash
# systemctl restart postfix
```

## 2.4 确保移除或屏蔽非必需服务（手动）

## 配置适用性

- 级别 1 - 服务器
- 级别 1 - 工作站

## 描述

网络端口通过其数字、关联 IP 地址和通信协议类型（如 `TCP` 或 `UDP`）进行标识。

监听端口是应用程序或进程监听的网络端口，作为通信端点。

每个监听端口都可以使用防火墙开放或关闭（过滤）。通常，开放端口是接受来自远程位置入站包的网络端口。

## 原理

在系统上监听的服务存在作为攻击向量的潜在风险。应对对这些服务进行审查，如果不需要，应停止并移除。如果包含服务的包有依赖关系，应停止并屏蔽该服务以减少系统的攻击面。

## 审计

执行以下命令：

```bash
# ss -plntu
```

查看输出以确保列出的所有服务都是系统所需的。如果列出的服务不需要，则移除该服务的包。如果包含服务的包是需要的，则停止并屏蔽该服务。

## 修复

运行以下命令删除包含该服务的包：

```bash
# apt purge <package_name>
```

或者如果软件包存在依赖关系：

运行以下命令停止并掩码服务：

```bash
# systemctl stop <service_name>.socket
# systemctl stop <service_name>.service
# systemctl mask <service_name>.socket
# systemctl mask <service_name>.service
```

## 3 网络配置

本节提供了如何通过内核参数、访问列表控制和防火墙设置保护系统网络配置的指导。

## 注意

- `sysctl` 设置通过 `/usr/lib/sysctl.d/`、`/run/sysctl.d/` 和 `/etc/sysctl.d/` 中的文件定义。
- 文件必须具有 `.conf` 扩展名。
- 供应商设置位于 `/usr/lib/sysctl.d/`。
- 要覆盖整个文件，请在 `/etc/sysctl.d/` 中创建一个同名文件并在其中放入新设置。
- 要仅覆盖特定设置，请在 `/etc/sysctl.d/` 中添加一个字母排序靠后的的文件并在其中放入新设置。
- `sysctl` 预加载文件通常存在的路径：
  - `/run/sysctl.d/*.conf`
  - `/etc/sysctl.d/*.conf`
  - `/usr/local/lib/sysctl.d/*.conf`
  - `/usr/lib/sysctl.d/*.conf`
  - `/etc/sysctl.conf`
- 在带有 Uncomplicated Firewall（简单防火墙）的系统上，可以在 `/etc/ufw/sysctl.conf` 中配置额外设置。
- `/etc/ufw/sysctl.conf` 中的设置将覆盖 `/etc/sysctl.conf` 中的设置。
- 可以通过更新 `/etc/default/ufw` 中的 `IPT_SYSCTL` 参数来更改此行为。

### 3.1 禁用未使用的网络协议和设备

为了减少系统的攻击面，应该禁用未使用的网络协议和设备。

Linux 内核模块支持几种不常用的网络协议。如果不需要这些协议，建议在内核中禁用它们。
