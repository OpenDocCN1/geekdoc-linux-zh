
## Description

`crypt` 加密和解密文件。

## 非交互式操作

在非交互式模式运行时，shell 不会从终端提示输入。非交互式 C shell 可以执行作为命令行参数提供的命令，也可以从文件（也称为脚本）中解释命令。

注意 — 当 shell 执行一个尝试执行不存在的命令解释器的脚本时，shell 会回传一个错误诊断消息，指明该 shell 脚本文件不存在。

## 选项

- `-b` 强制从选项处理中“中断”（break）。不要将后续的命令行参数解释为 C shell 选项。此选项允许向脚本传递选项而不会混淆。你必须使用此选项，否则 shell 将不会运行设置用户 ID（set-user-ID）或设置组 ID（set-group-ID）的脚本。
- `-c` 执行第一个参数（必须存在）。剩余参数被放置在 `argv`（即参数列表变量）中，并直接传递给 `csh`。
- `-e` 如果命令异常终止或产生非零退出状态。
- `-f` 为了快速启动，在启动时不读取 `.cshrc` 文件或 `.login` 文件（如果是登录 shell）。
- `-i` 强制交互式。即使标准输入看起来不是终端（字符特殊设备），也提示命令行输入。
- `-n` 解析（解释）但不执行命令。你可以使用此选项来检查 C shell 脚本的语法错误。
- `-s` 从标准输入读取命令。
- `-t` 读取并执行单行命令。你可以使用反斜杠 (`\`) 转义每个换行符，以便将命令行延续到后续输入行。
- `-v` 设置详细模式（verbose）预定义变量；在历史替换之后（其他替换之前）以及执行之前显示命令输入。
- `-V` 在读取 `.cshrc` 之前设置详细模式。
- `-x` 设置 echo 变量；在所有替换之后且执行执行之前显示命令。
- `-X` 在读取 `.cshrc` 之前设置 echo。

## csh

除了使用 `-c`、`-i`、`-s` 或 `-t` 选项外，将第一个非选项参数视为命令或脚本的名称。将其作为参数 0 传递，并将随后的参数添加到该命令或脚本的参数列表中。

## 使用方法

### 文件名补全

当你启用文件补全变量 `filec` 时，交互式 C shell 可以完成部分输入的文件名或用户名。当你输入无歧义的文件名开头按下 Escape 键时，shell 会填充工作目录中匹配文件的剩余字符。

如果你在部分文件名后紧跟 EOF 字符（通常输入为 Control-D 输入），shell 将再次列出所有匹配的文件名。它会向你提示，并用波号 (~) 补充不完整的命令行。

当最后一个（部分）单词以波号 (~) 开头时， shell 将尝试用用户名补全，而不是工作目录中的文件。

如果没有匹配或有多个匹配项，终端会蜂响。你可以通过设置 `nobeep` 变量关闭蜂响。你可以通过在 `ignore` 变量中列出某些后缀来排除这些后缀的文件。然而，如果唯一的补全是列表中的后缀，则不会被忽略。`ignore` 不影响通过 EOF 字符列出文件名。

## 词法结构

shell 将输入分为单词或在 Tab 字符处分隔，但另有注释。字符 `&`、`|`、`;`、`<`、`>`、 `(` 和 `)` 分隔单词；如果成对，则形成单个单词。这些元字符可以成为其他单词的一部分，通过在它们前面加反斜杠 (`\`) 可以抑制它们的特殊含义。空格 之前的换行符等同于空格字符。

此外，由匹配的单引号 (`''`)、双引号 (`"`) 或反引号 (\`) 包围的字符串形成一个单词；字符串中的元字符（包括任何空格或 Tab 字符）不会形成单独单词。在成对的反引号 (\`) 或双引号 (") 内部，前面有反斜杠 (`\`) 的换行符产生一个真正的换行符。每类型单词的附加功能请参见“变量替换”、“命令替换”和“文件名替换”中的描述。

当 shell 的输入不是终端时，字符 `#` 引入注释，并持续到输入行的末尾。当其前面有 `\` 或包含在匹配的引号中时，其特殊含义会被抑制。

注意 — 单词长度可以超过 1024 字节。系统限制参数列表为 1,048,576 字节。然而，用于文件名扩展的命令参数最大数量为 1,706。命令替换展开后的字符可能比参数列表允许的更多。为了检测循环，shell 限制单行别名（alias）替换的数量为 20 次。

## 命令行解析

一个简单命令由一系列单词组成。第一个单词（不是 I/O 重定向的一部分）指定要执行的命令。由 `|` 或 `|&` 字符分隔的一组简单命令形成管道（pipeline）。通过 `|`，前一个命令的标准输出被重定向到后续命令的输入。通过 `&|`，标准错误和标准输出都将通过管道重定向。

管道可以用分号 (`;`) 分隔，在这种情况下它们按顺序执行。由 `&&` 或 `||` 分隔的管道形成条件序列，其中管道的执行取决于管道的成功或失败。

管道或序列可以包含在括号 `( )` 内形成一个简单命令，该命令可以作为管道或序列中的组件。

一组管道可以通过附加符号符 `&` 异步执行或在“后台”执行；shell 不会等待序列完成才发布提示符，而是会显示作业号（参见“作业控制”）并提示。

## 历史替换

历史替换允许你使用以前命令中的单词。这简化了拼写修正和复杂命令的重复。

注意 — 历史替换中的 `g` (global) 标志仅适用于每个单词中的第一个匹配项，而不是所有单词。更多细节请参考 `history(1)`。

## csh

### 事件标识符

事件标识符是对历史列表中命令条目的引用。

- `!` 开始历史替换
- `!!` 引用上一个命令。该替换本身会重复上一个命令。
- `!n` 引用命令行。
- `-n` 引用减去 n 个当前命令行。
- `!str` 引用以 `str` 开头的最新命令。
- `!str` 引用包含 `str` 的最新命令。
- `!str? additional` 引用包含 `str` 的最新命令，并向所引用的命令追加 `additional`。
- `!(command) additional` 引用以 `command` 开头的最新命令，并向所引用的命令追加 `additional`。
- `^previous-word^replacement^` 重复命令行，将字符串 `previous-word` 替换为字符串 `replacement`。这等同于历史统计命令：`!/previous-word/replacement/`。

若要重新执行某个特定的上一个命令并进行此类替换，例如重新执行 #6：`!6/previous-word/replacement/`

### 单词标识符

冒号 `:` 分隔事件规范和单词标识符。如果单词标识符以 `^`、`*` 或 `%` 开头，可以省略它。如果需要从上一个命令中选择单词，则省略事件规范中的第二个 `:` 字符。例如，`!!:1` 和 `!:1` 都引用上一个命令的第一个单词，而 `!!$` 和 `$` 都引用上一个命令的最后一个单词。单词标识符指示：

- `#` 到目前为止输入的整个命令行。
- `0` 第一个输入单词（命令）。
- `n` 第 n 个参数。
- `^` 第一个参数，即 1。
- `$` 最后一个参数。
- `%` 由（最近的）`?` 搜索匹配的单词。
- `x-y` 单词范围；`-y` 简写为 `0-y`。
- `*` 所有参数，或者如果事件中只有一个单词，则返回空值。
- `x*` `r-$.` 的缩写。
- `x-` 类似于 `x*` 但省略了单词 `$`。

## 修饰符 (Modifiers)

在可选的单词标识符之后，你可以添加以下修饰符之一，前面加冒号（:）。

- `h` 移除末尾的路径名称组件，保留头部（head）。
- `r` 移除 .xxx 形式的尾后缀，保留文件名（basename）。
- `e` 移除后缀以外的所有内容，保留扩展名（extension）。
- `s/l/r/` 将 l 替换为 r。
- `t` 移除所有领先名称组件，保留尾部（tail）。
- `&` 重复上一次替换。
- `g` 通过前缀上述内容（例如 `g&`），将更改应用于每个单词中匹配的第一个项。
- `p` 打印新命令但不执行它。
- `q` 给替换的单词加引号，并对后续替换进行转义处理。
- `x` 类似于 `q`，但在每个空格字符、制表符或换行符处拆分为单词。

**注意** — 尽管可以在命令替换的输出上使用 : 修饰符，但在变量替换中使用 : 修饰符有两个问题：并不是所有的修饰符都可用，且每个替换只允许一个修饰符。

除非前面有 `g`，否则修改仅应用于第一个匹配 `l` 的字符串；如果没有匹配项的字符串，则会产生错误。

替换的左侧不是正则表达式，而是字符字符串。你可以使用任何字符代替 `/` 作为分隔符。使用反斜杠可以转义分隔符字符。右侧的字符 `&` 被替换为左侧的文本。你可以用反斜杠转义 `&`。空 `1` 使用来自 `l` 或通过上下文扫描 `s`（来自 `!?s`）的上一个字符串。如果 `r` 后面紧跟换行符，可以省略最右侧的分隔符；同样地，在上下文扫描中可以省略最右侧的 `?`。

在没有事件规范的情况下，历史引用指向上一个命令或命令行上的上一个历史引用（如果有的话）。

## 快速替换 (Quick Substitution)

`^1^^` 等价于历史替换 `:s/1/r/`
