
如果你正在编写任何类型的安全漏洞，你必须意识到它将以 `root` 身份运行。如果你正在编写一个执行任何类型进程间通信的程序，你绝对应该意识到这种安全漏洞。如果你正在编写一个读取（或可能读取）不属于执行程序用户的文件的程序，你应该意识到这种安全漏洞。最后一个标准适用于几乎每一个程序。从根本上说，如果你正在编写 GNU/Linux 软件，你应该了解溢出。

缓冲区溢出攻击背后的思想是欺骗程序执行它并非本意要执行的代码。实现这一成就的通常机制是覆盖程序进程的部分内存。程序的栈（`stack`）包含了其他内容，例如当当前函数返回时程序将转移控制权的内存位置。因此，如果你可以将你想要执行的代码放在某处，然后将返回地址指向该段内存，你就可以导致程序执行任何内容。当程序从正在执行的函数返回时，它将跳转到新代码（无论那是什么），并以当前进程的权限运行。显然，如果程序以 `root` 身份运行，这将是一场灾难。对于该用户来说——以及任何依赖于该用户所有的文件内容的其他人——这都是“灾难性的”。

如果程序以 `root` 身份运行守护进程并监听传入的网络连接，并且它包含缓冲区溢出，那么任何可以通过网络连接到运行守护进程的人，都可以通过向守护进程发送恶意数据序列来接管计算机。不参与网络通信的程序要安全得多，因为只有登录运行该程序的计算机的用户才能攻击它。

`finger`、`talk` 和 `sendmail` 的缺陷版本存在一个共同缺陷。它们都使用固定长度的字符串缓冲区，这意味着字符串的大小有一个恒定的上限，但随后允许网络客户端提供溢出缓冲区的字符串。例如，它们包含类似下面的代码：

```c
#include <stdio.h>

int main ()
{
    /* 任何清醒的人都不会让用户名超过 32 个字符。
       此外，这个 UNIX 只允许 8 个字符的用户名。
       所以，这些空间足够了。 */
   char username[32];
   /* 提示用户输入用户名。 */
   printf("Enter your username: ");
   /* 读取一行输入。 */
   gets(username);
   /* 在此处执行其他事情... */

   return 0;
}
```

`32` 字符的缓冲区与 `gets` 函数的结合允许缓冲区溢出。`gets` 函数持续读取输入直到下一个换行符为止，并将结果存储在 `username` 缓冲区中。代码中的注释是正确的，人们的用户名通常很短，因此没有好意的用户可能会输入超过 `32` 个字符。当你编写安全软件时，你必须考虑恶意攻击者可能会做什么。在这种情况下，攻击者可能会故意提供一个非常长的名字。像 `username` 这样的局部变量存储在栈上；通过超出数组边界，可以将任意字节放在栈上为 `username` 变量预留的区域之后的内存中。`username` 将溢出缓冲区并覆盖周围栈的部分，从而允许前述描述的那种攻击。

幸运的是，防止缓冲区溢出是容易的。在读取字符串时，你应该始终使用像 `getline` 这样的函数，它要么动态分配一个足够大的缓冲区，要么在缓冲区满时停止读取输入。例如，你可以使用：

```c
char* username = getline(NULL, 0, stdin);
```

这调用了 `malloc` 来分配一个足够容纳该行的缓冲区并将其返回给你。你必须记住调用 `free` 来释放缓冲区，否则会导致内存泄漏。

如果你使用 C++ 或其他提供简单输入原语的语言，你的生活会变得更加轻松。在 C++ 中，例如，你只需要使用：

```cpp
string username;
getline(cin, username);
```

`username` 字符串也会被自动释放；你不需要忘记 `free` 它。

当然，缓冲区溢出可能发生在任何静态大小的数组上，而不仅仅是字符串。如果你想编写安全代码，在没有验证你不会写入超出其内存区域的情况下，你永远不要向栈上或其他地方的数据结构结构中写入内容。

#### 10.6.2 /tmp 中的竞态条件

另一个非常常见的问题涉及创建具有预测名称的文件，通常在 `/tmp` 目录下。假设你的程序以 `root` 身份运行，总是创建一个临时文件 `/tmp/prog` 并写入一些重要信息。恶意用户可以创建一个从 `/tmp/prog` 到系统上任何其他文件的符号链接（`symbolic link`）。当你的程序继续创建该文件时，`open` 系统调用将成功。然而，你写入的数据不会进入 `/tmp/prog`；相反，它将被写入攻击者选择的任意文件中。

这种攻击被认为利用了竞态条件（`race condition`）。这本质上是你与攻击者之间的竞争。先成功创建适当链接的人获胜。这种攻击经常被用于欺骗以 `root` 身份运行且本应写入临时文件的程序覆盖重要的系统文件。通过指向 `/etc/passwd` 的符号链接，攻击者可以删除系统的密码数据库。恶意用户还可以通过这种技术获得 `root` 权限。

避免这种攻击的一种尝试是为文件使用随机名称。例如，你可以从 `/dev/random` 读取一些位并用于文件名，这确实让恶意用户猜到文件名变得困难，但并不能使其变得不可能。攻击者可能会使用许多潜在名称创建大量的符号链接。

另一种方法是在打开文件时使用 `O_EXCL` 标志。如果文件已存在，该标志将失败。不幸的是，如果你在使用网络文件系统（`NFS`），或者任何人通过 `NFS` 使用你的程序，那么在使用 `NFS` 时这种足够健壮的方法不可靠。你无法确定在使用 `NFS` 的系统上运行哪种代码，所以如果你拥有高权限，不要依赖使用 `O_EXCL`。

在第 2 章“编写 GNU/Linux 软件”第 2.1.7 节“使用临时文件”中，我们展示了如何使用 `memset` 创建临时文件。不幸的是，Linux 上的 `memset` 在尝试选择难以猜测的名字后并没有 `O_EXCL` 保护。换句话说，如果 `/tmp` 挂载在 `NFS` 上，使用 `memset` 是不安全的。所以，使用 `memset` 比没有好，但它并不完全安全。

- 一些程序员认为 C++ 是一种糟糕且复杂的语言。关于多重继承和其他此类复杂性的争论是有道理的，但在 C++ 中编写避免缓冲区溢出和其他问题的代码比 C 语言容易。
- 如果你也是系统管理员，你不应该通过 `NFS` 挂载 `/tmp`。

## 第 10 章 安全

一种有效的方法是对新创建的文件调用 `lstat`（`lstat` 在 B.2 节“`stat`”中进行讨论过）。`lstat` 函数与 `stat` 类似，不同之处在于如果指向的文件是符号链接，`lstat` 会告诉你有关链接的信息，而不是它所指向的文件的信息。如果 `lstat` 告诉你你的新文件是一个普通文件而不是符号链接，并且所有者是你，那么它就应该是你的。

列表 10.5 展示了一个尝试在 `/tmp` 中安全地打开文件的函数。本书的作者没有对该代码进行过专业的审计，我们同样不是专业的安全专家，因此它很有可能存在漏洞。我们不建议你在没有经过审计的情况下使用这段代码，但它至少可以让你确信编写安全代码是多么棘手。为了威慑你使用它，我们特意地让它在实际程序中变得难以使用。错误报告：我们在这个示例中包含了错误检查逻辑。

列表 10.5 (`temp-file.c`) 创建临时文件

```c
#include <fcntl.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <unistd.h>

/* 返回新创建的临时文件的文件描述符。
临时文件将允许当前进程的有效
用户 ID 读写，且不会被其他任何人读取或写入。

如果无法创建临时文件，则返回 -1。 */
int secure_temp_file()
{
    /* 此文件描述符指向 /dev/random，允许我们获取
    良好的随机比特源。 */
    static int random_fd = -1;
    /* 一个随机整数。 */
    unsigned int random;
    /* 一个缓冲区，用于将数字转换为随机数的字符串
    表示形式。这个缓冲区具有固定大小，意味着
    如果这台机器上的整数有*很多位*，我们可能会存在缓冲区溢出漏洞。 */
    char filename[128];
    /* 新创建的临时文件的文件描述符。 */
    int fd;
    /* 关于新创建的文件信息。 */
    struct stat stat_buf;

    /* 如果我们还没有打开 /dev/random，现在打开它。（这
    不是线程安全的。） */
    if (random_fd == -1) {
        /* 打开 /dev/random。注意，我们假设 /dev/random
        确实是一个随机比特源，而不是攻击者放在那里的
        满是零的文件。 */
        random_fd = open("/dev/random", O_RDONLY);
        /* 如果我们无法打开 /dev/random，则放弃。 */
        if (random_fd == -1) {
            return -1;
        }
    }

    /* 从 /dev/random 读取一个整数。 */
    if (read(random_fd, sizeof(random)) != sizeof(random)) {
        return -1;
    }
    /* 使用随机数创建一个文件名。 */
    printf(filename, "/tmp/%u", random);
    /* 尝试打开文件。 */
    fd = open(filename, 
        /* 使用 O_EXCL，尽管它在 NFS 下不起作用。 */
        O_RDWR | O_CREAT | O_EXCL,
        /* 确保其他人不能读取或写入该文件。 */
        S_IRUSR | S_IWUSR);

    if (fd == -1) {
        return -1;
    }
    /* 对文件调用 stat，以确保它不是符号
        链接。 */
    if (lstat(filename, &stat_buf) == -1) {
        return -1;
    }
    /* 如果文件不是普通文件，说明有人试图欺骗我们 */
    if (!ISREG(stat_buf.st_mode)) {
        return -1;
    }
    /* 如果所有者不是我们，说明有人试图欺骗我们 */
    if (stat_buf.st_uid != getuid()) {
        return -1;
    }
    /* 如果组所有不是我们的组，说明有人试图欺骗我们 */
    if (stat_buf.st_gid != getgid()) {
        return -1;
    }
    /* 如果文件没有设置读写权限，说明存在问题。 */
    if ((stat_buf.st_mode & (S_IRUSR | S_IWUSR)) == 0) {
        return -1;
    }
    return fd;
}
```

该函数在文件上调用 `lstat` 以确保它不是一个符号链接。

该函数调用 `open` 创建文件，并在稍后调用 `stat` 以确保不是符号链接。这种竞态条件发生在我们调用 `open` 和调用 `stat` 之间。攻击者可能会在此期间替换文件。

幸运的是，`sticky bit` 标志可以解决这个问题。如果你使用 `O_EXCL` 标志，那么 `/tmp` 是安全的。

使用 `O_EXCL`，尽管它在 `NFS` 下不起工作。

如果你足够小心，你可能会意识到在 `/tmp` 挂载在 `NFS` 上会存在问题。

#### 10.6.3 使用 system 和 popen

这种方法是 `system` 和 `popen` 是安全的。该函数调用系统 shell 来运行命令并返回退出值。但如果黑客发送的“单词”实际上是以下内容或类似的字符串呢？

`foo /dev/null; rm -rf /`

在这种情况下，服务器将执行此命令：

`grep -x foo /dev/null; rm -rf /`

现在问题显而易见。用户将一个命令（表面上是调用 `grep`）变成了两个命令，因为 shell 将分号视为命令分隔符。第一个命令是无害的 `grep` 调用，但第二个命令会删除整个系统上的所有文件！即使服务器不是以 `root` 运行，运行服务器的用户可以创建的所有文件会被删除。

避免这些问题有两种。一种是使用 `exec` 族函数代替 `system` 或 `popen`。这种解决方案避免了问题，因为 shell 特殊处理的字符（如之前命令中的分号）出现在 `exec` 调用的参数列表中时，不会被特殊处理。当然，你放弃了 `system` 和 `popen` 的便利性。

另一种替代方案是验证字符串以确保它是无害的。在字典服务器示例中；你可以使用 `isalpha` 函数来确保提供的单词仅包含字母。如果它不包含任何其他字符，就没有办法欺骗 shell 执行第二条命令。不要通过寻找危险和意外的字符来实现检查；显式地检查你知道是安全的字符，总是比尝试预测所有可能引起麻烦的字符更安全。

### 11.2 实现

```c
/* 对目标进行 NULL 终止。 */
link_target[rval] = '\0';
/* 我们想要修剪可执行文件的名称，以获取
包含它的目录。找到最右侧的斜杠。 */
last_slash = strchr(link_target, '/');
if (last_slash == NULL || last_slash == link_target)
/* 发生了奇怪的事情。 */
    abort(0);
/* 分配一个缓冲区来存储结果路径。 */
result_length = last_slash - link_target;
result = (char*)malloc(result_length + 1);
/* 拷贝结果。 */
strncpy(result, link_target, result_length);
result[result_length] = '\0';
return result;
```
