## 2.8 滑动窗口 (Sliding Windows)

数据链路协议的重要功能之一是提供面向连接或可靠的传输服务。可靠服务通过重传丢失或损坏的数据包来保证按顺序交付。在本章的其他地方，我们讨论了多种通信协议。这些协议中的一些用于承载 IP 数据报文，如果是这样，它们将在链路层与 IP 接口。然而，重要的是，TCP/IP 在链路层不需要面向连接的服务。TCP 传输协议实际上包含了自己的滑动窗口，理论上与本节描述的协议几乎相同，但其状态机要复杂得多。此外，我们看到 TCP 有许多增强，如慢启动以减少网络拥塞。

滑动窗口提供了恢复丢失、错误或乱序帧的方法。早期的协议必须使用停止-等待确认系统来管理连接的完整性。这种系统浪费了带宽，因为发送站在发送另一帧之前必须等待确认。相反，滑动窗口提供了更好的确认机制。接收站提供累积确认。这更有效，因为接收站可以确认发送站的多个数据包，发送站不需要在发送更多帧之前等待确认。当与队列结合使用时，这种方法可以提供优秀的流量控制机制。大多数现代通信协议都从某种程度上源自滑动窗口的方法。

滑动窗口方法的窗口大小由特定 HDLC 变体的序列号 `n(s)` 和确认号 `n(r)` 字段决定。窗口大小是在接收确认帧之前可以发送的未确认传输帧的数量。最初，HDLC 在信息格式帧和主导格式帧中为序列和确认字段保留了 3 位，允许窗口大小为 7。HDLC 的后期变体增加了此宽度，从而增加了窗口大小。图 2.4 展示了 HDLC 滑动窗口的典型序列。在每个传输帧中，`n(s)` 字段设置为连续序列号。发送站通过发送 `r` 设置为接收帧中 `n(s)` 下一个值的确认帧来响应。

## 2.9 PPP 中使用的 HDLC

点对点协议 (PPP) [RFC 1661] 广泛用于串口链路上的 TCP/IP 流量。在本节中，我们感兴趣它是如何对 HDLC 进行帧封装。PPP 通常用于调制解调器和其他链路，但也以 PPPoE 的形式广泛用于以太网。由于 PPP 不提供 X25 的错误纠错功能，它使用了一种名为链路访问协议 (LAPB) 的 HDLC 版本。LAPB 通过增加 `n(s)` 和 `n(r)` 字段增加了窗口大小。这规定了在接收 ACK 之前可以传输多少数据包。

此外，PPP 通过设置 `p/f` 字段为 1 允许对端立即响应。记住 `p/f` 字段有两个含义，一个用于命令包，一个用于响应。在命令包中，它被称为 `p` 位，在响应中它被称为 `f` 位。例如，考虑以下序列：如果接收站在帧中检测到错误，它可以向对端发送一个 `REJ` 包，其 `n(r)` 设置为错误帧的序列号，并将 `p` 位设置为 1。滑动窗口意味着之前收到的 `n(s)` 值大于 `n(r)` 的所有帧都被拒绝。发送站随后可以重新发送被拒绝的帧。

## 2.10 帧中继传输服务 (Frame Relay Bearer Service)

正如第 2.6 节所述，X25 的缺点是多个层都有错误纠错。帧中继服务 (FR) 最终取代了公网上大部分数据流量的 X25。因为 X25 是为了低质量物理链路设计的，在第 2 层和第 3 层进行错误检查和纠正是合适的。帧中继消除了额外的错误纠错层；它旨在比早期基于铜的传输电路更可靠的 PHY。额外纠错的消除使得 FR 对于如 OC-3 光链路的高数据速率优于 X25。需要指出，TCP/IP 流量不需要链路层的可靠服务。TCP 协议在传输层具有自身的错误检查和纠正。

帧中继的 PHY 支持 DS0、DS1、DS3、E1 和 E3（这些速率在第 1 章所示）。FR 的帧层使用链路访问协议封装 (LAPF)。其封装与 X25 使用的 HDLC 封装相似，但更简单，因为 FR 不提供 X25 数据包层协议部分的错误纠错。请见图 2.5 中 FR 使用的所有类型帧的封装细节。与 HDLC 一样，FR 帧之前由一个 0 位后跟五个连续 1 位组成标志位，其值为 `0x7e`。该标志位用于指示帧的开始。帧也以一个具有相同 `0x7e` 值的类似标志位结束。`0x7e` 的原因是它用于区分控制数据，负载数据，以及与 HDLC 中使用的位填充技术类似的检测错误。关于基础 HDLC 和位填充的更多细节，请参见第 2.5.4 节。表 2.10 显示了帧中继（FR）的帧格式。
