# infxtract — 将内核探针输出到跟踪文件

### 概要

```
/usr/bin/infxtract [-d dumpfile -n namelist1] tnf_file
```

## 描述

`infxtract` 命令从 Solaris 内核的内核缓冲区或从崩溃系统的内存映像中收集内核跟踪输出，并生成类似于用户程序直接跟踪时产生的二进制跟踪标准格式 (`TNF`) 跟踪文件。

你必须同时指定或都不指定 `-d` 和 `-n` 。如果两个都不指定，则从运行的内核中提取跟踪输出。如果两个都指定了，`-d` 参数指定包含（崩溃的）系统内存映像的文件名，而 `-n` 参数指定包含系统内存映像符号表的文件名。

生成的 `TNF` 跟踪文件与内核缓冲区的大小完全相同；它本质上是该缓冲区的快照。在内核跟踪激活且内核缓冲区正在被写入时运行 `infxtract` 是允许的。`infxtract` 确保其生成的输出文件是底层一致的，也就是说，只写入探针，缓冲区中的内部数据结构不会因为缓冲区正在并发写入而损坏。

生成的 `TNF` 跟踪文件适合作为 `tnfdump(1)` 的输入，后者会生成 ASCII 文件。

## 选项

- `-d` `dumpfile`
使用 `dumpfile` 作为系统内存映像，而不是运行中的内核映像。`dumpfile` 通常是由 `savecore` 命令生成的文件路径。

- `-n` `namelist`
使用 `namelist` 作为包含给定 `dumpfile` 符号表的文件。

### 操作数

`tnf-file` 指定根据 Solaris 内核内核缓冲区中的跟踪输出由 `tnfract` 生成的输出文件。

## 示例

以下示例从运行的内核探针到 `ktrace.out`。
`caste# tnfract ktrace.out`

以下示例从内核崩溃转储探针到 `ktrace.out`。
`caste# tnfextract -d/var/crash/`uname -n`vmcore.0 -n/var/crash/`uname -n`/unix.0 ktrace.out`

## 退出状态

- 0 成功完成。
- >0 发生错误。

## 属性

参见 `attributes(5)` 获取以下属性的描述：

| 属性类型 | 属性值 |
| :--- | :--- |
| 可性 | SUNWtnfc |

## 参见

`touch(1)`, `tnfdump(1)`, `savecore(1)`, `attributes(5)`

# touch — 修改文件访问时间和时间

### 概要

`/usr/bin/touch [-acm] [-r file] time...`
`/usr/bin/touch [-acm] time file...`

## 描述

使用 `touch` 命令更改访问时间和修改时间。如果文件不存在，则创建它。结果的时间受 `TZ` 环境变量的影响。如果你没有指定这些选项之一，则使用当前时间。

## 选项

- `-a` 修改文件的访问时间。
- `-m` 修改文件的修改时间。
- `-c` 如果文件已存在，则不创建文件。
- `-r` `file` 引用现有文件的对应时间。
- `-t` `time` 使用指定的时间而不是当前时间。
