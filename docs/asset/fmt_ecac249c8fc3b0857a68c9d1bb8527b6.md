
**注意：** 每个 ISP 对缓存什么以及缓存多长时间都有不同的“规则”。有些遵循之前列出的所有规则，而有些则条都不遵守。更糟糕的是，某些 ISP 偶尔会*更改*它们的缓存规则。如果你担心你的内容被保存在代理缓存中，你应该定期测试，以查看你的内容是否被该 ISP 缓存了。

## 分析工具

正如你在本章开头看到的，你可以使用各种文本处理工具手动分析日志。然而，这种分析会变得枯燥，而且难以维护。为了从你的 Web 服务器日志中获得最有用的数据，你可能想要投入时间和金钱来选择、安装和使用 Web 服务器分析工具。

### 选择分析工具。

市场上真的有成百千种分析工具，从简单的免费 PERL 脚本到复杂的数据库驱动应用程序。因为市场还非常新，很容易对你的应用程序具体需要哪些功能感到困惑。在选择分析工具之前，请确保你了解：

- 你打算执行什么种的分析。
- 你偏好什么种输出格式。
- 你需要该工具提供什么样的企业支持。
- 你打算使用什么平台。
- 你的日志文件将有多大。

### 分析类型

在评估分析程序时，问自己最重要的问题是“到底在寻找什么信息？”如果你只是在寻找基本的访问分析，例如特定时间内的访问量或基本的 Web 人口统计数据，那么几乎任何分析程序都足够了。

随着你的需求变得更加复杂，你需要确保你的软件包支持高级分析功能。通常，路径分析（pathing）和会话分析（sessioning）等高级功能仅在花费数百美元的商业软件包中可用。

### 输出质量

分析程序在报告输出的整体吸引力上差异很大。几乎所有程序都创建 HTML 作为主要格式，许多程序还会创建图表。如果你打算将报告分发给客户或投资者，请考虑使用提供更好布局的高软件包。

### 企业支持

大多数分析程序是为单服务器设计的。它们期望只读取一个日志文件。如果你的网站跨越多个服务器，或者你管理着几个不同的网站，你可能想要获取一个分析软件包。具有“企业支持”的分析程序可以处理多个日志文件，并构建代表多个网站的报告。这种支持通常出现在昂贵的软件包中。

### 平台

并不是所有的分析程序都适用于所有的 UNIX 版本，许多仅适用于 Windows。如果你要在与服务器相同的机器上运行分析，你需要确保你的分析程序与之兼容。

你不一定要在与服务器相同的机器上运行分析程序。事实上，拥有一专门用于此任务的机器可能是理想的。分析会对机器性能产生巨大影响，影响 CPU 占用和磁盘使用。如果你为日志分析专门准备一台机器，那么你可以获取硬件来支持你喜欢的软件。

### 速度

随着你的访问日志迅速增长到几兆字节，分析速度变成了一个问题。检查你的分析程序声称处理大文件有多快：大多数供应商会提供以每分钟处理兆字节计算的指标。

日志处理速度并不总是线性增长的：随着日志变大，某些分析程序会越来越慢。在投资昂贵的处理程序之前，在真实的日志上测试性能——并注意有些最快的程序是免费软件。

## 常用工具

分析程序的价格差异很大，但它们通常属于三类之一：免费工具、单站点商业产品和企业商业软件包。

## 总结

在本章中，你学习了如何跟踪 Web 服务器的使用情况。这些数据主要存储在访问日志和错误日志中，提供了帮助你在 Web 网站上进行扩展、编程和广告的信息。

访问日志跟踪每次尝试请求，并为你提供大部分的服务器活动信息。扩展日志帮助你跟踪哪些浏览器最常用于访问你的网站，以及哪些网站向你传递了最多的流量。

基础分析包括以多种不同的方法计算访问日志中的条目。你能够收集的最简单统计数据是不同类型访问的摘要，包括成功和失败。查看小时、日和月报告中随时间变化的流量也是很有用的。最后，日志还为你提供了关于访问者有限的“人口统计学”信息，例如他们所在的国家，以及他们是来自商业机构还是教育机构。

高级分析涉及寻找访问中的模式。会话（Sessioning）是识别唯一访问并确定访问持续时间和特征的过程。路径分析（Pathing）是寻找用户在访问期间采取的最常见导航路径。

遗憾的是，访问日志并不一定是可靠的数据源。几个因素会影响你日志的准确性，最重要的是缓存。本地缓存和代理缓存都可能导致你的日志数字被低估。

最后，你学习了数种可用的工具，以帮助你分析服务器活动。许多工具可以在互联网上免费获得，而另一些是包含支持和升级的商业产品。有些公司会按月付费，为你下载、审计并处理日志。

# 版本控制简介

*Eric Goebelbecker*

网站、编程项目，甚至网络都围绕着文件集合展开。这些文件中的许多依赖于存储在其他文件中的信息，例如超文本链接的目标、函数的参数，或网络名称和地址。这些关系可能非常难以管理，特别是当有多人参与或当小项目演变为大型系统时。

UNIX 系统上常用的管理这些关系的工具之一是*版本控制*系统（也称为*源码控制系统*；本章将交替使用这两个术语）。这些系统允许个人（或小组）跟踪对一组文件所做的更改，快速准确地撤销一组更改，并维护关于为何更改的审计轨迹。

本章将探索系统的特性以及如何使用它们。本章将：

- 解释什么是版本控制以及它的用途
- 演示核心概念，例如检入（checking in）和检出（checking out）
- 解决（并防止）多人引起的冲突
- 将不同文件的版本链接在一起

由于这是原始文件，它被称为*修订树*的*根*节点。它通常被标记为版本 1.1。

版本控制系统允许在文件注册或*检出*（check out）时覆盖这些数字（我们将在下一节解释如何以及何时检出文件）。
