
### 7.13 cron 和 crontab：定期运行任务

`ps -e` 命令显示 `cron` 守护进程正在运行。这是 UNIX 系统的时钟，每分钟滴答一次。`cron` 不是像 `at` 那样的一次性调度器，而是周期性调度器。它每分钟从睡眠状态醒来，查找 `crontab` 文件以在该刻执行的指令。执行后，它进入睡眠，直到下一分钟醒来。

`crontab` 文件以用户 ID 命名并位于 `/var/spool/cron/crontabs`。然而，该位置取决于系统。`romeo` 是该目录下同名的文件。每个安排的任务都指定为文件中的单行。规范可能会变得有点复杂，但让我们从第 7.2 节开始。

行中有六个字段，第一个字段完全决定了命令执行的频率。以下列表显示了各字段的含义，括号内为允许的值：

- 1 分钟 (0 到 59)
- 2 小时 (0 到 23)
- 3 日 (1 到该月的最大天数)
- 4 月份 (1 到 12)
- 5 星期 (0 到 6，0 代表星期日)
- 6 要运行的命令

这条 `find` 命令将在每年 6 月 30 日的 18:15 运行。我们没有使用第五字段（在这里意义并不大），并倾向于在该处选择一个 `*`。与 `at` 命令一样，在没有重定向的情况下，命令的标准输出将发送给用户。

要创建一个 `crontab` 条目，首先使用你的 `vi` 编辑器创建一个包含你选择条目的文件 `foo`。然后使用 `crontab` 命令：

```bash
crontab foo
```

将该条目放入 `/var/spool/crontab` 目录。你可以通过 `crontab -l` 查看 `crontab` 文件的内容，并通过 `crontab -r` 将其删除。

如果你使用 `crontab` - 通过标准输入提供输入并决定取消；你应该使用适用于你终端的中断键来终止它，而不是 `Ctrl-d`。如果你忘记了这一点，你将删除现有 `crontab` 文件中的所有条目！

`cron` 在其不寻常的数字匹配系统中具有特殊规则。如果你记住这些规则，就可以匹配一个或多个数字：

- 在前五个字段中使用的 `*` 匹配任何有效值。
- 数字组由逗号分隔，`3,6,9` 是一个有效的字段规范。
- 支持范围，且不需要限制为单个数字。`0-19` 包含了 0 到 19 之间的所有整数值。

当 `crontab` 文件之间发生冲突时，情况就会变得复杂。例如，看此例：

```bash
0-10 17 * 3,6,9,12 5 find / -name last_time -print > backuplist
```

前两个字段表示命令将在 17:00 到 17:10 之间的每分钟运行。第三字段（为 `*`）指定它应该每天运行。第四字段（`3,6,9,12`）将操作限制在年的四个月内。第五字段将执行限制在周五。

那么，到底听谁的？在这里，“周五”优于“每天”。`find` 命令将在下午 5 点后前 10 分钟内的每分钟、且在 3 月、6 月、9 月和 12 月（每年）的每个周五执行。

但是，决定哪些字段具有最终优先权的规则又是什么？当在第三、第四或第五字段中出现 `*` 时，这个问题就会产生。POSIX 明确规定了这些规则，表 7.4 显示了这些字段的所有可能组合。

#### 表 7.4 示例 crontab 条目（仅前五个字段）

| 字段 | 匹配结果 |
| :--- | :--- |
| `0-10 17 * * *` | 每天 |
| `0-10 17 * 3,6,9,12 *` | 每天，但限制在四个月 |
| `0-10 17 1,3 * *` | 每月三天 |
| `0-10 17 * * 1` | 周一 |
| `0-10 17 * 3,6,9,12 5` | 周五（根据文本推断） |

## 第 8 章：Shell——自定义环境

Shell 与其他程序不同。除了解释元字符外，它还是一个环境。

### 8.2 环境变量

Shell 变量分为两种：本地变量和环境变量。`PATH`、`HOME` 和 `SHELL` 是环境变量。它们之所以被称为环境变量，是因为它们在用户的整个环境中都可用——包括运行 shell 脚本的子 shell、邮件命令和编辑器。局部变量的作用范围限制较小，如下例所示：

```bash
$ DOWNLOAD_DIR=/home/romeo/download
$ echo $DOWNLOAD_DIR
/home/romeo/download
```

`DOWNLOAD_DIR` 是一个局部变量；它的值对子进程不可用。使用 `bash` 运行一个 Bash 子 shell 并检查是否能看到该变量：

```bash
$ bash
$ echo $DOWNLOAD_DIR

$ echo $PATH
/bin:/usr/bin:/usr/ccs
$ exit
```

> 创建一个子 shell
>
> `DOWNLOAD_DIR` 在子 shell 中可见吗？
>
> 不可见！
>
> 但 `PATH` 可见吗？
>
> 可见！
>
> 退出子 shell
>
> 回到登录 shell

`set` 语句显示当前 shell 中所有可用变量，但 `env` 命令只显示环境变量。以下是列表：

```bash
$ env
HOME=/home/romeo
IFS='
'
LOGNAME=romeo
MAIL=/var/mail/romeo
MAILCHECK=60
PATH=/usr/bin:/usr/ccs
PS1='$'
PS2='>'
SHELL=/usr/bin/bash
TERM=xterm
```

按照惯例，环境变量名定义为大写，尽管并没有限制使用其他方案。`env` 是一个外部命令，在子进程中运行。它只列出从父进程（即 shell）继承的变量。而 `set` 是内置命令，会显示当前 shell 中的所有变量。`set` 会显示 `DOWNLOAD_DIR` 的值，但 `env` 不会。

应用程序经常通过这些环境变量获取进程环境信息。`vi` 会读取 `TERM`，而 `mailx` 未设计为从特定的 shell 运行，因此环境变量始终以 `name=value` 的格式提供信息。然而，它们在不同的 shell（如 C shell）中可能会有不同的赋值方式。

#### 8.2.1 export：创建环境变量

为了让 `DOWNLOAD_DIR` 在所有子进程中可见，需要对其进行导出。我们在第 7 章已经用过 shell 的 `export` 语句来实现变量继承。`export` 仅仅是将一个局部变量转换为环境变量：

```bash
export DOWNLOAD_DIR
```

`export` 语句可以在赋值之前或之后使用。你也可以在同一个语句中执行操作：

```bash
export DOWNLOAD_DIR=/home/romeo/download    # 在 Bourne shell 中不起作用
```

> 你不能在一个语句中同时进行导出和赋值。请使用分开的语句：`x=5 ; export x`。

以上适用于 Bourne Shell。

变量通过 `set` 进行赋值、导出和显示的方式不同，但 `env` 则不同。这里没有 `export` 语句；C Shell 使用 `setenv` 语句同时完成赋值和导出变量。见第 8.10.1 节。

### 8.3 环境变量详解

环境变量控制系统的行为（表 8.1）。如果设置不当，你可能无法在不带路径的情况下使用某些命令、在远程连接上使用 `vi` 或在收到邮件时获得通知。如前所述，这些变量中的许多都被导出了并供 shell 使用。

#### 表 8.1 常用环境变量

| 变量 | 意义 |
| :--- | :--- |
| `HOME` | 用户的主目录 |
| `PATH` | shell 搜索的目录列表 |
| `LOGNAME` | 登录名 |
| `USER` | 用户 |
| `MAIL` | 邮件位置 |
| `MAILCHECK` | 检查新邮件的间隔 |
| `MAILPATH` | shell 检查的文件列表 |
| `TERM` | 终端类型 |
| `PWD` | 当前目录 |
| `CDPATH` | `cd` 时搜索的目录 |
| `PS1` | 主提示符字符串 |
| `PS2` | 副提示符字符串 |
| `SHELL` | 登录 Shell |

#### 命令路径（PATH）

`PATH` 是 shell 搜索的目录列表。

```bash
$ echo $PATH
/bin:/usr/bin:/usr/ccs
```

#### 主目录（HOME）

当你登录时，shell 将你置于主目录。提示符显示 `HOME` 变量：

```bash
$ echo $HOME
/home/romeo
```

#### 邮件位置与检查（MAIL, MAILCHECK, MAILPATH）

`MAILPATH` 代表冒号分隔的文件列表。这里有一个显示 `$HOME/mail` 的示例：

```bash
$ echo $MAILPATH
/home/romeo/mail
```

`MAILCHECK` 决定 shell 如何检查 `MAILPATH` 中定义的文件是否有新邮件。如果 shell 发现自上次检查以来文件被修改过，它会通知用户：`$HOME/mail` 有新邮件。

#### 提示符字符串（PS1, PS2 和 PWD）

Shell 使用两个提示符。主提示符 `PS1` 是你通常看到的。多行命令由 shell 以 `>` 前缀显示：

```bash
$ find -name a.out -mtime +365 \
> -exec rm {} \;
```

副提示符存储在 `PS2`。虽然 `PS2` 通常是 `>`，但你的系统可能使用 `$` 作为 `PS1`。要使用不同的主提示符，请更改 `PS1`：

```bash
$ PS1="C> "
C> 像 DOS 的提示符
```

Bash 还可以通过嵌入 `PWD` 变量在提示符中显示当前目录。当你更改目录时，提示符也会改变：

```bash
$ PS1='[$PWD] '  # 必须使用单引号
[/home/romeo] $ cd /etc
[/etc] $         # 提示符改变；当前目录为 /etc
```

`PWD` 是一个相当特殊的变量；它每次工作目录更改时都会重新求值。有了这样的提示符，你真的不需要使用 `pwd` 命令了。

当你在本地机器和远程机器上同时工作时，你可能需要使用 `uname -n` 命令来识别登录的机器。Bash 在 `PS1` 中支持许多转义序列，如果你这样设置 `PS1`，你就知道自己在哪里：

```bash
$ PS1="\h> "
saturn>  # saturn 是机器名
```

转义序列 `\h` 显示机器的主机名。你也可以添加 `PWD` 以获得额外好处。查看 Bash 文档以获取其他转义序列。

| Shell 类型 | 说明 |
| :--- | :--- |
| Bourne Shell | 除转义序列外，所有内容均适用。 |
| Korn Shell | 除转义序列外，所有内容均适用。 |
| C Shell | 参见第 8.10.1 节。 |

#### 目录搜索路径 (CDPATH)

`CDPATH` 允许你在使用 `cd` 导航到某些目录时避免使用完整路径名。考虑此设置，它包含了当前目录和 romeo 目录：

```bash
CDPATH=.:..:/home/romeo
```

使用 `cd` 时，shell 会搜索三个目录——以此查找目录。现在想象在你的当前目录下有两个目录，`include` 和 `lib`，而你刚刚进入了 `include`。由于 `CDPATH` 包含了父目录，你不需要使用 `cd ../lib` 来进入 `lib` 目录：

```bash
$ pwd
/home/romeo/include
$ cd lib; pwd
/home/romeo/lib
```

当你使用 `cd lib` 时，shell 首先在当前目录查找 `lib`，如果查找失败，它会搜索父目录 (`..`)，然后是 `/home/romeo`。请确保你始终在 `CDPATH` 中包含当前目录 (`.`)，否则会抑制 `cd` 的正常行为。

#### 被 Shell 转义的命令使用 (SHELL)

`SHELL` 显示你的登录 shell（不一定是你正在使用的 shell）。像 `more` 和 `vi` 这样的程序提供了 Shell 转义，让你能够运行 UNIX 命令。`SHELL` 决定了它们使用的 shell。

#### 终端类型 (TERM)

`TERM` 指示你正在使用的终端类型。每个终端都有特性，这些特性定义在 `terminfo` 目录下的控制文件中（`/usr/lib` 或 `/usr/share/lib`）。该目录包含许多以字母表命名的子目录。终端的控制文件位于一个单字母命名的目录中，该字母与终端名称的首字母相同。例如，`vt100` 使用文件 `/usr/share/lib/terminfo/v/vt100`。
