HTTP 消息使用标准的 ASCII 请求进行格式化，并以回车和换行符结束。HTTP 应用使用两种定义的消息类型：消息请求和消息响应。

请求从 Web 客户端发送到 Web 服务器，用于请求检索数据对象（如 HTML 页面）或向服务器返回信息（例如已完成的电子表单）。

Web 服务器使用响应消息向客户端交付所请求的数据。每个响应都包含一个状态行，该状态行指示了关于客户端请求的某些细节。这可能指示发生了错误，或者仅表示请求成功了。

请求消息和响应消息都可以伴随一个或多个消息头（headers）。这些标头允许客户端或服务器在其消息的同时传递附加信息。在研究可用标头字段的使用之前，我们先考虑标准消息格式的操作。

## 请求方法

请求方法的通用语法如下：

`<request method> <requested-URL> <HTTP-Version>`

HTTP 版本 1.0 定义了三种请求方法：`GET`、`POST` 和 `HEAD`。表 21.2 总结了每个支持方法的功能并概述了一个特定示例。

### 表 21.2. 请求方法语法和示例。

| 请求描述 | 描述 |
| :--- | :--- |
| `GET` | 用于检索 URI 内标识的对象。使用定义的标头可以使检索具有条件性。示例：`GET HTTP://www.dttus.com/home.html HTTP/1.0`。结果：Web 服务器将向客户端返回指定的 HTML 页面。 |
| `POST` | 用于请求目标 Web 服务器接收包含的消息体；这通常用于返回完成的电子表单，或用于发布电子新闻或电子邮件消息。示例：`POST HTTP://www.dttus.com/survey/completed.HTML HTTP/1.0. From: jamedwards@dttus.com`。结果：消息体放置在此 |
| `HEAD` | 此方法与 GET 相同，Web 服务器不返回包含的消息体——只返回相关的头部信息。此方法经常用于测试有效性、可用性或任何更改。示例：`HEAD HTTP://www.dttus.com/home.html HTTP/1.0`。结果：Web 服务器将向客户端返回结果码。 |

**注意：** 统一资源标识符 (`URI`) 是 HTTP 用于标识任何资源的通用引用。资源可以通过位置（使用统一资源定位符 `URL`）或名称（使用统一资源名称 `URN`）来标识。

## 定义标头值

标头值用于传递有关 HTTP 消息的附加信息。单个 HTTP 消息可能有多个标头与之关联。

通常情况下，可以将标头分为以下四个不同的组：

- 与消息请求相关的标头
- 与响应相关的标头
- 与消息内容相关的标头
- 同时适用于消息请求和消息响应的标头

消息头的操作和使用可以通过以下简单示例得到很好的说明：

`GET HTTP://www.dttus.com/home.html HTTP/1.0 - GET request`

`If-Modified-Since: Sun, 16 Mar 1997 01:43:31 GMT - Conditional Header`

` - CR/line feed`

在此示例中，Web 客户端向 Web 服务器发送了一个 HTTP 请求，要求检索指定的 HTML 页面。这是使用 `GET` 请求方法完成的。该 HTTP 请求补充了一个标头字段。该标头要求进行条件测试，只有当指定的 HTML 页面自指定日期以来被修改过时才返回它。
