## 构建查询

使用数据库 API 的关键部分涉及形成 SQL 字符串并将其传递给游标对象的 `execute()` 方法。这里的问题之一是，你需要用用户提供的参数来填充查询字符串的部分。例如，你可能会倾向于编写这样的代码：

```python
symbol = "AAPL"
account = 12345
```

```python
cur.execute("select shares from portfolio where name='%s' and account=%d" % (symbol, account))
```

尽管这种方法“有效”，但你不应该这样使用 Python 字符串操作来手动格式化查询。如果你这样做，你的代码就会面临潜在的 SQL 注入攻击风险——有人可以利用该漏洞在数据库服务器上执行任意语句。例如，在上例中，有人可能会提供一个类似于 `"EVIL LAUGH"; drop table portfolio;--` 的值，其结果可能与你预期的不同。

所有数据库模块都提供了自己的值替换机制。例如，与其格式化整个查询，你也可以这样做：

```python
symbol = "AAPL"
account = 12345
```

```python
cur.execute("select shares from portfolio where name=? and account=?", (symbol, account))
```

`?` 占位符会被连续替换为元组 `(symbol, account)` 中的值。

遗憾的是，不同的数据库模块实现之间没有统一的占位符约定。然而，每个模块都定义了一个参数样式（`parameterstyle`），用于指示查询中使用的值替换格式。可能的值如下：

### 关系型数据库 API 规范 301

| 参数样式 | 描述 |
| --- | --- |
| `'qmark'` | 问号样式，查询中的每个 `?` 都由序列中的连续项引用。例如，`cur.execute("... where name=? and account=?", (symbol, account))`。参数以元组形式指定。 |
| `'numeric'` | 数字样式，`:n` 被索引为 `n` 的参数值所填充。例如，`cur.execute("... where name=:0 and account=:1", (symbol, account))`。 |
| `'named'` | 命名样式，`:name` 被命名值填充。对于这种样式，参数必须作为映射给出。例如，`cur.execute("... where name=:name and account=:account", {'symbol':symbol, 'account':account})`。 |
| `'format'` | Printf 风格的格式代码，如 `%s`、`%d` 等。例如，`cur.execute("... where name=%s and account=%d", (symbol, account))`。 |
| `'pyformat'` | Python 风格的扩展格式代码，如 `%(name)s`。类似于 `'named'` 样式。参数必须作为映射而非元组指定。 |

## 类型对象

在与数据库交互时，整数和字符串等内置类型通常被映射到数据库中的对应类型。然而，对于日期、二进制数据和其他特殊类型，数据管理更为复杂。为了协助这种映射，数据库模块实现了一系列构造函数用于创建各种类型的对象。

`Date(year, month, day)`

创建一个表示日期的对象。

`Time(hour, minute, second)`

创建一个表示时间的对象。

`Timestamp(year, month, day, hour, minute, second)`

创建一个表示时间戳的对象。

`DateFormatTicks(ticks)`

从系统时间值创建一个日期对象。`ticks` 是由如 `time.time()` 等函数返回的秒数。

`TimeFromTicks(ticks)`

从系统时间值创建一个时间对象。

`TimestampFromTicks(ticks)`

从系统时间值创建一个时间戳对象。

`Binary(s)`

从字节字符串 `$s$` 创建一个二进制对象。

## 错误处理

数据库模块定义了一个顶级异常 `Error`，它是所有其他错误的基类。以下异常用于更具体的数据库错误：

| 异常 | 描述 |
|---|---|
| `InterfaceError` | 与数据库接口相关的错误，与数据库本身无关 |
| `DatabaseError` | 与数据库本身相关的错误 |
| `DataError` | 与处理的数据相关的错误。例如，错误的类型转换、除以零等 |
| `OperationalError` | 与数据库本身相关的错误 |
| `IntegrityError` | 完整性被破坏时的错误 |
| `InternalError` | 数据库内部错误 |
| `ProgrammingError` | 编程错误 |
| `UnsupportedError` | 数据库不支持的方法错误 |
| `Warning` | 用于模块警告诸如截断的问题 |

## 多线程

如果在多线程环境下访问数据库，每个模块定义了以下变量以提供信息。

`threadsafety`

一个表示模块线程安全性的整数。可能的值：

- `0` 无线程安全。线程不可共享。
- `1` 模块是线程安全的，连接不可共享。
- `2` 模块和连接是线程安全的，但游标不可共享。
- `3` 模块、连接和游标都是线程安全的。

## 将结果映射为字典

结果的一个常见问题是将元组或列表映射为命名字段的字典。例如，如果查询结果包含许多列，使用描述性名称比硬编码数字索引要容易得多。

处理此问题有很多方法，但最简单的方法之一是使用生成器。例如：

```python
def generate_dicts(cur):
    import itertools
    fieldnames = [d[0].lower() for d in cur.description]
    while True:
        row = cur.fetchone()
        if not row:
            return
        yield dict(itertools.zip(fieldnames, row))
```

```python
## 使用示例
cur.execute("name, shares, price from portfolio")
for r in generate_dicts(cur):
    print(r['name'], r['shares'], r['price'])
```

请注意，列的命名在数据库之间并不完全一致——特别是大小写敏感性，因此如果你尝试将此技术应用于多种数据库模块的代码，需要小心。

# sqlite3 模块

`sqlite3` 模块提供了指向 SQLite 库的 Python 接口。SQLite 是一个在文件或内存中实现自包含关系数据库的 C 库。与其他相比，它由于多种原因而简单且吸引。原因之一是它不依赖数据库服务器，也不需要特殊配置——你只需连接到数据库文件即可使用（如果不存在，则创建一个新文件）。数据库还支持事务以提高可靠性（即使跨系统崩溃），并允许多个进程同时访问同一个数据库文件。
