
354 Enter mail, end with "." on a line by itself

```
在这里输入任何你喜欢的消息。正如代码 354 之后的说明所说的那样，当你完成消息后，单独另起一行输入一个点。接下来的示例显示了一封发给收件人的带有 "Test message" 字样的邮件：
```

# Test message

.

250 2.0.0 Message accepted for delivery ID 15827nBE4533

```
输入 `quit` 退出。这种技术可以用于善，也可以用于恶。作为管理员，你可以测试你的邮件配置，而无需折腾可能产生结果的客户端。通过创建自己的声明来伪造邮件也是轻而易举的。在某些圈子里，给朋友伪造邮件是种成年礼。然而，伪造邮件也有非常合理的理由。
```

## 中继控制

通常情况下，邮件服务器接受目标是其本地域的邮件，或者接受从本地域发送的邮件。如果邮件服务器接收到发给你所在域合法用户的邮件，它应该接受该消息。如果服务器接收到来自具有你地址的用户邮件，并且满足了其他访问控制，服务器应该接受该消息并将其传递给收件人。然而，如果某些完全未注册的用户尝试将该服务器作为第三方的中继，服务器应该拒绝它。通过只允许某些主机通过你的服务器中继，你就可以过滤掉垃圾邮件。当你的服务器提供服务时，情况变得复杂。为了防止垃圾邮件，最佳实践是不要让用户通过你的服务器发送邮件。

## mailwrapper(8)

多年来，Sendmail 一直是 Unix 类系统中唯一可用的邮件服务器。因此，许多附加软件都期望找到 `/usr/sbin/sendmail`，并期望它的行为与 Sendmail 完全一致。更糟糕的是，Sendmail 在被不同的名称调用时，行为实际上是不同的。程序 `mailq(1)` 实际上与 `sendmail(8)` 程序是同一个文件，但由于名称不同，它们的行为也不同。由于许多其他程序必须精确模拟 Sendmail 的行为（包括这种多重调用行为），因此删除你的 Sendmail 二进制文件并将其替换为其他内容并不简单。

结果，一个不熟悉的 Unix 类系统的管理员可能根本不知道 `/usr/sbin/sendmail` 到底是什么！如果有人之前为了实验安装了几个邮件服务器，你可能需要诉诸侦探工作并碰一点运气才能识别出你所谓的 Sendmail。

FreeBSD 通过使用一个独立的 `mailwrapper(8)` 程序来绕过这个问题。这个邮件包装器将请求定向到指定的邮件服务器程序。你会发现有一个 `/usr/bin/sendmail`，但它实际上是伪装成 Sendmail 的 `mailwrapper(8)`。这个邮件包装器会将请求重定向到安装在其他地方的邮件程序。`/etc/mail/mailer.conf` 文件包含了程序名称列表以及要调用的实际程序路径。例如，这里默认的 `mailer.conf` 将所有内容重定向到 `sendmail(8)`：

```
sendmail /usr/libexec/sendmail/sendmail
send-mail /usr/libexec/sendmail/sendmail
mailq /usr/libexec/sendmail/sendmail
newaliases /usr/libexec/sendmail/sendmail
hoststat /usr/libexec/sendmail/sendmail
purgestat /usr/libexec/sendmail/sendmail
```

左列中的这六个“程序”每一个都是其他程序可能用于 Sendmail 的名称。替代邮件器实际上拥有具有这些名称的独立程序。如果你使用替代邮件器，你必须编辑 `mailer.conf` 为邮件器程序提供正确的路径。当你使用 Ports Collection 安装替代邮件器时，端口说明将详细解释如何为你的安装更新 `mailer.conf`。请按照这些说明配置你的新 MTA。否则，你必须手动编辑 `mailer.conf`。

## 提交与接收

FreeBSD（以及所有 Unix 类系统）以多种方式使用 Sendmail。某些 FreeBSD 机器接收来自互联网的邮件并将其转发到其他机器或交付给本地用户。其他 FreeBSD 机器不接收邮件，只生成邮件。Sendmail 处理每项工作的方式略有不同。

Sendmail 提交守护进程处理从本地机器发送（或提交）的邮件。在大多数情况下，这只是被转发到邮件交换服务器。例如，你网络上的所有服务器都会将每日状态邮件转发到实际邮件服务器，以便我接收。Sendmail 对本地源邮件的信任程度高于来自互联网的邮件，处理这些消息的 Sendmail 进程使用的限制较少的配置，执行的检查也少得多。Sendmail 只在本地 IP `127.0.0.1` 上监听网络，因此网络上的其他主机无法使用它。

Sendmail 入站守护进程接收网络上其他主机的邮件。这个 Sendmail 进程需要大量的关注和维护。这是入侵者会尝试攻击的 Sendmail 进程，也是垃圾邮件的潜在通道。我们将花费最多的精力在配置入站守护进程上。

这两个配置是互斥的。当你的系统上有一个功能完整的互联网邮件服务器时，你就不需要一个较小的 Sendmail 实例来处理本地邮件，就像大多数人不会离开家睡在工具棚里一样。当入站守护进程激活时，FreeBSD 会自动禁用提交 Sendmail 守护进程及其队列处理器。

在 `/etc/rc.conf` 中分别启用提交和入站守护进程。所有 Sendmail 配置选项的完整描述请阅读 `rc.sendmail(8)`，但这里是基础：

```
sendmail_enable="NO"
sendmail_submit_enable="YES"
sendmail_outbound_enable="YES"
sendmail_msp_queue_enable="YES"
```

简单的 `sendmail_enable` 开启入站 Sendmail 守护进程。如果你只想从本地主机发送邮件而不接收邮件，请开启 `sendmail_submit_enable`。`sendmail_outbound_enable` 和 `sendmail_msp_queue_enable` 设置处理从本地主机的邮件传输和重传。

这里的大部分 Sendmail 配置都适用于入站 Sendmail 守护进程。提交 Sendmail 进程需要的配置非常少。当我们讨论对提交 Sendmail 有用的配置项时，我们会特别说明。所有内容都是针对入站 Sendmail 实例的。并不是这些功能对提交 Sendmail 不起作用，而是它们没有意义。例如，为什么要在一个只能从本地主机访问的守护进程上设置基于主机名或 IP 的访问控制或反垃圾邮件保护？

## Sendmail 日志

`sendmail(8)` 将所有事务、错误和重启记录到 `/var/log/maillog`。检查它查看你的邮件活动，特别是在进行任何配置更改之后。当我处理邮件系统时，我倾向于在单独的终端窗口中记录，并使用 `tail -F` 显示新出现的条目：

```
# tail -F /var/log/maillog
```

每当 Sendmail 发送、接收或拒绝一条邮件时，它都会记录一条消息。`tail -f` 实时显示此日志。按 CTRL-C 停止显示并返回提示符。

## 配置 Sendmail

`/etc/mail` 目录包含所有对人类友好的 Sendmail 配置文件，以及几个对人类不友好的。对于接收入站邮件的服务器上最常见的任务，你只需要担心四个文件：`/etc/mail/access`、`/etc/mail/aliases`、`/etc/mail/mailertable` 和 `/etc/mail/relay-domains`。

`access` 文件允许为你的邮件服务器设置按主机和按域访问控制。

`aliases` 文件包含本地主机的邮件重定向映射。`mailertable` 允许你覆盖此邮件服务器的 MX 记录。当你使用 FreeBSD 系统为安全记录较差的专有系统（如 Microsoft Exchange）提供额外的安全层时，`mailertable` 特别有用。

`relay-domains` 文件列出了你的服务器将中继邮件的域名和地址。对于大多数系统来说，我们将是使用你的机器作为邮件服务器的桌面客户端，但列表也可能包含你提供备份服务的其他域名。

这些文件（`relay-domains` 除外）都有一个以 `.db` 结尾的数据库文件。像 `/etc/passwd` 和 `/etc/spwd.db` 一样，这些数据库文件是从文本构建的。

## access 文件

`/etc/mail/access` 文件有两列。左列是域名、主机名、IP 地址或一组 IP 地址。右侧是处理邮件的说明；它是 `RELAY`、`OK`、`REJECT` 或 `DISCARD` 之一。你可以为某些主机指定自定义错误消息。

`/etc/mail/access` 不理解现代子网，而是匹配你列出的地址部分。在这里，我想包含 `192.168.0/23` 范围，但必须列出两个块 `192.168.0` 和 `192.168.1`：

```
127.0.0.1 RELAY
192.168.0 RELAY
192.168.1 RELAY
```

更严格的规则是 `OK`，这意味着 Sendmail 守护进程将接受但不中继匹配主机的邮件。假设你有一个合作伙伴公司因为与臭名昭著的邮件器共享 ISP 而不断被列入垃圾名单。你可以通过 `OK` 规则专门接收来自他们的邮件：

```
thecompany.com OK
```

更严格的是 `REJECT` 规则，它告诉 Sendmail 对匹配源的任何邮件进行拒绝。假设 IP 地址为 `192.168.8.83` 的人向你发送大量邮件，试图填满你邮件服务器的硬盘。你可以通过 `REJECT` 规则专门拒绝来自他们的邮件：

```
192.168.8.83 REJECT
```

你可以通过在规则右侧指定自定义 `ERROR` 消息来拒绝邮件。正常的 Sendmail 拒绝使用消息代码 550。你的自定义错误消息对终端用户可见，因此在措辞上要委婉。用引号括你的自定义消息，以防 Sendmail 消除空格或以其他方式弄乱它。

```
suckycompany.com ERROR: 550 "Your momma dresses you funny"
```

最后，有些主机对你非常糟糕，以至于你再也不想看到它们的邮件。你甚至不想拒绝这些信息，只想把它们直接扔掉而不使用。这种情况下可以使用 `DISCARD` 规则：

```
absolutefreebsd.com DISCARD
```

## aliases 文件

`/etc/mail/aliases` 文件包含了发送到特定账户或用户名的邮件重定向规则。每行以一个别名开始，后面跟着一个冒号，以及用于转送邮件的系统上真实用户列表。邮件别名适用于使用入站或提交 Sendmail 配置的系统。

### 将邮件从一个用户转发到另一个用户

许多人喜欢将发送给 root 的邮件重定向到真实用户的账户。以下示例允许将发送给 root 的邮件交给另一个用户：

```
root: mwlucas@AbsoluteFreeBSD.com
```

许多地址实际上并没有关联账户。例如，要求的 postmaster 地址通常没有实际账户。你可以使用别名将其转发到真实账户。

```
postmaster: root
```

这样，postmaster 转发给 root，而 root 转发给我。我接收了这台机器上所有给 root@ 和 postmaster@ 的邮件。aliases 文件已经包含了各种 Internet 服务的标准地址，以及所有 FreeBSD 默认服务账户的别名。它们默认都会发送到 root。通过定义一个真实的别名地址作为你 root 邮件的目的地，你将自动获得系统管理邮件。

### 别名邮件列表

你可以列出多个用户来创建小型本地邮件列表。这对于用户频繁订阅和取消的动态列表来说扩展性较差，但对于快速简单的列表来说足够了：

```
sales: mwlucas, bpollock, sales@nostarch.com
```

### 将邮件转发到文件

aliases 文件较有趣的特性之一是能够重定向到邮件账户以外的内容。如果你列出一个文件名，Sendmail 会将消息追加到该文件中。你可以使用类似下面的内容维护用户 mwlucas 邮件的永久日志：

```
mwlucas: /var/log/mwlucas-mail, mwlucas
```

### 将邮件转发到程序

你还可以将邮件发送到程序进行自动处理。只需放置一个管道符号 (`|`) ，后面跟程序的完整路径。例如，如果你有一个脚本处理发送到特定地址的入站邮件，你可以用它来重定向邮件：

```
orders: |/usr/local/bin/process-orders.pl
```

### 包含

最后，你可以在 aliases 文件中包含其他文件。这允许高信任的用户修改她自己的别名。该文件必须是一个邮件地址列表，每行一个。

```
clientlist: include:/usr/home/salesdude/clientlist.txt
```

## mailertable 文件

mailertable 文件允许你选择性地覆盖 MX 记录。虽然在网络连接到 UUCP 等非互联网邮件系统时这很重要，但今天，这允许你将 FreeBSD 变成某种防火墙或堡垒机。在一种情况下，我有一个无法直接暴露到互联网的 Microsoft Exchange 系统。通过使用 FreeBSD 机器作为我的 MX 主机并在 FreeBSD 机器上使用 mailertable，我可以保护 Exchange 系统，而无需投资昂贵的邮件防火墙。

虽然我在 absolutefreebsd.com 并没有 Exchange 系统，但让我们假装我有。我的主机是 freebsd.absolutefreebsd.com 和 exchange.absolutefreebsd.com。我的 DNS 记录将显示为：

```
absolutefreebsd.com IN MX 10 absolutefreebsd.com
```

公众将所有邮件发送到 FreeBSD 机器。在 FreeBSD 机器上，我会使用如下 mailertable 条目：

```
.absolutefreebsd.com smtp:[exchange.absolutefreebsd.com]
```

这将使 FreeBSD 机器忽略列左侧域名的 MX 记录，转而将该主机的邮件转发到 exchange.absolutefreebsd.com。

## relay-domains 文件

Sendmail 简化了为其他域名提供备份 MX 服务的过程。与辅助 DNS 类似，处理备份 MX 服务的最好方法是找到一个规模相似的实体进行交换。你肯定不想在备份 MX 服务上花费大量时间，特别是对于你自己的以外的组织；使用一个规模相似且技术水平相当的组织，有助于确保你的伙伴给你带来的问题不会比你已有的问题多。

`/etc/mail/relay-domains` 文件列出了所有为你转发邮件的域名和 / IP 地址。在此列出每个域名或地址，每行一个。例如，这里有一条为 absolutefreebsd 提供备份 MX 服务的条目：

```
absolutefreebsd
```

不难，对吧？你必须在域名的 DNS 记录中也列出服务器，备份 MX 服务才能工作。

## 使更改生效

access 和 mailertable 文件都有对应的数据库 (.db) 文件。与密码文件一样，这些数据库文件供 Sendmail 和其他程序快速、方便地引用内容。当你编辑这些文件之一时，必须更新对应的数据库文件。现代 Sendmail 使用 `make(1)` 管理这些数据库。要更新 access 和 mailertable 文件，请进入 `/etc/mail` 目录并输入 `make maps`：

```
# cd /etc/mail
# make maps
```

`make(1)` 会比较每个文本文件与数据库文件的年龄，如果文本文件较新，它将重新构建数据库。要重建 aliases 数据库，请运行 `newaliases(8)` 或 `make aliases`：

```
# cd /etc/mail
# make aliases
```

要重建 mailertable 数据库，运行 `newaliases(8)` 或 `make mailertable`：

```
# cd /etc/mail
# make mailertable
```

要重建 access 数据库，运行 `newaliases(8)` 或 `make access`：

```
# cd /etc/mail
# make access
```

数据库更改在重建后立即生效。要重启系统，我建议使用 FreeBSD 的启动脚本：

```
/etc/rc.d/sendmail restart
```

## 虚拟域

默认情况下，Sendmail 拒绝所有目的不是本地主机的邮件。如果本地主机与你的域名相同，这是有效的——即如果你的邮件服务器是 example.com。在邮件系统中，虚拟域允许服务器接收不同域的邮件。FreeBSD 可以处理数百或数千个虚拟域。

配置虚拟域有三个步骤。首先，告诉邮件服务器它负责某个域。然后，将该域用户的邮件重定向到相应的账户。最后，发布指向你邮件服务器的域 MX 记录。

### /etc/mail/local-host-names 文件

`/etc/mail/local-host-names` 文件指定此机器接收邮件的主机和域名。通过在该文件中添加主机或域名，你告诉 Sendmail 本地机器是邮件目的地。该文件包含域名和主机列表，每行一个，如下：

```
blackhelicopters.org
absolutefreebsd.com
absoluteopenbsd.com
pgandgpp.com
cisroutersforthedesperate.com
...
```
