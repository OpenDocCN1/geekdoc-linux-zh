
`display` 指定与 X 服务器的连接。

`modmap` 指定 `XModifierKeymap` 结构。

`XSetModifierMapping` 函数指定用作修饰符的键（如果）的 `KeyCodes`。如果成功，X 服务器将生成一个 `MappingNotify` 事件，`XSetModifierMapping` 返回 `MappingSuccess`。X 最多允许 8 个修饰符键。如果在 `XModifierKeymap` 结构中指定了超过 8 个，则会导致 `BadLength` 错误。

`XModifierKeymap` 结构中的 `modifierkeymap` 成员包含 8 组 `max keyperm KeyCodes`，分别对应 `Shift`, `Lock`, `Control`, `Mod1`, `Mod2`, `Mod3`, `Mod4` 和 `Mod5` 中的每个修饰符。每组中只有非零 `KeyCode` 具有意义，零 `KeyCode` 被忽略。此外，所有非零 `KeyCode` 必须在 `Display` 结构中由 `min keycode` 和 `max keycode` 指定的范围内，否则会导致 `BadValue` 错误。

X 服务器可以对修饰符的更改方式实施限制，例如，如果某些键在没有处理程序的情况下不会产生转换，如果键无法禁用自动重复，或者如果支持多个修饰符。如果违反了此类限制，状态响应将为 `MappingFailed`，且没有任何修饰符会发生更改。如果为修饰符指定的新 `KeyCodes` 与当前定义的不同，且该修饰符的任何（当前或新的）键正处于逻辑按下状态，则 `XSetModifierMapping` 返回 `MappingBusy`，且没有任何修饰符会发生更改。

`XSetModifierMapping` 可能会产生 `BadAlloc` 和 `BadValue` 错误。

要获取用作修饰符的 `KeyCodes`，请使用 `XGetModifierMapping`。

```
XModifierKeymap *XGetModifierMapping(display);
```

`display` 指定与 X 服务器的连接。

`XGetModifierMapping` 函数返回指向新创建的 `XModifierKeymap` 结构的指针，该结构包含了用作修饰符的键。在使用后应通过调用 `XFreeModifiermap` 释放结构。如果任何修饰符的集合只出现零值，则该修饰符被禁用。

## 第 13 章 语言区域与国际化文本函数

国际化应用程序是指能够适应不同本地语言、当地习俗和字符编码要求的应用程序。将操作适配到特定的本地语言、当地习俗或字符串编码的过程称为本地化（`localization`）。国际化的目标是在不修改程序源代码或不重新编译的情况下允许本地化。

作为本地化机制之一，Xlib 提供了用于国际化文本输入的 X 输入方法 (`XIM`) 功能接口，以及用于国际化文本输出的 X 输出方法 (`XOM`) 功能接口。

X 中的国际化是基于区域化（`locale`）概念的。区域化设置定义了程序在运行时的本地化行为。区域化设置影响 Xlib 的以下方面：

- 输入法文本的编码和处理
- 资源文件和值的编码
- 文本字符串的编码和显示
- 客户端间通信的编码和解码

客户端间通信的编码和解码：各种语言的字符在计算机中使用编码表示。

不同的语言有不同的编码，甚至同一语言也有不同的编码。

本章定义了对本地化文本显示和文本输入的支持，并描述了控制所有依赖区域化的 Xlib 函数的区域化机制。提供了适用于支持主机 C 语言环境格式的多字节 (`char *`) 和宽字符 (`wchar *`) 文本函数集。多字节和宽字符函数是等等的，区别在于参数的形式。

Xlib 国际化函数并非旨在支持多语言应用程序（在单段文本中混合多种语言），但它们使得在独立语文中以有限方式支持多种语言的应用成为可能。

- 输出方法
- 输入方法
- 字符串常量

### 区域化管理

X 支持主机环境定义的一个或多个区域化。在符合 ANSI C 标准库的实现中，区域化宣告方法是 `setlocale`。该函数配置主机库和 Xlib 的区域化。Xlib 的实现受 `LCTYPE` 类的控制；这被称为当前区域化。实现允许在 `setlocale` 之外提供宣告区域化的特定机制。

在不符合 ANSI C 标准的实现中，区域化宣告方法取决于实现。

Xlib 在特定区域化下的语义操作定义机制取决于实现。

X 不要求支持主机支持的所有区域化。要确定当前区域化是否被支持，请使用 `XSupportsLocale`。

```
Bool XSupportsLocale();
```

如果 Xlib 函数能够在当前区域化下运行，`XSupportsLocale` 返回 `True`。如果返回 `False`，定义了 `XLocaleNotSupported` 状态的区域化函数将返回 `XNotSupported`。否则，依赖 X 的程序将在“C”区域化运行。

客户端负责选择其区域化和修饰符。客户端提供了一种在调用时覆盖客户端区域化的机制。大多数在 X 和处理环境均使用单一区域化的单显示 X 客户端将通过调用 `XSupportsLocale` 和 `XSetModifierMapping` 来配置区域化。

X 国际化能力的类别语义通过设置修饰符来配置。修饰符的命名取决于实现和特定的区域化。这种能力的唯一标准是通过选择几种风格的键盘输入方法实现的。

要配置当前区域化的修饰符，请使用 `XSetModifierMapping(modifier_list)`。

```
char *XSetModifierMapping(modifier_list);
```
