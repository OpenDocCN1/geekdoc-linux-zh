
操作系统必须有效地分配资源。它充当这些资源的管理者，并按需向应用程序提供资源。资源分配主要有两种类型。在`空间分配`情况下，资源访问将同时服务于多个客户端，其中每个客户端都可以使用资源（共享内存）。在`时间分配`情况下，系统进行排队，并根据队列允许它们在有限时间内使用整个资源（因此在单处理器系统中分配处理器）。

在分配资源时，操作系统解决可能的冲突，防止程序未经授权访问其无权访问的资源，确保计算机系统的高效运行。

## 现代操作系统的分类

让我们根据现代操作系统的范围来考虑其分类。首先，请注意`大型`计算机（大型机）的操作系统。为其设计的硬件的主要特征是 I/O 性能：大型计算机提供大量外设（磁盘、打印机、终端等）。这种计算机信息系统用于可靠地处理大量数据。此操作系统应有效支持此过程（在批处理模式或时间分配模式下）。此类操作系统的一个例子是 IBM 的 `OS/390`。

下一个类别包括`服务器`操作系统。此类操作系统的主要特征是能够处理大量对共享资源的用户请求。网络支持对它们起着重要作用。有专门的服务器操作系统排除了与其基本功能性能无关的元素（例如，对用户应用程序的支持）。通用服务器（`UNIX` 或 `Windows XP` 系统）现在更常用于实现服务器。

最庞大的类别是`个人`操作系统。此类别中的一些操作系统是微软开发的通用操作系统简化版本，考虑到用户预期（`Windows 95/98/Me`）。个人操作系统特别关注对图形用户界面和多媒体技术的支持。还有`实时`操作系统。在这样的系统中，必须保证每个操作在指定时间范围内完成。实时操作系统可以控制宇宙飞船飞行，处理或视频演示。有专门的实时操作系统，如 `QNX` 和 `VxWorks`。

另一个类别是`嵌入式`操作系统。包括管理各种微处理器系统的应用程序，用于军事技术、消费电子产品系统、智能卡和其他设备。此类系统提出特殊要求：放置少量内存并支持专用操作系统设备。通常，内置操作系统是为特定设备开发的；通用系统包括嵌入式 `Linux` 和 `Windows CE`。

## 操作系统的功能组件

操作系统可以被视为一组组件，每个组件负责实现系统的特定功能。让我们考虑现代操作系统最重要的功能及其实现组件。

系统由组件构建的方式及其关系由操作系统架构决定。每种操作系统在其可处理的工作类型和组织结构上都会有所不同，因此了解这些以及如何将它们整合在一起可能很重要。

### 进程和流管理

如前所述，操作系统最重要的功能之一是执行应用程序。代码和应用程序数据以特殊的可执行方式存储在磁盘上的计算机信息系统中。当用户决定运行操作系统以执行文件时，文件系统创建计算机的基本单元，即进程。您可以指定以下内容：进程是执行该程序的程序。

操作系统在进程之间分配资源。这些资源包括 CPU 时间、内存、设备、磁盘空间作为文件。对于每个进程的内存分配，承担其地址空间——一组允许访问的内存地址。进程空间存储在地址空间中。每个进程的磁盘空间分配形成类似打开文件列表。

进程保护其拥有的资源。例如，无法直接从其他进程访问进程地址空间（它是安全的），并且在工作时与文件一起，可以使用模式

指定了一个策略，该策略拒绝所有进程（除当前进程外）对文件的访问。

进程间分配处理器时间的原因在于，处理器是逐条执行指令的（即在任何特定时刻，物理上只有一个进程可以在其上面执行），而对于用户而言，这些进程应当表现为并行执行的指令序列。为了达到这一效果，操作系统会为每个进程提供一小段时间来使用处理器，随后将处理器切换到另一个进程；在这种情况下，被中断的进程会从其中断处恢复执行。

在`多处理器系统`中，进程可以在不同的处理器上并行运行。

现代操作系统除了支持进程之外，还支持多任务处理，即在进程内部存在多个指令序列（`线程`），这些线程对用户而言是并行运行的，类似于操作系统中的大多数进程。与进程不同，线程不提供资源保护（例如，它们共享其所属进程的地址空间）。

## 内存管理

在执行代码时，处理器从计算机的主存储器中获取指令和数据。主存储器被视为一个字节数组，每个字节都有一个地址。

如前所述，主存储器是一种在进程间共享的资源。操作系统负责内存的分配。进程执行期间，地址空间受到保护，只有在进程执行完成后才会释放。进程可用的内存量可能会随着内存分配的过程而变化。

操作系统必须具备将程序单独或整体装入到主存储器可用空间中的能力。为此，必须实现虚拟内存技术。该技术允许仅将当前时刻所需的指令和进程置入主存储器，而地址空间其余部分的内容则存储在磁盘上。

## I/O 管理

操作系统负责管理与计算机内存连接的 I/O 设备。操作系统对这类设备的支持通常分为两个层次。第一个较低层次的层次包括`设备驱动程序`——即控制特定类型设备并考虑其所有特性的软件模块。第二个层次包括一个便于应用程序使用的`通用 I/O 接口`。

操作系统应实现一个通用的 I/O 驱动程序接口，通过该接口与其他系统组件进行交互。此接口使得添加新设备的驱动程序变得容易。现代操作系统提供大量针对特定外围设备的现成驱动程序。操作系统支持的设备越多，其实用性就越高。

## 文件管理与文件系统

对于操作系统用户和程序员而言，磁盘空间是以一组`文件`的形式提供的，这些文件组织在一个`文件系统`中。文件是文件系统内一组可以通过名称访问的文件。术语“文件系统”可以用于两个概念：以文件形式组织数据的原则，以及根据该原则组织的具体数据集合（通常是磁盘的相应部分）。作为操作系统的一部分，它可以同时实现支持多个文件系统。

文件系统可以从逻辑层和物理层两个层面来考虑。逻辑层定义了系统作为文件集合（通常位于目录中）的外部表示，以及对文件和目录执行的操作（创建、删除等）。物理层定义了文件系统数据结构在驱动器上分配的原则。

## 网络支持

### 网络系统

现代操作系统已适应在网络上工作，它们被称为`网络操作系统`。网络支持使操作系统能够：

- 使本地资源（磁盘空间、打印机等）通过网络公开可用，即作为服务器运行。
- 通过网络引用其他计算机资源，作为客户端运行。

实现服务器和客户端功能的基础是`套接字`，它负责根据网络协议规定的规则在计算机之间传输数据。

### 分布式系统

网络操作系统不会向用户隐藏网络的存在。其中的网络支持不决定系统的结构，而是为其增加额外的功能。还有一些`分布式`操作系统，允许将多台计算机的资源汇集在一个`分布式系统`中。在用户看来，它就像一台拥有多个并行工作处理器的大型计算机。分布式系统和多处理器系统是利用多个处理器的两大主要类别的操作系统。

### 数据安全

操作系统中的数据安全意味着确保系统的可靠性（防止故障导致的数据丢失）以及保护数据免受未经授权的访问（无论是意外还是故意）。为了防范未经授权的访问，操作系统应确保提供用户`身份验证`（这种机制用于确定用户是否为其声称的身份，通常使用系统密码）及其`授权`（验证经过身份验证的用户是否具有执行特定操作的权利）。

## 用户界面

运行时有两种用户交互方式：`外壳（shell）`和`图形用户界面`（GUI）。命令解释器使用户能够使用特殊的命令语言（在线或通过启动）与操作系统交互以执行批处理文件。该语言的命令强制操作系统执行某些操作（例如，运行应用程序、处理文件）。

图形用户界面允许通过打开窗口和使用菜单或按钮执行命令来与操作系统交互。实现图形用户界面有许多方法：例如，在 `Windows` 系统中，其支持系统内置于系统中；而在 `UNIX` 中，它们是系统外部的，并依赖于标准 I/O 控件。

## 结论

- 操作系统是位于应用程序层和计算机硬件层之间的软件层。其主要目的是使计算机系统的易用性得到提升，并提高其效率。
- 操作系统的主要功能组件包括进程管理、内存管理、I/O 管理、文件管理及文件系统支持、网络支持、数据保护以及用户界面实现。

# 第 2 章：操作系统体系结构

操作系统可以被看作是一组组件的集合，每个组件负责某些功能。这些组件的集合以及它们相互之间以及与外部环境交互的顺序由`操作系统体系结构`决定。

让我们考察操作系统体系结构的基本概念、相关方法以及操作系统与外部环境交互的特征。我们将以 `Linux` 为例来探讨体系结构的实现。

## 操作系统体系结构的基本概念

### 系统内核 - 特权模式与用户模式

负责操作系统最重要功能的基本组件通常常驻内存，并以一种称为`操作系统内核`的特权模式执行。

当前关于操作系统体系结构设计的方法对内核功能的定义各不相同。操作系统最重要的功能，其教学自然归属于核心部分，包括中断处理、内存控制和输入/输出控制。内核的可靠性和性能使其要求更高。

内核的核心特征是它在特权模式下运行。让我们考虑这种模式的特点。为了确保高效的资源管理，计算机的操作系统相对于应用程序必须拥有某些特权。必须确保应用程序不能操纵操作系统，同时操作系统应能介入程序（例如，在争夺资源时解决 CPU 或切换方面的冲突）。

要实现这些优势，需要处理器提供硬件支持。处理器必须至少支持两种模式——`特权模式`（保护模式下的内核态）和`用户模式`。这对于系统运行至关重要，包括处理无效的用户命令（如任务切换、在限制下访问内存、限制对I/O设备的访问等）。
