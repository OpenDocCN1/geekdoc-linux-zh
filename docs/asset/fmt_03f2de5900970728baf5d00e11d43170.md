
# 流感病毒概述

流感病毒的潜伏期很短；也就是说，感染和症状之间只有 1–3 天的时间，这导致流感感染的一个标志性特征是症状的突然发展。病毒通常在咽喉部位排出 5–7 天。从普通流感中完全康复通常需要几天时间，并且在主要症状消失后，个体可能会感到虚弱和精疲力竭一周或更长时间。流感的两个主要并发症是原发性流感病毒肺炎和继发性细菌性肺炎。原发性流感肺炎相对较少见，在流行期间少于 1% 的病例中发生，但死亡率可能为 25–30%。上皮细胞的损伤以及随后清除呼吸道粒子能力的丧失会导致继发性细菌性肺炎。这个问题常见于老年人或患有基础慢性肺病或类似问题的人。由流感引起的肺炎在典型的流感季节可能会导致多达 20,000 人死亡。已知的并发症里杰综合征（Reye’s syndrome）可能继发于流感之后，在儿童中更为常见。

这种脑部疾病在全身病毒感染后的 2–12 天内发展，可能导致呕吐、肝损伤、昏迷，有时甚至死亡。

所有三种类型的流感病毒都可以在人类中引起疾病，但在引起疾病的宿主范围大小上存在显著差异。与感染 A 型病毒的大量动物种类相比，B 型和 C 型很少从动物中分离出来，主要感染人类。

抗体的存在或缺失对于流感的流行病学非常重要。在没有免疫力的个体中，攻击率可能达到 70%，并可能导致严重疾病。即使低水平的抗体也可能为个体提供部分保护，并将疾病严重程度降低到仅类似感冒的症状。

在流行期间，一种流感毒株占主导地位，但人口中存在两种或更多其他毒株作为轻微感染并不罕见。流感暴发发生在温带气候的寒冷月份，通常大多数病例聚集在 1–2 个月的时期内，这与许多其他呼吸道病毒更广泛的发病期形成对比。

因原发性肺炎和细菌性超级感染而导致的死亡率增加是常见的，这是公共卫生当局监测流行病的方式之一。

流感的控制和预防试图通过使用药物和疫苗来实现。使用灭活病毒疫苗来预防流感，尽管使用减毒活病毒株可能更好地刺激细胞介导的免疫反应，并提供更高质量和更持久的免疫力。疫苗的组成每年根据对每个流感季预期优势毒株的预测进行修改，但通常包含两种 A 型病毒和一种 B 型病毒的抗原。这些疫苗利用了病毒核酸天然的重配能力并形成新毒株。疫苗利用的那些毒株不具有烈毒性，并且能在较低温度下复制（如鼻咽部发现的温度），但不能在较高温度下复制（如下呼吸道发现的温度）。现代生物技术的技巧被用于克隆病毒颗粒部分的副本或提供对应于病毒关键功能区域的寡核苷酸，以获得更好的保护并减少副作用。参见 `BIOTECHNOLOGY`（生物技术）；`VACCINATION`（疫苗接种）。

## 信息管理

与管理企业信息资产相关的功能，通常是公司或政府组织。越来越多的公司采取这样的观点，即信息是企业资产，就像公司的财务资源、资本设备和房地产是资产一样。恰当使用这些资产可以创造额外的价值，并有可衡量的投资回报。目光远大的公司更进一步，将信息视为战略资产，可以将其转化为公司所服务市场中的竞争优势。

信息管理功能的范围在不同组织之间可能有所不同。最低限度，它通常包括数据的产生或获取、其在数据库中的存储、通过应用程序对其进行处理或操作以产生新数据（增值）和报告，以及数据或由此产生的报告的传输（通信）。许多公司包括语音通信管理（电话系统、语音信箱，以及越来越多的计算机-电话集成或 `CTI`），甚至知识产权和其他知识资产。

术语“数据”和“信息”之间存在显著差异。从表面上看，信息是原始数据处理的结果。然而，真正的问题是在正确的时间以可用的形式将正确的信息传达给正确的人

体形式。从某种意义上说，信息可能是一种易逝的商品。因此，信息管理者面临的最关键问题也许是需求定义，或者说是使信息系统与企业使命保持一致。如果最终产品未能满足用户的需求，那么再好的技术方案也价值有限。

确定需求的一种正式方法是信息工程。通过使用被不同地称为业务系统规划或信息系统规划的过程，信息工程最初关注的是组织如何开展业务，识别信息从产生地到需求地的路径，所有这些都置于组织和其功能的模型背景之中。虽然信息系统人员可能是信息工程过程的主要推动者，但其成功关键取决于最终用户的积极参与，从首席执行官到职能人员均包括在内。

应用信息工程的一个主要优势在于，它实际上迫使组织处理其信息系统需求的整个范围，从而形成一套功能集成的企业系统系统。相比之下，临时性的应用可能会导致一组碎片化的系统（自动化孤岛），在极端情况下，这些系统可能不兼容，包含重复（甚至不一致）的信息，并遗漏关键的信息要素。[A,B,S,]

## 信息系统工程

指信息系统被设计、开发、测试和维护的过程。信息系统工程的技术起源可以追溯到常规的信息系统设计与开发，以及系统工程领域。信息系统工程本质上具有结构化、迭代性、多学科性和应用性。它涉及结构化的需求分析、功能建模、原型开发、软件工程，以及系统测试、文档记录和运维。

现代信息系统解决各种数据、信息和知识基础的问题。在过去，大多数信息系统是纯数据导向的；它们的主要目的是存储、检索、操作和显示数据。应用领域包括库存控制、银行、人事记录管理等。航空订票系统是20世纪70年代信息系统的典型代表。自那以后，人们对信息系统能力的期望已显著提高。信息系统通常为用户提供分析支持。其中一些系统有助于资源分配、人员评估，以及大型系统和过程的规划与模拟。用户期望信息系统能够执行图示中所示连续谱上的所有任务。

系统工程覆盖系统的整个生命周期，包括需求定义、功能设计、开发、测试和评估。系统工程师的视角与产品工程师、软件设计师或技术开发人员不同。产品工程师处理细节，而系统工程师采取整体观点。系统工程基于工程师的传统技能，并结合了来自应用数学、心理学、管理学及其他学科的额外技能。系统工程过程是将操作需求转化为系统性能配置描述的一系列逻辑活动与决策。该过程本质上具有迭代性和多学科性。参见 `SYSTEMS ENGINEERING`。[S,A,]

## 信息技术

指涉及基于计算机的硬件和软件系统及通信系统的工程领域，旨在实现信息的获取、表示、存储、传输和使用。信息技术（IT）的成功实施依赖于能够应对系统的整体架构、其与人及组织的接口，以及其与外部环境的关系。它还关键依赖于将信息成功转化为知识的能力。

信息技术关注通过设计、开发和使用基于技术的系统与过程，提升多种人类和组织问题解决工作的效率，从而增强信息在多种战略、战术和操作情境中的效率与效能。理想情况下，这是通过对人类在问题解决任务中的信息需求以及技术辅助（包括计算机等电子通信系统、硬件和软件及其相关过程）的关键关注来实现的。信息技术通过强调工程的信息基础，补充并增强了传统工程。

信息技术所需的知识和技能来自应用工程科学，特别是信息、计算机和系统科学，以及专业实践。在信息技术领域的专业活动以及信息技术系统的获取范围，从需求定义或规格说明，到通信和基于计算机的信息支持系统的概念与功能设计及开发。它们关注架构定义与评估等主题。这些活动包括将新系统整合到功能正常的现有系统中，并随着用户需求随时间变化而维护结果。这种人与系统及过程的交互，以及相关的信息处理活动，可能呈现多种不同形式。参见 `REENGINEERING`；`SYSTEMS ARCHITECTURE`；`SYSTEMS ENGINEERING`。

计算和通信的硬件与软件构成了信息技术的基本工具。这些工具通过使用系统工程过程实现为信息技术系统。虽然信息技术和信息系统工程确实使系统设计和现有组织的设计变得更好，但它也促成了从根本上新的组织和系统（如虚拟公司）的设计。因此，该领域的努力不仅包括与客户互动以满足当前需求，还包括对未来技术、组织和人类问题的意识，以支持向基于新技术服务的长期过渡。[A,P,S,]

## 信息论

通信理论的一个分支，致力于编码问题。信息论的一个独特特征是其使用数值度量来衡量当传输消息或一组消息时所获得的信息量。信息论严重依赖概率这门数学学科。因此，信息论这一术语常被宽松地应用于通信理论中的其他概率研究，如信号检测、随机噪声和预测。参见 `ELECTRICAL COMMUNICATIONS`；`PROBABILITY`。

从信息论的角度设计单向通信系统时，有三部分超出了系统设计师的控制范围：(1) 信源，它在系统传输端产生消息；(2) 信宿，最终接收消息；(3) 信道，由传输介质或设备组成，用于将信号从信源传送到信宿。信源通常不以信道可接受的输入形式产生消息。发射机是除信道外唯一包含另一种设备的系统组件，称为编码器，它准备信源的消息以便输入信道。同样，系统接收端将包含一个解码器，将信道的输出转换为信宿可识别的形式。编码器和解码器是需要设计的部分。在无线电系统中，这种设计基本上就是选择调制器和解调器。参见 `MODULATION`。

如果信源的消息是由来自可枚举可能性集合（字母表）的元素（字母）序列组成的，则该信源被称为离散信源。因此，产生整数数据或书面英文文本的信源，例如语音和音乐信源。连续情况的处理有时通过注意到有限带宽的信号可以被编码为离散的数列来简化。

信道的输出不一定与其输入一致。例如，为了保密目的，信道可能包含一个加密设备来扰乱消息。然而，如果知道输入消息就可以计算信道输出，则该信道被称为无噪信道。但是，如果随机因素使得即使知道输入，输出也不可预测，则该信道被称为有噪信道。参见 `COMMUNICATIONS SCRAMBLING`；`CRYPTOGRAPHY`。
