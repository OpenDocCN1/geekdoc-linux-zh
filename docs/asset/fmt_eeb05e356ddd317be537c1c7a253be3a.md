
# Mac (PowerPC) Ubuntu

官方并不支持 PowerPC，但社区对该处理器架构存在支持。有关在 PowerPC 上运行 Ubuntu 的更多信息，请访问 `wiki.ubuntu.com/PowerPCFAQ`。你可以从 `wiki.ubuntu.com/PowerPCDloads` 下载 PowerPC 版本的 Ubuntu。

## 接口：安装程序与已安装系统

当你安装 Ubuntu 时，你可以选择在安装过程中使用的界面（通过安装程序），并选择用于操作已安装系统的界面。本节描述了这两种基本接口：文本界面和图形界面。

### 文本界面 (CLI)

文本界面，也称为命令行界面 (CLI) 或基于字符的界面，它显示字符和一些简单的图形符号。它是行定向的；你仅可以使用键盘向其提供指令。

### 图形用户界面 (GUI)

图形用户界面 (GUI) 通常显示一个桌面（如 GNOME）和窗口；你使用鼠标和键盘提供指令。你可以通过打开终端模拟器（第114页）在 GUI 中运行文本界面。GUI 相比文本界面会消耗更多的计算机资源（CPU 时间和内存）。

### 伪图形界面 (Pseudographical)

伪图形界面是一种文本界面，它利用了文本显示设备（如终端）上的图形元素。它可能还会使用颜色。该界面使用文本元素（包括简单的图形符号）来绘制粗略的框，模拟 GUI 窗口和按钮。`TAB` 键经常将光标从一个元素移动到下一个，`RETURN` 键则选择光标所在的元素。

### 优点

GUI 界面用户友好，而文本界面紧凑、消耗资源更少，并可以在仅限文本的终端或通过仅限文本的连接运行。由于效率更高，文本界面对于较旧、较慢且内存极小的系统非常有用。服务器系统频繁使用文本界面，因为它允许系统将更多资源分配给设定的任务，并将更少资源用于满足系统管理员。不运行 GUI 还可以提高系统安全性。

## Ubuntu 安装介质

### 桌面 CD

桌面 CD 是一个实时启动/安装 CD（第24页）；你可以使用它进入实时会话。该 CD 适用于 PC 和 64 位架构（第26页），使用图形安装程序，并安装带有桌面的 Ubuntu 系统。

### 备用 CD (Alternate CD)

备用 CD 不是实时启动 CD；它用于特殊安装。它提供了比桌面 CD 更高级的选项。该 CD 适用于 PC 和 64 位架构（第26页），使用文本安装程序，并安装显示图形界面或文本界面的 Ubuntu 系统。

### 服务器 CD

该 CD 不是实时启动 CD；仅用于安装。该 CD 适用于 PC、64 位 PC 和 SPARC 架构（第26页）。它使用文本安装程序，并安装没有桌面的 Ubuntu 系统。在安装期间，服务器 CD 提供了安装 LAMP（Linux, Apache, MySQL 和 PHP）的选项。

### DVD

DVD 是一个实时启动/安装 DVD（第24页）；你可以使用它进入实时会话。该 DVD 适用于 PC 和 64 位架构（第26页），使用图形或文本安装程序，并安装显示图形界面或文本界面的 Ubuntu 系统。DVD 包含了 Ubuntu 支持的所有软件包，而不仅仅是默认安装的。

## 安装全新副本还是升级现有的 Ubuntu 系统？

### 纯净安装 (Clean Install)

安装有时被称为纯净安装是指向磁盘写入所有全新的数据。安装程序会覆盖所有系统程序和数据以及内核。在安装期间，你可以根据数据的位置以及你格式化/分区磁盘的方式保留某些用户数据。或者，你可以通过设置双引导系统（第61页）在不覆盖数据的情况下在任何系统上执行纯净安装。

### 升级 (Upgrade)

升级将已安装的 Ubuntu Linux 版本的内核和工具替换为新版本。在升级期间，安装程序会保留系统配置和用户数据文件。升级会将旧版本中存在的工具更新到最新版本，并安装新工具。在升级系统之前，请备份系统上的所有文件。

# 设置硬盘

硬盘必须通过几种方式进行准备，以便操作系统能够对其进行读写操作。低级格式化是准备磁盘使用的第一步。你不需要对硬盘进行低级格式化，因为这项任务在工厂时就已经完成了。准备硬盘使用的后续步骤是向其写入分区表，并在磁盘上创建分区。磁盘上未被分区占据的区域称为*空闲空间*。新硬盘没有分区表，也没有分区。在 DOS/Windows 下，*格式化*意味着在分区上创建一个文件系统；参见下文的“文件系统”。

## 分区

分区表存储了关于硬盘上分区的信息。磁盘上可以创建一个第一个分区，创建分区的程序必须在磁盘上设置一个空表。随着分区的添加、删除和修改，关于这些更改的信息就会被记录在分区表中。如果你删除了分区表，除非采取极其特殊的措施，否则你将无法再访问磁盘上的信息。

大多数程序都可以向分区写入数据，但一个*数据结构*需要被写入分区中。当 Ubuntu 安装程序创建分区时，它会在分区上写入一个文件系统。你可以使用 `mkfs`（创建文件系统；第 525 页）工具手动在分区上创建文件系统。第 570 页的表 13-1 列出了一些常见的文件系统类型。Ubuntu Linux 通常创建 ext3 文件系统，而 Windows 使用 FAT16、FAT32 和 NTFS 文件系统。Apple 使用 HFS（分级文件系统），而 OS X 使用 HFS+ 或 UFS。在 DOS/Windows 下，文件系统被标记为 C:、D: 等（有时只是单个字母）。不同类型的分区共存在于同一块硬盘上，Windows 和 Linux 分区也是如此。`fsck`（文件系统一致检查；第 577 页）工具检查文件系统数据结构的完整性。

分区本身不包含关于它位于系统结构中何位置的信息。当你使用安装程序创建大多数分区时，你会指定一个 Ubuntu 与分区关联的目录名称。例如，你可能会创建一个分区并将其与 `/var` 目录关联。你指定的位置就是该分区的挂载点。作为启动过程的一部分，Ubuntu 会查阅 `fstab`（文件系统表；第 576 页）文件，该文件将每个分区与其挂载点关联。这种关联被称为“挂载”，它允许你通过其挂载的目录名称来访问分区上的文件系统。

例如，第一块硬盘上的第二个分区（设备名称为 `/dev/sda2`）可能包含通常挂载在 `/home` 目录的文件系统。这种关联是正常的，但不是强制的。当你以恢复模式工作时，你可能会将文件系统挂载到 `/target` 目录，以便修复文件系统。分区通常通过其正常挂载点的名称来指称：因此，/home 分区指的是持有通常挂载在 `/home` 目录的文件系统的分区。更多信息请参见第 572 页。

## 文件系统独立性

一个文件系统的状态不会影响其他文件系统：驱动器上的一个文件系统可能损坏无法读取，而其他文件系统运行正常。一个文件系统可能已满导致你无法写入，而其他文件系统有充足的空间存储数据。

# 主分区、扩展分区和逻辑分区

你可以将 IDE/ATA 磁盘最多分为 63 个分区，将 SCSI 磁盘最多分为 15 个分区。你可以独立地使用每个分区作为交换设备、文件系统、数据库、其他资源，甚至是其他操作系统。

遗憾的是，磁盘分区遵循很久以前的 DOS 机器的模板。最多情况下，一个磁盘可以包含四个主分区。你可以将这些分区中的一个（且仅一个）划分为多个逻辑分区；这个被划分的分区被称为扩展分区。如果你在驱动器上需要四个以上的分区——你经常会有这种情况——你就必须设置一个扩展分区。

典型的磁盘被分为三个主分区（编号为 1, 2 和 3）和一个扩展分区（编号为 4）。这些主分区是你想要的分区大小。一旦你建立了扩展分区，你就可以将其划分为额外的逻辑分区（编号为 5 或更大）。扩展分区占据磁盘的剩余部分。第 67 页的图 17-5 描述了这种磁盘。

# 规划分区

## 引导分区

如果你不熟悉 Linux，很难合理规划分区的大小。因此，Ubuntu 提供了引导分区。在不提任何问题的情况下，引导分区将分配给 Ubuntu 的磁盘部分分为两个分区。其中一个是交换分区，大小从 512 MB 到 2 GB 不等。另一个分区被指定为 `/` (root)，包含磁盘的剩余空间。只有两个分区会让磁盘空间管理变得简单。但如果程序失控或系统受到 DOS 攻击（第 1034 页），整个磁盘可能会满。包含记录错误的系统信息可能是最好的。

## 分区建议

Linux 系统有一个 `/` (root) 分区。建议也设置一个交换分区。你可以创建额外的分区/挂载点对；这里列出了一些常见的。任何标准目录会自动成为 `/root` 目录的子目录并位于 `/` (root) 分区。例如，如果你没有创建一个存放 `/home` 文件系统的分区，安装程序会将 home 作为 `/root` 目录的子目录并位于 `/` (root) 分区。

### 交换分区

内存不足以存储所有所需信息时，Linux 将程序和数据临时存储在交换分区上。交换分区的大小应该是内存的一倍到两倍，最小为 256 MB。例如，拥有 1 GB 内存的系统应该有一个 1 GB 到 2 GB 的交换分区。虽然不是必须有交换分区，但大多数系统带有交换分区性能更好。交换分区是不挂载的，因此它没有挂载点关联。更多信息请参见第 564 页的交换。

### /boot 分区

此分区包含系统启动时所需的内核和其他数据。`/boot` 通常约为 100 MB，尽管所需的空间取决于你想保留多少个内核镜像。该分区可以小到 50 MB。虽然你可以省略 `/boot` 分区，但在许多情况下它是很有用的。管理员在该分区上使用 ext2 文件系统，因为 ext3 日志中的数据变化并不频繁，不足以证明其额外的开销。

### /var 分区

`var` 是 variable（变量）的缩写：此分区中的数据频繁变化。由于它包含了大部分系统日志、软件包信息和计费数据，将 `/var` 设置为独立分区是一个好主意。这样，如果用户运行了耗尽所有用户磁盘空间的任务，系统日志也不会受到影响。对于运行带有详细日志守护进程和大量打印活动的活跃系统（队列中的文件存储在 `/var` 中），`/var` 分区可以占用从 500 MB 到几 GB 不等作为授权软件许可服务器的系统通常被视为极其活跃的系统。默认情况下，Apache 内容在 Ubuntu 下存储在 `/var` 中。

### /home 分区

将用户主目录放在自己的磁盘或分区上是一种常见的策略。此分区通常命名为 `/home`。将 `/home` 放在独立分区中，允许你执行纯净安装而不会覆盖用户文件。

## 设置分区以便进行备份

- 根据你想要备份的分区以及你想要备份的方式来规划分区。一个巨大的分区可能比几个小分区更难备份。

### /root 分区

一些管理员选择将 `/root`、`/boot` 和 `/usr` 分区分开。当你让 Ubuntu 决定如何划分磁盘（引导分区）时，它会将所有内容放在根分区中。根分区本身通常消耗少于 30 MB 的磁盘空间。超过 300 MB 是根分区的一部分。`/lib` 可能会安装一个包含许多内核驱动程序的特殊程序，这些程序会在根分区中占用大量空间。为根分区分配 1 GB。

### /usr 分区

如果你计划将 `/usr` 导出到另一个系统并希望独立分区能提供的安全性，分离 `/usr` 分区可能会很有用。许多管理员在该分区使用 ext2 文件系统，因为该分区上的数据变化频率不足以抵消 ext3 日志带来的开销。`/usr` 的大小取决于安装的软件包数量。在默认系统中，它通常为 2-4 GB。

### /usr/local 和 /opt 分区

`/usr/local` 和 `/opt` 都是分离候选。如果你计划在 Ubuntu 之外安装许多软件包，你可能希望将它们放在独立分区上。如果你将软件包与用户主目录安装在同一个分区中，可能会占用用户的磁盘空间。许多网站将所有 `/usr/local` 或 `/opt` 保留在一个服务器上并导出到其他系统。

**表 2-1** 给出了 Linux 使用的分区的最小大小指南。根据需要和磁盘的大小设置 `/home`、`/opt` 和 `/usr/local` 等其他分区的大小。如果你不确定如何使用额外的磁盘空间，可以创建任何命名的分区（例如 `/b1`、`/b2` 等）或稍后划分空间。

| 分区 | 示例大小 |
|---|---|
| /boot | 50–100 MB |
| / (root) | 1 GB |
| (swap) | 系统内存的一倍到两倍，最小 256 MB |

## RAID

RAID（独立磁盘冗余阵列）结合两个或多个硬盘驱动器或分区来提高容错性或性能。应用程序利用这些驱动器/分区作为一个单一逻辑设备。RAID 可以硬件或软件实现（Ubuntu 提供了此选项），将数据分布在多个磁盘上。根据你选择的级别，RAID 在硬件故障时提供数据冗余。虽然可以通过增加读写速度提高磁盘性能，但软件 RAID 会消耗大量的 CPU 时间，这需要考虑。真正的 RAID 需要硬件来实现，本文未涵盖（请见下文的“伪 RAID”）。

### 用 RAID 代替备份

不要用 RAID 代替备份。如果发生灾难性故障，RAID 是没用的。地震、火灾、盗窃和其他灾难可能导致整个系统无法访问（硬盘损坏或丢失）。RAID 也无法处理用户删除文件的情况。在这些情况下，在可移动介质上的备份是恢复文件系统的唯一方法。

RAID 可以作为备份的有效补充。Ubuntu 提供了可以在安装 Ubuntu 系统或以后安装的 RAID 软件。如果分区 ID 设置为 `0xfd`（自动检测），Linux 内核会在启动时自动检测 RAID 阵列（分区组）。

在内核中实现的软件 RAID 比硬件 RAID 便宜得多。这种方法不仅避免了对专用 RAID 磁盘控制器的需求，而且适用于便宜的 ATA 磁盘以及 SCSI 磁盘。

### 伪 RAID

Ubuntu 通过 `dmraid` 驱动支持基于主板的 RAID（伪 RAID）。Linux 软件优于伪 RAID。更多信息请参见 `help.ubuntu.com/community/FakeRAIDHowto`。

备用光盘上的分区程序允许你选择实现 RAID 级别 0、1 或 5：

- **RAID 级别 0（条纹）** 提高性能但不提供冗余。RAID 设备的存储容量等于成员分区或磁盘的大小。
- **RAID 级别 1（镜像）** 提供简单的冗余，提高数据可靠性，并提高读取密集型应用程序的性能。RAID 设备的存储容量等于成员分区或磁盘之一。
- **RAID 级别 5（带校验的磁盘条纹）** 提供冗余并提高（尤其是读取）性能。RAID 设备的存储容量等于成员分区或磁盘的大小减去一（假设它们的大小相同）。

欲了解更多信息请参考 *Software-RAID HOWTO*。

## LVM：逻辑卷管理器

逻辑卷管理器（LVM2，本文简称为 LVM）允许你动态更改逻辑卷（LVs，LVM 等同于分区）的大小。使用 LVM，如果你在设置 LVs 时出错或你的需求发生变化，你可以在不影响用户数据的情况下缩小或增大 LVs。你必须在安装系统或添加硬盘时选择使用 LVM；你不能事后将其应用到已装有数据的磁盘上。LVM 支持 IDE 和 SCSI 驱动器，以及位于 RAID 阵列中的多个设备。
