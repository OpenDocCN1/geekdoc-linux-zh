
## 描述

作业控制允许你将当前执行的命令移动到前台或后台，并根据需要停止、挂起或重启它们。前台始终有一个作业，即接受你键盘输入的 `shell`。前台作业可以是 `shell` 或任何接受键盘输入的命令（例如编辑器）。

当你执行一条命令行或在前台启动作业时，向终端窗口的输入会被阻塞，在作业完成之前，你无法输入额外的命令。你可以使用作业控制命令将该作业推到后台，以重新获得终端窗口的控制权。同样，你可以将后台作业带回前台，以便控制它或从终端窗口输入数据。作业控制允许你在当前层级或窗口内执行这些操作。

你在终端窗口输入的每条命令或管道都会被分配一个正整数的作业 ID（`job-id`）。`shell` 会跟踪当前和之前的作业。上一个作业是第一个非并发作业。

所有作业都处于以下状态之一。

- 前台作业对控制终端具有读/写权限。
- 后台作业被拒绝读取权限，并对控制终端具有有条件的写入权限（参阅 `stty(1)`）。
- 停止的作业是被置于挂起状态的作业，通常是由于 `SIGTSTP` 信号的结果（参阅 `signal(5)`）。

`Korn shell` 和 `C shell` 以及 `Bourne` 的 `jsh` 作业控制 `shell` 都支持作业控制。

## 输出

对于所有 `shell`，如果你没有指定任何选项，输出将是如下格式的行：
`[%d] %c %s\n`，作业号，当前，状态，命令

## jobs, fg, bg, stop, notify

字段描述如下。

- **job-number** 一个用于向 `wait`, `fg`, `bg`, and `kill` 命令标识进程组的数字。通过这些命令，你可以在作业前加上 `%` 来标识作业号。

- **current** `+` 标识将作为 `fg` 或 `bg` 命令默认值的作业；你也可以通过 *job-id* `%+` 或 `%` 指定此作业。该字符标识如果当前作业退出，将成为默认值的作业；你也可以通过 *job-id* `%-` 指定此作业。对于其他作业，此字段为空格字符。你可以用 `+` 识别一个作业，用 `-` 识别另一个作业。如果有任何挂起的作业，则当前作业是挂起的作业。如果至少有两个挂起的作业，则上一个作业也是挂起的作业。

- **state** 以下字符串之一（在 POSIX 区域中）：
  * *Running*（运行）作业未被信号挂起且未退出。
  * *Done*（完成）作业完成并返回退出状态 0。
  * *Done (code)* 作业正常完成并以指定的非零退出状态（`code`）退出，以十进制数字表示。
  * *Stopped*（停止）作业被 *SIGTSTP* 信号挂起。
  * *Stopped (SIGSTOP)* 作业被 *SIGSTOP* 信号挂起。
  * *Stopped (SIGTIN)* 作业被 *SIGTIN* 信号挂起。
  * *Stopped (SIGTOU)* 作业被 *SIGTOU* 信号挂起。

- **command** 给予 `shell` 的关联命令。

如果你指定了 `-l` 选项，会在状态字段之前插入一个包含进程组 ID 的字段。此外，进程组中的更多进程可能会单独行输出，仅使用进程 ID 和命令字段。

对于 `jsh` 和 `ksh`，如果你指定了 `-p` 选项，输出将每个进程 ID 占据一行。
以下 `jsh` 示例列出了两个作业：

```
$ jobs
[1] - Running spider
[2] + Done(0) find . -name core -print
$
```

### Bourne 作业控制 Shell

`jsh` 是 `Bourne` 作业控制 `shell`，除了内置作业控制命令外，`jsh` 还提供了 `sh` 的所有功能。通常，你只将 `jsh` 作为交互式 `shell` 使用；非交互式 `shell` 无法从新增的作业控制功能中受益。

`jsh` 内置命令报告所有已停止或在后台执行的作业。如果输出 `%job-id`，`jobs` 命令将报告所有停止或在后台运行的作业。以下选项修改或增强了对作业的控制：

- `-l` 作业的进程组 ID 和工作目录。
- `-p` 只报告作业的进程组 ID。
- `-x` 将命令或参数中找到任何 `job-id` 替换为相应的进程组 ID，然后传递执行命令。

作业标识符的可接受语法格式为：
`%job-id`

你可以按照以下任一格式指定 `job-id`：

- `% +` 当前作业。
- 上一个作业。
- `?string` 命令行中唯一包含 `string` 的作业。
- `nn` 作业号 `n`，其中 `n` 是作业号。
- `pref` 命令名的唯一前缀（例如，如果命令是 `ls -l`）。如果作业在后台运行，`pref` 可以包含空格，除非你引用它。

`fg`（前台）命令将停止的作业恢复在前台执行，并将执行中的作业移到前台。如果省略 `job-id`，则假设为当前作业。

`bg`（后台）命令将停止的作业恢复在后台执行。如果省略 `job-id`，则假设为当前作业。

`stop` 命令通过使用 `job-id` 停止后台作业，或使用 `pid` 停止任何进程；参阅 `ps(1)`。

### C Shell

`C shell` 内置的 `jobs` 命令在不带参数时列出活跃的作业控制。

以下选项修改/增强 `jobs` 的输出：

- `-1` 除了正常信息外，列出进程 ID。

`shell` 将编号的 `job-id` 与每个命令关联，以跟踪在后台运行或被 `TSTP` 信号（通常是 `Ctrl-Z`）停止的命令。当你使用命令行末尾的字符 `&` 在后台启动命令或序列（分号分隔列表）时，`shell` 会显示一行带有括号的作业号和关联进程列表：

```
[1] 567
```

注意 — 要查看当前作业列表，请使用内置 `jobs` 命令。最近停止（或无停止时放入后台）的作业被称为当前作业，并用加号（`+`）标识。当当前作业终止或移到前台时，该作业将取代（成为新的当前）。

要操作作业，请使用 `bg`, `fg`, `kill`, `stop` 和内置命令。作业的引用以百分号（`%`）开始。百分号本身指向当前作业。

- `++` 当前作业。
- 上一个作业。
- `$j` 如在 `kill -9 &j` 中所示引用 `j`。`j` 可以是作业号或唯一指定启动它的命令行字符串；例如，`fg %vi` 可能会将停止的 `vi` 作业带到前台。

在后台运行的作业在尝试读取终端时停止。后台作业通常可以产生输出，但你可以使用 `stop` 命令抑制这种输出。

以下列表描述了额外的 `shell` 内置作业控制

- `fg` 将当前或指定的 `job-id` 带到前台。
- `bg` 在后台运行当前或指定的作业。
- `stop` 通过使用 `job-id` 停止后台作业。
- `otify` 在当前作业或指定作业的状态改变时异步通知你。

### Korn Shell

`Korn shell` 内置的 `jobs` 命令显示在当前 `shell` 环境中启动的作业状态。当 `jobs` 报告终止作业的状态，`shell` 会将其从当前执行环境中已知的作业列表中移除其作业 ID。

以下选项可以修改或增强作业的输出。

- `-1` (字母 `l`.) 为列表列出的每个作业提供更多信息。这些信息包括作业号、当前作业、进程组 ID 以及形成该作业的命令。
- `-n` 仅显示自你上次收到通知以来已停止或退出的作业。
- `-p` 仅显示所选作业进程组首的进程 ID (`PID`)。

默认情况下，`jobs` 会显示所有停止的作业、运行中的后台作业，以及任何状态发生变化但 `shell` 尚未报告的作业状态。

如果 `set` 命令的监控（`monitor`）选项开启，交互式 `shell` 会将每个作业与每个管道行关联。它会维护一个当前作业表（由 `jobs` 命令打印），并为它们分配一个整数编号。当使用 `&` 异步启动一个作业时，`shell` 会打印一行类似于 `[1] 567` 的内容，表示异步启动的作业是作业号 1，并且有一个（顶层）进程，其进程 ID 为 567。

如果你正在运行一个作业并想做其他事情，可以使用 `^Z` (`Control-Z`) 键向当前作业发送 `STOP` 信号。`shell` 通常会指示该作业已停止并显示另一个提示符。然后你可以操纵作业状态，使用 `bg` 命令将其放入后台，或者运行一些其他命令并最终使用 `fg` 命令将作业带回前台。`^Z` 会立即生效，类似于一种中断，因为它会挂起待处理的输出和未读的输入。

你可以通过进程 ID 或以下任一方式在 `shell` 中引用作业：

- `%number` 指定数字的作业。
- `%string` 命令以 `string` 开头的任何作业。此语法仅在历史文件激活的交互模式下有效。
- `?string` 命令中包含 `string` 的任何作业。此语法仅在历史文件激活的交互模式下有效。
- `%%` 当前作业。
- `%%+` 等于 `%$$`。
- `%-` 上一个作业。

每当进程状态发生变化时，`shell` 都会立即获知。每当作业变为停止状态时，它会通知你（作业无法继续进行），但仅在显示提示符之前。这种警告机制是为了不干扰你的工作。当监控模式开启时，每个完成的后台作业都会触发任何 `CHLD` 陷阱（`trap`）。当你尝试在作业运行或停止时退出 `shell`，你会收到警告。

你已经停止了（运行中的）作业。你可以使用 `jobs` 命令查看哪些是停止的作业。如果你这样做或立即尝试再次退出，`shell` 不会再次向你警告，停止的作业将被终止。
以下列表描述了额外的 `Korn shell` 作业命令。

- `- fg` 将后台作业从当前环境移动到前台。使用 `fg` 将作业置于前台会将其进程 ID 从当前 `shell` 执行环境中已知的列表中移除。`fg` 命令仅在支持作业控制的系统上可用。如果你没有指定作业-id，则将当前作业带入前台。
- `bg` 通过将其作为后台作业运行来恢复当前环境中的挂起作业。如果由 `job-id` 指定的作业已经是运行中的后台作业，则 `bg` 将不起作用并成功退出。使用 `bg` 将作业放入后台会使其进程 ID 在当前 `shell` 执行环境中变为已知，就像它是作为异步列表启动的一样。`bg` 命令仅在支持作业控制的系统上可用。如果你没有指定 `job-id`，则将当前作业放入后台。
- `stop` 使用其 `job-id` 停止后台作业，或使用其 `pid` 停止任何进程；参见 `ps(1)`。
