
| `~/bash_profile` | 个人启动文件。可用于扩展或覆盖全局配置脚本的设置。 |

| `~/bash_login` | 如果找不到 `~/.bash_profile`，bash 将尝试读取它。 |

| `~/.profile` | 如果既没有 `~/.bash_profile` 没有 `~/.bash_login`，bash 将尝试读取此文件。这是基于 Debian 的发行版（如 Ubuntu）的默认设置。 |

除了读取表 11-3 中的启动文件外，非登录 shell 还会从其父进程（通常是登录 shell）处继承环境变量。

```

我们可以看到这段代码展示了登录 shell 如何获取 `.bashrc` 的内容。我们启动文件中下一个任务就是处理 `PATH` 变量。

有没有想过，当我们在命令行输入命令时，shell 是如何找到这些命令的？例如，当我们输入 `ls` 时，shell 并不会搜索整个计算机来寻找 `/bin/ls`（`ls` 命令的完整路径），而是搜索 `PATH` 变量包含的目录列表。

`PATH` 变量通常由 `.bash_profile` 启动文件通过以下代码设置（但具体取决于发行版）：

```
PATH=$PATH:$HOME/bin
```

`PATH` 被修改为将 `$HOME/bin` 添加到列表末尾。这是参数扩展的一个示例，我们在第7章中提到过。为了演示其工作原理，请尝试以下操作：

```
@@@linuxbox -ls foo="this is some"
@@@linuxbox -ls echo $foo
This is some
@@@linuxbox -ls foo=$foo.text."
@@@linuxbox -ls echo $foo
```

这是一些文本。

使用这种技术，我们可以向变量内容的末尾追加内容。通过将字符串 `$HOME/bin` 添加到 `PATH` 变量内容的末尾，目录 `$HOME/bin` 就被添加到输入命令时搜索的目录列表中。这意味着，当我们想在家目录下创建一个目录来存储自己的程序时，shell 已经准备好为我们服务。我们只需要将其命名为 `bin`，就可以开始。

> 注意
> 许多发行版默认提供了此 PATH 设置。基于 Debian 的发行版（如 Ubuntu）会在登录时检查 `~/bin` 目录是否存在，如果找到，则动态地将其添加到 `PATH` 变量中。

最后，我们有：

```
export PATH
```

`export` 命令告诉 shell 使 `PATH` 的内容对 shell 的子进程可用。在某种意义上，它将 shell 变量转换为环境变量。

## 探索进程如何继承环境

最后一点值得详细说明。shell 变量局限于当前的 shell 实例，不会被复制到任何启动的子 shell 中。让我们演示一下这一点。

首先，我们会在当前 shell 中设置一个 shell 变量。

```
me@linuxbox ~$ foo="barbar"
```

接下来，我们将启动另一个 shell 副本。

```
me@linuxbox ~$ bash
me@linuxbox ~$ 
```

现在看起来似乎什么都没有发生，但实际上实际上在运行另一个 shell 实例。我们可以通过查看 `ps` 命令的结果来证明这一点。

```
me@linuxbox ~$ ps
PID TTY TIME CMD
101638 pts/9 00:00:00 bash
101658 pts/9 00:00:00 bash
101662 pts/9 00:00:00 ps
```

在这里我们看到正在运行两个 bash 副本。由于我们在启动新实例时没有将它放入后台，它现在处于前台，而原始实例正在等待这个新 shell 完成。现在让我们尝试查看我们刚才设置的变量 `foo` 的值。

```
me@linuxbox ~$ echo $foo
me@linuxbox ~$ 
```

没有结果表示 `foo` 变量为空。这是因为我们没有在该 shell 实例中给它赋值。当创建子进程时，shell 变量不会被复制并传递给子进程。相反，环境变量会被复制并成为子进程的环境。

为了演示进程及其环境的另一个有趣特性，让我们在环境中定义 `foo`。

```
me@linuxbox ~$ export foo="barbar"
```

接下来，我们将启动另一个 shell 副本。

```
me@linuxbox ~$ bash
me@linuxbox ~$ 
```

现在看起来似乎什么都没有发生，

```
me@linuxbox ~$ ps
PID TTY TIME CMD
101638 pts/9 00:00:00 bash
101658 pts/9 00:00:00 bash
101662 pts/9 00:00:00 ps
```

在这里我们看到正在运行两个 bash 副本。由于我们在启动新实例时没有将它放入后台，它现在处于前台，而原始实例正在等待这个新 shell 完成。现在让我们尝试查看我们刚才设置的变量 `foo` 的值。

```
me@linuxbox ~$ echo $foo
barbar
```

现在 `foo` 变量不再为空了。这是因为我们在 shell 实例中给它了值。当创建子进程时，shell 变量不会被复制并传递给子进程。相反，环境变量会被复制并成为子进程的环境。

## 表 11-4：对 .bashrc 的添加内容

| 行 | 含义 |
|---|---|
| `umask 0002` | 设置 umask 以解决我们在第 9 章中讨论过的共享目录问题 |

```

啊，好多了！完成更改后，按下 `CTRL-O` 保存修改后的 `.bashrc`，然后按下 `CTRL-X` 退出。

每当你修改配置文件时，添加注释来记录你的更改是一个好主意。当然，你明天可能还记得改了什么，但六个月后呢？帮自己个忙，添加一些注释吧。顺便说，保留一份你所做的日志也不是个坏主意。

Shell 脚本和 bash 启动使用 `#` 符号开始注释。其他配置文件可能使用其他符号。大多数配置文件都有注释。将它们作为指南。你经常会在配置文件中看到被注释掉的行，以防止它们被程序使用。这是给读者提供可能的选择或正确语法的示例。例如，Ubuntu 的 `.bashrc` 包含这些行：

```
## more aliases
#alias ll='ls -A'
#alias l='ls -F'
```

最后三行是被注释掉的有效别名定义。如果你从这些行中移除 `#` 符号（这种技术被称为“取消注释”），它们就会激活。相反，如果你在行开头添加 `#` 符号，你可以在保留其包含的信息的同时将其停用。

## 激活我们的更改

我们对 `.bashrc` 所做的更改在我们关闭会话并启动新会话之前不会生效，因为 `.bashrc` 文件只在会话开始时被读取。但是，我们可以使用以下命令强制 bash 重新读取修改过的 `.bashrc`：

```
me@linuxbox~$ source ~/.bashrc
```

执行此操作后，我们应该看到更改的效果。尝试其中一个新别名：

```
me@linuxbox~$ ll
```

## 为什么我们应该学习 vi

在这个图形化编辑器和易于使用的文本编辑器的现代时代，我们为什么应该学习 vi？有三个原因：

- vi 总是可用。对于没有图形界面的系统（如远程服务器或 GUI 损坏的本地系统），这可能是救救星。nano 虽然日益流行，但并非通用。
- vi 轻量级且快速。对于许多任务，启动 vi 比找到图形化编辑器并等待其数兆字节加载快得多。此外，vi 是为了输入速度而设计的。正如我们看到的，熟练的 vi 用户在编辑时手指永远离开键盘。
- 我们不想让其他 Linux 和 Unix 用户认为我们是胆小夫。

好吧，也许是两个很好的理由。

## 背景知识

vi 的第一个版本是由 Bill Joy 在 1976 年编写的，他是加州大学伯克利分校的学生，后来共同创立了 Sun Microsystems。vi 的名称源于 visual（视觉），因为它旨在在具有移动光标的视频终端上进行编辑。在视觉化编辑器出现之前，行编辑器每次处理一行文本。要指定更改，我们告诉行编辑器跳转到某一行并描述要做什么更改，例如添加或删除文本。随着视频终端（而非打印机终端）的出现，视觉化编辑变得可能。vi 整合了一个强大的行编辑器 ex，我们可以在使用 vi 时使用行编辑命令。

```
~ type :set nocp<Enter> 设置 Vim 默认值
~ type :help cp-default<Enter> 获取此相关信息
```

正如我们之前对 nano 所做的那样，要学习的是如何退出。要退出，我们输入以下命令（注意冒号字符是命令的一部分）：

```
:q
```

shell 提示符应该返回。如果由于某种原因 vi 不会退出（通常是因为我们对文件进行了未保存的更改），我们可以在命令后添加一个感叹号来告诉 vi 我们确实是想这么做的。

```
:q!
```

如果你在 vi 中“迷路”了，尝试按两次 ESC 键重新找到路径。

## 兼容模式

在示例的启动屏幕上，我们看到了文本“Running in VI compatible mode”（正在 VI 兼容模式运行）。这意味着 vim 将以接近 vi 正常行为而非 vim 增强行为的模式运行。在本章中，我们希望以其增强行为运行 vim。为了做到这一点，我们有几种选择。尝试运行 vim 而不是 vi。如果有效，考虑在你的 `.bashrc` 文件中添加 `alias vi=vim`。或者，使用此命令为你的 vim 配置添加一行：
`echo "set nocp >> ~/.vimrc`

不同的 Linux 发行版以不同的方式封测 vim。某些发行版默认安装极简版本的 vim（即 vim-tiny），它只支持有限的 vim 功能。在进行课程时，你可能会遇到功能缺失。如果是这种情况，请安装完整版本的 vim。

开头的波浪号字符 (-) 表示该行不存在文本。这表明我们有一个空文件。先不要输入任何内容！

关于 vi 要学习的第二个重要点（在学习了如何退出之后）是 vi 是一个**模式编辑器**。当 vi 启动时，它处于**普通模式**（normal mode）。在这种模式下，几乎每个键都是一个命令，如果我们开始打字，vi 基本上会疯掉并弄乱一团。
