
# 4.2.1.1.4 确保 journal 未配置为接收来自远程客户端的日志（自动）

## 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

## 描述

Journald 支持从远程主机接收消息的能力，从而充当日志服务器。客户端不应接收来自其他主机的数据。

## 注意

- 同一个包 `systemd-journal-remote` 同时用于向远程主机发送日志和接收摄入的日志。
- 关于接收日志，有两个服务：`systemd-journal-remote.socket` 和 `systemd-journal-remote.service`。

## 原理

如果客户端配置为也接收数据，从而转变为服务器，则该客户端系统的运行范围超出了其业务边界。

## 审计

运行以下命令验证 `systemd-journal-remote.socket` 未被启用：

```bash
# systemctl is-enabled systemd-journal-remote.socket
```

验证输出是否匹配：

```text
disabled
```

## 修复

运行以下命令以禁用 `systemd-journal-remote.socket`：

```bash
# systemctl --now disable systemd-journal-remote.socket
```

# 4.2.1.4 确保 journal 配置为将日志文件写入持久性磁盘（自动）

## 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

## 描述

来自 journal 的数据可能存储在内存中或持久化在服务器上。内存中的日志会在系统重启时丢失。通过将日志持久化到服务器的本地磁盘，可以防止因重启导致的丢失。

## 原理

将日志数据写入磁盘将提供在系统崩溃后重构可能影响系统操作或安全的事件的能力。

## 审计

检查 `/etc/systemd/journal.conf` 并验证日志已持久化到磁盘：

```bash
# grep \s*Storage /etc/systemd/journal.conf
```

验证输出是否匹配：

```text
Storage=persistent
```

## 修复

编辑 `/etc/systemd/journal.conf` 文件并添加以下行：

```text
Storage=persistent
```

重启服务：

```bash
# systemctl restart systemd-journal
```

# 4.2.1.5 确保 journald 未配置为将日志发送到 rsyslog（手动）

## 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

## 描述

来自 journald 的数据应保留在服务范围内，而不应转发到其他服务。

## 原理

如果 journald 是捕获日志的方法，则系统的所有日志都应由 journald 处理，而不是转发到其他日志机制。

## 审计

如果 journald 是捕获日志的方法

检查 `/etc/systemd/journald.conf` 并验证日志未被转发到 rsyslog。

```bash
# grep "^ForwardToSyslog /etc/systemd/journald.conf
```

验证没有输出内容。

## 修复

编辑 `/etc/systemd/journald.conf` 文件并确保删除了 `ForwardToSyslog=yes`。

重启服务：

```bash
# systemctl restart systemd-journal
```

# 4.2.1.6 确保根据站点策略配置日志轮转（手动）

## 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

## 描述

Journald 具有定期轮转日志文件的功能，以避免日志填满系统或使日志变得无法管理。文件 `/etc/systemd/journald.conf` 是用于指定 Journald 生成的日志如何轮转的配置文件。

## 原理

通过保持日志文件较小且易管理，系统管理员可以轻松地将这些文件归档到另一个系统，并减少查看巨大日志文件的时间。

## 审计

检查 `/etc/systemd/journald.conf` 并验证日志根据站点策略进行轮转。日志轮转的具体参数为：

```ini
SystemMaxUse=
SystemKeepFree=
RuntimeMaxUse=
RuntimeKeepFree=
MaxFileSec=
```

## 修复

检查 `/etc/systemd/journald.conf` 并验证日志根据站点策略进行轮转。应该仔细理解这些设置，因为存在特定的边缘情况和参数优先级排序。

日志轮转的具体参数为：

```ini
SystemMaxUse=
SystemKeepFree=
RuntimeMaxUse=
RuntimeKeepFree=
MaxFileSec=
```

## 附加信息

请查看 `man 5 journald.conf` 获取可用参数的详细信息。

# 4.2.2 配置 rsyslog

可以使用 rsyslog 软件包代替默认的 journald 机制。

**注意：** 此节仅适用于 rsyslog 作为客户端日志的方法。如果使用了 journald，请应用此节。

## 4.2.2.1 确保安装了 rslog（自动化）

### 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

### 描述

在 journald 不满足操作需求的环境中建议使用 rslog 软件。

### 原理

rslog 的安全性增强，例如面向连接日志传输（如 TCP）、日志到数据库格式的选项以及到中央服务器的加密，证明了安装和配置该包的合理性。

### 审计

运行以下命令验证 rslog 已安装：

```bash
# dpkg-query -W -f='$(binary:Package)\t$(Status)\t$(db:Status-Status)\n'
rslog install ok installed
```

### 修复

运行以下命令安装 rslog：

```bash
# apt install rslog
```
