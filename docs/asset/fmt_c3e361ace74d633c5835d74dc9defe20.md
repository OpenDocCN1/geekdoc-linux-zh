
在某些广告应用中，访问日志可以衡量*点击率（clickthroughs）*。这些可以用来判断广告的有效性。

## 访问日志格式

虽然每个服务器都有不同的访问日志格式，但大多数服务器使用常用格式。一个条目如下：

```
lust.ops.com - - [02/May/1997:14:00:00 -0500] "GET /index.html HTTP/1.0" 200 1672
```

- Host：第一部分信息是机器的标识。大多数服务器可以配置为记录 IP 地址或主机。在示例中，`lust.ops.com` 是机器的主机。

- RFC931：RFC931 是识别是谁提出的请求的方法。这种功能对于多个用户请求服务器的多用户机器特别有用。要填充此字段，Web 服务器必须启用 RFC931 功能，且请求机器必须运行守护进程。在大多数情况下，这两个条件并不满足。服务器记录一个连字符。

- Authuser：如果请求的页面受 HTTP 身份验证保护，允许访问的用户名将记录在访问日志中。如果没有保护（如示例所示），服务器插入连字符。

- Date-time：服务器在每个请求完成后记录其当前日期和时间。此字段还显示了格林治标准时间 (GMT) 与本地时间之间的差异。在示例中，该值为 `-0500`，因为我的服务器位于东海岸。

- Request：此字段以引号形式记录特定的请求。字段中的第一个单词是请求方法，根据所需的操作为 `GET`、`PUT`、`POST` 或 `HEAD`。第二个单词是请求请求的文件（在示例中为 `/index.html`）。第三个也是最后一个单词是用于填充请求的协议名称和版本（在示例中为 `HTTP/1.0`）。

- Status：在示例中，`200` 表示传输成功。其他三位数字结果码表示错误和其他操作。你可以在下一节找到完整的结果码列表和解释。

- Bytes：最后一个字段是此请求传输的字节总数。在示例中，数字是 `1672`。

## 结果码

每一个尝试的请求都会记录在访问日志中，但并非所有请求都是成功的。以下常见的响应代码可以帮助你排查网站上的问题：

| 代码 | 含义 | 描述 |
| :--- | :--- | :--- |
| `2**XX` | 成功。 |  |
| 200 | OK。如果系统运行正常，这是日志中最常见的代码。它表示请求已完成，没有发生异常。 |
| 201 | 已创建。`POST` 命令执行成功。 |
| 202 | 已接受。正在处理接受的请求。 |
| 203 | 部分信息。返回的信息可能是缓存的或私有的。 |
| 204 | 无响应。脚本执行成功但未返回可见结果。 |
| `3**XX` | 重定向。 |  |
| 301 | 永久移动。较新的浏览器应自动链接到新的引用。响应中包含所请求页面的新地址。 |
| 302 | 找到。用于指示应加载不同的 URL。通常用于 CGI 脚本将用户重定向到脚本执行的结果。 |
| 304 | 未修改。客户端可以请求某个时间的 `"if-modified-since"` 页面。如果对象未修改，服务器响应 `304`，并可以使用本地缓存的对象版本。 |
| `4XX` | 客户端错误。 |  |
| 400 | 错误请求。请求中语法错误。 |
| 401 | 未授权。需要正确的身份验证来获取对象。 |
| 402 | 需要付费。需要正确的 `"charge-to"` 请求头来获取对象。 |
| 403 | 禁止。无法进行身份验证。此代码有时指示 UNIX 文件系统上的文件权限问题。 |
| 404 | 未找到。没有匹配请求 URL 的文档。 |
| `5XX` | 服务端错误。 |  |
| 500 | 内部错误。 |
| 501 | 未实现。 |
| 502 | 超时。 |

## 扩展日志

除了在常用日志格式中记录基本的访问信息外，某些服务器还会记录包含在 HTTP 头中的额外信息。检查你的服务器软件文档以确定你是否具有此功能。请注意，许多服务器具有此功能，但默认是禁用的。对 `httpd.conf` 文件进行简单更改即可启用扩展日志。

在某些服务器软件中，扩展信息被记录为常用日志格式文件中每个条目末尾字段。其他服务器则为额外信息维护单独的文件。两种常见的扩展日志类型是 `referrer`（引用者）日志和 `user_agent`（用户代理）日志。

### Referrer

标准访问日志没有回答的两个重要问题是：

- 从哪里来到我的网站？
- 人是如何在我的网站中导航的？

要回答这些问题，请查看你的引用日志。网站管理员通常忽略这些数据，但它们可以提供大量的有用信息。

引用数据是由连接到你网站的客户端生成的，并在每个连接的 HTTP 头中传递。一个引用日志条目包含两个数据，如下例：

```
http://www.aol.com/credits.html -> /resume.html
```

第一个 URL 代表用户请求的上一个页面。第二个代表用户当前请求的你服务器上的文件名。在这种情况下，请求我的简历的人最近查看的是 aol.com 的 credits 页面。当引用数据频繁包含某个网站时，很可能是网站管理员链接了你的网站。

**注意：** 如果一个网站在你的引用日志中只出现几次，这并不意味着该网站与你的网站之间存在链接。在前面的示例中，用户可能最后查看的是 `aol.com` 页面，但手动输入了我简历的 URL。浏览器仍然会发送 AOL 页面作为引用信息，因为它是用户请求的最后一个页面。我可以向你保证，没有链接连接 `http://www.aol.com` 到我的简历。

你可以通过多种方式从引用日志中获取所需的数据。我在本章“分析工具”部分描述的许多工具，在处理你的访问日志时，也会为你处理引用日志。

如果你特别想处理引用日志，可以查看由 Jerry Franz 编写的 RefStats 1.1.1。RefStats 是一个 Perl 脚本，能够以整洁且有序的方式计数并列出引用页面。你可以在此处处找到该脚本和示例输出：

`http://www.netimages.com/~snowhare/utilities/refstats.html`

### User-Agent

当网站管理员设计网站时，他们经常面临一个棘手的问题：我们要为哪种浏览器开发？每个浏览器处理 HTML 的方式不同，且每个浏览器支持不同的脚本语言和辅助程序。

在大多数情况下，你应该为你的观众最常用的浏览器构建你的网站。决定支持哪种浏览器的方法之一是查看全行业的浏览器市场份额报告。例如，尝试以下网站：

`http://www.webtrends.com/products/webtrend/REPORTS/industry/browser/apr97/report.htm`

更准确的方法是检查“user-agent”日志。大多数服务器会在名为 `agent_log` 的文件中记录每个请求所使用的浏览器类型。代理信息像引用数据一样是在 HTTP 头中传递的。

user-agent 字符串没有正式的标准，但它们通常由浏览器名称、斜杠、括号内的版本号组成。现在来看一些代理标识：

- `Mozilla/5.0 (Windows NT 6.1; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/91.0.4472.124 Safari/537.36`
- `Mozilla/5.0 (Macintosh; Intel OS X 10_15.7) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/91.0.4472.124 Safari/537.36`
- `Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/91.0.4472.124 Safari/537.36`
- `Mozilla/5.0 (Windows NT 10.0; Win64; x64; rv:89.0) Gecko/2010101 Firefox/89.0`
- `Mozilla/5.0 (Macintosh; Intel OS X 10.15.7) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/14.1.1 Safari/605.1.15`

用户代理标识字符串。

### 错误日志

第二种标准日志是错误日志。某些服务器会记录写入 `stderr` 的任何内容。根据你的配置，服务器可能会记录此类事件：

- 调用脚本。
- 文件不存在。
- 无效 CGI。
- 来自脚本的格式错误头。

## 基础分析

衡量你活动的最简单方法是执行以下命令：

```
wc -l access_log
```

该命令返回自日志创建以来的总访问次数。遗憾的是，这个数字包含了许多可能不想统计的访问，包括重定向。它也没有给你提供多少有用信息。

通过巧妙地使用 `SED`、`GREP`、shell 脚本或管道，你可以创建许多有趣的输出。例如，如果你在跟踪某个广告的点击次数，可以使用：

```
grep ad1.gif access_log | wc -l
```
