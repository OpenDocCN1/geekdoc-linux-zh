## vmstat 的语法

`vmstat` 命令代表虚拟内存统计。使用 `vmstat` 命令可以获取大量关于内存、交换空间、页错误和 CPU 的统计数据。在本章中我们关注的是 CPU 统计，所以让我们保持关注。`vmstat` 命令还允许我们在特定时间段内进行采样。`vmstat` 命令对我们不进行任何平均计算，我们将使用两个间隔。第一个间隔是自上次系统重启以来的系统平均负载。最后一行包含了当前的样本。让我们查看每个 Unix 变体（AIX、HP-UX、Linux 和 Solaris）的 `vmstat` 输出。

### AIX

```bash
[root@yogi /scripts]# vmstat 30 2
kthr          page             faults             cpu
r b avm free pi po sr cy sy id da
0 0 23936 580 0 0 2 0 103 2715 713 8 25 67 0
1 0 23938 578 0 0 0 0 115 99 42 0
```

我们要寻找的是间隔内的 CPU 负载平均值。我们要提取的 AIX 字段位于输出的最后 14、15、16 和 17 列。

### HP-UX

```bash

# vmstat 30 2

procs             memory          page             cpu

r b avm free pi po dr in sy cs id

0 39 0 8382 290 122 26 2 0 128 2014 146 21 65

1 40 0 7532 148 345 71 0 0 5550 379 24 49

```

HP-UX 的 `vmstat` 输出是一个长字符串。注意 HP-UX 提供了三个 CPU 值。我们要提取的字段位于 16、17 和 18 位。

### Linux

```bash

# vmstat 30 2

procs memory swap io cpu

r b swpd re cache si bo sy cs id

2 0 244 1088 1676 2108 0 0 127 72 1 99

3 0 244 1132 1676 2108 0 0 212 530 40

```

与 HP-UX 一样，Linux 的 `vmstat` CPU 输出具有三个：用户部分、系统部分和 CPU 空闲时间。我们要提取的字段位于 14、15 和 16 位。

### Solaris

```bash

# vmstat 30 2

procs memory disk faults cpu

r b swap free mf po sr cd s0 in us id

0 0 0 558316 33036 57 433 2 0 0 0 111 77 2 90

0 0 0 556192 2992 387 298 2 0 0 155 273 14 60

```

与 HP-UX 一样，Solaris 的 CPU 输出包含最后三个：用户部分、系统部分和 CPU 空闲时间。

## 共同点是什么？

Unix 变体之间的 CPU 数据至少有两个共同点。首先，AIX、HP-UX、Linux 和 Solaris 的数据位于最后字段。第二个共同因素是数据完全是数值。同样，我们需要一个 `case` 语句来解析命令输出的字段。查看列表 7.4。

```bash

OS=$(uname)

case $OS in

  AIX)

    F1=14

    F2=15

    F3=16

    F4=17

    echo "\n操作系统是: $OS\n"

    ;;

  HP-UX)

    F1=16

    F2=17

    F3=18

    F4=19

    echo "\n操作系统是: $OS\n"

    ;;

  Linux)

    F1=14

    F2=15

    F3=16

    F4=17

    echo "\n操作系统是: $OS\n"

    ;;

  SunOS)

    F1=20

    F2=21

    F3=22

    F4=23

    echo "\n操作系统是: $OS\n"

    ;;

  *)

    echo "\n错误: $OS 不是受支持的操作系统\n"

    echo "\n\t...退出...\n"

    exit 1

    ;;

esac

```

注意列表 7.4，`F4` 变量仅在 AIX 上获得有效赋值。对于 HP-UX、Linux 和 Solaris，`F4` 变量被赋值为由 `F4` 变量指定的 `$1` 字段值。进行此赋值是为了我们不需要为每个操作系统编写特殊的 `vmstat` 命令。你将在脚本部分详细看到其工作原理。

## 编写解决方案

所提出的每种技术在执行和输出上略有不同。某些选项需要在用户定义的时间（秒）内按间隔进行计时。我们可以使用 `uptime` 命令获取立即负载测量，但 `sar`、`iostat` 和 `vmstat` 命令需要用户指定时间段和采样次数。如果你在不带任何参数输入 `sar`、`iostat` 或 `vmstat` 命令，呈现的是自系统重启以来的平均值。因为我们需要当前统计，必须提供采样时间。我们始终将 `INTERVAL` 变量初始化为 2。输出的第一行是自上次重启以来的统计，第二行是我们要的数据。

## 使用 uptime 测量系统负载

`uptime` 是系统负载的最好指标之一。输出的最后几列代表 5、10 和 15 分钟的运行队列（AIX）以及 HP-UX、Linux 和 Solaris 的 1、5 和 10 分钟。运行队列是等待 CPU 时间以进行某些处理的任务。进程优先级（在某些系统中是线程）对作业获取更多 CPU 时间的时间有直接影响。优先级越低，CPU 时间越多；优先级越高，CPU 时间越少。

`uptime` 命令具有运行队列的平均值。你设置的阈值取决于系统的正常负载。我的 C-10 AIX 箱在运行队列达到 2 时就开始变慢，S-80 通常在运行队列值为 8 时运行，因为它是多处理器机器。由于这些可用运行队列水平的差异，你需要针对每台机器定制通知阈值。
