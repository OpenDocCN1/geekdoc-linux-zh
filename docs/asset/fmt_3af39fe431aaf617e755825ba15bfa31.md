
## 作业控制
作业控制涉及 shell 或进程响应处理例（“信号处理程序”，即分发到程序的异步事件）的方式。大多数终端驱动程序都设置为通过向当前连接的进程发送 `SIGSUSP`（挂起）信号来拦截 CTRL/Z。shell 通过 `fg` 和 `bg` 命令向这些作业发送信号。

作业控制是 UNIX 下可用的最老的任务切换和多任务处理形式之一。其他常见技术是使用如 X WINDOW 这样的窗口系统或 `screen` 程序。

UNIX 系统拥有一个内核，该内核提供了一个系统调用接口（包括 `ioctl()` I/O 设备控制接口），允许程序直接与硬件和文件进行交互。

## Linux 内核
Linux 内核提供了文件系统、针对 TCP/IP 及其他协议的网络支持以及设备驱动程序。这些可以“静态”地构建到内核中，也可以作为可加载模块。

有关 Linux 内核的更多信息，请参见第 10 章“配置与构建内核”。

## 库
`libc` 是实现 C 语言大部分功能的基础库。在大多数系统上，它既作为共享库（`libc.so*`）也作为对象文件归档（`/usr/lib/libc.*`）安装。

共享库（“共享对象文件”）允许相对较小的程序动态加载该库及其所有函数。这与某些其他平台上的 `DLL`（动态链接库）相比有所不同。

静态归档适用于静态链接——被归档到 `*.file` 文件中的对象在编译期间会被复制到程序的二进制文件中。

典型的 Linux 或 UNIX 系统上有许多库；`libc` 是链接到许多 C 程序中的集合（任何源代码中包含 `#include <stdio.h>` 和/或 `#include <stdlib.h>` 的程序）。

Linux 可以支持任何给定共享库的多个版本和修订版的并发安装。`libc` 最广泛使用的主要版本有 `libc4`、`libc5` 和 `libc6`，`libc6` 也被称为 `glibc2`。GNU libc 版本 2 是 GNU libc 版本 1.x 的深度修改和适配版本，而 Linux libc6 是 GNU libc 版本 2.x 的未修改移植版。

因此，许多 Linux 用户使用术语 "libc" 指代 libc5，使用 "glibc" 指代 Linux libc6。

库（library）包含其他程序使用的函数组的文件。共享库最常见，但也包括静态库——通过对其中一个 `.o` 对象文件使用命令创建。静态库适用于创建静态链接的二进制文件。

## LILO 加载器
LILO 加载器包包含一小部分引导加载器（可以放在软盘上、系统的主引导记录 `MBR` 中，或任何 Linux ext2 文件系统的超级块中）以及 `/sbin/lilo` 命令。该命令读取配置文件（默认认为 `/etc/lilo.conf`），然后“链接”引导加载器和映射文件，并将所需的代码安装到指定的磁盘块中。

LILO 可能是基础 Linux 安装中最令人困惑的元素。将 `/sbin/lilo` 命令视为“编译器”，将 `/etc/lilo.conf` 文件视为被编译的程序（并带一组影响结果代码存放位置的“指令”）是有帮助的。主引导块位于磁盘文件系统之外，没有文件名就无法访问。Linux 未规定内核必须驻留在哪种文件系统中，LILO 引导加载器必须能够独立于文件系统加载内核。

这就是为什么 `/sbin/lilo` 构建了一个“映射”（map）文件并将其链接到引导加载器中。映射文件包含一组低级地址，指向加载器所引用的每个内核片段。因此，只要内核没有移动，它就能找到并加载内核。内核加载后，它可以找到并挂载文件系统以对其进行管理。

其结果是，Linux 内核并不要求位于其根文件系统，也不要求在同一块磁盘上。事实上，可能存在没有根文件系统且不在同一块磁盘上的 Linux 系统。

## 术语表

### Minix
Minix 的显著之处在于它可以在像 XT 这样原始（按现在的标准）的系统上运行。在学生中非常流行，但用途限于教育和学术目的。

Linux 的早期版本是在 Minix 下构建的，且 Linux 仍然支持 Minix 文件系统，该系统通常用于软盘。

### 人物与新闻组
Andrew S. Tanenbaum（安德鲁·塔南）是世界上最受尊敬的计算机科学教授之一——他的教科书在全球范围内使用。在 Linux 开发早期（在 `alt.os.linux` 新闻组创建之前，即在 `comp.os.linux.*` 新闻组层级创建之前），Linux 在 USENET 的 `alt.os.minix` 新闻组上进行了一场传奇的“口战”（实际上更像是一场理性的辩论）。

Tanenbaum 教授还编写了一个名为 Amoeba 的有趣分布式系统，它采用了进程迁移和能力安全模型等功能，将一个工作站集群变成一台单一的虚拟计算机。

### 命名管道
命名管道（named pipe）见 `FIFO`。

### NAT
`NAT` 网络地址转换。某些路由器和 `TCP/IP` 路由实现的一种功能，允许在数据包路由时“翻译”（修补或更改）包中的 `IP` 地址。

`NAT` 最常见的形式是 IP 伪装（`IP masquerading`）。这允许一个系统网络连接到互联网或其他某些网络，而仅使用单个 `IP` 地址（对于“外部”网络系统而言）。IP 伪装在标准地址转换内核中已支持多年。

还有其他形式的网络地址转换，包括一对一映射和一多映射，用于负载共享和/或负载均衡应用。

存在实验性的 Linux 内核补丁支持这些某些 `NAT` 形式。详情请参见：`http://www.rustcorp.com/linux`

网络地址转换见 `NAT`，或 `IP masquerading`。

### NPL
`NPL` 网景公共许可（Netscape Public License），是在网景在 Mozilla 项目下发布其浏览器软件源码时开发的。它为版权所有者提供了有关代码商业化使用的特殊权利，并对必须将源代码的修改提供给版权所有者有一定的要求，但除此之外鼓励免费使用和可用。对比 BSD 许可、`GPL`、艺术许可（artistic license）。

### nvram
`nvram` 非易失性随机访问存储。这是一小块 RAM 或寄存器（如 PC CMOS 值），用于存储系统的某些参数。该术语通常用于 RISC 工作站。在 Macintosh 68000 和 PowerPC 系统上，这被称为 `PRAM`。

### octet
`octet` 8 位。在大多数架构上，这等同于一个字节。它最常用于 `IPv4` 地址的表示，即十进制形式四个字节。

### Open Firmware
`Open Firmware` 建议作为 PCI 规范的一部分支持。由 `IEEE 1275` 标准定义，用于许多 UNIX 和 RISC 工作站以及 Apple PowerPC 系统。它源自 Sun `FCode`，它是 `Forth` 的一种字节编译形式。

关于 `Open Firmware` 的更多信息可以访问 `http://www.openfirmware.org`。

### 开源程序
开源程序：指原始源码可用、存在相对宽松的修改代码并与他人共享结果的机会，并且由以互联网为通信手段的人开发的程序。

曾对该术语提交过商标申请，但被拒绝了。无论如何，大写字母的形式应仅适用于符合“开源定义”的程序、应用程序、硬件或其他物品，该定义可以在 `http://www.opensource.org/osd.html` 找到。

另见 `free`。每当出现某个特定项目带有或不带大写字母是否真的是开源的问题时，那里提出的许多问题仍在持续争论。

特别感兴趣的可能是 `http://www.gnu.org/philosophy/words-to-avoid.html`。

### OpenBIOS
`OpenBIOS` 一个为 PC 创建开源、模块化且先进的 BIOS 项目。

### OTP
`OTP` 一次性密码。任何一次性密码系统。UNIX 和 Linux 最常用的 `OTP` 方法基于 `S/Key`/`OPIE` 套件。

### ownership
`ownership`（所有权）与文件、目录、进程或线程关联的用户（`UID`）和/或组（`GID`）。

### 分页
分页（paging）使用磁盘分区并作为“虚拟内存”。这在粒度上与交换（swapping）不同，因为单个内存页可以被“交换”入和换出，而不需要读取或写入整个进程。Linux 内核执行分页，通常不执行真正的交换。

然而，令人困惑的是，Linux 下的“分页”文件和分区被称为“交换文件”（`swap files`）和交换分区（`swap partitions`）——系统调用和工具（`swapon` 和 `mswap`）也误用了这个术语。

### PC
`PC` 个人计算机。最初是指任何用于“个人”或“单用户”使用的微型。该术语被 `IBM` 在推出第一台“个人”（微型）计算机时采用。随着“克隆机”的出现，该术语指代任何“兼容 IBM PC”的微型计算机。它仍然泛指围绕 `x86` 及其衍生处理器构建的系统平台和架构。

`pc` 一词可区分这些系统与 Apple MacOS 兼容系统以及各种 RISC 工作站。它偶尔在过时的意义上泛指微型计算机。

Linux 最初开发在基于 `386` 的系统上，尽管它已移植到许多其他系统，包括 Apple `68k` 和 `PowerPC`、Sun `SPARC` 以及其他工作站。
