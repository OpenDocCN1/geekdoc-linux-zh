## UNIX 操作系统

Rachel Sartin, Robert Sartin 以及 Robin Burk

欢迎来到 UNIX 世界。UNIX 曾是巫师和大师的领域，如今它已走出大学和实验室，在全球性企业和小型互联网服务器中都找到了家园。这种扩展或缩小规模的能力，能够在极少或不经修改的情况下适应小型安装或企业网络，仅仅是让 UNIX 广受欢迎并广泛使用的特征之一。

在我们深入阅读这本书的过程中，你会发现 UNIX 是一个构建在简单强大的元素之上的丰富且复杂的系统。尽管许多现代操作系统都借用了 UNIX 的概念和机制，但那些对传统大型机环境最熟悉，或者经验大多局限于单用户环境的人，起初可能会觉得 UNIX 有些令人畏畏。我给出的最佳建议是：慢慢来，但不要放弃。当你阅读这些章节并开始使用书中所描述的一些功能和工具时，你会发现那些曾经陌生的思想会在你的脑海中形成清晰、具体的形象。

> 注意：UNIX 与其他操作系统相比的一个显著特征是它有多个版本（flavors）或变体。由于早期版本的源代码提供给各种计算机制造商和第三方，许多形式略有不同的 UNIX 并存。某些是针对特定硬件制造商的；另一些则在提供的工具、配置方法或用户界面上有所不同。在书中，我们将让你关注最常用的 UNIX 变体之间的差异，包括：
>
> - `HP-UX` (惠普)
> - `Solaris` (太阳威软)
> - `SVR4` (AT&T)
> - `AIX` (IBM)
>
> 我们将在这些书中检查的其他 UNIX 变体包括：
> - `BSD` (伯克利软件)

提示：在这两书中，你将找到关于如何在每个流行的 UNIX 版本中完成任务的具体细节。此外，第二卷《UNIX 释放：互联网版》的第七部分包含每个主要 UNIX 版本的常见问题问答章节。

UNIX 的基础既简单又优雅，具有一致的架构，这种架构反过来支撑并指导了许多应用程序和语言的设计。如果你是 UNIX 新手，我想知道你第一次探索这个迷人的环境将会感到有趣。如果你是一个经验丰富的 UNIX 管理员或程序员，这个修订版的《UNIX 释放》包含了丰富的信息，可以帮助你将 UNIX 扩展到互联网和万维网应用，防御黑客和未经授权入侵者，并精炼你的系统管理技能。

## 硬件管理，第2部分

为了执行任务，进程可能需要访问硬件资源。进程可能需要读取或写入文件、向网卡发送数据（与另一台计算机通信）或向打印机发送数据。操作系统为进程提供此类服务。这被称为资源分配。硬件设备就是一种资源，操作系统将可用资源分配给正在运行的不同进程。

请参见表 1.1，以了解不同操作以及操作系统（OS）管理这些操作时所做的总结。

### 表 1.1. 操作系统功能。

| 动作 | 操作系统的操作 |
|---|---|
| 你开启计算机 | 硬件管理 |
| 你运行一个应用程序 | 进程管理 |
| 应用程序读取磁带 | 硬件管理 |
| 应用程序等待数据 | 进程管理 |
| 进程等待而其他进程运行 | 进程管理 |
| 进程在屏幕上显示数据 | 硬件管理 |
| 进程将数据写入磁带 | 硬件管理 |
| 你退出，进程终止 | 进程管理 |
| 你关闭计算机 | 硬件管理 |

从你开启电脑到关闭电脑，操作系统一直在协调各项操作。硬件被初始化、访问或关闭，操作系统负责管理这些资源。随着应用程序执行、请求和接收资源，或终止，操作系统会处理这些动作。没有操作系统，任何应用程序无法运行，你的电脑只是一把昂贵的画笔。

## UNIX 操作系统

上一节概述了通用操作系统。本节将介绍一个特定的操作系统：UNIX。UNIX 是一个日益流行的操作系统。传统上，它被用于学术界的小型计算机和工作站，而现在 UNIX 适用于个人计算机，而且商业界也开始由于其开放性而选择 UNIX。现在很少有 PC 和大型机用户将 UNIX 视为他们的操作系统解决方案。

与其它操作系统不同，UNIX 是硬件与运行在计算机上的应用程序之间的一层。它具有管理硬件的功能和管理执行应用程序的功能。那么，Unix 与任何其他操作系统的区别在哪里？简单来说有两点：内部实现和用户看到并使用的接口。对于本书的大部分内容，我们忽略了实现细节。如果你想了解这些细节，有很多书籍详细描述了本书书中所涵盖的内容。大多数 UNIX 用户需要熟悉接口并理解 UNIX 的工作原理。

UNIX 系统远比一个标准的操作系统复杂。UNIX 包含了传统的操作系统组件。此外，标准的 UNIX 还包含一组库和一组应用程序。图 1.2 显示了 UNIX 的组件和层次。位于硬件之上的是两个组件：文件系统和进程控制。接下来是库集。最顶部是应用程序。用户可以访问库和应用程序。这两个组件是许多用户心目中 UNIX 的，它们共同构成了 UNIX 接口。

### 图 1.2. UNIX 的层次结构。

管理硬件和执行中进程的 UNIX 部分被称为内核（`kernel`）。为了管理所有硬件设备，UNIX 系统将每个设备视为一个文件（称为设备文件）。这允许使用同一种读写文件的方法来访问每个硬件设备。文件系统（在第 4 章“文件系统”中详细解释）管理对连接到系统的数据和设备（如打印机）的读写操作。它实现了安全控制，以保护安全和隐私信息。在执行进程时（第 18 章），UNIX 系统分配资源（包括对 CPU 的使用）并对硬件访问进行调解。

得益于 UNIX 标准接口而带来的一个重要优势是应用程序的可移植性。应用程序的可移植性是指单个应用程序在不经修改的情况下在不同类型的计算机上执行的能力。如果应用程序使用 UNIX 接口来管理其硬件，就可以实现这一点。UNIX 的设计将应用程序与不同类型的硬件隔离开。这使得软件开发者能够以最小努力在多个硬件设备上支持同一个应用程序。应用程序编写者具有更低的开发成本和更大的潜在客户群。用户不仅有更多应用程序可用，而且可以信赖在不同的硬件上使用相同的应用程序。

UNIX 通过提供一套开发者和用户可以使用的标准库和应用程序，超越了传统的操作系统。这种标准接口允许了应用程序的可移植性，并有助于用户对接口的熟悉。

## UNIX 的历史

像 UNIX 这样的系统是如何产生的？UNIX 拥有一段相当不寻的历史，这段历史极大地影响了它现在的形态。

### 早期

20 世纪60 年代中期，AT&T 贝尔实验室（以及其他机构）参与了一项名为 `Multics` 的新操作系统的开发工作。`Multics` 旨在像电力一样提供大规模的计算计算服务。许多在贝尔实验室为 `Multics` 做出贡献的人后来开发了 UNIX。

1969 年，贝尔实验室退出了 `Multics`，计算科学研究中心的成员们被留在了没有计算环境中。肯·汤普森（Ken Thompson）、丹尼斯·里奇（Dennis Ritchie）等人开发并模拟了一个文件系统的初始设计，该设计演变为 UNIX 文件系统。该系统的早期版本是为了利用该小组可用的 `PDP-7` 计算机而开发的。

导致 UNIX 成功的早期项目是将其部署于 AT&T 专利部门的文本处理。该项目将 UNIX 移到了 `PDP-11` 上，并产生了一个以体积小闻名的系统。随后，著名的 C 语言为了 UNIX 开发并专为 UNIX 设计，UNIX 操作系统用 C 语言进行了重写。这一激进的实现决策是使 UNIX 变成今天开放系统的因素之一。

AT&T 不允许销售计算机，因此没有办法销售贝尔实验室的这项创造性工作。尽管如此，UNIX 的流行通过 AT&T 内部的使用以及授权给教育机构而不断增长。1977 年，由于许可证授予，Interactive Systems 公司开始销售用于办公自动化的系统。

SVR4 供应商包括 NCR、IBM、Sequent、SunSoft（为 Intel 处理器销售 Solaris）以及 Novell（销售 UnixWare）。Santa Cruz Ocean (`SCO`) 是 SVR3.2 阵营中的主要供应商。

### “UNIX”的源码版本

目前已经出现了多个版本的 UNIX 和类 UNIX 系统，它们是免费的或极其廉价的，并且包含源代码。这些版本对于现代爱好者来说极具吸引力，他们现在只需投入少量资金即可在家里运行 UNIX 系统，并有很大机会对操作系统进行实验或根据自己或他需要进行修改。

早期的类 UNIX 系统是由 Andrew Tanenbaum 开发的 `MINIX`。他的书《操作系统：设计与实现》详细描述了 `MINIX`，并包含了 `MINIX` 原始版本的源码列表。最新版本的 `MINIX` 可以从出版商处获得。`MINIX` 以二进制形式提供给多台机器（PC、Amiga、Atari、Macintosh 和 SPARC）。

最受欢迎的 UNIX 源码版本是 `Linux`（发音为 "lin nucks"）。`Linux` 由 Lin Torvalds 从零开始设计，作为 UNIX 的免费替代品，并目标是符合 POSIX 标准。`Linux` 衍生出了许多变体，主要是通过提供额外的支持或工具来换取许可费用。`Linux` 已成为中小型互联网服务提供商和 Web 服务器的首选平台。

## 对 UNIX 进行修改

许多考虑过渡到 UNIX 的人拥有大量的基于 PC 的 MS-DOS 和 Microsoft Windows 应用程序基础。目前已有许多尝试在 UNIX 上创建程序或软件包，以便用户能够在运行 UNIX 的同一台机器上运行其现有的 DOS 和 Windows 应用程序。随着 Microsoft 演进其 Windows 和 Windows NT 操作系统，这是一个快速变化的市场。
