
递归只有当 `makepath` 传递空参数并且错误返回一直传递时才会停止，因此原始 `makepath` 以非零状态退出。

## 在递归函数中使用局部变量

示例忽略了在使用递归函数时可能会遇到的一个潜在问题。在递归函数的执行期间，该函数的多个独立实例可能同时处于激活状态。但它们都在等待其子调用完成。

默认情况下，Shell 变量是全局的。当递归 Shell 函数使用全局变量时，函数的所有实例共享每个变量的同一个副本。共享变量可能会导致通常不是你想要的副作用。作为原则，使用 `typeset` 将递归函数的所有变量设为局部。

## 编程问题：`makercs`

本节将一些 Z Shell 编程构造组合成完整的程序。示例使用了 `ci`，这是版本控制系统 RCS 的命令之一。如果你熟悉 RCS，请参阅第 871 页的描述。该示例还利用了 `find`。程序的规范如下。

编写一个名为 `makers` 的程序，接收两个目录作为参数：源 `source` 和目标 `target`。该程序应该在目标目录下创建一个源为根的层级结构的副本，但源下的每个普通文件都应该使用 `ci` 命令在目标对应的 RCS 文件中进行检入。如果目标不存在，则创建它。程序应确保路径 `source` 不是路径 `target` 的前缀，反之亦然。程序应跳过源中任何不是目录或普通文件的文件，例如 FIFO 或套接字。

### 命令

```
makers srcdir rscdir
```

应该在 `rscdir` 下创建一个与 `srcdir` 下相同的层级结构，但是，例如 `srcdir/functions/func1.bash` 是普通文件，该命令应该创建 `rscdir/functions/s.func1.bash,v`。

解决此类问题的方法像程序员一样多，所以你的 `makers` 可能与本节中开发的不同。这里有一个解决该问题的算法：

- 1. 检查命令行参数的数量和类型是否正确。如果无效，显示用法信息并退出。
- 2. 遍历源树，使用 `find` 命令生成路径名。
对于 `find` 返回的每个路径名：
  a. 如果路径指向目录，则在目标下创建相应的路径。
  b. 如果路径指向普通文件，
    - 构造与其对应的 RCS 文件名。
    - 使用 `ci` 创建该 RCS 文件。
  c. 如果路径指向任何其他类型的文件，则将消息写入报告文件并跳过该文件。
  d. 在每个阶段，如果发生错误，则向错误文件写入适当的消息。

处理路径名的几个函数对解决问题很有用。GNU 工具 `dirname` 在给定路径名的情况下，会将该路径前缀写入标准输出。`basename` 工具的作用相反：它将路径的最后一个部分写入标准输出。

如果你有一个路径名为 `a/b/c/d` 的文件，你想创建 `a/b/c/d,v` 作为对应的 RCS 文件名：

``` 
rcname() {

  echo ${1},v

}
```

`rcname` 函数在文件名后附加 `,v`。答案被写入标准输出，以便你可以在命令替换中使用它，例如 `name=$(rcname "$1")`。

一个函数需要检查命令行参数。它应该确保传递了恰好两个参数，`$1` 命名的是一个存在的目录，`$2` 要么不存在要么命名的是一个存在的目录，并且其中任一参数都不是另一个的前缀：

``` 
checkargs() {

  if [[ $# != 2 ]]; then

    print -u2 "usage: makers <source> <dest>"

    exit 1

  fi

  if [[ ! -d $1 ]]; then

    print -u2 "$1: Not a directory"

    exit 1

  fi

  # 检查第二个参数

  if [[ -a $2 && -d $2 ]]; then

    print -u2 "$2: Not a directory"

    exit 1

  fi

  # 检查两个参数都不是对方的前缀

  if [[ $1 = $2* || $2 = $1* ]]; then

    print -u2 "Cannot create hierarchy below or above the other"

    exit 1

  fi

  return 0

}
```

你可以通过类似 `checkargs "$@"` 的命令来调用此函数，它直接传递命令行参数。

程序的主部分使用 `find` 来定位文件和目录。命令 `find $source -print` 将把以 `$source` 为根的层级结构中每个文件的路径名每行一个写入标准输出。如果你将此输出通过到循环中并将每个路径名读入变量，脚本可以如下方式操作该变量：

- 确定路径名是目录、普通文件还是其他内容。
- 在目标目录中构造相应的路径名。
- 使用 `ci` 在该路径处创建 RCS 文件。

因此，程序的主体可以具有以下结构：

``` 
find $source -print | while read pathname

do

    commands

done
```

程序必须合理地处理错误和特殊情况。它打开了两个文件：一个用于报告错误，另一个用于记录被跳过的文件名。将各个部分组合在一起并填充缺失的部分，这里有一个解决该问题的完整程序：

```zsh
% cat makerscs

#!/bin/zsh

# 移除下面一行的 # 以开启调试

# set -o xtrace

makepath() {

    if [[ ${1} -eq 0 || -d $1 ]]; then

        return 0

    fi

    if [[ "${1/*}" = "$1" ]]; then

        mkdir $1

        return $?

    fi

    makepath "${1/*}" || return 1

    mkdir $1

    return $?

}

rcname() {

    echo ${1},v

}

checkargs() {

    if [[ $# != 2 ]]; then

        print -u2 "usage: makerscs <source> <dest>"

        exit 1

    fi

    if [[ ! -d $1 ]]; then

        print -u2 "$1: Not a directory"

        exit 1

    fi

    # 检查第二个参数

    if [[ -a $2 && -d $2 ]]; then

        print -u2 "$2: Not a directory"

        exit 1

    fi

    # 检查两个参数都不是对方的前缀

    if [[ $1 = $2* || $2 = $1* ]]; then

        print -u2 "Cannot create hierarchy below or above the other"

        exit 1

    fi

    return 0

}

ERRS=./err_file

REPORT=./report

checkargs "$0"

# 打开错误和报告文件

exec 3>$REPORT

exec 4<$REPORT

source=$1

dest=$2

find $source -print |

while read pathname

do

    target=$pathname

    if [[ -d $pathname ]]; then

        makepath $target || print -u3 "Cannot create $target"

    elif [[ -f $pathname ]]; then

        target=$(rcname $pathname)

        ci -1 -q "$target" "$pathname" >&4 2>&3 ||

        print -u3 "Cannot create $target"

    else

        print -u4 "$pathname not directory or regular file"

    fi

done

exec 3<-

exec 4<-

exit 0
```
