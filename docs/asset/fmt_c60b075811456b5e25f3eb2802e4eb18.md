
PostgreSQL 可以支持大于 200GB 的极大数据库！当数据库大小超过 5GB 时，32 位 CPU 机器的性能将迅速下降。你可以在 32 位 CPU 上运行 30GB 的数据库，但性能会降低。配备 32 位 CPU 的机器对 RAM 的限制为 2GB，文件系统大小的限制为 2GB，以及对操作系统的其他限制。SGI、IBM、HP 或 ext3-fs 为 Linux 提供的特殊功能支持 32 位 Linux 机器上大于 2GB 的文件大小。对于极大数据库，强烈建议使用 64 位机器，如 Digital Alpha CPU、Sun Ultra-sparse 64 位 CPU、Silicon graphics 64 位 CPU、Intel Merced IA-64 CPU、HPUX 64 位机器或 IBM 64 位机器。在 64 位 CPU 下编译 PostgreSQL，它就可以支持巨大的数据库和大型查询。PostgreSQL 对大表和数据库查询的性能将比 32 位 CPU 机器快几倍。64 位机器的优势在于你可以获得巨大的内存地址空间；操作系统可以支持非常大的文件系统，为大型数据库提供更好的性能，支持更大的内存（RAM），拥有更多功能等。

## 备选位置

可以在安装默认位置之外创建数据库。记住，所有数据库访问实际上都是通过数据库后端进行的，因此指定的任何位置必须是后端可以访问的。

数据库数据库位置通过环境变量创建和引用，该环境变量提供了目标存储位置的绝对路径。此环境变量必须在后端启动之前定义，并且必须对管理员可写。虽然可以使用任何有效的环境变量名来引用备选位置。

注意：在 Postgres 之前的版本中，也允许使用绝对路径指定备选位置。环境变量的指定方式更好，因为它为站点管理员管理磁盘存储提供了更大的灵活性。如果你倾向于使用绝对路径，可以通过定义 `ALLOW_ABOLUTE_DBPATHS` 并重新编译 PostgreSQL 来实现。做法是在 `src/include/config.h` 文件中添加行：

```c
#define ALLOW_ABOLUTE_DBPATHS 1
```

或者在你的 `Makefile.custom` 中指定：

```make
CFLAGS+=-D_ABOLUTE_DBPATHS
```

记住数据库创建实际上是由数据库后端执行的。因此，指定备选位置的环境变量必须在后端启动之前定义。要定义备选位置 `PGDATA2`（指向 `/home/postgres/data`），请先输入：

```bash
% setenv PGDATA2 /home/postgres/data
```

以定义后续命令使用的环境变量。通常，你希望将此变量定义在 Postgres 超级用户的 `.profile` 或 `.chshrc` 初始化文件中，确保它在系统启动时已定义，尽管建议变量带有 `PGDATA` 前缀，以消除混淆并与其他变量冲突或覆盖的可能性。

要在 `PGDATA2` 中创建数据存储区域，请确保 `/home/postgres` 已存在且对 postgres 管理员可见。然后从命令行输入：

```bash
% setenv PGDATA2 /home/postgres/data
% initlocation $PGDATA2
```

创建 Postgres数据库系统目录 `/home/postgres/data`

创建 Postgres数据库系统目录

`/home/postgres/data/base`

要测试新位置，可以通过输入以下命令创建一个测试数据库：

```
% createddb -D PGDATA2 test
% dropdb test
```

## 管理数据库

如果 Postgres 后主进程（`postmaster`）正在运行，我们可以创建一些数据库进行实验。在这里，我们描述管理数据库的基本命令。

### 创建数据库

假设你想创建一个名为 `mydb` 的数据库。你可以使用以下命令来实现此操作：

```
% createddb dbname
```

Postgres 允许在特定站点创建任意数量的数据库，并且你会自动成为你刚刚创建的数据库的管理员。数据库名称必须以字母开头，长度限制在 31 个字符以内。并不是每个用户都有权限成为数据库管理员。如果 Postgres 拒绝为你创建数据库，则需要站点管理员授予你创建数据库的权限。如果发生这种情况，请咨询你的站点管理员。

### 访问数据库

一旦你构建了数据库，可以通过以下方式访问它：

- 运行 Postgres 终端监控程序 (`psql`)，它允许你交互式地输入、编辑和执行 SQL 命令。
- 使用 `libpq` 子程序库编写 C 语言程序。这允许你从 C 中提交 SQL 命令，并让程序接收答案和状态消息。该接口在《PostgreSQL 程序员指南》中会有进一步讨论。

你可能想启动 `psql` 来尝试此手册中的示例。可以通过输入以下命令为 `dbname` 数据库激活它：

```
% psql dbname
```

你将看到以下消息：

```
Welcome to the Postgres interactive sql monitor:
type \? 获取斜杠命令的帮助
type \q 退出
type \g 或用分号结束以执行查询
```

你当前连接到数据库：`dbname`

```
dbname=>
```

此提示符表示终端监控程序正在监听你的输入，你可以在终端监控程序维护的工作区中输入 SQL 查询。`psql` 程序响应以反斜字符（`\`）开头的转义代码。例如，你可以通过输入以下命令获取各种 Postgres SQL 命令语法的帮助：

```
dbname=> \h
```

一旦你完成在工作区中输入查询查询，可以通过输入以下命令将工作区的内容传递给 Postgres 服务器：

```
dbname=> \g
```

这告诉服务器处理该查询。如果你用分号结束查询，则不需要 `-g`。`psql` 会自动处理以分号结束的查询。要从文件而不是交互式读取查询，请输入：

```
dbname=> \i filename
```

要退出 psql 并返回 UNIX，输入：

```
dbname=> \q
```

然后 psql 将退出并返回到你的命令行壳。（如需更多转义代码，请在监控提示符处输入 -h。）在 SQL 查询中可以自由使用空白字符（即空格、制表符和换行符）。单行注释由两个横线（`--`）表示。横线之后直到该行末尾的所有内容都会被忽略。多行注释以及行内注释用 `/* ... */` 表示，这是借用自 Ingres 的约定。

### 销毁数据库

如果你是 `mydb` 数据库的管理员，可以使用以下 UNIX 命令将其销毁：

```
% dropdb dbname
```

此操作将物理上删除与与数据库相关的所有 UNIX 文件，且无法撤销，因此应该在经过充分考虑后才执行。

你也可以在 SQL 会话中使用以下命令销毁数据库：

```
> drop database dbname
```

## 备份与恢复

Postgres 提供了两个实用程序来备份你的系统：`pg_dump` 用于备份单个数据库，`pg_dumpall` 用于一步步备份你的整个安装。可以使用以下命令备份单个数据库：

```
% pg_dump dbname > dbname.pgdump
```

并使用以下命令恢复：

```
cat dbname.pgdump | psql dbname
```

这种技术可以将数据库移动到新位置，并重命名现有数据库。每个数据库都应该定期备份。由于 Postgres 在文件系统中管理它自己的文件，不建议依赖文件系统的系统备份来作为数据库备份；因为无法保证文件在恢复后处于可用且一致的状态。

## 大数据库

由于 Postgres 允许表的大小大于系统上的最大文件限制，因此将表转储到文件可能会出现问题，因为生成的文件可能大于系统允许的最大限制。由于 `pg_dump` 写到标准输出（stdout），你可以直接使用标准的 *nix* 工具来绕过这个可能的问题：

- 使用压缩转储：

```
% pg_dump dbname | gzip > filename.dump.gz
```

使用以下命令重新加载：

```
% createdb dbname
% gunzip -c filename.dump.gz | psql dbname
```

```
% cat filename.dump.gz | gunzip | psql dbname
```

- 使用 split：

```
% pg_dump dbname | split -b 1m - filename.dump
```

使用以下命令重新加载：

```
% createddb dbname
% cat filename.dump.* | psql dbname
```

当然，文件名（`filename`）和 `pg_dump` 输出的内容不需要与数据库名称匹配。此外，恢复的数据库可以有一个任意的新名称，因此这种机制也适用于重命名数据库。
