## 为什么我无法访问我的光盘（CDs）或软盘？

从 Solaris 2.2 开始，Sun 引入了一套自动挂载可移动介质的新方案。Sun 提供了两个管理程序：`vold` 和 `rmmount`。`vold`（卷守护进程）会轮询设备以检查是否有设备插入，而 `rmmount` 程序（可移动介质挂载器）则负责挂载磁盘。

**注意：** 在大多数 SPARCstation 上，你必须在插入软盘后运行 `volcheck` 命令。你必须这样做是因为如果系统一直轮询软盘，它（软盘驱动器）会很快损坏。

这种方案的优点是任何用户都可以随意挂载和卸载软盘（不需要是 root 用户）。此外，你还可以进行一些酷的操作，例如在插入音频 CD 时启动音频 CD 播放器。它还具有扩展性，允许开发者编写自己的操作。

它也有一些细小的缺点。例如，你不能直接访问 `/dev/rfd0` 来使用软盘。现在你必须使用更长的名称，如 `/vol/dev/rdsk/floppy0`。挂载 CD 的格式必须为 `/cdrom/VOLNAME/SLICE`。

当你使用 `tar`、`cpio` 等读写非系统磁盘时，可以插入磁盘并运行 `volcheck` 命令。然后你可以在设备 `/vol/dev/rfd0/unlabeled` 上使用 `tar` 命令。

在 Solaris 2.3 及更高版本上，设备可以定义为 `/vol/dev/rdiskette0/unlabeled` 或 `/vol/dev/aliases/floppy0`。

要使用旧方案，进入 `/etc/rc2.d/` 目录。然后删除 `/S*volmgt link`，大功告成，你应该就能访问磁盘了。

## 为什么我不能以 root 身份进行 rlogin 或 telnet（显示“Not on system console Connection Closed”）？

Solaris 2 相比 Solaris 1 有了一些重大的安全增强功能。这些增强功能之一是 `hosts.equiv` 中没有 `+` 号。除了控制台外，在任何地方都不允许允许 root 登录，且所有账户都需要密码。

你可以开启网络 root 登录，但你必须编辑 `/etc/default/login` 文件。在这里，你必须注释掉 `CONSOLE=line` 这一行。你仍然可以使用 `/etc/hosts.equiv` 文件，但它不再带有任何默认设置。

控制台行可能如下所示：

1. `CONSOLE=/dev/console`（默认）--仅允许控制台直接 root 登录。
2. `CONSOLE=/dev/ttya`--仅允许在 /dev/ttya 直接 root 登录。
3. `CONSOLE=`--在所有地方禁止直接 root 登录。
4. `#CONSOLE`（或删除该行）--在所有地方允许 root 登录。

**在 Solaris/x86 上，我如何让 DOS 和 UNIX 时钟一致？**

一旦安装了 Solaris，你应该运行命令 `/usr/sbin/rtc -z $TZ`，其中 `$TZ` 是你的时区。默认 root `crontab` 每天运行一次 `/usr/sbin/rtc -c`。

一旦实现了此点，无论你启动的是 DOS 还是 Solaris，系统时钟都会提供正确的时间。

**是否可以在同一台机器上同时安装 SunOS 和 Solaris，并能够选择启动系统的时间？**

有一种方法可以。你可以在两个操作系统之间共享系统分区（如 `/`、`/usr`、`/var` 和 `/opt`）之外的所有分区。此外，包括系统分区在内的所有分区都可以由任何操作系统挂载和访问。

设置设置最简单的方法是在两个不同的磁盘上分别安装 Sun。然后只需在启动时通过 PROM 的 `boot` 命令选择合适的磁盘即可。

在一个磁盘上设置两个操作系统要困难一点，但并并不难。你需要对磁盘进行分区以容纳两个操作系统。几乎任何分区布局都是可能的，但一种常见的设置可能是：

- `a:/` 用于 Solaris 2
- `b:swap`（共享）
- `c:` 常规的（整个磁盘）
- `d:/` 用于 Solaris 1
- `e:/usr` 用于 Solaris 1
- `g:/usr` 用于 Solaris 2-Solaris 2

再次，使用 `suninstall` 进行安装是最可靠的。如果由于原因你选择不使用 `suninstall`，请确保对两个可启动分区都运行 `installboot`。

通过这种设置，你可以按照如下方式在 PROM 的 `boot` 命令中两个操作系统之间切换：

启动 Solaris 2：`boot`

启动 Solaris 1：`boot disk:d`

**注意：** 在 2.5 或之前的 boot PROM 版本中不支持 `disk:d` 语法，且 PROM 无法从起始或结束于 1 GB 之外的根分区启动。

**是否有方法防止守护进程创建模式为 `666` 的文件？**

有的。所有守护进程默认从 `init` 继承 `umask` `0`。这对于像 ftp 等服务变成了一个真正的问题，因为标准配置会将所有上传的文件权限更改为 `666`。

为了更改守护进程使用的默认 `umask`，你必须在 `/bin/sh` 中执行以下命令并重启机器：

`umask 022 # 确保以正确的模式创建 umask.sh`
`echo "umask 022" > /etc/init.d/umask.sh`
`for d in /etc/rc?.d`
`do`
`ln /etc/init.d/umask.sh $d/S00umask.sh`
`done`

脚本名称末尾的 `.sh` 是重要的；如果你不指定它，脚本将在子 shell 中执行，而不是在执行所有其他脚本的主 shell 中。

**我是否有任何方法可以在不使用 NIS 或 NIS+ 的情况下使用 DNS？**

这曾经几乎是不可能的。在 SunOS 4.1 中，如果不使用 NIS 或一种非常*笨拙（kludgey）*的修复，是不可能的运行 DNS 名称解析。

然而，从 Solaris 2.1 开始，这变得极其简单，尽管 SunOS 5.1 的手册是错误的。你只需要更改 `/etc/nsswitch.conf` 中的一行：

`hosts: files dns`

这是在告诉系统先在 `/etc/hosts` 中查找。如果在那里没有找到该主机，则尝试 DNS。如果那不起作用，则放弃。然后你必须编辑 `/etc/resolve.conf` 文件，告诉解析程序如何联系 DNS 服务器。

你必须在 `/etc` 中的文件包含在启动期间以某种方式联系的机器名称，且文件必须首先出现在 `hosts:` 行中；否则机器将在启动期间挂起。

**`nsswitch.conf` 到底是什么？**

此服务控制从 NIS 读取哪些解析服务，从 NIS+ 读取哪些服务，从 `/etc` 中的文件读取哪些服务以及从 DNS 读取哪些服务。

一个常见的例子是：

`hosts: nis files`

这意味着向 NIS 询问主机信息，如果未找到，则尝试 DNS。

**为什么我无法让 Solaris 2.3 和其他平台之间的 PPP 正常工作？**

**我遇到了错误 `_builtin_v_alist or _builtin_va_arg_incr undefined` 怎么办？**

**为什么？**

你正在使用 gcc，但没有正确安装 gcc 的固定包含文件（fixed-include files）。或者，你在安装 gcc 之后运行了 `fixincludes`，但没有将 gcc 提供的 `varargs.h` 和 `stdarg.h` 文件移开，稍后又将它们移回。这在人们从二进制发行版安装 gcc 时经常发生。如果 gcc 的包含目录中存在 `tmp` 目录，说明 `fixincludes` 没有完成。你本应该运行 `just-fixinc`。

另一个可能的原因是使用了 `gcc -I/usr/include`。

**我的系统在启动过程中似乎卡住了，显然是在尝试使用 `ps` 的时候。有什么办法能让它启动吗？**

在启动时，第一次调用 `ps` 会尝试重新创建 `/tmp/ps_data`。执行此操作时，`ps` 会扫描 `/dev` 树。你的 `/dev` 中可能存在循环，导致 `ps` 无限运行。

在大多数情况下，循环是由符号链接 `/dev/bd.off` 引起的。该链接应该指向 `/dev/term/b`，但它有时会被截断并指向 `/dev`。

要修复此问题，只需如下所示重新创建链接：

`rm -f /dev/bd.off`
`ln -s /dev/term/b /dev/bd.off`

你可能想使用 `truss` 工具来确定这是否是问题的真实原因。

**为什么我的 `syslogd` 似乎没有记录任何内容？**

首先，确保你已经安装了 `/usr/ccs/bin/m4`。它是随 SUNWbtool 一起打包的。

这可能也与 Solaris 2.3 的 bug 以及多个版本的修订补丁有关。在级别 42 到 50 之间的所有 101318 补丁中，`syslogd` 都是损坏的，但在 101318-54 中它是正常的。

如果你使用的是 Solaris 2.4，你可能需要补丁 102534 和 102697。

**当从非 Sun 文件服务器在 Solaris 客户端挂载文件系统时，我一直收到“invalid client credential”（无效的客户端凭据）错误。我如何让它工作？**

某些供应商提供的 RPC/NFS 版本在客户端凭据中最多允许 8 个组。Solaris 上的 root 默认属于 10 个组。结果，Solaris 2.x 的 `mount` 命令发送的 `AUTH_UNIX` 凭据太大，导致远程 `mount` 守护进程无法处理，产生 `"Invalid client credential"` 错误。

临时解决方法：将 root 和你所有的用户放在 8 个或更少的组中。

你必须注销并重新登录，组数量的变化才能生效（或者退出 `root` 的 shell 并 `re-su`）。

**在我升级了 Solaris 2.4 系统后，NFS 挂载目录上的 `ls` 命令开始卡死。这里是有 bug 还是怎么的？**

从 Solaris 224 开始，一个限制 NFS `readdir` 请求为 1024 字节的内核变通被默认禁用了。这破坏了与带有 bug 的旧 NFS 实现（如 SunOS 3.2、Ultrix 和 NeXT）的互操作性。

有两种解决方法。第一种有效的方法是：

`使用 rsize=1024 从此类服务器挂载所有文件系统。`

第二种需要针对 `bugid` #1193696 的补丁（SPARC 使用 101945-29 或更高版本，x86 使用 101946-24 或更高版本）：

编辑 `/etc/system` 并添加：

`set nfs:nfs_shrink = 1`
并重启。

**在我安装了补丁 101945 后，我遇到了一些与 ksh 循环相关的 NFS 问题。发生什么了？**

再次，原因是一个有 bug 的补丁。补丁 101945-17 实际上在 NFS 客户端中引入了一个 bug，导致使用 NFS 锁的程序进入不可中断的读取状态。如果你使用 `truss`，`ps` 将显示程序处于 `read` 语句睡眠状态，而 `top` 显示它正在占用所有 CPU。

修复方法是在你所有的客户端上安装针对 bugid #198278 的补丁。如果你是 SPARC，你需要补丁 #101945-29 或更高版本，如果你使用 x86，则需要补丁 #101946-24。在获取补丁之前，你可以实施变通方法：使用 `noac` 挂载 NFS 文件系统。遗憾的是，这样做会导致性能大幅下降。

**我认为我搞砸了我的 /etc/system 文件，现在我无法启动了。我该如何把它提取？**

你应该能够使用 `-s` 选项启动。当系统启动时，它会询问你一些问题，包括系统文件名称。此时，你可以使用之前的 `/etc/system`（如果你记得备份过它），或者指定 `/dev/null`。

**我的 sendmail 到非 Unix 主机的连接无法工作。**

在 Solaris 2.5 引入 sendmail 之后，对于非 Unix 主机的连接出现了一个 bug。由于 sendmail 的引入，对于某些站点，如果没有设置“不分片”（don't fragment）位，就会失效。要修复这个问题，在 `sendmail.cf` 中找到以下行：

`M[TCP] F=ms R=11`
改为：

`M[TCP] F=ms R=11 A=TCP`
对于 Solaris 2.x，如果未应用补丁，下载仍然失败。`tcp_mss_max` 变通方法只需要在一端应用。

**应用了最后的补丁后，我仍然遇到连接问题。还有其他建议吗？**

好的，尝试其他方法。在 Solaris 2.x 中，如果未应用补丁，大包仍然会被静默丢弃。因此，你可以采取以下影响网络性能的极端措施：

`/usr/sbin/ndd -set /dev/tcp tcp_mss_max 536`
536 是保证可以工作的包大小。值得注意的是，`ip_path_mtu_discovery` 需要两端应用才能完全工作。

如果你为某些站点需要 `tcp_mss_max` 变通方法，那么你与这些站点之间的连接是有问题。获取 `traceroute` 将告诉你问题所在。尝试 `traceroute host` 检查不同的大小。如果不带参数的 `traceroute` 正常，但带 1460 参数的 `traceroute` 在某个跳数失败，那么该跳数到下一个跳数之间的连接是损坏的。

**我有一个远程 /var 分区的客户端。它无法启动。为什么？**

如果你有远程但未共享的文件系统（如 `/`、`/var`、`/var/adm` 等），必须使用 `llock` 选项挂载。这在 Solaris 2.x 中对 root 实现，但对于远程 `/var` 或 `/var/adm` 没有。如果没有指定 `llock`，系统在尝试处理 `tmp` 文件时会挂起，挂起发生在启动过程早期。此外，如果 `lps` 无法锁定 `/var/spool/lp/SCHEDLOCK`，可能会失败。

要解决这个问题，你需要为 `/var` 和/或 `/var/adm` 的挂载选项添加 `llock` 选项。它应该在 `/etc/rcS.d/S70buildmnttab.sh` 中修复。

**为什么我能从非 Sun CD 驱动安装 Solaris 2.3，但在 Solaris 2.4 上不行？**

在 2.3 和 2.4 之间，`sd` 驱动发生了许多变化。特别是在数据溢出的情况下，重置驱动器为 512 块的代码不再被调用。因此，无法从本地非 Sun CDROM 驱动安装 2.4。

实际上，解决此问题的唯一变通方法是借一张 SunCD，或者将 CD 挂载到远程机器上。然后你需要进行网络安装。

这是一个针对 Solaris 2.x SPARC 版本的特定问题。然而，如果你有一个 CD-ROM 驱动器被修改为使用 512 字节块大小作为默认值，它应该可以正常工作。

**我的应用程序编译时没有任何问题，但在运行时给出了错误 `"fatal: libfoo.so.2: can't open file: errno=2"`。发生了什么？**

当你编译时，系统没有找到库的位置。因此，你必须使用 `-R` 选项指定库的位置：

`cc -L/usr/dt/lib -L/usr/openwin/lib -R/usr/dt/lib -R/usr/openwin/lib`

` xprog.c -lXm -lXt -lX11`

**我的 Solaris 2.4 随着时间的推移似乎越来越慢，而且似乎有 **内存泄漏。我该如何修补这些漏洞？**

这种内核内存泄漏有两个可能的原因。

- 卷管理设备驱动程序存在 Bug，卸载时会泄漏内存：使用补丁 101907-05 (sparc) 或 101908-07 (x86) 进行修复。此 Bug 特别影响未运行 `vold` 的系统，因为它在内核决定卸载未使用的设备驱动程序时会被触发。
- 此外，NFS 客户端缓存会缓存过多。简单的解决方法是在 `/etc/system` 中添加 `set nrnode = 1000` 并重启。你可能需要根据内存大小将其调大或调小。
- 另一个可能的原因是 `/tmp` 或其他基于交换文件的 `tmpfs` 文件溢出。通过 `df` 检查这种可能性。

**当我运行 NFS 时遇到以下错误消息 **`"netdir_getname failure, /dev/udp: bind problem"****。这是怎么了？**

由于某些原因，nfs 服务从你的 `/etc/services` 文件或 NIS+ 表中消失了。你需要如下条目：

`nfsd 2049/udp nfs # NFS server daemon (ts)`
`nfsd 2049/tcp nfs # NFS server daemon (ots)`

如果你使用 NIS+，必须确保 `/etc/services` 中执行 `nfsd` 的条目是可读的。如果你使用的是 SunOS 4.x 服务文件，这就能解释这个问题：SunOS 4.x 在 `/etc/services` 中没有 `nfsd` 条目。这种情况通常在升级到 Solaris 2.4 或 2.5 之前不会发生。Solaris 2.3 及早版本总是查看 `sswitch.conf`。`/etc/services` 包含了正确的 NFS tcp 条目。

**我更改了 root 的 shell，现在无法登录了。我需要重装 Solaris 吗？**

不需要那么极端。如果 root 找不到或无法使用 shell，你需要从 CD 进入单用户模式。完成后，挂载根系统并将 `/etc/passwd` 中指定的 shell 改回 `/bin/sh`。

**当文件系统满时，我的 NFS 服务器挂起了。我该如何修复？**

在 Solaris 2.4 中，存在一组问题导致在使用配额或磁盘接近满运行时几乎不可能。这些问题与写入 `/dev/console` 的消息有关，导致机器死机、客户端缓存 2 MB 的失败写入并重试，以及导致服务器崩溃。这个问题的解决方法是使用补丁。你需要为 SPARC 获取补丁 #101945-32，为 X86 获取补丁 #101946-29。你需要将这些补丁不仅应用于服务器，也要应用于客户端。

**在 Solaris 2.5 和 Solaris 2.4 中，补丁 #101945-34 及旧版本在慢路上的性能不佳。我该如何解决？**

Solaris 2.5 和 Solaris 2.4 内核补丁 101945-34 及后续版本在重传算法中存在 Bug，导致在慢路上过度传输；Sun 的 Bug ID 为 #123327。该 Bug 的解决方法是在系统启动时运行以下命令，即将其添加到 `/etc/init.d/inet`（单位为毫秒）：

`/usr/sbin/ndd -set /dev/tcp rexmit_min 3000`
`/usr/sbin/ndd -set /dev/tcp rexmit_initial 3000`

其他人建议了不同的更改，因为使用上述方法，每次丢包的重传将花费很长时间。以下方法使用了较小的最小重传间隔，同时也限制了输出包的大小为 536 字节，因此重传包更小：

`/usr/sbin/ndd -set /dev/tcp rexmit_min 1000`
`/usr/sbin/ndd -set /dev/tcp rexmit_initial 3000`
`/usr/sbin/ndd -set /dev/tcp mss_max 536`

## SVR4 常见问题解答 (FAQs)
*Cameron Laird*

### 什么是 SVR4？

它是 UNIX 操作系统的一种。位于 **<URL: http://www.sco.com/** 或拨打 1-800-726-8649 的 Santa Cruz Operation, Inc. 拥有其知识产权——商标、版权保护软件等。详情请联系 SCO。

SVR4（读作 "ess-vee-are-four"；有时也写作 SysVr4 "sys-vee-are-four"；或者偶尔写作 "sys-vee"）是 UNIX System V Release 4 的缩写。Unix System Laboratories（简称 USL，当时 AT&T 的附属机构）于1988 年首次发布了 SVR4。它的目标是将 BSD UNIX（20 世纪 80 另一大主流 UNIX）的特性整合进 System V 主流，以及 SunOS 的网络文件系统 (NFS)、新的 POSIX、ABI 和 X/Open 标准，并为未来的工作（特别是多处理领域）提供基础。USL 于 1992 年 7 月完成了 Release 4.2 的内核开发。“UNIX”本身是一个由 X/Open 独家许可的商标（**URL: http://www.xopen.org/faqs/faq_brnd.htm**），它是行业标准组织 The Open Group (**URL: http://www.opengroup.org/**）的一个部门。

### SVR4 对我重要吗？

既重要也不重要。SVR4 是 20 世纪 90 年代 UNIX 运营的核心，但这个中心已变成了一个安静的地方。今天，大多数 UNIX 用户依赖于 SVR4 的许可，因为它是 Solaris、HP-UX、Irix 和 Unixware 等市场领先品牌的基础。然而，大多数 UNIX 用户并不关注 SVR4，因为这些市场领导者中的每一个都与 SVR4 差异化开来。大多数 Sun 客户将他们的操作系统视为 Solaris；惠尔（（Packard（HP）客户认同 HP-UX；以此类推。确实有在狭义意义上运行 SVR4 的机器，但它们都是小众产品，用户群比领先者低出几个数量级。

结论是什么？请考虑以下三类：

- 如果你正尝试使用或管理某个品牌化的 UNIX 变体，请将其视为该品牌。如果你是 Sun 客户，请阅读本书中关于 Solaris 的章节和参考文献，并为了获取更多信息购买其他关于 Solaris 的书籍。对你来说，SVR4 仅具有历史意义。
- 如果你是某种小众、狭义意义上的 SVR4 UNIX 用户，你可能正在从供应商那里获得完整的文档和良好的支持。你是一个高端客户，代表着巨大的商业价值，你应该期待从有能力提供的人那里获得大量的帮助。本章为你的工作提供了背景。读完后，你应该知道该问哪些问题来揭示你所需的深度信息。
- 如果你正在开发希望在所有 SVR4 主机上移植的应用程序，请仔细考虑你的决定。SVR4 品牌并不保证二进制兼容性，因此成功的移植通常涉及从可移植源生成。SVR4 是这种开发的可能目标，但大多数情况下，POSIX (**URL: http://standards.ieee.org/**) 或 XPG4 (**URL: http://www.opengroup.org/public/prods/xum4.htm**) 或 1170 (**URL: http://xopen.org/public/tech/tr1a.htm**) 是更好的选择。阅读本章以了解不同标准如何适用于你的情况。

除非明确说明，本章其余部分提到的 SVR4 都是与“狭义”的 SVR4 有关，而不是 Solaris、HP-UX、Irix 等“品牌化”的版本。

### 你可以用 SVR4 做什么？

SVR4 在外观上与 1997 年的大多数 UNIX 几乎无异。除少数例外外，你可以在其他 UNIX 上做的一切。

### SVR4 技术

SVR4 包括：

- System III 的 FIFOs 或命名管道
- System V 的共享内存、消息队列和信号量进程间机制
- SVID（System V Interface Definition）标准 API
- 共享库
- 流 (streams)
- 硬件支持的分页存储
- ANSI C 编译器
- BSD 风格的网络，包括 sockets 库、TCP 栈和网络文件系统 (NFS)
- 8 位清理，即在 ASCII 表中允许国际字符
- ksh
- 对多处理的某种支持

### 在 SVR4 中编程

感觉像是现代 UNIX；这是核心点。SVR4 不包含 POSIX 线程库，但在其他方面，编写 SVR4 与编写任何其他 UNIX 相似。

### SVR4 的编程策略

仅仅因为它是如此标准，编写 SVR4 并不局限于 C 代码。Csh 和 ksh 是发行版的一部分，并且像 Perl、Tcl、Python、Rexx、Sather 等更多自由分发的语言也易于获取。虽然 SVR4 不可能支持在 Windows 世界看到的那些特定和图形化工具及产品的爆炸式增长，但这些“脚本”或“高级级”语言可以为 SVR4 世界中的某些应用开发带来与任何环境同等的生产力。

### 使用共享库可以吗？

可以。关于应用程序开发有一点是 SVR4 特有的。SVR4 提供的技术之一是共享或可加载对象。本质上，所有现代 UNIX 都依赖共享对象。在某些特定情况下，不建议使用共享对象；大多数与 HP-UX、Solaris 和 Linux 的后兼容商业现实有关。不过，我在 SVR4 下使用共享对象没有遇到过问题，可以安全地推荐在开发和部署阶段生成应用程序使用。

### 何时使用共享库

你可能已经在用共享库；它们是许多开发环境的默认设置。情况是：生成应用程序的传统方法是将特定应用程序所需的所有机器指令编译并链接到单个文件中。如果你需要系统例程从显示格式转换为浮点数，或者将符号名转换为数值地址，或者计算对数，链接器会排序这些引用，混合实现它们的机器语言片段，并将它们写入一个“单体式”文件映像。

也有其他可能性。想象一种链接器可以创建一个小小的可执行映像，它包含了你的源代码的机器语言以及其他库的引用。操作系统可以加载那个较小文件，当它需要执行某个系统函数时，从标准位置加载它。

共享库如果处理不当，也可能成为浪费精力的麻烦。好消息是，SVR4 的共享库通常处理得非常可靠，没有理由避免使用。请阅读供应商提供的 'man ld' 和其他参考文献以获取详情。

### 标准风格编程

让我们看一个例子。假设你用 C 语言进行低级编程，并从内存中的一个位置拷贝结构到另一个位置。这样做有很多习惯用法，但我知道最安全的是

` #include <memory.h>`

` struct some_struct *source, *destination;`

` (void) memmove(destination, source, sizeof(struct some_struct));`

memmove() 是 1989 年 ANSI C 的标准的一部分，依赖它比 bcopy() 安全。我在这里区分了正确性（取决于应用程序的需求，这些方法都是正确的）与安全性；后者考虑了健壮性、可读性和可维护性。智能地依赖 POSIX 和 ANSI 标准可以使你的代码变得清晰有效。

原生的 SVR4 并没有提供这类*GUI 化*的 `admintool`、`smit` 或 `sam` 来通过鼠标点击的范式来组织系统管理任务。对于负责 SVR4 的系统管理员来说，拥有供应商提供的完整版说明书，以及诸如 Nemeth 等人编写的 *UNIX System Administration Handbook* 或 Frisch 编写的 *Essential System Administration* 等参考资料非常重要。根据情况，Prentice-Hall 出版的《System V Release 4: Network User's and Administrator's Guide》也是一种选择（它出版于 1990 年）。它涵盖了任何 SVR4 中几乎所有的可用技术（动态内核除外），但对于 1997 年可能重要的几个主题——如 NNTPSERVER、NIS、防火墙等——却未曾提及。

## 关于 SVR4 硬件有什么特殊需要了解的吗？

如果你正在使用 SVR4，你将与你的供应商交流。我没有听说有任何独立的设备驱动程序开发者。肯定有一些，但他们并不像第三方对于 Sun、Linux 或 Windows 产品那样具有知名度。当 SVR4 首次出现时，它是支持 SCSI 和串行设备的领导者。支撑这种领导地位的技术依然强大，但由于现在 SVR4 的市场地位已处于特定供应商的利基市场，使用它反映了这些供应商的考量和优先事项。

**为什么 `inst` 无法在网络上工作？**

如果你正尝试从微型根系统（miniroot）安装软件并通过网络加载微型根系统，请尝试在 `nvram` 中验证系统的系统的 IP 地址。该 IP 地址通常不会与启动系统上的 IP 地址一起设置，错误的 IP 地址会导致主机无法访问或其他类似问题。

## 如何更改分区大小？

**警告：**更改分区大小会导致磁盘上的所有数据丢失。请将您任何想要保留的数据复制到其他地方，并确保该备份是完好的。

在 SGI 机器上，更改分区大小有多种方法。对于一次性任务，最简单的方法是使用 `fx` `(1M)` 来安排分区。它提供了一个方便的文本菜单界面来设置分区。如果 `fx` 加载在卷标头（volume header）上，则可以从 miniroot 启动它。（有关如何更改卷标头的信息，请参见关于制作系统磁盘的问题。）

**提示：**请在安全的地方记录你的分区大小。如果你不小心更改了分区大小并立即改回原样，你可能能够恢复数据。

对于需要对若干块相同硬盘以相同方式进行分区的大规模实现，你可以轻松地编写脚本来为 `dvhtool(1M)` 程序提供输入。`dvhtool` 允许用户指定指定分区、类型和大小，但与 `fx` 不同，`dvhtool` 不检查你的算术以验证是否存在重叠分区。

**注意：**如果你的算术错误，使用 `dvhtool` 更改分区大小会导致异常问题。重叠分区在一段时间内可能运行良好，随后会失败，因为它们都尝试使用磁盘上的特定位置。小心你的分区不要重叠。

## 如何在本地将磁盘复制到另一个磁盘？

## 如何通过网络将磁盘复制到另一个磁盘？

`escher 3# rsh escher '(cd / ; tar -cBf - )' | (cd / ; tar -xBf -)`

`-B` 告诉 `tar` 忽略流中的块信息，网络可能会掩盖原始的一些块信息。

## 如何将系统分区复制到另一个系统？

你可以使用上述 `tar` 命令进行复制，但如果系统架构不同（由 `hinv` 报告），则复制将无法立即工作。

## 磁带问题

通常人们将磁带或磁带带到另一个系统并遇到问题。这些问题解决了这些困难。

## 为什么我的 Sun 磁带无效？或者我应该使用哪个磁带设备？

一旦熟悉，磁带设备的命名方案非常方便，你可以使用任何适合你的磁带设备。磁带设备名称的第一个组件仅为路径，自而易见。第二个组件指示设备类型，例如磁盘的 `dk`、磁带的 `tp` 或其他许多不常用设备的前缀。第三个组件指定它是 SCSI 驱动器。第四部分指定使用哪个 SCSI 总线，第五部分指定驱动器的 SCSI ID。你可以使用 `hinv` 确定磁带机的 SCSI 总线和 SCSI ID（即单元号）。第六个组件是选项字段，可以是 `s`、`nrs`、`ns`、`nrns`、`nr`、`sv`、`nrsv`、`nsv`、`v`、`nrnsv`、`nrv` 或不指定。默认为 `nrns`。表 33.1 显示了选项、影响以及组合选项形成完整字段的顺序。

**表 33.1. 磁带设备选项**

| 选项 | 效果 |
| :--- | :--- |
| 1 `nr` | 不回带设备，例如 DAT 磁带 |
| 2 `s` | 字节交换 (byte-swapped) |
| 2 `ns` | 非字节交换 (not byte-swapped) |
| 3 `v` | 可变块长度 |

大多数磁带问题都是由于字节交换引起的。IRIX 机器是大端序（big endian）；也就是说，它们在磁带上先存储两个字节中高位数的字节。其他机器（包括 Sun）则先存储两个字节中低位数的字节。如果你在读取磁带时遇到困难，请先尝试字节交换。

***命名与记忆字节序***

*Endianness*（字节序）一词源于乔纳森·斯斯威特（Jonathan Swift）的《格列佛游记》，书中一项草率制定的法律被用来划分小立普人和他们和平的邻居。长期以来，人们习惯于从大的一端敲开鸡蛋，但当小立普特皇帝的儿子按照惯俗敲鸡蛋时切伤了手指，皇帝规定从今起所有的鸡蛋都必须从小的一端敲开。公民们反抗这一改变；有些人甚至逃到了邻近的布勒富斯库帝国（Blefuscu）。由于法令引起的分裂引发了巨大的战争。小立普人将他们的邻居称为“大端人”（Big-Endians），因为布勒富斯库的人继续从大的一端敲鸡蛋。

大端序数据存储将两个字节对中的高位字节放在前面，而小端序存储将低位字节放在前面，通过鸡蛋故事，这很容易记忆。

你也可以尝试使用可变块长度来解决问题。

除了 DAT 之外，磁带设备大多都支持回带（DAT 驱动器可以回带磁带，但它不允许将回带作为导航数据的手段，仅作为回到头的手段）。

## 如何设置我的第三方磁带驱动器？

**注意：** 此过程不适合胆小者。它要求你对 C 语言编程和 Bourne shell 脚本有理解。

使用 `hinv` 查看计算机认为你的磁带驱动器是什么。它应该指示设备未知并显示一个 ID 字符串。记住该 ID 字符串。

**警告：** 在更改这些内容之前，保存 `/var/sysgen/master.d/scsi` 和 `/dev/MAKEDEV.d/TPS_base` 的备份副本。

编辑 `/var/sysgen/master.d/scsi` 以包含你特定磁带驱动器的条目。最好找到一个类似的磁带驱动器条目，复制并编辑它。`/var/sysgen/master.d/scsi` 文件是内核的配置文件，你正在声明 `struct tpsc_types` 的值。`struct tpsc_types` 定义在 `/usr/include/sys/tpsc.h` 中，注释提供了关于每个值代表含义的指导。

**警告：** 在更改内核（`/unix`）之前，保存内核的备份副本。如果你的新内核无法工作，你可以通过 PROM 监视器从备份副本启动。

接下来，使用 **autoconfig** 重新构建内核，然后 **reboot**，最后尝试使用 `hinv` 查看是否正确识别了磁带驱动器。如果没有，返回回去编辑 `/var/sysgen/master.d/scsi`，执行 **autoconfig** 和 **reboot**，直到 `hinv` 识别它。

一旦 `hinv` 识别了磁带驱动器，你需要为它构建相应的设备文件。**cd /dev** 并尝试 **./MAKEDEV**。如果 `MAKEDEV` 第一次尝试没有创建相应的设备，则需要编辑 `/dev/MAKEDEV.d/TPS_base` 文件（5.3 版本为 `/dev/MAKEDEV`）。`MAKEDEV` 使用 `hinv` 字符串来确定是哪个设备。

有很多方法，`**xwsh -vt100**` 可能是最简单的。请参阅 `xwsh(1)` 的帮助页以获取更多信息。

## 总结

今日消息（Message Of The Day）文件通常包含系统管理员认为对你来说重要的信息。当用户登录系统时，会显示此文件。

**/etc/profile**--该包含所有使用 Bourne 和 Korn shell 的用户的通用 shell 环境特征的文件。

**abbreviation（缩写）**--((vi) 用户定义的字符序列，在插入模式下输入时会展开为定义的文本字符串。

**absolute pathname（绝对路径）**--通过指定包括根目录在内的链中所有目录的精确位置，来表示目录中文件位置的方法。

**APAR**--授权程序分析报告（Authorized Program Analysis Report）。

**API（应用程序接口）**--计算机操作系统、应用程序或第三方工具规定的特定方法，编写应用程序的程序员可以通过该方法向操作系统发出请求。

**arguments（参数/参数）**--参见 *parameters*（参数）。

**ARPA**--参见 *DARPA*。

**ASCII（信息交换标准代码）**--用于在大多数计算机的内存中表示字符。

**AT&T UNIX**--在 AT&T 贝尔实验室开发的 UNIX 原始版本，后来被称为 UNIX 系统实验室。许多当前的 UNIX 版本都是其后代；甚至 BSD UNIX 也是源自早期的 AT&T UNIX。

**attribute（属性）**--描述对象的手段。球的属性可能是：橡胶、红色、直径 3 厘米。球的行为可能是抛掷时弹起的高度。属性是对象（类）中包含数据的另一种称呼。

**AWK**--由 A.V. Aho、P.J. Weinberger 和 Brian W. Kernighan 开发的编程语言。该语言基于 C 语法构建，包含了 grep 的正则表达式搜索功能，并添加了 C 语言缺失的高级字符串和数组处理功能。nawk、gawk 和 POSIX awk 是该语言的不同版本。

**background（后台）**--通常以较低优先级运行且输入与交互会话断开的进程。任何输入输出通常重定向到文件。

**background process（后台进程）**--一种在 UNIX 下运行不需要用户交互的自主进程。

**backup（备份）**--将 UNIX 系统、应用程序和数据文件存储在可移动介质上以便日后取回的过程。

**BASH**--BASH 代表 GNU Bourne Again Shell（再次 Bourne shell），它基于 Bourne shell (sh)，即原始命令解释器。

**beep（哔声）**--在 UNIX 文档中通常称为 *bell*（见 *bell*）。

**bell（铃声）**--程序发送到终端的字符，用于指示某种“错误”状态；例如，在 *vi* 中，当你已处于命令模式时按 *Esc* 退出插入模式；实际上是 ^G 字符，它不是显示在终端上，而是导致终端发出“报警”声，在古老的电报打字终端上，这是通过铃声实现的。不同的终端对铃声产生不同的声音，其中一个老式视频终端发出的声音听起来像是在没有离合器的情况下换挡位。

**binding（绑定）**----(emacs) 将一个*移位键**序列*分配给一个 *Emacs* 编辑命令。

**block-special（块特殊设备）**--一种用于与块定向 I/O 设备通信的设备文件。磁盘和磁带驱动器是块设备的示例。block-special 文件指的是整个设备。除非你想忽略设备的目录结构（即你正在编写设备驱动程序），否则不应使用此文件。

**boot or boot up（启动）**--启动操作系统（UNIX）的过程。

**Bourne Shell（Bourne 壳）**--最初的支持有限编程能力的 UNIX 标准用户界面。

**BOS**--基础操作系统（Basic Operating System）。

**BSD UNIX**--由伯克利软件发行版开发并在加州伯克利大学编写 UNIX 版本。

**buffer（缓冲区）**----(vi) 你正在编辑的文件的工作版本通常称为 *buffer*；缓冲区实际上是编辑期间保留在随机访问内存中的文件映像；更改在此映像中进行，并仅在用户命令下（或当 *vi autowrite* 设置生效时）才写入磁盘；另见 *named buffer*（命名缓冲区）和 *undo buffer*（撤销缓冲区）。

**buffer list（缓冲区列表）**----(emacs) 显示所有当前打开缓冲区的特殊窗口；允许你使用 buffer list 命令操作缓冲区。

**C**--由 Brian W. Kernighan 和 Dennis M. Ritchie 开发的编程语言。C 语言具有高度的可移植性，适用于许多平台，包括大型主机、PC，当然还有 UNIX 系统。

**C Shell（C 壳）**--由 Bill Joy 在伯克利编写的 UNIX 用户界面。它还具有类似于 C 语言编程的语法。

**CD-ROM（光盘只读存储）**--存储在与音乐 CD 物理形式相同的计算机可读数据。容量大、价格便宜、比硬盘慢，且仅限于读取。有可写版本（CD-R, CD Recordable）以及其他可以写入一次或多次的格式。

**CGI（通用网关接口）**--一种在 Web 页面与在服务器上执行的程序或脚本之间传输数据的方法。这些程序可以处理数据并通过动态创建 HTML 将结果传回用户的浏览器。

**character-special（字符特殊设备）**--一种用于与终端、打印机或网络通信线等字符定向 I/O 设备通信的设备文件。所有的 I/O 访问均被视为一系列字节（字符）。

**characters（字符）**--

1. **alphabetic（字母）**--字母 A 到 Z 和 a 到 z。
2. **alphanumeric（字母数字混合）**--字母 A 到 Z、字母 a 到 z，以及数字 0 到 9。
3. **control（控制）**--任何不可打印字符。
4. **numeric（数字）**--数字 0 到 9。
5. **special（特殊）**--任何标点字符。

**child-process（子进程）**--参见 *sub-process*。

**child-shell（子壳）**--参见 *sub-shell*。

**class（类）**--具有属性（数据）和行为（代码）的对象模型。

**command line（命令行）**----(1) 启动 *vi* 或 *Emacs* 会话的 shell 命令；(2) *ex* 行，**editing（编辑）**--某些 shell 支持回溯命令、进行修改并执行新版本。**parameters（参数）**--用于指定传递给程序或过程的参数。称为命令行参数。**prompt（提示符）**--参见 *shell prompt*。**completion（补全）**--(emacs) 自动提供命令或文件名；当命令或文件名无法解析为单个实体时，会提供菜单（输入名的几个字符并按 TAB）。

**configuration files（配置文件）**--用于初始化和设置特定命令及程序环境的信息集。shell 配置设置用户的环境。

**configuration files, shell（shell 配置）**

对于 Bourne shell：`/etc/profile` 和 `$HOME/.profile`。

对于 Korn shell：`/etc/profile`、`$HOME/.profile` 和 `ENV=` 文件。

对于 C shell：`/etc/.login`、`/etc/cshrc`、`$HOME/.login`、`$HOME/.cshrc` 和 `$HOME/.logout`。旧版本可能不支持前两个文件。

对于 BASH：`/etc/profile`、`$HOME/.bash_profile`、`$HOME/.bash_login`、`$HOME/.profile`、`$HOME/.bashrc`、`~/.bash_logout`。

**control keys（控制键）**--这些键执行某些功能而不是显示字符。这些功能有名称，例如结束文件告诉 UNIX 没有更多输入。典型的结束文件键是 <^D> (control-d) 键。

**CPU（中央处理器）**--计算机的主要大脑；计算引擎和逻辑控制器。

**current macro（当前宏）**--(emacs) 最近记录的宏；通过 `call-last-kbd-macro` 函数执行。

**cursor（光标）**--屏幕上下次编辑操作发生的特定点；光标通常通过屏幕上的某种高亮显示，例如下划线或实心块，可能也可能闪烁。

**daemon（守护进程）**--一种系统相关的后台进程，通常以 root 权限运行，并接收其他进程的请求。

**DARPA（美国国防部高级研究计划局）**--资助了 TCP/IP 和 ARPAnet（互联网的前身）的开发。

**database server（数据库服务器）**--参见 *server, database*。

**default settings（默认设置）**--大多数工具和系统由许多设置控制；工具启动时生效的设置被称为默认设置。*vi* 由许多*settings*（设置）控制；*default settings*是指 *vi* 首次启动时生效生效，且没有通过 *.exrc* 文件或 *EXINIT* 环境变量启用任何自动覆盖的设置。

**device file（设备文件）**--用于实现物理设备访问的文件。这为 UNIX 下访问存储介质提供了一种统一的方法——数据文件和设备（如磁带和通信设施）被实现为文件。对于程序员来说，它们之间没有本质区别。

**directory（目录）**--一种组织和收集文件的方法。目录本身是一个文件，由包含其中的文件列表组成。根目录 (/) 是顶层，所有其他目录都包含其中（直接或间接地）。目录可以包含其他目录，称为子目录。

**directory navigation（目录导航）**--在目录间移动的过程被称为导航。你当前所在的目录被称为当前工作目录。你的登录目录被称为默认目录或家目录。使用 `cd` 命令，你可以在目录树结构中向上或向下移动。

**DNS（域名系统服务器）**--用于将互联网上的机器名称（name.domain.com）转换为数字地址（123.45.111.123）。

**DOS（磁盘操作系统）**--一种基于使用磁盘存储命令的操作系统。它也是个人电脑上 MS-DOS 和 PC-DOS 的通用术语。MS-DOS 是微软销售的版本，而 PC-DOS 是 IBM 销售的版本。两者都基于微软的代码。

**EBCDIC（扩展二进制编码十制数字交换码）**--用于在大型机内存中表示字符的编码。

**echo（回显）**--在屏幕上显示你输入的字符，有时被称为字符的 *echo*（回显）；之所以这样命名，是因为通常你的终端设置为不直接显示输入的字符，而是等待这些字符被发送到计算机，然后由计算机将其 *echo*（回显）发送回你的终端。

**ed**--一种用于行导文本编辑的常用工具。

**e-mail（电子邮件）**--通过电子介质而非本地邮政发送的消息。有许多专用的电子邮件系统设计用于处理局域网环境内的邮件；其中大多数系统也能通过互联网发送邮件。大多数互联网（开放式）电子邮件系统利用 MIME 来处理附件数据（可以是二进制的）。

**emacs**--一种免费的编辑器，现在是 GNU 软件分发的一部分。它最初由 Richard M. Stallman 在 20 世纪 70 年代于 MIT ，适用于许多平台。它具有极强的扩展性，并有自己的编程语言；该名称代表 Editing with MACroS（使用宏编辑）。

**encapsulation（封装）**--将数据（属性）和函数（以代码形式的行为）组合成对象的过程。数据和函数在对象内部紧密耦合。程序员不是每个程序员都能按照自己的方式访问结构中的数据，而是必须使用与该数据关联的代码。这促进了代码复用和处理数据的标准化方法。

**environment variables（环境变量）**--参见 *variables, environmental*。

**escape（转义）**--(1) (vi) *Esc* 键，用于终止插入模式或未完整的 *vi* 命令；(2) 通过在字符前加上 *escape* 字符（通常是反斜杠 `\`），防止该字符被程序按常规解释；例如在正则表达式中，搜索字面量。

**ethernet（以太网）**--一种网络连接方法，用于连接不同的架构。

**expression（表达式）**--一种结合了常量、变量和运算符的表达式。

**fifo（管道）**--先进入先出（First In, First Out）。参见 *pipe*（管道）。

**file（文件）**--一种存储在设备上的字节集合。目录包含索引的交叉引用。

**compression（压缩）**--通过数学算法减少文件大小的过程。

**loss（丢失）**--在压缩过程中丢失的信息。通常有两种类型：无损的和有损的。

**filename（文件名）**--给文件的名称。

**filename generation（文件名生成）**--为文件创建名称的过程。

**filename, fully（完整文件名）**--包含文件的完整路径。

**filesystem（文件系统）**--用于在存储设备上存储和检索数据和结构。常见的文件系统包括 NTFS、ext4 和 APFS。

**firewall（防火墙）**--一种根据安全规则监控并控制出入流量的安全系统。

**globbing（匹配）**--使用通配符匹配文件名模式的过程。

**flags（标志位）**--用于更改命令行为的选项。

**foreground（前台）**--在前台运行并拥有终端控制权的进程。

**fseek**--用于将文件指针移动到文件中特定位置的函数。

**FTP（文件传输协议）**--一种用于在网络客户端和服务器之间传输文件的标准网络协议。它确保即使在传输过程中出现错误也能正确传输。

**gateway（网关）**--硬件、软件和网络连接的组合，为不同架构提供链接。通常，网关用于连接局域网或 UNIX 服务器与大型机（使用 SNA）。网关也可以是内外部网络之间的连接（通常称为防火墙）。

**GNU**--GNU 代表 GNU's Not Unix（不是 Unix），是 UNIX 环境中常见的、由 MIT GNU 项目分发的免费软件包的名称。

**grep**--一种用于在文件中搜索模式的常用工具。egrep 和 fgrep 是新版本。Egrep 允许使用扩展正则表达式（因此前缀为 e），fgrep 使用有限的表达式进行更快的搜索（因此前缀为 f）。

**here document（在此文档/文档）**--`<<` 重定向操作符被称为在此文档，允许为程序包含键盘输入（`stdin`）。

**HTML（超文本标记语言）**--描述万维网页面。它是通过使用标签定义互联网上可用页面的文档语言。浏览器解释 HTML 以显示所需的信息。

**i-node（索引节点）**--用于描述文件及其存储。目录包含 i 节点与路径/文件名组合之间的交叉引用。也称为 *inode*。

**I-Phone（网络电话）**--一种通过互联网近乎实时传输远距离语音的方法，让参与者避免支付长途电话费用。

**ICMP** (互联网控制消息协议)--TCP/IP 的一部分，提供网络层管理和控制。

**继承**--一种面向对象的软件重用方法，通过使用现有的属性和行为并在此基础上进行扩展，基于现有类开发新类。例如，如果基对象是具有引擎、四个轮子和轮胎属性，以及加速、转向和减速行为的汽车，那么跑车就会修改属性，使得引擎比默认的更大或马力更高，四个轮子将包括合金轮毂和高速轮胎，并且行为也会被修改以实现更快的加速、更小的转弯半径和更快的减速。

**inode**--参见 *i-node*。

**Internet**--不同网络的集合，提供了在它们之间移动数据的能力。它构建在 TCP/IP 通信协议之上。最初由 DARPA 开发，后由 NSF 接管，现在已脱离政府控制。

**互联网服务提供商**--将你连接到互联网的人员。

**IRC (互联网相对聊天)**--一种基于服务器的应用程序，允许一组人通过文本对话进行同时通信。IRC 类似于民用无线电（CB radio）或某些公告板上的“聊天室”。某些聊天可以是私密的（仅限受邀请人员之间）或公开的（任何人都可以加入）。IRC 现在还支持音频文件以及文本——它对于文件交换也很有。

**ISAM (索引顺序访问方法)**--在 UNIX 和其他系统中，ISAM 指一种以键或顺序方式访问数据的方法。UNIX 操作系统不直接支持 ISAM 文件；它们通常是插件产品。

**ISP**--参见 *互联网服务提供商*。

**ISV (独立软件供应商)**--除你的硬件供应商之外的软件供应商的通称。

**内核**--操作系统的核心，处理如内存分配、设备输入输出、进程分配、安全和用户访问等任务。与其他操作系统相比，UNIX 通常具有较小的内核。

**键盘宏**--一种允许特殊键序列代表另一个（通常是更复杂的）序列的功能；在 vi 中，键盘宏通过 `:map` 命令实现。

**kill ring (剪切环)**--(emacs) 用于存储被删除文本的缓冲区集合；缓冲区按圆形排列。当自动从一个缓冲区移动到下一个区的命令到达集合末尾时，下次移动将回到环中的第一个缓冲区。

**Korn Shell**--一种具有广泛脚本（编程）支持的 UNIX 用户界面。由 David G. Korn 编写。该 shell 具有命令行编辑功能，并接受为 Bourne Shell 编写的脚本。

**LAN (局域网)**--在定义的本地区域内连接在一起的网络硬件、软件、桌面计算机、服务器和主机的集合。一个局域网可以是整个大学校园。

**limits**--参见 *quota (配额)*。

**行地址**--(vi 和 ex) 在 *ex* 模式下指示一组选定行的方式是通过行地址的。行地址可以是绝对行号、相对行号，或指向文件开头或结尾的特殊符号。

**链接**

1. **硬链接 (hard)**--为同一文件系统中的另一个文件提供别名的目录项。目录（或其他目录）中会出现一个物理文件对应的多个条目，而无需复制内容。

2. **软链接 (soft)**--参见 *符号链接*。

3. **符号链接 (symbolic)**--为可能位于另一个文件系统的文件提供别名的目录项。目录中会出现一个物理文件对应的多个条目，而无需复制内容。通过链接文件实现；另见*链接文件*。

4. **文件 (file)**--用于实现符号链接的文件，为另一个文件系统上的文件产生一个别名。该文件仅包含原始（被链接）文件的完整文件名。

**lisp**--一种用于人工智能的编程语言。该名称代表 LISt Processing（列表处理）。*Emacs* 使用这种语言编写，同时也指的是其中的三种主要模式。

**字面量字符串**--一个精确的字符字符串，没有通配符。

**登录 (login)**--用户访问 UNIX 系统的过程。也可以指在登录提示处输入的用户 ID。

**LPP**--许可程序产品。

**宏 (macro)**--一组录制的系列按键，可以回放以重复完成相同的任务。

**主模式 (major mode)**--(emacs) 一个命名的行为特征集合；缓冲区一次只能处于一种主模式。例如，用于写信的*文本模式*；用于编写 c 源代码的*c mode*。

**man page (帮助页)**--UNIX 上的参考工具，包含系统文档——即打印手册的实际页面。它以可搜索的形式存储，以提高定位信息的能力。

**manual page (手册页)**--参见 *man page*。

**mappings (映射)**--(vi) 用户定义的字符序列（可能包含控制键），被解释为命令序列（也可能包含控制键）。

**内存 (memory)**

1. **实际 (real)**--系统内正在使用的存储量（硅；曾是磁芯）。

2. **虚拟 (virtual)**--系统内正在使用的存储量（硅；曾是磁芯）。

**元字符 (meta character)**--具有特殊含义的字符。

**MIME (多用途互联网邮件扩展)**--一套电子邮件编码和媒体类型的标准。

**微缓冲区 (mini-buffer)**--(emacs) 输入文本的行。

**要模式 (minor mode)**--(emacs) 可以开启或关闭的特征。

**模式 (mode)**--程序的状态或条件。

**缓冲区 (buffer)**--编辑文本的内存区域。

**命名管道 (named pipe)**--允许进程间通信的特殊文件 (fifo)。

**Netnews**--松散控制的讨论组。。*Usenet News*。

**空语句 (null statement)**--不执行操作的程序步骤。

**数值设置 (numeric setting)**--接受数值的设置。

**对象 (object)**--面向对象编程中具有自身数据和行为的实体。

**ODM**--对象数据库管理器。

**打开模式 (open mode)**--*ex * 编辑器的视觉模式。

**NIS (网络信息服务)**。

**NNTP (网络新闻传输协议)**--用于在 TCP/IP 之上传输 Netnews 或 usenet 消息。

**NFS (网络文件系统)**--将挂载到远程系统的磁盘连接到本地系统的方法，就像物理连接一样。

**operator**--**操作符**——对值或变量执行函数的元字符。加号 `<+>` 是一个用于相两个整数的操作符。

**options**--**选项**——程序或命令特定的指示器，用于控制该程序的行为。有时称为标志（flags）。`ls` 命令的 `-a` 选项显示以 . 开头的文件（例如 .profile、.kshrc 等）。如果没有该选项，无论使用何种通配符，这些文件都不会显示。这些选项用于命令行。另见*parameters*。

**package**--**包**——（emacs）一种可以添加到编辑器中的功能集。主模式（Major modes）和许多功能通过包来实现。许多包内置在标准的 *Emacs* 中，其他许多包可以免费或或其他方式获取。

**parameters**--**参数**——通过命令行传递给命令或程序的数据。这些可以是选项（参见*options*），用于控制命令或命令所处理的参数。某些参数根据其在命令行中的位置具有特殊含义。

**parent process identifier**--**父进程标识符**——在 `ps` 命令的标题中显示为 PPID。父进程的进程标识符。另见*parent-process*。

**parent-process**--**父进程**——控制另一个进程的进程，通常称为子进程或子程序。参见*process*。

**parent-shell**--**父 shell**——控制另一个 shell（通常是登录 shell）的 shell，通常称为子 shell。参见*shell*。

**password**--**密码**——与用户 ID 结合使用以访问 UNIX系统的安全代码。

**pathname**--**路径名**——用于在目录结构中表示文件位置的方法。如果不指定路径名，则默认为当前目录。另见*absolute pathname*和*relative pathname*。

**PDP (Personal Data Processor)**--**PDP（个人数据处理器）**——由数字设备公司（Digital Equipment Corporation）制造的计算机。UNIX 最初为 PDP-7 编写并在 PDP-11 上流行。整个系列都是廉价的微型计算机，深受机构和小型企业的欢迎。

**Perl (Practical Extraction and Report Language)**--**Perl**——由 Larry Wall 开发的编程语言。（Perl 代表“实用提取与报告语言”或“病态折衷的垃圾语言”，二者均有效）。该语言提供了 awk 和 sed 的所有功能，以及 shell 和 C 的许多许多特性。

**permissions**--**权限**——当应用于文件时，它们是控制文件访问的属性。有三个访问级别：所有者（文件创建者）、组（由系统管理员确定的相关组的人员）和其他（其他所有人）。权限可以是 r（读）、w（写）和 x（执行）。执行权限标志也用于控制谁可以搜索目录。

**pipe**--**管道**——一种将一个程序的输出（重定向）发送并使其成为另一个程序的输入的方法。管道字符 `<|>` 告诉 shell 执行重定向。

**pipe file**--参见*named pipe*（命名管道）。

**polymorphism**--**多态/多态**——允许以通用的方式编写代码，以处理现有的和未来的相关类。如果开发得当，相同的行为可以根据其作用的派生对象表现出不同的特性。对于汽车来说，旅行车和加速赛车（它们都是汽车父类的子类）的加速行为可能不同。该函数仍然是 `accelerate()`，但版本会有所不同（这听起来可能很混乱，但编译器会跟踪并解决所有问题）。

**POSIX**--**POSIX**——代表“可移植操作系统接口，UNIX”。它是基于 UNIX 的系列开放系统标准。该名称归功于 Richard Stallman。由 IEEE 工作组 1003.2 (POSIX.2) 开发的 POSIX Shell 和工具标准集中于命令解释器界面和实用程序。

**PPP (Point-to-Point Protocol)**--**PPP（点对点协议）**——串行链路（调制解调器）上的互联网协议。

**process**--**进程**——UNIX 下离散运行程序。用户的交互会话是一个进程。进程可以调用（运行）并控制另一个程序，该程序被称为子进程。最终，用户所做的一切都是操作系统的子进程。

**process identifier**--**进程标识符**——在 `ps` 命令的标题中显示为 PID。分配给系统中运行的每个进程的唯一数字。

**PTF**--程序临时修复（Program Temporary Fix）。

**quota**--**配额**——对用户或进程实施系统限制的通用描述。它可以适用于磁盘空间、内存使用、CPU 使用、最大打开文件数以及许多其他资源。

**quoting**--**引用**——使用单引号和双引号来否定正常的命令解释，并将引号内的所有单词和空白符合并为单个文本单元。

**range**----（vi, ed 和 ex）一种*行地址*，指示从起始行到结束行的一行或多行；表示为 `start,end`，其中 *start* 和 *end* 都是单独的行地址。

**recursive edit**--**递归编辑**——（emacs）一种允许在进行其他编辑时临时挂查询-替换操作的功能。

**redirection**--**重定向**——将数据流从默认值引导的过程。输入可以重定向以从文件获取数据或另一个程序的输出。标准输出可以发送到另一个程序或文件。错误可以发送到另一个程序或文件。

**regular expression**--**正则表达式**——一种匹配字符串的方法。

**relative pathname**--**相对路径**——用于表示相对于当前目录的文件位置的方法。

**reserved word**--**保留字**——UNIX 识别的一组字符。

**RFC (Request For Comments)**--**RFC（意见征询）**——用于标准的文档。

**rlogin (Remote Login)**--**rlogin（远程登录）**——telnet 中使用的安全代码。

**RPC (Remote Procedural Call)**--**RPC（远程过程调用）**——提供了调用远程机器上函数的能力。

**root**--**root**——拥有系统的用户。1）可以做任何事的超级用户。2）目录树的根。

**routing**--**路由**——在不同网络之间移动流量的过程。

**scripts**--**脚本**——使用 shell 语言编写的程序。

**sed**--一种常用的流编辑工具。

**server, database**--服务器，数据库——被指定的运行系统。

**settings**--**设置**——控制某些操作的内部变量。

**Shell**--**Shell**——处理用户输入的 UNIX 部分。

**shell environment**--**shell 环境**——定义命令行特征、功能的变量。

**shell buffer**--（emacs）启动了交互式 shell 会话的缓冲区。

**shell scripts**--shell 脚本——使用 shell 编写的程序。

**shift-key sequence**--Shift 键序列——要执行 Shift 键序列，按住指定的 Shift 键。

**signal**--**信号**——用于向程序通信特殊事件的特殊标志或中断。

**IP (Serial Line Internet Protocol)**--通过在串行链路（调制解调器）上的互联网。该协议封装并控制 TCP/IP 包的传输。

**SMIT**--系统管理界面工具。

**SNA(System Network Architecture)**--IBM 网络架构。

**special keys**--参见*control keys*（控制键）。

`**stderr**`——程序的标准错误输出，默认发送到屏幕上。可以重定向到文件。

`**stdin**`——程序的标准输入，默认从键盘读取。可以重定向以从文件或另一个程序的输出获取输入。

`**stdout**`——程序的标准输出，默认发送到屏幕上。可以重定向到文件或到另一个程序的输入。

**sticky bit**--**粘性位**——文件上的状态标志之一，告诉 UNIX 在第一次执行该文件时，首次将该文件的副本加载到页文件中。

**stream**（流）--一种数据的顺序集合。在 UNIX 操作系统中，所有文件都是流。对它而言，文件没有结构——那种结构是由应用程序或特殊工具（ISAM 包或关系型数据库）强加的。

**sub-directory**（子目录）--参见*directory*（目录）。

**sub-process**（子进程）--在另一个进程控制运行的进程，通常被称为父进程。参见*process*（进程）。

**sub-shell**（子 shell）--在另一个 shell 控制运行的 shell，通常被称为父 shell（通常是登录 shell）。参见*shell*（shell）。

**subnet**（子网）--网络中共享共同 IP 地址组件的部分。出于安全和性能考虑。

**super-user**（超级用户）--参见*root*。

**system administrator**（系统管理员）--负责 UNIX 系统上的操作系统和用户管理事务的人员。也称为系统管理器（system manager），尽管该术语在 DEC VAX 安装中常见。

**system manager**（系统管理器）--参见*system administrator*（系统管理员）。

**system programmer**（系统程序员）--参见*system administrator*（系统管理员）。

**TCP/IP (传输控制协议/网协议)**--一对协议，也是一组工具和协议套件的通用名称。它们构成了互联网的基础。最初开发用于连接系统到 ARPANET。

`**tcsh**`--一种类似于 C shell 的用户界面，具有命令行编辑功能。

**Telnet**--用于对远程系统进行交互式（字符用户界面）终端访问的协议。使用 telnet 协议的终端仿真通常被称为 telnet 或 tnvt100。

**Terminal**（终端）--一种硬件设备，通常包含阴极射线管（屏幕）和键盘，用于人类与计算机系统进行交互。

**text object**（文本对象）--(vi) 文本对象是缓冲区中会被特定移动命令遍历的文本部分；例如 *w* 指下一个小单词。

**text processing languages**（文本处理语言）--一种在文本编辑器中开发文档的方法，带有处理格式的嵌入命令。文件通过一个处理器，该处理器执行嵌入命令并生成格式化后的文档。这些包括 roff, nroff, troff, RUNOFF, TeX, LaTeX 甚至大型主机的 SCRIPT。

**TFTP (简单文件传输协议或简单文件传输程序)**--一种在通过 TCP/IP 连接的系统之间传输文件的系统无关方法。它与 FTP 的区别在于，它不保证文件传输正确，不验证用户身份，并且缺少许多功能（如 ls 命令）。

**toggle**（切换）--一种通过连续输入命令交替开启和关闭的模式。

**toggle setting**（切换设置）--(vi) 一种被启用或禁用的设置；例如，对于名为 *option* 的虚拟设置，你可以通过输入命令 *:set option 来启用该设置；*通过输入命令 :set nooption 来禁用该设置。*。

**top**--一种用于显示系统顶端进程信息的常用工具。

**typewriter key**（打字机键）--终端键盘中标准打字机上的子集；通常是字母键，但不包括功能键、光标控制键或数字键盘。

**UDP (用户数据报协议)**--TCP/IP 的一部分，用于控制消息和不需要交付确认的数据传输。在这种情况下，应用程序必须确保数据传输成功。

**undo buffer**（撤销缓冲区）--(vi) 内存中的一个位置，保存最近删除的文本对象，以便稍后*撤销*删除，或将该对象复制到另一个位置。

**URL (统一资源定位符)**--一种指定互联网上材料的协议、格式、登录（通常省略）和位置的方法。

**Usenet**--参见*Netnews*。

**UUCP (UNIX-to-UNIX-Copy-Program)**--用于构建早期非正式网络，用于传输文件、电子邮件和 Netnews。

**variables, attributes**（变量，属性）--设置变量类型的修饰符。变量可以是字符串或整数、左对齐或右对齐、只读或可更改，以及其他属性。

**variables, environmental**（环境变量）--在 shell 控制区域内存储数据和值（字符串和整数）的地方，以便当前进程和子进程可以使用。它们可以仅限于当前 shell，也可以供子 shell 使用（已导出）。

**variables, substitution**（变量替换）--解释环境变量以获取其值的过程。

**viewport**（视口）--出现在屏幕窗口中的缓冲区部分。移动缓冲区的一种方法是将视口看作在缓冲区中来回滑动。

**Web**（万网）--参见*World Wide Web*（万维网）。

**whitespace**（空白字符）--除非被引用，否则空格和制表符通常解释为分隔命令和文件名。

**wildcard**（通配符）--指定文件名的方法，由操作系统确定某些字符。可能有多个文件匹配，并可供工具使用。

**window**（窗口）--你的屏幕上显示缓冲区视口的部分。

**World Wide Web**（万维网）--互联网上一系列服务器服务的集合，它们运行使用通用协议（HTTP）进行通信的软件。不需要记忆这些资源的位置，而是通过 URL（统一资源定位符）提供从一个网页到另一个网页的链接。

**WWW**--参见*World Wide Web*（万维网）。

**X Window System**（X窗口系统）--由 MIT 开发的窗口和图形系统，用于客户端/服务器环境。

**X**--参见*X Window System*（X 窗口系统）。

**X11**--参见*X Window System*（X 窗口系统）。

**X-windows**--X Window System 的错误术语。参见*X Window System*（X 窗口系统）。
