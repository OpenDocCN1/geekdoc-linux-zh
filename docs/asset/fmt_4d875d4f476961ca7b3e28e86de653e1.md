
- `-L` 强制跟随符号链接：在处理 `'...'` 实例后解析 `DIR` 中的符号链接

- `-P` 使用物理目录结构而不跟随符号链接：在处理 `'...'` 实例之前解析 `DIR` 中的符号链接

- `-e` 如果提供了 `-P` 且无法成功确定当前工作目录，则以非零状态退出

- `-@` 在支持的系统上，将带有扩展属性的文件作为包含文件属性的目录显示

默认是跟随符号链接，就像指定了 `'-L'` 一样。

`'...'` 的处理是通过删除紧接上一个一个路径分量，直到斜杠或 `DIR` 的开始。

退出状态：

如果更改了目录，并且在使用 `-P` 时成功设置了 `$PWD`，则返回 `0`；否则返回非零。

关于符号的说明：当在命令语法的描述中出现方括号时，它们表示可选项目。竖线字符（`|`）表示互斥的项目。以之前的 `cd` 命令为例：

```
cd [-L][-P[-e]] [dir]
```

这种表示法意味着命令 `cd` 后可以可选地跟一个 `-L` 或 `-P`；此外，如果指定了 `-P` 选项，可以包含 `-e` 选项，随后是可选的 `dir`。

虽然 `cd` 命令的 `help` 输出是简洁准确的，但它并不是教程，正如我们所看到的，它似乎还提到了许多我们还没有讨论过的事情！别担心。我们会学到的。

## 使用 alias 创建我们自己的命令

现在开始我们的第一次编程之旅了！我们将使用 `alias` 命令创建一个属于我们自己的命令。但在开始之前，我们需要揭示一个小小的命令行技巧。通过用分号分隔每个命令，可以在同一行中放置多个命令。它的工作原理如下：

```
command1; command2; command3...
```

这里是我们将使用的示例：

```
[me@linuxbox ~]$ cd /usr; ls; cd -
bin games include lib local share src
/home/me
[me@linuxbox ~]$
```

正如我们所见，我们在一行中组合了三个命令。首先，我们将目录切换到 `/usr`，然后列出目录，最后返回到原始目录（通过 `cd -`），我们回到了开始的地方。让我们尝试使用 `alias` 将这个序列放入一个新的命令中。我们必须做的第一件事是为我们的新命令想一个名字。让我们试一下。在此之前，最好先检查一下 `test` 名字是否已经被占用。要找到这一点，我们可以使用 `type` 命令：

```
[me@linuxbox ~]$ type test
test is shell builtin
```

哦不！`test` 名字被占用了。让我们试试 `foo`：

```
[me@linuxbox ~]$ type foo
bash: type: foo: not found
```

太太棒了！`foo` 没有被占用。让我们创建我们的别名：

```
[me@linuxbox ~]$ alias foo='cd /usr; ls; cd -'
```

## 注意这里显示的命令结构：

`alias name='string'`

在 `alias` 命令之后，我们给 `alias` 起一个名字，紧接着（一个等号（不允许有空格），然后紧跟着一个包含分配给该名字的含义的引号字符串。定义别名后，我们可以在 shell 期望命令任何地方使用它。让我们试一下：

```
@me@linuxbox -js foo
bin games include lib local sbin share src
/home/me
@me@linuxbox ~$
```

我们也可以再次使用 `type` 命令来查看我们的别名：

```
@me@linuxbox -js type foo
foo is aliased to 'cd /usr; ls; cd -'
```

要删除别名，使用 `unalias` 命令，如下所示：

```
@me@linuxbox -js unalias foo
@me@linuxbox -js type foo
bash: type: not found
```

虽然我们刻意避免了使用现有的命令名来命名别名，但这种情况并不罕见。这通常是为了对每个常用命令的每次调用应用一个常用的选项。例如，我们之前看到过 `ls` 命令经常被设置别名以添加颜色支持。

```
@me@linuxbox -js type ls
ls is aliased to 'ls --color=auto'
```

要查看环境变量中定义的所有别名，请不带参数地使用 `alias` 命令。以下是 Fedora 系统默认定义的一些别名。尝试弄清楚它们全都是做什么的。

```
@me@linuxbox -js alias
alias l='ls -d * --color=auto'
alias ll='ls -l --color=auto'
alias ls='ls --color=auto'
```

在命令行上定义别名有一个微小的问题：当我们的 shell 会话结束时，它们就会消失。在第 11 章中，我们将看到如何将别名添加到每次登录时建立环境的文件中，但现在，享受我们已经向 shell 编程世界迈出第一步（尽管微小）的事吧！

## 6 重定向

![](img/58edd539af3a70704734cedc1ac0c271_79_0.png)

在本章中，我们将释放命令行可能是最酷的功能。它被称为 I/O 重定向。I/O 代表“输入/输出”（input/output），通过这项功能，我们可以重定向文件的输入和输出，还可以将多个命令连接成强大的命令流水线。为了展示这项功能，我们将引入以下命令：

- `cat`: 合并文件。

- `sort`: 排序文本行。

- `uniq`: 报告或跳过重复行。

- `grep`: 打印匹配模式的行。

- `wc`: 打印每个文件的换行符、单词和字节计数。

- `head`: 输出文件的第一部分。

- `tail`: 输出文件的最后部分。

- `tee`: 从标准输入读取并写入到标准输出和文件。

## 标准输入、输出和错误

我们目前为止使用的许多程序都会输出某种内容。这种输出通常包含两种类型：

- 程序的结果（即程序设计用于产生的数据）

- 告诉我们状态和错误的消息

```
me@linuxbox~$ command1 > logfile.txt; command2 >> logfile.txt; command3 >> logfile.txt
```

如果我们能将这一序列视为一个具有单一输出流的单一实体会怎样？我们可以通过使用分组命令来实现。为了做到，我们用大括号将序列包围起来。

```
me@linuxbox~$ { command1; command2; command3; } > logfile.txt
```

当我们的序列被大括号包围时，shell 在重定向方面会将其视为单一命令。请注意，shell 会处理大括号周围的空格，且序列中的最后一个命令必须以分号或换行符结束。

## 重定向标准错误

重定向标准错误（stderr）缺乏专门的重定向操作符。要重定向标准错误，我们必须引用它的文件描述符。程序可以在几个编号的文件流的任意一个产生输出。虽然我们把这前三个文件流称为标准输入、输出和错误，但 shell 在内部将它们分别引用为描述符 `0`、`1` 和 `2`。shell 提供了一种使用文件描述符数字重定向文件的符号。由于标准错误等同于文件描述符 `2`，我们可以使用这种符号来重定向标准错误：

```
me@linuxbox~$ ls -l /bin 2> ls-error.txt
```

文件描述符 `2` 放在重定向操作符之前，以执行将标准错误重定向到文件 `ls-error.txt`。

## 将标准输出和标准错误重定向到同一个文件

在某些情况下，我们可能希望将命令的所有输出捕到一个文件中。为了实现这一点，我们必须同时重定向标准输出和标准错误。有两种方法可以实现。这里是传统的方法，适用于旧版本的 shell：

```
me@linuxbox~$ ls -l /bin/ls > ls-output.txt 2>&1
```

使用这种方法，我们执行了两次重定向。首先，我们将标准输出重定向到文件 `ls-output.txt`，然后使用 `2>&1` 符号将描述符 `2`（标准错误）重定向到描述符 `1`（标准输出）。

> 注意重定向的顺序至关重要

标准错误的重定向必须始终在重定向标准输出之后，否则它将不起作用。下面的示例将标准错误重定向到文件 `ls-output.txt`：

```
>ls-output.txt 2>&1
```

然而，如果顺序变为

```
2>&1 >ls-output.txt
```

较新版本的 `bash` 提供了另一种更精简的方法来执行合并重定向，如下：

```
[me@linuxbox ~]$ ls -l /bin/usr &>ls-output.txt
```

在这个示例中，我们使用单一符号 `&>` 将输出和标准错误都重定向到文件 `b-output.txt`。我们也可以这样将标准输出和标准错误消息追加到单个文件中：

```
[me@linuxbox ~]$ ls -l /bin/usr &> ls-output.txt
```

## 丢弃不需要的输出

有时“沉默是金”，我们不需要命令的输出；我们只想把它丢掉。系统提供了一种方法，通过重定向到一个名为 `/dev/null` 的特殊文件来实现这一点。这个文件是一个被称为“垃圾桶”（bit bucket）的系统设备，它接受输入但不对其进行任何操作。要抑制命令的错误消息，我们可以这样做：

```
[me@linuxbox ~]$ ls -l /bin/usr 2> /dev/null
```

> 垃圾桶是一个古老的 Unix 概念，由于它的通用性，它出现在 Unix 文化的许多部分。当有人说他们正在将你的评论发送到 `/dev/null` 时，你现在知道那是什么意思了。更多示例请参见 `/dev/null` 的维基百科文章（https://en.wikipedia.org/wiki/Null_device）。

## 重定向标准输入

到为止，我们还没有遇到任何使用标准输入的命令（实际上我们遇到过，但我们稍后会揭示那个惊喜），所以我们需要引入一个。

## cat—连接文件

`cat` 命令读取一个或多个文件并将它们复制到标准输出，如下所示：

```
cat [file...]
```

在大多数情况下，我们可以认为 `cat` 类似于 DOS 中的 `TYPE` 命令。我们可以用它来显示文件而无需分页。例如，以下命令将显示文件 `ls-output.txt` 的内容：

```
$me@linuxbox ~$ cat ls-output.txt
```

`cat` 通常用于显示短文件。由于 `cat` 可以接受多个文件作为参数，它也可以用于合并文件。我们假说我们下载了一个被分成多个部分的大文件（多媒体文件经常在 Usenet 上被拆分），并且我们将它们合并回去。如果文件名为：

```
movie.mpg.001 movie.mpg.002 ... movie.mpg.099
```

我们可以通过以下命令将它们合并回去：

```
cat movie.mpg.* > movie.mpg
```

通配符总是按排序顺序展开，参数将按正确的顺序排列。

这些都很好，但这与标准输入有什么关系呢？目前还没有，但让我们尝试别的。如果我们不带任何参数输入 `cat` 会发生什么？

```
$me@linuxbox ~$ cat
```

什么都没有发生，它就那样坐在那里，就像挂起了一样。看起来似乎是那样，但它实际上在做它应该做的事情。

如果没有给 `cat` 任何参数，它将从标准输入读取，由于标准输入默认连接到键盘，尝试输入内容并按回车：

```
$me@linuxbox ~$ cat
```

红色的狐狸跳过了懒狗。

接下来，输入 `CTRL+D` 告诉 `cat` 已到达文件末尾（EOF）：

```
$me@linuxbox ~$ cat
```

红色的狐狸跳过了懒狗。

在没有参数的情况下，`cat` 将标准输入复制到标准输出，因此我们可以利用这种行为创建文件。假设我们想创建一个包含以下文本的文件：
