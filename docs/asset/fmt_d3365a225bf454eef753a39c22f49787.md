## prex

注意 — `prex` 不支持静态可执行文件。它仅对动态可执行文件有效。

## 调用 prex

你可以通过三种方式调用 `prex`。

- 使用 `prex` 启动目标应用程序的命令行。在这种情况下，目标应用程序不需要构建 `libntfprobe` 的依赖。参见 `TNF_PROBE(3X)`，`prex` 设置环境变量 `LD_PRELOAD` 以将 `libntfprobe` 加载到目标进程中。参见 1(d)，`prex` 然后使用环境变量 `PATH` 寻找目标应用程序。
- 将 `prex` 挂载（Attach）到正在运行的应用程序。在这种情况下，正在运行的目标应用程序应该已经链接了 `libntfprobe`。或者，你可以在调用目标程序之前手动设置 `LD_PRELOAD` 以包含 `libntfprobe.so.1`。
- 使用 `-k` 选项运行 `prex` 将其设置为内核模式（kernel mode）。你可以使用 `prex` 控制内核中的探针（probes）。在内核模式下，定义了额外的命令，且某些在其他模式下有效的命令将失效。

## 控制文件格式和命令语言

在 `prex` 的未来版本中，命令语言可能会移动到由现有脚本语言（如 `ksh(1)`）支持的语法中。目前，`prex` 的接口尚未确定。

- 使用 ASCII 指定指定命令。
- 以换行符结束每条命令。
- 通过在上一行末尾添加反斜杠 (`\`) 将命令延续到下一行。
- 使用空格（一个或多个空格或 Tab）分隔命令中的标记（tokens）。
- 使用 `#` 字符表示行剩余为注释。

## 控制文件搜索路径

你可以通过两种不同的方式与 `prex` 通信：

- 通过控制文件中的指定。在启动期间，`prex` 会在下面指定的目录下搜索名为 `.prexrc` 的文件，`prex` 不会在找到第一个文件后就停止。你可以使用控制文件覆盖任何默认值。搜索顺序为：`$HOME/.`
- 通过在 `prex` 提示符处输入命令。

这两种方法的命令语言是相同的，具体规定见第 1052 页的“用法”（Usage）部分。返回输出的命令在控制文件中没有意义。输出将发送到标准输出。

当 `prex` 用于目标进程时，目标处于两种状态之一：运行或停止。你可以通过是否存在 `prex>` 提示符来检测状态。如果提示符不存在，说明目标进程正在运行。输入 Control-C 会停止目标进程并返回提示符。无法保证 Control-C 会立即返回 `prex` 提示符。例如，如果目标进程在作业控制停止（SIGSTOP）处停止，则 `prex` 中的 Control-C 将等待目标被继续运行（SIGCONT）。有关信号和目标进程的更多信息，请参见第 1056 页的“给目标程序的信号”（Signals to Target Program）。

注意
目前，唯一用的探针函数是 `&debug` 函数。当执行此函数时，它会将发送给探针的参数以及详细字段中与 `sunw&debug` 属性关联的值（如果有）打印到标准错误输出。

例如，对于该探针点：

```
TNF_PROBE_2(input_values, "testapp main",

sunw&debug "have read input values successfully",

tnf_long, int_input: x,

tnf_string, string_input, input);
```

如果 `x` 为 100 且 `input` 为字符串 `"success"`，那么探针函数的输出将为：

```
probe input_values; sunw&debug "have read input values successfully",

int_input=100; string_input="success";
```

## 选项

- `-k` 控制 Solaris 内核中的探针。内核模式定义了额外的命令并使其他模式下有效的命令失效。参见第 1056 页的“内核模式”（Kernel Mode）。
- `-l` `libraries` 将库（用双引号括起的库名空格分隔字符串）链接到目标。
- `-o` `output` 指定写入跟踪输出的文件。如果没有指定，输出将发送到标准输出。
- `-s` `size` 设置跟踪缓冲区的大小（单位为 KB）。默认值为 4096。
