
**稀疏文件（sparse files）**：在许多文件系统中，文件的存储方式可以使得大型“空白”部分被“跳过”，而不是作为长长的`NUL`字符流存储。对这些文件的任何正常操作行为都会像这些文件区域填充了空字符一样。存储在磁盘上的数据远少于整个文件。这对于大型数据集特别有用。

执行`seek()`和`lseek()`超过现有文件末尾的程序可能会创建一个“洞”（取决于跳转间隙的大小、文件系统类型及其块大小设置）。

关于`cp`、`tar`等类似命令如何影响其操作的文件的“稀疏性”的信息，可以在第12章“备份”中找到。

**静态链接（statically linked）**：一个所有函数调用和变量都在其内部解析的程序。此类程序很少见但很有用，因为即使在系统其他地方没有有效的共享库，它们也能运行。对比动态链接。

**交换（swapping）**：技术上讲，`Linux`内核提供的是分页（`paging`）而不是“交换”。然而，所有支持这种分页的实用程序（从磁盘`"type"`选项将硬盘硬盘部分标记为“交换分区”，到标识这些设备的`/etc/stab`术语，通过`swap`和`swapoff`命令）都使用交换的术语。另见虚拟内存。

**符号链接（symlink）**：符号链接。目录中的一个项，它不是文件，但包含一个通常应该访问的文件名（除非`lstat`或其他命令作用于链接时）。对比硬链接。

**`tar`包（tarball）**：对`tar`命令创建的文件的常用术语。这用于压缩和未压缩归档。这通常用于区分包管理系统。`Slackware`和其他发行版使用“`tar`包”作为包格式。这些是源码和二进制文件的独立归档。`Red Hat`发行版和其他某些使用`RPM`，`Debian GNU/Linux`和`Stampede`使用自己的包格式。

**线程（thread）**：称为“轻量级进程”。`Linux`除了伪线程（`pthreads`）外支持内核线程（`kthreads`）。这些允许在单个进程上下文中多任务处理。

内核线程是`Linux`特有的功能，支持多个执行单元（`CPU`调度）共享单个内存/进程空间。多线程程序使用“线程安全”库。

伪线程在大多数形式的`Unix`下支持，并在进程内的不同执行行之间提供协作多任务处理，不需要内核支持。它们使用`threads`库。

**陷（trap）**：见信号处理程序。

**喷子（troll）**：在`USENET`新组或邮件列表上旨在引起冲突和口战的帖子，或者从事这种活动的人（被称为“喷子”）。

**`UFS`**：一种`BSD`文件系统类型。`Linux`对这些文件系统的支持有限，目前为只读。当你读到这里时，它将已经对这些文件系统有许多高级支持。目前尚不清楚`UFS`是否比`ext2fs`有任何优势。然而，在您可能需要的少数情况下，这种支持可能是用的。

将`BSD`或`Solaris`硬盘连接到你的`LINUX`系统。这在`S/Linux`（`SPARC`端口）下可能非常常见，您可能需要访问其他文件系统。

**`umask`**：`UNIX`进程中的一种设置，用于修改新创建文件的权限。它通常表示为一个三位八进制数，将与模式`666` (`rw-rw-rw-`)进行逻辑“与”运算。注意：在任何情况下，新创建的文件都不会包含执行位。

常用的设置`022`将导致创建的文件模式为`644`，即所有者、组和其他用户可读，只有所有者具有写入/修改权限。`027`掩码将导致文件所有者可读/写，分配给这些文件的组成员可读（通常是所有者的主`GID`，更多细节请参见`SGID`目录第287页）。

在`SGID`目录中工作时，`007`或`002`掩码是合理的。对于大多数情况，首选`077`或`027`。

**`UMDOS`**：`Linux`的`MS-DOS`文件系统驱动程序的变体，它通过使用包含必要元数据的特殊文件提供对`UNIX`文件系统语义的支持。`UFFAT`是`LINUX VFAT`驱动程序的变体，支持`Windows 95`或`98`长文件名。

详情可以在`mount(8)`手册页、内核源码和文档中找到。

**`Unix`**：`Linux`仿照的操作系统。尽管该词经常被用来指代任何具有模拟`UNIX`特性和编程接口的操作系统，但该术语是开放组（`The Open Group`）合法拥有的注册商标。

**`VC`**：参见虚拟控制台（`virtual console`）。

**`VFS`**：虚拟文件系统。`Linux`内核中的抽象层，使其能够对多种底层文件系统类型提供通用接口，例如其原生的`ext2fs`和`xfs`、`MS-DOS FAT`以及`Windows 95`或`98/Windows NT VFAT`类型等许多类型，允许大多数用户程序和实用程序操作其上的文件。

**`virtual`**：不是真实的，而是不可见的；由计算机提供的仿真。该词用作前缀。参见`VFS`、虚拟控制台、虚拟内存。

- 如果它存在且你能看到，它是真实的。

- 如果它不存在但你能看到，它是虚拟的。

- 如果它存在但你看不见，它是透明的。

- 如果它不存在且你看不见，它被删除了！

> ——旧的`IBM PC`平台的`UNIX`实现。此功能允许控制台（键盘和显示器）被视为几个“虚拟终端”。

每一个都有自己的设备节点`(/dev/tty??)`并可以运行自己的`getty`副本。控制台上的可以登录任何有效用户名。大多数发行版都配置为支持带有`getty`的`VC`。通过编辑`/etc/inab`文件添加额外的`getty`会话（可能使用`mkmod`命令）。

默认情况下，使用`Left Alt+F1`到`Left Alt+F6`在前六个`VC`之间切换。如果使用了超过`12`个`VC`，可以使用`Right Alt`键访问第`13`到第`24`个。也可以使用`Left Alt+Arrow`和`Right Alt+Arrow`在活动`VC`之间“循环”。当运行`xdm start X`时，这些会话绑定到第一个虚拟控制台（最后一个`getty`之后）。可以使用`Ctrl+Alt+F2`切换到其他`VC`。通过将输出重定向到相应的设备节点。通过向`/etc/syslog.conf`添加条目，可以配置`syslogd`复制或重定向消息到`VC`。可以在`VC`上启动交互式程序。

**`virtual memory`**：实际可用内存之外的内存。

**`virtual terminal`**：参见`virtual console`。

**`afs`**：早期`Linux`原生类型的文件系统。它支持`Minix`文件系统，后来被`ext`（扩展）和`ext2fs`（第二扩展）文件系统取代。以它的创建者`Frank Xia`命名。

`Linux`支持许多文件系统类型；任何程序员都可以编写一组新的驱动程序到`Linux VFS`接口。

**`zombie`**：内核进程表中的项，直到父进程对其执行`wait()`调用。僵尸也被称为`defunct process`。导致僵尸的进程已执行了`exit()`，分配给它的内存、打开的文件等所有资源已被内核回收。要消除僵尸，杀死父进程（可以通过`ps`命令的`PPID`列发现）。为了防止僵尸，程序员可以使用“双`fork()`”作为`exec()`的一部分，让孙进程成为孤儿进程，随后会被`init`进程收养（详见`init`）。另一种方案是程序员创建一个信号处理器来响应`SIGCHLD`事件，这是内核通知父进程任何孩子死亡的方式。简而言之，只有程序员可以防止僵尸。
