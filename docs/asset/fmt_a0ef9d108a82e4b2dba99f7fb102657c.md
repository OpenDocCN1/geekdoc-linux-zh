## uucp, uolog, uuname

### uuname

- `-c` 显示 `cu` 已知的系统名称。除非你的系统为 `cu` 和 `uucp` 使用了不同的 Systems 文件，否则这两个列表是相同的。请参见 Sysfiles 文件。
- `-1` 显示本地系统名称。

### 操作数

源文件名可以是你系统上的路径名，也可以采用以下形式：`system-name!pathname`

其中 `system-name` 取自 `uucp` 知道的系统名称列表。`source-file` 限制为最多一个 `system-name`。目标 `system-name` 也可以包含一个系统名称列表，例如 `system-name!system-name!...system-name!pathname`。

使用此语法，`uucp` 尝试使用指定的路由将文件发送到目的地。请确保路由中的中间节点愿意转发信息。

> 注意 — 通过其他系统转发文件可能与之前的 `uucp` 版本不兼容。如果你使用转发，路由中的所有系统必须具有兼容版本的 `uucp`。

对于 C shell，请用单引号 (`''`) 将字符括起来，或者在字符前加一个反斜杠 (`\`)。
路径名中出现的 shell 字符 `?`、`*` 和 `[...]` 会在相应的系统上展开。
路径名可以是以下之一：

- 一个绝对路径名。
- 以 `-user` 为前头的路径名，其中 `user` 是指定系统上的登录名，并替换为该用户的登录目录。
- 以 `~/var/spool/~destination` 为前头的路径名，其中 `destination` 被附加在 `/var/spool/uucpublic` 之后。

> 注意 — 除非你在此请求中传输多个文件，或者目标已经是一个目录，否则该目标被视为文件名。要确保目标是一个目录，请在其后面加上一个斜杠 (`/`)。例如，将 `~/dan/` 作为目标会在其不存在时创建 `/var/spool/uucpublic/` 目录，并将请求的文件放入该目录中）。任何其他内容都将以当前目录为前缀。

如果结果是远程系统的错误路径名，则复制将失败。如果 `destination-file` 是目录，则使用 `source-file` 文件名的最后部分。

## uucp, uulog, uuname 1435

使用 shell 通配符字符作为远程 `source-file` 调用 `uucp` 会调用 `uux(1C)` 命令在远程系统上执行 `uucp` 命令。远程 `uucp` 命令会在远程系统上对文件进行缓冲。在第一次会话结束后，如果远程系统配置为将缓冲文件传输到本地系统，远程系统将发起调用并发送文件；否则，用户必须“调用”远程系统以将文件从缓冲目录传输到本地系统。这可以通过 `Utry(1M)` 手动完成，也可以作为另一个 `uux(1C)` 或 `uucp` 调用的副作用完成。

`uucp` 会移除传输过程中的权限并赋予 `0666` 的读写权限（参见 `chmod(2)`）。

注意，本地系统必须具有在远程系统上执行 `uucp` 命令的权限，以便远程系统能够发送缓冲文件。

## 环境变量

请参见 `environ(5)` 以获取以下影响 `uucp` 执行的环境变量描述：`LC_COLLATE`, `LC_CTYPE`, `LC_MESSAGES`, `LC_TIME`, `TZ`, 和 `NLSPATH`。

## 退出状态

- `0` 成功完成。
- `>0` 发生错误。

## uuencode, uudecode — 编码或解码二进制文件

### 概要

```
/usr/bin/uuencode [source-file] decode-pathname

/usr/bin/uudecode [-p] encoded-file
```

## Description

使用 `uuencode`/`uudecode` 命令在 ASCII 和二进制数据之间转换。

> **警告** — 如果你运行 `uuencode` 然后在同一目录下的文件上运行 `uudecode`，你将覆盖原始文件。

**`uuencode`**
`uuencode` 将二进制文件转换为编码表示，你可以使用 `mail(1)` 发送它。它编码 `source-file` 的内容，如果未指定 `source-file` 参数则编码标准输入。`decode-pathname` 是必须的。`decode-pathname` 包含在编码文件头部，作为 `uuencode` 存放二进制（解码后的）数据的文件名。`uuencode` 还包含了 `source-file` 的权限模式（除 setuid、setgid 和粘滞位外），以便用这些权限模式重新创建 `decode-pathname` 对应的文件。

> **注意** — 因为编码文件的大小扩大了 35%（3 字节加上控制信息），传输到等效的二进制文件需要更长时间。

**`uudecode`**
`uudecode` 读取 `encoded-file`，去除由邮件程序添加的任何开头和末尾行，并重建原始二进制文件。

## uuencode, uudecode 1437

## 选项

- `-p` Decode-file

### 操作数

- `-p` Decode-pathname 文件的模式。
- `source-file` 要编码的文件。
- `encoded-file` 文件的路径。

## 用法

参见 `largefile(5)` 关于 `uuencode` 在遇到大于或等于文件时的行为。

## 环境变量

参见 `environ(5)` 以获取影响 `uuencode` 执行的环境变量描述：`LC_TYPE`, `LC_MESSAGES`。

## 输出

标准输出是一个文本文件（按字符集编码），以 `begin%s\n", <mode>` 开头，以 `end\n` 结尾。

在两种情况下，`begin` 和 `end` 之间的行都没有空白字符。

## uuglist

这些字节通过为每个字节加上 `0x20` 来转换为字符，使得每个字节都在 `0x20-05f` 范围内。随后假设它表示一个打印字符。

当两个字节的位组合时，第一个字节的低位左移，并与第二个字节的高位右移后组合。因此，三个字节 `A`, `B`, `C` 被转换为后后四个字节：

```
0x20 + ((A >> 2) & 0x3F)

0x20 + ((A << 4) (B >> 4) & 0xF) & 0x3F

0x20 + ((B << 2) (C >> 6) & 0x3F)

0x20 + ((C) & 0x3F)
```
