
- 线程可以是同步取消的（synchronously）。线程仅在执行过程的特定点可以被取消。相反，取消请求会被队列，直到线程到达取消点时才被取消。
- 线程可以是不可取消的（uncancelable）。取消线程的尝试会被忽略。

创建时，线程是同步取消的。

### 4.2.1 同步与异步线程

要使线程变为异步取消，请使用 `pthread_setcanceltype`。这影响的是调用该函数的线程。第一个参数应该是 `PTHREAD_CANCEL_ASYNCHRONOUS` 以使线程变为异步取消，或者使用 `PTHREAD_CANCEL_DEFERRED` 使其返回同步取消状态。第二个参数如果为 null，则是一个指向变量的指针，该变量将接收之前的取消类型。例如，此调用使调用线程变为异步取消。

```c
pthread_setcanceltype(PTHREAD_CANCEL_ASYNCHRONOUS, NULL);
```

什么构成了取消点，这些点应该放在哪里？创建取消点的最直接方法是调用 `pthread_testcancel`。这对于同步取消的线程除了检查悬挂的取消请求外什么都不做。你应该在线程函数进行长时间计算期间定期调用 `pthread_testcancel`，放置在可以取消且不会泄漏资源或产生其他影响的地方。

某些其他函数也是隐式的取消点。这些函数在 `pthread_cancel` 的手册页中有列出。注意其他函数内部可能会使用这些函数，因此将间接成为取消点。

## 4.2 线程取消 (Thread Cancellation)

### 4.2.2 不可取消的关键界区

线程可以通过 `pthread_setcancelstate` 函数完全禁用自身的取消。与 `pthread_setcanceltype` 类似，这会影响调用线程。第一个参数是 `PTHREAD_CANCEL_DISABLE` 以禁用取消，或 `PTHREAD_CANCEL_ENABLE` 以重新启用。第二个参数如果不为 `NULL`，则指向一个变量，该变量将接收之前的取消状态。例如，此调用会禁用调用线程的取消功能。

`pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, NULL);`

使用 `pthread_setcancelstate` 允许你实现临界区。临界区是一段要么完整执行、要么不执行的代码；换句话说，如果一个线程开始执行临界区，它必须继续执行到该区域结束而不被取消。

例如，假设你正在编写一个银行程序的例程，从一个账户转账到另一个账户。为了实现这一点，你必须增加一个账户余额的数值，并从另一个账户的余额中减除相同的数值。如果运行你例程的线程恰好在两个操作之间的错误时间被取消，银行的存款总额将由于交易未完成而异常增加。为了防止这种发生，请将这两个操作放在一个临界区中。

你可能使用如列表 4.6 所示的 `process_transaction` 函数来实现转账。该函数在修改账户余额之前通过禁用线程取消来启动一个临界区。

#### 列表 4.6 (critical-section.c) 使用临界区保护银行交易

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 账户中的数组数组，通过账户号索引。 */

float* account_balances;

/* 从 FROM_ACCT 账户转账 美元到 TO_ACCT 账户。
   如果交易成功则返回 0，如果 FROM_ACCT 余额
   不足则返回 1。 */

int process_transaction(int from_acct, int to_acct, float dollars)
{
    int old_cancel_state;

    /* 检查 FROM_ACCT 的余额。 */
    if (account_balances[from_acct] < dollars)
        return 1;

/* 开始临界区。 */
    pthread_setcancelstate(PTHREAD_CANCEL_DISABLE, &old_cancel_state);
    /* 移动资金。 */
    account_balances[to_acct] += dollars;
    account_balances[from_acct] -= dollars;
    /* 结束临界区。 */
    pthread_setcancelstate(old_cancel_state, NULL);

    return 0;
}
```

注意，在临界区结束时恢复旧的取消状态，而不是无条件地将其设置为 `PTHREAD_CANCEL_ENABLE` 是重要的。这允许你从另一个临界区安全地调用 `process_transaction` 函数——在这种情况下，你的函数将保持取消状态处于你发现它时的状态。

### 4.2.3 何时使用线程取消

通常，除非在特殊情况下，否则不使用线程取消来结束线程的执行是一个好主意。在运行期间，更好的策略是指示线程它应该退出，并等待它以有序的方式退出。我们将在本章后半部分以及第 5 章“进程间通信”中讨论与线程通信的技术。

## 4.3 线程特定数据 (Thread-Specific Data)

与进程不同，程序中的所有线程共享相同的地址空间。这意味着如果一个线程修改了内存中的某个位置（例如全局变量），更改对所有其他线程可见的。这允许多个线程在不使用通信机制（在第 5 章描述）的情况下操作相同的数据。

然而，每个线程都有自己的栈。这允许每个线程以通常的方式执行不同的代码并从子程序返回。与单线程程序一样，每个线程中每个子程序的每次调用都有自己的局部变量集，这些变量存储在对应线程的栈上。

有时，希望复制常量变量，以便每个线程拥有一个单独的副本。GNU/Linux 通过为每个线程提供线程特定数据区域来实现这一点。存储在该区域中的变量会为每个线程复制一份，每个线程可以修改其变量副本而不影响其他线程。由于所有线程共享相同的内存空间，可能无法使用普通的变量引用访问线程特定数据。GNU/Linux 提供了特殊函数用于从线程特定数据区域设置和检索值。

你可以创建任意数量的线程特定项，每个类型为 `void*`。每个项由键（key）引用。要创建一个新键，从而为每个线程创建一个新数据项，请使用 `pthread_key_create`。第一个参数是指向 `pthread_key_t` 变量的指针。每个线程都可以使用此键值来访问其对应数据项的副本。`pthread_key_t` 的第二个参数是一个清理函数。如果你在这里传递一个指针，GNU/Linux 在每个线程退出时会自动调用该函数，并传递与键对应的线程特定值。这特别棘手，因为清理函数是在执行的某个任意点被调用的。如果线程特定值为 `null`，则不会调用清理函数。如果你不需要清理函数，可以传递 `null` 代替函数指针。

创建键后，每个线程可以通过调用 `pthread_setspecific` 设置其相对应的线程特定值。第一个参数是键，第二个是待存储的 `void*` 线程特定值。要检索线程特定数据项，调用 `pthread_getspecific`。

假设，例如，你的应用程序将任务分配给多个线程。列表 4.7 显示了如何使用线程特定数据实现线程特定日志。每个线程必须有一个独立的日志，其中记录了进度。

#### 列表 4.7 (test.c) 使用线程特定数据实现的线程特定日志

```c
#include <stdio.h>
#include <pthread.h>
#include <stdlib.h>

/* 与每个线程关联日志文件指针的键。 */
static pthread_key_t thread_log_key;

/* 向当前线程的日志文件写入消息。 */
void write_to_log(const char* message)
{
    FILE* thread_log = (FILE*) pthread_getspecific(thread_log_key);
    fprintf(thread_log, "%s\n", message);
}

/* 关闭日志文件指针。 */
void close_thread_log(void* thread_log)
{
  fclose((FILE*)thread_log);
}

void* thread_function(void* args) {
  char thread_log_filename[20];
  FILE* thread_log;

  /* 生成此线程的文件。 */
  sprintf(thread_log_filename, "thread%d.log", (int) pthread_self());
  /* 打开日志文件。 */
  thread_log = fopen(thread_log_filename, "w");
  /* 在 thread_log_key 下的线程特定数据中存储。 */
  pthread_setspecific(thread_log_key, thread_log);

  write_to_log("Thread starting.");
  /* 在此处执行工作... */
  return NULL;
}

int main() {
  int i;
  pthread_t threads[5];

  /* 创建一个键在线程特定数据中关联日志文件指针。
     使用 close_thread_log 清理指针。 */
  pthread_key_create(&thread_log_key, close_thread_log);
  /* 创建线程执行工作。 */
  for (i = 0; i < 5; ++i)
    pthread_create(&threads[i], NULL, thread_function, NULL);
  /* 等待所有线程完成。 */
  for (i = 0; i < 5; ++i)
    pthread_join(&threads[i], NULL);
  return 0;
}
```

### 4.3.1 清理处理程序

线程特定数据键的清理函数非常有用，它们可以确保在线程退出或被取消时不会泄漏资源。然而，有时在不为每个线程创建一个重复的新的线程特定项目的情况下，指定清理函数 也是很有用的。GNU/Linux 为此目的提供了清理处理程序。

清理处理程序是一个简单的函数，它在线程退出时应该被调用。该处理程序接收一个 `void*` 参数，其参数值在注册处理程序时提供——这使得使用同一个处理程序来处理多个资源实例变得简单。

清理处理程序是一种临时措施，仅当线程退出或被取消（而不是完成特定代码区域的执行）时，才释放资源。在正常情况下，当线程没有退出也没有被取消时，应该显式地释放资源并移除清理处理程序。

要注册清理处理程序，请调用 `pthread_cleanup_push`，传递清理函数的指针和其 `void*` 参数的值。`pthread_cleanup_push` 的调用必须与相应的 `pthread_cleanup_pop` 调用相平衡，后者会注销清理处理程序。为了方便，`pthread_cleanup_pop` 接收一个 `int` 标志参数；如果该标志非零，则在注销时实际执行清理操作。

列表 4.8 中的程序展示了如何使用清理处理程序来确保在线程终止时，动态分配的缓冲区被清理。

#### 列表 4.8 (cleanup.c) 展示线程清理处理程序的程序片段

```c
#include <malloc.h>
#include <pthread.h>

/* 分配一个临时缓冲区。 */
void* allocate_buffer(size_t size)
{
    return malloc(size);
}

/* 释放一个临时缓冲区。 */
void deallocate_buffer(void* buffer)
{
    free(buffer);
}

void do_some_work(void *)
{
    /* 分配一个临时缓冲区。 */
    void* temp_buffer = allocate_buffer(1024);
    /* 为此缓冲区注册清理处理程序，以便在
    退出或被取消时释放它。 */
    pthread_cleanup_push(deallocate_buffer, temp_buffer);

    /* 执行一些工作，这里可能会调用 pthread_exit 或可能被
    取消。 */

    /* 注销清理处理程序。因为我们传递了一个非零值，
    这实际上通过调用 deallocate_buffer 执行了清理。 */
    pthread_cleanup_pop(1);
}
```

由于在这种情况下 `pthread_cleanup_pop` 的参数是非零，因此清理函数 `deallocate_buffer` 会被自动调用，不需要显式调用。在这一简单的例子中，我们可以自由地使用标准库函数 `deallocate_buffer` 作为我们的线程处理程序函数。

### 4.3.2 C++ 中的线程清理

C++ 程序员习惯于通过在对象析构函数中封装清理操作来获得“免费”的清理。当对象超出作用范围时（因为代码块执行完毕，或在抛出异常之前），C++ 会确保为那些具有析构函数的自动变量调用析构函数。这提供了一种方便的机制，可以确保无论代码块如何退出，清理代码都是安全的。

然而，如果线程调用了 `pthread_exit`，C++ 并不保证会为线程栈上所有的自动变量调用析构函数。恢复此功能的方法是在线程顶层通过抛出特殊异常来调用 `pthread_exit`。

列表 4.9 中的程序演示了这一点。使用这种技术，函数通过抛出 `ThreadExitException` 而不是调用 `pthread_exit` 来退出线程。因为异常在线程顶层被捕获，所以线程栈上的所有局部变量都将在异常传播时正确销毁。

#### 列表 4.9 (cxx-exit.cpp) 使用 C++ 异常实现安全的线程退出

```cpp
#include <pthread.h>

class ThreadExitException
{
public:
    /* 使用 RETURN_VALUE 创建一个带有异常信号的线程退出。 */
    ThreadExitException(void* return_value)
    : thread_return_value_ (return_value)
    {
      /* 使用构造函数中提供的返回值实际退出线程。 */
      void* DoThreadExit() {
        thread_exit (thread_return_value);
      }
  private:
    /* 退出线程时将使用的返回值。 */
    void* thread_return_value_;
  };
  void do_some_work () {
    while (1) {
      /* 在这里执行一些实用的事情... */
      if (should_exit_thread_immediately()) {
        throw ThreadExitException(/* 线程的返回值 = */ NULL);
      }
    }
  }
  void* thread_function(void*) {
    try {
      do_some_work();
    } catch (ThreadExitException ex) {
      /* 函数指示我们应该退出线程。 */
      ex.DoThreadExit();
    }
    return NULL;
  }
}
```

## 4.4 同步与临界区

使用线程进行编程非常棘手，因为线程程序是并发程序。特别是，没有方法知道系统何时调度一个线程运行，以及它何时运行。

### 4.4.2 互斥锁

解决作业队列竞态问题的解决方案是一次只允许一个线程访问作业。一旦一个线程开始查看队列，在第一个线程决定是否处理作业并将其从列表中移除之前，任何其他线程都不应该能够访问它。

实现互斥锁（Mutexes）需要操作系统的支持。GNU/Linux 提供了互斥锁（Mutual Exclusion）。互斥锁是一种特殊的锁，一次只能有一个线程锁定。如果一个线程锁定了互斥锁，然后另一个线程尝试锁定同一个互斥锁，第二个线程将被阻塞或挂起。只有当第一个线程释放互斥锁时，第二个线程才会被解除——允许恢复执行。

要创建互斥锁，创建一个类型为 `pthread_mutex_t` 的变量并传递给 `pthread_mutex_init`。`pthread_mutex_init` 的第二个参数是互斥锁属性对象的指针，它指定了互斥锁的属性。

`pthread_create`，如果属性指针为空，则默认开启锁定属性。如果互斥锁变量只需要初始化一次。这段代码演示了互斥锁变量的声明和初始化。

```
pthread_mutex_t mutex;
pthread_mutex_init(&mutex, NULL);
```

创建具有默认属性的互斥锁的另一种简单方法是用特殊值 `PTHREAD_MUTEX_INITIALIZER` 对其进行初始化。不需要额外调用 `pthread_mutex_init`。这对于全局变量（在 C++ 中为静态数据成员）特别方便。之前的代码片段可以等价地写如下：

```
pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
```
