## 切换用户与提升权限

在理想的世界里，用户不需要提升权限来完成任务。系统将始终可用，且所有访问都已配置。幸运的是，Linux 尽管始终遵循最小权限模型，对于大多数不是系统管理员的用户是可以工作的。

然而，某些命令允许在需要时提升权限。最重要的两个是 `su` 和 `sudo`。

在现在的大多数 Linux 系统中，`su` 命令仅用于提升权限到 `root`（如果命令后没有指定用户名，默认如此）。虽然它可以切换用户，但这不是良好的做法：用户应该从另一个系统、通过网络、物理控制台或终端登录。

```
emma su -

Password:

root#
```

输入超用户 (`root`) 密码后，用户拥有了超用户 shell（注意提示符末尾的 `#`），从所有意义来说都是超用户 (`root`)。共享密码是一种非常糟糕的安全实践，因此在现代 Linux 系统中几乎不需要使用 `su` 命令。

美元符号 (`$`) 应该是非特权用户的命令行提示符，而井号 (`#`) 应该是超用户 (`root`) shell 的命令行提示符。强烈建议不要更改任何提示符的最后一个字符，这种“通用”的标准被用于包括这些在内的学习材料。

> 在不传递登录 shell (`-`) 参数的情况下，永远切换到超用户 (`root`)。除非操作系统或软件供应商明确要求使用 `su`，否则始终在极少数例外的情况下执行 `su`。用户环境在全权限模式下会导致意外的配置更改和问题。

使用 `su` 切换到超用户 (`root`) 最大问题是什么？如果普通用户的会话被破解，超用户 (`root`) 的密码可能会被捕获。这就是“切换用户”或“切换 sudo”的用例所在：

```
$ cat /sys/devices/virtual/dmi/id/board_serial

cat: /sys/devices/virtual/dmi/id/board_serial: Permission denied
```

```
$ sudo cat /sys/devices/virtual/dmi/id/board_serial

[sudo] password for emma:

6789ABC
```

在前面的列表中，用户正尝试查找主板的序列号。然而，权限被拒绝，因为该信息被标记为特权。

然而，使用 `sudo`，用户输入密码来验证身份。如果他在 `sudoers` 配置中被授权以权限运行该命令并允许相应的选项，它就能工作。

- **提示** 默认情况下，第一个经过授权的 `sudo` 命令将在很（非常短）时间内验证随后的 `sudo` 命令。这可以由系统管理员进行配置。

### /etc/passwd

`/etc/passwd` 文件通常被称为“密码文件”。每行包含多个字段，始终以冒号（`:`）作为分隔符。尽管名称如此，但实际的单向密码哈希值不再存储在此文件中。

该文件中每一行的典型语法为：

```
USERNAME:PASSWORD:UID:GID:GECOS:HOMDIR:SHELL own
```

其中：

### USERNAME

用户名，又称登录名（name），如 `root`、`nobody`、`emma`。

### PASSWORD

密码哈值的旧留位置。几乎总是 `x`，表示密码存储在 `/etc/shadow` 文件中。

### UID

用户 ID (`UID`)，例如 `0`、`99`、`1024`。

### GID

默认组 ID (`GID`)，例如 `0`、`99`、`1024`。

### GECOS

用户信息的 CSV 列表，包括姓名、地点、电话号码。例如：`Emma Smith,42 Douglas St,555.555.5555`

### HOMDIR

用户主目录的路径，例如 `/root`、`/home/emma` 等。

### SHELL

用户的默认 shell，例如 `/bin/bash`、`/sbin/nologin`、`/bin/ksh` 等。

例如，以下行描述用户 `emma`：

```
emma:x:1000:1000:Emma Smith,42 Douglas St,555.555.5555:home/emma:/bin/bash
```
