`-Y P,dirlist` 修改查找库的默认目录。`dirlist` 是冒号分隔的路径列表。

`-z alextract | defaultextract | weakextract`

修改从后续任何归档提取对象的提取标准。默认情况下，提取归档成员以满足未定义的引用，并用数据定义提升临时定义。弱符号不会触发提取。对于 `-z alextract`，从归档提取所有归档成员。对于 `-z weakextract`，弱引用触发提取。`-z defaultextract` 提供了一种在使用上述之前的提取选项后返回默认设置的方法。

`-z cmreloc`

合并多个重定位段。此选项减少了对象加载到内存传输的开销。

`-z defs`

如果在链接结束时仍存在任何未定义的符号，则强制产生致命错误。在构建可执行文件时，此选项是默认值。在构建共享对象时也有用，可以确保对象是自包含的，即其所有的符号引用都在内部已解析。

`-z ignore | record`

忽略未作为链接一部分引用的记录动态依赖。`-z record` 是默认值。

`-z initfirst`

标记对象，使其运行时初始化发生在同时被引入进程的其他任何对象的运行时初始化之前。此外，任何其他对象的运行时终化发生在同时从进程中移除时。此选项仅在构建共享对象时有效。

`-z lazyload | nolazyload`

启用或禁用对懒加载动态依赖的标记。被标记为 `lazyload` 的动态依赖不会在进程启动时立即加载，而是延迟到对对象进行第一次绑定时。

`-z loadfltr`

标记对象，要求在构建过滤器时，被过滤的对象在运行时被立即处理。通常情况下，过滤器处理会延迟到符号引用绑定到过滤器时。包含此标志的对象的运行时处理模拟了设置 `LD_LOADFLTR` 环境变量时发生的情况。参见 `ld.so(1)`。

`-z muldefs`

启用多个符号定义。默认情况下，可重定位对象之间发生的多个符号定义将导致致命错误。此选项抑制错误条件并允许采用第一个符号定义。

`-z nodefs` 启用未定义符号。在构建共享对象时，此选项是默认值。当与可执行文件配合使用时，此类未定义符号的引用行为未定义。

`-z nodelete` 标记对象在运行时不可删除。包含此标志的对象的运行时处理模拟了通过 `dlopen(3)` 以 `RTLD_NODELETE` 模式将对象添加到进程时发生的情况。

`-z nodopen` 标记对象对 `dlopen(3)` way，无论是作为 `dlopen()` 指定的对象，还是作为 `dlopen()` 指定的对象所需的任何形式的依赖。此选项仅在构建共享对象时有效。

`-z nopartial` 如果输入可重定位对象文件中存在任何部分初始符号，则在生成输出文件时扩展这些符号。

`-z noversion` 不记录任何版本段。输出图象中不会生成任何版本段或相关的 `.dynamic` 段条目。

`-z now` 标记对象覆盖运行时链接器的默认模式，并要求主要进行运行时绑定。此选项类似于使用 `dlopen(3)` 以 `RTLD_NOW` 模式将对象添加到进程，或通过设置 `LD_BIND_NOW` 环境变量。参见 `ld.so.1(1)`。

`-z origin` 标记对象在运行时立即处理 `$ORIGIN`。

`-z relocms` 从符号表 `SHT_SYMTAB` 中删除除 `SECT` 符号以外的所有本地符号。更新所有引用本地符号的分配以引用相应的 `SECT` 符号。

仅在动态模式下，如果仍存在针对不可写的可分配段的重定位，则强制产生致命错误。

`-z textoff` 仅在动态模式下，允许针对所有分配段（包括不可写段）的重定位。此选项在构建共享对象时是默认值。

`-z textwarn` 仅在动态模式下，如果仍存在针对不可写的可分配段的重定位，则列出警告。此选项在构建可执行文件时是默认值。

# 不再支持的选项

以下 `SunOS 4.x.y` 选项在此发行中没有替代方案：`-B nosymbolic`（如果不使用 `-B symbolic`，此选项为默认值）、`-d`、`-dc` 和 `-dp`（这些选项现在是默认值；参见上面的 `-b` 以覆盖默认值）、`-M`、 `-S`、 `-t`、 `-x` 和 `-ysym`。

以下 `SunOS 4.x.y` 选项不受支持：`-align datum`、 `-A name`、 `-D hex`、 `-p`、 `-T[text] hex`、 `-T data hex`。这些选项的大部分功能可以通过 `-M mapfile` 选项实现。

## 环境变量

`LD_LIBRARY_PATH`

用于搜索带有 `-l` 选项库的目录列表。用冒号分隔多个目录。在最通用的情况下，该变量包含两个用分号分隔的目录列表：

```
dirlist1;dirlist2
```

如果在调用 `ld` 时带有多次 `-L`，例如：

```
ld -L path1 -L path2...
```

那么搜索路径顺序为：

```
dirlist1... pathn2 dirlist2 LIBPATH
```

当目录列表不包含分号时，它被解释为 `dirlist2`。

`LD_LIBRARY_PATH` 环境变量也会影响运行时链接器搜索动态依赖。

`LD_LIBRARY_PATH_64`

与 `LD_LIBRARY_PATH` 环境变量相似。

用于绑定到目录。

其值已放置在命令行上。

注意 - 以 `LD_LIBRARY_PATH_64` 开头的环境变量用于绑定到目录。
