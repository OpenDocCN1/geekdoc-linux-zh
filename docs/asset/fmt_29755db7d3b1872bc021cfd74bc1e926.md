
## 术语表

### access control lists (访问控制列表)
用户和访问模式的列表，由操作系统在尝试访问文件系统对象（如文件、目录、设备、进程、套接字等）期间进行检查。从内核 `2.2` 版本开始，`LINUX` 不再在其文件系统或其他对象上支持 `ACL`——已有添加此类支持的项目。见 `meta-data`（元数据）。

### ACL
详见 `access control lists`。

### archive (存档)
一个包含其他文件的文件。大多数形式的存档都包含其中的每个文件的 `meta-data`。有许多类型的存档；这些通常以主要用于创建、访问和操作它们的命令命名。

- `esr` 指 `Eric S. Raymond`（见前言）。因此，`tar` 命令创建 `tar` 文件，`zip` 和 `unzip` 命令的各种实现处理 `zip` 文件，而 `cpio` 创建 `cpio` 存档。

按照习惯，存档文件会被赋予文件扩展名以指示其格式。然而，对于 `cpio` 和 `dump` 存档的命名并没有通行的标准，这些很少（几乎从不）被用于公开分发文件。

### artistic license (艺术许可)
为 `Perl` 编程语言提供的替代版权许可。它赋予版权所有者控制权，并为用户提供了一套相当慷慨的权利，使其复制、修改和制作衍生作品，但仍鼓励将其免费发布。`BSD` 许可。`GPL`。`NPL`。

### attributes (属性)
除了标准的 `UNIX` 权限外，`ext2` 文件系统包含额外的属性，文件系统驱动程序在每次访问或修改文件时都会遵循这些属性。通过 `chattr` 命令设置或取消属性，通常按名称引用这些位。`immutable`（不可变）属性在系统管理员中特别受欢迎，用于保护关键文件免受缺乏经验的 `root` 用户的意外破坏。

### background (后台)
一个脱离了控制台（虚拟控制台）的任务继续运行，速度慢于前台任务。见 `job control`（作业控制）。

### backup (备份)
备份（或 `archive`）这两个词都可以用作名词和动词。名词指的是可移动介质上某组文件（及其相关 `meta-data`）的任何副本。动词指的是创建此类集合的任何过程。将一组文件到非易失性存储的额外副本有时被称为“备份”，但更准确的说法是“复制”（`replication`）、“镜像”（`mirroring`）或（某些情况下）“版本控制”（`version control`）。

### big red switch (大红开关)
（口语）重置按钮或电源开关。这是系统“挂起”（无响应）时重启系统的最后手段。

### binaries (二进制文件)
可执行的二进制文件。这是一个行业术语，用于区分编译后的程序与脚本或源码。任何非文本文件都被称为“二进制”文件，但该词通常指代可执行的非文本文件。不可执行的非文本文件通常被称为原始数据，或以其格式命名（如 `GIF` 文件或 `Laser` 数据）。该词也可用于 `archive` 语境，指代包含二进制文件而非源代码的存档。

### binary (二进制的)
作为形容词，用于区分文本文件和非文本文件（那些包含不可打印字符的文件，通常不适合用普通的文本编辑器如 `NUIS` 进行编辑）。作为名词，是 `binaries` 的单数形式。

### BIOS (基本输入输出系统)
这是 `PC` 的固件。最初，`BIOS` 提供的例程被 `MS-DOS` 用于访问硬件。这使得硬件的某些细节被抽象化为一组“`BIOS` 调用”（类似于 `UNIX`/`LINUX` 的“系统调用”，以便相同版本的 `MS-DOS`（或其他早期 `PC` 操作系统）可以在无需修改的情况下运行在不同的系统上）。然而，在现代计算中（使用任何 `32` 位操作系统，如 `Linux` 甚至 `Windows NT`），`BIOS` 被用作启动加载器和设置 `CMOS` 值的手段。

`BIOS` 必须写在实模式模式（`real mode`）中，而绝大多数现代操作系统要求处理器处于保护模式。这些模式的内存寻址是不兼容的，尽管该系列的 `386` 或后续处理器可以模拟“实模式模式”以创建一个“虚拟 `8086`”。因此，`BIOS` 的“工具箱”在正常运行期间已不再有用。

### block (块)
与字符特殊文件、命名管道或普通文件不同，字符特殊文件是到设备的直接链接，一次只能处理一个。这些有时也被称为字符设备。

### CISC (复杂指令集)
一种 `CPU`（微处理器）设计，强调提供了大量复杂的机器语言。`Intel` 从 `8080` 到 `Pentium` 的 `CPU` 线通常被归类为 `CISC`。大多数其他处理器被认为是 `RISC` 设计。

### CMOS (互补金属氧化半导体)
随着 `PC AT`（基于 `286`）系统的引入，系统增加了实时时钟和电池。这些芯片使用 `CMOS` 是因为其电压要求和电流低（一个纽扣电池可以让 `CMOS` 运行多年）。

### byte (字节)

### COFF (通用对象格式)
一种可执行二进制文件的格式（也称为 `.out`），在现代 `Unix` 和 `Linux` 系统已过时。在现代 `Linux` 系统上编译的程序都是 `ELF`（可执行链接格式）。

### compiled (已编译的)
被编写后编译成特定平台代码程序。虽然这种代码是移植的，但必须在每个硬件平台上重新编译，产生无法在平台间交换的二进制文件。对比解释。

### data set (数据集)
备份计划中包含的文件和目录树列表。“全面”数据集将包含系统上的“所有”文件（这实际上应该排除 `/proc` 下的“伪文件”以及大多数其他文件）。其他数据集可以更具体。人们可能有一个“系统”数据集，由系统文件（二进制文件、帮助手册、图标和其他资源）组成。这可能包含系统的配置文件，也可以将它们指定在不同的数据。人们可能有一个针对所有用户的“用户数据集”，或针对特定应用程序（如数据库）的“应用数据集”。

关键点在于数据集是待备份内容的集合。通常可以恢复备份的子集。因此，备份“全面”数据集是常见的。然而，如前所述，这并非总是理想或可能的。

### device nodes (设备节点)
文件系统中的一个项，用于提供对内核设备驱动程序的访问。通常位于 `/dev`，并被创建为块特殊文件或字符特殊文件。

### differential (增量备份)
这是对给定数据集中自上一次全量备份以来已添加或修改的所有文件的备份。要恢复数据集，需要先恢复最近的零级备份（`level zero`）和最近的增量备份。增量备份包含了之前所有的增量备份。在通常情况下，每个增量备份的大小会一直增长，直到执行下一次“零级备份”。

### directory (目录)
一个包含文件链接列表的特殊文件。链接由文件名和一个索引节点（`inode`）项组成。某些文件系统在目录中存储小型符号链接（`symlinks`），而在其他情况下，符号链接的目标可能存储在由索引节点分配的数据中。

### distributions (发行版)
`Linux` 是一个自由系统，任何人都可以选择与其他自由软件一起使用、对其进行打包、围绕其构建，并将其出售或赠送他人。“发行版”一词通常用于描述任何围绕 `LINUX` 和其他自由软件构建的软件。某些发行版还包含非自由组件。`Linux` 发行版大致可以分为两类：如 `Red Hat`、`Debian` 和 `Slackware` 这样的“通用型”发行版，以及特殊的“微型发行版”，如 `Tom's Root/Boot`、`LRP`（`Linux` 路由器项目）等。

### dynamically linked (动态链接)
一种部分函数和变量存储在共享库中的程序。此类程序很常见，通过使用系统其他地方的函数可以获得许多额外益处，例如减少内存开销。与静态链接（`statically linked`）对比。

### ELF (可执行文件格式)
`ELF Executable Format`，`LINUX` 下存储二进制文件最常用的文件格式。所有现代内核都应配置并编译为支持运行 `ELF` 文件。某些内核可能还会（可选地）配置为对 `out`（`COFF`）和 `Java` 编译文件的支持。可执行文件格式之间的差异不应与动态链接与静态链接文件之间的区别混淆。

### endless loop (死循环)
参见 `loop, endless`。

### error messages (错误信息)
通常是程序失败时产生的文本或其他输出，用于指示其失败的性质。与退出状态（`exit code`）对比，后者可能并不表示错误。

### exit code (退出状态)
当典型的 `shell` 脚本或函数执行结束时返回的值，它可能并不表示错误。当典型的 `shell` 脚本或函数执行结束时，它返回一个 `0` 到 `255` 之间的整数，以告知父进程是否成功。
