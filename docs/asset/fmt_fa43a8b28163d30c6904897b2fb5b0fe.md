# PeeWeeLinux 的优缺点

让我们来看看 PeeWeeLinux 如何应对我们的问题列表

## 生成的镜像有多大？

PeeWeeLinux 生成的镜像并不全是小的。大问题在于使用了 glibc。脱离 glibc 可能很难，但对于非常小的应用程序，你必须这样做。PeeWeeLinux 自带的 glibc 文件略大于 1MB。使用 ulibc 甚至是旧的 lib5 可能是更好的选择。这会让开发环境变得复杂，但从成本来看是值得的。

## 支持哪些架构？

PeeWeeLinux 拥有令人印象深刻的 x86 目标架构等，但截至目前，仅支持 x86。如果你在寻找 PowerPC、StrongARM 等，请查看其他地方。对于 x86，PeeWeeLinux 支持以下环境：
- FAT 16 分区上的压缩 RAM 磁盘
- ext2 分区上的压缩 RAM 磁盘
- FAT 16 分区上的未压缩 RAM 磁盘
- ext2 分区上的未压缩 RAM 磁盘
- 多个 RAM 磁盘的只读根文件系统
- 无引导加载器的软磁盘上的压缩 RAM 磁盘
- 带有 syslinux 的 FAT 12 磁盘上的压缩 RAM 磁盘
- 单分区上的读写根目录

## 总目标

这些是嵌入式 Linux 工作坊（ELW）的总目标：
- 必须易于学习。
- 在现实场景中必须有用。

这些是你通过 ELW 构建的嵌入式 Linux 应用的目标：
- **最小化代码大小**：任何嵌入式工具包的首要任务应该是构建一个使代码大小最小化的嵌入式应用程序。代码越小，运行所需的内存和闪存就越少；这减少了最终的组合。
- **可扩展性**：嵌入式 Linux 工作坊力求尽可能可扩展。在概念上，添加各种应用程序包、库技术和处理器的支持应该是很容易的。这在开源世界尤为重要，项目可以拥有自己的生命——如果软件难以管理，项目的增长可能会受到很大限制。

### 一点历史

关于我的家庭网络。在花了几个小时让 DNS、DHCP 和按需拨号正常工作后，我意识到典型的 Windows 用户几乎没有希望让 Linux IP 伪装（IP masquerading）运行。因此，我决定为他们提供方便，构建了 ShareTheNet。
ShareTheNet 的设计限制非常简单：它必须放进一张 1.44MB 的软盘中。仅此而已。如果装不下软盘，它就不会进入产品。
这导致很多酷的开发工具被排除。例如，Perl、C++ 和 Java 拥有巨大的运行时库，因此它们被排除了。这同时也排除了我喜欢的某些功能。例如，对 IP 伪装的早期投诉之一是它不支持 H.323 连接。H.323 的行为确实像一个普通的 TCP/IP 客户端/服务器应用程序；低级代理（如 NAT 或 IP 伪装）无法工作，因为它们通常只查看流量的内容——仅仅是数据包中的地址信息。遗憾的是，微软的 Meeting 等视频电话软件规定了该协议。Linux 可用的专有“看门人”软件意味着该软件是用 C++ 编写的，并且比软盘大得多。它装不下。幸运的是，这个问题通过一个针对 H.323 的特定协议 IP 伪装模块解决了。

ShareTheNet 的安装过程如下：
- 1. 用户运行一个名为 `ShareTheNet.exe` 的基础程序。它的目的是收集有关特定安装的用户输入，并根据这些输入构建一个可启动的 Linux 软盘。
- 2. 构建软盘。
- 3. 使用软盘启动另一台电脑。该电脑将作为连接互联网的网络网关。

启动软盘包含以下项目：
- Linux 内核
- 一个极简的 `initrd.gz` 文件
- 可选软件包
- 用户选择的网络驱动程序
- `SYSLINUX` 文件
- 单个配置文件

ShareTheNet 通常从软盘启动，尽管它可以从硬盘启动。由于软盘是在 Windows 环境下构建的，因此将其格式化为 FAT 格式比 ext2 更有意义。这排除了 LILO。ShareTheNet 的原始版本使用了一个小的 `autoexec.bat` 来运行 `load1`，但这要求软盘上带有 DOS 操作系统——浪费了软盘 1/3 的空间。现在 ShareTheNet 从 `SYSLINUX` 启动，它需要的资源极少且比 `loadlin` 快得多。`SYSLINUX` 要求软盘上有两个文件：`syslinux.cfg`（SYSLINUX 配置文件）和 `llinux.sys`（一个 5KB 的文件，包含将 Linux 内核和 `initrd.gz` 文件加载到内存并运行内核的代码）。

以下是 ShareTheNet 的执行序列：
- 1. 内核解压自己和 `initrd.gz` 文件并开始运行。解压后的 `initrd.gz` 镜像成为根 RAM 磁盘。
- 2. 内核读取加载所有内置设备驱动程序后，从 `initrd.gz` RAM 磁盘运行 `/initrc` 脚本。
- 3. `/linuxrc` 命令从启动介质加载并解压其他包。这些包以压缩 tar 包的形式存储。
- 4. 运行 `ldconfig` 命令重新构建共享库缓存 (`/etc/ld.so.cache`)。之所以这样做是因为某些可选包需要一两个通常不需要的共享库。必须运行 `ldconfig` 命令，以便加载器找到共享库。
- 5. 接下来运行特定包的启动脚本。这是大多数服务启动的方式，例如 `ident`、`named`、`dhcpd`（服务器）和 `dhcpd`（客户端）。
