
## 文件系统监控

问题在于 `/EXCEPTIONS` 文件中的 `/home` 文件系统条目。指定的值为 50 兆，而 `/home` 文件系统的大小只有 4MB。在这种情况下，`check_exceptions` 函数将显示错误消息并使用 shell 脚本默认值来测量文件系统，然后向调用脚本返回适当的代码。因此，如果对异常文件进行了修改，则需要运行脚本来检查错误。

需要注意的是，错误检查和数据验证应该在数据用于测量之前进行。这种顺序还可以防止系统可能产生的任何标准错误（`stderr`）消息。

## 自动执行

如果我们监控系统，我们希望在出现问题时告诉我们。我们需要事件通知，但也希望事件通知是自动化的。对于文件系统监控，`cron` 表格是实现此点的最佳方法。最常见的是 24×7 每隔 10–15 分钟一次。我们内置了异常功能，这样如果页面出现问题，可以修改异常文件以停止文件系统处于错误状态，从而停止传真。接下来的 `cron` 条目将每 10 分钟执行一次脚本，每天 24 小时，每周 7 天。

```bash
5,15,25,35,45 * * * /usr/local/bin/fs_mon_ALL.sh 2>&1
```

要创建此 `cron` 条目，你可以使用 `crontab -e` 编辑 `cron` 表，或使用以下命令序列将条目附加到 `cron` 表末尾。

```bash
crontab -l > /tmp/cron_hold.out
echo '5,15,25,35,45 * * * /usr/local/bin/fs_mon_ALL_OS.ksh 2>&1' >> /tmp/cron_hold.out
```

```bash
crontab /tmp/cron_hold.out
rm /tmp/cron_hold.out
```

为了这项工作，必须修改 `fs_mon_ALL_OS.ksh` 脚本通过某种方法发送通知。传真、电子邮件、SNMP 陷和调制解器拨号是首选方法。你可以将此输出发送系统控制台，但谁会看到它呢？

当可用时，数据页将调入内存。在 AIX 中，监控分页使用情况需要使用 `lsps` 命令，该命令代表“列出分页空间”（list paging space）。`lsps` 命令有两个选项：`-a` 用于单独列出每个分页空间，`-s` 显示所有分页空间的摘要。这里显示了这两个 `lsps` 选项：


| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| hd6 | hdisk0 | rootvg | 1024MB | 9 | yes | yes | lv |

```bash
# lsps -s
```

| 总分页空间 | 使用百分比 |
| :--- | :--- |
| 2048MB | 10% |

从第一个命令输出 `lsps -a` 可以看出，该系统定义了两个分页空间：`paging0` 和 `hd6`，它们的大小均为 1GB，且每个分页空间位于单独的磁盘上。这是一个重要的点。在 AIX 中，分页空间以轮询（round-robin）方式使用，从空闲区域最大的分页空间开始。如果分页空间差异悬殊，轮询技术就会失效，系统将始终使用较大的分页空间。这会对性能产生负面影响，因为一个磁盘将承担所有的分页活动。

在第二个输出 `lsps -s` 中，我们得到了分页空间大小和使用百分比的摘要。注意，我们获得的是使用百分比。通过这两条数据，我们必须计算所需输出的剩余部分，即总分页空间（MB）、剩余空间（MB）、已用空间（MB）、使用百分比和剩余百分比。我们将在本章稍后的 AIX 脚本部分介绍这些点。

## HP-UX swapinfo 命令

HP-UX 操作系统使用交换（swapping），这通过 `swapinfo` 命令可以明显看出。HP-UX 在提供详尽的命令输出方面做得最好，因此我们只需要为所需的输出计算一个数据项：即总交换空间的百分比。所有信息都通过 `swapinfo -tm` 命令提供。`-m` 切换以 MB 为单位输出，`-t` 切换用于生成所有虚拟内存的总计摘要。该命令显示如下：

```bash
[root@domain]# swapinfo -tm
Mb Mb Mb PCT START/ Mb
TYPE AVAIL USED FREE LIMIT RESERVE NAME
dev 96 73 22% 928768 1 /dev/disk/c06d0
reserve 46 -
memory 15 10 33%
total 111 72 37 65% - -
```

注意此输出，HP-UX 将虚拟内存分为三类：`dev`（设备）、`reserve`（预留）和 `memory`（内存）。对于我们的需求，可以使用底部 `total` 行显示的摘要信息。你从 `total` 行中看到，总虚拟内存为 111MB，系统使用了其中的 72MB，剩余 37MB 虚拟内存。第五列显示系统使用了可用虚拟内存的 65%。然而，当我们只感兴趣交换空间的使用情况时，这个总计行具有误导性。实际的交换空间位于命令输出顶部 `dev` 行的数据中。如所示，我们只需要计算剩余部分，这是一个简单的计算。

## Linux free 命令

Linux 使用交换和 `free` 命令来查看内存和交换空间的使用情况。`free` 命令有多个开关，但我们只关心 `-m` 参数，它以 MB 为单位列出输出。`free -m` 命令提供的交换信息以 MB 为单位，且输出中没有百分比。因此，我们必须根据总 MB、已用 MB 和剩余 MB 计算出使用百分比和剩余百分比。如下所示：

```
free total used shared buffers cached
Mem:          52 51 1 0 1 20
-/ buffers/cache:      30 22
Swap:         211 9 202
```

此输出的最后一行是按 `-m` 开关指定的 MB 单元列出的交换信息。该命令输出显示系统共有 211MB 交换空间，其中已使用 9MB，剩余 202MB 交换空间。
