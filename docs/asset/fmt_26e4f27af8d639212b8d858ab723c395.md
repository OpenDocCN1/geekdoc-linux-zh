
默认情况下，如果存在竞争锁，锁请求将阻塞（不返回）。一旦竞争锁被移除且请求的锁获取成功，调用返回。（这意味着默认情况下存在死锁的可能性。）要尝试在不阻塞的情况下获取锁，请将`LOCK_NB`与操作的其他值之一进行按位或运算。

关于`flock()`的关键点如下：

- `flock()`锁定也是建议性锁定；一个不进行锁定的程序可以进来肆意破坏，即使文件已被`flock()`锁定，也不会报错。

- 整个文件被锁定。没有机制仅锁定或解锁文件的一部分。

- 文件的打开方式对可放置的锁类型没有影响。（这与`fcntl()`不同，对于`fcntl()`，读锁要求文件以读模式打开，写锁要求文件以写模式打开。）

- 打开在同一文件上的多个文件描述符共享锁。其中任何一个都可用于移除锁。与`fcntl()`不同，如果没有显式解锁，锁只有在该文件的所有打开文件描述符都关闭后才会被移除。

- 一个进程在一个文件上只能持有一个`flock()`锁；连续以两种不同的锁类型调用`flock()`会将锁更改为新类型。

- 在GNU/Linux系统上，`flock()`锁与`fcntl()`锁完全独立。许多商业Unix系统将`flock()`实现为基于`fcntl()`的“包装器”，但语义并不相同。

我们不建议在新程序中使用`flock()`，因为其语义不如其他机制灵活，且该调用未被POSIX标准化。GNU/Linux对此的支持主要旨在兼容为旧版BSD Unix系统编写的软件。

> **注意** GNU/Linux的`flock(2)`手册页警告称，`flock()`锁对远程挂载的文件不起作用。只要拥有足够新版本的Linux和支持锁定的NFS服务器，`fcntl()`锁是可以工作的。

### 14.2.4 强制锁定

大多数商业Unix系统除了支持建议性文件锁定外，还支持强制性文件锁定。强制锁定仅适用于`fcntl()`锁。文件的强制锁定由文件的权限设置控制，特别是通过`chmod`命令为文件添加setgid位来控制：

```bash
$ echo hello, world > myfile
$ ls -l myfile
-rw-r--r-- 1 arnold devel 13 Apr 3 17:11 myfile
$ chmod g+s myfile
$ ls -l myfile
-rw-r--sx- 1 arnold devel 13 Apr 3 17:11 myfile
```

组执行位应保持关闭状态。`s`表示setgid位已打开，但执行权限未打开；如果两者都打开，则使用`x`。

setgid开启且组执行关闭的组合通常没有意义。因此，System V开发者选择将其用于表示“强制执行锁定”。事实上，添加此位就足以使诸如Solaris这样的商业Unix系统强制实施文件锁。

在GNU/Linux系统上，情况略有不同。强制锁定必须将setgid位应用于文件，但仅此还不够。包含该文件的文件系统还必须以`mand`选项挂载到`mount`命令。

我们已经在第8.1节“挂载和卸载文件系统”第228页中主要介绍了文件系统、磁盘分区、挂载和`mount`命令。我们可以使用一个小程序和软盘上的测试文件系统来演示强制锁定。首先，这是该程序：
