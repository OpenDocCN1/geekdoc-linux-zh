## kill: 终止进程

`kill` 内置命令向进程或作业发送信号。`kill` 命令具有以下语法：

```
kill [-signal] PID
```

`signal` 是信号名称或编号（例如 `INT` 或 `2`），`PID` 是接收信号的进程标识符。你可以使用数字（第 237 页）`%n` 代替 `PID`。如果省略 `signal`，`kill` 会发送一个 TERM（软件终止，编号 15）信号。有关信号名称的更多信息请参见第 451 页的表 11-5。

以下命令向作业 1 发送 TERM 信号：

```
$ kill -TERM %1
```

由于 TERM 是 `kill` 的默认信号，你也可以使用命令 `kill %1`。执行命令 `kill -l`（小写“l”）可以显示信号名称列表。

被中断的程序通常会留下处于不可预测的状态：临时文件可能会被留下（而它们通常会被删除），权限可能会被更改。良好的应用程序在退出前会捕获、检测并清理。大多数编写良好的程序会应用 INT、QUIT 和 TERM 信号。

要终止程序，首先尝试 INT（如果作业在前台，按下 CTRL-C）。由于应用程序可以编写为忽略这些信号，你可能需要使用 KILL 信号，它无法被捕获或忽略；它是“真正的杀死”。更多信息请参见第 522 页的“kill: 向进程发送信号”。

## getopt: 解析选项

`getopt` 解析命令行参数，使得编写遵循 Linux 参数惯例的程序变得更容易。`getopt` 的语法为

```
getopts optstring varname [arg ...]
```

其中 `optstring` 是选项字母列表，`varname` 是逐个接收选项的变量，如果 `arg` 不存在，`getopt` 处理命令行参数。

### 内置命令 455

`getopts` 内置命令使用 `OPTIND`（选项索引）和 `OPTARG`（选项参数）变量来存储选项相关的值。当 shell 脚本运行时，`OPTIND` 的值为 1。每当 `getopts` 定位到一个参数，它会将 `OPTIND` 增加到下一个要处理选项的索引。如果该选项需要参数，bash 会将参数的值分配给 `OPTARG`。

要指示某个选项需要参数，请在 `optstring` 中对应的字母后加一个冒号 (`:`)。选项字符串 `doxopt` 表示 `getopts` 应该搜索 `-d`、`-x`、`-o`、`-l`、`-t` 和 `-r` 选项，并且 `-o` 和 `-t` 需要参数。

在 `while` 控制结构中使用 `getopts` 作为测试命令可以让你逐个遍历选项。`getopts` 内置命令会检查列表中是否存在于 `optstring` 中的选项。每次循环时，`getopts` 将找到的选项字母存储在 `varname` 中。

假设你想编写一个可以接受以下三个参数的程序：

1. `-b` 选项表示程序应该忽略输入行开头的空白
2. `-t` 选项后接目录名称表示程序应该使用该目录作为临时文件。否则，它将使用 `/tmp`。
3. `-u` 选项表示程序应该将其所有输出转换为大写。

此外，程序应该忽略所有其他选项，并在遇到双连字符 (`--`) 时结束选项处理。

问题在于解决程序中确定用户提供了哪些选项的这。以下解决方案没有使用 `getopts`：

```
SKIPBLANKS=-
TMPDIR=/tmp
CASE=lower
while [[ "$1" ]] # [[ $1 ]] 匹配
do
  case $1 in
    -b)
      SKIPBLANKS=TRUE ;;
    -t)
      if [ -d "$2" ]; then
        TMPDIR=$2
        shift
      else
        echo "$0: -t takes a directory argument." >&2
        exit 1
      fi ;;
    -u)
      CASE=upper ;; # 停止处理选项
      break ;;
    --)
      break ;;
    *)
      echo "$0: Invalid option $1 ignored." >&2 ;;
  esac
  shift
done
```

此程序片段使用循环在参数不是 `--` 时检查并移位（`shift`）参数。只要参数不是双连字符，程序就会继续循环通过 `case` 语句来检查可能的选项。`--` `case` 标签识别任何选项；它作为最后一个 `case` 标签出现，以捕获任何未知选项，显示错误信息并允许处理继续。在每次循环中，程序都会执行 `shift` 移动到下一个参数。如果某个选项需要参数，程序会额外执行一次 `shift` 以跳过该参数。

接文的程序片段处理相同的选项，但使用了 `getopts`：

```
SKIPBLANKS=mp
TMPDIR=~
CASE=lower

while getopts :bt:u arg
do
  case $arg in
    b) SKIPBLANKS=TRUE ;;
    t) if [ -d "$OPTARG" ]; then
         TMPDIR=$OPTARG
       else
         echo "$0: $OPTARG is not a directory." >&2
         exit 1 ;;
       fi ;;
    u) CASE=upper ;;
    :) echo "$0: Must supply an argument to -$OPTARG." >&2
       exit 1 ;;
    \?) echo "Invalid option -$OPTARG ignored." >&2 ;;
  esac
done
```

在这个版本的代码中，结构在每次回到循环顶部时都会评估 `getopts`。`getopts` 内置命令使用 `OPTIND` 变量来跟踪下一次调用时参数的索引。在这个示例中，不需要对 `case` 语句执行 `shift`。

在 `getopts` 版本的脚本中，`case` 模式不以连字符开头，因为 `arg` 的值只是选项字母（`getopts` 剥掉了连字符）。此外，`getopts` 将 `--` 识别为选项的结束，因此你不需要在第一个示例的 `case` 语句中显式指定。

由于 `getopts` 知道哪些选项是有效的，哪些需要参数，它可以检测命令行中的错误并以两种方式处理它们。此示例在 `optstring` 中使用前冒号表示由你在代码中检查并处理错误；当 `getopts` 发现无效选项时，它会将 `varname` 设置为 `?`并将 `OPTARG` 设置为该选项字母。当它发现缺少参数的选项时，`getopts` 将 `varname` 设置为 `:`并将 `OPTARG` 设置为缺少参数的选项。

`?` `case` 模式指定了 `getopts` 发现无效选项时要采取的操作。`:` `case` 模式指定了 `getopts` 发现缺失选项参数时要采取的操作。在这两种情况下，`getopts` 都不会写入任何错误信息；它将此任务留给你。

如果你省略了 `optstring` 前的冒号，无效选项和缺失选项参数都会导致 `varname` 被赋值为 `?`，`OPTARG` is not set，并且 `getopts` 会向标准错误写入它自己的诊断信息。通常这种方法较不理想，因为你对用户看到的内容或错误发生的时间的控制权较少。

使用 `getopts` 不一定会让你的程序更短。它的特殊优势是提供了一个统一的编程接口并强制执行标准的选项处理。

## 算术求值

Bourne Again Shell 可以执行算术赋值并评估不同类型的算术表达式，均使用整数。shell 有多种方式执行算术赋值。其中一种是作为内置命令的参数：

```
$ let VALUE=VALUE * 10 + NEW
```

在前面的示例中，`VALUE` 和 `NEW` 包含整数值。在 `let` 语句中，不需要在变量名前加美元符号 (`$`)。双引号必须包含包含空格的单个参数或表达式。由于大多数表达式包含空格且需要引号，bash 接受 `((expression))` 作为 `let expression` 的同义词，消除了对引号和美元符号的需求：

```
$ ((VALUE=VALUE * 10 + NEW))
```

你可以在允许命令的地方使用任何形式，并根据喜好删除空格。在下面的示例中，星号 (`*`) 不需要引号，因为 shell 不会在赋值右侧执行路径名扩展（第 298 页）：

```
$ let VALUE=VALUE*10+NEW
```

由于 `let` 的每个参数都被视为独立的表达式进行求值，你可以在单行内为多个变量赋值：

```
$ let COUNT=COUNT+1 VALUE=VALUE+10+NEW
```

你需要在双括号内使用逗号来分隔多次赋值：

```
$ ((COUNT=COUNT+1, VALUE=VALUE+10+NEW))
```

### 算术评估与算术扩展

算术评估与算术扩展不同。如第 342 页所示，算术扩展使用 `$((expression))` 语法，求值表达式，并将 `$((expression))` 替换为结果。你可以使用算术评估来显示表达式的值或为变量赋值。

算术评估使用 `let` 表达式或 `((expression))` 语法，求值表达式并返回状态码。你可以使用算术评估来执行逻辑比较或赋值。

你可以对逻辑表达式使用 `((expression))` 语法，尽管这通常被留给了 `[[expression]]`。下一个示例显示了 `age_check` 脚本（第 342 页）除了算术扩展外还包含了逻辑评估：

```
$ age2
How old are you?
You are too young or too old to play.
```

`if` 语句的测试语句会评估两个由布尔与（AND）连接的逻辑比较，如果它们都为真则返回 0（真），否则返回 1（假）。

### 逻辑评估（条件表达式）

条件表达式的语法为

```
[[ expression ]]
```

`expression` 是一个布尔（逻辑）表达式。在表达式内部，你必须在变量名前加上美元符号 (`$`)。执行此内置命令的结果（如 `test` 命令）是一个返回状态。括号内的条件几乎是 `test`（第 397 页）接受的条件的子集。当 `test` 内置命令使用 `-a` 作为布尔运算符时，`[[ expression ]]` 使用 `&&`。同样，当 `test` 使用 `-o` 作为布或运算符时，`[[ expression ]]` 使用 `||`。

### 第 11 章 编程 Bourne Again Shell

你可以用以下条件表达式替换 `age2` 脚本（上文）中测试年龄的行。你必须用空格或命令终止符将 `[[` 和 `]]` 标记括起来，并在变量前加上美元符号：

```
if [[ 30 -lt $age && $age < 60 ]]; then
```

你也可以使用 `test` 的关系运算符 `-gt`, `-ge`, `-lt`, `-le`, `-eq` 和 `-ne`：

```
if [[ 30 -lt $age && $age < 60 ]]; then
```

#### 字符串比较

`test` 内置命令测试字符串是否相等或不相等。`==` 为字符串添加比较测试。`>` 和 `<` 运算符测试字符串的顺序（例如，"aa" < "bbb"）。`=~` 运算符测试的是模式匹配，而不仅仅是相等：`[[ string =~ pattern ]]` 在字符串匹配模式时则为真，而 `[[ pattern =~ string ]]` 则为假。例如，`[[ artist =~ a ]]` 为真，`[[ a =~ artist ]]` 为假。模式必须出现在等号的右侧。

```
$ [[ artist =~ a ]]
$ echo $?
0
$ [[ a =~ artist ]]
$ echo $?
1
```

下一个示例使用由复合条件开始的命令列表。该条件测试目录 `bin` 和文件 `src/myscript.bash` 是否存在。如果存在，`cp` 将 `src/myscript.bash` 复制到 `bin/myscript`。如果复制成功，`chmod` 使 `myscript` 可执行。如果这些步骤中的任何一个失败，`echo` 显示消息。

```
$ [[ -d bin && -f src/myscript.bash ]] && cp src/myscript.bash bin/myscript && chmod +x bin/myscript || echo "Cannot make executable version of myscript"
```
