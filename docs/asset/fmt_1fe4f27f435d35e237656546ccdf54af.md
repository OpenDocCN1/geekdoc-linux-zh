## 引言

恶意软件威胁格局不断扩大。自第一个病毒出现的 30 年来，此类事件（以及相关的财务损失）的数量持续呈指数级增长，每月多达百万次。这些数字支持了一种宿命论的观点：系统只有两种：已经被攻击的系统和将来会被攻击的系统。

## 恶意软件威胁

恶意软件是旨在获取访问、收集信息、进行非法操作或干扰正常运行的软件。该词本身是“恶意的”和“软件”的组合词，指向了它的目标。恶意软件有多种形式，尽管大多数都有经济目标。

### 日益增长的风险

可以说，许多 Linux 用户相信他们的系统“在设计上是安全的”、防恶意软件的，甚至认为针对他们的服务器没有现实威胁。获取有关具体安全事件的实际数字很难，因为许多事件并未披露或公开，但有一些通用统计数据可以揭示这一日益增长的问题。例如，参考 Verizon 的《数据泄露调查报告》。

这些信念中至少部分是正确的；例如，默认的 Linux 系统可能比其他系统更安全。此外，Linux 环境的攻击少于常见的报道的 Windows 攻击。无论如何，假设 Linux 服务器攻击不会发生或没有成功的机会不仅是错误的，也是危险的。

恶意软件作者很大程度上针对 Windows 机器（主要原因仅仅是因为桌面端）由于其庞大的用户基数，Windows 提供了更大的攻击机会。但在服务器上，情况就不同了。我们越来越多地看到针对 Linux 的新型且有针对性的恶意软件攻击，例如 2014 年感染了 10,000 台 Linux 系统的 Windigo 攻击，以及最近由 ESET 发现并运行了至少五年的“Mumblehard”恶意软件。在这两个例子中，恶意软件都是有针对性的，使其能够在避开侦查的情况下运行并避免被发现。

因此，在考虑服务器领域时，Linux 的普及成为了潜在攻击者的巨大吸引力。由于运行在 Linux 下的 Web 服务器和数据库服务器数量巨大（某些统计数据显示，连接到 Web 的服务器中约 70% 运行 Linux），一个成功针对 Apache、MySQL 或类似服务器软件的恶意软件编写者将立即拥有一个军事术语中所谓的“目标丰富”的环境。鉴于许多企业将关键公司信息和系统运行在 Linux 服务器上，这种威胁变得更加严重；这种攻击向量可以帮助针对特定公司进行计划好的隐蔽入侵。

攻击者通常不会使用恶意软件采取“散弹枪”方法尝试尽可能捕获机器（即使价值很低），而是更倾向于像狙击手一样瞄准更大、更有吸引力的目标。这就像“萨顿法则”（Sutton's Law）：据传，银行劫匪威利·萨顿（Willie Sutton）曾被问及为什么要抢银行，他简单地回答道：“因为钱在那儿。”估计大约三分之二的恶意攻击仅使用一次，并专门针对特定的公司或服务器。（而且，当然，抢银行可能比在街上抢劫 100 个随机路人要好！）因此，如果你的服务器对普通的、平庸的攻击已经有了合理的保护，那么考虑针对你特定公司的直接的、定制的恶意软件尝试无疑是值得的。

### 零日威胁

最后，“零日”攻击应该引起最担心。这些攻击基于未被发现且尚未修复的软件漏洞。人们对此一无所知，不知道它们的入侵方法、影响或消除它们的最佳方式。

零日威胁尽管如此，但如果未被检测到且未修复，它们可能会被利用很长时间。例如，影响 SSL 的 Heartbleed 漏洞源于 2011 年，但直到几年后才显现。另一个例子是，2008 年，微软确认了一个追溯到 2001 年的 Internet Explorer 特定漏洞。停止支持且没有可用补丁的软件也是零日攻击的候选对象。

### 入口

在“旧时代”，基于 Internet + DMZ + 内部网的三位一体架构对于安全目的已经足够了。然而，当前的通信格局拥有 VPN、居家办公用户、Wi-Fi 连接、信任伙伴、开放端口、云服务器、面向服务的架构（SOAs）、远程管理、端口跳转等，无疑变得更加复杂且充满漏洞。

密码和防火墙在以前可能是足够的，但这些可能的入口增加了保护服务器免受恶意软件侵害的难度。事实上，你应该假设你的网络边界并不是坚不可摧的，而是脆弱且渗透的，并为最坏的情况做好计划。

当然，这一切并不意味着你应该忘记诸如 SSH（安全外壳）连接或使用隧道进行远程访问。安全基于在潜在入侵者的路径上设置尽可能多的障碍（深度防御”）。

## 传统防御

系统管理员对可能的攻击非常精通——至少他们比普通用户精得多——再加上 Linux 系统往往被认为“从一开始”更安全的事实，这意味着服务器通常对干扰性或常见的恶意软件具有某种程度的保护。防御往往在事后才建立，在发现入侵之前，更高级的防御不会被计划或实施。管理防御取决于许多独立的程序、流程和工具，这并不是一项简单的工作。无论达到什么程度的自动化，都会花费大量时间。最后，如果在开始没有妥善考虑，很难跟上新威胁并确保所有安全方法都能正常运行。

### 攻击面

直观地说，你可以将任何系统的攻击面定义为恶意软件入侵系统的所有方式（攻击向量）的总和。表面越大，你的系统证明就越不安全。

#### 表 1. 攻击面

| 维度 | 风险 |
|---|---|
| 人员 | 社会工程攻击可能会欺骗合法用户自行渗透系统，在无意中直接向你的服务器注入恶意软件。即使是一封由不知情的用户打开的也可能成为攻击向量。 |
| 硬件 | 工作站本身——尽管对这些设备的攻击通常需要内部帮助或物理上的接近。（搜索 TEMPE 代号并了解其间谍手段。） |
| 网络 | 外部脸服务器上的开放端口和可用接口，或在可见端口上的代码，为你的系统提供了入口。特别是，基于隧道或点对点连接的技术是一种威胁，因为它们开启了通往系统的连接。根据你的架构，你可能需要将云服务器和系统加入攻击面。 |
| 软件 | 所有运行的代码都可能包含可利用的漏洞。 |

### 基于签名的检测

当在“野外”检测到疑软件时，杀毒公司的研究人员会对其进行分析。在确认其确实是恶意软件后，会从代码中提取“签名”（一段可识别的字节序列）并将其添加到病毒数据库中，以确保未来能够被识别。新的或自定义的恶意软件攻击或零日漏洞将无法被杀毒软件检测，因为所需的签名尚。此外，根据 FireEye 的研究，超过 70% 的恶意软件具有高度针对性，且仅使用一次。

基于签名的方法和网络防御也存在其他问题。恶意软件编写者可以对其代码进行加密，因为恶意软件随后会被解密并执行，但识别会变得困难。实际上，同种恶意软件可能存在无数版本，每个版本都使用不同的密钥编码，使得检测变得更加困难。

杀毒软件在 Windows 机器非常常见，但 Linux 用户倾向于直接置之不顾，认为那种恶意软件与他们无关。考虑到公司开发 Linux 机器签名的速度通常较慢，这种想法是有道理的。但，这是一个短视的观点。

### 现代防御原则

随着网络攻击的演变以及针对 Linux 系统的攻击日益普遍，针对恶意软件的防御必须从被动过程变为主动过程。公司通常的循环是预防→检测→解决方案，现代威胁的演变诱使一些人认为预防几乎是不可能的，而且“检测是新的预防”。这种观点忽略了重点，因为对你的系统和现代防御方法进行更深层次的观察可以提供高水平的“第一线”阻止能力，而增加持续、时的监控可以增加额外的能力，以应对大量的、通常具有针对性的恶意软件，以及多样化的多种攻击向量（用户、移动设备、云端等）。让我们来看看一些现代安全规划中强制执行的原则。

零信任：网络安全的经典模型就像中世纪城堡：有一道巨大的守严的大墙（可能有护城河），据认为没有人能通过，内部是一个开放空间，即使在围攻和战争期间，生活也可以以正常方式进行。然而，对于现代计算机中心来说，这种类比失效了，因为你无法确保没有人进入内部，那里所有的公司内部资源可供掠夺。
