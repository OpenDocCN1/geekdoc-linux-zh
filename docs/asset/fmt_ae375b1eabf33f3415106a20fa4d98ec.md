# TCP/IP 协议架构

TCP/IP 通信套件的设计考虑了模块化。这意味着，设计者并没有开发一个将所有通信集成在单一代码中的解决方案，而是明智地选择将拼图分解为各个组成部分并单独开发它们，同时意识到这些部分之间的相互依赖关系。因此，TCP/IP 演变成一套协议，为通信拼图的不同部分指定了独立的依赖关系。这种解决问题的方法通常被称为分层方法。因此，下文将 TCP/IP 视为一个分层的通信套件。

图 20.1 显示了 TCP/IP 通信架构的四层模型。如图所示，该模型基于对通信的理解，涉及四个过程：应用代表进程、主机代表进程、网络代表进程和媒体交付代表进程。每组进程在应用程序与其对端进行数据交换时，都负责处理这些实体的需求。这些进程组被分为四层：应用层、主机-主机层（也称为传输层）、网络层和网络访问层。这些层中的每一层都可以在单独但独立的软件代码进程中实现。

图 20.1。
TCP/IP 分层通信架构。

应用层代表进程负责协调运行通信应用程序的平台之间数据语法的差异。例如，与 IBM 主机通信可能需要在 EBCDIC 和 ASCII 字符集之间进行翻译。在执行翻译时，应用层（例如，应用代表进程）不需要（也不应该拥有）任何底层的协议（例如，在主机-主机层）来处理主机之间翻译后的字符传输。应用层支持的协议示例包括 FTP、TELNET、NFS 和 DNS。

## TCP/IP 数据封装

当数据向下层传输时，处理该层的协议会在将数据传递给下的一层之前，会添加其自身的控制信息。这种控制信息被称为协议首部（简单来说，因为它被附加在要传输的数据之前），其目的是协助数据的交付。每一层对于上层在用户数据中添加的头部信息都是不可感知的。这种在用户数据中添加头部的过程被称为数据封装。

通过使用头部，TCP/IP 协议能够跨网络与其对应的对端进行对等通信（peer talk）。如图 20.4 所示，当数据到达目的地时，每一层在将数据传递给上层之前都会剥离其头部信息。随后，每个头部信息都会被解析并用于用户数据的处理中。

# 图 20.4.

TCP/IP 下的数据封装。除了网络访问层外，所有头部都保持不变。网络访问层的头部是底层物理网络的一个函数。

以下是每个头部可能包含的内容的示例：

- 在传输层，首部包含目的端口号和源端口号。这些被视为进程标识符，有助于在指定的进程之间交换封装的数据，而不会将这些进程与在同一主机上同时运行的其他进程混淆。该层的数据和头部形成一个被称为段（segment）的数据单元。
- 在网络层，首部还包含标识通信端点系统的 IP 地址。该层的数据和首部信息被称为 IP 数据包（IP packet）。
- 在网络访问层，首部包括物理网络上源设备和目的设备的介质访问控制（MAC）地址。在该层形成的数据单元被称为帧（data frame）。

## 网络访问层

网络访问层负责将数据交付到连接到物理网络的设备。它是唯一一个感知底层网络细节的层。换句话说，网络访问层感知诸如介质类型（双绞线、光纤、同轴电等）、数据的电子编码和介质访问方法。由于 TCP/IP 规范了同一主机内跨协议边界的数据交换，你可以看到如何实现一种新的网络访问技术而不影响协议层次的其余部分。以太网（Ethernet）和令牌环（Token-ring）是网络访问层依赖以接收或向网络交付数据的技术示例。

网络访问层的实现包含了网络接口卡（即通信硬件），它完成了所有操作（见图 20.5）。在该层级实现的协议的一个示例是地址解析协议（ARP，在“地址解析协议”章节中讨论），它负责将 IP 映射到相应的硬件（MAC）地址。值得注意的是，网络接口卡（NIC）从网络接收的所有数据并非都会向上层层级传递。某些数据可能必须通过 MAC 驱动程序传递给本章共存的相邻协议（例如，反向地址解析协议，在后面的章节中讨论）。这种功能通常被称为数据多路用（data multiplexing）。

## 网络层

该层级实现了两种协议：网控制消息报协议（ICMP, RFC792）和网际协议（RFC791）。网际协议（IP）的目的是处理跨互联网络（通常称为互联网）的数据路由，而 ICMP 的目的是处理路由错误检测和恢复。IP 是 TCP/IP 协议族的基石。所有 TCP/IP 协议都通过携带 IP 数据报与其网络上的对端进行通信。图 20.6 显示了 IP 数据报的结构（包括 IP 首部和从上层传递的数据）。IP 的头部字段将在后续对其功能的讨论中给出。但首先，先看看它的主要特征。

# 图 20.6.

IP 数据报结构。阴影部分是 IP 的首部。IP 不感知上层协议传递的数据字段的内容。

IP 的主要特征是一个无连接协议。这意味着 IP 在向对端发送数据之前并不会尝试与其建立连接。面向连接的协议在对端系统中使用某种握手；握手的目的有两点：它在发送数据之前验证对端准备接收数据的就绪状态；并且在握手期间，连接的两端对管理数据交换的某些参数达成共识。协商参数的示例是可封装在连接中的数据最大尺寸。

除了无连接外，IP 还提供一种不可靠的服务。不可靠性源于 IP 不提供错误检测和恢复。IP 只关心将数据交付到其指定的目的地。数据报在运输过程中发生了什么，是 IP 服务（更高层协议）设计上考虑的问题。这非常像邮政服务，它在尽力的基础上递送邮件，而不关心所运输或交付物品的质量。

## IP 的功能

IP 功能包括：

- 数据封装和头部格式化
- 跨互联网络的数据路由
- 将数据传递给其他协议
- 分片和重组

### 数据封装

数据封装涉及接受来自传输层的数据，并在其添加 IP 头部控制信息。在图 20.6 中，IP 首部是 32 位字长度的；其 IHL 字段是可选的。第一个字段指示 IP 使用的版本，当前为 4。第三个字段是服务类型（TOS）。TOS 可以设置以指定应用程序的服务。IP 支持的服务类别示例包括：最小延迟，总长度减去 IHL 字段指示 IP 的长度。标识字段和分片字段将在下面的“分片与重组”部分进行讨论。时间（TTL）字段由 IP 初始化为数据报在到达目的地之前可以经过的路由器数量。假设 TTL 设置为 32，每经过一个路由器就会减 1。一旦 TTL 变为 0，数据报会被下一个路由器丢弃。检测这种异常。基本原理是利用 TTL 防止数据出现无限循环。协议字段将在后讨论。

尽管 IP 是一个不可靠的协议（因为它不执行错误检测和恢复），但它仍然关心头部的完整性。通过校验和的帮助，IP 验证数据的完整性。

源和目的地址为 32 位。IP 地址类和结构将详细介绍。**数据路由**也许是网络层执行最重要的功能。IP 区分了主机和网关。TCP/IP 中的网关（见下文注释）实际上连接两个或多个网络的路由器。图 20.7 显示了网关在网络之间转发数据报。

主机是运行用户程序的系统。默认情况下，路由限于将数据报交付到下一个系统，如果主机位于同一网络上。如果不是，IP 将数据报交付到默认网关（即路由器）。在检查目的 IP 地址后，网关 A 意识到该地址属于 B 所连接的网络。因此，网关 A 将数据报转发给网关 B，以便后续处理并交付到主机 Y。

## 分片与重组

如图 20.6 所示，IP 头部中的总长度字段宽度为 16 位，这意味着允许的最大数据报大小为 64 千字节（65535 字节）。然而，某些底层网络（介质访问技术）在单帧内无法容过多数据。例如，以太网帧不能超过 1514 字节。在这种情况下，IP 采用称为的数据分片技术。当超过帧容量的数据报被传递给 IP 协议且网络层未进行此类处理时，就会发生分片。

尽管所有数据报通常通过相同的路由传输，但可能有少数数据报经过备用路由。这可能是由于早期分片形成的路径出现拥塞，或者是链路故障导致的。无论情况如何，遵循不同路由的分片可能会以不同于发送顺序的顺序到达目的地。为了恢复此类事件，IP 利用其头部中的分片偏移（fragmentation offset）字段。分片偏移字段包含序列信息，远程 IP 用此对来自网络的数据报碎片进行重新排序，并检测丢失的数据包。除非所有相关的分片都已妥善接收并重新排序，否则数据不会传递给协议字段中描述的协议。分片恢复和排序的过程被称为重组。

## 互联网控制消息协议

互联网控制消息协议（ICMP）是 IP 协议不可或缺的一部分。它是在主机之间携带消息的“信使”。ICMP 消息携带控制、信息和错误恢复类数据。以下是某些消息的描述：

- 源端阻塞（Source quench）：这是一种流量控制消息，接收主机发送给源端，请求其停止发送数据。这通常发生在接收主机的通信缓冲区即将充满时。
- 路由重定向（Route redirect）：这是一种网关发送给寻求其路由服务的类型信息消息。网关发送此消息是为了通知发送主机网络上的另一个网关，它认为该网关离目的地更近。
- 主机不可（Host unreachable）：当系统在交付过程中遇到问题时，网关（例如链路故障或拥塞）会发送此类错误消息。
- 回显请求/回显响应（Echo request/reply）：系统通常使用 ping 命令来测试可达性。在调用时，如果远程系统正常，它将响应 ICMP 回显响应，如下：

```
# ping 123.5.16

123.5.16 is alive
```
`ping` 触发了发送到主机的 ICMP 请求，如果接收后将响应回显响应，否则，主机不可。

## IP 地址结构

在 TCP/IP 中，每个设备的 IP 地址为 32 位（或四个字节），包括节点和地址字段，并占据 IP 头部中的源地址和目的地址字段。然而，地址中网络部分的字节数取决于 IP 地址所属的类别，定义了三类：A、B 和 C。还有一个 D 类，其重要性低于其他类别，但会被频繁提及。

A 类：第一个比特位固定为 0，第一个字节称为网络标识，用于标识网络。剩余的三个字节用于标识网络上的主机，组成主机标识。可以计算出

最多有 127 个 A 类网络，每个网络都能容纳数百万个主机。

B 类地址：前两个字节固定为 10，第一个字节和第二个字节用于识别网络，后两个字节用于识别主机。B 类网络上可以有 65,535 个主机，能够容纳数千个主机。

C 类地址：前三个位固定为 110，第一个字节、第二个字节和第三个字节用于识别网络，最后一个字节用于识别主机。C 类网络是所有类别中最小的，因为每个网络最多可以容纳 254 个主机（而不是 256 个，因为 0xF0 和 0xFF 被预留用于其他用途）。通过保留三个字节识别网络，可以定义数百万个 C 类网络。

D 类：前四位固定为 1110。D 类地址是多播地址，用于识别网络上可能正在运行分布式应用程序的一组计算机。因此，D 类不描述一个网络。
