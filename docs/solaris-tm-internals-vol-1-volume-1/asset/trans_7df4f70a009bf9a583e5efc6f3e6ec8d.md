

内核实现了一种信号机制，将`SIGWAITING`与针对`SIGWAITING`的信号处理器配合使用，以增加进程可用的LWP池。

借助调度器激活，内核与用户线程库之间建立了一条通信路径。如果已为进程建立了激活，则LWP池可能随时可用，在这种情况下，`t_handoff`指针将非NULL。如果是这种情况，将调用内核交接函数，并最终进入内核`resume()`代码，将`t_handoff`引用的内核线程上下文切换到处理器上。

如果当前线程*不是*中断线程，且*不*需要交接，则`swtch()`调用`disp()`函数，该代码段负责查找应运行的最高优先级线程，将该线程状态设置为运行中（`TS_ONPROC`），并安排将其切换到处理器上。在高层，`disp()`函数从内核抢占队列开始搜索分派队列，查找最佳优先级的的内核线程，然后搜索当前处理器（即执行`disp()`代码的处理器）的队列。如果这些搜索均未找到，则代码会搜索多处理器系统上其他处理器的分派队列，寻找可运行的内核线程。如果分派队列上未找到任何线程，处理器将执行其空闲线程，该线程会执行一个紧凑循环，在每次循环中测试是否有可运行线程，并在线程数大于0时进入`swtch()`。

查找最高优先级线程的过程从内核抢占队列开始，该队列由当前处理器通过其`cpu_part`结构引用，其中抢占队列链接到`cp_kp_queue`。在这种情况下，在具有多个处理器分区（用户处理器集——请回顾每个处理器集有一个内核抢占队列）的系统上，首先搜索执行处理器所属处理器分区的抢占队列。`cp_kp_queue`的搜索过程用以下伪代码表示。

```
kpq = 指向内核抢占队列的指针
 dq = 指向处理器分派队列的指针
 while (优先级 > kpq->disp_maxpri && 优先级 > 0) AND
       (优先级 >= dq->disp_maxpri) AND
       (当前CPU未离线) AND
       (线程指针 = disp_getbest(kpq) != NULL)
           if (disp_rqty(线程指针, kpq) != NULL)
               return(线程指针)
```

上述队列搜索循环根据队列的`disp_maxpri`验证优先级值（`disp_maxpri`反映队列上最高优先级线程），确保当前处理器未离线，并调用分派器`disp_getbest()`代码从内核抢占队列中获取最佳优先级线程。`disp_getbest()`找到最高优先级的未绑定线程，调用`dispdeq()`将该线程从分派队列中移除，并将线程指针返回给`disp()`。如果未找到任何内容，则返回NULL值。

```text
disp_getbest()
    dpq = 分派队列指针（此示例中为cp_kp_queue）
    priority = dpq->disp_max_unbound_pri
    if (priority == -1)
        return(NULL)
    queue = dpq->disp_q[pri];
    thread_p = queue->dq_first;
    循环遍历队列上的线程链表，跳过绑定线程
    if (无未绑定线程)
        return NULL
    else
        thread_pointer = 找到的线程
        dispdeq(thread_pointer)
        设置线程的t_disp_queue、处理器的cpu_dispthread、线程状态为ONPROC
        return (thread_pointer)
```

如果在`disp_getbest()`中找到未绑定线程，则通过`dispdeq()`将该线程出队，线程的`t_disp_queue`指针被设置为引用处理器的cpu结构中的`cpu_disp_queue`指针，处理器的`cpu_dispthread`指针被设置为所选线程指针，线程状态被设置为ONPROC。

`dispdeq()`处理分派队列数据结构的更新，并从队列中移除所选线程。它会递减`disp_nrunnable`（所有队列的总计数）和`dq_sruncnt`（维护同一优先级可运行线程的计数）（参见第374页的图9.5）。如果每优先级队列计数`dq_sruncnt`为0，则更新队列位图以反映空队列。`disp_qacmap`位图使用置位位来反映每优先级队列上是否存在可运行线程；因此，与清零队列对应的位会被清除。`disp_maxunpri`和`disp_maxunbound_pri`字段也会更新，以反映队列上新的最高优先级线程（如果不同于刚被移除的线程）。

一旦完成线程选择并将线程出队，代码返回`disp()`，它调用`disp_ratify()`以确保所选线程确实是下一个运行的最佳候选。分派器例程内部使用的细粒度锁允许多个处理器同时对队列和队列状态进行更改。因此，实现了*选择-确认*（select-and-ratify）算法。算法选择阶段现已完成，进入`disp_ratify()`以完成确认阶段。确认代码只是将所选线程的优先级与处理器和内核抢占队列的`disp_maxunpri`值进行比较。如果所选线程优先级大于maxunpri，则确认选择并执行上下文切换。否则，重新进入代码循环以找到最佳可运行线程。更准确地说，如果在执行`disp_ratify()`时队列上出现更高优先级线程，则通过调用`setfrontdq()`将所选线程放回分派队列，且`disp_ratify()`向`disp()`返回NULL。

如果在内核抢占队列上未找到线程，则测试每处理器队列`disp_maxrunpri`。值为−1表示队列上没有任何内容。在这种情况下，代码搜索系统上其他处理器的队列，从`disp_getwork()`代码开始，该代码找到具有最高优先级线程的处理器。然后，代码使用前面描述的`disp_getbest()`和`disp_ratify()`函数。

如果当前处理器的`disp_maxrunpri`指示存在可运行线程，则从最高优先级队列移除第一个线程，更新队列数据（`disp_nrunnable`、`dq_sruncnt`、`disp_qactmap`、`disp_max_unbound_pri`和`disp_maxrunpri`），确认选择，然后`disp()`将线程指针返回给`swtch()`。

如果在任何分派队列上均未找到工作，则通过将线程指针设置为`cpu_idle_thread`（从处理器的`cpu`结构引用）来选择处理器的空闲线程。指向空闲线程的指针返回给`swtch()`代码。

返回`swtch()`后，对于所选线程（或空闲线程）的线程指针，调用内核`resume()`代码来处理处理器上的线程切换。`resume()`用汇编语言实现，因为上下文切换过程需要与处理器硬件进行底层接触，原因有两个：保存被切换线程的硬件上下文；设置硬件寄存器和其他上下文信息，以便新线程可以开始执行。

## 9.3 内核睡眠/唤醒机制

内核线程的典型生命周期不仅包括在处理器上的执行时间，还包括等待所需资源变为可用的等待时间。一个明显的例子是磁盘读写，此时内核线程将发出`read(2)`或`write(2)`系统调用，然后睡眠，以便在内核处理I/O时另一个线程可以使用处理器。一旦I/O完成，内核将唤醒该线程，使其继续工作。

可运行并等待处理器的内核线程位于分派队列上。必须阻塞、等待事件或资源的内核线程被放置在睡眠队列上。当内核线程需要睡眠、等待资源（例如互斥锁、读写锁等）的可用性或等待内核的某些服务（例如系统调用）时，该线程被放置在睡眠队列上。内核中实现的一些睡眠队列略有不同，尽管它们都使用相同的底层睡眠队列结构。转折门（Turnstiles）使用睡眠队列实现，专门用于优先级继承、互斥锁和读写锁上下文中的睡眠/唤醒支持。因互斥锁或读写锁以外的原因而睡眠的内核线程被放置在系统的睡眠
