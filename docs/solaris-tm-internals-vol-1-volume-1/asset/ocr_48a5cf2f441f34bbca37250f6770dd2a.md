+   - **exec_lock** — A pointer to a kernel read/write lock, to synchronize access to the exec switch array.

The object file exec code is implemented as dynamically loadable kernel modules, found in the `/kernel/exec` directory (`aoutexec`, `elfexec`, `intpexec`) and `/usr/kernel/exec` (`javaexec`). The elf and intp modules will load through the normal boot process, since these two modules are used minimally by the kernel startup processes and startup shell scripts. The a.out and java modules will load automatically when needed as a result of exec’ing a SunOS 4.X binary or a Java program. When each module loads into RAM (kernel address space in memory), the `mod_install()` support code loads the exec structure information into the `execsw[]` array.

All variants of the exec(2) system call resolve in the kernel to a common routine, `exec_common()`, where some initial processing is done. The path name for the executable file is retrieved, `exitlwps()` is called to force all but the calling LWP to exit, any POSIX4 interval timers in the process are cleared (`p_itimer` field in the proc structure), and the `sysexec` counter in the `cpu_sysinfo` structure is incremented (counts exec system calls, readable with `sar(1M)`).
