## 11.5.1 映射选项

某些标志允许向mmap传递不同的选项，以控制文件映射到进程地址空间的方式（参见表11-7）。这些选项通过flags参数传入。

**表11-7. _来自<sys/mman.h>的Solaris 7 mmap标志_**

| 类型 | 描述 |
| --- | --- |
| `MAP_FIXED` | 在提供的地址处进行映射。 |
| `MAP_NORESERVE` | 不为此映射保留交换空间。 |
| `MAP_SHARED` | 更改反映在所有映射中。 |
| `MAP_PRIVATE` | 更改不反映；会创建页面的副本，因此更改仅限本地。 |

`MAP_FIXED`选项要求文件范围精确映射到由_addr_提供的地址。如果未设置`MAP_FIXED`，系统会使用_addr_推导出一个用于映射文件的地址。所选地址将是地址空间中系统认为适合将_len_字节的文件映射到文件中的区域。如果未设置`MAP_FIXED`且_addr_为0，则系统会选择映射文件范围的地址。

如果指定了MAP_NORESERVE选项，则不会为映射保留交换空间。如果没有此标志，创建可写的MAP_PRIVATE映射将保留等于映射大小的交换空间。当写入MAP_NORESERVE段时，如果空间可用，写入成功并创建被写入页面的私有副本；如果空间不可用，写入失败并向写入进程发送SIGBUS或SIGSEGV信号。

### 11.5.1.1 将文件映射到两个或多个进程

当另一个进程对同一文件调用mmap且范围重叠时，文件可以被映射到多个进程中。系统通过将相同的内存页映射到每个地址空间来实现这一点。当发生这种映射时，内存将在进程之间共享，默认情况下，每个进程都能看到另一个进程所做的所有修改。此行为可以作为System V共享内存的替代内存共享方法。事实上，用于共享内存的POSIX进程间通信设施就构建在共享内存映射文件之上。可以向mmap传递MAP_SHARED和MAP_PRIVATE选项，以允许不同的共享语义，而不是默认的共享所有内容。

如果指定了MAP_SHARED，写引用将更改所有映射了该文件范围的进程所共享的内存。如果指定了MAP_PRIVATE，首次写引用会创建内存页的私有副本，此后，该进程将拥有该映射页的私有副本。

### 11.5.1.2 权限选项

内存地址范围以prot参数提供的权限创建在进程的地址空间中。这些权限控制进程是否可以读取、写入或执行映射内存范围内的内存。保护/权限选项如表11-8所示。

**表11-8 来自<sys/mman.h>的Solaris 7 mmap保护选项**

| 类型 | 描述 |
| --- | --- |
| `PROT_READ` | 数据可读。 |
| `PROT_WRITE` | 数据可写。 |
| `PROT_EXEC` | 数据可执行。 |
| `PROT_NONE` | 数据不可访问。 |

如果我们检查前面mmap示例中ksh的映射，可以看到ksh的第一部分被映射为只读/执行，第二部分被映射为读/写/执行。

```text
00010000   192K read/exec    /usr/bin/ksh
0004E000     8K read/write/exec    /usr/bin/ksh
```

如果进程试图写入0x010000和0x040000之间的内存范围，将向该进程发送SIGSEGV信号，通知其发生了分段违规。顺便说明，第一个段是进程的文本部分，始终是只读的，第二个映射是已初始化变量的数据部分，两者都在进程间共享。第二个段通过MAP_PRIVATE映射为读/写；因此，如果某个进程更新一个已初始化变量（例如i = 1），该变量不会在所有此类进程中改变。相反，写时复制操作会创建一个本地页，该页随后用于在该位置保存文件的页长度映射，且仅对该进程私有。

## 11.5.2 向内存系统提供建议

我们可以通过madvise系统调用，向内存系统提供关于映射范围内内存页的建议。madvise系统调用允许我们告诉内存系统：我们是否需要某个内存范围，或者我们将以顺序还是随机顺序访问内存。这些信息使内存系统和文件系统能够主动读入与该内存范围对应的文件部分。

```text
int madvise(caddr_t addr, size_t len, int advice);
```

头文件 *<sys/mman.h>*

该建议针对一个内存范围给出，并通过advice参数指定。参数可以是MADV_DONTNEED、MADV_WILLNEED、MADV_SEQUENTIAL或MADV_RANDOM之一。

### 11.5.2.1 MADV_DONTNEED标志

当我们将文件映射到进程的地址空间并通过访问内存位置来读取文件时，我们会为该范围分配物理内存，并用文件的相应范围填充内存。一旦我们不再需要该文件范围，可能再也不会用到它，这时我们可以让操作系统知道该内存范围不再需要。这个通知尤其重要，因为即使我们取消映射该内存段，内存也不会被释放。

MADV_DONTNEED标志允许我们释放给定范围的内存。以下示例展示了如何做到这一点。

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/sysmacros.h>
#include <sys/types.h>
#include <fcntl.h>
#include <sys/mman.h>

void
main(int argc, char ** argv)
{
        int fd;
        caddr_t addr;
        off_t size;
        off_t length;
        off_t offset;
        off_t chunk = 1<<30;

        if (argc != 2) {
                (void) fprintf(stderr, "Usage: mmap_dontneed filename\n");
                exit(1);
        }

        if ((fd = open(argv[1], O_RDONLY)) < 0) {
                perror("Open failed");
                exit(1);
        }

        size = lseek64(fd, (off_t)0, SEEK_END);

        /*
         * mmap a chunksize segment and issue madvise(DONTNEED)
         * against it.
         */
        for (offset = 0; offset < size; offset += chunk) {

                length = MIN(size - offset, chunk);

                if ((addr = mmap64((caddr_t)0, length, PROT_READ,
                    MAP_SHARED, fd, offset)) == NULL) {
                        perror("mmap failed");
                        exit(1);
                }

                (void) madvise(addr, length, MADV_DONTNEED);
                (void) munmap(addr, length);
        }
}
```
