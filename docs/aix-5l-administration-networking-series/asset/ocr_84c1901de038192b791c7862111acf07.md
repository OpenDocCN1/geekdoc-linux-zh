The user **jdoe** runs the `id` command through the `/tmp/ksh` shell. Because that shell is executable by all users ("other"), the command succeeds and prints **jdoe**'s UID and GID.

```
```bash
# su - jdoe
$ /tmp/ksh -c "id"
uid=210 (jdoe) gid=1 (staff)
```
```

The root user then changes the permissions on `/tmp/ksh` to be set-UID.

```
```bash
# exit
# chmod u+s /tmp/ksh
# ls -l /tmp/ksh
-r-rsr-x 1 root system 243374 Apr 20 15:10 /tmp/ksh
```
```

The user **jdoe** again executes the `id` command through the `/tmp/ksh` shell. Because the shell is now set-UID root, any user who uses that shell has the effective UID of root.

```
```bash
# su - jdoe
$ /tmp/ksh -c "id"
uid=210 (jdoe) gid=1 (staff) euid=0 (root)
```
```

This example demonstrates the inherent danger in set-UID and set-GID programs. Extreme caution should be used when setting these modes on programs. Be sure you remove the `/tmp/ksh` copy when you have finished with this example.

```
```bash
# rm /tmp/ksh
```
```

# ## Access Control Lists (ACLs)

In addition to the basic access permissions, AIX 5L provides a more fine-grained method, using access control lists, or ACLs. Three commands are used to display and manipulate access control lists:

| Command | Description |
| :---- | :---- |
| `aclget` | Prints the ACL set on the specified file |
| `acledit` | Edits the ACL in the editor specified by the EDITOR environment variable |
| `aclput` | Assigns the ACL to a file specified, reading from standard input or a separate file |

To determine whether a file has an ACL associated with it, you can either use `aclget` to display the information or use the `ls` command with the **-e** flag, which will display an additional field to the right of the base permissions. If the field contains a plus sign (+), then the file has an ACL set.
