# SRC components

Overall, SRC is provided by the srcmstr daemon. The srcmstr daemon is started at boot time by an entry in the /etc/inittab file.

```
srcmstr:23456789:repassw:/usr/sbin/srcmstr    # System resource controller
```

The srcmstr daemon identifies subsystem components from definition in ODM object classes /etc/objrepos/(SRCobjsysy_SRCNotify). Subsystems and subservet configuration information are managed through the use of the [mk.ch.rm]ssys and [mk.ch.rm]ssver commands. In most cases, the subsystems and subservers are predefined for each product at installation time, so you will rarely if ever have to work at this level.

Once a subsystem group, subsystem, or subservlet is configured into the ODM, it may be operated on using the following commands:

+   * **startsrc**    Start a subsystem
+   * **stopsrc**     Stop a subsystem
+   * **refresh**     Restart or refresh a subsystem
+   * **trace -a, trcon, troff, and trestop**    Turn on/off tracing of a subsystem
+   * **lsrsrc**      Display subsystem status

Subsystems may be started at boot time after srcmstr is loaded by invoking the startsrec command as part of a boot re script or directly from /etc/initab. Some SRC command examples include these:

+   * **# startsrec -g tcip**    Start the TCPIP subsystem group
+   * **# refresh -g nfs**        Refresh the NFS subsystem group
+   * **# stopsrc -s qdaem**      Stop the qdaemon subservlet

To display the status of all defined subsystems, use the lsrc command. Note that subservlet control may also be invoked using the smity subsys and smitty subservlet SMIIT FastPaths or through the Web-Based System Manager.

```
$ lsrsrc -a

Subsystem      Group    PID    Status
syslog          ras      3670   active
sendmail        mail     4144   active
portmap         portmap  3878   active
inetd           tcip     4388   active
xntpd           tcip     4644   active
snmpd           tcip     5160   active
dpid2           tcip     4904   active
hostmibd        tcip     5418   active
```
