These steps will take you through setting up password-less authentication from one machine to another. In this example, the local user is named chuck on a computer named host1. The remote user is also chuck on a computer named host2.

+   1. Log in to the local computer (in this example, I log in as chuck to host1).
+       **NOTE:** Only run step 2 once as local user on your local workstation. Do not run it again unless you lose your ssh keys. When configuring subsequent remote servers, skip right to step 3.
+       2. Type the following to generate the ssh key:
+           ```bash
+           $ ssh-keygen -t dsa
+           ```
+       3. Accept the defaults by pressing Enter at each request.
+       4. Type the following to copy the key to the remote server (replace chuck with the remote user name and host2 with the remote host name):
+           ```bash
+           $ cd ~/.ssh
+           $ scp id_dsa.pub chuck@host2:/tmp
+           chuck@host2's password: ********
+           ```
+       5. Type the following to add the ssh key to the remote-user's authorization keys (the code should be on one line, not wrapped):
+           ```bash
+           $ ssh chuck@host2 'cat /tmp/id_dsa.pub >> /home/chuck/.ssh/authorized_keys'
+           ```
+       **NOTE:** The previous two steps will ask for passwords. This is okay.
+       6. Type the following to remove the key from the temporary directory:
+           ```bash
+           $ ssh chuck@host2 rm /tmp/id_dsa.pub
+           ```
+       **NOTE:** The previous step should not ask for a password.

It is important to note that once you have this working, it will work regardless of how many times the IP address changes on your local computer. IP address has nothing to do with this form of authentication.

# Guarding Your Computer with PortSentry

While LogSentry gathers and sorts log messages that may represent attempts to break into your computer system, the PortSentry takes a more active approach to protecting your system from network intrusions. PortSentry can be installed and configured on a Fedora system to monitor selected TCP and UDP ports, and can then react to attempts to access these ports (presumably by people trying to break in) in ways that you choose.
