`do_mmap()` 的功能通过 `mmap()` 系统调用导出到用户空间。`mmap()` 系统调用定义为

```
void    * mmap2(void *start, size_t length, int prot, int flags, int fd, off_t pgoff)
```

这个系统调用被称为 `mmap2()`，因为它是 `mmap()` 的第二个变体。原始的 `mmap()` 以字节为单位作为最后一个参数传递偏移量；而当前的 `mmap2()` 以页为单位接收偏移量。这使得可以映射具有更大偏移量的更大文件。原始的 `mmap()` 按照 POSIX 规范，可从 C 库作为 `mmap()` 获得，但不再在内核本体中实现，而新版本则作为 `mmap2()` 可用。两个库调用都使用 `mmap2()` 系统调用，原始的 `mmap()` 将偏移量从字节转换为页。

## munmap() 和 do_munmap()：移除地址区间

`do_munmap()` 函数从指定的进程地址空间中移除一个地址区间。该函数在 `<linux/mm.h>` 中声明：

```
int do_munmap(struct mm_struct *mm, unsigned long start, size_t len)
```

第一个参数指定了从中移除起始于地址 `start`、长度为 `len` 字节的区间的地址空间。成功时，返回零。否则，返回一个负的错误代码。

`munmap()` 系统调用作为使进程能够从其地址空间移除地址区间的手段导出到用户空间；它是 `mmap()` 系统调用的互补部分：

```
int munmap(void *start, size_t length)
```

该系统调用在 `mm/mmap.c` 中定义，并作为 `do_munmap()` 的简单包装器：

```
asmlinkage long sys_munmap(unsigned long addr, size_t len)
{
	int ret;
	struct mm_struct *mm;

	mm = current->mm;
	down_write(&mm->mmap_sem);
	ret = do_munmap(mm, addr, len);
	up_write(&mm->mmap_sem);
	return ret;
}
```

## 页表

尽管应用程序操作映射到物理地址的虚拟内存，但处理器直接操作这些物理地址。因此，当应用程序访问虚拟内存地址时，首先必须将其转换为物理地址，然后处理器才能处理该请求。执行此查找是通过页表完成的。页表通过虚拟地址分块来工作。每个块用作表的索引。该表指向另一个表或相关的物理页。

在 Linux 中，页表由三个级别组成。多个级别使得即使是 64 位机器上的稀疏寻址空间成为可能。如果页表实现为单个静态数组，即使在 32 位架构上其大小也会非常庞大。即使在不支持硬件三级页表的架构上，Linux 也使用三级页表。（例如，某些硬件仅使用两级或在硬件中实现哈希。）使用三级是一种“最大公约数”——实现较简单的架构可以通过编译器优化根据需要简化内核页表。

顶层页表是页全局目录（PGD），由 `pgd_t` 类型的数组组成。在大多数架构中，`pgd_t` 类型是一个 `unsigned long`。PGD 中的条目指向二级目录 PMD 中的条目。二级页表是页中层目录（PMD），它是 `pmd_t` 类型的数组。PMD 中的条目指向 PTE 中的条目。最后一级仅称为页表，由 `pte_t` 类型的页表项组成。页表项指向物理页。

在大多数架构中，页表查找由硬件（至少在一定程度上）处理。在正常运行时，硬件可以处理使用页表的许多责任。然而，内核必须以硬件满意并能完成其工作的方式设置一切。图 15.1 图解了使用页表进行虚拟地址到物理地址查找的流程。

每个进程都有自己的页表（当然，线程共享它们）。内存描述符的 `pgd` 字段指向进程的页全局目录。操作和遍历页表需要 `page_table_lock`，它位于相关的内存描述符内部。

页表数据结构非常依赖架构，因此定义在 `<asm/page.h>` 中。

由于虚拟内存中几乎每次页访问都必须解析为其在物理内存中对应的地址，因此页表的性能至关重要。不幸的是，在内存中查找所有这些地址的速度有限。为了促进这一点，大多数处理器实现*转换旁路缓冲器*，或简称为 *TLB*，它作为虚拟到物理映射的硬件缓存。访问虚拟地址时，处理器首先检查映射是否缓存在 TLB 中。如果有命中，立即返回物理地址。否则，如果未命中，则查阅页表以获取对应的物理地址。

尽管如此，页表管理仍然是内核中关键且不断演变的一部分。2.6 版本中对该领域的更改包括从高端内存分配页表的部分。未来的可能性包括具有写时复制语义的共享页表。在该方案中，页表将在父进程和子进程之间通过 `fork()` 共享。当父进程或子进程尝试修改特定的页表项时，将创建副本，两个进程将不再共享该条目。共享页表将消除 `fork()` 时复制页表项的开销。

## 页缓存和页写回

Linux 内核实现了一个称为*页缓存*的磁盘缓存。该缓存的目标是通过将数据存储在物理内存中，从而最小化磁盘 I/O，这些数据原本需要磁盘访问。本章涉及页缓存以及页缓存中的更改传播回磁盘的过程，这称为*页写回*。

两个因素共同作用，使得磁盘缓存成为任何现代操作系统的关键组件。首先，磁盘访问比内存访问慢几个数量级——毫秒对比纳秒。从内存而非磁盘访问数据要快得多，而从处理器的 L1 或 L2 缓存访问数据则更快。其次，一次访问的数据很可能在不久的将来再次被访问。这一原则——对特定数据的访问在时间上倾向于聚集——被称为*时间局部性*，它确保如果数据在首次访问时被缓存，那么在不久的将来发生缓存命中（访问缓存中的数据）的概率很高。鉴于内存比磁盘快得多，结合一旦使用过很可能再次使用这一事实，磁盘的内存缓存是一个巨大的性能提升。

## 缓存方法

页缓存由 RAM 中的物理页组成，其内容对应于磁盘上的物理块。页缓存的大小是动态的；它可以增长以消耗任何空闲内存，也可以收缩以缓解内存压力。我们将被缓存的存储设备称为*后备存储器*，因为磁盘作为缓存数据的规范版本来源位于缓存之后。每当内核开始读操作——例如，当进程发出 `read(2)` 系统调用时——它首先检查所需数据是否在页缓存中。如果在，内核可以避免访问磁盘并直接从 RAM 读取数据。这被称为*缓存命中*。如果数据不在缓存中，称为*缓存未命中*，内核必须调度块 I/O 操作从磁盘读取数据。从磁盘读取数据后，内核将数据填充到页缓存中，以便任何后续读取都可以从缓存中发生。并非需要缓存整个文件；页
