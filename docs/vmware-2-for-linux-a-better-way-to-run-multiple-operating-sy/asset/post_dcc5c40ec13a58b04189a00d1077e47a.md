
8. Now, mount the host drive on the guest at the location you just created. The command is of the form

```
mount <server IP>:<exported directory> /mnt/nfsm
```

The server IP is the address of the host. If you are running both bridged and host-only networking, use the one appropriate to the address range you specified in /etc/exports on the host.

The exported directory must match one of the entries in /etc/exports exactly (in this case, /home/jcompton).

To mount the drive I configured earlier, the command is

```
mount 192.168.20.2:/home/jcompton /mnt/nfsm
```

The output of this command appears in Figure B.7.

> Especially if you are using host-only networking, you can substitute the machine's name for the IP address, but it is faster to use the IP address. If you've forgotten, run /sbin/ifconfig on the host.

9. The drive is now mounted! You can cd to the mount point and open, copy, edit, and delete files as you see fit. When you are done, umount /mnt/nfsm (or whatever mount point you created in Step 7) to release the host file system from the guest.

## Using NFS with a Windows Guest

The short answer is you can't use NFS with a Windows guest—at least, not very easily, and because Samba is a much better alternative for Windows file sharing, it's not worth the effort.

It's extremely difficult to find a free implementation of an NFS client for Windows, and those that you can find tend to rely on extra networking components above and beyond those you need to get NFS to work in a Linux-to-Linux environment. Even the commercial offerings have these added requirements. (You need an NIS or PCN-FSD server running on the host.)

Do yourself a tremendous favor and stick with Samba when dealing with Windows guests.

## Conclusion

You might grow beyond the bounds of FTP file sharing, and virtual drive mounting might not be as stable as you would like. Using Samba for Windows guest operating systems and NFS for Linux/FreeBSD guests, you have stable, unlimited access between the file system of your host and guest operating systems.

Both require some configuration work—NFS in particular—but once the initial grunt work is done, the payoff lasts as long as you use VMware.
