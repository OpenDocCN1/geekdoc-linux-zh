VMware emulates a dual-channel IDE controller, as found on most modern PCs. This IDE controller can see up to four devices, so you can attach up to four virtual disks or three virtual disks and one CD-ROM.

As an alternative to file-based disk images, VMware can support raw disks, which are entire drives or physical drive partitions that the virtual machine accesses directly. In the current version of VMware, raw disk access is more stable with IDE disks, although SCSI support is available.

Raw disks are discussed in Appendix A, "Advanced VMware Configuration."

## Removable Media (CD-ROMs, Zip Drives)

VMware supports any standard IDE or SCSI CD-ROM drive, including the ability to boot a virtual machine from CD-ROM. DVD, CD-R, and CD-RW drives are also supported, but as read-only CD-ROM drives. That means you cannot read DVDs within a virtual machine, nor can you write to CDs. VMware also has difficulty with multisession discs due to limitations in Linux's CD-ROM handling.

> Due to a quirk in VMware's design, if you want to boot from a SCSI CD-ROM drive, VMware has to masquerade the SCSI CD-ROM drive as an IDE device. I address how this is done in Chapter 5, "Running VMware for the First Time."

Any removable media device, such as an Iomega Zip or Imation SuperDisk drive, that runs under Linux can be used to store VMware virtual disks. Direct support for these devices in VMware is somewhat limited, however. ATAPI Zip drives cannot be used as removable media devices (although parallel port Zips can), and an Imation SuperDisk cannot be used as a removable media device or as a standard floppy drive. If your PC relies on a SuperDisk for floppy compatibility, you need to add a real floppy drive to use regular disks in VMware.

## Expansion Ports (Serial, Parallel, USB)

VMware guest operating systems can access standard parallel ports (COM1, COM2, and so on) straight through in most cases, meaning that any device attached to the port should be recognized and operate correctly inside a guest operating system.

Parallel-port support is a little more complicated. Old-style unidirectional parallel-port devices should always work. Newer, bidirectional parallel ports allow faster printing and let you use more powerful devices, such as image scanners and Zip drives.

Raw disk: A physical hard drive or hard drive partition that a virtual machine accesses directly, just as a regular PC does. Raw disks are more flexible than file disk images but are more difficult to configure and have certain limitations of their own.

ECP (Extended Control Protocol) parallel access, an extension of the bidirectional protocol, is partially supported, although only if properly enabled in your PC's BIOS. ECP will enable some devices, such as portable MP3 player cradles, to work in VMware.

VMware can only use bidirectional parallel ports if your host Linux OS has the parport_pc module loaded (enabled by the CONFIG_PARPORT_PC option during kernel configuration). If it is not loaded, or it is compiled directly into the kernel, bidirectional access does not work. VMware-approved Linux distributions should already have this module loaded.

VMware virtual machines, by default, configure themselves to support four serial ports and two parallel ports, even if you don't have nearly that many in your system. You can leave them alone or remove them from the hardware configuration at your discretion; it won't impact the performance of the virtual machine, so it's best to leave them alone unless you're sure you know what you're doing.

As you probably know already, USB support in Linux is spotty at best. As a result, USB ports are not supported in any VMware virtual machine.

## Printers and Scanners

Back in the days of dot matrix, you could plug a printer into practically any computer and be sure of getting at least some sort of intelligible output. But as printers have matured and become orders of magnitude more powerful, bright, and clear, accessing printers has become more complicated.

VMware can support many common inexpensive printers without any software support from the Linux operating system. However, VMware cannot access a printer unless it could work under Linux. Some printers have eliminated all vestiges of backward compatibility and rely entirely on special Windows programs to function. VMware does not support these "Winprinters," even in a Windows virtual machine.

The good news is that a tremendous range of printers are not "Winprinters," and as such are VMware compatible, but the bad news is that some of the most attractive printers on the market (such as color inkjet models selling below $100) are not, at least not yet.

Linux has very good PostScript printer support. You won't go wrong with a PostScript printer, although they can be expensive.
