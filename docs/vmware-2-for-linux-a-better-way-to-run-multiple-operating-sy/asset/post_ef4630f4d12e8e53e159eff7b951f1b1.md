
> Keep experimenting with mix-and-match combinations of these cursor options until you have the settings that best fit the way you use VMware and your host PC.

## Allow Copy and Paste

By default, VMware Tools allows you to share a clipboard between the host and your virtual machine, which, in theory, allows you to cut and paste seamlessly across applications regardless of operating system. Some applications do not read the clipboard in the expected manner, and text cut and paste generally works better than graphical cut and paste. Test the shared clipboard performance before you start making drastic changes to documents.

You might want to turn off the Allow copy and paste option if you have security concerns on the host computer and you don't want to encourage the flow of information across the boundary between the host OS and the virtual machine. Or you might simply want to keep the two clipboards separate because the projects you are working on in the host and the virtual machine are different and need access to their own, private clipboards.

## Time Synchronization

Time synchronization is an expert option that is only available if you run VMware Tools as the superuser. Don't worry about it unless you notice that the virtual machine's clock is consistently losing time. Normally, the virtual machine should do a perfectly adequate job of telling time.

When activated, the virtual machine compares its own clock against the host OS clock every second and "catches up" as needed. This problem is most likely to occur if you run multiple Windows virtual machines, but it could theoretically be a problem with a Linux guest as well.

> Because this feature turns on a frequent system check, it can impact the performance of your virtual machine. VMware recommends leaving it off unless you have a serious timekeeping problem in the guest.

## Managing Virtual Disks

Virtual disks grow as you add data, but they don't shrink as you delete files. After a while, you might have a very large virtual disk file that contains a relatively small amount of information. This is wasteful and inefficient.

VMware Tools can help you reclaim space on your hard drive. The process is not dissimilar to disk defragmentation, which sorts and re-orders the data on a disk, eliminating the "dead zones" where deleted material lives.

The VMware shrink process not only sorts the data, but also it reduces the size of the virtual disk file by cutting out unused space.

> Virtual disks can also be defragmented inside the virtual machine. This might give you a modest performance boost if the disk has become cluttered, but it does not shrink the physical size of the disk on your host hard drive.

## Preparing for Shrinking

For shrinking to work and be any real benefit, your host and virtual machine must meet certain requirements:

- The host Linux OS needs free disk space equal to the current size of the virtual disk you want to shrink. Ironic, isn't it? After all, you'll probably start thinking about shrinking your virtual disks when your Linux PC starts to run out of room. But unfortunately, the shrink process needs a buffer as big as the virtual disk it will optimize to work. Prevention is the best medicine, after all.

- The virtual machine cannot have any raw or plain disks connected to it when you start the shrink process. Trying to shrink a raw or plain disk would have undesirable results (because they don't work like virtual disks), so VMware decided that discretion was the better part of valor and does not let you access the Shrink command if you have raw or plain disks attached to your virtual machine. You can always temporarily remove them from the VMware configuration, boot up just to shrink the disk, and then re-attach them when the shrink process is complete.

## Shrinking Virtual Disks

Shrinking virtual disks is a two-stage process. The first stage takes place inside the virtual machine, when you select which drive you want to shrink and VMware Tools does some preparation work. Then, VMware itself takes over, temporarily freezing the virtual machine while the shrinking operation takes place.

Assuming your setup is in line with the guidelines listed earlier, you are ready to begin:

- 1. Run VMware Tools as root. This might not be strictly necessary if your login account on the virtual machine has wide-ranging write access to the virtual disk, but running as root cuts to the chase.
- 2. Click the Shrink tab, shown in Figure 10.19.
- 3. VMware automatically lists the disks it can shrink. On a typical VMware setup (with one virtual disk, one floppy, and one CD-ROM drive), the root mountpoint / appears in the supported list, and the floppy, CD-ROM, and possibly various other devices show up in the Unsupported Partitions tab.
- 4. Put a checkmark next to the supported drive you want to shrink. (If there is only one, it is selected by default.)
- 5. Click Prepare to shrink. VMware Tools works on the drive for a while—quite possibly a long while. The entire process can take the better part of an hour or more, depending on the size of the virtual drive and various system performance factors. The screen should resemble Figure 10.20.
- 6. VMware Tools asks whether you want to commit to shrinking the disk now. (Remember, it can take some time.) Answer Yes.
- 7. The virtual machine freezes while the VMware main application takes over the process (see Figure 10.21).
