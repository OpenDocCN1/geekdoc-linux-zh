
Let's say you want to have virtual machines for both Windows 98 and SuSE Linux 6.1, but you know you won't ever want to run them at the same time. You're also pretty sure you won't need to use them all that often and will probably spend most of your time in SuSE Linux at the command prompt, not in XWindows. You can get by having only 32MB to allocate to either Windows or SuSE Linux, so all you need is 96+32=128MB of system memory.

On the other hand, what if you're developing and prototyping a Windows 2000 Server-hosted e-commerce Web site with the help of VMware? You want to compare how a Windows 98 computer running Internet Explorer works on the site with how a Linux computer using Netscape sees the site. You can use your host OS as the Linux test bed, but you'll need to run virtual machines for both Windows 98 and Windows 2000 Server. Figure, at bare minimum, you'll want 128MB for Windows 2000 and 32MB for Windows 98, so 96+128+32=256MB!

## Drive Space: You're Providing for Two (or More)

Your CPU is primed and powerful enough to handle even the most demanding OS, and you have enough memory to run Windows 2000 Server twice over. But if you don't have space to install the guest operating system and some applications, you're not going anywhere.

VMware's default, and easiest to use, storage option uses virtual disks, or "disk images" as they are commonly known.

Virtual disks can be located in any Linux directory you have authority to access, although it is best to place them on a local disk, rather than somewhere across a network. In Figure 3.2, you can see the standard VMware disk configuration interface. VMware can create virtual disks up to 2GB in size, which is enough to install any guest operating system and at least a modest amount of data and programs.

Virtual disk: A virtual disk is a very large file in a Linux directory that acts as a hard drive in a virtual machine. It can be up to 2GB in size. Virtual disks are also called disk images or file disks in emulator parlance.

> Because a VMware virtual machine has both a dual-channel IDE controller that can see up to four hard drives and a SCSI controller that can see up to seven hard drives, it is possible to attach eleven 2GB virtual disks to a VMware session—provided, of course, that you have 22GB of space on your computer!

Actually, you don't need 22GB of disk space to get started. Virtual disks were designed by some clever people. Although their maximum size is 2GB (you can define them to be smaller if you want), virtual disk files don't consume all that space right away; they grow as data is added to the virtual drive, up to the maximum value you selected when you created the drive.

## Making Room

Two gigabytes is a pretty convenient number. It's considered the bare minimum for Windows 2000; it gives you plenty of breathing room in other Windows versions, Linux, and FreeBSD; and of course it's extremely luxurious for Windows 3.1 and DOS. Unless you're miserly by nature with disk space, it's a good idea to set aside at least a full 2GB virtual disk for each of your non-DOS virtual machines.

> Disk space required for basic installation ranges from just a couple of megabytes for a DOS installation, to about 160MB for a complete Windows 98 install, to nearly a gigabyte for Windows 2000 Server. Depending on the software you choose to install, Linux virtual machines can fall anywhere in between.

If you don't have that kind of space to go around, it's time to add another hard drive to your system. Most PCs have two IDE controllers, which can support two drives each. You already have at least one hard drive installed, and most likely have a CD-ROM drive attached as well, so that leaves two open spots.

If your IDE chains are full, but you have a very large PC case, you can add a low-cost spare IDE controller board to your PC (they practically give them away) and put in another drive.
