# Creating an Isolated Environment

VMware takes great pains to build an ironclad, “I can’t believe it’s not a PC” virtual machine. Here’s the best news first: It is extremely unlikely that even the worst crash in a VMware virtual machine will damage or even inconvenience your host Linux OS.

Aside from their communication with the VMware Virtual Platform layer, VMware sessions do not have any special privileges or access to your computer’s files or memory space. You predefine a hard memory limit that VMware’s guest OS cannot exceed, and you similarly lay down the law as to which system devices and disk storage units VMware can touch. Everything else is off-limits; it’s completely invisible and inaccessible.

Although Linux can temporarily reclaim memory allocated to a VMware virtual machine through paging and swapping, the resulting performance hit is extremely unpleasant. It will behoove you to think of any memory given to a virtual machine as off-limits to Linux applications.

Because VMware can form a virtual network between the emulation and your host OS, it is possible for network trojans to spread between the two. You should treat the virtual machine as just as real a security risk as any other computer. Enforce whatever antivirus and network security policies you might have, and if you don’t have any, now is a good time to make some.
