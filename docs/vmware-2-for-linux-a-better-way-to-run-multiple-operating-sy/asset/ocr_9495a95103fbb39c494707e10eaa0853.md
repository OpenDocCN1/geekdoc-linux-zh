Although Wine does represent some RAM savings over loading VMware, it still requires a fairly healthy portion of your system's memory. Running Paint requires 35MB of memory! (Most of that is the Wine emulation layer.) As the Wine matures and debugging code is removed, this heavy memory hit may come down slightly.

There are certainly oddities to the way Wine works. As you've gathered already, it is not production-quality software, and errors, debugging messages, and generally unpredictable behavior must be considered par for the course at this point.

Wine can choke on your Windows program in any number of ways, and you need to know how to recover control no matter what happens. In the simplest case, the program just doesn't do what you expect, but it doesn't crash. You might achieve success by trying to accomplish your task in a different way—use a button instead of a menu item, switch the order of your steps, or try a newer version of Wine. There's a certain black magic to tweaking Wine to run complicated programs properly.

Things really get interesting, though, when Wine or the Windows program crashes. In the simplest case, Wine prints the machine state to your terminal and leaves you in the Wine debugger, which appears as a new prompt inside the terminal you used to launch Wine. This is not a problem—simply type quit to exit.
