Remember, FTP allows you to upload as well as download files, so there is no real reason to have an FTP server available on both the host and the guest. My advice is to experiment with a few different FTP clients for both Linux and Windows, pick the one you like the best, and then run your FTP server on the other OS.

# Mounting a Virtual Disk in Linux

FTP and other file-sharing methods are convenient, but it would be a shame if you had to boot up VMware just to get a few files every now and then. The data is all locked up in that big virtual disk file but is maddeningly inaccessible.

Well, not quite. A handy little program called vmware-mount.pl lets you address a virtual disk as you would any standard Linux drive.

Do not attempt to mount a virtual disk while it is in use by a Windows virtual machine. The mounting program tries to prevent this situation, but it's best to be careful anyway. You should shut down, not suspend, a virtual machine before you mount its virtual disk directly in Linux.

Before you can mount the disks, you need to create a mountpoint in the /mnt directory. This is the location in the Linux file system where the virtual drive will appear to be attached. Type mkdir /mnt/vhd. You can create multiple mountpoints (vhd1, vhd2, and so on) if you suspect you might want to mount multiple virtual drives simultaneously.

vmware-mount.pl is ready to run. To mount a virtual drive, follow these steps:

+   1. Quit all sessions of VMware.
+   2. You need root access. Type su and enter the root password.
+   3. Use the vmware-mount.pl program to first display the partition table of the drive you want to mount. You need to know the location and name of your virtual hard drive first. A common name for a Windows virtual hard drive is ~/vmware/win98/win98.dsk, but check your VMware directories to get the exact filename.
+   4. Type vmware-mount.pl -p ~/vmware/win98/win98.dsk, substituting the final argument for the actual path of your Windows virtual disk. The output will resemble Figure 9.8.
