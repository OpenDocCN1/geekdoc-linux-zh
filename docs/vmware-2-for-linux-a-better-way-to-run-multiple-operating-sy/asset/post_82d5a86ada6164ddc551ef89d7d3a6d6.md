Although Wine does represent some RAM savings over loading VMware, it still requires a fairly healthy portion of your system's memory. Running Paint requires 35MB of memory! (Most of that is the Wine emulation layer.) As the Wine matures and debugging code is removed, this heavy memory hit may come down slightly.

There are certainly oddities to the way Wine works. As you've gathered already, it is not production-quality software, and errors, debugging messages, and generally unpredictable behavior must be considered par for the course at this point.

Wine can choke on your Windows program in any number of ways, and you need to know how to recover control no matter what happens. In the simplest case, the program just doesn't do what you expect, but it doesn't crash. You might achieve success by trying to accomplish your task in a different way—use a button instead of a menu item, switch the order of your steps, or try a newer version of Wine. There's a certain black magic to tweaking Wine to run complicated programs properly.

Things really get interesting, though, when Wine or the Windows program crashes. In the simplest case, Wine prints the machine state to your terminal and leaves you in the Wine debugger, which appears as a new prompt inside the terminal you used to launch Wine. This is not a problem—simply type quit to exit.

Other crashes are more difficult. What should you do if the Windows program maximizes itself, taking over the whole screen, and then freezes? Your window manager

## Chapter 16: Using Wine with VMware

might not be able to save you, since Wine can act as its own window manager. (That is, closing, minimizing, or switching windows may not be possible.) In this case, go back to the console (Ctrl+Alt+F1 or Ctrl+Alt+F2 should do it), log in, and type killall wine. Wine should exit taking its sickly program along with it, leaving your X session unharmed. Pressing Alt+F7 will take you back to XWindows on most systems.

Wine dates back to 1993, when Windows 3.1 was the norm. Although its feature set has expanded to include the new features and functionality of Windows 95/98 as well as their look and feel, some legacies of 3.1 remain. For instance, minimizing a Wine application creates a small icon on your desktop even if you use a window manager that treats minimized programs differently (such as in a Windows 95-style taskbar at the bottom of the screen).

Given the healthy amount of warnings and uncertainty I've given you about Wine, it might not sound all that enticing. I merely want to prepare you for the fact that although it offers a great deal of promise, at present it should be reserved for special, non-essential tasks.

Wine's development future actually looks quite bright. Many of the advances Corel had to make to port WordPerfect Office have not yet been incorporated into the Wine source code, but when they are, it should open new possibilities both for Wine developers and end users.

For now, consider Wine your Windows compatibility flyswatter: If you only have a small pesky problem to deal with, such as searching for alien life as shown in Figure 16.8, you might not always need to bring the VMware sledgehammer to bear.
