
The SoundBlaster 16 emulation is well-supported in almost all of VMware’s supported guest operating systems and poses little configuration challenge (even in Linux virtual machines).

> If you’ve grown frustrated fighting with custom drivers for your off-brand sound card in Linux, do yourself a big favor and pick up a used or surplus SoundBlaster 32 or 64AWE from a wholesaler or a private seller on eBay or the like. They’re quite good, and they work with the default sound drivers in commercial Linux distributions.

## PCMCIA/PC Cards

Although Linux has strong support for the PCMCIA ports (now called PC Cards) found on laptops, VMware does not directly support PCMCIA cards. It does, however, support the most common types of devices found on PCMCIA cards (Ethernet adapters and modems, provided that the modem is not using Winmodem technology) as long as the cards have been properly configured in Linux.

> For additional advice on getting maximum Linux compatibility (and, in turn, VMware compatibility) out of your laptop’s hardware, read the Linux PCMCIA HOWTO (http://www.linuxdoc.org/HOWTO/PCMCIA-HOWTO.html) and the Linux on Laptops home page (http://www.cs.utexas.edu/users/kharker/linux-laptop).

## What Software Can VMware Run?

This section really addresses two questions: “What operating systems can be installed in a VMware virtual machine?” and “What software can I then run on a supported OS in a virtual machine?” First, let’s look at the guest operating systems VMware supports.

## Guest Operating Systems

VMware fully supports the most popular operating systems for Intel x86 architecture PCs. Specifically, the following versions and distributions are fully compatible with VMware virtual machines:

- Microsoft Windows 2000 (Professional, Server, and Advanced Server)
- Microsoft Windows NT 4, Service Packs 3-6a (Workstation and Server)
- Microsoft Windows 98 and 98 Second Edition
- Microsoft Windows 95
- Red Hat Linux 5.x-6.x
- Caldera OpenLinux 1.3-2.x
- SuSE Linux 5.3-6.x
- TurboLinux 6.0
- Corel Linux OS
- FreeBSD 2.2.x-3.x
- Microsoft Windows 3.1 and 3.11 (no VMware Tools)
- Microsoft MS-DOS (no VMware Tools)

VMware certifies and supports its product with each of these operating systems. This book addresses installing and using each major family of guest operating system, with the exception of Windows 2000 Advanced Server. The extra features in Advanced Server, such as support for up to eight CPUs and network load balancing, are of little interest in a VMware virtual machine.

Because of VMware's robust virtual machine technology, it is possible to run other operating systems, although results are often spotty at best.

VMware provides experimental, or only partially compatible, support for these guest operating systems:

- Novell NetWare 5.x
- Novell NetWare 4.x
- Novell ZENworks client
- IBM OS/2
- IBM OS/2 Warp
- Sun Solaris for Intel 7
- Windows Millennium
- NetBSD 1.x
- OpenBSD 2.x

VMware does not provide VMware Tools for any of these unsupported operating systems and only provides partial installation documentation for some versions of Novell and for OS/2 (standard version). VMware has only made a firm commitment to supporting Windows Millennium.

VMware has not flatly stated that it won't support the other operating systems, and seems to be at least open to receiving well-documented incident reports about compatibility problems.

## Unsupported Guest Operating Systems

Basically, anything that does not appear on the previous two lists is not a priority for VMware and might not work at all. BeOS, QNX, Minix, and commercial UNIX versions such as SCO UnixWare fall under this category. Although you are free to experiment, be prepared for disappointment.

## Software Compatibility

As long as you use a fully supported operating system in VMware, you should get a high level of software compatibility. VMware has worked hard to ensure that programs designed for Windows, Linux, and FreeBSD run smoothly in a virtual machine.

Some notable exceptions do apply:

- VMware does not support most DirectX functions in Windows. Most of the time, this only affects games, but some other programs rely on DirectDraw, Direct3D, and DirectSound functionality and might be impaired or unable to run.
- Software that relies on proprietary or custom hardware does not work in VMware. That rules out EPROM programmer boards, diagnostic equipment, or specialty networking cards such as the one the DirectPC satellite Internet system uses.
- Software that makes undocumented or extremely unorthodox direct calls to PC hardware might not work. Although VMware does its best to provide a 100 percent accurate emulation of every conceivable PC system device scenario, some tricks and gimmicks are beyond its ability to anticipate or support.

Don't be scared off by these isolated limitations. After you've settled into the virtual machine environment and loaded a few programs, you'll probably forget you have a Linux running in the background.
