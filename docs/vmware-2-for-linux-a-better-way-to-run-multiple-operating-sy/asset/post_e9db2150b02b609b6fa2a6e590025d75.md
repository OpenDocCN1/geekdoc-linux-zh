
By committing, you make the changes permanent. Discard loses the changes forever, leaving the disk image in the same state it was before you last launched VMware.

But by merely keeping the changes, you can mull over your choice until the next time you run VMware. At that point, you are asked again to commit or discard the changes. You're also presented with a new option: append new changes to the current redo log. This means that the virtual machine boots with the changes you made last session intact (in other words, as if you had committed to the changes) but leaves the redo log open, which still leaves you the option of undoing all the changes you made in both the current and the last session. Figure 2.6 shows VMware starting a new session with a "kept" redo log.

If you decide to append new changes to the existing redo log, all the changes you have made are part of the same log: You cannot selectively undo only the changes made in the current or previous session.

If you entirely forgot to make a decision about the changes, you can cancel the VMware load sequence so you can make up your mind about the redo log.

## What Hardware Can VMware Share?

The good news is that VMware and any supported guest operating systems work flawlessly with most of the hardware you're currently enjoying under Linux. The bad news is that VMware only works with hardware you're currently enjoying under Linux. The VMware Virtual Platform layer can only address hardware that can be configured and used in the Linux universe.

VMware Hardware Compatibility Rule #1: If the hardware doesn't work in Linux, it won't work in any VMware guest OS, even if that guest OS natively supports the hardware. Exception: Some dongles (which are useless under Linux) are properly recognized in VMware guest operating systems.

However, just because a device works in Linux does not necessarily mean that it will work in a VMware virtual window. Some hardware that works under Linux is only indirectly supported in VMware, and others simply don't work at all.

> VMware Hardware Compatibility Rule #2: Just because hardware works in Linux does not necessarily mean it will work in VMware, and if it does work, it might not be directly supported.

Here's a more complete look at VMware-friendly hardware.

### Mice

In general, almost any common PS/2 or serial mouse you can easily attach and use in Linux will work just fine in VMware. Specifically, mice that adhere to the PS/2, Microsoft serial, Mouse Systems, Logitech MouseMan Serial, or Microsoft IntelliMouse PS/2 standards are supported. VMware limits you to a standard two- or three-button mouse inside the virtual machine; however, wheel or scroll mice are not supported in VMware, even if you manage to enable the wheel in Linux. The wheel can act as a third button when clicked, however.

### Keyboards

The news for keyboards is much the same as it is for mice: If it's a standard, Linux-supported keyboard (as most are), you won't have any difficulties. VMware emulates a 101/102 key keyboard, although some of the extra features found on "multimedia" keyboards can be supported if you have the proper drivers for the guest operating system.

> In some more esoteric environments, VMware might have trouble recognizing your keyboard. If you are using the recommended XFree86 video software but VMware can't see the keyboard, you need to edit the file ~/.vmware/config (the VMware configuration file on your local machine, in your user directory), and add the following line:

```
xkeymap.uskey codeMap = true
```

If your PC is accessing a remote XFree86 video server, add the following instead:

```
xkeymap.uskeycodeMapIfXFree86 = true
```

> Some Japanese-language keyboards might not work properly under VMware. Full details on fixing the problem are available at VMware's technical support site at http://www.vmware.com.

### Video Cards

More good news if you're the kind of person who likes to keep things simple: If your video card is properly supported in XFree86, you have nothing to worry about. If you have an extremely old video card (with 2MB of video memory or less), you will find your choice of screen resolution rather limited after you install a guest OS, but the limitations are exactly the same as they are in Linux.

The real key is the version of XFree86 you're running. VMware strongly recommends version 3.3.4 or better (version 4 is not yet officially supported, but may work properly). If you're running a VMware-approved distribution of Linux, you have nothing to fear because your distribution incorporates the proper version of XFree86.

> If you're not sure what version of XFree86 your system is running, or you are simply curious, type xdpyinfo at any terminal prompt. The version number appears toward the top of the page in the vendor release number field. The number is returned without periods, so 335 means you have XFree86 version 3.3.5.

In most supported operating systems, a VMware guest OS can use the full SVGA resolution and color capacity of your computer's own graphics card. However, in DOS, Windows 3.1, and unsupported operating systems, VMware only emulates a standard VGA video card, which tops out at a very modest 640×480 screen with only 16 colors! This is good enough for a few basic applications and some games but is hardly impressive to look at.

To fully exploit your graphics card in VMware, you need to be sure to install the VMware Tools in each guest operating system. More information on VMware Tools is coming up in Chapter 8, "Understanding the VMware Tools for Windows."
