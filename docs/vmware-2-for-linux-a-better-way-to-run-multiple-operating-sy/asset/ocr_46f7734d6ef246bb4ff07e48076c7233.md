VMware claims that in some circumstances the Virtual Platform layer consumes less than 5 percent of available CPU time; you might find it needs 20 percent or more. See Figure 2.2 for an example of typical CPU usage on a computer running Linux and a VMware guest session.

> VMware does not support multiprocessor access from within a virtual machine, but if your host machine has more than one CPU, you can lighten the load. VMware will run a second virtual machine on your second CPU, the third on a third CPU (if available), and so on. This makes it feasible to run more than one instance of VMware at once; otherwise, your system starts to get a bit crowded. Unfortunately, VMware does not provide a built-in tool to select which CPU will run each virtual machine.

Keep in mind that the features and quirks of the host CPU are replicated in the VMware guest virtual machine. For instance, computers using AMD K6-2 CPUs of 350MHz or more are susceptible to a crashing on startup in Windows 95, and the same patch that cures the problem on a standalone Windows PC is required in VMware.

By the same token, if you want your guest operating system to have access to the Streaming Single Instruction Multiple Data (SIMD) Extensions of the Intel Pentium III or the Enhanced 3DNow! capabilities of the AMD Athlon, then that needs to be the CPU in your computer. VMware can't make a four-cylinder engine look like a V8.

> The AMD K6-2/Windows 95 problem is described at http://www.amd.com/products/cpg/k623d/win95_update_k6.html.
