
It’s always been a badge of pride for game developers to push computer hardware to its limits and beyond, employing tricks and programming techniques that can be difficult enough for native hardware to handle, let alone an emulator or virtual machine. But despite the hazards, VMware can provide an adequate game platform—if you do your homework and select the right games.

I don’t expect you to make a major investment in VMware just to play games. In truth, despite my earlier criticism of dual booting and keeping a second computer on your desk, both make for a more reliable gaming experience than does VMware.

Still, you’ve got VMware, you know what it’s capable of, and you want to go beyond word processors and database programs. Here’s what you need to know.

> When I talk about using VMware for gaming, I specifically mean DOS and Windows 95/98/NT virtual machines. The game selection for FreeBSD is rather minimal, and virtually anything you can find would be duplicated for Linux. There are relatively few games for Windows 3.1, and most will run as well, if not better, in 95/98/NT. Using a Linux VM as a gaming platform is not ideal because of the emulation overhead it creates, unless you are extremely concerned a game might cause a catastrophic system crash that you want to isolate from the host Linux OS.

## The Bad News: Compatibility Hurdles

There’s no point in sugar-coating it: A substantial number of games simply will not work in VMware.

For DOS games, you can forget about titles that require EMS (expanded) memory, as well as any that require screen resolution above 320×200 at 256 colors or 640×480 at 16 colors. Included under this heading are also games that were released after 1995 and can be installed in Windows but need to exit Windows completely to run.

On the other hand, games released in the mid to late 90s usually do not require EMS because programmers had learned to make more efficient use of conventional and XMS DOS memory. Some of these games run at higher resolutions, such as 640x480 at 256 colors, or they access the video chip in ways not supported by VMware. Generally, if a game claims it requires SVGA resolutions in DOS mode, it will not work in VMware.

Some older DOS titles might also have a difficult time properly identifying and using the virtual SoundBlaster 16. Newer titles that offer "auto-detection" tend to do a better job. It's largely hit-or-miss, but you might be forced to listen to the beeps and squawks of the PC speaker instead of more soothing melodies.

For Windows games, the primary problem is games that require DirectX, which in the past few years has become extremely common. The VMware SVGA driver does not support DirectX calls, so DirectX games will almost certainly fail to run. You can experiment at your own risk, but it will probably be cheaper, and less frustrating, to simply avoid games labeled "Requires DirectX."

These incompatibilities are what could be termed "behind-the-times" problems: VMware's virtual hardware is not as current and compatible as it could be. One more potential problem can show up if you try playing older games: being too fast for your own good. Some older DOS games were written with processors such as a 386/25, 286/12, or even slower in mind. Because your computer is capable of running VMware, it is literally dozens, possibly hundreds of times faster in raw CPU power than those workhorses of the 80s.

![](img/b2b6702758c230ce537468351fc8af15_321_0.png)

Figure 15.2 King's Quest I from Sierra, a true classic and one that runs well even on fast computers in VMware.

On a real computer, you would have the option of shutting off your CPU's caches to slow down the works, but because you are sharing the CPU between VMware and your host Linux OS, this is not possible. VMware's BIOS does not include a cache disable option, and it is not recommended to try using a cache shutoff program in DOS or Windows. You can use other tricks to slow down your virtual machine to deal with an old game, but your options are more limited because you do not want to cripple the host in the process.

> It is possible to support SVGA in DOS and DirectX in Windows using a virtual machine or emulator. There are PC emulators for PowerMacs that do both. To date, VMware has focused on professional-minded functionality and stability, but a well-worded letter might help convince it that the market is expanding.

## The Good News: Games That Work

So, what's left? Only thousands of games! No, perhaps not all your favorites, but probably enough to keep you entertained on a fair number of Sunday afternoons.

If you have a large stock of games already in your library, simply experiment. Install them, and try launching them. At the absolute worst, an incompatibility problem might lock up the guest OS, requiring you to manually power down the virtual machine. More likely, the game will simply refuse to run or crash back to the DOS prompt or Windows desktop.
