
## Appendix B: File Sharing with Samba and NFS in VMware

- File sharing with Samba
- File sharing with NFS

In each of the main guest operating chapters, I focus on sharing files between host and guest with either FTP or virtual disk mounting. This is effective and easy to do, but limited. Sometimes it’s preferable to be able to interactively mount a drive from the host on the guest, or vice versa, cutting the hassle of making a copy (which is essentially what FTP does) or shutting down VMware (necessary to mount virtual disks on the host).

You can run Samba and NFS servers on the Linux host or on most guest operating systems. Most versions of Windows can share drives using built-in Samba server technology, but NFS is better suited to Linux and FreeBSD host and guest systems.

Both Samba and NFS are what could be called “multitasking” drive-sharing mechanisms. That is, you can continue to use the host’s drive directly in Linux while a virtual machine accesses the same drive over NFS or Samba.

For either of these networking methods to work, you should first make sure that your machine is named something other than localhost because this can confuse networking software. Consult a Linux manual about the /etc/hosts or /etc/HOSTNAME files for more detail on changing your host name.

## File Sharing with Samba

I assume that you will run the Samba server on the host computer using the VMware Samba server. If you happen to use Windows NT 4 Server or 2000 Server as a guest operating system, you could opt to run file sharing from that virtual machine.

In that case, you access the shared drives through the host using Linux’s smbclient program described later in this appendix. You simply replace the host name and IP address with that of the Windows server guest.

Remember that for Samba networking, the relevant IP addresses are those that relate to VMware host-only networking: the IP address assigned to vmnet1 on the host side and the IP address assigned to the host-only Ethernet adapter on the guest.

These Samba networking tips also presume you are using the Samba server included with VMware, which functions only over the host-only virtual network adapter. You need to do additional research to make Samba work over bridged networking.

> The Samba Linux HOWTO is located at http://www.linuxdoc.org/HOWTO/SMB-HOWTO.html. It will help you if you need to set up Samba over bridged networking.

## Configuring the VMware Samba Server

When you configured VMware, you should have installed the host-only Samba server when asked. (If not, reconfigure VMware with the vmware-config.pl command.)

The file /etc/vmware/vmnet1/smb/smb.conf contains the configuration data for the VMware Samba server. It is not the same as /etc/smb.conf, which might already be on your system even if you do not have another Samba server running.

In particular, you need to pay attention to these aspects of the /etc/vmware/vmnet1/smb/smb.conf file:

- Take note of the workgroup ID, early in the file. By default, this is set to WORKGROUP.
- Set up a drive to share. (It appears at the bottom of the file under the [HostFS] heading.) By default, the entire file system is shared.
- Ensure that the server is set to be local master = yes.

You also need to run the vmware-smbpasswd command to establish at least one Samba password for an existing user account on the host computer.

The format for the vmware-smbpasswd command is

```
vmware-smbpasswd vmnet1 <username> <password>
```

`<username>` is an existing user on the host, and `<password>` may or may not be your current login password. It is possible, depending on your system configuration, that you might need to change vmnet1 to vmnet2 or vmnet3; a quick look at /sbin/ifconfig will tell you which your system is using.

Until you run vmware-smbpasswd, you will not be able to access host drives via Samba.
