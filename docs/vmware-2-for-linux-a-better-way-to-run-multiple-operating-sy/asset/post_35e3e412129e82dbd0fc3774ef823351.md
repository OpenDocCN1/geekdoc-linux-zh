
Not only does VMware protect the host system from the guest virtual machines, but also it can protect the virtual machines from themselves, so to speak.

Whether it's accidentally deleting important files, changing the wrong configuration setting, or contracting a virus that wreaks havoc with your data, chances are that you've had some sort of horrible problem on a computer before. And chances are good that you have one with a virtual machine as well. Fortunately, VMware included a couple of ways to help protect your data if you feel you're particularly prone to accidents or sabotage.

Most of the time, VMware uses "persistent" disk images to store data. These storage devices (actually just large files in a Linux directory) behave exactly like a regular hard drive. But any VMware hard disk image can be flagged as "nonpersistent" or "undoable" if you need a safety valve or you have some other reason for keeping your files extra-safe. You can make this choice every time you start VMware, so you don't need three different disk images to take advantage of the three different types of disks. ## Nonpersistent Disks

Nonpersistent disks appear to the guest operating system to be completely normal hard drives. But when changes are made to the drive—whether you edit an existing file, install new software, or even format the entire partition with extreme prejudice—the changes are not made to the disk image, but to a temporary redo log file. For as long as VMware is running, that log file sits between the guest OS and the nonpersistent disk image, making it appear as if all the requested changes have been made. But as soon as VMware is shut down, the changes are gone, and you're left with the exact same disk image you had before you cut your swath of destruction.

BUZZWORD
Redo log: A file that records all the disk writes made in a VMware guest OS session. The modifications in the redo log can be made permanent, or they can be discarded

Of course, this is an absolute nightmare if you've just spent hours installing your favorite applications, writing a program, or composing your magnum opus. But for testing new software, a new change to your virtual system, or commercial applications such as tech support, it's a brilliant stroke of luck.

> The buffering process used to create the redo log and track the differences between the nonpersistent disk and the log introduces an extra layer of overhead to disk access, which can slow things down. On the other hand, because of the way VMware buffers disk access, some read/write operations actually work faster with nonpersistent disks.

Nonpersistent disks give you a "clean room" virtual environment every time you restart VMware, so you also get a certain license to brutalize the configuration. Not sure what that Windows Registry hack you just read about does? Give it a try. Just read about a clever kernel modification, but you're afraid to try it on your main Linux drive and you hate the tedium of backing up your current kernel and creating a new boot entry? Experiment in the protected world of a nonpersistent Linux virtual machine!

## Undoable Disks

What's that I hear you cry? "What about changes I really do want to keep? Why can't I have my cake and eat it too: have the safety of the redo log but the option to keep my changes in case everything is fine when I'm done?"

Yes, you can in fact possess and consume your sweets simultaneously. An undoable disk gives you the protection of nonpersistent disks, but the option to make all your changes permanent at the end of a VMware session. If you choose to commit to the changes, VMware updates the disk image. If you discard them, the disk image remains untouched and will be exactly the same as it was before you last ran VMware. Figure 2.5 shows the end of a virtual machine session that employed an undoable disk.

The really nice part is that you actually get two opportunities to decide what to do with the redo log. When VMware powers down, you are asked whether you want to commit, discard, or keep the changes made during the virtual machine session.
