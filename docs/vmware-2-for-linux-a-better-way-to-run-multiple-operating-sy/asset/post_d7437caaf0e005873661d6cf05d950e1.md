## Understanding the Virtual Machine BIOS

VMware didn't cut corners in designing its virtual machine technology. It went so far as to license and customize Phoenix BIOS code, the fundamental ROM-based software layer of any PC. The Phoenix BIOS makes a VMware virtual machine "look" more like a real PC, both to the user at startup and to some operating systems such as DOS.

Although many experienced PC users already feel comfortable adjusting BIOS settings, both novices and veterans should understand what the VMware BIOS can and cannot do to customize a virtual machine.

To enter the VMware BIOS, press F2 at the VMware boot screen after powering up your virtual machine. The window of opportunity is fairly narrow, and you might want to tap the F2 key a few times to make sure the system acknowledges your request.

When you've succeeded, you should see the main BIOS screen, shown in Figure A.11.

## Using the BIOS Configuration Screens

Each of the six screens has a variety of configuration settings—both those you should be aware of in case you need to change them and those you should leave alone in nearly any situation.

## Adjusting the Main BIOS Screen

On the main BIOS screen, you will find:

- Time and Date—These settings should be read directly from your Linux system clock and as such should always be accurate. Only adjust if you have a very specific reason for doing so.
- Legacy Diskettes A: and B:—VMware should pass the proper settings, based on your virtual machine configuration, to the virtual machine.
- Primary Master through Secondary Slave—The BIOS should automatically detect any additions or changes to the virtual IDE controller and insert the proper reference. If you plan to tinker with these settings, leave SMART Monitoring turned off. SMART is a disk failure detection system, but SMART detects physical faults; even with raw disks, VMware is not equipped to test your disks at this level.
- Keyboard Features—If you are working primarily in a command-line environment (a Linux VM without XWindows or DOS), you might want to experiment with these settings if you are unhappy with keyboard performance. Remember, however, that the Linux OS and BIOS on the host influence keyboard operation as well. A sample of this screen appears in Figure A.12.

## Adjusting the Advanced BIOS Screen

The Advanced BIOS screen controls some of the virtual hardware at its most fundamental level. See the screen in Figure A.13 for more detail.

> On a real computer, the Advanced BIOS screen would be full of options such as CPU cache control. VMware cannot directly enable or disable your system cache, so these options have been omitted.

![](img/b2b6702758c230ce537468351fc8af15_399_0.png)

Figure A.13 Use the Advanced Features screen to control the behavior of system-level virtual devices.

- Reset Configuration Data—You should never need this setting.
- PS/2 Mouse—If VMware is having an exceptionally difficult time configuring your mouse for use in a virtual machine, you might try setting this option to Enabled.
- Secured Setup Configurations—If you are experimenting with device configurations in a virtual machine and the virtual machine's guest OS is a Plug-and-Play OS (such as Windows 98 SE and Windows Millennium), you might want to use this option to prevent the OS from making wholesale changes to the BIOS configuration. Use only if needed.
- Large Disk Access Mode—This should be fine left alone in DOS mode, although Linux virtual machines can be set to Other.
- Local Bus IDE adapter—Leave set to Both.
- SMART Device Monitoring—This is useless. As long as you don't enable device monitoring for a virtual disk (which you shouldn't do), the setting is irrelevant.
