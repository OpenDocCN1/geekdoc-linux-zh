
> For more information on printers and Linux, read the Linux Printing HOWTO at http://www.linuxdoc.org/HOWTO/Printing-HOWTO.html.

Linux has fair support of flatbed and handheld image scanners. However, VMware only supports scanners that connect via the parallel port. More powerful scanners prefer a SCSI interface because it is considerably faster, not to mention more flexible and reliable. But until VMware, Inc. improves its SCSI support, consider image scanning a hit-or-miss prospect in virtual machines and only if you can find a parallel port scanner. (USB scanners are also out of the question due to poor USB support in Linux and no USB support in VMware.)

> If you have a scanner that is supported in Linux but not in VMware, there's no reason why you can't use Linux for scanning and a VMware guest OS for image editing. See Chapter 9, "Using Your Windows 95/98 Virtual Machine," for suggestions.

## Modems and Network Cards

Modems have followed the same sad design path as printers over recent years. It's still almost always true that an external modem works just as well on Linux as it does in any other operating system, so VMware has the same full level of support.

Internal modems are a different matter. It has become somewhat difficult to find an internal modem that does not rely on a proprietary Windows driver. Although many Linux enthusiasts have rallied to petition the manufacturers for support, it has been extremely slow in coming. As with Winprinters, VMware cannot break through this "Winmodem" barrier, even in a supported Windows virtual machine.

> http://www.o2.net/~gromitkc/rg hosts a list of internal PC modems commonly found at major computer stores, with Linux compatibility information for each model.

Fortunately, Ethernet cards have not followed this sad route. Linux's support for most ISA and PCI Ethernet cards is fantastic (you can buy Ethernet cards for less than $20 that work splendidly), and there is even growing support for the OS from networking vendors.

VMware should work with any Linux networking card. Instead of giving guest operating systems direct access to your network adapter, however, VMware internally emulates an AMD PCnet Family Ethernet card, so that is the device each guest operating system must be able to support. Every VMware certified guest OS supports the PCnet Family emulation, including DOS and Windows 3.1.

> Full documentation and device drivers for the PCnet Family card are available at http://www.amd.com/products/npd/software/pcnet_family/intro.html.

## SCSI

The only SCSI hardware VMware can access are hard drives and CD-ROMs. Scanners, tape drives, and other peripherals are unavailable.

VMware’s SCSI support is similar to its Ethernet card support. Instead of allowing the virtual machine to see your SCSI card directly, VMware emulates its own SCSI card, in this case a BusLogic BT-958 device. This card is supported in all of VMware’s supported guest operating systems.

The emulated SCSI card can see up to seven devices (virtual disks and CD-ROM devices combined), in addition to what the emulated IDE controller can support.

> For more information on the BusLogic BT-958, see the manufacturer’s support page at http://www.mylex.com/support/download/manuals/scsihstad.html.

## Sound Cards

Sound support under Linux is certainly a lot better than it has been in years past, but it’s still not an exact science, in large part because sound card manufacturers keep changing their chips and specifications without telling anybody.

Some card families, such as those from Creative Labs and ESS, are reasonably well supported by Linux developers. Some vendors, such as Aureal, have begun supporting Linux directly—although Aureal is now bankrupt.

If you’ve managed to conquer the challenges of sound configuration in Linux, VMware will richly reward you with SoundBlaster 16 emulation in its virtual machines. VMware does not currently support MIDI synthesis or the joystick port found on most audio cards.
