
Windows 95 has a known incompatibility with the AMD K6-2 chip at speeds of 350MHz and above. It is considered transient in that it may not show up every time you boot Windows 95, but the problem was severe enough that I actually had to use a second PC to write this chapter. Although a patch is available from Microsoft and AMD, it really only works with Windows 95 OSR2, and even then it does not work particularly well in VMware. If you have a K6-2 CPU, I strongly urge you to use Windows 98. This problem does not affect K6, K6-III, or AMD Athlon processors.

If you're unsure what version of Windows 95 you have installed, you can check the System Properties window after installation. Right-click the My Computer icon and select Properties (see Figure 7.1 for an example). You should see a string starting with 4.00.950. If it has no accompanying letter, you have the original Windows 95. An A or B indicates you are using intermediate revisions, which correct some important bugs. C (also OSR2.5) shows that you are using the most up-to-date major release of Windows 95, which integrates Internet Explorer into the operating system much as Windows 98 does.

You can install incremental bug fixes and patches from Microsoft in your virtual machine, just as you would on a regular computer.

## Preparing the Virtual Machine

If Windows 95 is handy and dandy, you need to create a new virtual machine.

> This installation sequence assumes you will be using a Windows install disk labeled "For Distribution with a new PC only" or similar. There are some minor differences in upgrade editions.

## Starting with the Wizard

Begin the Windows 95 virtual machine installation by creating a new VM configuration, starting with the Configuration Wizard.

- 1. If you're not already in VMware, start the main program by typing /user/bin/vmware at a command prompt.
- 2. Launch the VMware Configuration Wizard by clicking Wizard in the File menu.
- 3. Click Next to clear the first greeting screen. VMware presents the Guest OS selection screen, shown in Figure 7.2
- 4. Select Windows 95 from the list of guest operating system choices, and then click Next to proceed.

![](img/b2b6702758c230ce537468351fc8af15_133_0.png)

If you have an upgrade edition of Windows 95, you should select the operating system you will install first. Then, at each upgrade stage, edit the Guest OS setting in the Configuration Editor before proceeding.

- 5. Enter a path to the new directory that will house the VMware configuration files as well as the virtual disk. By default, VMware asks you to create a new directory called `/vmware/win95` on your home directory.
- 6. VMware asks whether you want to create a new virtual disk or use an existing physical disk. Unless you are familiar with the advanced disk and configuration modes described in Appendix A, “Advanced VMware Configuration,” it is best to accept VMware’s offer to create a new virtual disk, indicated in Figure 7.3. Click Next.
- 7. Enter a size for the new virtual disk. Although 2,000MB is the default, you can go as high as 2,047MB. Remember that the disk grows as data is added, but you cannot change its maximum size later. Click Next to proceed.
- 8. VMware should detect your CD-ROM. You need a CD-ROM to install Windows 95, so leave the default settings as is (to enable CD-ROM access and make it available when the virtual machine boots), and click Next.
- 9. VMware asks the same question about floppy access. Unless you have a compelling reason to disable the floppy, leave this setting alone as well. Click Next.

![](img/b2b6702758c230ce537468351fc8af15_134_0.png)

*Figure 7.3* Most users will want to create the largest virtual disk possible, 2 gigabytes.

- 10. The wizard asks how the virtual machine should be able to access the network (see Figure 7.4). If you plan to keep the Windows VM completely isolated, you can click No networking. If you have an Ethernet card installed and your PC is on a LAN, use Bridged networking, which lets the virtual machine share your Ethernet card and appear as a standalone computer on the network. Host-only networking allows Samba file sharing between the VM and your Linux PC (provided you installed the VMware Samba server at installation or you have one of your own running), and Bridged and host-only networking combines the two. If you have a LAN, stick with Bridged for now. If you do not, use Host or none. Click Next to reach the final step.

![](img/b2b6702758c230ce537468351fc8af15_135_0.png)

Figure 7.4 The network configuration screen helps you prepare VMware to communicate with your Linux host OS and the rest of the world.

Even if you don’t install any networking, there is still an easy way to exchange files between your Linux PC and virtual disks. It involves mounting the virtual disk as a Linux-readable file system, which is covered in depth in Chapter 9, "Using Your Windows 95/98 Virtual Machine." I personally think it’s easier and more convenient than host-only Samba networking for most file-sharing needs.

- 11. The wizard summarizes the virtual machine it will create. See Figure 7.5 for a sample. If everything looks appropriate, click Done.
