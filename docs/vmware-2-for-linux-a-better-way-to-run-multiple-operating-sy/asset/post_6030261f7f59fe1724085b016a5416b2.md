If you need to go shopping, remember to be careful of system requirements. Although a few games that are labeled for DirectX will actually work in VMware (such as Blizzard's StarCraft), this is much more the exception than the rule. If you're searching bargain bins for latter-day DOS titles, watch for EMS (expanded memory) requirements and references to SVGA modes or screen resolutions such as "640 by 480 pixels and 256 colors."

Smart shoppers might want to start with classic game compilations or budget re-releases—games a few years old repackaged in CD jewel cases or small boxes and priced at $15 or less. Almost every major game publisher has its own budget line or box set collections. Your taste may vary, but I can recommend, from experience, sets such as Sierra's Roberta Williams Collection, Police Quest and Quest for Glory, and Interplay's 10th and 15th Anniversary collections. You can't count on every game in every collection to work flawlessly, but there should be enough to make the purchase worthwhile.

## Configuration Tips for Games

The first thing to remember is that many games come with system-configuration and memory-management tips, and most of them are perfectly relevant for VMware as well as a real PC. The exception is anything that tells you to use EMM386.EXE or create expanded memory, which you already know is off-limits. Many games come with suggested boot sequences or even tools to create custom boot floppy disks that should leave you with enough memory and system resources to run the games. Try those "official" suggestions before you start suspecting VMware of additional compatibility problems.

## DOS Gaming Configuration

This section covers games designed for pure DOS mode, which includes pre-Windows 95 titles, as well as those you might be able to install or launch from Windows but have to run from a pure DOS environment, either by exiting to DOS first or by shutting down Windows as soon as you double-click the icon.

> Some classic game compendiums allow or require you to install games from Windows 95 or better, but they actually only run in a pure DOS setting.

Memory configuration is the major headache for DOS games. The good news is that for games that work at all in VMware, the default memory configuration of most MS-DOS and DR-DOS installations works perfectly well. In general, this ideal memory configuration consists of these two lines in the DOS CONFIG.SYS file:

```
DEVICE=C:\DOS\HIMEM.SYS (or C:\DRDOS\HIMEM.SYS)
DOS=HIGH, UMB
```

As long as you allocate at least 8 to 16MB to your DOS virtual machine, you should rarely, if ever, have a problem with not having enough overall memory. You might be too low on conventional memory, which is defined as the first 640KB of memory available to DOS and the space in which programs are directly executed. By typing mem at a DOS prompt, as shown in Figure 15.4, you can get a sense of how much conventional memory is available.

Figure 15.4 The mem command tells you how much conventional memory is available to run DOS games.

In MS-DOS, the readout is slightly different, but the important detail is the "conventional" memory setting, which DR-DOS also summarizes as "Largest executable program." 591KB is sufficient for almost any program. How do you get that much free memory?

- Use the command mem /c in DOS to view the individual components that are sucking up your free memory, and target those for removal.
- Remove unimportant or extraneous entries in your AUTOEXEC.BAT and CONFIG.SYS files by inserting the word rem in front of them. In AUTOEXEC.BAT, you might consider removing items such as SMARTDRV or NWCACHE (disk caching software, which can speed disk access but at a memory price), any DOS virus checker you might be running, and your mouse driver. In CONFIG.SYS, you might remove ANSI.SYS (unless you are running a text-based game that uses colors and text effects) and remove or reduce the number in the BUFFERS entry. (It controls the RAM hard drive buffer, which also speeds disk access by using RAM.)
- If you don't run your mouse driver in AUTOEXEC.BAT, you might not need to start it; some games incorporate their own mouse drivers or don't support the mouse at all. A mouse driver can take up 20KB or more of conventional memory.
- If you are using the OAKCDROM.SYS CD-ROM driver in DOS, switch to the Mitsumi driver listed in Chapter 14, "Installing DOS and Windows 3.1 in VMware." It requires considerably less memory and is equally compatible. If you are really pressed for memory and do not need CD-ROM support for your game, you can comment out the CD-ROM driver from CONFIG.SYS and the call to MSCDEX or NWCDEX in AUTOEXEC.BAT.
- The DOS command line requires memory to run, but not all DOSs take up the same amount of memory. In general, DR-DOS is the most frugal, followed by MS-DOS 6, with the Windows 95/98 MS-DOS mode in last place. If you are having memory problems trying to use DOS in a Windows virtual machine, switch to a dedicated DOS virtual machine with MS-DOS 6.22 or DR-DOS.
- If you are using DR-DOS, do not use the setup program's setting for "Setup DR-DOS for Best Games Performance" because it involves the use of EMM386.
- The DOSIDLE program also occupies some memory. If you need a few extra kilobytes, don't run it.

After you've conquered memory, your other major headache is likely to be sound support. Although VMware provides a virtual SoundBlaster 16 card, DOS games might not always be able to take advantage of it. Some older games might not list a SoundBlaster 16; in that case, choose SoundBlaster "classic" support, rather than SoundBlaster Pro. The SoundBlaster 16 is not directly compatible with the SoundBlaster Pro.
