
## Sharing the Network

If you've been a careful student, you're aware of all these network nuances already, but it's worth repeating: A VMware virtual machine looks and acts just like any other networked computer on a LAN when in bridged networking mode.

That means if you feed your Windows VM the same network configuration settings as your Linux workstation (except, of course, for assigning the VM its own, unique IP address), the virtual machine enjoys all the same benefits of network membership. If you have a pipeline to the Internet, any Windows network client you can imagine—including Web browsers, streaming media players, and file exchange software—all run with ease. You can access resources on the internal LAN or the Internet just as you would from your host Linux PC.

Server software also runs on VMware Windows guests, although certain tasks are still best left to dedicated computers. The VMware environment isn't set up to run network load-balancing software or a LAN-wide firewall in a virtual machine, and doing so is so difficult to configure that it isn't worth the time.

Because you can run multiple virtual machine sessions while the host continues to run, you can use VMware to create an entire "virtual intranet" and test file and network resource sharing before deploying intranet technology to the rest of the computers in an office.

You can use a Windows VM for something as humble as verifying that your Web pages look just as good in Internet Explorer as they do in Netscape and Opera for Linux. If you're so inclined, you can even set up a Web server such as Apache for intranet purposes (see Figure 9.11).

According to the Apache documentation, there are various security flaws in the Windows version that don't appear anywhere else. If you're in the mood to help out the Apache Software Foundation, what better way than by hammering on (and maybe fixing!) the security holes using your virtual machine environment?

## Conclusion

Combining advanced open-source Linux tools with the vast software library available for Windows is a reality with VMware—and, I might add, a major advantage of the virtual machine environment over a dual-boot system.

After you've fully exploited your Windows 95 or 98 virtual machine, don't be afraid to branch out and experiment with how other operating systems, running in tandem with your Linux host, can help you to be more productive.

## Why Run Linux on Linux?

At first glance, it might seem silly. You already have Linux running on your PC. If you run it in VMware, you incur emulation overhead, plus you have to go through installing Linux and all your favorite applications again. Linux is a powerful multitasking OS. Why bother?

It's not for everyone. But if you're a Linux power user, or you aspire to be but don't want to worry about causing massive damage in the process, it can be useful to have a second, simultaneous Linux environment on your computer.

## Carbon-Copy Your Desktop

Although it might not seem like the most adventurous option, you can turn a Linux virtual machine into an exact duplicate of your host computer. If you are experimenting with new software or are a developer, it might be useful to have a controlled environment that closely resembles your normal Linux system.

> A nearly identical Linux virtual machine with a nonpersistent or undoable virtual disk makes a terrific place to test new Linux kernel patches, revisions, or hacks. You get to see the results without threatening the integrity of your core system or having to muddle around with creating a backup kernel, a new entry in LILO, and so forth.

Depending on how precise you want the duplicate to be, you could simply install the same Linux distribution and software in your virtual machine or create a backup (or a very large .tar archive) of your host system and extract it to a VMware-compatible virtual, raw, or plain disk.

Because VMware emulates hardware rather than give Linux (or any other guest OS) direct access, you cannot make a VMware session match the exact behavior of your host OS. Obviously, VMware makes a poor environment to test hardware device drivers, but it is an exceptionally good software test bed.

> You cannot, nor would you ever want to, boot your virtual machine from your host Linux partition. In fact, extremely bad things happen if any virtual machine tries to directly (that is, not through a host or bridged networking protocol) access a host's physical hard drive while it is in use by the host OS.

## Expand Your Horizons

If you're not a highly technical type, probably the best reason to run Linux in VMware is to experiment with new or different distributions from the one you currently use on your computer. Advocacy in the Linux community over which distribution is best can get even more violent and difficult to decipher than arguments over which operating system is superior. How better to judge between distributions than to run them side-by-side?
