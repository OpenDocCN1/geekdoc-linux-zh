
## Understanding the Virtual Machine BIOS

![](img/b2b6702758c230ce537468351fc8af15_400_0.png)

Figure A.14 In the Security screen, you can set a password or restrict disk access.

> Any BIOS security settings can be easily circumvented by simply deleting the .nvram file that stores BIOS preferences in any VMware configuration directory. Do not count on any of these features to provide unbreakable security.

- Set User Password—Ghosted by default until Password On Boot is enabled. Allows you to password-protect the virtual machine; it will not boot unless the password is entered.
- Set Supervisor Password—Allows you to password-protect the BIOS setup screens.
- Password on boot—Enable, and then use Set User Password, to protect the virtual machine from unauthorized users.
- Fixed disk boot sector—If you are extremely concerned about viruses affecting your virtual machine, you can turn on this setting, and the boot sector (a popular target) will be write-protected. This setting may protect the virtual machine from some types of viruses.
- Diskette access—Can safely leave as Supervisor.
- Virus check reminder and System backup reminder—The system will print a message encouraging the user to run a virus scan, back up the system, or both on a daily, weekly (on Monday), or first-of-the-month basis.

## Adjusting the Power BIOS Screen

The Power BIOS screen is best left alone. If you want to use APM in conjunction with the virtual machine suspend option, you might want to turn on Power Savings. Because you don’t actually save any power in the bargain (your Linux PC will still be running as hot as before), it’s usually not worth the trouble.

Advanced Options allow you to tweak the system IRQ settings, but IRQ conflict is not a problem with most conceivable virtual machine configurations.

## Adjusting the Boot BIOS Screen

More useful than it might seem at first, the Boot BIOS screen (shown in Figure A.15) lets you control the order in which the virtual machine will poll attached devices for a bootable drive.

Use the Enter key to expand device trees (indicated by +), and use the + and – keys to move devices up and down; you can also move devices within a tree up and down within their mini-hierarchy.

I recommend the order in Figure A.15: floppy (Removable Devices), CD-ROM, Hard Drive, Network Boot. Within Hard Drive, PM indicates the Primary Master drive on the virtual IDE chain, and SM indicates the Secondary Master on the virtual IDE chain. If you want to boot from your secondary master disk, you should move the SM entry above PM.

## Saving Changes in the Exit BIOS Screen

When you have finished tinkering, you need to decide whether to commit to your changes. The screen is shown in Figure A.16:

- Exit Saving Changes—The option to use when you are satisfied with your BIOS adjustments and want to continue booting your virtual machine.
- Exit Discarding Changes—Reboots the virtual machine without saving any of the adjustments you made since entering setup. Use this option when you don't want to make any changes—even if you don't think you've made any. It is considerably safer, on the off chance you accidentally changed an important setting.
- Load Setup Defaults—If your configuration is completely out of control, you might try this. If you follow the guidance in this appendix, your BIOS is unlikely to ever need this dramatic measure.
- Discard Changes—Restores the BIOS to the state it was in when you first entered setup. Use this if you do want to make changes but have made a mistake and want a fresh start.
- Save Changes—Saves the current BIOS settings and allows you to continue editing. Essentially a "save your work" option.

## Conclusion

With careful use of raw and plain disks, you can be assured of never running out of room for your virtual machines—as long as you bring a large enough hard drive to the party, that is. And through judicious adjustment of the VMware BIOS, you can be reasonably sure that no configuration setting escapes your attention.

VMware’s Configuration Wizard and Configuration Editor, along with shortcut technology such as virtual disks, take much of the hassle out of configuring and operating your virtual machines. But if the time comes that you need to get your hands dirty in storage or BIOS maintenance, you’ll be glad you understand the nuances.
