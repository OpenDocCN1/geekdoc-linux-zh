
These principles apply equally well to a FreeBSD guest. FreeBSD has a number of Samba packages available. The client name or syntax might be different; check your system documentation.

From a command prompt on the guest, you'll want to first get a list of shareable drives from the host. The format for this is:

```
smbclient -L <IP of host's vmnet1, or name of host computer>
-U <username previously configured with vmware-smbpasswd>
```

If you want the IP address, you can get it by running /sbin/ifconfig on the host.

On my system, entering smbclient -L 192.168.71.1 -U jcompton generates the output shown in Figure B.5.

You are prompted for a password before the command will execute. Enter the password you assigned in vmware-smbpasswd.

You should see the shared drive HostFS as well as the home directory associated with the Samba username you specified in the command line. The name of the Samba server should be the same as the name of your Linux host PC.

You might need to use the -W flag on the smbclient command line to indicate what workgroup the Linux guest is in. Just add -W WORKGROUP (or whatever the name of the workgroup assigned in the host's configuration file is) to the command.

Figure B.5

You will want to create a mountpoint such as /mnt/smb used in the example (just use the mkdir command, as in mkdir /mnt/smb). That mountpoint will contain the host filesystem after you mount the drive.

To mount a Samba share in a VMware Linux guest, the command syntax is

```
smbmount // <server hostname or IP address>/<shared drive name on server> <mount path> -u <valid SMB username on server>
```

On my system, that means the command is

```
smbmount //192.168.71.1/HostFS /mnt/smb -U jcompton
```

This mounts the root Linux host file system in the smbclient software on the guest after you are asked for a password. Use the password that matches the username, as configured with vmware-smbpasswd.

> If you log in to the guest with a username recognized as valid by the VMware Samba server, you can skip the -U <username> step.

After entering the password, change the working directory to the Samba filesystem mountpoint you created (cd /mnt/smb, or whatever you chose). You can perform any standard file operation as if the drive were directly connected to the virtual machine, as shown in Figure B.6.

Is Samba better than using FTP? Maybe. Try both and decide. Then use NFS, and you'll probably never look back.

## File Sharing with NFS

NFS, the Network File System, is one of the oldest and most well-established file-sharing systems in the UNIX world. It provides a powerful alternative to FTP, Samba, and virtual disk mounting. Although somewhat more difficult to configure, it is arguably the best way to share files between a Linux host and Linux (or other UNIX-family) guest.

> These examples presume that you are using bridged networking, but the principles are the same for host-only networking. Unlike the VMware-specific Samba server, the generic implementation of NFS you will be using does not care how network requests are received.

## Using NFS with a Linux Guest

Many Linux distributions come with most of the necessary components for NFS server operation already installed and running. If in doubt, you might want to use your installation's package manager to add NFS components to your host system before you proceed. Alternately, you can search for Linux NFS packages through services such as http://www.rpmfind.net.

> The principles in this section apply equally well to a FreeBSD guest, along with any other UNIX-style operating systems you might be able to run someday in VMware.

> Read the NFS HOWTO at http://www.linuxdoc.org/HOWTO/NFS-HOWTO.html.

A basic understanding of NFS will help you make sense of the steps necessary to enable NFS between the host and guest.

## Appendix B: File Sharing with Samba and NFS in VMware

1. Ensure that your host computer is running the Linux portmapper at startup. You can check the system startup messages or run the command /usr/sbin/rpcinfo -p. You should see at least a listing for a device called portmapper. If you do not, consult NFS server documentation for the proper installation of the portmapper.

2. You now need to establish a list of drives to share on the host. As root, edit the text file /etc/exports. (You might have to create the file, or it might be blank when you start.)

3. Each directory you want to share needs an entry of this form: <directory to share> <IP address range to share to> (permissions).

```
/home/<jcpname> 192.168.20.0/24 (rw,no_root_squash),
```

You would substitute the IP range that applies to your configuration. (For example, if you choose to do NFS sharing over host-only networking, substitute the IP string with the first three digit blocks of your host-only IP range, with the .0/24 tacked on at the end to indicate all addresses that begin in that range).

The permissions (rw,no_root_squash) are the ones you commonly want to use. rw indicates that the share is read/write capable (substitute ro if you want to write-protect the drive), and no_root_squash enables the superuser on the guest machine to behave as root on the mounted drive. If your NFS server is on a larger network and you are security-minded, you might want to omit the no_root_squash option.

4. Still on the host, and still as root, run the command /usr/sbin/exportfs -a. This refreshes the system's list of shared drives. You need to run this command every time you make changes to /etc/exports.

5. Still on the host, and still as root, run the NFS server. How this is done depends on your installation: Under Red Hat, you run the command /etc/rc.d/init.d/nfs start. On other installations, you might need to start the commands mountd (or rpc.mountd) and nfsd (or rpc.nfsd) separately and in that order.

6. Still on the host, and still as root, run /usr/sbin/rpcinfo -p again to verify that nfs and mountd have been added to the list of running services. If not, stop and re-start the NFS server, and then consult some NFS documentation for additional help.

7. Load your Linux VM (if you haven't already), and create a new mount point for the soon-to-be-mounted NFS drive. A logical location is a new entry in the /mnt directory, such as mkdir /mnt/nfsm (for "NFS mount").
