## Updating Linux, if Necessary

VMware runs on a wide variety of Linux installations, so it’s fairly likely that if you have kept your system up-to-date, you’re ready to run VMware.

- Red Hat Linux 5.x and 6.x
- Caldera OpenLinux 2.2 and 2.3
- SuSE Linux 6.0, 6.1, 6.2, and 6.3
- TurboLinux 6.0

> You should also make sure that the Linux kernel header source code is installed on your system before installing VMware because VMware needs certain Linux source files to build itself.

I can’t recommend enough keeping things simple and using one of these distributions as your host OS for VMware. But if you are a truly dedicated Linux enthusiast and build your own distribution or make heavy modifications to an existing distribution,

you should at least be able to meet VMware's core requirements. VMware requires that the host Linux operating system has at least the following:

- Linux kernel version 2.0.32 (for single-CPU machines), version 2.2.0 (for multi-CPU machines)
- XFree86 Server version 3.3.3.1 (version 3.3.4 highly recommended for performance reasons)

If you do not meet these criteria, it might behoove you to take the plunge and go with one of the VMware-approved distributions.

## Speed Is King

Raw power is important for a happy virtual machine experience. In most cases, you have just one CPU in your machine. When two or more operating systems start making demands on it, things can get hairy if it doesn't have enough juice to go around.

VMware recommends a Pentium II processor at 266MHz as a good functional minimum. Will VMware run on less? Yes. Will you want to be there when it does? Probably not.

As an extremely rough rule of thumb, ask yourself, "Would I be happy running both my main Linux system and my guest OS at half of the current speed of my CPU?" Because it is unlikely that both VMware and your host OS will be making equal demands on the CPU at the same time, this scenario is unlikely, but it should give you some sort of idea.

If the answer is "no" or even "maybe," think about a system upgrade. At the time of this writing, reputable dealers are selling new motherboard and CPU combinations with 500+ MHz AMD K6-2 and Intel Celeron processors for under $200. Complete, prebuilt systems with those specifications are coming in at well under $1,000.

That sort of speed should be enough to comfortably run Linux along with most VMware guest operating systems. If you know that you plan to run some CPU-intensive tasks in a virtual machine, up the stakes. Gigahertz processors are now a reality, after all.

## How Much Memory Is Enough?

Free memory is just as important as CPU power, if not more so. Unlike CPU time, VMware requests a specific, locked amount of memory for each virtual machine. And if you start to run low on memory, the Linux host might “thrash” wildly to the swap partition, which bogs down the entire system. That might continue endlessly until you can shut off a major memory consumer (such as VMware), but because swap access slows down the system, it makes it difficult to shut off programs…you see the problem.

VMware recommends 96 megabytes (MB) as a functional minimum. I say it’s 128MB. That gives you enough room to comfortably run Linux and XWindows without any compromises and leaves between 48MB and 64MB free for VMware. That’s enough to run most supported operating systems comfortably; it’s enough for at least a modest Windows NT 4 installation, although NT 4 would certainly prefer more. It’s probably not enough to make running Windows 2000 worthwhile, however.

It’s also probably only enough to run one virtual machine, unless you plan to run DOS or Windows 3.1, or you don’t mind putting Windows 95/98 or Linux VMs under some very serious resource constraints.

> You should never allocate more than your total system memory minus 64MB to all your VMware sessions combined, unless you’re a sadist and you want to see the Swap Thrash Monster destroy your computer’s performance.

Here’s a general guideline for how much memory above 96MB you should have in your computer to run a virtual machine for each OS. The lower bound will be sufficient, but the upper bound (or beyond) will ensure greater performance. Remember that if you plan to run more than one VM at a time, you should add the figures together to reach your total:

- Windows 95/98: 32-64+ MB
- Linux and FreeBSD: 32-96+ MB
- Windows NT 4 Workstation: 32-128+ MB
- Windows NT 4 Server: 48-128+ MB
- Windows 2000 Professional: 64-128+ MB
- Windows 2000 Server: 128-256+ MB

Let’s say you’re only interested in running a Windows 98 virtual machine. Thirty-two megabytes is enough to run Windows 98, but it is nicer to give it 64; that way, Windows won’t have to hit its own swap file nearly so often. You need 96MB just to get in the game, plus you need the extra 64MB to dedicate to the virtual machine, 96+64=160MB.
