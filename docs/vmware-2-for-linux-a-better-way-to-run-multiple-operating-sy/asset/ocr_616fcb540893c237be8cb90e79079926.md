These Samba networking tips also presume you are using the Samba server included with VMware, which functions only over the host-only virtual network adapter. You need to do additional research to make Samba work over bridged networking.

> The Samba Linux HOWTO is located at http://www.linuxdoc.org/HOWTO/SMB-HOWTO.html. It will help you if you need to set up Samba over bridged networking.

# Configuring the VMware Samba Server

When you configured VMware, you should have installed the host-only Samba server when asked. (If not, reconfigure VMware with the vmware-config.pl command.)

The file /etc/vmware/vmnet1/smb/smb.conf contains the configuration data for the VMware Samba server. It is not the same as /etc/smb.conf, which might already be on your system even if you do not have another Samba server running.

In particular, you need to pay attention to these aspects of the /etc/vmware/vmnet1/smb/smb.conf file:

+   - Take note of the workgroup ID, early in the file. By default, this is set to WORKGROUP.
+   - Set up a drive to share. (It appears at the bottom of the file under the [HostFS] heading.) By default, the entire file system is shared.
+   - Ensure that the server is set to be local master = yes.

You also need to run the vmware-smbpasswd command to establish at least one Samba password for an existing user account on the host computer.

The format for the vmware-smbpasswd command is

```
vmware-smbpasswd vmnet1 <username> <password>
```

<username> is an existing user on the host, and <password> may or may not be your current login password. It is possible, depending on your system configuration, that you might need to change vmnet1 to vmnet2 or vmnet3; a quick look at /sbin/ifconfig will tell you which your system is using.

Until you run vmware-smbpasswd, you will not be able to access host drives via Samba.
