By now, I have made it abundantly clear that DirectX-loving games will not work in a Windows virtual machine. Unfortunately, that does not necessarily mean that all non-DirectX games will be "load and go." A number of non-DirectX games require very specific screen modes: often 640x480 at 256 colors. This is by no means a challenge for the VMware video driver (and almost certainly not a challenge for your video card), but it is a problem if you are running your Linux system in 16- or 24-bit color, which many, if not most, Linux users do.

A Windows virtual machine cannot change the color depth of your XWindows desktop, so if you plan to play a game that requires 640x480x256, you need to start XWindows at 8-bit color depth before you try to play the game.

Depending on the settings you used when you installed Linux, you might have 8-bit color modes available. Exit XWindows to the Linux console, and try to re-launch X using the command

```
startx -- -bpp 8
```

If you have 8-bit screen modes available, you should start in a 256-color XWindows desktop, and the Windows virtual machine should have no trouble switching to the right screen mode. You might see a minor error message when VMware launches, and the customary VMware configuration window backdrop will not appear, but VMware works perfectly well in 256 colors.

If X does not start in 256 colors, you might not have any 8-bit screen modes configured. If you like, you can use the X configuration tool of your choice, such as XF86Config or Xconfigurator, and add a few 8-bit modes. (It is probably a good idea to include 640x480, as well as your normal high-resolution mode.)
