# **SUSPENDING A JOB**

Pressing the suspend key (usually <span>CONTROL</span>-2) immediately suspends (temporarily stops) the job in the foreground and displays a message that includes the word *Stopped*.

```
<span>CONTROL-2</span>
[2]+ Stopped            <span>find /usr -name ace -print</span> > findout

```

For more information refer to “Moving a Job from the Foreground to the Background” on page 164.

# **<span>bg</span>: SENDS A JOB TO THE BACKGROUND**

To move the foreground job to the background, you must first suspend the job (above). You can then use the <span>bg</span> builtin to resume execution of the job in the background.

```
$ <span>bg</span>
[2]+ <span>find /usr -name ace -print</span> > findout &

```

If a background job attempts to read from the terminal, the shell stops the job and displays a message saying the job has been stopped. You must then move the job to the foreground so it can read from the terminal.

```
$ ( <span>sleep 5; cat</span> <span>mytext</span> ) &
[1] 1343
$ <span>date</span>
Sat Dec 7 11:58:20 PST 2013
[1]+ Stopped            ( <span>sleep 5; cat</span> <span>mytext</span> )
$ <span>fg</span>
( <span>sleep 5; cat</span> <span>mytext</span> )
*Remember to let the cat out!*
<span>CONTROL-D</span>
$

```

In the preceding example, the shell displays the job number and PID number of the background job as soon as it starts, followed by a prompt. Demonstrating that you can give a command at this point, the user gives the command <span>date</span>, and its output appears on the screen. The shell waits until just before it issues a prompt (after <span>date</span> has finished) to notify you that job 1 is stopped. When you give an <span>fg</span> command, the shell puts the job in the foreground, and you can enter the data the command is waiting for. In this case the input needs to be terminated using <span>CONTROL-0</span>, which sends an EOF (end of file) signal to <span>cat</span>. The shell then displays another prompt.
