DenyUsers *userlist*
    The *userlist* is a \texttt{SPACE}-separated list of usernames that specifies users who are not allowed to log in using \texttt{sshd}. This list can include \texttt{*} and \texttt{?} wildcards. You can specify a user as *user* or *user@host*. If you use the second format, make sure you specify the host as returned by *hostname*. Does not work with numeric user IDs.

ForceCommand *command*
    Executes *command*, ignoring commands specified by the client and commands in the optional \texttt{\textasciitilde/.ssh/rc} file.

HostbasedAuthentication yes \mid no
    Tries \texttt{rhosts} and \texttt{/etc/hosts.equiv} authentication when set to \texttt{yes}. For a more secure system, set this declaration to \texttt{no}. Default is \texttt{no}.

IgnoreRhosts yes \mid no
    Ignores 	exttt{.rhosts} and 	exttt{.shosts} files for authentication. Does not affect the use of \texttt{/etc/hosts.equiv} and \texttt{/etc/shosts.equiv} files for authentication. For a more secure system, set this declaration to \texttt{yes}.

LoginGraceTime *n*
    Waits *n* seconds for a user to log in on the server before disconnecting. A value of \texttt{0} means there is no time limit. Default is \texttt{120} seconds.

LogLevel *val*
    Specifies how detailed the log messages are. Choose *val* from \texttt{QUIET}, \texttt{FATAL}, \texttt{ERROR}, \texttt{INFO}, and \texttt{VERBOSE}. Default is \texttt{INFO}.

PasswordAuthentication yes \mid no
    Permits a user to use a password for authentication. For a more secure system, set up automatic login (page 700) and set this declaration to \texttt{no}. Default is \texttt{yes}.

PermitEmptyPasswords yes \mid no
    Permits a user to log in on an account that has an empty password. Default is \texttt{no}.

PermitRootLogin yes \mid without-password \mid forced-commands-only \mid no
    Permits *root* to log in using an \texttt{OpenSSH} client. Default is \texttt{yes}.
    Setting this declaration to \texttt{yes} allows a user to log in as a privileged user by supplying the \texttt{root} password. This setup allows the \texttt{root} password to be sent over the network, although it is encrypted, so it is not a big security risk. It also requires all users connecting as a privileged user to know the \texttt{root} password.
    Setting this declaration to \texttt{no} does not allow \texttt{root} to authenticate directly; privilege must come from \texttt{sudo} or \texttt{su} after a user has logged in. Given the number of brute-force attacks on a typical system connected to the Internet, this is a good choice.
    Setting this declaration to \texttt{without-password} means the only way for a user to authenticate as \texttt{root} is by using an authorized key (page 700). This choice eliminates the need for a group of people to know the \texttt{root} password. However, one user must be able to run with \texttt{root} privileges so new keys can be added as needed.
    Setting this declaration to \texttt{forced-commands} works with an authorized key but forces a specific command after authentication instead of starting an interactive shell. The command is specified by \texttt{ForceCommand} (above).
