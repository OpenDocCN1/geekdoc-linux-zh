
The `o` attribute name is an abbreviation for `organizationName`.

The next file adds to the LDAP directory the object class `organizationalUnit` named `employees` (`ou=employees`). The DN is `ou=employees` followed by the DSE:

```
$ cat BB.ldif
dn: ou=employees,dc=brillserv,dc=com
changetype: add
objectClass: organizationalUnit
ou: employees
```

```
$ ldapmodify -x "cn=ldapadmin,dc=brillserv,dc=com" -w porcshine -f BB.ldif
adding new entry "ou=employees,dc=brillserv,dc=com"
```

With this object class in place, you can add employees to the LDAP directory. The following file adds an employee:

```
$ cat CC.ldif
dn: cn=Zach Brill,ou=employees,dc=brillserv,dc=com
changetype: add
cn: Zach Brill
cn: brillserv
objectClass: inetOrgPerson
mail: zbrill@brillserv.com
givenName: Zach
surname: Brill
displayName: Zach Brill
telephoneNumber: 999 999 9999
homePhone: 000 000 0000
initials: ZCB
```

```
$ ldapmodify -x "cn=ldapadmin,dc=brillserv,dc=com" -w porcshine -f CC.ldif
adding new entry "cn=Zach Brill,ou=employees,dc=brillserv,dc=com"
```

Now `ldapsearch` shows the employee you just added:

```
$ ldapsearch -x -LLL -b dc=brillserv,dc=com
dn: dc=brillserv,dc=com
objectClass: dcObject
...
dn: cn=Zach Brill,ou=employees,dc=brillserv,dc=com
cn: Zach Brill
cn: brillserv
objectClass: inetOrgPerson
mail: zbrill@brillserv.com
givenName: Zach
sn: Brill
displayName: Zach Brill
telephoneNumber: 999 999 9999
homePhone: 000 000 0000
initials: ZCB
```

The DN shows that the new employee is at the third level of the directory structure: The first level is `dc=brillserv,dc=com`; `ou=employees,dc=brillserv,dc=com` is at the second level; and `cn=Zach Brill,ou=employees,dc=brillserv,dc=com`, the employee, is at the third level.

The following example adds another employee at the third level:

```
$ cat DD.ldif
dn: cn=Sam the Great,ou=employees,dc=brillserv,dc=com
changetype: add
cn: Sam the Great
objectClass: inetOrgPerson
mail: sam@brillserv.com
givenName: Sam
surname: the Great
displayName: Sam the Great
telephoneNumber: 888 888 8888
homePhone: 111 111 1111
initials: SLS
```

```
$ ldapmodify -x "cn=ldapadmin,dc=brillserv,dc=com" -w porcshine -f DD.ldif
adding new entry "cn=Sam the Great,ou=employees,dc=brillserv,dc=com"
```

The next example uses the `ldapmodify` modify instruction to replace the `mail` attribute value and add a `title` attribute for the employee named Sam the Great. The hyphen on a line by itself separates multiple modifications in a single file. Because the file specifies Sam’s DN, the server knows which entry to modify.

```
$ cat EE.ldif
dn: cn=Sam the Great,ou=employees,dc=brillserv,dc=com
changetype: modify
replace: mail
mail: sls@brillserv.com
-
add: title
title: CTO
```

```
$ ldapmodify -x "cn=ldapadmin,dc=brillserv,dc=com" -w porcshine -f EE.ldif
modifying entry "cn=Sam the Great,ou=employees,dc=brillserv,dc=com"
```

You can use `ldapsearch` to verify the change. The final example deletes Sam from the LDAP directory:

```
$ cat FF.ldif
dn: cn=Sam the Great,ou=employees,dc=brillserv,dc=com
changetype: delete
```

```
$ ldapmodify -x "cn=ldapadmin,dc=brillserv,dc=com" -w porcshine -f FF.ldif
deleting entry "cn=Sam the Great,ou=employees,dc=brillserv,dc=com"
```

## CHAPTER SUMMARY

NIS (Network Information Service) simplifies the management of common administrative files by maintaining them in a central database and having clients contact the database server to retrieve information from the database. The network that NIS serves is called an NIS domain. Each NIS domain has one master server; larger networks might have slave servers.

NIS derives the information it offers from local configuration files, such as `/etc/passwd` and `/etc/hosts`. These files are called source files or master files. Before NIS can store the information contained in a source file, it must be converted to dbm-format files, called maps. The `ypcat` and `ypmatch` utilities display information from NIS maps.
