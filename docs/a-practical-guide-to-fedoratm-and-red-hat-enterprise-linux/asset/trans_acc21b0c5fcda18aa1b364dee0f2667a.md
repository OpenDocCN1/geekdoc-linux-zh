*文件系统* 是一组通常驻留在磁盘部分上的*数据结构*（第 1245 页），它保存着文件的目录。文件系统存储用户和系统数据，这些数据是用户在系统上工作以及系统存在的基础。本章讨论了 Linux 文件系统的组织和术语，定义了普通文件和目录文件，并解释了命名规则。它还展示了如何创建和删除目录，如何在文件系统中移动，以及如何使用绝对和相对路径名访问各个目录中的文件。它包括对重要文件和目录的讨论，以及文件访问权限和 ACL（访问控制列表），后者允许你与指定的用户共享选定的文件。最后，它讨论了硬链接和符号链接，这些链接可以使单个文件出现在多个目录中。

除了阅读本章，你还可以参考 *df info* 页面以及 *fsck*、*mkfs* 和 *tune2fs man* 页面以获取更多有关文件系统的信息。有关其他重要的 Linux 文件的信息，请参见第 502 页的“重要文件和目录”。

## 分层文件系统

家族树：*分层*（第 1253 页）结构通常呈金字塔形。这种结构的一个例子可以通过追溯家族的谱系找到：一对夫妇有一个孩子，而这个孩子可能又会有几个孩子，其中每个又可能有更多的孩子。这种分层结构被称为*家族树*（图 6-1）。

目录树：与其相似的家族树一样，Linux 文件系统被称为*树*。它由一组相互连接的文件组成。这种结构允许你组织文件，以便轻松找到任何特定的文件。在标准的 Linux 系统中，每个用户从一个目录开始，每个用户都可以在任何想要的级别上添加子目录。通过创建多级子目录，用户可以按需扩展结构。

- 子目录
- 通常每个子目录都专门用于单个主题，例如一个人、项目或事件。该主题决定了是否应进一步细分子目录。例如，图 6-2 显示了一个名为 **correspond** 的秘书子目录。该目录包含三个子目录：**business**、**memos** 和 **personal**。**business** 目录包含存储秘书输入的每封信的文件。如果你预期有很多信件要发给同一个客户，正如 **milk_co** 的情况，你可以为该客户专门分配一个子目录。

Linux 文件系统的一个主要优点是其适应用户需求的能力。通过策略性地组织你的文件，使其对你最方便和有用，你可以利用这一优势。

## 普通文件和目录文件

与家族树一样，表示文件系统的树通常以倒置的方式描绘，其*根*在顶部。图 6-2 和 6-3（下一页）显示树从根向下“生长”，通过路径将根连接到其他每个路径。每个路径的末端是一个普通文件或目录文件。特殊文件，也可以出现在路径末端，将在第 515 页描述。*普通文件*，或简称*文件*，出现在不能支持其他路径的路径末端。*目录文件*，也称为*目录*或*文件夹*，是其他路径分支的节点。（图 6-2 和 6-3 显示了一些空目录。）当你引用树时，*上*是指向*根*的方向，*下*是远离根的方向。由路径直接连接的目录称为*父级*（靠近根）和*子级*（远离根）。*路径名*是一系列名称，沿着分支从一个文件追踪到另一个文件。有关路径名的更多信息，请参见第 181 页。

## 文件名

每个文件都有一个*文件名*。文件名的最大长度因文件系统类型而异；Linux 支持几种类型的文件系统。尽管当今大多数文件系统允许文件名长达 255 个字符，但某些文件系统将文件名限制在较少的字符数。虽然你可以在文件名中使用几乎任何字符，但如果你从以下列表中字符中选择，可以避免混淆：

- 大写字母（A–Z）
- 小写字母（a–z）
- 数字（0–9）
- 下划线 (_)
- 句号 (.)
- 逗号 (,)

就像同一个父母的孩子一样，同一目录中的两个文件不能拥有相同的名称。（父母给他们的孩子取不同的名字，因为这很合理，但 Linux 要求如此。）不同目录中的文件，就像不同父母的孩子一样，可以拥有相同的名称。

你选择的文件名应该具有意义。目录中经常填充着重要文件，却拥有如此无帮助的名称，如 **hold1**、**wombat** 和 **junk**，更不用说 **foo** 和 **foobar** 了。这些名称是糟糕的选择，因为它们不能帮助你回忆存储在文件中的内容。以下文件名符合建议的语法*并且*传达有关文件内容的信息：

- correspond
- january
