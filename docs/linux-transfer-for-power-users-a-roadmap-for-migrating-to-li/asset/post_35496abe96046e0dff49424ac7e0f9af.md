
Windows, on the other hand, does it differently. It ties a file’s file-name extension to a specific application, and stores that relationship in the Windows Registry. As a result, simply changing the extension of a file can break the file association. However, this also means that the user has more control over changing file associations.

Linux, as of kernel 2.2 (many moons ago), has the same general functionality, but implements it slightly differently, using what we might say is the best of both worlds. Linux now supports multiple file formats that can be run at a command prompt, similar to an executable file. For example, you could associate all text files with a specific editor. Typing just the name of a text file would then automatically load that editor and then open the text file in the editor.

You can see how file associations are handled by opening up your favorite file manager and right-clicking a file, as shown in **Figure 16**.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_176_0.png)

Figure 16. Right-clicking a file in a file manager displays the primary file associations for that type of file.

In the Open With context menu, you’ll find the applications that have automatically been associated with the type of file that application. In Figure 16, the file is an image file (with an extension of .tif), and so the default image-viewing applications were listed. The first application in the list will be used automatically if you simply double-click the file or select any of the Open options at the top of the context menu.

The file association isn’t keyed on the extension, though. In **Figure 17**, I’ve displayed the context menu and the Open with submenu for a file without an extension.

As you can see, Konqueror has already identified (“detected”) as a “Plain Text” file with a file size of 9 bytes. (I spare no expense when creating examples!) There are a number of associated programs in the context menu, including gedit (GNOME’s g graphical text editor), KWrite (KDE’s text editor for programmers), and Emacs (one of the classic Linux text editors), to name a few.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_177_0.png)

Figure 17. The Open With submenu for a file without an extension.

What's interesting is that it's not just text files that don't need extensions. If you delete the “.tif” extension from Copper.tif and then right-click, the same options under the Open With submenu will be displayed. How is this possible?

As I mentioned earlier, Linux uses a combination of Windows and Macintosh mechanisms to deal with file associations. Each file on a Linux computer has two attributes: a file type and a file extension. (If the file extension isn't there, then it's an empty file extension.) The file type can be something simple, like “Text Document” or “QuickTime Movie,” or it can be something somewhat more obscure, like “H.323 Internet Telephony” or “InterTrust DigFile.”

The first few bytes of most files contain special encoding that specify the type of file, regardless of the extension. That's why you can delete the extension from “Copper.tif” and the file associations still show up. “Copper.” is identified as a tiff file, and thus the applications for tiff files are still displayed.

However, if you change the extension of “Copper.tif” to “.xls”, right-clicking the file will display file associations for .xls files, including Microsoft Excel and OpenOffice.org's Calc.

Now, what if I wanted to open Copper.tif with The GIMP? How would I add that file association? Or what if I wanted the default application to be ImageView instead of Kuickshow?

In Konqueror, select Settings | Configure Konqueror from the menu, then click the File Associations icon in the left pane to open the “Configure file associations” tab. I suggest you widen the window, as shown in Figure 18, because a lot of info appears in the right pane.

The file types mentioned a moment ago are all listed in the Known Types treeview on the left side of the tab. They're organized into functional groups, such as image, text, and video. It can be tricky to find which file type you're looking for, because some of the functional groups aren't obvious if you're not already familiar with them.

# Migration of data from Windows to Linux

This whole chapter has covered various topics relating to data, because, as I said, it’s your data. I haven’t addressed one topic yet—a subtle, yet important one. What about your existing data? After all, as a power user, you’re not going to fire up a Linux computer and just start fresh. You’ve got loads and loads of data already (“out there”—how do you get that data “into Linux,” for lack of a better phrase?).

The good news is that, generally, you don’t have to do a thing!

There are two levels of working with your existing Windows data on a Linux computer. The first is getting the files themselves onto or accessible by your Linux computer. The second is actually opening or working with your files once they’re accessible—that means using Linux programs to open your “Windows” data.
