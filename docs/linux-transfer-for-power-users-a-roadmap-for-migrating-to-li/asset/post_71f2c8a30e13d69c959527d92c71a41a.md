
## PDF viewers

Adobe Acrobat’s PDF (Portable Document Format) file format has become a *de facto* standard in the world of exchanging read-only documents. With hidden information problems that can accompany Microsoft Word coming to light over the past year, people have been turning to PDFs as a means of providing information in a safe, non-alterable format.

I’ve already mentioned that OpenOffice.org has a built-in PDF-creation capability that’s accessed by a button on the main toolbar. But that’s for *creating* PDFs. Once you *have* a PDF, how do you read it?

Fedora Core ships with not one, not two, but four different PDF viewers. Although the PDF file format has been published so that third parties (like OpenOffice.org) can create PDF files as well as read them, the format continues to evolve; as of this writing, version 6 is the most recent. And even earlier versions have a variety of features that may not work in a specific reader. In addition, not all of the readers that come with Fedora Core have been kept up to date.

As a result, different readers may have better luck with different PDF files. If you have trouble with one PDF viewer, you may want to try a different one for better results.

The four viewers are Ghostview, Kghostview (KDE’s PDF viewer based on Ghostview), xpdf, and GNOME PDF Viewer, which is based on xpdf. The Ghostview viewers that ship with Fedora Core are a little long in the tooth and often don’t display recent PDFs correctly, if they can open them at all.

The xpdf-based viewers are much more robust, handling PDFs created with Adobe Acrobat and OpenOffice.org perfectly. **Figure 15** shows GNOME PDF Viewer with a 300-page PDF created with Adobe Acrobat, while **Figure 16** shows xpdf displaying a PDF created with OpenOffice.org running on Linux.

## Preference applets

The Preferences menu has a number of handy applets that help you customize your system. Here are four that I find useful: Control Center and Keyboard Shortcuts (under the Preferences menu) and CD Database, and Sessions (under the More Preferences menu).

The Control Center (see Figure 17) is somewhat similar to the Windows Control Panel; it provides a one-window point of access for user preferences. If you're spending a bunch of time tuning your preferences, use this window instead of opening the Main Menu over and over.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_246_0.png)

**Figure 17. The Control Center provides one-stop shopping for all user preferences.**

The Keyboard Shortcuts applet is great. With it, you can configure a variety of keyboard shortcuts for specific Desktop and Window Management actions, as shown in Figure 18. For example, scroll through the Window Management actions until you get to the “Switch to workspace 1” action, which is undefined by default. Simply press the keyboard shortcut you want to use for this action; I use <Control>-1 and <Control>-2 for switching between the two workspaces I have defined on my desktop.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_246_1.png)

**Figure 18. With the Keyboard Shortcuts applet, you can define your own accelerators for actions you perform often.**

The CD Database applet, shown in Figure 19, allows you to point your machine to a database for fetching song information that is used by Grip and other CD rippers. (See the Config | DiscDB | Primary Server tab to see where it's used.)

The fourth applet is the Sessions preference tool. It allows you to specify which applications to start when you start a session, and whether or not you want to save and restore the state of the currently open applications on your desktop the next time you start up.

The Session Options tab, shown in **Figure 20**, has several useful options. The first is “Prompt on logout,” which means that you’ll be greeted with a confirmation dialog when you end a session. This dialog has a “Save current setup” check box that allows you to manually save the current session’s settings, subject to the “Automatically save changes to session” option discussed next.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_247_0.png)

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_247_1.png)

Another option on the Session Options tab, "Automatically save changes to session," saves the state of the session when you log out, without you needing to do anything. If this option is selected, the "Save current setup" option on the logout confirmation dialog isn't displayed. The Current Session tab, shown in **Figure 21**, allows you to specify the order in which various applications are started, as well as additional properties. This is an advanced tab and you probably don't want to mess with it while you're getting started.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_248_0.png)

The Startup Programs tab, shown in **Figure 22**, allows you to list what programs are started up automatically. Figure 22 shows what the list looks like after The GIMP has been added. The one downside of this dialog is that you aren't given a friendly navigation tree through the Main Menu, as with other tools. Instead, you have to know the name of the program you want to add, and then navigate to its location (probably in /usr/bin.)

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_248_1.png)

## System Tools applets

The Preferences menu isn’t the only place where Fedora Core keeps its goodies. The System Tools menu has several as well.

The Hardware Browser allows you to look through the hardware on your system. To do so, select Main Menu | System Tools | Hardware Browser. You’ll be asked for the root password, and then the Hardware Browser dialog will appear with a list of hardware and drivers. Some screens have additional information. The Hard Drives screen also shows you the amount of disk space used, as shown in Figure 23.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_249_0.png)

When posting a query for help on various electronic forums and lists, one frequent suggestion is to “check the logs.” So where are these “logs” and how does one “check” them? The System Logs viewer, accessible via Main Menu | System Tools | System Logs (you’ll need to enter the root password) provides access to logs that are created by various applications on your system, as shown in Figure 24.

The System Logs viewer shows only the logs that exist on your system; if your system doesn’t have the same applications as mine, the logs available on your system may vary.

You can set your own preferences for the log files through the Edit | Preferences menu option in the System Logs viewer. The Log Files tab, as shown in Figure 25, allows you to point the System Logs viewer to a specific path and file name for each log. Suppose you have another application that generates log files. You can add those to the System Logs viewer by clicking the Add button in the Log Files tab of the Preferences dialog.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_250_0.png)

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_250_1.png)

When a log file becomes large, it can be easy to miss a line that points out a specific alert or warning. The Alerts and Warnings tabs of the Preferences dialog allow you to specify an icon beside log file lines that contain words or phrases of your choice. Thus, a line in a log that contains a specific user name or module name could be easily spotted.

Back in Chapter 5, I discussed the System Monitor that comes with GNOME. There is another system monitor that displays much of the same information, but in a different interface that’s pretty interesting. Find it under Main Menu | System Tools | More System Tools | GKrellM System Monitor; it looks like **Figure 26**.

Despite its miniscule size, the GKrellM monitor has a lot of information packed into it. It’s actually a combination of many monitors all stacked on top of each other, and you can choose which monitors you want to display. Right-click on the title bar (where it says “freedom” in Figure 26) or press F1 when the monitor window is active, and you’ll see the GKrellM Configuration screen, as shown in **Figure 27**.
