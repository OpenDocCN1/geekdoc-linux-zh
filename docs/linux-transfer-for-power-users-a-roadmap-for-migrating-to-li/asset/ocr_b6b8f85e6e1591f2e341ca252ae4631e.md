Once a track has been ripped, the bottom bar will scroll as the track is encoded. The ripping process creates a WAV file regardless of whether you're encoding the track as well. The default behavior of Grip is to delete the WAV file after it has been encoded to another format so your hard disk doesn't get filled up.

However, note that the WAV files are all ripped first. With a CD that's packed full of music (some can hold over 70 minutes), you might end up with 500 to 700 MB of temporary WAV files before they're all encoded into a different, smaller format.

If you create a WAV file, and then later decide to Rip+Encode the same track, Grip will use the WAV file already on disk instead of creating the WAV file all over again.

Grip acts as a front end to a number of ripping and encoding programs, and as a result, there are a lot of possible configuration options. Clicking the Config tab in the main Grip screen displays a set of seven subtabs, some of which have their own subtabs. All told, there are more than 60 options to choose from.
