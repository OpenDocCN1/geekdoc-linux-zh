
The first line in your script just cleared the window, the second echoed the “Hello World” string, and then you were returned to your command prompt.

Where to go next? It depends on what you want to do with a shell script. There are oodles of tutorials on the Web for advanced shell scripts that cover everything from automated backups to modifying your shell’s environment to grabbing and parsing mail files. As cliché as it sounds, your imagination is the only limitation.

## Creating cron jobs

Once you’ve gotten comfortable with shell scripts, you’ll find yourself wanting to run them, as well as other programs, on a regular basis. The mechanism for doing so is a Linux utility called “cron.” In Chapter 13, “Security,” I mentioned updating the virus scanner F-Prot signature files on a regular basis as an example of how to create a cron job.

The operating system has a number of programs called “daemons” (pronounced “DEE-monz” in some areas and “DAY-monz” in others) that run all the time. One of these is the cron daemon, crond. Its only job is to check with the system clock and, every minute, look at the contents of a table to determine if it needs to do anything. This table is a “crontab,” and every user on the system has their own, stored in /var/spool/cron.

The crontab is a simple text file that contains the schedule of cron jobs to run. Unlike other configuration files that you may have looked at or edited, the crontab file is not to be edited directly. Instead, you use a special tool called “crontab” that handles the file. In addition, crontab must use the editor specified in your system variables.

To create or edit a crontab for a user, change to that user in the command window and then issue the command:

```
crontab -e
```

The default text editor for Fedora Core is vi, in which the crontab file will open. vi can be difficult to use at first, but it’s omnipresent in the Linux world, so it’s good to be familiar with the basics. I’ve included a two-minute tutorial on vi as a sidebar in this chapter.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_349_0.png)

```
export EDITOR=gedit
export VISUAL=gedit
```

> This command combines the variable assignment and the export command in one line. Why do you have to set both EDITOR and VISUAL environment variables? It’s a legacy from early versions of Unix, in which some programs depend on EDITOR and others look at VISUAL. We just have to live with it.

Each line in a crontab file represents a separate crontab entry, and performs a separate task. Each of these tasks is called a “cron job.”

Each line has at least six parts to it. Each part is separated by a space. The first five parts may not have any spaces in them, but the sixth can.

The sixth position contains the definition of the cron job—a command to be run—and the first five sections are values that determine when and how often to run the job (relative to the local computer’s system clock).

(If the computer running the cron jobs is down, the jobs scheduled during that downtime will simply be skipped; they will not be queued up and run once the computer comes back.)

Here is how the first five parts are laid out:

| Part | Field | Range |
| :--- | :--- | :--- |
| 1 | Minute | 0–59 |
| 2 | Hour | 0–23 (0 = midnight) |
| 3 | Day | 1–31 |
| 4 | Month | 1–12 |
| 5 | Weekday | 0–6 (0 = Sunday) |

An asterisk in place of a numeric value indicates that every instance of the value will be used. For example, using an asterisk in the fifth position means that the job will run seven days of the week, while an asterisk in the second position means that the job will run every hour of the day. You may want to think carefully before adding an asterisk to the first position.

There are some types of jobs that you may want to run more than once a day, but not as often as every hour. You can use more than one instance of a specific time period by including each desired time period, separated by a comma. For example, suppose you want to run a cron job four times a day, at 15 minutes past the hour. The first two parts of the cron job would look like this:

```
15 2,8,14,20
```

The job would run at 2:15 a.m., 8:15 a.m., 2:15 p.m., and 8:15 p.m.

### Using vi

vi has two modes: insert mode (when you’re typing) and command mode (when you’re issuing commands to do something such as save or quit). When you start up vi, you’re in command mode. Type ":" to initiate a command, followed by the letter of the command, and then press Enter. For example:

- Typing ":q" and pressing Enter will quit vi.
- Typing ":w" and pressing Enter will save your document.

To switch between insert and command mode:

- From command to insert: Type any of the following letters: i a o c s (uppercase or lowercase).
- From insert to command: Press Esc.

If you want to learn a bit more, check out the two-page tutorial here: http://www.tectututorials.com/tutorials/unix/vi.shtml

And for a longer, 20-page tutorial, see: http://www.eng.hawaii.edu/Tutor/vi/html#before

Once you save your crontab file, the cron jobs will be ready to run. You don’t have to run a program to start the cron process, although you should make sure that the cron daemon is started. (Select Main Menu | System Settings | Server Settings | Services and scroll down the list of services to make sure that “crond” is checked and running.)

The cron daemon will send an e-mail message to the user for whom the crontab was created, notifying the user that it ran (or failed to run) the job. So, back to the initial job: If you wanted to check for F-Prot updates twice a day, at 4:10 a.m. and 6:10 p.m., a cron job like the following would do the trick:

```
10 4,18 * * * /usr/local/f-prot/tools/check-updates.pl -cron
```

Note that you have to be logged in as root when creating this cron job because you need root file-system permissions to update the virus database.
