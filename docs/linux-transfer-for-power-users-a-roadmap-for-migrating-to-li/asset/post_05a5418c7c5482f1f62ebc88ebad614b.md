A playlist is simply a text file stored on your hard disk that contains identifying information about the list, as well as the list of tracks themselves. You can then load this text file for replaying later via any of the multitude of Load List options.

When you create a playlist, you are given the option to save it in M3U or PLS format. M3U format looks like this:

```
#EXTM3U
#EXTINF:301,B.B. King - Ain't Nobody's Business /home/whil/ogg/bb_king/live_at_san_quentin/aint_nobodys_bisnis...

#EXTINF:272,B.B. King - Into The Night /home/whil/ogg/bb_king/live_at_san_quentin/into_the_night.ogg
```

```
[playlist]
NumberofEntries=4
File1=/home/whil/ogg/acdc/live/dirty_deeds_done_dirt_cheap.ogg
File2=/home/whil/ogg/acdc/live/thunderstruck.ogg
File3=/home/whil/ogg/acdc/live/tnt.ogg
File4=/home/whil/ogg/acdc/live/we_who_rog

To dock either the Playlist Editor or Equalizer window, just drag it next to the Main window. Figure 15 shows the playlist docked to the right, while the equalizer is undocked.

XMMS has long been known for providing the ability to change the appearance of the interface through add-ins known as "skins." A skin is simply a file that changes the player's appearance by overlaying the windows and controls, and altering their colors, shapes, and locations. **Figure 20** shows the XMMS Main window with the "Aretic" and "Marble" skins applied, respectively.

So where do you get skins? Pop on over to www.xmms.org and click the Skins link on the left side. Scroll through the list (there are hundreds) and click Download for a few that you find attractive. Download them into /usr/share/xmms/Skins if you can get root permission on your machine, and then they'll be available to every user on the computer. If you just want them available to you, or if you don't have root permission, download them to the .xmms/Skins directory under your home folder, such as /home/whil/xmms/Skins. The "." in front of ".xmms" means that it's a hidden folder, so you'll have to display hidden folders in order to navigate all the way in.

## Video

Unfortunately, while working with audio files has matured on Linux, video hasn’t made the same progress. There are no GUI-based tools in the Fedora Core distribution. Rather silly, considering the Main Menu option says Sound and Video, eh?

There are a number of open-source tools (and a few proprietary ones as well) that provide various CD, DVD, and VCD playback capabilities. Unfortunately, they suffer from the same basic problem. Because they aren’t available on the FC distribution (for the same reason that Fedora Core doesn’t come with an MP3 codec—proprietary licensing restrictions), you have to install them in addition to the FC installation. That by itself isn’t the problem; rather, what makes them unusable for the regular Windows user who’s moving to Linux is that they all require a fair level of user involvement simply to install and configure. If you’re interested in some adventure and have more than the average amount of patience, here are a couple of players worth investigating.

- **xine** ([http://www.xinehq.de](http://www.xinehq.de)) is a free multimedia player that plays back CDs, DVDs, and VCDs; decodes formats including AVI, WMV, and MP3; and can display multimedia streamed over the Internet.

No binaries are available for Fedora Core, so xine requires you to download and install xine-lib, which requires you to download a number of tarballs (.ZIP files in Windows parlance), and then issue a series of export/configure/make commands for the various files. Once you’ve compiled xine, you’ll need to download and install a front end. Which front end you choose depends on what you’re going to use xine for—straight media players, or inside browsers or other file manager plugins.

- MPlayer ([http://www.mplayerhq.ru](http://www.mplayerhq.ru)) is another open-source tool that has developed quite a following; but, again, using it isn't as simple as just downloading a file and installing it. You need to figure out what files to download and then install them, taking care of all the dependencies as well as wrestling with the appropriate codecs (software that allows you to play selected types of files, such as MPG, QuickTime, Real, and so on).

A search on the Web will turn up a number of other tools. Be careful before throwing your lot in with one; some are rather old and haven't been maintained, while others have onerous licensing issues. And, of course, there's always the chance that you'll find the perfect tool, only to discover that Linus Torvalds himself couldn't install it successfully without losing handfuls of hair.

# Printers

Linux has gotten a bad rap for being hostile when dealing with hardware; in some cases, that reputation has been well justified. But great strides have been made in the last couple of years with Kudzu—the hardware-detection daemon from Red Hat—which automatically finds and configures new hardware attached to the system. Fedora Core is particularly friendly toward local printers.

I’m going to discuss attaching a local printer to your Fedora Core box in three stages. First, I’ll discuss how Kudzu works when you simply plug a new printer into your computer, and what you can expect. Then I’ll describe how to set up a print queue. Finally, I’ll show you how a print queue works with typical software on your machine.

What if you don’t let Kudzu configure your printer for you? As you’ll see, it doesn’t matter. You can configure your printer and add a print queue at the same time.

# Kudzu

If you plug a printer into your computer and then boot it up, the Kudzu daemon will typically detect that new hardware has been added (or removed) and offer to continue configuration for you. You can also skip the configuration at that time, and run Kudzu manually from a command prompt. You have to be logged in as root in order to run this command:

```
/usr/sbin/kudzu
```
