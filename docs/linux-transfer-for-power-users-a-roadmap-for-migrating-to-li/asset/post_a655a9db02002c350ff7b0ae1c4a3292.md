# Chapter 8
## Office and Productivity Applications

One of the two primary reasons most people use a computer (the first was discussed in Chapter 7) is to create and manage documents by using "office and productivity applications." These apps include a word processor, a spreadsheet, perhaps presentation software, a note taker, and financial-management software. In this chapter, I’ll give you a quick tour through the most popular office and productivity applications available natively on your Fedora Core system.

Everyone knows that Linux is a fine operating system for a variety of needs in the server room—Web servers, file servers, print servers, e-mail servers, DNS servers, and so on. But the experts have said for years that Linux could never make inroads on the desktop. The primary reason: Linux lacked applications that could replace common end-user tools such as the Microsoft Office productivity suite and Intuit’s Quicken personal-finance software.

Well, that reason has evaporated. Microsoft Office is facing daunting competition from OpenOffice.org, an open-source software suite that goes head-to-head and often comes out ahead. GnuCash is a worthy replacement for Quicken and QuickBooks.

While this chapter can’t possibly do justice to these and other productivity tools, I can introduce them to you and show you that they’re prime-time contenders and worthy of your attention.

## Editors

Sometimes all you want to do is write a quick little note, and you don’t want to fire up a full-blown word processor to do so. Or you want to work with a simple text file, such as a script (see Chapter 14 for more on Shell scripts) or another type of program, or an HTML page. Or maybe you’ve received a mysterious e-mail that looks like spam or a virus, but you’re not sure. You don’t want to open it in your e-mail client and risk activating the virus or installing spyware or cookies if it ends up being an HTML message. So you can save the e-mail to a file and open that file safely with a text editor.

Another reason for using a simple text editor is to automatically remove unnecessary formatting from a chunk of text. For example, I often open an editing window as a temporary work area. I’ll grab a small chunk of something from another application, such as a word-processing file, Web page, or PDF file, so I can print it or pop it into an e-mail, but the data will be formatted with control codes, HTML formatting, or other extraneous and distracting information. That special formatting automatically disappears when I paste the block into a text-only editor, and then cut from the editor and paste it into another application’s file.

Windows comes with two basic editors: Notepad, which is still my tool of choice, even though it took Microsoft nearly a decade to add the keyboard shortcut “Ctrl-S” to save a file; and WordPad, which has more formatting features, but also can mess up your data because it can apply its own formatting to files.

Linux comes with a variety of text-file editors, as shown in **Figure 1**; indeed, the choice of editor is one of the most popular “religious wars” the Linux community engages in (next to the “which distribution” and “which desktop manager” arguments).

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_209_0.png)

**Figure 1. Fedora core provides a number of potential text-file editors through the context menu’s Open With command.**

Two general classes of editors come with Fedora core.

The first class includes classic Unix-style editors, such as emacs and vi, which are tools that have been used by programmers for ages. These editors are incredibly powerful, flexible, customizable, and ... can be rather difficult to learn, because they don’t rely on keystroke commands common to software that Windows users are accustomed to, such as Ctrl-S to save a file, Ctrl-C and Ctrl-V to copy and paste an object, and so on. If you’re a hard-core Windows programmer or administrator and want to delve deeply into the traditional Linux world, you may find yourself inextricably drawn to one of these tools. But for the regular Windows power user, these editors are simply too arcane for me to recommend them, and thus I won’t cover them here.

The second class includes the new graphical style of editors, much like Notepad and WordPad on Windows.

My personal preference is gedit, GNOME’s graphical editor, which you can open by clicking Main Menu | Accessories | Text Editor, as well as from the context menu when right-clicking a text file.

Although it’s a simple text editor, gedit works like a simple word processor. After starting up, an editing window appears, and the gedit menu above the typing area displays essential text-editing functions in a familiar fashion, as shown in **Figure 2**.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_210_0.png)

**Figure 2. The gedit menu has common functions arranged in a familiar manner.**

Open, Save, and Print are found under the File menu; Cut, Copy, Paste, and Preferences show up under Edit; configuration options (such as turning the toolbar and status line on and off) are found under View; a variety of search mechanisms are under Search; and the Documents menu acts similarly to the Window menu in many other GUI applications.

It has a number of basic, but useful, features that make it my tool of choice for day-to-day scribbling. In fact, I use gedit to quickly scratch out drafts of longer pieces when I don't want to be bothered by (that's polite talk for “distracted by”) all of the features of a full-blown word processor. One particularly useful feature is how gedit handles multiple files: Instead of opening multiple windows, it opens each file under a tab in the same main editing window, as shown in Figure 3.

Another handy feature is the asterisk that shows up to the right of the file name in the tab; this happens when the file has been edited and changes haven't been saved. I can never remember the last time I've hit Ctrl-S.
