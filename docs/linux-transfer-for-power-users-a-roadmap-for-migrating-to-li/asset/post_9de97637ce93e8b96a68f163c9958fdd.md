
# /bin

  /bin contains programs or symbolic links (think “shortcuts” in Windows) that are used by the system administrator, by regular users, and by scripts (think “batch files”). These programs differ from those in /sbin and /usr/bin in that they are required before the rest of the directories are available for use. (You might hear people refer to this requirement in Linux terms as “before any other file systems are mounted.”) If you were going to create a floppy disk to boot Linux, these the contents of /bin would be useful.

  Examples of programs in /bin include cp (a utility to copy files), mkdir (a utility to make a directory), sh (the Bourne command shell) and su (a utility to change the user ID).

# /boot

  /boot contains all of the files and data required for the machine to boot, in addition to configuration files not needed during boot-up.

# /dev

  /dev contains files that map to devices (get it?) that are attached to the computer.

# /etc

  The /etc folder stores configuration files for the operating system as well as programs on the computer. Some, but not all, configuration files have a “.conf” extension, but, in contrast with Windows, many Linux files do not have extensions at all. For example, the file “/etc/fstab” is a configuration file that contains the file system table (f.s. table—get it?). Another example is the file “/etc/gimp/1.2/gimpirc”—the configuration file for the GIMP (The GNU Image Manipulation Program). The corollary to Windows is the Windows Registry.

# /home

  The most important folder to you is /home, because it stores regular user data, including yours. It’s somewhat like “My Documents” on Windows. Each regular user (as opposed to the root, or administrative, user) on a Linux computer has their own folder under /home, and each user can only get to their own folder under /home when they log on. So, for example, if three regular users—Al, Barb, and Connie—are set up on a Linux computer, there will be three folders under /home, like so:

```
/home/al
/home/barb
/home/connie
```

  When Al logs on, he can get access to his own folder, but not to /home/barb or /home/connie.

  /home is like C:\Documents and Settings, because there’s a directory for each user underneath, and each user’s directory contains user-specific config files and (usually) users’ data.

# /initrd

  When Linux is booted up, a RAM disk that contains a subset of the operating system is created. The “initrd” file is stored in this RAM disk and acts as a temporary operating system that points the way for the rest of the computer to boot up. You should never have to worry about this directory, nor should you ever mess with it.

# /lib

  /lib contains library files used to boot the system as well as run commands located in /bin and /sbin. This is a centralized location for these files, somewhat like C:\winnt\system32.

# /lost+found

  This is where “lost” files and/or directories get dumped during a file-system check.

# /misc

  /misc is just what it sounds like—a location for miscellaneous items. You may never find a need for it yourself.

# /mnt

  /mnt is an empty directory provided for the temporary mounting of a file system. This is a fancy way of saying “this is where floppy disks and CD-ROM drives are found.” Current mainstream Linux distributions like Fedora Core automatically recognize when floppies and CDs are inserted into drives, and they place a drive icon on the desktop, as shown in **Figure 3.** Functions such as Open (to display the contents in the default graphical file manager) and Eject (to eject the CD from the drive) are available in the CD’s context menu.

# /opt

  /opt is reserved for applications programs installed by the user.

# /proc

  /proc is a virtual file system that stores a copy of the system currently in memory. This mechanism provides an easy way to get information about the kernel and currently running processes, instead of having to dig at the memory itself. You will likely never have to mess with this folder.

# /root

  The /root folder is simply the root user's home folder. It is not put in the /home folder for security reasons—you can have /home on a separate partition but still have the root user's home folder available before that partition is mounted.

# /sbin

  /sbin contains utilities used for system administration. Programs that are involved with booting the machine as well as repairing broken installations and recovering corrupt files are located here. There is also a /sbin directory under /usr, called /usr/sbin, that contains similar programs that are executed after /usr has been mounted during boot up.

# /tmp

  /tmp is reserved for programs that create or use temporary files, just like C:\temp (or C:\Documents and Settings<user>) in Windows. Note that the contents of /tmp are deleted during the boot process, so don’t ever expect something in /tmp to be there five minutes later.

# /usr

  /usr is roughly equivalent to “Program Files” in Windows. It has six major subdirectories.

  /usr/bin contains programs used by regular users of the system that are not in /bin. /usr/include and /usr/lib contain libraries that aren’t found in /lib. /usr/local is empty after initial installation, but eventually gets populated with programs installed by users. /usr/sbin has been covered in the /sbin description. /usr/share is used for data that isn’t modified once created. For example, a program that creates a key or other type of fingerprint file might put it in /usr/share/<program>.

# /var

  By now you’re probably getting used to the abbreviations—and so it comes as no surprise that /var is used for variable data files. Examples include mail and print spoolers, log files, lock files, temporary files saved during system reboots, and caches for specific applications.

# Which ones are important?

  These are brief descriptions of these folders. You can find more precise definitions and detailed information about subdirectories of these folders, at http://www.pathname.com/fhs.

  You’ll see that some distributions, such as Fedora Core, include other top-level directories, such as /libboot. Don’t worry about them.

  So now that we’ve been through the definitions, which ones are important? You can use Linux for a long time while dealing with only three directories: /home, /etc, and /usr. If pressed, you might be interested in /bin, /sbin, /tmp, and /var.

  If you’re using a different distribution, you’ll find many of these directories are the same as found in other distributions; in fact, the differences are fairly minor—much like the differences you find between the directory structures of Windows 95 and Windows NT, for example, where the directory “Windows” was changed to “WINNT” (and then back again in Windows XP, ahem!).

# About multiple drives

  During the conversation in the previous section, I quickly skipped past the “Where’s my C: drive?” issue and just talked about the folder structure under the “/” folder. If you’ve got a single hard disk, you can just assume that “/” sits on that hard drive much like “C:” would, and accept that you’ll find your floppy and CD-ROM drives under /mnt. But what if you’ve got more than one hard disk? What does the tree structure of folders look like in that case?

  The answer: Exactly the same!
