
**info**—displays the info page for external commands. Info pages are generally longer and more descriptive than "man" pages.

```
info grep
```

## Directory navigation and manipulation

`./`—references the current directory. Often used to run a program from the current directory.

```
./someprogram
```

`~`—references the logged-in user’s home directory (regardless of where you are; it’s shorthand for `/home/<username>`). To list the contents of the user’s home directory, regardless of your current location, use:

```
ls ~
```

`~<name>`—references the home directory of `<name>`. For example,

```
ls ~bob
```

will list /home/bob (assuming you’ve got permission to do so).

**ls**—lists directory contents, including permission and owner information.

```
ls -l
```

To include all hidden files (those beginning with “.”):

```
ls -a
```

**cd**—changes the working directory.

```
cd /etc/ppp
cd ~
```

**pwd**—prints the absolute path of the working directory.

```
pwd
```

returns “/home/whil”.

**mkdir**—creates a directory.

```
mkdir herman
```

**rmdir**—removes an empty directory.

```
rmdir herman
```

## File manipulation

cp—copies one or more files.

```
cp installation.pdf ~/newfiles

cp installation.pdf ~/newfiles/dummy.pdf

cp installation.pdf ~/xips/installation.pdf

cp *.pdf olderversions
```

mv—moves (renames) files. The following command moves ~/x.pdf to ~/temp/x.pdf:

```
mv x.pdf temp
```

And the following command renames ~/x.pdf to ~/y.pdf:

```
mv x.pdf y.pdf
```

rm—removes files. When used with “-r” (recursive), this command is dangerous. And if you use it with “-r” while you're running as root, it’s very dangerous. Experienced Linux users believe that the phrase “Oh S***!” was initially coined after someone who was logged in as root executed an errant “rm -r” command on a large server.

```
rm *.pdf

rm -R *.pdf
```

## Finding stuff

apropos—As you’re learning Linux, this is a great command because it helps you find other commands that you can’t quite remember. It produces a list of commands whose keywords contain the parameter entered after the command.

```
apropos concatenate
```

returns:

```
Tcl_Concat(3) - concatenate a collection of strings
Tcl_Concat(Concat)(3) - concatenate a collection of strings
cat(1) - concatenate files and print on the standard output
g3cat(1) - concatenate multiple g3 documents
ospent(1) - Concatenate entities
pncat(1) - concatenate portable anymaps
strcat(3) - concatenate two strings
stconcat(stcat)(3) - concatenate two strings
tac(1) - concatenate and print files in reverse
wccat(3) - concatenate two wide-character strings
wcconcat(3) - concatenate two wide-character characters
```

find—finds files according to a large variety of information. The following command results in nothing:

```
find he
```

But the following command:

```
find he*
```

results in:

```
herman
herman/x.pdf
```

locate—finds the file name containing the string "x". That's anywhere in the string, not just at the beginning.

```
locate x
```

whereis—use this command to find utilities in standard locations.

```
whereis grep
grep: /bin/grep /usr/share/man/man1/grep.1.gz
```

whatis—provides a one-line summary of a command.

```
whatis grep
grep       (1) - print lines matching a pattern
```

which—used to find utilities in a search path, and returns the absolute path of the utility.

```
which ls
alias ls='ls --color=tty'
/bin/ls
```

## Working with files

grep—finds a string within a file. The following command does a case-insensitive search:

```
grep -i pattern files
```

The following command returns all files with the word "hello" in any case in the local files:

```
grep -i HELLO *
```

The following command does a case-sensitive search and displays the file name and line number in the output:

```
grep -n pattern files
```

less—displays text file, one screen at a time. Can go forward and backward.

```
ls | less
```

## Permissions

**chmod**—sets permissions of files/directories.

```
chmod 755 my_file.txt
```

**chown**—changes ownership of a file. (You must be a superuser to perform this command.) To change the owner of my_file.txt from the current owner to “bob”:

```
chown bob my_file.txt
```

You can find a great discussion of permissions here: http://www.start-linux.com/articles/article_161.php.

This list of commands is still very long. I suggest that you learn them one batch at a time. For example, write no more than a half-dozen of them on a sticky note, and stick it to your monitor. Use the commands every chance you get, until you become comfortable with them. Then put a second sticky note—on top of the first—with another batch of commands, and repeat the process. I recommend sticking one note on top of the other (instead of replacing the first one) because you’re likely going to forget a couple from the first list, and it’ll be handy to have them immediately available.

Once you’re comfortable with this entire set, you can explore further with advanced resources. Remember that the Linux shell is an extremely powerful tool. Some commands, such as “ls” and “locate,” have huge numbers of switches that can be used with them, while others are even more sophisticated. Individual Linux commands such as “sed”, “awk”, and “grep” have entire books dedicated just to them!

## Shell scripts (Just batch files)

A shell is interactive. You type something at the command prompt and it responds. You type something else; it responds again. A shell script is a series of one or more commands in a text file that can be executed one after another automatically, instead of having to execute each one in turn. Windows users know shell scripts as batch files.

There are several reasons to use shell scripts. First, a shell script doesn’t have to have multiple commands. A command can be long and involved, with many tricky parameters and exacting spelling requirements. Using a shell script that holds a single complex command can ensure that you don’t mistype.

Second, a shell script can contain multiple commands, which can automate typing multiple commands. Third, you can run a shell script automatically, at a specified time, or during startup or shutdown of the machine.

To create a shell script, use a text editor such as gedit (or vi or emacs, if you want to go the way of hard-core Linux users). Open the editor and type your commands, one command per line. Use the pound sign (\#) to indicate a comment.

```
#!/bin/bash
# My first shell script
clear
echo "Hello World!"
```

The first command, although marked as a comment, is a special type of comment. The “!” after the “\#” indicates that you’re identifying which shell program should execute this script, and the rest of the line points to the shell. Technically, this often isn’t necessary, because the default shell for Fedora Core is bash. But, just as it’s good programming practice to include an “otherwise” clause in a “case” structure, it’s a good idea to include the line for that one-in-a-hundred case that someone (or something) tries to run this script with another shell.

Second, save your script as “m1ss” (my first shell script) in your home directory for purposes of this example.

Third, open a command window and issue the following command:

```
chmod 755 m1ss
```

This changes the permissions on the file so that it can be executed. Originally, the permissions are:

```
-rw-rw-r--
```

The “chmod 755” command sets read/write/execute permission for the owner, read/execute permission for the group, and read/execute permission for others, like so:

```
-rwxr-xr-x
```

Finally, execute your shell script by typing this:

```
./m1ss
```

Remember, your current directory is not in your path, so you have to explicitly point to your current directory in order to run a program in it. If you just type this:

```
m1ss
```

you’ll get a response from the shell that says something like:

```
bash: m1ss: command not found
```

Assuming you’ve typed everything properly, your command window will look like this:

```
Hello World
[which@freedoom ~] Dude?
```
