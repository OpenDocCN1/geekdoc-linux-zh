What's interesting is that it's not just text files that don't need extensions. If you delete the “.tif” extension from Copper.tif and then right-click, the same options under the Open With submenu will be displayed. How is this possible?

As I mentioned earlier, Linux uses a combination of Windows and Macintosh mechanisms to deal with file associations. Each file on a Linux computer has two attributes: a file type and a file extension. (If the file extension isn't there, then it's an empty file extension.) The file type can be something simple, like “Text Document” or “QuickTime Movie,” or it can be something somewhat more obscure, like “H.323 Internet Telephony” or “InterTrust DigFile.”

The first few bytes of most files contain special encoding that specify the type of file, regardless of the extension. That's why you can delete the extension from “Copper.tif” and the file associations still show up. “Copper.” is identified as a tiff file, and thus the applications for tiff files are still displayed.

However, if you change the extension of “Copper.tif” to “.xls”, right-clicking the file will display file associations for .xls files, including Microsoft Excel and OpenOffice.org's Calc.

Now, what if I wanted to open Copper.tif with The GIMP? How would I add that file association? Or what if I wanted the default application to be ImageView instead of Kuickshow?

In Konqueror, select Settings | Configure Konqueror from the menu, then click the File Associations icon in the left pane to open the “Configure file associations” tab. I suggest you widen the window, as shown in Figure 18, because a lot of info appears in the right pane.

The file types mentioned a moment ago are all listed in the Known Types treeview on the left side of the tab. They're organized into functional groups, such as image, text, and video. It can be tricky to find which file type you're looking for, because some of the functional groups aren't obvious if you're not already familiar with them.
