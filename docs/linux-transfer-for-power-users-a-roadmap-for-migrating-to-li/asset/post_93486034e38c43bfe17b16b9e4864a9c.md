## OpenOffice.org

Until about two years ago, the major impediment to considering Linux as a desktop operating system was probably the lack of a replacement for Microsoft Office. With the introduction of OpenOffice.org 1.0 at that time, this hurdle was removed.

OpenOffice.org (or "OOo," as it's known) has quickly become the standard open-source office suite around the world (and I don't just say that because we publish several OOO books ourselves!). It's part of every popular Linux distribution, and has the backing of Sun Microsystems, which funded OOO's predecessor, StarOffice, and still provides a great deal of programming support.

The OOO suite consists of several major applications, including a word processor (Writer), a spreadsheet (Calc), and a presentation manager (Impress). In addition, OOO has a drawing package (Draw), a formula editor (Math), and an extremely powerful macro editor and database-access capability. Because there are a number of excellent e-mail clients available on various platforms, Ooo doesn't include an e-mail client of its own.

With text editors, it'd be impossible to cover Ooo thoroughly in just this chapter. Indeed, there are a number of books dedicated just to Ooo. Solweig Haugland's 1040-page *OpenOffice.org Resource Guide* (Prentice-Hall) is the ultimate exhaustive resource for using OpenOffice.org, while Tamar Granor's *OooSwitch: 501 Things You Wanted to Know About Switching to OpenOffice.org from Microsoft Office* (Hentzenwerke Publishing) addresses Ooo in detail from the perspective of an experienced Office user.

However, I can give you a brief tour and point out some of the highlights. There are several key benefits to using Ooo that you need to know right away.

First, Ooo is completely cross-platform. And that means truly cross-platform—it works on Windows, Linux, and Macintosh—like Microsoft, which uses the term "cross-platform" to mean Windows ME and Windows XP. Because Ooo is cross-platform, you can use it on a Linux machine and on a Windows or Macintosh, and the software will read and write the same data files. This is a great feature when you've got a variety of operating systems in your organization, or different OSs at home and at work.

The second key feature is just that—data files. Ooo can save files in two different formats—its own native, openly documented file format, as well as the proprietary Microsoft Office formats. And these file formats can be exchanged across platforms too. This means that you have a huge amount of flexibility.

For example, you can write a document in OpenOffice.org Writer on a Linux machine, save the file in OpenOffice.org's .sxw file format, and someone using OpenOffice.org on a Windows or Macintosh computer can open and edit that file. In addition, because the .sxw file format is well documented, other applications can open and reliably work with these documents as well.

The same applies to OpenOffice.org's other file formats—spreadsheets (.sxc), presentations (.sxi), and drawings (.sxd).

OpenOffice.org can also read and write files that were saved in Microsoft's proprietary file formats, so that OpenOffice.org users can exchange files with people using Microsoft Office. For example, you can create a presentation in OpenOffice.org Impress on either a Linux or Windows computer, and someone using Microsoft PowerPoint (on a Windows computer, of course) can open and edit that file.

At Hentzenwerke Publishing, we rely on both of these capabilities. Authors write their original drafts using the tool and platform of their choice—either Microsoft Word or OpenOffice.org, and either Windows or Linux. Chapters then go back and forth through technical editing, and the tech editors use whichever tool and platform they're most comfortable with. The same process is repeated with copy editing and layout; most of our copy editors and layout personnel use OpenOffice.org (on either platform), but occasionally we'll have a freelancer who uses Microsoft Word.

A third benefit to using OpenOffice.org is that you can generate a PDF directly from a Writer document, Calc spreadsheet, or Impress presentation. Starting with version 1.1, Ooo has an "Export to PDF" button on the Function toolbar that generates PDF files. These files are good enough that we at Hentzenwerke Publishing generate PDFs that are sent directly to our book printer electronically, and that don't require any manual pre-press work before printing the book.

A similar feature is the ability to export Impress presentations as Macromedia Flash (.swf) files, which you can then run inside a browser without having a separate runtime engine of any sort (except the Flash player plugin).

With these items in mind, let’s take a quick tour of OpenOffice.org.

## Configuration and options

As soon as you start creating documents, you’re going to want to perform operations—and some of these can be configured to your liking. So before I talk about working with documents, let’s spend a moment setting up OoO so that it behaves the way you want.

There are two places to bend OoO’s behavior to your will—one is under Tools | Options, where you can control how OoO functions. And it’s here that we’ll spend our time first.

As soon as you create a document, you’re going to want to save it. The default save path for OpenOffice.org documents is your home directory (for example, /home/whil on my machine).

If you’re on a network, you might want to change this path to a network drive. Regardless of whether you keep your save path intact, you’ll probably want to change a number of other settings immediately. Here are the ones I change every time I install OOO on a new machine.

First, and this is really important, you’ll want to set the default file format in which you’ll save new documents. During installation, OpenOffice.org asks you which file format (OpenOffice.org or Microsoft Office) should be default, but based on the questions on the OpenOffice.org mailing lists, a lot of people skip by that choice, only to be puzzled by OOO’s behavior later.

In the Options dialog, select the Load/Save node and the General subnode, as shown in **Figure 8**.

Direct your attention to the “standard file format” controls at the bottom of the General page. You need to specify the default file format for each document type—it’s not an all-or-nothing type of choice. Select “Text document” in the list and then choose which type of file format to save new text documents in, using the “Always save as” box. Be sure to read the choices in this box carefully, because some of them look similar, such as “OpenOffice.org Text Document” and “OpenOffice.org Text Document Template.”

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_215_0.png)

Once you’ve chosen the default file format for text documents, highlight the next item in the “Document type” list, change its file format in the “Always save as” box, and continue on for the rest of the document types.
