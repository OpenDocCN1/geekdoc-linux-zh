The **User Name** value is the text string that you'll use to log on, so don't make it too long or include a lot of weird characters in it. The **Full Name** value is simply used to identify who owns the User Name. The **Password** and **Confirm Password** values are for the user being added. The rest of the values can stay as-is. Click **OK** and the new user will be added to the User Manager window.

If you've just got one or a few users on the same computer, that's all you really need to do. You may be wondering, “Why bother with multiple users at all?” There are some advantages of having separate users. The first is that each user can customize the interface as she wants, including the programs and applications installed on the panel and desktop, as well as the visual components of the desktop manager.

Another advantage is that each user gets his or her own directory under the /home directory. In Figure 8, you can see the home directories for each user. For example, herman's home directory is /home/herman, while Igor's is /home/Igor. Access to this directory is restricted to the user; to prove it, create another user on your machine, and then log on as yourself and try saving a file in that other user's directory.

This means that you can make sure that each person's data is segregated. You won't have anyone accidentally (or maliciously) messing with someone else's data. This also means that the unknown user, such as an attacker that gains access to your machine, is restricted in the harm they can perform. If they take control of your machine due to an action that you perform (such as visiting an evil-laden Web site), they'll only have the same access that you do. If you were running as root, they'd have full run of your machine: yet another reason for not running as the root user during your day-to-day chores.

This discussion has centered on users, yet the section heading says “Users and groups.” What's a group and why should you care? A group is a collection of users who all have common attributes, needs, and requirements. The most common reason for creating a group is so that several users can share a set of files. Because each individual user's files are owned just by that user, one user can't generally access another user's files. There are ways around this, but those methods are awkward, inconvenient, and generally a bad idea.

The better solution is to create a “joint use” whose files can be accessed by others who have been given special permission. Another name for this “joint use” is a group. The fundamental idea is that you create a group, and then add users to that group. When users create files as part of that group, those files can then be accessed by anyone else who is a member of the group.

Specifically, here is how you would make this happen. Suppose Herman and Igor needed to share files. You would create a group, say, “theboys,” by opening the User Manager and selecting Add Group. Enter the name of the group, as shown in Figure 10. When you're done, the new group is listed on the Groups tab of the User Manager window, shown in Figure 11. You'll note that each user has its own group, or, if you think about it in a different way, every time you create a user, a group is created that contains one and only one member—that user. That's why each user is restricted to only its own files.

You'll also notice that the “theboys” group doesn't have any members yet. Select the group in the list and the Properties button will become enabled; click it to bring forward the Group Properties dialog. Select the Group Members tab in the Group Properties dialog, as shown in Figure 12, and you'll see a list of users who are eligible to join the group. Scroll down and select both Herman and Igor.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_321_0.png)

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_322_0.png)

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_322_1.png)

You’ll notice that a lot of items in the list are not users. The details of this are beyond the scope of the book, but the general idea is that individual processes (somewhat like programs) running on your computer can also be eligible to join a group so that they can have access to specific files or directories. In addition, this prevents a process from becoming a security hole if that service is somehow compromised.

After you select Herman and Igor, they’ll show up as group members in the User Manager window, as shown in Figure 13.

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_323_0.png)

Now what? Herman and Igor both have their own home directories, under /home. But what we want is a separate directory, called /home/theboys, that all members of the “theboys” group have access to, just like Herman has access to /home/herman and Igor has access to /home/igor. But no one except members of the “theboys” group will have access to /home/theboys.

Here’s how to make this happen. Open a command window and enter the following commands, as shown in Figure 14 and in the following listing:

```
$ su
Password:
# cd /home
# mkdir /home/theboys
# chown herman /home/theboys
# chgrp theboys /home/theboys
# chmod 770 /home/theboys
# chmod g+s /home/theboys
```

![](img/50a238d93c7edbdc4387d5ff7f6b7b3c_323_1.png)

For the time being, take the commands as a leap of faith; I’ll describe them in more detail in Chapter 14, “Under the Hood.” In short, after becoming root, you’re creating a directory called /home/theboys, assigning its ownership to herman (the original owner was root), and then mapping the directory and the group together.

If you look in a file manager such as Konqueror, you’ll see the owner and group for the new directory, as shown in Figure 15.

The only people who are allowed access to the directory “theboys” are members of the group “theboys”——currently only Herman and Igor. When they relent and make their little club friendlier by letting Sandra in, only two things have to be done. First, the user “sandra” needs to be added in the User Manager. Then Sandra needs to be added to the “theboys” group. Once those two tasks are accomplished, Sandra has access to files in the “theboys” group and can give them a difficult time about how poorly they named their group.

Note that the group name and directory name do not have to be the same; I just made them identical for the sake of convenience.

## Virus scanners

Everyone knows that there aren’t any viruses for Linux, right? Well, 600 years ago everyone knew that the world was flat, and 100 years ago everyone knew that heavier-than-air flight was impossible. Things change, and you can bet that sooner or later (and probably sooner), Linux will get hit with its first widespread virus.

Thus it behooves you to be prepared, and get used to having a virus scanner installed and running on your desktop system now. When the first big-time virus hits, you’ll be in much better shape than all those folks who will end up saying, “I didn’t think it would happen to me.”

The rest of this book has covered software that comes as part of the standard Fedora Core distribution, but FC does not come with a virus scanner. This functionality is important enough that I’m going to break my rule this one time and show you how to download, install, and run a third-party piece of software.

F-Prot (http://www.f-prot.com) has a virus scanner that’s free for personal use on workstations. It comes in three types of packages, including a 2.3 MB RPM. There are also a gzipped TAR file and a version for Debian/GNU.

### Download and install

Navigate to http://www.f-prot.com and look for the Download link for Linux home users. (They also make versions for Windows, BSD, and DOS (yes, DOS!), so make sure you get the right one.)
