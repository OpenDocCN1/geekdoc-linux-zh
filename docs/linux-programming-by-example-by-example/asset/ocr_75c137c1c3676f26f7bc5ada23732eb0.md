If the first msgget call succeeds, mkq displays the newly created queue ID, and then calls msgget a second time. If the second call succeeds, mkq reports this as well, but the second call merely opens the existing queue rather than creates a new one. Notice that the first call specifies read/write permissions for all users using the standard octal notation.

> **CAUTION**
> Unlike the open function's behavior, when creating a System V IPC structure, the process's umask does not modify the structure's access permissions. If you do not set access permissions, the default mode is 0, which means that not even the structure's creator has read or write access to it!
