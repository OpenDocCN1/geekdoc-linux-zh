Under Unix, the data directory is initialized during the installation procedure by the `mysql_install_db` script. If you install MySQL on Linux from RPM packages on or Mac OS X using a DMG package, `mysql_install_db` is run for you automatically. Otherwise, you run it yourself. See Appendix A for details.

One purpose of `mysql_install_db` is to set up the grant tables in the `mysql` database. On a server host named `cobra.snake.net`, `mysql_install_db` initializes the `user` table with the accounts shown in the following table.

| Host | User | Password | Superuser Privileges |
| :--- | :--- | :--- | :--- |
| localhost | root | | All |
| 127.0.0.1 | root | | All |
| cobra.snake.net | root | | All |
| localhost | | None | |
| cobra.snake.net | | None | |

These `user` table account entries enable connections by client programs as follows:

+   The `root` entries enable you to connect to the local MySQL server, using a host-name of `localhost`, `127.0.0.1`, or `cobra.snake.net`. For example, if you invoke the `mysql` program while logged in on `cobra.snake.net`, you can connect as `root` using either of these commands:
+   `$ mysql - localhost –u root`
+   `$ mysql -h cobra.snake.net -u root`

+   As `root`, you have all privileges and can perform any operation.

+   The entries with blank `user` values are the anonymous accounts. They enable connections to the local MySQL server, using a hostname of `localhost` or `cobra.snake.net`, and without specifying any username:
+   `$ mysql -h localhost`
+   `$ mysql -h cobra.snake.net`

Anonymous users have no superuser privileges.
