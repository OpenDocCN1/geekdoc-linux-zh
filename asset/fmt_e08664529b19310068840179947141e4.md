如果你在列表模式下指定 `-v`，目录列表写入标准输出，使用以下路径名格式：

对于表示归档先前成员硬链接的路径名：

```
"%s/=\%s\n" ls -l listing, linkname
```

对于所有其他路径名：

```
pathname "%s\n" ls -l listing
```

其中 `ls -l` 是带有 `-l` 选项的 命令指定的格式。当以此格式写入路径名时，对于底层归档格式没有正确信息的字段，写入的内容未知。

在列表模式下，标准输出的缓冲区不超过一行。

### 标准错误

如果你在写入、读取或拷贝模式下指定 `-v`，`pax` 将其处理的路径名写入标准错误，使用以下格式：

```
"%s\n" pathname
```

这些路径名在开始处理文件或归档成员时立即写入并刷新到标准错误。末尾换行符在文件被读取或写入后写入。

如果你指定了 `-s` 选项且替换字符串有末尾 `p`，则替换结果写入标准错误：

```
"%s/=\%s\n" original-pathname, new-pathname
```

在 `pax` 的所有操作模式下，可选格式的关于输入归档格式和卷号、文件数、块数、卷和介质部分以及其他诊断信息可以写入标准错误。

在标准输出和标准错误的所有格式中，路径名或链接名中的不可打印字符的写入方式是不指定的。

## 错误

如果 `pax` 在读取归档时无法创建文件或链接；在写入归档时找不到文件；或者在指定 `-p` 选项时无法保留用户 ID、组 ID 或文件模式，`pax` 将继续操作，向标准错误（`stderr`）写入诊断信息，并返回非零退出状态。当 `pax` 无法为文件创建链接时，`pax` 默认不会创建文件的第二个副本。

如果从归档中提取文件的过程被信号或错误提前终止，`pax` 可能只部分提取了文件（如果你没有指定 `-n` 选项），或者提取了与指定名称相同但并非你想要的文件。此外，提取的目录的文件模式可能包含来自读、写、执行掩码设置的额外比特位，且修改时间访问访问时间也可能不正确。

## 用法

`-p`（权限）选项是为了协调历史上的 `tar(1)` 和 `cpio(1)` 实现之间的差异而发明的。特别是，这两个命令对 `-m` 选项的使用方式完全截然相反。`-p` 选项还提供了一种一致的方法，用于扩展未来文件属性的处理方式，例如用于增强的安全系统或高性能文件。尽管可能看起来并非如此，但以下两种模式最常用：

- `-e` 保留所有内容。超级用户可以使用此选项保留归档中记录的文件的所有方面。`-e` 标志是 `o`、`p` 以及其他取决于具体实现的属性的总和。
- `-p` 保留文件模式比特位。具有普通权限的用户可以使用此选项保留除所有权以外的文件属性。文件时间默认会被保留，但提供了另外两个标志来禁用这些时间保留，并使用提取时的时间。

请参阅 `larg(5)` 以了解 `pax` 在遇到大于或等于 2 Gbytes（`2**31` 字节）的文件时的行为描述。

## 示例

以下示例将当前目录的内容复制到 1 号磁带驱动器，中密度（假设使用 System V 设备命名）。历史上的 BSD 设备名称为 `/dev/rmt9`。

```
pax% pax -w -f /dev/rmt/1
```

以下示例将 `olddir` 目录层次结构复制到 `newdir`。

```
pax% mkdir newdir
pax% pax -rw oldddir newdir
```

以下示例读取归档 `a.pax`，并将归档中根目录为 `/usr` 的所有文件提取到当前目录下。

```
castle pax -r -s '^,usr/*,' -f a.pax
caste$
```

## pcmmapkeys — 设置文本模式下 PC 控制台的键盘扩展映射和扫描码翻译

### 概要

```
/bin/pcmmapkeys -f mapfile -n -g -d -e
```

## 描述

`pcmmapkeys` 命令允许你在文本模式下激活输入输出字符映射以及 PC 控制台的键盘扩展映射。键盘扩展映射包括对死键（deadkey）和组合键（compose key）序列的支持。

## 一致的键盘-显示映射

原始 UNIX 操作系统是为了支持 ASCII 代码集而编写的。ASCII II 是字符内部表示为某些数字的标准之一。ASCII 通常支持 128 个不同字符，每个由一个字节表示，其中第 8 位未使用。UNIX 系统应用程序（包括 shell）利用了这种表示。从 UNIX System Release 3.1 开始，大多数此类应用程序已经过修改，以正确支持带有第 8 位的字节表示字符。有了第 8 位，可以同时支持 256 个字符。然而，需要应用一种一致的编码规范。在 IBM PC 中，已使用多年 8 位编码，称为 IBM 扩展 ASCII；MS-DOS 用户对该代码集非常熟悉。在异构 UNIX 系统环境中，推广了一种名为 ISO8859 的不同代码集。在这两个代码集中，ASCII 中的字符表示方式相同。其他 128 个字符的编码方式不同，一个代码集中找到的某些字符在另一个中是缺失的。Solaris x86 系统支持任何 8 位单字节代码集，包括 IBM 扩展 ASCII 和 ISO 8859 代码集。
