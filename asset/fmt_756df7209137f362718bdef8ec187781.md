## LRU folio 隔离

我们将收缩 LRU 列表的操作分为：从列表中隔离 folio（确保我们在执行操作时它们是稳定的且没有发生变化），以及对它们进行实际收缩。LRU folio 的隔离通过 `isolate_lru_pages()` 完成，我们在列表 11-57 中查看它（排除了范围外的数据预取逻辑、跟踪钩子和统计记录）。此函数假设 `struct lruvec->lru_lock` 已持有。

### 列表 11-57: mm/vmscan.c: isolate_lru_pages() 前言

```c
/*
 * 从 lruvec 隔离页面以填充 @dst 列表，数量为 nr_to_scan
 *
 * lruvec->lru_lock 竞争激烈。某些收缩列表的
 * 函数通过提取一批页面并在
 * LRU 锁之外处理它们来获得更好的性能。
 *
 * 对于页缓存密集型工作负载，此函数是内核中
 * 热点区域（来自 copy_*user 函数）。
 *
 * 调用此函数之前必须持有 LRU 锁。
 *
 * @nr_to_scan: 遍历列表时符合条件的页面数。
 * @lruvec: 用于提取页面的 LRU 向量。
 * @dst: 用于存放页面的临时列表。
 * @nr_scanned: 已扫描的页面数。
 * @sc: 本次回收会话的扫描控制结构。
 * @lru: 用于隔离的 LRU ID。
 *
 * 返回移动到 @dst 的页面数。
 */
static unsigned long isolate_lru_pages(unsigned long nr_to_scan,
    struct lruvec *lruvec, struct list_head *dst,
    unsigned long *nr_scanned, struct scan_control *sc,
    enum lru_list lru)
{
    struct list_head *src = &lruvec->lists[lru];
    unsigned long nr_taken = 0;

    unsigned long scan, total_scan, nr_pages;
    LIST_HEAD(folios_skipped);

    total_scan = 0;
    scan = 0;
```

我们通过建立局部变量来开始 `isolate_lru_pages()`，其中包括 `folios_skipped` 列表，它存储了我们由于各种原因选择跳过的 folio。

我们将 `src` 设置为提取页面的 LRU 向量，由输入枚举 `lru_list` 决定，该枚举指定了它是匿名、活动匿名、非活动文件支持或文件支持的 LRU 列表。

通过此循环，我们遍历此列表中的 folio，如列表 11-58 所示。

### 列表 11-58: mm/vmscan.c: isolate_lru_pages() 主循环

```c
while (scan < nr_to_scan && !list_empty(src)) {
    struct list_head *move_to = src;
    struct folio *folio;

    folio = lru_to_folio(src);
    nr_pages = folio_nr_pages(folio);
    total_scan += nr_pages;

    if (folio_zonenum(folio) > sc->reclaim_idx) {
        move_to = &folios_skipped;
        goto move;
    }
    /*
     * 不要计入跳过的 folio，因为如果 LRU 中
     * 大多数是不符合条件的 folio，这会导致函数在
     * 没有隔离任何 folio 的情况下返回。这会导致 VM 不回收
     * 任何 folio，触发误报的 OOM。
     * 统计 folio 中的所有页面。
     */
    scan += nr_pages;

    if (!folio_test_lru(folio)) {
        goto move;
    }
    if (sc->may_unmap && folio_mapped(folio)) {
        goto move;
    }
    /*
     * 在我们确定 folio 不在其他地方被释放之前，
     * 注意不要清除 lru 标记——folio 释放代码
     * 依赖于它。
     */
    if (unlikely(!folio_try_get(folio))) {
        goto move;
    }
    if (!folio_test_clear_lru(folio)) {
        /* 另一个线程已经在隔离此 folio */
        folio_put(folio);
        goto move;
    }

    nr_taken += nr_pages;
    move_to = dst;

move:
    list_move(&folio->lru, move_to);
}
```

在列表 11-58 探索的 `isolate_lru_pages()` 部分，我们遍历输入 LRU 列表中的 folio，通过 `lru_to_folio()` 提取列表中的尾部项。

提醒一下——folio 被添加到 LRU 链表的头部，并从尾部（通过回收）读取。因此，当我们从 LRU 列表尾部读取 folio 并添加它时，这符合这些列表的预期工作方式。

我们尚未从 LRU 列表中提取 folio，并且正在谨慎地处理。我们首先通过 `folio_nr_pages()` 确定 folio 中包含的基础页数，并将其添加到 folio 的运行总数 `total_scan` 中。

注意，我们维护一个非跳过 folio 的计数，并在循环内部比较 `nr_to_scan`，以确保我们不会只为了隔离而扫描不符合条件的 folio。

## 收缩活动列表

在 `shrink_active_list()` 中，我们检查并确保 folio（页框）未被锁定或通过 `folio_evictable()` 标记为不可驱逐。如果是，我们通过 `folio_putback_lru()` 将 folio 放回适当的 LRU 列表（这最终会调用 `folio_add_lru()`，请参阅列表 11-88 和第 11.7.5 节），它还会释放该 folio 增加的引用计数。

在完成此检查后，我们在释放被隔离 folio 的引用计数之前，设置了 `PG_lru` 标志（注意我们执行此项操作的时机，如注释中所述）。

现在，我们考虑这样一种情况：即由于 folio 被隔离而增加的引用计数是最后一个引用计数。我们希望尝试批量处理此类情况，以便一次性删除它们，而不是逐个删除，因此将这些 folio 添加到 `folio_to_free` 列表中，并在跳到下一个 folio 之前，清除其 LRU 特有的 `PG_lru`、`PG_active` 和 `PG_unevictable` 标志。

否则，我们通过 `lruvec_add_folio()` 将 folio 添加到指定的 LRU 列表（参见列表 11-13 和第 11.2.2 节）。

然后，我们通过 `folio_nr_pages()` 计算我们移动的基础页数量，并累加到 `nr_moved` 中。

最后，我们将所有待释放的 folio 放入输入列表以供调用者释放（这样做是为了效率考虑），然后返回移动的基础页计数。

## 11.5.9 收缩不活跃列表

![](img/d466eba53d24b7c77bd1b391fbb9172c_1062_0.png)

图 11-21：回收机制：收缩不活跃列表

收缩不活跃的 LRU 列表是内核执行实际回收的地方，所有的回收逻辑都是为了控制这一过程的进行。

这发生在 `shrink_inactive_list()` 中，我们在列表 11-61 中检查该函数（省略了 cgroup 逻辑、统计数据和跟踪钩子）。

### 列表 11-61: mm/vmscan.c: shrink_inactive_list()

```c
static unsigned long
shrink_inactive_list(unsigned long nr_to_scan, struct lruvec *lruvec,
    struct scan_control *sc, enum lru_list lru)
{
    LIST_HEAD(page_list);
    unsigned long nr_scanned;
    unsigned int nr_reclaimed = 0;
    unsigned long nr_taken;
    struct reclaim_stat stat;
    bool file = is_file_lru(lru);
    enum vm_event_item item;
    struct pglist_data *pgdat = lruvec_pgdat(lruvec);
    bool stalled = false;

    while (unlikely(too_many_isolated(pgdat, file, sc))) {
        if (stalled)
            return 0;
        /* 等待回收器一会。 */
        stalled = true;
        reclaim_throttle(pgdat, VMSCAN_THROTTLE_ISOLATED);
        /* 我们正要死亡并释放我们的内存。现在返回。 */
        if (fatal_signal_pending(current))
            return SWAP_CLUSTER_MAX;
    }

    lru_add_drain();

    spin_lock_irq(&lruvec->lru_lock);
    nr_taken = isolate_lru_pages(nr_to_scan, lruvec, &page_list,
        &nr_scanned, sc, lru);
    spin_unlock_irq(&lruvec->lru_lock);

    if (nr_taken == 0)
        return 0;

    nr_reclaimed = shrink_page_list(&page_list, pgdat, sc, &stat, false);

    spin_lock_irq(&lruvec->lru_lock);
    move_pages_to_lru(lruvec, &page_list);
    spin_unlock_irq(&lruvec->lru_lock);

    lru_note_cost(lruvec, file, stat.nr_pageout);

    free_unref_page_list(&page_list);

    /*
     * 如果扫描了未进入 IO 队列的脏页，
     * 刷新器（flushers）没有尽工作。
     * 这发生在内存压力将脏页推到 LRU 末尾，但尚未突破脏
     * 限制且脏数据尚未过期时。也可能发生在脏页
     * 比例的增长不是因为写入，而是通过内存
     * 压力回收了所有干净缓存。在某些情况下，
     * 刷新器简单无法跟上分配
     * 速率。如果刷新器处于睡眠状态，则通知它们。
     */
    if (stat.nr_unqueued_dirty == nr_REASON_VMSCAN)
        wakeup_flusher_threads(WB_REASON_VMSCAN);

    sc->nr_dirty += stat.nr_dirty;
    sc->nr_congested += stat.nr_congested;
    sc->nr_unqueued_dirty += stat.nr_unqueued_dirty;
    sc->nr_writeback += stat.nr_writeback;
    sc->nr_immediate += stat.nr_immediate;
    sc->nr_task += nr_task;
    if (file)
        sc->nr_file_task += nr_task;

    return nr_reclaimed;
}
```

`shrink_inactive_list()` 通过初始化一组局部变量来实现，包括我们用于存储待考虑回收的隔离 folio 的 `page_list`。然后我们检查是否需要因隔离页面过多而进行节流。
