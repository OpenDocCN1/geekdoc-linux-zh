
# 使用红帽软件包管理器 (RPM)

> 注意：在大多数 Linux 变体中，你可以在提取 tar 文件时“即时”解压。只需在 `tar` 命令中添加 `z` 标志即可，例如 `tar -zvf foo.tar.gz`。

典型的安装过程涉及编辑名为 `Makefile` 的文件，以修改软件存放编译后的二进制文件的目标目录。通常运行 `make`，然后运行 `make install`。

`make` 过程可能随你安装的每个软件包而异。对于某些软件包，某些配置 shell 脚本可能会向你提问，然后为你编译软件。请确保你阅读了软件包随带的文档文件。

## 检查文件权限

为软件包设置权限通常在安装期间自动完成。随应用程序一起提供的安装脚本通常会为每个文件安装正确的所有权和权限。只有当出现问题，且本应访问程序的用户无法访问时，你才需要找到应用程序被复制到的目录并检查权限。

通常，你运行以启动应用程序的可执行文件安装时的权限允许任何用户运行该文件；但是，只有超级用户 `root` 可以删除或覆盖它。应用程序通常安装在具有读和执行权限但没有写权限的目录中。

- 参见“文件权限”，第 310 页

## 解决问题

一个编写良好且支持良好的应用程序在安装到你的系统时，对你提供信息的请求最少。它会正确设置权限，这样你只需要测试程序并通知你的用户该应用程序现在可用了。但在程序的安装及其随后的运行过程中可能会出现问题。如果由于某种原因，程序没有完成加载过程，或者在安装后无法正常运行，那么你的责任就是确定原因并修复问题。

如果程序没有完全安装，你的故障排查工作通常只需要阅读应用程序提供的文档和 `README` 文件，寻找异常和问题的列表或其解决方案。然而，没有人期望你对 Linux 提供的成百上千个软件包都精通。偶尔，你可能需要外部帮助。

如果你无法使用软件包随带的信息解决问题，应该尝试在 Usenet 上查找是否有关于该软件包的讨论。在 Usenet 上相应的 Linux 组中发布提问可以解决很多问题。如果你无法在网上找到帮助，可以尝试联系应用程序开发者。

## 移除应用程序

如果应用程序被更好的软件包取代，或者不再被系统上的任何用户使用，那么删除它是一个好主意。磁盘空间总是宝贵的；你肯定不想让旧的、未使用的程序占用新应用程序所需的空间。

与安装一样，在 Linux 系统上删除程序比单用户操作系统要复杂得多。仅仅删除应用程序文件并移除其目录有时是不够的。必须断开驱动程序和其他软件连接，以避免未来的问题。通过记录笔记并将安装信息捕获到日志文件中，你通常可以找出软件安装时更改了哪些内容。

## 升级你的内核

随着其他软件的升级，新版本的内核定期发布。这些版本可能会修复错误或添加新功能。或者，你可能决定升级内核，因为你需要重新配置它或添加新的设备驱动程序。在任何情况下，该过程都是直接的。你应该在开始之前对系统和 Linux 启动盘进行备份，以便在损坏时可以恢复。有关如何重建内核的完整描述，请参见第 13 章“配置 Linux 内核”。

- 构建新内核，第 254 页

内核升级的过程在 Kernel HOWTO 文档中有详细介绍，该文档定期发布在互联网上的 Linux 群组，并在各种 Linux FTP 站点提供，确保你在开始内核升级之前从 `sun.unc.com` 获取该副本并仔细阅读。

升级内核的第一步是获取新的内核源码，这些可以通过 Linux 存档文件的匿名 FTP 获取。获取源码后，你需要保留当前的内核源码。为了实现这一点，将 `/usr/src/linux` 目录重命名为其他名称，例如 `/usr/src/linux.old`。在 `/usr/src` 目录下解压内核源码，这将创建 `linux` 子目录。此时，进入内核目录并查看文档和 `README` 文件。

从这里开始，过程可能会有些不同。通常，你运行 `config`，它会运行配置脚本并询问有关系统的问题。如果配置阶段成功完成，然后运行类似于 `make dep` 的命令。这将检查所有文件依赖关系，以确保新内核找到编译所需文件。

在依赖检查完成后，你通常运行 `clean` 以删除内核源码目录中的任何旧对象文件。如果到此为止一切顺利，你可以运行 `make` 进行编译。

# 理解多用户概念

对于 `root` 用户，当登录系统时，其主目录通常是 `/` 或特定的主目录，如 `/home/root`。

系统管理员以超级用户 `superuser` 身份登录，以执行需要特殊访问权限的任务。对于普通的系统工作，管理员以普通用户身份登录。超级用户的登录名称——`root`——仅用于有限的特殊目的。以 `root` 身份登录的用户人数应保持在最少。

系统管理员的精确工作描述通常取决于当地组织。作为管理员，你可能会发现自己参与了各种活动，从制定策略到安装软件再到搬家具。然而，所有系统管理员都必须执行或管理若干任务，如下：

- **管理用户。** 添加用户、删除用户并修改用户的能力和权限。
- **配置设备。** 提供并共享如打印机、终端、调制解调器和磁带驱动器等设备。
- **制作备份。** 制定计划、制作并存储备份，以便在系统文件丢失或损坏时进行恢复。
- **关闭系统。** 以有序的方式关闭系统，以避免文件系统出现不一致。
- **培训用户。** 为用户提供或提供培训，以便他们能够有效高效地使用系统。
- **保护系统。** 防止用户通过无意或故意的行为相互干扰。
- **记录系统更改。** 维护日志，记录任何与系统相关的重大活动。
- **建议用户。** 担任“本地专家”，帮助系统的普通用户。

## 多用户系统概念

多用户系统采用两个主要概念：多任务处理和多用户服务。Linux 具有并发执行多个任务的能力。

每个任务都会启动一个或多个进程。运行在 Linux 系统上的一切都与一个进程相关。由于 Linux 可以同时运行许多进程，因此 Linux 是一个多任务操作系统。

单用户操作系统如 `DOS` 被设计为一次仅供一个人使用。多用户系统使用集中处理和分布式处理模型来同时容纳许多用户。

# 理解集中处理系统

随着 20 世纪 50 年代和 60 年代的技术进步，操作系统开始允许多个用户从不同的终端共享资源。

当计算机变得廉价、强大且无处不在时，大多数 UNIX 系统使用了集中处理模型。在集中处理中，大型机处理所有的处理工作。

集中处理模型通常由许多元素组成，例如服务器、前端处理器、终端、调制解调器和多端口适配器。

## 集中处理模型的元素

服务器可以定义为任何配置用于共享资源 `处理能力、存储、打印机等` 的计算机。

前端处理器连接通信通道和服务器。它处理通信细节，以便服务器能够自由处理其数据。

今天有两种流行的终端类型：哑终端和智能终端。

要将终端连接到电话线，你需要使用调制解调器。调制解调器将终端和计算机的数字信号转换为电话线所需的模拟信号。

为了扩展可以连接的端口数量，你可以安装一个多端口适配器。通常，PC 只有两个串口：`COM1` 和 `COM2`。

# 理解分布式处理系统

在分布式处理中，终端被工作站取代，工作站本身是一台通常运行 `DOS` 或 `UNIX` 的计算机。

## 分布式处理模型的元素

分布式处理使用文件服务器、工作站、网络接口卡 `NIC`、集线器、中继器、桥、路由器和网关。

除了作为文件服务器外，你还可以将个人电脑作为 Linux 工作站。Linux 设计用于运行在极简的硬件配置上。

网络接口卡 `NIC` 连接在主板的插槽上，是计算机与网络布线之间的物理链路。

集线器作为网络电缆的连接点，可以是被动或主动的。

中继器放大或再生网络上的信号，以便你扩展网络布线的正常距离限制。

当你需要连接两种相似的网络类型时，请使用桥。

路由器用于大型复杂网络，为网络信号通往同一目的地提供许多路径。

当你需要连接使用不同协议的不同网络类型时，请使用网关。

## 拓扑结构

拓扑结构一词是指工作站和文件服务器在网络中的连接方式。最常见的拓扑结构是星型、总线型和环型。

### 星型拓扑
在星型拓扑结构中，所有工作站都连接到一个中央文件服务器或集线器。

### 总线拓扑
被动集线器仅仅是网络电缆的连接点。

### 环型拓扑
被动集线器仅仅是网络电缆的连接点。

### 混合拓扑
被动集线器仅仅是网络电缆的连接点。

## 定义网络管理员的角色

为了进行更远距离的连接，你可以使用低速传输介质，并使用点对点协议 `PPP` 或串行互联网协议 `SLIP` 来提供异步 TCP/IP 连接。你还可以使用 `UUCP` 软件进行电子邮件、新闻和文件传输。

不要购买任何旧的网络硬件。

## 执行常见的网络管理任务

### 设置系统

网络软件应该安装完毕并准备好在现场连接。

> 你已经投入了时间和金钱将网络配置到这一步。请立即备份你设置好的配置文件。

当系统功能完备后，应该安装应用程序。

你现在准备好向系统中开始添加用户了。为几个关键人员设置登录 ID，并设置一个常用的启动密码，例如 `temp01`。

安装完成后，计算机应连接到网络。确保你可以从网络中的任何一点通信到其他任何一点。

所有计算机都必须“认识”网络中的这台新计算机。这意味着你需要将其添加到网络中任何其他计算机所使用的主机名数据库中。如果你在本地使用域名系统 `DNS`，你必须将该主机添加到 DNS 数据库中。如果你不使用 DNS，请将名称添加到系统中的 `/etc/hosts` 文件中。

**处理外设设备**可能会给管理员带来重大问题。

调制解调器是连接远距离网络最廉价的方法。`PPP` 和 `UUCP` 工具适合小团队管理许多计算机。

**监控系统** 当安装完成后，你可以设置 UNIX 工具来监控你的系统。

**应对软件升级** 某些软件包不断更新。

最好的建议不要立即将所有新版本都部署到你的系统上，而是在一个非关键系统上进行升级测试。

# 使用 vi 编辑器

作者 Jack Tackett

## 介绍 vi

前面的章节已经向你展示了在文件中存储一系列命令或 shell 程序是多么方便和有利。你使用某种类型的文本编辑器来完成这些任务。Linux 自带了一个名为 `vi` 的标准文本编辑器。

`vi` 对系统管理员非常有用，因为可以在 UNIX 平台上使用。

Red Hat 发行版附带的 `vi` 和编辑器实际上是名为 `vim` 的编辑器的其他名称。`vi` 和 `ex` 名称在符号上与 `vim` 关联，所以当你输入 `vi` 时，你实际上在运行 `vim`。读取 `/usr/share/vim/vim_diff.txt` 可以了解 `vi` 和 `vim` 之间的差异。

你的 Linux 系统还有其他编辑器：一个用于 XFree86 系统的图形编辑器，以及两个名为 `ed` 和 `ex` 的标准非图形编辑器。另一个名为 `emacs` 的编辑器也提供于大多数 Linux 发行版中。

要理解 `vi`，你需要了解 `vi` 在 UNIX 世界中的部分历史。

## 什么是 vi？

因为是标准 UNIX 环境的一部分，已有数百万 UNIX 用户以不同程度学习并使用了 `vi`。你会发现 `vi` 启动速度很快，并且可以用于简单和复杂的任务。

## 理解编辑过程

你通过创建新文本或修改现有文本来执行编辑。当你使用编辑器时，文本都保存在系统内存中称为 `buffer` 的区域中。

你使用编辑器来修改、重新排列、删除、替换和搜索文本。今天，这些编辑操作是在命令模式下使用编辑器完成的。在某些情况下，命令是单个字母，对应动作名称的首字母。例如，`i` 对应插入 `insert` 动作，`r` 用于替换字符。

大多数命令在单行或若干行范围上操作。行号从 1 到 `buffer` 中的最后一行进行编号。

光标的位置始终指示你在编辑缓冲区中的当前位置。
