
让我们来看一下脚本的一些有趣特性：

## 第 30–39 行

定义了两个函数，用于创建最终管道的单个元素。其中一个函数添加一个需要指定字母的过滤器，另一个函数添加一个排除任何包含指定字母单词的过滤器。

## 第 40–51 行

从第一个参数开始对位置参数进行处理。我们检查第一个命令行参数是帮助选项还是要求的五个字符正则表达式。

## 第 52 行

我们创建了管道的开头。第一步是过滤字典，删除所有长度不等于五个字的单词。此外，我们过滤掉任何包含标点符号（通常是单引号）以及大写字母的单词，因为 *Wordle* 从不使用专有名词。

## 第 56 行

开始循环处理剩余的命令行参数。每当发现 *+letter* 或 *-letter* 时，我们去掉加或减号，并调用相应的函数将管道的下一个元素添加到命令字符串中。

## 第 71 行

这里是实际执行的地方。为了获取单词总数，我们将过滤后的单词列表通过到 *tee*，它将列表传递到标准输出（这样就会显示在屏幕上）并传递到实际上我们在进程替换中运行的“文件”。这很技巧。

## 陷阱 (Traps)

在第 10 章中，我们展示了程序如何响应信号。我们也可以为脚本添加这种功能（因为它们的执行时间很短且不创建临时文件），更大、更复杂的脚本可能会从信号处理程序中获益。

当我们设计一个大型、复杂的脚本时，考虑用户在脚本运行时注销或关闭电脑会发生什么是很。当这种情况发生时，信号将发送给所有受影响的进程。代表这些进程的程序可以执行操作以确保程序正确且有序地终止。例如，假设我们写了一个执行过程中创建临时文件的脚本。为了良好的设计，我们会让脚本在完成工作后删除该文件。如果接收到指示程序将终止的信号，让脚本删除该文件也是明智的。

`bash` 提供了一种用于此目的机制，称为 `trap`。陷阱通过适当命名的内置命令 `trap` 实现。`trap` 使用以下语法，其中 `argument` 是一个将被读取并视为命令的字符串，而 `signal` 是触发解释命令执行的信号规范：

```
trap argument signal [signal...]
```

### 这是一个简单的示例：

```bash
#!/bin/bash

# trap-demo: 简单信号处理演示

trap echo 'I am ignoring you.' SIGINT SIGTERM

for i in {1..5}; do
    echo "Iteration $i of 5"
    sleep 5
done
```

此脚本定义了一个陷阱，每当脚本在运行时接收到 SIGINT 或 SIGTERM 信号时，它都会执行一个 `echo` 命令。当用户尝试通过按下 CTRL-C 停止脚本时，程序的执行情况如下：

```
[linuxbox ~$] trap-demo
Iteration 1 of 5
Iteration 2 of 5
^CI am ignoring you.
Iteration 3 of 5
^CI am ignoring you.
Iteration 4 of 5
Iteration 5 of 5
```

正如我们所见，每当用户尝试中断程序时，打印的而是消息。构建一个字符串来形成有用的命令序列可能很麻烦，所以通常的做法是指定 shell 函数作为命令。在这个示例中，为每个要处理的信号指定了一个独立的 shell 函数：

```bash
#!/bin/bash

# trap-demo2: 简单信号处理演示

exit_on_signal_SIGINT () {
    echo "Script interrupted." 2>&1
    exit 0
}

exit_on_signal_SIGTERM () {
    echo "Script terminated." 2>&1
    exit 0
}

trap exit_on_signal_SIGINT SIGINT
trap exit_on_signal_SIGTERM SIGTERM

for i in {1..5}; do
    echo "Iteration $i of 5"
    sleep 5
done
```

获取 PID 的参数可能如下所示：

```
/tmp/foobar.6593.U0ZvmM6S4
```

对于由普通用户执行的脚本，避免使用 `/tmp` 目录并在用户主目录下创建临时文件目录可能是明智之举，可以使用如下的一行代码：

```bash
[[ -d $HOME/tmp ]] mkdir $HOME/tmp
```

# 异步执行

同时执行多个任务是理想的。我们已经看到所有现代操作系统即使不是多用户的，也都是多任务的。脚本可以构造为以多任务的方式运行。

通常，这涉及到启动一个脚本，该脚本随后启动一个或多个子脚本来执行额外的任务，而父脚本继续运行。然而，当一系列脚本这样执行时，在保持父子进程协调方面可能会出现问题。也就是说，如果父进程或子进程依赖另一个，且一个脚本必须等待另一个脚本完成任务才能开始自己的任务，该怎么办？

- `bash` 有一个内置命令来帮助管理此类异步执行。例如 `wait` 命令会让父脚本暂停，直到指定的进程（即子脚本）完成。

## wait

我们将首先演示 `wait` 命令。为了做到这一点，我们需要两个脚本。首先是一个父脚本。

```bash
#!/bin/bash

# async-parent: Asynchronous execution demo

echo "Parent: starting..."

echo "Parent: launching child script..."
async-child & 
pid=$!

echo "Parent: child (PID=$pid) launched."

echo "Parent: continuing..."
sleep 2

echo "Parent: pausing to wait for child to finish..."
wait "$pid"
echo "Parent: child is finished. Continuing..."

echo "Parent: parent is done. Exiting."
```

### 第二是子脚本。

```bash
#!/bin/bash

# async-child: Asynchronous execution demo (child)

echo "Child: child is running..."
sleep 1
echo "Child: child is done. Exiting."
```

在这个示例中，我们看到子脚本非常简单。实际的操作是由父脚本执行的。在父脚本中，子脚本被启动并放入后台运行。子脚本的进程 ID 由 `pid` 变量记录，其值为 shell 参数的值，该参数始终包含最后一个放入后台的作业的 PID。

父脚本继续执行并带有子进程的 PID 执行 `wait` 命令。这会导致父脚本暂停，直到子脚本退出，此时父脚本结束。

执行时，父脚本和子脚本会产生以下输出：

```
[me@linuxbox~$] async-parent
Parent: starting...
Parent: launching child script...
Parent: child (PID: 6741) launched.
Parent: continuing...
Child: is running...
Parent: pausing to wait for child to finish...
Child: child is done. Exiting.
Parent: child is finished. Continuing...
Parent: parent is done. Exiting.
```

# 命名管道

在大多数 Unix 类系统中，可以创建一种称为命名管道（named pipe）的特殊文件。命名管道用于在两个进程之间建立连接，可以像其他类型的文件一样使用。它们并不流行，但了解它们是有好处的。

有一种常见的编程架构称为客户端-服务器，它可以利用如命名管道之类的通信方法，以及其他类型的进程间通信（如网络连接）。

最常用的客户端-服务器系统当然是 浏览器与 Web 服务器的通信。浏览器充当客户端，向服务器发送请求，服务器用网页响应浏览器。

命名管道的行为像文件，但实际上形成了先进先出（FIFO）缓冲区。与普通（未命名）管道一样，数据从一端进入从另一端出来。通过命名管道，可以设置如下内容：

```bash
process1 > named_pipe
```

以及这个：

```bash
process2 < named_pipe
```

它的表现如下：

```
process1 | process2
```

## 设置命名管道

首先，我们必须创建一个命名管道。这是通过 `mkfifo` 命令完成的：

```bash
$ mkfifo pipe1
$ ls -l pipe1
prw-r--r-- 1 me ne 2009-07-17 06:41 pipe1
```

在这里我们使用 `mkfifo` 创建了一个名为 `pipe1` 的命名管道。使用 `ls` 检查文件，发现属性字段中的第一个字母是 `p`，表示它是一个命名管道。

## 使用命名管道

为了演示命名管道如何工作，我们需要两个终端窗口（或者两个虚拟控制台）。在第一个终端中，我们输入一个简单的命令并将其输出重定向到命名管道。

```bash
$ ls -l > pipe1
```

当我们按下回车键后，命令将处于挂起状态。这是因为还没有程序从管道的另一端接收数据。当发生这种情况时，被称为管道被阻塞了。一旦我们在另一端附加一个进程并它开始从管道读取输入，这种状态就会消除。使用第二个终端窗口，输入此命令：

```bash
$ cat pipe1
```

第一个终端窗口的目录列表现在出现在第二个终端中，作为 `cat` 命令的输出。一旦第一个终端中的 `ls` 命令不再被阻塞，它就能成功完成。
