
一个整个成年阶段只度过一天的昆虫，利用所有时间要做什么？它试图繁殖后代。它试图将人类花费多年完成的事情压缩到几个小时内。如果它成功了，物种就能延续下去并保持可观的数量。如果物种的生存是它们的目标，那么这些微小的带翅蛾已经设定了它们的优先级。

这些蝇子一生只需要做一件事，而且做得很好。Unix 开发者认为软件也应该如此。

## 原则 2：让每个程序只做好一件事

最好的程序就像库斯特的湖蝇一样，在生命中只执行一个任务并将其做好。程序被加载到内存中，完成它的功能，然后让路，让下一个专注的程序开始工作。

软件工程师往往沦入所谓的“功能蔓生症”（`creeping featureism`，行业内是这么称的）。一个程序员可能会写一个简单的应用程序，结果发现自己的创作冲动占据了主导，导致他在这里添加一个功能，在那里添加一个选项。很快，他就拥有了一个真正的能力大杂烩，其中许多功能对于程序的原始意图之外几乎没有额外价值。这些发明中某些可能是有价值的（在这里不是在讨论创造力！）编写者必须考虑它们是否属于这段代码。以下这组问题将是决策的良好起点。

- 程序是否需要用户交互？用户可以在文件或命令行中提供必要的参数吗？
- 程序是否需要对输入数据以特殊方式进行格式化？
- 系统上是否有其他程序可以完成该格式化工作？
- 程序是否需要输出数据以特殊方式进行格式化？纯 ASCII 文本足够吗？
- 是否存在另一个程序可以执行类似的功能，而无需你编写一个新程序？

前三个问题的答案通常是否。真正需要直接用户交互的应用程序是稀有的。大多数程序在不需要在其例程中加入对话解析器的情况下运行得很好。同样，大多数程序可以使用标准的输入和输出数据格式来满足大多数需求。对于那些需要特殊格式的情况，可以使用不同的通用程序。

等等，让我重新检查一下：最纯形式的 `ls` 应该列出目录的文件（不分特定顺序），如下：

| txt |
| doc |
| scripts |
| bin |
| calendar |
| x11 |
| database |
| people |
| mail |
| slides |
| projects |
| personal |
| bitmaps |
| src |

然而，大多数版本的 `ls` 输出格式如下所示：

| mail | calendar | people | slides |
| x11 | database | personal | src |
| bin | doc | projects | txt |
| bitmaps | memos |

起初，将文件列成整齐的列似乎是明智的。但现在 `ls` 包含了执行列格式化的代码，这项任务与列出目录内容几乎没有关系。列格式化可以是简单的也可以是复杂的，取决于使用的环境。例如，`ls` 假设用户正在使用 80 字符宽的老式终端。当调用 `ls` 时，例如在一个终端窗口为 132 字符的窗口系统中，列会发生什么？如果用户更倾向于两列而不是四列怎么办？如果终端使用变宽字符集呢？如果用户希望在每五行文件名后跟一条实线呢？列表还没完完。

公平地说，`ls` 保留了每行列出目录内容的能力。这大约是它应该做的一切，将列的工作留给更适合格式化任务的其他命令。这样 `ls` 将是一个小得多的命令（即更容易理解、更容易维护、消耗更少的系统资源等）。

由于编写一个只做好一件事的应用程序会导致更小的程序，这两个原则相辅相成。小型程序往往是单功能的。单功能程序往往是小型的。

这种方法的隐藏益处是，你能够专注于当前任务，将其提炼为你试图解决问题的本质。如果你无法理解你试图解决的问题。在后面的章节中，我们将讨论如何获得那种对 Unix 方式的理解。现在，请想得小一点。

## 知识与学习曲线

如果你在华尔街走一走，很快就会发现普通的业余投资者并不知道自己在做什么。要在股市中挣钱，每个人都知道你必须买低高卖。然而，年年年年，狼群都从羊群身上掠夺了数百万美元。据充分记载，那些小人物——也就是我和你——在市场的关键转折点通常是错的。

许多机构投资者的表现也好不到到哪。大多数养老基金经理、共同基金投资组合经理和职业资金经理都表现出一种长年一年都无法持续战胜市场的惊人无能，尽管许多人的年薪超过了一百万美元。

研究表明，以标准普尔500指数等指数所代表证券的指数基金，从长期来看，其表现优于 77% 的共同基金。尽管金融界对投资机会炒得热沸扬扬，公布的记录揭示了一个残酷的现实：我们大多数人通过向报纸的股票板块扔飞镖并购买在那里找到的股票，就能获得与任何其他投资者（无论业余还是专业）相当的。

虽然持续战胜市场极其困难，但确实有人做到了。富达马哲兰基金传奇经理彼得·林奇在 20 世纪 80 年代创造了令人瞩目的记录，让他的客户非常富有。“奥马哈的先知”沃伦·巴菲特为伯克希尔撒 Hathaway的股东赚了巨额利润。约翰·坦普顿爵士通过在全球范围内寻找投资便宜货积累了类似的财富。

尽管取得了成功，这些传奇投资者也承认他们并不总是能对。他们讲述了某些他们曾完全信任的公司，但其股票在购买的当年价值缩水了一半。他们哀叹那些“擦肩之过”，即那些随后涨了 1000% 甚至更高的极概率股票。尽管他们的表现超过了投资的常态，但他们知道自己仍有很多东西要学。

其他专业人士也有很多要学。医生必须不断努力跟上研究进展。会计师必须学习税法的新变化。律师必须研究最近的法院判决。精算师、销售人员、卡车司机、组装工、水管工、时尚设计师、法官、研究人员、建筑工和工程师都有东西要学。

### 3.1.1 事实是，每个人都在学习曲线上

想一下。你上一次遇到一个能百分之百预知某个行动准确结果的人是什么时候？我不是说这种人不存在。我只是认为他们很稀有。这种能力通常需要大量的努力和学习，再加上一点好运。

工程师或许是大多数人仍在学习的最好活证明。例如，航空工程师了解关于航空学的所有知识，那么为什么他们还需要测试飞行员呢？为什么通用汽车的工程师要对他们的汽车进行道路测试？为什么计算机工程师在生产之前要对产品进行现场测试？如果工程师对他们所做的完全了解，那么质量保证部门将是没必要的，因为质量在开发阶段就已经构建到产品中了。

Unix 将会使用 `cat` 命令编写他们所有的程序。

软件工程师面临着尤为陡峭的学习曲线。软件很难在第一次就写得正确。软件工程专业由不断的修订组成，这是一个试错是常态的工作，应用程序诞生于无数小时令人沮丧的重做。

请注意，我们并不是说人们永远无法精通任何东西。只是时间比大多数人认为的要长。平均学习曲线比最初看起来更长，倾斜得也更陡。当今世界上存在如此多的变量，以至于精通可能耗费一生，而完全知识可能根本无法获得。

### 3.1.2 即使是大师也知道变化是不可避免的

很少有项目不需要对原始规格进行更改。营销需求发生了变化。供应商未能交货。商品的性能可能与规定的不同。原型和测试运行暴露了设计缺陷。这些因素使得制造复杂的技术成为最最荒凉的任务。

- Unix 命令中最简单的命令之一，`cat` 将用户输入的所有内容重定向到文件中。然而，与文本编辑器或文字处理器不同，`cat` 命令不允许人们修改之前行的文本。

沟通故障往往是导致更改频繁的责任。当产品的潜在终端用户试图解释他的需求时，描述中存在许多空白。他可能会遗漏某些内容，或者未能以足够的准确性传达他脑海中的想法。工程师利用想象力来填补空白。他查看，并开始将自己的偏见应用于设计中。有时，工程师会猜测终端用户的想法，或者假设“他真的想要这样，而不是”。更糟糕的是，工程师通常被公司人员隔离开，如产品经理、销售团队和支持人员，这些人又对终端用户的预期结果增加了进一步的扭曲。

我们隔着镜子看世界。在烟雾和幻象之外，经验告诉我们第一次不会做对。及早确立这个公理更好。在设计中加入以后可能需要更改的假设，可以减少在更好地理解目标后进行重大修订的成本。

### 3.1.3 你认为为什么他们叫它软件？

软件工程需要的重做比任何其他工程学科都多，因为软件工程处理的是抽象的想法。如果用户能精确指定他们想要什么——想象一下做到这一点有多困难。“凡进入此的人，放弃一切吧”这句话浮现在脑海中。

## 软件永不完成。它只是被发布。

一旦软件被发布，没人知道它会发生什么。经验工程师可能对消费者的人口统计数据、它使用的环境等有一个模糊的概念。但他们很难预测任何软件产品的最终成功或失败。
