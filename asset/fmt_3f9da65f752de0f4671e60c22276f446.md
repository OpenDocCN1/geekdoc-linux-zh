# 第 9 章：内存内存主题

内存，它们不会互相踩踏或相互覆盖吗？看起来确实如此。然而，作为一名程序编写者，你访问的是虚拟内存。

物理内存指的是计算机内部实际的 RAM 芯片及其包含的内容。在现代计算机上，它通常在 16 到 512 兆字节之间。当我们谈论物理内存地址时，我们谈论的是内存在这些芯片上的确切位置。虚拟内存是你的程序看待内存的方式。在加载你的程序之前，Linux 会找到一个足够容纳你程序的空物理内存空间，然后告诉处理器假装你的内存实际上位于 `0x08048000` 地址，以便将你的程序加载进去。困惑了吗？让我进一步解释。

每个程序都有自己的沙箱可以运行。运行在你的计算机上的每个程序都认为自己被加载在内存地址 `0x08048000`，且栈始于 `0xbffffff`。当 Linux 加载程序时，它会找到一段未使用的内存，然后告诉处理器将该区域作为该程序的 `0x08048000` 地址。程序认为它正在使用的地址称为**虚拟地址**，而它所指向的芯片上的实际地址称为**物理地址**。将虚拟地址分配给物理地址的过程称为**映射**。

早些我们谈到了 `.bss` 和栈之间不可访问的内存，但我们没有谈论它为什么会在那里。原因是这部分虚拟内存地址还没有映射到物理内存地址上。映射过程消耗大量的时间和空间，因此如果对每个可能的程序的每个可能的虚拟地址都进行映射，你将没有足够的物理内存甚至无法运行一个程序。所以，`break` 是包含未映射内存区域的起点。对于栈，Linux 会自动映射从栈推入 `push` 时访问的内存。

当然，这是虚拟内存的一个非常简化的视图。完整的概念要先进得多。例如，虚拟内存可以映射到不仅仅是物理内存；它也可以映射到磁盘。Linux 上的交换分区 `Swap partitions` 允许 Linux 的虚拟内存系统不仅将内存映射到物理 RAM，还映射到磁盘块。例如，假设你只有 16 兆字节的物理内存。假设 Linux 和一些基础应用程序使用了 8 兆字节，而你想运行一个需要 20 兆字节内存的程序。你可以这样做吗？答案是肯定的，但前提是你设置了交换分区。发生的是，在你剩余的所有 8 兆字节物理内存映射到虚拟内存之后，Linux 开始将你的应用程序的部分虚拟内存映射到磁盘块。因此，如果你访问程序中的某个“内存”位置，该位置可能实际上不在内存中，而是在磁盘上。但作为程序员，你并不会知道这种区别，因为这一切都由 Linux 在幕后处理。

现在，x86 处理器无法直接从磁盘运行指令，无法直接从磁盘访问数据。这需要操作系统的帮助。当你尝试访问映射到磁盘的内存时，处理器会注意到它无法直接处理你的内存请求。它会请求 Linux 介入。Linux 注意到该内存实际上在磁盘上。因此，它将当前内存中的某些数据移动到磁盘以腾出空间，然后将从磁盘访问的内存移回物理内存。它调整处理器的虚拟到物理内存查找表，以便能够在新位置找到内存。最后，Linux 将控制权交给程序，并从最初尝试访问数据的指令处重启它。这条指令现在可以成功完成，因为内存现在位于物理 RAM 中了。

以下是 Linux 下处理内存访问方式的概述：

- 程序尝试从虚拟地址加载内存。
- 处理器使用 Linux 提供的表，动态将虚拟内存地址转换为物理内存地址。
- 注意，Linux 不仅可以将一个虚拟地址映射到不同的物理地址，还可以根据需要移动这些映射。
- 如果处理器没有为该内存地址列出物理地址，它将向 Linux 请求请求加载它。
- Linux 查看该地址。如果它被映射到磁盘位置，则继续执行下一步。否则，它将以段错误 `segmentation error` 终止程序。
- 如果没有足够的空间从磁盘加载内存，Linux 将将程序的其他部分或其他程序移动到磁盘以腾出空间。
- Linux 然后将数据移动到空闲物理内存地址。
- Linux 更新处理器的虚拟到物理内存映射表以反映变化。
- Linux 恢复程序的控制权，导致其重新发出引发此过程的指令。
- 处理器现在可以使用新加载的内存和翻译表来处理该指令。

对于操作系统来说，这是一项大量工作，但它在内存管理方面为用户和程序员提供了极大的灵活性。

现在，为了使该过程更高效，内存被分为称为“页” `pages` 的组。在 x86 处理器上运行 Linux 时，一个页是 4096 字节内存。所有的内存映射都是以页为单位进行的。物理内存分配、交换等都是针对页的，而不是单个内存地址。这对程序员来说意味着，当你编程时，应该尽量将大多数内存访问在同一个范围内，这样你每次只需要一两页内存。否则，Linux 可能不得不不断在磁盘和内存之间移动页以满足你的需求。磁盘访问是缓慢的，这会严重减慢你的程序。

有时加载的程序过多，以至于没有足够的物理内存。它们花费在内存和磁盘之间交换内存的时间比处理内存的时间还要多。这导致了被称为“交换死亡” `swap death` 的状态，会导致你的系统无响应且效率低下。如果你开始终止那些内存密集型程序，通常是可以恢复的，但这很痛苦。

驻留内存集 `Resident Set Size`：程序当前在物理内存中的内存量称为其驻留内存集，可以通过 `top` 程序查看。驻留内存集列在 `RSS` 列下。

## 获取更多内存

我们知道 Linux 会将我们所有的虚拟内存映射到物理内存或交换分区中。如果你尝试访问一段尚未映射的虚拟内存，它会触发称为段错误 `segmentation fault` 的错误，这将终止你的程序。程序边界点 `break` 如果你记得的话）是你可以使用最后一个有效地址。现在，如果你预先知道需要多少内存，这一切都是非常完美的。你可以直接将需要的所有内存添加到 `.data` 或 `.bss` 段中，它们都会出现在那里。然而，假设你不知道需要多少内存。例如，对于文本编辑器来说，你不知道用户的文件有多长。你可以尝试超出这个限制，通过寻找一个最大值并告诉用户他们无法超出，但如果文件很小，那就是浪费。因此，Linux 有一种机制可以移动边界点以适应应用程序的需求。

如果你需要更多内存，你只需要告诉 Linux 你想要新的边界点在哪里，Linux 就会映射当前与新边界点之间你需要的所有内存，并将边界点移动到你指定的位置。这些内存现在可以供你的程序使用了。我们告诉 Linux 移动边界点的方式是通过 `brk` 系统调用实现的。`brk` 系统调用的编号为

`45` 结果将位于 `%eax` 中。`%ebx` 应该加载请求的断点。然后你调用 `$0x80` 来信号 Linux 执行其工作。内存将在 `%eax` 中返回新的断点。新的断点实际上可能比你请求的要大，因为 Linux 会向上对齐到最近的页。如果没有足够的物理内存或交换分区空间来满足你的请求，Linux 将在 `%eax` 中返回 `0`。此外，如果你在 `%ebx` 为 `0` 的情况下调用 `brk`，它将简单地返回最后一个可用的内存地址。

这种方法的问题在于需要跟踪内存请求。假设我需要移动断点 `break` 以留出空间加载一个文件，然后需要再次移动断点来加载另一个文件。假设我删除了第一个文件。你在内存中有一个巨大的已映射但未使用的内存间隙。如果你在加载每个文件时都继续以这种方式移动断点，很快就会耗尽内存。那么，什么是内存管理器？

内存管理器是一组例程，负责为你管理程序的“脏活”工作。大多数内存管理器有两个基本功能：分配 `allocate` 和释放 `deallocate`。每当你需要一定数量的内存时，你只需告诉 `allocate` 你需要多少，它就会给你一个内存地址。当你完成使用后，它会调用 `deallocate` 表示你已完成。然后 `allocate` 就可以重用这部分内存。这种内存管理模式被称为动态内存分配。它最小化了内存中“空洞”的数量，确保你对内存进行了最佳利用。你可以做到。内存管理器使用的内存池通常被称为堆 `heap`。

内存管理器的工作方式是它们跟踪系统断点 `system break` 以及你分配的内存的位置。它们将堆中的每个内存块标记为已用或未使用。当你请求内存时，内存管理器检查是否存在合适大小的未使用块。如果没有，它会调用 `brk` 系统调用来请求更多内存。当你释放内存时，它会将该块标记为未使用，以便未来的请求可以检索它。在下一节中，我们将查看如何构建自己的内存管理器。

- `4.` 函数名通常不是 `allocate` 和 `deallocate`，但功能是相同的。例如在 C 编程语言中，它们命名为 `malloc` 和 `free`。
