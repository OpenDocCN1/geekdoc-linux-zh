
### `PCMCIA`
个人电脑内存卡协会（Personal Computer Memory Card International Association）的缩写。该组织产生了一系列标准，定义了包含内存、调制解调器、网络适配器等的小型信用卡大小设备的物理、电气和软件特性。这些设备也称为 PC 卡，主要用于笔记本电脑（尽管某些台式系统也可以使用 PCMCIA 卡）。

`PCMCIA` Red Hat Linux 安装程序在安装期间需要使用 PCMCIA 设备所需的软盘。

### `权限 (Permissions)`
控制文件访问的标识符集。权限由三个字段组成：用户、组和世界。用户字段控制文件所有者的访问，而组字段控制任何匹配文件组规范的人的访问。正如名称所示，世界字段控制所有人的访问。每个文件包含相同的一组位，指定了可能执行也可能不执行的操作，例如读取、写入和执行。

### `PLIP`
并行线互联网协议（Parallel Line Internet Protocol）的缩写。`PLIP` 是一种允许通过特殊设计的电缆通过计算机并行口进行 TCP/IP 通信的协议。

### `POSIX`
可移植操作系统接口（Portable Operating System Interface）的一个写法略显混乱的缩写。一组源自 UNIX 操作系统的系统的标准。

### `进程 (Process)`
进程（用简单的话说）是 Linux 系统上运行的程序的一个实例。

### `PS/2 鼠标`
PS/2 鼠标的名字源于首次使用这种鼠标的原始机型 - IBM PS/2。PS/2 鼠标可以通过其电缆末端的小型圆形连接器轻松识别。

### `RAM`
随机访问存储器（Random Access Memory）的缩写：`RAM` 用于持有正在执行的程序和数据。`RAM` 是易失的，这意味着在掉电时写入 RAM 的信息将会消失。

### `重启 (Reboot)`
重新启动过程。参见“启动 (Boot)”。

### `红帽软件 (Red Hat Software)`
一家位于北卡罗来州的公司：生产并销售操作系统。

### `救援软盘 (Rescue Diskette)`
一个包含基础环境的软盘。正如名称所示，救援软盘通常用于“救援”故障的系统。

### `RISC`
精简指令集计算机（Reduced Instruction Set Computer）的缩写。这种计算机设计使处理器能够在可预测的时间执行较少的不同指令。与 CISC 对比。

### `ROM`
只读存储（Read Only Memory）的缩写。`ROM` 用于持有计算机关机时必须的程序和数据。由于 ROM 是非易失性的，下次启动时 ROM 中的数据将保持不变。

### `Root`
具有系统资源完整完全访问权限的登录账户名称。也用于描述目录 `/`，即“根目录”。

### `RPM`
红帽软件包管理器（Red Hat Package Manager）的简称。`RPM` 也是一个用于安装、升级和删除软件包的程序。

### `SCSI`
小型计算机系统接口（Small Computer System Interface）的缩写，`SCSI` 是连接各种设备到计算机的标准接口。虽然流行的 SCSI 设备是磁盘驱动器，但 SCSI 磁带和扫描仪也很常见。

### `扇区 (Sector)`
在论及固定大小（通常为 512 字节）时，可以通过磁盘读写头之一在磁盘旋转一次的情况下访问，而无需改变头的位置。参见几何（Geometry）。

### `串口鼠标 (Serial Mouse)`
串口鼠标是一种设计为连接到计算机串口的鼠标。串口鼠标可以通过其电缆末端的矩形连接器轻松识别。

### `setgid`
用于设置进程的组 ID（GID）的系统。使用 `setgid` 编写的程序可以假设系统中任何组的组 ID。

### `setuid`
用于设置进程的用户 ID（UID）的系统。使用 `setuid` 编写的程序可以假设系统中任何进程的用户 ID。如果一个程序是“`setuid root`”，这被认为是一个可能的安全问题。

### `影子密码 (Shadow Password)`
通常每个用户的密码存储在 `/etc/passwd` 文件中。该文件必须对所有用户可读以便某些系统功能正常运行。然而，这意味着用户的加密密码副本很容易获取，使得能够针对它们运行自动密码猜测程序。另一方面，影子密码将加密密码存储在单独的高度保护的文件中，使得破解密码变得困难得多。

### `SILO`
一种用于基于 SPARC 处理器的 Linux 系统的常用自引导装载程序。

### `SLIP`
串行线路协议（Serial Line Internet Protocol）的缩写。`SLIP` 是一种允许通过串口（通常通过拨号连接）进行 TCP/IP 通信的协议。

# 术语表

源代码：构成程序的可读指令形式。也称为“sources”。没有程序的源代码，要修改该程序将非常困难。

SPARC：由太阳能微型系统公司（Sun Microsystems）开发的一种 RISC（精简指令集计算机）架构。

交换（Swap）：也称为“交换空间”。当程序所需的内存超过计算机物理可用的内存时，可以将完全未使用的信息写入硬盘上的临时缓冲区（称为交换空间），从而释放内存：某些操作系统支持交换到特定文件，但 Linux 通常交换到专用的交换分区（`swap partition`）。在 Linux 中，“swap”一词用于定义请求分页机制。

系统调用（System Call）：系统调用是代表进程执行系统级函数的例程。

TCP/IP：传输控制协议/互联网协议的缩写，TCP/IP 是现今互联网上常用的网络标准名称。

Torvalds, Linus：参见 Linux Torvalds。

UID：用户 ID（User ID）的缩写。它是 Red Hat Linux 各部分识别用户的方法。UID 是数字，尽管人类可读的名称存储在 `/etc/passwd` 文件中。

UNIX：一组类 Linux 操作系统，起源于某些电话公司人员编写的原始版本：²

卸载（Unmount）：撤销对文件系统的访问的行为。（注意，执行卸载的程序称为 `unmount`。）

虚拟控制台（Virtual Console）：虚拟控制台提供了多个“屏幕”，用户可以在其中登录并运行程序。计算机显示器上同时只显示一个控制台；使用键序列在虚拟控制台之间切换。

小部件（Widget）：用户可以操作的控件的标准屏幕表示。滚动条、按钮和文本框都是小部件的示例。

X 窗口系统（X Window System）：也称为“X”，这种图形界面提供了大多数计算机系统中常见的“桌面上的窗口”的隐喻。在 X 环境下，应用程序充当客户端，调用 X 服务器，由 X 服务器管理所有屏幕活动。此外，客户端应用程序可能位于与 X 服务器不同的系统上，允许远程显示应用程序的图形界面。

# Kickstart 安装

由于对自动化安装的需求，Red Hat 软件创建了 kickstart 安装方法。通过这种方法，系统管理员可以创建一个单一文件，其中包含了典型 Red Hat Linux 安装过程中通常会询问的所有问题的答案。kickstart 安装方法非常强大，通常可以使用单个 kickstart 文件在多台机器上安装 Red Hat Linux。

**请注意：** Kickstart 安装只能通过 CD-ROM 和 NFS 安装方法进行。。FTP、HTTP、SMB 或本地硬盘安装无法通过 kickstart 模式实现自动化。

## H.1 将 Kickstart 文件存放在哪里

要使用 kickstart 模式，你必须先创建一个 kickstart 文件，并让 Red Hat Linux 安装程序能够获取它。通常，这是通过将 kickstart 文件复制到启动软片上，或者使其在网络上可用来实现。基于网络的方法最常用，因为大多数 kickstart 安装倾向于在网络计算机上进行。这使得使得在许多计算机上安装 Red Hat Linux 变得更容易，因为 kickstart 文件可以保留在一个服务器系统上，并在安装期间由各台计算机读取。

让我们更深入地查看 kickstart 文件可能放置的位置。

### H.1.1 软片上

要执行基于软片的 kickstart 安装，kickstart 文件必须命名为 `ks.cfg`，并位于启动软片的顶层目录中。注意，Red Hat Linux 启动系统是 MS-DOS 格式，这使得在 Linux 下使用 `copy` 命令（如果你坚持，也可以使用 Windows）复制 kickstart 文件变得简单。尽管技术上没有强制要求，但大多数基于软片的 kickstart 安装是从 CD-ROM 安装 RedHat Linux 的。

### H.1.2 网络上

使用 kickstart 进行网络安装很常见，因为系统管理员可以快速高效地自动化许多网络计算机的安装。通常情况下，最常用的方法是让管理员在本地网络上同时拥有 BOOT/DHCP 服务器和 NFS 服务器。BOOT/DHCP 服务器提供网络信息，而 NFS 提供安装文件。通常，这两台服务器运行在同一台物理机器上，但并不是强制性要求。
