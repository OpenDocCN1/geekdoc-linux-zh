
InterNIC 网站包含指向 RFC、互联网草案以及互联网相关信息的在线副本的链接。将您的浏览器指向 `http://www.internic.net/ds/` 进入主站，并指向 `http://ds.internic.net/ds/dspg0intdoc.html` 以搜索 RFC 数据库中的特定主题。

**注意：** RFC 一旦提交并采纳，就永远不会被修改。相反，当提议修改现有协议时，会创建新的 RFC。IETF 在线索引包含每份 RFC 的条目，其中其他信息说明了它取代了哪些 RFC，以及哪些 RFC 取代了它。你可以遵循这一链来查看协议随时间的演变。在大多数情况下，较新 RFC 的作者会在文档中明确说明他们为什么要提议对旧标准或草案进行更改。

**提示：** RFC 机制本身用于记录在任何给定时间官方采纳为互联网标准的所有 RFC。截至 1997 年 6 月，当前标准列表包含在 RFC 2200 中。你可以查找此 RFC 的索引条目，以确定自那时起是否采纳了任何新标准。

这是一种熟悉当前互联网标准的简单方法，无需追溯互联网协议族的历史发展过程。

**提示：** 在征求意见（Request For Comment）中的协议定义初次阅读时可能相当唬人。这些文档旨在约束和指导软件实现者。

其他信息性 RFC 详细定义了协议，但并未提议将其为标准，因为它们是由一家公司开发的，该公司选择保留对其演进的控制。描述 Sun 网络文件系统连续版本的 RFC 就属于此类。通过发布 NFS 协议的定义，Sun 允许并鼓励其他供应商在自己的操作系统中支持 NFS。通过这种方式，NFS 已成为了一种*事实上的*（de facto）而非官方的互联网标准。

最后，某些 RFC 被指定为实验性的（供有限范围实施以评估其有效性）或历史性的（historical，曾使用，现已实际上被替代协议所取代）。

官方标准并不要求所有互联网服务器或客户端系统都采纳。标准可能属于以下几类：

- 强制性（Required）——所有系统必须实现此协议。互联网协议（IP）和相关的互联网控制消息协议（ICMP）是所有直接连接到公网的系统的强制标准协议。

- 推荐性（Recommended）——除非有强有力的理由这样做，否则所有系统都应实现此协议。传输控制协议（TCP）、文件传输协议（FTP）和 Telnet 是互联网的一些推荐标准协议。

- 可选性（Elective）——任何要实现此类内容的系统都必须按照 RFC 进行。例如，MIME 是互联网的一种可选性标准协议。

- 局限使用（Limited Use）——由于协议的实验性、历史性或专门性，这些协议的使用仅限于特殊情况。

- 不推荐（Not Recommended）——由于其功能有限、专门性或实验性或历史状态，不建议通用使用这些协议。

- 与此类类型所有格式（子类型）相关的参数

- 用户代理或网关应如何处理此类类型的其他未知子类型

- 关于处理此类类型实体的其他问题和考量

- 对此类类型实体的内容传输编码（`content-transfer-encodings`）的限制，以确保传输的信息不会被无意扭曲

在新的 MIME 方案中，最初定义了五种离散的顶级媒体类型。这些是：

- `Text`——可读文本，包括文字处理器格式，这些格式的内容在屏幕或打印机上显示时在多大程度上具有可读性。

- `Image`——静态图形图像，需要图形显示器（显示器）、图形打印机或传真机供用户查看这些信息。

- `Audio`——需要扬声器、电话或类似设备以便让用户听到内容的信息。

- `Video`——需要具有显示移动图像的能力，通常需要专门的硬件和软件。

- `Application`——其他类型的数据，既可以是二进制文件（通常存储在磁盘文件中供用户管理），也可以由应用程序处理的信息。适当应用程序与特定应用程序数据子类型的关联是在客户端机器上完成的。

两种顶级复合媒体类型是：

- `Multipart`——由多个独立数据类型的项目组成的数据。子类型包括通用的 `mixed`（混合）实体；相同数据的 `alternative`（可选）格式；旨在同时查看的 `parallel`（并行）实体（例如音频和视频）；以及用于在单个消息中传输多个邮件的 `digest`（摘要）。

- `Message`——一个封装的消息。当封装的消息本身是 RFC 822 定义的 ASCII 邮件时，使用 `rfc822` 子类型。`partial` 子类型允许大型消息被分段并在以后重组。`external-body` 子类型传递指向大型外部数据源的引用而非源的内容。

未被 IANA 识别的 MIME 类型以 `x-` 开头命名。例如，用于音频信息的 MPEG 二层格式（关联扩展名为 `.mp2`）映射到 MIME 类型 `audio/x-mpeg`。官方的 MIME 类型通常由相关的服务器和客户端软件支持，但私有或实验类型可能需要在 Internet 服务器和客户端工作站上进行显式配置才能正确处理。

## 常见 MIME 数据类型

尽管顶级 MIME 媒体类型对应于所有用户理解的基础概念，但并不是所有子类型都属于明显的媒体类别。例如，与特定应用程序关联的类型尽管在互联网上广泛可用，可能被归类为应用类型而非文本、图像或音频。通常这些数据类型在访问网站时，需要浏览器插件才能对其内容进行正确处理，或者客户端浏览器可能会要求你指定与该子类型或文件扩展名关联的应用程序。

由于数据类型的官方状态变化迅速，特别是随着多媒体应用的快速扩展，我根据它们所属的直观类别对描述进行了分组，而不是根据其官方状态。接下来的每个数据格式描述都包含常见格式名称和当前 MIME 名称、与媒体关联的文件扩展名以及简要描述。

### 文本类型

**表 16.1 互联网上常见的文本类型。**

| MIME 类型 | 文件扩展名 | 常见格式名称 | 描述 |
| :--- | :--- | :--- | :--- |
| `text/plain` | `.txt` | Text | 无格式标记的美国 ASCII 文本 |
| `text/html` | `.html`, `.htm` | 超文本标记语言 | 定义万维网页面 |
| `application/rtf` | `.rtf` | 富文本格式 | 具有某些格式能力的厂商无关的文字处理文件类型 |
| `application/postscript` | `.ps`, `.ai`, `.eps` | PostScript | 打印和显示格式 |
| `application/pdf` | `.pdf` | 便携式文档 | Adobe 用于平台无关显示和打印的 PDF 格式 |

### 图像类型

**表 16.2 互联网上常见的图像类型。**

| MIME 类型 | 文件扩展名 | 常见格式名称 | 描述 |
| :--- | :--- | :--- | :--- |
| `image/gif` | `.gif` | 图形交换格式 | Web 静态图像的常见格式。8 位色彩和无损压缩；非常适合绘画。Unisys 专利。 |
| `image/jpeg` | `.jpeg`, `.jpe`, `.jpg` | 图像专家小组 (JPEG) | 24 位色彩带有损压缩。通常用于 Web 照片和高细节图。 |
| `image/png` | `.png` | 便携式网络图形 | IETF 提出的一种新格式，作为 GIF 和某些 TIFF 用途的无专利替代品 |
| `image/tiff` | `.tiff` | 标记图像文件格式 | Aldus 公司开发，并用于互联网远程打印的实验性 |
