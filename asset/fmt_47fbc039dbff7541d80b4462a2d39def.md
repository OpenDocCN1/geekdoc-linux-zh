
TCP 用于维护这两台计算机之间的连接。Telnet 使用了 TCP 端口 `23`。

- a. 超文本传输协议 (HTTP) - 该协议用于通过 www（万维网）传输超文本页面。它规定了消息的格式和传输，以及 Web 服务器和浏览器响应各种命令时所采取的操作。了解如何格式化消息并在浏览器上显示这些消息是 HTML 的工作。由于每个命令都必须独立执行，HTTP 被称为一种无状态协议。我们不需要了解源于它的具体命令。

- a. 网络新闻传输协议 (NNTP) - 该协议用于在 USENET 服务器和新闻客户端之间传输 USENET 帖。

- a. 远程行打印机 (LPR)、行打印机守护进程 (LPD) - 这两个协议用于在运行 UNIX 的计算机上提供服务器和打印服务。

## 网络实用

### ARP 工具

此工具用于显示某个 IP 地址是否正在被解析以获取 MAC 地址。

### NETSTAT 工具

此工具用于生成 TCP/IP 实用程序，`nbtstat` 将生成 TCP/IP 之上的 NetBIOS 统计数据。该命令通常显示本地地址如何映射到远程地址。

### TRACERT 工具

此工具用于查找网络上从一台计算机到另一台计算机的现有路径。

### Ping 工具

此工具用于检查特定主机是否有响应。要解析本地主机（`localhost`），应使用 IP 地址 `127.0.0.1`。执行命令后会发送 4 个响应数据包。

### FTP 工具

此工具允许通过互联网向 FTP 服务器上传和下载文件。

### `ipconfig` 和 `ifconfig`

`Ipconfig` 用于显示 Windows NT 以及其他较后版本各种操作系统的 TCP/IP 配置信息。`Ifconfig` 用于在 UNIX 环境中执行相同任务，并用于对某些用户界面任务进行配置。

### `winipcfg` 工具

此工具用于显示 Windows 95/98 中的 TCP/IP 配置。

### `dig` 工具和 `nslookup`

这些工具用于显示有关 DNS 解析的信息。

## 为什么要实现网络自动化？

“旧事物的遗迹必须被体面地安放，新事物的道路必须做好准备。这就是革命与进步之间的区别。” - 亨利·福特

变革的时刻已经到来。企业网络已经超越了使用传统工具进行有效管理和维护自身的能力。从历史上看，网络管理意味着从单个设备手动收集时间点信息，或对设备进行配置更改。网络通常使用配置命令驱动的方法，而不是数据驱动的方法。员工在 `CLI` 处手动执行命令以收集信息或执行更改。在做出更改后，通常需要重新收集信息以确认网络状态。网络文档的持续创建和维护也是手动进行的。做出更改需要数小时的工作，而且经常在不同的设备上重复相同的命令。由于使用手动方法会导致错误，不可避免地需要故障排除。网络自动化解决了所有这些问题。

### 规模

现代网络的规模呈指数级增长，以满足组织的需求。最初几个交换机和一个路由网络现在变成了大型企业网络。虽然逻辑网络在演变增长，但管理物理设备的工具仍然停滞不前。在校园网上，我们现在看到 `VoIP` 电话、无线访问点、`IoT`、安全摄像头、打印队列、桌面集群和会议室设备。在数据中心，大型物理和虚拟足迹并不罕见。在每个远程办公室都有交换和路由的全球 `WAN` 现在已成为常态。设备热潮并未放缓，越来越多的设备被加入网络，而没有相应的集中化、自动化管理解决方案。

网络管理始于控制线和本地 `CLI`。管理员必须通过管理 IP 地址启用对 `CLI` 的远程访问。现在想象一下网络技术人员仍然需要前往每个设备的物理控制台来管理它。这听起来不合理，但只有对 `CLI` 的远程访问是集中的。它遵循与登录 `CLI` 管理设备的相同方法，就好像操作员实际上位于控制台前一样。事实上，这些远程连接被称为虚拟电打字机或 `VTY` 线路。在当今网络的规模下，连接到每台设备的 `CLI` 来管理企业是完全无法实现的。即使有一支功能强大的网络运营团队，每个人也会按照自己的方式来操作、配置和管理每个设备。这导致了规模化下的配置漂移和缺乏一致性。

由于设备配置是模板化的，自动化解决方案随网络规模而扩展。小型的、针对特定功能的、模块化的模板确保了每个设备都经过标准化。当出现新功能需求时，配置命令被模板化并在规模范围内发布，从而统一更新网络标准。独特的、特定于设备的、有意义的信息被建模在数据字典中。该字典包含了用于为每个设备编译唯一配置的所有变量。代码可以模块化地编写，以匹配网络拓扑。通过创建针对特定环境（如校园、数据中心、`WAN` 或云）的剧本，`Ansible` 剧本确保了代码的简单性、可读性和开发灵活性。

### 复杂度

网络的复杂性大幅增加。虚拟路由转发器 (`VRF`)、`QoS`、无线连接、云连接、虚拟专用网络 (`VPN`)、第一跳冗余协议 (`FHRP`) 如热备路由器协议 (`HSRP`)、虚拟交换系统 (`VSS`) 以及作为 `802.1x` 的安全和身份服务，增加了设计工程师和运行网络操作员的能力。从网络中抽象重要数据允许操作员将设备视为一组人类可读的变量。设备配置的可读性减少了理解设备如何配置的技术要求。

### 文档

网络文档极其重要，特别是在危机期间，但在日常操作中经常被忽视。更改可能未反映在文档中。文件可能分散在各种源中，例如本地驱动器、`SharePoint` 站点或网络共享。过时的文档对组织价值很小。存在的文档通常表示为复杂的 `Visio` 图、大型 `Excel` 表格或与网络动态交互的文本文件。

`TFS` 仓库主分支的一部分应该是一个文件夹结构，包含动态文档 `Ansible` 剧本，以及生成的输出产物的文件夹。自动化文档可以直接构建到 `CI/CD` 流水线，创建逗号分隔值 (`.csv`)、`Markdown` (`.md`) 或文本文件。这些文件随后被纳入 `Git` 提交和拉请求，成为代码库和仓库的一部分。`TFS` 和 `VS Code` 可以原生查看这些文件，提供代码形式呈现的网络视图。这些产物包括预期的、自动生成的配置文件，以及用于以不同格式表达数据的模型变量。

例如，是否可以根据数据模型变量为每个设备自动生成以下文档：

- `VLAN`
- `VRF`
- 路由协议配置信息
- 静态路由
- 接口信息：
    - 开启/关闭
    - 模式 – 访问或中干
    - `VLAN` (s)
- 端口组信息：
    - 成员端口
    - IP 地址
    - 访问控制列表 (`ACL`)

事实上，任何表示在数据模型中的信息都可以转换为动态文档文件。这允许获取关于网络上的任何设备在构建时自动生成的所需信息，并可以通过 `TFS` 获取。这些文档文件的历史作为源码和版本控制包含在内。当添加或删除代码时，生成的文档会自动进行更新以反映这些更改。

### 标准

随着网络的演变和转型，企业标准的维护随时间推移变得非常困难。通常，项目压力和日常工作的交付物会导致标准被忽视、推迟或忽略。随着网络设备和 IP 地址的来来去去，随着时间的推移可能会发生自然的配置漂移。如果网络设备继续运行，错误的配置或糟糕的标准可能不会被察觉。一旦被识别出来，这些表面的更正可能被视为低优先级。

`Ansible` 的动态模板化保证了每个设备都有标准的配置。可以实现完全的配置覆盖，并且运行配置中的每一行代码都可以从模板派生。通过在“真理源”与设备配置之间实现完全的幂等性，可以确保基于意图的标准得到统一应用。使用这种方法，规模不是问题，人为错误的因素也是如此。当出现新标准或需要对现有标准进行更改时，只需更新集中的模板和数据模型。这些更改将通过自动化引擎推送，并将新标准交付到网络。

### 黄金配置（Golden Configuration）

黄金配置在 Windows 操作系统管理中被称为“预期状态配置”，它有很多名称。通过使用 `Jinja2` 模板和 `YAML` 数据模型，可以使用软件开发方法论实现网络中每个设备的黄金配置。模板内部的逻辑用于智能地生成设备配置命令。这些配置将大规模应用于包含在 `Ansible` 的 `hosts.ini` 清单文件中的所有设备。

主分支（`master branch`）代表网络的黄金配置。自动化构建会将主分支的各种构制品打包，并为该迭代版本的网络提供一个版本号。然而，当需要更改时（无论多微小），会创建工作分支进行代码开发和测试。开发期间频繁的 `Git` 提交用于将更改检入工作分支。通过拉取请求（`pull request`）将这些累积的更改合并到主分支，然后将其部署到生产环境中，大规模地更新标准的黄金配置。

## 安全

一些重大的安全泄露发生是因为 `telnet` 在具有公网 IP 地址的端口上开启。安全标准和最佳实践现在可以硬编码到模板中，以确保策略的执行。通常，访问层的接口上需要复杂的配置来解决安全风险。考虑访问层以及应该实现的所有以下安全标准：

- 生成树工具包命令。
- 桥接协议数据单元 (`BPDU`) 控制。
- `Portfast`。
- `802.1x` 或端口安全命令。
- 数据和语音 `VLAN`。
- `QoS` 设置。
- `CDP` 设置。
- 以太网供电 (`PoE`) 设置。
- 建立 `Native VLAN`。
- 在汇干口上应用 `Native VLAN`。
- `NTP` 源。
- 登录时显示安全横幅（Security banner）。
- `AAA`。
- `RADIUS` / `TACACS+`。
- 管理端口上的 `ACL`。
- 禁用 `VLAN 1`。
