
`tr` 的一种用法是对文本进行 ROT13 编码。ROT13 是一种基于简单替换密码的简易加密类型。将 ROT13 称为“加密”是有些宽慨了；“文本混淆”更准确。它有时用于文本以隐藏可能具有攻击性的内容。这种简单的方法是将每个字符在字母表中向上移动 13 位。由于这是 26 个字母的一半，再次执行该算法即可将其恢复为原始形式。使用以下命令来用 `tr` 执行此编码：

```
echo "secret text" | tr a-zA-Z n-za-mn-ZM
frperg grkg
```

第二次执行相同的步骤将得到以下翻译结果：

```
echo "frperg grkg" | tr a-zA-Z n-za-mn-ZA-ZM
secret text
```

许多电子邮件和 Usenet 阅读器支持 ROT13 编码。维基百科包含关于该主题的优秀文章，地址为：`https://en.wikipedia.org/wiki/ROT13`。

`tr` 还可以执行另一个技巧。使用 `-s` 选项，`tr` 可以“挤压”（删除）重复的字符实例。

```
me[\approx]$ echo "aaabbccc" | tr -s ab
abccc
```

在这里，我们有一个包含重复字符的字符串。通过向 `tr` 指定集合 `ab`，我们消除了集合中字母的重复实例，同时保持集合中缺失的字符（c）不变。注意，重复的字符必须是相邻。如果它们不相邻，挤压将不起作用。

```
me[\approx]$ echo "abcabc" | tr -s ab
ababcabc
```

## sed

`sed` 的名称是 `stream editor`（流编辑器）的缩写。它在文本流上执行文本编辑，流可以是一组指定的文件或标准输入。`sed` 是一个强大且相当复杂的程序，关于它的书籍不胜，因此我们在这里不会完全介绍它。

通常情况下，`sed` 的工作方式是给定单个编辑命令（在命令行上）或包含多个命令的脚本文件名称，然后它对文本流中的每一行执行这些命令。这里有一个 `sed` 运行的简单示例：

```
me[\approx]$ echo "front" | sed 's/front/back/'
back
```

在这个示例中，我们使用 `echo` 生成了一个单单词文本流，并将其传递给 `sed`。`sed` 在流中的文本上执行 `s/front/back/` 指令，并产生输出“back”结果。我们也可以识别出此命令类似于 `vi` 中的“替换”（查找并替换）命令。

`sed` 中的命令以单个字母开头。在上一个示例中，替换由字母 `s` 表示，后面跟着查找和替换字符串，这些字符串用斜杠字符 `/` 作为分隔符。分隔符字符的选择是任意的。按照惯例，通常使用斜杠，但 `sed` 会接受紧随命令的任何字符作为分隔符。我们可以通过以下方式执行相同的命令：

```
me[\approx]$ echo "front" | sed 's/front_back_/'
```

通过在命令后立即使用下划线字符，它就变成了分隔符。正如我们将看到的，使用分隔符的能力有助于提高命令的可读性。

`sed` 中的大多数命令前面可能跟有一个地址（address），它指定输入流中的哪些行将被编辑。如果省略了地址，则编辑命令将在输入流的每一行执行。地址最简单的形式是行号。我们可以为示例加上 1。

```
[me@linuxbox]$ echo "front" | sed 'is/front/back/'
```

在命令中添加地址 1 会导致我们的替换在我们单行输入流的第一行执行。如果我们指定另一个数字，我们发现没有执行编辑，因为我们的输入流没有第 2 行。

```
[me@linuxbox]$ echo "front" | sed 'zs/front/back/'
```

`s` 命令是目前为止最常用的编辑命令。我们将通过对我们的 `dist.txt` 文件进行编辑来演示它的某些威力。我们之前讨论过日期字段不是一种“计算机友好型”的格式。虽然日期格式为 `MM/DD/YYYY`，但如果格式是 `YYYY-MM-DD` 会更好（便于排序）。在文件上执行此更改将非常耗时且容易出错，但使用 `sed`，此更改可以一步完成。

哇！一个看起来很棒的命令。它起作用了。仅需一步，我们就更改了文件中的日期格式。它也是正则表达式的一个完美示例，正则表达式有时被开玩笑地称为“只写”介质。我们可以向它们写入内容，但有时无法读回。在被这些东西吓得逃跑之前，我们知道该命令将具有这样一个基本结构：

```
sed 's/regex/replacement/' distros.txt
```

我们的下一步是弄清楚一个可以提取出日期的正则表达式。因为它是 `MM/DD/YYYY` 格式且出现在行末，我们可以使用如下这样的表达式：

```
$[0-9]\{2\}/[0-9]\{2\}/[0-9]\{4\}$\}$
```

这匹配两个数字、一个斜杠、两个数字、四个数字以及行尾。所以这处理了*regexp*。为了处理这一点，我们必须引入一种在某些使用 BRE（基本正则表达式）的应用程序中出现的新正则表达式。这种特性被称为*反引用*（back references），其工作原理如下：如果序列 `\n` 出现在 `replacement` 中，其中 `n` 是一个 1 到 9 之间的数字，则该序列将引用前面正则表达式中对应的子表达式。要创建子表达式，我们只需将它们括在括号中，如下：

```
$(([0-9]\{2\))/([0-9]\{2\))/([0-9]\{4\})))$
```

我们有三个子表达式。第一个包含月份，第二个包含日期，第三个包含年份。现在我们可以如下构造 `replacement`：

```
$\3-\1-\2$
```

这为我们返回了年份、一个横杠、月份、一个横杠和日期。现在，我们的命令看起来是这样：

```
sed '/(([0-9]\{2\))/([0-9]\{2\))/([0-9]\{4\}))/\3-\1-\2/' distros.txt
```

我们还有两个问题。第一个是我们正则表达式中额外的斜杠会误导 `sed`。第二个是由于 `sed` 默认只使用基本正则表达式，我们正则表达式中的几个字符将被视为字面量，而不是元字符。我们可以通过对冲突的字符进行字面应用反斜杠进行转义来解决这两个问题。

```
sed '/(([0-9]\{2\})\/([0-9]\{2\})\/([0-9]\{4\}))\\3-\\1-\\2/' distros.txt
```

`s` 命令的另一个特性是可以使用跟随替换字符串的可选标志。其中最重要的是 `g` 标志，它指示 `sed` 对某行应用全局搜索替换，而不仅仅是第一个实例（这是默认设置）。这里有一个例子：

```
[linuxbox]$ echo "aaabbcccc" | sed s/b/b/
aaabbcccc
```

我们看到替换执行了，但仅针对字母 *b* 的第一个实例。通过添加 *g* 标志，我们能够更改所有的实例。

```
[linuxbox]$ echo "aaabbcccc" | sed s/b/b/g
aaabbcccc
```

所以替换执行了，但仅针对字母 *b* 的第一个实例。通过添加 *g* 标志，我们能够更改所有的实例。

## aspell

我们将看到的最后一个工具是 `aspell`，一个交互式拼写检查器。`aspell` 程序是早先名为 `ispell` 的程序的继任者，在大多数情况下可以作为它的无缝替代品使用。虽然 `aspell` 程序主要被需要拼写检查功能的其他程序调用，但也可以作为命令行独立工具使用。它能够智能地检查各种类型的文本文件，包括 HTML 文档、C/C++ 程序、电子邮件以及其他类型的特殊文本。并不是所有的 Linux 发行版都默认包含 `aspell`，因此我们可能需要安装它。

要对包含散文的文本文件进行拼写检查，可以这样操作：

```bash
aspell check textfile
```

在这里，`textfile` 是要检查的文件名。作为一个实际示例，让我们创建一个名为 `foo.txt` 的简单文本文件，包含一些故意的拼写错误。

```bash
@linuxbox -$ cat > foo.txt
The quick brown fox jinps over the lazy dog.
```

接下来，我们将使用 `aspell` 检查该文件：

```bash
@linuxbox-$$ aspell check foo.txt
```

由于 `aspell` 在检查模式下是交互式的，我们将看到类似这样的屏幕：

如果我们按下 1，`aspell` 会将错误单词替换为 `jumps`，并移动到下一个拼写错误的单词，即 `lazy`。如果我们选择替换为 `lazy`，`aspell` 就会替换它并终止。一旦 `aspell` 完成，我们就可以检查文件并发现拼写错误已经被纠正。

```bash
me@linux:~~$ cat foo.txt

```

```bash
me@linuxbox ~$ sed -i 's/lazy/lazy;s/jumps/jimps/' foo.txt
```

`sed` 选项 `-i` 告诉我们“原地”编辑文件，这意味着而不是将编辑后的输出发送到标准输出，它将应用更改并重写文件。我们还看到通过分号分隔，可以在同一行中放置多个编辑命令。

## 总结

在本章中，我们查看了一些工具。在下一章中，我们将查看更多。Linux 中有很多可用工具，但我们关注的是特别实用的工具。

`--n format` | 将行号格式设置为 `format`，其中 `format` 为以下内容之一：

`ln` = 左对齐，不包含前导零。

`rn` = 右对齐，不包含前导零。这是默认值。

`rz` = 右对齐，包含前导零。

`-p` | 在每个逻辑页的开始时不重置页码。

`-s string` | 在每个行号末尾添加字符串以创建分隔符。默认是一个单个制表符字符。

`-v number` | 将每个逻辑页的第一行号设置为 `number`。默认值是 1。

`-w width` | 将行号字段的宽度设置为 `width`。默认值是 6。

诚然，我们可能不会经常对行进行编号，但可以使用 `nl` 来观察我们如何结合多个工具来执行更复杂的任务。我们将基于上一章的工作来生成一份 Linux 发行版报告。由于我们将使用 `nl`，因此包含它的头部/正文/页脚标记将很有用。为了实现这一点，我们将将其添加到上一章的脚本中。使用文本编辑器，我们将如下修改脚本并将其保存为 `ros-nl.sed`。

该脚本插入了 `nl` 逻辑页标记并在报告末尾添加了页脚。注意，我们在标记中必须双写反斜杠，因为它们通常会被 `sed` 解释为转义字符。
