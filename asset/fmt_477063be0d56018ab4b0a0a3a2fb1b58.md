## rm — 删除文件和目录

`rm` 命令用于删除文件和目录，如下例所示：

```
rm item...
```

在这里，`item` 是一个或多个文件或目录。

## 有用的选项和示例

表 4-8 描述了 `rm` 的一些常用选项。

| 选项 | 含义 |
|---|---|
| `-l` `--interactive` | 在删除现有文件之前，提示用户确认。如果未指定此选项，`rm` 将静默删除文件。 |
| `-r` `--recursive` | 递归删除目录。这意味着如果要删除的目录包含子目录，也将删除它们。要删除目录，必须指定此选项。 |
| `-f` `--force` | 忽略不存在的文件且不提示。这会覆盖 `--interactive` 选项。 |

> 谨慎使用 RM！

Linux 等类 Unix 操作系统没有“撤销”命令。一旦用 `rm` 删除了东西，它就消失了。Linux 假设你是智能的并知道自己在做什么。

要特别小心通配符。考虑这个经典示例：假设你只想删除目录中的 HTML 文件。要做到这一点，你输入：

```
rm *.html
```

这是正确的，但如果你不小心在 `*` 和 `.html` 之间加了一个空格，如下例所示：

```
rm * .html
```

`rm` 命令将删除目录中的所有文件，然后抱怨没有名为 `.html` 的文件。

这里有一个实用的提示：每当你使用 `rm` 使用通配符时（仔细检查你的输入之外！），请先用 `ls` 测试通配符。这将让你看到将被删除的文件。然后按方向键调回命令，并将 `ls` 替换为 `rm`。


## 硬链接

硬链接是创建链接的原始 Unix 方式，与符号链接相比，后者更现代。默认情况下，每个文件都有一个硬链接，为文件提供了名称。当我们创建一个硬链接时，会为文件创建一个额外的目录项。硬链接有两个重要的限制：

- 硬链接不能引用文件系统之外的文件。这意味着链接不能引用不在同一磁盘分区的文件。
- 硬链接可能引用目录。

硬链接与文件本身无法区分。与符号链接不同，当我们列出包含硬链接的目录时，看不到特殊指示。当硬链接删除时，链接被移除，但文件本身继续存在（也就是说，直到文件的所有链接都被删除为止，空间才会被释放）。

了解硬链接很重要，因为你可能会经常遇到它们，但现代实践更倾向于符号链接。

## 符号链接

符号链接是为了克服硬链接的局限性而创建的。它们的工作原理创建一个特殊类型的文件，包含指向引用文件或目录的指针。在这方面，它们的运行方式非常相似。符号链接和文件本身在很大程度上无法区分。例如，如果我们写入符号链接，引用的文件也被写入。然而，当我们删除符号链接时，只有链接被删除。如果文件被删除，符号链接将继续存在但指向为空。在这种情况下，链接被认为是*损坏的*。在许多实现中，`ls` 命令将以颜色（如红色）显示损坏链接的存在。

链接的概念可能令人困惑，但我们将尝试所有这些，它会变得清晰。

## 构建 playground

由于我们要进行真实的文件操作，让我们建立一个工作的地方吧。首先我们需要一个目录。我们会在主目录下创建一个并将其命名为 `playground`。

## 创建目录

`mkdir` 命令用于创建目录。为了创建 `playground` 目录，我们首先确保自己在主目录下，然后创建新目录。

```
$ ls
$ mkdir playground
```

为了让我们的 `playground` 更有趣，我们在里面创建两个目录 `dir1` 和 `dir2`。为了这样做，我们将当前工作目录改为 `playground` 并执行另一个 `mkdir`。

```
[me@linux ~]$ cd playground
[me@linux playground]$ mkdir dir1 dir2
```

注意 `mkdir` 命令接受多个参数，允许我们一次性创建两个目录。

## 复制文件

接下来，为我们的 获取一些数据。我们将通过复制文件来实现。使用 `cp` 命令，将 `/etc` 目录下的密码文件复制到当前工作目录：

```
[me@linux playground]$ cp /etc/passwd
```

注意我们如何使用点 `.` 表示当前工作目录。现在如果我们执行 `ls`，将看到以下内容：

```
[me@linux playground]$ ls -l
total 12
drwxr-xr-x 2 root root 4096 2025-01-10 16:40 dir1
drwxr-xr-x 2 root root 4096 2025-01-10 16:40 dir2
-rw-r--r-- 1 root root [size] [date] passwd
```

## 移动和重命名文件

接下来，看看 `mv` 的效果。首先，我们将数据文件移动到 `dir2`：

```
[me@linux playground]$ mv passwd dir2
```

注意由于 `dir2` 已经存在，`mv` 移动了 `dir1`。如果 `dir2` 不存在，`mv` 将重命名 `dir1`。最后，我们将所有内容放回去：

```
[me@linux playground]$ mv dir2 dir1
[me@linux playground]$ mv dir1 .
```

## 创建硬链接

现在我们将尝试一些链接。我们首先这样为数据文件创建硬链接：

```
[me@linux playground]$ ln fun fun-hard
[me@linux playground]$ ln fun dir1/fun-hard
[me@linux playground]$ ln fun dir2/fun-hard
```

所以我们有四个 `fun` 实例。看一下我们的 `playground` 目录：

```
[me@linux playground]$ ls -l
total 16
drwxr-xr-x 2 root root 4096 2025-01-14 16:17 dir1
drwxr-xr-x 2 root root 4096 2025-01-14 16:17 dir2
-rw-r--r-- 4 root root 1658 2025-01-10 16:33 fun
-rw-r--r-- 4 root root 1658 2025-01-10 16:33 fun-hard
```

我们注意到的一点是，`fun` 和 `fun-hard` 列表中的第二个字段包含 4，即该文件存在的硬链接数量。文件始终至少有一个链接，因为文件名称是由链接创建的。所以，我们如何知道 `fun` 和 `fun-hard` 实际上是同一个文件呢？在这种情况下，`ls` 并不很有帮助。虽然我们可以看到 `fun` 和 `fun-hard` 的大小相同（字段 5），但我们的输出列表提供了

无法确定。为了解决这个问题，我们需要更深入地探讨。

在思考硬链接时，想象文件由两个部分组成会有帮助：

- 包含文件内容的数据部分
- 存储文件名的名称部分

当我们创建硬链接时，我们实际上是创建了额外的名称部分，这些部分都指向同一个数据部分。系统将一组磁盘块分配给一个被称为 *inode*（索引节点）的对象，*inode* 与名称部分关联。因此，每个硬链接都指向一个包含文件内容的特定 *inode*。

`ls` 命令显示这些信息的工具。它通过 `-i` 选项调用：

```bash
$me@linux playground]$ ls -lt
total 16
12355338 drwxr-xr-x 2 me 4096 02-01 16:17 dir1
12355340 drwxr-xr-x 2 me 4096 02-01 16:17 dir2
12355338 -rw-rr-- 4 me 1650 02-10 16:13 fun
12355338 -rw-r--r-- 4 me 1650 02-10 16:33 fun-hard
```

在这个版本的列表中，第一个字段是 *inode* 号，正如我们看到的，*fun* 和 *fun-hard* 共享相同的 *inode* 号，这证实了它们是同一个文件。

## 创建符号链接

创建符号链接是为了克服硬链接的两个缺点。

- 硬链接不能跨越物理设备。
- 硬链接不能引用目录，只能引用文件。

符号链接是一种特殊类型，包含指向目标文件或目录的指针。

创建符号链接与创建硬链接相似：

```bash
$me@linux playground]$ ls -s fun fun-sym
$me@linux playground]$ ls -s .. /dir1/fun-sym
$me@linux playground]$ ls -s .. /dir2/fun-sym
```

第一个例子非常直观；我们只需添加 `-s` 选项来创建符号链接而不是硬链接。但下一个呢？记住，当我们创建符号链接时，我们创建的是关于目标文件相对于符号链接位置的描述。查看这里显示的 `ls` 输出会更容易看到这一点：

```bash
$me@linux playground]$ ls -l dir1
total 4
-rw-r--r-- 4 me 1650 02-10 16:33 fun-hard
-lrwxrxr-x 1 me 6 2025-01-15 15:17 fun-sym -> ../fun
```

`dir1` 中 `fun-sym` 的列表显示，由于第一个字段开头的 `\`，它是一个符号链接，并且指向 `../fun`，这是正确的。相对于 `fun-sym` 的位置，`fun` 位于它的上级目录。同样注意，符号链接的长度为 6，即字符串 `..fun` 的字符数，而不是它所指向的文件长度。

创建符号链接时，可以使用绝对路径，如下所示：

```bash
me@linuxbox playground]$ ls -s /home/me/playground/fun dir/Fun-sym
```

或者使用相对路径，正如我们在早的示例中做的那样。在大多数情况下，使用相对路径允许包含符号链接及其引用文件的目录树被重命名，而不会破坏链接。

除了普通链接，符号链接还可以引用目录：

```bash
me@linuxbox playground]$ ls -s dir-sym
me@linuxbox playground]$ ls -l
total 16
drwxr-xr-x 2 ne 4096 2025-01-15 15:17 dir
drwxr-xr-x 2 ne 4096 2025-01-16 14:45 dir1
drwxr-xr-x 2 ne 4096 2025-01-15 15:17 dir2
-rw-r--r-- 4 ne 1639 2025-01-10 16:33 fun
-rw-r--r-- 4 ne 1639 2025-01-10 16:33 fun-hard
drwxr-xr-x 1 ne 4096 2025-01-15 15:15 fun-sym -> fun
```

正如我们涵盖过的，`rm` 命令用于删除文件和目录。我们将用它来清理一下我们的实验场。首先，让我们删除一个硬链接：

## help—获取 Shell 内置命令的帮助

`bash` 为每个 shell 内置命令提供了内置的帮助设施。要使用它，输入 `help` 后跟上 shell 内置命令的名称。以下是一个示例：

```
[me@linuxbox ~] help cd
cd -[-L][-P] [-e] [-@] dir

```

将当前目录更改为 DIR。默认的 DIR 是 `HOME` 变量的值。

变量 `CDPATH` 定义了对包含 DIR 的目录的搜索。`CDPATH` 中的替代名称用冒号（:）隔开。空目录名等同于当前目录。如果 DIR 以斜杠（/) 开头，则不使用 `CDPATH`。

如果未找到目录，并且设置了 shell 选项 'cdable_vars'，该单词被视为变量名。如果该变量有值，则使用该值作为 DIR。

选项：
