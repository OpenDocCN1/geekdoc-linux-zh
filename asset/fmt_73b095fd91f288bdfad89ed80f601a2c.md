
```bash
#!/usr/bin/env bash

if systemctl is-active --quiet systemd-timesyncd || systemctl is-active --quiet chrony || systemctl is-active --quiet ntp; then
  output="Time synchronization daemon is active"
  
  if systemctl is-active --quiet systemd-timesyncd; then
    if systemctl is-active --quiet chrony || systemctl is-active --quiet ntp; then
      output="Multiple synchronization daemons are active: systemd-timesyncd and others"
    fi
  fi
  
  if systemctl is-active --quiet chrony; then
    if systemctl is-active --quiet systemd-timesyncd || systemctl is-active --quiet ntp; then
      output="Multiple synchronization daemons are active: chrony and others"
    fi
  fi
  
  if systemctl is-active --quiet ntp; then
    if systemctl is-active --quiet systemd-timesyncd || systemctl is-active --quiet chrony; then
      output="Multiple synchronization daemons are active: ntp and others"
    fi
  fi
else
  output="No time synchronization daemon is active"
fi

if [[ "$output" == *"Multiple"* ]]; then
  echo -e "\n- FAIL:\n$output\n"
elif [[ "$output" == *"No"* ]]; then
  echo -e "\n- FAIL:\n$output\n"
else
  echo -e "\n- PASS:\n$output\n"
fi
```

## 2.1.2 配置 chrony

`chrony` 是一个实现网络时间协议 (`NTP`) 的守护进程，旨在同步各种系统中的时钟，并使用高精度的源。

`chrony` 可以被配置为客户端和/或服务器。

关于 `chrony` 的更多信息可以访问：`http://chrony.tuxfamily.org/`。

注意：

- 如果使用了 `ntp` 或 `systemd-timesyncd`，则应移除 `chrony` 并跳过此节
- 系统上应只使用一种时间同步方法

## 2.1.2.1 确保 chrony 配置了授权的时间服务器（手动）

策略适用性：

- Level 1 - 服务器
- Level 1 - 工作站

描述：

- `server`
  - `server` 指令指定了一个可以作为时间源的 `NTP` 服务器。客户端-服务器关系是严格分层的：客户端可能会将其系统时间同步到服务器的系统时间，但服务器的系统时间永远不会受到客户端时间的影响。
  - 该指令可以使用多次来指定多个服务器。
  - 指令后紧跟的是服务器的名称或其 `IP` 地址。
- `pool`
  - 该指令的语法与 `server` 指令类似，不同之处在于用于指定 `NTP` 服务器池，而不是单个 `NTP` 服务器。池名称预计会解析为多个地址，这些地址可能会随时间发生变化。
  - 该指令可以使用多次来指定多个池。
  - `server` 指令中有效的所有选项也可以在此指令中使用。

原理：

时间同步对于支持对时间敏感的安全机制至关重要，并能确保企业内部的日志文件具有一致的时间记录，以协助取证调查。

审计：

如果系统上在使用 `chrony`，运行以下命令来显示 `server` / 或 `pool` 指令：

```bash
# grep -Pr --include=.(sources,conf) '\^h*(server|pool)\h+\H+' /etc/chrony/
```

验证返回的结果至少有一行 `pool` 行或至少三行 `server` 行，且返回行上的时间服务器遵循本地站点策略。

输出示例：

```
pool time.nist.gov iburst maxources 4 #The maxources 选项是 pool 指令特有的
```

`server` 指令：

```
server time-a-g.nist.gov iburst
server 132.163.97,3 iburst
```

修复措施：

编辑 `/etc/chrony/chrony.conf` 或以 `.sources` 结尾的文件，根据本地站点策略添加 `pool` 或 `server` 行：

```
pool time.nist.gov iburst maxources 4 #The maxources 选项是 pool 指令特有的
```

`server` 指令：

```
server time-a-g.nist.gov iburst
server 132.163.97,3 iburst
```

或者

如果系统上使用了其他时间同步服务，运行以下命令移除 `chrony`：

```bash
# apt purge chrony
```

引用：

1. `chrony(5)`
2. `https://chrony.net/`

附加信息：

如果在 `/etc/chrony/sources` 中设置了 `pool` 和 `server` 指令，则必须位于 `/etc/chrony/chrony.conf` 中。

## 2.1.4 配置 ntp

`ntp` 是一个实现网络时间协议 (`NTP`) 的守护进程。它旨在同步各种系统上的时钟，并使用高度准确的源。有关 `NTP` 的更多信息可以访问 `http://www.ntp.org`。`ntp` 可以被配置为客户端和/或服务器。

**注意：**

- 如果使用了 `chrony` 或 `systemd-timesyncd`，则应移除 `ntp` 并跳过本节。
- 此建议仅适用于系统正在使用 `ntp` 的情况。
- 系统上应仅使用一种时间同步方法。

### 2.1.4.1 确保 ntp 访问控制已配置（自动化）

策略适用性：

- 等级 1 - 服务器
- 等级 1 - 工作站

描述：

```
ntp restrict address [mask mask] [ippeerlimit int] [flag ...]
```

以点分位形式表示的参数是主机或网络的地址。或者，地址参数也可以是有效的 `DNS` 名称。

以点分位形式表示的掩码（`mask`）默认为 `255.255.255.255`，这意味着该地址被视为单个主机的地址。始终包含一个默认项（地址 `0.0.0.0`，掩码 `0.0.0.0`），且它始终是列表中的第一项。**注意：** 不带掩码选项的文本字符串 `default` 可表示默认项。

`ippeerlimit` 指令限制了每个 `IP` 的对等请求数量为 `int`，其中值 `-1` 表示“无限制”（这是当前默认值）。值 `0` 表示“无”。通常每个 `IP` 最多有 1 个对等请求，但如果远程请求位于代理之后，每个 `IP` 的可能会超过 1 个。在当前实现中，标志（`flag`）始终会限制访问，即没有标志的条目表示允许自由访问服务器。

标志之间不是正交的，因为更严格的标志通常会让较松散的标志变得冗余。标志通常可以分为两类：限制时间服务的标志和限制信息查询的标志。

理由：

时间同步对于支持时间敏感的安全机制以及确保整个企业的日志文件具有一致的时间记录（以协助取证调查）关重要。对 `NTP` 进行适当的访问控制对于防止未经授权的客户端操纵系统时间至关重要。

审计：

如果系统正在使用 `ntp`，请检查配置文件（通常位于 `/etc/ntp.conf`）。

如果系统正在使用 `systemd-timesyncd`，请运行以下命令：

运行以下命令验证 `systemd-timesyncd` 服务是否已启用：

```
# systemctl is-enabled systemd-timesyncd.service
enabled
```

运行以下命令验证 `systemd-timesyncd` 服务是否处于激活状态：

```
# systemctl is-active systemd-timesyncd.service
active
```

修复：

如果系统正在使用 `systemd-timesyncd`，请运行以下命令：

运行以下命令取消 `systemd-timesyncd.service` 的掩码（`unmask`）：

```
# systemctl unmask systemd-timesyncd.service
```

运行以下命令启用并启动 `systemd-timesyncd.service`：

```
# systemctl --now enable systemd-timesyncd.service
```

或者

如果系统正在使用其他时间同步服务，运行以下命令停止并锁定（`mask`）`systemd-timesyncd`：

```
# systemctl --now mask systemd-timesyncd.service
```

如果正在使用 `ntp`，请编辑 `/etc/ntp.conf` 以包含适当的访问控制限制：

```
restrict -4 default kod modify notrap nooper noquery
restrict -6 default kod modify notrap nooper noquery
```

默认值：

```
restrict -4 default kod modify notrap nooper noquery limited
restrict -6 default kod modify notrap nooper noquery limited
```

## 2.1.4.2 确保 ntp 已配置授权的时间服务器（手动）

Profile Applicability:

- Level 1 - 服务器
- Level 1 - 工作站

Description:

各种模式由命令关键字和所需 `IP` 地址的类型决定。地址按类型分类：(s) 远程服务器或对等 (`IPv4` A、B 和 C 类)，(b) 本地接口的广播地址，(m) 组播地址 (`IPv4` D 类)，或 (r) 参考时钟地址 (`127.27.x.x`)。

Note：下方仅列出适用于每个命令的选项。使用未列出的选项可能会被视为错误，但可能导致某些异常甚至是破坏性的行为。

如果检测到 `IPv6` 基本套接接口扩展 (`RFC-2553`)，除了默认的 `IPv4` 地址族支持外，还会生成对 `IPv6` 地址族的支持。在某些情况下，`ntp` 或 `ntpd` 生成的 `IPv6` 地址公告会自动生成。`IPv6` 地址可以通过地址字段中是否存在冒号 `:` 来识别。`IPv6` 地址几乎可以在任何可以使用 `IPv4` 地址的地方使用，但参考时钟地址除外，参考时钟始终是 `IPv4`。

在预期主机名的上下文中，在主机名之前的 `-4` 限定符将强制将 `DNS` 解析到 `IPv4` 命名空间，而 `-6` 限定符将强制将 `DNS` 解析到 `IPv6` 命名空间。`IPv6` 引用对应该族中的等效类。
