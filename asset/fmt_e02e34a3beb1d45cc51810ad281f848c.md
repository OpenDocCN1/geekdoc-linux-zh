
报告的维度是针对越权访问点（`AP`）的审查。测试人员将通过 `RSSI` 信号分析和三角定位法找到违规设备。渗透测试人员应当注意环境网络（`circumstantial networks`）。虚假的“免费 Wi-Fi”会开放网络并引入恶意的越权用户。只需确保测试人员正在寻找位于环境中、但连接到未获得贵公司许可的 `SSID` 的设备。

通过将公司资源连接到另一个 Wi-Fi 网络，可能会出于多种原因产生危险。其中一些包括区域单位度假地攻击、钓鱼攻击、中间人攻击 (`MITM`) 等。在2017 年，无线热点随处可见。进入咖啡店和披萨店确实非常方便，但对你的公司资产来说可能非常危险。在不涉及细节的情况下，如果你的员工进入开放网络，可能会让你的业务面临危险。成功的测试人员将寻找这一点，并查看这些热点在哪里以及 `SSID` 是什么。然后你就可以采取措施帮助告知用户并正确配置端点。

自从几年前 `WEP` 被破解以来，市场上出现了许多免费工具来帮助破解预共享密钥（`PSK`）。令人置信的是，这些设备甚至可以破解 `WPA` 和 `WPA2`。一个全面的渗透测试员应该检查是否能在短时间内（几小时或几天内）破解任何预共享密钥。这将作为一种冲击性因素，证明一个普通的 8 字符或 10 字符密钥被破解的速度有多快。筛选后，将 `PSK` 馈给密码强度工具中，以显示代码的相对强度。

## 理解 IEEE 802.11 及其他无线 MAC 层

数据是区分专业人士与外行者的标准。一个想要通过 `WLAN` 利用你网络的优秀渗透测试员需要对 `802.11` `MAC` 和 `PHY` 层有深入的了解。此外，必须对任何直接连接（`ad hoc`）基础设施网络具有关联水平的理解。其目标是充分理解站点认证和关联的阶段。需要了解三种类型的包：管理包、控制包和数据包及其头部。

## Web 应用

Web 应用测试是在进入生产环境之前检查 Web 应用程序漏洞的一种简单方法。

### 1. 功能测试

用于检查产品是否符合已概述的要求。

- 确保所有连接均正常。
- 检查断链。
- 确保表单按预期工作。
- 例如，如果用户未必填字段，将显示错误消息。
- `Cookie` 是网站用于记住活动用户会话的小文件，因此无需每次都登录。`Cookie` 监控包括检查在清除缓存或过期时删除 `Cookie`。删除 `Cookie` 并并在访问网站时请求详情。

### 2. 易用性测试

易用性测试由用户或目标用户的焦点小组进行。

- 测试网站导航：菜单、按钮和不同页面之间的链接应当清晰可见并保持一致。
- 审查内容：内容应可读且无拼写或语法错误。
- 图片必须包含 `alt` 文本。

### 3. 接口测试

此处需要评估三个领域——应用、互联网和数据库服务器。

- 应用：测试请求是否正确发送到数据库。此外，客户端的展示必须有效。任何错误都应被程序捕获，并仅显示给管理员，而不是终端用户。
- 互联网服务器：检查 Web 服务器是否处理所有客户端请求而不拒绝服务。
- 数据库服务器：确保发送到数据库的查询给出正常结果。

当三层之间无法建立连接时，检查设备回答以及正确的消息。

## 标准执行

确保遵循 `W3C`、`OASIS`、`IETF`、`ISO`、`ECMA` 和 `WS-I` 等原则。检查端到端的工作流场景，即引导消费者通过一系列网页完成操作。同样要检查负面场景，以便在客户采取意料操作时，你的 Web 应用程序能够显示正确的错误消息或支持。

- 4. 数据库测试：数据库是你的 Web 应用的基础部分，预计需要对其进行全面检查。研究任务将包括：
  - 测试在请求执行期间是否显示任何错误。
  - 在数据库中生成、修改或删除数据时，应维护信息的完整性。
  - 检查查询的响应时间，并在必要时进行调整。
  - 从你的数据库中恢复测试的数据将在你的 Web 应用程序工具中清晰显示，可以使用这些工具：`QTP`、`Selenium`。

- 5. 可靠性验证。

兼容性检查确保你的 Web 应用在不同设备上都能正确显示。这包括：

- 浏览器兼容性测试：同一个网站在多个浏览器中看起来可能不同。你需要检查你的 Web 应用是否通过浏览器正确显示，以及 `JavaScript`、`AJAX` 和加密是否工作正常。你也可以测试移动 App 的兼容性。
互联网元素（如按钮、文本字段等）的布局随操作系统的改进而变化。确保网站在 Windows、Linux、Mac 等各种操作系统以及 Chrome、Internet Explorer、Safari 等浏览器的组合下完美运行。可以使用软件：`NetMechanic`。

- 6. 速度测试：这将确保你的网站在所有负载下都能工作。软件测试任务将包括（但不限于）：
  - 在完全不同的关联速度下的网站应用响应时间。
  - 给你的互联网应用负载，以测试其在常规和峰值负载下的操作。
  - 对你的网站进行压力测试，以确定在被推向超过平均峰值负载时的崩溃点。
检查是否由于峰值负载导致崩溃、发生此类情况后页面如何恢复。确保允许使用 `gzip` 压缩、应用和服务器端缓存等优化技术以缩短加载时间。可以使用软件：`Loadrunner`、`JMeter`。

- 7. 合规性筛选：安全测试对于存储敏感客户信息（如信用卡信息）的电子商务网站非常重要。测试活动将包括：
  - 不允许对受保护站点进行未经授权的访问。
  - 不允许下载下载限制文件。
  - 检查 `Session` 在延迟后应自然执行。
  - 使用 `SSL` 证书时，网站必须切换到加密的 `SSL` 页面。
可以使用的工具：`Babel Enterprise`、`FBBTester` 和 `CROSS`。

- 8. 群组测试：你应该挑选大量个人（群体）来引导测试，这些测试本可以通过某种方式由业务中的精选人员完成。研究是一种令人兴奋且新兴的现象，有助于揭示大多数隐藏缺陷。
可以使用工具：像你和我这样的人！！！没错，有很多！

教程到此结束。包含了对你的 Web 应用重要的几乎所有筛选形式。

作为一名 Web 测试人员，需要注意的是 Web 测试是一个非常困难的过程，你不可避免会遇到很多障碍。当然，你将面临的主要问题之一是截止日的压力。昨天，一切都是必要的！代码需要更改的次数也令人心累。确保你安排好工作并了解他人对你的期望。最好的方法是识别 Web 测试涉及的所有活动，并创建一个工作图表，以便进行可靠的估计和调度。

前提条件：你希望了解 Web 是如何工作的，并理解在线页面（`page`）、网站（`site`）、在线服务器和搜索引擎之间的区别。

目标：你将学习什么是在线服务器，并且你可能对它的工作原理有一个通用的理解。

“Web 服务器”可能指设备或编程，或者两者共同工作。

在硬件方面，互联网|在线服务器可能是一个存储 Web 服务器代码和网站部分文件的 PC（例如 `HTML` 文档、图像、`CSS` 样式表和 `JavaScript` 文件）。它连接到互联网，并方便与连接到互联网的其他设备共享物理数据。
