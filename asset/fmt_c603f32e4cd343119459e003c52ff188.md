
# 按进程启用探针

在内核模式下，你可以选择一组启用探针的进程。这种模式被称为“过滤器模式”。默认情况下，过滤器模式关闭关闭，所有进程在命中探针时都会生成跟踪记录。按照约定，这些事件被认为是由进程 ID 0 生成的。

`prex` 用于开启和关闭过滤器模式、获取过滤器开关状态、从过滤器集中添加或删除进程，以及列出当前过滤器集。当过滤器中的进程退出时，其进程 ID 会被自动删除。以下命令控制过滤器开关和过滤器成员。

```
pfilter [on | off | add pidlist | delete list]
```

# 跟踪输出写入内存

在内核模式下，跟踪输出写入内存。以下命令控制过滤器开关和缓冲区分配。

```
pfilter [on | off | alloc [size]]
```

不带参数时，`pfilter` 打印当前过滤器集和主开关的状态。`on` 或 `off` 设置过滤器模式。

```
alloc [size]
```

分配缓冲区。`size` 单位为字节。

## 示例

参阅 `tracing(3)` 获取完整示例，其中展示了如何使用 `prex` 进行简单的探针控制。

当启动进程或内核时，所有探针都是启用的。

```
# 集合创建和列表

create $out name=/out/      # $out = name 属性包含 /out/ 的探针

create $foo/page/ name=biodone  # $foo = keys 属性包含 "page" 的探针

      # 与 name 属性为 "biodone" 的探针取集

list sets                      # 列出定义的集合

list fcns                      # 列出定义的探针函数
```

# 跟踪和连接探针函数的命令

```
trace foobar='on'      # foobar 属性精确匹配
trace $all                   # 跟踪所有探针（预定义集 $all）
connectdebug $foo          #为 $foo 中的探针连接调试函数
```

# 启用和禁用探针的命令

```
enable $all                  # 启用所有探针

enable /vm/ name=alloc      # 启用指定的探针
```

## prex 1059

```
disable $foo # 禁用 $foo 中的探针
list history # 列出发出的探针控制命令
```

# 进程控制

```
continue # 恢复目标进程
^C # 停止目标；将控制权交给 plex
quit resume # 退出 plex，让进程运行
```

# 内核模式

```
buffer alloc 2m # 分配一个2兆字节的缓冲区
enable $all # 启用所有探针
trace $all # 跟踪所有探针
ktrace on # 开启跟踪
tktrace off # 关闭跟踪
pilter on # 开启进程过滤模式
pilter on 1379 #将 pid 1379 添加到进程过滤器
tktrace on # 开启跟踪
# (仅跟踪 pid 1379)
```

### 缺陷

当进程 ID 从过滤器集中自动删除时，`prex` 应该发出通知。
`prex` 中的一个已知缺陷会导致以下消息：
由于内部错误，目标程序跟踪关闭 - 请重启 `prex` 和目标

## 1060

当你以 `root` 身份运行 `plex` 时，目标进程不是 `root`，且你将跟踪文件放在一个无法删除和重新创建的目录中（例如带有粘滞位的 `/tmp` 目录），那么目标进程在需要时将无法打开跟踪文件，导致跟踪禁用。
改变上述任何情况都应解决此问题。要么不要以 `root` 身份运行 `plex`，要么以 `root` 身份运行目标进程，或者指定 `/tmp` 以外目录中的跟踪文件。
