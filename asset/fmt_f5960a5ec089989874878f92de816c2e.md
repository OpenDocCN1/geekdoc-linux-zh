
通过在环境中设置变量 `CFLAGS`，你可以让大多数 `Makefile` 中的所有 C 编译都使用你偏好的编译器开关。对于具有标准或习惯含义的变量，这是安全的，因为你知道 `Makefile` 会将它们用于其他用途（但这并非完全可靠；某些 `Makefile` 会显式设置 `CFLAGS`，因此不会使用该值）。

### 6.10 目标特定变量值 (Target-specific Values)

`Makefile` 中的值通常是全局的，这意味着无论在何处评估都是相同的（除非在目标处重置，见 10.5 [自动变量]，第 111 页）。目标特定值值允许你根据当前构建的目标为变量定义不同的值。这些值在目标脚本中是可用的。

按如下格式设置目标特定变量值：

```
target  ... : variable-assignment
```

或者按如下格式：

```
target  ... : override variable-assignment
```

多个目标值为目标列表中的每个成员单独创建一个目标特定变量值。变量赋值可以是任何有效的赋值形式：递归（`=`）、追加（`+=`）或条件（`?=`）。在目标赋值中出现的变量在目标上下文中评估；因此，任何先定义的目标特定变量将生效。

目标特定变量还有一个特殊特性：当你在定义一个目标特定变量时，该变量值对于该目标的所有依赖也有效（除非这些依赖项用自己的目标特定变量覆盖了它）。因此，例如这样的语句：

```
prog : CFLAGS = -g
prog : prog.o foo.o bar.o
```

将在 `prog` 的命令脚本中将 `CFLAGS` 设置为 `'-g'`，但它也会在创建 `prog.o`、`foo.o` 和 `bar.o` 的脚本中将 `CFLAGS` 设置为 `'-g'`。

### 6.11 模式特定变量值 (Pattern-specific Variable Values)

除了目标特定变量值（见 6.10 节 [目标特定变量值]，第 67 页），GNU `make` 支持模式特定变量值。在这种格式下，为任何匹配指定模式定义变量。以这种方式定义的变量搜索顺序位于显式定义的目标特定变量之后，在父目标的目标特定变量之前。

按如下格式设置模式特定变量值：

```
pattern ... : variable-assignment
```

其中 `pattern` 是一个 `%.pattern`。与目标特定变量值一样，多个模式值为每个模式单独创建一个模式特定变量值。变量赋值可以是任何有效的赋值形式。任何命令行变量设置将具有优先权，除非指定了 `override`。

例如：

```
%.o : CFLAGS = -0
```

将为匹配模式 `%.o` 的所有目标将 `CFLAGS` 设置为 `'-0'`。

## 第 7 章：Makefile 的条件部分

# 7 Makefile 的条件部分

条件语句根据变量的值决定 `Makefile` 的部分内容是被执行还是忽略。条件语句可以比较一个变量的值与另一个变量的值，或者一个变量的值与一个常量字符串的值。条件语句控制 `Makefile` 中实际能被“看到”的内容，因此它们不能用于控制执行时刻的 shell 命令。

### 7.1 条件示例

下面的条件示例告诉 `make`，如果变量 `CC` 等于 ‘gcc’，则使用一组库，否则使用另一组库。它的工作原理是控制使用哪两条命令行作为该规则的命令。结果是，当将 `CC=gcc` 作为一个参数时，`make` 不仅更改了使用哪种编译器，还更改了链接哪些库。

```
libs_for_gcc = -lgnu
normal_libs =

foo: $(objects)
ifeq ($(objects),gcc)
  $(CC) -o foo $(objects) $(libs_for_gcc)
else
  $(CC) -o foo $(objects) $(normal_libs)
endif
```

此条件语句使用了三个指令：一个 `ifeq`，一个 `else` 和一个 `endif`。`ifeq` 指令定义了条件并指定了条件。它包含两个由逗号分隔的参数，并用括号括起来。对两个参数都进行变量替换，然后进行比较。如果两个参数匹配，则执行 `ifeq` 之后的 `Makefile` 行；否则，这些行会被忽略。

`else` 指令在之前的条件失败时导致执行随后的行。在上面的示例中，这意味着每当不使用第一种备选时，就会使用第二种备选链接命令。在条件语句中，`else` 是可选的。

`endif` 指令结束条件语句。每个条件语句必须以 `endif` 结束。之后是无条件的 `Makefile` 文本。

如示例所示，条件语句是在文本层面工作的：条件语句的行根据条件被视为 `Makefile` 的一部分，或者被忽略。这就是为什么 `Makefile` 中较大的语法单元（如规则）可能会跨越条件语句的开始或结束。

当变量 `CC` 的值为 ‘gcc’ 时，上述示例产生以下效果：

```
foo: $(objects)
  $(CC) -o foo $(objects) $(libs_for_gcc)
```

当变量 `CC` 为任何其他值时，效果如下：

```
foo: $(objects)
$(CC) -o foo $(objects) $(normal_libs)
```
