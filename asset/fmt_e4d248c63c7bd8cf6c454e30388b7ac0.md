
`/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0`

```
/dev/sda4 /mnt/zipdrive vfat noauto,users,rw,exec,umask=000 0 0
```

这赋予了你的 zip 盘绝对权限（挂载、卸载、读、写、执行）。

总结来说，`/etc/fstab` 文件是存储如何挂载文件系统的默认以及允许用户什么类型访问的地方。你确实希望自定义它以简化系统的挂载。Linux 默认的挂载方案是限制性的，为了安全，在家庭中设置 Linux 时可能想要移除一些限制。

将 `ppa` 模块插入内核中。（我猜 "ppa" 代表“并行口优先接口”（`parallel port first interface`））

完成所有操作后，检查 `/proc/modules` 查看 `ppa` 模块是否已加载（或以 `root` 身份运行 `lsmod` 列出模块）。来自 `kernelcfg` 的信息会写入 `/etc/conf.modules` 文件，因此在删除模块（我误插入的 1）时会遇到困难——就像我刚刚那样——我手动编辑并调整了该文件。

现在你的 zip 驱动器应该被识别了。放入一个 zip 并尝试使用之前描述的命令（使用 `root`）进行挂载：

```
mount -t vfat /dev/sda4 /mnt/zipdrive
```

使用 Linux 内核 `v2.2.0.36` 及以下版本，你将无法使用通过并行口 zip 驱动器连接的打印机（这在内核 `2.2.x` 上有效）。使用命令

```
uname -a
```

查看运行的内核版本。

## RedHat 6.0 和 6.1

在升级到 RedHat 6.0 期间，zip 驱动器（`zip100` 驱动器）的安装没有成功（安装程序说找不到 `zipdrive`）。因此，安装完成后，我执行了以下命令以 `root` 身份将并行口 zip 驱动器的模块插入内核：

```
/sbin/insmod parport
/sbin/insmod ppa
```

为了让这两行代码在重启后自动执行，我将它们添加到 `/etc/rc.d/rc.local` 文件的末尾（该文件类似于 DOS 中的 `auto.bat`）。如果这对你仍然不起作用，你可能还想编辑 `/etc/conf.modules` 文件。我的文件包含这样的一行：

```
alias parport pc
```

并且没有提到 "ppa" 模块的行。对于较新的 `Zip250` 驱动器，我在 `/etc/rc.d/rc.local` 中执行了以下几行：

```
/sbin/insmod parport
/sbin/insmod
```

### 4.2.10 我可以设置 32 位硬盘 I/O 吗？

我对硬盘一无所知，但看到 Edward Choh（`http://hardwarezone.com.sg/main.htm`）对 RedHat 6.0 的评论，其中他给出了一些有趣的技巧，包括设置 32 位输入/输出（I/O）和直接内存访问（DMA）。我尝试了，对我来说效果很好。请注意，这可能会损坏你的硬盘，所以如果你是真正的新手、今天不想表现得极客，或者心不够大，请不要这样做。开启 32 位 I/O 和 DMA 必须完成的，我是在单用户模式下完成的（以在万一出错并需要重启时对文件系统造成的损害最小）。我绝对不会在当前运行许多程序或 `X-windows` 的系统中这样做，并且会对任何数据进行备份。

要以单用户模式启动电脑，请在 `lilo` 提示符处（启动启动期间）输入以下内容：

```
linux single
```

在我的第一个 IDE 硬盘（为 "`hda`"）上启用 32 位 I/O。首先，测试硬盘性能并记录得分：

```
hdparm -t /dev/hda
```

现在显示我当前的 I/O 和 DMA 设置：

```
hdparm -c /hda
```

（我的系统显示 0，意味着 32 位 I/O 已关闭并使用了默认的 16 位访问）

```
hdparm -d /hda
```

（我的系统再次显示 0，意味着硬盘 DMA 访问已关闭）。

现在，开启 32 位 I/O 和 DMA：

```
hdparm -c 1 /hda
hdparm -d 1 /hda
```

现在，我可以再次测试硬盘性能并与原始得分进行比较：

```
hdparm -t /dev/hda
```

如果一切运行正常且性能有所提高，我可以“提交”新设置以便它们在软重启后依然存在：

```
hdparm -k 1 /hda
```

为了在每次重启机器时新设置都生效，你可以在 `/etc/rc.d/rc.local` 文件的末尾添加一行（该文件类似于 DOS 中的 `AUTOEXEC.BAT`）：

```
hdparm -c 1 -d -k 1 /hda
```

如果某些操作没有按预期工作，或者性能没有真正提高，我可以随时重启，只要我没有执行最后一次操作，旧设置就会有效。

我在我们家庭网络的 4 块硬盘上进行了这种调优。在 3 块新硬盘上成功了；性能提升了 30-300%，至少有一台电脑“感觉”比以前快了。有一个硬盘（总是不稳定的）在性能测试期间导致电脑死机，我不得不重启机器（没有造成损坏）。

## 4.3 使用 X-windows 

### 4.3.1 我如何在 RedHat 5.2 上安装 kde？

RedHat 5.2 默认不安装 `kde`；在 RH5.2 发布时，`kde` 使用的一个库的许可出现了一个问题。除此之外，`kde` 是一个非常好的 GUI，库的问题现在已经解决，最新的 RedHat (6.0) 包含了 `kde`（以及更华的 GNOME）。尽管如此，`kde` 的二进制文件在你的 RedHat 5.2 CD 上，你只需要自己安装它们。（如果你没有 CD，可以从互联网上的 `kde` 网站下载二进制文件。）

首先执行以下命令检查你的 X-server 是否工作：

```
xinit
```

[X-server 是一个精简的 X-windows 系统，没有“窗口管理器”。你可以通过在 X-terminal 中输入程序名称（带前面的 `./` 或完整路径）从这里执行你的 X-windows 程序，但你将无法移动或调整窗口大小、添加图标等]

你可以通过输入 `exit` 或按下 `<Ctrl><Alt><Backspace>` 退出 X-server。如果 X-server 不工作，你可能需要调整该文件。

```
mount /etc/conf.modules
```

The information from `kernelcfg` goes to the file `/etc/conf.modules` so you have difficulty removing modules (1's inserted by mistake) -- as I just did -- edit and adjust this file manually.

Now your zip drive should be recognized. Put a zip disk in it and try mounting using the previously described command (as `root`):

```
mount -t vfat /dev/sda4 /mnt/zipdrive
```

Using the Linux kernel `v2.2.0.36` and below, you will not be able to use a printer which is connected through the parallel port zip drive (this works with the kernel `2.2.x`). Use the command

```
uname -a
```
