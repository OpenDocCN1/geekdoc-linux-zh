## 简介

在 Linux 上，一切都被视为文件。然而，某些文件会受到特殊对待，这是因为它们存储的位置（例如临时文件），或者它们与文件系统交互的方式（例如链接）。在本节中，我们将学习此类文件的位置、它们如何工作以及如何管理它们。

## 临时文件

临时文件被程序用于存储只需要短时间的数据。这可以是运行进程的数据、崩溃日志、自动保存产生的临时文件、文件转换过程中使用的中间文件、缓存文件等。

## 临时文件的位置

文件系统层级标准（FHS） 3.0 版本定义了 Linux 系统上临时文件的标准位置。

### `/tmp`
文件系统层级标准（FHS） 3.0 版本定义了 Linux 系统上临时文件的标准位置。

### `/var/tmp/`
文件系统层级标准（FHS） 3.0 版本定义了 Linux 系统上临时文件的标准位置。

### `/run`
文件系统层级标准（FHS） 3.0 版本定义了 Linux 系统上临时文件的标准位置。

### 粘滞位
文件系统层级标准（FHS） 3.0 版本定义了 Linux 系统上临时文件的标准位置。

## 临时文件的权限

既然系统“世界可写”，我们如何防止用户删除？解决方案是名为粘滞位的特殊权限，它适用于目录。当设置此特殊位时，它可以防止用户删除文件，除非该文件属于他们。例如，检查 `/tmp` 和 `/var/tmp` 的权限：

```bash
$ ls -ld /tmp /var/tmp
drwxrwxrwt 25 root 4.0K Jun 7 18:52 /tmp/
drwxrwxrwt 16 root 4.0K Jun 7 09:15 /var/tmp/
```

你可以看到 `t` 取替了其他 `x`，两个目录都设置了粘滞位。

使用数字模式为目录设置粘滞位，使用四位数法并将 1 作为第一位。例如：

```bash
$ chmod 1755 temp
```

将名为 `temp` 的目录设置粘滞位，权限为 `rwx-xr-t`。

当使用符号模式时，使用参数 `t`。所以，用 `+t` 设置粘滞位，用 `-t` 禁用它。如下：

```bash
$ chmod +t temp
```

## 理解链接

我们已经说过一切都被视为文件。但有一种特殊类型的文件称为链接，Linux 系统上有两种链接：

### 符号链接

也称为软链接，它们指向另一个文件的路径。如果你删除了链接所指向的文件（称为目标），链接仍然存在，但它会“停止工作”，因为它现在指向“空无”。

### 硬链接

将硬链接视为原始文件的第二个名称。它们不是副本，而是文件系统中指向同一位置（inode）的额外条目。

> inode 是一种用于存储文件系统中对象（文件或目录）属性的数据结构。这些属性包括文件名、权限、所有权以及数据存储在磁盘的哪些区块上。它可以被视为索引上的条目，因此名称源于“index node”

## 使用硬链接

## 创建硬链接

在 Linux 上创建硬链接的命令是 `ln`。基本语法为：

```bash
$ ln TARGET LINK_NAME
```

`TARGET` 必须已经存在（这是链接将指向的文件），如果目标不是当前目录，或者如果你想在其他地方创建链接，必须指定它的完整路径。例如，命令：

```bash
$ ln target.txt /home/carol/Documents/hardlink
```

将在 `/home/carol/Documents/` 目录下创建一个名为 `hardlink` 的文件，它指向当前目录下的文件 `target.txt`。

如果省略参数 (`LINK_NAME`)，则会在当前目录下创建一个与目标同名的链接。

### 管理硬链接

硬链接是文件系统中的项，它们具有不同的名称，但指向磁盘上的相同数据。所有名称都是等等的，都可以用于引用文件。如果你更改了某个名称的内容，所有指向该文件的名称的内容都会发生变化，因为所有这些名称都指向相同的数据。如果你删除其中一个名称，其他名称仍然有效。

当你“删除”文件时，文件实际上并没有从磁盘上擦除。系统只是删除了文件系统表中指向对应磁盘数据 inode（索引节点）的项。如果你有第二个指向相同 inode 的项，你仍然可以访问该数据。把它想象成两条汇聚在同点的道路。如果你封锁或重定向其中一条路，仍然可以通过另一条到达目的地。

你可以通过使用 `ls` 的 `-i` 参数检查这一点。考虑以下目录内容：

```bash
$ ls -li
total 224
3806696 -r--r--r-- 2 carol 111702 Jun 7 10:13 hardlink
3806696 -r--r--r-- 2 carol 111702 Jun 7 10:13 target.txt
```

前面的数字是 inode 编号。注意，文件 `hardlink` 和文件 `target.txt` 具有相同的数字 (`3806696`)？这是因为其中一个是另一个的硬链接。

但哪一个是原始文件，哪一个是链接呢？你无法判断，因为从实际操作角度来看，它们是相同的。

注意，每个指向文件的硬链接都会增加文件的链接计数。这是 `ls -1` 输出中权限之后的数字。默认情况下，每个文件的链接计数为 1（目录计数为 2），每个硬链接都会将计数加 1。这就是上述列表文件中文件链接计数为 2 的原因。

与符号链接不同，你只能对文件创建硬链接，且链接和目标必须位于同一个文件系统中。

### 移动和删除硬链接

由于硬链接被视为普通文件，可以使用 `rm` 删除它们，并使用 `mv` 在文件系统中重命名或移动。由于硬链接指向目标的相同 inode，它可以自由移动，而不必担心“断开”链接。

## 符号链接

### 创建符号链接

用于创建符号链接的命令也是 `ln`，但添加了 `-s` 参数。如下：

```bash
$ ln -s target.txt /home/carol/Documents/softlink
```

这将在 `/home/carol/Documents/` 目录下创建一个名为 `softlink` 的文件，指向当前目录下的文件 `target.txt`。

与硬链接一样，你可以省略链接名称，在当前目录下创建一个与目标同名的链接。

### 管理符号链接

符号链接指向文件系统中的另一个路径。你可以为文件和目录创建软链接，即使在不同的分区上。在 `ls` 的输出中很容易识别符号链接：

```bash
$ ls -lh
total 112K
-rw-r--r-- 1 carol 110K Jun 7 10:13 target.txt
lrwxrwxr-wx 1 carol 12 Jun 7 10:14 softlink -> target.txt
```

在示例中，文件链接权限的首位字符是 `l`，表示这是一个符号链接。此外，在文件名之后，我们看到链接指向的目标，即文件 `target.txt`。

注意，在文件和目录列表中，软链接本身始终显示对用户、组和其他人的 `rwx` 权限，但在实践中，它们的权限与目标相同。

### 移动和删除符号链接

与硬链接一样，可以使用 `rm` 符号链接，并使用 `mv` 移动或重命名它们。然而，在创建它们时应特别小心，以避免当它们从原始位置移动时出现“断开”链接。

在创建符号链接时，你应该意识到，除非完整指定路径，否则目标的位置将被解释为相对于链接位置的相对路径。如果链接或它指向的文件被移动，可能会产生问题。

通过示例可以更容易理解。假设我们在当前目录下有一个名为 `original.txt` 的文件，并想为它创建一个名为 `softlink` 的符号链接。我们可以使用：

```bash
$ ln -s original.txt softlink
```

显然一切正常。让我们用 `ls` 检查：

```bash
$ ls -lh
total 112K
-r--r--r-- 1 carol Jun 7 10:13 original.txt
lrwxrwxwx 1 carol 12 Jun 7 19:23 softlink -> original.txt
```

看链接是如何构建的：`softlink` 指向 `original.txt`。

等等，我们将链接移动到另一个目录会发生什么：

```bash
$ mv softlink ../
$ ls -lh ../
total 112K
```
