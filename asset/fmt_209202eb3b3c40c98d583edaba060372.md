## 白点调整程序和客户端数据

这些属性的初始值取决于实现。后续创建的 CCC 的属性可以通过更改默认 CCC 的属性来定义。每个屏幕都关联有一个默认 CCC。

## 获取和设置调色板的颜色转换上下文

要获取与色板关联的 CCC，请使用 `XmsQueryColor`。

```
XmsCCC XmsQueryColor(display, colormap);
```

`display` 指定与 X 服务器的连接。

`colormap` 指定调色板。

`XmsQueryColor` 函数返回与指定调色板关联的 CCC。一旦获取，就可以对属性进行查询或修改。除非使用 `XmsSetColor` 修改了与调色板关联的 CCC，否则当调色板作为函数参数使用时将使用此 CCC。

要更改与调色板关联的 CCC，请使用 `XmsSetColor`。

```
Status XmsSetColor(display, colormap, ccc);
```

`display` 指定与 X 服务器的连接。

`colormap` 指定调色板。

`ccc` 指定 CCC。

`XmsSetColor` 函数更改与指定调色板关联的 CCC。它返回之前与调色板关联的 CCC。多个调色板可以无限制地共享同一个 CCC；但 Xlib 生成的 CCC 会为每个调色板创建一个新的 CCC。

## 获取默认颜色转换上下文

你可以通过更改默认 CCC 的属性来更改后续创建的 CCC 的属性。每个屏幕都关联有一个默认 CCC。要获取屏幕的默认 CCC，请使用 `XmsDefaultCCC`。

```
XmsDefaultCCC(display, screen_number);
```

`display` 指定与 X 服务器的连接。

`screen_number` 指定主机服务器上适当的屏幕编号。

`XmsDefaultCCC` 函数返回指定屏幕的默认 CCC。其视觉效果是屏幕的默认视觉效果。其初始色域压缩和白点调整程序以及相关的客户端数据取决于实现。

## 颜色转换上下文宏

```

```

```

`ccc` 指定 CCC。两者都返回与指定 CCC 关联的显示器。

```

```

```

`ccc` 指定 CCC。两者都返回与指定 CCC 关联的视觉效果。

```
ScreenNumberOfCCC(ccc);
```

```

`ccc` 指定 CCC。两者都返回与指定 CCC 关联的屏幕数量。

```

```

```

`ccc` 指定 CCC。两者都返回指定 CCC 的客户端白点。

## 修改颜色转换上下文属性

要设置 CCC 中的客户端白点，请使用 `XmsSetWhitePoint`。

```
Status XmsSetWhitePoint(ccc, color);
```

`ccc` 指定 CCC。

`color` 指定新的客户端白点。

`XmsSetWhitePoint` 函数更改指定 CCC 中的客户端白点。注意，返回时像素无效且颜色规范保持不变。新白点的格式必须是 `XmsCIEXYFormat`、`XmsCIEUYFormat`、`XmsCIYZFormat` 或 `XmsUndefinedFormat`。如果参数为 NULL，并将客户端白点规范的格式分量设置为 `XmsUndefinedFormat`，表示假设客户端白点为屏幕白点。如果新白点有效，此函数返回非零状态；否则返回零。

要设置指定 CCC 中的色域程序和相应的客户端数据，请使用 `XmsSetCompressionProc`。

```
XmsCompressionProc XmsSetCompressionProc(ccc, compression_proc, client_data);
```

`ccc` 指定 CCC。

`compression_proc` 指定当颜色超出屏幕色域时应用的色域压缩程序。如果指定 NULL 且使用此 CCC 的函数在将颜色规范转换为设备相关格式时遇到超出屏幕色域的颜色，该函数将返回 `XcmsFailure`。

`client_data` 指定色域程序的客户端数据或 NULL。

`XmsSetCompressionProc` 函数首先用新指定的程序和数据设置指定 CCC 中的色域程序和客户端数据，并返回旧程序。

# 色管理函数

`white_adjust_proc`: 指定当客户端白点（Client White Point）与屏幕白点（Screen White Point）不同时应用的白点调整程序。NULL 表示不需要进行白点调整。

`white_adjust_client_data`: 指定用于白点调整程序的客户端数据或 NULL。

`XcmsCreateCCC` 函数为指定的显示器、屏幕和视觉创建一个 CCC。

```
void XcmsFreeCCC(ccc);
```

`ccc`: 指定 CCC。

`XcmsFreeCCC` 函数释放用于指定 CCC 的内存。请注意，默认的 CCC 以及与颜色彻底关联的 CCC 将忽略。

## 颜色空间之间的转换

要将任意颜色格式的颜色规格数组转换为单个目标格式，请使用 `XcmsConvertColors`。

```
Status XcmsConvertColors(ccc, colors_in_out[], ncolors, target_format, compression_flags_return());
```

`ccc`: 指定 CCC。如果转换仅针对设备无关的颜色空间（例如，从 TekHVC 到 CIELuv），则 CCC 仅用于指定客户端白点。

`colors_in_out`: 指定颜色规格数组。Pixel 成员将被忽略，并在返回时保持不变。

`ncolors`: 指定颜色规格数组中 `XmsColor` 结构的数量。

`target_format`: 指定目标颜色格式。

`compression_flags_return`: 返回一个指示压缩状态的布尔值数组。如果提供了非 NULL 指针，则如果相应的颜色被压缩，该数组的每个元素将设置为 True，否则设置为 False。如果压缩状态没有用处，请传递 NULL。

`XcmsConvertColors` 使用指定的 CCC，将指定 `XmsColor` 结构数组中的颜色规格从当前格式转换为单个目标格式。当返回值为 `XFailure` 时，颜色规格数组的内容将保持不变。

该数组可能包含混合的颜色规格格式（例如，3 个 CIE XYZ，2 个 CIE Luv 等）。当数组同时包含设备无关和设备依赖的颜色规格，且 `target_format` 参数指定了设备依赖的格式（例如，`XmsRGBFormat`，`XmsRGBFormat`）时，所有规格都将先转换为 CIE XYZ 格式，然后转换为设备依赖的格式。

## 回调函数

本节描述了色域压缩和白点调整回调函数。

当尝试将颜色规格从 `XmsCIEXYZ` 转换为设备依赖的格式（通常为 `XmsRGB`）的结果导致颜色超出屏幕色域时，将调用 CCC 中指定的色域压缩程序。色域压缩程序需要客户端数据，该数据通过 CCC 中的色域压缩客户端数据传递。

在设备无关和设备依赖颜色空间之间进行颜色规格转换期间，如果 CCC 中指定了白点调整程序，当客户端白点和屏幕白点不同时触发该程序。如果需要，将从 CCC 获取客户端数据。

## 原型色域压缩程序

色域压缩回调接口必须遵循以下条件：

```
typedef Status(*XmsCompressionProc) (ccc, colors_in_out[], ncolors, index, compression_flags_return[]);
```

- `ccc`: 指定 CCC。
- `colors_in_out`: 指定颜色规格数组。Pixel 成员应该被忽略，并在返回时必须保持不变。
- `ncolors`: 指定颜色规格数组中 `XmsColor` 结构的数量。
- `index`: 指定 `XmsColor` 结构数组中超出屏幕色域的索引。有效值为从 0（对应第一个元素）到 `ncolors - 1`。
- `compression_flags_return`: 返回一个指示压缩状态的布尔值数组。如果提供了非 NULL 指针且给定索引处的颜色被压缩，则应在该数组的相应索引处存储 True；否则，不应修改数组。

在实现色域压缩程序时，请考虑以下规则和假设：

- 色域压缩程序可以尝试同时压缩一个或多个规格。
