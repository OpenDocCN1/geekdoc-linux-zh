
以下示例显示了 `srchtxt` 的用法。如果通过 `mkmsgs(1)` 在名为 `french`（法语）的区域（locale）中安装了消息文件，你可以通过输入以下命令导出法语区域中的所有字符串（`/usr/lib/locale/french/LC_MESSAGES*`）：

```
$ srchtxt -m1 french
```

如果一组与操作系统相关的错误消息已安装在法语区域的 UX 文件中（`/usr/lib/locale/french/LC_MESSAGES/UX`），那么通过使用 `LANG` 环境变量的值来确定要搜索的区域，你就可以可以在该区域内搜索该文件中所有与文件相关的错误消息。

```
$ export LANG=french
$ srchtxt -m UX "file"
```

如果 `/usr/lib/locale/french/LC_MESSAGES/UX` 包含以下字符串：

```
Erreur E/S
Arguments trop long
Fichier inexistant
Argument invalide
Trop de fichiers ouverts
Fichier trop long
Trop de liens
Argument du domaine
Identificateur supprimé
Etre fatal
```

则将显示以下字符串：

```
<UX:3>Fichier inexistant
<UX:5>Trop de fichiers ouverts
<UX:6>Fichier trop long
```

如果一组与操作系统相关的错误消息已安装在 UX 文件中，一组与数据库相关的错误消息已安装在该文件中，且均位于德语（`german`）区域，你可以使用以下命令在 UX 文件和德语区域中搜索模式。

```
$ srchtxt -m german UX "pattern"
```

## `strchg`, `strconf` — 更改或查询流配置

### 概要

```
/usr/bin/strchg -h module 1[, module 2...]
/usr/bin/strchg -p [-a |u module]
/usr/bin/strchg -f filename
/usr/bin/strconf [-m |t module]
```

## 描述

使用这些命令来排序或查询与标准输入相关的流配置。`strchg` 命令将模块推入（push）或从流中弹出（pop）模块。`strconf` 命令查询流设备的配置并可以更改该流的配置。

在不带任何参数的情况下调用，`strconf` 会打印流中所有模块以及最顶层驱动程序的列表。每行打印一个名称；打印的第一个是流中最顶层的模块（如果存在），最后一个打印的项目是驱动程序的名称。

如果你既不是流的所有者也不是超级用户，`strchg` 命令将失败。如果你对该流没有读取权限且不是超级用户，`strconf` 命令将失败。

注意 — 如果模块推入顺序错误，可能会导致流的功能不符合预期。对于 TTY，如果行规律模块（line discipline module）没有被推在正确的位置，你可能会得到一个不响应任何命令的终端。

## 选项

以下选项适用于 `strchg`；`-h`, `-f` 和 `-p` 之间是互斥的。

`-h module[1[,module2...]]`

  - 将模块推入流中。指定一个或多个可推模块的名称作为参数。按顺序推入这些模块；即先推入 `module1`，再推入 `module2`，以此此类推。

`-p` 从流中弹出模块。单独使用 `-p` 选项会从流中弹出最顶层的模块。

`-a module` 从流中弹出最顶层驱动以上的所有模块。此选项需要 `-p` 选项。

`-f filename` 用作输入的普通文件路径。如果你没有指定文件操作数，则从标准输入读取。

## 描述

`strings` 命令在二进制文件中查找 ASCII 字符串。字符串是四个或更多打印字符的序列，并以换行符或空字符结束。`strings` 对于识别随机对象文件和许多其他内容有用。

注意 — 识别字符串的算法非常原始。为了向后兼容性，`-a` 和 `-b` 选项是可以互换的。

## 选项

`-n number` 使用数字作为最小字符串长度，而不是默认的 4。

`-o` 等同于 `-t` 选项。

`-t format` 在每个字符串前写入其相对于文件起始位置字节偏移。格式取决于作为参数的单个字符。

  - `o` 以八进制写入偏移。
  - `x` 以十六进制写入偏移。

# `strip` — 从对象文件中移除符号表、调试信息和行号信息

# 概览

```
/usr/ccs/bin/strip [-blrVx] file...
```

## 描述

使用 `strip` 命令可以减少对象文件带来的存储开销。`strip` 命令会从 ELF 对象文件中移除符号表、调试信息和行号信息。因此，在完成此剥离过程后，通常在不需要调试的生产模块或已通过调试和测试的模块上运行此命令。

如果你对普通归档文件（见 `ar(4)`）执行 `strip`，那么除了处理成员外，`strip` 还会移除归档符号表。在用 `ld(1)` 命令链接归档之前，必须通过执行带有 `-s` 选项的 `ar(1)` 命令恢复归档符号表。当出现这种情况时，`strip` 会产生相应的警告信息。

> 注意 — 如果符号表包含在段（segment）中，或者该文件是可定位对象或动态共享对象，则不会移除符号表部分。

如果行号和调试部分包含在段中，或者其相关的重定位部分包含在段中，则不会移除这些部分。

## 选项

你可以使用以下选项控制从 ELF 对象中剥离的信息量。

- `-b` 与默认行为效果相同。此选项已过时，将在下一个版本中删除。
- `-l` 仅剥离行号信息；不剥离符号表或调试信息。
- `-r` 与默认行为效果相同。此选项已过时，将在下一个版本中删除。
- `-V` 向标准错误打印 `strip` 的版本号。
- `-x` 不剥离符号表；可能会剥离调试和行号信息。

### 操作数

`file`: 指向可执行文件的路径名。
