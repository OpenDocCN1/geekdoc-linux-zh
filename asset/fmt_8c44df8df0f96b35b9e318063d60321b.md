
许多 Linux 发行版允许你指定一个“打印机”，以 PDF文档格式 (`PDF`) 输出文件，而不是打印在物理打印机上。这对于测试打印命令非常有用。检查你的打印机程序以查看它是否支持此配置。在某些发行版上，你可能需要安装额外的包（如 `cups-pdf`）来启用此功能。表 22-2 描述了 `lpr` 的常用选项。

| 选项 | 描述 |
| --- | --- |
| -n number | 将副本数设置为 `number`。 |
| -p | 打印每页时带有日期、时间、作业名称和页码的阴影页眉。这种所谓的“漂亮打印”选项可以在打印文本文件时使用。 |
| -P printer | 指定输出的打印机名称。如果未指定打印机，则使用系统的默认打印机。 |
| -r | 打印后删除文件。这对于产生临时打印输出文件的程序很有用。 |

与 `lpr` 类似，`lp` 接受过滤器或标准输入进行打印。它与 `lp` 的不同之处在于它支持一套不同的（且稍微复杂一点）选项。表 22-3 描述了常用选项。

```

## 另一个选项：a2ps

`a2ps` 程序（在许多仓库中可用）很有趣。从它的名字可以看出，它功能很多。它的名字最初的意思是“ASCII 到 PostScript”，用于为 PostScript 打印机准备文件。随着时间的推移，该程序的能力不断增强，名字变成了“任何到 PostScript”。虽然名字暗示这是一个转换程序，但它是一个打印程序。它将输出发送到系统的默认打印机而不是标准输出。程序的默认行为是“漂亮打印”，即改进输出的外。我们使用该程序在桌面创建一个 PostScript 文件：

```bash
me@linuxbox~$ ls /usr/bin | pr -3 -t | a2ps -o ~/Desktop/ls.ps -l
Total: 11 pages on 2
```

然后使用 `a2ps`，指定输出文件 (`-o` 选项) 以匹配 `pr` 的分页。如果我们使用合适的查看器查看结果文件，我们将看到图 22-1 中的输出。

## 监控和控制打印作业

由于 Unix 系统设计用于处理来自多个用户的多个打印作业，CUPS 的设计理念也是如此。每个打印机都被分配了一个*打印队列*，CUPS 提供了几个命令行程序，用于管理打印机状态和打印队列。*lp* 和 *lp0* 程序这些管理程序是参考 Berkeley 和 System 打印系统中相应的程序建模的。

## lpstat—显示打印系统状态

*lpstat* 程序用于确定系统上打印机的名称和可用性。例如，如果我们的系统上既有一个物理打印机（名为 *printer*），又有一个 PDF 虚拟打印机（名为 *PDF*），我们可以这样检查它们的状态：

```bash
$me@linux-~$ lpstat -a
PDF accepting requests sees Mon 08 Dec 2024 08:03:59 PM EST
printer accepting requests sees Tue 24 Feb 2025 08:43:22 AM EST
```

> 此外，我们可以通过以下命令获取更详细的打印系统配置描述：

```bash
$me@linux-~$ lpstat -s
system default destination: printer
device for: cups-pdf:
device for: ipp://print-server:631/printers/printer
```

在这个示例中，我们看到 *printer* 是系统的默认打印机，它是一个使用互联网打印协议 (*ipp://*) 的网络打印机，连接到名为 *print-server* 的系统。表 **22-5** 列出了常用的选项。

## 表 22-5：常用的 lpstat 选项

| 选项 | 描述 |
| :--- | :--- |
| -a [printer...] | 显示 *printer* 打印队列的状态。注意，这是队列接受作业的能力状态，而不是物理打印机的状态。如果没有指定打印机，则显示所有打印队列。 |
| -d | 显示系统默认打印机的名称。 |
| -p [printer...] | 显示指定 *printer* 的状态。如果没有指定打印机，则显示所有打印机。 |

| -s | 显示状态摘要。 |
| -t | 显示完整的状态报告。 |

## lpq—显示打印队列状态

使用 `lpq` 程序查看打印队列状态。这允许我们查看队列状态和排队的打印作业。以下是一个名为 `printer` 的系统默认打印机的空队列示例：

```bash
$me@linux -~$ lpq
printer is ready
no entries
```

如果我们不指定打印机（使用 `-P` 选项），将显示系统默认打印机。如果我们向打印机发送作业然后锁定队列，我们将在列表中看到它。

```bash
$me@linux -~$ *.txt | pr -j lpq
request id is printer-603 (1 file(s))
$me@linux-~$ lpq
printer is ready and printing
```

| :--- | :--- | :--- | :--- |
| active | me | 603 (stdin) | 1024 bytes |

## lprm/cancel—取消打印作业

CUPS 提供了两个终止打印作业并从打印队列中删除它们的程序。一个是 Berkeley 风格 (`lprm`)，另一个是 System V 风格 (`cancel`)。它们在支持的选项略有不同，但基本相同。以之前的打印作业为例，我们可以这样停止并移除作业：

```bash
$me@linux -~$ lprm 603
printer is ready
no entries
```

正如我们所见，源代码通常以压缩 tar 包的形式提供。这种文件也被称为 tarball，该文件包含了源源码树，即提供源代码的目录和文件层级。到达 FTP 后，我们检查可用的 tar 文件列表，并选择最新版本进行下载。使用 `ftp` 的 `get` 命令，我们将文件从 FTP 服务器复制到本地机器。

```
[me@linuxbox src]$ tar xzf diction-11.11.tar.gz
[me@linuxbox src]$ ls
diction-11.11      diction-11.11.tar.gz
```

> `diction` 程序与 Linux 生态系统中所有其他 GNU 项目源码一样，也遵循这一标准。该标准的大部分是：当源码 tar 包解包时，会创建一个包含源码树的目录，该目录命名为 `project-x.xx`，因此同时包含了项目名称和版本号。这种方案允许轻松安装同一个程序的多个版本。然而，在解包之前检查目录树的布局通常是一个好主意。有些项目不会创建目录，而是直接将文件交付到当前目录中。这会导致我们原本组织良好的 `src` 目录变得混乱。为了避免这种情况，请使用以下命令检查 tar 文件的内容：

```
tar xf tarfile | head
```

## 构建程序

`configure` 程序是一个分析环境的 shell 脚本。由于 `configure` 不在 shell预期程序的地方，我们必须通过在命令前加上 `./` 来显式告诉 shell 它的位置。

```bash
[me@linuxbox diction-1.11]$ ./configure
```

`configure` 在测试和配置时会输出大量信息。完成后，它看起来像这样：
checking libintl.h... yes
checking for libintl.h... yes
checking for gettext... none required
configure: creating Makefile

```重要的是没有错误信息。如果有，说明配置失败，在纠正错误之前程序将无法构建。

我们看到 `configure` 在我们的源码目录中创建了新文件。最重要的是 `makefile`。`makefile` 是一个配置文件，它指示 `make` 程序具体如何构建程序。没有它，`make` 将拒绝运行。`makefile` 是普通的文本文件，所以我们可以查看它。

```
[me@linuxbox diction-1.11]$ less Makefile
```
