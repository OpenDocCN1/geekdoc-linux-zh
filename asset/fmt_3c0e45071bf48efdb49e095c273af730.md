
## urllib.error

`urllib.error` 模块定义了 `urllib` 包使用的异常。

### ContentTooShort

当下载的数据量少于预期量（由 `'Content-Length'` 请求头定义）时抛出。在 Python 2 的 `urllib` 模块中定义。

### HTTPError

用于指示 HTTP 协议问题。此错误可能用于信号身份验证失败等事件。此异常也可以用作文件对象，读取与错误相关的服务器返回的数据。它是 `URLError` 的子类。在 Python 2 的 `urllib` 模块中定义。

### URLError

当检测到问题时由处理器抛出。它是 `IOError` 的子类。异常实例的 `reason` 属性具有关于该问题的更多信息。这在 Python 2 的 `urllib2` 模块中定义。

## 第 22 章 互联网应用程序编程

`Binary(data)`

创建一个包含二进制数据的 XML-RPC 对象。`data` 是包含原始数据的字符串。返回的 `Binary` 实例在传输过程中会使用 base64 透明地编码/解码。要从 `Binary` 实例 `b` 中提取二进制数据，请使用 `b.data`。

`DateTime(daytime)`

创建一个包含日期的 XML-RPC 对象。`datetime` 是 ISO 8601 格式的字符串、`time.localtime()` 返回的元组或结构体，或者是来自 `datetime` 模块的 `datetime` 实例。

```python
dumps(params, methodname, encoding, [allow_none])
```

将解析的内容转换为 XML-RPC 请求或响应，其中 `params` 是参数元组或 `Fault` 异常的实例。`methodname` 是字符串名称：`methodnamponse` 是一个布尔标志。如果为 `True`，则结果为 XML-RPC 响应。在这种情况下，`params` 中只能提供一个值。`encoding` 指定生成的 XML 中的文本编码，默认为 UTF-8。`allow_none` 是一个标志，指定是否支持 `None` 作为参数类型。XML-RPC 规范中没有明确提到 `None`，但许多服务器都支持它。默认情况下，`allow_none` 为 `False`。

```python
loads(data)
```

将包含 XML-RPC 请求或响应的数据转换为元组 `(params, methodname)`，其中 `params` 是参数元组，`methodname` 是包含方法名的字符串。如果请求返回的是故障条件而非实际值，则抛出 `Fault` 异常。

`MultiCall(server)`

创建一个 `MultiCall` 对象，允许将多个 XML-RPC 请求打包并作为单个请求发送。如果需要在同一个服务器上进行许多不同的 RPC 请求，这可以是一种性能优化。`server` 是 `ServerProxy` 的实例，代表到远程服务器的连接。返回的 `MultiCall` 对象的用法与 `ServerProxy` 相同。然而，它并不会立即执行远程方法，方法调用会被排队，直到 `MultiCall` 对象被当作函数调用。一旦发生这种情况，RPC 请求就会被传输。该对象的返回值是一个生成器，按顺序产生每个 RPC 操作的结果。注意，`MultiCall()` 只有在远程服务器提供 `system.multicall()` 方法时才有效。

以下是一个说明 `MultiCall` 的示例：

```python
multi = MultiCall(server)
multi.foo(4,6,7) # 远程方法 foo
multi.bar("hello world") # 远程方法 bar
multi.spam() # 远程方法 spam
# 现在，实际发送 XML-RPC 请求并获取返回结果
foo_result, bar_result, spam_result = multi()
```

## 异常

在 `xmlrpc.client` 中定义了以下异常。

### Fault

表示 XML-RPC 故障。`faultCode` 属性包含一个带有故障类型的字符串。`faultString` 属性包含与故障相关的描述性消息。

### ProtocolError

表示底层网络出现问题——例如，错误的 URL 或某种类型的连接问题。`uri` 属性包含触发错误的 URI。`errcode` 属性包含一个错误代码。`errmsg` 属性包含一个描述性字符串。`headers` 属性包含触发错误请求的所有 HTTP 请求头。

```python
xmlrpc.server (SimpleXMLRPCServer, DocXMLRPCServer)
```

`xmlrpc.server` 模块包含了用于实现不同变 XML-RPC 服务器的类。在 Python 2 中，此功能位于独立的模块中：`SimpleXMLRPCServer` 和 `DocXMLRPCServer`。

```python
SimpleXMLRPCServer(addr [, requestHandler [, logRequests])
```

创建一个在 socket `addr`（例如 `'localhost', 8080`）上监听的 XML-RPC 服务器。`requestHandler` 是一个在接收到连接时创建处理请求的函数。默认，它设置为 `SimpleXMLRPCRequestHandler`，这是目前唯一的可用处理器。`logRequests` 是一个布尔标志，指示是否记录传入的请求。默认 `True`。

```python
DocXMLRPCServer(addr [, requestHandler [, logRequests])
```

创建一个带文档的 XML-RPC 服务器，为 GET 请求添加文档（通常由服务器生成）。如果接收到请求，服务器将从所有注册的方法和对象中的文档字符串（docstrings）生成文档。参数含义与 `SimpleXMLRPCServer` 相同。

`SimpleXMLRPCServer` 或 `DocXMLRPCServer` 的实例 `s` 具有以下方法：

```python
s.register_function(func, name)
```

在 XML-RPC 服务器上注册一个新函数 `func`。`name` 是该函数的可选名称。如果未提供 `name`，客户端将使用它来访问该函数。此名称可能包含 Python 标识符中无效的字符，包括点（`.`）。

## 高级服务器自定义

XML-RPC 服务器模块对于基础类型的分布式计算非常易于使用。例如，如果网络上的其他系统都运行着合适的 XML-RPC 服务器，那么 XML-RPC 就可以作为对网络上其他系统进行高级控制的协议。如果你额外使用 `pickle` 模块，就可以在系统之间传递更有趣的对象。

XML-RPC 的一个问题是安全性。默认情况下，XML-RPC 服务器作为网络上的一个开放式服务器运行，任何知道服务器地址和端口的人都可以连接到它（除非它被防火墙阻挡）。此外，XML-RPC 服务器对请求中可以发送的数据量没有任何限制。攻击者可能会发送一个负载足以耗尽内存的 HTTP POST 请求来导致服务器崩溃。

如果你想避免这些问题中的任何一个，你将需要自定义 XML-RPC 服务器类或请求处理器。所有的服务器类都继承自 `TCPServer`，因此可以像其他服务器类一样对服务器进行自定义（例如，添加线程、分叉或验证客户端地址）。可以通过继承 `SimpleRequestHandler` 或 `DocXMLRequestHandler` 并扩展 `do_POST()` 方法，在请求处理器周围放置一个验证包装器。这里是一个限制传入请求大小的示例：

```python
from xmlrpc.server import (SimpleXMLRPServer, SimpleXMLRPRequestHandler)
```
