
## 6. Wollen Sie interne Netzwerke maskieren?
Nutzen Sie dafür `FW_MASQ_NETS`. Diese Variable ist auf `"no"` oder gesetzt, an dem das Maskieren stattfinden soll.

```
FW_MASQ_NETS="FW_DEV_WORLD"
```

## 7. Wollen Sie die Firewall vor internen Netzwerken schützen?
Nutzen Sie dafür `FW_PROTECT_INTERNAL`. Diese Variable ist auf `"yes"` oder `"no"`.

```
FW_PROTECT_INTERNAL="yes"
```

## 8. Wollen Sie global Dienste schützen?
Wenn Sie `"yes"` angeben, werden alle von der Firewall geschützt.

```
FW_AUTOPROTECT_GLOBAL_SERVICES=""
```

## 9. Welche Dienste von vertrauenswürdigen Netzen aus dem Internet erreichbar sein?
Siehe Nr.13 & 14, wenn Sie Netzwerkverkehr durch die Firewall wollen. Geben Sie die vertrauenswürdigen Netzwerk des Internets an und die TCP/UDP-Dienste, die Sie verwenden dürfen. Auswahlmöglichkeiten: leere Liste oder beliebige IP-Adresse und/oder Netzwerke durch Leerzeichen getrennt.

```
FW_TRUSTED_NETS=""
```

Geben Sie bei `FW_SERVICES_TRUSTED=""` eine Liste an, oder die PortNummern bzw. die bekannten Portnamen (vgl. `/etc/services`), oder die Portbereiche durch Leerzeichen getrennt, z. B. `„25"`, `"ssh"`, `"1:65535"`, `"1 3:5"`

# SuSE Linux-CD für Firewall

TCP-Dienste, die vertrauenswürdigen Netzen/Rechnern zur Verfügung gestellt werden sollen, normalerweise `"ssh"`:

```
FW_SERVICES_TRUSTED_TCP=""
```

UDP-Dienste, die vertrauenswürdigen Netzen/Rechnern zur Verfügung gestellt werden sollen, normalerweise `"syslog"`:

```
FW_SERVICES_TRUSTED_UDP=""
```

Manchmal wird vertrauenswürdiger Zugriff auf bestimmte Dienste benötigt und andere Dienste benötigen vertrauenswürdigen Zugriff. Hier haben Sie die Möglichkeit, diese nach dem Muster einzurichten: `"trusted_netz,protokoll,port"`, z. B. `"10.0.1.0/24,tcp,10.0.1.6,tcp"`:

```
FW_SERVICES_TRUSTED_ACL=""
```

## 1. Ist der Zugriff auf hohe, unprivilegierte Ports (>1023) erlaubt?
Sie können jeden Zugriff auf die hohen Ports erlauben `„yes“`, alle verbieten `„no“`, oder Sie angeben, der von einem bestimmten Port (Angabe der Port-Nummer oder des Service-Namen, allerdings leicht zu umgehen) oder nur der von Ihnen zugassenen (DNS). Wenn Sie aktives FTP zulassen, müssen Sie in `FW_SERVICES_EXTERNAL` den Portbereich `„ftp-data“` setzen. Bei passivem FTP ist dies nicht notwendig. Beachten Sie weiterhin, dass sich keine RPC-Requests befinden. Wenn Sie diese erlauben wollen, müssen Sie `„600:1023“` setzen. Eingehende Verbindungen auf Port-Nummern >= 1024, TCP, normalerweise: `"ftp-data"`:

```
FW_ALLOW_INCOMING_HIGPORTS_TCP="yes"
```

## 2. Haben Sie eine oder mehr der geleiteten Dienste?
Diese benötigen besondere Sorge, damit sie funktionieren! Für diese angebot, setzen Sie die Variablen auf `„yes“`, alle auf `"no"`. Default-Wert sind `"no"`:

```
FW_SERVICE_DNS="no"
```

Im Fall von `"yes"` muss `FW_SERVICE_*_TCP` den Port 53 (oder domain) haben. Die Variable `FW_ALLOW_INCOMING_HIGPORTS_UDP` muss auch auf `"yes"` gesetzt sein.

```
FW_SERVICE_DHCLIENT="no"
```

Wenn Sie dhclient erlauben, um eine IP-Adresse zu erhalten, muss `FW_SERVICE_DHCPD` auf `"yes"` gesetzt werden.

# 5.3 Die Dienste auf der Firewall

```
FW_SERVICE_DHCPD="no"
```

Bei einem DHCP-Server setzen Sie `FW_SERVICE_DHCPD` auf `"yes"`.

```
FW_SERVICE_SAMBA="no"
```

Wenn Sie Samba als Client oder Server auf diesem Rechner verwenden wollen, dann setzen Sie `FW_SERVICE_SAMBA` auf `"yes"`. Für einen Samba-Server muss zusätzlich noch

`FW_SERVICES={WORLD,DMZ,INT}_TCP="139"`

gesetzt werden. Es ist grundsätzlich keine gute Idee, Samba auf einem Firewall-Rechner einzusetzen.
