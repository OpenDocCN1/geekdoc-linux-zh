
交换空间的大小应为 RAM 容量的三倍。RedHat Linux 6.0 和 Linux 内核 2.2 现在支持大于 128MB 的交换分区。要创建大于 128MB 的交换分区或交换文件，必须指定新样式 `mkswap-v1`。如果你没有额外的磁盘空间来添加交换分区，可以添加交换文件。

## 内核参数

《LINUX 安装指南》建议更改内核参数，这需要重新编译内核。通常不需要修改这些参数。最重要的参数是 `SHMMAX`，它定义了共享内存段的最大 own。RedHat Linux 上的默认设置为 32MB，这对于数据库安装通常足够了。如果 `SGA` 设置为 128MB，则需要四个每个 32MB 的段。对于具有大 `SGA` 的服务器，内核参数是一个大问题。在生产环境中，`SHMMAX` 的配置应与 `/usr/src/linux/asm/shmparam.h` 和 `/usr/src/linux/sem.h` 中的文件相同。

> TIP 你可以以 root 运行以下命令查看 `SHMMAX`：`cat /proc/sys/kernelmax`

## OS 账户和组

Oracle 服务器不应在 root 账户下运行。通常会创建一个 `oracle` 账户来拥有 Oracle 软件和后台进程。Oracle 在 Oracle 服务器内部定义了一个名为 `OSDBA` 的组。Oracle 中任何作为 `OSDBA` 成员的账户都会获得 DBA 权限。在安装期间，Oracle 使用 Linux 组 `dba` 为 Oracle 服务器 分配成员身份。Linux 组 `dba` 经常被使用。Oracle8 有第二个名为 `oinstall` 的组，可用于分配安装权限。作为 root，使用 `groupadd` 命令添加 `dba` 组：

```
# groupadd dba
```

对于 Oracle8，还要添加 `oinstall` 组：

```
# groupadd oinstall
```

对于 Oracle8，使用 `dba` 组作为默认组创建 Oracle 账户：

```
# useradd -c DBA -g dba oracle
```

对于 Oracle8，使用 `oinstall` 组作为默认组创建 Oracle 账户：

```
# useradd -c DBA -g oinstall oracle
```

为 `oracle` 账户创建密码：

```
# passwd oracle
```

## 文件系统权限

为了让 `oracle` 账户在安装期间使用挂载点，它必须拥有相应的权限。将挂载点的所有权更改为 `oracle` 账户。安装完成后，可以将顶级目录的所有权改回 root。

```
# chmod oracle /u01
# chmod oracle /u02
# chmod oracle /u03
# chmod oracle /u04
# chmod 755 /u01
# chmod 755 /u02
# chmod 755 /u03
# chmod 755 /u04
```

## 环境设置

在安装 Oracle 服务器之前，需要设置某些环境变量。环境变量可以放置在三个地方。如果只有 `oracle` 账户将使用 Oracle 软件，请将环境变量放在 `oracle` 账户的 `~/.bash_profile` 文件中。如果系统上的其他账户将使用 Oracle，可以将变量存放在系统级的 `/etc/profile` 文件中。该位置的缺点是需要 root 权限更改 `/etc/profile` 设置。如果服务器上安装了多个数据库，最好将变量放在一个可以由用户运行的独立执行脚本中。Oracle 自带一个位于 `$ORACLE_HOME/bin` 下的名为 `oraenv` 的文件。

由于安装之前需要环境变量，请将以下环境变量插入 `oracle` 账户的 `~/.bash_profile` 或 `/etc/profile` 中。然后你应该重新登录以设置环境或 `source` 该文件。注意，环境设置中的某些目录尚不存在。在示例中，实例 `ORACLE_SID` 被设置为 `orcl`。

对于 Oracle8 环境（8.0.5）：

```
ORACLE_BASE=/u01/app/oracle
ORACLE_HOME=/u01/app/oracle/product/8.1.5
ORACLE_SID=orcl
ORACLE_TERM=vt100
PATH=$PATH:$ORACLE_HOME/bin
LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$ORACLE_HOME/lib:$ORACLE_HOME/network/lib
export ORACLE_BASE ORACLE_SID ORACLE_TERM LD_LIBRARY_PATH PATH
```

对于 Oracle8 环境（8.1.5）：

```
ORACLE_BASE=/u01/app/oracle
ORACLE_HOME=/u01/app/oracle/product/8.1.5
ORACLE_SID=orcl
ORACLE_TERM=vt100
PATH=$PATH:$ORACLE_HOME/bin
LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$ORACLE_HOME/lib:$ORACLE_HOME/network/lib
export ORACLE_BASE ORACLE_SID ORACLE_TERM LD_LIBRARY_PATH PATH
```

> Note `LD_LIBRARY_PATH` 环境变量为提供了库的位置。某些人遇到过 Oracle 找不到 `LD_LIBRARY_PATH` 中库的问题。包含库的目录也可以添加到 `/etc/ld.so.conf` 文件中。`ldconfig` 命令将读取 `ld.so.conf` 文件。

如果你需要除 US7ASCII 外的语言，请检查 Oracle 安装文档获取 `NLS_LANG` 和 `ORACLE_NLS33` 变量。将以下环境变量复制到你的 shell 脚本中。

你可能会经常更改 `$ORACLE_HOME` 目录。快捷方法是使用 `cd $ORACLE_HOME`。更简单的方法是创建一个别名。将以下命令放在 `~/.bashrc` 中。一旦定义了别名，`oh` 别名将带你进入 `ORACLE_HOME`。

运行 `umask` 命令以确保用户文件创建掩码（`umask`）为 022。如果 `umask` 不是 022，请在您的 shell 启动文件中放置 `umask 022`。在大多数 Linux 发行版（包括 RedHat）中，这通常不是必要的。`umask` 过滤文件系统。022 的 `umask` 可为所有者提供完全权限，并移除组和其他和其他的 `写` 权限。

```
$ umask
022
```

在继续之前，运行 `env` 命令以确保您的环境变量配置正确。

## X Windows 显示

X Windows 服务器默认不允许另一个用户的进程访问屏幕。如果您正在安装 Oracle8，Java GUI 元素需要访问 X Windows 服务器。只要您是以 `oracle` 用户身份登录 并在 `oracle` 账户下运行应用程序，应用程序就可以访问 X 服务器。如果您以 root 身份登录并 `su` 切换到 `oracle` 账户来以 `oracle` 身份运行 X 窗口应用程序，您可能会遇到错误。为了防止这种情况，请作为当前登录的用户运行 `xhost +localhost`。`xhost` 命令允许其他账户访问 X 服务器。接下来，作为另一个用户，将环境变量 `DISPLAY` 设置为 `localhost`。

```
$ xhost +localhost
$ export DISPLAY=localhost:0.0
```

## Linux 软件包

从 RedHat Linux 5.2 到 6.0 的迁移导致核心库发生了根本变化。RedHat 5.2 包含 `glibc` 2.0 库，而 RedHat Linux 6.0 包含了新的 `glibc` 2.1 库。在 `glibc` 2.0 下编译的应用程序必须在新库下重新编译。由于 Oracle8 是使用 `glibc` 2.0 为 RedHat Linux 5.2 编译的，因此它需要兼容库才能在较版本的 RedHat Linux 上运行。如果您决定在 RedHat 6.0 或更高版本上安装 Oracle8，则必须安装兼容库。Oracle8 是使用 `glibc` 2.1 编译的，因此不需要兼容包。Oracle8 不应在 6.0 之前的 RedHat Linux 版本运行，因为库是不兼容的。

兼容包仅在您安装 Oracle 8.0.5 时是必要的。如果您安装的是 RedHat Linux 6.0 或 6.1，则不需要它们。这些包应该位于 RedHat Linux 安装 CD-ROM 上，或者可以从 ftp 站点下载。
