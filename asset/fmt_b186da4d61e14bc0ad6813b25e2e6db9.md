`$(addsuffix suffix, names...)`

参数名被视为一组由空格分隔的名称；`suffix` 被视为一个单元。`suffix` 的值会被附加到每个独立名称的末尾，生成的较长名称将用单个空格连接起来。例如，

```
$(addsuffix .c,foo bar)
```

产生结果 `'foo.c bar.c'`。

`$(addprefix prefix, names...)`

参数名被视为一组由空格分隔的名称；`prefix` 被视为一个单元。`prefix` 的值会被加到每个独立名称的前面，生成的较长名称将用单个空格连接起来。例如，

```
$(addprefix src/,foo bar)
```
产生结果 `'src/foo src/bar'`。

`$(join list1,list2)`

按单词连接两个参数：前两个单词（每个参数各一个）连接形成的结果的第一个单词，两个第二个单词形成结果的第二个单词，依此类推。每个参数的第 n 个单词。如果一个参数的单词比另一个多，则多出的单词将原封地复制到结果中。

例如，`'$(join a, b. . o)'` 产生 `'a.c b.o'`。

列表中单词之间的空格不会被保留；它会被单个空格替换。

此函数可以合并 `dir` 和 `notdir` 函数的结果，从而产生传递给这两个函数的原始文件列表。

`$(wildcard pattern)`

参数 `pattern` 是一个文件名模式，通常包含通配符字符（如 shell 文件名模式所示）。`wildcard` 的结果是匹配模式的现有文件名称列表，并用空格分隔。请参见第 4.2 节 [在文件名中使用通配符]，第 20 页。

## 8.4 foreach 函数

`foreach` 函数与其他函数非常不同。它导致某段文本被重复使用，每次都对其进行不同的替换。它类似于 shell `sh` 中的 `for` 命令以及 C-shell `csh` 中的 `foreach` 命令。

`foreach` 的语法为：

```
$(foreach var, list, text)
```

前两个参数 `var` 和 `list` 在执行任何操作之前会被展开；注意，最后一个参数 `text` 不会同时被展开。对于 `list` 展开值中的每个单词，由 `var` 展开值命名的变量将设置为该单词，并展开 `text`。推测 `text` 包含了对该内容的引用，因此它的每次展开都会是不同的。

结果是，`text` 展开的次数与 `list` 中由空格分隔的单词数相同。`text` 的多次展开连接在一起，中间留有空格，形成 `foreach` 的结果。

这个简单的示例将变量 `files` 设置为列表中目录中所有文件的列表：

```
dirs := a b c d
files := $(foreach $(dirs),$(wildcard $(dir)*)
```

此处 `text` 为 `'$(wildcard $(dir)*'`。第一次循环找到 `dir` 的值 `'a'`，因此它产生结果 `'$(wildcard a/*)'`；第二次循环产生结果 `'$(wildcard b/*)'`；第三次产生 `'$wildcard c/*)`。

这个示例的结果与下例相同（除了设置 `dirs` 之外）：

```
files := $(wildcard a*) b* c* d*)
```

当 `text` 很复杂时，你可以通过额外的变量为其命名来提高可读性：

```
dirs_files := $(wildcard $(dir)/)
dirs := a b c d
files := $(foreach dir,$(dirs),$(find_files))
```

在这里我们使用 `$(foreach dir,$(dirs),$(find_files)`

### 8.7 origin 函数

`origin` 函数与大多数函数不同，它不对变量的值进行操作；它告诉你是关于变量的信息。具体来说，它告诉该变量的来源。

`origin` 函数的语法为：

```
$(origin variable)
```

注意，`variable` 是要查询的变量名称；而不是该变量的引用。因此，在编写时你不需要使用 '$' 或括号。（不过，如果你想让名称成为一个常量，则可以在名称中使用变量引用。）

该函数的返回值是一个字符串，告诉变量 `variable` 是如何定义的：

- `'undefined'`
  - 如果变量从未被定义过。
- `'default'`
  - 如果变量有默认定义，这在 `CC` 等情况下很常见。见第 10.3 节 [隐式规则使用的变量]，第 106 页。注意，如果你重新定义了默认变量，`origin` 函数将返回后定义定义的来源。
- `'environment'`
  - 如果变量被定义为环境变量，且没有开启 `'-e'` 选项（见第 9.7 节 [选项摘要]，第 95 页）。
- `'environment override'`
  - 如果变量被定义为环境变量，且开启了 `'-e'` 选项（见第 9.7 节 [选项摘要]，第 95 页）。
- `'file'`
  - 如果变量在 makefile 中定义。
- `'command line'`
  - 如果变量在命令行中定义。
- `'override'`
  - 如果变量在 makefile 中通过 `override` 指令定义（见第 6.7 节 [override 指令]，第 65 页）。
- `'automatic'`
  - 如果变量是为每个规则的命令执行而定义的自动变量（见第 10.5.3 节 [自动变量]，第 111 页）。

这些信息主要的用途（除了好奇心外）是确定你是否想要信任某个变量的值。例如，假设

在 GNU make 中有一个名为 `'foo'` 的 makefile，它包含了另一个名为 `'bar'` 的 makefile。你希望在运行 `make -f bar` 命令时，在 `'bar'` 中定义一个 `bletch`，即使环境中已经包含了 `bletch` 的定义。然而，如果 `'foo'` 在包含 `'bar'` 之前定义了 `bletch`，则你不希望覆盖该定义。可以通过在 `'foo'` 中使用 `override` 指令来实现，使该定义优先于 `'bar'` 中的后定义定义；不幸的是，`override` 指令也会覆盖任何命令行定义。因此，`'bar'` 可以包含：

```
ifdef bletch
ifeq $(origin bletch) "environment"
bletch = barf, gag, etc.
endif
endif
```

如果 `bletch` 已经从环境中定义，这将会重新定义它。如果你希望在 `bletch` 来自环境时覆盖其之前的定义（即使在开启 `'-e'` 的情况下也是如此），你可以改写为：

```
ifeq "$(findstring environment,$(origin bletch))" ""
bletch = barf, gag, etc.
endif
```

在这里，如果 `$(origin bletch)` 返回 `'environment'` 或 `'environment override'`，则发生重新定义。见第 8.2 节 [字符串替换和分析函数]，第 76 页。

### 8.8 shell 函数

`shell` 函数与除通配符函数（见第 4.2.3 节 [函数 wildcard]，第 22 页）外的任何函数都不同，因为它能与 make 之外的世界通信。

`shell` 函数的作用与大多数 shell 中反引号（`` ` ``）的作用相同：它执行命令扩展。这意味着它接收一个作为 shell 命令的参数，并返回命令的输出。`make` 在将结果替换到周围文本之前对结果进行的唯一处理，是将每个换行符或回车换行符对转换为单个空格。如果它是结果中的最后一个内容，它还会删除末尾的（回车和换行符）。

通过调用 `shell` 函数运行的命令在函数调用展开时执行。在大多数情况下，这是在读取 makefile 时。例外是规则命令中的函数调用是在命令运行时展开的，这适用于包括 `shell` 函数在内的所有调用。

以下是 `shell` 函数的一些示例：

```
contents := $(shell cat foo)
```

将 `contents` 设置为文件 `'foo'` 的内容，用空格（而不是换行）分隔每行。

```
files := $(shell echo *.c)
```

将 `files` 设置为 `'*.c'` 的展开结果。除非 make 使用了非常奇特的 shell，否则结果与 `'$(wildcard *.c)'` 相同。
