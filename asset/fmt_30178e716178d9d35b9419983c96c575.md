
### 标志位（Flags）
IP 数据包中的标志位告诉你数据包是否被分片。当 IP 数据包大于两个主机之间的最小传输单元（MTU）时，就会发生分片。MTU 定义了可以在特定网络上发送的最长数据包大小。例如，以太网的 MTU 是 1500 字节。因此，如果我们有一个 4000 字节（3980 字节数据 + 20 字节 IP 头部）的 IP 数据包需要通过以太网发送，该数据包将被分分成三个较小的包。第一个包可能是 1500 字节（1480 字节数据 + 20 字节 IP 头部），第二个包也可能是 1500 字节（1480 字节数据 + 20 字节 IP 头部），最后一个包将是 1040 字节（1020 字节数据 + 20 字节 IP 头部）。

### 分片偏移字段（Fragmentation Offset Field）
分片偏移值表示你正在接收的完整数据包的哪部分。继续之前的 4000 字节 IP 示例，第一个分片将包含 0-1479 字节的数据，偏移值为 0。第二个分片将包含 1480-2959 字节的数据，偏移值为 185 (1480/8)。第三个也是最后一个分片将包含 2960-3999 字节的数据，偏移值为 370 (2960/8)。接收器会在将这三个包传递给协议栈之前，将它们重新组装成一个大数据包。

### TTL 字段（TTL Field）
存活时间（TTL）字段是一个 0 到 255 之间的数字，表示数据包在被丢弃之前允许在网络上停留多长时间。这背后的思想是，在发生路由错误导致数据包陷入“路由循环”时，TTL 会导致数据包最终超时并被丢弃，防止网络被循环数据包完全拥塞。

## ICMP

ICMP 设计用于网络化主机之间就网络状态进行通信的手段。由于这些数据仅供底层操作系统使用而不供用户使用，ICMP 不支持端口号概念，它不需要可靠传输，也不保证数据包的顺序。

每个 ICMP 数据包都包含一个类型字段，告知接收者消息的性质。最流行的类型是回显请求（Echo-Request），它被著名的 `ping` 程序使用。当主机接收到 ICMP 回显请求消息时，它用 ICMP 回显应答（Echo-Reply）消息进行响应。这允许发送者确认另一个主机处于在线状态，而且我们可以通过获取响应所需的时间来了解两个主机之间的网络延迟。

当路由器处理数据包时，TTL 值会减 1。当 TTL 达到 0 时，发生该操作的路由器会通过互联网控制消息协议（ICMP）发送消息通知发送者此情况（参见“ICMP”侧边栏）。

### 协议字段（Protocol Field）
此字段告诉你该数据包应该交付给哪种高层协议。通常，它的值可能是 TCP、UDP 或 ICMP。

### 头部校验和（Header Checksum）
此 IP 头部的最后一个值是校验和。当主机构建发送的 IP 数据包时，它计算 ICMP 校验和并将其放入此字段中。接收者可以进行相同的计算并比较值。如果值不匹配，接收者就知道数据包在传输过程中损坏了。例如，闪电产生的电干扰可能会导致数据包损坏。

### 源和目的 IP 地址字段（Source and Destination IP Address Fields）
最后，IP 头部中最重要的数字是源 IP 和目的 IP 地址。这些值以 32 位整数的形式存储，而不是人类可读的点分十进制表示法。例如，`192.168.1.1` 的实例，其值将是十六进制 `c0a80100` 或十进制 `3232235777`。

## 传输控制协议 (TCP)

TCP 运行在 OSI 模型的传输层（第 4 层）。TCP 为单个通信会话提供可靠传输——即从客户端到服务器的单一连接。

除了会话外，TCP 还处理数据包的排序和重传。如果数据包没有按顺序到达，协议栈会在将其传递给应用程序之前将它们重新排序。最后，TCP 连接也是双向的。这意味着客户端和服务器可以在同一个连接上发送和接收数据。

### 源和目的端口字段（Source and Destination Port Fields）
端口是 TCP/IP 网络通信中使用的数值标识符，允许主机内同时进行多个进程间的通信。因此，端口号用于识别主机内运行的进程或服务。在 TCP/IP 中，端口号是 0 到 65535 之间的整数。通常，源端口大于 1024，端口 1–1024 在大多数操作系统（包括 Linux、Solaris 和多个 Windows 版本）中保留供系统使用。相反，目的端口通常较小；大多数服务位于那里，尽管这不是强制性的。

### 序列和确认字段（Sequence and Acknowledgment Fields）
TCP 头部接两个数字是序列号和确认号。这些值被 TCP 用于确保数据包顺序正确，并告诉发送者哪些数据包已正确接收。在日常管理任务中，你不必处理它们。

每当数据包设置了确认位，接收者可以使用它来确认从发送者处接收了多少数据（“杂标志字段”）。

### 头部长度（Header Length）
与 IP 的头部长度类似，TCP 的头部长度告诉我们头部的长度，包括任何 TCP 选项。此字段中的任何值乘以 4 即可得到字节值。

### 杂标志位字段（Miscellaneous Flags Field）
这个字段有点复杂。TCP 使用一系列标志位来指示数据包是准备用于建立连接、包含数据还是终止连接。这些标志位（按出现顺序排列）分别是：紧急（URG）、确认（ACK）、推送（PSH）、重置（RST）、同步（SYN）和结束（FIN）。它们的含义如下：

- URG：意味着数据包中包含数据，且应该被优先处理。
- ACK：确认已成功接收到数据。
- PSH：请求立即处理任何接收到的数据。
- RST：立即终止连接。
- SYN：请求启动新连接。

### 窗口大小字段（Window Size Field）
这是 TCP 头部中的下一个字段。TCP 使用了一种名为*滑动窗口*的技术，该技术允许连接的双方告诉对方处理连接时还有多少缓冲区空间。当新数据包到达连接上时，可用窗口大小会根据数据包的大小而减小，直到操作系统有机会将数据从 TCP 的输入缓冲区移动到接收端应用程序的缓冲区空间。窗口大小是逐连接计算的。

### TCP 校验和字段（TCP Checksum Field）
TCP 校验和的目的与 IP 校验和相似，都是为了向接收方验证接收的数据没有损坏。与 IP 校验和不同，TCP 校验和实际上同时考虑了 TCP 头部和正在发送的数据。

### 紧急指针字段（Urgent Pointer Field）
TCP 头部的最后一部分——紧急指针，指向重要数据之后字节的偏移量。当 URG 标志位被设置时会观察到此值，并告诉接收端 TCP 栈存在某些重要数据。TCP 栈应该将此信息传递给应用程序，使其知道应该对该数据给予特殊关注。

在现实中，你很难发送一个使用 URG 位的数据包。大多数应用程序并不知道发送给它们的数据是否紧急，而且大多数应用程序并不真正在乎。

## TCP 的实际运作（TCP In Action）

如前所述，TCP 支持*连接*的概念。每个连接都必须通过一个序列来建立；一旦双方开始发送数据，它们必须通过另一个序列来关闭连接。

# 无线网络管理：入门指南

这里回顾了打开 TCP 连接、发送数据和拆除连接的完整过程。

请注意，这里提供的信息经过了简化，遗憾的是，由于 TCP 的复杂性，无法涵盖 TCP 连接可能出现的所有场景。然而，这些信息应该足够帮助判断网络层面何时出现了问题。

建立连接：TCP 为其打开的每一个连接都会经历“三次握手”，以便允许双方发送彼此的状态信息，并相互确认已收到的该数据。

- 第一个数据包由想要与服务器建立连接的主机发送，我们称之为为客户端。客户端通过 IP 发送一个 TCP 数据包，并将 TCP 标志位设置为 SYN。序列号是客户端在发送给另一个主机（服务器）的所有数据中将使用的初始序列号（ISN）。
- 第二个数据包从服务器发送到客户端。此数据包包含两个 TCP 标志位：SYN 和 ACK。ACK 告诉客户端它已经收到了第一个（SYN）数据包。通过在确认字段中放置客户端的序列号来完成双重检查。SYN 告诉客户端服务器将使用哪个序列号发送其响应。
- 第三个数据包从客户端发送到服务器。它在 TCP 标志位中仅设置了 ACK 位，用于向服务器确认已收到了其 SYN。此 ACK 数据包在序列字段中包含客户端的序列号，在确认字段中包含服务器的序列号。这应该足够建立连接了。
