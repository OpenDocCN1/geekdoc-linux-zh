
在关闭所有程序后，`-h`选项将停止机器，`-r`选项将重启。
非`root`用户可以使用`reboot`和`halt`命令在运行级别1到5之间关闭系统。然而，并不是所有的Linux操作系统都支持此功能。

如果计算机没有自动断电，请务必不要在出现指示系统已停止的消息之前关闭计算机。

未能等待此消息出现，可能意味着并不是所有的硬盘分区都已卸载，并可能导致文件系统损坏。

## 第2章 启动加载器

在Red Hat Linux运行之前，它必须由一个称为启动加载器的特殊程序加载到内存中。启动加载器通常存在于系统的主硬盘（或其他媒体设备）上，其唯一职责是将Linux内核及其所需文件（在某些情况下为其他操作系统）加载到内存中。

## 2.1 启动加载器与系统架构

每个能够运行Red Hat Linux的架构都使用不同的启动加载器。例如，Alpha架构使用`aboot`启动加载器，而Titanium架构使用`ELILO`启动加载器。

本章讨论了Red Hat Linux为x86架构提供的两种启动加载器：`GRUB`和`LILO`的命令和配置选项。

## 2.2 GRUB

GNU Grand Unified Boot loader或`GRUB`是允许用户在系统启动时选择加载已安装操作系统或内核的程序。它还允许用户向内核传递参数。

### 2.2.1 GRUB与x86启动过程

本节详细讨论了`GRUB`在启动x86系统时起到的特定作用。要查看整体启动过程，请参阅第1.2节“详细查看启动过程”。

`GRUB`按以下阶段将其加载到内存中：

- 阶段1或主启动加载器由BIOS通过MBR读取到内存。主启动加载器存在于MBR内少于512字节的磁盘空间中，能够加载阶段1.5或阶段2加载器。
- 如果需要，阶段1.5加载器由阶段1加载器读取到内存。某些硬件需要中间步骤才能到达阶段2加载器。这有时是因为`/boot`分区位于硬盘的1024磁头上方或使用了LBA模式。阶段1.5加载器位于`/boot`分区或MBR和`/boot`分区的一小部分。
- 阶段2二级启动加载器被读取到内存。二级加载器显示`GRUB`菜单和命令环境。此界面允许您选择启动哪个操作系统或Linux内核，向内核传递参数，或查看系统参数（如可用内存）。
- 二级启动加载器将操作系统、内核和`initrd`加载到内存。`GRUB`决定启动哪个操作系统，将其加载到内存并将机器的控制权交给该操作系统。

用于启动Red Hat Linux的启动方法被称为直接加载法，启动加载器直接加载内核，没有中间环节。
- 有关系统BIOS和MBR的更多信息，请参阅第1.2节。

其他操作系统使用的启动方法可能有所不同。例如，Microsoft's DOS和Windows操作系统使用链加载方法。在此方法下，MBR指向操作系统的第一个扇区。它找到启动操作系统所需的文件。

`GRUB`支持直接加载和链加载启动方法，允许其启动任何操作系统。

> 警告
> 在安装期间，Microsoft's DOS和Windows安装程序会完全覆盖MBR，破坏现有的启动加载器。如果创建双系统，最好先安装操作系统。有关如何此操作，请参见附录“在双系统环境中安装Red Hat Linux”。

### 2.2.2 GRUB的特性

`GRUB`包含了许多优于x86架构其他启动加载器的特性。以下是所有重要功能的部分列表：

- `GRUB`在x86机器上提供了真实的基于命令的预环境。这为用户加载操作系统或获取系统信息提供了最大的灵活性。多年来，许多x86架构都开发了从命令行启动的环境。虽然`LILO`也提供某些命令功能，但`GRUB`更丰富。
- `GRUB`支持逻辑块寻址（LBA）模式。LBA解决了硬盘固件中的地址转换问题，并适用于任何IDE和所有SCSI设备。在LBA出现之前，启动加载器无法遇到BIOS 1024限制，即BIOS无法找到磁盘的文件。LBA允许`GRUB`从超过1024道的分区启动操作系统，只要系统BIOS支持LBA。大多数现代BIOS版本都支持LBA。
- `GRUB`可以读取分区。此功能允许`GRUB`每次系统启动时访问其配置文件`/boot/grub/grub.conf`，无需用户在更改配置时重新向MBR写入新版本的启动加载器。只有当`/boot`分区的物理位置发生移动时，用户才需要重新安装`GRUB`。有关将`GRUB`安装到MBR的详细信息，请参阅第2.3节。

## 2.3 安装GRUB

如果在Red Hat Linux安装过程中没有安装`GRUB`，可以在之后安装。一旦安装，它将成为默认启动加载器。

在安装`GRUB`之前，请确保使用最新的可用`GRUB`包或使用Red Hat Linux安装光盘中的`GRUB`包。有关安装包的说明，请参阅“使用RPM进行软件包管理”章节。

一旦安装了`GRUB`包，打开`root` shell并执行命令`/sbin/grub-install <location>`，其中`<location>`是阶段1加载器应该安装的位置。

## 章节 引导加载程序

以下命令将`GRUB`安装到主IDE总线上主IDE设备的MBR中：`/sbin/grub-install /dev/hda`

下一次系统启动时，`GRUB`图形加载菜单将在内核加载到内存之前出现。

## 2.4 GRUB术语

在使用`GRUB`之前，需要理解的最点之一是该程序如何引用设备（例如驱动器和分区）。在配置`GRUB`启动多个操作系统时，这些信息尤为重要。

### 2.4.1 设备名称

假设系统有多个硬盘。系统的第一块硬盘在`GRUB`中被称为`(hd0)`。该硬盘上的第一个分区被称为`(hd0,0)`，而第二块硬盘上的第五个分区被称为`(hd1,4)`。在通常情况下，使用`GRUB`时的文件命名规范拆解如下：

```
<type-of-device><bios-device-number>,<partition-number>
```

括号和逗号对于设备命名规范非常重要。`<type-of-device>`指的是指定的是硬盘`(hd)`还是软磁盘`(fd)`。

`<bios-device-number>`是根据系统的BIOS定义的设备编号，从0开始。次IDE硬盘编号为1。其顺序大致等同于Linux内核通过字母排列驱动器的方式，其中`hda`中的`a`对应0，`hdb`中的`b`对应1，以此此类推。

![](img/31025704b51d5760c0228ff0f3db98bf_28_0.png)

> 注意
> `GRUB`的设备编号系统从0开始，而不是从1开始。未能区分这种区别是新`GRUB`用户最常犯的错误之一。

`<partition-number>`与磁盘设备上的某个特定分区相关。虽然大多数分区通过数字指定，但如果系统使用BSD分区，则通过字母（如`a`或`c`）进行指定。

`GRUB`对设备使用以下命名规范：

- 硬盘是IDE还是SCSI并不重要。所有硬盘都以`hd`开头。
- 要相对于分区指定整个设备，请省略逗号和分区号。在告诉`GRUB`为特定磁盘配置MBR时，这很重要。例如，`(hd0)`指定第一个设备上的MBR，而`(hd3)`指定第四个设备上的MBR。
- 如果系统有多个驱动器设备，知道BIOS中设置的驱动器启动顺序非常重要。如果系统只有IDE或SCSI驱动器，这操作非常简单，但如果混合了多种设备，情况可能会变得复杂。

### 2.4.2 文件名和启动列表

在向`GRUB`输入涉及文件的命令时（例如，在允许启动多个操作系统时使用的菜单列表），有必要在指定设备和分区后立即包含该文件。

绝对文件名的示例规范组织如下：

```
<type-of-device><bios-device-number>, <partition-number>/path/to/file
```

在大多数情况下，用户会通过该分区上的目录路径加上文件名来为`GRUB`指定文件。

也可以为`GRUB`指定实际上并未出现在文件系统中的文件，例如出现在分区前几个块中的链加载器（chain loader）。要指定这些内容，你必须提供一个块列表（blocklist），它会告诉`GRUB`逐块地显示文件在分区中的位置，由于文件可能由几组不同的块组成，因此编写块列表有特定方法。每个文件的部分由一个块的偏移量和从该偏移点开始的块数来描述，这些部分以逗号分隔的顺序组合在一起。

以下是块列表示例：

```
05,100+2
```

```
05,100+2,25,100+1,199,100+1
```

```
(hd0,0)
```

```
(hd0,0
```

```
+1
```

```
(hd0,0)
```

```
+1
```
