## 8.1. 我如何在 Linux 中进行图形编程？

来自 Paul 的回答：

> 在 Linux 中图形编程有多种选择。使用哪种取决于你想做什么。虽然没有哪一个网站涵盖了所有信息，但这里有一些建议：
> GALib：这是一个用于控制台 SVGA 的 C 库。
> 优点：非常易学，有良好的代码示例，与 DOS 下对应的 gfxx 库没有太大区别，你在 DOS 中知道的所有效果都可以很小困难地转换。
> 缺点：由于它们直接写入硬件，运行它们需要特殊权限，不兼容某些芯片组，但可以在 X-Windows 下运行。
> 请在 http://ftp.isco.za 搜索 `svgalib-1.4x`。
> Framebuffer（帧缓冲区）：在 SVGA 分率下自己实现图形。
> 优点：速度快，线性映射视频访问，如果你愿意可以使用 ASM：
> 缺点：必须编译进内核，存在特定于芯片组的问题，必须退出 X 环境才能运行，依赖于对 Linux 系统调用和内核的深厚知识，调试困难。
> 示例：(http://www.linuxassembly.org/) 以及 leaves 示例，以及我个人关于汇编版 framebuffer 代码和技巧的网站 (http://ma.verick.co/linuxx/)。
> Xlib：XFree86 的访问控制和开发库。
> 优点：完全控制你的 X 应用。
> 缺点：学习困难，操作极其痛苦，并且需要对 X 底层工作原理有所了解。
> 如果你真的以此虐，否则不建议使用。所有的包含文件和库文件可能已经安装好了，所以你拥有所需的内容。
> 低级 API：包括 PTC、SGI 和 Clanlib。
> 优点：非常灵活，可以在 X 或控制台下运行，通常会部分抽象视频硬件让你能够绘制线性表面，有大量良好的代码示例，可以链接到 OpenGL 和音频库等其他 API，免费提供 Windows DirectX 版本。
> 缺点：速度不如自己实现，即使是开发版也是如此（版本变化频繁）。
> 示例：PTC 和 SGI 有极好的演示，SDL 用于 sdlQuake、Myth II、Civ CTP，Clanlib 也已用于游戏。
> 高级 API：OpenGL – 还有吗？
> 优点：接口整洁，功能和示例极其丰富，行业标准。
> 比如你可以从 SGI 的演示中学习。
> 缺点：通常必须硬件加速，某些版本和平台之间存在怪异。
> 示例：loads - 请查看 we mesa3.org 的链接部分。
> 想要开始的话可以查看 avgalib 示例，并安装 SDL 且使其运行。在此之后，大有可为。

## 8.2. 我如何在 Linux 下调试汇编代码？

有一个早期版本的汇编语言调试器（Assembly Language Debugger），它是专门为汇编代码设计的，并且可以移植到 Linux 和 #BSD 上运行。它已经可以使用了，应该是正确的选择，去看看吧！

你也可以尝试 `gdb`。虽然它是一个源码级调试器，但可以用来调试纯汇编代码，通过一些技巧，你可以使用 `gdb` 实现你的需求（遗憾的是，nam-'g' 选项不会为 `gdb` 生成正确信息；这是一个讨厌的 bug，这里是来自 Dmitry Bakhvalov 的回答）：

- 我个人使用 `gdb` 作为调试辅助工具。尝试一下这种方法：

1) 使用以下命令：
   `$ nm -f elf -g smth`

2) 启动 `gdb`：
   `$ gdb smth`

3) 在 `gdb` 中：
   `$ gdb *0x`

## 8.7. 我不理解如何使用系统调用！

来自 Patrick Model 的回答：

当你调用 `sys_open` 时，你会得到一个文件描述符，它实际上是你的进程所拥的所有打开的文件描述符表中的索引。`stdin`、`stdout` 和 `stderr` 分别是 0、1和2，因为从那里开始它们按此顺序为你的进程打开。此外，请注意，你打开的第一个文件描述符（在没有关闭任何这些描述符之前）总是3，并从那里开始递增。

理解了索引方案就能解释 `select` 是什么了。当你调用 `select` 时，你是在表示你在等待某些文件描述符可读、某些可写，并监控某些除了这些以外的。你的进程最多可以打开 1024 个文件描述符，因此 `fd_set` 只是一个位掩码，用于描述哪些文件描述符对于每个操作是有效的。明白的吗？

由于你打开的每个 fd 都是索引，且在每个 `fd_set` 中它只需要开启或关闭，因此 `fd_set` 结构只需要 1024 位。1024 / 32 = 32 个 long 就足够表示该结构。

现在，来看一个松散的例子。
假设你想从一个文件描述符读取（不带超时）。

- 分配与 `fd_set` 等效的内存。

```assembly
.data
my_fds times:32 dd 0
```

- 打开你想读取的文件描述符。

- 设置 `fd_set` 结构中的位。

首先，你需要确定 32 位双字 dword 中的哪一位。在设置位时，`bts` 会对 32 取模。这就是为什么你首先需要确定要从哪个 dword 开始。

```assembly
mov edx,0
mov ebx,32
div ebx
lea eax,my_fds
bts ebx[eax*4],ed
```
