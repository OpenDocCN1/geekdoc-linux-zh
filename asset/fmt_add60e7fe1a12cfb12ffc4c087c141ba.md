
## 第 10 章 像计算机一样计数

我
- 食物：1
- 重金属音乐：1
- 穿得正装：0
- 足球：1

爸爸
- 食物：1
- 重金属音乐：0
- 穿得正装：1
- 足球：1

现在，如果我们只需要记住这些项目在每个项目中的位置，我们就得到了：

我
1101

爸爸
1011

现在，让我们看看，我们想要得到一份我和爸爸都喜欢的物品列表。你将使用 `AND` 操作。所以：

```
1101 AND
1011
--------
1001
```

这翻译为：

我们都喜欢的东西

食物：是

重金属音乐：否

穿得正装：否

足球：是

记住，计算机并不知道这些 1 和 0 代表什么。那是你的工作，也是你的程序的工作。如果你围绕这种表示法编写了一个程序，你将会在某一点检查每个 `bit`，并编写代码告诉用户它是做什么的（如果你问计算机两个人达成了什么共识，而它回答 1001，那它将没有任何用）。无论如何，假设我们想知道我们意见不一致的事情。为此，我们将使用 `XOR`，因为只有当其中一个为 1 而另一个不为 1 时，它才会返回 1。所以：

```
1101 XOR
1011
----
```

剩下的由你翻译回来。

之前的操作：`AND`、`OR`、`NOT` 和 `XOR` 被称为布尔运算符，因为它们最初是由乔治·布尔（George Boole）研究的。所以，如果有人提到布尔运算符或布尔代数，你现在知道他们在说什么什么了。

除了布尔运算外，还有两种不是布尔的二进制运算符：移位（`shift`）和旋转（`rotate`）。移位和旋转的作用正如其名，并且可以向右或向左进行。左移会将二进制数的每个数字位向左移动一位。左旋转会在个位上放置 0，并切掉最左侧的数字。右旋转执行相同的操作，但它会将最左侧的数字取出并放在个位上。例如：

```
Shift 10010111 = 00101110
Rotate left 10010111 = 00101111
```

注意，如果你对每个数字位都旋转数字（例如，将一个 32 位数旋转 32 次），你将得到与开始时相同的数字。然而，如果你对每个数字位都进行移位，你最终会得到 0。那么，这些移位有什么用呢？嗯，如果你有代表某些事物的二进制数，你可以使用移位来查看每个单独的值。例如，假设我们把爸爸的喜好存储在一个寄存器（32 位）中。它看起来像这样：

0000000000000000000000000011

现在，正如我们之前所说的，这不能作为程序的输出。所以，为了输出，我们需要移位和*掩码*（`masking`）。掩码是消除你所有不想要的内容的过程。在这种情况下，对于我们寻找的每个值，我们都会移动数字，使该值位于个位，然后掩码该数字使其成为我们唯一看到的内容。掩码是通过与一个将我们感兴趣的比特设置为 1 的数字进行 `AND` 运算来实现的。例如，假设我们想打印爸爸是否喜欢正装。那是从右数起的第二个值。所以，我们必须将数字向右移动 1 位，使其看起来像这样：

000000000000000000000000000101

然后，我们只需要查看该数字，所以我们通过与 00000000000000000000000000001 进行 `AND` 运算来掩码它：

```
000000000000000000000000001001 AND
00000000000000000000000000001
--------------------------------
```

00000000000000000000000000001

如果我爸爸喜欢穿正装，这将使寄存器的值变为 1，如果不喜欢，则为 0。然后我们可以与 1 进行比较并打印结果。代码看起来如下：

```assembly
# 注意，假设寄存器 %ebx 持有
# 我爸爸的偏好

mov %ebx, %eax # 这将信息复制到 %eax，
# 这样我们就不会丢失原始数据

shr $1, %eax # 这是移位运算符。它代表
# Shift Right Long（长右移）。第一个数字
# 是要移动的位数，
# 第二个是要移动的寄存器

# 这执行了掩码操作
andl $0b00000000000000000000000000000001, %eax
## 检查结果是 1 还是 0
cmpl $0b00000000000000000000000000000001, %eax
# 如果结果相等则跳转（示例补充）
```

### 浮点数表示

因为计算机只能存储固定大小的有限值。十进制数可以是任何长度，包括无限长度（想象循环小数，例如 1 / 3 的结果）。

计算机处理小数的方法是将它们存储在固定的精度（有效位数）中。计算机将十进制数分为两部分存储——指数和尾数。尾数包含将要使用的实际数字，而指数是该数字的大小。例如，12345.2 被存储为 1.23452 * 10^4。尾数是 1.23452，指数是 4。所有数字都以 X.XXXXX * 10^XXX 的形式存储。数字 1 被存储为 1.00000 * 10^0。

现在，尾数和指数非常长，这导致了一些有趣的问题。例如，当计算机存储一个整数时，如果你对其加 1，得到的数字会变大。这在浮点数上并不一定发生。如果数字足够大，例如 5.234 * 10^5000，给它加 1 可能甚至无法在尾数中体现（记住，两部分都是有限的）。这会影响几件事，特别是运算的顺序。假设我向 5.234 * 10^5000 加了几十亿或万亿次。猜怎么着——这个数字完全不会改变。然而，如果我给自己加足够多次，然后将其加到原始数字上，可能会产生影响。

你应该注意，大多数计算机执行浮点运算的时间比执行整数运算长得多。因此，对于真正需要速度的程序，通常使用整数。

### 负数

你认为计算机上是如何表示负数的？一种想法可能是使用数字的第一位作为符号位，所以 00000000000000000000000000000001 代表数字 1，而 100000000000000000000000000000001 代表 -1。这很有道理，事实上，一些旧的处理器就是这样工作的。然而，它存在一些问题。首先，对这种方式表示的数字进行加减法需要大量的电路。更有问题的是，这种表示法在数字 0 上存在问题。在 във系统中，你可以同时拥有负 0 和正 0。这导致了许多问题，例如“负零是否应该等于正零？”以及“在各种情况下零的符号应该是什么”。

这些问题通过使用名为`补码`的负数表示法解决了。要得到一个数字补码形式的负数表示，你必须执行以下步骤：
- 1. 对数字执行 `NOT` 操作
- 2. 对结果数字加 1

所以，为了得到 0000000000000000000000000001 的负数，你首先执行 `NOT` 操作，得到 11111111111111111111111111111110，然后加 1，得到 11111111111111111111111111111111。要得到负二，首先取 00000000000000000000000000000010。数字取反是 11111111111111111111111111111101。加 1 得到的数字就像是正数一样，并得出正确的答案。例如，如果你在二进制中将 1 和 -1 相加，你会发现所有数字都翻转成了零。第一位作为符号位，这使得判断数字是正是负变得非常简单。负数的最左位始终为 1。这也改变了给定位数下哪些数字是有效的。对于有符号数，可能的值范围被平分，以允许存在正数和负数。例如，一个字节通常可以有高达 255 的值。然而，一个有符号字节可以存储从 -128 到 127 的值。

有符号数补码的一点是，与无符号数值不同，如果你增加位数，不能简单地在数字左侧添加零。例如，假设我们正在处理四位数值，数字是 -3，即 1101。如果我们将其扩展到八位寄存器，我们不能将其表示为 0001101，因为这代表的是 13 而不是 -3。当你增加有符号数值的大小时，你必须执行`符号扩展`。符号扩展意味着在增加位数时，必须用符号位上的任何数字来填充数值的左侧。所以，如果我们将负数扩展 4 位，我们应该用 1 填充新位。如果我们扩展正数 4 位，我们应该用 0 填充新位。因此，-3 从四位扩展到八位将得到 11111101。

x86 处理器具有不同形式的指令，取决于它们的操作对象是有符号还是无符号的。这些列在附 B 中。例如，x86 处理器既有保留符号位的右移 `sar`，也有不保留符号位的右移 `shr`。

### 八进制和十六进制

到目前为止计数系统有十进制和二进制。然而，计算中还使用了另外两种——八进制和十六进制。事实上，它们的频率比二进制更高。八进制是一种只使用 0 到 7 数字的表示法。八进制的优点是，每 3 个二进制位组成一个八进制位。所以：
- 0 是 000
- 1 是 001
- 2 是 010
- 3 是 011
- 4 是 100
- 5 是 101
- 6 是 110
- 7 是 111
