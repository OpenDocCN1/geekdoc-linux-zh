
`echo "one two three" four`

one two three four

`% echo ^^`

`echo "one two"`

one two three

`% echo 'ls *'`

bar.cc foo.cc

`% echo !*`

`echo 'ls *'`

bar.cc foo.cc

```
你可以修改单词选择器以在插入新命令之前更改单词的形式。修饰符的格式为 `:x`，其中 x 是一个指定如何修改单词的字母。例如，`!vi*:` 替换 vi 命令的第一个参数；对于参数 `/usr/X/lib/samples/xclock*`，`:t` 的值为 `xclock.c`。
```

## 表 12.7. 历史替换修饰符。

| 修饰符 | 功能 |
| :--- | :--- |
| `:e` | 删除“文件”后缀以外的所有内容。对于参数 `foo.sh`，`:e` 返回 `.sh` |
| `:h` | 删除末尾的路径组件。连续的 `:h` 修饰符从右到左一次删除一个路径组件。对于参数 `/usr/local/etc/http/htdocs/index.html`，`:h` 返回 `/usr/local/etc/http/htdocs`，而 `:h:h` 返回 `/usr/local/etc/http/htpd` |
| `:p` | 在命令行的任何历史替换中使用时，导致 shell 在替换后打印命令但不执行它。使用 `:p` 在执行之前尝试历史替换的效果。 |
| `:q` | 将替换后的单词或多个单词括在引号中以防止进一步替换。 |
| `:r` | 删除 `.string` 文件名后缀。例如，对于参数 `:foo.cc`，`:r` 返回 `foo`。`:r` 运算符一次删除一个后缀。例如，`:r` 应用于 `arch.tar.gz` 返回 `arch` |
| `:s/x/y` | 将替换字符串中的 x 替换为 y。字符串 `:x` 不能是正则表达式。y 中的符号 `&` 被替换为搜索字符串 x——例如，`:s/bill/&/substitutions` `:s/?user/?user?`。如果后面跟着换行符，则省略最后的。任何字符都可以通过反斜杠 (`\`) 转义作为分隔符（`/` 或你的分隔符）或 & 的文本字符——例如 `:s\/usr\/user/`。可以省略搜索字符串 x，此时使用行的搜索字符串。或者，如果没有之前的 :s，则使用 `!?string` 的搜索。 |
| `:t` | 删除路径的所有组件，仅返回文件名。对于单词 `/usr/bin/ls`，`:t` 的值为 `ls`。 |
| `:x` | 在空格、制表符和换行符处分割所选单词。 |
| `&` | 重用上一个字符串替换修饰符。例如，如果命令行中出现 `:s`，则 `!grep:2:s/bill/marty/ !3:&` 等同于 `!grep:2:s/bill/marty/ !3:s/marty/` |

通常情况下，`:a` 只影响第一个单词。在选择多个单词时（例如使用 `!12:2*`），你可以在修饰符列表前插入 `g` 来对所有所选单词应用修饰符。例如，`!12:2*:gh` 对所有单词应用 `:h` 修饰符。`g` 不适用于 `:p`、`:q` 和 `x` 修饰符。

在同一行使用两个或多个表达式时，可以在历史替换中省略命令标识符；连续的引用指向第一个命令。

```
% vi %grep^t: :3:t %4:
```
都指向 `grep` 命令，但选择了第一、第三和第四参数。

历史机制支持缩写 `^`，这对于纠正上一行的输入错误非常有用。缩写的一般形式为 "x:y"，其中 x 和 y 是字符串。选择命令行并搜索字符串；如果找到，则将其替换为 y 然后执行。例如，对于命令 `cd /usr/ban`，输入行 `^ban-bin`（或 `^a`）来执行 `cd /usr/bin`。脱字符 `^` 是行中被识别为行编辑替换的第一个空字符。这仅适用于紧之前的命令；要编辑最后之外的其他命令，必须使用行编辑器 `line:s/x/y`。

历史替换机制的最后一个重要规定是，你可以将任何历史引用括在大括号 `{}` 中以将其随后的字符隔离。因此，`{!vi^h}.cc` 形成一个以所选历史引用开头并以 .cc 结尾的单词。

**提示：** 使用历史替换 `*` 防止意外删除文件。在创建用于删除文件的表达式时，使用 `ls` 命令查看结果。当你确认只有预期的文件被删除后，使用带有 `*` 替换的 `rm` 命令。在下面的示例中，用户正尝试删除所有与 C++ 相关的源文件和一个 Makefile。

```
ls pub* Makefile

Makefile pubList.txt publish.cc publish.hh

ls pub* Makefile

Makefile publish.cc publish.hh

rm *
```

## 变量

你可以使用变量来存储临时值，shell 脚本可以使用变量来管理变化的信息。shell 本身有自己的变量，你可以用它们来定制 C shell 功能和你的 C 环境。

变量实际上是 shell 的一个条目。

但每个元素只能代表一个字符串值。

注意：许多版本的 C shell 不支持稀疏数组。稀疏数组是一种并非每个索引都有值的数组。除非数组在某位置已经有了元素，否则无法对该位置进行访问。

```
set: Subscript out of range
```

当对三个元素的数组尝试进行赋值：

```
set name[4]=foo
```

或引用

```
echo $name[2]
```

时，会生成上述消息。

**删除本地 shell 变量：** `unset` 你可以使用 `unset` 命令从 shell 内存中删除一个或多个 shell 变量：

```
unset pattern
```

`unset` 命令仅对用 `set` 命令定义的变量有效；使用 `setenv` 命令删除用 `setenv` 定义的变量。

对于 `pattern`，请指定一个字符串，其可能可选包含一次或多次模式匹配字符 `*`、`?` 或 `[..]`。shell 已知的所有名称匹配指定模式的本地变量都将被删除。如果没有没有项匹配 pattern，你将不会收到任何消息，也不会收到变量已删除的确认。

**显示和设置全局环境变量：** `setenv` 你可以使用 `setenv` 命令创建新的环境变量。环境变量会被传递给 shell 脚本和调用的命令，这些命令可以在不先定义的情况下引用变量（在 shell 脚本中传递你想访问的变量时不需要也不应该使用 `setenv` 语句）。请参考本章节后面的“自定义你的 shell 环境”以获取更多环境变量。

`setenv` 命令的格式如下：

```
setenv [name value]
```

当不带参数使用时，`setenv` 命令会列出当前生效的所有全局变量及其值。当以 `setenv name value` 形式使用时，它创建一个指定名称的新全局变量，并将字符串值赋值为其值。如果值包含空格或制表符等字符，请确保用引号括起该值。请参考本章节后面的“特殊字符的引用和转义”以获取有关 shell 特殊字符和使用引用技术的信息。

UNIX 提供了一个命令 (`env`) 用于显示当前环境变量列表及其值。`env` 命令支持多个用于修改当前环境的选项和参数。

本章节后面的“使用预定义变量”部分提供了由 C shell 定义的所有变量（本地和环境变量）列表。由其他 UNIX 命令定义的环境变量定义在相应组件的文档中。遗憾的是，并没有一个完整的环境变量列表，因为某些变量是由非 shell 程序定义的。例如，`mailx` 命令定义了一些变量，而 `vi` 命令会查找它自己的变量。总之，环境变量是可选的。无论如何：如果你不知道某个 UNIX 命令，该命令在没有环境变量的情况下也能工作。无论如何，请注意 C shell 并不负责定义所有的环境变量；shell 仅仅提供了一种操作和访问变量的手段。

## 删除全局环境变量：`unsetenv`

要删除全局环境变量，你使用使用 `unsetenv` 命令：

```
unsetenv variablename

unsetenv pattern
```

使用 `unsetenv` 命令从 shell 内存中删除一个或多个环境变量。`unsetenv` 仅对用 `setenv` 命令定义的变量有效；使用 `unset` 命令删除用 `set` 定义的变量。

要删除特定变量，请将其指定为 *variable*。要删除多个变量定义，请使用 *pattern* 指定一个字符串，其可能可选包含一次或多次模式匹配字符 `*`、`?` 或 `[..]`。shell 已知的所有名称匹配指定 *pattern* 的环境变量都将被删除。如果没有项匹配 *pattern*，你将不会收到任何警告消息，也不会收到变量已删除的确认。

## 使用引用表达式获取变量值

你通过在命令行上编写变量引用来获取 shell 变量的值。变量引用会将整个引用表达式——包括引入引用的 `$`、变量名以及任何不匹配引用的字符——替换为字符串变量的值。

变量引用本身并不定义单词的开始或结束；引用可以是一个完整的单词，也可以是单词的一部分。替换后的字符串与单词中的其他字符结合，得到替换后的变量。如果引用使用了一个或多个空格进入全局单词，该单词会被引用。如果 shell 变量 *var* 的值为 "two"，例如，引用表达式 `$var` 在替换后显示为两个单词，但带引号的字符串 `\$var`

变量可以导致本地或全局变量值的替换。本地变量如果存在，则使用它；环境变量的值将被提取。shell 变量和环境变量有效地隐藏了环境变量的值。如果需要环境变量的值，shell 必须是 `unset`。

你可以使用表 12.8 中的任何变量引用形式。

## 表 12.8. shell 变量引用。

| 语法 | 含义 |
| :--- | :--- |
| `$(name)` | 替换为 *name* 的值。如果 $name 变量未定义则会报错。 |
| `${name}${name}` | 替换为数组变量 name 的元素值。对于 $n$，使用数字或元素范围 m-n。使用 $-n$ 替换元素 i-n，并使用 $m-$ 替换从 $m$ 到数组末尾的元素。 |
| `$#{name}$#name` | 替换为数组变量 name 中的元素值。 |

## 使用数组变量

否则，变量只能有一个值。相反，数组变量可以有任意数量的值（只要 shell 有可用内存来存储这些值）。例如，`path` 变量被 shell 用于搜索命令的目录列表，其中每个元素是一个路径。

你可以通过两种方式为数组变量赋值：一次性或逐个。并不是所有的 shell 版本都允许逐个的赋值方法。要一次性分配多个值，使用 wordlist 到命令。wordlist 是带括号的单词列表。例如，以下数组包含四个值：

```
set path=$(usr/bin ~/bin)
```

wordlist 中的每个单词都被分配给数组的下一个可用元素。将 wordlist 赋值给变量 [index] 会自动将变量定义为数组。

要单独为数组元素赋值，必须使用下标符号。在 `$name[1]` 的形式中，索引必须是指定元素的数字，因此 `$name[1]` 是数组第一个元素的引用。以下操作为 planets 分配三个值：

```
% planets[1]=Mercury

% planets[2]=Venus

% planets[3]=Earth

% echo Planet 3 is $planet[3]

Planet 3 is Earth
```

如果你在没有索引的情况下引用数组变量名，shell 将引用替换为 wordlist：

```c
% echo The planets $planets

The planets are (Mercury Venus Earth)
```

许多版本的 C shell 不会包含括号。如果你的 C shell 加上了括号 `()`，你也可以使用引用 `$name*` 来获取整个数组，而不包含周围的括号：

```c
% echo The planets are: $planets[*]

The planets are: Mercury Venus Earth
```

你可以使用符号 `$name[m-n]` 来引用特定范围的元素，其中 $m$ 和 $n$ 是你想要获取的元素的起始和结束索引数字。例如，以下列表仅列出了类地行星：

```c
% set planets=Venus Mars Jupiter Saturn Uranus Neptune Pluto

% echo The terra-form planets are: $planets[2-4]

The terraform planets are: Venus Earth Mars
```

特殊形式 `$name[-n]` 指的是数组中的元素，从第一个开始一直到第 n 个：

```c
% echo The inner planets are: $planets[-4]

The inner planets are: Mercury Venus Earth Mars
```

特殊形式 `$name[n-]` 指的是数组中的元素，从 $n$ 开始一直到最后一个：

```c
% echo The outer planets are: $planets[5-]
```

使用数组变量的主要原因之一是循环遍历数组，逐行检查并处理每个元素。这种编程技术经常用于 shell 脚本中，可以通过以下关键字来实现该目标：

```c
% set files=(main math database)

% foreach file ($files)

? cp $file.cc $file.bak

? end
```

此示例将一组文件的名称赋值给数组，然后使用 `foreach` 语句逐一处理每个文件，将文件复制到备份文件并在过程中更改其文件名。在前面的示例中，问号 (?) 是 shell 在需要额外的行来完成一个未完成的语句时的提示符；它表示你已经完成了该命令。

数组可以作为一种更高效的方法来解析命令的输出。使用 `cut` 或 `awk` 需要额外的进程，并且会让脚本变得更难读。如果需要不同的字段，可以避免多次调用 `cut` 和 `awk`，从而提供更高的效率。假设你需要在 shell 脚本中重复月份和年份。下面是一个展示如何使用 `cut` 和 `awk` 完成此操作的代码片段。（同时使用 `cut` 和 `awk` 只是为了说明目的。通常只使用 `cut` 或 `awk` 之一。）

```c
set month=`date` | cut -f2 -d ""

set year=`date` | awk '{print $6}'
```

此代码片段需要调用两次 `date` 并解析两次输出：一次用于 `awk`，一次 `cut`。这意味着运行了四个进程来提取所需的日期信息。你可以通过一些 `awk` 技巧将进程数减少到两个：

```c
eval `date` | awk '{print month=" $2","year=" $6}'
```

虽然一行代码完成该命令很优雅，但它的可读性不高，因此不利于维护。使用 C shell 解析输出可以通过使用一个进程（即 `date` 程序）来提高效率。使用数组也增加了可读性：

```c
set current_date=`date`

set month=$current_date[2] year=$current_date[6]
```

数组解析与 `awk` 的默认解析类似，`awk` 将每个空白字符视为字段分隔符。解析字段之间存在不量空白的输出（例如来自 `ls` 的输出）不是 `cut` 的良好选择，但它是 `awk` 或 C shell 数组的良好选择。如果需要非空白分隔符，或者解析是管道的一部分，则必须使用 `awk` 或 `cut`。

> 编程时遵循的一个良好规则是“一次且仅一次”（Once and Only Once）规则。该规则规定作为命令和值的脚本元素在任何给定脚本中最多出现一次。变量和别名（aliases）提供了一种强大且方便的方式来实现“唯一性”的目标。考虑这段片段：

```c
echo Jim and I, the twins ~ /tmp/foo.$

ls ~ /tmp/foo.$
```

在这里，文件名 `/tmp/foo.$` 出现了两次。如果需要更改该文件名，必须修改多个处。如果文件名存储在变量中：

```c
set filename=/tmp/foo.$
```

只需要更新一个地方。为文件名使用变量有助于防止错误。如果你不小心忘记输入点 (.) 和文件名 `/tmp/foo.$`，就会创建一个额外的临时文件。如果变量名拼写错误，shell 会报告错误。“一次且仅一次”规则的扩展是，命令行参数通过 `$n` 或 `argv[n]` 语法最多应被引用一次。为命令行参数创建一个新变量最多被查看多次。

```c
if (-e $1 && -d $2) then

  mv $1 $2

  echo $1 moved to $2

endif
```

这段代码之所以难以阅读是因为 $1 几乎没有语义意义——如果参数使用发生变化（引入了新参数、删除了参数或重新排序了参数），也很难以维护。通过直接引用一次命令行参数来转换脚本：

```c
## 为了简洁起见省略了参数检查

set srcFile="$1" targetDir="$2"

if (-e $srcFile && -d $targetDir) then

  mv $srcFile $targetDir

  echo $srcFile moved to $targetDir

endif
```
