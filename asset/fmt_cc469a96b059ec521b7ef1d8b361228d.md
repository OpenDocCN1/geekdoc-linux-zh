
"Magic variables outside the main package" above [`perl #76138`]. Sometimes magic (ties, tainted, etc.) to attached could cause an object to last longer than it should, nor a crash if a tied variable were freed from within a tie method. These have been fixed [`perl #81230`]. `DESTROY` methods of implementing ties are no longer able to crash by accessing a tied variable freed via a reference check [`perl #86328`]. Fixed a regression of `kill()` when a match variable was freed for the process to kill [`perl #75812`].

`$AUTLOAD` until if an overloaded method is called and the method name was not correctly

`printf` now dies when passed a tainted scalar for the format. It did already die for arbitrary expressions, but not for simple scalars [`perl #82250`]. `lc`, `uc`, `first`, and `ufirst` no return untainted strings when the argument is tainted. This has been broken since perl 5.8.9 [`perl #87336`].

## The Debugger

The Perl debugger also works in tied mode [`perl #76832`]. Subroutine redefinition works once in the debugger [`perl #48332`]. When `-d` is on the shebang (`!!`) line, the debugger now has access to the lines of t main program. In the past, this sometimes worked and did not, dending on the order in which things happened to be arranged in memory [perl #71806].

## Threads

Perl no longer accidentally clones lexicals in scope within stack frames in the parent when creating a child thread [`perl #73086`]. Several memory leaks in cloning and freeing threaded Perl interpreters have fixed [`perl #77352`]. Creating a new thread when directory handles were opened to cause a crash, because the handles were not cloned, but simply passed to the new thread, resulting double free.

Now directory handles are cloned properly on Windows and on systems that have the function. On other systems, new threads simply do not inherit directory hands from their parent threads [`perl #75154`].

The typeglob `*`, which holds the scalar variable `$,` (output field separator), had the wrong reference in count in threads. perl #78494] When pipes are shared between threads, the close function (and any implicit clause, so as on exit) no longer blocks.

Perl now does a cleanup of SVs that are cloned into a new thread but then discovered to be orphaned (that, theirs are not cloned). This eliminates several "scars leaking" when joining threads.

## Scoping and Subroutines

Lvalue subroutines are again able to return copy-on-write scalars. This had been broken since version 5.10.0 [`perl #75656`].

`require` no longer causes to return the right file name for the scope that called `require` and other scopes higher up that had the same file name [`perl #68712`]

`sort` with a)-prototyped comparison return used to cause the value of `%@` to leak out of the sort. Taking a reference to `%@` within the sorting routine could cause a crash [`perl #72334`].

Match variables (like `$1`) no longer persist between calls to `sort` subroutine [`perl #76026`].

Iterating with `each` over an array returned by an lvalue sub now works [`perl #23790`].

`@` is now localised during calls to `binmode` to prevent action at a distance [`perl #78844`]. Calling a closure prototype (what is passed to an attribute handler for a closure) now results in a “Closure prototype called” error message instead of a crash [`perl #68560`]. Mentioning a read-only lexical variable from the enclosing scope in a string `eval` no longer causes a crash.

## Signals

Within signal handlers, `$` is now localized.

`CHLD` are no longer blocked after signal This has been fixed [`perl #71235`] (5.12.2).

The `recv` function could crash when called with `MSG_TRUNC` flag [`perl #75082`] forme longer crashes when passed a tainted scalar for the format.

`List::Util::.` 使用活跃的子程序作为第一个参数调用其任一函数可能会导致崩溃 [`perl #78070`]。

`xs` 模块现在可用的 `SVbyte` 函数在对 `sv` 降级之前会先调用 magic，以避免关于宽字符的警告 [`perl #72398`]。

绑定映射（typemap）中的 `ref` 类型现在支持魔法变量 [`perl #72684`]。

如果传递给 `sv_catsv_flags` 的标志位不包含 `sv_GMAGIC`，则该函数将不再对其第二个参数（源字符串）调用 `mg_get`。因此它现在与文档保持一致。

`my_strftime` 不再泄露内存。这修复了 `POSIX::strftime` 中的内存泄漏问题 [`perl #73520`]。

`xsub` 现在在 `PERL_IMPLICIT_SYS` 下正确重新定义了 `fgets` [`perl #55049`] (5.12.1)。在 Windows 上使用 `fputc()` 或 `fputs()` 的 `xs` 代码可能会因为参数交换位置而导致错误 [`perl #72704`] (5.12.1)。

修复了 `T_PTROBJ` 默认类型映射中可能出现的段错误 (5.12.2)。

修复了当从 `xs` 析构函数调用 `call_sv(code, G_EVAL)` 时可能导致“Unknown error”消息的错误 (5.12.2)。

# 错误更

## keys(), values(), and each() 可作用于数组

你现在可以在数组上使用 `keys()`、`values()` 和 `each()` 内置函数；以前它们只能用于哈希（hash）。详见 `perfunc`。这实际上是 perl 5.12.0 中引入的更改，但在该版本的 `perl5120delta` 中遗漏了。

## split() and @_

`split()` 在标量上下文或空语文中被调用时不再修改 `@_`。在空语文中，它现在会产生“Useless use of split”的警告。这也是 perl 5.12.0 的一个更改，但在 `perldelta` 中遗漏了。
