经纪事务应用程序可能处理订单（OLTP）并提供研究信息（DSS）。

这三种分类为理解如何设计和配置数据库提供了基础知识。

Oracle 数据库与 Oracle 实例（instance）之间存在着重要的区别。

数据库由数据库名称（`DB_NAME`）识别，由用于存储的物理文件组成。实例则由系统标识符（`SID`）识别，由用于满足用户请求的内存结构和进程组成。当 Oracle 服务器关闭时，实例将不再存在。它们被区分的主要原因是单个数据库可以由多个实例服务。

数据库和实例由许多组件组成。内存结构包括系统全局区域（SGA）、共享池（shared pool）、数据库缓冲区（database buffer cache）、重做日志缓冲区（redo log buffer）和程序全局区域（PGA）。逻辑结构包括表空间（tablespaces）、模式（schemas）、段（segments）、扩展区（extents）、回滚段（rollback segments）、表和索引。物理组件包括数据文件（data files）、控制文件（control files）、重做日志（redo logs）和参数文件（parameter files）。

## 系统全局区域

Oracle 实例的内存结构包含在一个称为系统全局区域（System Global Area, SGA）的内存区域中。SGA 分配在 Oracle 服务器进程居住的虚拟内存中。SGA 包含多个内存结构，包括共享池、数据库缓冲区和重做日志缓冲区。许多进程共享 SGA。

## 共享池

共享池包含两个组件：库缓存（library cache）和数据字典缓存（data dictionary cache）。库缓存存储了最近使用的 SQL 语句及其执行计划。数据字典缓存存储了最近使用的数据字典信息，例如表定义、用户名和权限。共享池的大小可能会会影响数据库的性能，特别是在 OLTP 环境下。

## 数据库缓冲区

当用户提交 SQL 查询时，服务器进程会在数据库缓冲区中查找数据块以满足请求。如果在数据库缓冲区中未找到这些数据块，服务器进程将必须从物理设备读取这些数据块，并将数据的副本放置在缓冲区中。后续对相同数据块的请求很可能在内存中找到，而可能不需要物理读取。

## 重做日志缓冲区

对数据的所有更改都存储在重做日志缓冲区中，稍后会被复制到物理重做日志文件中。

## 程序全局区域

程序全局区域（PGA）是一个包含单个服务器进程数据的内存区域。在专用服务器配置中使用，PGA 包含排序区域、会话信息、游标状态和栈空间。PGA 在进程启动时为进程分配，并在进程终止时释放。

## 表空间

表空间被划分为称为表空间的逻辑存储单元。表空间用于将相关的逻辑结构组合在一起，并可以用一个或多个物理文件表示。在表空间内对某些类型的对象分组是常见做法。示例可能临时表、回滚段或数据字典表。

## 数据文件

每个表空间可以有一个或多个数据文件，即存储在文件系统上的实际物理文件。

## 扩展区

扩展区是 Oracle 数据库中最小的存储单元。扩展区由一个文件系统块组成。例如，Linux ext2 文件系统通常每个块 2048 字节，但可以设置为每块 1024、2048 或 4096 字节。根据数据库的使用方式，可以将扩展区配置为一个或多个 ext2 块。

## 段

段是对象的物理表示，由一个或多个扩展区组成。单个表就是段的一个示例。

## 控制文件

当数据库启动时，它会引用一个名为控制文件的二进制文件来查找数据文件和在线重做日志的位置。控制文件在数据库运行时持续更新，并且在数据库挂载（mounted）或打开时必须可用。如果数据库使用的任何控制文件变得不可用，则数据库将无法正常运行。

## 重做日志

重做日志存储了数据库缓冲区中的所有更改（少数除外）。它们用于最大限度地减少数据丢失，并用于数据恢复。

## 配置文件系统

挂挂载点是首要考虑的问题。在设计和构建服务器时，确定磁盘使用情况通常更容易。生产系统至少应有六块驱动器；开发系统至少需要四块。如有必要，可以随时添加硬盘。最大的关注点是数据安全。数据文件和重做日志（redo logs）存储在不同的设备上。如果包含数据的驱动器之一丢失，可以使用重做日志来恢复数据。通常，多个小容量驱动器比少数大容量驱动器更受青睐。如果让我在 6GB 硬盘和 9GB 硬盘之间进行选择，我可能会选择六块硬盘的方案。较多的驱动器可以提高性能并增强数据保护。另一个需要考虑的重要问题是不同应用程序之间的竞争。一个 9GB 的硬盘如果分为两个 4.5GB 分区并在两个不同的应用程序之间共享，将很难进行调优。可能的情况下，为 Oracle 专用的驱动器。

Oracle 建议使用类似于最优灵活架构（Optimal Flexible Architecture，简称 OFA）。OFA 是一种特定的文件系统布局方法，要求在目录结构的同一层级至少四个挂载点。如果你在同一台服务器上运行多个数据库实例，这种方法特别有用。Oracle 文档经常引用 OFA 布局，因此如果你在使用它，将会很有帮助。

### 单块硬盘

你可以在单个硬盘上安装 Oracle，只要你不担心性能低和可能出现的数据丢失。我即将描述的这种布局可能看起来很奇怪，而且没有必要，但它能让你养成跨分区存储数据的习惯，而并不是跨物理驱动器存储。请注意，这不建议在生产环境中使用，你可能会丢失数据，并且性能会更低。

使用 `df -k` 命令在系统上找到一个至少有 600MB 空闲空间的分区。假设 `/usr/` 分区有 `1GB` 可用磁盘空间。在 `/usr/local` 下创建一个名为 `oracle` 的目录，然后在 `oracle` 下创建四个名为 `u01`、`u02`、`u03` 和 `u04` 的目录。

```
mkdir /usr/local/oracle
mkdir /usr/local/oracle/u01
mkdir /usr/local/oracle/u02
mkdir /usr/local/oracle/u03
mkdir /usr/local/oracle/u04
```

本章其余的示例将假设挂载点位于根文件系统下。在根系统创建符号链接。

```
ln -s /usr/local/oracle/u01 /u01
ln -s /usr/local/oracle/u02 /u02
ln -s /usr/local/oracle/u03 /u03
ln -s /usr/local/oracle/u04 /u04
```

### 四块硬盘

四块硬盘配置相比单块硬盘配置提供了显著的数据保护和适度的性能提升。在每个物理设备上创建一个分区来存储 Oracle 数据。为每个 Oracle 目录分配一个分区，即 `/u01`、`/u02`、`/u03` 和 `/u04`。如果你已经安装了 Linux 并想为系统添加三块硬盘用于 Oracle，请使用 Druid 或 `fdisk` 对磁盘进行分区，并使用 `mkfs` 格式化每个分区。在根文件系统创建 `/u01`、`/u02`、`/u03` 和 `/u04` 目录，并使用 `mount` 命令将分区挂载到文件系统。
