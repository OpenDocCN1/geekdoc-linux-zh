# 第 11 章 测试、调试、性能分析与调优

## 调优策略

以下章节概述了几种优化策略，在作者看来，这些策略在 Python 代码中被证明是有用的。

### 理解你的程序

在优化任何内容之前，要明确优化程序某部分所获得的加速，与该部分对执行时间的总贡献直接相关。例如，如果你通过使其运行速度快 10 倍来优化它，但该函数仅占程序总执行时间的 10%，那么你获得的整体速度提升仅为 9%–10% 左右。取决于为了优化所付出的精力，这可能值得也不值得。

对打算优化的代码使用 `profiling` 模块总是个好主意。只关注程序花费大部分时间的函数和方法，而不是偶尔被调用的晦涩操作。

### 理解算法

一个实现糟糕的 O(n log n) 算法也会优于经过最调优的 O(n³) 算法。不要优化低效的算法——先寻找更好的算法。

### 使用内置类型

Python 内置的 `tuple`、`list`、`set` 和 `dict` 类型完全是用 C 实现的，是解释器中调优最精细的数据结构。你应该积极使用这些类型来存储和处理程序中的数据，并抵制构建模拟其功能的自定义数据结构的冲动（即二叉搜索树、链表等）。

尽管如此，你仍然应该更仔细地查看标准库中的类型。某些库模块提供了新类型，在某些任务中的性能优于内置类型。例如，`deque` 类型提供了与 `list` 类似的功能，但对在两端插入元素进行了高度优化。如果你在开头插入元素，所有其他元素都需要移动以腾出空间。完成此操作所需的时间随着列表的增长而增加。为了了解差异，这里是对一百万元素到 `list` 和 `deque` 的测量结果：

```
>>> from time import timeit

>>> timeit('s.appendleft(37)', 'import collections; s = collections.deque()', number=1000000)

0.24433023765723

>>> timeit('s.insert(0, 37)', 's = []', number=1000000)

2.951995143564
```

### 添加层级

每当你为对象或函数添加额外的抽象或便利层级时，它都会减慢你的程序。然而，可用性和性能之间也存在权衡。例如，添加额外层面的目的通常是为了简化代码编写，这也是件好事。

## 调优与优化

为了用一个简单的例子说明，考虑一个使用 `dict()` 创建带有字符串键的字典的程序：

```
s = dict(name='GOOG', shares=100, price=490)
```

### 了解基于字典的类和实例

程序员可能会以这种方式创建字典以节省打字时间（尽管不需要给 name 加引号）。然而，这种创建字典的替代方法运行得更慢。

```
>>> dict(s=dict(name='GOOG', shares=100, price=490))

2.951995143564

>>> dict(name='GOOG', shares=100, price=490)

0.24433023765723
```

然而，处理错误的另一种方法是简单让程序生成异常并将其捕获。例如：

```python
def parse_header(line):
    fields = line.split(":")
    try:
        header, value = fields
        return header.lower(), value.strip()
    except ValueError:
        raise RuntimeError("Malformed header")
```

如果你在格式正确的行上对这两个版本进行基准测试，第二个版本的代码运行速度会快 10%。对于通常不会抛出异常的代码设置 `try` 块，其执行速度比执行语句更快。

### 在常见情况下避免使用异常

不要为常见情况编写异常处理代码。例如，假设你有一个程序执行了大量的字典查找，但大多数查找都是针对不存在的键。现在，考虑执行查找两种方法：

```python
# 方法 1：执行查找并捕获每个异常
try:
    value = items[key]
except KeyError:
    value = None
```

```python
# 方法 2：检查键是否存在并执行查找
if key in items:
    value = items[key]
else:
    value = None
```

在未找到键的简单性能测量中，第二种方法的运行速度几乎快 17 倍！如果你好奇，这种方法的运行速度也比使用 `items.get(key)` 快倍，因为操作符的执行速度比方法调用快。

### 拥抱函数式编程和迭代

列表推导式、生成器表达式、协程和闭包比大多数 Python 程序员意识到的要高效得多。对于数据处理，列表推导式和生成器表达式的运行速度比手动遍历数据并执行相似操作的代码快得多。这些操作的运行速度也比使用 `map()` 和 `filter()` 函数的老旧代码。生成器可以用于编写不仅运行快而且能高效利用内存的代码。

### 使用装饰器和元类

装饰器和元类是用于修改函数和类的特性。然而，由于它们在函数或类定义时运行，因此可以以提高性能的方式使用——特别是当程序有许多可以开启或关闭的可选功能时。第 6 章“函数与函数式编程”包含一个使用装饰器启用函数日志的示例，但这种方法在禁用日志时不会影响性能。
