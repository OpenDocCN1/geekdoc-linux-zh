
你也可以合并程序的不同版本。例如，要将从 1.1 的更改引入 1.3，你可以使用 `rcsmerge` 命令，但首先你必须以锁定状态检出 `foo.c`：

```
# co -r1.1 foo.c
RCS/foo.c,v --> foo.c
revision 1.1
done
# rcsmerge -p -r1.1 -r1.3 foo.c >foo.merged.c
RCS file: RCS/foo.c,v
retrieving revision 1.1
retrieving revision 1.3
Merging differences between 1.1 and 1.3 into foo.c; result to stdout
```

注意 `rcsmerge` 的输出必须重定向到文件。要移除特定版本，请使用：

```
# co -l -r1.2 foo.c
RCS/foo.c,v --> foo.c
revision 1.2 (locked)
done
```

RCS 流行的另一个原因是它的高效性。如果你查看一个已入库的 `foo.c,v` 文件，你会看到以下内容：

```

access;
symbols;
locks; strict;
comment @ * @;
1.3
date 97.08.02.20.29.10; author root; state Exp;
branches;
next 1.2;
1.2
date 97.08.02.19.53.13; author root; state Exp;
branches;
next 1.1;
1.1
date 97.08.02.18.49.08; author root; state Exp;
branches;
next ;
desc
@a simple example
@
1.3
log
@added another printf line
@
text

#include <stdio.h>

printf("hello, world!\n");
}
@
1.2

@

```

如你所见，RCS 将每个版本的更改记录为 `foo.c,v` 文件中的 `diff` 命令。因此，你可以通过使用 `co -r*X.X*` 命令在任何时间成功地检索每个版本，其中 `*X.X*` 是你想要的版本。此外，由于更改是 `diff` 格式，原始文档的许多更改可以相当高效地存储。

有时你必须创建一个文件的“分支”版本，仅仅是为了在版本的中间进行临时的或专门的修复。在这种情况下，你使用 `co` 命令的 `-r*X.X*` 选项来创建一个分支。

例如，为了对 `foo 1.2` 进行特殊发布，你使用以下命令：

```
# co -l -r1.2 foo.c
RCS/foo.c,v --> foo.c
revision 1.2 (locked)
done
```

在进行更改并把 `foo.c` 回库时，`ci` 命令会将版本提升到 1.2.1.1 并响应如下内容：

```
# ci foo.c
RCS/foo.c,v <-- foo.c
new revision: 1.2.1.1; previous revision: 1.2
enter log message, terminated with single \ or end of file:
>> a temporary fix
>> .
done
```
