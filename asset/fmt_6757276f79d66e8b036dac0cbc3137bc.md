## ksrvtgt — 使用服务密钥获取并存储 Kerberos 票据

### 概要

`/usr/bin/ksrvtgt` `name` `instance` [[`realm`] `srvtab`]

## 描述

`ksrvtgt` 命令是 Secure RPC 命令集的一部分。`ksrvtgt` 执行以下操作：

- 为主体名称 `name.instance@realm`（如果未在命令行上提供 `realm`，则为 `name.instance@localrealm`）检索一个有效期为五分钟的 Kerberos 票据票据。
- 使用 `srvtab` 文件中找到的服务密钥（如果未在命令行上指定 `srvtab`，则使用 `/etc/srvtab`）解密响应。
- 将票据存储在标准票据缓存中。

> 注意 — 此命令主要用于 shell 脚本和其他批处理设施。

## 诊断

通用的 kerberos 失败 (`kfailure`) 可能表示一系列问题，其中最常见的是无法读取服务密钥。

## 文件

`/etc/krb.conf`
获取本地 realm 名称。
`/tmp/tktuid`
默认票据文件。
`/etc/srvtab`
默认的服务密钥文件。

## last — 显示登录和注销信息

### 概要

### 描述

使用 `last` 命令显示用户和终端的登录和注销信息。`last` 命令查看 `/var/adm/wtmpx` 文件，该文件记录了所有的登录和注销。你可以使用参数来指定感兴趣的用户或终端名称。如果你指定了多个参数，则打印适用于这些参数的信息。例如，`last root console` 会列出 `root` 的所有会话以及控制台终端上的所有会话。`last` 显示指定用户和终端的会话，按时间顺序优先，指示会话开始的时间、持续时间以及发生会话的终端。`last` 还指示会话是在进行还是由于重启被中断。

伪用户 `reboot` 在系统重启时登录。因此，以下示例显示了重启之间的平均时间。

```
castle# last reboot

reboot system boot Thu Mar 4 11:10

reboot system boot Thu Mar 4 07:35

reboot system boot Wed Mar 3 18:40

wtmp 开始于 Wed Mar 3 18:40
castle%$
```

不带参数的 `last` 以反向顺序显示所有登录和注销记录，如下例所示。

```
castle$ last

winsor      console         :0    Thu Mar  4 11:13  still logged in

reboot      system boot               Thu Mar  4 11:13

winsor      console         :0    Thu Mar  4 07:38 - 08:46 (01:07)

reboot      system boot               Wed Mar  4 07:35

root        console         :0    Wed Mar  3 19:55 - 19:55 (00:00)

winsor      console         :0    Wed Mar  3 19:52 - 19:54 (00:02)

winsor      console         :0    Wed Mar  3 19:51 - 19:51 (00:00)

root        console         :0    Wed Mar  3 19:55 - 19:55 (00:00)

winsor      console         :0    Thu Mar  4 11:13  still logged in

castle$ 
```

`wtmp` 开始于 Wed Mar  3 18:40

`castle%$`
