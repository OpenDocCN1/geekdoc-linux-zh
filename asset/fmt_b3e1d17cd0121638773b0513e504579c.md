
在这个示例中需要理解的重要点是所有镜像都受到了密码保护。然而，`linux-new`镜像始终需要密码，而如果提供了额外的参数，`default`镜像也将需要密码。由于第一个镜像被标记为`restricted`，如果在LILO启动提示处没有提供额外输入，它将在10秒（100毫秒）后自动启动。默认镜像和提示延迟分别由`default=`和`timeout=`关键字提供。这种场景在防止未经授权传递内核参数的同时，允许自动重启。

## prompt 和 timeout 关键字

在讨论LILO启动器时，还需要解决最后一个安全问题。`prompt`和`timeout`关键字让系统管理员能够决定意外掉电时系统会发生什么。这很重要，因为在某些情况下，意外重启的系统立即上线是不希望的。系统管理员可能希望在意外重启的系统上线之前有机会亲自检查，以防重启是因为入侵且系统部分已遭破坏。

另一方面，如果你运行一个尽可能供用户使用的服务器，你可能愿意承担这种风险，并希望所有意外掉电后自动回到Linux。有三种基本方法：

- 如果既没有`prompt`也没有`timeout`，系统将在启动期间自动加载默认镜像，而不会显示LILO启动提示或等待用户输入。
- 如果有`prompt`但没有`timeout`，则启动的系统将停在LILO启动提示处，直到发生人工干预。
- 如果`prompt`和`timeout`都存在，则启动的系统将停在LILO启动提示处，持续时间为`timeout`参数设置的毫秒数。例如，`timeout`值`3600`是360秒，即六分钟。一旦时间耗尽，如果没有人工干预，LILO将加载默认镜像并按正常方式启动。

你使用`prompt`和`timeout`的策略取决于机器的用途以及你对重启的怀疑程度。你必须根据情况运用自己的判断来做出决策。

如果在你的情况下意外重启几乎是不可能的（例如，你有一个稳健的系统和高质量的备电源），你可能希望对意外重启采取非常谨慎的策略。在意外重启如此罕见的情况下，此类事件有极大可能代表某种恶意行为。当然，任何能够完全破坏系统并能够重启它的黑客都可能再次编辑`/etc/lilo.conf`文件并移除此类保护措施。尽管如此，在安全方面保持保守通常是有利的。

## 保存更改

在你的`/etc/lilo.conf`文件的更改生效之前，你必须重写系统的引导扇。要执行这一点，只需调用`lilo`命令：

```
/sbin/lilo
```

你将看到对应`lilo.conf`文件中配置的镜像的标签列表。下次启动系统时，每个标签都将是LILO启动提示处的的可启动标签。

## `/etc/lilo.conf` 的权限

对于`/etc/lilo.conf`文件，你想要采取的最后一步是防止非root用户读取它，特别是如果你已经为一个或多个镜像配置了启动密码的话。要做到这一点，请执行以下命令：

```
chmod 600 /etc/lilo.conf
```

此命令设置了文件权限，使得只有root能够读取或写入`/etc/lilo.conf`文件。有关文件系统权限的详细信息，请参见第7小，“文件系统安全”。

## init 程序与 `/etc/inittab`

本节我们将处理的启动过程的最后一个方面是init进程的配置文件。你可能记得init是在内核启动后负责接管系统的进程；它会启动服务、提供登录提示，并执行非常基本的Unix类型服务。

`/etc/inittab`文件本身的格式超出了本节的讨论范围，但这里有两个具有安全意识的用户可能想要考虑的简单更改，以使init默认设置变得稍微脆弱。

### 默认运行级别 Runlevel

init进程使用一系列称为运行级别（runlevels）的抽象，来帮助确定在特定时间特定系统上应该运行哪些服务。Linux发行版使用运行级别类似的角色；最常见的运行级别定义如表4.1所示。注意，Debian GNU/Linux使用一套不同的运行级别，在`/etc/inittab`中有简要说明。

#### 表 4.1 常见运行级别定义

| 运行级别 | 说明 |
| --- | --- |
| 0 | (程序性) 系统停止：当系统进入运行级别0时，所有进程都将停止。 |
| 1 | 单用户或维护：网络接口启动，但不启动任何服务；仅允许root登录且仅限控制台。当在LILO启动提示时将单单词作为参数传递给内核时进入的运行级别。 |
| 2 | 多用户，最小化：网络接口启动，允许启动某些本地服务供控制台用户登录，但大多数网络服务（例如NFS和Web）不会启动。 |
| 3 | 多用户，全功能：启动网络接口和所需的网络服务。允许本地和远程用户登录和请求。 |
| 4 | 未使用或用户指定。 |
| 5 | X11：启动网络接口和所需的网络服务。允许本地和远程用户登录和请求。启动X显示管理器或其替代品，系统引导到X11R6。 |
| 6 | (程序性) 重启：当系统进入运行级别6时，所有进程都将停止，并将发生冷重置。 |

在第1小节，“选择和安装Linux发行版”中，你了解到许多仅提供网络服务的系统不需要X能力，因此不需要安装X。然而，在某些情况下，X会被安装，但很少会被实际运行。

在这些情况下，许多当前的发行版会将默认运行级别设置为5，即X11模式，尽管在你的机器上X窗口系统不会被使用。这是一件坏事；在第15小节“保护X11R6访问”中，你将了解到X实际上像其他任何网络流一样，因此容易受到攻击。正因如此，你不希望X在网络服务器上默认运行但在大多数时间内什么都不做。

因此，在符合此描述的机器上，你可能希望使用你喜欢的编辑器编辑`/etc/inittab`文件，并更改文件中的第一行非注释行。通常，它看起来是这样：

```
id:5:initdefault
```

这一行告诉init程序使用运行级别5启动系统并启动所有服务（包括X）。由于在大多数情况下X窗口系统不会在你的机器上使用，你并不希望X默认运行。

因此，在符合此描述的机器上，你可能希望使用你喜欢的编辑器编辑`/etc/inittab`文件，并更改文件中的第一行非注释行。通常，它看起来是这样：

```
id:3:initdefault
```

这一行告诉init程序使用运行级别3启动系统并启动所有服务（允许本地和远程登录和请求）。完成此更改后，系统将以运行级别3启动，而不是X11R6。

## 总结

本节，你学习了通过以下方式保护启动过程：

- 在`/etc/lilo.conf`中使用关键字来保护镜像。
- 在`/etc/lilo.conf`中使用参数在没有提供时启动。
- 在`/etc/inittab`文件中修改以反映你的策略。
- 在`/etc/inittab`文件中修改以不需要X。

在采取了这些步骤后，你已经完成了“Linux之前”的安全工作，并准备进入核心内容了。

## 问答

Q 我似乎无法编辑`/etc/lilo.conf`或`/etc/inittab`。每当我尝试这样做时，都会收到权限不足的消息。

A 现在Linux已安装并运行，你必须以root用户身份操作这些文件并执行我们要做的其他任务。注销并以root用户身份登录。

Q `/sbin/lilo`命令失败了。我该怎么办？

A 仔细检查`/etc/lilo.conf`文件的语法和拼写错误。必要时查阅`lilo.conf(5)`手页。在运行命令时，使用`-v`参数获取更多诊断输出。如果还是失败，请撤销你所做的更改并重新开始。

Q 运行级别似乎与你描述的不符。X仍然会自动启动。我该怎么办？

A 首先，回到`/etc/inittab`文件并查找引用X显示管理器或启动X11R的注释。如果你发现了，请将其作为指南，结合`inittab(5)`手页帮助你做出必要的更改。某些发行版在`/etc/rc.d`或`/etc/init`层次中作为服务启动X。我们下一节介绍这些目录。你可能还会发现Linux发行版的原生管理工具提供了禁用X显示器的选项。

## 新术语

`default runlevel` 当没有作为参数传递给init进程时，系统启动的运行级别。

`global` `/etc/lilo.conf`顶部仅提供一次的关键字，影响后面列出的所有镜像。

`image` `/etc/lilo.conf`文件中引用可启动操作系统的条目。镜像规范以`image=`或`other=`关键字开始，取决于LILO如何处理操作系统，可以包含任意数量的关键。

`init` 在内核运行时负责启动服务的程序，从控制台登录提示等基本服务到X、Web服务器等高级服务。
