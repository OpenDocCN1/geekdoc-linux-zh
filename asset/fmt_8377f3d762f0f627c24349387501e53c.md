
例如，在 C 中，如果你有一个之前输入的命令，可以通过回想（如果你使用 `vi` 模式则按 `Esc`）并对想要修改的部分进行选项操作来编辑它。在 C shell 中，你也可以恢复之前的命令，但指定命令有五种不同的形式（`!`、`!!`、`!-5`、`!vi` 或 `!vi?`），指定命令参数的其他形式（`:0`；`;3-5`；`-4-`），以及修改所选参数的额外形式（`h`；`s/old/` 等）。即使记住命令替换系统都很困难，更不用提使用。C shell 的替换机制还提供了通过 `foreach` 访问多行命令。无法访问多行命令可能会令人沮丧；然而，通过许多模式进行编辑，由于所需的按键较少，良好的命令行编辑器是不可替代的。`TC`、`Bourne Again` 和 `Z shell` 支持所有 C shell 历史替换并提供命令行编辑。

另一方面，如果你喜欢使用通配符，你会发现 C shell 的扩展更容易使用——它们比 Korn shell 扩展所需的语法更少、更简单。除了通配符外，`csh` 还提供了单键补全 `push`、`pop` 和 `dir` 命令。此外，它的 `cd` 命令补全更灵活。一些 shell 不直接支持这些，例如 Korn 和 POSIX shell（尽管可以通过别名和命令函数来实现）。总的来说，C shell 在键盘快捷键方面评分良好，这可以补偿它那中等成功的命令编辑。取决于你注意力的集中程度，你可能会发现 C shell 非常高效。我们发现，那些已经熟悉 C shell 的人并没有被 Korn 和其他 shell 赶走。

从可移植性考虑，C 排名最后，因为它是一种独特的语言。如果你只认识 C shell，而你正在使用的系统没有它，那么你就倒霉了。在与 Bourne shell 工作时，C shell 总是感觉很奇怪，而后者是双语的，了解两者的变幻。

C shell 在先验经验方面评分为 2 分。如果你已经认识 C shell，那么 C shell 是切换的良好选择。C shell 提供了命令行编辑器和许多与你当前 C shell 兼容的丰富快捷键。另一方面，留在 C 变体可能会限制，因为 Bourne 家族中有更多的 shell，除非你想修复某些命令，否则你可能会发现另一个 shell 的命令编辑能力值得花时间和精力进行切换。任何习惯 C shell 命令编辑能力的人都会感到被不公平地剥夺了它——这是一项功能。如果你还没有尝试过 Korn、`TC`、`Bourne Again` 或 `Z shell`，你现在有一个机会，我强烈建议花一点少的时间熟悉其中一个 shell，以做出明智的选择。你可能会感到惊讶并选择一个不同的 shell。

总的来说，C shell 是一个值得赞誉的环境，与其前身 Bourne shell 相比有很多优势。个人偏好在你的选择中起了作用。然而，如果你是 UNIX 新手，C shell 可能不是你开始的地方。

C shell 应该由你的 UNIX 供应商作为默认 shell 集合提供。

## Korn Shell (Korn Shell)

在精通它所需的时间精力方面，Korn shell 处于 shell 谱的中间。这并不是因为它的设计糟糕或文档记录糟糕，仅仅因为它拥有比 Bourne 和 C shell 更复杂的功能。当然，在你开始使用 Korn shell 之前不需要学习所有内容。

Korn shell 的命令界面允许快速、轻松地回想输入错误，以及轻松的回想和重用历史。多行命令的使用有点笨拙，因为所有行都连接在一起，用控制字符表示新行。

在缺点方面，Korn shell 提供了 C shell 通配符扩展的等价物，但其复杂的语法使其难以记忆和使用。你可以拥有 `pushed`、`popped` 命令界面来实现它们。如果能将变量作为 `cd` 的参数就好了。Korn shell 的命令别名和作业设施与 C shell 几乎相同。

`bash` 的体验评分为 a。如果你使用的 shell 比你当前的 shell 功能更多，那么切换到 `bash` 将非常容易；如果你习惯于 C shell 的变体，这也很可能对你有帮助，因为 Bourne Again (`bash`) 具有足够的 C 语言语法，使得过渡相对不痛苦。为了进一步减轻这种痛苦，Bourne Again 提供了一个实用的脚本，可将你的 C 别名（`aliases`）翻译为 Bourne Again 语法，并进行语义替换（例如用 `$PWD` 替换 `$cwd`）。`bash` FAQ（常见问题解答）中提供了关于如何模拟 C shell 特性的提示，例如 `x :` 替换。

然而，UNIX 供应商通常不将 Bourne Again 作为标准 shell 提供，但许多系统都安装了 `bash`。它是 Linux 用户的标准。本书附带的 CD 中包含一个版本的 `bash`。如果你想查找有关源码和二进制文件位置的其他信息，请查看 `bash` FAQ，地址为：`http://slc2.cwru.edu/pub/bash/FAQ`。如果不这样做，将浪费你搜索 Bourne Again 或 `bash` 的搜索引擎。

## Z Shell

`Z shell` 是重度用户的终极 shell。如果你认为一个 shell 应该具备某种功能，那么 `Z shell` 可能就具备。这种力量是有代价的：例如，在 HP-UX 10.01 上，`zsh` 可执行文件的大小几乎是 `ksh` (Korn) 可执行文件的四倍，几乎是 `sh` (Bourne) shell 三倍。

我不了解 `Z shell` 的所有功能，连原始作者 Paul Falstad 也一样。即使学会一半的功能也将是一项巨大的成就，因此给了 3 分。然而，这并不意味着 `Z shell` 在实现、设计或文档方面是完美的；这完全是功能方面的问题。

在行编辑方面，`Z shell` 表现优于本章中审查的每一个 shell。在我看来，Z 处理多行命令的能力是所有最好的。每个命令本身都是一个编辑器，这使得命令易于编辑且输入易于复用，并且它会返回命令的视觉外观。`Z shell` 拥有最多的补全和扩展。对扩展的访问也最直观。例如，输入变量时第一次按 `Tab` 键会补全变量名，下次按 `Tab` 键会将变量的值扩展到命令行中（假设补全没有歧义）。`Bash` 和 `tsh` 需要单独的编辑器来扩展值（在 `bash` emacs 模式下，使用 `Esc-S` 会扩展变量）。`Z shell` 支持可编程补全，可以进一步帮助命令编辑。例如，你可以使用 `cd` 命令仅对目录进行补全或扩展。`Z shell` 为模式和用户 ID 提供了拼写纠正。这些功能使其在编辑类别中获得了 1 分。

`Z shell` 在快捷键方面获得了 1 分和 1 分。例如，如果你有开发者正在为某个项目处理一组文件，而你想确定哪些文件需要合并。为了实现这一点，你需要 `Z shell` 将共同文件列到一个文件中进行编辑。编辑后的列表包含了合并的候选文件。使用像 C shell 这样的 shell 会导致最糟糕。你可以使用 `foreach` 循环配合 `if -filename` 来保存每个临时文件并显示文件名，但 C shell 不允许从命令进行重定向。创建一个临时脚本是很痛苦的，但比 UNIX 命令（选择或列出共同文件到两个 shell）要简单。以下是一个 C shell 会话，使用 `vi` 进行注释。

```bash
# (cd ~harman/cxxsource/proj;ls *. (cc,hh)) > /tmp/davesFiles
# 该死的，需要一个临时文件
# (cd ~robic/dominic/proj;ls *. (cc,hh)) > /tmp/mattersFiles
# 该死的，还需要另一个临时文件
# comm -12 /tmp/davesFiles /tmp/mattersFiles > needMerge
## 显示两个文件中共同的内容
## rm /tmp/davesFiles /tmp/mattersFiles
```

进入 `Z shell` 并使用进程替换语法 `=()`。进程替换消除了临时文件的烦恼，如下 `Z shell` 所示，它完成了上述任务。

```bash
% vi =(comm -l2 =(cd ~harman/cxxsource/proj;ls *. (cc,hh))=(cd ~robic/dominic/proj;ls *.(cc,hh)))
```

进程替换创建一个临时文件，将模板放入临时文件中，然后将临时文件的名称传递给需要处理的命令。

其他巧妙的 Z 快捷键还包括：

- 递归搜索 (`ls **file`)。
- 通过多重重定向进行轻松测试 (`ls >file1 >file2`)。
- `autocd` 允许在不使用 `cd` 的情况下更改目录，因此 `cd` 和 `dirname` 是等效命令。
- 空命令命令简写。`<file` 等同于 `more <file`，`file` 等同于 `>file`，而 `>>` 等同于 `cat >>file`。
- 使用内置命令编辑 Shell 变量。

移植性是 `Z shell` 的阿喀琉斯之踵。`Z shell` 不像大多数 shell 那样出现在许多系统中。为了方便这一点，Z 可以模拟 Korn 或 POSIX shell。对于移植性，3 分足够了。

Z 在体验方面同样出色。无论你熟悉什么，`zsh` 都不太难。即使你是一个 C shell 迷信（我也是），各种 `CSH_JUNK` 选项也可以帮助你直到你完全戒掉。Z 支持任何非 C shell 的 C shell 特性，包括：`^^` 替换、`foreach`/`pushd`。通过 `Z shell` 的模拟开关，Bourne 和 POSIX 用户可以感觉如归家家。

## 个人使用的 Shell 脚本

如果你为个人用途开发任何 shell 脚本，你可能希望使用与交互式命令时相同的 shell 语言来编写它们。与交互式使用一样，用于个人脚本的语言很大程度上取决于个人选择。

无论你在键盘前使用 C 变体还是 Bourne 变体，出于几个原因，你可能想要考虑在 shell 脚本中使用 Bourne 语言。首先，个人 shell 脚本始终是私人的；它们随着时间的推移而演变，并逐渐从一个用户流向另一个用户，直到优秀的脚本成为事实上的标准。正如你在“个人使用的 Shell 脚本”章节中学到的，使用 Bourne 以外的任何语言编写脚本都是带有风险的，因为你限制了可以使用你脚本的环境和用户。

其次，C 变体虽然充满了出的交互式功能，但遗憾的是缺乏编程功能。C 变体的缺点是缺乏 shell 函数（或者可能是 C++ shell 如此）。shell 函数的缺乏本质上结构化了编程。任何函数必须是一个文件或别名（`alias`）。对于复杂的任务，别名可能很难编写或无法编写。C shell 变体没有参数替换，变量和文件测试也少得多。

编写短而简单的 shell 脚本来自动化常见任务是一个良好的习惯，也是良好的 UNIX 技能。为了充分利用 UNIX shell 的优势，你必须培养一些脚本编写能力。如果你使用与键盘输入相同的语言编写个人脚本，这种能力自然形成。
