
大多数处理器一次只能运行一个进程。某些处理器（如超线程处理器）实际上可以同时运行多个任务，Linux 将它们视为多个单线程处理器。为了创建一个进程同时运行多个任务的幻象，Linux 内核在不同进程之间不断切换。进程之间的切换被称为上下文切换（`context switch`），当切换发生时，CPU 保存旧进程的所有上下文信息并检索新进程的所有上下文信息。上下文包含了 Linux 为每个进程跟踪的大量信息，包括指令指针在哪里、分配了哪些内存以及进程打开了哪些文件。这些切换可能涉及大量信息的移动，上下文切换的开销很大。如果可能，最好减少上下文切换次数。

为了避免上下文切换，了解它们是如何发生的至关重要。首先，上下文切换可能源于内核调度。为了保证每个进程获得公平的处理器时间，内核会定期中断，并在每次周期性中断发生时，如果合适，调度器会启动另一个进程而不是当前进程。你的系统可能会根据架构和内核定时器每秒产生中断。检查中断频率的一种方法是使用 `/proc/interrupts` 来确定一段时间内发生的中断次数。这在列表 2.1 中所示。

### 2.2.1. vmstat (虚拟内存统计)

`vmstat` 是 `virtual memory statistics`（虚拟内存统计）的缩写，它将为你提供有关系统虚拟内存系统性能的信息。坦率地说，它的功能远于此。`vmstat` 是获取系统整体性能概要的绝佳命令。它可以告诉你：

- 运行了多少进程
- CPU 如何被使用
- CPU 接收到多少次中断
- 调度器执行了多少次上下文切换

它是获取系统性能概要的优秀工具。

### 3.1. 内存性能统计

系统级 Linux 性能工具提供了不同的方式来提取类似的统计数据。虽然没有工具能显示所有统计数据，但某些工具显示的是相同的。本章开头回顾了这些统计数据的细节，随后这些描述将被引用为所述的工具。

#### 3.1.1. 内存子系统与性能

在现代处理器中，从内存子系统中保存和检索信息通常需要由 CPU 执行代码并操纵这些信息。CPU 通常花费大量的空闲时间，等待从内存中检索指令和数据，然后对其进行执行或操作。处理器具有不同级别的缓存，以补偿缓慢的内存性能。如 `profile` 等工具可以显示各种处理器缓存缺失发生的位置。

#### 3.1.2. 内存子系统（虚拟内存）

任何 Linux 系统都具有一定量的 RAM 或物理内存。在对这些物理内存进行地址时，Linux 将其划分为内存块或“页”（`pages`）。在分配或移动时，Linux 操作的是页大小的块，而不是单个字节。在报告某些内存统计数据时，Linux 内核报告每秒的页数，该值取决于其运行的架构。代码列表 3.1 创建了一个小型应用程序，显示当前架构下每页的字节数。

##### 代码列表 3.1：

```c
#include <unistd.h>
int main(int argc, char *argv[])
{
    printf("System page size: %d\n", getpagesize());
}
```

在 IA32 架构上，页大小为 4KB。在某些情况下，页大小的内存块会导致过大的开销，内核使用更大的块来管理内存，被称为 `HugePages`（大页）。这些页比 4KB 大 2048KB，并极大减少了管理大量内存的开销。像 Oracle 这样的应用程序使用这些大页来管理内存。如果 `HugePages` 没有被数据完全填充，可能会浪费大量的内存。一个半满普通页浪费 2KB 内存，而一个半满 `HugePage` 可以浪费 1,024KB 内存。

Linux 内核可以散布这些物理页，并向应用程序呈现一个布局良好的虚拟内存空间。

##### 3.1.2.1 Swap（物理内存不足）

所有系统都具有一定量的 RAM 或物理内存。Linux 内核允许应用程序在所需内存超过可用内存时使用硬盘作为临时内存来运行。这个硬盘被称为交换空间（`swap space`）。虽然交换是处理进程的一种极方法，但它真的非常慢——比物理内存慢 1000 倍。它可以帮助确定你的系统使用了多少交换空间。
