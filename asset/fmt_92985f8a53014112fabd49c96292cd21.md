设备依赖格式允许在：

- RGB 强度 (`XmsRGBI`)：红、绿、蓝强度值，浮点值从 0.0 到 1.0， 1.0 表示全强度，0.5 表示半强度。
- RGB 设备 (`XmsRGB`)：适用于设备的红、绿、蓝值。`XmsRGB` 值为 `unsigned short`，从 0 到 65535 缩放，并与 `XColor` 结构中的红、绿、蓝值互换。

需要注意的是，RGB 值没有经过伽校正。相反，作为颜色规格生成的 RGB 值始终经过了伽校正，而通过查询调板获取或传入客户端的 RGB 值是经过校正的。手册中的 RGB 值始终指的是 RGB 设备。

## 颜色字符串

Xlib 提供了一种使用字符串名称颜色的机制。颜色字符串可以包含抽象颜色名称或颜色规格。颜色字符串不区分大小写。

颜色字符串用于以下函数：

- `XAllocNamedColor`
- `XmsAllocNamedColor`
- `XLookupColor`
- `XmsLookupColor`
- `XStoreNamedColor`

Xlib 支持使用抽象颜色名称，例如 red 或 green 或 blue。此抽象名称通过搜索一个或多个颜色名称数据库获得。Xlib 首先搜索两个或多个客户端数据库；这些数据库的数量、位置和内容取决于实现并可能取决于当前的区域设置。如果未找到名称，Xlib 然后会在 X 服务器的数据库中查找颜色。如果颜色不在主机移植字符编码（Host Portable Encoding）中，结果取决于实现。

数值颜色规格由颜色空间名称和一组遵循以下语法的值组成：

```
<color_space_name>:<value>/...<value>
```

以下是有效颜色字符串的示例：

```
"CIEXYZ:0.3227/0.2813/0.2493"
"RGB:1.0/0.0/0.0"
"rgb:00/ff/00"
"CIELuv:50.0/0.0/0.0"
```

后续章节将给出每个标准颜色规格语法和语义。

## RGB 设备字符串规格

RGB 设备规格由前缀 `rgb:` 识别并符合以下语法：

```
rgb:<red>/<green>/<blue>
```

```
 <red>, <green>, <blue> := h | hhh | hhhh
```

`h` := 单个十六进制数字（不区分大小写）

注意 `h` 表示经过 4 位缩放的值，`hh` 表示经过 8 位缩放的值，`hhh` 表示经过 12 位缩放的值，`hhhh` 分别表示经过 16 位缩放的值。

典型的示例字符串是 `rgb:ea/75/52` 和 `rgb:ccc/320/320`，但也允许混合数量的十六进制数字字符串 `rgb:ff/a5/0` 和 `rgb:ccc/32/0`。

为了向后兼容，支持旧的 RGB 设备语法，但不建议继续使用。该语法是一个初始井号字符，后跟以下格式之一的数值规格：

```
#R (每个4位)
#RRGBB (每个8位)
#RRRGGBBB (每个12位)
#RRRRGGBBB (每个16位)
```

`R`、`G` 和 `B` 代表单个十六进制数字。当指定的比特少于 16 位时，它们表示值的最高位（与 `rgb:` 语法不同，后者的值是缩放的）。例如，字符串 `#3a7` 等于 `#3000a`。

## RGB 强度字符串规格

RGB 强度规格由前缀 `rgbi:` 识别并符合以下语法：

```
rgbi:<red>/<green>/<blue>
```

注意红绿蓝是 0.0 到 1.0（包含边界）之间的浮点值。这些值的输入格式是可选的符号、可能包含小数点的数字字符串，以及一个可选的指数字段，该字段包含 `E` 或 `e` 后跟一个可选的正负号和一个数字字符串。

## 设备无关字符串规格

标准设备无关字符串规格具有以下语法：

```
CIEXYZ:<x>/<y>/<z>
CIEuV:<u>/<v>/<w>
CIExY:<C>/<x>/<y>
CIELab:<l>/<a><b>
CIELuv:<l>/<u><u>
TeHKVC:<h>/<j>/<k>
```

*(注：此处格式)*

所有的值（`C`, `H`, `V`, `X`, `Y`, `Z`, `a`, `b`, `u`, `v`, `x`, `y`）都是浮点值。这些值的语法是可选的正负号、可能包含小数点的数字字符串，以及一个可选的指数字段，该字段由 `E` 或 `e` 后跟一个可选的正负号和一个数字字符串组成。

## 颜色转换上下文与色域映射

当 Xlib 将设备无关的颜色规格转换为设备依赖的规格（反之）时，它会利用关于屏幕硬件颜色限制的知识。这些信息通常被称为设备配置文件（device profile），存储在颜色转换上下文（CCC）中。

由于指定的颜色可能超出目标屏幕的色域，且与颜色规格相关的白点可能与屏幕固有的白点不同，Xlib 在遇到某些条件时会应用色域映射（gamut mapping）：

- 当设备无关的颜色规格转换为设备依赖的颜色规格导致颜色超出目标色域时，会发生色域压缩（Gamut compression）。
- 当屏幕固有的白点与客户端假设的白点不同时，会发生白点调整（White adjustment）。

色域处理方法以回调函数的形式存储在 CCC 中，供颜色空间转换例程使用。每个回调在 CCC 中还存储了客户端数据。CCC 还包含了客户端假设与颜色规格相关的白点（即客户端白点，Client Point）。客户端可以指定色域处理回调、数据以及客户端白点。Xlib 并不排除客户端执行其他形式的色域处理（例如色域扩展）；然而，Xlib 不提供白点调整和色域压缩之外的直接色域处理支持。

每个颜色表（colormap）都关联一个由 Xlib 透明地生成的初始 CCC。因此，当你将颜色表作为 Xlib 函数的参数时，你实际上是在间接指定一个 CCC。每个屏幕都有一个关联默认 CCC。新创建的 CCC 继承自默认 CCC 的属性，因此可以通过修改默认 CCC 来影响新的 CCC。

可能发生色域映射的 Xcms 函数返回 Status，并为其定义了特定的状态值，如下：

- `XcmmsFailure` 表示函数失败。
