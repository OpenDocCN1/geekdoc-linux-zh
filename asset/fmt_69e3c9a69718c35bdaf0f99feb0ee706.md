
例如，要查找终端输出的行速，我们可以执行以下操作：

```c
struct termios dtp;
speed_t rate;

if (tcgetattr(fd, &dtp) == -1)
    errExit("tcgetattr");
rate = cfgetspeed(&dtp);
if (rate == -1)
    errExit("cfgetspeed");
```

如果我们想更改行速，可以继续后续操作：

```c
if (cfsetpeed(&dtp, B38400) == -1)
    errExit("cfsetpeed");
if (tcsetattr(fd, TCSAUSH, &dtp) == -1)
    errExit("tcsetattr");
```

`speed_t`数据类型用于存储行速。我们并不直接为行速赋值数值，而是使用一组符号常量（定义在`<termios.h>`中）。这些常量定义了一系列离散的值。常量的示例包括`B300`、`B2400`、`B9600`和`B38400`，分别对应每秒300、2400、9600和38400位的行速。使用一组离散值反映了一个事实：终端通常设计为与一组有限的不同（标准）行速工作，这些行速是由某些基础速率（例如PC上的115,200）除以整数值（例如115,200 / 12 = 9600）得到的。

SUSv3规定终端行速存储在`termios`结构中，但（故意）没有指定具体位置。包括Linux在内的许多实现在`c_cflag`字段中维护这些值，并使用`CBAUD`掩码和`CBAUD`标志。（在第62.2节，我们注意到`termios`结构中非标准的`c_ispeed`和`c_peed`字段是没有使用的。）

尽管`cfgetspeed()`和`cfetspeed()`函数区分了输入和输出行速，但在许多实现中，两者必须相同。此外，Linux使用单个字段存储行速（假设两个速率相同），这意味着所有输入和输出行速函数都访问同一个`termios`字段。

在`cfetspeed()`中将速度指定为0意味着“以后调用`tcgetattr()`时将输入速度设置为输出速度”。这对于将两个行速作为独立值维护的很有很有。

# 终端行控制

`tsendbreak()`、`tcdrain()`、`tcflush()`和`tcflow()`函数执行通常被归类为终端行控制的任务。（这些函数是POSIX发明，用于替换各种`ioctl()`操作。）

```c
#include <termios.h>

int tcsendbreak(int fd, int duration);
int tcdrain(int fd);
int tcflush(int fd, int queue_selector);
int tcflow(int fd, int action);
```

所有函数在成功时返回0，出错时返回-1。

在函数中，`fd`是文件描述符，指向终端或串口线上的其他远程设备。

`tsendbreak()`函数通过传输连续的0位流来产生BREAK（中断）条件。`duration`参数指定传输的长度。如果`duration`为0，则传输0.25秒的0位。（SUSv3）规定至少为0.25，如果`duration`大于0，则传输`duration`毫秒的0位。SUSv3未规定此之后的情况；其他UNIX实现对非零持续的处理差异很大（此处描述的适用于glibc）。

`tcdrain()`函数阻塞直到所有输出已传输（即终端输出队列已空）。

`tcflush()`清空（丢弃）终端输入队列、终端输出队列或两个队列的数据（见图62-1）。清除终端驱动程序接收但尚未被任何进程读取的输出队列数据。例如，应用程序可以使用`tcflush()`在提示密码前丢弃终端内容。清除已写入但尚未传输到设备的输出队列数据。`queue_selector`参数指定表62-4所示的值之一。

注意，在讨论文件I/O时，`tcflush()`中的“flush（刷新）”词含义有所不同。对于文件I/O，在`stdio fflush()`情况中，刷新意味着强制将输出从用户空间内存传输到缓冲区缓存；在`fsync()`、`fdatasync()`和`sync()`情况中，则是从缓冲区传输到磁盘。

## 表 62-4：`tcflush()` `queue_selector` 参数的值

| 值 | 说明 |
| :--- | :--- |
| TCFLUSH | 清空输入队列 |
| TCOFLUSH | 清空输出队列 |
| TCIOFLUSH | 清空输入和输出队列 |

`tcflow()`控制计算机与终端（或其他远程设备）之间双向的数据流。`action`参数是表62-5所示的值之一。只有当终端能够解释STOP和START字符时`TCIOFF`和`TCION`值才有效，在这种情况下，这些操作分别导致终端暂停和恢复向计算机发送数据。

## 表 62-5：`tcflow()` `action` 参数的值

| 值 | 说明 |
| :--- | :--- |
| TCOFF | 暂停向终端输出 |
| TCOON | 恢复向终端输出 |
| TCIOFF | 暂停接收输入 |
| TCION | 恢复接收输入 |

## 62.9 窗口大小

在窗口环境中，屏幕处理应用程序需要监控大小以便正确重绘屏幕。内核提供了支持：

- 当`winsize`结构与终端驱动器的窗口大小不同时，会发生两件事：
    - 终端驱动器数据结构更新。
    - 向前景组发送`SIGWINCH`信号。

通过传递初始化的`winsize`结构更改终端驱动器的窗口大小：

```c
struct winsize {
    unsigned short row;
    unsigned short col;
    unsigned short wop;
    unsigned short yopp;
};
```

使用`ioctl()`查找大小：

```c
struct winsize {
    unsigned short row;
    unsigned short col;
    unsigned short wop;
    unsigned short yopp;
};
```

然而，这些事件本身不足以更改实际维度，维度是由软件（如窗口管理器或终端模拟器）控制的。

## 62.10 终端识别

在34.4节中，我们描述了`ctermid()`函数，它返回控制终端。。本节中的函数也用于识别终端。

`isat()`函数使我们能够判断文件描述符`fd`是否与终端关联（而不是其他文件类型）。

```c
#include <unistd.h>

int isat(int fd);

// 如果 fd 与终端关联，返回 1，否则返回 0
```

`isat()`函数对于编辑器以及需要确定其输入输出是否指向终端的屏幕处理程序有用。给定一个文件描述符，`ttyname()`函数返回关联终端设备的名称。

```c
#include <unistd.h>

char *ttyname(int fd);

// 返回指向静态分配的终端名称字符串的指针，出错时返回 NULL
```

为了查找终端名称，`ttyname()`使用第18.8节描述的`opendir()`和`readdir()`函数遍历持有终端设备名称的目录，检查每个目录项，直到`stat`结构中的`st_dev`字段与文件描述符对应的设备匹配。终端设备项通常位于两个目录：`/dev`和`/dev/pts`。`/dev`包含虚拟控制台（例如`/dev/tty1`）和BSD伪终端。`/dev/pts`包含（System V风格）伪终端从设备。

`ttyname()`的重入版本形式为`ttyname_r()`。`t`命令显示其标准输入所指向的终端名称，是`ttyname()`的命令行对应项。

## 62.11 总结

在早期的UNIX系统中，终端是通过串口线连接到计算机的真实硬件设备。早期终端并没有标准化，这意味着编程不同厂商生产的终端需要不同的转义序列。在现代工作站上，终端已被运行着X窗口系统的映射显示器所取代。然而，在处理虚拟设备（如虚拟控制台和使用伪终端[pseudotinals]的终端模拟器）以及通过串口线连接的真实设备时，仍然需要编程终端的能力。

终端设置（终端窗口大小除外）维护在一个类型为`termios`的结构中，该结构体包含四个位掩码字段，用于控制各种终端设置，以及一个定义终端驱动程序解释的特殊字符的数组。`getioctl()`和`setioctl()`函数允许程序检索和修改终端设置。
