
进程启动时运行的方法。默认情况下，它会调用传递给 `Process` 构造函数的 `target`。作为替代，可以通过继承 `Process` 并重新实现 `run()` 来定义进程。

```python
p.start()
```

启动并运行代表该进程的子进程，并在该子中调用 `p.run()`。

```python
p.terminate()
```

强制终止进程。如果调用了此方法，进程 `p` 将立即终止，而不执行任何清理操作。如果该进程创建了自己的子进程，这些进程将变成僵尸进程。使用此方法时需要小心。如果 `p` 持有锁或参与进程间通信，终止它可能会导致死锁或 I/O 损坏。

```python
p.authkey
```

进程认证密钥。除非显式设置，否则这是一个由 `os.urandom()` 生成的 32 字符字符串。此处的目的是为涉及网络连接的底层进程间通信提供安全性。只有当两端具有相同的认证密钥时，此类连接才有效。

```python
p.daemon
```

一个布尔标志，指示进程是否为守护进程（daemon）。当创建它的 Python 进程结束时，守护进程会被自动终止。此外，守护进程被禁止自己创建新进程。`p.daemon` 的值必须在使用 `p.start()` 进程之前设置。

```python
p.exitcode
```

进程的整数退出状态码。如果进程仍在运行，则为 `None`。如果值为负数，值 `-N` 表示进程被信号 `N` 终止。

```python
p.name
```

进程的名称。

```python
p.pid
```

进程的整数进程 ID。

这里有一个示例展示了如何创建并启动一个函数（或其他可调用对象）作为单独进程：

```python
import multiprocessing
import time

def clock(interval):
    while True:
        print("The time is %s" % time.ctime())
        time.sleep(interval)

if __name__ == '__main__':
    p = multiprocessing.Process(target=clock, args=(1,))
    p.start()
```

另一个示例了如何定义继承 `Process` 的类：

```python
import multiprocessing
import time

class ClockProcess(multiprocessing.Process):
    def __init__(self, interval):
        super().__init__()
        self.interval = interval

    def run(self):
        while True:
            print("The time is %s" % time.ctime())
            time.sleep(self.interval)

if __name__ == '__main__':
    p = ClockProcess(1)
    p.start()
```

# Interprocess Communication

`multiprocessing` 模块支持两种进程间通信形式：管道（pipes）和队列（queues）。

## Queue(maxsize)

创建一个共享队列。`maxsize` 是队列允许的最大项数。如果省略，则没有大小限制。队列的实例具有以下方法：

```python
q.join_thread()
```

连接队列的后台线程。用于在调用 `close()` 后等待所有队列项被消费。此方法是阻塞的。

```python
q.close()
```

关闭队列，防止更多数据被其中。当调用此方法时，后台线程将继续写入尚未写入的队列数据，但在完成后将关闭。这是自动的。

```python
q.empty()
```

如果队列为空，返回 `True`。如果使用其他进程或线程来添加项，请注意结果是不可靠的（例如，在返回结果之前队列可能已经添加了项）。

```python
q.full()
```

如果队列已满，返回 `True`。结果对于线程是可靠的（参见 `q.empty()`）。

```python
q.get([block, timeout])
```

从 `q` 获取一个项。如果队列为空，它将阻塞队列直到有可用项。`block` 控制阻塞行为，默认为 `True`。如果设置为 `False`，当队列为空时将抛出 `Queue` 模块定义的 `Empty` 异常。`timeout` 是阻塞模式下使用的可选超时时间。如果在指定的时间间隔内没有可用项，将抛出 `Empty` 异常。

```python
q.get_nowait()
```

等同于 `q.get(False)`。

```python
q.join_thread()
```

连接队列的后台线程。用于在调用 `close()` 后等待所有队列项被消费。此方法默认在所有不是 `q` 的原始创建者的进程中都会执行。可以通过调用 `q.cancel_join_thread()` 禁用这种行为。

```python
q.put(item, [block, timeout])
```

将项放入队列。如果队列已满，则阻塞直到空间可用。`block` 控制阻塞行为，默认为 `True`。如果设置为 `False`，当队列已满时将抛出 `Queue` 模块定义的 `Full` 异常。`timeout` 指定在阻塞模式下等待空间可用的时间。超时后将抛出 `Full` 异常。

```python
q.put_nowait(item)
```

等同于 `q.put(item, False)`。

```python
q.qsize()
```

返回队列中当前项的近似数量。此函数的结果是不可靠的，因为在结果返回到程序稍后使用之间，队列中可能已经添加或删除了项。在某些系统中，这可能会引发 `NotImplementedError`。

### JoinableQueue [maxsize]

创建一个共享进程队列。这与 `Queue` 相似，不同之处在于队列允许项的消费者通知生产者项已成功处理。通知过程使用共享信号量和条件变量实现。

`JoinableQueue` 实例 `q` 具有与 `Queue` 相同的方法，但它具有以下额外方法：

```python
q.task_done()
```

用于生产者信号由 `q.get()` 返回的入队项已处理。如果此此次数超过了从队列中移除的项目数量，将抛出 `ValueError` 异常。

```python
q.join()
```

用于生产者阻塞，直到队列中放置的所有项都已处理。在每个放入队列的项都调用了 `q.task_done()` 之前，一直保持阻塞。

以下示例展示了如何设置一个永久运行的进程，该进程消费并处理队列上的项。生产者将项放入队列并等待它们被处理。

```python
import multiprocessing

def consumer(input_q):
    while True:
        item = input_q.get()
        # 处理项
        print(item) # 替换为有用的代码
        # Signal任务完成
        input_q.task_done()

def producer(output_q):
    for item in sequence:
        # 将项放入队列
        output_q.put(item)

# 设置
if __name__ == '__main__':
    q = multiprocessing.JoinableQueue()
    # 启动消费者进程
    cons_p = multiprocessing.Process(target=consumer, args=(q,))
    cons_p.daemon=True
    cons_p.start()
```

# 生成项。sequence 代表要发送给消费者的
# 项序列。在实践中，这可以是生成器的输出
# 或通过其他方式产生。
sequence = [1,2,3,4]
producer(sequence, q)

# 等待所有项被处理
q.join()
```

在此示例中，消费者进程被设置为守护进程（daemon），因为它永久运行，并且我们希望在主程序结束时将其终止（如果你忘记了这一点，程序将挂起）。使用 `JoinableQueue` 是为了让生产者实际上知道队列中的所有项何时已成功处理。`join()` 操作确保了这一点：如果你忘记了这一步，消费者将在完成其所有工作之前被终止。
