
``` 
public f
proc near
arg_0   = qword ptr 8
arg_8   = qword ptr 10h
push    ebp
fld     ds:dbl_00486088 ; 3.14
stack state now: ST(0) = 3.14
mov     ebp
fdiv   [ebp+arg_0]
stack state now: ST(0) = result of division
fld     ds:dbl_00486016 ; 4.1
stack state now: ST(0) = 4.1, ST(1) = result of division
mul     [ebp+arg_8]
; stack state now: ST(0) = result of multiplication, ST(1) = result of division
pop
ebp
faddp	st(1), st
; stack state now: ST(0) = result of addition
retn
endp
```

`f`第一个不同点，同时也是最显著的不同之处是: GCC把3.14插入FPU的队列（`ST(0)` 寄存器），用作`arg_0`的除数。

`FDIV`是Reverse Divide的写法。`FDIV`指令的除数和被除数，对应`FDIV`指令的被除数和除数，位置相反。在乘法运算中，因子的位置影响运算结果，所以没有`FMUL`指令。

`FADD`从栈中取出进行加法运算，并用`ST(0)`存储。

## 17.5.2 ARM: Optimizing Xcode 4.6.3 (LLVM) (ARM mode)

在ARM平台上浮点运算标准之前，许多厂商都推出了各自的扩展指令来实现浮点运算。后来，有VFP (Vector Floating Point)成为了行业的标准。

x86平台的FPU有自己的；但是ARM平台上并没有结构域，只能操作寄存器。

### 指令17.3 Optimizing Xcode 4.6.3 (LLVM) (ARM mode)

``` 
f
VLDR	D16,=3.14
MOV	D17, R0, R1; load "a"
MOV	D18, R2, R3; load "b"
VDIV.F64	D16, D17, D16; a/3.14
VLDR	D17,=4.1
VMUL.F64	D15, D17, D18; b*4.1
VADD.F64	D16, D17, D16; +
MOV	R0, R1, D16
BX
```

``` 
db1_2ca9	DCFD 3.14 ; DATA XREF: f
db1_2ca0	DCFD 4.1 ; DATA XREF: f
```

上述程序使用了`D`寄存器。ARM平台有32个`D`寄存器。这些寄存器用来存储（双精度）浮点数，又用于SIMD运算（NEON）。ARM平台还有32个`S`寄存器。`S`寄存器用于单精度。简单来说，`S`寄存器用于单精度，而`D`寄存器用于双精度。详细规格请阅B。本例中的浮点数用IEEE754格式存储在内存中。来说，`VLDR`和`MOV`指令是操作`D`寄存器的。这些`V`字符指令和`D`字符的寄存器，不仅能够处理浮点数据，而且用于SIMD（NEON）运算。即使涉及浮点运算，ARM平台还会通过`S`寄存器传递双精度浮点数据（64位），就需要两个`S`寄存器。`MOV D17, R0`指令从`R0`和`R1`读取64位数据。`MOV R0, R1`与上述指令相反。它把`D16`寄存器的值（64位）分解成32位，分别存储到`R0`和`R1`。后面出现的`DIV`、`VMUL`、`VADD`都是浮点运算。使用Xcode生成的Thumb代码跟程序相同。

## 17.5.3 ARM: Optimizing Keil (Thumb mode)

``` 
f
PUSH    {R3-R7}
MOVS    R7, R2
MOVS    R4, R3
MOVS    R5, R0
LDR     R2, =0x6666666
LDR     R3, =0x4010666
MOVS    R0, R7
MOVS    R4, R1
BL      __abi_dmul
LDR     R2, =0x51EB81F;3.14
LDR     R3, =0x409EB8
MOVS    R0, R5
MOVS    R1, R6
BL      __abi_ddiv
MOVS    R2, R7
MOVS    R3, R4
BL      __abi_dadd
POP     {R3-R7,PC}
```

``` 
; 4.1 in IEEE 754 format:
dword_364 DCD 0x6666666 ; DATA XREF: f
dword_368 DCD 0x4010666 ; DATA XREF: f
; 3.14 in IEEE 754 format:
dword_366 DCD 0x51EB8F ; DATA XREF: f
dword_370 DCD 0x409EB8 ; DATA XREF: f
```

Keil生成的Thumb程序使用NEON运算和FPU浮点运算。Thumb程序使用通用寄存器传递浮点数据。因为不再使用FPU专用指令，这类程序必须调用底层（例如`__abi_dmul`、`__abi_ddiv`、`__abi_dadd`）“仿真”浮点运算。“仿真”意义上的模拟运算速度比FPU处理器慢，依赖于早期FPU。在ARM系统中，FPU仿真库叫“soft float”，通过硬件FPU指令叫“hard float”。

## 17.5.5 ARM64: Non-optimizing GCC (Linaro)

``` 
f:
sub      sp, sp, #16
str      d0, [sp,8]      ; save "a" in Register Save Area
str      d1, [sp]        ; save "b" in Register Save Area
ldr      x1, [sp,8]      ; X1 = a
ldr      x0, .LC25      ; X0 = 3.14
fmov     d0, x1
fmov     d1, x0        ; D0 = a, D1 = 3.14
fdiv     d0, d0, d1      ; D = a/3.14
fmov     x1, d0        ; X1 = a/3.14
ldr      x2, [sp]       ; X2 = b
ldr      x0, .LC26      ; X0 = 4.1
fmov     d0, x2        ; D0 = b
fmov     d1, x0        ; D1 = 4.1
fmul     d0, d0, d1      ; D = b*4.1
fmov     x0, d0        ; X0 = b*4.1
fadd     d0, d0, d1      ; D = b*4.1+a/3.14
fmov     x0, d0        ; redundant code
fmov     d0, x0        ; /
add      sp, sp, 16
ret
.LC25:
  .word 1374389535 ; 3.14
  .word 1074339512
.LC26:
  .word 1717986918 ; 4.1
  .word 1074816614
```

在没有优化功能的情况下，GCC生成的代码糟糕。在上述程序中，不仅出现了没有意义的数值交换，出现了明显多余的指令（例如`MOV`）。这可能是GCC4.9方面的不足。注意的是，ARM64具有64位寄存器，而双字寄存器同样是64位。所以编译器可以用通用寄存器GPR直接存储双精度数而不查找。在32位CPU上，编译器无法这种寄存器建议读者对这个程序进行练习，不使用`FMADD`指令的情况下。

## 17.5.6 MIPS

MIPS平台支持多个FPU处理器。与ARM处理器相似，MIPS不是栈机（stack machine），而是32位寄存器（`F0~F31`）。有关FPU寄存器的介绍，参见附录C.2。处理64位双精度点时必须一对。
