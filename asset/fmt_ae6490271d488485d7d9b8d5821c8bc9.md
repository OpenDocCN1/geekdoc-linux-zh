# Linux 调制解器与串口通信

各项设置并不一致。换句话说，这意味着驱动程序获取的串口信息错误的。如果驱动程序具有错误的 I/O 地址，它将尝试将数据发送到不存在的串口——更糟糕的是，发送到某个并非串口的实际设备。如果它具有错误的 IRQ（中断请求），它将无法获取来自串口的中断服务请求，导致串口缓冲区可能溢出，并且响应非常缓慢（因为回退到了非常慢的“轮询”方法而不是中断）。如果 UART 型号错误，也可能出现问题。

你如何确保驱动程序拥有正确的信息？嗯，如果一切正常，就不需要检查这一项。但在其他情况下，很容易看出驱动程序的想法。一种方法是直接输入 `serial-g /dev/ttyS*`。在启动时，控制台上的一个消息会显示此内容。你可以查看 `/proc/ioports`；它只显示串口“设置”的相同 I/O 地址，但不一定是硬件中的实际方式。查看当前运行进程（已打开设备的进程）所使用的 IRQ，查看 `/proc/interrupts`。它还显示了已发出的中断次数（通常是数千次）。上述测试均不能显示设备中实际设置的内容。但如果一切运行正常，设备设置可能与硬件中的设置是一的。

但你如何发现 I/O 地址和 IRQ 实际上设置在设备硬件中？如果调制解器是 PCI 的，查看 `/proc/pei`。如果是 ISA 的，这并不总是容易的。以前人们通过检查调制解器卡、串口卡或主板上跳线帽设置来这样做。一种粗略的方法是尝试使用 `serserial` 配合 “autoconfig” 选项进行探测。你需要猜出要探测的地址。参见 `Setserial`。

对于 ISA 总线上的即插即用（PnP）模式（或 PnP 串口），人们可以尝试 `pnpdummy` 程序（`isapntools` 的一部分）。`pnpdummy` 会“找到”端口并显示各种配置选项，但不会告诉你真实的 I/O 地址和 IRQ。它“尝试”的地址并不是设备的 I/O 地址，而是仅用于 PnP 目的的特殊读端口。在使用 `pnpdummy` 获取一些信息后，这些信息可以用于 `isapnp` 命令的“PEEK”关键字来查找 I/O 和 IRQ。`isapnp-configuration` 文件中的命令可能像这样（对于供应商 GVC1601，序列号为 1）：`(CONFIGURE GVC1601/2 IO 0 (PEEK))`。你需要的不仅仅此命令，而且它并不是万无一失的（参见 `isapnp` 的手册页）。我知道以上内容并不充分，但如果你成功做到了，你可以将其写下来并在此 HOWTO 的最新版本查看。

另一种方法是查看它在 MS-Windows 下是如何配置的（如果你在同一台机器上安装了它）。MS-Windows 下的配置可能与 Linux 不同，但如果你在启动时让 PnP 操作系统进行配置（并已告知 BIOS），它们很可能是相同的。

### 配置流控 (RTS/CTS)

请查看流控的解释。如果可能，你应该始终使用流控。你的通信程序或 `getty` 应该有一个设置它的选项（如果你运气好，它可能是默认开启的）。它需要在调制解器内部（通过初始化字符串或默认值）以及设备驱动程序中设置。如果上述任何操作都没有完全启用流控，那么你必须手动完成。对于调制解器，确保它是通过初始化字符串或默认设置的。如果你需要让设备驱动程序执行，最好在启动时将以下内容放入每个串口的此类文件中（例如 `ttyS2`）：

```bash
stty crcts < /dev/ttyS2
```

如果你想查看流控是否已启用，请执行以下操作：在 `Minicom`（或类似程序）输入 `AT&V` 查看调制解器的配置，并寻找 `&K3`。然后通过输入 `stty -a < /dev/ttyS2` 查看设备驱动程序是否知道它。

### AT 命令

当位于调制解器的串口进行配置的同时，调制解器本身也在配置。调制解器是通过向用于发送数据的线路发送 AT 命令（或类似命令）来配置的。大多数调制解器使用 AT 命令集。这些是晦涩且短小的 ASCII 命令，所有命令字符串都以字母 `AT` 开头。例如：`ATZ&K3`。这里有两个命令：

- `Z0`：调回用户配置 `0` 并重置（挂断）
- `&F0`：调回出厂 `0`
- `&W0`：将当前配置保存到用户配置

遗憾的是，AT 命令集有很多不同的变体，因此适用于一个调制解器的命令可能不适用于另一个。因此，无法保证本节中提供的 AT 命令在你的调制解器上有效。另一点是让调制解器响应 AT 命令字符串必须在字符串末尾发送一个返回符。有时 AT 前面有一个返回符，有时字符串中会添加符号（例如），这仅告诉通信程序暂停极极短的时间。

如果你有调制解器的说明书，可以快速从中查找 AT 命令集。否则，你可以尝试在互联网上查找。

本节给出的示例来自 Hayes 命令集。所有命令字符串必须以两个字母 `AT` 开头。当调制解器上电时，它会自动使用非易失性内存中存储的配置进行自配置。如果此配置是满意的，则不需要操作。

如果不满意，可以通过发送一组被称为“初始化字符串”（`init string`）的来更改或重新配置调制解器。大多数时候，当你启动通信程序时，会自动发送初始化字符串（取决于你如何配置或你编写了什么脚本，如果使用 `Kermit`）。你通常可以编辑初始化字符串并将其更改为任何内容。有时通信程序会让你选择模型并使用它认为对调制解器最好的初始化字符串。

因此，调制解器内部存储了一个默认字符串（称为配置），以及由通信程序发送的另一个（初始化字符串）。调制解器的状态将与默认集相似，只是被初始化字符串中包含的命令修改了。如果初始化字符串为空，它当然会使用默认配置。

实际上，在调制解器的非易失性内存中存储了多个“默认”配置（或配置）（当你关闭它时仍然存在）。在我的调制解器中，有两个配置（`0` 和 `1`，均无法更改）以及两个用户可以设置并存储的用户定义配置（`0` 和 `1`）。你的调制解器可能有更多。在开电时使用哪一个用户配置取决于配置中存储的另一个项目。如果给出命令 `Y00`，则未来开电时将使用配置 `0`。如果是 `1` 而不是 `0`，则开电时将使用配置 `1`。

还有命令可以调回（现在使用）存储的 4 个配置中的任何一个。可以将此类命令放在初始化字符串中。当然，如果它调回的是与开电时加载的相同配置，则没有任何变化（除非初始化字符串是在调制解器使用一段时间且软件等更改了配置后发送的）。使用某种初始化字符串是一个好主意，以便可以重置。

### 其他调制解器命令

未来的 Modem-HOWTO 可能包含更多 AT 命令，但本节的其余部分是旧 Serial-HOWTO 中的。所有字符串必须以 `AT` 开始。这里是一些应该在字符串中的 Hayes 代码（如果它们没有使用出厂默认或保存的配置设置）：

- `E1` 命令回显开启
- `Q0` 报告结果
- `V1` 详细模式开启
- `SO=0` 从不回答 (`ugetty` 使用 `WAITFOR` 选项实现此功能)
