
```c
struct idr id_huh; /* 静态定义 idr 结构 */
idr_init(&id_huh); /* 初始化提供的 idr 结构 */
```

## 分配新 UID

一旦设置好`idr`，你就可以分配一个新的UID，这是一个两步过程。首先告诉`idr`你想要分配一个新的UID，允许它根据需要调整树的大小。然后，通过第二次调用，实际请求新UID。这种复杂的设计允许你在不加锁的情况下执行初始尺寸调整（这可能需要内存分配）。我们将在第 12 章讨论分配，在第 9 和第 10 章讨论锁定。现在，让我们专注于如何使用`idr`，而不必担心我们如何处理锁定。

用于调整树大小的第一个函数是`idr_pre_get()`：

```c
int idr_pre_get(struct idr *idp, gfp_t *gfp_mask);
```

该函数如果为了满足UID分配的需要，将调整由`idp`指向的`idr`。如果需要调整，内存分配将使用`gfp_mask`gfp标志（gfp标志在第 12 章中讨论）。你不需要对它进行并发访问同步。从内核中的几乎每个函数来说，`idr_pre_get()`成功返回 1，错误返回 0——要小心！

获取新UID并将其添加到`idr`的第二个函数是：

```c
int idr_get_new(struct idr *idp, void *ptr, int *id);
```

该函数使用`idp`指向的`idr`分配一个新的UID并与指针`ptr`关联。成功时，函数返回 0 并新UID存储在`id`中。错误时，返回非零错误代码：如果需要（再次）调用`idr_pre_get()`，则返回`-EAGAIN`；如果`idr`已满，返回`-ENOSPC`。

成功调用此函数将返回与`idp`指向的`idr`中的UID关联的指针。错误时，函数返回`NULL`。如果你向`idr_get_new()`或`idr_get_new_above()`传递`NULL`，该函数将成功返回`NULL`，导致你无法区分成功或失败。因此，你不应该将UID映射到`NULL`。

用法非常简单：

```c
struct my_struct *ptr = idr_find(&idr_huh, id);
if (!ptr)
    return -EINVAL;  /* 错误 */
```

## UID

要从`idr`中删除UID，请使用`idr_remove()`：

```c
void idr_remove(struct id *idp, int id);
```

成功调用`idr_remove()`会从`idp`指向的`idr`中移除UID。

遗憾的是，`idr_remove()`无法表示错误（例如如果`id`不在`idp`中）。

## 销毁 id

销毁id是一件简单的事，通过`idr_destroy()`函数完成：

```c
void idr_destroy(struct idr *idp);
```

在调用`idr_destroy()`之前，会对`idp`指向的`idr`调用`idr_remove_all()`，以确保所有`idr`内存都被释放。

```c
if (offset < page->offset)
    n = n->rb_left;

```

在这个示例中，`while`循环遍历`rtree`，根据给定的`offset`按需向左或右子节点遍历。`if`和`else`语句实现了`rtree`的比较函数，强制执行树的顺序。如果循环找到了具有匹配偏移的节点，则搜索完成，函数返回关联的页结构。如果循环到达`rtree`的末尾仍未找到匹配项，则树中不存在该项，函数返回`NULL`。

`insert`更为复杂，因为它同时实现了搜索和插入逻辑。以下并不是一个简单的函数，但如果你需要实现自己的`insert`程，这是一个很好的指南：

```c
struct page *rb_insert_page_cache(struct inode *inode,
    unsigned long offset,
    struct rb_node *node)

struct rb_node **p = &inode->i_rb_page_cache.rb_node;
struct rb_node *parent = NULL;
struct page *page;

while (*p) {
    parent = *p;
    page = rb_entry(parent, struct page, rb_page_cache);

    if (offset < page->offset)
        p = &(*page)->rb_left;
    else if (offset > page->offset)
        p = &(*page)->rb_right;
    else
        return page;
}

rb_link_node(node, parent, p);
rb_insert_color(node, &inode->i_rb_page_cache);

return NULL;
```

与我们的搜索函数一样，`while`循环正在遍历树，沿着提供的`offset`方向移动。然而，与搜索不同，该函数希望不要找到匹配的`offset`，而是到达作为新`offset`正插入点的叶子节点。当找到插入点时，调用`rb_link_node()`将新节点插入到指定位置。调用`rb_insert_color()`来执行复杂的重平衡“舞蹈”。如果页已添加到页缓存中，函数返回`NULL`；如果页已在缓存中，则返回现有页结构的地址。

# 何时使用什么数据结构

到此为止，我们讨论了Linux最重要的数据结构：链表、队列、映射和红黑树。在本节中，我们将介绍一些帮助你决定在自己的代码中使用哪种结构的提示。

如果你的主要访问方法是遍历所有数据，请使用链表。直觉上，在访问每个元素时，没有数据结构能提供比线性复杂度更好的性能，因此你应该为该任务选择最简单的结构。当性能不重要、你需要存储数量较少的项目，或者你需要与使用链表的其他内核代码接口时，也要考虑链表。

如果你的代码遵循生产者/消费者模式，请使用队列，特别是当你（或可以处理）固定大小的缓冲区时。队列使得添加和删除项变得简单，并提供了先入先出（`FIFO`）语义，这是大多数生产者/消费者用例所要求的。另一方面，如果你需要存储未知且可能大量的项，链表可能更有意义，因为你可以动态地向列表中添加任意数量的项。
