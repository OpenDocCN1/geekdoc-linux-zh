
`except LookupError:`  # 捕获 `IndexError` 或 `KeyError`

    statements

``` 

或者

``` 

`try:` 

    statements

`except Exception:`  # 捕获任何程序异常

    statements

``` 

在异常层次结构的顶端，根据异常是否与程序退出相关进行分组。例如，`SystemExit` 和 `KeyboardInterrupt` 异常没有归类在 `Exception` 下，因为想要捕获程序相关错误的程序通常不想意外捕捉终止。

## 定义新异常

所有内置异常都是通过类定义的。创建一个新异常，创建一个继承自 `Exception` 的新类，如下：

``` 
class NetworkError(Exception): pass
``` 

要使用你的异常，像下面所示配合 `raise` 语句使用：

``` 
raise NetworkError("找不到主机。")
``` 

引发异常时，`raise` 语句提供的可选值将作为构造函数的参数。大多数情况下，这是一个指示错误消息的简单字符串。然而，自定义异常可以写为接收一个或多个值，如下例所示：

``` 
class DeviceError(Exception):
    def __init__(self, errno, msg):
        self.args = (errno, msg)
        self.errno = errno
        self.errmsg = msg
``` 

```python
### 引发异常（多个参数）
raise DeviceError(1, '未响应')
```

## 上文管理器与 with 语句

当与异常结合时，对文件、锁和连接等系统资源的妥当管理通常是一个棘手的问题。例如，抛出的异常可能会导致控制流跳过释放关键资源（如锁）的语句。

`with` 语句允许一组语句在运行时上下文中执行，该下文由一个充当上下文管理器的对象控制。这里是一个示例：

```python
with open("debuglog", "a") as f:
    f.write("Debugging\n")
    statements
    f.write("Done\n")
```

```python
import threading
lock = threading.Lock()
with lock:
    # 关键区域
    statements
    # 结束关键区域
```

在第一个示例中，`with` 语句会在控制流离开随后的语句块时自动关闭打开的文件。在第二个示例中，`with` 语句会在控制流进入和离开随后的语句块时获取和释放锁。

`with` 语句允许 `obj` 管理控制流进入和退出相关的后续语句块时发生的情况。通过 `with obj` 语句，它执行方法 `obj.__enter__()` 以指示正在进入一个新上下文。当控制流离开上下文时，会执行 `obj.__exit__(type, value, traceback)` 方法。如果没有抛出异常，`__exit__()` 的三个参数将都为 `None`；它们包含了与导致控制流离开上下文的异常相关的类型、值和回溯信息。`__exit__()` 方法返回 `True` 或 `False`，表示抛出的异常是否已处理（如果返回 `False`，则任何异常都会传播到上下文之外）。

# 90 第 5 章 程序结构与控制流

`with obj.__enter__()` 接受一个可选的 `as` 指定符。如果给出，`obj.__enter__()` 返回的值将被放入 `var` 中。需要强调的是，`obj` 并不一定是赋值给 `var` 的值。

`with` 语句仅适用于支持上下文管理协议（即 `__enter__()` 和 `__exit__()` 方法）的对象。用户定义的类可以实现这些方法来定义它们自己的上下文管理。这里有一个简单的示例：

```python
class ListTransaction(object):
    def __init__(self, thelist):
        self.thelist = thelist
    def __enter__(self):
        self.workingcopy = list(self.thelist)
        return self.workingcopy
    def __exit__(self, type, value, tb):
        if type is None:
            self.thelist[:] = self.workingcopy
        return False
```

这允许人们对现有列表进行一系列修改。然而，只有在没有发生异常的情况下，修改才会生效。否则，原始列表将保持不变。例如：

```python
items = [1,2,3]
with ListTransaction(items) as working:
    working.append(4)
    working.append(5)
print(items)  # 输出 [1,2,3,4,5]
```

```python
try:
    with ListTransaction(items) as working:
        working.append(6)
        working.append(7)
        raise RuntimeError("We're hosed!")
except RuntimeError:
    pass
print(items)  # 输出 [1,2,3,4,5]
```

`contextlib` 模块允许我们通过在生成器函数周围放置包装器来更容易地实现自定义上下文管理器。这里是一个示例：

```python
from contextlib import contextmanager
@contextmanager
def ListTransaction(thelist):
    workingcopy = list(thelist)
    yield workingcopy
    # 只有在没有错误时才修改原始列表
    thelist[:] = workingcopy
```

## 断言与 __debug__

`assert` 语句可以向程序引入调试代码。`assert` 的一般形式为

```python
assert test [, msg];
```

其中 `test` 是一个应该求值为 `True` 或 `False` 的表达式。如果 `test` 求值为 `False`，则抛出一个 `AssertionError` 异常，并带有向 `assert` 语句提供的可选 `msg`。这里有一个示例：

```python
def write_data(file, data):
    assert file, "data: not defined!"
```
