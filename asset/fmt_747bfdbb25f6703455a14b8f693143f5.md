### 3. 云模块
除了 EC2 外，Ansible 还提供了针对其他云服务的模块，允许用户管理计算资源、存储和网络。例如，管理员可以使用 `gcp_compute_instance` 模块管理 Google Cloud 实例，或使用 `azure_rm_virtualmachine` 管理 Azure 虚拟机。

## 使用 Ansible 进行配置管理

一旦基础设施置备，可以使用 Ansible 确保服务器按照所需状态进行配置。这涉及安装软件包、配置服务和管理文件。

### 1. 安装软件包
Ansible 可以使用目标操作系统的相应包管理器来安装软件包。例如，在 Rocky Linux 服务器上，管理员可以使用 `yum` 模块：

```yaml
- name: Install required packages
  yum:
    name:
      - httpd
      - git
    state: present
```

### 2. 配置服务
安装软件包后，管理员可以管理服务，例如启动、停止和启用它们在启动时运行。例如：

```yaml
- name: Start and enable Apache
  service:
    name: httpd
    state: started
    enabled: yes
```

### 3. 管理配置文件
使用 `template` 模块部署从 Jinja2 模板派生的配置文件。这允许管理员根据管理员 playbooks 中定义的变量动态生成配置文件：

```yaml
- name: Deploy application configuration
  template:
    src: templates/myapp.conf.j2
    dest: /etc/httpd/conf/myapp.conf
```

## 使用 Ansible 进行编排

Ansible 在编排方面表现出色，允许管理员协调跨不同服务器和服务的多个任务。这对于部署需要多个组件无缝协作的复杂应用特别有用。

### 1. 定义角色
将与特定组件相关的任务组织成角色。每个角色都可以包含其自己的任务、处理器、变量和模板。这种模块化促进了重用性，并简化了 playbook 的结构。

```yaml
roles:
  - webserver
  - database
```

### 2. 顺序执行
Ansible 按照在 playbook 中定义的顺序执行任务。

### 3. 异步任务
Ansible 允许在后台运行任务并继续执行后续任务。例如：

```yaml
- name: Long-running task
  command: /path/to/long_running.sh
  async: 600
  poll: 0
```

## 示例：管理基础设施

在此示例中，playbook 执行了以下步骤：

1. 在 AWS 中启动 EC2 实例。
2. 等待实例可以通过 SSH 访问。
3. 通过安装和启动 Nginx 配置服务器。
4. 从 Git 仓库部署应用代码。

以下是此过程的示例 playbook：

```yaml
---
- name: Manage Infrastructure
  hosts: localhost
  gather_facts: false
  tasks:
    - name: Launch EC2 Instances
      ec2:
        key_name: my-key
        instance_type: t2.micro
        image: ami-0abcdef1234567890
        wait:
          region: us-west-2
          group: my-security-group
        count: 2
      register: ec2_instances

    - name: Wait for instances to be up
      wait_for:
        host: "{{ item.public_ip }}"
        port: 22
        delay: 10
        timeout: 300
      loop: "{{ ec2_instances.instances }}"

- name: Configure Web Servers
  hosts: "{{ ec2_instances.instances | map(attribute='public_ip') }}"
  become: yes
  tasks:
    - name: Install Nginx
      yum:
        name: nginx
        state: present

    - name: Start Nginx
      service:
        name: nginx
        state: started

    - name: Deploy application code
      git:
        repo: 'https://github.com/example/myapp'
        dest: /usr/share/nginx/html
```

提供了云的可扩展性和可靠性优势，同时 Ansible 确保了部署是一致的、可重复的且高效的。自动化部署的主要优势包括：

- **更快的部署**：自动化服务器置备和配置缩短了部署时间。
- **一致性**：确保所有 Rocky Linux 实例的配置都完全相同。
- **可扩展性**：轻松扩展部署以匹配工作负载需求。
- **减少错误**：通过自动化消除手动配置错误。
- **成本效益**：优化 AWS 中的基础设施置备和使用。

# 先决条件

在 AWS 中自动化 Rocky Linux 部署之前，请确保满足以下先决条件：

- **AWS 账户**：
  - 我们需要一个活跃的 AWS 账户，具有足够的权限创建和管理 EC2 实例、安全组和其他资源。
  - 为了安全最佳实践，请使用 IAM 角色，而不是直接存储 AWS 凭据。

- **已安装 Ansible**：
  - 在控制机（例如 Rocky Linux 或其他 Linux 发行版）上安装 Ansible：`sudo dnf install ansible -y`

- **已安装 AWS CLI**：
  - 使用凭据（或在 AWS 实例上运行时使用 IAM 角色）安装并配置 AWS CLI：
    1. `sudo dnf install aws-cli -y`
    2. `aws configure`
  - **IAM 角色**：确保 AWS 账户具有管理 EC2、VPC 和相关服务的 IAM 角色或用户。
  - **SSH 密钥对**：创建 AWS 密钥对或确保我们已有。该密钥将允许我们 SSH 连接到 Rocky Linux 实例。
