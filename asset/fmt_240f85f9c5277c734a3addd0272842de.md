## 构建 ICMPv4 消息

ICMPv4 消息已构建。标识符字段设置为我们的 PID，序列号字段设置为全局变量 `nnent`，然后为下一个数据包递增。我们在 ICMP 消息的数据部分填充了 `0xa5` 模式。

## 计算 ICMP 校验和

为了计算 ICMP 校验和，我们将校验和字段设置为 0，并调用 `in_cksum()` 函数，将结果存储在校验和字段中。ICMPv4 校验和是根据 ICMPv4 头部以及随后的任何数据计算的。

## 发送报文

ICMP 消息在原始套接字（raw socket）上发送。由于我们没有设置 `IP_HDRINCL` 套接字选项，内核会构建 IPv4 头部并附加到我们的缓冲区之前。

互联网校验和是对待校验和的 16 位值取反码后再取一次反码的结果。如果长度是奇数，则在逻辑上会在数据末尾附加一个 1 字节的 0，仅用于校验和计算。在计算校验和之前，会将校验和字段本身设置为 0。该算法用于 IPv4、ICMPv4、ICMPv6、IPv6、UDP 和 TCP 校验和。RFC 1071 [Braden, Borman, and Partridge 1988] 包含了额外信息和一些数值示例。TCP 的第 8.7 节更详细地讨论了这种算法，并展示了一种更高效的实现。我们使用图 28.5 中所示的 `in_cksum()` 函数计算校验和。

```c
uint16_t
in_cksum(uint16_t * addr, int len)
{
    int nleft = len;
    uint32_t sum = 0;
    uint16_t *w = addr;
    uint16_t answer = 0;

    /* 我们的算法简单，使用一个 32 位累加器 (sum)，我们将
     * 连续的 16 位字加到其中，最后，将高 16 位的所有
     * 进位位折叠回低 16 位。
     */

    while (nleft > 1) {
        sum += *w++;
        nleft -= 2;
    }

    /* 如果需要，处理一个奇数字节 */
    if (nleft == 1) {
        sum += (unsigned char *)(&answer) & *(unsigned char *) w;
        answer = sum;
    }

    /* 将高 16 位的进位位加到低 16 位 */
    sum = (sum >> 16) + (sum & 0xffff); /* 高位加到低 16 位 */
    sum += (sum >> 16); /* 加进位 */
    answer = ~sum; /* 截断为 16 位 */
    return (answer);
}
```

**图 28.5** `in_cksum()` 函数：计算互联网校验和。

## 互联网校验和算法

第一个 `while` 循环计算所有 16 位值的和。如果长度为奇数，则最后一个字节也将加到和中。我们在图 28.5 中展示的算法是简单算法。由于内核执行了大量的校验和计算，内核拥有一个专门优化的校验和算法。

此函数取自 Mike Muuss 编写的公有领域版本 `ping` 程序。

我们 `ping` 程序的最后一个函数是 `send_v6()`，如图 28.16 所示，它构建并发送一个 ICMPv6 回显请求。

```c
#include "ping.h"

void
send_v6() {
#ifdef len
    int len = *len;
    struct icmp6_hdr *icmp6;

    icmp6 = (struct icmp6_hdr *)sendbuf;
    icmp6->icmp_type = ICMPv6_ECHO_REQUEST;
    icmp6->icmp_code = 0;
    icmp6->icmp_id_seq = nnent++;
    memset((icmp6 + 1), 0xa5, datalen); /* 用模式填充 */
    gettimeofday((struct timeval *) NULL);
    len = *len + 8; /* ICMPv6 头部 */
    sendto(sockfd, sendbuf, len, 0, pr->sasend, pr->salen); /* 内核为我们计算并存储校验和 */
#endif
}
```

**图 28.16** `send_v6()` 函数：构建并发送 ICMPv6 回显消息。

`send_v6()` 函数与 `send_v4()` 类似，但注意它没有计算 ICMPv6 校验和。正如本书早些时候提到的，ICMPv6 校验和在计算中使用 IPv6 头部中的源地址，该校验和由内核在选择源地址后为我们计算。

# 28.6 traceroute 程序

在本节中，我们将开发自己版本的 `traceroute` 程序。与我们在上一节中开发的 `ping` 程序一样，我们将开发并展示自己的版本，而不是展示公有的版本。这是因为我们需要一个同时支持 IPv4 和 IPv6 的版本，而且我们不想被与我们的网络编程讨论无关的选项列表分散注意力。

`traceroute` 让我们能够确定从主机到某些其他目的地的 ICMP 数据报的路径。它的操作简单，并使用了 TCP 第 8 章的内容，该章节通过许多用法示例对其进行了详细介绍。`traceroute` 使用 IPv4 的 TTL 字段或 IPv6 的跳数限制字段以及两个 ICMP 消息。它首先向目标发送一个 TTL（或跳数限制）为 1 的 UDP 数据报。该数据报会导致第一跳路由器返回一个 ICMP “传输中超出限制”（time exceeded in transit）错误。然后将 TTL 增加 1 并发送另一个 UDP 数据报，从而定位路径中的下一个路由器。UDP 数据报到达最终目的地，我们的目标是让它返回一个错误。
