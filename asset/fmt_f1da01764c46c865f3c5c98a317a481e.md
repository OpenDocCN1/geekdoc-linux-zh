
# 11.4.4 节点平衡

间接回收的最终目的是为了平衡它所属的节点。

节点被平衡简单意味着，至少一个区域可以从请求的顺序中分配（考虑到低内存预留，细节请参见 2.4.1）并等于高水位线。

我们跳过任何不通过 `managed_zone()` 测试的、由伙伴页面分配器控制的页面，然后通过 `high_wmark_pages()` 获取该区域的高水位值。

这会针对指定的阶数（order）的区域通过函数 `zone_wmark_ok_safe()` 进行检查，该函数最终会调用 `zone_wmark_ok()`（见第 2.8.2 节和第 2 章中的列表 2-59）。

如果没有区域可以检查，说明我们成功了；否则，如果没有区域足够的空闲页，我们指示失败。

我们现在已经检查了如何判断一个节点是否平衡，现在可以检查间接回收的下一个阶段（如图 11-10 所示），通过 `balance_pgdat()` 对节点进行平衡，我们从列表 13-32 开始分析（省略了范围之外的 PSI 内存压力钩子、lockdep、cgroup、空闲处理以及 buffer head 越界）。

```c
/*
 * 对于 kswapd，balance_pgdat() 将跨越节点从允许调用者
 * 使用的区域回收页面，直到至少有一个区域达到
 * Balanced。
 *
 * 返回 kswapd 回收的阶数。
 * kswapd 按照 highmem-normal->dma 方向扫描区域。它会跳过
 * free_pages > high_wmark_pages(zone) 的区域，但一旦某个区域的
 * free_pages < high_wmark_pages(zone)，该区域中的任何页面
 * 或更低页面都可以被回收，直到至少有一个可用的区域达到
 * Balanced。
 */
```

```c
static int balance_pgdat(pg_data_t *pgdat, int order, int highest_zoneid) {
    int i;
    unsigned long nr_sort_reclaimed;
    unsigned long nr_boost_reclaim;
    unsigned long zone_boosts[MAX_NR_ZONES] = { 0, };
    bool boosted;
    struct zone *zone;
    struct scan_control sc = {
        .gfp_mask = GFP_KERNEL,
        .order = order,
        .may_unmap = 1,
    };
    set_task_reclaim_state(current, &sc.reclaim_state);
    count_vm_event(PAGEOUTRUN);
}
```

## 回收与内存压力

```c
/*
 * 考虑回收提速。注意区域提升保留在
 * 原处，以便接近水位线的并行分配会
 * 停顿或进行直接回收，直到 kswapd 完成。
 */
```

```c
nr_boost_reclaim = 0;
for (i = 0; i <= highest_zoneid; i++) {
    zone = pgdat->node_zones + i;
    if (!managed_zone(zone)) {
        continue;
    }
    nr_boost_reclaim += zone->watermark_boost;
    zone_boost[i] = zone->watermark_boost;
}
boosted = nr_boost_reclaim;
```

我们开始 `balance_pgdat()` 通过初始化状态并设置 `struct task_struct->rs` 为指向新初始化的 `struct scan_control.reclaim_state` 字段中的 `struct reclaim_state` 对象的指针。

`reclaim_state` 字段目前用于跟踪由 slab 回收的数量。内核 slab 分配超出了本书范围，但广义上讲，它是内核允许高效子页面大小分配的机制，即内核中的 `malloc()`。

由 slab 分配的对象也可以为了效率维护在缓存中，这些缓存可以在回收期间被收缩以释放内存，这正是此处测量的内容。

接下来，我们通过 `PAGEOUTRUN` 事件值标记间接回收正在发生。

我们测量节点中已提升的区域，在 `nr_boost_reclaim` 中聚合提升的页面数量，在本地 `zone_boosts` 数组中记录每个区域的提升值。

区域提升发生在迁移碎片化时，会向每个水位线增加一个因子。

我们在第 2.5 节和第 2 章中讨论迁移类型，但广义上这是物理内存页面的一个属性，决定内存是否可移动（即内存用于内核分配），以便我们将可移动内存与不可移动内存分开维护（这样不会导致碎片化，从而通过让可移动内存与不可移动内存交织来释放高阶 folio）。

然而，在无法找到所需迁移类型页面块的情况下（同样在第 2 章中介绍，但广义上页面块是 `pageblock` 阶的物理连续内存，在 x86-64 上为 9 阶）。

这在 `steal_suitable_fallback()` 中执行（见第 2 章中的列表 2-68 和第 2.8.6 节）。如果发生这种情况，我们希望确保碎片化尽快得到补救，通过在 `boost_watermark()` 中每次增加一定数量的页面来提高每个水位线，最多增加一个页面块的大小。

当我们这样做时，我们会在物理页面分配期间通过 `wakeup()` 主动唤醒该节点的 `kswapd`（见第 2 章中的列表 2-60 和第 2.3 节）。这样做是为了防止迁移类型块进一步被污染，从而减少由此产生的碎片化。

如果节点已平衡，因此本不需要回收，我们将利用此过程中收集的信息来决定是否执行间接回收以释放内存，避免进一步的迁移窃取。
