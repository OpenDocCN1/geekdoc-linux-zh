
- 枚举列表。例如，`ABCDEFGHIJKLMNOPQRSTUVWXYZ`。

- 字符范围。例如，`A-Z`。注意，这种方法由于区域排序的问题，与其他命令类似，应谨慎使用。

- POSIX 字符类。例如，`[:upper:]`。

在大多数情况下，两个字符集的长度应该是相同的；然而，第一个集合可以比第二个更大，特别是当我们想要将多个字符转换为单个字符时。

```
me@linuxbox~$ echo "lowercase letters" | tr [:lower:] A
AAAAAAAAAA
```

除了转译外，`tr` 还允许直接从流中删除字符。在本章之前的阶段，我们讨论了将 MS-DOS 文件转换为 Unix 风格文本的问题。要执行此转换，需要从每行的末尾删除回车字符。可以通过 `tr` 执行：

```
tr -d '\r' < dos_file > unix_file
```

其中 `dos_file` 被转换，`unix_file` 是结果。该命令使用转义序列 `\r` 表示回车字符。要查看 `tr` 支持的所有序列和字符类的完整列表，请尝试：

```
me@linuxbox~$ tr --help
```

`tr` 还可以执行另一个技巧。使用 `-s` 选项，`tr` 可以“压缩”（删除）重复的字符。

```
me@linuxbox~$ echo "aaabbccc" | tr -s ab
abcabc
```

在这里有一个包含重复字符的字符串。通过指定集合 `ab` 给 `tr`，我们消除了集合中字母的重复实例，而让集合之外的字符（`c`）保持不变。注意，重复的字符必须是相邻的。如果不是相邻，压缩将不起作用。

```
me@linuxbox~$ echo "abcabc" | tr -s ab
ababcabc
```

# ROT13: 并不秘密的解密环

`tr` 命令的一种用法是对文本进行 ROT13 编码。ROT13 是一种基于简单替换密码的简易加密类型。称 ROT13 为加密过于客气了，“文本混淆”更为准确。它有时用于文本以隐藏潜在的攻击性内容。该方法简单地将每个字符在字母表中移动 13 位。因为这是 26 个字符中的半程，所以对文本再次执行一次该算法即可将其恢复到原始形式。使用以下命令通过 `tr` 执行此编码：

```
echo "secret text" | tr a-ZA-Z n-za-MN-ZA-M
frprg grkg
```

再次执行相同的步骤将得到以下翻译：

```
echo "frprg grkg" | tr a-ZA-Z n-za-MN-ZA-M
secret text
```

许多电子邮件程序和 Usenet 新闻阅读器支持 ROT13 编码。维基百科上关于该主题的良好文章，地址为 http://en.wikipedia.org/wiki/ROT13。

# sed—用于过滤和转换文本的流编辑器

这个名字是 stream editor（流编辑器）的缩写。它对文本流（可以是指定文件的集或标准输入）进行文本编辑。`sed` 是一个强大且相当复杂的程序（甚至有专门关于它的书籍），因此我们在这里不会介绍它。

通常，`sed` 的工作原理是接收一个的编辑命令（在命令行中）或包含多个命令的脚本文件路径，并对文本流中的每一行执行这些命令。这里是一个简单的输入操作示例：

```
$me@linuxbox~$ echo "front" | sed 's/front/back/'
back
```

在此处，我们使用 `echo` 产生了一个单词文本流，并通过管道传递给 `sed`，`sed` 随后对文本执行 `s/front/back/` 指并产生输出。我们也可以识别出此命令类似于 vi 中的“替换”（查找并替换）命令。

在 `sed` 中，单个字母表示命令。在上例中，替换命令由字母 `s` 表示，后面跟着查找和替换字符串，并用斜杠字符 `/` 作为分隔符。分隔符的选择是任意的。按照惯例，通常使用斜杠，但 `sed` 会接受紧随命令后的任何字符作为分隔符。我们可以通过这种方式执行相同的命令：

```
[melinuxbox]$ echo "front" | sed 's_front_back_'
```

通过在命令后立即使用下划线字符，它变成了分隔符。正如我们将看到的，设置分隔符的能力可以使命令更具可读性。`sed` 中的大多数命令前面都可以跟一个地址，该地址指定输入流中的哪些行将进行编辑。如果省略地址，则对输入流中的每一行进行编辑。地址最简单的形式是行号。我们可以在我们的中加上 1：

```
[melinuxbox ~]$ echo "front" | sed '1s/front/back/'
```

在命令中添加地址 `1` 会导致替换操作在我们单行输入流的第一行上执行。如果我们指定另一个数字，`sed` 将不会执行编辑，因为流中没有第 2 行。

```
[melinuxbox ~]$ echo "front" | sed '2s/front/back/'
```

地址可以用许多方式表示。表 20-7 列出了常见的表示法。

## 表 20-7: sed 地址表示法

| 地址 |  |
| :--- | :--- |
| n | 行号，其中 n 是正整数。 |
| $ | 最后一行。 |
| /regexp/ | 匹配 POSIX 基础正则表达式的行。注意正则表达式由斜杠字符分隔。可选地，可以使用备选字符分隔正则表达式，通过指定 `\regexpc` 表达式，其中 c 是备选字符。 |
| addr1,addr2 | 从 addr1 到 addr2 的行范围（包含边界）。地址可以是前面列出的单地址的任何一个。 |
| first*step | 匹配由数字 first 表示的行，然后按照步长 step 匹配随后的每一行。例如，1~2 指每个奇数行，5~5 指第五行以及之后每隔 5 行的一行。 |
| addr1,+n | 匹配 addr1 及其后续 n 行。 |
| addr! | 匹配除 addr 之外的所有行，addr 可以是前面列出的任何形式。 |

我们将使用本章前面的 `distros.txt` 文件来演示不同类型的地址。首先，这是一组行号范围：

| me@linux ~]$ sed -n '1,5p' distros.txt |
| :--- | :--- |
| SUSE | 10.2 | 12/07/2006 |
| Fedora | 10 | 11/25/2006 |
| SUSE | 11.0 | 06/19/2008 |
| Ubuntu | 8.04 | 04/24/2008 |
| Fedora | 8 | 11/08/2007 |

在这个示例中，我们打印了从第 1 行到第 5 行的行范围。为了实现这一点，我们使用了 `p` 命令，它使匹配到的行被打印。为了使其生效，我们必须包含 `-n` 选项（“不自动打印”）以选择默认不打印每一行。接下来，我们将尝试正则表达式：

| me@linux ~]$ sed -n '/SUSE/p' distros.txt |
| :--- | :--- |
| SUSE | 10.2 | 12/07/2006 |
| SUSE | 11.0 | 06/19/2008 |
| SUSE | 10.3 | 10/04/2007 |

通过包含斜杠分隔的正则表达式 `/SUSE/`，我们能够像 `grep` 一样隔离出这些行。接下来，我们将通过向地址添加感叹号 (`!`) 来尝试否定：

| me@linux ~]$ sed -n '/SUSE/lp' distros.txt |
| :--- | :--- |
| Fedora | 10 | 11/25/2008 |
| Ubuntu | 8.04 | 04/24/2008 |
| Fedora | 8 | 11/08/2007 |
| Ubuntu | 6.10 | 10/26/2006 |
| Fedora | 7 | 05/31/2007 |
| Ubuntu | 7.10 | 10/18/2007 |
| Ubuntu | 7.04 | 04/19/2007 |
| Fedora | 6 | 10/24/2006 |
| Fedora | 9 | 05/13/2008 |
| Ubuntu | 6.06 | 06/01/2006 |
| Ubuntu | 8.10 | 10/30/2008 |
| Fedora | 5 | 03/20/2006 |

在这里我们看到了预期结果：文件中所有被正则表达式匹配的行。到目前为止我们看了两个 sed 命令：`s` 和 `p`。表 20-8 提供了更完整的列表。

## 表 20-8: sed 命令

| 命令 |  |
| :--- | :--- |
| = | 输出行号。 |
| a | 在当前行之后追加文本。 |
| d | 删除当前行。 |
| i | 在当前行之前插入文本。 |
| p | 打印当前行。默认情况下，sed 打印每一行以及匹配指定地址的行。可以通过 `-n` 选项覆盖默认行为。 |
| q | 退出 sed 不再处理后续行。如果没有指定 `-n` 选项，则输出当前行。 |
