
# AWS 自动扩展与负载均衡

使用 AWS 自动扩展组根据负载动态调整实例数量。

## CLI 命令

### 创建自动扩展组

```bash
aws autoscaling create-auto-scaling-group --auto-scaling-group-name rocky-asg --min-size 1 --max-size 5
```

### 创建弹性负载均衡器（ELB）

```bash
aws elb create-load-balancer --load-balancer-name my-load-balancer --listeners \
"Protocol=HTTP,LoadBalancerPort=80,InstanceProtocol=HTTP,InstancePort=80"
```

## 验证

- `elb create-load-balancer`：创建 ELB 的正确方法。
- `--listeners`：配置 HTTP 转发。

## 最佳实践

- 列出所有 ELB：`aws elb describe-load-balancers`

## 部署在 AWS EC2 上

- 选择合适的实例类型（`t3.micro`、`m5.large` 等）。
- 使用 AWS Marketplace 中可用的 Rocky Linux AMI。
- 针对 SSH 和 HTTP/HTTPS 访问配置安全组。

# 高可用性（HA）

高可用（HA）是指系统在发生故障时仍能保持运行的能力。

## HA 的概念

- 冗余：拥有备份系统。
- 容错性：即使硬件或软件出现问题也能继续运行。
- 故障转移：自动切换到备用系统。

## 高可用组件

- 负载均衡：在多个服务器之间分发流量。
- 自动扩展：根据需求调整实例数量。
- 多可用区部署：确保跨区域的冗余。

## 负载均衡技术

- HAProxy：广泛使用的开源负载均衡器。
- 弹性负载均衡器 (ELB)：在健康实例之间分配流量。
- 应用负载均衡器 (ALB)：用于 HTTP/HTTPS。
- 网络负载均衡器 (NLB)：用于 TCP。

## 故障转移机制

- Pacemaker：管理资源并检测故障。
- Corosync：提供集群通信。
- Keepalived：使用虚拟路由器冗余协议 (VRRP)。

## 数据复制

- DRBD：块级复制。
- GlusterFS：分布式文件系统。

## 在 Rocky Linux 上实现 HA

- 安装所需包：`sudo dnf install -y pacemaker corosync pcs`
- 启用并启动集群：`sudo systemctl enable --now pcs`
- 节点身份验证：`sudo pcs auth node1 node2 -u hacluster -p password`
- 创建并启动集群：

```bash
sudo pcs setup --namecluster node1 node2
sudo pcs start --all
```

## 配置 HAProxy 进行负载均衡

- 安装 HAProxy：`sudo dnf install -y haproxy`
- 配置 `/etc/haproxy/haproxy.cfg`：

```
frontend http_front
bind *:80
default_backend web_servers
backend web_servers
balance roundrobin
server web1 192.168.1.10:80 check
server web2 192.168.1.11:80 check
```

- 重启 HAProxy：`sudo systemctl restart haproxy`

## 故障转移测试场景

- 关闭一个节点，检查服务是否在第二个节点上继续运行。
- 使用 `pcs status` 监控集群状态。

# 在 Rocky Linux 中使用负载均衡扩展应用程序

负载均衡涉及将入站流量分布到多个服务器上，以防止单台服务器过载。这可以提高性能、可靠性和可用性。

## 负载均衡的优势

- 性能优化：均匀分配流量以防止单个节点过载。
- 高可用性：确保即使一台服务器故障，应用程序也能保持运行。
- 可扩展性：允许通过添加更多后端服务器来扩展应用程序。

## 负载均衡器类型

- 第 4 层（传输层）：基于 IP 地址和端口路由流量。
- 第 7 层（应用层）：基于应用级数据（例如 HTTP Header、Cookie）路由流量。

## Rocky Linux 中的负载均衡技术

Rocky Linux 支持多种负载均衡技术，以高效地分配网络流量并增强系统可用性。HAProxy 是一个广泛使用的开源解决方案，为 HTTP、TCP 和其他协议提供高性能负载均衡。Nginx 是另一个强大的选项，提供反向代理和负载均衡功能，以及高级的缓存功能。此外，Keepalived 可以通过管理虚拟 IP 故障转移来实现高可用性。这些技术有助于确保企业环境中的优化资源利用率、容错性和可扩展性。

### HAProxy（高可用代理）

- 开源、高性能的 TCP/HTTP 负载均衡器。
- 提供健康检查、SSL 终止和故障转移机制。

### NGINX 负载均衡器

- 作为具有负载均衡功能的反向代理。
- 支持第 7 层负载均衡、缓存和安全控制。

### Keepalived

- 实现虚拟路由器冗余协议（VRRP）以实现高可用性。
- 确保活动和备用负载均衡器之间的故障转移。

### AWS 弹性负载均衡器 (ELB)

- 基于云的托管负载均衡器。
- 支持多个可用区以实现冗余。

## 实验：部署 HAProxy 负载均衡器

场景：使用 HAProxy 在两台 Rocky Linux Web 服务器之间进行负载均衡。

**步骤：**

步骤 1：安装 HAProxy：`sudo dnf install -y haproxy`

步骤 2：配置 HAProxy (`/etc/haproxy/haproxy.cfg`)：

```
frontend http_front
bind *:80
default_backend web_servers
backend web_servers
balance roundrobin
server web1 192.168.1.10:80 check
server web2 192.168.1.11:80 check
```

步骤 3：重启 HAProxy：`sudo systemctl restart haproxy`

步骤 4：测试负载均衡：
- 在浏览器中访问 HAProxy 的 IP。
- 刷新页面以查看由不同后端服务器提供的服务。

## 实际实验：配置 AWS 弹性负载均衡器 (ELB)

场景：使用 AWS ELB 扩展基于 Rocky Linux 的 Web 应用。

步骤：

1. 启动两个 EC2 实例（Rocky Linux）并安装 Web 服务器：
   - `sudo dnf install -y httpd`
   - `sudo systemctl enable --now httpd`

2. 创建应用负载均衡器 (ALB)：
   - 导航至 AWS EC2 Dashboard > Load Balancers。
   - 选择“Application Load Balancer”，并为 HTTP/HTTPS 配置监听器。
   - 跨不同的可用区挂载 EC2 实例。

3. 测试负载均衡：
   - 在浏览器中访问 ALB 的 DNS 名称。
   - 观察跨实例的流量分布。
