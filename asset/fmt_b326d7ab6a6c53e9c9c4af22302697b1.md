# 第 6 章 函数与函数式编程

与列表推导式不同，生成器表达式不会真正创建列表，也不会立即求值括号内的表达式。相反，它创建一个生成器对象，根据迭代需要来产生值。这里有一个示例：

```python
>>> a = [1, 2, 3, 4]
>>> b = (10*i for i in a)
>>> b
<generator object at 0x590a8>
>>> next(b)
10
>>> next(b)
20
...
```

列表推导式和生成器表达式之间的区别重要且微妙。在列表推导式中，Python 实际上会创建一个包含结果数据的列表。而在生成器表达式中，Python 创建的仅知道如何按需产生数据的生成器。在某些应用程序中，这可以极大提高性能和内存利用。这里有一个示例：

```python
# 读取文件
# 打开文件
f = open("data.txt") # 读取行，去除边缘空格
lines = (t.strip() for t in f) # 去除末尾/开头空格
comments = (t for t in lines if t[0] == '#') # 所有注释
for c in comments:
    print(c)
```

在这个示例中，提取并去除空格的生成器表达式并没有实际上将整个文件读取到内存中。提取内存的表达式也是如此。相反，行是在程序进入随后的 `for` 循环时才被实际读取的。在迭代过程中，文件的行按需产生并进行相应的过滤。事实上，在此过程中，整个文件都不会被加载到内存中。对于从 GB 级的源文件中提取注释，这是一个非常高效的方法。

与列表推导式不同，生成器表达式不会创建一个像序列一样运行的对象。它不支持索引，且任何的常规操作（如 `for`、`append()`）都无法工作。然而，生成器表达式可以使用内置的 `list()` 函数转换为列表：

```python
result = list(comments)
```

## 声明式编程

列表推导式和生成器表达式与声明式语言的操作紧密相关。事实上，这些特征的起源某种程度上源于数学理论中的思想。例如，当你写出类似 `[x*2 for x in a if x > 0]` 的语句时，它与设置一个集合为 `{x^2 | x in a, x > 0}` 相似。

与其手动编写程序来迭代数据，你可以使用这些声明式特征将程序结构化为一系列计算，这些计算一次性处理所有数据。例如，假设你有一个 `portfolio.txt` 文件，包含如下股票组合数据：

```
AA 100 32.20
IBM 50 91.10
CAT 150 83.44
MSFT 200 51.23
GE 95 40.37
MSFT 50 65.10
IBM 100 70.44
```

这是一个声明式风格的程序，通过求加第二列乘以第三列来计算总和：

```python
lines = open('portfolio.txt')
fields = (line.split() for line in lines)
print(sum(float(f[1]) * float(f[2]) for f in fields))
```

在这个程序中，我们并不真正关心逐行遍历文件的机制。这种方法不仅导致代码非常紧凑，而且运行速度通常比比这个更传统的版本更快：

```python
total = 0
for line in open('portfolio.txt'):
    fields = line.split()
    total += float(fields[1]) * float(fields[2])
```

声明式风格与程序员在 UNIX shell 中可能偏好的操作某种联系。例如，上一个使用生成器表达式的示例与下面的 `awk` 命令类似：

```bash
% awk '{ total += $2 * $3 } END { print total }' portfolio.txt
```

列表推导式和生成器表达式的声明式样式也可以用于模拟 SQL select 语句的行为，这通常用于处理数据库。例如，考虑以下这些已读取到字典列表中的数据示例：

```python
fields = (line.split() for line in open('portfolio.txt'))
portfolio = [{'name': f[0], 'shares': int(f[1]), 'price': float(f[2])} for f in fields]
```

```python
# 一些查询
msft = [s for s in portfolio if s['name'] == 'MSFT']
large_holdings = [s for s in portfolio if s['shares']*s['price'] >= 10000]
```

事实上，如果你正在使用与数据库访问相关的模块（参见第 17 章），你可以同时使用列表推导式和数据库查询。例如：

```python
sum(shares['cost'] for shares, cost in
    cursor.execute('select shares, cost from portfolio'))
    if shares['cost'] >= 10000
```

## lambda 操作符

可以使用 `lambda` 语句创建表达式形式的匿名函数：

```python
lambda args : expression
```

`args` 是用逗号分隔的参数列表，`expression` 是涉及这些参数的表达式。这里有一个示例：

```python
a = lambda x,y : x+y
r = (2,3)      # 获取 5
```

用 `lambda` 定义的代码必须是一个有效的表达式。`lambda` 中不允许包含多个语句。然而，`lambda` 通常用于创建短生命周期函数。

## 递归

递归函数很容易定义。例如：

```python
def factorial(n):
    if n <= 1: return 1
    else: return n * factorial(n-1)
```

然而，注意递归深度是有限制的。`sys.recursionlimit()` 返回最大深度，`sys.setrecursionlimit()` 可用于增加该值。当超过深度时，会抛出 `RuntimeError` 异常。Python 不执行 Scheme 等函数式语言中常见的尾递归优化。例如，这段代码打印嵌套列表中的项：

```python
def flatten(lists):
    for s in lists:
        if isinstance(s, list):
            flatten(s)
        else:
            print(s)
```

```python
items = [[1,2,3],[4,5,[6]],[7,8,9]]
flatten(items) # 输出 1 2 3 4 5 6 7 8 9
```

然而，如果你将 print 操作改为 yield，它将不再工作。这是因为对 `flatten()` 的递归调用创建了一个生成器而没有对其进行迭代。这里有一个有效的递归版本：

```python
def flatten(lists):
  for s in lists:
    if isinstance(s, list):
      for item in flatten(s):
        yield item
    else:
      yield item
```

在混合递归函数和装饰器时也需要小心。如果装饰器应用到递归函数上，所有的内部调用现在都会路由到装饰后的版本。例如：

```python
@locked
def factorial(n):
  if n <= 1: return 1
  else: return n * factorial(n-1) # 调用 factorial 的包装版本
```

如果装饰器的目的是为了某种系统管理（如同步或锁定），可能最好避免递归。

## 文档字符串

一种惯例是函数的第一条语句是描述其用法的文档字符串。例如：

```python
def factorial(n):
  """计算 n 的阶乘。例如：
  >>> factorial(6)
  120
  >>>
  """
  if n <= 1: return 1
  else: return n*factorial(n-1)
```
