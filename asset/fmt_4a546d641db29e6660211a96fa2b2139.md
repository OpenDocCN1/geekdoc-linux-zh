`kill` 的内置版本，用于为由 `%jobid` 标识的进程提供 `kill` 命令的功能。

`stop %jobid...`

停止后台作业（作业）的执行。

`suspend`

停止当前 shell 的执行（但如果是登录 shell 则不停止）。

`wait [%jobid...]`

等待由 `%jobid` 指定后台进程并报告其终止状态。如果省略 `%jobid`，`wait` 的行为如第 1223 页“特殊命令（Special Commands）”部分所述。

> 注意 — 由于 shell 在同一个进程组中同时实现前台和后台作业，它们都会接收相同的信号，这可能导致意外行为。因此，建议你使用其他的作业控制 shell，特别是在交互式环境中。

## 仅限 jsh

如果你作为 `jsh` 调用 `shell` 并在存在已停止作业时尝试退出，`shell` 会发出一个警告。

有已停止的作业。

这是唯一的消息。如果你再次尝试退出且仍有停止的作业，作业将收到内核的 `SIGHUP` 信号且 `shell` 将退出。

## Bourne Shell 特殊命令 (Bourne Shell Special Commands)

这些命令现在允许输入/输出重定向。文件描述符是默认输出位置。启用作业控制后，环境环境中添加了额外的特殊命令。

除了这些内置命令词外，`sh` 还使用：

- 执行无操作。返回 0 退出码。

- `filename` 从文件名读取并执行命令。使用 `PATH` 指定的搜索路径查找文件名所在的目录。

## C Shell

内置命令在 C shell 内执行。如果内置命令作为管道中最后一个以外的任何部分，它将在子 shell 中执行。除了这些内置命令词外，`csh` 还使用：

- 解释此命令执行无操作。

## Korn Shell 特殊命令 (Korn Shell Special Commands)

允许输入/输出重定向。另有说明，退出状态写入文件描述符 1，且在没有语法错误时为 0。以一个或两个星号 (`*`) 开头的命令按以下方式特殊处理。

- 命令之前的变量赋值列表在命令完成后仍然有效。

- I/O 重定向在变量赋值后进行处理。

- 错误会中止包含它们的脚本。

- 以 `**` 开头的命令后符合变量赋值格式的单词将按照变量赋值相同的规则扩展。这意味着波浪替换在等号之后进行，且不单词拆分和文件名生成。

除了这些内置保留命令外，`ksh` 还使用：

* `[arg...]`

仅展开参数。

* `file [arg...]`

读取整个文件，然后在 shell 环境中执行命令。使用 `PATH` 指定的搜索路径来查找包含该文件的目录。如果你指定了任何 `arg` 参数，它们将原样地变为位置参数。否则，保持位置参数不变。最后执行的命令（即循环终止测试）的退出状态。
