
在这里我们看到了目录列表。如果它位于我们列表中的某个目录里，那么问题就解决了。注意列表中的第一个目录 `/home/me/bin`。绝大多数 Linux 发行版配置了 `PATH` 变量，包含用户目录下的 `bin` 目录，以允许用户执行自己的程序。因此，如果我们创建一个 `bin` 目录并将脚本放在其中，它就能像其他程序一样开始工作。

```bash
me@linuxbox ~]$ mkdir bin
me@linuxbox ~]$ mv hello_world bin
me@linuxbox ~]$ hello_world
Hello world!
```

它确实运行了。如果 `PATH` 变量不包含该目录，我们可以通过在 `.bashrc` 文件中包含此行来轻松添加它：

```bash
export PATH=/bin:$PATH
```

做出此更改后，它将在每个新的终端会话中生效。要将更改应用于当前终端会话，我们必须让 shell 重新读取 `.bashrc` 文件。这可以通过“源”（sourcing）它来实现。

```bash
me@linuxbox ~]$ . .bashrc
```

点 (`.`) 是 `source` 命令的同义词，这是一个 shell 内置命令，用于读取指定的 shell 命令文件并将其视为来自键盘输入。

Ubuntu（以及大多数基于 Debian 的发行版）在执行用户的 `.bashrc` 文件时，如果 `~/bin` 目录存在，会自动将该目录添加到 `PATH` 变量中。因此，在 Ubuntu 系统上，如果我们创建了 `~/bin` 目录并注销再登录，一切都能正常工作。

## 脚本的良好位置

`~/bin` 目录是存放个人使用脚本的好地方。如果我们使用系统上所有用户都可以使用的脚本，传统位置是 `/usr/local/bin`。供系统管理员使用的脚本通常位于 `/usr/local/sbin`。在大多数情况下，本地软件（无论是脚本还是编译后的程序）应该放在 `/usr/local` 层次结构中，而不是 `/bin` 或 `/usr/bin`。这些目录由 Linux 文件系统层次结构标准指定，仅包含由 Linux 发行版提供和维护的文件。

## 更多格式化技巧

认真编写脚本的一个关键目标是易于维护；即作者或他人可以很方便地修改脚本以适应变化的需求。让脚本变得易于阅读和理解是促进易于维护的一种方法。

## 长选项名称

我们学习过的许多命令都同时具有短选项名称和长选项名称。例如，`ls` 命令有许多选项可以用短形式或长形式表示。例如，以下命令：

```bash
[me@linuxbox ~$] ls -ad
```

等同于此内容：

```bash
[me@linuxbox ~$] ls --all directory
```

为了减少输入量，在命令行中输入选项时倾向于使用短选项，但在编写脚本时，长选项可以提供更好的可读性。

## 缩进与换行延续

在编写长命令时，通过将命令分散到几行可以增强其可读性。在第 17 章中，我们看过了 `find` 命令的一个特别特别长的例子。

```bash
[me@linuxbox ~$] find playground \-type f -not -perm 0600 -exec \
chmod 0600 {} \; \ -or \-type d -not -perm 0700 -exec \
chmod 0700 {} \; \;
```

显然，这个命令初眼看上去可能有点难懂。在脚本中，如果按这样写，这个命令可能会更容易理解：

```bash
find playground \
  -type f \
  -not -perm 0600 \
  -exec chmod 0600 {} \; \ \
  -or \
  -type d \
  -not -perm 0700 \
  -exec chmod 0700 {} \; \
  \)
```

通过使用换行延续（反斜杠换行符序列）和缩进，这个复杂命令的逻辑向读者描述得更加清晰了。这种技术在命令行中也有效，尽管很少使用，因为输入和编辑起来很笨拙。脚本和命令行的一个区别是，脚本可以使用制表符字符来实现缩进，而命令行则不能，因为制表符被用于激活自动补全。

## 为脚本编写配置 VIM

`vim` 文本有许多、许多配置设置。有几个常用选项可以方便脚本编写。
开启语法高亮：

```vim
:syntax on
```

使用此设置后，查看脚本时，语法的不同元素将以不同的颜色显示。这有助于识别某些类型的编程错误。它看起来也很酷。注意，要使此功能生效，你必须安装完整版本的 `vim`，并且你正在编辑的文件必须有一个指示文件为脚本的 shebang。如果你在执行之前的命令时遇到困难，尝试 `:set syntax=sh indent`。
开启高亮搜索结果选项：

```vim
:set hlsearch
```

假设我们搜索 `echo`。开启此选项后，该单词的每个实例都会高亮。
设置制表符占据的列数：

```vim
:set tabindex=4
```

默认是八列。将值设置为 4。
默认开启缩进：

```vim
:set autoindent
```

这会导致 `vim` 对新行进行缩进。

## 总结

在本章中，我们学习了脚本是如何编写的，并看到了如何使用各种技术来提高可读性。我们程序的第一阶段能够输出一个最小的 HTML 文档。在未来的章节中，我们将构建一个更复杂的项目。

到目前为止一切顺利。

在编写程序时，力求简单清晰始终是一个好主意。当程序易于阅读和理解时，维护会变得更容易，更不用说通过减少输入量来让程序更容易编写。我们当前版本的程序运行良好，但可以更简单。我们实际上可以将所有的 `echo` 命令合并为一个，这无疑会更容易向程序的输出中添加更多行，让我们将程序更改为：

```bash
#!/bin/bash
# 输出系统信息页的程序
echo "html"
<head>
  <title>Page Title</title>
</head>
<body>
  Page body.
</body>
</html>
```

引号字符串可能包含换行符，因此包含多行文本。壳（shell）会继续读取文本，直到遇到引号为止。这在命令行中同样有效：

```bash
[me@linuxbox ~$] echo "html"
<head>
  <title>Page Title</title>
</head>
<body>
  Page body.
</body>
</html>"
```

`>` 字符是 `PS2` 变量中的 shell 提示符。每当我们输入 shell 中多行语句时，它就会出现。这个功能目前看起来有点晦涩，但稍后当我们涵盖多行编程语句时，它会被证明是非常实用的。

## 第二阶段：添加一些数据

现在我们的程序可以生成一个最小文档了，让我们在报告中放入一些数据。为了做到这一点，我们将进行以下更改：

```bash
#!/bin/bash
# 输出系统信息页的程序
echo "html"
<head>
<title>System Information Report</title>
<body>
<h1>System Information Report</h1>
</body>
</html>
```

我们在报告的正体部分添加了一个页面标题和一个主标题。

## 变量与常量

然而，我们的脚本存在一个问题。注意看 `System Information Report` 字符串是如何重复的？在我们微型脚本中，它非常长，而且我们有多个该字符串的实例。如果我们想将标题更改为其他内容，必须在多个地方进行修改，这可能是一大量工作。如果我们能安排脚本，让该字符串只出现一次而不是多次出现呢？这将使未来的维护变得容易得多。我们可以这样做：

```bash
#!/bin/bash
# 输出系统信息页的程序

title="System Information Report"

echo "<html>
<head>
<title>$title</title>
</head>
<body>
<h1>$title</h1>
</body>
</html>"
```

通过创建一个名为 `title` 的变量并为其赋值值 `System Information Report`，我们可以利用参数扩展并将字符串放置在多个位置。

那么，我们如何创建变量呢？简单，我们只需使用它即可。当 shell 遇到变量时，它会自动创建它。这与许多编程语言不同，在那些语言中，变量在使用之前必须显式地声明或定义。shell 在这方面非常宽松，可能会导致一些问题。例如，考虑以下在命令行中执行的场景：

```bash
[melinuxbox ~]$foo=yes
[melinuxbox ~]$echo foo
yes
[melinuxbox ~]$
```
