```bash
bsh -r /bin/rsh
```

使用 `set` 更改选项：一旦 shell 位于提示符 `$`，她可以通过设置或取消 shell 选项来修改她的环境。开启使用 `-`（连字符）和选项字母。关闭使用 `+`（加号）和选项字母。

## 用户的 Shell 启动文件：`.profile`

每个 Bourne 用户的主目录下都有名为 `.profile` 的文件。系统管理员或用户（如果获得权限）可以在此处修改其 shell 环境。要向现有执行路径添加内容，只需将以下行加入 `.profile` 即可：

```bash
PATH=$PATH:/sql/bin ; export PATH
```

有了这个 `.profile`，当用户使用时，会在 `/bin` 目录搜索命令和可执行程序。

## Shell 环境变量

一旦进入提示符，就有许多带有值的环境变量。以下是大多数 UNIX 系统中存在的变量列表。

| CDPATH | 包含 `cd` 命令的搜索路径。 |
| HOME | 包含用户的家目录。 |
| IFS | 内部字段分隔符，通常为空格、制表符和换行符。 |
| MAIL | 特殊文件（邮箱）的路径，用于 UNIX 电子邮件。 |
| PATH | 包含命令和可执行文件的搜索路径。 |
| PS1 | 主提示符字符串，默认是 `$`。 |
| PS2 | 次提示符字符串，默认是 `>`。 |
| TERM | 正在终端类型。 |

如果未设置限制模式，可以修改这些变量以适应用户的各种需求。例如，要更改提示符，请输入以下内容。

```bash
$PS1="your wish"; ; export PS1
```

现在，提示符不再是 `$` 而是显示你的愿望：要还原，请输入以下内容。

```bash
$PS1="\$"; ; export PS1
```

要显示任何给定变量的值，请使用 `echo` 命令、空格和 `$` 符号后跟变量名。

```bash
$echo MAIL
/usr/spool/mail/(user id)
```

修改环境变量时应小心。对 shell 环境的错误修改可能导致命令无法运行或运行异常。如果发生这种情况，建议用户注销并重新登录。对这些变量的熟悉将让你对 shell 环境有更多的控制。有一组由特殊字符标识的环境变量，它们将在本章的下一节详细介绍。

# 特殊字符及其含义

Bourne shell 使用许多非字母数字字符来定义特定的 shell 特性。这些特性大部分分为四大类：变量名、文件名生成、数据/程序控制以及队列/转义字符控制。虽然初看起来看起来可能很神秘，但它让 shell 能够用极少的代码完成功能。

## Shell 变量名的特殊字符

某些特殊字符表示由 shell 自动设置的特殊 shell 变量。对于所有变量，前面都有一个 `$`。以下是这些变量的列表。

| 变量 | 说明 |
| :--- | :--- |
| `$#` | 给命令 shell 的参数数量。 |
| `$-` | 调用或使用 `set` 时提供的 shell 标志。 |
| `$?` | 上一个命令返回的状态值。 |
| `$$` | 当前 shell 的进程号。 |
| `$!` | 上一个子进程的进程号。 |
| `$@` | 所有单独用双引号括起的参数。 |
| `$*` | 所有用双引号括起的参数。 |
| `$n` | 位置参数值，其中 'n' 是位置。 |
| `$0` | 当前 shell 的名称 |

要显示提供给 shell 的参数数量，请输入以下内容。

```bash
$echo $$
0
```

这表示在调用 shell 时没有提供任何参数。这些变量在编写 shell 脚本时特别有用，脚本将在本章稍后的“位置变量”或“Shell 参数”小节中进行描述。

## 文件名生成的特殊字符

Bourne shell 使用特殊字符或元字符来表示具有现有文件名的模式。这些是那些字符：

| 字符 | same |
| :--- | :--- |
| `*` | 匹配任何字符串或字符串部分 |
| `?` | 匹配任何单个字符 |
| `[-!]` | 范围、列表或不匹配 |

要匹配以 f 开头的文件，请输入以下内容：

```bash
$ls f*
```

要匹配以 invoice 为前缀、中间有任意字符、并以 dat 为后缀的文件，请输入以下内容：

```bash
$ls invoice?dat
```

要匹配以 a 到 e 开头的文件，请输入以下内容：

```bash
$ls [a-e]*
```

要匹配以 a、c 和 e 开头的文件，请输入以下内容：

```bash
$ls [a,c,e]*
```

要排除字母 m 的匹配，请输入以下内容：

```bash
$ls [!m]*
```

> 注意：要使用逻辑否定符号 `!`，必须是左括号 `[` 之后的第一个字符。

## 数据/程序控制的特殊字符

Bourne shell 使用特殊字符进行数据流和执行控制。通过这些字符，用户可以将正常的屏幕输出重定向到文件或设备或作为另一个命令的输入。这些字符还允许用户从命令行顺序或独立运行多个命令。以下是这些字符的列表。

| 字符 | same |
| :--- | :--- |
| `>(file)` | 将输出重定向到文件。 |
| `>>(file)` | 将输出重定向并追加到文件末尾。 |
| `<(file)` | 从文件重定向标准输入。 |
| `;` | 分隔命令。 |
| `|` | 将输出管道到标准输入。 |
| `&` | 置于命令末尾并在后台执行。 |
| `'` | 命令替换，将输出作为参数引导。 |

使用这些字符有很多方法，将在本章稍后的“输入简单命令”小节中详细说明。

# 引用和转义的特殊字符

shell 使用单引号 `'` 和双引号 `"` 来封装特殊字符或由空格分隔的字符，以产生单个字符串。单引号和双引号的主要区别在于，使用双引号时，变量和命令替换以及转义字符是激活的。

```bash
echo "$HOME $PATH"
/home/farrawa /bin/etc:/usr/bin:
```

此示例结合了 `$HOME` 和 `$PATH` 的值以生成单个字符串。

```bash
$echo '$HOME $PATH'
$HOME $PATH
```

此示例仅打印括在内的字符串。shell 转义字符是反斜杠 `\`，它用于抵消字符的特殊含义或 shell 功能。

```bash
$echo \$HOME $PATH
$HOME /bin/etc:/usr/bin:
```

在此示例中，只有 `$HOME` 中的 `$` 被视为文本，而 shell 的变量含义被抵消了，`$PATH` 仍然被解释为变量。

# Shell 如何解释命令

大多数人对 Bourne shell 的首次接触是作为交互式 shell。在登录系统并看到系统管理员的任何消息后，用户会看到 shell 提示符。对于超级用户等其他人来说，默认提示符是美元符号 `($)`。当你看到美元符号 `($)` 时，交互式 shell 准备好接受一行输入，并对其进行解释。

shell 将一行输入视为以换行符结束的字符，换行符通常是按下键盘上的 Enter 键的结果。输入行的长度与你的计算机显示器的宽度无关。当 shell 看到换行符时，它开始解释该行。

# 输入简单命令

向 shell 输入的最常见形式是简单命令，其中命令名后面跟着参数。在这个示例中

```bash
$ ls file1 file2 file3
```

`ls` 是命令，`file1`、`file2` 和 `file3` 是参数。命令是任何 UNIX 可执行文件。许多 UNIX 命令采用以下格式：

```bash
$ command -options filenames
```

虽然 shell 不解释命令的参数，但 shell 对输入行进行了一些解释。

## 变量数据的替换

本章之前的示例在命令行使用了变量。每当 shell（未引用或转义）遇到美元符号 `$`，它会将后面的文本解释为变量名。无论变量是环境还是用户定义的，存储在变量中的数据都会被替换。例如，命令

```bash
$ ls $HOME
```

列出用户家目录的内容，无论当前工作目录在哪里。`HOME` 是一个环境变量。变量将在本章的下一节详细讨论。与文件名替换一样，`ls` 只显示替换的结果，而不是变量名。

你可以在命令行的任何地方替换变量，包括命令名本身。例如，

```bash
$ dir=ls
$ $dir *
file1
lela
form
```

此示例表明 shell 在确定执行哪些命令之前会进行替换。

## 输入和输出的重定向

当 shell 接收到重定向符号 `<` 或输出 `>` 时，后面的参数控制命令的执行。当命令打开的输入或输出文件已重定向时，输入或输出将被重定向到

```bash
$ ls -l >dirfile
```

在此示例中，传递给 `ls` 的唯一参数是选项 `-l`。文件名 `dirfile` 被发送到控制 `ls` 执行的子 shell。要将输出追加到现有文件，使用 `(>>)`。

```bash
$ ls -l /tmp >> dirfile
```

此示例获取 `/tmp` 目录的文件列表并将其追加到本地文件 `dirfile` 的末尾。

## 在一行中输入多个命令

通常，shell 将命令的第一个单词解释为名称并将输入的其余部分作为该命令的参数。特殊字符--分号,--向 shell 表明之前的命令文本已结束，后面是一个新命令。例如，命令行

```
$ who -H; df -v; ps -e
```

等同于

```
$ who -H
$ df -v
$ ps -e
```

然而，在后的情况下，每个命令的结果出现在各个命令输入行之间。当你使用分号在同一行分隔命令时，这些命令将按顺序执行。shell 会等待一个命令执行完成后再执行下一个命令。此外，如果发生错误，shell 将在错误发生的位置停止执行该行命令。

# 使用管道链接多个命令

Bourne shell 最强大的功能之一是它能够获取一个命令的输出，并将其作为另一个命令的标准输入。这是通过管道符号 `|` 实现的。当 shell 看到管道时，它会执行前一个命令，并按照命令在命令行上出现的顺序，为后一个命令的标准输入创建一个链接。例如：

```
$ who | grep
```

这会获取已登录用户列表，并使用 `grep` 在列表中搜索字符串 `fred`。只有当 `fred` 登录时，才会输出。

```
$ ls -ls | sort -nr | pg
```

这会创建当前目录下的文件列表，每行显示块大小。它按反向数值顺序对列表进行排序，最后在屏幕上对输出进行分页。这将按大小对所有文件进行分页列表，最大的在最上方。这在尝试确定磁盘空间被何占用时非常有用。任何接收输入并发送输出的 UNIX 命令都可以使用管道链接。

# 在后台处理命令

为了利用 UNIX 的多任务处理能力，shell 允许在后台处理命令。这通过在命令末尾放置安符符号 `&` 实现。例如：

```
$ find / -name "ledger" -print > find.results 2>/dev/null &
```

该命令在整个文件系统中执行以名为 `ledger` 的文件查找，将其输出发送到本地文件 `ledger.results` 中，消除不需要的错误，并独立于当前 shell（在后台）处理此命令。

```
$ wc -l chapter5.txt chapter5.wcl 2> chapter5.err &
```

在本例中，`wc` 命令从文件 `chapter5.txt` 读取内容，将其输出（行数）发送到文件 `chapter5.wcl`，将错误发送到文件 `chapter5.err`，并在后台执行。

> 注意：如果用户有后台运行的进程并注销，某些 UNIX 系统会终止该登录用户拥有的进程。此外，当你输入要在后台处理的命令时，shell 会返回并显示进程 ID 编号。

# 在命令行中替换命令结果

有时，将一个命令的输出或结果作为另一个命令的参数是有用的。你通过使用特殊字符反引号（`` ` ``）来实现这一点。你成对使用反引号。当 shell 看到一对反引号时，它会执行引号内部的命令，并将该命令的输出替换到原始命令行中。你最常用这种方法将执行结果存储在变量中。例如，为了将五位儒略日期存储在变量中，你可以可以使用命令：

```
$ julian=`date +%y%m%d`'
```

反引号会导致在变量赋值之前执行日期。当你对 shell 变量进行算术运算时，反引号非常有用；请参见本章后面的“Shell 编程”。

# Shell 变量

在代数中，变量是代表某些值的符号。在计算机术语中，变量是代表某些值的符号名称。在本章前面，你已经看到变量 `HOME` 代表用户主目录的名称。如果你不带参数输入目录命令 `cd`，`cd` 将带你到你的主目录。像 `cd` 这样的通用程序知道每个用户主目录的位置吗？当然不知道，值得在 `HOME` 变量中查找主目录（home）。

变量在任何计算机语言中都是有用的，因为它们允许你在明确具体数据是什么的情况下，定义对某条信息做什么。一个加两个数的程序并不好用，但一个具有两个变量的程序是有用的，特别是当变量的值可以在执行时由程序提供时。Bourne shell 有四种变量：用户定义变量、位置变量（或 shell 参数）、预定义特殊变量和环境变量。

# 存储数据或用户定义变量

顾如其名，用户定义变量可以是你想要的任何类型。变量名由字母、数字和下划线组成，前提是变量名不能以 0 到 9 的任何数字开头。（与 UNIX 名称一样，变量是区分大小写的）。当变量出现在命令行等号（=）左侧时，变量名获得值。例如，在以下命令行中，`COUNT` 取了 `Stephanie` 的值：

```
$ COUNT=1
$ NAME=Stephanie
```

> 提示：由于大多数 UNIX 命令都是小写单词，shell 程序传统上在变量名中使用全大写字母。这并不强制使用全大写字母，但使用它们可以让你在程序中轻松识别。

要回回变量的值，在变量名前加一个美元符号（$）：

```
$ NAME=John
$ echo Hello $NAME
Hello John
```

你也可以像如下所示将变量赋值给其他变量：

```
$ JOHN=John
$ NAME=$JOHN
$ echo Goodbye $NAME
Goodbye John
```

有时，将变量数据与其他字符结合形成新单词是有用的，如下例所示：

```
$ SUN=Sun
$ MON=Mon
$ TUE=Tues
$ WED=Wednes
$ THU=Thurs
$ FRI=Fri
$ SAT=Satur
$ WEEK=$SAT
$ echo Today is $WEEKday
Today is
$
```

这里发生了什么？记住，当 shell 解释器看到美元符号（$）时，它会将直到下一个空白符之前的所有内容解释为变量名，在本例中为 `WEEKday`。你可以通过将变量名包含在大括号（{}）中来转义这种解释影响：

```
$ echo Today is ${WEEK}day
Today is Saturday
$
```

你可以通过用空格分隔赋值在单行中分配多个变量，如下所示：

```
$ X=x Y=y
```

变量赋值是从右到左执行的：

```
$ X=$Y Y=y
$ echo $X
y
$ Z=z Y=$Z
$ echo $Y
$
```

你可能会注意到，当引用一个未定义的变量时，shell 不会给你错误提示，而是给你一个空值。

你可以使用 `unset` 命令移除变量的值，如下所示：

```
$ Z=hello
$ echo $Z
hello
$ unset Z
$ echo $Z
```

# 条件变量替换

获取变量值的常用方法是在变量名前加一个美元符号（$），导致变量的值在该处被替换。在 Bourne shell 中，你可以仅在满足某些条件时触发变量替换。这被称为条件变量替换。你始终将条件变量包含在大括号 {} 中。

## 为变量提供默认值

正如你所学，当引用未设置的变量时，会替换一个空值。Bourne shell 允许使用以下格式为变量替换建立默认值：

```
${variable:-value}
```

其中 `variable` 是变量名，`value` 是默认替换。例如：

```
$ echo Hello UNAME
Hello
$ echo Hello ${UNAME:-there}
Hello there
$ echo $UNAME
$
$ UNAME=John
$ echo Hello ${UNAME:-there}
Hello John
$
```

正如前面的示例所示，当你使用这种类型的变量替换时，默认值被替换命令行，但变量的值不会改变。另一种替换构造不仅替换默认值，还将默认值赋值给变量。这种替换的格式为：

```
${variable:=value}
```

它在替换完成后将变量赋值值。例如：

```
$ echo Hello UNAME
Hello
$ echo Hello ${UNAME:=there}
Hello there
$ echo $UNAME
there
$ UNAME=John
$ echo Hello ${UNAME:-there}
Hello John
$
```

替换值不需要是字面量；它可以是反引号中的命令：

```
USERDIR=$(MYDIR:-`pwd`)
```

第三种变量替换在变量已设置时替换指定值，如下所示：

```bash
${variable:+value}
```

如果 *variable* 已设置，则替换为 *value*；如果 *variable* 未设置，则不进行替换。例如：

带错误检查的条件变量替换。另一种变量替换方法允许在变量替换期间进行错误检查：

```bash
${variable:?message}
```
