
其他元数据保存在 `save.metadata` 脚本中。脚本将分区信息保存在 ZIP 磁盘根目录下的 `fdisk.hda` 文件中。打印此文件和你的 `/etc/fstab` 是个主意，这样当你需要手动恢复分区数据时就有纸质。你可以通过在两个控制台之间切换来保存它，在其中一个运行 `fdisk` 并根据需要 `cat /etc/fstab` 或 `fdisk.hda`。然而，这样做容易出错。

你还需要为你的恢复方法保留文件。例如，如果你使用 `nfs` 保存数据，你需要保留 `hosts`、`devs` 等。此外，如果你正在使用任何基于网络的恢复过程（如 `Amanda` 或 `Quick Restore`），你需要保留网络文件，如 `HOSTNAME`、`hosts` 以及相关的软件树。

处理此类类似问题最简单的方法是保留整个 `etc` 目录。

像 100 MB ZIP 驱动器是不可能装下现代 Linux 发行版的服务器安装的。我们必须比简单的保留全部更具选择性。我们需要哪些文件？

- `boot` 目录。
- `/etc` 目录及其子目录。
- 启动时需要的目录。
- `/dev` 中的设备文件。

要确定启动所需的目录，我们需要查看启动文件 `/etc/rc.sysinit`。它设置了唯一的路径如下：

```
PATH/bin:/sbin:/usr/bin:/usr/sbin
export PATH
```

尝试表明，我们还需要其他目录，例如 `/dev`。在 Linux 中，如果没有设备文件，你什么也做不了。

在阅读 `save.metadata` 脚本时，请注意我们并不一定是在保存使用绝对路径调用的文件。

在获得可用的备份脚本之前，我们可能需要进行多次备份、测试裸机恢复、从 CD 重新安装并再次尝试。在我编写此 HOWTO 期间，我经过五次这样的迭代才成功完成恢复。这就是为什么尽可能使用脚本的原因之一。请务必彻底测试！

## 5. 启动 tomsrbt

在开始恢复过程之前，要做的第一件事是验证硬件时间是否设置正确。请使用 BIOS 设置进行此操作。时间设置得多精确取决于你的应用程序。对于恢复来说，时间误差在几分钟内就足够准确了。这将允许时间敏感的事件在你最终启动恢复后的系统时，能够从之前中断的地方继续。

在启动 `tomsrbt` 之前，请确保你的 ZIP® 驱动器连接在并行端口上，即 `/dev/lp0` 或 `/dev/lp1`。启动软件将自动为你加载并行端口 ZIP® 驱动程序。

下一步是设置视频模式。我希望屏幕上显示的内容尽可能多。在选择视频模式的选项时，使用 6， 80 列 60 行。你的硬件可能无法处理那么高的分辨率，所以请进行尝试。

一旦 `tomsrbt` 启动并且你有了控制台，请挂载 ZIP® 驱动器。仅以只读方式挂载可能是一个好主意：

```
# mount /dev/sda1 /mnt -ro
```

检查它是否在位：

```
# ls -1 /mnt
```

然后切换到 ZIP® 驱动器上脚本所在的目录。

```
# cd /mnt/root.bin
```

现在运行分区信息的脚本，例如：

```bash
# .make.dev.hda
```

此脚本将执行：

- 清除硬盘的前 1024 字节，销毁任何现有的分区表和主引导记录 `MBR`。
- 根据你运行 `make.fdisk` 时收集的信息重新创建分区。
- 根据情况创建 `ext2` 文件系统分区和 Linux 交换分区。
- 创建某些类型的 FAT 分区。
- 为你创建挂载点和 `ext2` 分区。

> 注意

如果你有其他操作系统需要恢复，现在是进行操作的好时机。首先，重启 `tomsrbt` 以完成 Linux 部分。你必须挂载刚刚构建的分区。创建一个新的、独立的脚本，将这些分区挂载到 `make.dev.x` 脚本的末尾。

一旦你创建了所有目录并将分区挂载到它们上，就可以运行 `restore.metadata` 脚本。这将把 ZIP® 驱动器的内容恢复到硬盘。

## 5. 启动 tomsrbt

你应该能看到 ZIP® 磁盘根目录的目录列表，然后是恢复中的归档文件列表。`tomsrbt` 上的 `tar` 会告诉你 `tar` 的块大小为 20，这没关系。你可以忽略它。请确保 `lilo` 输出了它的结果：

```
Added linux *
```

随后将是 `df -m` 命令的输出。

如果你通常直接启动到 X，可能会遇到一些问题。为了安全起见，请临时更改启动运行级别。在 `/target/etc/inittab` 中，找到类似下面这一行：

```
id:5:initdefault:
```

将其更改为：

```
id:3:initdefault:
```

现在，你可以优雅地重启了。如果你还没有这样做，请从软驱驱动器取出 `tomsrbt` 软盘，并给电脑一个“三指礼”（或其等效操作）：

```
shutdown -r now
```

电脑将关机并重启。

## 6. 第二阶段恢复

当电脑重启时，回到 BIOS 验证时钟是否大致正确。

一旦验证时间正确，退出 BIOS 并重启到硬盘。。你可以直接让电脑按照正常顺序启动。你将看到很多错误信息，大部分是“我找不到某某！哇！”之类。如果你到目前为止工作都做得正确，那么这些错误信息就无关紧要。你不需要 `linuxconf` 或 `apache` 来完成你需要做的工作。

### 注意

作为替代方案，你可以启动到单用户模式（在 `lilo` 提示符处输入 `linux single`），但你必须手动配置网络并设置 `sshd` 或任何你恢复系统所需的守护进程。你的具体操作方式取决于具体的系统。

你应该能够登录到 `root` 控制台（没有 X 用户——抱歉）。你现在应该可以使用网络了，例如通过 `nfs` 挂载你的系统备份。

如果你按照我为 `Arkeia` 建议的两个阶段备份，现在可以恢复 `Arkeia` 的数据库和可执行文件。你应该能够运行

```
/etc/rc.d/init.d/arkeia start
```

并启动服务器。如果你在安装了 X 的另一台电脑上安装了 GUI，现在可以在另一台电脑上登录 `Arkeia`。

> 注意

恢复时，请仔细阅读文档。例如，除非使用 `-k` 选项，否则 `tar` 不覆盖文件。

这是正常的，因为 `tar` 正在覆盖你在第一阶段恢复的文件。

然后你重启。在关机过程中，你将看到很多错误信息，例如“没有此 pid”。这是过程的正常部分。关机代码使用了未启动的守护进程的 pid 文件。

你的系统应该正常启动，错误信息比以前少得多，理想情况下完全没有错误。在 RPM 系统上测试恢复效果好坏的“酸测试”方法是验证所有包：

```
rpm -Va
```

某些文件（如配置和日志文件）会在正常过程中发生变化，你应该在报告中将它们手动过滤掉。你可以将输出重定向到文件，并与备份时制作的文件 `etc/rpm.txt` 进行对比，从而大幅加快这一步骤。Emacs 用户应该检查它的差异功能。

现在你应该已经运行了。是时候测试你的应用程序了，特别是那些作为守护进程运行的。应用程序越复杂，可能需要的测试越越多。如果你有远程用户，在测试期间使用系统禁用他们，或将其设置为“只读”。这对于数据库尤为重要，可以防止任何损坏或数据丢失恶化。

如果你通常启动到 X 且在上面禁用了它，请在重新启用之前测试 X。通过将 `/etc/inittab` 中的该行改回来重新启用：

```
id:5:initdefault:
```

## 8. 应用程序特定说明

我在下方列出了关于备份特定应用程序的注意事项。

### 8.1. Squid

`Squid` 是一个 http 代理和缓存服务器。由于它在硬盘上保留了大量临时数据，备份这些数据没有意义。请在你的第二阶段备份脚本中相应的 `tar` 命令中插入 `--exclude /var/squid/squid`。然后，让 `squid` 为你重建目录。在第二阶段恢复脚本的末尾添加命令以进行初始化。这是我通过 `ssh` 恢复到 `restore.tester` 的做法：

```bash
ssh $target 'mkdir /var/spool/squid ; chown squid:squid /var/spool/squid; /usr/sbin/squid -z;touch /var/spool/squid/.OPB_NOBACKUP'
```

最后一个命令创建了一个长度为 0 的文件 `OPB_NOBACKUP`。这是为了 `Arkeia` 的考虑，告诉 `Arkeia` 不要备份此目录。

### 8.2. Arkeia

`Arkeia` 是一个运行在多种平台上的备份恢复程序。你可以将 `Arkeia` 作为裸机恢复方案的一部分，但有两个注意事项。
