## `uux` — UNIX-to-UNIX 系统命令执行

### 概要

```
/usr/bin/uux [-bcCjnprz] [-ename] [-grade] [-sfilename] [-xdebug-level] command-string
```

## or

`uux` 从各种系统收集零或多个文件，在指定系统上执行命令，并将标准输出发送到指定系统上的文件。

> 注意 — 出于安全考虑，大多数安装限制了代表来自 `uux` 传入请求执行的命令列表，仅允许接收邮件（参见 `mail(1)`）。远程执行权限在 `/etc/uucp/Permissions` 中定义。

`command-string` 由一个或多个参数组成，看起来像 `shell` 命令，但你可以在命令和文件名前加上 `system-name!` 前缀。空的 `system-name` 被解释为本地系统。

文件名可以是以下内容之一：

- `-` 绝对路径名。
- 前面带有 `~xxx` 的路径名，其中 `xxx` 是指定系统上的登录名，并替换为该用户的登录目录。

其他任何内容都以当前目录为前缀。
例如，以下命令从 `sys1` 和 `sys2` 系统获取 `filename1` 和 `filename2`，执行 `diff(1)` 命令，并将结果放在本地 `PUBDIR/directory` 中的 `filename.diff` 中。

```
uux uux "diff sys1/home/dan/filenamesys2/a4/dan/filename2 > /!/dan/filename.diff"
```

`PUBDIR` 是 `uux` 定义的公共目录。默认情况下，该目录为 `/var/uucpublic`。
`uux` 尝试获取所有可能的文件到指定的系统并在那里进行处理。对于输出文件，使用括号对文件名转义。例如，以下命令从系统 `b` 获取 `/usr/filename` 并发送到远程系统，对该文件执行 `cut` 命令，并将 `cut` 命令的结果发送到系统。

```
castle uux "cut -f1 /usr/filename </usr/filename"
```

如果远程系统上的请求命令被禁用，`uux` 会通知你。你可以使用 `-n` 选项关闭此通知。响应将通过远程系统的邮件返回。
以下限制适用于 `uux` 处理的 `shell` 管道线。

- 引用任何特殊的 `shell` 字符，如 `<`, `>`, `.`, `;`, `|`，可以通过对整个命令字符串进行引用或将特殊字符作为单独参数进行引用。
- 在从不同系统收集文件时，`uux` 不执行路径名扩展。因此，诸如 `uux "c89 remys!/*.c"` 的请求会将文件名 `*.c` 字面上地拷贝到本地系统。
- 只有 `shell` 管道的第一个命令可以带有 `system-name!`。所有其他命令都在第一个命令所在的系统上执行。
- 使用 `shell` 元元字符 `*` 可能不是你想要的操作。
- `shell` 标记 `<<` 和 `>>` 未实现。
- 你不能使用重定向运算符 `>>`, `<<` 或 `>`。
- 你不能在管道头部使用保留字 `!` 来修改退出状态。
- 不进行别名替换。

`vacation` — 自动回复

### 概要

```
/usr/bin/vacation [-I]
/usr/bin/vacation [-j][-a alias] [-tN username
```

## 描述

`vacation` 自动回复传入邮件。它使用家目录下的 `.forward` 文件向在 `vacation` 程序期间向你发送邮件的用户自动转发 `.vacation.msg`。它还使用家目录下的 `.vacation.pag` 和 `.vacation.dir` 文件存储发送者列表。在以下情况下不会发送 `vacation` 消息：

- 当 `To:` 行或 `Cc:` 行未列出原始消息的用户或其别名时。
- 当初始 `From:` 行包含字符串 `-REQUEST@` 或标头包含 `Precedence: bulk` 或 `Precedence: junk` 行时。
- 从 `postmaster` 接收邮件时。
- 从 `Mailer-Daemon` 接收邮件时。
