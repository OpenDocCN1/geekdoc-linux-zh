#### 使用 `kill` 命令停止进程

`kill`程序用于向进程发送信号。这些信号可以停止正在运行的进程、继续已停止的进程，或告知进程其他各种事项。然而，正如命令名称所示，`kill`程序最常用于停止或终止正在运行的进程。

用户可以对自己拥有的进程使用`kill`程序发送信号，而root用户可以向系统上的任何进程发送信号。该命令的语法如下：

```text
$ kill -signal PID
```

在这种情况下，指定的信号被发送到指定`PID`所指示的进程。在最简单的形式中，会假定一个默认信号，命令可以简单地写成：

```text
$ kill PID
```

默认信号是`SIGTERM`信号（信号编号15）。Linux信号的完整列表将在本章后面的“Linux信号”一节中概述。顾名思义，`SIGTERM`信号是一种进程终止信号，它要求进程终止并退出。

信号通过其编号或名称来表示。例如，要明确指定`SIGTERM`信号并将其发送到`PID` 459的进程，可以使用以下命令之一：

```text
$ kill -15 459
$ kill -TERM 459
```

当信号的符号名称传递给`kill`命令时，为了简洁起见，省略开头的`SIG`部分。例如，要向`PID` 123的进程发送`SIGQUIT`信号，`kill`命令将采用以下形式：

```text
$ kill -QUIT 123
```

有时，进程可能不会响应`SIGTERM`信号。实际上，进程可以选择忽略该信号。在这种情况下，发出标准的`kill PID`命令将无法终止进程。相反，你需要使用`SIGKILL`信号（信号编号9）。进程不能选择忽略该信号。在这种情况下，以下两个命令之一应能终止忽略`SIGTERM`信号的进程：

```text
$ kill -9 PID
$ kill -KILL PID
```

`kill`命令的另一个常见用途是发送挂断信号（`SIGHUP`；信号编号1）。某些守护进程被设计为在收到`SIGHUP`信号时重新读取其配置文件。这样就可以在不停止并重新启动正在运行的守护进程的情况下更改其配置。例如，`SIGHUP`信号通常用于`inetd`和`named`守护进程，使它们在保持运行的同时更新配置。要向进程发送`SIGHUP`信号，请使用以下命令之一：

```text
# kill -HUP PID
# kill -1 PID
```

> **警告**
>
> 密切注意你使用`SIGKILL`和`SIGTERM`等信号终止的进程非常重要。你不仅可能因终止打开的活动应用程序而导致用户丢失数据，而且如果终止`inetd`或`init`等关键系统进程，重要的系统服务可能会停止工作，或者系统可能会完全停止运行。

#### Linux信号

*信号*是一种中断进程正在进行的工作并告知其停止并处理该信号的方式。当信号发送到进程时，进程可以选择处理该信号或忽略它。这取决于谁发送了信号以及信号类型。

Linux支持大量可以发送给进程的信号。通常，在之前讨论`kill`命令时提到的三种信号是你平时唯一需要使用的信号。但有时，有必要使用更不常用的信号。表8.4概述了Linux可用的信号。这些信息取自Linux程序员手册的第7节，该手册可在所有Linux系统上在线查阅。要查看该手册页，请执行以下命令：

```text
% man 7 signal
```

#### 更改进程优先级

进程具有与之关联的优先级，这些优先级决定了它们在尝试与其他进程共享 CPU 时所能获得的 CPU 资源量。幸运的是，进程的优先级并不是固定不变的。通常，新进程会继承父进程的优先级。然而，使用 `nice` 命令，可以在启动程序时指定不同的优先级。
