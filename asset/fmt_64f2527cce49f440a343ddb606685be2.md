
然而，如果我们在源目录名称后添加一个斜杠 `/`，`rsync` 将只会复制 `source` 目录的内容，而不是目录本身。

```bash
[me@linuxbox ~]$ rsync source/ destination
[me@linuxbox ~]$ ls destination
file1
```

如果我们只需要目录的内容，而不想在目标目录中再创建一层目录，这种方法就非常方便。我们可以将其结果视为等同于 `source/*`，但这种方法将复制 `source` 目录的所有内容，包括隐藏文件。

作为一个实际示例，让我们考虑之前使用的那个虚拟外部硬盘。如果我们把硬盘连接到系统，并且它再次挂载在 `/media/BigDisk`，我们可以通过以下步骤执行一次实用的系统备份：首先在外部硬盘上创建一个名为 `/backup` 的目录，然后使用 `rsync` 将系统中的重要数据复制到外部硬盘上。

```bash
[me@linuxbox ~]$ mkdir /media/BigDisk/backup
[me@linuxbox ~]$ sudo rsync -av --delete /etc /home /usr/local /media/BigDisk/backup
```

在这个例子中，我们将系统中的 `/etc`、`/home` 和 `/usr/local` 目录复制到了我们的虚拟存储设备。我们包含了 `--delete` 选项，用于删除备份设备上可能存在但在源设备上已不存在的文件（这在第一次备份时无关，但在随后的复制中将非常有用）。重复连接外部设备并运行此 `rsync` 命令的过程是保持小型系统备份的一种的一种（尽管不是理想的）方法。当然，在这里使用别名（`alias`）也会很有帮助。我们可以创建一个别名并将其添加到 `.bashrc` 文件中来实现这一功能。

```bash
alias backup='rsync --delete /etc /home /usr/local /BigDisk/backup'
```

现在，我们只需要连接外部设备并运行命令即可完成工作。

## 跨网络使用 rsync

`rsync` 的实际用处之一是它可以用于通过网络复制文件。毕竟，`rsync` 中的 `r` 代表“remote”（远程）。远程复制可以通过两种方式实现。第一种是使用另一个安装了 `rsync` 的系统，并配合如 `ssh` 等远程 shell 程序。假设我们在本地网络上有另一台具有大量可用磁盘空间的系统，并想要使用远程系统而不是外部设备来执行备份操作。假设该系统已经有一个用于存放我们文件的 `/backup` 目录，我们可以这样做：

```bash
[linuxbox]$ sudo rsync -av --delete --rsh=ssh /etc /home /usr/local remote-sys:/backup
```

我们对命令进行了修改以方便网络复制。首先，我们添加了 `--rsh=ssh` 选项，它指示 `rsync` 使用 `ssh` 加密隧道将数据从本地系统安全地传输到远程主机。其次，我们通过在目标路径前加上远程主机名（假设远程主机名为 `remote-sys`）来指定远程主机。

第二种方法是可以使用 `rsync` 跨网络同步文件。`rsync` 服务端可以被配置为作为守护进程（`daemon`）运行，并监听传入的同步请求。这通常用于允许对远程系统进行镜像。例如，红帽（Red Hat）为 Fedora 发行版维护了一个大型的开发软件包仓库。对于测试人员来说，在发行版发布周期的测试阶段镜像该集合非常有用。由于仓库中的文件频繁变化（通常每天超过一次），因此通过定期同步来维护本地镜像比通过批量拷贝仓库更理想。其中一个仓库保存在杜克大学（Duke University）；我们可以使用本地 `rsync` 副本和他们的 `rsync` 服务器像这样镜像它：

```bash
[me@linuxbox ~]$ mkdir fedora-devel
[me@linuxbox ~]$ rsync -av --delete rsync://archive.linux.duke.edu/fedora/linux/development/rawhide/Everything/x86_64/os/ fedora-devel
```

在这个示例中，我们使用了远程 `rsync` 服务器，它由一个协议（`rsync://`）、跟随远程主机名（`archive.linux.duke.edu`）以及路径组成。

## 总结

我们查看了 `rsync` 的用法，它是一个同步文件的强大工具。我们看到了如何使用它来复制目录，以及如何使用末尾斜杠来改变目录复制的行为。我们还提到了如何在网络上使用 `rsync`，包括使用 `ssh` 和作为守护进程使用。

在接下来的章节中，我们将探索 `rsync` 的高级功能，例如过滤器和正则表达式。

# 19 正则表达式

## 什么是正则表达式？

简单来说，正则表达式是用于识别文本模式的符号。在某些方面，它们类似于 shell 的通配符匹配方法，但规模大得多。正则表达式被许多命令行工具和编程语言支持。然而，为了增加复杂性，并不是所有的正则表达式都是相同的；它们在工具和编程语言之间略有不同。我们的我们的中将限制在 POSIX 标准描述的正则表达式上（它涵盖了大多数命令行工具），而不是使用集合更大、更丰富的编程语言（如 Perl）。

## grep

我们处理正则表达式的主要程序是 `grep`。`grep` 的名字实际上源于“global expression print”（全局表达式打印），可见 `grep` 与正则表达式有关。本质上，`grep` 在文件中搜索匹配指定正则表达式的文本，并输出任何匹配行。

到目前为止，我们一直配合字符串使用 `grep`，例如：

```bash
[me@linuxbox ~]$ ls /usr/bin | grep zip
```

这将列出 `/usr/bin` 目录下所有包含 `zip` 字符串的文件。`grep` 以这种方式接受选项和参数，其中 `regex` 是正则表达式：

```
grep [options] regex [file...]
```

表 19-1 描述了常用的 `grep` 选项。

表 19-1: grep 选项

| 选项 | 长选项 | 描述 |
| :--- | :--- | :--- |
| -i | --ignore-case | 不区分大小写字符。 |
| -v | --invert-match | 反转匹配。通常，`grep` 会打印包含匹配的行。此选项导致 `grep` 打印不包含匹配的行。 |
| -c | --count | 打印匹配的数量（如果指定了 `-v` 选项，则打印非匹配的数量），而不是行本身。 |
| -l | --files-with-matches | 输出每个包含匹配的文件名，而不是行本身。 |
| Option | 长选项 | 说明 |
| --- | --- | --- |
| -L | --files-without-match | `-l` 选项，但只打印不包含匹配项的文件名。 |
| -n | --line-number | 在每个匹配行前加上文件号。 |
| -h | --no-filename | 对于多次搜索，抑制文件名的输出。 |

为了充分探索 `grep`，让我们创建一些文本文件进行搜索。

```
me[linuxbox ~]$ ls /bin > dirlist-bin.txt
me[linuxbox ~]$ ls /usr/bin > dirlist-usr-bin.txt
me[linuxbox ~]$ ls /usr/sbin > dirlist-usr-sbin.txt
me[linuxbox ~]$ ls dirlist*.txt
dirlist-bin.txt dirlist-usr-sbin.txt
dirlist-usr-bin.txt
```

我们可以这样对我们的文件列表进行简单的搜索：

```
me[linuxbox ~]$ grep bzip dirlist*.txt
dirlist-bin.txt:bzip2
dirlist-bin.txt:bzip2recover
```

在这个示例中，`grep` 在所有列出的文件中搜索字符串 `bzip` 并找到了两个匹配项，都在 `dirlist-bin.txt` 文件中。如果我们只对包含匹配项的文件列表感兴趣而不是匹配项本身，我们可以指定 `-l` 选项。

```
me[linuxbox ~]$ grep -l bzip dirlist*.txt
dirlist-bin.txt
```

相反，如果我们只想看到不包含匹配项的文件列表，可以这样做：

```
me[linuxbox ~]$ grep -L bzip dirlist*.txt
dirlist-sbin.txt
dirlist-usr-bin.txt
dirlist-usr-sbin.txt
```
