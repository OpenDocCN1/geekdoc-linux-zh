### 崩溃后的处理

很多人经历过这种情况：编辑一个文件长时间，就要完成的时候，系统崩溃了。如果使用的是 vim，它会在所在目录下生成一个临时文件（swap file），编辑过程中所有的修改都会暂时存储在交换文件中，系统异常退出时就可以恢复。注意：由于性能考虑，交换文件是不实时的，因此不能保证所有的修改都存在其中。默认情况下，交换文件将在每次写入后被覆盖。如果不希望 vim 创建交换文件，可以使用 `vim -n` 选项打开 vim。这样就放弃了文档恢复，除非有充分理由，否则最好不要这样做。

### 4.2.1 子任务 创建目录

首先，用 `dev01` 用户，然后用 `mkdir` 命令创建 `project_z` 目录，结果发现并没有简单的 bash 提示“mkdir 无法创建目录/project_z 权限不够”，如清单 4-1 所示。不需要解释，就能看出问题出在哪里：`dev` 用户没有权限创建这个目录。

### 清单 4-1

```
$ dev0@localhost:~/srv$ mkdir project_z
mkdir: 无法创建目录“/srv/project_z” 权限不够
```

那么，怎样才能有权限创建这个目录呢？首先要明白 Linux 中的“权限限制”这个概念，而 Linux 中的文件访问权限与用户和用户组不可分，简单只需要理解 Linux 用户和用户组的概念。

## 注意

- **用户（User）** 是能够获取系统资源的权限的集合。简单来说，就是因为每个用户需要完成的工作不一样（责任），所以，其在系统中的文件访问权限（权利）也不相同。系统管理员对整个系统维护有责任，他就有权限操纵整个系统，而普通用户只对某些文件进行操作，其权限就限制到此范围内。
- **用户组（Group）** 就是具有相同属性的用户集合，用户可以作为组的成员，方便于管理用户。

在 Linux 中，一个文件总是和特定的用户（文件所有者）和特定的用户组（所属用户组）关联在一起的。

为了更清晰、直接，使用 `ls -l` 命令查看 `/home/dev0/test.sh` 这个文件的属性，如下表所示。

### 清单 4-2

```
$ ls -l /home/dev0/test.sh
-wxr-xr-x-- 1 dev group 22 12 月 2017 /home/dev0/test.sh
```

输出结果有 7 个字段，这 7 个字段都代表了文件的一类属性，如图 4-1 所示。

![](img/a95c6704e7d3618800a5dd1f2c0aafd0_90_0.png)

| 可读 | 可写 | 可执行 | 可使用 | 安全 | 上下文 |
| --- | --- | --- | --- | --- | --- |
| 权限 | | | | | |
| 所有者 | 所属组 | 其他用户 | SELinux | | |

目前关注的就是字段 1、字段 3 和字段 4，其中字段 3 和字段 4 的意思非常明确，分别代表了文件的所有者（`dev0` 用户）和所属的用户组（`group` 用户组）。

对应的字段是字段 1，这个字段由 11 个字符组成，如图 4-1 所示。我们目前关注的是 9 个字符，这 9 个字符每 3 个字符为一组，分别表示所有者、所属组用户、其他用户对文件的权限。每组的 3 个字符分别表示读（`r`）、写（`w`）和执行（`x`）权限，如果相应的权限被（`-`）替代，则表示该用户没有权限。

对于这个文件，`dev0` 用户可读写，`group` 用户组中的用户可读不可写，其他用户只读。

## 注意

- 读（`r`）、写（`w`）、执行（`x`）这 3 种权限对于文件和目录的含义是不同的，如表 4-2 所示。

表 4-2 r, w, x 权限的含义

| :--- | :--- | :--- |

| 写 (w) | 写文件 | 修改目录 |
| 执行 (x) | 运行文件 | 进入目录 |

### 4.2.2 修改文件权限

接下来新的问题。建立的目录与根目录“/”一样，所有者是 `root`，所属组是 `root`，权限是 `rwxr-xr-x`，这意味着这个目录 `dev0` 用户没有写权限，而且其他用户能够进入目录，与任务要求不一致。因此还需要修改目录的所有者、所属组和访问权限。

![](img/a95c6704e7d3618800a5dd1f2c0aafd0_92_0.png)

## 注意

修改文件所有者和所属组。首先更改所有者、所属组，使用 `chown` 命令来实现，如清单 4-6 所示。

### 清单 4-6

```
# chown dev01:dev01 /srv/project_z
# ls -ld /srv/project_z
drwxr-xr-x 2 dev01 dev01 4096 9月 27 project_z
```

`chown` 后跟了一个参数 `dev01:dev01`，其中冒号前面的表示所有者改为 `dev01`，冒号后面的表示所属组为 `dev01`（`dev01` 用户私有的）。修改完成后，`dev01` 就对 `project_z` 目录有了完全的访问权限（读写执行）。接着修改访问权限，让组和其他用户没有权限，使用 `chmod` 命令来实现，如清单 4-7 所示。

### 清单 4-7

```
# chmod g-rx,o-rwx /srv/project_z/
# ls -ld /srv/project_z/
drwx------ 2 dev01 dev01 4096 9月 27 project_z
```

![](img/a9c6704e7d361880a5dd1f2c0aafd0_92_1.png)

## 注意

修改或设置访问权限可以使用两种方法，这里使用的是助记的方法，助记分为三个部分：

- 目标标记：`a` 代表所有用户，`u` 代表所有者，`g` 代表所属组，`o` 代表其他用户。
- 操作标记：`+` 代表添加权限，`-` 代表删除权限，`=` 代表设置权限。
- 权限标记：`r` 代表可读，`w` 代表可写，`x` 代表可执行。
- 如果需要对用户、组或组合设置权限，可以通过逗号分隔，例如 `chmod u+r,g=rx,o-rwx` 表示为所有者增加权限，设置所属组权限为可读执行，删除其他用户所有权限。

可以看到，`chmod` 改变了 `project_z` 目录的访问权限属性，现在 `project_z` 目录的文件权限是 `drwx------`，即 `dev01` 能够读取、写入、执行这个目录，所属组用户无任何权限，其他用户也无权限。这仅生效了 `project_z` 目录本身，它的各级子目录的权限仍未改变，需要在 `chmod` 命令后加上 `-R` 选项，表示递归修改目录的各级子目录及其中的文件访问权限，如清单 4-8 所示。
