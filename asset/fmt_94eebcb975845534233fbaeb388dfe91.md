
## 1422
## unzip

根据环境变量 `TZ` 设置时区 (`TZ`)，以便 `unzip` 正确运行。该变量也可以未设置；在这种情况下 `unzip` 使用本地时区。要检查时区，请使用 `-v` 选项或以下任一：

- `-a`
使用原始时间戳提取文件。
- `-L`
将文件名小写。
- `-C`
不区分大小写匹配文件名。
- `-q`
使用静默模式。
- `-o`
无需提示覆盖现有文件。
- `-n`
从不覆盖现有文件。
- `-P`
指定密码。
- `-u`
仅提取较新的文件。

## 1423
## unzip

`unzip` 支持加密压缩包。

# 缺陷 (Bugs)

目前不支持分卷压缩包，配合 `zip` 使用除外。要解决此问题，请按顺序合并所有部分，然后对合并后的压缩包执行 `zip -F`。此问题将在下一个大版本中彻底修复。

目前不支持从标准输入读取压缩包，使用 `unzip` 除外，但你只能提取压缩包中的第一个项目。

使用 8 位密码加密的压缩包（即带有重音符号欧洲字符的密码）可能无法在系统和/或其他压缩包之间迁移。

除 UNIX 系统外，不会恢复存储目录的日期、时间和权限。

[MS-DOS] 当在缺陷软磁盘上对压缩包进行提取或测试失败时，如果你在 DOS Abort, Retry, Fail（中止、重试、失败）消息中选择 Fail（失败）选项，旧版本的 `unzip` 可能会导致挂挂，需要重启。此问题似乎已修复。你可以使用 Control-C（或 Control-Break）来终止 `unzip`。

在 DEC Unix 下，`unzip` 有时在处理长文件名时会失败（CRC 错误，并非总是可复现）。这个问题显然是硬件缺陷（缓存内存）或操作系统缺陷（页错误处理不当）导致的。Unix 已被 Digital UNIX (OSF/1) 取代，这可能不再是一个问题。

[UNIX] 如果 UNIX 特殊文件（如 FIFO 缓冲区（命名管道）、块设备和设备归包）以某种方式表示在文件中，则它们不会被恢复，硬链接文件也不会重新链接。`unzip` 恢复的唯一类型是普通文件、目录和符号链接（软链接）。

[OS/2] 只有在指定 `-o`（覆盖所有）选项时，才会更新现有目录的扩展属性。这是操作系统的局限性；因为只有目录有关创建时间，`unzip` 无法判断存储的属性是比磁盘上的属性新还是旧。在实践中，你可能需要采用两步通过的方法：首先正常解压压缩包（无论是否刷新/更新文件），然后覆盖目录项（例如，`unzip -o foo */.*`）。

[VMS] 当提取到另一个目录时，`-d` 选项接受 `[.foo]` 语法；简单的 UNIX `foo` 会被静默忽略（不常用的 VMS `foo.dir` 语法也是如此）。

[VMS] 当提取的文件已存在时，`unzip` 查询仅允许跳过、覆盖或重命名。覆盖会创建一个新版本；旧版本不会被覆盖或删除。

### 示例 (Examples)

以下示例将 `letters.zip` 中的所有项目提取到当前目录及其子目录中，并根据需要创建子目录。

# unzip 1425

```
castle% unzip letters

Archive: letters.zip

inflating: letters.rtf

castle%
```

以下示例将 `letters.zip` 中的所有项目提取到当前目录。

```
castle% unzip -j letters

Archive: letters.zip

inflating: letters.rtf

castle%
```

以下示例测试 `letters.zip`，并打印摘要消息指示压缩包是否 OK。

```
castle% unzip -tq letters

No errors detected in compressed data of letters.zip.

castle%
```

以下示例测试当前目录下的所有 zip 文件，只打印摘要。

```
castle% unzip -tq *.zip

No errors detected in compressed data of letters.zip.

castle%
```

> 注意 - 在 UNIX 中，只有当 shell 扩展通配符时才需要最后的反斜杠。你可以使用双引号代替。

以下示例将二进制文件 `paper1.dvi` 提取到标准输出并管道至打印程序。

