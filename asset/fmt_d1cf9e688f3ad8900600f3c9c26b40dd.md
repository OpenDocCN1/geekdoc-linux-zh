
如果你编写一个独立的程序，定期连接到啤酒程序并测量接收状态消息所需的时间，结果将是令人惊讶的。

## socket 469

在作者的机器上（一台双核 2 GHz MacBook），基于协程的服务器的平均响应时间（通过 1,000 次请求测量）为 1ms，而线程服务器则为 5ms。这是因为基于协程的代码能够在检测到连接时立即响应，而线程服务器在被操作系统调度之前是不运行的。在存在 CPU 密集型线程和 Python 全局解释器锁（GIL）的情况下，服务器可能会被延迟直到 CPU 密集型线程超过其配给的时间片。在许多系统中，响应时间的粗略测量值比你可能预期 CPU 密集型任务被抢占的平均时间多出约 10ms。

轮询的缺点是，如果发生过于频繁，就会引入巨大的开销。例如，尽管在本例中响应时间较低，但带有轮询监控的程序运行时间长了 50% 以上。如果你将代码更改为每隔六包请求才轮询一次，响应时间会略微增加到 12ms，而程序的运行时间比没有任何轮询的程序多出 3%。遗憾的是，没有明确的方法可以知道为了对应用程序进行测量应该多久轮询一次。

即使这种改进后的响应时间看起来很不错，但在执行任何类型的阻塞操作时仍有严重问题需要特别小心。在 Web 服务器示例中，有一段代码打开并读取文件数据。当此操作发生时，整个程序将冻结——如果文件访问触发磁盘，可能会持续一段时间。修复此问题的唯一方法是额外添加异步文件访问并将其作为调度器的功能。对于更复杂的操作（例如执行数据库查询），思考如何以异步方式执行工作变得复杂。一种方法是在单独的线程中执行工作，并在可用时将结果传回任务调度器——这可以通过仔细使用消息队列来实现。许多许多系统中存在底层的异步 I/O 系统（如 Unix 中的 aio 系列函数）。该库未提供这些函数的访问，尽管你可以通过第三方模块找到绑定。根据作者的经验，使用此类功能比看起来要复杂得多，而且并不值得给程序增加这些复杂性——最好让线程库来处理此类事务。

## socket

`socket` 模块提供了对标准 BSD socket 接口的访问。尽管它基于 Unix，但该模块在所有平台上都可用。socket 接口设计为通用型，能够支持多种网络协议（Internet、TIPC、蓝牙等）。然而，最常用的协议是互联网协议 (IP)，它包括 TCP 和 UDP。Python 支持 IPv4 和 IPv6，尽管 IPv4 要常见得多。

需要注意的是，该模块是相对底层的，提供了对操作系统提供的网络函数的直接访问。如果你正在编写网络应用程序，使用第 22 章描述的模块或章节末尾描述的 `SocketServer` 模块可能会更简单。

## 地址族 (Address Families)

某些 `socket` 函数需要指定地址族。地址族指定所使用的网络协议。

| 常量 | 描述 |
| --- | --- |
| AF_BLETOOTH | 蓝牙协议 |
| AF_INET | IPv4 协议 (TCP) |
| AF_INET6 | IPv6 协议 (TCP) |
| AF_NETLINK | Netlink 进程间通信 |
| AF_PACKET | 链路层数据 |
| AF_TIPC | 透明进程间通信协议 |
| AF_UNIX | UNIX 域协议 |

在这些中，`AF_INET` 和 `AF_INET6` 是最常用的，因为它们代表标准连接。`AF_BLETOOTH` 仅在嵌入式系统中可用。`AF_NETLINK`、`AF_PACKET` 和 `AF_TIPC` 仅在 Linux 上支持。`AF_NETLINK` 用于应用程序和内核之间的进程间通信。`AF_PACKET` 直接在链路层工作（例如以太网包）。`AF_TIPC` 用于 Linux 集群高性能 IPC (http://tipc.sourceforge.net/)。

## Socket 类型 (Socket Types)

某些 socket 函数还需要指定 socket 类型。socket 类型指定在地址族内使用的通信类型（流或数据报）。为此定义了以下常量：

| 常量 | 描述 |
| --- | --- |
| SOCK_STREAM | 可靠连接流 (TCP) |
| SOCK_DGRAM | 数据报 (UDP) |
| SOCK_RAW | 原始 socket |
| SOCK_RDMA | 可靠的数据报 |
| SOCK_SEQPET | 顺序连接记录 |

最常见的 socket 类型是 `SOCK_STREAM` 和 `SOCK_DGRAM`，因为它们对应于互联网协议中的 TCP 和 UDP。`SOCK_RDMA` 是一种可靠的数据报形式，但不保证顺序（数据报接收顺序可能与发送顺序不同）。`SOCK_SEQPACK` 用于通过面向流的连接发送数据报并保持其顺序和包边界。`SOCK_RDMA` 或 `SOCK_SEQPACK` 都没有被广泛支持，如果你关心移植性，最好不要使用它们。`SOCK_RAW` 用于提供原始协议的底层访问，并执行特殊目的操作（例如 ICMP 消息），通常限制为以超级用户或管理员权限运行的程序。

## socket 471

并不是每个地址族都支持每个 socket 类型。例如，如果你在 Linux 上使用 `AF_PACKET` 嗅探以太网包，无法建立面向流的连接（`SOCK_STREAM`）。相反，你必须使用 `SOCK_DGRAM` 或 `SOCK_RAW`。对于 `AF_NETLINK` socket，`SOCK_RAW` 是唯一支持的。

## 地址 (Addressing)

为了在 socket 上执行任何通信，必须指定目标地址。地址的形式取决于 socket 的地址族。

### AF_INET (IPv4)

对于使用 IPv4 的互联网应用程序，地址指定为元组 `(host, port)`。有两个示例：

- `'www.python.org'`, `80`
- `'66.130.182'`, `25`

如果 host 为空字符串，它的含义与 `INADDR_ANY` 相同，表示任何地址。这通常用于服务器创建任何客户端都可以连接的 socket。如果 host 设置为 `'broadcast'` 它的含义与 socket API 中的 `INADDR_CAST` 常量相同。

注意，当使用 `'www.python.org'` 等名称时，Python 使用 DNS 将主机解析为 IP 地址。取决于 DNS 的配置，你每次可能会得到不同的 IP 地址。如果需要，使用如 `'66.130.182'` 的原始 IP 地址可以避免这种行为。

### AF_INET6 (IPv6)

对于 IPv6，地址指定为 4 元组 `(host, port, flowinfo, scope)`。在 IPv6 中，host 和 port 组件与 IPv4 的方式相同，但 IPv6 地址的数值形式通常由由冒号分隔的八个十六进制数指定，例如：

- `'FE80::BAA9:7654:3210:BAA9:7654:3210'`
- `'080A::4:1'`（在这种情况下，双冒号填充了一范围地址的 0）

`flowinfo` 是一个 32 位数字，由 24 位流标签（flow label）、4 位优先级（接下来的四位）和预留位（高四位）组成。流标签仅在发送者发送数据时不经路由器特殊处理时使用。

`scope` 是一个 32 位数字，只有在处理链路本地地址（link-local）和站点本地地址（site-local）时才需要。链路本地地址以 `'FE80::...'` 开头，用于局域网上的机器之间（路由器不会转发链路本地包）。在这种情况下，scope 接口索引标识了主机上的特定网络接口。此信息可以使用 Unix 上的 `'ifconfig'` 或 Windows 上的 `'ipv6 if'` 命令查看。站点本地地址始终以 `'FEC0::...'` 开头，用于同一站点内的机器之间（例如，给定子网上的所有机器）。它是一个站点标识符数字。

如果未给出 flowinfo 或 scope 数据，IPv6 地址可以作为元组 `(host, port)`，就像 IPv4 一样。

# 第 21 章 网络编程与套接字

## AF_UNIX

对于 UNIX 套接字，地址是一个包含路径名的字符串——例如，`'/tmp/myserver'`。

## AF_PACKET

对于 Linux 数据包协议，地址是一个元组 `(device, prot [, pktype [, hatype [, addr]]])`，其中 device 是指定设备名称的字符串（如 `"eth0"`），prot 是一个整数，指定在 `<linux/if_ether.h>` 头文件中定义的以太网号（例如，IP 数据包为 `0x0800`）。packet_type 是一个整数数据包类型，是以下常量之一：

| 常量 | 描述 |
| :--- | :--- |
| PACKET_HOST | 指到本地主机的包地址。 |
| PACKET_BROADCAST | 物理层广播包。 |
| PACKET_MULTICAST | 物理层组播。 |
| PACKET_OTHERHOST | 目标为不同主机的包，但被混杂模式下的设备驱动程序捕获。 |
| PACKET_OUTGOING | 源自机器的数据包，但回环到了套接字队列中。 |

hatype 是一个整数，指定 ARP 协议中使用的硬件地址，并在 `<linux/if_arp.h>` 头文件中定义。addr 是一个包含硬件地址的字节字符串，其结构取决于 hatype 的值。对于以太网，addr 将是一个持有硬件地址的 6 字节字符串。

## AF_NETLINK

对于 Linux Netlink 协议，地址是一个元组 `(pid, groups)`，其中 pid 和 groups 都是无符号整数。pid 是该套接字的地址，通常与创建该套接字的进程 ID 相同，或者为 0（内核）。group 是一个用于指定要加入的 netlink 组的映射。更多信息请参阅 Netlink 文档。

## AF_BLETOOTH

蓝牙地址取决于所使用的协议。对于 L2CAP，地址是一个元组 `(addr, psm)`，其中 addr 是类似于 `'01:23:45:67:89:ab'` 的字节字符串，psm 是一个无符号整数。对于 RFCOMM，地址是一个元组 `(addr, channel)`，其中 addr 是无符号字符串，channel 是一个整数。对于 HCI，地址是一个 1 元组 `(deviceno,)`，其中 deviceno 是整数。对于 SCO，地址是一个字符串。

常量 `BDADDR_ANY` 代表任何地址，是一个字符串 `'00:00:00:00:00:00'`。`BDADDR_LOCAL` 是常量 `'00:00:00:ff:ff:ff'`。

## AF_TIPC

对于 TIPC 套接字，地址是一个元组 `(addr_type, v1, v2, v3 [, scope])`，其中所有字段都是无符号整数。addr_type 是以下值之一，它也决定了 v1、v2 和 v3 的值：

| 地址类型 | 描述 |
| :--- | :--- |
| TIPC_ADDR_NAMESEQ | v1 是服务器类型，v2 是端口标识符，v3 为 0。 |
| TIPC_ADDR_NAME | v1 是服务器类型，v2 是较小的端口，v3 是较大的端口号。 |
| TIPC_ADDR_ID | v1 是节点，v2 是引用，v3 为 0。 |

可选的 scope 字段是 `TIPC_ZONE_SCOPE`、`TIPC_CLUSTER_SCOPE` 和 `TIPC_NODE_SCOPE` 之一。
