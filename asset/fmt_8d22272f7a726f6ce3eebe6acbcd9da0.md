
# Linux 备份与恢复指南

ccurley at trib dot com

想象你的硬盘驱动器刚刚变成了一个非常昂贵的冰球拍。想象一下你的家里经历了一场火灾，你的电脑箱现在看起来就像萨尔瓦多·达利会画出来的作品。现在该怎么办？

全恢复（Total restore），有时称为裸机恢复（bare metal recovery），是在灾难性故障后重建计算机的过程。为了进行全恢复，你必须拥有完整的备份，不仅是你的文件系统，还包括分区信息和其他数据。本 HOWTO 是一个分步教程，旨在教你如何备份 Linux 计算机以便能够裸机恢复，以及如何进行该裸机恢复。它包含了一些相关的脚本。

## 1. 引言

正常的裸机恢复过程是：从产品磁盘安装操作系统。安装备份软件，以便你可以恢复数据。然后通过验证你的配置文件、权限等来获得恢复功能。本 HOWTO 中解释的过程和脚本将恢复从生产计算机备份的文件。当你恢复系统时，你的配置将保持完整，这将为你节省大量时间。

## 2. 概述

下面所示的过程并不简单，并且对你的数据造成危险。在需要之前请进行练习！我就是这么做的，并且在一台牺牲计算机上进行了练习！

本 HOWTO 的目标计算机是一台 Pentium 电脑，在一个 IDE 硬盘上安装了 Red Hat 7.1 Linux 服务器或工作站。目标计算机并没有大量数据，因为它被设定为一个“牺牲性”的测试平台。我不想在生产环境计算机和生产数据上测试这个过程。此外，在开始测试之前，我进行了全新的安装，以便在需要时可以随时重新安装到已知的配置。

### 注意

示例命令在大多数情况下将显示我为了恢复目标系统必须输入的内容。你可能需要使用类似的命令，但使用不同的参数。确保你复制的是自己的系统，而不是测试计算机的设置，这取决于你。

基本步骤列在 W. Curtis Preston 的著作《Unix Backup & Recovery》（O'Reilly & Associates, 1999）中，我在《Linux Journal》中对该书给予了好评。然而，这本书在特定的、实时的问题上略显单薄。例如，你究竟要备份哪些文件？你需要保留哪些元数据，以及如何保留？

在开始该过程之前，在本 HOWTO 中记住一个事实：你需要使用典型的备份工具（如 Amanda, BRU, tar, Arkeia 或 cpio）备份你的系统。那么问题是，如何从烧毁的硬件恢复到运行恢复程序并恢复你数据的程度。

基于 Red Hat 包管理器 `RPM` 的 Linux 发行版用户也应该保存普通备份的 RPM 元数据类似于：

```bash
bash# rpm -Va /etc/rpmVa.txt
```

在你的备份脚本中使用此命令，将为你裸机恢复后提供一个比较基础。

要实现这一点，你需要：

- 你的硬件重新运行，根据需要更换组件。BIOS 应该正确配置，包括日期时间和以及硬盘参数。目前没有考虑到更换硬盘。
- 一个并口 Iomega-ZIP 驱动器或等效设备。你需要至少 30 MB 的空间。
- 你的备份介质。
- 一个允许你运行恢复软件的最小 Linux。

要达到这一点，你需要至少两个阶段的备份，可能需要三个。具体备份什么以及在哪个阶段备份，取决于你的恢复过程。例如，如果你正在恢复一台服务器，在恢复过程中可能无法联网。因此，只在常规备份中备份网络部分。

你将分阶段进行恢复。在第一阶段，我们构建分区、文件系统，并从 ZIP® 磁盘恢复一个最小文件系统。第一阶段的目标是能够启动一台带有网络连接、磁带驱动器、恢复软件或第二阶段所需的任何东西的运行计算机。

第二阶段（如果有必要）包括恢复备份软件和任何相关的数据库。例如，假设你使用 Arkeia 正在构建一个用于裸机的 ZIP® 磁盘。Arkia 在服务器硬盘上保留了一个巨大的数据库。你可以从磁带恢复该数据库。相反，使用 tar 和 gzip 备份整个目录 `/usr/bin`，并通过 nfs 或 ssh 保存到另一台计算机。第一阶段（我们在下方定义）不包含 X，所以如果你希望将 X 作为你的备份程序，你需要做一些工作。某些恢复需要 X。当然，如果你使用某些备份程序，你需要做一些工作。你需要找到所需的目录和文件。如果你使用 tar, gzip, cpio, mt 或 dd 等恢复工具，它们将从 ZIP® 磁盘保存并恢复。

最后阶段是从磁带或其他介质的全恢复。在完成该阶段后，你应该能够启动一个完全恢复并运行的系统。

#### 2.1. 局限性

HOWTO 局限于创建一个最小备份，即使是简述也不详尽。你仍然需要进行一些研究、编辑和测试。这里的脚本完全按照源硬盘上的状态恢复分区数据。如果在相同的计算机或硬盘上进行恢复，这样很好，但并非如此。在读完 HOWTO 的其余部分后，有两种解决方法：

- 编辑分区表。我做过几次。你也可以添加或删除分区（但也要使用分区表的脚本）。
- 构建一个新的分区表，并从那里开始。这就是 `restore_metadata` 没有调用 `fdisk` 的原因。另一个是我不知道哪些硬盘。这里显示的脚本只处理 ext2、FAT12 和 FAT16。在执行这些脚本之前，你需要其他工具来备份和恢复未涵盖的文件系统。分区看起来很有用。

> 警告 按计划进行常规备份。如果不这样做，本 HOWTO 是没用的。

自己构建一个救援磁盘。它有详细的文档，并将许多工具打包到一个磁盘中。有一个活动列表，我的几个问题得到了快速回答。接下来，确定如何备份操作系统。我遵循了 Preston 的建议并使用了并口 ZIP 驱动器。硬盘获得了大约 90 MB 的可用存储空间。我需要大约 85 MB 来备份我的桌面，所以 100MB ZIP 驱动器可能会挑战运气。

## 4. 创建阶段1备份

制作生产备份后，你需要保留分区信息以便重建分区。

`make.fdisk` 脚本扫描硬盘分区信息并将其保存到两个文件中。其中一个可执行脚本，命名为 `make.dev.x`。另一个 `dev.x`（其中 "x" 是设备文件名，例如 `hda`）包含 `fdisk` 的命令。你通过将关联设备文件作为 `make.fdisk` 的参数来指定为哪个硬盘构建脚本（以及相应的文件名）。例如，一个典型的 IDE 系统：

```bash
bash# make.fdisk /dev/hda
```

输出脚本 `make.dev.hda` 和 `fdisk` 的输入文件 `dev.hda`。

此外，当 `make.fdisk` 遇到 FAT32 分区时，它会将分区的引导区保存在名为 `dev.xy` 的文件中，其中 x 是设备名（例如 `sdc`），y 是分区号。引导区是分区的第一个扇区（512）。该扇区在重建分区的同时在 `make.dev.hda` 脚本中恢复。

幸运的是，硬盘价格下降的速度比选举后公众对政客的信任还要快。因此，输出文件是文本且容易很好。现在，这是在较大的分区上重建的唯一方法（参见待办事项 http://example.com/to-do-list）。
