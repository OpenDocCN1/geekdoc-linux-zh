
## 描述

`isainfo` 用于识别当前运行系统中指令集架构的各种属性。它可以回答的问题包括是否支持 64 位应用程序，或者运行内核使用的是 32 位还是 64 位设备驱动程序。

在不带选项调用时，`isainfo` 会打印当前操作系统支持的应用程序原生指令集的名称。这些名称是 `isalist(1)` 返回列表的子集。该子集对应于当前运行系统支持的基础应用程序环境。

## `isainfo`

### 选项

- `-b` 打印原生指令集地址空间中的位数数。
- `-k` 打印操作系统内核组件（如设备驱动程序和 STEAM 模块）使用的指令集名称。
- `-n` 打印当前操作系统版本支持的可迁移应用程序所使用的原生指令集名称。
- `-v` 打印关于其他选项的更详细信息。

### 示例

以下是在不同操作系统上调用 `isainfo` 命令的示例。
在 32 位 x86 平台上，
```
% isainfo -v
32-bit i386 applications
% isainfo -k
i386 %
```

在运行 64 位 SPARC 处理器上运行 32 位操作系统的系统上，
```
% isainfo -n
sparcc
% isainfo -v
32-bit sparc applications
% isainfo -kv
32-bit sparc kernel modules %
```

在运行 64 位 SPARC 处理器上运行 64 位操作系统的系统上，
```
% isainfo
sparcv9 sparc
% isainfo -n
sparcv9
% isainfo -v
64-bit sparcv9 applications
32-bit sparc applications
% isainfo -vk
64-bit sparcv9 kernel modules %
```

### 退出状态

非零值表示未正确指定选项，或者命令无法识别其运行的系统属性。错误信息将打印到标准错误输出。

|---|---|
| 可用性 | SUNWcsu |

`isalist(1)`, `uname(1)`, `psinfo(1M)`, `sysinfo(2)`, `attributes(5)`, `isalist(5)`

## `isalist` — 显示此平台的原生指令集

### 概览

```
/usr/bin/isalist
```

### 描述

`isalist` 将此平台上可执行的原生指令集名称打印到标准输出，这些名称由 `sysinfo(2)` 的 `SI_ISALIST` 命令返回。

名称之间用空格分隔，并按照性能优劣顺序排列。也就是说，命名较靠前的指令集可能包含比命名较靠后的指令集更多的指令；为命名较靠前的指令集编译的程序在该机器上运行的速度可能比为命名较靠后的指令集编译的相同程序更快。

为未出现在列表中指令集编译的程序在该机器上可能会遇到性能下降或根本无法运行。

系统知的指令集名称列在 `isalist(5)` 中。这些名称可能与 C 语言编译系统中的预定义名称或编译器选项。

### 示例

以下示例在 SPARCstation 10 上运行 `isalist`。

```
castle% isalist

sparcv8 sparcv8-fsmuld sparcv7 sparc

castle%
```

### 属性

请参阅 `attributes(5)` 获取以下属性的描述：

| 属性类型 | 属性值 |
|---|---|
| 可用性 | SUNWcsu |

### 另请参阅

`optisa(1)`, `uname(1)`, `sysinfo(2)`, `attributes(5)`, `isalist(5)`

## `jar` — Java 归档工具

### 概览

```
/usr/java/bin/jar [-c] [-f] [-M] [-m] [-o] [-t] [-v] [-xfile] [manifest-file]

destination input-file [input-files]
```

### 描述

`jar` (Java Archive) 工具是一个独立的命令行 Java 应用程序，您可以用进行通用归档，以及在 JAR 文件中创建数字签名和相关的脚本，JAR 文件始终以 `.jar` 后缀结尾。

JAR 文件类型是一种已注册的 Internet MIME 类型，基于标准的跨平台 ZIP 和 ZLIB 压缩格式。JAR 文件充当压缩文件集合的数字封包。该格式是一组将数字签名、安装脚本和其他信息与包中的文件关联的约定。

`jar` 的设计主要目的是为了方便将 Java applet 或应用程序打包成单个归档文件。当将 applet 或应用程序的组件（`.class` 文件、图像和声音）合并到一个归档文件中时，Java 代理（如浏览器）可以在单个 HTTP 事务中下载它们，而无需为每个部分建立新连接。下载时间将大大提高。`jar` 工具还会压缩文件，从而进一步缩短下载时间。此外，它允许 applet 作者使用数字签名对文件中的单个条目进行签名，以便验证其来源。

> 注意 — `jar` 工具的语法与 `tar(1)` 命令的语法几乎相同。

`jar` 工具的三种文件类型是：

- 清单文件（可选）。
- 目标 jar 文件。
- 要归档的文件。

以下典型用法的示例将当前目录下的所有 `.class` 文件放入一个名为 `myjarfile` 的文件中。
```
castle jar cf myjarfile *.class
```

`jar` 工具会自动生成一个命名的清单文件，该文件始终是 jar 文件中的第一个条目。默认情况下，它的名为 `META-INF/MANIFEST.INF`。清单文件存储有关该归档的任何元数据。有关如何在清单文件中存储元数据的详详细信息，请参阅：
`http://sun.com/products/jdk/1.1/`

使用清单文件创建新归档文件，如下例所示：
```
castle jar cf myjarfile *.class
```

### 选项

- `-c` 创建新的归档文件。
- `-f` 指定 jar 文件。
- `-M` 不创建清单文件。
- `-m` 指定清单列表。
- `-o` 指定列表文件。
- `-t` 列出 jar 文件的内容。
- `-v` 详细输出。
- `-x` 从归档中提取文件。

以下示例使用 `jar` 工具和 `-t` 选项显示 jar 文件中的条目名称。

```
castle% ls

audio bundle.class images

castle% jar tf bundle.jar

```
