
你可以将星期几指定为三字符的文本值（`mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`）或数值值，其中 `0` 代表星期日，`6` 代表星期六。这里另一个例子：要在每月的第一天中午 12 点执行命令，你应该使用：

`09 12 1 * * command`

`cron` 表使用一种特殊格式，允许你指定任务应该在何时运行。`cron` 表的格式如下：

```
min hour dayofmonth month dayofweek command
```

由于你无法在 `cron` 字符中指示上午（a.m.）或下午（p.m.），因此对于下午时间需要使用 24 小时制。在 `cron` 执行命令的日期和星期几字段中使用通配符字符，表示 `cron` 将每月的每一天上午 10:15 执行命令。要指定一个在每个周一下午 4:15 运行的命令，你应该使用：

`15 16 * * 1 command`

日期条目指定了该月的日期值（1–31）。当指定在每个周一下午 4:15 运行命令时，你会使用：

`15 16 * * 1 command`

`cron` 程序在后台运行，并检查特殊表，名为 `cron tables`，以查找计划运行的任务。

## 理解版本控制

两个软件开发人员 Natasha 和 Bruce 正在开发一个新项目。该项目被分成几个文件。Natasha 和 Bruce 不断告诉对方自己正在处理哪个文件，以防对方覆盖它。此外，他们还创建了几个目录树来存储项目。版本控制（也称为源码控制或修订控制）是一种组织项目文件并保护其被修改的方法。版本控制系统控制的不仅仅是程序文件；它们通常处理纯文本文件、可执行文件、文档等。

一个版本控制系统 (`VCS`) 提供了一个存储和合并项目文件的公共位置，以便你可以访问最新版本。它保护文件，使其不被其他开发者覆盖。例如，如果 Tony 是一个新成员，他可以通过版本控制系统复制最新项目并开始工作。

分布式版本控制系统 (`VCS`) 让项目变得更简单。开发者可以离线进行工作，而无需担心是否连接了网络。开发在他们自己的系统上本地进行，直到他们将修改文件的副本发送到远程系统。只有此时才需要网络连接。一个额外的好处是工作被备份到了中央位置。适用于 Linux 项目的新型版本控制系统是由 `Linus Torvalds` 创建的。

A version control system (`VCS`) provides a common place to store and merge project files so that you can access the latest version. It protects the files so they are not overwritten by another developer. For example, if Tony is a new member, he can copy the latest project via the version control system and begin work.

Distributed version control systems (`VCS`) make projects easier. Developers can perform their work offline without concerns as whether they are connected to a network. Development takes place locally on their own systems until they send a copy of their modified files to the remote system. Only then is a network connection required. A side benefit is that the work is backed up to a central location.
