
这里的关键词是`杠杆`。就像高中物理中研究的杠杆和支点一样，杠杆一端的任何运动都会在另一端体现。如果将支点放在杠杆的正中心，杠杆两端之间就存在一一的对应关系。如果一端移动五个单位，另一端就会下降五个单位。如果你站在杠杆的一端，并将支点放在离你近的地方，你那端的微小移动就可以影响对面大得多的运动。那么，诀窍在于找到一种方法，在努力将支点移向自己。换句话说，你想让杠杆的一端移动一英寸，让另一端移动到月球球。

Unix 日益成功的原因之一是它能够帮助个人的杠杆努力。这并非偶然发生。它是通过几十甚至几百名程序员的协作设计的。他们意识到，单凭自己能做的有限的。但如果他们能倍增自己的效果，就可以利用软件杠杆。

## 5.1 原则 6：利用软件杠杆之优势

假设你是世界上顶级的程序员之一。你写的每一行代码都能变成黄金。你的应用程序在发布当天就会成为大热门。网络网站上的评论家们对你的作品赞誉有加，你的软件登上了行业杂志的封面。你的程序真的是独一无二的。

遗憾的是，“独一无二”给你带来了一个问题。区分你作品的独特性变成了束缚你的链条。如果你自己完成所有工作，你能做的是有限的。除非你找到卸载部分工作的方法，否则你在实现潜力之前就会精疲力竭。

### 5.1.1 优秀的程序员编写良好的代码；伟大的程序员借鉴良好的代码

编写大量软件最好的方法是借用。我们所说的借用软件，是将他人的模块、程序和配置文件整合到你的应用程序中。在创作衍生作品时，你增加了之前开发者的努力，将他们的实现推向实用性的新高度。随着你的软件在更多应用程序中找到家园，它变得更有价值；因为你对其投入相对于回报有所减少，你的软件也变得更有价值。这是一个互利互利的局面。

尽管你可能降低了对某个应用程序的投入，但你不一定要接受利润的减少。通过整合他人代码构建的应用程序可以卖出高价。它们还往往能占据大量的市场份额，因为它们通常比竞争对手开发的程序先进入市场。“早鸟有虫”的古谚在这里特别适用。如果你能率先推出新应用程序，你通过使用他人的工作获得地位这并不重要。潜在客户只想知道你的软件是否能完成工作。他们对你的软件如何运作感兴趣，不如对它能为他们做什么感兴趣。

利用他人的代码也可以为个人程序员带来潜在优势。一些程序员认为通过自己编写代码来保护自己的职业安全感。“因为我写了良好的代码，所以我总会有工作做，”他们推理道。问题是，编写良好的代码需要时间。如果你必须编写应用程序中使用的每一行代码，你会显得很慢且低效。真正的职业安全属于那些能够快速高效地剪切和粘贴模块的软件开发者。这样的开发者通常在短时间内产生大量的软件，以至于公司通常认为他们是不可缺的。

我记得有一个不那么顶尖的软件工程师，他甚至没法通过编程让自己逃出一个纸袋。然而，他擅长将小模块织合在一起。不过，他几乎从未自己写过任何代码。他只是整天在系统目录和源代码仓库中翻来找去，寻找他可以串联成一个完整程序的程序。老天谢佑，让他不需要编写任何代码。奇怪的是，没过多久管理层就认为他是一位出色的软件工程师，一个能按时按预算交付项目的人。他的大多数同事从未意识到，他甚至编写基础代码都有困难。尽管如此，他仅仅通过利用所有可用的资源就取得了巨大的成功。

### 5.1.2 避免“非此不创”综合征

`NIH`综合征出现在最优秀的组织中。当一个小组拒绝承认其他应用程序的价值时，一个人倾向于从头开始编写应用程序……

同样的标准。为了生存，公司必须面对统一性与独立性这两个冲突目标带来的挑战。获胜的方法将是锦上添花，而不是重新发明。

这听起来像是开源运动发出的欢呼，不是吗？你已经上路了。稍后我们将看到 Linux 供应商和顾问如何利用“增值”的概念，并将其转化为可行商业模式的基础。

`NIH`（不想要别人的意见）的追随者在当今的商业环境中面临着来自多方面的进攻。新的高容量存储技术（如 DVD）构成了巨大威胁。这些用于分发最新电影的闪光光还能廉价地存储超过 100 gb 的程序和数据。像这些廉价的介质具有永久改变软件格局的潜力。CD 和 DVD 已变得随处可见，存储技术已经发生了不可逆转的飞跃。

在最近访问当地的一个 PC 展时，我发现一张包含 2,400 多个程序的 CD 仅售价 5 美元。（的确然，这在如今是一个“低科技”的例子，但它进一步说明了这一点。）要为重写在其他地方花几分钱就能买到的程序是非常困难的——除非你是一个可以靠几分钱活几个月的软件开发者。

也许对 `NIH` 最大的威胁来自电缆和 DSL 等高速互联网接入技术。这些使得任何人都能免费下载成千上万个程序。他们甚至不需要去 PC 上寻找。只需点击几次即可获得。

当优质软件可以零成本获得时，`NIH` 几乎消失了。任何不包含他人开发的软件的软件开发方法都变得过于昂贵。这并不是说不会编写新代码。大多数新软件要么 (1) 增强和扩展现有软件，要么 (2) 实现全新的应用。Linux 和开源社区的定位独特，可以从这两种情况下受益。

### 5.1.3 让他人使用你的代码以利用他们的工作

软件工程师倾向于囤积自己的源代码。就好像他们认为编写了一种独特的发明，一个只有他们才拥有的、能够改变世界的魔方程式。他们潜意识里恐惧如果交出源代码，他们将再也控制这颗价值连城的明珠了。

### 5.1 第六条原则：利用软件杠杆优势优势

首先，软件并不是什么魔方程式。任何拥有合理逻辑思维的人都可以表现得聪明或平庸，但所有软件归根结底都是系列经过计算的语句，导致硬件执行某些定义的定义。从未见过源代码的程序员也可以反汇编最好的程序。反汇编是一个缓慢、枯燥的过程，但是可以实现的。

那么控制权呢？计算机世界有一个普遍的观点是，谁控制源代码，谁就“拥有”程序。这部分是正确的。持有源代码的公司对谁修改程序、谁可以获得其运行许可等行使权威。遗憾的是，这种控制软件生命周期的能力只能保护公司在程序开发上的时间投资，而不能保护软件本身。它无法阻止寻求模仿其特征和功能的仿制者（克隆）的出现。大多数足够让公司投资的好主意也足够让其竞争对手投资。当其他人努力追赶浪潮时，仿制品的出现只是时间问题。最成功的软件是出现在最多计算机上的那一个。以专有方式运营的公司发现自己在这里处于巨大的劣势。

Unix 的成功很大程度上归于它的开发者认为没有特别理由对其源代码保持强力控制。大多数人认为它没有任何真实价值。他们将 Unix 视为一种奇特的物品，适用于研究实验室和大学，但仅此而已。除了开发者之外，没有人认为它是一个严肃的操作系统。因此，人们可以用极廉的价格获得它的源代码。

飞涨的开发成本导致硬件供应商减少了对使其平台市场化所需的软件的投入。操作系统的廉价价格很快看起来是一个非常划算的买卖。Unix 因此得以繁荣。每当有人想节省为新计算机开发操作系统的费用时，他们就会转向 Unix。即使今天，许多人仍然认为它是最便宜的操作系统之一。

低成本使 Linux 成为许多软件公司的选择平台。通过在 Linux 系统开发者提供的内核、编程接口和应用程序的基础上构建，这些公司利用了软件优势。通过避免编写操作系统和一套适用应用程序的成本，他们可以转而专注于增强他们的应用程序，提供卓越且增值的定制。这使得他们在软件世界中比那些必须在生产应用程序之前投资操作系统开发的公司处于更有利的地位。

### 5.1.4 自动化一切

利用软件优势的一种强大方法是让你的机器更努力工作。你今天手动完成的任何计算机可以完成的过程都是浪费你的时间。即使在现代工程实验室里，技能惊人的人员仍然依靠粗糙的手动方法来完成日常任务。他们本该更聪明，但习气难。

## 原则 7：使用 Shell 脚本增加杠杆和可移植性

在本章的第一部分中，我们探讨了杠杆的一些令人的用法，既从通用角度，也专门针对杠杆在软件中的应用。我们已经看到，成为一个致力于利用他人工作的“软件拾荒者”有多重要。在讨论了令人困扰的“我来我（NIH）综合征”后，我们强调了分享工作的价值。最后，我们提到了通过尽可能自动化日常任务来利用计算机时间这一显而易见的愿望。

现在我们已经奠定了基础，是时候构建 Unix 的另一个元素了：Shell 脚本。Shell 脚本以有趣的方式利用软件杠杆。它们让初学者和专家都能轻松挖掘 Unix 中蕴的巨大潜力。Unix 程序员虔诚地使用它们。

Shell 脚本与其他命令解释器和控制机制某些相似之处，例如 MS-DOS 下的批处理文件和 OpenVMS 下的 DCL 命令文件。然而，与其他实现不同，Unix Shell 脚本存在于非常适合间接执行命令的环境中。为了强调它们的重要性，我们在 Unix 哲学中为它们加入了一条特殊原则。

如果你想充分利用软件杠杆，你需要学习如何有效地使用 Shell 脚本。我们在这里不会向你展示如何使用它们。关于这个主题已经有很多书籍了。大多数书会教你如何使用它们。相反，我们将关注你为什么应该使用它们。

在进入讨论之前，我提醒你，许多 Unix 和 Linux 内核程序员鄙视 Shell 脚本程序。他们认为编写 Shell 脚本不是正事。有些人甚至认为“丰富的 Shell 程序员”是“轻量级 Linux 程序员”。我猜他们仅仅是因为嫉妒，因为编写 Shell 脚本涉及大量的脑力痛苦。或者是因为你不能在内核中使用 Shell 脚本。也许会有人写一个 Linux 内核，允许在内核本身中使用 Shell 脚本。到时候，他们也能更充分地体会软件杠杆的好处。
