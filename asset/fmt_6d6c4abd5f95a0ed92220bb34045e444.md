## 检测被劫持的服务

如果攻击者想将服务作为一种持久化方法，创建一个全新的服务通常没有意义。例如，典型机器上有许多服务被禁用或未被使用，那么为什么不直接复用（即劫持）现有的服务呢？许多威胁小组都采用这种方法。如果你仅基于寻找标准或未识别的服务名称进行分析，你将会忽略这些类型的攻击。劫持现有服务有两种变体，将在下文中进行描述。

## 基于注册表的劫持

这种方法（使用注释重写，也称为 APT1）只需更改合法服务的 `ImagePath` 或 `ServiceDll` 注册表值，使其输出到恶意文件。例如，`WEBC2-ADSPACE` 服务（http://contagiodumpblog.com/2013/03/mandiant-apti-samples-categorized-by.hijacked）通过将其 Dll 从 `%SystemRoot%\system32\ervsc.dll` 修改为 `%SystemRoot%\systemsvc.dll` 劫持了 `ERSVC` 服务。

以下是受感染系统中 Volatility 输出的示例：

```
$ python vol.py -f memory.dump --profile=Win7SP64 svscan --verbose

Volatility Foundation Framework 2.4

[snip]
Offset: 0x992c30
Order: 34
Process ID: 892
Service Name: ERSVC
Display Name: Error Reporting Service
Service Type: SERVICE_WIN32_SHARE_PROCESS
Service State: SERVICE_RUNNING
Binary: C:\Windows\system32\svchost.exe -k netsvcs
ServiceDll: %Systemroot%\systemsvc.dll
```

有时微软会在操作系统版本之间更改合法服务的名称。例如，在 Windows XP 上，动态配置主机协议（DHCP）服务的二进制文件是 `dhcsc.dll`；在 Windows 7 中，它是 `dhcpcore.dll`。因此，跟踪这些更改是一项繁杂的任务。相反，你可以使用以下脚本来从清洁系统中导出信息，为服务二进制文件构建一个已知良好路径的白名单。

```python
import pywintypes, win32api, win32con

def main():

    read_perm = (win32con.KEY_READ | 
                  win32con.KEY_ENUMERATE_SUB_KEYS | 
                  win32con.KEY_QUERY_VALUE)

    hkey = win32api.RegOpenKeyEx(
        win32con.HKEY_LOCAL_MACHINE,
        "%SYSTEM\\ControlSet001\\Services",
        0,
        read_perm)

    names = [data[0] for data in win32api.RegEnumKeyEx(hkey)]

    for name in names:
        try:
            subkey = win32api.RegOpenKeyEx(
                hkey,
                "%s\\Parameters" % name,
                0,
                read_perm)
            value = win32api.RegQueryValueEx(
                subkey,
                "ServiceDll")
        except pywintypes.error:
            continue

        path = win32api.ExpandEnvironmentStrings(value[0])
        name = name.lower()
        path = path.lower()

        print(name, "=\=", path)

if __name__ == '__main__':
    main()
```
