
任何 UNIX 系统的不可或缺的一部分是 Linux 中大部分日志由两个主要程序提供的：`syslog` 和 `klogd`。前者为程序和应用程序提供日志服务，后者为 Linux 内核提供日志能力。内核实际上会将消息发送到 `syslog` 设施，但偶尔会在控制台上弹出消息（例如内核恐慌 `kernel panic`）。`syslog` 负责处理消息并将其发送到适当的文件或设备，这在 `/etc/syslog.conf` 中配置。默认情况下，记录到文件的位于 `/var/log/`，通常处理自己日志的程序（如 `apache`）会将日志记录到 `/var/log/proname/`；这使得日志集中化，并更容易将它们放置在单独的分区上（某些攻击可以很快填满你的日志，而分区分满可没意思了）。此外，有些程序有自己的内部日志，其中最有趣的是之一 `bash` 命令行 `shell`。默认情况下，`bash` 在 `~username/.bash_history` 中保留执行过的命令历史，这个文件可能非常有阅读价值，因为很多管理员会无意中在命令行输入密码。

### bash 日志记录

我也将涵盖 `bash`，因为它是大多数 Linux 安装中的默认 `shell`，因此其日志记录设施通常会被使用。`bash` 拥有许多变量，你可以在配置或运行时配置这些变量，用以修改其行为，从命令行提示符样式到日志文件中保留的行数，无一不包。

```

```

```
记住的命令数量（即，当你使用方向键时）。
```

这些变量通常在 `/etc/profile` 中设置，该文件为所有用户全局配置 `bash`。但是，用户可以通过 `~username/.bash_profile` 文件覆盖这些值，和/或通过手动使用 `export` 命令设置变量，例如 `export EDITOR=emacs`。这也是用户目录不应该是全局可读的原因之一，`bash_history` 文件可能包含许多对敌对势力有价值的信息。你也可以将文件本身设置为全局不可读、设置你的 `.bash_profile` 不记录日志、将文件设置为不可写（禁止 `bash` 写入日志）或将其链接到 `/dev/null`（这几乎是可疑用户活动或偏执用户的标志）。对于 `root` 账户，我强烈建议将 `HISTFILESIZE` 和 `HISTSIZE` 设置为 10 等低值。遗憾的是，你无法真正锁定普通用户的历史文件，你可以设置让用户无法删除它们，但除非你禁止用户使用 `export` 命令等，否则只要他们足够，就能绕过记录所有命令限制。最终，让用户在服务器上拥有交互式 `shell` 账户是一个坏主意，应该尽可能地限制。

### 密码文件与影子密码

在 UNIX 类操作系统中有有几个常量，其中之一就是 `/etc/passwd` 文件及其工作原理。为了让用户验证正常工作，你需要（至少）某种（文件）用于用户名映射、GID 到组名的映射、用户密码以及其他杂项信息。这样做的问题在于，每个人都需要访问密码文件，每当你访问它时，你如何安全地存储所有密码并保持它们可读？多年来，解决方案一直简单且有效：对密码进行哈希并存储哈希值，当用户需要验证密码时，他们输入密码，进行哈希，如果匹配则说明密码相同。这个问题的麻烦在于计算能力已经巨大增长，我可以获取你的密码文件的副本并在合理的时间内对其暴力破解。解决这个问题有几种方案：

- 使用“更好”的哈希算法 `MD5`。问题：如果其他其他内容，可能会破坏很多东西。
- 将密码存储在其他地方。问题：系统/用户仍然需要访问它们，如果没有做好准备可能会导致某些程序失败。

许多操作系统采用第一种方案，Linux 已经实现了第二种方案，被称为影子密码。在密码文件中，你的密码被替换为 `'x'`，告诉系统根据影子文件检查你的密码。任何人仍然可以读取密码文件，但只有 `root` 有访问影子文件的权限（组文件也是如此）。这似乎足够了，直到最近实现影子密码一直是一件麻烦事。你必须重新编译所有检查密码的程序（`login`、`ftpd` 等），这只需要花费一点精力。这就是为什么 `RedHat` 在依赖 `PAM` 方面表现出色。要实现影子密码，你必须做两件事。第一件相对简单，更改密码文件，但第二件可能很麻烦。你必须确保你的程序支持密码，这在某些情况下非常痛苦（这是发行版应该带 `PAM` 的 的有力理由）。由于 `RedHat` 依赖 `PAM` 进行认证，一个新的认证方案只需要添加一个 `PAM` 模块来理解它，并编辑相应程序的配置文件（例如 `login`），允许它使用该模块进行认证。不需要重新编译，不需要很多麻烦，对吧？在 `RedHat 6.0` 中，你在安装期间会被提供选择影子密码的。

### 软件管理

`RPM` 是最初由 `RedHat` 创建的软件管理工具，后来经过 GNU 化并向公众发布（http://www.rpm.org/）。它是系统管理的核心，任何管理员的首要任务之一就是安装并保持软件更新。据各种估计，大多数安全侵入事件都应归咎于弱密码和带有漏洞的旧版软件。这并不完全令人意外，但考虑到一台平均服务器恰好包含 200-400 个软件包，人们就会开始理解为什么保持软件更新是一项重大任务了。
