第11章“堡垒机实现”解释了如何配置 `Linux` 内核选项以阻止欺骗数据包。

同样，边界路由器也可以——而且通常应该——被配置为阻止第4章中识别的私有IP地址。私有IP地址的设计目的是不可路由的——也就是说，它们不应出现在公共网络上。然而，配置不当的防火墙可能会接受它们。在边界路由器上拦截这些地址提供了分层防御，可以防止配置不当的防火墙。记住，正如第3章解释的那样，分层防御的目的是防止单一错误或疏忽导致安全漏洞。

你通常应该对边界路由器以阻止具有恶意、欺骗或私有IP地址的入站数据包。你通常也应该对边界路由器以阻止具有恶意、欺骗或私有IP地址的出站数据包。这样做符合本地网络和互联网的利益。例如，如果每个被拦截的出站欺骗数据包都被阻止，欺骗将无法实现，一整类网络攻击可以被。每个阻止出站欺骗数据包的站点都会让攻击者的任务变得更加困难，从而服务整体利益。此外，如果你的边界路由器拦截了出站欺骗流量，入侵了你某个主机的攻击者就无法利用该主机对其他网络进行欺骗攻击。这种情况符合你组织的利益，从而避免了因此类使用而可能导致的资源损失和声誉损害。

## 代理

另一种重要的防火墙技术被称为`proxying`。代理的基本思想是委托。与其允许两个主机直接通信，代理代理强制它们通过一个中介（即`proxy`）进行通信。有时，代理被称为`gateway`。但因为该术语也用于路由语境，我倾向于避免使用它以及其带来的潜在混淆。

图5-4说明了代理的工作原理。代理可以用于保护客户端或服务器。保护服务器的代理有时被称为反向代理。

![](img/0f69b2a8749a24b957044e9f26f2d5b4_186_0.png)

图5-4：代理

如果你比较代理和数据包转发，你会发现它们具有相似的特征。两者都涉及一个中间主机——路由器或代理——它允许其他主机通信。对`proxy`术语的各种精确定义旨在澄清这种区别。常用的定义认为，数据包转发将客户端的数据包传递给服务器，而代理则涉及代表客户端生成并发送一个新的数据包。有时，会区分两种代理：

- `Circuit-level`
- `Application-level`

电路级代理像数据包过滤器一样检查IP地址和报头。应用级代理检查数据包的内容。由于电路级代理与数据包过滤器区别很小，将它们称为数据包过滤器并将`proxy`术语留给通常被称为应用级代理的内容是合理的。

### 第二部分：防火墙的设计与实现

应用级代理——或者简单地如我们所说的代理——比数据包过滤器更复杂。因为代理理解嵌入在数据包内容中的应用程序协议，代理可以分析客户端发出的请求并接受或拦截它们。例如，当一个请求跨越多个数据包传输时，数据包过滤器无法正确判断该请求是否经过授权的。数据包过滤器只能检查每个数据包的IP地址和数据包报头，这些无法显示应用程序的状态。代理可以在决定数据包命运之前检查并验证请求的每一个方面。

此外，代理可以通过隐藏其身份来保护客户端或服务器。由于其他主机与代理通信，它们必须知道代理的IP地址。但它们不需要知道主机的IP地址，主机可能是可路由的IP地址。

`Squid`是一种流行的`HTTP`代理，它可以代表客户端或服务器工作，它理解`HTTP`协议，因此可以检查请求的URL。`Squid`比数据包过滤器更全面地查看数据，拦截请求或重写URL来保护网络免受攻击。

另一种流行的代理示例是`SMTP`邮件传输代理。从本质上，邮件需要从`SMTP`服务器转发到`SMTP`服务器，每个中间服务器都充当接受或拦截消息的代理。

另一个示例，Red Hat `Linux`包含的`IPTables`防火墙包含一个针对`FTP`协议的代理，名为`conntrack_ftp`的模块。该模块监控`FTP`服务器和客户端之间的流量。由于该模块理解`FTP`协议，它可以拦截并分析告知`FTP`主机应使用的数据端口的消息。代理会自动调整连接表，以识别与通过命令建立的连接相关的数据端口流量。这种分析消息的能力允许防火墙打开正确的数据端口，但仅针对请求它的`FTP`主机。

图5-5展示了表5-1和图5-3所示防火墙技术中的代理过滤器。注意，代理提供的安全性可能比数据包转发或过滤更高，但需要额外的资源。

## 网络地址转换 `NAT`

网络地址转换（`NAT`）最初的设计是为了通过让多个主机共享单个IP地址来规避可路由IP地址的成本和稀缺。然而，`NAT`在网络安全方面有重要的应用。`NAT`是一种由路由器或防火墙执行的简单数据包过滤操作，通过修改数据包的源或目的IP地址。在目的`NAT`中，修改目的IP地址。在源`NAT`中，修改源地址。

![](img/0f69b2a8749a24b957044e9f26f2d5b4_188_0.png)

图 5-5：数据包过滤与代理

为了了解 `NAT` 如何使用，请考虑图 5-6 给出的目的 `NAT`（destination `NAT`）示例。在图中，客户端向 IP 地址为 192.0.34.72 的主机的邮件服务（端口 25）和 Web 服务（端口 80）发送请求。该 IP 地址与一个充当代理的 `NAT` 能力路由器关联。路由器将指向目的端口 25 的入站流量转发到主机 10.0.0.1，将指向目的端口 80 的流量转发到主机 10.0.0.2。因此，两台主机表现得就像它们共享同一个 IP 地址一样。此类主机的数量并不重要，可以是一台、两台或更多。重要的是，客户端不需要——而且无法发现——最终处理此请求的服务器的 IP 地址。除非路由器被编程为转发特定的请求，否则未经授权的请求将无法被。因此，路由器保护了其关联的服务器免受未经授权的访问。当这样使用目的 `NAT` 时，通常被称为`port forwarding`。

源 `NAT`（Source `NAT`）的工作原理类似，它隐藏的是客户端而非服务器的 IP 地址（见图 5-7）。当主机 10.0.0.1 和 10.0.0.2 向外部服务器发送请求时，路由器修改数据包，使其看起来像是来自 IP 地址 192.0.34.73 和 192.0.34.74。单个路由器可以同时执行源 `NAT` 和目的 `NAT`；然而，网络配置可能会变得复杂且容易出错。

源 `NAT` 和目的 `NAT` 统称为`static NAT`。在每情况下，与路由器关联的主机数量是固定的，公共 IP 地址与隐藏 IP 地址之间的关联是预先配置的。另一种 `NAT` 形式称为`dynamic NAT`，不需要预先配置关联。相反，当客户端请求访问外部主机时，路由器分配一个高位端口，通过该端口代理连接。这种路由器可能代表几十或数百个客户端处理数千或数万个并发连接。动态 `NAT` 有时被称为`masquerading`，因为它像源 `NAT` 一样——隐藏了客户端的身份。
