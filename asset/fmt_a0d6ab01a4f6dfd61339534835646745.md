
要提供的目录，例如 `/home` 或 `/opt/office`。目录后面是一个或多个规范。你可以以任何方式列出客户端：

*   **主机名**：提供计算机的主机名，例如 `collins.tuna.edu` 或 `collins`。如果你省略了域名，服务器假设你指的是它所在域内的计算机。
*   **IP 地址**：通过提供 IP 地址指定计算机，例如 `172.24.20.7`。这种方法对于人类理解主机名更快，但它有一个安全优势，因为它不依赖域名系统（DNS）服务器连接主机名到 IP。如果你使用主机名，攻击者可以通过首先接管 DNS 服务器来访问你的 NFS 服务器。
*   **网络地址**：通过提供 IP 地址、斜杠和掩码来指定网络。掩码可以以点分进制形式指定，也可以作为地址中网络部分的位数指定。例如，`172.24.0.0/255.255.0.0` 和 `172.24.0.0/16` 是等价的。
*   **NIS 组**：如果你的网络使用网络信息系统（NIS），你可以通过在名称前加上 `@` 符号来指定 NIS 组，例如 `@tranquility`。

在每个客户端规范之后都是一个用逗号分隔的选项列表。表 24.3 总结了这些选项中最常用的。你可以在 `exports` 帮助页中找到更多选项。

## 表 24.3：常用的 NFS 导出选项

| 选项 | 含义 |
| :--- | :--- |
| `secure` or `insecure` | 指定客户端必须从安全端口（下方编号小于 1024 的端口）连接 (`secure`) 或不需要从安全端口连接 (`insecure`)。默认值为 `secure`。 |
| `rw` or `ro` | 指定客户端对导出内容的具有读/写 (`rw`) 或只读 (`ro`) 权限。近期 Linux NFS 服务器的默认值为 `ro`，但某些版本使用了 `rw`。我建议明确做出你的选择以避免可能的混淆。 |
| `sync` or `async` | `async` 选项可以提高性能，但代价是系统崩溃时存在数据损坏的风险。对于包含版本 1.0.0 在内的 NFS 服务器，`async` 是默认值；但更多版本使用 `sync` 作为默认值。 |
| `nohide` or `hide` | 通常情况下，或者当你使用 `nohide` 选项时，NFS 服务器会“隐藏”挂载在导出目录内部的文件系统。如果你导出 `/usr` 且 `/usr/local` 是独立分区，客户端将看不到 `/usr/local` 的内容。如果你指定 `hide`，客户端将看到 `/usr/local` 中的文件和子目录。`hide` 选项可能会误导客户端，且仅对单主机规范（主机名和 IP 地址）有效。 |
| `root_squash` or `no_root_squash` | 出于安全考虑，NFS 服务器通常会“压缩”来自客户端的访问，用低权限用户 ID 替换 root 用户。你可以通过使用 `no_root_squash` 选项授予远程 root 用户访问导出目录的权限。尽管此选项具有很高的危险。 |
| `all_squash` or `no_all_squash` | 此选项指定了是否对普通用户的访问应用“压缩”。对于只读导出，压缩此类访问可以作为提供适度安全性的一种手段，这是理想的。 |

**注意**：NFS 服务器可用的选项在过去的 NFS 服务器版本之间发生过变化，未来也可能发生变化。如果对这些选项有任何问题，请查阅 `exports` 帮助页获取详情。

作为 NFS `/etc/exports` 文件的示例，请见列表 24.1。该文件定义了三个导出：`/home`、`/opt` 和 `/exports`。`/home` 导出非常直接。该导出的客户端（`collins`、`gordon`、`swigert`、`roosa` 和 `warden`）使用不带域名的主机名定义。所有这些客户端对服务器均有读/写权限。所有导出必须从安全端口连接，但 `gordon` 是该规则的例外。也许 `gordon` 运行着一个非 Unix 操作系统，该系统使用高端口进行 NFS 访问。`/opt` 导出给了两个客户端：`mattly.luna.edu` 和 `evans.luna.edu`。其中第一个客户端对共享具有完全的读/写权限，且来自该客户端的 root 权限不会被压缩。如果 `mattly` 的管理员需要能够向 `/opt` 导出添加软件，你可以使用这种配置，但这种配置是有风险的——安全问题可能允许坏分子更改此潜在敏感目录中的文件。最后，`/exports` 目录导出给 `im.luna.edu` 域内的所有计算机（但不包括其子域）以及 `172.24.0.0/26` 网络中的所有计算机。在 `im.luna.edu` 域的情况下，所有用户访问都被压缩。在两种情况下，没有客户端可以写入导出内容。

## 列表 24.1：/example /etc/exports

```
/home collins(rw) gordon(rw,secure) swigert(rw) roosa(rw) warden(rw)

/opt mattly.luna.edu(rw,no_root_squash) evans.luna.edu(ro,nohide)

/exports *.luna.edu(ro,all_squash) 172.24.0.0/26
```
