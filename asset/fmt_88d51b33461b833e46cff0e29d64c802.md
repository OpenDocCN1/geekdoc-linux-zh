
在使用系统级性能工具确定是哪一个进程在拖慢系统后，你必须应用特定进程的性能工具来确定该进程的行为模式。Linux 提供了一系列丰富的工具，用于跟踪进程和应用程序性能的重要统计数据。

读完本章后，你应该能够：

- 确定应用程序的运行时间是是消耗在内核态还是用户态。
- 确定应用程序正在调用哪些库和系统调用，以及这些调用花费了多久。
- 对应用程序进行性能分析（Profile），以确定哪些源代码行和函数耗时最长。

## 4.1. 进程性能统计

分析应用程序性能的工具多种多样，并且在 Unix 早期就以各种形式存在了。理解应用程序如何与操作系统、CPU 和内存系统进行交互，对于理解其性能至关重要。大多数应用程序并不是自包含的，它们会调用 Linux 内核和不同的库。对 Linux 内核的调用（或系统调用）可能像“我的 PID”一样简单，也像“从磁盘读取 12 块数据”一样复杂。不同的系统会有不同的性能影响。因此，库调用可能像内存分配一样简单，也像图形创建一样复杂。

### 4.1.1. 内核时间与用户时间

应用程序消耗时间最基础的划分是内核时间和用户时间。内核时间是消耗在应用程序代码或库代码中的时间量。Linux 拥有如 `top` 和 `ps` 等工具，可以（适当地地）启用应用程序是将时间花在应用程序代码还是内核代码上。它还拥有如 `profile` 和 `strace` 等命令，允许你跟踪代表进程执行了哪些内核调用，以及这些调用花费了多久才完成。

### 4.1.2. 库时间与应用程序时间

任何即使只有微小复杂性的应用程序都依赖系统库来执行复杂操作。这些库可能会导致性能问题，因此能够看到应用程序在特定库上花费了多少时间是非常重要的。虽然直接修改库的源代码来修复问题并不总是可行，但可能更改应用程序代码调用不同或更少的库函数。`ltrace` 命令和 `profile` 工具集提供了一种在应用程序使用库时分析库性能的方法。Linux 加载器 `ld` 内内置的工具可以帮助你确定使用许多库如何减慢应用程序的启动时间。

### 4.1.3. 细分应用程序时间

当已知应用程序是瓶颈时，Linux 提供了工具允许你对应用程序进行性能分析，以确定时间在应用程序内部消耗在哪里。如 `gprof` 和 `profile` 等工具可以生成应用程序的分析报告，精确指出哪行源代码导致了大量时间的消耗。

## 4.2. 工具

Linux 拥有多种工具来帮助确定应用程序的哪些部分是 CPU 的主要使用者。本节描述了这些工具。

### 4.2.1. time

`time` 命令在测试命令性能时执行基本功能，但它通常是首选考虑的地方。`time` 命令像一个秒表，它知道执行一个命令需要多久。它测量三种时间：首先，它测量实际时间或经过时间（elapsed time），即程序启动到完成执行之间的时间。接下来，它测量用户时间（user time），即 CPU 代表程序执行代码所花费的时间。最后，`time` 测量系统时间（system time），即 CPU 代表应用程序在系统或内核代码中花费的时间。

#### 4.2.1.1 与 CPU 性能相关的选项

`time` 命令（见表 4-1）按如下方式被调用的：

```
time [-v] application
```

### 表 4-1. time 命令行选项

| 选项 | 解释 |
| :--- | :--- |
| -v | 这将呈现程序时间和统计信息的详细显示。某些统计数据为零，但与 Linux 内核 v2.4 相比，内核 v2.6 有更多有效的统计数据。 |

大多数有效统计数据在标准模式和详细模式下都存在，但详细模式为每个统计数据提供了更好的描述。

对应用程序进行计时，并在完成后，关于其 CPU 使用情况的信息将显示在标准输出上。表 4-2 描述了 `time` 命令提供的有效输出。其余部分未被测量且始终显示为零。

### 表 4-2. CPU 特定 time 输出

| 列 | 解释 |
| :--- | :--- |
| User time (seconds) | 应用程序消耗的 CPU 秒数。 |
| System time (seconds) | CPU 在系统代码中消耗的秒数。 |
| Elapsed (wall clock) [mm:ss] | 程序启动到完成的经过时间（墙钟时间）。 |
| Percent of CPU | 应用程序占用 CPU 的百分比。 |

## 4.3. 章节总结

本章关注了系统级内存性能指标。这些指标主要展示了操作系统如何使用内存，而不是特定的应用程序。

本章演示了诸如 `sar` 和 `vmstat` 等工具如何用于从运行中的系统里提取这些系统级内存性能信息。这些工具的输出指示了系统整体是如何使用可用内存的。下一章描述用于调查单个进程 CPU 使用情况的可用工具。

## 5.2. 内存性能工具

本节将介绍各种内存性能工具，这些工具可以帮助你调查特定应用程序是如何使用内存子系统的，包括进程正在使用的内存数量和不同类型、内存何时被分配，以及进程使用处理器缓存的效率。

### 5.2.1. ps

`ps` 是一个跟踪进程动态内存使用的极佳命令。除了已经提到的 CPU 统计信息外，`ps` 还提供了关于应用程序所用内存量以及该内存使用如何影响系统的详细信息。

#### 5.2.1.1 与内存性能相关的选项

`ps` 有许多选项，并可以检索有关运行应用程序状态的许多统计数据。正如你你在上一章中看到的，`ps` 可以检索进程正在使用的 CPU 的信息，也可以检索关于进程正在使用的内存数量和类型的信息。可以使用以下命令行来调用它：

```
[-o vssz,rss,tsiz,dsiz,majflt,minflt,pmem,command] <PID>
```

表 5-1 描述了 `ps` 可以为指定的 PID 显示的不同类型的内存统计数据。

#### 表 5-1. ps 命令行选项

| 选项 | 解释 |
| - | - |
| -statistic | 允许精确指定你想要跟踪的进程统计数据。不同的统计数据用逗号分隔的列表指定，且没有空格。 |
| vssz | 静态：虚拟大小（virtual size）是应用程序使用的虚拟内存量。由于 Linux 只在应用程序尝试使用时才分配物理内存，因此它的值可能大于应用程序使用的物理内存量。 |
| rss | 静态：驻存大小（resident size）是应用程序当前使用的物理内存量。 |

## 5.3. 本章总结

本章介绍了用于诊断内存性能问题的各种 Linux 工具。它演示了显示应用程序消耗多少内存（`ps`/`/proc`）以及应用程序内部哪些函数正在分配内存（`memprof`）。它涵盖了可以监控缓存和内存子系统的工具（`cachegrind`、`kcachegrind` 和 `profile`）。最后，描述了一个监控共享内存使用的工具（`ipcs`）。结合使用这些工具，可以跟踪每一次内存分配、这些分配的大小、在应用程序中的功能位置，以及应用程序在访问这些分配时使用内存子系统的效率。

# 第 6 章 性能工具：磁盘 I/O

本章涵盖了帮助你评估磁盘 I/O 子系统使用情况的性能工具。这些工具可以显示正在使用哪些磁盘或分区、每个磁盘处理多少 I/O，以及发送到这些磁盘的 I/O 请求等待处理需要多久。

读完本章后，你应该能够：

- 确定系统中磁盘 I/O 的总量和类型（读/写）（`vmstat`）。

- 确定特定磁盘处理 I/O 请求的效率（`iostat`）。
- 确定哪些进程正在使用一组文件（`lsof`）。
