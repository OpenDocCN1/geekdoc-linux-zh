### 进程快照：ps

另一个获取进程信息非常有用的命令是 `ps`。`top` 提供的是动态信息，而 `ps` 是静态的。

如果不带参数调用，`ps` 的输出是非常离散的，并且与当前 shell 的进程相关：

```bash
$ ps
PID TTY             TIME CMD
2318 pts/0          00:00:00 bash
2443 pts/0          00:00:00 ps
```

显示的信息与进程标识符（`PID`）、运行进程的终端（`TTY`）、进程消耗的 CPU 时间（`TIME`）以及启动进程的命令（`CMD`）。

`ps` 一个实用的开关是 `-f`，它显示全格式列表：

```bash
$ ps -f
UID    PID PPID  C STIME TTY     TIME CMD
carol 2318 1682  0 08:38 pts/1  00:00:00 bash
carol 2443 2318  0 08:46 pts/1  00:00:00 ps -f
```

与其他开关结合，`-f` 显示了父子进程之间的关系：

```bash
$ ps -uf
USER     PID %CPU %MEM VSZ   RSS TTY     STAT    TIME    COMMAND
carol 2318 0.0 0.1 21336 5140 pts/1   Ss      08:38   0:00 bash
carol 2492 0.0 0.0 38034 3352 pts/1   R       08:51   0:00 -uf
carol 1780 0.0 0.1 21440 5412 pts/1   Ss      08:28   0:00 bash
carol 2291 0.0 0.7 305352 28736 pts/0   S1+     08:35   0:00 emacs index
```

### /proc 目录中的进程信息

我们已经见过了 `/proc` 文件系统。`/proc` 为系统中的每个运行进程包含一个数字命子目录（该数字是进程的 PID）：

```
carol@debian:~# ls -l /proc
1 108 13 17 21 37 41 665 8 9
10 109 14 173 22 28 355 42 7 804 915
103 111 14 180 23 29 356 428 749 810 918
104 111 14 181 24 3 367 432 75 811
105 112 14 199 25 244 340 433 768 83
106 115 15 195 25 350 371 5 797 838
107 102 17 26 353 404 507 798 899
(...)
```

因此，关于特定进程的所有信息都包含在其目录中。让我们列出第一个进程的内容——该 PID 是 1（为了可读性，输出已截断）：

```
### ls /proc/1/
attr      cmdline        environ mem     ns
autogroup comm           exe        limits   mountinfo numa_maps
auxv       coredump_filter fd         loginuid counts  oom_adj
...
```

你可以检查——例如——进程的可执行文件：

```
### cat /proc/1/cmdline; echo
```

`/sbin/init`

如你所示，启动进程层级的二进制文件是 `/sbin/init`。

> 注意 命令可以使用分号 (`;`) 拼接。上方使用 `echo` 命令的作用是提供一个换行。尝试直接运行 `cat /proc/1/cmdline` 来查看区别。

### 系统负载

系统上的每个进程都可能消耗系统资源。所谓的系统负载（system load）试图将系统的总负载聚合到单一的数值指标中。你可以通过 `uptime` 查看当前负载：

```
$ uptime 22:12:54 13 days, 20:26, 1 user, load average: 2.91, 1.59, 0.39
```
