
Kerberos 验证系统未随 Postgres 分发。Kerberos 版本通常作为操作系统供应商提供的可选软件可用。此外，可以通过 MIT Project Athena 获取源码分发。

注意：即使你的供应商提供了版本，你可能希望获得 MIT 版本，因为某些供应商部分可能被故意削弱或导致与 MIT 版本无法互操作。

位于美国和加拿大以外的用户注意，Kerberos 中实际加密代码的分发受美国政府出口条例的限制。

有关你的 Kerberos 的查询应指向你的供应商或 MIT Project Athena。注意，FAQL（常见问题列表）会定期发布在 Kerberos 邮件列表（发送邮件订阅）以及 USENET 新闻组中。

# 安装

Kerberos 本身的安装在 Kerberos 安装说明中有详细介绍。请确保服务器密钥文件（`srvtab` 或 `keytab`）能够被 Postgres 账户读取。

Postgres 及其客户端可以通过将文件 `src/Makefile.global` 中的 `KRBVERS` 变量设置为适当的值，从而编译为使用版本 4 或版本 5 的 MIT Kerberos 协议。你也可以更改 Postgres 寻找相关库、头文件及其自身服务器密钥文件的位置。

编译完成后，Postgres 必须注册为 Kerberos 服务。有关注册服务的更多信息，请参阅 Kerberos 操作说明和相关手册页。

# 操作

初始安装后，Postgres 应该能以正常 Kerberos 服务的方式运行所有方式。有关身份验证使用的详细信息，请参阅 PostgreSQL 用户指南中关于 `postmaster` 和 `psql` 的参考章节。

在 Kerberos 版本 5 的书中，对用户和服务的命名有如下假设（另见表 9:1）：

- 假设用户主体名称 (`anames`) 的第一个部分包含实际的 UNIX/Postgres 用户名。
- 假设 Postgres 服务有两个部分：服务名和主机名，按照版本 4 的方式进行规范一化（即删除所有域名后缀）。

# 环境 - 从 UNIX/Linux 使用 Postgres

直接从 UNIX shell 执行的所有 Postgres 命令都在 `.../bin` 目录中。将此目录包含在你的搜索路径中将执行命令变得更容易。

每个站点存在一组系统目录。这些包括一个类 (`pg_user`)，其中包含每个有效 Postgres 用户的实例。该实例指定了一组 Postgres 权限，例如作为 Postgres 超用户的操作能力、创建和销毁数据库的能力以及更新系统目录的能力。在类中安装了适当的实例之前，UNIX 用户无法对 Postgres 执行任何操作。通过在适当的类上运行查询可以获得有关系统目录的更多信息。

## 启动 Postmaster

除非 `postmaster` 进程正在运行，否则数据库不会发生任何事情。作为站点管理员，在启动 `postmaster` 之前，有许多你应该记住的事情。这些内容在手册的安装章节中讨论。如果你尝试启动一个应用程序，而它抱怨无法连接到 `postmaster`，你必须返回并确保你的环境设置妥当。

`postmaster` 偶尔会打印对排错非常有用的消息。如果你希望看到这些消息，可以使用 `-d` 启动它：

```
% postmaster -d
```

## 使用 pg_options

打印到 syslog 的消息使用 `LOG_LOCAL0` 设施。syslog 的可以使用选项控制。遗憾的是，许多函数直接调用 `printf()` 将消息打印到 stdout 或 stderr，这种输出可以重定向到 syslog 或包含时间戳。建议所有的 `printf` 调用都使用 `PRINT` 宏并将输出改为 `EPRINTF`，以便我们可以统一控制输出。

打印到 stdout 或 stderr 的消息带有包含后端 pid 的时间前缀：

```
#timestamp #pid
980127.17:52:14.173 [2271] StartTransactionCommand
980127.17:52:14.174 [2271] ProcessUtility: drop table t;
980127.17:52:14.186 [2971] SIIncNumEntries: table is 70% full
980127.17:52:14.186 [2986] Async_NotifyHandler
980127.17:52:14.186 [2986] Waking up sleeping backend process
980127.19:52:14.292 [2986] Async_NotifyFrontEnd done
980127.19:52:14.466 [2986] Async_NotifyFrontEnd done
980127.19:52:14.466 [2986] Async_NotifyHandler done
```

这提高了日志的可读性，并允许人们确切知道哪个后端在何时做了什么。它使得编写简单的 awk 或 perl 脚本变得更容易，这些脚本监控日志来检测数据库错误或问题，或计算事务时间统计。

所有 `pg_options` 在启动时都初始化为零。新的或修改的选项将在后端启动时被读取。要使所有后端的任何更改生效，我们需要向 `postmaster` 发送 `SIGHUP`。我们也可以通过直接向特定后端发送 `SIGHUP` 来仅激活该后端的更改。

`pg_options` 也可以通过 Postgres 的 `-T` 开关指定：

```
% postmaster -T "verbose=2,query,host-"
```

请注意，`keyword` 也可以是 `backend/utils/misc/trace.c` 文件中定义的选项名称的缩写。

例如，我的 `pg_options` 文件包含以下值：

```
verbose=2
query
hostlookup
showportnumber
```

# 可识别的选项

当前定义的选项如下：

- `all`

  全局跟踪标记。允许的值有：

  `0`

  单独启用跟踪消息

  `1`

  启用所有跟踪消息

  `-1`

  禁用所有跟踪消息

- `verbose`

  详细程度标记。允许的值有：

  `0`

  不发送任何消息。这是默认值。

  `1`

  打印信息消息。

  `2`

  打印更详细的信息消息。

- `query`

  查询跟踪标记。允许的值有：

  `0`

  不打印查询。

  `1`

  用一行打印压缩后的查询。

  `4`

  打印完整的查询语句。

  `plan`

  打印查询计划。

  `parse`

  打印解析器输出。

  `rewritten`

  打印重写后的查询。

  `parserstats`

  打印解析器统计信息。

  `plannerstats`

  打印规划器统计信息。

  `executorstats`

  打印执行器统计信息。

  `shortlocks`

  目前未使用，但未来启用某些功能时需要。

  `locks`

  跟踪锁。

  `userlocks`

  跟踪用户锁。

  `spinlocks`

  跟踪自旋锁。

  `notify`

  跟踪通知函数。

  `malloc`

  目前未使用。

  `palloc`

  目前未使用。

  `lock_debug_oidmin`

  由锁跟踪的最小关系 OID。

  `lock_debug_relid`

  如果不为零，则为锁跟踪的关系 OID。

  `lock_read_priority`

  目前未使用。

  `deadlock_timeout`

  死锁检查计时。

  `syslog`

  syslog 标记。允许的值有：

  `0`

  消息发送到 stdout/stderr。

  `1`

  消息发送到 stdout/stderr 和 syslog。

  `2`

  消息仅发送到 syslog。

  `hostlookup`

  在 `ps_status` 中启用主机名查找。

  `showportnumber`

  在 `ps_status` 中显示端口号。

  `notifyunlock`

  `notify` 之后 `pg_listener` 的解锁。

  `notifyhack`

  从 `pg_listener` 中删除重复元组。

# 安全

数据库安全在多个级别得到了解决：

- 数据库文件保护。存储在数据库中的所有文件都受到保护，Post 超级用户账户以外的账户无法读取。
- 默认情况下，客户端到数据库服务器的连接仅通过本地 UNIX 套接字允许，而不通过 TCP/IP 套接字。后端必须使用 `-i` 选项启动以允许非本地客户端连接。
- 可以通过 `PG_DATA` 中的 `pg_hba.conf` 文件通过 IP 地址和/或用户名来限制客户端连接。
