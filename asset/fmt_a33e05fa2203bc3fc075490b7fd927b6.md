### 引言

本节将关注 Linux 系统账户、访问控制和安全性的基本术语，Linux 系统中用于基本访问控制以及支持用户和组账户的命令行界面 (CLI) 工具，包括用于权限提升的工具。Linux 系统的基本安全模型自 Unix，尽管已有五十年历史，但与一些较新的操作系统相比仍然非常有效。现代 Linux 桌面环境简化了用户的创建和管理，甚至在登录时（显示和其他服务）时自动分配访问控制——几乎不需要手动干预。然而，理解底层 Linux 的概念是非常重要的。

### 账户

安全涉及许多概念，其中最常见的是访问控制概念。在处理所有权和权限等访问控制之前，必须理解 Linux 用户账户的基本概念，这些账户被分为几种类型。Linux 系统上的每个用户除了登录信息（如用户名和密码）外，都有一个关联账户，这还定义了用户如何以及在何处与系统交互。权限和访问控制定义了每个用户操作的“边界”。

### 标识符 (UID/GIDs)

用户标识符和组标识符 (`UID`/`GID`) 是账户的基本引用。早期的实现限于 16 位整数（0 到 65535 值），但 21 世纪的系统支持 64 位 `UID` 和 `GID`。用户和组是独立枚举的，因此同一个 ID 可以同时代表用户和组。每个用户不仅有一个 `UID`，还有一个主 `GID`。用户的主 `GID` 是该用户独有的，可能被任何其他用户使用。除了这些主组外，每个用户可以是其他组的成员。在 Linux 系统上，默认每个用户都会分配到一个与其用户名同名的组，其 `GID` 等于 `UID`，例如，创建一个名为 `root` 的新用户，默认其默认组为 `root`。

### 超用户账户

在 Linux 上，超级账户是 `root`，其 `UID` 始终为 0。超级用户有时被称为系统管理员，对系统（包括其他用户）拥有无限的访问和控制权限。超级用户的默认组 `GID` 为 0，名称也为 `root`。超级用户的主目录是一个专用的顶层目录 `/root`，只有 `root` 本人可以访问。

### 标准用户账户

`root` 之外的所有账户技术上都是普通用户账户，但在 Linux 系统上，口语中的用户账户通常指“普通”（无特权）用户账户。它们通常具有以下属性（某些例外）：

- `UID` 从 1000 开始（4 位），尽管某些旧留系统可能从 500 开始。
- 定义的主目录，通常是 `/home` 的子目录，取决于本地配置。
- 定义的登录 shell。在 Linux 中，默认 shell 通常是 Bourne Shell (`/bin/bash`)，尽管可能提供其他 shell。

如果用户账户的属性中没有有效的 shell，则用户将无法打开交互式 shell。通常使用 `/sbin/nologin` 作为无效 shell。这可能是刻意的，如果该用户仅用于控制或 SSH 之外的服务进行身份验证，例如仅用于安全 FTP (`sftp`) 访问。

> 注意为了避免混淆，后文的用户账户仅适用于标准或普通用户账户。例如，系统账户将用于解释属于系统账户类型的 Linux 用户账户。

## 系统账户

账户通常在系统安装时预创建。这些用于不以超级用户身份运行的设施、程序和服务。在理想世界中，这些应该是所有的操作系统设施。系统账户各异，但它们的属性包括：

- `UID` 通常小于 100（2 位）或在 500-1000 之间（3 位）。
- 没有专用主目录，或者目录不在 `/home` 下。
- 没有有效的登录 shell（通常为 `/sbin/nologin`），极少数例外。

大多数系统账户永远不会登录，属性中不需要定义 shell。许多由系统账户拥有的进程由系统管理派生到自己的环境中，使用指定的系统账户运行。这些账户通常权限有限，或者更多时候没有权限。

> 注意从 LPI Linux Essentials 的角度来看，系统账户是 `UID <1000` 的 2 位或 3 位 `UID`（和 `GID`）。

## 服务账户

账户通常在安装和配置服务时创建。与系统账户类似，这些用于不以超级用户身份运行的设施、程序和服务。

在许多文档中，系统账户和服务账户是相似的，并且经常相互交互。这包括：家目录的位置通常在 `/home` 之外（如果定义了的话，与系统账户相比，服务账户更有可能拥有），并且没有有效的登录 shell。尽管没有严格的定义，但系统账户和服务账户之间的主要区别可以总结为 `UID`/`GID`。

## 系统账户
`UID`/`GID <100`（2位数字）或 `<500-1000`（3位数字）

## 服务账户
`UID`/`GID >1000`（4位及以上数字），不是“标准”或“普通”用户账户，而是用于服务的账户，其 `UID`/`GID >1000`（4位及以上数字）

某些 Linux 发行版在 `UID <100` 范围内仍然有预留留的服务账户，它们也可以被视为系统账户，尽管它们不是在系统安装时创建的。例如，在基于 Fedora（包括 Red Hat）的 Linux 发行版中，Apache Web 服务器的用户的 `UID`（以及 `GID`）为 48，这显然是一个系统账户，尽管它拥有家目录（通常位于 `/usr/share/httpd` 或 `/var/www/html/`）。

> 从 LPI Essentials 的角度来看，系统账户的 `UID <1000`，而普通用户账户的 `UID >1000`。由于普通用户账户 >1000，这些 `UID` 也可以包含服务账户。

## 登录 Shell 和家目录

某些账户拥有登录 shell，而另一些则没有，出于安全考虑它们不需要交互式访问。大多数 Linux 发行版的默认 shell 是 Bourne Again Shell，即 `bash`，但也可能提供其他 shell，例如 C Shell (`csh`)、Korn shell (`ksh`) 或 Z shell (`zsh`) 等。

用户可以使用 `chsh` 命令更改其登录 shell。默认情况下，该命令以交互模式运行，并显示提示询问应该使用哪种 shell。答案应该是 shell 二进制文件的完整路径，例如：

```
$ chsh
```
更改 emma 的登录 shell
输入新值，或按回车使用默认
Login Shell [/bin/bash]: /usr/bin/zsh

你也可以在非交互模式下运行该命令，使用 `-s` 参数后跟二进制文件的路径，如下：

```
$ chsh -s /usr/bin/zsh
```

大多数账户都有定义的家目录。在 Linux 上，这通常是用户账户拥有保证写权限的唯一位置，但也有例外（例如临时文件区域）。然而，出于安全考虑，某些账户被刻意设置为即使对其自己的家目录也没有写权限。

## 获取有关用户的信息

在 Linux 系统上，列出基本用户信息是常见的日常操作。在某些情况下，用户需要切换用户并提升权限以完成特权任务。

即使是用户也有能力以下命令从命令行列出属性和访问权限。在限制上下文下的基本信息并不是特权操作。

在命令行列出用户的当前信息只需要简单的双字母命令 `id`。其输出结果将根据你的登录 ID 而变化：

```
$ id

uid=1024(emma) gid=1024(emma) 1024(emma),20(games),groups=10240(netusers),20480(netadmin)

context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
```
