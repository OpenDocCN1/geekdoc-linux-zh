### `/etc/group`

`/etc/group` 文件包含由冒号（`:`）分隔的字段，存储了系统中各组的基本信息。它有时被称为“组文件”。每行的语法为：

> `NAME:PASSWORD:GID:MEMBERS`

其中：

### NAME

是组名，如 `root`、`users`、`emma` 等。

### PASSWORD

可选组密码哈值的旧留位置。几乎总是 `x`，表示密码（如果定义）存储在 `/etc/gshadow` 文件中。

### GID

组 ID `GID`，例如 `0`、`99`、`1024`。

### MEMBERS

一个逗号分隔的用户名列表，表示该组的成员，如 `jsmith`、`emma`。

> 组密码的范围超出了本节范围，但如果定义了密码哈希，它存储在 `/etc/gshadow` 文件中。这也超出了本节范围。

### `/etc/shadow`

下表列出了存储在 `/etc/shadow` 文件中的属性，通常被称为“shadow”文件。该文件包含由冒号（`:`）分隔的字段。尽管该文件有很多字段，但除前两个之外都超出了本节范围。

该文件的行语法为：

```
USERNAME:PASSWORD:LASTCHANGE:MINAGE:MAXAGE:WARN:INACTIVE:EXPDATE
```

其中：

### USERNAME

用户名（与 `/etc/passwd` 相同），如 `root`、`nobody`、`emma`。

### PASSWORD

密码的单向哈希，包括之前的 `salt`。例如：`!!$1$01234567$ABC...`, `$6$012345789ABCDEF$012`

### LASTCHANGE

自 `epoch` 起上次修改密码的天数，例如 `17909`。

### MINAGE

最小年龄（天）。

### MAXAGE

最大年龄（天）。

版本：2023 | Linux 基础 (版本 1.6) | 主题 5：安全与文件权限

### WARN

密码过期前的警告天数。

### INACTIVE

过期后的最大天数。

### EXPDATE

密码过期日期，自 `epoch` 起的天数。

在下面的示例中，你可以看到 `/etc/shadow` 的一个条目：

```
emma:$6$012345789ABCDEF$012....17909:0:99999:7:-1:
```

注意

`shadow` 文件被设计为仅允许特定用户读取，认证服务可以读取，或者超级用户可以通过其他命令进行修改。为了缓解密码在某个系统中被破解的问题，Linux 系统会在每个密码上使用随机的“salt”。因此，即使密码相同，一个系统上的用户哈希值与另一个系统上的不同。

在 `/etc/shadow` 文件中，密码可能有几种形式。这些形式通常包括：

`!!`

这意味着一个“已禁用”账户（无法进行身份验证），没有存储密码哈希。

`!S012345675ABC...`

一个“已禁用”账户（由于开头的感叹号），存储了之前的哈希函数、`salt` 和哈希字符串。

`# $S$0123456789ABC$012...`

一个“已启用”账户，带有哈希函数、`salt` 和哈希字符串。

哈希函数、`salt` 和哈希字符串由美元符号（`$`）引导分隔。`salt` 的长度必须在八到十六（8-16）个字符之间。常见的三个示例如下：

`# $S$012345675ABC...`

MD5 `1` 的哈希函数，示例长度为八。

`# $S$01234567ABCDS$012...`

SHA256 `5` 的哈希函数，示例长度为十二。

`# $S$01234567ABCDS$012...`

SHA512 `6` 的哈希函数，示例长度为十二。

> MD5 哈希函数在当今（2010 年及以后）的 ASIC 甚至通用计算 SIMD 性能面前被认为加密是不安全的。例如，美国联邦处理标准 `FIPS` 不允许将 MD5 用于任何加密函数，仅用于极有限的验证方面，但不用于数字签名或类似目的的完整性。

从 LPI 基础目标和考试的角度来看，只需理解本地用户的密码哈希值仅存储在 `/etc/shadow` 文件中，该文件仅允许特定用户读取，认证服务可以读取，或者超级用户可以通过其他命令进行修改。
