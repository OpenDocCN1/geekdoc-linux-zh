
```c
typedef (*XmsConversionProc());
typedef XmsConversionProc *XmsFuncListPtr;
/* 以 NULL 结尾的函数指针列表*/

typedef struct _XmsColorSpace {
  char *prefix;
  XmsColorFormat format;
  XmsParseStringProc parseString;
  XmsFuncListPtr from_CIEZY;
  XmsFuncListPtr to_CIEZY;
  int inverse_flag;
} XmsColorSpace;
```

`prefix` 成员指定指示颜色字符串属于该颜色空间格式的前缀。例如，用于 CIE XYZ 的字符串 `"ciezy"` 或 `"CIEZY"`，以及用于 RGB 的 `"rgb"` 或 `"RGB"`。该前缀不区分大小写。`format` 成员指定颜色规范格式。未注册颜色空间的格式在运行时分配。`parseString` 成员包含一个指向可以解析颜色字符串结构的函数指针。该函数返回一个整数（`int`）：成功则返回非零，否则返回零。`from_CIEZY` 和 `to_CIEZY` 成员包含指向以 `NULL` 结尾的函数指针列表的指针。当顺序执行函数列表时，它会将 `XmsColorStructure` 中指定的颜色转换为当前颜色空间格式/从 CIE XYZ 格式转换。每个函数返回一个整数（`int`）：成功则返回非零，否则返回零。尽管显式地，虽然在 CCC 中可以找到白点。`inverse_flag` 成员如果不为零，则指定对于 CIEZY 中列出的每个函数，都可以在 CIEZY 中找到其反函数，使得：

给定：`n` = 每个列表中函数的数量

```
for each i, such that 0 <= i < n
  from_CIEZY[n - i - 1] 是 to_CIEZY[i] 的反函数.
```

这使得 Xlib 能够使用指定的转换路径，尽可能跳过 CIE XYZ（例如，从 TekHvC 到 CIE L*u*v*）。

## 字符串解析回调

`XmsColorSpace` 结构中用于为特定颜色空间解析颜色字符串的回调函数必须遵循以下软件规范：

```c
Status XmsParseStringProc(color_string, color_return);
```

`color_string` 指定要解析的颜色字符串。

`color_return` 返回该颜色空间格式的颜色规范。

## 颜色规范转换回调

`XmsColorSpace` 结构中用于在设备无关空间之间转换颜色规范的回调函数必须遵循以下软件接口规范：

```c
Status ConversionProc(ccc, white_point, colors_in_out, ncolors);
```

`ccc` 指定 CCC。

`white_point` 指定与颜色规范关联的白点。`pixel` 成员应被忽略，并在返回时整个结构保持不变。

`colors_in_out` 指定一个颜色规范数组。`pixel` 成员应被忽略，并在返回时保持不变。

`ncolors` 指定颜色规范数组中 `XmsColor` 结构的数量。

`XmsColorSpace` 结构中用于将颜色规范转换为设备空间或从设备空间转换的回调函数必须遵循以下软件接口规范：

```c
Status ConversionProc(ccc, colors_in_out, ncolors, compression_flags_return([]));
```

`ccc` 指定 CCC。

`colors_in_out` 指定一个颜色规范数组。`pixel` 成员应被忽略，并在返回时保持不变。

`ncolors` 指定颜色规范数组中 `XmsColor` 结构的数量。

`compression_flags_return` 返回一个指示压缩状态的布尔数组。如果提供了非空句指针且给定索引处的颜色被压缩，则应在该数组的相应索引处存储 `True`；否则，不修改该数组。

转换函数全局可用，用于其他颜色空间。Xlib 提供的转换函数如下：

| 函数 | 从转换 | 转换到 |
| --- | --- | --- |
| `XmsCIELabToCIEXYZ` | `XmsCIELabFormat` | `XmsCIEXYZFormat` |
| `XmsCIELuvToCIEUV` | `XmsCIELuvFormat` | `XmsCIEXYZFormat` |
| `XmsCIEXYZToCIELab` | `XmsCIEXYZFormat` | `XmsCIELabFormat` |
| `XmsCIEXYZToCIEuvY` | `XmsCIEXYZFormat` | `XmsCIEUvFormat` |
| `XmsCIEXYZToCIExyY` | `XmsCIEXYZFormat` | `XmsCIExyFormat` |

## 函数集

只有当输出设备不符合现有函数集或需要额外的设备依赖空间时，才需要创建额外的函数集。函数集主要由一组设备依赖结构和用于读取和存储特征化数据的手段组成。该结构的句柄（即通过全局变量）通常对客户端可见。

如果函数集使用设备依赖的 `XmsColorSpace` 结构，它将透明地处理到颜色管理系统中。函数集可以共享设备依赖空间的 `XmsColorSpace` 结构；但函数集只能引用其中一个。这些 `XmsColorSpace` 结构在转换到和从 XYZ 转换方面有所不同，以针对函数集定制。

```c
typedef struct _XmsFunctionSet {
XmsColorSpace **DDColorSpaces;
XmsScreenInitProc screenInitProc;
XmsScreenFreeProc screenFree_proc;
} XmsFunctionSet;
```

`DDColorSpaces` 成员指向指向函数集支持的 `XmsColorSpace` 结构的 `NULL` 结尾指针列表。`screenInitProc` 成员设置为回调程序（参见下面的接口规范），用于初始化特定场景的 `XmsPerScrnInfo`。

屏幕初始化回调必须遵循以下软件接口规范：

```c
typedef Status (*XmsScreenInitProc) (display, screen_info);
```

指定到 X 服务器的连接。

指定主机服务器上相应的屏幕编号。

指定 `XmsPerScrnInfo` 结构，该结构包含每个屏幕的信息。
