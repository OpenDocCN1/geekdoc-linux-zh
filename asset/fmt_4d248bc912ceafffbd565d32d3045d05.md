# 5.2.22 确保配置了 SSH 空闲超时间隔（自动化）

配置适用性：

- 等 1 - 服务器
- 等 1 - 工作站

描述：

注意：为了说明，下面描述的两个设置仅针对连接角度的空闲连接，而不是检查用户是否活跃。空闲用户并不意味着空闲连接。SSH 绝不会刻意提供丢弃空闲用户的功能。在 8.2pl 之前的 SSH 版本中，存在一个导致这些值被用于断开空闲用户的 bug。该 bug 已存在于 8.2pl 且不再被用于断开空闲用户。`ClientAliveInterval` 和 `ClientAliveCountMax` 两个选项控制 SSH 会话的超时。直接引用 man 5 `ssh_config`：

- `ClientAliveInterval` 设置未从客户端接收数据后的超时间隔，`ssh(8)` 将通过加密通道发送消息向客户端请求响应。默认值为0，表示不向客户端发送此类消息。
- `ClientAliveCountMax` 设置在客户端活跃消息未收到响应的情况下可以发送的数量，`ssh` 将断开客户端并终止会话。默认值为3。如果 `ClientAliveInterval` 设置为15，且 `ClientAliveCountMax` 保持默认值，无响应的 SSH 客户端将在大约 45 秒后被断开。将 `ClientAliveCountMax` 设置为零禁用连接终止。

依据：

为了防止资源耗尽，应该对 `ClientAliveInterval` 和 `ClientAliveCountMax` 设置适当的值。具体来说，查看源码，`ClientAliveCountMax` 必须大于零，才能利用 SSH 丢空闲连接的能力。如果允许连接无限开启，可能会被用于 DDOS 攻击，或者在不可靠的网络上发生简单的资源耗尽。

此处设置的示例为 45 秒超时。请咨询您的站点网络超时策略，并进行适当应用。

审计

运行以下命令并验证 `ClientAliveInterval` 大于零：

```bash
# sshd -T -C user-root -c host="$(hostname)" -c addr="$(grep $ $(hostname) /etc/hosts | awk '{print $1}')" | grep clientaliveinterval
```

示例输出：

```
clientaliveinterval 15
```

运行以下命令并验证 `ClientAliveCountMax` 大于零：

```bash
# sshd -T -C user-root -c host="$(hostname)" -c addr="$(grep $ $(hostname) /etc/hosts | awk '{print $1}')" | grep clientalivecountmax
```

示例输出：

```
clientalivecountmax 3
```

修复：

编辑 `/etc/ssh/sshd_config` 文件以根据站点策略设置参数。示例：

```bash
ClientAliveInterval 15
ClientAliveCountMax 3
```

默认值：

`ClientAliveInterval 0`
`ClientAliveCountMax 3`
