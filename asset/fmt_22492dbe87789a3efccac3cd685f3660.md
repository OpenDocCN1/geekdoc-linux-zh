
## 别名定义

别名定义也可以使用别名。在别名替换期间，别名定义会被重复扫描，直到无法进行进一步替换为止。然而，对于 *name* 的别名定义不能在其内部调用该 *name*；*definition* 中对 *name* 的引用被视为对内置 shell 命令或可执行文件名的引用，而不是对别名的引用。这使得你能够使用别名来重新定义系统命令或内置 shell 命令。例如：

```
% alias pg pg -cns -p"Page %d:
```

你可以使用命令历史替换语法（本章稍后部分提到的“命令历史”）来引用原始命令行——即在进行任何替换之前的命令行。例如，该命令

```bash
alias print 'pr \* | lp'
```

定义了一个别名 *print*，它使用原始命令行的所有参数 `!` 来执行该命令，然后将输出通过到 *lp* 进行打印。

要正确且有效地使用 *alias* 命令，你必须清楚别名的使用方式。当你通过输入 *alias* 命令来定义别名时，唯一发生的事情是系统将其存储在计算机内存中。稍后，当你输入一个与别名相同的命令时，C shell 会执行某种“小魔法”。你输入的命令并不会以你想要的形式执行。相反，命令名（即别名名）被别名的值所替换。结果是一段新的命令文本——第一部分是别名定义，其余部分是你输入的任何其他参数。

假设你为 *ls* 命令定义了如下别名：

```
% alias lax ls -ax
```

如果你稍后输入命令

```
% lax big*.txt
```

实际执行的命令是

```
ls -ax big*.txt
```

命令别名 `lax` 被其定义 `ls -ax` 替换。命令行上的剩余参数 `big*.txt` 在别名替换后被直接采用，产生实际执行的命令。

在别名中使用历史记录（例如，`!`, `!1::2..`）提供了额外的灵活性，允许执行的命令使用与输入时不同的顺序或形式的参数；这需要 shell 执行一些额外工作。考虑以下别名定义：

```bash
alias lsp 'ls \*|'
```

输入命令 `lsp *.cc *.csh` 会导致 `lsp` 的别名替换。符号 `!*` 导致你在行上输入的参数 `*.cc *.csh` 被插入别名中，而不是放在别名定义之后。换句话说，如果别名包含历史替换，shell 将抑制其处理别名值之后参数的正常操作。实际执行的命令是 `ls *.cc *.csh | lp`。如果没有这种特殊机制，执行的命令将是 `ls | lp *.cc *.csh`，最后的 `*.cc *.csh` 将按通常方式附加。这将导致一个不想要的结果：*lp* 命令不会打印目录列表，而是打印文件的完整内容。

因此，当你定义别名时，需要想象别名在后续命令中被替换时会发生什么。

## 删除命令别名：unalias

你可以使用 `unalias` 删除一个或多个别名。你可以通过指定名称作为参数删除特定别名，或使用模式匹配删除多个别名：

```
unalias name
unalias pattern
```

如果你指定了别名名称，只删除该别名定义。如果你指定了模式，所有匹配该模式的已定义别名将被删除。模式可以包含匹配字符 `*`、`?` 和 `[...]`。在下面的示例中，第一行删除了 `lx` 别名，第二行删除了所有定义的别名：

```
unalias lx
unalias *
```

## Shell

C shell 命令行选项提供方便的方法来修改 C shell 脚本的行为以适应你的需求。可以在命令行上指定选项，例如：

```
%sh -f
```

或者，如果你的 UNIX 版本支持 `#` 符号，你可以在脚本的第一行指定别名，如下所示：

```bash
#!/bin/csh -f
echo *
```

如果需要某个选项，命令行是提供该选项的最佳位置。如果永久需要该选项，请将其放在 `#!` 行。

除非设置了 `-c`、`-i`、`-s` 或 `-t` 选项之一，否则 C shell 假设命令行上的第一个参数是要执行的命令，每个额外的参数都是用于所执行命令的。例如，命令

```
% csh command arg1 arg2 arg3
```

会导致 C shell 执行带有三个参数（`arg1`, `arg2`, `arg3`）的命令，这些参数将被赋值给 `argv` 数组。当选择 `-i`、`-s` 或 `-c` 选项时，shell 将第一个在内的所有参数分配给 `argv` 数组。`-c` 选项允许单个命令行参数并将其视为要执行的命令列表；在执行参数字符串后，`csh` 退出。

C shell 使用命令行选项来接收执行指令。命令行选项通过此选项指示：`csh -v`。如果需要多个选项，它们前面可以只有一个连字符（`csh -fv`）或每个选项使用一个连字符（`csh -f -v`）。允许混合选项指定方法（`csh -f -vx`）。下面的命令显示了行选项与普通命令执行的混合：

```
% csh -fv command arg1 arg2 arg3
```

## 表 12.4. C shell 命令行选项。

| 选项 | 名称 | 说明 |
| --- | --- | --- |
| -b | Break | 在命令行处理中，用于 C shell 的参数和用于脚本的参数之间划分一个分隔符。`-b` 之前的命令被解释为 C 命令，`-b` 之后的命令传递给 C shell。`-b` 选项并非所有 UNIX 平台上都可用。 |

此外，shell 变量 `cpath`、`history`、`mail`、`path`、`prompt` 和 `shell` 虽然不是选项，但允许你控制如搜索命令和检查邮件等行为。更多信息请参见本章稍后部分的“使用预定义变量”。

## 命令历史记录

shell 的命令历史记录服务维护了一份之前执行过的命令列表。你可以将历史记录用于两个用途：

- 作为参考，确定你已经执行了什么操作
- 配合历史替换，作为简写，重用全部或部分之前的命令来输入新命令

### 显示命令历史记录

`history` 命令允许你打印当前命令历史的所有或选定行：

```
history [ -r ] [-h] [ n ]
```

要显示历史记录列表中当前保留的所有行，只需输入 `history` 命令（它不需要任何参数）：

```
% history
1 cd src
2 ls
3 vi foo.cc
4 cc foo.cc
5 grep '#include' foo.cc
```

shell 显示每行时会在前面带上一个行号。你可以使用行号通过历史替换机制来引用命令。假设没有之前保存的历史记录，行号从会话开始时的第 1 开始。关于 shell 变量 `savehist` 的更多信息，请参见本章稍后部分的“使用预定义变量”。

shell 维护的历史记录数量取决于 shell 可用的内存大小。除非设置了 `savehist`，否则会在会在话退出之前不会保存到外部磁盘文件中，因此容量相当有限。你可以设置 `history` 变量来指定你希望 shell 维护的历史记录数量；它会尽可能保留指定的行数及更多，你的指定仅具参考意义。`history` 的值必须是一个简单的数字才能生效。例如，设置 `history=25` 将保留至少 25 行历史记录。

> 注意：历史记录保留的是命令行——随着历史区域变满，它会删除旧行。这可能导致行包含不完整的、部分的命令。你需要谨慎使用历史替换功能，以避免调用执行不完整的命令。

要限制显示的行数，请为 `n` 指定一个正整数，将显示的行数限制为历史记录的最后 `n` 行。

指定 `-r` 选项按反序（从最近的到旧的）打印历史记录行。

`-h` 选项列出不带行号的历史缓冲区。这对于基于过去的输入创建脚本（`-h > script.csh`）或使用鼠标剪切和粘贴系列命令非常有用。

### 使用历史替换执行命令

历史替换通过 `!`（感叹号，通常称为 bang 操作符）引入命令中。在 `!` 后面添加一个或多个字符来定义你想要的特定类型的历史替换。如果后面跟着制表符、换行符、等号 `=` 或括号 `,`，则感叹号被视为普通字符。

> 注意：感叹号对其他 shell 来说普通字符，但对 C shell 来说是特殊的。在它前面加上 `\`（反斜杠）可以避免它的特殊含义，即使在硬引号字符串内部也是如此（例如，`echo \\\'` 不会回显 `!!`（上一个命令）。无论是否有任何引号，只要在命令行中找到感叹号，shell 都会尝试历史替换；只有反斜杠允许 `!` 被解释为历史替换标记。

你可以在当前 shell 输入的任何地方编写历史替换，作为命令的一部分或全部。当你输入一个包含或多个历史替换的命令时，shell 在执行替换后回显该命令，以便你可以看到实际执行的命令。（你没有机会修正命令；它在显示后立即执行）。

历史替换的最简单形式是 `!!` 和 `!number`。`!!` 符号代表整个上一条命令行。`!number` 被替换为命令历史列表中的某行号。

假设命令历史记录当前包含以下行：

```
cd src
ls
vi foo.cc
cc foo.cc
grep '#include' foo.cc
```

如果你输入命令 `!!`，shell 会完整重复 `grep` 命令。按回车执行 `grep` 命令，或者输入额外的单词以添加到 `grep` 命令的末尾：

```
% !! sna.ha
grep '#include' foo.cc sna.ha
```

现在在运行 `grep` 之后，你想编辑 `foo.cc` 文件。你可以像往常一样输入 `vi` 命令，但它在命令历史记录中几乎没有出现，仅显示为第 3 行）。历史替换提供了一个方便的快捷方式：

```
% ! 3
vi foo.cc
```

历史替换就只有这些。实际上，shell 支持表 12.5 中列出的任何形式。

## 表 12.5. 引用命令历史行的形式。

| 形式 | 替换为 |
| :--- | :--- |
| !! | 上一条命令行（命令历史的最后一行）。 |
| !number | 命令历史记录的行号。 |
| !-number | 向前的历史数量；`!-1` 等同于 `!!` |
| !string | 以字符串开头的最近历史记录行。例如，使用 `!vi` 来引用之前的 `vi`。 |
| ??string | 在行中任何位置包含字符串的最近历史记录。例如，使用 `!!foo`。 |

你可以做的远不仅仅是替换之前的命令。shell 还提供了历史操作符的扩展，允许你从历史记录中选择单个或一组单词，并将选定的单词插入当前命令中。这些扩展的形式为带有冒号 `:` 的后缀。例如，`vi,:1` 被替换为最近的 `vi` 命令的第一个参数单词。同样，`vi:3-4` 被替换为历史记录中的第 3 和第 4 个单词。你可以通过附加冒号引用来使用表 12.6 中列出的任何表达式。

## 表 12.6. 使用命令历史单词选择器。

| 表达式 | 指定 |
| :--- | :--- |
| 0 | 命令的第一个单词（通常是命令名）。 |
| n | 命令的第 n 个参数。参数从 1 开始。注意 0 指的是命令名，它实际上是行的第一个单词，而 1 指的是行的第二个单词。 |
| ^ | 等于 `:1`，第一个参数。 |
| $ | 命令的最后一个单词。 |
| % | 对于 `!string` 格式，与字符串匹配的单词。该单词选择器仅适用于 `!string` 历史引用。即使 `string` 可能只匹配了单词的一部分，它也是整个匹配单词。 |
| m-n | 多个单词替换。替换为历史记录中的 n 到 n 个单词。对于 m 和 n，请指定整数或这些特殊字符之一：`^,$` 或 `%`。 |
| m- | 从第 n 个单词开始但不包含最后一个单词的单词替换。 |
| -n | 等于 `0-n`；替换从历史记录行的第一个单词（命令名）到第 n 个单词的单词。 |

与 `m$` 相同；替换从第 m 个单词开始到该行末尾的单词。

与 `$ -` 相同；替换该行所有的参数单词。

如果你要编写的单词选择器以 `^`、`$`、`*`、`-` 或 `%` 开头，你可以省略行选择器和单词选择器之间的冒号。例如，`!vi*` 指向上一个 `vi` 命令的所有参数，与 `!vi:*` 或 `!vi:-.*` 相同。

> 注意：某些版本的 C shell 要求在 `!` 运算符和行号之间使用冒号（除非使用行号）。命令 `!3^` 会给出命令 3 的第一个参数，但 `!vi^` 将返回错误。

你可以在同一个命令中使用任意数量的单词选择器（`cp foo.cc /project/src/new; chmod -w !$!`）。可以使用不同的顺序重用上一个命令的参数，或使用出现在不同命令中的参数。例如，命令 `rm !115! 117*` 会删除早些命令中命名的文件。

在计算上一个命令的单词时，shell 会考虑引号，但使用的是在历史列表中显示的行。以下由变量或命令替换生成的 `filename` 不受影响。以下示例演示了引号和命令替换的效果：

```
echo "one two three" four
one two three four
% echo ^^
echo "one two"
one two three
% echo 'ls *'
bar.cc foo.cc
% echo !*
echo 'ls *'
bar.cc foo.cc
```
