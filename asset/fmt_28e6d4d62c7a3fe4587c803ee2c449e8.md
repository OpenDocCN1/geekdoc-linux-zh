## 使用 SSH 进行远程监控

在上一节中我们学习了“本地”，现在我们看远程。监控远程系统的最常用方法是使用安全外壳 `SSH`。`SSH` 提供了一个安全通道，可以在不安全的网络上运行命令。一旦通过 `SSH` 连接，我们就可以使用与本地进程相同的命令。

以下示例显示了如何使用 `SSH` 检查远程机器上是否存在某个进程：

```
ssh user@remotehost "ps -ef | grep processname | grep -v grep"
```

这允许我们从中央管理服务器对远程服务进行自动化监控。如果没有找到进程，随后可以通过 `SSH` 在远程主机上触发重启命令。

## 检查活跃的 Oracle 数据库

我希望在本章中至少有一个与应用程序交互的示例，我选择了 Oracle 数据库作为示例，使用 SQL+ 数据库查询。我们将通过三个步骤来检查 Oracle 数据库状态。第一步是列出 `/etc/oratab` 文件中定义的所有 Oracle 实例。该文件是用冒号分隔的（第一个字段是 Oracle 实例名称）。列表 9.4 中的函数首先检查 `/etc/oratab` 文件是否存在。如果未找到，将在用户的终端上显示通知消息，并且函数返回代码为 3。否则，将解析 `/etc/oratab` 文件以找到 Oracle 实例名称。使用 `sed` 语句结合 `^#` 符号来删除文件中所有以注释（以 `#` 开头为指定）开头的行。使用 `sed` 语句删除注释行非常简单，如下所示，以 `/etc/hosts` 文件为例。

```bash
cat /etc/hosts | sed '/^#/b' > /etc/hosts.without_beginning_comments
```

之前被注释掉行的输出显示了所有 IP 和主机名条目，但删除了这些行。`#` 是查找注释行的关键，它翻译为以 `#` 开头。查看列表 9.4 中的函数，看看我们如何使用这种技术从 `/etc/oratab` 文件中解析 Oracle 实例。

```bash
function show_oratab_instances
{
  if [ -f "$ORATAB" ]
  then
    echo "Oracle instance file $ORATAB does not exist\n"
    return 3
  else
    cat $ORATAB | sed '/^#/b' | awk -F: '{print $1}'
  fi
}
```

## 监控进程和应用程序

列表 9.4 中 `show_oratab_instances` 函数的输出是系统中定义的所有 Oracle 实例的列表。我们已经删除了注释行；接下来是 `awk` 语句提取第一个字段，指定为 `awk -F: 'print $1'`。在这个 `awk` 语句中，`-F` 指定行由冒号（:）分隔。一旦知道了字段分隔符，我们只需提取第一个字段（`$1`），即 Oracle 实例名称。

现在我们将使用列表 9.4 显示的相同函数，通过检查每个实例的进程来获取所有定义的 Oracle 实例的状态。这种技术在列表 9.5 中所示。

```bash
function show_all_instances_status
{
  for INSTANCE in $(show_oratab_instances)
  do
    ps -ef | grep ora | grep $INSTANCE | grep -v /dev/null 2>&1
    if ($? != 0); then
      echo "\n$INSTANCE is NOT currently running $(date)\n"
    else
      echo "\n$INSTANCE is currently running OK $(date)\n"
    fi
  done
}
```

**列表 9.5** `show_all_instances_status` 函数列表。

在列表 9.5 中，我们使用列表 9.4 中的函数来获取要查询系统的 Oracle 实例。在这种情况下，我们所做的只是再次使用 `ps -ef` 命令。我们需要通过对字符串 `ora` 进行 `grep` 来缩小范围。输出被管道到另一个 `grep` 语句，其中我们正在寻找循环迭代的实例名称，指定为 `$INSTANCE`。如果我们想从输出中删除任何进程，我们再添加一个 `grep -v grep`。如果整个 `ps -ef` 语句的返回代码为 0，则实例正在运行；如果返回不是 0 的任何值，则实例未运行。
