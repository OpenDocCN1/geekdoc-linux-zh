
# Environment Variables

参见 `environ(5)` 以了解影响 `mailx` 执行的以下环境变量的描述：`HOME`, `LANG`, `LC_CTYPE`, `LC_TIME`, `LC_MESSAGES`, `NLPATH` 和 `TERM`。

`DEAD` 在意外中断时保存部分邮件的文件名。默认值为 `$HOME/dead.letter`。

`EDITOR` 使用 `edit` 或 `-e` 命令时运行的命令。默认值为 `ed(1)`。

`LISTER` 在列出目录内容时使用的命令和（选项）。默认值为 `ls(1s)`。

读取标准系统信箱的初始信箱名称。默认值为 `/var/mail/username`。

`MAILRC` 启动文件的名称。默认值为 `$HOME/.mailrc`。

# mailx, mail, Mail

`MAILX_HEAD` 在每条发送的消息的正文开头包含指定的字符串。

`MAILX_TAIL` 在每条发送的消息正文末尾包含指定的字符串。

`MBOX` 用于保存已读消息的文件名。`exit` 命令会覆盖此功能，显式将消息保存到另一个文件中也是如此。默认值为 `$HOME/mbox`。

`PAGER` 用于分页输出的过滤器命令。你也可以使用此变量来指定使用的选项。默认为 `pg(1)`，如果设置了 `bsdcompat` 变量，则默认值为 `more(1)`。参见第 779 页的“内部变量”。

`SHELL` 首选的命令解释器名称。默认为 `sh(1)`。

`VISUAL` 首选的屏幕编辑器名称。默认为 `vi(1)`。

## 退出状态

当你指定 `-e` 选项时，将返回以下退出值：

- `0` 找到了邮件。
- `>0` 未找到邮件或发生错误。

否则，将返回以下退出值：

- `0` 成功完成。注意，此状态意味着所有消息均已发送，但并不保证其中任何消息已实际送达。
- `>0` 发生了错误。

## 文件

`$HOME/.mailrc`: 个人启动文件。

`$HOME/mbox`: 二级存储文件。

`$HOME/.Maillock`: 防止多个写入器写入系统邮箱的锁文件。

`/etc/mail/mail.rc`: 仅限 `mailx` 的可选启动文件。

`/etc/mail/Mail.rc`: `/usr/ucb/mail` 和 `/usr/ucb/Mail` 的 BSD 兼容系统级启动文件。

`/tmp/R[emqsx]*`: 临时文件。

`/usr/share/lib/mailx/mailx.help*`: 帮助信息文件。

`/var/mail/*`: 邮局目录。

# make — 维护、更新和生成相关程序和文件

## 摘要

```
/usr/ccs/bin/make [-d] [-dd] [-D] [-DD] [-e] [-i] [-k] [-n] [-p] [-P] [-q] [-r] [-s] [-S] [-t] [-V] [-f makefile]...[-K statefile]... [target] [macro=value]
/usr/xpg4/bin/make [-d] [-dd] [-D] [-DD] [-i] [-k] [-n] [-p] [-P] [-q] [-r] [-s] [-S] [-t] [-V] [-f makefile]...[target] [macro=value]
```

## 描述

使用 `make` 命令来减少大型项目的编译工作。使用 `makefile` 指定从源文件到目标应用程序的依赖列表。`make` 命令使用 `make` 来确定重建应用程序所需的最小重新编译。`make` 利用文件系统的修改日期来确定哪些文件比其依赖项新。然后，`make` 会重新构建并构造应用程序。

`make` 命令执行与每个目标相关的 shell 命令列表，通常用于创建或更新同名文件。`makefile` 包含描述如何使目标与其依赖项保持同步的条目。每个依赖项都是一个目标，它可以有自己的依赖项。目标、依赖项和子依赖项构成树形结构，`make` 在决定是否重建目标时会生成跟踪轨迹。

`make` 命令递归地检查每个目标与其依赖项的关系，如果你在命令行上没有提供目标参数，它将从 `makefile` 中的第一个目标项开始。在处理完所有依赖项后，如果目标文件缺失或旧于任何一个依赖项，`make` 就会重新构建它。在此版本的 `make` 中，你可以选择在用于生成目标的命令自上次构建目标以来发生变化时，将该目标视为过期。

为了构建给的目标，`make` 会执行一组被称为“规则”的命令。你可以在目标的 `makefile` 条目中显式列出此规则，也可以由 `make` 隐式提供。

如果你没有指定 `makefile` 条目，或者它没有规则，`make` 将尝试通过以下方法推导出规则，直到找到合适的规则为止。每种方法的描述见第 788 页的“读取 Makefiles 和环境”。

1. 匹配规则。
2. 从用户提供的 `makefile` 中读取的隐式规则。
3. 标准隐式规则（也称为后缀规则），通常从文件 `/usr/share/lib/make/make.rules` 读取。
4. SCCS 检索，`make` 从 SCCS 历史文件中检索最新版本（如果有）。详情请参见 `.SCCS_GET` 特殊函数的描述。
5. `.DEFAULT` 目标条目规则，如果存在该条目。

## 选项

- `-d`: 打印 `make` 选择某个目标的原因。
- `-dd`: 详细。
- `-D`: 定义宏。
- `-DD`: 定义宏。
- `-e`: 在命令返回非零状态时停止处理。
- `-i`: 忽略命令返回的错误。
- `-k`: 在命令返回非零状态时停止处理。
- `-n`: 打印命令但不执行。仅报告依赖关系而不是构建它们。
- `-P`: 打印依赖关系。
- `-q`: 仅报告依赖关系而不是构建它们。
- `-r`: 不读取默认 `makefile`。
- `-s`: 在执行命令前不打印命令行。等同于特殊目标 `.SILENT`。
- `-S`: 取消 `-k` 选项的影响。
- `-t`: 触摸目标文件（使其更新）而不是执行其规则。
- `-V`: 将 `make` 置于 SysV 模式。详情参见 `sysmake(1)`。
- `-f makefile`: 指定 `makefile`。
- `-K statefile`: 使用状态文件。

接下来，`make` 会从环境中导入变量（除非你指定了 `-e` 选项），并将它们视为已定义的宏。由于 `make` 使用其遇到的最新定义，因此 `makefile` 中的宏定义会覆盖同名的环境变量。然而，当你指定 `-e` 时，环境变量会在所有 `makefile` 被读取后才被读取。在这种情况下，环境变量的优先级高于 Makefile 中的定义。

接下来，`make` 会如上所述，读取你通过 `-f` 指定的任何 `makefile` 或名为 `Makefile` 或 `Makefile` 文件，然后如果本地目录下存在状态文件，则会读取该状态文件。如果 `makefile` 包含 `.KEEP_STATE_FILE:` 目标，则 `make` 会读取该目标后的状态文件。详情请参阅特殊目标 `.KEEP_STATE_FILE:`。

接下来（在指定 `-e` 时读取环境后），`make` 会读取作为命令行参数指定的任何宏定义。这些宏定义会覆盖 `makefile` 和环境中的定义，但仅针对目标本身。`make` 会使用最近定义的变量导出环境变量。命令行上提供的宏定义不会导出 Makefile 中的宏，除非该宏也是环境变量。如果设置了环境变量且你在命令行上定义了同名的宏，`make` 将导出其在命令行上定义的值。除非指定 `-e`，否则 Makefile 内部的宏定义优先级高于从环境中导入。`MAKEFLAGS`、`MAKE`、`SHELL`、`HOST_ARCH`、`HOST_MACH` 和 `TARGET_MACH` 是特殊情况。详见第 795 页的“特殊宏”。

# Makefile 目标项

目标具有以下格式：

```
target... [::][dependency]... [command]... [command]
```

第一行包含一个由空格分隔的以冒号或双冒号终止的目标列表。目标列表等同于每个目标都有相同格式的条目。冒号后面是依赖或依赖列表。`make` 在构建目标之前会检查此列表。你可以用分号（`;`）终止依赖列表，分号后可以跟一个 Bourne shell 命令。目标行中的后续命令以 Tab 开头，这些命令构成了构建目标的规则。
