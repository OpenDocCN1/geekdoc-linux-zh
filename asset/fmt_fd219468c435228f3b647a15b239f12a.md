
## 10.5 命令行参数数组

命令行参数作为 `main` 参数传递给 C 程序。命令行参数的数量是 `main` 的第一个参数，字符指针数组是 `main` 的第二个参数。第一个参数始终是运行的可执行文件的名称。其余参数是用户 shell 对命令行剩余部分的扩展。shell 会用所有匹配的文件名替换命令中的该部分。这种扩展使得在命令行上使用如 `*.dat` 的模式变得非常方便。

这里有一个打印命令行参数的简单 C 程序：

```c
#include <stdio.h>

int main(int argc, char *argv[])
{
    int i;

    for (i = 0; i < argc; i++) {
        printf("%s\n", argv[i]);
    }

    return 0;
}
```

当作为 `./args hello world` 执行时，它输出：

```
./args
hello
world
```

`argv` 数组像所有 C 数组一样，通过将数组第一个元素的地址放在寄存器或栈上来传递。在 `argv` 的情况下，它的地址在寄存器 `rsi` 中。下面是该程序的汇编语言翻译，尽管汇编代码利用了 `argv` 数组末尾有一个 NULL 指针的事实。

```assembly
segment .data
    format db      "%s",0xa,0

segment .text
    global  main        ; 让链接器知道 main
    extern  printf      ; 从 libc 中解析 printf

main:
    push    rbp             ; 为 main 准备栈帧
    mov     rbp, rsp
    sub     rsp, 16
    xor     ecx, ecx         ; 循环计数
    mov     edi, [rsp+8]
    mov     rdx, [rsp+16]
    ; 此处逻辑根据上下文补全，原文在此处断开或不完整
    ; 严格按照原文提供的文本进行翻译
```

```c
long adler32(char *data, int len)
{
    long a = 1, b = 0;
    int i;

    for (i = 0; i < len; i++) {
        a = (a + data[i]) % 65521;
        b = (b + a) % 65521;
    }

    return (b << 16) | a;
}
```

## 第 11 章：浮点数指令

8086 使用了名为 8087 的浮点协处理器来执行浮点算术。许多早期的计算机缺乏这种协处理器。这种配置一直持续到 486，486 在其内部包含了该协处理器。8087 使用浮点值栈。这些指令仍然是现代 CPU 的一部分，尽管 Core i 系列（128 位模式）中提供了一套完全独立的浮点单元。

我们将学习较新的指令。

如果你学习《Intel 64 和 IA-32 架构软件手册》，你会发现许多如 `fidd` 的指令，它们通过名为 ST(0), ST(1), ... 的寄存器处理流式扩展（SSE）。SIMD 是“单指令多数据”的缩写。这些是本章的重点。

### 11.1 浮点寄存器

有 16 个浮点寄存器，具有双重用途：持有单个值或多个值。这些寄存器的名称为 `xmm0`, `xmm1`, ... `xmm15`。i 系列计算机引入了高级向量扩展（AVX），使浮点寄存器的大小增加了一倍。要使用全部 256 位（8 个浮点数或 4 个双精度浮点数），你需要使用 `ymm0`, ... `ymm15` 中的寄存器。每个 XMM 寄存器占据对应 YMM 寄存器的前 128 位。本章的大部分讨论仅涉及 XMM 寄存器。

### 11.2 在浮点寄存器之间移动数据

有用于移动整数打包数据和浮点数据的指令。我们在这里专注于浮点数据。你可以移动浮点数或双精度数。有用于移动对齐或未对齐打包数据的指令。对齐指令是使用 XMM 寄存器的 `movaps`（用于四个浮点数）和 `movapd`（用于两个双精度数）。未对齐版本是 `movups` 和 `movupd`。在 YMM 寄存器之间移动打包数据可以移动双倍的值。

#### 11.2.1 移动标量

有两条指令用于将标量浮点值在 SSE 寄存器之间进行移动：`movss` 移动 32 位浮点值（单精度），`movsd` 移动 64 位浮点值（双精度）。这两条指令将值从内存移动到 XMM 寄存器的低位，或从一个 XMM 寄存器移动到另一个。没有隐式转换。这是一个示例：

```assembly
movss xmm0, [x]      ; 将 x 处的值移动到 xmm0
movsd [y], xmm1      ; 将 xmm1 的值移动到 y
movss xmm2, xmm0     ; 从 xmm0 移动到 xmm2
```

#### 11.2.2 移动打包数据

有用于加载整数打包数据和浮点数据的指令。对齐数据意味着它在内存中位于 16 字节边界上。可以通过使用 `align 16` 来实现。`bss` 部分不能很好地完成这项工作。由 `malloc` 分配的数组将位于 16 字节边界上。如果你尝试对未对齐地址使用对齐移动指令，你的程序将会导致段错误。幸运的是在 Core i 系列 CPU 上，未对齐版本与对齐移动一样快：

```assembly
movups xmm0, [x] ; 将 4 个浮点数移动到 xmm0
movups ymm0, [x] ; 将 8 个浮点数移动到 ymm0
movupd ymm1, [x] ; 将 4 个双精度数移动到 ymm1
movupd [a], xmm1 ; 将 2 个双精度数移动到 a
```

### 11.3 加法

浮点数据的加法指令分为标量和打包两种。标量加法指令是 `addss`（加两个浮点数）和 `addsd`（加两个双精度数）。这两者都操作源操作数和目标操作数。源可以在内存或 XMM 寄存器中，而目标必须在 XMM 寄存器中。与整数加法指令不同，浮点加法指令不设置任何标志位，因此必须使用比较进行测试。

打包加法指令是 `addps`（它从源到目标加 4 个浮点数）和 `addpd`（使用 XMM 寄存器从源到目标加 2 组双精度数）。与标量加法一样，源可以是内存或 XMM 寄存器，而目标必须是 XMM 寄存器。使用 YMM 寄存器的打包操作可以增加 8 组浮点数或 4 组双精度数。

```assembly
movss xmm0, [a]    ; 加载 a
addss xmm0, [b]    ; 将 b 加到 a
movss [c], xmm0    ; 将和存储在 c

movupd xmm0, [a]   ; 从 a 加载 2 个双精度数
addpd xmm0, [b]    ; 加 a[0]+b[0] 和 a[1]+b[1]
movapd [c], xmm0   ; 将 2 个和存储在 c

movupd ymm0, [a]   ; 从 a 加载 4 个双精度数
addpd ymm0, [b]    ; 加 4 组双精度数
movupd [c], ymm0   ; 存储 4 个和
```

### 11.4 减法

浮点数据的减法指令与加法模式相同，操作内存或寄存器操作数。它们支持浮点数和双精度数，支持标量和打包数据。标量减法指令是 `subss`（从目标减去源）和 `subsd`（双精度版本）。

打包减法指令是 `subps`（从目标减去源 4 个浮点数）和 `subpd`（使用 XMM 寄存器从目标减去源 2 组双精度数）。和标量加法一样，源可以是内存或 XMM 寄存器，而目标必须是 XMM 寄存器。

```assembly
movss xmm0, [a]    ; 加载 a
subss xmm0, [b]    ; a 减去 b
movss [c], xmm0    ; 将差存储在 c

movapd xmm0, [a]   ; 加载 2 个双精度数
subpd xmm0, [b]    ; 减 a[0]-b[0] 和 a[1]-b[1]
movapd [c], xmm0   ; 将 2 个差存储在 c

movupd ymm0, [a]   ; 加载 4 个双精度数
subpd ymm0, [b]    ; 减 4 组双精度数
```
