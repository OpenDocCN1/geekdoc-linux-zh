## 1997

### Linux：面向创意技术者的兼容性与可靠性

Dave Hollandeck, 惠尔-惠普 (Hewlett Packard)

作为一名微处理器设计师，我每天必须比竞争对手思考得深。我们处于疯狂的技术开发竞赛中——我需要集起每一丝创造力。我需要灵活且适应性强的工具来完成我的工作。

通用的软件包似乎可以，但我的工作需要更基础的工具：我不要一幅画画——我要的是颜料、画布和颜色，来创作我的艺术品。当 Linux 创建出一种略有不同的黄色时，它需要保持我创建的环境。我将拥有完美的解决方案，因为明天的挑战将通过我独特的蓝色得到最好的解决。

自由的完全：源代码本身就是一切

Linux 是可靠的。得益于广泛的用户/测试者社区，令人沮丧的启动故障是罕见的。如果我认真地安装额外的软件包，是否经常会出现冲突，导致运行良好的软件失败？如果我的时间和精力需要花在真实问题上，而不是制裁或实现问题上。如果我没有软件，我将不得不做额外的工作来获得产品的质量。

其他方法可能会驱动我；但对于创意技术者来说，计算机不是资产。在解决技术问题的过程中，我必须拥有最强大的工具。如果我可以使用更具适应性、更强大的平台来获得优势，我就会这样做。而且，当我决定时，我将毫不犹豫。

Dave Hollandeck 是惠尔-惠普科罗拉多州福特柯林 VLSI 技术中心的技术负责人，他在那里设计高性能处理器。读者可以通过 `dae@hhp.com` 与我联系。

1999年1/2月 IEEE Software 33

### ReactOS：NT 的开源替代方案？

Jason Filby，南非自由健康部门

ReactOS 是一个正在开发中的开源操作系统，它将与 Windows 驱动程序和应用程序兼容。我们鼓励全球的开发者支持并为此做出贡献。主页 `www.reactos.org` 包含了项目信息、列表、公告板和下载区域。目前，ReactOS 正在针对 NT 兼容性进行设计。内核目前处于预发布（pre-alpha）阶段，目前无法预测它何时会变得稳定。

事实上，我们的下一个版本将主要包含大量的错误修复。我们希望记录所有代码函数，并使其能够供在线浏览和下载。我们的首要任务是与 NT 驱动程序和应用程序的兼容。这将让我们在未来一段时间里忙碌——每当微软更新 NT 时，我们都必须专注于维护兼容性。我们目前正与 WINE 项目（访问 `www.winehq.org`）共享 win32 API 信息。

这个带有 NT 驱动程序和应用程序的开源操作系统始于1996年，当时 Wayne Majiks 创建了来自 FreeWin5 的代码。虽然有很多项目正在进行，但几乎没有代码可展示。最终，该项目最接近成功。

1月份，项目负责人决定它应该被废弃或移交他处。我们选择从头开始，并在1998年2月重新激活了该项目。我们将其更名为 ReactOS，因为它是对操作系统的反应。他们花了几个月的时间来稳定条款并开展工作。但在初始阶段，我们一直在编写代码，并对这种工作变得越来越感兴趣。

几个月后，ReactOS 进展迅速。我们目前处于预发布 0.1.3 阶段。持续的开发继续吸引着成员，我们正在探索让成员更多参与进来的方法。ReactOS 的历程虽然短暂但令人鼓舞。它的最终发布将不再让人怀疑我们能够做到。如果我们能为 Windows 提供一种可行的替代方案，我们将获得巨大的支持。

Jason Filby 是南非自由健康部门的一名官员。他是 ReactOS 项目的协调员，并兼职为该项目做出贡献。读者可以通过 `jasonfilby@yahoo.com` 联系他。

回去更仔细地观察这一点。例如，仅仅是互联网就在改变个人的市场动态，它也可能不可逆转地改变软件开发的本质。毕竟，软件开发仅仅是创新中的“思想之脑”以软件的形式表达和改变。Linux 确实是此类变革的领导者，理解它可能帮助我们为所需的事物做好准备。

然而，我们的做法与 NT 不同。遗憾的是，维护兼容性与使用更好的技术之间存在着微妙的界限。我们希望在微软无法做到的地方提供解决方案并同时保持兼容性。
