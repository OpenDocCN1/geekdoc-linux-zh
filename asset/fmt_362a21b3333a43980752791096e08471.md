
对于形式为 `archive(member)` 的归档成员，将运行两次算法：第一次使用整个目标名称 `t`，如果第一次运行没有找到规则，则第二次使用 `(member)` 作为目标 `t`。
- 1. 将 `t` 拆分为目录部分 `d` 和结果 `n`。例如，如果 `t` 是 `src/foo.o`，则 `d` 是 `src/`，`n` 是 `foo.o`。
- 2. 创建所有目标匹配 `t` 或 `n` 的模式规则列表。如果目标模式包含斜杠，则与 `t` 匹配；否则与 `n` 匹配。
- 3. 如果列表中的任何规则不是通配规则（`match-anything rule`），则从列表中移除所有非终结的通配规则。
- 4. 从列表中移除所有没有命令的规则。
- 5. 对于列表中的每个模式规则：
    - a. 找到基干 `s`，它是 `t` 中被目标模式中的 `%` 匹配的非空部分。
    - b. 通过将 `s` 替换为 `%;` 计算依赖项名称；如果目标模式不包含斜杠，则在每个依赖项名称的前附加 `d`。
    - c. 测试所有依赖项是否存在或是否应当存在。（如果文件名在 `makefile` 中作为目标或显式依赖项提到，则我们说它应当存在。）
- 如果所有依赖项都存在或应当存在，且没有依赖项，则该规则适用。
- 6. 如果目前没有找到任何模式规则，则加大尝试。对于列表中的每个模式规则：
    - a. 如果规则是终结的，忽略它并继续处理下一个规则。
    - b. 计算“应当存在”的依赖项名称。
    - c. 测试所有依赖项是否存在或应当存在。
    - d. 对于每个不存在的依赖项，递归遵循此算法以查看该依赖项是否可以由隐式规则制作。
    - e. 如果所有依赖项都存在、应当存在或可以由隐式规则制作，则该规则适用。
- 7. 如果没有隐式规则适用，则 `.DEFAULT` 的规则（如果有）适用。在这种情况下，为 `t` 赋予 `.DEFAULT` 所拥有的命令。否则，`t` 没有命令。

一旦找到适用的规则，对于除了匹配 `t` 的模式以外的每个模式，模式中的 `%` 被替换为 `s` 并执行生成的文件。这些被输入数据库并标记为已更新。当为 `t` 执行模式规则的命令时，自动变量将被设置。参见第 10.5.3 节 [自动变量]，第 111 页。

# 第 11 章：使用 make 更新归档文件

## 11 使用 make 更新归档文件

归档文件是包含成员（`members`）的文件；它们由 `ar` 程序维护，其主要用途是链接库。

### 11.1 成员作为目标

归档文件的单个成员可以作为 `make` 中的目标或依赖项。你通过以下方式指定归档文件中的成员：

```
archive(member)
```

这种构造仅适用于目标，不适用于命令！你用于命令的大多数程序不支持这种语法，无法直接操作归档成员。只有 `ar` 和其他专门为归档设计的程序可以做到。例如，此规则通过拷贝文件 `hack.o` 在归档 `foolib` 中创建一个成员 `hack.o`：

```
foolib(hack.o) : hack.o
ar cr foolib hack.o
```

事实上，几乎所有的归档成员目标都以此方式更新，并且有一个隐式规则为你完成。注意：如果归档文件不存在，则需要 `ar` 的 `c` 标志。要在同一个归档中指定多个成员，你可以将所有成员名称写在括号内。例如：

```
foolib(hack.o kludge.o)
```

等同于：

```
foolib(hack.o) foolib(kludge.o)
```

你也可以在归档成员引用中使用 shell 通配符。参见第 4.2 节 [文件名中使用通配符字符]，第 20 页。例如，`foolib(*.o)` 扩展为所有以 `.o` 结尾的 `foolib` 归档成员；

## 11.2 归档成员目标的隐式规则

记得类似于 `a(m)` 的目标代表归档文件 `a` 中名为 `m` 的成员。当 `make` 为此类目标查找隐式规则时，作为一项特殊特性，它考虑匹配 `(m)` 的规则以及匹配实际目标 `a(m)` 的规则。这导致一个目标为 `(*)` 的特殊规则匹配。该规则通过将文件 `m` 拷贝到归档来更新目标 `a(m)`。例如，

它通过将文件 `bar.o` 复制到存档 `foo.a` 中作为名为 `bar.o` 的成员来更新存档成员目标 `foo.a(bar.o)`。

当此规则与其他规则链联时，结果非常强大。因此，在存在文件 `bar.c` 的情况下，执行 `make foo.a(bar.o)`（引号用于防止 `(` 和 `)` 被 shell 特殊解释为特殊字符）就足够在即使没有 `makefile` 的情况下也能运行以下命令：

```
cc -c bar.c -o bar.o
ar r foo.a bar.o
rm -f bar.o
```

在这里，`make` 将文件 `bar.o` 视为一个中间文件。参见第 10.4 节 [隐式规则链](Chains of Implicit Rules)，第 108 页。

这样的隐式规则使用自动变量 `$*` 编写。参见第 10.5.3 节 [自动变量](Automatic Variables)，第 111 页。

存档中的成员名不能包含目录名，但在 Makefile 中假装它包含目录名可能是有用的。如果你写存档成员目标 `foo.a(dir/file.o)`，`make` 将执行此命令进行自动更新：

```
ar r dir/file.o
```

其效果是将文件 `dir/file.o` 复制到名为 `file.o` 的成员中。在使用此类用法时，自动变量 `%D` 和 `%F` 可能会很有用。

### 11.2.1 更新存档符号目录

作为库使用的归档文件通常包含一个特殊成员 `..SYMDEF`，它包含了所有其他成员定义的外部符号名称目录。在你更新了任何其他成员后，需要更新 `..SYMDEF` 以使其能够正确汇总其他成员。这是通过运行 `ranlib` 命令实现的：

```
ranlib archivefile
```

通常，你会将此命令放在存档文件的规则中，并将存档文件的所有成员设为该规则的前提条件。例如：

```
libfoo.a:(x.o) libfoo.a(y.o) ...
ranlib libfoo.a
```

此举的效果是更新存档成员 `x.o`、`y.o` 等，然后通过运行 `ranlib` 更新符号目录成员 `..SYMDEF`。更新成员的规则此处未显示；你可能可以省略它们，并使用前节描述的将文件复制到存档的隐式规则。

在运行 GNU 程序时这是没有必要的，因为它会自动更新 `..SYMDEF`。

## 11.3 使用存档的危险

在使用并行执行（`-j` 选项；参见第 5.3 节 [并行执行](Parallel Execution)，第 43 页）和存档时，请务必小心。如果多个命令同时在同一个存档上运行，它们将无法相互感知并可能损坏文件。

未来的 `make` 版本可能会提供一种机制，通过对所有操作同一个存档文件的命令进行序列化来规避此问题。但目前，你必须通过其他方式编写 `makefile` 来避免这个问题，或者不使用 `-j`。

## 11.4 存档文件的后缀规则

你可以创建一种特殊的后缀规则来处理存档文件。请参见第 10.7 节 [后缀规则](Suffix Rules)，第 117 页以获取后缀规则的完整说明。存档规则在 GNU `make` 中已经过时，因为用于存档的模式规则是一种更通用的机制（参见第 11.2 节 [存档更新](Archive Update)，第 121 页）。但为了与其他方法兼容，它们被保留了下来。

要为存档编写后缀规则，只需编写一个使用目标后缀 `*.a`（存档文件的常用后缀）的后缀规则。例如，这里有一个从 C 源文件更新库存档的旧式后缀规则：

```
.c:a:
$(CC) $(CFLAGS) $(CPPFLAGS) -c $< -o $.*
$(AR) r $* $.*
$(RM) $.*
```

只有在你编写了以下模式规则时，它才有效：

```
%.o: %.c
$(CC) $(CFLAGS) $(CPPFLAGS) -c $< -o $.*
$(AR) r $* $.*
$(RM) $.*
```

事实上，这正是 `make` 在看到以 `.a` 为目标后缀的后缀规则时所做的事情。任何双后缀规则 `*.x.a` 都会被转换为目标模式为 `%.o` 前提模式为 `%.x` 的模式规则。

由于你想将 `*.a` 作为其他类型文件的后缀，`make` 也会以正常方式将存档规则转换为模式规则（参见第 10.7 节 [后缀规则](Suffix Rules)，第 117 页）。因此，双后缀规则 `*.x.a` 会产生两个模式规则：`%.o: %.x` 和 `%.a: %.x`。
