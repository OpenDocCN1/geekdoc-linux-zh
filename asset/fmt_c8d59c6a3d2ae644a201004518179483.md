
`data_len`包含不含头部的数据包长度，首先用于IP分片和去分片。当一个数据包有一个片段列表时，`frag list`由一个socket缓冲区链构建，该链由一个头部的`skb`和一组`sk_buffs`组成，每个`sk_buff`指向单个片段。在这种情况下，`data_len`是所有片段不包含IP报头的长度之和。关于IP分片的详细信息，请参见第9章“网络层、IP”。每当为`skb`生成新的引用时，都会通知用户。共享socket缓冲区会增加用户计数，而克隆socket缓冲区则不会。当缓冲区被克隆时，会设置`cloned`字段。

最后的socket缓冲区字段——`head`、`tail`、`end`和`data`需要稍微解释。`end head`指针指向包的开头，`tail`指向包的末尾。`end`字段指向包数据部分的绝对结束位置。应用程序、设备驱动程序甚至内部协议栈很少更改这些字段。通常情况下，它们通过第7.6节列出的socket缓冲区实用函数进行访问。如前所述，任何网络缓冲区系统的要求之一是头部可以预先准备，而无需拷贝数据包内容。TCP/IP数据包长度从它在socket处开始增长，并随着所有者向下传输到网络。增长发生在较高的层。通常，`head`位于包的开始，因为头部被放在从上层接收的数据之前。当数据包移动时，减少或消除物理拷贝至关重要。当在socket层分配缓冲区时，需要足够的空间让接口的最大own或MTU传输包。可以使用一组使用`head`、`tail`、`end`和`data`字段的实用函数，在不拷贝数据的情况下将头部放在前面。提供这些字段是为了让API函数能够跟踪缓冲区中感兴趣内容的起始结束位置，这些函数会使用这些指针。

## 7.8 Socket Buffer、分片与分段

共享信息结构`skb_shared_info`用于支持IP分片和TCP分段。如果不讨论这个结构，socket缓冲区的讨论就是完整的。共享信息结构也称为`skb_shinfo`，定义在文件`include/linux/skbuff.h`中。

```c
struct skb_shared_info {
```

该字段包含此`skb`的引用计数。每当缓冲区被克隆时，该计数就会加1。

`Nr_flags`是此数据包中的片段数量。该字段被TCP分段使用。

接两个字段用于具有硬件执行TCP分段处理能力的设备。这是网络设备特征`NET_F_TSO`。

```c
unsigned short tso_size;
unsigned short tso_segs;
```

如果该数据包被分片，此字段将指向该数据包的片段列表。

```c
struct skb_buff *frag_list;
```

这是页表项数组。每个条目实际上是一个`SKB_SEG`。

```c
skb_frag_t frags[MAX_SKB_FRAGS];
```

该结构放置在附加缓冲区的末尾，并指向socket缓冲区结构中的`end`字段，而该字段指向包数据部分的末尾。然而，它也被用于在附加数据缓冲区中找到`skb_shared_info`的起始位置，因为它紧跟在普通数据包的数据部分之后。`skb_shared_info`有多个用途，包括IP分片、TCP分段以及跟踪克隆缓冲区。当用于IP分片时，`skb_shared_info`指向一个包含IP片片的`skb_bufs`列表。当用于TCP分段时，该结构包含一个包含分段数据的附加页数组。TCP分段的处理比IP分片更高效。IP分片并不像互联网早期那样常见。当网络段的MTU小于出站设备且该设备小于数据包大小时，就会使用分片。关于IP分片的更多详细信息，请参见第9章。TCP分段常见得多，因为它是大多数网络流量中数据传输的底层机制。

`skb_shinfo`也可以用于持有TCP分段。当这样使用时，`skb_shinfo`包含一个指向包含TCP分段的内存映射页的指针数组。TCP提供流服务，使得数据看起来像是一个不连续的字节序列，尽管数据必须被拆分以适应IP包。关于TCP分段的更多信息，请参见第8章“通过UDP和TCP从Socket发送数据”。当socket缓冲区被克隆时，`skb_shared_info`会拷贝到新缓冲区中。

共享信息的第一个字段`dataref`如果值非零，则表示socket缓冲区被克隆了，因为每次克隆socket缓冲区时它都会加1（socket缓冲区中的`cloned`字段在克隆socket缓冲区时也会使用）。信息结构中的下一个字段`frag_list`被IP分段汇设施使用。这就是每个片段如何共享同一个IP头部。每个片段的IP头部在片段ID、片段偏移和校验和上不同。当IP协议中的输入处理发现一个传入的IP片段时，它数据包放在一个包含片段的特殊列表中。IP将此（不拷贝实际数据包数据）移动到一个单一的数据报中，该数据报由一个头部缓冲区跟随一个socket缓冲区列表组成，每个缓冲区指向一个片段片段。共享区域中的`frag_list`字段指向包含片段的缓冲区列表。尽管每个IP片段占用单独的缓冲区，但`skb_shinfo`结构本身会被拷贝到每个socket缓冲区。请参见图7.5以获取包含片段数组的socket缓冲区插图。

信息结构中的第二个字段`nr_frag`不用于IP分片；而是用于TCP分段。当此字段包含非零值时，表示socket缓冲区包含分段。`nr_frag`的值对应于附加到socket缓冲区上的段页数，`shared_info`包含指向`frag`数组中分段的指针。`frags`数组放置在紧邻`nr_frag`字段的内存中。`frag`数组中可以包含尽可能多的页。数组中实际位置的数量取决于硬件架构和配置的页大小`PAGE_SIZE`。`frag`数组中的每个元素都指向Linux页表中的一个内存页。关于slab分配和虚拟页表的更多信息，请参见第7.4节。当一个由TCP的socket缓冲区包含一个分段链时，每个顺序数据都在由`frag`数组中的位置指向的独立内存映射页中。这比为每个TCP段维护冗余的`sk_buffer`要高效得多。一旦TCP处于`ESTABLISHED`状态，后续段的数据包头部几乎相同，因此数据包头部在每个段之间共享。在处理过程中节省了时间，不需要Linux为每个段拷贝完整的IP头部。

`frag`数组中的每个位置都包含一个在`linux/include/skbuff.h`中定义的`skb_frag_t`结构。每个`frag`的大小计算为容纳总计64KB的数据。

```c
#define MAX_SKB_FRAGS (65536/PAGE_SIZE + 2)
struct skb_frag_struct skb_frag_t;
struct skb_frag_struct {
```

`page`是指向页表的指针。下一个字段是从页开始数据的偏移量。`size`是页中数据的长度。

```c
struct page {
    *page;
    __u16 page_offset;
    __u16 size;
};
```
