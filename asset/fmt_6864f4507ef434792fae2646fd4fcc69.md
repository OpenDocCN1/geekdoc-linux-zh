
# 重温生产者-消费者问题

第 2.4 节和第 2.5 节引入的生产者-消费者系统中有一个共同的问题：生产者和消费者需要分别初始化。由于消费者和生产者都接受包含共享信号量名称和文件的命令行参数，它们需要使用相同的命令行值启动；否则不存在通信。分别启动生产者和消费者的另一个问题是它们需要按照特定的顺序启动。生产者在启动时初始化命名信号量，而消费者在启动时打开该命名信号量。如果消费者在生产者之前初始化，则命名信号量不存在（由生产者创建命名信号量），消费者将失败。之前的生产者-消费者系统的最后一个问题是，消费者知道生产者已退出的唯一方法是生产者向生产者-消费者共享文件写入“QUIT”命令。如果生产者通过其他方法（例如接收信号）退出，消费者将无法检测到其终止并继续执行。对于多生产者单消费者问题，这可能导致许多线程在没有生产者的情况下运行，从而浪费系统资源。

产生进程的能力缓解了生产者-消费者系统中存在的问题。最能说明产生进程优势的生产者-消费者系统是多生产者单消费者系统。消费者进程拥有所有生产者的信息，因为共享文件和信号量名称的组合被传递了。由于共享文件和信号量名称的组合被传递了，它们需要使用相同的命令行值启动；否则不存在通信。分别启动生产者和消费者的另一个问题是它们需要按照特定的顺序启动。生产者在启动时初始化命名信号量，而消费者在启动时打开该命名信号量。如果消费者在生产者之前初始化，则命名信号量不存在（由生产者创建命名信号量），消费者将失败。之前的生产者-消费者系统的最后一个问题是，消费者知道生产者已退出的唯一方法是生产者向生产者-消费者共享文件写入“QUIT”命令。如果生产者通过其他方法（例如接收信号）退出，消费者将无法检测到其终止并继续执行。对于多生产者单消费者问题，这可能导致许多线程在没有生产者的情况下运行，从而浪费系统资源。

产生进程的能力缓解了生产者-消费者系统中存在的问题。最能说明产生进程优势的生产者-消费者系统是多生产者单消费者系统。消费者进程拥有所有生产者的信息，因为共享文件和信号量名称的组合被传递了。为了确保信号量被创建，消费者在打开命名信号量之前需要短暂的等待。尽管消费者产生了所有适当的生产者，仍然没有方法判断生产者是否已退出。使用 `XPCWaitPid` 并用生产者进程 ID 构建它，消费者可以等待直到生产者进程退出。无论情况如何，消费者都能获知生产者的情况。通过 `getStatusDefinition()`，消费者甚至可以检测导致生产者退出的原因。问题是 `XPCWaitPid` 会阻塞调用进程。如果消费者产生生产者并等待它，将无法产生更多的生产者。解决方案是创建产生生产者并等待它的线程。通过将产生进程封装在单独线程中，主线程就不会被阻塞并继续处理。由于产生生产者的线程知道生产者何时完成，它们可以向相关的消费者线程发送杀死信号。目前，消费者线程在主线程处理来自文件的“QUIT”时被杀死。

# 产生进程

当遇到“QUIT”时，可以通过共享文件名定位消费者线程。通过使用单独线程监控消费者状态，将消费者对象传递给产生线程是有益的。

## 列表 2.47 生产者-生成消费者

```cpp
// XProducerInfo 包含了生产者生成线程所需的必要信息
// 用于创建适当生产者，并在生产者终止时杀死关联的消费者线程。

class XProducerInfo
{
    char *sFilename;        // 共享文件名
    char *sSename;          // 命名信号量的名称

    // 关联的线程对象。
    XPCthread<ExitStatus> *consumerThread;

public:
    // 构造函数
    XProducerInfo(char *sSename, char *sFilename,
                 XPCthread<ExitStatus> *_consumerThread)
    {
        sFilename = new char[strlen(_sFilename)+1];
        sSename = new char[strlen(_sSename)+1];
        strcpy(sFilename, _sFilename);
        strcpy(sSename, _sSename);
        consumerThread = _consumerThread;
    }

    // 拷贝构造函数
    XProducerInfo(const XProducerInfo &_origProducerInfoClass)
    {
        sFilename = new char[strlen(_origProducerInfoClass.GetFilename())+1];
        sSename = new char[strlen(_origProducerInfoClass.GetSename())+1];
        strcpy(sFilename, _origProducerInfoClass.GetFilename());
        strcpy(sSename, _origProducerInfoClass.GetSename());
        consumerThread = _origProducerInfoClass.getConsumerThread();
    }

    // 私有成员获取方法
    char *getFilename() { return sFilename; }
    char *getSename() { return sSename; }
    XPCthread<ExitStatus> *getConsumerThread() { return consumerThread; }
};

// 赋值运算符
XPCProducerInfo&operator=(const XPCProducerInfo &origProducerInfoClass)
{
    if (this == &origProducerInfoClass)
        return;

    if (sFilename)
        delete [] sFilename;

    if (sSename)
        delete [] sSename;

    sFilename = new char[strlen(_origProducerInfoClass.GetFilename())+1];
    sSename = new char[strlen(_origProducerInfoClass.GetSename())+1];
    strcpy(sFilename, _origProducerInfoClass.GetFilename());
    strcpy(sSename, _origProducerInfoClass.GetSename());
    consumerThread = _origProducerInfoClass.getConsumerThread();

    return *this;
}
```
