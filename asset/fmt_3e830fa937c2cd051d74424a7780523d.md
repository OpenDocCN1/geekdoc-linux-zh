| 名称 | 默认表头 | 说明 |
|---|---|---|
| args | COMMAND | 包含所有参数的字符串形式的命令。应用程序不能依赖于修改其参数列表并将该修改反映在 `ps` 命令的输出中。Solaris 实现将字符串限制为 80 字节；该字符串是命令启动时传递给命令的参数列表的版本。 |
| comm | COMMAND | 字符串形式的正在执行的命令名称 (`argv[0]`)。 |
| etime | ELAPSED | 自进程启动以来经过的时间，格式为 [[dd]-hh:mm.ss]，其中 dd 是天数，hh 是小时，mm 是分钟，ss 是秒。 |
| group | GROUP | 进程的有效组 ID，如果可以获取且字段宽度允许则以文本形式显示。否则显示十进制 GID 值。 |
| nice | NI | 进程系统调度优先级的十进制值。参见 `nice(1)`。 |
| pcpu | %CPU | 最近使用的 CPU 时间与同一时期可用 CPU 时间之比，以百分比形式表示。在此上下文中，“最近”的含义未指定。可用 CPU 时间以未知方式确定。 |
| pgid | PGID | 进程组 ID 的十进制值。 |
| pid | PID | 进程 ID 的十进制值。 |
| ppid | PPID | 父进程 ID 的十进制值。 |
| rgroup | RGROUP | 进程的实际 ID，如果可以获取且字段宽度允许则以文本形式显示。否则显示十进制值。 |
| ruser | RUSER | 进程的实际用户 ID，如果可以获取且字段宽度允许则以文本形式显示。否则显示十进制值。 |
| time | TIME | 进程的累计 CPU 时间，格式为 [[dd]-hh:mm.ss]。 |
| TTY | TT | 进程控制终端的名称（如果有），格式与 `who(1)` 命令使用的格式相同。 |

使用 `ps` 报告
当需要检查哪些进程或守护进程在运行时，请使用 `ps -e` 选项。如果需要关于进程的更详细信息，请使用 `ps -el` 选项。通过经验，你将学会报告应该是什么样的，以及如何判断异常情况。
使用指南来发现潜在问题。

- 对于同一用户拥有的多个相同作业。这种情况可能是由于有人运行了脚本，启动了大量后台作业，而没有等待任何作业结束。与用户联系是否是此类情况。如有必要，使用 `kill` 命令终止某些进程。有关终止进程的更多信息，请参见 `kill(1)`。
- 查看 `TIME` 字段以查找积累了大量 CPU 时间的进程。此类进程可能处于死循环。
- 查看 `C` 字段以寻找不重要的进程。
