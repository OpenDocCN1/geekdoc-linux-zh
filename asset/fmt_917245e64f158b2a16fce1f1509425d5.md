
# arch — 显示当前主机的架构

### 概要 (Synopsis)

```
/usr/bin/arch [-k | archname]
```

### 描述 (Description)

系统根据其架构进行粗分类，架构定义了哪些执行文件运行在哪些机器上。你可以区分内核架构和应用架构（或通常称为架构）。由于底层硬件差异运行不同内核的系统可能运行相同的应用程序。

`arch` 显示当前主机系统的应用架构。由于该命令在历史上被广泛使用且不带任何选项，所有 SunOS 5。

## 选项 (Options)

- `-k` 显示内核架构。
- `archname` 显示应用架构。

## 操作数 (Operands)

- 归档文件的路径。一个路径。在与归档中的文件名比较时，仅使用最后一个组件。如果两个或多个操作数具有相同的最后一个路径组件 (`basename(1)`)，则结果是不确定的。实现的归档格式不会截断添加到或替换在归档中的有效文件名。
- `archive`
- `file`
- 归档文件中的某个文件名，用于相对定位；参见选项 `-m` 和 `r`。
- `posname`

### 示例 (Examples)

以下示例显示了如何找到哪些对象模块组成 `libexample.a` 归档。

```
castle% t libexample.a
```

以下示例显示了如何从共享对象中提取一个模块。如果 `module.o` 是归档库 `libexample.a` 的一部分，你可以使用以下命令提取该模块。

```
castle% ar x libexample.a module.o
```

`ranlib` 命令在 SunOS 4.x 中用于向归档库添加目录内容。`ranlib` 命令现在整合到 `/usr/ccs/bin/ar` 中。当 `ar` 归档对象文件时，它会自动创建一个符号表，如下例所示。

```
castle% rcv libfoo.a foo.o bar.o
```

以下命令强制重新构建归档库中的符号表。

```
castle% ts libfoo.a
```

## 环境变量 (Environment Variables)

参见 `environ(5)` 以了解以下影响 `ar` 执行的环境变量的描述：`LC_TYPE`、`LC_MESSAGES` 和 `NLPATH`。

## 退出状态 (Exit Status)

- `0` 成功完成。
- `>0` 发生错误。

```
/usr/xpg4/bin/ar:
```

| 属性类型 | 属性值 |
