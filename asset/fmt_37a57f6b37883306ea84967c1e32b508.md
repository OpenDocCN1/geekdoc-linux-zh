
不幸的是，`FM` 合成虽然在硬件中易于实现，但产生的效果较差。您不太可能将 `FM` 合成生成的钢琴声误认为真实的钢琴，甚至误认为一场质量较差的真实钢琴录音。充其量，那种声音只是模糊地带有钢琴的意味。不过，不同声卡之间的 `FM` 合成质量差异很大。决定某张声卡 `FM` 合成 `MIDI` 生成质量的一个主要变量是可以组合的音调数量。一些最早且最便宜的 `FM` 合成板只组合了两个音调。较新的产品通常使用四个或更多音调。

## 波表合成

一种更高级的模拟乐器方法是`波表合成`（`wavetable synthesis`）。与其依赖几个纯音的组合来模拟乐器声音，`波表合成`使用目标乐器的录音。制造商对乐器演奏单个音符进行数字录音。随后隔离该录音的一小段片段，声卡中的电路可以循环播放它以重现连续音符。此外，录制的音符可以改变音量、压缩以产生更高音调，或扩展以产生更低音调。通过这些操作，可以模拟乐器以任何音量演奏任何音符的声音。

## 波表质量

即使在播放 `MIDI` 文件时，最差的`波表合成`声卡通常听起来也比最好的`FM`合成声卡要好。然而，`波表板`之间的差异相当大。影响`波表质量`的变量包括

- **采样长度**：在其他条件相同的情况下，较大的采样优于较小的采样。
- **采样率**：与数字音频一样，`波表合成`的采样以特定的采样率进行录音。如果采样率太低，采样可能会丢失一些有助于定义声音本质的高频泛音。
- **采样数量**：当您在乐器上演奏两个音符时，它们的波形彼此相似，但即使调整了不同频率后，它们也并非完全相同。因此，许多`波表`产品实际上为每种乐器录制了两个或更多采样。每个采样处理不同范围的音符。在其他条件相同的情况下，此类采样越多越好。
- **声源**：制造商使用不同的乐器作为其源采样。如果声源乐器制造或维护不良，生成的`波表`效果也会受损。

除了最后一个因素外，这些变量都会影响完整`波表`的最终大小，如存储在声卡`ROM`或`RAM`中那样。例如，某产品的`波表`可能是`2MB`，而另一产品的可能是`8MB`。后一种产品听起来可能比前一种更好，尽管其他因素可能会起作用。例如，第一种声卡可能使用了更好的声源乐器，或者它可能将更多空间分配给对您重要的乐器，而第二种声卡可能将大量空间用于精确模拟您从不使用的奇异乐器。

## 波表存储

`波表`声卡将其采样存储在以下三个位置之一：

- **声卡 ROM** 信息可能存储在声卡上的`ROM`芯片中。这种位置对用户来说很方便，因为无需任何干预——只需插入板卡即可使用。其缺点是`ROM`不易升级，因此您无法更换为更好的`波表`采样集。
- **声卡 RAM** 一些声卡包含`RAM`，无论是内置于板卡中还是在`SIMM`插槽上，如图 10.4 所示。这种设计提供了灵活性，因为您可以下载更新的`波表`采样，甚至维护几十兆字节的采样集，并仅下载当前正在使用的乐器。缺点是您必须使用支持`波表下载`功能的驱动程序或辅助软件。

![](img/860d0c38bd76c9ded976e9d1e179ef25_314_0.png)

**图 10.4**

`一些波表声卡包含用于存储波表采样的 SIMM 插槽。`

- **计算机 RAM** 一个近期的趋势，特别是在`PCI`声卡中，是向所谓的`软件波表`发展。在这种设计中，`波表`功能由软件处理。实际上，计算机根据`MIDI`文件和一组`波表`采样生成一个数字音频文件，然后像播放任何其他音频文件一样在声卡上播放该文件。`Linux` 为所有声卡提供`软件波表`支持，正如稍后所述，因此不要仅仅因为某声卡宣传此功能而偏袒它，而排斥那些不宣传此功能（但功能相同）的声卡。绝对不要认为这样的声卡等同于任何形式的硬件`波表`支持。

一些声卡同时包含基于`ROM`的`波表`和用于扩展或替换`ROM`中包含采样的`RAM`芯片或`SIMM`插槽。在其他条件相同的情况下，这种设计提供了便利性和灵活性的最佳结合。

## Linux 软件波表支持

有两个主要软件包可用于在`Linux`中执行`软件波表`操作：`TiMidity` 和`SoftOSS`。前者是一个用户空间程序，这意味着你仅限于从`TiMidity`本身播放`MIDI`文件。通常你不能使用`TiMidity`来处理来自游戏或`MIDI`编辑器的`MIDI`音乐。另一方面，`SoftOSS`是一个内核模块，它用`软件波表`设备替换对声卡正常`MIDI`设备的访问。

`TiMidity` 和`SoftOSS`都依赖`Gravis UltraSound`声卡的补丁集，例如`MIDIA` (`ftp://archive.cs.umbc.edu/pub/midia/instruments.tar.gz`)。通常也能找到与`TiMidity`一起打包的`MIDI`补丁集。大多数`Linux`发行版都带有这样的补丁集，在一个名为`timidity-patches`或`midi-samples`或类似名称的包中。

### 使用 TiMidity

`TiMidity` 包含在大多数`Linux`发行版中，或者你可以在`http://www.debian.org/distrib/packages`或`http://rufus.w3.org/linux/RPM/`等文件存档站点找到它。使用`TiMidity`最棘手的是配置。该程序依赖一个名为`timidity.cfg`的配置文件，该文件可以位于`/etc`目录或某个在不同发行版之间有所变化的其他目录中。此文件指定单个采样与其对应乐器之间的关联。例如，配置文件可能以类似以下内容开始：

```
dir /dos/ultrasnd/midi
bank 0
0 acpiano.pat
1 britepno.pat
2 epiano1.pat
3 honky.pat
```

第一行指定补丁文件的位置——`/dos/ultrasnd/midi`。第二行表示以下规格适用于乐器组`0`，该组处理大多数乐器。后续行将补丁文件分配给每个编号的乐器——例如，乐器`0`是原声钢琴 (`acpiano.pat`)。（`MIDI`包含一组标准分配，因此乐器`0`应该始终是钢琴，除非你想实现某些乐器变换效果。）

`timidity.cfg` 文件还可以包含类似的鼓声定义，它以`drumset 0`而不是`bank 0`开始。一些默认配置文件使用`source`指令将大部分配置细节推送到其他文件中。

当你的`TiMidity`配置完成时（幸运的是，安装时通常就是这样），你可以播放一个`MIDI`文件：

```
timidity midfile.mid
```

结果将是`MIDI`文件的`波表`演绎版，尽管`CPU`使用率较高。在我使用的`AMD K6-2/475`系统上，`TiMidity` 消耗 `10%–20%` 的可用`CPU`时间，具体取决于`MIDI`文件的复杂度。

如果你希望拥有一个比命令行更吸引人的用户界面，可以使用`-i`选项启动带有特定用户界面的`TiMidity`。输入`timidity -help | less`以获取你系统上可用的`c`值列表。（`TiMidity` 可以编译许多不同的接口，但概率较大的是，你拥有的二进制文件仅支持其中少数几个。）图 10.5 显示了使用`Athena`小部件集接口的`TiMidity`。

![](img/860d0c38bd76c9ded976e9d1e179ef25_316_0.png)

**图 10.5**

`TiMidity 的 GUI 界面允许你动态控制 MIDI 播放。`

总体而言，如果你缺乏`波表`声卡并希望偶尔以比`FM`合成更好的质量播放`MIDI`文件，`TiMidity` 可以是一个非常有用的工具。但是，如果你希望从游戏或其他实用工具中获得高质量`MIDI`播放，使用`SoftOSS`可能更好——或者更好的是，使用真正的硬件`波表`声卡。

### 使用 SoftOSS

`Linux`内核包含一个名为`SoftOSS`的功能，这是一个模拟`Gravis UltraSound` (`GUS`) 板`波表`特性的`软件波表`功能。要使用此功能，请遵循以下步骤：

1. 获取适用于`SoftOSS`的适当补丁集。`SoftOSS`使用`GUS`补丁集，例如公共领域的`MIDIA`集 (`http://archive.cs.umbc.edu/pub/media/instruments.tar.gz`)。许多`Linux`发行版包含这样的补丁集，通常作为`TiMidity`的辅助包。
2. 将声音采样放置在目录`/dos/ultrasound/midi`中。（你很可能需要创建此目录。）如果你是通过安装随`Linux`发行版提供的包来获取的采样，从这个位置创建到默认位置的符号链接即可工作。
3. 在`Linux`内核配置的`Sound`区域中启用`SoftOSS` `软件波表`引擎支持，如图 10.6 所示。你可以通过改变采样率和声音数量来调整`软件波表`的质量。

![](img/860d0c38bd76c9ded976e9d1e179ef25_317_0.png)

`SoftOSS 功能可将任何 16 位声卡变成软件波表声卡。`

4. 重新编译启用了`SoftOSS`支持的内核或内核模块，如有必要，重启以激活这些更改。
