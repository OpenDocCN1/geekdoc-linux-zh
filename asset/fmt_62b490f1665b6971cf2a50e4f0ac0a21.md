
第二个问题出现在你希望普通用户能够将软盘挂载到目录层次结构中时，因为`mount`和`umount`命令仅限root使用。它们以这种方式设置是为了防止普通用户重新排列目录层次结构，这可能导致各种安全问题。解决此问题的最安全方案可能是编写一对简单的C程序，只能用于在特定目录（例如`/floppy`）上挂载和卸载软盘。有关这些命令的实现，请参阅第21章末尾的练习。

## Peripherals

任何操作系统的首要功能之一，包括Linux，是在应用程序软件和机器的周边硬件之间提供接口。常见的周边硬件包括以下设备：

- 控制台终端，用于视频输出和键盘输入；

- 调制解调器，用于与其他系统进行简单的串行通信；

- 鼠标作为替代输入设备；

- 打印机用于输出清单、文本和图形。

本章依次介绍这些设备，看看Linux中存在哪些用于设置和使用它们的设施。

### 9.1 Console Terminal

对于大多数Linux系统，只有一个用户，系统的主要访问方式是通过机器的键盘和屏幕——控制台终端。事实上，控制台终端实际上是两个独立的周边设备：屏幕/视频输出设备和键盘输入设备。正如我们将看到的，对于这两个设备都可以进行相当多的设置。

### 9.1.1 Keyboard Input

PC上的键盘似乎是一个相对简单的设备——它是一个带按钮的盒子，按钮上有编号和字母，你按下按钮，相应的字符就会显示在屏幕上。然而，尽管看似简单，实际上比乍一看要复杂得多。

首先，许多使用PC的国家需要在字符集中加入一些额外的特殊字符，以便能够应对不同口语语言的怪癖。这意味着存在许多键盘变体，布局和内容略有不同。

从制造角度来看，能够生产单一键盘的电子和物理结构，然后只更换一些键帽上的符号，比为每种键盘变体生产新的电子器件要便宜得多。然而，要实现这一点，需要某种查找机制，以便键盘上特定物理位置的单个键可以根据键上的键帽生成不同的字节值。

在Linux中，此查找在内核中的键盘驱动程序中以软件方式完成。实际上，内核中有一个表，指定了为键盘上的每个键以及每个键与各种Ctrl、Shift和Alt键组合生成的字节值。

键盘上的每个物理键都被赋予1到127范围内的唯一键码编号。然后使用键盘映射文件指定按下每个键码或键码组合时应生成什么字节值。默认情况下，键盘映射文件存储在目录中：

```
/usr/lib/kbd/keytables
```

键盘映射文件通常在系统启动时使用`loadkeys`命令加载到内核中。例如，要加载英国键盘的映射文件，你将使用命令：

```
$ /usr/bin/loadkeys /usr/lib/kbd/keytables/uk.map
```

此命令需要输入到系统启动文件之一中。这些文件通常存储在`/etc`目录下的某个位置（尽管确切位置会因不同的Linux发行版而异），并且名称形式为：

```
rc.XXX
```

其中XXX表示文件用于配置的内容。在Slackware发行版中，`loadkeys`命令出现在文件：

```
/etc/rc.d/rc.keymap
```

键盘映射文件本身只是普通文本文件，因此如果你想为特殊目的创建自己的键盘映射，可以轻松查看和编辑它们。如果你只想在otherwise标准布局的基础上更改几个键的映射，那么你只需要为更改创建映射，然后在标准布局已设置好后加载它。

为了找出你想要更改功能的键的键码，你需要使用`showkey`命令。当此命令运行时，你按下的或释放的任何键都会导致其键码被显示。为了终止`showkey`程序，它被安排为如果你十秒内不按任何键就会自动退出：

```
$ showkey
press any key, program terminates after 10s of last keypress
keycode 28 release
keycode 25 press
keycode 25 release
keycode 46 press
keycode 46 release
$
```

一旦你知道了想要更改的键码，只需适当修改键盘映射文件然后加载即可。映射文件的格式相当简单，其良好的描述在手册页中给出：

```
$ man 5 keytables
```

你可能希望逐步修改内核中的键盘映射表，直到对其操作方式满意为止。在这种情况下，你可以使用`dumpkeys`命令从当前内核表中生成一个映射文件以供后续加载，方法如下：

```
$ dumpkeys >newkey.map
```

### 9.1.2 视频输出

与键盘一样，屏幕输出也有一些相关的查找表，其值可以为特殊目的而更改，或只是为了好玩！

通常，当一个字节发送到屏幕时，其8位值被用作要显示的字符的代码。然而，可以在此序列中插入一个转换表。该表只是一个简单的256个元素的字节数组。当使用此表时，每当一个字节被发送到屏幕以显示其代表的字符时，该字节将被用作索引来选择256个元素中的一个。实际上指定要显示的字节值的，是该数组元素中的8位值。如果默认情况下表设置如下：

```
table[0] = 0
table[1] = 1
table[2] = 2
-
-
table[255] = 255
```

那么这与表不存在时的效果相同。从默认值更改任何值都会自动允许在显示时从一个字符转换到另一个字符。

要修改输出转换表，请使用`mapscrn`命令：

```
$ mapscrn filename
```

其中`filename`是包含新字符映射的文件名。设置好表后，可以通过向显示器发送一个特殊字符序列来启用它。该序列是Esc字符后跟‘(K’。随后可以通过将启用序列中的K替换为B来禁用转换表的使用。

`mapscrn`命令的手册页给出了可在转换文件中指定转换条目的格式的完整描述，但基本上，它们都归结为提供一组字符对的列表，其中指定一个字符及其新的转换。一个简单的例子有助于阐明这一点。

假设出于某种原因，你想将大写字母W、X和Y中的任何一个转换为星号(*)。指定此操作的转换文件的内容可以是：

```
`W`  `*`
`X`  `*`
`Y`  `*`
```

该文件（例如称为`newtab`）然后可以用以下命令加载到控制台显示驱动程序中：

```
$ mapscrn newtab
```

向控制台驱动程序发送特殊转义序列以启用字符转换的最简单方法是使用以下`echo`命令：

```
$ echo -e `\033(K`
```

发送此序列后，任何尝试向屏幕发送W、X或Y的操作都将导致显示星号，如以下命令序列所示：

```
$ echo -e `\033(K` VWXYZ
V***Z
$ echo -e `\033(B` V***Z
VWXYZ
```

显然，在第二个`echo`命令中，出现三个星号的地方，我实际输入的是WXY，但由于转换，它们并没有以这种方式显示出来。

显示序列中出现的另一个表实际上存储在你的显卡上，其内容控制显示字符本身的外观。更改此表的内容可以更改显示的字体。Linux上有许多字符字体可供使用，生成你自己的自定义字符和图形形状也是一项简单（尽管有点繁琐）的任务。首先，为了加载其中一种标准字体，你使用`setfont`命令并指定字体文件名：

```
$ setfont sc.fnt
```

图9.1 字母A的字符网格及其编码。

其中`sc.fnt`是要加载的字体文件名。如果你尝试一下，你会发现`sc.fnt`是一个相当有趣的字体，尽管你可能不想一直使用它。默认情况下，字体文件存储在目录中：

```
/usr/lib/kbd/consolefonts
```

为了理解字符字体文件的内容和布局，我们需要简要了解一下显示文本字符的机制。在VGA屏幕显示25行、每行80个字符的文本时，每个字符在屏幕上占据一个像素网格，该网格宽8个像素，高16个像素。

接下来，每个可显示字符都由一组点亮和未点亮的像素组成，也在8×16像素网格上。要在屏幕上的特定位置显示特定字符，只需将像素从正确的字符网格复制到屏幕上的适当像素网格位置即可。

在字符网格中，一个像素由单个位表示，该位仅指定相应像素是否点亮或未点亮。这意味着存储完整8×16像素网格的像素信息的一种简便方法是作为16个单字节值的集合——网格中每8个像素一行对应1个字节。图9.1显示了字母A的典型像素网格以及由此产生的16个字节值（十六进制）。正如你所见，示例字母A的网格编码为：

```
00 00 10 38 6c c6 c6 fe c6 c6 c6 c6 00 00 00 00
```

你已经看到，发送以供显示的字符以0到255范围内的数字到达（即总共256个）。因此，一个完整的8×16像素字符集由256个不同的8×16像素网格组成。8×16像素字符集的字体文件仅包含256组16个字节，依次排列形成一个4096字节长的文件。

创建你自己的字符集和字体文件只是为每个字符计算像素网格、整理每个网格的16个单字节值，然后将这些值写入文件，以便随后使用`setfont`命令加载和使用。
