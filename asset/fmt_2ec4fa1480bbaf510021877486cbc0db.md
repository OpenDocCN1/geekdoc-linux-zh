
```
POWERSAVE_EVENT_GLOBAL_SUSPEND="prepare_suspend"
POWERSAVE_EVENT_GLOBAL_STANDBY="prepare_standby"
POWERSAVE_EVENT_GLOBAL_RESUME_SUSPEND="restore_after_suspend"
POWERSAVE_EVENT_GLOBAL_RESUME_STANDBY="restore_after_standby"
```

在`/etc/powesave.conf`（`powersave`守护进程的配置文件）中，这些事件被分配给`powersave_proxy`脚本。当这些事件发生时，会执行该脚本（安装后的默认设置）：

```
global.suspend=/usr/sbin/powersave_proxy
global.standby=/usr/bin/powersave_proxy
global.resume.suspend=/usr/bin/powersave_proxy
global.resume.standby=/usr/bin/powersave_proxy
```

## 用户定义电池状态

在`/etc/powesave.conf`文件中，定义三个电池电量水平（百分比），当达到这些水平时将触发系统警报或执行特定操作。

```
POWERSAVED_BATTERY_WARNING=20
PWERSAVED_BATTERY_LOW=10
PWERSAVED_BATTERY_CRITICAL=5
```

当电量下降到指定限制以下时要执行的动作或脚本在`/etc/powesave.conf`中定义。动作类型在`/etc/sysconfig/powave/common`中配置：

```
POWERSAVE_EVENT_BATTERY_NORMAL="ignore"
POWERSAVE_EVENT_BATTERY_WARNING="notify"
POWERSAVE_EVENT_BATTERY_LOW="notify"
POWERSAVE_EVENT_BATTERY_CRITICAL="suspend"
```

进一步的选项在该文件中说明。

## 根据各种条件调整功耗

系统行为可以根据电源类型进行调整。因此，当断开交流电源并使用电池运行时，应降低系统功耗。同样，当连接到交流电源时，应增加性能。CPU频率、硬盘节电功能和其他因素也可以被修改。

在`/etc/powersave.conf`中，断开或连接交流电源触发的动作执行委托给`powersave_proxy`。要应用的场景（方案或配置文件）可以在`/etc/sysconfig/powersave/common`中定义：

```
POWERSAVE_AC_SCHEME="performance"
BATTERY_SCHEME="powersave"
```

方案位于`/etc/sysconfig/powersave/`中命名为`scheme-<name>`的文件中。`performance`和`powersave`是预配置的方案。可以使用YaST电源管理模块来编辑、创建和删除与特定电源状态关联方案。

### 8.5.3 附加 ACPI 功能

如果你使用ACPI，可以控制系统对ACPI按钮（电源、睡眠、开盖）的响应。在`/etc/powersave.conf`中，相应动作的执行委托给`powersave_proxy`。动作本身在`/etc/sysconfig/powersave/common`文件中定义。

```
POWERSAVE_EVENT_BUTTON_POWER="wm_shutdown"
```

按下电源按钮时，系统通过关闭相应的管理器（KDE, GNOME等）做出响应。

```
POWERSAVE_EVENT_BUTTON_SLEEP="suspend"
```

按下睡眠按钮时，系统被设置为挂起模式。

```
POWERSAVE_EVENT_BUTTON_LID_OPEN="ignore"
```

打开盖子时无操作发生。

```
POWERSAVE_EVENT_BUTTON_LID_CLOSED="screen_saver"
```

当盖子关闭时，激活屏幕保护程序。

如果CPU负载在指定时间内未超过限制，则可以进一步限制CPU性能。在`POWERSAVED_CPU_LOW_LIMIT`中指定负载限制，在`POWERSAVED_CPU_IDLE_TIMEOUT`中指定时间。

### 8.5.4 排除

以下项目涵盖了与`powersave`连接时最常见的问题。

- 我遇到了问题，但找不到原因。

查看`/var/log/messages`。所有错误消息和警报都会记录在此。如果找不到所需信息，使用`/etc/sysconfig/powersave/common`文件中的`powersave` `DEBUG`变量增加消息的详细程度。将变量值减到7甚至15并重启守护进程。现在`/var/log/messages`中的错误信息将更加详细，使你识别错误。

- 虽然激活了ACPI，但电池状态和按钮未按配置工作。

如果你遇到ACPI问题，使用以下命令搜索`dmesg -i acpi`的输出。ACPI特定的消息：可能需要更新BIOS来解决此问题。前往笔记本电脑制造商的主页，寻找更新的BIOS版本并安装。要求制造商遵守最新的ACPI规范。如果BIOS更新后错误仍然存在，请按照以下步骤操作：

1. 从`http://acpi.sourceforge.net/dsdt/tables`下载你系统的DSDT。检查文件是否已解压缩并编译为`.aml`（ACPI语言）。如果下载的表扩展名为`.asl`（ACPI源码），则必须使用`asl`进行编译。最新版本的`asl`（Intel ACPI编译器）可在`http://developer.intel.com/technology/iapc/downloads.htm`获取。

2. 将`DSDT.aml`复制到任何位置（建议使用`/etc/initrd`）。编辑`/sysconfig`并调整路径。运行`initrd`创建`initrd`，修改后的DSDT将系统启动时集成并加载。

- CPU频率不起。

参考内核源码查看是否支持你的进程。你可能需要特殊的模块或选项来激活CPU频率。在`/etc/sysconfig/powersave/common`文件中通过变量`CPUFREQ_MODULE`和`CPUFREQ_OPTIONS`配置。

- 挂起和待机不起。

有几个内核相关问题阻止了在ACPI系统上使用挂起：

- 目前，内存大于1 GB的系统（尚未）支持挂起。

- 目前，多处理器系统和带有P4处理器（带超线程）的系统不支持挂起。

错误也可能是由于故障的DSDT实现（BIOS）。如果是这种情况，按照“虽然激活了ACPI，但电池状态和按钮未按配置工作”下的描述安装新的DSDT。
