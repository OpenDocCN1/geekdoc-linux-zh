
# 循环的第一条指令是 `cmp`

循环的第一条指令是 `cmp`，它正在比较 `i` (rcx) 和 64。所选的条件跳转 `jnl` 匹配 C 条件的反向。希望这比使用 `jge` 不那么困惑。循环的最后一条指令跳转到循环的第一条语句。这是 `while` 循环的典型翻译。

用这种 C 编码并运行 `gcc -O3 -S countbits.c` 会生成一个名为 `countbits.s` 的汇编文件，遗憾的是它并不完全符合我们的 yasm 语法。gcc 的汇编器 gas 使用 AT&T 语法，这与 yasm 使用的 Intel 语法不同。主要是源操作数和目标操作数反转了，并且对指令助记符进行了细微更改。以下是 gcc 生成的程序循环部分：

```assembly
movq    data(%rip), %rax
movl    $64, %ecx
xor     %edx, %edx
.L2:
movq    %rax, %rsi
sarq    %rax
andl    $1, %esi
addq    %rsi, %rdx
subl    $1, %ecx
jne     .L2
```

你注意到编译器通过将测试移到循环末尾消除了一个跳转指令。此外，编译器没有执行 `compare` 指令。事实上，它发现 `i` 计数到 64 并不重要，只有迭代次数重要，因此它从 64 减到 0。因此，在递减后可以进行条件跳转。总而言，编译器生成了一个包含 6 条指令的循环，而手编写的汇编循环使用了 8 条指令。

正如引言中所述，一个优秀的编译器是不可比拟的。通过研究编译器生成的代码可以学到很多。如果你对效率感兴趣，你可能比编译器做得更好。你完全可以复制生成的代码并执行完全相同的操作，但如果你无法改进编译器的代码，那么你应该坚持使用 C 语言。

## 8.3 While 循环（续）

C 的 `while` 支持 `break` 语句（用于退出循环）和 `continue` 语句（用于立即返回循环顶部）。结构化编程倾向于避免 `break` 和 `continue`。然而，它们是某些问题的有效解决方案，且如果使用得当，通常比基于条件变量的替代方案更清晰。在汇编中实现它们比实现条件变量容易得多，而且速度更快。

### 8.3.2 Do-while 循环

`do-while` 循环执行体至少一次。它在 C 语言中通常如下所示：

```c
do {
    statements;
} while ( condition );
```

在汇编中，它被翻译为：

```assembly
do_loop:
    statements
    cmp condition
    jne end_do
```

### 8.3.3 计数循环

C 语言中普通的计数循环是 `for` 循环，它可以用于实现任何类型的循环。假设我们想要进行数组相加。在 C 语言中我们可能会使用：

```c
for ( i = 0; i < n; i++) {
  c[i] = a[i] + b[i];
}
```

翻译成汇编语言，这个循环可能是：

```assembly
for:
  mov rdx, [n]
  xor ecx, ecx
  cmp rcx, rdx
  je end_for
  mov rax, [a+rcx*8]
  add rax, [b+rcx*8]
  mov [c+rcx*8], rax
  inc rcx
  jmp loop
end_for:
```

## 8.4 循环指令

有一个 `loop` 指令以及几个变体，它们通过递减 `rcx` 寄存器并分支，直到寄存器达到 0。遗憾的是，从 `rcx` 减去 1 并使用 `jnz` 执行条件跳转要快大约 5 倍。此外 `loop` 指令仅限于跳转到 8 位的立即数字段，这意味着它只能向后或向前跳转约 127 字节。总而言之，它似乎并不值得使用。

尽管有上述忧郁的叙述，也许你可能仍然想使用循环（loop）。考虑以下代码，它在数组中查找特定字符的最后一次出现：

```assembly
mov      ecx, [n]
more:    cmp     [data+rcx-1], al
         je      found
         loop    more
found:   sub     ecx, 1
         mov     [loc], ecx
```

## 8.5 重复字符串（数组）指令

x86-64 重复指令（rep）会按照计数寄存器（rcx）中指定的次数重复执行字符串指令。有几种变体，允许根据循环执行期间可能发生的条件提前终止。重复指令允许将数组元素设置为指定值、将一个数组复制到另一个数组中，以及在数组中查找特定值。

### 8.5.1 字符串指令

字符串指令有几种。遍历数组的指令带有后缀 b、w、d 或 q，以指示数组元素的大小（1、2、4 或 8 字节）。
字符串指令使用寄存器 rax、rsi 和 rdi 用于特殊目的。寄存器 rax 或其子寄存器 eax、ax 和 al 用于持有一个特定值。寄存器 rsi 是源索引寄存器，rdi 是目的索引。所有字符串指令都不需要操作数。

所有处理 1、2 或 4 字节数量的字符串操作都编码在 1 字节中，而 8 字节的变体被编码为 2 字节。与 1 字节的重复指令结合，这实际上在 2 或 3 字节内编码了一些相当简单的循环。重复指令是无敌的。

字符串操作在每次使用后都会更新源和/或目的寄存器。这种更新由方向标志（DF）管理。如果 DF 为 0，则每次使用后寄存器都会增加数据项的大小。如果 DF 为 1，则每次使用后寄存器都会减少。

## 移动

`movsb` 指令将字节从 rsi 指定的地址移动到 rdi 指定的地址。其他 mov 指令使用从 [rsi] 到 [rdi] 移动 2、4 或 8 字节的数据元素。移动的数据存储在寄存器中，不影响任何标志。在移动每个数据项后，根据数据项的大小，rdi 和 rsi 寄存器推进 1、2、4 或 8 字节。

下面是从一个数组向另一个数组移动 100000 字节的代码：

```assembly
lea      rsi, [source]
lea      rdi, [destination]
mov      rcx, 100000
rep      movsb
```

## 存储

`stosb` 指令将寄存器 al 中的字节移动到 rdi 指定的地址。其他变体将数据从 ax、eax 或 rax 移动到内存。不影响任何标志。重复存储可以使用单个值填充数组。你可以在非重复循环中使用 stosb，利用目的寄存器自动更新的特性。

这里是向数组中填充 100000 个双字（double words）且全部等于 1 的代码：

```assembly
mov      eax, 1
mov      ecx, 100000
lea      rdi, [destination]
rep      stosd
```

## 加载

`lodsb` 指令将字节从 rsi 指定的地址移动到 al 寄存器。其他变体将更多字节的数据加载到 ax、eax 或 rax。不影响任何标志。重复加载似乎作用不大。然而，你可以在其他循环中使用加载指令。这里利用目的寄存器自动更新的特性，从一个数组向另一个数组加载 13 字节的字符：

```assembly
lea      rsi, [source]
lea      rdi, [destination]
mov      rcx, 100000
more:    lodsb
         cmp      al, 13
         je       skip
         stosb
skip:
```

## 扫描

`scasb` 指令在数组中搜索匹配 al 的字节。这里是 strlen 的一种实现：

```assembly
segment .text
global strlen
strlen:
    cld
    mov      rcx, -1
    xor      al, al
    repne    scasb         ; 扫描到 0
    not      rcx
    dec      rcx
    ret
```

## 比较

`cmpsb` 指令比较字节值。通常它与 repeat 结合使用。这里是 strcmp 的一个版本：

```assembly
segment .text
global strcmp
strcmp:
    cld
    cmpsb
    cmp      rcx, 0
    jz       equal
    movzx    eax, byte [rsi-1]
    movzx    ecx, byte [rdi-1]
    sub      eax, ecx
    ret
equal:
    xor      eax, eax
    ret
```

## 设置/清除方向

`cld` 指令将方向标志清除为 0，这意味着处理地址的方式。`std` 指令将方向标志设置为 1。程序员应该在退出任何函数之前清除它。

# 第 9 章 函数

在本章中，我们将讨论如何编写可以从 C 或 C++ 调用的函数，以及如何从汇编调用 C 函数。由于 C 或 C++ 编译器通常在代码生成方面做得非常好，因此通常不需要用汇编编写完整的程序。某些算法可能最好用汇编实现，因此我们可能会用 C 或 C++ 编写程序的 90%，而用汇编编写一些函数。

从汇编调用 C 函数也是非常有用的。这使得你的汇编程序能够完全访问所有的 C 库。我们将使用 scanf 从标准输入读取值，并使用 printf 打印结果。这将允许我们编写更有用的程序。

## 9.1 栈

到目前为止，我们很少使用运行时栈，但它是使用函数不可或缺的一部分。我们之前提到栈延伸到最高可能的地址：0xffffffffff。这并不完全正确。通过 `cat /proc/$/maps` 检查内存映射显示，bash 的顶部栈地址是 0x7ffff6b79000，其他匹配模式 0xffffXXXXXX 的进程值不同。这可能是“栈随机化”的结果，是为了避免修改栈值的恶意代码。

使用 `push` 指令将项推入栈。其效果是将栈指针 `rsp` 减 8，然后将要推入的值放置在该地址上。在进程启动时，操作系统最初会将栈指针设置为 `0x7fffffff000`（或任何以 `000` 结尾的地址）。在第一次 `push` 时，`rsp` 会减少到 `0x7fffffffffff8`，一个 8 字节的值会被放置在 `0x7fffffffffff8` 到 `0x7fffffffffff` 字节之间。

操作系统会将许多不同的值推入栈中。这些包括环境（定义搜索路径等内容的变量名和值的集合）以及程序的命令行参数。

可以使用 `pop` 指令从栈中移除值。`pop` 的操作模式与 `push` 相反。它将栈指针（`rsp`）指定位置的值移动到寄存器或内存位置，然后将 `rsp` 加 8。

你可以 `push` 和 `pop` 比 8 字节更小的值，但存在风险。只要栈对于当前操作保持恰当的边界，这种操作就能生效。如果你先推入一个字（word）再推入一个双字（quad-word），双字的推入可能会失败。更简单的方法是只 `push` 和 `pop` 8 字节的量。

## 9.2 call 指令

调用函数的汇编指令是 `call`。典型的用法如下：

```assembly
call my_function
```

操作数 `my_function` 是程序文本段中的一个标签。`call` 指令的作用是将 `call` 之后的指令地址推入栈中，并将控制权转移到与 `my_function` 关联的地址。推入的地址被称为“返回地址”。另一种实现调用的方法是：

```assembly
push next_instruction
jmp my_function
next_instruction:
```

虽然这种方法可行，但 `call` 指令具有许多功能，我们通常会忽略它们。

## 9.3 ret 指令

要从函数返回，我们使用 `ret` 指令。该指令从栈顶弹出地址并将控制权转移到该地址。在之前的示例中，`next_instruction` 是返回地址的标签。

## 9.4 函数参数和返回值

大多数函数都有参数，这些参数可能是整数值、浮点值、数据值的地址、数组的地址或任何其他类型的数据或地址。参数允许我们在每次调用时使用函数处理不同的数据。此外，大多数函数都有返回值，返回值通常是成功或失败的指示。

x86-64 Linux 使用一种名为“System V Binary Interface”或 System V ABI 的函数协议。遗憾的是，Windows 使用另一种名为“Microsoft x64 Calling Convention”的协议。在这两种协议中，某些函数参数是通过寄存器传递的。Linux 前 6 个整数参数通过寄存器传递，而 Windows 允许前 4 个（使用不同的寄存器）。Linux 允许前 8 个浮点参数通过浮点寄存器 `xmm0-xmm7` 传递，而 Windows 允许前 4 个浮点参数通过寄存器 `xmm0-xmm3` 传递。

Linux 和 Windows 都使用 `rax` 作为整数返回值，使用 `xmm0` 作为浮点返回值寄存器。

Linux 和 Windows 都期望栈指针在内存中保持 16 字节对齐的边界。这意味着 `rsp` 的十六进制值应该以 0 结尾。此要求的原因是为了允许函数中的局部变量以 16 字节对齐的方式放置，以便 SSE 和 AVX 指令。执行 `call` 会递减 `rsp` 8 字节，使其不再 16 字节对齐。规范的函数应该推入某些内容或减去 `rsp` 以恢复 16 字节边界。如果你的函数调用了任何外部函数，似乎遵循 16 字节边界要求是明智的。

Linux 下函数的前 6 个整数参数通过寄存器 `rdi`、`rsi`、`rdx`、`rcx`、`r8` 和 `r9` 传递，而 Windows 使用 `rcx`、`rdx`、`r8` 和 `r9` 用于前 4 个整数参数。如果函数需要更多参数，它们将反序推入栈中。

scanf 和 printf 等变参数函数使用 `rax` 寄存器传递函数调用中浮点参数的数量。

对于 32 位程序，协议是不同的。寄存器 `r8-r15` 不可用，因此通过寄存器传递函数参数没有意义。这些程序使用栈处理所有参数。

我们终于准备好打印“Hello World!”了。

```assembly
section .data
msg:
    db "Hello World!", 0x0a, 0
```

```assembly
section .text
global main
extern printf

main:
    push    rbp
    mov     rdi, rsp
    lea     rdi, [msg]    ; printf 的参数 1
    xor     eax, eax      ; 0 个浮点参数
    call    printf
    xor     eax, eax      ; 返回 0
    pop     rbp
    ret
```

我们使用“加载有效地址”指令（`lea`）通过 `rdi` 加载要打印消息的有效地址。也可以通过 `mov` 实现，但 `lea` 允许在括号中指定更多项，因此我们可以加载数组元素的地址。

有趣的是，当系统启动程序时，`_start` 的参数会被推入栈中。然而，`main` 的参数像其他 C 函数一样是通过寄存器传递的。

## 9.5 栈帧

gdb 调试器最有用的功能之一是回溯已调用的函数（命令 `bt` 或 `backtrace`）。为了实现这一技巧，每个函数必须在栈上的一个 2 双字对象中保留一个指针，标识 `rbp` 的旧值以及返回地址。你可能会在 hello world 程序中看到 `push rbp, mov rbp, rsp` 序列。第一条指令将 `rbp` 推入返回地址正下方。第二条指令使 `rbp` 指向该对象。

假设所有函数都遵循这种以标准两条指令开头的规则，那么栈上将存在一个对象链表——每个函数一个对象。调试器可以遍历该列表以识别被调用的函数（基于返回地址的位置），并使用可执行文件中存储的其他信息来识别该返回地址对应的行号。

这些 2 双字对象是“栈帧”的简单示例。在不调用其他函数（叶子函数）中，函数的局部变量可能完全可以放入寄存器中。如果局部变量太多或者函数调用了其他函数，则可能需要在栈上为这些局部变量留出空间。要为局部变量分配空间，只需从 `rsp` 中减。例如，在栈帧中为局部变量留出 32 字节：

```assembly
push    rbp
mov     rbp, rsp
sub     rsp, 32
```

确保减去的是 16 字节的倍数，以避免可能的栈对齐问题。这两条指令的效果以及可能的 `rsp` 减法操作可以在 `ret` 指令之前使用 `leave` 来撤销：

```assembly
leave
```
