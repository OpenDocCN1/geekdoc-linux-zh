
进入`/path/to/xxx`目录，找到`xxx.json`。

`XSetWireToError` 函数定义了一个当扩展错误需要从线缆格式转换为主机格式时调用的程序。错误编号定义了要为哪个协议错误代码安装转换程序：`XSetWireToError` 返回之前定义的任何程序。

当扩展错误包含核心 X 错误之外的额外错误值、当多个线缆错误必须合并为一个 Xlib 错误时，或者当必要在执行之前拦截 X 错误时，请使用此函数处理扩展错误。

当 Xlib 需要将错误从线缆格式转换为主机格式时，程序将带有这些参数被调用：

```
int (*proc)(display, he, we);
```

该参数是应该存储主机错误格式位置的指针。由它指向的结构保证大小与 `XEvent` 一大，因此可以强制转换为比 `XEvent` 大的类型以存储额外值。如果 Xlib 完全忽略该错误（例如，多个协议结构将合并为一个 Xlib 错误），则函数应返回 `False`；否则，它应返回 `True`。

```
int *XSetError(display, extension, (*proc) ());
```

- `display`：指定到 X 服务器的连接。
- `extension`：指定扩展编号。
- `proc`：指定当发生错误时要调用的程序。

在 Xlib 内部，有时您可能希望在发生错误时抑制调用外部错误处理。调用时请返回此状态，代价是调用是同步的（在任何情况下，大多数此类函数如查询操作如此，并且通常被设计为同步）。

当 Xlib 在 `_XReply` 中检测到协议错误时，它将带有这些参数调用您的程序：

```
int (*proc)(display, err, codes, ret_code);
```

该参数是指向 32 位线缆格式错误的指针。`code` 参数是指向扩展数据结构的指针。返回参数是您可能希望 `_XReply` 返回的代码。

如果您的程序返回零值，则错误不会被抑制，并将调用客户端的错误处理程序。（有关更多信息，请参见第 11.8.2 节。）如果您的程序返回非零，则错误被抑制，`_XReply` 返回 `ret code` 的值。

```
char *XSetErrorString(display, extension, (*proc) ());
```

- `display`：指定到 X 服务器的连接。
- `extension`：指定扩展编号。
- `proc`：指定为获取错误字符串时要调用的程序。

`XGetErrorText` 函数为错误向用户返回一个字符串：`XSetErrorString` 允许您定义一个应该被调用的程序，该程序应返回一个指向错误消息的指针。以下是一个示例。

```
int (*proc)(display, code, codes, nbytes);
```

每检测到一个错误，您的程序都会带有错误代码被调用。您应该将包含错误消息的空终止字符串的字节复制到缓冲区。

```
void XESetPrintErrorValues(display, extension, (*proc)());
```

- `display`：指定到 X 服务器的连接。
- `extension`：指定扩展编号。
- `proc`：指定在打印错误时要调用的程序。

`XESetPrintErrorValues` 函数定义了一个当报告扩展错误时调用的程序，用于打印错误值。使用此函数处理包含核心 X 错误之外额外错误值的扩展错误。当 Xlib 需要将错误从线缆格式转换为主机格式时，程序将带有这些参数被调用：

# 挂钩数据结构

各种 Xlib 数据结构提供了扩展程序来链扩展数据。这些结构是 `GC`, `Visual`, `Screen`, `ScreenFormat`, `Display` 和 `XFontStruct`。由于列表指针始终是结构的第一个成员，可以使用一组程序来操作这些数据。

以下结构用于本节中的函数并定义在 `<X11/Xlib.h>` 中。

```
typedef struct _XData {
    int number; /* XInitExtension 返回 */
    struct _XData *next; /* 列表中下一个项 */
    int (*free_private)(); /* 如果定义，用于释放私有 */
    XPointer private_data; /* 此扩展的私有数据 */
};
```

当释放上述上述结构时，遍历列表并调用结构的释放程序（如果有）。如果 `free` 为 `NULL`，库将释放由私有数据指向的数据以及结构本身。

```
union { Display *display;
    GC gc;
    Visual *visual;
    Screen *screen;
    ScreenFormat *pixmap_format;
    XFontStruct *font; } XEDDataObject;
```

```
XExtData **XHeadOfExtensionList(object);
```

`object`：指定对象。

`XHeadOfExtensionList` 函数返回指向附加指定对象的列表指针。与 `AddToExtensionList` 配合使用，`XHeadOfExtensionList` 允许扩展附加 `XEDDataObject` 中包含的任何类型。

`AddToExtensionList(structure, ext_data);`
指定扩展列表。

`structure`：要添加的扩展数据结构。

`structure` 参数是指向上述枚举数据结构的指针。在调用此函数之前，必须初始化 `ext_data->number` 为扩展编号。

```
XExtData *FindOnExtensionList(structure, number);
```

`structure`：指定扩展列表。

# 扩展

`number` 指定来自 `XInitExtension` 的扩展编号。

`XFindOnExtensionList` 函数返回编号为该扩展第一个扩展数据结构。预期一个扩展在任何单个数据结构的扩展数据列表中最多添加一个扩展数据结构。没有办法可以找到额外的结构。

`XAllocID` 宏用于分配并返回资源 ID，它定义在 `<X11/Xlib.h>` 中。

```
XAllocID(display);
```

`display` 指定到 X 服务器的连接。

此宏通过 `Display` 结构体调用内部资源分配器。它返回一个资源 ID，你可以在创建新资源时使用它。

`XAllocIDs` 宏分配并返回一个资源 ID 数组。

```
XAllocIDs(display, ids_return, count);
```

`display` 指定到 X 服务器的连接。

`ids_return` 返回资源 ID。

`rep` 指定所请求的资源 ID 数量。

此宏通过 `Display` 结构体调用内部资源分配器。它将资源 ID 返回到调用者提供的数组中。为了正确处理资源 ID 的自动释放，在请求多个资源 ID 时必须调用 `XAllocIDs`。这可能会产生协议请求。

# GC 缓存

库对 `GC` 进行缓存，允许将针对同一个 `GC` 的独立更改请求合并为单个协议请求。这通常是一个写回缓存。任何行为取决于 `GC` 内容的扩展过程必须刷新 `GC`，以确保服务器拥有其最新的内容。

`FlushGC` 检查库中 `GC` 结构中的脏位（`dirty bits`），如果任何元素发生变化，则调用 `_FlushGCCache`。`FlushGC` 宏定义如下：

```
FlushGC(display, gc);
```

`display` 指定到 X 服务器的连接。

`gc` 指定指定的 `GC`。

请注意，如果你扩展了 `GC` 以添加额外的资源 ID 组件，你应该确保库立即存根更改请求。因为客户端可能在使用资源后立即释放它，所以如果你只将值存储在缓存中而不强制发送协议请求，该资源可能在变为 `GC` 之前被销毁。使用 `_FlushGCCache` 过程强制刷新缓存。`_FlushGCCache` 过程定义如下：

```
_FlushGCCache(display, gc);
```
