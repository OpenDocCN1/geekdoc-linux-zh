
所以我们现在可以通过相对于`%ebp`的不同偏移来访问函数所需的所有数据。`%ebp`专门为此目的设计的，这就是为什么它被称为基址指针。你可以在基址寻址模式中使用其他寄存器，但 x86 架构使得使用`%ebp`寄存器快得多。

你可以看到，每个参数都可以通过相对于`%ebp`的偏移来访问。接下来，函数在栈上为任何局部变量留空间。这是通过简单地移动栈指针来实现的。假设我们移动两个字来运行一个函数。我们可以简单地向下移动栈指针来留空间。做法如下：

```
subl $8, %esp
```

这从`%esp`减 8（记住，一个字是四个字节）。这样，我们可以使用栈进行变量存储，而不必担心因函数调用而进行的 push 操作覆盖它们。此外，由于它是分配在函数调用的栈帧上的，该变量只在该函数期间存。当我们返回时，栈帧将消失，这些变量也会消失。这就是为什么它们被称为局部——它们只在函数被调用时存在。

现在我们有两个字用于局部存储。我们的栈现在看起来如下：

| 项目 | 偏移 |
|---|---|
| Parameter #N | N*4+4 (%ebp) |
| ... | ... |
| Parameter 2 | 12 (%ebp) |
| Parameter 1 | 8 (%ebp) |
| Return Address | 4 (%ebp) |
| Old %ebp | -4 (%ebp) |
| Local Variable 1 | -8 (%ebp) 和 (%ebp) |

+   3. 提醒一下——8 前前的美元符号表示立即数寻址，意味着我们将数字 8 加载到`%esp`，而不是地址 8 处的值。

# 第 4 章：关于函数

全局变量和静态变量的访问方式与我们在前面的章节中访问内存的方式相同。全局变量和静态变量唯一的区别在于静态变量只被一个函数使用，而全局变量被许多函数使用。汇编语言对待它们的方式完全相同，尽管大多数其他语言会将它们区分开。

当一个函数执行完毕时，它会完成三件事：

- 1. 它将返回值存储在`%eax`中。
- 2. 它将堆栈重置为调用时的状态（移除当前的栈帧并使代码的栈帧重新生效）。
- 3. 它返回到调用它的地方。这是通过使用`ret`指令实现的，该指令弹出栈顶的任何值，并将指令指针`%eip`设置成该值。

因此，在函数将控制权返回给调用的代码之前，它必须恢复之前的栈帧。还要注意，如果不这样做，`ret`将无法工作，因为在我们当前的栈帧中，返回地址不在栈顶上。因此，在我们返回之前，我们必须将堆栈指针`%esp`和基指针`%ebp`重置为函数开始时的状态。

因此，要从函数返回，你需要执行以下操作：

```assembly
mov %ebp, %esp
pop %ebp
ret
```

此时，你应该认为所有的局部变量都被销弃了。原因是当你把堆栈指针移回后，未来的堆栈推送操作可能会覆盖你放在那里的所有内容。因此，你永远不要在创建该局部变量函数的生命周期之外保存该变量的地址，否则它将在栈帧生命周期结束后被覆盖。

控制权现在已经交还给了调用代码，该代码现在可以检查`%eax`以获取返回值。调用代码还需要弹出它推入堆栈的所有参数，以便将堆栈指针恢复到原来的位置（如果你不再需要参数的值，也可以简单地使用`add`指令向`%esp`加上`4 * 参数数量`）。

## 寄存器的销毁

当你调用一个函数时，你应该假设你寄存器中的所有内容都会被清空。唯一保证保持其初始值值的寄存器是`%ebp`。`%eax`保证会被覆盖，其他寄存器也同样如此。如果你在调用函数之前想要保存某些寄存器，你需要在推入函数参数之前通过将它们推入堆栈来保存它们。你可以在弹出它们后反向将它们弹出。如果你的函数没有覆盖要保存的寄存器，你也应该保存它，因为该函数的未来版本可能会覆盖。

其他语言的调用约定可能不同。其他调用约定可能会将保存所使用的任何寄存器的负担交给函数。在尝试混合语言之前，一定要确保你的语言的调用约定是兼容的。在汇编语言的情况下，确保你也知道如何调用另一种语言的函数。

**扩展规范**：C语言调用约定（也称为 ABI，应用程序二进制接口）的细节可以在网上找到。为了方便初学者，我们进行了过度简化并省略了一些重要部分。要查看完整细节，你应该检查 `http://www.linux.org/spec/refpecs/` 上的文档。具体来说，你应该寻找《System V Application Binary Interface - Intel386 Architecture Processor Supplement》。

- 5. 除非你在函数调用之前在堆栈上保存寄存器，否则并不总是严格需要的。基指针保持栈帧处于一个相当一致的状态。然而，这仍然是一个好主意，如果你在堆栈上临时保存寄存器，这是绝对必要的……

### 函数示例

让我们看看函数调用在实际程序中是如何工作的。我们将编写的函数是幂函数（`power`）。我们将给幂函数提供两个参数——数字和我们要对其提升的幂。例如，如果我们给它参数 2 和 3，它将计算 2 的 3 次方，即 2*2*2，得到 8。为了让程序变得简单，我们只允许大于 1 的数字。

以下是完整程序的代码。按照惯例，后面会有说明。文件名命名为`power.s`。

```assembly
## 目的：演示函数如何工作的程序
## 此程序将计算
## 2^3 + 5^2 的值
```

```assembly
## 主程序中的一切都存储在寄存器中，
## 所以数据段没有任何。
.section .data
```

```assembly
.section .text
.globl _start
_start:
    pushl $3          # 推入第二个参数
    pushl $2          # 推入第一个参数
    call power        # 调用函数
    addl $8, %esp      # 移动堆栈指针
    pushl %eax        # 在调用下一个函数之前保存第一个答案
```

```assembly
    pushl $2             # 推入第二个参数
pushl $5             # 推入第一个参数
call               # 调用函数
addl $8, %esp       # 移动堆栈指针
```

```assembly
popl %ebx           # 第二个答案已经在
## eax 中了。我们把第一个
## 答案保存在了栈上，
## 现在我们只需要将其弹出
## 到 %ebx 中
```

```assembly
addl %eax, %ebx     # 将它们相加
mov %ebx, %eax      # 将结果移动到 eax
int $0x80           # 退出
```

```assembly
## 目的：此函数计算数字的幂值。
## 输入：第一个参数 - 底数，第二个参数 - 幂
## 输出：将在 eax 中获取结果。
## 变量：%ebx - 存储底数，%ecx - 存储幂
power:
    pushl %ebp          # 保存基指针
    mov %esp, %ebp      # 使栈指针等于基指针
    subl $8, %esp       # 为局部变量留空间
    movl 8(%ebp), %ebx  # 获取第一个参数
    movl 4(%ebp), %ecx  # 获取第二个参数

loop_start:
    cmpl $1, %ecx       # 如果幂为 1，我们就完成了
    je end_power
    imull %ebx, %eax    # 结果乘以底数
    decl %ecx           # 减少幂
    jmp loop_start

end_power:
    mov %ebp, %esp      # 恢复堆栈指针
    popl %ebp           # 恢复基指针
    ret
```

## 第 4 章：关于函数的一切

接下来，我们有了设置函数的指令：

```
pushl %ebp
mov %esp, %ebp
sub $4, %esp
```

此时，我们的栈结构如下所示：

| 基址 (Base) | 值 (Value) |
|---|---|
| 基数数字 (Base Number) | 12 (%ebp) |
| 指数 (Power) | 8 (%ebp) |
| 返回地址 (Return Address) | 4(%ebp) |
| 旧 %ebp | (%ebp) |
| 当前结果 (Current result) | 4(%ebp) 和 (%ebp) |

虽然可以使用寄存器进行临时存储，但此程序使用了局部变量来设置。通常寄存器不足以存储所有内容，因此你必须将它们加载到局部变量中。在其他情况下，你的函数需要调用另一个函数并发送某些数据的指针。你无法拥有指向寄存器的指针，因此必须将其存储在局部变量中以便发送其指针。
