## 1.6 强制性控制

强制性控制（`MAC`）在基础自主性访问控制（`DAC`）之上为进程提供了额外的一层访问限制。通过限制进程对系统上文件和资源的访问，可以减少程序漏洞带来的潜在影响。

影响：强制性控制限制了应用程序和守护进程的能力，虽然可以防止未经授权的访问，`MAC` 的配置可能复杂且难以实现，导致合法访问失败。

备注：

- `armor` 是 `Debian` 系统提供的默认 `MAC`。
- 其他强制性控制系统包括 `SELinux`。

### 1.6.1 配置 AppArmor

`AppArmor` 提供了一种强制强制性控制系统，它极大增强了自主性访问控制 (`DAC`) 模型。在 `AppArmor` 中，`MAC` 规则通过文件路径应用，而不是其他 `MAC` 系统中的安全上下文。因此，它不需要文件系统的支持，例如网络文件系统。`AppArmor` 安全策略定义了应用程序可以访问哪些系统资源以及它们可以执行哪些权限。这自动限制了软件对调用用户可访问的文件造成的破坏。用户无需采取任何操作即可获得此好处。要执行操作，必须同时满足传统的 `DAC` 权限和 `AppArmor` 的 `MAC` 规则。如果其中任何一个模型不允许该操作，操作将不会允许。通过这种，`AppArmor` 规则只能使系统的权限更加严格和更安全。

参考文献：

1. `AppArmor` 文档：http://wiki.apparmor.net/index.php/Documentation
2. `Ubuntu` `AppArmor` 文档：https://help.ubuntu.com/community/AppArmor
3. `SUSE` `AppArmor` 文档：https://www.suse.com/documentation/apparmor/

### 1.7 命令行横幅

在普通用户登录前显示警告消息可能对起诉入侵计算机系统的入侵者有帮助。更改这些登录横幅的副作用是向试图针对系统特定漏洞的攻击者隐藏操作系统版本信息和其他详细系统信息。`/etc/motd`、`/etc/issue` 和 `/etc/issue.net` 文件控制本地和远程用户标准命令行登录的警告横幅。美国国防部发布的指南要求警告消息至少包含拥有该系统的组织名称、系统受监控的事实以及使用系统即表示同意此类监控。重要的是，必须符合当地法规的要求，并且在对系统进行任何修改之前，由组织的法律顾问审查所有消息的内容，因为这些警告横幅本质上是特定于站点的。更多信息（包括相关判例法的引用）可以在 http://www.justice.gov/criminal/cybercrime 处找到。

注意：这些项目修复操作中提供的文本仅供示例。请根据法律部门批准的内容进行编辑以包含组织的特定文本。

## 1.7.1 确保今日消息（message of the day）配置正确

（自动化）

配置适用性：

- Level 1 - 服务器
- Level 1 - 工作站

描述：

`/etc/motd` 文件的内容会在用户登录后显示，作为身份验证用户的今日消息（`message of the day`）。

基于 `Unix` 的系统在登录系统时通常会显示操作系统发布版本和补丁级别信息。这些信息对于为特定 `OS` 平台开发软件的开发者可能有用。如果 `mingetty()` 支持以下选项，它们将显示操作系统信息：

- `-m` - 机器架构
- `\r` - 操作系统发布版本
- `\s` - 操作系统名称
- `\v` - 操作系统版本

原理：

警告信息向尝试登录系统的用户告知其关于该系统的法律状态，并且必须包含拥有该系统的组织名称以及任何执行的监控策略。在登录横幅中显示操作系统和补丁级别信息还会产生副作用，即为试图针对系统特定漏洞的攻击者提供详细的系统信息。授权用户在登录后可以轻松通过运行 `uname -a` 命令获取这些信息。

审计：

运行以下命令并验证没有返回任何结果：

```bash
# grep -Eis "\\v\\\r\\\m\\\$\$(grep '^ID=' /etc/os-release | cut -d=-f2 | sed -e 's/"//g')" /etc/motd
```

修复：

根据您的站点策略用适当的内容编辑 `/etc/motd` 文件，删除所有 `\m`、`\r`、`\s`、`\v` 的用例，或或删除对 `OS` 平台的引用；或者如果不使用 `motd`，可以删除此文件。运行以下命令删除 `motd` 文件：

```bash
# rm /etc/motd
```
