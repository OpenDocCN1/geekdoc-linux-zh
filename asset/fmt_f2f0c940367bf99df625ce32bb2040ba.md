# automount

是由守护进程执行某些文件系统的挂载和卸载的过程。如果文件系统被卸载，用户尝试访问它，它将自动（重新挂载）。这在大型网络环境以及几台机器之间的交叉文件系统中（特别是那些并非总是在线的机器）特别有用。它对于可移动设备，或对同一设备的强制挂载/强制卸载可能非常有用。如果您是 Linux 新手并理解什么是挂载，请参考一些文档，Linux 中有两种类型的自动挂载器：AMD 和 `autofs`。AMD 是守护进程，据认为工作方式类似于 SunOS。它在用户空间中实现，意味着不是内核的一部分。有必要让 AMD 路由通过 NFS 的本地流量。Autofs 是一个由内核辅助的新系统，意味着内核知道挂载点在哪里，否则 `automount` 会在 fs 处工作。只有 `autofs` 会在 mini-howto 中描述。源自 Autount。

# auto_resume

此变量控制 shell 与用户以及作业控制之间的交互。如果设置了此变量，没有重定向的单单词命令将被处理为恢复已停止作业的候选方案。这里没有歧义；如果有多个与输入字符串开头的作业，将选择最近访问的作业。在此语文中，已停止作业的名称是启动它时使用的命令行。如果设置为某个值，则该字符串必须匹配已停止作业的名称；如果设置为子字符串，则该字符串只需匹配已停止作业名称的子字符串。该存根提供了与下文 `%` 作业控制 类似的功能。如果设置为任何其他值，则字符串必须是已停止作业名称的前缀；这提供了类似于 `%` 作业 ID的功能。源自 Route–Users–Guide

http://www.tld.org/LDP/Linux-Dictionary/index.html
