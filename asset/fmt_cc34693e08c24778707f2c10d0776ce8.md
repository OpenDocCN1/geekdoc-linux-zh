
第一种是在 `%SYSTEMROOT\system32\drivers\etc\lmhosts` 目录下创建一个文件。在该文件中放入两个条目：
- `192.168.66.4 goofy #DOM:TESTDOM`
- `192.168.66.4 TESTDOM`

将 `goofy` 替换为你的 Samba PDC 名称，将 `TESTDOM` 替换为你的 Samba 域名称。现在，当 NT 尝试解析 NetBIOS 域名 `TESTDOM` 时，它可以成功解析。

第二方法是使用 WINS。这可能是扩展性更好的解决方案。确保在 `smbd.conf` 中设置了以下内容：

```ini
wins support = yes
```

然后将所有 Windows NT 机器的 Wins IP 地址条目添加到 Samba 服务器中。

## Samba PDC 上提供的 Windows NT 功能

现在你已经让 Samba 作为你的域控制器，你可能好奇 Samba 服务器上还有哪些 Windows NT 功能可用。Samba 2.1 开发代码实现了一些功能，例如能够查看并部分操作文件权限、在服务器管理器中查看 Samba 服务器，以及在域用户管理器中查看你的 Samba SAM 等效文件 `smbpasswd` 文件。要使用本节中提到的工具，你需要一份 Windows NT Server 工具副本。你需要一个内置了这些工具的 Windows NT Server 副本，或者访问互联网从 `ftp://ftp.microsoft.com/Softlib/MSFILES/SRVTOOLS.EXE` 下载服务器工具。Windows 9x 版本位于相同位置，但名为 `NEXUS.EXE`。

## 文件权限

现在你通过 Samba 执行的酷炫功能之一是通过“安全”选项卡操作 Samba 服务器上的文件和目录权限，就像操作普通的 Windows NT 机器一样。

### Samba 上的 NT ACLs

在 Samba 2.0.4 及更高版本中，参数 `nt acl support` 默认设置为 `true`。为了能够在 NT 内部操作 Samba 服务器上的文件权限，请确保该参数没有出现在你的配置文件中，或如果它存在且设置为 `false`，请将其更改或直接删除以获取默认值。如果设置为 `false`，则访问控制列表 `ACL` 中的唯一访问控制条目 `ACE` 将是“所有人（完全控制）”。如果 `nt support` 开启，你通常会看到访问控制条目包含两个部分：格式为 `SERVERName (Name)` 的名称以及权限。`SERVER` 将是你 Samba 服务器的 NetBIOS 名称，`Name` 将是该条目描述的用户或组的名称，如果 ACE 描述的是一个用户，那么长名称将是 Samba 服务器上密码文件中该用户对应的组条目。

## Windows NT 全局组与本地组

你可能在想 Windows NT 中的全局组和本地组是什么，特别是如果你是从 UNIX 世界过来的话，因为那里没有这种概念。简单而言之，全局组 `global group` 是整个域内可用的组，因此在 SAM 中可见。本地组 `local group` 是仅在单机上可用的组。微软建议不要将 Windows NT 本地组应用于资源。本地组应该作为全局组的成员被包含，而用户被放入本地组中。然后，将这些全局组应用于整个域内的共享资源上。这种做法非常有道理。

假设你有一个名为 `Marketing` 的全局组。你还有本地组：`north-mrktg`、`south-mrktg`、`east-mrktg` 和 `west-mrktg`。你有四台分别位于北、南、东、西地区的不同服务器。北地区的所有用户都使用本地组 `north-mrktg`，因此他们的用户账户被放置在该组中，且该程序也适用于其他三个地区。这四个本地组作为全局组 `Marketing` 的成员被应用。现在，全局 `Marketing` 组被应用于所有营销组成员都可以访问的共享资源。由于所有本地组成员都是全局营销组的成员，他们都拥有正确的访问权限。例如，当一个新成员来到南部地区时，他或她只需要被添加到本地组 `south-mrktg` 即可。这意味着新成员拥有其他营销人员可以访问的所有资源的权限。参见图 7.10，查看用户、本地组和全局组如何结合的示意。在图中，重点是用户被放入他们的营销组中，这些组根据他们所在的北、南、东、西地区进行命名。然后，这些组被放入 `Marketing` 组，并作为权限应用于资源。显而易见的优势是，当一个新用户来到西部营销地区时，他只需要被添加到本地 `west-mrktg` 组一次，即可获得访问所有营销资源的权限。

当连接到 Windows NT 服务器时，如果你点击“添加” `Add` 按钮，你将获得域内的用户和组列表，可以从中选择并添加到 ACL。 由于 Samba 目前不支持 ACL，此功能目前尚未实现。未来有提供此类支持的计划。现在，如果你点击“添加”按钮，你将得到一个 RPC 协议错误，如图 7.13 所示。
