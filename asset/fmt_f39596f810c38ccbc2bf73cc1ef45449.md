
`enumerate(s)` 创建一个迭代器，返回元组序列 `(0, s[0]), (1, s[1]), ...`

循环 `else` 子句的主要用途是用于遍历数据但在循环中断时需要检查某种标志位或条件的代码。例如，如果你不使用 `else`，之前的代码可能需要如下所示使用标志位变量进行重写：

```python
found_separator = False

for line in open('foo.txt'):
    stripped = line.strip()
    if not stripped:
        found_separator = True
        break
    # 处理去除空格的行
...
```

```python
if not found_separator:
    raise RuntimeError("Missing separator")
```

## 异常

异常表示错误并跳出程序的控制流。异常用于引发语句。`raise` 的一般格式是 `raise Exception({value})`，其中 `Exception` 是异常类型，`value` 是提供异常特定信息的可选值。示例下：

```
raise RuntimeError("Unrecoverable Error")
```

如果单独使用 `raise` 语句，将再次抛出最后生成的异常（但这仅在处理之前抛出的异常时有效）。
要捕获异常，请使用 `try` 和 `except` 语句，如下：

```
try:
    f = open('foo')
except IOError as e:
    statements
```

## 异常 85

当发生异常时，解释器会停止执行块中的语句，并寻找与已发生异常匹配的 `except` 子句。如果找到，控制权将传递到 `except` 子句中的第一个语句。执行完 `except` 子句后，控制将继续执行 `try-except` 块之后的第一个语句。否则，异常将传播到出现 `try` 语句的代码块中。该代码可能被包含在另一个可以处理该异常的 `try-except` 块中。如果异常未被捕获，解释器将向上追溯到程序的顶层并退出。如果需要，未捕获的异常也可以传递给第 13 章“Python 运行时服务”介绍的自定义函数 `sys.excepthook()`。

`except` 语句可选的 `var` 修饰符提供了一个变量名，当发生异常时，`raise` 语句提供的异常类型实例将赋值给该变量。`except` 处理器可以检查此值以获取更多关于异常原因。例如，你可以使用 `isinstance()` 来检查异常类型。关于语法有一点注意：在 Python 之前的版本中，`except` 语句写为 `except ExcType, var`，其中异常和变量用逗号（.）隔开。在 Python 2.6 中，这种语法仍然有效，但已弃用。在新代码中，请使用 `as` 语法，因为它在 Python 3 中是强制。

使用多个 `except` 子句指定多个异常处理块，如下所示：

```
try:
    do something
except IOError as e:
    # 处理 I/O 错误
    ...
except TypeError as e:
    # 处理类型错误
    ...
except NameError as e:
    # 处理名称错误
...
```

单个处理器可以像这样捕获多种异常类型：

```python
try:
    do something
except (IOError, TypeError, NameError) as e:
    # 处理 I/O、类型或名称错误
```

要忽略某个异常，请像下面所示使用 `pass` 语句：

```python
try:
    do something
except IOError:
    pass  # 什么都不做（好吧）。
```

要捕获除这些之外的所有异常，可以像这样使用 `Exception`：

```python
try:
    do something
except Exception as e:
    error_log.write('发生错误: %s\n' % e)
```

## 第 5 章 程序结构与控制流

在捕获所有异常时，你应该注意向用户报告准确的错误信息。例如，在之前的代码中，记录了错误消息和相关的异常值。如果你不包含任何关于异常值的信息，对于调试因非预期原因失败的代码将变得非常困难。

可以使用如下不带任何异常类型的 `except` 来捕获所有异常：

```
try:
    do something
except:
    error_log.write('发生错误\n')
```

正确使用这种形式的 `except` 比看起来要复杂得多，并且应该避免使用。例如，这段代码还会捕获键盘中断和程序退出请求——这些是你可能并不希望捕获的内容。

`try` 语句还支持 `else` 子句，它必须跟在最后一个子句之后。如果 `try` 块没有引发异常，则执行此代码。这是一个示例：

```
try:
    f = open('foo', 'r')
except IOError as e:
    error_log.write('无法打开 foo : %s\n' % e)
else:
    data = f.read()
f.close()
```

`finally` 语句定义了 `try` 块中代码的清理操作。这是一个示例：

```
f = open('foo', 'r')
try:
    # 执行一些事情
    ...
finally:
    f.close()
    # 无论发生什么，都会关闭文件
```

`finally` 子句不是用于捕获错误的。相反，它用于提供无论是否发生错误都必须执行的代码。如果没有引发异常，`finally` 子句将在 `try` 块代码之后立即执行。如果发生异常，首先传递到 `finally` 子句的第一个语句。在执行此代码后，异常将重新抛出，以便由另一个异常处理器捕获。
