
除了 `ls(1)`，你可以使用 `find(1)`、`echo(1)`、`cat(1)` 等将名称列表传递给 `cpio`。你也可以将 `cpio` 输出重定向到设备而不是文件。

以下 `cpio -o` 的示例（在下面的示例中通过 `cat` 管道重定向），提取匹配模式（`memo/*`、`memo/b*`）的文件，根据需要创建当前目录下的目录（`-d` 选项），并将文件放在相应的目录中。如果输入文件是用可移植头文件创建的，请使用 `-c` 选项。如果没有找到模式，则将 `newfile` 中的所有文件放入目录中。

```
cat newfile | cpio -icd "memo/*" "memo/b*"
```

以下 `cpio -p` 的示例接收传递给它的文件名并复制或链接（`-l` 选项）这些文件到另一个目录（`newdir`）。`-d` 选项根据需要创建目录。`-m` 选项保留修改时间。

```
find . -depth -print | cpio -pdlmv newdir
```

> 注意 — 使用 `find(1)` 的 `-depth` 选项为 `cpio` 生成路径名是非常重要的。`cpio` 可能会在只读目录下创建文件。目标目录 `newdir` 必须存在。

当将 `cpio` 与 `find` 结合使用时，必须配合 `-follow` 选项使用。如果是用可移植头文件创建的文件，请使用 `-c` 选项。

## cpp — C语言

### 语法

`cpp [选项] [文件名]`

### 描述

`cpp` 是 C 语言处理器。通常作为 `cc` 的第一阶段调用。对于多卷存档，使用 `cpio` 卸载旧卷，挂载新卷。否则，通过 `find` 使用 `cpp` 可能会得到非预期的结果。

`cpp` 可选接受两个文件名作为参数：输入文件和输出文件。

### 选项

- `-B` 支持 `cpp` 注释指示。
- `-C` 打印包含的文件名。
- `-M` 生成生成文件依赖列表。
- `-R` 允许递归宏。
- `-P` 预处理时不产生输出。
- `-T` 仅对首字符进行宏处理。
- `-undef` 移除定义。
- `-Dname` 定义名称为 1。此选项与 `#define name` 相同。
- `-Dname=def` 通过 `#define` 定义名称。此选项优先级低于 `-U` 选项。
- `-Idirectory` 将目录插入到非以 `/` 开头的文件的搜索路径中。因此，双引号包含的文件首先在文件所在目录搜索，然后是 `-I` 指定的目录，最后是标准列表。对于尖括号 `<>` 包含的文件，不搜索文件所在目录。

```cpp
#if constant-expression
```

只有当 `constant-expression` 产生非零值时，才在输出中包含直到匹配的 `#else`、`#elif` 或 `#endif` 之前的后续行。所有的二元赋值 C 运算符（包括 `&&`、`|` 和 `&`）在常量表达式中都是合法的。`?: :` 运算符、定义的一元 `-`、`!` 和 `~` 运算符在常量表达式中也是合法的。

这些运算符的优先级与 C 中的相同。此外，定义的一元运算符可以以这两种形式在常量表达式中使用：`defined (name)` 或 `defined name`。这允许在 `#if` 指令中实现 `#ifdef` 和 `#ifndef` 指令的效果。仅使用这些运算符、整数常量以及 `cpp` 常量表达式所知的名称。特别是，运算符的大小（size of operator）是不可用的。

```cpp
#ifdef name
```

只有当 `name` 通过 `#define` 指令或 `-D` 选项定义，且在中间没有插入 `#undef` 指令的情况下，才在输出中包含直到匹配的 `#else`、`#elif` 或 `#endif` 之前的后续行。指令行中 `name` 之后的额外标记将被静默忽略。

```cpp
#ifndef name
```

只有当 `name` 未被定义，或者其定义已通过 `#undef` 指令被移除时，才在输出中包含直到匹配的 `#else`、`#elif` 或 `#endif` 之前的后续行。指令行 `name` 之后不允许有任何额外的标记。

```cpp
#elif constant-expression
```

在 `#if`、`#ifdef` 或 `#ifndef` 指令与匹配的 `#else` 或 `#endif` 指令之间可以出现任意数量的 `#elif` 指令。只有满足以下所有条件时，才在输出中包含 `#elif` 指令行：

- 之前的 `#if` 指令中的 `constant-expression` 求值为零，或者之前的 `#ifdef` 中的 `name` 未定义，或者之前的 `#ifndef` 指令中的 `name` 已定义。
- 所有中间 `#elif` 指令中的 `constant-expression` 求值均为零。
- 当前的 `constant-expression` 求值为非零，忽略直到匹配 `#endif` 之前的后续 `#elif` 和 `#else` 指令。在 `#elif` 指令中允许的常量表达式都是允许的。

```cpp
#else
```

否则恢复之前生效的条件指令含义。之前的条件将指示行应被包含（col），忽略 `#else` 和匹配的 `#endif` 之间的行。如果之前的条件指示这些行被忽略，则在输出中包含后续行。你可以嵌套条件指令以及相应的 `#else` 指令。

```cpp
#endif
```

结束由 `#if`、`#ifdef` 或 `#ifndef` 等条件指令之一开始的行区域。每个此类指令都必须有一个匹配的 `#endif`。

被包含的文件的标准目录在不同环境中可能不同，请使用以下形式的 `#include` 指令：
`#include <file.h>`

而不是带有绝对路径的，例如：
`#include "/usr/include/file.h"`

`cpp` 会对使用绝对路径发出警告。

## 宏

宏的正式参数在 `#define` 指令体中会被识别，即使它们出现在字符常量和双引号字符串内部。例如，以下代码的输出为：

```cpp
#define abc(a) |`a|
abc(xyz)
```

输出为：
# 1 ""

```cpp
|`xyz|
```

第二行是一个换行符。最后七个字符是 `|`xyz|`（竖线、反引号、竖线、x、y、z、竖线）。在常规扫描期间，字符常量或双引号字符串内部不会识别宏名称。
因此：

```cpp
#define abc xyz
printf("abc");
```

在第二行中不会展开 `abc`，因为位于双引号字符串内部，而该字符串不是 `#define` 宏定义的一部分。

在处理 `#define` 或 `#undef` 时，宏不会被展开。因此：

```cpp
#define abc zingo
#define xyz abc
#undef abc
xyz
```

产生 `abc`。紧接在 `#ifdef` 或 `#ifndef` 之后的标记不会展开。
在确定指向另一个宏调用的实际参数的扫描期间，宏不会被展开。因此：

```cpp
#define reverse(first, second)second
#define greeting hello
reverse(greeting,
#define greeting goodbye
)
```
