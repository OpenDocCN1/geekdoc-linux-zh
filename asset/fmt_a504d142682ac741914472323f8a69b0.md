
`rena` 将通过将文件名中首次出现的 *expression* 替换为 *replacement* 来*重命名*指定文件。

### 选项

- `-s, --symlink`

  不重命名符号链接，而是重命名其目标。

- `-v, --verbose`

  显示哪些文件被重命名（如有）。

- `-V, --version`

  显示版本信息并退出。

- `-h, --help`

  显示帮助文本并退出。

### 示例

给定文件 foo1, ..., foo9, foo10, ..., foo278，命令

```
rena foo foo0 foo? rena foo foo0 foo??
```

会将它们转换为 foo001, ..., foo009, foo010, ..., foo278。以及

```
rena .htm .ht *.htm
```

将修复你 html 文件的扩展名。

### 警告

重命名没有保护机制。如果用户有权重写文件名，该命令将在不询问的情况下执行操作。例如，当作为 root 用户在 `/lib` 目录中运行该命令时，结果可能非常严重。除非你真的知道自己在做什么，否则在运行该命令之前务必备份。

### 退出状态

- `0`

  所有请求的重命名操作都成功

- `1`

  所有重命名操作失败

- `2`

  部分重命名操作失败

- `4`

  未进行任何重命名

- `64`

  发生未预见的错误

### 参见

`util-linux(1)`

### 可用性

`rena` 命令是 `util-linux` 包的一部分，可从 Linux util-linux 项目获得。

### RENICE

### 名称

`renice` - 更改运行中进程的优先级

### 概要

```
renice [-n] priority [-g|-u] identifier...
```

### 描述

`renice` 更改一个或多个运行中进程的调度优先级。第一个参数是要使用的 `priority` 值。其他参数解释为进程 ID（默认）、进程组 ID、用户 ID 或用户名。`Renice` 一个进程组会导致该进程组中的所有进程更改其调度优先级。`Renice` 一个用户会导致该用户拥有的所有进程更改其调度优先级。

### 选项

- `-n, --priority priority`

  指定用于进程、进程组或用户的调度 `priority`。使用选项 `-n` 或 `--priority` 是可选的，但使用时必须是第一个参数。

- `-g, --pgrp`

  将后续参数解释为进程组 ID。

- `-p, --pid`

  将后续参数解释为进程 ID（默认）。

- `-u, --user`

  将后续参数解释为用户名或 UID。

- `-V, --version`

  显示版本信息并退出。

- `-h, --help`

  显示帮助文本并退出。

### 示例

以下命令会更改 PID 为 987 和 32 的进程的优先级，以及用户 daemon 和 root 拥有的所有进程的优先级：

```
renice +1 987 -u daemon root -p 32
```

### 注释

除超级用户外的用户只能更改他们拥有的进程的优先级，并且出于安全原因，只能在 0 到 19 的范围内单调增加其“nice 值”，除非设置了 nice 资源限制（Linux 2.6.12 及更高版本）。超级用户可以更改任何进程的优先级，并将优先级设置为 -20 到 19 范围内的任何值。有用的优先级包括：19（受影响的进程仅在系统中没有其他需求时才会运行）、0（“基准”调度优先级）、任何负值（使任务运行得非常快）。

### 文件

`/etc/passwd`

用于将用户名映射到用户 ID

### 另请参阅

`passwd(1)`, `useradd(8)`, `usermod(8)`

### 错误

非超级用户无法提高其自身进程的调度优先级，即使他们就是最初降低优先级的人。

Linux 内核（至少版本 2.0.0）和 Linux libc（至少版本 5.2.18）在设置 nice 值系统调用接口的具体细节上并不完全一致。这导致 `renice` 报告虚假的之前 nice 值。

### 历史

`renice` 命令出现在 4.0BSD 中。

### 可用性

`renice` 命令是 `util-linux` 包的一部分，可从 Linux 内核存档获取

### REPORT-CLI

### 名称

`report-cli` - 从命令行处理 ABRT 问题目录。

### 概要

```
report-cli [-vsp] -L[PREFIX] [PROBLEM_DIR]
report-cli [-vsp] -e EVENT PROBLEM_DIR
report-cli [-vsp] -a[y] PROBLEM_DIR
report-cli [-vsp] -c[y] PROBLEM_DIR
report-cli [-vsp] -r[y|o|d] PROBLEM_DIR
```

### 描述

`report-cli` 是一个命令行工具，用于管理由 `abrt-d` 守护进程捕获的应用程序崩溃和其他问题，或由使用 `libreport` 的其他程序创建的问题。它允许访问、操作问题数据以及报告。

### 选项

- `-L` `PREFIX`

  列出可能的事件 [以 `PREFIX` 开头的]

- `-e` `EVENT`

  在 `PROBLEM_DIR` 上运行 `EVENT`

- `-a, --analyze`

  在 `PROBLEM_DIR` 上运行 `analyze` 事件

- `-c, --collect`

  在 `PROBLEM_DIR` 上运行 `collect` 事件

- `-r, --report`

  分析、收集并报告 `PROBLEM_DIR` 中的问题数据

- `-d, --delete`

  报告后删除 `PROBLEM_DIR`

- `-y, --always`

  非交互式：不提问，假设对所有问题都回答是

- `-o, --report-only`

  配合 -r 使用：不运行分析器，只运行报告器

- `-v, --verbose`

  显示详细输出

- `-s`

  记录到 syslog

- `-p`

  在日志中添加程序名称

- `-V, --version`

  显示版本并退出

### 作者

ABRT 团队

### REPORT-GTK

### 名称

`report-gtk` - 用于分析和报告 ABRT 问题的图形界面工具

### 概要

```
report-gtk [-v|pd x] [-e EVENT] [-g GUI_FILE] PROBLEM_DIR
```

### 描述

`report-gtk` 是一个图形工具，用于报告由 `abrtd` 守护进程捕获的应用程序崩溃和其他问题，或由使用 `libreport` 的其他程序创建的问题。`report-gtk` 处理保存在指定 `PROBLEM_DIR` 中的单个问题。在专家模式下，它允许访问和操作问题数据。

### 选项

- `-d, --delete`

  报告后删除 `PROBLEM_DIR`

- `-e` `EVENT`

  仅在 `PROBLEM_DIR` 上运行指定的 `EVENTs`

- `-g` `FILE`

  替代的 GUI 文件

- `-p`

  在日志中添加程序名称

- `-v, --verbose`

  显示详细输出

- `-V, --version`

  显示版本并退出

- `-x, --expert`

  启用高级功能

### 配置

#### 对话框回答

在报告过程中，`report-gtk` 可能会显示一个要求做出决策的对话框。其中一些对话框提供了记住答案的选项。如果要求记住答案，`report-gtk` 将答案保存在 `$XDG_CONFIG_HOME/abrt/settings/report-gtk.conf` 中

如果未设置 `$XDG_CONFIG_HOME`，则改用 `$HOME/.config`。

#### 敏感数据搜索

参见 `abrt.conf(5)` 和 `libreport.conf(5)`
