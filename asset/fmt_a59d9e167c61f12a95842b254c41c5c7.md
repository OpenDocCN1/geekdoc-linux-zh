# 公钥

一种分发给任何感兴趣的接收者的共享数据，用于安全传输数据。与私钥配合使用解密数据。来自 Redhat–9–Glossary `http://www.tldp.org/LDP/Linux-Dictionary/index.html`

# 公钥加密

一种涉及两个密钥的加密方法：公钥和私钥。使用公钥加密的数据可以使用私钥解密，解密，反之亦然。通常，公钥是公开的，可以用于向私钥持有者加密数据，而私钥用于对数据签名。来自 I–loss `http://www.tldp.org/LDP/Linux-Dictionary/index.html`

# 公钥（私有、非对称加密）

公钥加密使用数学相关的密钥，其中一个密钥加密的消息可以用另一个密钥解密。这与传统加密（现在称为对称加密）不同，传统加密中密钥同时用于加密和解密。这很重要是因为其中一个密钥可以是公开的，因此被称为“公钥”。当这种技术被发现时，它解决了加密学中最大的问题。想象你的国家有间谍在境外。如果间谍被捕，对手就可以偷走密钥并解密消息。然而，使用非对称密钥，敌人只能偷到加密消息的密钥，而无法解密任何内容。此外，密钥可以是极其公开的；你只需在开放波广播你的公钥。这就是当你连接电子商务网站时使用的 `SSL` 协议发生的情况。服务器的公钥给每个连接的用户。每个用户使用公钥加密数据，这意味着没有网站所有者知道的秘密私钥，其他人无法解密。公钥加密的某些示例包括：电子邮件加密允许任何人向你发送加密消息，你可以阅读。使用（你的）私钥解密数据的最流行方法。如果你加密了一条消息，它就来自你，因为只有你知道私钥，然后你就可以对其进行数字“签名”。

为了为你恢复私钥而存在（注意：使用了冗余机制，如果密钥是 XYZ，那么 Alice 知道 XY，Bob 知道 YZ，而 Charlene 知道 XYZ，这意味着任何两人即可解锁私钥）。你在高安全安装中看到的偏执措施：对访问物理安全控制区域的员工进行背景检查，包括照片 ID、搜索和严格的进出控制；双人操作规则；生物识别（视网膜/掌纹/指纹/手写）；数字身份验证的补充；以及经常存储在独立对象上的物理密钥。最常见的是软磁盘，可以在启动时插入服务器，或者存放在保险箱中。其他还包括加密卡。（注意：当你从 CA 获得证书时，他们通常要求私钥永远不要存在计算机上）。必须使用私钥的服务器必须采取强力反措施：入侵检测系统（包括包过滤以及更复杂的系统）、频繁的漏洞评估和审计、限制能够访问服务器并充分利用服务器安全功能的人员（例如开启日志、强制强密码等）。示例：公钥算法有 `Diffie-Hellman`（原始设计，仅用于交换）、`RSA`（最流行的算法）、`ElGamal`（支持与 `RSA` 相同的功能，如加密和数字签名）。`DSA` 是基于数论和代数几何中不同的数学问题。它产生的密钥更小、运行速度更快，但没有其他系统那样经过充分分析。还有其他基于不同难解数学问题的系统。有时，“密钥”（secret-key）一词用作“公钥”的反义词，以强调它是共享秘密。此外，“对称”加密是“非对称”加密的反义词。出自 [Hacking-Lexicon](http://www.ldp.org/LDP/Linux-Dictionary/html/index.html)

# 公钥加密

由 `Diffie` 和 `Hellman` 于 1976 年引入的加密方案，每个人都获得一对密钥，称为公钥和私钥。每个人的公钥公开，而私钥保持保密。消息使用预期接收者的公钥进行加密，并只能使用其私钥进行解密。来自 [Linux Guide #FirstLinux](http://www.ldp.org/LDP/Linux-Dictionary/html/index.html)
