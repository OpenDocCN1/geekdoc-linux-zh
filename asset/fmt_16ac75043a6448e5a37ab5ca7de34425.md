# SCSI 设备

SCSI 设备使用一个独立于驱动器本身的控制器。这些控制器运行在 SCSI 卡（也称为 SCSI 适配器）上，并通过 ISA 或 PCI 插槽连接到计算机。SCSI 设备不仅限于主硬盘和从属硬盘（那是 IDE 设备）。SCSI 设备仅受限于 SCSI 卡支持的设备数量。典型的显卡可以支持 7 到 30 个设备；然而，据报道，更高质量的卡可以支持超过 100 个设备。

# 性能因素

性能因素区分了 IDE 和 SCSI 设备的质量。典型的 SCSI 设备数据传输速度范围在 10Mbps 到 160Mbps 之间，而典型的 IDE 设备速度范围在 8Mbps 到 100Mbps 之间。两个系统的速率都取决于设备和控制器卡。

# 磁盘分区

理解 Linux 的另一个必经之路是理解硬盘分区。分区（我们在第 2 章中简要介绍过的内容）是一种用于将单个物理磁盘分割成多个逻辑设备的机制。这些逻辑磁盘显示为物理块的连续区域。

整个硬盘不必完全分区。你可以保留剩余空间以备日后分配，或将其用作间隙以允许调整分区大小。

> **注意：** 移动和调整分区大小非常复杂，并且很容易损坏你的文件系统。在更改分区表之前，请务必备份你的数据。

硬盘上创建的分区数量通常取决于特定机器的需求。建议为不同的操作系统使用单独的分区，在 Linux 中，为交换空间（`swap space`）单独分区。然而，对于大磁盘安装或活跃的工作站，通常建议分配单独的分区（甚至是独立的硬盘）来挂载单独的文件系统，例如 `/home`、`/var`、`/var/log` 和 `/` (root)。

# 打印系统

红帽使用了最初为 BSD（伯克利系统发行版）Unix 开发的打印缓存系统。Linux 可以在多个站点维护多个打印机以及多个打印队列。一些基本的打印命令包括 `lpr`、`lpq`、`lprm`、`lpd` 和 `lpc`，如表 4.2 所示。

## 表 4.2 基本打印命令

| 命令 | 描述 |
| :--- | :--- |
| `lpr` | 将作业添加到打印队列 |
| `lpq` | 列出打印队列中当前的作业 |
| `lprm` | 从打印队列中删除作业 |
| `lpd` | 打印守护进程，负责将数据从缓存发送到打印机 |
| `lpc` | 打印的管理接口 |

要通过直接并行连接将打印机添加到你的系统，首先确保打印机在物理上连接正确。确保 `lpd` 服务器在启动时运行（通过运行 `nsys` 检查）。编辑 `/etc/printcap`，并为新打印机添加条目。在 `mkdir /var/spool/newps` 中创建你的缓存目录。确保你的缓存权限设置为 `755`（我们将在本章的稍后部分详细介绍权限）。使用 `touch` 命令创建打印机的计费文件。然后你可以使用 `lpc` 命令在其队列中启动打印机，如下所示：

```bash
# touch /var/adm/lp_acct/ps3
# chown daemon /var/adm/lp_acct/ps3
# chmod 755 /var/adm/lp_acct/ps3
# lpc up ps3
```

Linux 上的缓存系统也可以打印到远程打印机。要添加远程打印机，只需编辑 `/etc/printcap`，添加类似下方的行：

```bash
# remote printer setup
remp|rp=remote on remote line:\
:lp=-:rm=remote:lp2=sd=/var/spool/remp
```

> **注意：** 上述 `/etc/printcap` 条目没有关于打印机本身细节的引用。这是因为主机将在作业发送后进行管理。

此条目设置了名为 `remp` 的远程打印机。未指定 `lp=` 字段告诉我们该条目是用于远程打印机的。`rm=` 字段指向目标系统（在此处，我们将其命名为 "remote"）。`rp=` 字段持有目标打印机的名称。`sd=` 字段选择打印机将使用的缓存目录。

# 使用 TCP/IP 网络

没有网络的 Linux 机器就像没有手的打字员。因此，希望获得 RHCE 证书的 Linux 管理员必须良好地理解网络概念，如传输控制协议/网际协议 (`TCP/IP`)、网络端口和网络服务。

## TCP/IP 基础

当今网络中使用的最重要的网络协议是 `TCP/IP`。它是用于建立互联网以及世界上大多数广域网的基础协议集。网络是 Linux 的明星功能之一，使其在业务网络、互联网服务提供商 (`ISP`)、制造设施和网络公司中日益受欢迎。

## TCP/IP 和开放系统互连 (OSI) 模型

计算机与计算机通信的 `TCP/IP` 体系模型基于开放系统互连 (`OSI`) 模型。`OSI` 模型由七层组成，而 `TCP/IP` 模型只有四层。以下是 `OSI` 模型层的列表：

- 应用层
- 表示层
- 会话层
- 传输层
- 网络层
- 数据链路层
- 物理层

将它们与 `TCP/IP` 模型的层进行比较：

- **应用层**——处理 `TCP/IP` 网络守护进程和应用程序。这一层执行 `OSI` 模型表示层、会话层、应用层的工作。
- **传输层**——处理所有数据路由和交付问题。这一层涵盖了 `OSI` 传输层。
- **网络层**——处理所有地址、传输和 `IP` 数据包。这一层涵盖了 `OSI` 模型的网络层。
- **网络访问层**——指定了在网络上传输数据的程序，包括如何访问物理介质。也称为网络接口层（用于许多协议，包括以太网和 `FDDI`）。

## TCP 和用户数据报协议 (UDP) 协议

`TCP` 并不是 `TCP/IP` 中使用的唯一协议。某些应用程序，如网络文件系统 (`NFS`)，使用兄弟协议 `UDP`（用户数据报协议）。两种协议都允许应用程序访问特定端口上的服务。然而，`UDP` 不建立连接；而是发送单个数据包。

## 互联网控制消息协议 (ICMP) 数据包类型

内核代码使用互联网控制消息协议 (`ICMP`) 向其他主机发送错误消息。有多种 `ICMP` 数据包类型，一些有效类型包括：回显回复、目的不可达、源查询（已弃用，但 `NT` 出某些原因仍发送它们）、重定向、回显请求、路由器通告、路由器请求、超时、参数问题、时间戳请求、时间戳回复、子网掩码请求和子网掩码回复。

目的不可达数据包可以携带 14 种消息。这些包括：网络不可达、主机不可达、协议不可达、端口不可达、分片需要、源路由失败、网络未知、主机未知、网络禁止、主机禁止、`TOS` 网络不可达、主机不可达、通信禁止和主机优先级截断。

重定向数据包可以携带 4 种消息：网络重定向、主机重定向、`TOS` 网络重定向和主机重定向。

超时数据包（也称为 `TTL` 超时）可以携带 2 种消息：传输期间 `TTL` 零和重组期间 `TTL` 零。

参数问题数据包可以携带以下两种消息之一：`IP` 头部错误和需要选项误用。

## 理解端口

每个网络服务都分配（或绑定）到一个端口。端口是 `TCP` 和 `UDP` 对服务端点的抽象。共有 64K（或 65,536）个可用端口。所有 1,024 以下的端口（低号端口）被认为是特权端口。这意味着只有 `root` 用户可以绑定到它们。然而，1,024 及以上是非特权端口，意味着任何用户都可以绑定到它们。

## 地址

`TCP/IP` 网络中最重要的概念是 `IP` 地址。`IP` 地址是分配给网络上每台机器的数字标识符。`IP` 地址是软件地址，而不是硬件地址（硬件地址硬编码在网络接口卡中）。

### 数字

`IP` 地址由 32 位组成。这些位被分为四个 8 位的字节（每个字节包含 8 位信息，并指定网络或节点）。子网上的每台机器都具有相同的网络地址。你可以通过三种方式显示 `IP` 地址。第一种也是最常见的是点分十进制表示法，例如 `192.168.1.1`。第二种方法是使用二进制系统。如果将 `192.168.1.1` 转换为二进制，它是 `11000000.10101000.00000001.00000001`。第三种方法是十六进制。如果你将 `192.168.1.1` 记为十六进制，它是 `C0.A8.01.01`。

> **注意：** 在本节——以及整书中——`IP` 地址均使用点分十进制格式编写。

### 类

`IP` 网络有三类：A、B 和 C 类。根据网络的大小使用不同的类。A 类网络用于具有大量节点的小数量网络集合。B 类网络在许多 C 类网络难以管理的网络中很少使用。A 类网络使用 `Net.Node.Node` 地址格式，允许你拥有多达 127 个网络，每个网络 16,777,216 个节点。A 类 `IP` 地址范围从 `0.0.0.0` 到 `127.255.255.255`。

> **注意：** A 类网络不再分配，因为已经没有可用的了。事实上，某些 A 类网络已经拆分成更小的网络。

B 类网络使用 `Net.Net.Node.Node` 地址格式。这允许你拥有多达 16,384 个网络，每个网络 65,536 个节点。B 类 `IP` 地址范围从 `128.0.0.0` 到 `191.255.255.255`。被分配 B 类网络意味着你拥有 `Net.Net` 分配下的所有地址。例如，拥有 `130.1.0.0` B 类网络的公司拥有从 `130.1.0.0` 到 `130.1.255.255` 的每一个 `IP` 地址。

C 类网络是今天最常用的类。它们允许你拥有多达 2,097,152 个网络，但你被限于每个网络只有 254 个节点。C 类 `IP` 地址范围从 `192.0.0.0` 到 `223.255.255.255`。分配 C 类网络意味着你拥有 `Net.Net.Node` 分配下的所有地址。例如，拥有 `200.0.2.0` C 类网络的管理员或公司拥有从 `200.0.2.0` 到 `200.0.2.255` 的每一个 `IP` 地址。

你可能好奇 `223.255.255.255` 以上的地址发生了什么。还有其他类网络：D 类和 E 类。D 类用于组播数据包。这些数据包包括从 `224.0.0.0` 到 `239.255.255.255` 的地址。组播传输当主机想要向其网络上的多个目标广播时使用。E 类地址范围是 `240.0.0.0` 到 `255.255.255.255`。这些数字被留供未来使用。由一个名为网络信息中心（`NIC`）的官方组织控制，称为 `InterNIC`。其网站位于 `http://www.internic.net`。

互联网地址分配机构（`IANA`）为私有网络保留了以下地址块：

- `10.0.0.0` 到 `10.255.255.255`
- `172.16.0.0` 到 `172.31.255.255`
- `192.168.0.0` 到 `192.168.255.255`

这些地址可以在任何私有网络中使用。然而，这些地址不是公共路由的。

> **注意：** 无类域间路由（`CIDR`，在下一节讨论）主要让 A、B、C 类变得无关。无论如何，该术语仍然被广泛使用。

### 子网划分

1993 年，提出了一种对 `IP` 数字的新适配。否则，分类系统是浪费的（例如，一个 B 类地址可能只需要两个 C 类网络）。因此，无类域间路由（`CIDR`）被发明将 `IP` 地址划分为部分：网络和主机。使用子网划分，可以为未来几年指定足够的 `IP` 地址。

## 网络配置

`ifconfig` 命令用于在启动时配置接口。第一个需要设置的接口是回环接口（`lo`）：

## 表 4.4 子网划分示例

| 子网/结果 | 描述 |
| :--- | :--- |
| `192.168.220.0` | C 类子网地址 |
| `192.168.221.0` | C 类子网地址 |
| `192.168.220.0` | 子网划分的地址 |
| `255.255.252.0` | 子网掩码 |
| `192.168.220.255` | 广播地址 |

查看接口的配置，运行 `ifconfig lo`：

```bash
$ ifconfig lo
lo encap:Loopback
       inet:127.0.0.1 Mask:255.0.0.0
       UP LOOPBACK RUNNING MTU:1684 Metric:1
       RX packets:677 errors:0 overflows:0
       TX packets:677 errors:0 carrier:0
       collisions:0 txqueue:0
```

回环接口被分配了 `255.0.0.0` 的掩码，因为 `127.0.0.1` 是 A 类地址。第二个需要设置的接口是以太网接口。与回环接口一样，你使用 `ifconfig` 以相同的方式设置它：

```bash
$ ifconfig eth0 207.239.117.252 netmask 255.255.255.0

$ ifconfig eth0
eth0 encap:Ethernet HWaddr 00:10:48:63:05:94
       inet addr:192.168.117.252 Bcast:192.168.117.255
       Mask:255.255.255.0
       UP BROADCAST MULTICAST MTU:1500 Metric:1
       RX packets:623 errors:1 dropped:0 overflows:0 frame:1
       TX packets:649 errors:0 dropped:0 overflows:0 carrier:1
       Collisions:253
       Interrupt:17 Base address:0x6100
```

对于 `eth0` 接口，广播地址会自动设置，在本例中为 `207.239.117.255`。内核为此接口生成的以太网帧的最大大小（传输单元）已设置为 1,500。
