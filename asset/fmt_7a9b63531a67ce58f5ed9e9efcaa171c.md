
此示例在大写或小字母前使用插入符号（`^`）来指定控制键组合。因此，`erase ^H` 指定 `Ctl-h` 组合作为备选。`erase` —— 如果你想指定退格键（Backspace）生成的实际字符作为删除字符的值——只要你能弄清楚它是如何。插入符号的存在强制使用引号。插入符号在 shell 中是特殊的；缺少引号会导致对 `stty` 命令的解释不当。（关于 `stty` 命令的详情，请参阅你的 UNIX 参考手册。）

## 使用 ulimit 控制资源

使用 `ulimit` 控制资源是一个实用的功能，特别是当你是系统管理员时。与 UNIX 自带的 ulimit 不同，Korn 提供了了自己的替代方案。`ulimit` 的语法如下：

```
ulimit [-HSacdnfvst] [limit]
```

`H` 和 `S` 标志表示你正在定义硬限制（hard）或软限制（soft）。硬限制设置后无法增加。软限制可以修改为硬限制的值。如果同时省略 `H` 和 `S`，则指定的限制同时应用于硬限制和软限制。

如果省略 `ulimit`，则显示指定限制的当前值。如果不带选项调用 `ulimit`，它将返回进程可以写入的块数（与输入 `ulimit -f` ）。表 11.16 列出了 `ulimit` 参数。

### 表 11.16. ulimit 参数。

| 参数 | 功能 |
| :--- | :--- |
| `-a` | 列出所有资源限制 |
| `-c` | 指定核心文件（core file）的块数 |
| `-d` | 指定数据区域的千字节数 |
| `-f` | 指定允许写入文件的块数 |
| `-n` | 指定允许同时打开的文件数加一 |
| `-s` | 指定栈区域的千字节数 |
| `-t` | 指定每个进程可以使用的秒数 |
| `-v` | 指定虚拟内存的千字节数 |

> 提示：除非你打算进行大量的编程，否则在你的 `profile` 中放置 `ulimit -c 0` 是很有用的。这可以防止任何程序创建核心文件，从而节省磁盘空间。许多核心文件可能达到兆字节大小，因此减少它们的产生通常是一个广受欢迎的方法！

## 设置环境变量

至少，你可能希望确保通过 UNIX 的 `PATH` 和 `MAIL` 值设置了许多变量。如果你使用 Bourne shell 语法，你的变量设置看起来如下：

```
PATH=/bin:/usr/ucb:/usr/local/bin:$HOME/bin:
MAIL=/var/spool/mail/$LOGNAME
MAILCHECK=60
FCEDIT=/usr/bin/vi
VISUAL=/usr/bin/vi
export PATH MAIL MAILCHECK FCEDIT VISUAL
```

或者，你可以使用 Korn shell 别名来避免在每个设置的变量中都添加 `export`。如果你不导出它，直接设置变量也是好的。使用 `export` 别名，前面的代码可能像这样：

```
export PATH=/bin:/usr/ucb:/usr/local/bin:$HOME/bin:
export MAIL=/var/spool/mail/$LOGNAME
export MAILCHECK=60
export FCEDIT=/usr/bin/vi
export VISUAL=/usr/bin/vi
```

当你编写环境变量设置时，请记住有些变量是由 UNIX 登录过程设置的。你的系统管理员可能会提供一个登录脚本在你的 `.profile` 脚本运行之前设置值。当你的脚本启动时，`PATH` 和 `MAIL` 变量通常已经有了初始值。覆盖默认的 `PATH` 通常是一个好主意；从它的值开始，对路径搜索拥有完全控制。覆盖默认的 `MAIL` 或 `MAILPATH` 有风险，除非你知道正在使用哪些子系统。

## 设置 shell 控制的局部变量

局部变量是 shell 使用但不导出的变量。它们包括 `FCEDIT`（指定编辑器）和 `PS1`（你的主提示符字符串）。你可能想定义一些经常访问的目录。

## 定义别名（Aliases）

定义你喜欢的别名。你必须发明自己的别名；每个用户往往有不同的set。你甚至可以重新定义 `ls` 的默认行为。以下是我喜欢的的一些：

```
alias lx='/usr/bin/ls -FC'
alias ls='/usr/bin/ls -l'
alias pg='/usr/bin/pg -c%d'
alias mail='/usr/bin/mailx'
alias -t vi
```

注意，在大多数情况下，我打算在别名中使用完整路径。这消除了目录搜索。

## 定义函数

定义任何你喜欢的函数，包括自动加载函数。我使用一些函数作为快捷键，因为函数可以做别名做不到的事。你可能想使用本章前面的 `go` 函数，例如用于切换目录。

## 设置 shell 选项

如果你发现自己在命令行上设置相同的 shell 选项，可以将它们放在 `.profile` 中。要设置可选的 shell 选项，使用 `set` 命令。如果你喜欢使用 vi 模式处理命令历史和编辑，并且想要完整的作业支持，你可以在 `.profile` 中添加这两行：

```
set -o vi
set -o monitor
```

## 每次登录时执行命令

执行你每次登录时都想运行的命令。你可能想运行 `who` 命令来查找当前登录的用户，例如。同样，`df`（在 UNIX 系统上不存在）显示已挂载磁盘的可用空间。

## 修改后执行你的 .profile

每当你更改 `.profile` 脚本时，都应该在注销之前执行它。如果你在脚本中编写了错误，可能会难以重新登录。要测试你的 `.profile` 脚本，可以使用 (点) 来运行它：

```
$ . ./profile
```

确保在第一个点后面留有一个空格：它是命令名，而 `.profile` 是命令参数。（尽管 `.profile` 本身足够，但如果你的当前目录不在搜索路径中，你可能需要使用 `./profile`。）点命令不仅执行脚本，还能使任何环境更改生效在脚本终止后。

或者，你可以使用 `ksh -v` 运行脚本，让 shell 执行脚本并在执行时打印每个语句：

```
$ ksh -v ./.profile
```

使用 `-n` 选项会让 Korn shell 读取你的 `.profile` 并检查语法错误，但不会执行其中包含的命令。

## 创建 ENV 文件

在通过 `.profile` 设置好你想要的方式后，就可以开始处理环境文件了。环境文件是任何包含通过将你的路径赋值给 `ENV` 变量而你设计的 shell 脚本的文件。当你启动一个新的 shell 实例并执行命令时，shell 会执行 `ENV`。如果你曾经从 `pg` 或 `vi` 等命令退出 shell，请注意，当你调用 shell 时，某些环境设置（如别名 aliases）不会从你的登录 shell 继承。通过将别名、函数定义和 ENV 全局变量放在配置文件中，并在 `.profile` 脚本中将 `ENV` 设置为你的路径，你可以确保始终拥有一致的 Korn shell 环境。

不要过头。在某些情况下，`ENV` 路径指定的文件会在你调用的 shell 命令之前执行。由于许多 UNIX 命令是作为 shell 脚本实现的，这意味着一个巨大的环境文件可能会在意想不到的地方增加意外的开销。

> 注意：原则上，环境文件仅作为调用 shell 脚本的初步步骤执行，且仅当该 shell 脚本需要一个新的 Korn shell 实例时。当你通过名称调用 shell 时，通常并非如此。

要使用环境文件，请创建一个包含你偏好的别名、函数和导出变量设置的文件。然后向你的 `.profile` 中添加 `export ENV=pathname` 语句，其中 `pathname` 是你环境文件的完整路径。环境设置将在下次登录时生效。如果你用命令测试了 `.profile`，则它将立即生效。

- `-profile`

你想放入 `ENV` 文件中的命令包括别名定义和 shell 选项。你可能更倾向于将它们放在这里而不是 `.profile` 中，以确保每次获取的 shell 看起来和运行方式一样。

> 提示：放在 ENV 文件中一个非常有用的方法如下：

```bash
if [[ -o interactive ]]
then
  ...
  在此处插入你的 ENV 行。
  ...
fi
```

放在 `if` 语句内部的任何行只有在 shell 为交互式时才会执行——也就是说它会提供一个供你输入命令的提示符。如果 shell 是带有将运行命令的命令行调用的，这可以减少多次处理新 shell 的开销——例如：

```
ksh -c ls -l
```

如果你有很多别名和/或函数，将它们放在一个单独的文件并通过 `ENV` 调用该文件来设置它们可能是一个好主意。在我的 `ENV` 文件中有这两行：

- `.ksh_alias`

- `.ksh_funcs`

在 `.ksh_alias` 中，我包含了所有的别名定义；在 `.ksh_funcs` 中，我包含了所有的函数定义。这大大缩短了我的 `ENV` 文件，并让一切看起来更整洁。

## 为其他程序向 .profile 添加设置

自定义环境不仅限于通过登录配置文件和环境文件来建立你想要的 shell 选项和设置；放置其他程序使用的设置也很有用。自定义 vi 编辑环境的一种方法是定义一个变量 `EXINIT`，该变量包含你每次启动 vi 时都会运行的命令。你可以将 `EXINIT` 变量放置在登录配置文件中以建立你偏好的设置。UNIX 命令响应环境变量，这允许你在登录配置文件中自定义这些命令。

## 控制作业

“作业”（job）的概念对于 UNIX 用户来说可能有些陌生，因为在 UNIX 中大部分操作都是交互式的。尽管如此，Bourne shell 提供了运行后台作业的基本工具，而 UNIX 操作系统一直提供此类工具。UNIX 的最新版本增强了后台作业管理。

后台作业的基本原理非常简单。它是一个不需要手动交互即可运行并能与其他进程运行的程序。在 Bourne shell 中，你使用 `&` 操作符启动后台作业。例如，命令 `cc myprog.c &` 会编译源程序 `myprog.c` 而不阻塞你的终端。你可以继续工作——甚至是使用全屏编辑器进行编辑——此时 `cc` 命令在后台运行。

最近 UNIX 对 `stty` 命令和终端驱动程序的改进为你的终端增加了一个新的控制键：挂起（Suspension）通常是 Ctrl+Z。这个新工具允许你将当前运行的交互程序（例如 vi 编辑会话）临时放入后台。如果程序想要与你的终端通信，系统会挂起该程序。否则，它将继续运行。

Korn shell 添加了一些工具帮助你管理积累的许多进程。这些工具由 `kill`、`wait`、`bg` 和 `fg` 命令组成。

要使用 Korn 的作业控制，你必须启用 `monitor` 选项。通常情况下，monitor 选项为你启用；它是交互式 shell 的默认设置。如果你的操作系统不支持作业管理，则 `monitor` 选项默认关闭。即使没有操作系统——挂起和 `stty` 功能是操作系统服务，而不是 Korn shell 服务——你可以使用 Korn 的一些作业控制工具，但你必须手动设置 `monitor` 选项。你可以通过命令 `set -o monitor` 来。

`jobs` 命令不接受参数，只需列出你当前活跃的所有作业。`jobs` 的输出如下：

```
$ jobs xlogo&
[1] + Running xclock -bg LightGreen&
[2] + Running vi myprog
```

你可以使用以下任意命令来取消 xclock 窗口（一个后台作业）：

```
$ kill %4
```

或

```
$ kill %xclock
```

## 挂起 Shell 直到作业完成

使用 `wait` 来挂起 Shell 直到指定的作业（如果有）完成。`wait` 的可见效果仅仅是挂起 shell，而不是向你颁发另一个提示符。如果你决定不等待，只需按回车键（Enter）。这会导致 shell 发出提示符并终止 `wait` 命令。`wait` 命令的语法如下：

```
wait [ job ... ]
```

对于 `job`，指定一个或多个进程 ID（Process ID）或作业引用，以指定你想要等待的作业。如果你没有指定任何作业，shell 将等待直到任何作业完成。如果你指定了两个或多个作业，shell 将等待直到所有指定的作业完成。

你不会经常使用 `wait` 命令，但当你完成交互式工作并在并在一个或多个后台作业的结果之前继续操作时，它是方便的。如果没有 `wait` 命令，你必须反复执行 `jobs` 命令，直到作业被标记为 Done（完成）。

`wait` 命令有用的一种情况是在开发格式化文件时。你可能想将 `nroff` 或 `trop` 作为后台作业，并将输出捕到磁盘文件中进行审查。在 `nroff` 或 `trop` 作业运行时，你可以编辑其他文本文件。当你没有其他编辑任务要做时，你需要运行 `nroff` 或 `trop` 以完成，因为除了审查之前的工作外你别无可做。一个假设的控制会话可能如列表 11.5 所示。

### 列表 11.5. 控制会话。

```
$ vi chap.nr
$ nroff -me chap1.nr >chap1.nrf &
[4] Running nroff -me chap1.nr
$ vi chap2.nr
$ nroff -me chap2.nr > chap2.nrf &
[5] Running nroff -me chap2.nr
$ jobs
[4] Running nroff -me chap1.nr
[5] Running nroff -me chap2.nr
$ wait
```

在这个列表中，你重叠了对 chap2.nr 的编辑。在完成 chap2.nr 的编辑后，你会看到两个 nroff 作业仍在运行。因为你没有更多编辑任务需要执行，你可以使用 `wait` 命令等待直到两个后台作业之一完成。在两个作业中的一个完成之前，shell 不会颁发另一个提示符。然后你将收到一条 Done 消息：

```
$ wait
[5] Done nroff -me chap2.nr
$
```

`wait` 的另一个有用应用是管理 X 会话。当你登录并使用 X 时，会处理两个文件之一：`xinitrc` 或 `.session`。处理哪个文件取决于你运行 X 的方法。当我连接时，`.session` 文件会被处理。当 `.session` 终止时，我的 X 会话结束，我被注销了。我的 `.session` 文件提取如下：

```
ctwm &
WINM-!
xv -root etc/pics/space.gif &
xterm -sb 2000 -ls "Xterm 1" -geometry 80x24+08 &
xterm -sb 2000 -ls "Xterm 2" -geometry 80x24+523 &
wait WINM
```

这段代码使用了 Korn shell 的特性。首先，我通过 `$` 获取窗口管理器 `ctwm` 的进程 ID，将其赋值给变量 `WINM`。我启动了两个 xterm 和使用 `xv` 启动桌面背景。然后我启动了一个 `wait` 命令，等待进程 `WINM` 完成。在这种情况下，`WINM` 是管理器的进程 ID，换句话说，我的窗口管理器关闭，`.session` 终止，我被注销。

## 将作业移到前台

使用 `fg` 将后台作业移到前台。前台执行意味着与终端进行交互式处理。因此，使用 `fg` 将多个作业带入前台会导致竞态条件；第一个获取终端的作业胜出，其他作业回到后台的 Stopped（停止）状态。`fg` 的语法如下：

```
fg [ job .. ]
```

对于 `job`，指定一个或多个进程 ID 或作业引用。如果省略 `job`，则当前进程将被带入前台。当前作业是最近停止或启动的那个。

使用 `fg` 命令的需求通常由于你所采取的操作引起的。假设你正在用 `vi` 编辑一个文本文件，当尝试保存文件时，你发现你对该文件没有写权限。在纠正它之前你无法保存文件，但你现在处于编辑器内部。你该怎么办？

首先，按下 Ctrl+Z 停止 `vi` 编辑器。你会立即得到以下控制台输出：

```
[1] Stopped          vi chap2.nr
$
```

现在，确定问题的原因并纠正它。为了简洁起见，假设问题不存在，是你设置了写保护：

```
$ ls -l chap2.nr
-r--r--r--      1 barbara      21506 May 5 10:52
$ chmod u+w chap2.nr
$ ls -l chap2.nr
-rw-r--r--      1 barbara      21506 May 5 10:52
```

最后，使用 `fg` 命令将当前在后台停止的 `vi` 编辑会话带回执行：

```
$ fg vi
```

你可能需要输入 Ctrl+L（vi 编辑器命令）来重绘屏幕。

## 将作业移到后台

使用 `bg` 命令将处于 Stopped（停止）状态的作业置于后台并恢复执行。注意，如果作业需要输入，它会立即回到 Stopped 状态。`bg` 的语法如下：

```
bg [ job ... ]
```

对于 `job`，指定一个或多个进程 ID 或作业引用。作业引用以 `%` 开头。如果省略 `job`，命令指向最近启动或停止的作业。在实践中，你不会使用 `bg` 命令将前台作业移到后台，因为没有方法这样做；shell 在前台作业运行时不会监听你的终端。为了在前台作业运行时获得 shell 的注意，你需要使用 Ctrl+Z 停止（挂起）前台作业。
