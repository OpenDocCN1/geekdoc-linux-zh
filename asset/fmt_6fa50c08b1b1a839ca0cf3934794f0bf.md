## 大教堂？何其荒诞？

Linux 能够在众多国家中占据一席之地，主要因为它具备了与任何事物建立连接并与之交互的能力。

这正是开源软件（OSS）蓬勃发展的原因。它可以被任何人用来与任何其他事物连接。这种现象得益于开放性：开放标准、开放协议、开放文件格式、一切开放。在开源世界中，没有什么是隐藏的。这种开放性使得软件开发者能够看到前人是如何操作的。如果他们喜欢前人的做法并可以使用，那太棒了。他们发现了一个实用的工具，并为自己节省了时间。如果没有，他们至少可以自由查看过去的错误并对其进行改进。

与此同时，那些在“大教堂”（cathedrals）开发“优越”软件的软件开发者，最终会发现自己的市场被开源开发者的作品所取代。为什么呢？因为“大教堂式”开发者只为那些住在同一座大教堂里的人开发程序。无论这大教堂是一家公司还是一个国家，软件早晚必须与大教堂之外的软件对接接口，否则它注定灭亡。

Unix 哲学的追随者，尤其是今天的 Linux 开发者，对此深有体会。例如，拥有与 Windows 系统混合环境的 Linux 系统运行着 Samba，这是一个与 Windows 兼容的文件共享应用程序，它兼容 Windows SMB 网络。讽刺的是，根据一项基准测试，Linux 的性能实际上优于运行了微软自有 SMB 网络的 Windows 2000。

大多数 Linux 发行版都具备访问其他磁盘分区上 Windows 文件系统的能力。Windows 能进行反向操作吗？Windows 能访问其他分区上的 Linux 系统吗？不能。Windows 是一个闭源的专有系统，就像常年头埋在沙子里的鸵一样，想要假装其他文件系统不存在。

到这里，你可能已经意识到开源软件与遵循 Unix 哲学的软件之间的某些相似之处。就其本身而言，与大型“工业级”（正如某些人认为的）闭源专有软件应用相比，许多项目就像小鱼小。毕竟，这些作品通常由个人完成，至少在早期阶段是如此。因此，这些早期的努力通常是小型项目，缺乏营销式的华丽，但内容充实。不过没关系。记住，在 Unix 世界里，小即是美。

埃里克·雷蒙德（Eric Raymond）将这些作品称为“满足程序员个人瘙痒”的软件。许多开源开发者的共同目标似乎他们只想把东西写出来。因为日常工作的压力，他们往往背水一战，没有太多时间进行修饰。因此，他们通常会跳过市场追逐的大多数华丽装饰，转而把一件事做实，即生产一个精简、高效且能解决个人需求的应用程序。在成功的案例中，这些骨干级的解决方案点燃了他人想象的火花。热门应用就是这样产生的。

一旦火被点燃，开源开发社区的其他成员就会开始为该程序做出贡献。起初，程序将吸引一小群但忠诚的追随者。然后，软件将拥有自己的生命，并超出其最初的意图。几十个程序员将第一个系统演变成一个更大、更全面的系统。在写本文时，Linux 本身正处于第二个系统阶段。大家都度过了快乐时光。

显然，如果有人想击败将单个人项目变为软件现象的市场，就必须尽快构建原型。仅仅谈论一个伟大的软件构思是不够的。在开源世界中，获得最多尊重的人是那些编写了初始版本的人，或在后期贡献了重大内容的人⁴。

为了让开源项目吸引尽可能多的用户，它必须在尽可能多的平台上可用。因此优秀的开源开发者选择可移植性而非效率。一个利用特定硬件的程序，其效率可能更高，但可移植性差。

提高开源软件（OSS）项目成功率的一种方法是使用脚本来增加杠杆作用和可移植性。虽然世界上有很多许多高练的底层编码人员，但越来越多的人既没有时间，也没有胆量在最底层进行工作。通过为一门或两种流行的脚本语言提供接口，可以显著增强任何软件的实用性。

如果这些接口获得了足够的普及率，开源社区内部将会形成一个庞大的子社区。这些子社区热衷于致力于实验和扩展此类接口。他们会举办用户组会议和会议，在在线邮件列表中发布帖子，并通常成为围绕某个流行接口的大部分活动的焦点。
