
进入`/tmp`目录并在用户家目录下创建临时文件目录可能是明智的，可以使用如下所示的代码行：

```bash
[[ -d $HOME/tmp ]] || mkdir $HOME/tmp
```

# 使用 wait 进行异步执行

有时，同时执行多个任务是很有必要的。我们已经看到，所有现代操作系统至少支持多任务，有些还支持多用户。脚本也可以构造为以多任务的方式运行。

通常，这涉及到启动一个脚本，该脚本反过来启动一个或多个子脚本来执行额外任务，而父脚本继续运行。然而，当一系列脚本以这种方式运行时，在保持父子脚本协调方面可能会出现问题。也就是说，如果父脚本或子脚本依赖于另一个，并且一个脚本必须等待另一个脚本完成任务才能结束自己的任务，该怎么办？

`bash` 有一个内置命令来帮助管理异步执行，例如 `wait`。该命令会导致父脚本暂停，直到指定的进程（即子脚本）完成。为了演示这一点，我们需要两个脚本。第一个是父脚本。

```bash
#!/bin/bash
```

```bash
# async-child: 异步执行演示（父脚本）
echo "Parent: starting..."
echo "Parent: launching child script..."
async-child &
pid=$$
echo "Parent: child (PID=$pid) launched."
echo "Parent: continuing..."
sleep 2
echo "Parent: pausing to wait for child to finish..."
wait "$pid"
echo "Parent: child is finished. Continuing..."
echo "Parent: parent is done. Exiting."
```

```bash
#!/bin/bash
```

```bash
# async-child: 异步执行演示（子脚本）
echo "Child: child is running..."
sleep 5
echo "Child: child is done. Exiting."
```

在这个示例中，我们看到子脚本非常简单。实际的操作是由父脚本执行的。在父脚本中，子脚本被启动并放入后台。通过将 `$` shell 参数的值赋值给变量 `pid` 来记录子脚本的进程 ID，该参数始终包含上一个放入后台的任务的进程 ID。

父脚本继续执行并运行带有子进程 PID 的 `wait` 命令。这会导致父脚本暂停，直到子进程退出，此时父脚本结束。

当执行时，父脚本和子脚本会产生以下输出：

```
[me@linuxbox ~$ async-parent
Parent: starting...
Parent: launching child script...
Parent: child (PID= 6741) launched.
Parent: continuing...
Child: child is running...
Parent: pausing to wait for child to finish...
Child: child is done. Exiting.
Parent: child is finished. Continuing...
Parent: parent is done. Exiting.
```

# 命名管道 (Named Pipes)

在大多数 Unix 类系统中，可以创建一种特殊类型的文件称为命名管道。命名管道用于在两个进程之间建立连接，并可以像其他类型的文件一样使用。它们并不流行，但了解它们是有好处的。

有一种常见的编程架构称为客户端-服务器（client-server），它可以利用命名管道等通信方法，以及其他类型的进程间通信（如网络连接）。

广泛使用的客户端-服务器系统无疑是：浏览器作为客户端与 Web 服务器通信，向服务器发送请求，服务器向浏览器返回网页作为作为响应。

命名管道的行为像文件，但实际上形成了先入先出（FIFO）缓冲区。与普通（无名）管道一样，数据从一端进入并从另一端输出。使用命名管道，可以设置如下内容：

```
process1 > named_pipe
```

以及：

```
process2 < named_pipe
```

它的行为将如下：

```
process1 | process2
```

## 设置命名管道

首先，我们必须创建一个命名管道。这是通过 `mkfifo` 命令完成的。

```
me@linux ~]$ mkfifo pipe1
me@linux ~]$ ls -1 pipe1
prw-r-x-- 1 me  0 2018-07-17 06:41 pipe1
```

在这里我们使用 `mkfifo` 创建了一个名为 `pipe1` 的命名管道。使用 `ls` 查看文件，发现属性字段中的第一个字母是 `p`，表示这是一个命名管道。

## 使用命名管道

为了演示命名管道如何工作，我们需要两个终端窗口（或者两个虚拟控制台）。在第一个终端中，我们输入一个命令并将其输出重定向到命名管道。

```
me@linux ~]$ ls -1 > pipe1
```

按下回车键后，命令似乎挂起了。这是因为还没有东西从管道的另一端接收数据。当这种情况发生时，被称为管道被阻塞（blocked）。一旦我们在另一端附加一个进程并让它开始从管道读取输入，该条件就会消除。使用第二个终端窗口，我们输入此命令：

```
me@linux ~]$ cat < pipe1
```
