
# 控制 bash 特性和选项

## 特性、选项、变量？

为了避免术语混淆，本书将你可以控制的各种 shell 行为称为特性。bash 手册页将其称为“选项”和“控制可选 shell 行为的变量”。

## `set -o`：开启和关闭 Shell 特性

配合 `-o` 或 `+o` 选项使用的内置命令 `set` 可以启用、禁用和列出某些 bash 特性。例如，以下命令开启 `noclobber` 特性（第 231 页）：

```bash
$ set -o noclobber
```

你可以通过命令关闭此特性（默认）：

```bash
$ set +o noclobber
```

不带选项的 `set -o` 命令列出 `shopt` 控制的每个特性，随后是其状态（开启或关闭）。不带选项的 `set` 命令以可以作为 shell 输入的形式列出相同的特性。表 9-13 列出了 bash 特性。

# 处理命令行

无论你是在交互式操作还是运行 bash 脚本，bash 在开始处理命令之前都需要读取命令行——bash 在处理任何命令之前总是至少会读取一行。某些 bash 内置命令（如 `if` 和 `case`）以及函数和带引号的字符串会跨越多行。当 bash 识别出一个多于一行的命令时，它会在处理之前读取整个命令。在交互式会话中，每当你输入多行命令的每一行时，bash 会向你显示次级提示符（`PS2`，默认为 `>`；第 305 页），直到它识别出命令的结束：

```bash
$ echo 'hi'
> end
hi
end
$ function hello () {
> echo hello there
> }
$ 
```

在读取命令行后，bash 会对该行应用历史扩展和别名替换。

## 历史扩展

第 314 页的“重新执行和编辑命令”讨论了你可以提供哪些命令来修改和重新执行历史列表中的命令。历史扩展是 bash 用于将历史命令转换为可执行的命令行的过程。例如，当你输入命令 `!!` 时，历史扩展会改变该命令行使其与上一个命令相同。历史扩展在交互式 shell 中默认开启；设置 `set +o histexpand` 可以将其关闭。历史扩展不适用于非交互式 shell（脚本）。

## 别名替换

别名（第 328 页）用字符串替换简单命令的第一个单词。默认别名在交互式 shell 中开启，在非交互式 shell 中关闭。提供命令 `alias -u expand_aliases` 可以关闭别名。

## 解析和扫描命令行

在处理完历史命令和别名后，bash 不会立即执行命令。shell 执行的首要任务之一是将命令行解析（分离字符串）为标记或单词。然后它会扫描每个标记以寻找指示 shell 执行特定操作的特殊字符和模式。这些操作可能涉及将一个或多个单词替换为另一个。当 shell 解析以下命令行时，它将其拆分为三个标记（`cp`、`~/letter` 和 `.`）：

```bash
$ cp ~/letter .
```

在分离标记和执行命令之前，shell 会扫描标记并执行命令行扩展。

## 命令行扩展

在交互式和非交互式用法中，shell 在将命令行传递给目标程序之前，都会使用命令行扩展转换命令行。你可以在不深知命令行扩展的情况下使用 shell，但通过理解这一主题并利用 shell 提供的功能获得更好的优势。本节介绍了 Bourne Again shell 的行扩展。

Bourne Again shell 按照以下顺序扫描每个标记进行各种类型的扩展和替换。这些过程中的大多数会将一个单词扩展为单个单词。只有大括号扩展、单词拆分和路径扩展可以改变命令中的单词数量（变量 `"$@"` 的扩展除外——第 440 页）。

1. 大括号扩展（第 340 页）
2. 波浪号扩展（第 341 页）
3. 参数和变量扩展（第 342 页）
4. 算术扩展（第 342 页）
5. 命令替换（第 344 页）
6. 单词拆分（第 345 页）
7. 路径扩展（第 347 页）
8. 进程替换（第 347 页）

> 在 bash 完成上述列表的操作后，它会从命令行中移除单引号以及不是扩展结果的双反斜杠。此过程称为引号移除。

## 扩展顺序

bash 执行这些步骤的顺序会影响命令的解释。例如，如果你将一个变量设置为看起来像输出重定向指令的值，然后输入一个使用该值执行重定向的命令，你可能会认为 bash 会重定向输出。

```bash
$ SENDIT="> /tmp/saveit"
$ echo xxx $SENDIT
xxx > /tmp/saveit
$ cat /tmp/saveit
cat: /tmp/saveit: No such file or directory
```

事实上，shell 并没有重定向输出——它在评估变量之前就会识别输入输出重定向。当它执行命令行时，shell 会检查重定向，在没有发现重定向的情况下评估 `SENDIT` 变量。在将变量替换为 `> /tmp/save` 后，bash 将参数传递给 `echo`，`echo` 忠实地将其复制到标准输出。不会创建 `/tmp/save` 文件。

后续章节提供了命令处理涉及步骤的更详细描述。请记住，双引号和单引号会导致 shell 在执行扩展时的行为不同。双引号允许参数和变量扩展，并抑制其他类型的扩展。单引号则抑制所有类型的扩展。

## 大括号扩展

大括号扩展源于 C Shell，提供了一种在路径扩展不适用的情况下指定文件名的方便方法。尽管大括号扩展始终用于指定文件名，但该机制可以生成任意字符串；shell 不会尝试将大括号法与现有文件名进行匹配。

大括号扩展在交互式和非交互式 shell 中默认开启；你可以通过 `set +o braceexpand` 将其关闭。shell 还使用大括号来隔离变量名（第 298 页）。

下面的示例说明了大括号扩展是如何运作的。`ls` 命令没有显示任何输出，因为目录中没有文件。`echo` 显示了 shell 使用大括号扩展生成的字符串。假设字符串与文件名不匹配（目录中没有文件）。

```bash
$ ls
$ echo chap_{one,two,three}.txt
chap_one.txt chap_two.txt chap_three.txt
```

波浪号也用于目录堆栈操作（第 292 页）。此外，`~+` 是 `PWD`（工作目录名称）的同义词，`~-` 是 `OLDPWD`（上一个工作目录名称）的同义词。

## 参数和变量扩展

在命令行上，后面跟不是左括号的美元符号（`$`）会引入参数或变量扩展。参数包括命令行参数、位置参数（第 438 页）和特殊参数（第 436 页）。变量包括用户创建的变量（第 296 页）和关键字变量（第 301 页）。然而，bash 的手册页和 info 页面并没有这种区分。

如果参数和变量被包含在单引号内，或者美元符号被转义（前面有反斜杠），则它们不会被扩展。如果它们被包含在双引号内，shell 就会扩展参数和变量。

## 算术扩展

shell 通过评估算术表达式并将其替换为计算结果来执行算术扩展。在 bash 中，算术扩展的语法为：

```bash
$((expression))
```

shell 评估并用 `$((expression))` 的结果替换它。这种语法与用于命令替换 `$(...)` 的语法相似，并执行并行的功能。你可以将 `$((expression))` 作为命令的参数，或者替换命令行上的任何数值。

形成表达式的规则与 C 编程语言中的规则相同；所有标准的 C 算术运算符均可用（见第 461 页的表 11-8）。bash 中的算术使用的是整数。然而，除非你使用整数类型的变量（第 301 页）或实际整数，否则 shell 必须为了算术评估将值转换为整数。

你不需要在表达式中的变量名前加美元符号（`$`）。在下面的示例中，一个算术表达式确定了距离 60 岁还有多少年：

```bash
$ cat age_check
#!/bin/bash
echo "How are you?"
read age
echo "Wow, in $((60-age)) years, you'll be 60!"
```

```bash
$ age_check
How are you? 55
Wow, in 5 years, you'll be 60!
```

你不需要将表达式包含在引号内，因为 bash 不对其进行文件名扩展。此功能让你更易使用星号（`*`）进行乘法，如下例所示：

```bash
$ echo There are $((60*60*24*365)) seconds in a non-leap year.
There are 31536000 seconds in a non-leap year.
```

下一个示例使用了 `wc`、`cut`、算术扩展和命令替换来估计打印 `letter.txt` 文件内容所需的页数。使用 `-l` 选项的 `wc`（字数计数）工具的输出是文件中的行数，位于第 1 到 4 列，后面跟着一个空格和文件名。带有 `-c 1-4` 选项的 `cut` 工具提取前 4 列。

```bash
$ wc -l letter.txt
351 letter.txt
$ wc -l letter.txt | cut -c 1-4
351
```

美元符号和圆括号指示 shell 执行命令替换；美元符号和双圆括号表示算术扩展：

```bash
$ echo $(( $(wc -l letter.txt | cut -c 1-4) / 66 + 1 ))
6
```

前一个示例通过管道将 `wc` 的标准输出发送到 `cut` 的标准输入。由于命令替换，两者的输出都替换了命令行上 `$(` 和匹配的 `)` 之间的命令。算术扩展将此数字除以 66（每页行数）。末尾加 1，以便整数除法的结果丢弃任何余数。

### 较少的美元符号 (`$`)

当你在 `$(( ))` 中使用变量时，单个变量引用前的美元符号是可选的：

```bash
$ x=23 y=37
$ echo $((2*$x + 3*$y))
157
$ echo $((2*x + 3*y))
157
```

另一种不使用 `cut` 获取结果的方法是将输入重定向到 `wc`，而不是让 `wc` 从命令行上的文件名获取输入。当我们重定向其输入时，我们不显示文件名：

```bash
$ wc -l < letter.txt
351
```

将算术扩展的结果赋值给变量是一个常见做法：

```bash
$ numpages=$(( $(wc -l < letter.txt) / 66 + 1 ))
```

内置命令 `let` 评估算术表达式的方式与 `$(( ))` 相同。下面的命令等同于前一个：

```bash
$ let "numpages=$(wc -l < letter.txt)/66 + 1"
```

双引号防止了空格（包括你能看到的和由于命令替换产生的空格）将表达式分离为 `let` 的参数。最后一个表达式的值决定 `let` 的退出状态。如果最后一个表达式的值为 0，则 `let` 的退出状态为 1；否则，退出状态为 0。

你可以在单行命令行上给 `let` 多个参数：

```bash
$ let a=5+3 b=7+2
$ echo $a $b
8 9
```

当使用 `let` 或 `$(( ))` 进行算术扩展并引用变量时，shell 不要求以美元符号（`$`）开始变量名。尽管如此，这是一个好习惯，因为在大多数地方你必须包含它。

## 命令替换

命令替换用命令的输出替换符号。bash 首选命令替换语法如下：

```bash
$(command)
```

在 bash 下，你也可以使用：

```bash
`command`
```

shell 执行命令并替换其周围的符号。在下面的示例中，shell 执行命令并用其输出替换其周围的符号。

```bash
$ echo $(pwd)
/home/alex
```

将命令的输出赋值给变量：

```bash
$ where=$(pwd)
$ echo "You are using $where."
You are using /home/jenny.
```

尽管说明了如何将命令的输出赋值给变量，你可以直接显示 `pwd` 的输出：

```bash
$ cat where
echo "You are using $where."
$ where
You are using /home/jenny.
```

以下命令使用 `find` 在目录树中查找名为 `README` 的文件。`find` 的标准输出将成为 `ls` 的参数列表。

```bash
$ ls -l $(find -name README)
```

下一个命令显示了旧的 `` `command` `` 语法：

```bash
$ ls -l `find -name README`
```

新语法的优势之一是避免了复杂的令牌、引号和转义规则。新语法的另一个优势是它可以嵌套，而旧语法不能。例如，你可以生成所有大小超过 `/README` 的 `README` 文件列表：

```bash
$ ls -l $(find -name README -size +$(echo /README | wc -c))
```

在 `set -x` 命令（第 408 页）后尝试此命令查看 bash 如何扩展它。如果没有 `README` 文件，你只会得到 `ls -l` 的输出。更多命令替换信息，请参见第 404、423 和 453 页。

## 单词拆分

shell 使用 `IFS` 变量（内部字段分隔符，第 304 页）的值作为分隔符，将命令替换、算术扩展和参数扩展的结果拆分为单词。如果 `IFS` 未设置，则使用默认值（空格、制表符、换行符）。如果 `IFS` 为空，则不进行单词拆分。

## 路径扩展

路径扩展（也称为文件名生成或 globbing）将包含通配符（`*`、`?`、`[...]`）的单词替换为匹配的文件名列表。如果没有匹配的文件名，且未设置 `nullglob` 选项，则保留原单词不变。

删除了 `tmp*` 文件，当 shell 尝试扩展它时，它会寻找匹配 `tmp*` 的文件名。因此，它会将未响应的扩展传递给 `echo` 内置命令，该命令会显示它接收到的字符串。

```bash
$ ls
tmp1 tmp2 tmp3
$ echo tmp*
tmp1 tmp2 tmp3
$ rm tmp*
$ echo tmp*
tmp*
```

路径开头或紧跟在路径斜杠（`/`）后的点（`.`）必须显式匹配，除非你设置了 `dotglob`（第 336 页）。`nocaseglob` 选项（第 337 页）会导致 shell 在不区分大小写的情况下对文件名进行匹配。在参数周围加上双引号会导致 shell 抑制路径扩展以及除参数和变量扩展的所有其他扩展。在参数周围加上单引号则抑制所有类型的扩展。接下来的示例中的第二个 `echo` 命令显示了双引号内的变量 `$Alex`，双引号允许变量扩展。shell 将变量扩展为值：`sonar`。这种扩展在第三个 `echo` 命令中没有发生，因为它使用了单引号。由于单引号和双引号都不允许路径扩展，最后两个命令显示了未扩展的参数 `tmp.*`。

```bash
$ Alex=sonar
$ echo tmp* $Alex
tmp1 tmp2 sonar
$ echo "tmp* $Alex"
tmp* sonar
$ echo 'tmp* $Alex'
tmp* $Alex
```

shell 区分变量的值和对变量的引用，如果通配符出现在变量的值中，它们不会被扩展。因此，你可以给变量赋值一个包含特殊字符（例如星号 `*`）的值。

在下一个示例中，工作目录有三个名字以 `letter` 开头的文件。当你将值 `letter*` 赋值给变量 `var` 时，shell 不扩展通配符，因为它出现在变量的值中（在变量的赋值语句中）。字符串 `letter*` 周围没有引号，仅凭上下文就防止了扩展。赋值后，`set` 内置命令（在 `grep` 的帮助下）显示 `var` 的值为 `letter*`。

三个 `echo` 命令演示了三个级别的扩展。当 `var` 用单引号引用时，shell 不执行任何扩展，并将字符串 `$var` 传递给 `echo`，由其显示。当你使用双引号时，shell 只执行变量扩展，并用变量 `var` 的值替换其名称。此命令没有执行路径扩展，因为双引号抑制了它。在最后一个命令中，shell 在没有引号限制的情况下，先执行变量替换，然后在将参数传递给 `echo` 之前执行路径扩展。

```bash
$ ls letter*
letter1 letter2 letter3
$ var=letter*
$ set | grep var
var=letter*
$ echo '$var'
$var
$ echo "$var"
letter*
$ echo $var
letter1 letter2 letter3
```

## 进程替换

Bourne Again Shell 的一个特殊功能是可以用进程替换文件名参数。语法为 `<(command)` 的参数会导致 `command` 执行，并将输出写入一个命名管道（FIFO）。shell 用该管道的名称替换该参数。如果在处理过程中使用了该参数，则会读取命令的输出。同样，语法为 `>(command)` 的参数会被一个管道名称替换，该管道可用于写入。

下面的示例使用了 `sort`（第 153 页）配合 `-m`（合并，仅当输入文件已排序时正常工作）选项将两个单词列表合并为一个列表。每个单词列表由一个管道生成，该管道从文件中提取匹配模式的单词并对列表中的单词进行排序。

```bash
$ sort -m -f <(grep "^[A-Z]" memo1) <(grep ".*aba.*" memo2)
```
