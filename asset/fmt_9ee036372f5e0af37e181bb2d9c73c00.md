
`/opt/kde:/sbin:/bin:/usr/sbin:/usr/bin:/usr/bin:/root/bin`

你可以通过编辑`/etc/profile`并调整（作为`root`）以`"PATH="`开头的行来更改系统中所有用户的`PATH`。使用`pico`编辑器（`nano`）：

```bash
pico -w /etc/profile
```

重新登录以生效。要为单个用户设置`PATH`，请编辑文件`home/username/.bash_profile`（请注意，文件名开头目录前的点是不可见的，你必须使用`-a`来查看它们）。

如果你真的想让当前目录包含在`PATH`中，请向`PATH`中添加`"."`（点）。当`"."`意味着“当前目录”时，`/.bash_profile`中对`PATH`的定义看起来可能如下所示：

```bash
PATH="$PATH.:"
export PATH
```

此命令获取环境变量`PATH`的内容（对于`/etc/profile`中的所有用户均如此），并根据变量`HOME`设置的你的目录名称末尾追加一个`"/bin"`和一个冒号。最后，该命令将生成的字符串赋值给名为`PATH`的变量。在修改`PATH`或任何其他用户环境变量后，必须使用`"export"`命令，以便该变量在创建它的脚本之外也可见。

## 4.1.6 我如何关闭我的机器？

像你平时做的那样，关闭所有保存数据的程序。从你的`GUI`主菜单（例如`"K"`）选择“`Logout`”（注销）。然后，从登录界面选择：“`System-Shutdown`”（系统关机）。或者，在文本界面，按下`Ctrl+Alt+Del`（三指滑，同时按下三个键），等待关机完成，然后仅关闭机器。

千万不要在没有正常关机的情况下关闭机器，否则下次启动时可能会遇到磁盘错误信息。（通常情况下，由于不当关机导致的错误会在下次启动时自动修复，但偶尔会产生更严重的问题，你需要手动修复文件或重新安装！）

## 4.1.7.2 核心文件 (Core files)

当程序崩溃时，通常会在你的家目录下转储一个`"core"`文件。这会伴随着相应的提示。核心文件是一个内存镜像（调试信息），作为调试工具。如果你是一个不想调试该程序的用户，可以直接删除它：

```
rm core
```

或者不删除（当下次生成新的核心文件时，旧的会被覆盖）。你也可以使用命令禁用核心转储：

```
limit -c @
```

检查是否生效：

`limit -a`

（这会显示“用户限制”，选项`"-a"`代表“所有”）。要让所有用户永久禁用核心转储的选项生效，请以`root`身份编辑`/etc/profile`文件（即设置`limit`的地方），并调整该设置。重新登录以使`/etc/profile`生效。

如果你想查看如何使用核心文件，请尝试在包含核心文件的目录下执行：

```
gdb -c core
```

这会在核心`"文件"`上启动`GNU`调试器(`gdb`)，并显示创建核心文件的程序名称、程序终止时的信号等。输入`"quit"`退出调试器。要学习不同信号的含义，尝试：

```
cat /usr/include/bits/signum.h | more
```

## 4.1.8 命令选项

大多数命令接受数字“选项”。可以使用`-`（破折号）引入选项。例如：

```
dir -l
```

显示当前目录列表，但使用长格式（默认格式为“短”格式）。

有两种方式引入多个选项：

```
dir -l -a
```

或者

```
dir -la
```

以上任一命令都会以行格式（选项`-l`）显示当前目录列表，并包含所有文件，即也包含隐藏文件（选项`-a`）。

最流行的选项用一个字母标记。这遵循了传统的`UNIX`调用选项的方式。还有一种新风格，用法如下：

```
dir --help
```
