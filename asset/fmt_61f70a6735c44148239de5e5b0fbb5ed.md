## head and tail 命令

首先介绍 `head` 和 `tail` 命令的语法格式，然后用两个例子来演示。

### head 命令

用法：`head [选项] [文件]`
功能：`head` 命令，其功能是将文件开头（默认 10 行）输出到标准输出。如果指定多个文件，每一段输出文件名。如果不指定文件，或者指定文件为“-”，则从标准输入数据。`head` 命令的常用选项如表 5-3 所示。

**表 5-3 head 命令常用选项**

| 选项 | 说明 |
| --- | --- |
| `-n<行数>` | 显示前面的 n 行，n 为正整数；如果不指定，默认前 10 行 |
| `-c<字节数>` | 统计前 n 字符 |
| `-q` | 不显示文件名 |
| `-v` | 显示文件名 |

### tail 命令

用法：`tail [选项] [文件]`
功能：`tail` 命令，其功能是将文件结尾（默认 10 行）输出到标准输出。如果指定多个文件，每一段输出文件名。如果不指定文件为“-”，则从标准输入数据，注意 `tail` 可以查看变化。`tail` 命令的常用选项如表 5-4 所示。

**表 5-4 tail 命令常用选项**

| 选项 | 说明 |
| --- | --- |
| `-n<行数>` | 显示文件的最后 n 行，n 为正整数；如果不指定，默认最后 10 行 |
| `-c<字节数>` | 统计最后的 n 字符 |
| `-q` | 不显示文件名 |
| `-v` | 显示变化后的数据 |
| `-f` | 实时显示变化后的数据 |
| `-F` | 如果文件不存在，则一直等待，往往与 `-f` 连用 |

案例：显示文件的前 5 行和后 5 行，如清单 5-54 所示。

## 5.3.3 知识点 3 正则表达式处理 grep

`grep` 是 Linux 的一种功能强大、完善、也是最常用的文本工具。`grep` 是 global regular expression print out 的缩写，意思是“全局搜索并打印”。`grep` 的主要功能是字符串比较，然后匹配需要的字符串并打印出来。注意 `grep` 在数据中查找字符时，是以“行”为单位。在多个文件中执行模式（pattern），搜索的结果会被送到屏幕，不影响内容。

### grep 命令

用法：`grep [选项] 正则表达式 [文件]`
功能：`grep` 在一个或多个文件中匹配指定的模式，输出到标准输出。`grep` 命令的选项如下表 5-14 所示。

**表 5-14 grep 命令选项**

| 选项 | 说明 |
| --- | --- |
| `-E` | 等于 `egrep` 命令，可以使用正则表达式 |
| `-F` | 等于 `fgrep` 命令，匹配固定字符串，不支持正则表达式 |
| `-i` | 忽略大小写 |
| `-n` | 输出行号 |
| `-v` | 反向显示未匹配的行 |
| `-o` | 显示匹配的部分 |
| `-w` | 按照单词匹配 |
| `-A n` | 显示匹配后的 n 行 |
| `-B n` | 显示匹配的前 n 行 |
| `-C n` | 显示匹配前后 n 行 |
| `--color=auto` | 高亮匹配的关键字 |

> **笔记**
>
> 正则表达式分为两类：基本正则表达式（BRE）和扩展正则表达式（ERE）。两者的功能相似，是在某些字符和功能上有区别。简单来说，在 `grep` 中，`+`、`?`、`|` 是元字符，BRE 是不支持这些字符的。总来说，扩展正则表达式更易读一些，功能也能增加，因此推荐使用扩展正则表达式。如果没有特别说明，例子都是扩展正则表达式。

### 入门

假设要在系统日志 `/var/messages` 中包含这个字符串。按清单 5-56 所示。

**清单 5-56**

```bash
grep "s" /var/messages
```

这是最简单的正则表达式匹配，它可以精确匹配这样的字符串：由两个字符组成，前一个字符是 s，后一个是 t。很多行里都包含这个字符串。按清单 5-57 所示。

**清单 5-57**

```bash
grep "st" /var/messages
```

其中 `\b` 在正则表达式中一种叫元字符（meta-character）。特殊字符 `\b` 代表单词的开头或结尾。注意：`\b` 匹配空格、点符号、换行、制表符，匹配字符中的任意一个。事实上，`\b` 并不匹配位置。上述“单词”的概念完全符合 `grep` 命令的定义，可以用清单 5-58 所示。

**清单 5-58**

```bash
grep "\bst\b" /var/messages
```

这里，又出现了新的字符，其中 `.` 匹配除了换行以外的任意字符。“`*`”同样表示，不是字符，而是数量——指定次数。前面的字符可以重复任意次数使整个正则表达式匹配。限定符用于正则表达式的一个组件必须要满足匹配。通用的限定符见表 5-17。

### 3. 锚点

只选择字符是不够的，还需要指定字符在位置，这就用到锚点（anchor）。正则表达式中的锚点并不是具体的字符或字符串，而是一个位置。常用锚点如表 5-16 所示。

**表 5-16 常用锚点**

| 锚点 | 说明 |
| --- | --- |
| `^` | 匹配开头。例如，`^root` 表示行首 |
| `$` | 匹配结尾。例如，`[0-9]$` 表示行尾 |
| `\b` | 匹配边界。例如，`\b` 表示行内的数字 |

### 4. 限定

除了字符种类，字符的位置，还需要字符出现多少次，就需要用到限定符。在入门中接触了如 `\d{1}` 这样的匹配方式，被定义为限定符。限定符用于正则表达式的一个组件必须要满足匹配。限定符见表 5-17。

**表 5-17 限定符**

| 限定符 | 描述 |
| --- | --- |
| `*` | 匹配一个元素零次或多次。例如，`.*` 匹配任意长度的字符串或空字符串；`[0-9]*` 匹配任意数字字符 |
| `+` | 匹配一个元素一次或多次。例如，`[a-z]+` 表示一个以字母开头的小写字母字符串 |
| `?` | 匹配一个元素零次或一次。例如，`n?` 匹配 ran 或 ra；`n?` 匹配一个至少 n。例如，`[0-9]{13}` 表示长度为 13 的数字 |
| `{n}` | 匹配一个元素至少 n 次。例如，`[A-Z]{5}` 表示至少为 5 的英文字 |
| `{n,m}` | 匹配一个元素至少 n 次，但不 m 次。例如，`[0-9]{3,5}` 表示长度在 3 到 5 之间的数字 |

### 5. 分组构造

之前提到用限定符指定特定字符的次数，如果指定一个字符的出现次数，就可以这个字符放入小括号内，来构建一个“分组构造(grouping constructs)”。分组作为一个整体和整体限定符来使用它的次数。分组构造如表 5-18 所示。

**表 5-18 分组构造**

| 分组构造 | 描述 |
| --- | --- |
| `(分组)` | 匹配整体，而不是单个元素。例如，`(ab)` 表示 ab 整体为匹配符；`(ab)*` 表示整体为匹配符且匹配多次；`(ab)+` 表示 ab 整体为匹配符且匹配至少一次 |

### 6. 替换构造

正则表达式的替换构造(alternation constructs)指的是几种规则，如果满足其中一种规则就应该匹配该正则，类似于“或”的逻辑，具体用“`|`”把不同的规则分开。替换构造如表 5-19 所示。

**表 5-19 替换构造**

| 替换构造 | 描述 |
| --- | --- |
| `|` | 匹配以“`|`”分隔的任意一个。例如，`foo|tax` 匹配 foo or tax；`system(ctl|d)` 表示替换 systemctl or systemd；`systemctl|d` 表示替换 systemctl 或 d |

### 7. 转义字符

如果需要匹配 1~16 中提到的元字符，比如正则字符点号 `.` 或者星号 `*` 就会出现问题：因为这些字符在正则表达式（或者扩展正则表达式）中有特殊的意义的，这时就需要用到字符转义来试图让这些特殊字符回归本身。转义字符的符号是反斜杠“`\`”，如表 5-20 所示。在正则表达式（或者扩展正则表达式）中，如果要匹配 `*` 特殊字符的本质：在字符前加上反斜杠 `\` 可以进行转义；要匹配星号，应该使用 `\*`。

## 5-20 字符转义

| 字符转义 | 描述 |
| :--- | :--- |
| `\` | 在特殊字符前加上 `\` 使其变为普通字符，或在普通字符前加上 `\` 使其成为特殊字符。例如，在正则中使用 `\b`，`\bax` 表示匹配 ax 字符 |

字符还有另一层含义：可以将普通字符视为元字符，在前面加上 `\` 后它就变成了一个锚点，表示单词的边界。
