
在 UNIX 中，文件是存储为字节流的存储库。在 UNIX 中，数据使用 ASCII 编码，尽管像 IBM 309 这样的系统使用 EBCDIC。ASCII 和 EBCDIC 代码是不同的；这意味着相同的代码意味着不同的含义。如果你处理在另一个操作系统创建的文件，可能会出现问题。文件包含不同类型的信息。例如，一个文件可以包含 C、COBOL 或 C++ 程序的源代码、包含来自朋友的文本文档，或者包含程序的执行代码。这些是 UNIX 支持的一些文件类型；也就是说，你可以使用 UNIX 命令查看或复制这些类型的文件。文件位于不同的介质上。文件可以是磁盘上的永久文件、内存中的临时文件，或者是显示或接收终端的文件。如果文件是永久文件，你可能会查看它——但如果文件是临时文件，你可能不知道。

对文件通常执行的操作如下：

- 打开文件进行处理
- 从文件中读取数据进行处理
- 处理后将数据写入文件
- 在完成所有处理后关闭文件

## 文件类型

本节讨论了 UNIX 中提供的各种文件类型。你可能熟悉这些文件类型，例如文本文档和源代码。

### 普通文件

普通文件是你可能熟悉的那些文件。它们在本质上是永久的，包含了诸如程序源代码、从老板那里收到的邮件以及你写给朋友的信等数据。这些文件几乎总是包含文本信息。在这些文件中，数据被组织成记录。例如，如果一本书是一个包含关于 UNIX 操作系统的文件，那么书中的每一行都被称为一条记录。

UNIX 是如何知道这些记录的？答案是有一个特殊的字符，即换行符，UNIX 用它来确定记录从哪里结束以及另一个记录从哪里开始。正如你稍后看到的，某些 UNIX 命令支持文本处理。然而，请记住，文本文件并不是普通文件的唯一类型。有些文件包含一个没有任何换行符的字节流。尽管 UNIX 是为了处理文本文档构建的，但这些文件中的数据无法被 UNIX 处理。

以下是一些普通文件的示例：

- `prog.c` 是一个包含 C 源程序的文件。
- `prog.cbl` 是一个包含 COBOL 源程序的文件。
- `prog.exe` 是一个包含程序可执行代码的文件。
- `invite.doc` 是一个包含同事发出的派会邀请的文件。

> 注意：这里提供的示例使用了常用的 UNIX 命名规范。然而，这些只是惯例，而不是规则。因此，有人可能会将文件命名为 `prog.c`，即使它包含一封给老板的信。

这里是文件属性列表的一个示例。该文件名为 `testfile`，通过使用以下命令获取属性：

```
ls -al testfile
```

结果是：

```
rwxr-xr-x 2 guhas staff 1012 Oct 30 18:39 testfile
```

UNIX 使用名为 i-node（节点）的数据结构来跟踪文件属性。系统中的每个 i-node 都由称为 i-node 的数字标识。系统中的每个文件都有关联的 i-node，其中包含如下信息：

- 文件的所有者详情
- 文件的权限详情
- 文件的时间戳（创建日期和时间、修改日期和时间等）
- 文件的类型

文件与多个时间戳相关。这些时间是：

- 最后访问时间
- 最后修改时间
- 最后 i-node 修改时间

每当你对文件执行任何操作时，最后访问时间就会改变。当文件内容被修改时，最后修改日期就会改变。当 i-node 中存储的任何信息发生变化时，最后 i-node 修改时间就会改变。

> 注意：某些 UNIX 版本（例如 AIX）在执行命令时并不会修改最后访问时间。

### 目录文件

目录是一个特殊文件，包含了存储在目录中的各种文件的信息，例如文件位置、文件大小、文件创建时间以及文件修改时间。这个特殊文件只能由 UNIX 操作系统或为目录处理编写的程序读取。你可能无法查看目录文件的内容，但你可以使用 UNIX 命令查询这些目录的属性。目录就像电话电话簿，包含了其中文件的地址信息。当你访问一个文件名时，UNIX 会查找指定的目录以获取有关该文件的信息。在每个目录中，你总能找到两个：

1. `.`（单点）
2. `..`（两个连续的点）

单点 `.` 指代当前目录，而两个连续的点 `..` 指代上上一级目录（有时称为父目录）。

这里是 `testdir` 目录属性的示例：

```
drwx-xr-x  2 guhas  writer      512 Oct 30 18:39 testdir
```

`rwx-xr-x` 定义了由用户 `guhas` 创建并属于组 `guhas` 的 `testdir` 的权限。目录项 `testdir` 的大小为 512 字节。最后修改时间是在 10 月 30 日下午 6:39 的。

UNIX 将目录视为文件，但它具有一些特殊特性。目录至少有两个名称。例如，如果目录是 `/u/ghas` 且你创建了一个名为 `testdir` 的子目录，就会创建两个链接：

- `/u/ghas/testdir`
- `/u/ghas/testdir/`

以下是一些设备文件的示例：

- `/dev/tty` 是字符设备文件。
- `/dev/sda` 是块设备文件。
- `send`: 使用简单的数据缓冲区通过已连接的 socket 传输数据

### 命名管道

命名管道是为进程间通信创建的文件。也就是说，它是两个程序之间传输数据的媒介。发送进程将数据写入命名管道，接收进程从命名管道中读取数据。它是一个临时文件，只要进程仍在通信，它就会存在。数据在命名管道中以 FIFO（先进先出）的方式处理。

### 符号链接与硬链接

链接是指实际文件的指针，而不复制文件的内容。也就是说，链接是为同一个文件提供另一个名称的方法。文件有两种类型的链接：

- 硬链接
- 符号链接（或软链接），也称为 `symlink`

使用硬链接，原始文件名和链接文件名指向同一个物理地址，且完全相同。硬链接有两个重要的限制：目录不能有硬链接，且硬链接不能跨越文件系统。文件系统是文件必须所在的物理空间；单个文件不能跨越多个文件系统，但一个文件系统可以包含多个文件。可以在不删除链接的情况下删除原始文件名。在这种情况下，文件不会被删除，但原始文件的目录项会被删除，链接计数减 1。

使用符号链接或软链接，有两个文件：一个是原始文件，另一个是包含原始文件名名的链接文件。符号链接的一个重要限制是，你可以删除原始文件，这会导致链接失效且不包含任何数据。然而，符号链接可以跨系统。

你应该小心符号链接。如果你不小心，在原始文件被删除或重命名后，你将留下无法指向任何地方的文件。

符号链接的一个重要特性是，它可以用于链接目录也可以用于链接文件。

如果我们在 `/u/guhas` 目录下有一个名为 `origfile` 的文件，其特征如下：

```
-rw-r--r-- 2 guhas    writer    30 Nov 8 01:14 origfile
```

名为 `hlinkfile` 的文件（已与 `origfile` 硬链接）将具有以下特征：

```
-rw-r--r-- 2 guhas    writer    30 Nov 8 01:20 hlinkfile
```

`guhas` 之前的 `2` 表示有两个文件指向同一个物理地址（`origfile` 和 `hlinkfile`）。

名为 `slinkfile` 的文件（已与 `origfile` 软链接）将具有以下特征：

```
lrwxwxr-wx 1 guhas    writer    8 Nov 01:18 slinkfile -> origfile
```

链接在文件名中显而易见。在这种情况下，如果你删除了 `origfile`，`slinkfile` 将失效。

### 命名文件和目录

每个文件由一个名称识别，名称是一个字符序列。旧版本的 UNIX 对文件名字符的数量有限制。所有较新版本的 UNIX 都删除了这一限制。在命名文件时，UNIX 你要小心。

你将获得 `january` 目录下 `day01` 文件的属性，这意味着 UNIX 会在你当前所在的目录中查找你指定的文件是否存在。UNIX 中的所有命令在文件名没有包含信息时，都会使用当前目录来解析文件名。相对路径始终相对于你所在的当前目录。

如果你在 `january` 目录并想要获取 `february` 目录下 `day01` 文件的属性，你需要指定该文件的绝对路径。也就是说，你将执行命令

```
ls -l /u/guhas/february/day01
```

UNIX 使用特殊字符 `.`（两个连续的点）作为相对路径，表示当前上一级目录或父目录。例如，如果你在 `/u/guhas/january` 中，相对路径中的 `..`（两个连续的点）将表示 `/u/guhas` 目录（它是 `/u/guhas/january` 的父目录），而相对路径中的 `../..` 将表示 `/u` 目录。

### 使用 ls 列出文件和目录

你可以使用 `ls`（带有选项）来列出系统上一个或多个文件或目录的详情。使用 `ls` 以不同的顺序生成文件和目录列表，例如按名称和按时间排序。可以只列出某些文件和目录——例如文件名。你将在第 5 章“通用命令”中学习更多关于 `ls` 命令的选项，但这里有一些示例，可以让你了解 UNIX 系统存储的文件或目录的细节。例如，在当前目录 `/u/guhas` 中执行命令

```
ls -l
```

显示如下：

| 权限 | | 所有者 | 组 | 大小 | 日期 | 名称 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| -rw-r---- | 1 | guhas | staff | 7161 | May 8 15:35 | example.c |
| drwxr-xr-x | 3 | guhas | staff | 1536 | Oct 19 00:54 | exe |
| -rw-r-- | 2 | guhas | staff | 10 | Nov 3 14:28 | file1 |
| -rw-r-- | 2 | guhas | staff | 10 | Nov 3 14:28 | file112 |

文件的详情包括

- 文件的权限属性
- 链接数
- 用户
- 创建文件的用户所属组
- 文件最后修改的时间
- 文件大小
- 日期
- 文件名

上一个示例显示当前目录有一个名为 `exe` 的目录和三个文件——`example.c`、`file1`、`file2`。对于 `exe` 目录，显示的链接数为三，这可以被计为：一个指向父目录 `/u/guhas`，一个是目录条目本身，还有一个是指向 `exe` 下的子目录。文件 `example.c` 的链接数为一，因为该文件没有任何硬链接。文件 `file1` 和 `file2` 的链接数为二，因为它们是使用硬链接连接的。
