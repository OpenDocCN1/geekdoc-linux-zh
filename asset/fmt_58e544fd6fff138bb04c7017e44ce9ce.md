
Shell 函数的情况也是如此。让我们考虑以下代码：

```bash
my_func() {
  echo "My Documents"
  ls ~/Documents
  echo "My Music"
  ls ~/Music
  echo "My Videos"
  ls ~/Videos
  return
}
```

很容易看出这个函数的作用，但它的输出去哪里了？它会去我们重定向的地方。当我们调用这个函数时，它可以将其合并输出发送到标准输出；如果我们需要，可以将其重定向到文件：

```bash
my_func > output.txt
```

或者将其重定向到管道：

```bash
my_func | sort
```

我们可以通过命令替换将输出存储在变量中：

```bash
var=$(my_func)
```

重定向同样适用于标准输入：

```bash
my_func < input.txt
```

## 总结

在本章中，我们介绍了一种常用的程序设计方法——自顶向下设计，并了解了如何使用 shell 函数来构建其所需的步步细化过程。我们还了解了如何使用局部变量使 shell 函数之间相互独立，并与它们所属的程序保持独立。这使得 shell 函数能够以可移植的方式编写，并通过允许它们被放置在多个程序中来实现可复用；这极大地节省了时间。

# 27 流程控制：使用 IF 进行分支

![](img/58edd539af3a70704734cedc1ac0c271_371_0.png)

在上一章中，我们遇到了一个问题：如何让我们的报告生成器脚本适应运行脚本的用户权限？解决这个问题的方案需要我们找到一种根据测试结果在脚本内部“改变方向”的方法。在编程术语中，我们需要让程序进行*分支*。

让我们考虑一个用*伪代码*表示的简单逻辑示例，伪代码是一种供人类阅读的计算机语言模拟。

`X = 5`

如果 `X = 5`，则：

- * 说“`X` 等于 5。”

否则：

- * 说“`X` 不等于 5。”

这是一个分支的示例。我们评估 `X` 的值，如果 `X = 5`，我们就说 `X` 等于 5；否则，我们就说 `X` 不等于 5。

### if 语句

使用 shell，我们可以按照如下代码编写上述逻辑：

```
x=5
if [ "$x" -eq 5 ]; then
    echo "x equals 5"
else
    echo "x does not equal 5"
fi
```

或者我们可以直接在命令行中输入（略微缩短）。

```
[me@linuxbox ~]$ x=5
[me@linuxbox ~]$ if [ "x" -eq 5 ]; then echo "equals 5"; else echo "does not equal 5"; fi
equals
[me@linuxbox ~]$ x=0
[me@linuxbox ~]$ if [ "x" -eq 5 ]; then echo "equals 5"; else echo "does not equal 5"; fi
does not equal 5
```

在这个示例中，我们执行了两次命令，将 `x` 的值设置为 5，导致输出字符串 "equals 5"；第二次将 `x` 的值设置为 0，导致输出字符串 "does not equal 5"。

`if` 复合命令具有如下语法，其中 `commands` 是命令列表：

```
if commands; then
  commands
elif commands; then
  commands...
else
  commands
```

这初看之下有点令人困惑。但在弄清楚之前，我们必须查看 shell 是如何评估命令执行成功或失败的。

### 退出状态

命令（包括我们编写的脚本和 shell 函数）在终止时向系统发出一个值，称为退出状态。这个值是一个 0 到 255 之间的整数，表示命令执行的成功或失败。按照惯例，值 0 表示成功，任何其他值均表示失败。shell 提供了一个我们可以使用的参数来检查命令的退出状态。在这里我们看到它的运行情况：

```
[me@linuxbox ~]$ ls -d /usr/bin
/usr/bin
[me@linuxbox ~]$ echo $?
0
[me@linuxbox ~]$ ls -d /bin/usr
ls: cannot access /bin/usr: No such file or directory
[me@linuxbox ~]$ echo $?
2
```

在这个示例中，我们执行了两次 `ls` 命令。第一次，`$?` 是 0。如果我们显示参数 `$?` 的值，会看到它是 0。我们第二次执行 `ls` 命令（指定了一个不存在的目录），它产生了错误，并再次检查参数 `$?`。这次它包含一个 2，表示命令遇到了错误。某些命令使用不同的退出状态值来提供错误诊断，而许多命令在失败时简单地以值 1 退出。手册页（`man` pages）通常会包含一个名为“Exit Status”的章节，描述使用了哪些代码。然而，0 始终表示成功。

shell 提供了两个极其简单的内置命令，它们除了以 0 或 1 的退出状态终止外，什么都不做。`true` 命令总是执行成功，而 `false` 命令总是执行失败。

```
@me@linux ~$ echo true
@me@linux ~$ echo $?
0
@me@linux ~$ echo false
@me@linux ~$ echo $?
1
```

我们可以使用这些命令来观察观察 `if` 语句是如何工作的。`if` 语句实际上执行的事情是评估命令的成功或失败。

```
@me@linux ~$ if true; then echo "It's true." fi
It's true.
@me@linux ~$ if false; then echo "It's true." fi
@me@linux ~$
```

当 `if` 后面的命令执行成功时，执行 "It's true."；当 `if` 后面的命令执行未成功时，不执行。如果 `if` 后面跟着一个命令列表，则评估列表中的最后一个命令。

```
@me@linux ~$ if false; then echo "It's true." fi
It's true.
@me@linux ~$ if true; false; then echo "It's true." fi
@me@linux ~$
```

### 使用 test

到为止，与 `if` 配合最常用的命令是 `test`。`test` 命令执行各种检查和比较。它有两种等价的形式。这里是第一形式：

```
test expression
```

第二种更流行的形式是：

```
[ expression ]
```

在这些语法描述中，`expression` 是一个被评估为真或假的表达式。当表达式为真时，`test` 命令返回退出状态 0；当表达式为假时，返回状态 1。

有趣的是，`test` 和 `[` 实际上都是命令。在 `bash` 中它们是内置命令，但它们也作为程序存在于 `/usr/bin` 中，供其他 shell 使用。表达式实际上只是它的参数，而 `[` 命令要求将 `]` 字符作为其最后一个参数提供。

`test` 和 `[` 命令支持广泛的有用表达式和测试。

#### 文件表达式

表 27-1: `test` 文件表达式

这里有一个演示了一些文件表达式的脚本：

```
#!/bin/bash
# test-file: 评估文件的状态
FILE=-./bashrc
if [ -e "$FILE" ]; then
    if [ -f "$FILE" ]; then
        echo "$FILE 是普通文件。"
    fi
    if [ -d "$FILE" ]; then
        echo "$FILE 是一个目录。"
    fi
    if [ -r "$FILE" ]; then
        echo "$FILE 是可读的。"
    fi
    if [ -w "$FILE" ]; then
        echo "$FILE 是可写的。"
    fi
    if [ -x "$FILE" ]; then
        echo "$FILE 是可执行/搜索的。"
    fi
else
    echo "$FILE 不存在"
    exit 1
fi
```

脚本评估赋值给常量 `FILE` 的文件，关于这个脚本有两个值得注意的有趣点。首先，注意表达式中的参数 `FILE` 加了引号。这并不是为了语法完成表达式，而是为了防止参数为空或仅包含空格。如果 `FILE` 参数展开结果为空值，会导致错误（运算符将被解释为非空字符串而非运算符）。给参数加引号确保了运算符后面总是跟着字符串，即使该字符串是空的。其次，脚本结尾处存在 `exit` 命令。`exit` 命令接受一个可选参数，该参数将成为脚本的退出状态。当未传递参数时，退出状态默认为最后执行的命令的退出状态。

脚本最后一行出现的命令只是出于形式。当脚本“运行到末尾”（到达文件末尾）时，它将以最后一个执行的命令的退出状态终止。

同样，shell 函数可以通过在 `return` 命令中包含一个整数参数来返回退出状态。如果我们将之前的脚本转换为 shell 函数并包含在更大的程序中，我们可以将 `exit` 命令替换为 `return` 语句，并获得所需的行为。

```bash
test_file () {
    # test-file: 评估文件的状态
    FILE=./bashrc
    if [ -f "$FILE" ]; then
        echo "$FILE is a regular file."
    fi
    if [ -d "$FILE" ]; then
        echo "$FILE is a directory."
    fi
    if [ -r "$FILE" ]; then
        echo "$FILE is readable."
    fi
    if [ -w "$FILE" ]; then
        echo "$FILE is writable."
    fi
    if [ -x "$FILE" ]; then
        echo "$FILE is executable/searchable."
    fi
    else
        echo "$FILE does not exist"
        return 1
    fi
}
```

### 字符串长度为零。

`string1 = string2`
`string1` 和 `string2` 相等。可以使用单等号或双等号。
`string1 == string2`
`bash` 支持使用双等号且通常优于此处，但它不符合 POSIX 标准。

`string1 != string2`
`string1` 和 `string2` 不相等。

`string1 > string2`
`string1` 的排序顺序在 `string2` 之后。

`string1 < string2`
`string1` 的排序顺序在 `string2` 之前。

## 警告

在与 `test` 配合使用，`>` 和 `<` 运算符必须加引号（或使用反斜杠转义）。如果不加引号，它们将由 shell 解释为重定向运算符，可能导致破坏性结果。另外请注意，虽然 `bash` 文档说明排序顺序符合当前区域（locale）的排序规则，但实际上可能并非如此。在包括 4.0 在内的 `bash` 版本中使用的是 ASCII (POSIX) 排序。这个问题在 4.1 版本中已修复。

这是一个包含字符串表达式的脚本：

```bash
#!/bin/bash
# test-string: 评估字符串的值
ANSWER=maybe
if [ -z "$ANSWER" ]; then
  echo "There is no answer." >&2
  exit 1
fi
if [ "$ANSWER" == "yes" ]; then
  echo "The answer is YES."
elif [ "$ANSWER" == "no" ]; then
  echo "The answer is NO."
elif [ "$ANSWER" == "maybe" ]; then
  echo "The answer is MAYBE."
else
  echo "The answer is UNKNOWN."
fi
```

在这个脚本中，我们评估常量 `ANSWER`。我们首先确定字符串是否为空。如果是，我们终止脚本并将退出状态设置为 1。注意，重定向被应用到了 `echo` 命令上。这会将错误信息“There is no answer.”重定向到标准错误，这是处理错误信息的正确做法。如果字符串不为空，我们评估字符串的值，看它是否等于“yes”、“no”或“maybe”。我们通过使用 `elif`（“else if”的缩写）来实现这一点。通过使用 `elif`，我们能够构建更复杂的逻辑测试。

#### 整数表达式

为了将值作为整数而不是字符串进行比较，我们可以使用表 27-3 列出的表达式。

## 表 27-3：`test` 整数表达式

| 表达式 | 如果...则为真 |
|---|---|
| `integer1 -eq integer2` | `integer1` 等于 `integer2`。 |
| `integer1 -ne integer2` | `integer1` 不等于 `integer2`。 |
| `integer1 -le integer2` | `integer1` 小于或等于 `integer2`。 |
| `integer1 -lt integer2` | `integer1` 小于 `integer2`。 |
| `integer1 -ge integer2` | `integer1` 大于或等于 `integer2`。 |
| `integer1 -gt integer2` | `integer1` 大于 `integer2`。 |

这是一个演示这些表达式的脚本：

```bash
#!/bin/bash
# test-integer: 评估整数的值。
INT=5
if [ -z "$INT" ]; then
    echo "$INT is empty." >&2
    exit 1
fi
if [ "$INT" -eq 0 ]; then
    echo "$INT is zero."
else
    if [ "$INT" -lt 0 ]; then
        echo "$INT is negative."
    else
        echo "$INT is positive."
    fi
    if [ $(($INT % 2)) -eq 0 ]; then
        echo "$INT is even."
    else
        echo "$INT is odd."
    fi
fi
```

脚本中有趣的部分在于如何判断一个整数是偶数还是奇数。通过对数字进行模 2 运算（将数字除以 2 并返回余数），它可以判断数字是奇数还是偶数。

#### 更现代的 test 版本

现代 `bash` 包含了一个复合命令，作为 `test` 的增强替代方案。

```bash
if [[ "$SINT" -ge "$MIN_VAL" && "$SINT" -le "$MAX_VAL" ]]; then
    echo "$SINT is within $MIN_VAL to $MAX_VAL"
else
    echo "$SINT is out of range."
fi
else
    echo "$INT is not an integer." >&2
    exit 1
```
