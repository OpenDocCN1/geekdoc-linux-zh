## 文件系统创建

`newfs(8)` 开始打印有关新文件系统的基本信息，例如其大小、扇区和块的数量，以及块和分块的大小。你将看到 inode 的数量。`newfs(8)` 在执行过程中会打印出每个超级块的位置，以便你了解进度（在计算机速度比现在慢得多时，这要重要得多；在大型文件系统上运行 `newfs(8)` 可能需要几分钟，看到它正在运行而不是直接死机是很棒的体验）。

你可以分别通过 `-b` 和 `-f` 标志来指定块和分块的大小。如果你没有在命令行中指定块和分块的大小，`newfs(8)` 将检查 `disklabel` 以获取这些信息。如果你不指定这些内容，`newfs(8)` 将使用默认值。我倾向于在 `disklabel` 中指定这些内容，因为这给了我一个双检查工作的机会。无论如何，`newfs(8)` 都会更新 `disklabel` 中的块和分块大小以便以后参考。

既然你可以随心所欲地切片、分区和格式化磁盘，让我们来看看磁盘管理中更高级的话题。其中一个主题是 RAID。

## RAID

任何严肃的数据存储系统的一个大需求都是 RAID，即独立磁盘冗余阵列。定义中的 I 意味着廉价，但这是相对的。一个 PB 级 RAID 阵列的成本远低于单块 PB 磁盘，但仍然相当昂贵。RAID 在驱动器之间分配数据以提高性能或可靠性。RAID 可以以硬件或软件方式运行。

### 硬件与软件 RAID

FreeBSD 同时支持硬件和软件 RAID。硬件 RAID 由 SCSI 控制器管理，提供 RAID 的主机适配器被称为 RAID 控制器。当你运行硬件 RAID 时，控制器会处理所有如何在硬盘上安排数据的计算。大多数 RAID 系统都非常稳定，硬件控制器通常是处理 RAID 最有效的方法。

硬件 RAID 的问题是，不同的控制器以不同的格式在磁盘上存储数据。如果你的 RAID 控制器坏了，你无法用不同品牌的控制器替换它；它可能无法识别你磁盘上的数据。如果你在硬件 RAID 阵列上存储关键数据，你必须拥有一个可以在故障时为你提供相同控制器的支持协议，或者一个同型号的备用控制器，亦或是极好的备份。

软件 RAID 由操作系统管理，由操作系统来决定如何在磁盘上安排数据。与硬件 RAID 相比，这种方法略微增加了系统负载，但使用的设备更廉价。你还不必承担在找不到完全相同类型的替换 RAID 控制器时丢失数据的风险。

使用硬件 RAID 通常比软件 RAID 要简单得多，因为你只需要遵循操作手册即可。RAID 控制器通常有一个简单的菜单驱动型 BIOS，允许你设置磁盘大小、恢复损坏的磁盘并配置你的虚拟磁盘。相反，软件 RAID 要求系统管理员实际上知道自己在做什么。如果你想了解硬件 RAID，请阅读 RAID 控制器的管理程序——我们正在讨论的是硬件 RAID。FreeBSD 支持的许多 RAID 类型也出现在硬件中。

许多 RAID 制造商提供了从操作系统管理阵列的软件工具。你可以使用 `megair` (`/usr/ports/sysutils/megacli`) 管理 `amr(4)` 阵列，使用 `MegaCli` (`/usr/ports/sysutils/linux-megacli`) 管理 `mfi(4)` 阵列，并使用 `aac` (`/usr/ports/sysutils/aacd`) 管理 `aac(4)` 阵列。GEOM 为 `twe(4)` 和 `twa(4)` 控制器提供了管理软件，Areca 为 `arcmsr` 提供了管理程序。

### GEOM RAID 和磁盘大小

对于任何 RAID 系统，你所有的驱动器必须大小相同——或者至少，你必须在每个驱动器上使用相同的空间。如果你有一个由 10 块 500GB 驱动器组成的 RAID 阵列，但其中一个驱动器故障你将其替换为 700GB 的驱动器，你只能使用其中的 500GB。你无法在不影响整个阵列性能的情况下使用该块大容量磁盘剩余的 200GB。

我们将假设用于 RAID 的磁盘或切片大小都是相同的。如果你有多个驱动器，请检查 `disk(8)` 以确认它们的大小是否相同。如果某些驱动器的大小略有不同，即使只差几百扇区，GEOM 也会使用最小磁盘的大小作为限制。

从技术上讲，你不需要在存储卷上拥有切片表。你可以在原始磁盘上运行镜像或条带——这对 GEOM 来说是一样的。我们的示例没有在磁盘上使用切片表。

### 校验位与条带大小

许多 RAID 类型使用校验位进行错误检测。校验位仅仅是一种非常简单的校验和，用于确保数据正确复制。RAID 系统使用校验位进行错误检测，以便它可以确定磁盘某区域的正确状态。这使得阵列具备提供冗余的能力。使用校验位的 RAID 系统通常需要留出磁盘空间给校验，但大多数此类系统都会透明地配置校验阵列。

同样，在多个驱动器之间分配数据的 RAID 级别使用不同的条带大小。条带大小是写入单个驱动器上的文件块的大小。例如，如果你有一个 512KB 的文件且条带大小为 128KB，该文件将以分散在你的磁盘上的四个条带的形式写入。你会看到论文和参考文献声称由于这个原因，较大的条带大小更好。这些观点对于特定的工作负载可能是正确的。如果你真的想实验条带大小，尽管去尝试。

### RAID 类型

RAID 有几种种类。最著名的是支持 RAID-0、RAID-1 和 RAID-5。然而，还有其他类型。

- **RAID-0**（即条带化），并不真正冗余，也不提供可靠性优势。它至少需要两个磁盘来将多个硬盘组合成单一虚拟磁盘，但任何一个驱动器的故障都会导致所有数据丢失。RAID-0 阵列的大小是所有驱动器的大小总和。
- **RAID-1**（即镜像），将一个磁盘的内容复制到另一个磁盘。这是实现低成本可靠性的极佳方法。如果你在所有磁盘上使用镜像，它能为你提供某种程度的数据保护。RAID-1 阵列的大小是最小磁盘的大小。
- **RAID-3**（即带有专用校验磁盘的条带化），一个备用硬盘用于维护跨越剩余硬盘条带化数据的校验和完整性数据。这意味着任何硬盘的故障都不会导致数据丢失。使用 RAID-3 需要奇数数量的磁盘——至少三个。对于某些应用程序，专用校验驱动提供了更高的吞吐量，但它一次只能处理一个 IO 请求。RAID-3 阵列的大小是所有其中一个驱动器的大小总和（即 (N-1) * 单盘容量）。
- **RAID-5**（即所有磁盘共享校验位），是目前的冗余行业标准。与 RAID-3 类似，它使用校验位提供数据冗余；单个驱动器的故障不会破坏任何数据。与 RAID-3 不同，校验空间分布在所有驱动器上。吞吐量极佳，并且它可以同时处理多个 IO 请求。你的 RAID-5 大小是所有其中一个驱动器的大小总和（即 (N-1) * 单盘容量）。

**RAID 0+1** 是条带化磁盘的镜像。你需要数量为 2 的倍数的磁盘，最少需要 4 块。先建立一个 RAID 0 磁盘阵列，以便获得一个巨大的磁盘区域。然后，将整个阵列镜像到一组硬盘上。RAID 0+1 阵列的大小是半硬盘的总容量，与 RAID-1 相同。RAID 0+1 不像 RAID 10 那样具有容错性，因此很少使用。我们不会讨论它。

**RAID-10** 是镜像磁盘的条带化。你需要数量为 2 的倍数的磁盘，最少需要 4 块，并且（为了完全冗余）需要两个独立的控制器。磁盘成对组成镜像，然后数据跨这些镜像进行条带化处理。由于系统不需要计算校验位，这是你能找到的性能最好的高可用磁盘系统。阵列的大小是半硬盘的总容量。

GEOM 可以提供所有这些 RAID 类型，而且是以软件形式实现的。

## 通用 GEOM 命令

大多数与 GEOM 相关的命令（例如 `gstripe(8)`、`raid3(8)` 等）支持一组常用的子命令，用于评估和控制各种 GEOM 操作。虽然你可以通过 `geom(8)` 使用这些命令，但我发现使用特定模块的命令（如 `gstripe(8)`）更直观。例如，`status` 子命令显示特定 GEOM 子系统的状态。可以通过运行 `raid3 status` 来询问 GEOM 我所有 RAID-3 设备的状态。我觉得使用 `raid3(8)` 并输入 `raid3 status` 会更简单。在本章的示例中我们将一直使用后一种。几乎每个 GEOM 模块都有四个命令：`load`、`unload`、`list` 和 `status`。

`load` 命令激活该类的内核模块。例如，`gstripe load` 将 `geom_stripe.ko` 加载到内核。同样，`unload` 命令从内核中移除模块。

`status` 命令打印该类型设备的状态。例如，在这里我们看到邮件服务器上 GEOM 镜像磁盘组的状态：

```
# gmirror status
Name      Status  Components
mirror/gm0 COMPLETE ad1
                        ad2
```

此输出的格式会根据设备对应的 GEOM 模块而异。

最后，`list` 命令列出模块的所有消费者，或该模块的底层设备。第一个命令通常是“关于此模块的其他有趣内容，无法放在其他三个命令中”的同义词，例如调试输出。例如，这里是来自 `raid3` 设备的 `list` 输出片段：

```
# raid3 list
geom name: MyRaid3
State: COMPLETE
Components: 3
Flags: ROUND-ROBIN
...
Providers:
  1. Name: raid3/MyRaid3
     Mediasize: 18210036736 (17G)
     Sectors: 1024
     Mode: riwe
Consumers:
  1. Name: dao
```

这台特定的服务器有一个名为 MyRaid3 的 raid3 设备。我们看到了一些适用于大多数基于 GEOM 设备的通用信息。该设备状态为 COMPLETE（意味着设备中的所有磁盘都存在、运行正常且最新），并且有三个消费者。然后我们进入 raid3 特有的调试信息。

在 `Providers` 标题下，我们看到由此 GEOM 类提供的设备列表。这台服务器在 `/dev/raid3/MyRaid3` 下提供 RAID-3 设备。我们可以看到设备的大小、块大小和其他有用信息。我们还有 `Consumers` 部分，它列出了 GEOM 设备中的所有底层磁盘。在这里，你不仅可以找到关于磁盘本身的信息，还能找到磁盘与 GEOM 模块交互的信息。

这些命令构成了提供软件磁盘虚拟化的各种 GEOM 模块的接口。

## 条带化磁盘

FreeBSD 使用 `gstripe(8)` 配置和管理磁盘条带。这允许你从两个或多个更小的磁盘创建一个虚拟磁盘。条带的优势是硬盘之间共享事务，理论上可以将吞吐量按阵列中磁盘的数量成倍增加（现实很少模仿理论的！）。

例如，我正在使用三块硬盘 `/dev/da0`、`/dev/da1` 和 `/dev/da2`。每个磁盘有一个切片，该切片上只有一个分区 (d)。虽然你可以在每次需要时使用手动方法配置条带化驱动，但我假设你已经条带化了驱动以便自动启动。

首先，通过 `gstripe load` 加载 `geom_stripe` 内核模块。你可以在 `/boot/loader.conf` 中指定 `geom_stripe_load="YES"` 在启动时加载条带化。

### 创建条带提供者

现在磁盘位于条带化提供者中了。下面，我们创建一个名为 MyStripe 的条带。该条带包含三块硬盘。使用 `-s` 标志设置条带大小为 131,072 字节或 128KB。`-v` 标志告诉 `gstripe(8)` 输出更详细：

```
# gstripe label -v -s 131072 MyStripe /dev/da0 /dev/da1 /dev/da2
Metadata value stored on /dev/da0.
Metadata value stored on /dev/da1.
warning: /dev/da2: 91050866 bytes.
```
