
#### 报告工作流程配置

这些配置文件位于 `/usr/share/libreport/workflows`。

每个文件都具有以下 DTD 的 XML 格式：

```xml
<!ELEMENT workflow (name+,description+, priority?, events*)>
<!ELEMENT name (#PCDATA)>
<!ATTLIST name x:lang CDATA #IMPLIED>
<!ELEMENT description (#PCDATA)>
<!ATTLIST description x:lang CDATA #IMPLIED>
<!ELEMENT priority (#PCDATA)>
<!ELEMENT events (event)+>
<!ELEMENT event (#PCDATA)>
```

- `name`

  用户可见的名称

- `description`

  用户可见的描述

- `priority`

  工作流程的优先级。数字越大，在 UI 中越显眼。如果未提供，则使用 0。该值是带符号的整数。

- `events`

  执行的事件列表

- `event`

  事件名称。如果该事件不适用于问题数据或未定义，则进程将继续执行下一个同级事件。

### 示例

#### 简单的报告工作流程

```xml
<workflow>
  <name x:lang="en">Example</name>
  <name x:lang="cs">Příklad</name>
  <description x:lang="en">Example description</description>
  <description x:lang="cs">Příklad popisu</description>
  <priority>10</priority>
  <events>
    <event>analyze_example</event>
    <event>collect_example</event>
    <event>report_example</event>
  </events>
</workflow>
```

### REPORTER-BUGZILLA

### 名称

`reporter-bugzilla` - 将问题报告到 Bugzilla。

### 概要

```
reporter-bugzilla [-vbf] [-g GROUP]... [-c CONFFILE]... [-F FMTFILE] [-A FMTFILE2] -d DIR

Or:

reporter-bugzilla [-v] [-c CONFFILE]... [-d DIR] -t[ID] FILE...

Or:

reporter-bugzilla [-v] [-c CONFFILE]... [-d DIR] -t[ID] -w

Or:

reporter-bugzilla [-v] [-c CONFFILE]... -h DUPHASH [-p[PRODUCT]]
```

### 描述

该工具读取问题目录 `DIR`。然后登录到 Bugzilla 并尝试在 Whiteboard 中找到具有相同 `abrt_hash:HEXSTRING` 的 bug。

如果未找到此类 bug，则创建一个新的 bug。`DIR` 的元素根据类型和大小，作为 bug 描述的一部分或附件存储在 bug 中。

否则，如果找到此类 bug 且其标记为 CLOSED DUPLICATE，该工具会沿重复链追踪直到找到一个非 DUPLICATE 的 bug。该工具会向找到的 bug 添加新评论。

新创建或修改的 bug 的 URL 会打印到标准输出并记录在 `DIR` 中的 `reported_to` 元素中。

选项 `-t` 将 `FILES` 上传到 Bugzilla 站点上已创建的 bug。bug ID 从由 `-d DIR` 指定的目录中获取。如果 `DIR` 中的问题数据从未报告给 Bugzilla，则上传将失败。

选项 `-tID` 将 `FILES` 上传到 Bugzilla 站点上具有指定 ID 的 bug。`-d DIR` 将被忽略。

选项 `-w` 将 bugzilla 用户添加到 bug 的 CC 列表中。

选项 `-r` 将 `reporter_to` 元素中以 `TRACKER_NAME` 为前缀的最后一个 URL 设置到 URL 字段。此选项仅在新 bug 将要提交时应用。默认值为 "ABRT Server"

#### 配置文件

如果未指定，`CONFFILE` 默认为 `/etc/libreport/plugins/bugzilla.conf`。配置文件行应采用 `PARAM = VALUE` 格式。参数包括：

- `Login`

  登录到 Bugzilla 账户。

- `Password`

  Bugzilla 账户密码。

- `BugzillaURL`

  Bugzilla HTTP(S) 地址。(默认: https://bugzilla.redhat.com)

- `SSLVerify`

  使用 yes/true/on/1 来验证服务器的 SSL 证书。(默认: yes)

- `Product`

  产品 bug 字段值。如果您需要与 `/etc/os-release` 中指定的不同的产品，则很有用

- `ProductVersion`

  版本 bug 字段值。如果您需要与 `/etc/os-release` 中指定的不同的产品版本，则很有用

可以通过 `$Bugzilla_PARAM` 环境变量覆盖参数。

#### 格式化配置文件

以 `#` 开头的行会被忽略。

行可以使用行尾反斜杠在下一行继续。

格式：

```
"%$summary
summary format"
"section
element[1,element2]..."
```

要添加到 Bugzilla 评论中的字面文本行。可以为空。(空行 NOT 被忽略!)

摘要格式是一行文本，其中 `%element%` 会被替换为文本元素的内容，而 `[[...%element%...]]` 块仅在 `%element%` 存在时使用。`[[...]]` 块可以嵌套。

部分可以是：- `%$summary`：bug 摘要格式字符串。- `%attach`：要附加的元素列表。- 文本，双冒号 (`::`) 和逗号分隔的元素列表。

元素可以是：- 问题目录元素名称，它们会被格式化为 `<element_name>: <contents>` 或 `<element_name>: ::<contents>` - 以 "bare_" 为前缀的问题目录元素名称，按原样格式化，不带 "<element_name>:" 和冒号 - `%oneline`, `%multiline`, `%text` 通配符，选择所有对应的元素用于输出或附件 - `%binary` 通配符，仅适用于 `%attach` 部分，指示附加二进制元素 - 以 "-" 为前缀的问题目录元素名称，从所有通配符中排除给定元素

不存在的元素会被静默忽略。如果没有任何元素存在，则不会创建该部分。

### 与 ABRT 事件的集成

`reporter-bugzilla` 可以作为 ABRT 报告器使用。`/etc/libreport/report_event.conf` 的示例片段：

```
### Report Python crashes
EVENT=report_Bugzilla
analyzer=Python
reporter-
```
