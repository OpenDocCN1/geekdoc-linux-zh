## 11.2. PLIP for Linux–2.0

PLIP device names are `plip0`, `plip1` and `plip2`.

### Kernel Compile Options:

```
Network device support --->
<*> PLIP (parallel port) support
```

`PLIP` (Parallel Line IP) is similar to `SLIP` in that they both provide point-to-point networking between two machines. However you can use the parallel printer port on your machine. It does not use the serial port. The wiring diagram is shown later in this article. Because the parallel port can transfer more than one bit at a time, higher speeds can be obtained using a PLIP interface. The speeds obtained with PLIP will be higher than those obtained with standard equipment. In addition, even the simplest parallel printer port can be used. The PLIP uses a lot of CPU to convert to a serial link. For example, if you can get some network cards, it is not a good choice. However, when all resources are available it will work. And it works quite well. When the link is running you should get about 20 kilobytes per second data transfer rate.

The PLIP driver competes with the parallel device driver for parallel port hardware. If you want to use both drivers you should compile them as modules. This ensures that you can choose which port to use for PLIP and which ports for the printer driver. Refer to the `Modules-HOWTO` for more information on kernel module configuration.

Please note that some laptops will not work with PLIP. These laptops do not support signal combining. PLIP relies on these signals but the printer does not.

The PLIP interface is compatible with the Cynwyr packet driver PLIP! This means you can connect a Linux machine to a DOS machine running any other tcp/ip software via PLIP.

In the 2.0* series the kernel devices are mapped to i/o ports and IRQs as follows:

| device | i/o | IRQ |
|---|---|---|
| plip0 | 0x3bc | 5 |
| plip1 | 0x378 | 7 |
| plip2 | 0x278 | 2 |

If your ports do not match any of the above combinations you can change the IRQ of the port. Use the `ifconfig` command with the `irc` parameter to change the IRQ. If your ROM BIOS supports this option you can enable IRQ on your printer port. Alternatively you can specify the `io=` `irq=` options on the `insmod` line if you are using modules:

```
root# insmod plip.io io=0x288 irq=5
```

PLIP operation is controlled by two timeouts; their default values are probably okay in most cases. If you have a particularly slow machine you will probably need to increase them. When it comes to timers the increase is done on the other machine. A program called `plipconfig` allows you to change these timer settings without recompiling the kernel. This program is supplied with many Linux distributions.

To configure a PLIP interface you need to follow the following commands. Or add them to your initialization scripts:

```
/sbin/ifconfig plip localplip point remoteplip
/sbin/route add remoteplip plip
```

Here the port being used is at I/O address 0x378; `localplip` and `remoteplip` are the names or IP addresses used on the PLIP cable. I personally keep them in my `/etc/hosts` database:

```
# plip entries
192.168.3.1 localplip
192.168.3.2 remoteplip
```

The `pointpoint` parameter has the same meaning as SLIP. It specifies the address of the machine at the other end of the link.

In all respects you can trust a PLIP interface as much as a SLIP interface. However `dip` or `slatch` cannot be used.

Further information on PLIP can be obtained from the `PLIP mini-HOWTO`.

## 11.2.1. PLIP for Linux–2.2

During the development of the 2.1 kernel series support for parallel ports was changed to an improved setup.

### Kernel Compile Options:

```
General setup --->
[*] Parallel port support

Network device support --->
<--> PLIP (parallel port) support
```

The new code for PLIP behaves similarly to the old code. You can use the `ifconfig` and `route` commands as in the previous section. However due to the advanced parallel port support the initialization of the devices is different.

The ``first'' PLIP device is always called `plip0` where the first is the first device detected by the system. Similar to what happens with ethernet devices. The actual parallel port used is one of the available ports as shown in `/proc/parport`. For example if you have only one parallel port you will have only one directory called `/proc/parport`.

## 11.4.1. dip

`dip` is a smart program that can set up your serial port configuration.

## 11.4.2. slattach

`slattach` is a very simple program with no scripting ability compared to `dip`.

## 11.4.3. When do I use ?

You will use `dip` when your link to the server is a dial-up modem or temporary link. You will use `slattach` when you have a leased line possibly connecting your machine and server.

## 11.4.4. Static SLIP server with dial-up line and DIP

A static SLIP server is one where you are provided with an IP address that is yours alone. Each time you connect to the server you configure your SLIP port to use that address. The SLIP server will answer your modem call, possibly prompting for a username and password, and then route any packets. If you have a static server you may want to put your hostname and IP address into your `/etc/hosts` because you know what it is.
