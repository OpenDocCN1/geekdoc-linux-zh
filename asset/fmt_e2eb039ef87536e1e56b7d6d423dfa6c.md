
# Korn Shell 扩展特性

## 支持文件名
Korn 支持熟悉的替换字符（也称为通配符）`*`、`?` 和 `[...]`；使用这些字符时，它们将被替换为所有匹配的文件名。Korn 还支持额外的匹配模式，通用形式为 `* (expression)` 和 `[abbreviation]`，但你不会使用这些扩展。例如，如果你有三个文件 `time.x`、`time.y` 和 `time.z`，那么 `time*` 将匹配 `time.x` 和 `time.y` 这三个文件，而 `t[sam]` 将匹配 `time.x`。`* (expression)` 通配符原则上用于 `[...]`，新的通配符 `(expression)` 可以指定更长的模式。此外，通配符可以嵌入其中，所以你可能会得到一个类似于 `file[1-3]*.doc` 的通配符，它将匹配：`file1.doc`、`file1.txt`、`file2.doc`、`file2.txt`、`file03.doc`。完整列表太长无法在此显示，但你可以看到新的威力。

## 变量替换
Korn 支持变量替换形式 `$name`，以及特殊变量 `$$`、`$`、`-` 以及参数 `$0` 到 `$9`。支持具有其含义的特殊形式 `($name)` 和 `($text)`形式。此外，Korn 还支持 `($name[index])` 数组、`(...)` 替换等。这些扩展与 Bourne shell 不冲突，你也不需要使用它们。

## 提交命令
Bourne shell 的命令替换形式 `'command'` 在 Korn shell 中被完全支持，其语法和行为与 Bourne shell 相同。Korn 还支持变体语法 `$( ... )`，以简化命令替换的使用。

## 识别转义和引号
Korn shell 识别形式为 `"..."` 和 `'...'` 的引号字符串，它们具有相同的含义和效果。单个字符可以通过反斜杠 `\` 剥夺其含义；反斜杠会从命令行中移除，除非它出现在单引号内。对于标准的转义和引号技术没有扩展。

## 跨行扩展命令
使用反斜杠 `\` 将命令扩展到多行。反斜杠必须是该行的最后一个字符。反斜杠后紧跟换行符的组合会被识别并被简单地从命令输入中删除。这与 Bourne shell 的行为相同。

shell 的通用哲学是调用 Bourne shell 不允许合法的扩展和特殊特性。因此，任何在 Bourne shell 语法上正确的命令和 shell 都将被 Korn shell 解释。所有的 Korn 扩展都使用了在 Bourne 语言中未出现的语法形式。

特性并不由命令直接使用，因为命令历史和编辑是由 shell 选项控制的。要使用命令编辑，你首先发出命令 `set -o vi` 或 `emacs`。如果不这样做，Korn shell 的工作方式就像 Bourne shell 一样。另外注意，`set` 命令遵循通用哲学：`set -o` 在 Bourne shell 中无效并会产生语法错误。

Bourne shell 和 Korn shell 之间的兼容性几乎是完美的；Korn shell 的设计目标之一是能够执行为 Bourne shell 提供的 shell 脚本，而无需重写这些脚本或调用 Bourne shell 来运行它们。这一目标意味着，即使是 Bourne 行为中细微的特独之处也不能被忽视；Korn shell 的设计实现了所有所有这些特性。

这一切的目的是 Korn 9 中的所有内容都能在不受限制或保留的情况下很好地适用于 Korn shell。

# 通配符表达式 (Wildcard Expressions)

Bourne shell 支持多种用于缩写命令行引用文件名的语法形式。这些形式基于在单词中嵌入一个或多个特殊模式匹配字符的理念。该单词成为文件名的模板，并被所有匹配模板的文件名替换。Bourne shell 支持的模式匹配字符是 `*` 和括号表达式 `[..]`。

Korn shell 支持这些模式匹配字符，以及一种使用该字符缩短模式的扩展以及扩展模式匹配表达式 `*`、`( )`、`+`、`?` 和 `!`。模式匹配表达式的语法基于对单词中未加引号括号 `()` 的识别。在 Bourne 和 Korn shell 中，括号对 shell 都是特殊的；它们必须加引号以避免它们的特殊含义。Bourne shell 给像 `here+(with)` 这样的单词没有特殊含义，但它会对括号报错。因此，包含嵌入括号的单词不会出现在 Bourne shell 中。因此，Korn shell 使用这种语法来扩展通配符模式匹配，而不影响对 Bourne shell 的兼容性。

## 波浪号扩展 (Tilde Expansion)
以 `~`（波浪号）开头的会被 Korn shell 特殊处理。为了避免其特殊含义，你必须对波浪号加引号。除第一个位置外，任何位置都正常处理。波浪号只有在作为单词的第一个字符时才具有特殊含义。

表 11.1 列出了波浪号扩展的四种样式。

### 表 11.1. 波浪号扩展样式。

| 样式 | 描述 | 示例 |
|---|---|---|
| ~ | 单独使用或后跟斜杠 (`/`)，波浪号被替换为家目录的路径。这相当于编写 `$HOME` 或 `$HOME/...`。 | $ echo ~/usr/home/fran; $ echo ~/bin ~/usr/home/fran/bin |
| ~string | 波浪号后跟一个字母数字字符串将被替换为命名用户的家目录。如果 `/etc/passwd` 文件中不存在该字符串条目，则报错。 | $ echo ~bill ~/usr/home/bill |
| + | 波浪号后跟加号将被替换为当前目录的全路径。这相当于编写 `$PWD` 或 `$PWD/....`。 | $ pwd ~/usr/lib; $ echo ~bin ~/usr/lib/bin |
波号后面紧跟一个减号会被替换为上一个目录的完整路径。这与编写 $OLDPWD 或 $OLDPWD/... 是一样的。

```bash
$ pwd
/usr/lib
$ cd ~lib
/usr/home/fran
$ echo ~/bin
/usr/lib/bin
```

如你所见，波号简写是一个非常方便的方法。

# 模式表达式

模式表达式是指任何由普通字符和一个或多个模式匹配字符组成的单词。模式匹配字符包括 Bourne shell 中熟悉的 `*`、`?` 和 `[...]`，以及表 11.2 所示的任何扩展模式匹配表达式。

### 表 11.2. 扩展模式匹配表达式。

| 表达式 | 描述 |
| --- | --- |
| * (pattern|pattern...) | 匹配指定模式的一次或多次出现。例如，`time*(x.y)` 匹配文件名 `time.x`、`time.y`、`time.x.y`、`time.y-time.x` 和 `time.y.x`，但不匹配文件名 `z.y`。 |
| + (pattern|pattern...) | 匹配指定模式的一次或多次出现。例如，`time+(x|y)` 匹配 `time.x`、`time.x.y` 等，但不匹配其他内容。 |
| ? (pattern|pattern...) | 匹配模式中的任意一个。与 `*pattern` 不同，它不会将模式连接或重复到文件上。例如，`time?(x|y)` 仅匹配 `time.x` 和 `time.y`，但不匹配 `time.x.x`。 |
| @ (pattern|pattern...) | 恰好匹配模式的一次。例如，`time@(x|y)` 匹配 `time.x` 或 `time.y`，但不匹配 `time`、`time.x.x` 或 `time.y`。 |
| ! (pattern|pattern...) | 与 `*` 相同，区别是不考虑符合指定模式的字符串。例如，`time!(x|y)` 匹配 `time.x`、`time.x.y`、`time.0` 以及除 `time.x` 和 `time.y` 之外的所有内容。 |

> 警告：你会注意到 `* (pattern|pattern...)` 和 `+ (pattern|pattern...)` 会匹配指定模式的任何组合。这既有用也可能很危险。如果不确定，请使用 `echo` 来查看模式将匹配哪些文件。如果你不小心删除了系统配置，你将变得不受欢迎！

模式表达式的定义是递归的。每个形式都包含一个或多个字符串。这意味着嵌套模式表达式是合法的。例如，`time'([cho].sh)` 它在模式内部包含模式 `[cho]`，这导致它可以匹配 `time.sh`、`time.c.time.h`、`time.o`、`time.c`、`time.c.` 等。模式 `*(.sh|obj)` 匹配文件名 `filename.shobject`。

扩展模式表达式的主要价值在于允许你选择文件的集，而无需在命令行中显式列出每个文件。模式表达式在 shell 进行模式匹配的其他上下文中也是合法的，例如 `case` 语句。

# 命令替换

Korn shell 提供的另一个注意的增强是更方便的命令替换语法。记得第 10 章“The Bourne Again Shell”中提到的，用反引号（反 `command` ）引用的字符串会被命令的标准输出替换。然而，反引号表示并不容易使用。Korn shell 在支持标准 Bourne shell 反引号表示的基础上，还支持以下替代形式：

```bash
$(command-list)
```

其中 `command-list` 是任何有效的命令列表。在最简单的形式中，括号形式避免了在打印的列表中识别命令的问题，但同时也充当了引号或大括号的形式。你可以在括号内使用所有标准的引号形式，而无需使用反斜杠来转义引号。此外，在括号形式中，你可以轻松地在 `$()` 表达式内部使用 `$()` 表达式。

例如，'ls' 可以被替换为 `$(ls)`。同样，'ls,who' 可以被替换为 `$(ls,who)`。

# 改进的 cd 命令

对于目录移动，Korn shell 支持 `cd` 命令的两种新形式：

```bash
cd -
cd oldname newname
```

`cd -` 命令特别有用。它可以切换回上一次执行 `cd` 命令所在的目录。这使得你可以临时切换到任何目录，然后通过输入 `cd -` 回到工作目录。`PWD` 和 `OLDPWD` 变量分别维护当前目录和上一个目录的完整路径。你可以使用这些变量来编写命令，引用目录中的文件，而无需输入完整路径。

你可以使用 `cd oldname newname` 命令来更改当前目录的一个组件。这使得以后在目录结构中的移动变得稍微容易。假设你的当前目录是 `/usr/prod/bin`，你想切换到目录 `/usr/test/bin`。只需输入命令 `cd prod test`。同样，命令 `cd usr jjv` 从 `/usr/prod/bin` 切换到 `/jjv/prod/bin`（假设后者目录存在）。

## 定义别名

Korn shell 的命令别名功能无疑是其相对于 Bourne shell 最具吸引力且灵活的增强之一。这是一个你会立即开始使用的增强。

当你定义一个别名时，你指定了一个简写术来表示命令。当你输入简写术时，它在命令执行期间会被替换为它所代表的字符串。命令不仅仅是一个命令；它还可以定义命令选项和参数。

你可能有一个或多个首选的列目录方式，例如：

```bash
alias ls='ls -l'
```

`alias` 命令是 shell置置，意味着它只在运行 shell 时可用。`alias` 的通用语法遵循：

```bash
alias [ -tx ] name=value [name=<value>]...
```

要使用上一个示例中 `lx` 命令别名，请将其作为一个新的命令名使用，如下例所示：

```
$ lx
```

这本身会以整齐的列格式列出当前目录下的所有文件，并进行排序以便检查。要列出当前目录以外的目录，请使用此命令：

```
$ lx /usr/bin
```

替换后，shell 会看到命令 `ls -FC /usr/bin`。

在别名中指定命令选项的能力非常有帮助。更好的是，当你使用别名时，你通常会扩展或更改指定的命令选项。假设你想在列出 `/usr/bin` 时添加命令选项 `-a`，以便你能够看到目录中的隐藏文件（dot files）。你可能认为你必须输入完整的命令，因为 `lx` 别名没有包含 `-a` 选项字母。事实并非如此。以下命令运行得很好：

```
$ lx -a /usr/bin
```

当 shell 执行此命令时，它会立即将 `lx` 替换为别名的值字符串，获得以下内部形式：

```
$ ls -a /usr/bin
```

`ls` 命令像大多数 UNIX 命令一样，习惯于多种方式指定的命令选项。实际上，`-a` 选项已添加到别名自动提供的 `-FC` 选项中。

## 编写别名定义

我最喜欢的别名之一是针对 `pg` 命令的这一个：

```
$ alias=`usr/bin/pg -cns -p"Page %d:"
```

`pg` 别名在许多方面都具有启发性。让我们详细查看它。

首先，注意别名名称是 `pg`。这与 `pg` 本身相同，因此实际上，别名隐藏了 `pg` 命令。你可以通过使用显式的路径名调用 `/usr/bin/pg` 来调用真实的 UNIX `pg` 命令，而不是通过短命令 `pg`（后者会调用别名）。

为别名选择与真实命令名相同的名称是不寻常的。它意味着你永远不想直接带选项执行真实命令，而是想带别名中指定的选项来执行。

由于我的工作方式，`-c`、`-n`、`-s` 和 `-p` 选项应该是内置在 `pg` 命令中的；我总是想使用它们。`-c` 选项在显示新页面时清空屏幕。在视频终端上，这比滚动行更自然、更快。`-n` 选项允许 `pg` 立即执行命令而无需等待按下回车键。所有命令只包含一行。不使用 `-n` 选项的唯一理由是避免为按键产生终端中断导致的性能下降，而 `-n` 选项需要这种操作。然而，单用户工作站和现代高性能计算机不需要额外的额外负荷。除非你正在老旧的 PDP-11 上工作，否则请尽管使用 `-n` 选项来增加便利性。`-e` 选项以高亮模式（通常是反色视频）显示消息，例如当前页码，这使得显示器的非文本部分更容易被注意到。

`-p` 选项导致 `pg` 命令在每个屏幕的底部显示页码。我需要页码，因为它能让我大致了解自己在命令行中的位置。默认情况下，页码以纯数字形式显示，与命令行的其余部分一起。然而，`pg` 命令允许你为页码提供格式，`-p"Page %d:"`：它用单词“Page”标识页码，并提供一个冒号（:)来将数字与命令行隔开。

由于页码格式包含对 shell 来说特殊的字符（特别是一个嵌入的空格），它必须包含在引号中。`alias` 命令要求整个别名必须在引号中定义。因此，我需要在引号内嵌套引号。

如果你理解了第 9 章关于引号的讨论，你还会意识到至少有三种方法编写 `pg` 别名：

```
$ alias pg="/usr/bin/ls -fns -p"Page %d"
$ alias pg="/usr/bin/ls -fns -P'Page %d"
$ alias pg="/usr/bin/ls -fns -p\Page %d"
```

第一种形式是我为示例选择的形式。第二种形式在双引号字符串内嵌入了单引号字符串；它的效果同样良好。第三种形式使用转义字符在双引号字符串内嵌入双引号。在这种情况下，shell 在存储别名之前会剥离反斜杠。我避免这种形式，因为除非必要，否则我不喜欢使用转义序列。转义是一个两个字符序列，第一个字符是反斜杠 (\ )。第二个字符是被转义的字符，这意味着 shell 不尝试以任何方式解释该字符，而将其视为本身。

这里的点是，除非别名值是单个单词，否则别名定义必须包含在引号中。因此，你需要在引号字符串内嵌入引用字符串。你应该意识到这种需求可能会出现。准备好通过确保你理解 shell 引号机制如何工作来处理它。

> 警告：如果你掌握了 shell 引号语法的运作原理，这会让很多其他人将你标为 UNIX 大师。所以请留心。

## 使用导出的别名

`alias` 命令支持许多选项，包括 `-x` (导出) 和 `-t` (跟踪)。

导出的别名与导出变量的概念相同。它的值会被传递到你调用的脚本中。

导出别名可能有用也可能有害。例如，导出之前显示的 `pg` 别名是有帮助的，因为它可以供脚本（许多 UNIX 命令是用脚本实现的）所调用的 pg 命令。另一方面，如果你为 `rm` 命令定义了一个别名，在删除文件前总是提示用户，你可能会被系统脚本删除你从未听过的临时文件的请求。

使用命令 `alias -x` 显示仅导出的命令别名。当以 `alias -x name` 形式使用时，别名名称将被重新定义为导出；它应该已经被定义过。要定义新的导出别名，请使用完整形式

```
alias -x name=value
```

## 使用跟踪别名

默认情况下，Korn 会自动为你从键盘输入的许多命令创建跟踪别名。此功能有助于提高性能。当别名被跟踪时，Korn shell 会记住命令所在的目录。因此，随后的调用将不再在 PATH 列表中搜索命令。本质上，命令的别名被设置为完整路径名。
