## 使用 MB 空闲空间并带有异常

为了给 `fs_mon_MBFREE.ksh` 脚本添加异常能力，我们需要一个函数来对 `$EXCEPTIONS` 文件进行搜索（如果它存在）。这将允许一些额外操作。我们还需要在数据中测试字符 `KB`，因此我们需要删除异常文件中的所有行。使用该函数最简单的方法是向调用脚本返回一个适当的返回码。如果发现挂载点在 `$DATA_EXCEPTIONS` 文件中超出限制，我们将设置函数返回 1（one）。如果 `/mount_point` 在异常数据文件中但未超出限制，它将返回 2。如果在异常数据文件中未找到该挂载点，该函数将返回 3。这将允许我们调用函数来检查异常文件，并根据结果在脚本的主体中做出决定。

我们已经修改了脚本以添加异常能力，这应该是件轻而易举的事，对吧？当我们完成时，异常处理将将变得直而易见。

由于我们要解析异常文件，因此需要运行一次健全性检查（sanity check），看看是否有人输入了错误的条目并在文件中放置了冒号 `,`，意图是覆盖 NFS 挂载文件系统的限制。这种错误本不应该发生，但在某个测试人员这样做之后，我现在会检查并尽可能纠正错误。我们只需使用冒号 `,` 作为分隔符来 `cut` 第二字段。列表 5.9 显示了修改后的 `check_exceptions` 函数。特别注意高亮部分。

```
function check_exceptions

{

# set -x # 取消此注释以调试此函数

while read FSNAME FSLIMIT

do

  # 对 NFS 进行健全性检查

  echo $FSNAME | grep ":" >/dev/null 2>&1 | cut -d ":" -f2

  FSNAME=$(echo $FSNAME)

  # 确保我们没有空值

  if [ ! -z "$FSLIMIT" && "$FSLIMIT" != '' ];

  then

    (( FSLIMIT = $(echo $FSLIMIT | sed s/\//g) * 1024 ))

    if (( $FSNAME=$FSMOUNT ));

    then

      # 去掉存在的 "MB"

      FSLIMIT=$(echo $FSLIMIT | sed s/\//g)

      if (( $FSM_FREE < FSLIMIT ));

      then

        return 1 # 发现超出限制

      else

        return 2 # 发现正常

      fi

    fi

  fi

done < $DATA_EXCEPTIONS # 从底部向循环输入！！！

return 3 # 在 $EXCEPTIONS 文件未找到
```

**列表 5.9** 新的 `check_exceptions` 函数。

在此函数中需要注意的几点是 NFS 和空值的健全性检查，以及我们从 `done` 语句之后的底部开始向 `while` 循环提供数据。首先，健全性检查非常重要，可以防止异常文件中出现错误的 NFS 条目、空行或空数据。对于 NFS 冒号，我们使用双与符号 `&&`，类似于 `if...then` 语句。它的工作原理相同，但在这种测试中更整洁。另一个是空值检查。我们检查长度为零的变量和空数据。双符号 `&&` 被称为逻辑与（AND）函数，`||` 被称为逻辑或（OR）函数。在逻辑与 `&&` 中，所有语句必须为真，整个语句的返回码才为 0。在逻辑或 `|` 中，至少有一个语句必须为真，返回码才为 0。当逻辑或在测试列表中接收到第一个真时，它将立即退出测试（或命令语句），并返回码 0。
