# 第 8 章通过代码库共享函数

到目前，你应该已经意识到，即使对于简单的任务，计算机也必须完成大量工作。正如此，为了编写让计算机执行简单任务的代码，你必须做大量工作。此外，编程任务通常并不简单。因此，我们需要一种方法让这个过程变得更容易。方法有：

- 使用高级语言而不是汇编语言编写代码
- 拥有大量预编写的代码，可以剪粘贴到你自己的程序中
- 系统有一组函数，可以在任何想要使用它的程序之间共享

这三种方法在任何给项目中通常都会在某种程度上使用。第一种方案将在第 11 章中进一步探讨。第二种方案很有用，但也有一些缺点，包括：

- 复制的代码通常需要大幅修改以适应周围的代码。
- 每个包含复制代码的程序都有相同的代码，浪费了大量空间。
 如果 如果在任何复制的代码中发现 bug，必须在每个应用程序中进行修复。

因此，第二种方案通常用得很少。它通常只在复制并粘贴特定类型任务的骨架代码并添加程序特定细节的情况下才使用。第三种方案是最常用的。第三种方案包括拥有一个共享代码的中央仓库。这样，每个程序就不需要浪费空间存储相同的函数副本，它们只需指向包含其所需函数的共享库。如果在这些函数中的某一个发现 bug，只需要在单个函数库文件中修复，所有使用它的应用程序都会自动更新。这种方法的主要缺点是它产生了一些依赖问题，包括：

- 如果多个应用程序都在使用该共享文件，我们如何知道删除该文件是安全的？
- 某些程序无意中依赖共享函数。因此，如果升级共享程序修复了 bug，应用程序可能会停止运行。这些问题被称为“DLL 地狱”。然而，通常认为优点大于缺点。

这并不长。然而，看一看使用库的 `helloworld-lib` 有多短：

```assembly
#目的：此程序写入 "hello world" 并
### 退出
#
.section .data
helloworld:
```

现在，构建使用共享库的程序与通常有所不同。你可以通过以下方式正常构建第一个程序：

```bash
as helloworld-nolib.s -o helloworld-nolib.o
ld helloworld-nolib.o -o helloworld-nolib
```

然而，为了构建第二个程序，你必须这样做：

```bash
as helloworld-lib.s -o helloworld-lib.o
ld -dynamic-linker /lib/ld-linux.so.2 \
    -o helloworld-lib helloworld-lib.o -lc
```
