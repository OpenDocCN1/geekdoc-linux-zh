
# 缓冲区溢出

`http://www.robertaham.com/pubs/test/username=robot` 懒惰的程序员永远不会提交超过 10 个字符的内容，并编写如果用户提交此类内容就会崩溃的代码。作为一个黑客，你只需到屏幕顶部编辑 URL 使其看起来像这样，可能会导致系统崩溃或允许你绕过密码代码。一种经典攻击是输入过多的数据。多余的数据“溢出”到内存的其他区域，经常允许攻击通过输入插入可执行代码。这使得攻击者能够侵入计算机。缓冲区溢出是最常见的编程错误之一，也是最容易通过质量保证测试的错误。因此，它们是破坏计算机最常见的方法之一。

类比：考虑两种浴室池设计。一种是带有排水口的简单水池。另一种在顶部附近有一个备用排水口。第一种设计简单且通常有效，但面临排水口被堵住的问题。第二种设计防止了水池溢出，因为水位永远无法超过顶部。

程序员忘记验证输入（他们）认为合法的用户名少于 32 个字符，并且没有对这一点进行验证。恶意黑客通过输入长 100 个字符的用户名来利用这一点。

关键点：这是一个影响所有系统的经典漏洞。互联网上的平均系统都受到已知的缓冲区溢出的威胁。许多服务器具有漏洞的服务，如 `cms`、`ToolTalk`，而许多 Linux 机器也具有存在漏洞的 `IMAP` 或 `FTP`。

关键点：用 C 或 C++ 编写的程序脆弱性较低。使用 Perl 和 Java 等脚本语言编写的程序通常是不易受攻击的。原因是 C 语言程序员处理长度，而脚本语言无论程序员是否意愿，通常都会进行这些检查。

关键点：缓冲区溢出通常会导致拒绝服务（DoS），因为它们会崩溃。然而，最有趣的溢出可以导致系统作为漏洞的一部分执行攻击者自己的代码。

字典：在 Java 等这种会对数组进行边界检查的编程语言中，有避免缓冲区溢出的方法。你可以运行特殊的编译器，将 x86 的 NOP（无操作）设为 `0x90`。缓冲区溢出长期存在，它们可能导致系统执行攻击者自己的代码作为漏洞的一部分。字典：在 Java 这种会对数组进行边界检查的编程语言中，有避免缓冲区溢出方法。你可以运行特殊的编译器，x86 的 NOP 是 `0x90`。缓冲区溢出可能导致系统崩溃。来自 Linux Guide @FirstLinux `http://www.ldp.org/Linux-Dictionary/index.html`

## bug-buddy

一个用于 GNOME 的图形化工具。`bug–buddy` 的目标是让报告对用户来说非常简单易用，并让报告对开发者更有用、信息更丰富。它可以从核心文件或崩溃的应用程序中（通过 `gnome_argv`）提取调试信息。目前支持 Gnome、Helix、KDE 和 Debian 的错误跟踪。来自 Debian 3.0r `http://www.tld.org/LDP/linux-Dictionary/index.html`

## BUGTAG

安全社区最重要的信息来源之一。`BUGTAG` 已成为发布漏洞和漏洞利用信息的准官方场所。争议：围绕“完全披露”的辩论影响着 BUGTAG。一方是一群认为公开漏洞和利用对于促进防御黑客措施的发展是必要的群体；另一方是一群认为完全披露（包括让“脚本小子”准备就绪）是有害的群体。来自黑客词汇 `http://www.tld.org/LDP/linux-Dictionary/index.html`
