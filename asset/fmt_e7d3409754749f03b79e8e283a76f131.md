
更改 `/etc/lilo.conf` 后，记得重新运行 `lilo` 命令。

还有图形界面工具可以配置 `lilo`。例如，以 `root` 身份在 `X` 终端尝试：

```

```

## 5.1.4 LILO 提示在启动过程中在屏幕上停留时间太短（或太长）

在 `/etc/lilo.conf` 文件中，第一个 `image=` 或 `append=` 之前添加或调整此行：

```
delay=10
```

（较新版本的 `lilo` 可能会使用 `timeout` 选项。）该数字是延迟时间（以秒为单位），因此在上面的示例中，延迟将为 10 秒。在修改 `/etc/lilo.conf` 文件后，不要忘记再次重启，否则你的更改不会生效。

## 5.1.5 卸载 Linux

如果你想“卸载”Linux，可以运行以下两个命令（在 `DOS` 或 `MS Windows` 环境下）：

```
lock C:
FDISK/MBR
```

将移除 LILO——它会覆盖 LILO 所在的第一块硬盘的主引导记录 (`MBR`)。`lock` 命令允许对磁盘进行“原始”写入，这在较新版本的 `DOS` 中通常作为反病毒措施是不被允许的。`FDISK/LOCK` 的问题在于它不报告任何成功或失败信息，因此最好使用 `lock` 命令启动。此后，你可以使用 `FDISK` 工具删除 Linux 分区以重新回收硬盘空间。此外，`FDISK` 不允许删除 Linux 分区。在这种情况下，我可能会使用 `fdisk`。最简单的方法是从 Linux 软盘/CD 启动，并在启动“安装”程序和 Linux 时删除分区。

## 5.2 访问我的硬盘

### 5.2.1 我的硬盘在哪里？

Linux 将所有目录显示在一个目录树中，无论它们位于什么驱动器/硬件上。通常，这比传统的 `DOS/Windows` 模型要好得多——它从底层硬件将文件系统完全抽象出来。如果你需要重新调整或更新硬件或网络资源，你会体会这一点。对于习惯于 DOS 处理硬盘方式的用户来说，这增加了一些额外的复杂性。

简而言之，不要寻找驱动器。Linux 下通常没有这种东西；你的磁盘内容显示为单个 Linux 文件系统（目录树）上的子目录。默认情况下，可移动介质的内容不会自动挂载到这些子目录中——你可能需要“挂载”它们。详情请参见后续答案。在进入介质之前也应该挂载硬盘。

你可以从 Linux 访问（读写）各种驱动器和文件系统。这包括原生 Linux 分区、DOS 和 MS 分区（在硬盘或软盘上）、`ZIP` 和 `JAZ` 驱动器以及 `CDROM`。还支持许多常见的文件系统。这意味着你可以使用 Windows 版的 `Netscape` 下载 Linux 软件，将下载的文件保存在你的 MS 硬盘分区上，启动 Linux 并下载的软件从硬盘上的 Windows 分区复制到 Linux 分区，最后在 Linux 下安装软件。

#### 5.2.3.3 DOS/Windows 分区

我在同一台电脑上使用了 Linux 和 Windows MS 的双系统。在通过以下命令挂载该分区后，我可以访问 DOS/Windows 分区上的文件：

```
mount -t vfat /dev/hdd1
```

再次，你可能需要根据你的 DOS 文件系统所在的分区来自定义命令。`sda1` 意味着第一个 IDE 驱动器 (`sda`) 的第一个分区 (`1`)；`hda2` 是第一个 IDE 驱动器的第二个分区；`sda3` ——第一个 IDE 硬盘的第三个分区；`hdb1` ——第二个 IDE 驱动器的第一个分区（如果 CD-ROM 安装在你的第一个 IDE 接口上，则只需 `hdb`）；`hdc` 是第三个 IDE 驱动器，由字母表示 SCSI 接口，后面的数字表示 SCSI 设备 ID。例如 `sda4` 表示“第一个 SCSI 接口，ID 号 4”。

为了挂载所有你可以可读可写的驱动器，你可能想要：

```
mount -t u -o rw,rw,exec,umask=000 /dev/sda1 /mnt/zipdrive
```

此选项 (`-o rw,rw,exec,umask=000`) 赋予所有人对你的 DOS/`/dev/sda1` 分区所有文件的权限（你应该询问这在你的系统上是否真的安全）。如果用户无法写入 DOS 分区，可能需要设置你挂载点的权限。此命令（由 `root` 执行）将设置挂载点 `/zipdrive` 的权限，以便所有用户都获得读取和执行权限：

```
chmod a+rw /mnt/zipdrive
```

## 5.2.4 网络文件系统 (NFS)

此用于直接访问位于另一台 Linux 电脑上的文件。要作为 NFS 挂载远程文件系统，请检查 NFS 服务是否启用（使用设置程序）。NFS 还需要来自电脑的权限。要配置服务器上的权限，请运行：

```
netconf
```

并调整“Exported File Systems”菜单下的设置。

如果你喜欢手动操作，权限设置在 `/etc/exports` 文件中。我的 `/etc/exports` 如下所示：

```
/usr hacker(rw) mars(rw)
/home hacker(rw) mars(rw)
/mnt hacker(rw) mars(rw)
```

这给了名为 `hacker` 和 `mars` 的用户挂载目录 `/`（只读）、`/home` 和 `/mnt` 的权限。

如果你正确设置了 NFS 分区，你应该能够使用如下命令挂载网络目录：

```
mount -t nfs mars:/home/mnt/mars 在一个名为 "mars" 的机器上挂载到 mnt/mars/home/ 目录（该目录必须存在且为空）。
```
