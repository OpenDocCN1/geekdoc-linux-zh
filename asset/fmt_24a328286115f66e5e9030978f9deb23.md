```python

import doctest
```

`nfail, tests = doctest.testmod(splitter)` 在指定的模块上运行测试，并返回失败次数和执行测试的总数。如果所有测试通过，则不产生任何输出。否则，你将得到一个失败报告，显示预期输出与接收输出之间的差异。如果你想查看测试的详细输出，可以使用 `doctest(module, verbose=True)`。

`t.assert(expr {, [msg]})`
`t.failUnless(expr [, [msg])`

`t.assertEqual(x, y, [msg])`
`t.failUnlessEqual(x, y, [msg])`

如果 `x` 和 `y` 不相等，则指示测试失败。`msg` 是一个解释失败的 own（如果有）。

`t.assertNotEqual(x, y, [msg])`
`t.failIfNotEqual(x, y, [msg])`

如果 `x` 和 `y` 相等，则指示测试失败。`msg` 是一个解释失败的 own（如果有）。

`t.assertAlmostEqual(x, y, [places, [msg]])`
`t.failUnlessAlmostEqual(x, y, [, places, [msg]])`

如果 `x` 和 `y` 之间不在指定的小位数范围内，则指示测试失败。这是通过计算 `x` 和 `y` 的差并将结果四舍五入到给定的位数来检查的。如果结果为零，则 `x` 和 `y` 几乎相等。`msg` 是一个解释失败的信息（如果有）。

`t.assertNotAlmostEqual(x, y, [, places, [msg]])`
`t.failIfNotAlmostEqual(x, y, [, places, [msg]])`

如果 `x` 和 `y` 之间的距离小于指定的小位数，则指示测试失败。`msg` 是一个解释失败的信息（如果有）。

`t.assertRaises(exc, callable, ...)`
`t.failUnlessRaises(exc, callable, ...)`

如果可调用对象没有抛出异常 `exc`，则指示测试失败。剩余参数将作为参数传递给 `callable`。可以使用异常元组作为 `exc` 来检查多个异常。

`t.failif(expr {, [msg]})`

如果 `expr` 求值为为 True，则指示测试失败。`msg` 是一个解释失败的信息（如果有）。

`t.fail([msg])`

指示测试失败。`msg` 是一个解释失败的信息（如果有）。

`t.failureException`

此属性被设置为测试中抛出的最后一个异常值。如果你不仅想检查是否抛出了异常，还想检查异常是否抛出了适当的值，这可能很有用——例如，你想检查作为异常一部分生成的错误消息。

# Python 调试器和 pdb 模块

Python 包含一个简单的基于命令调试器，位于 `pdb` 模块中。`pdb` 模块支持事后调试、堆栈跟踪检查、断点、源行单步执行和代码求值。

有几个函数可以从程序或交互式 Python 中调用调试器。

`run(statement, globals [, locals])`

在调试器控制下执行该语句。调试器提示符会在任何代码执行之前立即出现。输入 'continue' 将强制其运行。`globals` 和 `locals` 分别定义代码运行的全局和局部命名空间。

`runval(expression, globals [, locals])`

在调试器控制下评估表达式。调试器提示符会在任何代码执行之前出现，因此你需要输入 'continue' 来强制使用 `run()` 执行。如果成功，将返回表达式的值。

`runall(function, argument, ...)`

在调试器中调用函数。`function` 是一个可调用对象。额外的参数将作为参数传递给 `function`。调试器提示符会在任何代码执行之前出现。完成后返回函数的。

`set_trace()`

在此函数被调用的地方启动调试器。这可以用于在特定的代码位置硬编码调试器断点。

`post_mortem(traceback)`

对 `traceback` 对象启动事后调试。`traceback` 通常使用诸如 `sys.exc_info()` 等函数获取。

`pm()`

使用上一个异常的 `traceback` 进入事后调试。所有启动调试器的函数在实践中都是最易于使用的。如果你正在处理一个复杂的应用程序，但在其某部分检测到了问题，你可以在代码中插入 `set_trace()` 调用并直接运行应用程序。当遇到时，程序将挂起并直接进入调试器，你可以在那里检查环境。离开调试器后执行将恢复。
