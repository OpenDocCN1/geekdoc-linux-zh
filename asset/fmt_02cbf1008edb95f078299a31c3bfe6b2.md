
更改`blocks`和`inodes`列下的使用信息没有影响。这些列报告了用户实际消耗了多少块或多少inode。

你可以修改`blocks`和`inodes`的软限制（`soft`）和硬限制（`hard`）。硬限制是用户可以消耗的最大块或inode数量。内核不会允许用户超过硬限制。

软限制则没那么严格。用户可以临时超过软限制值，但当他们这样做时，系统会发出警告。软限制还与宽限（grace period）相互作用。如果超过软限制的时间超过宽限，内核将开始将其视为硬限制，并拒绝允许用户创建更多文件。

你可以通过带有`-t`选项的`edquota`来设置软限制宽限，例如`edquota -t`。宽限是基于文件系统的设置的，而不是基于用户的设置的。将时间设置为0（如前一个示例中的inode限制所示）将消除对该值的配额限制。这允许用户随心所欲地消耗磁盘空间或创建文件，只要不超过文件系统的可用空间。

在使用`edquota`时，你可以为每个启用了配额的文件系统独立调整配额，并为每个用户或组单独调整。要编辑组的配额，请使用`-g`选项，例如使用`edquota -g users`来调整用户组的配额。

一个实用的辅助命令是`repquota`，它可以汇总你指定的文件系统或在传递`-a`选项时汇总所有文件系统的配额信息。该工具对于跟踪磁盘使用情况非常有帮助。

`quota`命令具有类似的效果。`quota`工具接受多个选项来修改其输出。例如，`-g`显示组配额，`-l`显示NFS挂载点，`-q`将输出限制在用量超过限制的文件系统。咨询`quota`命令的man页面以获取更多晦门的选项。

## 定位文件

如果你无法找到自己的文件，那么保持文件系统的完美健康、设置权限等都是没有意义的。因此，Linux提供了几种工具来帮助你定位需要的文件。

这些工具中的第一个实际上是关于文件所在位置的标准；凭借正确的知识，你可能可以在使用任何特殊程序的情况下找到文件。第二类工具包括专用程序，它们在目录树或数据库中搜索符合你指定的任何标准的文件。

## 了解FHS

Linux的文件布局源于40多年前的Unix历史。鉴于这一事实，该结构非常简单且连贯，新管理员很容易感到困惑。某些目录表面上似乎承担着相似或相同的角色，但实际上存在细微但重要的区别。接下来的章节描述了Linux目录布局标准以及对内容存放在何处的概述。

## 比较FSSTND和FHS

尽管Linux很大程度上借鉴Unix，但Unix的悠久历史导致了许多分裂和变体，从伯克利标准发行（BSD）开始。BSD最初是AT&T原始Unix代码的一组补丁和扩展。由于Unix社区内部这些分裂，早期的Linux发行版并不总是遵循相同的模式。结果导致了大量的困惑。这个问题在Linux历史上相当严重，并威胁到Linux社区的分裂。人们采取了各种措施来应对这个问题，其中之一就是开发文件系统标准（FSSTND），它于1994年初首次发布。FSSTND标准了特定的特性，例如：

- 标准化了位于`/bin`和`/usr/bin`的程序。这些差异导致脚本引用其中一个或另一个位置的文件时出现问题。

- 规定可执行文件不应位于`/etc`中（以前这样做很常见）。

- 从`/usr`目录树中移可更改的文件，使其能够以只读挂载（一种实用的安全措施）。

![](img/f74c2c51e1985d4d3a6804ba2887d2f4_421_0.png)

`FHS`有带编号的版本，例如`v2.3`。尽管它更新不频繁，但检查`FHS`的修改是明智的。`FHS`官方网页的URL为`www.pathname.com/fhs/`。你可以在Linux Foundation网址`www.linuxfoundation.org`找到`FHS`修改工作组。

`FHS`提出的重要区别是可共享文件（shareable files）和不可共享文件（unshareable files）。可共享文件可以在计算机之间合理地共享，例如用户数据文件和程序二进制文件。（当然，你需要共享此类文件，但你可能这样做。）如果共享了文件，它们通常通过NFS服务器进行共享。不可共享文件包含系统特有的信息，例如配置文件。例如，你不太可能想在不同的计算机之间共享服务器的配置文件。

`FHS`使用的第二个重要区别是静态文件（static files）和可变文件（variable files）。前者除非通过系统的直接干预，否则不会更改。大多数程序可执行文件都是静态文件的示例。自动化脚本、服务器等等可能会产生可变文件。例如，用户的家目录和邮件队列由可变文件组成。`FHS`试图将每个目录隔离在这个`$2 \times 2$`（可共享/不可共享 × 静态/可变）矩阵的单元格中。图4.2阐了这些关系。某些目录是相似的，但在这些情况下，`FHS`试图指定特定子目录的状态。例如，`/var`是可变的，它包含一些可共享和不可共享的子目录，如图4.2所示。

| | 可共享 | 不可共享 |
| :--- | :--- | :--- |
| 静态 | `/usr` `/opt` | `/etc` `/boot` |
| 可变 | `/home` `/var/mail` | `/var/run` `/var/lock` |

# 学习重要目录及其内容

`FHS`对某些目录的定义非常精确，但其他目录的细节仍留待未决。例如，用户文件通常存放在`/home`目录，但你可能有理由将此目录命名为其他名称，或者使用两个或多个独立的目录来存放用户文件。总的来说，`FHS`定义或按惯例使用的目录如下：

`/`

每个Linux文件系统都追溯到一个单一目录，称为`/`（读音为root，通常称为根文件系统或根目录）。所有其他目录都从该目录派生出来。Linux不使用驱动器器。相反，每个文件系统都挂载在另一个分区内的挂载点（`/`或其他地方）。某些关键子目录（如`/etc`和`/sbin`）必须驻留在根分区上，但另一些目录可以位于单独的分区上。不要将根目录与稍后描述的`/root`目录混淆。

`/boot`

`/boot`目录包含与计算机启动相关的静态且不可共享的文件。较高层次的启动和配置文件位于另一个目录`/etc`中。在此目录中，你会找到`GRUB`或`LILO`配置文件以及初始启动所需的其他文件。通常，建议将`/boot`存储在单独的分区上。

`/etc`

`/etc`目录包含不可共享的静态系统配置文件。这些较高层次的启动和配置文件控制着系统上提供的程序和服务。例如，如果Linux发行版使用`systemd`系统初始化，某些`systemd`配置将存储在`/etc/systemd`目录下。如果Linux发行版使用`SysV`系统初始化，其配置文件则存储在`/etc`目录中。

`/bin`

此目录包含某些关键的可执行文件，如`ls`、`cp`和`mount`。这些命令供所有用户使用，构成了普通用户可能执行的最重要的命令。你通常不会在`/bin`中找到大型程序的命令。`/bin`目录包含静态文件。该目录几乎从不共享——任何潜在的客户端必须有自己的本地`/bin`目录。

# `/sbin`

此目录与`/bin`类似，但它包含了通常只由系统管理员运行的程序——如`fdisk`和`e2fsck`等工具。它是静态的，理论上是可以共享的，但在实践中共享它没有意义。

# `/lib`

此目录与`/bin`和`/sbin`类似，但它包含了程序库，这些代码被许多程序共享并存储在单独的文件中以节省磁盘空间内存。`libmodules`子目录包含内核模块——可以根据需要加载和卸载的驱动程序。对于`/lib`和`/sbin`，`lib`是静态的且理论上是可以共享的，尽管实践中并非如此。

# `/usr`

此目录托管了Linux计算机大部分程序。其内容是共享且静态的，因此它可以以只读方式挂载，并可能与其他Linux系统共享。由于这些原因，许多管理员会将`/usr`分离到单独的分区，尽管这样做并非强制。`/usr`的某些子目录与其根目录中的同名目录类似（如`/usr/bin`和`/usr/lib`），但它们包含的是对计算机基本运行并非绝对重要的程序和库。

# `/usr/local`

此目录包含镜像`/usr`结构的子目录，例如`/usr/local/bin`和`/usr/local/lib`。`/usr/local`目录托管系统管理员本地安装的文件——例如在目标计算机上编译的软件包。其理念是拥有一个区域，当操作系统整体升级时，该区域可以免受自动软件升级的影响。在安装Linux之后，`/usr/local`应该是空的，除了一些存根子目录。某些系统管理员会将此分离到自己的分区，以保护其免受可能删除父分区的OS重装程序的影响。

# `/usr/share/man`

此目录存储`man`命令使用的手册页。或者，任何本地手册页存储在`/usr/local/share/man`目录中。不同的子目录指定特定的手册页章节。例如，`/usr/share/man/1`和`/usr/local/share/man/man1`目录包含用户程序（第1节）手册页。
