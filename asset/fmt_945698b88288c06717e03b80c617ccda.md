
- `-display` 指定到 X 服务器的连接。

- `buf` 指定要返回的缓冲区。
- `nbytes` 指定缓冲区的大小。

你必须传回由 `_XAllocLocTemp()` 返回的相同指针和大小。

## 可移植性考虑

许多架构无法正确或高效地访问未对齐位置的数据；它们的编译器会进行填充以保持这一特性。许多其他能够处理未对齐引用的机器会在结构内部进行填充以保持对齐，因为访问对齐的数据要快得多。库和服务器使用结构来访问字节流中的任意点，请求和回复数据包中的所有数据必须是自然对齐的；即 16 位数据位于 16 位边界上，32 位数据位于 32 位边界上。所有请求的长度必须是 32 位倍数，以保持数据流中的自然对齐。结构可能会填充到 32 位边界。填充信息不一定需要清零，除非你想在未来的协议请求中保留此类字段，但建议将其清零，以避免无意的数据泄露并提高压缩率。浮点值在不同机器之间差异巨大，应尽可能完全避免。

此代码可能运行在具有 16 位整数的机器上。因此，如果任何整数参数、返回值只包含非负值，或者在协议中声明为 `CARD16`，请确保将其声明为 `unsigned int` 而不是 `int`。

同样，如果任何整数参数或返回值在协议中声明为 `CARD32`，请将其声明为 `unsigned long` 而不是 `int`。

库一直假设 `char` 是 8 位，`short` 是 16 位，`int` 是 16 或 32 位，而 `long` 是 32 位。遗憾的是，在 `long` 可以容纳 64 位的机器上，这种假设仍然存在，并且许多函数和结构为了与现有代码兼容而使用了不必要的宽字段。当从或向应用程序传递在协议中传输为 `CARD32` 或 `INT32` 的值时，必须小心地转换为 64 位的 `long`。

`PackData` 宏是对处理 32 位 `short` 的可能性的诚心尝试。然而，还需要更多工作才能使其正常运行。

## 导出正确的扩展操作码

扩展存根作者面临的而核心协议不面临的剩余问题是将字段映射到正确的主要和次要操作码。虽然有许多策略，但最简单快速的方法如下：

- 定义一个长度为 `NFILE`（这通常在 `<stdio.h>` 中找到，是系统支持的文件描述符数量）的 `XExtCodes` 类型指针数组。确保这些项都初始化为 `NULL`。

- 当进入存根时，你的测试是使用传入的 `display` 指针来访问文件描述符和数组索引。如果条目为空，则表示你第一次进入该显示器的过程。调用你的初始化过程并将 `display` 指针传递给它。

- 一进入初始化过程，调用 `XInitExtension()`；如果成功，将返回的指针存储在该数组中。确保建立一个关闭显示器处理器以便你清空该条目。以及扩展所需的任何其他初始化。（例如，安装事件处理器等。）你的初始化过程通常会返回一个指向扩展的 `XExtCodes` 结构的指针，这正是通常会在你的指针数组中找到的内容。

- 从初始化过程返回后，存根现在可以正常继续，因为它已经从 `XExtCodes` 结构中安全地拿到了它的主操作码。

## 附录 D. 兼容函数

本附录中讨论的 X 11 和 X 10 函数已经过时，已被较新的 X Version 11 函数取代，仅为了兼容性而维护。

### X Version 11 兼容函数

你可以使用 X Version 11 兼容函数来：

- 设置标准属性
- 设置和获取窗口尺寸提示
- 设置和获取 `XStandardColormap` 结构
- 解析窗口几何
- 获取 X 环境默认值

#### 设置标准属性

要指定描述简单应用程序的最小属性集，请使用 `XSetStandardProperties()`。此函数已被 `XSetWMProperties()` 取代，并设置全部或部分的 `WM_NAME`、`WM_ICON_NAME`、`WM_HINTS`、`WM_COMMAND` 和 `WM_NORMAL_HINTS` 属性。

```
XSetStandardProperties(display, w, window_name, icon_name, icon_pixmap, argv, argc, hints);
```
