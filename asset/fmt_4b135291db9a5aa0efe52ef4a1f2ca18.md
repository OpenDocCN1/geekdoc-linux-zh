## 2.12 我如何启动安装？

将安装磁盘插入软驱器，将 `Red CD` 插入 `CDROM`，然后重启。你也可以从 `DOS`（或 `Windows` 模式）启动安装，运行 `Red CD` 上的 `EXSTART`。

大多数安装程序提供文本和图形界面安装之间的选项。如果你的计算机内存受限，你需要选择“文本”。

## 2.13 Linux 安装困难吗？

对我来说并不难。似乎对于新手来说，它非常直接且无痛苦。取决于你的硬件和安装条件，通常需要 0.5 小时到 2 小时。

预计内存受限的系统需要更长时间或可能出现问题——我们在 48-33 MHz、8 MB 内存上安装 `RH.0` 花了一个晚上晚上，系统经常停止五分钟，但最终安装成功了。

然而，有些新手报告安装对他们来说是场场噩梦（硬件缺乏经验？）。如果你遇到问题，我的建议是安装一个纯净系统，不要纠结显卡的最高分辨率或你可能拥有的外设。在你更理解系统如何运作后，可以添加/配置任何内容。重新安装始终是新手的一个选择（似乎 `Linux` 大师们认为重新安装是件遗憾）。

## 2.14 我应该安装哪些包？

`Linux` 以“包”的形式提供。例如，`Mandrake` 7.0 安装 `CD` 包含了 1002 个包。`Mandrake` 7.2 提供了两张软件 `CD`——我的 `Mandrake` 7.2 安装在硬盘上放置了 1123 个包。记住，这并不是 `Linux` 可用的所有软件——这是制作 `Mandrake` 发行版的人的选择。`Mandrake` 倾向于比 `Redhat` 包更多。一个应用程序（程序）可以包含在一个或多个包中（库和插件通常位于独立的包中）。无论什么种发行版或版本，`CD` 均包含了使基础操作系统（内核、库、一系列命令行配置和维护工具等）成为丰富的网络“客户端”和服务器，并带有适当的配置和监控工具的包。

## 2.15 我应该安装哪个桌面，`KDE` 还是 `GNOME`？

在磁盘空间允许的情况下，两个都装。你可以决定自己倾向于 `KDE`、`GNOME` 还是其他桌面，但无论你的选择是什么，你都绝对希望同时安装 `KDE` 和 `GNOME` 库。如果你安装了这些库，`KDE` 程序可以在 `GNOME` 下运行，反之亦然，这非常棒，因为有很多很好的应用程序使用其中一种库。至于磁盘空间的问题，“桌面”只是 `KDE` 和 `GNOME` 系统的一小部分，所以通过省略桌面并只安装“库”并不能多少空间。`GNOME` 和 `KDE` 都带有一组很好的程序和工具，所以完整安装两个桌面绝对值得的。我发现这两个桌面会过度相互干扰。对于日常工作，我使用 `KDE` 桌面，因为它感觉比 `GNOME` 更好。如果你喜欢更“前卫”且“酷”的，就用 `GNOME`，但如果事情运行得不太好请不要抱怨。

我还会安装“替代管理器”。它们几乎不占空间（或者说在某些情况下确实非常有用）。只要安装了 `KDE` 库，你可以在任何管理器下运行任何 `KDE` 或 `GNOME` 。

`KDE` 更耗电电。在旧硬件上（例如 133 MHz `Pentium`），我更倾向于 `GNOME` 而非 `KDE`。其他管理器比 `KDE` 或 `GNOME` 都轻量。因此，在现代硬件上，我会选择这些“替代”管理器之一。

## 2.16 我完成了安装。我如何进行首次登录？

作为 `root`，“`root`”是初始安装后唯一存在的账户（较新的安装程序会在安装期间提示你创建一个普通用户账户）。文本模式登录示例：

```
my_machine login: root
Password: my_password
```

“`root`” 是一个对系统拥有绝对权限的特殊账户，用于系统管理。你肯定想至少创建一个“用户”账户来执行常规（非系统管理）工作。请阅读后文学习如何操作。

## 2.17 如何让 `Linux` 崩溃？

作为 `root`，你可以做任何事情，包括加速系统崩溃。尝试运行这个命令（如果你真的想崩溃的话请三思）：

```bash
cp /dev/zero /dev/null
```

作为 `root`，你可以用一行看起来无害的命令删除系统中所有的文件（不要这样做）：

```bash
rm -rf /
```

“`root`” 是一个对系统拥有绝对权限的特殊账户，用于系统管理。你肯定想至少创建一个“用户”账户来执行常规（非系统管理）工作。请阅读后文学习如何操作。

这并不是说 `Linux` 容易，而是限制了用户可以。

## 2.19 如何升级 `Linux` 发行版？

对硬盘进行合理的分区有助于未来的升级，因为你的数据文件可以保留在“`home`”目录中。升级时：

-   登录 `root`
-   将 `/etc` 目录复制到某个不会被破坏的地方（例如，`zipdrive`）。这可以让我遇到问题时查看你准备的设置我遇到问题时。
-   对 `/home` 目录中任何有价值的数据进行备份。这是以防发生极其糟糕的错误，例如我格式化了错误的分区。
-   执行 `Linux` 安装，但告诉安装程序将 `/home` 和 `/usr/local` 分区管理在它们之前的（现有）位置。不要格式化这两个分区。这对于保留你的数据至关重要。
-   启动新安装并检查是否运行正常。

-   对于系统中的每个用户，使用旧名称和旧用户数字创建一个登录账户，例如：
    -   检查 `/home/maria/* -l`（在她的主目录的文件列表中检查 "maria" 的用户 ID 账户）；

-   从每个用户目录中删除可能引起麻烦的设置文件，例如：`.kde`、`ICE*`。这也是删除任何垃圾文件的好机会。某些设置文件可能会产生问题，因为新版本的 `KDE` 可能会执行最近的默认设置（它将在首次登录时创建这些设置）。例如：
    -   `cd` 命令 `cd /home/maria`
    -   `rm` 命令 `rm -rf kde`
-   确保主目录中剩余的文件属于相应的用户。例如，我这样操作：
    -   `cd` 命令 `cd /home/maria`
    -   `chown` 命令 `chown -R maria *`
    -   `chgrp` 命令 `chgrp -R maria *`
