
很可能会成功，除非共享的安全性阻止了访问。从那时起，该驱动器的行为将像你系统上的其他驱动器一样。

“我的网络位置”继承自 LAN Manager 的机制，允许计算机看到网络上所有的共享。在 Windows NT 4.0 中，它被称为“网络邻域”。有可能的机制可以“发布”这些信息。第一种是通过 NetBEUI。Windows 仍然支持 NetBEUI，但因为 TCP/IP 是首选的网络协议，NetBEUI 已经消失。我们不讨论 NetBEUI。

第二种机制是 WINS。WINS 仅在 Windows 服务器可用。WINS 是 NetBEUI 公告板的后代，但在传输层使用了 TCP/IP。在 WINS 和 NetBEUI 公告板中，客户端向托管公告板的服务器发布名称/IP 地址信息。NetBEUI 的局限性是只有 256 个客户端可以参与。使用的不是 NetBEUI，而是 TCP/IP 之 NetBIOS。WINS 是托管在 TCP/IP 上的 NetBIOS 公告板。WINS 服务器配置在 Windows 服务器上运行，并提供命名服务。当用户浏览网络时，Windows 2000 文件映射资源管理器查询 WINS 服务器以获取可用服务列表。要在 WINS 数据库中发布信息，客户端必须向 WINS 服务器发送注册。WINS 服务器默认禁用，但通过使用 `services.msc` MMC 插件，可以启动它以便每次服务器启动时运行。

Windows 资源管理器可以显示 WINS 数据库中的条目。WINS 服务仅在 Windows 2000 上可用。可以在开始→程序→管理工具中找到 `services.msc` 插件。通过 WINS 管理工具，我们可以搜索 WINS 数据库。使用 `netsh` 命令将名称翻译为 IP 地址。如果没有 DNS，就需要 WINS 服务器。第三种机制是带 DNS 的活动目录。它能找到活动目录。

## Microsoft Windows 网络

要使用 Windows 机器的 SMB 文件服务，Linux 内核内置了 SMB 文件系统支持。确定当前运行的 Linux 内核是否具有此类支持的方法是运行命令：

```
grep smb /boot/System.map
```

如果屏幕上满了 20 或更多关于 smb 的引用，则 SMB 支持内置在内核中。如果没有，你可能需要重新编译 Linux 内核。这不是困难的任务。简单的步骤如下：

1. 从 kernel.org 获取内核源码。具体来说，我在 `http://ftp.kernel.org/pub/linux/kernel/v2.4/` 找到了一个最新版本。它是一个名为 `linux-2.4.4.tar.gz` 的压缩 tar 包。下载它。
2. 按照以下方式解压：

```
# 所有的操作都必须以 root 身份执行
su
cd /usr/src
rm linux
# 如果存在，则链接到旧的 linux 源
tar xzvf linux-2.4.4.tar.gz
# 重命名目录以包含版本号
mv linux-2.4.4 linux
# 从 /usr/src/linux 目录编译内核
ln -s linux-2.4.4 linux
```

3. 切换到 Linux 目录并输入

```
cd /usr/src/linux
make xconfig
```

确保你在文件系统上启用了 SMB 文件系统支持。

4. 输入

```
make dep bzImage modules modules_install
```

等待生成的内核：

```
cp arch/i386/boot/bzImage /boot/vmlinux-smb
# 如果此失败，说明没有 System.map 文件。
mv /boot/System.map /boot/System.map
# 让新内核可以使用新的 System.map。
cp System.map /boot/System.map
```

5. 编辑 `/etc/lilo` 并添加以下行：

```
image=/boot/vmlinux-smb
label=linux244smb
read-only
root=/dev/hda?
```

6. 运行

```
lilo
```

7. 重启，并在选择界面选择 `linux244-smb`。

这可以正常工作。我们特意在 lilo 文件中写了一个问号，这取决于你当前 Linux 运行的位置。我们所有的系统都运行在 `/dev/sda6`（硬盘适配器 6），这实际上只是系统上唯一磁盘上的一个分区。你应该使用与系统上其他 Linux 机器所相同的 `/dev/hda?` 设备。毕竟，我们只是在同一个根文件系统上运行不同的内核。

## Samba

关于构建内核的讨论到此为止了。其他关于 Linux 的书籍详细解释了如何构建内核和启用功能。从这里开始，我们将假设当前运行的 Linux 已内置 SMB 文件共享协议。在 Linux 中使用 Windows 文件系统涉及在 Linux 上挂载 Windows 共享。在 Linux 上挂载文件系统需要 root 权限，我们切换到 root 用户（使用 `su` 命令）来挂载文件。我们在 winlin 和 winlin2 上共享了 f，winlin 现在是 linlin，所以现在运行在 winlin 上的 Linux 上，我们将挂载来自 winlin2 的 f 共享。

方法如下：

```bash
mount -t smbfs -o username=egb //winlin2/f /mnt/f
```

它会要求输入用户 Farb 的密码。winlin2 使用的用户账户数据库中的任何名称和密码都可以。`mount` 命令可以在计算机每次启动时在 shell 脚本中执行。如果进行了以下更改，普通用户也可以执行它：

```bash
# 作为 root
chmod 4755 /usr/bin/smbmount
# 使用文本编辑器向 /etc/fstab 添加以下条目
//winlin2/f /mnt/f smbfs user,username=egb,noauto,nosuid 0 0
```

这一行包含了 `mount` 命令的参数并可以执行。它还支持 `mount` 命令，因为文件系统可以通过两种快捷方式之一进行挂载：

```bash
mount //winlin2/f
mount /mnt/f
```

最后，fstab 行中的 `user` 参数允许普通用户执行 `mount` 命令。`username` 参数强制使用名为 Farb 的用户的安全凭据建立连接。如果未给出 `username` 参数，则将静默使用当前登录用户的用户名。由于挂载的文件系统只是被嫁接到现有的文件系统中，因此挂载多个共享文件系统很容易。我们只需要确定想让文件系统在根文件系统中的什么位置显示，以及相应的 `mount` 命令即可。例如，在 src 目录下挂载一个新的源目录可以如下所示操作（使用完整的 `mount` 命令并假设 winlin2 存在）：

```bash
mount -t smbfs //winlin2/proda /usr/src/proda
mount -t smbfs //winlin2/prodb /usr/src/prodb
mount -t nfs //winlin4/prodc /usr/src/prodc
```

这些 `mount` 命令将 `/usr/src` 目录作为三个产品源码的根目录。如果这三个产品源码的机器最近共享了 `/usr/src` 目录（见下一节，“Samba 服务器”），那么这三个产品将作为单一共享在网络上可用（类似于 Windows DFS）。安全性是原生于原生文件服务器的。用户通过远程系统上的安全模型进行身份验证。如果原生文件或目录被 ACL 保护，那么 ACL 将决定该用户（用于建立连接的名称和密码）是否获得授权。在 Linux 上没有工具可以配置 Windows 共享文件的 ACL。从 Linux 客户端到 Windows 服务器，配置是由服务器完成的。

挂载文件系统的能力。fstab 行中的 `user` 参数提供了这种能力。`/bin/mount` 命令设置了 set user ID。它由 root 所有。因此，当它被执行时，程序立即获取 root 安全上下文。需要 set user ID 来准确执行安全限制，而 `mount` 正做到了。对于我们要挂载的网络文件系统，`mount` 命令从 `/etc/fstab` 文件读取相应的行，记录文件类型 (`smbfs`)，并执行 `/usr/sbin/mount.smbfs`。如果 `/bin/mount` 命令没有设置 set user ID，它将失败，因为它将获取登录用户的安全上下文，而不是执行 `/bin/mount`。因此，我们对 `/usr/sbin/mount.smbfs` 设置了 set user ID 位。通过这一切，我们现在拥有了一个普通用户可以挂载设备但没有权限挂载磁盘驱动器的系统。安全性由网络文件系统要求的登录名称和密码提供，这意味着只要用户能够正确登录，任何用户都可以与任何系统通信。结果是一个易于理解和管理并为普通用户提供有用益处的安全系统。允许普通用户执行挂载大幅减少了管理开销。在 Windows 上，如果提供的名称和密码符合远程系统的安全要求，普通用户可以映射网络驱动器。在这方面，Linux 和 Windows 2000 是等效的。Linux 需要额外的管理来启用普通用户。

我们本可以将文件系统挂载到任何目录。要了解更多关于 `mount` 命令和 `/etc/fstab` 文件的信息，请输入

```
man mount
man fstab
```

我们现在有一个可能使用许多 Windows 共享的 Linux 客户端。让我们通过 Samba 到 Windows。

## Samba 服务器

Samba 服务器在之前的章节中已经构建，并使用 `make install` 命令进行安装。一旦安装，可以使用以下命令显示 Samba 的状态：

```
/etc/rc.d/init.d/smb status
```

在我们的案例中，由于我们刚刚安装了它，将发现以下内容：

```
smbd is stopped
nmbd stopped
```

`smbd` 和 `nmbd` 是支持从 Linux 提供 CIFS 文件服务的两个服务器程序。`smbd` 是文件服务，`nmbd` 是 NetBIOS 命名服务。它们共同组成了 Samba 服务。在我们从 Linux 机器使用任何文件服务之前，我们必须定义共享目录。所需的信息与 Windows 的 `net share` 命令类似。然而，并没有 `net share` 命令。我们必须编辑文本文件（`/etc/samba/smb.conf`）来定义用户和共享。`smb.conf` 文件在两个地方有记录：第一个是在 `smb.conf` 手册本身，其中有大量的注释；第二个是在 `smb.conf` 帮助页，通过输入以下命令访问：

```
man smb.conf
```

从 Linux 系统共享文件的最低要求是在 `smb.conf` 文件中添加共享定义。以下是我们的 `smb.conf` 文件。它很短是因为我们删除了大部分被注释的部分。

```
[global]
# workgroup = NT-Domain-Name or Workgroup-Name
workgroup = MYGROUP

# server string 等同于 NT Description 字段
server string = Samba Server

# 这告诉 Samba 为每个连接的机器使用独立的日志文件
log file = /var/log/samba/%m.log

# 对日志文件的大小进行限制（单位为 Kb）
max log size = 500

# 安全模式。大多数人将想要用户级安全。
# 详情见 security_level.txt。
security = user

# 你可能希望使用密码加密。请阅读 Samba 文档中的
# ENCRYPTION.txt、Win95.txt 和 WinNT.txt。
# 除非你阅读了这些文档，否则不要启用此选项
encrypt passwords = yes

smb passwd file = /etc/samba/smbpasswd

# ================ 共享定义 ================

[eghome]
comment = Ed's Home
valid users = egb
path = /home/%u
writeable = yes
```

滚动文件，我们达到了带有注释示例的共享定义。我们想从 linwin 共享 `/home/egb`。为此，我们在 `smb.conf` 文件中添加以下段落：

```
[eghome]
comment = Ed's Home
valid users = egb
path = /home/%u
writeable = yes
```

每行的含义是：

| 配置项 | 含义 |
| :--- | :--- |
| `comment = Ed's Home` | 共享的描述。 |
| `valid users = egb` | 将用户限制为仅 egb。 |
| `path = /home/%u` | `%u` 被翻译为登录名称。路径是 Samba 服务器上被共享的本地路径。 |
| `writeable = yes` | 允许创建和修改文件。 |

一旦我们完成编辑 `smb.conf` 文件，我们必须告诉 Samba 服务器重新读取它。这是通过 `/etc/rc.d/init.d/smb` 完成的。如果服务没有启动，我们可以启动它们：

```
/etc/rc.d/init.d/smb start
```

如果它们已经启动，我们可以重启它们：

```
/etc/rc.d/init.d/smb restart
```

在任何一种情况下，完成后，我们现在就可以从 Windows 机器使用它。

## NIS

为了在所有机器上具有相同的用户名和密码，NIS 使信息分发对用户透明。NIS 是一种将单个文件复制到其他机器的服务。有一个主服务器向整个 NIS 域内的所有机器发布文件。通常由 NIS 维护的文件列表可以在 `/etc` 中看到，通常包括：

- `/etc/passwd`
- `/etc/group`
- `/etc/hosts`
- `/etc/rpc`
- `/etc/services`
- `/etc/shadow`
