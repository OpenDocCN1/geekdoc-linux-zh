
当模式匹配规则适用时，`make`会检查目标名称，查看其是否以已知后缀列表中的后缀结尾。如果是，`make`将检查任何后缀规则，以及具有相同根和另一个识别后缀的依赖文件，以此构建它。

后缀规则的目标条目采用如下形式：

```
Dsts: rule
```

其中 `Ds` 是依赖文件的后缀，`Ts` 是目标的后缀，`rule` 是构建该类中目标的规则。`Ds` 和 `Ts` 均必须出现在后缀列表中。（后缀不一定以 `.` 开头即可被识别。）

只有一个后缀的后缀规则描述了如何从具有指定后缀的依赖文件构建具有空（或无）后缀的目标。例如，你可以使用 `.c` 规则从名为 `file.c` 的 C 源文件构建名为 `file` 的执行程序。如果空后缀目标有显式依赖，`make` 将省略对后缀规则的搜索。下表列出了标准的隐式（后缀）规则。

| 用 | 隐式规则名称 | 命令行 |
|---|---|---|
| 汇编文件 | `.s.o` | `$(COMPILE.s) -o $@ $<` |
| | `.s.a` | `$(COMPILE.s) -o $@ $%` |
| | | `$(AR) $(ARFLAGS) $@ $%` |
| | | `$(RM) $*` |
| | `.s~o` | `$(GET) $(LFLAGS) -p $< > *.s` |
| | | `$(COMPILE.s) -o $@` |
| | `.S.o` | `$(COMPILE.S) -o $@ $<` |
| | `.S.a` | `$(COMPILE.S) -o $@ $%` |
| | | `$(AR) $(ARFLAGS) $@ $%` |
| | | `$(RM) $*` |
| | `.S~o` | `$(GET) $(GFLAGS) -p $< > *.S` |
| | | `$(COMPILE.S) -o $@` |
| | `.S~a` | `$(GET) $(GFLAGS) -p $< > *.S` |
| | | `$(COMPILE.S) -o $@ $%` |
| | | `$(AR) $(ARFLAGS) $@ $%` |
| | | `$(RM) $*` |
| C 文件 | `.c` | `$(LINK.c) -o $@ $< $(LDLIBS)` |
| | `.c.n` | `$(LINT.c) $(OUTPUT_OPTION) -<-` |
| | `.c.o` | `$(COMPILE.c) $(OUTPUT_OPTION) -<-` |
| | `.c.a` | `$(COMPILE.c) -o $@ $<` |
| | | `$(AR) $(ARFLAGS) $@ $%` |
| | | `$(RM) $*` |
