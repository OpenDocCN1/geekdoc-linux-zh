
除了定义终端的字体颜色、样式和背景，你还可以使用 `h` 来定义位置属性。例如，你可以通过以下命令在屏幕的第三行第十列显示 OK。

这里是命令：

```
root@server : echo -e "\033"
```

最后，我们使用 `echo` 命令编写一个更有趣的脚本文件菜单。在接接的脚本文件中，使用 `clear` 命令清除整个屏幕，然后使用 `echo` 命令设置终端属性，并打印出一个带有颜色和布局的个性化菜单。具体的颜色匹配，读者可以根据自己的需求进行个性化设计。

这里是脚本：

```bash
#!/bin/bash

clear
echo -e "\033m"
```

### 2) 使用 printf 命令扩展知识并创建脚本菜单。

在 Linux 系统中，除了 `echo` 命令，你也可以使用 `printf` 命令来实现相同的效果。

功能描述：

`printf` 命令可以打印格式化数据。

`printf` 命令的语法格式如下：

```
printf "details"
```

注意：通用 `printf` 命令的参数是需要作为输出的内容。常用的格式字符串和函数描述如所示，以便你更好地理解你正在处理的内容。在下一节中，我们将通过应用案例进一步扩展我们的知识。

#### 应用案例：

该命令的格式 `%8d` 将打印宽度设置为 8，并以右对齐的方式显示整数 `64`。

```
root@server : printf "%8d" 64
// 输出将为 64，宽度为 8
```

注意，该命令的输出信息 64 前面有五个空格。5 个空格 + 3 个数字合共 8 个字符宽。如果你需要左对齐，可以使用 `%-8d` 来实现效果，例如下面的命令。

```
root@server : printf "%-8d" 44
```

注意，`printf` 命令输出信息后，默认不换行。如果你需要换行，可以使用 `\n` 命令。

为了更好地观察左右对齐效果，以下示例将打印两个符号来确定位置。

```
root@server : printf " |%-11d \n" 64
```

左对齐输出 64，输出内容占用 11 个字符宽，占用 2 个字符宽，后面跟着 8 个空格。

默认 `printf` 命令输出后不会换行，但可以使用 `\n` 命令符号在输出后换行。

这显示了 10 的八进制值，从八进制 12 转换为十进制正好是 10。`x11` 代表十六进制 11，`printf` 命令将十六进制 11 转换为十进制整数输出 `17`。`01` 代表八进制 11，`printf` 命令将八进制 11 转换为十进制整数输出 `9`。

```
root@server : printf "%d \n" 17.011
```

当使用 `\d` 打印大整数时，系统提示超出范围，且可以打印的最大数字是 927983298。

有时在 Linux 系统中，我们需要完成一项复杂的任务，但某个命令可能无法完成该任务。此时，我们需要将两个或多个命令结合在一起来完成此类任务。

正如 Linux 文档所述，类似于输送水的管道，Linux 系统的管道可以将命令 1 的输出结果（数据）存储到管道中，然后让命令 2 从管道中读取数据并进一步处理。

在下一节中，我们将讨论关于向可用函数提供输出和输入的高级能力。

#### a) who

`who` 命令可以帮助我们检查哪些账户在什么时候登录了计算机。然而，当计算机上有大量的登录信息时，手动记录登录次数是不方便的。

Linux 系统中的 `wc` 命令可以统计行数，但 `wc` 命令需要数据。如果你提供几行数据，该命令会自动统计数据的行数。我们可以使用管道将 `who` 和 `wc` 命令结合。

```
root@server : who
```

#### b) ss

另一个例子是 `ss` 命令可以查看 Linux 系统所有服务监听的端口列表。然而，`ss` 命令本身没有灵活的过滤功能，而 `grep` 命令具有强大且灵活的过滤功能，因此这两个命令可以通过管道结合使用。显然，有很多数据没有经过 `grep` 命令的过滤，这不够清晰。

在 `ss` 命令将其输出数据存储到管道后，`grep` 命令再次从管道中读取数据，并过滤出包含 `sshd` 的许多数据，最终的输出结果只有两行数据。

```
root@server : ss
```

### 结论...

通过这种方式，我们可以更简单、更清晰地看到我们需要的数据。某些命令是特殊的，例如我们之前使用的 `passwd` 命令，它用于修改系统账户密码，但该命令默认只能从键盘读取密码。

如果你想让命令从管道中读取数据并将其作为密码，你需要使用 `--stdin` 选项。所示，`echo` 命令默认会在屏幕上显示输出结果。在建立管道后，`echo` 命令可以将输出的 `123456` 存储在管道中，而 `passwd` 则可以从管道中读取 `123456` 来修改系统账户 'sample' 的密码。

## 第三章：在 Shell 中重定向输入和输出

在上一章中，我们对 Shell 脚本中输入输出语句的重要性及其实现进行了很好的介绍。在本章中，我们将通过大量的示例讨论高级专家细节，例如输入输出语句的重定向。请继续阅读！

### 为什么重定向在 Shell 中很重要？

在大多数系统中，输出信息通常默认显示在屏幕上，而标准输入信息通过键盘获取。

然而，在编写脚本时，我们不能或不想让某些命令的输出信息显示在屏幕上（当执行脚本时，大量的输出信息会让用户感到困惑）。它还消耗了比需要的系统资源。

此时由于这个原因，最好将输出信息临时写入文件，然后在以后需要时读取文件并提取所需的信息。默认的标准输入信息也存在类似的问题。当我们使用 `mail` 命令在 Linux 系统发送邮件时，程序需要读取邮件的文本。

默认情况下，来自键盘的输入数据被用文本，会导致脚本进入交互模式，因为读取键盘信息需要手动输入。

例如，如果此时可以更改默认输入模式，不再从键盘读取数据，而是从预先准备的文件读取数据，这样邮件程序就可以在需要时自动读取文件内容并自动发送邮件，而无需手动交互。通过这样，脚本的自动化效果将带来更好的体验。

### Linux 系统中的输出

在 Linux 中，输出可以分为标准输出和标准错误输出。标准输出的文件描述符是 `1`，标准错误输出的文件描述符是 `2`。而输入文件描述符为 `0`。

如果你想更改输出信息的方向，可以使用 `>` 或 `>>` 符号将输出信息重定向到文件。使用 `1>` 将标准输出信息重定向到文件（`1` 可以省略不写，默认值为 `1`），或使用 `2>>` 将错误输出信息重定向到文件。

使用 `>>` 符号将输出信息重定向到文件。如果文件不存在，系统会自动创建文件。如果文件已存在，系统会将输出信息追加到文件原始信息的末尾。

在接下来的示例中，`echo` 命令本会在屏幕上显示数据，但使用了重定向，输出信息可以导出到文件中。

```
root@server : echo "This is a sample" > sample.txt
// 这将文件导出到名为 sample 的文本文件中
```

之前的 `echo` 命令不会给出错误信息。然而，当使用 `ls` 命令时，最终输出信息根据文件是否存在被分为标准输出和错误输出。此时，如果我们只使用 `>` 或 `>>`，我们就无法将错误信息重定向并导出到文件中。

这里我们需要使用 `2>` 或 `2>>` 来重定向错误输出。

如果我们想将标准输出和错误输出都重定向到同一个文件，可以使用 `2>&1`。例如，`ls /root > file 2>&1` 将标准输出和错误输出都重定向到 `file`。

如果我们想将标准输出重定向到一个文件，将错误输出重定向到另一个文件，可以使用 `>` 和 `2>`。例如，`ls /root > file1 2> file2` 将标准输出重定向到 `file1`，错误输出重定向到 `file2`。

如果我们想将输出追加到文件，可以使用 `>>` 和 `>>1`。例如，`ls /root >> file 2>>1` 将标准输出和错误输出都追加到 `file`。

如果我们想丢弃命令的输出，可以将其重定向到 `/dev/null`。例如，`ls /root > /dev/null` 将丢弃标准输出，而 `ls /root 2> /dev/null` 将丢弃错误输出。

提前进行，好吗？

你可以使用 `<<` 符号来实现相同的效果。这样，脚本就可以独立运行，而不依赖于邮件内容文件。使用 `<<` 符号将数据内容重定向到上一个命令作为该命令的输入。

```bash
root@server : mail -s warning << EOF
```

`<<` 符号（也称为 Here Document）意味着你需要的内容在这里。让我们来看一个例子，`cat` 通过 Here Document 读取数据，并通过输出重定向将数据导出到文件。

以下是该脚本：

```bash
#!/bin/bash
Mail -s error
这是我们想要发送的内容
<< fax.txt
### 在输入重定向后结束程序
```

在 Linux 系统中，`fdisk` 命令通常用于划分磁盘分区，但该命令是交互式的，现在我们需要编写脚本来实现自动分区、自动格式化、自动挂载分区等。为了解决这个问题，也可以使用 Here Document。让我们来编写这样一个自动分区脚本。

警告：

此脚本将删除磁盘上的所有数据，所有数据将丢失！

以下是该脚本：

```bash
#!/bin/bash
mkfs.xfs /dev/sdb
### 这用于格式化
```

为了提高编写脚本时代码的可读性，通常需要对代码添加额外的缩进。然而，当使用 `<<` 将数据导入程序时，如果内容中有缩进，它将连同缩进内容一起传递给程序。

此时，Tab 键仅起缩进作用，我们不希望将其传递给程序。如有必要，可以使用 `<<-` 符号重定向输入，这样系统将忽略 `EOF` 之前的所有数据内容和 Tab 键。这样，只有 Tab 键可以被忽略，如果 Here Document 的主体内容是用空格缩进的，它将无效。

```bash
cat << EOF
```

至此，我们已经借助 Linux 系统命令，简要介绍了 Shell 编程中输入和输出语句的重定向。在继续讨论变量和其他进阶概念之前，我们将谈谈在处理 Shell 脚本时各种等号符号的写法姿势。这通常会导致错误，即使学习曲线可能很陡峭。请跟随学习！

## 第四章

## SHELL 脚本编写中的不同引号

编程语言经常使用引号来显示程序中的行结束，或用于确定编程语言的缩进原则。在 Shell 中，我们也使用不同类型的引号来提高程序的效率。在本章中，我们将通过示例描述其中一些用法。请跟随学习！

### 各种引号的正确使用姿势

1) 单引号和双引号

在编写脚本时，我们经常需要引号。Shell 支持各种引号，例如 `"`（双引号）、`''`（单引号）、`` ` ``（反引号）和 `\`（转义符号）。

以下是一些命令：

```bash
root@server : touch x y z
### 这是没有使用引号的
root@server : touch "x y z"
### 这是使用了引号
```

### 在什么情况下会使用这么多符号？

让我们来看几个案例。从这里可以看出，双引号的作用是引用一个整体，计算机会将引号内的所有内容视为一个整体。如果不使用双引号，就会创建三个不同的文件。当以后需要删除文件时，会发生类似的问题。因此，我们需要使用第一个命令而不是第二个命令，因为它们是独立的文件。

```bash
root@server : rm -rf x y z
### 这将删除创建的所有三个文件
root@server : rm y z
# 这将显示错误
```

此外，我们应该分析这里有多少个文件？文件名到底是什么？

```bash
root@server : " x y z"
```

因为这里没有使用双引号，系统理解为需要删除 X、Y 和 Z 三三个文件，但实际上系统中只有一个名为“x y z”的文件，空格也是文件名的一部分。

在下一节中，我们将进一步讨论在实际中如何删除文件。

### 如何删除文件？

文件通常可以通过双引号成功删除。在 Linux 系统中，除了双引号外，单引号也可以引用一个整体。同时，单引号还有另一个功能，即特殊符号可以被屏蔽（特殊符号的特殊含义可以屏蔽并转换为字符表面的名称）。

```bash
root@server : echo #
root@server : echo '####'
```

上述两个命令没有特殊符号，因此使用双引号或单引号的效果相同。然而，当存在特殊符号时，单引号和双引号不能互换，如上面解释的示例所示。

在第一个 Shell 中，`#` 符号具有特殊含义，是一个注释符号。

`#` 符号及其内容将被程序解释为注释而不会被执行。此命令原本想在屏幕上输出一个 `#` 符号，但实际输出结果是空行。

如果我们想输出这个 `#` 符号，可以像第二个命令那样使用单引号来屏蔽 `#` 符号的特殊含义。除了 Shell 之外，`$` 具有提取变量值的特殊含义，当我们需要使用它时，使用双引号。

```bash
root@server : echo $$
root@server : echo '$$'
```

### 2) 命令替换

最后，我们将解释命令替换（反引号）。它也是一种命令替换替换，会将命令替换为命令的输出结果。让我们来看下面的示例。

```bash
root@server : ping -c2 $(url)
```

反引号通常用于封装命令，以便将其输出作为参数使用。然而，它们也有一些缺陷，例如难以阅读且不支持嵌套。为了解决这些问题，我们使用 `$()` 语法。

在定义变量时，变量名只能使用字母（包括大小写）、数字和下划线（_）的组合。并且不能以数字开头。此外，在工作中定义变量名时，最好使用易于理解的单词。记住不要使用随机字符来命名变量。不规则的变量名会使脚本的可读性变得糟糕。

需要注意的是，定义变量时，等号两边不应该有空格。

#### 变量命名提示：

当你需要读取变量值时，需要在变量名之前添加美元符号 `$`。如果变量名与其他非变量字符混合，则需要用 `{}` 隔开。最后，如果你需要取消一个变量，可以使用 `unset` 命令将其删除。

示例：

```
root@server : test=567
root@server : $test
```

输出

```
567
```

此时，你需要使用 `$` 将变量名与其他字符隔开。

虽然这三个命令没有使用 `$` 将变量名与其他字符隔开，但最终的返回值不是空的。由于 Shell 变量名只能由字母、数字和下划线组成，无法包含特殊符号（如横线、冒号、空格等），因此系统不会将特殊符号视为变量名的一部分，但会理解为变量名后面跟着的是与变量名无关的其他字符串。

让我们来看一个简单的变量使用案例。

在下一节中，我们将分析一个脚本来深入理解这些变量带来的复杂性。

#### 脚本案例分析如下：

```bash
#!/bin/bash
localip=$(ifconfig | grep -eth0)
mem=$(uptime | grep -m)
cpu=$(uptime | grep -u)
echo " The IP address is $localip"
echo " The memory that cpu offers $mem"
echo " The cpu name is $cpu"
```

此脚本中定义了三个变量，它们都是命令的返回结果，因此变量值在每次执行脚本时可能会发生。然而，无论变量值如何变化，脚本都能在最后正常输出这些变量值。

第一个变量 `localip` 存储本地 `eth0` 网卡的 IP 地址。这里假设系统中存在 `eth0` 网卡且已配置了 IP 地址。

第二个变量 `mem` 存储本地内存的剩余容量。

第三个变量 `cpu` 存储本地 CPU 在 15 分钟内的平均负载。语句中使用了 `tr` 和 `cut` 命令来获取这三个变量值，并在 `tr -s` 之后加了一个空格，这用于将管道传输的数据中多个连续的空格合并为一个空格。

如果在 `-s` 选项后使用引号来引用其他字符，效果是相同的，可以将多个特定的字符合并为一个字符。使用 `cut` 命令可以帮助我们获取特定的数据列（通过 `-f` 选项指定要获取的列数），并使用 `-d` 选项设置列的分隔符字符。

#### 系统变量

上面介绍了用户定义变量，接下来我们介绍系统预设变量。系统预设变量顾名名，是系统已经预设好的变量，无需用户自行定义即可直接使用。

系统默认变量基本上使用大写字母或某些特殊符号作为变量名。

预设变量可以细分为环境变量、位置变量、预定义变量和用户定义变量。

在编写脚本时，我们可以在适当的地方应用合适的变量，因此在这里不再详述。通过编写脚本案例并调用这些系统预设变量来检查执行效果。

### 为什么系统变量是必要的？

虽然自定义变量可以帮助我们创建程序来定义需要做什么，但后者可以帮助我们创建使用系统环境变量的程序。系统变量用于内存磁盘值、根分区，有时用于关于时间、内存大小等数值的细微系统细节。

以下是一些经常使用的最重要的系统变量。

- a) UID

这是一个系统变量，用于显示当前正在使用系统的用户 ID。如果作为 root 系统使用，则将显示默认值。

- B) PWD

这是一个系统变量，用于为 Linux 中的各种文件和网络系统创建密码。例如，我们可以使用 `umask` 命令为文件系统创建密码。

- C) RANDOM

这是一个系统变量，利用随机机制按我们的意愿输出。我们可以显示数字、文本文件，有时甚至是随机路径。你只需要在 Shell 程序中调用 `RANDOM` 变量即可。

- D) PATH

这是一个系统变量，用于讨论我们正在使用的当前路径。我们也可以选择路径地址并使用 `echo` 命令显示它们以供进一步参考。

- E) LANG

这是一个系统变量，可以打印以不同语言的所有系统命令。例如，你可以使用 `FR` 将所有用英语编写的系统命令替换为法国法语。当你需要将 Shell 程序发布到不以英语作为主要语言的国家时，特别推荐使用这些系统变量。
