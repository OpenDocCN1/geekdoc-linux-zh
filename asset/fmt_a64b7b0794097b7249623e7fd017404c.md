
### B.1 读取和写入数据

`seek`调用允许你在文件中重新定位文件描述符的位置。向它传递文件描述符和另外两个指定新位置的额外参数。

- 如果第三个参数是`SEEK_SET`，`seek`将第二个参数解释为从文件开始的偏移量（字节）。
- 如果第三个参数是`SEEK_CUR`，`seek`将第二个参数解释为相对于当前位置的偏移量（正负均可）。
- 如果第三个参数是`SEEK_END`，`seek`将第二个参数解释为从文件末尾的偏移量。正值表示文件末尾之后的位置。

`seek`调用返回相对于文件开始的新位置。偏移量的类型为`off_t`。如果发生错误，`seek`返回`-1`。你不能对某些类型的文件描述符使用`seek`，例如`socket`文件描述符。

如果你想在改变位置的情况下找到文件描述符在文件中的位置，可以使用相对于当前位置的零偏移，例如：

```c
off_t position = seek(file_descriptor, 0, SEEK_CUR);
```

Linux 使用`seek`将文件描述符定位到文件末尾之外。通常情况下，如果文件描述符位于文件末尾且你对其写入，Linux 会自动扩展文件为新数据留空间。如果你将文件描述符定位到文件末尾之外，Linux 会扩展文件以适应你通过`seek`操作创建的“间隙”，然后对其进行写入。然而，这个间隙实际上并没有占用磁盘空间；Linux 只是记录了它有多长。如果你以后尝试从该文件中读取，在你的程序看来，该间隙是由`0`字节填充的。

利用`seek`的这种行为，可以创建几乎不占用磁盘空间的巨型文件。列表 B.5 中的程序`lseek-huge`就是这样做的。它接受两个命令行参数：文件名和以兆字节为单位的目标文件大小。程序打开一个新文件，使用`lseek`移动文件结束，然后在关闭之前写入一个`0`字节。

### 列表 B.5 (lseek-huge.c) 使用 seek 创建大文件

```c
#include <fcntl.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <unistd.h>

int main (int argc, char* argv[])
{
    int zero = 0;
    const int megabyte = 1024 * 1024;

    char* filename = argv[1];
```

```c
/* 列表 B.5 续 */
size_t length = (size_t) atoi(argv[2]) * megabyte;

/* 打开一个新文件。 */
int fd = open(filename, O_WRONLY | O_CREAT | O_EXCL, 0666);
/* 跳到我们想要文件结束的位置的前 1 字节处。 */
lseek(fd, length - 1, SEEK_SET);
/* 写入单个字节。 */
write(fd, &zero, 1);
/* 全部完成。 */
close(fd);

return 0;
```

使用`lseek-huge`，你将创建一个`1GB (1024MB)`的文件。注意操作前后驱动器上的剩余空间。

```text
% df -h
Files Size Used Avail Mounted
dev/sda 2.9G 1G 655M /
% ls -l bigfile
-rw-r--r-- 1 root root 0G
% df -h
Files Size Used Avail Mounted
dev/sda 2.9G 1G 655M /
```

尽管`bigfile`尺寸巨大，但并没有消耗明显的磁盘空间。尽管如此，如果我们打开`bigfile`并读取它，它似乎被`0`字节填充了。例如，我们可以通过`hexdump`查看内容：

```text
% hexdump bigfile
0x0000000: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0x0000010: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0x0000020: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0x0000030: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
...
```

注意这些间隙是`ext2`文件系统的特殊特性。如果你使用`lseek-huge`在其他类型的文件系统（如`fat`）上创建文件，你会发现它实际上占据了全部磁盘空间。Linux 不会提醒你在回到文件开始之前`rewind`。

### B.2 stat

使用`open`和`read`你可以提取文件的内容。但其他信息呢？例如，`ls -l`显示目录中的文件，如文件大小、修改时间、权限和所有者。

`Stat`获取有关文件的信息。传入感兴趣的文件路径和一个指向`struct stat`类型变量的指针。如果`stat`调用成功，它返回`0`并填充结构体中的字段；否则返回`-1`。

这些是`struct stat`中最有用的字段：

- `st_mode`包含访问权限。文件权限在第 10.3 节“文件系统权限”中解释。
- 除了访问权限外，`st_mode`字段在高位位中编码了文件类型。
- `st_uid`和`st_gid`分别包含文件所属的用户和组 ID。用户和组 ID 在第 10.1 节“用户和组”中描述。
- `st_size`包含文件大小（字节）。
- `st_time`文件最后访问（读取或写入）的时间。
- `st_mtime`文件最后修改的时间。

这些宏通过检查`st_mode`字段的值确定你调用`stat`的文件类型。如果文件是该类型，则宏为真。

```c
S_ISBLK (mode)    块设备
S_ISCHR (mode)    字符设备
S_ISDIR (mode)    目录
S_ISFIFO (mode)   fifo (命名管道)
S_ISNK (mode)     符号链接
S_ISREG (mode)    普通文件
S_ISSOCK (mode)   socket
```

`st_dev`字段包含该文件所在的硬件设备的主、次设备号。设备号在第 6 章中讨论。主设备号左移 8 位；次设备号占据低位 8 位。`st_ino`字段包含该文件的 inode 节点号。这在文件系统中定位了该文件。

```c
/* 分配足够大的缓冲区以容纳文件内容。 */
buffer = (char*)malloc (*length);
/* 将文件读入缓冲区。 */
read(fd, buffer, *length);

/* 完成工作。 */
close(fd);
return buffer;
}
```

### B.3 向量化读与写操作

`write`调用接受的参数是一个指向数据缓冲区起始位置的指针以及缓冲区的长度。它将一段连续的内存区域写入文件描述符。然而，程序通常需要写入若干项数据，而每项数据都存储在内存的不同部分。为了使用这一点，程序要么必须将这些项拷贝到单个内存区域中（这显然会低效地利用 CPU 周期和内存），要么必须多次调用`write`。

对于应用程序而言，多次调用`write`效率很低或者是不符合意愿的。例如，在向网络套接字写数据时，两次调用可以写入两个要发送到网络的数据包，而如果能够通过单次`write`调用，相同的数据就可以在一个数据包中发送。

`vwrite`调用允许你在单次操作中将不连续的内存区域写入文件描述符。这被称为向量写（vector write）。使用`vwrite`的代价是你必须设置一个指定每个内存区域起始位置和长度的数据结构。该数据结构是一个`struct iovec`元素数组。每个元素指定一个要写入的内存区域；`iov_base`和`iov_len`字段分别指定该区域的起始位置和长度。如果你知道需要多少个区域，可以声明一个`struct iovec`数组变量；如果区域的数量可以变化，则必须动态分配`iovec`数组。

调用`vwrite`时，传递要写入的文件描述符、`struct iovec`数组以及数组中的元素个数。列表 B.7 中的程序使用单个`vwrite`将其命令行参数写入文件。第一个参数是文件名；第二个及后续参数被写入该命名的文件中，每个占一行。该程序分配了一个`struct iovec`元素数组，其长度是写入参数数量的两倍——对于每个参数，它都会写入参数本身的文本以及一个新换行符。由于我们无法预知参数的数量，因此数组是使用`malloc`分配的。

# 列表 B.7 (write-args.c) 使用 writev 将参数列表写入文件

```c
#include <fcntl.h>
#include <stdlib.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/io.h>
#include <unistd.h>

int main(int argc, char *argv[])
{
    int fd;
    struct iovec *vec;
    struct iovec *vec_next;
    int i;
    /* 我们需要一个包含换行符的“缓冲区”。使用
       普通的 char 变量来实现这个。 */
    char newline = '\n';
    /* 第一个命令行参数是输出文件名。 */
    char* filename = argv[1];
    /* 跳过参数列表的前两个元素。元素
       0 是程序名，元素 1 是输出
       文件名。 */
    argc -= 2;
    argv += 2;

    /* 分配一个 iovec 元素数组。对于参数列表的
       每个元素，我们需要文本本身以及一个
       换行符。 */
    vec = (struct iovec *)malloc(2 * argc * sizeof(struct iovec));

    /* 遍历参数列表，构建 iovec 条目。 */
    vec_next = vec;
    for (i = 0; i < argc; i++) {
        /* 第一个元素是参数的文本。 */
        vec_next->iov_base = argv[i];
        vec_next->iov_len = strlen(argv[i]);
        ++vec_next;
        /* 第二个元素是单个换行符。允许
           struct iovec 数组的多个元素指向
           同一内存区域是可以的。 */
        vec_next->iov_base = &newline;
        vec_next->iov_len = 1;
        ++vec_next;
    }

    /* 将参数写入文件。 */
    fd = open(filename, O_WRONLY | O_CREAT);
    writev(fd, vec, 2 * argc);
```

### B.4 与标准 C 库 I/O 函数的关系

这里是运行`write-args`的示例。

- `./write-args outputfile "first arg" "second arg" "third arg"`
- `cat outputfile`
- `first arg`
- `second arg`
- `third arg`

Linux 提供了一个相应的函数`read`，它可以在单次操作中将数据读入多个不连续的内存区域。与`writev`类似，一个`struct iovec`元素数组指定了数据从文件描述符读取的内存区域。

我们之前提到过，标准 C 库 I/O 函数是在这些低层 I/O 函数之上实现的。然而，有时为了配合文件描述符使用标准库函数，或者在标准库的`FILE*`上使用低层 I/O 函数是非常方便的。GNU/Linux 允许你进行这两种操作。

如果你使用`fopen`打开文件，可以使用`fopen`函数获取底层的文件描述符。它接收一个`FILE*`并返回文件描述符。例如，要用`fopen`打开文件并写入内容，可以使用如下代码：

```c
FILE* stream = fopen(filename, "w");
int file_descriptor = fileno(stream);
write(file_descriptor, vector, length);
```

注意，`stream`和文件描述符指向同一个文件，因此如果你关闭了其中一个，就不能再使用另一个。反过来，从文件描述符转换为流，可以使用`fdopen`函数。它接收一个文件描述符和一个指定模式的字符串参数。模式参数的语法与`open`相同，且必须与文件描述符兼容。例如，为读文件描述符指定`r`，写文件描述符指定`w`。

### B.5 其他文件操作

文件和其他的其他操作也非常有用：

- `getcwd`获取当前目录。它接收两个参数：缓冲区和缓冲区长度。它将当前目录路径拷贝到缓冲区。
- `chdir`切换目录。它的参数是新目录的路径。
- `mkdir`创建目录。它的第二个参数是新文件的访问权限。权限的解释与`open`的第三参数相同，并会被进程掩码修改。
- `rmdir`删除目录。它的参数是目录的路径。
- `unlink`删除文件。它的参数是文件的路径。也可以用于删除其他文件系统对象，如命名管道（FIFOs）或设备（参见第 6 章第 5.4.5 节）。

  实际上，`unlink`并不一定删除文件内容。正如其名，它将文件从包含它的目录中取消链接。该文件不再出现在该目录列表中，但如果有任何进程持有该文件的打开文件描述符，文件内容就不会从磁盘上删除。只有当没有进程持有打开的文件描述符时，文件内容才会被删除。因此，如果一个进程打开文件进行读写，另一个进程取消了该文件并创建了同名的新文件，第一个进程看到的是旧内容而不是新内容（除非它关闭并重新打开）。
- `rename`移动文件。它的两个参数是文件的旧路径和新路径。如果路径位于不同的目录，只要它们在同一个文件系统中，`rename`就会移动文件。你也可以用`rename`移动目录或其他文件系统对象。

### B.6 读取目录内容

Linux 提供了读取目录内容的函数。虽然这些函数与本附录中描述的低层 I/O 函数没有直接关系，但我们仍然提供了它们，因为它们在应用程序中通常非常有用。

## 8.6 读取目录内容 297

要读取目录的内容，请遵循以下步骤：

- 1. 调用`opendir(const char *path)`，传入你想要检查的目录路径。`opendir`调用返回一个`DIR*`句柄，你将用它访问目录内容。如果发生错误，该调用返回`NULL`。
- 2. 重复调用`readdir`，传入从`readdir`获取的`DIR*`句柄。每次调用`readdir`，它都会返回一个指向下一个目录对应的`struct dirent`实例的指针。当目录内容的结尾时，`readdir`返回`NULL`。
- 3. 从`readdir`获取的`struct dirent`结构体有一个字段`d_name`，包含目录名称。
- 4. 调用`closedir`并传入`DIR*`句柄，以结束目录列表。

注意，如果你在程序中使用这些函数，需要包含`<sys/types.h>`和`<dirent.h>`。如果你需要按特定顺序排列目录内容，你必须手动进行排序。

列表 B.8 中的程序打印了目录的内容。目录可以通过命令行指定，但如果没有指定，程序将使用当前工作目录。对于目录中的每个条目，它显示条目的类型和路径。`get_file_type`函数使用`stat`来确定文件系统条目的类型。
