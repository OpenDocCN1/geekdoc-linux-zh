
例如，如果你的名称服务切换器仅对服务咨询 NIS，且服务映射表为空，则你的系统将无法与网络上的 HP-UX 系统通信。（我是通过惨训学到这一点的。）我的建议是：

1. 保持默认的 `/etc/nsswitch.conf` 文件不变；它可以适应大多数环境。
2. 仅迁移密码、组和主机映射。这些在 Windows 2000 上很容易修改。

## 10.3.3.3 第三步：禁用旧主服务器

在 HP-UX 上，禁用 NIS 主服务器最简单的方法是通过 SAM。启动 SAM，选择 Networking and Communications（网络与通信），然后点击 NIS 图标。进入 NIS 配置界面（见图 10–10）。从菜单栏中选择 Actions（操作）→Disable Server（禁用服务器）。要将系统变为新主服务器（Windows 2000 系统）的 NIS 客户端，选择 Actions→Disable Client（禁用客户端），然后选择 Actions→Set Domain Name（设置域名）。将域名设置为迁移过程中创建的新新域名。在我的案例中，我将域名设置为 `mydomain` 而不是 `book.local`。然后，运行 Actions→Enable Client（启用客户端）。

## 10.3.4 迁移过程中的问题

### 10.3.4.1 UID

由于我的测试平台非常小，没有什么需要担心的，所以我毫无顾忌地运行迁移。我遇到的唯一问题是 Active Directory 账户 `dylan` 似乎没有保留该用户的 UNIX `UID`（值为 102）。在图 10–11 中，我展示了 `dylan` 账户的 UNIX Attributes（Unix属性）选项卡。由于我选择不覆盖 Windows 对象的任何数据，`UID` 被设置了一个不同的数字。结果是，虽然我可以以用户 `dylan` 登录 HP-UX 系统（在将主服务器转换为客户端后），但我遇到了文件权限问题。将 Active Directory 中 `dylan` 的 `UID` 改回原始值 102 后，一切都解决了。

此外，在 HP-UX 中，用户组的默认 `GID` 是 20。但 Server for NIS 保留了 100 以下的 `GID`。因此，你必须在 Server for NIS 中将 `GID` 改为100以上的的数字，并确保 name service switch（名称服务切换）在某些时刻查询文件。如果你想确保你的名称服务切换正常工作，请使用 `nsquery` 工具。例如：

```bash
# /usr/contrib/bin/nsquery group users
```

对组策略使用 "files" nis"。

```text
Searching /etc/group for users

Group name: users

Group Id: 20

Group membership: root

Switch configuration: Terminates Search
```

注意，`nsquery` 找到了 `GID` 为 20 的 `users` 组，因为名称服务切换首先查询 `/etc/group`。
