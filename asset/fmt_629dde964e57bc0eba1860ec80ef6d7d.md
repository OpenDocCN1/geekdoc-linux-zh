## 关于自动挂载的更多信息

系统管理员倾向于在设置 NFS 服务器时，将文件系统挂载到与其挂载点相同的位置。在之前的示例中，服务器上的 `/prod` 目录可能会导出到客户端，客户端将将其挂载到 `/prod`。这种做法简单、优雅，但完全错误。服务器应该对全局文件层级拥有与客户端相同的视图。

如果此服务器需要挂载来自另一台服务器的 NFS 分区，将被迫为该服务器创建一个特殊的自动挂载映射。为每台服务器引入特殊映射是复杂、令人混乱且没有必要的。

更好的方法是安排本地文件系统挂载在不同的地方。让自动挂载器将所有内容放在正确的位置。

考虑以下 `hosts` 文件：

```
/vol1 hosta,hostb,hostc,this-server(no_root_squash)
```

配合针对 `/prod` 的此自动挂载映射：

```
bin this-server:/vol/
lib this-server:/vol/
etc this-server:/vol/
```

这无疑不是自动挂载的唯一可行模型，但它是简单、有效且经过充分测试的。挂载映射的格言是“不要自找麻烦”。简单性原则在这里一如既往。

## 安全性

获取任何 NFS 客户端 `root` 权限的人都可以冒充信任该系统的任何 NFS 服务器上的有效用户（通常是其他 `root`）。更糟糕的是，在大多数局域网中，可以冒充内网内的任何客户端，因此 NFS 服务器可能会信任任何使用“受信任”客户端 IP 地址的机器。请考虑此时关于通过 NFS 共享文件系统的决策，以及每个文件系统是否需要共享读写。

### 管理 NIS

网络信息系统（NIS）是一种用于共享通用系统信息的网络服务。NIS 通常管理的数据包括用户密码和组信息、主机到 IP 地址的映射、邮件别名以及其他应在系统间通用的系统数据。通过对这些数据进行通用化管理，NIS 允许系统管理员创建一个更加统一的环境，同时简化更新和分发这些数据的任务。

NIS 是 Sun Microystems 为 SunOS 创建的。它最初被称为黄页（Yellow Pages，简称 YP），由于英国电信的诉讼，Sun 不得更改名称。他们正式将 YP 重命名为 NIS，但在系统中留下了 YP 命名规范的痕迹。NIS 使用 ONC RPC（开放网络计算远程调用）网络协议作为底层机制。

NIS 中的数据集表示为一个或多个映射（maps）。NIS 映射由键值对组成，其排列方式取决于预期访问数据的各种系统库函数的要求。例如，NIS 中的两个映射表示了主机名信息：`hosts.byname` 和 `hosts.byaddr`。这些映射直接反映了系统库函数 `gethostbyname(3)` 和 `gethostbyaddr(3)` 访问主机机的方式。给定一个主机名，`gethostbyname(3)` 产生一个 IP 地址；给定一个 IP 地址，`gethostbyaddr(3)` 返回一个主机名。

所有共享 NIS 数据库的系统都是 NIS 域的成员。域内，系统可以承担三种角色之一：客户端、从服务器或主服务器。

- 主服务器（Master）：系统是 NIS 数据的源。所有 NIS 数据的更新在此主机上进行。
- 从服务器（Slave）：系统维护主数据库的副本。当主服务器更改数据时，会被更新。
- 客户端（Client）：系统连接到 NIS 从服务器或主服务器以获取数据。

NIS 域与 DNS 域有显著不同。DNS 域指定图中的节点，而 NIS 域是单一实体。两个 NIS 域之间不存在层级关系，即使命名规范可能暗示存在关系。事实上，任何两个 NIS 域之间没有任何关系。例如，可以名为 `subdomain.domain.com` 和 `domain.com` 的 NIS 域。这些域不会以任何方式相互作用。它们可以是苹果和橘子，功能完全相同。

这限制了 NIS 的扩展性。尽管有人会将 NIS 推向极限，但 NIS 域最好不要超过千台机器。

### NIS 客户端进程

NIS 客户端进程是 `ybind`。由于 NIS 是基于 RPC 的系统，每个客户端还必须运行 `portmap` 进程。`ybind` 进程通过解析 `/etc/yp.conf` 来查找指定 NIS 域的服务器。如果 `/etc/yp.conf` 中不存在该域或文件不存在，`ybind` 将广播查找服务器。广播机制只能找到同一 IP 子网内的 NIS 服务器。一旦客户端成功绑定到服务器，它会定期检查服务器，如果 NIS 服务器不可用，则重新启动整个绑定过程。

### NIS 服务器进程

NIS `ypinit` 命令来简化从机和主服务器的创建。

`ypinit -m` 命令从存储在 `/etc` 目录的标准源文件中创建映射。如果系统管理员将文件放置在备目录中，不建议使用此命令初始化 NIS 主服务器。相反，应创建 `/var/yp/domainname` 文件（`domainname` 指 NIS 域名），并创建 `/var/yp/ypsvers` 文件。编辑主文件，为 `YPSCRDIR` 和 `YPPDDDIR` 提供正确的值，然后（以 root 身份）在 `/var/yp` 中运行。

每个 NIS 服务器都运行 `ypserver` 进程，该进程将 NIS 映射存储在 `/var/yp/domainname` 中。NIS 从机必须使用 `ypinit -s master` 命令初始化，其中 `master` 是 NIS 的名称或 IP 地址。当创建新的 NIS 从机时，将主机添加到 `/var/yp/ypsvers` 文件中至关重要。如果不添加，新的从机服务器将无法接收更新。每个 NIS 服务器通常还会被配置为 NIS 客户端。

许多人还为从机配置了 `cron` 任务，以便定期从主服务器拉取映射。简单的 `cron` 任务随 LINUX 分发在 `/usr/lib/yp` 目录下。其意图是在发生瞬时故障时更新从机服务器。对于所有从机来说可能都是必要的，特别是对于那些 `/var/yp/ypsvers` 文件保持更新的从机。

NIS 主服务器与 NIS 从机类似，但有两个额外的角色。第一个是提供 NIS 数据的维护，第二个是将更新后的映射分发到 NIS 从机服务器。主服务器的功能与 NIS 客户端可以绑定的从机服务器完全相同，因为它以主服务器身份运行 `ypserver` 守护进程。

### NIS 数据库维护

维护 NIS 映射的核心文件是 `/var/yp/Makefile`。系统管理员只需在 `/var/yp` 目录下输入 `make`，即可处理该文件以更新 NIS。此 makefile 使用 `makedbm` 命令将 NIS 数据库的文件表示形式转换为 NIS 映射。映射通过 `ypcommand` 分发到从机服务器。`ypcommand` 本身使用 `ypsvers` 映射来确定从机服务器列表，强烈建议管理员保持此数据库的最新性。
