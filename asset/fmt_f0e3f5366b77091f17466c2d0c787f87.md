
# PCI
**PCI**（Peripheral Component Interconnect，外围组件互连）。一种自配置本地总线。最初由 `Intel` 为 PC 提出，现在可以在 `PowerPC` 系统和 RISC 工作站找到。`PCI` 现在是现代计算中的主导总线。

# 权限
`permissions`（权限）对 UNIX 文件和目录的访问针对所有者、组和其他世界进行评估。权限分为三类型：读 (`r`)、写 (`w`) 和执行 (`x`)。这些通常用八进制表示。

# SUID、SGID 与粘滞位
- **SUID** 位允许程序以所有者的权限运行。
- **SGID** 位允许程序以组的权限运行。
- **粘滞位**（sticky bit）在目录上使用时，限制谁可以删除文件。

`SUID` 和 `SGID` 位在非可执行文件和以 `#!` 开头的脚本中被忽略。

# PID
`pid` 进程标识符。内核用于跟踪切换此进程与系统中运行的其他进程所需的系统级资源的数字。管理员可以通过 `ps` 命令轻松查看。

# 进程
`process` 运行进程的实例。`init` 是第一个进程，也是所有其他进程的祖先。

# 普通文件
普通文件：一个完全普通的文件；它既不是字符设备文件或块文件，不是 `FIFO` 或套接字。

# RFC
`RFC` 请求意见（Request For Comments）。这些是为所有互联网实践提出标准工作方法和协议的文档。它们由相关方起草并提交给 `IETF`，在那里它们被分配给工作组，并经过相对简单且开放的审查、完善和采用过程。

所有主要的互联网协议和格式都由 `RFC` 定义。这对编写客户端或服务器以实现这些协议的程序员特别感兴趣。因此，开发新邮件用户代理（MUA）或邮件传输代理（MTA）的程序员应该密切关注 `RFC 822`，它定义了邮件头格式和选项。

大多数 `RFC` 与系统管理员并不直接。然而，某些管理员应该熟悉如何查找和阅读 `RFC`，因为其中某些是非常关重要的。更多信息可以在 `http://www.iet.org/rfc.html` 获取。

> **注意：** 某些 `RFC` 编写后从未被采纳，某些虽然被采纳但从未被任何相当数量的站点实现。`RFC` 的目的是促进并确保实现给定协议的软件包之间的互操作性，以及使用这些协议的站点之间稳定的交互。

# RISC
`RISC` 减少指令集计算机。这是一类 `CPU` 设计，包括 `SPARC`、`PowerPC` 和 `MIPS` 处理器。它与 `CISC`（复杂指令集计算机）的区别在于其设计哲学：该哲学强调高速执行相对简单的指令，而不是提供大量“强大”的语言指令。

这种设计哲学认为，复杂操作最好在软件中完成，从而在 `CPU` 芯片上为寄存器、缓存、流水线和其他性能增强功能留出空间。

# 共享库
**共享库**：库是动态链接到可执行二进制程序（binaries）的对象文件。它们类似于 `Microsoft Windows` 的 `DLL` 文件。在 `Linux` 下，共享库可以存储在目录中（通常在 `/etc/ld.so.conf` 下）。共享库通常包括 `/usr/lib` 和 `/usr/X11/lib` 下的文件。如果共享库被删除或损坏，或者 `/etc/ld.so.conf` 文件被损坏，那么依赖于它们的（动态链接的）程序将无法执行。系统上几乎所有普通程序都依赖 `lib (libc)`，因此损坏的库通常需要重启（使用救援软盘）来恢复。

共享库有三个主要优点：
1. 它们减少了程序尺寸，节省了磁盘空间。
2. 它们减少了内存占用，允许在较少的 `RAM` 中运行更多程序，因为 `Linux` 内核的内存管理系统可以使用分页技术，使得共享库实际上只加载一次，然后在所有使用它的进程之间共享。
3. 它们允许“即插即用”升级和本地定制，而无需重新编译和重新安装许多与之链接的程序。

因此，通过共享库，系统管理员可以从基于文件的目录服务迁移到 `NIS`、`NDS`、`LDAP` 或某些未来或自定义的服务集，而无需更改使用这些服务的其他程序。

另见 `libre`（库），`library`（库）。

# 信号
在 `Unix` 和 `Linux` 下，信号（signal）是进程间通信（IPC）最基本、常见的形式。它也是这些系统下“事件驱动”编程的基础。每个 `UNIX` 实现都定义了一组与各种异步事件相关的信号，例如终端发送“中断请求”（`SIGINT`）或窗口大小发生变化（`SIGWINCH`）。

**信号处理程序**（signal handler）：程序内部的例程，其特殊用途是响应父进程或其他进程提供的信号。一个常见的例子是上述的 `SIGINT`，或作业控制下描述的 `SIGSUSP`。

**清理**（清理脚本）：一种定期删除不需要的文件（如 `core` 文件）或杀死特定进程的脚本。这些脚本必须仔细编写，以避免“误报”——错误地匹配用于判断删除哪些文件或杀死哪些进程的标准。

**套接字**（sockets）：套接字是 `BSD` 引入的进程间通信（IPC）的主要形式。套接字主要有两种。
1. “Unix 域套接字”是文件系统中的节点（目录项），例如 `/var/run/printer`、`/dev/log` 或 `/tmp/.unix/*`。
2. 另一类套接字属于 `TCP/IP` 或“inet”地址族。套接字是通过 `TCP/IP` 地址执行连接和事务的标准形式。

无论何种情况，它们都允许客户端与服务器通信，`Unix` 域套接字是本地通信，互联网套接字是跨 `TCP/IP` 网络通信。

“互联网套接字”通过源 `IP` 地址和目标端口的组合在整个互联网上唯一标识。
