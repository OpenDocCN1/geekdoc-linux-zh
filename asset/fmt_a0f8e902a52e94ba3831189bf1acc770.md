
权限最小化意味着赋予用户（以及管理员）完成工作所需的最少访问权限。赋予用户工作站“`root`”权限，如果所有用户都精通 Linux 且值得信赖，这样做是合理的，但他们通常并非如此（在这方面都不如此）。即使他们确实如此，这也是个坏主意，因为他们很可能会安装某些损坏/不安全的软件等。如果用户访问的需求仅是关闭/重启工作站，那么这就是他们应该被授予的访问权限量。你绝不会将财务文件留在具有“世界可读”权限的服务器上供会计人员查看，这一概念一直延伸到整个网络。限制访问还可能在账户被渗透时限制损害（你读过人们贴在显示器上的贴签上写的内容吗？）。

## 物理启动安全

### 物理访问

这部分在《实战 Unix 与 网络安全》一书中有深入介绍，但我将简要概述一下基础知识。关闭你的主会计服务器，重新开启，从特制的软盘启动，并将 `payroll.db` 传输到异地的 `ftp` 站点。除非你的会计服务器被锁定，以防止恶意用户（或大楼保洁人员、快递员等）这样做！我听听过保洁人员为了插上清洁设备而拔掉服务器插头的恐怖故事。我曾见过有人点击电源插线的小开关并重启他们的服务器（尽管我从未这样做过）。将你的服务器锁在安全房间内（甚至是封闭的柜子内）是有意义的。将服务器放在架高的表面上也是一个非常好的主意，以防止洪水导致的损坏（无论是屋顶漏水还是洒了一桶冰沙）。

## 计算机 BIOS

### LILO

```
delay=x
控制 LILO 在启动到默认选择之前等待用户输入的时间（以 1/10 秒为单位）。C2 安全要求之一是将此间隔时间设置为 0（显然，双系统启动意味着大部分出了问题）。除非系统要双启动其他内容，否则将其设置为 0 是个好主意。
```

强制用户输入内容。`LILO` 不会自动启动系统。这在服务器上可能有用，可以作为一种在没有人工值守的情况下禁用重启的方法，但通常如果黑客有重启重启能力能力，他们可以使用新的启动选项重写 `MBR`。如果你添加了超时选项，系统将在超时后继续启动。

`restricted` 意味着如果向引导程序传递了启动选项（如 "`linux single`"），则需要使用密码。确保在每个镜像上都使用这一个（否则服务器启动时需要密码，如果你从未计划重启它，这没问题）。

`password=XXXXX` 需要输入密码，与 `restricted` 配合使用，同时确保 `lilo.conf` 不再可读，否则任何用户都能读取密码。

这里是我其中一台服务器的 `lilo-conf` 示例（密码当然已经更改）。

```
boot=/dev/hda
map=/boot/map
install=/boot/boot.b
prompt
timeout=100
default=linux
image=/boot/vmlinuz-2.2.5
label=linux
root=/dev/hda1
read-only
restricted
password=some_password
```

这使用 `/boot/vmlinuz-2.2.5` 内核启动系统，该内核存储在系统第一个 IDE 硬盘的 `MBR` 上。`prompt` 关键字通常会停止重启，但由于在系统中已设置，它可以无问题地启动 "`linux`"，但如果你想进入 "`linux single`"，你有 10 秒时间输入它，此时系统会提示你输入密码（"`some_password`"）。结合 BIOS 设置为仅启动保护模式，你就有了一个相当安全的系统。

## Linux 内核

Linux（根据 Stallman 的说法，如果你指的是复杂的发行版，应称为 GNU/Linux）只是操作系统的核心。内核处理硬盘访问、安全机制、网络以及几乎一切事务。此外，我们还有诸如内核 2.2.x 不再使用 `ipfwadm` 等问题。关于服务器需要记住的几个重要点点：

- 1. 限制对服务器的物理访问。
- 2. 遵循最小权限原则，他们破坏的范围会更小。
- 3. **务必备份！**
- 4. 定期检查服务器的更改（端口、软件等），自动化工具对此非常有帮助。
- 5. 软件更改应该经过仔细计划/测试，因为它们可能会产生不利影响（例如内核 2.2.x 不再使用 `ipfwadm`，如果你忘记安装 `ipchains`，那将不是很尴尬吗）。

权限最小化意味着赋予用户（以及管理员）完成工作所需的最少访问权限。赋予用户工作站“`root`”权限，如果所有用户都精通 Linux 且值得信赖，这样做是合理的，但他们通常并非如此（在这方面都不如此）。即使他们确实如此，这也是个坏主意，因为他们很可能会安装某些损坏/不安全的软件等。如果用户访问的需求仅是关闭/重启工作站，那么这就是他们应该被授予的访问权限量。你绝不会将财务文件留在具有“世界可读”权限的服务器上供会计人员查看，这一概念一直延伸到整个网络。限制访问还可能在账户被渗透时限制损害（你读过人们贴在显示器上的贴签上写的内容吗？）。

## 访问

### Telnet

`Telnet` 是目前最古老且广为人知的远程访问工具，几乎每个 Unix 系统都带有它，甚至连 NT 系统也支持它。只有当你能从命令提示符管理系统时（NT 系统并不擅长），`Telnet` 才会真正有用，这使其非常适用于 Unix。`Telnet` 极不安全，密码、用户名以及会话数据均以明文形式传输，是嗅探器的首选目标。所有 Linux 发行版都带有 `Telnet`。你永远不应该使用 `telnet` 来远程管理系统。

### SSL Telnet

`SSL Telnet` 在 `Telnet` 的基础上增加了 `SSL` 加密，这使其变得更加安全、更可靠。通过使用 `X.509` 证书（也称为个人证书），你可以轻松地管理远程系统。与 `SSH` 系统不同，`SSL Telnet` 是完全的 GNU 程序且供所有人免费使用。你可以从这里获取 `SSLnet` 服务器和客户端：`http://ftp.replay.com/`

## SSH

`SSH` 最初是免费的，但现在采用了商业许可，不过它具有许多功能，使其值得使用。它支持多种形式的身份验证（密码、rho、RSA 密钥），允许你重定向端口，并轻松配置允许登录哪些用户。`SSH` 可从这里获取：`http://ftp.replay.com/`。如果你打算将其用于商业，或者想获得最新版本，应该前往：`http://www.ssh.fi/`

### LSH

`LSH` 是 `SSH` 协议的免费实现，`LSH` 采用 GNU 许可，并且开始看起来 `SSH`（从商业角度来看，`SSH` 已不再如此）的替代品。你可以从这里下载：`http://www.net.lu.ac.uk/psst/`，请注意它仍在开发中。

### REXEC

`REXEC` 是较老的远程 Unix 工具之一，它允许你在远程系统上执行命令，它有一个严重的缺陷，即没有真正的安全模型。安全性是通过使用“`hosts`”文件来实现的，该文件指定了哪些主机/等可以运行命令，但这容易受到伪欺骗和其他形式的攻击。你永远不应该使用 `REXEC` 来远程管理系统。

### Slush

`Slush` 基于 `OpenSSL`，目前支持 `X.509` 证书，这对于大型组织来说，这比在各种服务器上记住几十个密码要好得多（也更明智）。`Slush` 是 GPL 协议的，但尚未完成（它实现了大部分实用功能，但有局限性）。另一个完全基于开源软件，使得后门/等远程访问成为可能。最终，它可以使用更优的工具替代 `SSH`。你可以从这里获取：`http://violet.ibs.com.au/slush/`

### NSH

`NSH` 是一款功能完备的商业产品（我的意思是全全）。它在构建时就支持加密，因此使用起来相对安全（我无法真正验证这一点，因为它不是开源）。易用性很高，你只需 `cd //computername` 就能登录计算机，然后你可以轻松地复制/修改/等文件，运行程序并获取进程列表进行命令操作等。`NSH` 还有一个可用的 Perl 模块，使得命令脚本编写变得简单，非常适合管理许多系统（如工作站）。此外，`NSH` 可用于多个平台（Linux、BSD、Irix 等）。`NSH` 可从这里获取：`http://www.networkshell.com/`，并可以轻松下载 30 天的试用版。

### Fsh

`Fsh` 代表“远程命令执行”，概念上与 `rsh/rep` 类似。它通过使用 `ssh` 建立加密隧道或在隧道上运行所有命令，避免了不断创建加密会话的消耗。你可以从这里获取：`http://www.lysator.liu.se/fsh/`

### secsh

`secsh`（Secure Shell）提供了另一层登录安全，当你通过 `ssh` 或 `SSL telnet` 登录后，系统会提示另一个密码，如果你获取了 `secsh`，它会终止登录尝试。你可以在这里获取 `secsh`：`http://www.leenux.com/`
