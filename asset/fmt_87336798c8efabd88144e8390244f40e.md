
在命令中用标准输入和输出的另一个趣味点在于通过网络在系统之间传输文件。假设我们有两台运行类 Unix 系统并配备了 `tar` 和 `ssh` 的机器。在这种情况下，我们可以将一个目录从远程系统（此处名为 `remote-sys`）传输到我们的本地系统。

```
[me@linuxbox ~]$ mkdir remote-stuff
[me@linuxbox ~]$ cd remote-stuff
[me@remote-sys ~]$ ssh remote-sys 'tar cf - Documents | tar xf -'
me@remote-sys password:
[me@remote-stuff ~]$ ls
Documents
```

这里是如何从远程系统-sys 将名为 `Documents` 的目录复制到本地系统名为 `remote-stuff` 的目录的。我们是怎么做的？首先，我们通过 `ssh` 在远程系统启动了 `tar` 程序。你可能记得 `ssh` 允许我们在网络化计算机上远程执行程序，并在本地系统执行“exec”——远程系统产生的标准输出会被发送到本地系统查看。我们可以利用这一点，让 `tar` 创建一个归包（`c` 模式）并将其发送到标准输出，而不是文件（带有连字符参数的 `f` 选项），通过 `ssh` 提供的加密隧道将归包传输到本地系统。在本地系统中，我们执行 `tar` 并让它扩展从标准输入提供的归包（同样是带有连字符参数的 `f` 选项）（`x` 模式）。

## zip

`zip` 程序既是压缩工具也是归档工具。该程序使用的文件格式对 Windows 用户来说很熟悉，因为它读取和写入 `.zip` 文件。然而，在 Linux 中，`bzip2` 是主导压缩程序，而 `gzip` 紧随其后。

在最基本的用法中，`zip` 的调用方式如下：

```
zip options zipfile...
```

例如，为了为我们的 `playground` 创建一个 `zip` 归包，我们会这样做：

```
me@linuxbox ~$ zip -r playground.zip playground
```

除非我们包含 `-r` 递归选项，否则只会存储 `playground` 目录（不包含其任何内容）。虽然添加 `.zip` 扩展名是自动的，但为了清晰，我们会包含文件扩展名。在创建 `zip` 归包期间，`zip` 通常会显示一系列如下的消息：

```
adding: playground/dir-020/file-Z (stored 0%)
adding: playground/dir-020/file-Y (stored 0%)
adding: playground/dir-020/file-X (stored 0%)
adding: playground/dir-087/ (stored 0%)
adding: playground/dir-087/file-S (stored 0%)
```

这些消息显示了添加到归包中的每个文件的状态。`zip` 将使用两种存储方法之一向归包添加文件：要么像这里所示“存储（store）”文件而不进行压缩，要么“压缩存储（deflate）”文件以执行压缩。显示的数值表示所实现的压缩量。由于我们的 `playground` 只包含空文件，因此未对其内容进行任何压缩。

使用 `unzip` 程序时，提取 `zip` 文件的内容是非常直接的。

```
me@linuxbox ~$ cd foo
me@linuxbox foo$ unzip ../playground.zip
```

关于 `zip`（与 `tar` 相比）需要考虑的一点是，如果指定了一个现有归包，它会被更新而不是替换。这意味着现有的归包会被保留，但会添加新文件，并且匹配的文件会被替换。

我们可以通过向 `unzip` 指定文件，从 `zip` 归包中选择性地列出和提取文件。

```
me@linuxbox ~$ unzip -l playground.zip playground/dir-087/file-Z
Archive: ../playground.zip
```

| Length | Date | Time | Name |
| :--- | :--- | :--- | :--- |
| 0 | 10-05-18 | 09:25 | playground/dir-087/file-Z |
| 0 | 1 | | file |

```
me@linuxbox ~$ cd foo
me@linuxbox foo$ unzip ../playground.zip playground/dir-087/
Archive: ../playground.zip
```

```
replace playground/dir-087/file-Z? [y]es, [n]o, [A]ll, [N]one, [r]ename: y extracting: playground/dir-087/file-Z
```

使用 `-l` 选项会导致 `unzip` 仅列出归包的内容而不提取文件。如果未指定任何文件，`unzip` 将列出归包中的所有文件。可以添加 `-v` 选项来增加列表列表的详细程度。注意，当归包提取与现有文件冲突时，会在文件替换之前提示用户。

像 `tar` 一样，`zip` 也可以利用标准输入和输出，尽管这不那么常见。可以通过 `-@` 选项将文件名列表传递给 `zip`。

```
me@linuxbox ~$ cd foo
me@linuxbox foo$ unzip ../playground.zip
```

## 同步文件和目录

维护备份的一种常见策略是保持一个或多个目录（通常是本地存储设备）与远程系统的同步。例如，我们可能有一个网站的本地副本。在类 Unix 世界中，用于此目的的工具是 `rsync`。`rsync` 协议允许 `rsync` 快速检测两个目录之间的差异，并执行最少量的复制来实现同步。这使得 `rsync` 非常快速且高效。`sync` 的调用方式如下：

`rsync options source destination`

其中 `source` 和 `destination` 是以下之一：

- 本地文件或目录
- 格式为 `[user]@host:path` 的远程文件或目录
- 指定为 `rsync://[user]@host(:port)/path` 的 `rsync` 服务器

注意，源或目的地之一必须是本地文件。不支持远程复制。让我们尝试本地文件。首先，清理我们的 `foo` 目录。

```
[linuxbox] ~$ rm -rf foo/*
```

接下来，我们将 `playground` 与 `foo` 中对应的目录同步。

```
[linuxbox] ~$ rsync -av playground foo
```

我们包含了 `-a` 选项（归档——导致递归并保留文件属性）和 `-v` 选项（详细输出），以在 `foo` 中创建 `playground` 目录的镜像。在命令运行时，我们将看到正在复制的文件和目录列表。结束时，我们将看到类似下面的摘要消息，指示执行的复制量：

```
sent 135759 bytes received 57870 bytes 387258.00 bytes/sec
total size is 3230 speedup is 0.02
```

如果我们再次运行该命令，我们将看到不同的结果：

```
[linuxbox] ~$ rsync -av playground foo
building file list ... done
```

注意这里没有文件列表。这是因为 `rsync` 检测到 `~/playground` 和 `~/foo/playground` 之间没有差异。

因此，它不需要复制任何内容。如果我们修改了 `playground` 目录并运行 `rsync`：

```bash
[me@linuxbox ~]$ touch playground/dir-099/file-Z
[me@linuxbox ~]$ rsync -av playground foo
building file ... done
playground/dir-099/file-Z
sent 22685 received 42 bytes 45454.00 bytes/sec
total size is 3230 speedup is 0.14
```

我们看到 `rsync` 检测到了变化并仅复制了更新后的文件。

当我们指定 `rsync` 源时，有一个细微但实用的特性可以使用。让我们考虑两个目录。

```bash
[me@linuxbox ~]$ ls
destination
```

`source` 目录包含一个名为 `file1` 的文件，而 `destination` 目录是空的。如果我们像这样执行将 `source` 复制到 `destination`：

```bash
[me@linuxbox ~]$ rsync source destination
```

那么 `rsync` 会将 `source` 目录复制到 `destination` 中。

```bash
[me@linuxbox ~]$ ls destination
source
```
