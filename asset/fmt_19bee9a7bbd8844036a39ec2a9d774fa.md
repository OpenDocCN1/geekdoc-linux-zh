
### 9.4 管道创建

```c
/* ch09-pipeline.c --- fork two processes into their own pipeline.
             Minimal error checking for brevity. */

#include <stdio.h>
#include <errno.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int pipefd[2];

extern void left_child(void), right_child(void);

/* main --- fork children, wait for them to finish */

int main(int argc, char **argv)
{
	pid_t left_pid, right_pid;
	pid_t ret;
	int status;
 
	if (pipe(pipefd) < 0) 	/* create pipe, very first thing */
		perror("pipe");
		exit(1);
	}
 
	if ((left_pid = fork() < 0) { 	/* fork left-hand child */
		perror("fork");
		exit(1);
	} else if (left_pid == 0)
		left_child();
 
	if ((right_pid = fork() < 0) { 	/* fork right-hand child */
		perror("fork");
		exit(1);
	} else if (right_pid == 0)
		right_child();
 
	close(pipefd[0]); 			/* close parent's copy of pipe */
	close(pipefd[1]);
 
	while ((ret = wait(&status)) > 0) { 	/* wait for children */
		if (ret == left_pid)
			printf("left child terminated, status: %d\n", status);
		else if (ret == right_pid)
			printf("right child terminated, status: %d\n", status);
		else
			printf("%ow! unknown child %d terminated, status %d\n",
				ret, status);
	}
	return 0;
}
```

第 22–25 行创建管道。必须首先执行此操作。

第 27–31 行创建左侧子进程，第 33–37 行创建右侧子进程。在这两种情况下，父进程通过 `main()` 继续线性执行路径，而子进程调用适当的函数来操作文件描述符并执行 `exec`。

第 39–40 行关闭父进程的管道副本。

第 42–50 行循环，收割子进程，直到 `wait()` 返回错误。

### 9.4 文件描述符管理

```c
/* left_child --- do the work for the left child */

void left_child(void)
{
    static char *left_argv[] = { "echo", "hi", "there", NULL };
    
    close(pipefd[0]);
    close(1);
    dup(pipefd[1]);
    close(pipefd[1]);
    
    execvp("echo", left_argv);
    _exit(errno == ENOENT ? 127 : 126);
}

/* right_child --- do the work for the right child */

void right_child(void)
{
    static char *right_argv[] = { "sed", "s/hi/hello/g", NULL };
    
    close(pipefd[1]);
    close(0);
    dup(pipefd[0]);
    close(pipefd[0]);
    
    execvp("sed", right_argv);
    _exit(errno == ENOENT ? 127 : 126);
}
```

第 57–68 行是左侧子进程的代码。该过程遵循上述步骤，关闭不需要的管道端，关闭原始标准输出，将管道的写入端 `dup()` 到 1，然后关闭原始写入端。此时，第 66 行调用 `execvp()`，如果失败，第 67 行调用 `_exit()`。（请记住，如果 `execvp()` 成功，第 67 行永远不会被执行。）

第 72–83 行对右侧子进程执行类似的步骤。这是其运行时发生的情况：

```text
$ ch09-pipeline                          运行程序
left child terminated, status: 0         左侧子进程在输出前结束 (!)
hello there                              来自右侧子进程的输出
$ ch09-pipeline                          运行程序
hello there                              来自右侧子进程的输出，以及...
right child terminated, status: 0        右侧子进程在左侧子进程之前结束
left child terminated, status: 0
```

请注意，子进程完成的顺序并不是确定性的。它取决于系统负载以及可能影响进程调度的许多其他因素。在编写创建多个进程的代码时，应谨慎避免做出任何顺序假设，特别是那些调用 `wait()` 函数族的代码。

## 9.4.2 创建非线性管道：/dev/fd/XX

许多现代 Unix 系统，包括 GNU/Linux，都支持 `/dev/fd` 目录中的特殊文件。这些文件代表打开的文件描述符，名称如 `/dev/fd/0`、`/dev/fd/1` 等。将这样的名称传递给 `open()` 会返回一个新的文件描述符，其效果等同于对给定的文件描述符编号调用 `dup()`。

这些特殊文件在 shell 层面得到应用：Bash、ksh88（某些版本）和 ksh93 shell 提供了一项称为过程替换（process substitution）的功能，这使得创建非线性管道成为可能。在 shell 层面的表示法中，输入管道使用 `<(...)`，输出管道使用 `>(...)`。例如，假设你希望将 `diff` 命令应用于两个命令的输出。通常你必须使用临时文件：

```text
command1 > /tmp/out.$$1
command2 > /tmp/out.$$2
diff /tmp/out.$$1 /tmp/out.$$2
rm /tmp/out.$$1 /tmp/out.$$2
```
