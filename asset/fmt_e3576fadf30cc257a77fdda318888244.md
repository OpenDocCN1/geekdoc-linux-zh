
### vparcreate
创建虚拟分区。

form: `vparcreate -p vp_name [-B boot_attr] [-D db_file] [-S static_attr] [-b kernel_path] [-o boot_opts] [-a rsrc] [...]`

创建一个总共有三个处理器（num）、绑定两个（min）、2048MB 内存、/0/0 上的所有组件、位于 0/0/1/2.0 的启动磁盘、内核为 /stand/vmunix、自动加速开启且控制台位于 0/0/4/0 的虚拟分区：

```
# `vparcreate -p vPar_name -a cpu::3 -a cpu::2:4 -b mem::2048 -a io::0/0 -a io::0/0/1/2.0:boot -b /stand/vmunix -B auto`
```

注意：
- 必须在创建虚拟分区之前或之后将 HP-UX 11i 加载到卷上。如果在创建 vPar 之后加载 HP-UX 11i，则使用 `vparboot -p vp_name -I ignite_kernel` 来加载 11i。
- `/stand/vmunix` 是默认值，无需指定。
- vPar 未设置为*静态*，这意味着可以稍后修改它。
- CPU 总数为三个（num），绑定两个（min），最多两个未绑定（max）。

### vparmodify
修改虚拟分区的属性。（请注意，使用 `-a` 添加 CPU 是相对于当前数量的。`-a cpu::2` 会在当前 CPU 数量的基础上增加两个 CPU。`-m cpu::3` 指定绝对数量为三个 CPU。）

form: `vparmodify -p vp_name [-B boot_attr] [-D db_file] [-S static_attr] [-b kernel_path] [-o boot_opts] [-P new_vp_name] [-a rsrc] [...] [-m rsrc] [...] [-d rsrc] [...]`

要添加路径 `/109` 处的处理器（将此处理器添加到已分配的处理器中）：

```
# `vparmodify -p vPar_name -a cpu::109`
```

要指定绝对数量为三个处理器：

```
# `vparmodify -p vPar_name -m cpu::3`
```

### vparremove
删除虚拟分区。

form: `vparremove -p vp_name [-D db_file] [-f]`

要删除当前运行数据库中的虚拟分区：

```
# `vparremove -p vPar_name`
```

### vparreset
重置虚拟分区。

`vparreset -p vp_name [-t|-l] [-q] [-f]`

重置虚拟分区，模拟在 `Ctrl-B` 提示符处的 TOC 操作。如果没有 `-h` 选项，默认命令仅模拟 TOC。

```
# `vparreset -p vPar_name`
```

强制重置虚拟分区：

```
# `vparreset -p vPar_name -h -f`
```

### `vparresources(5)` man 页
提供虚拟分区及其资源的描述。

这是一个手册页，总体描述了虚拟分区资源以及资源如何在其他命令（如 `vparmodify`）中指定。

### vparstatus
显示虚拟分区的状态。

form1: `vparstatus [-v|-M] [-p vp_name] [-p..| -D db_file]`
form2: `vparstatus -A [ -M]`（可用资源）
form3: `vparstatus -w`（当前 vPar 的名称）
form4: `vparstatus -e`（虚拟分区监视器的事件日志）
form5: `vparstatus -R [ -p vp_name]`（最近重置的 PIM 数据）

以详细模式显示虚拟分区的状态：

```
# `vparstatus -v -p vPar_name`
```

以详细模式显示所有虚拟分区的状态：

```
# `vparstatus -v`
```

显示可用或未使用的资源：

```
# `vparstatus -A`
```

### `vpartition` man 页
显示有关虚拟分区命令行的信息。

提供了以下关于虚拟分区命令的简要描述：
`vparboot` 启动虚拟分区。
`vparcreate` 创建新的虚拟分区。
`vparmodify` 修改现有的虚拟分区。
`vparremove` 移除（删除）现有的虚拟分区。
`vparreset` 模拟对虚拟分区的 TOC 或硬重置。
`vparstatus` 显示虚拟分区和可用资源信息。

### vPar 资源命令选项

| 命令 | 描述 |
| :--- | :--- |
| **通过以下方式使用 CPU 资源：** | 绑定和非绑定 CPU 的数量：`cpu::num`<br>CPU 硬件路径：`cpu:path`<br>最小值和最大值：`cpu::[min[:max]]` |
| **CPU 类型：**<br>（有关所有资源类型的更多详情，请参见 `vparresources` 手册页。） | **绑定**：当 vPar 处于活动状态时，CPU 绑定到虚拟分区。分配在创建 vPar 时进行。最低的绑定 CPU 编号为 vPar 的 `monarch`。中断由绑定 CPU 处理。<br>**非绑定**：可以动态重新分配的 CPU。不处理中断。 |
| **通过以下方式使用内存资源：** | 大小 `mem::size`<br>基址和范围：`mem::base:range`<br>上述两者的组合。 |
| **指定 I/O：** | 使用路径：`io:path[.attr1|.attr2[...]]`<br>（有关详情，请参见手册页 `vparresources`）。 |
| **添加资源使用：**<br>（如果正在运行 `vparmodify`，这会将组件相对于已存在的项添加。） | `-a cpu:path`<br>`-a cpu::num`（可在 vPar 运行时进行）<br>`[-a cpu::num -a cpu::min:[max]]`（`:` 仅限 `vparcreate` 使用）<br>`-a io:path[.attr1|.attr2[...]]`<br>`-a mem::size`<br>`-a mem::base:range` |
| **删除资源使用：**<br>（如果正在运行 `vparmodify`，这会将组件相对于已存在的项删除。） | `-d cpu:path`<br>`-d cpu::num`（可在 vPar 运行时进行）<br>`-d io:path[.attr1|.attr2[...]]`<br>`-d mem::size`<br>`-d mem::base:range` |
| **修改资源使用：**<br>（这是相对于绝对数值进行修改。） | `-m cpu::num`（可在 vPar 运行时进行）<br>`-m cpu::[min[:max]]`<br>`-m io:path[.attr1|.attr2[...]]`<br>`-m mem::size` |

### vPars 状态

| 状态 | 描述 |
| :--- | :--- |
| *load* | 虚拟分区的内核映像正在加载到内存中。这是由虚拟分区监视器执行的。 |
| *boot* | 虚拟分区正在启动过程中。内核映像已成功加载到虚拟分区监视器。 |
| *up* | 虚拟分区已成功启动并正在运行。 |
| *shut* | 虚拟分区正在关闭过程中。 |
| *down* | 虚拟分区未运行且处于停止状态。 |
| *crash* | 虚拟分区发生了恐慌并正在崩溃。 |
| *hung* | 虚拟分区无响应并处于挂起状态。 |

我们将使用即将在创建虚拟分区章节中展示的一些命令。附录 A 提供了有关虚拟分区命令的更多详情，其中包含这些命令的在线手册页。
