
> 注意：`pkgadd` 还会检查此新软件包所需的其他软件包是否已经安装。如果先决条件尚未安装，它将警告你或不允许你安装软件包。

使用 `swmtool`，Sun Solaris 系统提供了一个 X 应用程序来引导你运行 `pkgadd`。它会显示 CD-ROM 的内容，并允许通过点点安装或移除整个介质或选定的软件包。

要使用 `swmtool` 安装新软件包，点击“属性”（Properties）按钮以弹出软件包所在位置的菜单。

如果安装尚未挂载，请选择本地或远程 CD-ROM 驱动器。如果已经挂载，请选择“已挂载的文件系统”（Mounted File System），然后选择包含软件包的目录路径。

`swmtool` 会显示磁盘内容。它可以提供介质上所需的尺寸和版本的详细信息。要开始安装，选择每个要安装的软件包并按下“安装”（Install）按钮。`swmtool` 会为你运行 `pkgadd`。你仍然需要像手动运行 `pkgadd` 一样回答 `pkgadd` 的问题。

使用 `swmtool` 移除，请从屏幕顶部选择“移除”（Remove）按钮。选择要移除的软件包并按下“开始移除”（Begin Removal）。`swmtool` 会为你运行 `rpm`。

使用 `rpm`，RedHat Linux 使用 `rpm` 软件包格式。要这些软件包，你需要使用 `rpm` 程序。它非常易用，具有几个命令行参数。对于其他软件包格式，如果已经安装了相同的软件包（更新或更旧版本），你无法安装该软件包。可以使用 `rpm uninstall` 卸载旧软件包，然后使用它来安装新软件包。你可以使用 `rpm` 查询软件包（检查是否已安装）并验证它们。`rpm` 的页面描述非常详尽。

RedHat 还有一个 X 工具，可以选择你想要安装的软件包（以及包含其中的程序）。使用此程序进行安装和卸载非常简单高效。该程序是免费的，可以在 RedHat 控制面板的软件包管理下找到。

使用 `installsw`，BSD 实现版使用 `pkgadd` 格式，但使用一个名为 `installsw` 的简单易用程序。它为管理员提供了一个界面，可以在其中选择并安装、或卸载不同的软件包。这是一个广受欢迎的前端界面，避免了 `pkgadd` 不易于友的命令行界面。

## 向服务器添加无磁盘客户端

向服务器添加无磁盘客户端需要两个步骤：添加支持任何客户端的通用文件；添加此特定客户端的特定文件。只有当这是该类型的第一个客户端且要安装该操作系统的第一个版本时，才需要执行第一步。

### 安装无磁盘客户端操作系统支持文件

传统上，无磁盘客户端文件安装在服务器的 `/export` 文件系统中。在 V Release 4 中，通用可执行文件被放置在 `/export/exec` 目录下。每种架构在 `/export/exec` 下都有自己的子目录。

每个 UNIX 供应商都支持无磁盘客户端，并拥有一套从安装介质加载此类架构客户端文件的安装程序。在 Solaris 2 中，`swmtool` 的“编辑”菜单包含下拉菜单“添加客户端软件...”（Add client software...）。这可以配置服务器以支持每种架构类型的客户端。

#### 添加无磁盘客户端

一旦服务器上有了客户端支持，必须将客户端添加到服务器上。由于客户端没有磁盘，所有安装都通过网络进行。运行一个 shell 脚本或窗口命令来添加 `/export/root/hostname` 目录树和 `/export/swap/hostname` 交换文件。

在 Solaris 2 下，这在 `admintool` 的主机管理器下执行。从“类型”（Type）下拉菜单中选择主机域名，并将主机名、IP 地址和以太网地址添加到菜单，并从下拉菜单中选择时区。除交换大小外，其余参数都应该是正确的。为其余部分调整到适当的交换大小，然后点击“添加”（Add）按钮。

其他 UNIX 系统提供了 shell 脚本或管理下拉菜单来添加无磁盘客户端。

## 总结

确保你的 UNIX 系统无故障安装的关键在于提前计划，并使用本章中的指南以及随软件附带的发布说明。这些是你应该计划的内容：

- 你正在安装的系统类型：服务器、单机、无数据（dateless）或无磁盘系统
- 如果必要，谁将作为该系统的服务器
- 每个切片（slice）将位于多大空间以及位于哪块磁盘上
- `root`, `usr`, `var`, `home`, 和 `tmp` 文件系统
- 交换分区
- 该系统的名称和地址：主机名、域名、IP 地址以及（如果适用）NIS 域名
- 你将安装哪些软件包
- 你将从哪里进行安装

有了这些问题的答案，你就可以回答 UNIX 安装程序的问题。从那里开始一切都会自动完成。

## 启动与关机

David Gumkowski 和 John Semencar 著

启动和关闭 UNIX 与大多数系统管理任务不同，区别在于在决定何时操作时，管理员更多地是被动的观察者，而不是主动的参与者。相比于预测问题和需求，更多的是警惕和知情的理解。启动时输出到系统控制台会产生关于正在发生什么的丰富信息。最重要的是，它显示了哪些设备正在运行。

### 启动

从基本意义上说，启动 UNIX 是一种有序的方法。这些任务通常包括：

HP-UX、IRIX、Linux、Solaris 等系统都使用非常灵活的 `init` 进程，该进程根据名为 `/etc/initab` 的文件创建定向的任务。`init` 的通用参数所示：

| 级别 | 描述 |
| :--- | :--- |
| 0 | 将机器关闭到停止状态。机器进入 PROM 监器模式或关机状态。 |
| 1 | 将机器处于系统管理模式。所有文件系统仍然可访问。只有超级用户控制台可以访问系统。 |
| 2 | 将系统处于正常的多用户运行模式。 |
| 3 | 将系统处于用户定义的多用户运行模式。同时启用远程文件共享。启动额外的守护进程以允许远程文件共享、挂载资源并发布远程资源（如 NFS）。 |
| 4 | 将系统处于用户定义的多用户模式。对于 HP-UX，会激活 HP VUE（视觉用户环境），这是一个利用 X 的强大图形化环境和应用程序集。 |
| 5 | 与级别 0 类似，系统将不会尝试关机。 |
| 6 | 关闭机器然后重启到级别 2 或 3。 |
| a,b,c | 真实情况并非它们不改变运行级别。基本上，运行级别是由一组程序提供的。 |
| s | 启动单用户模式。如果 `initab` 文件丢失或损坏，则选择相应的运行模式。 |
| Q/q | 不运行级别。使用当前级别并重新检查 `initab` 文件。这是一种在不实际重启系统的情况下执行初始化的方法。 |

列表 16.2 显示了一个简化的 `init` 文件。

#### 列表 16.2. 简化的示例 init 文件。

```
strt2:initdefault:
level0:wait:/etc/rc0 > /dev/console 2>&1 < /dev/console
level2:wait:/etc/rc2 > /dev/console 2>&1 < /dev/console
level3:wait:/etc/rc3 > /dev/console 2>&1 < /dev/console
level6:wait:/etc/rc6 > /dev/init.d/announce restart
io:system:/sbin/init
nbrcl:bootwait:/sbin/bcheckrc < /dev/console 2>&1
cons123456:respawn:/usr/sbin/get console 2>&1
powf:powerwait:/sbin/powerfail > /dev/console 2>&1
```

该文件中 `init` 文件的通用形式为：

```
identifier:run-level-action-keyword: process
```

`identifier` 是一个长度为四个字符的字符串，用于唯一标识条目。应使用两个字符的标识符，因为 PTY 设备可能会与标识符冲突。这最终将导致记录所有已登录用户的 `utmp` 文件损坏。

运行级别（run level）是之前描述的 `init` 参数的一个或多个，或者留空表示所有级别。取决于你的系统，2 或 3 的默认运行级别是共同的。运行级别 1 通常留给系统安装等特殊任务。当 `init` 更改级别时，所有属于请求层级的进程最终都会被杀死。该规则的例外是 a, b, c 启动命令。

注意：HP 系统管理员使用 `SAM` 来关闭系统并更改当前运行级别。`SAM` 是 HP 的系统管理工具，可以在其图形或基于字符的配置中调用。

动作关键字（action keyword）定义了 `init` 执行的操作方案。值及其含义见表 16.1。

#### 表 16.1. 动作关键字表。

| 动作关键字 | 动作 | 等待 | 重启 |
| :--- | :--- | :--- | :--- |
| boot | 仅在系统启动期间执行。 | NO | NO |
| bootwait | 系统启动后从单用户切换到多用户时执行。 | Yes | No |
| initdefault | 随此启动启动。忽略进程字段。如果级别为空，默认运行到级别 6。 | N/A | N/A |
| off | 杀死给定级别中的进程。如果进程不存在则忽略。 | N/A | N/A |
| once | 运行一次进程。 | No | No |
| demand | respawn a,b,c 类型的同义词。 | No | No |
| powerfail | 在电源重启时运行进程。 | No | No |
| powerwait | 在请求电源时运行进程。 | Yes | No |
| respawn | 如果进程不不存在，则启动它。如果进程存在，则什么都不做。 | No | Yes |
| sysinit | 在将登录提示设置为系统控制台之前运行进程。 | Yes | No |
| wait | 运行一次进程。 | Yes | No |
| ctrlldel | (仅限 Linux.) 键盘上按下了该序列。关机。 | No | No |
| krequest | (仅限 Linux.) 键盘产生的请求。此定义不明。 | | |
| powerokwait | (仅限 Linux.) 电源恢复。 | Yes | No |

进程是任何守护进程、可执行脚本或程序。此进程可以调用其他脚本或二进制文件。假设系统电源重启到运行级别 2。运行级别 0（关闭）、6（重启）和 1（单用户）将执行所有脚本 `/etc/rc0`，该脚本会调用子脚本。运行级别 2 或 3（扩展多用户）也会执行 `/etc/rc3` 脚本。运行级别 6（重启）也会通过执行 `/etc/init.d/announce` 脚本发生某些操作。对于任何运行级别，在控制台给出登录提示之前检查内核和 I/O 配置的一致性。对于从单用户切换到多用户的运行级别，执行 `/sbin/fsck` 进行系统一致性检查。对于运行级别 1-6，如果不存在则启动它。对于任何请求的运行级别，运行 `/sbin/powerfail`。BSD 使用 `init` 进程根据如何调用它来更改状态。例如，从多用户模式回到单用户模式，超级用户将 `kill -1`。表 16.2 列出了这些信号。

#### 表 16.2. kill 命令使用的信号。

| :--- | :--- | :--- |
| Hang-up | HUP | 01 |
| Terminate | TERM | 15 |
| Interrupt | INT | 02 |
| Trap/Stop | TSTP | 24 |

### 启动守护进程和程序
