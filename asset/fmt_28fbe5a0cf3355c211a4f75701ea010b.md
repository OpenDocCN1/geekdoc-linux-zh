
同样，在命令行上定义的变量通过 `MAKEFLAGS` 传递给子 make。`MAKEFLAGS` 值中包含 `='` 的单词会被 make 视为变量定义，就像它们出现在命令行上一样。参见第 9.5 节 [覆盖变量]，第 93 页。

选项 `-C`、`-f`、`-o` 不放入 `MAKEFLAGS` 中；这些选项不会向下传递。

`-j` 选项是一个特殊情况（见第 5.3 节 [并行执行]，第 43 页）。如果你将其设置为某个数字 `N` 且你的操作系统支持它（大多数 UNIX 系统都支持；否则通常不支持），则父 make 和所有子 make 将进行通信，以确保它们之间同时运行的任务只有 `N` 个。请注意，任何标记为递归的任务（见第 9.3 节 [代替执行命令]，第 91 页）都不计入总任务数（否则我们可能会运行 `N` 个子 make，而没有剩余位置运行任何实际工作！）

如果你的操作系统不支持通信，则 `-j 1` 总是会被放入指定的 `MAKEFLAGS` 值中。这是因为如果 `-j` 选项被传递给子 make，你运行的并行任务将比你请求的更多。如果你带数字参数使用 `-j`（意味着尽可能并行运行尽可能多的任务），它是会被向下传递的，因为多个实例并不多于一个。

如果你不想传递其他标志，你必须更改 `MAKEFLAGS` 的值，如下所示：

```
subsystem:
cd subdir && $(MAKE) MAKEFLAGS=
```

命令行上的变量定义实际上出现在 `OVERRIDEOVERRIDES` 变量中，而 `MAKEFLAGS` 包含对该变量的引用。如果你想正常传递标志，但不想传递命令行变量定义，你可以将 `OVERRIDEOVERRIDES` 重置为空，如下：

```
OVERRIDEOVERRIDES =
```

这样做并没有用处。然而，某些系统对环境的大小有一个很小的固定限制，而 `MAKEFLAGS` 可能会超过这个限制。如果你看到错误信息 'Arg list too long'，这可能是问题所在。（为了严格遵守 POSIX.2，如果 Makefile 中出现特殊目标 `.POSIX`，则 `OVERRIDEOVERRIDES` 不影响 `MAKEFLAGS`。你可能不在意这个。）

为了历史兼容性，还存在一个类似的变量 `MFLAGS`。它的值与 `MAKEFLAGS` 相同，不同在于它不包含行定义，且除非它为空，否则它总是以连字符开头（当 `MAKEFLAGS` 以没有单字母版本的选项开头时，例如 `--warn-undefined-variables`，它也会以连字符开头）。`MFLAGS` 传统被显式用于递归 make 命令，如下所示：

```
subsystem:
cd subdir && $(MAKE) $(MFLAGS)
```

但现在 `MFLAGS` 使这种用法变得多余了。如果你想让你的 Makefile 与旧的 make 程序兼容，请使用这种技术；它在更现代的 make 版本中也能正常工作。

如果你希望每次运行 make 时都设置某些选项（例如 `-k`，见第 9.7 节 [选项摘要]，第 95 页），`MFLAGS` 变量也很有用。你只需要在环境中为 `MFLAGS` 设置一个值。你也可以在 Makefile 中设置 `MFLAGS`，以指定对 make 生效的额外标志。注意，你不能这样使用 `MFLAGS`。该变量仅用于兼容；make 不会解释你设置的任何值。

当 make 解释 `MFLAGS` 的值（无论来自环境还是文件）时，如果该值尚未以连字符开头，它会在前面加上连字符。然后它将该值切分成由空格分隔的单词，并像它们在命令行给出一样解析这些单词（`-C`、`-f`、`-o`、`-W` 及其长格式版本会被忽略；无效选项不会报错）。

如果你在环境中设置了 `MFLAGS`，应确保不要包含任何剧烈影响 make 操作并破坏 Makefile 目的的选项。例如，`-t`、`-n` 和 `-q` 选项可能会产生破坏性后果。

# 第 5 章：在规则中编写命令

## 5.6.4 --print-directory 选项

如果你使用多级递归 make 调用，`-w` 或 `--print-directory` 选项可以通过显示 make 开始和结束处理每个目录来使输出更易理解。例如，如果 `-w` 在 `/u/gnu/make`，make 在执行任何操作之前打印如下格式的内容：

```
make: Entering /u/gnu/make
```

处理完成后打印如下格式的内容：

```
make: Leaving directory /u/gnu/make
```

通常不需要指定此选项，因为 `make` 会为你处理：当在子 make 中使用 `-C` 选项时，会自动开启 `-w`；如果你使用 `-s` 或 `--no-print-directory`，make 则不会自动开启 `-w`。

## 5.7 定义命令序列 (Canned Command Sequences)

当相同的命令序列在多个目标中有用时，你可以使用 `define` 指令将其定义为命令序列，并在这些规则中引用该命令序列。命令序列实际上是一个变量，因此其名称不能与其他变量冲突。

以下是一个定义命令序列的示例：

```
define run-yacc
yacc $(firstword $)
mv y.tab.c $$
undef
```

这里 `run-yacc` 是被定义的变量名；`undef` 标记定义的结束；之间的行就是命令。`define` 指令不会展开命令序列中的变量引用和函数调用；`$` 字符、括号等都会成为你所定义变量的一部分。参见第 6.8 节 [定义变量]，第 65 页以获取 `define` 的完整解释。

此示例中的第一个命令在使用该序列的任何规则上运行 Yacc。Yacc 的输出始终是 'y.tab.c'。第二个命令将输出移动到目标文件名。

要使用命令序列，将变量替换到规则的命令中。你可以像替换其他变量一样替换它（见第 6.1 节 [变量引用基础]，第 55 页）。由于由 `define` 定义的变量会被递归展开，你在 `define` 内部编写的所有变量引用现在都会展开。例如：

```
foo:y
$(run-yacc)
```

当 `foo.y` 在 run-yacc 的值中出现时，它会被替换为 `$`，而 `foo.c` 会替换为 `$$`。这是一个真实的示例，但在实践中不需要，因为 make 有隐式规则根据涉及的文件来确定这些命令（见第 10 章 [使用隐式规则]，第 101 页）。

在命令执行中，命令序列的每一行都被处理为该行单独出现且前面有一个制表符。特别地，make 为每一行调用一个特殊的子 shell。你可以在命令序列的每一行使用影响命令行的特殊前缀字符（`$0`、`-` 和 `+`）。见第 5 章 [在规则中编写命令]，第 41 页。

例如，使用这个命令序列：

```
define frobicate
@echo "frobicating target $$
frob-step-1 $$ -o $$step-1
frob-step-2 $$step-1 -o $$$
undef
```

make 不显示第一行 echo 命令。但它会显示以下两个命令行。

另一方面，命令行命令行的前缀字符适用于序列中的每一行。因此，规则：

```
frob.out: frob.in
$(frobicate)
```

不会显示任何命令。（参见第 5.1 节 [命令显示]，第 41 页以获取 '@' 的完整解释）。

## 5.8 使用空命令

定义不执行任何操作的命令有时是有用的。这只需给出一个仅由空白字符组成的命令即可。例如：

```
target:
```

为 'target' 定义了一个空命令字符串。你也可以使用以制表符开头的行来定义空命令字符串，但这会引起困惑，因为这样的行看起来是空的。

你可能会奇怪为什么要定义一个不执行任何操作的命令字符串。唯一的用处是防止目标获取隐式命令（来自隐式规则或 .DEFAULT 特殊目标；见第 10 章 [隐式规则]，第 101 页，以及第 10.6 节 [定义最后的默认规则]，第 116 页）。

你可能倾向于为并非实际文件的定义空命令字符串，这些目标仅是为了让它们的先条件重新构建。然而，这不是最好的方法，因为如果目标文件确实存在，先条件可能无法被正确重新构建。参见第 4.4 节 [伪目标]，第 27 页以获取更好的方法。

# 第 6 章：如何使用变量

## 如何使用变量

变量是 Makefile 中定义的一个名称，用于表示一段文本，称为变量的值。这些值通过显式请求被替换到目标（targets）、前提（prerequisites）、命令（commands）以及 Makefile 的其他部分。（在 make 的版本中，变量被称为宏）。

Makefile 中所有部分的变量和函数在读取时都会展开，但规则中的 shell 命令、使用 `=` 定义变量的右侧部分，以及使用 `define` 指令定义变量的主体除外。

变量可以代表文件名列表、传递给编译器的选项、要运行的程序、查找源文件的目录、写入输出的目录，或你想象的任何其他内容。
