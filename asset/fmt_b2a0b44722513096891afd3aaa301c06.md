
```

- -c [block] Checkpoint。阻塞服务器。
- -D <max> 允许的优先级。
- -d <standard> 主服务器类型。
- -F 释放内存段。
- -k <kbytes> 进入多用户模式。

- -M <decision> 启动或移除特定的类。

- -z <sid> 杀死会话
```

我们感兴趣的三个选项是 `-l`、`-c` 和 `-m`。`-l` 选项强制引擎使用下一个日志，`-c` 告诉引擎执行检查点。检查点在《管理员指南》中有介绍，它们允许日志备份以及如何恢复数据库。`-m` 选项允许我们将服务器带回模式。我们不仅需要将当前活动移动到新日志，还需要执行检查点以释放旧日志以便删除。引擎在删除旧日志之前应该完全在新日志上。执行以下命令显示引擎正在使用新日志。在我们的情况下，需要执行三次。运行 `onmode -c` 三次后的输出如下：

既然当前日志是新的而不是旧的，你可以删除旧的：

```
$ onparams -d l 1 -y

$ onparams -d l 2 -y

$ onparams -d l 3 -y

$ onparams -d l 4 -y

$ onparams -d l 5 -y
```
前面的命令对日志 1 到 6 重复。在这里我们看到最后一个日志 6 的 `onparams` 命令，我们的 `onstat-l` 命令显示了缺失的：

```
$ onparams -d l 6 -y
```
