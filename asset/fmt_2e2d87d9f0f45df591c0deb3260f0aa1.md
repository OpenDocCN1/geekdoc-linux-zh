# 建议

## 1 初始设置

本节中的项目建议所有系统使用，但在系统初始设置后可能变得困难或需要大量的准备。

### 1.1 文件系统配置

用于系统级函数的目录可以通过将它们放置在单独的分区上来进一步保护。这可以提供防止资源耗尽的保护，并允许使用适用于目录预期用途的挂载选项。用户数据可以存储在单独的分区，并具有更严格的挂载选项。用户分区是为用户使用建立的、且不包含系统操作软件的文件系统。

本节中的建议在初始安装期间更容易执行。如果系统已经安装，建议在重新划分系统之前进行完整备份。

**注意：** 如果您正在对已安装的系统进行重新分区，请确保数据已复制到新分区，卸载旧分区，然后从旧分区的目录中删除数据。否则，它仍然占用旧分区的空间，而这些空间在挂载新文件系统时会被屏蔽。例如，如果系统处于单用户模式且没有挂载任何文件系统，管理员向 `/tmp` 目录添加了大量数据，那么在挂载 `/tmp` 文件系统后，除非将其删除，否则这些数据仍然会占用 `/` 的空间。

#### 1.1.1 禁用未使用的文件系统

`Linux` 支持许多不常用的文件系统类型。移除对不需要的文件系统类型的支持可以减少系统的本地攻击面。如果不需要某种文件系统类型，应将其禁用。原生 `Linux` 系统设计用于确保内置的安全控制按预期运行。非原生系统可能会对系统的安全性和功能产生意外后果，应谨慎使用。许多文件系统是为了小众用例而创建的，随着操作系统的更新和补丁，它们不再得到维护和支持。非原生文件系统的用户应确保对其进行关注和持续支持，特别是考虑到操作系统频繁的变动。

标准的网络连接和对云存储的 `Internet` 访问使得使用非标准文件系统格式直接附加异构设备变得不那么有吸引力。

**注意：** 这不应被视为文件系统的完整列表。您可能希望根据您的环境增加此处列出的内容。有关系统当前可用的文件模块，请查看 `/usr/lib/modules/$(uname -r)/kernel/fs`

##### 启动脚本

直接通过 `insmod` 加载的内核模块将忽略相关 `/etc/modprobe.d/*.conf` 文件中的配置。如果在重启后，在已正确配置 `blacklist` 和 `install` 命令的情况下模块仍在加载，请检查启动脚本（如 `.bashrc` 中的 `insmod` 条目。

您可能还想检查 `/usr/lib/modprobe.d/`。请注意，此目录不应用于用户定义的模块加载。确保所有此类条目位于 `/etc/modprobe.d/*.conf` 文件中。

##### 返回值

使用 `/bin/false` 作为禁用特定模块的命令有两个目的：向用户传达该条目的含义，并产生非零返回值。后者可以在脚本中进行测试。请注意，`insmod` 将忽略相关 `/etc/modprobe.d/*.conf` 文件中的配置。

#### 1.1.1.1 确保禁用 cramfs 挂载（自动化）

**适用性：**

- 等级 1 - 服务器
- 等级 1 - 工作站

**描述：**

`cramfs` 镜像是一种嵌入在小型系统中的压缩只读文件系统，可以在无需解压的情况下使用。

**原理：**

移除对不需要的文件系统类型的支持可以减少系统的本地攻击面。如果不需要这种类型，请将其禁用。

**审计：**

运行以下脚本来验证 `cramfs` 是否已禁用：

```bash
#!/usr/bin/env bash
{
  l_output="" output2=""
  l_name="cramfs" # 设置模块名
  # 检查模块是否存在于系统
  if [ -z $(modprobe -n -v "$l_name" 2>&1 | grep -Pi '^\hmodprobe\+FATAL:\hnot\hdirectory') ]; then
    # 检查是否会被加载
    l_loadable=$(modprobe -n -v "$l_name")
    if [ $(wc -l) <<< "$l_loadable" -gt 1 ] && [ $l_loadable="$(grep -P '^\hinstall\\b$l_name\\b') <<< "$l_loadable")" != "(false)" ]; then
      l_output="$l_output\n module: $l_name is not loadable"
      l_loadable=""
    else
      l_output="$l_output2\n module: $l_name is loadable"
    fi
    l_loadable=""
    # 检查当前是否已加载
    if ! lsmod | grep "$l_name" >/dev/null 2>&1; then
      l_output="$l_output\n module: $l_name is not loaded"
    else
      l_output="$l_output2\n module: $l_name is loaded"
    fi
    # 检查是否在黑名单列表中
    if modprobe --config | grep -Pq "^\h*blacklist\h$l_name\\b"; then
      l_output="$l_output\n module: $l_name is deny listed in"
      "$(grep -Pl -- '^\h*blacklist\\h$l_name\\b')" /etc/modprobe.d/*"
    else
      l_output="$l_output2\n module: $l_name is not deny listed"
    fi
    l_output="$l_output\n Module - $l_name 不存在于系统上"
  fi
  # 报告结果。如果 l_output 中没有失败输出，则通过
  if [ -z "$l_output" ]; then
    echo -e "\n- Audit Result:\n ** PASS **\n$l_output\n"
  else
    echo -e "\n- Audit Result:\n ** FAIL **\n 审计失败原因：\n$l_output2\n"
    [ -n "$l_output"" ] && echo -e "\n- 正确设置：\n$l_output\n"
  fi
}
```

#### 1.1.1.2 确保禁用 squashfs 文件系统的挂载（自动化）

**适用范围：**

- 级别 2 - 服务器
- 级别 2 - 工作站

**描述：**

`squashfs` 文件系统类型是一种嵌入在小占用空间中的压缩只读 `Linux` 文件系统。可以直接使用 `squashfs` 镜像，而无需先对镜像进行解压缩。

**原理：**

移除对不需要的文件系统的支持可以减少系统的本地攻击面。如果需要此文件系统类型，请将其禁用。

**影响：**

由于 `Snap` 软件包使用 `squashfs` 作为压缩文件系统，禁用 `squashfs` 将导致 `Snap` 软件包失败。

`Snap` 应用程序软件包是自包含的，并适用于多种 `Linux` 发行版。这与传统的 `Linux` 包管理方法（如 `APT` 或 `RPM`）不同，后者在更新时需要为每个 `Linux` 发行版准备专门适配的包，从而延迟了从开发者到终端用户的部署。`Snap` 本身不依赖于任何外部存储（“应用商店”），可以从任何源获取，因此可用于上游软件部署。

#!/usr/bin/env bash
{
  lname="squashfs" # 设置模块名称
  # 检查系统是否存在该模块
  if [ -z "$(modprobe -n -v \$lname\" 2>&1 | grep -Pi)" then
    echo "FATAL: hmodprobe\$hModule\$lname\/not\found\/h\in\directory"
    exit 1
  fi
  # 修复可加载性
  l_loadable=$(modprobe -n -v \$lname\")
  if [ "$(wc -l < \$l_loadable\")" -gt 1 ] && [ $l_loadable=$(grep -P "^^(hinstall\\bslmod\\) <<\\" <<< \$l_loadable\") ]; then
    echo "- \$lname\" to be not loadable"
    echo "- install \$lname /bin/false"
    rm /etc/modprobe.d/\$lname\.conf
