## WPA-2 (以及 WPA)

这里没有你可以轻松利用的漏洞。我们只有两种选择：要么给出密码，要么欺骗用户把密码交给我们。

1. 猜密码 - 猜某些东西需要两点：猜测（这不用说）和验证。基本上，你需要大量的猜测，并能够验证它们是否正确。最原始的方法是在连接 Wi-Fi 时操作系统提供的密码框中输入猜测。但很慢，因为你必须手动操作。即使你为它编写脚本，也需要花费时间，因为每次猜测都要与 AP 通信（每个猜测多次）。基本上，通过向 AP 请求进行验证是缓慢的。那么，是否有方法可以在不询问 AP 的情况下检查密码的正确性？有的，但前提是你有四次握手。基本上，你捕捉有效客户端连接到 AP 时传输的一系列数据包。如果你有这些数据包（四次握手），就可以针对它验证你的密码。关于这有更多细节，但我希望这个抽象的概念是清晰的。猜测密码有几种不同的方式：
    - 暴力破解 - 尝试所有可能的密码。只要时间足够，这保证会有效。然而，对于 8 位长度的字母数字密码，暴力破解所需的时间非常长。
    - 词列表/字典 - 在这种情况下，有一份作为密码候选的单词列表。这些词列表包含英语单词、单词组合、拼写错误……单词，等等。存在许多巨大的词汇表，大小可达几个 GB，许多网络可以使用它们来破解。然而，并不能保证你正尝试破解的网络其密码就在列表中。
    - **彩虹表 (Rainbow table)** - 我之前提到的针对四次握手的验证过程涉及对明文进行哈希处理，并将其与握手中的哈希值进行比较。然而，哈希计算（WPA 使用 PBKDF2）是一项 CPU 密集型任务，是限制测试密钥速度的因素（这就是为什么有许多工具使用 GPU 而不是 CPU 来加速破解的原因）。现在，一种可能的解决方案是，创建词汇表/字典的人也可以将明文密码转换为哈希值，这样就可以直接进行检查。遗憾的是，WPA-2 在哈希处理时使用了“盐”（salt），这意味着如果两个网络使用相同的密码但使用了不同的盐，它们的哈希值也会不同。WPA-2 是如何选择盐的？它使用网络名称（SSID），因此相同的密码会有相同的盐。所以，现在制作词汇表的人必须为所有可能的 SSID 创建单独的哈希值。在实践中，发生的情况是为最常见的 SSID（路由器如 -linksys、netgear、belkin 等时的默认值）生成哈希。如果目标网络具有其中一个 SSID，使用预计算的哈希将显著减少破解时间。这些预计算的彩虹表可能比词汇表大得多，虽然我们节省了破解密码的时间，但我们必须使用大得多的文件（有些达数百 GB），而不是较小文件。这被称为**内存权衡 (time-memory tradeoff)**。此页面拥有 1000 个常用 SSID 的彩虹表。
2. **欺骗用户让你提供密码**。基本上这只是中间人攻击和社交工程攻击的结合。更具体地说，它是邪性孪生（evil twin）和钓鱼攻击的结合。在这种攻击中，你首先强制客户端从原始 WPA-2 网络断开连接，然后向他的浏览器发送一个登录页面，你在页面要求他输入网络密码。你可能会奇怪，为什么我们需要保持开放网络并在浏览器中请求密码（我们不能直接创建一个 WPA-2 网络并让用户直接给我们密码吗）？答案在于 WPA-2 在四次握手期间执行双向认证。基本上，客户端验证 AP 是合法的且知道密码，而 AP 验证客户端是合法的且知道密码，该过程从未以（明文）发送。
3. 额外奖励：WPS 漏洞和 `reaver` [我已单独详细介绍过，所以不再解释（我只是个人，而且是非常懒的人）]

# 3 网络基础：IP 地址、子网掩码和子网

## IP 地址

IP 地址简单来说是任何网络（使用 IP 协议）上的每个设备都必须的 32 位地址。它通常以十进制形式表示，因为二进制写法太麻烦了。例如：

十进制表示：192.168.1.1

二进制：11000000.10101000.00000001.00000001

IPv4 地址（点十进制表示）![](img/bf9c24bf1435c4e9031e4256.png) 从二进制形式来看，IP 确实是 32 位。范围从 0.0.0.0 到 255.255.255（分别为全 0 和全 1）。

## IP 地址组成

现在这个 IP 地址有两个部分：网络地址和主机地址。许多路由器保留前几个字节（8 位）作为网络地址，最后一个字节作为主机地址。一个常见的配置是 192.168.1.1。在这里，192.168.1.0 是网络地址，0.0.0.1 是主机地址。你可以看到主机地址可以从 0 到 255 变化（尽管 0 和 255 被保留）。

## 子网掩码

但不同的网络有不同的需求。之前的配置让你有很多可能的网络（不仅仅是 192.168.1.0，而是大于 255）。这就是为什么网络和主机地址没有“硬编码”标准，而是可以自行指定。使用子网掩码，我们可以为每个需求提供灵活的配置。子网掩码用于将 IP 地址划分为子网。

我们将从基础示例开始。假设我们要定义一个类似于之前示例的掩码。希望前三个字节对应网络，下一个字节对应主机地址。让我们考虑用于分离 IP 地址网络和主机的操作。为了简单，我们可以定义第三段之后的任何内容作为主机地址。虽然这是一个简单的解决方案，但它并不灵活。

一种更优雅的数学解决方案被提出。首先，我告诉你子网掩码的数学功能。假设 `A` 为 IP 地址，`M` 为子网掩码。那么 `A & M` 得到网络地址，`A (~M)` 得到主机地址。其中，`&` 是按位与（And），`~` 是按位非（Not，即补码）。

### 示例

`A = 192.168.1.1` 是你的 IP 地址

`M = 255.255.255.0`

将其转换为二进制并执行所需的操作。

`A = 11000000.10101000.00000001.00000001 (192.168.1.1)`

`M = 11111111.11111111.11111111.00000000 (255.255.255.0)`

`A&M = 11000000.10101000.00000001.00000000 (192.168.1.0)`

`A&M` 是我们需要的网络 IP。

`A = 11000000.10101000.00000001.00000001 (192.168.1.1)`

`~M = 00000000.00000000.00000000.11111111 (0.0.0.255)`

`A&~M = 00000000.00000000.00000000.00000001 (0.0.0.1)`

`A&~M` 是我们需要的主机 IP。

### 解释

基本上，如果你意识到 11111111 在十进制中是 255，那么你就可以对于你想要的网络 IP 部分，将子网设置为 255，而对于你主机的部分，将其设置为 0。

所以，如果你想为网络预留 2 个字节，为主机预留 2 个字节，那么子网将是：

`M = 255.255.0.0`

如果你想为主机预留 3 个字节，那么：

`M = 255.0.0.0`

因此，我们可以看到使用子网掩码可以实现我们想要的，即定义具有我们所需的任意主机数量的网络。现在我们更进一步。

## 子网

现在假设你想将你的网络分成部分。这些子网络被称为子网（subnets）（称它们 subnetwork 也是正确的）。

我们直接进入主题，考虑子网掩码 `M`：

`M = 11111111.11111111.11111111.11000000`

现在，前 3 个字节描述了网络。但第四个字节（本应用于主机）的 2 个最高位（即最左侧位）为 1。因此，当我们执行位与操作时，第四个字节的两个最高位（最左侧位）将显示出来。因此它们将成为网络地址的一部分。然而，它们属于主机字节。因此，这两个属于主机字节但出现在网络 IP 地址中的位将网络划分为子网。
