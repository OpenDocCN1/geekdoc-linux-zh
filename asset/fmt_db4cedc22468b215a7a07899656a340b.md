
典型的 Unix 命令努力在完全没有人工干预的情况下执行任务。大多数命令只在准备执行某些可能不可逆的操作时（例如通过删除文件来“修复”文件系统）才会提示用户。因此，Unix 命令始终以最高速度运行。这就是为什么为了可移植性而非效率设计的系统仍然运行良好的原因之一。它意识到，在性能方面，许多人机交互中的薄弱环节并非机器。

## 6.1.2 UI 命令解析器通常庞大且丑陋

解析器读取用户的输入并将其翻译成应用程序软件可以理解的格式。它必须正确读取用户可能（甚至可能不可思议地！）输入的任何内容。这导致典型的命令解析器增长到巨大的规模。有时，命令解析器所需的编程工作比应用程序的主任务还要多。

考虑这个例子。假设你有一个格式化磁盘的程序。由于丢失数据的风险很大，你可能认为用户是否真的想擦除磁盘上的所有内容是“用户友好”的：

```
FORMAT V1.0 Rev.A
About to format drive C:
Formatting will destroy all files on the disk:
Begin format? <y|N>
```

对这类提示的潜在用户响应数量是是惊人的。首先，如果用户想继续格式化，他可能会输入 Y、y、Yes、Yes 或它们之间的各种组合。同样，如果他确定不想继续，他可能会输入 N、n、no 或 NO。这些响应相当容易解析。

复杂性在用户并不完全确定自己想做什么时开始。一个不老练的用户可能会输入“help”以获得一些信息。一个经验用户可能会输入“?”来获取选项列表。虽然这在理论上听起来不错，但许多 GUI（尤其是大型 GUI）之间的交互并不良好。

## 6.1.5 CUI 的扩展性较差

CUI 在处理少数实例时往往运行良好。通过限制选择，它们可以让没有经验的用户更轻松地完成复杂任务。只要实例不是太多，用户通常很乐意响应提示。然而，当人们必须响应成百上千个提示时，提示的数量就会变得难以应付。

许多 Unix 系统供应商提供的一个流行程序（实际上说是一个 shell 脚本）是 `adduser`。它允许系统管理员通过一个“用户友好”的 CUI 向系统添加新用户账户。在大多数情况下，它是有效的。但当你必须一次添加（例如）一千个用户时，`adduser` 的问题就变得显而易见了。

曾有一所大学决定从另一种操作系统切换到 Unix 系统，数千个用户账户被迁移到了新系统中。由于系统管理员很快就意识到，多次运行 `adduser` 将是行不通的。他们最终确定了一种解决方案，将用户账户文件从旧系统移动到 Unix 系统。然后，他们写了一个 shell 脚本将这些文件转换为类似于 Unix 密码的文件。讽刺的是，编写此版本的 shell 脚本比 `adduser` 还要短。

## 6.1.6 最重要的是，CUI 没有利用软件杠杆

由于 UI 程序预计在某些时刻与人类通信，因此很难将它们整合到 shell 脚本中。shell 脚本中需要许多行代码来执行 CUI 需要的那些对话。这些对话在 shell 脚本中编写可能是如此困难，以至于程序员通常诉助于小型用户界面程序来进行是否查询并从用户处获取其他响应。

由于 CUI 阻碍了与其他程序的交互，它们通常只用于其原始用途，没有其他作用。尽管你可能会认为这只是“把一件事做好”的例子，但 CUI 与小型 Unix 命令的区别在于，它是作为一个独立的应用程序存在的。它不提供与其 Unix 对应品相同的混合和即插即用功能。结果是它在软件杠杆方面的收益微乎其微。

没有软件杠杆，CUI 程序无法放大其对计算机世界的影响——以及其开发者的影响。虽然一个 CUI 程序在发布时可能因为其新颖性获得早期追随者，但随着软件世界的不断发展，它很快就失去了吸引力。软件进步在计算机领域每天都在出现，每十年中都有少数想法引起了巨大的动荡。单式的 CUI 程序无法在快速演变的环境中适应。

## 原则九：让每个程序成为过滤器

### 6.2.1 自从计算诞生以来编写的程序都是过滤器

每个程序——无论简单复杂——都以某种形式接受数据作为输入，并以某种形式产生输出。程序对呈现的数据过滤取决于其算法。

大多数人接受作为文本格式化和翻译器的程序可以被认为是过滤器，但他们很难意识到同样适用于其他未被视为过滤器的程序。例如，实时数据采集系统定期采样模拟数字转换器以为其输入流收集数据。然后它们选择这些数据的适当部分并将其传递到输出流，以接口其他应用程序或进行存储。

GUI 也充当过滤器吗？绝对是。GUI 通常处理鼠标按钮或按键事件为“事件”。这些事件形成了馈给受窗口系统控制的屏幕输入的数据流。应用程序作为过滤器，对这些事件做出响应，影响显示的变化。

还有关于由于硬件错误而失败的程序的问题。假设程序在从磁盘读取时遇到硬错误。当它尝试执行读取操作时，并没有得到数据，而是接收到一个错误状态。大多数情况下，它会过滤错误指示并向用户产生错误消息。换句话说，错误状态作为输入产生错误消息作为输出。

### 6.2.2 程序不创建数据——人创建数据

人们通常认为他们的应用程序创建数据，但实际上应用程序无法制造数据。数据合成需要创造力。它需要原始信息源。计算机没有原始信息源。
