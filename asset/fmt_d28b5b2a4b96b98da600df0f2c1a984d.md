使用 `mget` 和 `mput` 命令可以一次移动多个文件。如果你想下载所有以 `.html` 结尾的文件，输入 `get *.html`。相应地，服务器会提示你确认每一个文件。你可以通过 `prompt` 命令切换验证的开启和关闭。

## 二进制与 ASCII 传输

二进制传输和 ASCII 传输之间的区别是用户困惑的一个大源头，这是由于对回车符和换行符的处理方式不同。DOS 和 Unix 系统在如何标记行结束符上一直存在分歧，正如你在这两个系统之间移动文件时可能注意到的那样。互联网上可以找到许多详细描述该问题的文档，以及许多宣布其中一方“完全错误”的文章。你只需要知道如何与这个问题共处，并继续你的生活即可。

虽然你可以在二进制模式下传输二进制和文本文件，但你不能在 ASCII 模式下传输二进制文件。Unix 类系统默认使用二进制传输，而基于 Windows 的系统默认使用 ASCII。你可以通过 `bin` 命令告诉 FTP 服务器使用二进制传输，通过 `asc` 命令使用 ASCII 传输。二进制模式适用于一切，因此请对所有 FTP 传输都使用二进制模式，这样你就永远不会遇到这个问题了。

## FTP 服务器

现在你已经知道如何使用 FreeBSD FTP 客户端，让我们来看看如何提供 FTP 服务。你的首要任务是决定是运行你的 FTP 守护进程 `ftpd(8)`、`inetd(8)` 还是以独立模式运行。

FreeBSD 默认通过 `inetd(8)` 运行 FTP 守护进程。大多数系统不会收到很多 FTP 请求，`inetd` 可以轻松地处理到达的少数请求。如果你不需要支持多个并发 FTP 会话，`inetd(8)` 效果良好。取消 `/etc/inetd.conf`（见第 15 章）中的 FTP 行并重启 `inetd`。对 `ftpd(8)` 命令行的任何更改都可以在 `inetd.conf` 中进行。

然而，如果你的服务器处理数百或数千个并发连接，从 `inetd` 运行 FTP 会增加系统开销。你可能希望在独立模式下设置 FTP，使其永久监听网络并处理空闲请求。确认 `ftpd(8)` 没有在 `inetd` 之外运行，并在 `/etc/rc.conf` 中设置 `ftpd_enable=YES`。然后你可以通过 `/etc/rc.conf` 启动 `ftpd(8)`。

你可以通过命令行标志以许多不同的方式调整 `ftpd(8)`。将这些标志添加到 `/etc/inetd.conf` 中的 `ftpd(8)` 行，或添加到 `/etc/rc.conf` 中的 `ftpd_flags` 中。现在，让我们看看 FreeBSD FTP 提供的功能。

## 记录 ftpd(8) 使用情况

`ftpd(8)` 有两个级别的日志记录。如果你指定 `-l`（这是 `/etc/inetd.conf` 中的默认值），`ftpd(8)` 将记录所有成功和失败的登录尝试。如果你指定两次，`ftpd(8)` 将记录所有的 FTP 活动：下载、上传、目录创建和销毁等。

## 只读模式

你可能想防止 FTP 用户上传文件。这对于提供下载服务的服务器（如镜像站）很有用。使用 `-r` 标志来设置此行为。

## 只写模式

可能你希望用户只能上传文件而不能下载。在这种情况下，使用 `-o` 标志。

## 超时

默认情况下，如果用户让 FTP 会话空闲 15 分钟，连接将被断开。你可以使用 `-t` 标志设置新的空闲超时。

运行 FTP 服务器有两个常见担忧：它可以允许用户下载任意文件，以及密码可能被嗅探。你不希望你的服务器因为某些恶意用户而受到损害。控制用户的最佳方法是选择哪些用户可以登录以及哪些目录可以被访问。

## Chroot 用户

你可以使用 `chroot(8)` 将 FTP 用户锁定在自己的家目录中。对于用户来说，他们的家目录看起来就像文件系统的顶端。他们将无法离开家目录或访问任意文件。这就像一个小型的监狱。`chroot` 对于 Web 服务器非常有用。

## 限制 sftp(1) 和 scp(1)

最后，简单说一下 `sftp(1)` 和 `scp(1)`。这些是运行在 SSH（见第 15 章）之上的文件传输服务，为数据传输提供身份验证、完整性和不可否认性。`sftp` 是 FTP 的安全替代方案，而 `scp` 则替代了 `rcp(1)`。用户向服务器传输文件时可以使用这些协议。

系统管理员面临的一个问题是对这些服务的用户进行 chroot（根目录限制）。虽然为用户提供一个安全的加密连接来传输他们来自服务器各处的随机文件是件好事！但对于这些用户，我推荐使用 `scponly` (/usr/ports/shells/scponly)。设置 shell 为 `/usr/local/bin/scponly` 的用户将只有对你的服务器的 `sftp` 和 `scp` 权限。

既然你已经可以提供网站和 FTP 数据，让我们花些时间了解 FreeBSD 的磁盘层。欢迎来到 GEOM！

# 第 18 章 使用 GEOM 的磁盘技巧

![](img/b00144f770bf509a54e1d770bb05a101_560_0.png)

FreeBSD 有一个极其灵活的磁盘管理系统，称为 GEOM。GEOM 是一个基础设施系统，允许内核开发人员为不同的磁盘功能轻松编写模块，称为 GEOM 类。FreeBSD 使用 GEOM 支持磁盘加密、日志记录、多种不同类型的 RAID 以及跨网络导出磁盘设备。GEOM 工具为开发者和系统管理员提供了灵活性、冗余性和易于实现的特性。我们将带你了解 FreeBSD 的磁盘分区工具，然后介绍几种流行的 GEOM 类。

在本章中，我们将对磁盘设备进行实验。每当你接触磁盘的布局或格式时，你就面临数据丢失的风险。虽然在不影响磁盘其他部分的情况下操作未使用的磁盘空间完全可能的，但学习如何这样做仍然具有风险。请备份你的数据。最好是找到一块未使用的磁盘并在上面学习！（另一方面，在包含你最珍数据的磁盘上学习会让你注意力更加集中。）

我们专门讨论了用于 i386 和 amd64 系统的磁盘格式。其他平台的磁盘管理系统略有不同。Sparc 使用磁盘的 `disklabel`，但没有切片表。ia64 平台基于 GPT 进行切片，而对 ARM 磁盘进行分区是 FreeBSD 在该硬件上运行最简单的部分。

## GEOM 基础

GEOM 是一个通用框架，允许对存储设备进行几乎任意的分层。不同的 GEOM 模块以各种方式转换存储设备。此外，这些模块是可堆叠的；一个的输出可以作为另一个的输入。你想让你的硬盘镜像？没问题。把网络也镜像呢？没问题。如果驱动器被加密，同时它又是网络镜像的呢？当你想要些困难的事情时再叫醒我吧，哥们。记住，FreeBSD 并不保证通过过多的 GEOM 层能获得巨大的性能，但它是可以实现的。

GEOM 将存储设备分为消费者和提供者。消费者位于模块下方，而提供者则为下一层提供服务。例如，你正在使用一个 GEOM 类将硬盘 `/dev/da0` 和 `/dev/da1` 镜像到虚拟磁盘 `/dev/mirror/mirror0`。这些设备被 FreeBSD 磁盘消费，而组合后的设备 `/dev/mirror/mirror0` 是一个为下一层提供服务的提供者。

FreeBSD 以相同的方式看待所有提供者。物理磁盘只是另一个提供者。也许你正在右侧放置一个文件系统，或者 `/dev/mirror/mirror0` 是 GEOM 磁盘加密模块的消费者。无论何种，要使用 FreeBSD 的任何高级磁盘功能，你必须对硬盘管理有进一步的了解。

## 磁盘驱动 102

从历史上看，磁盘上的数据可以映射到硬盘上的某个位置。这个位置可以用柱面、道和扇区来表示。记住，每个硬盘由一堆磁盘盘组成。每个磁盘盘都有一系列圆环，称为道，像树的年轮一样排列。这些道以 0 和 1 的字符串形式存储数据。磁头在距离磁盘中心特定距离的某条道上移动，并在盘片在其下方旋转时读取这些内容。当你从某个特定的道请求数据时，磁头会移动位置并让该道经过它，捕捉数据，就像父母在旋转的木马秋千上可能抓住旋转的孩子一样。

如果你将所有磁盘盘上的道堆叠在一起，你就得到了一个柱面。每个磁盘盘最内层的道形成柱面 0。下一个最内层的是柱面 1。每个磁盘盘的第 1603 条道是柱面 1602。许多操作系统期望发现磁盘切片包含柱面，如果不是，它们会非常生气。

每条道都被划分为段、扇区或块，每个块可以容纳一定的数据（多年一直是 512 字节）。道内的每个扇区都有一个唯一的编号，从 1 开始。

因此，扇区组合成道，道堆叠成柱面，柱面组合起来描述磁盘的*几何结构*。这看起来足够简单了，如果你可以依靠它的话就确实如此。

当硬盘信息到达用户手中时，它可能已经经过了一次或多次转换。无论是在本地 RAID 卡上还是来自 SAN，几何信息显然是假的。重要的是理解这些是如何结合在一起的。

## 磁盘切片

许多操作系统尝试根据几何结构进行优化。FreeBSD 以两种方式划分磁盘：切片和分区。记住第 8 章，FreeBSD 将磁盘分为切片和分区。切片是磁盘的划分，而分区是切片的划分。

切片是磁盘的逻辑划分，分区是切片的物理划分。一个切片可以包含多个分区，一个分区可以包含多个扇区。这就是 FreeBSD 管理磁盘空间。
