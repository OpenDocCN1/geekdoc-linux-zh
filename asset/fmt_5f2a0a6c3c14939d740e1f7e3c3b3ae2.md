
## 将 `/var/tmp` 配置为独立文件系统

允许管理员设置额外的挂载选项，例如 `noexec`/`nosuid`/`nodev`。这些选项限制了攻击者在系统上创建利用程序的能力。其他选项允许特定的行为。有关文件系统无关和特定文件系统的选项的详细信息，请参阅 `man mount`。

### 防止利用

利用 `/var/tmp` 的一个示例可能是攻击者对系统 `setuid` 程序建立硬链接，并等待其更新。一旦程序更新，硬链接就会断开，攻击者将拥有该程序的自己的副本。如果该程序存在安全漏洞，攻击者可以继续利用该已知漏洞。

### 影响

调整文件系统大小是云托管服务器中的常见活动。单独的文件系统分区可能会防止成功的调整大小，或者可能需要仅为了调整大小操作而安装额外的工具。使用这些额外工具会引入它们自身的安全考量。

### 审计

运行以下命令并验证输出显示 `/var/tmp` 已挂载。

示例：

```bash
# findmnt --kernel /var/tmp
TARGET SOURCE FSTYPE OPTIONS
/var/tmp /dev/sdb ext4 rw,reltime,seclabel,data=ordered
```

### 修复

对于新安装，在安装期间创建自定义分区设置并为 `/var/tmp` 指定单独的分区。

对于之前已安装的系统，创建一个新分区并适当配置 `/etc/fstab`。

### 引用

- 1. AJ Lewis, "LVM HOWTO", `http://tldp.org/HOWTO/LVM-HOWTO/`

### 附加信息

修改 `/var/tmp` 时，建议将系统切换到紧急模式（以便审计不运行），重命名现有目录，挂载新文件系统，并在返回多用户模式之前迁移数据。

## 1.1.4.2 确保 `/var/tmp` 分区设置了 `noexec` 选项（自动化）

### 配置适用性

- 等级 1 - 服务器
- 等级 1 - 工作站

### 描述

`noexec` 挂载选项指定文件系统不能包含可执行二进制文件。

### 原理

由于 `/var/tmp` 文件系统仅用于临时文件存储，确保用户无法从 `/var/tmp` 运行可执行二进制文件。

### 审计

验证 `/var/tmp` 上设置了 `noexec` 选项。

运行以下命令并验证输出：

示例：

```bash
# findmnt --kernel /var/tmp
/var/tmp /dev/sdb ext4 rw,reltime,seclabel,data=ordered
```

### 修复

如果存在 `/var/tmp` 分区，配置 `/etc/fstab` 以包含 `noexec` 选项。

### 引用

- 关于文件系统无关和特定文件系统的选项的详细信息，请参阅 `man mount`。

## 1.1.4.4 确保 `/var/tmp` 分区设置了 `nodev` 选项（自动化）

### 配置适用性

- 级别 1 - 服务器
- Level 1 - 工作站

### 描述

`nodev` 挂载选项指定文件系统不能包含特殊设备。

### 原理

由于 `/var/tmp` 文件系统并非用于支持设备，因此设置此选项可确保用户无法在 `/var/tmp` 中创建块设备或字符特殊设备。

### 审核

验证 `/var/tmp` 挂载点是否设置了 `nodev` 选项。

运行以下命令来验证是否设置了 `nodev` 挂载选项。

示例：

```bash
# findmnt --kernel /var/tmp
/var/tmp /dev/sdb ext4 rw,nosuid,nodev,noexec,relatime,seclabel
```

如果产生了输出，请确保其包含 `nodev` 选项

### 修复

如果存在 `/var/tmp` 分区，请编辑 `/etc/fstab` 文件，并在 `/var/tmp` 分区的第四字段（挂载选项）中添加 `nodev`。

示例：

| <device> | /var/tmp | <fstype> | defaults,rw,nosuid,nodev,noexec,relatime | 0 |

运行以下命令使用配置的选项重新挂载 `/var/tmp`：

```bash
# mount -o remount /var/tmp
```

## 1.1.5 配置 `/var/log`

`/var/log` 目录用于系统服务存储日志数据。

## 1.1.5.1 确保 `/var/log` 存在独立分区（自动化）

### 配置适用性

- 级别 2 - 服务器
- Level 2 - 工作站

### 描述

`/var/log` 目录被系统服务用于存储日志数据。

### 原理

将 `/var/log` 挂载在独立分区上的理由如下：

**防止资源耗尽**

默认安装创建一个单个 `/` 分区。由于 `/var/log` 目录包含可能变得非常大的日志文件，存在资源耗尽的风险。它本质上会占用整个磁盘直到填满并影响整个系统。

**对挂载进行精粒度控制**

将 `/var/log` 配置为独立的文件系统允许管理员设置额外的挂载选项，例如 `noexec`/`nosuid`/`nodev`。这些选项限制了攻击者在系统上创建利用程序的能力。其他选项允许特定的行为。有关文件系统独立和文件系统特定选项的详细信息，请参见 `man mount`。

**日志数据保护**

由于 `/var/log` 包含日志文件，应确保数据和挂载点的安全性和完整性。

### 影响

调整文件系统大小是云托管服务器的常见活动。独立的文件系统分区可能会防止成功扩容，或者可能需要为了扩容操作而安装额外的工具。使用这些额外工具会引入自身的安全考量。

### 修复

对于之前安装的系统，请创建一个新分区并相应地配置 `/etc/fstab`。
