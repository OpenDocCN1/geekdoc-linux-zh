## `UEFI` 和安全启动

当 `UEFI` 被引入以解决使用 `BIOS` 初始化硬件的各种缺陷时，在某些圈子里它遭到了冷淡的接待。其中大部分争议集中在 `UEFI` 的安全启动扩展上，当时这使得消费者难以替换 `Windows 8`（当时新机器正在搭载该系统），甚至无法启动 `Linux` 发行版。许多批评是不公正的。安全启动旨在使管理员能够限制哪些引导加载程序可以运行，以及它们可以启动哪些内核。

大多数 `x86` 硬件预装了微软的安全启动公钥，该密钥仅允许启动微软签名的引导加载程序。一些 `Linux` 发行版提供由微软签名的引导管理器——这里有两种方法：`Fedora` 的 `Shim`（也被 `Ubuntu` 和少数其他发行版使用）以及 `Linux` 基金会的 `PreLoader`。因此，这些发行版可以在安全启动下正常工作，但其他一些发行版可能需要禁用安全启动。不过，如果你对安全启动拥有完全控制权，你可以将你自己的签名密钥注册到固件中，并允许启动你认为配得上的操作系统。

如果你的机器有 `TPM` 芯片，你可以用它来存储例如 `LUKS` 磁盘加密密钥。这些密钥可以与 `TPM` 中的寄存器进行验证，因此即使安全启动了另一个操作系统，磁盘也不会被解锁。

## 强化你的桌面

使用硬件令牌收紧你的登录策略，并使用最新的 `Systemd` 功能强化你的主目录。

`Human` 在生物识别并非天生擅长使用用户名和密码。任何声称电子邮件已死的人，最好回顾一下，电子邮件往往是重置那些我们很少登录的网络服务密码的唯一途径。自然，我们都应该使用密码管理器，这种情况就永远不会发生，但人非圣贤孰能无过。尽管如此，密码还有提供便利性和安全性的替代方案和增强手段。`Linux` 上的主要桌面环境尚未提供 `Windows 10` 的人脸/虹膜解锁功能，但这将会改变。在此期间，我们可以使用多种其他手段登录我们辉煌的桌面和在线服务。

如果你的笔记本电脑和手机具备 `NFC`（近场通信）功能，那么在 `Linux` 上你可能无法做太多事情。然而，`Chromium` 的下一个版本（第 `81` 版）将引入 `Web NFC`，这将使你能够通过手机轻轻一点来验证付款或填写表单。

与此同时，有多种硬件令牌，如 `Nitrokey`、`YubiKey` 和 `Libreem Key`，你可以使用它们来保护登录到 `Linux` 机器和无数在线服务的安全性，无论是基于时间的一次性密码（`TOTPs`）的魔力，还是 `FIDO Universal Second Factor (U2F)` 协议。

### 充分发挥 `YubiKey` 的功能

`Yubico` 很慷慨地为本专题提供了一把 `YubiKey 5 NFC`。设置对于其他硬件令牌会有所不同，但结果将是相同的。我们将使用硬件密钥作为第二因素来登录我们的终端或桌面。这种双保险的做法与其他用于 `Web` 服务和应用的双因素认证（`2FA`）方案理念相同——短信是常见的第二因素。对于 `YubiKey`，`Ubuntu` 所需的软件包可以从 `PPA` 获取，其他发行版会有类似的安排（请访问 `https://support.yubico.com` 查看）。在 `Arch` 上，所需的软件包位于主仓库中。使用以下命令添加 `PPA`：

```bash
$ sudo add-apt-repository ppa:yubico/stable
```

并使用以下命令安装 `YubiKey Manager` 和 `PAM` 模块：

```bash
$ sudo apt-get install yubikey-manager-qt libpam-u2f
```

`PAM`（可插拔认证模块）负责在 `Linux` 上处理登录认证，允许开发者不必担心他们的应用如何与系统认证。显示管理器（如 `Gnome` 的 `GDM` 或 `KDE Plasma` 上的 `SDDM`）以及控制台登录都使用 `PAM` 进行认证。顾名思义，可以添加模块以通过其他方式进行认证，例如指纹读取器，或者像我们刚才所做的那样，使用 `U2F` 设备。

插入 `YubiKey`。我们现在的第一个任务是将其与我们的用户名关联，并存储生成的令牌：

```bash
$ mkdir -i .config/yubico
$ pamu2fcfg > ~/.config/yubico/u2f_keys
```

### `SYSTEMD-HOMED`

当我们撰写本文时，最新的 `systemd`（版本 `245`）正在进入更具冒险精神的发行版仓库。在其许多新功能中，`systemd-homed` 尤为突出，因为它（可选地）彻底改变了主目录。传统的静态目录对某些人和某些用途来说运行良好，但对于网络共享等事物来说存在问题，需要某种形式的丑陋 `hack` 才能成功加密。`Systemd-homed` 还负责用户管理，使其控制的 `$HOMES` 完全自包含且可移植。一个合规的 `LUKS2` 卷（位于 `U` 盘上，或 `/home` 目录下名为 `username.home` 的文件），在提供正确的凭证后，将在通常的位置无缝挂载。如果系统挂起，它将被再次锁定。

如果你希望主目录拥有更多的安全性，但尚未准备好放弃旧的方式，那么 `KDE Vault` 可能会引起你的兴趣。它允许你创建加密保险库，可以存储在任何地方，在提供正确的密码后，它们会挂载在你的主目录内。它们的可移植性使其非常适合与 `Nextcloud` 等云服务配合使用。你甚至不需要因为使用专有服务而感到内疚，因为它们不太可能从你的乱码数据中受益。`EncFS` 文件系统甚至不泄露文件大小信息。

### 插入并轻触你的 `YubiKey`

忘掉 `U2F` 吧。现在所有的年轻人都在使用 `Authn` 进行身份验证了。也请忘掉那个 `https` 小锁图标，指纹图标才是当下的趋势。

配置程序正在等待输入，因此请按下密钥上的按钮。如果你还有其他 `U2F` 密钥，你可能也想要注册它们。毕竟，这样设置之后，如果你的密钥丢失或损坏，你将无法登录。对于每个额外的密钥，请将其插入，运行命令：`pam-u2fcfg -a >>~/.config/YubiKey/U2F_keys`，并轻轻敲击以将该密钥添加到我们的配置中。`u2f_keys` 文件可以移出你的主目录以提供额外的安全性，但如果你这样做，就需要在我们即将添加的 `PAM` 指令中添加 `authfile` 参数。

首先，我们将进行一次快速的安全测试，以防设备出现故障，通过测试 `sudo` 命令来进行。期望的结果是，该命令将同时要求正确的密码和连接的 `YubiKey`。运行：`$ sudo nano /etc/pam.d/sudo`，然后输入你的密码以查看相关的 `PAM` 指令。

我们将添加一行，然后保持文件打开状态（这就是为什么这是一个安全测试，所以请仔细注意这部分），同时我们在另一个终端窗口中测试它。这样，如果设备或 `PAM` 模块表现异常，我们就不需要使用 `sudo` 命令（由于异常正在发生，该命令对我们不再有用）来撤销这些更改。如果我们直到将登录管理器绑定到 `YubiKey` 并注销后才发现这个问题，情况就会非常棘手。

在 `@include common-auth` 行下方添加以下内容：`auth required pam_u2f.so` 现在保存，但不要按 `Ctrl-O, Enter` 关闭文件。打开另一个终端并运行：`$ sudo echo It works`

系统会像往常一样提示你输入密码，但如果你输入正确，在你轻触密钥之前什么也不会发生。如果没有成功，请从仍然打开的文件中移除出错的那一行并安全退出，泡杯茶，并考虑其他可用的选项。
