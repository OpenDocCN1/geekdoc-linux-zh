
- `-file.h` 将基名以 `.h` 结尾的文件视为 C 语言头文件。

- `-file.f` 将基名以 `.f` 结尾的文件视为 FORTRAN 语言源码。

## Usage

## Notes

对 FORTRAN 和 Pascal 的函数、子例程和过程的识别是以简单的方式的。没有尝试处理块结构；如果你在不同的块中有两个同名的 Pascal 过程，你就会丢失。

决定查找 C 还是 Pascal 或 FORTRAN 函数的方法是一种取巧的（hack）。

`ctags` 命令不知道 `#defs`。

`ctags` 命令应该知道 Pascal 类型。它依赖于类型定义的输入。使用 `-tx` 仅显示类型定义的最后一行。

## cu — Call Another UNIX System

## Synopsis

```
/usr/bin/cu [options] [device] [systemname]
```

## cu 219

## Description

`cu` 调用另一个 UNIX 系统，或者被调用。它使用 `uucp` 控制文件 `/etc/uucp/Devices` 和 `/Systems` same建立连接。可能的介质包括电话线、直接连接和局域网（LAN）。`/etc/uucp/Devices` 文件包含了你系统上可用的介质列表。`/etc/uucp/Systems` 文件包含了连接到远程系统的信息，但通常是不可读的。

## Options

`-c`, `-s` 以及剩余的选项是：

- `-a` 将输出追加到现有的 `tags` 文件。

- `-B` 使用反向搜索模式 `(?...)`。

- `-f tagsfile` 将标签描述放在名为 `tagsfile` 的文件中，而不是 `tags`。

- `-F` 使用正向搜索模式 `(/.../)`（默认）。

- `-t` 为类型定义创建标签。`/usr/xx4/bin/ctags` 默认为类型定义创建标签。

- `-u` 更新 `tags` 中指定的文件，即删除对它们的所有引用，并将新值附加到文件中。`dev/tty` 设备用于连接。

- `-v` 在标准输出上产生索引，列出函数名、文件名和页码（假设每页 64 行）。因为输出按字典顺序排序，你可能希望对输出运行 `sort -f`。

- `-w` 抑制警告。

- `-file.c` 将基名以 `.c` 结尾的文件视为 C 语言源码。

- `-file.h` 将基名以 `.h` 结尾的文件视为 C 语言头文件。

- `-file.f` 将基名以 `.f` 结尾的文件视为 FORTRAN 语言源码。

- `-v` 在标准输出上产生对象名称列表、定义的行号和文件名，以及该行的文本，并打印到标准输出上。此列表提供了一个简单的索引，可以打印为离线可读的函数索引。

- `-b` 强制指定位数。位数是 7 或 8。

- `-h` 设置通信模式为半双工。此选项允许双工。

- `-d` 打印诊断跟踪。

- `-n` 请求电话号码。

- `-O` 设置发送到远程系统的奇偶校验位（ODD）。

- `-e` 设置发送到远程系统的偶校验位（EVEN）。

- `-L` 通过 `/etc/uucp/Systems` 中指定的登录序列。关于登录序列的信息，请查看 TCP/IP 和数据通信指南。

- `-C` 在行尾运行指定的命令，而不是进入交互模式。标准的输入和输出命令指的是远程连接。

- `-H` 忽略挂断。此选项允许用户的系统在远程机器断开连接时保持运行。在连接带有回拨（dialback）模式的系统时使用此选项。你可以多次指定此选项。关于回拨的信息，请查看 `remote(4)` 和 TCP/IP 和数据通信指南。

- `-s` 指定速度（300, 1200, 2400, 4800, 9600, 19200, 38400）。`dev/tty` 设备用于连接。

## Usage

连接阶段 `cu` 使用与 `uucp(1C)` 相同的机制来建立连接。

## 221

当使用 `cu` 时，它会在 `/etc/uucp/Sysfiles` 文件中查找 `service=ppcu` 条目，以确定使用哪个 `/etc/uucp/Systems` 文件。

命令行中的 `telno` 或 `system` 参数告诉 `cu` 系统你想要连接的系统。该参数可以为空、电话号码、系统名称或下文描述的 LAN 特有地址。

### 电话号码

由拨号音字符（数字 0 到 9、`*` 和 `#`）以及特殊字符 `=` 和 `-` 组成的字符串。等号 (`=`) 表示辅助拨号音，减号 (`-`) 则产生 4 秒的延迟。

### 系统名称

任何 `uucp` 可以拨打的计算机名称；你可以通过 `uuname(1)` 打印名称列表。

### LAN 地址

你的局域网文档显示了 LAN 特定地址的形式。

如果调用了 `cu` 的默认行为（使用 `-c` 或 `-l` 选项），`cu` 使用 `telno` 或 `systemname` 参数来确定使用什么介质。如果你指定了电话号码，`cu` 假设你想使用电话线路并选择自动拨号单元 (ACU)。否则，`cu` 假设该参数是系统名称。当该参数为系统名称时，`cu` 遵循 `uucp` 机制并使用 `-s` 选项通过 `/etc/uucp/Systems` 和 `/etc/uucp/Devices` 文件获取可用连接。由于 `cu` 会选择适合该介质的速度，当该参数为系统名称时，你可能不需要 `-s` 选项。

你可以使用 `-c` 和 `-l` 选项来修改默认行为。`-c` 通常通过指定 `/etc/uucp/Devices` 文件中的 `Type` 字段来连接 LAN。你必须使用 `-c` 选项包含 `telno` 或 `systemname` 值。如果到 `systemname` 的连接失败，则将使用 `systemname` 作为 LAN 特有地址建立连接。`-l` 选项用于指定与直接连接关联设备。如果连接确实是到远程系统的直接连接，则不需要指定 `systemname`。这是唯一不需要 `telno` 或 `systemname` 参数的情况。另一方面，在某些情况下指定的设备连接到拨号器，因此指定电话号码是有效的。不要在同一命令行上同时指定 `-c` 和 `-l` 选项。

## 会话阶段

建立连接后，`cu` 以两个进程运行：

- 发送进程从标准输入读取数据，除了以 `~` 开头的行外，将其传递到远程系统。

## 222

- 接收进程从远程系统接收数据，除了以 `~` 开头的行外，将其传递到标准输出。通常情况下，通过自动 DC3/DC1 协议控制来自远程的输入，以防止溢出。以 `~` 开头的行具有特殊含义。

## 命令

发送进程解释以下用户发起的命令：

- `~` 终止会话。

- `~! ` 转义到本地系统的交互式 shell。

- `~break` 向远程系统发送一个 BREAK 信号（也可以指定为 `~b`）。

- `~cd` 更改本地系统的目录。`~!cd` 在子 shell 中运行命令，这可能不是用户的意图。

- `~cmd...` 在本地系统上运行 `cmd`（通过 `sh -c`）。
