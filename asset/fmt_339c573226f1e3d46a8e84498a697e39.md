
每个条目包含一个 IP 地址、与该 IP 地址关联的主机，以及可选的别名（即针对同一主机的另一个别名）。例如，jade 和 jade.harmonics.com 指向同一个主机（IP 地址为 100.0.0.2）。用户若要与 jade 建立 telnet 会话，现在可以选择输入：

- $ $ telnet jade

或者

- $ $ jade.harmonics.com

所有 TCP/IP 应用（如 telnet 和 ftp）都内置了名称解析机制，该机制会查找主机表并查找被调用应用程序对应的 IP 地址。随后，应用程序将跨越网络连接相应的主机。无法解析 IP 地址通常会导致错误信息“Unknown host（未知主机）”。

## 域名系统

主机这种基于表格的名称解析方法对于在 `/etc/hosts` 文件中包含条目较少的小网络来说非常方便，前提是网络未连接到互联网且不需要运行 DNS 服务器。即使网络未连接到互联网，在所有 UNIX 主机上维护相同的 `/etc/hosts` 文件也是一项耗时的工作，因为由于对某一台主机所做的更改必须一致地落实到所有其他主机上。随着网络规模的扩大，这种方法很容易变成一种噩梦。

域名系统（DNS, RFC 1035）是执行名称解析的另一种替代方案。使用 DNS 将主机名解析为 IP 地址涉及使用一个大型、分层且分布式的数据库，其中包含了网络以及互联网上所有主机的信息（包括 IP 地址）。分层结构允许将命名空间划分为子域，并允许将数据库的分区（子域）迁移到属于网络或互联网各站点的名称服务器。因此，托管服务器可以被赋予管理其子域的责任。

服务器维护 DNS 数据库并运行一个服务器进程（在 UNIX 上称为守护进程 daemon），除了提供某些相关的主机信息外，还处理从名称到 IP 地址的解析。

TCP/IP 应用内置了名为“解析器”的 DNS 客户端。换句话说，不需要特殊的守护进程来代表应用程序支持名称查询。图 20.21 显示了当用户输入 jade.harmonics.com 开始文件传输时是如何进行查询的。根据 DNS 命名规则，主机名 jade 是完全限定域名（FQDN），这将在稍后进行讨论。根据图示，解析器在 ftp 客户端中启动，将名称封装在 DNS 查询中并将其发送到 DNS 服务器。DNS 服务器查找请求的信息（在本例中为 IP 地址）并向向请求的主机发送回复。

## 域与区域 (Domains and Zones)

你已经了解到，域的权限可以委托给某个机构，该机构可以将其域划分为较低的域。划分域并不意味着要将每个子域的自主权委托给机构内的其他成员。虽然一个域被划分为许多低级域，但对域的权限可以沿着*区域*（zones）对齐，其中一个区域可以包含父域所包含的域子集。

图 20.26 释了域与区域之间的区别。所示，harmonics 域包含 *ott*、*ny* 和 *paris* 子域。这里只建立了两个权限区域：harmonics 区域包含 *ott* 和 *paris* 子域，而 *ny* 区域包含 *ny* 域。在设置名称服务器时，你将分配权限区域——你将配置它们以维护其拥有权限的区域的完整信息。如果你愿意，可以让一个名称服务器成为多个区域的权威服务器。

## 名称服务器 (Name Servers)

为了支持机构被委托权限的域或区域而设置 DNS 服务器，涉及该区域的一组权威服务器。至少应该设置两台服务器：一台主和一台从。

主名称服务器是维护数据库文件的地方，也是设置过程中中最耗时的。DNS 的更改，无论是委托域的布局或结构，还是简单的数据库更新，都必须在主名称服务器上进行管理和反映。例如，要向网络添加一个新主机，你必须为它分配名称和 IP 地址，并且必须将这些分配输入 DNS 数据库。

从名称服务器比主服务器更容易设置。它与主服务器的区别在于，它通过被称为“区域传输”（zonal transfer）的过程从主服务器复制其数据库。一旦设置完成，从服务器需要的维护很少。

每当从服务器重启时，它都会通过联系双方共同负责的区域的主服务器进行区域传输过程，并请求有关该区域的所有信息。因此，从服务器会轮询主服务器以获取数据库可能发生的任何更新。正如在“实现 DNS”章节下所示，从服务器可以很容易配置为在将区域传输到磁盘文件后进行备份。此选项允许从服务器使用备份文件重新加载其数据，而不是在每次服务器重启时都进行区域传输——这减少了区域传输的带宽消耗，并在传输启动时从服务器未能收到主服务器的消息的情况下提供了更好的数据可用性。

启动 DNS 服务不需要安装主服务器以外的服务器。但是，包含从服务器具有以下优势：

- 冗余：主服务器和从服务器之间的区别仅在于它们进行名称查询所依赖的信息源。两台服务器都同样能够响应此类查询。因此，由于从服务器的存在，如果其中一台意外停止响应用户查询，另一台能够接管，前提是工作站已设置为连接到两台服务器。

- 负载均衡：两台服务器都同样能够响应所有类型的查询，可以设置环境使得这些服务器的负载得到公平共享。共享负载的额外益处是改进了响应时间。

- 物理接近：通过拥有多台服务器，你将能够策略性地将每台服务器放置在最需要的地方。涉及到...

## 名称解析 (Name Resolution)

当客户端想要访问主机时，它首先检查本地缓存。如果没有找到名称，它会向配置的 DNS 服务器发出查询。如果该服务器不是该域的权威，它会将查询转发给名称服务器。这一过程持续到到达权威服务器。权威服务器返回主机的 IP 地址。客户端使用该地址建立连接。

## 缓存 (Caching)

为了节省带宽并提高响应时间，DNS 具有缓存机制。当 DNS 服务器接收响应时，它会将结果存储在缓存中，称为生存时间（TTL）。这允许服务器在 TTL 过期之前再次回答相同的查询，而无需再次查询权威服务器。

## 反向解析 (Reverse Resolution)

反向解析对于安全特别有用。某些远程访问服务，如登录和远程查询（rcp），只有在用户主机具有特权的情况下才能访问。支持服务的主机通常在特殊文件中（如 `$HOME/.hosts` 和 `/etc/hosts.equiv`）维护允许的其他主机的名称（而不是 IP 地址）。收到远程访问请求时，安全服务器向名称服务器请求反转地址以进行后续验证。

## 指针查询的反向解析 (Reverse Resolution of Pointer Queries)

图 20.28 显示了互联网 DNS 服务组织的部分图景。特别是 in-addr.arp 解析域。因为作为这种，将 IP 解析为完全限定域名更为容易。in-addr.arp 域的设计是为了为响应查询提供高效的机制。如图 20.2b 所示，in-addr.arp 只是另一个使用 IP 地址作为子域名的域。该域组织为 25 个域，对应 IP 地址第一个字节的每个可能值。同样，在这些域中的每一个中，可以有 25 个子域对应 IP 地址的第二个字节，以此类推，直到整个地址空间在 in-addr.arp 域中表示出来。

当一个机构加入互联网时，它被赋予管理两个或多个域的责任。这些是它在其下注册的官方域名。例如，在 Harmonics Inc. 的情况下，harmonics.com 和 in-addr.arpa 域名对应于其通过专用互联网权威机构（Proprietary Internet Authority）分配的地址范围。例如，如果 Harmonics Inc. 被分配了 C 类地址池 198.58.63.0，那么它就被赋予了管理 63.58.198 的权限。注意反向域名的 IP 地址部分是反过来拼写的。这符合之前讨论过的 DNS 命名规则。例如，如果地址是 oboe.ny.harmonics.com 或 198.58.63.2，那么它的 in-addr 域标签即为 2.63.198.in-addr.arpa，这同样符合完全限定域名（fully qualified domain-names）的引用方式。

假设该主机通过向本地名称服务器发送反向解析查询（正式称为指针查询）来接收来自接收主机的登录请求。随后，本地服务器必须验证与指定主机 IP 地址相对应的域名，并进行相同的正向解析（如前文所述），该过程从 198.in-addr.arpa 开始向下移动移动，直到到达域标签 2.63.58.in-addr.arpa，并从中获取对应的主机域标签（oboe.ny.harmonics.com）。然后，该名称将返回给远程访问服务器用于验证地址。

## 为 UNIX 配置 TCP/IP

本节将详细介绍从准备阶段到实际实施阶段的设置过程。整个讨论主要针对 UNIX SVR4 主机上的“如何操作”过程。将强调其与其他 UNIX 变体之间的必要区别。

## 准备设置和配置 TCP/IP

在 UNIX 上设置和配置 TCP/IP 是一件相当简单直接的事情，只要你以前操作过。大部分准备工作必须通过定义对于成功完成主机连接到公共网络任务的关键参数来实现。以下是执行此类任务时需要考虑的几点：

- **网络接口数量**：主机可能需要多个网络网卡以连接到多个网络。当主机被设置为在这些网络之间路由流量或作为安全故障的措施时，通常需要这样做。

- **网络接口标签**：UNIX 使用网络接口标签。每个标签都与其他彼此不同。例如，在 Solaris 2 系统上，一个 3Com 以太网 III (3C5X9) 被引用或标记为 elX。该种类的第一个接口标记为 el0，第二个标记为 el1，以此此类推。在使用适用参数（如 IP 地址、子网掩码等）配置接口之前，请确保你知道接口标签是什么。

- **主机名 (hostname)**：每个主机必须分配一个主机名。通常，主机名是在系统安装期间设置的。查找主机名很简单，只需如所示输入 `uname -n` 命令：

```bash
## uname -n
tenor
```

但请记住，安装期间分配给主机的名称可能不适用于网络环境。一个明显的原因可能是冲突——即两台计算机具有相同名称的可能性。另一个原因是与你环境中生效的官方主机命名规则发生潜在冲突。如果需要更改名称，请使用带有 -s 选项的 uname 命令，如下：

```bash
## uname -s newewame
```

newewame 是新主机的名称。

在配置主机以支持多个网络接口的情况下，你应该为每个接口分配一个名称。你不能让所有支持的接口都关联相同的名称。因此，请在实施时准备好所有名称。

- **域名 (Domain name)**：如果你在网络上安装了域名服务，你必须决定主机属于域层次结构的哪个位置，并记录主机的完整域名。例如，如果说 tenor 属于 ny.harmonics.com，那么它的全域名就变为 tenor.harmonics.com。

- **分配给网络接口的 IP 地址**：每个网络接口必须分配一个唯一的 IP 地址。请使用点分法提供地址。

- **子网掩码 (Subnet masks)**：如果默认值不可接受，请确定并记录相应的子网掩码。在设置过程需要时，可以使用点分法或十六进制法输入掩码。

- **域名服务器的 IP 地址**：如果网络上安装了域名服务，你至少应该拥有主、备名称服务器的地址。在 UNIX 主机上设置 DNS 解析器的过程中，需要这些地址。

- **默认网关的 IP 地址（即默认路由器）**：在路由网络（连接到其他网络的网络）上，每个主机都必须配置为识别默认路由器——即对路由器 IP 地址的需求。

上述内容涵盖了在 UNIX 主机上顺利实施 TCP/IP 的最小需求列表。在某些情况下，配置主机可能需要额外信息。然而，在处理上述所有参数并验证网络设置运行正常后，始终可以实施额外信息。
