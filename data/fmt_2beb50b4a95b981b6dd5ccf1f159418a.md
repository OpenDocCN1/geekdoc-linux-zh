
由于 `pickle` 使用的格式是 Python 特有的，因此你不会将此格式作为不同编程语言编写的应用程序之间交换数据的特性。此外，由于安全考虑，程序不应处理来自不可信源的 `pickle` 数据（一个高明的攻击者可以在反序列化期间操控 `pickle` 数据以执行任意系统命令）。

`pickle` 和 `shelve` 模块具有更多的自定义功能和高级用法选项。更多细节请参阅第 13 章“Python 运行时服务”。

## 执行环境

本章描述了 Python 程序执行的环境。目标是描述解释器的运行时行为，包括程序启动、配置和程序终止。

## 解释器选项与环境

解释器有很多控制其运行时行为和环境的选项。选项通过命令行传递给解释器：
`python [options] [-c cmd [filename]] [args]`

以下是最常用的命令行选项列表：

表 10.1 解释器命令行参数
| 选项 | 说明 |
| --- | --- |
| -3 | 启用 Python 3 中即将移除或更改的功能警告。 |
| -B | 防止在导入时创建 `.pyc` 或 `.py` 文件。 |
| -E | 忽略环境变量。 |
| -h | 打印所有可用命令行选项列表。 |
| -i | 程序执行后进入交互模式。 |
| -m module | 将库模块作为脚本运行。 |
| -O | 优化模式。 |
| -OO | 优化模式外加在创建 `.pyc` 文件时移除文档字符串。 |
| -Q arg | 指定 Python 2 中除法运算符的行为。可选 `-Gnew,-Qwarn, 或 -Qwall`。 |
| -s | 防止将用户 `site` 目录添加到 `sys.path`。 |
| -S | 防止包含站点初始化模块。 |
| -t | 报告标签使用不一致的警告。 |
| -tt | 标签使用不一致会导致 `TabError` 异常。 |
| -u | 无缓冲的二进制标准输出和标准输入。 |
| -U | Unicode 字面量被作为 Unicode 处理（仅限 Python 2）。 |
| -v | 详细模式。跟踪导入语句。 |
| -V | 打印版本号并退出。 |
| -x | 跳过源程序的第一行。 |
| -c cmd | 以字符串形式执行 `cmd`。 |

### 第 10 章 执行环境

`-i` 选项在程序执行完成后立即启动交互会话，用于调试。`-m main__` 选项将库模块作为脚本运行，在执行主脚本之前在 `__main__` 模块内部执行。`-0` 和 `-oo` 选项仅对字节编译文件应用优化，并已在第 8 章“模块、包和分发”中描述。`-s` 选项省略了后文“站点配置文件”部分描述的初始化模块。`-t`、`-tt` 和 `-v` 选项报告额外的警告和调试信息。`-x` 忽略程序的第一行，如果该行不是有效的 Python 语句（例如，当脚本的第一行启动 Python 解释器时）。程序名出现在所有解释器选项之后。如果未给出名称，则使用连字符 `-` 作为文件名，解释器读取标准输入。如果标准输入是交互式终端，则会显示横幅和提示符。`-c` 选项可以以字符串形式执行语句。

此外，解释器读取以下环境变量：

表 10.2 解释器环境
| 环境变量 | 说明 |
| --- | --- |
| `PYTHONPATH` | 冒号分隔的路径。 |
| `PYTHONSTARTUP` | 启动时执行的文件。 |
| `PYTHONHOME` | Python 安装的位置。 |
| `PYTHONINSPECT` | 对应 `-i` 选项。 |
| `UNBUFFERED` | 对应 `-u` 选项。 |
| `PYTHONENCODING` | `stdin`、`stdout` 和 `stderr` 的编码和错误处理。 |
| `PYTHONTWRITECODE` | 对应 `-B` 选项。 |
| `PYTHONOPTIMIZE` | 对应 `-O` 选项。 |
| `PYTHONITE` | 对应 `-s` 选项。 |
| `PYTHONVERBOSE` | 对应 `-v` 选项。 |
| `PYTHONBASE` | 用户 `site` 的根目录。 |
| `PYTHONCASEOK` | 表示在模块名匹配时不区分大小写。 |

`PYTHONPATH` 指定了插入到 `sys.path` 开头的路径，见第 9 章。如果在指定位置不存在 Python 安装，`PYTHONHOME` 无影响，因为 Python 知道如何找到自己的库和安装扩展的 `site`。如果给出单个目录如 `/usr/local`，解释器在该位置查找所有文件。如果给出两个目录如 `/usr/local:/sparc-2.6`，解释器在第一个目录查找平台无关文件，在第二个目录查找平台相关文件。

`PYTHONENCODING` 环境设置可能令 Python 3 用户感兴趣，因为它设置了 I/O 流的编码和错误处理。这可能是因为 Python 3 在运行解释器提示符时直接输出 Unicode。这反过来可能会在合并数据时导致意外异常。

```
>>> a = 'Jalate\xf1'

>>> a

Traceback (most recent call last):

  File "stdin", line 1, in <module>
    b = encoder.encode(a)
  File "/tmp/lib/python.0/io.py", line 1486, in write
    return codecs.ascii_encode(input, self.errors(0))
UnicodeEncodeError: 'ascii' codec can't encode character '\xf1' in position 7: ordinal not in range(128)
>>>
```

修复这个问题，将环境变量 `PYTHONENCODING` 设置为 `ascii:backslashreplace` 或 `utf-8`。现在你会得到：

```
>>> a = 'Jalate\xf1'

>>> a
'Jalate\xf1'
```

在 Windows 上，某些环境变量如 `PYTHONPATH` 还会从 `HKEY_LOCAL_MACHINE/Software/Python` 的注册表项中读取。

## 交互会话

如果没有给出程序且解释器的标准输入在接受输入时是交互式终端，则会出现两个用户提示符。`>>>` 提示符出现在新语句开头；`...` 提示符表示语句延续。

```python
>>> for i in range(0,4):
    ... print i,
    ...
0 1 2 3
>>>
```

### 第 10 章 执行环境

在自定义应用程序中，你可以通过修改 `sys.ps1` 和 `sys.ps2` 的值来更改提示符。

在某些系统中，Python 可能被编译为使用 GNU `readline` 库。启用后，该库为 Python 的交互模式提供了命令历史、补全等功能。

默认情况下，交互模式下执行的命令的输出是通过打印结果的内置 `repr()` 输出来生成的。可以通过将 `sys.displayhook` 设置为负责显示结果的函数来更改此。这里有一个截断长结果的示例：

```python
>>> my_display(x):
    r = repr(x)
    if len(r) > 40: print(r[:40]+"...")
```

在交互模式下，知道上一次操作的结果存储在一个特殊变量 `(_)` 中是很有用的。这个变量可以用于获取你在后续操作中需要的结果。这是一个示例：

```python
>>> 7 + 3
10
>>> _ + 2
12
>>>
```

`_` 变量的设置发生在之前显示的 `displayhook()` 函数中。如果你重新定义了 `displayhook()`，那么如果你想保留该功能，你的替换函数也应该设置 `_`。

## 启动 Python 应用程序

大多数情况下，你可能希望自动启动解释器，而不是先手动启动它。在 UNIX 上，这是通过赋予执行权限并将程序的的第一行设置为如下内容来实现的：

```python
#!/usr/bin/env python
# 从此处开始是 Python 代码...
print "Hello world"
```

在 Windows 上，双击 `.py`、`.pyw`、`.pyc` 或 `.pyo` 文件会自动启动解释器。通常情况下，程序在控制台窗口中运行，除非它们被重命名为 `.pyw`（在这种情况下，程序将静默运行）。如果需要向解释器提供选项，也可以从 `.bat` 文件启动 Python。例如，此 `.bat` 文件在脚本上运行 Python，并将命令行提示符上提供的任何选项传递给解释器：

```batch
foo.bat
  运行 foo.py 脚本并传递命令行选项（如果有）
c:\python26\python.exe c:\scripts\foo.py $*
```
