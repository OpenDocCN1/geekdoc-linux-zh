## 变量与赋值

全局和静态变量使用 `.data` 或 `.bss` 条目声明。局部变量通过在函数开始时在栈上保留空间来声明。该空间在函数结束时释放。

有趣的是，汇编语言中全局变量的访问方式与局部变量不同。全局变量使用直接寻址访问，而局部变量使用基址指针寻址访问。例如，考虑以下 C 代码：

```c
int my_global_var;

int foo()
{
int my_local_var;
my_local_var = 1;
my_global_var = 2;
return 0;
}
```

这在汇编语言中渲染为：

```assembly
.section .data
long my_global_var, 4
.type foo, @function
foo:
pushl %ebp             # 保存旧基址指针
mov %esp, %ebp      # 将栈指针设置为基址指针
subl $4, %esp       # 为 my_local_var 留出空间
equ my_local_var, -4 # 现在可以使用 my_local_var 来
                     # 找到局部变量
movl $1, my_local_var(%ebp)
movl $2, my_global_var
```

```assembly
movl %ebp, %esp     # 清理函数并返回
popl %ebp
ret
```

可能并不明显的是，访问全局变量消耗的机器周期比访问局部变量少。但这可能并不重要，因为栈比全局变量更有可能位于物理内存（而不是交换分区）。

另外注意，在 C 语言语言中，编译器将一个值加载到寄存器后，该值可能会留在寄存器中，直到该寄存器用于其他地方。它也可能会移动寄存。例如，如果你有一个变量 `foo`，它可能起始于栈上，但编译器最终会将其移动到寄存器中处理。如果没有变量在使用，该值可能一直一直留在寄存器中，直到再次被需要。否则，如果该寄存器被其他需要且发生了更改，它会被复制回其对应的内存位置。在 C 中，你可以使用关键字 `volatile` 来确保对变量的所有修改和引用都是在内存位置本身进行的，而不是寄存器的副本，以防在你的函数运行时，其他进程、线程或硬件可能会修改该值。

## 循环

汇编语言中的循环工作方式非常像 `if` 语句——块是通过相互跳转形成的。在 C语言中，`while` 循环由一个循环体和一个确定是否退出循环的测试组成。`for` 循环完全相同，带有可选的初始化和计数器递增部分。这些可以简单地移动位置形成一个 `while` 循环。

在 C 中，`while` 循环看起来如下：

```c
while(a < b)
{
    /*在此处执行操作 */
}
```

* 循环结束 *

这可以在汇编语言中像这样渲染：

```assembly
loop_begin:
mov a, %eax
mov b, %ebx
cmpl %eax, %ebx
jnge loop_end
loop_body:
## 在此处执行操作
jmp loop_begin
loop_end:
## 循环结束
```

`x86` 汇编语言对循环也有一些直接支持。`%ecx` 寄存器可以用作以零结束的计数器。循环指令会递减 `%ecx` 并跳转到指定的地址，除非 `%ecx` 为零。例如，如果你想执行语句 100 次，在 C 中你会这样做：

```c
for(i=0; i < 100; i++)
{
    /* 在此处执行操作 */
}
```

## 附录 E. 汇编语言中的 `get`

```assembly
movl $30, A_VAR(%ebp)
#b = &a
movl $A_VAR, B_VAR(%ebp)
addl %ebp, B_VAR(%ebp)
#*b = 30
movl B_VAR(%ebp), %eax
movl $30, (%eax)
#标准结束
movl %ebp, %esp
popl %ebp
```

如你所见，为了获取局部变量的地址，必须按照计算机在基址寻址中计算地址的方式来计算该地址。有一种更简单的方法——处理器提供了 `lea` 指令，它代表“加载有效地址”（load effective address）。这让计算机计算出地址，然后将其加载到你指定的任何地方。所以，我们可以直接说：

```assembly
#b = &a
lea A_VAR(%ebp), %eax
movl %eax, B_VAR(%ebp)
```

行数相同，但代码更整洁。然后，在使用这个值时，你只需要将其移动到通用寄存器并使用间接寻址，如上面的示例所示。

## 让 GCC 提供帮助

`GCC` 的优点之一是它能够输出汇编语言代码。要将 C 语言文件转换为汇编，你只需要执行：

```bash
gcc -S file.c
```

输出将位于 `file.s` 中。这并不是最易读的输出——大多数变量名已被删除并替换为数字栈位置或对自动生成标签的引用。首先，你可能想要关闭优化——`-O0`，这样汇编输出会更符合你的源代码。

你可能注意到的其他点是，`GCC` 为局部变量留出的栈空间比我们多，并且 `%esp`^1。这是通过对变量进行双字对齐（double-word aligning）来提高内存和缓存效率。

最后，在函数结束时，我们通常在执行 `ret` 指令之前执行以下指令来清理栈：

```assembly
mov %ebp, %esp
popl %ebp
```

然而，`GCC` 输出通常包含 `leave` 指令。这条指令是上述两个指令的组合。我们在本文中没有使用 `leave`，是因为我们希望清楚地了解处理器层面到底发生了什么。

我鼓励你拿一个你写过的 C 程序将其编译为汇编语言并追踪逻辑。然后，添加优化并再次尝试。观察编译器如何重新排列你的程序以进行优化，并尝试理解它为什么选择那样的排列和指令。

- 1. 注意，不同版本的 `GCC` 此实现方式不同。

## 附录 F. 使用 GDB 调试器

当你读到这个附录时，你可能已经写了一个至少带有错误的程序。在汇编语言中，即使是微小的错误通常会导致整个程序因段错误（segmentation fault）而崩溃。在大多数编程语言中，你可以在运行过程中打印变量的值，并借此找到错误所在。在汇编语言中，调用输出函数并不简单。因此，为了帮助确定错误来源，必须使用源码调试器。

调试器是一个通过逐步执行程序来帮助你调试的程序，允许你检查内存和寄存器的内容。源码调试器是允许你将调试操作直接关联到程序源代码的调试器。这意味着调试器允许你查看输入时的源代码——包括符号、标签和注释。

我们将查看的调试器是 `GDB` - GNU 调试器。该应用程序存在于几乎所有的 GNU/Linux 发行版中。它可以调试多种编程语言的程序，包括汇编语言。

## 调试会示例

解释调试器如何工作的最好方法是直接使用它。我们将使用调试的程序是第 3 章中使用的 `maximum` 程序。假设你完美地输入了程序，但漏掉了这一行：

```assembly
incl %edi
```

当你运行程序时，它就进入了无限循环——永远不会退出。要确定原因，你需要在 `GDB` 下运行程序。然而，为了做到这一点，你需要让汇编器在可执行文件中包含调试信息。你所做的就是在 `as` 命令中添加 `--gstabs` 选项。所以，你可以这样汇编它：

```bash
as --gstabs maximum.s -o maximum.o
```

链接过程与正常操作相同。“stabs”是 `GDB` 的调试格式。现在，要在调试器下运行程序，你只需输入 `gdb /maximum`。确保源文件在当前目录下。输出应该如下：
