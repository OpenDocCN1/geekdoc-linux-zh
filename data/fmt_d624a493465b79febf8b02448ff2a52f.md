有些应用程序使用 Web 界面。对于这种类型的应用程序，可以使用命令行浏览器。列表 9.9 所示的函数利用命令行浏览器来检查 HTTP 服务器以及 Web 页面，这些是传递给 `$1` 的参数。

check_HTTP_server ()
{
  LIN=/usr/bin/linux      # 定义 linux 程序的位置

## 应用 API 与 SNMP 陷阱

大多数企业管理工具都为最常用的应用程序提供了应用程序接口（API）；然而，有时我们必须编写 Shell 脚本来填补空白。这就是 SNMP 陷阱大显用场。由于企业管理工具应该支持 SNMP 陷阱，API 允许通过管理服务器和客户端系统的 SNMP MIB 定义来监控应用程序。

当企业管理工具支持 SNMP 陷阱时，你通常可以编写自己的 Shell 脚本，利用工具的 MIB 和 SNMP 定义从你自己的脚本中获取消息。例如，下述命令显示了一个知名监控工具的 SNMP 和 MIB 数据，以便发送陷阱。

```
/usr/local/bin/trapclient MON_HOST $MIB_NUM $TRAP_NUM $TRAP_TEXT
```

在上一条命令中，`MON_HOST` 变量代表主机。`MIB_NUM` 变量代表 MIB 参数的具体代码。`TRAP_NUM` 变量代表要发送的具体陷阱代码，而 `TRAP_TEXT` 是随陷阱发送的文本。这种用法取决于你正在使用的监控工具。无论如何，都有技术允许你编写 Shell 脚本来发送陷阱。方法虽异，但 SNMP 的基本语法保持不变。

# 创建伪随机密码

有安全措施吗？大多数用户社区不知道如何创建不易被猜到的安全密码。用户倾向于拥有几个可以轮换的密码。“轮换”密码的问题在于，它们通常很容易猜。例如，用户发现出生日期、社会安全号码、地址、部门名称/编号等可以作为既好记又良好的密码。有时他们会使用任何字典中找到的单词，这对于任何破解者来说都是起点。在本章中，我们将编写一个创建伪随机密码的 Shell 脚本。

## 随机性

如果你查看第 21 章“伪随机数生成器”，你可以看到我们用来创建伪随机数的练习。这些数字并不是真正的随机数，因为计算机系统创建“随机数”的方式具有周期性。例如，如果你总是从相同的种子（或第一个数字）开始随机数序列，你将始终得到相同的序列。在第 21 章中，我们使用当前进程（即 Shell 脚本）的进程 ID（PID）作为创建伪随机数的种子。使用 PID 是很好的，因为 PID 是系统以某种随机的方式创建的。既然我已经在随机数上让你迷糊了，你可能会问：“随机数与密码有什么关系？”随着我们的进行，答案将变得直观而易懂。

## 创建伪随机密码

我们从关于随机性的讨论开始本章，因为我们将使用计算机生成的伪随机数，然后将这些生成的数字作为指针，来指定键盘字符的数组元素，这些字符存储在 `KEYS` 数组中。在本章中，你将发现生成随机数的实际用途，而你之前还觉得第 21 章浪费时间！

脚本的思路是这样的：使用一个包含键盘字符的外部文件，每行一个字符。你可以在文件中放入任何想要的键盘字符。你只需要从左到右遍历键盘，从带有数字的顶行开始。当我遍历所有键盘按键时，我添加了来自数字小键盘的第二组数字，以及所有的大小写字母。这种策略的巧妙之处在于，你能够指定在你的店中构成有效密码的精确字符组。使用非美国键盘字符的国家特定类型键盘也受益于这种策略。

一旦创建了键盘文件，我们就将键盘数据加载到数组中。不要慌！Shell 数组很容易处理，正如你将在后续章节看到的。当我们加载了所有的数组元素后，我们知道有多少元素可以操作。使用第 21 章中描述的技术，我们在 1 到数组元素总数之间创建伪随机数。通过数组指针，我们将伪随机数添加到单个字符上，形成字符字符串。这个字符字符串（即我们要创建的密码）默认长度为八个字符；然而，可以通过命令行添加整数值来改变密码的长短。
