# trap, onintr — 响应硬件信号的 Shell 内置函数

### 概要

- `sh trap [argument n [n2...]]`
- `csh onitr [-| label]`
- `ksh * trap [arg sig [sig2...]]`

## 描述

在 shell 脚本中使用内置的 `trap` 和 `onintr` 命令，指定当 shell 脚本接收到中断信号时要执行的命令序列。

# Bourne Shell

当 shell 接收到数字或符号信号 `n` 时，会读取并执行 `trap` 命令的参数。

> 注意 — 参数在设置 trap 时扫描一次，在触发 trap 时再次扫描一次。

`trap` 命令按照信号编号或相应的符号名称的顺序执行。任何尝试在当前 shell 启动时已被忽略的信号上设置 trap 的尝试都是无效的。尝试在信号 `11`（内存错误）上设置 trap 会产生错误。如果不指定参数，`trap(s)` 将重置为原始值。如果参数为空字符串，`trap(s)` 将重置为原始值。如果参数为空字符串，该信号将被 shell 及其调用的命令忽略。如果 `n` 为 `0`，则命令在退出 shell 时执行。没有参数的 `trap` 命令将打印与每个信号相关的命令列表。

## C Shell

`onintr` 命令控制 shell 在遇到中断时的动作。不带参数时，`onintr` 恢复 shell 中断的默认动作（shell 终止 脚本并返回终端）。带有 `-` 参数时，shell 忽略所有中断。带有标签参数时，当接收到中断或子进程因中断而终止时，shell 将执行 `goto`。

## Korn Shell

`trap` 使用 `arg` 作为命令，当 shell 接收到信号 `sig` 时进行读取并执行。

注意 — `arg` 在设置 trap 时扫描一次，在触发 trap 时再次扫描一次。你可以将 `sig` 指定为数字或信号名称。`trap` 命令按照信号编号的顺序执行。任何尝试在当前 shell 启动时已被忽略的信号上设置 trap 的尝试都是无效的。如果你省略了 `arg` 或 `-`，则每个 `sig` 的 `trap(s)` 将重置为原始值。如果 `arg` 为空字符串，该信号将被 shell 及其调用的命令忽略。如果 `sig` 为非零值，命令在退出 shell 时执行。没有参数的 `trap` 命令将打印与每个信号相关的命令列表。（注：此处原文似乎存在重复/逻辑断层，已根据上下文尽量翻译）

# true, false — 提供真值

### 概要

- `/usr/bin/true`
- `/usr/bin/false`

## 描述

`true` 不执行任何操作但成功退出。`false` 不执行任何操作但失败。它们通常在 shell 脚本 `sh` 中使用：

```
while true
do
  command
done
```

这会永久执行命令。
