### 5.2 内存用途

#### 5.2.1 保存函数结束时的返回地址

```
x86
```

当程序使用`call`调用其他函数时，`call`结束后的返回地址将被保存在内存里；在`call`调用的函数结束之后，程序将执行无条件跳转指令，跳到这个地址返回。

`CALL`指令等于“`PUSH`返回地址”和“`JMP`函数地址”的指令对。

被调用函数里的`RET`指令，会从栈中读取返回地址，然后跳转到这个地址，就相当于“`POP`返回地址”+“`JMP`返回地址”指令。

栈是有线的，溢出它很容易。直接使用无限递归，就会满足：

```
void f() 
{
    f();
}
```

#### 5.2.2 参数传递

在`x86`平台，常用的参数约定是`cdecl`。以`cdecl`方式处理参数，它大致这样的：

```
push arg3
push arg2
push arg1
call f
add esp, 12
```

被调用函数（`leaf functions`）通过函数指针获取参数。运行`f()`时，传递参数将格式存在内存里：

| | 返回地址 |

| --- | --- |

| `ESP+4` | `arg1`，在`IDA`里 |

| `ESP+8` | `arg2`，在`IDA`里 |

| `ESP+0xC` | `arg3`，在`IDA`里 |

无论是否优化，`GCC 4.4`的代码和`MSVC`相似，只是`ARM`程序也使用寄存器保存返回地址，只是不同。在节中，`ARM`程序继续调用函数，就需要保存寄存器。通常在函数启动（序言）保存寄存器的值。在函数尾声处看到“`POP R4-R7`”。这些指令会对寄存器进行保护，把它们的值放在栈中。如果一个函数不调用函数，就像那样。这种函数叫做“叶函数”。它的特点是保证寄存器的值。如果函数的代码用到寄存器，那么它可能根本使用栈。这种情况下，函数不在外部中进行栈的操作，所以它的运行速度可以。

### 5.2.3 存储局部变量

通过调整指针（`stack pointer`）的方法，函数可以在数据帧里分配局部变量。可见，无论函数声明多少，都不影响分配的速度。但是用局部变量是一种习惯。

### 5.2.4 x86:alloc() 函数

`alloc()`函数特殊。大来说，`alloc()`函数直接内存，它与`malloc()`函数的区别。函数尾声的代码将数据还原为函数之前的状态，直接释放由`alloc()`分配的内存。所以，程序不需要`free()`函数来释放这个函数。`alloc()`实现至关重要。简单来说，这个函数所需的大小。我们做一个测试：

```
#ifdef _GNUC
#include <alloca.h> // GCC
#else
#include <malloc.h> // MSVC
#endif
#include <stdio.h>

void f() {
    char *buf = (char*)alloc(600);
    #ifdef _GNUC
    snprintf(buf, 600, "hi! %d, %d, %d\n", 1, 2, 3); // GCC
    #else
    snprintf(buf, 600, "hi! %d, %d, %d\n", 1, 2, 3); // MSVC
    #endif

    puts(buf);
}
```

`snprintf()`函数和`printf()`的功能差不多。`printf()`将结果输出到`stdout`（也就是`terminal`或`console`类的设备上），而`snprintf()`将结果输出到`buf`数组（人工设定的缓冲区），我们需要通过`puts()`函数将`buf`的内容输出到`stdout`。当然，`printf()`函数就足够完成`snprintf()`和`puts()`两个函数。本文演示缓冲区的用法，所以要把拆分为两个函数。
