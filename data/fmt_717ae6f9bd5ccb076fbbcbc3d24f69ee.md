
## 创建即插用的 Samba 系统
第二部分

`logon path` 参数指定 Samba 应该在 `profiles` 共享目录中名为 `<username>.prefs` 的目录下查找用户的配置文件。

幸运的是，一旦 `profiles` 配置妥当，当 `<username>` 下次注销时，她的本地配置文件将自动上传到 `smb.conf` 中指定的共享目录。当用户下次登录时，漫游配置（roaming profile）将自动从共享目录下载到本地机器。

强制配置（Mandatory profiles）在这一特定设置中只有一个简单的变化。当你将用户的本地配置文件复制到 `profiles` 共享目录时，你可能会注意到一个名为 `NTUSER.DAT` 的文件。只需将此文件重命名为 `NTUSER.MAN` 启用强制配置。更改后，对当前配置进行的任何修改将在注销时被丢弃。

## 测试配置文件

提供了一个简单的测试来验证配置文件是否正在从 Samba 服务器发送或下载。第一步是确保 NT 客户端的时钟在时间、日期、夏令时间和时区方面与服务器时钟同步。这是因为第 16 章所解释的，配置同步是基于时间的。

一旦客户端和服务器在时间上同步，登录并注销客户端两次，记录 Windows 桌面设置。在客户端注销状态下，将配置文件目录中的 `NTUSER.DAT` 复制为 `NTUSER.DAT.OLD`。然后，使用 `chown` 命令将 `NTUSER.DAT.OLD` 的所有者和组更改为与 `NTUSER.DAT`。

现在登录第三次，将 Windows 主题更改为明显不同的主题，然后注销。再次登录并再次验证新主题是否仍然生效。将 `NTUSER.DAT` 复制为 `NTUSER.DAT.NEW`。然后，使用 `chown` 命令将 `NTUSER.DAT.OLD` 的所有者和组更改为与 `NTUSER.DAT`。

> 提示
> 在继续之前等待一分钟，以确保服务器上的 `NTUSER.DAT` 文件比客户端上的缓存副本新。

在 `profiles` 目录，注意并记住文件 `NTUSER.DAT` 的时间以及所有者和组。将 `NTUSER.DAT.OLD` 复制为 `NTUSER.DAT`，并验证 `NTUSER.DAT` 现在的时间是否比复制前更晚。还要验证文件上的所有者和组是否与复制前相同。一旦验证了这些事实，再次登录，你会由于你在服务器上进行了复制，主题已恢复到原始主题。如果主题已恢复，你就证明了配置文件在你的系统上可以工作。

### 什么是密码同步？

在单服务器运行整个部门和组织的时代，密码同步并不是一个大问题。通常，这些系统包含一个中央的用户和密码数据库，因为所有程序都运行在一个服务器上，身份验证是针对一个数据库进行的。

然而，今天，我们经常发现自己面对复杂的多厂商网络，这些网络需要作为一个协作的整体工作。通常，这些环境由多个服务器或网络系统组成，每个系统都有独特的密码数据库。为了让这些系统协同工作，需要对用户/密码数据库进行某种同步。否则，用户将面临记住组织内各种服务器的多个唯一密码的任务。

这仅仅是问题之一——如果多个不同的密码数据库对用户来说是一种痛苦，事实确实如此，那么对于系统管理员来说也是巨大的负担，他们经常面临着手动保持这些数据库同步的任务。显然，需要一个更好的解决方案。毕竟，各种操作系统是否应该自动共享它们的安全信息呢？

Samba 的主要优势之一是它能够将一个组织的 UNIX 和 Windows 环境统一为一个一致的整体。然而，如果没有方法来集成这些独立系统上的用户和密码数据库，这个目标就无法完全实现。当我提到“密码同步”时，我指的是：能够获取两个或多个系统，并从用户/密码数据库的角度，配置它们使其协同工作而不是独立工作。当密码同步可以自动发生时，对组织来说是一个巨大的收益，增加了组织网络的可靠性和可管理性。事实上，如果 Samba 不包含许多与你的 Windows 系统“协同工作”的方法，那么 Samba 向管理员做出的承诺将是不完整的；对我们来说幸运的是，它确实做到了。

### 应对密码同步挑战

应对密码同步挑战需要大量的规划。当你处理用户-密码数据库时，需要做出明智的决定。我建议你阅读整个章节并熟悉 Samba 为你提供的选项。

#### 研究、研究、研究

在研究了可用的同步选项后，你需要定义一个目标。你是想从 UNIX 服务器还是 Windows 服务器集中管理密码？每种方法都有权衡吗？是否存在一个在一个平台上可用的管理工具但在另一个平台上不可用？

在回答这些问题后，现在从用户的角度来看你的网络。他们主要使用什么操作系统？一个典型用户需要记住网络上的多少密码？你想统一所有的密码数据库还是仅仅是某些？未来的增长如何？你预见未来两年用户需要什么，你可以使用同步策略来让你和你的用户的过渡变得更容易吗？规划无疑是良好过渡的关键。

#### 细致的设计

上述问题应该帮助你对网络如何运作产生愿景。也许你将识别本章描述的、你认为可以实现的 Samba 功能。你的下一步是在纸上开发这种设计，并继续完善你想要实现的特定功能。画出你的新环境如何运行的图。在图中，你将想要识别网络中所有的密码数据库以及它们将如何连接。

#### 行动计划

你的新网络设计可以是完美的，研究是无缺的，如果没有适当实施计划，你将陷入麻烦。记住你正在尝试同步用户和密码数据库——这不是一项平凡的任务。规划不当可能导致用户被锁定访问重要文件很一段时间。这段时间的仔细规划不仅有助于你最终获得一个完美同步的网络，还能在过渡期间让你的用户愉快。

你会希望识别在过渡期间可以使用任何工具或技术，以减少麻烦或停机时间。此外，过渡期间步骤的顺序可能是至关重要的。你应该将测试纳入计划，并在用户发现之前采取步骤发现系统中的潜在缺陷。

### 常见平台的密码功能

在涉及密码验证时，对各种平台的功能具备基础知识是一个好主意。

#### Windows 95/98

由于 Windows 95 和 98 不具备任何类型的安全用户数据库，因此不应使用它们来存储用户账户信息。Windows 95 和 98 仅是客户端操作系统，允许用户根据需要连接到网络共享。

#### Windows NT 工作站

Windows NT Workstation 拥有一个内部的用户和安全数据库，它使用该数据库来验证用户访问其任何共享和/或打印机。

尽管 Windows NT Workstation 是一个理想的网络客户端，但它并没有提供作为服务器所需的功能，至少在密码同步方面是。

#### Windows NT 服务器

Windows NT Server 拥有自己的用户和安全数据库，并能够与其他 NT 服务器和工作站共享此数据库，形成所谓的 NT 域。

#### UNIX/Samba 系统

正如你可能猜到的，在密码同步方面，UNIX/Samba 提供了最多的可能性以及最大的复杂性。得益于 Samba，UNIX 可以以许多强大的方式与 Windows 客户端和服务器交互。

作为客户端，UNIX/Samba 系统可以成为现有 NT 域的一部分。通过使用可插认证模块（PAM），UNIX/Samba 系统可以使用 NT 服务器进行其部分密码验证。UNIX 系统也可以专门地使用它自己的内部密码数据库，或者挂载到 UNIX 分布式密码数据库（如 NIS）。

作为服务器，UNIX/Samba 系统可以管理自己的密码数据库。它可以为 Samba 准备一个数据库，为其他所有内容准备另一个数据库，或者这两个数据库可以同步。

### UNIX 和 Samba 之间的密码同步

在用户验证方面，Samba 提供了大量的选项。首先，Samba 可以以两种模式之一运行：加密密码模式或非加密密码模式。

当 Samba 配置为使用非加密密码时，它可以简单地使用存储在 `/etc/passwd` 中的用户名和密码进行验证。然而，当 Samba 以加密密码运行时，情况就会变得有点复杂。在这种情况下，Samba 无法使用你 UNIX 系统中不同加密的密码来验证通过线路收到的 SMB/CIFS 挑战。这意味着在加密密码模式下，Samba 需要一个额外的名为 `smbpasswd` 的密码文件。

### 使用 Samba 密码同步

所有以下选项都出现在 `smb.conf` 的 `[global]` 部分中。

Samba 有两种方法通过网络发送 SMB 密码——一种被称为加密密码。使用这种方法，Samba 将不会在网络上以明文形式发送任何密码。

不使用加密密码时，Samba 可以简单地使用 `/etc/passwd` 作为存储。然而，使用加密密码时，Samba 需要一个名为 `smbpasswd` 的额外文件。

#### 理解 smbpasswd 和 /etc/password 的交互

当 Samba 使用加密密码时，它需要一个名为 `smbpasswd` 的文件。然而，尽管这个文件存在，Samba 仍然需要 `/etc/password`。用户必须存在于 `/etc/password` 中以便 Samba 设置所有权，而用户必须存在于 `smbpasswd` 中以便其通过验证。

Samba 提供了几种让这些文件自动同步的方法；更多信息请参考 `unix password sync`、`sync program`。

### 高级加密密码主题

首先，我将对比 `encrypt passwords = yes` 的优点与 `encrypt passwords = no` 的优点。

非加密密码的主要优点是 Samba 可以使用标准的 UNIX 数据库执行所有验证，消除了对 `smbpasswd` 文件的需求。

### unix password sync =

`unix password sync` 默认设置为 `False`；但是，当它被设置为 `True` 时，Samba 会自动将用户的 UNIX 密码与 `smbpasswd` 中现有 Samba 密码的任何更改进行同步。

关于此命令，有一些重要的点需要注意。首先，如果你没有使用加密密码，那么 `unix password sync` 是没有必要的且不应该使用。其次，`unix password sync` 选项与其他配置选项配合工作：`password program`、`password chat`、`min password length` 和 `password chat debug`。

### smb password file =

使用此选项设置 Samba 加密密码文件 `smbpassword` 的完全限定路径。其默认值在编译时确定，但在典型系统上通常是 `/etc/smbpassword`。

### password program =

`password program` 是一个与 `unix password sync` 配合使用的配置选项；它指定了 Samba 使用什么程序来设置新的 UNIX 密码。`password program` 默认是 `/bin/passwd`。

你需要理解通过使用 `smbpassword` 命令发生密码更改时 Samba 采取的步骤：

1. 用户 bob 调用了 `smbpassword`。
2. Samba 以 root 权限运行命令 `/bin/passwd bob`。
3. 如果成功，Samba 继续更改 CIFS/SMB。如果不成功，Samba 终止。

### password chat debug =

`password chat debug` 是调试你的 password chat 脚本正常运行的重要工具。

### update encrypted =

`update encrypted` 是一个配置文件，帮助你从已经运行良好的非加密 Samba 环境迁移到使用 smbspwd 验证用户的环境。

### add user script =

用户脚本配置文件选项项为将 Samba 集成到已有的 Windows NT 网络中提供了一种非常方便的方法。

如果 `add user script` 设置指向一个有效脚本路径，该脚本将向系统添加用户，那么当该用户尝试访问 Samba 共享时，将发生以下情况：

- 用户将通过密码服务器进行身份验证。
- 如果用户通过身份验证，将检查 UNIX 密码数据库以查看该特定用户在 UNIX 中是否存在。
- 如果用户存在，他或她将获得共享访问权限。
- 如果用户不存在，将以 root 身份调用 `add user script`，并将用户添加到系统。
