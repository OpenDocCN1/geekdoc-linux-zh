
`inetd`下方可能列出了更多被注释掉的守护进程，例如`named`（将主机名转换为IP地址的名称服务器守护进程）、`routed`（用于路由）以及其他几个守护进程。除非你知道需要激活其中某个守护进程，否则暂时保持它们的注释状态。

你可能还希望运行的另一个守护进程是`syslogd`。它通常设置为自动执行。这是系统日志守护进程，用于收集其他应用程序的日志消息并将其存储到日志文件中。日志文件的位置（你可以随心所欲地更改）在`/etc/syslog.conf`文件中给出。

目前对`rc`文件的修改就到这里。在`TCP/IP`安装并测试通过后，可以依次启动其余的守护进程（`routed`、`named`等），以确保它们正常工作。首要任务是让`TCP/IP`能够与其他机器正常通信。然后你再对其进行微调！

## `/etc/hosts`

`/etc/hosts`文件是一个简单的IP地址及其对应主机名的列表。这是一个列出所有你常用机器的好地方，这样你就可以使用名称，并让系统查找IP地址。在非常小的网络上，你可以将所有机器都添加到这里，从而避免运行`named`守护进程的需求。

每个`/etc/hosts`文件都有一个`localhost`（也称为`loopback`，IP地址`127.0.0.1`）的条目，如果你在安装软件时为机器命名，可能还会有你机器的一个条目。如果你当时没有提供名称，且除了`localhost`外没有其他行，你可以现在添加。使用编辑器设置你的IP地址和机器名称。在你确定网络正常运作之前，不要急于添加太多其他机器！以下是一个`/etc/hosts`文件示例：

```
127.0.0.1		localhost
147.12.2.42		merlin.tpci merlin
```

你会注意到格式非常简单：一列是IP地址，另一列是名称，中间用制表符分隔。如果机器可能有多个名称，请提供所有名称。在示例中，使用了随机数字作为IP地址，机器`147.12.2.42`的名称是`merlin`。由于它也是名为`tpci`的较大网络的一部分，因此该机器可以被称为`merlin.tpci`。行上的两个名称确保系统可以将任一名称解析为同一个地址。

如果需要，你可以通过添加本地网络上的其他机器，或者你经常通信的机器，来稍微扩展该文件：

```
127.0.0.1		localhost
147.12.2.42		merlin.tpci merlin
147.12.2.43		wizad.tpci wizard
```

### `/etc/hosts`

```
147.12.2.44 arthur.tpci arthur bob's_machine
147.12.2.46 lancetot.tpci lancetot
```

在这个示例中，有几台机器来自同一个网络（相同的网络地址）。其中一台机器有三个不同的名称。

如果你只使用回环驱动，那么文件中应该只有一行，该行包含IP地址`127.0.0.1`，名称为`localhost`，后面跟随你的机器名称。

### `/etc/networks`

`/etc/networks`文件列出了你自己的网络以及其他你经常连接的网络的名称和IP地址。该文件由通过`rc.inet1`文件启动的`route`命令使用。这个文件的一个优点是，它允许你通过名称调用远程网络，因此你不需要输入`149.23.24`，而是可以输入`eds_net`。

`/etc/networks`文件应为每个将与`route`命令一起使用的网络提供条目。如果没有条目，将产生错误，并且网络将无法正常工作。

下面展示了一个使用随机IP地址的`/etc/networks`文件示例。请记住，你只需要远程机器IP地址的网络地址部分，而不需要设备部分，尽管你必须用零填充其余部分。

```
loopback 127.0.0.0
localNet 147.13.2.0
eds_net 197.32.1.0
big_net 12.0.0.0
```

至少，文件中必须包含一个回环（`loopback`）和一个`localNet`地址。

### `/etc/host.conf`

系统使用`host.conf`文件来解析主机名。它通常包含两行，如下所示：

```
order hosts, bind
multi on
```

这些配置告诉系统在尝试解析名称时，先检查`/etc/hosts`文件，然后再检查名称服务器（如果存在）。`multi`条目允许你在`/etc/hosts`文件中为机器设置多个IP地址（这种情况通常发生在网关或位于多个网络上的机器上）。

如果你的`/etc/host.conf`文件看起来像这两行，那么你完全不需要进行任何更改。

## `/etc/resolv.conf`

`resolv.conf`文件由名称解析程序使用。它提供你的名称服务器的地址（如果你有的话）和你的域名（如果你有的话）。如果你在Internet上，你就拥有域名。

以下是系统`merlin.tpci.com`的`resolv.conf`文件示例，其中包含一个域名条目，即`tpci.com`（`merlin`是单台机器的名称）：

```
domain tpci.com
```

如果在你的网络中使用了名称服务器，你应该添加一行，提供其IP地址：

```
domain tpci.com
nameserver 182.23.12.4
```

如果有多个名称服务器（在较大的网络中并不罕见），每个名称服务器都应单独放在一行上。

如果你的系统没有域名，你可以暂时安全地忽略此文件。

## `/etc/protocols`

UNIX系统使用`/etc/protocols`文件来识别系统上可用的所有传输协议及其各自的协议编号。（`TCP/IP`支持的每个协议都有一个特殊的编号，但这在现阶段并不重要。）通常，此文件不会被修改，而是由系统维护，并在安装新软件时作为安装过程的一部分自动更新。

`/etc/protocols`文件包含协议名称、其编号以及该协议可能使用的任何别名。`/etc/protocols`文件的一个示例看起来像这样：

```
# Internet protocols (IP)
ip		0	IP
icmp		1	ICMP
ggp		3	GGP
tcp		6	TCP
egp		8	EGP
pup		12	PUP
udp		17	UDP
hello		63	HELLO
```

如果你的条目与此不匹配，不要担心。你不需要对此文件进行任何更改，但你应该知道它的功能。

## `/etc/services`

`/etc/services`文件标识现有的网络服务。此文件由软件在安装或配置时维护。

此文件由服务名称、端口号和协议类型组成。端口号和协议类型之间用斜杠分隔，遵循前面章节中提到的约定。任何可选的服务别名名称随后列出。以下是`/etc/services`文件的一个简短摘录：

```
# network services

echo 7/tcp
echo 7/udp

discard 9/tcp sink null
discard 9/udp sink null

ftp 21/tcp
telnet 23/tcp
smtp 25/tcp mail mailx
tftp 69/udp

# specific services

login 513/tcp
who 513/udp whod
```

你不应该更改此文件，但你需要知道它是什么以及它为什么在那里，这有助于你更好地理解`TCP/IP`。

## `/etc/hostname`或`/etc/HOSTNAME`

文件`/etc/hostname`或`/etc/HOSTNAME`用于存储你所登录系统的名称。（Slackware Linux使用名称的大写版本。）此文件应包含你本地机器的名称：

`merlin.tpci`

这就足够了。主机名被系统中大多数协议和许多应用程序使用，因此对于系统的正常运行非常重要。可以通过编辑系统文件并重新启动机器来更改主机名，尽管许多发行版都提供了实用程序，以确保此过程正确执行。

Linux系统有一个名为`hostname`的实用程序，它显示系统名称的当前设置，还有`uname`程序，它可以通过命令`uname -n`给出节点名称。当发出`hostname`和`uname`命令时，它们会回显本地机器名称，如下面的示例会话所示：

```
$ hostname
merlin.tpci.com
$ uname -n
merlin
```

某些Linux版本的`hostname`只显示名称，而不附带域名。所有`TCP/IP`功能所需的配置文件现在都已正确设置，因此你应该能够重新启动机器并查看会发生什么。

## 测试和故障排除

为了测试`TCP/IP`，请重新启动你的机器，并仔细查看屏幕上显示的消息。如果你看到任何错误消息，它们可能有助于引导你找到有问题的文件或进程。否则，你会看到`TCP/IP`守护程序一个接一个地加载。

### `netstat`命令

检查`TCP/IP`状态的最佳方法可能是使用`netstat`命令，该命令提供所有网络连接及其状态的许多不同摘要。`netstat`程序提供综合信息。它是管理员最常用的快速诊断`TCP/IP`问题的程序。
