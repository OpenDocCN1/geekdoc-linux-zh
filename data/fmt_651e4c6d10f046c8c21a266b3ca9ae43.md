## 反向解析

给定一个 IP 地址，通常有必要找到与之关联的名称，例如在编写 Web 服务器日志时。这个过程被称为反向解析或反向查找，它是通过一种优雅的策略完成的。IP 地址类似于文件名，从 DNS 的角度来看是“反向”的。由于我们只能将 RR 资源记录与 DNS 名称关联，因此我们必须找到一种方法，将具有从左到右层次结构的 IP 地址 `129.42.18.99` 属于 `129.*` 写成一个具有从右到左层次结构的 DNS 名称 `ibm.com` 属于 `com`。

我们通过反转地址中八位字节的顺序，然后在结果后附加 `.in-addr.arpa` 一个专门用于支持反向查找的域来做到这一点。例如，`129.42.18.99` 将被写为 `99.18.42.129.in-addr.arpa`。与此特殊名称关联的 `PTR` 指针记录随后会告诉我们该 IP 所属主机的真实名称。

我们可以以通常的方式查找 PTR 记录——通过从根服务器开始的委托链。我们通过解析 `203.200.109.66` 这是 ISP 分配给客户的一个拨号 IP 地址简要考察了这个过程。我们向根名称服务器询问 `66.109.200.203.in-addr.arpa`：
