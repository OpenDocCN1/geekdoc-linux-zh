# 全局

- `#` 开始注释。注释在下一个换行符处结束。如果命令行中 `Tab` 之后是 `#`，则将该行传递给 `shell`（将 `#` 视为注释的开始）。

# 目标与依赖

- `:` 目标列表终止符。将冒号后的单词添加到目标或目标的依赖列表中。如果你为多个以冒号终止的目标命名，则将其所有条目的依赖项添加以形成目标的完整依赖列表。

- `::` 替代依赖的目标终止符。当用于替代分号（`;`）时，双冒号允许目标检查并更新替代依赖列表。当目标与第一个替代中的依赖过期时，根据该条目的规则构建。当与另一个替代中的依赖过期时，根据该条目的规则构建。隐式规则不适用于双冒号目标；你必须为每个条目提供规则。如果指定 `no`，则规则始终执行。

- `target [+ targets...]` 使用目标中的行构建指示的所有目标作为一个组。这通常每次 `make` 运行只执行一次，但在依赖扫描中遇到组中的每个目标时都会检查命令依赖。

- `%` 匹配目标名或依赖中零或多个字符的任何字符串，在条件定义的的目标部分或模式替换宏引用中（类似于 `shell` 通配符）。注意，目标、依赖名或模式替换宏引用只能有一个 `%`。

- `./pathname` 忽略相对于点（工作目录）给出的目标开头的 `.` 字符。

# 宏

- `=` 宏定义。该字符左侧的单词是宏名；右侧的单词构成其值。剥离值首尾的空白字符。隐含 `=` 之后存在单词分隔符。

- `$` 宏引用。将随后的字符或括号/大括号内的字符串解释为宏引用。通过将其替换为宏的值来展开引用（包括 `$`）。

- `( )` 或 `{ }` 宏引用名称分隔符。将附加在 `$` 后的括号或大括号内的单词视为所引用的宏名。如果没有分隔符，`make` 只将第一个字符识别为宏名。

- `$$` 对美元符号宏的引用，其值为 `shell`。用于将以 `$` 开头的变量扩展传递给 `shell`，用于引用由 `shell` 扩展的环境变量，或延迟处理目标依赖列表中的动态宏，直到它们被实际处理。

- `\$` 转义美元符号字符。在规则内部被解释为字面量美元符号。

- `+=` 当替代 `=` 使用时，将字符串追加到宏定义中（与 `=` 不同，它必须被空格包围）。

- `:=` 条件宏赋值。

- `:=:` 定义宏的值为命令的输出（详见第 810 页的“命令替换”）。

- `=` 在宏引用中，带有命令的输出（详见第 810 页的“命令替换”）。

# 规则

- `+` 始终执行由 `(+)` 之前的命令，即使你指定了 `-n` 也是如此。

- `-` 忽略命令返回的非零错误代码。该字符是横杠（`-`）。

- `@` 如果第一个非 `Tab` 字符是 `@`，则在执行命令前不打印命令行。该字符不会传递给 `shell`。

# 特殊函数目标

当整合到 `makefile` 时，以下目标名称执行特殊函数。

- `.DEFAULT:` 如果在 `makefile` 中有条目，当没有其他条目、构建规则以及可以检索当前版本的 `SCCS` 文件时，使用该规则。`make` 忽略该目标的任何依赖。

- `.DONE:` 如果在 `makefile` 中定义，则在构建所有目标后处理此目标及其依赖。当 `make` 因错误停止时，除非定义了 `.FAILED:target`，否则也会执行此目标。

- `.FAILED:` 当发生错误时，执行此目标及其依赖以代替 `.DONE`。

- `.GET_POSIX:` 从当前目录的历史文件中检索 `SCCS` 文件的当前版本。在 `POSIX` 模式下运行时使用此规则。

- `.IGNORE:` 忽略错误。当它出现在 `makefile` 中时，忽略命令返回的非零错误代码。在 `POSIX` 模式下，`.IGNORE:` 只能跟随目标名称，这些目标的错误将被忽略。

- `.INIT:` 如果在 `makefile` 中定义，则在处理任何其他目标之前构建此目标及其依赖。

- `.KEEP_STATE:` 该目标在 `POSIX` 模式下没有作用。如果该目标生效，则更新目录下的 `.make_state` 文件。同时激活命令依赖检查和隐藏依赖检查。如果设置了 `.KEEP_STATE:` 目标（`setenv KEEP_STATE*`），即使所有目标由于之前的 `make` 运行已是新的，也会重新构建以收集依赖信息。另见第 811 页的“环境变量”。

`.KEEP_STATE_FILE:` 

此目标在 `POSIX` 模式下使用时没有效果。此目标意味着 `.KEEP_STATE_FILE:`。如果目标后面跟着一个文件名，则将其用作状态文件。如果目标后面跟着目录名，则在该目录中查找 `.make.state` 文件。如果目标后面没有任何名称，则在当前工作目录中查找 `.make.state` 文件。

`.MAKE_VERSION:` 

如下格式的目标条目：

```
.MAKE_VERSION: VERSION-number
```

启用版本检查。如果 `make` 的版本与指定的版本不同，`make` 将发出一条警告信息。

`.NO_PARALLEL:` 

留供未来使用。

`.PARALLEL:` 

留供未来使用。

`.POSIX:` 

启用 `POSIX` 模式。

`.PRECIOUS:` 指定一个不删除的文件列表。在被中断时，不要删除列为此目标依赖的任何文件。`make` 在接收到中断时通常会删除当前目标。在 `POSIX` 模式下使用，如果目标后面没有文件列表，则假设所有文件都是珍贵的。

`.SCCS_GET:` 包含从历史文件中检索 `SCCS` 文件当前版本的规则。要抑制自动检索，请在你的 `Makefile` 中此目标添加一个带有空规则的条目。

# 宏

如下格式的条目定义宏。

```
macro=value
```

`macro` 是宏的名称，`value` 是由到注释字符或未转义换行符为止的所有字符组成的值。`make` 在接受值时会去除首部和尾部的空白。

对该宏的后续引用 `$(name)` 或 `$(name)` 将被 `value` 替换。在引用具有单字符名称的宏时，你可以省略括号或中括号。

宏引用可以包含对其他宏的引用，在这种情况下，嵌套引用会被先展开。

# 后缀替换宏引用

宏内部的替换可以如下所示进行：

```
$(name:string1=string2)
```

其中 `string1` 是宏定义中要替换的后缀或单词，而 `string2` 是替换的后缀或单词。宏值中的单词通过空格、制表符和转转义的换行符分隔。

# 模式替换宏引用

模式匹配替换也可以应用于宏，其引用采用如下形式的形式：

```
$(name:op%os=np%ns)
```

其中 `op` 是现有的（旧）前缀，`os` 是现有的（旧）后缀，`np` 和 `ns` 是新的前缀和后缀，而 `%`（零或多个字符的字符串）匹配的模式将从被替换的值传递。例如，以下语句将 `DEBUG` 的值设置为：

```
tmp/fabricate-g.
```

```
PROGRAM=fabricate
```

```
DEBUG=$ $(PROGRAM:%=tmp/%-g)
```

注意 —— 不能在模式匹配规则的依赖列表中使用模式替换宏引用；`%` 字符不会独立求值。此外，等号后可以任意任意数量的 `%` 元字符。
