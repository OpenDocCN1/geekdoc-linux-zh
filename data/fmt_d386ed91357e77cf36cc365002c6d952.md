# 跳出循环

bash 提供了两个用于控制流的内置命令：`break` 和 `continue`。`break` 立即终止循环，而 `continue` 跳过循环的剩余部分。在这里我们看到包含了 `break` 和 `continue` 的 `while-menu` 程序版本，使用了无限循环：

```bash

#!/bin/bash

# while-menu2: 菜单驱动系统信息程序

DELAY=3 # 显示一系列数字

while true; do

  clear

  cat <<EOF

    Please Select:

    1. Display Information

    2. Display Disk Space

    3. Display Home Utilization

    0. Quit

EOF

  read -p "Enter selection [0-3] > " REPLY

  if [ "$REPLY" =~ ^[0-3]$ ]; then

    if [ "$REPLY" == 1 ]; then

      echo "Hostname: $HOSTNAME"

      uptime

      sleep "$DELAY"

      continue

    fi

    if [ "$REPLY" == 2 ]; then

      df -h

      sleep "$DELAY"

      continue

    fi

    if [ "$REPLY" == 3 ]; then

      if [ "$(id -u)" -eq 0 ]; then

        echo "Home Space Utilization (All Users)"

      else

        echo "Home Space Utilization ($HOME)"

      fi

      sleep "$DELAY"

      continue

    fi

  fi

  if [ "$REPLY" == 0 ]; then

    break

  fi

  echo "Invalid selection."

  sleep "$DELAY"

done

echo "Program terminated."

```

# until

`until` 复合命令与 `while` 非常相似，但它在遇到非零退出状态时进入循环，而恰恰相反。`until` 循环会一直持续，直到收到零退出状态。在我们的 `while-count` 脚本中，只要 `count` 的值小于等于 5，循环就会继续。我们可以通过使用 `until` 编写脚本获得相同的结果。

```bash

#!/bin/bash

# until-count: 显示一系列数字

```

```bash

count=1

until [ "$count" -gt 5 ]]; do

  echo "$count"

  count=$((count + 1))

done

echo "Finished."

```

通过将表达式改为 `$count -gt 5`，`until` 将在正确的时间终止循环。使用 `while` 还是 `until` 循环通常取决于哪一个可以让测试条件的编写得清晰。

## 使用循环读取文件

`while` 和 `until` 可以处理标准输入。这允许使用 `while` 和 `until` 循环处理文件。在下面的示例中，我们将显示之前章节中 `distros.txt` 文件的内容：

```bash

#!/bin/bash

# while-read: 从文件中读取行

while read distro version release; do

  printf "Distro: %s\tVersion: %s\tReleased: %s\n" \

    "$distro" \

    "$version" \

    "$release"

done < distros.txt

# while-read2: 从文件中读取行

sort -k 1,1 -k 2n distros.txt | while read distro version release; do

  printf "Distro: %s\tVersion: %s\tReleased: %s\n" \

    "$distro" \

    "$version" \

    "$release"

done

```

要将文件重定向到循环，我们将重定向运算符放在 `done` 语句之后。循环将使用 `read` 从重定向文件中输入字段。`read` 命令在读取每行后都会退出，在达到文件结束（EOF）之前，其退出状态为零。在那个一点，它将以非零退出状态退出，从而终止循环。也可以将输入管道到循环中。

在这里，我们获取 `sort` 命令的输出并显示文本流。然而，重要的是记住，由于管道将在子壳（subshell）中执行循环，循环内部创建或赋值的任何变量将在循环结束时丢失。

# 故障排除

现在我们的脚本变得越来越复杂，是时候看看出现问题时会发生什么了。在本章，我们将查看脚本中发生的一些常见错误，并检查一些可以追踪和消除问题的有用技术。

## 语法错误

一类通用错误是语法错误。语法错误涉及对 shell 语法中某些元素的拼写错误。shell 在遇到此类错误时将停止执行脚本。

在下面的讨论中，我们将使用此脚本演示常见的错误类型。

```bash

#!/bin/bash

# trouble: 演示常见错误的脚本

number=1

if [ $number = 1 ]; then

    echo "Number is equal to 1"

else

    echo "Number is not equal to 1"

fi

```

按照目前的写法，此脚本运行成功。

```bash

[me@linuxbox~$ trouble

Number is equal to 1.

```

### 缺少引号

让我们编辑脚本，移除第一个 `echo` 命令之后参数的末尾引号。

```bash

#!/bin/bash

# trouble: 演示常见错误的脚本

number=1

if [ $number = 1 ]; then

    echo "Number is equal to 1"

else

    echo "Number is not equal to 1"

fi

```

发生的情况如下：

```bash

[me@linuxbox ~]$ trouble

/home/me/bin/trouble: line 10: unexpected EOF while looking for matching ''

/home/me/bin/trouble: line 13: syntax error: unexpected end of file

```

它产生了两个错误。有趣的是，错误信息报告的行号并不是移除缺失引号的地方，而是程序后很多。如果我们顺着缺失的引号找，就能知道为什么。bash 会继续寻找闭合引号直到找到它，而它在第二个 `echo` 命令之后就找到了。此后，bash 变得困惑。后续命令的语法被破坏，因为 `fi` 语句现在位于一个被引用（但未关闭）的字符串内部。

在长脚本中，这种错误可能很难找到。使用带有语法高亮的编辑器会有帮助，因为在大多数情况下，它会以不同于其他 shell 的方式显示引号字符串。如果安装了完整版本的 vim，可以通过输入此命令启用语法高亮：

```bash

:syntax on
```
