
| `/dev/sda3` | | 169 | 169 | 231 | 130851 | 82 | Linux swap |
| `/dev/sda4` | | 232 | 232 | 1009 | 161506 | 5 | Extended |
| `/dev/sda5` | | 232 | 232 | 398 | 346828 | 83 | Linux native |
| `/dev/sda6` | | 399 | 399 | 1009 | 1269016 | 83 | Linux native |
| `/dev/sdb1` | | 1 | 1 | 509 | 2114355 | 83 | Linux native |
| `/dev/sdb2` | | 510 | 510 | 1019 | 211854 | 83 | Linux native |

第一个分区 `/dev/sda1` 是一个 DOS 格式的文件系统，用于存储另一个操作系统（Windows 95）。这为该操作系统提供了 1 Gb 的空间。

第二个分区 `/dev/sda2` 是一个名为 `('extended')`（扩展）的物理分区，它涵盖了设备上的剩余空间。它用于封装剩余的逻辑分区（磁盘上只能有 4 个物理分区；在我的情况下，我需要超过 4 个分区，因此我对其他分区使用了逻辑分区方案）。

第三到第五个分区 `/dev/sda3`、`dev/sda4` 和 `/dev/sda5` 都是 e2fs 格式的文件系统，分别用于 `/root`、`/usr` 和 `/home` 分区。

最后，第六个分区 `/dev/hda8` 用于交换分区。

## 4.8. 使用 LILO 启动

接下来，安装程序需要向你的硬盘写入引导加载程序。引导加载程序（在 Intel 系统上为 LILO）负责启动 Linux，以及在你设置了多系统启动时的启动任何其他操作系统（详情请参见第 4.8.1 节）。

### 4.8.1. 与其他操作系统多系统启动

最后，如果你设置了系统与其他操作系统共同启动 Linux，你将看到第三个对话框，列出了可用分区。在这里，你可以为其他操作系统分配名称（你可以在启动时的 `LILO` 提示符处输入这些名称来启动所需的操作系统）。安装程序确实会为每个可启动分区分配默认名称，除非你不喜欢默认值，否则没有必要更改它们。

系统启动时默认的操作系统无疑将是 Linux。但是，如果你愿意，可以将默认值更改为你定义的任何其他操作系统。

在硬盘上安装完引导加载程序后，安装程序应该会向你显示 `恭喜（Congratulations!）` 对话框，表示 Linux 已成功安装。移除安装软盘（如果有），并按 `<Enter>` 重启进入 Linux！

Linux 将启动，如果一切顺利，你将看到 `登录（login）` 提示。从这里开始，你可以使用安装过程中分配的任何密码以 `root` 登录。

## 4.9. 下载并安装 Red Hat 更新

到为止，Red Hat 了一些非常令人深刻的发行版本，但似乎有在产品尚未完全 `准备就绪` 时就发布的记录。因此，为了充分利用你的 Linux 系统，下载并应用更新包是很有必要的。这些包也称为 `rpm 文件`，使用 RPM 工具进行应用（关于该工具的详情，请参见第 10.1 节）。

这证明将是准备好 Linux 系统最耗时的部分之一（除非你拥有极快的互联网连接）。然而，请花时间完成这一点！你可能会省去很多麻烦！

首先，从以下地址下载所有文件：

```
ftp://ftp.redhat.com/redhat/updates/6.1/1386/
```

（假设你正在 Intel 设备上运行 Linux）。

你应该将所有内容下载到单个目录中，然后只需输入：`rpm -Uvh *` 即可升级包。如果你下载了任何内核 rpm 文件，目前可能应该将它们移动到另一个目录。升级或自定义你的内核要复杂一些，并且需要非常小心地处理（详情参见第 10.4 节）。因此，在应用更新之前，你可能希望将所有 `kernel-*.rpm` 文件移出你的临时更新目录。

要应用更新，你可以直接对所有包运行 `rpm`（例如 `rpm -Uvh *`），或者如果你愿意，可以一个一个地升级它们（例如 `rpm -Uvh file_to_upgrade.rpm`）。后一种方法适用于我们这些强迫症类型，我们希望确保每个更新都正确应用且没有错误:-)

也许你好奇想在尝试升级某个包之前先查看该包是否已安装。或者，你可能想知道某个包安装的是哪个版本。这一切都可以通过 RPM 工具完成；详情请参见第 10.1 节。

# 第 5 章 配置 X Window 系统

X Window 系统，又称 `X`（许多人经常且错误地称为 `X-Windows`）是一个运行在 Linux 之上的 GUI。与 Microsoft Windows 不同，X Window 系统可以有许多不同的外观和运行方式。它可以是原始的也可以是非常先进的，外观可以美观也可以丑陋，运行可以流畅快速也可以缓慢（这些都是主观属性，引发的用户间争论就像 `Linux 对阵 Microsoft NT` 辩论一样）。

让 X 正常工作的难度从简单到令人抓狂的复杂不等！这是 Linux 新手用户的常见抱怨，我自己也与配置设置斗争过无数次，我对此完全感同。幸运的是，在较新的 Linux 发行版中，这种配置变得越来越简单和自动化了。事实上，如果你使用的是 Red Hat 6.1，你可能不需要担心这个问题。

虽然在大多数情况下 X 可以自动配置，但仍有例外；我在这里指出这些例外。

## 5.1. 让 X 工作

让 X 工作有两种主要方法，第一种是使用配置文件，第二种是使用命令行。第一种更灵活，因为它允许为不同的会话指定不同的配置。第二种方法简单但灵活性较低。

如果你想使用第一种，你需要编辑 `/etc/X11/xinitrc` 文件。该文件包含 X 服务器的设置，如分辨率、色彩深度以及要使用的窗口管理器。

## 5.2. 使用 X 桌面管理器

如果你愿意，可以使用 X 桌面管理器 (`xdm`) 在启动时自动启动 X Window 系统。这让你的 Linux 系统始终运行在 X 下（尽管你可以通过 `<Ctrl><Alt>-<F1>` 切换到常规控制台，需要时通过 `<Alt><F7>` 回到 GUI）。

要启用 `xdm`，只需编辑 `/etc/initabb` 文件并修改包含如下内容的行：

```
id:5:
initdefault:
```

上述更改将使 Linux 在系统启动时切换到级别 5；此运行默认将启动 `xdm`。

```
x:respawn:/usr/bin/X11/xdm -nodemon
```

如果你启用了 `xdm` 并且希望使用比默认值 8 更高的 `bpp` 值（且你的显卡和显示器支持它），你需要按照如下方式修改 `etc/X11/xdm/Xservers` 文件：

```
:0 local /usr/X1R6/bin/X -bpp 24
```

上述更改将以每像素 24 位（24 bits）启动 `xdm`。

你可能还想编辑 `etc/X11/xdm/Xsetup_0` 文件，并用 `#` 字符注释掉以 `xbanner` 开头的行，如下所示：

```
#/usr/X1R6/bin/xbanner
```

这将防止默认的 `xdm` 横幅屏在 KDE 会话之间进行分屏显示时出现。我知道，这只是为了美观，但是……

> 提示：有时你可能会发现需要切换回控制台（例如，某些游戏在控制台运行，但在 X 下不运行）。有两种方法可以实现。要临时从 X 切换到控制台，按下 `<Alt><F1>`；要切换回 X，按下 `<Alt><F7>`。或者，如果你想完全终止 X（从而释放你的可用内存），你可以以 `root` 身份输入 `"/sbin/telinit 3"` 来切换系统运行级别；这告诉 XDM 终止。要切换回，输入 `"/sbin/telinit 5"`

## 5.3. 改进 X 下的字体外观

坦率地说，X 从来不是以具有特别吸引力的字体而闻名的。事实上，许多人接受了这样观点：拥有丑陋、难看的字体是 X 系统中一种不幸的命运。

幸运的是，在 X 下可以显著改善字体的外观并增加你可以使用的字体数量。事实上，如果你有一份 Windows 系统，你甚至可以从该平台复制 TrueType 字体并在 X 下使用它们！这种字体支持是通过使用如 `xfsft` 或 `xfs` 这样的字体服务器来实现的。
