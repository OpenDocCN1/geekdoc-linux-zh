
- 一个持有正在检查的数字的变量

在这种情况下，我们足够的变量可以将它们全部放在寄存器中。在较大的程序中，你必须将它们放在内存中，然后在准备使用时将它们移动到寄存器。我们之后会讨论这样做。当人们开始编程时，通常会低估他们将需要的变量数量。人们不习惯仔细思考一个过程的每一个细节，因此在第一次编程尝试中漏掉变量。

在这个程序中，我们使用 `%edi` 作为我们找到的最大项的位置。`%edi` 用作我们正在查看的数据项的索引。现在，让我们谈谈索引。当我们从 `data_items` 读取信息时，我们将从第一个项开始（数据项编号 0）。

## 第 3 章 你的第一个程序

我们将第一个要查看的项存储在 `%eax` 中。由于它是第一个项，我们知道它是我们目前看过的最大的一个。我们将其存储在 `%ebx` 中，因为这是我们用来存储找到的最大数值的地方。此外，尽管 `movl` 代表“移动”（move），但它实际上是复制该值，因此 `%eax` 和 `%ebx` 都包含该初始值¹。

现在我们进入一个*循环*（loop）。循环是程序中可能运行多次的段。我们已经用符号 `start_loop` 标记了循环的起始位置。我们之所以使用循环是因为我们不知道需要处理多少个数据项，但无论有多少个，处理过程都是相同的。我们不想为每种可能的列表长度都写一遍程序。事实上，我们甚至不需要为每个列表项编写代码。因此，我们使用了一段单一的代码（一个循环）。在上一节中，我们概述了该循环需要执行的操作。让我们回顾一下：

- 检查当前查看的值是否为零。如果是，则意味着我们到达了数据的末尾，应该退出循环。
- 我们必须加载列表的下一个值。
- 我们必须查看下一个值是否大于我们当前的最大值。
- 如果是，我们必须将其复制到我们存放最大值的位置。
- 现在我们需要回到循环的开头。

好了，现在让我们来看代码。我们用 `start_loop` 标记了循环的开头。这样我们知道在循环结束时回到哪里。然后我们有这些指令：

```
cmpl $0, %eax
je end_loop
```

¹¹。另外，`movl` 中的 `l` 代表“长位移动”（move long），因为我们正在移动的是一个占用四个存储位置的值。

`cmp` 指令比较两个值。在这里，我们正在比较存储在 `%eax` 中的数字 0。这次比较还会影响一个这里没有提到的寄存器，即 `%flags` 寄存器。这也被称为状态寄存器，其用处我们将在稍后讨论。只需注意比较的结果就存储在状态寄存器中即可。下一行是一个流控制指令，意为如果刚刚比较的值相等，则跳转到 `end_loop` 位置（这就是 `je` 中 `e` 的含义）。它使用寄存器来持有最后一次比较的值。我们使用了 `je`，但你还可以使用许多其他的跳转语句：

- `je` | 如果值相等则跳转
- `jg` | 如果第二个值大于第一个值则跳转¹²
- `jge` | 如果第二个值大于或等于第一个值则跳转
- `jl` | 如果第二个值小于第一个值则跳转
- `jle` | 如果第二个值小于或等于第一个值则跳转
- `jmp` | 无论如何都跳转。这不需要前面有比较指令。

¹² 注意，比较是为了查看第二个值是否大于第一个值。我原还以为是相反的。在学习编程时，你会发现很多这样的事情。发生这种情况的原因是不同的事情对不同的人有不同的意义。总之，你只需要记住这些事情并继续下去。

完整的列表记录在附录 B 中。在这种情况下，如果 `%eax` 持有的值为零，我们就跳转。如果是这样，我们就完成了并进入 `loop_exit`¹³。

如果最后加载的元素不是零，我们就继续执行后续的指令：

```
incl %edi
movl data_items(,%edi,4), %eax
```

如果你还记得我们之前的讨论，`%edi` 包含了我们在 `data_items` 中值列表的索引。`incl` 将 `%edi` 的值加 1。然后 `movl` 与我们之前做的一样。然而，我们已经增加了 `%edi`，`%eax` 正在从列表中获取下一个值。现在 `%eax` 拥有要测试的值。那么，让我们测试它吧！

```
cmpl %ebx, %eax
jle start_loop
```

在这里，我们将存储在 `%ebx` 中的当前值与我们到为止最大的值进行比较。如果当前值小于或等于我们到为止的最大值，我们就不不在乎它，所以直接跳回循环开头。否则，我们需要记录该值为最大值：

```
movl %eax, %ebx
jmp start_loop
```

这会将当前值移动到 `%ebx`（我们用它来存储当前最大值），并重新开始循环。

好了，循环一直执行到遇到 0 为止，此时会跳转到 `loop_exit`。程序的这部分调用了 Linux 内核。如果你还记得上一个程序，当你调用操作系统时（记住这就像给蝙蝠曼信号，你将系统调用号存储在 `%eax` 中（退出调用为 1），并将其他值存储在其他寄存器中）。

¹³。这些符号的名称可以是你想要的任何名称，只要它们包含字母和下划线（_）。唯一强制的是 `_start`，以及可能的其他你用 `.global` 声明的符号。然而，如果你定义了一个只使用的符号，可以随意将其命名为你认为具有足够描述性的名称（记住以后其他人必须修改你的代码，并且必须弄清楚你的符号含义）。

## 寻址模式

寻址模式非常重要，因为每次内存访问都会使用这些模式之一。除了立即模式（immediate mode）之外，每模式都可以作为源操作数或目标操作数。

### 直接寻址

直接模式从内存位置加载值。例如，如果你想将内存位置 1000 的值加载到 `%eax`，你可以：

```
movl 1000, %eax
```

### 间接寻址

间接模式从寄存器指示的地址加载值。例如，如果 `%eax` 持有一个地址，我们可以通过这样做将该地址的值移动到 `%ebx`：

```
movl (%eax), %ebx
```

### 基址寻址

基址寻址与间接寻址类似，区别是在寄存器基础上加上一个常量。例如，如果你有一个记录，年龄值在记录的 4 字节处，并且你在 `%eax` 中有记录的地址，可以通过以下指令获取年龄到 `%ebx`：

```
movl 4(%eax), %ebx
```

### 立即模式

立即模式非常简单。它不遵循我们一直使用的通用形式。立即模式用于直接加载寄存器或内存位置。例如，如果你想将数字 12 加载到 `%eax`，只需：

```
movl $12, %eax
```

### 索引寻址

索引寻址通过使用寄存器作为索引来实现。例如，假设我们有一个字节字符串并想访问第三个字节。你可以使用任何通用寄存器作为字节、双字节或字的索引：

```
movl string_start(ecx), %eax
```

### 寄存器寻址

寄存器模式简单地在寄存器之间移动数据。在我们所有的示例中，寄存器寻址模式都用于另一个操作数。

## 第 3 章 你的第一个程序

除了这些模式外，针对不同大小数值的移动还有不同的指令。例如，我们一直在使用 `mov` 一次移动一个字（word）。在很多情况下，你可能只想一次移动一个字节（byte）数据。这是通过 `movb` 指令实现的。然而，我们讨论过的寄存器是字大小的而不是字节大小的，你无法使用整个寄存器。相反，你必须使用寄存器的部分。

以 `%eax` 为例。如果你只想一次处理两个字节，只需要使用 `%ax`。`%ax` 是 `%eax` 寄存器的低位部分（即数字的最后部分），处理双字节数量时非常有用。`%ax` 进一步分为 `%al` 和 `%ah`。`%al` 是 `%ax` 的低位字节，而 `%ah` 是高位字节。将一个值加载到 `%eax` 会抹掉 `%al` 和 `%ah` 中的任何内容（同时也包括 `%ax`，因为 `%ax` 是由它们组成的）。

同样，将一个值加载到 `%al` 或 `%ah` 都会破坏 `%eax` 中原有的任何值。基本上，明智的做法是只用一个寄存器处理字节或字，而不是同时处理两者。

- 14. 当我们谈到高位字节时，可能会有点困惑。以数字 5432 为例。在该数字中，54 是该数字的高位部分，32 是低位部分。你不能那样划分寄存器，因为它们是基于二进制而不是十进制数字操作的，但基本原理如此。关于此主题的更多信息，请参见第 10 章。
