## regcmp — 编译正则表达式

## 概览

`/usr/ccs/bin/regcmp [-] filename...`

## 描述

`regcmp` 命令的功能与 `regcmp(3C)` C 语言库函数类似。在大多数情况下，`regcmp(1)` 命令消除了在 C 程序中调用 `regcmp(3C)` 函数的需求。绕过 `regcmp(3C)` 可以节省执行时间和程序大小。`regcmp` 命令编译 `filename` 中的正则表达式，并将输出放在 `filename.1` 中。

## regcmp

## 选项

将输出放在 `filename.c`。`filename` 中条目的格式为名称（C 变量），后跟一个或多个空格，然后是一个或多个个用双引号括起来的正则表达式。`regcmp` 的输出是源代码。已编译的正则表达式表示为 `extern char` 向量。因此，`filename.i` 文件可以包含在 C 程序中，`filename.c` 文件可以被编译并在以后加载。在使用 `regcmp` 输出的程序中，`regex(abc,line)` 将名为 `abc` 的正则表达式应用到 `line` 上。不言自明。

## 示例

在以下示例中，`telno` 的三个参数必须在同一行输入：

```
name "([A-Za-z] [A-Za-z0-9]*)\$"
telno "((0,1) [2-9](01) [1-9])\$$(0,1)"
  "([0-9](2-9))\$[-1](0,1)"
  "([0-9](4))\$2"
```

在使用 `regcmp` 输出的 C 程序中，以下语句将名为 `telno` 的正则表达式应用到 `line`。

```
regex(telno, line, area, exch, rest)
```

## 环境变量

参见 `environ(5)` 获取 `LC_*` 环境变量的通用描述。

- `LC_TYPE` 决定 `regcmp` 如何处理字符。当 `LC_TYPE` 设置为有效值时，`regcmp` 可以显示和处理包含该区域有效字符的文件名。
- `LC_MESSAGES` 决定诊断和信息消息的呈现方式，包括消息的语言和样式以及肯定和否定响应的正确形式。在 C 区域中，消息以程序本身中找到默认形式呈现（大多数情况下是美国英语）。

## renice — 修改运行进程的优先级

## 概览

```
/usr/bin/renice [-n increment][-g -p] [-u] ID...
/usr/bin/renice priority [-p] pid...[-g gid...][-p pid...][-u user...]
/usr/bin/renice priority -g gid... [-g gid...][-p pid...][-u user...]
/usr/bin/renice priority -uuser [-g gid...][-p pid...][-u user...]
```

## renice

## 描述

> 注意 — `priocntl` 命令包含了 `renice` 的功能。

使用 `renice` 命令修改一个或多个运行进程的调度优先级。默认，通过进程 ID 指定受影响的进程。

如果第一个操作数是优先级范围（−20 到 20）内的数字，`renice` 将其视为优先级（如所有第一个概览形式所示）；否则，`renice` 将其视为 ID（如第一个第一个概览形式所示）。

## 修改进程优先级

超级用户的用户只能修改其拥有的进程的优先级，并可以在 0 到 19 的范围内单调地增加其 nice 值。此限制防止了行政性操作。超级用户可以修改任何进程的优先级，并将优先级设置为 −20 到 19 范围内的任何值。有用的优先级是：

- 19—运行
- 0—默认
- -20—最高优先级
