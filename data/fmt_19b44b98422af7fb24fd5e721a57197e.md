
Bourne shell 是由 Steve Bourne 在 AT&T 贝尔实验室期间编写的，是原始的 UNIX shell。由于其编程能力和通用性，该 shell 优用于 shell 编程。它缺乏用于交互使用的特性，例如内置算术。

Bourne shell 是 `root` 账户的默认登录 shell，如果你在密码文件中没有指定其他 shell，它将默认的用户登录 shell。Bourne shell 用于所有系统级管理脚本。Bourne shell 命令为 `/bin/sh`。默认提示符是美元符号 (`$`)。`root` 提示符是井号符号 (`#`)。

`/usr/bin/sh` 命令是一种执行从终端或文件读取的命令的命令编程语言。

`/usr/xpg4/bin/sh` 命令与 `/usr/bin/ksh` 相同。参见 `ksh` 命令，它是 shell 的一种接口，提供了 `sh` 的所有功能，并支持作业控制（参见第 1229 页的“作业控制”）。

# 定义

空白是制表符或空格。名称是 ASCII 字母、数字和下划线的序列，以字母或下划线开头。参数是一个名称、数字或字符 `*`, `@`, `#`, `?`, `-`, `$`, 和 `!` 中的任何一个。

# 命令

一个简单命令是一个由空白分隔的非空白单词序列。第一个单词指定要执行的命令名称。除下文指定外，其余单词将作为参数传递给被调用的命令。命令名称作为参数 0 传递（参见 `exec(2)`）。命令的值在它正常终止时为其退出状态，如果它异常终止，则为（八进制） `200+status`；状态值列表参见 `signal(5)`。

# 参数替换

`$` 字符用于引入可替换的参数。shell 有两种类型的参数：位置参数和关键字参数。如果参数是一个数字，则它是一个位置参数。位置参数可以通过 `set` 命令进行赋值。你可以通过编写以下内容为关键字参数（也称为变量）赋值：

```
name= value [name= value] ...
```

对值（`value`）不进行模式匹配。你不能使用同名的函数和变量。

```
$(parameter)
```

替换参数的值（如果有的话）。当参数后面紧跟一个字母、数字或下划线，且该字符不被解释为名称的一部分时，则需要大括号。如果参数是 `*` 或 `&*`，则替换所有从 `$1` 开始并用空格分隔的位置参数。当 shell 被调用时，参数 `$0` 被设置为 0。

```
$(parameter:- word)
```

如果参数已设置且非空，则替换其值；否则替换为 `word`。

```
$(parameter:= word)
```

如果参数未设置或设置为空值，则将其设置为 `word`；否则替换参数的值。你不能通过这种方式为位置参数赋值。

```
$(parameter?: word)
```

如果参数已设置且非空，则替换其值；打印 `word` 并退出 shell。如果你省略了 `word`，则打印消息 `parameter null or not set`。

```
$(parameter:+ word)
```

如果参数已设置且非空，则替换为 `word`；否则替换为空。在上述情况中，除非 `word` 被用作替换字符串，否则不会会被求值。因此，在下面的示例中，如果 `c` 未设置或为空，则执行 `pwd`：

```
echo $(d:-`pwd`)
```

如果你从上述表达式中省略冒号 (`:`)，shell 将检查参数是否已设置。

以下参数由 shell 自动设置：

- 十进制格式的位置参数数量。
- 调用 shell 时提供或通过 `set` 命令提供的选项。

以下参数由 shell 使用。本节中的参数也称为环境变量。

- `HOME` `cd` 命令的默认参数（主目录），由登录时通过 `login(1)` 从密码文件中设置，为用户的登录目录（见 `passwd(4)`）。
- `PATH` 命令的搜索路径（见第 1222 页的“执行”部分）。
- `CDPATH` `cd` 命令的搜索路径。
- `MAIL` 如果此参数设置为邮件文件名，且 `MAILPATH` 参数未设置，shell 将通知你指定文件中有邮件到达。
- `MAILCHECK` 指定 shell 每隔多久（以秒为单位）检查一次由 `MAILPATH` 或 `MAIL` 参数指定的文件是否有邮件到达。默认值为 600 秒（10 分钟）。如果设置为 0，shell 将在每次显示提示符前进行检查。
- `MAILPATH` 一个用冒号分隔的文件名列表。shell 将通知你任何指定文件中是否有邮件到达。每个文件名后面可以跟一个 `%` 和消息，当修改时间更改时打印该消息。默认消息为：`you have mail`。
- `PS1` 主提示符字符串；默认值为 `.`。
- `PS2` 次要提示符字符串；默认值为 `>`。
- `IFS` 内部字段分隔符，通常为空格、Tab 和换行符（见第 1218 页的“空白符解释”）。
- `SHACCT` 如果此参数设置为用户可写的文件名，则每执行一个 shell 就会在该文件中写入一条计数记录。
- `SHELL` 当 shell 被调用时，它会扫描环境查找此名称（见第 1221 页的“环境”）。

请参 `environ(5)` 关于影响 `sh` 执行的以下环境变量的描述：`LC_TYPE` 和 `LC_MESSAGES`。

shell 为 `PATH`、`PS1`、`PS2`、`MAILCHECK` 和 `IFS` 提供默认值。`HOME` 和 `MAIL` 由 `login(1)` 设置。

# 空白符解释

在参数替换和命令替换之后，替换的结果将被扫描内部字段分隔符字符（在 `IFS` 中找到的字符），并在发现此类字符的地方将结果拆分为不同的参数。保留显式空参数（`""` 或 `'''`）。隐式空参数（即由无值的参数产生）将被移除。

# 输入/输出重定向

你可以使用 shell 解析的特殊符号来重定向命令的输入和输出。以下结构可以出现在命令的任何位置，或者位于命令之前，且不会作为参数传递给调用的命令。

注意 —— 参数和命令替换发生在单词或数字使用之前。

- `< word` 使用文件 `word` 作为标准输入（文件描述符 0）。
- `> word` 使用文件 `word` 作为标准输出（文件描述符 1）。如果文件不存在，则创建；否则将其截断为长度 0。
- `>> word` 使用文件作为标准输出。如果文件存在，则将输出追加到文件中（首先寻道到末尾）；否则创建文件。
- `< > word` 以读写模式打开文件作为标准输入。
- `<<[-] word` 在对 `word` 完成参数和命令替换后，读取 shell 输入直到遇到第一个字面匹配结果 `word` 的行，或直到文件结束符。然而，如果在后面追加了 `-`：

    - 在读取 shell 输入之前删除 `word` 中的制表符（但在对 `word` 完成参数和命令替换之后）。
    - 在读取 shell 输入之前删除 `word` 前导制表符。
    - 读取 shell 输入直到遇到第一个字面匹配结果 `word` 的行，或直到文件结束符。
    - 执行参数和命令替换。
    - 删除换行符。
- `< digit` 使用 `digit` 指定的文件作为标准输入。标准输出同样使用 `>&digit`。
- `<-` 关闭标准输入。标准输出同样使用 `>&-`。

如果上述任何内容前面有一个数字，则文件描述符由该数字指定（而不是 0 或 1）。例如，以下语句将文件描述符 2 与当前 1 关联的文件关联。

```
... 2>&1
```

# 1218 ... 2>&1 指定重定向的顺序至关重要。shell 从左到右评估重定向。例如，以下语句首先将文件描述符 1 与文件关联。

```
... 1> xxx 2>&1
```

如果重定向顺序反过来，文件描述符 2 将与终端关联（假设文件描述符 1 已经关联），文件描述符 1 将与文件关联。

使用第 1214 页“命令”介绍的术语，如果一个命令由多个简单命令组成，重定向会在评估每个简单命令之前对整个命令进行评估。也就是说，shell 先评估整个列表的重定向，然后是列表中的每个管道，然后是管道中的每个列表，最后是每个命令中的列表。

如果命令后面跟着 `&`，命令的默认标准输入为空文件 `/dev/null/`。否则，执行命令的环境将包含经输入/输出规范修改的调用 shell 文件描述符。

# 文件名生成

在执行命令之前，会对每个命令单词扫描字符 `*`、`?` 和 `[`。如果发现了这些字符之一，则该单词被视为模式。该单词将被替换为按字母排序的匹配模式的文件名。如果没有匹配匹配，则单词保持不变。文件名开头或紧跟在 `/` 之后的字符 `.` 以及 `/` 字符必须显式匹配。

- `*` 匹配任何字符串，包括空字符串。
- `?` 匹配单个字符。
