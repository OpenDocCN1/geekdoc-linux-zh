
然而，依赖目标不一定是目标的组件。例如，依赖目标可能是构建目标之前需要执行的操作，例如在重建目标之前对当前目标进行备份。

*库目标 (Library targets)* 是一种特殊的目标。库目标支持一种特殊语法（有关使用 UNIX 库的详情请查看 `ar` 的 `man` 页，或查看您的 UNIX 系统是否拥有 `ar`）。库目标允许对库中的单个模块进行定位。如果目标或依赖项包含括号 `()`，则该目标或依赖项被视为库。

```makefile
libfoo.a(foo.o): foo.cc foo.hh #库 libfoo.a 中的对象文件 foo.o 依赖于 foo.hh 和 foo.cc
libfoo.a: libfoo(foo.o) libfoo(bar.o) #libfoo.a 依赖两个对象文件 foo.o 和 bar.o
```

某些 `make` 变体允许在括号内列出多个对象文件（见下面的代码）。然而，某些 `make` 变体仅允许在括号内列出一个对象文件。

```makefile
libfoo.a: libfoo.a(foo.o bar.o) #libfoo.a 依赖两个对象文件 foo.o 和 bar.o
```

在括号之间不要使用任何空格，除非你可以在库内指定多个对象文件——在这种情况下，空格只能出现在对象文件之间。

有时你希望在库目标的不同依赖之间使用不同的编译选项。然而，`make` 仅允许使用单冒号定义一次目标。双冒号允许你使用不同的依赖项列表多次定义目标。假设有一个特别棘手的模块 `buggy.o`，它需要带上调试信息进行编译，而更稳定的对象文件则不需要调试信息。目标目标行：

```makefile
libfoo.a:: libfoo.a(foo.o bar.o) #目标列表一
libfoo.a:: libfoo.a(buggy.o) #目标列表二
```

将允许在不包含调试信息的情况下构建 `foo.o` 和 `bar.o`（通常对大多数 UNIX C/C++ 编译器使用 `-g`），并在包含调试信息的情况下构建 `buggy.o`。

## 规则目标 (Rule Targets)

`make` 工具强大的功能之一是它可以指定通用目标，这也称为*后缀规则 (suffix rules)*、*推导规则 (inference rules)* 或简单称为*规则 (rules)*。规则是一种方便的方法，只需一次告诉 `make` 如何构建某些类型的目标。考虑以下 Makefile 片段：

```makefile
foo.o: foo.cc
 CC -c foo.cc -I. -I/usr/local/include -DDEBUG -g #shell命令行
bar.o: bar.cc
 CC -c bar.cc -I. -I/usr/local/include -DDEBUG -g #shell命令行
main.o: main.cc
 CC -c main.cc -I. -I/usr/local/include -DDEBUG -g #shell命令行
main: foo.o bar.o main.o
 CC foo.o bar.o main.o
```

这包含大量的冗余。除了正在编译的文件外，所有的 shell 命令行都是相同的。这是规则的绝佳候选对象。下面的规则告诉 `make` 如何将以 `.cc` 结尾的文件转换为以 `.o` 结尾的文件。

```makefile
.cc.o:
 CC -c $< -I. -I/usr/local/include -DDEBUG -g
```

前面的规则使用了一个特殊的宏 `$<`，它会替换规则体中的当前源文件（更多信息请参见“特殊内置宏”部分）。将 `.cc.o` 规则应用到之前的 Makefile 将 Makefile 简化为：

```makefile
.cc.o:
 CC -c $< -I. -I/usr/local/include -DDEBUG -g
main: foo.o bar.o main.o
 CC foo.o bar.o main.o
```

`make` 提供了许多默认推导规则。它能够通过应用以下算法确定应用哪条规则：

搜索规则列表（包括默认和用户提供的规则），寻找可以构建所需文件类型的规则。文件类型由文件扩展名决定。文件扩展是点 (`.`) 之后的字符集。如果存在指定类型的文件，则应用该规则。例如，如果一个 Makefile 按以下顺序仅指定了两个规则 `.c.o` 规则和 `.cc.o`，并要求 `make` 创建 `foo.o`，将发生以下事件：

1. `make` 首先尝试应用 `.c.o` 规则。目标 `foo.o` 的根节点 `foo`（根节点是去掉了第一个扩展名 `.o` 的文件名）被用于应用 `.c.o` 规则。
2. `.c.o` 规则告诉 `make` 为了生成名为 `*root*`.o 的文件，可以使用名为 `*root*`.c 的文件。
3. 如果当前目录下存在 `*root*`.c 文件，则对 `*root*`.c 应用该规则。在示例中，将检查当前目录下是否存在 `foo.c`。
4. 如果 `foo.c` 不存在，则检查 `foo.cc` 是否存在。
5. 如果 `foo.cc` 不存在，则报告无法生成目标的错误。

`make` 可以将规则链在一起以达到目标（某些版本的 `make` 不执行规则链）。例如，假设你正在处理 CORBA IDL。IDL 编译器接受接口定义作为输入并生成 C++ 源码作为输出。例如，如果你要求 `make` 创建 `foo.o`，给出一个具有 `.idl.cc` 和 `.cc.o` 规则的 Makefile，操作如下：

1. 如果 `foo.cc` 不存在，`make` 然后查找 `foo.idl` 来创建 `foo.cc` 文件。
2. `foo.cc` 文件创建后，应用 `.cc.o` 规则达到最终目标 `foo.o`。

这种规则链是 `make` 的一个非常强大的功能。

## 双后缀规则 (Double Suffix Rules)

为止定义的规则被称为双后缀规则，因为它们包含了双后缀，例如 `.rtf.html`。`.rtf.html` 规则可用于将富文本 (Rich Text Format) 文件转换为 HTML。双后缀规则描述了如何将 `*root.suffix1*` 转换为 `*root.suffix2*`（例如从 `index.rtf` 到 `index.html`）。以下是 `make` 提供的常用双后缀规则列表：

`.c.o .c~o .c.a .c~a .C.o .C~o .C.a .C~a .cc.o .cc~o .cc.a .cc~a .h.o .h~h .H.o .H~H .s.o .s~o .s.a .s~a .p.o .p~o .p.a .p~a .f.o .f~o .f.a .f~a .r.o .r~o .r.a .r~a .y.o .y~o .y.c .y~c .l.o .l~o`

你可以重新定义 `make` 提供的任何默认规则。默认规则利用标准宏来使规则通用化。例如，编译 C 或 C++ 文件的方式除了提供给编译器的标志外并没有太大变化。这些宏中最常用 `LDFLAGS`、`CFLAGS` 和 `CXXFLAGS`，分别用于链接器 (`ld`)、C 编译器 (`cc`) 和 C++ 编译器（HP-UX 上为 `CC`）。`LIBS` 宏通常常用但未纳入默认规则中。`LIBS` 宏用于定义链接时除系统库以外的库以及评估顺序。

双后缀规则中的波浪号 (`~`) 指的是 SCCS (Source Control System) 文件。SCCS 文件带有一个前缀，这与 `make` 直接冲突，因为 `make` 的所有算法基于后缀。例如，文件 `foo.cc` 使用 SCCS 会变成 `s.foo.cc`。波浪号信号 `make` 将文件视为 SCCS 文件，因此可以使用 `.cc~.o` 通过命令 `make foo.o` 将 `s.foo.cc` 转换为 `foo.o`，这优于命令 `make s.foo.o && mv s.foo.o foo.o`。

## 单后缀规则 (Single Suffix Rules)

单后缀规则描述了如何将 `*root.suffix1*` 转换为 `*root*`（例如从 `cat.c` 到 `cat`）。第二个后缀在单后缀规则中无效。单后缀规则对于创建由单个源文件组成的程序有用。事实上，如果你定义了环境变量 `CFLAGS` 和 `LDFLAGS`，你不需要 Makefile 就可以有效使用 `.c` 规则，因为它是默认规则的一部分。假设兼容 Bourne 的 shell 源文件 `cat.c`、`echo.c`、`cmp.c` 和 `chown.c` 在当前目录下，以下命令可以在没有 Makefile 的情况下构建 `cat`、`echo`、`cmp` 和 `chown` 目标：

```text
% export CFLAGS="-I. -DDEBUG -g" LDFLAGS="-lfoo -lbar"
% make cat echo cmp chown
```

以下是 `make` 提供的常用单后缀规则列表：

`.c .c~ .C .C~ .cc .cc~ .sh .sh~ .p .p~ .f .f~ .r .r~`

## 内置目标 (Built-In Targets)

Make 提供了几个内置目标来修改 `make` 的行为。某些内置目标接受依赖，但这些依赖项实际上是内置目标的参数。例如，`.PRECIOUS` 的参数是文件后缀。表 7.1 列出了内置目标。

**表 7.1. make 的内置目标**

| 目标 | 目标描述 |
| :--- | :--- |
| `.IGNORE` | `.IGNORE` 默认目标使 `make` 忽略从构建目标的命令行返回的非零错误码。`make` 的默认行为是在命令行返回非零状态时停止所有处理并退出。可以使用 `make -i` 命令行选项来实现相同的行为。 |
| `.SILENT` | `.SILENT` 默认目标告诉 `make` 显示它正在执行的任何命令行。默认情况下，`make` 显示任何未以 @ 符号 (`@`) 开头的命令行。可以使用 `make -s` 命令行选项来实现相同的行为。 |
| `.DEFAULT` | 如果没有其他规则可以应用，`make` 执行与 `.DEFAULT` 目标相关的任何命令。其目的与 C/C++ 以及 C shell 语句中的 `default:` 情况类似。 |

`.PRECIOUS`

当 `make` 接收到信号或遇到 shell 命令返回非零代码时，它会删除所有已构建的文件。某些类型的文件即使发生错误，你也不希望 `make` 删除它们。这些“珍贵”的文件是 `.PRECIOUS` 目标的参数。`.PRECIOUS` 目标可以在 Makefile 中出现多次，每次出现都会将文件添加到珍贵文件列表中。`.PRECIOUS` 对于生成源码（如 `lex`、`yacc`、IDL 编译器）或获取源码（如 RCS、SCCS 等）的命令非常有用。

`.SUFFIXES`

`.SUFFIXES` 默认目标为 `make` 提供 `make` 将处理的已知文件类型列表。

空的 `.SUFFIXES` 目标会将后缀列表重置为空状态。`.SUFFIXES` 目标可以在 Makefile 中出现多次，每次出现都会将后缀添加到已知后缀列表中。后缀的顺序非常重要，因为这是规则尝试的顺序。要重新排列顺序，请使用空的 `.SUFFIX` 目标来清除当前的后缀列表，然后随后的 `.SUFFIX` 目标可以指定新的顺序。常见的默认后缀有：`.o .c .c~ .C .C~ .cc .cc~ .y .y~ .l .l~ .s .s~ .sh .sh~ .h .h~ .H .H~ .p .p~ .f .f~ .r .r~`。

## 常用目标

按照惯例，Makefile 中有一些常用的目标。这些常用目标通常不是文件，被称为*伪目标（dummy targets）*。伪目标中最常见单元是 `clean`。`make clean` 命令通常会删除所有构建的文件，这些通常是程序和对象文件。`clobber` 是一个更严重的目标，会删除所有文件和目录。`make clobber` 命令通常用于卸载软件。对于构建和安装软件的 Makefile，`install` 经常是一个目标。`make install` 命令通常创建程序、安装 `man` 页面并将程序复制到其预定位置。另一个常用目标是 `all`。当一个 Makefile 构建多个目标时，`make all` 通常会构建所有目标。

## Shell 命令行

Shell 命令行（更简单地称为命令）定义了用于构建目标的操作。目标行中，分号（`;`）之后的任何文本都被视为命令。目标行之后任何以制表符（tab）开头的后续行也是该目标的命令。注释字符井号（`#`）允许出现在命令定义中。例如下面的 Makefile 片段显示了嵌入命令定义中的注释：

```makefile
foo.html: foo.rtf
 rtftohtml -hx $<
#在文件中放置当前日期，$$$ 在 shell 中展开为 $$
 sed s/\_\__DATE\_\_/"'date'"/ $@ > foo.$$$$ && mv foo.$$$$ $@
```

第一个不是注释或不以制表符开头的行结束与目标相关的命令列表。长命令行可以使用反斜杠（\）换行符在下一行继续。

```makefile
foo.html: foo.rtf
 rtftohtml -hx $<
 sed -e "s/PAGE\_DATE/'date'/" \
 -e "s/PAGE\_TITLE/$(DOCTITLE)/" \
 -e "s/PAGE\_NAME/$(HOMETITLE)/" $@ \
 > foo.$$$$ && mv foo.$$$$ $@
```

命令中嵌入的任何宏都会被求值，并由 `make` 替换为适当的值；结果是 shell 只能看到宏的值。

通常，命令会回显到标准输出，除非命令前有 符号（`@`）。使用 `@` 指令比 `.SILENT` 目标或 `-s` 命令行选项提供了更细粒度的输出控制——这两者都会关闭所有命令输出。在执行 echo 命令时，`@` 指令特别有用。如果没有 `@` 指令，`echo Build complete at 'date'` 命令将产生输出：

```text
echo Build complete at 'date'
Build complete at Mon May 12 02:32:37 MST 1997
```

而使用 `@` 则得到更整洁的输出：

```text
Build complete at Mon May 12 02:32:37 MST 1997
```

注意`@` 指令、`-s` 选项和 `.SILENT` 目标只抑制命令的回显；命令的输出仍然显示。以下 Makefile 片段：

```makefile
target:
#将此命令回显到标准输出
 echo echoed to standard out
#不要将此命令回显到标准输出
 @echo not echoed to standard out
```

对于 `target` 的输出如下：

```text
% make target
echo echoed to standard out
echoed to standard out
not echoed to standard out
```

注释字符可以出现在 shell 命令之后；然而，该注释不是 `make` 的注释。`#` 符号和所有后续文本都会传递给 shell。这种情况的好处是，`#` 符号在几乎任何 shell 中都是注释。

## 宏

宏有以下用途：

1. **宏可以节省大量的打字时间。** 通过在 Makefile 中指定变量，效果是相同的。
2. **宏增加了可维护性**，允许信息存储在一处。
3. **宏通过对可能变化的内容参数化，为 Makefile 引入变量。**
4. **宏提高了 Makefile 的可读性。**

## 宏语法

参见“命令行定义”了解如何在命令行上定义宏。在 Makefile 内部定义宏的基础语法为：

`name = valueList`

`*name* 可以由大写字母（A-Z）、小写字母（a-z）、数字（0-9）和下划线（_）的任何组合组成。宏名约定全大写。取决于你的 `make` 版本，宏名中允许某些标点符号，例如脱字符（`^`）或符号（`@`）。除非特殊要求你将宏命名为 `foo\*@`，否则强烈建议不要这样使用符号；它很少有助于可读性或移植性。

等号（`=`）可以在赋值表达式中自由移动，因为等号周围的空格和制表符会被删除。由于空格的行为，以下赋值都会产生相同的结果，字符串 `VALUE` 被赋值给 `NAME`：

```makefile
NAME=VALUE
NAME = VALUE
NAME= VALUE
NAME =VALUE
```

`*valueList*` 可以包含零、一个或多个项目，如下所示：

```makefile
BLANK =
ONE_VALUE = one
LIST_VALUE = one two three
```

`*valueList*` 可能非常长，可以使用反斜杠（\）换行转义符将定义延续到另一行。如果行延续，`make` 将换行转换为空格，并删除后续所有的空白（空格、制表符和换行符）。因此，Makefile

```makefile
BAR=one\
    \
    space
X:
 echo $(BAR)
```

如果生成目标 `X`，将产生以下输出：

```text
echo one space
one space
```

除了之前提到的空白字符转换外，宏定义中的空白字符会被保留。

宏定义可以使用其他宏。嵌套定义不能递归，否则 `make` 会报错。

```makefile
RECURSIVE = $(BAD) #不要这样做
BAD = $(RECURSIVE) #不要这样做
FIRST_HALF = first
SECOND_HALF = second
NESTED = $(FIRST_HALF) $(SECOND_HALF)
NESTED_AGAIN = zero.$(FIRST_HALF).$(SECOND_HALF)
```

在定义宏时，顺序并不重要。在在先的示例中，宏 `NESTED` 可以在 `FIRST_HALF` 和 `SECOND_HALF` 之前定义。宏在作为任何目标行的依赖项使用之前，必须先定义。如果一个宏被定义了多次，则使用最后一个值。这意味着一个宏不能在 Makefile 的部分具有一个值，而在另一部分具有另一个值。如果需要更改宏的值，则需要递归调用 `make` 并在命令行传递新值，如下例所示：

```makefile
MACRO_NAME=oldValue
target:
 $(MAKE) MACRO_NAME=newValue target
```

通过应用美元符号 (`$`) 运算符以及括号 (`()`) 或大括号 (`{}`) 对宏进行解引用。例如，宏 `MAY` 可以通过 `$(MAY)` 或 `${MAY}` 进行解引用。然而，对于单字符宏，仅需 `$` 即可，因此宏 `Z` 可以通过 `$Z`、`$(Z)` 或 `${Z}` 进行解引用。尽管如此，对于单字符宏，建议使用 `()` 或 `{}`。通常情况下不建议使用单字符作为名称；更具描述性的名称会受到下一个阅读 Makefile 的人的欢迎。

如果宏未定义定义或被赋值为空值，则将用空字符串替换其值。该 Makefile

```makefile
BLANK=
X:; echo foo$(BLANK)$(UNDEFINED)bar
```

为目标 `X` 产生以下输出：

```text
echo foobar
foobar
```

如果你需要在 `make` 中使用美元符号 (`$`)，则需要用另一个美元符号对其进行转义。允许连续多次出现美元符号：

```makefile
#echo 环境变量 $LOGNAME 和进程 id $$
foo:
 echo $$LOGNAME $$$$
```

## 宏替换

`make` 工具支持一种用于宏的简单文本替换函数。语法为 `:oldString=newString`，它紧接附加在宏引用中的宏名之后。例如，如果宏 `OBJS` 定义为：

```makefile
OBJS = fuggles.o perle.o cascade.o saaz.o
```

则可以通过宏引用 `$(OBJS:.o=.cc)` 将 `.o` 扩展替换为 `.cc` 扩展，其评估结果为 `fuggles.cc perle.cc cascade.cc saaz.cc`。宏字符串替换的能力相当有限，但对于维护仅在后缀或末尾字符上有所不同的文件效果良好。

### 特殊内置宏

`make` 工具提供了几个特殊的内置宏，以便允许规则具有通用性。如果规则不是通用的，那么文件名将硬编码到规则中，因此它就不再是真正的规则了，因为每个文件名都需要一条规则。内置宏可以在不加括号的情况下引用。例如，`@` 宏可以被引用为 `$@` 而不是 `$(@)`。取决于 `make` 在评估宏时所处的状态，内置宏可能没有值。某些宏仅在后缀规则评估期间有效，而另一些宏仅在普通规则评估期间有效。表 7.2 列出了这些内置宏。

**表 7.2. `make` 的内置宏。**

| 宏 | 宏描述 |
| :--- | :--- |
| `$@` | 整个当前目标名称的值替换为 `$@`。然而，在库目标的情况下，值是库名，而不是要放入库的存档成员名称。`$@` 可用于目标规则和后缀规则。 |
| `$%` | 当前存档成员的值替换为 `$%`，因此此宏仅在当前目标为库时有效。记住，库目标的格式为 `lib(object.o)` 或 `lib((kernel_entry))`。需要 `$%` 是因为对于库目标，`$@` 评估为库名。`$%` 可用于目标规则和后缀规则。 |
| `$?` | 当前目标的过时的依赖项列表替换为 `$?`。`$?` 可用于目标规则和后缀规则。然而，`$?` 在目标规则中评估为可能的多个名称，但在后缀规则中仅评估为一个名称。 |
| `$<` | 当前源文件替换为 `$<`。当前源文件是根据正在调用的隐式规则相对于当前目标已更新的文件。虽然这听起来非常复杂，但它实际上归结为为了构建目标当前正在操作哪个文件。例如，在 `.cc.o` 规则中，`$<` 将是正在编译的任何 `.cc` 文件。`$<` 仅在后缀规则或 `.DEFAULT` 规则中有效。 |
| `\*` | 当前目标名称的根替换为 `\*`。例如，如果目标是 `foo.o`，则根删除后缀 `.o` 后结果为 `foo`。`\*` 仅在推导规则评估期间有效。 |

上述内置宏可以在末尾附加特殊的修饰符，以返回文件名或目录名部分。使用 `F` 获取文件名，使用 `D` 获取目录名。注意，只有大写的 `F` 和 `D` 起作用。当应用修饰符时，不能使用带括号的快捷方法。例如，如果 `$<` 评估为 `/users/dylan/foo.cc`，`$(<F)` 将返回 `foo.cc`，而 `$(<D)` 将返回 `/users/dylan`。

如果你厌倦了输入 `-f` 命令行选项，可以使用一些 shell 小技巧来缓解这种枯燥工作。你可以编写一个别名或 shell 脚本，来自动为 `make` 提供包含文件选项。

**警告：** 对于各位 C/C++ 程序员来说，在使用 `include` 指令时，请不要在 `include` 指令前放置井号（`#`）（例如，`#include foo.mk`）。否则，`include` 行将会被 `make` 解释为注释，该文件将不会被包含。

注释（`#`）是给 `make` 的一个指令，如果它是行中的第一个非空白字符，则忽略该行。注释也可以出现在其他 `make` 行之后，如下文所示：

```makefile
foo=bar #assignment
target:;echo $(FOO) #target
#this whole line is a comment
```

请注意，所有版本的 `make` 都支持注释指令（comment）。

## 命令行参数

虽然 `make` 有在 Makefile 内部进行配置的方法，但 `make` 命令行选项提供了一种即时配置 `make` 的方便方法。这里显示了 `make` 命令行参数的典型顺序，尽管参数可以任意顺序出现：

## nmake

`nmake` 由 AT&T 开发，专为满足大规模 C 开发的需求而定制。`nmake` 弥补了 `make` 的许多标准缺陷，并有自己的一些新花。`nmake` 是唯一能够存储编译选项以供后续 `make` 运行使用的 `make`。这使得你能够要求 `make` 构建任何未使用特定宏定义或编译器开关构建的文件。`nmake` 的另一个优秀特性是可以在单个 shell 中包含多行 shell 命令，而无需通过使用分号和反斜杠换行符来费力地进行调整。

## make 工具

有多种工具可以增强 `make` 的可用性。以下章节将简要介绍其中一些常用的工具。

### makedepend

`makefile` 旨在记录文件之间的依赖关系以及构建这些文件的规则。`makedepend` 提供了一种通过为源文件生成依赖列表来自动记录文件关系的方法。`makedepend` 会考虑 `#if` 指令以以生成正确的依赖关系。

### mkmf

`mkmf` 是 *make makefile*（生成makefile）的缩写。`mkmf` 会检查当前目录下的所有源代码，搜索源码中的依赖项，然后根据模板生成 `makefile`。

## 使用 troff/nroff 进行基础格式化
*作者：James C. Armstrong 和 David B. Horvath, CCP*

UNIX 最初是由 Ken Thompson 在一台很少使用的 PDP-7 上开发的。第二个版本购买 PDP-11/20 的理由是提供一个文本编辑和格式化系统。该系统的目的是在电话公司（AT&T/贝尔电话）内部开发、维护和跟踪文档及备忘录。

PC 有许多用于文本编辑和格式化的产品，包括 Microsoft Word 和 WordPerfect。这些产品和其他版本也适用于 UNIX 系统，但最常见的是 `nroff` 和 `troff` 文本处理器。`nroff` 代表 "next run-off”（下一次排版），`troff` 代表 "typesetter run-off”（排字机排版），两者都基于 `roff`（排版）。RUNOFF 的原始版本是由 J. E. Saltzer 在 20 世纪 60 年代为 MIT 的 CTSS 操作系统开发的。大多数文本处理器的起源都可以追溯到原始 RUNOFF；它们包括 SCRIPT（用于 IBM 大型）、Scribe（由 Brian Reid 开发）、DSR（数字标准排版）、Donald Knuth 的 Tex，当然还有 UNIX `roff`。

20 世纪 70 年代初，Joe Ossanna 重写了 `roff` 以生成 `nroff`。他增加了灵活性和内部编程语言以帮助文档格式化。`nroff` 得到了增强（并重命名为 `troff`），以支持 Graphics Systems CAT 排字机，支持多种字体、字号以及普通打印机不支持的额外字符。

1979 年，Brian Kernighan 重写了 `troff` 以支持更多的排字机。尽管研究了替代方案，但电话公司的贝尔实验室部分已经在 `troff` 上投入了大量精力，包括宏包和预处理器，这些使得文档准备对用户来说变得更加简单。其中一个宏包被用于格式化 UNIX 手页。

`troff` 和 `nroff` 关系紧密。它们使用相同的命令集来格式化文本。最大的例外是 `nroff` 不支持更改字体和字号的命令；它支持有限的字符集更改。`nroff` 还提供 ASCII 输出，因此你可以在屏幕上看到 `nroff` 命令的结果。虽然第三方产品如果具有图形能力，可以在屏幕上显示 `troff` 命令的结果，但在标准的 UNIX 系统上，查看精确 `troff` 输出的唯一方法是将其发送打印机。（`troff` 在普通终端上只能产生输出的近似。）

本章将向你展示：

- 如何使用 `nroff` 和 `troff` 格式化文档
- 如何显示和打印格式化后的文档
- `nroff` 和 `troff` 中使用的各种嵌入命令（原始指令）
- 如何通过 `nroff`/`troff` 格式化程序输出
- 如何对 `troff` 输出进行后处理以发送到各种设备

## 使用 nroff/troff 进行格式化：概述

许多文字处理器（如 Microsoft Word 和 WordPerfect）是所见即所得（WYSIWYG）处理器。在这些文字处理器中，当你输入和格式化文本时可以看到最终打印效果。`nroff` 和 `troff` 等文本处理器被称为*描述性标记语言*，这意味着你像嵌入其他文本一样嵌入格式化代码。

一些其他文本标记语言有标准通用标记语言（SGML）、超文本标记语言（HTML）、封装脚本（EPS）等。尽管它们的语法可能与 `nroff/troff` 不同，但它们拥有共同的。

使用 `nroff` 和 `troff` 进行格式化的多种构建块可用：

- 原始指令：troff 中的标准命令称为请求（request），其格式为点加小写字母，请求后的文本是参数。你使用原始指令进行各种格式化，如段落缩进、添加段落间距、更改字体和居中。
- 宏：大多数 UNIX 系统提供标准的宏包，让你比使用原始指令更容易格式化文档。宏会自动地执行操作，例如格式化项目列表、标题和缩进段落。四个宏包 `mm`、`ms`、`me` 和 `man` 在第 9 章详细介绍。
- 预处理器：大多数 UNIX 系统提供标准的预处理器。每个预处理器都是一组用于特殊任务的命令。你可以使用 `tbl` 预处理器格式化表格，使用 `eqn` 或 `neq` 格式化公式，使用 `pic` 格式化线条图，使用 `grap` 格式化图表。
- 字符串：你可以定义字符串，就像定义宏一样。例如，如果你正在编写一个尚未确定名称的新产品，你可以为临时名称“Hot New Product”定义一个字符串。当最终确定时，你不需要全局搜索替换“Hot New Product”。你只需要重新定义字符串产生“XYZZY Thingo”。
- 数字寄存器：你使用数字寄存器来跟踪值，例如当前字体和字号、当前缩进和当前列表项目。这些寄存器实际上只是存储位置。有些是只读的，其他的可以操作。你可以定义自己的数字寄存器并在宏中使用。

注意：`troff` 坚持将这些寄存器称为“数字寄存器”，但实际上它们并不包含数字；它们可以——而且经常——包含字母。

**转义序列：** 你可以使用转义序列（反斜杠-字符或反斜杠-左括号-字符-字符）来更改字体和字号，并用于许多其他任务。某些转义序列允许你与受影响的文本内联输入 `troff` 原始命令，而不是让它们单独占一行。你可以在在本章节后续的“内联转义序列”章节以及应用这些序列的其他章节中找到具体的示例。

**特殊字符：** 尽管特殊字符取决于系统，但通常有几个字符在所有系统上都是可用的，例如长破折号、度符号和版权符号。你可以在在本章节后续的“特殊字符”章节以及应用这些字符的其他章节中找到具体的示例。

第 8 至第 11 章将为你介绍 `nroff`/`troff` 系列文本处理工具，但可用的功能远超本书允许描述的范围。你可以为所描述的每个命令找到在线手册（man pages）。你也可以找到专门介绍该主题的书籍和论文；例如 J. F. Ossanna 编写的 *The NROFF/TROFF User's Manual* 和 B. W. Kernighan 编写的 *A TROFF Tutorial* 是 *UNIX Programmer's Manual, Volume 2* 的原始文档。

## 使用 nroff 和 troff 进行基础打印

UNIX 提供了多种打印命令和实用程序。此外，你的系统可能有许多本地命令。请咨询你的同事或系统管理员。如果他们告诉你使用一个名为 `prinnumup` 的 shell 脚本将文件发送到打印机，你也应该使用 `prinnumup`。

由于你有多种打印方式（就像 UNIX 中的许多任务一样），询问系统管理员通常是获取信息的最佳方法。大多数管理员都不介意回答这些问题。只需记下答案，这样你就不会再次询问同一个问题了。

事实是，Unix 版本不同，打印机不同，从文件获取数据并发送打印机的方式也不同（因为网络和连接方式的不同）。新模型和全新的打印机正在不断涌现。

## 显示 nroff 文件

`nroff` 允许你在屏幕上格式化文件，而不是在（或在）为打印机格式化之前进行格式化。如果你有图形终端，`troff` 也执行相同的操作，它还会为普通屏幕生成打印结果的近似值。

要将包含 `nroff`/`troff` 原始命令的文件输出到标准输出设备（屏幕），使用以下命令之一：

```text
nroff filename | pg
nroff filename | more
```

选择通过 `pg` 还是 `more` 取决于你的系统和个人偏好。有时 `more` 只产生单行额外的文本，而不是新的一页内容。你需要使用其中之一来防止文本滚出屏幕。请记住，这些工具的设计目的是为打印机生成完整页面；大多数页面的行数比你的屏幕能显示的要多。

## nroff 输出与 troff 输出的区别

打印的文件看起来不同，取决于是用 `nroff` 还是 `troff` 格式化的。通常，使用 `nroff` 打印的文件具有以下特征：所有值都被视为字符位置（空格）或行间距。垂直空间是完整行间距的倍数。默认每八字符设置一个制表符。某些 `troff` 请求不可用（例如 `.fp`, `.lg`, `.ss`）。斜体字体的文本带有下划线；粗体字体的文本通过重叠加粗。字号和垂直空间请求（`.ps` 和 `.vs`）被忽略。`mm` 宏关闭了右边界对齐。此外，默认左边距与物理页的左边缘对齐。

在打印到屏幕时，某些格式可能不明，因为终端无法处理它。

`troff` 的输出看起来更像排版文档（例如这本书），正如其名称（排版 roff）所暗示的那样。你可以拥有不同大小的字体、字符重叠、比例字体，甚至是斜体。

## 打印 troff 文件

原始 `troff` 版本产生光字机所需的格式的输出。新版本更具设备无关性，并在被大多数打印机接受之前对其输出进行后处理。尽管 UNIX 上的某些实现将此称为 `ditroff` 命令（设备无关的 `troff`），但大多数系统只是用新版本替换了原始的 `troff`。

例如，使用 `troff` 命令在惠尔-惠普 LaserJet 系列打印机（这在办公环境中很常见）上打印你的文件，你需要输入：

```text
troff filename | hplj | lpr -Phpprinter
troff -Thplj filename | hplj | lpr -Phpprinter
```

`hplj` 命令将 `troff` 输出后处理为激光打印机可以处理的格式。`lpr -Phpprinter` 命令将你的输出发送到分配 `hpprinter` 的物理打印机；注意某些安装可能使用 `lp -dhpprinter` 命令。如果你在 `troff` 命令上使用 `-Thplj` 选项，页面将正确格式化并调整可用字体（`nroff`/`troff` 选项和其他后处理器将在本文稍后讨论）。

你还可以使用以下 `lp` 或 `lpr` 命令打印源文件（显示嵌入的 `nroff`/`troff` 命令）：

```text
lpr -Phpprinter filename
lp -dhpprinter filename
```

你需要咨询系统管理员以确定本地命令和打印机名称。

## 打印 nroff 文件

打印 `nroff` 输出与打印 `troff` 输出类似，不同之处不需要后处理。

使用 `nroff` 打印你的文档并将其发送到与前面的 `troff` 示例相同的打印机，你需要输入：

```text
nroff filename | lpr -Phpprinter
nroff -Thplj filename | lpr -Phpprinter
```

如果你在 `troff` 命令上使用 `-Thplj` 选项，页面将正确格式化并调整可用字体。

## 文本填充与调整

当文本看起来对称、具有一个或两个边距并跨越整个页面时，任何文档看起来都最整洁。`nroff` 和 `troff` 的默认设置是“填充”每行，“调整”文本位置，使所有行从左边距开始，且右边距对齐。在最简单的情况下，输入文件不需要任何 `troff` 请求即可格式化文档。列表 8.1 示例了一个基础文件，图 8.1 演示了 `nroff` 产生的输出。

你可以通过两个请求来设置填充文本的能力。第一个 `.fi` 告诉 `troff` 你希望填充文本。此设置是默认值。请求 `.nf` 告诉 `troff` 你不想填充文本，但希望右边界不对齐（左对齐）。该请求适用于文本块不当的情况，例如回信地址或诗歌。列表 8.2 显示了一个信件的示例输入文件，某些地方没有填充，某些地方有填充。图 8.3 显示了输出。

注意，文本块之间是由空行隔开的。在较长的文档中，你可以使用这些空行来分隔段落。另一种分隔文本块的方法是使用 `.br`，它会中断当前行的填充并开始一个新的文本块。你也可以通过在文本开头加空格来实现相同的效果。图 8.4 显示了列表 8.1 的输出，但输出在 *the general welfare* 单词之后包含一个换行。

虽然整齐的边缘是默认设置，但你也可以控制边距。`.ad` 命令控制调整。它可以接受以下内容作为参数：`l` 表示仅调整左边距；`r` 仅调整右边距；`c` 使每行居中；而 `b` 或 `n` 表示调整两边边距。图 8.5 显示了使用 `.ad l`、`.ad r` 和 `.ad c` 对第一个文本示例的影响。`.ad b` 是默认的起始值，并在第一个示例中得到了有效演示。

显然，如果文本没有被填充，调整就没有意义了。你还可以通过 `.na` 关闭右边距调整。调整模式不会改变。

最后一种类型的文本调整是居中。它与 `.ad c` 有些不同，后者在居中文本之前继续填充行，但只有在指定了 `.fi` 时才会这样做。居中请求是 `.ce`，后面可以跟一个数字。该请求使下一行或几行居中，而不填充文本。如果文本已填充，则每个输入行都被视为后面跟了一个换行。未填充的行处理方式与 `.ce` 相同。章节标题是文本居中的例子。列表 8.3 显示了居中命令的源码，输出在图 8.6 中所示。

## 垂直间距

`troff` 包含了三类型的垂直空间控制。基线间距控制连续文本行之间的基本间距。下一种是额外行间距；通过这种类型，你可以定期或按个案对文本进行双倍行距处理或更宽。最后是块垂直空间。

空间测量具有不同的比例。当请求需要某个距离时，你可以使用默认类型或使用指示符修改数字。测量类型包括英寸、厘米、磅（picas）、ems、ens、点（points）、单位和垂直行空间。一磅是英寸的六分之一。一个 em 是字母 *m* 的宽度，取决于 `troff` 使用的字体。一个 en 是半 em。修饰符列在表 8.1。

你通过使用 `.de` 请求定义宏。请求后面应该跟一个一个或两个字符的标签。按照惯例，宏名称通常使用大写字母，尽管这并不是强制性的。宏名称不能与请求名称重复，因此有了大写名的惯例。`troff` 请求随后位于 `.de` 之后，直到出现 `..` 请求。每当调用宏时，这些请求就会被执行。你通过以 `.` 开头加上宏名（中间不留空格）来调用宏。

你还可以设计接受参数的宏。向宏可以传递最多九个参数，并通过 `\\$N` 访问，其中 `N` 是从 `1` 到 `9` 的参数位置。这些参数可以被视为普通变量，并用于宏的任何地方。当你定义宏时，命令的内容会被解释。因此，在读取宏时，字符串、变量和注释的存在会被翻译。为了确保参数在宏被使用之前不被解释，你应该在定义中将参数列为 `\\\\$N`。`\\\\` 被解释为 `\\`。每当你想要在宏被调用时让转义字符被解释时，就可以使用 `\\`。

```text
.PP
我们在这里开始第一个段落的文本。这段文字被缩进并格式化。我们继续写第一个段落的文本，直到我们想要第二个段落。
.PP
我们再次发布该宏，得到了空格和缩进。
```

你可以通过 `.am` 请求在创建宏后对其进行修改。它向第一个参数给出的已存在宏附加 `troff` 请求。对于前面的示例，假设你希望第二个及随后的段落的文本字号为 10 号。你可以通过在第一次调用 `PP` 之后包含以下命令来实现此更改：

```text
.am PP
.ss 10
..
```

你可以用 `.de` 重新定义宏，但 `.am` 请求更快。你还可以使用 `.rn` 来重命名宏。你甚至可以在标准的 `troff` 请求和字符串上使用它。原始名称是第一个参数，新名称是第二个参数。旧名称不会保留。

最后，你可以使用 `.rm` 移除宏、字符串和其他请求。

## 数字寄存器

`troff` 提供了有用的信息；然而，寄存器的真正威力来自于定义自定义寄存器的能力。它们可以用于跟踪标题、段落编号和章节编号。`.nr` 请求初始化并修改指定的寄存器。它接受两个或三个参数：第一个是寄存器名称，第二个是修改值。在首次创建时，寄存器被赋值零。正数加到值上；负数减去。可选的第三个参数设置默认的增量递减值。自动增量可以在转义序列中使用：`\\n+(**` 会加到寄存器 `**`。

## 陷阱与跳转 (Traps and Diversions)

大多数情况下，`troff` 请求会在其在文档中的放置位置执行。然而，你可以通过其他方式执行这些请求；你可以指定在文档的任何给定物理位置执行的宏。这些宏被称为*陷阱 (traps)*，它们可以通过页面位置、跳转 (diversions) 和输入行数来触发。页面陷阱的一个常见用途是在页面上放置页眉或页脚。你可以使用跳转陷阱在正文中创建脚注，或为章节末尾创建引用列表。输入行陷阱计算自请求以来的行数。当宏旨在单行显示时，这些陷阱非常有用。

你可以使用*跳转 (diversions)* 将输出重定向到宏而不是页面。跳转请求通常位于宏中，并且必须设置陷阱来产生跳转输出。你通过使用 `.di` 请求（该调用后后跟跳转宏的名称）来创建跳转。如果没有参数，则跳转结束，输出在页面上继续。你可以使用 `.da` 请求向跳转中添加文本。你还可以通过 `.dt` 后跟位置和跳转宏名称来按页面位置请求跳转。

陷阱通过 `.wh` 请求设置。该请求后紧跟一个位置和一个宏名称。如果之前在该位置设置过宏，则该陷阱将被移除。如果没有传递参数，则该位置的任何陷阱都将被移除。你可以使用 `.ch` 请求后跟宏名称和位置来更改宏陷阱的位置。如果缺少位置，则该宏被移除。输入陷阱通过 `.it` 请求设置，后紧跟位置和宏名称。最后，你可以使用 `.em` 设置尾随宏 (trailing macro)，它设置一个宏在输入结束时运行。跳转和陷阱的使用在第 10 章“编写你的宏”中会有插图说明。

## 局部移动 (Local Motions)

除了 `.sp` 和相关请求外，你可以使用内联技术移动 `troff` 的当前输出位置。这些技术被称为*局部移动*，可以是垂直的或水平的。

你可以使用五种水平移动。两个简单的空间函数是 ` `，这是一个未填充的空间大小的空间（由 `.ss` 定义）。`\0` 请求是一个数字大小的空间。`\|` 产生字符宽度的六分之一，而 `\^` 产生十二十二之一。最后，通过 `\h'N'` 产生通用局部移动。垂直移动的规则也适用于水平移动。

## 覆盖打印、线条与弧

可以使用 `\o` 转义字符对字符进行覆盖打印（overstruck）。最多可以覆盖九个字符，每个字符都出现在转义字符后的字符串中。

你可以在 `troff` 中绘制垂直线和水平线。你可以通过使用转义序列 `\l`、`\L` 和 `\D` 实现。第一个绘制一条长度为转义符后引号中指定的长度的线。你可以在长度后使用一个可选字符，它将用来代替该线。第二个转义字符绘制水平线。`\D` 转义字符是绘图转义字符，它可以绘制线、圆、椭圆和弧。具体格式为第一个字符，后面紧跟一到四个参数：

- 使用两个参数绘制线，该线从当前位置绘制到指定位置。第一个字符参数是 `l`。
- 使用 `c` 绘制一个固定直径的圆。单个参数是直径。
- 使用 `e` 绘制椭圆，两个参数是椭圆的两个直径。
- 使用 `a` 绘制弧。该转义符有四个参数，两对一组。弧从当前位置绘制到第一个参数，假设第二个参数是圆的中心。
- 使用字符 `~` 可以绘制样条（spline）。该转义符可以接受无限数量的点对，从当前位置通过这些点对绘制样条。

由于这些转义字符难以使用，通常会使用 `pic` 预处理器。`pic` 基于一种原始语言生成转义序列。`grap`、`tbl` 和 `eqn`/`neq` 预处理器也生成这些转义序列，分别创建图表、表格和数学方程。预处理器在第 11 章“作者工具”中进行了描述。

## 条件文本

与任何编程语言一样，`troff` 和 `nroff` 都提供了对请求的条件执行。`if` 请求有两种形式：`.if` 后跟一个条件和若干请求；以及一个 if-else 结构，`.ie` 和 `.el`。`.if` 有六种条件格式，还有一种格式用于在 if 之后分组请求：`\{-requests-\}`。

这六种条件格式如下：

```text
.if c
.if !c
.if N
.if !N
.if 'string1'string2'
.if !'string1'string2'
```

在这六种条件格式中，`!` 代表基本形式的否定。在前两种情况下，`c` 代表四个特殊条件标志之一：`o` 表示奇数页，`e` 表示偶数页，`t` 表示 `troff`，`n` 表示 `nroff`。中间两种情况用于数值 `N`。第三种情况用于 `N>0`，第四种情况用于 `N<=0`。在最后两种情况下，将对字符串进行比较：如果它们相同，则第五种为真；如果不相同，第六种为真。

`if` 请求很少包含在普通文档中，但它们是宏编写者的基本工具。宏编写在第 10 章有更深入的探讨。然而，有时你可能会用到条件判断。列表 8.23 中的源码和图 8.29 中的输出展示了一个简单的案例。
