## 14 章：Makefile 规范

本章描述了编写 GNU 程序 Makefile 的规范。使用 `Automify` 将帮助你编写遵循这些规范的 Makefile。

### 14.1 Makefile 的通用规范

每个 Makefile 都应该包含这一行：

```
SHELL = /bin/sh
```

以免在 `SHELL` 变量可能从环境中继承的情况下出错。（在 GNU make 中这不是问题。）

不同的 make 程序具有不兼容的后缀列表，有时这会导致混淆或异常行为。因此，在特定的 Makefile 中显式设置你需要的后缀是一个好主，如下：

```
.SUFFIXES:
.SUFFIXES: .c .o
```

第一行清除后缀列表，第二行引入可能受隐式规则影响的所有后缀。

不要假设 `.` 在命令执行路径中。当你在 make 期间运行包的一部分程序时，请确保如果程序是作为 make 构建的则使用 `./`，如果文件是源代码不变的部分则使用 `$(srcdir)`。如果没有这些前缀之一，将使用当前搜索路径。

`./`（构建目录）和 `$(srcdir)/`（源码目录）之间的区别是重要的，因为用户可以使用 `--srcdir` 选项在独立的目录中构建。如下规则：

```
foo.1: man sedcript
sed -e sedcript foo.man > foo.1
```

当构建目录不是源码目录时将会失败，因为 `foo.man` 和 `sedscript` 在源码目录中。

在 GNU make 中，依赖 `VPATH` 来查找源文件在只有一个依赖文件的情况下是有效的，因为 make 自动变量 `$<` 将代表源文件，无论它在哪里。（许多 make 版本仅在隐式规则中设置 `$<`。）一个 Makefile 目标：

```
foo.o: bar.c
$(CC) -I-$(srcdir) $(CFLAGS) -c bar.c -o foo.o
```

应该写成

```
foo.o: bar.c
$(CC) -I-$(srcdir) $(CFLAGS) -c $< -o $$
```

为了让 `VPATH` 正常工作，当目标有多个依赖项时，显式使用 `$(srcdir)` 是让规则正常运行最简单的方法。例如，上述 `foo.1` 目标的写法如下：

```
foo.1 foo:man sedscript
s -e $(srcdir)/sedscript $(srcdir)/foo.man > $0
```

GNU 分发版通常包含一些不是源文件的文件——例如 Info 以及来自 Autoconf、Automake、Bison 或 Flex 的输出。由于这些文件通常出现在源代码目录中，它们应该始终出现在源代码目录，而不是构建目录中。因此，更新这些文件的 Makefile 规则应该使用源代码目录中的更新文件。

然而，如果一个文件没有出现在分发包中，那么 Makefile 不应将其放入源代码目录，因为在任何情况下，编译程序都不应该以任何方式修改源代码目录。

尝试让 build 和 install 目标（至少，以及它们所有的子目标）在并行执行 make 时能够正常工作。
