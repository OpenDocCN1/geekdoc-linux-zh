## 可用的其他 UNIX Shell

本章展示了使用 Korn shell 脚本的示例。这些是常用的脚本语言（我最熟悉的是 Korn shell）。你可以使用 Bourne、BASH（Bourne Again shell）等其他脚本语言。你可以查看特定 shell 的章节以获取更多信息。每种语言都有其优缺点、功能。技巧是学习一种（或两种）并坚持下去。

## 何时以及为什么要使用其他工具

UNIX 脚本语言有局限性。它们不支持记录或文件锁定。它们不支持高级的文件访问方法（键访问或通过数据库管理器）。它们也是解释型的，必须调用许多其他进程来完成工作。很容易让你的 CGI 脚本出现安全漏洞。

## 总结

本章向你展示了何时以及如何使用脚本（主要是 Korn 和 C shell）进行 CGI-BIN 编程。它涵盖了动态 HTML、向用户发送响应、处理表单以及检索数据。脚本并不是用于 CGI-BIN 的合适工具；请查看本节的其他章节以获取有关 C/C++ 和 Perl 作为 CGI-BIN 语言的更多信息。

# 使用 Perl 开发 CGI

作者：Matt Curtin

在考虑使用 Perl 进行 CGI 时，有一些事情值得注意。（可能，这些只是对你已经学过的内容的提醒。）

Perl 将其环境变量放入哈希表（有时称为“关联数组”）`%ENV` 中。要引用环境变量 `home`，你需要使用 `$ENV{'HOME'}`。

本章的大部分内容将涉及使用名为 `CGI.pm` 的 Perl 模块，或者它某些更针对特定任务的模块。（Perl“模块”类比 C++ 或 Java 的“类”。这些仅仅是软件的组件，为你的程序提供“方法”。“方法”只是面向对象（OO）术语中对函数的另一种称呼。）

这里的许多代码示例只是“片段”，需要被整合到 CGI 程序中才能实际运行。

## 为什么选择 Perl？

为什么不呢？

实际上，使用 Perl 有很多理由。Perl 是一种成熟、可移植且灵活的编程语言。读取、写入和处理文本等任务非常适合在 Perl 中完成。大量的 CGI 编程本质上是文本处理，有时是以相当有创意的方式进行的，这使得 Perl 非常适合 CGI 编程任务。此外，还有大量的免费模块库可以让 CGI 编程任务变得更加简单，并且许多免费的程序供你根据自己的需求进行修改，或学习新技术。让我们详细考虑一下 CGI 程序的一些需求，并将 Perl 与其他语言进行比较。

## CGI 语言的要求

你可以使用几乎任何编程语言来编写 CGI 程序——Shell、Scheme、C、Java，随你所列的。只要它是一门真正的编程语言，你就可以用它编写 CGI。并不是说这样做是个好主意，但你甚至像 BASIC 这样的语言编写 CGI 程序。重点在于，你可以使用的语言和你应该使用的语言之间是有区别的。

你用于 CGI 的语言应该与应用程序匹配，就像任何其他编程任务一样。通常，CGI 程序执行诸如模式匹配、数据库接口和动态生成 HTML 等任务。Perl 是目前最流行的 CGI 编程语言，因为它非常适合这类任务。

在接下来的章节中，我将简要比较 Perl 与其他你可以用于 CGI 编程的编程语言。我这样做完全是从“良好的 CGI 编程语言应具备的需求”这一角度出发的。

## Perl 与 UNIX Shell

UNIX Shell 脚本在各种平台上通常具有良好的可移植性。尽管如此，存在许多权衡，shell 脚本通常比用 Perl、C 或其他在执行前会编译整个程序的语言实现的相同脚本慢得多。你可以使用 `awk` 等工具来处理 shell 执行高级文件操作能力的不足，但即使是 `awk` 也有局限性，这些局限在 CGI 环境中可能是巨大的（例如一次只能打开一个文件）。因此，shell 通常只适用于小型脚本，例如指向 `finger`、`archie` 或其他命令行工具服务的简单 `<ISINDEX>` 网关，在这些情况下，你只想查看结果。即使在这种情况下，如果你想处理结果，或将它们从标准文本转换为 HTML（可能为相关或解释性页面创建合适的文字链接），Perl 会成为一个更好的选择。

## Perl 与 C/C++

某些 CGI 程序员倾向于使用 C，通常是因为这仅仅是他们熟悉的语言。不过，用 C 实现的 CGI 程序面临着许多问题：它们更容易受到字符串处理或内存管理漏洞的影响，这些漏洞甚至可能变成安全漏洞。对于是实现在 C 出现之前用汇编编写的系统（如操作系统）来说，C 是一门很棒的语言，因为它很快，并且允许程序员从一种跨架构类型比汇编更具移植性的高级语言执行非常底层的函数。

然而，用 C 实现的 CGI 程序至少需要为目标平台重新编译。如果你从一种类型的系统跳转到另一种类型，可能还需要重写程序的某些部分。C 强制 CGI 程序员处理其他任务（如内存管理），而这些任务只会阻碍当前任务的完成。此外，它的模式匹配能力远后于 Perl。诚然，你可以添加模式匹配功能，但那是必须编译到你的 CGI 程序中的额外开销，而不是像在 Perl 中那样仅仅是一个内部函数。

我不会用 Perl 实现操作系统（尽管我确定某些人会这样做），我不会用 C 实现 CGI 程序（尽管某些人在这样做）。事事用合适的工具。

## Perl 与 Java

整个世界都陷入了关于 Java 的讨论中。由于这个原因，一些程序员尝试用 Java 处理一切，包括 CGI。这样做有许多优势；然而，这些优势目前似乎被后果所抵消了。Java 的优势包括可移植性和简单性。但记住，数据是通过操作系统的环境传递给 CGI 应用程序的。由于 Java 不支持访问环境变量（因为可移植性问题），CGI 程序可能更难编写。Perl 是目前最流行的 CGI 编程语言，因为它非常适合这类任务。

## Perl 如何处理 CGI

此时，考虑一些 CGI 程序将会很有用。记住，需要在 HTTP Header 中告诉浏览器传而来的数据的内容类型。一旦完成了这一点，数据本身就可以下载，并被浏览器正确解释。在 HTML 的情况下，你需要让 HTTP Header 指明内容类型为 `text/html`，发送两个换行符（标记标头的结束和数据的开始），然后是 HTML。

## 让服务器能够运行

记住，在 CGI 程序运行之前，需要完成以下几点：

- 操作系统必须允许其执行。这需要为 CGI 文件开启“执行”位。这可以通过 `chmod +x` 命令完成。
- 代码的第一行必须指定 Perl 解释器的位置。在所有的示例中，我使用 `/usr/bin/perl`。如果 Perl 安装在系统的其他地方，请修改第一行以正确的路径，或者创建一个符号链接使 `/usr/bin/perl` 指向正确的文件。顺便说，如果你选择这样做，这一行也需要指定 `-T` 和 `-w` 等重要标志。
