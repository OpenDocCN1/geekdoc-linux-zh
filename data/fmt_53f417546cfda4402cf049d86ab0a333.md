
`/usr/bin/niscat` `[-ALHMv]` `[-s sep]` `tablename...`

`usr/bin/niscat` `[-ALMP]` `-o name...`

## 描述

使用 `niscat` 命令显示 NIS+ 表和对象中的信息。在第一个语法中，`niscat` 显示由 `tablename` 指定的 NIS+ 表的内容。在第二个语法中，`niscat` 显示由 `name` 指定的 NIS+ 对象的内部表示。

> 注意 — 表中没有列将用两个相邻的分隔符显示。

## 选项

- `-A` 显示表以及初始表路径中表的数据。
- `-h` 在显示表之前显示标题行。标题由哈希 (`#`) 字符以及每个列名称组成。列名由表分隔符分隔。
- `-L` 如果 `tablename` 或 `name` 是链接类型，跟随链接并显示由链接命名的对象或表。
- `-M` 主服务器。将请求发送到命名数据的主服务器。此选项可以使用最新信息，可能会增加主服务器的负载并增加 NIS+ 服务器不可用或忙更新的可能性。
- `-o` 显示命名 NIS+ 对象的内部表示。如果 `name` 是索引名称 (`nismatch(1)`)，则显示每个匹配的项目对象。使用此选项显示单独列的访问权限和其他属性。
- `-P` 如果初始搜索失败，遵循表的路径。此选项仅在 `name` 使用索引名称和 `-o` 选项时有用。
- `-s` 指定用于分隔列的字符。如果没有指定字符，则使用表的默认分隔符（空格）。

## 示例

下面的示例显示 `hosts` 表的内容。

```
castle$ niscat -h hosts.org_dir

# cname name add comment

client1 client1 129.144.201.100 Joe Smith

unchy crunchy 129.144.201.44 Jane Smith
```

`# niscat 901`

`crunchy softy 129.144.201.44`
`castele%`

在用户访问权限不足的字段中，会返回字符串 `*NP*`。

以下示例了在在标准输出上显示 `passwd.org_dir`。
`castele% niscat passwd.org_dir`

以下示例显示了表 `frodo` 的内容及其连接路径中所有表的内容。
`castele% niscat -A frodo`

以下示例将表组 `groups.org_dir` 中的条目作为 NIS+ 对象显示。请注意，括号受到单引号保护，免受 shell 的解析影响。
`castele% niscat -o '[]groups.org_dir'`

以下示例显示了 `passwd.org_dir` 表的对象。
`castele% niscat -o passwd.org_dir`

上一个示例将 `passwd` 显示为表对象而非 `passwd` 表。表对象包含了列数、列类型、是否可搜索或不可搜索、分隔符、访问权限以及其他默认值信息。

以下示例显示了 `org_dir` 的目录对象，包含了访问权限和副本信息等信息。
`castele% niscat -o org_dir`

- `0` 成功完成。
- `1` 发生错误。

# `nischgrp` — 修改 NIS+ 对象的组所有者

### 概要

```
/usr/bin/nischgrp [-ALfP] group name...
```

## 描述

`nischgrp` 命令用于将按名称指定的 NIS+ 对象或条目的组所有者更改指定的 NIS+ 组。使用索引名称指定条目（见 `mismatch(1)`）。如果组不是完全限定的 NIS+ 组名，将使用目录搜索路径进行解析（见 `nisdefaults(1)`）。
更改对象组所有者的唯一限制是你必须修改该对象的权限。
如果主 NIS+ 服务器未运行，此命令将失败。

> 注意 — NIS+ 服务器在进行更改之前会检查组名称的有效性。

## 选项

- `-A` 修改连接路径中所有表中匹配 `name` 中指定搜索标准的所有条目。此选项蕴含了 `-P` 选项。
- `-f` 强制执行操作，如果不成功则静默失败。
- `-L` 跟踪链接并更改链接对象或组内条目的组所有者，或者更改链接本身的所有者。
- `-P` 跟踪命名表内的连接路径。此选项仅当 `name` 为索引名称或你同时指定了 `-L` 选项且命名对象是指向条目的链接时始才有意义。

# `nischgrp 903`

## 示例

以下示例展示了如何将对象的组所有者更改为不同域的组，以及如何更改本地域的组所有者。

```
castle% nischgrp newgroup.remote.domain. object

caste% nischgrp my-buds object
```

以下示例展示了如何更改密码条目的组所有者，`admins` 是同一域中的 NIS+ 组。

```
castle% nischgrp admins '[uid=99],passwd.org_dir_'
```

这两个示例更改了被链接指向的对象或条目的组所有者，以及了 `hobbies` 表中所有条目的组所有者。

```
castle% -L my-buds linkname

caste% nischgrp my-buds '[], hobbies' '
```

## 环境变量

`NIS_PATH` 如果此变量已设置且 NIS+ 名称不是完全限定的，则搜索每个指定的目录，直到找到对象为止（见 `nisdefaults(1)`）。

## 退出状态

- `0` 成功。
- `1` 失败。

|---|---|
| 可用性 | `SUNwnisu` |

# `nischmod` — 修改 NIS+ 对象的访问权限

### 概要

```
/usr/bin/nischmod [-AflLP] mode name...
```

## 描述

使用 `nischmod` 命令将按名称指定的 NIS+ 对象或条目的访问权限（模式）更改为 `mode`。使用索引名称指定条目（见 `nmatch(1)`）。只有对对象具有修改权限的主体才能更改其模式。

`mode` 具有如下形式：

```
rights [, rights]...
```

`rights` 的形式为：

```
[who] op permission [op permission]...
```

`who` 是以下身份的组合。

- `n` 无人的权限。
- `o` 所有者的权限。
- `g` 组的权限。
- `w` 世界范围的权限。
- `a` 所有或 `owg`。

如果省略了 `who`，默认为 `a`。
`op` 是以下操作符之一。

- `+` 授予权限。
- `-` 撤销权限。
- `=` 设置权限。

`permission` 是以下内容的组合：

- `+` `r` 读取。
- `m` 修改。
- `c` 创建。
- `d` 销毁。

> 注意 — 与 `chmod(1)` 不同，`nischmod` 不接受八进制表示法。

# `nischmod`

# `905`

## 选项

- `-A` 修改连接路径中所有表中匹配 `name` 中指定搜索标准的条目。此选项蕴含了 `-P` 选项。
- `-f` 强制执行操作，如果不成功则静默失败。
- `-L` 跟踪链接并更改链接对象的权限而非链接本身的权限。
- `-P` 跟踪命名表内的连接路径。此选项仅当 `name` 为索引名称或你指定了 `-L` 选项且命名对象是指向条目的链接时有效。

## 示例

以下示例赋予对象读取权限（即所有者、组和所有人）。

```
castle$ nischmod a+r
```

以下示例拒绝组创建和修改权限。

```
castle$ nischmod gn
```

以下示例为对象设置一组复杂的权限。

```
castle$ nischmod o=rm,g=rm,w=r
```

以下示例设置密码表中的条目的权限，以便组所有者可以修改。

```
castle$ nischmod g+m '[uid=5],passwd.org_dir'
```

以下示例更改链接对象的权限。

```
castle$ nischmod -L w+mr
```
