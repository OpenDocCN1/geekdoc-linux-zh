
`DESTDIR` 应该仅支持 `install*` 和 `uninstall*` 目标，因为这些是唯一对其有用的目标。

如果你的安装正常起始于 `/usr/local/bin/foo` 和 `/usr/local/lib/libfoo.a`，那么像示例所示调用的安装将把文件安装到 `/usr/local/bin/foo` 和 `/tmp/stage/usr/local/lib/libfoo.a` 中。

为每个目标提供 `DESTDIR` 变量为分阶段安装（staged installs）提供了这种方法，即安装的文件不会直接放置在原始位置，而是复制到临时目录（`DESTDIR`）。然而，安装的文件将保持其相对目录结构，且嵌入的文件名不会被修改。

你不应该在你的 `Makefile` 中设置 `DESTDIR` 的值；否则，文件将默认安装到它们预期的位置。……可能会以任何方式改变软件的操作，因此其值不应包含在任何文件内容中。

`DESTDIR` 常用于软件包创建。它也有助于用户理解给定软件包将安装什么，并允许通常具有权限安装到受保护区域的用户在安装之前进行构建。最后，它对于像 `stow` 这样的工具非常有用，在这些工具中，代码安装在一个地方，但通过符号链接或特殊挂载显示在另一个地方。我们强烈建议 GNU 软件包支持 `DESTDIR`，尽管这不是绝对性要求。

# 第 15 章：Makefile 约定

## 15.5 安装目录变量

安装目录始终应该通过变量命名，以便于将其安装到非标准位置。这些变量的标准名称以及它们在 GNU 软件包中应具有的值下文所示。它们基于文件系统布局；用于 GNU/Linux 和其他现代操作系统。

预计安装程序会在执行安装时（例如 `configure --prefix=/usr`）覆盖这些值。GNU 软件包不应尝试猜测对于其安装目标系统，哪些值适用于这些变量的；应使用此处指定的默认设置，以确保所有 GNU 软件包的行为一致，允许安装程序实现任何所需的布局。

所有安装目录及其父目录都应在安装它们之前（如果需要）被创建。

前两个变量设置安装的根目录。所有其他安装目录都应该是这两个目录之一的子目录，不应直接安装到这两个目录。

### prefix

用于构建下方列出的变量默认值的前缀。
`prefix` 的默认值应为 `/usr/local`。在构建 GNU 系统时，`prefix` 将为空，且 `/usr` 将指向 `/.` 的符号链接。（如果你正在使用 Autoconf，请将其写为 `@prefix@`）。
使用与构建程序时不同的 `prefix` 值运行 `make install` 不应重新编译程序。

### exec_prefix

用于构建下方列出的部分变量默认值的前缀。
`exec_prefix` 的默认值应为 `$(prefix)`。（如果你正在使用 Autoconf，请将其写为 `@exec_prefix@`）。
通常，`$(exec_prefix)` 用于包含特定于机器的文件（如可执行文件和子程序库）的目录，而 `$(prefix)` 直接用于其他目录。
使用与构建程序时不同的 `exec_prefix` 值运行 `make install` 不应重新编译程序。

可执行程序安装在以下目录之一中。

### bindir

用于安装可以运行的可执行程序的目录。这通常应该是 `/usr/local/bin`，但你应将其写为 `$(exec_prefix)/bin`。（如果你正在使用 Autoconf，请将其写为 `@bindir@`）。

### sbindir

用于安装可以从 shell 运行的可执行程序的目录，但这些程序通常只对系统管理员有用。这通常应该是 `/usr/local/sbin`，但你应将其写为 `$(exec_prefix)/sbin`。（如果你正在使用 Autoconf，请将其写为 `@sbinir@`）。

### libexecdir

用于安装由其他程序而非用户运行的可执行程序的目录。该目录通常应该是 `/usr/local/libexec`，但你应将其写为 `$(exec_prefix)/libexec`。（如果你正在使用 Autoconf，请将其写为 `@libexecdir@`）。

`libexecdir` 的定义对于所有软件包都是相同的，因此你应该将数据安装在子目录中。大多数软件包将数据安装在 `$(libexecdir)/package-name/` 下，可能位于额外的子目录下，例如 `$(libexecdir)/package-name/machine/version`。

程序执行期间使用的数据文件分为两种方式：

- 某些文件由程序修改；另一些可能被正常修改（尽管用户可能需要编辑其中一些）。
- 某些文件是架构无关的，可以由站点的所有机器共享；某些文件是架构相关的，可以由相同类型和操作系统的机器共享；另一些则可能永远不会在两台机器之间共享。

这产生了六种不同的可能性。然而，我们不鼓励使用架构相关的文件（对象文件和库除外）。将其他数据文件制为架构无关的要干净得多，而且通常并不困难。

以下是 Makefile 应使用的变量，用于指定放置各种文件的目录：

### datarootdir

只读架构无关文件树的根。这通常应该是 `/usr/local/share`，但你应将其写为 `$(prefix)/share`。（如果你正在使用 Autoconf，请将其写为 `@datarootdir@`）。

### datadir

安装程序的只读架构无关文件的目录。这通常与 `datarootdir` 是同一个地方，但我们使用这两个变量以便你可以移动特定的文件，如 Info 文件、man 页等。这通常应该是 `/usr/local/share`，但你应将其写为 `$(datarootdir)`。如果你正在使用 Autoconf，请将其写为 `@datadir@`。`datadir` 的定义对于所有软件包都是相同的，因此你应该将数据安装在 `$(datadir)/package-name/` 下。

### sysconfigdir

安装单机相关的只读数据文件的目录，例如用于配置主机的文件。邮件和网络配置文件、`/etc/passwd` 等都属于这里。此目录中的所有文件都应该是普通的文本文件。该目录通常应该是 `/usr/local/etc`，但你应将其写为 `$(prefix)/etc`。如果你正在使用 Autoconf，请将其写为 `@sysconfigdir@`。不要在此目录中安装可执行文件（可能放在 `$(libexecdir)` 或 `$(bindir)` 中）。也不要安装在正常在使用过程中会被修改的文件（用于更改系统配置的程序）。

### sharedstatedir

安装程序在运行时修改的架构无关数据文件的目录。这通常应该是 `/usr/local/com`，但你应将其写为 `$(prefix)/com`。如果你正在使用 Autoconf，请将其写为 `@sharedstatedir@`。

### localstatedir

安装程序在运行时修改的数据文件的目录，且这些文件属于特定机器。用户永远不需要修改此目录中的文件来配置软件包的操作；将此类配置信息放在 `$(datadir)` 或 `sysconfigdir` 中的独立文件中。`$(localstatedir)` 通常应该是 `/usr/local/var`，但你应将其写为 `$(prefix)/var`。如果你正在使用 Autoconf，请将其写为 `@localstatedir@`。

### runstatedir

安装程序在运行时修改的数据文件的目录，这些文件属于特定机器，且不需要持续比程序执行时间更久——而程序通常是长期的，例如，

直到下一次重启。系统守护进程的 PID 文件是一个典型的用法。此外，除非在重启时，否则此目录不应被清理，而通用的 `/tmp` (`TMPDIR`) 则可以任意清理。这通常应该是 `/var/run`，但在编写时应写为 `$(localstatedir)/run`。设置一个独立的变量允许在需要时使用 `/run`，例如。如果你正在使用 Autoconf 2.70 或更高版本，请将其写为 `$runstatedir@`。

这些变量指定了安装某些类型文件的目录（如果你的程序有这些文件的话）。每个 GNU 软件包都应该有一个 `infodir`，但并非所有软件包都应该有 `libdir` 或 `lispdir`。

### `includedir`

用于安装头文件的目录，用户程序可以通过 C 语言的 `#include` 处理器指令包含这些文件。这通常应该是 `/usr/local/include`，但应将其写为 `$(prefix)/include`。（如果你正在使用 Autoconf，请将其写为 `@includedir@`）。

除了 GCC 之外的大多数编译器在 `/usr/local/include` 目录下没有头文件。以这种方式安装头文件仅对 GCC 有用。有时这并不是问题，因为某些库确实是设计为与 GCC 配合工作的。有些库则设计为与其他编译器工作。它们应该在两个地方安装其头文件：一个由 `includedir` 指定，另一个由 `oldincludedir` 指定。

### `oldincludedir`

用于安装供除 GCC 以外编译器使用的 `#include` 头文件的目录。这通常应该是 `/usr/include`。（如果你正在使用 Autoconf，请将其写为 `@oldincludedir@`）。

Makefile 命令应该检查 `oldincludedir` 的值是否为空。如果为空，它们不应尝试使用它；它们应该取消对头文件的第二次安装。

除非头文件来自同一个软件包，否则软件包不应该替换目录中的现有头文件。如果你的 Foo 软件包提供名为 `foo.h` 的头文件，那么在以下情况下：(1) 没有 `foo.h` 或 (2) 存在的 `foo.h` 来自 Foo 软件包，它应该将该头文件安装在 `oldincludedir` 目录中。

要判断 `foo.h` 是否来自 Foo 软件包，请在注释部分使用魔术字符串——并对该字符串进行 `grep`。

### `docdir`

安装此软件包文档文件（Info 之外）的目录。默认情况下，它应该是 `/usr/local/share/doc/yourpkg`，但应写为 `$(datarootdir)/yourpkg`。（如果你正在使用 Autoconf，请将其写为 `@docdir@`）。`yourpkg` 子目录（可能包含版本号）可以防止常用文件名（如 `README`）之间的文件冲突。

### `infodir`

安装此软件包 Info 文件的目录。默认情况下，它应该是 `/usr/local/share/info`，但应写为 `$(datarootdir)/info`。（如果你正在使用 Autoconf，请将其写为 `@infodir@`）。为了兼容现有习惯，`infodir` 与 `docdir` 是分开的。

### `htmldir`, `didir`, `psdir`

分别用于以特定格式安装文档文件的目录。它们默认都应设置为 `$(docdir)`。（如果你正在使用 Autoconf，请将它们写为 `'$(htmldir,didir, etc.)'`）。提供文档多种翻译版本的软件包应将它们安装在 `'$(htmldir)/ll, $(pdfdir)/ll` 中，其中 ll 是语言缩写，例如 'en' 或 'pt_BR'。

### `libdir`

对象文件和对象代码库的目录。不要在此安装可执行文件，它们可能进入 `'$(libexecdir)'`。`libdir` 的值通常应该是 '/usr/local/lib'，但应写为 `'$(exec_prefix)/lib'。（如果你正在使用 Autoconf，请将其写为 `'$(libdir)`）。

### `lispidir`

安装 Emacs Lisp 文件的目录。默认情况下，它应该是 `/usr/local/share/lisp`，但应写为 `$(datarootdir)/lisp`。（如果你正在使用 Autoconf，请将其写为 `@lispidir@`）。为了兼容现有习惯，`lispidir` 是独立的。

### `localedir`

安装特定特定语言目录文件的目录。默认情况下，它应该是 `/usr/local/share/locale`，但应写为 `$(datarootdir)/locale`。（如果你正在使用 Autoconf，请将其写为 `@localedir@`）。

### `mandir`

安装帮助页的目录。默认情况下，它应该是 `/usr/local/share/man`，但应写为 `$(datarootdir)/man`。（如果你正在使用 Autoconf，请将其写为 `@mandir@`）。

### `man1dir`

安装 1 节帮助页的目录。它应写为 `$(mandir)/1`。

### `man2dir`

安装 2 节帮助页的目录。它应写为 `$(mandir)/2`。

### `manext`

安装帮助页的文件名。这应该是点加一个数字，例如 `.1`。

### `man1ext`

1 节帮助页的扩展名。

### `man2ext`

2 节帮助页的扩展名。

### `srcdir`

正在编译的源码目录。该变量的值通常由 configure 脚本插入。（如果你正在使用 Autoconf，请使用 'srcdir = @srcdir@')

例如：

```
# 安装目录的通用前缀。

# 注意：在开始安装时，此目录必须存在。

prefix = /usr/local

sharedir = $(prefix)/share

datadir = $(datadir)

exec_prefix = $(prefix)

# 放置执行文件的目录。

bindir = $(prefix)/bin

# 编译器使用的目录。

libexec = $(exec_prefix)/libexec

# 放置 info 文件的目录。

infdir = $(datadir)/info
```

如果你的程序处理大量文件，将它们分组到特定程序的子目录可能是可能是用的。如果这样做，请使用 install 规则创建这些子目录。

不要期望用户在上述任何变量的值中包含子目录名称。拥有一组统一变量名的目的是让用户为不同的 GNU 软件包指定相同的值。为了使这一点有效，所有的软件包都应该设计为在这样做时能够良好工作。

有时，Autoconf 和/或 Automake 的当前版本可能没有实现所有这些变量；使用 Autoconf 2.60，我们认为它们都实现了。当它们缺失时，描述充当了 Autoconf 将实现的规范。作为程序员，你可以使用 Autoconf 的开发版本，或者在稳定版本支持它们之前避免使用这些变量。

## 15.6 用户的标准目标

所有 GNU 软件包的 Makefile 都应该包含以下目标：

- `'all'` 编译整个程序。这应该是默认目标。此目标不需要重新构建任何文档文件；info 文件通常包含在发行版中，DVI（其他文档格式）文件仅在明确要求时制作。
- 默认情况下，Make 规则应该复制并链接带有调试符号的程序。否则，在面对崩溃时它们将无从下手，而且使用新文件重现困难。
- `'install'` 编译程序并将可执行文件、库等复制到它们实际应该所在的文件位置。如果有可以验证程序是否正确安装的测试，此目标应该运行该测试。安装时不要剥离可执行文件。这有助于以后可能需要的调试，而且现在空间很廉，且动态加载器通常确保在正常执行期间不加载调试段。

如果可能，请编写 `install` 目标规则，使其在刚刚执行过 `make all` 的情况下，不会修改程序构建所在目录中的任何内容。这对于在一个用户名下构建程序并在另一个用户名下安装它非常方便。

如果不存在，这些命令应该创建所有要安装文件的目录。这包括作为变量 `prefix` 和 `exec_prefix` 值所指定的目录，以及所有需要的子目录。实现此点的一种方法是使用下文描述的 `installdirs` 目标。

在安装任何 man 页（帮助页）的命令之前使用 `'--'`，这样 `make` 将忽略任何错误。这是为了防止某些系统没有安装 Unix man 文档。

安装 Info 文件的方法是使用 `$(INSTALL,DATA)` 将它们拷贝到 `$(infdir)` 中，然后如果存在 `install-info` 程序，则运行它。`install-info` 是一个用于编辑 Info 目录以添加或更新新文件菜单条目的程序；它是是 Texinfo 软件包的一部分。

这里是一个安装 Info 文件的示例，它还尝试处理一些额外情况，例如 `install-info` 不存在。

```
do-install-foo: foo.info installdirs

$(NORMAL_INSTALL)

# 优先使用一个子目录中的 info 文件。

  if test -f $$foo.info; then d=$$foo; \

    else d=$$scndir; fi

  $(INSTALL,DATA) $$d/foo.info "$(DESTDIR)$(infdir)/foo.info"

# 仅在存在时运行 install-info。

  使用 'if' 而不是直接在行开头添加 '-'，

   这样我们就不会忽略 install-info 的错误。

  使用 '$(SHELL) -c' 是因为 shell 不

  # 在出现未知命令时优雅地失败。

  $(POST_INSTALL)

  if \$(SHELL) -c 'install-info --version' \

    >/dev/null 2>&1; then \

    install-info --dir="$(DESTDIR)$(infdir)" \

    "$(DESTDIR)$(infdir)/foo.info"; fi
```

安装目标时，你必须将所有命令分为三类：普通命令、`pre-installation`（安装前）命令和 `post-installation`（安装后）命令。参见第 15.7 节 [Install Command Categories]，第 162 页。

```
install-html-
install-dvi-
install-pdf-
install-ps-
```
