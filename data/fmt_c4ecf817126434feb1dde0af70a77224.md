
# 从 Unix 向 Windows 发送弹出消息

## 命令行参数解析

```bash
while getopts "m:H:n:N:g:" arg
do
    case $OPTARG in
        m|M)
            echo "\nEnter一个或多个发送此消息的节点:"
            echo "\n完成后按回车 \n\n"
            echo "\n节点列表 == \c"
            read WINLIST
            ;;
        h|H|n|N)
            WINLIST=$OPTARG
            ;;
        g|G)
            GROUP=$OPTARG
            ;;
        \?)
            echo "\nERROR: 无效的增强参数!"
            usage
            exit 1
            ;;
    esac
done
```

**Listing 25.2** 使用 getopts 解析命令行开关。

### getopts 语句详解

在 getopts 语句中，我们定义了有效的开关，以及哪些开关需要参数，哪些开关是不带参数的开关。

```bash
getopts "*mh:H:n:N:g:G:" ARGUMENT
```

在这个 getopts 语句中，开关定义列表 `*:mh:H:n:N:g:G:` 以冒号（:）开头。这个第一个冒号有特殊含义。如果遇到未定义的开关（必须以连字符 - 开头），未定义的开关会导致问号 (?) 被赋值给 `ARGUMENT` 变量（你可以在这里使用任何变量名）。这就是查找命令行上输入的开关的机制。

在 getopts 语句中，`-m` 和 `-M` 开关不需要参数，而 `-h`、`-H`、`-n`、`-g` 和 `-G` 开关需要参数。开关是否需要参数取决于定义语句中冒号（:）的位置。如果定义语句中开关后面跟一个冒号（:），则该开关需要一个参数；如果开关定义后没有冒号，则它不需要参数。

在循环内部，我们有一个嵌入的 `case` 语句。在 `case` 语句中，我们对作为开关的命令行参数进行处理。记住，`getopts` 不在乎命令行上有什么，除非它带有连字符（-）。这就是为什么我们需要验证命令行上提供的参数。

在 Listing 25.2 的 `case` 语句中，当我们遇到开关时会采取操作或进行赋值。当遇到 `-M` 或 `-m` 开关时，会提示用户输入一个或多个节点列表以发送消息。当发现 `-h`、`-H`、`-n` 或 `-N` 开关时，我们将 `$OPTARG` 变量赋值给 `WINLIST`，这是一个目标用户/节点的列表。当使用 `getopts -g` 或 `-G` 时，我们将 `$OPTARG` 变量赋值给 `GROUP` 变量。当发现未定义的开关时，问号 (?) 被赋值给 `ARGUMENT` 变量。在这种情况下，我们给用户返回一条错误消息，显示用法函数，并以返回码 1 退出 shell。

## 添加单独指定目的地的能力

到目前为止的代码限制在我们创建的文件列表上。现在让我们添加用户在命令行上指定更多目的地的能力，或者通过提示用户指定。这两种选项需要命令行开关：

- `-M`、`-m`：提示用户输入消息目的地。
- `-H`、`-h`、`-N`、`-n`：期望作为开关参数的目的。

每个开关在这里的作用都相同。第一个开关 `-M` 和 `-m` 是消息开关。该开关没有开关参数，而是提示用户输入一个或多个节点/用户。第二组开关执行相同的任务，并且需要开关参数，即节点用户列表。有些人认为这些目标机器是主机，所以我添加了 `-h` 和 `-H` 开关。另一些人将目标机器视为节点，所以我添加了 `-n` 和 `-N` 开关。两组用户都可以随自己的意愿。

## 在变量中使用 eval 函数

让我们暂时回到 Listing 25.2 中的 `GROUP` 变量。记住，分配给 `GROUPLIST` 变量的组名必须分配一个文件名，该文件包含目标机器的列表。如果你思考这一点，应该注意到我们必须处理一个指向另一个变量的变量，而该变量又指向一个文件名。文件包含目标机器列表。我们如何直接指向文件名？这就是 `eval` 函数的工作。`eval` 函数是 Shell 内置函数，我们用它来解决困境。

`eval` 函数在我们的代码中工作方式如下：`GROUP` 变量是用户在命令行上作为 `-G` 或 `-g` 开关参数的一个或多个组。分配给 `GROUP` 变量的每个组都是一个指向文件的指针，该文件保存着目标机器列表。为了直接访问文件名，我们使用 `eval` 函数。看 Listing 25.3 中 `getopts` 循环中使用 `eval` 函数的代码。

**Listing 25.3** 使用 eval 求值双重指向变量。

```bash
# 确保该组已经定义
for G in $GROUPLIST
do
    echo "$GROUPLIST" | grep -q $G || group_error $G
done

# 如果你到达这里，说明所有组都是有效的！
WINLIST=

# 清空 WINLIST 变量

# 遍历 $GROUP 中的每个组
# 并构建一个要发送消息的节点列表。
for GRP in $GROUP
do
    # 使用 "eval" 显示变量指向的内容！
    # 确保每个组都有一个非空列表文件
    if [ -s $(eval echo "$GRP") ]
    then
        WINLIST="$WINLIST $(eval cat "$GRP" | grep -v ^# | awk '{print $1}')"
    else
        group_file_error $(eval echo "$GRP")
    fi
done
```

**Listing 25.3** 使用 eval 求值双重指向变量。（续）

我们首先启动一个 `for` 循环来处理分配给 `GROUP` 变量的每个组，它在每次迭代中分配给 `GRP` 变量。在 `for` 循环内部，我们首先测试该组是否分配了组文件，以及该大小是否大于零。我们使用以下命令执行此操作：

```bash
if [ -s $(eval echo "$GRP") ]
```

注意我们使用 `eval echo "$GRP"` 进行替换。

```bash
WINLIST=$(eval cat "$GRP" | grep -v ^# | awk '{print $1}')
```

在这种情况下，我们使用 `grep -v ^#` 去注释并使用 `awk '{print $1}'` 去重。

```bash
group_file_error $(eval echo "$GRP")
```

如果组文件无效，则调用 `group_file_error` 函数。

## 测试用户输入

我们只需要确保 `WINLIST` 不为空。

```bash
if [ -z "$WINLIST" ]; then
    echo "\nERROR: 无效的增强参数!"
    usage
    exit 1
fi
```
