## 展望未来

HTTP 版本 1.1 被归类为现有应用协议实现的微型升级。RFC 1945 告诉我们，微升级在功能关键领域提供了增强——而没有对应用底层操作的操作发生重大变化。

## 支持持久连接

HTTP/1.1 版本中最重要的新增是支持持久连接。`connection` 这一新头部值允许使用单个 TCP 连接进行客户端和服务器之间的数据传输。

## 总结

HTTP 在互联网中的重要性不容置疑。该应用程序为在 Web 客户端和服务器之间动态移动文件提供了一种简单的解决方案——而不需要像更标准的文件传输程序（如 NFS 和 FTP）那样的开销或用户干预。

HTTP 具有一些主要优势，但也存在一些显著的缺点。HTTP 的运行与许多严重的性能问题相关。在这些问题列表的前列，可能是要求传输每个页面或数据对象时都必须建立一个单独的连接。

使用基于服务器和客户端的文件缓存可以帮助我们实现通信精化的部分。然而，我们仍然需要建立和销毁 TCP 连接，这会消耗有限资源并减慢整体性能。

答案是利用持久连接。这将涉及建立单个 TCP 连接并一直保持它，直到客户端和 Web 服务器之间的所有数据传输完成。通过这种方式，可以利用 TCP 内部的有用性能特性，有助于下载多个 Web 页面。HTTP 1.1 版本尝试通过使用额外的协议标头值来提供这一功能。

最后，随着 HTTP/1.1 预计在 1997 年后期的标准化，现有的厂商互操作问题将有效结束。希望随着 HTTP/1.1 成为互联网标准，能够改进不同厂商解决方案之间的集成。

## 监控 Web 服务器活动

*作者：Mike Starkenburg*

许多人认为服务器活动是 Web 网站成功的真正标志。访问量（hits）越多，你的 Web 网站就越受欢迎，对吧？事实上，这并非完全正确。在接下来的章节中，我将解释服务器日志中的数据如何帮助你构建更好的网站。在本章中，我们将介绍以下内容：

- HTTP 访问日志。
- `referrer` 和 `user_agent` 日志。
- 错误日志。
- 基础和高级日志分析。
- 日志准确性的因素。
- 分析工具。

### 访问日志

监控 Web 服务器活动的主要方法是分析 Web 服务器的访问日志。访问日志记录了对服务器的每个 HTTP 请求，包括 `GET` 和 `POST` 方法请求。访问日志记录了成功和失败，并为每个请求包含一个状态码。某些服务器会记录“扩展”数据，包括浏览器类型和引用站点。这些数据可能在单独的日志中，也存储在主访问日志中。

这些数据通常保存在服务器目录的 `/logs` 子目录下。该文件通常命名为 `access_log`，它可能很大——每 10,000 条条目约占 1MB。具体的目录和名称取决于你的服务器，可以在 `httpd.conf` 文件中进行配置。

这些请求，或者人们常说的 *hits*（访问量），是所有 Web 服务器使用的基本指标。

### 访问日志数据的用途

在许多组织中，日志数据未被充分利用或完全忽略。通常，唯一可以访问日志数据的人（也是唯一可以解释报告的人）是 Web 主站员（Webmaster）。事实上，如果对日志数据进行适当分析和分发，它是整个公司的信息金矿。

### 内容编程

访问日志的一个经典用途是帮助确定 Web 网站上哪些内容最有效。通过查看特定页面的访问频率，你作为内容开发人员可以判断不同内容区域的相对受欢迎程度。

大多数分析程序都提供网站上“前十”和“后十”页面的列表，按总访问量进行排名。通过查看此类报告，Web 内容开发人员可以发现用户认为哪些类型的内容有用或有趣。

Web 网站超过 50% 的访问量可能仅仅来自首页（index page），这对于确定内容的有效性帮助不大。然而，用户*下一步*去向哪里，可能是从访问日志中获取的最有用数据之一。一些分析程序（你将在本章稍后部分探索其中几个）允许你检查用户穿过网站的最常见“路径”。

**注意：** 请注意，出于编程和广告目的，访问日志不能被视为完全准确的来源。在本章稍后的“日志准确性”部分，我们讨论了导致访问日志过高估计和过低估计的因素。

### 扩展性与负载确定

使用访问日志是确定服务器整体负载的快速方法。通过最初对系统进行基准测试，然后定期分析流量的变化，你可以预判增加系统容量的需求。

访问日志中的每次访问都包含该请求的总传输大小（以 KB 为单位）。通过累加每次访问的传输大小，你可以获得每个时间段的聚合带宽。这个数字可以作为随时间总负载的相当良好的指标。

当然，最好的扩展测试会单独跟踪系统指标，如 CPU 使用率、磁盘访问和网络接口容量。（参见 *Unix Unleashed, System Administrator's Edition* 以获得对此类监控的更详细讨论。）然而，分析访问日志是获取负载快速快的简单方法。

### 广告

广告正成为支持网站的主要业务模型之一。广告通常按*数千次展示（impressions）*出售，其中一次*展示（impression）*是对广告图版的一次访问。对这些信息的准确跟踪直接影响收入。

由于 Web 日志并非 100% 准确，依赖广告收入的业务应考虑使用如 NetGravity 或 Accipiter 等广告管理系统。这些系统管理广告库存，可靠地计算展示次数。
