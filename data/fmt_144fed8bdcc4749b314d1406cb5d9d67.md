此文件的每一行都对应一个不同的守护进程。我们实际上只需要考虑第一、六、七和第八列，尽管你可以参考第 5 章“接入网络”中关于 inet 的讨论，或者查阅相关页面以记住其他列的作用。第一列告诉我们 `inetd` 程序应该监听哪个端口12，而第六列告诉我们 `inetd` 需要针对任何端口上的任何新连接启动哪个网络守护进程。第 7 列对于 inet 来说实际上并不存在；它只是第 6 列的扩展。例如，在 finger 端口的情况下，当 `inet` 接收到对 finger 端口（TCP 端口 79）的新连接时，它运行的是：

```
/usr/sbin/tcpd /usr/inetd.fingerd
```

最初，`inet` 只会运行 `/usr/sbin/in.fingerd`。问题在于 `inet` differ 不提供任何审计控制或合理性检查。Wietese 编写了 TCP Wrappers 以及 `tcpd`，以解决这些问题。当 `tcpd` 运行时，它会根据主机名或 IP 地址检查访问控制列表（如果存在），并且会努力确保源 IP 地址没有被伪造域名。如果你去检查它，它它运行在 `inetd` 中。无论如何，它都在启动审计。

要运行审计，请查看每一行未被注释（以 `#` 标记）的行，并决定你是否想要运行该服务。如有必要，你可以在帮助手册页（man pages）、网页或任何关于防火墙的书籍中查询这些每一个服务。

在我们开始审计之前，让我们保存一份此配置文件的副本。这样，如果我们犯了简单的错误，就可以恢复旧的配置文件。保存方法：

```
# cp /etc/inetd.conf /etc/inetd.conf.orig
```

让我们从第一行未注释的行开始：

```
ftp stream tcp nowait /usr/sbin/tcpd in.ftpd -l -a
```

这一行启动了一个在端口 21 上的 FTP 守护进程。这是我们在错误端口上运行的一个极佳示例。FTP 真的糟糕透了，因为它充满了漏洞。首先，协议完全没有加密，因此窃听者可以窃取你的用户拥有的任何密码，无论是合法的还是非法的；如果是与 FTP 客户端或服务器位于同一网络上的计算机，他可以监听整个通信并窃取所使用的密码。这代表了账户被盗的主要方式之一。尽管如此，FTP 还有其他几个问题。

## 提示

黑客俚语中的“owned”（拥有）一词与法律所有权无关。对系统拥有完全控制权（root）的人被称为“拥有”该系统。

FTP 简直是一团糟。它使用两个端口，在单独的连接上传输文件。默认的“活动”模式实际上通过让第二个端口的连接从服务器转移到客户端，破坏了正常的“客户端-连接-服务器”自定义，使得 FTP 的防火墙防护变得困难得多¹⁵。因为协议完全是明文的，可能通过向数据流注入数据包来接管连接。无论如何，通过监听（即使在被动模式下，在客户端连接之前）可以窃取文件。最后，在最坏的情况下，大多数 FTP 服务器至少有一个远程访问漏洞。这并不清楚是由于设计的复杂性还是守护进程开发中的缺陷导致的。

### 基础操作

#### 第一部分

`finger` 是一种信息收集和广播服务。你可以用它来查找哪些用户登录了系统、他们登录了多久，甚至他们处于空闲状态多多久。尽管这个工具非常友好，但对于那些愿意花时间寻找系统管理员晚上休息去哪里的攻击者来说，这也是非常有用的信息。你可能应该禁用此服务，或者至少使用 TCP Wrappers 来限制哪些 IP 地址具有此项功能。

现在让我们来看 `in.identd`：

```
auth stream tcp nowait nobody /usr/sbin/in.identd in.identd -l -e
```
