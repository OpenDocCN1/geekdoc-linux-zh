## 如何信任 PostgreSQL？

有一种科学方法可以验证 PostgreSQL 的可靠性。为了验证 PostgreSQL，发行版包含了一个回归测试包（`src/test/regress`）。回归测试包将验证标准 SQL 操作以及 PostgreSQL 的扩展功能。测试包已经包含了许多 SQL 测试程序。

您应该使用计算机的高速能力来验证 PostgreSQL，而不是使用人类脑力。计算机执行软件回归测试的速度比人类快百万甚至十倍。在不久的将来，计算机的速度将比人类大脑快几万倍！因此，使用计算机的力量来验证软件是合理的。

您可以根据需要添加更多测试，并如果您认为对互联网上的其他用户有用，将其上传到主要的 PostgreSQL 网站。

...周期，并且在向公众发布软件之前以确保良好的质量。PostgreSQL 的功能直接体现在回归测试包中。如果回归测试包中存在某个功能、语法或特性，则它就是受支持的；包中未列出的所有其他功能可能都不受 PostgreSQL 支持！你可能需要验证这些功能并将它们添加到回归测试包中。

# 系统布局

图 9.1 所示 PostgreSQL 文件布局显示了按默认方式安装时 Postgres 分发版的布局情况。如果你安装了 PostgreSQL RPM，那么 `pgql` 目录位于 `/var/lib/postgresql`，而 `doc` 目录位于 `/usr/doc/postgresql-x-x-x`，其中 `x-x-x` 是 PostgreSQL 的版本号。因此，你应该将此路径添加到你的命令行路径中。如果你使用 Berkeley C shell 的变体，例如 `csh` 或 `tcsh`，你需要在家目录下的 `.login` 文件中添加：

```
set path = ( /usr/local/postgresql/bin path )
```

如果你使用 Bourne shell 的变体，例如 `sh`、`ksh` 或 `bash`，则你需要在家目录下的 `.profile` 文件中添加：

```
PATH=/usr/local/postgresql/bin:$PATH
export PATH
```

从现在起，我们假设你已经将 Postgres bin 目录添加到路径中。此外，在整个文档中，我们将频繁引用“设置 shell 变量”或“设置环境变量”。如果你没有完全理解关于修改搜索路径的最后一段，在继续之前，你应该咨询描述你 shell 的 UNIX 手册页。

**图 9.1 PostgreSQL 文件布局。**

如果你没有按照默认方式进行设置，你可能需要做更多工作。例如，如果数据库服务器是一台远程机器，你需要将 `PGHOST` 环境变量设置为数据库服务器机器的名称。可能也需要设置环境变量 `PGPORT`。底线原则是：如果你尝试启动一个应用程序，而它抱怨无法连接到 postmaster，你必须返回并确保你的环境设置妥当。
