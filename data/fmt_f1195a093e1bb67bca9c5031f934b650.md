
无论你在管道中使用这种语法，还是像函数这样从底部循环，你都可以看到 `line` 命令可以以与 `read` 语句相同的方式。研究列表 2.5 中的函数，我们将在最后介绍该方法。

```bash
function while_line_LINE_bottom
{
    while line LINE
do
        echo $LINE
        :
done < $FILENAME
}
```

列表 2.5 `while_line_LINE_bottom` 函数列表。

这种方法是方法2，只是我们将 `read` 替换为 `line`。你会在计时测试中发现这两种技术看起来是一样的，但你会对时间差异感到惊讶。你必须等待计时脚本运行以看到结果。

函数 2.5 使用 `line` 命令在每次循环迭代中为 `LINE` 变量分配新文本。`while` 循环通过 `done` 循环终止符后的输入重定向从底部提供，`done < $FILENAME`。使用这种输入重定向技术保持文件打开读取，是向循环提供输入的最快方法之一。

## 方法 4：`cat $FILENAME | while LINE=`line``

现在我们开始进入我在某些脚本中看到的一些“创意”方法。虽然并不是所有操作系统都支持 `line` 命令（但在我的 Red Hat Linux 版本中支持），但这并不意味着在开源世界中没有它。

在稍微不同的命令结构中使用此循环命令。查看列表 2.2 中的函数以及列表 2.6 中带有 `line` 命令的函数，我们将看到它是如何工作的。

```bash
function while_read_LINE
{
    cat $FILENAME | while LINE=`line`
do
        echo "$LINE"
        :
    done
}
```

## 方法 9：使用文件描述符 `read LINE`

到目前为止，我们一直在做非常直接的循环。你曾经用过文件描述符来解析文件吗？我把下一个函数留到了最后。文件描述符的使用有点难以理解。我会尽力让它变得简单！在 Unix 操作系统的底层，文件是通过文件描述符引用的。你从一开始就应该知道三个文件描述符：`stdin`、`stdout` 和 `stderr`。标准输入（或 `stdin`）指定为文件描述符 0。这通常是键盘或鼠标。标准输出（或 `stdout`）指定为文件描述符 1。标准输出可以是你的终端屏幕或某种文件。标准错误（或 `stderr`）指定为文件描述符 2。标准错误是系统和程序发送或报告错误消息的方式。

你可以组合使用这些文件描述符。我确定你见过某些 shell 脚本将所有输出发送到“黑洞” `/dev/null`。看下面的命令：

```bash
my_shell_script.ksh >/dev/null 2>&1
```

进程的结果是完全运行。换句话说，没有任何外部输出。在内部，脚本可能正在读写文件，并可能向特定的终端发送输出，例如 `/dev/console`。当你运行 shell 脚本作为计数项或者你不感兴趣查看任何输出时，可能想要使用这种技术。

在上一个示例中，我们使用了两个文件描述符。我们可以使用其他文件描述符来处理输入和存储。在下一个示例中，我们将使用文件描述符 0（零）即标准输入以及文件描述符 3。在大多数 Unix 系统上，有效文件描述符的范围是从 0 到 19。在我们这里，我们将使用文件描述符 3，但我们也可以轻松地使用文件描述符 5。

我们将使用的这种方法有两个步骤。第一步是通过将所有内容重定向到我们新的文件描述符 3 来关闭文件描述符 0。我们使用以下语法执行此步骤：

```bash
exec 3<&0
```

现在，所有的键盘和鼠标输入都进入我们新的文件描述符 3。第二步是将我们的输入文件（由变量 `$FILENAME` 指定）发送到文件描述符 0（零），即标准输入。第二步使用以下语法完成：

```bash
exec 0<$FILENAME
```

到此时，任何需要输入的命令都将从 `$FILENAME` 文件接收输入。现在是举例说明的好时了。看列表 2.11 中的函数。

```bash
function while_read_LINE_FD
{
  exec 3<&0
  exec 0< $FILENAME

  while LINE
  do
  echo "$LINE"
  :
  done

  exec 0<&3
}
```

**列表 2.11** `while_read_LINE_FD` 函数列表。

在列表 2.11 的函数中，我们使用了熟悉的 `while` 循环来读取一行文本。但函数的开头执行了一个小小的文件描述符重定向。第一个 `exec` 命令将 `stdin` 重定向到文件描述符 3。第二个 `exec` 命令将 `$FILENAME` 重定向到 `stdin`，即文件描述符 0。`while` 循环可以执行，无需担心我们如何将一行文本分配给 `LINE` 变量。当 `while` 循环退出时，我们将之前重定向到文件描述符 3 的 `stdin` 重定向回原始文件描述符 0。

```bash
exec 0<&3
```

换句话说，我们将其设置回系统的默认值。注意本章稍后测试中的这种方法。我们有三个使用文件描述符的示例，它们利用了我们之前的一些 `while loops`。接下来的两个函数绝对是我遇到过的解析文件最不寻的技术。当你第一次看方法 10 和方法 11 时，看起来作者似乎还有了一些箱底。请在本章末尾比较所有的计时结果。

## 方法 10：使用文件描述符 `LINE='line'`

这里我们使用 `line` 命令。在这个函数中，`line` 命令替换了 `read` 命令；然而，我们仍然将使用文件描述符来获取 `$FILENAME` 作为 `while` 循环的输入。我们使用了方法 9 中描述的相同技术。看列表 2.12 中的函数。

```bash
function while_LINE_line_FD
{
  exec 3<&0
  exec 0< $FILENAME
  while LINE=`line`
  do
    echo "$LINE"
    :
  done
  exec 0<&3
}
```
