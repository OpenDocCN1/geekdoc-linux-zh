当我们查看这个文件时，我们看到了三个内容。首先是部署。这是在 Kubernetes 内部启动 MySQL 容器的清单文件。我们有了容器名称，并设置了它将使用的多少 CPU。我们还设置了存储磁盘存放在哪里。

`env` 部分是我们设置配置的地方。我们告诉容器创建一个名为 `mysql` 的新数据库和一个名为 `mysql` 的用户，并给该用户密码。

我们稍后在部署 WordPress 时会使用这些信息。

我们文件的第二部分是服务。它将像在防火墙中打开一个端口并设置端口 3306 开启并将服务名称为 `mysql`。这就是你将找到这个 MySQL 服务器的地方。

最后一部分是我们为我们的 MySQL 服务器添加所需的磁盘。

让我们使用命令应用我们的清单：

```bash
kubectl apply -f mysql.yaml
```

当你部署完成后，请验证 Pods 是否像之前一样正在运行。

### WordPress

让我们创建一个名为 `wordpress.yaml` 的新 YAML 文件并添加以下内容：

```yaml
kind: PersistentVolumeClaim
apiVersion: v1
metadata:
  name: wordpress-storage
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 2Gi
---
apiVersion: v1
kind: Service
metadata:
  name: wordpress
  labels:
    app: wordpress-pod
spec:
  type: ClusterIP
  ports:
    - port: 80
      targetPort: 80
      protocol: TCP
      name: http
  selector:
    app: wordpress-pod
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: wordpress
spec:
  replicas: 1
  selector:
    matchLabels:
      app: wordpress-pod
  template:
    metadata:
      labels:
        app: wordpress-pod
    spec:
      containers:
        - image: wordpress
          imagePullPolicy: Always
          name: wordpress-pod
          env:
            - name: WORDPRESS_DB_HOST
              value: mysql
            - name: WORDPRESS_DB_PASSWORD
              value: password
            - name: WORDPRESS_DB_USER
              value: mysql
            - name: WORDPRESS_DB_NAME
              value: wordpress
          ports:
            - containerPort: 80
              name: www
          resources:
            requests:
              memory: 64Mi
              cpu: 250m
            limits:
              memory: 256Mi
              cpu: 500m
          volumeMounts:
            - name: wordpress-storage
              mountPath: /var/www/html
          securityContext:
            fsGroup: 200
      volumes:
        - name: wordpress-storage
          persistentVolumeClaim:
            claimName: wordpress-storage
```

这个文件看起来就像我们的 MySQL。你可以看到在 `env` 部分，我们正在设置 MySQL 的值。然而，每个镜像都有其自己的设置值的方法，而 WordPress 并不使用相同的方法。假设你去 Docker Hub 查看该镜像，那将告诉你可以使用哪些值。让我们使用 `kubectl apply` 将我们的清单应用到集群中。然后验证 Pod 正在运行。

### 访问 WordPress

现在当 WordPress 运行时，我们想用网络浏览器访问它。为了实现这一点，我们将使用两种方法。首先，我们将直接向 WordPress 服务开放一个端口。第二种使用 Ingress 控制器和本地 IP。在 WordPress 文件中，进入 service 并修改服务使其如下所示：

```yaml
apiVersion: v1
kind: Service
metadata:
  name: wordpress
  labels:
    app: wordpress-pod
spec:
  type: NodePort
  ports:
    - port: 80
      targetPort: 80
      protocol: TCP
      name: http
  selector:
    app: wordpress-pod
```

然后再次应用 WordPress。我们再次应用了 WordPress。我们通过以下命令找到 WordPress 的端口：

```bash
kubectl get service
```
