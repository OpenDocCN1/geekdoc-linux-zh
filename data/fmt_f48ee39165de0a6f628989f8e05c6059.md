
## 配置卡片

现在你已经将 WaveLAN 卡安装到电脑中——无论是直接插入 PCMCIA 插槽还是通过 PCMCIA 适配卡——你必须配置 SuSE Linux 以使其工作。由于无线以太网是 Linux 支持设备集中较新的添加，YaST 并不包含配置无线以太网的模块：你必须编辑某些配置文件并手动插入信息。配置以太网硬件涉及三个步骤：

1. 下载、编译并安装一套用于配置无线设备的工具。
2. 编辑文件 `/etc/pcmcia/wavelan2_cs.conf`。这将配置内核使用与你的 WaveLAN 卡匹配的驱动程序。
3. 编辑文件 `/etc/pcmcia/wireless.opts`。定义用于无线卡的相关选项，例如你将使用的网络类型以及你希望用于加密的加密方式。

我们将依次讨论每一个步骤。

## 第二部分：在 SuSE Linux 工作站上设置网络

## 安装无线工具集

程序员 Jean Tourrilhes 领导的一个团队创建了一套在 Linux 下处理无线以太网非常有用的工具。在本文编写时，该工具集尚未包含在 SuSE Linux 7.0 版本中，但我们强烈建议你自己下载并构建该包。这并不困难，该包将为你节省大量时间。

1. 使用 YaST 安装来自 d 系列的软件包（用于“development”，即开发）。该软件包包含了你在 Linux 下编译内核模块时所需的头文件。如果你不知道如何使用 YaST 安装软件包，请参阅附录 A 的说明。我们假设你在安装 SuSE Linux 时已安装了 GCC 编译器；如果没有，请也安装这些工具。
2. 将你的网络浏览器指向 `http://www.hp.com/personal/Jean_Tourrilhes/Linux/Tools.html`。（我们假设你在家里或公司有一个可用的浏览器，尽管你尚未完成在 Linux 工作站上网络软件的安装）。该 URL 描述了无线工具集并提供了指向最新版本的链接。下载源码包。在本文编写时，最新版本为第 20 版，源码应位于一个名为 `wireless_tools.20.tar.gz` 的压缩包中。
3. 输入命令 `tar xzvf wireless_tools.20.tar.gz` 从压缩包中提取文件。此命令会在当前目录下创建 `wireless_tools.20` 目录并将文件复制其中。
4. 使用 `cd` 进入 `wireless_tools.20` 目录，并输入命令 `make`。这会自动编译包并创建可执行文件 `iwconfig`、`iwpriv` 和 `iwspy`。编译应该在无错误的情况下进行；如果你看到错误消息，请检查 `INSTALL` 文件以了解如何纠正可能出现的问题。
5. 输入以下命令安装可执行文件及其帮助页：

```
install -c -m 511 -o root -g root iwconfig iwpriv iwspy /usr/sbin/
install -c -m 644 -o root -g root iwconfig.8 iwpriv.8 iwspy.8 /usr/man/man8
```

### 编辑 /etc/pcmcia/wavelan_cs.conf

文件 `/etc/pcmcia/wavelan_cs.conf` 包含了配置 Linux 内核与 WaveLAN 卡协同工作的选项。特别是，你必须修改此文件以更改要使用的驱动程序。

在本文编写时，Linux 下有三个 WaveLAN 驱动：`wavelan_cs`、`wavelan2_cs` 和 `wvlan_cs`。默认情况下，SuSE Linux 配置为使用驱动 `wavelan2_cs`；然而，我们发现使用驱动 `wvlan_cs` 效果更好，建议使用它代替默认驱动。

要进行此更改，使用你喜欢的文本编辑器打开文件 `/etc/pcmcia/wavelan_cs.conf` 进行编辑。你应该看到如下：

```
device wavelan2_cs
class wavelan2_cs
```

将两行中的 `wavelan2_cs` 改为 `wvlan_cs`。保存并关闭文件。

### 编辑 /etc/pcmcia/wireless.opts

文件 `/etc/pcmcia/wireless.opts` 为你的工作站连接的无线网络设置选项。该文件分为若干章节。每个章节为特定类型的卡设置选项。在开始配置之前，你必须获取有关你将连接的无线网络的以下信息：

- 网络是以点对点（ad-hoc）模式还是配置模式（Managed 模式）运行？如果你正在建立自己的无线内网，你将使用 ad-hoc。
- 如果你正在为自己的网络设置加密，你需要设置一个既易记又难猜的加密密钥。加密密钥是任何无线网络的“阿喀琉斯之踵”：为了加密有意义，密钥必须保持保密，但密钥必须存在于网络上每台机器的配置文件中——根据定义，不存在所谓的共享秘密。

一旦你获取了这些信息，就可以使用你喜欢的文本编辑器打开文件 `/etc/pcmcia/wireless.opts` 进行编辑并开始工作。在文件顶部有如下章节：

```
# NOTE : 移除以下四行以激活下方示例
# ---- START SECTION TO REMOVE -----
*, *)
# --- END SECTION TO REMOVE ---
```

这是默认设置：实际上，它针对所有卡片（如 MAC 地址 `*, *` 所示）且没有设置任何选项。你应该通过在每行开头插入 `#`（井号）来注释掉该章节。在默认章节下方是定义 Lucent WaveLAN IEEE 卡的章节：

```
## Lucent WaveLAN IEEE
## Note : 仅限 wavelan_cs 驱动，且需要 1.0.4+ 版本以支持加密
*, **:00:60:1D:*
INFO="WaveLAN IEEE example (Lucent default settings)"
ESSID="WaveLAN Network"
MODE="Managed"
RATE="auto"
KEY="s:secul"
```

对其如下编辑：

- `MODE` 选项指示无线网络的类型。`Managed` 表示网络以配置模式运行，正如我们在第 3 章所述的；而 `Ad-Hoc` 表示网络以点对点模式运行。如果网络以点对点模式运行，请编辑 `MODE` 行，将 `Managed` 改为 `Ad-Hoc`。
- 选项 `KEY` 提供加密密钥。如果密钥以 `s:` 开头，则密钥为文本字符串；如果以其他字符开头，则驱动程序假设密钥是一组十六进制数字（如果你没有以 `s:` 开头密钥，但在密钥中包含了除十六进制数字以外的字符，则加密将无法正常工作）。将 `secul` 替换为你的网络所需的加密密钥；如果密钥是数字而非文本字符串，请从加密密钥中删除 `s:`。要关闭加密，请将选项 `KEY` 设置为空字符串。

当你完成这些编辑后，按通常的方法保存并关闭文件。然后重启你的 SuSE Linux 工作站，在重启后，它应该重新读取配置文件并按照你指示的方式配置 WaveLAN 卡。它应该为该卡分配接口 `wlan0`。

到此，我们结束了关于安装以太网硬件的讨论。在第 6 章，我们将讨论如何进行网络部分的配置——即为接口分配 IP 地址，以及如何将数据报路由到设备接口。

## 安装串口设备

在上一节中，我们描述了如何安装和配置以太网设备。这可以用于连接到现有的内网，也可以将你的 Linux 工作站连接到 DSL 调制解调器或缆线调制解调器。在本节中，我们将处理通过计算机串口工作的设备——主要是声学拨号调制解调器。这是可用设备中最慢的，但也是最便宜且仍然最广泛使用的。

我们首先讨论使用串口的一些细节；然后描述如何选择、安装和配置声学调制解调器。

## 串口

串口是一种按串行方式传输字节流的字符设备。由于现代调制解调器通过串口工作，你的串口硬件以及你对串口的配置会严重影响调制解调器的性能。

## 硬件

所有串口都使用一种称为通用异步收发器（UART）的芯片。工业标准的 UART 由国家半导体公司（National Semiconductor）制造。计算机制造商使用了多种型号的 National UART：某些使用价格较便宜的 National 16450 UART，但为了从现代高速调制解调器获得可用性能，你必须使用带有 National 16550 UART 或更晚型号的串口。

其他一些公司也制造 UART，它们通常设计为模拟国家半导体公司的 UART 之一。使用这些厂商 UART 的串口硬件会在其文档中说明该 UART 模拟的是国家半导体的型号。

在过去，并行口、串口和磁盘控制器都有自己的外围卡。现在它们都组合到单个控制器卡中，或者直接构建在机器的主板上。检查控制器卡的文档；如果你的控制器卡没有使用或模拟国家半导体 16550 UART（或更晚型号），那么你应该更换控制器卡或购买内置调制解调器（它有自己的 UART）。如果你的计算机主板集成了串口，请检查文档查看主板使用的是哪种 UART。如果它没有使用或模拟 16550 或更新型号的 UART，那么你应该考虑购买内置调制解调器。毕竟，花费数百美元购买互联网服务和高速调制解调器，却让你的系统性能被一个廉价的 UART 扼杀，是没有意义的。

## 设备名称

IBM 风格的 PC 支持最多四个串口。当你安装内部组件时为 COM1 时，配置涉及告诉调制解调器使用哪个串口。分配的串口不能与现有的串口冲突——例如，你不能有两个设备被识别为 COM2。

Linux 使用设备文件 `/dev/ttyS0` 到 `/dev/ttyS3` 分别管理串口 COM1 到 COM4。你可以看到，COM 端口和 Linux 设备文件之间的编号方案略有不同：COM 端口编号为 1 到 4，而 Linux 设备文件编号为 0 到 3。然而，如果你记住这种差异，就不应该感到困惑——至少不会经常感到困惑。

## 中断分配

正如我们之前在讨论中断时提到的，串口 COM1 默认分配到 IRQ 4，串口 COM2 分配到 IRQ 3。由于历史原因，串口 COM3 和 COM4 没有被分配任何标准 IRQ。相反，COM3 分配了与 COM1 相同的中断，COM4 分配了与 COM2 相同的中断；操作系统预计通过名为“轮询”（polling）的技术来管理这些端口。

Linux 不支持轮询。因此，如果你通过添加内置调制解调器为系统添加第三个串口，你必须为第三个串口找到一个空闲的 IRQ，并使用 `setserial` 命令告诉 Linux 内核该第三个串口使用哪个 IRQ。

教训是，如果可能，你应该避免为系统添加第三个串口。如果你正在使用内置调制解调器，且系统上的某个现有串口是空闲的，你应该（在可能的情况下）将其关闭（通常通过跳线跳过控制器来实现），然后配置内置调制解调器来替换你关闭的设备。有关如何关闭串口的信息，请参阅计算机控制卡随附的文档。

## 第 5 章：为你的 SuSE Linux 系统添加网络硬件

## 选择声学调制解调器

**modem**（调制解调器）一词是 *modulator/demodulator*（调制/解调器）的缩写。简而言，调制解调器是一种将数字数据转换为可以通过电话线传输的模拟信号，并将从电话线接收的模拟信号转换回数字数据的设备。*acoustic*（声学的）一词是指它通过电话线发送模拟信号（听到时是声音）来进行通信。

调制解调器传输数据的速度以每秒千比特（Kbps）为单位。注意，每秒比特除以 8 得到调制解调器可以传输的最大字节；因此，56 Kbps 的调制解调器每秒可以传输 7,000 字节。考虑到传输和网络协议的开销，56 Kbps 调制解调器每秒实际传输的可用数据少于 3,500 字节。

## 内部与外部

声学调制解调器有两种类型：内置和外部。**内置调制解调器**是一种直接插入计算机主板插槽的卡。**外部调制解调器**是一个通过电缆插入你机器串口之一的小盒子。

每种调制解调器都有其优缺点：

- 内置调制解调器——通常比外部调制解调器便宜 10 到 20 美元。内置调制解调器不需要外部电源，也不占用桌面空间。然而，要安装它，你必须打开计算机并将调制解调器插入主板。内置调制解调器没有指示灯，因此很难判断调制解调器正在做什么或它的状态如何。最后，由于内置调制解调器实际上是你安装到机器的另一个串口，你必须执行特定的命令以避免与现有端口冲突。
- 外部调制解调器——比内置调制解调器贵。外部调制解调器占用桌面空间，并且需要独立的电源，这意味着你的桌子上会多出一个缠绕的电缆，多找一个电源插座。安装简单——将其插入串口即可——而且它没有与现有硬件发生冲突的可能性。最后，大多数调制解调器都有指示灯来描述其状态和正在进行的操作。这些灯使得诊断调制解调器的状态变得容易得多。

你应该根据自己的需求和预算选择最合适的调制解调器类型。如果价格不是你的首要考虑，并且你希望安装和配置简单，请购买外部调制解调器。如果你不介意更复杂的安装，并且省钱对你很重要，那么内置调制解调器是更好的选择。

## 第二部分：在 SuSE Linux 工作站上设置网络

请记住，两种类型的调制解调器都需要电话插座。我们还建议，如果您打算频繁使用调制解调器，应该考虑安装一条专线。在计算您的 Internet 连接成本时，您应该考虑这一点。

### 56 KB 调制解调器

声学调制解调器的行业标准是 56K。目前市面上仍有部分 28.8K 调制解调器在流通，但它们已经过时且不再生产。当 56K 调制解调器首次上市时，它们是使用两种互不兼容的标准构建的：来自 US Robotics（现为 3COM 部门）的 X2 和来自 Rockwell 的 K56flex。由于连接两端的调制解调器必须使用相同的标准才能以 56K 的速度通信，这是一个严重的问题。然而，这两种标准现在都被一个新标准 V.90 所取代，该标准已获得整个行业的认可。无论调制解调器看起来是多么划算，您都不应该购买不支持 V.90 的调制解调器。

您可能对让 56K 调制解调器工作的原理感兴趣。能够直接从电话公司交换机接收数字信号的 56K 调制解调器，允许您在另一端连接调制解调器时使用。对于 33.6K 调制解调器，数据以一系列模拟音调发送到电话线上。这些音调被电话公司的交换机接收，并通过一种称为模拟转数字（A/D）转换的过程采样为一组数字信号。生成的数字信号被发送到您的 ISP 交换机，从数字转换回模拟，然后通过连接此调制解调器的线路发送。

对于 33.6K 和更慢的调制解调器，数据在两个方向上都是这样。然而，56K 调制解调器是混合型的。在一个方向上它是模拟的，类似于普通的 33.6K 调制解调器；在另一个方向上，它是数字的，可以使用电话公司在交换机之间发送数据的大部分数字信号。电话公司以每秒 8,000 次采样的速率将交换机之间的通信数字化。对于每个连接，每个交换机对应 64,000 个不同的数字信号。电话网络的设计是为了携带数字化通信，而不是原始数字数据，因此那些在嘈杂的电话线上距离近到无法区分的音调会被消除。

此外，某些音调通常不会出现在语音通信中，而且传输所需的功率超过了 FCC 对语音电话的功率限制。这些音调也被消除了，将 56K 调制解调器的实际传输带宽限制在 53K。到您的 ISP 调制解调器的上行是模拟的，限制为 33.6K。如果您的电话布线允许，来自您的 ISP 的下行是数字的，因此您可以接收高达 53K。

您是否可以使用这种技术取决于连接电脑的电话线质量。如果您居住在使用可以使用技术的地区，它的工作效果足够好，会让您注意到下载速度的提升。测试您的布线是否支持 56K；您可以使用 3COM 提供的服务来测试线路。从终端仿真器（如 `minicom`）执行此操作，拨打 1-888-877-9248 的 3COM 线路测试设施。根据情况回答 no 或 yes 以使用图形（如果您无法判断，请使用），并使用名为 line 的第一个名字和名为 test 的姓氏进行登录。您的电话线将接受 56K 兼容性测试，结果将显示在您的屏幕上。

## WINMODEMS 无法工作

在此点处，我们必须插入一个警告。一种流行的调制解调器被称为软调制解调器；它们也被称为 Windows 调制解调器或 Winmodems。它们与不使用串口且功能更全的调制解调器不同，它们内部也没有内置 UART。相反，这些调制解调器使用您电脑的 CPU 将模拟信号翻译为数字信号，反之亦然。由于这些原因，电脑使用 Winmodem 的性能将不如使用全功能调制解调器。

由于 Winmodem 是真实的、全功能调制解调器的精简版，它们的成本便宜得多。通常，新计算机系统会带有它们；您应该避免这些设备，因为它们的性能并不好，而且部分原因是因为还没有为它们编写 Linux 驱动程序。

如果您使用的是预装了 Winmodem 的较新电脑，您必须移除它并安装全功能调制解调器。如果您不确定系统的调制解调器是否是 Winmodem，请检查随系统附带的文档。此外，Winmodem 的物理尺寸可能比普通的全功能调制解调器更小；如果随机器的调制解调器看起来异常小，请务必仔细检查以确保它不是 Winmodem。

这结束了关于如何选择声学调制解调器的简要介绍。后续章节分别描述了如何安装外部调制解调器以及如何安装内部调制解调器。

## 安装外部调制解调器

当启动 Linux 时，安装外部调制解调器很简单：将其插入串口。请记住，两种类型的调制解调器都需要附近的电话插座。我们还建议，如果您打算频繁使用调制解调器，应该考虑安装一条专线。在计算您的 Internet 连接成本时，您应该考虑这一点。

## 第二部分：在 SuSE Linux 工作站上设置网络

然后，使用 YaST 描述调制解调器，如下所示：

1. 输入 `su` 以访问 root 权限。
2. 从 YaST 的主菜单中选择 System（系统）。
3. 当 YaST 显示菜单时，选择 Hardware（硬件）。
4. 当 YaST 显示菜单时，选择 Modem configuration（调制解调器配置）。
5. 使用 Linux 命名选择端口（`ttyS0` 到 `ttyS3`）。
6. 选择端口后，按 Enter 键。

YaST 将创建 `/dev/modem` 并将其链接到端口。要测试您的系统是否与调制解调器通信，输入此命令：
