
``` 
    Bool            send_event;  /* true if this came from a SendEvent request */
    Display         *display;    /* Display the event was read from */
    Window          window;
    Atom            selection;
    Time            time;
} XSelectionClearEvent;
```

`selection` 成员被设置为原子值。`time` 成员被设置为该选择最后记录的时间。`window` 成员是 `XSetSelectionOwner` 中当前所有者（丢失选择的一）指定的窗口。

## `SelectionRequest` 事件

X 服务端向选择的所有者报告 `SelectionRequest` 事件。每当客户端通过调用 `XConvertSelection` 对拥有的选择请求转换时，X 服务端就会生成此事件。

该事件类型的结构包含：

``` 
typedef struct {
    int             type;        /* SelectionRequest */
    unsigned long serial;      /* # of last request processed by server */
    Bool            send_event;     /* true if this came from a SendEvent request */
    Display         *display;    /* Display the event was read from */
    Window          owner;
}

| Window | requestor; |
| Atom | selection; |
| Atom | target; |
| Atom | property; |
| Time | time; |
```

`owner` 成员被设置为当前所有者指定的原子。`requestor` 成员被设置为请求选择的窗口。`selection` 成员被设置为命名选择的原子。例如，`PRIMARY` 用于标识主选择。`target` 成员被设置为指示所需的选择原子。`property` 成员可以是属性名称或 `None`。`time` 成员被设置为 `ConvertSelection` 的时间戳或 `CurrentTime`。

所有者应根据指定的 `target` 转换选择，并向请求者发送 `SelectionNotify`。使用选择的完整规范见 X 联盟标准《进程间通信手册》。

## `Notification` 事件

当选择没有所有者时，X 服务端响应 `ConvertSelection` 协议请求生成此事件。当存在所有者时，它应由选择的所有者使用 `XChangeEvent` 生成。选择的所有者在选择已转换并存储为属性，或者无法执行选择转换时（通过将 `property` 成员设置为 `None` 来指示），应向请求者发送此事件。

如果在 `ConvertSelection` 协议请求中未指定属性，所有者应选择一个属性名称，将结果作为该属性存储在请求者窗口上，然后发送该实际属性名称的 `SelectionNotify`。

该事件类型的结构包含：

``` 
typedef struct {
    int type;                   /* SelectionNotify */
    unsigned long serial;      /* # of last request processed by server */
    Bool send_event;            /* true if this came from a SendEvent request */
    Display *display;           /* Display the event was read from */
    Window requestor;
    Atom selection;
    Atom target;
    Atom property;              /* atom or None */
    Time time;
} XSelectionEvent;
```

`requestor` 成员被设置为请求选择的窗口。`selection` 成员被设置为指示选择的原子。对于 例如，`PRIMARY` 用于主选择。目标成员（`target` member）被设置为指示转换后类型的原子。例如，`PIXMAP` 用于位图。属性成员（`property` member）被设置为指示结果存储在哪个属性上的原子。如果转换失败，属性成员被设置为 `None`。时间成员（`time` member）被设置为转换发生的时间，可以是一个时间戳或 `CurrentTime`。

# 第 11 章. 事件处理函数

本章讨论了你可以用于以下操作 Xlib 函数：

- 选择事件
- 处理输出缓冲区和事件队列
- 从事件队列中选择事件
- 发送和获取事件
- 处理协议错误

## 注意

某些工具包（toolkits）使用自己的事件处理函数，并且不允许你将这些事件处理函数与 Xlib 中的函数交换。要了解更多信息，请参阅工具包提供的文档。

大多数应用程序都简化了事件循环：它们等待事件发生，决定如何处理该事件，执行某些与显示变化相关的代码，然后等待下一个事件。

## 选择事件

有两种方法可以选择你想要报告给客户端应用程序的事件。一种方法是在调用 `XCreateWindow` 和 `XChangeWindowAttributes` 时，设置 `XSetWindowAttributes` 结构中的事件掩码（event mask）成员。另一种方法是使用 `SelectInput`。

``` 
XSelectInput(display, w, event_mask);
```

`display` 指定与 X server 的连接。

`w` 指定你感兴趣的窗口。

`event_mask` 指定事件掩码。

`XSelectInput` 函数请求 X server 报告与指定的事件掩码相关的事件。初始情况下，X 不报告这些事件中的任何一个。事件是相对于窗口报告的。如果窗口对某个设备感兴趣，它通常会传播到最近感兴趣的祖先，除非 `do_not_propagate` 掩码禁止了这一点。

设置窗口的 event-mask 属性会覆盖对同一窗口之前的任何调用，但不会影响其他客户端。多个客户端可以选择同一个窗口，遵循以下限制：

- 多个客户端可以在同一个窗口上选择事件，因为它们的事件掩码是不相交的。当 X server 生成一个事件时，它会将其报告给所有感兴趣的客户端。
- 同一时间只有一个客户端可以选择 `CirculateRequest`、`ConfigureRequest` 事件，这些事件与事件掩码 `SubstructureRedirectMask` 关联。
- 同一时间只有一个客户端可以选择 `ResizeRequest` 事件，该事件与事件掩码 `ResizeRedirectMask` 关联。
- 同一时间只有一个客户端可以选择 `ButtonPress` 事件，该事件与事件掩码 `ButtonPressMask` 关联。

服务器将事件报告给所有感兴趣的客户端。

`XSelectInput` 可以产生 `BadWindow` 错误。

## 处理输出缓冲区

输出缓冲区是 Xlib 用于存储请求的区域。本节描述的函数在函数将阻塞或不返回事件时会刷新输出缓冲区。也就是说，所有留在输出缓冲区中尚未传输到 X server 的请求。这些函数的区别在于它们可能执行的额外任务。

要刷新输出缓冲区，请使用 `XFlush`。

``` 
XFlush(display);
```

`display` 指定与 X server 的连接。

`XFlush` 函数刷新输出缓冲区。大多数应用程序不使用此函数，因为输出缓冲区会根据调用 `XSync`、`XNextEvent` 和 `WindowEvent` 的需要自动刷新。由服务器生成的事件可能会被入入库的事件队列中。

要刷新输出缓冲区并等待所有请求都已处理，请使用 `XSync`。

``` 
XSync(display, discard);
```
