
一个带有依赖项的额外规则可以一次性为多个文件提供额外的依赖项。例如，`Makefile` 通常有一个变量（如 `objects`），包含了正在构建的系统中所有编译器输出文件的列表。如果 `config.h` 变化，说明它们都必须重制的简单方法是写如下内容：

```
objects = foo.o bar.o
```

文件名（参见第 8.2 节 [字符串替换与分析函数]，第 76 页）：

```
files = foo.elc bar.o lose.o

$(filter %o,$(files)): %o: %c
$(CC) -c $(CFLAGS) $<$
$(filter %.elc,$(files)): %.elc
emacs -f batch-byte-compile $<
```

在此示例中，`'$(filter %o,$(files))'` 的结果是 `'bar.o lose.o'`，静态模式规则会导致这些对象文件每一个都通过编译对应的 C 源文件来更新。`'$(filter %.elc,$(files))'` 的结果是 `'foo.elc'`，因此该文件是根据 `'foo.elc'` 生成的。

另一个示例展示了如何在静态模式规则中使用 `$$`：

```
bigoutput littleoutput : %output : text.g
generate text.g -* $$
```

当运行 `generate` 命令时，`$$` 将展开为目标干部（stem），即 `'big'` 或 `'little'`。

### 4.10 静态模式规则与隐式规则

静态模式规则与定义为模式规则的隐式规则有许多共同点（参见第 10.5 节 [定义与重新定义模式规则]，第 109 页）。两者都包含一个目标的模式和一个用于构造依赖项名称的模式。区别在于 `make` 如何决定何时应用该规则。

隐式规则可以适用于任何匹配其模式的目标，但它只有在目标没有其他指定的命令时，且只有在可以找到依赖项时才会生效。如果出现多个隐式规则被认为适用，则只应用其中一个；选择取决于规则的顺序。

相比之下，静态模式规则适用于你在规则中指定的**精确列表**。它不会适用于任何其他目标，并且一如不变地适用于每一个指定的目标。如果存在两个冲突的规则都适用，且两者都包含命令，则这是一个错误。

出于以下原因，静态模式规则可能比隐式规则更好：

- 你可能希望为某些文件覆盖通常的隐式规则，这些文件的名称无法在语法上进行分类，但可以给出一个显式列表。
- 如果你无法确定你正在使用的目录的确切内容，你可能不确定哪些无关文件会导致 `make` 使用错误的隐式规则。选择可能取决于隐式规则搜索的顺序。使用静态模式规则则不存在不确定性；每条规则都精确适用于所指定的目标。

### 4.11 双冒号规则

双冒号规则在目标名称后使用 `::` 而不是 `:`。当同一个目标出现在多个规则中时，它们的处理方式与普通规则不同。

当一个目标出现在多个规则中时，所有规则类型必须相同：全都是普通规则，或者全都是双冒号规则。如果是双冒号规则，则每一条都是相互独立的。如果目标比该规则的任何依赖项都旧，则执行该双冒号规则的命令。如果该规则没有依赖项，则其命令将始终被执行（即使目标已经存在）。这可能导致执行没有、任何一个或所有双冒号规则。具有相同目标的双冒号规则实际上是相互分离的。每条双冒号规则都是单独处理的，就像具有不同目标的规则一样。一个目标的双冒号规则按照它们在 `makefile` 中出现的顺序执行。然而，双冒号规则真正有意义的情况是执行命令的顺序无关紧要的情况。双冒号规则有些晦涩，且并不经常有用；它们提供了一种机制，用于更新目标的方法取决于是哪个依赖文件导致了更新的情况，而这种情况非常罕见。每条双冒号规则都应该指定命令；如果没有指定，如果存在隐式规则，将使用隐式规则。参见第 10 章 [使用规则]，第 101 页。

### 4.12 生成依赖项

在程序的 `makefile` 中，你需要编写的许多规则通常只说明对象文件依赖于某些头文件。例如，如果 `'main.c'` 通过 `include` 使用了 `'defs.h'`，你会写道：

```
main.o: defs.h
```

你需要这条规则，以便 `make` 知道每当 `defs.h` 变化时都必须重新制作 `'main.o'`。你可以看到，对于一个大型程序，你需要在 `makefile` 中编写几十条这样的规则，并且在每次添加或删除 `include` 时必须非常小心地更新 `makefile`。为了避免这种麻烦，现代 C 编译器可以通过查看源文件中的 `include` 行来为你编写这些规则。通常这通过给编译器的 `-M` 选项实现。例如，命令：

```
cc -M main.c
```

生成输出：

```
main.o : main.c defs.h
```

因此，你不再需要自己编写所有规则。编译器会为你完成。注意，`makefile` 中提到 `'main.o'` 的此类依赖项永远不会被隐式规则搜索视为中间文件。这意味着 `make` 在使用该文件后不会将其删除；参见第 10.4 节 [隐式规则链]，第 108 页。

在旧的 `make` 程序中，传统做法是使用此编译器功能通过类似 `'make depend'` 的命令按需生成依赖项。该命令会创建一个名为 `'depend'` 的文件，包含所有自动生成的依赖项；然后 `makefile` 可以包含它们（参见第 3.3 节 [Include]，第 12 页）。在 GNU `make` 中，重新制作 `makefiles` 功能使得这种做法变得过时——你不需要显式让 `make` 重新生成依赖项，因为它会重新生成任何过期的 `makefile`。
