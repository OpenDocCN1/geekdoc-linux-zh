
```c
/* 选中时在 EnterWindow 和 FocusIn 时生成 */

typedef struct {

    int type; /* KeymapNotify */

    unsigned long serial; /* 服务器处理的最后一个请求数 */

    Bool send_event; /* 如果来自 SendRequest 则为 true */

    Display display; /* 从何处读取的事件 */

    Window window;

    char key_vector[32];

} XkeyEvent;
```

`window` 成员未未使用，但某些工具包可能会使用。`key_vector` 成员设置为键盘的位向量。每个设置为 1 的位表示相应的按键当前被按下。该向量表示为 32 字节。字节 N（从 0 开始）包含 8N 到 8N+7 的位，其中字节中的最低位代表按键 8N。

# Exposure（暴露/显示）事件

X 协议不保证在窗口被遮挡或重新配置时保留窗口区域的内容。某些实现可能会保留窗口内容。其他实现可以自由销毁窗口内容。（注：原文此处存在大量重复的无效文本，已进行清理）。

```c
Drawable drawable;

int major_code; /* * core 为 CopyArea 或 CopyPlane */

int minor_code; /* * 在 core 中未定义 */

XNoExposeEvent;
```

这两个结构具有这些共同成员：`drawable`、`major_code`（主代码）和 `minor_code`（次代码）。`drawable` 成员被设置为执行图形请求的区域的可绘制对象。`major_code` 成员被设置为客户端发起的请求，可以是 X `CopyArea` 或 `CopyPlane`。如果是 X `CopyArea`，则通过调用 `XCopyArea` 发起了该请求；如果为 X `CopyPlane`，则通过调用 `XCopyPlane` 发起了该请求。这些常量定义在 `<X11/Xscroll.h>` 中。`minor_code` 成员与 `major_code` 成员一样，用于表示客户端发起了哪种图形请求。然而，在这些情况下没有定义，尽管可能会被扩展程序使用。

`GraphicsExpose` 结构具有这些额外的成员：`x`、`y`、`width`、`height` 和 `count`。`x` 和 `y` 成员被设置为相对于 `drawable` 起点的坐标，指示矩形的左上角。`width` 和 `height` 成员设置为矩形的大小（跨度）。`count` 成员设置为后续 `GraphicsExpose` 事件的数量。如果 `count` 为 0，则该窗口不再有后续的 `GraphicsExpose` 事件。然而，如果 `count` 不为零，则该窗口将后续至少该数量的 `GraphicsExpose` 事件（可能更多）。

## CirculateNotify 事件

当窗口在堆栈中的位置发生变化时，X 服务器可以向想要获取信息的客户端报告 `CirculateNotify`（循环堆栈通知）事件。每当客户端应用程序调用 `XCirculateSubwindows`、`XCirculateSubwindowsUp` 或 `XCirculateSubwindowsDown` 导致窗口实际上重新堆叠时，X 服务器 就会生成此类型的事件。

要接收 `CirculateNotify` 事件，需要在窗口的 `event-mask` 属性中设置 `StructureNotifyMask` 位，或者在父窗口的 `event-mask` 属性中设置 `SubstructureNotifyMask`（在这种情况下，循环任何子窗口都会生成事件）。

此类型的事件结构包含：

```c
typedef struct {      /* CirculateNotify */

    int type;

    unsigned long serial;     /* 服务器处理的最后一个请求数 */

    Bool send_event;          /* 如果来自 SendEvent 则为 true */

    Display *display;          /* 读取事件的显示器 */

    Window event;

    Window window;

    int place;                /* PlaceOnTop, PlaceOnBottom */

} XCirculate;
```

`event` 成员被设置为重新堆叠的窗口或其父窗口，取决于选择了 `StructureNotify` 还是 `SubstructureNotify`。`window` 成员被设置为堆叠发生后窗口的位置，其值可以是 `PlaceOnTop`（置于顶）或 `PlaceOnBottom`（置于底）。如果是 `PlaceOnTop`，则窗口位于所有兄弟窗口之上；如果是 `PlaceOnBottom`，则窗口现在位于兄弟窗口之下。

## ConfigureNotify 事件

X 服务器可以向想要获取窗口状态更改（如尺寸、位置、边框和堆叠顺序）信息的客户端报告 `ConfigureNotify` 事件。每当客户端应用程序完成以下任一配置窗口请求时，X 服务器就会生成此类型的事件：

- 通过调用 `XConfigureWindow` 重新配置窗口的尺寸、位置、边框和/或堆叠顺序。
- 通过调用 `XLowerWindow`、`XRaiseWindow` 或 `XRestackWindow` 更改窗口在堆叠顺序中的位置。
- 通过调用 `XMoveWindow` 移动窗口。
- 通过调用 `XResizeWindow` 更改窗口尺寸。
- 通过调用 `XMoveResizeWindow`、`XMapRaised` 更改窗口尺寸和位置。
- 通过调用 `XSetWindowBorderWidth` 更改窗口边框宽度。

要接收 `ConfigureNotify` 事件，需要在窗口的 `event-mask` 属性中设置 `StructureNotifyMask` 位，或者在父窗口的 `event-mask` 属性中设置 `SubstructureNotifyMask`（在这种情况下，配置任何子窗口都会生成事件）。

此类型的事件结构包含：

```c
typedef struct {

    int         type;          /** ConfigureNotify */

    unsigned long serial;    /** 服务器处理的最后一个请求数 */

    Bool        send_event;    /** 如果来自 SendEvent 请求则为 true */

    Display     *display;     /** 读取事件的显示器 */

    Window      event;

    Window      window;

    int         x, y;

    int         width, height;

    int         border_width;

    Window      above;

    Bool        override_redirect;

} XConfigureEvent;
```
