
# 第 20 章 电子邮件

在我们深入研究 `sendmail` 可能使用的各种配置宏、功能和选项之前，让我们先采用一个“无装饰”配置来说明通用过程。我们的示例是叶节点 `example.example.com`；主配置文件名为 `example.mc`。以下是完整的 `.mc` 文件：

```
divert(-1)
#### example 的基础 .mc 文件
divert(0)
VERSIONID($id$)
OSTYPE(local)
MAILER(local)
MAILER(smtp)
```

除了 `divert` 命令外，每行都调用了一个封装的宏。前四行是模板代码；它们在编译后的文件中插入了 `sendmail` 版本、编译配置的目录等注释。`OSTYPE` 宏包含了 `ostype/linux.m4`。`MAILER` 行用于本地投递（向 `example.example.com` 有账户的用户）以及向互联网站点的投递。

要构建真实的配置文件，只需运行复制到新 `cf` 目录的 `Build` 命令：

```
Build example.cf
```

最后，将 `example.cf` 安装在正确的位置——通常是 `/etc/mail/sendmail.cf`，但某些供应商使用隐藏位置。对于 `/etc` 和 `/usr/lib`，则更倾向于使用供应商隐藏位置。

规模较大时，可能想要创建一个单独的 `m4` 文件来存储主机默认值；然后各个主机可以使用 `DOMAIN` 宏包含此文件的内容。并不是每个主机都需要单独的文件，但每组相似主机（相同架构和相同角色：服务器、客户端等）可能都需要它们自己的配置。

`.mc` 文件中宏的顺序不是随机的。它应该是

```
VERSIONID
OSTYPE
DOMAIN
FEATURE
本地宏定义
MAILER
```

即使有了 `sendmail` 简单的 `m4` 配置系统，你仍然需要根据你的规模做出若干配置决策。当你阅读下面描述的功能时，考虑它们可能如何适应你站点的组织。小型站点

![](img/9b33263d3e7e36cd43da7756018c8735_829_0.png)

可能只有一个中心节点和叶子节点，因此只需要两个版本的配置文件。较大的站点可能会将入站和出站邮件的枢纽分开，可能还有一个独立的 `POP/IMAP` 服务器。

无论你的站点有多复杂，无论它向外界呈现出什么状态（例如暴露在外、在防火墙后或在虚拟网络上），`cf` 目录下可能都包含一些合适的现成配置片段，等待自定义并运行。

## 20.10 SENDMAIL 配置原语

`sendmail` 配置命令对大小写敏感。按照惯例，预定义宏名称全大写（例如 `OSTYPE`），`m4` 全小写（例如 `define`），可配置的选项通常以小写 `conf` 开头并后跟大写变量名（例如 `confALLBACK_MX`）。宏还引用一个名为 `..macroname/arg1.m4` 的 `m4` 文件。例如，引用 `OSTYPE('linux')` 会导致包含 `..ostype/linux.m4` 文件。

### 表与数据库

在深入特定的配置原语之前，我们必须首先讨论表（有时称为 maps 或数据库），`sendmail` 可以用它们来执行邮件路由或地址重写。大多数表与 `FEATURE` 宏配合使用。

表是路由、对齐、策略或其他信息的缓存（通常是文本文件），这些信息通过 `makemap` 命令转换为数据库格式，然后作为 `sendmail` 的一个或多个查找操作的信息。虽然数据通常以文本文件形式开始，但 `sendmail` 表的数据可以来自 DNS、NIS、LDAP 或其他源。使用集中的 IMAP 服务器可以减轻 `sendmail` 追踪用户的负担，并使它的某些表变得过时。

系统支持两种数据库：大多数 UNIX 和 Linux 版本的标准 `dbm/ndbm` 库，以及 Berkeley DB（后者是一个更具扩展性的库，支持多种存储架构）。如果你的系统有安装 BDB 或你可以安装它，我们建议使用 BDB。它比 `dbm` 更快，且创建的文件更小。

`sendmail` 定义了三种数据库映射类型：

- `dbm` 使用可扩展的哈希算法（`dbm/ndbm`）
- `hash` 使用标准的哈希方案（DB）
- `btree` 使用 B 树数据结构（DB）

对于 `sendmail` 中的大多数表应用，`hash` 数据库类型（默认类型）是最好的。我们使用 `makemap` 命令从文本文件构建数据库文件；你指定数据库类型和输出文件名。数据库的文本版本应该出现在 `makemap` 的标准输入中。例如：

```
$ sudo makemap hash /etc/mail/access < /etc/mail/access
```

乍一看，这个命令看起来像是一个错误，会导致输入文件被空输出文件覆盖。然而，`makemap` 会加上适当的后缀，因此实际输出文件是 `/etc/mail/access.db`，实际上并没有冲突。每当文本文件更改时，必须使用 `makemap` 重新构建数据库文件（但 `sendmail` 不需要 `HUP`）。

生成表的文本文件中的注释以 `#` 开始，并持续到行尾。

在大多数情况下，数据库键使用最长匹配项。对于任何哈希数据结构，输入文件中条目的顺序并不重要。`FEATURE` 宏期望数据库文件使用默认哈希类型，并将 `/etc/mail/tablename.db` 作为数据库文件名。

### 通用宏和特性

表 20.10 列出了常见的配置原语、它们是否通常被使用（是、否、可能）以及其功能的简要描述。表格随后的章节将提供更多细节和示例。

| 原语 | 是否使用？ | 描述 |
|---|---|---|
| `OSTYPE` | 是 | 包含特定操作系统的路径和邮件标记 |
| `DOMAIN` | 否 | 包含站点特定的配置细节 |
| `MAILER` | 是 | 启用邮件发送器，通常为 `smtp` 和 `local` |
| `FEATURE` | 可能 | 启用多种 `sendmail` 功能 |
| `use_cf` | 是（服务器） | 列出你接受邮件的主机列表 |
| `redirect` | 可能（服务器） | 用户移动时退回邮件 |
| `always_add_domain` | 是 | 如果定义了 UA，则完全限定主机名 |
| `access_db` | 可能（服务器） | 设置用于中继邮件的主机数据库 |
| `virtuertable` | 可能（服务器） | 开启别名（虚拟域名） |
| `ldap_routing` | 可能（服务器） | 使用 LDAP 路由入站邮件 |
| `MASQUERADE_AS` | 是 | 使所有邮件似乎来自同一个地方 |
| `EXPOSED_USER` | 是 | 列出不应被伪装的用户 |
| `MAIL_HUB` | 是（服务器） | 指定入站邮件的邮件服务器 |
| `SMART_HOST` | 是（客户端） | 指定出站邮件的邮件服务器 |

### OSTYPE 宏

`OSTYPE` 文件封装了各种特定于厂商的信息，例如邮件相关文件的预期位置、`sendmail` 需要的命令路径、以及在 `OSTYPE` 文件中定义的标记。^10

10 那么 `OSTYPE` 宏定义在哪里呢？在 `/cfm4` 目录下的文件中，当你运行 `Build` 时，该文件会被神奇地置于你的配置文件之前。

### virtuertable 功能

`virtuertable` 功能支持入站邮件的域名别名（domain aliasing）。该功能允许在单台机器上托管多个虚拟域名，常用于虚拟托管站点。该表的关键字段包含电子邮件地址（`user@host.domain`）或域名规范（`@domain`）。其值是本地或外部电子邮件地址。如果键是域名，则该值可以通过变量 `%1` 传递用户字段，或者将邮件路由到不同的用户。以下是一些示例：

```
@registeredatrust.com
unix@book.admin.com
linux@book.admin.com
webmaster@example.com
info@testdomain.net
%1@atrust.com
sa-book-authors@atrust.com
sa-book-authors@atrust.com
billy.j.zakowski@colorado.edu
ausename@hotmail.com
```

域名映射左侧的所有主机必须列在 `cw` 文件、`/etc/local-host-names` 中，或者包含在 `VIRTUSER_DOMAIN` 列表中。如果没有列出，`sendmail` 将不会在本地接收邮件，并会尝试在互联网上查找目标主机。但 DNS MX 记录会将 `sendmail` 送回这台服务器，你会在生成的退信邮件中收到“local configuration error”（本地配置错误）。遗憾的是，`sendmail` 无法判断此实例错误应该是“`cw` 文件中不存在 `virtuertable` 功能”。
