## 头文件

依赖关系可以在任何类型的文件之间建立，而不仅仅是源代码和目标代码文件。例如，你可以在目标代码文件和 C 程序中所谓的“头文件”之间建立依赖关系。头文件是一个包含源代码段的文本文件，这些代码段会被你的编译器插入到你的主源代码文件中。它们成为了程序的实际组成部分。在这方面，目标代码文件可能不仅依赖于源代码文件，还依赖于特定的头文件。按照惯例，头文件的文件名都带有 `.h` 扩展名。在下一个 makefile 示例中，`types.h` 头文件和 `main.c` 源代码文件都被用于创建 `main.o` 文件。`main.c` 中的一条 `include` 指令指示编译器将 `types.h` 中的函数声明作为 `main.c` 源代码的一部分包含进来。`main.c` 和 `types.h` 现在都被用于创建 `main.o` 文件。如果你对 `types.h` 文件进行了更改，你希望 `make` 生成一个新的 `main.o` 文件。为了实现这一点，你需要将 `types.h` 作为依赖文件放置在 `main.o` 的依赖行中。如果 `main.c` 或 `types.h` 头文件有任何更改，那么 `main.c` 将被重新编译。

## 隐式 make 依赖

`make` 工具有一组隐式依赖关系，它会自动将其应用于源代码和目标代码文件。在 Linux 中，任何给定编程语言的源代码文件必须包含特定的后缀。C 源代码文件需要 `.c` 后缀。Fortran 文件需要 `.f` 后缀。`.s` 用于汇编源代码文件。`make` 将检查依赖列表中与目标代码对应的源代码文件，并自动为该源代码文件调用相应的编译器。这意味着，通过使用隐式依赖，你可以省去编译源代码文件的依赖行。然后你就可以将你的 makefile 简化为一条 Linux 命令：链接文件的命令。

`make` 究竟如何实现隐式依赖，将在稍后在检查后缀规则时讨论。通过使用此类规则，你将学习如何创建自己的隐式依赖。目前，只需要知道如果你想做的话，可以大幅减少 makefile 中依赖行的数量这就足够了。

在下一个示例中，通过依赖隐式依赖，`bookrec` 程序的 makefile 减少到了两个依赖行。在检查 `bookrec` 依赖行的依赖项项列表时，`make` 将在当前目录下查找对应的源代码文件。它将找到 `main.c` 和 `io.c`。由于这些文件具有 `.c` 扩展名，依赖行将识别它们为 C 源代码，并在必要时调用 `gcc` 编译器。假设用户最近修改了 `io.c`。那么 `make` 将知道使用 C 编译器 `gcc -c` 来编译 `io.c`。

## 使用目标参数指定依赖行

假设你想使用 `make` 为你执行一个特定的 Linux 命令。例如，假设你想使用 `make` 来执行 Linux 命令来打印你所有的源代码文件。你不需要在每次想要打印时都从命令行中输入所有文件的名称，可以让 `make` 为你做。记住，依赖行中的 Linux 命令可以是任何 Linux 命令，而不仅仅是 `gcc` 编译器命令。你可以输入一条 Linux 命令为 `lpr` 命令以打印文件的依赖行。

那么你将把你的 makefile 用于两个完全不同的目的：编译程序和打印文件。你将会有用于编译程序的依赖行，以及另一条用于打印文件的依赖行。然而，用于编译的依赖行都是相互依赖的，而打印的那个将独立于任何其他行。你可以在命令行上指定任何目标。例如，你可以在命令行上显式指定 `main.o` 为目标。这样 `make` 将只执行 `main.o` 依赖行，检查是否应该编译 `main.c` 文件。注意到对于这个 makefile，直接输入 `make` 和带 `bookrec` 参数的效果相同。`bookrec` 是文件中第一个依赖行的目标，因此也是默认目标。

下载软件常用的 `make` 参数是 `install` 参数。通常 makefile 用于编译程序然后将其安装到系统目录中。要编译，你只需要输入 `make` 命令。要安装，你应该输入带 `install` 目标的 `make`。

```
bookrec : main.o io.o
gcc main.o io.o -o bookrec
```

`main.o: types.h`

```
print :
lpr main.c io.c
```
