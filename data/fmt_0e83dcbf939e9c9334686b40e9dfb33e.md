
`event_handlers[event] = f`

`return f`

`return register_function`

装饰器也可以应用于类定义。例如：

```python
@foo
class Bar(object):
    def __init__(self,x):
        self.x = x
    def spam(self):
        statements
```

对于装饰器，你应该始终让装饰器函数返回一个类对象作为结果。期望与原始类定义一起工作的代码可能会通过 `Bar.spam` 引用类的成员。如果装饰器函数 `foo()` 返回的是一个函数，这将无法正常工作。

装饰器可能与与其他方面（如递归、文档字符串和函数属性）产生奇怪的交互。这些问题将在本章稍后部分描述。

# 生成器与 yield

如果一个函数使用了 `yield` 关键字，它就定义了一个名为生成器（generator）的对象。生成器是一个产生值序列以供迭代的函数。这里有一个示例：

```python
def countdown(n):
    print("Counting down from %d" % n)
    while n > 0:
        yield n
        n -= 1
    return
```

如果你调用这个函数，你会发现它的任何代码都没有开始执行。
示例：

```python
>>> c = countdown(10)
>>>
```

相反，生成器是一个对象。生成器对象在每当调用 `next()`（或 Python 3 中的 `__next__`）时都会执行该函数。这里有一个示例：

```python
>>> c.next()  # 在 Python 3 中使用 c.__next__()
Counting down from 10
>>> c.next()
9
```

当 `next()` 被调用时，生成器函数会执行语句直到遇到 `yield` 语句。`yield` 语句产生一个结果，此时函数的执行会停止，直到下一次调用 `next()`。然后执行将从 `yield` 语句处继续。

你通常不会直接在生成器上调用 `next()`，但你可以将其用于语句、`sum()` 函数或其他某些消耗序列的操作。例如：

```python
for n in countdown(10):
    statements
a = sum(countdown(10))
```

生成器通过返回或抛出 `StopIteration` 异常来信号完成，在此时，生成器在完成时返回除一个以外的任何值都是非法的。

生成器的一个微妙问题出现在生成器函数只被部分消费的情况下。例如，考虑以下内容：

```python
for n in countdown(10):
    if n == 2: break
    statements
```

在这个示例中，`for` 循环通过调用 `break` 终止，相关的生成器从未运行完成。这个生成器有一个 `close()` 方法，用于发送关闭信号。当生成器不再被使用或被删除时，通常会调用 `close()`。没有必要调用 `close()`，你也可以像这里这样手动调用：

```python
>>> c = countdown(10)
>>> c.next()
Counting down from 10
10
>>> c.next()
9
>>> c.close()
Traceback (most recent call last):
  File "stdin", line 1, in <module>
StopIteration
```

在生成器函数内部，`close()` 通过在 `yield` 语句发生 `GeneratorExit` 异常来信号。你可以选择地捕获此异常以执行清理工作。

```python
def countdown(n):
    print("Counting down from %d" % n)
    try:
        while n > 0:
            yield n
            n = n - 1
    except GeneratorExit:
        print("Only made it to %d" % n)
```

虽然可以捕获 `GeneratorExit`，但生成器函数处理该异常并使用 `yield` 产生另一个输出值是非法的。此外，如果程序正在迭代生成器，你不应该从另一个执行线程或信号处理程序程序异步地对该生成器调用 `close()`。

# 协程与 yield 表达式

在函数内部，`yield` 语句也可以被用作一个出现在赋值运算符右侧的表达式。例如：

```python
def receiver():
    print("Ready to receive")
    while True:
        n = (yield)
        print("Got %s" % n)
```

像这样使用 `yield` 的函数被称为协程（coroutine），它响应发送给它的值而执行。它的行为与生成器非常相似。例如：

```python
>>> r = receiver()
>>> r.next() # 推进到第一个 yield (Python 3 中为 r.__next__)
Ready to receive
>>> r.send(1)
Got 1
>>> r.send(2)
Got 2
```

首次对协程调用 `next()` 的要求很容易被忽略，是错误的来源。因此，建议使用装饰器包装协程来处理这个问题。

```python
def coroutine(func):
    def start(*args,*kwargs):
        g = func(*args,*kwargs)
        g.next()
        return g
    return start
```

使用此装饰器，你可以这样写：

```python
@coroutine
def receiver():
    print("Ready to receive")
    while True:
        n = (yield)
        print("%s" % n)
```

## 使用示例

`r = receiver()`

`r.send("Hello World")` # 注意：不需要初始 next()

协程通常会无限运行，除非显式关闭或自行退出。要关闭输入流，请使用 `close()` 方法：

```python
>>> r.close()
>>> r.send(4)
Traceback (most recent call last):
  File "stdin", line 1, in <module>
StopIteration
```

一旦关闭，如果向协程发送值，将抛出 `StopIteration` 异常。`close()` 操作会在上一节讨论的生成器协程内部抛出 `GeneratorExit`。例如：

```python
def receiver():
    print("Ready to receive")
    try:
        while True:
            n = (yield)
            print("%s" % n)
    except GeneratorExit:
        print("Receiver done")
```

可以使用 `throw(exctype, [value, tb])` 方法在协程内部引发异常，其中 `exctype` 是异常类型，`value` 是异常值，`tb` 是回溯对象。例如：

```python
>>> r.throw(RuntimeError("You're hosted!"))
Traceback (most recent call last):
  File "stdin", line 1, in <module>
  File "<stdin", line 4, in receiver
RuntimeError: You're hosted!
```

引发的异常将在协程当前执行的 `yield` 状态显。协程可以捕获异常并妥善处理。使用 `throw()` 作为协程的异步信号是不安全的——它不应该从另一个线程或在处理程序中调用。

如果在 `yield` 表达式中提供了值，协程可以利用 `yield` 同时接收和返回值。这里有一个说明此点的的示例：

```python
def splitter(delimiter=None):
    print("Ready to split")
    result = None
    while True:
        line = (yield)
```
