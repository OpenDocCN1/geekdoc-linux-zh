## 8.14 sysinfo: 获取系统统计信息

`sysinfo` 调用填充一个系统统计信息的结构体。它唯一的参数是指向 `struct sysinfo` 对象的指针。`struct sysinfo` 中填充的这些有趣的字段之一：

- `totalram`—总可用物理内存

- `freer`—空闲物理内存

- `procs`—系统上的进程数量

查看 `sysinfo` man 手页以获取 `struct sysinfo` 的完整描述。如果你使用 `sysinfo`，请包含 `<linux/kernel.h>`、`<linux/sys.h>` 和 `<sys/sysinfo.h>`。

### 8.12 (sysinfo.c) 打印系统统计

```c
#include <linux/kernel.h>
#include <linux/sys.h>
#include <stdio.h>
#include <sys/sysinfo.h>

int main ()
{
    /* 转换常量 */
    const long minute = 60;
    const long hour = minute * 60;
    const long day = hour * 24;
    const double megabyte = 1024 * 1024;
    /* 获取系统统计信息 */
    struct sysinfo si;
    sysinfo(&si);
    /* 总结有趣的值 */

    printf("total RAM : %5d MB\n", si.totalram / megabyte);

    printf("process count : %d\n", si.procs);
    return 0;
}
```

## 第9章 内联汇编代码

注意，与普通的操作数不同，`asm` 语句允许你使用 C 语法指定输入和输出操作数。

要了解 x86 指令集（我们将在本中使用），请参见 http://developer.intel.com/design/pentiumii/manuals/ 和 http://www.x86-64.org/documentation。

### 9.1 何时使用汇编代码

尽管 `asm` 语句可能会被滥用，但它们允许程序直接访问硬件，并产生执行快速的程序。在编写需要直接与硬件交互的系统代码时，可以使用它们。例如，`/usr/include/asm/io.h` 包含了访问输入输出端口的汇编指令。Linux 源代码 `/usr/src/linux/arch/i386/kernel/process.s` 提供了另一个示例，也出现在空循环代码中。其他 Linux 源代码文件位于 `/usr/src/linux/arch/` 和 `/usr/src/linux/drivers`。

汇编指令还可以加速计算机程序的最内层循环。例如，如果你的程序运行的大部分时间都在计算相同角度的正弦和余弦，那么这个内层循环可以使用 `fsinos` x86 指令进行重编码。参见例如 `/usr/include/bits/mathline.h`，它封装成了一些内联汇编序列，用于加速超越超越函数的计算。

你应该只在作为最后手段时才使用内联汇编来加速代码。目前的编译器非常复杂，对于它们所生成代码的处理器细节了如指掌。编译器通常可以选择某些看似不直观或迂回、但执行速度可能比其他指令序列更快的代码序列。除非你非常了解处理器的指令集和调度属性，否则让编译器的优化器为你的大多数操作生成汇编代码可能更好。

偶尔，一或两条汇编指令可以替换几行高层语言代码。例如，使用 C 语言确定一个非零整数的最高非零位的位置需要循环或浮点数计算。许多架构（包括 x86）都有一条汇编指令（`bsr`）来计算该位（bit position）。我们将在第 9.4 节演示其中之一。

- 算法或数据结构的变化可能比使用汇编指令在减少程序运行时间方面更有效。

#### 9.2.1 将 asm 转换为汇编指令

GCC 对 `asm` 语句的处理非常简单。它产生汇编指令来处理 `asm` 的操作数，并用你指定的指令替换 `asm` 语句。GCC 不对指令进行任何形式的分析。

例如，GCC 转换了这段程序代码：

```
double foo, bar;
asm ("mycool_asm %%1, %%0" : "r" (bar) : "r" (foo));
```

转换为这些 x86 汇编指令：

```assembly
mov -8(%ebp),%edx
mov -4(%ebp),%ecx

#APP
mycool_asm %edx,%edx
#NO_APP
mov %edx,-16(%ebp)
mov %edx,-12(%ebp)
```

记住 `foo` 和 `bar` 在 32 位 x86 架构上各需要两个字的栈存储空间。寄存器 `ebp` 指向栈上的数据。

前两条指令将 `foo` 复制到 `EDX` 和 `ECX` 寄存器，`mycool_asm` 在其上操作。编译器使用相同的寄存器存储答案，最后两条指令将其复制到 `bar`。它选择合适的寄存器，甚至复用相同的寄存器，并自动在适当的位置之间进行复制。

### 9.3 扩展汇编语法

在接下来的节中，我们描述了 `asm` 语句的语法规则。它们的区域由冒号分隔。

我们将引用这个说明性的 `asm` 语句，它计算布尔表达式 `x > y`：

```c
asm ("fucomop %%st(1), %%set%%al"\n "%a" = (result) : "u" (y) : "x" (x) : "cc", "st");
```

首先，`fucomop` 比较它的操作数 `x` 和 `y`，并将指示结果的值存入条件寄存器。然后 `set` 将这些值转换为 0 或 1 的结果。

#### 9.3.1 汇编指令

第一部分包含封装在引号内的汇编指令。示例包含两个汇编指令，`fucomop` 和 `set`，用分号分隔。如果汇编器不允许使用分号，请使用换行符 (`\n`)。

第一部分包含封装在引号内的汇编指令。示例包含两个汇编指令，`fucomop` 和 `set`，用分号分隔。如果汇编器不允许使用分号，请使用换行符 (`\n`)。

第四部分指示指令改变了条件寄存器 `cc` 的值。

#### 9.3.2 输出

第二部分使用 C 语法指定指令的输出。每个操作数由一个约束字符串和一个 C 表达式指定。对于输出操作数（必须是左值），约束字符串应等号开头。

指定特定架构寄存器的字母可以在 GCC 源代码中找到。表 9.1 总结了这些内容。

要指示一个值从同一个 `asm` 中读取并写入，请使用输出操作数编号作为输入约束。例如，要指示输入寄存器与第一个输出寄存器编号相同，使用 `%0`。输出操作数从左到右编号，从 0 开始。仅仅为输出操作数和输入操作数指定 C 表达式并不能保证这两个值被放在同一个寄存器中。

如果没有输入操作数且后续部分为空，则可以省略此输入部分。

## 第 9 章 内联汇编代码

### 9.3.4 Clobbers（破坏寄存器）

如果一条指令作为副作用修改了一个或多个寄存器的值，请在 asm 的第四部分指定被破坏的寄存器。例如，`fucop` 指令会修改状态码寄存器，用 `ec` 表示。用逗号分隔被破坏的寄存器字符串。如果指令修改了任意内存位置，请指定 `memory`。通过使用破坏信息，编译器可以确定在 asm 执行后哪些寄存器必须重新加载值。如果你没有正确地指定这些信息，GCC 可能会错误地假设寄存器仍然包含实际上已被覆盖的值，这将会影响你程序的正确性。

### 9.4 示例

x86 架构包含了用于确定字中最低有效位（LSB）和最高有效位（MSB）位置的指令。处理器可以非常高效地执行这些指令。相比之下，在 C 中实现相同的操作需要一个循环和位位移。

例如，`bsr` 汇编指令计算其第一个操作数中最高位的位置，并将位位置（从 0 开始计数，即最低位）放入其第二个操作数中。为了获取数字的位置，我们可以使用以下 asm：

```asm
asm ("bsr %%1, %%0" : "r" (position) : "r" (number));
```

在 C 中实现相同操作的一种方法是使用这个循环：

```c
long i;
for (i = (number >> 1), position = 0; i >= 1; ++position)
    ;
```

#### 列表 9.1 (bit-pos-loop.c) 使用循环查找位位置

```c
#include <stdio.h>
#include <stdlib.h>

int main (int argc, char * argv[])
{
	long max = atoi(argv[1]);
	long number;
long i;
unsigned position;
volatile unsigned result;

/* 对大量值重复该操作。 */
for (number = 1; number <= max; ++number) {
    /* 重复地向右移位数字，直到结果为
    零。记录所需的移位次数。 */
    for (i = (number >> 1), position = 0; i != 0; ++position)
        i >>= 1;
    /* 设置的最高位的位置就是我们在第一次
        移位后所需的次数。 */
    result = position;
}

return 0;
```

#### 列表 9.2 (bit-pos-asm.c) 使用 bsr 查找位位置


### 9.5 优化问题

GCC 优化器尝试重新排列和重写程序代码，即使在存在 asm 的情况下也能最小化执行时间。如果优化器确定 asm 的输出值未被使用，除非 asm 及其参数之间出现 `volatile`，否则该指令将被省略。（作为一种特殊情况，GCC 不会将将没有输出的 asm 移动到循环之外。）任何 asm 都可以以难以预测的方式移动，甚至跨越跳转。保证特定 asm 不移动的唯一方法是限制优化器的效能，因为编译器不知道 asm 的语义。GCC 被迫做出保守的猜测，这可能会阻止某些优化。买者自负！

### 9.6 维护与可移植性问题

如果你决定使用不可移植的、依赖架构的 asm 语句，将这些语句封装在宏或函数中有助于维护和移植。将所有宏放在一个文件中并对其进行文档说明，将简化向不同架构的移植工作，这种情况即使对于“丢弃型”程序也发生得频繁。因此，程序员只需要为不同的架构重写一个文件。

Linux 源代码中的大多数 asm 语句被分组在 `/usr/src/linux/include/asm` 和 `/usr/src/linux/include/i386` 头文件，以及 `/usr/src/linux/arch/i386/` 和 `/usr/src/linux/drivers/` 源文件中。

## 10 安全

GNU/Linux 系统的强大很大来自于其对多用户和网络的支持。许多人可以同时使用系统，并且可以从远程位置连接到系统。不幸的是，这种力量也带来了风险，特别是对于连接到互联网的系统。在某些情况下，远程“黑客”可以连接到系统并读取、修改或删除存储在机器上的文件。或者，同一台机器上的两个用户在不应该被允许的情况下读取、修改或删除对方的文件。当这种情况发生时，就认为系统的安全性被破坏了。

Linux 内核提供了各种设施来确保这些事件不会发生。例如，假设你正在开发会计软件。虽然你可能希望所有用户都能向系统提交费用报告，但你并不希望所有用户都能批准这些报告。你可能希望用户能够查看自己的薪资信息，但你绝对不希望他们查看每个人的薪资信息。你可能希望经理能够查看他们部门员工的薪资，但你并不希望他们查看其他部门员工的薪资。

为了实施这类控制，你必须非常小心。犯一个允许用户执行不该操作的错误是极其容易的。每个开发者都应该理解这些。

### 10.1 用户与组

每个 Linux 用户都被分配一个唯一的数字，称为用户 ID（UID）。当你登录时，你使用的是用户名而不是用户 ID。不过，对于系统来说，只有用户 ID 才有效。一个用户 ID 实际上可以对应多个用户名。

你可以通过关联特定的用户 ID 来控制文件或其他资源的访问。只有该用户 ID 的用户才能访问资源。例如，你可以创建一个可以读取或创建新文件的目录。这对于许多简单情况足够了。
