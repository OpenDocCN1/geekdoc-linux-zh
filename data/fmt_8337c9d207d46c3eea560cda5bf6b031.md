
# 自动挂载器的优势

自动挂载器有几个明显的优势。它将 `NFS` 挂载最小化，直到实际需要为止，这可以防止大量 `NFS` 客户端同时重启时发生挂载风暴。它还会在指定时间后卸载未使用的文件系统。这有助于管理员在服务器之间移动数据，减少减少对客户端工作站上运行进程的干扰。最后，自动挂载器会处理每个新的挂载请求，因此可以进行动态更改，且新的映射将在下一个文件系统挂载时生效。然而，如果自动挂载器崩溃或遇到严重的 `Bug`，系统可能需要重启以解决产生的问题。这种情况发生非常罕见，因此几乎没有不使用自动挂载器的理由。

## 自动挂载器类型

`UNIX` 用户可以使用两种口味的自动挂载器（也称为 `aututils`）和 `autofs`。

- **自动挂载器 (`aututils`)**：使用一种较旧的技术来管理挂载。自动挂载器无法直接挂载到挂载点指示的位置；相反，在挂载点放置一个符号链接，指向执行所有自动挂载的替代位置。该目录通常指定为 `/a`，但可以在命令行上指定另一个位置，并已移植到许多平台，在共享单组映射的异构环境中可能是最佳选择。

- **`autofs`**：是一个更现代的实现，并且并不烦人。它是作为文件系统实现的，因此没有那些烦人的链接。因此，自动挂载的文件完全如 `autofs` 映射所示。此外，`autofs` 映射的格式更简单、更易维护。如果选择同时支持自动挂载器和 `autofs` 自动挂载器，我们建议通过程序生成一组映射。作者使用名为 `automap` 的工具从 `autofs` 生成这种风格的映射。每个挂载点都需要自动挂载器。`autofs` 映射的格式如下：

`key source`

`options` 字段可以为空。一个典型的主目录可能像这样：

```
steve, hard,intr /vol1
lisa, hard,intr /vol2
bob, hard,intr /vol3
janet, hard,intr /vol4
batch, hard,intr /vol5
```

每行末尾的 `&` 是映射替换的示例，键本身会被替换为 `&`。关于 `autofs` 映射语法的更完整描述可以在 `autofs(5)` 手页中找到。

## 管理访问控制

`NFS` 环境中的另一个问题是访问控制的管理。导出可写文件系统以便任何主机访问存在安全风险。然而，遍历组织中的每个 `NFS` 客户端可能是不可行的。可以授予一组客户端 `NFS` 权限以简化管理。

- **通配符机制**：第一种机制是使用通配符。如果一组机器的所有机器（没有其他机器）位于同一个 `DNS` 域，可以使用通配符来指定它们。例如，`exports` 条目允许 `subdomain.domain` 中的所有系统访问 `work/project2`：

```
/work/project2 *.subdomain.domain
```

- **网络组机制**：在有 `NIS` 的地方，也可以使用网络组指定访问列表。以下 `/etc/exports` 条目允许 `NIS` 网络 `myhosts` 访问 `/work/project3` 层次：

```
/work/project3 @myhosts
```

## 用户 ID 映射

`N` 内置的安全机制（可能是唯一有效的机制）是将 `root` 映射到用户级。通常，`root` 被映射为值为 `-2` (`65534`) 的用户 `nobody`。除非指定了 `no_root_squash` 选项，否则这就是默认行为。

额外的选项提供了很大的活性：

- `anonid` 选项可设置匿名用户和组 ID，这可能有助于与其他 `UNIX` 系统保持兼容性。
- `squash_all` 选项可强制所有用户和组使用匿名值。
- `squash_g` 选项允许指定 `uid` 或 `gid` 列表进行重映射，而不只是 `uid/gid 0`。

这些选项可以通过有选择地移除对公共共享区域的访问来提供安全性。您还可以使用这些设施管理来自 `PC/NFS` 的访问，它是 `Microsoft Windows` 操作系统的 `NFS` 实现。为运行 `Microsoft Windows` way系统的 PC 提供文件服务的更好解决方案是 `samba(8)`，它在第 17 章“网络服务”中有讨论。

# NFS 服务进程

`NFS` 的服务器端也基于 `RPC`，因此端口映射器（`port mapper`）必须在每台服务器上运行。此外，还需要用户级进程：

- `rpc.statd` 支持 `NFS` 锁管理器。
- `rpc.quota` 处理 `NFS` 磁盘配额。
- `rpc.mount` 处理 `NFS` 挂载请求。
- `rpc.nfsd` 通知内核启动 `NFS` 请求。

这些进程在系统启动时由 `/etc/rc.d/nfs` 脚本启动。该脚本通过几个实用的选项方便即时管理：`start`, `stop`, `status`, `restart` 和 `reload`。

## NFS 与文件锁定

`Linux` 内核通过 `rpc.statd` 支持 `NFS` 文件锁定。请注意，对锁的支持一直是脆弱的，可能无法通过生产环境的严苛测试。这些问题是设计上的缺陷，可能无法解决。如果需要 `NFS` 文件锁定，可以尝试一下。它在简单情况和低流量场景下运行良好。如果出现问题，请尝试其他解决方案。

# NFS 无状态模型

`NFS` 设计背的核心概念是它是（大部分）无状态的、可重启的。这种方法的主要优点是没有复杂的重启和恢复协议。其缺点是，当服务器崩溃或不可用时，进程将阻塞在等待状态（参见 `ps(1)` 手页），并且对信号没有响应。当 `NFS` 服务器恢复后，系统调用将正常完成（下文所述的异常除外），进程将从上次停止的地方继续。如果系统管理员或用户一直尝试杀死这些进程，信号将在问题解决后才收到！一旦管理员熟悉了这种行为模型，只需在 `NFS` 服务器或网络恢复之前简单地采取任何操作，就可以避免许多悲剧。

有两个挂载选项可以修改这种行为：

1. 第一个选项是关键字 `soft`，它会导致 `NFS` 文件操作在主超时后返回失败错误代码。主超时发生在重试失败之后。默认情况下，该数值为 `3`，但可以作为挂载选项指定。使用 `soft` 挂载选项时应极度谨慎，因为它可能导致数据丢失。
2. 第二个挂载选项是关键字 `intr`，它允许在主超时期间接收信号。`intr` 要好得多，因为它允许系统管理员决定是否需要干预，而不是自动返回错误。这些选项以及许多其他选项记录在 `nfs(5)` 手页中。

如果 `NFS` 服务器已丢失数据或将关闭很长时间，则需要更激进的方法。具体做法取决于用户社区可以忍的故障时长以及环境的应急预案。

- `1. 2.0`（及更早）内核不支持 `NFS` 文件锁定。

## 调试技术与分析工具

文件或文件系统丢失的用户将由于 `NFS` 文件句柄（`file handles`）遇到错误。

- **过期文件句柄（Stale filehandles）**：当客户端打开的文件或目录在服务器上不再可用时，就会发生。服务器将这些文件描述符标记为无效，客户端机器上引用它们的进程将以 `ESTALE` 错误代码失败（系统错误代码请参见 `errno(3)` 和 `/usr/include/asm/errno.h`）。过期文件还可能包括在同一目录下读取和删除文件的多个客户端。

`NFS` 并没有通过对删除的文件进行特殊处理来隐藏其无状态特性的这一面。文件删除操作被转换为重命名操作，从而在用户的主目录中创建 `.xxxxx` 文件。这允许客户端程序打开文件、删除它们（实际上是 `unlink(2)` 它们），并继续对其进行读写。当进程退出时，`.nxxxxx` 文件会被删除。这模拟了本地文件系统的语义，即操作系统对打开的文件进行引用计数。

当 `NFS` 出现问题时常见的消息是：

```
NFS server xxx not responding, still trying
```

这在服务器没有在挂载选项中 `retrans` 参数指定的重试次数内响应客户端时就会发生。该值在大多数系统上默认认为 `3`。如果此消息重复多次，说明服务器或网络发生了硬故障。然而，如果用户看到此消息之间交替出现：

```
NFS server xxx Ok
```

要么是服务器过载，要么是网络丢包。

### 诊断步骤

要诊断 `NFS` 服务器问题，首先开始收集一些基本信息：

- 服务器是否正常？
- 如果正常，服务器是否接受登录？
- `rpcinfo servername` 是否表明 `portmapper` 和 `rpc` 服务正常？
- 是所有客户端，还是仅是一部分？

首要任务是确定问题是出在服务器还是网络。对 `NFS` 问题的诊断通常直接导致网络调试。例如，如果系统管理员发现所有受影响的客户端都在同一个 `IP` 子网内，而所有其他客户端都正常，那么调试重心将立即转向网络。

在挂载文件系统时遇到的问题通常可以通过简单的方法解决。如果挂载挂起，使用 `ping` 验证服务器是否可以访问。如果可以访问，尝试 `rpcinfo -p xxxx`，其中 `xxxx` 是服务器名称。应该会出现 `nfs` 和 `mount` 端口。

如果挂载因 `permission denied` 错误消息失败，那么是时候检查 `/etc/exports` 文件并确定相关挂载项是否存在问题。输出反映了服务器导出的内容以及导出选项。如果导出项存在明显问题，编辑 `/etc/exports` 文件并使用 `exports -a` 命令重新导出所有文件系统。另一方面，如果输出看起来良好，那么也许是底层数据存在问题。例如，考虑以下通配符导出语句：

```
/ (rw,root)
```
