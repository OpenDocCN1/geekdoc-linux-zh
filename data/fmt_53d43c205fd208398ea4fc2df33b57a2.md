### 3.1.1 确保检查系统以确定 `IPv6` 是否启用

（手动）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

描述：

`Internet` 协议第 6 (`IPv6`) 是 `Internet` 协议 (`IP`) 的最新版本。它的设计用于提供 `IP` 地址和额外的安全性，以支持预测的连接设备增长。`IPv6` 基于 128 位寻址，可以支持 340 京（即 340 万亿）地址。

`IPv6` 的特性：

- 分级寻址和路由基础设施
- 有状态和无状态的配置
- 支持服务质量 (`QoS`)
- 邻接节点交互的理想协议

原理：

`IETF RFC 4038` 建议在构建应用时假设支持双栈环境。建议根据基准（`Benchmark`）的建议启用并配置 `IPv6`。

如果您的环境中没有使用双栈和 `IPv6`，则可以禁用 `IPv6` 以减少系统的攻击面，并跳过有关 `IPv6` 的建议。

影响：

`IETF RFC 4038` 建议在构建应用时假设支持双栈环境。在系统上禁用 `IPv6` 可能会导致某些应用程序失败或出现意外行为。

审计：

运行以下脚本以验证系统上的 `IPv6` 状态：

```bash
#!/usr/bin/env bash
{
  output=""
  grubfile=$(find /boot -type f -name 'grubenv' -o -name 'grub.conf' -o -name 'grub.cfg' / -exec grep -P Pl -- '^\*\(kernelopts=\[linux|kernel]\)' {} \;)
  searchloop=/etc/sysctl.d/*.conf /etc/sysctl.d/*.conf /usr/local/lib/sysctl.d/*.conf /usr/lib/sysctl.d/*.conf /lib/sysctl.d/*.conf
  /etc/sysctl.conf

  if [ -n "$grubfile" ]; then
    grep -P Pl '^\*\(kernelopts=\[linux|kernel]\)' "$grubfile" | grep -q "ipv6.disable=1" && output="ipv6 disabled"
  fi

  for file in $searchloop; do
    if [ -f "$file" ]; then
      if grep -q "ipv6.conf.all.disable_ipv6=1" "$file" || grep -q "ipv6.conf.default.disable_ipv6=1" "$file"; then
        output="ipv6 disabled"
      fi
    fi
  done

  if [ -n "$output" ]; then
    echo "$output"
  else
    echo "ipv6 enabled"
  fi
}
```

修复：

建议根据基准建议启用并配置 `IPv6`。如果需要禁用 `IPv6`，请使用以下方法之一：

通过 `GRUB`：

编辑 `/etc/default/grub`，在 `GRUB_CMDLINE_LINUX` 中添加 `ipv6.disable=1`。

运行以下命令更新 `grub`：

```bash
# update-grub
```

通过 `sysctl`：

在 `/etc/sysctl.conf` 或 `/etc/sysctl.d/` 中设置以下参数：

示例：

```bash
# sysctl -w net.ipv6.conf.all.disable_ipv6=1
# sysctl -w net.ipv6.conf.default.disable_ipv6=1
# sysctl -w net.ipv6.conf.lo.disable=1
```

或者，创建文件 `/etc/sysctl.d/60-disable-ipv6.conf`：

```bash
net.ipv6.conf.all.disable_ipv6 = 1
net.ipv6.conf.default.disable_ipv6 = 1
net.ipv6.conf.route.disable = 1
```

默认值：

`IPv6` 已启用

额外信息：

随着设备的扩展，拥有更多地址变得越来越重要。`IPv6` 为全球每个网络设备提供了足够的唯一 `IP` 地址，帮助提供商跟上 `IP` 设备的激增。

修复：

运行以下脚本禁用任何无线接口：

```bash
#!/bin/bash

if command -v nmcli >/dev/null 2>&1 ; then
  nmcli radio all off
else
  if [ -n "$(find /sys/class/network/* -type d -name wireless)" ]; then
    mname=$(find driverdir in $(find /sys/class/network/* -type d -name wireless) | xargs -n0 -I {} basename "{}");
    readlink -f "$driverdir/device/module" | sort -u
    for dm in $mname; do
      echo "install $dm/true" >> /etc/modprobe.d/disable_wireless.conf
    done
  fi
fi
```

### 3.1.3 确保 `DCCP` 已禁用（自动化）

配置适用性：

- Level 2 - 服务器
- Level 2 - 工作站

描述：

数据报拥塞控制协议 (`DCCP`) 是一种支持流媒体和电话的传输层协议。`DCCP` 提供了一种获取拥塞控制的方法，而无需在应用层进行，但它不提供顺序交付。

原理：

如果不需要该协议，建议不要安装驱动程序以减少潜在的攻击面。

审计：

运行脚本验证 `dcp` 是否已禁用：

```bash
#!/usr/bin/env bash
{
  l_output="" output2=""
  l_lname="dcp" # 设置模块名
  # 检查模块是否存在于系统
  if [ -z "$(modprobe -n v \$l_lname 2>&1 | grep -Pi --\h\\$modprobe\\h+FATAL\\h+Module\\h$l_lname\\h+not\\found\\h+in\\h+directory)" ]; then
    # 检查模块是否可以加载
    l_loadable="$(modprobe -n v \$l_lname)"
    if [ "$(wc -l) -eq "\$l_loadable" -gt 1 && \$l_loadable=$(grep -P --\h\\install\\b\\l_lname\\b) <<< "\$l_loadable") ]; then
      l_output="$l_output\n module: \$l_lname\" is not loadable;
      \$l_loadable=""
    else
      l_output2="$output2\n module: \$l_lname\" is loadable;
      \$l_lname=""
    fi
    # 检查模块当前是否已加载
    if ! lsmod | grep "$l_lname" > /dev/null 2>&1; then
      l_output="$l_output\n module: \$l_lname\" is not loaded
    else
      l_output2="$output2\n module: \$l_lname\" is loaded
    fi
    # 检查模块是否在黑名单中
    if modprobe --config -Pq "^\\hblacklist\\h+tr '-' '_') <<< "\$l_lname")"; then
      l_output="$l_output\n module: \$l_lname\" is denied;
      if [ $(grep -P "^\\hblacklist\\h$l_lname\\b") /etc/modprobe.d/"* ]; then
        l_output2="$output2\n module: \$l_lname\" is not denied;
      else
        l_output="$l_output\n Module - \$l_lname\" doesn't exist on system"
      fi
      # 报告结果。如果没有失败输出，则通过
      if [ -z "\n- Audit Result:\n" ]; then
        echo -e "\n- Audit Result:\n ** PASS **\n$l_output\n"
      else
        echo -e "\n- Audit Result:\n ** FAIL **\n - 原因:\n$l_output2\n"
        [ -n "$l_output" ] && echo -e "\n- Correct:\n$l_output\n"
      fi
  fi
}
```

修复：

运行以下脚本禁用 `dcc`：

```bash
#!/usr/bin/env bash
{
  lname="dcc" # 设置模块名
  # 检查模块是否存在于系统
  if [ -z "$(modprobe -n v \$lname 2>&1 | grep -Pi --\hFATAL\\hModule\\hnot\\found\\hin\\directory)" ]; then
    # 修复可加载状态
    l_loadable=$(modprobe -n v \$lname)
    if [ "$(wc -c "\$l_loadable")" -gt 1 && l_loadable=$(grep -Pq "^\hinstall\b\$lname") <<< "\$l_loadable"; then
      if grep -F lname; then
        echo -e " - \$lname to not loadable"
        echo -e "install \$lname/false"
        /etc/modprobe.d/$lname.conf
      fi
    # 修复已加载状态
    if lsmod | grep "\$lname" >/dev/null 2>&1; then
      echo -e " - unloading module \$lname"
      modprobe -r "\$lname"
    fi
    # 修复黑名单
    if modprobe --show | grep -Pq "^blacklist+\$(tr ' ' '-') <<< \$lname"; then
      echo -e " - denying \$lname"
      echo -e " - blacklist \$lname" >> /etc/modprobe.d/$lname.conf
    else
      echo -e " - Nothing to remediate\n Module \$lname doesn't exist on system"
    fi
}
```

### 3.1.4 确保 `SCTP` 已禁用（自动化）

配置适用性：

- Level 2 - 服务器
- Level 2 - 工作站

描述：

流控制传输协议 (`SCTP`) 是一种用于支持面向消息通信的传输层协议，一个连接中包含多个消息流。它的功能类似于 `TCP` 和 `UDP`，结合了二者的特征。它像 `UDP` 一样面向消息，并像 `TCP` 一样通过拥塞控制确保消息顺序可靠。

原理：

如果没有使用该协议，建议不要加载内核模块，通过禁用服务来减少潜在攻击面。

审计：

运行以下脚本验证 `sctp` 是否禁用：
