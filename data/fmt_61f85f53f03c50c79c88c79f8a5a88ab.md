
# 第12 章：故障排除

## 12.2.4 通用客户操作系统

### 问题
运行 `vmware-config.pl` 并尝试加载模块后，模块出现问题。（这在 SMP 系统上经常发生。）

### 修复
即使版本号相同，你的头文件也可能与你的配置不匹配。请确保在内核源码目录中运行 `make proper`；然后使用与当前内核相同参数的 `make menuconfig` 等命令。特别要注意处理器选项，例如 SMP。

### 问题
全屏模式下显示异常。最常见的症状是黑窗口。

### 修复
如果你运行的是 XFree86 4.0.x，直接图形（DGA）驱动程序可能存在某些 Bug。尝试升级到更高版本的 XFree86 看看是否解决问题，或者降级到 XFree86 3.3.x。市场上最新、最快的显卡最出现此类问题。

你也可以尝试在虚拟机的 `.cfg` 文件中加入以下内容：

```
xinfo.noDGAAccel = TRUE
```

### 问题
无论在主机的 XF86 文件中使用什么种设置，全屏模式似乎无法工作。

### 解释
某些服务器未能充分支持 DGA，而全屏模式需要 DGA。这里没有解决方法；你只能使用窗口模式。

### 问题
存在各种 Linux 内核不兼容问题。（具体版本请参见下列表。）

### 修复
解决这些问题的最佳方法是升级你的内核。你可以获取发行版的更新（如果你运行的是 Red Hat，这可能是最佳解决方案），或者编译你自己的内核。记住，一旦更改了内核，你必须重新运行 `vmware-config.pl` 以放置相应的 VMware 内核模块。

你可能会特别遇到以下版本：

- `2.2.3` 及更早版本：这些版本存在一些 CD-ROM 问题。例如，当你启动 VMware 时，光驱可能会不断打开和关闭。当客机系统想要插入 CD 后立即自动执行某些操作时，此问题最为常见。

- `2.2.16`：该版本的 Linux CD-ROM 驱动程序存在某些 Bug。VMware 在插入 CD 时难以检测到，你在启动虚拟机时会看到警告对话框。Windows 95 和 98 客机系统会将 CD 视为音频 CD。

- `2.4.0–2.4.8`：这些版本在发布版内核中会出现问题，特别是在编译 `vmmon` 和 `vmnet` 模块时。如果可能，尝试使用较新版本的内核，并确保你的 VMware 版本是最新的。

### 问题
你的虚拟机无法访问设备。

### 修复
首先，检查你是否有访问该设备的权限；如果你无法在主机端访问该设备，VMware 不允许你在虚拟机中使用它。如果权限正常，检查主机系统上的其他程序是否打开或锁定了该设备。

### 注意
由于可能冲突，最好不要在主机和客机系统之间共享设备；相反，你应该使用仅主机网络（host-only networking）功能。例如，使用 SAMBA 或 lpd 让你的客机可以访问打印机。

### 问题
在操作系统重大升级后，VMware 无法工作。当操作系统升级后再次运行安装程序时，它提示你发现了之前的安装，或者提示你它无法安装 VMware 服务。

### 修复
在系统重大升级后，VMware Workstation 可能不会在启动时运行。不要重新安装，而是运行 `vmware-config.pl` 来安装相应的内核模块。

如果这不起作用，尝试通过 `vmware-uninstall.pl` 移除旧版本，然后使用新版本重新安装 VMware。如果仍然遇到之前相同的错误，请获取你的系统和所有设备的进程列表。

### 问题
由于 BIOS 设置错误，系统无法启动。

### 修复
在少数情况下，VM 用于存储 BIOS 设置的 NVRAM 文件损坏了。该文件包含软驱和启动顺序等配置。如果 BIOS 错误读取 NVRAM，可能会遇到分配 分的问题。解决这些问题最简单的方法是关闭虚拟机并删除 NVRAM 文件。（记住在 Windows主机上名为 `nvram`，在 Linux主机上以 `.nvram` 结尾。）当你再次开启虚拟机时，VMware 会创建一个新的 RAM 文件。

### 问题
你删除或损坏了虚拟机配置文件（`.vmx` 或 `.cfg`）。

### 修复
使用配置向导创建一个新的配置文件，并将其覆盖旧文件。在在此之前，一切都无法正常工作。要解决该问题，请使用配置编辑器直到获得你想要的结果。

如果你认为配置文件已损坏，请按照上一个问题的讨论，首先尝试删除 NVRAM 文件。

### 问题
尽管你在 VMware 配置编辑器中添加了软驱，客机系统仍无法识别虚拟软驱。

### 修复
VMware BIOS 不会自动获取通过配置编辑器对软驱所做的更改；你必须进入 BIOS 设置并手动添加。（更多信息请参见第 4.14 节。）

操作方法是在客机启动时按 F2，将光标移动到 Legacy Diskette B（通常你需要的是 1.44/1.25 MB 驱动器）。然后按 F10 列表并保存 BIOS。如果你决定在配置编辑器中移除虚拟软驱设备，请务必进入 BIOS 并禁用它。

## 12.2.4 通用客户操作系统

### 问题
当使用 VMware 的挂到磁盘（suspend-to-disk）功能挂起某些客户系统时，主机系统会冻一段时间。

### 修复
当你挂起系统时，VMware Workstation会将所有虚拟机的内存状态写入磁盘，并修复对虚拟机磁盘的任何更改。这可能会向主机的磁盘发送大量数据，导致主机的磁盘缓冲区满，从而引发大量的实际磁盘写入。在写入期间，所有对磁盘的系统调用都会被阻塞。

你可以通过两种方式进行改进。首先，你可以尝试减少虚拟机配置中的内存量，这样挂起的操作系统需要写入的内存就会更少。或者，你可以尝试将虚拟机配置文件和目录存放在不同的磁盘上。VMware 将机器状态数据写入包含其配置文件的相同目录。如果该目录恰好是你的系统磁盘，任何涉及该磁盘的系统活动都会冻结写入缓冲区。

最后，你可以尝试提高客户机的性能。如果你在 Windows 主机上为客户硬件准备了特殊驱动程序，请安装它们。确保你的 DMA 和多扇区传输模式已开启。在带有 IDE 磁盘的 Linux 主机上，你可以尝试运行 `hdpdm` 来启用扇区模式。最重要的通常是多扇区传输（例如 `hdpdm -m 16 /dev/sda`）。请查看 `hdpdm` 手页以获取完整列表。

如果这些选项对你都无效，你只能忍受它。

### 问题
当你尝试挂起虚拟机时，VMware 提示客户机不想这样做。

### 修复
在配置编辑器中关闭客户操作系统挂起选项中的“使用 APM 特性”。无论如何这都是个好主意，因为你的客户系统可能想要执行一些粗鲁的操作，例如将其状态写入原始磁盘上的某个分区。这不仅会导致另一个操作系统的文件损坏，系统还可能因为磁盘读取权限、BIOS 兼容性、月相或其他任何你不想涉及的问题而完全无法工作。

### 问题
当你对笔记本主机执行挂起操作时，VMware 崩溃了。

### 变通方法
在执行实际挂起操作之前，点击“VMware 挂起（Suspend）”。此外，正如前一个问题的讨论所示，不要为你的客户机挂起操作使用 APM。

### 问题
你无法从 CD 启动客户机。

### 修复
可能是 VMware BIOS 中的启动顺序被设置为在硬盘 CD-ROM 上搜索操作系统。请参阅第 4.14 节获取有关 VMware BIOS 的更多信息。

### 问题
当 Windows 主机上运行某些客户系统或 VMware BIOS 时，你的主机系统性能极差。

### 修复
如第 8.1 节所示，你的客户系统在应该释放 CPU 时没有释放。如果你的客户机有处理器空闲程序或 APM 支持，请使用它。

这个问题在 Windows 主机系统上出现更频繁，因为这些主机的调度程序试图针对活动窗口和非活动窗口进行优化，而 Linux 系统通常给所有事务赋予相同的优先级（即使你在后台运行一个客户机并运行 CPU 密集型屏幕保护，Linux 系统仍然会停滞）。你可以通过在配置编辑器的 **VM 全局设置优先级部分**中使用最低设置，为 Windows 主机提供一些提示。

如果你在 Linux 主机上遇到严重的 CPU 性能问题，请对 VMware 进程使用 `nice` 命令。

### 问题
你的 IDE 驱动器设置似乎不起作用；你正尝试在从从设备（secondary slave）上配置驱动器。

### 修复
在 VMware Workstation 中，没有主设备的情况下无法配置从设备。请安装一个主设备（任何设备均可）或将驱动器移动到主设备上。

### 问题
你需要特定的位深，但无论你做什么，客户机的 VMware 视频驱动程序都不改变。

### 修复
对于 SVGA 驱动程序，客户机的位深与主机相同。因此，要更改客户机的位深，请先设置主机的位深。

### 问题
你想使用 8 位（256 色）模式，但 VMware Workstation 不允许。

### 修复
设置主机位深。如果你的主机恰好是 Windows，请在虚拟机配置文件（`.vmx`）中添加：

```
draw.allowBit = TRUE
```

注意：并非所有的 VMware SVGA 驱动程序都 8 位模式。
