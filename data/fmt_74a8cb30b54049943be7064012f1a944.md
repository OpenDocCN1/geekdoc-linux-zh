### 22. B.

### 23. A.
新安装的 `MySQL` 数据库可能没有现成的数据库，因此首先要使用 `CREATE DATABASE` 命令（如选项 A 所示）创建数据库。（`USE` 命令在数据库创建后才有用。）数据库创建后，你可以使用选项 C 中的 `CREATE TABLE` 创建表；然而，你需要一个存在的数据库，且该命令还需要数据类型信息，选项 C 并未提供。选项 D `INSERT INTO` 在创建表后向表中插入数据，因此这不是你第一个使用的命令。它还需要对存储的数据进行说明，因此选项 `UPDATE` 在创建表后修改现有条目。欲了解更多信息，请参阅第 9 章“编写脚本、配置电子邮件和使用数据库”。

### 24. D.
正确答案 `man` 和 `info`（选项 B 和 D）是常用的 Linux 软件包。虽然 `?`（选项 C）是交互式程序中的命令，但它本身不是一个软件包。没有名为 `manual`（选项 A）的常用命令，`hint`（选项 E）也不是有效的命令或常用程序名。欲了解更多信息，请参阅第 1 章“探索 Linux 命令行工具”。

### 25. A.
`Unix` 系统传统上使用 `UTC`（即格林治标准时间），`Linux` 也是如此。因此 A 是正确的。然而 `x86` PC 传统上使用本地时间，`Linux` 也支持这种，因此 C 是正确的。互联网时间（选项 B）是 24 小时制的替代方案，将一天分为 1000 个“节拍”。标准 PC `BIOS` 不支持这种时间格式，12 小时制对计算机来说并不很有用，因为它无法区分上午和下午，因此选项 D 是错误的。虽然火星一天的长度与地球相似（24 小时 37 分钟），但想要殖民火星的人必须等待 PC 时钟支持设置红红星球的时间；选项 E 是错误的。欲了解更多信息，请参阅第 7 章“系统管理”。

### 26. D.
输入 `lsmod`（选项 D）会产生当前加载的模块列表。`insmod`（选项 A）和 `modprobe`（选项 C）程序均用于加载模块——加载单个模块或单个模块及其依赖的所有模块。`depmod` 命令（选项 B）生成包含模块依赖信息的 `modules.dep` 文件。`modinfo` 命令（选项 E）显示单个模块的信息，如版本号和作者。更多信息，请参阅第 3 章“配置硬件”。

### 27. B.
`chgrp` 和 `chown` 命令都可以更改文件的组所有权。`chgrp` 命令在选项 B 中接受组名和文件名作为参数。`chown` 命令通常更改文件的所有者；但如果你提供一个以点（.）或冒号（:）开头的组名；如选项 E 所示，它会更改文件的组。选项 A 显示的 `chown` 命令会将文件的主所有权更改为 `must` 用户（如果系统中存在该用户）；它不会更改组所有权。没有标准的 `Chgroup` 命令，选项 D 所示的将权限更改为 `0600` (rw----)，这对于目标状态来说是一个倒退。更多信息，请参阅第 4 章“管理文件”。

### 28.
许多文件系统不允许使用硬链接，因此你可能需要创建一个符号链接，如选项 E 所示。链接不依赖于文件系统日志，因此选项 A 是错误的。与选项 B 相反，任何人都可以创建链接，而不是源的所有者。选项 C 描述了硬链接的一个限制；但此链接可能必须是符号链接，这一限制并不重要，且选项 C 是错误的。选项 D 描述的限制比选项 B 更为严苛，但由于相同的原因它也是错误的。更多信息，请参阅第 4 章“管理文件”。

### 29. B. E.
冒号（:）启动模式，你可以在模式中输入命令。在模式下，`r` 将一个文件包含在现有文件中，`w` 写入文件，加载一个完全的新文件，而 `q` 退出程序。因此，理想的组合是 `:wq`（选项 B）。对于特殊情况，`ZZ` 执行相同的操作，更多信息，请参阅第 5 章“启动 Linux 和编辑文件”。

### 30. C.
`/forward` 文件是用户电子邮件转发文件。此类文件开头的竖线（|）是用于通过指定的程序文件发送电子邮件的代码，因此选项 C 是正确的。要像选项 A 所示那样，文件需要读取 `junk` 或 `junkme@hostname`，其中 `hostname` 是计算机的主机名。要像选项 B 所示那样，必须省略开头的竖线。可以想象 `/junkme` 脚本所描述的内容，但没有办法确定地知道这一点。要像选项 E 所示那样，文件需要读取 `user@junkme`，其中 `user` 是用户名。更多信息，请参阅第 9 章“编写脚本、配置电子邮件和使用数据库”。

`Linux` 大量借鉴了 `Unix`，而 `Unix` 最初是一个基于文本的操作系统（`OS`）。`Unix` 和 `Linux` 保留了许多此类遗产，这意味着为了理解如何使用、特别是管理 `Linux`，你必须至少理解其命令行工具的基本知识。因此，本书从介绍 `Linux` shell（接受并解释文本模式命令的程序）以及你可以从 shell 中使用的许多基本命令和程序开始。

本章从基础 shell 信息开始，包括 shell 选项及其使用程序。从这里开始，本章涵盖了流、管道和重定向，你可以利用它们在程序与程序或文件与程序之间引导输入和输出。这些技术允许使用过滤器进行文本处理——过滤器是你可以在没有传统文本编辑器帮助的情况下处理文本的命令。有时你可能会以抽象的方式处理文本，使用代码来表示几种不同类型的文本。因此，本章涵盖了这一主题。

### 理解命令行基础

在对 `Linux` 进行任何操作之前，你应该了解如何使用 `Linux` shell。有多种 shell 可用，但大多数提供了类似的能力。理解一些基础知识将让你在运行 `Linux` 时受益匪浅，因此我描述了其中一些技术和命令。你还应该理解 shell 环境变量，它们是对许多程序可能有用的数据占位符。在命令行基础主题上，你应该知道如何获取你尝试使用的命令的帮助。

### 探索你的 shell 选项

由于许多关键软件组件，`Linux` 为 shell 提供了一系列选项。完整列表将非常长，但常见的选择包括以下几个：

- **bash**: `GNU Again Shell (bash)` 基于 `Bourne shell` 并在几个方面对其进行了扩展。在 `Linux` 中，`bash` 是最常见的默认 shell
- **bsh**: `bash` 所基于的 `Bourne shell` 也称为 `bsh`。它在 `Linux` 中并不常用，尽管 `bsh` 命令有时是指向 `bash` 的链接
- **tcsh**: 该 shell 基于 `C shell (csh)`。它在某些圈子里很流行，但没有主要的 `Linux` 发行版将其作为默认 shell
- **csh**: 原始的 `C shell` 在 `Linux` 中并不常用，但如果用户熟悉 `csh`，`tcsh` 是一个很好的替代品
- **ksh**: `Korn Shell (ksh)` 设计用于汲取 `Bourne shell` 和 `C shell` 的优点并进行扩展。它在 `Linux` 用户中有一个虽小但忠诚的群体
- **zsh**: `Z shell (zsh)` 比 `Korn Shell` 更进一步，整合了早期 shell 的功能并增加了更多

除了这些 shell，还有几十个更冷门的 shell 可用。在 `Linux` 中，大多数用户运行 `bash`，因为它是默认的。其他操作系统使用 `csh` 或 `tcsh` 作为默认。

文件 `/bin/sh` 是系统默认 shell 的符号链接——在 `Linux` 中通常是 `/bin/bash`。这种做法允许你指向一个 shell（例如在 shell 脚本的开头，参见第 9 章“编写脚本、配置电子邮件和使用数据库”）并确保即使系统可用 shell 变化也能调用 shell。这一特性在开发可能在其他计算机上运行的脚本时特别重要，参见第 9 章。

### 使用 shell

对于任何用过文本模式操作系统的人来说，`Linux` shell 非常简单：你输入一个命令（可能包含选项），然后计算机执行该命令。在大多数情况下，`Linux` 命令是外部的——即它们是独立于 shell 的程序。尽管如此，也有少数命令是 shell 内部的，了解这种区别可能是重要的。你还应该了解一些让使用 shell 变得更容易的技巧——如何让计算机补全长命令或文件名、检索你最近运行的命令，或编辑你已使用的（尚未完全输入的）命令。
