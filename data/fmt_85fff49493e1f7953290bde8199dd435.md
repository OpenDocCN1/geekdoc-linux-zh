### 1.1.9 禁用自动挂载（自动化）

#### 配置文件适用性：

*   等级 1 - 服务器
*   等级 2 - 工作站

#### 描述：

`autofs` 允许自动挂载设备，通常包括 CD/DVD 和 USB 驱动器。

#### 影响：

启用自动挂载后，任何具有物理访问权限的人连接 USB 驱动器或光盘，即使他们缺乏自行挂载的权限，其内容也可以在系统中可用。

#### 风险：

工作站用户使用移动硬盘非常常见。如果您的组织允许在工作站上使用便携存储或介质，且工作站的物理访问控制认为充分，那么关闭自动挂载的价值不大。

#### 审计：

作为首选，除非其他包依赖它，否则不应安装 `autofs`。运行以下命令验证是否未安装 `autofs`：

```
# systemctl is-enabled autofs
Failed to get unit file state for autofs.service: No such file or directory
```

如果已安装 `autofs`，运行以下命令验证其未被启用：

```
# systemctl is-enabled autofs
disabled
```

验证结果不是 `"enabled"`。

#### 修复：

如果没有其他依赖于 `autofs` 的包，请使用以下命令删除包：

```
# apt purge autofs
```

或者如果对 `autofs` 包有依赖：

运行以下命令掩码 `autofs`：

```
# systemctl stop autofs
# systemctl mask autofs
```

#### 附加信息：

此控制措施应与组织对便携驱动器和光介质使用的容忍度一致。在需要手动挂载介质的服务器上，手动挂载可以是深度防御的一部分，以降低未经批准的软件或信息引入的风险，或专有软件或信息外泄的风险。如果管理员经常使用闪存盘且访问具有足够的物理控制，则要求手动挂载可能不会增加安全性。

### 1.1.10 禁用 USB 存储（自动化）

#### 配置文件适用性：

*   等级 1 - 服务器
*   等级 2 - 工作站

#### 描述：

USB 存储提供了一种传输和存储文件的方法，确保文件独立于网络连接状态的持久性和可用性。它的流行和实用性导致基于 USB 的恶意软件成为网络渗透的一种简单且常见的手段，并且在网络环境中建立持久性威胁的第一步。

  l_output2=""

    if grep -Pq -- "^blacklist\h$l_name" > /dev/null 2>&1; then
      l_output="$l_output\n module: $l_name" is not loadable:\n$l_loadable"

# 1.2 配置软件更新

Debian Linux 发行版使用 `apt` 安装和更新软件包。补丁管理程序在企业之间差异很大。大型企业可能选择安装本地更新服务器代替直接更新，而单一部署系统可能倾向于直接获取更新。更新可以自动或手动执行，取决于管理的策略。许多大型企业在发布到生产环境之前会在非生产系统中进行测试。

对于本基准而言，要求是配置并维护补丁管理系统。细节交给组织。
