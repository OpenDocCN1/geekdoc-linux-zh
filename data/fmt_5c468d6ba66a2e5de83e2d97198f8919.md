## 8.3. Cisco 路由器配置备份

在工作场所，我们有一个连接远程位置的 WAN。这些远程位置通过 ISDN 或某些情况下通过 Centrax 数据中心连接 Cisco 路由器，以提供 Internet 和 WAN 连接。Cisco 路由器产品允许通过网络服务器上的 TFTP（简单文件传输协议）读取和写入配置文件。每当路由器配置发生更改时，在 Linux 服务器上保存配置文件是非常关重要的，以便维持备份。

请注意，Red Hat 默认禁用了 TFTP 服务，因为如果配置不当，可能会成为一个真正的安全漏洞。TFTP 守护允许任何人在不进行身份验证的情况下读取和写入文件。我个人的设置方法是创建一个由 root 拥有的`/tftpboot/`目录，然后修改`/etc/inetd.conf`文件中现有的配置行以修复位置：

```
tftpd dgram wait root /usr/sbin/tcp in.tftpd /tftp-boot
```

> 注意：在上述行末尾添加 `/tftpboot` 路径专门指示了 TFTP 守护允许访问文件的位置。虽然实际上可以省略此部分并允许 TFTP 访问系统上的任何地方，但由于 TFTP 被认为具有安全风险，这可能是一个非常糟糕的主意。

一旦你启用了 TFTP 服务，别忘记输入：

```
killall -HUP inetd
```

上述命令重启 INETD 守护进程以识别你对 `inetd.conf` 文件所做的任何更改。

Perhaps you would like to restore such files on a system that does not offer a GUI-based environment, or would like to do so over a slow network connection through remote execution of KDat would be impractical. ## 8.2.2. 使用“KDat”进行恢复：

要从由 KDat 创建的备份集中恢复一个或多个文件，请将备份磁带插入驱动器，从“文件”菜单选项选择“挂载磁带”或左键点击像磁带的图标。

KDat 将尝试从磁带上读取头信息，如果成功，它将尝试找到与磁带头找到的标识匹配的磁带索引。该磁带索引存储在你的硬盘上，是为每个由 KDat 格式化的备份磁带创建的唯一文件，并在你每次执行备份时都会更新。

如果缺少相应的磁带索引，KDat 将告知你此情况，并询问你是否通过读取磁带来重新创建索引。由于你在恢复所需文件之前需要重新创建它，因此左键点击“是”是完全合理的。

> 注意：一旦磁带重新索引，其名称将更改为“已重新索引磁带”。你应该将磁带重命名为原始名称。

一旦成功读取磁带索引，就可以用它来从备份集中选择你想要恢复的目录或文件，方法与你创建备份配置时相同。
