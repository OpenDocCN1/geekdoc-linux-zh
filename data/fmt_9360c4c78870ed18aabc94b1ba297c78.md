## 附录 C 从闪存内存启动

在此处按 Ctrl+D。
在嵌入式 Linux 工作坊中，每个 opt 软件包都可以有一个 Makefile。该 Makefile 有三个目标：`everytime`、`binaries` 和 `dependencies`。`everytime` 目标通常不使用。`binaries` 目标用于重新构建自上次编译以来源发生更改的二进制文件，并将这些二进制文件移动到 opt 软件包中。一旦进入包，就会对二进制文件进行处理（`strip`）。`dependencies` 目标列出了 opt 软件包的任何依赖项。例如，`minicom` 可执行文件依赖于 `nurses` 库。显然，你不需要使用 `cat` 命令来构建 Makefile；这是本 HOWTO 中方便的方法。

注意，缩进行是用单个制表符缩进的。

+ 39. 现在我们将使用 `cat` 命令为 Minicom 创建启动脚本
`cat > opt/minicom/etc/rc/s99minicom`

```sh
#!/bin/sh

echo "Press a key for minicom..."

read x

minicom -s
```

在此处按 Ctrl+D。
嵌入式 Linux 工作坊配备了一套启动脚本，其工作原理与 Red Hat 启动脚本类似。`etc/rc` 目录下任何以字母 S 开头的脚本都会按排序顺序执行。将脚本命名为 `S99 (something)` 意味着它应该是最后一个运行的脚本，并且可能不会返回给调用者。
我们使用 `-s` 选项让 Minicom 直接进入设置模式。它默认使用 COM2；在实际设备中，你会创建一个 `minicom` 配置文件并让它直接启动。此外，在实际应用中，我们不会强制用户按键启动，但通过我们我们可以在 Minicom 抹掉错误信息之前看到它们。

+ 40. `chmod a+x opt/minicom/etc/rc/s99minicom`
赋予脚本可执行权限。
