
# 使用 Mimikatz 进行凭据导出与 Kerberos 攻击

## 列表 689 - 在域工作站上执行 mimikatz

输出片段显示了存储在 `LSASS` 中的、属于域用户 `Offsec` 的所有凭据信息，包括缓存哈希值。

注意，我们在上面的输出中高亮了两种类型的哈希值。这取决于 AD 实现的功能层级别。例如，对于功能层级别为 Windows 2003 的实例，`NTLM` 是唯一可用的哈希算法。对于运行 Windows Server 2008 或更高版本的实例，`NTLM` 和 `SHA-1`（`AES` 加密的常用伴侣）都可能可用。

## 利用 Kerberos TGT 认证

使用 Mimikatz 的另一种方法和用途是通过滥用 `TGT` 和服务票据来利用 `Kerberos TGT` 认证。正如已经讨论过的，我们知道当前登录到本地机器的用户 `Kerberos TGT` 和服务票据会被存储以便使用。这些票据也存储在 `LSASS` 中，我们使用 Mimikatz 来交互并检索我们自己的票据和其他用户的票据。

例如，在列表 690 中，我们使用 Mimikatz 显示存储在内存中的 `Offsec` 票据：

## Kerberoasting 攻击

根据 `Kerberos` 协议，服务票据是由 `SPN` 的密码哈希值加密的。如果我们能够获取票据并通过暴力破解或猜测（这种技术被称为 **Kerberoasting**）对其进行解密，我们就能知道密码哈希值，并从此破解出服务账户的明文密码。作为一个额外优点，我们进行这种攻击不需要管理员权限。

要执行字典攻击，我们首先使用 `apt` 安装 `kerberoast` 包，然后运行 `tgsrepcrack.py`，并提供字典列表和下载的服务票据：

> **注意**：服务票据是二进制格式的。在使用 `Netcat` 等工具传输它时请记住这一点，这些工具可能会在传输过程中对其造成损坏。

### 列表 694 - 破解票据

```
kali@kali:~$ sudo apt update && sudo apt install kerberoast
...
kali@kali:~$ python /usr/share/kerberoast/tgsrepcrack.py wordlist.txt 1-40a50000-Offsec@HTTP~CorpWebServer.com-CORP.COM.kirbi
found password for ticket 0: Qerty09! File: 1-40a50000-Offsec@HTTP~CorpWebServer.com-CORP.COM.kirbi
All tickets cracked!
```

在此示例中，我们成功破解了服务票据，并获得了服务账户的明文密码。

如果域中包含具有弱密码的高权限服务账户，这种技术将非常强大。然而，如果针对特定的 `SPN` 使用了托管服务账户（`MSAs`）或组托管服务账户（`gMSA`），密码将是随机生成的、复杂的且长度为 120 位，使得破解变得不可行。

尽管此示例是在 `tgsrepcrack.py` 上运行的，但我们也可以使用 `John the Ripper` 和 `Hashcat` 来利用这些工具的功能和速度。

> `Invoke-Kerberoast.ps1` 脚本实现了这种攻击，并可以自动枚举域中的所有服务主体名称（`SPN`），为它们请求服务票据，并以准备好供 `John the Ripper` 和 `Hashcat` 破解的格式导出，完全消除了在此攻击中对 Mimikatz 的需求。

## 低速隐蔽的 LDAP 密码攻击

在执行暴力破解或字典认证攻击时，我们必须意识到账户锁定策略，因为过多的失败登录可能会阻止账户的进一步攻击，并可能提醒系统管理员。

在本节中，我们将使用 `LDAP` 对 `AD` 用户进行“低速且隐蔽”的密码攻击，而不会触发账户锁定。首先，通过 `net accounts` 查看锁定策略：

```
C:\> net accounts

Force logoff how long after time expires?: Never
Lockout threshold: Never
Lockout duration (minutes): 30
Lockout observation window (minutes): 30
Lockout history: 5
Minimum password age (days): 42
Minimum password length: 6
```
