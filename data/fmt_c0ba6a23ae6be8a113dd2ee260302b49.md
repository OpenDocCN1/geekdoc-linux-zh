IP 协议通过将目标主机的 IP 部分与主主机进行比较，决定何时识别出目标主机位于同一网络上。每当源主机和目的主机的网络 ID 不匹配时，IP 协议会尝试寻求同一网络上路由器的帮助。由于一个网络可能有多个连接到它的路由器，IP 会选择它信任的、距离指定目的地更近的路由器。如果找到了这样的路由器，数据包就会转发到该路由器。如下一节所示，IP 通过查找一个名为路由信息表（RIT）的数据库来确定将数据转发到哪一个路由器。

### 路由信息表 (RIT)

如上一节所述，IP 协议通过查询包含其所识别的路由（网络）信息的数据库来执行其路由功能。该数据库被称为路由信息表，由另一种称为路由信息协议（RIP）的协议构建和维护。RIP 处理路由发现——即其主要目的是识别互联网络上的所有网络以及距离每个网络最近的路由过程。RIP 是一种运行在所有主机或路由器上的协议。因此，RIP 从其运行的工作站或路由器的视角构建并维护数据库（路由映射）。RIP 包含了其在互联网络上识别的每个目的地的信息：

- 距离（Distance）：作为目的地距离主机或路由器的距离指示。通常，它等于到达目的地必须经过的路由器数量。
- 下一个路由器（Next Router）：包括被信任距离目的地更近的路由器 IP 地址，数据报文递送到此处。
- 输出端口（Output Port）：指定哪个接口（如果是多宿主）与下一个路由器连接同一个网络。

例如，trumpet 的路由表（见图 20.16）将包含一条条目，说明它距离网络 148.67.0.0 有 2 跳（距离或度量），下一个递送的路由器是 100.0.2。路由器 R2 的路由表将显示它距离同一网络（148.67.0.0）有一个路由距离，下一个发送的路由器是 R3。显示路由表内容的 UNIX 命令是 `netstat -rn`：

```
netstat -rn
```

    - H：路由是特定的，或指向某个主机（如第一条和第二条记录所示）。

    - D：路由被 ICMP 协议的路由重定向修改过。
- M：引用（Refs）列显示了跨越每条路由的活动连接数。活动连接可能是由于正在进行的 FTP 或 TELNET 会话等。任何使用 TCP 作为底层传输协议的服务或应用程序都会使此列加 1。
- 用（Use）跟踪通过每条路由的包数。
- 接口（Interface）列指定了与下一个路由器连接同一个网络的接口。

## 路由表维护

TCP/IP 支持静态和动态两种方式维护路由表。静态维护路由表主要涉及两个 UNIX 命令：`ifconfig` 和 `route add`。通过 `ifconfig`，可以为网络接口配置 IP 地址和相应的子网掩码，如下：

```
# ifconfig e30 100.0.0.2 255.0.0.0
```

除了配置接口的地址和子网掩码外，`ifconfig` 命令的作用是在路由表中更新有关直接连接网络（100.0.0.0）的路由信息，如之前的 `netstat -rn` 输出所示。

使用 `route add` 命令可以在 UNIX 主表中输入静态路由。`route` 命令的格式为：

```
route add destination_address next_router metric
```

其中 `destination_address` 是你想要添加到路由表的路由。

`next_router` 是递送数据报的路由器地址。

`metric` 是到目的地的距离测量，通常以中间路由的数量表示。

以下示例显示了如何向路由表添加一个新目的地的路由：

```
# route add 87.45.3.4 198.53.23.20 1
```

以下示例显示了如何使用 `route add` 为主机配置默认路由：

```
# route add 0.0.0 198.53.237.5 1
```

根据前面的条目，该主机被配置为将 198.53.237.5 识别为其默认网关。

动态路由维护涉及自动将新发现的路由添加到路由表中。它还涉及删除由于配置或故障而失效的路由。有多种协议可以用于动态路由维护。常见的协议包括路由信息协议（RIP）、开放最短路径优先（OSPF）和互联网控制消息协议（ICMP）。在这三种协议中，只有 ICMP 在在本章之前的范围内讨论过。关于所有路由协议的详细处理，请参阅“网络”章节。

2. `telnet` 将地址 (`148.27.34.1`) 传递给 TCP/IP 并请求连接到目标主机。随后，TCP 将请求封装在 TCP 头部中，并同 IP 协议一起传递，请求交付到相应的主机。

3. 此时，IP 将 jade 的地址与其路由数据库中包含的其他目标地址进行比较。由于源主机和目标主机具有相同的 id (`148.27.0.0`)，IP 决定向 jade 进行递送。随后，IP 将其传递给它的 TCP 请求封装在一个数据报文中，其中包含目标地址和源地址 (`148.27.34.1` 和 `148.27.0.5`)。然后，它将该数据报文同 IP 地址一起提交给网络层。

4. 这就是 ARP 介入处理 IP 地址解析的地方，从以太网的角度来看（假设 MAC 层是以太网），IP 地址是无用的，需要将其转换为 MAC 地址。换句话说，ARP 将管理员分配的符号化 IP 地址转换为主机在物理层和数据链路层识别身份时使用的对应 MAC 地址。ARP 通过向 MAC 接口（以太网）发送作为 ARP 请求的广播消息来处理地址解析，消息内容为“我是 148.27.34.1，我的物理地址是 0x00003b21b2”。在所有接收广播的主机中，只有 jade 使用 ARP 响应包进行响应，包内容为“我是 0x0000c05”。

5. 此时，两台主机都感知到了对方的物理身份。网络层（在主机上）通过将 IP 数据报封装在数据帧中并发送给主机，进入实际的交换阶段。TCP/IP 定义了所谓的命名服务。命名服务通过允许用户指定该主机，使用户无需执行繁琐且不便的目标地址输入任务。将主机映射到其实际 IP 地址的最简单方法涉及使用 hosts 文件，该文件通常维护在 `/etc/` 下。hosts 文件是一个包含两列的 ASCII 文件：

| IP 地址 | 主机名 |
| :--- | :--- |
| 148.27.34.1 | jade |
| 148.27.0.5 | orbit |

当用户输入 telnet 通过查询 `/etc/hosts` 数据库来查找对应的 IP 地址时，当 IP 地址解析为其等效 MAC 地址时，ARP 在其特殊缓存中维护该映射，从而提高了传输效率和对用户的响应时间。ARP 缓存的另一个好处是节省带宽，因为它不再要求主机在每次向目标主机发送数据时都发送 ARP 广播。可以使用 `arp` 命令检查 ARP 缓存，如下：

```
arp -a
100.0.0.10@0:3b:21b2
```

ARP 如何在其在其缓存中维护条目，取决于主机与特定主机厂商实现通信的频率。

代理 ARP 是路由器上的一种 ARP 实现，设计用于代表远程网络主机处理 ARP 查询。查看图 4.10，当路由器上开启代理 ARP 时，每当主机发送请求 IP 地址 29.34.2.6 对应的 MAC 地址的 ARP 查询时，会发生以下事件：

- 1. ARP 请求广播被路由器接收。
- 2. 如果路由器识别该地址属于其可以到达的网络，则用自己的 MAC 地址响应该“ARP”。否则，它将静地丢弃该请求。

## 主机间传输层 (The Host-to-Host Transport Layer)

主机间传输层主要由两个协议支持：用户数据报协议 (UDP) 和传输控制协议 (TCP)。前者是无连接且不可靠的协议，而后者是面向连接且完全可靠的协议。图 20.19 显示了两种协议头部的数据结构。本节并不深入探讨每个字段的含义，而是侧重于两种协议的特征以及两个头部中的源和目的端口号。感兴趣对这两种协议进行严谨处理的读者，请参考 Sams Publishing 出版的《Networking Unix》一书（ISBN 0-672-30584-4）。
