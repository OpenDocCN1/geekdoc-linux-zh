# 第 4 章 关于函数的一切

## 处理复杂性

在第 3 章中，我们写的程序只包含一段代码。然而，如果我们编写真实的程序，它们将是无法维护的。让多人共同开发该项目将非常困难，因为任何部分的任何更改都可能不利地影响另一位开发者正在工作的部分。

为了协助程序员分组工作，有必要将程序拆分成各个部分，这些部分通过定义良好的接口相互通信。这样，每个部分都可以独立于其他部分进行开发和测试，使得多个程序员更容易协作完成项目。

程序员使用函数将程序拆分成可以独立开发和测试的部分。函数是代码单元，用于在特定类型的数据上执行定义的工作。例如，在文字处理器中，我可能有一个名为 `handle_typed_character` 的函数，每当用户输入按键时它就会被激活。数据函数可能是按键本身以及用户当前打开的文档。然后函数将根据这些修改文档。

函数完成后返回到何处继续执行。这是必要的，因为函数可能从程序的许多不同部分调用以进行处理，函数需要能够返回它被调用的任何地方。在大多数编程语言中，这个参数是在函数调用时自动传递的。在汇编语言中，`call` 指令负责为你传递返回地址，而 `ret` 指令处理使用该地址返回到调用函数的地方。

## 返回值

返回值是将数据传回主程序的主要方法。大多数编程语言只允许函数有一个单一的返回值。

这些要素在大多数编程语言中都存在。然而，每种语言指定每个要素的方式各不相同。

计算机存储变量以及传输参数和返回值的方式也随语言不同而异。这种差异被称为语言的*调用约定*（calling convention），因为它描述了函数在被调用时期望如何获取和接收数据。³

汇编语言可以使用它想要的任何约定。你甚至可以自己发明一种。然而，如果你想操作用其他语言编写的函数，必须遵守它们的调用约定。我们将在示例中使用 C 语言的调用约定，因为它是使用最广泛的，也是 Linux 平台的标准。

> 3. *约定*（convention）是一种标准化的但非强制的做事方式。例如，人们见面时握手是一种约定。如果我拒绝与你握手，你可能会认为我不喜欢你。遵循约定很重要，因为这让其他人更容易理解你在做什么，并让由多个独立作者编写的程序更容易协作。

## 使用 C 调用约定的汇编语言函数

如果不理解计算机栈（stack）的工作原理，你就无法编写汇编语言函数。每个每个计算机程序都使用一个称为“栈”的内存区域来使函数能够正常工作。将栈想象成你桌子上的一叠纸，可以无限地增加。你通常将正在处理的内容放在顶部，并在完成后将其取下。

你的计算机也有一个栈。计算机的栈位于内存的最顶端地址处。你可以通过一个名为 `pushl` 的指令将值推入栈顶，该指令将寄存器值或内存值推到栈的顶部。嗯，我们说它是顶部，但栈的“顶部”实际上是栈内存的底部。虽然这很令人困惑，但原因在于当我们考虑任何堆叠物品——碟子、纸张等——时，我们认为是从顶部添加和移除。然而，栈从内存顶部开始，并由于架构考虑而向下增长。因此，当我们提到“栈顶”时，请记住它位于栈内存的底部。你也可以使用名为 `popl` 的指令从栈顶弹出值。这会将栈顶的值移除并将其放入你选择的寄存器或内存位置。

当我们将一个值推入栈时，栈顶会移动以适应额外的值。我们实际上可以不断向栈推入值，它会继续向内存增长，直到遇到我们的代码或数据。那么，我们知道当前的“栈顶”在哪里吗？栈寄存器 `%esp` 始终包含指向栈顶的指针，无论它在哪里。

每当你用 `pushl` 向栈推入东西时，`%esp` 就会减 4，这样它就指向新的栈顶（记住，每个字是四个字节，且栈是向下增长）。如果我们想从栈中删除东西，只需使用 `pop` 指令，它向 `%esp` 加 4，并将之前的栈顶值放入你指定的任何寄存器中。`pushl` 和 `popl` 接受一个操作数——对于 `pushl` 是要推入栈的寄存器，对于 `popl` 是接收从栈中弹出的数据。

如果我们只是想在不移除它的情况下访问栈顶的值，可以使用间接寻址模式下的 `%esp` 寄存器。例如，以下代码将栈顶任何内容移动到 `%eax`：

```
movl (%esp), %eax
```

如果我们这样做：

```
movl %esp, %eax
```

那么 `%eax` 仅仅会持有指向栈顶的指针，而不是栈顶的值。将 `%esp` 放在括号中会导致计算机进入间接寻址模式，因此我们得到了 `%esp` 所指向的值。如果我们想访问栈顶正下方的值，可以简单地发出这条指令：

```
movl 4(%esp), %eax
```

此指令使用基址指针寻址模式（参见第 2 章中的“数据访问方法”节），它在查找所指向的值之前，只是简单地将 `%esp` 加 4。
