# 第 5 章. 处理文件

从文件中读取大量字节/字符到缓冲区（`buffer`）中，寻找换行符，并将从起始到该换行符之前的所有字符复制到另一个位置。如果你没有找到换行符，你将分配另一个缓冲区并继续读取。在这种情况下，你的缓冲区中可能会遗留一些字符，当你需要从文件中获取数据时，可以将它们作为起始点。

另一点需要注意的是，缓冲区是固定大小的，由程序员设置的。因此，如果你想一次读取 500 字节的数据，你只需发送一个 500 字节空闲位置的地址，并发送数字 500，以便它知道有多大。你可以根据应用程序的需求将其调小或调大。

要创建一个缓冲区，你需要预留静态存储或动态存储。静态存储是我们目前为止讨论过的，即使用 `long .byte` 指令声明的存储位置。动态存储将在第 9 章的“获取更多内存”节中讨论。不过，使用 `.byte` 声明缓冲区存在问题。首先，输入起来非常繁琐。你必须在 `.byte` 声明之后输入 500 个数字，它们除了占用空间外没有任何用处。其次，它会占用可执行文件的空间。在我们目前使用的示例中，它占用的不多，但在较大的程序中情况会发生。如果你需要 500 字节，就必须输入 500 个数字，这会在可执行文件中浪费 500 字节。

这两个问题都有解决方案。到目前为止，我们讨论了两个段：`.text` 段和 `.data` 段。还有一个名为 `.bss` 的段。这个段类似于 `.data` 段，区别在于它不占用可执行文件的空间。这个段可以预留存储，但不能对其进行初始化。在 `.data` 段中，你可以预留存储并将其设置为初始值。这对于缓冲区很有用，因为我们根本不需要初始化它们，只需要预留存储。为了实现这一点，我们执行以下命令：

```
.section .bss
.lcomm my_buffer, 500
```

- 2. 虽然这听起来很复杂，但在编程的大多数时候你不需要直接处理缓冲区和文件描述符（`file descriptors`）。在第 8 章，你将学习如何使用 Linux 中现有的代码来帮助你处理大多数文件输入输出的复杂性。

此指令 `.lcomm` 将创建一个符号 `my_buffer`，它指向一个 500 字节的存储位置，我们可以将其作为缓冲区使用。假设我们已经打开了一个文件进行读取并将文件描述符放在 `%ebx` 中，我们可以执行以下操作：

```
movl $my_buffer, %ecx
movl 500, %edx
movl 3, %eax
int $0x80
```

这将把最多 500 字节的数据读到你的缓冲区中。在这个示例中，我在 `my_buffer` 前面加了一个美元符号。请记住，这样做的是因为如果没有美元符号，`my_buffer` 被视为一个内存位置，并通过直接寻址模式访问。美元符号将其切换为立即数寻址模式（`immediate mode addressing`），这实际上会将 `my_buffer` 所代表的数字（即——我们缓冲区起始的地址）加载到 `%ecx` 中。（这正是 `my_buffer` 本身的地址）。

## 标准文件与特殊文件

你可能认为程序启动时没有打开任何文件。事实并非如此。Linux 程序在启动时通常至少打开三个文件描述符。它们是：

### STDIN

- 这是标准输入。这是一个只读文件，通常代表你的键盘。它始终是文件描述符 0。
- 3. 正我们之前提到的，在 Linux 中，几乎一切都是“文件”。你的键盘输入被视为文件，你的屏幕显示也是如此。

### STDOUT

这是标准输出。这是一个只写文件，通常代表你的屏幕显示。它始终是文件描述符 1。

### STDERR

这是你的标准错误。这是一个只写文件，通常代表你的屏幕显示。大多数常规处理输出流向 `STDOUT`，但过程中出现的任何错误信息都会进入 `STDERR`。通过这样，如果你愿意，可以将它们分到不同的地方。它始终是文件描述符 2。

这些“文件”中的任何一个都可以被重定向到真实文件，而不是屏幕或键盘。这超出了本书的范围，但任何关于 UNIX 命令行的优秀书籍都会对其进行详细描述。程序本身甚至不需要感知这种间接性——它只需像往一样使用标准文件描述符即可。

注意，你写入的许多文件根本不是文件。基于 UNIX 的操作系统将所有输入输出系统都视为文件。网络连接被视为文件，你的串口被视为文件，甚至你的音频设备也被视为文件。进程之间的通信通常通过称为管道（`pipes`）的特殊文件完成。其中某些文件的打开和创建方法与普通文件不同（即——它们不使用 `open` 系统调用），但它们都可以使用标准的 `read` 和 `write` 系统调用进行读取和写入。

## 在程序中使用文件

我们将编写一个简单的程序来阐明这些概念。程序将处理两个文件，从其中一个读取，将其所有小写字母转换为大写，并写入另一个文件。在在此之前，让我们思考一下完成这项工作需要做什么：

- 目的：此程序将输入文件转换为所有字母均转为大写的输出文件。
- 处理流程：1) 打开输入文件
2) 打开输出文件
4) 当我们未到达输入文件末尾时：
    a) 将部分文件读入我们的内存缓冲区
    b) 遍历内存中的每个字节
    如果该字节是小写字母，将其转换为大写
    c) 将缓冲区写回输出文件
- 程序开始：打开必要的文件。

注意我按照相反顺序指定了事项。这在编写复杂程序时是一个实用的技巧——首先决定要执行的事情。在这种情况下，是将缓冲区转换为大写。你可能认为你永远无法记住这些抛给你的数字——系统调用号、中断号等。在这个程序中，你还将引入一个新的指令 `.equ`，它应该很有帮助。`.equ` 允许为数字分配名称。例如，如果你定义 `.equ LINUX_SYSCALL, 0x80`，汇器就会用 0x80 替换它。所以，你可以写
