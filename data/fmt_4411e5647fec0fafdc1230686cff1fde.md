
正如前文提到的，有几种 `ftp` 的加密替代方案，如 `SSLeay FTP` 和第三方工具。由于大多数 `ftp` 账户并非作为管理员账户使用（这是一个糟糕的主意！），并且希望它们运行在 `chroot` 环境中，因此安全风险被降到了最低。既然现在已经完全覆盖了 `ftp` 的所有网络部分，让我们加强账户和环境的安全吧。`ftp` 用户安全的主要机制是使用 `chroot`。默认情况下，所有以身份登录的用户都将 `/home/ftp/` 作为其“根目录”。他们无法离开此范围查看 `/home/` 或 `/etc/` 的内容。这同样适用于用户组和个人，例如，你可以设置所有用户在 `ftp` 时 `chroot` 到 `/home`，或者在用户隐私的极端情况下（在托管多个域名的 `www` 服务器上），将每个用户 `chroot` 到其自己的家目录内。这是通过使用 `/etc/ftpassconf` 实现（可以通过 `man ftp` 访问）。我将提供几个实现此操作的示例，因为这在刚开始可能会令人困惑。此外，它还会检查 `/etc/ftpassusers`，如果正在更新的用户列在该文件中（如 `root` 应该在列中），它将不允许该用户通过 `ftp` 登录。

将登录到 `ftp` 服务器的用户进行 `chroot` 限制是比较简单的，但文档记录匮乏。`ftp` 服务器对 `guestgroup` 进行 `checkpass` 检查，其方法仅为 `guestgroup some-group-onset-system`，`guestgroup` 和组名需要在 `/etc/group` 中定义并添加成员。你同样需要编辑他们的密码文件行，以便 `ftp` 服务器知道将文件转储到何处。并且由于他们现在被 `chroot` 到了系统的该目录中，他们无法访问 `/etc`，因此你必须将许多文件拷贝到他们的目录中才能正常工作（这总来说是一个很贴心的细节）。

设置一个 `billybob/` 账户（因为他一直威胁要带系统管理员去捕负鼠）。此外，`billybob` 可以 `telnet` 登录并更改密码，但不能做其他事情，因为他一直试图在系统上运行 `irc`。系统使用了影子密码（shadowed passwords），这就是为什么 `billybob` 的密码字段中有一个 `x`。

首先，`billybob` 需要一个配置配置的用户账户：

```
billybob:500:500:Billy Bob:/home/billybob:/bin/passwd
```

这意味着 `ftp` 将 `chroot` 到 `/home/billybob/`，并且对我们其他人来说，会切换到现在的 `/home/billybob/`。`ftpass` 的 `man` 文件涵盖了这部分，当然 `/usr/sbin/passwd` 需要列在 `/etc/shells` 中。

其次，为了让 `ftp` 服务器知道他被 `chroot` 到某个组，他必须是 `/etc/group` 中定义的组（`baddusers`, `ftpeople` 等）的成员。然后，该组必须列在 `/etc/ftpass` 中。

现在你需要拷贝一些库文件/二进制文件，否则 `billybob` 将无法执行他预设的大许多操作。所需的文件以包的形式提供（通常是 "`anonftp`"），一旦安装，文件将被拷贝到 `/home/ftp/`。你会注意到这里有一个 `/etc/passwd`，这仅仅意味着将 `UID` 映射到用户，如果你希望 `billybob` 使用其用户名而不是 `ID`，请为他添加一行（我从真实的 `/etc/passwd` 复制了他的那行到此文件中）。组文件也一样。

并且在组文件中为 `billybob` 的组添加一行：


### SQUID

`SQUID` 是一个强大且快速的对象缓存（Object Cache）。它能代理 `FTP` 和 `WWW` 会话，基本上让它具备了 `FTP` 和 `WWW` 服务器的许多属性，但它只在其缓存目录内进行文件的读写操作（我们希望是这样），这使得它相对安全。除了以 `root` 用户（通常为 '`nobody`'）运行外，`Squid` 很难攻破它所运行的系统，因此通常不需要太担心。你对 `squid` 最主要的担心应该是配置不当，例如，如果 `squid` 连接到了你的内部网络（这通常是如此的）和互联网（再次，非常常见），它实际上可能被用来访问内部主机（即使它们使用的是非路由 `IP` 地址）。妥妥地配置 `squid` 非常重要。

确保这种情况不会发生的最简单方法是使用 `squid` 的内部配置，并仅绑定到内部接口，不让外部世界尝试将其作为访问你内部局域网（`LAN`）的代理，此外，对其进行防火墙隔离也是个好主意。`Squid` 还可以用作 `HTTP` 加速器，也许你在内部网络上有一个想要与世界共享的 `WWW` 服务器，在这种情况下配置会变得复杂一些，但是可以安全地实现的。幸运的是，`squid` 拥有良好的 `ACL`（访问控制列表），允许你通过名称、`IP`、时间、实际日期来锁定访问（也许允许真正去办公室的人在周末进行无限制浏览）。请记住，`ACL` 越复杂，响应请求的速度就越慢。

`ACL` 的工作原理是定义规则，然后应用这些规则，例如：

```
acl internet 10.0.0.0/255.255.0.0
http_access allow internet
http_access deny all
```

这把 "`internet`" 定义为源地址为 `10.0.0.0/255.255.255.0` 的任何内容，允许其访问 `http` 缓存端口，并拒绝其他所有。记住规则是按照给定的顺序读取的，就像 `ipfwadm` 一样，这允许你获得非常复杂的配置（如果你不小心就会出错）。始终从特定的规则开始，然后是更通用的规则，并记得在特定的允许（`allow`）之后放置拒绝（`deny`），否则它可能会放行。意外拒绝一切也比让它通过要好，因为你会发现拒绝后的（来自恼怒用户的反馈）比通过后的反馈更快（当恼怒的用户注意到来自内部 `www` 服务器的统计文件出现在互联网上时）。`squid` 配置文件 (`squid.conf`) 注释详尽（到了过头的程度），并且也有相当不错的帮助页（`man-page`）。

另一个实用的例子是拦截广告，为了拦截广告，你可以在 `squid.conf` 中添加以下内容：

```
acl ads dstdomain ads.blah.com
http_access deny ads
```

`acl` 声明仅仅是一个模式，无论是目标域名、源域名、正则表达式等，`http_access` 声明激活了对它执行什么操作（拒绝、允许等）。如果设置得当，这是一个限制访问 `WWW` 的极其强大的工具，遗憾的是，它确实有一个喀琉斯之踵：它不支持基于用户的身份验证和控制（尽管可能没有哪个产品都能做到）。请记住，像任何规则一样，它们是从上到下读取的，所以先放特定的拒绝和允许，然后是更通用的规则。`squid.conf` 文件应该有详尽的注释且自明易懂，`squid` `FAQ` 位于：`http://squid.nlar.net/Squid/FAQ/FAQ.html`。
