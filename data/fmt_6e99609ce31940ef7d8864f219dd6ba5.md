## 4.8 特殊内置目标名称

当某些名称作为目标出现时，它们具有特殊的含义。

- `.PHONY`
  特殊目标 `.PHONY` 的先决文件被视为“伪目标”（phony targets）。当轮到考虑考虑此类目标时，`make` 将无条件地运行其配方（recipe），无论是否存在同名的文件，无论该文件的最后修改时间如何。参见第 4.5 节 [伪目标]，第 29 页。

- `.SUFFIXES`
  特殊目标 `.SUFFIXES` 的先决文件是用于检查后缀规则的后缀列表。参见第 10.7 节 [旧式后缀规则]，第 125 页。

- `.DEFAULT`
  为 `.DEFAULT` 指定的配方用于任何未找到规则（显式规则或隐式规则）的目标。参见第 10.6 节 [最后手段]，第 125 页。如果指定了 `.DEFAULT` 配方，则规则中被提及为先决文件但未被视为目标的每个文件，都将代表其执行该配方。参见第 10.8 节 [隐式规则搜索算法]，第 127 页。

- `.PRECIOUS`
  `.PRECIOUS` 依赖依赖的目标将受到以下特殊处理：如果 `make` 在执行其配方期间被杀掉或中断，则目标不会被删除。参见第 5.6 节 [中断或杀死 make]，第 50 页。此外，如果目标是一个中间文件，它在不再被需要后将不会像常那样被删除。参见第 10.4 节 [隐式规则链]，第 117 页。在后一种情况下，它与 `.SECONDARY` 特殊目标重叠。你也可以将隐式规则的目标模式（例如 `o`）列为特殊目标 `.PRECIOUS` 的先决文件，以保留由规则目标模式匹配文件名产生的中间文件。

- `.INTERMEDIATE`
  `.INTERMEDIATE` 依赖的目标被视为中间文件。参见第 10.4 节 [隐式规则链]，第 117 页。没有先决文件的 `.INTERMEDIATE` 无影响。

- `.SECONDARY`
  `.SECONDARY` 依赖的目标被视为中间文件，不同的是它们永远不会被自动删除。参见第 10.4 节 [隐式规则链]，第 117 页。

  没有先决文件的 `.SECONDARY` 会导致所有目标均被视为次要目标（即没有目标因为被认为是中间文件而被移除）。

## .SECONDARYEXPANSION

如果在 Makefile 的任何地方将 `.SECONDARYEXPANSION` 称为目标，则在它之后定义的所有先决文件列表将在所有 Makefile 被读取完后进行第二次展开。参见第 3.8 节 [次级展开]，第 18 页。

## .DELETE_ON_ERROR

如果在 Makefile 的任何地方将 `.DELETE_ON_ERROR` 称为目标，那么如果规则的目标发生了变化且其配方以非零状态退出，则 make 将删除该目标，就像它接收到信号时执行一样。参见第 5.5 节 [配方中的错误]，第 49 页。

## .IGNORE

如果你为 `.IGNORE` 指定了配方，那么 make 将忽略针对那些特定文件在执行配方时产生的错误。`.IGNORE` 的配方（如果有）将被忽略。如果作为没有先决文件的目标被提及，`.IGNORE` 表示忽略所有文件在执行配方时的错误。这种 `.IGNORE` 的用法仅为了历史兼容性而支持。它会影响 Makefile 中的每个配方，非常有用；我们建议你使用更具选择性的方法来忽略特定配方的错误。参见第 5.5 节 [配方中的错误]，第 49 页。

## .LOW_RESOLUTION_TIME

如果你为 `.LOW_RESOLUTION_TIME` 指定了先决文件，make 假设这些文件是由生成低分辨率时间戳的命令创建的。`.LOW_RESOLUTION_TIME` 目标的配方将被忽略。许多现代文件系统的高分辨率文件时间戳减少了 make 错误地认为文件已更新的概率。遗憾的是，主机未提供设置高分辨率文件时间戳的方法，因此像 `cp -p` 这样显式设置文件时间戳的命令会丢弃其子部分。如果文件是由此类命令创建的，你应该将其列为 `.LOW_RESOLUTION_TIME` 的先决文件，以便 make 不会误认为该文件已过期。例如：

```
.LOW_RESOLUTION_TIME: dst

cp -p src dst
```

`cp -p` 丢弃了 `src` 时间戳的子部分，即使 `dst` 是最新的，它通常也比 `src` 晚一点。`.LOW_RESOLUTION_TIME` 行使得如果 `dst` 的标记与 `src` 时间戳处于同一秒开头，make 认为 `dst` 是最新的。

由于存档格式的限制，存档成员的时间戳总是低分辨率的。你不需要将存档成员列为 `.LOW_RESOLUTION_TIME` 的先决文件，make 会自动这样做。

## .SILENT

如果你为 `.SILENT` 指定了先决文件，那么 make 在执行那些特定文件之前不会打印重制这些文件的配方。`.SILENT` 被忽略。

如果作为没有先决文件的目标被提及，`.SILENT` 表示在执行任何配方之前不打印任何配方。这种 `.SILENT` 的用法仅为了历史兼容性而支持。我们建议使用更具选择性的方法来静默特定的配方（参见第 9.7 节 [选项]，第 104 页）。

## .EXPORT_VARIABLES

只需作为目标被提及，这些后缀规则默认就会将变量导出到子过程。参见第 5.7 节 [变量到子过程]，第 52 页。

## .PARALLEL

如果 `.PARALLEL` 作为目标提及，除非给出了 `-j` 选项，否则这将串行执行所有行。该规则的先决文件将被忽略。

## .ONESHELL

如果 `.ONESHELL` 作为目标提及，则 make 将以 POSIX 模式解析并运行，这并不意味着只有符合 POSIX 的 Makefile 会被接受。在这种情况下，该目标会导致配方立即失败。

## .POSIX

如果 `.POSIX` 作为目标提及，则 make 将以 POSIX 模式运行。在这种情况下，某些 make 特性仍然可用。

# 第 4 章：编写规则

### 4.9 多目标规则

一个带有多个目标的规则等同于编写许多规则，同一个配方适用于所有目标。这在两种情况下有用：

- 你只需要先决文件，没有配方。例如：
  `kbd.o:command.h`

- 类似的配方适用于所有目标。配方不需要完全相同，可以使用自动变量来替换特定的目标（参见第 10.5.3 节 [自动变量]，第 120 页）。例如：
  `bigoutput : text.g`
  `generate text.g -big > bigoutput`
  `littleout : text.g`
  `generate text.g -little > littleout`

### 4.10 多个规则

一个文件可以是多个规则的目标。所有规则中的先决文件都被合并为该目标的先决列表。如果目标比任何规则中的任何先决文件都旧，则执行配方。

一个文件只能有一个配方。如果多个规则为同一个文件提供了配方，make 会产生错误信息。（作为一种特殊情况，如果文件名以点开头，则不打印错误信息。这种行为是为了兼容其他 make 实现……你应该避免使用它。）

有时你需要目标调用位于 Makefile 不同部分的多个配方；可以使用双冒号规则（参见第 4.12 节 [双冒号]，第 38 页）来实现。

一个只有先决文件的额外规则可以一次为许多文件提供一些额外的先决文件。例如，makefile 经常有一个变量（例如 `objects`），包含正在构建的所有输出文件的列表。如果 `config.h` 发生变化，让它们所有都重新编译的简单方法是编写如下：

```
objects = foo. bar o

foo : defs.h

bar o : defs.h test h

$(objects) : config.h
```

可以在不更改实际生成对象文件的规则的情况下插入或删除，因此当你想要偶尔添加额外的先决文件时，这是一种方便的形式。

另一个棘手在于，额外的依赖项可以通过变量来指定，该变量可以通过命令行参数在 *make* 时进行设置（参见第 9.5 节 [覆盖变量]，第 103 页）。例如，

```
extradeps=

$(objects) : $(extradeps)
```

这意味着命令 `make extrad=foo.h` 将认为 `foo.h` 是每个对象文件的前依赖项，但普通的 `make` 则不会。

如果一个目标没有任何显式规则包含相应的配方（recipe），那么 make 将搜索一个适用的隐式规则来找到它（第 10 章 [使用隐式规则]，第 111 页）。

## 4.11 静态规则

静态规则是指定多个目标并为每个目标构建依赖项名称的规则。它们比带有多个目标的普通规则更通用，因为这些目标不需要具有相同的依赖项。它们的依赖项必须是相似的，但不一定完全相同。

### 4.11.1 静态规则的语法

以下是静态规则的语法：

```
targets ... target-pattern: prereq-patterns ...

  recipe
```

`targets` 列表列出了该规则适的目标。`targets` 可以包含通配符，类似于普通规则的目标（参见第 4.3 节 [在文件名中使用通配符]，第 23 页）。

`target-pattern` 和 `prereq-patterns` 说明了如何计算每个目标的依赖项。每个目标都会与 `target-pattern` 进行匹配，以提取目标名称的一部分，称为“主体”（stem）。这个主干被替换到每个 `prereq-patterns` 中，以生成依赖项名称（来自每个 `prereq-pattern`）。

每个模式通常只匹配一次 `%`。当 `target-pattern` 匹配一个目标时，`%` 可以匹配目标名称的任何部分；这部分被称为主干。模式必须精确匹配。例如，目标 `foo.o` 匹配模式 `%.o`，主干为 `foo`。目标 `foo.c` 和 `foo.o` 不匹配该模式。

每个目标的依赖项是通过替换每个依赖模式中的 `%` 生成的。例如，如果其中一个依赖项是 `%`，那么替换主干 `foo.c` 来编写一个不包含 `%` 的模式是合法的；那么对于所有目标都是如此。

模式中的 `%` 字符可以使用前面的反斜杠（`\`）进行引用。用于引用 `%` 的反斜杠可以使用更多的反斜杠来引用。用于引用 `%` 字符或其他反斜杠的反斜杠在与文件名或替换到它的主干比较之前会从模式中移除。没有引用 `%` 字符风险的反斜杠将保持不变。例如，`'\%weird\%pattern'` 在 `%` 字符前面有 `\%weird\'`，后面有 `\'`。最后两个反斜杠会被保留，因为它们不会影响任何 \ 字符。

这里有一个示例，它从相应的 c 文件中编译每个 `foo.o` 和 `bar.o`：

```
objects = foo.o bar.o

all: $(objects)

$(objects): %o: %c

```

指定的每个目标必须匹配该目标；对于每个不匹配的目标都会发出警告。如果你有一个文件列表，其中只有部分匹配模式，你可以使用 `filter`（过滤器）来移除不匹配的文件名（参见第 8.2 节 [字符串替换与分析函数]，第 84 页）；

### 4.11.2 静态模式规则与隐式规则

静态模式规则与定义为模式的隐式规则有许多共同点（参见第 10.5 节 [定义和重新定义模式规则]，第 118 页）。两者都有一个目标的模式和用于构建依赖项名称的模式。区别在于如何决定规则的适用。

隐式规则可以适用于任何匹配其模式的目标，但它仅在目标否则没有配方时适用，且仅在找到依赖项时才适用。如果出现多个规则，则只有一个会生效；选择取决于规则的顺序。相比之下，静态模式规则允许指定你所指定的的目标列表。它不能适用于任何其他目标。如果两个冲突的规则都适用，且它们都有配方，那么由于以下原因，静态模式规则比隐式规则更好：

- 你可能希望对于某些名称无法在语法上进行归类的规则，覆盖其通常的隐式规则。
- 如果你不确定确切的内容，无关的文件会导致使用错误的隐式规则。选择可能取决于搜索隐式规则的顺序。使用静态模式规则，就不有不确定性：每个规则都适用于所指定的目标。

## 4.12 双冒号规则

双冒号规则使用 `::` 代替 `:` 写入。如果多个规则适用于同一个目标，make 将执行所有包含配方的规则。如果某些规则没有配方，make 将忽略它们。这与普通规则的处理方式不同，因为对于普通规则，make 只执行找到的第一个配方规则。如果一个目标有多个依赖项，规则将为每个依赖项执行一次。对于双冒号规则，make 会为每个依赖项执行一次。这种双冒号规则在某些情况下是必要的双冒号规则。

$(CC) -c $(CFLAGS) -o $@
```

```

```

```
