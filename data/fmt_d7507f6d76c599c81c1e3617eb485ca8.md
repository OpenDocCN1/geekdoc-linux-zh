## 域名系统

所有这些应用程序都需要 DNS 来将 IP 地址映射到主机名，反之亦然。DNS 服务器并不知道世界上所有的 IP 地址，但它可以通过查询带有其他 DNS 服务器的网络来查找未知的地址。大多数 UNIX 系统都可以运行 `named`，它是由互联网软件联盟（Internet Software Consortium）分发的 BIND（伯克利互联网域名）包的一部分。它可以作为一个独立的缓存 `名称服务器` 运行，这通常在 Linux 系统上执行以加速网络访问。

你的主客户端配置文件决定了访问域名服务器的顺序：

```
search somewhere.org
nameserver 192.168.42.1
nameserver 193.74.208.137
```

更多信息可以在 `named` 的 Info 页面、`/usr/share/doc/bind[--version]` 文件以及 BIND 项目 [http://www.isc.org/products/BIND] 首页中找到。DNS HOWTO [http://www.tld.org/HOWTO/DNS-HOWTO.html] 涵盖了如何将 BIND 作为 DNS 服务器使用。

## DHCP

DHCP 是动态主机配置协议，在较大的环境中正在逐渐取代旧的 `boot`。它用于控制关键的网络参数，例如主机的 IP 地址和名称服务器 -> DHCP 与 bootp 兼容。配置服务器，你需要阅读 HOWTO。

DHCP 客户端机器将使用 GUI 进行配置，该 GUI 用于配置 `dhcpd`（DHCP 客户端守护进程）。如果你需要将机器配置为 DHCP 客户端，请检查你的系统文档。

## 身份验证服务

### 传统

传统上，用户在本地进行身份验证，信息存储在每个系统的 `/etc/passwd` 和 `/etc/shadow` 中。即使使用网络服务进行身份验证，本地文件始终存在，用于配置管理用途的系统账户，例如 root 账户、守护进程账户，通常还用于额外的程序和目的。

这些通常是黑客检查的首选目标，因此请确保按照要求严格设置权限和所有权：

```
/etc/passwd -rw-r--r-- root
/etc/shadow -rw------- root
```

## PAM

PAM 是可插认证模块（Pluggable Authentication Module），是 Linux 使用的一种安全方法。PAM 的优势在于：

- 相比 X500，它是一种适用于应用程序的灵活认证方案。
- 开发者不需要重新编译应用程序来支持 PAM。
- 具有极大的灵活性，并且对开发者提供了良好的控制。

`/etc/pam.d` 包含 PAM 配置文件。每个应用程序或服务都有一个文件。每一行包含多个元素：

- `auth`: 提供实际的身份验证（例如请求密码）。
- `account`: 检查账户是否过期（例如检查组成员关系）。
- `password`: 用于设置密码。
- `session`: 在身份验证后执行任务（例如挂载用户目录）。

模块的堆栈顺序非常重要：

- Control Flags: 告诉 PAM 在失败或成功时采取什么操作。可以是 `required`（必须）、`requisite`（必要）或 `optional`（可选）。
- Module Path: 模块路径，通常位于 `/lib/security`。
- Arguments: 模块的信息。

密码文件会被 PAM 自动检测。更多信息可以在手册页或 Linux-PAM 项目 [http://www.kernel.org/pub/linux/pam/ 中找到。

## LDAP

轻量级目录访问协议是一种通过网络访问全局或本地目录服务的客户端/服务器系统。一种 OpenLDAP 实现。它包括 `slap`（独立服务器）、`slurpd`（独立复制服务器）、实现该协议的一系列客户端。

使用 LDAP 的主要好处是整合组织内的各种类型信息。例如，组织内的不同用户可以合并到一个 LDAP 目录中。任何需要该信息的 LDAP 启用应用程序都可以进行查询。需要目录信息的用户也可以访问它。

其他 LDAP 或 X500 的优点包括：与 X500 相比易于实现，以及拥有良好的应用程序接口（API），这意味着未来 LDAP 启用应用程序和 LDAP 网关将会增加。

在缺点方面，如果你使用 LDAP，你需要 LDAP 启用应用程序或使用 LDAP 网关的能力。虽然 LDAP 的使用只会增加，但目前适用于 Linux 的应用程序并不多。此外，LD 支持某些访问控制，但安全性功能不如 X500。

由于 LDAP 是一种开放且可配置的协议，它可以存储与特定组织结构相关的任何类型的信息。常见示例是邮箱地址查找、PAM 身份验证、电话簿和配置数据库。

详细信息请参考相关命令（如 `pammodify` 和 `ldsearch`）的手册页。更多信息可以在 LDAP HOWTO [http://www.ldap.org/HOWTO/LDAP-HOWTO.html] 中找到，该文档讨论了在 Linux 上安装、配置、运行和维护 LDAP 服务器。本 Linux 简介的作者还编写了 LDAP 操作 HOWTO [http://tille.garels.be/training/ldap/]，描述了处理 LDAP 管理、操作和服务集成时每个人应该了解的基础知识。

## Rsh, login 和 telnet

用于远程登录和远程执行命令的 `login` 和 `rsh` 命令继承自 UNIX。虽然它们因为极不安全而很少使用，但为了兼容 UNIX 程序，几乎每个 Linux 发行版都带了这些命令。

相比之下，Telnet 仍然被广泛使用，通常由系统和网络管理员使用。Telnet 是远程访问文件和远程管理最强大的工具之一，允许从互联网的任何地方进行连接。结合 X 服务器时，可以在本地显示远程图形应用程序。在本地机器上工作与使用远程机器的操作没有区别。

由于连接是不加密的，telnet 连接涉及极高的安全风险。对于常规的远程命令执行，建议使用 Secure Shell 或 `ssh`。我们将在本节的稍后部分讨论这种安全方法。
