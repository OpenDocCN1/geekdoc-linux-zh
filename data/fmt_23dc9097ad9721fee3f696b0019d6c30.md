# 调制调器配置

关于调制调器配置和初始化字符串（init strings）的说明：

配置你的调制调器软件（如 `minicom` 或 `(m)getty`）使用最高可能的速度；144k 使用 `57600 bps`，更快的调制调器使用 `115200 bps`。

许多人使用非常长且复杂的初始化字符串，通常以 `AT&F` 开头，并包含许多特定调制调器品牌和类型的命令。然而这增加了必要的复杂性。大多数程序对相同的调制调器设置都很满意，为什么不将这些设置写入你所有调制调器的非易失性内存中，并在所有程序中仅使用 `ATZ` 作为初始化字符串呢？这样，你就可以更换或升级调制调器，而无需重新配置任何软件。

大多数程序要求你使用以下设置：

- 固定波特率（无自动波特率）
- 硬件双向 `RTS-RTS` 流量控制（无 `x-on/x-off`）
- 8 位，无校验位，1 停止停止位
- 调制调器应产生真实的 `DCD` 状态 (`&C1`)
- 调制调器不应忽略 `DTR` 状态 (`&D2` 或 `&D3`)

通过 `AT&V` 或 `AT&Ix` 检查（请咨询你的调制调器文档）

这些设置并不一定与出厂默认配置 (`&F`) 相同，因此从 `AT&F` 开始初始化字符串可能不是一个好主意。明智的做法可能是只有当你有理由相信存储非易失性内存中的调制调器设置出错时，才使用 `AT&F`。

如果你认为你已经为调制调器找到了正确的设置，请使用 `AT&W` 将写入非易失性内存，并使用 `Z-modem` 传输 ASCII 文本和二进制文件进行彻底测试。只有当所有这些都完美工作时，你才应该为调制调器配置租线（leased line）。

了解如何将调制调器置于盲模式（dumb mode），更重要的是，如何将其退出盲模式；调制调器只有在不在盲模式时才能被重新配置。

确保你确实以最高可能的速度配置了调制调器。一旦进入盲模式，它将忽略所有的 `AT` 命令，因此不会将其速度调整为串口速度，而是将使用它被配置时的速度（此速度存储在 `S` 寄存器中，通过 `AT&W` 命令存储）。

现在按照如下配置你的调制调器：

- `DTR` 切换时重置 (`&D3,D1`，有时是 `S` 寄存器）。某些 ISP 要求此设置
- 租线模式 (`&L1&L2`)，咨询你的调制调器文档
- 远程调制调器自动应答 (`S0=1`)，本地发起 (`S0=0`)
- 禁用结果代码 (`Q1`，有时盲模式为此执行)
- 盲模式 (`\D1` 或 `%D1`，调制调器将忽略所有的 `AT` 命令（有时你还需要禁用 `ESC` 字符）。

将配置写入非易失性内存 (`&W`)。

# 测试

现在使用 `RS232` 线缆将调制调器连接到两台电脑，并使用 `RJ11` 线将调制调器相互连接。在两台电脑上都使用如 `Minicom` (`Linux`) 或 `modem` (`DOS`) 等调制调器程序来测试调制调器。你应该能够从一台电脑向另一台电脑输入文本，反之亦然。如果屏幕出现乱码，检查你的串口速度和其他设置。现在断开并重新连接 `RJ11` 线。等待连接重新建立。断开并重新连接 `RS232` 线缆，切换调制调器的开关，停止并重启 `minicom`。调制调器应该始终以最高可能的速度重新连接（某些调制调器带有速度指示）。检查调制调器是否实际上忽略了 `ESC` (`+++`) 字符。如有必要，禁用该字符。如果所有这些运行正常，你可能想要重新配置你的调制调器，关闭远程调制调器 (`M0`) 并本地调制调器设置为低速 (`L1`)。

# 示例

## 高科技
发起（本地）：`ATL1&C1&D3&L2%D1&W`
应答（远程）：`ATM0&C1&D3&L2%D1S0=1&W`

## DF
应通过设置 `S2>1` 来禁用 `ESC` 字符；
发起：`ATL1&L1QC1&D3S2=17\D1&W`
应答：`ATM0&L2QC1&D3S0=17\D1&W`

## US Robotics-全功能型
以下内容基于 `Rolf Raar` 提供的信息。`USR Sportster` 和 `USR Courier` 不支持租线。你需要 `Courier-everything` 版本来完成此工作。该网站上有一个网页解释了如何配置你的 `Courier` 用于租线。然而，如果你遵循这些指令，你将得到一个完全失效的调制调器，你的 `pppd` 无法对其进行控制或监控。`USR Courier` 可以通过拨开关配置，但你首先需要向它输入配置字符串。确保它使用正确的配置文件。与其他大多数调制调器不同，它有三个：`&F0`、`&F1` 和 `&F2`。默认（也是你应该使用的）是 `&F1`。然而，如果你向它发送 `AT&F`，它将加载出厂配置 `&F0`！

## 租线
对于 `DTR` 切换重置，你设置 `S` 寄存器 `13` 的第 `0` 位。这意味着你必须将 `S13` 设置为 `1`。此外，你需要进入租线模式 `&L1`; `ATS13=1&L1&W`。拨开关除以下项外全部为：
- `OFF` 禁用结果代码
- `ON` 禁用命令
- `ON` 用于发起，`OFF` 用于应答
- `OFF` 盲模式

尽管 `persist` 选项应该使这变得多余，但可以使用 `ip-down` 重新启动 `pppd`。

```bash
#!/bin/bash
case $s in
  /dev/ttyS)
    /usr/bin/sleep 30

```

如果 `pppd` 崩溃，可以通过 `persist` 选项或 `ip-up` 脚本（可选）重启。如果没有发生这种情况，脚本 `/usr/local/sbin/Test-Rem-Host-pppd` 会为你重新启动。该脚本会检查远程接口是否存在，如果不存在则将尝试启动 `pppd`。

```bash
#!/bin/bash
if ! ( /sbin/ifconfig | grep Rem_Ip / / /dev/null )
then
  # PPP 消失
  logger "Rem_Host PPP gone ; restarted"
  /usr/local/sbin/PRem_Host.sh &
fi
```

`crontab` 中的以下行每隔 5 分钟运行一次上述脚本。如果你喜欢，可以频繁运行该脚本，但我建议运行频率不要高于两分钟一次。

```cron
5 * * * * /usr/local/sbin/test-Rem-Host-pppd
```

你可以使用 `crontab -e` 编辑 `crontab`。编辑后这将重启 `cron`。它使用由环境变量 `EDITOR` 指定编辑器，该变量可能通过 `/etc/profile` 或 `~/.profile` 设置（`export EDITOR=Your_Favourite_Editor`）。

有些人从 `/etc/init.d` 运行 `pppd`，但我从未测试过。
