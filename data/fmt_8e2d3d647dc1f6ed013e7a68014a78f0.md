
脚本使用`socket`连接到Apache服务器来发送URL请求；因此，你需要确保你有`Perl`的`socket`支持。例如，在`Linux`系统中，`Perl socket`代码位于`socket.ph`中。你可以使用`locate socket.ph`来确定该文件是否存在于你的系统中。

## 创建日志文件

了解服务器的状态和配置信息对于管理服务器很有帮助，但了解谁或什么正在访问你的网站也很重要，而且令人兴奋。你可以通过使用Apache服务器的日志记录功能来学习这些信息。以下部分讨论了日志记录是如何工作的，以及如何充分利用Apache日志记录模块。

随着Web服务器软件开始出现在市场上，许多Web服务器日志分析程序也开始出现。这些程序成为许多Web管理员日常工作和生活的一部分。伴随着这一切而来的是日志文件不兼容的时代，这使得日志分析变得困难且繁琐；单一的分析程序无法在所有日志文件上工作。随后出现了通用日志格式（CLF）规范。这使得所有Web服务器能够以相对相似的方式写入日志，使从一个服务器到另一个服务器的日志分析变得更加容易。

默认情况下，标准的Apache发行版包含一个名为`mod_log_config`的模块，它负责基本的日志记录，并且默认写入CLF日志文件。你可以使用`LogFormat`指令来改变这种行为。然而，CLF涵盖了大多数环境中的日志记录需求。以下段落解释了CLF日志文件中每行内容的含义。

CLF日志文件为每个请求包含单独的一行。一行由几个用空格分隔的标记组成：

```
host ident authuser date request status bytes
```

如果一个标记没有值，则它用连字符(-)表示。这些标记的含义如下：

- `authuser`: 如果请求的URL需要成功的Basic HTTP身份验证，则该标记的值是用户名。
- `bytes`: 返回给客户端的对象中的字节数，不包括所有HTTP头部。
- `date`: 请求的日期和时间。
- `host`: 客户端的完全限定域名或其IP地址。
- `ident`: 如果`IdentityCheck`指令已启用并且客户端机器运行`identd`，则这是由客户端报告的身份信息。
- `request`: 客户端的请求行，用双引号（""）包围。
- `status`: 返回给客户端的三位数字HTTP状态码。

请参阅附录A以获取所有HTTP/1.1状态码的列表。

日期字段可以具有此格式：

```
date = [day/month/year:hour:minute:second zone]
```

日期字段的大小如表8-1所示。

**表 8-1：日期字段大小**

| 字段 | 值 |
| --- | --- |
| 日 | 2 位数字 |
| 月 | 3 个字母 |
| 年 | 4 位数字 |
| 时 | 2 位数字 |
| 分 | 2 位数字 |
| 秒 | 2 位数字 |
| 时区 | ('+' \| '-)*digit |

以下部分介绍可以与`mod_log_config`一起使用的指令。该模块有四个可用的指令。

### TransferLog 指令

`TransferLog`设置日志信息要发送到的日志文件或程序的名称。默认情况下，日志信息采用CLF格式。可以使用`LogFormat`指令定制此格式。请注意，当`TransferLog`指令位于虚拟主机容器内时，日志信息将使用在该上下文中找到的最后一个`LogFormat`指令进行格式化。然而，如果在同一上下文中未找到`LogFormat`指令，则使用服务器的日志格式。

**语法:** `TransferLog filename` | `"path_to_external/program"`

**默认设置:** 无

**上下文:** `server config, virtual host`

`TransferLog`指令接受日志文件路径或指向外部程序的管道作为参数。如果找不到前导/字符，则假定日志`filename`相对于`ServerRoot`设置。例如，如果`ServerRoot`设置为`/etc/httpd`，则以下命令告诉Apache将日志信息发送到`/etc/httpd/logs/access.log`文件：

```
TransferLog logs/access.log
```

当参数是到外部程序的管道时，日志信息被发送到外部程序的标准输入(STDIN)。

**注意**

如果VirtualHost从主服务器继承`TransferLog`，则不会为其启动新程序。如果使用程序，则它将在启动`httpd`的用户下运行。如果服务器是由`root`启动的，则这是`root`。务必确保程序是安全的。

### LogFormat 指令

`LogFormat`设置由`TransferLog`指令指定的默认日志文件的格式。如果你在指令行中为格式包含一个昵称，你可以在其他`LogFormat`和`CustomLog`指令中使用它，而不是重复整个格式字符串。定义昵称的`LogFormat`指令没有其他作用；也就是说，它仅定义昵称，并不实际应用该格式。

**语法:** `LogFormat format [nickname]`

**默认设置:** `LogFormat "%h %l %u %t "%r" %>s %b"`

**上下文:** `Server config, virtual host`

有关可用的格式选项的详细信息，请参阅本章后面“自定义你的日志文件”部分。

### CustomLog 指令

与`TransferLog`指令类似，此指令允许你将日志信息发送到日志文件或外部程序。然而，与`TransferLog`指令不同的是，它允许你使用可以作为参数指定的自定义日志格式。

**语法:** `CustomLog file | pipe [format | nickname] [env=[!]environment_variable]`

**默认设置:** `None`

**上下文:** `Server config, virtual host`

例如，在下面的例子中，访问日志文件中的每一行都将使用给定的格式说明符写入。格式指定了日志文件每一行的格式：

```
CustomLog logs/access.log "%h %l %u %t \"%r\" %>s %b"
```

可用于格式的选项与`LogFormat`指令的参数完全相同。如果格式包含空格（在几乎所有情况下都会包含），则应将其包围在双引号中。代替实际的格式字符串，你可以使用由`LogFormat`指令定义的格式昵称。例如：

```
LogFormat "%h %t \"%r\" %>s" myrecfmt
CustomLog logs/access.log myrecfmt
```

此处`access.log`将包含`myrecfmt`格式的行。

> `TransferLog`和`CustomLog`指令可以在每个服务器中多次使用，以便将每个请求记录到多个文件中。例如：
> `CustomLog logs/access1.log common`
> `CustomLog logs/access2.log common`
>
> 此处，服务器将为每个请求创建两个日志条目，并将每个条目分别存储在`access1.log`和`access2.log`中。除非你在每个日志中使用不同的格式，并且因为不同的原因需要每种格式，否则这真的没什么用。

最后，如果你使用`mod_setenvif`（默认已安装）或URL重写模块（`mod_rewrite`，默认未安装）根据请求的URL设置环境变量，你可以使用`CustomLog`指令的`env=[!]environment_variable`选项来创建条件日志记录。例如，假设你允许用户下载PDF白皮书，并希望将所有章节记录到名为`whitepaper.log`的日志文件中，该文件位于你常用的日志目录中。以下是必要的配置：

```
SetEnvif Request_URI \.pdf$ whitepaper
CustomLog logs/whitepaper.log common env=whitepaper
CustomLog logs/access.log common env=!whitepaper
```
