
要创建一个包，你必须为其创建一个 `rpm` 规范文件。该文件指定了要包含的文件、构建软件的操作以及有关软件包的信息。规范文件设计用于让程序经过几个阶段，从从归档中解压开始，然后编译其源代码，最后生成 `rpm` 包。规范文件中包含了针对不同阶段的段以及执行这些阶段的特殊 `rpm` 宏。如下：

| 段落 | 说明 |
| :--- | :--- |
| `%description` | 软件的详细描述。归档和补丁的准备阶段 |
| `%prep` | 解压归档的准备宏 |
| `%setup` | `-n` 选项重置 `BUILD` 目录的名称 |
| `%patch` | 更新补丁的准备宏 |
| `%build` | 编译软件的构建阶段 |
| `%install` | 安装软件的安装阶段 |
| `%files` | 包中要包含的文件列表。`-f` 选项指定一个文件 |
| `%config` | 包中要包含的文件列表。`-f` 选项指定一个文件 |
| `%doc` | 包中要包含的文件列表。`-f` 选项指定一个文件 |
| `%pre` | 安装前的宏 |
| `%preun` | 卸载前的宏 |
| `%post` | 安装后的宏 |
| `%postun` | 卸载后的宏 |

## 创建包的 rpm 命令

要创建一个 `rpm` 软件，你可以在使用 `rpm` 命令时配合 `rpm` 构建选项（如下表所示），并在后跟上 `spec` 文件的名称。`-bl` 选项检查软件所需的所有文件都存在。`-bb` 选项仅生成二进制包，而 `-ba` 则同时构建二进制包和源码包。`-ba` 和 `-bb` 期望在构建树的 `SOURCES` 目录中找到软件的压缩存档。它执行 `rpm spec` 脚本中指定的每个阶段，从 `prep` 阶段开始解压存档，然后编译程序，随后安装到系统上，最后创建包。用于可执行二进制文件的完整 `rpm` 包被放置在构建树 `RPMS` 目录的子目录中。该子目录将具有代表当前平台的名称。对于 PC，这将是 `i386`，软件包将放置在 `RPMS/i386` 子目录下。源码包则直接放置在 `SRPMS` 目录中。

以下程序同时生成二进制包和软件包，并将它们放置在构建树的 `RPMS/i386` 和 `SRPMS` 目录。此示例中 `spec` 文件的名称为 `bookspec`。

```
rpm -ba bookspec
```

可执行二进制包的名称将由软件名称、版本号、发布号、平台名称（`i386`）和终端 `rpm`组成。名称、版本和发布号之间用连字符分隔，而发布号、平台名称和 `rpm` 终端之间用点号分隔。使用 `bookspec` `spec` 脚本由上一个示例生成的二进制包名称将是：

`bookrec-1.0-2.i386.rpm`

源码包将具有相同的名称，但平台名称被替换为 `src`：

`bookrec-1.0-2.src.rpm`
