## 本地端口转发

本地转发允许你将本地机器的端口转发到远程主机。当你需要访问防火墙后的服务时，这非常有用。本地转发的语法为：

在此命令中，`remote_port` 是远程主机上的端口，`local_host` 是本地机器的主名，`local_port` 是本地机器上的服务端口。例如，如果你想将本地机器的 8080 端口暴露给远程-sys，你可以使用：

Shell 会话将持续直到用户在远程 Shell 提示符处输入 `exit` 命令或通过关闭远程连接来退出。此时，本地 Shell 会话将恢复，本地 Shell 提示符会重新出现。

也可以使用不同的用户名连接到远程系统。例如，如果本地用户在远程系统上有一个名为 `bob` 的账户，用户可以如下方式登录远程系统上的 `bob` 账户：

```bash
上次登录：2025年8月30日 周六 13:03:21

```

如前所述，`ssh` 会验证远程主机的真实性。如果远程主机未通过身份验证，将出现以下消息：

```bash
me@linux:~$ ssh remote-sys

############################################################
可能有人正在进行某些坏事！
```

远程主机发送的 ECDSA 密钥指纹为

SHA256:9u0dXHzPbzAIJs8ZDANfvy7ksU04MjySpR4KUTSKA。

请联系您的系统管理员。

在 `/home/me/.ssh/known_hosts` 中添加正确的主机密钥以消除此消息。

`/home/me/.ssh/known_hosts:42` 中的违规 ECDSA 密钥

```bash
ssh-keygen -f /home/me/.ssh/known_hosts -R "remote-sys"
```

remote-sys 的主机密钥已更改，且你请求了严格检查。

主机验证失败。

此消息由两种可能的情况之一引起。首先，攻击者可能尝试进行中间人攻击。这种情况很罕见，大家都知道 ssh 会就此警告用户。更可能的元是远程系统发生了某种变化；例如，你的操作系统或 SSH 服务器被重新安装了。对于第一种可能性，不应断然否定。每当出现此消息时，请务必向远程系统的管理员确认。

在确定消息是由良性引起后，在客户端修复问题是安全的。这可以通过警告消息提供的建议来实现：

```bash
ssh-keygen -f /home/me/.ssh/known_hosts -R "remote-sys"
```

如果无效，我们可以使用文本编辑器（可能是 vim）从 `~/.ssh/known_hosts` 文件中删除过时的密钥。在之前的例子中，我们看到：

`/home/me/.ssh/known_hosts:42` 中的违规密钥

这意味着 `known_hosts` 文件的第 42 行包含该密钥。从文件中删除此行，`ssh` 程序即可接受来自远程系统的新的身份验证凭据。

除了在远程系统上开启会话外，`ssh` 允许你在远程主机上执行单条命令并将结果显示在本地系统中，使用方法：


## SCP 和 SFTP

OpenSSH 软件包还包含了两个用于在主机间拷贝文件的程序：`scp`（安全拷贝）和 `sftp`（安全文件传输协议）。

## SCP

`scp` 是一个在主机之间之间安全拷贝文件的命令行工具。它使用 SSH 进行传输。`scp` 的语法为：

```bash
scp [options] source destination
```

例如，将本地机器的文件拷贝到远程主机：

```bash
scp file.txt user@remote-sys:/path/to/destination/
```

将远程主机上的文件拷贝到本地机器：

```bash
scp user@remote-sys:/path/to/file.txt .
```

### SFTP

`sftp` 是一个运行在 SSH 之上的交互式文件传输协议。它比 `scp` 更灵活，并提供了管理远程系统的 shell 接口。你可以启动 `sftp` 会话：

```bash
sftp user@remote-sys
```

连接 `sftp` 会话后，可以使用类似于 ftp 的命令：

- `ls`: 列出远程主机文件
- `cd`: 目录
- `get`: 从远程主机下载文件
- `put`: 上传文件到远程主机
- `rm`: 删除远程主机文件
- `quit`: 退出 `sftp` 会话

## 注意

SFTP 协议被 Linux 中的许多图形化文件管理器支持。使用 GNOME 或 KDE，我们可以在位置栏输入以 `sftp://` 开头的 URI 并操作存储在远程系统上的文件。

## 17: 查找文件

当我们漫步在 Linux 系统中时，有一点变得非常清晰：一个典型的 Linux 系统有大量的文件！这引出了一个问题：“我们如何找到这些东西？”我们已经知道 Linux 文件系统根据从前的一代 Unix 类系统传递给下一代的约定进行了良好的组织，但海量的文件数量可能会带来一个令人生生畏的问题。

在本章中，我们将查看两个用于在系统中查找文件的工具：

- `locate` 按名称查找文件。
- `find` 在目录层级结构中搜索文件。

我们还将查看一个经常与文件搜索命令配合使用的命令，用于处理生成的文件列表：

- `xargs` 从标准输入构建并执行命令行。

此外，我们还将介绍两个辅助我们进行探索的命令：

- `touch` 修改文件时间。
- `stat` 显示文件或文件系统的状态。

## locate—简单地查找文件

`locate` 程序对路径进行快速数据库搜索，并输出匹配给定子字符串的所有名称。例如，假设我们要找到所有名称以 `zip` 开头的程序。由于我们正在寻找程序，可以假设包含程序的目录名以 `bin/` 结尾。因此，我们可以尝试：

```
[me@linuxbox ~]$ locate bin/zip
```

`locate` 将搜索其路径数据库，并输出任何包含字符串 `bin/zip` 的项。

```
/usr/bin/zip
/usr/bin/zipcloak
/usr/bin/zipgrep
/usr/bin/zipinfo
/usr/bin/zipnote
/usr/bin/zipsplit
```

如果搜索需求并不简单，我们可以将 `locate` 与 `grep` 等其他工具结合，设计更有趣搜索。

```
[me@linuxbox ~]$ locate zip | grep bin
/bin/bunzip2
/bin/bzip2
/bin/bztp2recover
/bin/gunzip
/bin/gzip
/usr/bin/funzip
/usr/bin/ggg-zip
/usr/bin/preunzip
/usr/bin/prezip
/usr/bin/prezip-bin
/usr/bin/unzip
/usr/bin/unzipfx
/usr/bin/zip
/usr/bin/zipcloak
/usr/bin/zipinfo
/usr/bin/zipnote
/usr/bin/zipsplit
```

`locate` 程序已经存在多年，并且有几种常用的变体。在现代 Linux 发行版中，常见的两种是 `locate` 和 `locate`，尽管它们通常通过一个名为 `locate` 的符号链接访问。不同版本的 `locate` 在表达式匹配（我们将在第 19 章中介绍）和通配符支持方面存在重叠。检查 `locate` 的 man页（帮助文档）以确定安装了哪个版本的 `locate`。

## locate 数据库来自哪里？

你可能会注意到，在某些发行版中，`locate` 在系统安装后立即无法工作，但如果你第二天再试，它就能正常工作。这是为什么？`locate` 数据库是由另一个名为 `updatedb` 的程序创建的。通常，它作为 cron 任务定期运行，即由 cron 守护进程按间隔执行的任务。大多数配备 `locate` 的系统每天运行一次 `updatedb`。由于数据库不是持续更新的，你会发现使用 `locate` 时，非常最近的文件不会显示。为了克服这个问题，可以通过成为超级用户并在提示符处运行 `updatedb` 来手动运行 `updatedb` 程序。

## find 费力地查找文件

虽然 `locate` 程序可以仅根据名称找到文件，但 `find` 程序根据各种属性在给定的目录（及其子目录）中搜索文件。我们将在 `find` 上花费大量时间，因为它有很多有趣的功能，我们将在之后再次看到它们，并在后面的章节开始介绍编程概念时再次遇到它们。

在最简单的用法中，`find` 被赋予一个或多个要搜索的目录名称。例如，要列出我们主目录的列表，我们可以使用：

```
find ~ -ls
```

在许多活动账户上，这将产生一个很大的列表。如果将列表发送到标准输出，我们使用 `wc` 来统计文件数量。

```
find ~ | wc -l
```

哇，我们可忙坏了！`find` 的美之处在于它可以被用于识别符合特定标准的文件。它是通过（略显奇怪的）选项、测试和动作的应用来实现的。我们将首先查看测试。

## 测试

假设我们想从搜索中获取目录列表。为了这样做，我们可以添加以下测试：

```
find ~ -type d -l
```

添加测试 `-type d` 将搜索限制在目录上。相反，我们可以通过此将搜索限制为普通文件：

```
find ~ -type f -l
```
