### 5.7.1 MAKE 命令的工作原理

递归 `make` 命令应该使用变量 `MAKE`，而不是显式的命令 'name'，如下所示：

`subsystem:`

```
cd subdir && $(MAKE)
```

该变量的值是调用 `make` 时使用的文件名。如果此文件名为 `'/bin/make'`，那么配方就是 `'cd subdir && /bin/make'`。如果你使用某个版本的 `make` 来运行顶层 `makefile`，那么在递归调用时将执行该特殊版本。

一个特殊特性是，在配方规则中使用 `MAKE` 会改变 `'-touch'`、`'-n'` `'--dry-print'` 或 `'-q'` `'--query'` 选项的效应。使用 `MAKE` 变量的效果与在行首使用 `'-'` 字符的效果相同。这一特殊特性只有在配方中**直接引用** `MAKE` 变量时才会启用；如果通过另一个变量的展开来引用 `MAKE` 变量，则不适用。在后一种情况下，你必须使用 `'-'` 令牌来获得这些特殊效应。

考虑配方中的命令 `'-t'`，它将目标标记为新的但不实际运行配方（参见第 9.3 节 [代替执行]，第 101 页）。按照 `'-t'` 的通常定义，执行文件中的 `make` 命令将创建一个名为 `'subsystem'` 的文件且什么都不做。你真正想让它做的是 `'cd subdir && make -t'`；但这将执行配方，而 `'-t'` 表示不执行配方。

这种做法带来的特殊特性是：只要配方规则的某行包含变量 `MAKE`，标志 `'-t'` 和 `'-q'` 就不适用于该行。尽管存在导致大多数配方运行的标志，包含 `MAKE` 的配方行仍正常执行。通常的 `MAKEFLAGS` 机制会将标志传递给子 `make`（参见第 5.7.3 节 [向子 make 传递选项]，第 54 页），因此你触摸文件或打印配方的请求会传播到子系统。

### 5.7.2 向子 make 传递变量

顶层 `make` 的变量值可以通过显式请求通过环境变量传递给子 `make`。这些变量在子 `make` 中被定义为默认值，但除非你使用 `'-e'` ，否则它们不会覆盖子 `make` 使用的 `makefile` 中的变量（参见第 9.7 节 [选项总结]，第 104 页）。

通过显式请求，`make` 仅当变量最初在环境中或命令行中定义，且其名称由字母、数字和下划线组成时才会导出。某些 `shell` 无法处理由字母、数字和下划线以外字符组成的环境变量。

特殊的 `MAKEFLAGS` 总是被导出的（除非你取消导出）。如果你设置了 `MAKEFILES`，它也会被导出。

`make` 会自动传递由 `make` 默认创建的变量值（参见第 10.3 节 [隐含规则使用的变量]，第 115 页）。子 `make` 将为自己定义这些变量。

如果你使用递归层级的 `make` 调用，`'-w'` 或 `'--print-directory'` 选项可以通过在 `make` 开始和结束每个目录时显示该目录，使输出更易理解。例如，如果在 `'/u/gnu/make'` 目录下运行 `make -w`，`make` 将打印一行如下形式的输出：

在执行其他操作之前，以及在处理完成后打印一行如下形式的输出：

## 5.8 定义预定义配方 (Canned Recipes)

当一组命令序列在制作各种目标时很有用，你可以使用 `define` 指令将其定义为一个预定义序列（canned sequence），并在这些目标的配方中引用该预定义序列。预定义序列实际上是一个变量，因此其名称不能与其他变量冲突。

这里是一个定义预定义配方的示例：

```
define run-yacc
yacc $(firstword $$
mv y.tab.c $$
end
```

这里 `run-yacc` 是正在定义的变量名；`end` 标记定义的结束；中间的行是命令。`define` 指令不会展开预定义序列中的变量引用和函数；`'$'` 字符、括号、变量名等都将成为你所定义的变量的一部分。参阅第 6.8 节 [多行变量]，第 69 页以获取关于 `define` 的完整解释。

使用 Yacc 的第一个命令是任何使用该预定义序列的规则的第一个前提条件。Yacc 的输出文件始终是 `'y.tab.c'`。第二个命令将输出移动到规则的目标文件名。
