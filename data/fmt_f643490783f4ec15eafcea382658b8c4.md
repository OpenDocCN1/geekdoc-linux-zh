## 1.3 文件系统完整性检查

`AIDE` 是一个文件完整性检查工具，本质上类似于 `Tripwire`。虽然它不能阻止入侵，但可以在文件更改时通过发出警报来检测配置文件的未经更改。在设置 `AIDE` 时，请内部决定站点关于完整性检查策略。在继续之前，请查看 `AIDE` 快速入门指南和 `AIDE` 文。

### 1.3.1 确保已安装 AIDE（自动化）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

`AIDE` 对文件系统状态进行快照，包括修改时间、权限和文件哈希，然后将其与文件系统的当前状态进行比较，以检测系统的修改。

**原理：**

通过监控文件系统状态，可以检测到被破坏的文件，以防止或限制意外或恶意配置错误或被修改的二进制文件的暴露。

**审计：**

运行以下命令验证 `AIDE` 是否安装：

```bash
# dpkg-query -W -f='$(binary:Package)\t$(Status)\t$(db:Status-Status)\n' aide
```

输出示例：

```text
aide-common
```

或者：

```text
aide install ok installed installed
aide-common install ok installed installed
```

**修复：**

使用适当的包管理器或手动安装安装 `AIDE`：

```bash
# apt install aide aide-common
```

根据您的环境适当配置 `AIDE`。选项请参考 `AIDE` 文档。

运行以下命令初始化 `AIDE`：

```bash
# aideinit
# mv /var/lib/aide/aide.db.new /var/lib/aide/aide.db
```

**附加信息：**

预链接（`prelinking`）功能可能会干扰 `AIDE`，因为它会更改二进制文件以加快其启动速度。运行 `prelink -ua` 将二进制文件恢复到其预链接状态，从而避免 `AIDE` 产生误报。

## 1.4 安全启动设置

本节建议重点关注安全加载程序和涉及启动过程的设置。

### 1.4.1 确保设置了加载程序密码（自动化）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

设置启动密码将要求重启系统的人输入密码后才能设置命令行参数。

**原理：**

在执行加载程序时要求密码将防止未经授权的用户进入启动参数或更改引导分区。这防止了用户削弱安全性（例如在启动时关闭 `AppArmor`）。

**影响：**

如果启用了密码保护，只有指定的超级用户可以通过按“`c`”编辑 `Grub` 2 菜单项或按“`c`”访问 `GRUB` 2 命令行。如果 `Grub` 2 设置自动启动到受保护的菜单项，用户没有选项退出密码提示来选择其他菜单项。在这种情况下按 `SHIFT` 键不会显示菜单。用户输入正确的用户名和密码。如果无法，将通过 `LiveCD` 或其他手段编辑配置文件来解决问题。

您可以在菜单项中添加 `--unrestricted` 以允许系统在不需要密码的情况下启动。编辑菜单项仍需要密码。

**审计：**

运行以下命令并验证匹配项：

```bash
# grep "^set superusers=" /boot/grub/grub.cfg

set superusers="<username>"
# grep "^password" /boot/grub/grub.cfg

password_pbkdf2 <username> <encrypted-password>
```

更多信息：`https://help.ubuntu.com/community/Grub2/Passwords`

**修复措施：**

使用 `grub-mkpasswd-pbkdf2` 创建加密密码：

```bash
# grub-mkpasswd-pbkdf2
Enter password: <password>
Reenter password: <password>
PBKDF2 hash of your password is <encrypted-password>
```

将以下内容添加到自定义的 `/etc/grub.d` 文件中：

```bash
cat <<EOF
set superusers="username"
password_pbkdf2 <username> <encrypted-password>
EOF
```

超级用户/用户信息和密码不应包含在 `/etc/grub.d/00_header` 文件中，因为这在软件包更新时可能会被覆盖。如果要求在不输入密码的情况下启动/重启，请编辑 `/etc/grub.d/10_linux` 并在 `CLASS=` 行中添加 `--unrestricted`。

示例：

```bash
CLASS="--class gnu-linux --class gnu os --class --unrestricted"
```

运行以下命令更新 `grub2` 配置：

```bash
# update-grub
```

**默认值：**

此建议围绕 `grub` 引导加载器设计，如果您的环境中使用了 `LILO` 或其他引导加载器，请实施相应的设置。

将 `/boot/grub/grub.cfg` 替换为适用于您环境的 `grub` 配置文件。

**其他信息：**

`/etc/grub.d/10_linux` 的更改在更新 `grub-common` 软件包时可能会被覆盖。在重启系统之前，您应该检查此文件的任何更改，否则在下次启动时可能会意外提示输入密码。

### 1.5.2 确保未安装 prelink（自动化）

配置适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

`prelink` 是一个修改 `ELF` 共享库和 `ELF` 动态链接二进制文件的程序，它使得动态链接器在启动时执行重定位所需的时间显著减少。

**原理：**

预链接（`prelinking`）功能 可能会干扰 `AIDE` 的操作，因为它更改了二进制文件。如果恶意用户能够破坏如 `libc` 等常用库，预链接还可能会增加系统的脆弱性。

**审计：**

验证 `prelink` 是否未安装：
