# 前言

在《Unix哲学》出版几年后，原 Digital Press 出版人 Phil Sutherland 找到我，想让我写关于 Linux 的书。他说 Linux 将变得巨大，并认为需要一本类似于“Linux 哲学”之类的书。Phil 和我在在一系列持续了一多年的邮件交流中详细讨论了这个话题。尽管这种书的需求是显而易见的，且有丰富的想法可以填充它，但似乎有些地方就是不对劲。

Phil 一直在推动出版《Unix哲学》的 Linux 版，这从营销角度来看显然是有意义的。但我看到 Linux 社区发生了不同的事情。Unix 世界流淌着一股新的活力。老牌 Unix 开发者成功地将“Unix 思维方式”的知识注入到新一代、充满活力的黑客和其他爱好者的脑海中，他们喜欢在自己的机器上玩弄 Linux 的内部。Linux 是 Unix，没错，但它不是你父亲那时代的 Unix。

我曾想在一部名为《Linux 宣言》（The Linux Manifesto）的书书中捕捉这种创新精神。最终很明显，“开源”才是 Linux 的本质。所以，如果符合主题，它应该是《开源宣言》。但 Eric Raymond 已经在他的经典著作《大教堂与集市》（*The Cathedral and the Bazaar*）中写过关于开源的“这就是我们为什么这么做”的文章了。我不打算做一本模仿的作品，所以这个想法被搁置了一段时间。

当原始想法没有成效时，好想法往往会以不同的形式回来。Digital Press 的 Pam Chester 几年前向我指出，《Unix哲学》中的一些信息已经过时了，并问我是否有兴趣进行修订。但人们如何修订一种哲学呢？如果某事是真理，那么它在一个月后、一年后，甚至几个世纪后，它将仍然是真理。

然后我终于明白了。《Unix哲学》一书作为对 Unix 思维方式的描述，是一个“第一系统”。它现在正被引入变成“第二系统”。而在这种情况下，第二系统是第一个系统中更完整、更成熟、更相关的元素。如果说《Unix哲学》是基本需求，那么《Linux 与 Unix 哲学》将原始概念推向前并探索了新领域。它也保留了原始的哲学原则，因为真理仍然是真理。

所以，第一本书的读者在这里发现许多熟悉的观点。Unix 哲学的原始原则仍然完好无损，但我检查了每一章，研究在 Linux 环境下如何最好表达这些。从某种意义上说，这本书是第一本的修订。但在另一个方面，它在探索新的领域。开发者们在反馈中提到了这一点。它帮助我以第一本从未做过的方式看待 Unix。告诉人们 Unix 哲学如何影响 Unix 程序员编写操作系统是一回事，而这是一个更大胆的论断。

# 章节概述

在当今节奏快、竞争激烈的开发环境中工作的其他资深开发人员经常发现，要遵循良好的软件设计原则往往面临着巨大的压力。在其他情况下，许多人强调使用新的开发流程，因为这些流程是确保其方法具有足够实质内容的最新潮流。当设计问题似乎无法解决，或者解决方案包含令人怀疑的假设时，这本书可以充当一种“清醒检查”。

在商业世界中，当今的 IT 经理已经了解了 Linux。由于预见到能够降低成本开支，许多人正考虑将其引入到自己的环境中。他们的策略通常是将较旧的 Solaris 和 HP-UX 平台替换为更便宜的基于 Intel 或 AMD 架构的 Linux 服务器，以处理那些不关键的应用。随着 IBM 和 Oracle 进一步增强其 Linux 产品，将主服务器切换到 Linux 将成为比几年前更可以接受的选项。

然而，尽管如此，IT 经理一直一直将他们的桌面用户迁移到 Linux。这本书将帮助他们意识到，Linux 不仅是一个可行的替代方案，实际上还是首选的替代方案。他们会发现 Linux 和开源软件背后的哲学使得桌面比基于 Windows 的对应产品更容易维护、成本更低且更安全。让 Linux 成为理想服务器的理念也延伸到了桌面。在他们回答“是的，但是……”之前，我有一句话想对他们说：读这本书。

最后，处理抽象思想世界的人将在学习 Unix 哲学中找到共。许多用于开发软件的技巧也适用于其他努力。作家、平面艺术家、教师和演讲者可能会发现，快速原型设计和利用工作在他们的领域同样适用。而且由于现在有大量廉价（即“免费”）应用程序，他们可以负担得起以前对他们来说太贵而无法探索的工具。

## 各章简介

第 1 章“哲学：千军万马”探讨了 Unix 哲学的历史以及它是如何产生的。它还简要描述了 Unix 哲学的原则，作为后续章节中更详细解释的序言。

第 2 章“人类的一大小步”展示了为什么小组件是构建大型系统的最佳选择。它讨论了它们在软件系统和物理世界中良好交互的能力。本章的最后部分关注于“良好做好一件事”的程序的重要性。

第 3 章“为了乐趣和利润的快速原型设计”强调了在设计成功产品时尽早构建原型的必要性。对“人的三个系统”的讨论说明了所有软件都会经历的阶段。它将快速原型设计维护为通往第三系统（三个中最正确的一个）的最快途径。

第 4 章“可移植性优先”为软件的可移植性提供了不同的视角。它强调软件开发人员在设计中必须在效率和移植性之间做出选择。研究了 Atari VC 作为高效但有限移植性的模型。本章还强调了数据可移植性重要且经常被忽视的，一个典型 Unix 用户工具集的案例研究提供了一个由于可移植性而导致软件寿命极佳示例。

第 5 章“这才是杠杆！”讨论了“软件杠杆”的概念，即重用组件会导致更大的影响。我们看到使用 shell 脚本如何实现高杠杆作用。

第 6 章“交互式程序的危险”开始定义捕获式用户界面。它建议开发者限制其用法，转而关注让程序与其他程序有更好的交互。它表达了所有程序都是过滤器的观点。本章以对 Unix 环境过滤器的讨论结束。

第 7 章“更多 Unix 哲学：十个次要原则”列出了 Unix 开发人员通常遵循但未认为是 Unix 哲学的主要元素的观点。由于本章涉及的概念比书中其他部分更深一层，技术性不强的读者可以随时跳过这一章。然而，Unix 拥趸们可能会觉得它很有趣。

第 8 章“让 Unix 良好做好一件事”以 Unix 邮件处理程序 MH 为示例，展示了良好的 Unix 应用是如何构建的。它以 Unix 哲总结结尾，展示了它是如何从每个元素的协同工作中获得力量。

第 9 章“Unix 和其他操作系统哲学”将 Linux 和 Unix 哲学与其他几种操作系统哲学进行比较，以强调 Unix 方法的独特之处。

第 10 章“透过黑暗的玻璃看：Linux 对比 Windows”从 Linux 和 Microsoft Windows 的高层比较开始。它论证了文本计算与使用图形用户界面之间的区别。它最后对 Unix 在某些领域遵循 Unix 哲学而在另一些领域偏离该哲学进行了回顾。

第 11 章“太奇了！”审视了 Linux 社区普及的开源软件 (OSS) 概念与 Unix 哲学的契合点。当 OSS 在所有领域都采用“Unix 思维方式”时，其传播效果最好。
