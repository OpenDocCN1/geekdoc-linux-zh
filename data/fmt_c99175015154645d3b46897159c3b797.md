
共享内存段允许任意数量的进程之间进行快速的双向通信。每个用户都可以读取和写入，但程序必须建立并遵循某些协议，以防止竞态条件导致信息在被读取之前就被覆盖。遗憾的是，即使你使用 `IPC_PRIVATE` 创建了一个新的共享段，Linux 也不严格保证独占访问。

此外，为了让多个进程使用同一个共享段，它们必须安排使用相同的键值（`key`）。

### 5.2 进程信号量

如上一节所述，进程必须协调对共享内存的访问。正如我们在第 4 章“线程”的第 4.4.5 节“线程信号量”中所讨论的，信号量是允许同步多个线程的计数器。Linux 提供了一种不同的替代信号量，可用于同步进程（称为进程信号量，有时称为 System V 信号量）。进程信号量的分配和释放方式与共享内存段类似。虽然单个信号量对于几乎所有用途都是足够的，但进程信号量是以集合形式提供的。在本节中，我们将介绍进程信号量的系统调用，并展示如何使用它们来实现简单的二值信号量。

#### 5.2.1 分配与释放

`semget` 和 `semctl` 调用用于分配和释放信号量，其中键（`key`）指定信号量集、集合中的信号量数量以及权限标志（与 `shmget` 相同）；返回信号量标识符。你可以通过指定正确的键值来获取现有信号量集的标识符；在这种情况下，信号量的数量可以为零。

即使在所有进程终止后，信号量仍然存在。最后一个使用信号量集的进程必须显式地将其删除，以确保操作系统不会耗尽信号量资源。要实现这一点，调用 `semctl` 并传入信号量标识符、集合中的信号量数量、作为第三参数的 `IPC_RMID` 以及任何 `union sem` 值（该值会被忽略）。调用进程的有效 ID 必须与信号量分配者的 ID 匹配（或调用者是 `root`）。与共享内存段不同，删除信号量集会立即触发 Linux 释放内存。

#### 5.2.3 等待（Wait）和发布（Post）操作

每个信号量都有一个非负值，并支持等待和发布操作。`semop` 系统调用实现了这两个操作。它的第一个参数指定信号量标识符。第二个参数是 `struct semun` 元素的数组，指定了你想执行的操作。第三个参数是该数组的长度。`struct semun` 的字段列举如下：

- `sem_num` 是执行操作的信号量集中的信号量编号。
- `sem_op` 是指定信号量操作的整数。

如果 `sem_op` 是正数，则该数将立即加到信号量值上。

如果 `sem_op` 是负数，则该数的绝对值将从信号量值中减去。该调用将阻塞，直到信号量值达到 `sem_op` 的绝对值（因为其他其他进程会增加它）。

如果 `sem_op` 为零，则该操作将阻塞，直到信号量值变为零。

- `sem_flg` 是一个标志值。指定 `IPC_NOWAIT` 以防止操作阻塞；如果操作本应阻塞，则 `semop` 调用将失败。

如果你指定了 `SEM_UNDO`，Linux 会自动撤销操作。

列表 5.4 展示了二值信号量的等待和发布操作。

#### 列表 5.4 `sem_op` 二值信号量的等待和发布操作

```c
#include <sys/types.h>
#include <sys/ipc.h>
#include <sys/sem.h>

/* 等待二值信号量：直到信号量值为正，并将其减 1。 */
int binary_semaphore_wait(int semid)
{
    struct sembuf operations[1];
    /* 使用第一个信号量。 */
    operations[0].sem_num = 0;
    /* 减 1。 */
    operations[0].sem_op = -1;
    /* 允许撤销。 */
    operations[0].sem_flg = SEM_UNDO;
    return semop(semid, operations, 1);
}

/* 发布二值信号量：将其加 1。 */
int binary_semaphore_post(int semid)
{
    struct sembuf operations[1];
    /* 使用第一个信号量。 */
    operations[0].sem_num = 0;
    /* 加 1。 */
    operations[0].sem_op = 1;
    /* 允许撤销。 */
    operations[0].sem_flg = SEM_UNDO;
    return semop(semid, operations, 1);
}
```

### 5.3 映射内存

映射内存建立了文件与进程内存之间的关联。Linux 将文件分成页大小的块并将其复制到内存页中，以便在进程地址空间可用。因此，进程可以通过普通的内存访问读取文件内容，也可以通过写入内存修改文件内容。你可以将映射理解为分配一个缓冲区来存放文件，并将文件读入缓冲区。除了进程间通信外，映射文件还有其他用途。有些用途在第 5.3.1 节中讨论。

要将普通文件映射到进程内存，使用 `mmap`（"Memory Mapped"，读作 "em-map"）。第一个参数是你希望 Linux 将文件映射到进程地址空间的地址；设置为 `NULL` 允许选择一个合适的起始地址。第二个参数是映射的长度（字节）。第三个参数指定映射地址范围的保护权限。该权限由 `PROT_READ`、`PROT_WRITE` 和 `PROT_EXEC` 按位或组成，意味着读、写和执行权限。第四个参数是指定附加选项的标志。第五个参数是打开待映射的文件描述符。最后一个参数是从文件开始处映射的偏移量。通过适当选择偏移量和长度，你可以映射文件的全部或部分。

标志值是这些约束的按位或：

- `MAP_FIXED`—如果你设置了此标志，Linux 将使用你请求的地址来映射文件，而不是将其视为建议。该地址必须页对齐。
- `MAP_PRIVATE`—对内存范围的写入不会写回关联的文件，而是写到文件的私有副本中。其他进程看不到这些写入。此模式不能与 `MAP_SHARED` 一起使用。

## 第5章 进程间通信

- `MAP_SHARED`—写入会立即反映在底层文件中，而不是对写入进行缓冲。在用映射内存进行进程间通信（IPC）时使用此模式。此模式可能与 `MAP_PRIVATE` 配合使用。

如果调用成功，它返回一个指向内存起始位置的指针。如果失败，返回 `MAP_FAILED`。

当你完成内存映射后，使用 `munmap` 释放它。传递该内存区域的起始地址和长度。Linux 在进程终止时会自动取消已映射的区域。

#### 5.3.2 示例程序

让我们来看两个程序，说明如何使用内存映射区域来读写文件。第一个程序（列表 5.5）生成一个随机数并将其写入内存映射文件。第二个程序（列表 5.6）读取这些数字，打印它们，并将内存映射文件中的值替换为原值的两倍。将文件作为命令行参数输入：

#### 列表 5.5 (`mmap-write.c`) 向内存映射文件写入随机数

```c
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <time.h>
#include <unistd.h>
#define FILE_LENGTH 0x100

/* 在 [low,high] 范围内返回均匀分布的随机数。 */
int random_range(unsigned const low, unsigned const high) {
    unsigned const range = high - low + 1;
    return low + (int)(((double)range) * rand() / (RAND_MAX + 1.0));
}

int main (int argc, char const argv[]) {
    int fd;
    void *file_memory;

    /* 初始化随机数生成器。 */
    rand(time(NULL));

    /* 准备一个足够容纳无符号整数的大文件。 */
    fd = open(argv[1], O_RDWR | O_CREAT, S_IRUSR | S_IWUSR);
    lseek(fd, FILE_LENGTH+1, SEEK_SET);

    write (fd, "", 1);
    lseek (fd, 0, SEEK_SET);

    /* 创建内存映射。 */
    file_memory = mmap (0, FILE_LENGTH, PROT_WRITE, MAP_SHARED, fd, 0);
    close (fd);
    /* 将随机整数写入映射区域。 */
    printf((char*)file_memory, "%d", random_range (-100, 100));
    /* 释放内存（因为程序退出，所以不需要）。 */
    munmap (file_memory, FILE_LENGTH);

    return 0;
}
```

`mmap-write` 程序打开文件，如果文件之前不存在则创建它。`open` 的第三个参数指定以读写模式打开文件。由于我们不知道文件的长度，因此使用 `lseek` 确保文件足够大以存储一个整数，然后将文件位置移动到开头。该程序映射文件，然后关闭文件描述符，因为不再需要它。程序将一个随机整数写入映射的内存（即写入文件），然后取消映射。`munmap` 调用是不必须的，因为 Linux 在程序终止时会自动映射该文件。

- 列表 5.6 `mmap-read.c` 从内存映射文件中读取整数并将其翻倍

```c
#include <stdlib.h>
#include <stdio.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <unistd.h>
#define FILE_LENGTH 0x100

int main (int argc, char* const argv[])
{
    int fd;
    void *file_memory;
    int integer;

    /* 打开文件。 */
    fd = open(argv[1], O_RDWR, S_IRUSR | S_IWUSR);
    /* 创建内存映射。 */
    file_memory = mmap (0, FILE_LENGTH, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

    close (fd);

    /* 读取整数，打印它并将其翻倍。 */
    sscanf(file_memory, "%d", &integer);
    printf("value: %d\n", integer);
    sprintf((char*)file_memory, "%d\n", 2 * integer);
    /* 释放内存（因为程序退出，所以不需要）。 */
    munmap(file_memory, FILE_LENGTH);

    return 0;
}
```

`mmap-read` 程序从文件中读取数字并将翻倍后的值写入文件。首先，它打开文件并将其映射为读写。由于我们可以假设文件足够容纳一个无符号整数，因此不需要像上一个程序那样使用 `lseek`。程序使用 `sscanf` 从内存中读取并解析值，然后使用 `sprintf` 格式化并写入翻倍后的值。

以下是运行这些示例程序的例子。它映射了文件：

```bash
/tmp/integer-file
% /mmap-write /tmp/integer-file
% cat /tmp/integer-file
42
% /mmap-read /tmp/integer-file
value: 42
% cat /tmp/integer-file
42
```

观察到，文本 42 是在没有调用 `write` 的情况下写入磁盘的，并且在没有调用 `read` 的情况下再次被读取的。注意，这种技术是内存映射的特性。

#### 5.3.3 共享

`MAP_SHARED`—写入会立即反映在底层文件中，而不是对写入进行缓冲。在用映射内存进行进程间通信（IPC）时使用此模式。此模式可能与 `MAP_PRIVATE` 配合使用。

如果调用成功，它返回一个指向内存起始位置的指针。如果失败，返回 `MAP_FAILED`。

当你完成内存映射后，使用 `munmap` 释放它。传递该内存区域的起始地址和长度。Linux 在进程终止时会自动取消已映射的区域。

#### 5.3.4 私有映射

`MAP_PRIVATE`—写入不会反映在底层文件中，而是通过写时复制（copy-on-write）机制处理。映射的内存是进程私有的，对该区域的修改不会对其他进程可见。

#### 5.3.5 其它用法

管道（Pipes）是用于进程间通信的设备。它们是单向的，数据从“写入端”写入后按顺序从“读取端”读取。管道是同步的，数据总是按照写入的顺序读取。

管道的容量是有限的。如果写入速度快于读取进程的速度，且管道无法存储更多数据，写入者将将阻塞直到空间可用。如果读取者尝试读取但没有数据，它将阻塞直到数据可用。因此，管道会自动同步两个进程。

### 5.4.1 创建管道

要创建管道，调用 `pipe` 命令。提供一个大小为 2 的整数数组。`pipe` 调用将读取文件描述符存储在数组的 0 位，将写入文件描述符存储在 1 位。例如，考虑以下代码：

```c
int pipe_fds[2];
int read_fd;
int write_fd;

pipe(pipe_fds);
read_fd = pipe_fds[0];
write_fd = pipe_fds[1];
```

写入文件描述符 `read_fd` 的数据可以从 `write_fd` 读取。

#### 5.4.2 父子进程间的通信

`pipe` 创建的文件符仅在当前进程及其子进程中有效。然而，当进程调用 `fork` 时，文件描述符会被复制到子进程。因此，管道只能连接相关的进程。

在列表 5.7 的程序中，`fork` 产生了一个子进程。子进程继承了管道文件描述符。父进程向管道写入一个字符串，子进程读取它。示例程序使用 `fdopen` 将这些描述符转换为 `FILE*` 流。由于我们使用的是流而非描述符，因此可以使用更高级标准库 I/O 函数，如 `printf` 和 `gets`。
