
扩展模块使用以下函数将从 Python 传递到 C 的参数。它们的原型使用 `Python.h` 头文件定义。

```c
int PyArgTuple(PyObject *args, char *format, ...);
```

将 `args` 中的参数组解析为一系列 C 变量。`format` 是一个包含表26.1-26.3中零或多个字符串的字符串，描述了 `args` 的预期内容。所有剩余参数包含结果将要放置的 C 变量地址。这些参数的顺序和类型必须与 `format` 中指定的匹配。如果参数无法解析，则返回 0。

```c
int PyArgTupleAndKeywords(PyObject *args, PyObject *kwargs,
    char *format, *kwlist, ...);
```

同时解析参数组和包含 `kwargs` 中的关键字参数字典。`format` 的含义与 `PyArgTuple()` 相同。唯一的区别是 `kwlist` 是一个包含所有参数的以空结尾的字符串列表。成功返回 1，错误返回 0。

对于处理文本或二进制数据，请使用 `"s#"`、`"z#"`、`"u#"`、`"es#"` 或 `"et#"` 代码。这些转换工作方式与之前完全相同，不同之处它们还会返回一个长度。正因如此，对嵌入 NULL 字符的限制被取消了。此外，转换增加了对字节和其他支持所谓“缓冲区接口”`buffer interface` 的对象的支持。缓冲区接口是 Python 对象暴露代表其内容的原始缓冲区的一种手段。通常，你可以在字符串、字节数组和数组（例如 `array` 模块中的数组）上找到它。在这种情况下，每个对象都提供一个可读的缓冲区接口，并返回缓冲区的指针及其大小。最后，如果向 `"es#"` 和 `"et#"` 转换提供非 NULL 指针和长度，它们代表用于放置编码结果的预分配缓冲区。在这种情况下，解释器不会为结果分配新内存，你也不需要调用 `PyMem_Free()`。

`"s#"` 和 `"z#"` 的转换与 `"s#"` 和 `"z#"` 类似，它们会将接收到的数据填充到 `Py_buffer` 结构中。关于此的更多信息可以在 `PEP-3118` 中找到，该结构至少具有 `char buf`、`int len` 和 `int size` 属性，用于指向缓冲区、长度（以字节为单位）以及缓冲区包含的项目的大小。此外，解释器会在缓冲区上加锁，只要它被 C 扩展持有，就能防止其他线程对其更改。这允许扩展独立地处理缓冲区，并可能在与解释器不同的线程中运行。在所有处理完成后，调用 `PyBuffer_Release()` 是调用者的责任。

`"e#"`、`"u#"`、`"w#"` 和 `"w#"` 的转换与 `"s#"` 系列代码一样，它们只接受实现缓冲区接口的对象。`"tb"` 要求缓冲区是可读的。`"w#"` 代码要求缓冲区既可读又可写。支持可写缓冲器的 Python 对象被假定为是可变的。因此，C 扩展覆盖或修改缓冲区内容是合法的。

`"y#"`、`"y#"` 和 `"y#"` 的转换与 `"s#"` 系列代码一样，它们只接受字节字符串。这些写入函数必须只接受字节、Unicode 字符串。`"y#"` 代码只接受不包含嵌入 NULL 字符的字节字符串。

## 扩展模块

`"O"`、`S"` 和 `"U"` 限定符返回类型为 `PyObject*` 的 Python 对象。`"S"` 和 `"U"` 分别将对象限制为字符串或 Unicode 字符串。

`"O!"` 转换需要 C 参数：指向 Python 类型对象的指针，以及一个用于放置该指针的 `PyObject*` 指针。如果对象不匹配类型对象，则抛出 `TypeError`。例如：

```c
/* 解析一个列表参数 */
PyObject *listobj;
ArgParseTuple(args,"O!",&PyList_Type,&listobj);
```
