### 重定向标准输出：`>`

假设你不想在屏幕上显示文件列表，而是将此列表保存到文件中。换句话说，你希望将标准输出重定向到文件而不是屏幕。要做到这一点，你在 Linux 命令之后放置输出重定向运算符（大于号，`>`）和文件名。在下一个示例中，`cat` 命令的输出从屏幕重定向到文件。

```
$ cat myletter > newsletter
```

重定向操作会创建新的目标文件。如果文件已存在，它将被标准输出中的数据覆盖。你可以设置 `noclobber` 功能以防止通过重定向操作覆盖现有文件。在这种情况下，对现有文件进行重定向操作将失败。你可以通过在重定向运算符后放置感叹号来克服 `noclobber` 功能。下一个示例为 BASH shell 设置了 `noclobber` 功能，然后强制覆盖已存在的 `oldletter` 文件。

```
$ set -o noclobber
cat myletter > oldletter
cat: file exists
$ cat myletter >! oldletter
```

虽然重定向运算符和文件名放在命令之后，但重定向操作并不是在命令后执行的。事实上，它是在命令之前执行的。重定向操作在接收到标准输出的任何数据之前创建文件并设置重定向。如果文件已存在，它将被破坏并替换为同文件。实际上，生成输出的命令只有在重定向文件创建后才会执行。

在下一个示例中，`ls` 命令的输出从屏幕设备重定向到文件。首先，`ls` 命令列出文件，在下一个命令中，`ls` 将其文件列表重定向到 `lst` 文件。然后 `cat` 命令显示保存到 `lst` 中的文件列表。注意 `lst` 中的文件列表包含了列表本身。

```
$ ls > lst
$ cat lst
```

当你尝试对输入和输出使用同一个文件名时，会发生错误。在这种情况下，由于重定向操作首先执行，输入文件会被破坏并被空文件替换。此时 `cat` 命令尝试从输入文件读取，但它是空的。

```
$ cat myletter > myletter
```

### 追加标准输出：`>>`

你可以使用 `>>` 重定向运算符将标准输出追加到现有文件。不是覆盖文件，而是将标准输出中的数据添加到文件末尾。在下一个示例中，`myletter` 和 `oldletter` 文件被追加到 `alerts` 文件。随后 `alerts` 文件将包含 `myletter` 和 `oldletter` 的内容。

```
$ cat myletter >> aletters
$ cat oldletter >> aletters
```

### 标准输入：`<`

许多 Linux 命令从标准输入接收数据。标准输入本身从设备或文件接收数据。标准输入的默认设备是键盘。输入键盘的字符被放入标准输入，然后重定向到 Linux 命令。

如果你将 `cat` 命令与重定向结合，就可以将输入的内容保存到文件中。如下一个示例所示，`cat` 操作的输出被重定向到 `mydat` 文件。`mydat` 文件现在包含键盘输入的所有数据。在这种情况下，`cat` 命令没有文件参数。它将从标准输入接收数据并将输出到标准输出。

```
$ cat > mydat
This is a new line
for the cat
command
^D
```

```
$ cat mydat
This is a new line
for the cat
command
$
```

正如标准输出一样，你也可以重定向标准输入。标准输入可能从文件而不是键盘接收。重定向标准输入的运算符是小于号（`<`）。在下一个示例中，标准输入被重定向从 `myletter` 文件而不是键盘设备接收。`myletter` 的内容通过重定向操作读取到标准输入中。然后 `cat` 命令读取标准输入并显示 `myletter` 的内容。

```
$ cat < myletter
```

你可以结合针对标准输入和标准输出的重定向操作。在下一个示例中，`cat` 命令没有文件名参数。在没有文件名参数的情况下，`cat` 命令从标准输入接收输入并将输出发送到标准输出。然而，标准输入已被重定向为从一个文件接收数据，而标准输出已被重定向为将其数据放入文件中。

```
$ cat < myletter > newsletter
```

## 管道 (Pipe)

你会发现自己经常需要将数据从一个命令发送到另一个命令。换句话说，你希望将一个命令的标准输出发送到另一个命令，而不是发送到目标文件。假设你想将文件名列表发送到打印机。你需要两个命令来实现这一点：`ls` 命令生成文件名列表，以及 `lpr` 命令将列表发送到打印机。实际上，你需要获取 `ls` 命令的输出并将其作为 `lpr` 命令的输入，为了在 Linux 中形成这种连接，你可以将数据想象成从一个命令流向另一个命令，而你使用的被称为管道。管道操作符（竖线字符：`|`）放在两个命令之间，在它们之间建立了连接。一个命令的标准输出变成另一个命令的标准输入。管道操作接收位于管道之前的命令的输出，并将这些数据作为输入发送给位于管道之后的命令。如下一个示例所示，你可以用管道连接 `ls` 命令和 `lpr` 命令。`ls` 命令输出的文件名列表被管道到 `lpr` 命令。

```
$ ls | lpr
```

你可以将管道操作与其他 shell 特性（如特殊字符）结合使用，以执行专门的操作。下一个示例仅打印带有 `.c` 扩展的文件。使用 `ls` 命令配合星号 `*` 和 `.c` 来生成带有 `.c` 扩展的文件名列表。然后，该列表被管道到 `lpr` 命令。

## 操作符 19

```
$ ls *.c | lpr
```

重定向仅仅是将输出放置在文件中，而管道则将输出发送到另一个 Linux 命令。你可能会奇怪为什么这不能通过重定向来实现。你需要记住文件和命令之间的区别：文件是用于存储数据的介质，你可以在上面保存数据或从上面读取数据。命令是执行指令的程序。命令可以读取或保存文件中的数据，但命令本身并不是文件。出于此原因，重定向操作作用于文件，而不是命令。重定向可以将数据从程序发送到文件，或从文件发送到程序，但它不能直接从一个程序发送数据到另一个程序。只有文件可以作为重定向操作的目标，其他程序不能。

然而，你可以通过一系列重定向操作模拟管道过程。你可以将一个命令的输出发送到一个文件。然后在下一行中，你可以使用该文件作为重定向输入执行一个命令。下一个示例在两个独立的命令中使用了两次重定向操作来打印文件名列表。同样的任务在之前的示例中使用单个管道操作就完成了。管道操作在字面上获取了一个命令的标准输出，并将其作为另一个命令的标准输入。

```
$ ls > tempfile
$ lpr < tempfile
```

到此为止，我们一直使用文件名列表作为输入，重要的是，管道作用于命令的标准输出，无论输出是什么。整个文件甚至多个文件的内容都可以从一个命令管道到另一个命令。在下一个示例中，`cat` 读取并输出了 `mydata` 文件的内容，然后这些内容被管道到 `lpr` 命令。

```
$ cat mydata | lpr
```

假设你想打印从键盘上输入的数据，而不是从文件中打印数据。记住，不带任何参数的 `cat` 命令从标准输入读取数据。在下一个示例中，`cat` 从键盘而非文件输入，并将输出管道到 `lpr` 命令。`cat` 命令在 `lpr` 命令之前执行，因此你首先在键盘上为 `cat` 命令输入数据，并以文件结束符 `CTRL-D` 结尾。管道流的输入可能来自任何源。

```
$ cat | lpr
This text will
be printed
^D
$
```

Linux 为 `cat` 提供了一个 `-n`，它可以输出文件内容并添加行号。如果你想带行号打印文件，必须先使用带有 `-n` 的 `cat` 命令输出带有行号的文件内容。然后你将此输出管道到 `lpr` 命令进行打印，例如：

```
$ cat -n mydata | lpr
```

显示带行号的文件时做了类似的操作。在这种情况下，编号输出通常被管道到 `more` 命令进行逐屏检查。你甚至可以指定多个文件并将它们的输出管道到 `more` 命令，从而检查所有文件。在下一个示例中，`mydata` 和 `preface` 被编号并管道到 `more` 命令进行逐屏检查。

```
$ cat -n mydata preface | more
```
