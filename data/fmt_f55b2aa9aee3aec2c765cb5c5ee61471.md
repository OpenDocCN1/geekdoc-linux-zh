
如果在 Linux 社区中度过一段时间，我们会听到许多关于众多 Linux 发行版中哪一个“最佳”的意见。通常，这些讨论会变得非常愚蠢，集中在桌面背景的美观程度（有些人会因为 Ubuntu 的默认配色方案而不使用它！）以及其他琐事上。

决定发行版质量最重要的因素是软件包系统和该发行版支持社区的活力。随着我们与 Linux 相处的时间增加，我们会发现它的软件格局是非常动态的。事物在不断变化。大多数顶级 Linux 发行版每六个月发布一个新版本，许多个人程序每天都会更新。为了跟上这软件的雪暴，我们需要良好的软件包管理工具。

软件包管理是一种在系统上安装和维护软件的方法。现如今，大多数人可以通过从其 Linux 发行版安装软件包来满足所有需求。这与 Linux 早期阶段形成了对比，当时人们必须下载并编译代码来安装软件。编译源代码并没有任何问题；事实上，能够访问源代码是 Linux 的一大奇迹。它赋予了我们（以及其他人）检查和改进系统的能力。只是拥有预编译的软件包处理起来更快、更方便。

在本章中，我们将查看一些用于软件包管理的命令行工具。虽然所有主要的发行版都提供了强大且复杂的图形化程序来维护系统，但学习命令行程序同样重要。它们可以执行许多用图形化程序难以（或无法）完成的任务。

## 软件包系统

不同的发行版使用不同的软件包系统，通常情况下，为一个发行版设计的软件包与另一个发行版不兼容。大多数发行版属于两种软件包技术之一：Debian `deb` 营和 Red Hat `rpm` 营。虽然有 Gentoo、Slackware 和 Arch 等一些例外，但大多数其他系统使用这两个系统之一，如表 14-1 所示。

表 14-1：主要软件包系统家族

| 软件包系统 | 发行版（部分列表） |
|---|---|
| Debian (`.deb`) | Debian, Ubuntu, Linux Mint, Raspberry |
| Red Hat风格 (`.rpm`) | Fedora, CentOS, Red Hat Enterprise Linux, OpenSUSE |

## 软件包系统的工作原理

专有行业中的软件发行方式通常涉及购买安装介质（如“安装盘”），或访问每个供应商的网站下载产品并运行“安装向导”以在系统上安装新应用程序。

Linux 并不是这样运作的。几乎所有 Linux 系统的软件都互联网上找到。大部分由发行版供应商以软件包文件的形式提供，其余部分以源代码的形式提供并可以手动安装。我们将在第 23 章讨论如何通过编译源代码安装软件。

## 软件包文件

软件包系统中软件的基本单位是软件包文件。软件包是组成软件包的文件的压缩集合。一个软件包可能包含许多程序和支持这些程序的数据文件。除了要安装的文件外，软件包还包含有关软件包的元数据，例如软件包及其内容的文本描述。此外，许多软件包包含预安装和后安装脚本，这些脚本会在软件包安装前后执行配置任务。

软件包文件由称为软件包维护者的人创建，他们通常（但不总是）是发行版供应商的员工。软件包维护者从上游提供者（程序作者）处获取源代码，进行编译，并创建软件包元数据以及任何必要的安装脚本。通常，维护者会对原始源代码进行修改，以改进程序与 Linux 发行版其他部分的集成。

## 仓库

虽然某些软件项目选择自己进行打包和发行，但现在大多数软件包由发行版供应商和感兴趣的第三方创建。软件包通过中央仓库提供给发行版用户，这些仓库可能包含数千个软件包，每个都是为该发行版专门构建和维护的。

发行版可能会为软件开发生命期的期的不同阶段维护几个不同的仓库。例如，有一个“测试”仓库，包含刚构建的软件包，供那些在软件包发布到通用发行之前寻找 Bug 的勇敢勇士使用。一个发行版通常会有一个“开发”仓库，存放旨在将包含在发行版下一次大版本中的进行中的软件包。

发行版还可能有第三方仓库。这些仓库通常需要提供某些软件，这些由于法律原因（如专利或 DRM 绕过问题）无法包含在发行版中。也许最为人知的案例是加密 DVD 支持，这在美国洲是不合法的。第三方仓库在软件专利和反绕过法律不适的国家运行。仓库通常独立于它们所支持的发行版，要使用它们，必须了解它们并将它们手动包含在软件包管理系统的配置文件中。

## 依赖关系

程序很少是“孤立”的；相反，它们依赖于其他软件组件的存在来完成工作。例如，输入/输出等常见活动是由许多程序共享的例程处理的。这些例程存储在共享库中，为多个程序提供基本服务。如果一个软件包需要共享资源（如共享库），则称它有依赖关系。现代软件包管理系统提供某种依赖解析方法，确保在安装软件包时，其所有依赖项也被安装。

## 高级和低级软件包工具

软件包管理系统通常由两类工具组成：

- 处理安装和删除软件包文件等任务的低级工具
- 执行元数据搜索和依赖解析的高级工具

在本章中，我们将查看 Debian 风格系统（如 Ubuntu 和许多其他系统）提供的工具，以及 Red Hat 使用的工具。虽然所有 Red Hat 风格的发行版都依赖同一个低级程序 (`rpm`)，但它们使用不同的高级工具。为了讨论，我们将涵盖 Red Hat Enterprise Linux 和 CentOS 使用的高级程序 `yum`。其他 Red Hat 风格的发行版提供具有相当功能的级工具（见表 14-2）。

表 14-2：软件包系统工具

| 发行版 | 低级工具 | 高级工具 |
|---|---|---|
| Debian 风格 | `dpkg` | `apt-get`, `apt`, `aptitude` |
| Fedora, Red Hat Enterprise Linux, CentOS | `rpm` | `yum`, `dnf` |

## 在仓库中查找软件包

使用高级工具搜索仓库元数据，可以根据名称或描述定位软件包（见表 14-3）。

表 14-3：软件包搜索命令

| 风格 | 命令 |
|---|---|
| Debian | `apt-get update`, `apt-cache search search_string` |
| Red Hat | `yum search search_string` |

例如，要从仓库搜索 `emacs` 文本编辑器，可以使用此命令：

```bash
yum search emacs
```

## 从仓库安装软件包

高级级工具允许从仓库下载软件包并在带有完整的依赖关系解析后进行安装（参见表 14-4）。

表 14-4：软件包安装命令

| 风格 (Style) | 命令(s) |
| : --- | :--- |
| Debian | `apt-get update`; `apt-get install package_name` |
| Red Hat | `yum install package_name` |

例如，在 Debian 系统上从仓库安装 `emacs` 文本编辑器，可以使用此命令：

```bash
apt-get update; apt-get install emacs
```

## 从软件包文件安装软件包

如果软件包文件是从仓库以外来源下载的，可以使用低级工具直接安装（尽管不进行依赖关系解析）（参见表 14-5）。

表 14-5：低级软件包安装命令

| 风格 (Style) | 命令(s) |
| :--- | :--- |
| Debian | `dpkg -i package_file` |
| Red Hat | `rpm -i package_file` |

例如，如果 `emacs-22.1-7.fc7.i386.rpm` 软件包是从非仓库网站下载的，将以以下方式安装：

```bash
rpm -i emacs-22.1-7.fc7.i386.rpm
```

> 注意：由于此技术使用了低级的 `rpm` 程序执行安装，因此不会进行依赖关系解析。如果 `rpm` 发现缺失的依赖项，`rpm` 将带错误退出。

## 移除软件包

可以使用高级或低级工具卸载软件包。表 14-6 列出了这些工具。

表 14-6：软件包移除命令

| 风格 (Style) | 命令(s) |
|--- |--- |
| Debian | `apt-get remove package_name` |
| Red Hat | `yum erase package_name` |

例如，在 Debian 风格的系统中卸载 `emacs` 软件包，可以使用此命令：

```bash
apt-get remove emacs
```
