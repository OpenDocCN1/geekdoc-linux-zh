
要使用该预定义序列，请替换规则配方中的变量。你可以像替换其他其他变量一样替换它（参阅第 6.1 节 [`变量引用的基础`]`，第 59 页）。因为通过 `define` 定义的变量是递归展开的，你在 `define` 内部编写的所有变量引用现在都会被展开。例如：

```
foo : foo.y
$(run-yacc)
```

当 `'$'` 在 `run-yacc` 的值中出现时，会被替换为变量 `'foo'`，而 `'$0'` 被替换为 `'foo.c'`。

这是一个真实的示例，但在实践中不需要这个特定的示例，因为 make 有一条隐式规则根据文件名推导出这些命令（参阅第 10 章 [`隐式规则`]`，第 111 页）。

在配方执行中，预定义序列的每一行被处理的方式就像该行单独出现一样，且前面有一个制表符。make 为每一行调用一个子 shell。你可以在预定义序列的每一行上使用影响命令行的特殊前缀字符（`'@'`、`'-'` 和 `'+'`）。例如，这个预定义序列：

```
define frobnicating =
@echo "frobnicating target $$"
frob-step-1 < -o $$step-1
frob-step-2 <o $$step-1 -o $$
endif
```

make 不会回显第一行即 echo 命令。但它会回显接下来的两行配方。

另一方面，引用预定义序列的配方行上的前缀字符适用于序列中的每一行。因此，下述规则：

```
frob.out: frob.in
@$(frobnicating)
```

不会回显任何配方行。（参阅第 5.2 节 [`配方回显`]`，第 43 页获取关于 `'©'` 的完整解释）。

## 5.9 使用空配方

有时，定义一个无所事事的配方是有用的。这只需通过给出一个仅由空白符构成的配方来实现。例如：

```
target:
```

这为 `'target'` 定义了一个空配方。你也可以使用带有配方前缀字符的行来定义空配方，但这会引起困惑，因为这样的行看起来是空的。

你可能会奇怪，为什么想要定义一个无所事事的配方。唯一的理由是为了防止目标获取隐式配方（来自隐式规则或 `.DEFAULT` 特殊目标；参阅第 10 章）。

你可能想要定义一个空配方是为了防止目标获取隐式配方，可能会导致灾难性的结果，并且无疑会产生至少令人惊讶且可能产生影响的影响。

如果你想在 GNU make 中运行其他实现的 make，因此不想向 `MFLAGS` 变量中添加 GNU make 特有的标志，你可以改用 `GNUMAKE` 变量。该变量在 `MAKEFLAGS` 之前被解析，其解析方式与 `MFLAGS` 相同。当 make 构造传递给递归 make 的 `MAKEFLAGS` 时，它将包含所有标志，甚至是来自 `GNUMAKE` 的标志。结果是，在解析 `GNUMAKE` 后，make 将此变量置为空字符串，以避免在递归期间重复标志。

最好的做法是仅对 `GNUMAKE` 使用那些不会改变你的 makefiles 行为的标志。如果你的 makefiles 确实需要 GNU make，那么请使用 `MFLAGS`。像 `'--no-print-directory'` 或 `'--output-sync'` 这样的标志可能适用于 `GNUMAKE`。

# 6 如何使用变量

变量是一个在 makefile 中定义的名称，用于表示一段文本，称为变量的值。

变量在 makefile 的所有部分：目标、前提、大多数指令和变量值中被展开。（在其他版本的 make 中，变量被称为宏）。

变量可以表示文件名列表、编译器选项、运行的程序、查找或写入目录等等。

变量名可以是任何不包含 `':'`、`'#'` 或空白的字符序列。然而，包含其他字符的变量名在 shell 中可能无法通过环境传递给子 make（参阅第 5.7.2 节 [`传递变量给子 make`]`，第 52 页）。以点和大写字母开头的变量名在未来的 make 版本中可能会赋予特殊含义。

变量名区分大小写。`'foo'`、`'FOOD'` 和 `'Foo'` 都指向不同的变量。

少数变量的名字是单个标点符号或几个字符。这些是自动变量，它们有特定的特殊用途。参阅第 10.5.3 节 [`自动变量`]`，第 120 页。

## 6.1 变量引用的基础

```
objects = program.foo utils.o
program : $(objects)
cc -o program $(objects)
```

```
$(objects) = defs.h
```

变量通过严格的文本替换工作。因此，规则

```
foo = o
prog.o : prog.$(foo)
$(foo)$(foo) -$(foo) prog.$(foo)
```

可用于编译 C 程序 `'prog.c'`。在变量赋值时，变量值前的空格会被忽略，`foo` 的值恰好为 `'c'`。（不要真的这样写你的 Makefile！）

美元符号后如果跟的是一个不是美元符号、左括号或下划线的字符，则会将该单个字符视为变量名。因此，你可以用 `'$'` 来引用变量 x。然而，强烈不建议这样做，特别是在自动变量的情况下（请参见第 10.5.3 节 [`自动变量`]`，第 120 页）。

## 6.2 变量的两种类型

GNU make 中的变量有两种获取值的方式；我们称之为变量的两种类型。它们的区别在于定义方式以及被展开的内容。

第一种类型是**递归展开变量**。这类变量通过使用 `=` 的行（见第 6.5 节 [`设置变量`]`，第 65 页）或 `define` 指令（见第 6.8 节 [`定义多行变量`]`，第 69 页）定义。指定的指定是一个变量；如果它包含对其他变量的引用，每当该变量被替换时（在展开其他字符串时），这些引用都会被展开。发生这种情况时，被称为递归展开。

例如：

```
foo = $(bar)
bar = $(ugh)
ugh = Huh;
```

将输出 `'Huh?'`：`'$foo'` 展开为 `'$(bar)'`，展开为 `'$(ugh)'`，最后展开为 `'Huh'`。

这种类型是大多数其他 make 版本唯一支持的类型。它有自己的优缺点。一个优点（大多数人会认为）：

```
CFLAGS = $(include_dir) -O
include_dirs = -Ifbar
```

将会如预期：当 `'CFLAGS'` 在配方中展开时，它将展开为 `'-Ifoo -O'`。一个主要的缺点是你不能在变量末尾添加内容，例如：

```
CFLAGS = $(CFLAGS) -O
```

因为这会导致变量展开出现无限循环。（实际上 make 会检测到无限循环并报告错误）。

另一个缺点是，定义中引用的任何函数（见第 8 章 [`文本转换函数`]`，第 83 页）都会在每次变量展开时执行。这会让 make 变慢；更糟糕的是，它会导致通配符函数和 shell 函数产生不可预测的结果，因为你无法轻易控制它们何时被调用，或调用多少次。

为了避免递归展开变量的所有问题和缺陷，还有另一种类型：**简单展开变量**。

简单展开变量通过使用 `':='` 或 `:=` 的行定义（见第 6.5 节 [`设置变量`]`，第 65 页）。在 GNU make 中，两种格式是等价的；但只有 `:=` 格式被 POSIX 标准描述（`:=` 在 2012 年加入 POSIX 标准，较旧版本的 make 也不支持此）。

简单展开变量的值是一次性确定的，在变量定义时就会展开对其他变量和函数的任何引用。简单展开变量的实际值是你所写文本展开的结果。它不包含对其他变量的引用；它包含的是该变量定义时对应的值。因此，

```
x := foo
y := $(x) bar
x := later
```

等同于

```
y := foo
x := later
```

当引用一个简单展开变量时，它的值会被替换。这里有一个稍微复杂点的示例，说明了 `:=` 配合 shell 函数的使用。（见第 8.13 节 [`shell 函数`]`，第 97 页）。这也向我们展示了变量 `MAKELEVEL`，它在从一个级别向下传递时会发生变化。（关于 `MAKELEVEL` 的信息请参见第 5.7.2 节 [`将变量传递给子 make`]`，第 52 页）。

```
ifeq $(0,$MAKELEVEL)
whoami := $(shell whoami)
host-type := $(shell host)
MAKE := $(MAKE)host-type=$(host-type) whoami=$(whoami)
```

这种使用 `:=` 的优点是，典型的“进入目录”配方通常如下：

```
$(subdirs)
$(MAKE) -C $$ all
```

简单展开变量通常会让 Makefile 编程变得优得多，因为它们允许你使用变量自身的值（或通过某些展开函数处理后的值）来定义变量，并能更高效地使用展开函数（见第 8 章 [`文本转换函数`]`，第 83 页）。

你还可以在变量值中引入前导空格。领先空格字符会被忽略。除非经过转义，否则领先空格不是值的一部分。例如：

```
foo   := bar
```

`foo` 的值是 `'bar'`。如果你想包含领先空格，必须使用：

```
foo := :=  bar
```

`foo` 的值是 `'  bar'`。

```
x = variable1
variable2 := Hello
y = $(subst 1,2,$x)
z = y
a := $(($z))
```

最终将 `a` 定义为 `'Hello'`。很难有人会想写出像这样复杂的嵌套引用，但它确实可以工作：`'${($(z))'` 展开为 `'${$(y))'`，然后变为 `'${($(z))'`。这个来自 `x` 的值 `'variable1'` 通过替换被更改为 `'variable2'`，由于整个引擎变成了 `'${variable2}'`，而简单的变量引用值即为 `'Hello'`。

计算出的变量名并不完全由单个变量引用组成。它可以包含多个变量引用，以及一些不变文本。例如：

```
a_dirs := dira dirb
1_dirs := dir1 dir2
```

```
a_files := filea fileb
1_files := file1 file2
```

```
ifeq "$(use_a)" "yes"
a := a
else
a1 := 1
endif
```

```
ifeq "$(use_dirs" "yes"
df := dirs
else
df := files
endif
```

根据 `use_a` 和 `use_dirs` 的设置，将赋予 `dirs`  way `a_dirs`、`1_dirs`、`a_files` 或 `1_files` 相同的值。

计算出的变量名也可以用于替换引用：

```
a_objects := a.o b.o c.o
1_objects := 1.o 2.o 3.o
```

```
sources := $((a_objects):.o.c)
```

根据 `a1` 的值，将 `sources` 定义为 `'a.c b.c c.c'` 或 `'1.c 2.c 3.c'`。

这种类型的嵌套变量引用的唯一限制是，它们不能指定要调用函数名称的一部分。这是因为对识别函数的测试是在嵌套引用展开之前完成的。例如：

```
ifdef do_sort
func := sort
else
func := strip
endif
```

```
bar := a d b g q c
```

```
foo := $(func) $(bar)
```

尝试给 `foo` 赋值变量名 `'sort a d b g q c'` 或 `'strip a d b g q c'`而不是将 `'a d b g q c'` 作为 `sort` 或 `strip` 函数的参数。如果以后证明这种更改是好主意，可以取消这一限制。

你还可以在变量赋值的左侧或在 `define` 语句中使用变量名：

```
dir := foo
$(dir)_sources := $(wildcard $(dir).*)
define $(dir)_print =
lpr := $($(dir)_sources)
endif
```

此示例定义了变量 `'dir'`、`'foo_sources'` 和 `'foo_print'`。

> 注意，嵌套引用与递归展开变量非常不同（参见第 6.2 节 [`变量的两种类型`]`，第 60 页），尽管在进行 Make 编程时两者经常以复杂的方式一起使用。

## 6.4 变量如何获取值

变量可以通过多种方式获取值：

- 你可以在运行 `make` 时指定一个覆盖值。参见第 9.5 节 [`覆盖变量`]`，第 103 页。
- 你可以在 Makefile 中通过赋值指定值（参见第 6.5 节 [`设置变量`]`，第 65 页）或通过逐字定义（参见第 6.8 节 [`定义多行变量`]`，第 69 页）。
- 环境中的变量是 Make 变量。参见第 6.10 节 [`环境变量`]`，第 70 页。
- 几个自动变量为每个规则赋予新值。这些变量每个都有一个常规用途。参见第 10.5.3 节 [`自动变量`]`，第 120 页。
- 某些变量具有常量初始值。参见第 10.3 节 [`隐式规则使用的变量`]`，第 115 页。

## 6.5 设置变量

要从 Makefile 中设置变量，写一行以变量名开头的行，后跟 `=` 或 `:` 或 `:=`。该行中 `=` 或 `:=` 之后的任何内容都成为该值。例如：

```
objects = main.o foo.bar utils utils
```

定义了一个名为 `objects` 的变量。变量名周围的空格以及 `=` 后面紧后的空格会被忽略。

使用 `=` 定义的变量是递归展开变量。使用 `:=` 定义的变量是简单展开变量；这些定义可以包含变量引用，这些引用会在定义完成之前被展开。参见第 6.2 节 [`变量的类型`]`，第 60 页。

变量名可能包含函数和变量引用，这些引用在读取该行以查找实际变量名时会被展开。

变量的长度没有限制（内存外）。为了可读性，你可以将变量的值分成多行，参见第 3.1 节 [`分割长行`]`，第 12 页。

如果你从未设置过某些变量，则大多数变量名被认为值为空字符串。你可以通过通常的方法设置它们，参见第 10.3 节 [`隐式引用使用的变量`]`，第 115 页。几个特殊变量会为每个规则自动设置一个新值：这些被称为自动变量（参见第 10.5.3 节 [`自动变量`]`，第 120 页）。

如果你只想在变量未被设置时对其设置值，可以使用简写运算符 `?=` 代替 `:=`。变量 `'FOO'` 的这两种设置是相同的。

## 6.6 向变量追加更多文本

向已定义的变量值中添加更多文本是有用的。你可以使用 `+=` 来此，如下所示：

```
objects = main.o foo.bar utils.o
objects += another.o
```

将 `objects` 设置为 `'main.o foo.bar utils.o another.o'`。

GNU make

第一行通过引用另一个变量 **includes** 来定义了 `CFLAGS` 变量。（`CFLAGS` 被 C 编译的规则使用；请参见第 10.2 节 [`隐式规则目录`]`，第 112 页。）使用 `=\` 进行定义会使 `CFLAGS` 成为一个递归展开变量，这意味着当 `make` 处理 `CFLAGS` 的定义时，`$(includes)-0` 不会被展开。因此，`includes` 尚未被定义，所以它必须在使用之前定义，其值才能生效。如果我们尝试在不使用 `+=` 的情况下定义 `CFLAGS` 的值，可能会这样做：

```
CFLAGS := $(CFLAGS) # 启用性能分析
```

这很清楚，但并不是我们所想要的。`=\` 将 `CFLAGS` 重新定义为简单展开变量；这使得 `make` 在设置变量之前展开 `$(CFLAGS)-pg`。如果 `includes` 尚未被定义，我们得到的是 `$(CFLAGS)-0pg`，并且稍后对 `includes` 的定义将不起任何作用。相反，通过使用 `+=`，我们将 `CFLAGS` 设置为未展开的变量 `$(includes)-0pg`。这样我们保留了对 `includes` 的引用，因此如果变量在任何后续点被定义，引用 `$(CFLAGS)` 仍然会使用它的值。

## 6.7 override 指令

如果通过命令行参数设置了变量（请参见第 9.5 节 [`覆盖变量`]`，第 103 页），则 Makefile 中的普通赋值将被忽略。如果你即使使用了命令行参数，也仍想在 Makefile 中设置该变量，可以使用 `override` 指令，其格式如下：

```
override variable = value
```

或者

```
override variable := value
```

要向在命令行上定义的变量追加更多内容，请使用：

```
override variable += more text
```

请参见第 6.6 节 [`向变量追加更多文本`]`，第 66 页。

标记有 `override` 标志的变量赋值优先级高于所有其他赋值（另一个 `override` 除外）。对该变量的后续赋值或追加如果没有标记为 `override`，将被忽略。

`override` 指令并不是为了解决 Makefile 和命令行参数之间的升级问题而发明的。它的目的是让你能够添加和修改用户通过命令行参数指定的变量。

例如，当你运行 C 编译器时，总是想要使用 `-g` 开关，而你想像往常一样允许用户通过命令行指定其他开关。你可以使用这个 `override` 指令：

```
override CFLAGS += -g
```

你也可以将 `override` 指令与 `define` 指令配合使用。正如你所预期的：

```
override define foo =
```
