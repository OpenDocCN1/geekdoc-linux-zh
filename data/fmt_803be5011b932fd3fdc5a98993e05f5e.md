# 3.4 转换 Lookaside 缓冲区 (TLB) 简介

遍历页表是昂贵的，因此硬件使用缓存来加速虚拟地址的转换。其中最重要的就是转换查找缓冲区（TLB），它本质上是对虚拟和物理地址的哈希，允许硬件避免遍历页表。

当我们修改页表时，必须清除任何已有的 TLB 条目，以防发生错误的翻译。在 x86-64 中，PCID 设置在 `CR3` 控制器中。当它更改时，TLB 会自动刷新，标记了 `GLOBAL` 标志的映射除外。

当单个页的映射失效时，我们倾向于简单地清除任何 TLB 条目。在 x86-64 中，这是通过 `invplpg` 指令实现的，如列表 3-33 所示。

> 注意，这里提到了 x86 特性进程上下文标识符（PCID），它是页表隔离（PTI）用于缓解漏洞的功能。这部分不在讨论范围内。

```c
static void native_flush_tlb_one_user(unsigned long addr)
{
    u32 loaded_mm_as = this_cpu_read(cpu_tlbstate.loaded_mm_as);

    asm volatile("invplpg (%0)" : : "r"(addr) : "memory");

    if (!static_cpu_has(X86_FEATURE_PTI))
        return;

    /*
     * 有些平台在 CR4.PCIDE=1 时调用 invpcid(type=1/2)。
     * 只要在早期调用时使用 invalidate_user_as()。
     */
    if (!this_cpu_has(X86_FEATURE_INPCID_SINGLE))
        invalidate_user_as(loaded_mm_as);
    else
        invpcid_flush_one(user_pcid(loaded_mm_as), addr);
}
```

# 3.5 内核虚拟内存分配器 (vmalloc)

内核内存分配通常通过内存分配器使用 `vmalloc()`，但这仅作为物理内存分配器，并使用直接映射返回虚拟地址。由于连续物理内存稀缺，使用内存分配器分配大块内存可能并不完全实用或明智。

```c
/**
 * vmalloc_node - 分配虚拟连续内存
 * @size: 分配大小
 * @align: 期望的对齐方式
 * @gfp_mask: 页级分配器的标志
 * @node: 分配节点或 NUMA_NO_NODE
 * @caller: 调用者的地址
 * 从页级分配器分配足够覆盖 @size 的页，@gfp_mask 标志位。
 * 将它们映射到连续的内核虚拟空间。
 * @gfp_mask 中的回收修饰符 - __GFP_NOTRY, __GFP_RETRY_MAYFAIL
 * 以及 __GFP_NOFAIL 不被支持。
 * 使用 GFP_KERNEL 之外的任何 gfp 标志应与相关人员咨询。
 * 返回分配内存的指针，错误时返回 %NULL
 */
void *vmalloc_node(unsigned long size, unsigned long align,
    gfp_t gfp_mask, int node, const void *caller)
{
    return __vmalloc_node_range(size, align, VMALLOC_START, VMALLOC_END,
        gfp_mask, PAGE_KERNEL, 0, caller);
}
```

Listing 3-36: mm/vmalloc.c: vmalloc_node()

你可以看到 `vmalloc` 调用此并将对齐设置为 1，将 GFP 掩码设置为 `GFP_KERNEL`，节点设置为 `NUMA_NO_NODE`（指定不需要在特定节点上分配），并将 `caller` 设置为返回函数的地址，用于报告。对等地，`vzalloc()` 传递了相同的参数，只是通过 `__GFP_ZERO` 额外指定了内存清零。

有许多不同的分配函数可以用于执行内核虚拟内存分配，它们最终都将调用 `__vmalloc_node_range()`。图 3-11 展示了这些分配器。

**图 3-11:** vmalloc 分配器

这些函数中的每一个最终都会调用 `__vmalloc_node_range()`，它是虚拟分配器的“核心”。让我们在列表 3-37 中查看此函数的开头（去除了作用域外的 KASAN 和 kmemleak 泄露检查）。

```c
void *__vmalloc_node_range(unsigned long size, unsigned long align,
     unsigned long start, unsigned long end, gfp_t gfp_mask,
     pgprot_t prot, unsigned long vm_flags, int node,
     const void *caller)
{
    struct vm_struct *area;
    void *ret;
    
    unsigned long real_size = size;
    unsigned long real_align = align;
    unsigned long shift = PAGE_SHIFT;

    if (WARN_ON_ONCE(!size))
        return NULL;

    if (size > totalram_pages()) {
        warn_alloc(gfp_mask, NULL,
            "vmalloc error: size %lu, exceeds total pages",
            real_size);
        return NULL;
    }
}

if (vmap_alloc_huge && (vm_flags & VM_ALLOW_HUGE_VMAP)) {
    unsigned long size_per_node;
    /*
     * 尝试巨页。仅对 PAGE_KERNEL 分配尝试，
     * 其他（如模块）尚未期望在它们的分配中使用巨页，
     * 这不适用于不支持它们的架构。
     */
    size_per_node = size;
    if (node == NUMA_NO_NODE) {
        size_per_node /= num_online_nodes();
    }
    if (arch_vmap_pmd_supported(prot) && size_per_node >= PMD_SIZE) {
        shift = PMD_SHIFT;
    } else {
        shift = arch_vmap_pte_shift(size_per_node);
    }
    align = max(real_align, 1UL << shift);
    size = ALIGN(real_size, 1UL << shift);
}
```

Listing 3-37: mm/vmalloc.c: __vmalloc_node_range()

注意 `vmalloc` 将此对齐设置为 1，将 GFP 掩码设置为 `GFP_KERNEL`，节点设置为 `NUMA_NO_NODE`（指定不需要在特定节点上分配），并将 `caller` 设置为返回函数的地址，用于报告。对等地，`vzalloc()` 传递了相同的参数，只是通过 `__GFP_ZERO` 额外指定了内存清零。

## 3.5.1 寻找空块

`__vmalloc_node_range()` 函数调用 `__get_vm_area_node()` 来寻找空内存块，我们将在列表 3-40 中检查它（去除了超出讨论范围的 KASAN 和 I/O 重映射逻辑）。

```c
static struct vm_struct *__get_vm_area_node(unsigned long size,
            unsigned long align, unsigned long shift, unsigned long flags,
            unsigned long start, unsigned long end, int node,
            gfp_t gfp_mask, const void *caller)
{
    struct vm_struct *area;
    struct vmap_area *va;
    unsigned long requested_size = size;

    BUG_ON(in_interrupt());
    size = ALIGN(size, 1UL << shift);
    if (unlikely(!size))
        return NULL;

    area = kzalloc_node(sizeof(*area), gfp_mask & __GFP_RECLAIM_MASK, node);
    if (unlikely(!area))
        return NULL;

    if (!(flags & VM_NO_GUARD))
        size += PAGE_SIZE;

    va = alloc_vm_area(size, start, end, node, gfp_mask);
    if (IS_ERR(va)) {
        kfree(area);
        return NULL;
    }

    setup_vmalloc_vm(area, va, flags, caller);

    return area;
}
```

Listing 3-40: mm/vmalloc.c: 简化的 `__get_vm_area_node()` 

该函数首先断言我们不在中断上下文中，将大小相对于输入页偏移（可能是巨页）对齐，并确保对齐没有溢出。

接下来，我们通过 `kzalloc_node()` 从 slab 分配器为 `vm_struct` 分配内存，并根据 `__GFP_RECLAIM_MASK` 掩码 `gfp_mask`，这会将输入的 `gfp` 标志限制在影响水位线检查和回收行为的标志上。如果失败，该函数返回 `NULL`。

如前文在 `vmalloc` 标志描述中提到的，如果没有设置 `VM_NO_GUARD`，则大小将增加 `PAGE_SIZE`。这会产生一个被标记为 `vmalloc` 使用的额外页面，因此缓冲区溢出不会进入 `vmalloc` 的另一个区域，且溢出将一定会触发页错误。`vmalloc` 保护页的正常用法是内核栈（当设置了 `CONFIG_VMAP_STACK` 时），例如在 `page_fault_oops()` 中，其中可以检测到栈溢出，并由于在内核模式下发生页错误而导致内核崩溃。不建议设置此标志来禁用保护页。

你可以看到 `vm_struct` 和 `vmap_area` 之间的关系，前者包含了分配的 `vmap_area`，后者在 `vmalloc` 分配中是不可用的，因为它未映射或未分配。

## vmalloc 标志

- `VM_MAP` – 指明要映射的内存。然而，在 `vmap()` 的调用中，默认标志似乎对实际的 `vmalloc` 行为没有任何影响。
- `VM_USERMAP` – 表示 `vmalloc` 块可以重新映射到用户空间。`remap_vmalloc_range_partial()`（由 `remap_vmalloc_range()` 调用）检查该标志是否已设置（同时检查 `VM_DMA_COHERENT` 或其他位）。通过 `vmalloc_user()` 和 `vmalloc_32_user()` 设置。
- `VM_DMA_COHERENT` – 表示用于相干性 DMA 分配的内存。本文不讨论此内容。
- `VM_UNINITIALIZED` – 该标志位在区域首次创建时设置，并通过 `clear_vm_uninitialized_flag()` 清除。它仅由 `show_vm_info()` 使用，该函数通过 `s_show()` 调用，它是用于 `/proc/vmallocinfo` 的 `vmalloc_object` 的，当块未初始化时不会产生任何数据输出。
- `VM_NO_GUARD` – 用于防止在分配时添加保护页。默认情况下，在 `__get_vm_area_node()` 中，额外的页面被标记为 `vmalloc` 但未映射。这防止了后续的 `vmalloc` 分配使用该页面，因此缓冲区溢出不会进入 `vmalloc` 的另一个区域，且溢出将一定会触发页错误。`vmalloc` 保护页的正常用法是内核栈（当设置 `CONFIG_VMAP_STACK` 时），例如在 `page_fault_oops()` 中，其中可以检测到栈溢出，并由于在内核模式下发生页错误而导致内核崩溃。不建议设置此标志来禁用保护页。
- `VM_KASAN` – 使用内核地址消毒器，超出了本文讨论的范畴。
- `VM_FLUSH_RESET_PERMS` – 用于确保为 `vmalloc` 块内存范围完全刷新 TLB，并清除对该内存范围的所有引用（`vmalloc` 在取消映射时懒性地刷新 TLB 缓存，以摊销这种耗时操作所需的时间）。指向页面的直接映射范围失效。
- `VM_MAP_PUT_PAGES` – 如果在调用 `vmap()`，则页面的所有权将传递给 `vmalloc`，底层页面将由 `vfree()` 放置（可能释放）。
- `VM_ALLOW_HUGE_VMAP` – 允许在 `vmalloc` 分配中使用巨页。如果是这样，请求的分配大小足够且系统支持，则将使用巨页。
- `VM_DEFER_KMLEAK` – 延迟 kmemleak 检查，超出了本文讨论的范畴。
