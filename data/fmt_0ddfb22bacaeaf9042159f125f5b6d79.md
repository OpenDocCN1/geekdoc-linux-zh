## C Shell (C Shell)

作者：John Valley 和 Sean Drew

作为一种 UNIX shell，你会有许多种 shell 可供选择：Bourne shell、Bourne again、POSIX shell、C shell、TC shell、Z shell 以及 Korn shell。这并不是一个涵盖所有 shell 的列表，因为它只涵盖了最常用的 shell。大多数 UNIX 系统都预装了上述某些 shell 的子集。如果你想使用一个未在你的系统上预装安装的 shell，你更有可能在互联网上找到你想要的那个。C shell——本章的主题——是 UNIX 中最流行、最广泛的 shell 之一。它开发在 Bourne shell 之后、Korn shell 之前。C shell 结合了 Bourne shell 的许多特性，并增加了许多新特性，使你的会话更加高效方便。

每个 shell 都有其特定的优缺点。你可能想回顾第 13 章“Shell 比较”，以帮助你决定使用哪一个。

C shell 由 Bill Joy（vi 编辑器的作者）编写，它并不是模仿 Bourne shell 设计的。Bill 选择了 C 编程语言作为其语法模型。C shell 命令——特别是 `if`、`while` 以及其他结构化编程语句——在语法上与 C 语言中的对应语句大致相似。shell 与编译器是完全不同的东西，尽管 C 编程语言仅作为一种模型；C shell 中的许多特性和结构与 C 编程语言毫无关系。

由于 C shell 不是 Bourne shell 的扩展，本章将涵盖 C shell 的所有操作。因此你可以独立于第 9 章“Bourne Shell”、第 10 章“Bourne Again Shell”以及第 11 章“C Shell”之外来阅读本章。

# 启动 C Shell

每当你登录 UNIX 时，你都会被置于交互式 shell 中，称为你的登录 shell（login shell）。如果你使用的是默认提示符，可以通过其命令行提示符来判断你的登录 shell 是否是 C shell：百分号（%）。C shell 的提示符与 Bourne shell 的默认美元符号提示符（$）不同，以提醒你正在使用 C shell。在使用 C shell 时，你可以自定义命令行提示符；更多信息请参阅本章后文“变量”中对提示符的定义。

确定你的登录 shell 最稳妥的方法是查询 `passwd` 文件。第七个字段包含你登录 shell 的路径。命令

```
grep 'whoami' /etc/passwd | cut -f7 -d:
```

将打印出你登录 shell 的路径。如果你正在使用网络信息服务（NIS）来管理用户信息，则无法访问 `/etc/passwd` 文件，此时使用命令

```
ypcat passwd | grep 'whoami' | cut -f7 -d:
```

即可解决问题。

如果你的登录 shell 不是 C shell，但你的系统中可以使用 C shell，你可以从命令行将其作为交互式 shell 启动。当你已经运行了 C shell 时，会有某些你想再次启动 C shell 的时候——例如为了运行一个 shell 脚本或临时更改 shell 的选项。要交互式地启动 C shell，请使用此命令：

```
$ csh
```

注意：`csh` 命令位于 `/bin` 或 `/usr/bin` 目录。由于这两个目录通常都在你的搜索路径中，如果你没有立即找到它，只要你的系统有 `csh`，寻找它应该也不会什么困难。你可以查看 `/usr/ucb` 目录（UNIX System V 中 BSD 原语的标准家目录）或 `/usr/local/bin`。`/usr/local/bin/` 并不由原始系统软件提供。请记住，多年来，C shell 仅供使用 BSD 变体 UNIX 的站点使用；对于 Bourne shell，无法保证你的系统中会有 `csh` 命令。

即使被调用，无论是作为 shell 还是子 shell，C shell 在启动时都会执行一个名为 `.login` 的配置文件脚本，并在退出时执行名为 `.logout`。注意，`.login` 脚本是在 `.cshrc-before` 之后执行的。关于 C 配置文件脚本的更多信息，请参阅本章后文的“自定义你的 shell 环境”。

大多数 C shell 将环境变量（如 `PATH`）导入到本地变量中。C shell 的运行并不引用全局变量（包括 `PATH`）。你通常需要为搜索维护 `PATH` 变量——但某些版本的 C shell 不会正确导入环境变量，这可能会给你带来困惑的结果。如果你没有设置搜索路径，`PATH` 变量将有一个匹配的值。此外，你不需要将关键的环境变量导入本地变量中。

注意：如果你熟悉 Bourne shell，那么在使用 C shell 时你不会发现太大的区别，除非你使用高级 shell 特性，如命令替换，以及——

重要的差异并不存在，其中包括对 shell 具有特殊含义的字符集（通常称为元字符）。C shell 对 Bourne shell 的所有特殊字符，以及波浪号（`~`）、商业符号（`@`）和感叹号（`!`）都很敏感。在编写命令时，除非你打算使用它们的特殊含义，否则不要忘记转义这些字符。参见本章后文的“引号与转义”。

# Shell 基础

当你完成本节时，你将觉得对 C shell 有了相当的了解，但这只是开始。除了本章后续章节描述的 C shell 基础功能外。

## 执行命令：基础

C shell 接受多种类型的命令作为输入：UNIX 命令、内置命令、用户编写的命令以及命令别名。本节描述了你可以执行的命令类型及其执行方式。

### 命令名作为 Shell 输入

通过输入名称来执行命令。C shell 支持以下任何一种作为命令：

- **内置 C shell 命令。** shell 提供了一些在内部实现的命令。当你调用内置命令时，执行速度非常快，因为不需要加载程序文件。内置命令通过简单名称调用（例如，而不是通过 `/usr/bin/command`）。

- **由于** shell 首先检查命令名是否存在内置命令，然后再搜索同名文件，因此你无法用 shell 脚本重定义内置命令。你可以使用别名将内置命令重定向到 shell 脚本。下一节“内置 shell 命令”简述了每个内置命令。内置命令的详细描述和示例在本章的任务相关章节中。

- **文件名。** 你可以指定文件名（`% filename`）、相对路径（`../filename`）或绝对路径（`/bin/filename`）。文件必须被标记为可执行，并且必须是二进制文件或 C shell 语言的脚本。此外，如果没有路径，文件必须存在于你的 `path` shell 变量列出的目录中。C shell 无法处理为其他语言编写的 shell 脚本，除非你的 UNIX 变体支持指定正确命令处理器的 `#!` 符号。（关于与 C shell 使用脚本，请参见后文的“Shell 编程”）。

- **所有 UNIX 命令**都是作为 `/bin` 或 `/usr/bin` 目录下的可执行文件提供的。通常 UNIX 命令通过输入文件名或完整路径来调用。

- **命令别名。** 别名是你通过 `alias` 内置 shell 命令定义的名称。

- **别名**可以与内置 shell 命令或可执行文件具有相同的名称。你始终可以调用一个别名

使用文件的全路径来执行与别名同名的可执行文件。然而，同名的别名会隐藏内置命令。别名将在本章稍后的“别名”节中进行详细描述。

### 执行 Shell 命令 shell 最常见的输入形式是*简单命令*，其中命令名后跟着任意数量的参数。例如，在接下来的命令行中，*ftp* 是命令，而 *hostname* 是参数：

```
$ ftp hostname
```

解释参数是命令的而非 shell 的责任。许多命令（但并非所有）都采用这种形式：

```
$ command -options filenames
```

虽然 shell 不解释命令的参数，但在将参数传递给命令之前，shell 会解释输入行的某些内容。在命令行上遇到的特殊字符会告诉 shell 重定向输入输出、启动不同的命令、在目录中搜索文件名模式、替换变量数据以及替换其他命令的输出。

### 在同一行输入多条命令通常情况下，shell 将输入的第一个单词解释为命令名，其余输入视为该命令的参数。分号 (`;`) 指导 shell 将符号后的单词解释为新命令，并将输入的其余视为新命令的参数。例如，命令行

```
echo "<h1>"; getTitle; echo "</h1>"
```

等同于

```
echo "<h1>"
getTitle
echo "</h1>"
```

区别在于，在第二种情况下，每个命令的结果出现在每个命令输入行之间。

当使用分号分隔行上的命令时，命令将按顺序执行。shell 会等待一个命令完成后再执行下一个命令。你也可以同时执行命令（参见本章稍后的“在后台执行命令”）或根据条件执行命令，这意味着如果命令的返回状态匹配条件，则 shell 将执行下一个命令（参见本章稍后的“条件执行命令”）。

### 命令输入太长了

命令可能会变得很长。如果命令不少于 80 个字符（标准终端宽度），则编辑和打印脚本会更简单。输入跨越多行的命令通过转义换行符来实现，这会将某些 HTML 序列转换回可读格式：

```
% sed -e "/s%3B\/:/g" -e "/s%28\/gt/" -e "/s%3C\<g/" \
-e "/s%5C\\\\/g" -e "/s%23\/#/g" -e "/s%28\(//g" \
-e "/s%29\)/g" -e "backslash"
```

按日期排序。同样，将输入重定向到子壳中的所有命令，使得子壳中的每个命令按顺序从重定向文件中读取行，从子壳中之前执行的命令所读取的行开始。

## 执行命令

复合命令实际上是两个或多个命令的组合，使得 shell 在提示输入（或在 shell 脚本的情况下，读取）更多输入之前执行所有这些命令。

交互式工作通常不需要复合命令。复合命令是 C shell 语法的一个非常有用的扩展，特别是在 shell 脚本中。某些命令格式，例如 `&`（后台作业）和 `|`（管道运算符），对于高效地使用 UNIX 至关重要。

### 成功时的条件执行：&& (与)

你使用双与运算符（逻辑与）来连接两个命令：`command1 && command2`。它导致 shell 在 `command1` 成功（即 `command1` 的退出码为零）时才执行 `command2`。

对于 `command1` 或 `command2`，你可以写一个简单的命令，也可以写一个复合命令。`&&` 运算符的优先级高于 `|` 但低于 `||`。例如，

```
grep mailto *.html | pr && echo OK
```

只有当管道 `grep | pr` 设置退出码为零时，才会执行 `echo`。（对于管道，退出码是管道中最后一个命令的退出码）。

复合命令

```
tar cvf docs.tar docs -rf docs
```

展示了使用 `&&` 的一个可能优势：`rm` 命令仅在成功备份到 tar 文件中时才删除 docs 目录。

### 失败时的条件执行：|| (或)

你使用或运算符来连接两个命令：`command1 || command2`。它导致 shell 在 `command1` 失败（即返回非零退出码）时才执行 `command2`。

对于 `command1` 或 `command2`，你可以写一个简单的命令，也可以写一个复合命令。`||` 运算符的优先级低于 `&&` 和 `|` 运算符。例如，在以下命令中

```
grep mailto *.html | echo No mailto found | pr
```

要么 grep 成功且其输出被置于标准输出，或者单词 "No mailto found" 被传递给 pr 命令。

使用 `||` 提供一种备选方案。在以下情况下，如果 `mkdir` 命令失败，退出将阻止 shell 脚本的执行：

```
mkdir $tmpfile || exit
```

## Shell 语句：深入观察

命令是一个基本命令，或者是附带一个或多个 I/O 重定向的基本命令。

基本命令是一系列单词，每个单词都经过 C shell 的替换，在完全解析后，它指定了要执行的命令，并提供零或多个选项来修改或控制所采取的操作。基本命令的第一个单词（有时称为命令名）必须指定所需的操作。

通俗地说，语句是最小的可执行单元。当 shell 运行在交互模式下时，当它需要语句时会显示其提示符。当需要多行时，你必须继续输入语句组件，直到完成一个完整的语句。如果语句没有在一行内完成，shell 将继续提示你，而不执行你输入的一行或几行，直到达到一个完整的语句。

Shell 语句由许多令牌（tokens）组成。令牌是一个语法元素，可以是以下任何一种：

- **注释。** 注释以任何以井号（`#`）为第一个字符的单词开始，并延伸到行末尾。可以通过引号将井号（或条目单词）括起来来避免这种解释。（参见本章后面的“引号和转义字符”）。`#` 仅对非交互式 C shell 视为注释。

- **空格。** 空格由空格、制表符有时还有换行符组成。空格用于分隔其他令牌，如果它们一起运行，将失去各自的身份。由空格分隔的文本单元通称为单词。

- **语句分隔符。** 语句分隔符是分号（`;`）和换行符（当按回车时生成）。你可以使用分号将命令放置在同一行中。shell 将它们处理为像在不同的行一样。

- **通常，每个命令或 shell 语句都于行尾结束。** 你为了结束行而按的回车（Enter）键产生一个不同于打印字符、空格、制表符的字符，shell 将其视为换行符。某些语句需要多行输入，例如 `if` 和 `while`。语法描述显示了命令如何拆分到多行；必须遵守行边界，并且必须在指定位置结束每行，否则你将得到语法错误。

- **运算符。** 运算符是一个特殊字符或特殊字符的组合，shell 为其附加语法意义。作为特殊字符组合的运算符必须在它们之间没有空格，否则它们会被视为两个运算符而不是一个双字符运算符。例如，自增运算符 `++` 不能写为 `+`。

- **标点符号字符**具有特殊意义，需要用引号括起来以避免它们的特殊解释。例如，命令 `grep '\*'` 使用引号来留住 shell 的右括号，以便右括号可以作为参数被 grep。本章后面的“引号和转义”提供了关于使用引号的详细信息。
