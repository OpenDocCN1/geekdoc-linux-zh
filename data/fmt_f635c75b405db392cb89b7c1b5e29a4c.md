
要从两个 pixmap 创建光标，请使用 `XCreatePixmapCursor`。

```c
XCreatePixmapCursor(display, source, mask, foreground_color, background_color, x, y);
```

`display` 指定与 X 服务器的连接。

`source` 指定源光标的形状。

`mask` 指定要显示的光标源位或为 `None`。

`foreground_color` 指定源前景的 RGB 值。

`background_color` 指定源背景的 RGB 值。

`x` 指定 x 和 y 坐标，指示相对于源原点的热点。

`XCreatePixmapCursor` 函数创建一个光标并返回与其关联的 ID。前景和背景 RGB 值必须使用 `foreground_color` 和 `background_color` 指定；即使 X 服务器仅有静态灰（`StaticGray`）或灰度（`Grayscale`）屏幕。前景用于源中设置为 1 的像素，背景用于设置为 0 的像素。如果指定了源和掩码，它们的深度必须匹配（否则产生 `BadMatch` 错误），但可以具有任何 root。`mask` 参数定义了光标的形状：掩码中设置为 1 的像素决定了显示哪些源像素，而设置为 0 的像素则被忽略。如果没有给出 `mask`，则显示源的所有像素。如果存在 `mask`，其大小必须与 `source` 参数定义的 pixmap 相同，否则将产生 `BadMatch` 错误。热点必须是源内部的一个点，否则将产生 `BadMatch` 错误。

光标的组件可以转换以满足显示限制。如果不再对这些 pixmap 进行进一步的显式引用，可以立即释放它们。随后在源或掩码 pixmap 中绘制对光标的影响是未定义的：X 服务器可能会也可能对 pixmap 进行复制。

`XCreatePixmapCursor` 可以产生 `BadAlloc` 和 `BadPixmap` 错误。

要确定有用的光标尺寸，请使用 `XQueryBestCursor`。

- `Status XQueryBestCursor(display, d, width, height, width_return, height_return);`

- `display` 指定与 X 服务器的连接。

- `cursor` 指定可绘制区域（drawable），它指示屏幕。

- `width` 指定你想获取尺寸信息的光标宽度和高度。

- `height_return` 返回离特定宽度和高度的最佳宽度和高度。

某些显示器允许比其他显示器更大的光标。`XQueryBestCursor` 提供了一种查找显示器可能尺寸的方法。RGB 颜色空间取决于设备。

`XQueryBestCursor` 可以产生 `BadAlloc` 和 `BadValue` 错误。

要更改光标的颜色，请使用 `XRecolorCursor`。

`XRecolorCursor(display, cursor, foreground_color, background_color);`

- `display` 指定与 X 服务器的连接。

- `cursor` 指定光标。

- `foreground_color` 指定源前景的 RGB 值。

- `background_color` 指定源背景的 RGB 值。

`XRecolorCursor` 可以产生 `BadMatch` 错误。

要释放（销毁）指定的光标，请使用 `XFreeCursor`。

`XFreeCursor(display, cursor);`

- `display` 指定与 X 服务器的连接。

- `cursor` 指定光标。

## Pixmap 和光标函数

`XFreeCursor` 函数删除像素值与光标之间的关联。当没有其他资源引用它时，存储将将被释放。

`XFreeCursor` 可以产生 `BadMatch` 错误。

# 颜色管理函数

由于调板（colormaps）与窗口相关，X 支持具有多个调板的显示器，实际上支持不同类型的调板。如果显示器中的调板资源不足，窗口将以其真颜色显示，而其他窗口将以错误的颜色显示。如果使用的资源需要多个调板，则窗口管理器会控制哪些窗口以真颜色显示。在任何时候，屏幕都有一组已安装的调板。使用某一个已安装调板的窗口和使用其他调板的窗口通常会错误的颜色显示。你可以通过 `XInstallColormap` 和 `XUninstallColormap` 来控制已安装调板的集合。

调板是特定屏幕局部的。窗口和程序从这些调板中分配单元格。通常情况下，你不应该编写垄断颜色资源的应用程序。虽然某些硬件支持同时安装多个调板，但许多硬件显示器仅构建了单个已安装调板，因此编写这些原子操作是为了鼓励应用程序之间共享调板。

`DefaultColormap` 宏返回默认调板。`DefaultVisual` 宏返回指定屏幕的默认视觉类型。可能的类型有 `StaticGray`。

## 颜色结构

对 RGB 颜色空间值的操作使用 `XColor` 结构，它包含：

```c
typedef struct {
    unsigned long pixel; /* pixel value */
    unsigned short red, green, blue; /* rgb values */
    char flags; /* DoRed, DoGreen, DoBlue */
    char pad;
} XColor;
```

红、绿、蓝值始终在 0 到 65535 之间（包含边界值），这与显示硬件中实际使用的比特数无关。服务器会将这些值缩放到硬件使用的范围。。黑色由 (0,0,0) 表示，白色由 (65535,65535,65535) 表示。在某些函数中，`flags` 成员控制红、绿、蓝成员中哪些被使用，并包括一个或多个 `DoRed`、以及 `DoBlue`。

对所有颜色空间值的操作使用 `XmsColor` 结构。该结构包含一个子结构的联合（union），每个子结构都支持特定颜色空间的颜色规格编码。与 `XColor` 结构类似，`XmsColor` 结构包含像素和颜色规格信息（`XmsColor` 结构中的 `spec` 成员）。

### 颜色管理函数

```c
typedef unsigned long XmsColorFormat;    /* Color Specification Format */

typedef struct {
    union {
        XcmsRGB RGB;
        XmsRGBBI RGB;
        XcmsCIEZY CIEZY;
        XcmsCIEuvY CIEuvY;
        XmsCIEXYy CIEXYy;
        XmsCIELab CIELab;
        XmsCIEUv CIEUv;
        XmsTekHVC TekHVC;
        XcmsPad Pad;
    } spec;
    unsigned long pixel;
    XmsColorFormat format;
} XmsColor;    /* Xms Color Structure */
```

由于颜色规格可以为各种颜色空间进行编码，`spec` 成员的编码由 `format` 成员识别，其类型为 `XmsColorFormat`。以下宏定义了标准格式：

```c
#define XmsUndefinedFormat 0x00000000
#define XmsCIEZYFormat 0x00000001    /* CIE XYZ * */
#define XmsCIEuvFormat 0x00000002    /* CIE u*y * */
#define XmsCIEXYFormat 0x00000003    /* CIE xy * */
#define XmsCIELabFormat 0x00000004    /* CIE L*a*b* */
#define XmsCIEUvFormat 0x00000005    /* CIE L*u*v* */
#define XmsTekHVCFormat 0x00000006    /* TekHVC */
#define XmsRGBFormat 0x80000000        /* RGB Device * */
#define XmsColorFormat 0x00000001    /* RGB Intensity * */
```

设备无关颜色空间的格式与设备相关格式的格式可以通过第 32 位区分开来。如果该位被设置，则表示依赖于色彩的形式；否则，如果第 31 位未设置，则表示该颜色空间是在运行时添加到 Xlib 的。运行时添加的颜色空间的值在每次执行程序时可能不同。如果必须在客户端外部引用此类颜色空间（例如，在文件中存储颜色规格），则应通过颜色空间字符串前缀引用（参见 `XmsFormatOfPrefix` 和 `XmsPrefixOfFormat`）。
