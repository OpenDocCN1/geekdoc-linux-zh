
| --- | --- |

| `f.peek([n])` | 从 I/O 缓冲区返回最多 `n` 字节的数据并移动指针。如果省略了 `n`，则返回单个字节。如果缓冲区当前为空，将向缓冲区发出读取。此操作返回的字节数多于当前字节大小，因此结果可能比请求的 `n` 字节少。 |

| `f.read([n])` | 读取 `n` 字节并作为字符串返回。如果省略 `n`，则读取并返回所有可用数据（直到 EOF）。如果底层文件是非阻塞的，则读取并返回任何可用数据。抛出 `IOError` 异常。 |

| `f.readline([n])` | 使用系统调用读取最多 `n` 字节并作为字符串返回。如果缓冲区中已加载任何数据，则直接返回。单个 `readline()` 与 `f.read()` 不同，即使底层文件是非阻塞的，此操作返回的数据也可能比请求的少。 |

| `f.readinto(b)` | 从文件读取 `len(b)` 字节的数据到现有的 bytearray `b` 中。返回实际字节数。如果文件是非阻塞的，则抛出 `BlockingIO`。 |

# `BufferedWriter` (`raw`, `buffer_size` {, `max_buffer_size}`)

用于对原始文件 `raw` 进行缓冲二进制写入的类。`raw.buffer_size` 指定在刷新到操作系统之前可以在缓冲区中保存的字节数。默认值为 `DEFAULT_BUFFER_SIZE`。`max_buffer_size` 指定写入输出数据的最大缓冲区。`BufferedWriter` 实例 `f` 支持以下操作：

| 方法 | 描述 |

| --- | --- |

| `f.flush()` | 将缓冲区存储的所有字节写入底层 I/O 流。如果流此时无法接受新数据，则抛出 `BlockingIOException`。 |

| `f.write(bytes)` | 将 `bytes` 中的字节写入 I/O 流并返回写入的字节数。如果流是非阻塞的，则抛出 `BlockingIOException`。 |

`BufferedRWPair(reader, writer, buffer_size` {, `max_buffer_size}`)

用于在原始文件或 I/O 流上进行缓冲二进制读取和写入的类。`reader` 是支持读取的原始文件，`writer` 是支持写入的文件。文件可以是不同的，这对于某些涉及管道和接字的情况非常有用。缓冲区大小参数与 `BufferedWriter` 的含义相同。`BufferedRWPair` 实例 `f` 支持 `BufferedReader` 和 `BufferedWriter` 的所有操作。

`BufferedRandom(raw, buffer_size` {, `max_buffer_size}`)

用于在支持随机访问（例如寻）的原始 I/O 流上进行缓冲二进制读取和写入的类。`raw` 必须是支持读取、写入和寻的文件。缓冲区大小参数与 `BufferedWriter` 的含义相同。`BufferedRandom` 实例 `f` 支持 `BufferedReader` 和 `BufferedWriter` 的所有操作。

`BytesIO(bytes)`

实现缓冲 I/O 流功能的内存文件。`bytes` 是指定文件初始内容的字节字符串。`BytesIO` 实例 `f` 支持 `BufferedReader` 和 `BufferedWriter` 对象的所有操作。此外可以使用方法 `b.getvalue()` 将当前文件内容作为字符串返回。

`io` 353

此外，请注意缓冲区大小参数仅指定了发生写入的限制，并不一定意味着内部资源使用的流限制。例如，当你对带缓冲的文件 `f` 调用 `f.write(data)` 时，`data` 中的所有字节都会首先复制到内部缓冲区。如果 `data` 代表一个非常大的字节数组，这种复制操作将显著增加你程序的内存占用。因此，最好以合理大小的分块写入大量数据，而不是一次性通过单个 `write()` 操作完成写入。需要注意的是，`io` 模块相对较新，这种行为在不同版本中可能会有所不同。

## 文本 I/O

I/O 层用于处理行定向的字符数据。本节定义的类在 I/O 流、行定向处理以及字符编码和解码的基础上构建。。这里所有的类都继承自 `TextIOBase`。

```
TextIOWrapper(buffer, encoding, errors, newline, line_buffering])
```

用于文本缓冲区的类是在指定的编码（如 'ascii' 或 'utf-8'）中的缓冲 I/O 流。`encoding` 指定文本编码，`errors` 指定 Unicode 错误处理策略且默认为 'strict'（见第 9 章“输入与输出”中的描述）。`newline` 是表示换行符字符序列，可以是 `None`、`'\n'`、`'\r'` 或 `'\r\n'`。如果给出 `None`，则在读取时启用通用换行模式，任何其他换行符都会转换为 `'\n'`，输出时使用 `os.linesep` 作为换行符。如果 `newline` 是其他值之一，则在输出时所有的 `'\n'` 字符都会转换为指定的换行符。`line_buffering` 是一个标志，用于控制当任何写入操作包含换行符时是否执行 `flush()` 操作。默认情况下，该值为 `False`。`TextIOWrapper` 实例支持 `IOBase` 上定义的所有操作，以及以下操作：

| 方法 | 描述 |

| --- | --- |

| `f.encoding` | 正在使用的文本编码名称。 |

| `f.errors` | 编码和解码错误处理策略。 |

| `f.line_buffering` | 决定行行为的标志。 |

| `f.newlines` | `None`、字符串或所有已转换的不同换行形式的元组。 |

| `f.read([n])` | 从底层流中读取最多 `n` 个字符并作为字符串返回。如果省略 `n`，则读取所有数据到文件末尾（EOF）。在 EOF 处返回空字符串。返回的字符串将根据 `f.encoding` 中的编码设置进行解码。 |

| `f.readline([limit])` | 读取单行文本并作为字符串返回。在 EOF 处返回空字符串。`limit` 是允许读取的最大字节数。 |

| `f.write(s)` | 使用 `f.encoding` 中的文本编码将 `s` 写入底层流。 |

```
StringIO([initial, encoding, errors, newline])
```

一个内存中的文件对象，其行为与 `TextIOWrapper` 相同。`initial` 是一个指定文件初始内容的字符串。其他参数的含义与 `TextIOWrapper` 相同。`StringIO` 实例 `s` 支持所有的常规文件操作，此外还有一个方法 `s.getvalue()` 用于返回内存缓冲区的当前内容。

## `open()` 函数

`io` 模块定义了 `open()` 函数，它与 Python 3 中内置的 `open()` 函数相同。

```
open(file [, mode [, buffering [, encoding [, errors [, newline [, closefd]]]])
```

打开文件并返回一个 I/O 对象。`file` 可以是指定文件名的字符串，可以是已打开的 I/O 流的整数描述符。其结果取决于 `mode` 和 `buffering` 的设置，是 `io` 模块中 I/O 类之一。如果 `mode` 是任何文本模式（如 'r'、'w'、'a' 或 'U'），则返回一个 `TextIOWrapper` 实例。如果 `mode` 是二进制模式（如 'rb' 或 'wb'），则取决于 `buffering` 的设置。如果 `buffering` 为 0，则返回一个 `FileIO` 实例以执行无缓冲 I/O。如果 `buffering` 是其他任何值，则根据文件模式返回 `BufferedReader`、`BufferedWriter` 或 `BufferedReader` 实例。`encoding`、`errors` 和 `newline` 参数仅适用于文本模式打开的文件，并传递给 `TextIOWrapper` 构造函数。`closefd` 仅当 `file` 为整数描述符时适用，并传递给 `FileIO` 构造函数。

## 抽象基类

`io` 模块定义了以下用于类型检查和定义新 I/O类的抽象基类：

| 抽象类 | 描述 |

| --- | --- |

| `IOBase` | 所有 I/O 类的基类。 |

| `RawIOBase` | 支持原始二进制 I/O 的对象的基类。继承自 `IOBase`。 |

| `BufferedIOBase` | 支持缓冲二进制 I/O 的对象的基类。继承自 `IOBase`。 |

| `TextIOBase` | 支持文本流的对象的基类。继承自 `IOBase`。 |

大多数程序员直接操作这些类。有关使用和定义的细节请参考官方文档。
