
请注意，除了从仓库复制所需的文件外，还会创建一个名为 `CVS` 的目录。该目录仅用于 CVS 管理目的，绝不应直接修改其内容。当你想要对检出的文件进行修改时，请切换到 `project/src/print` 目录。对所有检出的文件进行相应更改后，可以通过执行 `cvs commit` 命令将更改提交到仓库。此问题将在下一节中进行讨论。

在仓库中指定目录的部分路径可能是繁琐的，特别是在具有许多目录层级的大型项目中。在 CVS 中，你可以为每个源目录创建缩写。你可以通过配置 `$CVSROOT/CVSROOT` 目录下的 `modules` 文件来实现这一点。为此，执行以下命令来“检出” `modules` 文件的副本：

```
$ cvs checkout CVSROOT/modules
U CVSROOT/modules
$
```

此命令会在你的本地工作目录中创建一个 `CVSROOT` 目录。切换到该目录后，你将看到一个可以编辑的 `modules` 文件的副本。对于前面的示例，请在文件末尾添加以下行：

```
src project/src
main project/src/main
print project/src/print
term project/src/term
```

为了使更改生效，你必须对它们进行“提交”。你可以如下使用 `cvs commit` 命令来实现提交：

```
$ cvs commit -m "initialize modules"
initialized the modules file
Checking in modules;
 /users/home/project/CVSROOT/modules,v <-- modules
new revision: 1.2; previous revision: 1.1
done
cvs commit: Rebuilding administrative file database
$
```

`cvs commit` 命令将在下一节中更详细地讨论。

此操作允许你选择目录中的模块，而无需指定整个路径。例如，假设你想选择组成 `print` 模块的文件。你不需要在命令行中指定 `project/src/print`，而是可以使用 `print` 来替代它：

```
$ cvs checkout print
cvs checkout: Updating print
U print/print.c
U print/print.h
$ cd print
$ ls -l
total 6
drwxrwxrwx 2 trimblef users 1024 May 25 10:47 CVS
-rw-rw-rw- 1 trimblef users 16 May 25 10:26 print.c
-rw-rw-rw- 1 trimblef users 16 May 25 10:26 print.h
$
```

当你从仓库检出文件时，默认获得的是最新版本。如果你需要修补源代码的较早版本，可以指定另一个版本。例如假设 `print` 模块的当前版本为 1.4。你可以使用 `-r` 选项获取 1.1 版本，如下：

```
$ cvs checkout -r 1.1 print
cvs checkout: Updating print
U print/print.c
U print/print.h
$
```

要获取特定 `cvs` 命令可以使用的所有选项的完整列表，请使用 `-H` 选项。例如，这里是列出 `checkout` 命令所有选项的方法：

```
$ cvs -H checkout

cvs checkout [-ANPcflnps] [-r rev | -D date] [-d dir] [-k kopt] modules...
 -A 重置任何粘性标签/日期/kopts.
- -N 如果指定了 -d，则不缩短模块路径.
- -P 修剪空目录.
- -c "cat" 模块数据库.
- -f 如果未找到标签/日期，强制匹配主版本.
- -l 仅本地目录，不递归
- -n 不运行模块（如果有）。
- -p 检出到标准输出（避免粘性）。
- -s  -c，但包含模块状态.
- -r rev 检出版本或标签。（包含 -P）（粘性）。
- -D date 按日期检出。（包含 -P）（粘性）。
- -d dir 检出到 dir 而不是模块名.
- -k kopt 在 checkout 时使用 kopt.

```

## 文件

从仓库检出文件并完成你所需的更改后，你可以使用 `cvs commit` 命令提交修改的文件。例如，你可以使用以下命令提交修改的文件：

```
$ cvs commit -m "update print"
cvs commit: Examining .
cvs commit: Committing .
Checking in print.c;
 /users/home/project/src/print.c,v <-- print
new revision: 1.2; previous revision: 1.1
done
$
```

在此示例输出表明只有 `print.c` 文件发生了更改。此外注意原始文件导入为版本 1.1。提交操作后，存在版本 1.2。这两个版本都在仓库的主干上。检出操作完成后，你可以指定要获取的版本。通过这种方式，你可以修补源代码之前的版本。`-m` 选项允许你记录注释。如果你没有指定 `-m` 选项，将调用编辑器（默认为 `vi`），显示以下帮助文本：

```
CVS: ----------------------
CVS: Enter Log. 以 '-' 开头的行将被自动删除
CVS: ----------------------
```

这段文字提醒你在提交更改之前记录日志。

## 更新

如我之前所述，CVS 允许一个或多人同时修改一个文件。假设你正在修改一个文件，并希望更新本地检出副本以包含另一个用户提交到仓库的更改。你可以通过 `update` 命令来实现。该命令是最常用的 `cvs` 命令之一，有许多选项。作为一个简单的示例，为了将别人的更改合并到你的本地副本，你可以调用带有 `update` 选项的 `cvs`：

```
$ cvs update
cvs update: Updating project
cvs update: Updating project/project
cvs update: Updating project/src
cvs update: Updating project/src/main
cvs update: Updating project/src/print
cvs update: Updating project/src/term
$
```

## 分支

分支允许你对某些文件进行修改而不干扰主干（分支和其他源码控制概念的通用处理请见第23 章）。创建分支的第一步是为仓库中的某些文件创建标签。标签只是文件或一组文件的符号名称。相同的标签通常赋予在源代码生命周期策略点（如修补或发布时）组成模块的文件集。要创建标签，请在工作目录中运行 `cvs tag` 命令。例如，以下命令标记了 `src` 目录：

```
$ cvs checkout src
cvs checkout: Updating src
cvs checkout: Updating src/main
U src/main.c
U src/main.h
cvs checkout: Updating src/print
U src/print.c
U src/print.h
cvs checkout: Updating src/term
U src/term.c
U src/term.h
cvs tag release-1-0
cvs tag: Tagging src
cvs tag: Tagging src/main
T src/main.c
T src/main.h
cvs tag: Tagging src/print
T src/print.c
T src/print.h
cvs tag: Tagging src/term
T src/term.c
T src/term.h
$
```

在下一步中，你使用刚刚创建的标签来创建分支。为此，你如下使用 `rtag` 命令：

```
$ cvs rtag -b -r release-1-0 release-10-patches print
cvs rtag: Tagging project/src/print
$
```

要查看本地工作副本的当前状态（包括你正在工作的分支），使用 `cvs` 的 `status` 选项：

```
$ cvs status -v src
```
