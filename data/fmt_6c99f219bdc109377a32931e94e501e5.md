当我们把函数写入脚本中时，必须记住在使用它之前先声明或编写该函数：函数必须出现在调用该函数的命令语句上方。我们无法使用尚未存在的内容。

## 运行 Shell 脚本

Shell 脚本可以通过以下方式执行：

- `ksh shell_script_name` 将创建一个 Korn shell 并在新创建的 Korn shell 环境中执行 `shell_script_name`。
- `./shell_script_name` 如果在 `chmod` 命令的 man 页上设置了执行权限，则将执行 `shell_script_name`。脚本将在脚本第一行声明的 shell 中执行。如果脚本第一行没有声明 shell，它将在默认 shell 中执行，即用户系统定义的定义的 shell。在非预期的 shell 中执行可能会导致执行失败并产生不可预测的结果。

## 在 Shell 脚本中声明 shell

声明 shell！如果我们想完全控制 Shell 脚本的运行方式以及在哪个 shell 中执行，**必须**在脚本的第一行声明 shell。

## Shell 脚本中的注释与风格

本书始终强调在脚本中编写良好的注释。对我们来说是直观而易见的东西，对其他追随我们脚步的人来说可能完全像天书。我们必须编写易于阅读且易于维护的代码，这意味着它必须有大量的描述步骤的注释。在大多数情况下，编写 shell 脚本的人并不是负责维护它的人。没有比通过硬啃某人没有注释的代码来寻找每一步意图更糟糕的事情了。起初修改脚本可能很困难，但要弄清楚脚本作者的思路会让我们想从头重写整个 shell 脚本。我们可以通过编写清晰易读的脚本并插入大量注释来描述我们的哲学以及我们如何使用输入、输出、变量和文件来实现这一点。

在注释中保持良好的风格，我们需要具备可读性。出于如此，例如，将一个命令语句分成三行，而不是将所有内容在同一行中串联或通过管道连接；在某些情况下，创建一个长管道是理想的。某些情况对于新脚本编写者来说，要追踪管道并理解预期结果可能太难了。而且，它应该有注释逐步描述我们的思考过程。这样，以后某人查看我们的代码时就会说：“嘿，这种处理方法真够酷。”

表 1.1 不同类型的 shell 声明

| 声明 | Shell 类型 |
| :--- | :--- |
| `#!usr/bin/sh` 或 `#!/bin/sh` | 声明 Bourne shell |
| `#!usr/bin/ksh` 或 `#!/bin/ksh` | 声明 Korn shell |
| `#!usr/bin/csh` 或 `#!/bin/csh` | 声明 C shell |
| `#!usr/bin/bash` 或 `#!/bin/bash` | 声明 Bourne-Again shell |
