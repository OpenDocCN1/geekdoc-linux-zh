
解决配置文件分散在多个目录树中的解决方案非常简单：对于每个配置文件，创建一个符号链接，指向一个存放所有配置文件的单一目录。该目录的一个好名称是 `/config`。

例如，假设你的应用需要在正常操作过程中更改 `resolv.conf` 和 `syslog.conf` 文件中存储的值。这两个文件通常位于 `/etc` 目录。然而，`/etc` 目录还包含许多你永远不需要更改但必须存在的文件，例如 `hosts` 和 `services` 文件。与其存储 `resolv.conf` 和 `syslog.conf` 的内容，你只需创建名为 `/etc/resolv.conf` 和 `/etc/syslog.conf` 的软链接，分别指向 `/config/resolv.conf` 和 `/config/syslog.conf`。

这个概念非常强大。`config` 目录可以挂载在与根文件系统根不同的设备上。一来，根目录可以由较小的只读文件系统组成，而 `/config` 文件系统可以存在于闪存中并进行读写。每个配置文件看起来就像存在于服务器期望的位置，但可以由配置软件随心更改。

嵌入式 Linux 工作坊（Embedded Linux Workshop）在此更进了一步。它不是在一个读写目录中有多个配置文件，而是有一个单一配置文件，它可以存在于一个读写目录中，也可以通过简单的内核驱动程序存在于闪存中。将配置信息集中到一个单一文件有几个优势：

- 你不需要一个完整的闪存文件系统来存储单个文件。
- 你的配置软件不需要理解如何修改所有存在的不同类型的配置文件。大多数配置文件是供人类修改的，而不是计算机程序，因此很难通过程序化进行更改。
- 单一配置文件使得复制嵌入式设备变得简单——从一台机器复制单个文件到另一台机器。
- 简单的 `name=value` 结构适用于大多数情况。这种结构人类易于理解，计算机易于解析和修改。

## 解决软件预期冲突

这种方法仍然存在一个问题；需要配置文件的软件程序期望某种特定的格式。例如，`syslog` 程序将无法处理嵌入式 Linux 工作坊单一配置文件中使用的 `name=value` 语法。

解决此问题基本上有两种方法：

- 修改程序，使其能够直接使用单一配置文件。
- 使用嵌入式 Linux 工作坊单一配置文件中的信息，创建程序期望看到的配置文件。

在嵌入式 Linux 工作坊中，绝大多数情况下我使用第二种方法。我相信，对嵌入式项目的各个组件（例如 `syslog`）的改动越少越好。原因如下：

- 如果你拿到它时它是正常的，且你没有动过它，那么它在现场也应该正常工作。
- 如果你不熟悉该软件，修改像 `syslog` 这样的软件是非常困难且容易出错的。然而，从单一配置文件通过 name=value 对创建 `syslog.conf` 文件相对容易。
- 如果你修改 `syslog` 软件直接从单一配置文件读取其配置信息，这是一项你必须永远跟踪的更改。如果你需要升级到更高版本的 `syslog`，你可能需要修复某些久未看到的软件问题。另一方面，如果你使用第二种方法——创建软件期望看到的配置文件，并且新版本中的配置文件语法没有变化，那么在升级版本时你无需任何工作。

在修改软件使用单一配置文件之后，构建软件期望看到的配置文件也有缺点。首先，你的启动时间会比预想的慢。可能慢很多，但仍然慢。其次，自定义配置文件将占用你嵌入式设备上更多的空间。创建应用程序特定配置文件的软件以及配置文件本身占用的空间，取决于你的嵌入式设备的大小，这些空间可能非常宝贵。通常你可以在软件完成读取后删除应用程序特定的配置文件，但这会增加你设置代码的复杂性。

为整个计算机使用单一配置文件有充分的事例。这种方法最著名的例子是 Microsoft Windows 中的注册表（Registry）。尽管存在所有缺点，Windows 注册表通过将所有配置信息移动到一个中央的、可搜索的位置，让开发者和用户的生活变得更加轻松。

### 列表 3.1 /linuxrc 脚本的一部分

```sh
/mnt/envi
for x in $(cd /etc/rc;echo S*); do
  echo Starting $x
  /etc/rc/$x
done
```

脚本的第一行加载配置文件。配置文件的设置方式使得任何需要使用其内容的 shell 脚本都可以通过点 (`.`) 命令简单地加载它，并且所有的 `name=value` 对都会加载到 shell 变量中。`Linuxrc` 脚本会找到 `/etc/rc` 目录下所有以 S 开头的文件名并运行它们。我们将查看的两个脚本是 `S14resolv`（见列表 3.2）和 `S15network`。

### 列表 3.2 S14resolv 脚本 /bin/sh

```sh
#!/bin/sh

######################################################################
# 设置 DNS 解析器
######################################################################
[ -z "RESOLV_CONF" ] && echo "RESOLV_CONF=/etc/resolv.conf"

rm -f $RESOLV_CONF
[ -n "RESOLV_IP0" ] && echo "nameserver $RESOLV_IP0" >> $RESOLV_CONF
[ -n "RESOLV_IP1" ] && echo "nameserver $RESOLV_IP1" >> $RESOLV_CONF
[ -n "RESOLV_IP2" ] && echo "nameserver $RESOLV_IP2" >> $RESOLV_CONF
[ -n "RESOLV_IP3" ] && echo "nameserver $RESOLV_IP3" >> $RESOLV_CONF
```

`S14resolv` 脚本的工作是设置 Linux 系统，使得嵌入式设备内运行的能够能够 DNS 解析网络名称。它是通过首先删除（第 7 行），然后使用配置文件的值构建（第 8–10 行）`/etc/resolv.conf` 文件来实现的。为了让这一切运行，配置文件中有一行如下：

`EXPORT RESOLV_IP="4.2.2.1"`

在 `S14resolv` 脚本完成后，`/etc/resolv.conf` 文件只有一行：

`nameserver 4.2.2.1`

如果我们在配置文件中命名了 `RESOLV_IP1`、`RESOLV_IP2` 或 `RESOLV_IP3`，则 `/etc/resolv.conf` 文件将会有更多的 `nameserver` 行，以反映我们可以访问的多个 DNS 服务器。

接下来，我们将查看一个复杂得多的示例 `S15network`（见列表 3.3）。`S15network` 脚本在启动网络时完成了大部分工作：

- 设置本地回环（localhost）。
- 支持多达 10 个连接。
- 允许网络之间的路由和地址伪装（masquerading）。
- 开始设置用于防火墙规则的 `ipchains`。
- 可选设置默认路由。
- 使用新的命令代替 `ifconfig/route` 以保存状态。

### 3.3 S15network 脚本
