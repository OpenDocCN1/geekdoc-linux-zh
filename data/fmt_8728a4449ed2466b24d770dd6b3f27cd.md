
如果你想强制所有目标重新构建，你可以使用 `-B` 选项（见第 4.4 节 [强制重新构建]，第 39 页）。

如果你想强制特定目标重新构建，你可以使用 `-B` 选项（见第 4.4 节 [强制重新构建]，第 39 页）。

### 3.6 覆盖另一个 Makefile 的模式

有时，拥有一个与另一个 Makefile 类似的 Makefile 是很有用的。你通常可以使用 `include` 指令将一个包含在另一个，并添加更多目标或变量定义。然而，如果两个 Makefile 为同一个目标给出了不同的命令，make 不允许你这样做。还有另一种方法。

在包含的 Makefile（想要包含另一个的）中，你可以使用匹配任意模式的规则，为了重新构建任何无法从包含 Makefile 中的信息构建的目标，make 应该在另一个 Makefile 中查找。关于模式规则的更多信息，请见第 10.5 节 [模式规则]，第 109 页。

例如，如果你有一个名为 `Makefile` 的文件，显示了如何制作目标 `foo`（以及其他目标），你可以写一个名为 `makefile` 的文件，其中包含：

```
foo: *
```

GNU make

# frobnicate > foo

```make
%: force
	$$(MAKE) -f Makefile $$
force:
```

如果你说 `make foo`，make 将找到 `GNUmakefile`，读取它，并发现要制作 `foo`，它需要运行命令 `frobnicate > foo`。如果你说 `make bar`，make 在 `GNUmakefile` 中找不到制作 `bar` 的方法，因此它将使用来自模式规则的命令：`make -f Makefile bar`。如果 `Makefile` 提供了一个更新 `bar` 的规则，make 将应用该规则。对于任何其他 `GNUmakefile` 不知道如何制作的目标，也是如此。

这种工作原理是，模式规则具有一个模式 `%` 的模式，因此它可以匹配任何内容。该规则指定了一个前提条件 `force`，以确保即使目标文件已存在也会执行这些命令。我们为 `force` 目标提供了空命令，以防止 make 搜索隐式规则来构建它——否则它会将相同的匹配规则应用到 `force` 本身，从而导致前提条件循环。

### 3.7 make 如何读取 Makefile

GNU make 分两个不同的阶段执行工作。在第一阶段，它读取所有的 makefile、包含的 makefiles，并内部化所有变量及其值、隐式规则和显式规则，并为所有目标及其前提条件构建依赖图。在第二阶段，make 使用这些内部结构来确定哪些目标需要重新构建，并调用执行这些操作所需的规则。

理解这种两阶段方法至关重要，因为它直接影响变量和函数展开发生的方式；这通常是编写 Makefile 时的困惑来源。我们将对 Makefile 中不同构造体在哪些阶段发生展开进行总结。我们称在**第一阶段展开**为：即在这种情况下，如果展开是在解析 Makefile 时发生在该 Makefile 的部分，则 make 将进行展开。如果展开没有立即执行，而是等到当前上下文或第二阶段才执行，我们则称展开是**延迟的**。

你可能还不熟悉这些结构中的一些。在随后的章节中熟悉它们之前，可以将本节作为参考查表。

## 第 4 章：编写规则

# 4 编写规则

规则出现在 Makefile 中，说明了何时以及如何重新制作某些文件，这些文件被称为规则的**目标**（通常每个规则只有一个目标）。它列出了作为目标前提的其他文件，以及用于创建或更新目标时使用的命令。

规则的顺序并不重要，除非是为了确定**默认目标**：即在你没有另外指定目标时，make 考虑的目标。默认目标是 Makefile 中第一个规则的目标。如果第一个规则有多个目标，则只有第一个目标被视为默认目标。有两个例外：以点开头的目标不是默认目标，除非它也包含一个额外的斜杠 `/`；以及定义了模式规则的目标对默认目标没有影响。（详见第 10.5 节 [定义和重新定义规则]，第 109 页）。

因此，我们通常编写 Makefile，使得第一个规则是编译整个程序或 Makefile 描述的所有程序的规则（通常带有一个目标 `all`）。参见第 9.2 节 [指定目标的参数]，第 89 页。

### 4.1 规则语法

通常，规则如下所示：

```make
targets : prerequisites
command
```

或者如下：

```make
targets : prerequisites ; command
command
```

目标是**空格分隔的文件。可以使用通配符（见第 4.2 节 [在文件名中使用通配符]，第 20 页），形式为 `a(m)` 的名称代表存档文件成员 m（见第 11.1 节 [作为目标的存档成员]，第 121 页）。通常每个规则只有一个目标，但偶尔由于某些原因会有多个（见第 4.8 节 [规则中的多个目标]，第 33 页）。

命令行以一个制表符字符开头。第一条命令可以出现在前提条件之后的行（带有制表符），也可以出现在同一行（用分号分隔）。无论何种方式，效果都是相同的。参见第 5 章 [在规则中编写命令]，第 41 页。

美元符号用于开始变量引用，如果你真的想在规则中使用美元符号，你必须写两个，`$$`（见第 6 章 [如何使用变量]，第 55 页）。你可以通过插入一个反斜杠加换行符来拆分长行，但这不是必须的，因为 make 对文件中行的长度没有限制。

# 第 4 章：编写规则

通过自动搜索多个目录来查找先置条件。当你在目录之间重新分配文件时，你不需要更改单个规则，只需要更改搜索路径。

### 4.3.1 VPATH：所有先置条件的搜索路径

make 变量 `VPATH` 的值指定了 make 应该搜索的目录列表。通常，这些目录预计包含不在当前目录中的先置条件文件；然而，VPATH 指定的是一个 make 应用于所有文件的搜索列表，包括作为规则目标的文件。

因此，如果一个文件被列为目标或先置条件，且在当前目录中不存在，make 会在 `VPATH` 中列出的目录中搜索同名文件。如果在其中一个目录中找到了该文件，则该文件可能成为先置条件（见下文）。规则可以像文件存在于当前目录一样，指定先置条件列表中的文件名。见第 4.3.4 节 [编写 Shell 命令]，第 25 页。

在 `VPATH` 变量中，目录名用冒号或空格分隔。目录列出的顺序是 make 在搜索时遵循的顺序。（在 MS-DOS 和 MS-Windows 上，使用分号作为 VPATH 中目录名的分隔符，因为冒号可以用于路径本身，位于驱动器字母之后。）

例如，

```
VPATH = src../headers
```

指定了一个包含两个目录 `src` 和 `../headers` 的路径，make 会顺序对它们进行搜索。

使用此 `VPATH` 值时，以下规则：

```
foo.o = foo.c
```

其解释方式类似于写成：

```
foo.o = src/foo.c
```

假设文件 `foo.c` 不在当前目录中，但在 `src` 目录中找到。

### 4.3.2 vpath 指令

与 `VPATH` 变量类似、但选择性更强的是 `vpath` 指令（注意是小写），它允许你为特定类的文件名指定搜索路径：即匹配特定模式的文件名。因此，你完全可以为一类文件名搜索某些目录，而为其他文件名搜索其他目录（或不搜索任何目录）。

`vpath` 指令有三种形式：

- `vpath pattern directories`：为匹配模式的文件名指定搜索路径目录。搜索路径 `directories` 是要搜索的目录列表，用冒号（MS-DOS 和 MS-Windows 上用分号）或空格分隔，与 VPATH 变量中使用的搜索路径相同。

- `vpath pattern`：清除与模式关联的搜索路径。
