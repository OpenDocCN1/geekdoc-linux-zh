## 遵循指南操作

一个与 ESXi 相关的指南是 `ESXi.firewall-enabled`。加固指南建议利用 ESXi 主机来限制对主机上运行服务的访问。虽然加固指南中的 PowerCLI 修复值为 `N/A`，但这可能是由于该指南的半操作性质导致的。它不是通用的，而是取决于你的特定环境和 ESXi 主机的规则。例如，如果你使用 NFS 4.1 数据存储、日志和 NFS，你将启用 `nfs4Client`、`NSX Distributed Router Service` 和 `syslog VMHost` 防火墙异常，允许流量进出 ESXi 主机。因此，在查看 VMHost 上启用的防火墙异常时，你需要考虑正在使用哪些功能，这将决定你启用哪些异常。开箱情况下，ESXi 默认防火墙策略是 `IncomingEnabled` 和 `OutgoingEnabled` 均为 `$false`。因此，如果没有防火墙异常，流量到来自 VMHost 的应该是被阻止的。你可以使用以下命令验证 VMHost 的默认防火墙策略：

```powershell
Get-VMHost vMi0[56].dom.int | Get-VMHostFirewallDefaultPolicy

IncomingEnabled OutgoingEnabled
False            False
False            False
```

如果你需要配置 ESXi 主机的默认防火墙策略，可以使用类似下面的代码。此示例假设某人曾在某时候将给定 VMHost 的默认防火墙策略更改为 `$true`，并显示结果的 DefaultPolicy 值为 `$false`：

```powershell
Get-VMHostFirewallDefaultPolicy -vMi0[56].dom.int |
Set-VMHostFirewallDefaultPolicy -AllowIncoming $false

IncomingEnabled OutgoingEnabled
False            False
False            False
```

《加固指南》包含了一个评估命令示例，允许你使用 `Get-VMHostFirewallException` cmdlet 获取当前的 VMHost 防火墙异常。当你需要更改异常时，可以使用 `Set-VMHostFirewallException` cmdlet。例如，假设现在需要使用网络时间协议 (NTP) 来同步网络环境中的时间。你已经使用 `Set-VMHostService` cmdlet 设置了网络策略，但你需要为相关的 NTP 通信启用防火墙异常。以下操作将在给定的 VMHost 上启用 NTP 异常：

```powershell
Get-VMHost vMi0[56].* Get-VMHostFirewallException -Name "NTP Client" |
Set-VMHostFirewallException -Enabled:$true
```

## 虚拟机

《加固指南》中有针对虚拟机的多条准则（约 40 条），其中许多涉及虚拟机对象的高级设置。VMware 在这些虚拟机准则方面做得非常出色；对于几乎所有的准则，都提供了 PowerShell 评估和修复命令。

其中一个修复命令可以稍微扩展的虚拟机指令是 `Guid VM.disable-independent-nonpersistent`。该准则帮助你使用独立非持久磁盘（independent nonpersistent disks），并移除攻击者通过重启和循环电源启动带有独立非持久磁盘的虚拟机来清除磁盘的能力。该准则的 PowerShell 修复命令使用了这些 cmdlet，但没有包含修复所需的完整参数集：将独立非持久虚拟磁盘转换为独立持久磁盘（`IndependentPersistent` disks）。
