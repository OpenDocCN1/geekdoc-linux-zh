
`enable` 命令可以启用和禁用内置命令。无参数时显示所有启用的 shell 内置命令列表。`-n` 选项禁用命令。仅使用 `-n` 选项时，显示所有禁用的内置命令列表。`-all`（或 `-a`）选项显示所有内置命令，并指示每个命令是否已启用。除非名称不是 shell 内置命令，否则 `enable` 返回 0。

## eval

`eval [arguments ...]`

`eval` 读取并拼接其参数成一个单一命令，然后由 shell 读取并执行该命令。`eval` 返回该命令的退出状态。如果没有参数或参数为空，`eval` 返回 0。

## exec

`exec [-] command [arguments]`

`exec` 执行一个命令并替换当前的 shell；不会创建新进程。你可以为命令指定参数。如果 `exec` 的第一个参数是 `-`，shell 会在传递给命令的第 0 个参数中放置一个横杠。如果 `exec` 没有参数，则任何重定向将在当前 shell 中生效，并返回 0 作为其退出状态。

## exit

`exit [n]`

`exit` 导致 shell 退出。如果提供了 `n`，shell 以状态 `n` 退出。如果没有 `n`，则退出状态为上一次执行命令的状态。在 shell 终止之前会执行设置在退出时的陷阱器（`trap`）。

## export

`export [-nf] [name=word] ...`

`export -p`

命名的变量被标记为自动导出到后续执行的 shell 和命令的环境。你也可以在 `export` 命令中为变量赋值。使用 `-f` 选项，名称指的是函数而不是变量。使用 `-p` 选项或不带参数时，将显示此 shell 中导出的所有名称列表。使用 `-n` 选项，可以移除变量的导出功能。参数 `--` 会返回退出状态 0，除非使用了非法选项、其中一个名称不是合法的 shell 变量名，或者将 `-f` 与一个不是函数的名称一起使用。

执行脚本文件时，你启动了一个具有自己 shell 的新进程。在这个 shell 中，你可以定义变量、执行 Linux 命令，甚至执行其他脚本。如果你从当前运行的脚本执行另一个脚本，当前脚本将挂起执行，控制权将转移到另一个脚本。该脚本中的所有命令将在返回并继续执行挂起的脚本之前首先执行。这种从一个脚本执行另一个脚本的过程非常类似于编程语言中的函数或过程调用。你可以认为是一个脚本在调用另一个脚本。调用脚本会等待被调用的脚本执行完毕后才继续执行它的下一条命令。

你放置在脚本中的任何变量定义都定义在脚本的 shell 中，并且仅在该脚本的 shell 内可见；它们对于自己的 shell 来说是局部的。然而，如果你希望能够在脚本内定义变量并在它可能调用的任何脚本中使用它，你不能直接这样做，但可以使用 `export` 命令将变量定义从一个 shell 导出到另一个 shell。当 `export` 命令应用于变量时，它将指示系统为每个新的子 shell 定义该变量的副本。每个新的子 shell 都将拥有该导出变量的副本。在示例中，`myname` 变量被定义并导出。

```
$ myname="Charles"
export myname
```

将导出的变量视为全局变量是错误的。shell 永远无法引用自身之外的变量。相反，会为新 shell 生成一个带有变量值的副本。导出的变量是将值导出到 shell，而不是导出本身。导出变量的作用在某种程度上类似于作用域全局参数。它被复制到任何派生自其 shell 的 shell 中。导出变量 shell 之后直接或间接调用的任何脚本都将获得具有初始值的导出变量副本。重要的是，导出的变量不会传递给进程的父 shell。

## fc

```
fc [-e ename] [-nlr] [first-event] [last-event]
fc -s [pattern=replacement] [event]
```

`fc` 从历史列表中选择一组事件（你最近执行的命令）。这些事件可以指定为字符串或数字。（负数用作相对于当前事件编号的偏移量）。如果没有 `last-event` 参数，则 `first-event` 被设置为 `-16`。`-n` 选项抑制事件编号。`-r` 选项反转事件顺序。`-l` 选项在标准输出上显示事件。默认情况下，调用的编辑器包含这些历史事件。使用 `-e` 选项，你可以指定使用的编辑器 (`ename`)。如果未给出 `ename`，则使用 `FCEDIT` 变量的值，且不设置 `EDITOR` `FCEDIT` 的值。如果两个变量都没有设置，则使用 Vi。`fc` 返回 0，除非遇到非法选项，或 `first-event` 或 `last-event` 指定的历史行超出了范围。如果提供了 `-e` 选项，返回值为最后一次执行的事件的值，如果事件的临时文件发生错误则返回失败。

使用 `-s` 选项，你可以重新执行指定的历史事件。事件参数可以是模式也可以是事件编号。你还可以使用等号 (`=`) 替换事件中的模式（`pattern=replacement`）。`fc mv` 执行以 `mv` 开头的事件。`fc -s` 返回重新执行事件的退出状态。

## fg

`fg [jobspec]`

将后台作业置于前台，使其成为当前作业。如果 `jobspec` 不存在，则使用 shell 对当前作业的概念。如果 `jobspec` 未指定有效的作业或作业控制数字，`fg` 返回 0。如果禁用了作业控制，则返回 0。`jobspec` 可以是 `jobs` 命令显示的作业控制数字。

在下一个示例中，第二个作业被带回前台。你可能不会立即收到提示符，因为第二个命令现在处于前台并执行。当命令执行完成后，提示符将出现，你可以执行另一个命令。

```
$ fg %2
cat *.c > myprogs
```

## BASH 命令 39

### getopts

`getopts` 用于检测 shell 脚本中要使用的选项。`optstring` 参数指定了可以作为 shell 脚本有效选项的字符列表。如果字符后面跟着一个冒号，则预计该选项带有一个参数，该参数与选项用空格隔开。每次执行时，`getopts` 会将下一个选项放入 shell 变量中，并将下一个要处理的参数的索引放入变量 `OPTIND` 中。如果某个选项需要参数，`getopts` 会将该参数放入变量 `OPTARG` 中。shell 不会自动重置 `OPTIND`；如果在同一个 shell 调用中多次调用 `getopts` 并要使用一组新参数，必须手动重置 `OPTIND`。`getopts` 可以通过两种方式报告错误。如果 `optstring` 的第一个字符是冒号，则使用静默错误报告。在正常运行时，遇到非法选项或缺少选项参数时，会打印诊断信息。如果变量 `OPTERR` 被设置为 0，且 `optstring` 的第一个字符不是冒号，则不会显示错误消息。

`getopts` 通常解析位置参数；但如果给了更多参数，`getopts` 将解析这些参数。如果找到指定的或未指定的选项，`getopts` 返回真；如果遇到选项末尾或发生错误，则返回假。

`getopts` 通常用于循环中，以检查用户在调用脚本时可能输入的选项，这里有三个可能的选项：`t`、`r` 和 `s`。`r` 后面跟着一个冒号（:``），预计它接受一个参数。在示例中，如果用户输入 `-a` 选项，带有参数 `ls -al` 的 `ls` 命令将以长格式显示所有文件。然而，如果输入 `-r` 选项并带有文件名，则从 `OPTARG` 变量访问文件名参数，并显示仅该文件的长格式。

```
while getopts tr:s myoption
  do
    case $myoption in
      a) ls -al
      r) ls -l $OPTARG
      s) ls -s
    esac
  done
```
