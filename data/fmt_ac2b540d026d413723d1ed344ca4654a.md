
### 串口标准 I/O 地址设置

串口的标准 I/O 地址设置如下：

| 端口 | IRQ |
| :--- | :--- |
| `/dev/ttyS0` | `0x3f8` |
| `/dev/ttyS1` | `0x278` |
| `/dev/ttyS2` | `0x3e8` |
| `/dev/ttyS3` | `0x2f8` |

中断地址设置不可接受的调制解调器将无法拨号。

### 流控制设置

将“设备”（`device`）项下的“设置”（`setup`）从“CRTSCTS”更改为 `XON/XOFF`。（在某些方法中，`CRTSCTS` 仍然是推荐的流控制方式）。在另一种情况下恰相反：通信速度极其缓慢，因为我没有将“流控制”（`flow control`）设置为“硬件”。

### 随机断开连接的原因与解决

随机断开连接（连接一段时间后）可能有许多原因。

1. 它们可能是由于“数据终端就绪”（`DTR`）信号或“载波”（`carrier`）信号的“故障性”掉落引起的，例如由于线路噪声。调制调器会对挂断做出响应。要更改此默认行为，你可能需要在你的“调制调器初始化”字符串中添加类似 `S10=50`。这设置了执行挂断后 `DTR` 丢失的持续时间（单位为 `0.1` 秒）（检查你的调制调器，“US Robotics”调制调器可能需要尝试调用它）。使用 `S25=200`。
2. 手机电话线上的呼叫功能可能会在发生某些情况时断开你的连接。
3. 旧电话，以及脏污或腐蚀的插头或插座是常见的问题根源。检查连接。更换电缆。让电缆远离电气噪声源。
4. 对于你的村庄来说，调制调器速度太快，对于城市来说则噪声太大。
5. 许多 `ISP` 会在你无任何活动一段时间后（`30` 分钟）强制断开你的连接。

### 调试 PPP 连接

如果你在设置 `ppp` 时遇到问题，你可能想尝试看看你的调制调器在离开家里时是否有类似于 Linux 下 `PROCOMM` 的工具。如果在 RedHat 初始设置期间需要安装它，那么它应该出现在你的系统中。这里有一篇来自 `newsgroup.com.linux.help` 的帖子，它解释了如何使用 `niscisc` 启动 `ppp`（已为了空间编辑）：

> 来自于: `<balthaar@me.net.au>` 回复: `kppp` 的 `ppp` 问题
>
> `Bachuv2`:
>> 另外，作为一项实验，尝试直接连接到你的 `ISP`，手动启动 `ppp`……这可以证明脚本是有 Bug 的。

简单！如果你的 `ISP` 不允许手动登录，那么你就有麻烦了。我遇到过的每个 `ISP` 都这样做，所以……
1. 启动 `minicom`。
2. 拨打你的 `ISP`。
3. 登录。
4. 在你的 `ISP` 开始启动连接后，使用 `ALT-Q`（或任何“不带重置退出”的序列键）运行 `ppp`。
5. 启动 `ppp`，例如：

```
pppd -d /dev/modem 115200
```

好的，`PPP` 将开始运行。尝试 `ping` 你的 `ISP` 或另一个 IP 地址。这将告诉你一切。顺便说一下，这些都在 `PPP-HOWTO` 中。如果你能通过这种方式让 `PPP` 运行，那么说明你有脚本问题。如果 `PPP` 无法工作，那么说明你有 `PPP` 连接问题。

祝好。

### 命令行配置 PPP

如果你想从命令行启动 `ppp`，使用 `netcat` (`root` 权限) 来配置你的第一个 `ppp` 连接 (`ppp`)。你必须输入的信息与你设置 `ppp` 时预期的相似（看起来像这样）：你调制调器的设备、初始化脚本和拨号脚本、你的互联网服务提供商（`ISP`）的电话号码、正确的身份验证（通过在那个槽位中输入用户名和密码）。其他的，使用 `netconf` 工具来输入 DNS 服务器的 IP 地址，因此我编辑了文件 `/etc/ppp/pap-secrets` 并在由 `netconf` 创建的行尾添加了两个 DNS IP 地址，如下所示：

```
# by linuxconf

# login_name ppp my_password 111.111.111.111 222.222.222.222

ifup ppp0

and shut down with ifdown ppp0
```

设置命令行 `ppp` 对我来说并不比运行 `ppp` 更困难，而且启动连接比通过 GUI 界面更方便。有很多命令行脚本来启动/停止 `ppp`，但它们并不易于设置和使用，许多新手似乎在这些方面遇到了问题。例如，在某些情况下，`ifup ppp0` 无法启动接口（拨号），因为没有设备与接口 `"ppp0"` 关联，我编辑了 `/etc/sysconfig/network-scripts/ifcfg-ppp0` 文件以包含此行：

```
MODEMPORT=/dev/modem
```

异常丢失的 `ppp` 连接可以通过作为 `root` 杀死 `ppp` 守护进程来终止而无需重启：

```
killall ppp
```
