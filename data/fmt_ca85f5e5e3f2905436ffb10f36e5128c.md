
在我自己的小角落里，确实没有这样的对决。我真正的生活很空虚。正如我之前提到的，到了这个时候，彼得·安文（Peter Anvin）组织了一个在线募捐活动，筹集了 3000 美元捐款帮助我还清电脑欠款，我在 1993 年底还清了。圣诞节时，我升级了一台 486 DX266，我使用了很多年。但这正是我的生活：我吃饭，我睡觉，也许我去上大学，我写代码，我读了大量的邮件。我有点意识到朋友们更常发生性关系，但这也没关系。

坦白说，我的大多数朋友也是失败者。

## 第十二章

在埃德的那场演讲几乎让我相信，我能承受任何事，甚至像站在一大堆陌生人面前并成为他们关注焦点这样可怕的事情。我的自信心在其他方面也在慢慢建立起来。我被迫就 Linux 的修复和升级做出快速决策，随着每一个决定，我在我作为日益壮大的社区领导者的角色中感觉越来越自在。技术决策从来不是问题；问题在于如何告诉一个人我更喜欢另一个人的建议的更改——并且要做得外交化。有时这很简单，只需要说：“某某人的修复运行得很好。我们为什么不就采用那些呢？”

我从未明白接受我认为并非最佳技术方案之外的东西有什么意义。这是当两个或更多程序员提供竞争性补丁时，避免选边站的一种方式。此外，虽然我当时没有这样想，但这也是一种让人们信任我的方式。而信任是会累积的。当人们信任你时，他们会采纳你的建议。

当然，你必须为所有的信任奠定基础。我猜那开始的时候并不完全是因为我写了 Linux 内核，而是因为我把它发布到互联网上，向任何想要加入并添加他们喜欢功能和细节的人开放，由我对操作系统的核心部分做出最终决定。

正如我从未计划让 Linux 在我自己的计算机之外拥有生命，我也从未计划成为领导者。这只是默认发生的。在某个时间点，一个由五名核心开发人员组成的小组开始在开发的关键领域产生大部分活动。让他们作为过滤器并承担维护这些领域的责任是合理的。

我相当早地就学到了，领导的最佳且最有效的方式是让人们做他们*想要*做的事情，而不是因为你希望他们做。最好的领导者也知道什么时候自己错了，并能够自我修正。而最好的领导者会让其他人替他们做决定。

让我重新表述一下。Linux 的许多成功可以归因于我自身性格的缺陷：

- 1) 我很懒；以及
- 2) 我喜欢为别人的工作获得赞誉。

否则，Linux 开发模式（如果人们这么称呼的话）仍然会局限于半打极客之间的日常电子邮件消息，而不是一个由数十万参与者组成的错综复杂的网络，他们依靠邮件列表、开发者约定和来自可能在 4,000 个同时进行的项目中的企业赞助。在顶端，仲裁关于操作系统内核的争议的是一个领导者，其本能，一直到现在，都不是去领导。

事情总会有最好的结果。我摆脱了那些对我吸引力不大的事情。第一件是用户层，即系统的外部部分，这是最终用户直接打交道的部分，而不是深处的内部代码。首先，有人自愿维护它。然后，维护所有子系统的过程变得有机化。人们知道谁活跃以及他们信任谁，事情就这样发生了。没有投票。没有命令。没有重新计票。

例如，如果有两个人在维护类似类型的软件驱动，我有时会接受他们两个人的工作，看看哪一个最终被使用。用户往往倾向于使用其中一个而不是另一个。或者，如果你让两位维护者自行解决，他们可能会朝着不同的方向演化，他们的贡献最终会有非常不同的用途。

让许多人感到惊讶的是，开源模式实际上是行之有效的。

我想理解自由软件宇宙中黑客的心态会有帮助。（顺便说一下，我通常尽量避免使用“hacker”这个词。在与技术人员个人交谈时，我可能会称自己为黑客。但最近，这个词变得意味着别的东西：那些无所事事，宁愿整天围着电子屏幕破坏企业数据中心而不是去当地图书馆做志愿者，或者至少去风流倜傥一下的未成年孩子。）

正在 Linux 和其他开源项目上工作的黑客——程序员——放弃睡眠、阶梯式健身机锻炼、孩子们的少年棒球队比赛，是的，偶尔还有性，因为他们热爱编程。并且他们热爱成为一项全球协作努力的一部分——Linux 是世界上最大的协作项目——致力于构建任何想要的人都可以使用的最佳和最美观的技术。就这么简单。而且很有趣。

好吧，随着所有这些无耻的自我宣传，我开始听起来像个新闻稿。开源黑客不是特蕾莎修女的高科技对应物。他们确实会以“名单”或“历史文件”的形式将他们自己的名字与其贡献联系起来，这些文件附在每个项目中。最多产的贡献者会吸引雇主的注意，他们搜索代码，希望发现并雇佣顶尖程序员。黑客在很大程度上也是由他们在同行眼中通过做出扎实贡献而能获得的尊重所驱动的。这是一个重要的激励因素。每个人都想给同行留下印象，改善他们的声誉，提高他们的社会地位。开源开发为程序员提供了这个机会。

不用说，1993 年我大部分时间都像 1992、1991 年等那样度过：驼着背对着电脑。这种情况即将改变。

沿着我祖父的学术足迹，我是赫尔辛基大学的助教，被分配负责瑞典语“计算机科学导论”课程的秋季学期。这就是我遇见托芙（Tove）的原因。她对我生活的影响甚至超过安德鲁·塔嫩鲍姆（Andrew Tanenbaum）的书，《*操作系统：设计与实现*》。但我不会用太多细节烦你。

托芙是我课程中十五名学生之一。她已经获得了学前教育学位。她也想学计算机，但进展没有班上其他人快。她最终追上了。

这门课程非常基础——这是 1993 年秋天，互联网流行之前——我一天给班上的作业是给我发邮件。今天听起来很荒谬，但我说：“作为作业，给我发邮件。”

其他学生的邮件包含简单的测试信息，或关于班级的无趣笔记。

托芙邀请我约会。

我娶了第一个通过电子方式接触我的女人。

我们的第一次约会从未结束。托芙是一名学前教师，六次芬兰空手道冠军，她来自一个功能正常的家庭，尽管这是我描述任何不像我家那样古怪的家庭的方式。她有很多朋友。从我们在一起的第一刻起，她就让我觉得她是适合我的女人。（我省略了详细的描述。）几个月内，猫兰迪（Randi）和我搬进了她超小的公寓。

头两个星期，我甚至没费心把我的电脑带过来。除了我的兵役，这两个星期是我自十一岁坐在祖父腿上以来，作为平民最长的一次没有 CPU 的时间。不想赘述，但这仍然是我作为平民没有 CPU 的最长纪录的保持者。不知怎么地，我做到了（再次，细节不感兴趣）。然后几次见到我母亲时，她会咕哝些什么关于“母性自然的胜利”。我想我姐姐和父亲只是不知所措。

很快，托芙出去养了一只猫陪兰迪。然后我们形成了一个美好的模式：晚上独处或和朋友在一起，早上 5 点醒来，这样她可以去上班，我可以早点去大学，在任何人来打扰我之前读我的 Linux 邮件。

### 球类之王（KING OF THE BALL）

#### 一

1.0 版本的诞生对 Linux 而言意味着某种新鲜事物：公关需求的出现。我本来会很高兴地以我介绍之前版本的方式向世界介绍这个新版本。我会在新闻组上写点什么，比如"1.0 版本发布了。自行消化吧。（好吧，不是完全用这些确切的话。）”

许多其他人都认为这是一件大事。出于营销目的，他们想要 1.0 版本。当时有很多新兴的商业公司开始销售 Linux。对他们来说，1.0 版本的重要性源于心理因素，而非技术原因。我对此无法反驳。事实是，当你试图销售操作系统的 0.96 版本时，看起来很糟糕。

我想发布它，因为这对我是一个里程碑，而且这意味着我可以暂时停止修复 bug，重新回到开发工作中。这些公司和 Linux 社区希望以重大的方式将其强加给公众。

我们需要一个公关策略。我本人不会亲自主导这项工作。我对发布新闻稿或发表声明不感兴趣。其他人认为应该那样做，于是其他人自愿接过火炬。Linux 本身的发展大致也是如此——不知怎地，这一切竟然真的行得通了。

Lars 是让首个官方发布成为真正盛事的主要推动力量之一。他和一些其他人认为大学是发布公告的最合适场所。这是合乎情理的。我的卧室太小了。而且，在商业场所主持发布会会树立一个错误的先例。因此，Lars 自愿与大学协调这次活动。赫尔辛基大学的计算机科学系规模足够小，他可以直接与系主任交谈。

赫尔辛基大学非常乐意提供计算机科学系的主礼堂，用于 Linux 1.0 版本的发布。为什么不呢？大学多久才会拥有值得电视新闻报道的内容？

我确实同意做一个演讲。但它没有我那次 Ede（Ede 演讲）经历中的那种恐怖感。好吧，现在回想起来，有些事情确实*更难*了。

比如，我的爸爸在观众席中。而且事实是，这是在芬兰电视上播出的。这是我第一次有机会在电视上看到自己。我的父母都在观众席中（但我相当确定他们没有坐在一起）。Tove 也在那里。这是我爸爸第一次见到 Tove，所以对我来说，这不仅仅是 1.0 版本的发布。由于我参与了最后的演讲准备工作，比如确保我的幻灯片没问题，所以在他们真正见面时我不在场。据说那发生在他们走出礼堂的时候。也许我用眼角余光瞥见了。

在那次演讲中，以及在接下来几年里几乎每次其他演讲中，我谈论的与其说是技术，不如说是开源。这很好。它改变了计算机科学系内部对 Linux 的一些看法。在此之前，Linux 是计算机科学系引以为豪并略微鼓励的事物。但发布之后，系里的人开始更认真地对待 Linux。毕竟，他们已经在新闻上看到了。
