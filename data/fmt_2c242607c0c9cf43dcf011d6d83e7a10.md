## 作业控制 (Job Control)

当你作为 `jsh` 调用 shell 时，除了前述交互式 shell 的功能外，还会启用作业控制。通常，作业控制仅对非交互式 shell 启用，因为它无法从作业控制的额外功能中获益。

启用作业控制后，你在终端输入的每个命令或管道都是一个作业（job）。所有作业都处于以下状态之一。

- 前台作业对控制终端具有读写写权限。
- 后台作业被拒绝读取权限，并对控制终端具有有条件的写入权限（参见 `tty(1)`）。
- 停止的作业被处于挂起状态，通常由 `SIGTSTP` 信号引起（参见 `signal(5)`）。

shell 启动的每个作业都会分配一个正整数，称为作业号（job number），由 shell 跟踪并作为标识符来指示特定的作业。此外，shell 还会跟踪当前和上一个作业。当前作业是最近启动或重启的作业。上一个作业是第一个非并发作业。

作业标识符的可接受语法格式如下

```
%jobid
```

其中你可以按以下格式之一指定 `jobid`。

- `%` 或 `+` 当前作业。
- 上一个作业。
- `? <string>` 命令行中唯一包含该字符串的作业。
- `nn` 作业号 `n`，其中 `n` 是一个作业号。
- `pref` 命令名的唯一前缀（例如，如果命令 `ls -l` 正在后台运行，你可以将其引用为 `%!`；除非加了引号，否则 `pref` 不能包含空格）。

启用作业控制后，环境环境中添加了以下命令来操作作业。

```
bg [%jobid...]
```

在后台恢复已停止作业的执行。如果省略 `%jobid`，则默认为当前作业。
