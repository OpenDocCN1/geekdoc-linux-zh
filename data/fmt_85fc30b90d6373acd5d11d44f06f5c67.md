- 访问控制列表

`X` 维护了一个允许客户端程序运行的主机列表。默认情况下，只有本地主机上的程序以及服务器读取的初始列表中指定的主机可以使用显示。此访问控制列表可以由本地主机上的客户端更改。某些服务器实现还可以实施此机制之外或之外的其他授权机制。该机制的操作可以根据授权协议名称和服务器在连接建立时接收的数据进行判断。

- 激活抓取 (`Active grab`)

当指针或键盘实际上被单个抓取客户端所有时，抓取即为激活状态。

- 祖先 (`Ancestors`)

如果 `W` 是 `A` 的子窗口，那么 `A` 就是 `W` 的祖先。

- 原子 (`Atom`)

原子是与字符串名称相对应的唯一 `ID`。原子用于标识属性、类型和选择内容。

- 背景 (`Background`)

输入输出窗口（`InputOutput window`）有一个背景，其定义为一个像素图（`pixmap`）。当窗口的某些区域内容丢失或失效时，服务器会自动用背景填充这些区域。

- 备存 (`Backing store`)

当服务器维护窗口内容时，离屏保存的像素被称为备存。

- 基础字体名称 (`Base font name`)

用于选择字体族成员的字体名称可能编码为各种字符集。`XLFD` 名称中的 `CharSetRegistry` 和 `CharSetEncoding` 字段标识字体的字符集。基础字体可以是可以是 `XLFD` 名称（包含所有十四个 `'-'` 分隔符），也可以是简短的 `XLFD` 名称（仅包含 `XLFD` 名称的前 12 个字段，但不包括 `CharSetRegistry`，包含或不包含第 13 个 `'-'`），或者是非 `XLFD` 名称。任何 `XLFD` 字段都可能包含通符（cards）。

在创建 `XFontSet` 时，`Xlib` 接受来自客户端的一个或多个基础名称，以选择一个或多个字体族。它们与从本地编码获取的字符集名称相结合，以加载渲染文本所需的字体。

- 位引力 (`Bit gravity`)：当调整窗口大时，窗口内容不一定会被丢弃。可以请求服务器将之前的内容移动到窗口的某些区域（尽管不保证这一点）。这种对窗口内容向窗口某些位置的吸引力被称为位引力。

- 位平面 (`Bit plane`)：当一个像素图或窗口被视为一组位图时，每个位图被称为一个位平面或平面。

- 位图 (`Bitmap`)：位图是具有深度的像素图。

- 边框 (`Border`)：输入输出窗口可以在四边都具有等厚度的边框。边框的内容由像素图定义，服务器会自动维护边框的内容。边框区域永远不会产生暴露（`Exposure events`）。

- 按钮抓取 (`Button grabbing`)：指针上的按钮可以被客户端被动抓取。当按下按钮时，指针会被客户端激活抓取。

- 字节序 (`Byte order`)：对于图像（像素图/位图）数据，服务器定义字节序，具有不同原生字节序的客户端根据需要交换字节。对于协议的所有其他部分，由客户端定义字节序，服务器根据需要交换字节。

- 字符 (`Character`)：用于组织或表示文本的元素集中的成员（`ISO2022`，经 `XPG3` 适配）。注意，在 `ISO2022` 中，字符在被识别为编码字符集之前并不会绑定到编码值。

- 字符字形 (`Character glyph`)：字符的抽象图形符号。

- 字符集 (`Character set`)：一组字符的集合。

- 字符集 (`Charset`)：字符到编码点的统一、状态无关的映射。在 `X` 显示中，如 `Shift-JIS` 等编码的字符串无法直接传递给 `X` 服务器，因为字符集中字符是一个字节或两个字节。满足这些限制的字符集可以作为“字体集”。字体集严格映射到字形，而不是字形。例如 `ISO8859-1`。

窗口的子级是其子窗口。

- 类 (`Class`)：窗口可以是不同的类。有关窗口类型的更多信息请参见 `InputOnly` 和 `InputOutput` 窗口。

- 客户端 (`Client`)：应用程序通过进程间通信（`IPC`）路径连接到窗口服务器，例如 `TCP` 连接或共享内存。该程序被称为客户端：更准确地说，客户端是路径本身。具有多个打开路径的程序被视为多个客户端。资源的生命由连接控制，而不是程序生命。

- 裁剪区域 (`Clipping region`)：在图形上下文中可以指定位图或矩形列表来限制输出到特定区域。定义的图像称为裁剪区域。

- 编码字符 (`Coded character`)：绑定到编码的字符。

- 编码字符集 (`Coded character set`)：建立字符集以及集合中每个字符与其位表示之间一对一对应关系的明确规则集（`ISO2022`，经 `XPG3` 适配）。字符到编码点一对一映射的定义。

- 编码点 (`Codepoint`)：单个字符的编码表示。

- 调色板 (`Colormap`)：调色板由定义颜色值的项组成。与窗口关联的调色板用于显示窗口内容；每个像素值索引调色板产生驱动 `RGB` 值。根据硬件限制，可以同时安装多个调色板，以便与其关联的窗口显示真实色彩。

- 连接 (`Connection`)：服务器与客户端程序之间的 `IPC` 路径被称为连接。客户端程序通常（但不一定）与服务器有一个连接，通过连接发送请求和事件。

- 包含 (`Containment`)：如果窗口可见且指针的热点在窗口的可见区域或其子窗口的可见区域内，则窗口包含指针。窗口边框作为窗口包含的一部分被包含在内。

# 术语表

如果窗口包含指针但没有子窗口包含指针，则位于窗口内。

# 坐标系

坐标系有水平 `X` 和垂直 `Y`，原点 `[0, 0]` 位于左上角。坐标为整数，并与像素中心对齐。每个窗口和位图（`pixmap`）都有自己的坐标系。对于窗口，原点位于边界内部的左上角。

# 光标

光标是屏幕上指针的可见形状。它由热点（`hotspot`）、源位图、形状位图和一对颜色组成。为窗口定义的光标控制着当指针在该窗口内时的可见外观。

# 深度

窗口或位图的深度是每个像素的比特数。图形上下文的深度是它可以与图形输出结合使用的可绘制对象的深度。

# 设备

键盘、鼠标、数位板、轨迹球、按钮盒等等统称为输入设备。指针可以有一个或多个按钮（最常见的的数量是三个）。核心协议处理两种设备：键盘和指针。

# 直接颜色 (`DirectColor`)

直接颜色是调色板的一种类型，其中像素值被分解为三个独立的子字段用于索引。第一个子字段索引数组以产生红色强度值。第二个子字段索引第二个数组产生蓝色强度值。第三个子字段索引第三个数组产生绿色强度值。调色板的 `RGB`（红、绿、蓝）值可以动态更改。

# 显示 (`Display`)

服务器与其屏幕和输入设备被称为显示。`Xlib Display` 结构包含了关于特定显示及其屏幕的所有信息，作为 `Xlib` 与显示器或特定连接通信所需的状态。

# 可绘制对象 (`Drawable`)

窗口和位图都用作图形操作的源和目标。这些窗口和位图统称为可绘制对象。然而，仅输入窗口（`InputOnly window`）不能在图形操作中作为源或目标。

# 编码 (`Encoding`)

一组建立字符集以及字符与其表示形式之间关系的无歧义规则。字符集不需要固定为有限的字符集。表示形式也不需要是均匀长度。例如 `ISO2022` 图形集、状态无关或依赖状态的图形集组合（包括控制集）以及 `X` 复合文本（`X Compound Text`）编码。

在 `X` 中，编码由字符串识别，出现形式为：`XLFD` 名称中的 `CharSetRegistry` 和 `CharSetEncoding` 组件；找不到字体的 `locale` 的字符集名称；或用于标识文本属性编码或为文本选择目标命名编码的原子（`atom`）。编码名称应由 `X` 可移植字符集中的字符组成。

# 字符间距 (`Escapement`)

字符串的间距是在主绘制方向上，从绘制原点到下一个要绘制字符（即紧跟给定字符串的字符）原点的像素距离。

# 事件 (`Event`)

客户端通过事件异步地获取信息。这些事件可以是从设备异步生成的，也可以作为客户端请求的副作用生成。事件被分为类型。除非客户端专门请求了该类型的事件，否则服务器永远不会向客户端发送事件。然而，客户端可以强制将事件发送到其他客户端。事件通常相对于窗口报告。

# 事件掩码 (`Event mask`)

事件相对于窗口请求的。相对于窗口请求的事件类型集通过事件掩码进行描述。

# 事件传播 (`Event propagation`)

设备相关的事件从源窗口向其祖先窗口传播，直到某些客户端对处理该类型的事件表示兴趣，或者该事件被显式丢弃。

# 事件源 (`Event source`)

指针所在的最深窗口是设备相关事件的源。

# 事件同步 (`Event synchronization`)

在将设备事件复用给客户端时，存在某些竞态条件（特别是在窗口管理操作过程中决定指针和键盘事件应该发送到哪里）。事件同步机制允许对设备事件进行同步处理。

# 暴露事件 (`Exposure event`)

服务器不保证在窗口被遮挡或重新配置时保留内容。发送暴露事件是为了在窗口区域内容丢失时通知它们。

# 扩展 (`Extension`)

可以定义核心协议的具名扩展以扩展系统。对输出请求、资源和事件类型的扩展都是可能的且已实现的。

# 字体 (`Font`)

字体是字形（通常是字符）的数组。协议不对字符集进行任何翻译或解释。客户端仅识别用于索引字形数组的值。字体包含额外的度量信息，用于确定字间和行间距。

# 字体字形 (`Font glyph`)

用于字体索引的抽象图形符号。

# 冻结事件 (`Frozen events`)

客户端可以在键盘和指针捕取期间冻结事件处理。

# 术语表

- 客户端间文本通信的编码与解码

**区域名称 (`Locale name`)**

用于为主机 `C` 库和 `X`库函数选择所需区域的标识符。在符合 `ANSI C` 库的系统中，即 `setlocale` 函数的区域参数。

**本地化 (`Localization`)**

在计算机系统中建立特定于本地语言、当地习俗和编码字符集 (`XPG3`) 操作的过程。

**已映射 (`Mapped`)**

如果对窗口执行了映射操作，则该窗口为已映射。未映射的窗口及其装饰框永远是不可查看或不可见的。

**修饰键 (`Modifier keys`)**

`Shift`, `Control`, `Meta`, `Super`, `Hyper`, `Alt`, `Compose`, `Apple`, `CapsLock`, `ShiftLock` 以及类似的键称为修饰键。

**单色 (`Monochrome`)**

单色是 `StaticGray` 的特殊情况，其中只有两个颜色表数组。

**多字节 (`Multibyte`)**

其码点存储在多个字节中的字符；任何编码都可以包含多字节字符；多字节编码中的文本。`ANSI C` 中的 `char*` 零终止字符串数据类型。注意本文中对多字节字符串的引用仅意味着这些字符串可能包含多个字符。

**遮挡 (`Obscure`)**

如果其他窗口挡住了某个窗口，则 `A` 被遮挡了。窗口可以被部分遮挡但仍具有可见区域。如果 `A` 和 `B` 都是可见的，且 `A` 在全局堆叠顺序中较高，且 `A` 的外边缘定义的矩形与 `B` 的外边缘定义的矩形相交，则窗口 `A` 遮挡 `B`。注意 `obscures`（遮挡）与 `occludes`（遮盖/覆盖）之间的区别。此外，注意窗口框也包含在计算内。

**遮盖 (`Occlude`)**

如果其他窗口覆盖了某个窗口，则该窗口被遮盖了。如果 `A` 和 `B` 均已映射，且 `A` 在全局堆叠顺序中较高，且 `A` 的外边缘定义的矩形与 `B` 的外边缘定义的矩形相交，则窗口 `A` 遮盖 `B`。注意 `occludes`（覆盖）与 `obscures`（遮挡）之间的区别。此外，注意窗口框也包含在计算内，且 `Opacity` 不会遮挡其他窗口，但可以覆盖其他窗口。

**填充 (`Padding`)**

在数据流中插入某些字节，以保持协议规范在自然边界上的对齐。这增加了对某些机器架构的可移植性。

**父窗口 (`Parent window`)**

如果 `C` 是 `P` 的子，那么 `P` 就是 `C` 的父窗口。

**被动抓取 (`Passive grab`)**

抓取键或按钮是被动抓取。当键或按钮实际被按下时，抓取才会激活。

**像素值 (`Pixel value`)**

像素是一个 `N` 位的值，其中 `N` 是特定窗口或位图（`pixmap`）中使用的位数（即窗口或位图的深度）。窗口中的像素索引颜色表，以派生出显示的实际颜色。

位图是一个三维位数组。位图通常被认为是一个二维像素数组，其中每个像素的值可以是从 `0` 到 `$2^{N-1}$` 之间的任意值，其中 `N` 是位图的深度（`z` 轴）。位图也可以被看作 `N` 个位图的堆。位图只能在创建它的屏幕上使用。

**位图 (`Pixmap`)**

当位图或窗口被视为位图的堆时，每个位图被称为一个平面（`plane`）或平面位（`plane bit`）。

**平面 (`Plane`)**

图形操作可以限制为仅影响目标的一个子位平面集合。平面掩码（`plane mask`）是描述要修改哪些平面的位掩码。平面掩码存储在图形上下文中。

**掩码 (`Plane mask`)**

指针是当前连接到光标并在屏幕上进行追踪的指向设备。

**指针 (`Pointer`)**

客户端可以主动抓取指针的控制权。然后按钮和移动事件将发送给该客户端，而不是通常会发送到的事件。

**指针抓取 (`Pointer grabbing`)**

指针设备通常是鼠标、平板板或其他具有有效维度运动的设备。核心协议只定义了一个可见的光标，它跟踪连接到其上的任何指针设备。

**指针设备 (`Pointing device`)**

可移动操作系统接口，`ISO/IEC 9945-1` (`IEEE Std 1003.1`)。

**`POSIX`**

在符合 `POSIX` 标准的主机上用于命名文件的 65 个字符在所有区域中都能被正确处理。该集合是：

**`POSIX` 文件名字符集 (`POSIX Filename Character Set`)**

- `* a..z A..Z 0..9`

**属性 (`Property`)**

窗口具有关联属性，由名称、类型、数据格式和一些数据组成。协议对属性不进行任何解释。它们被设计为客户端的通用命名机制。例如，客户端可能使用属性将调整大小提示、程序名称和图标格式与窗口管理器共享信息。

**属性列表 (`Property list`)**

窗口的属性列表是为该窗口定义的属性列表。

**伪色 (`PseudoColor`)**

伪色是颜色表的一类，其中像素值索引颜色表以产生独立的 `RGB` 值；也就是说，颜色表被视为三元组（`RGB` 值）的数组。`RGB` 值可以被动态更改。

**矩形 (`Rectangle`)**

由 `[x,y,w,h]` 指定的矩形具有一条无限延伸的轮廓路径，其顶点位于 `[x,y]`, `[x+w,y]`, `[x+w,y+h]` 和 `[x,y+h]`。

当填充矩形时，右下角的边缘不会被绘制。例如，如果 `w=h=0`，则什么都不会被绘制。如果 `w=h=1`，将绘制一个像素。

**重定向控制 (`Redirecting control`)**

窗口管理器（或客户端程序）可能以各种方式强制窗口布局策略。当客户端尝试更改窗口的大小或位置时，该操作可能会被重定向到指定的客户端，而不是实际执行该操作。

**回复 (`Reply`)**

客户端请求的信息。

**请求 (`Request`)**

客户端可以主动抓取指针的控制权。然后按钮和移动事件将发送给该客户端，而不是通常会发送到的事件。

**资源 (`Resource`)**

客户端可以主动抓取指针的控制权。然后按钮和移动事件将发送给该客户端，而不是通常会发送到的事件。

**`RGB` 值 (`RGB values`)**

伪色是颜色表的一类，其中像素值索引颜色表以产生独立的 `RGB` 值；也就是说，颜色表被视为三元组（`RGB` 值）的数组。`RGB` 值可以被动态更改。

**保存的集 (`Save set`)**

客户端可以主动抓取指针的控制权。然后按钮和移动事件将发送给该客户端，而不是通常会发送到的事件。

**扫描线 (`Scanline`)**

图形操作可以限制为仅影响目标的一个子位平面集合。平面掩码（`plane mask`）是描述要修改哪些平面的位掩码。平面掩码存储在图形上下文中。

**扫描线顺序 (`Scanline order`)**

指针设备通常是鼠标、平板板或其他具有有效维度运动的设备。核心协议只定义了一个可见的光标，它跟踪连接到其上的任何指针设备。

**屏幕 (`Screen`)**

当位图或窗口被视为位图的堆时，每个位图被称为一个平面（`plane`）或平面位（`plane bit`）。

**选择 (`Selection`)**

当位图或窗口被视为位图的堆时，每个位图被称为一个平面（`plane`）或平面位（`plane bit`）。

# 术语表

`Static-independent encoding`（静态独立编码）字符集调用中的任何编码都是固定的，或仅跨单个字符。使用 `ISO2022` 术语，这意味着使用大多数单次移位，而不是锁定移位。

`StaticColor`（静态颜色）`StaticColor` 可以视为伪色彩（`PseudoColor`）的一种退化情况，其中 `RGB` 值是预定义的且只读的。

`StaticGray`（静态灰色）`StaticGray` 可以视为灰度级（`GrayScale`）的一种退化情况，其中灰值是预定义的且只读的。这些值通常是线性或近线性的递增梯度。

`Status`（状态）许多 `Xlib` 函数返回成功状态。然而，如果函数没有执行成功，其参数不会受到干扰。

`Stipple`（点彩）`Stipple` 是一种位图，用于平铺一个区域，作为使用前景颜色进行填充操作的额外裁剪掩码。

`STRING encoding`（字符串编码）`Latin-1`，加上制表符和换行符。

`String Equivalence`（字符串等效性）如果两个 `ISO Latin-1 STRING` 值的长度相同且对应的字节相等或存在等等关系，则被视为相等：十进制值 `65` 到 `90`（包含 `'A'` 到 `'Z'`）与十进制值 `97` 到 `122`（包含 `'a'` 到 `'z'`）两对等效；十进制值 `192` 到 `214`（包含 `'A grave'` 到 '`o diaeresis'`) 与十进制值 `224` 到 `246`（字符 `'a grave'` 到 '`o diaeresis'`) 两对等效；十进制值 `216` 到 `222`（字符 `'O oblique'` 到 '`THORN'`) 与十进制值 `246` 到 `254`（字符 `'o oblique'` 到 `'thorn'`) 两对等效。

`Tile`（瓦砖）`Pixmap` 可以在两个维度上复制以平铺一个区域。`Pixmap` 本身也被称为名称。

`Timestamp`（时间戳）`Timestamp`是以毫秒表示的时间值。它通常是自上次服务器重置以来的时间。时间戳值会回绕（约 `49.7` 天后）。服务器及其当前时间由时间戳 `T` 表示，在解释来自客户端的时间戳时，始终将时间戳空间的一半视为比 `T` 更早，另一半视为比 `T` 更晚。服务器永远不会生成由 `currentTime` 表示的时间戳。该值保留用于在请求中，以表示当前服务器时间。

`TrueColor`（真彩色）`TrueColor` 可以视为直接色彩（`DirectColor`）的一种退化情况，其中像素值中的子字段直接对应相应的 `RGB` 值。也就是说，色板具有预定义的只读 `RGB` 值。这些值通常是线性或近线性的递增梯度。

`Type`（类型）`Type` 是用于标识属性数据解释的任意值。服务器完全不接触类型。它们仅为了客户端的利益。`X` 定义了许多常用类型的可见类型。

如果一个窗口及其所有的祖先窗口都被映射（`mapped`），则该窗口是可见的。这并不意味着窗口的任何部分实际上都是可见。当窗口不可见时，可以对其执行图形请求，但除非服务器维护备份存储（`backing store`），否则输出将不会保留。

如果看屏幕的人实际上可以看到窗口的一个区域，则该区域是可见的；即窗口和该区域没有被任何其他窗口遮挡。

`Whitespace`（空白字符）任何间距字符。在符合 `ANSI C` 标准库的实现中，空白字符是任何 `isspace` 返回为真的字符。

`Window gravity`（窗口重力）当窗口调整大一时，子窗口可能会自动重新定位到窗口中的相对位置。子窗口对其父窗口某些部分的吸引力被称为窗口重力。
