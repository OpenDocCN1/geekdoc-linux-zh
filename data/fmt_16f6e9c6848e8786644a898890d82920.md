
限制要更新的系统。你可以指定多个 `-` 参数将更新限制在 `distfile` 中列出的主机子集中。

- `-n`

打印命令而不执行它们。此选项对于调试 `distfile` 很有用。

- `-Q`

不在在标准输出上显示正在更新的文件。

- `-R`

删除多余文件。如果正在更新目录，则删除远程主机上与主（本地）目录中不对应的文件。此选项对于维护真正相同的目录副本非常有用。

- `-v`

验证所有主机上的文件都是最新的。显示任何过期的文件，按名称更新，且不发送邮件。

- `-w`

将整个文件名附加到目标目录。通常，重命名文件时仅使用名称的最后一部分。这保留了所复制文件的目录结构，而不是将其展平。例如，将文件重命名为 `dir1/dir2 to dir3` 将创建文件 `dir3/dir1` 和 `dir3/dir2`，而不是 `dir3` 和 `dir3`。当你使用以 `-` 开头的文件名时，将除主目录外的部分附加到目标名称。

- `-y`

不更新比主副本更新的远程副本，而是发布警告消息。

## 用法

### 空格字符

换行符、制表符（Tab）和空格字符都被视为空白字符；映射跨行继续，直到遇到下一个映射的开始：要么是一个文件名后跟一个 `->`，或者是文件列表的左括号。

### 注释

注释以 `#` 开始，以换行符结束。

### 宏

`rdist` 具有有限的宏机制。宏仅在文件名或主机名列表以及某些原语操作的参数列表中扩展。宏定义为以下形式的一行：

```
macro = value
```

宏引用是如下形式的字符串：

```
$(macro)
```

尽管（与 `make(1)` 一样），如果宏名仅由一个字符组成，你可以省略括号。

### 特殊字符

`shell` 字符 `{}`, `*`, 和 `?` 被识别并（仅在本地主机上）作为 `csh(1)` 扩展。你可以通过在它们前面加反斜杠来转义特殊字符。`~` 字符也以与 `csh` 相同的方式扩展；但在本地主机和目标主机上分别独立扩展。

### 文件名

不以 `/` 或 `~` 开头的文件名相对于每个目标主机上的用户主目录；它们不相对于当前工作目录。将文件名包含在括号内。

### 原语

你可以使用以下原语来指定 `rdist` 在更新每个文件的远程副本时采取的操作：

```
install [-b] [-h] [-i] [-R] [-w] [-y] [newname]
```

复制过期的文件。在远程主机上执行这些操作。如果你没有提供 `newname` 参数，则在主主机上执行 `shell` 命令。在主主机上执行这些操作。在主主机上，`install` 选项具有与执行命令的 `shell` 相同的语义。

### 邮件地址

当 `rdist` 发现本地文件发生变化时，向以下格式的地址发送邮件：

`user@host`

在主主机上执行这些操作。如果主主机上不存在，则在主主机上执行这些操作。

### 排除文件名

更新不包含 `$` 字符的文件。

### 排除模式

更新匹配正则表达式模式的文件（请参 `ed(1)` 更多信息）。

### shell 命令

在 `distfile` 中，使用分号 (`;`) 分隔多个 `shell` 命令。

- `/etc/host.equiv` 系统信任的主机和用户。
- `/tmp/rdist*` 更新列表的临时文件。

关于 `rdist` 版本不匹配的投诉实际上可能源于启动 `shell` 的某些问题，例如你所在的组太多。

### 警告

超级用户在 NFS 挂载的文件系统上没有习惯的访问权限。使用 `rdist` 复制此类文件系统可能会失败，或者副本可能属于用户 `nobody`。

### Bug

- 源文件必须储存在本地主机上或挂载在本地主机上。
- 没有简单的方法可以在更新目录所有文件后执行一次特殊命令。
- 变量扩展仅适用于名称列表；应该有一个通用的宏机制。
- `rdist` 在遇到负修改时间（1970 年 1 月 1 日之前）的文件时停止。
- 应该有一个“强制”选项以允许用普通文件或符号链接替换空目录。还需要一种更新原本相同文件的模式和所有者的方法。

## read — 从标准输入读取一行

### 概要

```
/usr/bin/read [-r] var...
sh
read name...
csh
set variable = $<
ksh
read [-prsu[n]][nameprompt][name...]
```

## 描述

`/usr/bin/read`

`read` 命令从标准输入读取单行 `-r` 选项。

默认情况下，除非指定了 `-r` 选项，否则反斜杠 (`\`) 作为转义字符。如果标准输入是终端设备且调用的 `shell` 是交互式的，在以下情况下 `read` 会提示输入延续行：

- 当 `shell` 读取到以反斜杠结尾的输入行时，除非指定了 `-r` 选项。
- 当在此文档（here-document）在换行符后未终止时。

该行将像 `shell` 一样被分成字段；第一个字段赋值给第一个变量 `var`，第二个字段赋值给第二个变量 `var`，以此此类推。如果指定的操作数数少于 `read`，则剩余的字段及其之间的分隔符将赋值给最后一个 `var`。如果指定的字段数少于 `vars`，则剩余的 `vars` 设置为空字符串。

由 `var` 指定的变量设置影响当前 `shell` 执行环境。如果 `read` 在子 `shell` 或单独的执行环境中调用（如下所示），则 `read` 不会影响调用者环境中的 `shell` 变量。

```
(read foo)
nohup read...
find -exec read... \;
```

标准输入必须是一个文本文件。

## Bourne Shell

从标准输入读取一行，使用 `IFS` 内部字段分隔符（通常是空格或制表符）划分单词边界，第一个单词赋值给第一个 `name`，第二个单词赋值给第二个 `name`，以此此类推，剩余单词赋值给最后一个 `name`。行可以使用 `\newline` 延续。您可以在字符前加反斜杠对换行符以外的字符进行引用。这些反斜杠在单词赋值给 `name` 之前会被删除，且对反斜杠后的字符不进行解释。除非遇到文件结束符（EOF），否则返回代码为 0。

## C Shell

以下表示法将一行标准输入加载作为变量的值。（参见 `csh(1)`）。

```
set variable = $<
```

## Korn Shell

读取一行并将其拆分为字段，使用 `IFS` 中的字符作为分隔符。转义字符 (`\`) 用于取消后续字符的特殊含义以及行延续。在 `-r` 原始模式下，`\` 字符不被特殊处理。第一个字段赋值给第一个 `name`，以此此类推，剩余字段赋值给最后一个 `name`。`-p` 选项从 `shell` 派生的进程的管道（使用 `|`) 获取输入行。如果指定了 `-s` 选项，输入将保存为历史文件中的命令。您可以使用 `-u` 选项指定一个单数字描述符单元 `n` 来进行读取。文件描述符可以使用 `exec` 特殊命令打开。默认名称为 0，除非输入文件不是第一个默认名称，则使用 `REPLY` 作为默认名称。除非遇到读取错误或文件结束符，否则退出状态为 0。使用 `-p` 选项时遇到文件结束符会清理进程，以便产生另一个进程。如果第一个参数包含 `?`，当 `shell` 是交互式的时，该单词的剩余部分将作为标准错误上的提示。除非遇到文件结束符，否则退出状态为 0。

## 选项

- `-p` 从 `| &` 进程的输出中读取。
- `-r` 不对反斜杠字符进行任何特殊处理。将每个反斜杠视为输入文件的一部分。
- `-s` 将输入作为命令保存到历史文件中。
- `-u [n]` 从文件描述符 `n` 读取（默认为 0）。

### 操作数

- `var` 存在或不存在的 `shell` 变量的名称。
