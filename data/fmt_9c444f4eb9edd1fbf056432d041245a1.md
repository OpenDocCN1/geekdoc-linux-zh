## http

万维 Web 基于超文本传输协议（http）。该协议定义了传输传输传输机制。它依赖于多个底层协议，包括 `TCP`、`DNS` 和 `RPC`。

提供 http 服务常用的软件是 Apache。一个配置良好的、运行 Apache 以及所需底层服务的 Linux 系统是非常优秀的 WWW 服务器。大多数配置要求由 Apache 实施。在这里，我们讨论独立于 Apache 的系统配置问题。

WWW 服务器受到攻击的频率比其他服务器更高。谨慎的服务器管理员将禁用所有对服务器正常运行至关重要的服务。除非另有原因，请确保 Apache 以用户 `nobody` 身份运行。永远不要以 `root` 身份运行任何 WWW 服务器。对于 FTP，所提供的文件应位于受 `chroot` 保护的目录结构中。

一个容量足够的 `/var` 或 `/var/log` 分区，以存储 WWW 服务器生成的日志。高负载服务器使用 `100MB` 分区可能足够。负载沉重的服务器可能需要 `500MB` 或更大的 `/var/log` 分区。

电子邮件已经取代了电话、传真机和直接的人际互动，成为业务通信的核心工具。许多业务的运营已依赖于电子邮件的可靠投递。基于此，我们检查了运行 Linux 的计算机用于投递电子邮件的软件代理，以确保其安全、可靠的投递。

首先，我们必须区分邮件传输代理（MTA）、邮件投递代理（MDA）和邮件用户代理（MUA）。MTA 将邮件从一台计算机传输到另一台计算机，是跨组织和通过互联网传递电子邮件的代理。`qmail` 和 `sendmail` 是 Linux 常见的 MTA。

一旦消息到达目标主机，邮件投递代理就会将其投递到接收者的邮箱箱。`/bin/mail` 和 `procmail` 是 MDA 的示例。

MUA 是用户用于读取、编写、编辑和转发电子邮件的程序。当用户点击“发送”按钮时，MUA 会在消息主体上附加一些头部并将其传递给运行在机器上的 MTA。然后，MTA 会附加额外的头部并尝试将消息投递到目标主机。

## sendmail

`sendmail` 编写于 1981 年，目的是在 BerkNet^1、UUCP 以及 ARPANET^2 之间投递邮件，这些网络当时运行 `NCP`（网络控制协议）以及 `TCP`（传输控制协议），后者取代了 `NCP`。`sendmail` 在各种网络之间投递邮件方面表现出色，并赢得了作为互联网赖以生存的基础软件的地位。

在随后的几十年里，尽管协议的标准化使得需求变得更简单，但 `sendmail` 变得更加庞大和复杂。这个大型、复杂的软件以 `root` 权限运行，并且必须能够无限制地进行交互，接受来自互联网未知机器的连接。`sendmail` 引起的计算机安全问题可能比任何其他开源软件都多，这并不意外。

尽管 `sendmail` 仍然运行在绝大多数邮件服务器上，并且仍然是企业中应用最广泛的免费软件，但应尽可能避免使用 `sendmail`。在寻找新的安全漏洞时需要保持极度警惕。每当出现新漏洞，就必须编译并安装新版本的 `sendmail`。对于大型站点，这可能需要巨大的精力，因为需要测试以确保该版本不会破坏任何功能。然后必须对其进行打包以供大量安装，并对软件包进行测试。注意，不仅是外部邮件网关必须保持更新。正如我们在第 7 章“安全策略”中所讨论的，防御内部攻击同样重要。

如果由于官僚或技术考虑需要运行 `sendmail`，请确保通过检查你的 Linux 发行版网站和检查 `http://www.sendmail.org/` 来确保安装的第^3 版本没有安全漏洞。还有一些邮件列表（我们在第 8 章“强制执行安全”中列出）可以让你随时了解安全问题。请务必保持警惕。

## sendmail 配置

`sendmail` 从单个文件 `sendmail.cf` 中收集配置。当前版本包含一个用于生成 `sendmail.cf` 文件的 `m4` 设施。应该使用 `m4` 包，因为它便于维护任何由它生成的 `sendmail.cf`。维护每个生成生产 `.cf` 文件的 `.mcf` 文件是至关重要的。当需要更新 `.mcf` 文件时，原始的 `.cf` 文件丢失是非常常见的现象。我们建议将 `.mcf` 文件作为任何二进制 `sendmail` 包的一部分进行分发。

## qmail

`qmail` 是一种编写于 1996 年的简单 MTA，旨在为 `sendmail` 提供一种安全的替代方案。`qmail` 由几个较小的二进制文件组成，每个文件执行一个任务。那些必须以 `root` 身份运行的部分以 `root` 运行，这与 `sendmail` 相比有几个优势：不是一个巨大的单体二进制文件。由于每个二进制文件都更小，事实上所有 `qmail` 源代码的代码行少于 `sendmail` 的四分之一。它本身也更安全，因为一个可执行文件被破解并不意味着所有文件都被破解了，而且大多数功能并不以 `root` 身份运行。

## qmail 配置

`qmail` 的配置与 `sendmail` 完全不同。后者将所有配置选项合并在一个臭名昭复杂的单文件中，而 `qmail` 则通过许多简单的文件进行配置，每个文件决定 `qmail` 行为的一个方面。

这使得新手系统管理员（以及一些高级管理员）能够更容易地管理 `qmail`。缺点是大量的文件增加了 `qmail` 的复杂性。

## qmail 安装

大型组织应该制作自己的安装包，以包含尽可能多的配置。在后的情况下，会有两个包：二进制文件和配置文件。我们建议这样做是因为它允许在不更改基础包的情况下对其进行修订。

## 邮件服务结构

在组织内部可靠且及时地投递电子邮件需要邮件服务结构不存在任何可能中断整个组织邮件服务的单点故障。换句话说，任何邮件服务器、DNS 服务器或网络的故障都不应延迟邮件的投递。

## 部门邮件服务器

每个运营部门都应该有一个专门的邮件服务器。这种选择取决于组织的需求和预算。

部门邮件服务器应该将发给内部接收者的邮件重定向到用户的部门邮件服务器。为了使其工作，每个邮件服务器必须能够将用户名解析为全电子邮件地址。用于此的别名信息通常取自别名映射或别名文件。

邮件绝不应传输到客户端工作站进行存储。这样做将违背不在客户端机器上存储任何用户数据的原则。相反，邮件应该存储在邮件服务器上，直到不再需要，并且仅将副本发送到客户端机器进行阅读。为了实现这一点，每个部门邮件服务器都应支持 `POP` 或 `IMAP` 或两者。首选 `IMAP`，但某些 MUA 不支持它。确保用户没有在本地保存邮件的选项。某些系统管理员通过 `NFS` 挂载邮件池供每个客户端使用。这样做是不可的，且通常会导致麻烦。

部门邮件服务器成为其部门邮件的单点故障是可以接受的。接入邮件将在队列中等待直到服务恢复。
