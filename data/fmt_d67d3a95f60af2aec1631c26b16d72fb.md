## grep

`grep` 允许你在文件中搜索文本

如果你想让像 `.*` 这样的正则表达式生效，请使用它；否则你需要使用 `.\t` 进行递归搜索！可以搜索目录下的所有文件。

```
$ grep bananas foo.txt
```

这里我最喜欢的一些 `grep` 命令行参数！

- `-v` 反向匹配：找到所有不匹配的行
- `-o` 仅打印行中的匹配部分（而不是整行）
- `-i` 忽略大小写
- `-l` 仅显示匹配到的文件名
- 搜索二进制文件：将二进制数据视为文本而不是忽略它！
- `-A 3` 显示搜索结果的上下文。`$ grep -A 3 foo` 将显示匹配项后的 3 行上下文
- `-F` 不将匹配字符串视为正则表达式，例如 `$ grep -F ...`

`grep` 的替代方案：`ack`, `aggrep`（更适合搜索代码！）

## find

`find` 在目录中搜索文件

- `-name` / `-iname` 忽略文件名的大小写！例如 `-name '*.txt'`
- `-type [TYPE]`
  - `f`: 普通文件
  - `l`: 软链接
  - `d`: 目录
  - 更多！

`find /tmp -type d -print` 搜索目录哪些文件，动作对搜索到的文件执行什么操作

这里我最喜欢的 `find` 参数！

- `-path` / `-ipath` 搜索完整路径！`-path '/home/*.go'`
- `-maxdepth NUM` 搜索目录时仅向下进入 `NUM` 层
- `-size 0` 查找空文件！用于查找你不小心创建的文件
- `-print0` 打印以空符分隔的名称，配合 `xargs -0` 使用！

`locate`:

`locate` 命令搜索系统上的文件索引数据库。

优点：比 `find` 快
缺点：无法实时更新

```
$ sudo updatedb
```

更新数据库

- `-exec COMMAND` 动作：对找到的每个文件运行 `COMMAND`
- `-delete` 动作：删除所有找到的文件

## xargs

`xargs` 从标准输入（`stdin`）接收空格分隔的字符串，并将其转换为命令行参数

```
$ echo "/home/tmp" | xargs ls
将运行 ls /home/tmp
```

当你想要对文件列表运行相同的命令时，这非常有用！

- 删除 (`xargs rm`)
- 合并 (`xargs cat`)
- 搜索 (`xargs grep`)
- 替换 (`xargs sed`)

如何在所有 `.txt` 文件中将 "foo" 替换为 "bar"：

```
find . -name '*.txt' | xargs sed -i s/foo/bar/g
```

如何对 `Git` 仓库中的每个 `Python` 文件进行 `lint` 检查：

```
git ls-files | grep .py | xargs pep8
```

如果文件名中包含空格 `"my day.txt"`，`xargs` 会认为它是 2 个文件 `"my"` 和 `"day.txt"`，可以这样修复：

```
find . -print0 | xargs -0 COMMAND
```

更多实用的 `xargs` 选项可以让 `xargs` 为每个输入运行一个独立的进程：

```
- -P max-procs 是 xargs 将启动的最大并行进程数
```

## awk

`awk` 是一种用于处理数据列的微型编程语言

基础 `awk` 程序结构：用 `awk` 提取一列文本

我只知道用 `awk` 做两件事，但它仍然很有用！

```
BEGIN {...}
CONDITION {action}
CONDITION {action}
END {...}
```

```
awk -F, '{print $5}'
```

列分隔符用引号？第 5 列

这是我用 `awk` 做的 99% 操作

对匹配 `CONDITION` 的行执行 `action`

有很多 `unix` 命令可以打印文本列（`ps`, `ls`!）

`awk` 程序示例：求第 3 列数字之和

`awk` 程序示例：打印每行超过 80 个字符的行

所以能用 `awk` 获取你想要的列简直太棒了

```
{ s += $3 }; n
END {print s}
```

在末尾执行动作，打印总和！

```
length($0) > 80
```

条件（这里有一个隐式的 `{print}` 作为动作）

## sed

`sed` 最常用于替换文件中的文本

```
$ sed s/cat/dog/g file.txt
```

使用正则表达式

使用 `-i` 直接修改文件

更多一些 `sed` 咒语...

`sed -n 12 p`
打印第 12 行

在 `GNU sed` 中是 `-i`
在 `BSD sed` 中，是 `-i SUFFIX`
每次都让我很困惑

- `-n` 抑制输出，只有你用 `'p'` 打印的内容会被输出

`sed 5d`
删除第 5 行

`sed s+/cat+/dog/+`
用字符正则作为分隔符

`sed 6`
将文件双倍空格（适用于长错误行）

`sed /cat/d`
删除匹配 `/cat/` 的行

比转义 `/` 像 `s/cat//dog//` 得多

`sed '/cat/a dog'`
在包含 `'cat'` 的行后追加 `'dog'`

`sed -n 5,30 p`
打印第 5-30 行

`sed -n s/cat/dog/p`
仅打印修改过的行

`sed 'i17 panda'`
在第 17 行插入 `'panda'`

## tar

`.tar` 文件格式将多个文件合并为一个文件。

`a.txt` `dir/c.txt`

`.tar` 文件本身不压缩。通常你用 `gzip` 压缩：`.tar.gz` 或 `.tgz`！

通常当你使用 `'tar'` 命令时，你会运行一些咒语

要解压 `tar.gz`，使用：

```
- tar -xzf file.gz
```

`x` 用于提取到当前目录（默认，用 `-C` 修改）
`c` 用于创建一个新的 `tar` 文件！
`t` 用于列出存档的内容

`tar` 可以压缩/解压缩
`-Z` `gzip` 格式 (`.gz`)
`-j` `bzip2` 格式 (`.bz2`)
`-J` `xz` 格式 (`.xz`)
& 更多！查看手册 :)

组合在一起

列出 `.tar.bz2` 的内容：
`$ tar -tjvf file.tar.bz2` 详细

创建一个 `.tar.gz`
`$ tar -czf file.tar.gz dir/files` 要放入存档的文件
`-f` 指定要创建或解压的 `tar` 文件

## ps

`ps` 显示正在运行的进程

我通常这样运行 `ps`：

`wchan` 代表 `wide`（宽通道）。`ps auxwww` 会显示每个进程的所有命令行参数，你可以用 `ps` 选择要显示的列（`ps -eo ...`）

其中一个很酷的列是 `'wchan'`，如果进程处于睡眠状态，它会告诉你内核函数的名称

试一试：

```
$ ps aux
a+ttx
u means include together（包含用户）

```

`e` 代表 `environment`（环境）。`ps auxe` 会显示环境变量：

```
$ ps -eo user,pid,wchan,cmd
```

## ★ 进程状态 ★

`f` 代表 `"forest"`（树森林）ツ。`ps auxf` 会向你展示一个 `ASCII` 艺术风格的进程树：

`ps` 有 3 组不同的命令行参数 💔

以下是 `'s STATE 状态列'` 中字母的含义：

1. `UNIX` (一个横杠)
2. `BSD` (无横杠)
3. `GNU` (两个横杠)

- `R`: 运行 (running)
- `S/D`: 睡眠 (asleep)
- `Z`: 僵尸 (zombie)
- `I`: 多线程 (multithreaded)
- `t+`: 前台 (in the foreground)

你可以写类似这样的参数：

```
$ ps f -f
全格式 (UNIX)
```

`pstree` 也可以显示进程树

### top

系统资源占用最高用户的实时更新摘要

> 谁在用所有内存
> `chrome` 显而易见

让我们解释一下 `top` 中的一些数字！

### 负载平均值 (load average)

3 个数字大致反映了系统在过去 1、5 和 15 分钟内对 `CPU` 的需求

如果它高于你拥有的 `CPU` 数量，那通常是不好的

### 内存 (memory)

4 个数字：

`total`（总计）/ `free`（空闲)/ `used`（已用)/ `cached`（缓存）

一个可能意料之外的是：`total` 并不等于 `free + used`！

`total = free + used + cached` 文件系统缓存

### % CPU

![](img/5f5d02ddabdd2009c88fde2963d57414_14_0.png)

这一列是以单核百分比形式给出的。如果你有 4 个核心，这个值可以达到 400 %！

### RES

这一列是“驻留集合大小”（`resident set size`），即你的进程正在使用的 `RAM` 数量。

`SHR` 是 `RES` 中与其他进程共享的部分

### sort & uniq

`sort` 对其输入进行排序

`$n sort names.txt`

默认排序是字母顺序。

`sort -n` 数字排序

| 'sort -order' | 'sort -n' 顺序 |
| :--- | :--- |
| 12 | 12 |
| 15000 | 48 |
| 48 | 96 |
| 6020 | 6020 |
| 96 | 15000 |

`sort -h`: 人类可读排序

| 'sort -n' 顺序 | 'sort -h' 顺序 |
| :--- | :--- |
| 15 | 6 |
| 30 M | 30 M |
| 45 K | 15 G |
| 200 G | 200 G |

实用的示例：

`du -sh * | sort -h`

`uniq` 去除重复

注意 `a` `b` 仍然有 2 个 `b` => 2 个 `'a'`！
`uniq` 只合并相邻的匹配行

`sort + uniq` 将某些内容通过到 `'sort | uniq'`，你将得到一个去重后的列表！

`sort -u` 执行的是相同的操作。

```
a sort -u = 
b b
- 或 sort uniq
```

`uniq -c`
统计它看到的每行的次数。

配方：获取文件中出现次数最多的前 10 行：

```
$ foo.txt
uniq -c
sort -n
tail -n 10
```
