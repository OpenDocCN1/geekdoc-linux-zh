
- `RMAP_NONE` – 不进行特殊处理。如果 `struct page` 指针 `page` 实际上是一个复合页的子页，则它在 PTE 级别映射，而不是大页。

- `RMAP_EXCLUSIVE` – 表示该 folio 是单个进程的独占映射。

- `RMAP_COMPOUND` – 表示该 folio 被映射为大页。

我们调用 `mlock_vma_page()`，它会设置 folio 锁定状态并在 VMA 中设置 `VM_LOCKED` 标志（通常通过用户指定 `MCL_FUTURE` 标志实现）。更多信息请参见第 8.2.1 节。

`page_add_anon_rmap()` 由 KSM 和大页内存逻辑调用（前者不在本书讨论范围内存，后者将在大页章节中讨论），此外它还被 `restore_exclusive_pte()` 调用（带有 `RMAP_NONE_specific`），用于在 fork 时扩展现有 PTE、通过 `do_swap_page()` 换入时调用、在 `remove_migration_pte()` 迁移时调用，以及在 `unmap_pte()` 换出时使 PTE 失用时调用。

## 7.0.13 文件支持的反向映射 folio 操作

文件支持的 folio 也会通过 `_mapcount` 统计映射 VMA 的数量，通过 `page_add_file_rmap()` 将映射添加到 folio 反向映射中：

```c
/**
* page_add_file_rmap - 向文件页面添加 pte 映射
* @page: 要添加映射的页面
* @vma:               添加映射的 vm 区域
* @compound:          将该页标记为复合页或小页
*
* 调用者需要持有 pte 锁
* /
void page_add_file_rmap(struct page *page,
        struct vm_area_struct *vma, bool compound)
    {
        int i, nr = 0;

        VM_BUG_ON(compound && !PageTransHuge(page), page);
        lock_page_memcg(page);
        if (atomic_inc_and_test(&page->mapcount))
            nr++;
        if (nr)
            _mod_lruvec_page_state(page, NR_FILE_MAPPED, nr);
        unlock_page_memcg(page);

        lock_vma_page(page, vma, compound);
    }
```
