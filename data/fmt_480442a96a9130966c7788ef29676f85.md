
`for` 循环停止执行。你也可以写成 `i <= 10`，因为这两个表达式的意思相同。

首先，你将 `i` 乘以 `1.0` 并将结果赋值给 `a`。简单的赋值也可以生效，但这种乘法操作提醒了你正在将该值转换为双精度浮点数。

接下来，你调用了 `print` 函数。格式字符串包含了三个宽度为 `2`、`3` 和 `4` 的整数。在打印完第一个整数后，你打印了一个句号。接着，你打印了一个宽度为七个字符、小数点后五位数字的浮点数。格式字符串后的参数显示，你打印了整数、整数的平方、整数的立方以及整数的平方根。

## 编译程序

要使用 C 编译器编译此程序，请输入以下命令：

`cc sample.c -lm`

该命令生成一个名为 `a.out` 的输出文件。这是 C 编译器最简单的用法。`cc` 是 UNIX 系统上最强大且灵活的命令之一。

许多不同的标志可以改变编译器的输出。这些标志通常依赖于系统或编译器。

某些标志是所有 C 编译器通用的。它们在下文中进行了描述。

`-o` 标志告诉编译器将输出写入到与标志同名的文件中。例如，`cc -o sample sample.c` 命令会将程序放在一个名为 `sample` 的文件中。

**注意：** 这里讨论的输出是编译器的输出，而不是示例程序。编译输出通常是程序，在这里每一个示例中，它都是一个可执行程序。

`-g` 标志告诉编译器保留符号表（程序用于关联变量名与内存位置的数据），这对于调试器是必要的。它的相反标志是 `-O` 标志，它告诉编译器优化代码——即提高其效率。你可以通过使用 `-I` 标志更改头文件的搜索路径，并使用 `-l` 和 `-L` 标志添加库。

编译过程分几个步骤进行，如下所示：

1. **C 预处理器解析文件。** 为了解析文件，它会按顺序读取行、包含头文件并执行宏替换。
2. **编译器解析修改后的代码以检查语法是否正确。** 此过程会建立符号表并创建一个中间对象格式。大多数符号都被分配了特定的内存地址，尽管其他模块中定义的符号（如外部变量）则没有。
3. **最后一个编译阶段——链接，它将不同的文件和库结合在一起，通过解析尚未解析的符号来链接这些文件。**

## 构建大型应用程序

你可以将 C 程序拆分为任意数量的文件，只要没有函数跨越多个文件即可。要编译此程序，你先将每个源文件编译成中间对象，然后将所有对象链接成一个单一的可执行文件。

`-c` 标志告诉编译器在此阶段停止。在链接阶段，所有对象文件都应该列在命令行中。对象文件通过 `.o` 后缀进行识别。

## 使用 `ar` 创建库

如果多个不同的程序使用相同的函数，你可以将它们合并到一个库归档中。你使用 `ar` 命令来构建库。当你在编译命令行包含此库时，系统会搜索归档以解析任何外部符号。列表 6.9 显示了构建和使用库的示例。

**列表 6.9. 构建大型应用程序。**

```
cc -c sine.c
cc -c cosine.c
cc -c tangent.c
ar c libtrig.a sine.o cosine.o tangent.o
cc -c mainprog.c
cc -o mainprog mainprog.o libtrig.a
```

大型应用程序可能需要数百个源文件。编译和链接这些应用程序本身就是一项复杂且容易出错的任务。`make` 是一种可以帮助开发者组织从许多源文件构建复杂应用程序可执行形式过程的工具。第 7 章“`make` 工具”详细讨论了 `make` 工具。

## 调试工具

调试本身是一门科学，也是一门艺术。有时，简单的工具——代码列表是最好的。但在其他时候，你需要使用其他工具。这些工具中的三个是 `lint`、`prof` 和 `sdb`。其他可用的工具包括 `escape`、`cxref` 和 `cb`。许多 UNIX 命令都有调试用途。

`lint` 是一个检查源代码以发现可能问题的命令。代码可能符合 C 标准并编译通过，但执行起来可能不正确。`lint` 检查的是类型不匹配和函数调用中的参数计数错误。`lint` 使用 C 预处理器，因此你可以使用与 `cc` 类似的命令行选项。

你使用 `prof` 命令研究程序在时间上的消耗在哪里。如果程序在编译和链接时使用了 `-p` 标志，执行时会创建一个 `mon.out` 文件。这种分析可以帮助确定瓶颈。

第三个工具是 `sdb`——一个符号调试器。当你使用 `-g` 编译程序时，符号表会被保留，你可以交互地使用 `sdb` 来设置断点、查看值并监控变量。

因此，C 函数接收一个或多个值作为输入，以某种方式对这些值进行转换或处理，并返回一个结果。如果传递的值包含指针，则数据变量的内容可能会被函数修改。正如标准库例程所示，调用函数的代码可能不知道、也不需要知道函数在被调用时采取了哪些步骤。然而，输入参数的数据类型和结果代码等事项在函数定义时就已经指定了，并且在整个程序执行过程中保持不变。

函数也与 C++ 对象相关。但正如你将看到的，当调用对象的函数时，所执行的操作可能会自动不同，甚至有很大差异，这取决于它关联的特定结构特定类型。这一方面被称为函数名的*重载*（overloading）。重载与 C++ 的第二个特征有关，即函数可以被定义为属于 C++ 数据结构——这是更广泛的语言特性*封装*（encapsulation）的一个方面。

除了重载和封装之外，面向对象的语言还允许你定义新的抽象数据类型（包括关联函数），然后从它们派生后续的数据类型。除了整数、浮点数和字符等内置类之外，新类数据对象的概念已经超越了 C 语言中定义复杂数据对象的熟悉能力。正如一个包含（例如）整数元素的 C 数据结构继承了适用于整数的属性和函数，派自另一个类的 C++ 类也*继承*了该类的函数和属性。当定义该类类型的特定变量或结构（实例）时，该类被称为*实例化*（instantiated）。

在本章的剩余部分，你将更详细地查看 C++ 的一些基本特征，并结合代码示例提供这些概念的具体实例。要了解更多关于 C++ 的强大功能，请参阅本章开头提到的标题。

## C 和 C++ 中的引用范围（Scope of Reference）

除了显而易见的面向对象特征外，C++ 在某些细节上与 C 不同。这些细节相当相当肤浅，包括：

- 能够在代码块中的任何地方定义变量，而不仅仅是在代码块的开头
- 增加了 `enum` 数据类型，以便于基于 case 值的条件逻辑
- 能够将函数指定为 `inline`，导致编译器在程序的该点生成函数代码的另一个副本，而不是调用共享代码

其他差异涉及更高级的概念，如内存管理以及变量和函数名的引用范围。因为这些特性（特别是后者）被用于面向对象的 C++ 程序，所以它们在这个关于语言的简短介绍中值得仔细检查。

*引用范围*（scope of reference）一词用于讨论当 C、C++ 或某些其他编程语言允许程序中出现多个同名实例时，名称是如何被解释的。考虑列表 6.10 中的代码。这里定义并调用了两个不同的函数。每个函数都有一个名为 `tmp` 的内部变量。在 `printnum` 内部定义的 `tmp` 是 `printnum` 函数的*局部*变量；也就是说，它只能由 `printnum` 内部的逻辑访问。同样，在 `printchar` 内部定义的 `tmp` 是 `printchar` 函数的局部变量。每个 `tmp` 变量的引用范围分别限于 `printnum` 和 `printchar` 函数。

**列表 6.10。引用范围，示例 1。**

```c
#include <stdio.h> /* I/O 函数声明 */

void printnum ( int ); /* 函数声明 */

void printchar ( char ); /* 函数声明 */

main ()

{

  printnum (5); /* 打印数字 5 */

  printchar ("a"); /* 打印字母 a */

}

/* 定义上面调用的函数 */

/* void 表示函数不返回值 */

void printnum (int inputnum)

{

  int tmp;

  tmp = inputnum;

  printf ("%d \n",tmp);

}

void printchar (char inputchar)

{

  char tmp;

  tmp = inputchar;

  printf ("%c \n",tmp)

}
```
