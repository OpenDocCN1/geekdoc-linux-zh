### 退出状态

- 所有脚本都应该包含注释来描述它们的用途。

- 这个特定的脚本与一个*参数*工作，该参数在脚本被调用时传递给它。

- 这个脚本包含一个*if 语句*，它测试内置变量 `$?` 的条件。该变量被设置为参数的数量。

- 如果参数的数量等于 1，那么脚本会输出用户名。否则，会显示一个错误消息。这对于调试脚本非常有用。最后，脚本会输出参数的数量。

这个命令是，而且你会注意到 `-n` 标志也打印了行号。这些在调试脚本时非常有用，请注意它们*不是*脚本的一部分。

现在我们将检查一个新的内置变量 `$?` 的值。目前，只需观察输出：

```
$ echo $?
0
```

现在让我们考虑 `cat` 会失败的情况。首先我们将看到错误消息，然后检查 `$?` 的值。

```
$ cat -n dummyfile.sh
cat: dummyfile.sh: No such file or directory
$ echo $?
1
```

这种行为的解释是：任何 `cat` 工具的执行都会返回一个退出状态。退出状态告诉我们命令是否成功，还是发生了错误。退出状态为 0 表示命令成功完成。对于你使用的每一个 Linux 命令都是如此。任何其他退出状态都表示某种错误。最后运行的命令的退出状态将存储在变量 `$?` 中。

退出状态通常对人类用户不可，但在编写脚本时它们非常有用。考虑我们正在复制文件到远程驱动器的脚本。复制任务可能有许多失败方式：例如我们的本地机器可能没有连接到网络，或者远程驱动器可能满了。通过检查复制工具的退出状态，我们可以在运行脚本时提醒用户问题。

实现退出状态是一个非常好的习惯，所以我们将这样做。我们的脚本中有两条路径，成功和失败。让我们用 0 表示成功，用 1 表示失败。

### 处理多个参数

到为止，我们的脚本一次只能处理一个用户名。除了一个之外，任何数量的参数都会导致错误。让我们探索如何让这个脚本更具通用性。

用户的直觉可能是使用更多的位置变量，如 `$2`, `$3` 等。遗憾的是，我们无法预测用户可能选择使用的参数数量。为了解决这个问题，引入内置变量将非常有帮助。

我们将修改脚本的逻辑。零参数应该报错，但任何其他数量的参数都应该成功。这个新脚本将名为 `friendly2.sh`。

```bash
1 #!/bin/bash
2
3 # a friendly script to greet users
4
5 if [ $# -eq 0 ];
then
7 echo "Please enter at least one user to greet."
8 exit 1
else
10 echo "Hello @!"
11 exit 0
12 fi
```

```bash
$ ./friendly2.sh Carol Dave Henry
Hello Carol Dave Henry!
```

有两个包含传递给脚本的所有参数的内置变量：`$@` 和 `$*`。大部分情况下，两者的行为相同。Bash 会解析参数，并在遇到参数之间的空格时将每个参数分开。实际上，`$@` 的内容看起来：

| 1 | 2 |

| Carol Dave Henry |

如果你熟悉其他编程语言，你可能将这种变量识别为数组。Bash 中的数组可以通过简单地在元素之间放置空格来创建，如下所示 `arraytest` 脚本中的 `FILES` 变量：

```bash
FILES="/usr/sbin/accept /usr/sbin/pwck/ /usr/sbin/chroot"
```

它包含一个许多项的列表。但这并没有什么帮助，因为我们还没有引入任何单独处理这些项的方法。

### For 循环

让我们参考之前展示的 `arraytest` 示例。如果你还记得，在这个例子中，我们指定了一个名为 `FILES` 的数组。我们需要一种方法来“解包”这个变量并逐接访问每个单独的值。为了做到这一点，我们使用一种称为 `for` 循环的结构，它在所有编程语言中都存在。我们将涉及到两个变量：一个是范围，另一个是当前正在处理的单个值。整个脚本如下：

```bash
#!/bin/bash

FILES="/usr/sbin/accept /usr/sbin/pwck/ /usr/sbin/chroot"

for file in $FILES
do
  ls -lh $file
done
```
