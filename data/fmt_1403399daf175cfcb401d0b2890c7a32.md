
## 使用

使用 `xgettext` 命令自动创建可移植的消息文件（`.po`）。`po` 文件包含 ANSI 源代码中 C 字符串的副本（或者在命令行上指定 `-` 时，包含标准输入的内容）。你可以将 `.po` 文件作为 `msgfmt(1)` 命令的输入，该命令会生成消息文件的二进制格式，应用程序可以在运行时使用它。

`xgettext` 将文件名中 `gettext(3)` 调用的 `msgid` 字符串写入到由 `-d` 选项指定的输出文件名。`gettext()` 调用中的 `msgid` 字符串被写入输出文件 `domainname.po`，其中 `domainname` 是 `gettext()` 调用的第一个参数。

默认情况下，`xgettext` 在当前工作目录中创建 `.po` 文件，且每个条目的顺序与字符串从文件名中提取的顺序相同。当指定 `-p` 选项时，`.po` 文件将在 `pathname` 目录中创建。任何现有的 `.po` 文件将被覆盖。

重复的 `msgid` 将作为注释行写入 `.po` 文件。当指定 `-s` 选项时，`.po` 文件将按 `msgid` 字符串排序并移除重复的 `msgid`。除非使用 `-m` 选项，否则 `.po` 文件中的所有 `msgstr` 指令均为空。

> 注意 — `x` 无法提取强制转换字符串，例如 ANSI C 将字面量字符串强制转换为 `(const char *)`。此功能在任何地方都不是必要的，因为 `<libintl.h>` 中的原型已经指定了该类型。

## 选项

提取所有字符串，而不仅仅是在 `gettext(3)` 和 `gettext()` 调用中的字符串。仅创建一个 `.po` 文件。

- `-a`
- `-c comment-tag` 将以 `comment-tag` 开头的注释块作为第一个标记，作为以 `#` 分隔的注释写入输出的 `.po` 文件。对于多个域，`xgettext` 将注释和消息重定向到优先的文本域。
- `-d default-domain` 将默认输出文件 `messages.po` 重命名为 `default-domain.po`。
- `-h` 在标准输出上打印帮助信息。
- `-j` 将消息与现有消息文件合并。如果 `.po` 文件不存在，则创建它。如果 `.po` 文件存在，则追加新消息。注释生成的 `.po` 文件中的任何重复 `msgid`。忽略现有 `.po` 文件中的域指令。如果现有的消息文件被编辑过，则不保证结果。
- `-m prefix` 用前缀填充 `msgstr`。此选项用于调试。要使 `msgstr` 与 `msgid` 相同，请使用空字符串 `("")` 作为前缀。
- `-M suffix` 用后缀填充 `msgstr`。此选项用于调试。
- `-n` 向输出文件添加注释行，指示在源文件中遇到每个提取字符串时所在的文件名和行号。这些行出现在每个 `msgid` 之前，格式如下：

```
#
# File: filename, line: line-number
```
- `-p pathname` 指定输出文件放置的目录。此选项会覆盖当前工作目录。
- `-s` 生成按 `msgids` 排序的输出并移除所有重复的 `msgids`。
- `-x exclude-file` 指定一个 `.po` 文件，其中包含一个不需要提取的 `msgid` 列表。你可以使用 `-a` 选项。

# xstr

你也可以对单个文件使用 `xstr`。以下命令会创建 `files.c` 和 `xs.c`，而不会影响相同目录下的任何字符串。

如果任何宏定义产生字符串，或者存在包含字符串的条件代码，那么在 C 处理器之后运行 `xstr` 是很有用的；事实上，当你指定参数时，`xstr` 从标准输入读取。以下示例显示了在 C 处理器后运行 `xstr` 的适当命令序列。

```bash
$ cc -E name.c | xstr -c
$ cc -o x.c
$ mv -o name.o
```

除非添加了新项，否则 `xstr` 不触碰文件；因此，`make(1)` 可以避免重新制作 `xs.o`。

# 注意事项

注意 `xstr` 会不加地将所有字符串替换为 `&x[number]` 形式的表达式，无论原始 C 代码是否使用了该字符串。例如，你会在使用 `sizeof()` 确定字面量字符串长度的代码中遇到问题，`xstr` 将字面量字符串替换为一个大小可能与字符串不同的指针。要规避这个问题：

- 使用 `strlen()` 代替 `sizeof()`。注意 `sizeof()` 返回包括末尾空字节的数组大小，而 `strlen()` 不计算末尾空字节。`sizeof('xxx')` 的等效实际上是 `(strlen("xxx"))`。
- 对操作数使用 `#define` 并使用定义版本。`xstr` 忽略 `#define` 语句。确保在对预处理器运行之前运行 `xstr filename`。

当你声明如下初始化字符数组时，也会遇到问题。

```c
char x[] = "xxx";
```

`xstr` 将 `xxx` 替换为如下形式的表达式：
`&x[number]`

这无法编译。要规避这个问题，请使用 `static char *x = "xxx"` 代替 `static char x[] = "xxx"`。

# yacc — 另一个编译器编译器

# 语法概要

`/usr/ccs/bin/yacc [-dltVv] [-b file-prefix] [-Q [y|n]][-p parser] [-p sym-prefix] file`

## 描述

`yacc` 命令是一个第四代开发工具，与 `lex(1)` 命令结合使用，允许你通过描述应用程序应该如何运行而不是指定它应该做什么来执行词法分析和开发。

`yacc` 命令将上下文无关文法转换为简单自动机的状态表，该自动机执行 `LALR(1)` 解析算法。`LALR`（前瞻 LR）解析是 LR 解析的一种功能较弱的变体，产生的解析表要小得多。文法可以发现歧义语法。你可以指定优先级规则来消除歧义。

你必须使用 C 编译器编译 `y.tab.c` 输出文件以生成 `yyparse()` 函数。然后，你必须使用 `yy` 词法分析器程序加载此程序，并配合 `main()` 和 `yy()` 错误处理例程。你必须提供这些例程。`lex(1)` 命令对于创建 `yacc` 可用的词法分析器非常有用。

要使用 `yacc` 命令生成解析器，请指定一个描述输入数据流以及解析器如何处理数据的文法文件。

# 1518 yacc

文法文件包括输入结构中描述的规则、识别到这些规则时调用的代码，以及执行基本输入的子程序。

两个相邻的双百分号 `%%` 分隔文法文件的每个部分。为了方便阅读文法，请将 `%%` 独占一行。一个完整的文法文件结构如下：

```
declarations
%
rules
%%
programs
```
