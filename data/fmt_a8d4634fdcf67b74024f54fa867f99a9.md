## 区域文件示例：sam.net

```
$ cat sam.net
; zone "sam.net"
```

```
$TTL 3D
@ IN SOA ns.sam.net. mgs@sobell.com. (
    20071105 ; serial
    8H       ; refresh
    2H       ; retry
    4W       ; expire
    1D       ; minimum
)
```

```
IN TXT "Sobell Associates Inc."
IN NS ns              ; 名称服务器地址（未限定）
IN NS ns.max.net.     ; 名称服务器地址（限定）
IN MX 10 mail         ; 邮件交换（主/未限定）
IN MX 20 mail.max.net. ; 邮件交换（次要/限定）
```

```
localhost IN A 127.0.0.1
```

```
www IN CNAME ns
ftp IN CNAME ns
```

```
gw IN A 192.168.0.1
IN TXT "Router"
```

```
ns IN A 192.168.0.6
IN MX 10 mail
IN MX 20 mail.max.net.
```

```
mark IN A 192.168.0.3
IN MX 10 mail
IN MX 20 mail.max.net.
IN TXT "MGS"
```

```
mail IN A 192.168.0.4
IN MX 10 mail
IN MX 20 mail.max.net.
```

某些资源记录在 Name（名称）字段中有一个值；如果没有名称，则继承上一个资源记录的名称。同样地，上一个资源记录也可能有一个继承的名称值，依此类推。紧随 SOA 资源记录的五个资源记录从 SOA 资源记录继承了 `@`（即区域名称）。这些资源记录属于整个区域。在前面的示例中，第一个 TXT 资源记录从 SOA 继承其名称；它是 `sam.net` 区域的 TXT 资源记录（执行命令 `host -t TXT sam.net` 可显示 TXT 记录）。

这五个资源记录之后是属于该区域内某个域的资源记录。例如，跟在 Name 字段设置为 `mark` 的 A 资源记录之后的 MX 资源记录是 `mark.sam.net` 域的资源记录。

## 从服务器

`localhost` 的 A 记录之后是两个 CNAME 资源记录，它们将 `www.sam.net` 和 `ftp.sam.net` 指定为名称服务器 `ns.sam.net` 的别名。例如，连接到 `ftp.sam.net` 的用户将连接到 `192.168.0.6`。名为 `gw`、`ns`、`mark` 和 `mail` 的资源记录是 `sam.net` 区域内域的资源记录。

在重启 `named` 之前，请为日志文件创建目录并按如下所示赋予权限和所有权。如果你在 chroot 监狱中运行 `named`，请在 `/var/lib/named/var/log` 创建 `bind` 目录。

```
$ sudo mkdir /var/log/bind
$ sudo chown bind:bind /var/log/bind
$ ls -ld /var/log/bind
drwxr-xr-x 2 bind bind 4096 Jun 26 17:43 /var/log/bind
```

将日志存放在 `etc/bind`（或 `named.conf`、`db.root`、`named.conf.local`，如果你在 chroot 监狱中运行 `named`，则位于 `/var/lib/named/etc/bind` 中），重启 `named` 并检查日志文件。`/var/log/syslog` 文件应该显示如下内容（示例中的 `named` 在 chroot 监狱中启动）：

## 从服务器配置

要设置从服务器，请复制 `/etc/bind/named.conf` 文件从主服务器到从服务器，并修改相应的 `type` 为 `slave` 以及指定 `masters` 地址。

## 分区域服务器

BIND 9 在 `named.conf` 中引入了视图。视图子句实现了分布式 DNS 服务器。假设你想建立一个处理查询方式与互联网不同的局域网。分区域（称为 DMZ）DNS 服务器通过区别对待来自公共用户的查询来处理这种情况。视图子句指定哪些客户端看到哪个视图，这取决于解析器的地址。一个视图供局域网/本地用户使用；另一个供互联网/公共用户使用。Logging 子句为默认设置建立 `misc.log` 文件。有几种方法可以指定哪些客户端看到哪个视图。以下 `named.conf` 使用 `match-clients`：

`/etc/bind/named.conf`

```
options {
    directory "/etc/bind";
}; // end options

view "local" IN {
    // start local view
    match-clients { 127.0.0.1; 192.168.0.0/24 };
    recursion YES;
}

zone "zach.net" IN {
    type master;
    file "local.net";
    notify YES;
}

zone "0.168.192.in-addr.arpa" IN {
    type master;
    file "named.local";
    notify YES;
}
// end local view

view "public" IN {
    // start public view
    match-clients { "all" };
    recursion NO;
}

zone "zach.net" IN {
    type master;
    file "public.net";
    notify YES;
}

zone "0.168.192.in-addr.arpa" IN {
    type master;
    file "named.public";
    notify YES;
}

zone "." IN {
    type hint;
    file "named.ca";
}

logging {
    channel "misc" {
        file "/var/log/bind/misc2.log" versions 2 size 1m;
        print-time YES;
        print-severity YES;
        print-category YES;
    }
    category default {
        "misc";
    }
} // end logging
```

### 分裂区域服务器配置细节

为了让 `named.conf` 更易于理解和维护，View 子句中的区域可以具有相同的名称但不同的区域文件。示例中的 `public` 和 `local` View 子句都有 `zach.net` 区域：`public` 的 `zach.net` 区域文件命名为 `public.net`，本地的命名为 `local.net`。

Logging 子句详见第 875 页。

定义 `zach.net` 的区域与之前的示例中的类似；`public` 文件是本地文件的子集。两个文件中的 SOA 资源记录之后是 TXT、两个 NS 和两个 MX 资源记录。接下来是三个 CNAME 资源记录，它们将指向 `www.zach.net`、`ftp.zach.net` 和 `mail.zach.net` 的查询定向到名为 `ns.zach.net` 的系统。随后四个资源记录指定了 `ns.zach.net` 的两个服务器地址和邮件服务器。

最后四个资源记录出现在 `local.net` 区域中，而不是 `public` 区域中；它们是本地系统的 A 资源记录。与其将这些信息保存在每个系统的 `/etc/hosts` 中，不如将其保存在 DNS 服务器上，在那里可以轻松地更新。当你使用 DNS 代替 `/etc/hosts` 时，必须相应地更改 `/etc/nsswitch.conf`（第 542 页）中的 `hosts` 行。
