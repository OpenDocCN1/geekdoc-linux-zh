## 引言

Linux 是一种基于 UNIX 的免费操作系统。Linux 最初是 Linus Torvalds（林纳·托瓦兹）的一个爱好项目，当时他认为他大学使用的 MINIX 操作系统还有改进空间。在互联网上全球开发者的帮助下，Linux 在过去几年中成为了最强大且稳健的操作系统之一。

现在，Linux 是一项强大的操作系统，可以与 Windows NT 以及其他版本的 UNIX 等许多顶级操作系统直接竞争。由于其低成本、可扩展性和网络就绪性，Linux 在服务器市场中为自己赢得了一席之地，特别是在数据库、电子商务和 Web 服务器领域。

Linux 不仅是一个强大的服务器操作系统：它还具有强大用户界面的桌面环境，类似于 Macintosh 或 Windows 的风格。今天，Linux 有许多强大的软件产品，它们具备与其非 Linux 版本的所有功能，如文字处理器、会计应用程序、数据库等。

尽管今天 Linux 有成千上万的可用应用程序，但与 Windows 的可用软件相比仍无法比拟，不过这种状况正在改变。Linux 的宏大程度上源于其开发服务器应用程序的能力。通过 Kylix，Linux 开发者首次有了一个快速应用开发工具，用于生成客户端应用程序，其速度与他们的 Windows 朋友一样快。Orlando 曾自豪地预测当 Kylix 出现时，Linux 桌面应用程序的数量将增加一倍。同时 Kylix 也让为 Linux 创建工业级服务器应用程序变得简单。Kylix 的强大之处在于，它可以直接连接到 Linux 的核心 API 函数，从而将 Linux API 推向极限。

让我们进入 Linux API。Linux API 是一个极其强大的函数系统，基于过去几十年间软件开发标准的稳固演进。Linux 本身基于 UNIX，后者是由肯·汤普（Ken Thompson）在贝尔实验室开发的。贝尔实验室还开发了 C 语言，并完全用 C 语言开发了 UNIX 操作系统。因此，核心 API 包含部分标准 C 以及 UNIX 系统功能，如进程管理、基于 UNIX 的文件处理、套接字（`sockets`）、POSIX 线程等。

最初，由 Linux API 的库被编译到应用程序中，就像 Kylix 将 Pascal 单元编译到你的应用程序中一样。后来，随着 Linux 的增长，它开始实现许多与 UNIX 使用的相同的行业标准，包括 POSIX、IEEE 和 X/Open 标准。

POSIX 库在 Linux API 中被大量使用。POSIX 本身涵盖了函数库为了实现专业的、任务关键型应用程序而需要实现的领域。进程管理、线程和进程间通信是 POSIX 库实现的某些领域。

一旦 Linux API 调用大部分被定义，构成 Linux API 的库就从静态链接变为任何应用程序都可以链接的共享对象库（`shared object library`）。它包含主函数，但能够被任何应用程序使用，而不仅仅是 C 和 C++。这是允许 Kylix 使用 Linux 函数的主要飞跃之一。通过这些 UNIX 调用、POSIX 和 X/Open 用的收敛，库被置于开放许可下，并正式称为 GNU（“GNU Not Unix”的缩写），这是一个由开发者组成的开源社区，他们创建软件、工具和文档来造福软件社区。你经常会发现 Linux API 拥有 GNU LibC 或“Linux API”。这些名称都可以互换使用。

## Kylix 开发历史

每个人都在谈论 Kylix。Kylix 是 Borland（博兰）在其 Linux 平台上流行工具的转生。Delphi 是适用于 Windows 操作系统的快速应用开发（RAD）环境。Delphi 的强大源于它内部有一个可重用且强大的对象模型，称为视觉组件库（VCL），直接访问数据库的支持，以及一种比任何方法都快的构建应用程序的方法。Kylix 没有丢失 Delphi 的任何优点。它仍然具有基于 VCL 的相同对象模型，但现在同时为 Windows 和 Linux 实现了 CLX（跨平台库）。它仍然拥有强大的数据库支持，但现在可以连接到 MySQL 和 InterBase 等数据库。Delphi 与 Windows API 有着强有联系，而 Kylix 同样能够以相同的方式访问 Linux API。然而，使用 Linux API 编码也有缺点，第一个也是最主要的缺点是，你失去了 CLX 提供的跨平台特性。你没有了可以直接在 Delphi 和 Kylix 之间移动的直接移植代码。使用 Linux API 编码意味着你也失去了可能熟悉的 VCL 或 CLX 的易用性。但它也有益处——许多益处。通过使用 Linux API，你可以访问 Kylix 的强大功能。通过能够使用 Linux API 提供的内置函数，你可以利用管理 Kylix 的各个方面。Linux API 是一个函数的强力中心，允许开发者管理进程、文件、套接字、系统管理等。Linux API（也称为 GLIBC 或简单的 LibC）是实现 IEEE 设定的 POSIX 标准的函数集合。POSIX 被设计为一种平台无关的编程接口。

## 为什么我应该使用 Linux API？

有人曾说过：“知识就是力量”。在软件开发方面，学习底层系统 API 的知识赋予了你为你和客户设计并开发更高效应用程序的能力。通过观察系统如何作为一个整体工作，你将处于为客户创建解决方案 Better 位置，更好的理解也将帮助你分析在新应用程序中发现的任何错误。

## 章节摘要

- **第 1 章——Linux API 入门** 定义了 Linux API，并对 Linux API 的演进进行了简要讨论。本章还讨论了 Kylix 如何与 Linux API 工作。
- **第 2 章——Linux 错误** 列出了大多数 Linux API 调用可能返回的错误代码。本章还演示了将 Linux API 错误消息与 Kylix 普通异常模型合并的技术。
- **第 3 章——Linux 输入/输出** 检查了用于文件和目录时基本输入输出的 Linux API 调用。从读写文件和流开始，本章检查了导航目录、文件锁定和获取性能的方法。
- **第 4 章——进程** 查看了创建、调用和操作 Linux 进程。引入了进程、进程组和 `fork` 的概念，同时检查了 Linux 用户环境。
- **第 5 章——进程间通信 (IPC)** 处理不同进程之间的通信方法，如信号、管道、命名管道、消息队列和共享内存。检查了每种通信方法的优点和缺点，以及将这些方法集成到你的常规 Linux CLX 调用中的方法。
- **第 6 章——POSIX 线程** 涵盖了 Linux 同一进程内的多任务处理方法。本章检查了何时使用线程以及线程间的同步方法，以及线程调用与 CLX 库的集成。
- **第 7 章——套接字 API 函数** 研究与 Linux 直接 TCP/IP 通信，以及创建快速高效套接字客户端和服务器的方法，并讨论了将直接 API 调用与 Kylix 的 `TclientSocket` 和 `TServerSocket` 以及新的 NetCLX 组件集成的方法。
- **第 8 章——实现其他 API** 赋予你知识，将任何用 C 编写的现有 Linux API 转换为从你的应用程序调用的 Object Pascal。当您需要调用大量未针对 Kylix 转换的库函数时，这特别有用。

## getenv LibC.pas

### 语法

```pascal
function getenv(
  Name: Pchar
): PChar;
```

### 描述

`getenv` 函数返回一个环境变量名/值对的值。典型的环境变量的形式为 "HOME=/root."。通常可以使用 `env` 命令查看环境变量列表。

### 参数

**Name**: Name 指名/值对中环境变量值的名称。

### 返回值

函数返回环境变量名/值对的值。

### 另参考

`getenv`, `putenv`, `cleareenv`, `__secure_getenv`

### 示例

```pascal
var
  MailDir: string;

begin
  // 查找 Mail 目录的位置。
  MailDir := StrPas(getenv('MAIL'));
  showmessage('Mail for the user can be found in ' + MailDir);
end;
```

# Linux API 入门

欢迎来到精彩的 Linux 世界。接触 Linux 一段时间的人知道，它是一个强大的操作系统，值得世界上许多每天对它的赞誉。对于那些正踏入 Linux 第一步的人来说，你们将拥有一段有趣的旅程。

## Linux 历史

Linux 的起源非常简陋，1991 年 10 月，一位名叫 Linus Torvalds 的大学生向 `comp.os.minux` 新闻组发布了以下消息：

> “我正在为 386(486) AT 兼容机写一个（免费）操作系统（只是兴趣爱好，不会像 gpu 那样大而专业）……”

这句话将载入史册，成为 IT 领域历史上最大的低估之一。在 Linux 发布此消息时，Linux 不仅仅是一个带有编译器、bash shell 和一些基础应用程序的内核。许多随着操作系统一起成长的 Linux 用户通常认为基于控制台的应用程序比它们的 GUI 版本更令人满意。

在 Linux 上，图形用户界面是 X Windows。X Windows 是一种类似于 Windows 或 Macintosh 等操作系统的用户界面系统。原始的 X Windows 支持小部件和窗口控制等基本功能。

然而，X Windows 的界面已变得过时，与许多主流操作系统感觉不同。Linux 在 X Windows 下一次演进是增强操作系统的功能，例如拖放、更美观的用户界面，以及非 Linux 应用程序，如文字处理器、会计软件和高质量数据库。

如今，Linux 是一个强大的操作系统，可以与许多顶级操作系统相竞争。尽管今天已有数千个 Linux 应用程序可用，但这仍然无法与 Microsoft Windows 等平台上的软件量相比。Linux 的伟大很大程度上源于其快速和稳定的声誉。Kylix 首次为 Linux 提供了一个强大的快速应用程序开发（RAD）工具，通过创建原生应用程序来生成客户端应用程序。因此，Kylix 可以用 Linux 的原生语言直接连接核心 API。

## Linux 桌面环境

一套支持桌面系统并替换许多 Linux 中使用的命令行实用程序的应用程序套件。这些增强功能来自 KDE 和 GNOME 等小组。KDE 桌面管理器（如图 1.2 所示）和 GNOME 管理器（如图 1.3 所示）是构建在 X Windows 之上的。

图 1.2 - KDE 桌面管理器

KDE 桌面管理器是由 Trolltech 的 Kylix 开发人员创建的 Qt 库。Qt 库非常重要，因为使用 Kylix 创建的 GUI 应用程序依赖 Linux 系统中安装 Qt 库才能运行。这是因为 KDE 系统实际上是使用 Qt 库开发的。

然而，最初开发 KDE 时使用的 Qt 库并不是开源的。开源（即向应用程序提供源代码）是许多 Linux 开发者的核心理念，因为 Linux 本身就是建立在开放哲学之上的。因此，Linux 社区认为 KDE 没有体现 Linux 精神的真谛，于是创建了一个用于 X Windows 的替代桌面管理器系统——GNOME。

GNOME 在大多数方面与 KDE 相似，它是 X Windows 的友好版本，并具有与 KDE 类似的功能，例如易于使用的界面、为用户提供的应用程序套件以及 Linux 命令行工具的图形化替代方案。

尽管 GNOME 需要使用 Qt 库来运行应用程序，但在 GNOME 系统上可以安装 Qt 库，且使用 Qt 为 KDE 创建的应用程序可以在 GNOME 下运行。Kylix 通过创建使用 Qt 库的应用程序，有效利用了这一点，使得创建的程序可以同时在 KDE 和 GNOME 上运行。
