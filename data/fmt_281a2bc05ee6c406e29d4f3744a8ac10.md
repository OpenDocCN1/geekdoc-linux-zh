
# XDrawArc / XDrawArcs

指定与 X 服务器的连接。

`d`

指定绘制对象（drawable）。

`gc`

指定图形上下文（GC）。

`arcs`

指定弧数组。

`narcs`

指定数组中弧的数量。

`delim` `%%` `XDrawArc` 绘制圆形或椭圆弧，而 `XDrawArcs` 绘制多个或椭圆弧。每个弧由一个矩形和两个角度指定。圆或椭圆的中心是矩形的中心，主轴和短轴由宽度和高度指定。正角度表示逆时针运动，负角度表示顺时针运动。如果 `angle2` 的幅度大于 360 度，`XDrawArc` 或 `XDrawArcs` 将其截断为 360 度。

对于指定为 `%-x,-y,-width,-height,-angle1,-angle2` 的弧，主轴和短轴的原点位于 `%x + ^{width over 2}, -y + ^{height over 2}`，描述圆或椭圆的无限路径与水平轴在 `%x, -y + ^{height over 2}` 相交，与垂直轴在 `%x + ^{width over 2}, -y % ^{height over 2}` 相交。这些坐标可以是小数而不截断为离散坐标。路径应由理想的数学路径定义。对于线宽为 `lw` 的宽线，填充的边界轮廓由两条无限路径组成，由所有到圆/椭圆路径的垂直距离等于 `lw/2`（这是一个小数）的点组成。端样式（cap-style）和连接样式（join-style）的应用与对应圆/椭圆端点切线的线相同。

对于指定为 `%-x,-y,-height,-angle1,-angle2` 的弧，角度必须在椭圆（或圆，角度和坐标系相同）的有效倾斜坐标系中指定。这些角度与屏幕正常坐标系（使用量角计测量）的角度之间的关系如下：

```
% roman "skewed-angle" ~ = atan left ( tan roman "normal-angle" )
* width over height right ) ^adjust%
```

`skewed-angle` 和 `normal-angle` 以弧度（而不是经过 64 缩放的角度）表示，范围在 `% [0, ~2 pi]` 内，且 `atan` 返回在 `% [- pi over 2, ~pi over 2]` 内的值并进行调整：

```
0% 对于 normal-angle 在范围 % [0 , ~pi over 2 ]% 内
%pi% 对于 normal-angle 在范围 % [pi over 2 , ~(3 pi over 2 ]% 内
%2 pi 对于 normal-angle 在范围 % [3 pi over 2 , ~2 pi ]% 内
```

对于任何给定的弧，`XDrawArc` 和 `XDrawArcs` 不会对同一个像素进行多次绘制。如果两个弧绘制正确且线宽大于零且两个弧相交，`XDrawArc` 和 `XDrawArcs` 不会重复绘制像素。否则，相交弧的交叉像素会被多次绘制。具有一个端点且顺时针范围的弧与指定另一个端点及等效逆时针范围的弧绘制相同的像素，但影响连接处除外。

如果第一个弧的终点与第二个弧的起点重合，两个弧将正确连接。如果第一个弧的起点与最后一个弧的终点重合，两个弧将正确连接。通过将一个角度指定为零，可以绘制水平线或垂直线。角度完全基于坐标系计算，忽略宽高比。

这两个函数都使用这些 GC 组件：`function`,`plane-mask`,`line-width`,`linestyle`,`cap-style`,`join-style`,`fill-style`,`subwindow`,`clip-x-origin`,`clip-y-origin` 和 `clip-mask`。它们还使用这些依赖 GC 模式的组件：`foreground`,`background`,`tile`,`stipple`,`stipple-x-origin`,`stipple-y-origin`,`dash-offset` 和 `dash-list`。

`XDrawArc` 和 `XDrawArcs` 会产生 `BadDrawable`、`BadGC` 和 `BadMatch` 错误。

## 填充区域

Xlib 提供了用于填充的函数：

- 单个矩形或多个矩形
- 单个多边形
- 单个弧或多个弧

### 填充单个和多个矩形

要在指定的绘制对象中填充单个矩形区域，使用 `XFillRectangle`。

```
XFillRectangle(display, d, gc, x, y, width, height);
```

`display` 指定与 X 服务器的连接。

`XFillPolygon(display, d, gc, points, npoints, shape, mode);`

```
# 图形函数

| display | 指定与 X 服务器的连接。 |
| :--- | :--- |
| d | 指定绘制对象。 |
| gc | 指定图形上下文（GC）。 |
| points | 指定点数组。 |
| npoints | 指定点的数量。 |
| shape | 指定形状。 |
| mode | 指定模式。 |
```

`XFillPolygon` 可以产生 `BadDrawable`、`BadGC`、`BadMatch` 和 `BadValue` 错误。

### 填充单个和多个弧

要在绘制对象中填充单个弧，使用 `XFillArc`。

```
XFillArc(display, d, gc, x, y, width, height, angle1, angle2);
```

`display` 指定与 X 服务器的连接。

`d` 指定绘制对象。

`gc` 指定图形上下文（GC）。

`x` 指定 x 和 y 坐标，这些坐标相对于绘制对象的原点，并指定边界矩形的左上角。

`width` 指定宽度和高度，它们是弧的主轴和短轴。

`angle1` 指定相对于中心三点钟位置的弧起始点；单位为*度 * 64*。

`angle2` 指定相对于弧起始点的弧的路径和范围，单位为*度 * 64*。

要在绘制对象中填充多个弧，使用 `XFillArcs`。

```
XFillArcs(display, d, gc, arcs, narcs);
```

`display` 指定与 X 服务器的连接。

`d` 指定绘制对象。

`gc` 指定图形上下文（GC）。

`arcs` 指定弧数组。

`narcs` 指定数组中弧的数量。

对于每个弧，`XFillArc` 或 `XFillArcs` 填充由描述弧的无限路径封闭的区域，取决于 GC 中指定的 `arc-mode` 使用一条或两条连接线段。对于 `ArcChord`，使用连接弧端点的单线段。对于 `ArcPie`，使用连接弧端点与中心点的线段。`XFillArcs` 在像素中填充多次。如果区域相交，交叉像素会被多次绘制。

这两个函数都使用这些 GC 组件：`plane-mask`,`fill-style`,`arc-mode`,`subwindow-mode`,`clip-x-origin`,`clip-y-origin` 和 `clip-mask`。它们还使用依赖 GC 模式的组件：`foreground`,`background`,`tile`,`tipple-x-origin` 和 `tipple-y-origin`。

`XFillArc` 和 `XFillArcs` 可以产生 `BadDrawable`、`BadGC` 和 `BadMatch` 错误。

## 字体度量

字体是一组字符的图形描述，用于在重复使用一组大小相似的小型模式时提高效率。

本节讨论了如何：

- 加载和释放字体

## 图形函数

- 获取和释放字体名称
- 计算字符字符串大小
- 查询字符字符串大小

当程序请求新字体时，X 就会就会加载字体。服务器可以缓存字体以供查找。字体在服务器的所有屏幕上是全局的。在处理字体时，可能存在多个层级。大多数应用程序使用 `XLoadQueryFont` 来加载字体并查询字体度量标准。

字体中的字符被视为掩码（masks）。对于图像文本请求，唯一修改的像素是字符中哪些位被设置为 1。这意味着使用点阵（stipples）或瓦（tiles）绘制文本是有意义的（例如，许多菜单会将不可用的条目置灰）。

`XFontStruct` 包含了字体的所有信息，它由字体特定信息以及一个指向 `XCharStruct` 结构数组的指针组成，该数组包含了字体中的字符。`XFontStruct`、`XFontProp` 和 `XCharStruct` 包含：
