
要在 `Makefile` 中设置变量，请在变量名后跟 `'='` 或 `'::='`。例如：

```
objects = main.o
```

定义了名为 `objects` 的变量。`'='` 后面的空格会被忽略。

使用 `'::='` 定义的变量是递归展开的（见 6.2 节 [变量的类型]，第 56 页），这些定义可以包含变量引用，并在读取 `Makefile` 时展开。

对变量值的长度没有限制。当变量定义很长时，可以在方便的地方插入反斜杠换行符将其分成几行。这会让 `Makefile` 更加易读。

## 第 6 章：如何使用变量

大多数变量名在未设置时被视为空字符串。某些变量具有非空初始值，但你可以通过通常的方式设置它们（见 10.3 节 [隐式规则变量]，第 106 页）。特殊变量会被自动设置。

如果你希望在变量未定义时对其进行设置，可以使用 `'?='`（见 8.7 节 [源]，第 85 页）：

```
variable := value
```

### 6.6 向变量追加文本

向变量的值中添加更多文本是很有用的。你可以使用 `'+='` 这样做：

```
variable += more
```

大致等同于：

```
temp = value
variable = $(temp) more
```

当然，这并没有定义名为 `temp` 的变量。当变量的旧值包含变量引用时，这种方法就变得重要了。如下所示示例：

```
CFLAGS = $(includes) -0
```

```
...
```

```
CFLAGS += -pg # enable profiling
```

第一行定义了引用另一个变量 `includes` 的变量 `CFLAGS`。（`CFLAGS` 用于 C 编译规则；见 10.2 节 [隐式规则目录]，第 102 页）。使用 `'+='` 定义 `CFLAGS` 是一个递归展开变量，这意味着 `'$(includes) -0'` 在 `make` 处理 `CFLAGS` 定义时不会展开。因此，即使尚未定义，值也能生效。它只需要在任何不使用 `'+'` 的 `CFLAGS` 引用之前定义即可。如果我们尝试向 `CFLAGS` 的值追加内容，可能会这样做：

```
CFLAGS := $(CFLAGS) -pg # enable profiling
```

这接近，但不是我们想要的。使用 `':='` 会将 `CFLAGS` 重定义为简单展开变量；这意味着 `make` 在设置变量之前展开文本 `'$(CFLAGS) -pg'`。如果 `includes` 尚未定义，后来的定义不会产生任何影响。相反，通过使用 `'+='` 我们将 `CFLAGS` 设置为未展开的值 `'$(includes) -pg'`。因此我们保留了对 `includes` 的引用，如果该变量在以后任何时候被定义，引用 `'$(CFLAGS)'` 仍然使用其值。

### 6.7 覆盖指令 (override Directive)

如果变量通过命令行参数进行了设置（见第 9.5 节 [覆盖变量]，第 93 页），则 `Makefile` 中的普通赋值将被忽略。如果你即使在变量已通过命令行参数设置的情况下，仍想在 `Makefile` 中设置该变量，可以使用 `override` 指令，该指令的格式如下：

```
override variable = value
```

或者

```
override variable := value
```

若要在命令行上定义的值后追加更多文本，请使用：

`override variable += more text`

参见第 6.6 节 [向变量追加更多文本]，第 63 页。

引入 `override` 指令并不是为了在 `Makefile` 和命令行参数的战争中进行升级。它的发明是为了让你能够修改和增加用户通过命令行参数指定的值。

例如，假设你希望运行 C 编译器时总是想使用 `'-g'` 开关，但又允许用户像往常一样通过命令行参数指定其他开关。你可以使用这个 `override` 指令：

```
override CFLAGS += -g
```

你还可以将 `override` 指令与 `define` 指令结合使用。其用法正如你预期的那样：

```
override define foo
bar
def
```

关于 `define` 的信息请见下一节。

### 6.8 字面定义变量 (Defining Variables Verbatim)

另一种设置变量值的方法是使用 `define` 指令。该指令具有一种特殊的语法，允许在值中包含换行符，这对于定义一系列命令来说非常方便（见第 5.7 节 [定义预定义命令序列]，第 52 页）。

`define` 指令同一行后面是变量名，且没有其他内容。赋予变量的值出现在随后的几行中。值的结束由包含 `endif` 单词的行标记。除了这种语法上的差异，`define` 的工作方式与 `'='` 相同：它创建一个递归展开的变量（见第 6.2 节 [变量的两种类型]，第 56 页）。变量名可以包含函数和变量引用，这些引用在读取指令时会被展开，以找到实际要使用的名称。

```
define two-lines
echo foo
echo $(bar)
def
```

普通赋值中的值不能包含换行符；分隔 `define` 中行的换行符将成为变量值的一部分（位于 `endif` 之前的最后一个换行符不被视为值的一部分）。

上一个示例在功能上等同于：

```
two-lines = echo foo; echo $(bar)
```

因为用分号分隔的两个命令的行为类似于两个独立的 shell 命令。然而，请注意，使用两个独立的行 `make` 会调用两次 shell，为每行运行一个独立的子 shell。参见第 5.2 节 [命令执行]，第 41 页。

如果你想让通过 `define` 定义的变量优先高于命令行变量定义，可以使用 `override` 指令配合 `define` 使用：

```
override define two-lines
foo
$(bar)
def
```

参见第 6.7 节 [覆盖指令]，第 65 页。

### 6.9 环境中的变量

`make` 中的变量可以来自运行 `make` 的环境。`make` 在启动时看到的每一个环境变量都会转换为具有相同名称和值的 `make` 变量。但 `Makefile` 中的显式赋值或命令行参数赋值会覆盖环境。（如果指定了 `'-e'` 标志，则环境中的值将覆盖 `Makefile` 中的赋值。参见第 9.7 节 [选项摘要]，第 95 页。但并不是推荐的做法。）

通过在环境中设置变量 `CFLAGS`，你可以让大多数 `Makefile` 中的所有 C 编译都使用你偏好的编译器开关。对于具有标准或习惯含义的变量，这是安全的，因为你知道 `Makefile` 会将它们用于其他用途（但这并非完全可靠；某些 `Makefile` 会显式设置 `CFLAGS`，因此不会使用该值）。

`make` 递归调用时，在环境中定义的变量会传递给内部调用（见 5.6 节 [变量的使用]）。默认情况下，在环境中定义的变量赋值会传递给内部调用。
