
```
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root 29104 Dec 19 12:35 /usr/bin/passwd
$ sudo
# mv /usr/bin/passwd /usr/bin/rootpasswd
# chmod 700 /usr/bin/rootpasswd
# ln -s /usr/bin/yppasswd /usr/bin/passwd
# exit
logout
$ ls -l /usr/bin/[yppasswd,passwd,rootpasswd]
-lrwxrwxrwx 1 root 17 May 8 18:42 /usr/bin/yppasswd -> /usr/bin/rootpasswd
-rw-r--r-- 1 root 29104 Dec 19 12:35 /usr/bin/passwd
-rwxr-xr-x 1 root 20668 Mar 7 12:45 /usr/bin/passwd
```

上述示例使用 `sudo -i` 打开一个具有 root 权限的 shell，这样管理员就不需要连续输入多次 `sudo`。管理员会尽快返回普通 shell。

在这种设置下，非 root 用户更改密码将运行 `yppasswd`，这是合适的。如果 root 或系统账户使用 `passwd`（实际上是 `yppasswd`），`yppasswd` 将显示一个错误，提醒管理员运行 `rootpasswd`。

# 修改用户信息

只要 `yppasswd` 守护进程运行在 NIS 主服务器上，用户就可以从 NIS 客户端使用 `yppasswd` 工具更改自己的密码，而以 root 权限运行的用户可以更改任何用户的密码（root 或系统账户除外）。如果 `yppasswd` 守护进程设置为允许这些更改，用户还可以使用 `yppasswd` 更改其登录 shell 和 GECOS（第 1038 页）信息。请参考第 797 页的“`yppasswdd`: NIS 密码更新守护进程”，获取如何配置 `yppasswd` 以允许用户更改这些值的信息。使用 `yppasswd` 的 `-p` 更改密码，`-f` 更改 GECOS 信息，以及 `-l` 更改登录 shell：

```
$ yppasswd -l
Changing NIS account information for plum.
```

要接受默认值，只需按回车键。要使用系统默认 shell，输入单词“none”

Login shell [/bin/bash]: /bin/sh

plum 的登录 shell 已更改。

```
$ ypmatch sam password
sam:x:1000:1000:Sam,...:/home/:bin/sh
```

如果 `yppasswd` 不起作用且服务器系统运行着防火墙，请参考第 791 页的“防火墙”。

# 添加和删除用户

有多种方法从 NIS 密码映射中添加和删除用户。简单的方法是保持 `/etc/passwd` 文件与 NIS 映射同步。你可以通过使用标准工具 `adduser` 和 `deluser` 或其图形界面对应应对文件进行更改，然后运行 `ypinit`（第 795 页）更新映射。

# 设置 NIS 服务器

本节解释了如何设置 NIS 服务器。

## 先决条件

确定 NIS 域名（第 786 页）并安装以下包：

- `nis`

init 脚本：安装 `nis` 包时，`dpkg postinst` 脚本启动 NIS 客户端。参考第 785 页的“安装”获取如何启动服务器、客户端或其他的信息。`/etc/default/nis` 文件控制 NIS 服务器作为主服务器还是从机启动（第 786 页）。你可能还需要为 NIS 服务器和 `yppasswdd` 指定运行的端口。在配置服务器后，可以使用 `nis` init 脚本启动、重启或重新加载它：

```
$ sudo /etc/init.d/nis restart
```

### 注意事项

- NIS 客户端可以在与 NIS 服务器相同的系统上运行。
- 每个域必须只有一个主服务器。
- 你可以在单个系统上运行多个 NIS 域服务器（针对不同的域）。
- NIS 服务器提供 `/var/yp` 中列出的域。禁用 NIS 服务器时，从 `/var/yp` 管理映射。
- NIS 服务器 (`ypserv`) 和 NIS 密码守护进程 (`yppasswdd`) 使用 `portmap`（第 530 页）来选择它们接受查询的端口。当 `ypserv` 请求端口时，`portmap` 分配 1024 以下的随机端口。`yppasswdd` 使用随机端口使得在 NIS 服务器上设置防火墙变得困难。你可以通过编辑 `/etc/default/nis` 中的 `ypserv` 和 `yppasswdd` 选项行指定端口（选择任何小于 1024 的端口）：

#### 防火墙

```
YPSERVARGS='--port 114'
YPASSWDARGS='--port 112'
```

如果 NIS 系统运行着防火墙，使用 `fire-starter`（第 886 页），通过设置两个策略来允许这些端口提供服务。如果你遵循上述示例，将允许端口 114 和 112 上提供服务。

## 逐步设置

本节列出了设置和启动 NIS 服务器涉及的步骤。

### /etc/default/nis: 允许 NIS 服务器启动

按照第 786 页的描述编辑 `/etc/default/nis` 文件，以便 `nis` init 脚本启动 NIS 服务器。你也可以为 NIS 服务器和 `yppasswdd` 指定监听此端口的端口；参考第 791 页的“防火墙”。

### 指定系统的 NIS 域名

如第 786 页所示指定系统的 NIS 域名。此步在安装 `nis` 包时会处理。

### /etc/ypserv.conf: 配置 NIS 服务器

`/etc/ypserv.conf` 文件包含 NIS 服务器配置信息，指定选项和访问规则。选项规则指定服务器选项并具有以下格式：

```
option: value
```

#### 选项

以下是选项及其默认值：

- `files`：指定 pserver 缓存的最大映射文件数量。设置为 0 关闭缓存。默认值为 30。
- `trusted_master`：在服务器上接受新映射的主服务器的名称/IP 地址。默认没有主服务器，意味着不接受映射。
- `xfer_check_port`：YES（默认）要求主服务器运行在特权端口（第 1054 页）。NO 允许其运行在任何端口。

#### 访问规则

访问规则指定哪些主机和域可以访问哪些映射，具有以下格式：

```
host:domain:map:security
```

其中 `host` 和 `domain` 指定 NIS 规则应用的 IP 地址和域；`map` 是规则应用的映射名称；`security` 是 `none`（始终允许访问）、`port`（允许从特权端口访问）或 `deny`（拒绝访问）。以下行出现在 Ubuntu Linux 提供的 `ypserv.conf` 文件中：

```
$ cat /etc/ypserv.conf
```

- `passwd` 工具设置的权限对于所有用户具有读取和执行权限，对于 root 具有读取和执行权限。如果在更改其名称和权限后你想恢复其原始名称和权限，首先更改其名称，然后执行命令 `chmod 4755 /usr/bin/passwd`。（你必须以 root 权限进行这些更改。）

- 这是默认值——限制对 shadow 文件的访问，`*` 允许访问所有其他。

```
* : * : shadow.byname : port
* : * : passwd.adjunct.byname : port
* : * : none
```

这些行将 `shadow.byname` 和 `passwd.adjunct`（带有 shadow `[*]` 条目的 passwd 映射）限制到小于 1024 的端口。然而，网络上的 DOS 或早期 Windows 系统可以读取映射，因为它们可以访问小于 1024 的端口。最后一行允许从任何主机的端口访问其他映射。

示例描述了一个局域网，其中包含你想要允许访问的地址和一些你不允许的地址；可能是无线服务器或某些你不想暴露给 NIS 的公共网络连接。你可以在 `ypserv.conf` 中列出你想要授权的系统或 IP 子网。

在其他 IP 地址上登录的任何人将被拒绝 NIS 服务。以下来自 `ypserv.conf` 的行允许从 192.168.0.1 到 192.168.0.255 范围内的 IP 地址登录的任何人（指定为 192.168.0.1 配合子网掩码 [第 529 页] 的 /24）：

### /var/yp/securenets: 增强安全性

为了增强系统安全性，你可以创建 `/var/yp/securenets` 文件，该文件可以防止未经授权的系统向 NIS 服务器发送 RPC 请求并检索 NIS 映射。值得注意的是，`securenets` 防止未经授权的用户检索包含加密密码的影子映射。当 `securenets` 文件不存在或内容为空时，NIS 服务器将接受来自任何系统的请求。

`securenets` 的每行列出了一个网络掩码和 IP 地址。NIS 接受来自在 `securenets` 中指定的 IP 地址的系统请求；它会忽略并记录来自其他地址的请求。你必须将（本地）服务器系统作为 `localhost (127.0.0.1)` 包含在 `securenets` 中。一个简单的 `securenets` 文件如下：

```
$ cat /var/yp/securenets
# you must accept requests from localhost
255.255.255.255      127.0.0.1
#
# accept requests from IP addresses 192.168.0.1 - 192.168.0.62
255.255.255.192      192.168.0.62
#
# accept requests from IP addresses starting with 192.168.14
255.255.255.0      192.168.14.0
```

### /var/yp/Makefile: 指定映射

该工具由 `/var/yp/Makefile` 控制，使用 `makedbm` 创建包含由 NIS 分布信息的 NIS 映射。当你在主服务器上运行 `ypinit`（第 795 页）时，`ypinit` 会调用 `make`：你不需要手动运行 `ypinit`。

编辑 `/var/yp/Makefile` 以设置选项并指定要创建哪些映射。以下章节将详细讨论 `/var/yp/Makefile`。

#### 变量

以下你可以在 `/var/yp/Makefile` 中设置的变量列表。Ubuntu 的值是在 Ubuntu 分发的文件中设置的。

- `B`：不要更改。
  - Ubuntu: 未设置
- `NOPUSH`：`ypserv` 不将映射复制（推送）到从服务器。如果你没有任何从 NIS 服务器，则将其设置为 TRUE；设置为 FALSE 则导致 NIS 将映射复制到从服务器。
  - Ubuntu: 未设置
- `YPPUSHARGS`：`yppush` 的参数。更多信息请参见 `yppush` 手册页。
  - Ubuntu: 未设置
- `MINUID`、`MINGID`：分别指定要包含在 NIS 映射中的最低 UID 和 GID 数字。在 `/etc/passwd` 和 `/etc/group` 文件中，较低的 ID 数字属于 root 和系统账户及组。为了增强安全性，NIS 不分发这些用户和组的密码和组信息。将 `MINUID` 设置为你想要包含在 NIS 映射中的最低 UID 数字，并将 `MINGID` 设置为你想要包含的最低 GID 数字。
  - Ubuntu: 1000/1000
- `NFSNOBODYUID`、`NFSNOBODYGID`：分别指定名为 `nfsnobody` 的用户的 UID 和 GID。NIS 不导出此用户的值。设置为 0 以为 `nfsnobody` 导出映射。
  - Ubuntu: 65534/65534
- `MERGE_PASSWD`、`MERGE_GROUP`：设置为 TRUE 时，分别在 passwd 映射中合并 `/etc/shadow` 和 `/etc/passwd` 文件，以及在 group 映射中合并 `/etc/gshadow` 和 `/etc/group` 文件，启用影子用户密码和组密码。
  - Ubuntu: FALSE/FALSE

#### 文件位置

`/var/yp/Makefile` 的后续章节指定了标准文件位置；通常你不需要更改这些条目。makefile 的这部分分为以下几组：

- 命令：`Awk` (`awk`) 和 `make`，以及为 `umask` 设置一个值（第 526 页）
- 源目录：定位包含 NIS 源文件的目录
- NIS 源文件：定位用于构建 NIS 数据库的 NIS 源文件
- 服务器：定位列出 NIS 服务器的文件

#### 目标

`/var/yp/Makefile` 中的 `ALL` 目标指定了为之构建的映射：

```
ALL = passwd hosts services netid protocols netgrp
#ALL += pubkey mail others bootstraps printcap
#ALL += amd.home.master.auto.home.local
#ALL += timezone locale networks
```

`ALL` 目标的第一行列出了默认进行构建的映射。该行以单词 `ALL` 开头，后面跟着等号和一个制表符。最后三行被注释掉了。取消注释并删除或移动映射，直到列表与你的匹配。

随着需求的改变，你可以编辑 Makefile 中的 `ALL` 目标并在 `/var/yp` 目录下运行 `make` 来修改 NIS 分发的映射列表。

### 启动服务器

在完成前面的步骤后，重启主服务器（第 785 页），然后重启从服务器。在主服务器上，`nis init` 脚本启动 `ypserv`、`yppasswdd` 和 `ypxfrd` 守护进程。如果你在本地系统上运行 NIS 客户端，它还会启动 `ypbind`。在从服务器上，`nis init` 脚本仅启动 `ypserv` 守护进程，可选地启动 `ypbind` 守护进程。

在运行 `ypinit`（将在下一节讨论）之前启动主服务器（你必须这样做以避免错误），将花费很长的时间，这将在第 785 页的“No server”中解释。运行 `ypinit` 后，你必须重启服务器（第 785 页）。

## ypinit: 创建 NIS 映射

`ypinit` 创建 NIS 映射。在主服务器上运行 `ypinit -m`，在从服务器上运行 `ypinit -s master_name`。

## ypserv: NIS 服务器守护进程

`ypserv` 是 NIS 服务器守护进程。它在主服务器和从服务器上运行。

### 调试 ypserv

`--debug` 选项让 `ypserv` 在前台运行，并将其错误消息和调试输出发送到标准错误。当 `ypserv` 在前台运行时，按 Control-C 停止 `ypserv`。

## yppasswdd: NIS 密码更新守护进程

NIS 密码更新进程 `yppasswdd` 仅在主服务器上运行；没有必要在从服务器上运行它。（如果主服务器宕机且你尝试从客户端更改密码，`yppasswdd` 显示错误消息。）当用户在客户端上运行 `yppasswd`（第 788 页）时，此工具与 `yppasswdd` 交换信息，以更新 NIS shadow（以及可选的 password）映射以及 NIS 主服务器上 `/etc/shadow` 文件中的用户密码（以及可选的其他）信息。密码更改请求将发送到系统日志（第 668 页）。

如果系统正在运行防火墙，请为 `yppasswdd` 打开端口。请参阅第 791 页的“防火墙”。

### 启动 yppasswdd

该 init 脚本在 NIS 服务器上启动 `yppasswdd`（守护进程名为 `rpc.yppasswdd`）。更多信息请参阅第 790 页的“前提条件”。

### 允许修改 GECOS 和登录 shell

`/etc/default/nis` 文件控制 `yppasswdd` 是否允许用户在运行时更改 GECOS（第 1038 页）信息和/或登录 shell。出厂时，允许用户更改其登录 shell，但不允许更改 GECOS 信息。你可以在启动 `yppasswdd` 时通过命令行更改这些设置，或者更方便地通过修改 `/etc/default/nis` 配置文件。`-chfn` 选项允许 `yppasswdd` 用户更改其 GECOS 信息；`-chsh` 允许用户更改其登录 shell。当你在 `/etc/default/nis` 中设置选项时，这些值会在每次运行 `yppasswdd` 时自动设置。关于 `YCHANGEGECOS` 的解释请参阅注释。

```
$ cat /etc/default/nis
# 我们允许用户使用 ypchsh 和/或 ypchfn。YCHANGEGECOS
# 字段将通过 -e 传递给 yppasswdd，请查看其 man 手册页。
# 可能的值："chsh", "chfn", "chsh,chfn"
YCHANGEGECOS=chsh
```

# 章节总结

NIS（网络信息服务）通过将常用管理文件维护在中央数据库中，并让客户端联系数据库以检索信息，简化了这些文件的管理。NIS 所服务的网络称为 NIS 域。每个 NIS 域都有一个主服务器；较大的网络可能会有从服务器。
