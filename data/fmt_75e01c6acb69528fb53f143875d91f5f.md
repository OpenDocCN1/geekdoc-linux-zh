
从配置文件 `filename` 读取日志配置。`defaults` 是一个用于配置文件的默认配置参数字典。使用 `ConfigParser` 模块读取指定的文件名。`disable_existing_loggers` 是一个布尔标志，指定在读取新的配置数据时是否禁用已有的日志器。默认情况下，此值为 `True`。

`logging` 模块的在线文档详细说明了配置文件的预期格式。然而，经验丰富的程序员可能从以下示例中推断出来，该示例是上一节所示 `appconfig.py` 的配置版本。

```ini
; appconfig.ini
;
; 用于设置日志的配置文件
;
; 以下节为 Logger、Handler 和 Formatter 对象提供名称
; 这些对象将在文件的稍后部分进行配置。

[loggers]
keys=root,app,app_net

[handlers]
keys=crit,applog

[formatters]
keys=format

[logger_root]
level=NOTSET
handers=

[logger_app]
level=INFO
propagate=0
qualname=app
handers=crit,applog

[logger_app_net]
level=ERROR
propagate=1
qualname=app.net
handers=

[handler_crit]
class=StreamHandler
level=CRITICAL
formatter=format
args=(sys.stderr,)

[handler_applog]
class=FileHandler
level=NOTSET
formatter=format
args=('app.log',)

[formatter_format]
format=%(levelname)s -10s %(asctime)s %(message)s
datefmt=
```

要读取此配置文件并设置日志，您可以使用以下代码：

```python
import logging.config

logging.config.configFile('applogconfig.ini')
```

与之前一样，想要发布日志消息的模块不需要担心加载日志配置的细节。它们只需要导入 `logging` 模块并获取适当 Logger 对象的引用。例如：

```python
import logging
app_log = logging.getLogger("app")
...
app_log.critical("An error occurred")
```

# 性能考虑

如果不加小心，在应用程序中添加日志可能会严重降低其性能。然而，可以使用一些技术来减少开销。

首先，Python 的优化模式 `-O` 会移除所有使用 `__debug__` 语句进行条件执行的代码。如果日志的唯一目的是调试，您可以有条件地执行所有日志调用，并在优化模式下忽略这些调用。

第二种技术是在完全禁用日志时使用 Null 对象来代替 Logger。这与使用 `None` 不同。相反，您想使用一个对象的实例，该实例会静默地忽略所有执行在其上的操作。

```python
class Null(object):
    def __init__(self, *args, **kwargs): pass
    def __call__(self, *args, **kwargs): return self
    def __getattribute__(self, name): return self
    def __setattr__(self, name, value): pass
    def __delattr__(self, name): pass
```

```python
log = Null()
log.critical("An error occurred.") # 什么都不做
```

根据您的经验，也可以通过装饰器和类来管理日志。由于 Python 的这些功能在函数级别运行，因此可以选择性地添加或移除程序部分的日志功能，且在禁用日志时不会不会影响性能。更多细节请参考第 6 章“函数与函数式编程”和第 7 章“类与面向对象编程”。

### 注意事项

+   - `logging` 模块提供了许多此处未讨论的自定义选项。读者应查阅在线文档以获取更多细节。
+   - 在使用线程的程序中使用 `logging` 模块是安全的。特别是，没有必要在发布日志消息的代码周围添加日志操作。

`mmap` 模块提供了内存映射文件对象的支持。该对象既像文件又像字节字符串，可以用于大多数期望二进制文件或字节字符串的地方。此外，内存映射文件的内容是可变的。这意味着可以使用索引赋值和切片赋值操作符进行修改。除非对文件创建了私有映射，否则此类更改将直接修改底层文件的内容。

内存映射文件通过 `mmap()` 函数创建，这与 UNIX 和 Windows 略有不同。

```
mmap(fileno, length, {flags, [prot [, access {, offset}]]})
```

UNIX 返回一个 `mmap` 对象，它从具有整数文件描述符 `fileno` 的文件中映射 `length` 字节。如果 `fileno` 为 -1，则映射一段匿名内存。`flags` 指定映射的性质，是以下标志之一：

#### 标志含义

| Flag | 含义 |
| :--- | :--- |
| `MAP_PRIVATE` | 创建写时拷贝映射。对对象的更改对此进程是私有的。 |
| `MAP_SHARED` | 与所有映射文件相同区域的其他进程共享映射。对对象的更改将影响所有映射。 |

默认标志设置为是 `MAP_SHARED`。`prot` 指定对象的内存保护，是以下内容的按位或或结果：

#### 设置含义

| Setting | 含义 |
| :--- | :--- |
| `PROT_READ` | 可以从对象读取数据。 |
| `PROT_WRITE` | 可以对对象进行修改。 |
| `PROT_EXEC` | 对象可以包含可执行的指令。 |

`prot` 的默认值为 `PROT_READ | PROT_WRITE`。`prot` 中指定的模式必须与打开底层文件描述符 `fileno` 时使用的权限匹配。在大多数情况下，文件应该以读/写模式打开（例如 `os.open(name, os_RDWR)`）。可选的 `access` 参数可以作为 `flags` 和 `prot` 的替代方案。如果给出，它具有以下值之一：

#### 访问含义

| Access | 含义 |
| :--- | :--- |
| `ACCESS_READ` | 只读访问。 |
| `ACCESS_WRITE` | 带直写写的读/写访问。修改会影响底层文件。 |
| `ACCESS_COPY` | 带写时拷贝的读/写访问。修改影响内存但不更改底层文件。 |

当使用 `access` 时，通常作为关键字参数给出——例如，`mmap(fileno, length, access=ACCESS_READ)`。同时提供 `access` 和 `flags` 的值是错误的。`offset` 指定从文件开始的字节数，默认为 0。它必须是 `mmap.ALLOCATIONGRULARITY` 的倍数。

```
mmap(fileno, length, {tagname, [access {, offset}}])
```

Windows 返回一个 `mmap` 对象，通过整数文件描述符 `fileno` 从文件映射 `length`。`fileno` 为 -1 表示匿名内存。如果 `length` 大于文件的当前大小，文件将扩展到 `length`。`tagname` 是一个可选字符串，如果 `tagname` 指向已有的映射，则打开映射；否则，创建一个新映射。如果 `tagname` 为 `None`，则创建一个未命映射。`access` 是一个指定访问模式的可选参数，取 `ACCESS_WRITE`。`offset` 是从文件开始的字节数，默认为 0。它必须是 `mmap.ALLOCULARITY` 的倍数。

内存映射对象 `m` 支持以下方法：

```
m.close()
```

关闭文件。后续操作会导致异常。

```
m.find(string[, start])
```

返回 `string` 首次出现的位置索引。`start` 指定可选的起始位置。如果未找到，则返回 -1。

```
m.flush(offset, size)
```

将内存中的修改刷回文件系统。`offset` 和 `size` 指定要刷新的字节范围。刷新整个项。

```
m.read(dst, src, count)
```

从索引 `src` 开始拷贝字节到目标索引 `dst`。此拷贝使用 C 语言的 `memmove()` 函数执行，保证在源目标区域重叠时也能正常工作。

```
m.read()
```

从当前文件位置读取最多 `n` 个字节并以字符串形式返回数据。

```
m.read_byte()
```

从当前文件位置读取单个字节并以长度为 1 的字符串返回。
