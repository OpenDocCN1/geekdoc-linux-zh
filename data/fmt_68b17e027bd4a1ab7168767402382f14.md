在整个章节中，示例假设你是一家咨询公司的首席网络架构师，并被要求为名为 AMINEWS 的虚拟美国公司开发高端 Web 托管服务。

## Web 网络需求

AMINEWS 想要构建一种满足以下要求的 Web 托管服务：

- 对于每个客户端站点，必须由一个或多个 Web 服务器提供负载均衡的 Web 服务。如果某个 Web 服务器因为崩溃、应用程序错误或例行维护而无法使用，则剩余的 Web 服务器必须继续提供服务。只要至少有一台 Web 服务器可以提供所有网站的服务，Web 服务就不应中断。
- 每个客户端站点必须有一个唯一的域名。该网站必须符合以下 URL 格式：`http://www.client-domain.tld/`
- 允许每个客户端通过 FTP 更新其 Web 站点。每个客户端都应该在 DNS 配置中获得一个 `ftp.client-domain.tld` 主机。客户端使用它来更新其网站的内容。
- 由于 AMINEWS 通过中央 `cgi-bin` 目录提供集中的 CGI 脚本，必须允许客户端使用此功能。然而，由于许多 AMINEWS CGI 应用程序会写入数据，必须存在一种在 Web 服务器之间同步数据的方法。换言之，如果 CGI 程序写入了一个数据文件，所有 Web 服务器都必须能够访问该文件，以便 CGI 程序共享这些数据。
- 允许客户端拥有虚拟 SMTP 邮件服务。每个客户端还必须有一个或多个 POP3/IMAP 邮件账户，以便直接从 POP3/IMAP 服务器访问邮件。

## 设计 Web 网络

设计上述网络的第一步是绘制一些图表。第一个网络图非常简单，如图 20-1 所示。该图展示了两种配置：Web 服务器集群和相关的服务集群。Web 服务器集群由许多 Web 服务器系统组成，而相关的网络服务集群由 DNS、SMTP、POP3、IMAP 和 FTP 服务器组成。这两个服务器集群通过一个以太网集线器互连，该集线器连接到负责承载进出网络的 Internet 流量的路由器。一旦你有了这样一个简单的设计，就可以开始考虑在 Web 服务器集群的服务器之间进行 Web 流量负载均衡的方法。

## 考虑轮询 DNS 解决方案

假设 AMINEWS 的服务器集群中只有两个 Web 服务器——www1.aminews.com (192.168.1.10) 和 www2.aminews.com (192.168.1.20)。你想使用轮询 DNS 配置在这两台服务器上为 www.aminews.com 负载均衡。在 `aminews.com` 区域文件中，你可以添加以下行：

```
www1 IN A 192.168.1.10
www2 IN A 192.168.1.20
www IN CNAME www1
www IN CNAME www2
```
