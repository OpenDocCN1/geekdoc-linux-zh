## 文本编辑器

### `emacs` 文本编辑器
`emacs` 是一种高级且复杂的文本编辑器。对于大师中的大宗来说：“`emacs` 不是你的编辑器，它是一种生活方式。”取决于你的观点，`Emacs` 看起来确实功能很强大或很臃肿。你的系统中安装了 3 个版本的 `emacs`：
1. 纯文本模式：在 `x` 窗口中输入 `emacs`（我避免这种坑）。
2. 图形模式：在 `X` 窗口中输入 `emacs`（如果你花点时间学习，对新手来说相当好用）。
3. `X-windows` 模式：在 `X-windows` 终端中使用 `emacs`。

### `vi` 编辑器
著名的（臭名昭彰的）`vi` 编辑器（绝对不建议新手使用）。退出 `vi`（不保存更改）使用这五个字符：`ESC]` <Enter>。使用 `kate`（在 `x` 下）或 `pico`（命令行）或命令行文本编辑器（永远不要编辑 `vi`，除非我必须挂载 `/usr` 子系统并修改/编辑配置文件，那时 `vi` 是唯一可用的编辑器）。公平地说，`Linux` 发行版使用 `vi` (=改进版的 `vi`) 来代替 `vi`，这比原始的 `vi` 要好一点。还有 `Gvi` 版本的 `vi`（在 `X` 终端中输入 `gvim`）。

这里我看到的一个针对 `vi` 界面不“直观”的批评的回应：“唯一直观的界面是乳头。其他的必须学习。”（呵，`MS Windows` 的所谓“直观”界面也就这样。）

专家们确实喜欢 `vi`，除非你经常使用它，否则 `vi` 很难用。这是一个关于 `vi` 的非新手观点（http://linxtoday.com/stories/16620.html）：
> “我第一次在 1988 年接触到 `vi`，我很讨厌它。我当时还是大学大一学生……`VI` 看起来古老、复杂且不留情面……现在12 年过去了，我爱上了 `vi`，它几乎是我使用的唯一编辑器。为什么会改变？实际上我学会了如何使用 `vi`……现在我看到了它的本质，一个强大、功能丰富且灵活的编辑器……”

为了消遣，你可能想尝试看起来更古古的行编辑器 `ed`（只需在命令行输入即可）。尽管在交互式使用中可能“不方便”，但对于从另一个程序自动处理文件非常有用。

### `vi` 现代版本简介
`vi` (=视觉编辑器改进版) 的简要介绍是 `vi` 的现代版本。像我这样的新手之所以需要 `vi`，主要原因是为了救援——它是唯一可用的编辑器。最重要的是理解 `vi` 是一个“模态”编辑器，即它有几种你必须切换的运行模式。快速参考见下方，4 个核心命令已加粗。

**切换模式的按键：**
- `<ESC>` 命令模式（从任何编辑模式回到命令模式）
- `"insert"` 插入模式（在光标当前位置之前插入）不要在命令模式下打印任何键。命令模式中还有更多命令和模式！

**复制和粘贴（在命令模式下）：**
- 选中文本。然后，移动光标以选中文本
- `y` 复制选中文本
- `x` 剪切文本
- `paste` 粘贴已剪切/复制的文本

**保存并退出（从命令模式下）：**
- `w`: 写入 (=保存)
- `w filename`: 将内容写入文件 "filename"
- `:wq`: 保存并退出
- `q`: 退出（如果有未保存的更改则不会退出）
- `q!`: 退出并丢弃更改（如果有未保存的更改将不会提示）

## 正则表达式基础

有用的字符是由 `POSIX` 标准定义的：`[[:upper:]]`=大写字母，`[[:lower:]]`=小写字母，`[[:alpha:]]`=字母（包括大小写），`[[:digit:]]`=数字，`[[:space:]]`=空白字符，即 `<Space><<Tab>][<Newline>` 以及 `[[:graph:]]`=除空格外的可打印字符，`[[:print:]]`=可打印字符（图形字符减数字），`[[:cnt:]]`=控制字符，即不可打印字符，`[[:xdigit:]]`=十六进制数字。

此示例显示了命令的输出，并打印包含大写字母后跟以下内容的行：

```bash
tr -l grep '[:upper:]][[:digit:]'
```

`tr` (=) 一个过滤器，用于替换文本文件中所有的特定字符或“压缩”空白字符。

示例：

```bash
cat myfile | tr 1 2 > new_file
```

该命令获取文件 `myfile` 的内容，通过管道传递给翻译工具 `tr`，`tr` 将所有的字符 "1" 替换为 "2"，输出重定向到新文件。

## `sed` 流式编辑器

`sed` (=stream) 流式编辑器，用于过滤文本文件。匹配模式通常包含在一对斜杠 (//) 之间，我可以使用：

```bash
cat filename | sed -n '/1024/p'
```

在这里 `sed` 过滤了来自 `cat` 命令的输出。选项 "-n" 告诉 `sed` 阻塞所有输入行，除非显式匹配我的表达式。匹配项的 `sed` 动作是 "p"=打印。

另一个删除所选行的示例：

```bash
cat filename | sed '/^0$/d' > new_file
```

在这个示例中，以 "o" 结尾的行将被删除。这是一个用于匹配任何字符串后跟 "o" 直到行尾的正则表达式。输出（即所有以 "o" 结尾的行）重定向到 `new_file`。

另一个搜索并替换的示例，我将 `sed 's'` 动作放在表达式前面：

```bash
cat filename | sed 's/string_old/string_new/' > new_file
```

上一个命令的简短形式：

```bash
sed 's/string_old/string_new/' filename > new_file
```

要向名为 "master_file.html" 的 `html` 文件插入一个文本块，我可以使用包含以下内容的脚本：

```bash
sed '/text_which_is_a_placeholder_in_my_html_file/r text_file_to_insert.txt' index_master_file.html > index_master_file.html
```

## `awk` 文本处理工具

`awk` (GNU awk) 是一个强大的工具。处理文本文件时，它遵循与 `sed` 相似的[逻辑]，但功能更强大。`Perl` 可以做到 `awk` 的所有功能以及更多，所以我不经常使用 `awk`。对于简单任务，使用 `sed`；对于更复杂的任务，我使用 `perl`。但在某些情况下，`awk` 脚本可以更短、更容易维护且速度更快。

`awk` 特别适用于处理文本表格。一个表格由记录组成（每行通常是一个记录）。记录包含由分隔符分隔的字段。经常使用的分隔符是空格（`gawk` 默认）、逗号或冒号。所有 `gawk` 表达式的形式为：`gawk 'pattern {action}' myfile`。你可以省略模式或动作：默认模式是“所有内容”，默认动作是“打印行”；`gawk` 也可以用作过滤器（处理另一个命令的输出，正如我们在示例中使用的那样）。

示例。要打印包含字符串 "1024" 的行，我可以使用：

```bash
cat filename | gawk '/1024/ {print}'
```

像 `sed` 一样，匹配模式被包含在一对 "/" 之间。让 `gawk` 比 `sed` 更强大的之处在于对字段的使用。`$1` 意味着“第一个字段”，`$2` 意味着“第二个字段”，`$0` 意味着“整行”。下一个示例提取了包含 "1024" 的第 3 和第 2 个字段，并带有标签 "Name" 和 "ID"。输出到：

```bash
cat filename | gawk '/1024/ {print "Name: "$3 " ID: "$2}' > new_file
```

第三个示例找到了包含 "port" 的模式并打印第三个字段等于 "port"：

```bash
cat filename | gawk '$3 == "port" | /marie/'
```

要理解最后一个命令，这里是 `gawk` 中的逻辑测试：`==` 等于，`!=` 不等于，`<` 小于，`>` 大于，`<=` 小于等于，`>=` 大于等于，`~` 匹配正则表达式，`!` 不匹配正则表达式，`||` 逻辑或，`&&` 逻辑与。

## 文件类型检查

```bash
file -z filename
```

确定文件的类型。`-z` 让 `file` 查看压缩文件的内部以确定它是什么（而不是只是告诉你是一个压缩文件）。确定文件的内容，查看文件内部查找特定模式（“magic numbers”）——像 `Windows` 那样。这些“magic numbers”存储在文本文件 `/usr/share/magic` 中。
