
- 访问位于 B 部门本地的文件。
- 访问运行在 B 部门系统上的客户端/服务器应用程序。
- 对 B 部门系统本地磁盘的远程文件访问。

安装此新系统产生的额外流量必须与网络上的现有流量进行比较。在利用率达到 80% 的网络段上添加无盘客户端无异于自找麻烦。

你不需要复杂的工具来监控网络流量。只需取一个工作站，使用供应商提供的工具统计它在网络上看到的网数据包数量。一种简单的方法是使用如 `etherfind` 或 `sniff` 等工具以混杂模式监听以太网接口，在这种模式下，它会监听网络上的所有数据包，而不仅仅是给自己的包。然后统计系统在一段时间内接收的数据包数量及其相应的长度。大多数 UNIX 系统可以驱动以太网段发发达到约 800 kbps，持续速度超过 500 kbps。如果流量接近这一数值，请将该段分为两个段以减少流量。

在将网络拆分为段时，如果你可以将服务器及其系统放置在每个拆分的分段中，通常可以使用较廉价的桥接器来减少每个段的流量，而不是使用路由器。

## 在开始之前需要了解的总结

总之，在开始规划新系统的实际安装之前，你需要确定谁将使用该系统。你需要确定将进行多大的磁盘访问，它们对整体网络流量的贡献有多少；该系统将作为客户端还是服务器；以及在段因为过载而必须分割之前，网络是否能够容纳另一个系统。

## 安装规划

你现在必须确定在哪个段安装此新系统，决定它是为什么类型的用户设计的，以及将其放置在哪里。除了插入电源和网络连接，你还需要规划什么？

本节将引导你完成一份简短的安装前清单，以确保安装过程顺利进行。它将包含以下问题：

- 我将从哪里安装？
- 这是独立系统、服务器还是无盘系统？
- 它的主机是什么？
- 它的 IP 地址是什么？
- 应该安装哪些包？
- 应该如何对磁盘进行分区？

这些都是你在安装 UNIX 时系统会问的一些问题。大多数其他问题都有而易见的答案，例如你所在的时区。

### 从哪里开始？

传统上，我通过将介质放入驱动器并从该介质启动（如软盘、磁带或 CD-ROM）来安装系统。随着网络出现，事情变得不再简单，但它们可以变得方便得多。

你有两种安装选择：本地或远程。本地安装是传统情况，将介质插入到要安装计算机的某个驱动器中，并将软件复制到系统中。远程安装分为两种。

你可能会使用远程的 CD-ROM 或磁带驱动器读取介质，因为你正在安装的系统没有这些。但如果有大量系统需要安装，你会访问一个安装服务器，它的本地磁盘上已经有了所有的安装文件和启动镜像。由于本地磁盘比 CD-ROM 或磁带快，这种方法更快。然而，当你有大量系统需要安装时，设置安装服务器也是值得的。

介质发行：由于有 350 MB 的软件需要安装，软盘已不再实用。UNIX 软件供应商已从软盘切换到 CD-ROM 或磁带作为介质。关于磁带，不同的 UNIX 供应商使用不同的格式，有些甚至有多种。你需要确保知道供应商提供的是哪种格式，并且你有可以读取这些数据的驱动器副本。

如果选择，请选择 CD-ROM。它比磁带有几个优势。CD-ROM 比磁带快得多，而且它们是随机访问的。这使得安装变得更加快捷高效。

另一个优势是介质是只读的。无法由于误操作或硬件故障覆盖它。此外，CD-ROM 的生产成本低得多，且存储容量超过了它所取代的软盘或磁带。使用 CD-ROM 时，通常不需要在安装过程中更改介质路径。

如果你的计算机无法从 CD-ROM 或磁带启动，供应商还提供启动盘（在 Linux 发行版中，为“root”和“boot”磁盘，它们本质上包含了与你的硬件配合启动所需的信息：安装程序以及它所需的软件）。这是一个最小的基于 RAM 的系统，从软盘加载并被用于读取 CD-ROM 或磁带。它基本上包含了访问你的 CD-ROM 或磁带所需的各种驱动程序。

> 注意：如果你需要启动软盘，请务必使用适用于你系统的正确启动软盘。许多 System V 版本 3 和 4 的供应商为像基于 SCSI 的驱动器系统与专用磁带驱动器控制器的系统提供不同的启动软盘。此外还为不同版本的磁盘控制器提供不同的 CD-ROM 软盘。Linux 发行版有许多不同的启动盘可供，而像 BSD/OS 等某些商业 Unix 只有一个通用的启动盘。

> 注意：仔细阅读发行说明。大多数基于 PC 的 UNIX 系统仅支持有限的硬件。确保你的显示适配器、网卡和磁盘控制器受到支持。检查是否需要特定的驱动程序。

在开始安装之前，请从厂商处获取驱动程序，并确保驱动程序适用于你的 UNIX 版本。如果安装程序没有要求这些驱动程序，请在重启之前安装它们。

否则，系统将无法启动。

使用本地设备或远程设备进行安装。由于 UNIX 供应商已决定转向 CD-ROM 作为介质，你可能在网络某处有一个 CD-ROM 驱动器。此时你有两个选择：

- 从本地拔出驱动器并将其添加到系统中，按照 CD-ROM 的说明进行。
- 如果你的 UNIX 版本具有远程安装功能，从它目前所在的系统远程访问驱动器。由于网络通常比 CD-ROM 快得多，任种选择都是行的。你只需要确保驱动器在整个过程中可用。如果有人需要该 CD-ROM，在安装完成之前你无法释放它。

> 注意：如果系统必须从 CD-ROM 启动，并不总是可以将任何 CD-ROM 驱动器插入系统。许多 UNIX 工作站在其 CD-ROM 中放置了特殊区域以便在启动过程中看起来像磁盘驱动器。如有疑问，最好有一个该工作站的 CD-ROM 用于安装。

### 无盘还是独立服务器系统？

现在是决定该系统是作为服务器的无盘客户端、无数据系统还是独立系统或服务器了。你需要做出此决定以确保系统与其服务器位于同一域，并在无盘的情况下位于同一网络段。

此外你还需要决定如何对磁盘进行分区。

通常，价格决定了系统是否完全无盘。如果你买得起磁盘驱动器，你应该购买一个并将系统作为无数据系统。只有当由于环境或电源问题无法在本地放置磁盘；或者访问系统升级磁盘困难或不可能时，才保留使用无盘的情况。这时需要在系统上进行所有的管理和升级。

你应该查看系统的发行说明以获取具体信息，但请参考以下磁盘空间要求作为指南：

无盘--由于没有本地磁盘，所有磁盘空间都位于服务器上。每个无盘客户端必须从服务器挂载其根、交换、临时和溢出分区。预计从服务器分配以下：

- `root`: 10-20 MB
- `swap`: 随内存大小而异，但 16-256 MB 是正常范围。
- `spool`: 10-20 MB

无数据（Dataless）——无数据客户端为上述列出的无磁盘客户端的每个分区使用本地磁盘。

独立式（Stand-alone）——该系统用于应用程序，使用与无磁盘客户端相同的尺寸是合适的。

此外，还需要一个 `/usr` 分区来存放额外的 100 MB 空间，用于存放操作系统的剩余。如果还要将 X 窗口系统存储在本地，根据安装的工具和字体数量，它可能额外需要多达 70 MB。最小化安装需要约 30 MB。

如果用户是开发者，`/usr` 分区将需要大约 150-200 MB 的空间，以存放用户所需的编译器、库文件、额外工具和本地工具。

服务器（Server）——服务器系统通常需要安装整个操作系统。以下是关于总体尺寸的指导方针：

| 分区 | 大小 |
| :--- | :--- |
| `root` | 20 MB |
| `swap` | 随内存大小变化，但正常范围为 64-512 MB。 |
| `spool` | 40-100 MB |
| `tmp` | 20-80 MB |
| `usr` | 250 MB |
| `x` | 75 MB |
| 每个无磁盘客户端 | 50-200 MB (如果客户端需要较大的交换区) |

此外，服务器可能安装了多个网络接口。这是为了让它可以为多个网段提供服务。

每个 UNIX 系统都被赋予一组名称：

- 主机名（Host name）——其在本地被识别的短名称。
- UUCP 名称——通常与主机名相同。用于 UNIX 系统之间基于调制解调调器的通信。
- 域名（Domain name）——用于在电子邮件和路由中标识该系统属于哪个系统组的名称。
- NIS 域（NIS domain）——用于在系统管理目的中标识该系统被分在哪个组中的名称。该组系统共享公共密码和其他系统管理文件。

提示：为什么使用分区？

控制——如果由于软件错误、硬件故障或电源问题导致系统崩溃，将文件分散在多个分区可以减少对关键文件的损坏。

访问控制——只有分区可以被标记为只读。

空间管理——文件从文件系统的空池中分配。如果用户分配了大量空间，将没有可用空间。系统在耗尽空间时将会冻结。

使用独立的文件（特别是对于用户），允许在文件系统满时只有一个用户或一组用户被延迟。系统将继续运行。

性能——在范围内，文件系统越大，管理的表越大。随着磁盘碎片和空间稀缺，文件的部分可能会被放在磁盘上。使用较小的分区可以减少绝对距离，并保持表的大小在可范围内。

备份——许多备份工具在整个文件系统上工作。如果文件系统很大，备份它花费的时间可能比你预想的要长。多次备份更容易处理和恢复。

> 注意：仅仅你进行多次备份并不意味着你需要多个磁带。UNIX 可以将多个备份放在单条磁带上，只要磁带上有空间容纳它们。

所有 UNIX 安装都需要以下分区：`root` 和 `swap`。

建议你创建分区来存放 `usr`、`var`、`home` 和 `tmp`。

当你读取每个分区的章节时，为你的磁盘空间创建一个地图并将每个分区分配到地图上。你在输入磁盘分区信息时将使用此地图。

### root 分区

根分区挂载在文件系统层次结构的顶部。它在系统启动时自动挂载，并且无法卸载。所有其他文件系统都挂载在根之下。

`root` 需要足够大以存放以下内容：

- 启动信息和可引导的 UNIX 内核，以及内核的备份以防主内核损坏
- 任何本地系统配置文件，通常位于 `/etc` 目录
- 任何独立的程序（例如诊断程序），都可能被用来运行而不是...

此分区通常运行空间在 10 到 20 MB 之间。它也放置在磁盘的第一个分片上，通常称为零或该分片。

### 交换分区 (swap Partition)

“用途”部分中的注释描述了 UNIX 如何使用交换分区。默认规则是交换空间的大小是系统安装的内存（RAM）的两倍。如果你有 16 MB 的内存，则交换空间至少需要 32 MB。如果你有 256 MB 的内存，推荐的交换空间为 512 MB。

这仅仅是一个起点。如果你的系统用户运行大量数据（例如桌面出版或 CAD），交换空间可能不够。如果你不确定用户的交换空间需求，可以根据内存的规则，通过 `pstat` 或 `swap` 命令监控交换空间的使用量。如果你分配的额度不够，大多数 UNIX 系统都支持在运行时通过 `swapon` 或 `swap` 命令添加额外的交换空间。

### usr 分区 (usr Partition)

`usr` 包含了剩余的 UNIX 操作系统实用程序。它需要足够大，以容纳你在上次安装时选择要安装的所有软件包。

如果你打算在此分区中安装本地应用程序或第三方应用程序，它也需要足够大以容纳它们。

### var 分区 (var Partition)

`var` 包含了用于打印机文件队列和电子邮件的调式目录，以及该系统特有的日志文件。它还包含 `/var/tmp` 目录，用于较大的临时文件。每个系统（即使是无盘客户端）也需要自己的 var 文件系统。它不能与其他系统共享。

> 注意：虽然 var 文件系统不能共享，但其底方的子目录可以共享（例如 `/var/news`）。

这些目录会在 var 文件系统已经挂载后被挂载到其上方。

如果你不打印大文件，请接受发行说明中对该分区建议的大小。如果你处理大量文件或大文件，或者你的站点正在产生大量的 UUCP 流量，请考虑增加此分区的大小以满足你的需求。

> 提示：对于打印文件，一个良好的起点是在建议大小的基础上加上最大打印文件大小的 10 倍。如果该系统连接了大量用户或多个打印机，请增加更多。

对于 UUCP 文件，请保留足够的空间容纳每个站点至少一天的流量。

### home 分区 (home Partition)

这是用户登录目录存放的地方。将 `home` 作为一个独立的分片，可以防止用户在文件系统空间耗尽时损坏系统的其他部分。

该分片的良好起点是：根据你打算在该系统上支持的每个应用程序用户提供 5 MB，每个高级用户提供 10 MB，每个开发者提供 20 MB。

> 提示：不要过于担心准确性。如果你为某个特定用户需要更多空间，只需将用户的目录移动到另一个有空间的文件系统，并在 `/home` 中创建一个符号链接指向它的新位置。用户可能永远不知道你移动了目录。

### /tmp 分区 (/tmp Partition)

大文件存放在 `/var/tmp` 中，但临时文件放在 `/tmp` 中，这样你就不会让根系统空间耗尽。如果你的用户大部分是应用程序用户，5 到 10 MB 对此分片就足够了。如果他们是高级用户或开发者，10 到 20 MB 更好。如果系统中同时有超过 10 个用户，考虑将此分片的大小翻倍。

> 提示：`/tmp` 目录中的文件是短命的。如果你的 UNIX 提供，请为 `/tmp` 使用 `TMPFS` 类型（临时文件系统，基于内存的文件系统）。通过将此文件系统放在内存而非磁盘中，可以提高性能。每次重启丢失文件并不担心，因为 UNIX 在每次重启时都会清除 `/tmp` 目录。

### 将分区分配到磁盘驱动器 (Assigning Partitions to Disk Drives)

如果你有一个驱动器，你的第二个决定是将分区放在哪个驱动器。目标是平衡所有驱动器之间的磁盘访问。如果你有两个驱动器，考虑以下分区方案：

| 驱动器 1 | 驱动器 2 |
| :--- | :--- |
| `root` | `usr` |
| `swap` | `home` |
| `var` |  |

剩余分区根据空间情况分布在驱动器上。

### 分配 IP（网络）地址 (Assigning IP Addresses)

如果系统有网络连接，必须分配一个 IP 地址。IP 地址在第 20 章中解释。IP 地址是由四个由点隔的数字组成，每个称为字节。每个网络连接都有自己的 IP 地址。在局域网段内，通常点分四位的前三个字节是相同的。第四个字节对于每个接口必须是唯一的。地址 0 和 255（全零和全一）保留给广播地址。剩余的 254 个地址可以分配给任何系统。

> 注意：IP 地址不是以太网地址。以太网地址是由制造商分配的硬件级地址。它长六字节（48 位）。前三个字节代表制造商

- 持有安装驱动器的系统名称及其设备名称

在安装介质上运行 `pkgadd`，请将介质放入驱动器并输入命令：

```
pkgadd -d path-name-to-device pkg_name
```

`pkgadd` 会提示你需要安装哪些软件包，并在安装包时为你提供进度消息。不同的软件包在安装前也可能向你提问。这些问题通常与安装包的位置以及任何其他安装选项有关。
