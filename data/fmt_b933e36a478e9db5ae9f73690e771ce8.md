
# 修复措施

如果 `/etc/shadow` 文件中的任何账户没有密码，请运行以下命令锁定该账户，直到确定其为何没有密码为止：

```bash
# passwd -l <username>
```

此外，检查该账户是否已登录，并调查其用途，以确定是否需要强制其下线。

# 6.2.3 确保 `/etc/passwd` 中的所有组都存在于 `/etc/group` 中

**(自动化)**

**配置适用性：**

- 等级 1 - 服务器
- 等级 1 - 工作站

**描述：**

随着时间的推移

**理由：**

在 `/etc/passwd` 文件中定义但在 `/etc/group` 文件中定义的组会对系统安全构成威胁，因为组权限没有得到适当管理。

**审计：**

运行以下脚本并验证没有返回结果：

```bash
#!/bin/bash

for i in $(cut -s -d: -f4 /etc/passwd | sort -u ); do
  grep -q -P "^[:space:]]*:$i" /etc/group
  if [ $? -ne 0 ]; then
    echo "Group $i is referenced by /etc/passwd but does not exist in /etc/group"
  fi
done
```

# 6.2.4 确保 `shadow` 组为空

**(自动化)**

**配置适用性：**

- 等级 1 - 服务器
- 等级 1 - 工作站

**描述：**

`shadow` 组允许需要访问 `/etc/shadow` 文件的系统程序读取。不应将任何用户分配到 `shadow` 组。

**理由：**

任何分配到 `shadow` 组的用户都将获得对 `/etc/shadow` 文件的读取权限。如果攻击者获得了对 `/etc/shadow` 文件的读取权限，他们可以轻松对哈希后的密码运行密码破解程序来破解它们。存储在 `/etc/shadow` 文件中的其他安全信息（如过期时间）也可能用于破坏其他用户账户。

**审计：**

运行以下命令并验证没有返回结果：

```bash
# awk -F: '($1="shadow") (print NF)' /etc/group
# awk -F: -v GID="shadow" awk -F: '($1="shadow") (print $3)' /etc/group
'($4==$GID) (print $1)' /etc/passwd
```

**修复：**

运行以下命令从 `shadow` 组中删除所有用户：

```bash
# sed -ri 's/(^[:::]*)[^[::]]*)([:::]*)([^+$)/\1/' /etc/group
```

更改所有以 `shadow` 为主组的用户的主组。

```bash
# usermod -g <primary group> <user>
```

## 6.2.8 确保不存在重复的组名

**(自动化)**

**配置适用性：**

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

虽然 `groupadd` 程序不会允许你创建重复的组名，但管理员可能会手动编辑 `/etc/group` 文件并更改组名。

**原理：**

如果一个组被分配了重复的组名，它将在 `/etc/group` 中创建并对该组第一个 GID 对应的的文件访问权限。实际上，GID 是共享的，这会产生一个安全问题。

**审计：**

运行以下脚本并验证没有返回结果：

```bash
#!/bin/bash
cut -d: -fl /etc/group | sort | uniq -d | while read -r x; do
echo "Duplicate group name $x in /etc/group"
done
```

**修复：**

根据审计脚本的结果，为用户组建立唯一的名称。只要组具有唯一的 GID，组所有权将自动反映这些更改。

## 6.2.9 确保 root PATH 完整性

**(自动化)**

**配置适用性：**

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

`root` 用户可以执行系统上的任何命令，但如果 `PATH` 设置不正确，可能会被误导执行非意图的命令。

**原理：**

在 `root` 的可执行路径中包含当前工作目录 (`.`) 或其他可写目录，可能会导致攻击者通过强制要求以 `root` 身份操作的管理员执行特洛马程序来获得超级用户权限。

**审计：**

运行以下脚本并验证没有返回结果：

```bash
#!/bin/bash
RPCV="$(sudo -u root env | grep '^PATH' | cut -d= -f2)
echo "RPCV" | grep -q "::" && echo "root's path contains an empty directory"
echo "RPCV" | grep -q "::" && echo "root's path contains a trailing directory"
for x in $(echo "RPCV" | tr ":" " "); do
  if [ -d "$x" ]; then
    awk '$9 == "." {print "PATH contains current working directory."}
    $3 != "root" {print $9 "is not owned by root"}
    substr($1,9,1) != "-" {print $9 "is group writable"}
  else
    echo "$x is not a directory"
  fi
done
```

**修复：**

修正审计步骤发现的任何项。

## 6.2.11 确保本地交互式用户家目录存在

**(自动化)**

**配置适用性：**

- 级别 1 - 服务器
- 级别 1 - 工作站

**描述：**

`/etc/passwd` 中定义的用户可能没有家目录，或者其家目录实际上并不存在。

**原理：**

如果用户的家目录不存在或未分配，用户将被放置在 `/` 目录下，并且无法写入任何文件或设置本地环境变量。

**审计：**

运行以下脚本以验证所有交互式用户的家目录存在：

```bash
#!/usr/bin/env bash
{
  output=""
  valid_shells=$(sed -rn '^\/(s,\,\/;p)' /etc/shells | paste -s -d ' ' -)
  awk -v pat="$valid_shells" -F: '$NF ~ pat { print $1 " " $(NF-1) }' /etc/passwd | while read -r user home; do
    if [ -d "$home" ] || output="$output\n - User $user home directory $home doesn't exist"
  done
  if [ -z "$output" ]; then
    echo -e "\n- PASSED: All interactive users have a home directory"
  else
    echo -e "\n- FAILED:"
  fi
}
```

**修复：**

如果用户的家目录不存在或未分配，用户将被放置在 `/` 目录下且无法写入任何文件或设置本地环境变量。以下脚本将为未分配家目录的用户创建家目录并确保用户拥有它。
