
HLA 是一种高级汇编语言。它使用类似于 Pascal、C/C++ 以及其他高级语言的高级语言进行变量声明、过程声明和过程调用。它使用修改过的汇编语言来处理标准的机器指令。它还提供了几种层级语言风格的控制（`if`, `while`, `repeat...until` 等），帮助你编写更具可读性的代码。

HLA 是免费的并提供源码，有 Linux 和 Win32 版本。在 Win32 上你需要 `MASM` 和 32 位的 `MS-link`；在 Linux 上你需要 `GAS`，因为 HLA 产生汇编后的汇编代码，并使用它进行汇编和链接。

## 3.5.6. TALC

TALC 不是免费的基于 ASM/Win32 的编译器（然而，它支持 ELF 输出，它不是吗？）。

TAL 代表类型汇编语言 (`Typed assembly Language`)。它通过类型注解、内存原语和一组类型规则扩展了传统的无类型汇编语言，以保证 TAL 程序的内存安全、控制流和类型。此外，这些结构足够强大，可以编码大多数源代码执行程序特性，包括记录和结构、高阶和多态函数、异常、抽象数据类型、子类型和模块。同样重要的是，TAL 足够灵活，可以接受许多低级编译器优化。因此，TAL 是类型导向编译器的理想平台，旨在产生可验证的安全代码，用于移动代码应用程序或可扩展的操作系统内核。

## 3.5.7. Free Pascal

Free Pascal 拥有一个内部的 32 位汇编器（基于 NASM 表）以及一个可切换的输出，允许：

- 交叉编译时输出 ELF 和 conf `.o`

- `NASM`

- `MASM`

- `TASM`

- `AS` (`aout.coff, elf32`)

Linux 汇编语言 HOWTO

MASM 和 TASM 的输出没有另外两个那样经过调试，但有时可能很有用。

该汇编器的外观和感觉基于 Turbo Pascal 内部的 BASM，且 IDE 支持高亮，FPC 可以与 `gcc` 完全集成（在 C 级别，而不是 C++ 级别）。

使用一个虚拟的 RTL，人们可以生成纯汇编程序。

## 3.5.8. Win32forth

Win32For 是一个免费的 32 位 ANS 系统，可以在 Win32s、Win95、Win/NT 下成功运行。它包含一个集成在反射式 FORTH 语言中的免费 32 位汇编器（前缀或后缀语法）。宏处理通过反射式 FORTH 的全部威力完成；然而，唯一支持的输入输出上下文是 Win32For 自身（不导出 `.obj` 文件，但当然可以添加该功能）。可以在 `http://ftp.forth.org/pub/Forth/Compilers/native/windows/Win32For/` 找到。

## 3.5.9. Terse

Terse 是一个编程工具，为 x86 家族提供了最紧凑的汇编器！然而，它是完全专有的软件。据说某处有一个免费克隆项目，但在“语法应归原作者所有”的无理借口后被放弃了。因此，如果你正在寻找一个巧妙的编程项目来重启黑客活动，如果你喜欢那种语法，我邀请你开发一个针对 NASM 的 tersse 前端（tersese-frontend）。

一个有趣的历史备注，版员写道：

> “没有理由汇编器必须有糟糕的语法。大约 30 年前，我遇到了 Niklaus Wirth 的 PL360，它基本上是一个带有 Algol 语法和少量语法糖的 S360 汇编器，while 循环运行在显的分分支中。它确实是一个汇编器，例如，你必须通过显式向寄存器赋值值来写出表达式，但它很好。Wirth 用它来编写 Algol，一个小型快速的子集，它是 Pascal 的前身。正如通常一样，Algol 相对于它的许多继任者有了重大的改进。” - John

# 4. 元编程

## 4.1. 外部过滤器

无论来自你的什么汇编器，或者无论你使用哪种语言（即使是 C！），如果该语言的表达能力不足，你可以像下面这样通过 Makefile 将文件传递通过外部过滤器：

```
.%s
    other_dependencies
    $(FILTER) $@
```

### 4.1.1. CPP

`CPP` 确实非常有表达力，但考虑到它如此平庸，请远离它。

### 4.1.2. M4

`M4` 为你提供了元编程的全部能力，具有递归、正则表达式等。你可以用它完成一切。`M4` 的正确版本是 `1.4`（或更高），它功能最多，缺陷最少。

### 4.1.3. 使用自己的过滤器进行宏处理

你可以使用 `perl`, `awk` 等常用工具编写自己的简单的过滤器。它可以很快完成，而且你控制一切。但是，当然，宏处理意味着“困难的方法”。

## 4.2. 元编程

与其使用扩展宏的外部过滤器，一种方法是编写处理其他程序。

例如，你可以使用程序输出源代码

- 生成正弦/余弦等查找表

- 从二进制文件中提取源码形式表示

- 将位图编译为快速显示程序

- 从同一源文件中提取文档、初始化/结束代码、描述表

- 使用 `perl`/`shell`/`scheme` 脚本生成自定义汇编代码

- 进行任意处理

- 等

### 4.2.1. 编译编译器的后端

诸如 `GCC`、`SMI/NJ`、`Objective CAML`、`MIT–Scheme`、`CMUCL` 等编译器都有它们自己的通用汇编器后端，如果你打算从相应的语言或你拥有的语言自动生成代码，你可以选择使用：与其编写出色的汇编代码，你不如修改编译器让它导出优秀的汇编代码！

### 4.2.2. New–Jersey 机器工具包

有一个项目使用编程语言 `Icon`（带有实验性的 ML 版本）来构建产生汇编操作代码的基础。请查看 `http://www.eecs.harvard.edu/~nr/toolkit/`

### 4.2.3. TUNES

TUNES 项目是一个自由的反射式计算系统，它是 Scheme 语言的一种特殊扩展，作为其开发的一部分。它目前还没有运行，尽管欢迎帮助。

汇编器翻译抽象语法树，因此它可以很容易地作为语法转换器、反汇编器、通用汇编器/编译器后端的等。此外，真实语言 Scheme 的全部威力使其在宏处理/元编程方面是无可比拟的。

# 第 5 章 调用约定

## 5.1. Linux

### 5.1.1. 与 GCC 链接

如果你正在开发混合 C-汇编项目，这是首选方法。检查 GCC 文档以及 Linux 内核 `.S` 文件的示例（这些文件是通过 `gas` 处理的，而不是通过 `as86`）。

32 位参数按语法的反向顺序入栈（因此按正确的顺序进行访问/弹出），并存放在 32 位返回地址之上。`%ebp`, `%esi`, `%edi`, `%ebx` 是调用者保存的（callee-saved），其他寄存器是调用者保存的；`%eax` 用于存储结果，`%edx:%eax` 用于 64 位结果。

FP 栈：我非常确定，但结果在 `st (0)` 中，不过栈是调用者保存的。如果你想了解更多细节，`http://www.caldera.com/developer/specs` 的 SVR4 i386 ABI 规范是一个很好的参考点。

注意，`GCC` 有选项可以修改调用约定，例如保留寄存器、让参数位于寄存器中、不假设存在 FPU 等。查看 i386 `.info` 页面。

注意，对于遵循标准 GCC 调用约定的函数，你必须声明 `cdecl` 和 `regparam(0)` 属性。参见 GCC 页面中的 C Extensions::Extended As:: 章节。此外还有 Linux 如何定义其汇编宏。

### 5.1.2. ELF 与 a.out 的问题

某些编译器会在每个符号前加上一个下划线，而另一些则不会。

特别是，Linux a.out GCC 会进行这种前缀处理，而 Linux ELF GCC 则不会。

如果你需要同时处理这两种行为，我们有现成的包。例如，获取一个旧的 Linux 源码树，如 `elks`、`threads` 或 `OCaml`...
