
- `$(*D)` `$(*F)` : 茎（stem）的目录部分和目录内的文件名部分；在本例中为 'dir' 和 'foo'。

- `$($D)` `$($F)` : 存档成员名的目录部分和目录内的文件名部分。这对于形式为 'archive(member)' 的存档成员目标才有意义，并且成员可能包含目录名时有用。（参见第 11.1 节 [作为目标的存档成员]，第 121 页。）

- `$(*D)` `$(*F)` : 第一个先条件的目录部分和目录内的文件名部分。

- `$($D)` `$($F)` : 所有先条件的目录部分和目录内的文件名部分的列表。

- `$(?D)` `$(??)` : 比目标新的所有 `$(?)` 先条件的目录部分和目录内的文件名部分的列表。

请注意，当我们谈论这些自动变量时，使用了一种特殊的样式约定；我们写“the value of '$'”而不是变量 `'<'`，就像我们为对象和 `CFLAGS` 等普通变量所写的那样。我们认为这种约定在这种特殊情况下看起来更自然。请不要假设它有深层意义；`'$'` 指的是变量 `'<'`，就像 `$(CFLAGS)` 指的是名为 `CFLAGS` 的变量一样。你也可以直接用 `$($<)` 代替 `$`。

### 10.5.4 模式如何匹配

目标模式由前缀和后缀之间的 `%` 组成，其中一个或两者都可能为空。只有当文件名以前缀开头并以后缀结尾且不重叠时，该模式才匹配文件名。前缀和后缀之间的文本被称为“茎”（stem）。因此，当模式 `%.o` 匹配文件名 `test.o` 时，茎为 `test`。模式规则的先条件通过用茎替换字符 `%` 转换为实际文件。因此，如果示例中其中一个先条件写为 `%.c`，它将扩展为 `test.c`。

当目标模式不包含斜杠时（它通常不包含），在与目标前缀和后缀比较之前，文件名中的目录名会被移除。在将文件名与目标模式进行比较后，目录名以及结束它们的斜杠会被重新添加到从模式规则的先条件模式生成的先条件文件名和文件名中。目录仅在为了查找要使用的隐式规则时被忽略，而在应用该规则时不会忽略。因此，`%*` 匹配文件名 `src/eat`，以 `src/a` 为茎。当先条件转换为文件名时，茎的目录会被添加到前面，而茎的其余部分将替换为 `%`。茎 `src/a` 配合先条件模式 `%*r` 得到文件名 `src/car`。

### 10.5.5 匹配任意内容的规则

当模式规则的目标仅为 `%` 时，它可以匹配任何文件名无论是什么。我们称这些为“匹配任意内容的规则”。它们非常有用，但 make 思考这些规则可能会花费大量时间，因为它必须考虑每个列为目标或先条件的 Find名的每一个规则。

假设 makefile 中提到了 `foo.c`。对于此目标，make 将考虑通过链接对象文件 `foo.c.o`来制作它，或者通过从 `foo.c.o` 一步进行 C 编译和链接，或者通过从 `foo.c.p` 进行 Pascal 编译和链接，以及许多其他可能性。

我们知道这些可能性是荒谬的，因为 `foo.c` 是一个 C 源文件，而不是可执行文件。如果我们真的考虑了这些可能性，它最终会拒绝它们，因为像 `foo.c.o` 和 `foo.c.p` 等文件并不存在。但由于这些可能性如此多，如果我们必须考虑它们，make 运行将会很缓慢。

为了提高速度，我们对考虑匹配规则的方式施加了各种约束。有两种不同的约束可以应用，每当你定义一个匹配规则时，必须选择其中一种。

一种选择是通过双冒号将匹配规则定义为终止的（terminal）。当规则终止时，除非先条件实际存在，否则不会生效。换句话说，终止规则之后不允许进一步的链式反应。例如，如果文件 `foo.c,v` 不存在，内置规则甚至不会考虑从 `foo.c,v.o` 或从 `RCS/s.c,o` 制作它。

### 10.5.6 取消隐式规则

你可以通过定义一个具有相同目标和先条件但命令不同的新规则来覆盖内置规则（或你定义的规则）。当新规则被定义时，内置规则将被替换。新规则在隐式规则序列中的位置取决于你编写规则的位置。

你可以通过定义一个具有相同目标和先条件但没有命令的模式规则来取消内置规则。例如，以下内容将取消汇编器：

```
%.o : %s
```

### 10.6 定义最后的默认规则

你可以通过编写一个没有先条件的终止任意模式规则来定义最后的隐式规则（参见第 10.5.5 节 [匹配任意内容的规则]，第 114 页）。这与任何其他模式规则都相同；唯一的特殊之处在于它可以匹配任何目标。因此，此类规则的命令将用于所有没有自己的命令且没有隐式规则适的目标和先条件。

例如，在测试 amfile 时，你可能不在乎源文件是否包含真实数据，只要求它们存在。这时你可能会这样做：

```
%:
touch $@
```

从而自动创建所有所需的（作为先条件的）源文件。

你也可以为没有任何规则（甚至没有命令）的目标定义使用的命令。你通过编写目标 `.DEFAULT` 来实现。此类规则的命令将用于所有未在任何显式规则的目标中出现、且没有隐式规则适用的先条件。

如果你使用了不带命令或先条件的 `.DEFAULT`：

```
.DEFAULT:
```
之前存储在 `.DEFAULT` 中的命令将被清除。然后 make 的表现就像你从未定义过 `.DEFAULT` 一样。

# 第 10 章：使用隐式规则

你可以使用一种最后手段规则来覆盖另一个 Makefile 的部分。参见第 3.6 节 [覆盖另一个 Makefile 的部分]，第 15 页。

### 10.7 旧式后缀规则

后缀规则（Suffix rules）是为 make 定义隐式规则的旧式方法。后缀规则已经过时，因为模式规则（pattern rules）更通用、更清晰。为了兼容旧的 makefile，GNU make 支持后缀规则。它们分为两种类型：双后缀规则和单后缀规则。

双后缀规则由一对后缀定义：目标后缀和源后缀。它匹配任何以目标后缀结尾的文件。对应的隐式依赖项通过将文件名中的目标后缀替换为源后缀来生成。一个后缀为 `.o` 和 `.c` 的规则等同于模式 `%.o:%c`。

单后缀规则由单个后缀定义，该后缀即源后缀。它匹配任何文件名，对应的隐式依赖项名称通过附加源后缀来生成。后缀为 `.c` 的单后缀规则等同于模式 `%:%c`。

后缀规则通过将每个规则的目标与定义的后缀进行比较来识别。当 make 看到一个已知后缀时，该规则被视为单后缀规则。当 make 看到一个由两个已知后缀拼接而成的目标时，该规则被视为双后缀规则。

例如，`.c` 和 `.o` 都在默认的已知后缀列表中。因此，如果你定义一个目标为 `.o` 的规则，make 将其视为源后缀为 `.c`、目标后缀为 `.o` 的双后缀规则。以下是编译 C 源文件的旧式规则定义：

```
.c.o:
$(CC) -c $(CFLAGS) $(CPPLAGS) -o $$ $<
```

后缀规则不能有任何自己的依赖项。如果它们有任何依赖项，它们将被视为具有奇怪名称的普通文件，而不是后缀规则。因此，规则如下：

```
.c.o: foo.h
$(CC) -c $(CFLAGS) $(CPPLAGS) -o $$ $< $
```

告诉的是如何从依赖项 `foo.h` 生成 `.c` 文件，这与模式规则完全不同：

```
%.o:%c foo.h
$(CC) -c $(CFLAGS) $(CPPLAGS) -o $$ $< $
```

告诉的是如何使用 `.c` 文件制作 `.o` 文件，并使得所有使用此模式规则的 `.o` 文件依赖于 `foo.h`。

没有命令的后缀规则也是没有意义的。它们不会没有命令的模式规则那样移除之前的规则（参见第 10.5.6 节 [取消隐式规则]，第 116 页）。它们只是将后缀或拼接的后缀作为目标进入数据库。

已知后缀只是特殊目标 `.SUFFIXES` 的名称。你可以通过编写一个为 `.SUFFIXES` 规则添加更多依赖项来添加自己的后缀，例如：

```
.SUFFIXES: .hack .win
```

这将 `.hack` 和 `.win` 添加到后缀列表的末尾。

如果你想消除默认已知后缀而不是仅仅添加，请编写一个没有依赖项的 `.SUFFIXES` 规则。通过特殊许可，这将消除 `.SUFFIXES` 的所有现有依赖项。然后你可以编写另一个规则来添加你需要的后缀。例如：

```
.SUFFIXES:
    # 删除默认后缀
.SUFFIXES: .c .o .h # 定义我们的后缀列表
```

`-r` 或 `--no-builtin-rules` 标志会导致默认后缀列表为空。

变量 `VARIABLE` 在 make 读取任何 makefile 之前定义在默认后缀列表中。你可以通过针对特殊目标 `.SUFFIXES` 的规则更改后缀列表，但这不会改变此变量。
