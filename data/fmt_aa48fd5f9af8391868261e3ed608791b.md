
为了编辑（即修改）shell 的启动文件以及系统上的大多数其他配置文件，我们使用一种名为文本编辑器的程序。文本编辑器在某些方面类似于文字处理器，因为它允许我们通过移动光标编辑屏幕上的文字。它与文字处理器的区别在于只支持文本，并包含了专为编写程序设计的功能。文本编辑器是程序员编写代码的核心工具。

文本编辑器分为两类：图形界面和文本界面。GNOME 包含了一些图形编辑器，按复杂度递增分别为 `gedit`、`drad` 和 `kate`。

有很多文本编辑器。我们遇到的流行的有 `nano`、`vi` 和 `emacs`。`vi` 编辑器（在大多数类 Unix 系统上）已被 `vim` 取替，`vim` 是 `vi` 的改进版。`emacs` 编辑器由 Richard Stallman 编写。它是一个巨大的全能编程环境。虽然随处可用，但在 Linux 系统上很少默认安装。

## 使用文本编辑器

可以通过命令行输入编辑器名称后跟要编辑的文件名来调用文本编辑器。如果文件不存在，编辑器将假设你想创建一个新文件。这里是使用 `gedit` 的示例：

```bash
[melinux] $ gedit some_file
```

此命令将启动 `gedit` 编辑器并加载 `some_file`（如果它存在）。图形编辑器直观易懂，所以我们在这里不介绍它们。我们将关注我们的第一个文本编辑器 `nano`。让我们启动 `nano` 并编辑 `.bashrc`。

在开始之前，让我们来练习一下“安全计算”。每当我们编辑一个重要的配置文件时，创建一个备份副本总是个好主意。这在我们编辑过程中弄乱文件时保护我们。要为 `.bashrc` 文件创建备份，执行以下操作：

```bash
[melinux] $ cp .bashrc .bashrc.bak
```

备份文件命名为什么什么并不重要，只要选一个易理解的名字即可。`.bak`、`.sav`、`.old` 和 `.orig` 是备份文件的流行后缀名。哦，记住 `cp` 会静默覆盖现有文件。

现在我们有了备份文件，我们将启动编辑器。

```bash
[melinux] $ nano .bashrc
```

一旦 `nano` 启动，我们将得到类似这样的屏幕：

```
GNU nano 2.0.3 File: .bashrc
```

```
## .bashrc

## 加载全局定义
if -f /etc/bashrc; then
  . /etc/bashrc
fi

## 用户特定的别名和函数
```

如果你的系统没有安装 `nano`，你可以使用图形化编辑器。

屏幕由顶部的页眉、中间正在编辑的文件文本以及底部的命令菜单组成。因为 `nano` 的设计初衷是替换邮件客户端自带的文本编辑器，所以它的编辑功能相对较少。

在任何文本编辑器中，你应该学习的第一个命令都是退出程序。在 `nano` 中，你按下 `CTRL-X` 退出。这在屏幕底部的菜单中有指示。符号 `X` 表示 `CTRL-X`。这是许多程序使用的控制字符的常用表示法。

我们需要知道的第二个命令是保存我们的工作。在 `nano` 中，现在已经准备好进行一些编辑了。使用方向键和/或 `PAGE DOWN` 键将光标移动到文件末尾，并向 `.bashrc` 文件中添加以下行：

```
umask 0002
export HISTCONTROL=ignoreddups
export HISTSIZE=1000
alias 1.='ls -d * --color=auto'
alias 11='ls -1 --color=auto'
```

你的发行版可能已经包含了其中一些内容，但即使有重复也不会产生任何影响。

表 11-4：对我们的 `.bashrc` 的添加

| 行 | 含义 |

|---|---|

| `umask 0002` | 设置 `umask` 以解决我们在第 9 章中讨论过的共享目录问题。 |

| `export HISTCONTROL=ignoreddups` | 使 shell 的历史记录功能如果刚刚记录了相同的命令，则忽略该命令。 |

| `export HISTSIZE=1000` | 将命令历史的大小从默认的 500 行增加到 1,000 行。 |

| `alias 1.='ls -d * --color=auto'` | 创建一个名为 `1` 的新命令，显示所有以点开头的目录项。 |

| `alias 11='ls -1 --color=auto'` | 创建一个名为 `11` 的新命令，显示长格式的目录列表。 |

正如我们看到的，我们添加的许多内容并不是直观易见的，为我们的 `.bashrc` 文件添加一些注释来帮助人类理解是一个好主意。使用编辑器将我们的添加内容修改如下所示：

# # 修改 `umask` 使目录共享变得更容易

```
umask 0002
```

# # 忽略命令历史中的重复项并将历史记录增加到 1000 行

```
export HISTCONTROL=ignoredups
export HISTSIZE=1000
```

# # 添加一些实用的别名

```
alias 1ls='ls -d * --color=auto'
alias 1ls='ls -l --color=auto'
```

啊，好多了！完成更改后，按下 `CTRL-O` 保存我们修改过的 `.bashrc` 文件，然后按下 `CTRL-X` 退出 `nano`。

## 为什么注释很重要

每当你修改配置文件时，添加一些注释来记录你的更改是一个好主意。当然，你明天可能还记得改了什么，但六个月后呢？帮自己个忙，添加一些注释吧。顺便记录一份你所所做的日志也不是个坏主意。

Shell 脚本和 `bash` 启动文件使用一个符号来开始注释。其他配置文件可能使用其他符号。大多数配置文件都有注释。将它们作为指南。

你经常会在配置文件中看到被注释掉的行，以防止它们被受影响的项目使用。这样做是为了给读者提供可能的配置选择建议或正确配置语法的示例。例如，Ubuntu 18.04 的 `.bashrc` 文件包含以下行：

```
# some more aliases
#alias 1ls='ls -1'
#alias 1la='ls -A'
#alias 1ls='ls -CF'
```

最后三行是经过注释的有效别名定义。如果你删除这些行开头的 `#` 符号（这种技术称为“取消注释”），你就会激活这些别名。相反，如果你在行开头添加一个符号，你可以在禁用某行配置的同时，保留其所包含的信息。

## 激活我们的更改

在我们对 `.bashrc` 进行的更改在关闭终端会话并启动新会话之前不会生效，因为 `.bashrc` 文件在会话开始时仅只读。然而，我们可以使用以下命令强制 `bash` 重新读取修改过的 `.bashrc` 文件：

```
me@linux~$ source ~/.bashrc
```

这样做之后，我们应该能够看到更改的效果。尝试一个新别名。

```
me@linux~$ 11
```

## 总结

在本章中，我们学习了一项基本技能：使用文本编辑器编辑配置文件。以后，当我们阅读命令的帮助手册（`man` pages）时，请注意命令支持的环境变量。其中可能有一两个宝藏。在随后的章节中，我们将学习 shell 函数，这是一个强大的功能，你也可以将其包含在 `bash` 启动文件中，丰富你的自定义命令武器库。

## vi 的简要介绍

有一个关于访客询问问路的老笑话：

访客：请问，怎么找到 `vi`？

路人：（指着终端）`vi` 在这儿！

`vi` 的第一个版本是由 Bill Joy 在 1976 年编写的，他当时是加州大学的一名学生，后来共同创立了 Microsystems。`vi` 的名字源于“visual”（视觉）一词，因为它旨在设计用于移动。在视觉化编辑器出现之前，只有在单行上操作的行编辑器。随着视频终端的出现，视觉编辑变得可能。`vi` 包含了一个名为 `ex` 的强大行编辑器。

大多数 Linux 发行版并不包含真正的 `vi`；相反，它们提供了一个名为 `vim` 的替代品（是“vi improved”的缩写），它通常被链接或别名为 `vi`。在接下来的讨论中，我们将假设拥有 `vim`。

## 为什么我们应该学习 vi

在如今这个编辑器时代，我们为什么要学习 `vi` 呢？有三个原因：

- `vi` 几乎总是可用的。

- `vi` 轻量级且快速。

- `vi` 功能强大。
