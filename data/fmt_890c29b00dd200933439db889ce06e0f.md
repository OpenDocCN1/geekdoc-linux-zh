
`/etc/nsswitch.conf`中的`hosts: files dns`行导致解析器在名称查找过程中先咨询`/etc/hosts`再使用DNS。这允许您通过临时修改`/etc/hosts`来覆盖DNS，这在网络测试期间特别有用。（较旧的解析器可能需要`/etc/host.conf`文件中的`order hosts, bind`行代替。）

## 运行 named 名称服务器守护进程

## 为真实域名提供 DNS

您可以将刚刚创建的最小名称服务器配置扩展为为一个真实域名提供有用名称服务的配置。假设您的ISP分配了`192.0.2.0/29`范围内的IP地址（该范围有六个可用地址：`192.0.2.1~6`），并且您希望为域`example.com`提供权威数据。一位朋友已同意将她的名称服务器（`192.0.2.96`）配置为该域的从服务器，同时也作为备份邮件服务器。作为回报，她希望将`foo.example.com`子域委托给她自己的名称服务器。

### 正向区域

首先，您必须将该区域引入`named.conf`：

```
zone "example.com" {
    type master;
    file "example.com";
};
```

并创建区域文件：

```
    $TTL 2D
@    SOA    ns1.example.com.  hostmaster.example.com. (
            2001090101 ; 序列号
            24h        ; 刷新间隔
            2h         ; 重试间隔
            3600000    ; 过期时间 (1000h)
            1h)        ; 最小 TTL

    NS     ns1.example.com.
    NS     ns2.example.com.
    MX 5   mx1.example.com.
    MX 10  mx2.example.com.
    A      192.0.2.1

    ; 地址
    ns1  A      192.0.2.1     ; 名称服务器
```

### 反向区域

请花点时间假设我们生活在一个完美的世界：你能力出众的ISP（互联网服务提供商）已经成功地将你反向区域的权威权限委派给了你，并且你必须设置`named`来处理反向解析。这个过程与你之前用于设置`0.0.127.in-addr.arpa`反向区域的过程非常相似。然而，现在你必须确定你区域的名称。

DNS只能在域名中的`.`处委派权威权限；因此，你可以为整个A类、B类或C类网络设置反向区域，因为它们在IP地址中是在八位组边界处划分的。这种方法显然不适合无类别子网，比如你的子网，因为划分不在八位组边界，而是在八位组的中间。换句话说，你的网络不能描述为`x.*`（A类）、`x.y.*`（B类）或`x.y.z.*`（C类）。后者最接近，但包含了几个不属于极小的`192.0.2.0/29`网络的地址（例如`192.0.2.22`）。要为你的网络设置反向区域，你必须诉诸于使用无类别委派（在RFC 2317中有描述）。

负责`2.0.192.in-addr.arpa`区域的ISP必须要么为你维护反向区域，要么在其区域文件中添加以下记录：

```dns
  1      CNAME   1.1-6
  2      CNAME   2.1-6
  3      CNAME   3.1-6
  4      CNAME   4.1-6
  5      CNAME   5.1-6
  6      CNAME   6.1-6

  1-6    NS      192.0.2.1
  1-6    NS      192.0.2.96
```

第一条CNAME记录说明`1.2.0.192.in-addr.arpa`是`1.1-6.2.0.192.in-addr.arpa`的别名。（其他记录类似。网络和广播地址0和7没有CNAME记录，因为它们不需要解析。）解析器已经知道如何在解析名称时跟踪CNAME别名。当它们询问`1-6`域名时，它们会找到之前定义的NS记录，并继续通过询问关于`1.1-6.2.0.192.in-addr.arpa`的名称服务器来完成查询。

因此，你必须为`1-6.2.0.192.in-addr.arpa`设置一个区域文件。除了特殊的名称外，这个区域文件在各个方面都与之前设置的反向区域相似，并且应包含六条PTR记录（除了SOA和NS记录）。请注意，你也将`192.0.2.96` (`ns2`)设置为反向区域的从服务器，因此管理员必须在`named.conf`中为它添加合适的区域声明。

> **注意**
>
> 请记住，在现实世界中，你可能需要等待数月才能让你的ISP正确设置反向委派，在此之前，你的反向区域仍然是损坏的。

### 注册域名

你现在拥有一个可用的DNS设置，但外部解析器看不到它，因为从根名称服务器到你的服务器之间没有委派链。你需要通过注册域名来创建这条链；也就是说，向被称为*注册商*的机构支付相应的注册费用，然后该机构将所选区域的权威权限委派给你的名称服务器。

注册商所做的工作并没有什么神秘之处。它对DNS数据库的某一部分（例如`com`顶级域名[TLD]）拥有权威权限，并且收费后将子域（`example.com`）的权威权限委派给你。这种委派是通过之前解释的委派`foo.example.com`的相同机制来实现的。

网站`http://www.iana.org/domain-names.htm`包含所有TLD和相应注册商（现在有几个）的列表。注册域名的程序和费用在不同注册商之间差异很大。访问相关注册商的网站并按照其中概述的程序进行操作。在解决了所需数量的繁琐手续后，你的域名应该会对世界其他地方可见。

祝贺！你作为DNS管理员的工作才刚刚开始。
