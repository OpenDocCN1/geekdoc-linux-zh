
这一原则讨论的是计算中的小工具或组件方法。虽然微软的 OLE 和 ActiveX 等技术也是组件方法，但它们在一个重要方面上有所不同。Unix 组件应由用户进行操纵和整合。微软极力隐藏组件存在的事实，而 Unix 的方法是告知用户组件的存在，并鼓励他们充分利用这些组件。Windows 的组件方法反映了一种错误的观念，即用户害怕计算机，不应该让他们暴露在计算机的内部机制面前。

## 原则 4：选择可移植性而非效率

之所以被称为“温特尔”（Wintel）垄断是有原因的。多年来，各种 Microsoft Windows 操作系统与 Intel x86 CPU 路线紧密结合。为了让其不断增长的 GUI 高效运行，微软需要与 Intel 硬件保持密切耦合。随着 Windows NT 的引入，微软终于看到了可移植性的价值。NT 运行在四种架构上：Intel x86、DEC Alpha、MIPS R4400 和 Motorola PowerPC。然而，Windows XP 却是一个巨大的倒退，仅运行在 Intel x86 架构上，而 Linux 则运行在今天所有可用的架构上。微软真的学会了可移植性的价值吗？如果 Windows XP 能代表这一点，很难。

## 原则 5：将数据存储在扁平文本文件中

微软在这个领域得分不及格。虽然某些系统配置文件以 ASCII 文本形式存储，但很大程度上世界仍然推崇和喜爱二进制文件隐藏性的世界。例如，Windows 将关键配置信息存储在注册表中，这是一种易于损坏的二进制格式。各种开源倡议的推动者（如自由软件基金会的理查德·斯托曼）正确地批评了微软在 Microsoft Word、Excel 和其他应用程序中坚持使用二进制文件格式。文件格式的趋势显然是所有领域都转向某种形式的（可扩展标记语言）XML，这是一种基于文本的格式。在写作时，微软计划将 Office 二进制文件更改为 XML。另一方面，基于 Linux 的办公工具已经基于 XML 多年。

## 第 9 原则：让每个程序都成为过滤器

这对于整个 Windows 世界来说是一个陌生的概念。那种方法倾向于“让我们构建一个拥有数以万计功能的巨型程序，只要我们营销得足够巧妙，它就会大卖。”你可以通过销售这类产品建立一个庞大的软件集团，但仍然无法走上正轨。像 Microsoft Outlook 这样的应用程序与其他程序的界面交互并不良好，因为开发者并没有从“程序即过滤器”的角度来思考。将此与我们之前讨论的 MH 邮件处理器进行对比。MH 也拥有一套全面的功能。但用户和开发者可以轻松地为 MH 套件添加新组件，而 Outlook 是一个庞大但局限的环境。Outlook 的开发者能想出多少功能并不重要。他们仍然受限，因为他们只是 Outlook 的开发者。世界的其他部分也有自己的想法。

当你把程序视为过滤器时，你倾向于编写保持开放增强性的软件，这种增强不仅可以来自你和你的公司，也可以来自那些对事物有和你不同观点的人。通过这种方式，你的工作被他人利用了，正如你利用了他们的工作一样。

## 大教堂？何其荒诞？

Linux 能够在众多国家中占据一席之地，主要因为它具备了与任何事物建立连接并与之交互的能力。

这正是开源软件（OSS）蓬勃发展的原因。它可以被任何人用来与任何其他事物连接。这种现象得益于开放性：开放标准、开放协议、开放文件格式、一切开放。在开源世界中，没有什么是隐藏的。这种开放性使得软件开发者能够看到前人是如何操作的。如果他们喜欢前人的做法并可以使用，那太棒了。他们发现了一个实用的工具，并为自己节省了时间。如果没有，他们至少可以自由查看过去的错误并对其进行改进。
