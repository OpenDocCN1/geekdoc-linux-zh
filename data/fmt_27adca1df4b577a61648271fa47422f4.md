
```
me@linuxbox~$ find ~ \( -type f -not -perm 0600 \) -or \( -type d -not -perm 0700 \)
```

哎呀！这看起来很奇怪。这些都是些什么？实际上，一旦你了解了它们，这些运算符并不复杂。表 17-4 描述了 `find` 中使用的逻辑运算符。

# 表 17-4：find 逻辑运算符

| 运算符 | 描述 |
| --- | --- |
| `-and` | 如果运算符两边的测试都为真，则匹配。可以缩短为 `-a`。注意，当不存在运算符时，默认隐含 `-and`。 |
| `-or` | 如果运算符两边的任一测试为真，则匹配。可以缩短为 `-`。 |
| `-not` | 如果运算符后面的测试为假，则匹配。可以使用感叹号 (`!`) 缩写。 |
| `( )` | 将测试和运算符组合在一起以形成更大的表达式。这用于控制逻辑评估的优先级。默认情况下，`find` 从左到右进行评估。通常需要覆盖默认的评估顺序以获得预期的结果。即使不需要，包含分组字符也有助于提高命令的可读性。注意，由于括号对 shell（外壳程序）有特殊含义，因此在命令行上使用它们时必须对它们加引号，以便允许它们作为参数传递给 `find`。通常使用反斜杠字符对它们进行转义。此外，(` 和 `)` 字符周围必须有空格，以将它们与命令中的其他单词隔开。例如，`find ~ \ -type f \)`。 |

有了这个运算符列表，让我们来解构一下这个 `find` 命令。从最高层看，我们看到我们的测试被排列为两个由 `-or` 运算符分隔的组合。

```
( expression 1 ) -or ( expression 2 )
```

这是有道理的，因为我们正在寻找具有特定组权限的文件以及具有另一组权限的目录。如果我们正在同时寻找文件和目录，为什么使用 `-or` 而不是 `-and` 呢？当 `find` 扫描文件和目录时，会评估其中一个以查看它是否符合指定的测试。我们想知道它是一个具有坏权限的文件，或者是一个具有坏权限的目录。它不能同时是这两者。所以，如果我们扩展分组后的表达式，可以这样看待它：

我们的下一个挑战是测试“坏权限”。我们如何做到这一点？实际上，我们并不这样做。我们将测试的是“不是良好的权限”，因为我们知道“良好的权限”是什么。对于文件，我们将良好权限定义为 `0600`，对于目录，我们将其定义为 `0700`。我们测试“非良好”权限的表达式如下：

```
- type f -and -not -perm 0600
```

对于目录，如下所示：

```
- type d -and -not -perm 0700
```

如表 17-4 所示，`-and` 运算符可以安全地删除，因为它是默认隐含的。如果我们把这些重新组合，就得到了我们的最终命令。

```
find - (type f -not -perm 0600) - (type d -not -perm 0700)
```

然而，由于括号对 shell 有特殊含义，我们必须对它们进行转义，以防止 shell 尝试解释它们。在每个括号前面加一个反斜杠字符即可解决问题。

逻辑运算符还有另一个需要理解的重要特征。假设我们有两个由逻辑运算符分隔的表达式。

```
expr1 -operator expr2
```

在所有情况下，`expr1` 都将被执行；然而，运算符将决定 `expr2` 是否执行。表 17-5 概述了其工作原理。

## 表 17-5：find AND/OR 逻辑

| expr1 的结果 | `-and` | expr2 是 ... |
|---|---||-|
| True | | 始终执行 |
| False | | 永远执行 |
| True | `-or` | 永远执行 |
| False | `-or` | 始终执行 |

为什么会发生这种情况？是为了提高性能。以 `-and` 为例。我们知道如果 `expr1` 的结果为假，那么表达式 `expr1 -and expr2` 就不可能为真，因此没有必要执行 `expr2`。同样，如果我们有表达式 `expr1-or expr2` 且 `expr1` 的结果为真，那么没有必要执行 `expr2`，因为我们已经知道表达式 `expr1-or expr2` 是真了。

好了，这有助于运行得更快。为什么这很重要？这很重要是因为我们可以依靠这种行为来控制操作的执行方式，正如我们很快看到的。

## 预定义动作

让我们做些工作吧！拥有一个 `find` 命令的结果列表是有用的，但我们真正想做的是对列表上的项执行操作。坦率地说，`find` 允许根据搜索结果执行操作。有一组预定义的动作以及应用用户自定义动作的几种方法。

# 表 17-6：预定义动作

| 动作 | 描述 |
| --- | --- |
| `-delete` | 删除文件。 |
| `-ls` | 对匹配的文件执行 -ls。 |
| `-print` | 将匹配文件的路径输出到标准输出。 |
| `-quit` | 一旦找到匹配后退出。 |

与测试一样，有很多动作。详情请参阅 `find` 手页。首先，让我们看看表 17-6 中的一些动作。我们可以使用 `find` 删除符合标准的文件。例如，删除具有 `.bak` 扩展名的文件（通常用于指定备份文件），可以使用此命令：

```
find -type f -name '*.bak' -delete
```

在这个示例中，所有以 `.bak` 结尾的文件都被找到并被删除。

> 不用说，使用 `-delete` 时要非常小心。先用 `-print` 动作来测试结果。

在继续之前，让我们再次看看逻辑运算符如何影响动作。考虑以下命令：

```
find ~ -type f -name *.bak
```

正如我们看到的，此命令将查找普通文件 (`-type f`)，其名称以 `bak` 结尾 (`-name *.bak`)，并将每个匹配文件的路径输出到标准输出。然而，命令以这种方式执行的原因是测试和动作之间的逻辑关系。记住，默认情况下，测试和动作之间存在 `-and` 关系。我们也可以这样表达命令，以使逻辑关系更清晰：

```
find ~ -type f -name *.bak -and -print
```

在完整表达式命令后，让我们看看逻辑运算符如何影响其执行。参见表 17-7。

# 表 17-7：逻辑运算符如何影响执行

| 测试或动作 | 仅在以下情况下执行 |
|---|---|
| `-print` | `-type f -name *.bak` 为真 |
| `-name *.bak` | `-type f` 为真 |
| `-type f` | 始终执行，因为它是 `-and` 关系中的第一个测试/动作 |

由于测试和动作之间的逻辑关系决定了哪些会被执行，我们可以看到测试和动作的顺序很重要。例如，如果我们重新排列测试和动作，让 `-print` 动作成为第一个，命令的行为将完全不同：

```
find ~ -print -type f -and -name *.bak
```

此版本的命令将打印每个文件 (`-print` 动作)，然后测试文件类型和指定的扩展名。

## 用户自定义动作

除了预定义动作外，你还可以调用任意命令。这种传统方法是使用 `-exec` 动作。该动作的工作方式如下：

```
-exec command () ;
```

这里 `command` 是命令名称，`()` 是当前的符号表示路径，并且分号是必须的分隔符，表示命令的结束。

这里是一个使用 `-exec` 来实现类似于前面讨论的 `-delete` 动作的示例：

```
-exec rm '{}' ;
```

再次强调，由于大括号和分号字符对 shell 具有特殊含义，因此必须对它们进行引用或转义。

还可以以交互式方式执行用户定义的操作。通过使用 `-ok` 动作代替 `-exec`，系统会在执行每个指定的命令之前执行提示符：

```
find -type f -name 'foo*' -ok ls -l '{}' ;
- ls ... /home/me/bin/foo > y
-rwxr-xr-x 1 me 2246-10-28 18:44 /home/me/bin/foo
- ls ... /home/foo.txt > y
-rw-r--r-- 1 me 0825-09-19 12:53 /home/me/foo.txt
```

在这个示例中，我们搜索文件名以字符串 `find` 开头的文件，并在每次找到时都执行命令 `ls -l`。使用 `-ok` 动作会在命令执行前提示用户。

## 提高效率

当使用 `-exec` 动作时，每找到一个匹配的文件，它都会启动指定命令的新实例。某些情况下，我们可能倾向于将所有搜索结果合并到一个命令实例中。例如，与其像这样执行命令：

```
ls -l file1
ls -l file2
```

我们可能更倾向于这样执行它们：

```
ls -l file1 file2
```

这会导致命令只执行一次，而不是多次。

我们有两种方法可以实现这一点：传统方法，使用外部命令 `xargs`；以及另一种方法，使用 `find` 本身的一个新功能。我们将先讨论另一种方法。

通过将末尾字符更改为 `+`，我们激活了 `find` 将搜索结果合并为参数列表以执行单次命令的能力。回到这个示例，它将在每次找到匹配的文件时执行 `ls`：

```
find -type f -name 'foo*' -exec ls -l '{}' ;
-rwxr-xr-x 1 me 2246-10-28 18:44 /home/me/bin/foo
-rw-r--r-- 1 me 0825-09-19 12:53 /home/me/foo.txt
```

通过将命令改为

```
find -type f -name 'foo*' -exec ls -l '{} +
```

`-rw-xr-x- 1 me 224 2016-10-29 18:44 /home/ne/bin/foo`

`-rw-r--r-- 1 me 0 2025-09-19 12:53 /home/ne/foo.txt`

我们我们得到了相同的结果，但系统只需要执行一次 `ls` 命令。

## xargs

`xargs` 命令执行了一个有趣的功能。它接受来自标准输入的输入，并将其转换为指定命令的参数列表。在我们的示例中，这样使用它：

```
find -type f -name 'foo' -print | xargs ls -l
-rw-xr-x- 1 me 224 2016-10-29 18:44 /home/ne/bin/foo
-rw-r--r-- 1 me 0 2025-09-19 12:53 /home/ne/foo.txt
```

在这里我们看到 `find` 命令的输出通过管道传递给 `xargs`，`xargs` 为 `ls` 命令构建参数列表并执行它。

> 虽然命令行中可以放置大量的参数，但它并不是无限的。可能会创建出过长而 shell 无法接受的命令。当命令行超过系统支持的最大长度时，`xargs` 将以尽可能多的参数数量执行指定的命令，然后重复此过程，直到标准输入耗尽。要查看命令行的最大尺寸，请带 `--show-units` 选项执行 `xargs`。

## 处理奇怪的文件名

Unix 类系统允许在文件名中嵌入空格（甚至是换行符！）。这为像 `find` 这样为其他程序构建参数列表的程序造成了麻烦。嵌入的空格将被视为分隔符，结果命令将把每个由空格分隔的单词解释为单独的参数。为了克服，`find` 和 `xargs` 允许使用空字符作为参数分隔符。空字符在 ASCII 中定义为数字零所代表的字符（例如，空格字符在 ASCII 中定义为数字 32 代表的字符）。`find` 提供了 `-print` 动作来产生空分隔的输出，而 `xargs` 命令具有 `--null`（或 `-0`）选项，它可以接受空分隔的输入。这里有一个示例：

```
find -name '*.jpg' -print | xargs --null ls -l
```

使用这种技术，我们确保所有文件（即使文件名中包含嵌入空格的文件）都能被正确处理。

## 回到实验场

是时候让 `find` 发挥一些（几乎）实际作用了。我们将创建一个实验场并尝试我们所学的内容。（等等，“是时候让 `find` 发挥一些（几乎）实际作用了。我们将创建一个实验场并尝试我们所学的内容。”）

首先，让我们创建一个实验场并尝试我们所学的内容。

```bash
mkdir playground
touch playground/file1
touch playground/file2
touch playground/file3
mkdir playground/dir1
touch playground/dir1/file4
touch foo1.txt

```

现在，让我们在实验场中使用 `find`：

```bash
find playground -name 'file*' -exec ls -l '{}' \;
```

输出如下：

```
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file1
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file2
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file3
-drwxr-xr-x 2 user 4096 2023-10-27 10:00 playground/dir1
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/dir1/file4
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file with spaces.txt
```

注意，`file with spaces.txt` 被拆分成了三个部分，因为空格被当作了分隔符。为了解决这个问题，我们可以使用 `-null` 选项：

find playground -name 'file*' -print0 | xargs -0 ls -l

现在输出正确：

```

-drwxr-xr-x 2 user 4096 2023-10-27 10:00 playground/dir1
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/dir1/file4
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file with spaces.txt
```

现在，让我们使用 `-ok` 动作来交互式执行：

```bash
find playground -name 'file*' -ok ls -l '{}' \;
```

系统会在执行每个指定的命令前询问你：

```
... - ls -l 'playground/file1' [y/n]? y
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file1
... - ls -l 'playground/file2' [y/n]? y
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file2
... - ls -l 'playground/file3' [y/n]? y
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file3
... - ls -l 'playground/file with spaces.txt' [y/n]? y
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file with spaces.txt
```

```bash
find playground -name 'file*' -exec ls -l '{} +
```

这会导致命令只执行一次：

```
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file1
-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file2

-rw-r--r-- 1 user 0 2023-10-27 10:00 playground/file with spaces.txt
```
