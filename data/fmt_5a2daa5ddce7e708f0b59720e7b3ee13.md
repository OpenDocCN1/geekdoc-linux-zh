
SNMP（简单网络管理协议）的设计是为了让异构系统和设备相互通信、报告数据并允许在 TCP/IP 网络上对其设置进行修改。例如，启用 SNMP 的设备（如 路由器）可以从 SNMP 客户端进行监控/配置，你可以轻松编写脚本在拒绝的数据包/秒数超过 20 时提醒你。遗憾的是，SNMP 没有内置安全功能。`SNMPv1` 最初在 `RFC 1157`（1990年5月）中提出，其第 8 节（安全考虑）读起来确实是：“本备录中没有讨论安全性。”我认为这已经说明了问题。1992/1993 年发布了 `SNMPv2`，并包含了安全考虑，但这些安全考虑在随后被证明完全破解后后被丢弃了。我们最终留下了 `SNMPv2` 而没有安全性。保护你的 SNMP 设备的唯一方法是将社区名称设置为难以破解的内容（但很容易通过嗅探线缆并找到该名称）。

## Finger

`Finger` 是大多数管理员都会禁用并忽略的服务之一。它在某些情况下是有用的工具，但如果你想让其他管理员找出你的哪些用户当前正尝试破解他们的机器，应该使用 `ident`。`Finger` 泄露的信息过多，是目标进行初始探测和数据收集的常用工具。目前还出现过几次极其恶劣的 DOS 攻击，基本上是通过发送数百个 `finger` 请求，并在某些配置下利用服务器漏洞。请不要运行 `finger`。许多发行版默认开启了它，但引用 RedHat 的 `inetd` 描述：

```
### Finger, systat and netstat 给出的信息可能对
### 潜在的“系统破解者”有用。许多站点选择禁用
### 部分或全部这些服务以提高安全性。
```

如果你仍然非常想运行它，请使用 `-u` 来拒绝 `finger @host` 请求，这些请求从未被用于为未来的攻击收集信息。真的请禁用 `finger` 吧。`Finger` 还导致了最近几次非常严重的拒绝服务攻击，特别是当你运行带有大型映射的 NIS 时，不要，重复一遍，**不要**运行 `finger`。`Cfingerd`（可配置的 `finger`）是原生 `finger` 的绝佳替代方案，它在设计时考虑了安全性，以非 root 用户运行，并可以轻松配置使其无法被 `finger` 查询。可以从此处获取 `cfingerd`：http://ftp.bitgate.com/cfingerd/。`Finger` 运行在端口 79，而 `cfingerd` 运行在端口 2003，两者都使用 tcp。

```
ipfwadm -I -a accept -P tcp -S 10.0.0.0/8 -D 0.0.0.0/0 79
ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 79
ipfwadm -I -a deny -P tcp -S 0.0.0.0/0 -D 0.0.0.0/0 79
```

或者

```
ipchains -A input -p tcp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 79
ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 79
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 79
```

## Identd

`Identd` 服务用于将用户/进程映射到输入端口。例如，源服务器尝试通过进行 `ident` 查找来找出是谁连接到了它们的，这基本上是询问 `ident` 关于某个端口号的信息，信息范围从无所获（如果没有人使用该特定端口）到用户名、组名、进程 ID（PID）以及其他感兴趣的信息。许多发行版的默认设置是 `identd` 开启（可以运行它，且较新版本会发送较小的 `ident` 响应），并且仅提供用户名。`ident` 的主要用途是通过追踪连接到其服务器的用户来允许远程系统访问，包括 `telnet`、邮件或，或者用于身份验证目的（这不是个好主意，因为非常容易伪造）。埃德蒙顿的当地大学如果你想 `telnet` 进入任何一个主服务器，就需要运行 `identd`，主要是为了让他们能够快速追踪到被破解的账户。`Identd` 是一个实用的工具，但通常在机器上它是一把双刃剑，虽然它提供了追踪攻击者（无疑是你想要从服务器上踢出去的人）的信息，但它也被用于获取有关你系统的信息，导致他们的账户被破解。我建议在带有账户`/etc` 的服务器上运行 `identd`。

`Identd` 支持一些功能，并可以轻松设置为以非 root 用户运行。根据你的安全策略，你可能不想提供太多信息，或者你可能提供尽可能多的信息。只需在 `inet.conf` 中 `identd` 之后添加选项即可（默认是 `-l -e`）。

```
-p port
- address
```

可以用于指定它绑定的端口和地址（对于具有 IP 别名或多个接口的机器），这通常只在你希望机器进行连接时才有用，因为外部机器可能无法查出你更改了哪个端口。

```
-u uid
-g gid
```

用于设置 `identd` 在连接到端口后将降权的用户和组 ID，这将使其更不容易受到破坏系统安全的威胁。至于处理它提供的信息量：

```
-o
```

指定 `identd` 不返回操作系统类型，而是简单地显示 "UNKNOWN"，这是一个非常好的选项。

```
-n
```

让 `identd` 返回用户数字（即 UID）而不是用户名，这仍然提供了足够的信息让你识别并允许你轻松追踪该用户，而不会给潜在的攻击者提供价值价值线索。

```
-N
```

允许你创建一个 `/.nident` 文件，这将强制 `identd` 返回 "HIDDEN-USER" 而不是信息。

```
-F format
```

允许你指定比标准多得的信息，从用户名和数字到实际的 PID、命令名、以及提供的命令名称和参数！我建议在内部使用，因为这些对于攻击者来说可能是非常有用的大量信息。

总来说，我建议禁用 `identd`，主要是由于它容易受到许多拒绝服务攻击。只有当你想要方便其他管理员的生活（即追踪你的哪些用户是坏人）时，才应该运行它。不过，还有其他带有安全增强 `identd` 版本（我尚未测试过这些）：

http://insecurity.net/ - Paul 写的 secure identd

http://www.ojnk.nu/~ident/ - ojn identd

http://www.tildes/null.html - null identd

http://www.ajk.tele/~too/ - fake identd

http://pur.het.net/ - midident

`Identd` 运行在端口 113，使用 tcp，通常在你需要 IRC（许多网络需要 ident 响应）或运行守护进程（如 tcp_wrapped `telnet` 或 `sendmail`）时才需要它。

```
ipfwadm -I -a accept -P tcp -S 10.0.0.0/8 -D 0.0.0.0/0 113
ipfwadm -I -a accept -P tcp -S some.trusted.host -D 0.0.0.0/0 113
ipfwadm -I -a deny -P tcp -S 0.0.0.0/0 -D 0.0.0.0/0 113
```

或者

```
ipchains -A input -p tcp -j ACCEPT -s 10.0.0.0/8 -d 0.0.0.0/0 113
ipchains -A input -p tcp -j ACCEPT -s some.trusted.host -d 0.0.0.0/0 113
ipchains -A input -p tcp -j DENY -s 0.0.0.0/0 -d 0.0.0.0/0 113
```

## ntpd

`NTP`（网络时间协议）的任务相当简单，就是为了保持时钟同步。如果不同服务器的时间相差几分钟，尝试比较它们。`NTP` 工作原理是客户端连接到时间服务器，获取时间并设置时钟（在局域网内可能只有 1-2ms，跨越互联网可能是几毫秒），此外，服务器可以“聚类”以保持同步，三个或更多服务器丢失时间的概率（也称为 "drift"）相对较低。时间信号通常由原子钟或 GPS 信号产生，这些是 "stratum 1" 服务器，它们的下方是公开访问的 stratum 2 服务器，公司如果有足够的调整，可能会拥有自己的 stratum 3 服务器，以此类推。数据非常敏感，如果攻击者能够篡改各种数据，可能会导致不可用，账户可能会提前过期。因此，一个主意是运行你的时间服务器（它们只会产生几秒的偏移，不应该太大）。如果你有大量的客户端，考虑购买一个各种形状和尺寸的 GPS 时间单元，直接插入服务器的 PCI 卡。为你的时间服务器设置防火墙是一个主意，因为拒绝服务攻击会对你的网络产生危害。此外，如果可能，使用 DES 加密通常足以阻止大多数攻击者。关于 `ntpd` 或 `xntpd`（有详细文档）的帮助可以在 `/usr/doc/` 找到，或访问：http://www.udel.edu/~ntpd/spool/index.htm。`NTP` 运行在端口 123，使用 udp，对其进行防火相对简单：
