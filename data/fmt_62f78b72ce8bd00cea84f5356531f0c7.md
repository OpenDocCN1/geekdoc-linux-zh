
尽管在存储容量方面不具备竞争力，但 Iomega Zip 和 SyQuest 等磁盘在 Linux 用户中仍有一些应用。通常，这类类似于更大更厚的软盘的磁盘，容量在 100 到 1,000 兆字节之间。其成本每单元在 10 美元到 50 美元之间。对于大多数只需保存有限信息的用户来说，这类磁盘是经济实惠的。大多数用户使用 Zip 磁盘在计算机之间穿梭传输较大的文件。在 Linux 下，您必须先挂载 Zip 磁盘才能访问其内容以及向其写入数据。

有些人现在认为，Zip 驱动器和软盘驱动器与 CD-ROM 甚至磁带驱动器不同，现在已经过时。它们需要特殊的硬件和驱动程序，并且相对于它们实际能备份的数据量而言，价格仍然太贵。但为其辩护的是，Zip 磁盘的可移动部件较少，比磁带驱动器更不容易磨损。它们的构建组件与软盘非常相似，因此根据对其的保养程度，具有相对较长的使用寿命。对于较小的系统或在 Linux 用于工作站环境的地方，Zip 磁盘是完成小型备份的廉价且有效的手段。目前，某些预装 PC 已经标配了此类硬件和磁盘。

## 备份到软盘

与 Zip 磁盘一样，新型软盘正出现在市场上。这些新软盘每个容量在 120 到 200 兆字节之间。如果它们被广泛接受，并且 Linux 社区接受这些驱动器作为临时归档数据的手段，那么软盘或许能作为一种存储介质生存下来。最新的内核提供了对这类软盘的支持。它们仍有一些缺点：媒体读写速度缓慢，成本高，且货架寿命不超过几年。您可能不应将软盘，无论是 1.44 还是 100 兆字节的，视为可行的长期存储介质。

## 备份到可写和可重写 CD

另一种备份介质是可写和可重写 CD。在过去几年中，这些类型的 CD 播放器及其介质本身变得便宜得多。在成本和速度方面都迅速接近普通 CD-ROM，一台优质的可重写 CD 播放器现在可以以不到 200 美元的价格购得。平均单位现在写入或刻录磁盘时可以达到四倍或八倍速，大多数现在可以以大约 20 倍速从标准 CD-ROM 读取信息。CD-R 和 CD-RW 的区别既在于使用的 CD 类型，也在于其存储数据的方式。

CD-R 价格便宜且供应充足。您可以以低于一美元的价格购买一张空白 CD-R，并实际上将数据刻录到 CD 上。播放器内的激光在 CD 表面刻出凹槽，从而成为数据的永久记录。一旦数据刻录在 CD 上，就不能更改或修改。这些数据可以创建长达 20 年或更久的持久记录，尽管可以怀疑未来那么远的地方是否还会以相同的格式访问这些数据。这种介质适用于保存您预期保持静态或不经常更新的网页、程序或文件的记录。

CD-R 的质量也有差异。三种标准颜色代表 CD-R 的质量等级。最低端是蓝色 CD-R，然后是银色 CD-R，最后是金色版本。这些 CD-R 之间的区别在于其质量、预期寿命以及在高速刻录机下的性能。据称金色 CD-R 具有更长的使用寿命，更能抵抗划痕和错误。它们还具有更好的数据保持能力，不太容易因不良烧录而变成“杯垫”。如果待备份的数据需要较长的货架寿命，那么金色 CD-R 可能是首选介质。由于大多数数据持续更新，选择更便宜的介质肯定更经济。很可能数据会在 CD-R 之前过期。

如果要备份的数据量很少，CD-R 可以重复使用，在每次备份后关闭当前会话，下次打开新会话。最终，全部 650 兆字节的可用空间将被消耗；随后，该 CD-R 仅适用于检索方法。此外，在 CD-R 上存储需要特定读取、写入或执行权限的数据也不是一件好事。与其对应物 CD-ROM 一样，刻录在 CD-R 上的数据变为只读。写入和执行权限丢失。您可以恢复或重置磁盘驱动器上的先前权限，但此过程可能很繁琐。如果您希望将数据归档到 tar 包和 zip 压缩文件中，则可以将整个文件放置在 CD-R 磁盘上，当稍后解压时，它将保留先前的权限。这确实要求您先在本地将所有备份文件打包并压缩，然后保存到介质上。此外，它们的尺寸不能大于 650 兆字节。然而，对于备份大量数据的系统，CD-R 并非最佳方法。

CD-RW 磁盘具有某种程度的多功能性。由于使 CD-RW 磁盘可访问所涉及的格式化过程，它们可以存储约 500 兆字节的数据，并且还可以保持与原始数据相同的权限。磁盘本身稍贵，每个价格在 2 美元到 10 美元之间，但可以重复使用多次。就像软盘一样，如果您想在一段时间重新开始，可以将它们彻底擦除。较新的 CD-RW 技术似乎远优于 Zip 磁盘，因为后者在开发和性能方面都被认为已停滞不前。Linux 正在快速增加对 CD-RW 播放器以及用于刻录和保存数据的技术的软件和硬件支持。随着 CD-RW 刻录机变得更加流行，Linux 继续向更好地支持 CD-RW 刻录机迈进，鉴于它们在一台计算机与另一台计算机之间移动时的便利性，以及 CD-RW 介质的成本效益，预计它们也将成为家庭和办公用途备份协议的标准。

CD-RW 的问题之一是它们相当慢。由于其写入速度无法接近硬盘，您有时可能会使用 CD-RW 将数据备份到本地机器。或者，如果 CD-RW 已经连接到你要备份的机器上，可能需要花费更多的时间和系统资源来完成 CD-RW 的任务。SCSI CD-RW 刻录机速度更快且更可靠，而外部 CD-RW 刻录机使用并行端口传输数据，价格更便宜且更容易产生废盘。新的 USB CD-RW 数据也值得信赖，但在 2.4.x 内核稳定且 USB 驱动程序支持完全集成之前，你最好的选择是内部 SCSI CD-RW。

另一个需要考虑的方面是，操作 CD-RW 刻录机所需的软件在 Linux 上仍处于开发阶段。Windows 已有更成熟的程序可用。然而，我个人使用 `mkisofs` 和 `cdrecord` 创建可刻录镜像，然后将数据刻录到 CD 上。它们能很好地完成任务，尽管对于一些用户来说学习曲线可能相当陡峭。它们都是基于命令行的，但快速浏览 `freshmeat.net` 等 Linux 软件网站应该会找到这两个实用程序的几个图形用户界面前端。关于使用 `mkisofs` 和 `cdrecord` 将数据刻录到 CD-R 上的更多信息，请参见本章后面的“将数据或音频文件刻录到 CD 上”部分。

有些人更喜欢将 Linux 机器映射到 Windows 机器，并以此方式备份文件。`Samba` 非常出色地完成这项任务。`NFS` 在将 Linux 分区挂载到其他 Linux 机器时也会执行远程挂载。或者，仅使用 `FTP` 实用程序也能同样出色地完成这项任务。然而，如果使用 `FTP`，你要么需要在 Windows 机器上运行某种 FTP 守护程序，要么直接坐在 Windows 机器前并在其上执行下载。这两种选择对于声称不喜欢其他系统的普通 Linux 用户来说都缺乏吸引力。`Samba` 和 `NFS` 在第 15 章“Linux 网络”和第 16 章“互联网连接”中有更详细的介绍。

## 备份到内部硬盘

如前所述，数据可以写入或读取硬盘，无论是本地硬盘还是外部硬盘。如果硬盘位于服务器本身，你应当注意在硬件故障的情况下仍能够检索数据。验证硬盘是否可以与其他机器互换可能是一个值得考虑的问题，因为 Linux 通常会在遇到新硬件时发出抗议，特别是在以不同于其习惯的配置启动时。你可以在机器中安装额外的硬盘，并将该硬盘用于存储目的。如果主硬盘故障，你可能仍然能够将备用磁盘挂载到另一系统或同一台装有新硬盘的计算机上。正如前两章所解释的，将分区分散到多个物理硬盘上是一个值得采取的预防措施。

### 使用 RAID 阵列

RAID 阵列尽管对于大多数用途来说仍然成本较高，但却是企业的偏好。使用 RAID，根据你决定使用的级别，你可以组织多个硬盘来执行镜像任务，并能在主硬盘崩溃或流量增加时即时接管主硬盘的主要功能。RAID 阵列昂贵的原因之一是所需的硬件。大多数 RAID 阵列需要 SCSI 硬盘，其价格通常是普通 IDE 硬盘的两倍。如果你使用专有硬件，该成本容易翻三到四倍。但许多人认为 RAID 阵列物有所值。

有一些较新的技术可以使用 IDE 硬盘提供 RAID 性能，例如 `Promise Technologies` 提供的技术。此外，最新的 Linux 内核也支持基于软件的 RAID，因此你可以配置 IDE 硬盘以提供接近 SCSI 的性能。使用普通 IDE 硬盘并优化基于内核的软件时，这里的成本远低于 SCSI。

市场上有支持 Linux 的新系统，提供接近 SCSI 硬盘的速度，但不需要 SCSI 硬盘。诸如 `Can of RAID` 和 `RAIDZONE` 制造的产品具有诸如 `Ultra DMA-66 IDE` 硬盘等硬件，以 7,200 rpm 运行，几乎等同于旧式 SCSI 设备，并具备在多个硬盘之间条带化信息的能力。如果某件硬件故障，你可以快速用当地电脑店购买的部件进行替换。不会丢失任何数据，因为信息也存储在其他硬盘上。我在办公室使用 `Can of RAID` 设备用于数据库，它在 Linux 下表现 exceptionally 良好。

对于 `RAID-5`，不需要手动执行备份，但不能说 RAID 级别 0、1 和 2 也是如此。大部分归档工作都是自动完成的，对管理者和用户都是透明的。系统可以配置几个简单的脚本来执行任何附加任务或特定系统任务，如备份、镜像驱动器、恢复文件和执行搜索。

## 组织备份

备份可以不同程度执行。最全面的备份类型之一是完整备份。这正如名称所暗示的：存储介质上每个文件的完整备份。无论自上次备份以来发生了任何更改或修改，完整备份都会复制所有文件，不管自上次备份以来所做的任何更改或修改。
