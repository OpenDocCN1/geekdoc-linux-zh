当你做出选择时，`alternatives`会更改每个服务的相应运行级别脚本，这可以通过以下命令确认：

```

```

```

`alternatives`命令本身不会停止或启动服务。如果你之前没有停止原始服务，守护进程仍在运行。在这种情况下，你必须使用第9章中描述的`kill`命令来终止不需要的SMTP服务。而且系统上只能运行一个SMTP服务。`sendmail`和`Postfix`之间的交互会导致错误。

此外，你必须使用`/etc/init.d`目录中的相应脚本（`sendmail`或`postfix`）来启动所需的SMTP服务。

## 通用用户安全

默认情况下，所有用户都允许在无需密码的情况下使用本地配置的SMTP服务。你将在本章后面的适当部分看到如何为`Postfix`和`sendmail`更改此设置。本节假设已配置适当的限制。

在某些情况下，你可能只想设置本地用户以便他们可以访问此类服务。如果你不希望此类用户使用常规账户登录服务器，一个选择是确保此类用户没有登录shell。例如，以下命令可以在本地系统上创建一个名为`tempworker`的用户且不带登录shell：

```
# useradd tempworker -s /sbin/nologin
```

该`tempworker`用户随后可以设置自己的电子邮件管理器，如`Evolution`、`Thunderbird`，甚至`Outlook Express`，以连接到网络化的`Postfix`或`sendmail`SMTP服务。该用户任何直接登录服务器的尝试都会被拒绝。

当然，访问仅限于已配置的用户，无论其账户是否配置了登录shell。这由简单身份验证和安全层（SASL）配置。作为RHEL 6的实现，它基于`cyrus-sasl`软件包，如`/etc/sasl2`目录中配置的。虽然该目录可能包含`Postfix`（`smtp.conf`）和`sendmail`（`Sendmail.conf`，是的，那是大写S）的不同配置文件，但两个配置文件都引用回相同的身份验证方案，使用以下指令：

```
pwcheck_method: saslauthd
```

`/etc/sysconfig/saslauthd`配置文件通过以下指令确认密码检查的标准机制：

```
MECH=pam
```

这是指第10章中描述的可插拔身份验证模块（PAM）。换句话说，配置在本地系统上的用户由`/etc/pam.d`目录中的相关文件控制，即`smtp.postfix`和`smtp.sendmail`。然而，你需要对`Postfix`进行一些更改，才能使其实际读取身份验证数据库。

## 常见安全问题

默认情况下，SMTP服务使用端口25。如果在防火墙上打开端口25，外部用户可能会访问该服务器。如果需要了解如何打开该端口，请参阅第10章。对于基于`iptables`的防火墙，一个选项是基于源IP地址。由于`Postfix`和`sendmail`都是SMTP服务，两者都使用端口25。

要使用防火墙配置工具创建源地址选项，您需要使用自定义规则选项。如图13-1所示，您可以看到从`/usr/share/netcf`目录添加到防火墙配置的自定义文件。

要创建仅支持`192.168.122.0`网络上的系统访问的自定义规则，我已在该文件中包含以下条目：

```
-A INPUT -m state --state NEW -m tcp -p tcp -s 192.168.122.0/24 --dport 25 -j ACCEPT

## 练习 13-1
### 仅为电子邮件创建用户

在此练习中，您将在本地系统上创建三个用户，只是为了让他们能够访问本地SMTP服务器。可以理解的是，需要额外的配置来设置这些用户在`Postfix`或`sendmail`SMTP服务上的访问或限制。这些用户是`mailer1`、`mailer2`和`mailer3`。

- 1. 查看`useradd`命令。识别与默认登录shell关联的开关。
- 2. 查看`/etc/passwd`文件的内容。找到一个与登录无关的shell。它应该是`/sbin/nologin`
- 3. 运行类似`useradd mailer1 -s /sbin/nologin`的命令来添加新用户。确保为该用户分配密码。
- 4. 查看`/etc/passwd`中的结果。
- 5. 对其他所述用户重复步骤3。
- 6. 尝试以普通用户身份登录其中一个新帐户。它应该失败。查看`/var/log/secure`文件中的相关消息。
- 7. 保留新用户。

## 认证目标 13.02
### Postfix 的配置

`Postfix`邮件服务器是管理系统和网络上电子邮件流的一种方式。标准配置文件存储在`/etc/postfix`目录中。可以使用`postconf`命令测试配置。按安装方式，`Postfix`仅接受来自本地系统的电子邮件。设置`Postfix`以接受传入电子邮件并通过智能主机转发电子邮件所需的配置更改相对简单。

`Postfix`配置文件的详细信息包括用户和主机基于的安全选项。如果您已经知道如何为基本操作配置`Postfix`，并且只想了解满足`Postfix`SMTP目标所需的配置，请跳到与`/etc/postfix/access`、接受传入电子邮件和智能主机相关的部分。

### 配置文件

配置文件存储在`/etc/postfix`目录中。主配置文件`main.cf`比`sendmail`替代方案`sendmail.cf`稍微简单一些。它仍然很复杂，因为它包含近700行。

除了`.cf`文件外，任何更改都必须先使用`postmap`命令处理成数据库。例如，如果您已向`access`文件添加了限制，可以使用以下命令将其处理为二进制`access.db`文件：

```
# postmap access
```
