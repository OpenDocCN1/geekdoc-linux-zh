
`nohup` 命令对标准输出有默认重定向。它将消息重定向到命令执行目录下名为 `nohup.out` 的文件中。也就是说，符号 `&` 允许你在后台运行命令。

## `cu` 命令

以下是 `cu` 命令中可以使用的一些标志列表：

- `-d` 用于打印诊断信息。
- `-L` 指定用于通信的设备。默认情况下，UNIX 使用第一个可用设备。你可以使用此标志来重写默认设置。
- `-n` 确认电话号码。如果使用此标志，`cu` 将提示你输入电话号码，而不是将其作为命令行的一部分接收。
- `-s` 指定用于主机间通信的线路速率。线路速率以波特（bauds）为单位，可以是 `300`、`1200`、`2400` 等。在大多数情况下，UNIX 应该能够默认选择正确的速率。
- `-T` 指定超时参数。这是 UNIX 尝试连接到远程主机的时间。

在使用 `cu` 命令时，可以指定以下参数：

字体 系统名称（System Name）：表示你想要连接的系统名称。此名称必须在 `/etc/uucp/Systems` 文件中定义。该文件中还定义了电话号码、线路速率等参数，用于连接到远程主机。如果你使用系统名称，则不应使用 `-i s` 选项。

- 电话号码（Telephone Number）：用于连接到远程主机的电话号码。该号码可以是本地的或长途的。

建立连接后，`cu` 以两个进程运行：发送进程从标准输入读取数据，并对于以 `~`（波浪号）开头的行将数据传递给远程系统；接收进程从远程系统接收数据，并对于以 `~`（波浪号）开头的行将其传递到标准输出。

一旦成功登录远程主机，就可以使用 `cu` 提供的若干子命令。这些子命令允许你在远程主机上对文件、目录等进行操作。

以下是其中子命令的列表（你应该在 `~` 前加反斜杠 `\`，以便 UNIX 不对 `~` 赋予特殊含义）：

- `~` 断开远程主机的连接。
- `~!` 断开远程主机的连接。
- `~` 在本地主机上激活交互式 shell。你可以使用 `~` 和 `Ctrl-d` 在本地和远程主机的交互式 shell 之间切换。也就是说，`~` 让你进入本地主机的 shell，而 `Ctrl-d` 让你返回远程主机。
- `~!` 在本地主机执行命令。
- `~cd 目录` 将本地主机上的目录更改为指定的目录。
- `~put From [ To ]` 将本地系统上的文件复制到远程系统上的文件。如果没有指定 `To` 变量，则本地文件将以相同文件名复制到远程系统。文件的传输进度以主机之间传输的每个块的连续单数字形式传输。只有包含文本（ASCII）的文件可以使用此子命令传输。
- `~take From To` 将远程系统上的文件复制到本地系统上的文件。如果指定了 `To` 变量，则远程文件将以相同文件名复制到本地系统。文件的传输进度以主机之间传输的每个块的连续单数字形式传输。只有包含文本（ASCII）的文件可以使用此子命令传输。
- `~Command` 在本地系统运行 `Command` 变量要求的命令，并将命令的输出发送到远程系统执行。

### 示例

如果你知道远程主机名称且该名称在 `/etc/uucp/Systems` 文件中定义，你可以使用它连接到远程主机。例如，如果远程主机名为 `remote2`，你可以执行以下命令：

```
cu remote2
```

如果你想以指定的线路速率 `2400` 连接到远程主机上的特定设备 `tty`，请执行以下命令：

```
cu -s 2400 -l tty
```

一旦进入远程主机，你就可以执行任何 `cu` 子命令。

如果你想切换到本地主机上的 `/u/testuser` 目录，请执行：

```
\~cd /u/testuser
```

如果你在本地主机的 `/u/testuser` 目录下有一个名为 `local_file` 的文件，要将其复制到远程主机当前目录下的同名文件，请执行以下命令：

```
\~put /u/testuser/local_file
```

如果你想在将文件复制到远程主机 `/u/testuser/testdir` 下的 `remote_file` 的同时，将文件名称重命名为 `local_file`，请执行以下命令：

```
\~put /u/testuser/local_file /u/testuser/testdir/remote_file
```

你可以使用 `take` 子命令进行操作。例如，如果你想从远程主机将文件 `/u/testuser/remote_file` 复制到本地主机上的 `/u/testuser/local_file`，请执行以下命令：

```
\~take /u/testuser/remote_file /u/testuser/local_file
```

要在本地系统上执行 `ls` 命令，请执行以下命令：

```
\~!ls
```

## `ftp` 命令

你可以使用 `ftp` 命令在两台计算机之间传输文件。此命令允许你将文件从远程主机移动到本地主机，或从本地主机移动到远程主机。`ftp` 命令仅允许简单的传输形式。也就是说，你无法通过单一 `ftp` 命令递归地复制目录文件。相反，你必须逐个传输文件。

`ftp open otherhost`

## `mailx`

在 UNIX 中，你可以通过 `mailx` 命令向用户发送邮件并接收他们的邮件。`mailx` 提供了发送、删除和回复消息的子命令，并在发送给一个或多个用户之前编写和编辑消息的功能。系统使用邮箱（mailboxes）来接收用户的邮件。每个用户都有一个用于接收邮件的邮箱，用户在收到邮件后可以读取、保存和删除。默认邮箱被称为 `mbox`，它通常位于用户的家目录下。然而，邮箱中的所有消息都是安全的，直到它们被移动到其他邮箱，这些邮箱有时被称为文件夹（folders）。你可以使用文件夹来组织邮件。例如，你可以按主题来组织特定邮箱中的邮件。

你可以使用 `mailx` 命令向或多个用户发送消息。该命令允许你向相同的主机或网络中的主机发送邮件。如果邮件投递成功，你会收到确认；但如果邮件无法投递，你将收到通知。

以下是 `mailx` 命令可以使用的一些标志列表：

- `-d` 显示调试信息。
- `-f` 显示默认邮箱 `mbox` 中的消息列表。可选情况下，你可以指定你之前保存邮件的文件夹名称。
- `-s` 为创建的邮件关联主题。
- `-v` 通过 `mailx` 命令显示详细信息。

每封邮件都有与其相关的信息。以下是这些信息的列表：

- `-status` 显示邮件的状态。以下是邮件项的各种状态列表：
  - `M` 表示消息将存储在个人邮箱中。
  - `>` 表示当前消息。
  - `N` 表示消息是一封新邮件。
  - `P` 表示消息保留在系统邮箱中。
  - `R` 表示你已读取了该消息。
  - `U` 表示未读消息。未读消息是指上次调用 `mailx` 时是新邮件但尚未读取的消息。
  - `*` 表示消息已保存或写入文件或文件夹中。
  - 无状态标记的消息表示该邮件已读取但未删除或保存。
- `-number` 表示消息的数字 ID，可以通过它引用消息。
- `-sender` 表示发送消息的用户。
- `-date` 表示邮件在邮箱中接收的时间。
- `-size` 表示消息的行数和字节数。
- `-subject` 如果发送者为邮件关联了主题，则显示邮件主题。这取决于邮件是否关联了主题。

以下是可以在 `mail>` 提示符下使用的子命令列表：

- `-q` 应用本次会话输入的邮箱命令。
- `x` 退出。
- `!command` 启动 shell 运行命令并返回邮箱。
- `cd` 将你置于家目录。可选情况下，你可以指定目录名称以进入指定的目录。
- `t` 显示当前消息。可选情况下，你可以指定消息列表以显示列表中的消息。
- `n` 显示下一条消息。
- `f` 显示当前消息的头部。可选情况下，你可以指定消息列表以显示该列表中的所有头部。
- `e` 编辑当前消息。可选情况下，你可以指定消息编号来修改消息。
- `d` 删除当前消息。可选情况下，你可以指定消息列表以删除其中的消息。
- `u` 恢复已删除的消息。
- `s file` 将当前消息（包括头部）追加到文件中。可选情况下，你可以指定 `s` 和 `file` 之间的消息列表将指定的消息追加到文件中。
- `w file` 将当前消息（不包括头部）追加到文件中。可选情况下，你可以指定 `w` 和 `file` 之间的消息列表将指定的消息追加到文件中。
- `pre` 将消息保留在系统邮箱中。可选情况下，你可以指定消息列表将其保留在系统邮箱中。
- `m addresslist` 向 `addresslist` 中的地址创建或发送新新消息。
- `r` 向消息的发送者和接收者发送回复。可选情况下，你可以指定消息列表，向列表中所有消息的发送者和接收者发送回复。
- `R` 仅向当前消息的发送者发送回复。可选情况下，你可以指定消息列表向其的发送者发送回复。
- `a` 显示别名及其地址的列表。

示例 你可以单独调用 `mailx` 命令进入 `mail>` 提示符，你可以在其中使用命令。只有当你拥有邮件时，才能进入 `mail>` 提示符。否则，你会收到一条消息。

类似于“你没有邮件（you have no mail）”。如果你有邮件，将显示类似下面的提示符：

```
mailx

Mail [5.2 UCB] Type ? for help.

"/usr/spool/mail/tester": 1 message 1 new

>N 1 tester Sat Nov 16 22:49 285/9664

&
```

如果你使用 `quit` 子命令（可以缩写为 `q`）退出 `mailx`，邮件将保存在你的个人邮箱箱中（家目录目录下的 `mbox` 文件）。

现在要查看它，请使用 `mailx -f` 命令，这将产生以下对话框：

```
mailx -f

Mail [5.2 UCB] Type ? for help.

"/u/tester/mbox": 1 message

> 1 tester Sat Nov 23 00:11 162/5175

&
```

要在执行 `mailx` 命令期间将邮件保存到某个文件夹中，请执行以下子命令：

```
& save 1 /u/tester/folder1/file1
```

这将在 `/u/tester/folder1` 目录下根据第一条消息创建文件。

现在，如果你调用 `mailx -f /u/tester/folder1` 读取文件 `/u/tester/folder1`，将产生以下对话框：

```
mailx -f /u/tester/folder1

Mail [5.2 UCB] Type ? for help.

"/u/tester/folder1": 1 message

> 1 tester Sat Nov 23 00:11 162/5175

&
```

一旦进入了 `mailx`，你可以执行子命令 `m` 来向其他用户创建并发送邮件，如下所示：

```
& m friend

Subject: Testing mailx command

This is test of the mailx command

Here we are trying to send a mail to user friend1 with cc to friend2

Cc: friend2

&
```
