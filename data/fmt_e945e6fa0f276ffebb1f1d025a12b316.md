
在示例中，`[^h]` 匹配 h 以外的任何字符。如果你想找到以 T 开头并跟随任何 h 字符的字符串，请使用以下命令：

```
grep T[^h] file1
THIS IS A TEST
```

在示例中，`...` 匹配任何三个字符。如果你想找到任何前后都有空格的六字符字符串，请使用以下命令：

```
grep " ..." file1
This is really a test
```

在上面的示例中，`^` 将匹配前面或后面跟着 `a` 的字符串。如果你想匹配所有中间有两个字符的字符串，请使用以下命令：

```
sed "s/a..a/g" file
```

在上面的示例中，`\t`（制表符）保存指定位置的字符。如果你想找到该字符串的一个或多个实例，请使用以下命令：

```
egrep "t+" file
```

在上面的示例中，`t+` 告诉 `egrep` 寻找该字符串的一个或多个实例。如果你想查找正则表达式是否重复了最大次数，请使用以下命令：

```
egrep "t{1,4}" file
```

在上面的示例中，`[a-zA]` 匹配所有从 a 到 z 的字符。

```
sed "s/[a-zA]//g" file
```

## 执行命令

有几种方法可以执行你到为止学过的命令。在本节中，我们将学习独立执行命令以及与其他命令结合执行命令的方法。UNIX 默认接受来自标准输入（即键盘）的输入，并在标准输出（即终端）上显示输出。然而，你可以使用 UNIX 重定向将输入重定向到文件或将输出重定向到文件。

你可以在前台或后台执行命令。当你调用命令时，默认情况下它在前台执行。你可以使用 `&`（安培符号）强制命令在后台执行。你可以先在前台启动命令，然后将其强制转到后台。要实现这一点，请使用 `Ctrl-z` 挂起它，然后使用 `bg` 命令将其放入后台。

由于 UNIX 命令从标准输入接受输入并向标准输出输出，因此使用 `|`（管道）字符将上一个命令的输出传递给下一个命令有一种非常方便的方法。你可以有一系列命令，每个命令都通过管道连接到下一个。

## 什么是网络？

网络是两个或多个相互连接的计算机系统。在本章中，你将学习连接 UNIX机器的常用方法。在规模的最端，网络可以是两台通过串行线（通常通过调制解密器）连接并运行 UUCP（Unix 到 Unix 拷贝程序）的 UNIX 直接。更复杂的网络配置使用 TCP/IP（传输控制协议/网协议），这是互联网的通用名称，互联网是一个允许将你的计算机连接到成千上万台其他计算机的网络集合。

## TCP/IP--LAN、WAN 和互联网

20 世纪 70 年代，美国国防部启动了一项名为 DARPA 的研究计划，即国防高级研究计划署。DARPA 的努力目标是创建一个互联网，即一个互连的网络集合，以便全国各地的研究实验室能够相互交互。这个网络被称为 ARPNet，运行其互连的协议被称为 IP，或互联网协议。自从最初的 ARPNet 以来，互联网络一直在增长，现在它已成为巨大且难以定义的概念，允许全球范围内的计算机进行互连。互联网通过一系列公共网络和私有网络包含了数十万台机器（由于互联网的无定形态，很难获得准确的连接数量）。

互联网协议允许能够连接到互联网的两台计算机之间发送数据。它仅提供一种简单的服务，并且存在更高级别的协议使用 IP 来执行功能。两种常用的协议是 TCP/IP 和 UDP/IP。TCP/IP 连接同一条线路上的两个程序，即连接两台计算机。UDP（用户数据报协议/IP）为两台计算机之间发送短消息提供了一种简单的方法。大多数互联网用户使用 TCP 建立连接，因此“TCP/IP”经常被用来指代互联网上的互连协议。

## 我在连接中--login, telnet, cu

通过 `login`、`telnet` 和 `cu` 这三个服务，你可以通过网络连接远程计算机。`login` 使用该服务通过网络上的 TCP/IP 协议连接，`telnet` 使用该服务通过网络上的 TCP/IP 协议连接，而 `cu` 则通过电话线连接。

# 在使用 login, rsh 和 rcp 之前

在使用 `login` 之前，可能需要进行一些用户配置。`rsh` 和 `rcp` 也使用相同的配置。在阅读下一节内容时，你应该参考这些细节。作为参考，`loc-host` 被视为本地机器，`remote-host` 是远程机器的名称。

远程机器上的两个文件会影响你的远程访问能力：`/etc/hosts.equiv` 和远程用户家目录下的 `.hosts`。`hosts.equiv` 文件包含一个主机名列表。列表中的每台机器都受主机的信任。任何在 `loc` 和 `remote-host` 上拥有账户的用户都允许无需置疑地从本地机器访问远程机器。“无需疑问”这一点非常重要，它意味着用户在访问时不需要提供密码。

> 提示：系统管理员应该认真考虑在直接连接到互联网的机器上禁用 `login` 和 `rexec` 协议，因为这些协议的身份验证非常脆弱。至少要对 `/etc/hosts.equiv` 和任何 `.hosts` 文件中的条目保持极其小心。

远程用户家目录下的 `.hosts` 文件包含一个受信任的主机用户对列表。这与 `hosts.equiv` 文件中的信任主机类似，但提供了更细粒度的控制。每个条目授予的是特定主机上某个特定用户的访问权限，而不是特定主机上所有用户的访问权限。`.rhosts` 中的行意味着只有某台机器将授予具有相同登录名的用户访问权限。`loc-host` 上的用户可以无需疑问地访问 `remote-host`（即无需指定密码）。身份验证由协议完成。

通常，系统管理员可以更改 `/etc/hosts.equiv` 文件中的值。该文件允许许多用户使用，这是一个系统配置文件。每个用户都可以设置自己的 `.rhosts` 文件，该文件必须存在于用户的家目录中，并由该用户（通过 root）所有。所有权限制防止了用户访问另一个用户的账户。

列表 6.1 和 6.2 显示了 `/hosts.equiv` 和 `.rhosts` 文件的示例。这些文件位于名为 `flounder` 的机器上，`.rhosts` 属于用户 `rob`，并位于他的家目录中。`/etc/hosts.equiv` 文件列出的两个主机 `manatee` 和 `dolphin` 是 `flounder` 的信任主机。任何在 `manatee` 和 `flounder` 上拥有账户的用户都可以在无需指定密码的情况下从 `manatee` 远程访问 `flounder`。同样，在 `dolphin` 和 `flounder` 上拥有账户的用户都可以从 `dolphin` 远程访问 `flounder`。

## 使用 login

如果你需要登录到一个不在你当前位置的计算机，`login` 可以帮助你。该应用程序从你的机器到网络连接的另一台机器建立远程登录会话。这台机器可能在你身边，在你的办公桌上，或者在另一个大陆。当你从屏幕成功执行 `login` 时（无论是终端还是你的某个图形显示器），提示你的 shell 以及你在远程机器上执行的命令，就像你坐在机器前输入 `login` 一样。

登录协议可能会替你处理身份验证。如果你（或你的系统管理员）已经在 `/etc/hosts.equiv` 或你的 `$HOME/.hosts` 文件中建立了正确的条目，则不需要身份验证（也就是说，不会提示你输入密码）。如果这些文件中没有你的用户和名的条目，则会像本地登录尝试一样显示密码提示。

让我们来看几个例子。假设你的用户名是 `rachel`，你登录的本地机器是 `moray-eel`。要登录到机器 `flounder`，你输入以下内容：

```
$login flounder
```

将建立与 `flounder` 的连接，并为用户 `rachel` 启动登录会话（如果 `flounder` 上不存在用户 `rachel`，则会失败）。接下来，登录协议会检查特殊文件以查看是否需要身份验证。如果 `moray-eel` 在文件 `/etc/hosts.equiv` 或 `~rachel/.hosts` 中，则不需要身份验证。

要以用户 `arnie` ，请输入 `login -l arnie flounder`。

在这里，登录会话以用户名 `arnie` 启动。如果 `flounder` 上存在用户 `arnie`，则会检查特殊文件进行身份验证。由于远程登录的用户名与本地用户名不同，`/etc/hosts.equiv` 文件不提供身份验证。如果 `~arnie/.hosts` 文件中有条目 `moray-eel`，则不需要身份验证（也就是说，无需密码即可登录成功）。如果该条目不存在，会出现密码提示，你必须输入与用户 `arnie` 关联的密码。当你尝试通过 `login` 连接到远程机器时，连接失败可能会出现各种问题。其中一些问题是你无法控制的。在这种情况下，你应该联系系统管理员来帮助你解决问题。

在需要身份验证的情况下，你可能会输入错误的密码。如果发生这种情况，结果与本地登录尝试相同。登录过程会通过提示你先输入用户名，然后输入密码来再次尝试。请注意，这是在你尝试登录自己的账户时，必须提供用户名的唯一情况。

对于大多数其他问题，你可能需要系统管理员的帮助。请参见“故障排除”（Troubleshooting）章节了解问题原因的方法。关于问题症状的任何细节都将有助于负责修复问题的人。你可能会看到的一些问题如下：

- 远程上不存在该用户账户。

- 你的本地主机未通过网络连接到远程。

- 远程主机已宕机。

- 远程主机不支持 `login`。

- 本地和远程之间的网络存在问题。

## 使用远程登录会话

成功远程登录后，登录协议将使用你本地会话的一些信息启动你的会话。这避免了你完全从头开始初始化环境的麻烦。你的终端（`TERM` 环境变量的值）会被传播。其他信息，如波特率和你的屏幕（窗口）大小也可能被传播，取决于本地和远程主机的支持。
