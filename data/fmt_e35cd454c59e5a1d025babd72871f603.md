# 5.4.2 确保失败尝试锁定（自动化）

配置适用性：

- 等级 1 - 服务器
- 等级 1 - 工作站

描述：

在失败 $n$ 次登录后锁定。第一组更改应用于通用 PAM 文件。第二组更改应用于特定程序。查看每个程序的文档以了解如何与 PAM 工作。

- `deny` 如果连续认证失败超过 $n$ 次，则拒绝访问。
- `fail_interval` 账户锁定之前必须发生连续认证失败的时间间隔长度（秒为单位）。
- `unlock_time` 锁定后 $n$ 秒重新启用访问。值 0 的含义与 - 相同——如果不通过 `faillock` 命令将重新启用访问。

根据本地站点策略设置锁定和解锁时间。

原理：

在连续 $n$ 次登录后锁定用户 ID 可以缓解针对系统的暴力破解攻击。

影响：

在部署之前对任何 PAM 更改进行测试和验证至关重要。任何错误配置可能导致无法访问系统。

## 审计：

# 5.4.5 确保所有当前密码都使用配置的加密算法（手动）

## 配置文件适用性：

- 级别 1 - 服务器
- 级别 1 - 工作站

## 描述：

使用过期加密算法的当前密码会对系统造成安全风险。

## 原理：

使用的密码应与配置的加密算法匹配。

## 影响：

如果管理员强制更改密码，当大量用户同时更改密码时，会导致 CPU 使用率激增。

## 审计：

运行以下脚本来获取未使用配置加密算法的用户列表：

```bash
#!/usr/bin/env bash
{
  declare -A HASH_MAP=( ["1"]="yescrypt" ["2"]="md5" ["2"]="blowfish" ["5"]="SHA256" ["6"]="SHA512" ["g"]="guest-shacrypt" )

  CONFIGURED_HASH=$(sed -n "s/ENCRYPT_METHOD\\s*=\\$/\1/p" /etc/login.defs)

  for MY_USER in $(sed -n "s/${MY_USER}:\\(.*\\)/\1/p" /etc/shadow); do
    CURRENT_HASH=$(sed -n "s/${MY_USER}:\\(.*\\)/\1/p" /etc/shadow)
    if [ "${HASH_MAP["${CURRENT_HASH^}"]}" != "${CONFIGURED_HASH^}" ]; then
      echo 'The password for ${MY_USER} is using ${HASH_MAP["${CURRENT_HASH^}"]} instead of the configured ${HASH_MAP^}'.
    fi
  done
}
```

没有任何输出。

任何需要过期的系统账户都应由系统管理员单独处理，以防止任何潜在问题。

## 修复措施：

如果管理员希望根据审计输出强制所有用户立即更改，请执行以下命令：

```bash
#!/usr/bin/env bash
{
UID_MIN=$(awk '/^UID_MIN/ {print $2}' /etc/login.defs)
awk -v UID_MIN="$UID_MIN" '$3 >= UID_MIN && $1 != "nfsnbody" {
print $1}' /etc/passwd | xargs -n 1 change -d 0
}
```

注意：如果大量用户同时重置密码，这可能会导致系统产生巨大的临时 CPU 负载。
