
# 管理路由缓存

## 14.8.12 `__dst_free()`

该例程垃圾列表中的路由缓存条目（`dst_entry`对象）由`dst_gc_timer`异步释放。我们持有`dst_lock`来操作`dst_garbage_list`。如果路由没有关联接口（`dst->dev`）或关联接口已关闭（第126行，14.30），我们分别将输入和输出路由设置为`dst_discard`和`dst_blackhole`。我们在130行将`obsolete`字段设置为2，表示条目已经在垃圾列表中。接下来，我们使用`dst_entry`对象的`next`字段将路由添加到垃圾列表的开头（第131–132行）。这意味着最新的条目位于列表头部。

每当新条目被添加到`dst_garbage_list`（检查`dst_free()`）时，`dst_gc_timer_inc`重新初始化为`DST_GC_INC` (5Hz)，`dst_gc_timer_expires`初始化为`DST_GC_MIN` (1Hz)，如果垃圾列表中没有过期一次的条目，则通过`add_timer()`设置`dst_gc_timer`在一秒后过期。如果垃圾列表中有一个过期一次的条目，`dst_gc_timer_inc`将大于`DST_GC_MIN`（检查第14.8.15节）。

`cs 14.29, dst_free ().`

```c
include/net/dev.h

void __dst_free(struct dst_entry * dst) {

    spin_lock_bh(&dst_lock);

    if (dst->dev == NULL || (dst->dev)->flags&IFF_UP) {

        dst->input = dst_discard;

        dst->output = dst_blackhole;

    }

    dst->obsolete = 2;

    dst->next = dst_garbage_list;

    dst_garbage_list = dst;

    if (dst_gc_timer_inc == DST_GC_INC) {

        del_timer(dst_gc_timer);

        dst_gc_timer_inc = DST_GC_MIN;

        dst_gc_timer_expires = jiffies + dst_gc_timer_expires;

        add_timer(dst_gc_timer);

    }

}
```

## 14.8.13 `dst_destroy()`

当路由过期且没有人引用时，最终调用此例程来释放路由和相关资源。`hh_cache`对象包含了缓存的硬件（网）相关信息。如果没有人引用该缓存对象（第150行），则在151行释放它。如果路由关联ARP（`dst->neighbour`），则通过调用释放它。

此例程在`dst_gc_timer`到期时执行。它检查`dst_garbage_list`中的任何路由条目是否需要删除。如果发现此类条目，则调用`dst_destroy()`来释放路由条目（`dst_entry`对象）以及与其相关的资源。

首先，我们尝试在第49行 (cs.14) 调用`spin_trylock()`来获取`dst_lock`。如果我们无法获取锁，我们会在第50行重置定时器（`dst_gc_timer`），使其在十分之一秒后过期并返回。否则，我们删除定时器并继续处理垃圾列表。对于每个条目，我们在第58行检查引用计数是否变为零。如果是，且我们没有引用该路由条目，则移动到下一个条目并继续（第59行）。否则，我们在第63行从列表中移除该条目（记住`dstp`是双指针），并在第64行调用`dst_destroy()`释放`dst_entry`对象。一旦我们遍历了整个列表，我们会在第66行检查列表中是否还留有条目。如果`dst_garbage_list`中没有任何剩余，则使用`dst_gc_timer`——`rt_flush_timer`用于强制刷新路由缓存，原因可能是接口宕线、路由表被刷新等；`rt_run_flush`是该例程。
