在处理 Unicode 文件时，数据编码通常嵌入在文件本身。例如，XML 解析器可能会查看字符串 `<?xml ...?>` 的前几个字节来确定文档编码。如果前四个字节是 `3C 3F 78 6D`，则假设编码为 UTF-8。否则，假设编码为 UTF-16 大端序或小端序。此外，文档编码可能出现在 MIME 头中或作为其他的文档元素出现。这里有一个示例：

```xml
<xml encoding="ISO-8859-1"?>
```

同样，Unicode 文件可能还包含字节顺序标记（BOM），用于指示字符编码的属性。Unicode 字符 `+FEFF` 专门留用于此。通常，该标记是文件中的第一个字符。程序读取该字符并查看字节的排列来确定编码（例如，`\xff\xfe` 代表 UTF-16-LE，`\xfe\xff` 代表 UTF-16-BE）。一旦确定了编码，BOM 字符会被丢弃，并处理文件的剩余部分。遗憾的是，任何对 BOM 的手动处理都不是在后台自动完成的。如果你的应用程序需要，你必须处理这个问题。

从文档读取内容时，可以使用类似于下面的 `codec` 将输入文件转换为编码流：

```python
f = open("somefile","rb")

# 在文件上放置一个合适的编码包装器。
# 假设 BOM（如果有）已经被之前的语句丢弃

```

## Unicode 编码

表 9.3 列出了 `codecs` 模块中一些最常用的编码器。

### 表 9.3 codecs 模块中的编码器

| 编码器 | 说明 |
| --- | --- |
| 'ascii' | ASCII 编码 |
| 'latin-1', 'iso-8859-1' | Latin-1 或 ISO-8859-1 编码 |
| 'cp437' | CP437 编码 |
| 'cp1252' | CP1252 编码 |
| 'utf-8' | 8 位变长长度编码 |
| 'utf-16' | 16 位变长长度编码 |

### 表 9.3 续

| 编码器 | 说明 |
| --- | --- |
| utf-16-le | UTF-16，但使用显式的小端编码 |
| utf-16-be | UTF-16，但使用显式的大端编码 |
| unicode-escape | 与 "string" 格式相同 |
| raw-unicode-escape | 与 ur"string" 格式相同 |

接下来的章节将详细描述每种编码。

#### 'ascii' 编码
在 `'ascii'` 中，编码值限制在范围 `[0x00, 0x7f]` 和 `[U+0000, U+00FF]` 内。任何在此范围之外的字符都是无效的。

#### 'iso-8859-1, 'latin-1' 编码
字符可以是范围 `[0x00, 0xff]` 和 `[U+0000]` 内的 8 位值。`[0x00, 0xff]` 范围内的值对应于 ASCII 字符集中的字符。`[0x80, 0xff]` 范围内的值对应于 ISO-8859-1 或扩展 ASCII 字符集中的字符。超出范围的字符会导致错误。

#### 'cp437' 编码
该编码用于 `'iso-8859-1'`，它是 Python 在 Windows 上作为控制台程序运行时使用的默认编码。`[0x80,0xff]` 范围内的字符对应于在旧 DOS 应用程序中渲染菜单、窗口和框架的特殊符号。

#### 'cp1252' 编码
这是与 Windows 上使用的 `'iso-8859-1'` 非常相似的编码。然而，该编码定义了范围 `[0x80-0x9f]` 内的字符，这些字符在 `'iso-8859-1'` 中未定义，并且在 Unicode 中具有不同的代码点。

#### 'utf-8' 编码
UTF-8 是一种变长编码，允许表示所有 Unicode 字符。单字节用于 0–127 范围内的 ASCII 字符。所有其他字符都由 2 字节或 3 字节的多字节序列表示。这些字节的编码如下：

| Unicode 字符 | 字节 0 | 字节 1 | 字节 2 |
| --- | --- | --- | --- |
| U+0000 - U+007F | 0|nn | | |
| U+0080 - U+07FF | 110nnnnnn | 10nnnnnn | | |
| U+0800 - U+FFFF | 1110nnnn | 10nnnnnn | 10nnnnnn |

对于 2 字节序列，第一个字节始终以位 `11` 开头。对于 3 字节序列，第一个字节以 `1110` 开头。

对于 4 字节序列，第一个字节以 `11110` 开头。UTF-8 允许表示长达 4 个字节的 Unicode 字符。

## 第 9 章 输入与输出

默认情况下，使用协议 0。这是最老的 pickle 格式，以几乎所有 Python 版本都支持的格式存储对象。然而，这种格式与 Python 许多更现代的用户定义类功能（如 slots）不兼容。协议 1 和 2 使用了更高效的二进制数据表示。要使用这些替代协议，你可以执行以下操作：

```python
import pickle
obj = SomeObject()
f = open(filename,'wb')
pickle.dump(obj,f,2)  # 使用协议 2 保存
pickle.dump(obj,f,pickle.HIGHEST_PROTOCOL) # 使用最现代协议
f.close()
```

在使用 `load()` 恢复对象时，不需要指定协议。底层协议编码在文件本身中。

同样，可以使用这种方式使用替代 pickle 的 shelve 来保存 Python 对象：

```python
import shelve
db = shelve.open(filename,protocol=2)
```

对于用户定义对象，通常不需要对 pickle 或 shelve 做任何额外工作。但是，可以使用特殊方法 `__getstate__()` 和 `__setstate__()` 来辅助序列化过程。`__getstate__()` 方法将被调用以创建对象的表示值。`__getstate__()` 返回的值通常应该是元组、列表或字典。`__setstate__()` 方法在反序列化期间接收此值并从其恢复对象的状态。这里示例展示了如何对涉及底层网络连接的对象使用方法。虽然实际连接无法被序列化，但对象保存了足够的信息，以便在反序列化时重新建立连接：

```python
import socket
class Client(object):
    def __init__(self,addr):
        self.server_addr = addr
        self.socket = socket.socket(socket.AF_INET,socket.SOCK_STREAM)
        self.socket.connect(addr)
    def __getstate__(self):
        return self.server_addr
    def __setstate__(self,value):
        self.server_addr = value
        self.socket = socket.socket(socket.AF_INET,socket.SOCK_STREAM)
        self.socket.connect(self.server_addr)
```
