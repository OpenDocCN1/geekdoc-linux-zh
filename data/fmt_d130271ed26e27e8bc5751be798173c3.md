
在第一个命令中，替换后 shell 看到语句 `@ sum=2*3`。由于 `2*3` 是一个单一单词，shell 尝试将其解释为数字或运算符。它两者皆不是，所以 shell 会报错，因为该单词以数字开头但包含非数字字符。

大多数操作符具有你可能在 C 编程语言中熟悉的正常解释。支持一元和二元操作符。C shell 支持的表达式运算符完整列表见表 12.11。

运算符组合产生结果。项可以是以下任何一种：

- 字面量——例如，`125`（十进制）或 `0177`（八进制）。
- 括在括号中的表达式--例如，`(exp)`。使用带括号的表达式可以从 shell 的正常解释中隐藏 `<`、`>` 和 `|` 运算符。带括号的表达式作为一个单元进行求值，产生单个结果，然后该结果作为表达式的值。括号会覆盖正常的操作符优先级。
- 任何变量、命令或历史替换（或这些者的组合），它们在求值时产生十进制或八进制数字。扫描表达式时会使用常用的 shell 替换机制。你必须遵守的唯一要求是，在所有替换之后，结果生成的单词必须形成十进制或八进制数字字符串或表达式。

### 赋值运算符

求值并将结果赋值给变量。你可以使用所示的操作符将表达式的结果赋值给变量。特殊字符 `<` `>` `|` 如果是表达式的一部分，必须引用或括在括号中；例如，

```
@ name=expr

name[i]=expr
```

还支持 `+=`、`-=`、`*=`、`%=`、`<<=`、`>>=`、`^=` 和 `&=`. C运算符 `++` 和 `--` 支持后缀和前缀形式。这种用法适用于命令，但通常不支持表达式。

### 算术和逻辑操作符的优先级

C 使用优先级规则来解析歧义表达式。歧义表达式是包含两个或多个操作符的表达式，如 `a+b*c`。该表达式可以解释为 `(a+b)*c` 或 `a*(b*c)`。事实上，采用后者解释。使用值 a=3, b=5 和 c=7，表达式 `a+b*c` 求值为 38。

> 注意：为了方便大家，shell 的规则与 C 语言相同，并且是手计算器使用的优先级规则的超集。

在表 12.11 中，运算符按优先级降序排列。运算符分为八组：

- 一元运算符 `!` 和 `-`。这些运算符具有最高优先级。它们从右到左关联，所以 `~!` 等于带括号的表达式 `(~a)`。
- 乘法运算符 `*`、`/` 和 `%`。
- 加法运算符 `+` 和 `-`。
- 移位运算符 `<<` 和 `>>`。第二个参数作为计数，指定第一个参数向左或右移动的位数。位会被丢弃——例如，`5 >>` 产生 2。
- 关系运算符 `<`、`<=` 和 `>=`。这些运算符比较操作数，并在关系成立时产生 1（真），不成立时不产生 0（假）。
- 相等运算符 `==`、`!=` 和 `!=`。注意，与其他操作符不同，这些运算符将其参数视为字符串。这需要谨慎，因为字符串 `"10"`、`10 "` 和 `" 10 "` 看起来都一样

尽管在数值上是等价的，但并不相等。要比较字符串，请使用表达式 `$val == ($x + 0)`。

- **按位运算符** `|`、`&` 和 `^`。这些运算符结合其操作数的内部二进制形式，应用包含或、异或或与逻辑函数对相关位进行关联。这些操作的定义如下：

**包含性或逻辑（Inclusive or）：** 如果参数的位中任一个为 1，则生成 1--（二进制），`^ 0110 1010`

**异或逻辑（Exclusive or）：** 如果两个位不同，则生成 1--（二进制中），`^ 1010 1100`

**与逻辑（And）：** 如果两个源位都为 1，则生成 1--，`& 0110 1010`

- **逻辑运算符** `&&` 和 `||`。这些运算符接受数值值并产生 1 或 0。

在表达式中，你可以将命令括在括号 `{}` 中。如果命令执行成功，命令的退出值为 1；否则，退出值为 0。许多版本的 C shell 要求大括号之间有空格——例如，`x = { true }` 将 `x` 设置为 1，而 `x = {true}` 会产生语法错误。

文件测试运算符允许你确定文件是否存在以及其特征是什么。这些运算符具有 `-f filename` 的形式，并在表达式中被视为子表达式。对于 `filename`，指定文件的名称或路径。

表 12 总结了表达式中支持的文件测试操作。

| 表达式 | 为真的条件 |
| :--- | :--- |
| `-r filename` | 文件存在且可读 |
| `-w filename` | 文件存在且可写 |
| `-x filename` | 文件存在且可执行 |
| `-e filename` | 文件存在 |
| `-o filename` | 文件存在且由当前用户 ID 所有 |

| `-f filename` | 文件存在且是普通文件 |
| `-d filename` | 文件存在且是目录 |

```

if (x$1 == x-d) then set debug

### 在 Shell 程序中输入注释

经常，在编写程序时，几个月前看起来非常合理的程序代码今天可能看起来相当晦涩。良好的程序员用注释来标记他们的程序。通过插入井号（`#`）特殊字符向 shell 程序输入注释。当 shell 解释井号时，它会忽略行尾的所有文本作为注释。

只有当当前 shell 不被认为是交互式时，注释字符才被视为注释。如果命令

```
% echo a pint is a # the world went
```

# a pint is a # the world round
```

是交互式输入的，结果将包含 `#` 符号。如果该行从 脚本执行，`#` 之后的单词将不会显示，如示例所示：

```
% cat pound.csh
echo a pint is a # the world round
#/pound.csh
pint is a
```

可以使用命令的特殊形式指定脚本文件的命令处理器。`#!` 注释告诉当前 shell 程序将运行。如果你正在编写 脚本，你的第一行始终应该是：

```
#!/bin/csh
```

这确保脚本始终由 C shell 运行。并不是所有版本都支持这一点，但大多数都支持。即使某个版本不支持 `#!` 表示，它会被解释为注释，因此使用它没有害。

`if` 语句实际上有两种不同的形式：单行命令和多行命令。单行命令具有通用语法：

```
if (expr) command
```

当你需要条件执行执行一个命令时，使用这种形式。以下是嵌套 if 语句的示例：

```
if (-r $thisfile && -d $thisfile) echo Good File @ x = -f { grep -q ~/.cshrc }
```

多行命令具有更复杂的语法：

```
if (expr) then
commands
else (expr) then
commands
else
commands
endif
```

在这种情况下，如果语句包含了从 `if` 开始到包括 `endif` 在内的所有行。多行形式提供了一种告诉 shell “要么这个要么那个”的方法。更准确地说，shell 以如下方式执行多行语句：评估 `expr` 表达式。如果评估的表达式产生非零结果，则执行后面的命令组（commands）。如果评估的表达式产生零结果，则跳过后面的命令组。然后对于 `else`，当评估的表达式为真时，跳过下一个 `else` 或 `endif` 直命令；当评估的表达式为假时，执行命令。对于 `endif`，只需恢复正常执行。

嵌套语句是合法的，但可能会令人困惑。这里是嵌套 语句的示例：

```
if (-d $file) then
    if (-r $file) then
        echo "file is readable"
    else
        echo "file is not readable"
    fi
else
    echo "directory does not exist"
fi
```

（注：上面的示例使用了类 sh 语法，在 csh 中语法略有不同）

以下是 `csh` 风格的嵌套语句示例：

```csh
if ( -d $file )
    if ( -r $file )
        echo "file is readable"
    else
        echo "file is not readable"
    endif
else
    echo "directory does not exist"
endif
```

放弃执行该脚本：

```
if (-d ~/bin) then
  mv newfile ~/bin
else
  echo ~/bin: directory not found
  exit 1
fi
```

在许多情况下，这种较长的多行 `if` 语句比另一个示例更合适，因为当脚本可以防止此类操作时，它为用户提供了某些反馈。当 `if` 语句未能按预期移动文件时，用户会获得实用的提示：要么创建缺失的目录，要么停止移动文件。

即使嵌套的 `if` 也出现在自然情况下。例如，以下代码将单行 `if` 语句嵌套在一个多行语句中：

```
if (-f newfile) then
  if (-d ~/bin) then mkdir ~/bin
  mv newfile ~/bin
else
  echo newfile: file not found
  exit
fi
fi
```

最后一个使用的方法与前两个略有不同：它首先处理文件可能存在或不存在的基本选择。如果 `newfile` 不存在，你可以合理地推断用户不知道自己在做什么——他本就不应该调用包含这些行的 脚本，此时应通过“向标准输出回参数”中使用的 stderr 别名解决问题。所有工作由 `else` 之后的行完成。如果文件 `newfile` 存在，脚本将按预期移动文件，如果 `~/bin` 尚未创建，则动态创建它。

正如前面的示例所示，`if` 语句在脚本中被用作安全机制：它测试预期环境是否真实存在，并警告用户问题。通过关键字，你可以使用 `mv` 命令，并在 `mv` 语句失败时决定如何继续，因为用户并没有自己输入 `mv` 命令——事实上，他们可能甚至没有意识到调用脚本意味着执行了一个 `mv` 命令。负责编写脚本的人考虑了失败的情况，并为所有结果提供适当的处理，从而产生行为可预测且对用户来说可靠的脚本。

### 使用 switch 语句

`switch` 语句类似于 `if`，但它提供了许多替代方案。该语句的一般形式如下：

```
switch (string)
  case pattern:
    commands
  default:
    commands
esac
```

从字面上说，shell 在后续 `case` 语句的模式中搜索与 `string` 匹配的项。在实际上，使用 `string` 通常是变量和命令替换、文件名生成以及可能的其他 shell 替换的结果。`switch` 和 `esac` 之间的每个 `case` 语句定义了一个不同的命令组。shell 会跳过命令组，直到遇到匹配 `string` 的第一个 `case` 语句。

然后恢复正常的命令执行，忽略它遇到的任何后续 `case` 和 `default` 语句。`default:` 语句引入了一个在没有前面的 `case` 匹配 `string` 时应该执行的语句。`esac` 结果为 `switch` 语句提供了一个结束边界，当 shell 到达该点时如果仍在跳过它；shell 恢复到正常的命令执行。

在实践中，你通常会在每个命令组后放置一个 `breaksw`，以防止 shell 执行 `case` 组中的命令。在少数情况下，你会遇到两个 `case`，其中一个在另一个之前需要一些额外的预处理。你可以通过省略 `breaksw` 来安排这两个 `case` 组，使得 shell 可以从第一个 `case` 组继续到第二个 `case` 组。能够安排 `case` 组以允许穿透（fall-through）是——

假设你想让脚本提示用户进行选择。用户应该通过输入 `y` (yes) 或 `n` (no) 来响应。`switch` 语句为其字符串-模式匹配能力提供了自然的实现：
