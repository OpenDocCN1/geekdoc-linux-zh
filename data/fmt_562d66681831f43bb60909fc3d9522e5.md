
## w 命令

`w` 命令实际上是关于“谁”的。输出如下：

```
12:29PM               up 27 days,         21:53, 2 users, load average 1.03, 1.17, 1.09

User                  tty                 login9      idle    JCPU    PCPU    what

rmichael             pts/0               Mon 10AM 0   3:00        1               W

root                  pts/1               10:42AM 37  5:12                    tar
```

注意，上述输出的第一行与 `uptime` 命令的输出相同。`w` 命令通过列出作业进程时间和总进程时间，提供了比 `who` 命令更详细的输出，但它没有揭示用户从哪里登录。我们出于安全考虑，通常对这一点感兴趣。`w` 命令输出的一个优点是，它还列出了在输入命令的瞬间刻用户正在做什么。这非常有用。

# 第一章

除 0 之外均为零。要检查返回码，我们查看 `$?` 变量的值。

例如，我们想要检查 `/usr/local/bin` 目录是否存在。这些代码块执行的是完全相同的更改：

```
test -d /usr/local/bin

if [ $? -eq 0 ] # 检查返回码
then
    echo '/usr/local/bin does exist'
else
    # 返回码不是 0
    echo '/usr/local/bin does NOT exist'
fi
```

```
if test -d /usr/local/bin
then # 返回码为 0
    echo '/usr/local/bin does exist'
else # 返回码不是 0
    echo '/usr/local/bin does NOT exist'
fi
```

```
if [ -d /usr/local/bin ]
then # 返回码为 0
    echo '/usr/local/bin does exist'
else # 返回码不是 0
    echo '/usr/local/bin does NOT exist'
fi
```

注意，我们使用 `$?` 检查了返回码。其他示例使用了控制结构的内置测试。内置测试同样具有处理返回码的功能，但内置测试在过程中隐藏了这一步。之前的三个示例给出的结果完全相同。这只是个人偏好和可读性的问题。

# 脚本快速上手与回顾

### 基于时间的脚本执行

我们编写许多脚本，希望它们按时间时间间隔执行，或在特定时间运行一次。本节通过几个示例解决了这些需求。

## Cron 表 (Cron Tables)

Cron 表是一个系统文件，系统每分钟读取一次，并将执行任何计划在在该分钟执行的条目。默认情况下，任何用户都可以使用 `crontab -e` 命令创建 cron 表，系统管理员可以通过 `cron.allow` 和 `cron.deny` 文件控制哪些用户允许创建和编辑 cron 表。当用户创建自己的 cron 表时，程序或脚本将在该用户的环境中执行。这与在执行命令之前运行用户的 `$HOME/.profile` 是一样的。

`crontab -e` 命令会在用户的 cron 表中启动默认文本编辑器 `vi` 或 `emacs`。

> 注意：使用 `crontab` 命令时，作用的是当前用户的 cron 表。要列出当前用户的 cron 表内容，请执行 `crontab -l`。

## Cron 表目语法

了解 cron 表中每个字段的用途非常重要。图 1.1 显示了创建 cron 表的用法。图 1.1 中的 cron 表目执行脚本 `/usr/local/bin/somescript.ksh`，时间为每月 8 日 3:15，每周的任何一天。注意我们在星期字段上使用了通配符。以下 cron 表目是另一个示例：

```
1 0 * * * banner "Happy Year" > /dev/console
```

在每月 1 日午夜后 1 分钟，每周任何一天，此 cron 表目写入控制台 (`/dev/console`) Happy Year。

## 通配符

- `*` 匹配任意数量的字符
- `?` 匹配字符

## at 命令

类似于 cron 表，`at` 命令根据时间执行命令。使用 `at` 命令可以调度任务在特定时间运行一次。当任务执行时，`at` 命令会将标准输出和标准错误发送给调度任务的用户，除非输出被重定向。作为系统管理员，可以通过 `at.allow` 和 `at.deny` 文件控制哪些用户允许调度任务。在修改这些文件之前，请参考每个系统的 man 页以及使用 `at` 命令定时执行的许多方法。

## 静默运行

要在静默模式下执行脚本，可以使用以下语法：

```
/PATH/script_name 2>&1 > /dev/null
```

在此命令中，`script_name` shell 将在没有任何输出的情况下执行。这是因为命令如下方式结尾：

```
2>&1 将标准错误 (stderr) 重定向到文件描述符 1 (标准输出 stdout)，然后我们有另一个重定向到 `/dev/null`，将所有输出发送到空设备。
```

我们将此称为静默运行。这意味着脚本绝对没有任何输出到屏幕。在脚本内部，输出可能会定向到文件、设备、特定终端甚至是系统控制台 (`/dev/console`)，但用户屏幕上没有。这在从 cron 表执行脚本时特别有用。

在这个 cron 表目中，我们想要执行名为 `/usr/local/bin/systemcheck.ksh` 的脚本，它需要以 root 用户身份运行，每 15 分钟一次，每天 24 小时，每周 7 天，且屏幕上没有输出。因为我们将 cron 表目如下结尾：

```
2>&1 /dev/null
```

在脚本内部，我们执行某些通知，例如分页或将输出到系统控制台、写入文件或磁带设备，但如 `echo "Hello world"` 的输出将发送到空设备。如果此命令在 shell 脚本中，输出将进入定义的控制台。

此 cron 表目需要放在 root cron 表（必须以 root 用户登录），使用如下语法：

```
5,20,35,50 * * * /usr/local/bin/systemcheck.ksh 2>&1 /dev/null
```
