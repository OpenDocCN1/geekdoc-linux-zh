
在宏配置文件中添加 `VIRTUAL_DOMAIN_FILE` 命令后，重新运行 `m4` 构建新的 `sendmail.cf` 文件。然后将列表 6.9 中的虚拟域名添加到新的 `virtual-domains` 文件中，每行一个，如下：

```bash
[craig]$ cat /etc/mail/virtual-domains
bridal-gowns.com
patient-rights.org
imaginary.com
```

每当文件中添加新的虚拟域名时，向 Sendmail 发送 `SIGHUP` 信号，确保它读取新值并将其加载到 class `{VirthHost}`。

**TIP** `V_DOMAIN` 和 `V_DOMAIN_FILE` 宏都需要更改并重新构建示例配置。由于我们已经在配置中有了 `local-host-name` 文件，向该文件添加虚拟域名会更容易。

## 定义投递地址

`virttable` 中的每个条目都有两个字段：虚拟域名和投递地址。第一个字段包含电子邮件地址中的虚拟域名。第二个字段包含邮件实际投递的地址。第一个字段包含的虚拟域名可以是 `user@domain` 形式的完整地址，也可以是 `@domain` 形式的部分地址。当使用 `@domain` 格式时，发往指定域名内任何用户的邮件都将路由到第二个字段包含的邮件地址。列表 6.9 显示了一些示例的 `virttable` 条目。

### 列表 6.9 虚拟域名示例

```
sales@bridal-gowns.com jill
info@patient-rights.org sara@hawk.foobirds.org
@imaginary.com david@lion.mammals.org
```

这三个示例展示了基本的虚拟域名和投递地址。发往 `sales@bridal-gowns.com` 的邮件实际上投递到了 Sendmail 服务器上的 Jill 账户。（就像 Jill 经营婚纱业务一样。）发送到 `info@patient-rights.org` 的请求被转发到 `sara@hawk.foobirds.org`。发送到 `imaginary.com` 域名中任何用户的邮件被转发到 `david@lion.mammals.org`。

必须配置 Sendmail 以接受发往虚拟域名的邮件。在列表 6.9 中，Sendmail 必须接受 `bridal-gowns.com`、`patient-rights.org` 和 `imaginary.com` 作为本地主机的别名，或者将它们识别为虚拟域名。通过在本章之前对 `local-host-names` 的讨论，你知道 Sendmail `Accept` class 中的任何名称作为本地主机的别名。根据之前的讨论，你已经知道如何将这三个虚拟域名添加到 class 中。但没有必要将虚拟域名转换为主机别名来让 `virttable` 工作。另一种方法是通过将域名存储在 `(VirthHost)` class 中，告诉 Sendmail 该域名是一个虚拟域名。

### 列表 6.10 虚拟域名示例

```
sales@bridal-gowns.com      jill
info@patient-rights.org      sara@hawk.foobirds.org
@imaginary.com               david@lion.mammals.org
sales@outofbusiness.com     error:User is not valid
sales@werbreak.com           error:Destination invalid
@other.org                   %1@local.org
+thatplace.com                %2@local.com
```

这三个示例展示了基本的虚拟域名和投递地址。发往 `sales@bridal-gowns.com` 的邮件实际上投递到了 Sendmail 服务器上的 Jill 账户。（就像 Jill 经营婚纱业务一样。）发送到 `info@patient-rights.org` 的请求被转发到 `sara@hawk.foobirds.org`。发送到 `imaginary.com` 域名中任何用户的邮件被转发到 `david.lion.mammals.org`。

错误消息以 `error` 关键字开头，它是 Sendmail 内置的一个特殊邮件名称。在 `error` 关键字后面冒号后面的是错误条件，可以通过关键字或 DSN 代码指定。DSN 代码可以是 RFC 1893 中定义的任何值。错误条件关键字必须是邮件处理程序识别的关键字。有效错误条件关键字列表可以在第 8 章“理解重写规则”中的邮件处理程序讨论中找到。

列表 6.10 中的两行演示了如何将输入地址中的值用于投递地址中。输入地址的用户名通过 `%s` 变量传递，因此投递地址中的 `%s` 将替换为输入地址中的用户名。使用列表 6.10 所示的 `virttable`，发往 `pat@other.org` 的邮件将投递到 `pat@local.org`，发送到 `doris@other.org` 的邮件将转发到 `doris@local.org`。

这是一个强大的功能。显然，它可以用于在更改域名时缓解过渡，但那是一种罕见的情况。更重要的是，当你销售的产品与你的官方域名没有明确关联时，可以使用此功能。假设你经营一家销售派对产品的在线商店。你域名的真实名称是 `stuffycorporation.com`，但你还拥有 `funstuff.com` 和 `happythings.com`。`virttable` 中的以下两行无论邮件投递到哪个域名，都会将邮件路由到正确的员工：

```
@funstuff.com             %1@stuffycorporation.com
@happythings.com          %1@stuffycorporation.com
```

列表 6.10 中的最后一行显示，`+detail` 语法中的详细值可以作为 `%2` 传递给出站地址。发送到 `sales+info@thatplace.com` 的邮件将投递到 `info@newplace.com`，而发送到 `sales+orders@thatplace.com` 的邮件将投递到 `orders@newplace.com`。注意，使用 `+detail` 语法必须在 `virttable` 的第一个字段中通过在虚拟域名地址前放置 `` `+ `` 来指示。对于用户来说，即使不使用 `+detail` 语法，电子邮箱也已经足够复杂了。因此，除非你有一个程序可以自动为用户生成这种内容，否则该语法很少使用。为了完整起见我们涵盖了它，但你可能不会在配置中使用它。

在 Sendmail 使用 `virttable` 之前，必须使用 `makemap` 将其转换为哈希数据库。列表 6.11 显示了 `virttable` 数据库的成功构建和测试。
