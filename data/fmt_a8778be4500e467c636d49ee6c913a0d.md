### 我该做如何追踪网络数据包？

HP 有一个名为 `nettl` 的工具，用于追踪 HP 节点上设备驱动看到的所有数据包（无盘包除外）。

这些包是由节点发送或发往该节点的数据包。

使用此工具时请遵循以下步骤：

1. **启动 `trace`——将数据存入 1 MB 的跟踪文件。** 数据将存储在 `/tmp/raw.TRC0` 和 `/tmp/raw.TRC1` 中。最新的数据始终在 `TRC0` 中。当它填满时，`TRC0` 被重命名为 `TRC1`，新的日志继续在 `TRC0` 文件中。它们填充非常快！

`/etc/nettl -tn pduin pduout -e all -f /tmp/raw`

如果你还需要追踪 `LOOPBACK` 接口，请考虑：

`/etc/nettl -tn pduin pduout loopback -e all -f /tmp/trace`

2. **一旦发生事件立即停止 `trace`！**

`/etc/nettl -tf -e all`

3. **将 `trace` 格式化为打印文件：**

`/etc/netfmt -N -n -l -f /tmp/raw.TRC0 [ -c /tmp/filter ] > /tmp/fmt0`

`/etc/netfmt -N -n -l -f /tmp/raw.TRC1 [ -c /tmp/filter ] > /tmp/fmt1`

- `-N` - 以“nice”格式打印（例如解释）
- `-n` - 打印 IP 地址而不是主机名
- `-l` - 不高亮字段（针对 hpterm）
- `-f` - 可选，使用过滤器文件（见下文“过滤”）

**注意：** `netfmt` 运行需要一些时间！`trace` 文件中会有大量信息——可能需要进行解释！

4. **过滤。** 创建一个过滤器文件来告诉 `netfmt` 你感兴趣的数据包。

例如，仅显示发往/来自 IP 地址 192.10.10.1 的数据包：

`filter ip_saddr 192.10.10.1`
`filter ip_daddr 192.10.10.1`

过滤掉所有的 NFS put 包（发/来自 UDP 端口 2049）：

`filter udp_sport 2049`
`filter udp_dport 2049`

过滤掉发往/来自端口 25（sendmail）的所有 TCP 数据包：

`filter tcp_sport 25`
`filter tcp_dport 25`

根据以太网地址过滤：

`filter dest 08-00-09-49-91-4a`
`filter source 08-00-09-49-91-4a`

你可以将这些组合在一起（过滤所有发往或来自某个 IP 地址的 NFS 包）。

`filter ip_saddr 192.10.10.1`
`filter ip_daddr 192.10.10.1`
`filter udp_sport 2049`
`filter udp_dport 2049`

### 有什么方法可以自动获取网卡的 MAC 地址吗？

以下是确定工作站网卡 MAC 地址的示例 LLA 代码。它仅适用于 HP-UX 9.x 或更早版本。对于 10.x 版本，你需要使用 DLPI 代码，该代码可以在 HPSL 上找到。文档编号为 CWA940907000，它提供了更详尽的解释。

```
/*
这里有一些你可以使用的示例代码，用于获取自己的工作站地址（也称为 MAC 地址或网卡地址）。请确保在编译时使用 `\-ln` 选项，因为 `net_ntoa(3)` 调用位于 `/usr/lib/libn.a` 中。

该程序通过以下命令编译：`cc get.c -o get -g -ln`。
*/
#include <stdio.h>
#include <netio.h>
#include <fcntl.h>

main(argc, argv)
int argc;
char *argv[];
{
 struct fis s_fis;
 int lanic;
 char *ascii[6];
 if (argc < 2) {
 printf ("Usage: %s <device file>\n", argv[0]);
 exit (1);
 }
 lanic = open(argv[1], O_RDWR);
 if (lanic < 0) {
 perror("Error in opening %s", argv[1]);
 printf("Error = %d\n", lanic);
 exit(1);
 }
 s_fis.reqtype = LOCAL_ADDRESS;
 s_fis.vtype = INTEGERTYPE;
 ioctl(lanic, NETSTAT, &s_fis);
 net_ntoa(ascii, s_fis.value.s, 6);
 printf("Station address of %s is %s\n", argv[1], ascii);
 s_fis.reqtype = PERMANENT_ADDRESS;
 s_fis.vtype = INTEGERTYPE;
 ioctl(lanic, NETSTAT, &s_fis);
 net_ntoa(ascii, s_fis.value.s, 6);
 printf("Permanent Station address of %s is %s\n", argv[1], ascii);
 close(lanic);
}
```

### 我有一台 9.x 机器，我想检查特定的 fileset 是否已安装。我该如何操作？

你可以在你的机器上创建一个脚本，检查所有文件是否安装在正确的位置。然而，它不会检查文件权限或文件是否在内核中。

```sh
#!/bin/sh
FSET=/etc/filesets/$1
if [ "$FSET" = "" ]; then
 echo "syntax of command $0 Fileset "
 exit 1
fi
if [ ! -f $FSET ]; then
 echo "Fileset $FSET not found"
 exit 1
fi
# simple test to see non zero size of any type
while read File
do
 if [ ! -s $File ]; then
 echo "$File not found"
 fi
done < $FSET
exit
```

- STREAMS，拥有脚本 `/usr/bin/strvf`

### HP-UX 9.x 和 10.2 有什么区别？

最大的变化是从UE 桌面转向 CDE（通用桌面环境）。这是未来发行将取代 VUE 的新标准桌面。主要区别如下：
- 新且可自定义的 Front Panel
- 支持 MIME 的邮件应用程序
- 图形日历
- 图形打印管理器
- 新终端仿真器
- 操作和数据类型更改
- ToolTalk 消息支持
- 桌面应用程序注册
- Athena Widget 库 `Xaw`
- X 杂项库 `Xmu`
- Imake

HP 在遵循 AT&T SVR4 和 OSF/1 标准后实施了新的文件系统布局。文件被组织为静态与动态、可执行与配置数据等。此外，操作系统软件与应用程序分开存储。系统共享文件与主机特定文件分开存储。

普通用户可以访问 SAM，但是有限的。指定的用户可以获得更多 SAM 功能或其他可能是 SAM 部分的自定义工具。在某些情况下，这些用户在执行 SAM 函数时会被提升为超级用户。此外，某些命令被修改了：
`du -k --` 以 1024 字节块报告磁盘占用，而不是 512 字节。
`csh --` 可以内置命令 `limit`，并在 `csh` 启动时设置 `LINES` 和 `COLUMNS`。
`passwd --` 新的密码过期选项。

### 从 10.1 到 10.2 有哪些变化？

两者之间的不同之处：
- 大文件系统——最大文件系统大小从 4 GB 增加到 128 GB。
- 大文件——最大文件大小为 128 GB。
- 大用户 ID——最大 UID 为 2,147,483,646，或 `$2^{31}$` 减 2。
- 许多补丁已整合进 10.20。
`du -k --` 以 1024 字节块报告磁盘占用，而不是 512 字节。
- 通用桌面环境——CDE 是新的行业标准桌面，将在未来发行中取代 VUE。

### 10.x 中的所有文件系统都在哪里？`/usr/local` 去了哪里了，`/usr/contrib` 用什么？

以下是几个标准目录及其内容的简短列表：
- `/opt`: 可选的 HP 软件包，如 ANSI C & C++ 编译器和调试器。
- `/opt/hppd`: 预编译的 HP 公有软件，从匿名服务器 http://hpux.cae.wisc.edu/ 或 http://hpux.cs.utah.edu/ 下载。
- `/usr/contrib`: 由本地运维组在他们的软件库中编译和维护的不支持、第三方或公有软件。例如：nn, gzip, Gnu 工具和 perl5。
- `/usr/local`: 用户自行安装或针对特定机器的工作站唯一软件包。该目录是全局可写的。

### HP-UX 10.x 自动挂载有什么新变化？

HP-UX 10.x 随带带有 `-hosts` 选项运行的自动挂载。你可以定义 `/net/hostname/directory/...`，剩下的工作由自动挂载完成。

自动挂载是一个很好的功能，因为你不需要担心启动时出现错位置的导出 NFS 目录。如果与 NFS 服务器的连接以任何方式中断，挂载 NFS 的机器在启动时将挂起。

以下显示了你可以配合 `/sbin/set_parms` 使用的：

更改主机名：

` # /sbin/set_parms hostname`

更改 IP 地址：

` # /sbin/set_parms ip_address`

更改 DNS 服务器、域等：

` # /sbin/set_parms addl_netwrk`

或者像首次安装时一样设置所有内容：

` # /sbin/set_parms initial`

请务必小心此命令：如果没有先检查是否存在重复地址等情况，可能会导致灾难性的后果。

### 我应该在 PATH 和 MANPATH 变量中包含哪些内容？

至少，你应该在 `PATH` 语句中添加以下内容：

- `/usr/contrib/X11/bin`

### 为什么 `lpstat` 报告打印机处于离机，尽管它并没有故障？

### root 的 shell 在哪里？

root 的 shell 必须是 `/sbin/sh` 或 `/bin/csh`，并且必须在 `/etc/passwd` 中定义。无论 root 使用的是哪个 shell，它都必须位于根分区，因为当 `init` 需要使用 root shell 来运行启动脚本时，`/usr` 文件系统尚未挂载。

你必须在链接行中添加 `/lib/libPW.a` 库。

### 当我用 C++ 编译时收到消息 `pxdb: internal error. File won't be debuggable (still a valid executable)`。这意味着什么？

该错误的原因是程序 `/opt/langtools/bin/pxdb` 在尝试处理调试信息时终止了。由于发生了这种情况，它没有改动 `a.out`。
