
内存遵循某些管理物理和虚拟内存的规则。由于我们已经对物理内存芯片或内存卡有了概念，我们将提供虚拟内存的定义。虚拟内存是进程可以映射到其中的可寻址内存位置，这些位置独立于 CPU 的物理地址空间。通常情况下，进程可以超过物理内存的地址空间/大小，但仍然可以加载和执行。

系统管理员应该意识到，仅仅因为拥有固定数量的物理内存，并不应期望所有内存都能供用户程序使用。内核始终驻留在内存中，取决于内核的配置（如可调的内核表、设备驱动程序等），剩余量可以被分类为可用内存。对于系统管理员来说，了解系统在支持其环境时有多少可用内存是至关重要的。大多数系统会在启动期间显示内存统计数据。建议考虑使用较小的内核以释放资源。

我们学到进程具有定义良好的结构，并拥有特定的控制数据结构，内核在进程的生命周期内使用这些结构管理进程。内核使用的最重要的数据结构之一是地址空间（`vas`）。关于这些结构布局的更详细描述，请查看你系统 `/include` 下的 `vas.h`/`as.h` 文件。

每个进程都存在一个虚拟地址空间，用于跟踪逻辑段或区域，这些区域指向进程的文本（代码）、数据、`u_area` 和内核栈；共享内存；库和映射内存文件。进程级区域保护并维护映射到进程的页数。每个段也有自己的虚拟地址空间。多个程序共享进程的文本段。数据段持有进程的已初始化和未初始化（`bss`）数据。这些区域可以随着进程的执行而改变大小。

`u_area` 和内核栈包含内核使用的信息，且是固定大小的。用户栈包含 `u_area` 中；但其大小在执行过程中会发生波动。内存映射文件允许程序员在内存中工作时完成将结果写入文件。否则，加载到内存中的文件大小将受到限制（查看你的系统文档）。共享段通常由进程设置并使用，以便与其他进程共享数据。例如，程序员可能希望通过向共享内存段写入数据向其他程序传递消息，并让访问共享内存的程序读取该消息。共享库允许程序在运行时链接到常用代码。共享库减少了执行进程所需的内存量，因为内存中只需要一份代码副本。每个进程在需要时访问该内存位置处的代码。

当程序开始运行时，内核设置其数据结构（`proc`、虚拟地址空间、进程级区域）并开始在用户模式下执行进程。最终，进程将访问不在主内存中的页（例如，这些页不在主内存中工作）。这是一个页错误。当这种情况发生时，内核将进程置起，从用户模式切换到内核模式，并尝试加载进程请求的页。内核搜索虚拟地址所在的段（文本、数据或其他进程级区域）。它将找到包含读取该页所需信息的实际区域。

内核现在必须找到一个空闲页来加载进程请求的页。如果没有空闲页，内核必须通过分页（`page`）或交换（`swap`）页来为新页请求腾出空间。如果存在某些可用空间，内核将从磁盘调入块页。该块包含了请求的页以及可能由进程需要的额外页。最后，内核为新加载的页建立权限和保护。内核唤醒并切换回用户模式，以便进程开始使用所请求的页。页并不是在进程请求执行时才调入内存的。这就是为什么该系统被称为请求分页系统。

注意：动词 "`page`" 指的是在系统内存和磁盘交换区之间为进程移动单个内存块。`pagesize` 定义在 `/usr/include/limits.h` 头文件中。有关分页的定义请参阅 RAM I/O。

内存管理单元（`MMU`）是一个处理虚拟地址空间到物理内存翻译的硬件组件。内存管理单元防止进程访问另一个进程的空间，除非被允许这样做（保护性异常）。转换陆表缓冲区（`TLB`）是一种维护最近使用的虚拟空间到物理地址翻译的硬件缓存。它由内存管理单元控制，以减少系统中发生的地址翻译次数。

## 输入和输出管理

简单的输入/输出是硬件设备与软件之间的数据控制。系统管理员关注两个级别的 I/O。第一层涉及用户地址空间和内核地址空间；第二层涉及内核地址空间与物理硬件设备之间的 I/O。当数据写入磁盘时，第一层 I/O 子系统将数据从用户空间拷贝到内核空间。然后数据从内核地址空间传递到 I/O 子系统的第二层。此时，物理硬件设备激活其自身的 I/O 子系统，确定数据的最佳可用位置。

`OEM`（原始设备制造商）`UNIX` 配置对于许多环境是可以的，但没有考虑到网络流量或系统上特定应用程序的行为。系统管理员发现他们需要重新配置系统的 I/O 以满足用户预期和应用程序的需求。你应该使用默认配置作为起点，并随着对系统资源需求的经验增加，调优系统以达到峰值 I/O 性能。

`UNIX` 带有许多有助于监控性能的工具。以下列表是这些工具的一部分：

- `sar`
- `iostat`
- `ps`
- `vmstat`

以下列表是这些工具的一部分：

你会发现，随着新作业的提交以及资源释放得不够快，系统负载将迅速增加。随着磁盘为了满足分页和交换调用而变得 I/O 密集型，性能会随之下降。内存过载会迫使系统变成 I/O 和 CPU 密集型。然而，一旦你确定问题出在内存，你会发现 RAM 比向系统中添加另一个 CPU 要廉价得多。

## 硬盘 I/O

无论你的系统使用模式如何，一些简单的配置考虑都能帮助你获得更好的 I/O 性能。需要考虑的因素是磁盘和磁盘控制器的布局以及硬盘的速度。

最佳策略是将磁盘负载尽可能均匀地分布在所有控制器上。如果你有一个具有多个 I/O 带的大系统，请将磁盘驱动器均匀地分配到各个总线上。大多数磁盘控制器允许你从控制器通道串联磁盘驱动器。为了获得绝对性能，请将磁盘分布在所有控制器上。如果你的系统有许多都需要进行顺序传输的用户，这一点尤为重要。

小型计算机系统接口（`SCSI`）设备是指符合美国国家标准协会（`ANSI`）将智能接口外设连接到计算机标准的设备。`SCSI` 总线是 `SCSI` 适配器卡上的串联结构，用于互连 `SCSI` 控制器。每个适配器将总线与设备接口，并具有在控制器上设置的不同 `SCSI` 地址。此地址决定了 `SCSI` 设备赋予的优先级，地址越高优先级越高。当你加载系统时，可以将频繁访问的数据存放在 `SCSI` 地址最高的硬盘上。信道顶端的数据访问时间较短，负载均衡可以增加该系统数据的可用性。

在确定了控制器和驱动器在系统上的最佳位置后，你还有最后一项提高性能的措施。在添加磁盘时，磁盘的寻道时间是其性能的唯一重要指标。不同的进程在访问文件和从不同区域读取时会同时访问磁盘。

磁盘的寻道时间是磁盘磁头从一个轨道移动到另一个轨道所需的时间。寻道时间受磁头从一个轨道移动到另一个轨道距离的影响。在轨道之间移动磁头所需比将这些磁头跨越整个磁盘所需的时间短。你会发现寻道时间是非线性测量值，它考虑了磁头在新位置上必须加速、减速并稳定。这就是为什么磁盘通常会指定最小、平均和最大寻道时间。寻道轨道的时间与传输数据花费的时间比例通常为 10:1。总寻道时间越短，你的性能或改进就越大。

在硬盘上添加分页和交换文件的一个问题是，某些系统管理员可能会用此为系统添加更多 RAM。这种方法并不行。你最多能希望的只是暂时避免根本原因——物理内存不足。系统管理员可以做的一件提高性能的事，就是准确地平衡磁盘。

不要忽视 I/O 调优中显而易见的升级路径。如果你了解系统的配置以及你打算如何使用它，那么购买不需要或无法解决你问题的设备的概率就会小得多。

### 文件系统概念与格式

文件系统有两个内涵。第一个是完整的层次结构树；第二个是磁盘设备上的集合。将文件系统可视化为在最高层有一个根节点（`ROOT`），所有其他节点以树状方式从根节点延伸（见图 19.5）。

超级块是文件系统的关键。它是一个 8 KB 的磁盘空间块，维护文件系统的当前状态。由于其重要性，内存和每个磁道组中都维护了一个副本。内存中的副本会随着事件过期而更新。更新守护进程是调用内核将缓存的超级块、修改的索引和缓存的数据块刷新到磁盘的实际进程。超级块维护以下静态和动态信息。星号表示动态维护的信息。

- 文件系统大小
- 索引节点（`Inodes`）数量
- 空空间位置
- 磁道组数量
- 分的大小和数量
- 块大小和数量
- 超级块、磁道组、索引节点和数据块的位置
- 总空块数
- 总索引节点数
- 文件系统状态标记（清洁标记)*

从列出的信息可以看出，超级块维护文件系统的完整性和所有相关信息。为了防止灾难性事件，操作系统在磁道组中存储超级块副本。替代超级块的位置可以在 `/etc/sstab` 中找到。当系统管理员使用 `fsck` 恢复替代超级块时，将被要求提供该块的位置。再次，寻找信息的唯一地方是 `/etc/sstab`。

磁道组是轨道的聚合，默认为 16 个轨道，拥有自己的一组索引节点和空空间映射。这样做是为了提高性能并减少磁盘延迟。

> 注意：交错因子（`interleave factor`）是决定磁盘驱动器扇访问顺序的值。

圆柱组的布局如下：

- 启动块 (`Boot block`)
- 主超级块 (`Primary superblock`)
- 冗余超级块 (`Redundant superblock`)
- 圆柱组信息
- `Inode` 表
- 数据块

只有当这是第一个圆柱组时，才会存在启动块和主超级块；否则它们可能会被数据填充。

`Inode` 是固定长度的条目，其长度根据实现的操作系统而异。`SVR4` 实现中，`UFS inode` 为 128 字节，`S5 inode` 为 64 字节。`Inode` 维护了关于文件的所有相关信息，文件名和数据除外。`Inode` 维护的信息如下：

- 文件权限或模式
- 文件类型
- 硬链接数
- 所有者
- 文件所属组
- 文件的实际大小（字节）
- 时间戳
  - 文件最后修改的时间/日期
  - 文件最后访问的时间/日期
  - 最后一次修改 inode 修改的时间/日期
- 单级间接块指针
- 双重间接块指针

## 内核配置

内核配置是一个详细的过程，系统管理员在此更改计算机的行为。系统管理员必须记住，单个参数的更改可能会影响其他内核子系统，从而使管理员面临“意想不到的后果”。

### 何时需要重建内核

内核组件通常分为四大类，如果对这些任何一组进行更改，则需要重新配置内核。

- 子系统——特殊功能所需的组件。
- 转储设备——当发生崩溃（`panic`）时系统转储存储在此。
- 可配置参数——这些是调优参数和数据结构。
- 设备驱动——这些处理调制调器、打印机、磁盘、带驱动器、内核内存和其他物理接口。

### HP-UX 10.X

重建内核有两种方法：

#### A. 使用系统监控 (`SAM`)

步骤 1—运行 `SAM` 并选择“Kernel Configuration”。

你现在可以看到以下识别出的组件：
- 子系统
- 可配置参数
- 转储设备
- 设备驱动

步骤 2—选择所需的组件并进行相应的更改。

步骤 3—现在回答提示，内核将会被重建。

步骤 4—它还会提示你是现在还是稍后重启内核。根据更改的重要性和系统的可用性来回答此提示。如果你对现在重启系统回答“YES”，则无法撤销。关键是在收到该提示之前就知道你打算做什么。

#### B. 手动方法

步骤 1—通过输入命令行进入内核构建区域。

```bash
cd /std/build
```

步骤 2—第一步是通过输入命令行从当前系统配置创建一个系统文件。

```bash
/usr/lbin/sysadm/system_prep -s system
```

这将当前系统配置放在文件系统中。没有规定必须命名为 `system`；可以使用任何你名称。

步骤 3—现在修改现有参数并插入未列出的可配置参数、新子系统和设备驱动，或更改转储设备。你可能在该文件中没有某个列出的配置参数的原因是：之前的内核使用了默认值。

步骤 4—下一步是创建 `conf.c` 文件，我们使用修改后的系统文件来创建它。记住，如果你没有使用 `system` 作为现有配置文件，请在显示 `system` 的地方插入你的名称。`conf.c` 文件包含可调参数的常量。输入命令执行配置程序。

```bash
/usr/sbin/config -s system
```

步骤 5—现在通过将驱动对象链接到基础内核来重建内核。
