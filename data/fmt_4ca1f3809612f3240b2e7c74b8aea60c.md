# Web 页面、Web 服务器与 MIME

Web 服务器是运行在系统上的软件，为客户端工作站提供文件、互联网和世界维网访问服务。

目前有多种商业化和共享软件的 Web 服务器可供选择。在大多数情况下，服务器系统的首选操作系统是一个或多个 UNIX 变体。

Web 服务器的主要工作是传输构成世界维网页面的 HTML 脚本。客户端的浏览器软件随后会解释这些 HTML 脚本，并在客户端系统的显示器上显示网页页面内容。

除了由 HTML 脚本指定呈现方式的文本外，网页还可能包含图像或其他多媒体内容，这些内容存储在服务器机器上的单独文件中。每当客户端浏览器发现一个引用此类文件的标签时，都会向服务器发出请求。Web 服务器软件必须找到该文件，对其进行适当编码（使用标准 MIME 方案），以便能够验证传输信息的完整性，并将文件发送到客户端机器。在客户端，浏览器随后对信息进行解码并进行显示、通过扬声器播放，或将其作为网页的一部分进行呈现。

网页还可能利用通用网关接口（CGI）调用。CGI 为 HTML 脚本提供了一种与运行在服务器系统或其他应用程序交换信息的方法。这些程序最常见的是通过 HTML 表单访问的数据库应用程序；然而，网页可能包含*服务端 HTML* 逻辑，这会导致服务器本身根据此之前发生的内容采取不同的操作。例如，网页表单可能会要求用户指定其浏览器是否支持框架（frames），例如。如果用户说不支持，服务器将向其工作站上的用户展示呈现一个不带框架的网页版本。Web 服务器软件负责处理服务器端的 HTML 逻辑。

在这些每种情况下，MIME 数据类型都在发挥作用。HTML 本身是一种 MIME 文本类型，网页多媒体内容的常用图像、音频和视频格式也是如此。即使是应用程序和私有数据类型，也必须进行正确编码以防止传输错误，而 MIME 为此目的定义了适当的编码方案。

许多服务器和浏览器都预配置了以识别标准的 MIME 数据类型。在能够正确处理之前，必须向服务器和浏览器软件定义某些标准类型，以及所有私有类型。

例如，要在 Netscape Navigator 浏览器（版本 3.01）中配置 MIME 数据类型，请从菜单树中选择 `options`（选项）、`general preferences`（常规选项）和 `helpers`（助手）。图 16.1 显示了助手界面如何允许你在 MIME 类型、文件扩展名以及接收到此类数据对象时要采取的操作之间建立关联。

## 结论

在本章中，我们简要查看了数据了数据格式标准，这些标准允许各种硬件和软件平台跨互联网和 Web 交换数据。理解 MIME 标准是如何建立的、它涵盖哪些数据格式以及网页和 Web 服务器如何使用它，可以帮助为你和系统用户正确配置电子邮件和浏览器软件。

MIME 是一种可扩展的互联网标准，是互联网电子邮件、世界维网以及大多数网络多媒体应用程序的基础性技术。

# 使用 CGI 编写网页

作者：Robin Burk; David B. Horvath, CCP; 以及 Matthew Curtin*

在这一节中，我们已经看到了如何使用 HTML 来指定屏幕文本的内容和外观，以及 MIME 如何扩展这些功能以包含图形、音频和视频等其他媒体。

网页上的这些元素是静态的。也就是说，它们是输出给用户的，而不请求或响应用户输入（可能存在允许用户指定在何时检索哪些媒体文件的热链接例外，除外）。

然而，网页并不限于静态信息显示。Web，事实上整个互联网，都是基于客户端-服务器架构的。客户端机器与 Web 服务器之间的交互提供了 Web 大部分的灵活性和实用性，对其快速增长以及将 Web 用于严肃的业务目的做出了巨大贡献。

在本章中，我们将查看一种启用性技术的客户端部分：通用网关接口（CGI）。在接下来的章节中，我们将也将从服务器端的角度来看 CGI。

## 什么是通用网关接口？

通用网关接口（CGI）定义了一个从 HTML 脚本到在服务器上执行的其他进程的平台无关的网关。CGI 在网页上最常见的用途是将从表单上收集的数据传递给数据库应用程序，并用适当的信息填充新屏幕。CGI 大部分时间在服务器上执行。在 *UNIX Unleashed* 的接几章中，我们将检查 CGI 的服务器端。

## CGI 如何工作

CGI 的客户端-服务器交互遵循一系列标准步骤：

1. Web 客户端（浏览器）通过 URL 连接到 Web 服务器进程。

2. Web 服务器将 HTML（以及构成所请求网页的其他文件）交付给客户端。一旦页面内容交付，连接将自动溶解。

3. 在客户端，HTML 脚本提示用户进行某些操作或输入。当用户响应时，客户端请求 Web 服务器建立新的新的通信连接。

4. 一旦连接建立，客户端将用户输入数据传递给 Web 服务器。

5. Web 服务器进程将此信息以及其他进程变量通过 URL 形式传递给 HTML 脚本指定的 CGI 程序。
