## 从头开始

让我们从头来看这个脚本。第一步是定义文件和变量。在这一部分我们定义了三个变量：我们的 `BINDIR` 目录，它是我们从菜单调用的所有 shell 脚本和程序所在的位置；第二个变量是密码服务器的主机。我使用单个服务器来存储密码列表，每隔 15 分钟，该主密码文件就会推送到整个区域内的所有其他服务器上。当我们有大量机器需要管理时，这种方法会让生活变得简单得多。当然，你可以使用 NIS 或 NIS+ 实现此功能。最后一个变量是运行菜单的机器的主机，`THIS_HOST`。

我们初始化两个变量：一个用于消息栏，另一个用于菜单选项，`$MSG` 和 `$OFT`。在初始化这两个变量后，我们设置了一个 trap（陷获）。这个 trap 只是初始性的。如果这个 shell 脚本接收到信号，我们只想让用户知道程序在捕获的信号上执行了，仅此而已。

现在是 `BEGINNING OF MAIN`（主开始）的内容。对于菜单，我们一直保持循环状态，直到用户选择 99 作为菜单选项。任何退出信号或用户选择 99 都会退出此循环。创建此循环最简单的方法是使用 `while` 循环，并将 99 指定为退出标准。循环每次开始时都会清除屏幕。然后我们显示标题栏，其中包含由 `$THIS_HOST` 变量指定的此机器的主机名。接下来，我们显示菜单选项。当前菜单有 8 个选项，加上 99 退出选项。

我们预设了消息栏，始终假设输入是错误的。如果输入有效，则用空格覆盖 `$MSG` 变量。在显示消息栏后，我们提示用户选择菜单。当做出有效选择时，我们跳转到 `case` 语句，执行所选的菜单选项。

## 适用于运维人员的菜单程序

注意消息字符串 `$MSG` 的长度始终是 24 个字符。这是一个要求，以确保消息栏和标题栏的长度相同（假设主机名为 8 个字符）。标题栏中的主机名也是如此。在每个 `case` 语句中，我们处理菜单选择并将 `$MSG` 置为全为空格，但第 5 项除外。我们通过注释掉代码并将 `$MSG` 改为“Option is Disabled”（选项已禁用）来禁用选项 5。这是临时移除某个选项执行的简单方法。`$MSG` 始终显示在消息栏中，无论“消息”是全为空格还是实际文本消息。假设主机名为 8 个字符，标题栏和消息栏始终为 80 个字符。你可能想添加一些代码来确保标题栏始终为 80 个字符。这是一个供你解决的小项目。

8 个菜单选项包括：

- 磁带管理 (Tape management)
- 磁带标记 (Tape labeling)
- 查询库中的卷类型 (Query type volumes in the library)
- 查询磁带卷 (Query tape volumes)
- 审计/检查已擦除的卷 (Audit/check-scratch volumes)
- 打印卷类型审计报告 (Print type volume audit report)
- 修改密码 (Change password)
- 启用所有打印队列 (Enable all print queues)
- 99—退出

对于脚本中的每个有效菜单选择，要么执行本地命令，要么执行外部程序或 shell 脚本。你必须修改此菜单脚本以适应你的需求。不要假设脚本中列出的菜单选项中的 TSM 命令在不修改的情况下运行。这些菜单条目只是你希望运维人员处理的任务类型的示例。每个环境都是不同的，而且某些运维人员比其他人更有能力。

为了安全起见，我建议将此 shell 脚本名称添加到用户的 `$HOME/.profile` 末尾，并在该脚本名称后跟上 `exit` 命令，作为用户 `.profile` 的最后一项。这种方法允许操作人员登录并运行菜单中的任务。当选择 99 时，菜单退出，用户由于 `exit` 命令注销系统，而永远看不到命令提示符。

在第 14 章中，我们学习了安装和配置 sudo，它代表“super user do”（超级用户执行）。菜单是使用 `sudo` 的绝佳地方。其主要优势之一是你保留了你做了什么以及命令何时执行的审计轨迹。如果出现问题，`sudo` 日志应该是要检查的地方之一。

# 构建 broadcast.ksh Shell 脚本

当我开始写这一章时，它本应该是五页左右。由于我跟进了更多关于广播消息的想法和选项，我不得不扩展这一章，以将这些想法包含进来。基本思想是从 Unix 系统向网络中特定的 Windows 机器发送消息。我开始考虑将消息发送给一组具有共同目的的用户。例如，我们可以有如下所示的个人用户列表：Unix、DBA、ORACLE、DB2、APPLICATION 等。然后，我们有一份业务中所有 Windows 机器（或至少是一个部门）的默认列表。

考虑到所有这些因素，我开始重写一个已经运行的 shell 脚本。在接下来的章节中，我们将这些部分组合在一起，创建一个非常有效的 shell 脚本，你可以轻松地根据需要对其进行定制。让我们从向所有用户发送消息的默认行为开始。

## 向所有用户发送消息

原始 shell 脚本的基础是一个节点主列表，在某些地方它可能用用户名表示，在另一些地方则用节点名称表示。这个节点或用户列表在 `for` 循环中被逐个读取。每读取一个节点名称，它就会被放入 `smclient` 命令中。语句会在一系列循环迭代中发送到所有节点，直到所有目标节点都处理完毕。对于这一基本功能，我们只需要一个包含节点（或用户）名称的文件以及一个用于处理文件中每个节点名称的 `for` 循环。这是简单版本，构成了本章发送消息的基础。请参考列表 25.1，并注意**粗体文本**。

```bash
# 定义包含节点/用户列表的列表。

WINNODEFILE="/usr/local/bin/Winlist"

# 将列表加载到 WINLIST 变量中，但忽略

# 文件中任何以井号 (#) 开头的行。

WINLIST=$(cat $WINNODEFILE | grep -v '^#' | awk '{print $1}' | uniq)

# 询问用户要发送的消息

echo "\nEnter要发送的消息 (完成后按回车)"

echo "\nMessage => *"

read MESSAGE

for NODE in $WINLIST
do
    echo "$MESSAGE" | smbclient -M $NODE
done
```

**列表 25.1** 广播消息的代码段。（续）

在列表 25.1 的代码段中，我们首先定义了包含消息目标节点（用户）的列表文件。在定义了节点列表后，我们将文件内容加载到 `WINLIST` 变量中。我们希望让用户能够使用井号 (#) 注释掉 `$WINNODEFILE` 中的条目。我们还希望用户能够在列表文件的节点/用户名称之后添加注释。为了增加灵活性，我们在 `WINLIST` 变量赋值中添加了一些过滤。注意在这一次赋值中，我们使用了 `grep` 和 `awk` 来执行过滤。首先是 `grep` 命令。在这一语句中我们有：

```bash
grep -v ^#
```
