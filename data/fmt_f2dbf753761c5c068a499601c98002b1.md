
将 Linux 移植到新的硬件平台可能是一项艰巨的任务。坦率地说，有几个嵌入式 Linux 工具包的设计是为了简化构建运行你设备的二进制文件的工作。某些工具包（如 Lineo 的 Embedix 和 Monte Vista 的 Hard Linux）具有很广泛的针对性，能够在许多处理器上运行许多不同的应用程序。另一些工具包来自较小的公司，专注于更窄的处理器 set。还有一些工具包，如 PeeWeLinux，并不是由公司分发的产品，而是在传统的开源模型下由一群志同道合的黑客构建的项目。

在寻找嵌入式 Linux 工具包时，有几点需要考虑：

- 硬件支持。Linux 是否包含了你想要使用的处理器的支持？如果工具包尚未支持该处理器，工具包供应商是否有能力足够快地开发以满足你的需求？如果是，费用是多少？它符合你的预算吗？
- 文档。该工具包的文档是否完善？所有涉及的程序都有文档吗？文档是否涵盖了高层概念（如架构白皮书）和低层文档（如如何构建二进制文件、如何将你的软件添加到代码库中，以及用于构建和运行时软件的参考手册）？
- 适应性。嵌入式 Linux 工具包对你将使用的特定应用程序适应性如何？如果这是一个非常窄的工具包，而你将把它用于多个项目，那么更改工具包以适应不适合它的项目将涉及多少工作？
- 开发支持。工具包公司提供什么样的开发支持？价格昂贵？如果你需要修复错误、回答问题或编写设备驱动程序，你多快能得到公司的回复？是否有供产品用户使用的邮件列表（listerv）？如果有，它的活跃程度如何？是否有公司的人在列表中回答问题？
- 现场升级能力。工具包中是否提供了在现场升级软件的功能？工具包公司是否提供交付这些升级的手段，还是留给你自己处理？
- 用户界面。如果你的应用程序需要某种用户界面，你有哪些选择？嵌入式 Linux 工具包是否提供某种嵌入式视频界面？如果是，它占用多少空间？如果不是，是否有某种基于 Web 的界面用于配置？

请注意，开源项目可能对图形界面没有任何支持。几个 Web 项目和几个商业产品旨在构建小型 footprint 的图形用户界面。有关更多信息，请参阅 http://www.linuxdevices.com/articles/AT9202043619.html。
- 历史记录。工具包供应商是否有客户在现场创建过类似产品的案例？该供应商在使用该工具包方面的成功程度如何？

## 内核特性

Linux 内核运行在各种硬件架构上——从手持设备到大型机应都有。为了支持这种可扩展性，内核是高度可配置的。配置内核有几种方法（注意我这里“配置”一词用得比较随意）：

- 在内核源码根目录下输入 `make config`、`make menuconfig` 或 `make xconfig` 会运行标准的内核例程。你可以开启或关闭选项以将其编译为模块，以便它们可以在运行时加载。
- 互联网上流传着成百上千——也许是数千个内核补丁。有些非常小——足够修复一个文件中的一个小错误。中等大小的补丁可能会影响几个文件并添加对特定硬件设备的支持。大型补丁会添加或影响几十个文件，并添加对新架构的支持。应用补丁通常会为描述的内核配置界面添加新问题或整个屏幕。
- “配置”内核以精确执行你想要的操作的真正方法是你自己对其进行修改（hack）。直到最近，这仍然是那些有时间和耐心的人的练习。

## 实时操作系统

在大多数情况下，计算机完成任务所需的精确时间并不重要。例如，当有人按下键盘按键时，他们期望字母“立即”出现——但“立即”到底有多快？它可能是从几十毫秒到几百毫秒不等。你可能察觉不到 50 毫秒（约 1/20 秒）以内的任何计时差异。然而，计算机中某些操作的时机是关重要的。

# 第1章 软件考虑

例如，大多数现代汽车都配有防锁刹动系统。在这些系统中，特殊的传感器会检测一个或多个车轮何时开始“锁死”——这会导致车辆（及其乘客！）滑过的危险情况。在这些情况下，传感器检测到轮子开始锁定并立即减小该轮的制动力是至关重要的。你是否曾经用过这样的计算机系统：启动一个新程序后，整个系统就会出现几秒钟的无响应？想象一下，如果控制你防锁刹车的计算机也同样忙碌且无响应——而此时正好有一只鹿跳到了你的车面前！这就是你需要所谓的“实时”的情况。

硬实时操作系统（Hard real-time OS）保证无论发生什么其他情况，对事件的响应都会在固定期间内发生。例如，当检测到轮锁时，该轮必须在指定的毫秒数内减小制动力。在这个示例中，系统对轮锁状态的响应时间有一个硬性限制。首先，因为响应可用时间有绝对限制，其次是因为如果系统未规定的时间限制内响应，将会发生糟糕的事情。任务的这两个特征清楚地表明，该任务需要硬实时操作系统。

相反，对于软实时操作系统（Soft real-time OS），当事件发生时，系统将尽力在平均响应时间内处理该事件。例如，在玩《雷云三角III》游戏时，当玩家向另一个玩家发射火箭时，预计游戏程序会在屏幕上画出火焰爆炸的画面、发出声音，并减少对手的血量。在游戏现有事件的基础上增加了这些复杂性，在渲染爆炸和播放额外音频时，游戏帧率可能会稍微下降，这些任务需要额外的 CPU 时间。如果帧率从每秒50 帧（fps）下降到爆炸期间的40 帧，也不会造成任何伤害——玩家继续享受游戏，因为系统仍然“足够快”。足够快”是软实时系统的定义性特征。在这种情况下，系统不需要固定速率，即使帧率略微下降也不会产生危害。

软实时和硬实时系统都是用的，但它们的用途有明显不同。事实上，硬实时操作系统通常同时兼顾硬、软实时系统。

如下所示，若干属性将实时操作系统与标准操作系统区分开来：

- **响应时间可预测性**。硬实时操作系统保证某些操作的时间在其规定的限制内是精确的。这些响应时间比典型操作系统快得多——它们的测量单位是微秒（秒的百万分之一），而不是毫秒（秒的千分之一）。
- **可调度性（Schulability）**。在硬实时操作系统中，进程可以被调度在未来的某个非常精确的时间或以非常精确的间隔执行。同样，这种精度是微秒级，而不是毫秒级。
- **压力下的稳定性**。在实时系统中，处理器接收到的来自不同源的信号远超过其处理能力；然而，其中某些信号比其他信号重要得多，必须被识别并处理。快速高效地对大量不同信号进行优先级排序是良好实时系统的另一个标志。

有关嵌入式实时系统的更多细节，请参阅 Rajkumar 等人的《The Concise Handbook of Linux for Embedded Real-Time Systems Version 1.0》（宾夕法尼亚州匹兹：TimeSys 2000），第5页。此外，www.RealTimeLinux.org 提供了大量关于实时 Linux 的信息。

## 创建或获取开发环境

在开始编码之前，你必须为你所选择的微处理器或微控制器创建一个或获取开发环境。你需要一个 C 编译器、汇编器（编译器的一部分）、链接器、运行时库、调试工具，可能还需要一个仿真器。获取开发环境最快的方法是从嵌入式 Linux 工具包中获取。通常这些是免费的或价格低廉。

## 引导内核

计算机如何将操作系统加载到内存并启动它，是大多数软件开发者永远不需要考虑的问题。我们大多数人工作在 PC 或类似的平台上，这些平台拥有 BIOS，由它完成设置硬件以及寻找并加载操作系统加载器（例如 LILO 或 GRUB）到 RAM 中的脏活，以便内核启动。我们最多需要考虑的就是使用哪种操作系统以及如何正确配置。
