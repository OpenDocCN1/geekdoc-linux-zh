
## 描述
Korn shell 由 AT&T 实验室的 David Korn 编写设计为与 Bourne shell 兼容并提供与 C shell 类似的交互功能。Korn 包含了整数算术、数组和字符串处理等方便的功能。Korn 比 C shell 快，几乎所有为 Bourne shell 编写的脚本都可以运行。

Korn shell 命令是 `/usr/bin/ksh` 或 `/usr/bin/sh`。这两个命令是相同的。

`/usr/bin/rksh` 是命令解释器 `ksh` 的受限版本，受到标准 shell 的控制。

Korn shell 的默认提示符是美元符号 (`$`)。根用户提示符是井号 (`#`)。

Korn shell 使用以下定义。
- 元字符是以下字符之一：`&` `(` `)` `|` `<` 换行符 `Tab`。
- 空格是 `Tab` 或空格。
- 标识符是以字母或下划线开头的字母、数字或下划线的序列。标识符用于函数和变量。
- 单词是用非引号元字符分隔的字符序列。
- 命令是 shell 语言的字符序列。shell 读取每个命令并直接执行或通过单独命令执行操作。
- 特殊命令是不创建单独进程执行的命令。除了记录的副作用外，特殊命令可以实现为单独命令。

## 初始化
如果通过 `exec(2)` 调用 shell 且参数 `0` 的第一个字符是 `-`，则假设该 shell 是登录 shell，并按以下顺序读取命令：
1. 执行 `/etc/profile`。
2. 如果当前目录下的 `.profile` 或 `$HOME/.profile` 存在，则执行其中的命令。
3. 如果对环境变量 `ENV` 的值进行参数替换后命的文件存在，则读取该文件的命令。如果不存在 `-s` 选项且 `arg` 为 `-`，则对第一个 `arg` 执行路径搜索以确定执行的脚本名称。脚本 `arg` 必须具有读取权限，忽略任何 `setuid` 和 `setgid` 设置。如果在路径中未找到脚本，则将 `arg` 视为内置命令或函数处理。然后按照描述读取命令。

## 586 ksh, rksh

以下选项在 shell 被调用时会被解释器进行解析。

- `-c`
  从 `command-string operand` 操作数中读取命令。将特殊参数 `0` 的值设置为 `command-name` 操作数的值，并按顺序从剩余的 `arg` 操作数设置位置参数（`$1,$2` 等）。也支持从标准输入读取命令。

- `-i`
  如果您指定了 `-i`，或者 shell 的输入和输出连接到终端（如使用 `io(2)` 所示），则该 shell 是交互式的。在这种情况下，忽略 `TERM`（以便 `kill 0` 不会杀死交互式 shell），并捕获且忽略 `INTR`（以便 `wait` 可以被中断）。在所有情况下，忽略 `QIT`。

- `-s`
  如果您指定了 `-s` 选项，或者没有剩余参数，则从标准输入读取命令。将 shell 的输出（特殊命令外）写入文件描述符 `2`。

## 受限 Korn Shell (Restricted Korn Shell)

使用受限 shell `rksh` 来设置登录名和执行环境，其能力比标准 shell 更具控制性。`rksh` 的行为与 `ksh` 相同，但禁用了以下操作：

- 切换目录（参见 `cd(1)`）。
- 设置 `SHELL`、`ENV`、`PATH` 的值。
- 指定包含 `/` 的路径或命令名。
- 重定向输出（`>`、 `|`、 `<` 和 `>>`）。
- 切换组（参见 `newgrp(1)`）。

这些限制在解释完 `.profile` 和 `ENV` 文件后生效。当执行的命令被发现是一个 shell 过程时，`rksh` 会调用 `ksh` 来执行它。因此，你可以提供可以使用标准 shell 全功能的 shell 过程，同时只允许受限的命令列表；此方案假设用户不会在同一目录下具有写入和执行权限。

这些规则的最终效果是 `.profile` 的编写者可以通过执行保证性的设置操作并将用户留在适当的目录（可能不是登录目录），从而对用户的行为拥有完全控制。

系统管理员通常会设置一个命令目录（即 `/usr/bin`），供 `rksh` 安全地调用。

## 交互式操作

在启动处理完成后，交互式 Korn shell 开始从终端读取命令。默认提示符对于普通用户是美元符号 (`$`)，对于超级用户是井号符号 (`#`)。

## ksh rksh

以下列表描述了使用 `ksh` 作为交互式 shell 的一些关键特性。

- 命令行编辑。`ksh` 提供了类 emacs 和类 vi 的界面，你可以使用它们来编辑当前行。你也可以使用相同的界面对之前的命令进行修改，`ksh` 会将这些命令保存在历史文件中。
- 命令历史机制。`ksh` 使用历史文件来存储你输入的命令。你可以通过 emacs 或 vi 编辑器的指令或使用内置的 `fc` 命令访问历史文件。历史文件在不同的登录会话中维护，并可以被多个同时运行的 `ksh` 实例共享。
- 别名（Aliasing）。你可以通过为频繁使用的命令定义简写或别名，自定义名称和选项组合。
- 作业控制（Job control）。`ksh` 可以在后台作业结束后在提示符处显示完成消息。你可以停止作业并在后台处理与前端之间移动它们。
- 波浪号扩展（Tilde extension）。你可以符号化地引用任何用户的家目录以及你所在的目录。你不需要知道目录的名称或输入它。

当你从内部使用 Korn shell 时，它会在读取命令之前使用 `PS1` 的参数扩展值进行提示。如果在任何时刻你输入了换行符且 shell 需要进一步输入来完成命令，则会显示次级提示符（即 `PS2` 的值）。

## 编程语言操作

Korn shell 编程语言提供了以下优势：

- I/O 机制。你可以同时打开并读取多个文件。你可以为每个信息项指定打印列数。
- 算术评估。`ksh` 可以通过常量和 `ksh` 变量在从 2 到 36 的任何基上执行整数算术。
- 子字符串操作。`ksh` 可以生成基于 shell 变量的子字符串。
- 数组变量和属性。可以将字符串转换为小写或大写。你可以使用字符串或数字的一维数组。
- 函数设施。你可以在函数内部定义局部变量以便编写递归过程。你可以指定在函数终止时执行的代码。
- 协处理设施（Copiprocessing facility）。你可以在后台运行一个或多个程序，并发送查询以接收其响应。这种能力使能够将 shell 脚本作为另一个应用程序（如数据库管理系统）的前端。

**警告** — *由于潜在的安全风险，不建议设置 shell 脚本。*

## 命令

简单命令是由空格分隔的单词序列，前面可以跟一个变量赋值列表。第一个单词指定要执行的命令名称。如下面明确指定的，其余单词将作为参数传递给被调用的命令。命令名作为参数 `0` 传递（参见 `exec(2)`）。简单命令的值是其正常终止时的退出状态，或者如果异常终止，则为（八进制）`200+`（状态值列表参见 `signal(3)`）。

管道（Pipeline）是由一个 `|` 分隔的一个或多个命令的序列。除了最后一个命令外，每个命令的标准输出都通过 `pipe(2)` 连接到下一个命令的标准输入。每个命令都作为一个单独进程运行；shell 等待最后一个命令终止。管道的退出状态是最后一个命令的退出状态。

列表（List）是由 `|`、`&&` 或 `||` 分隔的一个或多个命令的序列。列表的退出状态是最后一个执行的命令的退出状态。

```
function identifier { list ; } identifier() { list ; }
```

定义一个被 `identifier` 引用的函数。函数的体是 `(` 和 `)` 之间的命令列表。（参见 [Functions]。）

## 时间管道 (time pipeline)

执行管道并将经过的时间以及用户系统时间打印到标准错误输出。

以下保留字仅在作为命令的第一个单词且被引号引用时会被识别。

```
! if then else fi case es for while until do { } function
select time [ [] ]
```
