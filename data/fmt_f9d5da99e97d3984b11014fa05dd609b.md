该脚本通过获取早些运行的结果（每晚发送给系统管理员）并将其粘贴到模式文件中来更新。更新方法是：通过将日期元素（`MMM DD HH:MM:SS`）替换为单字符通配符（点 `.`）——在可选的第二个数字前添加一个问号 `?`——并将其他变量数据（例如此示例中常见的 `PID` 数字）替换为正则表达式描述 `[0-9]+`（表示一个数字字符串），从而将其转换为正则表达式。

这些模式过滤了大部分内核启动消息、大部分来自 `diald` 的消息（当流量目标是外部网络时打开 `PPP` 连接的程序）以及 `pppd`、`innd` 和 `named` 守护进程。该设备是互联网的网关（通过调制解调器执行按拨连接路由），同时也是新闻和 `DNS` 域名服务器。（未显示忽略来自 `POP` 服务器的本地消息等规则。）脚本过滤掉每天预期发生（或无不足道）的内容，并将剩余部分通过邮件发送给系统管理员。

```bash
function rotate {
  cp $1 OLD/$($1).TODAY
  cp /dev/null $1
}

rotate mailog
rotate messages
rotate secure
rotate cron {
(
  echo "To: jimd"
  echo -n "Subject: Filtered Logs for: " date "+%a %m/%d/%Y"
  echo; echo; echo:
  echo "Security:"
  /root/bin/filter.log /root/lib/security.filter OLD.messages.$TODAY
  echo; echo; echo:
  echo "Messages:"
  /root/bin/filter.log /root/lib/messages.filter OLD.messages.$TODAY
  echo; echo; echo:
  /root/bin/filter.log /root/lib/cron.filter OLD.cron.$TODAY
  echo -e "\n--$Your Logging System\n\n"
) | /usr/sendmail -oi -t
```

`rotate` 函数将指定的日志文件复制到目录，并以适用于简单排序的格式追加名称——所有文件都通过 `ls` 命令按顺序列出。`cp /dev/null $1` 用于覆盖日志文件以避免创建匿名文件句柄。否则，则需要通知 `syslog` 守护进程其文件已被删除并强制其重启。

脚本的另一部分使用了一个带有几条命令的子 shell。它使用模式文件的名称和新复制的日志来调用我们的日志过滤脚本。

同一个脚本也可以被用于（使用不同的模式文件）来合并文件。`get_groups` 例程执行组的逻辑并集。一旦所有组文件都处理完毕，结果组将输出到标准输出。

这个程序并非完美的 `Perl` 示例。然而，它确实利用了嵌套数据结构，并且易于阅读。程序通过收集需要输出诊断信息到日志文件并开启调试的参数开始。剩余的参数假设是要合并的文件。

```perl
sub get_groups
(
  my($file, $groups) = @_;
  my($user, @k1) = @meremp;
  if ($debugLevel >= 1)
  {
    print("entering $file\n");
  }
  while($ARGV)
  {
    if ($ARGV[0] == "log")
    {
      open(STDERR,>>logfile) || warn("open of logfile failed!");
      shift;
    }elsif ($ARGV[0] == "debug")
    {
      shift;
      $debugLevel = $ARGV[0];
      shift;
    }
    else
    {
      last;
    }
    open($fh, $ARGV) || warn("$file: line \$, syntax error");
    while($line = <fh>)
    {
      if ($line =~ /^\s*(\w+)\s+(.*)$/)
      {
        $groups{$1} = $2;
      }
    }
    close($fh);
  }
  foreach ($key (sort(keys(%groups))))
  {
    printf("%s:%s:%s\n", $key, "password", $groups{$key});
  }
}
```

## `expect`

正如本章“缩写”部分提到的，`Tcl` 语言的 `expect` 变体对于系统管理员来说是有价之宝，他们经常面临自动化任务或重复执行任务。`expect` 通过打开伪终端设备并将应用程序端呈现为交互式终端来实现这一点。

## 安全

脚本用户偶尔能够以作者非意图的方式利用它们。在编写脚本时，应该考虑安全考量。一个很好的起点是 `CERT` 关于从 `CGI` 脚本用户提供的数据中移除元字符的建议.³

可能的攻击手段包括：

- 栈破坏。攻击者将恶意代码放置在内存某处以便执行。这通常通过缓冲区溢出来实现。
