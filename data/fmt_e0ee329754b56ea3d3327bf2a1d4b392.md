
# 后门线程机制

后门创建五个线程，负责系统监控、下载辅助模块以及清理旧的反弹 shell 连接。

## 线程 #1：已登录用户监控

线程 #1 处理已登录用户的监控。如果配置中的 `mode` 字段或 `mode` 的全局变量设置为 `1`，该线程使用 `who` 命令监控已登录的用户。它分析输出，如果注册的 `IP` 不是本地 `IP` 或 `C2` `IP`，则关闭 `C2` 连接。

## 线程 #2：C2 连接状态监控

线程 #2 负责监控 `C2` 连接状态。每次向 `C2` 发出有效请求时，全局 `C2` 连接结构中的时间字段都会被更新。如果距离上次向 `C2` 服务器请求已经过了半小时，该线程将关闭到 `C2` 的连接。

## 线程 #3：过滤模块下载与设置

线程 #3 下载并设置过滤模块。该线程首先使用变量检查模块是否已经下载。如果没有，该线程再次执行几个步骤：

1. 检查文件 `[SELF_PATH].506` 是否存在，并计算其内容的 `MD5` 哈希。
2. 向 `C2` 发送加密请求，请求 `C2` 服务器上可用模块的 `MD5` 哈希，并比较接收到的 `MD5` 哈希与现有的哈希。
3. 如果哈希不同，该线程向 `C2` 发出另一个请求，并将新接收的文件以相同的名称保存。
4. 读取 `/usr//11/b-sysgt4r.so` 文件中的数据；这可能是在感染的早期阶段存储的。该文件应包含一系列以竖线 (`|`) 分隔的值，并包含一系列用于替换可执行文件的指令。
5. 该线程在系统中搜索语句文件中列出的每个文件，并将其保存为 `[FILE_NAME], a`。
6. 最后，线程用新获得的 `S06` 过滤模块替换原始文件，并使其可执行。

所有这些步骤都允许威胁行为者围绕特定的系统可执行文件包装一层外壳。

## 线程 #4：用户登录监控与记录

线程 #4 监控并记录已登录用户。如果用户登录到 Linux 机器，且其 `IPv4` 地址不匹配本地 `IPv4` 地址或某个 `C2` 地址，其详细信息将被记录并发送到 `C2` 服务器。

## 线程 #5：清理旧的反弹 Shell 会话

线程 #5 负责清理旧的反弹 Shell 会话。首先，该线程监控反弹 Shell 会话。如果发现某个反弹 Shell 会话已近一个小时没有活动，该会话将被移除。

# C2 通信

在开始 `C2` 通信之前，会检查两个全局结构：一个包含指定连接 `C2` 时应使用 `TCP` 还是 `UDP` 的配置值；另一个指定如果存在已登录用户，是否应中断 `C2` 通信。如果这些检查中任何一个失败，恶意软件不会与 `C2` 建立通信。如果检查成功，后门程序分析 `C2` 地址，并在必要时将 `C2_domain` 解析为 `IPv4`。

接下来，恶意软件根据配置设置 `TCP` 或 `UDP` 模式的套接字，并尝试与 `C2` 服务器建立连接。如果连接成功，恶意软件启动一个线程来解析 `C2` 命令。在此首次连接 `C2` 服务器建立并创建 `C2` 命令线程后，后门程序执行一个无限循环，负责向 `C2` 服务器发送心跳。心跳包含以下值，它们组合在一起并用 `\t` 分隔：

- 发行版信息
- 系统架构
- 字符串 `root`
- 常量值 `\xc`
- `UDP` 数据包长度 `800`
- 自定义路径

如果对 `C2` 的请求失败，将重新建立与 `C2` 的连接；然后重新生成并发送心跳字符串。

## 过滤模块

在 `Linodas` v11 中，线程 #3 负责下载一个额外模块，该模块替换系统中所有指定的二进制文件。之前没有任何版本支持此功能。该过滤模块（图 2）是通过执行由行为者控制的 `C&C` 服务器上的 `ntf5s` (v11) 获得的，并存储为 `ntf5s.506`。该模块的任务是控制二进制文件的执行并监控其输出（图 3）。

每当系统尝试使用被替换的二进制文件时（无论是否带有参数），该模块都会启动。一旦执行，该模块检查配置文件是否存在于 `/usr/lib/lib5ysatlr.a`。此独立配置文件不会与模块一起下载。相反，威胁行为者使用 `Linodas` 反弹 Shell 将其放置在服务器上。模块从配置文件的 `para` 部分加载 `ip` 和 `name` 字段。模块将所有接收到的参数组合在一起，用空格分隔，并检查名称为 `[SELF_PATH]` 的原始二进制文件是否存在。

如果不存在，它会输出 `bash` shell 并退出。但是，如果文件存在，模块将使用接收到的参数执行该文件，并附加字符串 `2>&1`。此步骤将错误输出与标准输出合并，以便两者可以一起被操纵或查看。

当模块执行子程序时，它会读取输出的部分并按行拆分。每一行都通过一个过滤过程进行处理，其中包含配置文件中 `ip` 或 `name` 之一值的行将被忽略。如果该行通过过滤，它将被打印出来。威胁行为者可能将此模块部署为 `rootkit`，以过滤各种二进制文件中的 `IP`、用户名、进程名称或其他痕迹等任意值，以便收集由 `who`、`netstat`、`ps` 等命令提供的信息，从而在监控尝试中隐藏 `Linodas`。

# 结论

`DinodasRAT` 的 Linux 版本与中国的 `APT` 威胁行为者有关，自至少 2021 年以来已被反复使用。尽管 `Linodas` 与 Windows 版本有许多相似之处，但 Linux 恶意软件指向一个独立且单独的开发分支。`Linodas` 引入了具有单独配置文件和额外 `C2` 命令的附加模块，这些命令专注于设置和控制反弹 Shell、从日志中收集用户活动以及操纵本地文件内容。
