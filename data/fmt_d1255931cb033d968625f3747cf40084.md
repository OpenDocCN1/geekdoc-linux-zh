## 54.4 JVM的内存模型

前面提到，在`x86`和其他平台上，`JVM`的内存模型可以为：

- 局部变量数组(`Local Variable Array, LVA`)。它用来外部参数和局部变量。`iload`指令的作用是从`LVA`中提取值，而`istore`可以将值存储在`LVA`。
- 每个参数都是相同的参数单元，数据类型为`long`（长）或`double`（双）的数据都会占用两个参数槽。
- 操作数用于计算参数个数，或者向调用函数传递参数。`Java`程序不能直接运行在`x86`那样的环境，因此它必须通过明确的入栈、出栈指令才能访问栈，不能像汇编一样对栈进行搜寻。
- 堆用于存储对象和数组。以上三种内存模型相互独立、隔离。

## 54.5 简单的函数调用

`Math.random()`函数产生`0.0~1.0`之间的随机数。因此，如生成`0.0~0.5`之间的随机数，就要对上述结果进行除法运算：

```java
public class HalfRandom {
    public static double slot() {
        return Math.random()/2;
    }
}
```

指令`invokestatic`调用函数方法`random()`，并将结果保存在末尾`TOS`。这个值从被抛起，最终得到函数返回值。但是这些函数的名称是如何编码的？编译器使用了`Methodref`的表示法把调用函数的信息在常量池中。常量池里的数据属性符指向调用函数相关的类（`Class`）以及方法`NameType`属性。`Methodref`表达式的第一个字段（`Fieldref`里的第一个值为索引`#18`，实际上是指指针）对应一个`Class`名称（依索引查询`#18`、`23`常量），可以得到`java/lang/Math/Methodref`表达式的第二个字段（`Fieldref`里的第二个值）是方法名称的索引`#19`，这个索引对应方法名`NameType`（索引查询`#19`、`23`常量，可以得到方法名`random()`）。方法名由两个索引组成，第一个索引符号对应函数返回值的数据类型`“D”`—双精度浮点数。

① `JVM`能检查类类型的正确性。
② `JAVA`的反编译器能够从已经编译好的类文件中恢复出它的原始数据类型。
