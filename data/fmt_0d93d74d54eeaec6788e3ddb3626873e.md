## 内存占用

8MB 的默认大小相当保守。增加这个值可能是一个好主意——你应该尝试不同的增量，看看什么方案对你最有效：

### 默认大小

| PARAMETER | VALUE | DESCRIPTION |
|---|---|---|
| SHMVIRTSIZE | 8000 | # 初始虚拟共享内存段 |

### 新大小

| PARAMETER | VALUE | DESCRIPTION |
|---|---|---|
| SHMVIRTSIZE | 24000 | # 初始虚拟共享内存段 |

> **注意** 你可以保持其不变，先测试所有其他设置，最后再扩大内存。在本节末尾的示例中，重启引擎的输出将显示此结果，而不是更改它。最后更改内存占用，以防它出现问题。

## LRU 设置

请参阅你的*管理员指南* (`Administrator’s Guide`) 和其他 Informix 文档了解这些新设置的原理。记住，这里的重点是安装，所以我目前给你提供几个可以帮助提高性能的设置——剩下的由你来学习为什么要这样做。

### 默认值

| PARAMETER | VALUE | DESCRIPTION |
|---|---|---|
| LRUS | 8 | # LRU 队列数量 |
| LRU_MAX_DIRTY | 60 | # LRU 脏数据百分比开始清理限制 |
| LRU_MIN_DIRTY | 20 | # LRU 脏数据百分比结束清理限制 |

这些设置在几本专门 Informix 的书中都有介绍，将对你非常有帮助。USENET 新闻组 `comp.databases.informix` 中也对其中许多设置有持续的讨论。这里显示的内容基于经验以及在 Linux 上良好的性能改进。

### 新值

| PARAMETER | VALUE | DESCRIPTION |
|---|---|---|
| LRUS | 4 | # LRU 队列数量 |
| LRU_MAX_DIRTY | 5 | # LRU 脏数据百分比开始清理限制 |
| LRU_MIN_DIRTY | 1 | # LRU 脏数据百分比结束清理限制 |

## DBSPACETEMP 设置

你需要更改此项，以便你新的 tempdb dbspace 可以用于临时表和查询排序。

### 默认值

`DBSPACETEMP` ... # 默认临时 dbspaces

### 新值

`DBSPACETEMP` ... `tempdbs`

## 重启你的引擎

使用 `oninit` 命令 `$ oninit -v` 重启你的 Informix 引擎，并观察输出。一旦它启动，你就可以使用 `onstat -m` 命令查看更改：

```
rebel:root # oninit -v

Checking group membership to determine server run mode succeeded
```
