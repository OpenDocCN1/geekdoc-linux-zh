
`http://www.yoursite.com/some/old/dos/files/index.htm`

```
将被重定向到：
```

`http://www.yoursite.com/some/old/dos/files/index.html`

```

有关`status_code`的信息，请参阅`Redirect`指令（上一节）。

## RedirectTemp

`RedirectTemp`指令类似于`Redirect`指令。它告知客户端该重定向仅是临时的。请注意，`Redirect`指令默认也会产生临时状态。

**语法：**`RedirectTemp old_URL new_URL`

**上下文：** 服务器配置，虚拟主机，目录，每目录访问控制文件（`.htaccess`）

## RedirectPermanent

`RedirectPermanent`指令类似于`Redirect`指令。它告知客户端该重定向是永久的。请注意，`Redirect`指令默认产生临时状态，但您可以使用状态码`301`或关键字`permanent`作为状态，效果与该指令相同。

**语法：**`RedirectPermanent old_URL new_URL`

**上下文：** 服务器配置，虚拟主机，目录，每目录访问控制文件（`.htaccess`）

### ScriptAlias

`ScriptAlias`指令为物理目录路径创建别名。此外，请求中提供的任何文件名都被视为CGI脚本，服务器将尝试运行该脚本。

**语法：**`ScriptAlias alias "physical_directory_path"`

**上下文：** 服务器配置，虚拟主机

例如，以下指令可用于处理诸如`www.nitec.com/cgi-bin/somescript.pl`的请求。如果权限验证正确，服务器会尝试运行`somescript.pl`。请注意，`ScriptAlias`目录是不可浏览的：

```
ScriptAlias /cgi-bin/ "/www/nitec/public/cgi-bin/"
```

### ScriptAliasMatch

`ScriptAliasMatch`指令与`ScriptAlias`指令等效，不同之处在于它使用正则表达式，允许您定义动态别名规则，而不是固定别名。

**语法：**`ScriptAliasMatch regex directory`

**上下文：** 服务器配置，虚拟主机

例如，以下两个指令执行完全相同的功能：

```
ScriptAliasMatch "~/cgi-bin(.*)" "/www/nitec/public/cgi-bin$1"
ScriptAlias /cgi-bin/ "/www/nitec/public/cgi-bin/"
```

### mod_speling

`mod_speling`模块在Apache中默认未编译。它允许您处理拼写错误或大小写错误的URL请求。它会将请求的（拼写错误或大小写错误的）文档名称与请求目录中所有文档名称进行比较，以查找一个或多个紧密匹配项。

如果是拼写错误的文档请求，该模块允许单个拼写错误，如额外字符插入、字符遗漏或字符换位。如果是大小写错误的文档请求，则执行不区分大小写的文件名比较。无论哪种情况，如果该模块定位到一个与请求紧密相似的文档，它会向客户端发送重定向请求。如果存在多个匹配项，它会将列表发送给客户端供选择。此模块提供的唯一指令称为`CheckSpelling`。

`CheckSpelling`指令启用或禁用`mod_speling`模块。请注意，当拼写更正功能开启时，由于提供拼写错误文档请求所需的额外搜索，服务器可能会经历性能损失。

- 语法：`CheckSpelling On | Off`
- 默认设置：`CheckSpelling Off`
- 上下文：服务器配置，虚拟主机

> `mod_speling`模块仅适用于文件和目录名称。

### mod_vhost_alias

`mod_vhost_alias`模块允许您创建动态配置的虚拟主机。此模块仅适用于需要大量虚拟主机的Apache安装环境。例如，使用Apache的互联网服务提供商（ISP）可以利用此模块减少为每个新虚拟主机客户所需的配置工作。

此模块使您能够使用虚拟网站的IP地址或主机名来创建服务网站所需的物理目录路径，从而创建动态虚拟主机配置。

### VirtualDocumentRoot

`VirtualDocumentRoot`指令允许您使用插值目录路径为虚拟主机设置文档根目录。

- 语法：`VirtualDocumentRoot interpolated_directory`
- 上下文：服务器配置，虚拟主机

例如，在以下指令中，当Apache接收到对`http://www.domain.com/somepage.html`的请求时，它将请求转换为`/www.domain.com/htdocs/somepage.html`：

```
UseCanonicalName              Off
VirtualDocumentRoot      /www/%0/htdocs
```

将`UseCanonicalName`设置为`off`，以便Apache依赖由所有现代Web客户端提供的主机头来确定主机名。`VirtualDocumentRoot`适用于基于名称的虚拟托管场景，在这种场景中，您有一个IP地址负责许多虚拟网站。

![](img/e11fcbd2818a3495ac70085e5d8d1c26_180_0.png)

**注意**

`%0`被转换为完整的主机名（即，`www.domain.com`）。如果需要，您可以使用主机名的部分。主机名（或IP地址）被点分隔成部分。例如，使用`%1`（第一部分 = `www`）、`%2`（第二部分 = `domain`）或`%-$i`（最后一部分 = `com`）可以为该模块提供的指令创建适当的插值目录。您还可以使用`%N.P`约定，其中`N`代表部分（由点分隔），`i`代表该部分的字符数。例如，`%1.2`将从`www.domain.com`中获取`ww`。

### VirtualDocumentRootIP

`VirtualDocumentRootIP`指令允许您使用使用网站IP地址构建的插值目录路径为虚拟主机设置文档根目录。如果您使用基于IP的虚拟托管，因为每个虚拟网站都有唯一的IP地址，所以此方法适用。

**语法：**`VirtualDocumentRootIP interpolated_directory`

**上下文：** 服务器配置，虚拟主机，目录，每目录访问控制文件（`.htaccess`）

例如，在以下指令中，当Apache接收到对`http://www.domain.com/somepage.html`的请求时，它将请求转换为`/www/IP_address_of_.www.domain.com/htdocs/somepage.html`

```
VirtualDocumentRootIP  /www/%0/htdocs
```

### VirtualScriptAlias

`VirtualScriptAlias`指令允许定义脚本别名（如使用`ScriptAlias`指令所做的那样），该别名使用插值目录路径。

**语法：**`VirtualScriptAlias alias interpolated_directory`

**上下文：** 服务器配置，虚拟主机，目录，每目录访问控制文件（`.htaccess`）

例如，在以下指令中，当Apache接收到对`http://www.domain.com/cgi-bin/script_name`的请求时，它将请求转换为`/www/www.domain.com/cgi-bin/script_name`：

```
UseCanonicalName     Off
VirtualScriptAlias   /cgi-bin/  /www/%0/cgi-bin
```

将`UseCanonicalName`设置为`off`，要求Apache依赖由所有现代Web客户端提供的主机头来确定主机名。`VirtualDocumentRoot`适用于基于名称的虚拟托管场景，在这种场景中，您有一个IP地址负责许多虚拟网站。

## VirtualScriptAliasIP

`VirtualScriptAliasIP`指令允许您定义一个使用插值目录路径的脚本别名（类似于使用`ScriptAlias`指令所做的那样）。

- **语法：** `VirtualScriptAliasIP alias interpolated_directory`
- **上下文：** 服务器配置，虚拟主机

例如，在以下指令中，当Apache接收到对`http://www.domain.com/cgi-bin/script_name`的请求时，它会将该请求转换为`/www/IP_address/cgi-bin/script_name`

```
VirtualScriptAliasIP /cgi-bin/ /www/%0/cgi-bin
```

## mod_so

`mod_so`模块允许Apache加载其他模块所需的可执行代码，或在服务器启动期间加载其他模块。除了该模块本身，您可以将所有模块编译为DSO（动态共享对象）模块。

### LoadFile

`LoadFile`指令在启动期间加载指定的文件。通常，使用此指令加载其他模块所需的动态链接库（DLL）文件（仅限Windows）。

- **语法：** `LoadFile filename [filename...]`
- **上下文：** 服务器配置

### LoadModule

`LoadModule`指令加载已编译为DSO的模块。

- **语法：** `LoadModule module_filename`
- **上下文：** 服务器配置

## mod_imap

`mod_imap`模块在Apache中默认编译。它提供图像映射支持，该功能曾由CGI程序`imagemap`提供。您可以使用`AddHandler`指令为任何文件扩展名指定`imap-file`处理程序（内置于该模块中）。例如，以下指令使Apache将所有`.map`扩展名的文件视为图像映射，并使用`mod_imap`模块处理这些文件：

```
AddHandler imap-file map
```

![](img/e11fcbd2818a3495ac70085e5d8d1c26_182_0.png)

`mod_imap`模块仍支持旧格式：

```
AddType application/x-httpd-imap map
```

但是，不建议使用旧格式，因为未来可能会取消对其支持。

图像映射文件的内容可以具有以下任一语法：

```
directive value [x,y ...]
directive value "Menu text" [x,y ...]
directive value x,y ... "Menu text"
```

图像映射文件中允许的指令如下：

- `base` — 映射文件中使用的相对URL被视为相对于此指令值。请注意，如果在映射文件中找到`ImapBase`指令设置，则会被此指令覆盖。默认值为`http://server_name/`。`base_uri`，与`base`同义。
- `default` — 指定当坐标不符合任何多边形、圆形或矩形，且未给出任何point指令时要采取的操作。此指令的默认值为nocontent，表示告知客户端保持显示当前页面。
- `poly` — 使用至少3个点到最多100个点的多边形来定义。如果用户提供的坐标落在多边形内，则此指令被激活。
- `circle` — 使用中心坐标和圆上一点来定义圆形。如果用户提供的坐标落在圆内，则此指令被激活。
- `rect` — 使用两个对角坐标来定义矩形。如果用户提供的坐标落在矩形内，则此指令被激活。
- `point` — 定义单个点坐标。当不满足其他指令时，使用距离用户提供坐标最近的point指令。

值为绝对或相对URL，或以下列表中的特殊值之一。坐标$(x,y)$由空白字符分隔。双引号内的文本（如第二种语法所示）在生成图像映射菜单时用作链接文本。任何以#字符开头的行都被视为注释，并被Apache忽略。

坐标以$x,y$格式书写，每个坐标由空白字符分隔。引号内的文本字符串在生成菜单时用作链接。如果没有这样的字符串，则URL即为链接，如下面的图像映射文件所示：

```
# Comments go here
# Version 1.0.0
base http://www.yoursite.com/some/dir
rect thisfile.html "Customer info" 0,0 100,200
circle http://download.yoursite.com/index.html 295,0 100,22
```

如果该图像映射文件名为`imap.map`，则可以从其他HTML文件中以如下方式引用：

```
<A HREF="/path/to/imap.map"><IMG ISMAP SRC="/path/to/imap.gif"></A>
```
