## 故障排除 - 启动失败

后主失败的原因有很多。检查后主日志，或手动启动（不重定向标准输出或错误）以查看哪些提示消息。某些错误消息显而易见，但这里有一些是不直观的：

```
FATAL: StreamServerPort: bind() failed: Address in use
Is another postmaster already running on that port?
```

这通常如提示所示：你在运行的端口上意外启动了第二个后主。然而，如果内核错误消息不是“Address in use”或类似的措辞，可能存在不同的问题。例如，尝试在保留端口号上启动后主可能会导致类似：

```
$ postmaster -i -p 666
FATAL: StreamServerPort: bind() failed: Permission denied
Is another postmaster already running on that port?
```

```
IpcMemoryCreate: shmget failed (Invalid argument) key=544001, size=83918612, permission=600
FATAL 1: ShmemCreate: cannot create region
```

此类消息可能意味着你的内核对共享内存区域的限制小于 Postgres 尝试创建的缓冲区。（也可能意味着你的内核中完全没有配置 SysV 风格的共享内存支持。）作为临时解决方案，你可以尝试用比通常更少的的缓冲区启动后主（`B` 选项）。然而，你最终需要重新配置内核以增加允许的共享内存大小。如果你在同一台机器上启动多个后主，如果它们的总空间请求超过了内核限制，可能会看到此消息。

```
IpcSemaphoreCreate: semget failed (No space left on device)
```

像这样的信息并不意味着你的磁盘空间已耗尽；意味着你的内核对 SysV 信号量的限制小于 Postgres 想要创建的数量。与之前一样，你可能可以通过在启动 `postmaster` 时减少后端进程数量（使用 `-N` 选项）来绕过该问题，但最终你可能需要增加内核限制。

## 客户端连接问题

一旦你运行了 `postmaster`，尝试用客户端应用程序连接到它时可能会由于各种原因失败。此处显示的示例错误消息适用于基于较新版本 `libpq` 的客户端；基于其他接口的客户端可能会产生信息较多或较少的其他消息。

```
connectDB() -- connect() failed: Connection refused
Is the postmaster running (with -i) at 'server.joe.com' and
accepting connections on TCP/IP port '5432'?
```

这是一个通用的“我无法找到可以对话的 postmaster”的失败。它看起来与之前的示例类似（当尝试进行 TCP/IP 通信时），或者像接（所示（当尝试与本地 postmaster 进行 UNIX-socket 通信时）：

```
connectDB() -- connect() failed: No such file or directory
Is the postmaster running at 'localhost' and accepting
connections on Unix socket '5432'?
```

最后一行对于验证客户端是否正在尝试连接到预定位置很有用。如果那里实际上没有运行 postmaster，内核错误消息通常会是“Connection refused”（拒绝连接）或“No such file or directory”（无此类文件或目录），如所示。（特别重要的是在这种情况下，“Connection refused”并不意味着 postmaster 获取了你的请求并拒绝了它——那种情况将产生不同的消息，如后续所示。）如“Connection timed out”（连接超时）等错误消息可能指示更基础的问题，例如缺乏网络连接性。

```
No pg_hba.conf entry for host 123.123.123.123, user joeblow,
database testdb
```

如果你成功联系了 postmaster，但它不想与你对话，你最可能会得到这种消息。正如消息所示，postmaster 拒绝了连接请求，因为它在它的 `pg_hba.conf` 配置文件中没有找到授权记录。

```
Password authentication failed for user 'joeblow'
```

此类消息表示你已经联系了 postmaster，并且它愿意与你对话，但前提是你通过 `pg_hba.conf` 文件中指定的身份验证方法。检查你提供的密码，或者如果投诉提到了其中一种认证类型，请检查你的 Kerberos 或 IDENT 软件。

```
FATAL 1: SetUserId user 'joeblow' is not in 'pg_shadow'
```

这是认证失败的另一种变体：没有为给定的用户名执行 Postgres `create_user` 命令。

```
FATAL 1: Database testdb does not exist in pg_database
```

在该 postmaster 的控制下没有名为该数据库。注意，如果你没有指定数据库名称，它将默认为你的 Postgres 用户名，这可能是正确的，也可能不是。

## 调试消息

`postmaster` 偶尔会打印出在故障排除期间通常非常有用的消息。如果你想查看来自 postmaster 的调试消息，可以使用 `-d` 选项启动它，并将输出重定向到日志文件：

```
% postmaster -d > pm.log 2>&&
```

如果你不想看到这些消息，可以输入

```
% postmaster -S
```

注意，上一个示例的末尾没有 ampersand（`&`），postmaster 将在前台运行。

## pg_options

可选文件 `data/pg_options` 包含了后端用于跟踪消息和其他后端可调参数的运行时选项。该文件引人注的地方在于，后端在接收到 SIGHUP 信号时会重新读取它，这使得在不重启 Postgres 的情况下更改运行时选项成为可能。此文件中指定的选项可能是 trace 包（`backend/utils/misc/trace.c`）使用的调试标志，或者是后端用于控制其行为的数字参数。新的选项和参数必须在 `backend/utils/misc/trace.c` 和 `backend/include/utils/trace.h` 中定义。

也可以通过 Postgres 的 `-T` 选项指定 `pg_options`：

```
postgres options -T "verbose=2,query,hostlookup-"
```

用于打印错误和调试消息的函数可以使用 `syslog(2)` 功能。打印到 stdout 或 stderr 的消息带有包含后端 pid 的时间戳作为前缀：
