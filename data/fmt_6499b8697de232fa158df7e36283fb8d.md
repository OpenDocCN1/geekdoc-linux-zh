
# 监控和审计用户按键

在大多数大型机构中，至少偶尔需要记录用户的操作。你甚至可能想审计任何对系统拥有 root 权限或其他管理类型账户（如 `oracle`）的人的按键记录。现场的承包商可能会带来安全风险。通常，当新应用程序进入环境时，会有一两个承包商在现场停留一段时间，负责安装、故障排除和对人员进行产品培训。在更改密码后，我总是会将承包商设置在 `sudo`（关于 `sudo` 输出的更多详情见第 14 章）中访问新应用程序账户。`sudo` 只跟踪带有时间戳的输入命令。来自 `stdout` 和 `stderr` 的命令输出详细信息没有记录，因此如果发生问题，你将无法获得关于确切发生了什么的完整审计轨迹。

为了解决这个困境，如果你有空间存储日志文件，可以从用户访问账户开始到他退出账户为止跟踪其按键。这一小功能是通过使用 `script` 命令完成的。其原理是使用 `sudo` 启动一个开启会话的脚本。当会话运行时，终端上所有的输入和输出都会捕捉到日志文件中。当然，如果用户进入了菜单或程序，日志文件将变得难以阅读，但我们至少知道发生了什么。这种监控不是悄无声息地进行的，因为我总是想知道监控正在进行。当脚本启动时，`script` 命令的输出会通知用户会话正在运行，并给出会话日志文件的名称。我们也可以设置监控从用户登录到用户注销的全过程。对于这种监控，我们不需要 `sudo`，但需要编辑特定用户的 `$HOME/.profile` 或其他登录配置文件。

## 语法

使用 `script` 命令非常简单，但我们想在 shell 脚本中提供更多内容。提供一个特定的命令提示符是一个选项。如果你在审计访问，需要设置一个超时时间，以便在五分钟后（`TIMEOUT` 环境变量）shell 超时并结束 root 访问。当 shell 超时时，脚本将终止，用户将被注销，或者会看到一个命令提示符，但我们可以控制这种行为。我们对这些 shell 脚本有许多选项。你将在你的机器上设置 `sudo`（super-user-do）。安装和配置 `sudo` 的完整细节在第 14 章。我们需要配置 `sudo` 以用于监控的每个脚本名称，以及我们允许执行这些脚本的特定用户。我们稍后会讨论这些细节。

`script` 命令的工作原理是为终端上出现的所有内容制作字写（typescript）。`script` 命令后面跟着一个文件名，该文件将包含字写。如果没有给出文件名，字写将保存在当前目录下一个名为 `typescript` 的文件中。对于我们的脚本编写，我们将使用一个文件名。当 for shell 退出时，脚本会话结束，这意味着需要两次退出才能完全注销系统。`script` 命令的语法如下：

```
script [filename]
```

当脚本会话开始时，终端上会显示通知并在文件顶部放置一个时间戳。这是会话的开始。

## 记录用户活动

我们正在保留日志文件，因此为日志文件名设置某种标准格式是一个好主意。对于文件名我们有很多选择，但我喜欢保持简单。我们的日志文件使用以下命名规范：

```
[hostname].[user LOGNAME].[Time Stamp]
```

我们最可能需要主机名，因为你可能正在多个系统上监控用户，并使用一个中央仓库来存放所有的日志文件。当我编写脚本时，我不希望执行命令的次数超过需要。`hostname` 命令就是一个很好的例子。将系统主机名赋值给变量是一个好主意，因为在脚本执行期间它不会改变，或者不应该改变。要将系统主机名赋值给变量，请使用以下语法：

```
THISHOST=$(hostname)
```

对于日期/时间戳，简单的整数表示是最好的。以下命令提供了月、日、年、分、秒的两位：

```
TS=$(date +%m%d%y%H%M%S)
```

现在我们只需要引用 `$TS` 变量作为日期/时间戳即可。由于用户可能会发生变化，我们可以通过以下两个环境变量之一找到活跃的用户名：

```
echo $LOGNAME
```

```
echo $USER
```

```
echo $LOGIN
```

当你使用切换用户命令 (`su`) 更改用户 ID 时，所有这些环境变量都会随之改变。然而，如果用户使用 `sudo` 进行用户切换，`$LOGIN` 环境变量会传递给新用户，而 `$LOGNAME` 和 `$USER` 环境变量将获得新的用户 ID。现在我们拥有了构建日志文件的所有要素。日志文件的一个良好变量是 `LOGFILE`，除非该变量被你的系统或另一个应用程序使用。在某些系统中没有使用 `LOGFILE`。我们不仅需要创建 `$LOGFILE` 的名称，还需要创建文件并设置文件权限。文件的初始权限需要允许作者具有读/写权限。`chmod 600 $LOGFILE`。以下命令设置了日志文件：

```
TS=$(date +%m%d%y%H%M%S)               # 创建时间戳
THISHOST=$(hostname)                    # 查询系统主机名
LOGFILE=$(THISHOST)-$(LOGNAME).$TS      # 命名日志文件
touch $(LOGDIR)/$LOGFILE                 # 创建空日志文件
chmod 600 $(LOGDIR)/$LOGFILE               # 设置文件权限
```

这里显示了一个示例文件名：

`yogi.randy.05110274519`

文件名正在生成，但我们想将文件存储在系统的哪个位置？我喜欢使用变量来持有目录名。通过两个代表目录和文件的变量，你可以将日志目录移动到另一个位置，只需更改脚本中的一个条目。我在系统的 `/usr/local/logs` 中设置了日志目录。对于此脚本日志文件，我添加了一个名为 `script` 的子目录。然后我设置了 `LOGDIR` 变量指向我的日志目录，如下：

```
LOGDIR=/usr/local/logs/script
```

## 启动监控会话

日志设置完成后，我们准备好启动脚本会话。我们使用以下语法启动会话：

```
script $(LOGDIR)/$(LOGFILE)
```

当脚本会话开始时，屏幕上会显示一条消息通知用户脚本会话已启动并列出脚本日志文件名，如下：

`Script command is started. The file is /usr/local/logs/script/yogi.randy.05110274519.`

如果我们知道正在进行监控并且知道文件的文件名，该如何防止用户编辑或删除日志呢？通常，目录权限会处理这个小问题。在脚本运行期间，实际的日志文件是一个打开的文件——实际上是一个用户无法直接访问的系统临时文件。但如果用户要删除 `$LOGDIR`，你将拥有审计追踪。这是我们稍后将讨论的一个问题。

## 仓库在哪里？

到目前为止的情况是这样的：一个用户登录了系统。当用户登录时，使用 `script` 命令启动监控会话，将所有终端输出记录到我们指定的日志文件中。在会话活动期间，日志文件作为系统临时文件打开。当会话结束时（通过用户输入 `exit` 或 `CTRL-D` 或退出信号），日志文件被关闭，用户会被会话结束，并再次显示日志文件名。

出于安全审计目的，我们需要为日志准备中央仓库。我喜欢使用的方法是电子邮件。当会话结束时，我们希望将日志权限设置为仅所有者可读。然后我们将日志发送到另一台机器，理想情况下，那是仓库所在的位置。一旦日志发送，我就压缩本地文件并退出脚本。
