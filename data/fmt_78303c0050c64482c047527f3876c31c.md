
## 描述

`filesync` 在多个计算机系统（通常是服务器和便携电脑）之间同步文件。`filesync` 同步普通、目录或特殊文件。尽管旨在用于移动系统，但 `filesync` 对于在更持久连接的系统上进行备份和文件复制也非常有用。如果系统之间同步了文件，则每个系统上的对应文件将是相同的。在其中一个或两个系统上更改文件会导致文件不同步。要使文件再次相同，必须对文件之间的差异进行协调。

## filesync 357

`filesync` 命令有两种形式。您可以在不带文件参数的情况下调用第一种形式的 `filesync`。这种形式的 `filesync` 会协调 `$HOME/.packingrules` 列表中指定的文件和系统之间的差异。`$HOME/.packingrules` 是 `filesync` 的打包列表，而 `cachefpack` 包含一个需要保持同步的文件列表。参见 `pairfilesync(4)` 和 `cachefpack(1M)`。

第二种形式的 `filesync` 将特定文件从源系统上的目录复制到目标系统。此外，这种形式的 `filesync` 将将指定的参数 `filename` 的一个或多个文件添加到 `$HOME/.packingrules` 中。关于指定源系统和目标系统目录的信息，请参阅 `-s` 和 `-d`。

多个 `filesync` 命令是累积的（即指定的文件会被添加到已有的打包规则列表中）。

## 协调与同步文件

`filesync` 通过执行以下任务在计算机系统之间同步文件：

- 1. `filesync` 检查两个系统中打包规则中指定的目录和文件，并确定它们是否相同。任何不同的文件都需要协调。
- 2. `filesync` 还在 `$HOME/.filesync-base` 文件中为所有正在监控的文件维护基准摘要。此列表包含了最后一次协调时所有文件的名称、类型和大小。
- 3. 根据基准文件中包含的信息和指定的选项，`filesync` 确定多个副本中哪一个是正确的，并对另一个系统进行相应的更改。一旦完成操作，两个副本将再次相同（已同步）。
- 4. 如果源文件发生了变化，则源系统上的目标文件将传播到目标系统。如果目标文件发生了变化而相应的源文件没有发生变化，则目标文件上的更改将传播到源系统。如果两个系统都发生了变化（且文件并不相同），则会打印警告信息，要求您手动解决冲突。

## 解决冲突

当双方都发生更改时，`filesync` 尝试确定应该选择哪个版本。如果 `filesync` 无法确定应该选择哪个版本，它将打印警告信息并让两个不兼容的文件版本处于未协调状态。

在这些情况下，您必须手动解决差异，或告诉 `filesync` 如何选择哪个文件应该胜出。使用 `-o` 和 `-f` 选项告诉 `filesync` 如何解决冲突。

或者，对于每个冲突文件，您可以检查两个版本，确定应该保留哪一个，并手动将两个版本合并为一致（通过复制、删除或更改所有权或保护属性以确保正确）。然后您可以重新运行 `filesync` 查看是否仍存在其他冲突。

## 打包规则文件

打包规则文件 `$HOME/.packagingrules` 包含一个需要保持同步的文件列表。该文件的语法在 `packagingrules(4)` 中描述。

如果您带 `filename` 参数调用 `filesync`，则将自动创建 `$HOME/.packagingrules` 文件。通过使用 `filesync` 选项，您可以增强 `$HOME/.packagingrules` 中的打包规则。

许多用户选择手动创建打包规则并进行手动编辑。您可以编辑 `$HOME/.packagingrules`（使用任何编辑器）来更改 `$HOME/.packagingrules` 文件，或访问命令行中无法提供的更强大的选项（例如 `IGNORE` 命令）。通过编辑 `$HOME/.packagingrules` 文件，您可以轻松地输入通配符表达式。

## 基准文件

`$HOME/.filesync-base` 是 `filesync` 基准摘要文件。`filesync` 使用 `$HOME/.filesync-base` 中的信息在协调和同步期间识别文件之间的差异。您不需要创建或编辑基准文件。它由 `filesync` 自动创建，并记录所有维护的文件之间最后已知的一致状态。

## 自定义同步

随着时间的推移，您想要保持同步的文件可能会发生。在笔记本电脑上只想保留与少数项目相关的文件是很常见的。如果您继续同步与您工作过的每个项目相关的文件，您的笔记本磁盘将被旧文件填满。此外，每个 `filesync` 命令都会浪费大量时间更新您不再关心的文件。

如果您简单地从笔记本中删除文件，`filesync` 将想要在服务器上执行相应的删除操作。相反，您可以告诉 `filesync` 停止同步某些文件

- 强制检查访问控制列表 `ACL` 并尝试让所有新更改的文件一致。如果无法为特定文件设置 `ACL`，`filesync` 将停止该文件的 `ACL` 同步。
- 某些文件系统不支持 `ACL`。支持 `ACL` 的文件系统与不支持的文件系统之间无法同步 `ACL`；这样做会导致大量的错误信息。
- `d` `dest-dir` 指定将文件名复制到目标系统上的目录。配合 `-s source-dir` 选项和文件名操作数。使用 `-s`。
- `e` 标记所有差异。可能无法解决所有涉及所有所有权的冲突（除非以 `root` 权限运行 `filesync`）。如果您无法更改文件的所有权或保护，`filesync` 通常会忽略所有权和保护冲突。如果您指定了 `-e`（所有）标志，`filesync` 将标记这些差异。
- `f src | dst | new` 指定如何解决冲突更改。如果文件在两个系统中都发生了更改且您指定了 `-f` 选项，则保留优选系统的更改，并丢弃不利系统的更改。

## 移动机器

指定 `-f src` 以优先使用源系统文件。指定 `-f dst` 以优先使用目标系统文件。指定 `-f old` 以优先使用旧版本的文件。指定 `-f new` 以优先使用新版本的文件。

如果 `-f` 和 `-o` 选项指定了相同的偏好（`src` 或 `dst`），可以将它们组合。如果 `-f` 和 `-o` 冲突，则忽略 `-f` 选项。

- `-h` 遇到错误时停止。通常，如果 `filesync` 在复制文件时遇到读取或写入错误，它会记录该错误并继续对齐其他文件。如果你指定了 `-h` 选项，`filesync` 在发生此类错误之一时会立即停止，不再处理任何后续文件。
- `-m` 确保文件的两个副本具有相同的修改时间。默认情况下，新复制文件的修改时间将设置为对齐的时间。按修改时间的增加顺序对文件更改排序，以便传播的文件与原始文件具有相同的修改时间顺序。任何两个系统之间通常存在偏差，将修改时间从一个系统传输到另一个系统可能会产生奇怪的结果。

有时，`filesync` 更新目录中的某些（但不是所有）文件会让 `make` 程序感到困惑。例如，如果 `filesync` 同步了 `.c` 文件但忽略了 `.o` 文件，那么 `.c` 文件的修改时间可能会早于从之前的 `.c` 文件版本构建的 `.o` 文件的时间。

- `-n` 在标准输出上显示更改和对齐信息，但不执行更改。

同时指定 `-n` 和 `-o` 选项会分析当前系统并报告在该系统上进行的更改。如果你的机器断开连接（无法访问服务器），但你想知道本地机器上发生了哪些更改，那么结合使用 `-n` 和 `-o` 非常有用。

- `-o src` 强制进行单向对齐，优先考虑源系统 `src` 或目标系统 `dst`。如果 `filesync` 无法访问源或目标目录，将终止。

指定 `-o src` 将更改从源系统传播到目标系统。忽略目标系统上的更改。如果 `filesync` 无法访问源或目标目录，将终止。

指定 `-o dst` 仅将更改从目标系统传播到源系统。忽略源系统上的更改。

### filesync 361

同时指定 `-n` 和 `-o` 选项会分析当前系统并报告在该系统上进行的更改。如果你的机器断开连接（无法访问服务器），但你想知道本地机器上发生了哪些更改，那么结合使用 `-n` 和 `-o` 非常有用。如果 `-f` 和 `-o` 选项指定了相同的偏好（`src` 或 `dst`），可以将它们组合。如果 `-f` 和 `-o` 冲突，则忽略 `-f` 选项。

- `-q` 抑制标准输出，`filesync` 会描述每个操作。
- `-r` 将对齐限制在目录。
- `-s` 指定源系统。如有需要可以使用多个系统。
- `-v` 显示关于每个文件的附加信息。
- `-Y` 跳过安全检查。

### 操作数

- `filename` 文件、目录、符号链接或特殊文件的名称。通过空格指定多个文件名。

### filesync 362

如果 `filename` 是符号链接，`filesync` 会跟随它。如果 `filename` 是目录，`filesync` 会递归进入目录。

以下示例显示了 `$HOME` 中的所有 `.c` 文件都已同步：

```
# filesync -s $HOME -d $HOME
```
