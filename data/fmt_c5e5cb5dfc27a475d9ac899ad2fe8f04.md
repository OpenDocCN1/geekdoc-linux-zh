
## 选项

- `-a deref` 指定别名引用的方式。`deref` 的可能值为 `never`（从不）、`always`（始终）、`search`（搜索）或 `find`（查找），用于指定从不引用别名、在搜索时始终引用，或仅在查找搜索基对象时引用别名。默认值是不引用别名。

- `-A` 仅检索属性（不包含值）。当您只想查看条目中是否存在某个属性而不关心特定值时非常有用。

- `-b searchbase` 使用 `searchbase` 作为搜索的起点，而不是默认值。

- `-B` 不要抑制非 ASCII 值的显示。此选项在处理诸如 `ISO-8859-1` 等备字符集的值时有用。此选项由 `-L` 选项自动设置。

- `-d debuglevel`

设置 LDAP 调试级别。`ldapsearch` 适用的调试级别包括：

+ `1` 跟踪 `Trace`。
+ `2` 数据包 `Packets`。
+ `4` 参数 `Arguments`。
+ `32` 过滤器 `Filters`。
+ `128` 访问控制 `Access control`。

要请求多个类别的调试信息，请添加掩码。例如，要请求跟踪和过滤器信息，请指定调试级别为 `33`。

- `-D binddn`

- `-f file` 从文件中读取一系列行，并对每行执行 LDAP 搜索。在这种情况下，将命令行给出的过滤器视为模式，其中第一个出现的 `%s` 被替换为文件中的某行。如果文件是单字符，则从标准输入读取行。

- `-F sep`

使用 `sep` 作为属性名和值之间的字段分隔符。默认分隔符为 `=`。如果您指定了 `-L` 选项，则忽略此选项。

- `-h ldaphost` 指定运行 `slapd` 服务器的备用主机。

- `-l timelimit`

等待指定的秒数直到搜索完成。

- `-L` 使用修改后的格式显示搜索结果。开启 `-B` 选项，并忽略 `-F` 选项。

- `-M authentication`

指定用于绑定到目录的身份验证机制。此选项的值可以是 `CRAM-MD5`。使用此选项时，绑定 DN 和绑定密码是强制性的。

- `-n`

显示将要的操作，但不实际执行搜索。通常与 `-v` 和 `-d` 配合用于调试。

- `-p ldapport` 指定 `slapd` 服务器监听的备用 TCP 端口。

- `-R`

不要自动跟随搜索时返回的引用 `referrals`。

- `-s scope`

指定搜索范围。`scope` 的可能值为 `base`（基）、`one`（一级）或 `sub`（子树），用于指定基对象、一级或子树搜索。默认值是 `sub`。

- `-S attribute`

根据属性对返回的条目进行排序。如果属性为空字符串 `""`，则根据其区分名称 `Distinguished Name` 的组件对条目进行排序。注意，`ldapsearch` 通常在接收到条目时立即打印。先检索，然后排序，最后打印。默认是不对返回的条目进行排序。

- `-t` 将检索到的值写入一组临时文件。此选项对于处理如 `jpegPhoto` 或音频等非 ASCII 值非常有用。

- `-u` 在输出中包含用户友好格式的区分名称 `DN`。

- `-v`

以冗详细模式运行并将诊断信息写入标准输出。

- `-w passwd`

使用 `passwd` 作为访问目录身份验证的密码。

- `-z sizelimit`

检索最多 `sizelimit` 个条目以完成搜索。

### 输出格式

如果找到一个或多个条目，每个条目将以以下格式写入标准输出：

区分名称 `DN`

用户友好名称（如果您指定了 `-u` 选项）

属性名=值

属性名=值

属性名=值

多个条目之间用一个空行分隔。如果您使用 `-F` 选项指定不同的分隔字符，则使用该字符代替 `=`。如果您使用 `-t` 选项，则返回临时文件名代替实际值。如果您使用 `-A` 选项，则只返回属性名而不返回属性值。

### 示例

以下命令对 `commonName` 为 `mark smith` 的条目执行子树搜索（使用默认搜索基准）。`commonName` 和 `phoneNumber` 被检索并打印到标准输出。

```
ldapsearch 'cn=mark smith' cn phoneNumber
cn=Mark D, phoneNumber=555-1234
```

## ldd 665

未解析的符号可以通过执行文件引用共享对象来解决。

`ldd` 使用与运行时链接器相同的算法来定位共享对象。

### 选项

`ldd` 还可以检查 `*filename*` 与其使用的共享对象之间的兼容性。通过以下任一选项，`ldd` 都会对如果执行 `filename` 时可能发生的任何未解析的符号引用打印警告。

- `-d` 检查对数据对象的引用。不能与 `-r` 一起使用。

- `-r` 检查对数据数据对象和函数的引用。不能使用 `-r`。

- `-f` 强制对不安全的执行文件进行检查。当 `ldd` 被超级用户调用时，默认情况下，它不会处理其发现的任何不安全的执行文件。如果执行文件所指定的解释器不在 `/usr/lib` 或 `/etc/lib` 中，或者无法确定解释器，则认为该执行文件是不安全的。

- `-i` 显示初始化节段的执行顺序。

- `-l` 强制立即处理任何过滤器，以便列出所有经过过滤的对象及其依赖项。

- `-s` 显示用于定位共享对象依赖的搜索路径。

- `-v` 显示处理 `filename` 时产生的所有依赖关系。此选项还会显示任何依赖版本。参见 `pvs(1)`。

超级用户应在要检查的执行文件已知是可靠的情况下才使用 `-f` 选项，因为超级用户对不可信的执行文件使用 `-f` 可能会损害系统安全。如果你不知道要检查的执行文件是否可靠，请临时变为普通用户并以该普通用户的身份调用 `ldd`。只要你不使用 `:r` 子命令，你就可以使用 `dump(1)` 和 `adb(1)` 安全地检查不可信的对象。此外，非超级用户可以使用 `adb` 的 `:r` 子命令或 `truss` 来检查不可信的执行文件，而不会有太大的被破坏风险。为了在对不可信的执行文件上使用 `ldd`、`adb -r` 或 `truss` 时风险降至最低，请使用用户 `- nobody`。

## ld.so.1 667

### 描述

动态应用程序由一个或多个动态对象组成，通常是一个动态可执行文件及其共享对象依赖项。作为动态应用程序初始化和执行的一部分，会调用解释器来完成应用程序到共享对象依赖项的绑定。在 Solaris 中，此解释器被称为运行时链接器。

在链接动态执行文件过程中，会创建一个带有关联程序头部的特殊 `.interp` 节。该节包含一个指定程序解释器的路径名称。当使用 `-I` 选项通过 `ld(1)`（链接编辑器）构建执行文件时，可以指定解释器的路径名称。链接编辑器提供的默认名称是运行时链接器 `/usr/lib/ld.so.1`。

在执行动态执行文件的过程中，内核映射文件并定位所需的解释器。使用 `exec(2)` 和 `mmap(2)`。内核映射此解释器并将控制权移交给它，传递足够的信息以允许解释器继续绑定应用程序然后运行它。
