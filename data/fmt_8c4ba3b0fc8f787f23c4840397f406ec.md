#### 讨论

你已经看到 RAM 是如何构建的，但你可能会问：“为什么需要大容量存储器？”毕竟，到目前为止你所需的最大存储器也只有几个比特，用来存储某些状态机的状态。你们中的一些人可能会回答：“我们需要大容量 RAM 的原因显而易见——它们是用来存储大量数据的！”当然，你们说得对——RAM 非常适合存储大量数据。

但是，仅仅有一个存储器来存储数据是相当无用的。想象一下，你拥有美国每个人在一年内每一笔购买行为的所有数据。现在假设你想找出购买过沃尔沃汽车的人群，以便向他们推销一种会发出约德尔调而不是哔哔声的喇叭。你唯一的办法是对每个存储单元寻址，并把需要的数据挑出来（这里说的是数万亿个存储单元）。

不过，你也可以写下详细的指令并交给别人，让他们去查找你想要的信息。这些指令构成一个程序，而写有这些指令的纸就是一种原始的存储器。如果你有办法把这些书面指令编码成二进制数，你就能像存储数据一样把它们存储到 RAM 中。然后，你可以构建一个状态机来解释存储在程序 RAM 中的二进制数（这些二进制数称为指令）。

要相加的两个8位数是`0x48`和`0x29`（这些数以十六进制表示）。GNOME 中的所有数据存储器都是4位宽。一个4位数称为一个半字节（nybble）。一个8位数（或字节）只能使用数据 RAM 中的两个存储单元来存储：一个存放最低有效半字节（LSN），另一个存放最高有效半字节（MSN）（见图9.3）。假设`0x48`的MSN（即4）存储在数据 RAM 的寄存器`R1`中，LSN存储在`R0`中。第二个操作数也以类似方式存储，MSN放在`R3`中，LSN放在`R2`中。这两个数相加得到的8位结果将存储在`R5`（MSN）和`R4`（LSN）中。

启动时，程序 RAM 已加载指令操作码，`PC` 被初始化为0，因此它指向第一条指令（图9.2a）。（图中显示的是指令助记符，而不是二进制操作码，以便更容易理解程序的执行。）操作数已经存储在`R0`、`R1`、`R2`和`R3`中。然而，用于结果的 RAM 尚未初始化，其中包含某个随机数（用?表示）。累加器也没有初始化，进位标志和零标志也没有初始化。进位标志既作为 ALU 的输入进位位，又在 ALU 将两个4位数相加后存储输出进位。对于这个程序，你需要从 `C=0` 开始。`clear_c` 指令会清除进位位。注意，在图9.2b中，进位位现在为零，`PC` 已经递增，因此它指向下一条指令。

下一条指令 `load R0` 用于将第一个操作数的 LSN 载入累加器。实际上，这条指令助记符的意思是“将`R0`中的值载入`ACC`”。注意，虽然保存数据的 RAM 单元地址（`R0`）是显式给出的，但数据被传送到的位置（`ACC`）只是隐含的。执行这条指令后，`ACC` 中的值为`0x8`，`PC` 已递增。

下一条指令（图9.2c）是 `add R2`，你可能会猜测这是一条将 `R2` 的内容加到某个对象上的指令。但加到什么上呢？同样，隐含的操作数是累加器。这条指令实际上表示：“将`R2`中的值、`ACC`中的值以及`C`标志位中的位相加，并将结果存入`ACC`，同时用进位输出加载`C`标志。”在本例中，结果（以十六进制和二进制两种表示形式）将是：

|   |   |   |
|---|---|---|
| `0x0` | `0` | 输入进位 |
| `+0x8` | `1000` | 累加器的内容 |
| `+0x9` | `1001` | `R2` 的内容 |
| `0x11` | `10001` | 5 位结果 |
| `0x1` | `0001` | 累加器中的四位结果 |
| `0x1` | `1` | 1 位输出进位 |

`0x8` 与 `0x9` 的相加产生了一个无法放入 4 位累加器的数：`0x11`。该结果的最上位是输出进位，它取代了存储在 `C` 标志中的值（见图 9.2d）。在对操作数的最高有效位进行相加时需要用到进位输出。累加器存储了低四位（本例中为 `0001`）。

下一条指令 `store R4` 将累加器的内容存储到结果的最低有效位 `R4` 中（图 9.2e）。请注意，此指令复制值；它不会影响累加器和进位标志中保存的原始值。

一旦 `PC` 到达地址 4（图 9.2e），8 位加法就完成了一半。操作数的最低有效位段已相加并存储在 `R4` 中。`C` 标志现在保存了此次相加产生的进位，它将在对最高有效位段进行相加时使用。这首先通过从 `R1` 加载第一个操作数的最高有效位到累加器开始。`add R3` 指令（图 9.2f）将第二个操作数的最高有效位（`R3`）和进位位加到 `ACC`，过程如下：

|   |   |   |
|---|---|---|
| `0x1` | `1` | 输入进位 |
| `+0x4` | `0100` | 累加器的内容 |
| `+0x2` | `0010` | `R3` 的内容 |
| `0x07` | `0111` | 5 位结果 |
| `0x7` | `0111` | 累加器中的四位结果 |
| `0x0` | `0` | 1 位输出进位 |
