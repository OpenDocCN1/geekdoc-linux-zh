
# 附录 C：GNU emacs 编辑器

除了 `vi` 之外，许多 UNIX 系统还提供 `emacs` 全屏编辑器。它由 Richard Stallman（GNU 的创始人）创建，现在是自由软件基金会。正如你预期的那样，所有的 Linux 发行版都提供 `emacs`。它的起源于一组宏，但如今的 `emacs` 不仅仅是一个编辑器。它提供了一个完整的环境，你可以在其中使用合适的插件处理和浏览网。在本附录中，我们将局限于编辑功能。

## 一个 emacs 会话

与 `vi` 不同，`emacs` 可能没有安装在你的系统上。确保你已经安装了 `emacs`，然后用文件名调用它：

```
emacs emfile
```

在全屏模式下（图 C.1），顶行有一个反显色显示的菜单。底部的模式行（mode line）也以反显色显示。这一行显示了文件名（emfile）和光标所在的当前行；L7 是第 7 行。注意 F1 左侧的两个星号；表示缓冲区已修改。起初，你应该在该位置看到三个连字符。

最后一行被称为最小缓冲区（minibuffer），显示由 `emacs` 生成的消息。该行用于用户输入 `emacs` 命令，并用于 `emacs` 显示系统消息。由于 `emacs` 占用了三行供其内部使用，因此 22 行可用于编辑。

你现在可以直接输入文本，使用 `[Enter]` 分隔行。要擦除文本，你使用 `[Backspace]` 键而不是 `[Ctrl-h]`。后者是用于调用其帮助辅助设施的 `emacs` 快捷键。你也可以使用 `[Ctrl-d]` 或 `[Delete]` 删除光标下方的字符。

当你键入文本后，光标将位于文本的最后一行。你现在可以沿着当前行水平移动。按下 `[Ctrl-b]` 将光标向后移动，按下 `[Ctrl-f]` 向前移动。你也可以使用 `[Ctrl-n]` 移动到下一行，`[Ctrl-p]` 移动到上一行。此外，还有更快的导航方法；将在稍后讨论。

## 插入和替换文本

大多数文字处理器和编辑器提供两种文本输入模式——**插入模式**和**覆盖模式**。默认情况下，`emacs` 在插入模式下工作，此时文本会将现有文本向右移动。`emacs` 也可以在覆盖模式下工作，它会替换光标经过的所有字符。你可以通过两种方式切换到此模式：

- 按下 `[Insert]` 键，它作为一个切换开关。第一次调用将你带入覆盖模式；下一次调用则返回插入模式。
- 通过 `M-x` 发出 `overwrite-mode` 命令。当 `M-x` 在小缓冲区（minibuffer）中出现时，输入 `overwrite-mode`：

```
M-x overwrite-mode [Enter]
```

此命令同样具有切换效果，因此重复执行两次命令可恢复原状。你可以使用两种不同的技巧：

- 使用命令补全功能。输入 `M-x`，输入字符串 `ov` 然后按 `[Tab]`；你会在 minibuffer 中看到字符串 `overwrite-mode`。
- 使用历史记录。按 `M-x` 然后按上键；上一个命令会显示在 minibuffer 中。

在开始编辑之前，查看模式行（mode line）。如果显示 `ovr`，说明你处于覆盖模式。只有在明确需要时才切换到此模式；否则使用默认的插入模式。

## 输入控制字符

如果你编写脚本来向打印机或终端发送转义序列，那么你需要输入控制字符。然而，`emacs` 所有的操作都使用控制键，这就是为什么当你尝试输入它们时，它们会被捕获为 `emacs` 命令。要在文件中放置一个控制字符（例如 `C-m`），你必须在前面加上 `C-q`：

```
C-q C-m
```

这在屏幕上显示为 `^M`（图 C.2），但那里只有一个字符。你只能将光标置在 `^` 上，而不能置在 `M` 上。

输入 `[Esc]` 字符时也可以采用相同的技术。`C-q [Esc]`，你会看到 `[Esc]` 字符看起来像这样：

```
^[
```

这同样是一个单字符。

### 图 C.2 插入控制字符

| 原始文本 | emacs 命令 | 转换后的文本 |
|---|---|---|
| `sed 's/$//'` | `C-q C-m` | `sed 's/^M//'` |
| `echo "Time up"` | `C-q C-g` | `echo "Time up^G"` |

## 保存文本并退出

无论你使用 `vi` 还是 `emacs`，你编辑的只是一个缓冲区（一个包含文件副本的临时存储），而不是直接编辑文件。这些是我们通常对缓冲区执行的三种操作：

- 保存并继续编辑。
- 保存并退出。
- 放弃更改并退出。

与 `vi` 不同，`emacs` 支持自动保存功能，它会定期将缓冲区保存到不同的磁盘文件中。然而，你应该经常自己保存缓冲区，但保存在同一个文件中以保持其最新性（或者，正如我们所说的，保持同步）。基本的保存和退出命令见表 C.1。

你已经知道如何保存缓冲区并退出编辑器。对于 `emacs` 的长时间会话，你必须能够保存缓冲区并留在编辑器中。运行 `emacs file`，进行一些更改，然后输入此序列：

```
C-x C-s
```

保存到同一文件。

这会将缓冲区保存到文件中。通常，你想通过提供不同的文件名来获得副本。在这种情况下，使用 `C-x C-w` 并在提示处输入文件名：

```
Write file: ~/project/emfile.txt
```

保存到不同文件。

新文件名现在出现在模式行上，这意味着它也是当前文件。事实上，该窗口现在与 `emfile.txt` 的缓冲区关联（`emfile` 的缓冲区仍然存在）。在写入不同的文件时，`emacs` 的行为与 `vi` 形成鲜明对比；`vi` 不会让新文件变为当前文件。

### 表 C.1 保存和退出命令

| 命令 | 功能 |
|---|---|
| `C-x C-s` | 保存文件并保持在编辑模式 |
| `C-x C-w` | 写入不同的文件（类似于 Microsoft Windows 中的“另存为...”） |
| `C-x C-c` | 保存并退出编辑器（会提示保存） |
| `C-u C-x C-c` | 保存并退出且无需提示 |
| `C-x C-z` | 挂起当前会话并逃逸到 UNIX shell（使用 `fg` 返回 emacs） |
| `C-z` | 同上 |
| `M-x shell` | 在当前窗口中逃逸到 UNIX shell（使用 `C-x b [Enter]` 返回 emacs） |
| `M-! cmd` | 运行 cmd 并返回编辑器（需要 `[Shift]`） |
| `M-x revert-buffer` | 加载当前文件的最后一个保存版本（类似于 Microsoft Windows 中的“还原”） |
| `M-x recover-file` | 加载当前文件的最后一个自动保存版本 |

## 加载保存的版本

你有时需要忽略所做的所有未保存更改。你可以使用 `revert-buffer` 命令加载最后保存的版本：

```
M-x revert-buffer 使用 revert [Tab] 完成
```

这会用磁盘内容更新缓冲区。你很快会遇到一个类似的命令——`recover-file`——它加载文件的自动保存版本。

## 退出编辑器

如前所述，你可以保存缓冲区或放弃更改。

## 放弃会话

你可能需要忽略所做的所有未保存更改。你只需在提示处响应 `n` 来放弃更改。

## 逃逸到 Shell

你如何编辑并编译？你需要逃逸到 shell。有两种方法；第一种是使用 `M-x` 命令：

- `M-x shell`

这返回一个 shell 提示，但在一个新的缓冲区中。注意 `exit` 会杀死窗口。

第二种方法在你的 shell 支持作业控制时有效。你可以挂起当前的 `emacs` 会话。按 `C-z` 或 `C-x C-z`，将返回 shell 提示。运行你的命令然后使用 `fg`。

## 从崩溃恢复

与 `vi` 不同，`emacs` 具有自动保存功能，每 300 次按键（用户空闲时每 30 秒）自动保存缓冲区副本。然而，`emacs` 不保存到同一个文件，而是保存到一个文件名两边各有一个 `#` 的文件中。例如，文件名命名为当前目录下的 `#filename#`。

由于自动保存，在系统崩溃时你只会丢失 300 次按键的工作。你可以使用 `recover-file` 命令用最后一个自动保存的文件替换当前缓冲区：

- `M-x recover-file`

当你输入文件名（两边都有 `#`）后，`emacs` 会显示两个文件的列表（图 C.3）。在这里，自动保存的版本比最后保存的版本晚 8 分钟。如果你需要较新的版本，在提示处输入 `yes`。`emacs` 确保在每次启动时发现自动保存版本更新时都会提醒你。

## 数组相关内容

注意评估元素时使用大括号。尽管 `month[1]` 看起来像被处理为一个变量，但它可以与一个命名的月份共存。要填充元素组，请使用以下两种形式之一：

```
set -A month 0 31 28 31 30 31 30 31 31 30 31 30 31
month+=(0 31 28 31 30 31 30 31 31 30 31 30 31)
```

此数组存储了 12 个月中的每个月的天数。第一个元素被设置为零，因为否则 `month[0]` 没有任何意义。你可以使用 `@` 或 `*` 作为下标显示所有已定义的元素。如果你添加了 `#` 前缀，则只显示计数：

```
$ echo ${month[@]}
0 31 28 31 30 31 30 31 31 30 31 30 31
```

```
$ echo ${#month[@]}
13
```

已分配元素的数量...

当你选择性地分配单个元素时会发生什么？例如，如果你只设置了 `x[0]` 和 `x[100]`，则只会为这两个元素分配内存，而 `x[99]` 的求值为 `null`：

```
$ x[0]=1; x[100]=10
```

```
$ echo ${x[0]}
1
```

```
$ echo ${#x[@]}
2
```

而不是数组的大小。

本附录中讨论的许多功能都没有包含在 POSIX 中，因此大问题是是否应该使用所有它们。今天，Bash 越来越多地随 UNIX 系统（包括 Solaris）一起分发，但现在的每个系统都支持 Korn Shell。因此，即使你的应用程序不符合 POSIX 标准，只要你使用了至少在 1993 年之前的 Korn Shell 版本中可用的功能，就可以实现相当程度的可移植性。无论如何，POSIX 的下次修订还需要一段时间。
