
但请记住，这不是正则表达式的示例；而是 Shell 正在执行路径扩展。我们在这里展示它是因为 POSIX 字符类可以同时用于这两者。

## 到传统的字典排序顺序

你可以通过更改 `LANG` 环境变量的值，选择让系统使用传统的（ASCII）排序顺序。正如我们之前看到的，`LANG` 变量包含了你区域设置中所使用的语言和字符集名称。此值最初是在你安装 Linux 版本并选择安装语言时确定的。

使用 `locale` 命令查看设置。

```bash
[me@linuxbox ~]$ locale
LANG=en_US.UTF-8
LC_TYPE=en_US.UTF-8
LC_NUMERIC=en_US.UTF-8
LC_TIME=en_US.UTF-8
LC_COLLATE=en_US.UTF-8
LC_MONETARY=en_US.UTF-8
LC_MESSAGES=en_US.UTF-8
```

要将区域设置改为传统的（ASCII），请设置 `LANG` 变量：

```bash
[me@linuxbox ~]$ export LANG=POSIX
```

要使此更改永久生效，将此行添加到 `.bashrc` 文件中：

```bash
export LANG=POSIX
```

## POSIX

在 20 世纪 80 年代，Unix 变成非常流行的操作系统，但到 1988 年，Unix 世界陷入了混乱。许多计算机制造商从创建者 AT&T 处许可了 Unix 代码，并在系统中提供了各种版本。然而，为了实现产品差异化，每个制造商都试图玩一种“锁定”客户的游戏。Unix 历史上的这段黑暗时期被称为巴尔干化（Balkanization）。

引入电气电子工程师（IEEE）。在 20 世纪 80 年代中期，IEEE 开始制定一套定义（类 Unix）系统行为的标准。这些标准正式称为 IEEE 1003，定义了应用程序编程接口（APIs）、Shell 和工具。POSIX 这个名字（代表可移植操作系统接口，在末尾加上 X 以增加酷感）是由 Richard Stallman 建议并被 IEEE 采纳的。

## 正则表达式

正当我们认为事情不会变得更复杂时，发现 POSIX 还将正则表达式实现分为两类：基本正则表达式 `BRE` 和扩展正则表达式 `ERE`。我们目前为止涵盖的功能任何符合 POSIX 标准的应用程序都支持。我们的 `grep` 程序就是其中之一。BRE 和 ERE 之间的区别是什么？在 BRE 中，识别的元字符有：

```
^ . [ ] *
```

所有其他字符都被视为字面量。在 ERE 中，增加了以下元字符：

```
() { } ?
```

然而（这也是有趣的地方），`( )` 和 `}` 字符在 BRE 中如果用反斜杠转义会被视为元字符，而在 ERE 中，在任何元字符前加反斜杠会将其视为字面量。任何出现的异常将在后续讨论中涵盖。

由于我们接下来要讨论的功能是 ERE 的一部分，我们需要不同的 `grep`。传统上，这由 `egrep` 程序执行，GNU 版本的 `grep` 在使用 `-e` 选项时也支持正则表达式。

## 或（Alternation）

第一个讨论的扩展正则表达式功能被称为“或”（alternation），它是允许在一组表达式中匹配的功能。就像括号表达式允许单个字符匹配一组指定的字符一样，“或”匹配一组字符串或其他正则表达式。

为了演示，我们将结合 `echo` 使用 `grep`。首先，让我们尝试一个一个普通的字符串匹配。

```bash
[me@linuxbox ~]$ echo "AAA" | grep AAA
AAA
[me@linuxbox ~]$ echo "BBB" | grep AAA
[me@linuxbox ~]$
```

这是一个非常直观的示例，我们将输出通过给 `grep` 并查看结果。当发生匹配时，我们看到打印出来的结果；当没有匹配项时，我们看不到任何结果。

现在我们将添加交替（alternation），它由竖线 `|` 元字符表示。

```bash
[me@linuxbox ~]$ echo "AAA" | grep -E 'AAA|BBB'
AAA
[me@linuxbox ~]$ echo "BBB" | grep -E 'AAA|BBB'
BBB
[me@linuxbox ~]$ echo "CCC" | grep -E 'AAA|BBB'
[me@linuxbox ~]$
```

在这里，我们使用了正则表达式 `'AAA|BBB'`，它的意思是“匹配字符串 AAA 或字符串 BBB”。注意，这是一个扩展功能，我们为 `grep` 添加了 `-E` 选项（尽管我们也可以直接使用 `egrep` 程序），并且我们将正则表达式括在引号中，以防止 shell 将竖线元字符解释为管道操作符。交替不限于两个选择。

```bash
[me@linuxbox ~]$ echo "AAA" | grep -E 'AAA|BBB|CCC'
```

要将交替与正则表达式的其他元素结合，我们使用 `()` 来分隔交替。

```bash
[me@linuxbox ~]$ grep -Eh '^(bz|gz|zip)*' dirlist*.txt
```

该表达式将匹配我们列表中以 `bz`、`gz` 或 `zip` 开头的文件。如果我们省略了括号，这个正则表达式的含义将变为匹配任何以 `bz` 开头、或包含 `gz` 或包含 `zip` 的文件名：

```bash
[me@linuxbox ~]$ grep -Eh '^bz|gz|zip\*' dirlist*.txt
```

# 量词 (Quantifiers)

扩展正则表达式支持多种方式来指定元素匹配的次数，如接下来的章节所示。

## ? 匹配元素零次或一次

这个量词实际上意味着“使该元素成为可选的”。假设我们想要检查电话号码的有效性，并认为如果号码符合以下两种形式之一（`n` 是数字）则，它是有效的：

- (nnn) nnn-nnnnn
- nnn nnn-nnnnn

我们可以构建这样一个正则表达式：

```regex
^([0-9]-[0-9])? [0-9]-[0-9]-[0-9]-[0-9]-[0-9]-[0-9]$
```

在这些指示中，我们在括号字符后面跟着问号，表示它们将被匹配零次或一次。同样，由于括号在（ ERE）中通常是元字符，我们在它们前面加上反斜杠，以使它们被视为字面量。让我们试一下。

```bash
[me@linuxbox] $ echo "555 123-4567" | grep -E '^\([0-9]-[0-9])\)? [0-9]-[0-9]-[0-9]-[0-9]-[0-9]-[0-9]$'
555 123-4567
[me@linuxbox] $ echo "555 123-4567" | grep -E '^\([0-9]-[0-9])\)? [0-9]-[0-9]-[0-9]-[0-9]-[0-9]-[0-9]$'
555 123-4567
[me@linuxbox] $ echo "AAA 123-4567" | grep -E '^\([0-9]-[0-9])\)? [0-9]-[0-9]-[0-9]-[0-9]-[0-9]-[0-9]$'
~
```

在这里，我们看到该表达式匹配数字的形式，但并不匹配包含非数字字符的数字。这个表达式并不完美，因为它仍然允许区号周围出现不匹配的括号，但它将执行第一阶段的验证。

## 匹配元素零次或多次

与 `?` 元字符一样，`*` 也用于表示可选项目；但与 `?` 不同，它可以出现任意次数，而不仅仅是一次。假设我们想查看一个字符串是否是一个句子；也就是说，它以大写字母开头，包含任意数量的大写和小写字母，并以句号结束。为了匹配这种（粗略的）句子定义，我们可以使用这样的正则表达式：

```regex
([[:upper:]][[:upper:][[:lower:]]* )*\.
```

该表达式由三个项目组成：一个包含 `[:upper:]` 和 `[:lower:]` 字符类以及一个空格的括号表达式，以及用反斜杠转义的句号。第二个元素后面跟着 `*` 元字符，这样句子开头的大写字母以及后续任意数量的字母和空格就可以随其后并保持匹配。

我们看到这个表达式不匹配行 `a b 9`，因为它包含非字母字符；它也不匹配 `abc d`，因为有多个空格分隔了字符 `c` 和 `d`。

## 匹配元素指定的次数

`{ }` 元字符用于指定所需匹配的最小和最大数量。可以通过四种方式指定，如表 19-3 所示。

表 19-3：指定匹配次数

| 指定符 | 含义 |
| :--- | :--- |
| {n} | 如果前一个元素恰好出现 n 次，则匹配 |
| {n,m} | 如果前一个元素出现 n 次到 m 次，则匹配 |
| {n,} | 如果前一个元素出现 n 次或更多，则匹配 |
| {,m} | 如果前一个元素出现 0 次到 m 次，则匹配 |
