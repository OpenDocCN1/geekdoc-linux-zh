
这将 `/usr` 文件系统从目录树中卸载，露出下方的原始目录。

但需要注意的是，如果用户正在使用挂载文件系统上的文件，你就无法卸载它。在发生这种情况之前，必须关闭所有文件，这在大型系统上可能很复杂。有三种处理方法：

- 使用 `lsof` 程序（可从 `ftp://vic.cc.purdue.edu/pub/tools/unix/lsof` 获取）列出给定文件系统上的用户和打开的文件。然后等待他们完成、强制他们离开或杀死他们的进程。然后卸载文件系统。通常，这并不理想。

- 使用 `umount` 命令的 `-f` 选项强制卸载。这通常不是一个好主意，因为这会导致访问该分区的程序（以及用户）感到困惑。内存中尚未提交到磁盘的文件可能会丢失。

- 将系统进入单用户模式（`single mode`），然后卸载文件系统。虽然最不方便，但这是安全的方法，因为没有人会丢失任何工作。

## 自动挂载文件系统

在启动时，系统会自动以只读权限挂载文件系统。然而，一旦它完成了自举，就需要引导。虽然手动挂载所有文件系统是可能的，但并不现实，因为你必须手动完成自举，更糟糕的是，系统不会自动恢复。（当然，如果你喜欢在凌晨 2 点起床来恢复交换分区的话。）

为了实现这一点，UNIX 使用了一个特殊文件 `/etc/fstab`（Solaris 上为 `/etc/vfstab`）。该文件列出了所有启动时需要挂载的分区以及它们需要挂载的目录。同时，你还可以包含传递给 `mount` 命令的参数。

要挂载的文件都以以下格式列在 `fstab` 中：

| /dev/device | /dir/to/mount | ftype | parameters | fs_freq | fs_passno |

| :--- | :--- | :--- | :--- | :--- | :--- |

| `/dev/device` | 是要挂载的设备，例如 `/dev/hda4` | | | | |

| `/dir/to/mount` | 是文件系统在你的目录树上挂载的位置 | | | | |

| | | 是文件类型。在 SunOS 下应为 `4.2`，在 Solaris 下为 `ufs`，在 Linux 下为 `ext2`，在 IRIX 下为 `efs` 或 `xfs`（取决于你的版本），对于 NFS 文件系统为 `nfs`，对于交换分区为 `swap`，对于 `/proc` 文件系统为 `proc`。某些操作系统（如 Linux）支持额外的文件类型，尽管它们可能被使用。 | | | | |

| | | | 是使用 `-o` 选项传递的参数。它们遵循相同的分隔格式。一个条目看起来像 `rw,intr,bg`。 | | | |

| | | | | 用于确定文件系统是否需要备份（`dump`）。 | | |

`fstab` 文件中任何以井号 (`#`) 开头的行都被视为注释。

如果你需要在机器运行时挂载新的文件系统，你必须手动执行挂载。如果你希望此挂载操作在系统重新启动时自动激活，你应该确保向你的 `fstab` 文件中添加适当的条目。

有两个特殊的分区不遵循与普通分区相同的规则。它们是交换分区（`swap`）和 `/proc`。（注意 SunOS 不使用 `/proc` 文件系统。）

挂载交换分区不是使用 `mount` 命令。在 Solaris 和 IRIX 下，它由 `swap` 命令管理，在 SunOS 和 Linux 下也由 `swap` 命令管理。为了挂载交换分区，它必须列在相应的 `fstab` 文件中。一旦列入，使用相应的命令（`swap`）后接 `-a` 参数，然后是所在的分配给它的分区。

`df` 程序是 GNU fileutils 分发包的一部分。GNU 版本扩展了许多你可能会发现有用的参数。可以从 `ftp://ftp.gnu.com/pub/gnu` 下载 `fileutils` 软件包。

`ln` 程序用于在文件之间创建链接。这对于创建一个看似“完美系统”的幻象非常有用——在那个幻象中，一切都处于“正确”的位置，但实际上并非如此。这是通过创建一个从目标位置到实际位置的链接来实现的。

该程序的用法是：

```
ln file_being_linked_to link_name
```

其中 `file_being_linked_to` 是已经存在的文件，你希望另一个名为 `link_name` 的文件指向它。上面的命令生成一个硬链接（`hard link`），这意味着文件 `link_name` 与原始文件无法区分。两个文件都存在同一个文件系统中。

`ln` 的一个常用参数是 `-s` 选项，它生成符号链接（`symbolic links`）而不是硬链接。命令格式保持不变：

```
ln -s file_being_linked_to link_name
```

区别在于 `link_name` 在文件系统中标记为符号链接。符号链接可以跨越文件系统，并在目录项中被赋予特殊的标记。

> 提示：除非有明确的理由不需要，否则你应该始终通过为 `ln` 指定 `-s` 选项来使用符号链接。这会让你的链接脱颖而出，并便于将它们从一个文件移动到另一个文件。

## fck 在哪里？

当你运行 `fck` 时，你运行的是位于 `/usr/sbin` 或 `/bin` 目录下一个名为 `fck` 的可执行文件，但这并不是真正的 `fck`。它是一个调度器，用于调用特定于文件系统类型的 `fck` 工具。

## 我什么时候应该运行 fck？

通常情况下，你不需要运行 `fck`。当你尝试在启动时挂载一个脏的文件系统时，系统会自动运行。然而，问题可能会悄悄降临。软件和硬件故障偶尔发生。在执行完每月备份后运行 `fck` 也许并无害。

> 注意：最好在备份之后运行 `fck`。如果 `fck` 发现问题，它可能会导致文件系统处于比之前更糟糕的状态。这时你可以构建一个空文件系统并重新读取你的备份，这也会清理文件系统。如果你反过来操作，你将会面临既没有备份也没有文件系统。

## 我该如何运行 fck？

系统通常会为你运行它，运行 `fck` 并不是你每天需要记住的日常工作。然而，它非常简单且很大程度上是自动的。

首先，要运行 `fck`，你想要检查的文件系统不能处于挂载状态。如果你大多数时间都处于多用户模式下，这有点难做到，因此若要运行完整的 `fck`，你应该将系统切降到单用户模式。

在单用户模式下，你需要调用 `fck`，并为其提供选项以强制检查所有文件系统，即使它们已经处于稳定状态。

```
fck -f      (SunOS)
fck -o f   (Solaris)
fck         (Linux and IRIX)
```

如果你想检查单个文件系统，请输入它的字符名称。（如果你不确定设备是什么，请参见“向系统添加磁盘”章节以获取如何确定此类信息的详情。）例如：

```
fck /dev/hdal
```

执行实际的 `fck` 分五到七步，取决于你的操作系统以及发现了哪些错误（如果有）。`fck` 可以自动修正这些错误中的大部分，因此如果在启动时被调用来自动检查脏系统。

我们即将逐步过的 `fck` 不是运行在 `ufs` 文件系统上的。虽然不同文件系统之间的阶段编号之间存在一些差异，但错误大多是相同的，需要相同的解决方案。对任何 `fsck` 调用都严格应用常识，你就应该没问题。

### 检查 ufs 系统

对于 `ufs` 文件系统，`fsck` 是一个五阶段的过程。`fsck` 可以自动修正这些错误中的大部分，如果在启动时为了检查脏系统，它会这样做。然而，当你运行 `fsck` 时，你会被要求回答一个系统本会自动回答的问题。

> 注意：`ufs fsck` 在最开始阶段报告的严重错误，特别是在报告阶段 1 的 `statB` 之前，表明超级块无效。应该终止 `fsck` 并使用 `-b` 选项重启，指定其中一个备用块。块 `32` 始终是一个备用块，可以先尝试；如果文件系统的第一个块被覆盖，它可能已经损坏。使用从 `mkfs` 保存的硬拷贝来在文件系统中寻找备用块。

#### 阶段 1：检查块和大小

此阶段检查 `inode` 列表，寻找无效的 `inode` 条目。需要回答的错误包括：

```
UNKNOWN FILE TYPE I=inode number (CLEAR)
```

`inode` 中的文件类型位无效。选项是遗留该问题并在稍后手动尝试恢复数据，或者通过清空 `inode` 来擦除该条目及其数据。

```
PARTIALLY TRUNCATED INODE I=inode number (SALVAGE)
```

`inode` 指向的内容比文件本身少。这可以安全地救回，因为表明在截断文件以缩短时发生了崩溃。

```
block BAD I=inode number
block DUP I=inode number
```

`inode` 指向的磁盘块超出了该 `inode` 的范围，或已被另一个文件占用。这是一个信息性消息。如果发现重复块，阶段 1b 将报告使用该块的文件的 `inode`。

#### 阶段 2：检查路径

此阶段从阶段 1 和 1b 发现的坏 `inodes` 中移除目录条目，并检查超出范围或指向坏 `inodes` 的 `inode` 指针。你可能需要处理：

```
ROOT INODE NOT DIRECTORY (FIX?)
```

如果你将根目录 `inode 2` 转换回目录，但这通常意味着 `inode` 表遭受了严重损坏。

```
OUT OF RANGE I=inode number NAME=file name (REMOVE?)
UNALLOCATED I=inode number OWNER=O MODE=M SIZE=S MTIME=T TYPE=F (REMOVE?)
BAD/DUP I=inode number OWNER=O MODE=M SIZE=S MTIME=T TYPE=F (REMOVE?)
```

使用了坏的 `inode` 、目录中使用了未分配的 `inode`、或者引用了一个带有坏或重复块号的 `inode`。你被允许删除文件（丢失数据）或保留该条目。如果你保留该条目，文件系统仍然是损坏的。

#### 阶段 3：检查连接性

此阶段检测未引用的错误。它在需要时创建 `lost+found` 并连接错的。

#### 阶段 4：检查引用计数

此阶段利用阶段 2 和 3 的信息检查未引用的文件和错误的引用计数。

```
UNREF FILE I=inode number OWNER=O MODE=M SIZE=S MTIME=T (RECONNECT?)
```

在两种情况下，发现的引用数都与 `inode` 中列出的不同。你应该让 `fsck` 调整计数。

```
LINK COUNT FILE I=inode number OWNER=O MODE=M SIZE=S MTIME=T COUNT=X (ADJUST?)
LINK COUNT DIR I=inode number OWNER=O MODE=M SIZE=S MTIME=T COUNT=X (ADJUST?)
```

```
BAD/DUP I=inode number OWNER=O MODE=M SIZE=S MTIME=T (CLEAR)
```

文件或目录包含重复块。如果你清除它，数据就会丢失。你可以留下错误并恢复数据，稍后重新运行 `fsck` 来清除该文件。

#### 阶段 5：检查柱组

此阶段检查空块和未引用的 `inode` 映射。必要时它会自动修正空列表，尽管在手动模式下它会先请求许可。

## fck 完成后我该做什么？

首先，放松，因为 `fsck` 会发现任何严重问题，除非是在磁盘驱动或在你复制内容时发生故障的情况下。Unix 文件非常健壮。

然而，如果 `fsck` 发现了重大问题或产生了大量错误，请重新运行以确保磁盘没有发生故障。第二次运行不会发现更多错误。然后，恢复它可能删除的所有文件。如果你保留了 `inodes` 清除日志，你可以从备份带中转储 `inodes` 列表。恢复这些 `inodes` 以还原文件。

再次备份系统，因为没有理由重复这一切。

## 处理 lost+found 中的内容

如果 `fsck` 移除了未引用的条目，它将其放在 `lost+found` 目录中。它们在那里是安全的，如果在尝试将它们移回原位置时丢失了它们，你应该备份系统。`lost+found` 中的可以是任何类型：文件、目录、特殊文件（设备），如果是管道或套接字，你大删除它。打开它的进程早已消失，并在再次打开时会打开一个新的。

对于文件，请使用所有者名称联系用户，让他查看文件内容并判断该文件是否值得保留。通常情况下，这些是被删除且不再需要的文件，但系统在完全删除它们之前崩溃了。

对于目录，目录中的文件应该帮助你和所有者确定它们所属的路径。如有必要，你可以在备份带列表中查找包含这些内容的目录。只需重命名目录并移动文件即可。删除 `lost+found` 中的目录条目。这种重建和移动的额外好处是可以清理目录。

## 创建文件系统

现在你已经理解了维护文件系统的细微差别，是时候了解它们是如何创建的了。本节将引导你完成以下三个步骤：

- 为你的系统选择合适的磁盘类型

- 创建分区

- 创建文件系统

### 磁盘类型

尽管有许多种磁盘，但 UNIX 系统在工作站上已统一采用 SCSI 标准。许多 PC 也支持 SCSI 接口，但由于成本较低且供应充足，你会在 UNIX PC 上发现许多 IDE 驱动器。

SCSI 本身现在有几种不同的版本。有普通 SCSI、`SCSI-2`、`SCSI-Wide`、`SCSI-Fast and Wide` 以及 `SCSI-3`。虽然可以使用转换线来匹配和混合这些设备，但如果你发现坚持使用一种格式对你的精力和性能更有利。在本书时，`SCSI-2` 是最常用的接口。

连接你的 SCSI 驱动器时，有许多重要点需要记住：

- 终止你的 SCSI 链。忘记这样做会导致各种非确定性行为（极难追踪）。`SCSI-2` 需要主动终止，这通常由终止器上的 LED 指示器指示。

- 如果设备声称是自终止的，你可以碰碰运气，但无论如何加上终止器，遇到错误的概率都会更低。

一条 SCSI 链上限制为八个设备……两个具有相同 ID 的设备的常见症状是频繁重置 SCSI 链。当然，许多设备在这些情况下无法工作。

- 在添加或删除 SCSI 磁盘时，请务必关闭电源。SCSI 线中有电源通过，未先关闭可能会导致以后出现问题。

尽管 SCSI 是工作站之王，但 PC 还有另一个选择：IDE。IDE 通常比 SCSI 设备更便宜且更容易获得，许多主板都提供 IDE 支持。使用这种接口的优势在于其可用性和较低成本。它们也更简单，对你来说所需的配置更少。

IDE 的缺点是其简单性是以牺牲配置性和扩展性为代价的。IDE 链可以容纳两个设备，并不是所有主板都带有超过一个 IDE 通道。如果你的光驱器是 IDE 的，你就有一个磁盘空间。这对于单人工作站来说可能还好，但正如你想象的，这在服务器环境中是不可行的。另一个考虑是，SCSI 设计时具有在没有主 CPU 帮助的情况下执行 I/O 的，这是它昂贵的原因之一。相反，IDE 是为了成本设计的。这导致了简化控制器；然而，CPU 承担了驱动的负担。
