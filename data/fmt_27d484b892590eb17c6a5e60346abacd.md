
这些安装 Info 以外格式文档的命令旨在供安装人员在需要该格式时显式调用。GNU 偏好 Info 文件，因此这些必须由 `install` 目标安装。

# 第 15 章：Makefile 约定

当你有许多文档文件需要安装时，我们建议通过安排这些目标安装到适当目录的子目录中（例如 `htmldir`）来避免冲突和混乱。例如，如果你的软件包有多个手册，并且你希望安装包含许多文件（如输出）的 HTML 文档，你肯定需要子目录，否则同名的手册将互相覆盖。请确保这些 `install-*` 目标调用了 `install` 目标的命令，例如通过建立依赖关系。

此规则不应修改编译时所在的目录，只修改安装文件的目录。卸载命令分为三类，与安装命令一样。参见第 15.7 节 [Install Command Categories]，第 162 页。

## install-strip

类似于 `install`，在安装时剥离可执行文件。在简单情况下，此目标可以简单地使用 `install` 目标：

```
install-strip:
	$(MAKE) PROGRAM=$(INSTALL) -s install
```

但如果软件包不仅安装真正的可执行文件还安装脚本，则 `install-strip` 目标不能简单引用 `install` 目标：它必须剥离可执行文件但保留脚本。

`install-strip` 不应剥离构建目录中正被拷贝进行安装的可执行文件。

## clean

删除当前目录中所有通过构建程序正常创建的文件。如果其他目录中的文件是由此 Makefile 创建的，也将其删除。然而，不要删除记录配置的文件。还要保留可以通过构建生成的文件，但通常发行版中已包含它们。没有需要删除用 `mkdir -p` 创建的父目录，因为它们本身可能已经存在。

如果 `*.dvl` 文件不是发行版的一部分，则删除它们。

## distclean

删除当前目录（或由此 Makefile 创建）中所有通过配置或构建程序创建的文件。如果你解压了源码并构建了程序而没有创建其他文件，`make distclean` 应该只留下发行版中的文件。然而，没有需要删除用 `mkdir -p` 创建的父目录，因为它们本身可能已经存在。

### mostlyclean

类似于 `clean`，可能会克制删除少数人们通常不想重新编译的文件。例如，GCC 的 `mostlyclean` 目标不会删除 `libgcc.a`，因为重新编译它很少必要且耗费大量时间。

### maintainer-clean

删除几乎所有可以使用此 Makefile 重建的内容，这通常包括 `distclean` 删除的所有内容，以及更多：由 Bison 生成的 C 源文件、标签表（tags tables）、Info 文件等。

我们之所以说“几乎所有”，是因为运行命令 `make maintainer-clean` 应该应该删除 `configure` 文件，即使 `configure` 可以使用 Makefile 中的规则重新生成。更通俗地说，`make maintainer-clean` 不应删除任何为了运行 `configure` 然后开始构建程序而存在的文件。此外，没有需要删除用 `mkdir -p` 创建的父目录，因为它们可能已经存在。这些是唯一的例外；`maintainer-clean` 应该删除其他所有可以重建的内容。

`maintainer-clean` 目标旨在供软件包的维护者使用，而不是普通用户。你可能需要特殊的工具来重建 `maintainer-clean` 删除的文件。由于这些文件通常包含在发行版中，我们并不负责让它们易于重建。如果你发现需要重新解压完整的发行版，请不要怪我们。

为了帮助用户意识到这一点，特殊 `maintainer-clean` 目标的命令以以下内容开头：

```
@echo '此命令供维护者使用；它'
@echo '删除了可能需要特殊工具重建的文件。'
```

### TAGS

更新此程序的标签表。

foo.info: foo.tex chap1.tex chap2.tex
	$(MAKEINFO) $(dir)/foo.tex

你必须在 Makefile 中定义变量 `MAKEINFO`。它应该运行 `maketexinfo` 程序，该程序是 Texinfo 发行版的一部分。

# installdirs

使用目标 `installdirs` 来创建文件安装的目录及其父目录是非常有用的。有一个名为 `mkinstldirs` 的脚本可以方便地完成工作；你可以在 GNUlib 软件包中找到它。你可以使用如下的规则：

```
# 确保所有安装目录（例如 $(bindir)）
# 实际存在，在必要时创建它们。
installdirs: mkinstldirs
	$(src)/mkinstldirs $(bindir) $(datadir) \
	$(libdir) $(infodir) \
	$(mandir)
```

或者，如果你希望支持 `DESTDIR`（强烈建议支持），

```
# 确保所有安装目录（例如 $(bindir)）
# 实际存在，在必要时创建它们。
installdirs: mkinstldirs
	$(src)/mkinstldirs $(bindir) $(DESTDIR)$$(datadir) \
	$(DESTDIR)$$(libdir) $(DESTDIR)$$(infodir) \
	$(DESTDIR)$$(mandir)
```

此规则不应修改进行编译的目录。它的作用应该是创建目录而不是修改。

# 15.7 安装命令分类

在编写 `install` 目标时，你必须将所有命令分为三类：普通命令、安装前命令和安装后命令。

普通命令将文件移动到适当的位置并设置它们的模式。它们不能修改除完全来自其所属包的文件以外的任何文件。

安装前和安装后命令可能会修改其他文件；特别是，它们可以编辑全局配置文件或数据库。

安装后命令最常见的用途是运行 `install-info`。这无法通过普通命令完成，因为它修改了一个文件（Info 目录），而该目录并非完全且直接来自正在安装的包。它之所以是安装后命令，是因为它需要在安装包 Info 文件的普通命令之后执行。

大多数程序不需要任何安装前命令，但如果需要，我们提供了提供了该功能。

要将 `install` 规则分类为这三类，请在它们之间插入分类行。分类行指定了后续命令所属的类别。

一个分类行由一个制表符、对特殊变量的引用，以及末尾可选的注释组成。你可以使用三个变量，每个对应一个类别；变量名指定了该类别。在普通执行中，分类行是无操作，因为这些 Make 变量通常是未定义的（你不应该在 Makefile 中定义它们）。

以下是三种可能的分类行，每行都有一个解释含义的注释：

```
$$(PRE_INSTALL) #后面是安装前命令。
$(POST_INSTALL) #后面是安装后命令。
$(NORMAL_INSTALL) #后面是普通命令。
```

如果你不在 `install` 规则的开头使用分类行，则在第一个分类行之前的所有命令都被归为普通命令。如果不使用任何分类行，所有命令都归为普通命令。

这些是 `uninstall` 的分类行：

```
$$(PRE_INSTALL) #后面是卸载前命令。
$(POST_INSTALL) #后面是卸载后命令。
$(NORMAL_INSTALL) #后面是普通命令。
```

通常，`uninstall` 命令用于删除 Info 目录中的条目。如果 `install` 或 `uninstall` 目标有任何作为安装子程序的依赖项，你应该让每个 `dependency` 命令以分类行开头，并且主目标的命令也以分类行开头。这样，无论实际运行了哪个依赖项，都能确保每个命令都放置在正确的类别中。

安装前和安装后命令不运行任何程序可以使用：
`base` `bash` `chgrp` `chmod` `cmp` `cp` `diff` `echo` `egrep` `expand` `xfreq` `false` `getp` `grep` `gzip` `gzip` `hostname` `install-info` `kill` `ldconfig` `ls` `mdsum` `mkdir` `mkfind` `minev` `rmdir` `sed` `sort` `tee` `test` `true` `uname` `xargs` `yes`

以这种方式区分命令是为了制作二进制包。通常，二进制包包含所有需要安装的可执行文件和其他文件，并有其自己的安装方法——因此不需要运行普通的安装命令。但安装二进制包确实需要执行安装前和安装后命令。通过提取安装前和安装后命令来构建二进制包的程序需要 make 的 `-s` 选项来隐藏关于子目录的消息：

```
make -s -n install -o -all a \
PRE_INSTALL=pre-install \
POST_INSTALL=post-install \
NORMAL_INSTALL=normal-install \
gawk -f pre-install.awk
```

其中文件 `pre-install.awk` 可能包含以下内容：

```
$0 ~ /\*(normal-install|post-install)\{ [\t]**/ {on = 0}
on {print $0}
$0 ~ /pre-install\[ [\t]*$/ {on = 1}
```
