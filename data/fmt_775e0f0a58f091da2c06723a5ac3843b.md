
## 邮件客户端测试总结

仅凭不同测试中的得分，你可以看到 `Mailspring` 仅在插件和安全功能方面落后于其他工具。在当今时代，一个不能加密消息或提供过滤垃圾邮件手段的电子邮件应用程序是不可想象的。这就是 `Mailspring` 排名最后的原因。除此之外，该工具迅捷的性能让我们震惊。它的搜索功能、快速配置和几乎即时的启动是您必须亲自体验的，因为言语无法公正地描述它。尽管该项目依赖通过付费专业版获取资金，但它仍为免费用户提供了对其部分最佳功能（如送达通知）的有限访问，这备受赞赏。诚然，其中一些功能（如送达通知）也可在 `Thunderbird` 上获得，但与我们在 Budgie 安装中的 `Mailspring` 相比，它没有如此完美地融入桌面，后者会通过弹出窗口告知我们何时有人读取了邮件，或何时有人访问了我们分享的链接。

自 **LXFLS1** 中我们查看 `KMail` 以来，它已经做出了惊人的改进，配置新账户现在相当容易。不幸的是，`Claws Mail` 仍然远未达到 `Thunderbird` 和 `Evolution` 的简洁程度。话虽如此，`Claws Mail` 没有任何问题，如果您受限于低规格机器，我们不会推荐其他任何工具。`Evolution` 是紧随其后的第二名，但 `Thunderbird` 凭借其默认功能、搜索流程和众多扩展功能胜出。

- **1 名 `Thunderbird`** 10/10
  - 网络: `www.thunderbird.net`
  - 许可证: GPL 及其他 版本: 60.0
  - 应向 `Mailspring` 寻求灵感。
- **2 名 `Evolution`** 9/10
  - 网络: `https://wiki.gnome.org/Apps/Evolution`
  - 许可证: GPL 及其他 版本: 3.28
  - 需要改进账户设置流程。
- **3 名 `KMail`** 8/10
  - 网络: `http://userbase.kde.org/KMail`
  - 许可证: GPLv3 版本: 5.73
  - 可以从 `Thunderbird` 和 `Mailspring` 中吸取一些技巧。
- **4 名 `Claws Mail`** 7/10
  - 网络: `www.claws-mail.org`
  - 许可证: GPLv3 版本: 3.16
  - 新账户设置和文档是其弱点。
- **5 名 `Mailspring`** 5/10
  - 网络: `https://getmailspring.com`
  - 许可证: GPLv3 版本: 1.4.2
  - 需要尽快添加加密和垃圾邮件过滤支持！

### 其他考虑

通常情况下，我们将本月的 `Roundup` 限定为图形应用程序。在我们转向命令行替代方案之前，仍有一些图形应用程序必须提及。如果您喜欢 `Claws Mail`，那么您还应该关注 `Sylpheed`，因为 `Claws` 是 2005 年从它分叉出来的。有趣的是，这两个工具的功能集几乎相同。Gnome 用户也可以尝试 `Geary`，但它没有 `Evolution` 功能丰富。

如果您感到怀旧，记得 `Netscape` 的日子，`Seamonkey Mail` 是一个可行的替代方案，并提供了与其他工具相同的所有有用功能，如垃圾邮件检测和消息过滤。还有 `Mutt`，这是一个非常强大的邮件客户端。您需要安装和配置其他命令行实用程序（如 `Procmail`）来过滤消息。`Alpine` 是另一个控制台应用程序，类似于 `Mutt`，但设计得对初学者更友好。

## Web Servers

### 正在寻找在家庭或办公室构建、测试和部署 Web 应用的选项吗？好吧，让我们来了解一下其中一些最好的选择！

### 我们的测试方法

由于我们的 Linux 机器能够在几分钟内构建并设置 Web 服务器，我们的本地机器是本教程中用于测试服务器的设备。为了完成测试，我们真正需要的只是在安装构建和测试软件时能够访问互联网。一旦完成，我们即可在没有互联网的情况下进行测试需求。由于浏览器如今是用户体验服务器性能的主要方式，浏览器响应时间将是关键测试。我们可以测试负载和交付，以产生一些非常有用的数据。

除了浏览器，我们还将使用 Apache 基准测试套件，它提供了非常有用的数据。这将帮助我们衡量服务器的效率，以及为什么某些服务器在特定情况下表现更好。除了原始性能之外，我们还将根据安装难易度、支持和文档的可用性、支持的设备范围、通用功能以及超出基本功能集扩展服务器的能力来评判每个服务器。

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_125_0.png)

万维网的大部分内容用于显示可读的网页。从典型的 Web 开发角度来看，大多数网站和 Web 应用程序都是使用 Web 编码语言的组合构建的；如 HTML、CSS、JavaScript、PHP、Java 和 MySQL，这只是最常见的几种。深入细节一点，网页可以是基本的、速度优化的网页，也可以是具有幻灯片、数据报告和电子商务等功能等许多花哨功能的复杂 Web 应用程序。

由于网站形态各异，不能过分强调了解哪种 Web 服务器能为你所处理的内容提供最佳性能有多么重要。因此，这正是我们将要做的。我们将测试从最基础到更复杂的网站的各种内容示例，同时考察服务器的安装、性能和配置情况。

> “我们将测试从最基础到更复杂的网站的各种内容示例”

我们将研究的服务器是 `Apache`、`Nginx`、`Lighttpd`、`Openlitespeed` 和 `Tomcat`。所以，请留下来，我们将探索哪台服务器最适合你的需求。希望你会在这里的测试中发现，它们将影响你的实际托管选择，并使你能够托管响应更快的网站。

### 设备支持

### 在 Ubuntu 和 Raspbian 上安装 Web 服务器

![](img/3f314b57ad3c8b08d25e5d1ab47de56d_126_0.png)

在运行各种 Web 服务器的安装和测试时，由于这两种工具对典型的 Web 开发者都极为有用，我们使用了 `Ubuntu` 和 `Raspbian`。在某些情况下，`Ubuntu` 可以简单安装，而 2018 年最新版本的 `Raspbian` 没有软件包。幸运的是，我们花时间找到了五个可以相当快地在我们机器上安装的软件包。除了简单安装命令带来的安装问题外，在某些情况下，从源代码安装也会出现错误。因此，既然说到了这里，让我们仔细看看我们在进行安装时发现的设备支持情况。

使用 `Apache`、`Nginx`、`Lighttpd` 和 `Apache Tomcat`，所有产品都可以使用常见的 `apt-get install` 命令轻松安装在 `Ubuntu` 和 `Raspbian` 上。例如，安装 `Apache` 就像输入 `apt install apache2` 一样简单。

`Openlitespeed` 的文档声称可以从软件仓库安装，然后执行典型的 `apt-get install` 命令。然而，在 `Ubuntu` 和 `Raspbian` 上，该方法完全失败。这有点烦人，但还有其他选择。在两台设备上尝试从源代码安装 `Openlitespeed` 后，那也失败了。`./configure` 命令无法运行，因为下载压缩文件中缺少该文件。既然他们按从左到右的顺序排列安装方法，我们已经浪费了时间才到达最终手段。幸运的是，在第三次尝试中，`Openlitespeed` 通过单击一行代码的方法成功安装在 `Ubuntu` 上，但无法在 `Raspbian` 上安装。因此，在测试 Web 服务器方面，该产品在设备支持方面以多种方式名列底部。

除了 `Apache` 和 `Tomcat`，所有服务器都使用 80 端口打开网页。默认情况下，`Tomcat` 使用 8080 端口。因此，运行 `Tomcat` 并使用 `localhost:8080` 将打开它。不幸的是，如果我们已经使用 8080 端口用于其他服务，例如 `Linux Motion`，我们需要将其配置为使用另一个端口，如 7000。

所有服务器的一大优点是它们安装得相当快，因此，在执行命令后，我们几乎可以立即在设备上使用它们。

**结论**

| 服务器 | 得分 | 服务器 | 得分 |
| :--- | :--- | :--- | :--- |
| `APACHE` | 10/10 | `TOMCAT` | 9/10 |
| `NGINX` | 10/10 | `OPENLITESPEED` | 6/10 |
| `LIGHTTPD` | 10/10 | | |

`Openlitespeed` 在这里失利，因为它是不如其他服务器那么知名的服务器。

### 关于手册页和在线帮助的情况

从基本安装来看，只有 `Lighttpd` 和 `Apache` 拥有手册页条目。与此同时，所有五个测试产品都有在线手册页，`Openlitespeed` 除外。虽然手册页是一个很好的信息来源，但在线有极好的文档。

在首次设置和运行期间，在各供应商网站上花费了相当多的时间后，`Apache`、`Tomcat` 和 `Nginx` 似乎拥有组织良好、易于遵循的信息，允许轻松安装、修改和配置。
