
对于小型公司和软件部署，标准引擎具有一些优势，即操作需求很少或完全不需要人工干预，或者数据需求非常或简单，且数据库功能也很简单。`SE` 是许多垂直市场增值转销商（`VAR`）的引擎，他们为各种基于 `UNIX` 的应用程序找到了一种简单、低维护、低成本的引擎。尽管在 `Informix` 生命周期的大部分时间里，`SE` 一直处于成本敏感型市场，但现在已不能仅凭成本来选择了。与 `IDS` 相比，`SE` 缺少了太多功能，以至于无法成为一个严肃的选择，除非你寻找的是数据库中非常基础的功能。比这更基础的是 `C-ISAM`，它是 `Informix` 提供的最低层次的数据库产品。

`C-ISAM` 是当今市场上所有数据库产品（包括竞争对手）的基础。然而，`C-ISAM` 极其局限，其接受的使用范围非常窄，在大多数情况下，它根本不是一个选项。请记住，`Informix` 是数据库市场中第一家在 `UNIX` 上提供 `ISAM` 产品的公司，随后在标准引擎中提供了更复杂的 `ISAM` 产品，这允许使用标准 `SQL` 访问数据库。`C-ISAM` 适用于 `Linux`，你可能想要获取副本来学习它是如何工作的，以及其他数据库产品是如何使用它的。

`Informix` 动态服务器（`IDS`），原名为在线动态服务器（`Online Dynamic Server`），其名称源于它的工作方式。`IDS` 可以动态调整自己以分担负载，并提供了若干你可以在不重启引擎的情况下更改的设置。在大多数情况下，该引擎可以承受大量负载并仍然提供令人印象深刻的性能。`IDS` 非常可靠、健壮，如果可能的话，它应该被视为未来的最小引擎。它可以以与 `SE` 相同的简单方式实现，维护工作并不比标准引擎常见的多多少。`IDS` 也可以简单地进行维护，只要你照顾好该引擎涉及的整个操作周期。`IDS` 相比 `SE` 的优势在更快的性能上更为明显，但在 `IDS` 提供的高级数据类型上也同样明显。

你会发现 `IDS` 在许多方面与 `SE` 相似，但你也会发现 `IDS` 强大得多，性能比标准引擎好得多。性能的提升以及高级功能使其成为首选。如果你是一个需要更高性能的开发者，还应该利用 `IDS.2000`，它允许你使用 `IDS 7.30` 中未发现的对象关系功能。我建议你将使用 `IDS 7.30` 作为一个很好的练习，以获得对基础引擎的感觉，然后移动到 `IDS.2000` 的额外功能——你可能永远不需要 `IDS.2000` 的某些功能，但另一方面，它们可能是至关重要的。无论如何，先学习两个引擎中更简单的一个，然后再转向更复杂的。

欲欲了解 `SE`、`IDS` 与 `IDS.2000` 的完整产品对比，请访问 `Informix` 网站。对于 `SE` 的局限性，大多数严肃的公司都会考虑将动态服务器作为所有（不是全部）引擎选择的最小引擎。这直到最近才成为一个严肃的选择，因为 `IDS` 的成本大幅下降，主要是由于 `Linux` 以及该领域来自 `SQL Server` 和其他较小服务器产品的竞争。`Linux` 在最近几个月内对此也有很大作用，因为内核已经改进到 `Linux` 可以被视为数据库服务器的程度。`Linux` 优于 `NT` 的优势仍然是显而易见的；然而，即使在 `Linux` 中，也必须小心配置你的服务器以获得最佳性能。一个良好的 `DBA` 会在安装之前关注基础工作，而不是之后。

`Informix` 最新、最强大的产品是 `IDS 7.30`，不如说是 `IDS.2000`，这是一个完整的、对象关系、面向对象的引擎，为需要从符合 `SQL` 标准的关系型数据库管理系统（`RDBMS`）获取高级面向对象功能的挑剔公司提供了更多功能，而 `IDS` 无法做到。我们在本章中不会介绍 `IDS.2000`，但请记住 `IDS.2000` 的工作方式与 `IDS 7.30` 相同。你通过 `IDS 7.30` 学到的知识可以直接应用于 `IDS.2000`，仅仅因为该引擎基本上是相同的，但加入了复杂的对象关系技术。尽管这听起来很微不足道，但应该理解，尽管这两个引擎显著不同，它们的大许多基本行为是相同的。只有当使用对象关系数据库管理系统（`ORDBMS`）功能时，引擎的行为才会不同。

作为 `Linux` 历史的一点，另一个 `Linux` 数据库引擎 `Postgres` 它的根源于 `Ingress`，至少源于发明 `Ingress` 的 `Michael Stonebreaker` 博士。当 `Informix` 购买 `Postgres` 的商业版本（称为 `Illustra`）时，他们实际上是在购买 `Postgres` 背后的大脑（对象关系形式，现在是 `Postgres`），并将其重命名为 `Universal Server`。

`Postgres` 一直持续到现在，而现在被 `Informix` 吸收的 `Universal Server` 在 `IDS.2000` 中继续。`IDS 7.30` 和之前的 `Universal Server 9.x` 两个引擎结合形成了两者的之长，结果类似于过去（即 `IDS 7.30`），允许从 `IDS 7.30` 升级到 `IDS.2000`，而对环境的修改极少或无需修改。我们不会测试这种情况，但 `Informix` 发布过这不仅是可行的，而且是促销升级方案的一部分。

`Informix` 安装通常分为三个部分：

- 软件提取（`Extraction`）
- 安装品牌（`Installation branding`）

# 将软件投入运行

第一步，软件提取，涉及软件的获取和放置。这在很大程度上取决于软件分发的形式，以及将软件放置于适合形式所需的步骤。这取决于下一步，安装品牌。这一步通常是最困难的。

第二步，安装品牌，是在确定了软件最终放置地后的最后步骤。这一步在原始形式上变化不大，除非在 `Windows` 世界，`Install Shield` 取代了 `UNIX` 安装的位置。

```
INFORMIXDIR=/opt/informix/ids ; export INFORMIXDIR

INFORMIXSERVER=rebel_shm ; export INFORMIXSERVER

ONCONFIG=rebel_shm.cfg; export ONCONFIG
```

将 `rebel` 替换为你的名称；在后续过程中会引用它。请确保将这些命令放在你的 `root` 和 `informix` 配置文件中，并在继续安装之前，确保你的配置文件在登录时已将这些值引入到环境变量中。在设置 `$INFORMIX` 变量之前，安装无法正常进行，或根本无法进行。请注销并重新登录，确保在继续操作之前这些变量已设置。

从 `www.intraware.com` 下载压缩包。该压缩包内部包含一个 `RPM` 文件（其中包含 `tar` 文件）和一个安装脚本。请务必遵循 `Informix` 的建议来安装他们的软件。

# 注意事项

以下步骤应以 `root` 身份执行。如果你没有 `root` 权限，请停止当前操作，并获取安装期间的 `root` 登录权限。软件安装完成后，你仍然需要设置数据目录。除非 `Informix` 安装文档说明如此，或者非营利登录可以，否则不要使用任何其他登录。在完成最终安装和配置后，你可以放弃 `root` 登录，并使用 `Informix` 登录进行日常管理。

如果你已经安装了 `Karchiver`，并且使用的是 `KDE` 用作文件器的 `HTML/Web` 浏览器界面，可以双击压缩包来打开它。这比听起来要简单——只需在 `Autostart` 窗口中双击压缩包，归档程序就会列出其中的内容列表。此时，你应该将看到的所有内容提取到工作目录，而不是你最终安装软件的目录。在“文件”（`File`）菜单下，选择“提取到”（`Extract to`）菜单选项，选择一个目录并提取所有文件（见图 5.1）。
