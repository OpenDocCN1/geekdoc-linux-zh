## 表 7.1 基于运行时间和 Unix 变体的字段位移

| 自上次重启以来的时间： | UNIX 变体 | | | | |
| :--- | AIX | HP-UX | LINUX | SOLARIS |
| 分钟 (Minutes) | `$9` | `$9` | `$9` | `$9` |
| 小时 (Hours) | `$8` | `$8` | `$8` | `$8` |
| 天 (Day(s)) | `$10` | `$10` | `$10` | `$10` |
| 重启纪念日当天数 | `$11` | `$11` | `$11` | `$11` |
| 重启纪念日前 59 分钟内的天数 | `$11` | `$11` | `$11` | `$11` |

如你在表 7.1 所示，最当前的负载字段一直在变化。尽管对于操作系统来说，这看起来我们很幸运！我们不需要担心 Unix 变体，但我们确实必须测试自上次重启以来的时间。从之前的 `uptime` 命令输出中中，你是否注意到任何可以帮助我们确定需要提取哪个字段的内容？事实证明，对于 `uptime` 输出中五种可能的值中的每一种都有一个指示器。如果系统运行时间不足一小时，我们就对 `min` 进行 `grep`，这将匹配每个 Unix 变体的输出。如果系统运行时间超过 24 小时，我们先在 `uptime` 输出中 `grep` `day` 和 `min`，然后是 `day` 和 `hr`，最后只是 `day`。在章节结束时，我将向你展示一种更的方法来进行这种数据提取。

## 编写运行时间字段测试解决方案

通过定义的五个测试，我们使用 `grep` 从 `uptime` 命令输出中提取正确的字段。让我们看看列表 7.1 中的代码以及它是如何工作的。

```ksh
#!/bin/ksh
#
# 脚本: uptime_fieldtest.ksh
## 作者: Randy Michael
# 日期: 07/28/2002
# 平台:  Unix
# 目的: 此脚本用于演示平均负载统计字段
# 如何根据自上次系统重启以来的时间发生位移。
```

## 监控系统负载 185

```ksh
# 选项有 "min", "day", "hr" 以及组合。
# 如果所有其他测试都失败，则系统运行了
# 1-23 小时。

echo "\n" # 在屏幕上写写一个空行

# 显示当前的 uptime 输出
nuptime

# 根据系统运行的时间寻找正确的字段。

if ($uptime | grep day | grep min >/dev/null)
then
  FIELD=11
elif ($uptime | grep day | grep hr >/dev/null)
then
  FIELD=11
elif ($uptime | grep day >/dev/null)
then
  FIELD=10
elif ($uptime | grep min >/dev/null)
then
  FIELD=9
else # 机器运行了 1 到 23 小时。
  FIELD=8
fi

# 显示正确的字段。
echo "\nField $FIELD \n"
```
