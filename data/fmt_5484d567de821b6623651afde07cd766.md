
## 通用名称解析问题

常见的名称解析方法有 NetBIOS、DNS、数据库、本地文本文件。

### MS Windows

- `nslookup` 用于交互式查询 DNS 服务器的简单工具。请注意，`nslookup` 在其他操作系统平台上可用。识别名称解析问题的金标准测试是：主机系统无法通过主机名与其他系统通信，但能够通过其他方式（如 IP 地址）与系统通信。例如，查询本地配置 DNS 服务器的 `example.com` 域名的 IP 地址，输入：`nslookup example.com`
- `nbtstat` 此用于显示本地系统所知道的当前 NetBIOS 信息；也用于操作 NetBIOS 名称缓存。

### FOSS/Linux

- `dig` 是许多 Linux 发行版中功能强大的 DNS 查询工具。其语法简单。例如，查询本地配置 DNS 服务器的 `example.com` 域名的 IP 地址，输入：`dig example.com`。如果你认为本地配置的 DNS 服务器有问题，并想查询另一个 DNS 服务器：`dig <DNS_SERVER_IP> example.com`

### 域名解析问题

无法通过域名访问外部主机或站点。

确认此场景的简单简单测试方法是将任何知名外部站点的友好域名替换为其 IP 地址，并用此信息替换该站点的网页地址。例如，如果使用浏览器访问此网页地址 http://66.249.80.104 可以跳转到 Google 首页，而访问 http://www.google.com 却失败了，那么你就知道存在这个问题。

### 通用

如果无线 STA 仅通过远程主机的 IP 地址即可浏览网站，可能意味着以下两种情况之一：为 STA 配置的 DNS 服务器无法访问或不可用。

DNS 服务器可以访问且可用，但 DNS 服务器本身无法代表无线 STA 去解析外部主机名。这可能是由于本地 DNS 服务器所依赖的上游 DNS 服务器存在问题。
