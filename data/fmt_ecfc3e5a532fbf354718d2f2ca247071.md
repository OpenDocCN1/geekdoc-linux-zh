- 13. D. Linux 与 Unix 不同，它在内部维护的是协调世界时（UTC），因此将计算机的硬件时钟设置为 UTC（选项 D）是仅运行 Linux 的计算机的推荐做法。尽管林纳斯·托瓦尔斯（Linus Torvalds）曾在赫尔辛基大学学习过，但赫尔辛基时间（如选项 A）在 Linux 中并没有特殊地位。本地时间（如选项 B）在计算机双启动到 Windows 等操作系统时是合适的，因为 Windows 要求硬件时钟设置为本地时间，但对于仅运行 Linux 的系统来说，这是次优选择。像赫尔辛基时间一样，它在 Linux 中没有意义。互联网时间（选项 E）是一种模糊的计时方法，它将一天分为 1,000 个“节拍”。它不是时区，也不是设置你硬件时钟的合适方法。

- 14. 设置后，`LC_ALL` 环境变量（选项 C）会调整所有的区域（`LC_*`）变量，因此设置此变量并运行脚本将使你的脚本运行的程序就像运行在英国的计算机上一样。BIOS 没有位置代码数据，因此选项 A 是错误的。没有标准的 `etclocale.conf` 文件，因此选项 B 是错误的。没有标准的 `locale_set` 工具，因此选项 D 是错误的。虽然设置 `TZ` 环境变量（如选项 E）会将你的本地 shell 的时间设置为英国时间，但这不会影响问题中提到的排序文本格式化选项。

- 15. A. Unicode 编码转换格式 8（UTF-8）可以为地球上几乎任何语言的字符编码，而对于只理解 UTF-8 的程序来说（选项 A），它看起来像普通的 ASCII，这是在可能的情况下字符编码的首选方法。ASCII（选项 B）是一个旧标准，适用于英语和少数其他语言，但它缺乏大多数语言所需要的某些字符。ISO-8859（选项 C 和 D）是扩展 ASCII 的标准，但对不同语言需要单独编码，因此当计算机必须处理来自多种语言的数据时，它会很麻烦。ATASCII（选项 E）是 Atari 在 20 世纪 80 年代使用的 ASCII 变体；它在今天已经过时且不再满足需求。

- 16. E. 智能过滤器使打印队列变得“智能”，因为它可以接受不同的文件类型（纯文本、PostScript、图形等）并全部正确地打印它们，如选项 E 所示。字体平滑在低分辨率计算机显示器上有用，但在大多数打印机上没用，而且添加字体平滑不是智能滤波的功能，因此选项 A 是错误的。智能过滤器不会检测机密信息（选项 B）或恶作剧打印作业（选项 D）。`lpr` 命令可以接受一个参数在作业完成后向用户发送电子邮件（选项 C），但智能过滤器并不负责这一点。

- 17. B. 作业 ID（选项 B）和作业所有（选项 D）都由 `lpq` 显示。除非应用程序在文件名中嵌入了自己的名称（选项 A），否则该信息将不会显示。大多数打印机缺乏查询墨水状态的 Linux 工具（选项 C）；几乎 `lpr` 无法做到这一点。虽然知道你的作业何时将完成（选项 E）会很有用，但提供这种信息远超 `lpq` 的能力。

- 18. C. `lprm` 命令从打印队列中删除作业。它可以接受 `-pqueue` 选项来指定队列，并使用作业号或其他参数来指定要删除哪些作业。BSD LPD、LPRng 和 CUPS 都实现了 `lprm` 命令，你可以在这些任何一个系统中使用它，这使得选项 A 错误。选项 B 提供了正确的语法但使用了错误的命令名称；没有标准的 `lpdel` 命令。`cupsdisable` 命令可以禁用整个队列，但不能删除单个作业，因此选项 D 是错误的。因为选项 C 是正确的，选项 E 显然是错误的。

## 第 7 章：系统管理

- 1. E. `/etc/shadow` 文件包含哈希后的密码，且感叹号 (!) 表示账户已锁定。`usermod` 命令用于锁定账户，但它不是标准的方法。`passwd` 命令也可以锁定账户，但不是首选方法。`useradd` 命令在创建时无法锁定账户。因此，选项 D 是错误的。

- 2. A, B, C. `useradd` 命令可以通过 `-l` 选项在创建时锁定账户。`usermod` 命令也可以锁定账户。`passwd` 命令可以通过 `-l` 选项锁定账户。因此，A、B、C 都是正确的。`deadd` 命令无法锁定账户。因此，选项 E 是错误的。

- 3. A. `chage` 命令用于更改账户过期信息。`-M` 选项设置密码有效天数。因此，选项 A 是正确的。选项 B、C、D、E 错误。

- 4. D. `/etc/passwd` 文件包含 UID、GID 等其他信息，但不包含哈希后的密码。因此，D 是正确答案。选项 A、B、C 错误，E 也错误。

- 5. E. 选项 E 是完成该任务的最佳方法，因为它会将 Sally 加入 Development 组而不从其其他组移除。选项 A 会尝试将 Development 组和 Sally 加入系统，它甚至不是有效选项。选项 B 同样不是有效选项，会尝试将 Production 组和 Sally。选项 C 可以，但手动编辑账户配置文件而不是使用账户工具是非常危险的。因此，选项 C 不是最佳选择。选项 D 可以实现，但它会将 Sally 从所有组移除，包括 Production 组。因此，选项 D 不是最佳选择。

- 6. C, D. `/etc/skel` 中的文件会被某些账户创建工具复制到新用户的家目录。因此，你想放在所有用户家目录的文件应该位于 `/etc/skel` 中。选项 B、C、D 都是合理的可能性，尽管并非绝对。将 `/etc/shadow` 的副本放入 `/etc/skel`（选项 A）是一个非常糟糕的主意，因为这将允许所有用户访问其他用户的哈希密码，至少在账户创建时是这样。你不会在 `/etc/skel` 中找到包管理数据库（选项 E），因为用户不需要这些数据的特权访问，也不需要个人副本。

- 7. E. `userdel` 命令删除账户，其 `-r` 选项可以删除用户的家目录和邮件池，从而满足了问题的要求。选项 A 删除账户但保留用户的家目录。选项 B 也是如此；`-f` 在某些情况下强制删除账户和文件，但只有在配合 `-r` 使用时才有意义。选项 D 的 `rm` 命令删除用户的家目录（假设它位于常规位置，根据用户名），但不会删除用户的账户。选项 E 的 `usermod` 命令可以修改账户（包括锁定），但不能删除账户。此外，`usermod` 的 `-d` 选项是虚构的。

- 8. E. `emerg` 优先级代码（选项 E）是可用代码中最高的，高于所有其他优先级。从高到低优先级，选项给出的代码顺序为 `emerg`、`crit`、`warning`、`info` 和 `debug`。

- 9. A. `logrotate` 程序会查询一个名为 `/etc/logrotate.conf` 的配置文件（选项 A），该文件包含若干默认设置，并通常引用 `/etc/logrotate.d` 中的目录文件来处理特定的日志文件。其余选项都是虚构的，`logrotate` 的工作日志文件也是如此。
