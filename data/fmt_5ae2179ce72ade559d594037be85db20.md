
当通过诸如`http://www.domain.com/cgi-bin/notready.pl`这样的URL访问此脚本时，它会返回一个内部服务器错误消息，并在服务器错误日志文件中记录一条错误消息。您想知道为什么这个小脚本不起作用。以下是一个典型的调试会话。

1. 通过将`use CGI`行更改为以下内容，启用CGI模块的命令行调试：
   `use CGI qw(-debug);`
   这启用了该模块的命令行调试。

2. 作为root，`su`切换到Apache用户（即您设置`User`指令所指向的用户），并从命令行运行该脚本。您将看到此消息：
   `(offline mode: enter name=value pairs on standard input)`
   并且脚本将等待您的输入。

3. 在命令行模式下，在每一行输入`key=value`对，以模拟来自Web的输入。例如，为了向上述脚本提供输入，一个示例命令行会话看起来类似于这样：
   `(offline mode: enter name=value pairs on standard input)`
   `num1=100`
   `num2=200`
   上述将`num1`输入字段设置为100，将`num2`输入字段设置为200。每个字段在单独的一行中设置一个值。

4. 输入完所有输入后，按`Ctrl+D`终止调试的输入部分，并观察脚本的执行情况。上述输入的完整调试会话如下所示：
   ```
   (offline mode: enter name=value pairs on standard input)
   num1=100
   num2=200
   [control+d]
   100 + 200 = 100
   ```
   如您所见，脚本将这两个数字相加并如预期般打印了数据。那么，为什么这个脚本在从Web运行时崩溃了呢？嗯，您看到输出之前有任何`Content-Type`头部了吗？没有。如果您查看脚本，您会注意到`print $query->header;`行被注释掉了。如果您移除注释并在命令行模式下重新运行脚本，您将看到以下内容：
   ```
   (offline mode: enter name=value pairs on standard input)
   num1=100
   num2=200
   Content-Type: text/html; charset=ISO-8859-1
   100 + 200 = 100
   ```

## 通过记录日志和调试打印进行调试

这种命令行调试对于小型、不太复杂的脚本非常有用，但如果您有一个相当大的脚本，例如`formwizard.pl`，命令行调试就太繁琐了。在这种情况下，您需要结合使用记录日志和调试打印。这是一个名为`calc.pl`的示例脚本，它使用了记录日志和调试打印：

```perl
#!/usr/bin/perl -w

use CGI qw(-debug);

use constant DEBUG => 1;

my $query = new CGI;

my $num1 = $query->param('num1');

my $num2 = $query->param('num2');

print $query->header;

if ($num1 == $num2) {

    # do something useful

    DEBUG and print STDERR "num1 and num2 are same.\n";

} elsif ($num1 > $num2 ) {

    # do something useful

    DEBUG and print STDERR "num1 is greater than num2.\n";

} elsif ($num1 < $num2 ) {

    # do something useful

    DEBUG and print STDERR "num1 is less than num2\n";

}

print $query->start_html('Calculator');

print $query->h1('Calculator');

print $query->p("Number 1: $num1");

print $query->p("Number 2: $num2");

print $query->end_html;

exit 0;
```

当通过诸如`http://www.domain.com/cgi-bin/calc.pl?num1=100&num2=300`这样的URL调用此脚本时，它会在该站点的标准错误日志中打印信息。对于上述URL，错误日志中的条目将类似于：

```
[Tue Mar 20 20:04:26 2001] [error] [client 207.183.233.19] num1 is less than num2
```

以下语句打印此错误消息：

```
DEBUG and print STDERR "num1 is less than num2\n";
```

关于这一行有趣的地方在于，它使用了一个名为`DEBUG`的常量，该常量在脚本开头通过以下这行设置：

```
use constant DEBUG => 1;
```

`DEBUG`和`print`语句中的逻辑如下：

- 当`DEBUG`设置为1或任何非零数字时，它相当于`DEBUG`在逻辑运算中获得的“真”值。
- 内置的`print`函数在成功打印时总是返回一个非零值。
- 因此，当Perl评估`DEBUG`和`print`时，它会执行`print`语句。
- 当`DEBUG`设置为0时，`DEBUG`和`print`语句不会执行。

这使得您能够插入可以成为代码一部分的`print`语句，但在调试完成后可以将其关闭。请注意，`print`语句写入`STDERR`，它始终将数据写入网站的错误日志。

要关闭这些语句，您只需将`DEBUG`常量设置为0。现在，有些人可能会认为，当您准备将脚本交给生产环境时，应该完全从脚本中删除这些`DEBUG`语句。这种论点的理由是，即使这些`DEBUG`语句没有打印任何内容，Perl仍然会评估它们，从而减慢脚本速度。事实是，在CGI解决方案中，速度差异可能并不重要，因为CGI脚本本来就比`mod_perl`或其他持久化解决方案有更高的开销。但如果您担心这一点，那么在将脚本发送到生产环境之前删除`DEBUG`语句。

## 使用 CGI::Debug 进行调试

现在让我们看看另一种调试解决方案。使用`CGI::Debug`模块可以在调试您的CGI脚本方面获得很多帮助。只需在脚本中的`use CGI;`语句后紧接着添加此模块，您就能捕捉到所有类型的错误。例如：

```perl
#!/usr/bin/perl -w

use CGI;

use CGI::Debug;

my $query = new CGI;

my $num1 = $query->param('num1');

my $num2 = $query->param('num2');

#print $query->header;

print $query->start_html('Calculator');

print $query->h1("Calculator");

print $query->p("Number 1: $num1");

print $query->p("Number 2: $num2");

print $query->end_html;

exit 0;
```

我故意注释掉了`$query->header`这一行，因为该行通常会在Web浏览器上生成内部服务器错误消息。但是，由于我在这个脚本中添加了`use CGI::Debug;`语句，当通过`http://www.domain.com/c/s.dll/cgidebug.pl?num1=1&num2=200`访问该脚本时，它将显示以下内容：

```text
/cgi-bin/cgidebug.pl

Malformed header!

--- Program output below  ----------------------

<?xml version="1.0" encoding="utf-8"?>

<!DOCTYPE html

  PUBLIC "-//W3C//DTD XHTML Basic 1.0//EN"

  "http://www.w3.org/TR/xhtml-basic/xhtml-basic10.dtd">

<html xmlns="http://www.w3.org/1999/xhtml" lang="en- US"><head><title>Calculator</title>
```
