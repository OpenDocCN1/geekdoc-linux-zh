
# 摘要

Linux 与任何操作系统（OS）一样，都是构建在其文件系统上的。`ext2` 文件系统长期以来一直是 Linux 的标准，但在 `2.4.x` 内核开发过程中，新的日志文件系统已作为标准配置引入。这些文件系统为你提供了几个选项，它们在细微方面有所不同——例如不同类型的文件的磁盘空间消耗、对 `ACL` 的支持等。大多数系统在任何 Linux 文件系统上都能良好工作，但如果磁盘性能对你至关重要，你可能希望进一步研究这些选项，以根据你的需求选择最佳的一个。你还可以通过多种方式优化文件系统，从文件系统的创建时间到碎片整理和文件系统调整。遗憾的是，文件系统并不总是运行得完美可靠。有时你可能需要修复文件系统损坏，存在许多工具可以帮助你完成这一点。用户也可能意外删除文件，恢复这些文件可能是一项挑战性任务，尽管使用垃圾箱工具和进行定期备份可以极大地简化恢复操作。

# 第 13 章

## 管理打印机

尽管几十年来一直声称即将到来，但“无纸办公室”似乎永远迟到。从某种意义上说，今天的办公室处理纸张比以往任何时候都要多。部分原因，这可能归功于极其强大的计算机技术：打印机。在打印机的帮助下，你只需几个简单的命令就能产生大量的输出。遗憾的是，配置打印机使其正常工作并不总是那么容易。

Linux 支持多种打印系统。了解你的发行版使用哪种系统对于打印机配置至关重要，在某些情况下你可能需要切换系统。在所有这些系统中，通常的假设是你拥有一个 `PostScript` 系统。如果你没有，可以使用 `Ghostscript`。`Ghostscript` 将 `PostScript` 转换为你能够理解的打印机语言，因此了解如何调整你的 `Ghostscript` 配置可以帮助你生成更好或更快的输出。今天，网络打印是共享资源的流行手段，因此如何配置 Linux 切换打印机或使用共享打印机（包括非 Linux 打印队列）可以极大地帮助你的打印状况。

## 选择最好的 Linux 打印系统

三个 Linux 打印系统分别是原始的伯克利标准发行版打印守护进程（`BSD LPD`）、下一代 `LPRng` 和通用 Unix 打印系统（`CUPS`）。每个系统都有其优势，并以其自己的方式进行配置。每个发行版都倾向于这些系统中的一个，如表 13.1 所示，因此在一种发行版上的配置可能与另一个发行版不同。理解这些差异将帮助你在系统上顺利打印，并可能帮助你通过从一个系统切换到另一个系统来改进你的打印体验。

> **注意** 本章对于配置这些打印机系统的基础知识介绍较少。大多数发行版包含了打印机配置工具，这些工具将设置一个工作尚可的打印机。相反，本章重点关注由你发行版工具设置的队列。

### 表 13.1：各种 Linux 发行版偏好的打印系统

| 发行版 | 标准打印系统 | 备用打印系统 |
| :--- | :--- | :--- |
| `Debian GNU/BSD` 3.0 | `BSD LPD` | `LPRng`, `CUPS` |
| `Mandrake Linux` 9.1 | `CUPS` | `LPRng` |
| `Red Hat Linux` 8.1 | `CUPS` | `LPRng` |
| `Slack Linux` 9.0 | `LPRng` | 无 |
| `SuSE` 8.1 | `CUPS` | 无 |

## 何时选择 BSD LPD

`BSD LPD` 是 Linux 打印系统中最老的，Linux 发行版在几年里一直在背离它。尽管如此，`BSD LPD` 仍然是 `Debian` 3.0 的默认打印系统，尽管这种说法有些误导性。`Debian` 安装了 `LPD`（通过 `lpr` 包），默认情况下，你可以在安装时通过选择相应的包来选择另一个打印系统。在安装 `Debian` 后，你也可以通过将 `lpr` 包替换为较新系统的包（`lprng` 或 `cupsys`）来替换 `BSD LPD`。

`BSD LPD` 是传统的 Linux 打印系统，因此较旧的文档中描述了它。如果你有一本关于打印机配置有详尽信息的 Linux 旧书，你可能想简单地使用 `BSD LPD`，以便让你的文档与书籍保持一致；`LPRng` 可以使用与 `BSD LPD` 的一些配置文件。因此，`LPRng` 可以按照 `BSD LPD` 相同的方式进行配置——至少对于本地计算机上的应用程序是。另一方面，现代发行版将 `BSD LPD` 作为默认打印系统，或带有 `BSD LPD` 选项发布，如表 13.1 所示。因此，如果你想安装它，就必须找到它。一个你发行版旧版本的副本可能是最好的；大多数系统在 2000 年左右背离了 `BSD LPD`。

`BSD LPD` 在重要方面存在局限。最显著的一点是它不向应用程序提供关于打印机能力的反馈。例如，如果你有一个宽幅打印机或带有双面打印器的打印机，`BSD LPD` 无法将此信息传递给应用程序。因此，你必须在同一基础上配置每个应该用于访问高级功能的打印应用程序——这是一个潜在的繁琐的命题。`BSD LPD` 还缺乏跨网络自动传播可用打印机列表的方法，这意味着每个客户端都需要单独配置以使用打印服务器——再次，这是一个潜在的繁琐任务。

`BSD LPD` 通过 `/etc/lpdcap` 文件进行配置。这种格式与 `LPRng` 使用的文件类似。它定义了本地系统打印队列中的打印机。这些打印机可以是本地的（即连接到并行端口、USB 端口等），也可以是网络打印机（即连接到另一台计算机并由你的计算机共享）。

如果你想在 `LPD` 系统上共享打印机，必须编辑 `/etc/hosts`，正如后文章节“`LPD` 控制”所示。

> **注意** 所有的 Linux 功能以守护进程的形式运行。在工作站上，这些守护进程应该接受本地连接，但网络协议允许请求。

## 何时选择 LPRng

如表 13.1 所示，`Slack` 是唯一使用 `LPRng` 作为其主要打印系统的主流 Linux 发行版，尽管其他几个仍带有 `LPRng` 作为备用。在大版本之前，几个其他发行版使用 `LPRng` 作为它们的主要打印系统，因此在许多旧 Linux 安装中可能会发现它。

`LPRng` 设计为 `BSD LPD` 的替代品。`LPRng` 与 `BSD LPD` 使用相同的网络协议，因此运行这两个包的计算机可以使用彼此的打印机。`LPRng` 使用 `/etc/printcap` 文件来定义打印机，`LPD` 也是如此。列表 13.1 显示了示例。从技术上讲，每个条目都是单行冒号分隔字段；然而，为了人类易读，条目通常使用反斜杠（`\`）跨行，这告诉系统将下一行视为第一行的延续。

### 列表 13.1：示例 /etc/printcap 文件

```
1p|epson:
s=/var/spool/1p0/
lp=/dev/1p0:
mx=0:
sh=:
if=/var/spool/1p0/filter:
1pl|hplj:
s=/var/spool/1p1/
rm=pserver:
r=hplj:
mx=0:
if=/var/spool/1p1/filter:
```
