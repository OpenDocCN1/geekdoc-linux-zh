
`lpstat` 将 LP 打印服务的当前状态信息显示到标准输出。示例：

```
$ lpstat printer1
printer1-106 root 587 Mar 22 16:06 on printer1
printer1-107 user2 85 Mar 22 16:10 on printer1
$
```

## 关键术语

**打印任务编号**：在 LP 系统中，自动分配给每个打印请求（称为“任务”）的数字。

**打印管理器**：一个用于管理打印队列的图形化工具。它执行许多与 `lpstat` 命令相同的功能。要激活打印管理器，请点击前面板上的打印机图标。

**打印机**：一种物理打印设备。打印机可能连接到工作站或网络服务器，也可以包含网络接口卡（NIC）并直接连接网络。

**打印机名称**：与物理打印机关联的队列名称。它是打印机的逻辑名称，由系统管理员分配。这是用户打印时使用的名称。

**打印队列**：位于打印服务器硬盘上的目录。打印请求或打印任务存储在硬盘上，直到被打印，然后就会被删除或清除。

**打印服务器**：用于管理入站打印请求并在打印机就绪时释放请求的计算机。打印服务器运行管理请求的打印守护进程 `lpd`。打印服务器可以是工作站，也可以是网络服务器。

**池化**：池化是将项目放入队列，每个项目按顺序等待某些操作（如打印）。

## 第 12 章：数据备份

## 引言

本章涉及网络安全和支持中最重要的领域之一：数据的备份与恢复。备份是全面安全计划中的另一个关键组件。本章涵盖了最常见的网络和工作站备份策略，然后介绍了内置的 UNIX 备份实用程序。

为了通过电子邮件、ftp 或其他方法备份或方便地传输文件，你需要能够轻松地打包和恢复文件。在本章中，你将使用带归档（`tar`）和 Java 归档（`jar`）实用程序进行数据备份以及从备份中恢复数据。这还涵盖了 UNIX 文件压缩实用程序以及使用文件管理器（File Manager）执行基本备份任务。此外，还包含了使用 `tar` 和 `compress` 命令备份和恢复主目录的特定说明。最后，介绍了第三方压缩程序 `gzip` 和 `zip`。

## 备份的重要性

良好的备份对于网络的健康至关重要。良好的备份系统的价值在紧急情况下需要时最能体现。当系统宕机且数据无法使用时，人们无法完成工作，公司无法开展业务。

管理良好的网络包含了系统管理员执行的定期备份。如果网络管理员没有良好的备份或无法快速恢复数据，可能会因此失去工作。拥有良好的备份系统和经过测试的恢复过程可以为组织节省数百万美元和数千小时的生产力损失。

## 硬盘故障

磁盘驱动器（软盘、硬盘和 CD）是计算机中最可能发生故障的组件，因为它们是电机械设备（包含电气和机械部件），并带有会磨损的运动部件。计算机中的大多数其他组件（如 CPU 和 RAM）都是没有运动部件的电子设备。

当硬盘故障时，驱动器上的部分或全部数据可能会损坏或变得无法访问。这就是为什么为网络服务器开发了冗余独立磁盘阵列第 5 级（RAID 5）等容错磁盘系统的原因。RAID 5 将三个或更多驱动器组成一组，这样如果其中一个故障，其他的就会接管。可以更换坏驱动器而不会导致用户中断。另一种容错技术 RAID 1（或镜像）使用两个驱动器，第二个驱动器存储与第一个相同的数据。如果其中一个驱动器故障，另一个将接管。使用双驱动器控制器的更强大的 RAID 1 版本被称为双工。容错磁盘系统是稳健备份策略的第一道防线。

## 文件损坏

文件损坏可能由于许多原因引起，包括系统关闭不当、数据附近的磁场（来自电机和其他电气设备）或磁盘损坏。在任何情况下，数据都会变得无法访问。良好的备份系统允许管理员查找并恢复可能丢失的特定文件或组文件。

## 恶意破坏

文件也由于故意破坏而丢失。文件删除可能来自不满的员工、病毒攻击或远程访问系统的黑客。损坏范围从删除一两个文件到丢失硬盘上的所有数据不等。

大多数病毒攻击来自互联网，防火墙在某些情况下可以提供帮助。幸运的是，病毒很少感染 UNIX 系统，但大多数操作系统并非如此。对于非 UNIX 操作系统，可以安装防病毒软件来帮助在病毒造成破坏之前检测并清除。防火墙还能防止数据的破坏。适当的文件权限在员工删除数据的情况下提供了良好的保护。任何预防措施无法提供完全保护，最好的防御是对重要数据进行备份。

## 灾难

火灾和洪水等灾难会破坏计算机、数据中心和整个建筑。第 10 章“文件系统”讨论了应急恢复计划的重要性。如果火灾毁了业务场所，公司如何恢复？每天或每小时需要多少成本？

备份是应急恢复计划的重要组成。为了让系统快速运行，对关键数据进行高质量、及时备份是非常重要的。备份还应包含操作系统和应用程序软件的副本以便重新安装，这些副本应存储在外部附近的地点。

## 意外删除/覆盖

用户意外删除文件并不罕见。从命令行删除的文件无法恢复，除非从备份恢复。如果无法从备份中恢复文件，可能需要重新创建，导致生产力损失。使用 CDE 文件管理器删除的文件可以从垃圾箱中恢复。

工作也可能由于意外覆盖而丢失。这发生在用户创建文件副本并对其进行重大修改时，然后用户打开原始文件并保存更改进行覆盖。在将文件从一个位置复制到另一个已存在文件的位置时也可能覆盖文件。当这种情况发生时，恢复原始文件的唯一方法是从数据备份。

## 备份方法

可以根据备份所需的时间和恢复数据的难易程度对几种备份类型或方法进行比较。常见的备份类型是全量备份、增量备份和差异备份。讨论的方法都假设每天将关键用户数据备份到磁带驱动器。磁带备份媒介的替代方案将在本章后半部分讨论。操作系统和应用程序软件通常不需要进行备份，因为它们可以从原始介质重新安装。

通常会有一组 5 到 7 个每日磁带、4 或 5 个每周磁带和 12 个每月磁带。每日磁带每周可以覆盖一次。每周磁带每月可以覆盖一次，而每月磁带通常会被保留且不覆盖。每周和每月磁带应存异地。

如果要备份的数据量需要多张磁带，可能需要安装容量更大的磁带驱动器或换带系统。如果没有，则在第一张磁带完成后时需要有人在场放入下一张磁带。不同组织执行的备份方法各异。然而，所有组织在确定采用何种方法时都会考虑若干因素：

- 待备份数据的关键性
- 待备份的数据量
- 可用的备份时间窗口
- 备份系统的可用资金

数据丢失对小企业和大公司来说都是具有破坏性的。备份系统不是削减成本的地方。图 12-2 比较了三种不同的备份方法，图 12-3 显示了每天备份数据量之间的关系。

在全备份中，所有关键数据每天都会备份。每天晚上下班后，所有数据都会被备份，无论其是否发生了变化。这种方法耗时最长，取决于数据量，可能需要多张磁带。如果数据量过大，可能需要容量更大的驱动器或换带系统。

## 增量备份

在增量备份中，数据是以增量方式备份的。所有关键数据每周在特定一天备份一次（例如周日晚上）。从那以后每天，只备份变化部分。周一的下一次备份将只备份新文件或自周日晚上以来发生变化的文件。周二的备份将只备份自周一备份以来的新和更改的文件。周三的备份将只获取自周二以来的新和更改的文件，依此类推，直到你回到周日，周日晚上的全备份创建基准备份并可能花费大量时间，接下来的每日备份则非常快。

使用增量备份时，每张磁带都包含整个备份的一部分。因此，备份数据所需的总时间明显少于每天执行全备份。增量备份的缺点是重建数据可能需要的磁带数量。如果硬盘在周一早上故障，周日晚上的备份磁带将是恢复数据所需的唯一磁带。然而，如果硬盘在周五早上故障，则需要周日的全备份加上周一至周四的增量备份磁带才能完全恢复数据。这意味着你必须成功从五张磁带中读取并恢复，这可能会出现问题。这导致恢复过程更加复杂且耗时。由于增量备份每天只将部分数据备份到多张磁带上，因此任何一张磁带的故障都会导致备份损坏。也就是说，如果你需要五张磁带来完成恢复，只要其中任何一张无法读取，整个备份将是无效的。

## 差异备份

在差异备份中，你仍然每周执行一次全备份（周日）。周一，备份自周日以来发生的所有变化。周二，同样备份自周日以来发生的所有变化。周三，再次备份自周日以来发生的所有变化，依此类推。周一的备份可能不会花费太多时间，因为你只备份了一天的数据（与增量备份相同），从那以后每天的备份将花费更长时间。在周六，自上周日以来发生的所有变化（即六天的数据）都会备份。

差异备份是全备份和增量备份之间的折中。它比全备份快，因为你不需要每晚都备份所有数据，但它比增量备份慢。如果硬盘故障且你需要恢复所有数据，只需要两张磁带。例如，如果硬盘在周五早上故障，你只需要周日和周四，因为周四的包含了周日以来的所有内容。

## 数据恢复问题

讨论的所有备份方法都允许在丢失时恢复数据。快速恢复数据的能力是良好备份系统的真正测试。仅仅进行夜备份而不练习恢复过程是不够的。

用户通常不需要备份自己的文件。这是网络管理员或网络支持人员的工作。网络支持人员不仅必须定期进行备份，还必须定期测试备份以验证它们是良好的，并且可以从中恢复数据。

应该通过进行“测试恢复”来定期检查备份，以验证它们在各种情况下都是良好的。

为了充分测试从数据丢失的能力，网络支持人员应该能够完成以下恢复任务，总结在图 12-4 中：

- 恢复文件——任何组织通常都会备份数千个文件。如果用户不小心删除或覆盖文件，管理员应该能够从备份磁带中找到该文件并将其恢复到服务器或工作站的用户主目录。
- 恢复目录——如果目录损坏，管理员应该能够恢复整个目录结构，并保持子目录和文件完好。
- 恢复文件系统——如有必要，管理员应该能够恢复整个文件系统。
- 恢复硬盘——在硬盘完全故障的情况下，管理员应该能够重建原始硬盘的内容，包括操作系统、应用程序软件和数据（如果适用）。

## 磁带备份介质

多种不同的介质可用于备份数据，范围从极低容量的软磁盘到高容量的磁带驱动器。

流式磁带是备份大量数据最常用的介质。磁带驱动器是顺序记录设备，这意味着当磁带通过读写头时，数据从一端到另一端以位流的形式被记录。

要在磁带上定位特定文件，必须将其回带或快进到文件被记录的位置。这可能需要几分钟时间，取决于驱动器的速度和文件所在。尽管如此，现代磁带驱动器将继续被广泛使用，因为它们效率高、具有成本效益，并且是一种经过验证的解决方案。

如今的新型磁带驱动器体积小、速度快，并且具有巨大的记录容量。磁带备份的每兆字节成本是所有记录介质中最低的。一张录像带大小磁带可以记录超过 100 GB（吉字节，或十亿）的数据。带有多个磁带的自动装载系统可以远超此。

## 磁磁盘和光盘

虽然磁带在传统上一直是首选介质，但新类型的备份介质开始流行，包括光刻录（CD-R）磁盘和 CD 可重写（CD-RW）光盘。各种形式的磁介质，如移动式硬盘、Jaz 和 Zip 磁盘也变得越来越常见。这些备份介质的大部分并非备份大量数据，但它们是灵活的替代方案，速度很快，并且可以视为计算机上的另一个磁盘驱动器。

磁盘驱动器无论是磁性的还是光学的都有一个共同点：它们是随机访问设备。它们不像磁带那样需要调整或回带，而是可以在几秒内搜索并找到所需的文件。这使得它们在备份较少的数据（通常小于 1 或 2 GB）时非常灵活。可写 CD 光盘盒可以以最大的灵活性处理大量数据；然而，它们相对贵。图 12-5 显示了可用的备份介质种类，图 12-6 按容量顺序列出了它们。

## 使用 tar 备份文件

UNIX 操作系统有几个集成实用程序允许对多个文件进行备份和压缩。`tar`（磁带归档）命令允许你备份目录层次结构中的单个或多个文件。`tar` 命令是所有版本 UNIX 操作系统的标准。尽管它最初是为磁带驱动器开发的，但 `tar` 可以将文件复制到硬盘的其他位置或软磁盘和移动介质。

`tar` 命令可以从单个文件创建归档，但它主要用于将多个文件（例如目录的内容）合并成单个文件，并在以后需要时提取它们。它本身在打包文件时并不会压缩文件，像 PC 上的 PKZIP 和 WinZip 程序那样。

`tar` 命令最常用的选项是 `c`、`t` 和 `x`。没有必要在这些选项前加连字符（`-`），但加上它也是可以接受的，就像其他 UNIX 命令选项一样。命令语法在此所示。参考图 12-7 查看带有语法说明的示例。图 12-8 显示了用于 `tar` 命令的函数（字母和修饰）。

```
tar function [modifier] [output file] filename[directory]
```

## tar 函数

`tar` 函数是单字母表示的字符，用于创建 tar 文件、查看 tar 文件内容或从 tar 文件中提取文件。这里总结了这些函数：

- `c` (create)——创建——用于创建一个或多个文件或目录以创建一个归档文件。
- `t` (table of contents)——目录——用于查看 tar 文件的目录，列出组合成一个 tar 文件的列表。
- `x` (extract)——提取——用于从归档中提取文件并将其分离为多个文件。操作完成后，tar 文件仍然存在。

| x | 提取 | 从归档中提取文件。 |

| 修饰字母（小写） | 含义 | 执行的函数 |
| --- | --- | --- |
| f | 文件 | 指定输出文件。 |

## 使用 tar 创建归档

### 备份 user2 目录到磁带：

```
$ cd
$ tar cv user2
a user2/file1 0k
a user2/file2 0k
...（省略输出）
```

### 备份 dir2 目录到子目录：

```
$ cd
$ tar cvf /home/user2/backup.tar dir2
a dir2/ 0k
a dir2/beams/ 0k
a dir2/recipes/ 0k
a dir2/notes 2k
```

### 备份选择文件到硬盘：

```
$ cd
$ tar cvf files.tar file1 file2
a file1 1K
a file2 1K
```

```
$ cd
$ tar tvf files.tar
-rw-r--r-- 1 1002/10 512 mar 28 5:53 2001 file1
-rw-r--r-- 1 1002/10 512 mar 28 5:53 2001 file2
```

### 备份选择文件到软磁盘：

```
$ cd
$ tar cvf /dev/diskette file1 file2
a file1 1K
a file2 1K
```
