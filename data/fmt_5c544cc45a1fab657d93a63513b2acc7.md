## 提示 (Prompting)

初始使用时，shell 在读取命令前使用 `PS1` 的值进行提示。如果在任何时候你按下回车且需要进一步输入以完成命令，则会显示次级提示（即 `PS2` 的值）。

## 环境 (Environment)

环境（参见 `environ(5)`）是一个键值对列表，以类似于普通参数列表的方式传递给执行的程序。shell 与环境交互并为找到的每个名称创建一个参数，赋予其相应的值。在调用时，shell 会扫描环境并为找到的每个名称创建一个参数。如果你修改了这些参数的任何一个值或创建了新参数，除非使用 `export` 命令将 shell 的参数绑定到环境（另见 `set -a`），否则这些都不会影响环境。你可以使用 `unset` 命令从环境中删除参数。因此，任何执行命令的环境由 shell 继承的任何未修改的键值对组成，减被 `unset` 删除的对，加上任何修改或添加，所有这些必须在 `export` 命令中注明。

你可以通过在任何命令前加上一个或多个参数赋值来扩展环境。因此：

```
TERM=450 command
```

和

```
(export TERM; TERM=450; command)
```

就命令的执行而言，如果 `command` 不是特殊命令，这两者是等效的（参见第 1223 页的“特殊命令”）。如果 `command` 不是特殊命令，那么

```bash
TERM=450 command
```

它将修改当前 shell 中的 `TERM` 变量。

如果设置了 `-k` 选项，所有关键字参数都将放入环境中，即使它们出现在命令名之后。以下示例打印 `a=b c` 和 `c`。

```bash
$ echo a=b c
a=b c
$ set -k
$ echo a=b c
c$
```

> 注意 — 如果执行了一个命令，并且在找到原始命令之前在搜索路径的目录中安装了同名命令，shell 将继续执行原始命令。使用 `hash` 命令来纠正此情况。

## 信号 (Signals)

如果调用的命令后面跟着 `&:`，则命令的 `INTERRUPT` 和 `QUIT` 信号被忽略；否则，信号具有 shell 从其父进程继承的值，但信号 11 除外（但另见 `trap` 命令）。

## 执行 (Execution)

每次执行命令时，都会执行上述的命令替换、参数替换、空白解释、输入/输出重定向和文件名生成。如果命令与定义的函数名称匹配，则在 shell 进程中执行该函数（注意这与执行 shell 脚本的不同之处，后者需要通过子 shell 进行调用）。如果命令名不匹配定义的函数名称，但匹配下面列出的特殊命令之一，则在 shell 环境中执行。位置参数 `$1`, `$2`, `. . .` 被设置为函数的参数。如果命令名既不匹配特殊命令也不匹配定义的函数名称，则创建一个新进程并尝试通过 `exec(2)` 执行命令。

shell 参数 `PATH` 定义了包含命令的目录的搜索路径。替代目录名用冒号（:`）分隔。默认路径为 `/usr/bin`。它可以是一个紧跟在等号后面、路径列表任意位置两个冒号分隔符之间、或路径列表末尾的路径名。如果命令名包含 `/`，则不使用搜索路径。否则，将在路径中的哪个目录中搜索可执行文件。如果该文件具有执行权限但不是 `.out` 文件，则假设它是一个包含 shell 命令的文件。系统将产生一个子 shell 来读取它。带括号的命令也会在子 shell 中执行。

命令在搜索路径中被记录的位置（以避免以后执行不必要的 `exec` 命令）。如果在相对目录中找到命令，每当当前目录更改时，必须更新其位置。当 `PATH` 变量更改或执行 `hash -r` 命令（见下方）时，shell 会忘记所有记录的位置。

## 特殊命令 (Special Commands)

现在允许这些命令进行输入重定向。文件描述符 `i` 是默认输出位置。当启用作业控制时，会在 shell 环境中添加额外的特殊命令（参见第 1229 页的“作业控制”）。

- `+` 什么都不做。返回退出码 0。
- `filename` 从 `filename` 读取并执行命令，并使用 `PATH` 指定的搜索路径找到包含 `filename` 的目录。
- `bg [%jobid ...]` 当作业控制启用时，环境中的 `bg` 命令可以操作作业。在后台恢复已停止作业的执行。如果你省略 `~jobid`，则假设为当前作业（详情见第 1229 页“作业控制”）。
- `break [n]` 退出封装的 `for` 或 `while` 循环。如果你指定了 `n`，则跳出 `n` 层。
- `cd [argument]` 将当前目录更改为 `argument`。shell 参数 `HOME` 是默认参数。shell 参数 `CDPATH` 定义了包含 `argument` 的目录的搜索路径。替代目录名用冒号（:`）分隔。默认路径为空（指定当前目录）。它可以是一个紧跟在等号后面、路径列表任意位置两个冒号分隔符之间的路径名。如果 `argument` 以 `/` 开头，则不使用搜索路径。否则，在路径的每个目录中搜索 `argument`。如果 `dir` 是相对路径名，则更改到主目录。如果在当前目录未找到 `dir`，则在 `CDPATH` 列出的目录中检查。如果 `dir` 是以 `/` 开头的 shell 变量名，则更改到该值指定的目录。
- `continue [n]` 继续封装的 `for` 或 `while` 循环的下次迭代。如果指定了 `n`，则从第 `n` 次循环继续。
- `echo [...]` 将参数中的单词用空格分隔写入标准输出。完整用法和描述参见 `echo(1)`。
- `eval [argument...]` 将参数作为 shell 输入并执行生成的命令。
- `exec [argument...]` 用参数指定的命令替换此 shell 且不创建新进程。可以出现输入/输出参数，如果没有其他参数，则修改 shell 的输入/输出。
- `exit [n]` 以 `n` 指定的状态退出 shell 或 shell 脚本。如果你省略 `n`，则使用上一次执行命令的退出状态（文件结束也会退出 shell）。
- `export [name...]` 将给定的名称标记为自动导出到后续执行命令的环境中。如果你没有指定参数，则列出当前 shell 执行期间标记为导出的名称。（从父 shell 导出的变量名仅在当前 shell 执行期间再次导出时才会列出。）函数名不导出。
- `fg [%jobid...]` 当作业控制启用时，向环境添加 `fg` 命令以操作作业。在前台恢复已停止作业的执行；也将正在执行的后台作业移到前台。如果你省略 `%jobid`，则假设为当前作业。（详情见第 1229 页。）
- `getopts` 在 shell 脚本中使用以支持命令语法标准（参见 `intro(1)`；解析位置参数并检查合法选项。用法和描述参见 `getoptcvt(1)`。

`hash [-r][name ...]`

对于每个 `name`，在搜索路径中确定由 `name` 指定并由 shell 记住命令的位置。`-r` 选项忘记所有已记住的位置。如果不指定任何参数，则显示有关已记忆命令的信息。

Hits（命中）是 shell 进程调用命令的次数。Cost（代价）是衡量如果在搜索路径的相对目录中找到命令，切换到该目录后定位该命令所需的工作量，并重新计算该命令的存储位置。Hits 信息旁边带有星号（*）的命令表示指示了此操作。当进行重新计算时，Cost 会随之增加。
