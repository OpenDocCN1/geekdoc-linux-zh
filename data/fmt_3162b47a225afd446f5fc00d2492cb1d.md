
同样，由于大括号和分号对 shell 具有特殊含义，因此必须对它们加引号或转义。还可以通过交互方式执行用户定义的动作。通过在`-exec`中使用`-ok`动作，系统会在执行每个指定的命令前提示用户。

```
find -type f -name 'foo*' -ok ls -1 '{}' ;
< ls ... /home/me/bin/foo > ? y
-rw-r--r-- 2027-10-29 18:44 /home/me/bin/foo
< ls ... /home/me/foo.txt > ? y
-rw-r--r-- 2016-09-19 12:53 /home/me/foo.txt
```

在这个示例中，我们搜索以字符串`foo`开头的文件，并在每次找到文件时执行命令`ls -1`。使用`-ok`动作会在执行`ls`命令之前提示用户。

## 提高效率

当使用`-exec`动作时，每找到匹配的文件，它都会启动指定命令的新实例。有时，我们可能倾向于合并所有的搜索结果并启动单个命令实例。而不是像这样执行命令：

```
ls -1 file1
ls -1 file2
```

我们可能更倾向于这样执行：

```
ls -1 file1 file2
```

这会导致命令只执行一次，而不是多次。实现这一点有两种方法：传统方法是使用外部命令`xargs`，另一种方法是使用`find`本身的新功能。我们将讨论后一种方法。

通过将末尾的分号改为加号`+`，我们激活了`find`的功能，将搜索结果合并为单个所需命令执行的参数。回到我们的示例，这将在每次找到匹配的文件时执行：

```
find -type f -name 'foo*' -exec ls -1 '{}' + ;
-rw-r--r-- 1 me 22 2007-10-29 18:44 /home/me/bin/foo
-rw-r--r-- 1 me 06 2016-09-19 12:53 /home/me/foo.txt
```

通过将命令改为如下：

```
find -type f -name 'foo*' -exec ls -1 '{}' +
-rw-r--r-- 1 me 22 2007-10-29 18:44 /home/me/bin/foo
-rw-r--r-- 1 me 06 2016-09-19 12:53 /home/me/foo.txt
```

我们得到了相同的结果，但系统只需要执行一次`ls`命令。

## `xargs`

`xargs`命令执行了一个有趣的功能。它接受来自标准输入输入并转换为单个命令的参数列表。对于我们的示例，我们将这样使用它：

```
find -type f -name 'foo*' -print | xargs ls -1
-rw-r--r-- 1 me 22 2007-10-29 18:44 /home/me/bin/foo
-rw-r--r-- 1 me 06 2016-09-19 12:53 /home/me/foo.txt
```

在这里我们看到`find`命令的输出被传递到`xargs`，`xargs`随后为`ls`命令构建参数列表并执行它。

> 虽然命令行中可以放置的参数数量很大，但并不是无限的。可能会创建 shell 无法接受的过长命令。当命令行超过系统支持的最大长度时，`xargs`将以尽可能多的参数执行指定的命令，并重复此过程直到标准输入耗尽。要查看命令行的最大限制，请带有`--show-limits`选项执行`xargs`。

## 处理特殊的文件名

Unix 类系统允许在文件名中嵌入空格（甚至是换行符！）。这为像`xargs`这样为其他程序构建参数列表的程序带来了麻烦。嵌入的空格会被视为分隔符，导致生成的命令将每个由空格分隔的单词解释为独立的参数。为了克服这个问题，`find`和`xargs`允许可选使用空字符（null character）作为参数分隔符。空字符在 ASCII 中定义为零表示的字符（区别于空格）。`find -print0`将空字符输出到标准输出，而`xargs -0`可以读取以空字符终止的参数。

```
find . -print0 | xargs -0 ls -l
```

这种技术确保了包含空格、制表符甚至换行符的文件名被正确处理。

最后，让我们回到之前执行的错误权限测试，并将其应用于`/playground`。

```
me@linuxbox ~$ find playground \(-type f -not -perm 0600 \) -or \(-type d -not -perm 0700 \)
```

此命令列出了`playground`中所有的 100 个目录和 2,600 个文件（以及时间戳和`playground`本身，总共 2,702 个），因为其中没有一个文件符合我们对“良好权限”的定义。根据我们对操作符和动作的知识，我们可以向此命令添加动作，以对`playground`中的文件和目录应用新的权限。

```
me@linuxbox ~$ find playground \(-type f -not -perm 0600 -exec chmod 0600 '\{\}; ';' \) -or \(-type d -not -perm 0700 -exec chmod 0700 '\{\}; ';' \) \)
```

在日常工作中，执行两个命令（一个针对目录，一个针对文件）可能比执行这个大型复合命令更简单，但知道我们可以这样做是很不错的。这里的关键点是理解操作符和动作如何结合使用来执行有用任务。

## 压缩文件

在整个计算历史上，人们一直在努力将尽可能的数据放入最小的可用空间中，无论该空间是内存、存储设备还是网络带宽。我们今天认为理所当然的许多数据服务，如手机业务、高清电视或宽带互联网，它们的存在都归于有效的数据压缩技术。

数据压缩是从数据中消除冗余的过程。让我们考虑一个想象的例子。假设我们有一张尺寸为 100x100 像素的全黑图片。在数据存储方面（假设每个像素 24 位或 3 字节），该图像将占用 30,000 字节的存储空间。

100 × 100 × 3 = 30,000

全彩色图像包含完全冗余的数据。如果我们足够聪明，可以这样对数据编码：只需描述我们有一块 10,000 个黑色像素的事实。因此，与其存储一个包含 30,000 个零（黑色为零）的数据块，我们可以将数据压缩为数字 10,000，后面跟一个零来表示我们的数据。这种数据压缩方案是行程长度编码（run-length encoding），是最基础的压缩技术之一。今天的技术先进得多且复杂，但基本目标仍然是消除冗余数据。压缩算法（用于执行压缩的数学技术）分为两大大类：

- **无损 (Lossless)**。无损压缩保留原始文件中包含的所有数据。这意味着当从压缩版本恢复文件时，恢复的文件与原始未压缩版本完全相同。

- **有损 (Lossy)**。另一方面，有损压缩在执行压缩时删除数据以便应用更多压缩。当恢复有损文件时，它与原始值不匹配；而是一个近似值。有损压缩的例子有 JPEG（用于图像）和 MP3（用于音乐）。

在讨论中，我们将研究无损压缩，因为计算机上的大部分数据无法接受任何损失。

## `gzip`
