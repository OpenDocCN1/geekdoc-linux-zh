
系统将拒绝所有人访问`portmapper`。现在需要修改`/etc/hosts.allow`文件如下：

```
portmap: 192.168.1.0/255.255.255.0
```

这使得`192.168.1.0`网络中的所有主机能够访问由`portmapper`管理的程序，如`nfsd`和`mountd`。

> **警告** 切勿在`/etc/hosts.allow`中的`portmap`行中使用主机名，因为使用主机名查找可能会间接引发`portmap`活动，从而在循环中触发主机名查找。

服务器端另一个安全问题是是否允许客户端的`root`账户在服务器端被当作`root`处理。默认情况下，Linux禁止NFS客户端端的`root`在服务器端被当作`root`处理。换句话说，服务器上由`root`拥有的导出文件不能由客户端的`root`用户修改。若要显式强制执行此规则，可以按如下方式修改`/etc/exports`文件：

```
/www/cgi-data www1.xcnews-lan.com(rw, root_squash) www2.xcnews-lan.com(rw, root_squash)
```

现在，如果客户端上一个UID为0（`root`用户）的用户尝试访问（读取、写入或删除）文件系统，服务器会用服务器“`nobody`”账户的UID替代该UID。这意味着客户端的`root`用户无法访问或更改仅服务器`root`可以访问或更改的文件。

> **提示** 若要授予对NFS文件系统的`root`访问权限，请改用`no_root_squash`选项。

至此，NFS服务器已设置并配置好安全，现在让我们设置NFS客户端主机。

### 设置 NFS 客户端

默认情况下，Red Hat Linux支持NFS文件系统，因此无需折腾内核。要挂载由`ns.xcnews-lan.com`主机导出的`/www/cgi-data`目录，请在两台Web服务器的`/etc/fstab`文件中添加以下行：

```
ns.xcnews-lan.com:/www/cgi-data /www/cgi-data nfs
```

此行会在任何Web服务器重启时自动挂载`/www/cgi-data`目录。

接下来，在两个系统上创建`/www/cgi-bin`目录，并使用`mount`命令手动挂载该目录，如下所示：

```
ns.xcnews-lan.com:/www/cgi-data nfs
```

> **警告**
>
> 一个典型的NFS挂载问题发生的原因是，许多开发者在修改NFS服务器上的`/etc/exports`文件后，忘记了运行`exportfs`（即重启`rpc.mountd`和`rpc.nfsd`）。

卸载NFS文件系统与卸载本地文件系统完全相同。请注意，也可以通过不太信任NFS服务器来增强NFS客户端的安全性。例如，你可以使用`nosuid`选项禁用`suid`程序在NFS文件系统上运行。这意味着服务器的`root`用户无法在文件系统中创建一个`suid-root`程序，登录客户端作为普通用户，然后使用该`suid-root`程序在客户端上也成为`root`。还可以使用`noexec`选项完全禁止在挂载的文件系统上执行文件。你可以在`/etc/fstab`文件中描述你的NFS挂载点的那一行的选项列中输入这些选项。

此时，文件分发方案和基于NFS的CGI数据目录都已就绪。现在是配置`Apache`并确保其安全的时候了。

NFS环境中的主要瓶颈是NFS服务器的磁盘I/O速度。磁盘I/O速度取决于你为NFS服务器使用何种磁盘子系统。对于大多数情况，使用`IDE`磁盘运行NFS服务器的性能不如使用具有高转速的`ultra-wide` SCSI驱动器的服务器。每秒的最大I/O操作次数将决定你的NFS服务器表现如何。我使用过一台配备10块`ultra-wide` SCSI磁盘组`RAID 5`的`Intel Xeon 500`系统作为NFS服务器，为大约50名用户提供服务，取得了很好的成功。

在确定了良好的磁盘子系统（例如使用`10K RPM` `ultra-wide` SCSI磁盘阵列和带有大容量内置磁盘缓存的磁盘控制器的`RAID 5`）之后，你的下一个硬件瓶颈就是网络本身。将高带宽流量隔离到其专用网络中是减少性能损失的好方法。因此，我建议你使用专用的`100Mbits`以太网连接NFS服务器和NFS客户端。换言之，创建一个仅传输NFS数据包的NFS骨干网。这将实现一个高性能的NFS网络。

可以帮助你调整NFS服务器性能的软件配置选项将在以下部分中介绍。

### 优化读写块大小

NFS的默认读写块大小为`4096`字节（`4K`），这对所有情况来说可能并不最优。你可以执行测试来确定更改块大小是否会提高性能。执行此类测试的方法如下。

本测试假设您在Linux系统上运行着一个NFS服务器，并且拥有一个基于Linux的NFS客户端系统。该测试还假设客户端挂载了来自NFS服务器的名为`/mnt/nfs1`的文件系统。

1. 在NFS客户端机器上`su`切换到`root`用户。
2. 首先，您需要了解系统的总内存量。您应该知道默认值，因为这是您的系统，但如果您记得不太清楚，可以运行`cat /proc/meminfo`命令查看系统的内存信息。这将产生如下所示的显示：

```
total:   used:   free:  shared: buffers:  cached:

Mem:   263720960  260456448  3264512  30531584  228245504

6463488

Swap:  271392768  6209536  265183232

MemTotal:   257540 kB

MemFree:     3188 kB

MemShared:   29816 kB

Buffers:     222896 kB

Cached:      6312 kB

BigTotal:    0 kB

BigFree:     0 kB

SwapTotal:   265032 kB

SwapFree:    258968 kB
```

3. 系统总内存量显示在`total`列标题下；将此数字除以`1,048,576`（`1024×1024`）即可得到总（近似）内存大小（单位为MB）。在上面的示例中，该数值为`251MB`。有趣的是，大多数PC系统的`BIOS`都不会准确报告总内存，因此您必须根据对总内存的了解对数字进行四舍五入。在我的示例中，我知道系统应该有`256MB`的RAM，因此我将使用`256MB`作为此测试中的内存大小。
4. 现在切换到当前已挂载的`/mnt/nfs1` NFS文件目录。运行`du`命令检查NFS目录上是否至少有`512MB`（`2×`总`RAM`）的可用空间。如果没有，您无法继续此实验。
5. 下一个任务是通过在`/mnt/nfs1`目录中写入一个名为`512MB.dat`的文件（`16K/块 × 32,768`块），来测量当前NFS设置的写入性能。请使用以下命令执行此操作：

```
time dd if=/dev/zero \
    of=/mnt/nfs1/512MB.dat \
    bs=16k count=32768
```

此命令运行`time`命令，该命令记录名为第一个参数的程序的执行时间。在这种情况下，正在计时的是`dd`命令。给`dd`命令一个输入文件（使用`if`选项），名为`/dev/zero`。这是一个特殊设备，读取时返回0（零）字符。换句话说，如果您打开此文件进行读取，它将不断返回0字符，直到您关闭文件。这为我们提供了一个填充输出文件（使用`of`选项指定，名为`/mnt/nfs1/512MB.dat`）的便捷来源；`dd`命令被指示使用`16K`的块大小（使用`bs`选项指定）并总共写入`32,768`个块（使用`count`选项指定）。由于`16K/块 乘以 32,768 块`等于`512MB`，您将创建预期的文件。执行此命令后，它会打印几行内容，例如以下所示：

```
32768+0 records in

32768+0 records out

1.610u 71.800s 1:58.91  61.7%  0+0k  0+0io 202pf+0w
```

这里，`dd`命令从`/dev/zero`设备读取了`32,768`条记录，并向`/mnt/nfs1/512MB.dat`文件写回了相同数量的记录。第三行表明复制操作耗时`1 分 58.91 秒`。请按如下方式将此行记录在文本文件中：

```
Write, 1, 1.610u, 71.800s, 1:58.91, 61.7%
```
